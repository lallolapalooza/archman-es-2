GIFSICLE(1) Manual de Comandos Generales GIFSICLE(1)

NOMBRE

gifsicle - manipula imágenes y animaciones GIF

SINOPSIS

gifsicle [opciones, fotogramas y nombres de archivo]...

DESCRIPCIÓN

gifsicle crea, edita, manipula e imprime información sobre imágenes y animaciones GIF.

Gifsicle normalmente procesa los archivos GIF de entrada según sus opciones de línea de comandos y escribe el resultado en la salida estándar. La opción -i, por ejemplo, le dice a gifsicle que entrelace sus entradas:

gifsicle -i < pic.gif > interlaced-pic.gif

Por defecto, gifsicle combina dos o más archivos de entrada en una animación tipo "flipbook":

gifsicle pic1.gif pic2.gif pic3.gif > animation.gif

Utilice opciones como --delay, --loopcount y --optimize para ajustar sus animaciones.

Para modificar archivos GIF sobre la marcha, utilice la opción --batch. Con --batch, gifsicle modificará los archivos que especifique en lugar de escribir un nuevo archivo en la salida estándar. Para entrelazar todos los GIF del directorio actual, podría decir:

gifsicle --batch -i *.gif

Los nuevos usuarios pueden querer saltar a la sección de Ejemplos al final.

LÍNEA DE COMANDOS

La línea de comandos de gifsicle consta de archivos de entrada GIF y opciones. La mayoría de las opciones comienzan con un guion (-) o un signo más (+); las selecciones de fotogramas, un tipo de opción, comienzan con un signo de número (#). Cualquier otra cosa es un archivo de entrada GIF.

gifsicle lee y procesa los archivos de entrada GIF en orden. Si no se proporciona ningún archivo de entrada GIF, o si se proporciona el nombre de archivo especial '-', lee desde la entrada estándar.

gifsicle sale con el estado 0 si no hubo errores y el estado 1 en caso contrario.

OPCIONES

Cada opción tiene una forma larga, '--nombre-descriptivo-largo'. No es necesario escribir el nombre descriptivo largo completo, solo lo suficiente para que sea inequívoco.

Algunas opciones también tienen una forma corta, '-X'. Puede combinar opciones cortas si no toman argumentos: '-IIb' es lo mismo que '-I -I -b'. Pero tenga cuidado con las opciones que sí toman argumentos: '-cblah' significa '-c blah', no '-c -b -l -a -h'.

Muchas opciones también tienen una inversa, '--no-opcion', que desactiva la opción. Puede desactivar una opción corta '-X' diciendo '+X' en su lugar.

Opciones de Modo

Las opciones de modo le dicen a gifsicle qué tipo de salida generar. Puede haber como máximo una, y debe preceder a cualquier entrada GIF.

--merge, -m
Combina todos los GIF de entrada en un solo archivo con múltiples fotogramas y escribe ese archivo en la salida estándar. Este es el modo predeterminado.
--batch, -b
Modifica cada GIF de entrada sobre la marcha leyendo y escribiendo en el mismo nombre de archivo. (Los GIF leídos de la entrada estándar se escriben en la salida estándar).
--explode, -e
Crea un GIF de salida para cada fotograma de cada archivo de entrada. Los GIF de salida se nombran 'xxx.000', 'xxx.001', y así sucesivamente, donde 'xxx' es el nombre del archivo de entrada (o lo que sea que especificó con '--output') y la extensión numérica es el número de fotograma.
--explode-by-name, -E
Igual que --explode, pero escribe cualquier fotograma con nombre en archivos 'xxx.nombre' en lugar de 'xxx.número-de-fotograma'. Los fotogramas se nombran usando la opción '--name'.

Opciones de transformación de

Las opciones de transformación de imagen se aplican a GIFs completos cuando se leen o escriben. Se pueden desactivar con ‘--no-option’

--resize widthxheight
Redimensiona el GIF de salida al ancho y alto dados. Si width o height es un guion bajo ‘_’, esa dimensión se elige para que la relación de aspecto permanezca sin cambios. El redimensionamiento ocurre después de que todos los marcos de entrada se han combinado y antes de la optimización. El redimensionamiento usa las dimensiones de la pantalla lógica; si el flujo de entrada tiene una pantalla lógica inusual (muchos visores de GIF ignoran las pantallas lógicas), puede que quieras proporcionar --no-logical-screen (o +S) para restablecerla de modo que gifsicle use las dimensiones de la imagen en su lugar. Ver también --resize-method.
--resize-width width
--resize-height height
Redimensiona a un ancho o alto dado, preservando la relación de aspecto. Equivalente a --resize widthx_ o --resize _xheight.
--resize-fit widthxheight
--resize-touch

OPTIONS

GIF File Options

--resize-fit widthxheight
Redimensiona el GIF de salida para que quepa dentro de un rectángulo con dimensiones widthxheight. La relación de aspecto se mantiene sin cambios. La opción --resize-fit solo reduce el tamaño de la imagen; no se realiza ningún redimensionamiento si el GIF ya cabe dentro del rectángulo. Cualquiera de width o height puede ser un guion bajo ‘_’, lo que deja esa dimensión sin restricciones.
--resize-fit-width width
--resize-fit-height height
--resize-touch-width width
--resize-touch-height height
Similar a --resize-fit y --resize-touch, pero restringe solo una dimensión.
--scale Xfactor[xYfactor]
Escala el ancho y el alto del GIF de salida por Xfactor y Yfactor. Si no se proporciona Yfactor, se utiliza por defecto Xfactor. El escalado ocurre después de que se han combinado todos los fotogramas de entrada y antes de la optimización.
--resize-method method
Establece el método utilizado para redimensionar imágenes. El método ‘sample’ se ejecuta muy rápido, pero al reducir imágenes, produce resultados ruidosos. El método ‘mix’ es algo más lento, pero produce resultados de mejor aspecto. El método por defecto actualmente es ‘mix’.

Detalles: Los métodos de redimensionamiento difieren más al reducir imágenes. El método ‘sample’ es un muestreador de puntos: cada posición de píxel en la imagen de salida se corresponde exactamente con una posición de píxel en la entrada. Al reducir, se descartan filas y columnas completas de la entrada. Los otros métodos utilizan todos los píxeles de entrada, lo que generalmente produce imágenes de mejor aspecto. El método ‘box’, un muestreador de caja, es más rápido que los filtros más complejos y produce resultados algo más nítidos, pero habrá anomalías al reducir imágenes en una pequeña cantidad en una dimensión. (Algunos píxeles de salida corresponderán a exactamente 1 fila o columna de entrada, mientras que otros corresponderán a exactamente 2 filas o columnas de entrada). El método ‘mix’ es un interpolador bilineal completo. Esto es más lento y produce resultados algo más borrosos, pero evita anomalías.

Gifsicle también soporta remuestreadores más complejos, incluyendo remuestreo cúbico de Catmull-Rom (‘catrom’), el filtro de Mitchell-Netravali (‘mitchell’), un filtro de Lanczos de 2 lóbulos (‘lanczos2’), y un filtro de Lanczos de 3 lóbulos (‘lanczos3’). Estos filtros son aún más lentos, pero pueden dar resultados más nítidos y mejores.

--resize-colors n
Permite a Gifsicle agregar colores intermedios al redimensionar imágenes. Normalmente, los algoritmos de redimensionamiento de Gifsicle utilizan las tablas de colores de las imágenes de entrada sin cambios. Al reducir imágenes con muy pocos colores (por ejemplo, imágenes puramente en blanco y negro), agregar colores intermedios puede mejorar los resultados. Por ejemplo: --resize-colors 64 permite a Gifsicle agregar colores intermedios para imágenes que tienen menos de 64 colores de entrada.

Opciones de Color

Las opciones de color se aplican a GIFs completos al leerlos o escribirlos. Se pueden desactivar con ‘--no-option’.

-k num
--colors num
Reduce el número de colores distintos en cada GIF de salida a num o menos. Num debe estar entre 2 y 256. Esto se puede usar para reducir los GIFs de salida o eliminar cualquier tabla de colores local.

Normalmente, se elige un grupo adaptativo de colores de la tabla de colores existente. Puedes afectar este proceso con la opción --color-method o proporcionando tu propia mapa de colores con --use-colormap. Gifsicle podría necesitar agregar un color adicional (haciendo num+1 en total) si hay transparencia en la imagen.

--color-method method
Determina cómo se elige un mapa de colores más pequeño. ‘diversity’, por defecto, es el algoritmo de diversidad de xv(1), que utiliza un subconjunto estricto de los colores existentes y generalmente produce buenos resultados. ‘blend-diversity’ es una modificación de este: algunos valores de color se mezclan a partir de grupos de colores existentes. ‘median-cut’ es el algoritmo de corte mediano descrito por Heckbert. --method es un sinónimo de --color-method.
-f
--dither[=method]
Cuando --dither está activado y el mapa de colores se cambia, se utilizan combinaciones de colores para aproximar los colores faltantes. Esto se ve mejor, pero genera archivos más grandes y puede causar artefactos de animación, por lo que está desactivado por defecto.

Especifica un algoritmo de difuminado con el argumento opcional method. El valor por defecto, ‘floyd-steinberg’, utiliza la difusión de error de Floyd-Steinberg. Esto generalmente se ve mejor, pero puede causar artefactos de animación, ya que las elecciones de difuminado variarán de un fotograma a otro. Gifsicle también soporta algoritmos de difuminado ordenado que evitan artefactos de animación. El modo ‘ro64’ utiliza un patrón grande de aspecto aleatorio y generalmente produce buenos resultados. Los modos ‘o3’, ‘o4’, y ‘o8’ utilizan patrones más pequeños y regulares. El modo ‘ordered’ elige un buen algoritmo de difuminado ordenado. Para efectos especiales, prueba los modos de semitonos ‘halftone’, ‘squarehalftone’, y ‘diagonal’. Algunos modos toman parámetros opcionales usando comas. Los modos de semitonos toman un tamaño de celda y un límite de color: ‘halftone,10,3’ crea celdas de semitonos de 10 píxeles de ancho donde cada celda utiliza hasta 3 colores.

--gamma gamma
Establece la corrección gamma a gamma, que puede ser un número real o ‘srgb’. En términos generales, los números más altos exageran las sombras y los números más bajos exageran las luces. El valor por defecto es la función definida por el espacio de color sRGB estándar, que generalmente funciona bien. (Sus efectos son similares a --gamma=2.2.) Gifsicle utiliza la corrección gamma al elegir una tabla de colores (--colors) y al difuminar (--dither).
--lossy[=lossiness]
Altera los colores de la imagen para reducir el tamaño del archivo de salida a costa de artefactos y ruido. Lossiness determina cuántos artefactos se permiten; valores más altos pueden resultar en tamaños de archivo más pequeños, pero causan más artefactos. El valor por defecto de lossiness es 20.
--change-color color1 color2
Cambia color1 a color2 en los siguientes GIFs de entrada. (Los argumentos de color tienen las mismas formas que en la opción -t.) Cambia múltiples colores proporcionando la opción varias veces. Los cambios de color no interfieren entre sí, por lo que puedes intercambiar de forma segura dos colores con ‘--change-color color1 color2 --change-color color2 color1’. Todos ellos surten efecto cuando se lee un GIF de entrada. --no-change-color cancela todos los cambios de color.
--transform-colormap command
Command debe ser un comando de shell que lee de la entrada estándar y escribe en la salida estándar. Cada mapa de colores en el GIF de salida se traduce al formato de mapa de colores de texto (ver --use-colormap a continuación) y se canaliza al comando. La salida que genera el comando (que también debe estar en formato de mapa de colores de texto) reemplazará el mapa de colores de entrada. El reemplazo no considera la coincidencia de colores, por lo que los píxeles que usaban la ranura de color n en la entrada seguirán usando la ranura de color n en la salida.
--use-colormap colormap
Cambia la imagen para usar colormap. Cada píxel en la imagen se cambia a la coincidencia más cercana en colormap (o, si --dither está activado, a una combinación difuminada de colores en colormap). Colormap puede ser web para la paleta de 216 colores "a prueba de web"; gray para escala de grises; bw para blanco y negro; o el nombre de un archivo. Ese archivo debe ser un archivo de texto (el formato se describe a continuación) o un archivo GIF, cuyo mapa de colores global se utilizará. Si --colors=N también se proporciona, se utilizará un subconjunto de tamaño N de colormap.

Los archivos de mapa de colores de texto utilizan este formato:

; cada línea que no sea comentario representa un color, "rojo verde azul"
; cada componente debe estar entre 0 y 255
0 0 0            ; como esto
255 255 255
; o usa notación hexadecimal web
#ffffff          ; como esto

EJEMPLOS

Primero, creemos una animación, ‘anim.gif’:

gifsicle a.gif b.gif c.gif d.gif > an
im.g
if

Esta animación se moverá muy rápidamente: como no especificamos un retraso, un navegador recorrerá los fotogramas lo más rápido que pueda. Vamos a ralentizarla y pausar 0.5 segundos entre fotogramas, usando la --delay opción

. 
gifsicle --delay 5
0 a.gif b.gif c.gi
f d.gif > anim.gif

Si también queremos que el GIF se repita tres veces, podemos usar --loopcount:

gifsicle -d 50 --lo
op=3 a.gif b.gif c.g
if d.gif > anim.gif

(En lugar de escribir --delay de nuevo, usamos su forma corta, -d. Muchas opciones tienen formas cortas; puedes verlas ejecutando ‘gifsicle --help’. También abreviamos --loopcount a --loop, lo cual está bien ya que ninguna otra opción empieza con ‘loop’.

)
