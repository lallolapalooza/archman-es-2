NOMBRE

git-index-pack - Construye un archivo de índice de paquete para un archivo de paquete existente

SINOPSIS

git index-pack [-v] [-o <archivo-indice>] [--[no-]rev-index] <archivo-paquete>
git index-pack --stdin [--fix-thin] [--keep] [-v] [-o <archivo-indice>]
                  [--[no-]rev-index] [<archivo-paquete>]

DESCRIPCIÓN

Lee un archivo de paquete (.pack) del archivo especificado, construye un archivo de índice de paquete (.idx) para él y, opcionalmente, escribe un índice inverso (.rev) para el paquete especificado. El archivo de paquete, junto con el índice del paquete, se puede colocar luego en el directorio objects/pack/ de un repositorio de Git.

OPCIONES

-v

Sé verboso sobre lo que está sucediendo, incluyendo el estado de progreso.

-o <archivo-indice>

Escribe el índice de paquete generado en el archivo especificado. Sin esta opción, el nombre del archivo de índice de paquete se construye a partir del nombre del archivo de paquete reemplazando .pack con .idx (y el programa falla si el nombre del archivo de paquete no termina en .pack).

--rev-index, --no-rev-index

Cuando se proporciona esta bandera, genera un índice inverso (un archivo .rev) correspondiente al paquete dado. Si se proporciona --verify, asegúrate de que el índice inverso existente sea correcto. Prevalece sobre pack.writeReverseIndex.

--stdin

Cuando se proporciona esta bandera, el paquete se lee desde stdin en su lugar y luego se escribe una copia en <archivo-paquete>. Si no se especifica <archivo-paquete>, el paquete se escribirá en el directorio objects/pack/ del repositorio de Git actual con un nombre predeterminado determinado por el contenido del paquete. Si no se especifica <archivo-paquete>, considera usar --keep para evitar una condición de carrera entre este proceso y git repack.

--fix-thin

Corrige un paquete "delgado" producido por git pack-objects --thin (ver git-pack-objects(1) para detalles) agregando los objetos excluidos en los que se basan los objetos deltificados al paquete. Esta opción solo tiene sentido junto con --stdin.

--keep

Antes de mover el índice a su destino final, crea un archivo .keep vacío para el archivo de paquete asociado. Esta opción es generalmente necesaria con --stdin para evitar que un proceso git repack simultáneo elimine el paquete e índice recién construidos antes de que las referencias puedan actualizarse para usar los objetos contenidos en el paquete.

--keep=<msg>

Al igual que --keep, crea un archivo .keep antes de mover el índice a su destino final. Sin embargo, en lugar de crear un archivo vacío, coloca <msg> seguido de un salto de línea en el archivo .keep. El mensaje <msg> se puede buscar posteriormente en todos los archivos .keep para localizar aquellos que han superado su utilidad.

--index-version=<version>[,<offset>]

Esto está destinado únicamente al uso del conjunto de pruebas. Permite forzar la versión del índice de paquete generado y forzar entradas de índice de 64 bits en objetos ubicados por encima del desplazamiento dado.

--strict[=<msg-id>=<severity>...]

Falla si el paquete contiene objetos o enlaces rotos. Una lista opcional separada por comas de <msg-id>=<severity> puede pasarse para cambiar la severidad de algunos problemas posibles, por ejemplo, --strict="missingEmail=ignore,badTagName=error". Consulte la entrada para las opciones de configuración fsck.<msg-id> en git-fsck(1) para obtener más información sobre los valores posibles de <msg-id> y <severity>.

--progress-title

Solo para uso interno.

Establece el título de la barra de progreso. El título es "Recibiendo objetos" por defecto y "Indexando objetos" cuando se especifica --stdin.

--check-self-contained-and-connected

Falla si el paquete contiene enlaces rotos. Solo para uso interno.

--fsck-objects[=<msg-id>=<severity>...]

Falla si el paquete contiene objetos rotos, pero a diferencia de --strict, no se bloquea por enlaces rotos. Si el paquete contiene un árbol que apunta a un blob .gitmodules que no existe, imprime el hash de ese blob (para que el llamador lo verifique) después del hash que va en el nombre del archivo pack/idx (ver "Notas").

Una lista opcional separada por comas de <msg-id>=<severity> puede pasarse para cambiar la severidad de algunos problemas posibles, por ejemplo, --fsck-objects="missingEmail=ignore,badTagName=ignore". Consulte la entrada para las opciones de configuración fsck.<msg-id> en git-fsck(1) para obtener más información sobre los valores posibles de <msg-id> y <severity>.

--threads=<n>

Especifica el número de hilos a generar al resolver deltas. Esto requiere que index-pack esté compilado con pthreads; de lo contrario, esta opción se ignora con una advertencia. Esto está destinado a reducir el tiempo de empaquetado en máquinas multiprocesador. La cantidad requerida de memoria para la ventana de búsqueda de deltas se multiplica por el número de hilos. Especificar 0 hará que Git detecte automáticamente el número de CPUs y utilice un máximo de 3 hilos.

--max-input-size=<size>

Falla si el paquete es más grande que <size>.

--object-format=<hash-algorithm>

Especifica el formato de objeto dado (algoritmo de hash) para el paquete. Los valores válidos son sha1 y (si está habilitado) sha256. El valor predeterminado es el algoritmo del repositorio actual (establecido por extensions.objectFormat), o sha1 si no se establece ningún valor o fuera de un repositorio.

Esta opción no se puede usar con --stdin.

Nota: Actualmente, no hay interoperabilidad entre repositorios SHA-256 y repositorios SHA-1.

Históricamente, advertimos que los repositorios SHA-256 pueden necesitar cambios incompatibles hacia atrás más adelante cuando introduzcamos dichas características de interoperabilidad. Hoy en día, solo esperamos cambios compatibles. Además, si dichos cambios resultan ser necesarios, se puede esperar que los repositorios SHA-256 creados con el Git actual sean utilizables por versiones futuras de Git sin pérdida de datos.

--promisor[=<message>]

Antes de confirmar el índice del paquete, crea un archivo .promisor para este paquete. Particularmente útil al escribir un paquete prometedor con --fix-thin, ya que el nombre del paquete no es final hasta que el paquete se ha escrito por completo. Si se proporciona un <message>, ese contenido se escribirá en el archivo .promisor para referencia futura. Ver clonación parcial[1] para más información.

Además, si hay objetos en el paquete dado que hacen referencia a objetos no prometedores (en el repo), vuelve a empaquetar esos objetos no prometedores en un paquete prometedor. Esto evita una situación en la que un repo tiene objetos no prometedores que son accesibles a través de objetos prometedores.

Requiere que <archivo-paquete> no se especifique.

NOTAS

Una vez creado el índice, el hash que va en el nombre del archivo pack/idx se imprime en stdout. Si también se usó --stdin, este se antepone con "pack\t" o "keep\t" si se creó con éxito un nuevo archivo .keep. Esto es útil para eliminar un archivo .keep utilizado como bloqueo para evitar la condición de carrera con git repack mencionada anteriormente.
