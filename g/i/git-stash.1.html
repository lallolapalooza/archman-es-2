GIT-STASH(1) Manual de Git GIT-STASH(1)

NOMBRE

git-stash - Guarda los cambios en un directorio de trabajo sucio

SINOPSIS

git stash list [<log-options>]
git stash show [-u | --include-untracked | --only-untracked] [<diff-options>] [<stash>]
git stash drop [-q | --quiet] [<stash>]
git stash pop [--index] [-q | --quiet] [<stash>]
git stash apply [--index] [-q | --quiet] [<stash>]
git stash branch <nombre-rama> [<stash>]
git stash [push [-p | --patch] [-S | --staged] [-k | --[no-]keep-index] [-q | --quiet]
             [-u | --include-untracked] [-a | --all] [(-m | --message) <mensaje>]
             [--pathspec-from-file=<archivo> [--pathspec-file-nul]]
             [--] [<pathspec>...]]
git stash save [-p | --patch] [-S | --staged] [-k | --[no-]keep-index] [-q | --quiet]
           [-u | --include-untracked] [-a | --all] [<mensaje>]
git stash clear
git stash create [<mensaje>]
git stash store [(-m | --message) <mensaje>] [-q | --quiet] <commit>
git stash export (--print | --to-ref <ref>) [<stash>...]
git stash import <commit>

DESCRIPCIÓN

Usa git stash cuando quieras registrar el estado actual del directorio de trabajo y del índice, pero quieras volver a un directorio de trabajo limpio. El comando guarda tus modificaciones locales y revierte el directorio de trabajo para que coincida con el commit HEAD.

Las modificaciones guardadas con este comando se pueden listar con git stash list, inspeccionar con git stash show y restaurar (potencialmente sobre un commit diferente) con git stash apply. Llamar a git stash sin argumentos es equivalente a git stash push. Por defecto, un stash se lista como "WIP on <nombre-rama> ...", pero puedes proporcionar un mensaje más descriptivo en la línea de comandos al crear uno.

El último stash que creaste se almacena en refs/stash; los stashes más antiguos se encuentran en el reflog de esta referencia y se pueden nombrar utilizando la sintaxis habitual del reflog (por ejemplo, stash@{0} es el stash creado más recientemente, stash@{1} es el anterior, también es posible stash@{2.hours.ago}). Los stashes también pueden ser referenciados especificando solo el índice del stash (por ejemplo, el entero <n> es equivalente a stash@{<n>}).

COMANDOS

push [-p | --patch] [-S | --staged] [-k | --[no-]keep-index] [-u | --include-untracked] [ -a | --all] [-q | --quiet] [(-m|--message) <mensaje>] [--pathspec-from-file=<archivo> [--pathspec-file-nul]] [--] [<pathspec>...]

Guarda tus modificaciones locales en una nueva entrada de stash y revierte las modificaciones al HEAD (en el árbol de trabajo y en el índice). La parte <mensaje> es opcional y proporciona la descripción junto con el estado guardado.

Para crear rápidamente una instantánea, puedes omitir "push". En este modo, no se permiten argumentos que no sean opciones para evitar que un subcomando mal escrito cree una entrada de stash no deseada. Las dos excepciones son stash -p, que actúa como alias para stash push -p, y los elementos de pathspec, que se permiten después de un doble guion -- para desambiguación.

save [-p | --patch] [-S | --staged] [-k | --[no-]keep-index] [-u | --include-untracked] [-a | --all] [-q | --quiet] [<mensaje>]

Esta opción está obsoleta en favor de git stash push. Difiere de "stash push" en que no puede aceptar pathspec. En su lugar, todos los argumentos que no sean opciones se concatenan para formar el mensaje del stash.

list [<log-options>]

Lista las entradas de stash que tienes actualmente. Cada entrada de stash se lista con su nombre (por ejemplo, stash@{0} es la última entrada, stash@{1} es la anterior, etc.), el nombre de la rama que estaba activa cuando se creó la entrada y una breve descripción del commit en el que se basó la entrada. 
stash@{0}: WIP on submit: 6ebd0e2... Update git-stash documentation
stash@{1}: On master: 9cc0589... Add git-stash

El comando toma opciones aplicables al comando git log para controlar qué se muestra y cómo. Ver git-log(1).

show [-u | --include-untracked | --only-untracked] [<diff-options>] [<stash>]

Muestra los cambios registrados en la entrada de stash como un diff entre el contenido guardado y el commit original en el que se creó la entrada de stash. Por defecto, el comando muestra el diffstat, pero aceptará cualquier formato conocido por git diff (por ejemplo, git stash show -p stash@{1} para ver la penúltima entrada en formato de parche). Si no se proporciona ninguna <diff-option>, el comportamiento por defecto lo darán las variables de configuración stash.showStat y stash.showPatch. También puedes usar stash.showIncludeUntracked para establecer si --include-untracked está habilitado por defecto.

pop [--index] [-q | --quiet] [<stash>]

Elimina un solo estado guardado de la lista de stashes y lo aplica sobre el estado actual del árbol de trabajo, es decir, realiza la operación inversa de git stash push. El árbol de trabajo debe coincidir con el índice.

La aplicación del estado puede fallar con conflictos; en ese caso, no se elimina de la lista de stashes. Necesitas resolver los conflictos a mano y llamar a git stash drop manualmente después.

apply [--index] [-q | --quiet] [<stash>]

Igual que pop, pero no elimina el estado de la lista de stashes. A diferencia de pop, <stash> puede ser cualquier commit que parezca un commit creado por stash push o stash create.

branch <nombre-rama> [<stash>]

Crea y extrae una nueva rama llamada <nombre-rama> a partir del commit en el que se creó originalmente el <stash>, aplica los cambios registrados en <stash> al nuevo árbol de trabajo e índice. Si eso tiene éxito, y <stash> es una referencia de la forma stash@{<revisión>}, entonces elimina el <stash>.

Esto es útil si la rama en la que ejecutaste git stash push ha cambiado tanto que git stash apply falla debido a conflictos. Dado que la entrada de stash se aplica sobre el commit que era HEAD en el momento en que se ejecutó git stash, restaura el estado originalmente guardado sin conflictos.

clear

Elimina todas las entradas de stash. Ten en cuenta que esas entradas estarán sujetas a poda y pueden ser imposibles de recuperar (ver EJEMPLOS más abajo para una estrategia posible).

drop [-q | --quiet] [<stash>]

Elimina una única entrada de stash de la lista de entradas de stash.

create

Crea una entrada de stash (que es un objeto commit regular) y devuelve su nombre de objeto, sin almacenarlo en ningún lugar del espacio de nombres de refs. Esto está destinado a ser útil para scripts. Probablemente no es el comando que quieres usar; ver "push" arriba.

store

Almacena un stash dado creado a través de git stash create (que es un commit de fusión colgante) en la referencia de stash, actualizando el reflog del stash. Esto está destinado a ser útil para scripts. Probablemente no es el comando que quieres usar; ver "push" arriba.

export ( --print | --to-ref <ref> ) [<stash>...]

Exports stashes as described in the git stash push section. The push command is more flexible, this command is intended to be useful for scripts.

import <commit>

Imports a stash created elsewhere, and adds it to the stash list. The push command is more flexible, this command is intended to be useful for scripts.

EXAMPLES

1. Guardar tus cambios locales y volver a un árbol de trabajo limpio:

    $ git stash
    Saved working directory and index state WIP on master:
     f777810... commit message
    HEAD is now at f777810... commit message

2. Guardar tus cambios locales, incluyendo los archivos no rastreados:

    $ git stash -u
    Saved working directory and index state On master:
     f777810... commit message

3. Guardar tus cambios locales con un mensaje descriptivo:

    $ git stash save "cambios de reestructuración en progreso"
    Saved working directory and index state On master:
     f777810... cambios de reestructuración en progreso

4. Volver a aplicar el último stash y eliminarlo de la lista de stashes:

    $ git stash pop
    On branch master
    Changes not staged for commit:
      (use "git add <file>..." to update what will be committed)
      (use "git restore <file>..." to discard changes in working directory)
            modified:   README.md

5. Volver a aplicar el segundo stash (índice 1) y eliminarlo de la lista de stashes:

    $ git stash pop stash@{1}

6. Listar todos tus stashes:

    $ git stash list
    stash@{0}: On master: f777810... commit message
    stash@{1}: On feature: a3457c0... commit message

7. Ver el diff de un stash sin aplicarlo:

    $ git stash show stash@{0}

8. Ver el diff en formato de parche de un stash sin aplicarlo:

    $ git stash show -p stash@{0}

9. Crear una nueva rama a partir del commit base del stash y aplicar el stash a la nueva rama:

    $ git stash branch new-branch stash@{0}

10. Eliminar todos los stashes (¡con precaución!):

    $ git stash clear

11. Recuperar un stash que se eliminó accidentalmente:

Si has eliminado un stash por accidente, puedes recuperarlo del reflog. Primero, busca el stash en el reflog de refs/stash:

    $ git reflog refs/stash
    a3457c0 refs/stash@{0}: drop: On feature: a3457c0... commit message
    f777810 refs/stash@{1}: On master: f777810... commit message

Luego, puedes aplicar el stash usando su nombre de reflog:

    $ git stash apply stash@{1}

Si estás satisfecho, puedes usarlo para recuperar el stash:

    $ git stash drop stash@{1}

Exporta los stashes especificados, o todos ellos si no se especifica ninguno, a una cadena de commits que pueden transferirse usando los mecanismos normales de fetch y push, luego importados usando el import subcomando.

import <commit>

Importa los stashes especificados desde el commit especificado, que debe haber sido creado por export, y los añade a la lista de stashes. Para reemplazar los stashes existentes, usa clear primero.

OPCIONES

-a, --all

Esta opción solo es válida para los comandos push y save .

Todos los archivos ignorados y no rastreados también se guardan en el stash y luego se limpian con git clean.

-u, --include-untracked, --no-include-untracked

Cuando se usa con los comandos push y save , todos los archivos no rastreados también se guardan en el stash y luego se limpian con git clean.

Cuando se usa con el comando show , muestra los archivos no rastreados en la entrada del stash como parte del diff.

--only-untracked

Esta opción solo es válida para el comando show .

Muestra solo los archivos no rastreados en la entrada del stash como parte del diff.

--index

Esta opción solo es válida para los comandos pop y apply .

Intenta restablecer no solo los cambios del árbol de trabajo, sino también los del índice. Sin embargo, esto puede fallar cuando hay conflictos (que se almacenan en el índice, por lo que ya no puedes aplicar los cambios tal como eran originalmente).

-k, --keep-index, --no-keep-index

Esta opción solo es válida para los comandos push y save .

Todos los cambios ya añadidos al índice se dejan intactos.

-p, --patch

Esta opción solo es válida para los comandos push y save .

Selecciona interactivamente bloques del diff entre HEAD y el árbol de trabajo para ser guardados en el stash. La entrada del stash se construye de modo que su estado de índice sea el mismo que el estado de índice de tu repositorio, y su árbol de trabajo contenga solo los cambios que seleccionaste interactivamente. Los cambios seleccionados se revierten entonces de tu árbol de trabajo. Consulta la sección “Modo interactivo” de git-add(1) para aprender a operar el modo --patch .

La opción --patch implica --keep-index. Puedes usar --no-keep-index para anular esto.

-U<n>, --unified=<n>

Genera diffs con <n> líneas de contexto. Por defecto es diff.context o 3 si la opción de configuración no está definida.

--inter-hunk-context=<n>

Muestra el contexto entre bloques de diff, hasta el número especificado de <número> de líneas, fusionando así bloques que están cerca el uno del otro. Por defecto es diff.interHunkContext o 0 si la opción de configuración no está definida.

-S, --staged

Esta opción solo es válida para los comandos push y save .

Guarda en el stash solo los cambios que están actualmente en el área de preparación. Esto es similar a un git commit básico, excepto que el estado se confirma en el stash en lugar de en la rama actual.

La opción --patch tiene prioridad sobre esta.

--pathspec-from-file=<file>

Esta opción solo es válida para el comando push .

El pathspec se pasa en <file> en lugar de en los argumentos de la línea de comandos. Si <file> es exactamente - entonces se usa la entrada estándar. Los elementos del pathspec se separan por LF o CR/LF. Los elementos del pathspec pueden ser entrecomillados como se explica para la variable de configuración core.quotePath (ver git-config(1)). Ver también --pathspec-file-nul y la opción global --literal-pathspecs.

--pathspec-file-nul

Esta opción solo es válida para el comando push .

Solo tiene sentido con --pathspec-from-file. Los elementos del pathspec se separan con el carácter NUL y todos los demás caracteres se toman literalmente (incluyendo saltos de línea y comillas).

-q, --quiet

Esta opción solo es válida para los comandos apply, drop, pop, push, save, store .

Silencioso, suprime los mensajes de retroalimentación.

--print

Esta opción solo es válida para el comando export .

Crea la cadena de commits que representan los stashes exportados sin almacenarla en ningún lugar del espacio de nombres de referencias e imprime el ID del objeto en la salida estándar. Esto está diseñado para scripts.

--to-ref

Esta opción solo es válida para el comando export .

Crea la cadena de commits que representan los stashes exportados y la almacena en la referencia especificada.

--

Esta opción solo es válida para el comando push .

Separa el pathspec de las opciones con fines de desambiguación.

<pathspec>...

Esta opción solo es válida para el comando push .

La nueva entrada del stash registra los estados modificados solo para los archivos que coinciden con el pathspec. Luego, las entradas del índice y los archivos del árbol de trabajo se revierten al estado en HEAD solo para estos archivos también, dejando intactos los archivos que no coinciden con el pathspec.

Para más detalles, consulta la entrada pathspec en gitglossary(7).

<stash>

Esta opción solo es válida para los comandos apply, branch, drop, pop, show, y export .

Una referencia de la forma stash@{<revision>}. Cuando no se proporciona <stash> , se asume el stash más reciente (es decir, stash@{0}).

DISCUSIÓN

Una entrada de stash se representa como un commit cuyo árbol registra el estado del directorio de trabajo, y su primer padre es el commit en HEAD cuando se creó la entrada. El árbol del segundo padre registra el estado del índice cuando se hace la entrada, y se hace hijo del commit HEAD

       . El grafo de ascendencia se ve así:

.----W / / -----H----I donde H es el commit HEAD , I es un commit que registra el estado del índice, y W

es un commit que registra el estado del árbol de trabajo.

EJEMPLOS

Hacer pull en un árbol sucio Cuando estás en medio de algo, te enteras de que hay cambios en el flujo ascendente que son posiblemente relevantes para lo que estás haciendo. Cuando tus cambios locales no entran en conflicto con los cambios del flujo ascendente, un simple git pull

te permitirá avanzar. Sin embargo, hay casos en los que tus cambios locales sí entran en conflicto con los cambios del flujo ascendente, y git pull

se niega a sobrescribir tus cambios. En tal caso, puedes guardar tus cambios en el stash, realizar un pull, y luego recuperarlos, así:

$ git pull ... file foobar not up to date, cannot merge. $ git stash $ git pull $ git stash pop

Flujo de trabajo interrumpido 
Cuando estás en medio de algo, tu jefe entra y exige que arregles algo inmediatamente. Tradicionalmente, harías un commit en una rama temporal para guardar tus cambios, y volverías a tu rama original para hacer la corrección de emergencia, así:

# ... hack hack hack ... $ git switch -c my_wip $ git commit -a -m "WIP" $ git switch master $ edit emergency fix $ git commit -a -m "Fix in a hurry" $ git switch my_wip $ git reset --soft HEAD^ # ... continue hacking ... Puedes usar git stash

para simplificar lo anterior, así:

# ... hack hack hack ... $ git stash $ edit emergency fix $ git commit -a -m "Fix in a hurry" $ git stash pop # ... continue hacking ...

Probar commits parciales Puedes usar git stash push --keep-index 
cuando quieras hacer dos o más commits de los cambios en el árbol de trabajo, y quieras probar cada cambio antes de confirmarlo:

# ... hack hack hack ... $ git add --patch foo # add just first part to the index $ git stash push --keep-index # save all other changes to the stash $ edit/build/test first part $ git commit -m 'First part' # commit fully tested change $ git stash pop # prepare to work on all other changes # ... repeat above five steps until one commit remains ... $ edit/build/test remaining parts $ git commit foo -m 'Remaining parts'

Guardar cambios no relacionados para uso futuro Cuando estás en medio de cambios masivos y encuentras algún problema no relacionado que no quieres olvidar arreglar, puedes hacer el(los) cambio(s), ponerlos en el área de preparación, y usar git stash push --staged 
para guardarlos en el stash para uso futuro. Esto es similar a confirmar los cambios preparados, solo que el commit termina en el stash y no en la rama actual.

# ... hack hack hack ... $ git add --patch foo # add unrelated changes to the index $ git stash push --staged # save these changes to the stash # ... hack hack hack, finish current changes ... $ git commit -m 'Massive' # commit fully tested changes $ git switch fixup-branch # switch to another branch $ git stash pop # to finish work on the saved changes

Recuperar entradas de stash que fueron borradas/eliminadas erróneamente 
Si eliminas o borras entradas de stash por error, no se pueden recuperar a través de los mecanismos normales de seguridad. Sin embargo, puedes probar el siguiente comando para obtener una lista de entradas de stash que aún están en tu repositorio, pero ya no son alcanzables:

git fsck --unreachable | grep commit | cut -d\ -f3 | xargs git log --merges --no-walk --grep=WIP

CONFIGURACIÓN Todo lo que está debajo de esta línea en esta sección se incluye selectivamente de la documentación de git-config(1)

. El contenido es el mismo que el que se encuentra allí:

stash.index Si esto se establece en true, git stash apply ylo stash pop se comportará como si se hubiera proporcionado --index . Por defecto es false.

stash.showIncludeUntracked

Si esto se establece en true, el git stash show comando mostrará los archivos sin seguimiento de una entrada del stash. Por defecto es false.

stash.showPatch

Si esto se establece en true, el git stash show comando sin una opción mostrará la entrada del stash en forma de parche. Por defecto es false.

stash.showStat

Si esto se establece en true, el git stash show comando sin una opción mostrará un diffstat de la entrada del stash. Por defecto es true.
