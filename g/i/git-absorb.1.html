DESCRIPCIÓ

N

Tienes una rama de funcionalidad con algunos commits. Tu compañero revisó la rama y señaló algunos errores. Tienes las correcciones para los errores, pero no quieres meterlas todas en un commit opaco que diga correcciones, porque crees en los commits atómicos. En lugar de buscar manualmente los SHAs de los commits para git commit --fixup, o ejecutar un rebase interactivo manual, haz

esto: 
$ git add $ARCHIVOS_QUE_CORREGISTE
$ g
it absorb --and-rebase (o) $ git abso
rb $ git rebase -i --autosquash master

git absorb identificará automáticamente qué commits es seguro modificar, y qué cambios en el índice pertenecen a cada uno de e

sos commits. Luego escribirá commits fixup! para cada uno de esos cambios. Puedes verificar su salida manualmente si no co
nfías en ella, y luego fusionar los fixups en tu rama de funcionalidad con la funcionalidad autosquash incorporada de git.

US

O
1.git add cualquier cambio que quieras absorber. Por diseño, git absorb solo considerará el contenido en el índice de
git.
2.git absorb. Esto creará una secuencia de commits en HEAD. Cada commit tendrá un mensaje fixup! que indicará el mensaje (si es único) o el SHA del commit en el que debe ser
fusionado.
3.Si estás satisfecho con la salida, git rebase -i --autosquash para fusionar los commits fixup! en sus predecesores. Puedes establecer la variable de entorno GIT_SEQUENCE_EDITOR si no necesitas editar el archivo TODO del
rebase.
4.Si no estás satisfecho (o si algo malo sucedió), git reset --soft PRE_ABSORB_HEAD al commit
pre-absorción para recuperar tu estado anterior. (También puedes encontrar el commit en cues
tión con git reflog.) Y si crees que git absorb es el culpable, por favor reporta un issue.

TAMAÑO DE LA

PILA

Cuando se ejecuta sin --base, git-absorb solo buscará candidatos a commits para fixup dentro de un cierto rango (por defecto 10). Si obtienes un error como

este: 
WARN se alcanzó el límite de la pila, límite:
10

edita tu .gitconfig local o global y agrega la siguiente

sección: 
[absorb]
    maxSta
ck=50 # O cualquier
otro valor razonab

UN FIXUP POR COMMIT

CORREGIBLE

Por defecto, git-absorb generará commits fixup separados para cada fragmento absorbible. Para generar siempre solo 1 commit fixup para todos los fragmentos que se absorben en el mismo commit, edita tu .gitconfig local o global y agrega la siguiente

sección: 
[absorb]
oneFi
xupPerComm
it = true

AUTO-ESTAGEAR TODOS LOS CAMBIOS SI NADA ESTÁ EN

STAGED

Por defecto, git-absorb solo considerará los archivos que has puesto en staged en el índice mediante git add. Sin embargo, a veces uno quiere intentar absorber todos los cambios, lo que requeriría ponerlos en staged primero mediante git add .. Para evitar este paso extra,

establece 
[absorb]
    au
toStageIfNothi
ngStaged = true

lo que le dice a git-absorb, cuando no hay cambios en staged, q

ue los ponga en staged automáticamente, cree commits fixup d
onde sea posible, y quite del índice los cambios restantes.

OBJETIVO DEL FIXUP SIEMPRE

SHA

Por defecto, git-absorb creará commits fixup con sus mensajes apuntando al resumen del commit objetivo, y si hay resúmenes duplicados, recurrirá a apuntar al SHA del objetivo. En su lugar, siempre puedes apuntar al SHA del objetivo

mediante: 
[absorb]

rgetAlways
SHA = true

TI

DESPRENDIDO
