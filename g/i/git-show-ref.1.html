NOMBRE

git-show-ref - Lista las referencias en un repositorio local

SINOPSIS

git show-ref [--head] [-d | --dereference]
             [-s | --hash[=<n>]] [--abbrev[=<n>]] [--branches] [--tags]
             [--] [<pattern>...]
git show-ref --verify [-q | --quiet] [-d | --dereference]
             [-s | --hash[=<n>]] [--abbrev[=<n>]]
             [--] [<ref>...]
git show-ref --exclude-existing[=<pattern>]
git show-ref --exists <ref>

DESCRIPCIÓN

Muestra las referencias disponibles en un repositorio local junto con los IDs de commit asociados. Los resultados se pueden filtrar usando un patrón y las etiquetas se pueden desreferenciar en IDs de objetos. Adicionalmente, se puede usar para probar si una referencia particular existe.

Por defecto, muestra las etiquetas, las cabeceras y las referencias remotas.

La forma --exclude-existing es un filtro que hace lo inverso. Lee las referencias de stdin, una referencia por línea, y muestra aquellas que no existen en el repositorio local.

La forma --exists se puede usar para comprobar la existencia de una sola referencia. Esta forma no verifica si la referencia resuelve a un objeto real.

Se recomienda el uso de esta utilidad en lugar de acceder directamente a los archivos bajo el directorio .git .

OPCIONES

--head

Muestra la referencia HEAD, incluso si normalmente sería filtrada.

--branches, --tags

Limita a ramas locales y etiquetas locales, respectivamente. Estas opciones no son mutuamente excluyentes; cuando se dan ambas, se muestran las referencias almacenadas en "refs/heads" y "refs/tags". Ten en cuenta que --heads es un sinónimo obsoleto para --branches y puede ser eliminado en el futuro.

-d, --dereference

Desreferencia también las etiquetas en IDs de objetos. Se mostrarán con ^{} añadido.

-s, --hash[=<n>]

Muestra solo el OID, no el nombre de la referencia. Cuando se combina con --dereference, la etiqueta desreferenciada se mostrará después del OID.

--verify

Habilita una comprobación de referencias más estricta al requerir una ruta de referencia exacta. Además de devolver un código de error de 1, también imprimirá un mensaje de error si --quiet no fue especificado.

--exists

Comprueba si la referencia dada existe. Devuelve un código de salida de 0 si existe, 2 si falta, y 1 en caso de que la búsqueda de la referencia falle con un error distinto a que la referencia falta.

--abbrev[=<n>]

Abrevia el nombre del objeto. Cuando se usa --hash, no tienes que decir --hash --abbrev; --hash=n bastaría.

-q, --quiet

No imprime ningún resultado a stdout. Se puede usar con --verify para comprobar silenciosamente si una referencia existe.

--exclude-existing[=<pattern>]

Hace que git show-ref actúe como un filtro que lee referencias de stdin de la forma ^(?:<anything>\s)?<refname>(?:\^{})?$ y realiza las siguientes acciones en cada una: (1) elimina ^{} al final de la línea si existe; (2) ignora si se proporciona un patrón y no coincide con el inicio de refname; (3) avisa si refname no es un nombre de referencia bien formado y lo salta; (4) ignora si refname es una referencia que existe en el repositorio local; (5) de lo contrario, imprime la línea.

<pattern>...

Muestra referencias que coincidan con uno o más patrones. Los patrones se comparan desde el final del nombre completo, y solo se comparan partes completas, por ejemplo master coincide con refs/heads/master, refs/remotes/origin/master, refs/tags/jedi/master pero no con refs/heads/mymaster o refs/remotes/master/jedi.

SALIDA

La salida tiene el formato:

<oid> SP <ref> LF

Por ejemplo,

$ git show-ref --head --dereference
832e76a9899f560a90ffd62ae2ce83bbeff58f54 HEAD
832e76a9899f560a90ffd62ae2ce83bbeff58f54 refs/heads/master
832e76a9899f560a90ffd62ae2ce83bbeff58f54 refs/heads/origin
3521017556c5de4159da4615a39fa4d5d2c279b5 refs/tags/v0.99.9c
6ddc0964034342519a87fe013781abf31c6db6ad refs/tags/v0.99.9c^{}
055e4ae3ae6eb344cbabf2a5256a49ea66040131 refs/tags/v1.0rc4
423325a2d24638ddcc82ce47be5e40be550f4507 refs/tags/v1.0rc4^{}
...

Cuando se usa --hash (y no --dereference), la salida tiene el formato:

<oid> LF

Por ejemplo,

$ git show-ref --branches --hash
2e3ba0114a1f52b47df29743d6915d056be13278
185008ae97960c8d551adcd9e23565194651b5d1
03adf42c988195b50e1a1935ba5fcbc39b2b029b
...

EJEMPLOS

Para mostrar todas las referencias llamadas "master", ya sean etiquetas o cabeceras o cualquier otra cosa, y sin importar cuán profundas estén en la jerarquía de nombres de referencias, usa:

        git show-ref master

Esto mostrará "refs/heads/master" pero también "refs/remote/other-repo/master", si tales referencias existen.

Cuando se usa el indicador --verify , el comando requiere una ruta exacta:

        git show-ref --verify refs/heads/master

solo coincidirá con la rama exacta llamada "master".

Si nada coincide, git show-ref devolverá un código de error de 1, y en el caso de la verificación, mostrará un mensaje de error.

Para scripts, puedes pedirle que sea silencioso con el indicador --quiet , lo que te permite hacer cosas como

        git show-ref --quiet --verify -- "refs/heads/$headname" ||
                echo "$headname is not a valid branch"

para comprobar si una rama particular existe o no (observa cómo no queremos realmente mostrar ningún resultado, y queremos usar el nombre de referencia completo para ello a fin de no desencadenar el problema con las coincidencias parciales ambiguas).

Para mostrar solo etiquetas, o solo cabeceras de ramas propias, usa --tags y/o --branches respectivamente (usar ambas significa que muestra etiquetas y ramas, pero no otras referencias aleatorias bajo el subdirectorio refs/).

Para hacer el desreferenciado automático de objetos de etiqueta, usa el indicador -d o --dereference , para que puedas hacer

        git show-ref --tags --dereference

para obtener un listado de todas las etiquetas junto con lo a lo que se desreferencian.
