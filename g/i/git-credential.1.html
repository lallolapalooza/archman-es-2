Paquete: git

GIT-CREDENTIAL(1) Manual de Git GIT-CREDENTIAL(1)

NOMBRE

git-credential - Recuperar y almacenar credenciales de usuario

SINOPSIS

'git credential' (fill|approve|reject|capability)

DESCRIPCIÓN

Git tiene una interfaz interna para almacenar y recuperar credenciales de ayudantes específicos del sistema, así como para solicitar al usuario nombres de usuario y contraseñas. El comando git-credential expone esta interfaz a scripts que pueden querer recuperar, almacenar o solicitar credenciales de la misma manera que Git. El diseño de esta interfaz scriptable modela la API interna de C; consulte credential.h para obtener más información sobre los conceptos.

git-credential toma una opción de "acción" en la línea de comandos (una de fill, approve o reject) y lee una descripción de credencial en la entrada estándar (ver FORMATO DE ENTRADA/SALIDA).

Si la acción es fill, git-credential intentará agregar los atributos "username" y "password" a la descripción leyendo archivos de configuración, contactando a cualquier ayudante de credenciales configurado o solicitando al usuario. Los atributos username y password de la descripción de credencial se imprimen luego en la salida estándar junto con los atributos ya proporcionados.

Si la acción es approve, git-credential enviará la descripción a cualquier ayudante de credenciales configurado, que puede almacenar la credencial para su uso posterior.

Si la acción es reject, git-credential enviará la descripción a cualquier ayudante de credenciales configurado, que puede borrar cualquier credencial almacenada que coincida con la descripción.

Si la acción es capability, git-credential anunciará las capacidades que soporta a la salida estándar.

Si la acción es approve o reject, no se debe emitir ninguna salida.

USO TÍPICO DE GIT-CREDENTIAL

Una aplicación que utiliza git-credential típicamente usará git credential siguiendo estos pasos:

1.Generar una descripción de credencial basada en el contexto.

Por ejemplo, si queremos una contraseña para https://example.com/foo.git, podríamos generar la siguiente descripción de credencial (no olvide la línea en blanco al final; le indica a git credential que la aplicación terminó de enviar toda la información que tiene):

protocol=https
host=example.com
path=foo.git
2.Pedirle a git-credential que nos dé un nombre de usuario y una contraseña para esta descripción. Esto se hace ejecutando git credential fill, alimentando la descripción del paso (1) a su entrada estándar. La descripción completa de la credencial (incluida la credencial en sí, es decir, el inicio de sesión y la contraseña) se producirá en la salida estándar, como:

protocol=https
host=example.com
username=bob
password=secr3t

En la mayoría de los casos, esto significa que los atributos dados en la entrada se repetirán en la salida, pero Git también puede modificar la descripción de la credencial, por ejemplo, eliminando el atributo path cuando el protocolo es HTTP(s) y credential.useHttpPath es falso.

Si git credential conocía la contraseña, este paso podría no haber implicado que el usuario escribiera realmente esta contraseña (el usuario podría haber escrito una contraseña para desbloquear el llavero en su lugar, o no se realizó ninguna interacción con el usuario si el llavero ya estaba desbloqueado) antes de devolver password=secr3t.

3.Usar la credencial (por ejemplo, acceder a la URL con el nombre de usuario y la contraseña del paso (2)), y ver si es aceptada.
4.Informar sobre el éxito o fracaso de la contraseña. Si la credencial permitió que la operación se completara con éxito, entonces puede ser marcada con la acción "approve" para indicarle a git credential que la reutilice en su próxima invocación. Si la credencial fue rechazada durante la operación, use la acción "reject" para que git credential solicite una nueva contraseña en su próxima invocación. En cualquier caso, a git credential se le debe proporcionar la descripción de la credencial obtenida del paso (2) (que también contiene los campos proporcionados en el paso (1)).

FORMATO DE ENTRADA/SALIDA

git credential lee y/o escribe (dependiendo de la acción utilizada) información de credenciales en su entrada/salida estándar. Esta información puede corresponder tanto a claves para las cuales git credential obtendrá la información de inicio de sesión (por ejemplo, host, protocolo, path), como a los datos de credenciales reales a obtener (nombre de usuario/contraseña).

La credencial se divide en un conjunto de atributos con nombre, con un atributo por línea. Cada atributo se especifica mediante un par clave-valor, separado por un signo = (igual), seguido de una nueva línea.

La clave puede contener cualquier byte excepto =, nueva línea o NUL. El valor puede contener cualquier byte excepto nueva línea o NUL. Una línea, incluida la nueva línea final, no puede exceder los 65535 bytes para permitir que las implementaciones analicen eficientemente.

Los atributos con claves que terminan en corchetes de array estilo C [] pueden tener múltiples valores. Cada instancia de un atributo multivaluado forma una lista ordenada de valores: el orden de los atributos repetidos define el orden de los valores. Un atributo multivaluado vacío (key[]=\n) actúa para borrar cualquier entrada previa y restablecer la lista.

En todos los casos, todos los bytes se tratan tal cual (es decir, no hay comillas, y no se puede transmitir un valor con nueva línea o NUL). La lista de atributos se termina con una línea en blanco o el final del archivo.

Git entiende los siguientes atributos:

protocol

El protocolo sobre el cual se utilizará la credencial (por ejemplo, https).

host

El nombre de host remoto para una credencial de red. Esto incluye el número de puerto si se especificó (por ejemplo, "example.com:8088").

path

La ruta con la que se utilizará la credencial. Por ejemplo, para acceder a un repositorio remoto https, esta será la ruta del repositorio en el servidor.

username

El nombre de usuario de la credencial, si ya tenemos uno (por ejemplo, desde una URL, la configuración, el usuario o desde un ayudante ejecutado previamente).

password

La contraseña de la credencial, si pedimos que se almacene.

password_expiry_utc

Las contraseñas generadas, como un token de acceso OAuth, pueden tener una fecha de caducidad. Al leer credenciales de los ayudantes, git credential fill ignora las contraseñas caducadas. Se representa como tiempo Unix UTC, segundos desde 1970.

oauth_refresh_token

Un token de actualización OAuth puede acompañar a una contraseña que sea un token de acceso OAuth. Los ayudantes deben tratar este atributo como confidencial, al igual que el atributo password. Git en sí mismo no tiene ningún comportamiento especial para este atributo.

url

Cuando este atributo especial es leído por git credential, el valor se analiza como una URL y se trata como si sus partes constituyentes hubieran sido leídas (por ejemplo, url=https://example.com se comportaría como si protocol=https y host=example.com hubieran sido proporcionados). Esto puede ayudar a los llamadores a evitar analizar URLs ellos mismos.

Tenga en cuenta que especificar un protocolo es obligatorio y si la URL no especifica un nombre de host (por ejemplo, "cert:///path/to/file") la credencial contendrá un atributo de hostname cuyo valor es una cadena vacía.

Los componentes que faltan en la URL (por ejemplo, no hay nombre de usuario en el ejemplo anterior) quedarán sin establecer.

authtype

Esto indica que se debe usar el esquema de autenticación en cuestión. Los valores comunes para HTTP y HTTPS incluyen basic, bearer y digest, aunque este último es inseguro y no debe usarse. Si se usa credential, esto puede establecerse en una cadena arbitraria adecuada para el protocolo en cuestión (generalmente HTTP).

Este valor no debe enviarse a menos que se proporcione la capacidad apropiada (ver más abajo) en la entrada.

credential

La credencial pre-codificada, adecuada para el protocolo en cuestión (generalmente HTTP). Si se envía esta clave, authtype es obligatorio, y username y password no se utilizan. Para HTTP, Git concatena el valor de authtype y este valor con un solo espacio para determinar el encabezado Authorization.
