GITFORMAT-LOOSE(5) Manual de Git GITFORMAT-LOOSE(5)

NOMBRE

gitformat-loose - Formato de objeto suelto de Git

SINOPSIS

$GIT_DIR/objects/[0-9a-f][0-9a-f]/*

DESCRIPCIÓN

Los objetos sueltos son la forma en que Git almacena objetos individuales, donde cada objeto se escribe como un archivo separado.

A lo largo de la vida de un repositorio, los objetos se escriben generalmente como objetos sueltos inicialmente. Con el tiempo, estos objetos sueltos se compactarán en archivos de paquete mediante el mantenimiento del repositorio para mejorar el uso del espacio en disco y acelerar la búsqueda de estos objetos.

OBJETOS SUELTOS

Cada objeto suelto contiene un prefijo, seguido inmediatamente por los datos del objeto. El prefijo contiene <tipo> <tamaño>\0. <tipo> es uno de blob, tree, commit o tag y tamaño es el tamaño de los datos (sin el prefijo) como un entero decimal expresado en ASCII.

El contenido completo, prefijo y datos concatenados, se comprime luego con zlib y los datos comprimidos se almacenan en el archivo. El ID del objeto es el hash SHA-1 o SHA-256 (según corresponda) de los datos sin comprimir.

El archivo para el objeto suelto se almacena en el directorio objects, con los dos primeros caracteres hexadecimales del ID del objeto siendo el directorio y los caracteres restantes siendo el nombre del archivo. Esto se hace para fragmentar los datos y evitar que demasiados archivos estén en un solo directorio, ya que algunos sistemas de archivos tienen un rendimiento deficiente con muchos elementos en un directorio.

Como ejemplo, el árbol vacío contiene los datos (cuando no están comprimidos) tree 0\0 y, en un repositorio SHA-256, tendría el ID del objeto 6ef19b41225c5369f1c104d45d8d85efa9b057b53b14b4b9b939dd74decc5321 y se almacenaría en $GIT_DIR/objects/6e/f19b41225c5369f1c104d45d8d85efa9b057b53b14b4b9b939dd74decc5321.

De manera similar, un blob que contenga los contenidos abc tendría los datos sin comprimir de blob 3\0abc.
