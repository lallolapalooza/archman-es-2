NOMBRE

git-annex-repair - recuperar repositorio git dañado

SINOPSIS

git annex repair

DESCRIPCIÓN

Esto puede reparar muchos de los problemas con los repositorios git que git fsck detecta, pero que no soluciona por sí mismo. Es útil si un repositorio ha quedado gravemente dañado. Una forma en que esto puede suceder es si un repositorio utilizado por git-annex está en una unidad extraíble que se desconecta en el momento equivocado.

Este comando puede usarse realmente dentro de repositorios git que no usan git-annex en absoluto; cuando se usa en un repositorio que usa git-annex, realiza reparaciones adicionales de la rama git-annex.

Funciona eliminando cualquier objeto corrupto del repositorio git, y recuperando todos los objetos faltantes que pueda de los remotos del repositorio.

Si eso no es suficiente para recuperar completamente el repositorio, también puede restablecer las ramas a commits anteriores a la corrupción, eliminar ramas que ya no están disponibles debido a la pérdida de datos y eliminar cualquier archivo faltante del índice. Solo hará esto si se ejecuta con la opción --force, ya que eso reescribe el historial y descarta los datos perdidos. Tenga en cuenta que la opción --force nunca toca las etiquetas, incluso si ya no son utilizables debido a datos perdidos.

Después de ejecutar este comando, probablemente querrá ejecutar git fsck para verificar que ha reparado el repositorio. Tenga en cuenta que fsck puede seguir quejándose de objetos referenciados por el reflog o el stash, si no pudieron ser recuperados. Este comando no intenta limpiar ni el reflog ni el stash.

También es una buena idea ejecutar git annex fsck --fast después de este comando, para asegurarse de que la rama git-annex refleje la realidad.

OPCIONES

--force
Habilita acciones de reparación que implican la eliminación de datos que se han perdido debido a la corrupción del repositorio git.
También se pueden usar las opciones comunes de git-annex(1).
