NOMBRE

git-check-ignore - Depurar archivos gitignore / excluidos

SINOPSIS

git check-ignore [<opciones>] <ruta_archivo>...
git check-ignore [<opciones>] --stdin

DESCRIPCIÓN

Para cada ruta de archivo proporcionada a través de la línea de comandos o desde un archivo a través de --stdin, comprueba si el archivo está excluido por .gitignore (u otros archivos de entrada para el mecanismo de exclusión) y muestra la ruta si está excluida.

Por defecto, los archivos rastreados no se muestran en absoluto ya que no están sujetos a las reglas de exclusión; pero véase '--no-index'.

OPCIONES

-q, --quiet

No muestres nada, solo establece el estado de salida. Esto solo es válido con una ruta de archivo única.

-v, --verbose

En lugar de mostrar las rutas que están excluidas, para cada ruta que coincide con un patrón de exclusión, muestra el patrón de exclusión junto con la ruta. (Coincidir con un patrón de exclusión generalmente significa que la ruta está excluida, pero si el patrón comienza con "!" entonces es un patrón negado y coincidir con él significa que la ruta NO está excluida).

Para las reglas de precedencia dentro y entre las fuentes de exclusión, véase gitignore(5).

--stdin

Lee las rutas de archivo desde la entrada estándar, una por línea, en lugar de desde la línea de comandos.

-z

El formato de salida se modifica para ser analizable por máquina (ver más abajo). Si también se proporciona --stdin, las rutas de entrada se separan con un carácter NUL en lugar de un carácter de nueva línea.

-n, --non-matching

Muestra las rutas dadas que no coinciden con ningún patrón. Esto solo tiene sentido cuando --verbose está habilitado, de lo contrario, no sería posible distinguir entre las rutas que coinciden con un patrón y las que no.

--no-index

No mires en el índice al realizar las comprobaciones. Esto puede usarse para depurar por qué una ruta se convirtió en rastreada por ej., git add . y no fue ignorada por las reglas como esperaba el usuario o al desarrollar patrones que incluyen negación para coincidir con una ruta agregada previamente con git add -f.

SALIDA

Por defecto, cualquier ruta de archivo dada que coincida con un patrón de ignorado se mostrará, una por línea. Si ningún patrón coincide con una ruta dada, no se mostrará nada para esa ruta; esto significa que la ruta no será ignorada.

Si se especifica --verbose, la salida es una serie de líneas con el formato:

<fuente> <DOS PUNTOS> <número_línea> <DOS PUNTOS> <patrón> <TAB> <ruta_archivo>

<ruta_archivo> es la ruta de un archivo que se está consultando, <patrón> es el patrón coincidente, <fuente> es el archivo fuente del patrón y <número_línea> es el número de línea del patrón dentro de esa fuente. Si el patrón contenía un prefijo "!" o un sufijo "/", se conservará en la salida. <fuente> será una ruta absoluta cuando se refiera al archivo configurado por core.excludesFile, o relativa a la raíz del repositorio cuando se refiera a .git/info/exclude o a un archivo de exclusión por directorio.

Si se especifica -z, las rutas de archivo en la salida se delimitan por el carácter nulo; si también se especifica --verbose, entonces los caracteres nulos también se usan en lugar de dos puntos y tabulaciones:

<fuente> <NULO> <número_línea> <NULO> <patrón> <NULO> <ruta_archivo> <NULO>

Si se especifican -n o --non-matching, también se mostrarán las rutas de archivo no coincidentes, en cuyo caso todos los campos de cada registro de salida, excepto <ruta_archivo>, estarán vacíos. Esto puede ser útil cuando se ejecuta de forma no interactiva, de modo que los archivos puedan transmitirse incrementalmente a STDIN de un proceso check-ignore en ejecución prolongada, y para cada uno de estos archivos, STDOUT indicará si ese archivo coincidió con un patrón o no. (Sin esta opción, sería imposible saber si la ausencia de salida para un archivo dado significaba que no coincidía con ningún patrón, o que la salida aún no se había generado).

El almacenamiento en búfer ocurre como se documenta en la opción GIT_FLUSH en git(1). El llamador es responsable de evitar interbloqueos causados por el llenado excesivo de un búfer de entrada o la lectura de un búfer de salida vacío.

ESTADO DE SALIDA

0

Una o más de las rutas proporcionadas están ignoradas.

1

Ninguna de las rutas proporcionadas está ignorada.

128

Se encontró un error fatal.
