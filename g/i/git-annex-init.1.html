NOMBRE

git-annex-init - inicializar git-annex

SINOPSIS

git annex init [descripción]

DESCRIPCIÓN

Hasta que un repositorio (o uno de sus remotos) haya sido inicializado, git-annex se negará a operar sobre él, para evitar usarlo accidentalmente en un repositorio que no estaba destinado a tener un anexo.

Es útil, pero no obligatorio, inicializar cada clonación nueva de un repositorio con su propia descripción. Si no proporcionas una, se generará usando el nombre de usuario, el nombre del host y la ruta.

Si algún remoto especial fue configurado con autoenable=true, esto también intentará habilitarlos. Ver git-annex-initremote(1). Para evitar eso, vuelve a habilitar un remoto con "autoenable=false", o márcalo como muerto (ver git-annex-dead(1)).

Este comando es completamente seguro, aunque generalmente inútil, de ejecutar dentro de un repositorio git-annex ya inicializado.

Un archivo .noannex de nivel superior impedirá que se use git-annex init en un repositorio. Esto es útil para repositorios que tengan una razón política para no usar git-annex. El contenido del archivo se mostrará al usuario que intente ejecutar git-annex init.

El comando git annex.pre-init-command o el hook pre-init-annex se ejecutan antes de la inicialización y también pueden salir con un valor no cero para evitar la inicialización, además de realizar otras configuraciones.

EJEMPLOS


# git annex add foo
git-annex: Primera ejecución: git-annex init
# git annex init
init ok
# git annex add foo
add foo ok

OPCIONES

--version=N
Fuerza la inicialización del repositorio utilizando una annex.version diferente a la predeterminada actual.
Cuando la versión dada no es compatible, pero se puede actualizar automáticamente a una versión más reciente, se usará esa versión más reciente en su lugar.
--autoenable
Solo habilita los remotos especiales que fueron configurados con autoenable=true, no inicialices nada más.
--no-autoenable
No habilites los remotos especiales que fueron configurados con autoenable=true.
--json
Habilita la salida JSON. Está destinada a ser analizada por programas que usan git-annex.
--json-error-messages
Los mensajes que normalmente se emitirían a la salida de error estándar se incluyen en el JSON en su lugar.
También se pueden usar las opciones comunes de git-annex(1).
