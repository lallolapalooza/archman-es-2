gnutls_certificate_set_rawpk_key_mem(3)

Paquete: gnutls

Licencias: GPL-3.0-or-later AND LGPL-2.1-or-later

gnutls_certificate_set_rawpk_key_mem(3) gnutls gnutls_certificate_set_rawpk_key_mem(3)

NOMBRE

gnutls_certificate_set_rawpk_key_mem - función de API

SINOPSIS

#include <gnutls/gnutls.h>

int gnutls_certificate_set_rawpk_key_mem(gnutls_certificate_credentials_t cred, const gnutls_datum_t * spki, const gnutls_datum_t * pkey, gnutls_x509_crt_fmt_t format, const char * pass, unsigned int key_usage, const char ** names, unsigned int names_length, unsigned int flags);

ARGUMENTOS

gnutls_certificate_credentials_t cred
es un tipo gnutls_certificate_credentials_t.
const gnutls_datum_t * spki
contiene una clave pública en bruto en formato PKIX.SubjectPublicKeyInfo.
const gnutls_datum_t * pkey
contiene una clave privada en bruto.
gnutls_x509_crt_fmt_t format
codificación de las claves. DER o PEM.
const char * pass
una contraseña opcional para desbloquear la clave privada pkey.
unsigned int key_usage
Una secuencia OR de flags GNUTLS_KEY_*.
const char ** names
es una matriz de nombres DNS pertenecientes a la clave pública (NULL si no hay ninguno).
unsigned int names_length
contiene la longitud de la lista de nombres.
unsigned int flags
una secuencia OR de gnutls_pkcs_encrypt_flags_t. Estos se aplican a la clave privada pkey.

DESCRIPCIÓN

Esta función establece un par de claves pública/privada en el tipo gnutls_certificate_credentials_t para ser utilizado en autenticación y/o cifrado. spki y privkey deben coincidir; de lo contrario, las firmas establecidas no podrán ser validadas. En caso de no coincidencia, esta función devuelve GNUTLS_E_CERTIFICATE_KEY_MISMATCH. Esta función debe llamarse una vez para el cliente, ya que actualmente no existe un mecanismo para determinar qué clave pública en bruto seleccionar para el par, cuando hay varias presentes. Las claves públicas en bruto múltiples para el servidor se pueden distinguir estableciendo los names.

Tenga en cuenta aquí que spki es una clave pública en bruto, tal como se define en RFC7250. Esto significa que no hay un certificado que contenga la clave pública y, por lo tanto, no hay un mecanismo directo para probar la autenticidad de esta clave. El par de claves se puede utilizar durante un handshake TLS, pero su autenticidad debe establecerse a través de un mecanismo diferente (por ejemplo, TOFU o huella digital conocida).

Los formatos admitidos son clave básica sin cifrar, PKCS8, PKCS12 y el formato openssl, y se detectarán automáticamente.

Si la clave pública en bruto y la clave privada se proporcionan en codificación PEM, las cadenas que contienen sus valores deben terminar con nulo.

El uso de la clave (tal como se define en la extensión X.509 (2.5.29.15)) se puede establecer explícitamente, ya que no hay una estructura de certificado alrededor de la clave para definir este valor. Consulte para más información gnutls_x509_crt_get_key_usage().

Tenga en cuenta que, de forma predeterminada, esta función devuelve cero en caso de éxito y un valor negativo en caso de error. Desde la versión 3.5.6, cuando el flag GNUTLS_CERTIFICATE_API_V2 se establece usando gnutls_certificate_set_flags(), devuelve un índice (mayor o igual a cero). Ese índice se puede utilizar en otras funciones para referirse al par de claves añadido.

DEVOLUCIONES

En caso de éxito, se devuelve GNUTLS_E_SUCCESS (0); en caso de que el par de claves no coincida, se devuelve GNUTLS_E_CERTIFICATE_KEY_MISMATCH; en otros casos de error, se devuelve un código de error negativo diferente.
