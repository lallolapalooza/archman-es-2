NOMBRE

gnutls_session_get_data2 - Función de API

SINOPSIS

#include <gnutls/gnutls.h>

int gnutls_session_get_data2(gnutls_session_t sesión, gnutls_datum_t * datos);

ARGUMENTOS

gnutls_session_t sesión
es un tipo gnutls_session_t.
gnutls_datum_t * datos
es un puntero a un dato que contendrá la sesión.

DESCRIPCIÓN

Devuelve los parámetros necesarios para soportar la reanudación. El cliente debe llamar a esta función y almacenar los datos de sesión devueltos. Una sesión puede reanudarse más tarde llamando a gnutls_session_set_data() con los datos devueltos. Tenga en cuenta que bajo TLS 1.3, se recomienda a los clientes que utilicen los parámetros de sesión solo una vez, para evitar que los observadores pasivos correlacionen las diferentes conexiones.

Los datos devueltos se asignan y deben liberarse usando gnutls_free().

Esta función fallará si se llama antes de completar el handshake. En caso de un inicio TLS falso, el handshake se completa solo después de que los datos se hayan recibido con éxito del par.

Bajo TLS1.3, la reanudación de sesión solo es posible después de que el cliente recibe un ticket de sesión. Para asegurarse de que se ha recibido dicho ticket, utilice gnutls_session_get_flags() y compruebe si tiene la marca GNUTLS_SFLAGS_SESSION_TICKET; si esta marca no está establecida, esta función esperará un nuevo ticket dentro de un viaje de ida y vuelta estimado, y si no se recibe, devolverá datos ficticios que no pueden conducir a la reanudación.

Para recibir notificaciones cuando el servidor reciba nuevos tickets, utilice gnutls_handshake_set_hook_function() para esperar los mensajes GNUTLS_HANDSHAKE_NEW_SESSION_TICKET. Cada llamada a gnutls_session_get_data2() después de recibir un ticket devolverá datos de reanudación de sesión correspondientes al último ticket recibido.

Tenga en cuenta que esta función, bajo TLS1.3, requiere que se establezca una devolución de llamada con gnutls_transport_set_pull_timeout_function() para un funcionamiento correcto. Había un error antes de la versión 3.6.10 que podía hacer que esta función fallara si no se establecía esa devolución de llamada. En versiones posteriores, si no se establece, la función devolverá un código de error exitoso, pero devolverá datos ficticios que no pueden conducir a una reanudación.

VALOR DEVUELTO

En caso de éxito, se devuelve GNUTLS_E_SUCCESS (0), de lo contrario, se devuelve un código de error.
