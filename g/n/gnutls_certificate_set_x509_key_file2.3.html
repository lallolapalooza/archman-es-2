gnutls_certificate_set_x509_key_file2(3)

Paquete: gnutls

gnutls_certificate_set_x509_key_file2(3) gnutls gnutls_certificate_set_x509_key_file2(3)

NOMBRE

gnutls_certificate_set_x509_key_file2 - Función de la API

SINOPSIS

#include <gnutls/gnutls.h>

int gnutls_certificate_set_x509_key_file2(gnutls_certificate_credentials_t res, const char * certfile, const char * keyfile, gnutls_x509_crt_fmt_t type, const char * pass, unsigned int flags);

ARGUMENTOS

gnutls_certificate_credentials_t res
es un tipo gnutls_certificate_credentials_t.
const char * certfile
es un archivo que contiene la lista de certificados (ruta) para la clave privada especificada, en formato PKCS7, o una lista de certificados
const char * keyfile
es un archivo que contiene la clave privada
gnutls_x509_crt_fmt_t type
es PEM o DER
const char * pass
es la contraseña de la clave
unsigned int flags
una secuencia OR de gnutls_pkcs_encrypt_flags_t

DESCRIPCIÓN

Esta función establece un par certificado/clave privada en el tipo gnutls_certificate_credentials_t. Esta función puede ser llamada más de una vez, en caso de que existan múltiples claves/certificados para el servidor. Para clientes que necesiten enviar más que su propio certificado de entidad final, por ejemplo, también un certificado de CA intermedio, el
certfile debe contener la cadena de certificados ordenada.

Tenga en cuenta que los nombres en el certificado proporcionado se considerarán al seleccionar el certificado apropiado para usar (en caso de múltiples pares de certificado/clave).

Esta función también puede aceptar URLs en keyfile y certfile. En ese caso, utilizará la clave privada y el certificado indicados por las URLs. Tenga en cuenta que las URLs compatibles son las indicadas por gnutls_url_is_supported(). Antes de GnuTLS 3.4.0, cuando se especificaba una URL, la parte pass se ignoraba y se tenía que registrar una devolución de llamada PIN; esto ya no es el caso en las versiones actuales.

En caso de que certfile se proporcione como una URL PKCS 11, entonces se importan el certificado y sus emisores presentes en el token (es decir, formando la cadena de confianza requerida).

Si esta función falla al cargar, la estructura res se encuentra en un estado indefinido; no debe reutilizarse para cargar otras claves o certificados.

Tenga en cuenta que, por defecto, esta función devuelve cero si tiene éxito y un valor negativo en caso de error. Desde la versión 3.5.6, cuando se establece el flag GNUTLS_CERTIFICATE_API_V2 usando gnutls_certificate_set_flags(), devuelve un índice (mayor o igual a cero). Ese índice puede usarse en otras funciones para referirse al par de claves agregado.

DEVUELVE

Si tiene éxito, esta función devuelve cero, y en caso contrario, un valor negativo en caso de error (ver arriba para modificar este comportamiento).
