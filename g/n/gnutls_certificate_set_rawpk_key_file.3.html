gnutls_certificate_set_rawpk_key_file(3)

Paquete: gnutls

Licencias: GPL-3.0-or-later AND LGPL-2.1-or-later

gnutls_certificate_set_rawpk_key_file(3) gnutls gnutls_certificate_set_rawpk_key_file(3)

NOMBRE

gnutls_certificate_set_rawpk_key_file - Función de API

SINOPSIS

#include <gnutls/gnutls.h>

int gnutls_certificate_set_rawpk_key_file(gnutls_certificate_credentials_t cred, const char * rawpkfile, const char * privkeyfile, gnutls_x509_crt_fmt_t format, const char * pass, unsigned int key_usage, const char ** names, unsigned int names_length, unsigned int privkey_flags, unsigned int pkcs11_flags);

ARGUMENTOS

gnutls_certificate_credentials_t cred
es un tipo gnutls_certificate_credentials_t.
const char * rawpkfile
contiene una clave pública cruda en formato PKIX.SubjectPublicKeyInfo.
const char * privkeyfile
contiene una ruta de archivo a una clave privada.
gnutls_x509_crt_fmt_t format
codificación de las claves. DER o PEM.
const char * pass
una contraseña opcional para desbloquear la clave privada privkeyfile.
unsigned int key_usage
una secuencia OR de flags GNUTLS_KEY_*.
const char ** names
es un array de nombres DNS que pertenecen a la clave pública (NULL si no hay ninguno).
unsigned int names_length
contiene la longitud de la lista de nombres.
unsigned int privkey_flags
una secuencia OR de gnutls_pkcs_encrypt_flags_t. Estos se aplican a la clave privada pkey.
unsigned int pkcs11_flags
uno de los flags de gnutls_pkcs11_obj. Estos se aplican a las URLs.

DESCRIPCIÓN

Esta función establece un par de claves pública/privada leídas de un archivo en el tipo gnutls_certificate_credentials_t para ser usado en autenticación y/o cifrado. spki y privkey deben coincidir, de lo contrario las firmas establecidas no podrán ser validadas. En caso de no coincidencia, esta función devuelve GNUTLS_E_CERTIFICATE_KEY_MISMATCH. Esta función debe ser llamada una vez para el cliente, ya que actualmente no hay un mecanismo para determinar qué clave pública cruda seleccionar para el oponente cuando hay múltiples presentes. Múltiples claves públicas crudas para el servidor pueden ser distinguidas estableciendo los names.

Tenga en cuenta aquí que spki es una clave pública cruda tal como se define en RFC7250. Significa que no hay un certificado circundante que contenga la clave pública y que, por lo tanto, no hay un mecanismo directo para probar la autenticidad de esta clave. El par de claves puede ser utilizado durante un apretón de manos TLS, pero su autenticidad debe establecerse a través de un mecanismo diferente (por ejemplo, TOFU o huella digital conocida).

Los formatos soportados son clave básica sin cifrar, PKCS8, PKCS12 y el formato openssl, y serán autodetectados.

Si la clave pública cruda y la clave privada se proporcionan en codificación PEM, entonces las cadenas que contienen sus valores deben ser terminadas en nulo.

El uso de la clave (tal como se define por la extensión X.509 (2.5.29.15)) se puede establecer explícitamente porque no hay una estructura de certificado alrededor de la clave para definir este valor. Ver para más información gnutls_x509_crt_get_key_usage().

Tenga en cuenta que, por defecto, esta función devuelve cero en caso de éxito y un valor negativo en caso de error. Desde la versión 3.5.6, cuando el flag GNUTLS_CERTIFICATE_API_V2 se establece usando gnutls_certificate_set_flags(), devuelve un índice (mayor o igual a cero). Ese índice puede ser utilizado en otras funciones para referirse al par de claves agregado.

DEVUELVE

En caso de éxito, se devuelve GNUTLS_E_SUCCESS (0), en caso de que el par de claves no coincida se devuelve GNUTLS_E_CERTIFICATE_KEY_MISMATCH, en otros casos erróneos se devuelve un código de error negativo diferente.
