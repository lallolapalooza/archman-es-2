gnutls_certificate_verify_peers3(3) gnutls gnutls_certificate_verify_peers3(3)

NOMBRE

gnutls_certificate_verify_peers3 - función de API

SINOPSIS

#include <gnutls/gnutls.h>

int gnutls_certificate_verify_peers3(gnutls_session_t session, const char * hostname, unsigned int * status);

ARGUMENTOS

gnutls_session_t session
es una sesión de gnutls
const char * hostname
es el nombre esperado del par; puede ser NULL
unsigned int * status
es la salida de la verificación

DESCRIPCIÓN

Esta función verificará el certificado del par y almacenará el estado en la variable status como un OR a nivel de bits de valores gnutls_certificate_status_t o cero si el certificado es de confianza. Tenga en cuenta que el valor en status se establece solo cuando el valor de retorno de esta función es éxito (es decir, el fallo en confiar en un certificado no implica un valor de retorno negativo). Las marcas de verificación predeterminadas utilizadas por esta función se pueden anular usando gnutls_certificate_set_verify_flags(). Consulte la documentación de gnutls_certificate_verify_peers2() para obtener detalles sobre el proceso de verificación.

Esta función tendrá en cuenta las respuestas OCSP apiladas (OCSP stapled) enviadas por el servidor, así como las siguientes extensiones de certificado X.509: Restricciones de Nombre, Uso de Clave y Restricciones Básicas (pathlen).

Si el hostname proporcionado no es NULL, esta función comparará el nombre de host en el certificado con él. La comparación seguirá las recomendaciones de RFC6125. Si los nombres no coinciden, se establecerá la bandera de estado GNUTLS_CERT_UNEXPECTED_OWNER.

Para evitar ataques de denegación de servicio, se establecen algunos límites superiores predeterminados con respecto al tamaño de la clave del certificado y el tamaño de la cadena. Para anularlos, use gnutls_certificate_set_verify_limits().

Tenga en cuenta que al usar claves públicas sin procesar (raw public-keys), la verificación no funcionará porque no hay un cuerpo de certificado correspondiente perteneciente a la clave sin procesar que pueda ser verificado. En ese caso, esta función devolverá GNUTLS_E_INVALID_REQUEST.

RETORNA

GNUTLS_E_SUCCESS (0) cuando se realiza la validación, o un código de error negativo en caso contrario. Un código de error exitoso significa que se debe verificar el parámetro status para obtener el estado de validación.
