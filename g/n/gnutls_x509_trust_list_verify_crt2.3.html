NOMBRE

gnutls_x509_trust_list_verify_crt2 - función de la API

SINOPSIS

#include <gnutls/x509.h>

int gnutls_x509_trust_list_verify_crt2(gnutls_x509_trust_list_t list, gnutls_x509_crt_t * cert_list, unsigned int cert_list_size, gnutls_typed_vdata_st * data, unsigned int elements, unsigned int flags, unsigned int * voutput, gnutls_verify_output_function func);

ARGUMENTOS

gnutls_x509_trust_list_t list
La lista
gnutls_x509_crt_t * cert_list
es la lista de certificados a verificar
unsigned int cert_list_size
es el tamaño de la lista de certificados
gnutls_typed_vdata_st * data
un array de datos tipificados
unsigned int elements
el número de elementos de datos
unsigned int flags
Marcas que pueden usarse para cambiar el algoritmo de verificación. Usar OR de las enumeraciones de gnutls_certificate_verify_flags.
unsigned int * voutput
contendrá la salida de la verificación del certificado.
gnutls_verify_output_function func
Si no es nulo, se llamará a cada elemento de la cadena de verificación con la salida.

DESCRIPCIÓN

Esta función intentará verificar la cadena de certificados dada y devolverá su estado. El parámetro voutput contendrá una secuencia OR de marcas de gnutls_certificate_status_t.

Cuando se proporciona una cadena de certificados de cert_list_size con más de un certificado, el estado de verificación se aplicará al primer certificado de la cadena que falló la verificación. El proceso de verificación comienza desde el final de la cadena (de CA a certificado final). El primer certificado de la cadena debe ser el certificado final, mientras que el resto de los miembros pueden estar ordenados o no.

Adicionalmente, se puede especificar un perfil de verificación de certificados de los definidos en gnutls_certificate_verification_profiles_t haciendo un OR del resultado de GNUTLS_PROFILE_TO_VFLAGS() con las marcas de verificación.

Son posibles parámetros de verificación adicionales a través de los tipos de datos de data; los tipos aceptables son GNUTLS_DT_DNS_HOSTNAME, GNUTLS_DT_IP_ADDRESS y GNUTLS_DT_KEY_PURPOSE_OID. El primero acepta como datos un nombre de host terminado en nulo, y el último un identificador de objeto terminado en nulo (por ejemplo, GNUTLS_KP_TLS_WWW_SERVER). Si se proporciona un nombre de host DNS, esta función comparará el nombre de host en el certificado final con el proporcionado. Si los nombres no coinciden, se establecerá la marca de estado GNUTLS_CERT_UNEXPECTED_OWNER. Además, considerará los certificados proporcionados con gnutls_x509_trust_list_add_named_crt().

Si se proporciona un OID de propósito de clave y el certificado final contiene la extensión de uso de clave extendido PKIX, se requerirá que coincida con el OID proporcionado o que esté marcado para cualquier propósito, de lo contrario, la verificación fallará con el estado GNUTLS_CERT_PURPOSE_MISMATCH.

DEVUELVE

En caso de éxito, se devuelve GNUTLS_E_SUCCESS (0), de lo contrario, un valor de error negativo. Tenga en cuenta que el fallo de la verificación no resultará en un código de error, solo se actualizará voutput.
