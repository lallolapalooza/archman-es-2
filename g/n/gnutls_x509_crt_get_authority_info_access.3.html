gnutls_x509_crt_get_authority_info_access(3) gnutls gnutls_x509_crt_get_authority_info_access(3)

NOMBRE

gnutls_x509_crt_get_authority_info_access - función de la API

SINOPSIS

#include <gnutls/x509.h>

int gnutls_x509_crt_get_authority_info_access(gnutls_x509_crt_t crt, unsigned int seq, int what, gnutls_datum_t * data, unsigned int * critical);

ARGUMENTOS

gnutls_x509_crt_t crt
Contiene el certificado
unsigned int seq
especifica el número de secuencia del descriptor de acceso (0 para el primero, 1 para el segundo, etc.)
int what
qué datos obtener, un tipo gnutls_info_access_what_t.
gnutls_datum_t * data
datos de salida que deben liberarse con gnutls_free().
unsigned int * critical
puntero al entero de salida que se establece en un valor distinto de cero si la extensión está marcada como crítica (puede ser NULL)

DESCRIPCIÓN

Tenga en cuenta que la función gnutls_x509_aia_get() y gnutls_x509_ext_import_aia() proporcionan una API más sencilla para acceder a los datos de información de la autoridad.

Esta función extrae la extensión de Acceso a la Información de la Autoridad (AIA), consulte la sección 4.2.2.1 de RFC 5280 para obtener más información. La extensión AIA contiene una secuencia de datos de AccessDescription (AD).

El parámetro de entrada seq se utiliza para indicar qué miembro de la secuencia interesa al llamante. El primer miembro es 0, el segundo miembro es 1 y así sucesivamente. Cuando el valor de seq está fuera de los límites, se devuelve GNUTLS_E_REQUESTED_DATA_NOT_AVAILABLE.

El tipo de datos devuelto en data se especifica a través de what, que debe ser valores de gnutls_info_access_what_t.

Si what es GNUTLS_IA_ACCESSMETHOD_OID, entonces data contendrá el OID del método de acceso (por ejemplo, "1.3.6.1.5.5.7.48.1").

Si what es GNUTLS_IA_ACCESSLOCATION_GENERALNAME_TYPE, data contendrá el tipo de GeneralName de la ubicación de acceso (por ejemplo, "uniformResourceIdentifier").

Si what es GNUTLS_IA_URI, data contendrá los datos de la URI de la ubicación de acceso. Solicitar este valor de what genera un error si la ubicación de acceso no es del tipo "uniformResourceIdentifier".

Si what es GNUTLS_IA_OCSP_URI, data contendrá la URI de OCSP. Solicitar este valor de what genera un error si el método de acceso no es 1.3.6.1.5.5.7.48.1 (es decir, OCSP), o si la ubicación de acceso no es del tipo "uniformResourceIdentifier". En ese caso se devolverá GNUTLS_E_UNKNOWN_ALGORITHM, y se debe incrementar seq y volver a llamar a esta función.

Si what es GNUTLS_IA_CAISSUERS_URI, data contendrá la URI de caIssuers. Solicitar este valor de what genera un error si el método de acceso no es 1.3.6.1.5.5.7.48.2 (es decir, caIssuers), o si la ubicación de acceso no es del tipo "uniformResourceIdentifier". En ese caso, se maneja como en GNUTLS_IA_OCSP_URI.

Se pueden asignar más valores de what en el futuro según sea necesario.

Si data es NULL, la función hace lo mismo sin almacenar los datos de salida, es decir, establecerá critical y realizará la comprobación de errores como de costumbre.

El valor del indicador crítico se devuelve en * critical. Proporcione un critical NULL si desea que la función se asegure de que la extensión no sea crítica, como lo requiere RFC 5280.

DEVUELVE

GNUTLS_E_SUCCESS si la operación es exitosa, GNUTLS_E_INVALID_REQUEST si el crt es inválido, GNUTLS_E_CONSTRAINT_ERROR si la extensión está marcada incorrectamente como crítica (use un critical no NULL para anular), GNUTLS_E_UNKNOWN_ALGORITHM si el OID solicitado no coincide (por ejemplo, al usar GNUTLS_IA_OCSP_URI), de lo contrario, un código de error negativo.
