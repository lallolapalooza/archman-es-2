ERRORES Y

ADVERTENCIAS

Los scripts deben tener cuidado al borrar nodos durante N{} y E{} bloques usando recorridos BFS y DFS, ya que estos dependen de pilas y colas de

nodos.

Cuando el programa se da como un argumento de línea de comandos, se produce la interpretación habitual del shell, lo que puede afectar algunos de los nombres especiales en gvpr. Para evitar esto, es mejor envolver el programa entre comillas

simples.

Si las constantes de cadena contienen metacaracteres de patrón que desea escapar para evitar la coincidencia de patrones, probablemente serán necesarias dos barras invertidas, ya que una sola barra invertida se perderá cuando la cadena se escanee originalmente. Usualmente, es más simple usar strcmp para evitar la coincidencia de

patrones.

A partir del 24 de abril de 2008, gvpr cambió a usar una nueva biblioteca de grafos subyacente, que usa el modelo más simple en el que solo hay una copia de un nodo, no una copia para cada subgrafo que lo contenga lógicamente. Esto significa que los iteradores como nxtnode no pueden recorrer un subgrafo usando solo un argumento de nodo. Por esta razón, el recorrido de subgrafos requiere nuevas funciones terminadas en "_sg", que también toman un argumento de subgrafo. Las versiones sin ese sufijo siempre recorrerán el grafo

raíz.

Hay un único ámbito global, excepto para los parámetros formales de las funciones, e incluso estos pueden interferir con el sistema de tipos. Además, la extensión de todas las variables es toda la vida del programa. Podría ser preferible que el ámbito reflejara el anidamiento natural de las cláusulas, o que el programa al menos reiniciara las variables declaradas localmente. Por ahora, es aconsejable usar nombres distintos para todas las

variables.

Si una función termina con una instrucción compleja, como una instrucción IF, con cada rama haciendo un return, la comprobación de tipos puede fallar. Las funciones deben usar un return al

final.

La biblioteca expr no soporta valores de cadena de (char*)0. Esto significa que no podemos distinguir entre "" y (char*)0 claves de aristas. Para los propósitos de buscar y crear aristas, traducimos "" a (char*)0, ya que este último valor es necesario para buscar cualquier arista con una cabeza y una cola

coincidentes.

Relacionado con esto, las cadenas convertidas a enteros actúan como punteros a char, obteniendo el valor 0 o 1 dependiendo de si la cadena consiste únicamente de ceros o no. Así, ((int)"2") evalúa a

1.

El lenguaje hereda los problemas habitu

ales de C como las referencias col
gantes y la confusión entre '=' y '=='.
