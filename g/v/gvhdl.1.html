DESCRIPCIÓ

N

FreeHDL es un conjunto de compilador/simulador para el lenguaje de descripción de hardware VHDL. Se admiten los estándares VHDL'93 y

VHDL'87.

FreeHDL traduce los archivos fuente originales de VHDL a C++. Luego, el código fuente C++ se puede compilar y enlazar con el kernel para construir el programa de simulación. Al iniciar el ejecutable generado se simulará el modelo VHDL correspondiente. El proceso de construcción real para generar el simulador a partir del código fuente VHDL es un proceso complejo que es gestionado por el script gv

hdl.

ARCHIVOS_VHDL es una lista de nombres de archivos fuente VHDL que deben terminar con .vhdl o .vhd. El primer nombre de archivo VHDL también determina el nombre del ejecutable del simulador. Es decir, el ejecutable final se nombrará después del primer archivo VHDL sin la extensión .vhdl o .vhd. Tenga en cuenta que los archivos objeto, así como el simulador, se crearán en el directorio

actual.

ARCHIVOS_OBJETO especifica una lista de archivos objeto que se enlazan con el ejecutable del simulador. gvhdl considera que todos los archivos que terminan con .o son archivos objeto. Típicamente, estos archivos objeto se

generan previamente (usando la opción -c) a partir de có
digo fuente VHDL durante un paso de compilación separado.

OPCIONE

S
-L VHDL
LIB
Ruta al directorio raíz de la biblioteca VHDL. Dentro de este directorio el compilador busca un archivo llamado v2cc.libs. El archivo de mapeo v2cc.libs traduce nombres de unidades de biblioteca a directorios. Tenga en cuenta que se puede proporcionar más de un
VHDLLIB.
-
g
Añade información de depuración al ejecutable. En detalle, esta opción asocia el código máquina generado con las líneas correspondientes en los archivos fuente
VHDL.
-
G
Añade información de depuración al ejecutable pero no asocia el código máquina con las líneas del código fuente VHDL. Esta opción se utiliza realmente para depurar el código C++
generado.
-
c
No generar el ejecutable del simulador. Usando esta opción, el compilador traduce el código fuente VHDL a ejecutables y los compila en código objeto, pero no genera un ejecutable final de simulador. Esta opción es especialmente útil para compilar paquetes
VHDL.
-l NOMBREBIBL
IOTECA
Asocia el código fuente VHDL a la biblioteca VHDL NOMBREBIBLIOTECA. Por defecto se usa el nombre de biblioteca WORK. Esta opción es especialmente importante si se desean construir componentes VHDL de varias bibliotecas VHDL en el simulador. Tenga en cuenta que para usar con éxito un componente VHDL de una biblioteca diferente a la biblioteca de trabajo actual, los archivos VHDL correspondientes deben ser encontrados por el compilador usando los mecanismos descritos en v2cc.libs. Además, los componentes deben compilarse con la opción apropiada -l

SOPORTADO

Actualmente, FreeHDL no soporta todo el estándar VHDL'93. La siguiente lista incompleta da una visión general de lo que actualmente no está

soportado:

- No se soporta la asociación individual de formales de tipo

compuesto.

- No se soportan las variables

compartidas.

- No se soportan los atributos transaction, quiet, stable y

delayed.

- No se soportan los atributos definidos por el

usuario.

- No se soportan los

grupos.

- No se soportan las asignaciones de señal

vigiladas.

- No se soportan las configuraciones

.

se pueden desact
ivar los drivers.

EJEMPLO

S

Us

e


gvhdl -c adder.

vhdl

para construir un archivo objeto para adder.vhdl. Tenga en cuenta que adder.vhdl puede contener varios modelos

VHDL.


gvhdl adder.

vhdl

generará un simulador para el último modelo VHDL encontrado en adder.vhdl. Sin embargo, en este caso, todos los componentes VHDL que se requieren para construir el simulador deben estar incluidos en el archivo fuente

VHDL.


gvhdl top.vhdl adder.o

--libieee

genera un simulador para el último modelo VHDL encontrado en top.vhdl compilando todos los modelos en top.vhdl y enlazando (el archivo objeto previamente generado) adder.o y las bibliotecas estándar IEEE al

ejecutable.


gvhdl -c -l mylib adder.

vhdl

construirá un archivo objeto que incluye todos los componentes proporcionados en adder.vhdl. Sin embargo, en este caso los compon

entes se asociarán con la biblioteca mylib en lugar del nombre de biblioteca por defecto work. Tenga en cuenta que la opción -
l solo afecta al código fuente C++ generado pero no altera el lugar donde se almacenan los archivos objeto o los ejecutables.

COMANDOS DE

SIMULACIÓN

Después de que se haya iniciado el simulador, se imprime en la pantalla un breve resumen de los comandos

disponibles:


c <número> : execute cycles = ejecuta <número> ciclos de simulación
n : next = ejecuta el siguiente ciclo de simulación
q : quit = sale de la simulación
r <tiempo> : run = ejecuta la simulación durante <tiempo>
d : dump = vuelca las señales
doff : dump off = deja de volcar las señales
don : dump on = continúa volcando las señales
s : show = muestra los valores de las señales
dv : dump var = vuelca una señal de la lista de señales
ds : dump show = muestra la lista de señales volcadas
nds : number show = muestra el número de señales volcadas
dc [-f <nombre_archivo>] [-t <escala_tiempo> <unidad_tiempo>] [-cfg <archivo_traducción>] [-q]
: configura el proceso de

volcado

Tenga en cuenta que las señales se vuelcan en un archivo (el nombre de archivo por defecto es "wave.dmp") en formato VCD. Este format

o de archivo debería ser aceptado por cualquier visor de formas de onda VCD. El nombre del archivo se establece como "wave.dmp"
pero puede cambiarse usando "dc -f <nuevo_nombre_archivo>". Sin embargo, asegúrese de ejecutar "dc -f ..." antes de ejecutar "d".

OPCIONES DE LÍNEA DE COMANDOS DEL

SIMULADOR

La simulación se puede controlar a través del parámetro de línea de comandos '-cmd "cmd1; cmd2; ..."' donde 'cmd1', 'cmd2', ... son comandos de simulación como se describe en la sección anterior. Tenga en cuenta que cada comando debe separarse con ';'. Por ejemplo,

ejecutar


./top -cmd "d;run 1000 ns;q;

"

iniciará el programa de simulación 'top', volcará todas las señales y ejecutará la simulación duran

te 1000 ns. Finalmente, la simulación se termina. En realidad, el último comando 'q;' es opcional ya
que el simulador se termina automáticamente tan pronto como se ha ejecutado el último comando.
