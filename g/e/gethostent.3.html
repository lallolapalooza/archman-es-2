DESCRIPCIÓN

Las funciones gethostbyname*(), gethostbyaddr*(), herror() y hstrerror() están obsoletas. Las aplicaciones deben usar getaddrinfo(3), getnameinfo(3) y gai_strerror(3) en su lugar.

La función sethostent() especifica, si stayopen es verdadero (1), que se debe usar un socket TCP conectado para las consultas al servidor de nombres y que la conexión debe permanecer abierta durante las consultas sucesivas. De lo contrario, las consultas al servidor de nombres usarán datagramas UDP.

La función endhostent() finaliza el uso de una conexión TCP para consultas al servidor de nombres.

La función gethostbyname() devuelve una estructura de tipo hostent para el host name dado. Aquí name es un nombre de host o una dirección IPv4 en notación de puntos estándar (como para inet_addr(3)). Si name es una dirección IPv4, no se realiza ninguna búsqueda y gethostbyname() simplemente copia name en el campo h_name y su equivalente en struct in_addr en el campo h_addr_list[0] de la estructura hostent devuelta. Si name no termina en un punto y la variable de entorno HOSTALIASES está establecida, primero se buscará en el archivo de alias apuntado por HOSTALIASES para name (ver hostname(7) para el formato del archivo). Se buscan el dominio actual y sus padres a menos que name termine en un punto.

La función gethostbyaddr() devuelve una estructura de tipo hostent para la dirección de host addr dada de tamaño size y tipo de dirección type. Los tipos de dirección válidos son AF_INET y AF_INET6 (definidos en <sys/socket.h>). El argumento de dirección de host es un puntero a una struct de un tipo dependiendo del tipo de dirección, por ejemplo un struct in_addr * (probablemente obtenido a través de una llamada a inet_addr(3)) para el tipo de dirección AF_INET.

La función (obsoleta) herror() imprime el mensaje de error asociado con el valor actual de h_errno en stderr.

La función (obsoleta) hstrerror() toma un número de error (típicamente h_errno) y devuelve la cadena de mensaje correspondiente.

Las consultas de nombres de dominio realizadas por gethostbyname() y gethostbyaddr() se basan en las fuentes configuradas del Name Service Switch (nsswitch.conf(5)) o en un servidor de nombres local (named(8)). La acción por defecto es consultar las fuentes configuradas del Name Service Switch (nsswitch.conf(5)), y si falla, un servidor de nombres local (named(8)).

Histórico

El archivo nsswitch.conf(5) es la forma moderna de controlar el orden de las búsquedas de hosts.

En glibc 2.4 y anteriores, la palabra clave order se usaba para controlar el orden de las búsquedas de hosts tal como se definía en /etc/host.conf (host.conf(5)).

La estructura hostent se define en <netdb.h> como sigue:


struct hostent {
    char  *h_name;            /* nombre oficial del host */
    char **h_aliases;         /* lista de alias */
    int    h_addrtype;        /* tipo de dirección del host */
    int    h_length;          /* tamaño de la dirección */
    char **h_addr_list;       /* lista de direcciones */
}
#define h_addr h_addr_list[0] /* para compatibilidad hacia atrás */

Los miembros de la estructura hostent son:

h_name
El nombre oficial del host.
h_aliases
Un array de nombres alternativos para el host, terminado por un puntero nulo.
h_addrtype
El tipo de dirección; actualmente siempre AF_INET o AF_INET6.
h_length
El tamaño de la dirección en bytes.
h_addr_list
Un array de punteros a direcciones de red para el host (en orden de bytes de red), terminado por un puntero nulo.
h_addr
La primera dirección en h_addr_list para compatibilidad hacia atrás.
