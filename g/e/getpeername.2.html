getpeername(2) Manual de llamadas al sistema getpeername(2)

NOMBRE

getpeername - obtener el nombre del socket del par conectado

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/socket.h>
int getpeername(int sockfd, struct sockaddr *restrict addr,
                socklen_t *restrict addrlen);

DESCRIPCIÓN

getpeername() devuelve la dirección del par conectado al socket sockfd, en el búfer apuntado por addr. El argumento addrlen debe inicializarse para indicar la cantidad de espacio apuntado por addr. Al regresar, contendrá el tamaño real del nombre devuelto (en bytes). El nombre se trunca si el búfer proporcionado es demasiado pequeño.

La dirección devuelta se trunca si el búfer proporcionado es demasiado pequeño; en este caso, addrlen devolverá un valor mayor que el que se suministró a la llamada.

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EBADF
El argumento sockfd no es un descriptor de archivo válido.
EFAULT
El argumento addr apunta a memoria que no forma parte del espacio de direcciones del proceso.
EINVAL
addrlen es inválido (por ejemplo, es negativo).
ENOBUFS
No había suficientes recursos disponibles en el sistema para realizar la operación.
ENOTCONN
El socket no está conectado.
ENOTSOCK
El descriptor de archivo sockfd no se refiere a un socket.

ESTANDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2001, SVr4, 4.4BSD (apareció por primera vez en 4.2BSD).

NOTAS

Para sockets de flujo, una vez que se ha realizado una llamada a connect(2), cualquiera de los sockets puede llamar a getpeername() para obtener la dirección del socket par. Por otro lado, los sockets de datagramas no requieren conexión. Llamar a connect(2) en un socket de datagramas simplemente establece la dirección del par para los datagramas salientes enviados con write(2) o recv(2). El llamador de connect(2) puede usar getpeername() para obtener la dirección del par que estableció anteriormente para el socket. Sin embargo, el socket par no es consciente de esta información, y llamar a getpeername() en el socket par no devolverá información útil (a menos que también se haya ejecutado una llamada a connect(2) en el par). Tenga en cuenta también que el receptor de un datagrama puede obtener la dirección del remitente cuando utiliza recvfrom(2).

VER TAMBIÉN

accept(2), bind(2), getsockname(2), ip(7), socket(7), unix(7)
