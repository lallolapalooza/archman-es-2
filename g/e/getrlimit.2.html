DESCRIPCIÓ

N

Las llamadas al sistema getrlimit() y setrlimit() obtienen y establecen límites de recursos. Cada recurso tiene un límite blando y uno duro asociados, tal como se define en la estructura r

limit.

El límite blando es el valor que el núcleo aplica para el recurso correspondiente. El límite duro actúa como un tope para el límite blando: un proceso sin privilegios solo puede establecer su límite blando a un valor en el rango desde 0 hasta el límite duro, y (irreversiblemente) reducir su límite duro. Un proceso privilegiado (en Linux: uno con la capacidad CAP_SYS_RESOURCE en el espacio de nombres de usuario inicial) puede realizar cambios arbitrarios en cualquiera de los valores de

límite.

El valor RLIM_INFINITY denota la ausencia de límite en un recurso (tanto en la estructura devuelta por getrlimit() como en la estructura pasada a setrlimit())

.

El argumento resource debe ser uno de los

siguientes:
RLIMIT_
AS
Este es el tamaño máximo de la memoria virtual (espacio de direcciones) del proceso. El límite se especifica en bytes y se redondea hacia abajo al tamaño de página del sistema. Este límite afecta a las llamadas a brk(2), mmap(2) y mremap(2), que fallan con el error ENOMEM al exceder este límite. Además, la expansión automática de la pila falla (y genera un SIGSEGV que mata al proceso si no se ha proporcionado una pila alternativa a través de sigaltstack(2)). Dado que el valor es un long, en máquinas con un long de 32 bits, o bien este límite es como máximo 2 GiB, o este recurso es
ilimitado.
RLIMIT_CO
RE
Este es el tamaño máximo de un archivo de volcado de memoria (ver core(5)) en bytes que el proceso puede volcar. Cuando es 0, no se crean archivos de volcado de memoria. Cuando es distinto de cero, los volcados más grandes se truncan a este
tamaño.
RLIMIT_C
PU
Este es un límite, en segundos, sobre la cantidad de tiempo de CPU que el proceso puede consumir. Cuando el proceso alcanza el límite blando, se le envía una señal SIGXCPU. La acción predeterminada para esta señal es terminar el proceso. Sin embargo, la señal puede ser capturada, y el manejador puede devolver el control al programa principal. Si el proceso continúa consumiendo tiempo de CPU, se le enviará SIGXCPU una vez por segundo hasta que se alcance el límite duro, momento en el que se le enviará SIGKILL. (Este último punto describe el comportamiento de Linux. Las implementaciones varían en cómo tratan a los procesos que continúan consumiendo tiempo de CPU después de alcanzar el límite blando. Las aplicaciones portables que necesiten capturar esta señal deben realizar una terminación ordenada al recibir por primera vez SIGXCP
U.)
RLIMIT_DA
TA
Este es el tamaño máximo del segmento de datos del proceso (datos inicializados, datos no inicializados y heap). El límite se especifica en bytes y se redondea hacia abajo al tamaño de página del sistema. Este límite afecta a las llamadas a brk(2), sbrk(2) y (desde Linux 4.7) mmap(2), que fallan con el error ENOMEM al encontrar el límite blando de este
recurso.
RLIMIT_FSI
ZE
Este es el tamaño máximo en bytes de los archivos que el proceso puede crear. Los intentos de extender un archivo más allá de este límite resultan en la entrega de una señal SIGXFSZ. Por defecto, esta señal termina un proceso, pero un proceso puede capturar esta señal en su lugar, en cuyo caso la llamada al sistema correspondiente (por ejemplo, write(2), truncate(2)) falla con el error EFBI
G.
RLIMIT_LOCKS (Linux 2.4.0 a Linux 2.4.
24)
Este es un límite sobre el número combinado de bloqueos flock(2) y arrendamientos fcntl(2) que este proceso puede
establecer.
RLIMIT_MEMLO
CK
Este es el número máximo de bytes de memoria que pueden ser bloqueados en la RAM. Este límite se redondea efectivamente hacia abajo al múltiplo más cercano del tamaño de página del sistema. Este límite afecta a mlock(2), mlockall(2) y a la operación mmap(2) MAP_LOCKED. Desde Linux 2.6.9, también afecta a la operación shmctl(2) SHM_LOCK, donde establece un máximo sobre el total de bytes en segmentos de memoria compartida (ver shmget(2)) que pueden ser bloqueados por el ID de usuario real del proceso llamante. Los bloqueos shmctl(2) SHM_LOCK se contabilizan por separado de los bloqueos de memoria por proceso establecidos por mlock(2), mlockall(2) y mmap(2) MAP_LOCKED; un proceso puede bloquear bytes hast

Antes de Linux 2.6.9, este límite controlaba la cantidad de memoria que podía ser bloqueada por un proceso privileg
iado. Desde Linux 2.6.9, no se imponen límites sobre la cantidad de memoria que un proceso privilegiado puede bloqu
ear, y este límite en su lugar gobierna la cantidad de memoria que un proceso sin privilegios puede bloquear.

La llamada al sistema específica de Linux prlimit() combina y extiende la funcionalidad de setrlimit() y getrlimit(). Puede ser usada tanto para establecer como para obtener los límites de recursos de un proceso

arbitrario.

El argumento resource tiene el mismo significado que para setrlimit() y getrlimi

t().

Si el argumento new_limit no es NULL, entonces la estructura rlimit a la que apunta es usada para establecer nuevos valores para los límites suave y duro de resource. Si el argumento old_limit no es NULL, entonces una llamada exitosa a prlimit() coloca los límites suave y duro previos de resource en la estructura rlimit apuntada por old_limit

.

El argumento pid especifica el ID del proceso sobre el cual la llamada va a operar. Si pid es 0, entonces la llamada se aplica al proceso que llama. Para establecer u obtener los recursos de un proceso distinto de sí mismo, el llamador debe tener la capacidad CAP_SYS_RESOURCE en el espacio de nombres de usuario del proceso cuyos límites de recursos están siendo cambiados, o los IDs de usuario real, efectivo y guardado del proceso destino deben coincidir con el ID de usuario real del llamador y los IDs de grupo real, efectivo y guardado d

NOTA

S

Un proceso hijo creado a través de fork(2) hereda los límites de recursos de su padre. Los límites de recursos se preservan a través de execve(

2).

Los límites de recursos son atributos por proceso que son compartidos por todos de los hilos en un

proceso.

Bajar el límite suave de un recurso por debajo del consumo actual de ese recurso por el proceso tendrá éxito (pero evitará que el proceso aumente aún más su consumo del recurso)

.

Se pueden establecer los límites de recursos del shell usando el comando incorporado ulimit (limit en csh(1)). Los límites de recursos del shell son heredados por los procesos que crea para ejecutar

comandos.

Desde Linux 2.6.24, los límites de recursos de cualquier proceso pueden ser inspected via /proc/pid/limits; see proc(

5).
