DESCRIPCIÓ

N

La aplicación getscu implementa un SCU para la Clase de Servicio de Consulta/Recuperación. getscu admite la funcionalidad de recuperación utilizando el mensaje C-GET. Envía claves de consulta a un SCP y espera respuestas con imágenes u otros objetos DICOM enviados mediante C-STORE. Como exige el servicio DICOM, C-GET y los mensajes C-STORE correspondientes se manejan en la misma asociación. Por lo tanto, los objetos solo pueden ser recibidos por getscu mismo y no pueden ser enviados a un tercero (movescu sería la herramien

ta adecuada pa
ra esta tarea).

NOTA

S

Cada archivo proporcionado en la línea de comandos será enviadoal SCP como parte de una solicitud C-GET. El archivo de consulta debe ser un conjunto de datos DICOM válido que contenga la parte del conjunto de datos de un mensaje C-GET-RQ. El archivo de consulta podría, por ejemplo, crearse con la utilidad dump2dcm a partir de un script como el siguiente

ejemplo: 
# solicitar todas las imágenes del paciente con ID=PAT001
(0008,0052) CS [PATIENT]     # QueryRetrieveLevel
(0010,0020) LO [PAT001]      #
PatientID

Otra posibilidad es usar la herramienta dcmodify para crear un archivo desde cero usando la opción --create-file con llamadas sucesivas a la opción --insert. Los atributos individuales pueden modificarse o complementarse usando la opción -k (o --key). Por ejemplo, el

comando: 
getscu -k "0010,0020=PAT002" caesar 5678 patqry.
dcm

cuando se envía al SCP caesar en el puerto TCP/IP 5678, hará que cualquier atributo PatientID en patqry.dcm tenga el valor 'PAT002'. Si tal atributo está presente, será reemplazado; si está ausente, será insertado. La opción -k puede aparecer más de una vez. La parte del valor (después del '=') puede estar ausente, lo que hace que el atributo se envíe con longitud cero. También es posible especificar secuencias, elementos y atributos anidados usando la opción -k. En estos casos, debe usarse una notación especial de "ruta". Los detalles se encuentran en la documentación de dcmodify

.

Si no se especifica ningún archivo en la línea de comandos, la consulta debe especificarse completamente con una o más opciones -k. Si se proporcionan varios archivos de consulta, getscu enviará múltiples solicitudes C-GET al

SCP.

Problemas

conocidos

getscu está destinado a ser utilizado como una herramienta de prueba para desarrolladores de software DICOM. El archivo de claves de consulta debe crearse manualmente basándose en el contenido del

SCP.

C-GET no es soportado por todos los SCPs de Consulta/Recuperación. El protocolo C-MOVE, que es implementado por la herramienta movescu, se encuentra con más frecuencia en la

práctica.

La aplicación getscu no intenta prevenir consultas incorrectas. En particular, las claves de consulta de una solicitud C-MOVE deben contener solo el at

ributo QueryRetrieveLevel y uno o más de los llamados "atributos de clave
única" (PatientID, StudyInstanceUID, SeriesInstanceUID y SOPInstanceUID).

REGISTR

O

El nivel de salida de registro de las diversas herramientas de línea de comandos y bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo errores y advertencias se escriben en el flujo de error estándar. Utilizando la opción --verbose también se informan mensajes informativos como detalles de procesamiento. La opción --debug se puede utilizar para obtener más detalles sobre la actividad interna, por ejemplo, con fines de depuración. Otros niveles de registro pueden seleccionarse utilizando la opción --log-level. En el modo --quiet solo se informan errores fatales. En tales eventos de error muy graves, la aplicación normalmente terminará. Para más detalles sobre los diferentes niveles de registro, ver la documentación del módulo

"oflog".

En caso de que la salida de registro deba escribirse en un archivo (opcionalmente con rotación de archivos de registro), en syslog (Unix) o en el registro de eventos (Windows), se puede utilizar la opción --log-config. Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o la aplicación donde se generan. Un archivo de configuración de ejemplo se proporciona en <etcdir>/l

ogger
.cfg.

LÍNEA DE

COMANDOS

Todas las herramientas de línea de comandos utilizan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos finales indican que se permiten múltiples valores (1-n), una combinación de ambos significa de 0 a n

valores.

Las opciones de línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Normalmente, el orden y la posición de las opciones de línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes se utiliza la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix

comunes.

Además, se pueden especificar uno o más archivos de comandos utilizando un signo '@' como prefijo del nombre de archivo (por ejemplo, @command.txt). Tal argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre dos comillas) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comando no puede contener otro archivo de comando. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (un ejemplo se proporciona en el archivo <datadir>/du

mppat
.txt).

ENTORN

O

La utilidad getscu intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH. Por defecto, es decir, si la variable de entorno DCMDICTPATH no está establecida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté integrado en la aplicación (por defecto en Windows)

.

Se debe preferir el comportamiento por defecto y la variable de entorno DCMDICTPATH solo debe usarse cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix en el que un dos puntos (":") separa las entradas. En sistemas Windows, se usa un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH. Es un error s
