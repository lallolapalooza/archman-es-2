DESCRIPCIÓ

N

La prioridad de planificación del proceso, grupo de procesos o usuario, como lo indican which y who, se obtiene con la llamada getpriority() y se establece con la llamada setpriority(). El atributo del proceso tratado por estas llamadas al sistema es el mismo atributo (también conocido como el valor "nice") que es tratado por nice(

2).

El valor which es uno de PRIO_PROCESS, PRIO_PGRP o PRIO_USER, y who se interpreta en relación con which (un identificador de proceso para PRIO_PROCESS, un identificador de grupo de procesos para PRIO_PGRP y un ID de usuario para PRIO_USER). Un valor cero para who denota (respectivamente) el proceso que llama, el grupo de procesos del proceso que llama o el ID de usuario real del proceso que

llama.

El argumento prio es un valor en el rango de -20 a 19 (pero véase NOTAS más abajo), con -20 siendo la prioridad más alta y 19 siendo la prioridad más baja. Los intentos de establecer una prioridad fuera de este rango se limitan silenciosamente al rango. La prioridad predeterminada es 0; valores más bajos dan a un proceso una prioridad de planificación más

alta.

La llamada getpriority() devuelve la prioridad más alta (valor numérico más bajo) que tiene cualquiera de los procesos especificados. La llamada setpriority() establece las prioridades de todos los procesos especificados al valor

especificado.

Tradicionalmente, solo un proceso privilegiado podía disminuir el valor nice (es decir, establecer una prioridad más alta). Sin embargo, desde Linux 2.6.12, un proceso no privilegiado puede disminuir el valor nice de un proceso de destino que tenga un límite suave RLIMIT_NICE adecuado; véase getrlimit(2) para

más
detalles.

VALOR DE

RETORNO

En caso de éxito, getpriority() devuelve el valor nice del hilo que llama, el cual puede ser un número negativo. En caso de error, devuelve -1 y establece errno para indicar el

error.

Dado que una llamada exitosa a getpriority() puede legítimamente devolver el valor -1, es necesario limpiar errno antes de la llamada, y luego comprobar errno después para determinar si -1 es un error o un valor

legítimo.

setpriority() devuelve 0 en caso de éxito. En caso de fallo, devuelve -1 y establece errno para ind

icar el
error.

Los detalles sobre la condición para EPERM dependen del sistema. La descripción anterior es lo que dice POSIX.1-2001, y parece ser seguida en todos los sistemas tipo System V. Los núcleos Linux anteriores a Linux 2.6.12 requerían que el ID de usuario real o efectivo del que llamaba coincidiera con el usuario real del proceso who (en lugar de su ID de usuario efectivo). Linux 2.6.12 y posteriores requieren que el ID de usuario efectivo del que llama coincida con el ID de usuario real o efectivo del proceso who. Todos los sistemas tipo BSD (SunOS 4.1.3, Ultrix 4.2, 4.3BSD, FreeBSD 4.3,

OpenBSD-2.5, ...) se comportan de la mi
sma manera que Linux 2.6.12 y posteriores.

NOTA

S

Para más detalles sobre el valor nice, véase sched(

7).

Nota: la adición de la función "autogroup" en Linux 2.6.38 significa que el valor nice ya no tiene su efecto tradicional en muchas circunstancias. Para más detalles, véase sched(

7).

Un hijo creado por fork(2) hereda el valor nice de su padre. El valor nice se conserva a través de execve(

2).

Diferencias entre la biblioteca C y el

núcleo

La llamada al sistema getpriority devuelve valores nice traducidos al rango 40..1, ya que un valor de retorno negativo se interpretaría como un error. La función envoltorio de glibc para getpriority() traduce el valor de vuelta según la fórmula unice = 20 - knice (así, el rango 40..1 devuelto p

or el núcleo corresponde a
l rango -20..19 como lo ve
el espacio de usuario).

ERRORES

CONOCIDOS

Según POSIX, el valor nice es una configuración por proceso. Sin embargo, bajo la implementación actual de POSIX threads en Linux/NP

TL, el valor nice es un atributo por hilo: diferentes hilos en el mismo proceso pueden tener diferentes valores nice. Las aplic
aciones portables deben evitar depender del comportamiento de Linux, el cual puede hacerse conforme a los estándares en el futuro.
