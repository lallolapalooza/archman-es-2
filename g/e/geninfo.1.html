--build-directory répertoire_de_build

Rechercher les fichiers de données . gcno dans répertoire_de_build plutôt que de les trouver uniquement à côté du fichier .o et/ou .gcda

correspondant. Par défaut, geninfo s'attend à trouver les fichiers .gcno et .gcda (tiempo de compilación y ejecución, respectivamente) en el mismo directorio.

Cuando se utiliza esta opción:

geninfo path1 --build-directory path2 ...

entonces geninfo buscará el archivo .gcno

path2/ruta/relativa/al/archivo/da_base.gcno

cuando encuentre el archivo .gcda

path1/ruta/relativa/al/archivo/da_base.gcda.

Utilice esta opción cuando haya utilizado la variable de entorno GCOV_PREFIX para dirigir el entorno de ejecución de gcc o llvm a escribir los archivos de datos de cobertura en un lugar distinto del directorio donde se compiló originalmente el código. Consulte gcc(1) y/o busque GCOV_PREFIX y GCOV_PREFIX_STRIP.

Esta opción se puede utilizar varias veces para especificar varios directorios alternativos donde buscar archivos .gcno. Esto puede ser útil si su aplicación utiliza código que se compila en muchas ubicaciones separadas, por ejemplo, bibliotecas comunes que son compartidas entre equipos.

--source-directory dirname
Añade 'dirname' a la lista de lugares donde buscar archivos fuente.

Para las rutas de archivos fuente relativas encontradas en los datos de gcov, posiblemente después de que se hayan aplicado sustituciones, geninfo buscará primero la ruta desde 'cwd' (donde se invocó genhtml) y luego desde cada nombre de directorio alternativo en el orden especificado. Se utilizará la primera ubicación que coincida.

Esta opción se puede especificar varias veces para añadir más directorios a la ruta de búsqueda de fuentes.

--branch-coverage

Recopila y retiene datos de cobertura de ramas.

Esto es equivalente a usar la opción "--rc branch_coverage=1"; la opción se añadió para que coincidiera mejor con la interfaz de genhml.

--mcdc-coverage

Recopila y retiene datos MC/DC.

Esto es equivalente a usar la opción "--rc mcdc_coverage=1". La captura de cobertura MC/DC es compatible con las versiones 14.2 y superiores de GCC, o las versiones 18.1 y superiores de LLVM.
Consulte llvm2lcov --help para obtener detalles sobre la captura de datos MC/DC en LLVM.

Consulte la sección MC/DC del manual genhtml(1) para obtener más detalles

--checksum
--no-checksum

Especifica si se deben generar datos de suma de verificación al escribir archivos de rastreo.

Utilice --checksum para habilitar la generación de sumas de verificación o --no-checksum para deshabilitarla. La generación de sumas de verificación está deshabilitada por defecto.

Cuando la generación de sumas de verificación está habilitada, se generará una suma de verificación para cada línea de código fuente y se almacenará junto con los datos de cobertura. Esta suma de verificación se utilizará para evitar intentos de combinar datos de cobertura de diferentes versiones de código fuente.

Si no trabaja con diferentes versiones de código fuente, deshabilite esta opción para acelerar el procesamiento de los datos de cobertura y reducir el tamaño de los archivos de rastreo.

Tenga en cuenta que esta opción está algo subsumida por la opción --version-script, que hace algo similar, pero a nivel de 'archivo completo'.

--compat mode=value[,mode=value,...]

Establece el modo de compatibilidad.

Utilice --compat para especificar que geninfo debe habilitar uno o más modos de compatibilidad al capturar datos de cobertura. Puede proporcionar una lista separada por comas de pares modo=valor para especificar los valores de varios modos.

Los valores válidos son:

on

Habilita el modo de compatibilidad.
off
Deshabilita el modo de compatibilidad.
auto
Aplica la autodetección para determinar si el modo de compatibilidad es necesario. Tenga en cuenta que la autodetección no está disponible para todos los modos de compatibilidad.

Si no se especifica ningún valor, se asume 'on' como valor predeterminado.

Los modos válidos son:

libtool

Habilite este modo si está capturando datos de cobertura para un proyecto que se compiló utilizando el mecanismo libtool. Consulte también --compat-libtool.

El valor predeterminado para esta configuración es 'on'.

hammer
Habilite este modo si está capturando datos de cobertura para un proyecto que se compiló utilizando una versión de GCC 3.3 que contiene una modificación (parche hammer) de versiones posteriores de GCC. Puede identificar un GCC 3.3 modificado comprobando el directorio de compilación de su proyecto en busca de archivos que terminen con la extensión .bbg. Las versiones no modificadas de GCC 3.3 nombran estos archivos como .bb.

El valor predeterminado para esta configuración es 'auto'.

split_crc
Habilite este modo si está capturando datos de cobertura para un proyecto que se compiló utilizando una versión de GCC 4.6 que contiene una modificación (checksums de función divididos) de versiones posteriores de GCC. Los mensajes de error típicos al ejecutar geninfo en datos de cobertura producidos por tales versiones de GCC son "out of memory" y "reached unexpected end of file".

El valor predeterminado para esta configuración es 'auto'.

--compat-libtool
--no-compat-libtool

Especifica si se debe habilitar el modo de compatibilidad libtool.

Utilice --compat-libtool para habilitar el modo de compatibilidad libtool o --no-compat-libtool para deshabilitarlo. El modo de compatibilidad libtool está habilitado por defecto.

Cuando el modo de compatibilidad libtool está habilitado, geninfo asumirá que el código fuente relacionado con un archivo .gcda ubicado en un directorio llamado ".libs" se puede encontrar en su directorio padre.

Si tiene directorios llamados ".libs" en su entorno de compilación pero no utiliza libtool, deshabilite esta opción para evitar problemas al capturar datos de cobertura.

--config-file archivo-config

Especifica un archivo de configuración a utilizar. Consulte el manual lcovrc(5) para obtener detalles sobre el formato del archivo y las opciones. Consulte también la entrada config_file en el mismo manual para obtener detalles sobre cómo incluir un archivo de configuración en otro.

Cuando se especifica esta opción, no se lee ni el archivo de configuración a nivel del sistema /etc/lcovrc, ni el archivo de configuración por usuario ~/.lcovrc.

Esta opción puede ser útil cuando existe la necesidad de ejecutar varias instancias de geninfo con diferentes opciones de archivo de configuración en paralelo.

Tenga en cuenta que esta opción debe especificarse por completo; no se admiten abreviaturas.

--profile [ archivo-datos-perfil ]

Indica a la herramienta que realice un seguimiento del rendimiento y otros datos de configuración. Si no se especifica el archivo-datos-perfil opcional, los datos del perfil se escriben en un archivo con el mismo nombre base que el --output-filename, con el sufijo .json añadido.

--derive-func-data

Calcula los datos de cobertura de funciones a partir de los datos de cobertura de líneas.

Utilice esta opción para recopilar datos de cobertura de funciones, incluso si la versión de la herramienta gcov instalada en el sistema de pruebas no proporciona estos datos. lcov derivará en su lugar los datos de cobertura de funciones a partir de los datos de cobertura de líneas e información sobre qué líneas pertenecen a una función.

--external
--no-external

Especifica si se deben capturar datos de cobertura para archivos fuente externos.

Los archivos fuente externos son aquellos que no se encuentran en uno de los directorios especificados por --directory o --base-directory. Utilice --external para incluir puntos de cobertura en archivos fuente externos al capturar datos de cobertura o --no-external para excluirlos. Si la ruta de su --directory o --base-directory contiene un enlace simbólico, el directorio real de destino no se considerará "interno" a menos que se utilice la opción --follow.

La opción --no-external es algo contundente; las opciones --exclude y --include proporcionan un control más detallado sobre qué datos de cobertura se incluyen y cuáles no, si la estructura de su proyecto es compleja y/o --no-external no hace lo que usted quiere.

Los datos de archivos fuente externos se incluyen por defecto.

-f
--follow

Sigue los enlaces al buscar archivos .gcda, así como para decidir si un directorio fuente particular (enlazado simbólicamente) es "interno" al proyecto o no - consulte la opción --no-external, anteriormente, para más información. La opción de línea de comandos --follow es equivalente a la opción de archivo de configuración geninfo_follow_symlinks. Consulte el manual de lcovrc(5) para más información.

--sort-input

Especifica si se deben ordenar los nombres de archivo antes de la captura y/o agregación. La ordenación reduce ciertos tipos de diferencias de salida dependientes del orden de procesamiento. Consulte la sección sort_input en el manual de lcovrc(5).

--gcov-tool herramienta

Especifica la ubicación de la herramienta gcov.

Si la opción --gcov-tool se utiliza varias veces, los argumentos se concatenan cuando se ejecuta la devolución de llamada, de forma similar a como funciona el parámetro -Xlinker de gcc. Esto proporciona una forma posiblemente más fácil de pasar argumentos a su herramienta, sin requerir un script de envoltorio. En ese caso, su devolución de llamada se ejecutará como: herramienta-0 'herramienta-1; ... 'nombre-archivo'. Tenga en cuenta que el segundo y subsiguientes argumentos se citan cuando se pasan a la shell, para manejar parámetros que contienen espacios.

El argumento --gcov-tool puede ser una cadena separada por split_char - consulte man(4) lcovrc.

Un uso común para esta opción es habilitar LLVM:

geninfo --gcov-tool llvm-cov --gcov-tool gcov ...
geninfo --gcov-tool llvm-cov,gcov ...

Nota: 'llvm-cov gcov nombre-archivo-da' generará salida en formato compatible con gcov según lo requerido por lcov.

Si no se especifica, se utiliza 'gcov' por defecto.

-h
--help

Imprime un breve texto de ayuda y luego sale.

--include patrón

Incluye archivos fuente que coinciden con patrón.

Utilice este modificador si desea incluir datos de cobertura solo para un conjunto particular de archivos fuente que coincidan con cualquiera de los patrones dados. Se pueden especificar varios patrones usando varios modificadores de línea de comandos --include. Los patrones se interpretarán como patrones comodín de shell (tenga en cuenta que pueden necesitar ser escapados adecuadamente para evitar que el shell los expanda primero).

Consulte la página del manual de lcov para obtener detalles

--exclude patrón

Excluye archivos fuente que coinciden con patrón.

Utilice este modificador si desea excluir datos de cobertura de un conjunto particular de archivos fuente que coincidan con cualquiera de los patrones dados. Se pueden especificar varios patrones

especificados usando múltiples opciones de línea de comandos --exclude. Los *patrones* se interpretarán como patrones comodín de shell (tenga en cuenta que pueden necesitar ser escapados adecuadamente para evitar que el shell los expanda primero). Nota: El patrón debe especificarse para que coincida con la ruta *absoluta* de cada archivo fuente.

Se puede combinar con la opción de línea de comandos --include. Si un archivo determinado coincide tanto con el patrón de inclusión como con el patrón de exclusión, el patrón de exclusión tendrá prioridad.

Consulte la página del manual de lcov para obtener más detalles.

--erase-functions *regexp*

Excluye datos de cobertura de líneas que se encuentran dentro de una función cuyo nombre coincide con la expresión regular proporcionada. Tenga en cuenta que este es un nombre codificado o decodificado, dependiendo de si se utiliza la opción --demangle-cpp o no.

Tenga en cuenta que esta opción requiere que utilice una versión de gcc lo suficientemente reciente como para admitir informes de línea de inicio/fin de función o que configure la herramienta para derivar los datos requeridos; consulte la discusión derive_function_end_line en la página del manual de lcovrc.

--substitute *regexp_pattern*

Aplica la expresión regular Perl *regexp_pattern* a los nombres de archivos fuente encontrados durante el procesamiento. Esto es útil cuando el nombre de la ruta informado por gcov no coincide con la estructura de su código fuente y el archivo no se encuentra. Consulte la página del manual de lcov para obtener más detalles.

--omit-lines *regexp*

Excluye datos de cobertura de líneas cuyo contenido coincide con *regexp*.

Utilice este modificador si desea excluir datos de cobertura de línea, rama y MC/DC para algunas construcciones particulares en su código (por ejemplo, alguna macro complicada). Consulte la página del manual de lcov para obtener detalles.

--forget-test-names

Si es distinto de cero, ignora los nombres de casos de prueba en el archivo de traza, es decir, trata todos los datos de cobertura como si provinieran del mismo caso de prueba. Esto puede mejorar el rendimiento y reducir el consumo de memoria si el usuario no necesita un resumen de cobertura por caso de prueba en los informes de cobertura.

Esta opción también se puede configurar permanentemente utilizando la opción del archivo de configuración forget_testcase_names.

--msg-log *[ nombre_archivo_log ]*

Especifica la ubicación para almacenar mensajes de error y advertencia (además de escribirlos en STDERR). Si no se especifica *nombre_archivo_log*, se utiliza la ubicación predeterminada.

--ignore-errors *errores*

Especifica una lista de errores después de los cuales continuar el procesamiento.

Utilice esta opción para especificar una lista de una o más clases de errores después de las cuales geninfo debe continuar el procesamiento en lugar de abortar. Tenga en cuenta que la herramienta generará una advertencia (en lugar de un error fatal) a menos que ignore el error dos (o más) veces:

geninfo ... --ignore-errors unused,unused

*errores* puede ser una lista separada por comas de las siguientes palabras clave:

branch:
el ID de rama (segundo campo en la entrada 'BRDA' del archivo .info) no sigue la secuencia esperada de enteros.
callback:
error de script de versión.
child:
el proceso hijo devolvió un código de salida distinto de cero durante la ejecución de --parallel. Esto generalmente indica que el hijo encontró un error: consulte el archivo de registro inmediatamente anterior a este mensaje. En contraste: el error parallel indica una excepción inesperada/no manejada en el proceso hijo, no un error 'típico' de lcov.
corrupt:
archivo corrupto/ilegible encontrado.
count:
se ha informado un número excesivo de mensajes de alguna clase: se suprimirán los mensajes posteriores de ese tipo. El límite se puede controlar mediante la variable 'max_message_count'. Consulte la página del manual de lcovrc.
deprecated:
está utilizando una opción obsoleta. Esta opción se eliminará en una próxima versión, por lo que debería cambiar sus scripts ahora.
empty:
el archivo de datos .info está vacío (por ejemplo, porque todo el código fue 'eliminado' o excluido.
excessive:
sus datos de cobertura contienen un recuento de 'hits' sospechosamente grande que es poco probable que sea correcto, lo que podría indicar un error en su cadena de herramientas.

Consulte la sección excessive_count_threshold en el manual lcovrc(5) para obtener más detalles.

fork:
no se pudo crear un proceso hijo durante la ejecución de --parallel.
Si se ignora el mensaje ( --ignore-errors fork ), genhtml esperará un breve período y luego reintentará la ejecución fallida.
Si ve errores continuos, desactive o reduzca el paralelismo, establezca un límite de memoria o encuentre un servidor más grande para ejecutar la tarea.
format:
se encontró sintaxis o valor inesperado en el archivo .info; por ejemplo, se encontró un número negativo o un número de línea cero.
gcov:
la herramienta gcov devolvió un código de retorno distinto de cero.
graph:
no se pudo encontrar el archivo de gráfico o está corrupto.
inconsistent:
sus datos de cobertura son internamente inconsistentes: hacen dos o más afirmaciones mutuamente excluyentes. Por ejemplo, alguna expresión está marcada como rama de excepción y no como rama de excepción. (Consulte el manual genhtml(1) para obtener más detalles.
internal:
se detectó un problema interno de la herramienta. Por favor, informe este error junto con un caso de prueba.
mismatch:
se encontró información incorrecta en los datos de cobertura y/o en el código fuente; por ejemplo, el código fuente contiene directivas de exclusión superpuestas.
missing:
el archivo no existe o no se puede leer.
negative:
se encontró un recuento de 'hits' negativo.

Tenga en cuenta que los recuentos negativos pueden ser causados por un error conocido de GCC; consulte


https://gcc.gnu.org/bugzilla/show_bug.cgi?id=68080

e intente compilar con "-fprofile-update=atomic". Necesitará recompilar, ejecutar sus pruebas y recapturar los datos de cobertura.

package:
un paquete de Perl requerido no está instalado en su sistema. En algunos casos, es posible ignorar este mensaje y continuar; sin embargo, ciertas funciones se deshabilitarán en ese caso.
parallel:
varios tipos de errores relacionados con el paralelismo, es decir, un proceso hijo murió debido a un error. El mensaje de error correspondiente aparece en el archivo de registro inmediatamente antes del error parallel.

La información de cobertura de ramas se almacena una línea por

rama:
BRDA:<número_de_línea>,[<excepción>]<bloque>,<rama>,
<tomada>

<número_de_línea> es el número de línea donde se encuentra la rama - y se espera que sea un entero distinto de cero.
<bloque> y <rama> sirven para definir de forma única una arista particular en el árbol de expresiones de un condicional particular encontrado en la línea asociada.
Dentro de una línea particular, <bloque> es un entero numerado desde cero sin huecos. Para algunos lenguajes y algunos estilos de codificación, solo habrá un bloque (valor de índice cero) en cualquier línea particular.
<rama> es una cadena que sirve para identificar de forma única una arista particular. Para algunos lenguajes y herramientas - por ejemplo, código C/C++ compilado con gcc o llvm - <rama> es un índice entero ordenado relacionado con el orden de recorrido del árbol de expresiones del condicional asociado. Para otros, puede ser una cadena significativa - ver abajo. <rama> aparece en la ventana emergente ('tooltip') de la rama asociada en la salida de genhtml - por lo que los valores legibles por humanos son útiles para los usuarios que intentan entender los resultados de cobertura - por ejemplo, para desarrollar pruebas de regresión adicionales, para mejorar la cobertura.
<tomada> es '-' si la expresión correspondiente nunca fue evaluada (por ejemplo, el bloque básico que contiene la rama nunca se ejecutó) o un número que indica cuántas veces se tomó esa rama.
<excepción> es 'e' (un solo carácter) si esta es una rama relacionada con el manejo de excepciones - y no está presente si la rama no está relacionada con excepciones. La identificación de ramas de excepción requiere soporte del compilador; nótese que las versiones de gcc anteriores a 9 no diferencian las ramas de excepción. Geninfo solo podrá identificar ramas de excepción si la versión de su cadena de herramientas es lo suficientemente nueva para soportar la

característica.

Los siguientes son ejemplos de registros de rama cuyos valores de expresión <rama> son cadenas legibles por

humanos.

BRDA:10,0,enable,1
BRDA:10,0,!enable,0 En
este caso, el código correspondiente de la línea 10 muy probablemente es similar a:

if (enable) {
...
}
de
modo que el caso de prueba asociado entró en el bloque ('enable' se evaluó como 'true').

en una expresión que contiene una llamada a función)

.

Nótese que herramientas en particular pueden o no suprimir expresiones que son estáticamente verdaderas o estáticamente falsas - por ejemplo, expresiones que usan parámetros de plantilla. Esto hace que sea potencialmente complicado comparar datos de cobertura generados por dos herramientas

diferentes.

La información MC/DC se almacena una línea por

MCDC:<número_de_línea>,<tamaño_de_grupo>,<sentido>,<tomada>,<índice>,<expresión>

<número_de_línea> es el número de línea donde se encuentra la condición - y se espera que sea un entero distinto de cero.
<tamaño_de_grupo> y <índice> sirven para definir de forma única un elemento particular en el árbol de expresiones de un condicional particular encontrado en la línea asociada.
Dentro de una línea y grupo particular, <índice> es un entero numerado desde cero hasta <tamaño_de_grupo> - 1 sin huecos. Para algunos lenguajes y algunos estilos de codificación, solo habrá un grupo en cualquier línea

sensibilizada.

<expresión> es una cadena arbitraria, destinada a ser una cadena significativa que ayude al usuario a entender el contexto de la condición - ver abajo. <expresión> aparece en la ventana emergente ('tooltip') de la condición MC/DC asociada en la salida de genhtml - por lo que los valores legibles por humanos son útiles para los usuarios que intentan entender los resultados de cobertura - por ejemplo, para desarrollar pruebas de regresión adicionales, para mejorar la cobertura.
Para un <tamaño_de_grupo> y <índice> dados, la <expresión> debería ser idéntica tanto para los sentidos "t" como

"f".
