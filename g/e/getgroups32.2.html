DESCRIPCIÓ

N

getgroups() devuelve los IDs de grupos suplementarios del proceso que llama en list. El argumento size debe establecerse al número máximo de elementos que pueden almacenarse en el búfer apuntado por list. Si el proceso que llama es miembro de más de size grupos suplementarios, se produce un

error.

No se especifica si el ID de grupo efectivo del proceso que llama está incluido en la lista devuelta. (Por lo tanto, una aplicación también debería llamar a getegid(2) y añadir o eliminar el valor resultante.

)

Si size es cero, list no se modifica, pero se devuelve el número total de IDs de grupos suplementarios del proceso. Esto permite al llamador determinar el tamaño de una lista asignada dinámicamente list a usar en una llamada posterior a getgroup

s().

setgroups() establece los IDs de grupos suplementarios para el proceso que llama. Se requieren los privilegios apropiados (véase la descripción del error EPERM, más abajo). El argumento size especifica el número de IDs de grupos suplementarios en el búfer apuntado por list. Un proceso puede eliminar todos sus grupos suplementarios con la

llamada: 


setgroups(0, (gid_t [0]){}
)

VERSIONE

Diferencias entre la biblioteca C y el

núcleo

A nivel del núcleo, los IDs de usuario y de grupo son un atributo por hilo. Sin embargo, POSIX requiere que todos los hilos de un proceso compartan las mismas credenciales. La implementación de hilos NPTL maneja los requisitos de POSIX proporcionando funciones envoltorio para las varias llamadas al sistema que cambian los UIDs y GIDs del proceso. Estas funciones envoltorio (incluyendo la de setgroups()) emplean una técnica basada en señales para asegurar que cuando un hilo cambia sus credenciales, todos los demás hilos del proceso también cambien sus credenciales. Para más detalles, véase npt

l(
7

NOTA

S

Un proceso puede tener hasta NGROUPS_MAX IDs de grupos suplementarios además del ID de grupo efectivo. La constante NGROUPS_MAX está definida en <limits.h>. El conjunto de IDs de grupos suplementarios se hereda del proceso padre y se conserva a través de un execve(

2).

El número máximo de IDs de grupos suplementarios puede encontrarse en tiempo de ejecución usando sysconf

(3): 


long ngroups_max;
ngroups_max = sysconf(_SC_NGROUPS_MAX)
;

El valor máximo de retorno de getgroups() no puede ser mayor que uno más que este valor. Desde Linux 2.6.4, el número máximo de IDs de grupos suplementarios también se expone a través del archivo de solo lectura específico de Linux, /proc/sys/kernel/ngroups_ma

x

#include <err.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

#define MALLOC(n, T)  ((T *) reallocarray(NULL, n, sizeof(T)))
static gid_t *agetgroups(size_t *ngids);
int
main(void)
{
    gid_t   *gids;
    size_t  n;
    gids = agetgroups(&n);
    if (gids == NULL)
        err(EXIT_FAILURE, "agetgroups");
    if (n != 0) {
        printf("%jd", (intmax_t) gids[0]);
        for (size_t i = 1; i < n; i++)
            printf(" %jd", (intmax_t) gids[i]);
    }
    puts("");
    free(gids);
    exit(EXIT_SUCCESS);
}
static gid_t *
agetgroups(size_t *ngids)
{
    int    n;
    gid_t  *gids;
    n = getgroups(0, NULL);
    if (n == -1)
        return NULL;
    gids = MALLOC(n, gid_t);
    if (gids == NULL)
        return NULL;
    n = getgroups(n, gids);
    if (n == -1) {
        free(gids);
        return NULL;
    }
    *ngids = n;
    return gids;
}
