getmntent(3) Manual de Funciones de Biblioteca getmntent(3)

NOMBRE

getmntent, setmntent, addmntent, endmntent, hasmntopt, getmntent_r - obtener una entrada del archivo descriptor del sistema de archivos

BIBLIOTECA

Biblioteca C estándar (libc,-lc)

SINOPSIS

#include <stdio.h>
#include <mntent.h>
FILE *setmntent(const char *path, const char *type);
struct mntent *getmntent(FILE *stream);
int addmntent(FILE *restrict stream,
              const struct mntent *restrict mnt);
int endmntent(FILE *streamp);
char *hasmntopt(const struct mntent *mnt, const char *opt);
/* Extensión GNU */
#include <mntent.h>
struct mntent *getmntent_r(int size;
              FILE *restrict streamp,
              struct mntent *restrict mntbuf,
              char buf[restrict size], int size);
Requisitos de la macro de prueba de características para glibc (ver feature_test_macros(7)):

getmntent_r():

    Desde glibc 2.19:
        _DEFAULT_SOURCE
    glibc 2.19 y anteriores:
        _BSD_SOURCE || _SVID_SOURCE

DESCRIPCIÓN

Estas rutinas se utilizan para acceder al archivo de descripción del sistema de archivos /etc/fstab y al archivo de descripción del sistema de archivos montado /etc/mtab.

La setmntent() función abre el archivo de descripción del sistema de archivos path y devuelve un puntero a archivo que puede ser utilizado por getmntent(). El argumento type es el tipo de acceso requerido y puede tomar los mismos valores que el argumento mode de fopen(3). El flujo devuelto debe cerrarse usando endmntent() en lugar de fclose(3).

La getmntent() función lee la siguiente línea del archivo de descripción del sistema de archivos desde stream y devuelve un puntero a una estructura que contiene los campos separados de una línea en el archivo. El puntero apunta a un área estática de memoria que es sobrescrita por llamadas subsecuentes a getmntent().

La addmntent() función añade la mntent estructura mnt al final del streamabierto.

La endmntent() función cierra el stream asociado con el archivo de descripción del sistema de archivos.

La hasmntopt() función escanea el campo mnt_opts (ver abajo) de la mntent estructura mnt buscando una subcadena que coincida con opt. Ver <mntent.h> y mount(8) para las opciones de montaje válidas.

La función reentrante getmntent_r() es similar a getmntent(), pero almacena la mntent estructura en el *mntbufproporcionado, y almacena las cadenas a las que apuntan las entradas en esa estructura en el array proporcionado buf de tamaño size.

La mntent estructura está definida en <mntent.h> como sigue:


struct mntent {
    char *mnt_fsname;   /* nombre del sistema de archivos montado */
    char *mnt_dir;      /* prefijo de ruta del sistema de archivos */
    char *mnt_type;     /* tipo de montaje (ver mntent.h) */
    char *mnt_opts;     /* opciones de montaje (ver mntent.h) */
    int   mnt_freq;     /* frecuencia de volcado en días */
    int   mnt_passno;   /* número de paso en fsck paralelo */
};

Dado que los campos en los archivos mtab y fstab están separados por espacios en blanco, se utilizan secuencias de escape octales para representar los caracteres espacio (\040), tabulador (\011), salto de línea (\012) y barra invertida (\\) en esos archivos cuando ocurren en una de las cuatro cadenas de una mntent estructura. Las rutinas addmntent() y getmntent() convertirán de la representación de cadena a la representación escapada y viceversa. Al convertir de la representación escapada, la secuencia \134 también se convierte a una barra invertida.

VALOR DEVUELTO

Las funciones getmntent() y getmntent_r() devuelven un puntero a la mntent estructura o NULL en caso de fallo.

La addmntent() función devuelve 0 en caso de éxito y 1 en caso de fallo.

La endmntent() función siempre devuelve 1.

La hasmntopt() función devuelve la dirección de la subcadena si se encuentra una coincidencia y NULL en caso contrario.

ESTÁNDARES

Ninguno.

HISTORIA

Las funciones no reentrantes provienen de SunOS 4.1.3. Una rutina getmntent_r() fue introducida en HP-UX 10, pero devuelve un int. El prototipo mostrado arriba es exclusivo de glibc.

System V también tiene una getmntent() función pero la secuencia de llamada difiere, y la estructura devuelta es diferente. Bajo System V /etc/mnttab se utiliza. 4.4BSD y Digital UNIX tienen una rutina getmntinfo(), un envoltorio alrededor de la llamada al sistema getfsstat().
