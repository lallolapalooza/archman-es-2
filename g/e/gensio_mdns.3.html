DESCRIPCIÓN

Estas funciones y tipos tratan con el descubrimiento de servicios mDNS (DNS Multicast) en una red local. Se pueden usar para anunciar servicios o encontrar servicios. Estas proporcionan una interfaz potente y fácil de usar para las capacidades de mDNS.

Para hacer estas cosas, primero debe usar gensio_alloc_mdns para asignar una estructura mdns con la estructura estándar de funciones de SO de gensio. Debe, por supuesto, hacer los bucles de espera de funciones de SO estándar y similares. Cuando haya terminado, debe liberar la estructura mdns con gensio_free_mdns. Tenga en cuenta que el código aún puede estar en las devoluciones de llamada de mDNS cuando la función de liberación retorna, tiene que asegurarse de esperar hasta que se llame a la devolución de llamada de finalización para saber que el código está fuera de todas las devoluciones de llamada. La devolución de llamada de finalización es opcional si no le importa. Tenga en cuenta también que el mDNS no se liberará (y no se llamará a done) hasta que se liberen todos los servicios y vigilancias para él.

Para las funciones restantes, el parámetro interface es el número de interfaz del sistema del dispositivo de red, y puede ser -1 para especificar todas las interfaces. El parámetro ipdomain es uno de los siguientes:

GENSIO_NETTYPE_UNSPEC
Tanto IPV4 como IPV4
GENSIO_NETTYPE_IPV4
Solo IPV4
GENSIO_NETTYPE_IPV6
Solo IPV6

Los parámetros name, type, domain y host son los campos estándar de mDNS, consulte la documentación sobre mDNS para más detalles. El parámetro txt es para los campos de texto de mDNS, y es un array estándar tipo argv.

Una vez que tenga una estructura mdns, puede anunciar un servicio en la red con ella usando gensio_mdns_add_service2. Ese servicio seguirá anunciándose hasta que llame a gensio_mdns_remove_service en él o su programa termine. Los parámetros domain y host generalmente deben ser NULL para tomar los valores predeterminados del sistema. El parámetro txt puede ser NULL si no tiene ninguno.

gensio_mdns_add_service2 toma una devolución de llamada, se llamará cuando el servicio haya sido registrado, y posiblemente con un nuevo nombre si hubo un conflicto de nombres. Puede pasar NULL para la devolución de llamada si no le importa. El parámetro de devolución de llamada puede tomar los siguientes valores:

GENSIO_MDNS_SERVICE_READY
El servicio ahora está registrado, y el nombre es el mismo que el nombre que pasó.
GENSIO_MDNS_SERVICE_READY_NEW_NAME
El servicio ahora está registrado, pero el nombre fue cambiado, estará en el parámetro info.
GENSIO_MDNS_SERVICE_REMOVED
Solicitó que el servicio fuera eliminado, la eliminación ahora está completa y la devolución de llamada no se llamará de nuevo.
GENSIO_MDNS_SERVICE_ERROR
Ocurrió un error como parte del registro del servicio.

Hay una función gensio_mdns_add_service para compatibilidad con versiones anteriores, es equivalente a llamar a gensio_mdns_add_service2 con una devolución de llamada NULL. No la use en código nuevo.

Para encontrar servicios en la red, agrega una vigilancia con gensio_mdns_add_watch. Cualquier servicio que coincida con su consulta será reportado con las funciones de devolución de llamada y todos los campos serán proporcionados en la devolución de llamada. Una vez que haya terminado con una vigilancia, puede llamar a gensio_mdns_remove_watch Tenga en cuenta que el código aún puede estar en las devoluciones de llamada de mDNS cuando la eliminación retorna, tiene que asegurarse de esperar hasta que se llame a la devolución de llamada de finalización para saber que el código está fuera de todas las devoluciones de llamada. La devolución de llamada de finalización es opcional si no le importa.

Algunas bibliotecas MDNS no soportan un NULL type para la vigilancia, y algunas sí. Para código portable, siempre especifique la vigilancia. Si la biblioteca no soporta un type nulo la función retornará GE_INCONSISTENT.

El estado de la devolución de llamada de vigilancia tiene tres valores posibles:

GENSIO_MDNS_WATCH_NEW_DATA
Esta es una nueva entrada que está siendo reportada.
GENSIO_MDNS_WATCH_DATA_GONE
Una entrada que fue reportada previamente como desaparecida.
GENSIO_MDNS_WATCH_ALL_FOR_NOW
Esto se llama una vez después de que se crea la vigilancia, reporta que todas las entradas actualmente conocidas han sido reportadas. Nuevas pueden ser reportadas en el futuro, pero esas habrán sido agregadas dinámicamente más tarde.

En la devolución de llamada de vigilancia, debe hacer copias de todas las cadenas y direcciones que se le pasan para conservarlas. Su existencia continua no está garantizada.

En las vigilancias, todos los campos de cadena pueden ser NULL, lo que significa que quiere tomar cualquier cosa en ese campo. Así que si todas las cadenas son NULL y la interfaz es -1 y el ipdomain es GENSIO_NETTYPE_UNSPEC obtendrá todos los campos.

VALORES DE CADENA PARA VIGILANCIAS

Los valores de cadena para la función de agregar vigilancia pueden usar expresiones regulares. Si la cadena comienza con '%', entonces los datos después de él son tratados como una expresión regular y los campos se comparan con ella. Consulte la página man regex(7) para más detalles.>

Se admiten comodines en algunas plataformas, pero su uso se desaconseja porque no están disponibles en algunas plataformas. Si la cadena comienza con '@', los datos que siguen se tratan como un comodín estándar. Consulte la página del manual glob(7) para obtener más detalles. Se devolverá un error si la plataforma no tiene soporte de coincidencia de comodines.

Si la cadena comienza con '=', se realiza una comparación exacta con los datos que siguen.

Si la cadena comienza con a-z0-9_ o un espacio, se realiza una comparación exacta de cadenas, incluyendo el primer carácter.

El comportamiento de la coincidencia para cualquier otro carácter inicial no está definido. En general, siempre debe usar '@', '%' o '=' como carácter inicial de todas sus cadenas de consulta para estar seguro.

VALORES DE RETORNO

Se devuelve cero en caso de éxito, o un error de gensio en caso de fallo.
