SINOPSI

S

Un Gemfile describe las dependencias de gemas requeridas para ejecutar el código Ruby

asociado.

Coloque el Gemfile en la raíz del directorio que contiene el código asociado. Por ejemplo, en una aplicación Rails, coloque el Gemfile en el mismo directorio que el Rake

fil
e.

SINTAXI

S

Un Gemfile se evalúa como código Ruby, en un contexto que pone a disposición

una serie de métodos utilizados para d

FUENTE

GLOBAL

En la parte superior del Gemfile, agregue una sola línea para la fuente de RubyGems que contiene las gemas listadas en el Gemfile

. 
source "ht
tps://rub
ygems.org"

Puede agregar solo una fuente global. En Bundler 1.13, agregar múltiples fuentes globales quedó obsoleto. La fuente DEBE ser un repositorio válido de

RubyGems.

Para usar más de una fuente de RubyGems, debe usar el bloque source

.

Una fuente se comprueba en busca de gemas siguiendo las heurísticas descritas en PRIORIDAD DE

FUENTE.

Nota sobre un comportamiento de la función obsoleta en Bundler 1.13: Si una gema se encuentra en más de una fuente global, Bundler imprimirá una advertencia después de instalar la gema indicando qué fuente se utilizó, y listando las otras fuentes donde la gema está disponible. Se puede seleccionar una fuente específica para las gemas que necesiten usar un repositorio no estándar, suprimiendo esta advertencia, usando la opción :source o el bloque source

.

GRUPO

S

Cada gema PUEDE especificar la pertenencia aen uno o más grupos. Cualquier gem que no especifique pertenencia a ningún grupo es colocado en el grupo por

El tiempo de ejecución de Bundler permite que sus dos métodos principales, Bundler.setup y Bundler.require, limiten su impacto a grupos

Bundler.
setup(:test) # solo configura el grupo _test_ (pero `no` _default_) Bundler.setup(:default, :test) # configura los grupos _default_ y _test_, pero no los demás # require requiere todas las gems de los grupos especificados Bun
dler.require # por defecto el grupo _default_ Bundler.require(:default) # idéntico Bundler.require(:default, :test) # requiere los grupos _default_ y _test_ Bundler.require(:test) # requiere el grupo _test_

La CLI de Bundler te permite especificar una lista de grupos cuyas gems bundle install no debe instalar con la opción without de

configuración.

Para especificar varios grupos a ignorar, especifica una lista de grupos separados por

espacios. 
bundle config set --local with
out test bundle config set --
local without development test

Además, llamar a Bundler.setup sin parámetros, o llamar a require "bundler/setup" configurará todos los grupos excepto los que hayas excluido mediante --without (ya que no están disponibles)

.

Ten en cuenta que en bundle install, bundler descarga y evalúa todas las gems, con el fin de crear una única lista canónica de todas las gems requeridas y sus dependencias. Esto significa que no puedes listar versiones diferentes de las mismas gems en diferentes grupos. Para más detalles, consulta Understanding Bundler https://bundler.i

E

Puedes seleccionar un repositorio alternativo de RubyGems para una gem usando la opción ':

source'. 
gem "some_internal_g

Esto fuerza a la gem a cargarse desde esta fuente e ignora la fuente global declarada en la parte superior del archivo. Si la gem no existe en esta fuente, no será

Bundler buscará las dependencias hijas de esta gem mirando primero en la fuente seleccionada para la gem principal, pero si no se encuentran allí, recurrirá a la fuente

Nota sobre un comportamiento de la función que se deprecó en Bundler 1.13: Seleccionar un repositorio fuente específico de esta manera también suprime la advertencia de gem ambigua descrita arriba en FUENTE GL

OBAL.

Usar la opción :source para una gem individual también hará que esa fuente esté disponible como una posible fuente global para cualquier otra gem que no especifique fuentes explícitas

asegures de que todas las demás gems en el Gemfile estén usando fuentes explícitas.

GEMSPE

C

El archivo .gemspec https://guides.rubygems.org/specification-reference/ es donde proporcionas metadatos sobre tu gem a Rubygems. Algunos atributos requeridos del Gemspec incluyen el nombre, la descripción y la página de inicio de tu gem. Aquí también especificas las dependencias que tu gem necesita para

ejecutarse.

Si deseas usar Bundler para ayudar a instalar dependencias para una gem mientras se está desarrollando, usa el método gemspec para obtener las dependencias listadas en el archivo .ge

mspec.

El método gemspec agrega cualquier dependencia de ejecución como requisitos de gem en el grupo por defecto. También agrega dependencias de desarrollo como requisitos de gem en el grupo development. Finalmente, agrega un requisito de gem sobre tu proyecto (path: '.'). En conjunto con Bundler.setup, esto te permite requerir archivos del proyecto en tu código de prueba como lo harías si el proyecto estuviera instalado como una gem; no necesitas manipular la ruta de carga manualmente ni requerir archivos del proyecto mediante rutas

relativas.

El método gemspec soporta las opciones opcionales :path, :glob, :name y :development_group, que controlan dónde busca bundler el .gemspec, el glob que usa para buscar el gemspec (por defecto: {,*,*/*}.gemspec), qué .gemspec con nombre usa (si hay más de uno presente), y en qué grupo se incluyen las dependencias de

desarrollo.

Cuando una dependencia de gemspec encuentra conflictos de versión durante la resolución, la versión local en desarrollo siempre será seleccionada -- incluso si hay versiones remotas que coinciden mejor con otros requisitos para la gem del

gems
pec.
