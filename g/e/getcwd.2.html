getcwd(3) Manual de Funciones de Biblioteca getcwd(3)

NOMBRE

getcwd, getwd, get_current_dir_name - obtener el directorio de trabajo actual

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
char *getcwd(char *buf, size_t size);
char *get_current_dir_name(void);
[[deprecated]] char *getwd(char buf[PATH_MAX]);
Requisitos de Macro de Prueba de Funciones para glibc (ver feature_test_macros(7)):

get_current_dir_name():

    _GNU_SOURCE

getwd():

    Desde glibc 2.12:
        (_XOPEN_SOURCE >= 500) && ! (_POSIX_C_SOURCE >= 200809L)
            || /* glibc >= 2.19: */ _DEFAULT_SOURCE
            || /* glibc <= 2.19: */ _BSD_SOURCE
    Antes de glibc 2.12:
        _BSD_SOURCE || _XOPEN_SOURCE >= 500

DESCRIPCIÓN

Estas funciones devuelven una cadena terminada en nulo que contiene una ruta absoluta que es el directorio de trabajo actual del proceso llamante. La ruta se devuelve como el resultado de la función y a través del argumento buf, si está presente.

La función getcwd() copia una ruta absoluta del directorio de trabajo actual a la matriz apuntada por buf, que tiene una longitud de size.

Si la longitud de la ruta absoluta del directorio de trabajo actual, incluyendo el byte nulo de terminación, excede los bytes size, se devuelve NULL y errno se establece en ERANGE; una aplicación debería comprobar este error y asignar un búfer más grande si es necesario.

Como extensión al estándar POSIX.1-2001, getcwd() de glibc asigna el búfer dinámicamente usando malloc(3) si buf es NULL. En este caso, el búfer asignado tiene la longitud size, a menos que size sea cero, cuando buf se asigna tan grande como sea necesario. El llamador debe free(3) el búfer devuelto.

get_current_dir_name() usará malloc(3) una matriz lo suficientemente grande para contener la ruta absoluta del directorio de trabajo actual. Si la variable de entorno PWD está configurada y su valor es correcto, se devolverá ese valor. El llamador debe free(3) el búfer devuelto.

getwd() no usa malloc(3) ninguna memoria. El argumento buf debe ser un puntero a una matriz de al menos PATH_MAX bytes. Si la longitud de la ruta absoluta del directorio de trabajo actual, incluyendo el byte nulo de terminación, excede los bytes PATH_MAX, se devuelve NULL y errno se establece en ENAMETOOLONG. (Tenga en cuenta que en algunos sistemas, PATH_MAX puede no ser una constante en tiempo de compilación; además, su valor puede depender del sistema de archivos, consulte pathconf(3).) Por razones de portabilidad y seguridad, el uso de getwd() está obsoleto.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven un puntero a una cadena que contiene la ruta del directorio de trabajo actual. En el caso de getcwd() y getwd(), este es el mismo valor que buf.

En caso de error, estas funciones devuelven NULL y errno se establece para indicar el error. El contenido de la matriz apuntada por buf no está definido en caso de error.

ERRORES

EACCES
Se denegó el permiso para leer o buscar un componente del nombre de archivo.
EFAULT
buf apunta a una dirección incorrecta.
EINVAL
El argumento size es cero y buf no es un puntero nulo.
EINVAL
getwd(): buf es NULL.
ENAMETOOLONG
getwd(): El tamaño de la cadena de ruta absoluta terminada en nulo excede los bytes PATH_MAX.
ENOENT
El directorio de trabajo actual ha sido eliminado.
ENOMEM
Falta de memoria.
ERANGE
El argumento size es menor que la longitud de la ruta absoluta del directorio de trabajo, incluido el byte nulo de terminación. Debe asignar una matriz más grande e intentarlo de nuevo.

VERSIONES

POSIX.1-2001 deja el comportamiento de getcwd() sin especificar si buf es NULL.

POSIX.1-2001 no define ningún error para getwd().

VERSIONES

Diferencias entre la biblioteca C y el kernel

En Linux, el kernel proporciona una llamada al sistema getcwd(), que las funciones descritas en esta página utilizarán si es posible. La llamada al sistema toma los mismos argumentos que la función de biblioteca del mismo nombre, pero se limita a devolver un máximo de PATH_MAX bytes. (Antes de Linux 3.12, el límite en el tamaño de la ruta devuelta era el tamaño de página del sistema. En muchas arquitecturas, PATH_MAX y el tamaño de página del sistema son ambos 4096 bytes, pero algunas arquitecturas tienen un tamaño de página mayor). Si la longitud de la ruta del directorio de trabajo actual excede este límite, la llamada al sistema falla con el error ENAMETOOLONG. En este caso, las funciones de la biblioteca recurren a una implementación alternativa (más lenta) que devuelve la ruta completa.

Tras un cambio en Linux 2.6.36, la ruta devuelta por la llamada al sistema getcwd() se prefijará con la cadena "(unreachable)" si el directorio actual no está debajo de la raíz del proceso actual (por ejemplo, porque el proceso estableció una nueva raíz del sistema de archivos usando chroot(2) sin cambiar su directorio actual a la nueva raíz). Dicho comportamiento también puede ser causado por un usuario sin privilegios al cambiar el directorio actual a otro espacio de nombres de montaje. Al tratar con rutas de fuentes no confiables, los llamadores de las funciones descritas en esta página (antes de glibc 2.27) o la llamada al sistema getcwd() en bruto deben considerar verificar si la ruta devuelta comienza con '/' o '(' para evitar malinterpretar una ruta inalcanzable como una ruta relativa.

HISTORIA

getcwd()
POSIX.1-2001.
getwd()
POSIX.1-2001, pero marcado como LEGACY. Eliminado en POSIX.1-2008. Usar getcwd() en su lugar.

En Linux, estas funciones utilizan la llamada al sistema getcwd() (disponible desde Linux 2.1.92). En sistemas más antiguos consultarían /proc/self/cwd. Si tanto la llamada al sistema como el sistema de archivos proc faltan, se llama a una implementación genérica. Solo en ese caso estas llamadas pueden fallar en Linux con EACCES.

.

NOTAS

Estas funciones se utilizan a menudo para guardar la ubicación del directorio de trabajo actual con el propósito de volver a él más tarde. Abrir el directorio actual (".") y llamar a fchdir(2) para regresar es generalmente una alternativa más rápida y confiable cuando hay suficientes descriptores de archivo disponibles, especialmente en plataformas distintas de Linux.

ERRORES

Desde el cambio de Linux 2.6.36 que añadió "(inaccessible)" en las circunstancias descritas anteriormente, la implementación de glibc de getcwd() no cumplió con POSIX y devolvió una ruta relativa cuando el contrato de la API requiere una ruta absoluta. A partir de glibc 2.27, esto se ha corregido; llamar a getcwd() desde una ruta de este tipo ahora resultará en un fallo con ENOENT.
