DESCRIPCIÓ

N

Estas funciones se utilizan para manipular un contexto previamente asignado e inicializado, consulte getdns_context (3) para obtener más detalles sobre las funciones utilizadas para asignar, inicializar y destruir contextos y para una discusión más detallada de getdns_context en

general.

getdns_context_set_append_name especifica si se debe añadir un sufijo proporcionado mediante getdns_context_set_suffix (3) a la cadena de consulta antes de que la API comience a resolver un

nombre.

getdns_context_set_context_update_callback establece una función que se llamará si hay cambios en los archivos del sistema (por ejemplo, /etc/resolv.conf y /etc/hosts)

.

getdns_context_set_dns_transport especifica el transporte utilizado para las búsquedas DNS, el valor predeterminado es usar UDP y volver a TCP según sea

necesario.

getdns_context_set_dnssec_trust_anchors permite al llamador especificar anclas de confianza como alternativas a las anclas de confianza predeterminadas

.

getdns_context_set_dnssec_allowed_skew establece el número de segundos de desfase permitido en cualquier dirección al verificar los campos de expiración e inicio de un RRSIG, el valor predeterminado es

0.

getdns_context_set_limit_outstanding_queries especifica el número máximo de consultas DNS pendientes, la API encolará las consultas que superen este límite hasta que las consultas actuales sean respondidas y luego emitirá automáticamente las consultas de la

cola.

getdns_context_set_dns_root_servers proporciona un conjunto alternativo de direcciones para usar al buscar los dominios de nivel superior. El valor predeterminado (si no se llama a esta función) es la lista de servidores raíz de IANA (piense en esto como las pistas de raíz)

.

getdns_context_set_follow_redirects especifica si las consultas DNS siguen o no las redirecciones (CNAME y DNAME), el comportamiento predeterminado es seguir las redirecciones y devolver el destino

final.

getdns_context_set_namespaces establece los espacios de nombres que utilizará el resolvedor, el valor predeterminado es DNS y luego archivos locales. Las implementaciones futuras soportarán netbios, mdns y

nis.

getdns_context_set_resolution_type especifica si las consultas DNS se realizan con búsquedas no recursivas o como un resolvedor

stub.

getdns_context_set_suffix Añade sufijos a los nombres de dominio antes de ejecutar la búsqueda basándose en getdns_context_set_append_name

.

getdns_context_set_timeout especifica el número de milisegundos que la API esperará una

respuesta.

context un getdns_context previamente asignado e

inicializado.

callback una función de retorno de llamada que se llamará cuando se realicen cambios en los archivos del sistema (/etc/resolv.conf y /etc/hosts) para contextos creados con set_from_os = 1. Cuando se llama a esta función, el parámetro changed_item indica qué elemento del contexto ha

cambiado.

root_addresses Esta es una lista de tipos getdns_dict que identifican cada uno un servidor raíz individual para usar al buscar dominios de nivel superior. Cada diccionario incluye dos nombres, address_type , un bindata que contiene la cadena "IPv4" o "IPv6" y address_data un bindata que contiene la dirección

IP.

transport puede ser uno de GETDNS_CONTEXT_UDP_FIRST_AND_FALL_BACK_TO_TCP, GETDNS_CONTEXT_UDP_ONLY, GETDNS_CONTEXT_TCP_ONLY, GETDNS_CONTEXT_TCP_ONLY_KEEP_CONNECTIONS_OPEN. Si necesita más información sobre lo que significa cada uno de estos, vuelva a leer el mnemotécnico y adivine ;

)

followredir Si se establece en GETDNS_REDIRECTS_FOLLOW (el valor predeterminado) se devuelve el destino final de la redirección. Si se establece en GETDNS_REDIRECTS_DO_NOT_FOLLOW se devuelve el CNAME o DNAME y NO el destino

final.

limit el número máximo de consultas DNS concurrentes pendientes (sin respuesta), si se supera, la API encolará las consultas y las emitirá a medida que disminuya el número de consultas pendientes. Un valor de 0 indica que no hay

límite.

namespaces El array namespaces contiene una lista ordenada de espacios de nombres que serán consultados. Importante: esta configuración de contexto se ignora para las funciones getdns_general y getdns_general_sync; se utiliza para las demás funciones. Los valores son GETDNS_CONTEXT_NAMESPACE_DNS, GETDNS_CONTEXT_NAMESPACE_LOCALNAMES, GETDNS_CONTEXT_NAMESPACE_NETBIOS, GETDNS_CONTEXT_NAMESPACE_MDNS y GETDNS_CONTEXT_NAMESPACE_NIS. Cuando se realiza una búsqueda normal, la API realiza las búsquedas en el orden dado y se detiene cuando obtiene el primer resultado; un método diferente con el mismo resultado sería ejecutar las consultas en paralelo y devolver cuando se obtiene el primer resultado. Dado que las búsquedas pueden realizarse a través de diferentes mecanismos debido a los diferentes espacios de nombres, puede haber una fuga de información similar a la observada con getaddrinfo(). El valor predeterminado lo determina el

SO.

restype se puede establecer en GETDNS_CONTEXT_RECURSIVE (el valor predeterminado) o GETDNS_CONTEXT_STUB (requiere que el llamador especifique los reenviadores)

.

seconds_skew el número de segundos de desfase permitido en cualquier dirección al verificar los campos de expiración e inicio de un

RRSIG.

suffixes Una lista de bindatas que son cadenas que deben añadirse basándose en getdns_context_set_append_name. Los valores aquí siguen las reglas de la sección 2.1 de la RFC 4343 para permitir octetos y caracteres especiales no ASCII en las

etiquetas.

timeout el número de milisegundos que la API esperará una respuesta, después de lo cual se invocará la función de retorno de llamada (o la función sincrónica retornará) con un error de tiempo de

espera.

trust_anchors lista de bindatas que son los anclas de confianza DNSSEC expresadas como RDATA de los registros de recursos DNSKEY, los valores predeterminados son proporcionados por la raíz de

IANA.
