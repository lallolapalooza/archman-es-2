getcontext(3) Manual de Funciones de Biblioteca getcontext(3)

NOMBRE

getcontext, setcontext - obtener o establecer el contexto de usuario

BIBLIOTECA

Biblioteca C estándar (libc,-lc)

SINOPSIS

#include <ucontext.h>
int getcontext(ucontext_t *ucp);
int setcontext(const ucontext_t *ucp);

DESCRIPCIÓN

En un entorno similar a System V, se tienen los dos tipos mcontext_t y ucontext_t definidos en <ucontext.h> y las cuatro funciones getcontext(), setcontext(), makecontext(3), y swapcontext(3) que permiten el cambio de contexto a nivel de usuario entre múltiples hilos de control dentro de un proceso.

El tipo mcontext_t depende de la máquina y es opaco. El tipo ucontext_t es una estructura que tiene al menos los siguientes campos:


typedef struct ucontext_t {
    struct ucontext_t *uc_link;
    sigset_t          uc_sigmask;
    stack_t           uc_stack;
    mcontext_t        uc_mcontext;
    ...
} ucontext_t;

con sigset_t y stack_t definidos en <signal.h>. Aquí uc_link apunta al contexto que se reanudará cuando el contexto actual termine (en caso de que el contexto actual haya sido creado usando makecontext(3)), uc_sigmask es el conjunto de señales bloqueadas en este contexto (véase sigprocmask(2)), uc_stack es la pila usada por este contexto (véase sigaltstack(2)), y uc_mcontext es la representación específica de la máquina del contexto guardado, que incluye los registros de la máquina del hilo que llama.

La función getcontext() inicializa la estructura apuntada por ucp al contexto actualmente activo.

La función setcontext() restaura el contexto de usuario apuntado por ucp. Una llamada exitosa no retorna. El contexto debería haberse obtenido mediante una llamada a getcontext(), o makecontext(3), o recibido como el tercer argumento de un manejador de señales (véase la discusión de la bandera SA_SIGINFO en sigaction(2)).

Si el contexto fue obtenido mediante una llamada a getcontext(), la ejecución del programa continúa como si esta llamada acabara de retornar.

Si el contexto fue obtenido mediante una llamada a makecontext(3), la ejecución del programa continúa con una llamada a la función func especificada como el segundo argumento de esa llamada a makecontext(3). Cuando la función func retorna, se continúa con el miembro uc_link de la estructura ucp especificada como el primer argumento de esa llamada a makecontext(3). Cuando este miembro es NULL, el hilo termina.

Si el contexto fue obtenido mediante una llamada a un manejador de señales, el texto estándar antiguo decía que "la ejecución del programa continúa con la instrucción del programa que sigue a la instrucción interrumpida por la señal". Sin embargo, esta frase fue eliminada en SUSv2, y el veredicto actual es "el resultado no está especificado".

VALOR DE RETORNO

Cuando tiene éxito, getcontext() retorna 0 y setcontext() no retorna. En caso de error, ambas retornan -1 y establecen errno para indicar el error.

ERRORES

Ninguno definido.

ATRIBUTOS

Para una explicación de los términos usados en esta sección, véase attributes(7).

Interfaz Atributo Valor
getcontext (), setcontext () Seguridad de hilos MT-Safe race:ucp

ESTÁNDARES

Ninguno.

HISTORIA

SUSv2, POSIX.1-2001.

POSIX.1-2008 elimina estas funciones, citando problemas de portabilidad, y recomendando que las aplicaciones se reescriban para usar hilos POSIX en su lugar.

NOTAS

La encarnación más temprana de este mecanismo fue el mecanismo setjmp(3)/longjmp(3) . Dado que esto no define el manejo del contexto de señal, la siguiente etapa fue el par sigsetjmp(3)/siglongjmp(3) . El mecanismo actual da mucho más control. Por otro lado, no hay una manera fácil de detectar si un retorno de getcontext() proviene de la primera llamada, o vía una llamada a setcontext() . El usuario tiene que inventar su propio dispositivo de contabilidad, y una variable de registro no servirá ya que los registros se restauran.

Cuando ocurre una señal, el contexto de usuario actual se guarda y el kernel crea un nuevo contexto para el manejador de señales. No se debe salir del manejador usando longjmp(3): es indefinido qué sucedería con los contextos. Use siglongjmp(3) o setcontext() en su lugar.

VÉASE TAMBIÉN

sigaction(2), sigaltstack(2), sigprocmask(2), longjmp(3), makecontext(3), sigsetjmp(3), signal(7)
