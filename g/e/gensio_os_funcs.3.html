DESCRIPCIÓ

N

Esta estructura proporciona una abstracción para la biblioteca gensio que le permite funcionar con varias bibliotecas de eventos. Proporciona las siguientes funciones

básicas:
asignación de memoria - Asignar y liberar
memoria.
mutexes - Proporcionan exclusión
mutua.
devoluciones de llamada de manejadores de archivos - Permite monitorear descriptores de
archivo
e informar cuando hay E/S lista en
ellos.
temporizadores - Llaman a devoluciones de llamada después de que haya transcurrido cierta cantidad de
tiempo.
ejecutores - Ejecutan una función en un nuevo contexto de ejecución. Llamar a devoluciones de
llamada
directamente desde funciones de usuario puede resultar en bloqueos mutuos, esto proporciona una forma de llamar a devoluciones de llamada desde un contexto
separado.
esperadores - Esperan a que ocurran operaciones mientras se ejecutan temporizadores,
ejecutores
y se vigilan los descriptores de
archivo.
registro de eventos - Permite a la biblioteca gensio generar registros para informar
problemas.

Este documento describe las funciones públicas que los usuarios pueden utilizar. Un manejador de SO tiene muchas otras funciones para el uso de los gensios, estas están documentadas en el archivo de inclusión de funciones de

SO.

El problema básico es que existen varias bibliotecas de manejo de eventos (Tcl/Tk, glib, Xlib, personalizadas, etc.) y es posible que desee integrar la biblioteca gensio con una de estas. Aunque es un poco tedioso tener que pasar una de estas alrededor, añade la flexibilidad

necesaria.

gensio_default_os_hnd (Obsoleto) proporciona una forma de obtener el manejador de funciones de SO predeterminado para la plataforma. Se devolverá el mismo valor cada vez, solo se crea uno. Generalmente debería usar este a menos que tenga una necesidad especial como se documenta arriba. El uso de esto ahora se desaconseja en general. Que dos partes independientes de un sistema compartan funciones de SO sin saberlo probablemente llevará a problemas. Si un programa sabe que es la única cosa que lo usa, entonces está bien por ahora, pero se volverá obsoleto en algún

momento.

gensio_alloc_os_funcs asigna un nuevo manejador de funciones de SO para la plataforma, para Unix o Windows. Se pueden usar varios manejadores de SO para manejar diferentes E/S en diferentes prioridades. Cuando crea un gensio, todas las devoluciones de llamada de E/S serán manejadas desde el manejador de SO utilizado para crearlo. Así puede ejecutar diferentes manejadores de SO en hilos de diferente prioridad para ejecutar diferentes gensios en diferente prioridad. De lo contrario, no hay mucha razón para tener más de uno de

estos.

El uso del parámetro wake_sig en Windows no se utiliza. Para sistemas Unix, esta señal se usa para señalar a otros procesos que puedan estar esperando que necesitan despertarse. Se usa para despertar un proceso que espera en un esperador, y se usa para señalar a todos los procesos en espera si se añade un temporizador que es anterior a cualquier otro temporizador para que puedan ajustar sus

esperas.

Si ejecuta su programa en un solo hilo, puede pasar de forma segura cero en este parámetro. Si pasa algo distinto de cero, configurará esa señal eliminándola de la sigmask e instalando un manejador para

ella.

Si su aplicación es multihilo (o, con más precisión, si su aplicación tiene múltiples hilos que realizan llamadas a gensio), debe pasar una señal válida en esto, y debe configurar un manejador vacío para esta señal, y la señal debe estar bloqueada en todos los hilos que llamen a una función de espera. No debe usar esta señal para ningún otro propósito. La función que asigna un manejador de señales bloqueará la señal en el hilo que llama, y esa sigmask se pasa a otros hilos que crea. Pero si ha asignado hilos antes de asignar las funciones del sistema operativo, debe asegurarse de que esos otros hilos tengan esta señal

bloqueada.

Puede pasar GENSIO_OS_FUNCS_DEFAULT_THREAD_SIGNAL para tomar el manejador de señal predeterminado, que es

SIGUSR1.

En unix, la función gensio_os_proc_setup maneja toda la configuración de señales mencionada anteriormente para usted (bloqueando señales, configurando el manejador de señales), para la señal de despertar como se mencionó arriba y también para algunas otras señales como SIGTERM, SIGCHILD, SIGPIPE y otras. Generalmente debe usar eso a menos que tenga necesidades especiales. También realiza la configuración necesaria en

Windows.

Además, si pasa un valor diferente a gensio_default_os_hnd que el primero que pasó, devolverá GE_INVAL. Puede pasar valores diferentes a las llamadas a gensio_unix_funcs_alloc, y los usará, pero no hay mucho valor en esto. Las funciones del sistema operativo para Unix pueden compartir un manejador de señales. Y no hay mucho valor en múltiples funciones del sistema operativo, de todos

modos.

gensio_os_thread_setup es muy similar a gensio_os_proc_setup, pero solo configura los manejadores de señales y el bloqueo de señales para la señal de despertar, no realiza ninguna de las otras configuraciones. Le permite incorporar un hilo a gensio que no fue creado por gensio. También realiza alguna configuración necesaria en Windows para el hilo. Si no tiene necesidades de manejo de señales, generalmente puede usar esto en lugar de gensio_os_proc_setup(). Si tiene necesidades de manejo de señales, un hilo debe llamar a gensio_os_proc_setup() y todos los demás hilos deben llamar a esta función si no fueron creados por

gensio.

gensio_unix_funcs_alloc y gensio_win_funcs_alloc asignan las funciones normales del sistema operativo para sistemas basados en Unix y Windows, respectivamente

.

El parámetro sel para Unix le permite crear su propio objeto selector y pasarlo al manejador del sistema operativo. Pasar NULL hará que asigne su propio objeto selector. Consulte el archivo de inclusión selector.h para más

detalles.

El valor wake_sig es una señal para uso de las funciones del sistema operativo para comunicación interna entre hilos. Si está ejecutando una aplicación multihilo, debe proporcionar una señal válida que no use para ningún otro propósito, generalmente SIGUSR1 o SIGUSR2. Puede usar GENSIO_DEF_WAKE_SIG que es cero en Windows y SIGUSR1 en

Unix.

La función gensio_os_proc_setup realiza toda la configuración estándar para un proceso. Casi con certeza debe usar esta función. En Windows esto configura algunas cosas básicas para que el registro de terminación funcione, pero en Unix hace toda la configuración del manejo de señales, para que no tenga que hacer todas las cosas mencionadas arriba. Esto bloqueará SIGPIPE (porque esos llegan cuando las conexiones mueren y a la mayoría de las aplicaciones no les importa), SIGCHLD (esos llegan para los gensios de stdio y pty), y el wake_sig si está configurado. También instala manejadores de señales para SIGCHLD y el wake_sig (si está configurado) y configura una máscara de

señales.

Para Unix esto es generalmente lo que quiere, no quiere que SIGPIPE haga cosas malas y tener SIGCHLD despertar una espera puede acelerar las cosas un poco al esperar

subprogramas.

Si usa la función del sistema operativo gensio_os_funcs_wait_intr_sigmask, debe pasar el valor proc_data devuelto por gensio_os_proc_setup en ella. Si quiere modificar la máscara de señal de espera, puede usar gensio_os_proc_unix_get_wait_sigset para obtener un puntero a ella y

modificarla.

Tenga en cuenta que si llama a esto más de una vez sin llamar a gensio_os_proc_cleanup en medio, devolverá GE_INUSE

.

La función gensio_os_proc_cleanup deshace todos los cambios que gensio_os_proc_setup hace, junto con desregistrando cualquier manejador de señales hecho por llamadas de registro. En Unix restaura la máscara de señales y los manejadores de señales que configura a sus valores anteriores. En Windows elimina los manejadores

registrados.

La función gensio_os_new_thread inicia un nuevo hilo en start_func pasando el valor de datos dado. Devuelve un thread_id que debe pasar a la función de espera. Esto es solo hilos genéricos básicos, puede usar sus funciones del sistema operativo si necesita más control sobre los hilos. Si usa hilos, asegúrese de ver las notas anteriores sobre cómo configurarlos correctamente. Esto debe ser llamado desde un hilo que ya esté

configurado.

La función gensio_os_wait_thread espera a que un hilo se detenga. Tenga en cuenta que no causa que el hilo se detenga, espera a que se detenga. Usted tiene que causar que el hilo se detenga usted

mismo.

La función gensio_os_proc_register_term_handler pasa un manejador a llamar cuando el proceso recibe una terminación (SIGINT, SIGQUIT, SIGTERM en Unix, manejador de control de consola o WM_CLOSE en Windows). Establezca handler a NULL para deshabilitar. Si hace esto en Unix, las señales estarán bloqueadas excepto cuando esté en una llamada de espera o servicio. Llame a esto antes de iniciar cualquier otro hilo para que hereden la sigmask

correcta.

La función gensio_os_proc_register_reload_handler establece la función a llamar cuando el sistema operativo solicita una recarga (SIGHUP en Unix). Establezca handler a NULL para deshabilitar. En Unix, esto hará que SIGHUP esté bloqueado excepto cuando esté en una llamada de espera o servicio. Llame a esto antes de iniciar cualquier otro hilo para que hereden la sigmask

correcta.

La función gensio_os_proc_register_winsize_handler establece la función a llamar cuando el sistema operativo solicita un cambio en el tamaño de la ventana de consola (SIGWINCH en Unix, a través de la interfaz de consola en Windows). Proporcionará los parámetros del nuevo tamaño. Establezca handler y console_iod a NULL para deshabilitar. Tenga en cuenta que el manejador será llamado con los parámetros del tamaño de ventana actual después de que esto sea llamado. Esto puede ser llamado después de que se hayan iniciado hilos, la máscara de señal SIGWINCH se configura por predeterminado en gensio_os_proc_setup en sistemas

*nix.

gensio_os_funcs_zalloc asigna un bloque de memoria y lo pone a cero. La biblioteca gensio tiene su propio asignador/liberador que se usa en las pruebas para rastrear si todos los datos asignados se liberan cuando las pruebas se apagan, y para detectar desbordamientos de memoria, desbordamientos inferiores y errores de uso después de liberar. Devuelve NULL si la memoria no puede ser asignada. Use gensio_os_funcs_zfree para liberar la memoria

asignada.

gensio_os_funcs_alloc_lock asigna un mutex que puede ser usado para bloqueo por el usuario. Use gensio_os_funcs_lock y gensio_os_funcs_unlock para bloquear/desbloquear el mutex. El gensio_os_funcs_free_lock se asegurará de que el bloqueo no esté bloqueado y liberará los datos asociados con el bloqueo. Tenga en cuenta que incluso para funciones del sistema operativo que no implementan bloqueos, esto implementará un contador para asegurar que todos los bloqueos estén

equilibrados.

gensio_os_funcs_get_monotonic_time devuelve un valor de tiempo del reloj monotónico usado para gensio_os_start_timer_abs. También puede usarse como un reloj monotónico estándar, pero no es un reloj de pared de ningún

tipo.

gensio_os_funcs_set_vlog debe ser llamado por el usuario para establecer una función de manejo de registro para las funciones del sistema operativo. Si algo sale mal internamente en la biblioteca gensio, esta función de registro será llamada para reportar el

problema.

Los temporizadores se asignan con gensio_os_funcs_alloc_timer. Cuando el temporizador expira, los manejadores serán llamados con el cb_data dado. Esto devolverá NULL si el temporizador no puede ser asignado. Los temporizadores no están corriendo cuando se asignan, deben ser iniciados con gensio_os_funcs_start_timer, o gensio_os_funcs_start_timer_abs. El primero inicia un temporizador relativo al tiempo actual. El segundo inicia un temporizador basado en un reloj monotónico, consulte gensio_os_funcs_get_monotonic_time para más detalles. Estos devolverán GE_INUSE si el temporizador ya estaba corriendo. Para detener un temporizador, llame a gensio_os_funcs_stop_timer o gensio_os_funcs_stop_timer_with_done. Ambos devuelven GE_TIMEDOUT si el temporizador no está corriendo. El primero no tiene forma de asegurar que el temporizador haya terminado de ejecutar sus manejadores; el manejador del temporizador puede seguir activo cuando devuelve. Si no devuelve un error, el segundo llamará a la función done_handler cuando el temporizador esté completamente detenido y todos los manejadores hayan terminado. El segundo también devuelve GE_INUSE si el temporizador ya ha sido detenido pero el manejador de finalización aún no ha sido llamado. Tenga en cuenta que no puede iniciar el temporizador de nuevo hasta que se llame al manejador de finalización. Y finalmente, para liberar un temporizador, use gensio_os_funcs_free_timer. El temporizador no debe estar corriendo cuando llame a

esto.

Los runners son como temporizadores de tiempo cero, simplemente serán llamados inmediatamente. Son útiles para escapar de situaciones de bloqueo profundas donde quiere hacer algo en el contexto base. Use gensio_os_funcs_alloc_runner para asignar uno de estos. Devuelve NULL si el runner no puede ser asignado. gensio_os_funcs_run hace que el manejador sea llamado. Devuelve GE_INUSE si el runner actualmente ya está programado para ejecutarse. Y gensio_os_funcs_free_runner libera el runner. No debe estar actualmente programado para

ejecutarse.

gensio_os_funcs_service proporciona la función de servicio principal para ejecutar temporizadores, runners, manejo de E/S, etc. Si es interrumpido por una señal (en Unix), devuelve GE_INTERRUPTED. Si timeout no es NULL, es una cantidad de tiempo relativa a esperar y esto devolverá GE_TIMEDOUT si el tiempo de espera expira. Tenga en cuenta que para tiempos de espera largos (días) esto puede devolver temprano en algunas funciones del sistema operativo, así que no confíe en esto para la medición de tiempo. Cuando esto devuelve, el tiempo de espera se actualizará a cualquier tiempo restante, incluso en un tiempo de espera temprano. Generalmente no usa esta función, usa los esperadores en su

lugar.

Llame a gensio_os_funcs_handle_fork en la función hijo después de un fork (solo Unix). Esto limpia varias cosas y deja la biblioteca gensio lista para usarse después de un fork. Si esto devuelve un error, es probable que la biblioteca gensio sea inutilizable en el

hijo.

Los esperadores se usan para esperar a que sucedan cosas. Cuando la cosa sucede, ese código debe llamar a wake para despertar al esperador. El servicio normal de tiers, runners, E/S, etc. se hace mientras se espera. Los esperadores y los despertares se basan en conteos, si llama a wake antes de la espera está bien, el despertar estará esperando cuando ocurra la espera. Si llama a wake 3 veces, hay 3 despertares pendientes. Para asignarpara un esperador, llama a gensio_os_funcs_alloc_waiter. Devuelve NULL si no puede asignar el esperador. gensio_os_funcs_wait espera a que se realicen count despertadores y luego devuelve cero. Si timeout es NULL, espera para siempre. De lo contrario, si el tiempo de espera expira, devuelve GE_TIMEDOUT y el tiempo de espera se actualiza al tiempo restante. Si se agota el tiempo de espera, la función no "usa" ningún despertador; si solo algunos están pendientes, esos siguen pendientes. gensio_os_funcs_wait_intr es como gensio_os_funcs_wait, excepto que si se recibe una señal (solo Unix) devolverá GE_INTERRUPTED. gensio_os_funcs_wait_intr_sigmask es como gensio_os_funcs_wait_intr, pero permite instalar una máscara de señales especificada por el usuario (solo Unix). Consulta gensio_os_proc_setup para más detalles. Para enviar un único despertador a un esperador, usa gensio_os_funcs_wake. Y, por supuesto, llama a gensio_os_funcs_free_waiter para liberar un

esperador.

Un os funcs tiene un único puntero void en el que el usuario puede instalar algunos datos para su propio uso. Usa gensio_os_funcs_set_data para establecer estos datos y gensio_os_funcs_get_da

ta para re
cuperarlos.
