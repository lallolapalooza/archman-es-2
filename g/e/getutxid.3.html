getutent(3) Manual de Funciones de Biblioteca getutent(3)

NOMBRE

getutent, getutid, getutline, pututline, setutent, endutent, utmpname — acceder a entradas del archivo utmp

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <utmp.h>
struct utmp *getutent(void);
struct utmp *getutid(const struct utmp *ut);
struct utmp *getutline(const struct utmp *ut);
struct utmp *pututline(const struct utmp *ut);
void setutent(void);
void endutent(void);
int utmpname(const char *path);

DESCRIPCIÓN

Las aplicaciones nuevas deben utilizar las funciones de la versión "utmpx" especificadas por POSIX.1; véase ESTÁNDARES.

utmpname() establece el nombre de ruta del archivo con formato utmp para que las otras funciones utmp accedan. Si no se utiliza utmpname() para establecer el nombre de ruta antes de usar las otras funciones, estas asumen _PATH_UTMP, tal como se define en <paths.h>.

setutent() rebobina el puntero de archivo al principio del archivo utmp. Generalmente, es una buena idea llamarla antes que a cualquiera de las otras funciones.

endutent() cierra el archivo utmp. Debe llamarse cuando el código del usuario haya terminado de acceder al archivo con las otras funciones.

getutent() lee una línea de la posición actual del archivo en el archivo utmp. Devuelve un puntero a una estructura que contiene los campos de la línea. La definición de esta estructura se muestra en utmp(5).

getutid() busca hacia adelante desde la posición actual del archivo en el archivo utmp basándose en ut. Si ut->ut_type es uno de RUN_LVL, BOOT_TIME, NEW_TIME o OLD_TIME, getutid() encontrará la primera entrada cuyo campo ut_type coincida con ut->ut_type. Si ut->ut_type es uno de INIT_PROCESS, LOGIN_PROCESS, USER_PROCESS o DEAD_PROCESS, getutid() encontrará la primera entrada cuyo campo ut_id coincida con ut->ut_id.

getutline() busca hacia adelante desde la posición actual del archivo en el archivo utmp. Escanea entradas cuyo ut_type es USER_PROCESS o LOGIN_PROCESS y devuelve la primera cuya campo ut_line coincida con ut->ut_line.

pututline() escribe la estructura utmp ut en el archivo utmp. Utiliza getutid() para buscar el lugar apropiado en el archivo para insertar la nueva entrada. Si no puede encontrar un espacio adecuado para ut, pututline() añadirá la nueva entrada al final del archivo.

VALOR DE RETORNO

getutent(), getutid() y getutline() devuelven un puntero a una struct utmp si tienen éxito, y NULL en caso de fallo (lo que incluye el caso de "registro no encontrado"). Esta struct utmp se asigna en almacenamiento estático y puede ser sobrescrita por llamadas posteriores.

Si tiene éxito, pututline() devuelve ut; en caso de fallo, devuelve NULL.

utmpname() devuelve 0 si el nuevo nombre se almacenó correctamente, o -1 en caso de fallo.

En caso de fallo, estas funciones establecen errno para indicar el error.

ERRORES

ENOMEM
Sin memoria.
ESRCH
Registro no encontrado.

setutent(), pututline() y las funciones getut*() también pueden fallar por las razones descritas en open(2).

ARCHIVOS

/var/run/utmp
base de datos de usuarios actualmente conectados
/var/log/wtmp
base de datos de inicios de sesión de usuarios anteriores

ESTÁNDARES

Ninguno.

HISTORIA

XPG2, SVr4.

En XPG2 y SVID 2, la función pututline() se documenta como void, y eso es lo que hace en muchos sistemas (AIX, HP-UX). HP-UX introduce una nueva función _pututline() con el prototipo dado arriba para pututline().

Todas estas funciones están obsoletas ahora en sistemas no Linux. POSIX.1-2001 y POSIX.1-2008, siguiendo SUSv1, no tienen ninguna de estas funciones, sino que utilizan

#include <utmpx.h>
struct utmpx *getutxent(void);
struct utmpx *getutxid(const struct utmpx *);
struct utmpx *getutxline(const struct utmpx *);
struct utmpx *pututxline(const struct utmpx *);
void setutxent(void);
void endutxent(void);

Estas funciones son proporcionadas por glibc y realizan la misma tarea que sus equivalentes sin la "x", pero utilizan struct utmpx, definida en Linux como igual a struct utmp. Para ser completos, glibc también proporciona utmpxname(), aunque esta función no está especificada por POSIX.1.

En algunos otros sistemas, la estructura utmpx es un superconjunto de la estructura utmp, con campos adicionales y versiones más grandes de los campos existentes, y se mantienen archivos paralelos, a menudo /var/*/utmpx y /var/*/wtmpx.

Por otro lado, glibc de Linux no utiliza un archivo utmpx paralelo, ya que su estructura utmp ya es lo suficientemente grande. Las funciones "x" listadas arriba son simplemente alias de sus contrapartes sin la "x" (por ejemplo, getutxent() es un alias para getutent()).

NOTAS

notas glibc

Las funciones anteriores no son seguras para hilos. glibc añade versiones reentrantes

#include <utmp.h>
int getutent_r(struct utmp *ubuf, struct utmp **ubufp);
int getutid_r(struct utmp *ut,
              struct utmp *ubuf, struct utmp **ubufp);
int getutline_r(struct utmp *ut,
                struct utmp *ubuf, struct utmp **ubufp);

Requisitos de Macro de Prueba de Funciones para glibc (véase feature_test_macros(7)):

getutent_r(), getutid_r(), getutline_r():

    _GNU_SOURCE
        || /* Desde glibc 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */    _SVID_SOURCE || _BSD_SOURCE

Estas funciones son extensiones de GNU, análogas a las funciones del mismo nombre sin el sufijo _r. El argumento ubuf proporciona a estas funciones un lugar para almacenar su resultado. Si tienen éxito, devuelven 0, y se escribe un puntero al resultado en *ubufp. En caso de error, estas funciones devuelven -1. No existen equivalentes utmpx de las funciones anteriores. (POSIX.1 no especifica tales funciones).

getutxid(3) - Arch Linux man pages

NAME

getutxent, getutxid, getutxline, pututxline, setutxent, endutxent - manipulate user accounting database

LIBRARY

Legacy UNIX supplement (libbsd)

SYNOPSIS

#include <utmp.h>
struct utmp *getutxent(void);
struct utmp *getutxid(const struct utmp *id);
struct utmp *getutxline(const struct utmp *line);
struct utmp *pututxline(const struct utmp *entry);
void setutxent(void);
void endutxent(void);

DESCRIPTION

The functions described in this manual page provide an interface to the user accounting database, which is typically implemented by the file /var/run/utmp (or /var/log/utmp). This database records information about currently logged-in users.

The structure struct utmp is defined in the <utmp.h> header and contains at least the following members:

  • ut_user: Username (null-terminated string).
  • ut_id: Identifier for the utmp entry (e.g., PID for login entries, tty name for other entries). This is often used to uniquely identify an entry.
  • ut_line: Name of the terminal device (e.g., tty1) associated with the entry (null-terminated string).
  • ut_pid: Process ID of the login process.
  • ut_type: Type of the utmp entry. Possible values are defined in <utmp.h> and include:
    EMPTY
    No current user.
    RUN_LVL
    System run-level information.
    BOOT_TIME
    System boot time.
    OLD_TIME
    Time the system was last brought down.
    NEW_TIME
    Time the system is to be brought down.
    INIT_PROCESS
    A process started by init(8) during system startup.
    LOGIN_PROCESS
    A process started by login(1).
    USER_PROCESS
    A normal user login.
    INTERACTIVE_SHELL
    A user shell started upon login.
    DEAD_PROCESS
    A process that has terminated.
    LOGOUT_TIME
    Time of logout.
    ACCOUNTING
    Accounting information.
  • ut_host: Hostname for remote logins (e.g., from telnet or ssh) (null-terminated string).
  • ut_addr: Internet address for remote logins. The format depends on the address family.
  • ut_time: Time of the last update to this entry. This is stored as time_t.

The UT_LINESIZE, UT_NAMESIZE, UT_HOSTSIZE, and UT_IDSIZE macros define the sizes of the corresponding members.

The setutxent() function opens and rewinds the user accounting database, preparing it for reading. If setutxent() is called, subsequent calls to getutxent() will read entries sequentially from the beginning of the database.

The getutxent() function reads the next entry from the database and returns a pointer to it. If the end of the file is reached or an error occurs, it returns NULL.

The getutxid() function searches the database for an entry that matches the ut_id or ut_type field of the structure pointed to by id. It returns a pointer to the matching entry, or NULL if no match is found or an error occurs. The ut_id field is used for matching if it is not empty; otherwise, the ut_type field is used.

The getutxline() function searches the database for an entry that matches the ut_line field of the structure pointed to by line. It returns a pointer to the matching entry, or NULL if no match is found or an error occurs.

The pututxline() function writes the structure pointed to by entry to the database. If an entry with the same ut_id already exists, it is overwritten. If no such entry exists, the new entry is appended. pututxline() typically updates the ut_time and ut_pid fields as appropriate. It returns a pointer to the written entry on success, and NULL on failure. Note that this function may leave the file descriptor for the utmp database in an undefined state.

The endutxent() function closes the user accounting database.

It is recommended to call setutxent() before the first call to getutxent(), getutxid(), or getutxline() to ensure proper initialization. Similarly, endutxent() should be called when finished with the database.

RETURN VALUE

On success, getutxent(), getutxid(), and getutxline() return a pointer to a statically allocated struct utmp. This pointer becomes invalid upon the next call to one of these functions or to endutxent(). On failure, these functions return NULL.

The pututxline() function returns a pointer to the written entry on success, and NULL on failure.

ERRORS

The functions may fail due to I/O errors when accessing the utmp database file.

FILES

/var/run/utmp (or /var/log/utmp): user accounting database.

ATTRIBUTES

For an explanation of the terms used in this section, see attributes(7).

Interface Attribute Value
getutxent(), getutxid(), getutxline(), pututxline(), setutxent(), endutxent() Thread safety MT-Unsafe

STANDARDS

These functions are part of the POSIX.1-2001 and POSIX.1-2008 standards.

HISTORY

The getutx* functions first appeared in the AT&T UNIX System V Release 3.0. The pututxline() function was introduced later.

NOTES

The getutxent(), getutxid(), getutxline(), setutxent(), and endutxent() functions are not thread-safe. Applications requiring thread safety should use the getutmp(3), getutid(3), getutline(3), pututline(3), setutent(3), and endutent(3) functions, which are designed for thread-safe operation.

The pututxline() function may not be safe to use concurrently from multiple processes or threads. It is generally recommended to use file locking mechanisms if concurrent access is expected.

The utmp file is typically maintained by programs like login, init, and getty. Directly manipulating this file can lead to inconsistencies if not done carefully.

The format and fields of the struct utmp may vary slightly between different Unix-like systems. The UT_IDSIZE field is particularly prone to variations.

EXAMPLES

The following example adds and removes a utmp record, assuming it is run from within a pseudo terminal. For usage in a real application, you should check the return values of getpwuid(3) and ttyname(3).

#include <err.h>
#include <pwd.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <unistd.h>
#include <utmp.h>
int
main(void)
{
    struct utmp entry;
    if (system("echo before adding entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    entry.ut_type = USER_PROCESS;
    entry.ut_pid = getpid();
    strcpy(entry.ut_line, ttyname(STDIN_FILENO) + strlen("/dev/"));
    /* only correct for ptys named /dev/tty[pqr][0-9a-z] */
    strcpy(entry.ut_id, ttyname(STDIN_FILENO) + strlen("/dev/tty"));
    entry.ut_time = time(NULL);
    strcpy(entry.ut_user, getpwuid(getuid())->pw_name);
    memset(entry.ut_host, 0, UT_HOSTSIZE);
    entry.ut_addr = 0;
    setutent();
    if (pututline(&entry) == NULL)
        err(EXIT_FAILURE, "pututline");
    if (system("echo after adding entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    entry.ut_type = DEAD_PROCESS;
    memset(entry.ut_line, 0, UT_LINESIZE);
    entry.ut_time = 0;
    memset(entry.ut_user, 0, UT_NAMESIZE);
    setutent();
    if (pututline(&entry) == NULL)
        err(EXIT_FAILURE, "pututline");
    if (system("echo after removing entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    endutent();
    exit(EXIT_SUCCESS);
}
