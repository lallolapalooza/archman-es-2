getgrnam(3) Manual de Funciones de Biblioteca getgrnam(3)

NOMBRE

getgrnam, getgrnam_r, getgrgid, getgrgid_r - obtener una entrada del archivo de grupos

BIBLIOTECA

Biblioteca C estándar (libc,-lc)

SINOPSIS

#include <sys/types.h>
#include <grp.h>
struct group *getgrnam(const char *name);
struct group *getgrgid(gid_t gid);
int getgrnam_r(size_t size;
               const char *restrict name, struct group *restrict grp,
               char buf[restrict size], size_t size,
               struct group **restrict result);
int getgrgid_r(size_t size;
               gid_t gid, struct group *restrict grp,
               char buf[restrict size], size_t size,
               struct group **restrict result);
Requisitos de la macro de prueba de características para glibc (ver feature_test_macros(7)):

getgrnam_r(), getgrgid_r():

    _POSIX_C_SOURCE
        || /* glibc <= 2.19: */ _BSD_SOURCE || _SVID_SOURCE

DESCRIPCIÓN

La función getgrnam() devuelve un puntero a una estructura que contiene los campos desglosados del registro en la base de datos de grupos (por ejemplo, el archivo de grupos local /etc/group, NIS y LDAP) que coincide con el nombre de grupo name.

La función getgrgid() devuelve un puntero a una estructura que contiene los campos desglosados del registro en la base de datos de grupos que coincide con el ID de grupo gid.

La estructura group está definida en <grp.h> de la siguiente manera:


struct group {
    char   *gr_name;        /* nombre del grupo */
    char   *gr_passwd;      /* contraseña del grupo */
    gid_t   gr_gid;         /* ID del grupo */
    char  **gr_mem;         /* matriz terminada en NULL de punteros
                               a los nombres de los miembros del grupo */
};

Para obtener más información sobre los campos de esta estructura, consulte group(5).

Las funciones getgrnam_r() y getgrgid_r() obtienen la misma información que getgrnam() y getgrgid(), pero almacenan la estructura group recuperada en el espacio al que apunta grp. Los campos de cadena a los que apuntan los miembros de la estructura group se almacenan en el búfer buf de tamaño size. Un puntero al resultado (en caso de éxito) o NULL (en caso de que no se haya encontrado ninguna entrada o haya ocurrido un error) se almacena en *result.

La llamada


sysconf(_SC_GETGR_R_SIZE_MAX)

devuelve -1 sin cambiar errno, o un tamaño inicial sugerido para buf. (Si este tamaño es demasiado pequeño, la llamada falla con ERANGE, en cuyo caso el llamador puede reintentarlo con un búfer más grande.)

VALOR DE RETORNO

Las funciones getgrnam() y getgrgid() devuelven un puntero a una estructura group , o NULL si no se encuentra la entrada correspondiente o si ocurre un error. Si ocurre un error, errno se establece para indicar el error. Si se desea comprobar errno después de la llamada, debería establecerse a cero antes de la misma.

El valor de retorno puede apuntar a un área estática y puede ser sobrescrito por llamadas posteriores a getgrent(3), getgrgid() o getgrnam(). (No pase el puntero devuelto a free(3).)

En caso de éxito, getgrnam_r() y getgrgid_r() devuelven cero y establecen *result en grp. Si no se encontró ningún registro de grupo correspondiente, estas funciones devuelven 0 y almacenan NULL en *result. En caso de error, se devuelve un número de error y se almacena NULL en *result.

ERRORES

0 o ENOENT o ESRCH o EBADF o EPERM o ...
El nombre name o el gid proporcionados no fueron encontrados.
EINTR
Se capturó una señal; consulte signal(7).
EIO
Error de E/S.
EMFILE
Se alcanzó el límite por proceso en el número de descriptores de archivo abiertos.
ENFILE
Se alcanzó el límite del sistema en el número total de archivos abiertos.
ENOMEM
Memoria insuficiente para asignar la estructura group .
ERANGE
Se proporcionó un espacio de búfer insuficiente.

ARCHIVOS

/etc/group
archivo de base de datos de grupos local

VERSIONES

La formulación dada anteriormente en "VALOR DE RETORNO" proviene de POSIX.1. No considera "no encontrado" como un error, por lo tanto no especifica qué valor podría tener errno en esta situación. Pero eso hace imposible reconocer los errores. Podría argumentarse que, según POSIX, errno debería dejarse sin cambios si no se encuentra una entrada. Experimentos en varios sistemas tipo UNIX muestran que ocurren muchos valores diferentes en esta situación: 0, ENOENT, EBADF, ESRCH, EWOULDBLOCK, EPERM y probablemente otros.
