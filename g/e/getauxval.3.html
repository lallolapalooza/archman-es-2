getauxval(3) Manual de Funciones de Biblioteca getauxval(3)

NOMBRE

getauxval - recuperar un valor del vector auxiliar

BIBLIOTECA

Biblioteca C Estándar (libc,-lc)

SINOPSIS

#include <sys/auxv.h>
unsigned long getauxval(unsigned long type);

DESCRIPCIÓN

La función getauxval() recupera valores del vector auxiliar, un mecanismo que el cargador de binarios ELF del kernel utiliza para pasar cierta información al espacio de usuario cuando se ejecuta un programa.

Cada entrada en el vector auxiliar consiste en un par de valores: un tipo que identifica lo que esta entrada representa, y un valor para ese tipo. Dado el argumento type, getauxval() devuelve el valor correspondiente.

El valor devuelto para cada type se da en la siguiente lista. No todos los valores de type están presentes en todas las arquitecturas.

AT_BASE
La dirección base del intérprete del programa (generalmente, el enlazador dinámico).
AT_BASE_PLATFORM
Un puntero a una cadena (solo en PowerPC y MIPS). En PowerPC, identifica la plataforma real; puede diferir de AT_PLATFORM. En MIPS, identifica el nivel de ISA (desde Linux 5.7).
AT_CLKTCK
La frecuencia con la que times(2) cuenta. Este valor también se puede obtener mediante sysconf(_SC_CLK_TCK).
AT_DCACHEBSIZE
El tamaño de bloque de la caché de datos.
AT_EGID
El ID de grupo efectivo del hilo.
AT_ENTRY
La dirección de entrada del ejecutable.
AT_EUID
El ID de usuario efectivo del hilo.
AT_EXECFD
Descriptor de archivo del programa.
AT_EXECFN
Un puntero a una cadena que contiene la ruta de acceso utilizada para ejecutar el programa.
AT_FLAGS
Banderas (sin uso).
AT_FPUCW
Palabra de control de la FPU utilizada (solo en la arquitectura SuperH). Esto proporciona cierta información sobre la inicialización de la FPU realizada por el kernel.
AT_GID
El ID de grupo real del hilo.
AT_HWCAP
Una máscara de bits dependiente de la arquitectura y la ABI cuya configuración indica capacidades detalladas del procesador. El contenido de la máscara de bits depende del hardware (por ejemplo, consulte el archivo del código fuente del kernel arch/x86/include/asm/cpufeature.h para detalles relacionados con la arquitectura Intel x86; el valor devuelto es la primera palabra de 32 bits del array descrito allí). Una versión legible de la misma información está disponible a través de /proc/cpuinfo.
AT_HWCAP2 (desde glibc 2.18)
Más indicaciones dependientes de la máquina sobre las capacidades del procesador.
AT_ICACHEBSIZE
El tamaño de bloque de la caché de instrucciones.
AT_L1D_CACHEGEOMETRY
Geometría de la caché de datos L1, codificada con el tamaño de línea de caché en bytes en los 16 bits inferiores y la asociatividad de la caché en los siguientes 16 bits. La asociatividad es tal que si N es el valor de 16 bits, la caché es asociativa por conjuntos de vía N.
AT_L1D_CACHESIZE
El tamaño de la caché de datos L1.
AT_L1I_CACHEGEOMETRY
Geometría de la caché de instrucciones L1, codificada como AT_L1D_CACHEGEOMETRY.
AT_L1I_CACHESIZE
El tamaño de la caché de instrucciones L1.
AT_L2_CACHEGEOMETRY
Geometría de la caché L2, codificada como AT_L1D_CACHEGEOMETRY.
AT_L2_CACHESIZE
El tamaño de la caché L2.
AT_L3_CACHEGEOMETRY
Geometría de la caché L3, codificada como AT_L1D_CACHEGEOMETRY.
AT_L3_CACHESIZE
El tamaño de la caché L3.
AT_PAGESZ
El tamaño de página del sistema (el mismo valor devuelto por sysconf(_SC_PAGESIZE)).
AT_PHDR
La dirección de las cabeceras de programa del ejecutable.
AT_PHENT
El tamaño de la entrada de la cabecera de programa.
AT_PHNUM
El número de cabeceras de programa.
AT_PLATFORM
Un puntero a una cadena que identifica la plataforma de hardware en la que se está ejecutando el programa. El enlazador dinámico utiliza esto en la interpretación de los valores de rpath .
AT_RANDOM
La dirección de dieciséis bytes que contienen un valor aleatorio.
AT_SECURE
Tiene un valor distinto de cero si este ejecutable debe ser tratado de forma segura. Lo más común es que un valor distinto de cero indique que el proceso está ejecutando un binario set-user-ID o set-group-ID (de modo que sus UIDs o GIDs reales y efectivos difieren entre sí), o que obtuvo capacidades al ejecutar un archivo binario que tiene capacidades (véase capabilities(7)). Alternativamente, un valor distinto de cero puede ser provocado por un Módulo de Seguridad de Linux. Cuando este valor es distinto de cero, el enlazador dinámico desactiva el uso de ciertas variables de entorno (véase ld-linux.so(8)) y glibc cambia otros aspectos de su comportamiento. (Véase también secure_getenv(3).)
AT_SYSINFO
El punto de entrada a la función de llamada al sistema en la vDSO. No está presente/no es necesario en todas las arquitecturas (p. ej., ausente en x86-64).
AT_SYSINFO_EHDR
La dirección de una página que contiene el Objeto Compartido Dinámico Virtual (vDSO) que el kernel crea para proporcionar implementaciones rápidas de ciertas llamadas al sistema.
AT_UCACHEBSIZE
El tamaño de bloque de la caché unificada.
AT_UID
El ID de usuario real del hilo.

VALOR DE RETORNO

En caso de éxito, getauxval() devuelve el valor correspondiente a type. Si type no se encuentra, se devuelve 0.

ERRORES

ENOENT (desde glibc 2.19)
No se pudo encontrar ninguna entrada correspondiente a type en el vector auxiliar.

ATRIBUTOS

Para una explicación de los términos utilizados en esta sección, véase attributes(7).

Interfaz Atributo Valor
getauxval () Seguridad de hilos MT-Safe

GNU.

HISTORIA

glibc 2.16.

NOTAS

El consumidor principal de la información en el vector auxiliar es el enlazador dinámico, ld-linux.so(8). El vector auxiliar es un atajo conveniente y eficiente que permite al núcleo comunicar un conjunto determinado de información estándar que el enlazador dinámico necesita usualmente o siempre. En algunos casos, la misma información podría obtenerse mediante llamadas al sistema, pero usar el vector auxiliar es más barato.

El vector auxiliar reside justo encima de la lista de argumentos y el entorno en el espacio de direcciones del proceso. El vector auxiliar suministrado a un programa puede visualizarse estableciendo la variable de entorno LD_SHOW_AUXV al ejecutar un programa:


$ LD_SHOW_AUXV=1 sleep 1

El vector auxiliar de cualquier proceso puede (sujeto a los permisos de archivo) obtenerse mediante /proc/pid/auxv; ver proc(5) para más información.

ERRORES

Antes de la adición del error ENOENT en glibc 2.19, no había forma de distinguir inequívocamente el caso en el que type no podía encontrarse del caso en el que el valor correspondiente a type era cero.

VER TAMBIÉN

execve(2), secure_getenv(3), vdso(7), ld-linux.so(8)
