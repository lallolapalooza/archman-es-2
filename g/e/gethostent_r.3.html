DESCRIPCIÓ

N

Las funciones gethostbyname*(), gethostbyaddr*(), herror() y hstrerror() están obsoletas. Las aplicaciones deberían usar getaddrinfo(3), getnameinfo(3) y gai_strerror(3) en su

lugar.

La función sethostent() especifica, si stayopen es verdadero (1), que debe usarse un socket TCP conectado para las consultas al servidor de nombres y que la conexión debe permanecer abierta durante consultas sucesivas. De lo contrario, las consultas al servidor de nombres usarán datagramas

UDP.

La función endhostent() termina el uso de una conexión TCP para consultas al servidor de

nombres.

La función gethostbyname() devuelve una estructura de tipo hostent para el host name dado. Aquí name es o bien un nombre de host o una dirección IPv4 en notación estándar con puntos (como en inet_addr(3)). Si name es una dirección IPv4, no se realiza ninguna búsqueda y gethostbyname() simplemente copia name en el campo h_name y su equivalente struct in_addr en el campo h_addr_list[0] de la estructura hostent devuelta. Si name no termina en un punto y la variable de entorno HOSTALIASES está definida, primero se buscará name en el archivo de alias al que apunta HOSTALIASES (ver hostname(7) para el formato del archivo). Se buscan el dominio actual y sus padres a menos que name termine en un

punto.

La función gethostbyaddr() devuelve una estructura de tipo hostent para la dirección de host addr dada de tamaño size y tipo de dirección type. Los tipos de dirección válidos son AF_INET y AF_INET6 (definidos en <sys/socket.h>). El argumento de dirección del host es un puntero a una estructura de un tipo que depende del tipo de dirección, por ejemplo un struct in_addr * (probablemente obtenido a través de una llamada a inet_addr(3)) para el tipo de dirección AF_INET

.

La función (obsoleta) herror() imprime el mensaje de error asociado con el valor actual de h_errno en stderr

.

La función (obsoleta) hstrerror() toma un número de error (típicamente h_errno) y devuelve la cadena de mensaje correspondiente

.

Las consultas de nombres de dominio realizadas por gethostbyname() y gethostbyaddr() dependen de las fuentes configuradas por el Name Service Switch (nsswitch.conf(5)) o de un servidor de nombres local (named(8)). La acción por defecto es consultar las fuentes configuradas por el Name Service Switch (nsswitch.conf(5)) y, si esto falla, un servidor de nombres local (named(8))

.

Históric

o

El archivo nsswitch.conf(5) es la forma moderna de controlar el orden de las búsquedas de

hosts.

En glibc 2.4 y anteriores, la palabra clave order se usaba para controlar el orden de las búsquedas de hosts como se define en /etc/host.conf (host.conf(5))

.

NAME

gethostent, gethostent_r, sethostent, endhostent - obtén una entrada de la base de datos de hosts

LIBRARY

Biblioteca de C estándar (libc, -lc)

SYNOPSIS

#include <netdb.h>
int gethostent_r(struct hostent *ret, char *buf, size_t buflen, struct hostent **result, int *h_errnop);
struct hostent *gethostent(void);
void sethostent(int stayopen);
void endhostent(void);

DESCRIPTION

These functions iterate through the host database. The host database can be the network-provided database or the host table file (/etc/hosts). The search order is controlled by the /etc/host.conf file (see host.conf(5)) and/or the nsswitch.conf(5) file.

sethostent() opens the connection to the name server or the host file. If the argument stayopen is non-zero, it tells the implementation to keep the file descriptor open across calls. Otherwise, it will be closed after each call.

gethostent() returns the next entry from the host database. The hostent structure is described in gethostbyname(3).

endhostent() closes the connection to the name server or the host file.

gethostent_r() is the reentrant version of gethostent(). It stores the result in the user-supplied hostent structure pointed to by ret. The buffer pointed to by buf with size buflen is used for allocating names and addresses. On success, result is set to point to ret, and 0 is returned. On error, result is set to NULL, and a nonzero error number is returned. If the buffer is too small, result is set to NULL, ERANGE is returned, and the call should be retried with a larger buffer. The error code is stored in the location pointed to by h_errnop. If no more entries are found, result is set to NULL and 0 is returned.

RETURN VALUE

On success, gethostent() returns a pointer to a hostent structure. On error or end of file, it returns NULL. Note that if the implementation uses static storage for the hostent structure, the contents of the structure may be overwritten by subsequent calls to other `gethost*` functions.

gethostent_r() returns 0 on success, or a nonzero error number on failure (e.g., ERANGE if the buffer is too small).

The variable h_errno (see ERRORS) is set on error.

ERRORS

The variable h_errno can have the following values:

HOST_NOT_FOUND
The specified host is unknown.
NO_DATA
The requested name is valid but does not have an IP address. Another type of request to the name server for this domain may return an answer. The constant NO_ADDRESS is a synonym for NO_DATA.
NO_RECOVERY
A nonrecoverable name server error occurred.
TRY_AGAIN
A temporary error occurred on an authoritative name server. Try again later.

NOTES

The functions gethostbyname() and gethostbyaddr() may return pointers to static data, which may be overwritten by later calls. Copying the struct hostent does not suffice, since it contains pointers; a deep copy is required.

In the original BSD implementation the size argument of gethostbyname() was an int. The SUSv2 standard is buggy and declares the size argument of gethostbyaddr() to be of type size_t. (That is wrong, because it has to be int, and size_t is not. POSIX.1-2001 makes it socklen_t, which is OK.) See also accept(2).

The BSD prototype for gethostbyaddr() uses const char * for the first argument.

System V/POSIX extension

POSIX requires the gethostent() call, which should return the next entry in the host data base. When using DNS/BIND this does not make much sense, but it may be reasonable if the host data base is a file that can be read line by line. On many systems, a routine of this name reads from the file /etc/hosts. It may be available only when the library was built without DNS support. The glibc version will ignore ipv6 entries. This function is not reentrant, and glibc adds a reentrant version gethostent_r().

GNU extensions

glibc2 also has a gethostbyname2() that works like gethostbyname(), but permits to specify the address family to which the address must belong.

glibc2 also has reentrant versions gethostent_r(), gethostbyaddr_r(), gethostbyname_r(), and gethostbyname2_r(). The caller supplies a hostent structure ret which will be filled in on success, and a temporary work buffer buf of size bufsize. After the call, result will point to the result on success. In case of an error or if no entry is found result will be NULL. The functions return 0 on success and a nonzero error number on failure. In addition to the errors returned by the nonreentrant versions of these functions, if buf is too small, the functions will return ERANGE, and the call should be retried with a larger buffer. The global variable h_errno is not modified, but the address of a variable in which to store error numbers is passed in h_errnop.

BUGS

gethostbyname() does not recognize components of a dotted IPv4 address string that are expressed in hexadecimal.
