DESCRIPCIÓ

N

Estas llamadas al sistema proporcionan acceso a temporizadores de intervalo, es decir, temporizadores que inicialmente expiran en algún momento en el futuro y (opcionalmente) a intervalos regulares después de eso. Cuando un temporizador expira, se genera una señal para el proceso que llama, y el temporizador se restablece al intervalo especificado (si el intervalo no es cero)

.

Se proporcionan tres tipos de temporizadores—especificados a través del argumento which—, cada uno de los cuales cuenta contra un reloj diferente y genera una señal diferente al expirar el

temporizador:
ITIMER_RE
AL
Este temporizador cuenta hacia atrás en tiempo real (es decir, tiempo de reloj de pared). En cada expiración, se genera una señal SIG
ALRM.
ITIMER_VIRTU
AL
Este temporizador cuenta hacia atrás contra el tiempo de CPU en modo usuario consumido por el proceso. (La medición incluye el tiempo de CPU consumido por todos los hilos en el proceso.) En cada expiración, se genera una señal SIGVT
ALRM.
ITIMER_PR
OF
Este temporizador cuenta hacia atrás contra el tiempo total de CPU (es decir, tanto de usuario como de sistema) consumido por el proceso. (La medición incluye el tiempo de CPU consumido por todos los hilos en el proceso.) En cada expiración, se genera una señal S
IGP
ROF.
En conjunto con ITIMER_VIRTUAL, este temporizador se puede usar para perfila
r el tiempo de CPU de usuario y
sistema consumido por el proceso.

Un proceso tiene solo uno de cada uno de los tres tipos de

temporizadores.

Los valores de los temporizadores están definidos por las siguientes

estructuras: 


struct itimerval {
    struct timeval it_interval; /* Intervalo para el temporizador periódico */
    struct timeval it_value;    /* Tiempo hasta la siguiente expiración */
};
struct timeval {
    time_t      tv_sec;         /* segundos */
    suseconds_t tv_usec;        /* microsegundos */
}
;

getitimer(

)

La función getitimer() coloca el valor actual del temporizador especificado por which en el búfer apuntado por curr_value

.

La subestructura it_value se rellena con la cantidad de tiempo restante hasta la siguiente expiración del temporizador especificado. Este valor cambia a medida que el temporizador cuenta hacia atrás, y se restablecerá a it_interval cuando el temporizador expire. Si ambos campos de it_value son cero, entonces este temporizador está actualmente desarmado (inactivo)

.

La subestructura it_interval se rellena con el intervalo del temporizador. Si ambos campos de it_interval son cero, entonces este es un temporiz

ador de disparo único (es d
ecir, expira solo una vez).

setitimer(

)

La función setitimer() arma o desarma el temporizador especificado por which, estableciendo el temporizador al valor especificado por new_value. Si old_value no es NULL, el búfer al que apunta se usa para devolver el valor anterior del temporizador (es decir, la misma información que es devuelta por getitimer())

.

Si cualquiera de los campos en new_value.it_value no es cero, entonces el temporizador se arma para expirar inicialmente en el tiempo especificado. Si ambos campos en new_value.it_value son cero, entonces el temporizador se

desarma.

El campo new_value.it_interval especifica el nuevo intervalo p

Los estándares son silenciosos sobre el significado de la

llamada: 


setitimer(which, NULL, &old_value)

Muchos sistemas (Solaris, los BSD, y quizás otros) tratan esto como equivalente

En Linux, esto se trata como equivalente a una llamada en la que los campos new_value son cero; es decir, el temporizador está deshabilitado. No use esta característica defectuosa de

Linux: no es portable

HISTORI

A

ugar. POSIX.1-2
024 los eliminó.

NOTA

S

Los temporizadores nunca expirarán antes del tiempo solicitado, pero pueden expirar algún tiempo (corto) después, lo que depende de la resolución del temporizador del sistema y de la carga del sistema; véase time(7). (Pero véase ERRORES a continuación.) Si el temporizador expira mientras el proceso está activo (siempre cierto para ITIMER_VIRTUAL), la señal se entregará inmediatamente cuando se

genere.

Un hijo creado a través de fork(2) no hereda los temporizadores de intervalo de su padre. Los temporizadores de intervalo se conservan a través de un execve(

2).

POSIX.1 deja la interacción entre setitimer() y las tres interfaces alarm(2), sleep(3), y usleep(3) s

in espe
cificar.

ERRORE

S

La generación y entrega de una señal son distintas, y solo una instancia de cada una de las señales listadas arriba puede estar pendiente para un proceso. Bajo una carga muy pesada, un temporizador ITIMER_REAL puede expirar antes de que la señal de una expiración anterior haya sido entregada. La segunda señal en tal evento se

perderá.

Antes de Linux 2.6.16, los valores de los temporizadores se representaban en jiffies. Si se hace una solicitud para establecer un temporizador con un valor cuya representación en jiffies excede MAX_SEC_IN_JIFFIES (definido en include/linux/jiffies.h), entonces el temporizador se trunca silenciosamente a este valor máximo. En Linux/i386 (donde, desde Linux 2.6.13, el jiffy predeterminado es 0.004 segundos), esto significa que el valor máximo para un temporizador es aproximadamente 99.42 días. Desde Linux 2.6.16, el núcleo usa una representación interna diferente para los tiempos, y este límite se

elimina.

En ciertos sistemas (incluyendo i386), los núcleos de Linux anteriores a Linux 2.6.12 tienen un error que producirá expiraciones prematuras del temporizador de hasta un jiffy bajo algunas circunstancias. Este error está corregido en Linux 2.6.

12.

POSIX.1-2001 dice que setitimer() debería fallar si tv_useSe especifica un valor c que está fuera del rango [0, 999999]. Sin embargo, hasta y incluyendo Linux 2.6.21, Linux no da un error, sino que en su lugar ajusta silenciosamente el valor de segundos correspondiente para el temporizador. Desde Linux 2.6.22 en adelante, esta no conformidad ha sido reparada: un valor tv_usec incorrecto resulta en un error

EINV
AL.
