getpid(2) Manual de llamadas al sistema getpid(2)

NOMBRE

getpid, getppid - obtener la identificación del proceso

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
pid_t getpid(void);
pid_t getppid(void);

DESCRIPCIÓN

getpid() devuelve el ID del proceso (PID) del proceso que llama. (Esto se utiliza a menudo en rutinas que generan nombres de archivo temporales únicos).

getppid() devuelve el ID del proceso padre del proceso que llama. Este será el ID del proceso que creó este proceso usando fork(), o, si ese proceso ya ha terminado, el ID del proceso al que se ha reparentado este proceso (ya sea init(1) o un proceso "subreaper" definido mediante la operación PR_SET_CHILD_SUBREAPER de prctl(2)).

ERRORES

Estas funciones siempre tienen éxito.

VERSIÓNES

En Alpha, en lugar de un par de llamadas al sistema getpid() y getppid(), se proporciona una única llamada al sistema getxpid(), que devuelve un par de PID y PID padre. Las funciones de envoltura getpid() y getppid() de glibc se encargan de esto de forma transparente. Vea syscall(2) para obtener detalles sobre el mapeo de registros.

ESTÁNDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2001, 4.3BSD, SVr4.

Diferencias biblioteca C/núcleo

Desde glibc 2.3.4 hasta glibc 2.24 (inclusive), la función de envoltura de glibc para getpid() almacenaba en caché los PID, con el objetivo de evitar llamadas adicionales al sistema cuando un proceso llama a getpid() repetidamente. Normalmente, esta caché era invisible, pero su correcto funcionamiento dependía del soporte en las funciones de envoltura para fork(2), vfork(2) y clone(2): si una aplicación omitía las envolturas de glibc para estas llamadas al sistema usando syscall(2), entonces una llamada a getpid() en el hijo devolvería el valor incorrecto (para ser precisos: devolvería el PID del proceso padre). Además, hubo casos en los que getpid() podría devolver el valor incorrecto incluso al invocar clone(2) a través de la función de envoltura de glibc. (Para una discusión de uno de esos casos, vea BUGS en clone(2).) Además, la complejidad del código de caché ha sido la fuente de algunos errores dentro de glibc a lo largo de los años.

Debido a los problemas mencionados, desde glibc 2.25, la caché de PID se ha eliminado: las llamadas a getpid() invocan siempre la llamada al sistema real, en lugar de devolver un valor en caché.

NOTAS

Si el padre del llamador está en un espacio de nombres PID diferente (vea pid_namespaces(7)), getppid() devuelve 0.

Desde la perspectiva del núcleo, el PID (que es compartido por todos los hilos en un proceso multihilo) a veces también se conoce como ID del grupo de hilos (TGID). Esto contrasta con el ID del hilo del núcleo (TID), que es único para cada hilo. Para más detalles, vea gettid(2) y la discusión de la bandera CLONE_THREAD en clone(2).
