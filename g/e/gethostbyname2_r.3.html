DESCRIPCIÓN

Las funciones gethostbyname*(), gethostbyaddr*(), herror() y hstrerror() están obsoletas. Las aplicaciones deben utilizar getaddrinfo(3), getnameinfo(3) y gai_strerror(3) en su lugar.

La función sethostent() especifica, si stayopen es verdadero (1), que se debe usar un socket TCP conectado para las consultas del servidor de nombres y que la conexión debe permanecer abierta durante consultas sucesivas. De lo contrario, las consultas del servidor de nombres utilizarán datagramas UDP.

La función endhostent() finaliza el uso de una conexión TCP para consultas del servidor de nombres.

La función gethostbyname() devuelve una estructura de tipo hostent para el nombre de host name dado. Aquí name es un nombre de host o una dirección IPv4 en notación de puntos estándar (como para inet_addr(3)). Si name es una dirección IPv4, no se realiza ninguna búsqueda y gethostbyname() simplemente copia name en el campo h_name y su equivalente en struct in_addr en el campo h_addr_list[0] de la estructura hostent devuelta. Si name no termina en un punto y la variable de entorno HOSTALIASES está establecida, se buscará primero en el archivo de alias apuntado por HOSTALIASES el name (ver hostname(7) para el formato del archivo). Se buscarán el dominio actual y sus padres a menos que name termine en un punto.

La función gethostbyaddr() devuelve una estructura de tipo hostent para la dirección de host addr dada de tamaño size y tipo de dirección type. Los tipos de dirección válidos son AF_INET y AF_INET6 (definidos en <sys/socket.h>). El argumento de dirección de host es un puntero a una struct de un tipo dependiente del tipo de dirección, por ejemplo, un struct in_addr * (probablemente obtenido mediante una llamada a inet_addr(3)) para el tipo de dirección AF_INET.

La función (obsoleta) herror() imprime el mensaje de error asociado con el valor actual de h_errno en stderr.

La función (obsoleta) hstrerror() toma un número de error (típicamente h_errno) y devuelve la cadena de mensaje correspondiente.

Las consultas de nombres de dominio realizadas por gethostbyname() y gethostbyaddr() se basan en las fuentes configuradas del Conmutador de Servicios de Nombres (nsswitch.conf(5)) o en un servidor de nombres local (named(8)). La acción predeterminada es consultar las fuentes configuradas del Conmutador de Servicios de Nombres (nsswitch.conf(5)), en caso de fallo, a un servidor de nombres local (named(8)).

Histórico

El archivo nsswitch.conf(5) es la forma moderna de controlar el orden de las búsquedas de hosts.

En glibc 2.4 y anteriores, la palabra clave order se usaba para controlar el orden de las búsquedas de hosts según se definía en /etc/host.conf (host.conf(5)).

La estructura hostent se define en <netdb.h> como sigue:


struct hostent {
    char  *h_name;            /* nombre oficial del host */
    char **h_aliases;         /* lista de alias */
    int    h_addrtype;        /* tipo de dirección del host */
    int    h_length;          /* tamaño de la dirección */
    char **h_addr_list;       /* lista de direcciones */
}
#define h_addr h_addr_list[0] /* para compatibilidad hacia atrás */

Los miembros de la estructura hostent son:

h_name
El nombre oficial del host.
h_aliases
Un array de nombres alternativos para el host, terminado por un puntero nulo.
h_addrtype
El tipo de dirección; actualmente siempre AF_INET o AF_INET6.
h_length
El tamaño de la dirección en bytes.
h_addr_list
Un array de punteros a direcciones de red para el host (en orden de bytes de red), terminado por un puntero nulo.
h_addr
La primera dirección en h_addr_list para compatibilidad hacia atrás.

NOTA

S

Las funciones gethostbyname() y gethostbyaddr() pueden devolver punteros a datos estáticos, que pueden ser sobrescritos por llamadas posteriores. Copiar el struct hostent no es suficiente, ya que contiene punteros; se requiere una copia

profunda.

En la implementación original de BSD, el argumento size de gethostbyname() era un int. El estándar SUSv2 tiene un error y declara que el argumento size de gethostbyaddr() es de tipo size_t. (Esto es incorrecto, porque tiene que ser int, y size_t no lo es. POSIX.1-2001 lo hace socklen_t, lo cual es correcto.) Véase también accept(

2).

El prototipo de BSD para gethostbyaddr() usa const char * para el primer

argumento.

Extensión de System

V/POSIX

POSIX requiere la llamada gethostent(), que debería devolver la siguiente entrada en la base de datos de hosts. Al usar DNS/BIND esto no tiene mucho sentido, pero puede ser razonable si la base de datos de hosts es un archivo que se puede leer línea por línea. En muchos sistemas, una rutina con este nombre lee del archivo /etc/hosts. Puede estar disponible solo cuando la biblioteca se compiló sin soporte DNS. La versión de glibc ignorará las entradas ipv6. Esta función no es reentrante, y glibc añade una versión reentrante gethoste

nt_
r().

Extensiones

GNU

glibc2 también tiene un gethostbyname2() que funciona como gethostbyname(), pero permite especificar la familia de direcciones a la que debe pertenecer la

dirección.

glibc2 también tiene versiones reentrantes gethostent_r(), gethostbyaddr_r(), gethostbyname_r(), y gethostbyname2_r(). El llamante proporciona una estructura hostent ret que se rellenará en caso de éxito, y un búfer de trabajo temporal buf de tamaño bufsize. Después de la llamada, result apuntará al resultado en caso de éxito. En caso de error o si no se encuentra ninguna entrada, result será NULL. Las funciones devuelven 0 en caso de éxito y un número de error distinto de cero en caso de fallo. Además de los errores devueltos por las versiones no reentrantes de estas funciones, si buf es demasiado pequeño, las funciones devolverán ERANGE, y la llamada debería reintentarse con un búfer más grande.
