DESCRIPCIÓN

Las llamadas a las funciones getdns requieren un contexto DNS, que es un conjunto de configuraciones de API que afectan cómo se realizan las llamadas DNS. Para la mayoría de las aplicaciones, un contexto predeterminado es suficiente.

Para crear un nuevo contexto DNS, utilice la función:


getdns_return_t getdns_context_create (getdns_context_t *context, bool set_from_os)

La llamada a getdns_context_create devuelve inmediatamente un contexto que se puede utilizar con otras llamadas a la API; ese contexto contiene los valores predeterminados de la API. La mayoría de las aplicaciones querrán que set_from_os sea true.

Para limpiar el contexto, incluida la limpieza de todas las transacciones pendientes que se realizaron utilizando este contexto, utilice la función:


void getdns_context_destroy (getdns_context_t context)

Cuando getdns_context_destroy() retorna, la aplicación sabe que todas las transacciones pendientes asociadas con este contexto habrán sido llamadas; las devoluciones de llamada que no se habían realizado antes de llamar a getdns_context_destroy() se llamarán con un tipo de devolución de llamada de GETDNS_CALLBACK_CANCEL. getdns_context_destroy() retorna después de que se haya realizado toda la limpieza necesaria y las devoluciones de llamada.

Si está utilizando getdns de forma multihilo, entonces, por supuesto, está utilizando la biblioteca subyacente OpenSSL de forma multihilo y la versión de esa biblioteca en uso podría tener requisitos sobre este tema. Es posible que deba proporcionar una o dos funciones para permitir que funcione correctamente. Por ejemplo, antes de llamar a getdns_context_create(), es posible que deba utilizar las funciones de OpenSSL CRYPTO_set_id_callback y CRYPTO_set_locking_callback para configurar la operación asíncrona (la aplicación llama a estas funciones una vez para la inicialización). OpenSSL 1.0.0 o posterior utiliza la función CRYPTO_THREADID_set_callback.

context Se utiliza para devolver el puntero a una estructura opaca. El llamante pasa la dirección de un puntero (decl: getdns_context *context; pasado como &context) que se poblará como resultado de retornar de la función. El resultado es un contexto recién asignado e inicializado (si no hay errores). En la función getdns_destroy_context, este es el contexto cuya memoria asociada se liberará.

set_from_os Si set_from_os es 0, el llamante debe proporcionar servidores de nombres de reenvío si se ejecuta en modo stub. Si set_from_os es 1, se utilizan los archivos del sistema para inicializar el contexto. /etc/resolv.conf se utiliza para poblar los reenviadores cuando se ejecuta como un resolvedor stub (solo se reconocen las líneas "nameserver"). Si set_from_os es 1, las entradas de /etc/hosts tienen prioridad antes de recurrir a una consulta DNS. Los errores en los archivos del sistema no impedirán la construcción del contexto.

userarg En el caso de uso extendido, este argumento se pasa sin cambios a cada una de las funciones de gestión de memoria cada vez que se llaman.

malloc La función que se utilizará para crear diccionarios de respuesta (y los miembros dentro de los diccionarios de respuesta). Por defecto, se utiliza el malloc del sistema.

realloc La función que se utilizará para crear diccionarios de respuesta (y los miembros dentro de los diccionarios de respuesta). Por defecto, se utiliza el realloc del sistema.

free La función que se utilizará para liberar el espacio de almacenamiento para los diccionarios de respuesta (y los miembros dentro de los diccionarios de respuesta). Por defecto, se utiliza el free del sistema.

DESCRIPCIÓN (LARGA)

Muchas llamadas en la API DNS requieren un contexto DNS. Un contexto DNS contiene la información que la API necesita para procesar las llamadas DNS, como las ubicaciones de los servidores DNS intermedios, los anclas de confianza de DNSSEC, etc. La estructura interna del contexto DNS es opaca y puede ser diferente en cada sistema operativo. Cuando se pasa un contexto a cualquier función, debe ser un contexto asignado; el contexto no debe ser NULL.

Una aplicación típica que utiliza esta API no necesita saber nada sobre los contextos. Básicamente, la aplicación crea un contexto predeterminado, lo utiliza en las funciones que requieren un contexto y luego lo desasigna cuando termina. La manipulación de contextos está disponible para programas con más conocimiento de DNS, pero es poco probable que interese a las aplicaciones que solo desean los resultados de las búsquedas de registros A, AAAA, SRV y PTR.

Se espera que los contextos en las implementaciones de la API no sean necesariamente seguros para hilos, pero no serán hostiles a los hilos. No se debe usar un contexto en varios hilos: cree un nuevo contexto para usarlo en un hilo diferente. Está bien que una aplicación tenga muchos contextos, y algunas aplicaciones con mucha carga de DNS ciertamente querrán tener muchos, incluso si la aplicación utiliza un solo hilo.

Cuando el contexto se utiliza en la API por primera vez y set_from_os es 1, la API comienza a reemplazar algunos de los valores con valores del sistema operativo, como los que se encontrarían en res_query(3), /etc/resolv.conf, etc., y luego procede con la nueva función. Algunos usuarios avanzados no querrán que la API cambie los valores a los valores predeterminados del sistema operativo; si set_from_os es 0, la API no realizará ninguna actualización de los valores iniciales basada en los cambios en el sistema operativo. Por ejemplo, esto podría ser útil si la API actúa como un resolvedor stub que está utilizando un resolvedor recursivo DNS específico elegido por la aplicación, no el que podría provenir de DHCP.

VALORES DE RETORNO

Tras una finalización exitosa, cada una de estas funciones devuelve GETDNS_RETURN_GOOD, de lo contrario, se devuelven los siguientes valores de error:

GETDNS_RETURN_GENERIC_ERROR la asignación de memoria falló o sucedió algo inesperado durante la inicialización del contexto

GETDNS_RETURN_BAD_CONTEXT si el puntero de contexto no es válido (getdns_context_destroy)

El getdns_dict devuelto por getdns_context_get_api_information debe ser destruido por el llamante e incluye los siguientes pares nombre/valor:

version_string
un bindata que contiene una cadena imprimible de la versión de la API DNS implementada por esta biblioteca
implementation_string
un bindata que contiene una cadena imprimible establecida por la implementación
resolution_type
un int igual a GETDNS_RESOLUTION_RECURSING o GETDNS_RESOLUTION_STUB
all_context
un getdns_dict con nombres para todos los tipos de contexto, páselo a getdns_pretty_print_dict(3) para obtener algo fácilmente legible
