Paquete: getdns

Licencias: BSD

NOMBRE

getdns_general, getdns_general_sync -- realizar una consulta DNS getdns

BIBLIOTECA

Biblioteca de resolución DNS (libgetdns, -lgetdns)

SINOPSIS

#include <getdns.h>

getdns_return_t
getdns_general (getdns_context *context,

const char *name,
uint16_t request_type
getdns_dict *extensions,
void *userarg,
getdns_transaction_t *transaction_id,
getdns_callback_t callbackfn)

getdns_return_t
getdns_general_sync (getdns_context *context,

const char *name,
uint16_t request_type
getdns_dict *extensions,
getdns_dict **response)

DESCRIPCIÓN

Las funciones getdns_general(3) y getdns_general_sync proporcionan puntos de entrada públicos a la biblioteca de la API getdns para recuperar cualquier respuesta válida a una consulta del DNS (tenga en cuenta que otros espacios de nombres en el contexto no se utilizan). La mayoría de los casos de uso típicos para las aplicaciones probablemente se satisfagan a través de llamadas a getdns_address(3), que reemplazaría a getaddrinfo(3).

context Un puntero al contexto DNS creado previamente que se utilizará con esta solicitud DNS. Ver getdns_context (3)

name El nombre de dominio basado en ASCII buscado como una cadena. También puede ser una dirección IPv4 o IPv6 para tipos de solicitud que toman direcciones en lugar de nombres de dominio, como PTR. Los valores aquí siguen las reglas de la sección 2.1 de RFC 4343 para permitir octetos no ASCII y caracteres especiales en las etiquetas.

request_type Especifica el tipo RR para la consulta; los números de tipo RR se enumeran en el registro IANA. Por ejemplo, para obtener los registros NS, request_type sería 2. La API también tiene macros definidas para la mayoría de los tipos RR por nombre; los nombres de definición comienzan todos con "GETDNS_RRTYPE_". Por ejemplo, para obtener los registros NS, también puede establecer request_type a GETDNS_RRTYPE_NS.

extensions extensiones para esta solicitud, NULL si no hay extensiones, ver libgetdns (3) para una descripción detallada de las extensiones

userarg devuelto a la función de devolución de llamada sin cambios, puede ser NULL

transaction_id poblado por la API y utilizado para identificar la devolución de llamada (por ejemplo, para getdns_cancel_callback), puede ser NULL, establecido a 0 si la función falla

callbackfn puntero no NULL a una función de devolución de llamada definida por la aplicación, utilizada típicamente para procesar la respuesta. Solo la firma asíncrona acepta una función de devolución de llamada, la firma síncrona no incluye una devolución de llamada. Ver libgetdns (3) para una discusión más detallada de las funciones de devolución de llamada.

response Se devuelve un tipo getdns_dict en la respuesta y siempre contiene al menos tres nombres: replies_full (una lista que contiene la respuesta DNS como datos binarios), replies_tree (una lista que contiene los datos de la respuesta DNS analizados) y status (un entero). El almacenamiento asociado con esto debe liberarse mediante una llamada a getdns_free_sync_request_memory (3).

VALORES DE RETORNO

Al completarse correctamente, las funciones devuelven GETDNS_RETURN_GOOD, de lo contrario, se devuelven los siguientes valores de error:

GETDNS_RETURN_BAD_CONTEXT si el puntero de contexto es inválido o si el contexto tiene deficiencias internas

GETDNS_RETURN_BAD_DOMAIN_NAME si el nombre de dominio pasado a la función es inválido

GETDNS_RETURN_EXTENSION_MISFORMAT si el tipo de dato especificado en una o más extensiones no coincide con las especificaciones

GETDNS_RETURN_GENERIC_ERROR si se encontró algún problema en la función no abordado por uno de los códigos de retorno más específicos

GETDNS_RETURN_INVALID PARAMETER si uno o más parámetros tienen un valor inválido

GETDNS_RETURN_MEMORY_ERROR si no se puede asignar la memoria requerida

GETDNS_RETURN_NO_SUCH_EXTENSION si uno o más de las cadenas especificadas en las extensiones no son válidas

Los valores de estado incluidos en el parámetro response son:

GETDNS_RESPSTATUS_GOOD si se devolvió al menos una respuesta

GETDNS_RESPSTATUS_NO_NAME si las consultas para el nombre produjeron todas respuestas negativas

GETDNS_RESPSTATUS_ALL_TIMEOUT si todas las consultas para el nombre expiraron

GETDNS_RESPSTATUS_NO_SECURE_ANSWERS si solo se aceptaron respuestas seguras (según el contexto) y se recibió al menos una respuesta, pero ninguna respuesta DNS fue segura a través de DNSSEC

Para una explicación más detallada del objeto de respuesta, consulte libgetdns (3)
