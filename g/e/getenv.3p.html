GETENV(3P) Manual del programador POSIX GETENV(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual correspondiente de Linux para conocer los detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

getenv — obtener el valor de una variable de entorno

SINOPSIS

#include <stdlib.h>
char *getenv(const char *name);

DESCRIPCIÓN

La funcionalidad descrita en esta página de referencia está alineada con el estándar ISO C. Cualquier conflicto entre los requisitos descritos aquí y el estándar ISO C es no intencional. Este volumen de POSIX.1‐2017 remite al estándar ISO C.

La función getenv() buscará en el entorno del proceso que la llama (consulte el volumen de Definiciones Base de POSIX.1‐2017, Capítulo 8, Variables de entorno) la variable de entorno name si existe y devolverá un puntero al valor de la variable de entorno. Si no se encuentra la variable de entorno especificada, se devolverá un puntero nulo. La aplicación debe asegurarse de no modificar la cadena apuntada por la función getenv().

El puntero de cadena devuelto puede quedar invalidado o el contenido de la cadena puede ser sobrescrito por una llamada posterior a getenv(), setenv(), unsetenv(),
o (si se soporta) putenv(), pero no se verá afectado por una llamada a ninguna otra función de este volumen de POSIX.1‐2017.

El puntero de cadena devuelto también puede quedar invalidado si el hilo que llama es terminado.

La función getenv() no necesita ser segura para hilos.

VALOR DE RETORNO

Tras completarse con éxito, getenv() devolverá un puntero a una cadena que contiene el valor para el nombre especificado. Si el nombre especificado no se encuentra en el entorno del proceso que llama, se devolverá un puntero nulo.

ERRORES

No se definen errores.

Las siguientes secciones son informativas.

EJEMPLOS

Obtener el valor de una variable de entorno

El siguiente ejemplo obtiene el valor de la variable de entorno HOME.

#include <stdlib.h>
...
const char *name = "HOME";
char *value;
value = getenv(name);

USO DE LA APLICACIÓN

Ninguno.

RACIONAMIENTO

La función clearenv() se consideró pero se rechazó. La función putenv() se ha incluido ahora para alinearse con la Single UNIX Specification.

La función getenv() no es intrínsecamente segura para hilos porque devuelve un valor que apunta a datos estáticos.

Se requiere que las aplicaciones conformes no modifiquen directamente los punteros a los que apunta environ, sino que utilicen únicamente las funciones setenv(), unsetenv() y putenv(), o la asignación a environ, para manipular el entorno del proceso. Esta restricción permite a la implementación gestionar adecuadamente la memoria que asigna. Esto permite a la implementación liberar cualquier espacio que haya asignado a cadenas (y quizás a los punteros a ellas) almacenadas en environ cuando se llama a unsetenv(). Un procedimiento de inicio del entorno de ejecución de C (que llama a main() y quizás inicializa environ) también puede inicializar una bandera que indique que el entorno aún no ha sido copiado a almacenamiento asignado, o que la tabla separada aún no se ha inicializado. Si la aplicación cambia a un entorno completamente nuevo asignando un nuevo valor a environ, esto puede ser detectado por getenv(), setenv(), unsetenv() o putenv() y la implementación puede en ese momento reinicializarse basándose en el nuevo entorno. (Esto puede incluir la copia de las cadenas del entorno en una nueva matriz y la asignación de environ para que apunte a ella.)

De hecho, para un mayor rendimiento de getenv(), las implementaciones que no proporcionan putenv() también podrían mantener una copia separada del entorno en una estructura de datos que pudiera buscarse mucho más rápidamente (como una tabla hash indexada o un árbol binario), y actualizar tanto esta como la lista lineal en environ cuando se invoca setenv() o unsetenv(). En implementaciones que sí proporcionan putenv(), una copia de este tipo aún podría valer la pena, pero tendría que permitir el hecho de que las aplicaciones pueden modificar directamente el contenido de las cadenas de entorno añadidas con putenv(). Por ejemplo, si una cadena de entorno encontrada al buscar la copia es una que se añadió usando putenv(), la implementación necesitaría verificar que la cadena en environ todavía tiene el mismo nombre (y valor, si la copia incluye valores), y siempre que la búsqueda en la copia no produzca ningún resultado, la implementación debería entonces buscar cada cadena de entorno en environ que se añadió usando putenv() en caso de que alguna de ellas haya cambiado su nombre y ahora coincida. Por lo tanto, cada uso de putenv() para añadir al entorno reduciría la ventaja de velocidad de tener la copia.

El rendimiento de getenv() puede ser importante para las aplicaciones que tienen un gran número de variables de entorno. Típicamente, las aplicaciones de este tipo utilizan el entorno como una base de datos de recursos de parámetros configurables por el usuario. El hecho de que estas variables estén en el entorno de shell del usuario generalmente significa que cualquier otro programa que utilice variables de entorno (como ls, que intenta utilizar COLUMNS), o realmente casi cualquier utilidad ( LANG, LC_ALL, etc.) se ve igualmente ralentizado por la búsqueda lineal a través de las variables.

Una implementación que mantiene estructuras de datos separadas, o incluso una que gestiona la memoria que consume, no se requiere actualmente ya que se pensó que reduciría el consenso entre los implementadores que no quieren cambiar sus implementaciones históricas.

DIRECCIONES FUTURAS

Una versión futura puede añadir una o más funciones para acceder y modificar el entorno de manera segura para hilos.
