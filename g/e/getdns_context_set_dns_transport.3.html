DESCRIPCIÓN

Estas funciones se utilizan para manipular un contexto previamente asignado e inicializado, ver getdns_context (3) para más detalles sobre las funciones utilizadas para asignar, inicializar y destruir contextos, y para una discusión más detallada del contexto getdns en general.

getdns_context_set_append_name Especifica si se debe añadir un sufijo proporcionado a través de getdns_context_set_suffix (3) a la cadena de consulta antes de que la API comience a resolver un nombre.

getdns_context_set_context_update_callback establece una función que se llamará si hay cambios en los archivos del sistema (por ejemplo, /etc/resolv.conf y /etc/hosts).

getdns_context_set_dns_transport especifica el transporte utilizado para las búsquedas DNS, por defecto se utiliza UDP y se recurre a TCP según sea necesario.

getdns_context_set_dnssec_trust_anchors permite al llamador especificar anclas de confianza como alternativas a las anclas de confianza predeterminadas.

getdns_context_set_dnssec_allowed_skew establece el número de segundos de desfase permitido en cualquier dirección al comprobar los campos de expiración e inicio de un RRSIG, el valor predeterminado es 0.

getdns_context_set_limit_outstanding_queries especifica el número máximo de consultas DNS pendientes, la API pondrá en cola las consultas que superen este límite hasta que las consultas actuales obtengan respuesta y luego emitirá automáticamente las consultas de la cola.

getdns_context_set_dns_root_servers proporciona un conjunto alternativo de direcciones para buscar los dominios de nivel superior. La predeterminada (si no se llama a esta función) es la lista de servidores raíz de la IANA (piense en esto como las sugerencias raíz).

getdns_context_set_follow_redirects especifica si las consultas DNS siguen o no los redireccionamientos (CNAME y DNAME), el comportamiento predeterminado es seguir los redireccionamientos y devolver el destino final.

getdns_context_set_namespaces establece los espacios de nombres que serán utilizados por el resolvedor, por defecto es DNS y luego archivos locales. Implementaciones futuras soportarán netbios, mdns y nis.

getdns_context_set_resolution_type especifica si las consultas DNS se realizan con búsquedas no recursivas o como un resolvedor stub.

getdns_context_set_suffix Añade sufijos a los nombres de dominio antes de ejecutar la búsqueda basándose en getdns_context_set_append_name.

getdns_context_set_timeout especifica el número de milisegundos que la API esperará una respuesta.

contexto un getdns_context previamente asignado e inicializado

callback una función de devolución de llamada que se llamará cuando se realicen cambios en los archivos del sistema (/etc/resolv.conf y /etc/hosts) para contextos creados con set_from_os = 1. Cuando se llame a esta función, el parámetro item_cambiado indicará qué elemento del contexto ha cambiado.

direcciones_raiz Esta es una lista de tipos getdns_dict que cada uno identifica a un único servidor raíz para usar en la búsqueda de dominios de nivel superior. Cada diccionario incluye dos nombres, tipo_direccion, un bindata que contiene la cadena "IPv4" o "IPv6" y datos_direccion un bindata que contiene la dirección IP.

transporte puede ser uno de GETDNS_CONTEXT_UDP_FIRST_AND_FALL_BACK_TO_TCP, GETDNS_CONTEXT_UDP_ONLY, GETDNS_CONTEXT_TCP_ONLY, GETDNS_CONTEXT_TCP_ONLY_KEEP_CONNECTIONS_OPEN. Si necesita más información sobre lo que significa cada uno de estos, relea el mnemónico y adivine ;)

seguir_redirecciones Si se establece en GETDNS_REDIRECTS_FOLLOW (el valor predeterminado), se devuelve el destino final del redireccionamiento. Si se establece en GETDNS_REDIRECTS_DO_NOT_FOLLOW, se devuelve el CNAME o DNAME y NO el destino final.

limite el número máximo de consultas DNS concurrentes pendientes (sin respuesta), si se supera la API pondrá en cola las consultas y las emitirá a medida que el número de consultas pendientes disminuya. Un valor de 0 indica que no hay límite.

namespaces El array de namespaces contiene una lista ordenada de namespaces que se consultarán. Importante: esta configuración de contexto se ignora para las funciones getdns_general y getdns_general_sync; se utiliza para las otras funciones. Los valores son GETDNS_CONTEXT_NAMESPACE_DNS, GETDNS_CONTEXT_NAMESPACE_LOCALNAMES, GETDNS_CONTEXT_NAMESPACE_NETBIOS, GETDNS_CONTEXT_NAMESPACE_MDNS, y GETDNS_CONTEXT_NAMESPACE_NIS. Cuando se realiza una búsqueda normal, la API realiza las búsquedas en el orden dado y se detiene cuando obtiene el primer resultado; un método diferente con el mismo resultado sería ejecutar las consultas en paralelo y devolver cuando se obtiene el primer resultado. Debido a que las búsquedas pueden realizarse a través de diferentes mecanismos debido a los diferentes namespaces, puede haber fugas de información similares a las que se ven con getaddrinfo(). El valor predeterminado lo determina el sistema operativo.

tipo_resolucion puede establecerse en GETDNS_CONTEXT_RECURSIVE (el valor predeterminado) o GETDNS_CONTEXT_STUB (requiere que los reenviadores sean especificados por el llamador).

skew_segundos el número de segundos de desfase permitido en cualquier dirección al comprobar los campos de expiración e inicio de un RRSIG.

sufijos Una lista de bindatas que son cadenas que se añadirán basándose en getdns_context_set_append_name. Los valores aquí siguen las reglas de la sección 2.1 de RFC 4343 para permitir octetos no ASCII y caracteres especiales en las etiquetas.

tiempo_espera el número de milisegundos que la API esperará una respuesta, después de lo cual se invocará la función de devolución de llamada (o la función síncrona devolverá) con un error de tiempo de espera.

anclas_confianza lista de bindatas que son las anclas de confianza DNSSEC expresadas como RDATA de los registros de recursos DNSKEY, las predeterminadas son proporcionadas por la raíz de la IANA.

cuando_apendear El valor es

  • GETDNS_APPEND_NAME_ALWAYS,
  • GETDNS_APPEND_NAME_ONLY_TO_SINGLE_LABEL_AFTER_FAILURE,
  • GETDNS_APPEND_NAME_ONLY_TO_MULTIPLE_LABEL_NAME_AFTER_FAILURE, o
  • GETDNS_APPEND_NAME_NEVER.

VALORES DE RETORNO

Tras una ejecución exitosa, las funciones devuelven GETDNS_RETURN_GOOD , de lo contrario, se devuelven los siguientes valores de error:

GETDNS_RETURN_BAD_CONTEXT si el puntero de contexto es inválido

GETDNS_RETURN_CONTEXT_UPDATE_FAIL si hubo un problema al actualizar el contexto
