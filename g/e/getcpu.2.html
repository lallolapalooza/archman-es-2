getcpu(2) Manual de llamadas al sistema getcpu(2)

NOMBRE

getcpu - determinar la CPU y el nodo NUMA en los que se está ejecutando el hilo que llama

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#define _GNU_SOURCE             /* Ver feature_test_macros(7) */
#include <sched.h>
int getcpu(unsigned int *_Nullable cpu, unsigned int *_Nullable node);

DESCRIPCIÓN

La llamada al sistema getcpu() identifica el procesador y el nodo en los que se está ejecutando actualmente el hilo o proceso que llama, y los escribe en los enteros a los que apuntan los argumentos cpu y node. El procesador es un entero pequeño único que identifica una CPU. El nodo es un identificador pequeño único que identifica un nodo NUMA. Cuando cpu o node es NULL, no se escribe nada en el puntero respectivo.

La información colocada en cpu solo está garantizada que sea actual en el momento de la llamada: a menos que la afinidad de la CPU se haya fijado usando sched_setaffinity(2), el kernel puede cambiar la CPU en cualquier momento. (Normalmente esto no ocurre porque el planificador intenta minimizar los movimientos entre CPUs para mantener las cachés activas, pero es posible). El llamador debe tener en cuenta la posibilidad de que la información devuelta en cpu y node ya no esté actualizada cuando la llamada regrese.

VALOR DE RETORNO

En caso de éxito, se devuelve 0. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EFAULT
Los argumentos apuntan fuera del espacio de direcciones del proceso llamante.

ESTÁNDARES

Linux.

HISTORIA

Linux 2.6.19 (x86-64 e i386), glibc 2.29.

DIFERENCIAS BIBLIOTECA C / NÚCLEO

La llamada al sistema del núcleo tiene un tercer argumento:


int getcpu(unsigned int *cpu, unsigned int *node,
           struct getcpu_cache *tcache);

El argumento tcache no se usa desde Linux 2.6.24, y (al invocar directamente la llamada al sistema) debe especificarse como NULL, a menos que se requiera portabilidad a Linux 2.6.23 o anterior.

En Linux 2.6.23 y anteriores, si el argumento tcache no era NULL, especificaba un puntero a un búfer asignado por el llamador en almacenamiento local del hilo que se utilizaba para proporcionar un mecanismo de caché para getcpu(). El uso de la caché podía acelerar las llamadas a getcpu(), a costa de que existía una pequeña posibilidad de que la información devuelta estuviera desactualizada. Se consideró que el mecanismo de caché causaba problemas al migrar hilos entre CPUs, por lo que el argumento ahora se ignora.

NOTAS

Linux hace todo lo posible para que esta llamada sea lo más rápida posible. (En algunas arquitecturas, esto se hace a través de una implementación en el vdso(7)). La intención de getcpu() es permitir a los programas realizar optimizaciones con datos por CPU o para optimización NUMA.

VER TAMBIÉN

mbind(2), sched_setaffinity(2), set_mempolicy(2), sched_getcpu(3), cpuset(7), vdso(7)
