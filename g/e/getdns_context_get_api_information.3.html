DESCRIPCIÓ

N

Las llamadas a las funciones de getdns requieren un contexto DNS, que es un grupo de ajustes de la API que afectan a la forma en que se realizan las llamadas DNS. Para la mayoría de las aplicaciones, un contexto predeterminado es

suficiente.

Para crear un nuevo contexto DNS, utilice la

función:

getdns_return_t getdns_context_create (getdns_context_t *context, bool
set_from_os)

La llamada a getdns_context_create devuelve inmediatamente un contexto que puede utilizarse con otras llamadas a la API; ese contexto contiene los valores predeterminados de la API. La mayoría de las aplicaciones querrán que set_from_os esté establecido en

true.

Para limpiar el contexto, incluida la limpieza de todas las transacciones pendientes que se llamaron utilizando este contexto, utilice la

función:

void getdns_context_destroy (getdns_context_t
context)

Cuando getdns_context_destroy() devuelve, la aplicación sabe que todas las transacciones pendientes asociadas con este contexto habrán sido llamadas; las devoluciones de llamada que no se habían llamado antes de que se llamara a getdns_context_destroy() se llamarán con un callback_type de GETDNS_CALLBACK_CANCEL. getdns_context_destroy() devuelve después de que se haya realizado toda la limpieza necesaria y se hayan hecho las devoluciones de

llamada.

Si está utilizando getdns de forma multihilo, entonces por supuesto está utilizando la biblioteca OpenSSL subyacente de forma multihilo y la versión de esa biblioteca en uso podría tener requisitos sobre este tema. Es posible que necesite proporcionar una o dos funciones para permitirle funcionar correctamente. Por ejemplo, antes de llamar a getdns_context_create() puede necesitar utilizar las funciones de OpenSSL CRYPTO_set_id_callback y CRYPTO_set_locking_callback para configurar la operación asíncrona (la aplicación llama a estas funciones una vez para la inicialización). Openssl 1.0.0 o posterior utiliza la función CRYPTO_THREADID_set_callback

.

context Se utiliza para devolver el puntero a una estructura opaca. El llamador pasa la dirección de un puntero (decl: getdns_context *context; pasado como &context) que se rellenará como resultado de la devolución de la función. El resultado es un contexto recién asignado e inicializado (si no hay errores). En la función getdns_destroy_context este es el contexto cuya memoria asociada se

liberará.

set_from_os Si set_from_os es 0, entonces el llamador debe proporcionar servidores de nombres de reenvío si se ejecuta en modo stub. Si set_from_os es 1, entonces se utilizan los archivos del sistema para inicializar el contexto. Se utiliza /etc/resolv.conf para rellenar los reenviadores cuando se ejecuta como resolutor stub (solo se reconocen las líneas "nameserver"). Si set_from_os es 1, las entradas de /etc/hosts se prefieren antes de recurrir a una consulta DNS. Los errores en los archivos del sistema no impedirán que se construya el

contexto.

userarg En el caso de uso extendido, este argumento se pasa sin cambios a cada una de las funciones de gestión de memoria cada vez que se

llaman.

malloc La función que se utilizará para crear diccionarios de respuesta (y los miembros dentro de los diccionarios de respuesta). Por defecto se utiliza el malloc del

sistema.

realloc La función que se utilizará para crear diccionarios de respuesta (y los miembros dentro de los diccionarios de respuesta). Por defecto se utiliza el realloc del

sistema.

free La función que se utilizará para liberar el almacenamiento de los diccionarios de respuesta (y

los miembros dentro de los diccionarios de respues
ta). Por defecto se utiliza el free del sistema.

DESCRIPCIÓN

(LARGA)

Muchas llamadas en la API DNS requieren un contexto DNS. Un contexto DNS contiene la información que la API necesita para procesar las llamadas DNS, como las ubicaciones de los servidores DNS ascendentes, los anclajes de confianza de DNSSEC, y así sucesivamente. La estructura interna del contexto DNS es opaca, y podría ser diferente en cada SO. Cuando se pasa un contexto a cualquier función, debe ser un contexto asignado; el contexto no debe ser

NULL.

Una aplicación típica que utiliza esta API no necesita saber nada sobre los contextos. Básicamente, la aplicación crea un contexto predeterminado, lo utiliza en las funciones que requieren un contexto y luego lo desasigna cuando ha terminado. La manipulación de contextos está disponible para programas más conscientes de DNS, pero es poco probable que interese a las aplicaciones que solo quieren los resultados de las búsquedas de registros A, AAAA, SRV y

PTR.

Se espera que los contextos en las implementaciones de la API no sean necesariamente seguros para hilos, pero no serán hostiles a los hilos. Un contexto no debe ser utilizado por múltiples hilos: cree un nuevo contexto para usarlo en un hilo diferente. Está bien que una aplicación tenga muchos contextos, y algunas aplicaciones intensivas en DNS ciertamente querrán tener muchos incluso si la aplicación usa un solo

hilo.

Cuando el contexto se utiliza en la API por primera vez y set_from_os es 1, la API comienza a reemplazar algunos de los valores con valores del SO, como los que se encontrarían en res_query(3), /etc/resolv.conf, y así sucesiva

mente, y luego procede con la nueva función. Algunos usuarios avanzados no querrán que la API cambie los valores a los valores predeterminados del SO; si set_from_os es 0, la API no hará ninguna actualización de los valores ini
ciales basada en cambios en el SO. Por ejemplo, esto podría ser útil si la API actúa como un resolutor stub que utiliza un resolutor recursivo ascendente específico elegido por la aplicación, no el que podría provenir de DHCP.
