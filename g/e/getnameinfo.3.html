DESCRIPCIÓ

N

La función getnameinfo() es el inverso de getaddrinfo(3): convierte una dirección de socket en un host y servicio correspondientes, de manera independiente del protocolo. Combina la funcionalidad de gethostbyaddr(3) y getservbyport(3), pero a diferencia de esas funciones, getnameinfo() es reentrante y permite a los programas eliminar las dependencias de IPv4 frente a

IPv6.

El argumento addr es un puntero a una estructura genérica de dirección de socket (de tipo sockaddr_in o sockaddr_in6) de tamaño addrlen que contiene la dirección IP y el número de puerto de entrada. Los argumentos host y serv son punteros a buffers asignados por el llamante (de tamaño hostlen y servlen respectivamente) en los cuales getnameinfo() coloca cadenas terminadas con nulo que contienen los nombres de host y servicio respectivamente

.

El llamante puede especificar que no se requiere un nombre de host (o un nombre de servicio) proporcionando un argumento host (o serv) NULL o un argumento hostlen (o servlen) cero. Sin embargo, se debe solicitar al menos uno de los dos: nombre de host o nombre de

servicio.

El argumento flags modifica el comportamiento de getnameinfo() de la siguiente

manera:
NI_NAMERE
QD
Si se establece, se devuelve un error si no se puede determinar el nombre de
host.
NI_DGR
AM
Si se establece, el servicio se basa en datagramas (UDP) en lugar de en flujo (TCP). Esto es necesario para los pocos puertos (512–514) que tienen servicios diferentes para UDP y
TCP.
NI_NOFQ
DN
Si se establece, devuelve solo la parte del nombre de host del nombre de dominio completamente calificado para hosts
locales.
NI_NUMERICHO
ST
Si se establece, se devuelve la forma numérica del nombre de host. (Cuando no está establecido, esto ocurrirá igualmente en caso de que no se pueda determinar el nombre del
nodo.)
NI_NUMERICSE
RV
Si se establece, se devuelve la forma numérica de la dirección d
e servicio. (Cuando no está establecido, esto ocurrirá igualment
e en caso de que no se pueda determinar el nombre del servicio.)

Extensiones a getnameinfo() para Nombres de Dominio Internacionalizado

s

A partir de glibc 2.3.4, getnameinfo() ha sido extendido para permitir selectivamente que los nombres de host se conviertan de manera transparente desde y hacia el formato de Nombre de Dominio Internacionalizado (IDN) (ver RFC 3490, Internationalizing Domain Names in Applications (IDNA)). Se definen tres nuevas

banderas:
NI_I
DN
Si se usa esta bandera, el nombre encontrado en el proceso de búsqueda se convierte del formato IDN a la codificación del locale si es necesario. Los nombres que son solo ASCII no se ven afectados por la conversión, lo que hace que esta bandera sea utilizable en programas y entornos
existentes.
NI_IDN_ALLOW_UNASSIG
NED
NI_IDN_USE_STD3_ASCII_RU
LES
Establecer estas banderas habilitará las banderas IDNA
_ALLOW_UNASSIGNED (permitir puntos de código Unicode
no asignados) y IDNA_USE_STD3_ASCII_RULES (verificar l
a salida para asegurarse de que es un nombre de host
conforme a STD3) respectivamente en el manejo de IDNA.

EJEMPLO

S

El siguiente código intenta obtener el nombre de host numérico y el nombre del servicio para una dirección de socket dada. Nótese que no hay ninguna referencia fija a una familia de direcciones en

particular. 


struct sockaddr *addr;     /* entrada */
socklen_t addrlen;         /* entrada */
char hbuf[NI_MAXHOST], sbuf[NI_MAXSERV];
if (getnameinfo(addr, addrlen, hbuf, sizeof(hbuf), sbuf,
            sizeof(sbuf), NI_NUMERICHOST | NI_NUMERICSERV) == 0)
    printf("host=%s, serv=%s\n", hbuf, sbuf)
;

La siguiente versión comprueba si la dirección de socket tiene un mapeo de dirección

inverso. 


struct sockaddr *addr;     /* entrada */
socklen_t addrlen;         /* entrada */
char hbuf[NI_MAXHOST];
if (getnameinfo(addr, addrlen, hbuf, sizeof(hbuf),
            NULL, 0, NI_NAMEREQD))
    printf("no se pudo resolver el nombre de host");
else
    printf("host=%s\n", hbuf)
;
