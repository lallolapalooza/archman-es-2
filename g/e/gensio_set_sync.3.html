gensio_set_sync(3)

Paquete: gensio

Licencias: GPL

gensio_set_sync(3) Manual de funciones de biblioteca gensio_set_sync(3)

NOMBRE

gensio_set_sync, gensio_clear_sync, gensio_read_s, gensio_write_s - Operaciones de E/S síncronas en un gensio

SINOPSIS

#include <gensio/gensio.h>

int gensio_set_sync(struct gensio *io);
int gensio_clear_sync(struct gensio *io);
int gensio_read_s(struct gensio *io, gensiods *count,

void *data, gensiods datalen,
struct gensio_time *timeout);
int gensio_read_s_intr(struct gensio *io, gensiods *count,

void *data, gensiods datalen,
struct gensio_time *timeout);
int gensio_write_s(struct gensio *io, gensiods *count,

const void *data, gensiods datalen,
struct gensio_time *timeout);
int gensio_write_s_intr(struct gensio *io, gensiods *count,

const void *data, gensiods datalen,
struct gensio_time *timeout);

DESCRIPCIÓN

La operación normal de gensio se basa en devoluciones de llamada asíncronas. Esto sirve bastante bien a la mayoría de los programas, especialmente si están escuchando varias conexiones al mismo tiempo. No querrías escribir un compilador de esta manera, pero si estás escribiendo algo que se rige por eventos externos, este tipo de programación basada en eventos funciona bien. Si lo piensas, si usas algo como poll, select, etc., casi siempre terminas con algo como:

poll(fds...)
if (fd1 read está establecido)
call fd1_read_handler()
if (fd1 write está establecido)
call fd1_write_handler()
if (fd2 read está establecido)
...

El manejo de gensio hace todo esto por ti. Simplemente registra un manejador con el gensio para recibir las llamadas de lectura y escritura. Es más eficiente, más limpio y terminas con menos código.

Pero ocasionalmente necesitas hacer algo síncrono con la ejecución del programa. Por ejemplo, en gtlsshd, si la verificación inicial del certificado y la contraseña falla, utiliza PAM para manejar la lectura de la contraseña del gensio remoto. Esto requiere E/S síncrona y utiliza esta capacidad.

gensio_set_sync configura el gensio para E/S síncrona. Si haces esto, la devolución de llamada de eventos que está actualmente registrada ya no recibirá devoluciones de llamada de lectura y escritura. Sí recibirá otras devoluciones de llamada. Debes llamar a esto antes de realizar cualquiera de las operaciones de lectura y escritura síncronas. Esta función se bloqueará (mientras maneja eventos normales de gensio) hasta que no haya devoluciones de llamada activas.

gensio_clear_sync devuelve el gensio a la E/S asíncrona. La devolución de llamada se restaurará a la que se estableció cuando se llamó a gensio_set_sync().

gensio_read_s espera datos del gensio, hasta datalen bytes. count (si no es NULL) se actualizará al número real de bytes leídos. Esperará cualquier lectura y devolverá lo que sea que se haya leído, incluso si es menos que datalen. Esta función espera la cantidad de tiempo en timeout. timeout se actualiza a la cantidad de tiempo restante para esperar. Si timeout es NULL, espera para siempre.

gensio_write_s escribe datos en el gensio. count (si no es NULL) se actualizará al número real de bytes escritos. Esta función esperará hasta que ocurra el tiempo de espera o se escriban todos los datos. Esta función espera la cantidad de tiempo en timeout. timeout se actualiza a la cantidad de tiempo restante para esperar. Si timeout es NULL, espera para siempre.

gensio_read_s_intr y gensio_write_s_intr son como gensio_read_s y gensio_write_s, pero devuelven inmediatamente si ocurre una interrupción de señal. En sistemas sin señales, estas son las mismas que gensio_read_s y gensio_write_s.

VALORES DE RETORNO

Se devuelve cero en caso de éxito, o un error de gensio en caso de fallo.

VER TAMBIÉN
