VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de get:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Básicas de POSIX.1-2017, Sección 8.2, Variables de internacionalización para la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de configuración regional).
LC_ALL
Si se establece en una cadena de valor no vacía, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la configuración regional para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en argumentos y archivos de entrada).
LC_MESSAGES

Determina la configuración regional que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en el error estándar, y los mensajes informativos escritos en la salida estándar (o en el error estándar, si se utiliza la opción -p).
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.
TZ
Determina la zona horaria en la que se evalúan las horas y fechas escritas en el archivo SCCS. Si la variable TZ no está establecida o es NULL, se utiliza una zona horaria predeterminada del sistema no especificada.

EVENTOS ASÍNCRONOS

Predeterminado.

STDOUT

Por cada archivo procesado, get escribirá en la salida estándar el SID que se está accediendo y el número de líneas recuperadas del archivo SCCS, en el siguiente formato:

"%s\n%d lines\n", <SID>, <número de líneas>

Si se utiliza la opción -e, el SID del delta que se va a crear aparecerá después del SID al que se accedió y antes del número de líneas generadas, en la configuración regional POSIX:

"%s\nnew delta %s\n%d lines\n", <SID accedido>,
    <SID a crear>, <número de líneas>

Si hay más de un archivo con nombre o si se nombra un directorio o la entrada estándar, cada ruta se escribirá antes de cada una de las líneas mostradas en uno de los formatos anteriores:

"\n%s:\n", <ruta>

Si se utiliza la opción -L, se escribirá un resumen de deltas siguiendo el formato especificado a continuación para los archivos l.

Si se utiliza la opción -i, los deltas incluidos se listar_n después de la notación, en la configuración regional POSIX:

"Included:\n"

Si se utiliza la opción -x, los deltas excluidos se listarán después de la notación, en la configuración regional POSIX:

"Excluded:\n"

Si se especifican las opciones -p o -L, la salida estándar consistirá en el texto recuperado del archivo SCCS.

STDERR

El error estándar se utilizará solo para mensajes de diagnóstico, excepto si se especifican las opciones -p o -L, que incluirán todos los mensajes informativos normalmente enviados a la salida estándar.

ARCHIVOS DE SALIDA

Varios archivos auxiliares pueden ser creados por get. Estos archivos se conocen genéricamente como el archivo g, archivo l, archivo p y archivo z. La letra antes del <guión> se llama el etiquetador. Un nombre de archivo auxiliar se formará a partir del nombre de archivo SCCS: la aplicación garantizará que el último componente de todos los nombres de archivo SCCS tenga el formato s.nombre-módulo; los archivos auxiliares se nombrarán reemplazando la s inicial por el etiquetador. El archivo g será una excepción a este esquema: el archivo g se nombra eliminando el prefijo s.. Por ejemplo, para s.xyz.c, los nombres de archivo auxiliares serían xyz.c, l.xyz.c, p.xyz.c y z.xyz.c, respectivamente.

El archivo g, que contiene el texto generado, se creará en el directorio actual (a menos que se utilice la opción -p). Se creará un archivo g en todos los casos, independientemente de si se generó alguna línea de texto por get. Será propiedad del usuario real. Si se utiliza o se implica la opción -k, el archivo g solo será escribible por el propietario (solo lectura para los demás); de lo contrario, será de solo lectura. Solo el usuario real necesita tener permisos de escritura en el directorio actual.

El archivo l contendrá una tabla que mostrará qué deltas se aplicaron al generar el texto recuperado. El archivo l se creará en el directorio actual si se utiliza la opción -l; será de solo lectura y será propiedad del usuario real. Solo el usuario real necesita tener permisos de escritura en el directorio actual.

Las líneas del archivo l tendrán el siguiente formato:

"%c%c%c %s\t%s %s\n", <código1>, <código2>, <código3>,
    <SID>, <fecha-hora>, <inicio de sesión>

donde las entradas son:

<código1>
Un <espacio> si se aplicó el delta; '*' de lo contrario.
<código2>
Un <espacio> si se aplicó el delta o si no se aplicó y se ignoró; '*' si el delta no se aplicó y no se ignoró.
<código3>
Un carácter que indica una razón especial por la que el delta se aplicó o no se aplicó:
I
Incluido.
X
Excluido.
C
Cortado (por una opción -c).
<fecha-hora>
Fecha y hora (utilizando el formato de la especificación de conversión %y/%m/%d %T del comando date) de creación.
<inicio de sesión>
Nombre de inicio de sesión de la persona que creó el delta.

Los comentarios y los datos de MR seguirán en líneas subsiguientes, con tabulación de un <tab>. Una línea en blanco terminará cada entrada.

El archivo p se utilizará para pasar información resultante de un get con la opción -e a delta. Su contenido también se utilizará para evitar una ejecución posterior de get con la opción -e para el mismo SID hasta que se ejecute delta o se establezca la bandera de edición conjunta, j, en el archivo SCCS. El archivo p se creará en el directorio que contiene el archivo SCCS y la aplicación garantizará que el usuario efectivo tenga permiso de escritura en ese directorio. Solo será escribible por el propietario y será propiedad del usuario efectivo. Cada línea en el archivo p tendrá el siguiente formato:

"%s %s %s %s%s%s\n", <SID del archivo g>,
    <SID del nuevo delta>, <nombre de inicio de sesión del usuario real>,
    <fecha-hora>, <valor i>, <valor x>

donde <valor i> utiliza el formato "" si no se especificó ninguna opción -i, y utilizará el formato:

" -i%s", <argumento de opción -i>

si se especificó una opción -i y <valor x> utiliza el formato "" si no se especificó ninguna opción -x, y utilizará el formato:

" -x%s", <argumento de opción -x>

si se especificó una opción -x. Puede haber un número arbitrario de líneas en el archivo p en cualquier momento; ninguna línea tendrá el mismo SID de nuevo delta.

El archivo z servirá como mecanismo de bloqueo contra actualizaciones simultáneas. Su contenido será el ID de proceso binario del comando (es decir, get) que lo creó. El archivo z se creará en el directorio que contiene el archivo SCCS durante la ejecución de get. Las mismas restricciones de protección que para el archivo p se aplicarán al archivo z. El archivo z se creará de solo lectura.
