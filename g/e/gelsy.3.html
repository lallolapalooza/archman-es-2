subrutina cgelsy (integer m, integer n, integer nrhs, complex, dimension( lda, * ) a, integer lda, complex, dimension( ldb, * ) b, integer ldb, integer, dimension( * ) jpvt, real rcond, integer rank, complex, dimension( * ) work, integer lwork, real, dimension( * ) rwork, integer info)

CGELSY resuelve sistemas sobredeterminados o subdeterminados para matrices GE

Propósito:

!>
!> CGELSY calcula la solución de norma mínima para un problema complejo
!> de mínimos cuadrados lineales:
!>     minimizar || A * X - B ||
!> usando una factorización ortogonal completa de A. A es una matriz
!> M-por-N que puede ser deficiente en rango.
!>
!> Varios vectores de segundo miembro b y vectores solución x pueden
!> manejarse en una sola llamada; se almacenan como las columnas de la
!> matriz de segundo miembro B de M-por-NRHS y la matriz de solución X
!> de N-por-NRHS.
!>
!> La rutina primero calcula una factorización QR con pivoteo de
!> columnas:
!>     A * P = Q * [ R11 R12 ]
!>                 [  0  R22 ]
!> con R11 definido como la mayor submatriz inicial cuyo número de
!> condición estimado es menor que 1/RCOND. El orden de R11, RANK, es
!> el rango efectivo de A.
!>
!> Entonces, R22 se considera despreciable, y R12 se anula mediante
!> transformaciones unitarias por la derecha, llegando a la
!> factorización ortogonal completa:
!>    A * P = Q * [ T11 0 ] * Z
!>                [  0  0 ]
!> La solución de norma mínima es entonces
!>    X = P * Z**H [ inv(T11)*Q1**H*B ]
!>                 [        0         ]
!> donde Q1 consiste en las primeras RANK columnas de Q.
!>
!> Esta rutina es básicamente idéntica a la original xGELSX excepto
!> por tres diferencias:
!>   o La permutación de la matriz B (el segundo miembro) es más rápida
!>     y más simple.
!>   o La llamada a la subrutina xGEQPF ha sido sustituida por la
!>     llamada a la subrutina xGEQP3. Esta subrutina es una versión
!>     Blas-3 de la factorización QR con pivoteo de columnas.
!>   o La matriz B (el segundo miembro) se actualiza con Blas-3.
!>

Parámetros

M 
!>          M es INTEGER
!>          El número de filas de la matriz A. M >= 0.
!>

N

!>          N es INTEGER
!>          El número de columnas de la matriz A. N >= 0.
!>

NRHS

!>          NRHS es INTEGER
!>          El número de segundos miembros, es decir, el número de
!>          columnas de las matrices B y X. NRHS >= 0.
!>

A

!>          A es un arreglo COMPLEX, dimensión (LDA,N)
!>          En la entrada, la matriz A de M-por-N.
!>          En la salida, A ha sido sobrescrita con los detalles de su
!>          factorización ortogonal completa.
!>

LDA

!>          LDA es INTEGER
!>          La dimensión principal del arreglo A. LDA >= max(1,M).
!>

B

!>          B es un arreglo COMPLEX, dimensión (LDB,NRHS)
!>          En la entrada, la matriz de segundo miembro B de M-por-NRHS.
!>          En la salida, la matriz de solución X de N-por-NRHS.
!>          Si M = 0 o N = 0, B no se referencia.
!>

LDB

!>          LDB es INTEGER
!>          La dimensión principal del arreglo B. LDB >= max(1,M,N).
!>

JPVT

!>          JPVT es un arreglo INTEGER, dimensión (N)
!>          En la entrada, si JPVT(i) .ne. 0, la i-ésima columna de A
!>          se permuta al frente de AP, de lo contrario la columna i es
!>          una columna libre.
!>          En la salida, si JPVT(i) = k, entonces la i-ésima columna de
!>          A*P era la k-ésima columna de A.
!>

RCOND

!>          RCOND es REAL
!>          RCOND se usa para determinar el rango efectivo de A, que
!>          se define como el orden de la mayor submatriz triangular
!>          inicial R11 en la factorización QR con pivoteo de A, cuyo
!>          número de condición estimado es < 1/RCOND.
!>

RANK

!>          RANK es INTEGER
!>          El rango efectivo de A, es decir, el orden de la submatriz
!>          R11. Este es el mismo que el orden de la submatriz T11 en
!>          la factorización ortogonal completa de A.
!>          Si NRHS = 0, RANK = 0 en la salida.
!>

WORK

!>          WORK es un arreglo COMPLEX, dimensión (MAX(1,LWORK))
!>          En la salida, si INFO = 0, WORK(1) devuelve el LWORK óptimo.
!>

LWORK

!>          LWORK es INTEGER
!>          La dimensión del arreglo WORK.
!>          La estrategia sin bloqueo requiere que:
!>            LWORK >= MN + MAX( 2*MN, N+1, MN+NRHS )
!>          donde MN = min(M,N).
!>          El algoritmo con bloqueo requiere que:
!>            LWORK >= MN + MAX( 2*MN, NB*(N+1), MN+MN*NB, MN+NB*NRHS )
!>          donde NB es una cota superior para el tamaño de bloque
!>          devuelto por ILAENV para las rutinas CGEQP3, CTZRZF,
!>          CTZRQF, CUNMQR y CUNMRZ.
!>
!>          Si LWORK = -1, se asume una consulta de espacio de trabajo;
!>          la rutina solo calcula el tamaño óptimo del arreglo WORK,
!>          devuelve este valor como la primera entrada del arreglo WORK
!>          y XERBLA no emite ningún mensaje de error relacionado con
!>          LWORK.
!>

RWORK

!>          RWORK es un arreglo REAL, dimensión (2*N)
!>

INFO

!>          INFO es INTEGER
!>          = 0: salida exitosa
!>          < 0: si INFO = -i, el i-ésimo argumento tenía un valor ilegal
!>

!>          En la entrada, la matriz del lado derecho B de tamaño M por NRHS.

!>          LDB es INTEGER
!>          La dimensión principal del array B. LDB >= max(1,M,N).

!>          Si NRHS = 0, RANK = 0 en la salida.

!>          WORK es un array COMPLEX*16, dimensión (MAX(1,LWORK))
!>          En la salida, si INFO = 0, WORK(1) devuelve el LWORK óptimo.

LWORK

!>          LWORK es INTEGER
!>          La dimensión del array WORK.
!>          La estrategia sin bloqueo requiere que:
!>            LWORK >= MN + MAX( 2*MN, N+1, MN+NRHS )
!>          donde MN = min(M,N).
!>          El algoritmo con bloqueo requiere que:
!>            LWORK >= MN + MAX( 2*MN, NB*(N+1), MN+MN*NB, MN+NB*NRHS )
!>          donde NB es una cota superior para el tamaño de bloque devuelto
!>          por ILAENV para las rutinas ZGEQP3, ZTZRZF, CTZRQF, ZUNMQR,
!>          y ZUNMRZ.
!>
!>          Si LWORK = -1, se asume una consulta de espacio de trabajo; la rutina
!>          solo calcula el tamaño óptimo del array WORK, devuelve
!>          este valor como la primera entrada del array WORK, y no se emite
!>          ningún mensaje de error relacionado con LWORK por parte de XERBLA.
