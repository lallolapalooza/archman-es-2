void clnt_pcreateerror(const char *s);



  

  
Imprime un mensaje en el error estándar indicando por qué no se pudo crear un manejador RPC de cliente. El mensaje se antepone con la cadena s y dos puntos. Se utiliza cuando una llamada a clnt_create(), clntraw_create(), clnttcp_create() o clntudp_create() falla.




void clnt_perrno(enum clnt_stat stat);



  

  
Imprime un mensaje en el error estándar correspondiente a la condición indicada por stat. Se utiliza después de callrpc().




clnt_perror(CLIENT *clnt, const char *s);



  

  
Imprime un mensaje en el error estándar indicando por qué falló una llamada RPC; clnt es el manejador utilizado para realizar la llamada. El mensaje se antepone con la cadena s y dos puntos. Se utiliza después de clnt_call().




char *clnt_spcreateerror(const char *s);



  

  
Similar a clnt_pcreateerror(), excepto que devuelve una cadena en lugar de imprimir en el error estándar.

  

  
Errores: devuelve un puntero a datos estáticos que se sobrescriben en cada llamada.




char *clnt_sperrno(enum clnt_stat stat);



  

  
Toma los mismos argumentos que clnt_perrno(), pero en lugar de enviar un mensaje al error estándar indicando por qué falló una llamada RPC, devuelve un puntero a una cadena que contiene el mensaje. La cadena termina con un salto de línea.

  

  
clnt_sperrno() se utiliza en lugar de clnt_perrno() si el programa no tiene un error estándar (como probablemente no lo tiene un programa que se ejecuta como servidor), o si el programador no desea que el mensaje se imprima con printf(3), o si se va a utilizar un formato de mensaje diferente al soportado por clnt_perrno(). Nota: a diferencia de clnt_sperror() y clnt_spcreateerror(), clnt_sperrno() devuelve un puntero a datos estáticos, pero el resultado no se sobrescribirá en cada llamada.




char *clnt_sperror(CLIENT *rpch, const char *s);



  

  
Similar a clnt_perror(), excepto que (como clnt_sperrno()) devuelve una cadena en lugar de imprimir en el error estándar.

  

  
Errores: devuelve un puntero a datos estáticos que se sobrescriben en cada llamada.




CLIENT *clntraw_create(unsigned long prognum, unsigned long versnum);



  

  
Esta rutina crea un cliente RPC de juguete para el programa remoto prognum, versión versnum. El transporte utilizado para pasar mensajes al servicio es en realidad un búfer dentro del espacio de direcciones del proceso, por lo que el servidor RPC correspondiente debería residir en el mismo espacio de direcciones; véase svcraw_create(). Esto permite simular RPC y adquirir sobrecargas RPC, como los tiempos de ida y vuelta, sin ninguna intervención del kernel. Esta rutina devuelve NULL si falla.




CLIENT *clnttcp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                int *sockp, unsigned int sendsz, unsigned int recvsz);



  

  
Esta rutina crea un cliente RPC para el programa remoto prognum, versión versnum; el cliente utiliza TCP/IP como transporte. El programa remoto se encuentra en la dirección de Internet *addr. Si addr->sin_port es cero, se establece en el puerto real en el que está escuchando el programa remoto (se consulta el servicio portmap remoto para obtener esta información). El parámetro sockp es un socket; si es RPC_ANYSOCK, esta rutina abre uno nuevo y establece sockp. Dado que RPC basado en TCP utiliza E/S con búfer, el usuario puede especificar el tamaño de los búferes de envío y recepción con los parámetros sendsz y recvsz; valores de cero eligen valores predeterminados adecuados. Esta rutina devuelve NULL si falla.




CLIENT *clntudp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                struct timeval wait, int *sockp);



  

  
Esta rutina crea un cliente RPC para el programa remoto prognum, versión versnum; el cliente utiliza UDP/IP como transporte. El programa remoto se encuentra en la dirección de Internet addr. Si addr->sin_port es cero, se establece en el puerto real en el que está escuchando el programa remoto (se consulta el servicio portmap remoto para obtener esta información). El parámetro sockp es un socket; si es RPC_ANYSOCK, esta rutina abre uno nuevo y establece sockp. El transporte UDP reenvía el mensaje de llamada en intervalos de tiempo wait hasta que se recibe una respuesta o hasta que la llamada expira. El tiempo total para que la llamada expire se especifica en clnt_call().

  

  
Advertencia: dado que los mensajes RPC basados en UDP solo pueden contener hasta 8 Kbytes de datos codificados, este transporte no se puede utilizar para procedimientos que aceptan argumentos grandes o devuelven resultados enormes.




CLIENT *clntudp_bufcreate(struct sockaddr_in *addr,
            unsigned long prognum, unsigned long versnum,
            struct timeval wait, int *sockp,
            unsigned int sendsize, unsigned int recosize);



  

  
Esta rutina crea un cliente RPC para el programa remoto prognum, en versnum; el cliente utiliza UDP/IP como transporte. El programa remoto se encuentra en la dirección de Internet addr. Si addr->sin_port es cero, se establece en el puerto real en el que está escuchando el programa remoto (se consulta el servicio portmap remoto para obtener esta información). El parámetro sockp es un socket; si es RPC_ANYSOCK, esta rutina abre uno nuevo y establece sockp. El transporte UDP reenvía el mensaje de llamada en intervalos de tiempo wait hasta que se recibe una respuesta o hasta que la llamada expira. El tiempo total para que la llamada expire se especifica en clnt_call().

  

  
Esto permite al usuario especificar el tamaño máximo de paquete para enviar y recibir mensajes RPC basados en UDP.




void get_myaddress(struct sockaddr_in *addr);



  

  
Introduce la dirección IP de la máquina en *addr, sin consultar las rutinas de la biblioteca que manejan /etc/hosts. El número de puerto siempre se establece en htons(PMAPPORT).




struct pmaplist *pmap_getmaps(struct sockaddr_in *addr);



  

  
Una interfaz de usuario para el servicio portmap, que devuelve una lista de los mapeos actuales de programa RPC a puerto en el host ubicado en la dirección IP *addr. Esta rutina puede devolver NULL. El comando rpcinfo -p utiliza esta rutina.




unsigned short pmap_getport(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned int protocol);



  

  
Una interfaz de usuario para el servicio portmap, que devuelve el número de puerto en el que espera un servicio que soporta el número de programa prognum, versión versnum y habla el protocolo de transporte asociado con protocol. El valor de protocol es muy probablemente IPPROTO_UDP o IPPROTO_TCP. Un valor de retorno de cero significa que el mapeo no existe o que el sistema RPC no pudo contactar al servicio portmap remoto. En este último caso, la variable global rpc_createerr contiene el estado RPC.




enum clnt_stat pmap_rmtcall(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout, unsigned long *portp);



  

  
Una interfaz de usuario para el servicio portmap, que instruye a portmap en el host en la dirección IP *addr para que realice una llamada RPC en su nombre a un procedimiento en ese host. El parámetro *portp se modificará al número de puerto del programa si el procedimiento tiene éxito. Las definiciones de otros parámetros se discuten en callrpc() y clnt_call(). Este procedimiento debe usarse para un "ping" y nada más. Véase también clnt_broadcast().




bool_t pmap_set(unsigned long prognum, unsigned long versnum,
                int protocol, unsigned short port);



  

  
Una interfaz de usuario para el servicio portmap, que establece un mapeo entre la tripleta [prognum,versnum,protocol] y port en el servicio portmap de la máquina. El valor de protocol es muy probablemente IPPROTO_UDP o IPPROTO_TCP. Esta rutina devuelve uno si tiene éxito, cero en caso contrario. Realizado automáticamente por svc_register().




bool_t pmap_unset(unsigned long prognum, unsigned long versnum);



  

  
Una interfaz de usuario para el servicio portmap, que destruye todos los mapeos entre la tripleta [prognum,versnum,*] y puertos en el servicio portmap de la máquina. Esta rutina devuelve uno si tiene éxito, cero en caso contrario.




int registerrpc(unsigned long prognum, unsigned long versnum,
                unsigned long procnum, typeof(char *(char *)) *procname,
                xdrproc_t inproc, xdrproc_t outproc);



  

  
Registra el procedimiento procname con el paquete de servicios RPC. Si llega una solicitud para el programa prognum, versión versnum y procedimiento procnum, se llama a procname con un puntero a sus parámetros; procname debe devolver un puntero a sus resultados estáticos; inproc se utiliza para decodificar los parámetros mientras que outproc se utiliza para codificar los resultados. Esta rutina devuelve cero si el registro tuvo éxito, -1 en caso contrario.

  

  
Advertencia: los procedimientos remotos registrados de esta forma se acceden utilizando el tra de UDP/IP
