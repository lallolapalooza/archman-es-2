--validation-model nombre
Esta opción cambia el modelo de validación predeterminado. Los únicos valores posibles son "shell" (que es el predeterminado), "chain" que fuerza el uso del modelo de cadena y "steed" para un nuevo modelo simplificado. El modelo de cadena también se utiliza si una opción en el 'trustlist.txt' o un atributo de la solicitud de certificado lo requieren. Sin embargo, el modelo estándar (shell) siempre se intenta primero en ese caso.

Añade oid a la lista de extensiones de certificado ignoradas. El oid se espera en formato decimal punteado, como 2.5.29.3. Esta opción se puede usar varias veces. Las extensiones de certificado marcadas como críticas que coinciden con uno de los OID de la lista se tratan como si estuvieran realmente manejadas y, por lo tanto, el certificado no será rechazado debido a una extensión crítica desconocida. Usa esta opción con cuidado porque las extensiones suelen marcarse como críticas por una razón.

Entrada y Salida

 

--armor
-a
Crea salida codificada en PEM. El valor predeterminado es salida binaria.
--base64
Crea salida codificada en Base-64; es decir, PEM sin las líneas de encabezado.
--assume-armor
Asume que los datos de entrada están codificados en PEM. El valor predeterminado es la autodetección de la codificación, pero esto puede fallar.
--assume-base64
Asume que los datos de entrada están codificados en base-64 plano.
--assume-binary
Asume que los datos de entrada están codificados en binario.
--input-size-hint n
Esta opción se puede utilizar para indicar a GPGSM el tamaño de los datos de entrada en bytes. n debe ser un número positivo en base 10. Se utiliza para la línea ``PROGRESS'' de --status-fd para proporcionar un valor para ``total'' si no está disponible por otros medios.
--p12-charset nombre
gpgsm utiliza la codificación UTF-8 al codificar contraseñas para archivos PKCS#12. Esta opción se puede usar para forzar que la contraseña se codifique en la codificación especificada nombre. Esto es útil si la aplicación utilizada para importar la clave utiliza una codificación diferente y, por lo tanto, no podrá importar un archivo generado por gpgsm. Los valores comúnmente utilizados para nombre son Latin1 y CP850. Ten en cuenta que gpgsm importa automáticamente cualquier archivo con una contraseña codificada a las codificaciones más comunes.
--default-key user_id
Utiliza user_id como clave estándar para firmar. Esta clave se utiliza si ninguna otra clave se ha definido como clave de firma. Ten en cuenta que la primera opción --local-users también establece esta clave si aún no se ha establecido; sin embargo, --default-key siempre la anula.
--local-user user_id
-u user_id
Establece los usuarios a utilizar para firmar. El valor predeterminado es la primera clave secreta encontrada en la base de datos.
--recipient nombre
-r
Cifra para el ID de usuario nombre. Hay varias formas en que se puede dar un ID de usuario (ver: [how-to-specify-a-user-id]).
--output archivo
-o archivo
Escribe la salida en archivo. El valor predeterminado es escribirla en stdout.
--with-key-data
Muestra información adicional con los comandos --list-keys. Especialmente se imprime una línea etiquetada grp que te indica el keygrip de una clave. Esta cadena se utiliza, por ejemplo, como nombre de archivo de la clave secreta. Implica --with-colons.
--with-validation
Al listar claves, realiza una verificación de validación completa para cada clave e imprime el resultado. Esto suele ser una operación lenta porque requiere una búsqueda de CRL y otras operaciones.

Cuando se usa junto con --import, se realiza una validación del certificado a importar y solo se importa si supera la prueba. Ten en cuenta que esto no afecta a un certificado ya disponible en la BD. Por lo tanto, esta opción es útil para simplemente verificar un certificado.

--with-md5-fingerprint
Para listados de claves estándar, también imprime la huella dactilar MD5 del certificado.
--with-keygrip
Incluye el keygrip en los listados de claves estándar. Ten en cuenta que el keygrip siempre se lista en el modo --with-colons.
--with-secret
Incluye información sobre la presencia de una clave secreta en los listados de claves públicas realizados con --with-colons.
--no-pretty-dn
Por defecto, gpgsm imprime los nombres distinguidos (DN) como el Emisor o el Asunto en un formato más legible (por ejemplo, utilizando un orden bien definido de las partes). Sin embargo, este formato no se puede utilizar como cadenas de entrada. Esta opción vuelve a imprimir en el formato estándar RFC-2253 y, por lo tanto, evita la necesidad de usar --dump-cert o --with-colons para obtener el nombre "real".

Cómo cambiar la forma en que se crea el CMS

 

--include-certs n
Usando n de -2 se incluyen todos los certificados excepto el certificado raíz, -1 incluye todos los certificados, 0 no incluye ningún certificado, 1 incluye solo el certificado del firmante y todos los demás valores positivos incluyen hasta n certificados comenzando con el certificado del firmante. El valor predeterminado es -2.
--cipher-algo oid
Utiliza el algoritmo de cifrado con el identificador de objeto ASN.1 oid para el cifrado. Para mayor comodidad, las cadenas 3DES, AES y AES256 pueden usarse en lugar de sus OID. El valor predeterminado es AES (2.16.840.1.101.3.4.1.2).
--digest-algo nombre
Utiliza nombre como algoritmo de resumen de mensajes. Normalmente, este algoritmo se deduce del certificado de firma respectivo. Esta opción fuerza el uso del algoritmo dado y puede provocar graves problemas de interoperabilidad.

Hacer cosas que normalmente no se quieren hacer

 

--chuid uid
Cambia el usuario actual a uid, que puede ser un número o un nombre. Esto se puede usar desde la cuenta raíz para ejecutar gpgsm para otro usuario. Si uid no es el UID actual, se establece una ruta PATH estándar y se anula la variable de entorno GNUPGHOME. Para anular esto último, se puede usar la opción --homedir. Esta opción solo tiene efecto cuando se usa en la línea de comandos. Actualmente, esta opción no tiene ningún efecto en Windows.
--extra-digest-algo nombre
A veces las firmas están rotas porque anuncian un algoritmo de resumen diferente al realmente utilizado. gpgsm utiliza un modelo de procesamiento de datos de una pasada y, por lo tanto, necesita confiar en los algoritmos de resumen anunciados para calcular correctamente el hash de los datos. Como solución alternativa, esta opción se puede usar para indicar a gpgsm que también calcule el hash de los datos utilizando el algoritmo nombre; esto ralentiza un poco el procesamiento, pero permite la verificación de firmas rotas. Si gpgsm imprime un error como ``digest algo 8 has not been enabled'' (el algoritmo de resumen 8 no ha sido habilitado), es posible que desees probar esta opción, con 'SHA256' para nombre.
--compliance cadena
Establece el modo de cumplimiento. Los valores válidos se muestran al usar "help" para cadena.
--min-rsa-length n
Esta opción ajusta el modo de cumplimiento "de-vs" para requisitos de tamaño de clave más estrictos. Por ejemplo, un valor de 3000 convierte las claves rsa2048 y dsa2048 en claves no conformes con VS-NfD.
--require-compliance
Para verificar que los datos se han cifrado de acuerdo con las reglas del modo de cumplimiento actual, un usuario de gpgsm necesita evaluar las líneas de estado. Esto permite a las interfaces de usuario manejar la verificación de cumplimiento de una manera más flexible. Sin embargo, para uso en scripts, la evaluación requerida de la línea de estado requiere bastante esfuerzo; esta opción se puede usar en su lugar para asegurar que el proceso de gpgsm termine con un error si las reglas de cumplimiento no se cumplen. Ten en cuenta que esta opción actualmente solo tiene efecto en el modo "de-vs".
--assert-signer fpr_or_file
Esta opción verifica si al menos una firma válida en un archivo ha sido hecha con la clave especificada. La clave se especifica como una huella dactilar o un archivo que lista huellas dactilares. La huella dactilar debe proporcionarse o listarse en formato compacto (sin dos puntos ni espacios entre ellos). Por ahora, solo se permiten huellas dactilares SHA-1. Esta opción se puede dar varias veces y cada huella dactilar se verifica contra la clave de firma, así como contra la clave primaria correspondiente. Si fpr_or_file especifica un archivo, se ignoran las líneas vacías y todas las líneas que comienzan con un signo de almohadilla. Con esta
la opción gpgsm garantiza devolver un código de salida 0 si y solo si se encuentra una firma, esta es válida y la clave coincide con una de las huellas digitales dadas por esta opción.
--always-trust
Forzar el cifrado a los certificados especificados sin ninguna validación de la cadena de certificados. El único requisito es que el certificado sea capaz de cifrar. Tenga en cuenta que esta opción no es efectiva si --require-compliance se usa.
--ignore-cert-with-oid oid
Añadir oid a la lista de OID que se verificarán al leer certificados de tarjetas inteligentes. Se espera que el oid esté en forma decimal con puntos, como 2.5.29.3. Esta opción puede usarse más de una vez. Por ahora, los certificados con un uso de clave extendido que coincida con uno de esos OID se ignoran durante una operación --learn-card y no se importan. Esta opción puede ayudar a mantener la base de datos de claves local limpia de certificados innecesarios almacenados en tarjetas inteligentes.
--faked-system-time epoch
Esta opción solo es útil para pruebas; retrocede o avanza la hora del sistema a epoch que es el número de segundos transcurridos desde el año 1970. Alternativamente, epoch puede darse como una cadena de hora ISO completa (por ejemplo, "20070924T154812").
--with-ephemeral-keys
Incluir claves marcadas como efímeras en la salida de los listados de claves. Tenga en cuenta que se incluyen de todos modos si la especificación de la clave para un listado se da como huella digital o keygrip.
--compatibility-flags flags
Establece banderas de compatibilidad para solucionar problemas debidos a certificados o datos no conformes. Las flags se dan como una lista de nombres de banderas separados por comas y se combinan con una operación OR. La bandera especial "none" limpia la lista y permite empezar de nuevo con una lista vacía. Para obtener una lista de las banderas disponibles, se puede usar la única palabra "help".
--debug-level level
Seleccione el nivel de depuración para investigar problemas. level puede ser un valor numérico o una palabra clave:
none
Sin depuración en absoluto. Se puede usar un valor menor que 1 en lugar de la palabra clave.
basic
Algunos mensajes de depuración básicos. Se puede usar un valor entre 1 y 2 en lugar de la palabra clave.
advanced
Mensajes de depuración más detallados. Se puede usar un valor entre 3 y 5 en lugar de la palabra clave.
expert
Mensajes aún más detallados. Se puede usar un valor entre 6 y 8 en lugar de la palabra clave.
guru
Todos los mensajes de depuración que pueda obtener. Se puede usar un valor mayor que 8 en lugar de la palabra clave. La creación de archivos de trazado de hash solo se habilita si se usa la palabra clave.

Cómo se asignan estos mensajes a las banderas de depuración reales no está especificado y puede cambiar con versiones más nuevas de este programa. Sin embargo, están cuidadosamente seleccionados para ayudar mejor en la depuración.

--debug flags
Establece banderas de depuración. Todas las banderas se combinan con OR y flags pueden darse en sintaxis C (por ejemplo, 0x0042) o como una lista de nombres de banderas separados por comas. Para obtener una lista de todas las banderas admitidas, se puede usar la única palabra "help". Esta opción solo es útil para depuración y el comportamiento puede cambiar en cualquier momento sin previo aviso.

Tenga en cuenta que todas las banderas establecidas con esta opción pueden ser anuladas por --debug-level.

--debug-all
Igual que --debug=0xffffffff
--debug-allow-core-dump
Normalmente gpgsm intenta evitar volcados de memoria (core) mediante código bien escrito y deshabilitando los volcados de memoria por razones de seguridad. Sin embargo, los errores son bestias bastante resistentes y para aplastarlos a veces es útil tener un volcado de memoria. Esta opción habilita los volcados de memoria a menos que la cosa mala haya ocurrido antes del análisis de las opciones.
--debug-no-chain-validation
Esto no es realmente una opción de depuración, sino que solo es útil como tal. Permite que gpgsm omita todas las comprobaciones de validación de la cadena de certificados.
--debug-ignore-expiration
Esto no es realmente una opción de depuración, sino que solo es útil como tal. Permite que gpgsm ignore todas las fechas notAfter, esto es usado por las pruebas de regresión.
--passphrase-fd n
Leer la frase de contraseña del descriptor de archivo n. Solo se leerá la primera línea del descriptor de archivo n. Si usa 0 para n, la frase de contraseña se leerá de STDIN. Esto solo puede usarse si se proporciona una sola frase de contraseña.

Tenga en cuenta que esta frase de contraseña solo se usa si la opción --batch también se ha dado.

--pinentry-mode mode
Establece el modo de pinentry a mode. Los valores permitidos para mode son:
default
Usar el valor por defecto del agente, que es ask.
ask
Forzar el uso de Pinentry.
cancel
Emular el uso del botón de cancelar de Pinentry.
error
Devolver un error de Pinentry (``No Pinentry'').
loopback
Redirigir las consultas de Pinentry al llamador. Tenga en cuenta que, a diferencia de Pinentry, no se le vuelve a pedir al usuario si introduce una contraseña incorrecta.
--request-origin origin
Indicar a gpgsm que asuma que la operación se originó en última instancia en origin. Dependiendo del origen, se aplican ciertas restricciones y el Pinentry puede incluir una nota adicional sobre el origen. Los valores admitidos para origin son: local que es el valor por defecto, remote para indicar un origen remoto o browser para una operación solicitada por un navegador web.
--no-common-certs-import
Suprimir la importación de certificados comunes al crear el keybox.

Todas las opciones largas también pueden darse en el archivo de configuración eliminando los dos guiones iniciales.

CÓMO ESPECIFICAR UN ID DE USUARIO

Hay diferentes maneras de especificar un ID de usuario a GnuPG. Algunas de ellas solo son válidas para gpg otras son solo buenas para gpgsm. Aquí está la lista completa de maneras de especificar una clave:

Por ID de clave.
Este formato se deduce de la longitud de la cadena y su contenido o del 0x prefijo. El ID de clave de un certificado X.509 son los 64 bits bajos de su huella digital SHA-1. El uso de los ID de clave es solo un atajo; para todo el procesamiento automatizado se debe usar la huella digital.

Al usar gpg se puede añadir un signo de exclamación (!) para forzar el uso de la clave primaria o secundaria especificada y no intentar calcular qué clave primaria o secundaria usar.

Las últimas cuatro líneas del ejemplo dan el ID de clave en su forma larga, tal como se usa internamente por el protocolo OpenPGP. Puede ver el ID de clave largo usando la opción --with-colons.

234567C4
0F34E556E
01347A56A
0xAB123456
234AABBCC34567C4
0F323456784E56EAB
01AB3FED1347A5612
0x234AABBCC34567C4
Por huella digital.
Este formato se deduce de la longitud de la cadena y su contenido o del 0x prefijo. Tenga en cuenta que solo está disponible la huella digital de 20 bytes con gpgsm (es decir, el hash SHA-1 del certificado).

Al usar gpg se puede añadir un signo de exclamación (!) para forzar el uso de la clave primaria o secundaria especificada y no intentar calcular qué clave primaria o secundaria usar.

La mejor manera de especificar un ID de clave es usando la huella digital. Esto evita cualquier ambigüedad en caso de que haya ID de clave duplicados.

1234343434343434C434343434343434
123434343434343C3434343434343734349A3434
0E12343434343434343434EAB3484343434343434
0xE12343434343434343434EAB3484343434343434

gpgsm también acepta dos puntos entre cada par de dígitos hexadecimales porque este es el estándar de facto sobre cómo se presentan las huellas digitales X.509. gpg también permite el uso de la huella digital SHA-1 separada por espacios tal como la imprimen los comandos de listado de claves.

Por coincidencia exacta con el ID de usuario de OpenPGP.
Esto se denota con un signo igual inicial. No tiene sentido para certificados X.509. 
=Heinrich Heine <heinrichh@uni-duesseldorf.de>
Por coincidencia exacta con una dirección de correo electrónico.
Esto se indica encerrando la dirección de correo electrónico de la manera habitual con ángulos izquierdo y derecho. 
<heinrichh@uni-duesseldorf.de>
Por coincidencia parcial con una dirección de correo electrónico.
Esto se indica anteponiendo el prefijo de búsqueda con un @. Esto usa una búsqueda de subcadena pero considera solo la dirección de correo (es decir, dentro de los ángulos). 
@heinrichh
Por coincidencia exacta con el DN del sujeto.
Esto se indica con una barra inicial, seguida directamente por el DN del sujeto codificado según RFC-2253. Tenga en cuenta que no puede usar la cadena impresa por gpgsm --list-keys porque esa ha sido reordenada y modificada para una mejor readabilidad; use --with-colons para imprimir la cadena RFC-2253 en bruto (pero escapada según el estándar). 
/CN=Heinrich Heine,O=Poets,L=Paris,C=FR
Por coincidencia exacta con el DN del emisor.
Esto se indica con un signo de número, seguido directamente de una barra y luego directamente del DN del emisor codificado en RFC-2253. Esto debería devolver el certificado raíz del emisor. Véase la nota anterior. 
#/CN=Root Cert,O=Poets,L=Paris,C=FR
Por coincidencia exacta con el número de serie y el DN del emisor.
Esto se indica con un signo de número, seguido de la representación hexadecimal del número de serie, y luego seguido de una barra y el DN del emisor codificado en RFC-2253. Véase la nota anterior. 
#4F03/CN=Root Cert,O=Poets,L=Paris,C=FR
Por keygrip.
Esto se indica con un ampersand seguido de los 40 dígitos hexadecimales de un keygrip. gpgsm imprime el keygrip al usar el comando --dump-cert. 
&D75F22C3F86E355877348498CDC92BD21010A480
Por coincidencia de subcadena.
Este es el modo predeterminado, pero las aplicaciones pueden querer indicarlo explícitamente colocando el asterisco al principio. La coincidencia no distingue mayúsculas de minúsculas. 
Heine
*Heine
Prefijos . y +
Estos prefijos están reservados para buscar correos electrónicos anclados al final y para un modo de búsqueda de palabras. Aún no están implementados y su uso es indefinido.

Tenga en cuenta que hemos reutilizado el identificador de signo de número que se usaba en versiones antiguas de GnuPG para indicar el llamado local-id. Ya no se usa y no debería haber conflictos al usarlo con X.509.

Usar el formato RFC-2253 de los DN tiene la desventaja de que no es posible convertirlos de vuelta a la codificación original, sin embargo no tenemos que hacerlo porque nuestra base de datos de claves almacena esta codificación como metadatos.

EJEMPLOS

$ gpgsm -er goo@bar.net <plaintext >ciphertext

ARCHIVOS

Hay algunos archivos de configuración para controlar ciertos aspectos de gpgsm. A menos que se indique lo contrario, se esperan en el directorio de inicio actual (véase: [opción --homedir]).

gpgsm.conf
Este es el archivo de configuración estándar leído por gpgsm al inicio. Puede contener cualquier opción larga válida; los dos guiones iniciales no pueden introducirse y la opción no puede abreviarse. Este nombre predeterminado puede cambiarse en la línea de comandos (véase: [gpgsm-opción --options]). Debería hacer una copia de seguridad de este archivo.
common.conf
Este es un archivo de configuración opcional leído por gpgsm al inicio. Puede contener opciones relativas a todos los componentes de GnuPG. Su uso principal actual es para la opción "use-keyboxd".
policies.txt
Esta es una lista de políticas de CA permitidas. Este archivo debería listar los identificadores de objeto de las políticas línea por línea. Las líneas vacías y las líneas que comienzan con un signo de número se ignoran. Las políticas que falten en este archivo y no estén marcadas como críticas en el certificado imprimirán solo una advertencia; los certificados con políticas marcadas como críticas y no listadas en este archivo fallarán la verificación de la firma. Debería hacer una copia de seguridad de este archivo.

Por ejemplo, para permitir solo la política 2.289.9.9, el archivo debería verse así:

# Políticas permitidas
2.289.9.9
qualified.txt
Este es el método heredado para marcar los certificados raíz como utilizables para certificados calificados. Los certificados calificados son capaces de crear firmas legalmente vinculantes de la misma manera que las firmas manuscritas. El método moderno para marcar dichos certificados raíz es usar la marca "qual" en el trustlist.txt del sistema; consulte la página de manual de gpg-agent para más detalles.

Los comentarios en este archivo comienzan con un signo de número y las líneas vacías se ignoran. Las líneas tienen un límite de longitud, pero esto no es una limitación grave ya que el formato de las entradas es fijo y verificado por gpgsm: Una línea que no es comentario comienza con espacios en blanco opcionales, seguidos de exactamente 40 caracteres hexadecimales, espacio en blanco y un código de país de 2 letras en minúsculas. Los datos adicionales delimitados por un espacio en blanco se ignoran actualmente pero podrían usarse más adelante para otros propósitos.

Tenga en cuenta que incluso si un certificado está listado en este archivo, esto no significa que el certificado sea de confianza; en general, los certificados listados en este archivo también deben estar listados en ‘trustlist.txt’. Este es un archivo global instalado en el directorio sysconf (por ejemplo, ‘/etc/gnupg/qualified.txt’).

Cada vez que gpgsm usa un certificado para firmar o verificar, se consultará este archivo para comprobar si el certificado en cuestión ha sido emitido en última instancia por una de estas CAs. Si es así, se informará al usuario que la firma verificada representa una firma legalmente vinculante («calificada»). Al crear una firma con un certificado de este tipo, se emitirá una indicación adicional para que el usuario confirme que realmente desea crear dicha firma legalmente vinculante.

Debido a que este software aún no ha sido aprobado para su uso con dichos certificados, se mostrarán los avisos correspondientes para indicar este hecho.

help.txt
Este es un archivo de texto plano con algunas entradas de ayuda usadas con pinentry así como una gran lista de elementos de ayuda para gpg y gpgsm. El archivo estándar tiene textos de ayuda en inglés; para instalar versiones localizadas use nombres de archivo como ‘help.LL.txt’ con LL denotando el idioma. GnuPG viene con un conjunto de archivos de ayuda predefinidos en el directorio de datos (por ejemplo, ‘/usr/share/gnupg/gnupg/help.de.txt’) y permite la anulación de cualquier elemento de ayuda mediante archivos de ayuda almacenados en el directorio de configuración del sistema (por ejemplo, ‘/etc/gnupg/help.de.txt’). Para una referencia de la sintaxis del archivo de ayuda, consulte el archivo ‘help.txt’ instalado.
com-certs.pem
Este archivo es una colección de certificados comunes usados para poblar un ‘pubring.kbx’ recién creado. Un administrador puede reemplazar este archivo con uno personalizado. El formato es una concatenación de certificados X.509 codificados en PEM. Este archivo global está instalado en el directorio de datos (por ejemplo, ‘/usr/share/gnupg/com-certs.pem’).

Tenga en cuenta que en instalaciones grandes, es útil poner los archivos predefinidos en el directorio ‘/etc/skel/.gnupg/’ para que los usuarios recién creados comiencen con una configuración funcional. Para los usuarios existentes se proporciona un pequeño script auxiliar para crear estos archivos (véase: [addgnupghome]).

Para fines internos gpgsm crea y mantiene algunos otros archivos; todos se encuentran en el directorio de inicio actual (véase: [opción --homedir]). Solo gpgsm puede modificar estos archivos.

pubring.kbx
Este es un archivo de base de datos que almacena los certificados así como los metadatos. Para fines de depuración, la herramienta kbxutil puede usarse para mostrar la estructura interna de este archivo. Debería hacer una copia de seguridad de este archivo.
random_seed
El contenido de este archivo se usa para mantener el estado interno del generador de números aleatorios entre invocaciones. El mismo archivo es usado por otros programas de este software también.
S.gpg-agent
Si este archivo existe gpgsm primero intentará conectarse a este socket para acceder a gpg-agent antes de iniciar un nuevo gpg-agent . Bajo Windows, este socket (que en realidad es un archivo simple que describe un puerto de escucha TCP regular) es la forma estándar de conectar el gpg-agent.
