DESCRIPCIÓN

gpsd es un demonio para gestionar receptores GPS, receptores GNSS, receptores AIS y más. Con el tiempo, se han agregado una serie de clientes diversos que se comunican con gpsd para diversas tareas.

CLIENTES

Cada uno de los clientes de gpsd se conecta a un demonio gpsd para usar los datos de varias maneras. Consulte las secciones ARGUMENTOS y OPCIONES para obtener más información sobre los clientes.

cgps

cliente de terminal curses para gpsd

gegps

cliente de Google Earth para gpsd

gps

Descripción general de los clientes y utilidades de gpsd

gpscsv

volcar la salida JSON de gpsd como CSV

gpsdecode

decodificar flujos GPS, RTCM o AIS en un formato legible

gpspipe

herramienta para conectarse a gpsd y recuperar frases

gpsplot

herramienta para volcar dinámicamente datos de gráficos desde gpsd

gpsprof

perfilar un GPS y gpsd, trazando información de latencia

gpsrinex

Leer datos de gpsd, convertirlos a RINEX3 y guardarlos en un archivo.

gpssubframe

herramienta para volcar frases de subtrama desde gpsd

gpxlogger

Herramienta para conectarse a gpsd y generar un archivo GPX

lcdgps

cliente LCD para gpsd

xgps

cliente X para gpsd

xgpsspeed

velocímetro X para gpsd

OPCIONES

Los clientes de gpsd comparten algunas opciones comunes:

Imprimir un resumen de las opciones y luego salir.

-V, --version

Imprimir la versión del paquete y salir.

ARGUMENTOS

De forma predeterminada, los clientes recopilan datos del demonio gpsd local que se ejecuta en localhost, usando el puerto GPSD predeterminado 2947. El argumento opcional de cualquier cliente puede anular este comportamiento:

[servidor[:puerto[:dispositivo]]]

servidor

El nombre de host, la dirección IPv4 o la dirección IPv6 opcional del demonio gpsd al que conectarse. Si la especificación del servidor contiene corchetes, la parte que está dentro de ellos se toma como una dirección IPv6, y los sufijos de puerto/dispositivo solo se analizan después del corchete final. El valor predeterminado es localhost.

puerto

El puerto TCP opcional del demonio al que conectarse. El valor predeterminado es 2947.

dispositivo

El nombre del dispositivo opcional a supervisar.

Algunos casos posibles se ven así:

example.com

Conectarse al puerto predeterminado 2497 en example.com, probando tanto IPv4 como IPv6.

example.com:2317

Mirar el puerto 2317 en example.com, probando tanto IPv4 como IPv6.

localhost::/dev/ttyS1

Mirar el puerto predeterminado, 2947, de localhost, probando tanto IPv4 como IPv6 y supervisando la salida del dispositivo serie 1.

71.162.241.5:2317:/dev/ttyS3

Mirar el puerto 2317 en la dirección IPv4 especificada, recopilando datos del dispositivo serie 3 conectado.

[FEDC:BA98:7654:3210:FEDC:BA98:7654:3210]:2317:/dev/ttyS5

Mirar el puerto 2317 en la dirección IPv6 especificada, recopilando datos del dispositivo serie 5 conectado.

ENTORNO

La mayoría de los clientes de gpsd comprueban las variables de entorno GPSD_UNITS, LC_MEASUREMENTy LANG. Quizás más.

GPSD_UNITS se comprueba si no se especifica un sistema de unidades en la línea de comandos. Se puede establecer en 'i', 'imperial', 'm', 'metric' o 'n', 'nautical'.

LC_MEASUREMENT y luego LANG se comprueban si no se ha especificado un sistema de unidades en la línea de comandos, ni en GPSD_UNITS. Si el valor es 'C', 'POSIX' o comienza con 'en_US', el sistema de unidades se establece en imperial. El valor predeterminado, si no se ha seleccionado ningún sistema, es métrico.

VALORES DE RETORNO

Los clientes de gpsd devuelven códigos simples de éxito o fallo:

0

en caso de éxito.

1

en caso de fallo
