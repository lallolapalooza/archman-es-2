gpsprof(1)

Paquete: gpsd

Licencias: BSD

GPSPROF(1) Documentación de GPSD GPSPROF(1)

NOMBRE

gpsprof - perfilado de un GPS y gpsd, trazando información de latencia

SINOPSIS

gpsprof [OPCIONES] [servidor[:puerto[:dispositivo]]]

gpsprof -h

gpsprof -V

DESCRIPCIÓN

gpsprof realiza perfilado de precisión, latencia, vista del cielo y deriva temporal en un GPS. Emite a la salida estándar un programa GNUPLOT que dibuja uno de varios gráficos ilustrativos. También se le puede indicar que emita los datos de perfilado sin procesar.

La información del gráfico espacial predeterminado que proporciona puede ser útil para caracterizar la precisión de posición de un GPS.

gpsprof utiliza la instrumentación integrada en gpsd. Puede leer datos de un gpsd en ejecución local o remoto. O puede leer datos de un archivo de registro guardado.

gpsprof está diseñado para ser ligero y usar recursos mínimos del host. No se necesita instalar ningún subsistema gráfico en el host que ejecute gpsprof. Simplemente copie el archivo de gráfico resultante a otro host para renderizarlo con gnuplot(1).

gpsprof no requiere privilegios de root, pero funcionará bien como root.

OPCIONES

La opción -f, --formatter establece el tipo de gráfico. Actualmente se definen los siguientes tipos de gráfico:

space

Genera un diagrama de dispersión de las posiciones y traza círculos de error probable. Estos datos solo son significativos si el GPS se mantiene estacionario mientras gpsprof está en ejecución. Se listan varias estadísticas sobre las posiciones en la parte inferior. Este es el tipo de gráfico predeterminado.

polar

Genera un mapa de calor de la Relación Señal-Ruido (SNR) de los satélites reportados usando coordenadas polares. Se traza un punto de color para cada satélite visto por el GPS. El color del punto corresponde al SNR del satélite. Los puntos se trazan por azimut y elevación. El norte, azimut 0 grados, está en la parte superior del gráfico. Directamente sobre la cabeza, elevación de 90 grados, se traza en el centro. Útil para analizar la calidad de la vista del cielo vista por el GPS.

polarunused

Similar al gráfico polar, pero solo se trazan los satélites no utilizados. Útil para ver qué partes de la vista del cielo de la antena están obstruidas, degradadas, por debajo de la máscara de elevación del GPS o rechazadas de otra manera.

polarused

Similar al gráfico polar, pero solo se trazan los satélites utilizados para calcular las posiciones. Útil para ver qué partes de la vista del cielo de la antena se están utilizando en las posiciones.

time

Traza el delta del reloj del sistema (tiempo corregido por NTP) contra el tiempo GPS reportado en los mensajes PPS. El eje X es el tiempo de la muestra en segundos desde el inicio del gráfico. El eje Y es el delta del reloj del sistema desde el tiempo GPS.

instrumented

Traza el perfil instrumentado. Traza varios componentes de la latencia total entre el tiempo de posición del GPS y cuando el cliente recibe la posición.

Para los fines de la descripción, a continuación, el inicio del ciclo de reporte (SORC) es cuando comienza el ciclo de reporte de un dispositivo. Este tiempo se detecta observando cuándo la disponibilidad de datos sigue a una cantidad suficiente de tiempo de silencio para estar seguros de que hemos visto el hueco al final del ciclo de transmisión de reporte del sensor anterior. Detectar este hueco requiere un dispositivo que funcione a 9600bps o más rápido.

De manera similar, EORC es el fin del ciclo de reporte; cuando el demonio ha visto la última oración que necesita en el ciclo de reporte y está listo para enviar una posición al cliente.

Los componentes del gráfico instrumentado son los siguientes:

Latencia de posición

Delta entre el tiempo GPS y SORC.

Tiempo RS232

Tiempo de transmisión RS232 para los datos enviados durante el ciclo (calculado a partir del volumen de caracteres y la velocidad en baudios).

Tiempo de análisis

EORC, menos SORC, menos tiempo RS232. La cantidad de tiempo real que el demonio pasó en computación en lugar de E/S.

Tiempo de recepción

Tiempo de envío desde el demonio hasta cuando fue recibido por gpsprof.

Debido a los efectos de amortiguación de RS232, el perfilador a veces genera informes de latencias absurdamente altas justo al comienzo de una sesión. La opción -m le permite establecer un umbral de latencia, en múltiplos del tiempo de ciclo, por encima del cual se descartan los informes.

uninstrumented

Traza la latencia total sin instrumentación. Útil principalmente como una verificación de que la instrumentación no está produciendo una distorsión significativa. El eje X es el tiempo de la muestra en segundos desde el inicio del gráfico. El eje Y es la latencia en segundos. Solo traza los tiempos para informes que contienen posiciones; los artefactos tipo escalera en el gráfico se crean cuando el tiempo transcurrido desde informes sin posiciones se agrupa.

-?, -h, --help

Imprime un mensaje de uso y sale.

-d ARCHIVO, --dumpfile ARCHIVO

Vuelca los datos del gráfico, sin el código gnuplot(1) adjunto, a un archivo especificado para su posterior análisis.

-d NIV, --debug NIV

Establece el nivel de depuración.

-l ARCHIVO, --logfile ARCHIVO

Vuelca los informes JSON sin procesar recopilados del dispositivo al ARCHIVO especificado.

-n SEG, --wait SEG

Establece el número de segundos para muestrear. El valor predeterminado es 100. La mayoría de los GPS están configurados para emitir una posición por segundo, por lo que 100 muestras abarcarían entonces 100 segundos.

-r, --redo

Vuelve a trazar desde un archivo de registro JSON (como el que produce -l, logfile ) en la entrada estándar. Las opciones -n, --wait y -l, --logfile se ignoran cuando se selecciona esta.

-S CAD, --subtitle CAD

Establece una cadena de texto para incluir en el gráfico como subtítulo. Estará debajo del título.

-t CAD, --title CAD

Establece una cadena de texto como título del gráfico. Esto reemplazará el título predeterminado.

-T TERM, --terminal TERM

Especifica la configuración del tipo de terminal en el código gnuplot(1) . El uso típico es "-T png", o-T pngcairo" para decirle a gnuplot(1) que escriba un archivo PNG. El terminal predeterminado es "x11".

Diferentes instalaciones de gnuplot(1) soportarán diferentes tipos de terminal. Diferentes tipos de terminal pueden funcionar mejor para usted que otros. "-T png" generará imágenes PNG. Use "-T jpeg" para generar imágenes JPEG. "-Tpngcairo

" a menudo funciona mejor, pero no es soportado por algunas distribuciones. El mismo tipo de terminal puede funcionar de manera muy diferente en diferentes distribuciones. Para ver qué tipos de terminal soporta su copia de gnuplot(1)

:

gnuplot -e "set terminal"

ARGUMENTOS Por defecto, los clientes recopilan datos del demonio gpsd local en ejecución en localhost, usando el puerto GPSD predeterminado 2947. El argumento opcional de cualquier cliente puede anular este comportamiento:

[servidor[:puerto[:dispositivo]]] Para una explicación más detallada y ejemplos, vea la sección ARGUMENTOS en la página del manual gps(1)

SEÑALES

Enviar SIGUSR1 a una instancia en ejecución hace que escriba un mensaje de finalización en la salida de error estándar y reanude el procesamiento. El primer número en el mensaje de inicio es el ID del proceso al que enviar la señal.

EJEMPLOS

Para mostrar el gráfico, use gnuplot(1) . Así que, por ejemplo, para mostrar el diagrama de dispersión espacial predeterminado en su pantalla x11, haga esto:

gpsprof | gnuplot -persist

Para generar un archivo de imagen:

gpsprof -T png | gnuplot > imagen.png

Para generar un gráfico polar y guardar los datos del GPS para más gráficos:

gpsprof -f polar -T jpeg -l polar.json | gnuplot > polar.png

Luego, para hacer los gráficos polarused y polarunused correspondientes y los png a partir de los datos del GPS recién guardados:

gpsprof -f polarused -T jpeg -r < polar.json > polarused.plot
gnuplot < polarused.plot > polarused.png
gpsprof -f polarunused -T jpeg -r < polar.json > polarunused.plot
gnuplot < polarunused.plot  > polarunused.png

Puedes dividir los pasos, de modo que no necesites ejecutar toda la cadena de una vez. Esto permite ajustar la configuración sin tener que recopilar todos los datos de nuevo. Así:

gpspipe -w -x 3600 ::/dev/ttyS0 > MY.raw
gpsdecode  < MY.raw > MY.json
gpsprof -r -T pngcairo -t "MY Title" < MY.json > MY.plt
gnuplot MY.plt > MY.png
display MY.png

El comando gpspipe guarda una hora de datos en bruto del dispositivo gpsd local /dev/ttyS0 en MY.raw. Tardará una hora en completarse.

El comando gpsdecode convierte los datos en bruto de MY.raw en un archivo gpsd JSON llamado MY.json.

El comando gpsprof lee MY.json y crea un programa gnuplot en MY.plt.

El comando gnuplot ejecuta el programa en MY.plt y crea el archivo de imagen MY.png.

El programa display dibuja MY.png en tu escritorio.

VALORES DE RETORNO

0

en caso de éxito.

1

en caso de fallo
