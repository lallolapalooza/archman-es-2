DESCRIPCIÓ

N

El gpg-wks-client se utiliza para enviar solicitudes a un proveedor de Servicio de Claves Web. Esto se hace normalmente para subir una clave a un Directorio de Claves

Web.

Con el comando --supported, el llamador puede probar si un sitio soporta el Servicio de Claves Web. El argumento es una dirección arbitraria en el dominio que se va a probar. Por ejemplo ‘foo@example.net’. El comando devuelve éxito si el Servicio de Claves Web es soportado. La operación es silenciosa; para obtener salida de diagnóstico use la opción --verbose. Vea la opción --with-colons para una variante de este

comando.

Con el comando --check, el llamador puede probar si existe una clave para una dirección de correo proporcionada. El comando devuelve éxito si una clave está

disponible.

El comando --create se usa para enviar una solicitud de publicación en el Directorio de Claves Web. Los argumentos son la huella digital de la clave y el user-id a publicar. La salida del comando es un correo correctamente formateado con todos los encabezados estándar. Este correo puede ser pasado a sendmail(8) o a cualquier otra herramienta para enviar realmente ese correo. Si sendmail(8) está instalado, la opción --send puede usarse para enviar directamente la solicitud creada. Si el proveedor solicita un user-id 'mailbox-only' y no se encuentra tal user-id, gpg-wks-client intentará un user-id

adicional.

Los comandos --receive y --read se usan para procesar correos de confirmación enviados por el proveedor del servicio. El primero espera un mensaje MIME cifrado, el segundo un mensaje MIME ya descifrado. El resultado de estos comandos es otro correo que puede ser enviado de la misma manera que el correo creado con --create

.

El comando --install-key instala manualmente una clave en un directorio local (vea la opción -C) que refleja la estructura de un WKD. Los argumentos son un archivo con el bloque de la clave y el user-id a instalar. Si el primer argumento se asemeja a una huella digital, la clave se toma del llavero actual; para forzar el uso de un archivo, prefije el primer argumento con "./". Si no se dan argumentos, los parámetros se leen de stdin; el formato esperado son líneas con la huella digital y el buzón separados por un espacio. El comando --remove-key elimina una clave de ese directorio, su único argumento es un

user-id.

El comando --mirror es similar a --install-key pero toma las claves del servidor LDAP configurado para Dirmngr. Si no se dan argumentos, se instalan todas las claves y user-ids. Si se dan argumentos, se toman como nombres de dominio para limitar las claves a instalar. La opción --blacklist puede usarse para limitar aún más las claves a

instalar.

El comando --print-wkd-hash imprime los identificadores de user-id de WKD y los buzones correspondientes de los user-ids dados en la línea de comandos o vía stdin (un user-id por línea)

.

El comando --print-wkd-url imprime las URLs usadas para obtener la clave de los user-ids dados desde WKD. Aquí se usa el formato preferido actualmente con

subdominios.

en darse también sin los
dos guiones iniciales.

EJEMPLO

S

Para usar los servicios con clientes que carecen de soporte integrado, se puede usar el mecanismo mailcap. Simplemente

ponga: 
application/vnd.gnupg.wks; \
  /usr/bin/gpg-wks-client -v --read --send; \
  needsterminal; \
  description=WKS
message
en el ‘/etc/mailcap’. Esto asume que un /usr/lib/sendmail está instalado. Con esta configuración, cualquier programa de correo real ejecutará gpg-wks-client para los mensajes recibidos de un Servicio de Claves
Web.
