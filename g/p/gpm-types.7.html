GPM-TYPES(7) Manual de Información Diversa GPM-TYPES(7)

NOMBRE

gpm-types - tipos de puntero (ratones, tabletas, etc.) gestionados por gpm.
La información siguiente está extraída del archivo texinfo, que es la fuente de información preferida.

DESCRIPCIÓN

Esta página man describe los distintos tipos de puntero actualmente disponibles en gpm. Si examina el código fuente, descubrirá que el código específico del puntero está confinado en mice.c (aunque antes solo incluía decodificadores de ratón, gpm ahora también soporta tabletas y pantallas táctiles).

El tipo de ratón se especifica en la línea de comandos con la opción -t. La opción toma un argumento, que representa el nombre de un tipo de ratón. Cada tipo puede estar asociado a diferentes nombres. Para los tipos de ratón antiguos, un nombre es el nombre antiguo compatible con la selección (selection) y otro es el nombre de XFree. Después de la versión 1.18.1 de gpm, el número de sinónimos se hizo arbitrario y el nombre real que se utiliza se pone a disposición de la función responsable de la inicialización del ratón. Por lo tanto, es posible que un decodificador de ratón se comporte ligeramente de forma diferente según el nombre que se utilice para el dispositivo (si esta característica ya hubiera estado presente, no tendríamos, por ejemplo, ms+ y ms+lr como tipos de ratón diferentes).

El procedimiento de inicialización de cada tipo de ratón también puede recibir opciones adicionales, por medio de la opción -o de la línea de comandos. Dado que la interpretación de la cadena de opciones es específica del decodificador, las opciones permitidas se describen en asociación con cada tipo de ratón. Cuando no se proporciona una descripción de las cadenas de opciones, eso significa que la cadena de opciones no se utiliza para ese tipo de ratón y especificar una genera un error. Cuando el documento se refiere a ``opciones seriales estándar'' significa que se puede especificar una de -o dtr, -o rts, -o both para alternar las líneas de control del puerto serie.

Los siguientes tipos de ratón se reconocen actualmente:

bare Microsoft
El protocolo Microsoft, sin ninguna extensión. Solo informa de dos botones. Si su dispositivo tiene tres, debería intentar ejecutar el decodificador mman o msc. En este último caso, necesita decirle al ratón que hable el protocolo msc alternando las líneas DTR y RTS (con una de -o drt, -o rts o -o both) o invocando gpm -t msc mientras mantiene presionado el botón central. Muy molesto, realmente. Este decodificador de ratón acepta opciones seriales estándar, aunque no deberían ser necesarias.
ms
Este es el protocolo Microsoft original, con una extensión para el botón central. Algunos dispositivos antiguos de dos botones envían algunos paquetes espurios que pueden malinterpretarse como eventos del botón central. Si este es su caso, use el tipo de ratón bare. Algunos dispositivos nuevos de dos botones son ``plug and play'' (conexión y uso), y no juegan limpio en absoluto; en este caso intente -t pnp. Muchos (la mayoría) de los dispositivos de tres botones que usan el protocolo microsoft fallan al informar algunos eventos del botón central durante el movimiento del ratón. Dado que el protocolo no distingue entre el botón central subiendo y el botón central bajando, es probable que se desincronice, por lo que este decodificador declara que el botón central está arriba siempre que el ratón se mueva. Esto previene el arrastre con el botón central, por lo que probablemente debería usar -t ms+lr en lugar de este decodificador, especialmente si quiere usar X. Este decodificador de ratón acepta opciones seriales estándar, aunque no deberían ser necesarias.
ms+
Esto es lo mismo que -t ms excepto que el botón central no se restablece durante el movimiento del ratón. Así que puede arrastrar con el botón central. Sin embargo, si su ratón exhibe el comportamiento defectuoso habitual, es probable que el decodificador se desincronice de la realidad, pensando que el botón central está arriba cuando está abajo y viceversa. Probablemente debería usar -t ms+lr en lugar de este decodificador. Este decodificador de ratón acepta opciones seriales estándar, aunque no deberían ser necesarias.
ms+lr
Esto es lo mismo que -t ms+ excepto que hay una funcionalidad adicional para restablecer el estado del botón central presionando los otros dos botones a la vez. Haga esto cuando el decodificador entre en un estado confuso en el que piense que el botón central está arriba cuando está abajo y viceversa. (Si se cansa de tener que hacer esto, por favor no culpe a gpm; ¡culpe a su ratón defectuoso! Tenga en cuenta que la mayoría de los ratones de tres botones que pueden hacer el protocolo microsoft pueden hacer el protocolo MouseSystems en su lugar. El ``3 Button Serial Mouse mini-HOWTO'' tiene información sobre esto.) Este decodificador de ratón acepta opciones seriales estándar, aunque no deberían ser necesarias.
msc MouseSystems
Este es el protocolo estándar para dispositivos serie de tres botones. Algunos de tales dispositivos solo entran en modo MouseSystem si las líneas RTS, DTR o ambas se ponen a nivel bajo. Así que, puede intentar -t msc asociado con -o rts, -o dtr o -o both.
mman Mouseman
El protocolo usado por los nuevos dispositivos Logitech con tres botones. Es compatible hacia atrás con el protocolo Microsoft, así que si su ratón tiene tres botones y funciona con -t ms o decodificadores similares, puede intentar -t mman en su lugar para usar el botón central. Este decodificador de ratón acepta opciones seriales estándar, aunque no deberían ser necesarias.
sun
El protocolo usado en computadoras Sparc y algunas otras. Este decodificador de ratón acepta opciones seriales estándar, aunque no deberían ser necesarias.
mm MMSeries
El título lo dice todo. Este decodificador de ratón acepta opciones seriales estándar, aunque no deberían ser necesarias.
logi Logitech
Este es el protocolo usado por los ratones Logitech serie antiguos.
bm BusMouse
Algunos dispositivos de bus usan este protocolo, incluyendo los producidos por Logitech.
ps2 PS/2
El protocolo usado por la mayoría de los ratones de bus.
ncr
Este `tipo' es capaz de decodificar el lápiz apuntador encontrado en algunos portátiles (el lápiz NCR 3125)
wacom
El protocolo usado por la tableta Wacom. Desde la versión 1.18.1 tenemos un nuevo decodificador Wacom, ya que el antiguo no funcionaba con las tabletas nuevas. Este decodificador fue probado con las tabletas Ultrapad, PenPartner y Graphire. Opciones: -o relative (por defecto) para modo relativo, -o absolute para modo absoluto.
genitizer
El Este decodificador de ratón acepta opciones seriales estándar, aunque no deberían ser necesarias.
logim
Usado para convertir ratones Logitech en compatibles con Mouse-Systems. Obviamente, solo funciona con algunos de los ratones Logitech.
pnp
Este decodificador funciona con los nuevos ratones producidos por nuestro amigo Bill, y quizás con los antiguos también. El protocolo Pnp está fijado a 1200 baudios y se altera con la inicialización normal, así que este es un decodificador -t bare sin ninguna inicialización. Este decodificador de ratón acepta opciones seriales estándar, aunque no deberían ser necesarias.
ms3
Un decodificador para los nuevos dispositivos serie IntelliMouse, los que tienen tres botones y un protocolo incompatible con los anteriores. La rueda actualmente no se usa.
imps2
``IntelliMouse'' en el puerto ps/2. Este tipo también puede usarse para un ratón ps/2 genérico de 2 botones, ya que detectará automáticamente el tipo.
netmouse
Decodifica el tipo de dispositivos ``Genius NetMouse'' en el puerto ps/2. Para dispositivos serie ``Netmouse'', use el decodificador ``ms3''.
cal
Un decodificador del ``dispositivo Calcomp UltraSlate.
calr
Igual que lo anterior, pero en modo relativo.
twid
Soporte para el teclado twiddler. A partir de gpm-1.14 este decodificador incluye un generador de caracteres para la consola de texto, pero aún no soporta keycodes de X. Si se usa con -R, gpm de todos modos repetirá los eventos del ratón al servidor X. Se puede encontrar más información sobre el soporte de twiddler en README.twiddler, en la distribución de gpm.
syn synaptics
Un decodificador para el Synaptics TouchPad conectado al puerto serie. Este decodificador de ratón acepta opciones seriales estándar, aunque no deberían ser necesarias.
synps2 synaptics_ps2
Igual que lo anterior, pero para los dispositivos conectados al puerto ps2.
brw
Un decodificador para el Fellowes Browser, un dispositivo con 4 botones y una rueda. Este decodificador de ratón acepta las opciones estándar de serie, aunque no deberían ser necesarias.
js Joystick
Este tipo de ratón usa el dispositivo de joystick para generar eventos de ratón. Solo está disponible si el encabezado linux/joystick.h se encuentra en tiempo de compilación. El encabezado (y el dispositivo también) se introdujo solo durante el desarrollo de la 2.1, y no está presente en la versión 2.0 del kernel.
summa
Este es un decodificador para la tableta Symmagraphics de Genius, ejecutado en modo absoluto. Un repetidor está asociado a este decodificador, por lo que se puede usar -R summa para generar eventos X incluso para otros dispositivos de puntería absolutos, como pantallas táctiles. Para usar los datos repetidos desde X, necesita un módulo xf86Summa.o modificado.
mtouch
Un decodificador para la pantalla táctil MicroTouch. Por favor, consulte el archivo README.microtouch en el árbol de fuentes de gpm para más información. En un futuro cercano, sin embargo, planeo incorporar el contenido de ese archivo a esta documentación.
gunze
Un decodificador para la pantalla táctil gunze. Por favor, consulte el archivo README.gunze en el árbol de fuentes de gpm para más información. En un futuro cercano, sin embargo, planeo incorporar el contenido de ese archivo a esta documentación. El decodificador acepta las siguientes opciones: smooth=, debounce=. Una mayor suavidad resulta en un movimiento más lento también; una menor suavidad da un movimiento más rápido pero, obviamente, menos suave. La suavidad predeterminada es 9. El tiempo de rebote se expresa en milisegundos y es la duración mínima de un evento de presión-soltado para ser considerado como un toque. Los rebotes más pequeños se ignoran.
acecad
La tableta Acecad en modo absoluto.
wp wizardpad
Tableta Genius WizardPad
