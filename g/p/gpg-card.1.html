DESCRIPCIÓ

N

El gpg-card se utiliza para administrar tarjetas inteligentes y tokens USB. Proporciona un conjunto de funciones superior al de gpg --card-edit y puede considerarse una interfaz para scdaemon, el cual es un demonio iniciado por gpg-agent para manejar tarjetas

inteligentes.

Si gpg-card se invoca sin comandos, se utiliza un modo

interactivo.

Si gpg-card se invoca con uno o más comandos, se ejecutan desde la línea de comandos los mismos comandos disponibles en el modo interactivo. Estos comandos deben delimitarse con un guion doble. Si se requiere un guion doble o un carácter específico del shell como parte de un comando, el comando completo debe ponerse entre comillas. Si uno de esos comandos devuelve un error, los comandos restantes ya no se ejecutan a menos que el comando esté precedido por un guion

simple.

Una lista de comandos está disponible mediante el comando help y una breve descripción de cada comando se imprime usando help CMD. Véase la sección COMANDOS para una descripción

completa.

Véase las secciones NOTAS para instr

ucciones relativas a tarjetas o
aplicaciones de tarjeta específicas.

NOTAS (OPENPGP)

El soporte para tarjetas OpenPGP en gpg-card aún no está completo. Para las funciones faltantes, continúe utilizando gpg --card-edit.

NOTAS (PIV)

GnuPG tiene soporte para tarjetas PIV ("Personal Identity Verification" según la Especificación Especial 800-73-4 del NIST). Esta sección describe cómo inicializar (personalizar) un token Yubikey nuevo con la aplicación PIV (requiere Yubikey-5). Asumimos que las credenciales aún no se han cambiado y son:

Clave de autenticación
Esta es una clave de 24 bytes descrita por la cadena hexadecimal
010203040506070801020304050607080102030405060708.
PIN de la aplicación PIV
Esta es la cadena 123456.
Clave de Desbloqueo de PIN
Esta es la cadena 12345678.

Consulte la sección de ejemplos sobre cómo cambiar estos valores predeterminados. Para uso en producción, es importante utilizar valores seguros. Tenga en cuenta que la Clave de Autenticación no se solicita a través del diálogo habitual de Pinentry, sino que debe introducirse manualmente o leerse de un archivo. Se sugiere encarecidamente el uso de una máquina dedicada para personalizar los tokens.

Para ver el contenido de la tarjeta, se puede usar el comando list. Usaremos el modo interactivo en lo siguiente (la cadena gpg/card> es el prompt). Un ejemplo de salida para una tarjeta nueva es:

gpg/card> list
Lector ...........: 1050:0407:X:0
Tipo de tarjeta ....: yubikey
Firmware de tarjeta ....: 5.1.2
Número de serie ....: D2760001240102010006090746250000
Tipo de aplicación .: OpenPGP
Versión ..........: 2.1
[...]

Se puede ver en la línea "Tipo de aplicación" que GnuPG seleccionó la aplicación OpenPGP del Yubikey. Esto se debe a que GnuPG asigna la máxima prioridad a la aplicación OpenPGP. Para usar la aplicación PIV del Yubikey se pueden utilizar varios métodos:

Con un Yubikey 5 o posterior, la aplicación OpenPGP en el Yubikey puede deshabilitarse:

gpg/card> yubikey disable all opgp
gpg/card> yubikey list
Aplicación  USB    NFC
-----------------------
OTP          sí     sí
U2F          sí     sí
OPGP         no     no
PIV          sí     no
OATH         sí     sí
FIDO2        sí     sí
gpg/card> reset

El reset es necesario para que el sistema GnuPG vuelva a leer la tarjeta. Tenga en cuenta que las aplicaciones deshabilitadas conservan todos sus datos y pueden ser habilitadas en cualquier momento (use ‘help yubikey’).

Otra opción, que funciona para todas las versiones de Yubikey, es deshabilitar el soporte para tarjetas OpenPGP en scdaemon. Esto se hace añadiendo la línea

disable-application openpgp

a ‘~/.gnupg/scdaemon.conf’ y reiniciando scdaemon, ya sea matando el proceso o usando ‘gpgconf --kill scdaemon’. Finalmente, el orden predeterminado en el que scdaemon prueba las aplicaciones de tarjetas puede cambiarse. Por ejemplo, para preferir PIV sobre OpenPGP basta con añadir

application-priority piv

a ‘~/.gnupg/scdaemon.conf’ y reiniciar scdaemon. Esto solo tiene efecto en tokens que admiten tanto PIV como OpenPGP, pero no obstaculiza el uso de tokens solo OpenPGP.

Con uno de estos métodos empleados, el comando list de gpg-card muestra esto:

En caso de que varios tokens estén conectados al ordenador, gpg-card solo mostrará uno. Para mostrar otro token, se puede proporcionar el número del token (0, 1, 2, ...) como argumento al comando list. El comando ‘list --cards’ imprime una lista de todos los tokens insertados.

Tenga en cuenta que el "S/n mostrado" se imprime en el token y también se muestra en los prompts de Pinentry al solicitar el PIN. Las cuatro ranuras de claves estándar siempre se muestran; si se inicializan otras ranuras de claves, también se muestran. La clave de autenticación PIV (referencia interna PIV.9A) se utiliza para autenticar la tarjeta y al titular de la tarjeta. El uso de la clave privada asociada está protegido por el PIN de la aplicación, que debe proporcionarse una vez y la clave podrá usarse hasta que la tarjeta se reinicie o se desconecte del lector o puerto USB. GnuPG utiliza esta clave con su soporte de Secure Shell. La clave de autenticación de tarjeta (PIV.9E), también conocida como CAK, se utiliza para soportar aplicaciones de acceso físico. La clave privada no está protegida por un PIN y, por lo tanto, se puede utilizar de inmediato. La clave de firma digital (PIV.9C) se utiliza para firmar digitalmente documentos. El uso de la clave privada asociada está protegido por el PIN de la aplicación, que debe proporcionarse para cada operación de firma. La clave de gestión de claves (PIV.9D) se utiliza para el cifrado. El uso de la clave privada asociada está protegido por el PIN de la aplicación, que solo necesita proporcionarse una vez para que las operaciones de descifrado puedan realizarse hasta que la tarjeta se reinicie o se desconecte del lector o puerto USB.

Ahora generaremos tres de las cuatro claves. Tenga en cuenta que GnuPG actualmente no utiliza la clave de autenticación de tarjeta; sin embargo, esta clave es obligatoria según el estándar PIV y, por lo tanto, también la crearemos. La generación de claves requiere que nos autentiquemos en la tarjeta. Esto se puede hacer en la línea de comandos (lo que revelaría la clave):

gpg/card> auth 010203040506070801020304050607080102030405060708

o leyendo la clave de un archivo. Ese archivo debe constar de una sola línea terminada en LF con la clave codificada en hexadecimal (como se muestra arriba):

gpg/card> auth < myauth.key

Como siempre, ‘help auth’ proporciona ayuda para este comando. Se mostrará un mensaje de error si se utiliza una clave incorrecta. La autenticación es válida hasta un reinicio de la tarjeta o hasta que la tarjeta se retire del lector o del puerto USB. Tenga en cuenta que en modo no interactivo, ‘<’ debe entrecomillarse para que el shell no lo interprete como su propio símbolo de redirección.

Aquí están los comandos reales para generar las claves:

gpg/card> generate --algo=nistp384 PIV.9A
Tarjeta PIV n.º yk-9074625 detectada
gpg/card> generate --algo=nistp256 PIV.9E
Tarjeta PIV n.º yk-9074625 detectada
gpg/card> generate --algo=rsa2048 PIV.9C
Tarjeta PIV n.º yk-9074625 detectada

Si ya se ha creado una clave para una de las ranuras, se imprimirá un error; para crear una nueva clave de todos modos, se utiliza la opción ‘--force’

Se puede usar. Tenga en cuenta que solo se han creado las claves privada y pública, pero no se almacenan certificados en las ranuras de la clave. De hecho, GnuPG utiliza su propio método no estándar para almacenar solo la clave pública en lugar del certificado. Otras aplicaciones no podrán hacer uso de estas claves hasta que gpgsm u otra herramienta se haya utilizado para crear y almacenar los respectivos certificados. Veamos qué muestra ahora el comando

list:

La información principal para cada clave es el keygrip, una cadena hexadecimal de 40 bytes que identifica la clave. Este keygrip es un identificador único para los parámetros específicos de una clave. Es utilizado por gpg-agent y otras partes de GnuPG para asociar una clave privada con su formato de certificado específico del protocolo (X.509, OpenPGP o SecureShell). Debajo del keygrip se muestran la referencia de la clave junto con las capacidades de uso de la clave. Finalmente, el algoritmo se imprime en el formato utilizado por {gpg}. En ese punto no se muestra otra información porque para estas claves nuevas gpg no podrá encontrar certificados

coincidentes.

Aunque podríamos haber creado la clave de gestión de claves también con el comando generate, crearemos esa clave fuera de la tarjeta para que exista una copia de seguridad. Para lograr esto, se necesita crear una clave con gpg o gpgsm o importarla en una de estas herramientas. Observe el último paso que importó el certificado creado. Si en su lugar hubiera creado una solicitud de firma de certificado (CSR) en lugar de un certificado autofirmado y la hubiera enviado a una CA, realizaría el mismo paso de importación con el certificado recibido de la CA. Ahora, para mover la clave y el certificado a la tarjeta, inicie gpg-card de nuevo e

introduzca: 
gpg/card> writekey PIV.9D 34798AAFE
0A7565088101CC4AE31C5C8C74461CB gp
g/card> writecert PIV.9D < encr.crt

Si introdujo una frase de paso para proteger la clave privada, se le pedirá a través del diálogo de Pinentry. En caso de éxito, la clave y el certificado se han escrito en la tarjeta y un comando list

muestra: 
[...]

      keyref .....:

Con esto, la clave de cifrado es ahora totalmente funcional y puede usarse para descifrar mensajes cifrados con este certificado. Tenga cuidado: la clave original todavía está almacenada en el disco y debe moverse a un medio de respaldo. Esto se puede hacer simplemente copiando el archivo ‘34798AAFE0A7565088101CC4AE31C5C8C74461CB.key’ del directorio ‘~/.gnupg/private-keys-v1.d/’ al medio de respaldo y eliminando el archivo de su ubicación

original.
