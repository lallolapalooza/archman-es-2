Archiva los binarios de la aplicación y los archivos fuente asociados en un experimento de gprofng para hacerlo autocontenido y

De forma predeterminada, los binarios se archivan como parte de la recopilación de datos, pero los archivos fuente de la aplicación no se archivan. Utilice esta herramienta para cambiar esto y, a continuación, archivar componentes

Archivado de binarios de la aplicación - De forma predeterminada, los binario
s se archivan automáticamente cuando se crea un experimento. Sin embargo
, el archivado no ocurre en una o más de las siguientes circunstancias:
  • Si la aplicación perfilada se termina antes de que salga
    • normalmente.
  • Si se perfila un proceso en
    • ejecución.
  • Si el archivado se desactiva explícitamente al perfilar. Por ejemplo, utilizando la opción -a off en gprofng
    • coll
ect
app.

En estos casos, gprofng archive debe ejecutarse manualmente y en la misma máquina donde se registraron los datos del

perfilado.

El archivado de datos de experimentos durante el proceso de recopilación de datos puede ser bastante costoso. Especialmente si el experimento tiene muchos procesos descendientes. En tales casos, una estrategia más eficiente es utilizar la opción -a off al recopilar los datos. Una vez que la recopilación haya finalizado, los datos pueden archivarse utilizando la opción -s all. Esto guarda todos los ejecutables y archivos fuente en el

experimento.

Si durante el archivado hay un mensaje de error de que un ejecutable o archivo fuente no se puede encontrar, el comando addpath para añadir la ruta a los archivos que faltan puede incluirse en el archivo .er.rc. Después de añadir este comando, archive el experimento de nuevo. El archivado puede repetirse tantas veces como sea necesario para archivar todos los

archivos.

El archivado debe realizarse en el mismo sistema que se utilizó para recopilar el experimento. Si algunos archivos no se pueden acceder desde este sistema (por ejemplo, fuentes u objetos), entonces se puede realizar un archivado adicional utilizando otro sistema que pueda acceder a ellos. Por ejemplo, el sistema donde se compiló la

aplicación.

Algunas aplicaciones de Java almacenan objetos compartidos en archivos jar. Por defecto, dichos objetos compartidos no se archivan automáticamente. Para archivar objetos compartidos contenidos en archivos jar, asegúrese de incluir el comando addpath en un archivo .er.rc. El comando addpath debe dar la ruta al archivo jar, incluyendo el propio archivo jar. El archivo .er.rc debe guardarse en el directorio de inicio

del usuario, o en el direc
torio padre del experimento.
  • Archivado de fuentes de la aplicación - De forma predeterminada, los archivos fuente de la aplicación no se archivan en el experimento. Ejecute el comando gprofng archive con la opción -s all o -s used en cada experimento para almacenar los archivos fuente en el
    • experimento.
  • Archivado automático de fuentes de la aplicación - La variable de entorno GPROFNG_ARCHIVE puede configurarse para archivar automáticamente las fuentes cuando el experimento haya finalizado. Esta variable de entorno puede contener argumentos -s y -m, como pares de argumentos y opciones, separados por uno o más espacios en blanco.

    Si aparece más de un argumento -s en la línea de comandos, prevalece el último. Si -s se pasa tanto en la línea de comandos como se establece por la variable de entorno, prevalece la opción de la variable de

    entorno.

    Tenga en cuenta que en caso de que se haya habilitado el archivado automático de fuentes durante la recopilación de datos utilizando ya sea la variable GPROFNG_ARCHIVE o la opción -a src o -a usedsrc, se recomienda confirmar que los archivos fuente se han resuelto correctamente ejecutando el comando gprofng archive -s all o gprofng archive

    -s
    • used.
  • Las opciones -d y -r son mutuamente
    • excluyentes.
  • Al utilizar la opción -d o -r, la variable de entorno GPROFNG_ARCHIVE_COMMON_DIR puede utilizarse para especificar la ubicación de el archivo común. Esto puede ser muy conveniente al utilizar un script para perfilar
    • aplicaciones.
  • Si se da más de una opción -s en la línea de comandos o se especifica en la variable de entorno, la opción especificada para todas debe ser la misma. Si no, gprofng archive termina con un
    • error.
  • Esta herramienta no funciona en experimentos registrados con versiones anteriores de las herramientas. Si se invoca en tales experimentos, se imprime una advertencia. Utilice la versión de gprofng archive de la misma versión con
    • la que se regi
