DESCRIPCI

ÓN

Este paquete intenta ser un servidor de ratón útil para aplicaciones que se ejecutan en la consola de Linux. Está basado en el paquete "selection", y parte de su código proviene del propio selection. Este paquete está destinado a ser un reemplazo para "selection" como mecanismo de cortar y pegar; también proporciona instalaciones adicionales. El paquete "selection" ofreció la primera implementación de cortar y pegar para Linux usando dos botones del ratón, y el búfer de corte se sigue llamando "búfer de selección" o simplemente "selección" en todo este documento. La información a continuación está extraída del archivo texinfo, que es la fuente de

información
preferida.

El ejecutable gpm está destinado a actuar como un demonio (por lo tanto, gpmd sería un mejor nombre para él). Esta sección está destinada a describir las opciones de línea de comandos para gpm, mientras que sus aspectos internos se

describen en la siguiente sección.

Debido a restricciones en la llamada al sistema ioctl(TIOCLINUX), gpm debe ser ejecutado por el superusuario. Las restricciones se han añadido en los últimos núcleos 1.1 para corregir un agujero de seguridad relacionado con la selección y el volcado de pantalla. El servidor se puede configurar para adaptarse al gusto del usuario, y cualquier aplicación que use el ratón heredará la actitud del servidor. Desde la versión 1.02 hasta la 1.19.2 era posible para cualquier usuario conectado a la consola del sistema cambiar la sensación del ratón usando

la opción -q. Esto ya no es
posible por razones de seguridad.

A partir de la versión 0.97, el programa del servidor se pone a sí mismo en segundo plano. Para matar gpm, simplemente puedes volver a invocarlo con el interruptor de línea de comandos -k, aunque killall gpm puede

ser una mejor opción.

COMANDOS

ESPECIALES

La versión 1.10 añade la capacidad de ejecutar comandos especiales en ciertas circunstancias. Los comandos especiales por defecto son reiniciar y apagar el sistema, pero el usuario puede especificar su propia elección. La capacidad de invocar comandos usando el ratón es útil para los programadores, porque permite emitir un apagado limpio cuando el teclado está bloqueado y no hay red disponible para restaurar el sistema a un estado

normal.

Los comandos especiales se activan haciendo triple clic con el botón izquierdo y el derecho -- un evento improbable durante el uso normal del ratón. La forma más fácil de hacer triple clic es presionar uno de los botones y hacer triple clic en el otro. Cuando el procesamiento especial se activa, un mensaje aparece en la consola (y el altavoz pita dos veces, si tienes un altavoz); si el usuario suelta todos los botones y presiona uno de ellos de nuevo dentro de los tres segundos, entonces el comando especial correspondiente al botón se

ejecuta.

El interruptor de línea de comandos -S habilita el procesamiento de comandos especiales y permite cambiar los tres comandos especiales. Para aceptar los comandos por defecto usa -S "" (es decir, especifica un argumento vacío). Para especificar tus propios comandos, usa una lista separada por dos puntos para especificar comandos asociados con el botón izquierdo, central y derecho. Si alguno de los comandos está vacío, se interpreta como `enviar una señal al proceso init'. Esta operación particular se admite, además de ejecutar comandos externos, porque a veces errores graves ponen al sistema en la imposibilidad
de hacer fork; en estos raros casos el programador debería poder apagar el sistema de todos modos, y matar init desde un proceso en ejecución es la única manera de hacerlo.
Como ejemplo, -S ":telinit 1:/sbin/halt", asocia matar init al botón izquierdo, ir a modo de usuario único al botón central, y apagar el sistema al botón
derecho.
Los administradores del sistema obviamente deberían tener cuidado con los comandos especiales, ya que gpm se ejecuta con permisos de superusuario. Los comandos especiales son más adecuados para ordenadores cuyo ratón solo puede ser accedido físicamente
por personas de confianza.

Habilitar modo múltiple. El demonio leerá dos dispositivos de ratón diferentes. Cualquier opción posterior se referirá al segundo dispositivo, mientras que cualquier opción anterior se usará para el primer dispositivo. Esta opciónn activa automáticamente la opción de repetidor (-R).
-o lista-de-opciones-extra
La opción funciona de manera similar a la ``-o'' de mount; se usa para especificar una lista de ``opciones extra'' que son específicas para cada tipo de ratón. La lista está separada por comas. Las opciones dtr, rts o both son usadas por la inicialización del puerto serie para alternar las líneas del módem, de forma compatible con versiones anteriores de gpm; sin embargo, ten en cuenta que usar -o dtr asociado con tipos de ratón que no sean de serie simple ahora puede generar un error. Y por cierto, usa -o después de -m y después de -t.
-p
Fuerza que el puntero sea visible mientras se selecciona. Este es el comportamiento de selection-1.7, pero a veces es confuso. Por defecto no se muestra el puntero, lo cual también puede ser confuso.
-r número
Establece la sensibilidad. Se usa una sensibilidad mayor para un movimiento del cursor más rápido.
-R[nombre]
Hace que gpm actúe como repetidor: cualquier dato del ratón recibido mientras se está en modo gráfico será producido en el fifo /dev/gpmdata en el protocolo nombre, dado como argumento opcional (¡sin espacio entre ellos!). En principio, puedes usar los mismos nombres que para la opción -t, aunque repetir a algunos protocolos puede no estar implementado por un tiempo. Además, puedes especificar raw como el nombre, para repetir los datos del ratón byte a byte, sin ninguna traducción de protocolo. Si nombre se omite, por defecto es msc. Usando gpm en modo repetidor, puedes configurar el servidor X para usar su fifo como un dispositivo de ratón. Esta opción es útil para los propietarios de ratones de bus para superar la limitación de apertura única. También es una manera fácil de manejar esos estúpidos ratones de modo dual que te obligan a mantener pulsado el botón central mientras cambias de modo de vídeo. La opción es activada por la opción -M.
-s número
Establece la frecuencia de muestreo para el dispositivo del ratón.
-S comandos
Activa el procesamiento de comandos especiales, y opcionalmente especifica comandos personalizados como una lista separada por dos puntos. Consulta arriba para una descripción detallada de los comandos especiales.
-t nombre
Establece el tipo de ratón. Usa -t help para obtener una lista de tipos permitidos. Desde la versión 1.18.1, la lista también muestra qué protocolos están disponibles como repetidores (consulta -R arriba), marcándolos con un asterisco (``*'').

Usa -t después de que hayas seleccionado el dispositivo del ratón con -m.

-v

-2
Fuerza dos botones. Esto significa que el botón central, si existe, será tomado como si fuera el derecho.
-3
Fuerza tres botones. Por defecto, el ratón se considera de 2 botones, hasta que se pulsa el botón central. Si hay tres botones, el derecho se usa para extender la selección, y el central se usa para pegarla. Cuidado: si usas la opción -3 con un ratón de 2 botones, no podrás pegar la selección.

OPERACIÓN

Para seleccionar texto, pulsa el botón izquierdo del ratón y arrastra el ratón. Para pegar texto en la misma u otra consola, pulsa el botón central. El botón derecho se usa para extender la selección, como en `xterm'.

Los ratones de dos botones usan el botón derecho para pegar texto.

Los dobles y triples clics seleccionan palabras completas y líneas completas. Se recomienda el uso de la opción `-p' para una mejor retroalimentación visual.

Si un espacio final después del contenido de una línea está resaltado, y si no hay otro texto en el resto de la línea, el resto de la línea será seleccionado automáticamente. Si se seleccionan varias líneas, los espacios finales resaltados en cada línea serán eliminados del búfer de selección.

Cualquier salida en la consola virtual que contiene la selección borrará la selección resaltada de la pantalla, para mantener la integridad de la visualización, aunque el contenido del búfer de pegado no se verá afectado.

El mecanismo de selección está deshabilitado si la consola virtual de control está en modo gráfico, por ejemplo cuando se ejecuta X11, y se vuelve a habilitar cuando se reanuda el modo texto. (Pero consulta la sección DE ERRORES más abajo.)

DE ERRORES

El servidor gpm puede tener problemas interactuando con X: si tu ratón es un dispositivo de apertura única (es decir, un ratón de bus), deberías matar a gpm antes de iniciar X, o usar la opción -R (consulta arriba). Para matar a gpm simplemente invoca gpm -k. Este problema no se aplica a los ratones de serie.

Dos instancias de gpm no pueden ejecutarse en el mismo sistema. Si tienes dos ratones, usa la opción -M (consulta arriba).

Mientras la consola actual está en modo gráfico, gpm duerme hasta que vuelve el modo texto (a menos que se use -R). Así, no responderá a los clientes. De todos modos, es poco probable que clientes ansiosos por el ratón aparezcan en consolas ocultas.

Los clientes que se distribuyen con gpm no están actualizados, por lo que existen riesgos potenciales de seguridad al usarlos.
