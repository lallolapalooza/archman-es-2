gpac [opciones]FILTRO[ENLACE]FILTRO[...]
gpac es la herramienta de línea de comandos de GPAC para configurar y ejecutar cadenas de

filtros.

FILTRO: una única declaración de filtro (p. ej., -i file, -o dump, inspect, ...), consulte gpac -h doc.
[ENLACE]: una instrucción de enlace (p. ej., @, @2, @2#StreamType=Visual, ...), consulte gpac -h doc.
[opciones]: una o más cadenas de opciones, cada una comenzando con el carácter -.
- una opción que utiliza un solo - indica una opción de gpac (consulte gpac -hx) o de libgpac (consulte gpac -hx core)
- una opción que utiliza -- indica una opción global de filtro o meta-filtro (p. ej. FFMPEG) opción, p. ej. --block_size=1000 o --profile=Baseline (consulte gpac -h

doc)

El orden de declaración de los filtros puede afectar al resolvedor de enlaces, que intentará enlazar en el orden de declaración. La mayoría de las veces, para grafos simples, esto no tiene impacto. Sin embargo, para grafos complejos sin declaraciones de enlace, esto puede conducir a resultados diferentes.
Las opciones no requieren ningún orden específico y pueden estar presentes en cualquier lugar, incluyendo entre instrucciones de enlace o declaraciones de filtro.
Los valores booleanos no necesitan que se especifique ningún valor. Otros tipos deben formatearse como opt=val, excepto las opciones .I -i, -src, .I -o, -dst y .I

-h.

La sesión puede interrumpirse en cualquier momento usando ctrl+c, que también puede usarse para alternar el informe

global.

the configuration file name (default: GF_GPAC_CONFIG). If the name is a profile name, the default configuration file is created/updated in the GPAC profile directory. Special profile names are:

Using Aliases

The gpac command line can become quite complex when many sources or filters are used. In order to simplify this, an alias system is provided.

To assign an alias, use the syntax gpac -alias="NAME VALUE".
* `NAME`: shall be a single string, with no space.
* `VALUE`: the list of argument this alias replaces. If not set, the alias is destroyed

When parsing arguments, the alias will be replace by its value.
Example
gpac -alias="output aout vout"

This allows later audio and video playback using gpac -i src.mp4 output

Aliases can use arguments from the command line. The allowed syntaxes are:
* `@{a}`: replaced by the value of the argument with index a after the alias
* `@{a,b}`: replaced by the value of the arguments with index a and b
* `@{a:b}`: replaced by the value of the arguments between index a and b
* `@{-a,b}`: replaced by the value of the arguments with index a and b, inserting a list separator (comma by default) between them
* `@{-a:b}`: replaced by the value of the arguments between index a and b, inserting a list separator (comma by default) between them
* `@{+a,b}`: clones the parent word in the alias for a and b, replacing this pattern in each clone by the corresponding argument
* `@{+a:b}`: clones the parent word in the alias for each argument between index a and b, replacing this pattern in each clone by the corresponding argument

The specified index can be:
* forward index: a strictly positive integer, 1 being the first argument after the alias
* backward index: the value 'n' (or 'N') to indicate the last argument on the command line. This can be followed by -x to rewind arguments (e.g. @{n-1} is the before last argument)

Before solving aliases, all option arguments are moved at the beginning of the command line. This implies that alias arguments cannot be options.
Arguments not used by any aliases are kept on the command line, other ones are removed

Example
-alias="foo src=@{N} dst=test.mp4"

The command gpac foo f1 f2 expands to gpac src=f2 dst=test.mp4 f1
Example
-alias="list: inspect src=@{+:N}"

The command gpac list f1 f2 f3 expands to gpac inspect src=f1 src=f2 src=f3
Example
-alias="list inspect src=@{+2:N}"

The command gpac list f1 f2 f3 expands to gpac inspect src=f2 src=f3 f1
Example
-alias="plist aout vout flist:srcs=@{-,N}"

The command gpac plist f1 f2 f3 expands to gpac aout vout flist:srcs="f1,f2,f3"

Alias documentation can be set using gpac -aliasdoc="NAME VALUE", with NAME the alias name and VALUE the documentation.
Alias documentation will then appear in gpac help.

User Credentials

Some servers in GPAC can use user-based and group-based authentication.
The information is stored by default in the file users.cfg located in the GPAC profile directory.
The file can be overwritten using the .I -users option.

GPAC usa un archivo de configuración para modificar las opciones predeterminadas de libgpac y los filtros. Este archivo se llama GPAC.cfg y se encuentra:
- en plataformas Windows, en C:UsersODatar in C:Program FilesGPAC.
- en plataformas iOS, en una carpeta .gpac en el directorio de almacenamiento de la aplicación.
- en plataformas Android, en /sdcard/GPAC/ si este directorio existe, de lo contrario en /data/data/io.gpac.gpac/GPAC.
- en otras plataformas, en $HOME/.

gpac/.

Las aplicaciones en GPAC también pueden especificar un archivo de configuración diferente a través de la opción .I -p profile. EX gpac -p=foo []
Esto cargará la configuración desde $HOME/.gpac/foo/GPAC.cfg, creándolo si es necesario.
El nombre reservado 0 se usa para deshabilitar la escritura del archivo de

configuración.

El archivo de configuración está estructurado en secciones, cada una hecha de una o más claves:
- la sección foo se declara como [foo]
- la clave bar con valor N se declara como bar=N0 El valor de la clave N no se interpreta y siempre se maneja como texto

ASCII.

Por defecto, el archivo de configuración solo contiene algunas opciones y directorios específicos del sistema. Es posible serializar el conjunto completo de opciones en el archivo de configuración, usando .I -wc .I -wf.
Esto debe evitarse, ya que el tamaño del archivo de configuración resultante será bastante grande, lo que implica un mayor uso de memoria para las aplicaciones.
Las opciones especificadas en el archivo de configuración pueden ser anuladas por los valores en el archivo restrict.cfg ubicado en el directorio de sistema de GPAC share (por ejemplo, /usr/share/gpac o C:Program FilesGPAC), si está presente; esto permite hacer cumplir valores de configuración en todo el sistema.

Overview

Los filtros son unidades de procesamiento configurables que consumen y producen paquetes de datos. Estos paquetes se transportan entre filtros a través de un canal de datos llamado PID. Un PID se encarga de asignar/rastrear paquetes de datos y de pasar los paquetes al(los) filtro(s) de destino. Un PID de salida de filtro puede conectarse a cero o más filtros. Este fan-out se gestiona internamente en GPAC (no existe tal cosa como un filtro tee en GPAC).
Nota: Cuando un PID no se puede conectar a ningún filtro, se mostrará una advertencia y todos los paquetes enviados por ese PID se destruirán. Sin embargo, la sesión puede seguir ejecutándose, a menos que se establezca .I -full-link.

Cada PID de salida transporta un conjunto de propiedades que describen los datos que entrega (por ejemplo, ancho, alto, códec, ...). Las propiedades pueden ser incorporadas (ver gpac -h props ) o definidas por el usuario. Cada PID rastrea los cambios de sus propiedades y activa la reconfiguración del filtro durante el procesamiento de paquetes. Esto permite que la cadena de filtros se reconfigure en tiempo de ejecución, recargando potencialmente parte de la cadena (por ejemplo, descargar un decodificador de video al cambiar de fuentes comprimidas a sin comprimir).

Cada filtro expone un conjunto de argumentos para configurarse, utilizando tipos de propiedades y valores descritos como cadenas formateadas con separadores. Esta ayuda se proporciona con los conjuntos de separadores predeterminados :=#,@ para especificar filtros, propiedades y opciones. Usa .I -seps para cambiarlos.

Property and filter option format

* booleano: formateado como yes,true,1 o no,false,0
* enumeración (solo para argumentos de filtro): debe usar la sintaxis dada en la descripción del argumento, de lo contrario el valor 0

Se asume (primero en la enumeración).
* 1-dimensión (números, flotantes, enteros...): formateado como valor[unidad], donde la unidad puede ser k,K (x 1000) o m,M (x 1000000) o g,G (x 1000000000) o sec (x 1000) o min (x 60000). +I significa el valor máximo de float/int/uint, -I el valor mínimo de float/int/uint.
* fracción: formateada como num/den o num-den o num, en cuyo caso el denominador es 1 si num es un entero, o 1000000 si num es un valor de punto flotante.
* entero sin signo de 32 bits: formateado como número o hexadecimal usando el formato 0xAABBCCDD.
* N-dimensión (vectores): formateado como valores DIM1xDIM2[xDIM3[xDIM4]], sin multiplicador de unidad.

Por defecto la cadena de filtros se resolverá sin ninguna decodificación/codificación si el destino acepta el formato deseado. códec

filtros.

Las directivas de enlace, cuando se proporcionan, especifican de qué fuente un filtro puede aceptar conexiones.
No especifican a qué destino un filtro puede

conectarse.

Enlace de filtros por

defecto

Cuando no se dan instrucciones de enlace (ver abajo), la estrategia de enlace por defecto usada es o bien el modo implícito (por defecto en gpac) o el modo completo (si .I -cl está establecido).
Cada PID se comprueba para posible conexión a todos los filtros definidos, en su orden de declaración.
Para cada filtro DST que acepta una conexión del PID, directamente o con filtros intermedios:
- si el filtro DST tiene directivas de enlace, usarlas para permitir o rechazar la conexión del PID.
- de lo contrario, si el modo completo está habilitado, permitir la conexión..
- de lo contrario (modo implícito):
- si DST no es un destino y es el primer filtro coincidente sin directiva de enlace, permitir la conexión.
- de lo contrario, si DST no es un destino y no es el primer filtro coincidente sin directiva de enlace, rechazar la conexión.
- de lo contrario (DST es un destino) y no hay conexiones previas a un filtro que no sea destino, permitir la

conexión.

En todos los modos de enlace, un filtro puede evitar ser enlazado a un filtro sin directivas de enlace estableciendo la opción RSID en el filtro.
Esto se necesita típicamente cuando se insertan/eliminan filtros dinámicamente en una sesión existente donde algunos filtros no tienen ID definido y no son deseados para la cadena

insertada.

Ejemplo
gpac -i file.mp4 c=avc -o

output

Con esta configuración en modo implícito:
- si el archivo tiene un PID de video, se conectará a enc pero no a output. El PID de salida de enc se conectará a output.
- si el archivo tiene otros PIDs además de video, se conectarán a output, ya que este filtro enc solo acepta

video.

Ejemplo
gpac -cl -i file.mp4 c=avc -o

output

Con esta configuración en modo completo:
- si el archivo tiene un PID de video, se conectará tanto a enc como a output, y el PID de salida de enc se conecta con la salida.
- si el archivo tiene otros PIDs que no sean de vídeo, se conectarán a la salida.

Además, en el modo implícito, las conexiones de filtros están restringidas a filtros definidos entre la última fuente y el/los sumidero(s).
Ejemplo
gpac -i video1 reframer:saps=1 -i video2 ffsws:osize=128x72 -o output

Esto conectará:
- video1 a reframer y luego reframer a output, pero evitará la conexión de reframer a ffsws.
- video2 a ffsws y luego ffsws a output, pero evitará la conexión de video2 a reframer.

Ejemplo
gpac -i video1 -i video2 reframer:saps=1 ffsws:osize=128x72 -o output

Esto conectará video1 Y video2 a reframer->ffsws->output

El modo implícito permite especificar cadenas de procesamiento lineales (sin bifurcación de PID excepto para la/s salida/s final/es) sin directivas de enlace, simplificando las líneas de comandos para casos comunes.
Advertencia: ¡El orden de los argumentos es realmente importante en el modo implícito!

Ejemplo
gpac -i file.mp4 c=avc c=aac -o output

Si el archivo tiene un PID de vídeo, se conectará a c=avc pero no a output. El PID de salida de c=avc se conectará a output.
Si el archivo tiene un PID de audio, se conectará a c=aac pero no a output. El PID de salida de c=aac se conectará a output.
Si el archivo tiene otros PIDs que no sean de audio o vídeo, se conectarán a output.

Ejemplo
gpac -i file.mp4 ffswf=osize:128x72 c=avc resample=osr=48k c=aac -o output

Esto forzará:
- SRC(video)->ffsws->enc(video)->output y evitará las conexiones SRC(video)->output, SRC(video)->enc(video) y ffsws->output que ocurrirían en el modo completo.
- SRC(audio)->resample->enc(audio)->output y evitará las conexiones SRC(audio)->output, SRC(audio)->enc(audio) y resample->output que ocurrirían en el modo completo.

Enlaces rápidos

El enlace entre filtros puede especificarse manualmente. La sintaxis es un carácter @ seguido opcionalmente por un entero (0 si se omite).
Esto indica que el siguiente filtro especificado en el prompt debe enlazarse solo con un filtro listado anteriormente.
El entero opcional es un índice basado en 0 para las declaraciones de filtros anteriores, 0 indica la declaración de filtro anterior, 1 la anterior a la declaración anterior, ...).
Si se usa @@ en lugar de @, el entero opcional da el índice del filtro empezando desde el primer filtro (índice 0) especificado en la línea de comandos.
Se pueden dar varias directivas de enlace para un filtro.
Ejemplo
fA fB @1 fC

Esto indica que fC solo acepta entradas de fA.
Ejemplo
fA fB fC @1 @0 fD

Esto indica que fD solo acepta entradas de fB y fC.
Ejemplo
fA fB fC ... @@1 fZ

Esto indica que fZ solo acepta entradas de fB.

Enlaces complejos

La directiva de enlace @ es solo un atajo rápido para establecer los siguientes argumentos de filtro:
* FID=name: asigna un identificador al filtro
* SID=name1[,name2...]: establece una lista de identificadores de filtro, o sourceIDs, restringiendo la lista de entradas posibles para un filtro.

Ejemplo
fA fB @1 fC

Esto es equivalente a fA:FID=1 fB fC:SID=1.
Ejemplo
fA:FID=1 fB fC:SID=1

Esto indica que fC solo acepta entrada de fA, pero fB podría aceptar entradas de fA.
Ejemplo
fA:FID=1 fB:FID=2 fC:SID=1 fD:SID=1,2

Esto indica que fD solo acepta entrada de fA y fB, y fC solo de fA
Nota: Un filtro con sourceID establecido no puede obtener entrada de filtros sin IDs.

Un nombre sourceID puede extenderse aún más usando un identificador de fragmento (# por defecto):
* name#PIDNAME: acepta solo PID(s) con el nombre PIDNAME
* name#TYPE: acepta solo PIDs del tipo de medio coincidente. TYPE puede ser audio, video, scene, text, font, meta
* name#TYPEN: acepta solo el PID N (índice basado en 1) del tipo coincidente de la fuente (por ejemplo, video2 para aceptar solo el segundo PID de vídeo)
* name#TAG=VAL: acepta el PID si su filtro padre no tiene etiqueta o una etiqueta que coincida con VAL
* name#ITAG=VAL: acepta el PID si su filtro padre no tiene etiqueta heredada o una etiqueta heredada que coincida con VAL
* name#P4CC=VAL: acepta solo PIDs con propiedad incorporada de tipo P4CC y valor VAL.
* name#PName=VAL: igual que lo anterior, usando el nombre incorporado correspondiente a la propiedad.
* name#AnyName=VAL: igual que lo anterior, usando el nombre de una propiedad no incorporada.
* name#Name=OtherPropName: compara el valor con el valor de otra propiedad del PID. La coincidencia fallará si el valor a comparar no está presente o es diferente del valor a comprobar. La propiedad con la que comparar debe ser una propiedad incorporada.
Si la propiedad no está definida en el PID, la propiedad coincide. De lo contrario, su valor se comprueba contra el valor dado.

Se permiten los siguientes modificadores para comparaciones (para cualquier formato de fragmento que use =):
* name#P4CC=!VAL: acepta solo PIDs con propiedad que NO coincida con VAL.
* name#P4CC-VAL: acepta solo PIDs con propiedad estrictamente menor que VAL (solo para propiedades numéricas de 1 dimensión).
* name#P4CC+VAL: acepta solo PIDs con propiedad estrictamente mayor que VAL (solo para propiedades numéricas de 1 dimensión).

Un nombre sourceID también puede usar un comodín o estar vacío para coincidir con una propiedad independientemente del filtro fuente.
Ejemplo
fA fB:SID=*#ServiceID=2
fA fB:SID=#ServiceID=2

Esto indica que la conexión entre fA y fB solo coincidirá para PIDs con una propiedad ServiceID de 2.
Estas extensiones también funcionan con el atajo LINK @.
Ejemplo
fA fB @1#video fC

Esto indica que fC solo acepta entradas de fA, y de tipo vídeo.
Ejemplo
gpac -i img.heif @#ItemID=200 vout

Esto indica conectar a vout solo PIDs con la propiedad ItemID igual a 200.
Ejemplo
gpac -i vid.mp4 @#PID=1 vout

Esto indica conectar a vout solo PIDs con la propiedad ID igual a 1.
Ejemplo
gpac -i vid.mp4 @#Width=640 vout

Esto indica conectar a vout solo PIDs con la propiedad Width igual a 640.
Ejemplo
gpac -i vid.mp4 @#Width-640 vout

Esto indica conectar a vout solo PIDs con la propiedad Width menor que 640
Ejemplo
gpac -i vid.mp4 @#ID=ItemID#ItemNumber=1 vout

Esto conectará a vout solo el PID con una propiedad ID igual a la propiedad ItemID (conservar elementos, descartar pistas) y un número de elemento de 1 (primer elemento).

Se pueden especificar múltiples fragmentos para comprobar múltiples propiedades de PID.
Ejemplo
gpac -i vid.mp4 @#Width=640#Height+380 vout

Esto indica conectar a vout solo PIDs con la propiedad Width igual a 640 y Height mayor que 380.

Advertencia: Si un PID se conecta directamente a uno o más filtros cargados explícitamente, no se hará ninguna resolución dinámica de enlace adicional para conectarlo a otros filtros sin sourceID establecido. Las directivas de enlace deben configurarse cuidadosamente.
Ejemplo
fA @ reframer fB

Si fB acepta entradas proporcionadas por fA pero reframer no, esto enlazará el PID de fA al filtro fB ya que fB no tiene sourceID.
Dado que el PID está conectado, el motor de filtros no intentará resolver un enlace entre fA y reframer.

Se hace una excepción para archivos locales: por defecto, un destino de archivo local forzará un remultiplexado de los PIDs de entrada de un archivo local.
Ejemplo
gpac -i file.mp4 -o dump.mp4

Esto evitará la conexión directa del PID de tipo archivo a dst file.mp4, remultiplexando el archivo.

La opción especial nomux se usa para permitir conexiones directas (ignorada para filtros que no son sumidero).
Ejemplo
gpac -i file.mp4 -o dump.mp4:nomux

Esto resultará en una copia directa de archivo.

Esto solo se aplica a destinos de archivos locales. Para tuberías, sockets u otras salidas de archivo (HTTP, ROUTE):
- la copia directa está habilitada por defecto
- se puede usar nomux=0 para forzar el remultiplexado

Etiquetado de subsesiones

Los filtros pueden asignarse a una subsesión usando :FS=N, con N un entero positivo.
Los filtros que pertenecen a diferentes subsesiones solo pueden enlazarse entre sí:
- si se permite explícitamente a través de directivas sourceID (@ o SID)
- o si tienen el mismo identificador de subsesión

Esto se usa principalmente para el modo implícito en gpac: cada primer filtro fuente especificado después de un filtro sumidero activará una nueva subsesión.
Ejemplo
gpac -i in1.mp4 -i in2.mp4 -o out1.mp4 -o out2.mp4

Esto resultará en ambas entradas multiplexadas en ambas salidas.
Ejemplo
gpac -i in1.mp4 -o out1.mp4 -i in2.mp4 -o out2.mp4

Esto resultará en in1 mezclado en out1 e in2 mezclado en out2, estos dos últimos filtros perteneciendo a una subsesión diferente.

Herencia de argumentos

A menos que se deshabilite explícitamente (ver .I -max-chain), el motor de filtros resolverá conexiones implícitas o explícitas (LINK) entre filtros y asignará cualquier cadena de filtros necesaria para conectar los filtros. Al hacerlo, carga nuevos filtros con argumentos heredados tanto de la fuente como del destino.
Ejemplo
gpac -i file.mp4:OPT -o file.aac -o file.264

Esto pasará el :OPT a todos los filtros cargados entre la fuente y los dos destinos.
Ejemplo
gpac -i file.mp4 -o file.aac:OPT -o file.264

Esto pasará el :OPT a todos los filtros cargados entre la fuente y el destino file.aac.
Nota: los argumentos de destino heredados son los argumentos colocados DESPUÉS de la opción dst=.
Ejemplo
gpac -i file.mp4 fout:OPTFOO:dst=file.aac:OPTBAR

Esto pasará el :OPTBAR a todos los filtros cargados entre la fuente file.mp4 y el destino file.aac, pero no OPTFOO.
La herencia de argumentos puede detenerse usando la palabra clave gfloc: los argumentos después de la palabra clave no serán heredados.
Ejemplo
gpac -i file.mp4 -o file.aac:OPTFOO:gfloc:OPTBAR -o file.264

Esto pasará :OPTFOO a todos los filtros cargados entre la fuente file.mp4 y el destino file.aac, pero no OPTBAR
Los argumentos se rastrean por defecto para comprobar si fueron usados por la cadena de filtros, y se lanza una advertencia si no es el caso.
Puede ser útil especificar argumentos que pueden no consumirse dependiendo de la resolución del grafo; la palabra clave específica gfopt indica que los argumentos después de la palabra clave no serán rastreados.
Ejemplo
gpac -i file.mp4 -o file.aac:OPTFOO:gfopt:OPTBAR -o file.264

Esto emitirá una advertencia si OPTFOO no es consumido, pero no rastreará OPTBAR.

A un filtro se le puede asignar un nombre (para fines de inspección, no heredado) usando la opción :N=name. Este nombre no se usa en la resolución de enlaces y puede ser cambiado en tiempo de ejecución por la instancia del filtro.

A un filtro se le puede asignar una etiqueta (cualquier cadena) usando la opción :TAG=name. Esta etiqueta no necesita ser única, y puede usarse para excluir un filtro en la resolución de enlaces. Las etiquetas no se heredan, por lo tanto los filtros cargados dinámicamente nunca tienen una etiqueta.

A un filtro también se le puede asignar una etiqueta heredada (cualquier cadena) usando la opción :ITAG=name. Dichas etiquetas se heredan, y se usan típicamente para rastrear filtros cargados dinámicamente.

Plantilla de URL

Las URL de destino pueden construirse dinámicamente usando plantillas. El patrón $KEYWORD$ se reemplaza en la plantilla con el valor resuelto y $KEYWORD%%0Nd$ se reemplaza en la plantilla con el entero resuelto, relleno con hasta N ceros si es necesario.
KEYWORD distingue entre mayúsculas y minúsculas, y puede estar presente varias veces en la cadena. KEYWORD soportados:
* num: reemplazado por el número de archivo si está definido, 0 en caso contrario
* PID: ID del PID de origen
* URL: URL del archivo de origen
* File: ruta en disco del archivo de origen; si no se encuentra, usa URL si está establecida, o el nombre del PID en caso contrario
* Type: nombre del tipo de flujo del PID (video, audio ...)
* OType: igual que Type pero usa el tipo original cuando el flujo está cifrado (por ejemplo, pasa de crypt a video)
* p4cc=ABCD: usa la propiedad del PID con el valor 4CC ABCD
* pname=VAL: usa la propiedad del PID con el nombre VAL
* cts, dts, dur, sap: usa las propiedades del primer paquete en el PID en el momento de la resolución de la plantilla
* OTHER: localiza la propiedad 4CC para el nombre dado, o el nombre de la propiedad si no hay 4CC que coincida.

$$ es una secuencia de escape para $

La plantilla puede ser útil al codificar varias calidades en una sola pasada.
Ejemplo
gpac -i dump.yuv:size=640x360 vcrop:wnd=0x0x320x180 c=avc:b=1M @2 c=avc:b=750k -o dump_$CropOrigin$x$Width$x$Height$.264

Esto creará una versión recortada de la fuente, codificada en AVC a 1M, y una versión completa del contenido en AVC a 750k. Las salidas serán dump_0x0x320x180.264 para la versión recortada y dump_0x0x640x360.264 para la no recortada.

Clonando filtros

Cuando un filtro acepta una sola conexión y tiene una entrada conectada, ya no está disponible para la resolución dinámica. Puede haber casos en los que este comportamiento no sea deseado. Tome un archivo HEIF con N elementos y haga:
Ejemplo
gpac -i img.heif -o dump_$ItemID$.jpg

En este caso, solo un elemento (probablemente el primero declarado en el archivo) se conectará al destino.
Los otros elementos no se conectarán ya que el destino solo acepta un PID de entrada.
Ejemplo
gpac -i img.heif -o dump_$ItemID$.jpg

En este caso, el destino será clonado para cada elemento, y todos serán exportados a diferentes JPEG gracias a la plantilla de URL.
Ejemplo
gpac -i vid.mpd c=avc:FID=1 -o transcode.mpd:SID=1

En este caso, el codificador será clonado para cada PID de video en la fuente, y el destino solo usará PIDs provenientes de los codificadores.

Cuando el enlace implícito está habilitado, todos los filtros son por defecto clonables. Esto permite duplicar el procesamiento para cada PID del mismo tipo.
Ejemplo
gpac -i dual_audio resample:osr=48k c=aac -o dst

El filtro de remuestreo será clonado para cada PID de audio, y el codificador será clonado para cada salida del remuestreador.
Puede desactivar explícitamente las instrucciones de clonación:
Ejemplo
gpac -i dual_audio resample:osr=48k:clone=0 c=aac -o dst

El primer audio se conectará al filtro de remuestreo, el segundo al filtro de codificación y la salida del remuestreo se conectará a un clon del filtro de codificación.

Plantilla de cadenas de filtros

Puede haber casos en los que el número de salidas deseadas dependa del contenido de la fuente, por ejemplo volcar un multiplex de N servicios en N archivos. Cuando el destino implica multiplexar los PIDs de entrada, la opción :clone no es suficiente ya que el multiplexor siempre aceptará los PIDs de entrada.
Para manejar esto, es posible usar un nombre de propiedad de PID en el sourceID de un filtro con el valor * o un valor vacío. En este caso, siempre que se encuentre un nuevo PID con un nuevo valor para la propiedad, el filtro con dicho sourceID será clonado dinámicamente.
Advertencia: Esta función solo debe ser llamada con una única propiedad establecida a * (o vacía) por ID de origen; los resultados son indefinidos en caso contrario.
Ejemplo
gpac -i source.ts -o file_$ServiceID$.mp4:SID=*#ServiceID=*
gpac -i source.ts -o file_$ServiceID$.mp4:SID=#ServiceID=

En este caso, cada nuevo valor de ServiceID encontrado al conectar PIDs al destino creará un nuevo archivo de destino.

La clonación en modo de enlace implícito se aplica también a la salida:
Ejemplo
gpac -i dual_audio -o dst_$PID$.aac

Cada pista de audio será volcada a aac (potencialmente recodificando si es necesario).

Asignando propiedades de PID

Es posible definir propiedades en PIDs de salida que serán declaradas por un filtro. Esto permite etiquetar partes del grafo con diferentes propiedades que otras partes (por ejemplo ServiceID). La sintaxis es la misma que la de las opciones de filtro, y usa el separador de fragmento para identificar propiedades, por ejemplo #Name=Value.
Esto establece la propiedad del PID de salida (4cc, nombre incorporado o cualquier nombre) al valor dado. El valor puede omitirse para booleanos (por defecto true, por ejemplo :#Alpha).
Las propiedades no incorporadas se analizan de la siguiente manera:
- file@FOO se declarará como cadena con un valor establecido al contenido de FOO.
- bxml@FOO se declarará como datos con un valor establecido al contenido binarizado de FOO.
- FOO se declarará como cadena con un valor establecido a FOO.
- TYPE@FOO se analizará de acuerdo con TYPE. Si el tipo no se reconoce, el valor completo se copia como cadena. Vea gpac -h props para los tipos definidos.

Las propiedades de PID asignadas por el usuario en el filtro fA serán heredadas por todos los filtros cargados dinámicamente para resolver la conexión fA -> fB.
Si fB también tiene propiedades de PID asignadas por el usuario, estas solo se aplican a partir de fB en la cadena y no son heredadas por los filtros entre fA y fB.

Advertencia: Las propiedades no se filtran y anulan las propiedades de los PIDs de salida del filtro, tenga cuidado de no romper la sesión anulando propiedades fundamentales como width/height/samplerate/... !
Ejemplo
gpac -i v1.mp4:#ServiceID=4 -i v2.mp4:#ServiceID=2 -o dump.ts

Esto multiplexará los flujos en dump.ts, usando ServiceID 4 para los PIDs de v1.mp4 y ServiceID 2 para los PIDs de v2.mp4.

Las propiedades de PID pueden asignarse condicionalmente verificando otras propiedades de PID. La sintaxis usa paréntesis (no configurables) después del signo de asignación de la propiedad:
#Prop=(CP=CV)VAL
Esto asignará la propiedad de PID Prop a VAL para PIDs con propiedad CP igual a CV.
#Prop=(CP=CV)VAL,(CP2=CV2)VAL2
Esto asignará la propiedad de PID Prop a VAL para PIDs con propiedad CP igual a CV, y a VAL2 para PIDs con propiedad CP2 igual a CV2.
#Prop=(CP=CV)(CP2=CV2)VAL
Esto asignará la propiedad de PID Prop a VAL para PIDs con propiedad CP igual a CV y propiedad CP2 igual a CV2.
#Prop=(CP=CV)VAL,()DEFAULT
Esto asignará la propiedad de PID Prop a VAL para PIDs con propiedad CP igual a CV, o a DEFAULT para otros PIDs.
La sintaxis de la condición es la misma que la sintaxis del fragmento de ID de origen.
Nota: Cuando se establece, el valor por defecto (condición vacía) siempre coincide con el PID, por lo tanto debe colocarse al final de la lista de condiciones.
Ejemplo
gpac -i source.mp4:#MyProp=(audio)"Super Audio",(video)"Super Video"

Esto asignará la propiedad MyProp a Super Audio para PIDs de audio y a Super Video para PIDs de video.
Ejemplo
gpac -i source.mp4:#MyProp=(audio1)"Super Audio"

Esto asignará la propiedad MyProp a Super Audio para el primer PID de audio declarado.
Ejemplo
gpac -i source.mp4:#MyProp=(Width+1280)HD

Esto asignará la propiedad MyProp a HD para PIDs con propiedad Width mayor que 1280.

El valor de la propiedad puede usar plantillas con las siguientes palabras clave:
* $GINC(init[,inc]) o @GINC(...): reemplazado por un entero para cada nuevo PID de salida del filtro (vea las opciones específicas del filtro para detalles sobre la sintaxis)
* PROP (encerrado entre `$` o `@`): reemplazado por el valor serializado de la propiedad PROP (nombre o 4CC) del PID o con cadena vacía si no existe dicha propiedad
Ejemplo
gpac -i source.ts:#ASID=$PID$

Esto asignará el ID del AdaptationSet de DASH al valor del ID del PID.
Ejemplo
gpac -i source.ts:#RepresentationID=$ServiceID$

Esto asignará el ID de Representación de DASH al valor del ServiceID del PID.

Usando archivos de opciones

Es posible usar un archivo para definir opciones de un filtro, especificando el nombre del archivo de destino como una opción sin valor, es decir :myopts.txt.
Advertencia: Solo se permiten archivos locales.
Un archivo de opciones es un archivo de texto simple que contiene una o más opciones o propiedades de PID en una o más líneas.
- Una línea que comienza con "//" es un comentario y se ignora (no configurable).
- Una línea que comienza con ":" indica una opción escapada (la línea completa se analiza como una sola opción).
Las opciones en un archivo de opciones pueden apuntar a otros archivos de opciones, con un máximo de 5 niveles de redirección.
Una declaración de archivo de opciones (filter:myopts.txt) sigue las mismas reglas de herencia que las opciones regulares.
Ejemplo
gpac -i source.mp4:myopts.txt:foo=bar -o dst

Cualquier filtro cargado entre source.mp4 y dst heredará tanto las opciones myopts.txt como foo y resolverá las opciones y propiedades de PID dadas en myopts.txt.

Ignorando filtros en tiempo de ejecución

La opción especial ccp puede usarse para reemplazar filtros con un filtro de identidad en tiempo de ejecución basado en el ID del códec de entrada.
La opción es una lista de IDs de códec a verificar. Para filtros de codificación, una lista vacía reutiliza el tipo de códec del codificador.
Cuando el ID del códec del PID coincide con uno de los códecs especificados, el filtro es reemplazado con un filtro de reencuadre con entrada de PID único y mismo nombre e ID. > Ejemplo
-i src c=avc:b=1m:ccp -o mux

Esto reemplazará el filtro codificador con un reframer si el PID de entrada tiene formato AVC|H264, o usará el codificador para otros PID visuales.
Ejemplo
-i src c=avc:b=1m:ccp=avc,hevc -o mux

Esto reemplazará el filtro codificador con un reframer si el PID de entrada tiene formato AVC|H264 o HEVC, o usará el codificador para otros PID visuales.
Ejemplo
-i src cecrypt:cfile=drm.xml:ccp=aac -o mux

Esto reemplazará el filtro encriptador con un reframer si el PID de entrada tiene formato AAC, o usará el encriptador para otros PID.

Opciones específicas de filtros

Algunas palabras clave específicas se reemplazan al procesar las opciones de filtro.
Advertencia: Estas palabras clave no se aplican a las propiedades de PID. No se pueden definir múltiples palabras clave para una sola opción.
Palabras clave definidas:
* $GSHARE: reemplazado por la ruta del sistema al directorio compartido de GPAC (por ejemplo, /usr/share/gpac)
* $GJS: reemplazado por la primera ruta del directorio de recursos globales y las rutas establecidas a través de .I -js-dirs que contiene el nombre de archivo que sigue a la macro, por ejemplo, $GJS/source.js
* $GDOCS: reemplazado por la ruta del sistema a:
- directorio de documentos de la aplicación para iOS
- la variable de entorno EXTERNAL_STORAGE si está presente o /sdcard en caso contrario para Android
- el directorio de inicio del usuario para otras plataformas
* $GLANG: reemplazado por la opción de configuración global de idioma .I -lang
* $GUA: reemplazado por la opción de configuración global de agente de usuario .I -user-agent
* $GINC(init_val[,inc]): reemplazado por init_val y se incrementa init_val en inc (número positivo o negativo, 1 si no se especifica) cada vez que se crea un nuevo filtro que utiliza esta cadena.

El constructo $GINC se puede usar para asignar dinámicamente números en cadenas de filtros:
Ejemplo
gpac -i source.ts tssplit @#ServiceID= -o dump_$GINC(10,2).ts

Esto volcará el primer servicio en dump_10.ts, el segundo servicio en dump_12.ts, etc...
Como se vio anteriormente, las siguientes opciones se pueden establecer en cualquier filtro, pero no son visibles en la ayuda individual del filtro:
* FID: identificador de filtro
* SID: origen(es) del filtro (valor de cadena)
* N=NAME: nombre del filtro (valor de cadena)
* FS: identificador de sub-sesión (valor entero sin signo)
* RSID: requiere que el sourceID esté presente en los filtros de destino (sin valor)
* TAG: etiqueta del filtro (valor de cadena)
* ITAG: etiqueta heredada del filtro (valor de cadena)
* FBT: tiempo de búfer en microsegundos (valor entero sin signo)
* FBU: unidades de búfer (valor entero sin signo)
* FBD: tiempo de búfer de decodificación en microsegundos (valor entero sin signo)
* clone: habilita/deshabilita explícitamente la bandera de clonación del filtro (sin valor)
* nomux: habilita/deshabilita la copia directa de archivos (sin valor)
* gfreg: nombres preferidos del registro de filtros para la resolución de enlaces (valor de cadena)
* gfloc: las siguientes opciones son locales a la declaración del filtro, no se heredan (sin valor)
* gfopt: las siguientes opciones no se rastrean (sin valor)
* gpac: separador de argumentos para URL (sin valor)
* ccp: control de reemplazo de filtro (valor de lista de cadenas)
* NCID: ID de la configuración de netcap a utilizar (cadena)
* LT: establece herramientas y niveles de registro adicionales para el filtro utilizando la misma sintaxis que -logs, por ejemplo: LT=filter@debug (valor de cadena)
* DBG: depura la propiedad de PID de entrada faltante (=pid), la propiedad de paquete de entrada faltante (=pck) o ambas (=all)

Las opciones de control de búfer se utilizan para cambiar el búfer predeterminado de los PID de un filtro:
- FBT controla el tiempo máximo de búfer de los PID de salida de un filtro
- FBU controla el número máximo de paquetes en el búfer de los PID de salida de un filtro cuando no hay información de tiempo disponible
- FBD controla el tiempo máximo de búfer de los PID de entrada de un filtro decodificador, ignorado para otros filtros

Si otro filtro envía mensajes de requisito de búfer, se utilizará el valor máximo de FBT (resp. FBD) y el tiempo de búfer solicitado por el usuario para el tiempo de búfer de salida (resp. tiempo de búfer de decodificación).
Las opciones FBT, FBU, FBD y DBG se pueden establecer:
* por instancia de filtro: fA reframer:FBU=2
* por clase de filtro para la ejecución: --reframer@FBU=2
* en el archivo de configuración de GPAC en una sección por filtro: [filter@reframer]FBU=2

Los valores predeterminados están definidos por los parámetros predeterminados de la sesión -buffer-gen, buffer-units y -buffer-dec.

Filtros externos

GPAC viene con un conjunto de filtros integrados en libgpac. También puede cargar filtros externos en bibliotecas dinámicas, ubicadas en la carpeta de módulos predeterminada o en las carpetas listadas en la opción .I -mod-dirs. Los archivos deben llamarse gf_* y exportar una única función RegisterFilter que devuelva un registro de filtros. Consulte la documentación de libgpac para obtener más detalles.
