GPROFNG-COLLECT-APP(1) Comandos de usuario GPROFNG-COLLECT-APP(1)

NOMBRE

gprofng-collect-app - Recopilar datos de rendimiento para la aplicación de destino

SINOPSIS

gprofng collect app [opción(es)] objetivo [opción(es)-objetivo]

DESCRIPCIÓN

Recopila datos de rendimiento en el programa de destino. Además del muestreo del Contador de Programa (PC), se admiten contadores de eventos de hardware y varias opciones de rastreo.

Por ejemplo, este comando recopila datos de rendimiento para un ejecutable llamado a.out y almacena los datos recopilados en un directorio de experimento con el nombre example.er.

$ gprofng collect app -o example.er ./a.out

OPCIONES

--version
Imprime el número de versión y sale.
--help
Imprime información de uso y sale.
-v, --verbose
Por defecto, el modo detallado está deshabilitado. Esta opción lo habilita.
-p {off | on | lo[w] | hi[gh] | <valor>}
Deshabilita (off) o habilita (on) el perfilado de reloj usando una granularidad de muestreo predeterminada, o habilita el perfilado de reloj implícitamente estableciendo la granularidad de muestreo (lo[w], hi[gh], o un valor específico en ms). Por defecto, el perfilado de reloj está habilitado (-p on).
-h <ctr_def>[,<ctr_def>]
Habilita el perfilado de contadores de eventos de hardware y selecciona uno o más contadores. Para ver los contadores admitidos en este sistema, use la opción -h sin otros argumentos.
-o <nombre_exp>
Especifica el nombre para el directorio de experimento. El nombre debe terminar en .er y puede contener una ruta absoluta (por ejemplo, /tmp/experiment.er). Un experimento existente con el mismo nombre no será sobrescrito.
-O <nombre_exp>
Esto es lo mismo que la opción -o, pero a diferencia de esta opción, sobrescribe silenciosamente un directorio de experimento existente con el mismo nombre.
-C <cadena_comentario>
Agrega hasta 10 cadenas de comentarios al experimento. Estos comentarios aparecen en la sección de notas de la cabecera y pueden recuperarse con el comando gprofng display text usando la opción -header.
-j {on | off | <ruta>}
Controla el perfilado de Java cuando el objetivo es una máquina JVM. Los valores permitidos para esta opción son:
on
Registra datos de perfilado para la máquina JVM y reconoce métodos compilados por la máquina virtual Java HotSpot. También registra pilas de llamadas Java.
off
No registra datos de perfilado de Java. Los datos de perfilado para pilas de llamadas nativas todavía se registran.
<ruta>
Registra datos de perfilado para la JVM y utiliza la JVM instalada en <ruta>.

El valor predeterminado es -j on.

-J <jvm-option(s)>
Especifica una o más opciones adicionales que se pasarán a la JVM utilizada. La lista de jvm-option(s) debe ir entre comillas si contiene más de una opción. Los elementos de la lista deben estar separados por espacios o tabulaciones. Cada elemento se pasa como una opción separada a la JVM. Tenga en cuenta que esta opción implica -j on.
-t <duracion>[m|s]
Recopila datos durante la duración especificada. La duración puede ser un número único, seguido opcionalmente por m para especificar minutos, o s para especificar segundos, que es el valor predeterminado.

La duración también puede constar de dos números separados por un guion (-). Si se da un solo número, los datos se recopilan desde el inicio de la ejecución hasta el tiempo dado. Si se dan dos números, los datos se recopilan desde el primer tiempo hasta el segundo. En caso de que el segundo tiempo sea cero, los datos se recopilan hasta el final de la ejecución. Si se dan dos números no cero, el primero debe ser menor que el segundo.

-n
Esto se utiliza para una ejecución de prueba (dry run). Se muestran varias configuraciones de tiempo de ejecución, pero el objetivo no se ejecuta y no se recopilan datos de rendimiento.
-F {off|on|=regex}
Controla si los procesos descendientes deben registrar sus datos. Para deshabilitar/habilitar esta función, use off/on. Use =regex para registrar datos en aquellos procesos cuyos nombres de ejecutables coincidan con la expresión regular. Solo se usa el nombre base del ejecutable, no la ruta completa. Si se usan espacios o caracteres interpretados por el shell, encierre la regex entre comillas simples. El valor predeterminado es -F on.
-a {off|on|ldobjects|src|usedldobjects|usedsrc}
Especifica el archivado de binarios y otros archivos. Además de deshabilitar esta función (off), o habilitar el archivado de todos los objetos de carga y fuentes (on), las otras opciones admiten una selección más refinada.

Todas estas opciones habilitan el archivado, pero la palabra clave controla qué se selecciona exactamente: todos los objetos de carga (ldobjects), todos los archivos fuente (src), los objetos de carga asociados con un contador de programa (usedldobjects), o los archivos fuente asociados con un contador de programa (usedsrc). El valor predeterminado es -a ldobjects.

-S {off|on|<segundos>}
Deshabilita (off), o habilita (on) el muestreo periódico de la utilización de recursos de todo el proceso. Por defecto, el muestreo se realiza cada segundo. Use la opción <segundos> para cambiar esto. El valor predeterminado es -S on.
-y <señal>[,r]
Controla el registro de datos con la señal llamada <señal>, denominada señal de pausa-reanudación. Cada vez que se entrega la señal dada al proceso, se alterna entre los estados de pausa (no se registran datos) y reanudado (se registran datos).

Por defecto, la recopilación de datos comienza en el estado de pausa. Si se proporciona la r opcional, la recopilación de datos comienza en el estado de reanudación y la recopilación de datos comienza inmediatamente.

Se recomiendan SIGUSR1 o SIGUSR2 para este uso, pero se puede usar cualquier señal que no sea utilizada por el objetivo.

-l <señal>
Especifica una señal que activará una muestra de la utilización de recursos de todo el proceso. Cuando se entrega la señal nombrada <señal> al proceso, se registra una muestra.

La señal se puede especificar usando el nombre completo, sin las letras iniciales "SIG", o el número de señal. Tenga en cuenta que el comando kill se puede usar para entregar una señal.

Si se usan las opciones -l y -y, la señal debe ser diferente.

-s <opcion>[,<API>]
Habilita el rastreo de espera de sincronización, donde <opcion> se utiliza para definir los detalles del rastreo (on, off, <umbral>, o all). La API se selecciona a través de la configuración de <API>: n selecciona nativo/Pthreads, j selecciona Java y nj selecciona ambos. El valor predeterminado es -s off.
-H {off|on}
Deshabilita (off), o habilita (on) el rastreo de montón (heap). El valor predeterminado es -H off.
-i {off|on}
Deshabilita (off), o habilita (on) el rastreo de E/S. El valor predeterminado es -i off.

NOTAS

Cualquier ejecutable en formato de objeto ELF (Executable and Linkable Format) puede ser utilizado para el perfilado con gprofng. Si hay información de depuración disponible, gprofng puede proporcionar más detalles, pero esto no es un requisito.
