DESCRIPCIÓ

N

gpg es la parte OpenPGP de GNU Privacy Guard (GnuPG). Es una herramienta para proporcionar servicios de cifrado y firma digital utilizando el estándar OpenPGP. gpg cuenta con una gestión de claves completa y todas las funcionalidades que se esperan de una implementación completa de

OpenPGP.

Existen dos versiones principales de GnuPG: GnuPG 1.x y GnuPG 2.x. GnuPG 2.x admite algoritmos de cifrado modernos y por lo tanto debería preferirse sobre GnuPG 1.x. Solo necesita usar GnuPG 1.x si su plataforma no admite GnuPG 2.x, o si necesita soporte para algunas funcionalidades que GnuPG 2.x ha obsoleto, por ejemplo, descifrar datos creados con claves

PGP-2.

Si está buscando la versión 1 de GnuPG, puede encontrar que esa versión está instalada bajo el nombre gp

g1
.

ADVERTENCIA

S

Use una buena contraseña para su cuenta de usuario y asegúrese de que todos los problemas de seguridad se corrijan siempre en su máquina. También emplee una protección física diligente en su máquina. Considere usar una buena frase de contraseña como protección de último recurso para su clave secreta en caso de que su máquina sea robada. Es importante que su clave secreta nunca se filtre. Usar un token fácil de transportar o una tarjeta inteligente con la clave secreta es a menudo

aconsejable.

Si va a verificar firmas separadas, asegúrese de que el programa lo sepa; ya sea que proporcione ambos nombres de archivo en la línea de comandos o use ‘-’ para especificar

STDIN.

Para uso en scripts u otro uso no supervisado de gpg, asegúrese de usar la interfaz analizable por máquina y no la interfaz predeterminada que está destinada al uso directo por humanos. La interfaz analizable por máquina proporciona una API estable y bien documentada independiente de la configuración regional o cambios futuros de gpg. Para habilitar esta interfaz use las opciones --with-colons y --status-fd. Para ciertas operaciones la opción --command-fd también puede ser útil. Vea esta página man y el archivo ‘DETAILS’ para la especificación de la interfaz. Tenga en cuenta que las páginas ``info'' de GnuPG, así como la versión PDF del manual de GnuPG incluyen un capítulo sobre el uso no supervisado de GnuPG. Como alternativa, la biblioteca GPGME puede usarse como una abstracció

n de alto nivel sobr

INTEROPERABILIDA

D

GnuPG intenta ser una implementación muy flexible del estándar OpenPGP. En particular, GnuPG implementa muchas de las partes opcionales del estándar, como el hash SHA-512 y los algoritmos de compresión ZLIB y BZIP2. Es importante ser consciente de que no todos los programas OpenPGP implementan estos algoritmos opcionales y que al forzar su uso a través de las opciones --cipher-algo, --digest-algo, --cert-digest-algo, o --compress-algo en GnuPG, es posible crear un mensaje OpenPGP perfectamente válido, pero que no puede ser leído por el destinatario

previsto.

Existen docenas de variaciones de programas OpenPGP disponibles, y cada uno admite un subconjunto ligeramente diferente de estos algoritmos opcionales. Por ejemplo, hasta hace poco, ninguna versión (sin modificar) de PGP admitía el algoritmo de cifrado BLOWFISH. Un mensaje que usara BLOWFISH simplemente no podía ser leído por un usuario de PGP. De forma predeterminada, GnuPG usa el sistema de preferencias estándar de OpenPGP que siempre hará lo correcto y creará mensajes que sean utilizables por todos los destinatarios, independientemente de qué programa OpenPGP usen. Solo anule esta configuración segura predeterminada si realmente sabe lo que está

haciendo.

Si absolutamente debe anular la configuración segura predeterminada, o si las preferencias en una clave dada son inválidas por alguna razón, estará mucho mejor usando las opciones --pgp6, --pgp7, o --pgp8. Estas opciones son seguras ya que no fuerzan algoritmos particulares en violación

de OpenPGP, sino que reducen los algoritmos
disponibles a una lista "segura para PGP".

Asume que el primer argumento es un archivo firmado y lo verifica sin generar ninguna salida. Sin argumentos, el paquete de firma se lee de STDIN. Si solo se da un argumento, se espera que el archivo especificado incluya una firma completa.

Si necesita actualizar una firma existente, por ejemplo, para añadir o cambiar datos de notación, debe utilizar la opción --force-sign-key.

Este comando utiliza valores predeterminados razonables y, por lo tanto, no proporciona la flexibilidad total del subcomando "sign" de --edit-key. Su uso previsto es ayudar a la firma de claves desatendida utilizando una lista de huellas digitales verificadas.

--quick-add-uid user-id new-user-id
Este comando añade un nuevo ID de usuario a una clave existente. A diferencia del subcomando interactivo adduid de --edit-key, el new-user-id se añade textualmente, eliminando solo los espacios en blanco iniciales y finales, se espera que esté codificado en UTF-8 y no se aplican comprobaciones sobre su formato.
--quick-revoke-uid user-id user-id-to-revoke
Este comando revoca un ID de usuario en una clave existente. No se puede utilizar para revocar el último ID de usuario de una clave (debe quedar algún ID de usuario no revocado), con el motivo de revocación "User ID is no longer valid". Si desea especificar un motivo de revocación diferente, o proporcionar texto adicional de revocación, debe utilizar el subcomando interactivo revuid de --edit-key.
--quick-revoke-sig fpr signing-fpr [nombres]
Este comando revoca las firmas de clave realizadas por signing-fpr de la clave especificada por la huella digital fpr. Si se proporcionan nombres, solo se ven afectadas las firmas en IDs de usuario de la clave que coincidan con alguno de los nombres dados (ver --quick-sign-key). Si ya existe una revocación, se imprime un aviso en lugar de crear una nueva revocación; en este caso no se devuelve ningún error. Tenga en cuenta que las revocaciones de firmas de clave pueden ser sustituidas por una firma de clave más reciente y, a su vez, revocadas nuevamente.
--quick-set-primary-uid user-id primary-user-id
Este comando establece o actualiza la marca de ID de usuario principal en una clave existente. user-id especifica la clave y primary-user-id el ID de usuario que se marcará como ID de usuario principal. La marca de ID de usuario principal se elimina de todos los demás IDs de usuario y la marca de tiempo de todas las autofirmas afectadas se establece un segundo adelante.
--quick-update-pref user-id
Este comando actualiza la lista de preferencias de la clave al valor predeterminado actual (ya sea incorporado o establecido a través de --default-preference-list). Esta es la versión desatendida de usar "setpref" en el menú --key-edit sin proporcionar una lista. Tenga en cuenta que puede mostrar las preferencias en una lista de claves utilizando --list-options show-pref o --list-options show-pref-verbose. También debe redistribuir las claves actualizadas a sus compañeros.
--quick-set-ownertrust user-id valor
Este comando establece la confianza del propietario de una clave y también puede utilizarse para establecer la marca de inhabilitación de una clave. Esta es la versión desatendida de usar "trust", "disable" o "enable" en el menú --key-edit.
--change-passphrase user-id
--passwd user-id
Cambia la frase de contraseña de la clave secreta que pertenece al certificado especificado como user-id. Este es un atajo para el subcomando passwd del menú --edit-key. Cuando se usa junto con la opción --dry-run, no cambiará realmente la frase de contraseña, pero verificará que la frase de contraseña actual es correcta.

OPCIONES

gpg presenta una serie de opciones para controlar el comportamiento exacto y modificar la configuración predeterminada.

Las opciones largas se pueden incluir en un archivo de opciones (por defecto "~/.gnupg/gpg.conf"). Los nombres de opciones cortas no funcionarán; por ejemplo, "armor" es una opción válida para el archivo de opciones, mientras que "a" no lo es. No escriba los dos guiones, sino simplemente el nombre de la opción y los argumentos requeridos. Las líneas que comienzan con un hash ('#') como primer carácter que no sea espacio en blanco se ignoran. Los comandos también se pueden incluir en este archivo, pero generalmente no es útil ya que el comando se ejecutará automáticamente con cada ejecución de gpg.

Recuerde que el análisis de opciones se detiene tan pronto como se encuentra un elemento que no es una opción; puede detener explícitamente el análisis utilizando la opción especial --.

Cómo cambiar la configuración

 

Estas opciones se utilizan para cambiar la configuración y la mayoría de ellas se encuentran normalmente en el archivo de opciones.

--default-key nombre
Utiliza nombre como clave predeterminada para firmar. Se sugiere utilizar una huella digital o al menos un ID de clave largo para nombre. Si esta opción no se utiliza, la clave predeterminada es la primera clave encontrada en el llavero secreto. Tenga en cuenta que -u o --local-user anulan esta opción. Esta opción se puede especificar varias veces. En este caso, se utiliza la última clave para la cual hay una clave secreta disponible. Si no hay una clave secreta disponible para ninguno de los valores especificados, GnuPG no emitirá un mensaje de error, sino que continuará como si esta opción no se hubiera proporcionado.
--default-recipient nombre
Utiliza nombre como destinatario predeterminado si la opción --recipient no se utiliza y no pregunta si es válido. nombre debe ser no vacío y se sugiere utilizar una huella digital para nombre.
--default-recipient-self
Utiliza la clave predeterminada como destinatario predeterminado si la opción --recipient no se utiliza y no pregunta si es válida. La clave predeterminada es la primera del llavero secreto o la establecida con --default-key.
--no-default-recipient
Restablece --default-recipient y --default-recipient-self. No debe utilizarse en un archivo de opciones.
-v, --verbose
Proporciona más información durante el procesamiento. Si se utiliza dos veces, los datos de entrada se enumeran en detalle.
--no-verbose
Restablece el nivel de detalle a 0. No debe utilizarse en un archivo de opciones.
-q, --quiet
Intenta ser lo más discreto posible. No debe utilizarse en un archivo de opciones.
--batch
--no-batch
Utiliza el modo batch. Nunca pregunta, no permite comandos interactivos. --no-batch deshabilita esta opción. Tenga en cuenta que incluso con un nombre de archivo proporcionado en la línea de comandos, gpg puede necesitar leer desde STDIN (en particular si gpg determina que la entrada es una firma separada y no se ha especificado ningún archivo de datos). Por lo tanto, si no desea alimentar datos a través de STDIN, debe conectar STDIN a '/dev/null'.

Se recomienda encarecidamente utilizar esta opción junto con las opciones --status-fd y --with-colons para cualquier uso desatendido de gpg. No debe utilizarse en un archivo de opciones.

--no-tty
Asegura que la TTY (terminal) nunca se utiliza para ninguna salida. Esta opción es necesaria en algunos casos porque GnuPG a veces imprime advertencias en la TTY incluso si se utiliza --batch.
--yes
Asume "sí" en la mayoría de las preguntas. No debe utilizarse en un archivo de opciones.
--no
Asume "no" en la mayoría de las preguntas. No debe utilizarse en un archivo de opciones.
--proc-all-sigs
Esta opción anula el comportamiento de la opción --batch de detener la verificación de firmas en la primera firma incorrecta.
--list-filter {select=expr}
Se puede utilizar un filtro de lista para mostrar solo claves específicas durante los comandos de listado de claves. Para ver los nombres de propiedad disponibles, consulte la descripción de --import-filter.
--list-options parámetros
Esta es una cadena delimitada por espacios o comas que proporciona opciones utilizadas al listar claves y firmas (es decir, --list-keys, --check-si firmas, --list-public-keys, --list-secret-keys, y las funciones --edit-key ). Las opciones pueden precederse con no- (después de los dos guiones) para dar el significado opuesto. Las opciones son:
show-photos
Hace que --list-keys, --check-signatures, --list-public-keys, y --list-secret-keys muestren cualquier ID de foto adjunto a la clave. Por defecto es no. Véase también --photo-viewer. No funciona con --with-colons: véase --attribute-fd para la forma adecuada de obtener datos de fotos para scripts y otros frontends.
show-usage
Muestra información de uso para claves y subclaves en el listado estándar de claves. Esta es una lista de letras que indican el uso permitido para una clave (E=cifrado, S=firma, C=certificación, A=autenticación). Por defecto es sí.
show-ownertrust
Muestra el valor de confianza del propietario para las claves también en el listado estándar de claves. Por defecto es no.
show-policy-urls
Muestra las URL de política en los listados --check-signatures . Por defecto es no.
show-notations
show-std-notations
show-user-notations
Muestra todas las notaciones de firma, las estándar de IETF o las definidas por el usuario en los listados --check-signatures . Por defecto es no.
show-keyserver-urls
Muestra cualquier URL de servidor de claves preferida en los listados --check-signatures . Por defecto es no.
show-uid-validity
Muestra la validez calculada de los ID de usuario durante los listados de claves. Por defecto es sí.
show-unusable-uids
Muestra los ID de usuario revocados y caducados en los listados de claves. Por defecto es no.
show-unusable-subkeys
Muestra las subclaves revocadas y caducadas en los listados de claves. Por defecto es no.
show-unusable-sigs
Muestra firmas de clave hechas usando algoritmos débiles o no soportados.
show-keyring
Muestra el nombre del llavero al principio de los listados de claves para mostrar en qué llavero reside una clave determinada. Por defecto es no.
show-sig-expire
Muestra las fechas de caducidad de las firmas (si las hay) durante los listados --check-signatures . Por defecto es no.
show-sig-subpackets
Incluye subpaquetes de firma en el listado de claves. Esta opción puede tomar una lista opcional de argumentos de los subpaquetes a listar. Si no se pasa ningún argumento, se listan todos los subpaquetes. Por defecto es no. Esta opción solo es significativa cuando se usa --with-colons junto con --check-signatures.
show-only-fpr-mbox
Para cada ID de usuario que tenga una dirección de correo válida, imprime solo la huella digital seguida de la dirección de correo.
sort-sigs
Con --list-sigs y --check-sigs ordena las firmas por ID de clave y hora de creación para facilitar la visualización del historial de estas firmas. La autofirma también se lista antes que otras firmas. Por defecto es sí. Esta opción no tiene efecto en el modo -with-colons .
--verify-options parámetros
Esta es una cadena delimitada por espacios o comas que da las opciones usadas al verificar firmas. Las opciones pueden precederse con `no-' para dar el significado opuesto. Las opciones son:
show-photos
Muestra cualquier ID de foto presente en la clave que emitió la firma. Por defecto es no. Véase también --photo-viewer.
show-policy-urls
Muestra las URL de política en la firma que se está verificando. Por defecto es sí.
show-notations
show-std-notations
show-user-notations
Muestra todas las notaciones de firma, las estándar de IETF o las definidas por el usuario en la firma que se está verificando. Por defecto es estándar de IETF.
show-keyserver-urls
Muestra cualquier URL de servidor de claves preferida en la firma que se está verificando. Por defecto es sí.
show-uid-validity
Muestra la validez calculada de los ID de usuario en la clave que emitió la firma. Por defecto es sí.
show-unusable-uids
Muestra los ID de usuario revocados y caducados durante la verificación de firmas. Por defecto es no.
show-primary-uid-only
Muestra solo el ID de usuario primario durante la verificación de firmas. Es decir, todas las líneas AKA así como los ID de fotos no se muestran con el estado de verificación de la firma.
--enable-large-rsa
--disable-large-rsa
Permite la creación de claves secretas RSA de hasta 8192 bits. Nota: 8192 bits es más de lo generalmente recomendado. Estas claves grandes no mejoran significativamente la seguridad, pero son más costosas de usar, y sus firmas y certificaciones son más grandes. Esta opción solo está disponible si el binario se compiló con soporte large-secmem.
--enable-dsa2
--disable-dsa2
Permite el truncamiento de hash para todas las claves DSA, incluso para claves DSA antiguas de hasta 1024 bits. Este es también el valor por defecto con --openpgp. Nótese que versiones más antiguas de GnuPG también requerían este indicador para permitir la generación de DSA mayores de 1024 bits.
--photo-viewer cadena
Esta es la línea de comandos que debe ejecutarse para ver un ID de foto. "%i" se expandirá a un nombre de archivo que contiene la foto. "%I" hace lo mismo, excepto que el archivo no se borrará una vez que el visor salga. Otros indicadores son "%k" para el ID de la clave, "%K" para el ID largo de la clave, "%f" para la huella digital de la clave, "%t" para la extensión del tipo de imagen (p. ej. "jpg"), "%T" para el tipo MIME de la imagen (p. ej. "image/jpeg"), "%v" para la validez calculada de un solo carácter de la imagen que se está viendo (p. ej. "f"), "%V" para la validez calculada como cadena (p. ej. "full"), "%U" para un hash del ID de usuario codificado en base32, y "%%" para un signo de porcentaje real. Si no están presentes ni %i ni %I, la foto se suministrará al visor en la entrada estándar.

En Unix el visor por defecto es xloadimage -fork -quiet -title 'KeyID 0x%k' STDIN con un respaldo a display -title 'KeyID 0x%k' %i y finalmente a xdg-open %i. En Windows se usa !ShellExecute 400 %i ; aquí el comando es un comando meta para usar esa llamada a la API seguida de un tiempo de espera en milisegundos que se usa para dar al visor tiempo para leer el archivo de imagen temporal antes de que gpg lo borre de nuevo. Nótese que si su programa visor de imágenes no es seguro, ejecutarlo desde gpg no lo hace seguro.

--exec-path cadena
Establece una lista de directorios donde buscar visores de fotos. Si no se proporciona, los visores de fotos usan la variable de entorno PATH .
--keyring archivo
Añade archivo a la lista actual de llaveros. Si archivo comienza con una virgulilla y una barra, estas se reemplazan por el directorio $HOME. Si el nombre de archivo no contiene una barra, se asume que está en el directorio de inicio de GnuPG ("~/.gnupg" a menos que se use --homedir o $GNUPGHOME ).

Nótese que esto añade un llavero a la lista actual. Si la intención es usar solo el llavero especificado, use --keyring junto con --no-default-keyring.

Si se ha usado la opción --no-keyring no se usarán llaveros en absoluto.

Nótese que si la opción use-keyboxd está habilitada en ‘common.conf’, no se usan llaveros en absoluto y las claves son todas mantenidas por el proceso keyboxd en su propia base de datos.

--primary-keyring archivo
Esta es una variante de --keyring y designa archivo como el llavero público primario. Esto significa que las claves importadas recientemente (vía --import o servidor de claves --recv-from) irán a este llavero.
--secret-keyring archivo
Esta es una opción obsoleta y se ignora. Todas las claves secretas se almacenan en el directorioprivate-keys-v1.dbajo el directorio de inicio de GnuPG .
--trustdb-name archivo
Usa archivo en lugar de la base de datos de confianza por defecto. Si archivo comienza con una virgulilla y una barra, estas se reemplazan por el directorio $HOME. Si el nombre de archivo no contiene una barra, se asume que está en el directorio de inicio de GnuPG (‘~/.gnupg’ si --homedir o $GNUPGHOME no se usa).
--homedir dir
Establece el nombre del directorio de inicio en dir. Si esta opción no se usa, el directorio de inicio por defecto es ‘~/.gnupg’. Solo se reconoce cuando se da en la línea de comandos. También anula cualquier directorio de inicio declaradoa través de la variable de entorno ‘GNUPGHOME’ o (en sistemas Windows) por medio de la entrada del registro HKCU\Software\GNU\GnuPG:HomeDir.

En los sistemas Windows es posible instalar GnuPG como una aplicación portátil. En este caso, solo se considera esta opción de línea de comandos; todas las demás formas de establecer un directorio de inicio se ignoran.

--display-charset name
Establece el nombre del juego de caracteres nativo. Se utiliza para convertir algunas cadenas informativas, como los ID de usuario, a la codificación UTF-8 adecuada. Tenga en cuenta que esto no tiene nada que ver con el juego de caracteres de los datos a cifrar o firmar; GnuPG no recodifica los datos proporcionados por el usuario. Si no se usa esta opción, el juego de caracteres predeterminado se determina a partir de la configuración regional (locale) actual. Un nivel de verbosidad de 3 muestra el juego elegido. Esta opción no debe usarse en Windows. Los valores válidos para name son:
iso-8859-1
Este es el juego Latin 1.
iso-8859-2
El juego Latin 2.
iso-8859-15
Actualmente es un alias para el juego Latin 1.
koi8-r
El juego ruso habitual (RFC-1489).
utf-8
Omite todas las traducciones y asume que el SO usa la codificación UTF-8 nativa.
--utf8-strings
--no-utf8-strings
Asume que los argumentos de la línea de comandos se proporcionan como cadenas UTF-8. El valor predeterminado (--no-utf8-strings) es asumir que los argumentos están codificados en el juego de caracteres especificado por --display-charset. Estas opciones afectan a todos los argumentos siguientes. Ambas opciones pueden usarse varias veces. Esta opción no debe usarse en un archivo de opciones.

Esta opción no tiene efecto en Windows. Allí, la codificación UTF-8 utilizada internamente se traduce para la entrada y salida de la consola. Se espera que los argumentos de la línea de comandos estén en Unicode y se traducen a UTF-8. Por lo tanto, al llamar a este programa desde otro, asegúrese de usar la versión Unicode de CreateProcess.

--options file
Lee las opciones de file y no intenta leerlas del archivo de opciones predeterminado en el directorio de inicio (véase --homedir). Esta opción se ignora si se usa en un archivo de opciones.
--no-options
Atajo para --options /dev/null. Esta opción se detecta antes de intentar abrir un archivo de opciones. El uso de esta opción también evitará la creación de un directorio de inicio ‘~/.gnupg’.
-z n
--compress-level n
--bzip2-compress-level n
--no-compress
Establece el nivel de compresión en n para los algoritmos de compresión ZIP y ZLIB. El valor predeterminado es usar el nivel de compresión predeterminado de zlib (normalmente 6). --bzip2-compress-level establece el nivel de compresión para el algoritmo de compresión BZIP2 (con un valor predeterminado de 6 también). Esta es una opción diferente de --compress-level ya que BZIP2 usa una cantidad significativa de memoria por cada nivel de compresión adicional.

La opción -z establece ambas. Un valor de 0 para n desactiva la compresión. Un valor de -1 fuerza la compresión usando el nivel predeterminado. La opción --no-compress es idéntica a -z0.

Excepto para el comando --store , la compresión siempre se usa a menos que gpg detecte que la entrada ya está comprimida. Para inhibir el uso de la compresión, use -z0 o --no-compress; para forzar la compresión, use -z-1 o la opción z con otro nivel de compresión que el predeterminado indicado por -1. Tenga en cuenta que esta anulación de la detección predeterminada solo funciona con z y no con la variante larga de esta opción.

--bzip2-decompress-lowmem
Usa un método de descompresión diferente para archivos comprimidos con BZIP2. Este método alternativo usa un poco más de la mitad de la memoria, pero también se ejecuta a la mitad de la velocidad. Esto es útil en circunstancias de memoria extremadamente baja cuando el archivo se comprimió originalmente a un alto --bzip2-compress-level.
--mangle-dos-filenames
--no-mangle-dos-filenames
Las versiones antiguas de Windows no pueden manejar nombres de archivo con más de un punto. --mangle-dos-filenames hace que GnuPG reemplace (en lugar de añadir a) la extensión de un nombre de archivo de salida para evitar este problema. Esta opción está desactivada por defecto y no tiene efecto en plataformas que no sean Windows.
--ask-cert-level
--no-ask-cert-level
Al hacer una firma de clave, solicita un nivel de certificación. Si no se especifica esta opción, el nivel de certificación utilizado se establece mediante --default-cert-level. Véase --default-cert-level para información sobre los niveles específicos y cómo se utilizan. --no-ask-cert-level desactiva esta opción. El valor predeterminado de esta opción es no.
--default-cert-level n
El valor predeterminado a usar para el nivel de verificación al firmar una clave.

0 significa que no hace ninguna afirmación particular sobre lo cuidadosamente que verificó la clave.

1 significa que cree que la clave es propiedad de la persona que afirma poseerla, pero no pudo, o no verificó la clave en absoluto. Esto es útil para una verificación de "persona", donde firma la clave de un usuario seudónimo.

2 significa que hizo una verificación casual de la clave. Por ejemplo, esto podría significar que verificó la huella digital de la clave y comprobó el ID de usuario en la clave contra una identificación con foto.

3 significa que hizo una verificación exhaustiva de la clave. Por ejemplo, esto podría significar que verificó la huella digital de la clave con el propietario de la clave en persona, y que comprobó, por medio de un documento difícil de falsificar con una identificación con foto (como un pasaporte), que el nombre del propietario de la clave coincide con el nombre en el ID de usuario de la clave, y finalmente que verificó (por intercambio de correo electrónico) que la dirección de correo electrónico en la clave pertenece al propietario de la clave.

Tenga en cuenta que los ejemplos dados anteriormente para los niveles 2 y 3 son solo eso: ejemplos. Al final, depende de usted decidir qué significan "casual" y "exhaustivo" para usted.

El valor predeterminado de esta opción es 0 (sin afirmación particular).

--min-cert-level
Al construir la base de datos de confianza, trata cualquier firma con un nivel de certificación inferior a este como inválida. El valor predeterminado es 2, lo que ignora las firmas de nivel 1. Tenga en cuenta que las firmas de nivel 0 "sin afirmación particular" siempre se aceptan.
--trusted-key long key ID or fingerprint
Asume que la clave especificada (que debe darse como huella digital) es tan confiable como una de sus propias claves secretas. Esta opción es útil si no desea mantener sus claves secretas (o una de ellas) en línea pero aún quiere poder verificar la validez de la clave de un destinatario o firmante determinado. Si la clave dada no está disponible localmente pero hay configurado un servidor de claves LDAP, la clave faltante se importa de ese servidor. El valor "none" se permite explícitamente para distinguir entre el uso de cualquier opción trusted-key y el no uso de esta opción en absoluto (p. ej., debido a la --no-options opción).
--add-desig-revoker [sensitive:]fingerprint
Añade la clave especificada por fingerprint como revocador designado a las claves recién creadas. Si la huella digital está precedida por la palabra clave ``sensitive:'', esa información normalmente no se exporta con la clave. Esta opción puede darse varias veces para añadir más de un revocador designado. Si se usa la palabra clave ``clear'' en lugar de una huella digital, se descartan todas las huellas digitales dadas anteriormente. Los revocadores designados están marcados en la clave como no revocables. Tenga en cuenta que un revocador designado especificado usando un archivo de parámetros también se añadirá a la clave.
--default-new-key-adsk fingerprint
Añade la subclave especificada por fingerprint como una Subclave de Descifrado Adicional (ADSK) a las claves recién creadas. Esta opción puede darse varias veces para añadir más de un ADSK. También es posible dar varias huellas digitales delimitadas por espacio o coma como valor para esta opción. Si se usa la palabra clave ``clear'' en lugar de una huella digital, se descartan todas las huellas digitales especificadas anteriormente (útil para anular opciones dadas en un archivo de configuración). Se espera que la huella digital especifique una subclave y no necesita un signo de exclamación como sufijo; debe darse en formato compacto (40 o 64 dígitos hexadecimales sin espacios).
--trust-model {pgp|classic|tofu|tofu+pgp|direct|always|auto}
Establece qué modelo de confianza debe seguir GnuPG. Los modelos son:
pgp
Esta es la Web de Confianza combinada con firmas de confianza tal como se usa en PGP 5.x y versiones posteriores. Este es el modelo de confianza predeterminado al crear una nueva base de datos de confianza.
classic
Esta es la Web de Confianza estándar tal como la introdujo PGP 2.
tofu

TOFU significa Trust On First Use (Confianza en el Primer Uso). En este modelo de confianza experimental, la primera vez que se ve una clave, se memoriza. Si más tarde se ve otra clave con un ID de usuario con la misma dirección de correo electrónico, ambas claves se marcan como sospechosas. En ese caso, la próxima vez que se use cualquiera de ellas, se muestra una advertencia describiendo el conflicto, por qué podría haber ocurrido (ya sea porque el usuario generó una nueva clave y no pudo firmar cruzadamente las claves antigua y nueva, la clave es una falsificación, o se está intentando un ataque de intermediario), y se le pide al usuario que confirme manualmente la validez de la clave en cuestión.

Dado que un atacante potencial es capaz de controlar la dirección de correo electrónico y así eludir el algoritmo de detección de conflictos usando una dirección de correo electrónico que es similar en apariencia a una dirección de correo electrónico de confianza, siempre que se verifica un mensaje, se muestran estadísticas sobre el número de mensajes firmados con la clave.
