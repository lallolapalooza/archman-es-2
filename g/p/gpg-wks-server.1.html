DESCRIPCIÓ

N

El gpg-wks-server es una implementación del lado del servidor del Servicio de Claves Web. Recibe solicitudes de publicación, envía solicitudes de confirmación, recibe confirmaciones y publica la clave. También cuenta con funciones para facilitar la configuración y el mantenimiento de un Directorio de Claves

Web.

Cuando se usa con el comando --receive se procesa un único correo del Servicio de Claves Web. Comúnmente este comando se usa con la opción --send para enviar directamente los correos creados. Véase más abajo un ejemplo de

instalación.

El comando --cron se usa para tareas de limpieza periódicas. Por ejemplo, las solicitudes no confirmadas deberían eliminarse después de su tiempo de expiración. Es mejor ejecutar este comando una vez al día desde un

cronjob.

El comando --list-domains imprime todos los dominios configurados. Además, crea los directorios faltantes para la configuración e imprime advertencias sobre problemas en la

configuración.

El comando --check-key (o simplemente --check) comprueba si una clave con el user-id dado está instalada. El proceso devuelve éxito en este caso; para imprimir también un diagnóstico use la opción -v. Si la clave no está instalada se imprime un diagnóstico y el proceso devuelve fallo; para suprimir el diagnóstico use la opción -q. Se puede dar más de un user-id; véase también la opción with-file

.

El comando --install-key instala manualmente una clave en el WKD. Los argumentos son un archivo con el bloque de claves y el user-id a instalar. Si el primer argumento se asemeja a una huella digital la clave se toma del llavero actual; para forzar el uso de un archivo, anteponga "./" al primer argumento. Si no se dan argumentos, los parámetros se leen de stdin; el formato esperado son líneas con la huella digital y el buzón separados por un

espacio.

El comando --remove-key desinstala una clave del WKD. El proceso devuelve éxito en este caso; para imprimir también un diagnóstico, use la opción -v. Si la clave no está instalada se imprime un diagnóstico y el proceso devuelve fallo; para suprimir el diagnóstico use la opción -q

.

EJEMPLO

S

El Servicio de Claves Web requiere un directorio de trabajo para almacenar claves pendientes de publicación. Como root cree un directorio de

trabajo: 
  # mkdir /var/lib/gnupg/wks
  # chown webkey:webkey /var/lib/gnupg/wks
  # chmod 2750 /var/lib/gnupg/w
k
s

Luego, bajo su cuenta webkey, cree directorios para todos sus dominios. Aquí lo hacemos para "example.

net": 
  $ mkdir /var/
lib/gnupg/wk
s/example.net

Finalmente

ejecute 
  $ gpg-wks-
server --li
st-domains

para crear los subdirectorios requeridos con los permisos establecidos correctamente. Para cada dominio se necesita configurar una dirección de envío. Todos los correos del servicio se dirigen a esa dirección. Puede ser la misma dirección para todos los dominios configurados, por

ejemplo: 
  $ cd /var/lib/gnupg/wks/example.net
  $ echo key-submission@example.net >submission-addre
s
s

El protocolo requiere que la clave a publicar se envíe con un correo cifrado al servicio. Por lo tanto necesita crear una clave para la dirección de

envío: 
  $ gpg --batch --passphrase '' --quick
-gen-key key-submission@example.net
$ gpg -K key-submission@example.net

La salida del último comando se parece a

esto: 
  sec   rsa3072 2016-08-30 [SC]
        C0FCF8642D830C53246211400346653590B37

bxzcxpxk8h87z1k7bzk86xn5aj47intu@example.net ssb rsa3072 2016-08-30 [E]

clave: 
  $ gpg-wks-server --install-key C0FCF8642
D830C53246211400346653590B3795B \ >
key-submission@example.net
