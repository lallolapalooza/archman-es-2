NOMBRE

mfsmetadump - volcar información de metadatos de MooseFS en formato legible por humanos.

SINOPSIS

mfsmetadump [-d] [-s nombre_seccion] archivo_metadatos

DESCRIPCIÓN

mfsmetadump volca información de metadatos de MooseFS en formato legible por humanos. La salida consiste en varias secciones con diferentes tipos de información. Cada sección consiste en datos de encabezado - filas que comienzan con un signo de almohadilla (#) - y datos de contenido (pueden estar vacíos).

OPCIONES

-d - reemplaza todos los caracteres no imprimibles (códigos < 32 y > 126) con '.' (era el comportamiento predeterminado en la versión < 3.0.110).

-s - volcar solo la sección especificada del archivo. Secciones posibles:

HEAD - información de encabezado
SESS - sesiones de clientes
LABS - etiquetas (no utilizadas)
SCLA - clases de almacenamiento
PATT - anulaciones de patrones
NODE - nodos del árbol (i-nodos)
EDGE - bordes del árbol (nombres de archivo)
FREE - nodos libres (i-nodos eliminados)
QUOT - definiciones de cuotas
XATR - datos xattr
PACL - datos acl posix
OPEN - archivos abiertos
FLCK - datos flock
PLCK - datos de bloqueos posix (lockf, ioctl)
CSDB - servidores de fragmentos activos
CHNK - fragmentos
archivo_metadatos
ruta al archivo metadata.mfs

NOTAS

Cada sección de metadatos, con la excepción de la sección HEAD, consiste en un conjunto constante de campos de ENCABEZADO y un conjunto variable de campos específicos de esa sección. La sección HEAD contiene solo campos específicos de la sección. Los campos del ENCABEZADO y todos los campos de la sección se enumeran a continuación:

SECCIÓN DE ARCHIVOS ABIERTO (OPEN)

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

DESCRIPCIÓN

mfsmetadump es una utilidad que vuelca datos de metadatos del archivo de metadatos de un maestro de MooseFS en un formato legible. Se puede utilizar para depurar problemas, recuperar datos de un archivo de metadatos dañado o analizar el estado del sistema de archivos.

El volcado de metadatos se divide en varias secciones. Cada sección está precedida por una cabecera de sección que indica el tipo de datos que contiene y el número de elementos en esa sección. Los elementos dentro de cada sección son líneas que describen un objeto específico (archivo, directorio, bloqueo, etc.). Cada línea consta de una etiqueta de clave seguida de los datos correspondientes.

SECCIÓN DE ENTRADAS DEL DIRECTORIO (DIR)

DIR
línea con descripción de entrada de directorio 
i	número de inodo
n	nombre del archivo
m	fecha de modificación
a	fecha de acceso
c	fecha de cambio
s	tamaño del archivo
u	identificador de usuario propietario
g	identificador de grupo propietario
e	número de enlaces duros
r	permisos de archivo (como en chmod)
o	flag de SO (e.g. 'D' para directorio, 'L' para enlace simbólico,
    'E' para entrada de directorio vacía, 'H' para hole)

SECCIÓN DE METADATOS EXTENDIDOS (XATTR)

XATTR
línea con descripción de metadatos extendidos 
i	número de inodo
n	nombre del atributo extendido
v	valor del atributo extendido

SECCIÓN DE FICHEROS ABIERTO (OPENFILE)

OPENFILE
línea con descripción de fichero abierto 
s	id de sesión
i	número de inodo

SECCIÓN BLOQUEO FLOCK (FLCK)

FLOCK
línea con descripción de bloqueo flock 
i	número de inodo
s	id de sesión
o	propietario del bloqueo (propietario del bloqueo FUSE)
t	tipo de bloqueo ('R' - bloqueo compartido, 'W' - bloqueo exclusivo)

SECCIÓN BLOQUEO POSIX (PLCK)

POSIXLOCK
línea con descripción de bloqueo posix 
i	número de inodo
s	id de sesión
o	propietario del bloqueo (propietario del bloqueo FUSE)
p	id del proceso local (pid del propietario)
r	rango del bloqueo en formato <INICIO,FIN)
t	tipo de bloqueo ('R' - bloqueo compartido, 'W' - bloqueo exclusivo)

SECCIÓN SERVIDORES DE CHUNKS (CSDB)

servidores de chunks
número de servidores de chunks
CHUNCKSERVER
línea con descripción de servidor de chunk 
i	ip del servidor
p	puerto del servidor
#	id del servidor
m	modo de mantenimiento
t	timestamp de tiempo de espera de mantenimiento

SECCIÓN CHUNKS (CHNK)

nextchunkid
primer número de chunk disponible
CHUNK
línea con descripción de chunk 
i	número de chunk
v	versión del chunk
t	timestamp, si está en el futuro, significa timestamp de bloqueo, si está en el pasado, timestamp de última modificación
a	flag de archivo
(s,#)	lista de entradas, s es id de clase de almacenamiento, # es número de ficheros en esta clase de almacenamiento que contienen este chunk
c	id de clase de almacenamiento calculada (id de clase efectivamente usada, si un chunk tiene más de una)

¡AVISO! Si el timestamp de un chunk es 0, significa que el chunk fue creado por una versión de MooseFS anterior a la 4.45.0 y no ha sido bloqueado o modificado desde entonces.
