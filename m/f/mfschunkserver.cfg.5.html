NOMBRE

mfschunkserver.cfg - archivo de configuración principal para mfschunkserver

DESCRIPCIÓN

El archivo mfschunkserver.cfg contiene la configuración del proceso mfschunkserver.

SINTAXIS

La sintaxis es:

OPCIÓN = VALOR

Las líneas que comienzan con el carácter # se ignoran como comentarios.

OPCIONES DE INICIO

Los cambios en esta sección requieren reiniciar el proceso.

USUARIO_DE_TRABAJO
usuario bajo el cual se ejecutará el demonio
GRUPO_DE_TRABAJO
grupo bajo el cual se ejecutará el demonio; valor opcional - si está vacío, se usará el grupo de usuario predeterminado
IDENTIFICADOR_DE_SYSLOG
nombre del proceso que se incluirá en los mensajes de syslog; el valor predeterminado es mfschunkserver
BLOQUEAR_MEMORIA
si se debe realizar mlockall() para evitar que el proceso mfschunkserver se vuelque a la memoria swap; el valor predeterminado es 0, es decir, no
LIMITAR_ARENAS_DE_GLIBC_MALLOC
limita las arenas de malloc a un valor dado - evita que el servidor utilice una gran cantidad de memoria virtual (solo Linux, el valor predeterminado es 4)
DESACTIVAR_OOM_KILLER
desactiva el "out of memory killer" (solo Linux, el valor predeterminado es 1)
NIVEL_NICE
nivel de nice para ejecutar el demonio; el valor predeterminado es -19; nota: el proceso debe iniciarse como root para aumentar la prioridad, si la configuración de la prioridad falla, el proceso retiene el nivel de nice con el que se inició
UMASK_ARCHIVOS
establece la umask predeterminada para grupos y otros (el usuario siempre tiene 0); el valor predeterminado es 027 - bloquea la escritura para el grupo y bloquea todo para otros
RUTA_DATOS
dónde almacenar el archivo de bloqueo del demonio
PERMITIR_INICIO_CON_DISCOS_INVALIDOS
cuando se establece en uno, el chunkserver no abortará el inicio incluso cuando se encuentren entradas incorrectas en el archivo 'mfshdd.cfg'; el valor predeterminado es 0 (no iniciar con entradas inválidas)
PUEDE_USAR_MMAP
el uso de mmap para la asignación puede reducir ligeramente el uso de RAM y proporcionar una ligera mejora de rendimiento, pero en ciertas arquitecturas/kernels puede generar problemas - especialmente en arquitecturas con más de una CPU física; el valor predeterminado es 0

OPCIONES DE TIEMPO DE EJECUCIÓN

Los cambios en esta sección solo requieren recargar el proceso.

NOMBRE_ARCHIVO_CONF_HDD
ubicación/nombre alternativo del archivo mfshdd.cfg
PRUEBA_VELOCIDAD_HDD
velocidad de las pruebas de chunks en segundo plano en MB/s por disco (formalmente entrada definida en mfshdd.cfg). El valor puede proporcionarse como un número decimal; el valor predeterminado es 1.0
INTERVALO_MINIMO_PRUEBA_HDD
evita probar la integridad de los chunks cuando la última E/S (incluida la prueba) se realizó hace menos de INTERVALO_MINIMO_PRUEBA_HDD; el valor predeterminado es 1 día; para el formato del valor ver TIEMPO
TIEMPO_MINIMO_FADVISE_HDD
si es posible, use posix_fadvise(POSIX_DONTNEED) después de cada prueba de chunk (pero solo si la última operación de E/S se realizó hace más de TIEMPO_MINIMO_FADVISE_HDD). Usar cero realizará siempre posix_fadvise (vaciar caché) y usar un valor negativo nunca vaciará la caché después de las pruebas. Esta configuración solo es válida para sistemas que soportan posix_fadivise; el valor predeterminado es 1 día; para el formato del valor ver TIEMPO
DEJAR_ESPACIO_POR_DEFECTO_HDD
cuánto espacio se debe dejar sin usar en cada disco duro; formato del número: [0-9]*([.][0-9]*)?([kMGTPE]|[KMGTPE]i)?B? ; el valor predeterminado es 256MiB; ejemplos: 0.5GB, .5G, 2.56GiB, 1256M etc.
UTILIZACION_REBALANCEO_HDD
porcentaje del tiempo total de trabajo que el chunkserver puede dedicar al rebalanceo de espacio en disco; el valor predeterminado es 20
LIMITE_REBALANCEO_ALTA_VELOCIDAD_HDD
escrituras simultáneas máximas por disco en rebalanceo de disco de alta velocidad (0 significa usar rebalanceo estándar; el valor predeterminado es 0)
TOLERANCIA_ERRORES_HDD, PERIODO_TOLERANCIA_ERRORES_HDD
cuántos errores de E/S (COUNT) se tolerarán en una cantidad dada de segundos (PERIOD) en un solo disco duro; si el número de errores excede esta configuración, el disco duro infractor se marcará como dañado; los valores predeterminados son 2 y 600
FSYNC_ANTES_DE_CERRAR_HDD
activa/desactiva fsync antes de cerrar el chunk; el valor predeterminado es 0 (apagado)
ESPACIO_EN_ESCRITURA_HDD
activa/desactiva la optimización de espacio (omitir ceros iniciales y finales) al escribir un nuevo bloque; el valor predeterminado es 1 (activado)
NUMERO_CHUNKS_RR_HDD
cuántos chunks se deben crear en un directorio antes de pasar al siguiente; valores más altos son mejores con la mayoría de los algoritmos de caché de los sistemas operativos, valores bajos conducen a una distribución de chunks más uniforme; el valor predeterminado es 10000, que funciona mejor en la mayoría de los casos
HORAS_MANTENER_DUPLICADOS_HDD
cuántas horas se deben mantener los chunks duplicados antes de eliminarlos (el valor predeterminado es una semana); cambiar este valor y recargar reiniciará el contador; para el formato del valor ver TIEMPO
TRABAJADORES_MAX, TRABAJADORES_MAX_INACTIVOS
número máximo de trabajadores activos y número máximo de trabajadores inactivos; los valores predeterminados son 250 y 40
NIVEL_MINIMO_SYSLOG
nivel mínimo de mensajes que serán reportados por el chunkserver; niveles en orden de importancia: ERROR, WARNING, NOTICE, INFO, DEBUG (el valor predeterminado es INFO)
ELEVACIÓN_SYSLOG_A
los mensajes reportados de un nivel inferior al establecido por esta opción se elevarán a este nivel (por ejemplo, si NIVEL_MINIMO_SYSLOG está establecido en DEBUG y ELEVACIÓN_SYSLOG_A está establecido en NOTICE, todos los mensajes INFO y DEBUG se enviarán a syslog como NOTICE; el valor predeterminado es NOTICE)

OPCIONES DE CONEXIÓN MAESTRA

Los cambios en esta sección solo requieren recargar el proceso.

ETIQUETAS
cadena de etiquetas definida como un conjunto de letras (sin distinguir mayúsculas y minúsculas) separadas por coma o punto y coma; el valor predeterminado es vacío - sin etiquetas
HOST_ENLACE
dirección local a utilizar para las conexiones maestras; el valor predeterminado es *, es decir, la dirección local predeterminada
HOST_MAESTRO
host maestro de MooseFS, la IP solo está permitida en instalaciones de un solo maestro; el valor predeterminado es mfsmaster
PUERTO_MAESTRO
puerto de comandos maestro de MooseFS; el valor predeterminado es 9420
PUERTO_CONTROL_MAESTRO
(solo pro) puerto de control maestro de MooseFS; el valor predeterminado es 9419
TIEMPO_ESPERA_MAESTRO
tiempo de espera en segundos para las conexiones maestras (si no es 0); Si este valor es cero, el chunkserver lo establecerá inicialmente en 10 y le pedirá al maestro este valor

MASTER CONNECTION OPTIONS

These options are used to establish connection with the master server. Changes in this section require a full server restart.

MASTER_HOST
master server hostname or IP address; default is NULL (mandatory)
MASTER_PORT
master server port (default is 9421)
MASTER_PASSWORD
password to authenticate with master server (if it requires one)
MASTER_RECONNECTION_DELAY
delay in seconds before trying to reconnect to master after disconnection (default is 5)
AUTH_CODE
authentication string (used only when master requires authorization)
CHUNKS_PER_REGISTER_PACKET
maximum number of chunks system will try to put in a single register message (default is 1000, limits 100-10000)

CLIENTS CONNECTION OPTIONS

Changes in this section require only process reload.

CSSERV_LISTEN_HOST
IP address to listen on for client (mount) connections (* means any)
CSSERV_LISTEN_PORT
port to listen on for client (mount) connections (default is 9422)

NOTES

TIME

For config variables that define time without requiring a single, specific unit, time can be defined as a number of seconds (integer) or a time period in one of two possible formats:

first format: #.#T where T is one of: s-seconds, m-minutes, h-hours, d-days or w-weeks; fractions of seconds will be rounded to full seconds

second format: #w#d#h#m#s, any number of definitions can be omitted, but the remaining definitions must be in order (so #d#m is still a valid definition, but #m#d is not); ranges: s,m: 0 to 59, h: 0 to 23, d: 0 t o 6, w is unlimited and the first definition is also always unlimited (i.e. for #d#h#m d will be unlimited)

Notice! For variable HDD_KEEP_DUPLICATES_HOURS only h,d and w time units are accepted and a value without a time unit is treated as hours; fractions are rounded to full hours.

Examples:

1.5h is the same as 1h30m, is the same as 90m, is the same as 5400s, is the same as 5400

2.5d is the same as 2d12h, is the same as 60h; 1d36h is not a valid time period (h is not the first definition, so it is bound by range 0 to 23)

1.03m is the same as 62s (61.8 seconds will be rounded up to 62)
