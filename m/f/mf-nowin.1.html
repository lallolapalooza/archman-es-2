MF(1) Manual de Comandos Generales MF(1)

NOMBRE

mf, inimf, mf-nowin - Metafont, un lenguaje para diseño de fuentes y logotipos

SINOPSIS

mf [opciones] [comandos]

DESCRIPCIÓN

Metafont lee el programa en los archivos especificados y genera fuentes rasterizadas (en formato gf) y métricas de fuentes (en formato tfm). El lenguaje Metafont se describe en The Metafontbook.

Al igual que TeX, Metafont se usa normalmente con un gran conjunto de macros precompiladas, y la generación de fuentes en particular requiere el soporte de varios archivos de macros. Esta versión de Metafont examina su línea de comandos para ver bajo qué nombre se llamó. Tanto inimf como virmf son enlaces simbólicos al ejecutable mf. Cuando se llama como inimf (o cuando se da la opción -ini) puede usarse para precompilar macros en un archivo .base. Cuando se llama como virmf usará la base plain. Cuando se llama con cualquier otro nombre, Metafont usará ese nombre como el nombre de la base a usar. Por ejemplo, cuando se llama como mf se usa la base mf, que es idéntica a la base plain. Otras bases que no sean plain rara vez se utilizan.

Los comandos dados en la línea de comandos al programa Metafont se le pasan como la primera línea de entrada. (Pero a menudo es más fácil escribir argumentos extendidos como la primera línea de entrada, ya que los shells de UNIX tienden a ignorar o malinterpretar los símbolos favoritos de Metafont, como los puntos y comas, a menos que los cite). Como se describe en The Metafontbook, esa primera línea debe comenzar con un nombre de archivo, una secuencia de control de barra invertida \secuencia, o una &basename.

El uso normal es decir

mf  '\mode=<printengine>; [mag=magstep(n);]' input  font

para comenzar a procesar font.mf. Las comillas simples son la mejor manera de evitar que el shell de Unix malinterprete los puntos y comas y que elimine el carácter \, que es necesario aquí para evitar que Metafont piense que quiere producir una fuente llamada mode. (O simplemente puede decir mf y dar lo otro en la siguiente línea, sin comillas). Otras secuencias de control, como batchmode (para operación silenciosa) también pueden aparecer. El nombre font será el ``nombre del trabajo'' (jobname), y se usa para formar los nombres de los archivos de salida. Si Metafont no recibe un nombre de archivo en la primera línea, el nombre del trabajo es mfput. La extensión predeterminada, .mf, puede ser anulada especificando una extensión explícitamente.

Un registro de mensajes de error va al archivo jobname.log. Los archivos de salida son jobname.tfm y jobname.<número>gf, donde <número> depende de la resolución y magnificación de la fuente. El mode en este ejemplo se muestra genéricamente como <printengine>, un término simbólico para el cual debe sustituirse el nombre de un dispositivo real o, lo más comúnmente, el nombre localfont (ver más abajo). Si el modo no se especifica o no es válido para su sitio, Metafont usará por defecto el modo proof, que produce imágenes grandes de caracteres para usar en el diseño y refinamiento de fuentes. El modo de prueba se puede reconocer por el sufijo .2602gf después del nombre del trabajo. Ejemplos de salida en modo de prueba se pueden encontrar en Computer Modern Typefaces (Volumen E de Computers and Typesetting). El sistema de magsteps es idéntico al sistema utilizado por TeX, con valores generalmente en el rango 0.5, 1.0, 2.0, 3.0, 4.0 y 5.0. A continuación se muestra una lista de números de gf para fuentes de 118 dpi, 240 dpi y 300 dpi.

MAGSTEP 118 dpi 240 dpi 300 dpi
mag=magstep(0) 118 240 300
mag=magstep(0.5) 129 263 329
mag=magstep(1) 142 288 360
mag=magstep(2) 170 346 432
mag=magstep(3) 204 415 518
mag=magstep(4) 245 498 622
mag=magstep(5) 294 597 746

La magnificación también puede especificarse no como un magstep, sino como un valor arbitrario, como 1.315, para crear tamaños de caracteres especiales.

Antes de que pueda comenzar la producción de fuentes, es necesario configurar los archivos de base apropiados. El conjunto mínimo de componentes para la producción de fuentes para un determinado motor de impresión es el archivo macro plain.mf y el archivo local mode_def. Las macros en plain.mf se pueden estudiar en un apéndice de The Metafontbook; fueron desarrolladas por Donald E. Knuth, y este archivo nunca debe ser alterado, excepto cuando se actualiza oficialmente. Cada especificación mode_def ayuda a adaptar las fuentes a un motor de impresión particular. Hay una discusión regular sobre mode_defs en TUGboat, la revista del TeX Users Group. Los locales en uso en esta computadora deben estar en modes.mf.

La respuesta e al modo de recuperación de errores de Metafont invoca el editor predeterminado del sistema en la línea errónea del archivo fuente. Hay una variable de entorno, MFEDIT, que anula el editor predeterminado. Debe contener una cadena con "%s" indicando dónde va el nombre del archivo y "%d" indicando dónde va el número de línea decimal (si lo hay). Por ejemplo, una cadena MFEDIT para el editor vi se puede configurar con el comando csh

setenv MFEDIT "vi +%d %s"

Un archivo conveniente en la biblioteca es null.mf, que no contiene nada. Cuando mf no encuentra el archivo que cree que desea introducir, sigue pidiéndole otro nombre de archivo; responder `null' te saca del bucle si no quieres introducir nada.

SALIDA GRÁFICA EN LÍNEA

Metafont puede usar la mayoría de las pantallas modernas, por lo que puede ver su salida sin imprimir. El capítulo 23 de The Metafontbook describe lo que puede hacer. Esta implementación de Metafont utiliza variables de entorno para determinar qué dispositivo de pantalla desea usar. Primero busca una variable MFTERM, y luego TERM. Si no encuentra ninguna, no obtiene salida en línea. De lo contrario, el valor de la variable determina el dispositivo a usar: hp2627, sun (para el antiguo SunView), tek, uniterm (para un emulador Tek 4014 de Atari ST), xterm (para X10 o X11). Algunos de estos dispositivos pueden no ser compatibles en todos los ejecutables de Metafont; la elección se realiza en tiempo de compilación.

En algunos sistemas, hay dos binarios de Metafont, mf y mf-nowin. En esos sistemas, el binario mf soporta gráficos, mientras que el binario mf-nowin no. El binario mf-nowin es utilizado por scripts como mktexpk donde el soporte gráfico es una molestia en lugar de algo útil.

OPCIONES

Esta versión de Metafont entiende las siguientes opciones de línea de comandos.

-base base
Usa base como nombre de la base a utilizar, en lugar del nombre por el cual se llamó Metafont o una línea %&.
-cnf-line cadena
Analiza cadena como una línea de configuración de texmf.cnf. Consulte el manual de Kpathsea.
-file-line-error
Imprime mensajes de error en el formato archivo:línea:error, que es similar a la forma en que muchos compiladores los formatean.
-no-file-line-error
Deshabilita la impresión de mensajes de error en el estilo archivo:línea:error.
-file-line-error-style
Este es el nombre antiguo de la opción -file-line-error.
-halt-on-error
Sale con un código de error cuando se encuentra un error durante el procesamiento.
-help
Imprime el mensaje de ayuda y sale.
-ini
Ser inimf, para volcar bases; esto es implícitamente cierto si el programa se llama como inimf.

INTERACCIÓN

Controla cómo Metafont responde a los errores. Los niveles son:

-batchmode
Sale con un código de error cuando se encuentra un error, sin solicitar entrada.
-nonstopmode
No solicita entrada en caso de error, sino que continúa procesando hasta el final del archivo de entrada.
-scrollmode
Permite que se muestren los mensajes y las preguntas (valor predeterminado si la entrada es una terminal).
-errorstopmode
Detiene el procesamiento y solicita entrada en caso de error (valor predeterminado si la entrada no es una terminal).

Las opciones de interacción también se pueden controlar mediante la entrada.

En su lugar, puede usar la opción -interaction=levelname.

levelname puede ser batchmode, nonstopmode, scrollmode o errorstopmode.

OPTIONS

-interaction mode
Establece el modo de interacción. El modo puede ser uno de batchmode, nonstopmode, scrollmode y errorstopmode. El significado de estos modos es el mismo que el de los comandos correspondientes.
-jobname name
Utiliza name para el nombre del trabajo, en lugar de derivarlo del nombre del archivo de entrada.
-kpathsea-debug bitmask
Establece las banderas de depuración de búsqueda de rutas de acuerdo con la máscara de bits. Consulta el manual de Kpathsea para más detalles.
-maketex fmt
Habilita mktexfmt, donde fmt debe ser mf.
-no-maketex fmt
Deshabilita mktexfmt, donde fmt debe ser mf.
-output-directory directory
Escribe los archivos de salida en directory en lugar del directorio actual. Busca los archivos de entrada en directory primero, luego a lo largo de la ruta de búsqueda normal.
-parse-first-line
Si la primera línea del archivo de entrada principal comienza con %&, analízala para buscar un nombre de volcado o una opción -translate-file.
-no-parse-first-line
Deshabilita el análisis de la primera línea del archivo de entrada principal.
-progname name
Finge ser el programa name. Esto afecta tanto al formato utilizado como a las rutas de búsqueda.
-recorder
Habilita el grabador de nombres de archivo. Esto deja un rastro de los archivos abiertos para entrada y salida en un archivo con extensión .fls.
-translate-file tcxname
Utiliza la tabla de traducción tcxname.
-version
Imprime información de la versión y sale.

ENTORNO

Consulta la documentación de la biblioteca Kpathsearch (el nodo 'Path specifications') para obtener detalles sobre cómo se utilizan las variables de entorno al buscar. La utilidad kpsewhich se puede utilizar para consultar los valores de las variables.

Si la variable de entorno TEXMFOUTPUT está establecida, Metafont intenta colocar sus archivos de salida en ella, si no se pueden colocar en el directorio actual. Nuevamente, consulta tex(1).

MFINPUTS
Ruta de búsqueda para archivos de entrada.
MFEDIT
Plantilla de comando para cambiar al editor.
MFTERM
Determina la visualización gráfica en línea. Si MFTERM no está establecido y DISPLAY está establecido, se utiliza el soporte de ventana de Metafont para X. (DISPLAY debe estar establecido en una especificación de servidor X válida, como de costumbre). Si ni MFTERM ni DISPLAY están establecidos, TERM se utiliza para adivinar el soporte de ventana a utilizar.

UTILIDADES DE FUENTES

Hay disponibles una serie de programas utilitarios. La siguiente es una lista parcial de las utilidades disponibles y su propósito. Consulta a tu gurú local de Metafont para obtener detalles.

gftopk
Toma un archivo gf y produce un archivo de fuente pk más compactado.
gftodvi
Produce hojas de prueba para fuentes.
gftype
Muestra el contenido de un archivo gf en mnemónicos y/o imágenes.
pktype
Muestra de forma mnemónica el contenido de un archivo pk.
mft
Formatea un archivo fuente como se muestra en Computer Modern Typefaces.
