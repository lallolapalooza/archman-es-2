NOMBRE

mfsbdev - daemon/herramienta de gestión de dispositivos de bloque de MooseFS

SINOPSIS

mfsbdev start [-H host_master] [-P puerto_master] [-B bind_master] [-S ruta_master] [-p contraseña_master | -x archivo_contraseña] [-l socket_enlace] [-i archivo_inicializar_mapeos] [-o opciones]

mfsbdev stop [-l socket_enlace]

mfsbdev map [-l socket_enlace] -f archivo_mfs [-d dispositivo_nbd] [-n nombre_enlace] [-s tamaño_disp_bloque] [-b tamaño_bloque | -5 | -1 | -2 | -4] [-r] [-i]

mfsbdev unmap [-l socket_enlace] ( -f archivo_mfs | -d dispositivo_nbd | -n nombre_enlace )

mfsbdev list [-l socket_enlace] [-t m|u|i]

mfsbdev resize [-l socket_enlace] ( -f archivo_mfs | -d dispositivo_nbd | -n nombre_enlace ) [-s tamaño_disp_bloque]

DESCRIPCIÓN

Esta herramienta se utiliza para gestionar dispositivos de bloque. Esta herramienta SOLO funciona en Linux. El módulo del kernel nbd debe estar cargado para que esta herramienta funcione correctamente.

COMANDOS

start - inicia el daemon; el daemon solo escucha en un socket en este punto; todos los demás comandos usan el socket para comunicarse con el daemon; si no se especifica ningún socket mediante la opción -l, se utiliza el predeterminado: /dev/mfs/nbdsock

stop - detiene el daemon

map - mapea un archivo en mfs para que se utilice como dispositivo de bloque

unmap - elimina un mapeo

list - lista los mapeos actuales

resize - cambia el tamaño de un dispositivo de bloque (requiere la versión del kernel 4.18 o superior)

OPCIONES

-H - host maestro; el valor predeterminado es 'mfsmaster'

-P - puerto maestro; el valor predeterminado es '9421'

-S - ruta del master (subcarpeta en MFS que se utilizará como raíz para todos los mapeos de dispositivos de bloque); el valor predeterminado es '/'

-p - contraseña del master; mutuamente excluyente con la opción -x; si no se proporcionan ni -p ni -x, la herramienta intenta conectarse sin contraseña

-x - ruta a un archivo que contiene la contraseña del master; mutuamente excluyente con la opción -p; si no se proporcionan ni -p ni -x, la herramienta intenta conectarse sin contraseña

-l - ruta al socket de comunicación; el valor predeterminado es /dev/mfs/nbdsock

-f - ruta al archivo mfs utilizado para mapear el dispositivo de bloque;

-d - ruta al dispositivo de bloque de red ('/dev/nbdX'); por defecto (si no se proporciona este parámetro) se utiliza el primer dispositivo disponible con el comando map

-n - nombre del enlace simbólico creado en '/dev/mfs', que apunta al dispositivo de bloque de red creado por el comando map; el valor predeterminado es una combinación del nombre del host maestro, el puerto y el nombre del archivo mfs

-s - tamaño del dispositivo de bloque, se pueden usar sufijos SI e IEC; el valor predeterminado es el tamaño del archivo al que se mapea el dispositivo de bloque

-b - tamaño de bloque en bytes

-5 - usa tamaño de bloque de 512 bytes (equivalente a -b 512)

-1 - usa tamaño de bloque de 1024 bytes (equivalente a -b 1024)

-2 - usa tamaño de bloque de 2048 bytes (equivalente a -b 2048)

-4 - usa tamaño de bloque de 4096 bytes (equivalente a -b 4096)

-r - mapea el dispositivo de bloque como solo lectura (permite múltiples mapeos del mismo archivo)

-i (map) - ignora bloqueos; un archivo puede mapearse a más de un dispositivo de bloque, cada operación de mapeo intentará obtener el bloqueo apropiado (compartido para ro, exclusivo para rw) pero tendrá éxito incluso si no se obtiene el bloqueo

-t - fuerza al comando list a mostrar información en un formato listo para usar con el comando map (parámetro m) o unmap (parámetro u) o con el formato de archivo MooseFS mfsbdev.cfg (parámetro i)

-i (start) - usa el archivo de configuración proporcionado en el parámetro para iniciar dispositivos de bloque iniciales; para el formato de la configuración, consulta mfsbdev.cfg(5)

-o - parámetros adicionales, estilo mfsmount, se pueden definir muchos parámetros, separados por comas:

mfswritecachesize=N
especifica el tamaño de la caché de escritura en MiB (en el rango: 16..2048 - predeterminado: 128)
mfsreadaheadsize=N
define el tamaño de todos los búferes de prelectura en MiB (en el rango: 16..2048 - predeterminado: 128)
mfsreadaheadleng=N
define la cantidad de bytes a leer adicionalmente (en el rango: 128KiB..2MiB - predeterminado: 2097152 = 2MiB)
mfsreadaheadtrigger=N
define la cantidad de bytes leídos secuencialmente que activan la prelectura (predeterminado: 20971520)
mfserroronlostchunk
cuando todos los servidores de fragmentos conocidos están conectados al maestro y falta el fragmento requerido, finaliza la E/S inmediatamente y devuelve un error
mfserroronnospace
cuando todos los servidores de fragmentos conocidos están conectados al maestro y no hay espacio libre, finaliza la E/S inmediatamente y devuelve un error
mfsioretries=N
especifica el número de reintentos antes de que se devuelva un error de E/S (predeterminado: 30)
mfstimeout=N
define el tiempo máximo de espera en segundos antes de que se devuelva un error de E/S (predeterminado: 0, lo que significa sin tiempo de espera)
mfslogretry=N
define el contador de reintentos mínimo en el que el sistema comenzará a registrar mensajes de E/S (predeterminado: 5)
mfsmaster=HOST
conéctate con el maestro de MooseFS en HOST (predeterminado es mfsmaster) - equivalente a -H
mfsport=PUERTO
conéctate con el maestro de MooseFS en PUERTO (predeterminado es 9421) - equivalente a -P
mfsbind=IP
dirección local a utilizar para conectarse con el maestro en lugar de la predeterminada - equivalente a -B
mfssubfolder=RUTA
monta un directorio específico de MooseFS (predeterminado es /, es decir, el sistema de archivos completo) - equivalente a -S
mfspassword=CONTRASEÑA
autenticarse en el maestro de MooseFS con CONTRASEÑA
mfspreflabels=EXPRESION_ETIQUETAS
especifica etiquetas preferidas para elegir servidores de fragmentos durante la E/S
mfsnbdtimeout=N
define el tiempo máximo de espera en segundos antes de que el kernel renuncie (predeterminado: 1800)

ARCHIVOS

mfsbdev.cfg
archivo de configuración para el daemon de dispositivos de bloque de MooseFS; consulta el manual de mfsbdev.cfg(5) para obtener detalles

EJEMPLOS

mfsbdev start - inicia el daemon nbd con opciones predeterminadas (host_master = mfsmaster, puerto_master = 9421, socket_enlace = /dev/mfs/nbdsock, autenticación sin contraseña)

mfsbdev start -H mfsmaster.my.domain -P 9521 -x /etc/mfs/mastersecret - inicia el daemon nbd que se conectará al maestro mfsmaster.my.domain en el puerto 9521 usando la contraseña leída del archivo /etc/mfs/mastersecret

mfsbdev stop -l /tmp/mynbdinstance - detiene el daemon nbd que usa el socket unix /tmp/mynbdinstance para la comunicación

mfsbdev map -f devices/mybdev1.bin -s 2Ti -n mytestvm - agrega un mapeo al daemon usando el socket de comunicación predeterminado (/dev/mfs/nbdsock). El dispositivo se asignará

mfsbdev(8) — MooseFS manual

NAME

mfsbdev - MooseFS block device management utility

SYNOPSIS

mfsbdev map [-r] [-p] [-s -S_size_] <file> <link_name>

mfsbdev unmap <link_name>

mfsbdev list

DESCRIPTION

mfsbdev is a utility to manage block devices backed by files in MooseFS. It allows mapping a file to a block device node, which can then be used by other applications as a regular block device. This is useful for virtualization, databases, or any other application that requires a block device.

The mapping is done via symbolic links in the /dev/mfs/ directory. For example, mapping a file to a link named mytestvm will create the device node /dev/mfs/mytestvm.

The size of the block device can be specified explicitly or it will be determined by the size of the underlying file.

The block device is created as a loop device using the kernel's loopback device driver.

Changes to the block device are written directly to the underlying file.

OPTIONS

map
Map a file to a block device.
-r, --read-only
Create a read-only block device.
-p, --permanent
Create a permanent mapping that will be restored after reboot. Requires configuration in mfsbdev.cfg.
-s <size>, --size <size>
Set the size of the block device. The size can be specified in bytes or using suffixes like K, M, G, T, P, E (e.g., 10G for 10 Gigabytes). If not specified, the size of the underlying file is used.
unmap
Unmap a block device.
list
List all currently mapped block devices.

FILES

/dev/mfs/
Directory where block device symbolic links are created.
/etc/mfs/mfsbdev.cfg
Configuration file for permanent mappings.

EXAMPLES

mfsbdev map /path/to/mydata.img mytestvm - map the file /path/to/mydata.img to the block device /dev/mfs/mytestvm. The size will be automatically determined by the file size. The mapping is temporary and will be lost on reboot.

mfsbdev map -s 100G /path/to/disk.img myvmdisk - map the file /path/to/disk.img to /dev/mfs/myvmdisk with a size of 100 GiB. The file will be created if it doesn't exist.

mfsbdev map -p -s 2TiB devices/mybdev1.bin mytestvm - map the file devices/mybdev1.bin to the device /dev/mfs/mytestvm, with a size of 2TiB. This mapping will be automatically restored on boot if configured in mfsbdev.cfg.

mfsbdev unmap -n mytestvm - remove the mapping with the link name mytestvm (uses the link /dev/mfs/mytestvm).
