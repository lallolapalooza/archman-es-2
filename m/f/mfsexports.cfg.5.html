NOMBRE

mfsexports.cfg - Control de acceso de MooseFS para montajes de mfsmount

DESCRIPCIÓN

El archivo mfsexports.cfg contiene la lista de acceso de MooseFS para los clientes mfsmount.

SINTAXIS

La sintaxis es:

DIRECCIÓN DIRECTORIO [OPCIONES]

Las líneas que comienzan con el carácter # se ignoran como comentarios.

DIRECCIÓN puede especificarse de varias formas:

*	todas las direcciones
n.n.n.n	dirección IP única
n.n.n.n/b	clase IP especificada por la dirección de red y el número de bits significativos
n.n.n.n/m.m.m.m	clase IP especificada por la dirección de red y la máscara
f.f.f.f-t.t.t.t	rango de IP especificado por direcciones de inicio a fin (inclusive)

DIRECTORIO puede ser / o una ruta relativa a la raíz de MooseFS; el valor especial . significa sistema de archivos complementario MFSMETA.

OPCIONES lista:

ro, readonly
exporta el árbol en modo de solo lectura; este es el predeterminado
rw, readwrite
exporta el árbol en modo de lectura y escritura
alldirs
permite montar cualquier subdirectorio del directorio especificado (similar a NFS)
dynamicip
permite la reconexión de un cliente ya autenticado desde cualquier dirección IP (el valor predeterminado es verificar la dirección IP en la reconexión)
ignoregid
deshabilita la prueba de acceso a grupos a nivel de mfsmaster (todavía se realiza a nivel de mfsmount) - en este caso, los permisos de "grupo" y "otros" se agregan lógicamente; necesario para que los grupos suplementarios funcionen (mfsmaster solo recibe información del grupo principal del usuario)
admin
privilegios administrativos:

cambio de valores de cuota

gestión de clases de almacenamiento - adición, eliminación, modificación

gestión de patrones - adición, eliminación

uso de clases de almacenamiento con el indicador admin (establecer, sobrescribir)

manipulación de los indicadores UNDELETABLE, APPENDONLY e IMMUTABLE en objetos del sistema de archivos

maproot=USUARIO[:GRUPO]
mapea los accesos de root (uid=0) a un usuario y grupo dados (similar a la opción maproot en montajes NFS); USUARIO y GRUPO pueden ser dados como nombre o número; si no se especifica grupo, se utiliza el grupo principal de USUARIO. Los nombres se resuelven en el lado del host mfsmaster (ver nota a continuación).
mapall=USUARIO[:GRUPO]
igual que lo anterior pero mapea todos los usuarios no privilegiados (uid != 0) a un usuario y grupo dados (ver notas a continuación).
umask=0###
este umask se agrega (OR) al umask del usuario y el umask resultante se usa en este punto de montaje
sclassgroups=-|N[:N[:...]]
si esta opción no está definida, cualquier clase de almacenamiento puede ser establecida por el usuario en este punto de montaje; si está definida, solo se pueden establecer las clases de almacenamiento que pertenecen a los grupos listados; para definir ningún grupo (el usuario no puede establecer ninguna clase de almacenamiento) use el signo '-' (menos); para obtener una explicación sobre cómo agregar una clase de almacenamiento a un grupo, vea mfsscadmin(1); para una explicación más detallada, vea GRUPOS DE CLASES DE ALMACENAMIENTO
password=CONTRASEÑA, md5pass=MD5
requiere autenticación con contraseña para acceder al recurso especificado
minversion=VER
rechaza el acceso de clientes más antiguos que el especificado
mintrashretention=TIEMPO, maxtrashretention=TIEMPO
especifica el rango en el que los usuarios pueden establecer la retención de la papelera
mintrashtime=TDUR, maxtrashtime=TDUR
opciones obsoletas (funcionan de manera similar a las anteriores)
disable=OPERACIÓN[:OPERACIÓN[:...]]
no permite que el cliente realice ciertas operaciones

Las opciones predeterminadas son: ro, maproot=999:999, mintrashretention=0, maxtrashretention=4294967295.

Nota: El valor predeterminado para maxtrashretention es imposible de establecer por el usuario, por lo que si el valor no está establecido, puede considerarse cercano a infinito, pero si está establecido, el máximo es 65535 horas (~390 semanas).

NOTAS

Los nombres de USUARIO y GRUPO (si no se especifican por número uid/gid explícito) se resuelven en el host mfsmaster.

TDUR (obsoleto) puede especificarse como un número sin unidad de tiempo (número de segundos) o como una combinación de números con unidades de tiempo. Las unidades de tiempo son: W,D,H,M,S. El orden es importante: las unidades de tiempo menos significativas no se pueden definir antes que las unidades de tiempo más significativas.

TIEMPO puede especificarse como un número de horas (entero) o como un período de tiempo en uno de los dos formatos posibles: primer formato: #.#T donde T es una de: h-horas, d-días o w-semanas; las fracciones de la unidad mínima se redondearán al valor entero; segundo formato: #s#d#h, se puede omitir cualquier número de definiciones, pero las definiciones restantes deben estar en orden (por lo que #s#h sigue siendo una definición válida, pero #h#s no); rangos: h: 0 a 23, d: 0 a 6, w es ilimitado y la primera definición también es siempre ilimitada (es decir, para #d#h, d será ilimitado)

Las unidades/períodos de tiempo no distinguen entre mayúsculas y minúsculas.

La opción mapall funciona en MooseFS de manera diferente que en NFS, porque MooseFS utiliza la opción "default_permissions" de FUSE. Cuando se usa la opción mapall, los usuarios ven todos los objetos con uid igual al uid mapeado como propios y todos los demás como objetos de root. De manera similar, los objetos con gid igual al gid mapeado se ven como objetos con el grupo principal del usuario actual y todos los demás objetos como objetos con grupo 0 (generalmente wheel). Con la opción mapall establecida, la caché de atributos en el kernel siempre se desactiva.

La opción disable puede tomar muchos parámetros (operaciones a deshabilitar) de dos maneras: como una lista separada por dos puntos (:) o repitiendo la opción muchas veces. Lista de operaciones que se pueden deshabilitar:

chown        - no permite al cliente realizar la operación chown
chmod        - no permite al cliente realizar la operación chmod
symlink      - no permite al cliente crear enlaces simbólicos
mkfifo       - no permite al cliente crear FIFOs
mkdev        - no permite al cliente crear dispositivos
mksock       - no permite al cliente crear sockets
mkdir        - no permite al cliente crear directorios
unlink       - no permite al cliente eliminar objetos que no son directorios (¡también negará la operación de mover/renombrar si el inode de destino ya existe!)
rmdir        - no permite al cliente eliminar directorios (¡también negará la operación de mover/renombrar si el inode de destino ya existe!)
rename       - no permite al cliente cambiar los nombres de los inodes (archivos, directorios)
move         - no permite al cliente mover inodes (archivos, directorios) a otra ruta
link         - no permite al cliente crear enlaces duros
create       - no permite al cliente crear archivos nuevos
readdir      - no permite al cliente listar directorios (el comando 'ls' no funcionará)
read         - no permite al cliente leer de archivos
write        - no permite al cliente escribir en archivos
truncate     - no permite al cliente acortar la longitud de un archivo con el comando truncate
setlength    - no permite al cliente aumentar la longitud de un archivo con el comando truncate
appendchunks - no permite al cliente agregar fragmentos de un archivo a otro (mfsappendchunks)
snapshot     - no permite al cliente crear instantáneas
settrash     - no permite al cliente cambiar el tiempo de retención de la papelera
setsclass    - no permite al cliente establecer clases de almacenamiento
seteattr     - no permite al cliente establecer atributos extra de mfs
setxattr     - no permite al cliente establecer XATTRs
setfacl      - no permite al cliente establecer ACLs

NAME

mfsexports.cfg

- MooseFS extentions configuration file

DESCRIPTION

The mfsexports.cfg file defines export rules for MooseFS clients. Each line in the file specifies a network address or range, a path to export, and export options. The file is read by the mfsmaster(8) daemon during startup and upon receiving a SIGHUP signal.

SYNTAX

Each line in the mfsexports.cfg file has the following format:

<source network> <export path> <export options>
  • <source network>: Specifies the network address or range of clients that are allowed to access the export. This can be an IP address, a network address with a netmask (e.g., 192.168.1.0/255.255.255.0), or a network address with a CIDR notation (e.g., 192.168.1.0/24).
  • <export path>: The path to the directory or file within the MooseFS namespace that will be exported.
  • <export options>: A comma-separated list of options that control how the export is accessed. Some common options include:
    • ro: Read-only access.
    • rw: Read-write access.
    • alldirs: Allows clients to mount any subdirectory of the exported path.
    • maproot=<user>: Maps the root user of the client to the specified MooseFS user.
    • mapall=<user>:<group>: Maps all users and groups of the client to the specified MooseFS user and group.
    • password=<password>: Sets a password for accessing the export.
    • mintrashretention=<time>: Sets the minimum retention time for files in the trash.
    • maxtrashretention=<time>: Sets the maximum retention time for files in the trash.
    • disable=<operation>: Disables specific operations for the export (e.g., unlink, rmdir, truncate).
    • sclassgroups=<groups>: Limits the Storage Classes that can be used for files within this export to the specified comma-separated list of Storage Class Group IDs (0-15).

NOTES

The mfsexports.cfg file is processed in order. The first matching rule for a client determines the export settings. If no rule matches, the client is denied access.

The sclassgroups option can be used to restrict the Storage Classes that clients can apply to files within a specific export. This is useful for enforcing storage policies and ensuring that certain types of data are stored on appropriate storage tiers.

First, selected Storage Classes must be assigned to one of 16 (numbered from 0 to 15) Storage Class Groups. This is done when creating or modifying a Storage Class with mfsscadmin tool (see mfsscadmin(1)). Once a group is properly defined, when option sclassgroups is used in a definition of a mountpoint export, a user using this mountpoint export can only apply (set) Storage Classes from the defined group, when they use the mfssclass tool.

Example: if there are four different Storage Classes defined in a cluster, two of them assigned to group 0, two to group 1, and a mountpoint export only allows to use Storage Classes from group 1, users will only be able to set the two Storage Classes that are assigned to group 1, an attempt to set a Storage Class assigned to group 0 will result in an error and the file's class will not be changed. This does NOT affect the Storage Class inheritance rule, that is, if a user creates a new file in a directory belonging to a Storage Class in group 0, this file will belong to the same class in group 0. But if the user subsequently changes the file's Storage Class to one of the classes they are allowed to use (from group 1), they cannot change it back to its original Storage Class, as that class belongs to "forbidden" group 0.

Important! Default Storage Class group is 0, unless another is explicitly set when creating or modifying a Storage Class, so for the purpose of limiting the availability of Storage Classes for users it's better to use group numbers greater than 0.

Legacy systems Up to MooseFS version 4.56.6 the mechanism of Storage Class Groups did not exist. Instead, there were two options mingoal and maxgoal, inherited from previous versions of MooseFS. If any of them were set, a user would be allowed to use only legacy Storage Classes (classes with IDs 1 to 9, named "1" to "9", with KEEP definitions 1* to 9*) with name not lower than mingoal and not higher than maxgoal plus any admin defined classes (ID>9). To simulate this behaviour, in case of an upgrade from a version that still had these classes and also used mingoal and maxgoal in config, the system will assign those legacy classes "1" to "9" to groups 1 to 9, respectively and will convert any mingoal and maxgoal to appropriate sclassgroups expression. Example: if mingoal is set to 3 and maxgoal is set to 5, sclassgroups will be set to 0,3,4,5 - 0 to allow users to use admin-defined classes, 3,4,5 to allow the use of legacy classes "3","4" and "5". The old settings should not be used, system admins should instead define Storage Class Groups of their choice and use the sclassgroups option explicitly.

EXAMPLES

*                    /       ro
192.168.1.0/24       /       rw
192.168.1.0/24       /       rw,alldirs,maproot=0,password=passcode
10.0.0.0-10.0.0.5    /test   rw,maproot=nobody,password=test
10.1.0.0/255.255.0.0 /public rw,mapall=1000:1000
10.2.0.0/16          /       rw,alldirs,maproot=0,mintrashretention=2d12h,maxtrashretention=2w
192.168.1.0/24       /       rw,disable=unlink:rmdir:truncate
192.168.1.0/24       /       rw,disable=unlink,disable=rmdir,disable=truncate
