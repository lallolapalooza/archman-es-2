NOMBRE

mfsipmap.cfg - Mapeos de IP de servidores de chunks de MooseFS

DESCRIPCIÓN

El archivo mfsipmap.cfg contiene listas de remapeos de IPs de servidores de chunks de MooseFS.

SINTAXIS

Formato general del archivo: el contenido son uno o más remapeos de LAN diferentes. Cada remapeo de LAN consiste primero en la lista de IPs de clientes a las que se les remapeararán las IPs de los servidores de chunks y luego los remapeos de los servidores de chunks. El archivo correcto se construye de la siguiente manera: lista de IPs de cliente - lista de remapeos - lista de IPs de cliente - lista de remapeos, etc.

Las IPs de los clientes se pueden definir como clases en dos formatos: IP/MASCARA o IP/BITS:
n.n.n.n/m.m.m.m
n.n.n.n/b
Las definiciones de clase pueden usar IPs acortadas, por ejemplo a.b.c.0/24 es lo mismo que a.b.c/24, y a.b.0.0/255.255.0.0 es lo mismo que a.b/255.255.0.0.

Las IPs de los clientes también se pueden definir como rangos en el formato IP - IP:
f.f.f.f-t.t.t.t

Y finalmente, las IPs de los clientes se pueden definir como IPs individuales, una IP por línea:
n.n.n.n
x.x.x.x

Los remapeos de IP de los servidores de chunks siempre se definen en un formato IP:IP:
n.n.n.n:r.r.r.r
Si la IP de un cliente se define en la lista que precede inmediatamente a este remapeo, el servidor de chunks con la IP en el lado izquierdo del remapeo se presentará a este cliente con la IP en el lado derecho del remapeo.

Las líneas que comienzan con el carácter # se ignoran como comentarios.

NOTAS

Este archivo permite definir remapeos de LAN en casos donde no hay un esquema de numeración común en las LAN, es decir, donde los mismos servidores tienen sufijos de IP diferentes en cada LAN. Si las máquinas tienen sufijos comunes, utilice las opciones MULTILAN_BITS y MULTILAN_CLASSES del archivo mfsmaster.cfg en su lugar.

EJEMPLOS

Contenido del archivo:

192.168.1/24
192.168.2.1-192.168.2.24
192.168.3.20

10.10.10.3:10.20.30.7
10.10.10.4:10.20.33.19

Comportamiento:

Cualquier cliente con una IP que comience con 192.168.1, que comience con 192.168.2 y termine entre 1 y 24, o con la IP 192.168.3.20, si quiere comunicarse con el servidor de chunks con IP 10.10.10.3, lo hará en su lugar usando la IP 10.20.30.7, con el servidor de chunks con IP 10.10.10.4 usará la IP 10.20.33.19.

Contenido del archivo:

192.168.1/24

10.10.10.3:10.20.30.7
10.10.10.4:10.20.33.19

192.168.2.1-192.168.2.24

10.10.10.3:10.20.38.8
10.10.10.5:10.20.38.37

Comportamiento:

Cualquier cliente con una IP que comience con 192.168.1, si quiere comunicarse con el servidor de chunks con IP 10.10.10.3, lo hará en su lugar usando la IP 10.20.30.7, con el servidor de chunks con IP 10.10.10.4 usará la IP 10.20.33.1. Cualquier cliente con una IP que comience con 192.168.2 y termine entre 1 y 24, si quiere comunicarse con el servidor de chunks con IP 10.10.10.3, lo hará en su lugar usando la IP 10.20.38.8, con el servidor de chunks con IP 10.10.10.5 usará la IP 10.20.38.37. Nótese que el mismo servidor de chunks (con IP 10.10.10.3) se presentará a clientes de diferentes listas de IP con diferentes IPs remapeadas.

Nota: las líneas vacías entre secciones no son necesarias, se usan en los ejemplos anteriores solo para facilitar la lectura.
