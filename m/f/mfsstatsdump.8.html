NOMBRE

mfsstatsdump - volcar datos de uso del archivo de estadísticas del maestro en formato csv o png

SINOPSIS

mfsstatsdump -f campos [-i archivo_estadisticas] [-r rango] [-s separador] [-p nombre_archivo_png [-x ancho_grafico] [-y alto_grafico]] [-hHd]

DESCRIPCIÓN

mfsstatsdump vuelca datos de uso del archivo de estadísticas del maestro. Estos son los mismos conjuntos de datos que se utilizan para crear gráficos de interfaz gráfica. La salida puede ser en formato de texto (csv) o en formato gráfico (png). Eso significa que las opciones -p, -x y -y son mutuamente excluyentes con las opciones -h, -H y -d.

El servidor maestro de MooseFS guarda el archivo de estadísticas en el directorio DATA_PATH - ver mfsmaster.cfg(5)

SALIDA

Salida de texto: archivo de texto (csv) donde la primera columna es una marca de tiempo (o fecha si se especificó la opción -d), las siguientes columnas son las especificadas con las opciones -f, formateadas según las opciones utilizadas (ninguna, -s y -h o -H)

Salida gráfica: se crea un archivo png con un gráfico por cada campo especificado con la opción -f, de acuerdo con el esquema de nomenclatura declarado con la opción -p. El tamaño se puede ajustar con las opciones -x y -y.

OPCIONES

-f
nombres de campos separados por ',' (ver sección CAMPOS); al menos un campo es obligatorio; si se usa un asterisco (*), se vuelcan todos los campos
-i
nombre del archivo de estadísticas binarias de mfs (por defecto: ruta_datos_predeterminada/stats.mfs)
-r
tipo de rango: 0 - rango corto (minuto) 1 - rango medio (6 minutos) 2 - rango largo (30 minutos) 3 - rango muy largo (día)
-s
especificar separador de columnas (por defecto: tabulador)
-p
nombre de archivo PNG opcional (el nombre del campo se agregará antes de .png; YYYY -> YYYY_CAMPO.png, YYYY.png -> YYYY_CAMPO.png)
-x
ancho del gráfico PNG (por defecto: 1600)
-y
alto del gráfico PNG (debe ser divisible por 20 - si no, se ajustará; por defecto: 320)
-h
números "legibles por humanos" usando prefijos base 2 (IEC 60027)
-H
números "legibles por humanos" usando prefijos base 10 (SI)
-d
mostrar marcas de tiempo en formato YYYY-MM-DD HH:MM

EJEMPLO

Dump all stats for last hour to csv file separated by comma, showing human-readable numbers:

$ mfsstatsdump -f \* -r 1 -s , -h > stats.csv

Dump selected stats for last 6 minutes to png file:

$ mfsstatsdump -f cpu,memoryrss,space -r 1 -p graphics.png

Dump all stats for the last day to png files (one file per field):

$ mfsstatsdump -f \* -r 3 -p graphics

mfsstatsdump(8) — MooseFS 4.58.2-1

NAME

mfsstatsdump — dump MooseFS metadata server statistics

SYNOPSIS

mfsstatsdump [options]

DESCRIPTION

mfsstatsdump is a tool for dumping MooseFS metadata server statistics.

OPTIONS

-h, --help
Show help message and exit.
-V, --version
Print program version and exit.
-d, --daemon-host
Metadata server hostname or IP address (default: 127.0.0.1).
-p, --daemon-port
Metadata server port (default: 9421).
-f, --format
Output format: “csv” (comma separated values) or “png” (image).
-o, --output
Output file name. If not specified, stdout is used.
-n, --no-header
Do not print header in CSV output.
-c, --no-cache
Do not use cache for fetching stats.

NOTES

Los conjuntos de datos delete y delete_stat en un sistema que funcione correctamente deberían ser aproximadamente iguales, pero no siempre idénticos (en su forma CSV), esto se debe a que el conjunto delete se calcula utilizando el número de solicitudes enviadas por el maestro, y el conjunto delete_stat se calcula utilizando el número de respuestas recibidas de los servidores de fragmentos, por lo que se pueden observar fluctuaciones locales (es decir, un minuto tiene más solicitudes enviadas - un valor más alto en el conjunto delete y al minuto siguiente tiene más respuestas - un valor más alto en el conjunto delete_stat). Pero si se calculara la suma de las diferencias entre los dos conjuntos a lo largo del tiempo, esta suma nunca debería superar un cierto número.

Sin embargo, si existe algún tipo de problema (con la comunicación de red y/o los procesos del servidor de fragmentos) y algunas solicitudes de eliminación de fragmentos se detienen/se pierden, entonces los valores de delete pueden ser constantemente más altos que los valores de delete_stat y la suma de las diferencias entre los dos conjuntos crecerá constantemente con el tiempo.

Lo mismo ocurre con los conjuntos de datos replicate(_stat), create(_stat), change(_stat) y split(_stat).
