NOMBRE

mfschunktool - comprueba la integridad de los fragmentos sin conexión

SINOPSIS

mfschunktool [-f] [-r] [-n] [-e] [-x] [-m directorio_dañados] archivo_fragmento|ruta_disco_mfs ...

DESCRIPCIÓN

mfschunktool comprueba la integridad de los fragmentos utilizando las sumas de verificación CRC almacenadas en la cabecera del fragmento. También puede 'reparar' un fragmento (corregir las sumas de verificación almacenadas). Esta herramienta puede ser útil para comprobar los últimos fragmentos escritos después de una posible corrupción de datos (corte de energía, etc.). Si el parámetro proporcionado es un archivo, la herramienta comprobará ese archivo. Si el parámetro proporcionado es un directorio, la herramienta recorrerá ese directorio recursivamente e intentará comprobar todos los archivos que parezcan ser fragmentos (se llaman como archivos de fragmento o, si se usa la opción -n, también tienen cabeceras como archivos de fragmento, incluso cuando el nombre es incorrecto).

¡Aviso! ¡Esta herramienta nunca debe usarse mientras el proceso del servidor de fragmentos esté activo! Si la herramienta se usa en un disco de fragmentos (también conocido como ruta en el archivo mfshdd.cfg) comprobará si el servidor de fragmentos está funcionando y se negará a operar. Pero si se usa en un solo archivo o subdirectorio, tal comprobación no es posible y es responsabilidad del usuario asegurarse de que la herramienta no se use en fragmentos "en funcionamiento", ya que podría provocar la pérdida de datos.

OPCIONES

-f
activa el modo rápido (en este modo solo se prueba el último bloque, lo que suele ser suficiente para encontrar fragmentos corruptos)
-r
activa el modo de reparación (si las sumas de verificación del fragmento dado no coinciden, se sobrescribirán con las sumas de verificación calculadas utilizando los datos reales)
-n
activa el modo de corrección de nombres (si el nombre del archivo de fragmento no es correcto pero existe una cabecera de archivo adecuada, la herramienta renombrará el archivo dado usando los datos almacenados en la cabecera)
-e
activa la comprobación de CRC de bloque vacío para fragmentos de versión 1.0 (fuerza la comprobación de valores CRC para bloques no existentes; puede fallar en caso de fragmentos truncados)
-x
activa la notificación de comprobación exitosa (imprime el mensaje 'OK' cuando todo es correcto)
-m directorio_dañados
mueve los fragmentos dañados a un directorio especificado directorio_dañados; véase NOTAS

NOTAS

La opción para mover fragmentos dañados a un directorio especificado es muy útil cuando se escanean directorios completos (discos) con fragmentos, y se puede emplear de diferentes maneras, dependiendo de qué otras opciones se utilicen al mismo tiempo.

Si se utiliza la opción -r junto con la opción -m, entonces solo se moverán los fragmentos que no se puedan reparar. Este es un enfoque rápido para la reparación de fragmentos, que repara y limpia el directorio de fragmentos (disco) de una sola vez.

Si solo se utiliza la opción -m, entonces todos los fragmentos dañados se moverán a un directorio especificado. El usuario puede entonces usar mfschunktool de nuevo en este directorio, esta vez con la opción -r, para reparar todos los fragmentos que se puedan reparar, pero solo introducir los fragmentos reparados de nuevo en el sistema si no hay otra copia disponible de otro servidor de fragmentos (una copia que no necesitó una operación de reparación en primer lugar). Este es un enfoque más lento, pero más seguro, para reparar múltiples fragmentos, por ejemplo, después de un corte de energía.
