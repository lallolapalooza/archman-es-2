NOMBRE

mwm — El Gestor de Ventanas de Motif

SINOPSIS

mwm [opciones]

DESCRIPCIÓN

El gestor de ventanas mwm proporciona funciones que facilitan el control (por parte del usuario y del programador) de elementos del estado de las ventanas, como la colocación, el tamaño, la visualización de iconos/normal y la propiedad del foco de entrada.

El gestor de ventanas independiente no es una parte integral de CDE y no admite la comunicación con otros componentes del entorno CDE, como el Gestor de Estilo y el Gestor de Sesión.

Opciones

-display pantalla
Esta opción especifica la pantalla a utilizar; consulte X(1).
-xrm cadena_recurso
Esta opción especifica una cadena de recurso a utilizar.
-multiscreen
Esta opción hace que mwm gestione todas las pantallas de la pantalla. La opción predeterminada es gestionar solo una pantalla.
-name nombre
Esta opción hace que mwm recupere sus recursos utilizando el nombre especificado, como en nombre*recurso.
-screens nombre [nombre [...]]
Esta opción especifica los nombres de recursos que se utilizarán para las pantallas gestionadas por mwm. Si mwm está gestionando una sola pantalla, solo se utiliza el primer nombre de la lista. Si mwm está gestionando varias pantallas, los nombres se asignan a las pantallas en orden, comenzando por la pantalla 0. La pantalla 0 recibe el primer nombre, la pantalla 1 el segundo nombre, y así sucesivamente.

Apariencia

Las siguientes secciones describen los comportamientos predeterminados básicos de las ventanas, los iconos, la caja de iconos, el foco de entrada y el apilamiento de ventanas. La apariencia y el comportamiento del gestor de ventanas se pueden alterar cambiando la configuración de recursos específicos. Los recursos se definen bajo el encabezado "VALORES PREDETERMINADOS DE X".

Pantallas

Por defecto, mwm gestiona solo la única pantalla especificada por la opción -display o la variable de entorno DISPLAY (por defecto, pantalla 0). Si se especifica la opción -multiscreen o si el recurso multiScreen es True, mwm intenta gestionar todas las pantallas de la pantalla.

Cuando mwm gestiona varias pantallas, se puede usar la opción -screens para dar a cada pantalla un nombre de recurso único. Los nombres se separan por espacios, por ejemplo, -screens scr0 scr1. Si hay más pantallas que nombres, los recursos para las pantallas restantes se recuperarán utilizando el primer nombre. Por defecto, se utiliza el número de pantalla para el nombre de la pantalla.

Ventanas

Los marcos de ventana mwm predeterminados tienen componentes distintivos con funciones asociadas:

Área de Título
Además de mostrar el título del cliente, el área del título se utiliza para mover la ventana. Para mover la ventana, coloque el puntero sobre el área del título, presione el botón 1 y arrastre la ventana a una nueva ubicación. Por defecto, se mueve un marco de alambre durante el arrastre para indicar la nueva ubicación. Cuando se suelta el botón, la ventana se mueve a la nueva ubicación.
Barra de Título
La barra de título incluye el área del título, el botón de minimizar, el botón de maximizar y el botón del menú de ventana. En ventanas con forma, como las ventanas redondas, la barra de título flota sobre la ventana.
Botón de Minimizar
Para convertir la ventana en un icono, haga clic con el botón 1 en el botón de minimizar (el cuadro del marco con un cuadrado pequeño en él).
Botón de Maximizar
Para hacer que la ventana ocupe toda la pantalla (o se agrande al tamaño máximo permitido por los archivos de configuración), haga clic con el botón 1 en el botón de maximizar (el cuadro del marco con un cuadrado grande en él).
Botón del Menú de Ventana
El botón del menú de ventana es el cuadro del marco con una barra horizontal en él. Para desplegar el menú de la ventana, presione el botón 1. Mientras presiona, arrastre el puntero en el menú a su selección, luego suelte el botón cuando su selección esté resaltada. Presionar el botón 3 en la barra de título o en los manejadores del borde de redimensionamiento también muestra el menú de la ventana. Alternativamente, puede hacer clic con el botón 1 para desplegar el menú y mantenerlo visible; luego posicione el puntero y seleccione. También puede mostrar el menú de la ventana presionando <Shift> <Esc> o <Alt> <Espacio>. Hacer doble clic con el botón 1 con el puntero sobre el botón del menú de la ventana cierra la ventana.

Iconos

Los iconos son pequeñas representaciones gráficas de las ventanas. Una ventana se puede minimizar (iconificar) utilizando el botón de minimizar en el marco de la ventana. Los iconos proporcionan una forma de reducir el desorden en la pantalla.

Presionar el botón del ratón 1 cuando el puntero está sobre un icono hace que aparezca el menú de la ventana del icono. Soltar el botón (presionar + soltar sin mover el ratón = clic) hace que el menú permanezca visible. El menú contiene las siguientes selecciones:

Icon Management

The mwm window manager supports two types of icons: window icons and icon box icons. Window icons are the default icons associated with a window. Icon box icons are icons that have been packed into an icon box. (To use an icon box, mwm must be started with the icon box configuration already set.)

The following table summarizes the behavior of this interface. Button actions apply whenever the pointer is on any part of the icon. Note that double-clicking an icon restores it to its previous state. For example, if a maximized window is iconified, double-clicking button 1 restores it to its maximized state. Double-clicking button 1 on the icon box's icon opens the icon box and allows access to the contained icons. (In general, double-clicking a mouse button is a quick way to perform a function.) Pressing <Shift> <Esc> or <Menu> (the pop-up menu key) causes the icon window menu of the currently selected icon to pop up.

Icon Box

When icons begin to clutter the screen, they can be packed into an icon box. (To use an icon box, mwm must be started with the icon box configuration already set.) The icon box is a mwm window that holds client icons. It includes one or more scroll bars when there are more window icons than the icon box can show at the same time.

Icons in the icon box can be manipulated with the mouse. The following table summarizes the behavior of this interface. Button actions apply whenever the pointer is on any part of the icon. Note that double-clicking an icon in the icon box invokes the f.restore_and_raise function.

Input Focus

The mwm window manager supports (by default) a keyboard input focus policy of explicit selection. This means when a window is selected to get keyboard input, it continues to get keyboard input until the window is withdrawn from window management, another window is explicitly selected to get keyboard input, or the window is iconified. Several resources control the input focus. The client window with the keyboard input focus has the active window appearance with a visually distinct window frame.

The following tables summarize the keyboard input focus selection behavior:

Window Stacking

There are two types of window stacks: global window stacks and an application's local family window stack.

The global stacking order of windows may be changed as a result of setting the keyboard input focus, iconifying a window, or performing a window manager window stacking function. When keyboard focus policy is explicit the default value of the focusAutoRaise resource is True. This causes a window to be raised to the top of the stack when it receives input focus, for example, by pressing button 1 on the title bar. The key actions defined in the previous table will thus raise the window receiving focus to the top of the stack.

In pointer mode, the default value of focusAutoRaise is False, that is, the window stacking order is not changed when a window receives keyboard input focus. The following key actions can be used to cycle through the global window stack.

Key Action Function Description
[Alt][ESC] Place top window on bottom of stack.
[Alt][Shift][ESC] Place bottom window on top of stack.

By default, a window's icon is placed on the bottom of the stack when the window is iconified; however, the default can be changed by the lowerOnIconify resource.

Transient windows (secondary windows such a dialog boxes) stay above their parent windows by default; however, an application's local family stacking order may be changed to allow a transient window to be placed below its parent top-level window. The following arguments show the modification of the stacking order for the f.lower function.

f.lower
Lowers the transient window within the family (staying above the parent) and lowers the family in the global window stack.
f.lower [ within]
Lowers the transient window within the family (staying above the parent) but does not lower the family in the global window stack.
f.lower [freeFamily ]
Lowers the window free from its family stack (below the parent), but does not lower the family in the global window stack.

The arguments within and freeFamily can also be used with f.raise and f.raise_lower.

Session Management

The window manager is an X Session Management Protocol aware client. It responds to SaveYourself (and other associated messages) by saving the geometries of its clients to a state file. mwm can then be restarted by the XSMP session manager. The default location for the state file is $HOME/.mwmclientdb. This location can be overriden with the resource sessionClientDB.

X Resources

The mwm command is configured from its resource database. This database is built from the following sources. They are listed in order of precedence, low to high:

/usr/X11R6/lib/X11/app-defaults/Mwm

$HOME/Mwm

RESOURCE_MANAGER root window property or $HOME/.Xdefaults

XENVIRONMENT variable or $HOME/.Xdefaults-host

mwm command line options

The file names /usr/X11R6/lib/X11/app-defaults/Mwm and $HOME/Mwm represent customary locations for these files. The actual location of the system-wide class resource file may depend on the XFILESEARCHPATH environment variable and the current language environment. The actual location of the user-specific class resource file may depend on the XUSERFILESEARCHPATH and XAPPLRESDIR environment variables and the current language environment.

Entries in the resource database may refer to other resource files for specific types of resources. These include files that contain bitmaps, fonts, and mwm specific resources such as menus and behavior specifications (for example, button and key bindings).

Mwm is the resource class name of mwm and mwm is the default resource name used by mwm to look up resources. the -screens command line option specifies resource names, such as "mwm_b+w" and "mwm_color".) In the following discussion of resource specification, "Mwm" and "mwm" (and the aliased mwm resource names) can be used interchangeably, but "mwm" takes precedence over "Mwm".

The mwm command uses the following types of resources:

Component Appearance Resources:
These resources specify appearance attributes of window manager user interface components. They can be applied to the appearance of window manager menus, feedback windows (for example, the window reconfiguration feedback window), client window frames, and icons.
General Appearance and Behavior Resources:
These resources specify mwm appearance and behavior (for example, window management policies). They are not set separately for different mwm user interface components. They apply to all screens and workspaces.
Screen Specific Appearance and Behavior Resources:
These resources specify the appearance and behavior of mwm elements that are settable on a per-screen basis.

Recursos de apariencia de componentes

La sintaxis para especificar recursos de apariencia de componentes que se aplican a los iconos, menús y marcos de ventanas de cliente del gestor de ventanas es Mwm* resource_id

Por ejemplo, Mwm*foreground se utiliza para especificar el color de primer plano para los menús, iconos, marcos de ventanas de cliente y diálogos de retroalimentación de mwm.

La sintaxis para especificar recursos de apariencia de componentes que se aplican a un componente particular de mwm es Mwm*[menu|icon|client|feedback] *resource_id

Si se especifica menu, el recurso se aplica solo a los menús de mwm; si se especifica icon, el recurso se aplica a los iconos; y si se especifica client, el recurso se aplica a los marcos de ventanas de cliente. Por ejemplo, Mwm*icon*foreground se utiliza para especificar el color de primer plano para los iconos de mwm, Mwm*menu*foreground especifica el color de primer plano para los menús de mwm, y Mwm*client*foreground se utiliza para especificar el color de primer plano para los marcos de ventanas de cliente de mwm.

La apariencia del área del título del marco de una ventana de cliente (incluidos los botones de gestión de ventanas) se puede configurar por separado. La sintaxis para configurar el área del título del marco de una ventana de cliente es Mwm*client*title* resource_id

Por ejemplo, Mwm*client*title*foreground especifica el color de primer plano para el área del título. Los valores predeterminados para los recursos del área del título se basan en los valores de los recursos correspondientes del marco de la ventana del cliente.

La apariencia de los menús se puede configurar según el nombre del menú. La sintaxis para especificar la apariencia del menú por nombre es Mwm*menu* menu_name*resource_id

Por ejemplo, Mwm*menu*my_menu*foreground especifica el color de primer plano para el menú llamado my_menu. El usuario también puede especificar recursos para componentes de menú del gestor de ventanas, es decir, los gadgets que componen el menú. Estos pueden incluir, por ejemplo, un título de menú, un separador de título, uno o más botones y separadores. Si un menú contiene más de una instancia de una clase, como varios PushButtonGadgets, el nombre de la primera instancia es "PushButtonGadget1", la segunda es "PushButtonGadget2", y así sucesivamente. Una aplicación también puede especificar qué funciones debe aplicar mwm a sus ventanas. Si lo hace, mwm aplica solo aquellas funciones indicadas tanto por la aplicación como por el recurso transientFunctions. Si a este recurso se le da un valor de True, los iconos se colocan en una caja de iconos. Cuando no se utiliza una caja de iconos, los iconos se colocan en la ventana raíz (valor predeterminado).

Recursos Específicos del Cliente

La sintaxis para especificar recursos específicos del cliente es

Mwm*nombre_o_clase_del_cliente *id_del_recurso

Por ejemplo, Mwm*mterm*windowMenu se utiliza para especificar el menú de ventana que se usará con los clientes de mterm. La sintaxis para especificar recursos específicos del cliente para todas las clases de clientes es

Mwm*id_del_recurso

Las especificaciones de clientes específicas tienen precedencia sobre las especificaciones para todos los clientes. Por ejemplo, Mwm*windowMenu se utiliza para especificar el menú de ventana que se usará para todas las clases de clientes que no tengan un menú de ventana especificado.

La sintaxis para especificar valores de recursos para ventanas que tienen un nombre y clase desconocidos (es decir, ventanas que no tienen una propiedad WM_CLASS asociada con ellas) es

Mwm*defaults*id_del_recurso

Por ejemplo, Mwm*defaults*iconImage se utiliza para especificar la imagen del icono que se utilizará para las ventanas que tienen un nombre y clase desconocidos.

Archivo de descripción de recursos

El archivo de descripción de recursos de mwm es un archivo de recursos suplementario que contiene descripciones de recursos a las que se hace referencia en las entradas de la propiedad del administrador de recursos (consulte xrdb(1) y los archivos de valores predeterminados (.Xdefaults, app-defaults/Mwm ). Contiene descripciones de recursos que deben ser utilizados por mwm, y que no pueden ser codificados fácilmente en los archivos de valores predeterminados (un archivo de mapa de bits es un tipo análogo de archivo de descripción de recursos). Se puede seleccionar un archivo de descripción de recursos de mwm particular utilizando el recurso configFile.

Los siguientes tipos de recursos se pueden describir en el archivo de descripción de recursos de mwm:

Botones
Las funciones del administrador de ventanas se pueden vincular (asociar) a eventos de botón.
Teclas
Las funciones del administrador de ventanas se pueden vincular (asociar) a eventos de pulsación de tecla.
Menús
Los paneles de menú se pueden utilizar para el menú de la ventana y otros menús que se muestran con enlaces de teclado y enlaces de botón.
El archivo de descripción de recursos de mwm se describe en mwmrc(4).

Entorno

El administrador de ventanas mwm utiliza la variable de entorno HOME para especificar el directorio principal del usuario.

El administrador de ventanas mwm utiliza la variable de entorno LANG para especificar la elección del idioma del usuario para el catálogo de mensajes de mwm y el archivo de descripción de recursos de mwm.

El administrador de ventanas mwm utiliza las variables de entorno XFILESEARCHPATH, XUSERFILESEARCHPATH, XAPPLRESDIR, XENVIRONMENT, LANG y HOME para determinar las rutas de búsqueda de los archivos de valores predeterminados de recursos. El administrador de ventanas mwm también puede utilizar XBMLANGPATH para buscar archivos de mapa de bits.

El administrador de ventanas mwm lee el archivo $HOME/.motifbind si existe para instalar una propiedad de enlaces de teclas virtuales en la ventana raíz. Para más información sobre el contenido del archivo .motifbind, consulte
