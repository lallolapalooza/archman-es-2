MPOST(1) Manual de Comandos Generales MPOST(1)

NOMBRE

mpost, pmpost, upmpost - MetaPost, un sistema para crear gráficos r-mpost, r-pmpost, r-upmpost - MetaPost restringido

SINOPSIS

mpost [opciones] [comandos]

mpost --dvitomp archivo.dvi[.dvi] [archivo.mpx[.mpx]]

DESCRIPCIÓN

MetaPost interpreta el lenguaje MetaPost y produce gráficos PostScript (EPS) o Scalable Vector Graphics (SVG). El lenguaje MetaPost es similar a Metafont de Knuth, con características adicionales para incluir comandos de tex(1) o troff(1) y acceder a características de PostScript no encontradas en Metafont.

MetaPost se usa normalmente con un conjunto de macros básicas, y usará su nombre de ejecutable como nombre del archivo de precarga a utilizar. Por ejemplo, cuando se llama como mpost se usa el archivo mpost.mp, que simplemente lee plain.mp. Cuando se da la opción --ini, la precarga no ocurre.

Los comandos dados en la línea de comandos al programa MetaPost se le pasan como la primera línea de entrada. (Pero a menudo es más fácil escribir argumentos extendidos como la primera línea de entrada, ya que los shells de UNIX tienden a tragarse o malinterpretar los símbolos favoritos de MetaPost, como los puntos y comas, a menos que los cite.) El uso normal es decir mpost figs para procesar el archivo figs.mp. El nombre base de figs se convierte en el "nombre del trabajo", y se utiliza para formar los nombres de los archivos de salida. Si no se nombra ningún archivo, el nombre del trabajo se convierte en mpout. La extensión predeterminada, .mp, se puede anular especificando una extensión explícitamente.

Cuando se da la opción --dvitomp, MetaPost actúa únicamente como un conversor DVI-a-MPX. Consulte dvitomp (1) para obtener detalles.

El programa pmpost es una variante con soporte japonés, y upmpost tiene soporte japonés habilitado para Unicode, análogo a ptex y uptex.

Las tres variantes también se instalan con un prefijo `r-', es decir, r-mpost, r-pmpost, r-upmpost, que especifican implícitamente la opción --restricted para hacer que MetaPost sea seguro de ejecutar en entradas desconocidas; los comandos tex, makempx y editor se deshabilitan.

Esta página del manual es solo un esqueleto. Para obtener una lista de todas las opciones de línea de comandos, ejecute --help.

La documentación principal de esta versión de MetaPost se encuentra en el Manual del Usuario que debería haberse instalado junto con el programa y también está disponible en https://tug.org/metapost.

El lenguaje MetaPost es similar a Metafont, pero el manual asume ningún conocimiento de Metafont. MetaPost no tiene comandos de salida de mapa de bits ni el mecanismo de visualización en línea de Metafont.

ARCHIVOS

plain.mp
El archivo de precarga estándar.
mfplain.mp
El archivo de precarga compatible con Metafont.
$TEXMFMAIN/metapost/base/*.mp
Las macros estándar de MetaPost incluidas en la distribución original.
$TEXMFMAIN/metapost/support/*
Varias tablas para manejar tex y troff incluidos.
$TEXMFMAIN/metapost/support/trfonts.map
Tabla de nombres de fuentes correspondientes para troff y PostScript.
psfonts.map
Tabla de nombres de fuentes correspondientes para tex y PostScript.
$TEXMFMAIN/doc/metapost/*
El manual de MetaPost y el código fuente del tutorial, que también incluye figuras de ejemplo.

AUTORES

MetaPost fue creado por John D. Hobby, incorporando algoritmos de Metafont de Donald E. Knuth. Originalmente se implementó en Unix, incorporando rutinas dependientes del sistema de web2c, sin depender de él excepto para el traductor real de Web a C.

Ulrik Vieth adaptó MetaPost para aprovechar las funciones avanzadas de búsqueda de rutas en versiones más recientes de web2c y trabajó para integrar completamente MetaPost en la distribución canónica de TeX para Unix.

El autor principal de MetaPost actual fue Taco Hoekwater, con la ayuda de Hans Hagen y muchos otros. Actualmente es mantenido por Luigi Scarso.
