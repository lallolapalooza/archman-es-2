mcheck(3) Manual de funciones de biblioteca mcheck(3)

NOMBRE

mcheck, mcheck_check_all, mcheck_pedantic, mprobe - comprobación de consistencia de la pila de memoria

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <mcheck.h>
int mcheck(typeof(void (enum mcheck_status mstatus)) *f);
int mcheck_pedantic(
           typeof(void (enum mcheck_status mstatus)) *f);
void mcheck_check_all(void);
enum mcheck_status mprobe(void *ptr);

DESCRIPCIÓN

La función mcheck() instala un conjunto de ganchos de depuración para las funciones de asignación de memoria de la familia malloc(3). Estos ganchos realizan ciertas comprobaciones de consistencia sobre el estado de la pila de memoria. Las comprobaciones pueden detectar errores de aplicación como liberar un bloque de memoria más de una vez o corromper las estructuras de datos de gestión que preceden inmediatamente a un bloque de memoria asignada.

Para ser efectivo, la función mcheck() debe llamarse antes de la primera llamada a malloc(3) o una función relacionada. En casos donde esto es difícil de asegurar, enlazar el programa con -lmcheck inserta una llamada implícita a mcheck() (con un argumento NULL) antes de la primera llamada a una función de asignación de memoria.

La función mcheck_pedantic() es similar a mcheck(), pero realiza comprobaciones en todos los bloques asignados cada vez que se llama a una de las funciones de asignación de memoria. ¡Esto puede ser muy lento!

La función mcheck_check_all() provoca una comprobación inmediata en todos los bloques asignados. Esta llamada solo es efectiva si se llamó previamente a mcheck().

Si el sistema detecta una inconsistencia en la pila de memoria, se invoca la función proporcionada por el llamador apuntada por f con un único argumento, mstatus, que indica qué tipo de inconsistencia se detectó. Si f es NULL, una función predeterminada imprime un mensaje de error en stderr y llama a abort(3).

La función mprobe() realiza una comprobación de consistencia en el bloque de memoria asignada apuntado por ptr. Se debe llamar a la función mcheck() previamente (de lo contrario, mprobe() devuelve MCHECK_DISABLED).

La siguiente lista describe los valores devueltos por mprobe() o pasados como argumento mstatus cuando se invoca f:

MCHECK_DISABLED (solo mprobe())
mcheck() no se llamó antes de llamar a la primera función de asignación de memoria. La comprobación de consistencia no es posible.
MCHECK_OK (solo mprobe())
No se detectó ninguna inconsistencia.
MCHECK_HEAD
Se corrompió la memoria que precede a un bloque asignado.
MCHECK_TAIL
Se corrompió la memoria que sigue a un bloque asignado.
MCHECK_FREE
Un bloque de memoria fue liberado dos veces.

VALOR DE RETORNO

mcheck() y mcheck_pedantic() devuelven 0 si tienen éxito, o -1 si ocurre un error.

NOTAS

Enlazar un programa con -lmcheck y usar la variable de entorno MALLOC_CHECK_ (descrita en mallopt(3)) provocan la detección de los mismos tipos de errores. Pero, usar MALLOC_CHECK_ no requiere que la aplicación se vuelva a enlazar.

EJEMPLOS

El siguiente programa llama a mcheck() con un argumento NULL y luego libera la misma zona de memoria dos veces. La siguiente sesión de shell demuestra lo que sucede al ejecutar el programa:


$ ./a.out
A punto de liberar
A punto de liberar por segunda vez
bloque liberado dos veces
Aborted (core dumped)

Código fuente del programa

#include <mcheck.h>
#include <stdio.h>
#include <stdlib.h>
int
main(void)
{
    char *p;
    if (mcheck(NULL) != 0) {
        fprintf(stderr, "mcheck() falló\n");
        exit(EXIT_FAILURE);
    }
    p = malloc(1000);
    fprintf(stderr, "A punto de liberar\n");
    free(p);
    fprintf(stderr, "\nA punto de liberar por segunda vez\n");
    free(p);
    exit(EXIT_SUCCESS);
}
