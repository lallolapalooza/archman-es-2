NOMBRE

mpopd - Un servidor POP3 mínimo

SINOPSIS

mpopd [opción...]

DESCRIPCIÓN

Mpopd es un servidor POP3 mínimo que entrega correos de un buzón local en formato maildir. Puede ser utilizado por usuarios finales como una forma de manejar el correo entrante con mpop con clientes de correo que insisten en usar POP3. Ver la sección EJEMPLOS abajo.
Mpopd escucha en 127.0.0.1, puerto 1100 por defecto, pero también puede ejecutarse sin sus propios sockets de red en modo inetd, donde maneja una única sesión POP3 en la entrada / salida estándar.
Para prevenir abusos, mpopd solo permitirá un número limitado de sesiones POP3 concurrentes, y si ocurre un fallo de autenticación, las futuras solicitudes de autenticación en cualquier sesión POP3 (durante un tiempo limitado) solo serán respondidas después de un pequeño retraso.

OPCIONES

--version
Imprimir información de la versión
--help
Imprimir ayuda
--inetd
Iniciar una única sesión POP3 en stdin/stdout
--interface=ip
Escuchar en la dirección IPv6 o IPv4 dada en lugar de 127.0.0.1
--port=número
Escuchar en el número de puerto dado en lugar de 25
--log=ninguno|syslog|nombre_archivo
Establecer registro: ninguno (por defecto), syslog, o registro en el archivo dado.
--auth=usuario[,eval_contraseña]
Requerir autenticación con este nombre de usuario. La contraseña se obtendrá del comando eval_contraseña dado (esto funciona igual que eval_contraseña en mpop) o, si no se proporciona ninguna, del llavero o, si falla, de una solicitud.
--maildir=directorio
Usar este maildir como el buzón.

EJEMPLOS

Usando mpopd para manejar correo entrante para un cliente de correo basado en POP3
Algunos clientes de correo no pueden recibir correo entrante de archivos locales y en su lugar insisten en usar un servidor POP3. Puedes configurar mpopd para que sea ese servidor POP3 y sirva tu correo entrante desde un directorio maildir local.
(De manera similar, algunos clientes de correo no pueden enviar correo saliente a través de un programa como msmtp y en su lugar insisten en usar un servidor SMTP. Puedes configurar msmtpd para que sea ese servidor SMTP y entregue el correo a msmtp. Ver la sección relevante en el manual de msmtp.)
Para este propósito, mpopd debe escuchar en un puerto no privilegiado, p.ej., 1100 (el predeterminado). Se define un buzón usando primero la opción --auth para establecer un nombre de usuario y contraseña, y luego usando la opción --maildir para especificar la carpeta maildir que contiene el correo entrante. Se pueden usar múltiples pares de opciones de este tipo para definir múltiples buzones, p.ej., de diferentes cuentas de correo remotas. Programas como mpop pueden entregar nuevo correo en las carpetas maildir en cualquier momento, pero mientras mpopd esté en ejecución, ningún otro programa podrá modificar o eliminar correos de estas carpetas.
Usemos el nombre de usuario mpopd-user. Tienes dos opciones para administrar la contraseña:

Almacena la contraseña en tu llavero, p.ej., con secret-tool store --label=mpopd host localhost service pop3 user mpopd-user. En este caso, usa la opción mpopd --auth=mpopd-user.
Almacena la contraseña en un archivo cifrado y usa el mecanismo de eval_contraseña. Ejemplo para gpg: mpopd ... --auth=mpopd-user,'gpg -q -d ~/.mpopd-password.gpg'

El comando completo entonces es (usando el llavero): mpopd --auth=mpopd-user --maildir=/ruta/a/tu/directorio/maildir
El software del cliente de correo debe configurarse entonces para usar localhost en el puerto 1100 para correo entrante vía POP3, y para usar autenticación con el usuario mpopd-user y la contraseña que elegiste. El cliente de correo probablemente se quejará de que el servidor POP3 no soporta TLS, pero en este caso especial eso está bien ya que toda la comunicación entre tu cliente de correo y mpopd permanecerá en la máquina local.
