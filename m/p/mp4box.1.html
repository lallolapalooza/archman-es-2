MP4Box - Empaquetador de medios de línea de comandos de GPAC

SINOPSIS

Opciones Generales

MP4Box es un empaquetador multimedia, con una gran cantidad de funcionalidades: conversión, división, marcado (hinting), volcado (dumping), DASH-ing, cifrado, transcodificación y otras.
MP4Box proporciona un amplio conjunto de opciones, clasificadas por categorías (ver .I -h). Estas opciones no siguen ningún orden particular.

Por defecto, MP4Box reescribe el archivo de entrada. Puede cambiar este comportamiento utilizando la opción .I out.
MP4Box almacena por defecto el archivo con una intercalación (interleaving) de 0.5 segundos y metadatos (moov ...) al principio, haciéndolo adecuado para descarga y reproducción por HTTP. Esto, sin embargo, puede tardar más en almacenar el archivo, use .I flat para cambiar este comportamiento.

MP4Box usualmente genera un archivo temporal al crear un nuevo archivo IsoMedia. La ubicación de este archivo temporal depende del SO, y puede ocurrir que la unidad/partición donde se crea el archivo temporal no tenga suficiente espacio o no tenga acceso de escritura. En tal caso, puede especificar una ubicación de archivo temporal con .I tmp.

El identificador de pista para operaciones basadas en pistas (generalmente referido como tkID en la ayuda) utiliza la siguiente sintaxis:
* INT: el objetivo es la pista con ID INT
* n`INT`: el objetivo es la pista número INT
* `audio`, `video`, `text`: el objetivo es la primera pista de audio, video o texto
* `audioN`, `videoN`, `textN`: el objetivo es la N-ésima pista de audio, video o texto, con N=1 siendo la primera pista del tipo deseado

Valores de las opciones:
A menos que se especifique lo contrario, una opción de operación de pista de tipo entero espera un valor identificador de pista a continuación.
Una opción de tipo booleano no espera ningún valor a continuación.

Opciones

-dash (número)

crea DASH a partir de archivos de entrada con una duración de segmento (subsegmento para el perfil onDemand) dada en ms
-dash-live (número)

genera una sesión DASH en vivo utilizando la duración del segmento dada en ms; usar -dash-live=F también escribirá el contexto en vivo en F. MP4Box ejecutará la sesión en vivo hasta que se presione q o ocurra un error fatal
-ddbg-live (número)

igual que .I dash-live sin regulación de tiempo para fines de depuración
-frag (número)

especifica la duración del fragmento en ms. Si no se establece, esta es la duración DASH (un fragmento por segmento)
-out (cadena)

especifica el nombre del archivo MPD de salida
-profile,-dash-profile (cadena)

especifica el perfil DASH de destino y establece opciones predeterminadas para garantizar la conformidad con el perfil deseado. El perfil predeterminado es "full" en modo estático, "live" en modo dinámico (la sintaxis antigua que usa :live en lugar de .live como separador todavía es posible). Los valores definidos son onDemand, live, main, simple, full, hbbtv1.5.live, dashavc264.live, dashavc264.onDemand, dashif.ll
-profile-ext (cadena)

especifica una lista de extensiones de perfil, como las utilizadas por DASH-IF y DVB. La cadena se concatenará con dos puntos con el perfil utilizado
-rap

asegura que los segmentos comiencen con puntos de acceso aleatorio, las duraciones de los segmentos pueden variar según la codificación de origen
-frag-rap

asegura que todos los fragmentos comiencen con puntos de acceso aleatorio (la duración puede variar según la codificación de origen)
-segment-name (cadena)

establece el nombre del segmento para los segmentos generados. Si no se establece (predeterminado), los segmentos se concatenan en el archivo de salida, excepto en el perfil live donde se llama dash_%%s. Las cadenas de reemplazo admitidas son:
- $Number[%%0Nd]$ se reemplaza por el número de segmento, posiblemente prefijado con 0
- $RepresentationID$ se reemplaza por el nombre de la representación
- $Time$ se reemplaza por la hora de inicio del segmento
- $Bandwidth$ se reemplaza por el ancho de banda de la representación
- $Init=NAME$ se reemplaza por NAME para el segmento init, ignorado de lo contrario
- $Index=NAME$ se reemplaza por NAME para los segmentos index, ignorado de lo contrario
- $Path=PATH$ se reemplaza por PATH al crear segmentos, ignorado de lo contrario
- $Segment=NAME$ se reemplaza por NAME para los segmentos de medios, ignorado para los segmentos init
-segment-ext (cadena, predeterminado: m4s)

establece la extensión del segmento, null significa sin extensión
-init-segment-ext (cadena, predeterminado: mp4)

establece la extensión del segmento para los segmentos de inicialización, índice y cambio de bits, null significa sin extensión
-segment-timeline

usa SegmentTimeline al generar segmentos
-segment-marker (cadena)

agrega una caja del tipo dado (4CC) al final de cada segmento DASH
-insert-utc

inserta el reloj UTC al principio de cada segmento ISOBMF
-base-url (cadena)

establece la URL base en el nivel MPD. Se puede usar varias veces.
Advertencia: esto no modifica la ubicación de los archivos generados
-mpd-title (cadena)

establece el título MPD
-mpd-source (cadena)

establece la fuente del MPD
-mpd-info-url (cadena)

establece la URL de información del MPD
-cprt (cadena)

agrega cadena de derechos de autor al MPD
-dash-ctx (cadena)

almacena/restaura el tiempo DASH del archivo indicado
-dynamic

usa tipo MPD dinámico en lugar de estático
-last-dynamic

igual que .I dynamic pero cierra el período (inserta la marca lmsg si es necesario y actualiza la duración)
-mpd-duration (número)

establece la duración en segundos de una sesión en vivo (si es 0, debes usar .I mpd-refresh)
-mpd-refresh (número)

especifica el tiempo de actualización del MPD en segundos
-time-shift (int)

especifica la profundidad del búfer de desplazamiento de tiempo del MPD en segundos, -1 para mantener todos los archivos)
-subdur (número)

especifica la duración máxima en ms del archivo de entrada a "dashear" en modo LIVE o contexto. Si no hay suficientes muestras para completar un segmento, los datos se repiten a menos que se use .I no-loop, lo que activa el final del período.

División de archivos

MP4Box puede dividir archivos de entrada por tamaño, duración o extraer una parte determinada del archivo en nuevos archivos IsoMedia.
Esto requiere que como máximo una pista en el archivo de entrada tenga puntos que no sean de acceso aleatorio (típicamente como máximo una pista de video).
La división ignorará todas las pistas de sistemas MPEG-4 y las pistas de indicación (hint tracks), pero intentará dividir las pistas de medios privadas.
El archivo de entrada debe tener suficientes puntos de acceso aleatorio para poder ser dividido. Si este no es el caso, tendrás que volver a codificar el contenido.
Puedes agregar medios a un archivo y dividirlo en el mismo paso. En este caso, el archivo de destino (el que se obtendría sin dividir) no se almacenará.

Los rangos de tiempo se especifican de la siguiente manera:
* `S-E`: S inicio y E fin de tiempos, formateados como HH:MM:SS.ms, MM:SS.ms o tiempo en segundos (int, double, fracción)
* `S:E`: S tiempo de inicio y E tiempo de fin en segundos (int, double, fracción). Si E va precedido por D, esto establece E = S + tiempo
* `S:end` o `S:end-N`: S tiempo de inicio en segundos (int, double), N número de segundos (int, double) antes del final

La división de MP4Box ejecuta una sesión de filtro utilizando el filtro reframer de la siguiente manera:
- la opción splitrange del reframer siempre se establece
- la fuente se desmultiplexa con la opción alltk establecida
- los rangos de inicio y fin se pasan a las opciones xs y xe del reframer
- para -splitz, se fuerzan las opciones xadjust y xround=after
- para -splitg, se fuerzan las opciones xadjust y xround=before
- para -splitf, se fuerza la opción xround=seek y propbe_refset si no se especifica en el prompt
- para -splitx, se fuerzan las opciones xround=closest y propbe_ref si no se especifican en el prompt

El modo de almacenamiento de salida predeterminado es interleaving completo y requerirá un archivo temporal para cada salida. Este comportamiento se puede modificar utilizando -flat, -newfs, -inter y -frag.
Los nombres de archivo de salida se pueden especificar usando -out y plantillas (por ejemplo, -out split$num%04d$.mp4 produce split0001.mp4, split0002.mp4, ...).
Se pueden especificar varios rangos de tiempo como una lista separada por comas para -splitx, -splitz y -splitg.

-split (string)

dividir en archivos de duración máxima dada (número flotante) en segundos. Se puede especificar una unidad final:
* `M`, `m`: la duración es en minutos
* `H`, `h`: el tamaño es en horas
-split-rap,-splitr (string)

dividir en archivos en cada nuevo RAP (punto de acceso aleatorio)
-split-size,-splits (string)

dividir en archivos de tamaño máximo dado (número entero) en kilobytes. Se puede especificar una unidad final:
* `M`, `m`: el tamaño es en megabytes
* `G`, `g`: el tamaño es en gigabytes
-split-chunk,-splitx (string)

extraer el rango de tiempo especificado de la siguiente manera:
- la hora de inicio se mueve al punto de muestra RAP más cercano a la hora de inicio especificada
- la hora de fin se mantiene según lo solicitado
-splitz (string)

extraer el rango de tiempo especificado de modo que los rangos A:B y B:C compartan exactamente el mismo límite B:
- la hora de inicio se mueve al punto RAP en o después de la hora de inicio especificada
- la hora de fin se mueve al fotograma anterior al punto RAP en o después de la hora de fin especificada
-splitg (string)

extraer el rango de tiempo especificado de la siguiente manera:
- la hora de inicio se mueve al punto RAP en o antes de la hora de inicio especificada
- la hora de fin se mueve al fotograma anterior al punto RAP en o después de la hora de fin especificada

Importing Options

File importing

Syntax is .I add / .I cat URL[#FRAGMENT][:opt1...:optN=val]
This process will create the destination file if not existing, and add the track(s) to it. If you wish to always create a new destination file, add .I -new.
The supported input media types depend on your installation, check filters documentation for more info.

To select a desired media track from a source, a fragment identifier '#' can be specified, before any other options. The following syntax is used:
* `#video`: adds the first video track found in source
* `#audio`: adds the first audio track found in source
* `#auxv`: adds the first auxiliary video track found in source
* `#pict`: adds the first picture track found in source
* `#trackID=ID` or `#ID`: adds the specified track. For IsoMedia files, ID is the track ID. For other media files, ID is the value indicated by MP4Box -info inputFile
* `#pid=ID`: number of desired PID for MPEG-2 TS sources
* `#prog_id=ID`: number of desired program for MPEG-2 TS sources
* `#program=NAME`: name of desired program for MPEG-2 TS sources

By default all imports are performed sequentially, and final interleaving is done at the end; this however requires a temporary file holding original ISOBMF file (if any) and added files before creating the final output. Since this can become quite large, it is possible to add media to a new file without temporary storage, using .I -flat option, but this disables media interleaving.

If you wish to create an interleaved new file with no temporary storage, use the .I -newfs option. The interleaving might not be as precise as when using .

Sé que es dependiente de la programación de la entrada del multiplexor (cada ejecución podría dar lugar a un resultado ligeramente diferente). Además en este modo:
- Algunas opciones de multiplexación (marcadas con X a continuación) se activarán para todas las entradas (por ejemplo, no es posible importar una pista AVC con xps_inband y otra sin).
- Algunas opciones de multiplexación (marcadas como D a continuación) no se podrán usar ya que requieren almacenamiento temporal para la edición de archivos.
- El uso de la concatenación de archivos con `.I cat` es posible, pero las fuentes concatenadas no se intercalarán en la salida. Si desea realizar operaciones de concatenación/adición más complejas sin archivo temporal, utilice una lista de reproducción.

La URL de origen puede ser cualquier URL admitida por GPAC, no se limita a archivos locales.

Nota: Al importar archivos SRT o SUB, MP4Box elegirá opciones de diseño predeterminadas para que los subtítulos aparezcan en la parte inferior del video. NO DEBE importar dichos archivos antes de que se agregue ninguna pista de video al archivo de destino, de lo contrario, los resultados probablemente no serán útiles (la importación predeterminada de SRT/SUB utiliza la fuente serif predeterminada, tamaño de fuente 18 y tamaño de visualización 400x60). Para más detalles, consulte la documentación de TTXT.

Al importar varias pistas/fuentes en un solo paso, todas las opciones se aplicarán si son relevantes para cada fuente. Estas opciones se establecen para todas las secuencias importadas. Si necesita especificar estas opciones por secuencia, establezca las opciones por archivo utilizando la sintaxis -add stream[:opt1:...:optN].

El nombre del archivo de importación puede establecerse como vacío o `self`, lo que indica que las opciones de importación se aplicarán a la(s) pista(s) del archivo de destino.
Ejemplo
-add self:moovts=-1:noedit src.mp4

Esto aplicará la opción moovts y noedit a todas las pistas en src.mp4
Ejemplo
-add self#2:moovts=-1:noedit src.mp4

Esto aplicará la opción moovts y noedit a la pista con ID=2 en src.mp4
Solo las opciones por archivo marcadas con S son posibles en este modo.

Opciones de Señalización

La señalización IsoMedia consiste en crear pistas especiales en el archivo que contienen información específica del protocolo de transporte y, opcionalmente, información de multiplexación. Estas pistas son utilizadas por el servidor para crear los paquetes reales que se envían a través de la red; en otras palabras, proporcionan al servidor pistas sobre cómo construir paquetes, de ahí sus nombres: pistas de señalización.
MP4Box soporta la creación de pistas de señalización para servidores RTP/RTSP que las soportan, como QuickTime Streaming Server, DarwinStreaming Server o servidores RTSP compatibles con 3GPP.
Nota: Las herramientas de streaming de GPAC, la salida rtp y el servidor rtsp no utilizan pistas de señalización; utilizan la paquetización sobre la marcha a partir de cualquier fuente multimedia, no solo de MP4.

Opciones de Codificación de Escenas MPEG-4

Consideraciones Generales

MP4Box soporta la codificación y decodificación de formatos BT, XMT, VRML y (parcialmente) X3D en MPEG-4 BIFS, y la codificación y decodificación de XSR y SVG en MPEG-4 LASeR.
Cualquier pista multimedia especificada a través de un elemento MuxInfo será importada en el archivo MP4 resultante.
Ver https://wiki.gpac.io/MPEG-4-BIFS-Textual-Format y páginas relacionadas.

Acceso Aleatorio a la Escena

Acceso Aleatorio

MP4Box puede codificar flujos BIFS o LASeR e insertar puntos de acceso aleatorio a una frecuencia dada. Esto es útil al empaquetar contenido para transmisión, donde los usuarios no ingresarán a la escena al mismo tiempo. En la terminología de MPEG-4, esto se llama el carrusel de escena.

Procesamiento de Bloques BIFS

El modo de codificación de bloques BIFS permite codificar unidades de acceso BIFS individuales a partir de un contexto inicial y un conjunto de comandos.

Las AU generadas son BIFS sin formato (no empaquetadas en SL), en archivos llamados FILE-ESID-AUIDX.bifs, donde FILE es el nombre base del archivo de entrada.

Los comandos con un tiempo de 0 en la entrada modificarán solo la versión del carrusel (es decir, el contexto de salida).

Los comandos con un tiempo diferente de 0 en la entrada generarán nuevas AU.

Opciones:

-def
codificar nombres DEF en BIFS
-sync (int)
forzar la generación de muestras de sincronización BIFS cada tiempo dado en ms (no se puede usar con .I shadow o .I carousel)

forzar la generación de muestras de sombra de sincronización BIFS cada tiempo dado en ms (no se puede usar con .I sync o .I carousel)
-carousel (int)

-sclog

-ms (string)

-resolution (int)

Opciones de Metadatos y HEIF

Los archivos IsoMedia se pueden usar como contenedores genéricos de metadatos, por ejemplo, para almacenar información XML e imágenes de muestra para una película. El archivo resultante puede no contener siempre una película, como es el caso de algunos archivos HEIF o MPEG-21.

Esta información se puede almacenar en el nivel raíz del archivo, como es el caso de los formatos de archivo HEIF/IFF y MPEG-21, o en el nivel de película o pista para una película normal.

-set-meta ABCD[:tk=tkID]
establecer el tipo de caja de metadatos, donde ABCD es el tipo de metadatos de cuatro caracteres (NULL o 0 para eliminar metadatos)
* tk no establecido: usar metadatos raíz (archivo)
* tkID == 0: usar metadatos moov
* tkID != 0: usar metadatos de la pista dada
-add-item (string)
agregar recurso a metadatos, con la sintaxis de parámetro ruta_archivo[:opt1:optN]
* ruta_archivo `this` o `self`: el elemento es el archivo mismo
* tk=tkID: ubicación de metadatos (archivo, moov, pista)
* name=str: nombre del elemento, ninguno si no está establecido
* type=itype: tipo 4cc del elemento (no necesario si se proporciona mime)
* mime=mtype: tipo mime del elemento, ninguno si no está establecido
* encoding=enctype: tipo de codificación de contenido del elemento, ninguno si no está establecido
* id=ID: ID del elemento
* ref=4cc,id: referencia de tipo 4cc a otro elemento (se puede establecer varias veces)
* group=id,type: indica la ID y el tipo de un grupo alternativo para este elemento
* replace: reemplazar el elemento existente por uno nuevo
-add-image (string)
agregar el archivo dado como un elemento de imagen HEIF, con la sintaxis de parámetro ruta_archivo[:opt1:optN]. Si se omite la ruta_archivo, la fuente es el archivo MP4 de entrada
* name, id, ref: ver .I add-item
* primary: indica que este elemento debe ser el elemento principal
* time=t[-e][/i]: usar la siguiente muestra de sincronización después del tiempo t (float, en segundos, por defecto 0). Un tiempo negativo importa TODOS los fotogramas intra como elementos
- Si se establece e (float, en segundos), importa todas las muestras de sincronización entre t y e
- Si se establece i (float, en segundos), establece el incremento de tiempo entre muestras a importar
* split_tiles: para una imagen HEVC con mosaicos, cada mosaico se almacena como un elemento separado
* image-size=wxh: forzar el establecimiento del tamaño de la imagen e ignorar la información del bitstream, se usa para imágenes derivadas de cuadrícula, superposición e identidad también
* rotation=a: establece el ángulo de rotación de esta imagen a 90*a grados en sentido antihorario
* mirror-axis=axis: establece el eje de espejo: vertical, horizontal
* clap=Wn,Wd,Hn,Hd,HOn,HOd,VOn,VOd: ver pista clap
* image-pasp=axb: forzar la relación de aspecto de la imagen
* image-pixi=(a|a,b,c): forzar la profundidad de bits (1 o 3 canales)
* hidden: indica que este elemento de imagen debe ocultarse
* icc_path: ruta a los datos icc para agregar como información de color
* alpha: indica que la imagen es una imagen alfa (debería usar ref=auxl también)
* depth: indica que la imagen es una imagen de profundidad (debería usar ref=auxl también)
* it=ID: indica la ID del elemento de origen a importar
* itp=ID: igual que it= pero copia todas las propiedades del elemento de origen
* tk=tkID: indica la ID de pista de la muestra de origen. Si es 0, usa la primera pista de video en el archivo
* samp=N: indica el número de muestra de la muestra de origen
* ref: no copiar los datos sino referenciar la muestra/elemento final, ignorado si se establece ruta_archivo
* agrid[=AR]: crea una cuadrícula automática a partir de los elementos de imagen presentes en el archivo, en su orden de declaración. La cuadrícula intentará tener una relación de aspecto AR si se especifica (float), o la relación de aspecto de la fuente en caso contrario. La cuadrícula será el elemento principal y todas las demás imágenes se ocultarán
* av1_op_index: selecciona el punto operativo AV1 a usar a través de la caja a1op
* replace: reemplazar la imagen existente por una nueva imagen, conservando las propiedades enumeradas en keep_props
* keep_props=4CCs: lista separada por comas de tipos de propiedades a conservar al reemplazar la imagen, por ejemplo, keep_props=auxC
* auxt=URN: marca la imagen como auxiliar usando la URN dada
* auxd=FILE: usar datos de FILE como extensiones auxiliares (cf caja auxC)
- cualquier otra opción se pasará como opciones al importador de medios, ver .I add
-add-derived-image (string)
crear un elemento de cuadrícula de imágenes, superposición o identidad, con la sintaxis de parámetro :type=(grid|iovl|iden)[:opt1:optN]
* image-grid-size=rxc: establecer el número de filas y columnas de la cuadrícula
* image-overlay-offsets=h,v[,h,v]*: establecer los desplazamientos horizontal y vertical de las imágenes en la superposición
* image-overlay-color=r,g,b,a: establecer el color del lienzo de la superposición [0-65535]
- se pueden usar cualquier otra opción de .I add-image
-rem-item,-rem-image item_ID[:tk=tkID]
eliminar recurso de metadatos
-set-primary item_ID[:tk=tkID]
establecer el elemento como principal para metadatos
-set-xml xml_file_path[:tk=tkID][:binary]
establecer datos XML de metadatos
-rem-xml [tk=tkID]
eliminar datos XML de metadatos
-dump-xml file_path[:tk=tkID]
volcar metadatos XML a archivo
-dump-item item_ID[:tk=tkID][:path=fileName]
volcar elemento a archivo
-package (string)

analiza un archivo XML de entrada en un contenedor ISO, todos los medios referenciados, excepto los hipervínculos, se agregan al archivo
-mgt (cadena)

analiza un archivo XML de entrada en un widget MPEG-U con contenedor ISO, todos los archivos contenidos en la carpeta actual se agregan al paquete del widget

Puedes especificar un archivo de entrada SWF con las opciones '-bt', '-xmt' y '-mp4'

todas las definiciones SWF se colocan en la primera escena de reemplazo en lugar de cuando son necesarias

usa un solo flujo para el control de la película y el diccionario (esto deshabilitará ActionScript)

elimina todo el texto SWF

elimina todas las fuentes SWF incrustadas (se usan las fuentes del host de reproducción local)
-no-line

elimina todas las líneas de las formas SWF
-no-grad

elimina todos los degradados de las formas SWF

usa curvas bézier cuadráticas en lugar de cúbicas
-xlp

soporte para transparencia y escalabilidad de líneas

usa un proto codificado de curva indexada 2D
-same-app

se reutilizan los nodos de apariencia
-flatten (número)

ángulo complementario por debajo del cual se fusionan 2 líneas, el valor 0 significa que no hay aplanamiento

Soporte de etiquetas

Las etiquetas se especifican como una lista separada por dos puntos nombre_etiqueta=valor_etiqueta[:etiqueta2=valor2]
Establecer una etiqueta sin valor o con el valor NULL elimina la etiqueta.
El valor especial de etiqueta clear (o reset) elimina todas las etiquetas.
Las etiquetas no admitidas se pueden agregar usando su código de cuatro caracteres como nombre de etiqueta, y se asumirá un valor de cadena.
Si la longitud del nombre de la etiqueta es 3, se usa el prefijo 0xA9 para crear el código de cuatro caracteres.

Las etiquetas también se pueden cargar desde un archivo de texto usando -itags nombre_archivo. El archivo debe estar en UTF8 con:
- las líneas que comienzan con nombre_etiqueta=valor especifican el inicio de una etiqueta
- otras líneas especifican el resto de la última etiqueta declarada

Si el nombre de la etiqueta comienza con WM/, la etiqueta se agrega a la caja Xtra (etiqueta WMA, solo cadena).

Clave de metadatos QT

La etiqueta se agrega como una clave de metadatos QT si:
- el nombre_etiqueta comienza con QT/
- o el nombre_etiqueta no se reconoce y tiene más de 4 caracteres

El nombre_etiqueta puede tener opcionalmente el prefijo HDLR@, que indica el 4CC del espacio de nombres de la etiqueta, siendo el espacio de nombres predeterminado mdta.
El valor_etiqueta puede tener el prefijo:
* S: fuerza la codificación de cadena (debe colocarse primero) en lugar de analizar el valor de la etiqueta
* b: usa codificación de 8 bits para enteros con signo o sin signo
* s: usa codificación de 16 bits para enteros con signo o sin signo
* l: usa codificación de 32 bits para enteros con signo o sin signo
* L: usa codificación de 64 bits para enteros con signo o sin signo
* f: fuerza la codificación de punto flotante para números
Los números se convierten por defecto y se almacenan en modo de tamaño variable.
Para forzar que un entero positivo use almacenamiento con signo, agregue + delante del número.
Ejemplo
-tags io.gpac.some_tag=s+32

Esto forzará el almacenamiento del valor 32 en formato de 16 bits con signo.
El valor_etiqueta también se puede formatear como:
* XxY@WxH: tipo rectángulo
* XxY: tipo punto
* W@H: tipo tamaño
* A,B,C,D,E,F,G,H,I: matriz de 3x3
* FNAME: los datos se cargan de FNAME, el tipo se establece en jpeg o png si es necesario

archivo SDP de salida

fuente de actualizaciones de escena
