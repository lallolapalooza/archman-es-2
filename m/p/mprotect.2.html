mprotect(2) Manual de llamadas al sistema mprotect(2)

NOMBRE

mprotect, pkey_mprotect - establecer protección en una región de memoria

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/mman.h>
int mprotect(const void *addr, size_t len, int prot);
#define _GNU_SOURCE             /* Ver feature_test_macros(7) */
#include <sys/mman.h>
int pkey_mprotect(const void *addr, size_t len, int prot, int pkey);

DESCRIPCIÓN

mprotect() cambia las protecciones de acceso para las páginas de memoria del proceso que realiza la llamada, conteniendo cualquier parte del intervalo de direcciones en [addr, addr+size-1]. addr debe estar alineado a un límite de página.

Si el proceso que realiza la llamada intenta acceder a memoria de una manera que viola las protecciones, el kernel genera una señal SIGSEGV para el proceso.

prot es una combinación de las siguientes banderas de acceso: PROT_NONE o un OR a nivel de bits de los otros valores en la siguiente lista:

PROT_NONE
La memoria no se puede acceder en absoluto.
PROT_READ
La memoria se puede leer.
PROT_WRITE
La memoria se puede modificar.
PROT_EXEC
La memoria se puede ejecutar.
PROT_SEM (desde Linux 2.5.7)
La memoria se puede usar para operaciones atómicas. Esta bandera se introdujo como parte de la implementación de futex(2) (para garantizar la capacidad de realizar operaciones atómicas requeridas por comandos como FUTEX_WAIT), pero actualmente no se usa en ninguna arquitectura.
PROT_SAO (desde Linux 2.6.26)
La memoria debe tener un orden de acceso fuerte. Esta característica es específica de la arquitectura PowerPC (la versión 2.06 de la especificación de la arquitectura añade la característica de hardware SAO, y está disponible en POWER 7 o PowerPC A2, por ejemplo).

Adicionalmente (desde Linux 2.6.0), prot puede tener una de las siguientes banderas establecidas:

PROT_GROWSUP
Aplicar el modo de protección hasta el final de un mapeo que crece hacia arriba. (Tales mapeos se crean para el área de pila en arquitecturas -por ejemplo, HP-PARISC- que tienen una pila que crece hacia arriba).
PROT_GROWSDOWN
Aplicar el modo de protección hacia abajo hasta el principio de un mapeo que crece hacia abajo (que debería ser un segmento de pila o un segmento mapeado con la bandera MAP_GROWSDOWN establecida).

Al igual que mprotect(), pkey_mprotect() cambia la protección en las páginas especificadas por addr y size. El argumento pkey especifica la clave de protección (ver pkeys(7)) a asignar a la memoria. La clave de protección debe ser asignada con pkey_alloc(2) antes de que se pase a pkey_mprotect(). Para un ejemplo del uso de esta llamada al sistema, ver pkeys(7).

VALOR DE RETORNO

En caso de éxito, mprotect() y pkey_mprotect() devuelven cero. En caso de error, estas llamadas al sistema devuelven -1 y errno se establece para indicar el error.

ERRORES

EACCES
La memoria no puede recibir el acceso especificado. Esto puede ocurrir, por ejemplo, si mmap(2) un archivo al que solo tiene acceso de lectura, y luego solicita a mprotect() que lo marque como PROT_WRITE.
EINVAL
addr no es un puntero válido, o no es un múltiplo del tamaño de página del sistema.
EINVAL
(pkey_mprotect()) pkey no ha sido asignado con pkey_alloc(2)
EINVAL
Se especificaron tanto PROT_GROWSUP como PROT_GROWSDOWN en prot.
EINVAL
Se especificaron banderas inválidas en prot.
EINVAL
(Arquitectura PowerPC) Se especificó PROT_SAO en prot, pero la característica de hardware SAO no está disponible.
ENOMEM
No se pudieron asignar estructuras internas del kernel.
ENOMEM
Las direcciones en el rango [addr, addr+size-1] son inválidas para el espacio de direcciones del proceso, o especifican una o más páginas que no están mapeadas. (Antes de Linux 2.4.19, el error EFAULT se producía incorrectamente para estos casos).
ENOMEM
Cambiar la protección de una región de memoria resultaría en que el número total de mapeos con atributos distintos (por ejemplo, protección de solo lectura frente a lectura/escritura) exceda el máximo permitido. (Por ejemplo, hacer que la protección de un rango sea PROT_READ en medio de una región actualmente protegida como PROT_READ|PROT_WRITE resultaría en tres mapeos: dos mapeos de lectura/escritura en cada extremo y un mapeo de solo lectura en el medio).

VERSIÓNES

POSIX dice que el comportamiento de mprotect() no está definido si se aplica a una región de memoria que no se obtuvo a través de mmap(2).

En Linux, siempre está permitido llamar a mprotect() en cualquier dirección del espacio de direcciones de un proceso (excepto en el área de syscal del kernel). En particular, se puede usar para cambiar mapeos de código existentes para que sean escribibles.

Que PROT_EXEC tenga algún efecto diferente de PROT_READ depende de la arquitectura del procesador, la versión del kernel y el estado del proceso. Si READ_IMPLIES_EXEC está establecido en las banderas de personalidad del proceso (ver personality(2)), especificar PROT_READ implícitamente añadirá PROT_EXEC.

En algunas arquitecturas de hardware (por ejemplo, i386), PROT_WRITE implica PROT_READ.

POSIX.1 dice que una implementación puede permitir acceso distinto del especificado en prot, pero como mínimo puede permitir acceso de escritura solo si se ha establecido PROT_WRITE, y no debe permitir ningún acceso si se ha establecido PROT_NONE.

Las aplicaciones deben tener cuidado al mezclar el uso de mprotect() y pkey_mprotect(). En x86, cuando se usa mprotect() con prot establecido en PROT_EXEC, el kernel puede asignar e imponer implícitamente una clave pkey en la memoria, pero solo cuando la pkey era 0 previamente.

En sistemas que no soportan claves de protección en hardware, pkey_mprotect() aún puede ser utilizado, pero pkey debe estar establecido en -1. Cuando se llama de esta manera, la operación de pkey_mprotect() es equivalente a mprotect().

NOTAS

EJEMPLOS

El programa a continuación demuestra el uso de mprotect(). El programa asigna cuatro páginas de memoria, hace que la tercera de estas páginas sea de solo lectura, y luego ejecuta un bucle que recorre la región asignada modificando bytes.

Un ejemplo de lo que podríamos ver al ejecutar el programa es el siguiente:


$ ./a.out
Inicio de la región:        0x804c000
Señal SIGSEGV recibida en la dirección: 0x804e000

Código del programa

#include <err.h>
#include <malloc.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/mman.h>
#include <unistd.h>
static char *buffer;
static void
handler(int sig, siginfo_t *si, void *unused)
{
    /* Nota: llamar a printf() desde un manejador de señales no es seguro
       (y no debe hacerse en programas de producción), ya que
       printf() no es seguro para señales asíncronas; véase signal-safety(7).
       Sin embargo, usamos printf() aquí como una forma sencilla de
       mostrar que el manejador fue llamado.  */
    printf("Señal SIGSEGV recibida en la dirección: %p\n", si->si_addr);
    exit(EXIT_FAILURE);
}
int
main(void)
{
    int               pagesize;
    struct sigaction  sa;
    sa.sa_flags = SA_SIGINFO;
    sigemptyset(&sa.sa_mask);
    sa.sa_sigaction = handler;
    if (sigaction(SIGSEGV, &sa, NULL) == -1)
        err(EXIT_FAILURE, "sigaction");
    pagesize = sysconf(_SC_PAGE_SIZE);
    if (pagesize == -1)
        err(EXIT_FAILURE, "sysconf");
    /* Asignar un búfer alineado en un límite de página;
       la protección inicial es PROT_READ | PROT_WRITE.  */
    buffer = memalign(pagesize, 4 * pagesize);
    if (buffer == NULL)
        err(EXIT_FAILURE, "memalign");
    printf("Inicio de la región:        %p\n", buffer);
    if (mprotect(buffer + pagesize * 2, pagesize,
                 PROT_READ) == -1)
        err(EXIT_FAILURE, "mprotect");
    for (char *p = buffer ; ; )
        *(p++) = 'a';
    printf("Bucle completado\n");     /* Nunca debería ocurrir */
    exit(EXIT_SUCCESS);
}
