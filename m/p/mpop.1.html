MPOP(1) Manual de Comandos Generales MPOP(1)

NOMBRE

mpop - Un cliente POP3

SINOPSIS

Modo de recuperación de correo (por defecto):
mpop [opción...] [--] [cuenta...]
mpop --host=host [opción...]
Modo de configuración:
mpop --configure <dirección de correo>
Modo de información del servidor:
mpop [opción...] --serverinfo [cuenta...]
mpop --host=host [opción...] --serverinfo

DESCRIPCIÓN

En el modo de operación de recuperación de correo, mpop recupera correos de uno o más buzones POP3, opcionalmente realiza algún filtrado, y los entrega a través de un agente de entrega de correo (MDA), a una carpeta maildir, o a un archivo mbox. Los correos que fueron entregados exitosamente antes no se recuperarán una segunda vez, incluso si ocurren errores o mpop se termina a mitad de una sesión.
En el modo de información del servidor, mpop imprime información sobre uno o más servidores POP3.
Si no se proporcionan nombres de cuenta en la línea de comandos, se utilizará uno llamado default.
La mejor manera de empezar es probablemente echar un vistazo a la sección EJEMPLOS.

ESTADO DE SALIDA

Se utilizan los códigos de salida estándar de sendmail, tal como se definen en sysexits.h.

OPCIONES

Las opciones anulan la configuración del archivo de configuración, para cada cuenta utilizada.

Opciones Generales
--version
Imprime información de la versión, incluida información sobre las bibliotecas utilizadas.
--help
Imprime ayuda.
-P, --pretend
Imprime la configuración que se utilizaría, pero no realiza ninguna acción adicional. Se imprimirá un asterisco (`*') en lugar de tu contraseña.
-d, --debug
Imprime mucha información de depuración, incluida toda la conversación con el servidor. Ten cuidado con esta opción: la salida (potencialmente peligrosa) no se sanitizará y tu contraseña puede imprimirse en un formato fácilmente decodificable.
Esta opción implica --half-quiet, ya que la salida de progreso interferiría con la salida de depuración.
Cambio del modo de operación
--configure=dirección de correo
Genera una configuración para la dirección de correo dada y la imprime. Esto se puede modificar o copiar sin cambios al archivo de configuración. Ten en cuenta que esto solo funciona para dominios de correo que publican registros SRV apropiados; consulta RFC 8314.
-S, --serverinfo
Imprime información sobre el(los) servidor(es) POP3 y sale. Esto incluye información sobre las características admitidas (pipelining, métodos de autenticación, comando TOP, ...), sobre parámetros (tiempo durante el cual los correos no se eliminarán, tiempo mínimo entre inicios de sesión, ...), y sobre el certificado TLS (si TLS está activo).
Opciones de configuración
-C, --file=archivo de configuración
Utiliza el archivo dado en lugar de ~/.mpoprc o $XDG_CONFIG_HOME/mpop/config como archivo de configuración del usuario.
--host=nombre de host
Utiliza este servidor con la configuración de la línea de comandos; no uses ningún dato del archivo de configuración. Esta opción deshabilita la carga del archivo de configuración. No puedes usar ambas opciones y nombres de cuenta en la línea de comandos.
--port=número
Establece el número de puerto al que conectarse. Consulta el comando port.
--source-ip=[IP]
Establece o elimina una dirección IP a la que enlazar el socket. Consulta el comando source_ip.
--proxy-host=[IP|nombre de host]
Establece o elimina un proxy SOCKS a utilizar. Consulta el comando proxy_host.
--proxy-port=[número]
Establece o elimina un número de puerto para el host proxy. Consulta el comando proxy_port.
--socket=[nombre de socket]
Establece o elimina un nombre de socket de dominio Unix local al que conectarse. Consulta el comando socket.
--timeout=(off|segundos)
Establece un tiempo de espera de red. Consulta el comando timeout.
--pipelining=(auto|on|off)
Habilita o deshabilita el pipelining POP3. Consulta el comando pipelining.
--received-header[=(on|off)]
Habilita o deshabilita la cabecera Received. Consulta el comando received_header.
--auth[=(on|method)]
Establece el método de autenticación en automático (con "on") o elige manualmente un método de autenticación. Consulta el comando auth.
--user=[nombre de usuario]
Establece o elimina el nombre de usuario para la autenticación. Consulta el comando user.
--passwordeval=[comando]
Evalúa la contraseña para la autenticación. Consulta el comando passwordeval.
--tls[=(on|off)]
Habilita o deshabilita TLS/SSL. Consulta el comando tls.
--tls-starttls[=(on|off)]
Habilita o deshabilita STARTTLS para TLS. Consulta el comando tls_starttls.
--tls-trust-file=[archivo]
Establece o elimina un archivo de confianza para TLS. Consulta el comando tls_trust_file.
--tls-crl-file=[archivo]
Obsoleto. Establece o elimina un archivo de lista de revocación de certificados (CRL) para TLS. Consulta el comando tls_crl_file.
--tls-fingerprint=[huella digital]
Establece o elimina la huella digital de un certificado TLS de confianza. Consulta el comando tls_fingerprint.
--tls-key-file=[archivo]
Establece o elimina un archivo de clave para TLS. Consulta el comando tls_key_file.
--tls-cert-file=[archivo]
Establece o elimina un archivo de certificado para TLS. Consulta el comando tls_cert_file.
--tls-certcheck[=(on|off)]
Habilita o deshabilita las comprobaciones del certificado del servidor para TLS. Consulta el comando tls_certcheck.
--tls-priorities=[prioridades]
Establece o elimina las prioridades TLS. Consulta el comando tls_priorities.
--tls-host-override=[host]
Establece o elimina la anulación de la verificación del host TLS. Consulta el comando tls_host_override.
--tls-min-dh-prime-bits=[bits]
Obsoleto, usa --tls-priorities en su lugar. Establece o elimina el tamaño mínimo de bits de la prima Diffie-Hellmann (DH). Consulta el comando tls_min_dh_prime_bits.
Opciones específicas para el modo de recuperación de correo
-q, --quiet
No imprime información de estado o progreso.
-Q, --half-quiet
Imprime estado pero no información de progreso.
-a, --all-accounts
Consulta todas las cuentas en el archivo de configuración.
-A, --all-dirs
Busca todos los directorios de correo disponibles.

COMMAND LINE OPTIONS

-A, --auth-only
Autenticar solamente; no recuperar el correo. Útil para SMTP-después-de-POP.
-s, --status-only
Imprimir solo el número y tamaño de los correos en cada cuenta; no recuperar el correo.
-n, --only-new[=(on|off)]
Procesar solo mensajes nuevos. Ver el comando only_new.
-k, --keep[=(on|off)]
No eliminar correos de los servidores POP3, independientemente de otras opciones o configuraciones. Ver el comando keep.
--killsize=(off|size)
Establecer o desestablecer el tamaño de eliminación. Ver el comando killsize.
--skipsize=(off|size)
Establecer o desestablecer el tamaño de omisión. Ver el comando skipsize.
--filter=[program]
Establecer un filtro que decidirá si recuperar, omitir o eliminar cada correo investigando las cabeceras del correo. Ver el comando filter.
--delivery=method,method_arguments...
Cómo entregar los mensajes recibidos de esta cuenta. Ver el comando delivery. Tenga en cuenta que se utiliza una coma en lugar de un espacio para separar el método de sus argumentos.
--uidls-file=filename
Archivo donde almacenar los UIDLs. Ver el comando uidls_file.

USO

Una sugerencia para un archivo de configuración adecuado puede generarse utilizando la opción --configure. El archivo de configuración predeterminado es ~/.mpoprc o $XDG_CONFIG_HOME/mpop/config. La configuración en este archivo puede modificarse mediante opciones de línea de comandos.
Un archivo de configuración es un archivo de texto simple. Las líneas vacías y las líneas de comentarios (el primer carácter no vacío es '#') se ignoran. Cada línea restante debe contener un comando y puede contener un argumento para ese comando. El argumento puede estar entre comillas dobles (").
Si un nombre de archivo comienza con la tilde (~), esta tilde se reemplazará por $HOME.
Si un comando acepta el argumento on, también acepta un argumento vacío y lo trata como si fuera on.
Los comandos están organizados en cuentas. Cada cuenta comienza con el comando account y define la configuración para una cuenta POP3.

Los comandos son los siguientes:

defaults
Establecer valores predeterminados. Los siguientes comandos de configuración establecerán valores predeterminados para todas las definiciones de cuenta siguientes.
account name [:account[,...]]
Iniciar una nueva definición de cuenta con el nombre dado. Se rellenan los valores predeterminados actuales.
Si se proporciona dos puntos y una lista de cuentas definidas previamente después del nombre de la cuenta, la nueva cuenta, con los valores predeterminados rellenados, heredará toda la configuración de las cuentas de la lista.
eval cmd
Reemplazar la línea actual del archivo de configuración con la primera línea de la salida (stdout) del comando cmd. Esto se puede usar para descifrar configuraciones o para crearlas a través de scripts. Por ejemplo, eval echo host localhost reemplaza la línea actual por host localhost.
Tenga en cuenta que cada línea eval se evaluará cuando se lea el archivo de configuración.
Tenga en cuenta que para las contraseñas también puede usar el comando passwordeval en lugar de eval password cmd. Esto tiene la ventaja de que el comando solo se evalúa si es necesario.
host hostname
El servidor POP3 desde el cual recuperar los correos. El argumento puede ser un nombre de host o una dirección de red. Cada definición de cuenta debe contener este comando.
port number
El puerto en el que escucha el servidor POP3. El valor predeterminado es 110 ("pop3"), a menos que se use TLS sin STARTTLS, en cuyo caso es 995 ("pop3s").
source_ip [IP]
Establecer una dirección IP de origen para enlazar la conexión saliente. Útil solo en casos especiales en sistemas con múltiples interfaces. Un argumento vacío deshabilita esto.
proxy_host [IP|hostname]
Usar un proxy SOCKS. Todo el tráfico de red pasará a través de este host proxy, incluidas las consultas DNS, excepto una consulta DNS que podría ser necesaria para resolver el propio nombre del host proxy (esto se puede evitar usando una dirección IP como nombre del host proxy). Un argumento de hostname vacío deshabilita el uso del proxy. El protocolo SOCKS soportado es la versión 5. Si desea usar esto con Tor, consulte también "Uso de mpop con Tor" a continuación.
proxy_port [number]
Establecer el número de puerto para el host proxy. Un argumento de number vacío lo restablece al puerto predeterminado, que es 1080 ("socks").
socket socketname
Establecer el nombre del archivo de un socket de dominio Unix al que conectarse. Esto anula tanto host/port como proxy_host/proxy_port.
timeout (off|seconds)
Establecer o desestablecer un tiempo de espera de red, en segundos. El valor predeterminado es 180 segundos. El argumento off significa que no se establecerá ningún tiempo de espera, lo que significa que se utilizará el valor predeterminado del sistema operativo.
pipelining (auto|on|off)
Habilitar o deshabilitar el pipelining POP3. Nunca debería necesitar cambiar la configuración predeterminada, que es auto: mpop habilita el pipelining para los servidores POP3 que anuncian esta capacidad y lo deshabilita para todos los demás servidores. El pipelining puede acelerar una sesión POP3 sustancialmente.
auth [(on|method)]
Elegir un método de autenticación. El argumento predeterminado on elige un método automáticamente.
Por lo general, se utiliza un nombre de usuario y una contraseña para la autenticación. El nombre de usuario se especifica en el archivo de configuración con el comando user. Hay cinco métodos diferentes para especificar la contraseña:
1. Añadir la contraseña al llavero del sistema. Los llaveros actualmente soportados son el llavero de Gnome y el Keychain de Mac OS X. Para el llavero de Gnome, use el comando secret-tool (parte de libsecret de Gnome) para almacenar contraseñas: secret-tool store --label=mpop host pop.freemail.example service pop3 user joe.smith. En Mac OS X, use el siguiente comando: security add-internet-password -s pop.freemail.example -r pop3 -a joe.smith -w. En ambos ejemplos, reemplace pop.freemail.example con el nombre del servidor POP3 y joe.smith con su nombre de usuario.
2. Almacenar la contraseña en archivos cifrados y usar passwordeval para especificar un comando para descifrar ese archivo, por ejemplo, usando GnuPG. Ver EJEMPLOS.
3. Almacenar la contraseña en el archivo de configuración usando el comando password. (Normalmente no se considera una buena idea almacenar contraseñas en archivos de texto plano. Si lo hace de todos modos, debe asegurarse de que el archivo solo pueda ser leído por usted mismo).
4. Almacenar la contraseña en ~/.netrc. Este método probablemente esté obsoleto.
5. Escribir la contraseña en la terminal cuando se requiera.
Se recomienda usar el método 1 o 2.
Existen múltiples métodos de autenticación. La mayoría de los servidores solo soportan algunos de ellos.
Los siguientes métodos de usuario/contraseña son soportados: user (un método simple de texto plano soportado por todos los servidores), plain (otro método simple de texto plano, soportado por casi todos los servidores), scram-sha-1 y scram-sha-1-plus (un método que evita las contraseñas de texto plano y requiere que el servidor demuestre que está en posesión de la contraseña (hasheada y con sal), lo que evita algunos ataques man-in-the-middle. La variante -plus usa además información de vinculación de canal TLS para garantías de seguridad aún mejores), scram-sha-256 y scram-sha-256-plus (lo mismo pero con una función hash más fuerte), apop (un método obsoleto que evita contraseñas de texto plano, pero ya no se considera seguro), cram-md5 (un método obsoleto que evita contraseñas de texto plano, pero ya no se considera seguro), digest-md5 (un método obsoleto sobrecomplicado que evita contraseñas de texto plano, pero ya no se considera seguro), login (un método de texto plano no estándar similar pero peor que el método plain), ntlm (un método oscuro no estándar que ahora se considera roto; a veces requiere un parámetro de dominio especial pasado a través de ntlmdomain).
Si no se especifica ningún método, mpop seleccionará uno automáticamente en función de los beneficios de seguridad. Con TLS, el orden es scram-sha-256-plus, scram-sha-1-plus, scram-sha-256, scram-sha-1, plain, seguido de algunos de los métodos obsoletos si no hay nada más disponible. Sin TLS, solo se consideran scram-sha-256 y scram-sha-1.
Actualmente existen tres métodos de autenticación que no se basan en información de usuario/contraseña y deben elegirse manualmente: oauthbearer o su predecesor xoauth2 (se utiliza un token OAuth2 del proveedor de correo como contraseña. Consulte la documentación de su proveedor de correo para obtener detalles sobre cómo obtener este token. El comando passwordeval se puede usar para pasar los tokens que cambian regularmente a mpop desde un script o una variable de entorno), external (la autenticación ocurre fuera del protocolo, típicamente enviando un certificado de cliente TLS, y el método simplemente confirma que esta autenticación tuvo éxito), y gssapi (el framework Kerberos se encarga de la autenticación segura, solo se requiere un nombre de usuario).
Depende de la biblioteca de autenticación subyacente y su versión si un método particular es compatible o no. Use --version para averiguar qué métodos son compatibles.
user login
Establecer el nombre de usuario para la autenticación. Un argumento vacío desestablece el nombre de usuario.
password secret
Establecer la contraseña para la autenticación. Un argumento vacío desestablece la contraseña. Considere usar el comando passwordeval o un llavero en lugar de este comando, para evitar almacenar contraseñas de texto plano en el archivo de configuración.
passwordeval [cmd]
Establecer la contraseña para la autenticación a la salida (stdout) del comando
nd cmd. Esto se puede usar, por ejemplo, para descifrar archivos de contraseñas sobre la marcha o para consultar anillos de claves, y así evitar almacenar contraseñas en texto plano.
ntlmdomain [dominio]
Establece un dominio para el método de autenticación ntlm. Esto es obsoleto.
tls [(activado|desactivado)]
Habilita o deshabilita TLS (también conocido como SSL) para conexiones seguras.
Transport Layer Security (TLS) "...proporciona privacidad en las comunicaciones a través de Internet. El protocolo permite que las aplicaciones cliente/servidor se comuniquen de una manera diseñada para prevenir escuchas, manipulaciones o falsificación de mensajes" (cita de RFC2246).
Un servidor puede usar TLS en uno de dos modos: a través de un comando STARTTLS (la sesión comienza con la inicialización normal del protocolo, y TLS se inicia luego usando el comando STARTTLS del protocolo), o inmediatamente (TLS se inicializa antes de la inicialización normal del protocolo; esto requiere un puerto separado). El primer modo es el predeterminado, pero puedes cambiar al segundo modo deshabilitando tls_starttls.
Cuando se inicia TLS, el servidor envía un certificado para identificarse. Para verificar la identidad del servidor, se espera que un programa cliente verifique que el certificado sea formalmente correcto y que haya sido emitido por una Autoridad Certificadora (CA) en la que el usuario confíe. (También puede haber cadenas de certificados con CAs intermedias).
La lista de CAs confiables se especifica usando el comando tls_trust_file. El valor predeterminado es "system" y selecciona el predeterminado a nivel de sistema, pero también puedes elegir las CAs confiables tú mismo.
Un problema fundamental con esto es que necesitas confiar en las CAs. Como cualquier otra organización, una CA puede ser incompetente, maliciosa, subvertida por personas malintencionadas o forzada por agencias gubernamentales a comprometer a usuarios finales sin informarles. Todas estas cosas sucedieron y continúan sucediendo en todo el mundo. La idea de tener organizaciones centrales en las que se deba confiar para que tu comunicación sea segura está fundamentalmente rota.
En lugar de confiar en una CA, puedes optar por confiar solo en un certificado único para el servidor al que deseas conectarte. Para este propósito, especifica la huella digital del certificado con tls_fingerprint. Esto asegura que ningún ataque de "man-in-the-middle" pueda falsificar la identidad del servidor presentándote un certificado fraudulento emitido por alguna CA que esté en tu lista de confianza. Sin embargo, debes actualizar la huella digital cada vez que cambie el certificado del servidor, y debes asegurarte de que el cambio sea legítimo cada vez, por ejemplo, cuando expire el certificado anterior. Esto es inconveniente, pero es el precio a pagar.
La información sobre un certificado de servidor se puede obtener con --serverinfo --tls --tls-certcheck=off. Esto incluye la CA emisora del certificado (para que puedas confiar en esa CA a través de tls_trust_file) y la huella digital del certificado (para que puedas confiar en ese certificado en particular a través de tls_fingerprint).
TLS también permite al servidor verificar la identidad del cliente. Para este propósito, el cliente debe presentar un certificado emitido por una CA en la que el servidor confíe. Para presentar ese certificado, el cliente también necesita el archivo de clave correspondiente. Puedes configurar los archivos de certificado y clave usando tls_cert_file y tls_key_file. Este mecanismo también se puede utilizar para autenticar usuarios, de modo que la autenticación tradicional de usuario/contraseña ya no sea necesaria. Consulta el mecanismo external en auth.
También puedes usar certificados de cliente almacenados en algún dispositivo de autenticación externo especificando URIs de dispositivo GnuTLS en tls_cert_file y tls_key_file. Puedes encontrar las URIs correctas usando p11tool --list-privkeys --login (p11tool se incluye con GnuTLS). Si tu dispositivo requiere un PIN para acceder a los datos, puedes especificarlo usando uno de los mecanismos de contraseña (por ejemplo, passwordeval, password).
tls_starttls [(activado|desactivado)]
Elige la variante TLS: iniciar TLS desde dentro de la sesión (activado, predeterminado), o tunelizar la sesión a través de TLS (desactivado).
tls_trust_file archivo
Activa la verificación del certificado del servidor utilizando una lista de Autoridades Certificadoras (CAs) confiables. El valor predeterminado es el valor especial "system", que selecciona el predeterminado del sistema. Un argumento vacío deshabilita la confianza en las CAs. Si seleccionas un archivo, debe estar en formato PEM y también deberías usar tls_crl_file.
tls_crl_file [archivo]
Establece un archivo de lista de revocación de certificados (CRL) para TLS, para verificar certificados revocados (un argumento vacío, que es el valor predeterminado, deshabilita esto).
OCSP es una alternativa a los archivos CRL. Cuando se utiliza GnuTLS, la información OCSP "stapled" se verificará automáticamente, y se soporta la extensión TLS MustStaple, sin embargo, no se enviarán consultas OCSP manuales cuando falte información OCSP "stapled". Con otras bibliotecas TLS, el comportamiento puede ser diferente.
tls_fingerprint [huella_digital]
Establece la huella digital de un solo certificado para aceptar en TLS. Este certificado será confiable independientemente de su contenido (esto anula tls_trust_file). La huella digital debe ser de tipo SHA256, pero por compatibilidad con versiones anteriores también puede ser de tipo SHA1 o MD5 (evita esto). El formato debe ser 01:23:45:67:.... Usa --serverinfo --tls --tls-certcheck=off --tls-fingerprint= para obtener la huella digital del certificado del servidor.
tls_key_file archivo
Envía un certificado de cliente al servidor (úselo junto con tls_cert_file). El archivo debe contener la clave privada de un certificado en formato PEM. Un argumento vacío deshabilita esta función.
tls_cert_file archivo
Envía un certificado de cliente al servidor (úselo junto con tls_key_file). El archivo debe contener un certificado en formato PEM. Un argumento vacío deshabilita esta función.
tls_certcheck [(activado|desactivado)]
Habilita o deshabilita las verificaciones del certificado del servidor. Están habilitadas por defecto. Deshabilitarlas anulará tls_trust_file y tls_fingerprint. ADVERTENCIA: Cuando las verificaciones están deshabilitadas, ¡las sesiones TLS no serán seguras!
tls_priorities [prioridades]
Establece las prioridades para los parámetros de sesión TLS. El valor predeterminado lo establece la biblioteca TLS y se puede seleccionar usando un argumento vacío para este comando. La interpretación de la cadena de prioridades depende de la biblioteca TLS. Usa --version para averiguar qué biblioteca TLS utilizas.
Para GnuTLS, consulta la sección sobre Cadenas de Prioridad en el manual.
Para libtls, la cadena de prioridades es una lista separada por espacios de cadenas de parámetros prefijadas con PROTOCOLS=, CIPHERS= o ECDHECURVES=. Estas cadenas de parámetros se pasarán a las funciones tls_config_parse_protocols, tls_config_set_ciphers y tls_config_set_ecdhecurves. Las partes no reconocidas de la cadena de prioridades serán ignoradas. Ejemplo: "PROTOCOLS=TLSv1.3 CIPHERS=ECDHE-RSA-AES128-SHA256 ECDHECURVES=P-384".
tls_host_override [host]
Por defecto, la verificación del host TLS utiliza el nombre de host proporcionado por el comando host. Este comando permite usar un nombre de host diferente para la verificación. Esto solo es útil en casos especiales.
tls_min_dh_prime_bits [bits]
Obsoleto, usa tls_priorities en su lugar. Establece o desestablece el número mínimo de bits de primo Diffie-Hellman (DH) aceptados para las sesiones TLS. El valor predeterminado lo establece la biblioteca TLS y se puede seleccionar usando un argumento vacío para este comando. Solo reduce el valor predeterminado (por ejemplo, a 512 bits) si no hay otra forma de que TLS funcione con el servidor remoto.
delivery método argumentos_del_método...
Cómo entregar los mensajes recibidos de esta cuenta.
delivery mda comando
Entrega los correos a través de un agente de entrega de correo (MDA).
Todas las ocurrencias de %F en el comando se reemplazarán con la dirección de remite del sobre del mensaje actual (o MAILER-DAEMON si no se encuentra ninguna). Ten en cuenta que se garantiza que esta dirección contendrá solo letras a-z y A-Z, dígitos 0-9 y cualquiera de los caracteres ".@_-+/", aunque esto sea solo un subconjunto de lo que teóricamente está permitido en una dirección de correo. Otros caracteres, incluidos los que interpreta el shell, se reemplazarán por "_". Sin embargo, deberías poner %F entre comillas simples: '%F'.
Usa "delivery mda /usr/bin/procmail -f '%F' -d $USER" para el MDA procmail.
Usa "delivery mda /usr/sbin/sendmail -oi -oem -f '%F' -- $USER" para que tu MTA gestione el correo.
Usa "delivery mda /usr/local/bin/msmtp --host=localhost --from='%F' -- $USER@`hostname`.`dnsdomainname`" para pasar el correo a tu MTA vía SMTP. (Esto es lo que fetchmail hace por defecto.)
delivery maildir directorio
Entrega los correos al directorio maildir especificado. El directorio debe existir y debe tener los subdirectorios de maildir cur, new y tmp; mpop no creará directorios. Este tipo de entrega solo funciona en sistemas de archivos que admiten enlaces duros.
delivery mbox archivo_mbox
Entrega los correos al archivo especificado en formato mbox. El archivo se bloqueará con fcntl(2). mpop utiliza la variante de formato mbox MBOXRD; consulta la documentación del formato mbox.
delivery exchange directorio
Entrega los correos al directorio de recogida de Exchange especificado. El directorio debe existir.

Si el método de entrega necesita analizar las cabeceras del correo para obtener una dirección de remite del sobre (el método mda si el comando contiene %F y el método mbox), entonces necesita crear un archivo temporal para almacenar las cabeceras del correo (pero no el cuerpo) en él.

OPCIONES

Las siguientes opciones de configuración están disponibles en el archivo de configuración.

uidls_file nombre_archivo
Especifica el nombre del archivo que se utilizará para almacenar las listas de UIDL. Las listas de UIDL se utilizan para identificar mensajes nuevos. El especificador de formato %U en el nombre del archivo será reemplazado por el nombre de usuario de la cuenta actual. El especificador %H en el nombre del archivo será reemplazado por el nombre de host de la cuenta actual. Si el nombre del archivo contiene directorios que no existen, mpop los creará. mpop bloquea este archivo para acceso exclusivo al acceder a la cuenta POP3 asociada.
El valor predeterminado es "~/.mpop_uidls/%U_at_%H". También puede usar un único archivo UIDLS para múltiples cuentas, pero entonces no podrá consultar más de una de estas cuentas al mismo tiempo.
only_new [(on|off)]
Por defecto, mpop procesa solo mensajes nuevos (los mensajes nuevos son aquellos que no fueron recuperados exitosamente en una sesión anterior). Si esta opción está desactivada, mpop procesará todos los mensajes.
keep [(on|off)]
Mantener todos los correos en el servidor POP3, nunca eliminarlos. El comportamiento predeterminado es eliminar los correos que han sido recuperados exitosamente o filtrados por filtros de eliminación.
killsize (off|tamaño)
Los correos más grandes que el tamaño dado serán eliminados (a menos que se utilice el comando keep, en cuyo caso solo se omitirán). El argumento de tamaño debe ser cero o mayor. Si va seguido de una `k' o una `m', el tamaño se medirá en kibibytes/mebibytes en lugar de bytes. Tenga en cuenta que algunos servidores POP3 informan tamaños ligeramente incorrectos para los correos; consulte NOTAS a continuación.
Cuando killsize se establece en 0 y keep se establece en on, todos los correos se marcan como recuperados, pero ningún correo se elimina del servidor. Esto se puede usar para sincronizar la lista UID en el cliente con la lista UID en el servidor.
skipsize (off|tamaño)
Los correos más grandes que el tamaño dado serán omitidos (no descargados). El argumento de tamaño debe ser cero o mayor. Si va seguido de una `k' o una `m', el tamaño se medirá en kibibytes/mebibytes en lugar de bytes. Tenga en cuenta que algunos servidores POP3 informan tamaños ligeramente incorrectos para los correos; consulte NOTAS a continuación.
filter [comando]
Establece un filtro que decidirá si recuperar, omitir o eliminar cada correo investigando las cabeceras del correo. El servidor POP3 debe soportar el comando POP3 TOP para que esto funcione; consulte la opción --serverinfo anterior. Un argumento vacío deshabilita el filtrado.
Todas las ocurrencias de %F en el comando serán reemplazadas por la dirección del remitente del sobre del mensaje actual (o MAILER-DAEMON si no se encuentra ninguna). Tenga en cuenta que se garantiza que esta dirección solo contendrá letras a-z y A-Z, dígitos 0-9, y cualquiera de “.@_-+/”, aunque esto sea solo un subconjunto de lo que teóricamente está permitido en una dirección de correo. Otros caracteres, incluidos los interpretados por el shell, se reemplazarán con "_". Sin embargo, debe poner %F entre comillas simples: '%F'.
Todas las ocurrencias de %S en el comando serán reemplazadas por el tamaño del correo actual según lo informado por el servidor POP3.
Las cabeceras del correo (más la línea en blanco que separa las cabeceras del cuerpo) se enviarán al comando. Basándose en el código de retorno, mpop decide qué hacer con el correo:
0: proceder normalmente; ninguna acción especial
1: eliminar el correo; no recuperarlo
2: omitir el correo; no recuperarlo
Los códigos de retorno mayores o iguales a 3 significan que ocurrió un error. Los códigos de error de sysexits.h pueden usarse para dar información sobre el tipo de error, pero esto no es necesario.

received_header [(on|off)]
Habilita o deshabilita la adición de una cabecera Received. Por defecto, mpop antepone una cabecera Received al correo durante la entrega. Esto es requerido por las RFC si el correo se entrega posteriormente, por ejemplo, vía SMTP.

FILTRADO

Hay tres comandos de filtrado disponibles. Se ejecutarán en el siguiente orden:

killsize
skipsize
filter
Si un comando de filtrado se aplica a un correo, los filtros restantes no se ejecutarán.

Archivo de configuración

# Ejemplo para un archivo de configuración de usuario ~/.mpoprc
#
# Este archivo se centra en TLS, autenticación y el método de entrega de correo.
# Las características no utilizadas aquí incluyen filtrado de correo, tiempos de espera, proxies SOCKS,
# parámetros TLS y más.

# Establecer valores predeterminados para todas las siguientes cuentas.
defaults

# Usar siempre TLS.
tls on

# Establecer una lista de CAs confiables para TLS. El valor predeterminado es usar la configuración del sistema, pero
# puede seleccionar su propio archivo.
#tls_trust_file /etc/ssl/certs/ca-certificates.crt

# Entregar correo a un archivo de correo MBOX:
delivery mbox ~/Mail/inbox
# Entregar correo a una carpeta maildir:
#delivery maildir ~/Mail/incoming
# Entregar correo a través de procmail:
#delivery mda "/usr/bin/procmail -f '%F' -d $USER"
# Entregar correo a través del servidor SMTP local:
#delivery mda "/usr/bin/msmtp --host=localhost --from='%F' -- $USER"
# Entregar correo a un directorio de recogida de Exchange:
#delivery exchange c:\exchange\pickup

# Usar un archivo uidls en ~/.local/share en lugar de ~/.mpop_uidls
uidls_file ~/.local/share/%U_at_%H

# Un servicio de correo gratuito
account freemail

# Nombre del host del servidor POP3
host pop.freemail.example

# Como alternativa a tls_trust_file, puede usar tls_fingerprint
# para fijar un único certificado. Tendrá que actualizar la huella digital cuando el
# certificado del servidor cambie, pero un atacante no podrá engañarle para que acepte
# un certificado fraudulento. Obtenga la huella digital con
# $ mpop --serverinfo --tls --tls-certcheck=off --host=pop.freemail.example
#tls_fingerprint
00:11:22:33:44:55:66:77:88:99:AA:BB:CC:DD:EE:FF:00:11:22:33

# Autenticación. La contraseña se proporciona utilizando uno de cinco métodos, véase a continuación.
user joe.smith

# Método de contraseña 1: Añadir la contraseña al keyring del sistema, y dejar que mpop la obtenga
# automáticamente. Para establecer la contraseña del keyring usando libsecret de Gnome:
# $ secret-tool store --label=mpop \
# host pop.freemail.example \
# service pop3 \
# user joe.smith

# Método de contraseña 2: Almacenar la contraseña en un archivo cifrado, y decirle a mpop
# qué comando usar para descifrarla. Esto se usa normalmente con GnuPG, como en
# este ejemplo. Normalmente gpg-agent pedirá una vez la contraseña de descifrado.
passwordeval gpg2 --no-tty -q -d ~/.mpop-password.gpg

# Método de contraseña 3: Almacenar la contraseña directamente en este archivo. Normalmente no es
# una buena idea almacenar contraseñas en archivos de texto plano. Si lo hace de todos modos, al menos
# asegúrese de que solo usted pueda leer este archivo.
#password secret123

# Método de contraseña 4: Almacenar la contraseña en ~/.netrc. Este método probablemente ya no es
# relevante.

# Método de contraseña 5: No especificar una contraseña. Mpop le pedirá entonces que la introduzca.
# Esto significa que debe poder escribir en una terminal cuando se ejecute mpop.

# Una segunda casilla de correo en el mismo servicio de correo gratuito
account freemail2 : freemail
user joey

# El servidor POP3 de su ISP
account isp
host mail.isp.example
auth on
user 12345
# Su ISP ejecuta SpamAssassin, así que pruebe cada correo con la cabecera "X-Spam-Status: Yes" y
# elimine todos los correos con esta cabecera antes de descargarlos.
filter if [ "`grep "^X-Spam-Status: Yes"`" ]; then exit 1;
else exit 0; fi

# Establecer una cuenta predeterminada
account default : freemail

Filtrado con SpamAssassin

El comando filter "/path/to/spamc -c > /dev/null" eliminará todos los correos que SpamAssassin considere spam. Dado que no se pasa ningún cuerpo de mensaje a SpamAssassin, debe deshabilitar todas las pruebas específicas del cuerpo en el archivo de configuración de SpamAssassin; por ejemplo, establezca use_bayes 0.

Si su proveedor de correo ejecuta SpamAssassin por usted, solo tiene que comprobar el resultado. El siguiente script puede hacerlo cuando se use como filtro de mpop:
#!/bin/sh
if [ "`grep "^X-Spam-Status: Yes"`" ]; then
exit 1 # eliminar este mensaje
else
exit 0 # proceder normalmente
fi
Dado que el comando de filtro se pasa a un shell, también puede usar esto directamente:
filter if [ "`grep "^X-Spam-Status: Yes"`" ]; then exit 1; else exit 0; fi

Uso de mpop con Tor

Utilice la siguiente configuración:
proxy_host 127.0.0.1
proxy_port 9050
tls on
Utilice una dirección IP como nombre de host del proxy, para que mpop no filtre una consulta DNS al resolverla.
TLS es necesario para evitar que los hosts de salida lean su sesión POP3.

ARCHIVOS

~/.mpoprc o $XDG_CONFIG_HOME/mpop/config
Archivo de configuración predeterminado.
~/.mpop_uidls
Directorio predeterminado para almacenar archivos UIDLs.
~/.netrc y SYSCONFDIR/netrc
El archivo netrc contiene información de inicio de sesión. Antes de solicitar una contraseña, msmtp lo buscará en ~/.netrc y SYSCONFDIR/netrc.

ENTORNO

$USER, $LOGNAME
Estas variables anulan el nombre de inicio de sesión del usuario. $LOGNAME solo se usa si $USER no está definido. El nombre de inicio de sesión del usuario se utiliza para las cabeceras Received.
