mknod(2) Manual de llamadas al sistema mknod(2)

NOMBRE

mknod, mknodat - crear un archivo especial o común

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/stat.h>
int mknod(const char *ruta, mode_t modo, dev_t dev);
#include <fcntl.h>           /* Definición de las constantes AT_* */
#include <sys/stat.h>
int mknodat(int fd_dir, const char *ruta, mode_t modo, dev_t dev);
Requisitos de macros de prueba de características para glibc (ver feature_test_macros(7)):

mknod():

    _XOPEN_SOURCE >= 500
        || /* Desde glibc 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */ _BSD_SOURCE || _SVID_SOURCE

DESCRIPCIÓN

La llamada al sistema mknod() crea un nodo del sistema de archivos (archivo, archivo especial de dispositivo o tubería con nombre) llamado ruta, con los atributos especificados por modo y dev.

El argumento modo especifica tanto el modo del archivo a utilizar como el tipo de nodo a crear. Debe ser una combinación (mediante OR bit a bit) de uno de los tipos de archivo listados a continuación y cero o más de los bits de modo de archivo listados en inode(7).

El modo del archivo se modifica por el umask del proceso de la forma habitual: en ausencia de una ACL predeterminada, los permisos del nodo creado son (modo & ~umask).

El tipo de archivo debe ser uno de S_IFREG, S_IFCHR, S_IFBLK, S_IFIFO o S_IFSOCK para especificar un archivo regular (que se creará vacío), un archivo especial de caracteres, un archivo especial de bloques, una FIFO (tubería con nombre) o un socket de dominio UNIX, respectivamente. (Un tipo de archivo cero es equivalente al tipo S_IFREG).

Si el tipo de archivo es S_IFCHR o S_IFBLK, entonces dev especifica los números mayor y menor del archivo especial de dispositivo recién creado (puede ser útil makedev(3) para construir el valor para dev); de lo contrario, se ignora.

Si ruta ya existe, o es un enlace simbólico, esta llamada falla con un error EEXIST.

El nodo recién creado será propiedad del ID de usuario efectivo del proceso. Si el directorio que contiene el nodo tiene el bit set-group-ID configurado, o si el sistema de archivos está montado con semántica de grupo BSD, el nuevo nodo heredará la propiedad de grupo de su directorio padre; de lo contrario, será propiedad del ID de grupo efectivo del proceso.

mknodat()

La llamada al sistema mknodat() opera exactamente de la misma manera que mknod(), excepto por las diferencias descritas aquí.

Si ruta es relativa, entonces se interpreta en relación con el directorio al que se refiere el descriptor de archivo fd_dir (en lugar de en relación con el directorio de trabajo actual del proceso que llama, como hace mknod() para una ruta relativa).

Si ruta es relativa y fd_dir es el valor especial AT_FDCWD, entonces ruta se interpreta en relación con el directorio de trabajo actual del proceso que llama (como mknod()).

Si ruta es absoluta, entonces fd_dir se ignora.

Ver openat(2) para una explicación de la necesidad de mknodat().

VALOR DE RETORNO

mknod() y mknodat() devuelven cero en caso de éxito. En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

EACCES
El directorio padre no permite permiso de escritura al proceso, o uno de los directorios en el prefijo de ruta de ruta no permitió permiso de búsqueda. (Ver también path_resolution(7).)
EBADF
(mknodat()) ruta es relativa pero fd_dir no es ni AT_FDCWD ni un descriptor de archivo válido.
EDQUOT
La cuota del usuario de bloques de disco o inodos en el sistema de archivos se ha agotado.
EEXIST
ruta ya existe. Esto incluye el caso en que ruta es un enlace simbólico, colgante o no.
EFAULT
ruta apunta fuera de su espacio de direcciones accesible.
EINVAL
modo solicitó la creación de algo que no sea un archivo regular, un archivo especial de dispositivo, una FIFO o un socket.
ELOOP
Se encontraron demasiados enlaces simbólicos al resolver ruta.
ENAMETOOLONG
ruta era demasiado larga.
ENOENT
Un componente de directorio en ruta no existe o es un enlace simbólico colgante.
ENOMEM
No había suficiente memoria del kernel disponible.
ENOSPC
El dispositivo que contiene ruta no tiene espacio para el nuevo nodo.
ENOTDIR
Un componente utilizado como directorio en ruta no es, de hecho, un directorio.
ENOTDIR
(mknodat()) ruta es relativa y fd_dir es un descriptor de archivo que se refiere a un archivo distinto de un directorio.
EPERM
modo solicitó la creación de algo que no sea un archivo regular, una FIFO (tubería con nombre) o un socket de dominio UNIX, y el llamador no está privilegiado (Linux: no tiene la capacidad CAP_MKNOD); también se devuelve si el sistema de archivos que contiene ruta no admite el tipo de nodo solicitado.
EROFS
ruta se refiere a un archivo en un sistema de archivos de solo lectura.

VERSIONES

POSIX.1-2001 dice: "El único uso portable de mknod() es crear un archivo especial FIFO. Si modo no es S_IFIFO o dev no es 0, el comportamiento de mknod() no está especificado." Sin embargo, hoy en día nunca se debería usar mknod() para este propósito; se debería usar mkfifo(3), una función especialmente definida para este propósito.

Bajo Linux, mknod() no se puede usar para crear directorios. Se deberían crear directorios con mkdir(2).

ESTANDARES

POSIX.1-2024.

HISTORIA

mknod()
SVr4, 4.4BSD, POSIX.1-2001 (pero ver VERSIONES).
mknodat()
Linux 2.6.16, glibc 2.4. POSIX.1-2008.

NOTAS

Existen muchas imperfecciones en el protocolo subyacente de NFS. Algunas de estas afectan a mknod() y mknodat().
