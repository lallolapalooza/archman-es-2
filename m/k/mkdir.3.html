Descripción detallada

Interfaz abstracta para proporcionar soporte para archivos definidos por el usuario.

Advertencia

Esto es para usuarios avanzados y experimentados. No lo necesitas a menos que realmente sepas lo que estás haciendo. La mayoría de las aplicaciones no lo necesitarán.

Históricamente, PhysicsFS proporcionaba un medio para montar varios formatos de archivo y directorios físicos en el sistema de archivos nativo. Sin embargo, las aplicaciones se limitaban a los formatos de archivo proporcionados por la biblioteca. Esta interfaz permite a una aplicación proporcionar sus propios tipos de archivos de archivo.

Conceptualmente, un PHYSFS_Archiver proporciona entradas de directorio, mientras que PHYSFS_Io proporciona flujos de datos para esas entradas de directorio. El uso más obvio de PHYSFS_Archiver es proporcionar soporte para un tipo de archivo que PhysicsFS no proporciona directamente: quizás algún formato propietario que solo su aplicación necesite entender.

Internamente, todo el soporte de archivo incorporado utiliza esta interfaz, por lo que los mejores ejemplos para construir un PHYSFS_Archiver son el código fuente de PhysicsFS mismo.

Un archivador se añade al sistema con PHYSFS_registerArchiver(), y luego estará disponible para su uso automáticamente con PHYSFS_mount(); si un archivo determinado puede ser manejado por su archivador, se le dará el control según corresponda.

Estos métodos tratan con manejadores de directorios. Tiene una instancia de su archivador y genera un manejador único y opaco para cada archivo abierto en su método openArchive(). Dado que la vida útil de un Archivador (no de un archivo) es generalmente la vida útil completa del proceso, y se asume que es un singleton, no proporcionamos ningún dato de instancia para el propio archivador; la aplicación puede usar variables estáticas si es necesario.

Los enlaces simbólicos siempre deben seguirse (excepto en stat()); PhysicsFS utilizará el método stat() para verificar los enlaces simbólicos y tomar una decisión sobre si continuar llamando a otros métodos basándose en eso.

Los archivadores, cuando sea necesario, deben establecer el estado de error de PhysicsFS con PHYSFS_setErrorCode() antes de devolver. PhysicsFS pasará estos errores a la aplicación sin modificaciones en la mayoría de los casos.

Seguridad en hilos: No se garantiza que las implementaciones de PHYSFS_Archiver sean seguras en hilos por sí mismas. PhysicsFS proporciona seguridad en hilos cuando llama a un archivador determinado dentro de la biblioteca, pero no promete que usar el mismo PHYSFS_File desde dos hilos a la vez sea seguro en hilos; como tal, su PHYSFS_Archiver puede asumir que el bloqueo se maneja por usted siempre que el PHYSFS_Io que devuelva de PHYSFS_open* no cambie ningún estado de su Archivador, ya que el PHYSFS_Io no estará protegido de forma tan agresiva.

Documentación de campos

void(* PHYSFS_Archiver::closeArchive) (void *opaque)

Destruir un archivo previamente abierto. Cierra este archivo y libera toda la memoria asociada, incluido el PHYSFS_Io original y (opaque) en sí, si corresponde. La implementación puede asumir que no se llamará si todavía hay archivos abiertos de este archivo.

PHYSFS_EnumerateCallbackResult(* PHYSFS_Archiver::enumerate) (void *opaque, const char *dirname, PHYSFS_EnumerateCallback cb, const char *origdir, void *callbackdata)

Listar todos los archivos en (dirname). Cada archivo se pasa a (cb), donde se hace una copia si es apropiado, por lo que puede desecharla al regresar de la devolución de llamada. (dirname) está en notación independiente de la plataforma. Si tiene un error, llame a PHYSFS_SetErrorCode() con el código que parezca apropiado y devuelva PHYSFS_ENUM_ERROR. Si la devolución de llamada devuelve PHYSFS_ENUM_ERROR, llame a PHYSFS_SetErrorCode(PHYSFS_ERR_APP_CALLBACK) y luego devuelva también PHYSFS_ENUM_ERROR. No llame a la devolución de llamada nuevamente bajo ninguna circunstancia. Si la devolución de llamada devuelve PHYSFS_ENUM_STOP, deje de enumerar y devuelva también PHYSFS_ENUM_STOP. No llame a la devolución de llamada nuevamente bajo ninguna circunstancia. No establezca un código de error en este caso. Las devoluciones de llamada solo deben devolver un valor de PHYSFS_EnumerateCallbackResult. Cualquier otro resultado tiene un comportamiento indefinido. Mientras la devolución de llamada haya devuelto PHYSFS_ENUM_OK y usted no haya experimentado ningún error propio, continúe enumerando hasta que termine y luego devuelva PHYSFS_ENUM_OK sin establecer un código de error.

Advertencia

PHYSFS_enumerate devuelve cero o no cero (éxito o fracaso), así que tenga en cuenta que este puntero de función devuelve valores diferentes.

PHYSFS_ArchiveInfo PHYSFS_Archiver::info

Información básica sobre este archivador. Se utiliza para identificar su archivo y se devuelve en PHYSFS_supportedArchiveTypes().

int(* PHYSFS_Archiver::mkdir) (void *opaque, const char *filename)

Crear un directorio en el archivo. Si la aplicación intenta crear múltiples directorios, PhysicsFS los dividirá en múltiples llamadas antes de pasarlas a su controlador. Si el archivo es de solo lectura, esta operación debería fallar. Devuelve un valor distinto de cero en caso de éxito, cero en caso de fallo. Este nombre de archivo está en notación independiente de la plataforma. En caso de fallo, llame a PHYSFS_setErrorCode().

PHYSFS_Io *(* PHYSFS_Archiver::openAppend) (void *opaque, const char *filename)

Abrir un archivo en este archivo para añadir. Si el archivo no existe, debe crearse. El desplazamiento de escritura debe ser el final del archivo. Si el archivo es de solo lectura, esta operación debería fallar. Este nombre de archivo está en notación independiente de la plataforma. Devuelve NULL en caso de fallo y llama a PHYSFS_setErrorCode(). Devuelve no NULL en caso de éxito. El puntero devuelto se pasará como parámetro "opaque" para llamadas de archivo posteriores.

void *(* PHYSFS_Archiver::openArchive) (PHYSFS_Io *io, const char *name, int forWrite, int *claimed)

Abrir un archivo proporcionado por (io). Aquí es donde se asignan recursos y se analizan los datos al montar un archivo. (name) es un nombre de archivo asociado con (io), pero no necesariamente se corresponde con nada, y menos aún con un nombre de archivo real. Este nombre posiblemente sin sentido está en notación dependiente de la plataforma. (forWrite) es distinto de cero si este se usará para el directorio de escritura y cero si se usará para un elemento de la búsqued

PHYSFS_Io *(* PHYSFS_Archiver::openArchive) (const char *filename, int *claimed)

Intenta abrir un archivo en este formato de archivo. Si (filename) es un archivo que su implementación de archivador puede manejar, deberá devolver un puntero a un PHYSFS_Io, y establecer claimed a 1. Si no es un archivo que su implementación pueda manejar, devuelva NULL y establezca claimed a 0. Si su implementación puede manejar el archivo, pero falla al abrirlo (por ejemplo, archivo corrupto, o no tiene suficientes permisos, etc.), debe establecer claimed a 1 y devolver NULL. El valor de claimed se establecerá en 1 si se trata definitivamente de un archivo que su implementador de archivador puede manejar, incluso si falla. Usamos esto para decidir si debemos dejar de intentar con otros archivadores si falla al abrirlo. Por ejemplo: el archivador .zip establecerá esto en 1 para algo que tiene una firma de archivo .zip, incluso si falla porque el archivo también está truncado. No tiene sentido intentar con otros archivadores aquí, ¡ya hemos intentado manejarlo con la implementación apropiada! Devuelve NULL en caso de fallo y establece claimed apropiadamente. Si ningún archivador abrió el archivo o estableció claimed, PHYSFS_mount() informará PHYSFS_ERR_UNSUPPORTED. De lo contrario, informará el error del archivador que reclamó los datos a través de claimed. Devuelve un valor no NULL en caso de éxito. El puntero devuelto se pasará como parámetro "opaque" para llamadas posteriores.

PHYSFS_Io *(* PHYSFS_Archiver::openRead) (void *opaque, const char *fnm)

Abre un archivo en este archivo para lectura. Este nombre de archivo, (fnm), está en notación independiente de la plataforma. Fallará si el archivo no existe. Devuelve NULL en caso de fallo y llama a PHYSFS_setErrorCode(). Devuelve un valor no NULL en caso de éxito. El puntero devuelto se pasará como parámetro "opaque" para llamadas posteriores de archivos.

PHYSFS_Io *(* PHYSFS_Archiver::openWrite) (void *opaque, const char *filename)

Abre un archivo en este archivo para escritura. Si el archivo no existe, debe crearse. Si existe, debe truncarse a cero bytes. El desplazamiento de escritura debe ser el inicio del archivo. Si el archivo es de solo lectura, esta operación debe fallar. Este nombre de archivo está en notación independiente de la plataforma. Devuelve NULL en caso de fallo y llama a PHYSFS_setErrorCode(). Devuelve un valor no NULL en caso de éxito. El puntero devuelto se pasará como parámetro "opaque" para llamadas posteriores de archivos.

int(* PHYSFS_Archiver::remove) (void *opaque, const char *filename)

Elimina un archivo o directorio en el archivo. Esta misma llamada se utiliza tanto para archivos como para directorios; no hay una llamada separada rmdir(). Los directorios solo deben eliminarse si están vacíos. Si el archivo es de solo lectura, esta operación debe fallar.

Devuelve un valor distinto de cero en caso de éxito, cero en caso de fallo. Este nombre de archivo está en notación independiente de la plataforma. En caso de fallo, llama a PHYSFS_setErrorCode().

int(* PHYSFS_Archiver::stat) (void *opaque, const char *fn, PHYSFS_Stat *stat)

Obtiene metadatos básicos del archivo. En caso de éxito, completa todos los campos en (stat), utilizando valores predeterminados razonables para los campos que se aplican a su archivo.

Devuelve un valor distinto de cero en caso de éxito, cero en caso de fallo. Este nombre de archivo está en notación independiente de la plataforma. En caso de fallo, llama a PHYSFS_setErrorCode().

PHYSFS_uint32 PHYSFS_Archiver::version

Información de compatibilidad binaria. Debe establecerse en cero en este momento. Las versiones futuras de esta estructura incrementarán este campo, por lo que sabremos qué soporta una implementación dada. Presumiblemente seguiremos dando soporte a versiones anteriores a medida que ofrezcamos nuevas funciones, aunque.
