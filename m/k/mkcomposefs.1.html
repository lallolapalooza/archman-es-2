NOMBRE

mkcomposefs - crea una imagen de sistema de archivos composefs

SINOPSIS

mkcomposefs ORIGEN IMAGEN

DESCRIPCIÓN

El proyecto composefs utiliza archivos de imagen EROFS para almacenar metadatos y uno o más directorios separados que contienen datos de respaldo dirigidos por contenido para archivos regulares.

mkcomposefs construye la "imagen composefs" montable utilizando el origen como entrada. También puede crear el directorio de almacenamiento de respaldo. Típicamente, el origen es un directorio, pero con --from-file también puede ser un archivo.

OPCIONES

El argumento DIRECTORIO_ORIGEN proporcionado debe ser un directorio y todo su contenido se leerá recursivamente. El argumento IMAGEN proporcionado será una imagen composefs montable.

mkcomposefs acepta las siguientes opciones:

--digest-store=RUTA
Esta ruta se convertirá en una "tienda de objetos" de composefs. Los archivos regulares de más de 64 bytes en el DIRECTORIO_ORIGEN se copiarán (revinculados si es posible) en este directorio de destino, nombrados según su digest fsverity. Los archivos pequeños se insertarán en los metadatos de la imagen. Si es posible, los archivos añadidos tendrán habilitado fs-verity.

Este directorio debe pasarse a la opción basedir al montar la imagen.

--print-digest
Imprime el digest fsverity del archivo de metadatos de composefs.
--print-digest-only
Imprime el digest fsverity del archivo de metadatos de composefs, pero no escribe la imagen. Si se pasa esto, se debe omitir el argumento IMAGEN.
--use-epoch
Utiliza una hora cero (época Unix) como hora de modificación para todos los archivos.
--skip-devices
No añade nodos de dispositivo a la imagen.
--skip-xattrs
No añade xattrs a los archivos de la imagen.
--user-xattrs
Solo añade xattrs con el prefijo "user." a los archivos de la imagen.
--from-file
El origen es un archivo en el formato composefs-dump(5). Si el archivo especificado es "-", los datos se leen desde stdin.
--version=VERSIÓN
La versión base a utilizar para el formato de la imagen.
--max-version=VERSIÓN
Si esto especifica una versión superior a --version, entonces la versión real del formato de imagen utilizada se ajustará hacia arriba si eso es beneficioso para la imagen, hasta la versión máxima.
--threads=COUNT
Número de hilos que se utilizarán para calcular los digests de los archivos y copiarlos. El número de hilos por defecto es el número de procesadores cuando no se especifica --threads.

VERSIONADO DE FORMATO

Las imágenes composefs son binariamente reproducibles, lo que significa que para una entrada dada, el resultado es siempre el mismo, dando el mismo digest de la imagen. Esto es importante ya que el digest se utiliza para validar la imagen, incluso si la imagen se recreó en lugar de transferirse tal cual. Sin embargo, a veces el formato necesita ser modificado, por ejemplo, cuando se introduce un nuevo tipo de archivo o se corrige un error. Esto se maneja introduciendo una versión de formato.

Especificar la versión se hace con dos opciones, la versión base (--version) y la versión máxima (--max-version). Al construir una imagen, mkcomposefs intenta mantener el formato de la imagen lo más bajo posible, pero si alguna característica solicitada en particular no está disponible con la característica base, pero es accesible en la versión máxima, entonces la versión utilizada aumentará. Esto nos permite introducir nuevas características y corregir errores en una versión posterior y migrar a ella utilizando versiones máximas, pero manteniendo los digests idénticos para las imágenes no afectadas.

Si necesita reproducibilidad binaria del 100% con el tiempo, especifique la misma versión y una versión máxima cada vez.

Historial de versiones de formato:

  • 0 - Versión inicial
  • 1 - Soporta archivos de ocultación de superposición (whiteout) en la imagen (añadido en 1.0.3)

El valor predeterminado si no se especifican argumentos de versión es la versión 0 y la versión máxima 1.

RECOMENDACIONES DE AISLAMIENTO

Esta herramienta esencialmente solo procesa un directorio de entrada o un archivo de texto y escribe un archivo. No requiere ningún privilegio en absoluto. Si está invocando esto como parte de un proceso con privilegios (como un tiempo de ejecución de contenedor), recomendamos reducir los privilegios antes de invocar mkcomposefs.

Especialmente si está usando --from-file, puede ejecutar esto como un usuario no privilegiado que no tiene acceso de escritura a ningún sistema de archivos, excepto a un descriptor de archivo pasado. Por ejemplo, puede pasar un descriptor de archivo escribible para el archivo de destino deseado como fd 3, y ejecutar mkcomposefs --from-file - /proc/self/fd/3 para utilizar efectivamente mkcomposefs como parte de una tubería.

Un ejemplo simple de aislamiento a partir de root es setpriv --nnp --reuid nobody -- mkcomposefs .... Otro es usar systemd-run -P DynamicUser=yes -P ProtectSystem=strict. Otro más (especialmente si su código ya forma parte de un tiempo de ejecución de contenedor) es utilizar la funcionalidad existente de ese tiempo de ejecución (seccomp, espacio de nombres de usuario no compartido, montaje de un subconjunto restringido del rootfs, etc.
