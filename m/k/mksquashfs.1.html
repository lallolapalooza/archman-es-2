MKSQUASHFS(1) Comandos de usuario MKSQUASHFS(1)

NOMBRE

mksquashfs - herramienta para crear y añadir a sistemas de archivos squashfs

SINOPSIS

mksquashfs fuente1 fuente2 ... SISTEMA_ARCHIVOS [OPCIONES] [-e lista de directorios/archivos a excluir]

DESCRIPCIÓN

Squashfs es un sistema de archivos de solo lectura altamente comprimido para Linux. Utiliza compresión gzip/xz/lzo/lz4/zstd para comprimir tanto archivos, inodos como directorios. Los inodos en el sistema son muy pequeños y todos los bloques se empaquetan para minimizar la sobrecarga de datos. Se admiten tamaños de bloque mayores que 4K hasta un máximo de 1 Mbyte (tamaño de bloque predeterminado 128K).

Squashfs está destinado al uso general de sistemas de archivos de solo lectura, para uso de archivo (es decir, en casos en los que se podría usar un archivo .tar.gz), y en sistemas con dispositivos de bloque/memoria restringidos (por ejemplo, sistemas integrados) donde se necesita baja sobrecarga.

OPCIONES

Opciones de compresión del sistema de archivos:

-b TAMAÑO_BLOQUE
establece el bloque de datos a TAMAÑO_BLOQUE. Predeterminado 128 Kbytes. Opcionalmente se puede dar un sufijo de K, KB, Kbytes o M, MB, Mbytes para especificar Kbytes o Mbytes respectivamente.
-comp COMP
selecciona la compresión COMP. Ejecuta -help-comp COMP para obtener opciones del compresor para COMP, o ALL para todos los compresores. Compresores disponibles: gzip (predeterminado), lzo, lz4, xz, zstd, lzma.
-noI
no comprimir la tabla de inodos.
-noId
no comprimir la tabla uid/gid (implícito por -noI).
-noD
no comprimir los bloques de datos.
-noF
no comprimir los bloques de fragmentos.
-noX
no comprimir los atributos extendidos.
-no-compression
no comprimir ninguno de los datos o metadatos. Esto es equivalente a especificar -noI -noD -noF y -noX.

Opciones de creación del sistema de archivos:

-tar
leer archivo tar sin comprimir desde la entrada estándar (stdin).
-no-strip
actuar como tar, y no eliminar los directorios iniciales de los archivos fuente.
-tarstyle
nombre alternativo para -no-strip.
-cpiostyle
actuar como cpio, y leer nombres de archivos desde la entrada estándar (stdin).
-cpiostyle0
similar a -cpiostyle, pero los nombres de archivo están terminados en nulo. Se puede usar con la acción -print0 de find.
-no-exports
no hacer que el sistema de archivos sea exportable a través de NFS ( predeterminado de -tar).
-exports
hacer que el sistema de archivos sea exportable a través de NFS ( predeterminado).
-no-sparse
no detectar archivos dispersos.
-no-tailends
no empaquetar extremos de cola en fragmentos (predeterminado).
-tailends
empaquetar extremos de cola en fragmentos.
-no-fragments
no usar fragmentos.
-no-duplicates
no realizar comprobación de duplicados.
-no-hardlinks
no enlazar archivos de forma dura, en su lugar, almacenar duplicados.
-keep-as-directory
si se especifica un directorio fuente, crear un directorio raíz que contenga ese directorio, en lugar del contenido del directorio.

Opciones de tiempo del sistema de archivos:

-mkfs-time TIEMPO
establece la marca de tiempo de creación del sistema de archivos a TIEMPO. TIEMPO puede ser "inode", que significa usar la marca de tiempo del inodo más reciente, un entero sin signo de 32 bits que indica segundos desde la época (1970-01-01) o un valor de cadena que se pasa al comando "date" para su análisis. Se puede usar cualquier valor de cadena que el comando date reconozca, como "now", "last week", o "Wed Feb 15 21:02:39 GMT 2023".
-inode-time TIEMPO
establece todas las marcas de tiempo de archivos y directorios a TIEMPO. TIEMPO puede ser "inode", que significa usar la marca de tiempo del inodo más reciente, un entero sin signo de 32 bits que indica segundos desde la época (1970-01-01) o un valor de cadena que se pasa al comando "date" para su análisis. Se puede usar cualquier valor de cadena que el comando date reconozca, como "now", "last week", o "Wed Feb 15 21:02:39 GMT 2025". Esta opción establece y anula la opción -root-time.
-root-time TIEMPO
establece la marca de tiempo del directorio raíz a TIEMPO. TIEMPO puede ser "inode", que significa usar la marca de tiempo del inodo más reciente, un entero sin signo de 32 bits que indica segundos desde la época (1970-01-01) o un valor de cadena que se pasa al comando "date" para su análisis. Se puede usar cualquier valor de cadena que el comando date reconozca, como "now", "last week", o "Wed Feb 15 21:02:39 GMT 2025".
-repro
crea una imagen de sistema de archivos reproducible. Esto es equivalente a -mkfs-time inode, lo que logra la reproducibilidad al establecer el tiempo de creación del sistema de archivos a la marca de tiempo del inodo más reciente. Obviamente, la imagen no será reproducible si cambian las marcas de tiempo o el contenido.
-repro-time TIEMPO
crea una imagen de sistema de archivos reproducible. Esto es equivalente a especificar -mkfs-time TIEMPO y -inode-time TIEMPO, lo que logra la reproducibilidad al establecer todas las marcas de tiempo a TIEMPO. Esta opción se puede usar en casos donde las marcas de tiempo pueden cambiar, y donde -repro no se puede usar por esta razón.

Opciones de permisos del sistema de archivos:

-all-root
hacer que todos los archivos y directorios pertenezcan a root.
-root-mode MODO
establece los permisos del directorio raíz a MODO. MODO puede ser simbólico u octal (ver sección Especificación de modo simbólico). El modo raíz predeterminado es ugo=rwx o 0777 octal.
-root-uid USUARIO
establece el propietario del directorio raíz al USUARIO especificado, USUARIO puede ser un uid entero o un nombre de usuario.
-root-gid GRUPO
establece el grupo del directorio raíz al GRUPO especificado, GRUPO puede ser un gid entero o un nombre de grupo.
-force-file-mode MODO
establece todos los permisos de archivos (no directorios) a MODO. MODO puede ser simbólico u octal (ver sección Especificación de modo simbólico).
-force-dir-mode MODO
establece todos los permisos de directorios a MODO. MODO puede ser simbólico u octal (ver sección Especificación de modo simbólico).
-force-uid USUARIO
establece todos los uid de archivos y directorios al USUARIO especificado, USUARIO puede ser un uid entero o un nombre de usuario.
-force-gid GRUPO
establece todos los gid de archivos y directorios al GRUPO especificado, GRUPO puede ser un gid entero o un nombre de grupo.
-uid-gid-offset VALOR
desplaza todos los uid y gid por el VALOR especificado. VALOR debe ser un entero.

Opciones de depuración y ayuda:

-h, --help
muestra un resumen de las opciones.
-h COMP, --help COMP
muestra opciones del compresor COMP.
-h ALL, --help ALL
muestra opciones de todos los compresores.
-v, --version
muestra la versión de mksquashfs y sale.
-x, --export-file ARCHIVO
exporta la estructura de directorios de la imagen squashfs a ARCHIVO en formato tar.
-i, --info ARCHIVO
muestra información sobre el sistema de archivos squashfs en ARCHIVO.
-s, --show-fragments ARCHIVO
muestra la lista de fragmentos en ARCHIVO.
-p, --print-contents ARCHIVO
muestra el contenido de ARCHIVO.
-a, --always-use-fragments
usa fragmentos para todos los archivos. Esto se usa para mejorar el rendimiento en dispositivos de bloque pequeños, pero aumentará el tamaño del sistema de archivos.
-no-ugly
elimina información que se considera "fea" (por ejemplo, directorios vacíos en el nivel superior). No recomendado.
-no-overwrite
no sobrescribir un sistema de archivos squashfs existente.

Opciones para añadir a un sistema de archivos:

-a, --append
añade un nuevo sistema de archivos squashfs a un sistema de archivos squashfs existente. El sistema de archivos squashfs existente debe tener el mismo tamaño de bloque y algoritmo de compresión. Las opciones de compresión no se pueden especificar cuando se utiliza esta opción.

EJEMPLO

Crea un sistema de archivos squashfs llamado myfs.squashfs a partir de los directorios dir1 y dir2, utilizando compresión xz y un tamaño de bloque de 1024 Kbytes:

    mksquashfs dir1 dir2 myfs.squashfs -comp xz -b 1024K

Crea un sistema de archivos squashfs omitiendo los directorios dir1/stuff y dir1/tmp:

    mksquashfs dir1 myfs.squashfs -e stuff tmp

Crea un sistema de archivos squashfs reproducible:

    mksquashfs /dir/to/source myfs.squashfs -repro

Crea un sistema de archivos squashfs reproducible con una marca de tiempo específica:

    mksquashfs /dir/to/source myfs.squashfs -repro-time "2024-01-01 12:00:00"

VER TAMBIÉN

Opciones pseudo de sistema de archivos:

-p PSEUDO-DEFINITION
agrega definición de archivo pseudo. La definición debe ir entre comillas. Consulte la sección "Formato de definición de archivo pseudo" para ver los detalles del formato.
-pd "d modo uid gid"
especifica un directorio pseudo predeterminado que se utilizará en las definiciones pseudo si un directorio en la ruta no existe. Esto también permite especificar definiciones pseudo sin especificar todos los directorios en la ruta. La definición debe ir entre comillas.
-pd "D tiempo modo uid gid"
especifica un directorio pseudo predeterminado que se utilizará en las definiciones pseudo si un directorio en la ruta no existe. El tipo D también permite especificar una marca de tiempo además del modo, uid y gid.
-pf PSEUDO-FILE
agrega una lista de definiciones de archivos pseudo del ARCHIVO-PSEUDO, use - para stdin. Las definiciones de archivos pseudo no deben ir entre comillas.
-pseudo-override
hace que los uid y gid de los archivos pseudo anulen las opciones -all-root, -force-uid y -force-gid.

Opciones de filtro de sistema de archivos:

-sort SORT-FILE
ordena archivos según las prioridades en ARCHIVO-ORDENAR. Un archivo o directorio con prioridad por línea. Prioridad de -32768 a 32767, prioridad predeterminada 0.
-ef EXCLUDE-FILE
lista de directorios/archivos excluidos. Uno por línea.
-wildcards
permite usar comodines extendidos del shell (globbing) en directorios/archivos excluidos.
-regex
permite usar expresiones regulares POSIX en directorios/archivos excluidos.
-max-depth LEVELS
desciende como máximo LEVELS de directorios al escanear el sistema de archivos.
-one-file-system
no cruza los límites del sistema de archivos. Si un directorio cruza el límite, crea un directorio vacío para cada punto de montaje. Si un archivo cruza el límite, ignórelo.
-one-file-system-x
no cruza los límites del sistema de archivos. Similar a la opción -one-file-system, excepto que los directorios también se ignoran si cruzan el límite.

Opciones de atributo extendido (xattrs) del sistema de archivos:

-no-xattrs
no almacena atributos extendidos.
-xattrs
almacena atributos extendidos (predeterminado).
-xattrs-exclude REGEX
excluye cualquier nombre de xattr que coincida con REGEX. REGEX es una expresión regular POSIX, p. ej., -xattrs-exclude '^user.' excluye xattrs del espacio de nombres de usuario.
-xattrs-include REGEX
incluye cualquier nombre de xattr que coincida con REGEX. REGEX es una expresión regular POSIX, p. ej., -xattrs-include '^user.' incluye xattrs del espacio de nombres de usuario.
-xattrs-add NAME=VAL
agrega el xattr NAME con VAL a los archivos. Si es un xattr de usuario, se agregará a archivos y directorios regulares (ver man 7 xattr). De lo contrario, se agregará a todos los archivos. VAL por defecto se tratará como binario (es decir, una secuencia de bytes no interpretada), pero puede ir precedido de 0s, donde se tratará como codificado en base64, o precedido de 0x, donde val se tratará como hexadecimal. Además, puede ir precedido de 0t donde esta codificación es similar a la codificación binaria, excepto que las barras invertidas se tratan especialmente, y se puede usar una barra invertida seguida de 3 dígitos octales para codificar cualquier carácter ASCII, lo que obviamente se puede usar para codificar códigos de control. La opción se puede repetir varias veces para agregar varios xattrs.

Opciones de tiempo de ejecución de Mksquashfs:

-version
imprime el mensaje de versión, licencia y derechos de autor.
-exit-on-error
trata los errores normalmente ignorados como fatales.
-quiet
sin salida detallada.
-info
imprime los archivos escritos en el sistema de archivos en la salida estándar. Esto deshabilita automáticamente la barra de progreso. Consulte -info-file para enviar la salida a un archivo sin deshabilitar la barra de progreso.
-info-file FILE
imprime los archivos escritos en el sistema de archivos en el archivo ARCHIVO. Esto no deshabilita la barra de progreso.
-no-progress
no muestra la barra de progreso.
-progress
muestra la barra de progreso cuando se usa la opción -info.
-percentage
muestra un porcentaje en lugar de la barra de progreso completa. Se puede usar con el diálogo --gauge, etc.
-throttle PERCENTAGE
limita la tasa de E/S de entrada en el porcentaje dado. Esto se puede usar para reducir el consumo de E/S y CPU de Mksquashfs.
-limit PERCENTAGE
limita la tasa de E/S de entrada al porcentaje dado. Esto se puede usar para reducir el consumo de E/S y CPU de Mksquashfs (alternativa a -throttle).
-processors NUMBER
usa NUMBER procesadores. Por defecto, usará el número de procesadores disponibles.
-mem SIZE
usa SIZE de memoria física para cachés. Use K, M o G para especificar Kbytes, Mbytes o Gbytes respectivamente.
-mem-percent PERCENT
usa PERCENT de memoria física para cachés. Por defecto es 25%.
-mem-default
imprime el uso de memoria predeterminado en Mbytes.
-single-reader
usa un solo hilo para leer archivos. Esto lee archivos secuencialmente de las fuentes.
-small-readers N
usa N hilos para leer archivos pequeños (archivos de menos de un tamaño de bloque) en paralelo desde las fuentes (predeterminado 4).
-block-readers N
usa N hilos para leer archivos de bloque (archivos de tamaño de bloque o mayor) en paralelo desde las fuentes (predeterminado 4).
-overcommit PERCENT
permite que PERCENT más hilos se ejecuten en paralelo que los procesadores disponibles. Hacer esto puede aumentar la utilización de la CPU. El valor predeterminado es 0%, ya que normalmente la sobreasignación reduce el rendimiento debido a la paginación. El valor porcentual está en la granularidad del número de procesadores, por ejemplo, 4 procesadores tienen una granularidad porcentual del 25%, y 20 procesadores tienen una granularidad porcentual del 5%.

Opciones de adjuntar de sistema de archivos:

-noappend
no adjuntar al sistema de archivos existente.
-root-becomes NAME
al adjuntar archivos/directorios de origen, hacer que la raíz original se convierta en un subdirectorio en la nueva raíz llamado NAME, en lugar de agregar los nuevos elementos de origen a la raíz original.
-no-recovery
no generar un archivo de recuperación.
-recovery-path NAME
usar NAME como el directorio para almacenar el archivo de recuperación.
-recover NAME
recuperar datos del sistema de archivos usando el archivo de recuperación NAME.

Opciones de acciones de sistema de archivos:

-action ACTION@EXPRESSION
evaluar EXPRESIÓN en cada archivo y directorio, y ejecutar ACCIÓN si devuelve VERDADERO.
-log-action ACTION@EXPRESSION
igual que -action, pero registra los resultados de la evaluación de expresiones y las acciones realizadas.
-true-action ACTION@EXPRESSION
igual que -action, pero solo registra las expresiones que devuelven VERDADERO.
-false-action ACTION@EXPRESSION
igual que -action, pero solo registra las expresiones que devuelven FALSO.
-action-file FILE
igual que acción, pero lee las acciones del ARCHIVO.
-log-action-file FILE
igual que -log-action, pero lee las acciones del ARCHIVO.
-true-action-file FILE
igual que -true-action, pero lee las acciones del ARCHIVO.
-false-action-file FILE
igual que -false-action, pero lee las acciones del ARCHIVO.

los archivos tar a menudo no almacenan los permisos para los directorios intermedios. Esta opción establece los permisos de directorio predeterminados en MODO. MODO puede ser simbólico

OPTIONS

-b block-size
Set block size for the filesystem. The default is 128 Kbytes, or if fragmented inodes are used then 1 Kibyte.
-all-root
Make all files and directories owned by root.
-comp compressor
Select compression algorithm. The default is gzip. Available compressors are: gzip, lzo, lz4, xz, zstd, lzma.
-no-compress
Do not compress any files.
-comp-dir directory
Directory to store compression tables for. Default is to use the block size set by -b.
-Xcompression-level COMPRESSION-LEVEL
Set the compression level for the compressor. The level is compressor specific. This option is passed directly to the chosen compressor library. If the chosen compressor library does not support compression levels, then this option is ignored.
-Xfragment-size size
Set maximum size of fragments. Fragments are used to store files smaller than the block size. The default is 1024 bytes. The minimum fragment size is 100 bytes and the maximum is 1/2 of block size. If the fragment size is set to 0 then fragments are disabled.
-Xfragment-count count
Set maximum number of fragments. The default is 2048. If the fragment count is set to 0 then fragments are disabled.
-no-fragments
Disable fragments. This is equivalent to setting -Xfragment-size 0 and -Xfragment-count 0.
-f
Force overwrite of the output file.
-e
Add exclusion pattern. The pattern is a Glob pattern, not a regular expression. See glob(7) for a description of patterns. The pattern is compared to the full pathname. You can use multiple -e options to specify multiple exclusion patterns. If the pattern is negated by starting with !, then it acts as an inclusion pattern.
-wildcards
Enable wildcard processing for exclusion patterns. By default, patterns are only matched against the basename. When this option is used, patterns can contain path separators and will be matched against the full path. Wildcards are processed by the shell and so patterns must be quoted to prevent shell expansion.
-p
Add pseudo-file definition. See section Pseudo-file definitions below.
-root-mode mode
Set the file mode for the root directory. Default is 755.
-root-owner
Make the root directory owned by root.
-force-uid uid
Force the UID for all files and directories. This option can be specified multiple times to force multiple UIDs. Can be specified as a name (eg. root) or as a number.
-force-gid gid
Force the GID for all files and directories. This option can be specified multiple times to force multiple GIDs. Can be specified as a name (eg. root) or as a number.
-force-user user
Force the user for all files and directories. This option is equivalent to -force-uid.
-force-group group
Force the group for all files and directories. This option is equivalent to -force-gid.
-force-file-mode mode
Force the file mode for all files. The mode is specified in octal or symbolic notation (e.g. 644 or u+r).
-force-dir-mode mode
Force the directory mode for all directories. The mode is specified in octal or symbolic notation (e.g. 755 or u+rx).
-no-exports
Do not export the filesystem to be mounted by NFS.
-no-xattrs
Do not store any extended attributes in the Squashfs filesystem. Any extended attributes in the source files will be ignored.
-xattrs-include xattr-spec
Only store extended attributes matching the xattr-spec. The xattr-spec is a glob pattern. See glob(7) for a description of patterns. By default, all extended attributes are stored.
-xattrs-exclude xattr-spec
Do not store extended attributes matching the xattr-spec. The xattr-spec is a glob pattern. See glob(7) for a description of patterns. By default, all extended attributes are stored.
-xattrs-add xattr-spec
Add the specified extended attribute to all files and directories in the filesystem. The xattr-spec is of the form:

name=value

Where name is the extended attribute name and value is the value to be set. The value can be specified as a string or as an octal representation of the value. See squashfs_edit(8) for more details. Values can contain newlines and other special characters. These should be represented as octal escape sequences (e.g. \012 for a newline).
-all-time timestamp
Set all file and directory timestamps to the specified timestamp. The timestamp can be specified as a number of seconds since the epoch, or as "now".
-no-exports
Do not export the filesystem to be mounted by NFS.
-root-squash
Map root user to nobody when the filesystem is mounted.
-no-root-squash
Do not map root user to nobody when the filesystem is mounted.
-quiet
Suppress progress messages.
-progress
Show progress messages.
-no-progress
Suppress progress messages.
-printf format
Print filesystem information according to format.
-help
Display help message.
-version
Display version information.

Compression options:

The following options are specific to compressors. They are passed as options to the compression library. If the chosen compressor library does not support these options, they are ignored.

gzip (default):
-Xcompression-level COMPRESSION-LEVEL
COMPRESSION-LEVEL should be 1 .. 9 (default 9).
-Xwindow-size WINDOW-SIZE
WINDOW-SIZE should be 8 .. 15 (default 15).
-Xstrategy strategy1,strategy2,...,strategyN
Compress using strategy1,strategy2,...,strategyN in turn and choose the best compression. Available strategies: default, filtered, huffman_only, run_length_encoded and fixed.
lzo:
-Xalgorithm ALGORITHM
Where ALGORITHM is one of: lzo1x_1, lzo1x_1_11, lzo1x_1_12, lzo1x_1_15, lzo1x_999 (default).
-Xcompression-level COMPRESSION-LEVEL
COMPRESSION-LEVEL should be 1 .. 9 (default 8). Only applies to lzo1x_999 algorithm.
lz4:
-Xhc
Compress using LZ4 High Compression.
xz:
-Xbcj filter1,filter2,...,filterN
Compress using filter1,filter2,...,filterN in turn (in addition to no filter), and choose the best compression. Available filters: x86, arm, armthumb, arm64, powerpc, sparc, ia64, riscv.
-Xdict-size DICT-SIZE
Use DICT-SIZE as the XZ dictionary size. The dictionary size can be specified as a percentage of the block size, or as an absolute value. The dictionary size must be less than or equal to the block size and 8192 bytes or larger. It must also be storable in the xz header as either 2^n or as 2^n+2^(n+1). Example dict-sizes are 75%, 50%, 37.5%, 25%, or 32K, 16K, 8K etc.
zstd:
-Xcompression-level COMPRESSION-LEVEL
COMPRESSION-LEVEL should be -131072 .. -1 or 1 .. 22 (default 15). Negative compression levels correspond to the zstd --fast option.
lzma:
(no options) (deprecated - no kernel support)

ENVIRONMENT

SQFS_CMDLINE
If set, this is used as the directory to write the file sqfs_cmdline which contains the command line arguments given to Mksquashfs. Each command line argument is wrapped in quotes to ensure there is no ambiguity when arguments contain spaces. If the file already exists then the command line is appended to the file.
SOURCE_DATE_EPOCH
If set, this is used as the filesystem creation timestamp. Also any file timestamps which are after SOURCE_DATE_EPOCH will be clamped to SOURCE_DATE_EPOCH. See https://reproducible-builds.org/docs/source-date-epoch/ for more information.
PAGER
If set, this is used as the name of the program used to display the help text. The value can be a simple command or a pathname. The default is /usr/bin/pager.

EXAMPLES

mksquashfs DIRECTORY IMAGE.SQFS
Create a Squashfs filesystem from the contents of DIRECTORY, writing the output to IMAGE.SQFS. Mksquashfs will use the default compressor (normally gzip), and a block size of 128 Kbytes.
mksquashfs DIRECTORY FILE1 FILE2 IMAGE.SQFS
Create a Squashfs filesystem containing DIRECTORY and FILE1 and FILE2. If multiple sources are specified on the command line they will be combined into a single directory.
mksquashfs DIRECTORY IMAGE.SQFS -b 1M -comp zstd
Use a block size of 1 Mbyte and Zstandard compression to create the filesystem.
mksquashfs DIRECTORY IMAGE.SQFS -all-time now
Set all file and directory timestamps to "now" (current time) in the filesystem.
mksquashfs DIRECTORY IMAGE.SQFS -force-uid phillip -force-gid phillip
Make all files and directories in the filesystem owned by "phillip".
mksquashfs DIRECTORY IMAGE.SQFS -force-file-mode ugo+r,go-w
Make all files readable by everyone, but only writable by user, all other permission bits are unaffected.
mksquashfs DIRECTORY IMAGE.SQFS -e file1 file2
Exclude file1 and file2 from DIRECTORY when creating filesystem. No wildcard matching of files.
mksquashfs DIRECTORY IMAGE.SQFS -wildcards -e "*.gz"
Exclude anything in DIRECTORY which matches the wildcard pattern "*.gz".
mksquashfs DIRECTORY IMAGE.SQFS -wildcards -e "... *.gz"
Exclude files which match the wildcard pattern "*.gz" anywhere within DIRECTORY and its sub-directories. The initial "..." indicates the wildcard pattern is "non-anchored" and will match anywhere.

Note: when passing wildcarded names to Mksquashfs, they should be quoted (as in the above examples), to ensure that they are not processed by the shell.

Using pseudo file definitions

mksquashfs DIRECTORY IMAGE.SQFS -p "build_dir d 0644 0 0"
Create a directory called "build_dir" in the output filesystem.
mksquashfs DIRECTORY IMAGE.SQFS -p "version.txt l /tmp/build/version"
Create a reference called "version.txt" to a file outside DIRECTORY, which acts as if the file "/tmp/build/version" was copied or hard-linked into DIRECTORY before calling Mksquashfs.
mksquashfs DIRECTORY IMAGE.SQFS -p "date.txt f 0644 0 0 date"
Create a file called "date.txt" which holds the output (stdout) from running the "date" command.
mksquashfs DIRECTORY IMAGE.SQFS -p "\"hello world\" f 0644 0 0 date"
As above, but, showing that filenames can have spaces, if they are quoted. The quotes need to be blackslashed to protect them from the shell.
mksquashfs - IMAGE.SQFS -p "input f 0644 root root dd if=/dev/sda1 bs=1024" -p "/ d 0644 0 0"
Create a file containing the contents of partition /dev/sda1". Ordinarily Mksquashfs given a device, fifo, or named socket will place that special file within the Squashfs filesystem, the above allows input from these special files to be captured and placed in the Squashfs filesystem. Note there are no other sources than the pseudo file, and so the command line source is "-". If there are no other sources than pseudo files, the root (/) directory must be defined too, as seen in this example.
unsquashfs -pf - IMAGE.SQFS | mksquashfs - NEW.SQFS -pf -
Transcode IMAGE.SQFS to NEW.SQFS by piping the pseudo file output from Unsquashfs to Mksquashfs using stdout and stdin. This can convert from earlier Squashfs filesystems or change compression algorithm, block size etc. without needing to unpack into an intermediate directory or file.

Note: pseudo file definitions should be quoted (as in the above examples), to ensure that they are passed to Mksquashfs as a single argument, and to ensure that they are not processed by the shell.

Using extended attribute options

mksquashfs DIRECTORY IMAGE.SQFS -no-xattrs
Do not store any extended attributes in the Squashfs filesystem. Any extended attributes in the source files will be ignored.
mksquashfs DIRECTORY IMAGE.SQFS -xattrs-include "^user.*"
Filter the extended attributes in the source files, and only store extended attributes in the user namespace in the Squashfs filesystem.
mksquashfs DIRECTORY IMAGE.SQFS -xattrs-exclude "^user.*"
Filter the extended attributes in the source files, and don't store any extended attributes in the user namespace in the Squashfs filesystem.
mksquashfs DIRECTORY IMAGE.SQFS -xattrs-add "user.comment=hello world"
Add the extended attribute called "user.comment" with the content "hello world" to all files and directories in the Squashfs filesystem.
mksquashfs DIRECTORY IMAGE.SQFS -xattrs-add "user.comment=0thello world\012"
Add the extended attribute called "user.comment" to all files and directories, but in this case the contents of the extended attribute will be "hello world" with a trailing newline character (012 octal).

EXAMPLES

mksquashfs DIRECTORY IMAGE.SQFS -xattrs-add "user.comment=0saGVsbG8gd29ybGQ="
Añade el atributo extendido llamado "user.comment" a todos los archivos y directorios, donde el valor se proporciona en codificación base64, representando "hello world".
mksquashfs DIRECTORY IMAGE.SQFS -action "-xattrs-include(^user.) @ type(f)"
Filtra los atributos extendidos pero solo en archivos regulares (tipo f), y solo almacena atributos extendidos en el espacio de nombres del usuario.
mksquashfs DIRECTORY IMAGE.SQFS -p "hello_world x user.comment=0tsalve mundi\012"
Añade el atributo extendido llamado "user.comment" al archivo llamado "hello_world", con el contenido del atributo extendido siendo "salve mundi" con un carácter de nueva línea al final (012 octal).

Usar Acciones para no comprimir, cambiar atributos, etc.

mksquashfs DIRECTORY IMAGE.SQFS -action "uncompressed @ (name(*.jpg) || name(*.mpg) ) || (name(*.img) && filesize(>=1G))"
Especifica que cualquier archivo que coincida con los comodines "*.jpg" y "*.mpg" no debe comprimirse. Además, también especifica que cualquier archivo que coincida con el comodín "*.img" y tenga 1 Gigabyte o más tampoco debe comprimirse. Esto demuestra que los operadores de prueba pueden combinarse con expresiones lógicas.
mksquashfs DIRECTORY IMAGE.SQFS -action "chmod(o+r)@! perm(o+r)"
Si algún archivo dentro de DIRECTORY no es legible por "otros", entonces hazlos legibles por otros en el sistema de archivos Squashfs.
mksquashfs DIRECTORY IMAGE.SQFS -action "uid(phillip)@! perm(o+r)"
Al igual que el anterior, coincide con cualquier archivo que no sea legible por "otros", pero, en este caso, cambia el propietario del archivo a "phillip" en el sistema de archivos Squashfs.
mksquashfs DIRECTORY IMAGE.SQFS -action "prune @ type(l) && ! exists"
Elimina cualquier enlace simbólico dentro de DIRECTORY que apunte fuera de DIRECTORY, es decir, que no se podrá resolver en el sistema de archivos Squashfs.
mksquashfs DIRECTORY IMAGE.SQFS -action "exclude @ depth(3)"
Crea un sistema de archivos Squashfs que contiene los dos niveles superiores (contenido de DIRECTORY y sus subdirectorios inmediatos), y excluye cualquier cosa en el nivel 3 o inferior.
mksquashfs DIRECTORY IMAGE.SQFS -action "-xattrs-include(^user.) @ type(f)"
Filtra los atributos extendidos pero solo en archivos regulares (tipo f), y solo almacena atributos extendidos en el espacio de nombres del usuario.

Nota: Las acciones deben ir entre comillas (como en los ejemplos anteriores), para asegurar que se pasen a Mksquashfs como un solo argumento, y para asegurar que no sean procesadas por el shell.
