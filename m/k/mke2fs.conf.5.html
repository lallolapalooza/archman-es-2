mke2fs.conf(5) Manual de formatos de archivo mke2fs.conf(5)

NOMBRE

mke2fs.conf - Archivo de configuración para mke2fs

DESCRIPCIÓN

mke2fs.conf es el archivo de configuración para mke2fs(8). Controla los parámetros predeterminados utilizados por mke2fs(8) cuando está creando sistemas de archivos ext2, ext3 o ext4.

El archivo mke2fs.conf utiliza un formato estilo INI. Las secciones, o secciones de nivel superior, están delimitadas por corchetes: [ ]. Dentro de cada sección, cada línea define una relación, que asigna etiquetas a valores, o a una subsección, que contiene más relaciones o subsecciones. A continuación se muestra un ejemplo del formato estilo INI utilizado por este archivo de configuración:

[seccion1]
etiqueta1 = valor_a
etiqueta1 = valor_b
etiqueta2 = valor_c

[seccion 2]
etiqueta3 = {
subetiqueta1 = valor_subetiqueta_a
subetiqueta1 = valor_subetiqueta_b
subetiqueta2 = valor_subetiqueta_c
}
etiqueta1 = valor_d
etiqueta2 = valor_e
}

Los comentarios están delimitados por un punto y coma (';') o un carácter de almohadilla ('#') al principio del comentario, y terminan con el carácter de fin de línea.

Las etiquetas y los valores deben ir entre comillas dobles si contienen espacios. Dentro de una cadena entre comillas, se aplican las interpretaciones estándar de la barra invertida: "\n" (para el carácter de nueva línea), "\t" (para el carácter de tabulación), "\b" (para el carácter de retroceso), y "\\" (para el carácter de barra invertida).

Algunas relaciones esperan un valor booleano. El analizador es bastante liberal al reconocer ``yes'', '`y'', ``true'', ``t'', ``1'', ``on'', etc. como un valor booleano verdadero, y ``no'', ``n'', ``false'', ``nil'', ``0'', ``off'' como un valor booleano falso.

Las siguientes secciones se utilizan en el archivo mke2fs.conf. Se describirán con más detalle en secciones futuras de este documento.

[opciones]
Contiene relaciones que influyen en cómo se comporta mke2fs.
[predeterminados]
Contiene relaciones que definen los parámetros predeterminados utilizados por mke2fs(8). En general, estos predeterminados pueden ser anulados por una definición en la sección tipos_fs, o por una opción de línea de comandos proporcionada por el usuario.
[tipos_fs]
Contiene relaciones que definen los predeterminados que deben utilizarse para tipos específicos de sistema de archivos y uso. El tipo de sistema de archivos y el tipo de uso se pueden especificar explícitamente utilizando las opciones -t y -T para mke2fs(8), respectivamente.
[dispositivos]
Contiene relaciones que definen los predeterminados para dispositivos específicos.

LA SECCIÓN [opciones]

Las siguientes relaciones se definen en la sección [opciones].

proceed_delay
Si esta relación se establece en un entero positivo, entonces mke2fs esperará proceed_delay segundos después de solicitar al usuario permiso para continuar y luego continuará, incluso si el usuario no ha respondido la pregunta. El valor predeterminado es 0, lo que significa esperar hasta que el usuario responda la pregunta de una forma u otra.
sync_kludge
Si esta relación se establece en un entero positivo, entonces mientras escribe la tabla de inodos, mke2fs solicitará al sistema operativo que vacíe las escrituras pendientes para inicializar la tabla de inodos cada sync_kludge grupos de bloques. Esto es necesario para solucionar errores en kernels que no manejan correctamente la limitación de escritura.

LA SECCIÓN [predeterminados]

Las siguientes relaciones se definen en la sección [predeterminados].

creator_os
Esta relación especifica el "sistema operativo creador" para el sistema de archivos a menos que se anule en la línea de comandos. El valor predeterminado es el SO para el cual se compiló el ejecutable mke2fs.
fs_type
Esta relación especifica el tipo de sistema de archivos predeterminado si el usuario no lo especifica a través de la opción -t, o si mke2fs no se inicia utilizando un nombre de programa de la forma mkfs.tipo-fs. Si tanto el usuario como el archivo mke2fs.conf no especifican un tipo de sistema de archivos predeterminado, mke2fs utilizará un tipo de sistema de archivos predeterminado de ext3 si se solicitó un journal a través de una opción de línea de comandos, o ext2 si no.
undo_dir
Esta relación especifica el directorio donde se debe almacenar el archivo de deshacer. Puede ser anulado a través de la variable de entorno E2FSPROGS_UNDO_DIR. Si la ubicación del directorio se establece en el valor none, mke2fs no creará un archivo de deshacer.

Además, cualquier etiqueta que se pueda especificar en una subsección de etiquetas por sistema de archivos, como se define a continuación (por ejemplo, blocksize, hash_alg, inode_ratio, inode_size, reserved_ratio, etc.), también se puede especificar en la sección predeterminados para especificar el valor predeterminado que se utilizará si el usuario no especifica uno en la línea de comandos, y la sección específica del tipo de sistema de archivos del archivo de configuración no especifica un valor predeterminado.

LA SECCIÓN [tipos_fs]

Cada etiqueta en la sección [tipos_fs] nombra un tipo de sistema de archivos o un tipo de uso que se puede especificar a través de las opciones -t o -T para mke2fs(8), respectivamente.

El programa mke2fs construye una lista de tipos_fs concatenando el tipo de sistema de archivos (es decir, ext2, ext3, etc.) con la lista de tipos de uso. Para la mayoría de las opciones de configuración, mke2fs buscará una subsección en la sección [tipos_fs] que corresponda con cada entrada de la lista construida, y las entradas posteriores anularán los tipos de sistema de archivos o de uso anteriores. Por ejemplo, considere el siguiente fragmento de mke2fs.conf:

[predeterminados]
base_features = sparse_super,filetype,resize_inode,dir_index
blocksize = 4096
inode_size = 256
inode_ratio = 16384

[tipos_fs]
ext3 = {
features = has_journal
}
ext4 = {
features = extents,flex_bg
inode_size = 256
}
small = {
blocksize = 1024
inode_ratio = 4096
}
floppy = {
features = ^resize_inode
blocksize = 1024
inode_size = 128
}

Si mke2fs se inicia con el nombre de programa mke2fs.ext4, entonces se utilizará el tipo de sistema de archivos ext4. Si el sistema de archivos es menor de 3 megabytes y no se especifica un tipo de uso, entonces mke2fs utilizará un tipo de uso predeterminado de floppy. Esto da como resultado una lista de tipos_fs de "ext4, floppy". Tanto la subsección ext4 como la subsección floppy definen una relación inode_size, pero dado que las entradas posteriores en la lista de tipos_fs anulan las anteriores, se utilizará el parámetro de configuración para fs_types.floppy.inode_size, por lo que el sistema de archivos tendrá un tamaño de inodo de 128.

La excepción a esta resolución es la etiqueta features, que especifica un conjunto de cambios en las características utilizadas por el sistema de archivos, y que es acumulativa. Así, en el ejemplo anterior, primero la relación de configuración defaults.base_features habilitaría un conjunto de características iniciales con las características sparse_super, filetype, resize_inode y dir_index habilitadas. Luego, la relación de configuración fs_types.ext4.features habilitaría las características extents y flex_bg, y finalmente la relación de configuración fs_types.floppy.features eliminaría la característica resize_inode, lo que resultaría en un conjunto de características del sistema de archivos que consiste en las características sparse_super, filetype, dir_index, extents y flex_bg.

Para cada tipo de sistema de archivos, las siguientes etiquetas se pueden usar en la subsección de ese tipo de fs. Estas etiquetas también se pueden usar en la sección predeterminados:

base_features
Esta relación especifica las características que se habilitan inicialmente para este tipo de sistema de archivos. Solo se utilizará una base_features, por lo que si hay múltiples entradas en la lista de tipos_fs cuyas subsecciones definen la base_features

i> relación, solo la última será utilizada por mke2fs(8).
enable_periodic_fsck
Esta relación booleana especifica si las comprobaciones periódicas del sistema de archivos deben forzarse al arrancar. Si se establece en verdadero, las comprobaciones se forzarán cada 180 días, o después de un número aleatorio de montajes. Estos valores pueden cambiarse posteriormente mediante las opciones de línea de comandos -i y -c de tune2fs(8).
errors
Cambia el comportamiento del código del kernel cuando se detectan errores. En todos los casos, un error del sistema de archivos provocará que e2fsck(8) compruebe el sistema de archivos en el próximo arranque. errors puede ser una de las siguientes opciones:
continue
Continuar la ejecución normal.
remount-ro
Remontar el sistema de archivos como solo lectura.
panic
Provocar un pánico del kernel.
features
Esta relación especifica una lista separada por comas de solicitudes de edición de características que modifican el conjunto de características utilizadas por el sistema de archivos recién construido. La sintaxis es la misma que la opción de línea de comandos -O de mke2fs(8); es decir, una característica puede ir precedida por un símbolo de intercalación ('^') para deshabilitar una característica con nombre. Cada relación features especificada en la lista fs_types se aplicará en el orden en que se encuentre en la lista fs_types.
force_undo
Esta relación booleana, si se establece en verdadero, obliga a mke2fs a intentar siempre crear un archivo de deshacer, incluso si el archivo de deshacer puede ser enorme y puede extender el tiempo de creación de la imagen del sistema de archivos porque la tabla de inodos no se está inicializando de forma perezosa.
default_features
Esta relación especifica el conjunto de características que deben habilitarse o deshabilitarse después de aplicar las características enumeradas en las relaciones base_features y features. Puede ser anulada por la opción de línea de comandos -O de mke2fs(8).
auto_64-bit_support
Esta relación es booleana y especifica si mke2fs(8) debe agregar automáticamente la característica 64bit si el número de bloques para el sistema de archivos requiere que esta característica esté habilitada. La característica resize_inode también se deshabilita automáticamente ya que no admite números de bloque de 64 bits.
default_mntopts
Esta relación especifica el conjunto de opciones de montaje que deben habilitarse por defecto. Estas pueden cambiarse posteriormente con la opción de línea de comandos -o de tune2fs(8).
blocksize
Esta relación especifica el tamaño de bloque predeterminado si el usuario no especifica un tamaño de bloque en la línea de comandos.
lazy_itable_init
Esta relación booleana especifica si la tabla de inodos debe inicializarse de forma perezosa. Solo tiene significado si la característica uninit_bg está habilitada. Si lazy_itable_init es verdadero y la característica uninit_bg está habilitada, la tabla de inodos no será inicializada completamente por mke2fs(8). Esto acelera notablemente la inicialización del sistema de archivos, pero requiere que el kernel termine de inicializar el sistema de archivos en segundo plano cuando el sistema de archivos se monta por primera vez.
lazy_journal_init
Esta relación booleana especifica si el inodo del journal debe inicializarse de forma perezosa. Solo tiene significado si la característica has_journal está habilitada. Si lazy_journal_init es verdadero, el inodo del journal no será completamente puesto a cero por mke2fs. Esto acelera notablemente la inicialización del sistema de archivos, pero conlleva un pequeño riesgo si el sistema falla antes de que el journal se haya sobrescrito completamente una vez.
journal_location
Esta relación especifica la ubicación del journal.
num_backup_sb
Esta relación indica si los sistemas de archivos con la característica sparse_super2 habilitada deben crearse con 0, 1 o 2 superbloques de respaldo.
packed_meta_blocks
Esta relación booleana especifica si los mapas de bits de asignación, la tabla de inodos y el journal deben ubicarse al principio del sistema de archivos.
inode_ratio
Esta relación especifica la relación de inodos predeterminada si el usuario no especifica una en la línea de comandos.
inode_size
Esta relación especifica el tamaño de inodo predeterminado si el usuario no especifica uno en la línea de comandos.
reserved_ratio
Esta relación especifica el porcentaje predeterminado de bloques del sistema de archivos reservados para el superusuario, si el usuario no especifica uno en la línea de comandos.
hash_alg
Esta relación especifica el algoritmo hash predeterminado utilizado para los nuevos sistemas de archivos con directorios b-tree con hash. Los algoritmos válidos aceptados son: legacy, half_md4 y tea.
flex_bg_size
Esta relación especifica el número de grupos de bloques que se empaquetarán juntos para crear un gran grupo de bloques virtual en un sistema de archivos ext4. Esto mejora la localidad de los metadatos y el rendimiento en cargas de trabajo intensivas en metadatos. El número de grupos debe ser una potencia de 2 y solo puede especificarse si la característica de sistema de archivos flex_bg está habilitada.
options
Esta relación especifica opciones extendidas adicionales que deben ser tratadas por mke2fs(8) como si estuvieran antepuestas al argumento de la opción -E. Esto se puede usar para configurar las opciones extendidas predeterminadas utilizadas por mke2fs(8) por tipo de sistema de archivos.
discard
Esta relación booleana especifica si mke2fs(8) debe intentar descartar el dispositivo antes de la creación del sistema de archivos.
set_raid_stride
Esta relación especifica si el tamaño del paso RAID del sistema de archivos se establece desde el dispositivo de bloques si está disponible. Los valores válidos son: always, disk, never. El valor predeterminado es always.
set_raid_stripe
Esta relación especifica si el tamaño de la franja RAID del sistema de archivos se establece desde el dispositivo de bloques si está disponible. Los valores válidos son: always, disk, never. El valor predeterminado es disk.
cluster_size
Esta relación especifica el tamaño de clúster predeterminado si la característica de sistema de archivos bigalloc está habilitada. Puede ser anulada mediante la opción de línea de comandos -C de mke2fs(8)
make_hugefiles
Esta relación booleana habilita la creación de archivos preasignados como parte del formateo del sistema de archivos. Los bloques de árbol de extensión para estos archivos preasignados se colocarán cerca del principio del sistema de archivos, de modo que si todos los demás bloques de metadatos también están configurados para colocarse cerca del principio del sistema de archivos (al deshabilitar los superbloques de respaldo, usar la opción packed_meta_blocks, etc.), los bloques de datos de los archivos preasignados serán contiguos.
hugefiles_dir
Esta relación especifica el directorio donde se crean los archivos enormes, relativo a la raíz del sistema de archivos.
hugefiles_uid
Esta relación controla la propiedad del usuario para todos los archivos y directorios creados por la característica make_hugefiles.
hugefiles_gid
Esta relación controla la propiedad del grupo para todos los archivos y directorios creados por la característica make_hugefiles.
hugefiles_umask
Esta relación especifica la máscara umask utilizada al crear los archivos y directorios por la característica make_hugefiles.
num_hugefiles
Esta relación especifica el número de archivos enormes a crear. Si esta relación no se especifica, o se establece en cero, y la relación hugefiles_size no es cero, entonces make_hugefiles creará tantos archivos enormes como quepan para llenar todo el sistema de archivos.
hugefiles_slack
Esta relación especifica cuánto espacio se debe reservar para otros archivos.
hugefiles_size
Esta relación especifica el tamaño de los archivos enormes. Si esta relación no se especifica, el valor predeterminado es llenar todo el sistema de archivos.
hugefiles_align
Esta relación especifica la alineación para el bloque de inicio de los archivos enormes. También fuerza que el tamaño de los archivos enormes sea un múltiplo de la alineación solicitada. Si esta relación no se especifica, no se impondrá ningún requisito de alineación a los archivos enormes.
hugefiles_align_disk
Esta relación especifica si la alineación debe ser relativa al principio del disco duro (asumiendo que el desplazamiento de inicio de la partición está disponible para mke2fs). El valor predeterminado es falso, lo que provocará que la alineación de los archivos enormes sea relativa al principio del sistema de archivos.
hugefiles_name
Esta relación especifica

EL ESTÁNDAR [defaults]

Cada etiqueta en el elemento [defaults] establece un valor predeterminado para las opciones de línea de comandos de mke2fs(8).

align_inodes
Este booleano especifica si los inodos se alinearán con el inicio de los grupos de bloques. Esto puede mejorar el rendimiento en algunos casos, especialmente en discos duros. El valor predeterminado es true.
align_resize_inodes
Esta relación booleana especifica si el extremo de los datos de los metadatos se alineará con el inicio de los grupos de inodos, y si el tamaño de los datos de los metadatos se establecerá para que se alinee con los grupos de inodos. Esto es útil para permitir que el tamaño del sistema de archivos se amplíe sin tener que mover los metadatos del sistema de archivos. El valor predeterminado es true.
default_encoding
Esta relación especifica la codificación de nombres de archivo predeterminada a utilizar si no se especifica en la línea de comandos. Consulte la sección de la relación encoding para obtener más detalles.
default_fragment_size
Esta relación especifica el tamaño del fragmento predeterminado. El tamaño del fragmento es el tamaño más pequeño de un bloque que puede ser asignado a un archivo. El valor predeterminado es 1024.
default_inode_size
Esta relación especifica el tamaño del inodo predeterminado. El tamaño del inodo es el tamaño de la estructura de datos que almacena información sobre un archivo. El valor predeterminado es 256.
default_journal_size
Esta relación especifica el tamaño predeterminado de la sección de registro (journal). Un tamaño de registro más grande puede mejorar el rendimiento en sistemas con muchas escrituras, pero también consume más espacio en disco. El valor predeterminado es 0, lo que significa que no se creará una sección de registro separada.
default_journal_type
Esta relación especifica el tipo predeterminado de sección de registro. Los valores posibles son ext2, data o unordered. El valor predeterminado es ext3.
default_reserved_blocks
Esta relación especifica el porcentaje de bloques que se reservarán para el superusuario. El valor predeterminado es 5.
default_revision
Esta relación especifica la versión predeterminada del sistema de archivos ext2/ext3/ext4. El valor predeterminado es 1.
default_stride
Esta relación especifica el número de bloques en un "stride" para un sistema de archivos RAID. El valor predeterminado es 0.
default_stripe_width
Esta relación especifica el ancho del "stripe" para un sistema de archivos RAID. El valor predeterminado es 0.
force_resize
Este booleano especifica si se debe forzar la expansión del sistema de archivos al tamaño máximo posible. El valor predeterminado es false.
hugefiles
Este booleano especifica si se deben crear archivos grandes (hugefiles) para el sistema de archivos. Los archivos grandes se utilizan para almacenar datos de manera más eficiente en sistemas con grandes cantidades de almacenamiento. El valor predeterminado es false.
hugefiles_digits
Esta relación especifica el ancho (relleno de ceros) del campo para el número de archivo grande.
warn_y2038_dates
Este booleano especifica si mke2fs emitirá una advertencia al crear un sistema de archivos con inodos de 128 bytes (y por lo tanto, no admitirá fechas posteriores al 19 de enero de 2038). El valor predeterminado es true, excepto para los sistemas de archivos creados para GNU Hurd, ya que solo admite inodos de 128 bytes.
zero_hugefiles
Este booleano especifica si se escribirán bloques de cero en los archivos grandes mientras mke2fs(8) los está creando. Por defecto, se escribirán bloques de cero en los archivos grandes para evitar que datos obsoletos estén disponibles para programas de usuario potencialmente no confiables, a menos que el dispositivo admita una operación de descarte/recorte (discard/trim) que se encargará de poner a cero los bloques del dispositivo. Al establecer zero_hugefiles en false, este paso siempre se omitirá, lo que puede ser útil si se sabe que el disco ha sido borrado previamente, o si se confía en que los programas de usuario que tendrán acceso a los archivos grandes no revelarán datos obsoletos.
encoding
Esta relación define la codificación de nombres de archivo que se utilizará si la característica de plegado de mayúsculas/minúsculas (casefold) está habilitada. Actualmente, la única codificación válida es utf8-12.1 o utf8, que solicita la versión más reciente de Unicode; dado que 12.1 es la única versión de Unicode disponible, utf8 y utf8-12.1 tienen el mismo resultado. encoding_flags Esta relación define indicadores específicos de codificación. Para las codificaciones utf8, el único indicador disponible es strict, que provocará que el kernel rechace los intentos de crear nombres de archivo que contengan caracteres Unicode no válidos. El modo estricto no está habilitado por defecto.

EL ESTÁNDAR [devices]

Cada etiqueta en el elemento [devices] nombra un nombre de dispositivo para que se puedan especificar valores predeterminados por dispositivo.

fs_type
Esta relación especifica el parámetro predeterminado para la opción -t, si esta opción no se especifica en la línea de comandos.
usage_types
Esta relación especifica el parámetro predeterminado para la opción -T, si esta opción no se especifica en la línea de comandos.
