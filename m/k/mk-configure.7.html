NOMBRE

mk-configure - reemplazo ligero para GNU autotools

DESCRIPCIÓN

mk-configure es una colección de archivos de inclusión para bmake (versión portable de NetBSD make) y un número de ejecutables. Está destinado a simplificar el desarrollo multiplataforma y la compilación de software.

Solo hay unos pocos makefiles de alto nivel: mkc.init.mk, mkc.mk, mkc.configure.mk, mkc.minitest.mk. Todo lo demás (archivos mkc_imp.*.mk) se incluye implícitamente. ¡No use los archivos mkc_imp.*.mk directamente! Si lo hace, no puedo garantizar la compatibilidad hacia atrás. mkc.configure.mk se incluye automáticamente por mkc.mk, pero se puede incluir explícitamente. mkc.minitest.mk proporciona un soporte trivial para pruebas de regresión y debe incluirse explícitamente. Normalmente, los makefiles mk-c consisten en asignaciones de variables e inclusión de mkc.mk en el encabezado y pie. También se puede usar mkc.prog.mk, mkc.lib.mk, mkc.files.mk, mkc.subdir.mk y mkc.subprj.mk en lugar de mkc.mk. Este último activa mkc.lib.mk si la variable LIB está establecida, mkc.prog.mk si las variables PROG o PROGS están establecidas, mkc.subprj.mk si la variable SUBPRJ está establecida, mkc.subdir.mk si la variable SUBDIR está establecida, y mkc.files.mk en caso contrario.

Para obtener parámetros de configuración a nivel de sistema, mkc.init.mk carga el archivo "${MAKECONF}" si existe. De lo contrario, carga /etc/mkcmake.conf si existe. Si ni ${MAKECONF} ni /etc/mkcmake.conf existen, intenta cargar el archivo /etc/mk.conf. Si el archivo "${SRCTOP}/Makefile.common" existe, también se incluye por todos los subproyectos. A menos que la variable SRCTOP esté establecida, "../Makefile.inc" también se incluye si existe. Estos archivos pueden definir cualquiera de las variables descritas a continuación. Los valores por defecto específicos del compilador también se cargan desde "~/.mkcmake" o directorios del sistema. Estos valores por defecto específicos del compilador se determinan en el momento de la compilación o con la ayuda de la utilidad mkc_compiler_settings.

A continuación, entre corchetes, se especifican los valores por defecto para las variables. Entre corchetes angulares, se indica la forma típica de uso, donde I significa "Inicializado por mk-configure", Iu significa "Inicializado por mk-configure pero puede ser sobrescrito por el usuario", Im significa "Inicializado por mk-configure pero puede ser establecido en Makefile", U significa "Generalmente establecido por el usuario", M significa "Puede ser establecido o modificado en el Makefile del proyecto" y Mu significa "Puede ser establecido en el Makefile del proyecto pero puede ser inicializado o sobrescrito por el usuario".

La variable MKCMAKE es siempre 1 en mkcmake.

Objetivos

Mk-configure proporciona los siguientes objetivos:

all
compilar todo.
clean
limpiar archivos temporales y directorios con la ayuda de los comandos ${CLEANFILES_CMD} y ${CLEANDIRS_CMD}.
cleandir
eliminar todos los archivos eliminados por el objetivo clean, así como los archivos de caché creados por mkc.configure.mk.
installdirs
crear directorios de destino.
install
instalar programas, bibliotecas, archivos, archivos de inclusión, páginas de manual, etc. en los directorios de destino con la ayuda del programa ${INSTALL}.
uninstall
eliminar archivos instalados con la ayuda del comando ${UNINSTALL}.
configure
verificar la variable MKC_ERR_MSG y fallar si está establecida imprimiendo un mensaje de error
depend
crear el archivo .depend_${.CURDIR:T} que contiene la lista de dependencias (ver mkdep(1)).
filelist
mostrar una lista de archivos de destino del proyecto, uno por línea, por ejemplo: 
  /usr/local/bin/hello
  /usr/local/man/man1/hello.1
obj
si MKOBJDIR es "yes", crea directorios de objetos (${.OBJDIR}) según las variables MAKEOBJDIR y MAKEOBJPREFIX. El umask actual se usa para esto.
mkgen
Ver mkc_imp.foreign_autotools.mk.
bin_tar, bin_targz, bin_tarbz2, bin_zip, bin_deb
compilar software, instalarlo en un directorio temporal (usando DESTDIR) y crear un archivo .tar/.tar.gz/.tar.bz2/.zip/.deb que contenga todos los archivos instalados. El objetivo bin_deb espera archivos de control debian en el subdirectorio DEBIAN, ver examples/files para un ejemplo.

NOTA: Los comandos asociados con los objetivos all, install, clean, cleandir, depend, test, installdirs, uninstall, configure y filelist en Makefile anulan el comportamiento estándar.

NOTA: Todos los objetivos de esta lista tienen contrapartes pre_*, do_* y post_*. Ver ALLTARGETS para más detalles.

mkc.mk

Este archivo es incluido por mkc.init.mk automáticamente. Utiliza las variables definidas en mkc.init.mk.

El objetivo predeterminado es el objetivo `all`.

mkc.configure.mk

Este archivo es incluido por mkc.mk automáticamente. Se ejecuta antes de la compilación. Verifica la existencia de los programas necesarios y la disponibilidad de las características del sistema. Los resultados de estas comprobaciones se almacenan en variables, que luego se usan para ajustar las flags de compilación y enlazado.

Ejemplos

Un simple Makefile:

PROG = hello
SRCS = hello.c

include mkc.mk

Un Makefile para una biblioteca estática:

LIB = mylib
SRCS = foo.c bar.c

include mkc.lib.mk

Un Makefile para una biblioteca compartida:

LIB = mylib
SRCS = foo.c bar.c
PICFLAGS = -fPIC

include mkc.lib.mk

Un Makefile para un programa que usa una biblioteca:

PROG = myprog
SRCS = main.c
LIBDEPS = mylib

include mkc.mk

Un Makefile para un proyecto con subdirectorios:

SUBDIRS = lib src

include mkc.subdir.mk

Un Makefile para un proyecto con subproyectos:

SUBPRJ = proj1 proj2

include mkc.subprj.mk

Un Makefile para instalar archivos adicionales:

FILES = conf/app.conf

include mkc.files.mk

Un Makefile para ejecutar pruebas de regresión:

MKTEST = test1 test2

include mkc.minitest.mk

mkc.subprj.mk

El archivo de inclusión mkc.subprj.mk maneja subproyectos (subdirectorios) organizados como un grafo de dependencias. Proporciona todos los objetivos proporcionados por mkc.prog.mk. La variable SUBPRJ contiene una lista de pares depdir:dir que significa que el subproyecto dir depende de depdir. El comando mkcmake all construirá todos los subproyectos listados en SUBPRJ en el orden correcto (comenzando con los subproyectos sin dependencias y así sucesivamente). También hay un objetivo que permite ejecutar el comando bmake <subdir> donde <subdir> es cualquier directorio listado en la variable SUBPRJ. Los siguientes objetivos también se proporcionan: <target>-<subdir> donde <target> es cualquiera de los siguientes: all, clean, cleandir, depend, installdirs, install, uninstall y filelist. También se proporcionan: los objetivos nodeps-<target>-<subdir> y subdir-<target>-<subdir>. La diferencia entre <target>-<subdir> y nodeps-<target>-<subdir> es que mkcmake <target>-<subdir> ejecuta el <target> especificado para <subdir> y todas sus dependencias, mientras que mkcmake nodeps-<target>-<subdir> lo hace solo para <subdir>. Un objetivo subdir-<target>-<subdir> es un sinónimo de nodeps-<target>-<subdir>. Ver el subdirectorio examples/hello_dictd para un ejemplo de uso.

Ejecuta el <target> especificado para el <subdir> especificado sin dependencias. Los objetivos subdir-<target>-<subdir:T> y nodeps-<target>-<subdir:T> se proporcionan si ${SHORTPRJNAME} es "yes".
print_deps
Muestra el grafo de dependencias en los objetivos en formato tsort(1) teniendo en cuenta las variables NODEPS y NOSUBDIR.

mkc.subdir.mk

El archivo de inclusión mkc.subdir.mk contiene los objetivos predeterminados para compilar subdirectorios. Proporciona los mismos objetivos que mkc.prog.mk. Para todos los directorios listados en la variable SUBDIR, se visitará el directorio especificado y se hará el objetivo. También hay un objetivo predeterminado que permite el comando bmake <subdir> donde <subdir>
es cualquier directorio listado en la variable SUBDIR. Como caso especial, el uso de un token .WAIT como entrada en SUBDIR actúa como una barrera de sincronización cuando se ejecutan múltiples trabajos de make; los subdirectorios antes de .WAIT deben completarse antes de que se inicien los subdirectorios después de .WAIT. Consulte bmake(1) para ver algunas advertencias sobre el uso de .WAIT y otras fuentes especiales. La variable SUBDIR también se proporciona, así como todas las variables proporcionadas por mkc.subprj.mk excepto SUBPRJ.

mkc.configure.mk

mkc.configure.mk es un archivo de inclusión auxiliar para verificar las características de la plataforma como encabezados, declaraciones de funciones o variables, implementaciones de funciones en bibliotecas específicas, tamaños de tipos de datos, etc. Este archivo de inclusión es incluido por mkc.prog.mk y mkc.lib.mk automáticamente pero en algunos casos tiene sentido incluirlo explícitamente. mkc.configure.mk en sí mismo incluye mkc.init.mk, luego mkc.conf.mk y finalmente un archivo de inclusión interno que actualiza CPPFLAGS, CFLAGS, LDADD y SRCS. mkc.configure.mk soporta las siguientes variables.

MKCHECKS
Si es "no", no se realizan comprobaciones. Se establece en "yes" a menos que el objetivo sea "clean" y "cleandir".
MKC_CACHEDIR
Directorio donde se crean los archivos intermedios y de caché. Por defecto es ${.OBJDIR}. Por defecto, la variable MKC_CACHEDIR se exporta a los subproyectos. Como resultado, los archivos de caché para subproyectos se crean en el directorio de nivel superior. Si el directorio de caché no existe, se crea automáticamente.
MKC_CHECK_BUILTINS
mk-configure proporciona una serie de comprobaciones integradas personalizadas, es decir, archivos fuente para compilar o scripts para ejecutar para verificar algo. Se ejecutarán las comprobaciones listadas en MKC_CHECK_BUILTINS.
Valores disponibles:
prog_flex, prog_bison, prog_gawk, prog_gm4, prog_gmake
Busca flex, bison, GNU awk, GNU m4 o GNU make respectivamente analizando los mensajes de ayuda y/o versión del programa. Si se encuentra, BUILTIN.prog_<progname> se establece en la ruta, de lo contrario se establece en cadena vacía. Tenga en cuenta que gawk puede encontrarse como awk, bison como yacc, gm4 como m4, flex como lex y gmake como make.
prog_mkdep, prog_nbmkdep
Busca respectivamente el mkdep(1) tradicional de BSD o la versión reciente de NetBSD.
endianness
La variable BUILTIN.endianness se establece en little, big o unknown dependiendo del hardware.

MKC_FEATURES
Esta es una lista de "características" requeridas por el proyecto. En general, una característica es algo que tiene problemas de portabilidad. Podría ser un nombre de función o una cabecera que falte en algunas plataformas, por ejemplo. Lo que el desarrollador necesita hacer es añadir FEATURENAME a la variable MKC_FEATURES y añadir #include <mkc_FEATURENAME.h> donde sea necesario. Internamente, los requisitos del sistema se comprueban en el archivo mkc_imp.f_FEATURENAME.mk incluido automáticamente, y todas las acciones requeridas (inclusiones, comprobaciones de define, etc.) se realizan en el archivo de cabecera mkc_FEATURENAME.h. bswap

Esta característica proporciona dprintf(3).

Esta característica proporciona esetfunc(3), efopen(3), ecalloc(3), emalloc(3), erealloc(3), ereallocarr(3), estrdup(3), estrndup(3), estrlcpy(3), estrlcat(3), easprintf(3), estrtoi(3), estrtou(3) y evasprintf(3) funciones de NetBSD.

Esta característica proporciona las peculiaridades de BSD err(3), errx(3), verr(3) y verrx(3).
errc
Esta característica proporciona las peculiaridades de BSD errc(3) y verrc(3).
fgetln
Esta característica proporciona la peculiaridad de BSD fgetln(3).
fparseln
Esta característica proporciona la peculiaridad de BSD fparseln(3).

Esta característica proporciona las funciones fts_open(3), fts_read(3) etc. disponibles en BSDs y Linux. Si está ausente en tu sistema, tienes que instalar libfts (tanto cabeceras como biblioteca). libfts es parte del proyecto musl.

definido como __attribute__((always_inline)) si es compatible con el compilador,
