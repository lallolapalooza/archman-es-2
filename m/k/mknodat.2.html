mknod(2) Manual de llamadas al sistema mknod(2)

NOMBRE

mknod, mknodat - crear un archivo especial o ordinario

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/stat.h>
int mknod(const char *path, mode_t mode, dev_t dev);
#include <fcntl.h>           /* Definición de constantes AT_* */
#include <sys/stat.h>
int mknodat(int dirfd, const char *path, mode_t mode, dev_t dev);
Requisitos de Feature Test Macro para glibc (ver feature_test_macros(7)):

mknod():

    _XOPEN_SOURCE >= 500
        || /* Desde glibc 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */ _BSD_SOURCE || _SVID_SOURCE

DESCRIPCIÓN

La llamada al sistema mknod() crea un nodo en el sistema de archivos (archivo, archivo especial de dispositivo o tubería con nombre) llamado path, con los atributos especificados por mode y dev.

El argumento mode especifica tanto el modo del archivo a usar como el tipo de nodo a crear. Debe ser una combinación (usando OR a nivel de bits) de uno de los tipos de archivo listados a continuación y cero o más de los bits de modo de archivo listados en inode(7).

El modo del archivo es modificado por el umask del proceso de la forma habitual: en ausencia de una ACL predeterminada, los permisos del nodo creado son (mode & ~umask).

El tipo de archivo debe ser uno de S_IFREG, S_IFCHR, S_IFBLK, S_IFIFO o S_IFSOCK para especificar un archivo regular (que se creará vacío), un archivo especial de caracteres, un archivo especial de bloques, una FIFO (tubería con nombre) o un socket de dominio UNIX, respectivamente. (Tipo de archivo cero es equivalente al tipo S_IFREG.)

Si el tipo de archivo es S_IFCHR o S_IFBLK, entonces dev especifica los números mayor y menor del archivo especial de dispositivo recién creado (puede ser útil makedev(3) para construir el valor para dev); de lo contrario, se ignora.

Si path ya existe, o es un enlace simbólico, esta llamada falla con un error EEXIST.

El nodo recién creado será propiedad del ID de usuario efectivo del proceso. Si el directorio que contiene el nodo tiene establecido el bit set-group-ID, o si el sistema de archivos está montado con semántica de grupo BSD, el nuevo nodo heredará la propiedad de grupo de su directorio padre; de lo contrario, será propiedad del ID de grupo efectivo del proceso.

mknodat()

La llamada al sistema mknodat() opera exactamente de la misma manera que mknod(), excepto por las diferencias descritas aquí.

Si path es relativo, entonces se interpreta en relación con el directorio al que hace referencia el descriptor de archivo dirfd (en lugar de en relación con el directorio de trabajo actual del proceso llamador, como hace mknod() para un nombre de ruta relativo).

Si path es relativo y dirfd es el valor especial AT_FDCWD, entonces path se interpreta en relación con el directorio de trabajo actual del proceso llamador (como mknod()).

Si path es absoluto, entonces dirfd se ignora.

Ver openat(2) para una explicación de la necesidad de mknodat().

VALOR DEVUELTO

mknod() y mknodat() devuelven cero si tienen éxito. En caso de error, devuelven -1 y se establece errno para indicar el error.

ERRORES

EACCES
El directorio padre no permite permisos de escritura al proceso, o uno de los directorios en el prefijo de ruta de path no permitió permisos de búsqueda. (Ver también path_resolution(7)).
EBADF
(mknodat()) path es relativo pero dirfd no es AT_FDCWD ni un descriptor de archivo válido.
EDQUOT
La cuota del usuario de bloques de disco o inodos en el sistema de archivos se ha agotado.
EEXIST
path ya existe. Esto incluye el caso en que path es un enlace simbólico, colgante o no.
EFAULT
path apunta fuera de su espacio de direcciones accesible.
EINVAL
mode solicitó la creación de algo que no fuera un archivo regular, un archivo especial de dispositivo, una FIFO o un socket.
ELOOP
Se encontraron demasiados enlaces simbólicos al resolver path.
ENAMETOOLONG
path era demasiado largo.
ENOENT
Un componente del directorio en path no existe o es un enlace simbólico colgante.
ENOMEM
No había suficiente memoria del kernel disponible.
ENOSPC
El dispositivo que contiene path no tiene espacio para el nuevo nodo.
ENOTDIR
Un componente utilizado como directorio en path no es, de hecho, un directorio.
ENOTDIR
(mknodat()) path es relativo y dirfd es un descriptor de archivo que hace referencia a un archivo distinto de un directorio.
EPERM
mode solicitó la creación de algo que no fuera un archivo regular, una FIFO (tubería con nombre) o un socket de dominio UNIX, y el llamante no tiene privilegios (Linux: no tiene la capacidad CAP_MKNOD); también se devuelve si el sistema de archivos que contiene path no soporta el tipo de nodo solicitado.
EROFS
path se refiere a un archivo en un sistema de archivos de solo lectura.

VERSIÓNES

POSIX.1-2001 dice: "El único uso portable de mknod() es para crear un archivo especial FIFO. Si mode no es S_IFIFO o dev no es 0, el comportamiento de mknod() no está especificado." Sin embargo, hoy en día nunca se debe usar mknod() para este propósito; se debe usar mkfifo(3), una función definida especialmente para este propósito.

En Linux, mknod() no se puede utilizar para crear directorios. Se deben crear directorios con mkdir(2).

ESTÁNDARES

POSIX.1-2024.

HISTORIA

mknod()
SVr4, 4.4BSD, POSIX.1-2001 (pero ver VERSIONES).
mknodat()
Linux 2.6.16, glibc 2.4. POSIX.1-2008.

NOTAS

Existen muchas rarezas en el protocolo subyacente de NFS. Algunas de ellas afectan a mknod() y mknodat().

mknodat(2) - Linux manual pages

NAME

mknodat - crear un nodo en un directorio especificado

LIBRARY

Direct Access Control, Realtime, and Tradicional IPC - Sección 2

SYNOPSIS

#include <sys/stat.h>

int mknodat(int dirfd, const char *pathname, mode_t mode, dev_t dev);

DESCRIPTION

The mknodat() function is similar to a combination of open(2) with the O_CREAT flag and mknod(2), but with the added ability to create a node in a directory referred to by a file descriptor.

mknodat() crea un nuevo nodo de archivo en la ubicación especificada por pathname. El nuevo nodo de archivo es creado con el modo especificado por mode. Si alguna parte del pathname es un enlace simbólico, mknodat() se resuelve el enlace simbólico.

El argumento dirfd es un descriptor de archivo que hace referencia a un directorio. El pathname es interpretado con respecto al directorio referido por dirfd (por lo que pathname puede ser relativo o absoluto).

Si pathname es relativo, se resuelve con respecto al directorio de trabajo actual, a menos que dirfd sea un descriptor de archivo válido para un directorio. Si dirfd es AT_FDCWD, entonces pathname se resuelve con respecto al directorio de trabajo actual.

Si pathname es una ruta absoluta, entonces dirfd se ignora.

El argumento mode especifica los permisos del archivo y debe ser una combinación de los permisos de archivo (por ejemplo, S_IRWXU) y los bits de modo especiales (consulte inode(7)). Los permisos de archivo se modifican con la máscara umask(2) del proceso.

El argumento dev se utiliza para especificar los números mayor y menor del dispositivo si el modo especifica un archivo de dispositivo (un archivo regular, un enlace simbólico, un directorio, un FIFO o un socket no se crean con mknodat()).

El bit S_IFMT en mode debe ser uno de los siguientes:

S_IFREG
Archivo regular.
S_IFCHR
Archivo de caracteres.
S_IFBLK
Archivo de bloques.
S_IFIFO
Archivo FIFO (named pipe).
S_IFSOCK
Socket de dominio Unix.

Si mode no contiene ninguno de los bits S_IFMT, o si contiene un valor que no es uno de los enumerados anteriormente, o si mode tiene bits de tipo que no sean S_IFMT o bits de permiso, el comportamiento no está definido.

Si el nodo de archivo ya existe, mknodat() fallará y establecerá errno a EEXIST.

Si pathname es un directorio, mknodat() fallará y establecerá errno a EEXIST.

Si pathname es un enlace simbólico, mknodat() fallará y establecerá errno a EEXIST.

Las siguientes banderas se pueden orquestar con mode:

S_ISUID
Establecer el bit SUID.
S_ISGID
Establecer el bit SGID.
S_ISVTX
Establecer el sticky bit.

Para que se establezcan los bits SUID y SGID, el archivo debe ser un archivo regular o un directorio, y el proceso que llama debe tener los privilegios adecuados.

Para que se establezca el sticky bit, el archivo debe ser un directorio, y el proceso que llama debe tener los privilegios adecuados.

El acceso a pathname se verifica usando las reglas de acceso de open(2) con el modo O_PATH.

Si pathname fue creado con éxito, mknodat() devolverá un descriptor de archivo abierto al nodo de archivo recién creado. Si mknodat() falla, devolverá -1 y errno se establecerá para indicar el error.

RETURN VALUE

En caso de éxito, mknodat() devuelve un descriptor de archivo abierto al nodo recién creado. En caso de error, devuelve -1 y errno se establece para indicar el error.

ERRORS

EACCES
No se permite el acceso de búsqueda a un componente de prefijo de pathname, o el directorio referido por dirfd no permite la escritura.
EBADF
dirfd no es un descriptor de archivo válido.
EEXIST
pathname ya existe como un archivo regular, directorio, enlace simbólico, o se ha intentado crear un tipo de archivo diferente al permitido en el directorio.
EINVAL
dirfd no se refiere a un directorio, o el mode especificado no es válido.
ELOOP
Se encontró demasiados enlaces simbólicos en pathname.
ENAMETOOLONG
pathname es demasiado largo.
ENOENT
Un componente de directorio en pathname no existe o pathname es una ruta vacía.
ENOSPC
No hay espacio libre en el dispositivo.
ENOTDIR
Un componente de prefijo de pathname no es un directorio o dirfd no se refiere a un directorio.
EROFS
El sistema de archivos de solo lectura.
ETXTBSY
El archivo está siendo utilizado como un archivo de texto de programa en ejecución.

VERSIONS

La llamada al sistema mknodat() está disponible en Linux desde el kernel 3.1.1.

STANDARDS

mknodat() proviene de POSIX.1-2008.

HISTORY

POSIX.1-2001.

NOTES

La distinción entre mknod() y mknodat() es similar a la de open(2) y openat(2), y stat(2) y fstatat(2).

Los bits de tipo de archivo en mode son:

S_IFMT
Máscara para el tipo de archivo.
S_IFREG
Archivo regular.
S_IFDIR
Directorio.
S_IFCHR
Archivo de caracteres.
S_IFBLK
Archivo de bloques.
S_IFIFO
FIFO (named pipe).
S_IFLNK
Enlace simbólico (aunque mknodat() no puede crear enlaces simbólicos; esto se hace con symlink(2)).
S_IFSOCK
Socket de dominio Unix.

Los permisos de archivo son:

S_IRUSR
Permiso de lectura para el propietario.
S_IWUSR
Permiso de escritura para el propietario.
S_IXUSR
Permiso de ejecución para el propietario.
S_IRGRP
Permiso de lectura para el grupo.
S_IWGRP
Permiso de escritura para el grupo.
S_IXGRP
Permiso de ejecución para el grupo.
S_IROTH
Permiso de lectura para otros.
S_IWOTH
Permiso de escritura para otros.
S_IXOTH
Permiso de ejecución para otros.

Los bits de modo especiales son:

S_ISUID
Establecer el bit SUID.
S_ISGID
Establecer el bit SGID.
S_ISVTX
Establecer el sticky bit.

Por ejemplo, para crear un archivo de caracteres con permisos rw-rw-r-- para el propietario, grupo y otros, y con los bits SUID y SGID establecidos, usaría:

mode_t mode = S_IFCHR | S_IRUSR | S_IWUSR | S_IRGRP | S_IWGRP | S_IROTH | S_ISUID | S_ISGID;

El valor dev debe ser el número de dispositivo mayor y menor codificado como un valor de tipo dev_t. Por ejemplo, para crear un dispositivo de caracteres con el número mayor 5 y el número menor 1:

dev_t dev = makedev(5, 1);
