MKINITCPIO(8) Manual de mkinitcpio MKINITCPIO(8)

NOMBRE

mkinitcpio - Crear un entorno de disco RAM inicial

SINOPSIS

mkinitcpio [opciones]

DESCRIPCIÓN

Crea un entorno de disco RAM inicial para arrancar el kernel de Linux. El disco RAM inicial es, en esencia, un entorno muy pequeño (espacio de usuario temprano) que carga varios módulos del kernel y configura las cosas necesarias antes de ceder el control a init. Esto hace posible tener, por ejemplo, sistemas de archivos raíz cifrados y sistemas de archivos raíz en una matriz RAID por software. mkinitcpio permite una fácil extensión con hooks personalizados, tiene autodetección en tiempo de ejecución y muchas otras características.

OPCIONES

-A, --addhooks hooks

Añade los hooks adicionales a la imagen. Estos se procesarán en orden después de todos los demás hooks del archivo de configuración. Múltiples hooks deben estar separados por comas. Esta opción puede especificarse varias veces.

-c, --config config

Usa el archivo config para generar el disco RAM. Por defecto: /etc/mkinitcpio.conf. Si se especifica, los archivos drop-in en /etc/mkinitcpio.conf.d serán ignorados.

-d, --generatedir directorio

Establece directorio como la ubicación donde se construye el initramfs. Esto puede ser útil para generar un ramfs de apagado en /run/initramfs/.

-D, --hookdir directorio

Establece directorio como la ubicación donde se buscarán los hooks al generar la imagen.

-g, --generate nombrearchivo

Genera una imagen CPIO como nombrearchivo. Por defecto: no; esto significa que nada se escribirá en el sistema de archivos a menos que se especifique esta opción.

-H, --hookhelp nombrehook

Muestra ayuda para el hook nombrehook.

-h, --help

Muestra un breve resumen de los interruptores de línea de comandos disponibles.

-k, --kernel versionkernel

Usa versionkernel, en lugar del kernel en ejecución actual. Puede ser una ruta a una imagen de kernel (solo soportado para arquitecturas basadas en x86), una versión de kernel específica o la palabra clave especial none. En este último caso, no se añaden módulos del kernel a la imagen.

-L, --listhooks

Lista todos los hooks disponibles.

-M, --automods

Muestra los módulos encontrados mediante autodetección. mkinitcpio intentará determinar automáticamente qué módulos del kernel son necesarios para iniciar tu ordenador. Esta opción lista los módulos que se detectaron.

-n, --nocolor

Desactiva la salida en color.

--nopost

No ejecuta los hooks post.

-U, --uki nombrearchivo

Genera una imagen de kernel unificada como nombrearchivo. Si se construye una imagen CPIO con éxito, se usará para generar una imagen de kernel unificada para el arranque UEFI. Esto combina el initramfs, el kernel y la línea de comandos del kernel en un solo ejecutable. Esto es útil para la integridad de la cadena de arranque donde el archivo está firmado. Por defecto: no. Para una lista de opciones relevantes, consulta Opciones para la imagen de kernel unificada a continuación.

-P, --allpresets

Procesa todos los presets contenidos en /etc/mkinitcpio.d. Consulta la opción -p para más detalles sobre los presets.

-p, --preset preset

Construye la(s) imagen(es) initramfs según el preset especificado. Puede ser un archivo en /etc/mkinitcpio.d (sin la extensión .preset) o una ruta absoluta completa a un archivo. Esta opción puede especificarse varias veces para procesar múltiples presets.

-R, --remove

Elimina la(s) imagen(es) initramfs generada(s) por el(los) preset(s) especificado(s). Si se usa en combinación con -P|--allpresets, elimina las imágenes para todos los presets. Esta opción solo se puede usar con -p|--presets o -P|--allpresets.

-r, --moduleroot root

Especifica el directorio raíz donde encontrar los módulos, por defecto es /.

-S, --skiphooks hooks

Omite los hooks al generar la imagen. Múltiples hooks deben estar separados por comas. Esta opción puede especificarse varias veces.

-s, --save

Guarda el directorio de compilación para el disco RAM inicial. Por defecto: no; esto significa que el directorio no se conservará si no se especifica esta opción. Útil para fines de depuración.

-t, --builddir tmpdir

Usa tmpdir como directorio temporal de compilación en lugar de /tmp. tmpdir debe existir. La variable de entorno TMPDIR también se respeta para establecer esta ubicación, pero la opción de línea de comandos tendrá precedencia.

-V, --version

Muestra información de la versión.

-v, --verbose

Salida detallada. Muestra más información sobre lo que está sucediendo durante la creación del disco RAM.

-z, --compress compress

Anula el método de compresión con el programa compress.

OPCIONES PARA IMAGEN DE KERNEL UNIFICADA

--cmdline nombrearchivo

Usa la línea de comandos del kernel con la imagen de kernel unificada. Si no se especifica ninguna, intenta usar uno de los archivos /etc/kernel/cmdline, /usr/lib/kernel/cmdline o /proc/cmdline.

--no-cmdline

Omite la incrustación de una cadena de línea de comandos del kernel en la imagen de kernel unificada. Las opciones de línea de comandos del kernel deberán pasarse a través de la línea de comandos del kernel. Anula la opción --cmdline.

--splash nombrearchivo

Los ejecutables UEFI pueden mostrar un archivo de mapa de bits al arrancar.

--uefistub nombrearchivo

Imagen stub UEFI utilizada para la generación de imágenes de kernel unificadas. No tiene efecto si se está utilizando ukify. Por defecto: Intenta buscar un cargador stub de systemd-boot o gummiboot.

--ukiconfig nombrearchivo

Archivo de configuración para pasar a ukify. Si no se especifica ninguno, intenta usar uno de los archivos /etc/kernel/uki.conf o /usr/lib/kernel/uki.conf. Si ninguno de estos existe, ukify usará su configuración predeterminada interna.

--no-ukify

No usar ukify para construir UKIs aunque esté disponible. No se recomienda.

--kernelimage nombrearchivo

Incluye una imagen de kernel para la imagen de kernel unificada. Por defecto: uno de /lib/modules/${KERNELVERSION}/vmlinuz, /lib/modules/${KERNELVERSION}/vmlinux, /boot/vmlinuz-${KERNELVERSION}, /boot/vmlinux-${KERNELVERSION}, /boot/vmlinuz-linux, o /boot/vmlinux-linux.

--osrelease nombrearchivo

Incluye un archivo os-release para la imagen de kernel unificada. Por defecto: /etc/os-release o /usr/lib/os-release.

SOBRE LOS PRESETS

Un preset es una definición predefinida sobre cómo crear un disco RAM inicial. En lugar de especificar el archivo de configuración y qué archivo de salida, cada vez que generas un nuevo disco RAM inicial, defines un preset y usas el interruptor -p para generar un disco RAM inicial de acuerdo con tu preset.

Típicamente, los presets son archivos ubicados en /etc/mkinitcpio.d con la extensión .preset, por ejemplo /etc/mkinitcpio.d/linux.preset para el preset de linux. Es posible usar archivos en otras ubicaciones también. Entonces, se debe especificar la ruta a ese archivo.

Los archivos de presets son scripts de shell que son cargados por mkinitcpio y las siguientes variables influirán en su comportamiento.

Ten en cuenta que mkinitcpio se llama a sí mismo para cada preset y pasa las opciones definidas en el archivo preset a través de argumentos de línea de comandos. Estos se mencionan en la descripción de las opciones a continuación, así que consulta el manual de los argumentos de línea de comandos para obtener más información sobre una opción en particular.

Una matriz de nombres de presets definidos en este archivo. Estos nombres se usarán como prefijo para otras opciones para proporcionar opciones específicas del preset. Por ejemplo, si se proporciona un PRESET=('custom'), la imagen se especifica a través de custom_image='/boot/custom.img'.

<preset>_kver (por defecto el valor de ALL_kver — se requiere uno de los dos)

<preset>_config (por defecto el valor de ALL_config — se requiere uno de los dos)

Ruta al archivo de configuración (pasado vía -c a mkinitcpio).

<preset>_uki (se requiere uno de <preset>_uki y <preset>_image)

Ruta del archivo de salida para una imagen de kernel unificada (pasado vía -U a mkinitcpio).

<preset>_image (se requiere uno de <preset>_uki y <preset>_image)

Ruta del archivo de salida para la imagen generada (pasado vía -g a mkinitcpio).

<preset>_cmdline (por defecto el valor de ALL_cmdline)

Ruta al archivo de línea de comandos del kernel (pasado vía --cmdline a mkinitcpio). Esta opción solo se usa al generar imágenes de kernel unificadas.

<preset>_splash (por defecto el valor de ALL_splash)

Ruta al archivo de imagen de pantalla de bienvenida (pasado vía --splash a mkinitcpio). Esta opción solo se usa al generar imágenes de kernel unificadas.

<preset>_kerneldest (por defecto el valor de ALL_kerneldest)

Ruta de destino del kernel que se pasará a los hooks posteriores. Esto anula la ubicación predeterminada del kernel (generalmente /boot) y permite la personalización de dónde debe ubicarse el kernel para el arranque. El valor se pasa a los hooks posteriores a través de la variable de entorno KERNELDESTINATION.

<preset>_options

Argumentos adicionales de línea de comandos para pasar a mkinitcpio como una cadena o un array. Se añadirán al final de la llamada a mkinitcpio (después de todas las opciones mencionadas anteriormente), por lo que esto se puede usar para anular opciones (por ejemplo, pasar un -S hook aquí para omitir un hook).

SOBRE LOS HOOKS DE INSTALACIÓN

Los hooks de instalación son scripts de bash que se enlazan durante la ejecución de mkinitcpio para agregar módulos, binarios y otros archivos a la imagen. Una variedad de funciones existen para facilitar esto.

add_module modname

Agrega el módulo especificado por modname a la imagen. Las dependencias se derivan y se agregan automáticamente.

add_binary binary [ destination ] [ mode ]

Agrega un binario a la imagen. El argumento binary no necesita ser una ruta absoluta y, si es necesario, se realizará una búsqueda. Si el binario es un binario ELF enlazado dinámicamente, las dependencias se agregarán automáticamente. Si es un enlace simbólico, se agregarán tanto el enlace simbólico como el binario de destino. Opcionalmente, se puede especificar un destino dentro de la imagen initramfs, así como un modo de archivo. Por defecto, el destino y el modo se tomarán de la fuente derivada de binary.

add_file path [ destination ] [ mode ]

Agrega un archivo y cualquier directorio padre necesario a la imagen. Si es un enlace simbólico, se agregarán tanto el enlace simbólico como el archivo de destino. Opcionalmente, se puede especificar un destino dentro de la imagen initramfs, así como un modo de archivo. Por defecto, el destino y el modo se tomarán de la fuente y el modo del archivo especificado por la path.

add_file_early path [ destination ] [ mode ]

Agrega un archivo y cualquier directorio padre necesario a la imagen temprana descomprimida. Funciona de la misma manera que add_file.

add_dir path

Agrega un directorio y sus padres a la imagen.

add_dir_early path

Agrega un directorio y sus padres a la imagen temprana descomprimida. Funciona de la misma manera que add_dir.

add_full_dir directory [ glob ] [ strip_prefix ]

Agrega recursivamente un directorio a la imagen recorriendo la ruta dada y llamando a add_file, add_dir y add_symlink correspondientemente. Esta función no seguirá enlaces simbólicos, ni agregará los destinos de los enlaces simbólicos.

Si se pasa el argumento glob, solo se agregarán archivos y enlaces simbólicos que coincidan con este glob.

Si se pasa el argumento strip_prefix, se utilizará para eliminar el prefijo especificado por el argumento strip_prefix de la ruta de destino (ruta en la imagen initramfs). Esto puede ser útil al escribir hooks de rootfs-overlay.

add_symlink path [ link-target ]

Agrega un enlace simbólico a la imagen en la path especificada, apuntando opcionalmente al link-target especificado. Si el link-target no se proporciona, se asume que este enlace simbólico existe en el sistema de archivos real, y el destino se leerá usando readlink(1). No se realiza ninguna verificación para asegurar que el destino del enlace simbólico exista, y los enlaces simbólicos no se seguirán recursivamente.

add_all_modules [ -f filter ] pattern

Agrega módulos a la imagen, sin tener en cuenta la lista blanca de autodetección. pattern debe ser un subdirectorio dentro del árbol del kernel que describa un subconjunto de módulos a incluir. Se pueden proporcionar más refinamientos a través del flag -f con una expresión regular extendida.

add_checked_modules [ -f filter ] pattern

Similar a add_all_modules con la restricción de que solo se agregarán a la imagen los módulos que coincidan con la lista blanca generada por el hook de autodetección. Si el hook de autodetección no está presente en la imagen, esta función es idéntica a add_all_modules.

add_runscript scriptname

Agrega un hook de tiempo de ejecución a la imagen, que es un script de shell compatible con busybox ash. Se garantiza que el nombre del script coincida con el nombre del hook desde el cual se llama al script.

add_udev_rule rule-file

Agrega una regla udev a la imagen. Las dependencias de los binarios se descubrirán y se agregarán. El argumento puede ser el nombre de un archivo de regla (descubierto de rutas udev conocidas) o una ruta absoluta.

add_all_modules_from_symbol symbol paths

Agrega módulos de los directorios paths que contienen el symbol a la imagen.

add_checked_modules_from_symbol symbol paths

Similar a add_all_modules_from_symbol con la restricción de que solo se agregarán a la imagen los módulos que coincidan con la lista blanca generada por el hook de autodetección. Si el hook de autodetección no está presente en la imagen, esta función es idéntica a add_all_modules_from_symbol.

SOBRE CPIO TEMPRANO

mkinitcpio tiene soporte para CPIO temprano. Estos son archivos CPIO descomprimidos que se anteponen al archivo CPIO comprimido principal. Se utilizan para la carga temprana de microcódigo de CPU o para cargar anulaciones de tablas ACPI.

Los hooks de instalación pueden instalar archivos en este archivo agregándolos a $EARLYROOT.

SOBRE LOS HOOKS DE TIEMPO DE EJECUCIÓN

Los hooks de tiempo de ejecución agregados a la imagen a través de la función add_runscript desde un hook de instalación pueden proporcionar funcionalidad adicional durante el espacio de usuario temprano. Las funciones específicas en estos archivos se ejecutarán en diferentes momentos. Un hook puede definir uno o más de estos. En cada punto de hook, los hooks se ejecutan en el orden en que se definen en la variable HOOKS, excepto para los hooks de limpieza que se ejecutan en orden inverso.

run_earlyhook

Las funciones con este nombre se ejecutarán una vez que las monturas de API se hayan configurado y se haya analizado la línea de comandos del kernel. Los demonios necesarios para el espacio de usuario temprano deben iniciarse desde este punto de hook.

run_hook

Las funciones con este nombre se ejecutarán después de cualquier hook temprano, y después de que se hayan instalado los módulos definidos por el usuario. Este es el punto de hook más común, y la funcionalidad, como el escaneo de volúmenes LVM y el mapeo de volúmenes cifrados, debe realizarse aquí.

run_latehook

Las funciones con este nombre se ejecutarán después de que se haya montado la raíz. Esto se usa generalmente para una configuración adicional necesaria en la raíz real, como montar otras particiones del sistema.

run_cleanuphook

Las funciones con este nombre se ejecutan lo más tarde posible. Cualquier demonio iniciado desde una función run_earlyhook debe apagarse aquí en preparación para cambiar a la raíz real.

run_emergencyhook

Las funciones con este nombre se ejecutan antes de que se inicie el shell de emergencia en caso de fallo de arranque. Por ejemplo, esto permite que las pantallas de bienvenida terminen su proceso, para que los usuarios noten el fallo.

getarg argument [ default ]

Esta función se puede usar en hooks de tiempo de ejecución para obtener un argumento de la línea de comandos del kernel. Si argument existe con un valor, se devuelve el valor. Si argument existe sin un valor, se devuelve y. Si argument no existe, se devuelve default. Si default no se especifica, no se devuelve nada.

SOBRE LOS HOOKS POSTERIORES

Los hooks posteriores son ejecutables o scripts ejecutados después de la generación exitosa de la imagen para su procesamiento posterior, como la firma. Cuando kernel-install(8) invoca mkinitcpio, los hooks posteriores están deshabilitados.

Reciben el kernel como primer argumento, la imagen como segundo y opcionalmente la imagen de kernel unificada como tercero.

Nota: Si mkinitcpio se invoca con -k none o -k version y no se encuentra la imagen del kernel, el primer argumento estará vacío.

Las siguientes variables de entorno se pasan:

KERNELVERSION

Contiene la versión completa del kernel del cual se ha construido la imagen.

KERNELDESTINATION

La ubicación predeterminada donde debe ubicarse el kernel para el arranque. Esto generalmente es lo mismo que el primer argumento, pero puede diferir si mkinitcpio no se invocó con -k /boot/*. Si no se encontró ninguna imagen de kernel, esta variable estará vacía.

ENTORNO DE INICIALIZACIÓN TEMPRANA

mkinitcpio da un tratamiento especial a ciertas variables de entorno pasadas en la línea de comandos del kernel:

break[=<premount|postmount>]

Si se especifica, mkinitcpio iniciará un shell durante la inicialización temprana. El parámetro opcional controla cuándo ocurre esto: cuando se especifica premount o ningún parámetro, el shell se lanzará antes de montar la raíz. Si se especifica postmount, el shell se lanzará después de montar la raíz.

disablehooks=lista_de_hooks

Esta es una lista separada por comas de hooks que se omitirán durante la inicialización temprana.

earlymodules=lista_de_módulos

Esta es una lista separada por comas de módulos que se cargarán antes que cualquier otro. Esto generalmente no es necesario y suele apuntar a un problema de configuración o del kernel.

quiet

Hace que mkinitcpio genere menos mensajes durante el arranque. Los errores no se suprimirán.

ro

Especifica que la raíz debe montarse con permisos de solo lectura. Este es el comportamiento predeterminado.

rw

Especifica que la raíz debe montarse con permisos de lectura/escritura. Esto generalmente solo es útil si tu initramfs utiliza el hook fsck.

root=dispositivo_raíz

Esta variable describe la partición raíz que la inicialización temprana montará antes de pasar el control al init real. mkinitcpio entiende una variedad de formatos, el más básico de los cuales es la ruta al dispositivo de bloques, ya sea directamente como /dev/sda2, o usando un enlace simbólico de udev como /dev/disk/by-label/CorsairF80-root. También se admite la identificación por etiquetas LABEL o UUID, como, LABEL=CorsairF80-root. A partir de util-linux 2.22, también se admiten PARTUUID y PARTLABEL. La identificación a través de ID de dispositivo mayor/menor codificado en hexadecimal se admite por razones de legado, pero debe evitarse, ya que tiende a ser frágil.

rootdelay[=segundos]

Establece el retraso, en segundos, que mkinitcpio está dispuesto a esperar a que aparezca el dispositivo raíz, si no está disponible inmediatamente. Esto tiene un valor predeterminado de 10 segundos. Si se pasa un entero no válido, esta variable no tendrá efecto.

rootflags=lista_de_flags

Una lista separada por comas de flags que se pasarán al comando mount(8) al montar el sistema de archivos raíz. Los valores aceptables son específicos del sistema de archivos.

rootfstype=tipo_sistema_archivos

Anula el tipo de sistema de archivos que se está montando como raíz. Esto casi nunca debería ser necesario, ya que mount(8) generalmente lo detecta por sí solo.

rd.debug

Habilita la depuración del shell (xtrace). Si rd.log no es también un parámetro en la línea de comandos del kernel, este parámetro implica rd.log=console.

rd.log[=<console|file|kmsg|all>]

Habilita el registro de mensajes del espacio de usuario temprano. Si se especifica, el parámetro opcional describe dónde se registra esta información. Se pueden combinar varias opciones usando el carácter de barra vertical (|). Los mensajes siempre se registran en la consola a menos que se pase el parámetro quiet. Si el parámetro opcional no se especifica, se asume kmsg|console. Si rd.log no está presente en la línea de comandos del kernel, no se realizará ningún registro.

console

Escribe la salida en /dev/console.

file

Escribe la salida en /run/initramfs/init.log.

kmsg

Escribe la salida en el dispositivo /dev/kmsg (introducido en Linux 3.5). Esta opción no tiene efecto si tu kernel no soporta /dev/kmsg.

all

Escribe la salida en todos los destinos de registro conocidos.

Estas son solo las variables que el núcleo de mkinitcpio respeta. Los hooks adicionales pueden buscar otras variables de entorno y deben ser documentados por la ayuda del hook.

REPRODUCIBILIDAD

mkinitcpio tiene como objetivo crear imágenes initramfs reproducibles por defecto.

Esto significa que dos ejecuciones subsiguientes de mkinitcpio deberían producir dos archivos que sean idénticos a nivel binario.

Las marcas de tiempo dentro de la initramfs se establecen en la época Unix del 1 de enero de 1970.

Tenga en cuenta que para que la compilación sea completamente reproducible, el compresor especificado (por ejemplo, gzip, xz) también debe producir archivos reproducibles. En el momento de escribir esto, como ejemplo no exhaustivo, el compresor lzop es incapaz de producir archivos reproducibles debido a la inserción de una marca de tiempo en tiempo de ejecución.

Puede encontrar más información en https://reproducible-builds.org.

ARCHIVOS

/etc/mkinitcpio.conf

Archivo de configuración predeterminado para mkinitcpio.

/etc/mkinitcpio.conf.d

Directorio que contiene archivos de configuración drop-in.

/etc/mkinitcpio.d

Directorio que contiene los presets de mkinitcpio.

/etc/initcpio/install, /usr/lib/initcpio/install

Ruta de búsqueda para hooks en tiempo de compilación.

/etc/initcpio/hooks, /usr/lib/initcpio/hooks

Ruta de búsqueda para hooks de runtime del espacio de usuario temprano.

/etc/initcpio/post, /usr/lib/initcpio/post

Ruta de búsqueda para hooks posteriores a la generación.

EJEMPLOS

mkinitcpio

Realiza una ejecución de prueba. Esto generará un disco ram inicial pero no escribirá nada. Usa -g para crear la imagen real.

mkinitcpio -p linux

Crea un disco ram inicial basado en el preset linux.

mkinitcpio -g /boot/initramfs-linux.img -k /boot/vmlinuz-linux

Crea un disco ram inicial para el kernel en /boot/vmlinuz-linux. La imagen resultante se escribirá en /boot/initramfs-linux.img.

mkinitcpio -U /efi/EFI/Linux/systemd-linux.efi

Crea un disco ram inicial para el kernel junto con una imagen de kernel unificada. El ejecutable resultante se escribirá en /efi/EFI/Linux/systemd-linux.efi.

mkinitcpio -U /efi/EFI/Linux/systemd-linux.efi --splash /usr/share/systemd/bootctl/splash-arch.bmp

Crea un disco ram inicial para el kernel y una imagen de kernel unificada. Esto también incluye una imagen de bienvenida que se usará durante el arranque.
