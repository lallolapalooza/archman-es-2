MKFIFO(3P) Manual del programador POSIX MKFIFO(3P)

PROLOG

Esta página del manual forma parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

mkfifo, mkfifoat — crear un archivo especial FIFO

SINOPSIS

#include <sys/stat.h>
int mkfifo(const char *path, mode_t mode);
#include <fcntl.h>
int mkfifoat(int fd, const char *path, mode_t mode);

DESCRIPCIÓN

La función mkfifo() creará un nuevo archivo especial FIFO nombrado por la ruta del archivo apuntada por path. Los bits de permiso del archivo del nuevo FIFO se inicializarán a partir de mode. Los bits de permiso del archivo del argumento mode serán modificados por la máscara de creación de archivos del proceso.

Cuando se establecen bits en mode distintos de los bits de permiso del archivo, el efecto depende de la implementación.

Si path nombra un enlace simbólico, mkfifo() fallará y establecerá errno a [EEXIST].

El ID de usuario del FIFO se establecerá en el ID de usuario efectivo del proceso. El ID de grupo del FIFO se establecerá en el ID de grupo del directorio padre o en el ID de grupo efectivo del proceso. Las implementaciones proporcionarán una forma de inicializar el ID de grupo del FIFO al ID de grupo del directorio padre. Las implementaciones pueden, pero no es necesario, proporcionar una forma definida por la implementación para inicializar el ID de grupo del FIFO al ID de grupo efectivo del proceso que llama.

Al completarse con éxito, mkfifo() marcará para actualización las últimas marcas de tiempo de acceso a datos, modificación de datos y cambio de estado del archivo. Además, las últimas marcas de tiempo de modificación de datos y cambio de estado del directorio que contiene la nueva entrada se marcarán para actualización.

La función mkfifoat() será equivalente a la función mkfifo() excepto en el caso en que path especifique una ruta relativa. En este caso, el FIFO recién creado se creará en relación con el directorio asociado con el descriptor de archivo fd en lugar del directorio de trabajo actual. Si el modo de acceso de la descripción del archivo abierto asociado con el descriptor de archivo no es O_SEARCH, la función verificará si las búsquedas de directorios están permitidas utilizando los permisos actuales del directorio subyacente al descriptor de archivo. Si el modo de acceso es O_SEARCH, la función no realizará la verificación.

Si a mkfifoat() se le pasa el valor especial AT_FDCWD en el parámetro fd, se utilizará el directorio de trabajo actual y el comportamiento será idéntico al de una llamada a mkfifo().

VALOR DE RETORNO

Al completarse con éxito, estas funciones devolverán 0. De lo contrario, estas funciones devolverán -1 y establecerán errno para indicar el error. Si se devuelve -1, no se creará ningún FIFO.

ERRORES

Estas funciones fallarán si:

EACCES
Un componente del prefijo de ruta deniega el permiso de búsqueda, o se deniega el permiso de escritura en el directorio padre del FIFO a crear.
EEXIST
El archivo nombrado ya existe.
ELOOP
Existe un bucle en los enlaces simbólicos encontrados durante la resolución del argumento path.
ENAMETOOLONG

La longitud de un componente de una ruta de archivo es mayor que {NAME_MAX}.
ENOENT
Un componente del prefijo de ruta de path no nombra un archivo existente o path es una cadena vacía.
ENOENT o ENOTDIR

El argumento path contiene al menos un carácter que no es <barra> y termina con uno o más caracteres <barra> finales. Si path sin los caracteres <barra> finales nombrara un archivo existente, no ocurrirá un error [ENOENT].
ENOSPC
El directorio que contendría el nuevo archivo no puede ser extendido o al sistema de archivos le faltan recursos de asignación de archivos.
ENOTDIR
Un componente del prefijo de ruta nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio.
EROFS
El archivo nombrado reside en un sistema de archivos de solo lectura.

La función mkfifoat() fallará si:

EACCES
El modo de acceso de la descripción del archivo abierto asociado con fd no es O_SEARCH y los permisos del directorio subyacente a fd no permiten búsquedas de directorios.
EBADF
El argumento path no especifica una ruta absoluta y el argumento fd no es ni AT_FDCWD ni un descriptor de archivo válido abierto para lectura o búsqueda.
ENOTDIR
El argumento path no es una ruta absoluta y fd es un descriptor de archivo asociado con un archivo que no es un directorio.

Estas funciones pueden fallar si:

ELOOP
Se encontraron más de {SYMLOOP_MAX} enlaces simbólicos durante la resolución del argumento path.
ENAMETOOLONG

La longitud de una ruta de archivo excede {PATH_MAX}, o la resolución de ruta de un enlace simbólico produjo un resultado intermedio con una longitud que excede {PATH_MAX}.

EJEMPLOS

Creación de un Archivo FIFO

El siguiente ejemplo muestra cómo crear un archivo FIFO llamado /home/cnd/mod_done, con permisos de lectura/escritura para el propietario, y con permisos de lectura para el grupo y otros.

#include <sys/types.h>
#include <sys/stat.h>
int status;
...
status = mkfifo("/home/cnd/mod_done", S_IWUSR | S_IRUSR |
    S_IRGRP | S_IROTH);

USO POR LA APLICACIÓN

Ninguno.

FUNDAMENTO

La sintaxis de esta función está destinada a mantener la compatibilidad con implementaciones históricas de mknod(). Esta última función se incluyó en el estándar /usr/group de 1984 pero solo para su uso en la creación de archivos especiales FIFO. La función mknod() fue excluida originalmente del estándar POSIX.1-1988 como definida por la implementación y reemplazada por mkdir() y mkfifo(). La función mknod() ahora se incluye para alinearse con la Especificación Única de UNIX.

El estándar POSIX.1-1990 requería que el ID de grupo de un FIFO recién creado se estableciera en el ID de grupo de su directorio padre o en el ID de grupo efectivo del proceso creador. FIPS 151-2 requería que las implementaciones proporcionaran una forma de establecer el ID de grupo al ID de grupo del directorio contenedor, pero no prohibía que las implementaciones también admitieran una forma de establecer el ID de grupo al ID de grupo efectivo del proceso que llama. Las aplicaciones conformes no deben asumir qué ID de grupo se utilizará. Si importa, una aplicación puede usar chown() para establecer el ID de grupo después de que se cree el FIFO, o determinar bajo qué condiciones la implementación establecerá el ID de grupo deseado.

El propósito de la función mkfifoat() es crear un archivo especial FIFO en directorios distintos del directorio de trabajo actual sin exposición a condiciones de carrera. mkfifo(3p) — Arch manual pages

PROLOG

This page is part of the Linux man-pages project. It describes a Linux specific system call that has not been standardized by POSIX. For portability reasons, you are strongly advised to use the POSIX standard interface mkfifo(3) whenever possible.

NAME

mkfifoat — create a FIFO (named pipe) relative to a directory file descriptor

SYNOPSIS

#include <sys/stat.h>

int mkfifoat(int dirfd, const char *pathname, mode_t mode);

DESCRIPTION

The mkfifoat() function is the same as mkfifo(), except that the FIFO is created relative to the directory referred to by the file descriptor dirfd.

If pathname is relative, then it is interpreted relative to the directory referred to by dirfd (rather than as is done by mkfifo() which interprets pathname relative to the current working directory if it is relative).

If pathname specifies a rooted path, then dirfd is ignored.

The mkfifoat() function was added to support the openat() interface.

The mode argument specifies the file permission bits for the new FIFO. This argument must be a value of type mode_t. The effective mode is modified by the process's umask(). The new FIFO is created with read and write permission for the owner, and read-only permission for group and others. See chmod(2) for the effect of umask().

The pathname argument is the name of the FIFO to be created. It is a pointer to a null-terminated string.

dirfd is a file descriptor that refers to a directory. AT_FDCWD is permitted in dirfd (and this is the default behaviour when pathname is absolute).

The following flags can be included in mode:

“S_IRUSR | S_IWUSR”
Read and write for owner.
“S_IRGRP”
Read for group.
“S_IROTH”
Read for others.

RETURN VALUE

On success, mkfifoat() returns 0. On failure, it returns -1 and sets errno to indicate the error.

ERRORS

See mkfifo(3).

EXAMPLES

Create a FIFO named fifotemp in the directory specified by the file descriptor dirfd:

#include <fcntl.h>
#include <sys/stat.h>
#include <unistd.h>
#include <stdio.h>
#include <stdlib.h>

int dirfd = open(".", O_RDONLY);
if (dirfd == -1) {
perror("open");
exit(EXIT_FAILURE);
}

if (mkfifoat(dirfd, "fifotemp", 0666) == -1) {
perror("mkfifoat");
close(dirfd);
exit(EXIT_FAILURE);
}

close(dirfd);

APPLICATION USAGE

The mkfifoat() function is intended for use by applications that need to create FIFOs in specific directories without changing the current working directory. This is particularly useful in multi-threaded applications or when dealing with temporary files.

RATIONALE

The mkfifoat() function is part of a set of functions (along with openat(), mkdirat(), etc.) that allow file operations to be performed relative to a directory file descriptor. This is useful for writing programs that do not rely on the current working directory, which can be important for security and robustness.

By using a file descriptor for the target directory and the mkfifoat() function, it can be guaranteed that the newly created FIFO is located relative to the desired directory.
