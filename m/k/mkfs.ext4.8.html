NOMBRE

mke2fs - crear un sistema de archivos ext2/ext3/ext4

SINOPSIS

mke2fs [ -c | -l nombre-archivo ] [ -b tamaño-bloque ] [ -C tamaño-clúster ] [ -d directorio-raíz|archivo-tar ] [ -D ] [ -g bloques-por-grupo ] [ -G número-de-grupos ] [ -i bytes-por-inodo ] [ -I tamaño-inodo ] [ -j ] [ -J opciones-journal ] [ -N número-de-inodos ] [ -n ] [ -m porcentaje-bloques-reservados ] [ -o os-creador ] [ -O [^]característica[,...] ] [ -q ] [ -E opciones-extendidas ] [ -v ] [ -F ] [ -L etiqueta-volumen ] [ -M directorio-último-montaje ] [ -S ] [ -t tipo-fs ] [ -T tipo-uso ] [ -U UUID ] [ -V ] [ -e comportamiento-errores ] [ -z archivo-deshacer ] dispositivo [ tamaño-fs ]

mke2fs -O journal_dev [ -b tamaño-bloque ] [ -L etiqueta-volumen ] [ -n ] [ -q ] [ -v ] journal-externo [ tamaño-fs ]

DESCRIPCIÓN

mke2fs se utiliza para crear un sistema de archivos ext2, ext3 o ext4, generalmente en una partición de disco (o archivo) denominada por dispositivo.

El tamaño del sistema de archivos se especifica mediante tamaño-fs. Si tamaño-fs no tiene sufijo, se interpreta como kilobytes en potencia de dos, a menos que se especifique la opción -b tamaño-bloque, en cuyo caso tamaño-fs se interpreta como el número de bloques de tamaño-bloque. Si tamaño-fs tiene un sufijo 'k', 'm', 'g', 't' (mayúscula o minúscula), se interpreta en kilobytes, megabytes, gigabytes, terabytes, etc., en potencia de dos. Si se omite tamaño-fs, mke2fs creará el sistema de archivos basándose en el tamaño del dispositivo.

Si mke2fs se ejecuta como mkfs.XXX (es decir, mkfs.ext2, mkfs.ext3 o mkfs.ext4) se implica la opción -t XXX; por lo tanto, mkfs.ext3 creará un sistema de archivos para usar con ext3, mkfs.ext4 creará un sistema de archivos para usar con ext4, y así sucesivamente.

Los valores predeterminados de los parámetros para el sistema de archivos recién creado, si no se anulan con las opciones que se enumeran a continuación, se controlan desde el archivo de configuración /etc/mke2fs.conf. Consulte la página del manual de mke2fs.conf(5) para obtener más detalles.

OPCIONES

-b tamaño-bloque
Especifica el tamaño de los bloques en bytes. Los valores válidos de tamaño-bloque son potencias de dos desde 1024 hasta 65536 (sin embargo, tenga en cuenta que el kernel solo puede montar sistemas de archivos con un tamaño de bloque menor o igual al tamaño de página del sistema - 4k en sistemas x86, hasta 64k en ppc64 o aarch64 dependiendo de la configuración del kernel). Si se omite, el tamaño-bloque se determina heurísticamente por el tamaño del sistema de archivos y el uso esperado del sistema de archivos (consulte la opción -T). En la mayoría de los casos comunes, el tamaño de bloque predeterminado es 4k. Si tamaño-bloque va precedido por un signo negativo ('-'), mke2fs utilizará heurísticas para determinar el tamaño de bloque apropiado, con la restricción de que el tamaño de bloque será de al menos tamaño-bloque bytes. Esto es útil para ciertos dispositivos de hardware que requieren que el tamaño de bloque sea un múltiplo de 2k.
-c
Verifica el dispositivo en busca de bloques defectuosos antes de crear el sistema de archivos. Si esta opción se especifica dos veces, se utiliza una prueba de lectura-escritura más lenta en lugar de una prueba rápida de solo lectura.
-C tamaño-clúster
Especifica el tamaño del clúster en bytes para sistemas de archivos que usan la característica bigalloc. Los valores válidos de tamaño-clúster varían de 2 a 32768 veces el tamaño de bloque del sistema de archivos y deben ser potencias de 2. El tamaño-clúster solo se puede especificar si la característica bigalloc está habilitada. (Consulte la página del manual de ext4(5) para obtener más detalles sobre bigalloc.) El tamaño de clúster predeterminado si bigalloc está habilitado es 16 veces el tamaño de bloque.
-d directorio-raíz|archivo-tar
Copia el contenido del directorio o archivo tar dado en el directorio raíz del sistema de archivos. La entrada de archivo tar solo está disponible si mke2fs se compiló con soporte para libarchive habilitado y si la biblioteca compartida libarchive está disponible en tiempo de ejecución. El valor especial "-" leerá un archivo tar desde la entrada estándar.
-D
Utiliza E/S directa al escribir en el disco. Esto evita que mke2fs ensucie mucha memoria de caché de búfer, lo que puede afectar a otras aplicaciones que se ejecutan en un servidor ocupado. Sin embargo, esta opción hará que mke2fs funcione mucho más lentamente, por lo que existe una compensación al utilizar E/S directa.
-e comportamiento-errores
Cambia el comportamiento del código del kernel cuando se detectan errores. En todos los casos, un error del sistema de archivos provocará que e2fsck(8) verifique el sistema de archivos en el próximo arranque. comportamiento-errores puede ser uno de los siguientes:
continue
Continúa la ejecución normal.
remount-ro
Remonta el sistema de archivos como solo lectura.
panic
Provoca un pánico del kernel.
-E opciones-extendidas
Establece opciones extendidas para el sistema de archivos. Las opciones extendidas están separadas por comas y pueden tomar un argumento usando el signo igual ('='). La opción -E solía ser -R en versiones anteriores de mke2fs. La opción -R todavía se acepta por compatibilidad, pero está obsoleta. Las siguientes opciones extendidas son compatibles:
assume_storage_prezeroed[= <0 para deshabilitar, 1 para habilitar>]
Si está habilitado, mke2fs asume que el dispositivo de almacenamiento se ha pre-cero, omite el cerado del journal y las tablas de inodos, y anota las banderas del grupo de bloques para indicar que la tabla de inodos se ha cero.
discard
Intenta descartar bloques en el momento de la creación del sistema de archivos (descartar bloques inicialmente es útil en dispositivos de estado sólido y almacenamiento con provisión escasa/thin). Cuando el dispositivo anuncia que descartar también pone a cero los datos (cualquier lectura posterior al descarte y antes de la escritura devuelve cero), entonces marca todas las tablas de inodos que aún no se han puesto a cero como cero. Esto acelera significativamente la inicialización del sistema de archivos. Esto está configurado por defecto.
encoding=nombre-codificación
Habilita la característica casefold en el superbloque y establece nombre-codificación como la codificación que se utilizará. Si no se especifica nombre-codificación, se utiliza la codificación definida en mke2fs.conf(5).
encoding_flags=flags-codificación
Define parámetros para las operaciones de codificación de nombres de archivo. Si un flag no se cambia usando este parámetro, se utiliza su valor predeterminado. flags-codificación debe ser una lista separada por comas de flags para habilitar. Para deshabilitar un flag, agréguelo a la lista con el prefijo "no".

El único flag que se puede establecer en este momento es strict, lo que significa que el sistema de archivos debería rechazar cadenas inválidas. En la configuración predeterminada, el flag strict está deshabilitado.

lazy_itable_init[= <0 para deshabilitar, 1 para habilitar>]
Si está habilitado y la característica uninit_bg está habilitada, la tabla de inodos no será completamente inicializada por mke2fs. Esto acelera notablemente la inicialización del sistema de archivos, pero requiere que el kernel termine de inicializar el sistema de archivos en segundo plano cuando se monte el sistema de archivos por primera vez. Si se omite el valor de la opción, por defecto es 1 para habilitar el cerado de inodos diferido.
lazy_journal_init[= <0 para deshabilitar, 1 para habilitar>]
Si está habilitado, el inodo del journal no será completamente cerado por mke2fs. Esto acelera notablemente la inicialización del sistema de archivos, pero conlleva una pequeña

lazy_itable_init[= <0 to disable, 1 to enable>]
This option disables lazy initialization of the inode table. This means that the entire inode table will be zeroed out at the time the file system is created. This slows down the file system creation process, but it ensures that all of the inodes are valid and initialized. This option is primarily intended to be used for testing purposes, as it offers no real benefit for production systems. The risk is that the system crashes before the journal has been overwritten entirely one time. If the option value is omitted, it defaults to 1 to enable lazy journal inode zeroing.
mmp_update_interval=interval
Ajusta el intervalo de actualización inicial de MMP a interval segundos. Especificar un intervalo de 0 significa usar el intervalo predeterminado. El intervalo especificado debe ser inferior a 300 segundos. Requiere que la función mmp esté habilitada. nodiscard No intente descartar bloques en el momento de la creación del sistema de archivos.
no_copy_xattrs
Normalmente mke2fs copiará los atributos extendidos de los archivos en la jerarquía de directorios especificada a través de la opción (opcional) -d. Esto deshabilitará la copia y dejará los archivos en el sistema de archivos recién creado sin ningún atributo extendido.
num_backup_sb=<0|1|2>
Si la función de sistema de archivos sparse_super2 está habilitada, esta opción controla si se crearán 0, 1 o 2 superbloques de copia de seguridad en el sistema de archivos.
offset=offset
Crea el sistema de archivos con un desplazamiento desde el principio del dispositivo o archivo. Esto puede ser útil al crear imágenes de disco para máquinas virtuales.
orphan_file_size=size
Establece el tamaño del archivo para rastrear inodos desvinculados pero aún abiertos y inodos con truncamiento en curso. Un archivo más grande permite una mejor escalabilidad, siendo ideal reservar algunos bloques por CPU.
packed_meta_blocks[= <0 para deshabilitar, 1 para habilitar>]
Coloca los mapas de bits de asignación y la tabla de inodos al principio del disco. Esta opción requiere que la función de sistema de archivos flex_bg esté habilitada para que tenga efecto, y también creará el journal al principio del sistema de archivos. Esta opción es útil para dispositivos flash que utilizan flash SLC en el principio del disco. También maximiza el rango de bloques de datos contiguos, lo que puede ser útil para ciertos casos de uso especializados, como las unidades Shingled admitidas.
quotatype
Especifica los tipos de cuotas (usrquota, grpquota, prjquota) que deben habilitarse en el sistema de archivos creado. El argumento de esta opción extendida debe ser una lista separada por dos puntos. Esta opción solo tiene efecto si se establece la función quota. Los tipos de cuota predeterminados que se inicializarán si no se especifica esta opción son las cuotas de usuario y grupo. Si la función de proyecto está habilitada, también se inicializarán las cuotas de proyecto.
resize=max-online-resize
Reserva suficiente espacio para que la tabla de descriptores de grupos de bloques pueda crecer para admitir un sistema de archivos con max-online-resize bloques.
revision=fs-revision
Especifica el número de revisión del sistema de archivos. Los sistemas de archivos de revisión 0 proporcionan compatibilidad con los kernels de Linux anteriores a la versión 1.2 (anteriores a 1995). Esto solo es necesario para pruebas o para personas que deseen utilizar sistemas Linux muy antiguos e históricos. El valor predeterminado actual (soportado por todos los sistemas Linux modernos) es la revisión 1.
root_owner[=uid:gid]
Especifica el ID numérico de usuario y grupo del directorio raíz. Si no se especifica UID:GID, se utilizará el ID de usuario y grupo del usuario que ejecuta mke2fs. En mke2fs 1.42 y anteriores, el UID y GID del directorio raíz se establecían por defecto en el UID y GID del usuario que ejecutaba el comando mke2fs. La opción root_owner= permite especificar explícitamente estos valores y evitar efectos secundarios para los usuarios que no esperan que el contenido del sistema de archivos cambie según el usuario que ejecuta mke2fs.
root_perms[=permissions]
Especifica los permisos del directorio raíz en formato octal. Si no se especifican permisos, los permisos del directorio raíz se establecerán de acuerdo con la máscara umask predeterminada del sistema de archivos.
stride=stride-size
Configura el sistema de archivos para un array RAID con stride-size bloques del sistema de archivos. Este es el número de bloques que se leen o escriben en el disco antes de pasar al siguiente disco, lo que a veces se denomina tamaño de chunk. Esto afecta principalmente a la colocación de metadatos del sistema de archivos en el momento de mke2fs para evitar colocarlos en un solo disco, lo que puede perjudicar el rendimiento. También puede ser utilizado por el asignador de bloques.
stripe_width=stripe-width
Configura el sistema de archivos para un array RAID con stripe-width bloques del sistema de archivos por stripe. Esto es típicamente stride-size * N, donde N es el número de discos que soportan datos en el RAID (por ejemplo, para RAID 5 hay un disco de paridad, por lo que N será el número de discos en el array menos 1). Esto permite al asignador de bloques evitar lecturas-modificaciones-escrituras de la paridad en un stripe RAID si es posible al escribir los datos.
test_fs
Establece un indicador en el superbloque del sistema de archivos que indica que puede ser montado utilizando código experimental del kernel, como el sistema de archivos ext4dev.
-F
Fuerza a mke2fs a crear un sistema de archivos, incluso si el dispositivo especificado no es una partición en un dispositivo especial de bloques, o si otros parámetros no tienen sentido. Para forzar a mke2fs a crear un sistema de archivos incluso si el sistema de archivos parece estar en uso o está montado (algo verdaderamente peligroso), esta opción debe especificarse dos veces.
-g blocks-per-group
Especifica el número de bloques en un grupo de bloques. En general, no hay razón para que el usuario establezca este parámetro, ya que el valor predeterminado es óptimo para el sistema de archivos. (Para administradores que crean sistemas de archivos en arrays RAID, es preferible utilizar el parámetro RAID stride como parte de la opción -E en lugar de manipular el número de bloques por grupo). Esta opción es generalmente utilizada por desarrolladores que crean casos de prueba.
Si la función bigalloc está habilitada, la opción -g especificará el número de clústeres en un grupo de bloques.
-G number-of-groups
Especifica el número de grupos de bloques que se empaquetarán juntos para crear un grupo de bloques virtual más grande (o grupo "flex_bg") en un sistema de archivos ext4. Esto mejora la localidad de los metadatos y el rendimiento en cargas de trabajo intensivas en metadatos. El número de grupos debe ser una potencia de 2 y solo se puede especificar si la función de sistema de archivos flex_bg está habilitada.
-i bytes-per-inode
Especifica la relación bytes/inodo. mke2fs crea un inodo por cada bytes-per-inode bytes de espacio en el disco. Cuanto mayor sea la relación bytes-per-inode, menos inodos se crearán. Este valor generalmente no debe ser menor que el tamaño del bloque del sistema de archivos, ya que en ese caso se crearían más inodos de los que se pueden utilizar. Tenga en cuenta que no es posible cambiar esta relación en un sistema de archivos después de que se crea, así que tenga cuidado al decidir el valor correcto para este parámetro. Tenga en cuenta que el redimensionamiento de un sistema de archivos cambia el número de inodos para mantener esta relación.
-I inode-size
Especifica el tamaño de cada inodo en bytes. El valor inode-size debe ser una potencia de 2 mayor o igual a 128. Cuanto mayor sea el inode-size, más espacio consumirá la tabla de inodos, lo que reduce el espacio utilizable en el sistema de archivos y también puede afectar negativamente al rendimiento. No es posible cambiar este valor después de que se crea el sistema de archivos.
Los sistemas de archivos con un tamaño de inodo de 128 bytes no admiten marcas de tiempo posteriores al 19 de enero de 2038. Los inodos de 256 bytes o más admitirán marcas de tiempo extendidas, IDs de proyecto y la capacidad de almacenar algunos atributos extendidos en la tabla de inodos para mejorar el rendimiento.
El tamaño de inodo predeterminado se controla mediante el archivo mke2fs.conf(5). En el archivo mke2fs.conf que se distribuye con e2fsprogs, el tamaño de inodo predeterminado es de 256 bytes para todos los sistemas de archivos, excepto para GNU Hurd, ya que solo admite inodos de 128 bytes.
-j
Crea el sistema de archivos con un journal ext3. Si la opción -J no se especifica, se utilizarán los parámetros de journal predeterminados para crear un journal de tamaño adecuado (dado el tamaño del sistema de archivos) almacenado dentro del sistema de archivos. Tenga en cuenta que debe estar utilizando un kernel que tenga soporte ext3 para poder utilizar realmente el journal.
-J journal-options
Crea el journal ext3 utilizando las opciones especificadas en la línea de comandos. Las opciones de journal están separadas por comas y pueden tomar un argumento utilizando el signo igual ('='). Se admiten las siguientes opciones de journal:
device=external-journal
Adjunta el sistema de archivos al dispositivo de journal de bloques ubicado en external-journal. El journal externo ya debe haber sido creado utilizando el comando
mke2fs -O journal_dev external-journal
Tenga en cuenta que external-journal debe haber sido creado con el mismo tamaño de bloque que el nuevo sistema de archivos. Además, aunque hay soporte para adjuntar múltiples sistemas de archivos a un solo journal externo, el kernel de Linux y e2fsck(8) actualmente no admiten journals externos compartidos.
En lugar de especificar un nombre de dispositivo directamente, external-journal también puede especificarse como LABEL=label o UUID=UUID para localizar el journal externo por la etiqueta del volumen o el UUID almacenado en el superbloque ext2 al principio del journal. Utilice dumpe2fs(8) para mostrar la etiqueta del volumen y el UUID de un dispositivo de journal. Vea también la opción -L de tune2fs(8).

fast_commit_size=tamaño-commit-rápido

Crea un área adicional de journal de commit rápido de tamaño tamaño-commit-rápido kilobytes. Esta opción solo es válida si la característica fast_commit está habilitada en el sistema de archivos. Si esta opción no se especifica y la característica fast_commit está activada, el tamaño del área de commit rápido por defecto es tamaño-journal / 64 megabytes. El tamaño total del journal con la característica fast_commit habilitada es tamaño-journal + ( tamaño-commit-rápido * 1024) megabytes. El tamaño total del journal no puede ser superior a 10,240,000 bloques del sistema de archivos o la mitad del tamaño total del sistema de archivos (el que sea menor).

location=ubicación-journal

Especifica la ubicación del journal. El argumento ubicación-journal puede especificarse como un número de bloque, o si el número tiene un sufijo de unidad (por ejemplo, 'M', 'G', etc.) interprétalo como el desplazamiento desde el principio del sistema de archivos.

size=tamaño-journal

Crea un journal interno (es decir, almacenado dentro del sistema de archivos) de tamaño tamaño-journal megabytes. El tamaño del journal debe ser al menos 1024 bloques del sistema de archivos (es decir, 1 MB si se usan bloques de 1k, 4 MB si se usan bloques de 4k, etc.) y no puede ser superior a 10,240,000 bloques del sistema de archivos o la mitad del tamaño total del sistema de archivos (el que sea menor)

Solo se puede dar una de las opciones size o device para un sistema de archivos.

-l nombre-archivo

Lee la lista de bloques defectuosos del nombre-archivo. Tenga en cuenta que los números de bloque en la lista de bloques defectuosos deben generarse utilizando el mismo tamaño de bloque que utiliza mke2fs. Como resultado, la opción -c de mke2fs es un método mucho más simple y menos propenso a errores para verificar un disco en busca de bloques defectuosos antes de formatearlo, ya que mke2fs pasará automáticamente los parámetros correctos al programa badblocks.

-L nueva-etiqueta-volumen

Establece la etiqueta del volumen del sistema de archivos a nueva-etiqueta-volumen. La longitud máxima de la etiqueta del volumen es de 16 bytes.

-m porcentaje-bloques-reservados

Especifica el porcentaje de bloques del sistema de archivos reservados para el superusuario. Esto evita la fragmentación y permite que los demonios propiedad de root, como syslogd(8), continúen funcionando correctamente después de que se impida que los procesos no privilegiados escriban en el sistema de archivos. El porcentaje por defecto es del 5%.

-M último-directorio-montado

Establece el último directorio montado para el sistema de archivos. Esto puede ser útil para utilidades que se basan en el último directorio montado para determinar dónde debería montarse el sistema de archivos.

-n

Hace que mke2fs no cree realmente un sistema de archivos, sino que muestre lo que haría si creara un sistema de archivos. Esto se puede usar para determinar la ubicación de los superbloques de copia de seguridad para un sistema de archivos determinado, siempre que se utilicen los parámetros de mke2fs que se pasaron cuando se creó originalmente el sistema de archivos (con la opción -n añadida, por supuesto).

-N número-de-inodes

Anula el cálculo por defecto del número de inodos que deberían reservarse para el sistema de archivos (que se basa en el número de bloques y la relación bytes-por-inodo). Esto permite al usuario especificar directamente el número de inodos deseados.

-o sistema-operativo-creador

Anula el valor por defecto del campo "sistema operativo creador" del sistema de archivos. El campo creador se establece por defecto al nombre del sistema operativo para el cual se compiló el ejecutable mke2fs.

-O [^]característica[,...]

Crea un sistema de archivos con las características dadas (opciones del sistema de archivos), anulando las opciones por defecto del sistema de archivos. Las características que están habilitadas por defecto se especifican mediante la relación base_features, ya sea en la sección [defaults] del archivo de configuración /etc/mke2fs.conf, o en las subsecciones [fs_types] para los tipos de uso especificados por la opción -T, modificadas además por la relación features que se encuentra en las subsecciones [fs_types] para el sistema de archivos y los tipos de uso. Consulte la página del manual mke2fs.conf(5) para obtener más detalles. La configuración específica del tipo de sistema de archivos encontrada en la sección [fs_types] anulará el valor por defecto global que se encuentra en [defaults].

El conjunto de características del sistema de archivos se editará además utilizando ya sea el conjunto de características especificado por esta opción, o si esta opción no se proporciona, por la relación default_features para el tipo de sistema de archivos que se está creando, o en la sección [defaults] del archivo de configuración.

El conjunto de características del sistema de archivos está compuesto por una lista de características, separadas por comas, que se habilitarán. Para deshabilitar una característica, simplemente prefije el nombre de la característica con un carácter de intercalación ('^'). Las características con dependencias no se eliminarán correctamente. La característica pseudo-sistema de archivos "none" borrará todas las características del sistema de archivos.

Para obtener más información sobre las características que se pueden establecer, consulte la página del manual ext4(5).

-q

Ejecución silenciosa. Útil si mke2fs se ejecuta en un script. -S Escribe solo el superbloque y los descriptores de grupo. Esta es una medida extrema que debe tomarse solo en el caso muy improbable de que todos los superbloques y superbloques de copia de seguridad estén corruptos, y los usuarios experimentados deseen un método de recuperación de último recurso. Hace que mke2fs reinicialice el superbloque y los descriptores de grupo, sin tocar la tabla de inodos y los mapas de bits de bloques e inodos. El programa e2fsck debe ejecutarse inmediatamente después de usar esta opción, y no hay garantía de que se pueda recuperar ningún dato. Debido a la gran variedad de posibles opciones para mke2fs que afectan la disposición en disco, es fundamental especificar exactamente las mismas opciones de formato, como el tamaño del bloque, el tipo de sistema de archivos, las banderas de características y otros parámetros ajustables al usar esta opción, o el sistema de archivos se corromperá aún más. En algunos casos, como sistemas de archivos que han sido redimensionados o a los que se les han habilitado características después del formato, es imposible sobrescribir todos los superbloques correctamente, y ocurrirá al menos alguna corrupción del sistema de archivos. Es mejor ejecutar esto en una copia completa del sistema de archivos para que se puedan probar otras opciones si esta no funciona.

-t tipo-fs

Especifica el tipo de sistema de archivos (es decir, ext2, ext3, ext4, etc.) que se va a crear. Si esta opción no se especifica, mke2fs elegirá un valor predeterminado ya sea por cómo se ejecutó el comando (por ejemplo, utilizando un nombre de la forma mkfs.ext2, mkfs.ext3, etc.) o por un valor predeterminado definido por el archivo /etc/mke2fs.conf. Esta opción controla qué opciones del sistema de archivos se utilizan por defecto, basándose en el fragmento de configuración fstypes en /etc/mke2fs.conf.

Si se utiliza la opción -O para añadir o eliminar explícitamente opciones del sistema de archivos que deben establecerse en el nuevo sistema de archivos, el sistema de archivos resultante puede no ser compatible con el tipo-fs solicitado. (por ejemplo, "mke2fs -t ext3 -O extent /dev/sdXX" creará un sistema de archivos que no es compatible con la implementación de ext3 tal como se encuentra en el kernel de Linux; y "mke2fs -t ext3 -O ^has_journal /dev/hdXX" creará un sistema de archivos que no tiene journal y, por lo tanto, no será compatible con el código del sistema de archivos ext3 en el kernel de Linux.)

-T tipo-uso[,...]

Especifica cómo se va a utilizar el sistema de archivos, para que mke2fs pueda elegir parámetros óptimos del sistema de archivos para ese uso. Los tipos de uso que se admiten se definen en el archivo de configuración /etc/mke2fs.conf. El usuario puede especificar uno o más tipos de uso utilizando una lista separada por comas.

Si esta opción no se especifica, mke2fs elegirá un único tipo de uso por defecto basado en el tamaño del sistema de archivos a crear. Si el tamaño del sistema de archivos es inferior a 3 megabytes, mke2fs utilizará el tipo de sistema de archivos floppy. Si el tamaño del sistema de archivos es mayor o igual a 3 pero inferior a 512 megabytes, mke2fs(8) utilizará el tipo de sistema de archivos small. Si el tamaño del sistema de archivos es mayor o igual a 4 terabytes pero inferior a 16 terabytes, mke2fs(8) utilizará el tipo de sistema de archivos big. Si el tamaño del sistema de archivos es mayor o igual a 16 terabytes, mke2fs(8) utilizará el tipo de sistema de archivos huge. De lo contrario, mke2fs(8) utilizará el tipo de sistema de archivos por defecto default.

-U UUID

Establece el identificador universalmente único (UUID) del sistema de archivos a UUID. El formato del UUID es una serie de dígitos hexadecimales separados por guiones, así: "c1b9d5a2-f162-11cf-9ece-0020afc76f16". El parámetro UUID también puede ser uno de los siguientes:

clear

borra el UUID del sistema de archivos

random

genera un nuevo UUID generado aleatoriamente

time

genera un nuevo UUID basado en el tiempo

-v

Ejecución detallada.

-V

Imprime el número de versión de mke2fs y sale.

-z archivo-deshacer

Antes de sobrescribir un bloque del sistema de archivos, escribe el contenido anterior del bloque en un archivo de deshacer. Este archivo de deshacer se puede usar con e2undo(8) para restaurar el contenido anterior del sistema de archivos si algo sale mal. Si se pasa una cadena vacía como argumento de archivo-deshacer, el archivo de deshacer se escribirá en un archivo llamado mke2fs-dispositivo.e2undo en el directorio especificado a través de la variable de entorno E2FSPROGS_UNDO_DIR o la directiva undo_dir en el archivo de configuración.

ADVERTENCIA: El archivo de deshacer no se puede utilizar para recuperarse de un corte de energía o un fallo del sistema.

ENTORNO

MKE2FS_SYNC
Si se establece en un valor entero distinto de cero, su valor se utiliza para determinar con qué frecuencia se llama a sync(2) durante la inicialización de la tabla de inodos.
MKE2FS_CONFIG
Determina la ubicación del archivo de configuración (ver mke2fs.conf(5)).
MKE2FS_FIRST_META_BG
Si se establece en un valor entero distinto de cero, su valor se utiliza para determinar el primer grupo de bloques meta. Esto es principalmente para fines de depuración.
MKE2FS_DEVICE_SECTSIZE
Si se establece en un valor entero distinto de cero, su valor se utiliza para determinar el tamaño lógico del sector del dispositivo.
MKE2FS_DEVICE_PHYS_SECTSIZE
Si se establece en un valor entero distinto de cero, su valor se utiliza para determinar el tamaño físico del sector del dispositivo.
MKE2FS_SKIP_CHECK_MSG
Si se establece, no se muestra el mensaje de comprobación automática del sistema de archivos debido al contador de montaje o al intervalo de comprobación.
