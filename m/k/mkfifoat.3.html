mkfifo(3) Manual de Funciones de Librería mkfifo(3)

NOMBRE

mkfifo, mkfifoat - crear un archivo especial FIFO (tubería con nombre)

LIBRERÍA

Librería C estándar (libc, -lc)

SINOPSIS

#include <sys/types.h>
#include <sys/stat.h>
int mkfifo(const char *path, mode_t mode);
#include <fcntl.h>           /* Definición de constantes AT_* */
#include <sys/stat.h>
int mkfifoat(int dirfd, const char *path, mode_t mode);
Requisitos de Macros de Testeo de Características para glibc (ver feature_test_macros(7)):

mkfifoat():

    Desde glibc 2.10:
        _POSIX_C_SOURCE >= 200809L
    Antes de glibc 2.10:
        _ATFILE_SOURCE

DESCRIPCIÓN

mkfifo() crea un archivo especial FIFO con el nombre path. mode especifica los permisos del FIFO. Se modifica por la umask(2) del proceso de la forma habitual: los permisos del archivo creado son (mode & ~umask).

Un archivo especial FIFO es similar a una tubería, excepto que se crea de una forma diferente. En lugar de ser un canal de comunicación anónimo, se crea un archivo especial FIFO en el sistema de archivos llamando a mkfifo().

Una vez que se ha creado un archivo especial FIFO de esta forma, cualquier proceso puede abrirlo para lectura o escritura, de la misma forma que un archivo ordinario. Sin embargo, debe estar abierto en ambos extremos simultáneamente antes de poder proceder a realizar operaciones de entrada o salida en él. Abrir un FIFO para lectura normalmente se bloquea hasta que otro proceso abre el mismo FIFO para escritura, y viceversa. Ver fifo(7) para el manejo no bloqueante de archivos especiales FIFO.

mkfifoat()

La función mkfifoat() opera exactamente de la misma manera que mkfifo(), excepto por las diferencias descritas aquí.

Si path es relativo, entonces se interpreta en relación con el directorio al que se refiere el descriptor de archivo dirfd (en lugar de en relación con el directorio de trabajo actual del proceso que llama, como se hace con mkfifo() para un nombre de ruta relativo).

Si path es relativo y dirfd es el valor especial AT_FDCWD, entonces path se interpreta en relación con el directorio de trabajo actual del proceso que llama (como mkfifo()).

Si path es absoluto, entonces dirfd se ignora.

Ver openat(2) para una explicación de la necesidad de mkfifoat().

VALOR DE RETORNO

En caso de éxito, mkfifo() y mkfifoat() devuelven 0. En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

EACCES
Uno de los directorios en path no permitió permisos de búsqueda (ejecución).
EBADF
(mkfifoat()) path es relativo pero dirfd no es ni AT_FDCWD ni un descriptor de archivo válido.
EDQUOT
La cuota del usuario de bloques de disco o inodos en el sistema de archivos se ha agotado.
EEXIST
path ya existe. Esto incluye el caso en que path es un enlace simbólico, colgante o no.
ENAMETOOLONG
Ya sea que el tamaño total de path sea mayor que PATH_MAX, o que un componente de nombre de archivo individual tenga una longitud mayor que NAME_MAX. En el sistema GNU, no hay un límite impuesto en la longitud total del nombre de archivo, pero algunos sistemas de archivos pueden imponer límites a la longitud de un componente.
ENOENT
Un componente del directorio en path no existe o es un enlace simbólico colgante.
ENOSPC
Al directorio o sistema de archivos no le queda espacio para el nuevo archivo.
ENOTDIR
Un componente utilizado como directorio en path no es, de hecho, un directorio.
ENOTDIR
(mkfifoat()) path es relativo y dirfd es un descriptor de archivo que se refiere a un archivo que no es un directorio.
EROFS
path se refiere a un sistema de archivos de solo lectura.
