NOMBRE

mkfs.xfs - construir un sistema de archivos XFS

SINOPSIS

mkfs.xfs [ -b opciones_tamaño_bloque ] [ -c opciones_archivo_configuracion ] [ -m opciones_metadatos_globales ] [ -d opciones_seccion_datos ] [ -f ] [ -i opciones_inodos ] [ -l opciones_seccion_log ] [ -n opciones_nombres ] [ -p opciones_prototipo ] [ -q ] [ -r opciones_seccion_tiempo_real ] [ -s opciones_tamaño_sector ] [ -L etiqueta ] [ -N ] [ -K ] dispositivo
mkfs.xfs -V

DESCRIPCIÓN

mkfs.xfs construye un sistema de archivos XFS escribiendo en un archivo especial usando los valores encontrados en los argumentos de la línea de comandos. Es invocado automáticamente por mkfs(8) cuando se le da la opción -t xfs.

En su forma más simple (y más comúnmente usada), el tamaño del sistema de archivos se determina desde el controlador del disco. Como ejemplo, para crear un sistema de archivos con un log interno en la primera partición del primer disco SCSI, use:

mkfs.xfs /dev/sda1

El log de metadatos puede colocarse en otro dispositivo para reducir el número de búsquedas de disco. Para crear un sistema de archivos en la primera partición del primer disco SCSI con un log de 100MiB ubicado en la primera partición del segundo disco SCSI, use:

mkfs.xfs -l logdev=/dev/sdb1,size=100m /dev/sda1

Cada uno de los elementos de opción en la lista de argumentos anterior puede ser dado como múltiples subopciones separadas por comas si múltiples subopciones se aplican a la misma opción. De manera equivalente, cada opción principal puede ser dada múltiples veces con diferentes subopciones. Por ejemplo, -l internal,size=100m y -l internal -l size=100m son equivalentes.

En las descripciones a continuación, los tamaños se dan en sectores, bytes, bloques, kilobytes, megabytes, gigabytes, etc. Los tamaños se tratan como hexadecimales si van precedidos por 0x o 0X, octales si van precedidos por 0, o decimales en caso contrario. Las siguientes listas de sufijos de multiplicación posibles:

s - multiplicar por el tamaño del sector (por defecto = 512, ver opción -s abajo).

b - multiplicar por el tamaño del bloque del sistema de archivos (por defecto = 4K, ver opción -b abajo).

k - multiplicar por un kilobyte (1,024 bytes).

m - multiplicar por un megabyte (1,048,576 bytes).

g - multiplicar por un gigabyte (1,073,741,824 bytes).

t - multiplicar por un terabyte (1,099,511,627,776 bytes).

p - multiplicar por un petabyte (1,024 terabytes).

e - multiplicar por un exabyte (1,048,576 terabytes).

Al especificar parámetros en unidades de sectores o bloques del sistema de archivos, la opción -s o la opción -b pueden usarse para especificar el tamaño del sector o bloque. Si el tamaño del bloque o sector no se especifica, se usarán los tamaños por defecto (bloque: 4KiB, sector: 512B).

Muchas opciones de funcionalidad permiten un argumento opcional de 0 o 1, para deshabilitar o habilitar explícitamente la funcionalidad.

La corrección de la implementación de la suma de verificación crc32c se probará antes de formatear el sistema de archivos. Si la prueba falla, el formato se abortará.

OPCIONES

Las opciones pueden especificarse tanto en la línea de comandos como en un archivo de configuración. No todas las opciones de la línea de comandos se pueden especificar en archivos de configuración; solo las opciones de la línea de comandos seguidas de una etiqueta [sección] se pueden usar en un archivo de configuración.

Las opciones que se pueden usar en archivos de configuración se agrupan en secciones relacionadas que contienen múltiples opciones. Las opciones de línea de comandos y los archivos de configuración utilizan las mismas secciones y agrupaciones de opciones. Los nombres de las secciones de archivos de configuración se enumeran en las secciones de opciones de la línea de comandos a continuación. Los nombres de las opciones y los valores son los mismos para la especificación en línea de comandos y en archivo de configuración.

Las opciones especificadas son el conjunto combinado de parámetros de la línea de comandos y parámetros del archivo de configuración. Las opciones duplicadas resultarán en un error de reposición, independientemente de dónde se especificaron.

-c opción_archivo_configuracion
Esta opción especifica los archivos de los que se obtendrán las opciones de configuración de mkfs. La opción_archivo_configuracion válida es:
opciones=nombre
Las opciones de configuración se obtendrán del archivo especificado por la cadena de opción nombre. Esta opción puede usar una ruta absoluta o relativa al archivo de configuración a leer. Los archivos de configuración de ejemplo se pueden encontrar en /usr/share/xfsprogs/mkfs.

-b opciones_tamaño_bloque

Nombre de sección: [bloque]
Esta opción especifica el tamaño de bloque fundamental del sistema de archivos. La opción_tamaño_bloque válida es:
tamano=valor
El tamaño del bloque del sistema de archivos se especifica con un valor en bytes. El valor por defecto es 4096 bytes (4 KiB), el mínimo es 512 y el máximo es 65536 (64 KiB).
Aunque mkfs.xfs aceptará cualquiera de estos valores y creará un sistema de archivos válido, XFS en Linux solo puede montar sistemas de archivos con bloques del tamaño de página o menores.

-m opciones_metadatos_globales

Nombre de sección: [metadatos]
Estas opciones especifican opciones de formato de metadatos que se aplican a todo el sistema de archivos o que no se caracterizan fácilmente por un grupo de funcionalidad específico. Las opciones_metadatos_globales válidas son:
bigtime=valor
Esta opción habilita sistemas de archivos que pueden manejar marcas de tiempo de inodo desde diciembre de 1901 hasta julio de 2486, y expiraciones de temporizadores de cuotas desde enero de 1970 hasta julio de 2486. El valor es 0 para deshabilitar la función, o 1 para habilitar marcas de tiempo grandes.
Si esta función no está habilitada, el sistema de archivos solo puede manejar marcas de tiempo desde diciembre de 1901 hasta enero de 2038, y temporizadores de cuotas desde enero de 1970 hasta febrero de 2106.
Por defecto, mkfs.xfs habilitará esta función. Si se usa la opción -m crc=0, la función de marca de tiempo grande no es compatible y se deshabilita.
crc=valor
Se utiliza para crear un sistema de archivos que mantiene y verifica información CRC en todos los objetos de metadatos en disco. El valor es 0 para deshabilitar la función, o 1 para habilitar el uso de CRCs.
Los CRC permiten una detección mejorada de errores debido a problemas de hardware, mientras que los cambios en el formato también mejoran los algoritmos de recuperación de fallos y la capacidad de varias herramientas para validar y reparar corrupciones de metadatos cuando se encuentran. El algoritmo CRC utilizado es CRC32c, por lo que la sobrecarga depende de la arquitectura de la CPU, ya que algunas CPUs tienen aceleración de hardware para este algoritmo. Típicamente, la sobrecarga de calcular y verificar los CRC no se nota en la operación normal.
Por defecto, mkfs.xfs habilitará los CRC de metadatos.
Formatear un sistema de archivos sin CRC selecciona el formato V4, que está obsoleto y se eliminará de upstream en septiembre de 2030. Los distribuidores pueden optar por retirar el soporte para el formato V4 antes de esta fecha. Varias otras opciones, señaladas a continuación, solo son configurables en formatos V4 y se eliminarán junto con el formato V4.
finobt=valor
Esta opción habilita el uso de un árbol B separado de inodos libres en cada grupo de asignación. El valor es 0 para deshabilitar la función, o 1 para crear un árbol B de inodos libres en cada grupo de asignación.
El árbol B de inodos libres refleja el índice del árbol B de inodos asignados existente, que indexa tanto los inodos utilizados como los libres. El árbol B de inodos libres no indexa u
sed inodes, permitiendo una asignación de inodos más rápida y consistente rendimiento a medida que los sistemas de archivos envejecen.
Por defecto, mkfs.xfs creará árboles b de inodos libres para sistemas de archivos creados con la opción (predeterminada) -m crc=1. Cuando se utiliza la opción -m crc=0, la función de árbol b de inodos libres no se admite y se deshabilita.
inobtcount=valor
Esta opción hace que el sistema de archivos registre el número de bloques utilizados por el árbol b de inodos y el árbol b de inodos libres. Esto puede usarse para reducir los tiempos de montaje cuando el árbol b de inodos libres está habilitado.
Por defecto, mkfs.xfs habilitará esta opción. Esta función solo está disponible para sistemas de archivos creados con la opción (predeterminada) -m finobt=1. Cuando se utiliza la opción -m finobt=0, la función de contador de árboles b de inodos no se admite y se deshabilita.
metadir=valor
Esta opción crea un árbol de directorios interno para almacenar los metadatos del sistema de archivos.
Por defecto, mkfs.xfs no habilitará esta función. Si se utiliza la opción -m crc=0, la función de directorio de metadatos no se admite y se deshabilita.
uuid=valor
Utiliza el valor proporcionado como UUID del sistema de archivos para el nuevo sistema de archivos creado. El valor predeterminado es generar un UUID aleatorio.
rmapbt=valor
Esta opción habilita la creación de un índice de árbol b de mapeo inverso en cada grupo de asignación. El valor es 0 para deshabilitar la función o 1 para crear el árbol b.
El árbol b de mapeo inverso mapea los bloques del sistema de archivos al propietario del bloque del sistema de archivos. La mayoría de los mapeos serán a un número de inodo y un desplazamiento, aunque también habrá mapeos a metadatos del sistema de archivos. Estos metadatos secundarios pueden usarse para validar los metadatos primarios o para identificar exactamente qué datos se han perdido cuando ocurre un error de disco.
Por defecto, mkfs.xfs creará árboles b de mapeo inverso cuando sea posible. Esta función solo está disponible para sistemas de archivos creados con la opción (predeterminada) -m crc=1. Cuando se utiliza la opción -m crc=0, la función de árbol b de mapeo inverso no se admite y se deshabilita.
reflink=valor
Esta opción habilita el uso de un índice de árbol b de recuento de referencias separado en cada grupo de asignación. El valor es 0 para deshabilitar la función o 1 para crear un árbol b de recuento de referencias en cada grupo de asignación.
El árbol b de recuento de referencias habilita el intercambio de extents físicos entre las bifurcaciones de datos de diferentes archivos, lo que comúnmente se conoce como "reflink". A diferencia de los sistemas de archivos Unix tradicionales que suponen que cada par de inodo y bloque lógico se mapea a un bloque físico único, un sistema de archivos XFS compatible con reflink elimina el requisito de unicidad, permitiendo que hasta cuatro mil millones de pares arbitrarios de inodo/bloque lógico se mapeen a un bloque físico. Si un programa intenta escribir en un bloque con múltiples referencias en un archivo, la escritura se redirigirá a un nuevo bloque, y el mapeo lógico a físico de ese archivo se cambiará al nuevo bloque ("copia en escritura"). Esta función permite la creación de instantáneas por archivo y la deduplicación. Solo está disponible para las bifurcaciones de datos de archivos regulares.
Por defecto, mkfs.xfs creará árboles b de recuento de referencias y, por lo tanto, habilitará la función reflink. Esta función solo está disponible para sistemas de archivos creados con la opción (predeterminada) -m crc=1. Cuando se utiliza la opción -m crc=0, la función de árbol b de recuento de referencias no se admite y reflink se deshabilita.
autofsck=valor
Establece la propiedad del sistema de archivos autofsck a este valor. Ver la página del manual de xfs_scrub(8) para más información sobre esta propiedad.
uquota
Si la función de directorio de metadatos está habilitada, la opción -m uquota configurará la contabilidad y la aplicación de cuotas de usuario en el momento del formateo; especificar las opciones de cuota en fstab ya no será necesario. Si los directorios de metadatos no están habilitados, las cuotas aún deben habilitarse a través de fstab.
gquota
Si la función de directorio de metadatos está habilitada, la opción -m gquota configurará la contabilidad y la aplicación de cuotas de grupo en el momento del formateo; especificar las opciones de cuota en fstab ya no será necesario. Si los directorios de metadatos no están habilitados, las cuotas aún deben habilitarse a través de fstab.
pquota
Si la función de directorio de metadatos está habilitada, la opción -m pquota configurará la contabilidad y la aplicación de cuotas de proyecto en el momento del formateo; especificar las opciones de cuota en fstab ya no será necesario. Si los directorios de metadatos no están habilitados, las cuotas aún deben habilitarse a través de fstab.
uqnoenforce
Si la función de directorio de metadatos está habilitada, la opción -m uqnoenforce configurará la contabilidad de cuotas de usuario en el momento del formateo; especificar las opciones de cuota en fstab ya no será necesario. Si los directorios de metadatos no están habilitados, las cuotas aún deben habilitarse a través de fstab.
gqnoenforce
Si la función de directorio de metadatos está habilitada, la opción -m gqnoenforce configurará la contabilidad de cuotas de grupo en el momento del formateo; especificar las opciones de cuota en fstab ya no será necesario. Si los directorios de metadatos no están habilitados, las cuotas aún deben habilitarse a través de fstab.
pqnoenforce
Si la función de directorio de metadatos está habilitada, la opción -m pqnoenforce configurará la contabilidad de cuotas de proyecto en el momento del formateo; especificar las opciones de cuota en fstab ya no será necesario. Si los directorios de metadatos no están habilitados, las cuotas aún deben habilitarse a través de fstab.

-d opciones_seccion_datos

Nombre de Sección: [datos]
Estas opciones especifican la ubicación, el tamaño y otros parámetros de la sección de datos del sistema de archivos. Las opciones_seccion_datos válidas son:
agcount=valor
Esto se utiliza para especificar el número de grupos de asignación. La sección de datos del sistema de archivos se divide en grupos de asignación para mejorar el rendimiento de XFS. Más grupos de asignación implican que se puede lograr más paralelismo al asignar bloques e inodos. El tamaño mínimo del grupo de asignación es de 16 MiB; el tamaño máximo es de poco menos de 1 TiB. La sección de datos del sistema de archivos se divide en valor grupos de asignación (el valor predeterminado se escala automáticamente según el tamaño del dispositivo subyacente).
agsize=valor
Esto es una alternativa a usar la subopción agcount. El valor es el tamaño deseado del grupo de asignación expresado en bytes (generalmente usando los sufijos m o g). Este valor debe ser un múltiplo del tamaño de bloque del sistema de archivos, y debe ser al menos 16MiB, y no más de 1TiB, y puede ajustarse automáticamente para alinearse correctamente con la geometría de la franja. Las subopciones agcount y agsize son mutuamente excluyentes.
cowextsize=valor
Establece la pista de tamaño de extent de copia en escritura en todos los inodos creados por mkfs.xfs. El valor debe proporcionarse en unidades de bloques del sistema de archivos. Si el valor es cero, se usará el valor predeterminado (actualmente 32 bloques). Los directorios pasarán esta pista a los archivos y directorios regulares recién creados.
name=valor
Esto se puede usar para especificar el nombre del archivo especial que contiene el sistema de archivos. En este caso, la sección de registro debe especificarse como internal (con un tamaño, ver la opción -l a continuación) y no puede haber sección de tiempo real.
file[=valor]
Esto se utiliza para especificar que el archivo dado por la subopción name es un archivo regular. El valor es 0 o 1, siendo 1 la señal de que el archivo es regular. Esta subopción solo se utiliza para crear una imagen de sistema de archivos. Si se omite el valor, se asume 1.
size=valor
Esto se utiliza para especificar el tamaño de la sección de datos. Esta subopción es obligatoria si se da -d file[=1]. De lo contrario, solo es necesaria si el sistema de archivos debe ocupar menos espacio que el tamaño del archivo especial.

La sección de datos debe tener al menos 300MB de tamaño.

sunit=valor
Esto se utiliza para especificar la unidad de franja para un dispositivo RAID o un volumen lógico. El valor debe especificarse en unidades de bloques de 512 bytes. Use la subopción su para especificar el tamaño de la unidad de franja en bytes. Esta subopción garantiza que las asignaciones de datos estarán alineadas con la unidad de franja cuando se extienda el final del archivo actual y el tamaño del archivo sea mayor que 512KiB. Las asignaciones de inodos y el registro interno también estarán alineados con la unidad de franja.
su=valor
Esto es una alternativa a usar sunit. La subopción su se utiliza para especificar la unidad de franja para un dispositivo RAID o un volumen lógico con franjas. El valor debe especificarse en bytes (generalmente usando los sufijos m o g). Este valor debe ser un múltiplo del tamaño de bloque del sistema de archivos.
swidth=valor
Esto se utiliza para especificar el ancho de franja para un dispositivo RAID o un volumen lógico con franjas. El valor debe especificarse en unidades de bloques de 512 bytes. Use la subopción sw para especificar el tamaño del ancho de franja en bytes. Esta subopción es obligatoria si se ha especificado -d sunit y debe ser un múltiplo de la subopción -d sunit.

ogdev=device
Esto se utiliza para especificar que la sección de registro debe residir en el dispositivo separado de la sección de datos. Las opciones internal=1 y logdev son mutuamente excluyentes.
size=valor
Esto se utiliza para especificar el tamaño de la sección de registro.
Si el registro está contenido dentro de la sección de datos y size no está especificado, mkfs.xfs intentará seleccionar un tamaño de registro adecuado dependiendo del tamaño del sistema de archivos. El tamaño real del registro depende del tamaño de bloque del sistema de archivos y del tamaño de bloque del directorio.
De lo contrario, la subopción size solo es necesaria si la sección de registro del sistema de archivos debe ocupar menos espacio que el tamaño del archivo especial. El valor se especifica en bytes o bloques, con un sufijo b que significa multiplicación por el tamaño de bloque del sistema de archivos, como se describió anteriormente. El valor mínimo que anula los demás es de 512 bloques. Con algunas combinaciones de tamaño de bloque del sistema de archivos, tamaño de inodo y tamaño de bloque del directorio, el tamaño mínimo del registro es mayor que 512 bloques.

El registro debe tener al menos 64 MB de tamaño. El registro no puede tener más de 2 GB de tamaño.

version=valor
Esto especifica la versión del registro. El valor predeterminado actual es 2, lo que permite tamaños de búfer de registro más grandes, además de admitir escrituras de registro alineadas con la franja (consulte las opciones sunit y su, a continuación).
La versión anterior 1, que está limitada a búferes de registro de 32k y no admite escrituras alineadas con franjas, se mantiene para compatibilidad con versiones anteriores con kernels 2.4 muy antiguos.
Esta opción solo se puede ajustar en el formato V4 obsoleto.
sunit=valor
Esto especifica la alineación que se utilizará para las escrituras de registro. El valor debe especificarse en unidades de bloque de 512 bytes. Utilice la subopción su para especificar el tamaño de la unidad de franja de registro en bytes. Las escrituras de registro se alinearán en este límite y se redondearán hacia arriba a este límite. Esto proporciona mejoras importantes en el rendimiento en algunas configuraciones, como RAID5 de software, cuando se especifica sunit como el tamaño de bloque del sistema de archivos. El valor de byte equivalente debe ser un múltiplo del tamaño de bloque del sistema de archivos. Los registros de versión 2 se seleccionan automáticamente si se especifica la subopción sunit del registro.
La subopción su es una alternativa al uso de sunit.
su=valor
Esto se utiliza para especificar la franja del registro. El valor debe especificarse en bytes (generalmente usando los sufijos s o b). Este valor debe ser un múltiplo del tamaño de bloque del sistema de archivos. Los registros de versión 2 se seleccionan automáticamente si se especifica la subopción su del registro.
lazy-count=valor
Esto cambia el método de registro de varios contadores persistentes en el superbloque. Bajo cargas de trabajo intensivas en metadatos, estos contadores se actualizan y registran con suficiente frecuencia como para que las actualizaciones del superbloque se conviertan en un punto de serialización en el sistema de archivos. El valor puede ser 0 o 1.
Con lazy-count=1, el superbloque no se modifica ni se registra en cada cambio de los contadores persistentes. En su lugar, se mantiene suficiente información en otras partes del sistema de archivos para poder mantener los valores de los contadores persistentes sin necesidad de mantenerlos en el superbloque. Esto proporciona mejoras significativas en el rendimiento en algunas configuraciones. El valor predeterminado es 1 (activado), por lo que debe especificar lazy-count=0 si desea desactivar esta función para kernels más antiguos que no la admiten.
Esta opción solo se puede ajustar en el formato V4 obsoleto.
concurrency=valor
Asigna un registro que se estima que es lo suficientemente grande como para manejar el nivel deseado de concurrencia sin que los hilos del programa de espacio de usuario compitan por el espacio del registro. Este esquema no creará un registro más pequeño que el mínimo requerido, ni un registro más grande que el máximo posible. Esta opción solo es válida para registros internos y no es compatible con la opción size. Esta opción no es compatible con las opciones logdev o size. El valor mágico nr_cpus o 1 o ningún valor en absoluto establecerá este parámetro al número de procesadores activos en el sistema.

-n opciones_de_nomenclatura

Nombre de sección: [nomenclatura]
Estas opciones especifican la versión y los parámetros de tamaño para el área de nomenclatura (directorio) del sistema de archivos. Las opciones_de_nomenclatura válidas son:
size=valor
El tamaño del bloque del directorio se especifica con un valor en bytes. El tamaño del bloque debe ser una potencia de 2 y no puede ser menor que el tamaño del bloque del sistema de archivos. El valor predeterminado del tamaño valor para los directorios de versión 2 es 4096 bytes (4 KiB), a menos que el tamaño del bloque del sistema de archivos sea mayor que 4096, en cuyo caso el valor predeterminado es el tamaño del bloque del sistema de archivos. Para los directorios de versión 1, el tamaño del bloque es el mismo que el tamaño del bloque del sistema de archivos.
version=valor
El valor de la versión de nomenclatura (directorio) valor puede ser 2 o 'ci', con un valor predeterminado de 2 si no se especifica. Con los directorios de versión 2, el tamaño del bloque del directorio puede ser cualquier potencia de 2 desde el tamaño del bloque del sistema de archivos hasta 65536.
Si se especifica la opción version=ci, el kernel transformará ciertos bytes en los nombres de archivo antes de realizar operaciones relacionadas con la búsqueda. La secuencia de bytes dada para crear una entrada de directorio se mantiene sin alteraciones. Las transformaciones de búsqueda se definen de la siguiente manera:


0x41-0x5a -> 0x61-0x7a


0xc0-0xd6 -> 0xe0-0xf6


0xd8-0xde -> 0xf8-0xfe

Esta transformación corresponde aproximadamente a la insensibilidad a mayúsculas y minúsculas en ISO 8859-1. Las transformaciones no son compatibles con otras codificaciones (por ejemplo, UTF8). No habilite esta función a menos que todo su entorno haya sido forzado a ISO 8859-1. Esta función está obsoleta y se eliminará en septiembre de 2030.

Nota: Los directorios de versión 1 no son compatibles.
ftype=valor
Esta función permite que el tipo de inodo se almacene en la estructura del directorio para que readdir(3) y getdents(2) no necesiten buscar el inodo para determinar el tipo de inodo.

El valor es 0 o 1, donde 1 significa que la información del tipo de archivo se almacenará en la estructura del directorio. El valor predeterminado es 1.

Cuando las sumas de verificación (CRCs) están habilitadas (predeterminado), la funcionalidad ftype siempre está habilitada y no se puede desactivar.

En otras palabras, esta opción solo se puede ajustar en el formato V4 obsoleto.
parent=valor
Esta función crea referencias inversas desde archivos hijos a directorios padres para que la reparación en línea pueda reconstruir archivos de directorio rotos. El valor es 0 para desactivar la función o 1 para crear punteros padre.

Por defecto, mkfs.xfs no creará punteros padre. Esta función solo está disponible para sistemas de archivos creados con la opción (predeterminada) -m crc=1 establecida.

-p opciones_prototipo
Nombre de sección: [proto]
Estas opciones especifican los parámetros del prototipo para poblar el sistema de archivos. Las opciones_prototipo válidas son:
[file=]
El prefijo file= no es necesario para este argumento de línea de comandos por razones de compatibilidad. Si se especifica como una directiva de archivo de configuración, se requiere el prefijo.
[file=]directorio
Si se proporciona el argumento opcional prototipo, y es un directorio, mkfs.xfs poblará el sistema de archivos raíz con el contenido del árbol de directorios dado. El contenido, las marcas de tiempo (atime, mtime), los atributos y los atributos extendidos se conservan para todos los tipos de archivo.
[file=]archivo_prototipo
Si se proporciona el argumento opcional prototipo y apunta a un archivo regular, mkfs.xfs lo utiliza como archivo prototipo y toma sus directivas de ese archivo. Los especificadores de bloques e inodos en el archivo_prototipo se proporcionan para compatibilidad con versiones anteriores, pero de lo contrario no se utilizan. La sintaxis del archivo prototipo se define por una serie de tokens separados por espacios o saltos de línea. Tenga en cuenta que los números de línea no forman parte de la sintaxis, sino que están destinados a ayudarle en la siguiente discusión del contenido del archivo. 
1       /stand/diskboot
2       4872 110
3       d--777 3 1
4       usr     d--777 3 1
5       sh      ---755 3 1 /bin/sh
6       ken     d--755 6 1
7               $
8       b0      b--644 3 1 0 0
9       c0      c--644 3 1 0 0
10      fifo    p--644 3 1
11      slink   l--644 3 1 /a/symbolic/link
12      :  Esto es una línea de comentario
13      $
14      $
La línea 1 es una cadena ficticia. (Anteriormente era el nombre del archivo de arranque). Está presente para compatibilidad con versiones anteriores: los bloques de arranque no se utilizan en los sistemas SGI.
Tenga en cuenta que alguna cadena de caracteres debe estar presente como la primera línea del archivo prototipo para que se analice correctamente; el valor de esta cadena es irrelevante ya que se ignora.
La línea 2 contiene dos valores numéricos (anteriormente los números de bloques e inodos). Estos también son solo para compatibilidad con versiones anteriores: deben aparecer dos valores numéricos en este punto para que el archivo prototipo se analice correctamente, pero sus valores son irrelevantes ya que se ignoran.
Las líneas 3 a 11 especifican los archivos y directorios que desea incluir en este sistema de archivos. La línea 3 define el directorio raíz. Otros directorios y archivos que desea en el sistema de archivos se indican en las líneas 4 a 6 y 8 a 10. La línea 11 contiene la sintaxis de enlace simbólico.
Observe el signo de dólar ($) en la línea 7. Es
s syntax dirige el comando mkfs.xfs a terminar la rama del sistema de archivos en la que se encuentra actualmente y luego continuar desde el directorio especificado por la siguiente línea, en este caso la línea 8. Debe ser el último carácter de una línea. El dos puntos en la línea 12 introduce un comentario; todos los caracteres hasta el siguiente salto de línea se ignoran. Tenga en cuenta que esto significa que no puede tener un archivo en un archivo prototipo cuyo nombre contenga dos puntos. El $ en las líneas 13 y 14 finalizan el proceso, ya que no hay especificaciones adicionales que sigan.
Las especificaciones de archivo proporcionan lo siguiente:

* modo de archivo
* ID de usuario
* ID de grupo
* el contenido inicial del archivo
Una cadena de 6 caracteres define el modo para un archivo. El primer carácter de esta cadena define el tipo de archivo. El rango de caracteres para este primer carácter es -bcdpl. Un archivo puede ser un archivo regular, un archivo especial de bloque, un archivo especial de carácter, archivos de directorio, tuberías con nombre (colas FIFO) y enlaces simbólicos. El segundo carácter de la cadena de modo se utiliza para especificar el modo setuserID, en cuyo caso es u. Si no se especifica el modo setuserID, el segundo carácter es -. El tercer carácter de la cadena de modo se utiliza para especificar el modo setgroupID, en cuyo caso es g. Si no se especifica el modo setgroupID, el tercer carácter es -. Los caracteres restantes de la cadena de modo son un número octal de tres dígitos. Este número octal define respectivamente los permisos de lectura, escritura y ejecución del propietario, grupo y otros para el archivo. Para obtener más información sobre los permisos de archivo, consulte el comando chmod(1).
Después de la cadena de caracteres de modo, hay dos tokens numéricos decimales que especifican los IDs de usuario y grupo del propietario del archivo.
En un archivo regular, el siguiente token especifica la ruta de acceso desde la cual se copian el contenido y el tamaño del archivo. En un archivo especial de bloque o carácter, el siguiente token son dos números decimales que especifican los números de dispositivo principal y secundario. Cuando un archivo es un enlace simbólico, el siguiente token especifica el contenido del enlace.

Cuando el archivo es un directorio, el comando mkfs.xfs crea las entradas . (punto) y .. (punto-punto) y luego lee la lista de nombres y especificaciones de archivo de manera recursiva para todas las entradas del directorio. Un escaneo del archivo prototipo siempre termina con el token de dólar ($).

atime=valor
Si se establece en 1, mkfs copiará las marcas de tiempo de acceso de los archivos de origen. De lo contrario, las marcas de tiempo de acceso se establecerán en la hora actual.
slashes_are_spaces=valor
Si se establece en 1, las barras ("/") en el primer token de cada línea del archivo prototipo se convierten en espacios. Esto permite la creación de un sistema de archivos que contenga nombres de archivo con espacios. Por defecto, este valor es 0.
-q
Opción silenciosa. Normalmente mkfs.xfs imprime los parámetros del sistema de archivos a construir; la bandera -q suprime esto.

-r opciones_seccion_tiempo_real

Nombre de Sección: [tiempo_real]
Estas opciones especifican la ubicación, el tamaño y otros parámetros de la sección de tiempo real del sistema de archivos. Las opciones_seccion_tiempo_real válidas son:
rtdev=dispositivo
Esto se utiliza para especificar el dispositivo que debe contener la sección de tiempo real del sistema de archivos. El valor de la subopción es el nombre de un dispositivo de bloque.
extsize=valor
Esto se utiliza para especificar el tamaño de los bloques en la sección de tiempo real del sistema de archivos. Este valor debe ser un múltiplo del tamaño de bloque del sistema de archivos. El tamaño mínimo permitido es el tamaño de bloque del sistema de archivos o 4 KiB (el que sea mayor); el tamaño predeterminado es el ancho de banda de los volúmenes distribuidos o 64 KiB para volúmenes no distribuidos; el tamaño máximo permitido es 1 GiB. El tamaño de extensión de tiempo real debe elegirse cuidadosamente para que coincida con los parámetros de los medios físicos utilizados.
size=valor
Esto se utiliza para especificar el tamaño de la sección de tiempo real. Esta subopción solo es necesaria si la sección de tiempo real del sistema de archivos debe ocupar menos espacio que el tamaño de la partición o el volumen lógico que contiene la sección.
noalign
Esta opción deshabilita la detección del tamaño de banda, forzando un dispositivo en tiempo real sin geometría de banda.
rgcount=valor
Esto se utiliza para especificar el número de grupos de asignación en la sección de tiempo real. La sección de tiempo real del sistema de archivos puede dividirse en grupos de asignación para mejorar el rendimiento de XFS. Más grupos de asignación implican que se puede lograr más paralelismo al asignar bloques. El tamaño mínimo del grupo de asignación es de 2 extensiones de tiempo real; el tamaño máximo es de 2^31 bloques. La sección rt del sistema de archivos se divide en valor grupos de asignación (el valor predeterminado se escala automáticamente según el tamaño del dispositivo subyacente).
rgsize=valor
Esto es una alternativa al uso de la subopción rgcount. El valor es el tamaño deseado del grupo de asignación de tiempo real expresado en bytes (generalmente usando los sufijos m o g). Este valor debe ser un múltiplo del tamaño de extensión de tiempo real, debe ser al menos dos extensiones de tiempo real, y no más de 2^31 bloques. Las subopciones rgcount y rgsize son mutuamente excluyentes.
concurrency=valor
Cree suficientes grupos de asignación de tiempo real para manejar el nivel deseado de concurrencia. El objetivo de este esquema de cálculo es establecer el número de rtgroups en un múltiplo entero del número de hilos de escritura deseados, para minimizar la contención de los bloqueos de rtgroup. Este esquema no creará menos rtgroups de los que se crearían con la configuración predeterminada, ni creará rtgroups más pequeños que 4 GB. Esta opción no es compatible con las opciones rgcount o rgsize. El valor mágico nr_cpus o 1 o ningún valor en absoluto establecerá este parámetro al número de procesadores activos en el sistema. Si el kernel anuncia que el dispositivo de tiempo real es un dispositivo de almacenamiento no mecánico, mkfs.xfs utilizará este nuevo esquema de cálculo de geometría. El valor mágico de 0 fuerza el uso de los esquemas de cálculo de rtgroups más antiguos que se utilizan para el almacenamiento mecánico.
zoned=valor
Controla si el asignador zonificado se utiliza para el dispositivo de tiempo real. El valor es 0 para deshabilitar la función, o 1 para habilitarla. Por defecto es 1 para dispositivos de bloque zonificados, de lo contrario 0.
start=valor
Controla el inicio de la sección interna de tiempo real. Por defecto es 0 para dispositivos de bloque convencionales, o el inicio de la primera zona secuencial requerida para dispositivos de bloque zonificados. Esta opción solo es válida si se utiliza el asignador de tiempo real zonificado.
reserved=valor
Controla la cantidad de espacio en la sección de tiempo real que se reserva para uso interno por los algoritmos de recolección de basura y reorganización. Por defecto es 0 si no se establece. Esta opción solo es válida si se utiliza el asignador de tiempo real zonificado.

-s opciones_tamaño_sector

Nombre de Sección: [tamaño_sector]
Esta opción especifica el tamaño fundamental del sector del sistema de archivos. La opción_tamaño_sector válida es:
size=valor
El tamaño del sector se especifica con un valor en bytes. El tamaño_sector predeterminado es de 512 bytes. El valor mínimo para el tamaño del sector es 512; el máximo es 32768 (32 KiB). El tamaño_sector debe ser una potencia de 2 y no puede ser mayor que el tamaño de bloque del sistema de archivos.
-L etiqueta
Establece la etiqueta del sistema de archivos. Las etiquetas de sistema de archivos XFS pueden tener como máximo 12 caracteres; si etiqueta tiene más de 12 caracteres, mkfs.xfs no procederá con la creación del sistema de archivos. Consulte las entradas del manual mount(8) y xfs_admin(8) para obtener información adicional.
-N
Hace que se impriman los parámetros del sistema de archivos sin crear realmente el sistema de archivos.
-K
No intente descartar bloques en el momento de mkfs.
-V
Imprime el número de versión y sale.

Formato del Archivo de Configuración

El archivo de configuración utiliza un formato INI básico para especificar secciones y opciones dentro de una sección. Los nombres de sección y opción distinguen entre mayúsculas y minúsculas. Los nombres de sección no deben contener espacios en blanco. Las opciones son pares nombre-valor, terminados por el primer espacio en blanco de la línea. Los nombres de opción no pueden contener espacios en blanco. Los comentarios de línea completa se pueden agregar comenzando una línea con un símbolo #. Si los valores contienen espacios en blanco, deben estar entre comillas.

El siguiente archivo de configuración de ejemplo establece el tamaño de bloque en 4096 bytes, activa los btrees de mapeo inverso y establece el tamaño de inodo en 2048 bytes.

# Archivo de configuración de ejemplo mkfs.xfs

[bloque]

tamaño=4k

[metadatos]

rmapbt=1

[inodo]

tamaño=2048
