MKVMERGE(1) Comandos de usuario MKVMERGE(1)

NOMBRE

mkvmerge - Fusiona flujos multimedia en un archivo Matroska(TM)

SINOPSIS

mkvmerge [opciones_globales] {-o salida} [opciones1] {archivo1} [[opciones2] {archivo2}] [@archivo-opciones.json]

DESCRIPCIÓN

Este programa toma la entrada de varios archivos multimedia y une sus flujos (todos o solo una selección) en un archivo Matroska(TM); ver el sitio web de Matroska(TM)[1].


Importante

El orden de las opciones de la línea de comandos es importante. Por favor, lea la sección "Orden de las opciones" si es nuevo en el programa.

Opciones globales

-v, --verbose

Aumenta la verbosidad.

-q, --quiet

Suprime la salida de estado.

-o, --output nombre-archivo

Escribe en el archivo nombre-archivo. Si se utiliza la división, este parámetro se trata de manera un poco diferente. Consulte la explicación de la opción --split para más detalles.

-w, --webm

Crea un archivo compatible con WebM. Esto también se activa si la extensión del nombre del archivo de salida es "webm". Este modo impone varias restricciones. Los únicos códecs permitidos son VP8, VP9 para video y Opus, Vorbis para audio. El elemento de encabezado DocType se cambia a "webm".

Para capítulos y etiquetas solo se permite un subconjunto de elementos. mkvmerge(1) eliminará automáticamente todos los elementos que no estén permitidos por la especificación.

--title título

Establece el título general para el archivo de salida, por ejemplo, el nombre de la película.

--default-language código-idioma

Establece el código de idioma predeterminado que se utilizará para las pistas para las que no se ha establecido un idioma con la opción --language y para las que el contenedor de origen no proporciona un idioma.

El código de idioma predeterminado es 'und' para 'indeterminado'.

Manejo de información de segmento (opciones globales)

--segmentinfo nombre-archivo.xml

Lee la información del segmento de un archivo XML. Este archivo puede contener los elementos UID de familia del segmento, UID del segmento, UID del segmento anterior y UID del segmento siguiente. Un archivo de ejemplo y un DTD se incluyen en la distribución de MKVToolNix.

Consulte la sección sobre archivos XML de información de segmento para obtener más detalles.

--segment-uid SID1,SID2,...

Establece los UID de segmento a utilizar. Esta es una lista separada por comas de UID de segmento de 128 bits en la forma habitual de UID: números hexadecimales con o sin el prefijo "0x", con o sin espacios, exactamente 32 dígitos.

Si SID comienza con = entonces su resto se interpreta como el nombre de un archivo Matroska cuyo UID de segmento se lee y se utiliza.

Cada archivo creado contiene un segmento, y cada segmento tiene un UID de segmento. Si se especifican más UID de segmento de los que se crean, los UID sobrantes se ignorarán. Si se especifican menos UID de los que se crean, se crearán UID aleatorios para ellos.

Manejo de capítulos y etiquetas (opciones globales)

--chapter-language código-idioma

Establece el código de idioma ISO 639-2 que se escribe para cada entrada de capítulo. Por defecto es 'eng'. Consulte la sección sobre capítulos para obtener más detalles.

Esta opción se puede utilizar tanto para archivos de capítulos simples como para archivos de origen que contienen capítulos pero sin información sobre el idioma de los capítulos, por ejemplo, archivos MP4 y OGM.

El idioma establecido con esta opción también se utiliza cuando se generan capítulos con la opción --generate-chapters.

--chapter-charset juego-de-caracteres

Establece el juego de caracteres que se utiliza para la conversión a UTF-8 para archivos de capítulos simples. Consulte la sección sobre archivos de texto y juegos de caracteres para obtener una explicación de cómo mkvmerge(1) realiza la conversión entre juegos de caracteres.

Este interruptor también se aplica a los capítulos que se copian de ciertos tipos de contenedores, por ejemplo, archivos Ogg/OGM y MP4. Consulte la sección sobre capítulos para obtener más detalles.

--chapter-sync d[,o[/p]]

Ajusta las marcas de tiempo de los capítulos en el archivo de origen siguiente en d ms. Alternativamente, puede utilizar la opción --sync con el ID de pista especial -2 (consulte la sección de IDs de pista especiales).

o/p: ajusta las marcas de tiempo en o/p para corregir derivas lineales. p tiene un valor predeterminado de 1 si se omite. Tanto o como p pueden ser números de punto flotante.

Predeterminados: sin corrección manual de sincronización (que es lo mismo que d = 0 y o/p = 1.0).

Esta opción se puede usar varias veces para un archivo de entrada, aplicándose a varias pistas seleccionando diferentes IDs de pista cada vez.

--generate-chapters modo

mkvmerge(1) puede crear capítulos automáticamente. Actualmente se admiten los dos modos siguientes:
•'when-appending' – Este modo crea un capítulo al principio y un capítulo cada vez que se adjunta un archivo.

Este modo también funciona con los modos de división 'parts:' y 'parts-frames:'. Para estos modos, se generará un capítulo por cada rango de marcas de tiempo adjuntado (aquellos cuyas marcas de tiempo de inicio van precedidas por '+').


Nota
mkvmerge(1) requiere una pista de video o audio para poder determinar cuándo se adjunta un nuevo archivo. Si se muxea una o más pistas de video, se utiliza la primera. De lo contrario, se utiliza la primera pista de audio.
•'interval:especificación-tiempo' – Este modo crea un capítulo a intervalos fijos dados por especificación-tiempo. El formato es bien la forma HH:MM:SS.nnnnnnnnn o un número seguido de una de las unidades 's', 'ms' o 'us'.

Ejemplo: --generate-chapters interval:45s

Los nombres de los nuevos capítulos se controlan mediante la opción --generate-chapters-name-template. El idioma se establece con --chapter-language, que debe aparecer antes de --generate-chapters.

--generate-chapters-name-template plantilla

Esto establece la plantilla de nombre para los nombres de capítulos generados por la opción --generate-chapters. Si la opción no se utiliza, se utilizará la predeterminada 'Capítulo <NUM:2>'.

Hay varias variables que se pueden utilizar en la plantilla que se reemplazan por sus valores reales cuando se genera un capítulo. La cadena '<NUM>' se reemplazará por el número del capítulo. La cadena '<START>' se reemplazará por la marca de tiempo de inicio del capítulo.

Las cadenas '<FILE_NAME>' y '<FILE_NAME_WITH_EXT>' solo se rellenan al generar capítulos para archivos adjuntos. Se reemplazarán por el nombre del archivo adjunto sin o con su extensión. Tenga en cuenta que solo se insertarán el nombre base y la extensión del archivo, no sus componentes de directorio o unidad.

Puede especificar un número mínimo de posiciones para el número de capítulo con '<NUM:lugares>'

gt;', por ejemplo, '<NUM:3>'. El número resultante se rellenará con ceros iniciales si el número de posiciones es menor que el especificado.

Puedes controlar el formato utilizado por la marca de tiempo de inicio con <START:formato>. El formato predeterminado es '%H:%M:%S' si no se proporciona ninguno. Los códigos de formato válidos son:

•%h – horas
•%H – horas rellenadas con ceros a dos posiciones
•%m – minutos
•%M – minutos rellenados con ceros a dos posiciones
•%s – segundos
•%S – segundos rellenados con ceros a dos posiciones
•%n – nanosegundos con nueve posiciones
•%<1-9>n – nanosegundos con hasta nueve posiciones (por ejemplo, tres posiciones con %3n)

La cadena '<TITLE>' solo se rellena al generar capítulos para archivos añadidos. Se reemplazará por el título del archivo añadido si está presente.

--cue-chapter-name-format formato

mkvmerge(1) admite la lectura de hojas CUE para archivos de audio como entrada para los capítulos. Las hojas CUE suelen contener las entradas PERFORMER y TITLE para cada entrada de índice. mkvmerge(1) utiliza estas dos cadenas para construir el nombre del capítulo. Con esta opción, se puede establecer el formato utilizado para este nombre.

Si no se proporciona esta opción, mkvmerge(1) utiliza por defecto el formato '%p - %t' (el intérprete, seguido de un espacio, un guion, otro espacio y el título).

Si se proporciona el formato, todo excepto los siguientes metacaracteres se copia tal cual, y los metacaracteres se reemplazan de la siguiente manera:

•%p se reemplaza por la cadena PERFORMER de la entrada actual,
•%t se reemplaza por la cadena TITLE de la entrada actual,
•%n se reemplaza por el número de pista actual y
•%N se reemplaza por el número de pista actual rellenado con un cero inicial si es < 10.

--chapters nombre-archivo

Lee la información de capítulos del archivo nombre-archivo. Consulta la sección sobre capítulos a continuación para obtener más detalles.

--tags-globales nombre-archivo

Lee las etiquetas globales del archivo nombre-archivo. Consulta la sección sobre etiquetas a continuación para obtener más detalles.

Control general de salida (opciones globales avanzadas)

--track-order FID1:TID1,FID2:TID2,...

Esta opción cambia el orden en el que se crean las pistas de un archivo de entrada. El argumento es una lista separada por comas de pares de IDs. Cada par contiene primero el ID del archivo (FID1), que es simplemente el número del archivo en la línea de comandos comenzando desde 0. El segundo es un ID de pista (TID1) de ese archivo. Si faltan algunos IDs de pista, esas pistas se crearán después de las especificadas con esta opción.

Si no se proporciona esta opción, las pistas se ordenarán primero por su tipo y luego por el orden de su archivo de origen. Las pistas de video van primero, seguidas por las de audio y subtítulos. Otros tipos de pistas de uso poco común van al final.

--cluster-length especificación

Limita el número de bloques de datos o la duración de los datos en cada clúster. El parámetro especificación puede ser un número n sin unidad o un número d seguido de 'ms'.

Si no se utiliza ninguna unidad, mkvmerge(1) colocará como máximo n bloques de datos en cada clúster. El número máximo de bloques es 65535.

Si el número d va seguido de 'ms', mkvmerge(1) colocará como máximo d milisegundos de datos en cada clúster. El mínimo para d es '100ms' y el máximo es '32000ms'.

mkvmerge(1) utiliza por defecto un máximo de 65535 bloques de datos y 5000ms de datos en un clúster.

Los programas que intentan encontrar un fotograma determinado solo pueden buscar directamente en un clúster y deben leer todo el clúster después. Por lo tanto, crear clústeres más grandes puede provocar búsquedas imprecisas o lentas.

--clusters-in-meta-seek

Indica a mkvmerge(1) que cree un elemento de metabusqueda al final del archivo que contenga todos los clústeres. Consulta también la sección sobre el diseño de archivos Matroska(TM).

--timestamp-scale factor

Forza el factor de escala de marca de tiempo a factor. Los valores válidos están en el rango de 1000..10000000 o el valor especial -1.

Normalmente mkvmerge(1) utilizará un valor de **1000000**, lo que significa que las marcas de tiempo y las duraciones tendrán una precisión de 1ms. Para archivos que no contendrán una pista de video pero sí al menos una pista de audio, mkvmerge(1) elegirá automáticamente un factor de escala de marca de tiempo para que todas las marcas de tiempo y duraciones tengan una precisión de una muestra de audio. Esto causa una mayor sobrecarga pero permite búsquedas y extracciones precisas.

Si se utiliza el valor especial **-1**, mkvmerge(1) utilizará la precisión de muestra incluso si hay una pista de video presente.

--enable-durations

Escribe las duraciones de todos los bloques. Esto aumentará el tamaño del archivo y no ofrecerá ningún valor adicional para los reproductores en este momento.

--no-cues

Indica a mkvmerge(1) que no cree ni escriba los datos de cue, que se pueden comparar con un índice en un AVI. Los archivos Matroska(TM) se pueden reproducir sin los datos de cue, pero la búsqueda probablemente será imprecisa y más lenta. Utiliza esto solo si te falta desesperadamente espacio o con fines de prueba. Consulta también la opción **--cues**, que se puede especificar para cada archivo de entrada.

--no-date

Por defecto, mkvmerge(1) establece el campo de información del segmento "date" (fecha) a la hora y fecha de inicio de la multiplexación. Con esta opción, ese campo no se escribe en absoluto.

--date marca-de-tiempo

Establece el campo DateUTC escrito en la información del segmento. La marca de tiempo debe ser similar a ISO 8601: YYYY-mm-ddTHH:MM:SSZ para UTC o con un desplazamiento ±HH:MM (también se acepta un espacio en lugar de T), por ejemplo, 2017-03-28T17:28:00Z o 2017-03-28 17:28:00+02:00. Si se utiliza junto con **--no-date**, **--no-date** tiene prioridad y no se escribirá ninguna fecha.

--disable-lacing

Deshabilita el entrelazado para todas las pistas. Esto aumentará el tamaño del archivo, especialmente si hay muchas pistas de audio. Esta opción no está pensada para un uso diario.

--disable-track-statistics-tags

Normalmente mkvmerge(1) escribirá ciertas etiquetas con estadísticas para cada pista. Si ya existen etiquetas de este tipo, se sobrescribirán. Las etiquetas son BPS, **DURATION**, **NUMBER_OF_BYTES** y **NUMBER_OF_FRAMES**.

Habilitar esta opción evita que mkvmerge(1) escriba esas etiquetas y toque cualquier etiqueta existente con los mismos nombres.

--disable-language-ietf

Normalmente mkvmerge(1) escribirá los nuevos elementos de idioma IETF BCP 47 además de los elementos de idioma heredados en las cabeceras de pista, capítulos y etiquetas. Si se utiliza esta opción, solo se escribirán los elementos heredados.

--normalize-language-ietf modo

Habilita la normalización de todas las etiquetas de idioma IETF BCP 47 a su forma canónica con el modo 'canonical', a su forma de subtags de idioma extendidos con el modo 'extlang' o la desactiva con el modo 'off'. Por defecto, se aplica la normalización a la forma canónica.

En la forma canónica, todos los subtags para los que existen valores preferidos se reemplazan por esos valores preferidos. Esto convierte, por ejemplo, 'zh-yue-jyutping' en 'yue-jyutping' o 'fr-FX' en 'fr-FR'.

Para la forma de subtags de idioma extendidos, primero se construye la forma canónica. Después, todos los idiomas primarios para los que existe un subtag de idioma extendido se reemplazan por ese subtag de idioma extendido y su prefijo. Esto convierte, por ejemplo, 'yue-jyutping' de nuevo a 'zh-yue-jyutping', pero no tiene efecto en 'fr-FR' ya que 'fr' no es un subtag de idioma extendido.

--stop-after-video-ends

Detiene el procesamiento después de que finaliza la pista de video principal, descartando los paquetes restantes de otras pistas.

División, vinculación, anexión y concatenación de archivos (más opciones globales)

--split especificación

Divide el archivo de salida después de un tamaño o tiempo dado. Ten en cuenta que las pistas solo se pueden dividir justo antes de un fotograma clave. Por lo tanto, el punto de división puede estar un poco alejado de lo que el usuario ha especificado.

En este momento, mkvmerge(1) admite los siguientes modos:

1. División por tamaño.

Sintaxis: **--split** [tamaño:]d[k|m|g]

Ejemplos: --split size:700m o --split 150000000

El parámetro d puede terminar con 'k', 'm' o 'g' para indicar que el tamaño está en KB, MB o GB respectivamente. De lo contrario, se asume un tamaño en bytes. Después de que el archivo de salida actual alcance este límite de tamaño, se iniciará uno nuevo.

El prefijo 'size:' se puede omitir por motivos de compatibilidad.

2. División después de una duración.

Sintaxis: **--split** [duración:]HH:MM:SS.nnnnnnnnn|ds

Ejemplos: --split duration:00:60:00.000 o --split 3600s

El parámetro debe tener el formato HH:MM:SS.nnnnnnnnn para especificar la duración con una precisión de hasta nanosegundos, o ser un número d seguido de la letra 's' para la duración en segundos. HH es el número de horas, MM el número de minutos, SS el número de segundos y nnnnnnnnn el número de nanosegundos. Tanto el número de horas como el número de nanosegundos se pueden omitir. Puede haber hasta nueve dígitos después del punto decimal. Después de que la duración del contenido en el archivo de salida actual alcance este límite, se iniciará un nuevo archivo de salida.

El prefijo 'duration:' se puede omitir por motivos de compatibilidad.

3. División después de marcas de tiempo específicas.

Sintaxis: **--split** timestamps:A[,B[,C...]]

Ejemplo: --split timestamps:00:05:00,00:10:00,00:15:00

El argumento es una lista de marcas de tiempo separadas por comas. Cada marca de tiempo indica el momento exacto en el que se debe cerrar el archivo de salida actual y se debe iniciar uno nuevo. Las marcas de tiempo deben estar en el formato HH:MM:SS.nnnnnnnnn.

--link

Si se especifica la opción **--split** y se utiliza la opción **--link**, entonces en lugar de crear varios archivos de salida separados, se creará un único archivo de salida. Las divisiones se crearán mediante enlaces duros a los archivos creados previamente. Esto ahorra espacio en disco y acelera la creación del archivo de salida. Los nombres de archivo de salida generados serán nombre-base.ext, nombre-base.ext.link, nombre-base.ext.link.link, y así sucesivamente.

--append-mode modo

Controla cómo se anexan los archivos de entrada. Los modos válidos son 'file' (por defecto) y 'segments'.

El modo 'file' significa que los archivos de entrada se anexarán uno tras otro. Si se utiliza la opción **--split**, entonces se crean varios archivos de salida. Cada archivo de salida contendrá el contenido del archivo de entrada original hasta el punto de división, o hasta el final si no hay división.

El modo 'segments' crea un único archivo de salida que contiene todos los segmentos de todos los archivos de entrada (anexados). Si se utiliza la opción **--split**, entonces se crean varios archivos de salida. Cada archivo de salida contendrá los segmentos de todos los archivos de entrada, hasta que se alcance el tamaño o la duración especificada por **--split**. Por lo tanto, los segmentos se dividen para que quepan en los archivos de salida individuales.

El modo 'segments' solo se puede utilizar si los archivos de entrada tienen el mismo códec y los mismos parámetros de codificación. De lo contrario, mkvmerge(1) fallará o creará un archivo Matroska inválido.

--concatenation modo

Permite la concatenación de varios archivos de entrada en un único archivo de salida. Los modos válidos son 'simple', 'hybrid' y 'all'.

El modo 'simple' es el que se utilizaba en versiones anteriores. Simplemente anexa todos los archivos de entrada uno tras otro. Solo se puede utilizar para archivos con el mismo códec y los mismos parámetros de codificación.

El modo 'hybrid' crea un único archivo de salida que contiene todos los archivos de entrada. Si hay varias pistas de video, se crea una pista de video separada para cada archivo de entrada. Para las pistas de audio y subtítulos, se crea una pista separada para cada archivo de entrada también.

El modo 'all' crea un único archivo de salida que contiene todos los archivos de entrada. Para las pistas de video, se crea una única pista de video que contiene todos los fotogramas de todos los archivos de entrada. Para las pistas de audio y subtítulos, se crea una única pista separada para cada archivo de entrada.

El modo 'all' solo se puede utilizar si todos los archivos de entrada tienen el mismo códec y los mismos parámetros de codificación.

Los parámetros A, B, C, etc., deben tener el mismo formato que los utilizados para la duración (ver arriba). La lista de marcas de tiempo está separada por comas. Después de que el flujo de entrada alcance la marca de tiempo del punto de división actual, se crea un nuevo archivo. Luego, se utiliza el siguiente punto de división dado en esta lista.

El prefijo 'timestamps:' no debe omitirse.

4. Mantener partes específicas especificando rangos de marcas de tiempo mientras se descartan otras.

Sintaxis: --split parts:inicio1-fin1[,[+]inicio2-fin2[,[+]inicio3-fin3...]]

Ejemplos:

1.--split parts:00:01:20-00:02:45,00:05:50-00:10:30
2.--split parts:00:01:20-00:02:45,+00:05:50-00:10:30
3.--split parts:-00:02:45,00:05:50-

El modo 'parts' indica a mkvmerge(1) que conserve ciertos rangos de marcas de tiempo mientras descarta otros. Los rangos a conservar deben enumerarse después de la palabra clave 'parts:' y estar separados por comas. Un rango en sí consiste en una marca de tiempo de inicio y fin en el mismo formato que aceptan otras variaciones de --split (por ejemplo, tanto 00:01:20 como 80s se refieren a la misma marca de tiempo).

Si se omite una marca de tiempo de inicio, se toma por defecto la marca de tiempo de fin del rango anterior. Si no había un rango anterior, se toma por defecto el inicio del archivo (ver ejemplo 3).

Si se omite una marca de tiempo de fin, se toma por defecto el fin de los archivos de origen, lo que básicamente le dice a mkvmerge(1) que conserve el resto (ver ejemplo 3).

Normalmente, cada rango se escribirá en un nuevo archivo. Esto se puede cambiar para que los rangos consecutivos se escriban en el mismo archivo. Para ello, el usuario debe anteponer un + al número de inicio de la marca de tiempo. Esto le indica a mkvmerge(1) que no cree un nuevo archivo y en su lugar añada el rango al mismo archivo en el que se escribió el rango anterior. Las marcas de tiempo se ajustarán para que no haya huecos en el archivo de salida, incluso si había un hueco en los dos rangos del archivo de entrada.

En el ejemplo 1, mkvmerge(1) creará dos archivos. El primero contendrá el contenido que comienza en 00:01:20 hasta 00:02:45. El segundo archivo contendrá el contenido que comienza en 00:05:50 hasta 00:10:30.

En el ejemplo 2, mkvmerge(1) creará un solo archivo. Este archivo contendrá tanto el contenido que comienza en 00:01:20 hasta 00:02:45 como el contenido que comienza en 00:05:50 hasta 00:10:30.

En el ejemplo 3, mkvmerge(1) creará dos archivos. El primero contendrá el contenido desde el inicio de los archivos de origen hasta 00:02:45. El segundo archivo contendrá el contenido que comienza en 00:05:50 hasta el final de los archivos de origen.


Nota
Tenga en cuenta que mkvmerge(1) solo toma decisiones sobre la división en posiciones de fotogramas clave. Esto se aplica tanto al inicio como al final de cada rango. Por lo tanto, incluso si una marca de tiempo de fin está entre dos fotogramas clave, mkvmerge(1) continuará emitiendo los fotogramas hasta, pero sin incluir, el siguiente fotograma clave.
5. Mantener partes específicas especificando rangos de números de fotograma/campo mientras se descartan otros.

Sintaxis: --split parts-frames:inicio1-fin1[,[+]inicio2-fin2[,[+]inicio3-fin3...]]

Ejemplos:

1.--split parts-frames:137-258,548-1211
2.--split parts-frames:733-912,+1592-2730
3.--split parts-frames:-430,2512-

El modo 'parts-frames' indica a mkvmerge(1) que conserve ciertos rangos de números de fotograma/campo mientras descarta otros. Los rangos a conservar deben enumerarse después de la palabra clave 'parts-frames:' y estar separados por comas. Un rango en sí consiste en un número de fotograma/campo de inicio y fin. La numeración comienza en 1.

Si se omite un número de inicio, se toma por defecto el número de fin del rango anterior. Si no había un rango anterior, se toma por defecto el inicio del archivo (ver ejemplo 3).

Si se omite un número de fin, se toma por defecto el fin de los archivos de origen, lo que básicamente le dice a mkvmerge(1) que conserve el resto (ver ejemplo 3).

Normalmente, cada rango se escribirá en un nuevo archivo. Esto se puede cambiar para que los rangos consecutivos se escriban en el mismo archivo. Para ello, el usuario debe anteponer un + al número de inicio. Esto le indica a mkvmerge(1) que no cree un nuevo archivo y en su lugar añada el rango al mismo archivo en el que se escribió el rango anterior. Las marcas de tiempo se ajustarán para que no haya huecos en el archivo de salida, incluso si había un hueco en los dos rangos del archivo de entrada.

Tenga en cuenta que mkvmerge(1) solo toma decisiones sobre la división en posiciones de fotogramas clave. Esto se aplica tanto al inicio como al final de cada rango. Por lo tanto, incluso si un número de fotograma/campo de fin está entre dos fotogramas clave, mkvmerge(1) continuará emitiendo los fotogramas hasta, pero sin incluir, el siguiente fotograma clave.
En el ejemplo 1, mkvmerge(1) creará dos archivos. El primero contendrá el contenido que comienza desde el primer fotograma clave en o después de 137 hasta, pero sin incluir, el primer fotograma clave en o después de 258. El segundo archivo contendrá el contenido que comienza desde 548 hasta 1211.

En el ejemplo 2, mkvmerge(1) creará un solo archivo. Este archivo contendrá tanto el contenido que comienza desde 733 hasta 912 como el contenido que comienza desde 1592 hasta 2730.

En el ejemplo 3, mkvmerge(1) creará dos archivos. El primero contendrá el contenido desde el inicio de los archivos de origen hasta 430. El segundo archivo contendrá el contenido que comienza desde 2512 hasta el final de los archivos de origen.

Este modo considera solo la primera pista de video que se emite. Si no se emite ninguna pista de video, no se realizará ninguna división.


Nota
Los números dados con este argumento se interpretan en función del número de bloques de Matroska(TM) que se emiten. Un solo bloque de Matroska(TM) contiene un fotograma completo (para contenido progresivo) o un solo campo (para contenido entrelazado). mkvmerge no distingue entre estos dos y simplemente cuenta el número de bloques. Por ejemplo: Si se quisiera dividir después del 25º fotograma completo con contenido entrelazado, se tendría que usar 50 (dos campos por fotograma completo) como punto de división.

Sintaxis: --split frames:A[,B[,C...]]

Los parámetros A, B, C, etc., deben ser todos enteros positivos. La numeración comienza en 1. La lista de números de fotograma/campo está separada por comas. Después de que el flujo de entrada alcance el número de fotograma/campo del punto de división actual, se crea un nuevo archivo. Luego, se utiliza el siguiente punto de división dado en esta lista.

Este modo considera solo la primera pista de video que se emite. Si no se emite ninguna pista de video, no se realizará ninguna división.

Sintaxis: --split chapters:all o --split chapters:A[,B[,C...]]

Ejemplo: --split chapters:5,8

Los parámetros A, B, C, etc., deben ser todos enteros positivos. La numeración comienza en 1. La lista de números de capítulos está separada por comas. Un capítulo que comienza en 0s nunca se considera para la división y se descarta silenciosamente.

La palabra clave 'all' se puede usar en lugar de enumerar todos los números de capítulo manualmente.

El prefijo 'chapters:' no debe omitirse.


Nota
El formato de archivo Matroska(TM) admite estructuras de capítulos anidadas de profundidad arbitraria llamadas 'entradas de edición' y 'átomos de capítulo'. Sin embargo, este modo solo considera el nivel superior de capítulos en todas las entradas de edición.

Para este modo de división, el nombre del archivo de salida se trata de manera diferente que para la operación normal. Puede contener una expresión similar a printf '%d' que incluya un ancho de campo opcional, por ejemplo, '%02d'. Si lo hace, el número de archivo actual se formateará adecuadamente y se insertará en ese punto del nombre del archivo. Si no hay tal patrón, se asume un patrón de '-%03d' justo antes de la extensión del archivo: '-o salida.mkv' resultaría en 'salida-001.mkv' y así sucesivamente. Si no hay extensión, se añadirá '-%03d' al nombre.

Otro patrón posible es '%c', que será reemplazado por el nombre del primer capítulo del archivo. Tenga en cuenta que cuando '%c' está presente, el patrón '-%03d' no se añadirá automáticamente.

When appending files, mkvmerge needs to know how to handle the timestamps of the appended tracks. There are two methods:

File mode
The timestamps of the appended track are used as they are. This is the default mode. This mode works well for files that were created independently of each other.
Track mode
The timestamps of the appended track are shifted so that the first timestamp of the appended track matches the last timestamp of the corresponding track in the first file. This is useful for files that are essentially parts of one big file, like VOB files from a DVD.

Unfortunately mkvmerge cannot detect which mode to use reliably. Therefore it defaults to 'file' mode. 'file' mode usually works better for files that have been created independently of each other; e.g. when appending AVI or MP4 files. 'track' mode may work better for sources that are essentially just parts of one big file, e.g. for VOB and EVO files.

Subtitle tracks are always treated as if 'file' mode were active even if 'track' mode actually is.

--append-to SFID1:STID1:DFID1:DTID1[,...]

This option controls to which track another track is appended. Each spec contains four IDs: a file ID, a track ID, a second file ID and a second track ID. The first pair, "source file ID" and "source track ID", identifies the track that is to be appended. The second pair, "destination file ID" and "destination track ID", identifies the track the first one is appended to.

If this option has been omitted then a standard mapping is used. This standard mapping appends each track from the current file to a track from the previous file with the same track ID. This allows for easy appending if a movie has been split into two parts and both file have the same number of tracks and track IDs with the command mkvmerge -o output.mkv part1.mkv +part2.mkv.

+

A single '+' causes the next file to be appended instead of added. The '+' can also be put in front of the next file name. Therefore the following two commands are equivalent: 
$ mkvmerge -o full.mkv file1.mkv + file2.mkv
$ mkvmerge -o full.mkv file1.mkv +file2.mkv

[ file1 file2 ]

If multiple file names are contained in a pair of square brackets then the second and all following files will be appended to the first file named within the brackets.

This is an alternative syntax to using '+' between the file names. Therefore the following two commands are equivalent:

$ mkvmerge -o full.mkv file1.mkv + file2.mkv
$ mkvmerge -o full.mkv '[' file1.mkv file2.mkv ']'

=

For certain file types (MPEG program streams = VOBs) mkvmerge(1) normally looks for files in the same directory as an input file that have the same base name and only differ in their running number (e.g. 'VTS_01_1.VOB', 'VTS_01_2.VOB', 'VTS_01_3.VOB' etc) and treats all of those files as if they were concatenated into a single big file. This option, a single '=', causes mkvmerge not to look for those additional files.

The '=' can also be put in front of the next file name. Therefore the following two commands are equivalent:

$ mkvmerge -o full.mkv = file1.vob
$ mkvmerge -o full.mkv =file1.vob

( file1 file2 )

If multiple file names are contained in a pair of parenthesis then those files will be treated as if they were concatenated into a single big file consisting of the content of each of the files one after the other.

This can be used for e.g. VOB files coming from a DVD or MPEG transport streams. It cannot be used if each file contains its own set of headers which is usually the case with stand-alone files like AVI or MP4.

Putting a file name into parenthesis also prevents mkvmerge(1) from looking for additional files with the same base name as described in option =. Therefore these two command lines are equivalent:

$ mkvmerge -o out.mkv = file.mkv
$ mkvmerge -o out.mkv '(' file.mkv ')'

Several things should be noted:

1.There must be spaces both after the opening and before the closing parenthesis.
2.Every parameter between parenthesis is interpreted as a file name. Therefore all options applying to this logical file must be listed before the opening parenthesis.
3.Some shells treat parenthesis as special characters. Hence you must escape or quote them as shown in the example above.

If the source file is a Matroska(TM) file then the CodecID should be enough to detect SBR AAC. However, if the CodecID is wrong then this switch can be used to correct that.

If mkvmerge wrongfully detects that an AAC file is SBR then you can add ':0' to the track ID.

Some audio codecs have a lossy core and optional extensions that implement lossless decoding. This option tells mkvmerge(1) to only copy the core but not the extensions. By default mkvmerge(1) copies both the core and the extensions.

Some audio codecs contain header fields that tell the decoder or player to apply a (usually negative) gain for dialog normalization. This option tells mkvmerge(1) to remove or minimize that gain by modifying the corresponding header fields.

Currently only AC-3, DTS and TrueHD tracks are affected by this option.

ORDEN DE OPCIONES

El orden en que se ingresan las opciones es importante para algunas de ellas. Las opciones se dividen en dos categorías:

1.Opciones que afectan a todo el programa y no están vinculadas a ningún archivo de entrada. Estas incluyen, entre otras, --command-line-charset, --output o --title. Estas pueden aparecer en cualquier lugar de la línea de comandos.
2.Opciones que afectan a un solo archivo de entrada o a una sola pista en un archivo de entrada. Todas estas opciones se aplican al siguiente archivo de entrada en la línea de comandos. Todas las opciones que se aplican al mismo archivo de entrada (o a pistas del mismo archivo de entrada) se pueden escribir en cualquier orden, siempre que aparezcan antes del nombre del archivo de entrada. Ejemplos de opciones que se aplican a un archivo de entrada son --no-chapters o --chapter-charset. Ejemplos de opciones que se aplican a una sola pista son --default-duration o --language.

Las opciones se procesan de izquierda a derecha. Si una opción aparece varias veces dentro del mismo ámbito, se utilizará la última ocurrencia. Por lo tanto, el título se establecerá en "Something else" en el siguiente ejemplo:

$ mkvmerge -o output.mkv --title 'This and that' input.avi --title 'Something else'

El siguiente ejemplo muestra que usar la opción --language dos veces está bien porque se utilizan en ámbitos diferentes. Aunque se aplican al mismo ID de pista, se aplican a diferentes archivos de entrada y, por lo tanto, tienen diferentes ámbitos:

$ mkvmerge -o output.mkv --language 0:fre français.ogg --language 0:deu deutsch.ogg

EJEMPLOS

Supongamos que tiene un archivo llamado MyMovie.avi y la pista de audio en un archivo separado, por ejemplo, 'MyMovie.wav'. Primero, desea codificar el audio a OggVorbis(TM):

$ oggenc -q4 -oMyMovie.ogg MyMovie.wav

Después de unos minutos, puede unir el video y el audio:

$ mkvmerge -o MyMovie-with-sound.mkv MyMovie.avi MyMovie.ogg

Si su AVI ya contiene una pista de audio, también se copiará (si mkvmerge(1) admite el formato de audio). Para evitarlo, simplemente haga:

$ mkvmerge -o MyMovie-with-sound.mkv -A MyMovie.avi MyMovie.ogg

Después de unos minutos de reflexión, extrae otra pista de audio, por ejemplo, los comentarios del director o en otro idioma a 'MyMovie-add-audio.wav'. Vuelva a codificarla y únela con el otro archivo:

$ oggenc -q4 -oMyMovie-add-audio.ogg MyMovie-add-audio.wav
$ mkvmerge -o MM-complete.mkv MyMovie-with-sound.mkv MyMovie-add-audio.ogg

El mismo resultado se puede lograr con

$ mkvmerge -o MM-complete.mkv -A MyMovie.avi MyMovie.ogg MyMovie-add-audio.ogg

Ahora inicie mplayer(TM) y disfruta. Si tienes múltiples pistas de audio (o incluso de video), puedes indicarle a mplayer(TM) qué pista reproducir con las opciones '-vid' y '-aid'. Estas son basadas en 0 y no distinguen entre video y audio.

Si necesitas sincronizar una pista de audio, puedes hacerlo fácilmente. Primero, averigua qué ID de pista tiene la pista Vorbis con:

$ mkvmerge --identify outofsync.ogg

Ahora puedes usar ese ID en la siguiente línea de comandos:

$ mkvmerge -o goodsync.mkv -A source.avi -y 12345:200 outofsync.ogg

Esto agregaría 200 ms de silencio al principio de la pista de audio con el ID 12345 tomada de 'outofsync.ogg'.

Algunas películas comienzan sincronizadas correctamente pero luego se desincronizan lentamente. Para este tipo de películas, puedes especificar un factor de retardo que se aplica a todas las marcas de tiempo; no se agregan ni eliminan datos. Por lo tanto, si haces que ese factor sea demasiado grande o demasiado pequeño, obtendrás malos resultados. Un ejemplo es un episodio que transcodifiqué, que estaba desincronizado 0.2 segundos al final de la película, que tenía 77340 fotogramas de longitud. A 29.97fps, 0.2 segundos corresponden aproximadamente a 6 fotogramas. Así que hice:

$ mkvmerge -o goodsync.mkv -y 23456:0,77346/77340 outofsync.mkv

El resultado fue bueno.

Las opciones de sincronización también se pueden usar para subtítulos de la misma manera.

Para subtítulos de texto, puedes usar algún software de Windows (como SubRipper(TM)) o el paquete subrip(TM) que se encuentra en las fuentes de transcode(1) en el directorio 'contrib/subrip'. El proceso general es:

1. Extraer un flujo de subtítulos en bruto de la fuente: 
$ tccat -i /path/to/copied/dvd/ -T 1 -L | tcextract -x ps1 -t vob -a 0x20 | subtitle2pgm -o mymovie
2. Convertir las imágenes PGM resultantes a texto con gocr: 
$ pgm2txt mymovie
3. Corregir la ortografía de los archivos de texto resultantes: 
$ ispell -d american *txt
4. Convertir los archivos de texto a un archivo SRT: 
$ srttool -s -w -i mymovie.srtx -o mymovie.srt

El archivo resultante se puede usar como otro archivo de entrada para mkvmerge(1):

$ mkvmerge -o mymovie.mkv mymovie.avi mymovie.srt

Si deseas especificar el idioma para una pista dada, esto se hace fácilmente. Primero, averigua el código ISO 639-2 para tu idioma. mkvmerge(1) puede listar todos esos códigos por ti:

$ mkvmerge --list-languages

Busca en la lista los idiomas que necesitas. Supongamos que has incluido dos pistas de audio en un archivo Matroska(TM) y deseas establecer sus códigos de idioma, y que sus IDs de pista son 2 y 3. Esto se puede hacer con:

$ mkvmerge -o with-lang-codes.mkv --language 2:ger --language 3:dut without-lang-codes.mkv

Como puedes ver, puedes usar el modificador --language varias veces.

Quizás también te gustaría que el reproductor usara el idioma holandés como idioma predeterminado. También tienes subtítulos adicionales, por ejemplo, en inglés y francés, y quieres que el reproductor muestre los franceses por defecto. Esto se puede hacer con:

$ mkvmerge -o with-lang-codes.mkv --language 2:ger --language 3:dut --default-track-flag 3 without-lang-codes.mkv --language 0:eng english.srt --default-track-flag 0 --language 0:fre french.srt

Si no ves el idioma o las marcas de pista predeterminadas que has especificado en la salida de mkvinfo(1), por favor, lee la sección sobre valores predeterminados.

Desactivar la compresión para un archivo de entrada.

$ mkvmerge -o no-compression.mkv --compression -1:none MyMovie.avi --compression -1:none mymovie.srt

Algunas de las opciones para mkvmerge(1) necesitan un ID de pista para especificar a qué pista deben aplicarse. Esos IDs de pista son impresos por los lectores al desmultiplexar el archivo de entrada actual, o si mkvmerge(1) se llama con la opción --identify. Un ejemplo de tal salida:

Track ID 1: audio (A_MPEG/L3)

No confundas los IDs de pista que se asignan a las pistas que se colocan en el archivo MKV de salida con los IDs de pista de los archivos de entrada. Solo los IDs de pista de los archivos de entrada se utilizan para las opciones que requieren estos valores.

También ten en cuenta que cada archivo de entrada tiene su propio conjunto de IDs de pista. Por lo tanto, los IDs de pista para el archivo 'file1.ext' reportados por 'mkvmerge --identify' no cambian sin importar cuántos otros archivos de entrada haya o en qué posición se use 'file1.ext'.

Los IDs de pista se asignan de la siguiente manera:

• Archivos AVI: La pista de video tiene el ID 0. Las pistas de audio obtienen IDs en orden ascendente comenzando en 1.
• Archivos AAC, AC-3, MP3, SRT y WAV: La única 'pista' en ese archivo obtiene el ID 0.
• La mayoría de los otros archivos: Los IDs de pista se asignan en el orden en que se encuentran las pistas en el archivo, comenzando en 0.

Las opciones que usan los IDs de pista son aquellas cuya descripción contiene 'TID'. Las siguientes opciones también usan IDs de pista: --audio-tracks, --video-tracks, --subtitle-tracks, --button-tracks y --track-tags.

IDs de pista especiales

Hay varios IDs que tienen un significado especial y no aparecen en la salida de identificación.

El ID de pista especial '-1' es un comodín y aplica el interruptor dado a todas las pistas que se leen de un archivo de entrada.

El ID de pista especial '-2' se refiere a los capítulos en un archivo de origen. Actualmente, solo la opción --sync utiliza este ID especial. Como alternativa a --sync -2:..., se puede usar la opción --chapter-sync ....

MANEJO DE IDIOMAS

Matroska(TM) tiene soporte para dos tipos diferentes de elementos de idioma: el elemento antiguo y obsoleto "Language" que contiene códigos alfanuméricos de 3 letras ISO 639-2 y las nuevas etiquetas de idioma "LanguageIETF" que contienen etiquetas de idioma IETF BCP 47. Todas las opciones de mkvmerge(1) que aceptan un idioma aceptan una etiqueta de idioma BCP 47. mkvmerge(1) derivará el valor para el elemento obsoleto "Language" de las etiquetas de idioma BCP 47 siempre que sea posible.

Al identificar un archivo en modo JSON, los elementos de cabecera de pista "LanguageIETF" existentes se mostrarán como la propiedad de pista language_ietf.

Al escribir un archivo, mkvmerge(1) siempre escribirá los elementos "LanguageIETF", "ChapLanguageIETF" y "TagLanguageIETF" (los dos últimos solo si se escriben capítulos o etiquetas respectivamente). Además de esos elementos, se escribirán los elementos antiguos correspondientes; se establecerán con la porción del código ISO 639-2 de la etiqueta de idioma BCP 47. Por ejemplo, cuando el idioma de la pista se establece en sr-Cyrl-RS, "LanguageIETF" se establecerá en sr-Cyrl-RS y el elemento antiguo "Language" se establecerá en srp.

Al leer archivos existentes (archivos Matroska, archivos de capítulos o etiquetas XML, etc.) que ya contienen elementos "...LanguageIETF", se conservarán los elementos existentes. De lo contrario, se agregarán elementos "...LanguageIETF" basándose en las opciones de línea de comandos y otros elementos obsoletos "...Language" existentes.

La creación de los nuevos elementos se puede deshabilitar completamente con la opción de línea de comandos --disable-language-ietf, que opera en los tres nuevos elementos.

Puedes elegir el método de normalización aplicado a los sub-etiquetas de idioma extendidas con el parámetro --normalize-language-ietf.

ARCHIVOS DE TEXTO Y CONVERSIONES DE JUEGO DE CARACTERES


Nota

Esta sección se aplica a todos los programas en MKVToolNix, incluso si solo menciona mkvmerge(1).

Introducción

Todo el texto en un archivo Matroska(TM) está codificado en UTF-8. Esto significa que mkvmerge(1) tiene que convertir cada archivo de texto que lee, así como cada texto dado en la línea de comandos, de un juego de caracteres a UTF-8. A cambio, esto también significa que la salida de mkvmerge(1) debe ser reconvertida de UTF-8 a ese juego de caracteres, por ejemplo, si se usa una traducción no inglesa con --ui-language o para texto que se origina en un archivo Matroska(TM).

mkvmerge(1) realiza esta conversión automáticamente basándose en la presencia de un marcador de orden de bytes (BOM) o la configuración regional (locale) actual del sistema. Cómo se infiere el juego de caracteres de la configuración regional depende del sistema operativo en el que se ejecute mkvmerge(1).

Marcadores de orden de bytes (BOM)

Los archivos de texto que comienzan con un BOM ya están codificados en una representación de UTF. mkvmerge(1) soporta los siguientes cinco modos: UTF-8, UTF-16 Little y Big Endian, UTF-32 Little y Big Endian. Los archivos de texto con un BOM se convierten automáticamente a UTF-8. Cualquiera de los parámetros que de otra manera establecerían el juego de caracteres para dicho archivo (por ejemplo, --sub-charset) se ignora silenciosamente.

Sistemas Linux y similares a Unix, incluido macOS

En sistemas similares a Unix, mkvmerge(1) utiliza la llamada al sistema setlocale(3) que, a su vez, utiliza las variables de entorno LANG, LC_ALL y LC_CYPE. El juego de caracteres resultante suele ser UTF-8 o la familia ISO-8859-* y se utiliza para todas las operaciones de archivos de texto y para codificar cadenas en la línea de comandos y para la salida a la consola.

Windows

En Windows, el conjunto de caracteres predeterminado que se utiliza para convertir archivos de texto se determina mediante una llamada a la llamada del sistema GetACP().

La lectura de la línea de comandos se realiza con la función GetCommandLineW() que ya devuelve una cadena Unicode. Por lo tanto, la opción --command-line-charset se ignora en Windows.

La salida a la consola consta de tres escenarios:

1. Si la salida se redirige con la opción --redirect-output, el juego de caracteres predeterminado es UTF-8. Esto se puede cambiar con --output-charset.

2. Si la salida se redirige con cmd.exe, por ejemplo, con mkvinfo file.mkv > info.txt, el juego de caracteres es siempre UTF-8 y no se puede cambiar.

3. De lo contrario (al escribir directamente en la consola), se utiliza la función de Windows WriteConsoleW() y la opción --output-charset se ignora. La consola debería poder mostrar todos los caracteres Unicode para los que está instalado el soporte de idioma correspondiente (por ejemplo, es posible que los caracteres chinos no se muestren en las versiones de Windows en inglés).

Opciones de línea de comandos

Existen las siguientes opciones que permiten especificar los conjuntos de caracteres:

• --sub-charset para archivos de subtítulos de texto y para pistas de subtítulos de texto almacenadas en formatos de contenedor para los que el conjunto de caracteres no se puede determinar de forma inequívoca (por ejemplo, archivos Ogg).

• --chapter-charset para archivos de texto de capítulos y para capítulos y títulos de archivo almacenados en formatos de contenedor para los que el conjunto de caracteres no se puede determinar de forma inequívoca (por ejemplo, archivos Ogg para información de capítulos, títulos de pistas y archivos, etc.; archivos MP4 para información de capítulos).

• --command-line-charset para todas las cadenas en la línea de comandos.

• --output-charset para todas las cadenas escritas en la consola o en un archivo si la salida se ha redirigido con la opción --redirect-output. En sistemas que no son Windows, el valor predeterminado para el conjunto de caracteres de salida es el conjunto de caracteres actual del sistema. En Windows, el valor predeterminado es UTF-8 tanto para la redirección con --redirect-output como con cmd.exe, por ejemplo, mkvinfo file.mkv > info.txt.

ARCHIVOS DE OPCIONES

Un archivo de opciones es un archivo del que mkvmerge(1) puede leer argumentos de línea de comandos adicionales. Esto se puede usar para eludir ciertas limitaciones del shell o del sistema operativo al ejecutar programas externos, como una longitud de línea de comandos limitada.

Un archivo de opciones contiene datos con formato JSON. Su contenido debe ser una matriz JSON válida que consista únicamente en cadenas JSON. La codificación del archivo debe ser UTF-8. El archivo no debe comenzar con un marcador de orden de bytes (BOM), pero si existe, se omitirá.

Las reglas para escapar caracteres especiales dentro de JSON son las de la especificación JSON oficial, RFC 7159[4].

El nombre del archivo de opciones en sí debe especificarse como un argumento de línea de comandos precedido por el carácter '@'.

La línea de comandos 'mkvmerge -o "mi archivo.mkv" -A "una película.avi" sound.ogg' podría convertirse en el siguiente archivo de opciones JSON llamado, por ejemplo, 'options.json':

[
  "-o",
  "c:\\Matroska\\mi archivo.mkv",
  "--title",
  "#65",
  "-A",
  "una película.avi",
  "sound.ogg"
]

El comando correspondiente sería entonces 'mkvmerge @options.json'.

ENLACE DE ARCHIVOS

Matroska(TM) admite el enlace de archivos, que simplemente indica que un archivo específico es el predecesor o sucesor del archivo actual. Para ser precisos, no son realmente los archivos los que se enlazan, sino los segmentos de Matroska(TM). Dado que la mayoría de los archivos probablemente solo contendrán un segmento de Matroska(TM), las siguientes explicaciones utilizan el término 'enlace de archivos' aunque 'enlace de segmentos' sería más apropiado.

Cada segmento se identifica por un UID de segmento único de 128 bits. Este UID es generado automáticamente por mkvmerge(1). El enlace se realiza principalmente colocando los UID de segmento (en resumen: SID) del archivo anterior/siguiente en la información del encabezado del segmento. mkvinfo(1) imprime estos SID si los encuentra.

Si un archivo se divide en varios más pequeños y se utiliza el enlace, las marcas de tiempo no comenzarán de nuevo en 0, sino que continuarán donde dejó el último archivo. De esta manera, se mantiene la hora absoluta incluso si los archivos anteriores no están disponibles (por ejemplo, al transmitir). Si no se utiliza el enlace, las marcas de tiempo deberían comenzar en 0 para cada archivo. Por defecto, mkvmerge(1) no utiliza el enlace de archivos. Si lo desea, puede activarlo con la opción --link. Esta opción solo es útil si la división también está activada.

Independientemente de si la división está activa o no, el usuario puede indicar a mkvmerge(1) que enlace los archivos producidos a SID específicos. Esto se logra con las opciones --link-to-previous y --link-to-next. Estas opciones aceptan un SID de segmento en el formato que imprime mkvinfo(1): 16 números hexadecimales entre 0x00 y 0xff prefijados con '0x' cada uno, por ejemplo, '0x41 0xda 0x73 0x66 0xd9 0xcf 0xb2 0x1e 0xae 0x78 0xeb 0xb4 0x5e 0xca 0xb3 0x93'. Alternativamente, se puede usar una forma más corta: 16 números hexadecimales entre 0x00 y 0xff sin los prefijos '0x' y sin los espacios, por ejemplo, '41da7366d9cfb21eae78ebb45ecab393'.

Si se utiliza la división, el primer archivo se enlazará al SID proporcionado con --link-to-previous y el último archivo se enlazará al SID proporcionado con --link-to-next. Si no se utiliza la división, el único archivo de salida se enlazará a ambos SID.

VALORES PREDETERMINADOS

La especificación Matroska(TM) establece que algunos elementos tienen un valor predeterminado. Por lo general, un elemento no se escribe en el archivo si su valor es igual a su valor predeterminado para ahorrar espacio. Los elementos que el usuario podría extrañar en la salida de mkvinfo(1) son los elementos de *idioma* y el *flag de pista predeterminada*. El valor predeterminado para el *idioma* es inglés ('eng'), y el valor predeterminado para el *flag de pista predeterminada* es *true*. Por lo tanto, si usó --language 0:eng para una pista, no aparecerá en la salida de mkvinfo(1).

ADJUNTOS

Quizás también quieras conservar algunas fotos junto con tu archivo Matroska(TM), o estás usando subtítulos SSA y necesitas una fuente TrueType(TM) especial que es realmente rara. En estos casos, puedes adjuntar esos archivos al archivo Matroska(TM). No se agregarán simplemente al final del archivo, sino que se incrustarán en él. Un reproductor puede mostrar estos archivos (el caso de las 'fotos') o usarlos para renderizar los subtítulos (el caso de las 'fuentes TrueType(TM)').

Aquí tienes un ejemplo de cómo adjuntar una foto y una fuente TrueType(TM) al archivo de salida:

$ mkvmerge -o salida.mkv -A video.avi sonido.ogg \
  --attachment-description "Yo y la banda detrás del escenario en una pequeña reunión" \
  --attachment-mime-type image/jpeg \
  --attach-file me_and_the_band.jpg \
  --attachment-description "La fuente realmente rara e increíblemente atractiva" \
  --attachment-mime-type application/octet-stream \
  --attach-file really_cool_font.ttf

Si se utiliza un archivo Matroska(TM) que contiene adjuntos como archivo de entrada, mkvmerge(1) copiará los adjuntos al nuevo archivo. La selección de qué adjuntos se copian y cuáles no se puede cambiar con las opciones --attachments y --no-attachments.

CAPÍTULOS

El sistema de capítulos de Matroska(TM) es más potente que el antiguo sistema conocido utilizado por los archivos OGM. Las especificaciones completas se pueden encontrar en el sitio web de Matroska(TM)[1].

mkvmerge(1) admite dos tipos de archivos de capítulos como entrada. El primer formato, llamado 'formato de capítulo simple', es el mismo formato que esperan las herramientas OGM. El segundo formato es un formato de capítulo basado en XML que admite toda la funcionalidad de capítulos de Matroska(TM).

Además de los archivos de capítulos dedicados, mkvmerge(1) también puede leer capítulos de otros formatos de archivo (por ejemplo, MP4, Ogg, Blu-ray o DVD).

El formato de capítulo simple

Este formato consta de pares de líneas que comienzan con 'CHAPTERxx=' y 'CHAPTERxxNAME=' respectivamente. La primera contiene la marca de tiempo de inicio, mientras que la segunda contiene el título. Aquí tienes un ejemplo:

CHAPTER01=00:00:00.000
CHAPTER01NAME=Intro
CHAPTER02=00:02:30.000
CHAPTER02NAME=Baby prepares to rock
CHAPTER03=00:02:42.300
CHAPTER03NAME=Baby rocks the house

mkvmerge(1) transformará cada par de líneas en un Matroska(TM) ChapterAtom. No establece ningún ChapterTrackNumber, lo que significa que todos los capítulos se aplican a todas las pistas del archivo.

Dado que este es un archivo de texto, puede ser necesario realizar una conversión de conjuntos de caracteres. Consulte la sección sobre archivos de texto y conjuntos de caracteres para obtener una explicación de cómo mkvmerge(1) convierte entre conjuntos de caracteres.

El formato de capítulo basado en XML

El formato de capítulo basado en XML se ve así:

<?xml version="1.0" encoding="ISO-8859-1"?>
<!DOCTYPE Chapters SYSTEM "matroskachapters.dtd">
<Chapters>
  <EditionEntry>
    <ChapterAtom>
      <ChapterTimeStart>00:00:30.000</ChapterTimeStart>
      <ChapterTimeEnd>00:01:20.000</ChapterTimeEnd>
      <ChapterDisplay>
        <ChapterString>Un capítulo corto</ChapterString>
        <ChapterLanguage>eng</ChapterLanguage>
      </ChapterDisplay>
      <ChapterAtom>
        <ChapterTimeStart>00:00:46.000</ChapterTimeStart>
        <ChapterTimeEnd>00:01:10.000</ChapterTimeEnd>
        <ChapterDisplay>
          <ChapterString>Una parte de ese capítulo corto</ChapterString>
          <ChapterLanguage>eng</ChapterLanguage>
        </ChapterDis
1 0 1 0 1 00:00:05.000000000 00:00:10.000000000 Introduction eng 2 00:00:15.000000000 00:00:20.000000000 The next part eng 3 00:00:16.000000000 00:00:18.000000000 A sub chapter eng 2 0 4 00:00:00.000000000 Default chapter deu ```

Con este formato, son posibles tres cosas que no son posibles con el formato de capítulo simple:

1. Se puede establecer la marca de tiempo del final del capítulo,
2. los capítulos se pueden anidar,
3. se pueden establecer el idioma y el país.

La distribución de mkvtoolnix contiene algunos archivos de ejemplo en el subdirectorio doc que se pueden usar como base.

    EditionFlagHidden (entero sin signo, rango válido: 0 <= valor <= 1)
    EditionFlagDefault (entero sin signo, rango válido: 0 <= valor <= 1)
    EditionFlagOrdered (entero sin signo, rango válido: 0 <= valor <= 1)
    ChapterAtom (maestro)
      ChapterAtom (maestro)
      ChapterUID (entero sin signo, rango válido: 1 <= valor)
      ChapterTimeStart (entero sin signo)
      ChapterTimeEnd (entero sin signo)
      ChapterFlagHidden (entero sin signo, rango válido: 0 <= valor <= 1)
      ChapterFlagEnabled (entero sin signo, rango válido: 0 <= valor <= 1)
      ChapterSegmentUID (binario, rango válido: 1 <= longitud en bytes)
      ChapterSegmentEditionUID (entero sin signo, rango válido: 1 <= valor)
      ChapterPhysicalEquiv (entero sin signo)
      ChapterTrack (maestro)
        ChapterTrackNumber (entero sin signo, rango válido: 1 <= valor)
      ChapterDisplay (maestro)
        ChapterString (cadena UTF-8)

Lectura de capítulos desde Blu-rays

mkvmerge(1) puede leer capítulos de Blu-rays sin cifrar. Para ello, puede utilizar la ruta a una de las listas de reproducción MPLS con el parámetro --chapters.

Ejemplo: --chapters /srv/blurays/BigBuckBunny/BDMV/PLAYLIST/00001.mpls

Lectura de capítulos desde DVDs

Cuando MKVToolNix se compila con la biblioteca libdvdread(TM), mkvmerge(1) puede leer capítulos de DVDs. Para ello, puede utilizar la ruta a una de las carpetas o archivos del DVD con el parámetro --chapters. Dado que los DVDs pueden contener más de un título y cada título tiene su propio conjunto de capítulos, puede añadir un dos puntos y el número de título deseado al final del argumento del nombre del archivo. El número de título tiene como valor predeterminado 1.

Ejemplo: --chapters /srv/dvds/BigBuckBunny/VIDEO_TS:2

Notas generales

Al dividir archivos, mkvmerge(1) ajustará correctamente los capítulos. Esto significa que cada archivo solo incluirá las entradas de capítulo que le correspondan, y que las marcas de tiempo se compensarán para coincidir con las nuevas marcas de tiempo de cada archivo de salida.

mkvmerge(1) es capaz de copiar capítulos de archivos de origen Matroska(TM) a menos que se deshabilite explícitamente con la opción --no-chapters. Los capítulos de todas las fuentes (archivos Matroska(TM), archivos Ogg, archivos MP4, archivos de texto de capítulos) generalmente no se fusionan, sino que terminan en ChapterEditions separadas. Solo si los capítulos se leen de varios archivos Matroska(TM) o XML que comparten los mismos UIDs de edición, los capítulos se fusionarán en una sola ChapterEdition. Si se desea dicha fusión en otras situaciones, el usuario debe extraer primero los capítulos de todas las fuentes con mkvextract(1), fusionar los archivos XML manualmente y multiplexarlos después.

ETIQUETAS

Introducción

El sistema de etiquetas de Matroska(TM) es similar al de otros contenedores: un conjunto de pares CLAVE=VALOR. Sin embargo, en Matroska(TM), estas etiquetas también pueden anidarse, y tanto la CLAVE como el VALOR son elementos por sí mismos. El archivo de ejemplo example-tags-2.xml muestra cómo utilizar este sistema.

Ámbito de las etiquetas

Las etiquetas de Matroska(TM) no se aplican automáticamente a todo el archivo. Pueden hacerlo, pero también pueden aplicarse a diferentes partes del archivo: a una o varias pistas, a uno o varios capítulos, o incluso a una combinación de ambos. La **especificación de Matroska(TM)**[5] ofrece más detalles sobre este hecho.

Un hecho importante es que las etiquetas se vinculan a pistas o capítulos con el elemento de etiqueta de Matroska(TM) Targets, y que los UID utilizados para este enlace *no* son los ID de pista que mkvmerge(1) utiliza en todas partes. En su lugar, los números utilizados son los UID que mkvmerge(1) calcula automáticamente (si la pista se toma de un formato de archivo distinto de Matroska(TM)) o que se copian del archivo de origen si el archivo de origen de la pista es un archivo Matroska(TM). Por lo tanto, es difícil saber qué UID utilizar en el archivo de etiquetas antes de que el archivo se entregue a mkvmerge(1).

mkvmerge(1) conoce dos opciones con las que puede añadir etiquetas a los archivos Matroska(TM): las opciones --global-tags y --tags. La diferencia es que la primera opción, --global-tags, hará que las etiquetas se apliquen a todo el archivo eliminando cualquiera de esos elementos Targets mencionados anteriormente. La segunda opción, --tags, inserta automáticamente el UID que mkvmerge(1) genera para la etiqueta especificada con la parte TID de la opción --tags.

Ejemplo

Supongamos que desea añadir etiquetas a una pista de vídeo leída desde un AVI. mkvmerge --identify file.avi le indica que el ID de la pista de vídeo (¡no mezcle este ID con el UID!) es 0. Así que crea su archivo de etiquetas, omite todos los elementos Targets y llama a mkvmerge(1):

$ mkvmerge -o file.mkv --tags 0:tags.xml file.avi

Formato del archivo de etiquetas

mkvmerge(1) soporta un formato de archivo de etiquetas basado en XML. El formato está modelado muy de cerca a la **especificación de Matroska(TM)**[5]. Tanto la distribución binaria como la de código fuente de MKVToolNix vienen con un archivo de ejemplo llamado example-tags-2.xml que simplemente enumera todas las etiquetas conocidas y que se puede utilizar como base para archivos de etiquetas reales.

Los conceptos básicos son:

•El elemento más externo debe ser <Tags>.
•Una etiqueta lógica está contenida dentro de un par de etiquetas XML <Tag>.
•Los espacios en blanco directamente antes y después del contenido de la etiqueta se ignoran.

Tipos de datos

El nuevo sistema de etiquetado de Matroska(TM) solo conoce dos tipos de datos, una cadena UTF-8 y un tipo binario. El primero se utiliza para el nombre de la etiqueta y el elemento <String>, mientras que el tipo binario se utiliza para el elemento <Binary>.

Dado que los datos binarios en sí mismos no cabrían en un archivo XML, mkvmerge(1) soporta dos métodos más para almacenar datos binarios. Si el contenido de una etiqueta XML comienza con '@', el texto siguiente se trata como un nombre de archivo. El contenido del archivo correspondiente se copia en el elemento Matroska(TM).

De lo contrario, se espera que los datos estén codificados en Base64. Esta es una codificación que transforma datos binarios en un conjunto limitado de caracteres ASCII y se utiliza, por ejemplo, en programas de correo electrónico. mkvextract(1) generará datos codificados en Base64 para elementos binarios.

El sistema de etiquetado obsoleto conoce algunos tipos de datos más que se pueden encontrar en las especificaciones oficiales de etiquetas de Matroska(TM). Dado que mkvmerge(1) ya no soporta este sistema, estos tipos no se describen aquí.

Etiquetas conocidas para el formato de archivo XML

A continuación, se enumeran las etiquetas XML admitidas, sus tipos de datos y, cuando corresponda, el rango válido para sus valores:

Tags (maestro)
  Tag (maestro)
    Targets (maestro)
      TargetTypeValue (entero sin signo)
      TargetType (cadena UTF-8)
      TrackUID (entero sin signo)
      EditionUID (entero sin signo)
      ChapterUID (entero sin signo)
      AttachmentUID (entero sin signo)
    Simple (maestro)
      Simple (maestro)
      Name (cadena UTF-8)
      TagLanguage (cadena UTF-8)
      DefaultLanguage (entero sin signo)
      String (cadena UTF-8)
      Binary (binario)

INFORMACIÓN DEL SEGMENTO

Con un archivo XML de información de segmento, es posible establecer ciertos valores en el campo de encabezado "información del segmento" de un archivo Matroska(TM). Todos estos valores no se pueden establecer a través de otras opciones de línea de comandos.

Otros campos de encabezado de "información del segmento" se pueden establecer a través de opciones de línea de comandos, pero no a través del archivo XML. Esto incluye, por ejemplo, las opciones --title y --timestamp-scale.

Hay otros elementos que no se pueden establecer ni a través de opciones de línea de comandos ni a través de archivos XML. Estos incluyen los siguientes elementos: DateUTC (también conocido como la "fecha de muxing"), MuxingApp, WritingApp y Duration. Siempre son establecidos por mkvmerge(1).

A continuación, se enumeran las etiquetas XML admitidas, sus tipos de datos y, cuando corresponda, el rango válido para sus valores:

Info (maestro)

DISTRIBUCIÓN DEL ARCHIVO MATROSKA(TM)

La distribución del archivo Matroska(TM) es bastante flexible. mkvmerge(1) renderizará un archivo de una manera predefinida. El archivo resultante se ve así:

[Cabecera EBML] [segmento {meta seek #1} [información del segmento] [información de la pista] {adjuntos} {capítulos} [cluster 1] {cluster 2} ... {cluster n} {cues} {meta seek #2} {etiquetas}]

Los elementos entre llaves son opcionales y dependen del contenido y las opciones utilizadas. Un par de notas:

•meta seek #1 incluye solo un pequeño número de elementos de nivel 1, y solo si existen realmente: adjuntos, capítulos, cues, etiquetas, meta seek #2. Versiones anteriores de mkvmerge(1) solían incluir los clusters en este elemento meta seek también. Por lo tanto, era necesaria una suposición imprecisa para reservar suficiente espacio. A menudo fallaba. Ahora solo los clusters se almacenan en meta seek #2, y meta seek #1 se refiere al elemento meta seek #2.
•Los elementos de adjuntos, capítulos y etiquetas solo están presentes si se agregaron.

El archivo Matroska(TM) más corto posible se vería así:

[Cabecera EBML] [segmento [información del segmento] [información de la pista] [cluster 1]]

Este podría ser el caso de archivos solo de audio.

ARCHIVOS DE MARCA DE TIEMPO EXTERNOS

mkvmerge(1) permite al usuario elegir las marcas de tiempo para una pista específica. Esto se puede usar para crear archivos con video de tasa de fotogramas variable o incluir huecos en el audio. Un fotograma en este caso es la unidad que mkvmerge(1) crea por separado por cada bloque Matroska(TM). Para video, esto es exactamente un fotograma, para audio es un paquete del tipo de audio específico. Por ejemplo, para AC-3 sería un paquete que contiene 1536 muestras.

Los archivos de marcas de tiempo que se utilizan cuando se unen pistas deben especificarse solo para la primera parte en una cadena de pistas. Por ejemplo, si une dos archivos, v1.avi y v2.avi, y quiere usar marcas de tiempo, su línea de comandos debe parecerse a esto:

$ mkvmerge ... --timestamps 0:my_timestamps.txt v1.avi +v2.avi

Hay cuatro formatos que son reconocidos por mkvmerge(1). La primera línea siempre contiene el número de versión. Las líneas vacías, las líneas que solo contienen espacios en blanco y las líneas que comienzan con '#' se ignoran.

Formato de archivo de marca de tiempo v1

Este formato comienza con la línea de versión. La segunda línea declara el número predeterminado de fotogramas por segundo. Todas las líneas siguientes contienen tres números separados por comas: el fotograma de inicio (0 es el primer fotograma), el fotograma final y el número de fotogramas en este rango. Los FPS son un número de punto flotante con el punto '.' como punto decimal. Los rangos pueden contener huecos para los cuales se utilizan los FPS predeterminados. Un ejemplo:

# timestamp format v1
assume 27.930
800,1000,25
1500,1700,30

Formato de archivo de marca de tiempo v2

En este formato, cada línea contiene una marca de tiempo para el fotograma correspondiente. Esta marca de tiempo debe proporcionarse con precisión de milisegundos. Puede ser un número de punto flotante, pero no necesariamente. Debe proporcionar al menos tantas líneas de marca de tiempo como fotogramas haya en la pista. Las marcas de tiempo en este archivo deben estar ordenadas. Ejemplo para 25fps:

# timestamp format v2
0
40
80

Formato de archivo de marca de tiempo v3

En este formato, cada línea contiene una duración en segundos seguida por un número opcional de fotogramas por segundo. Ambos pueden ser números de punto flotante. Si no se proporciona el número de fotogramas por segundo, se utiliza el predeterminado. Para audio, debe dejar que el códec calcule las marcas de tiempo de los fotogramas por sí mismo. Para ello, debe usar 0.0 como número de fotogramas por segundo. También puede crear huecos en el flujo utilizando la palabra clave 'gap' seguida de la duración del hueco. Ejemplo para un archivo de audio:

# timestamp format v3
assume 0.0
25.325
7.530,38.236
gap, 10.050
2.000,38.236

Formato de archivo de marca de tiempo v4

Este formato es idéntico al formato v2. La única diferencia es que las marcas de tiempo no tienen que estar ordenadas. Este formato casi nunca debería usarse.

CÓDIGOS DE SALIDA

mkvmerge(1) sale con uno de tres códigos de salida:

•0 -- Este código de salida significa que la multiplexación se ha completado con éxito.
•1 -- En este caso, mkvmerge(1) ha producido al menos una advertencia, pero la multiplexación continuó. Una advertencia va precedida del texto 'Warning:'. Dependiendo de los problemas involucrados, el archivo resultante puede estar bien o no. Se insta al usuario a verificar tanto la advertencia como el archivo resultante.
•2 -- Este código de salida se utiliza después de que ocurriera un error. mkvmerge(1) se aborta inmediatamente después de mostrar el mensaje de error. Los mensajes de error van desde argumentos de línea de comandos incorrectos, errores de lectura/escritura, hasta archivos rotos.

mkvmerge

mkvmerge - herramienta para fusionar pistas en archivos Matroska

SINOPSIS

mkvmerge [opciones] --output archivo [archivo de entrada...]

DESCRIPCIÓN

mkvmerge es un programa que une varias pistas de diferentes archivos de entrada en un solo archivo Matroska. Se pueden especificar tantos archivos de entrada como se deseen.

OPCIONES

Las opciones se pueden agrupar. Por ejemplo, se puede usar -a 0 -a 1 en lugar de -a 0,1.

Las opciones se pueden usar varias veces. Por ejemplo, -a 0 -a 1 en lugar de -a 0,1.

La mayoría de las opciones de selección de pistas tienen una forma corta y una forma larga.
