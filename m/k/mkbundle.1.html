Mono(mkbundle) Mono(mkbundle)

NOMBRE

mkbundle, mkbundle2 - Crea un ejecutable empaquetado.

SINOPSIS

mkbundle [opciones] assembly1 [assembly2 ...]

DESCRIPCIÓN

mkbundle genera un programa ejecutable que contendrá copias estáticas de los ensamblados listados en la línea de comandos. Por defecto, solo se incluirán en el paquete los ensamblados especificados en la línea de comandos. Para incluir automáticamente todas las dependencias referenciadas, utilice la opción de línea de comandos "--deps".

Hay dos modos de operación, uno usa un binario Mono existente o una lista de binarios alojada en un servidor y se habilita cuando utiliza las opciones de línea de comandos --cross, --sdk o --runtime.

Un mecanismo más antiguo crea un pequeño stub de C que se enlaza con la biblioteca libmono para producir un ejecutable autocontenido y requiere un compilador de C. Se describe en la sección "EMPAQUETADO ANTIGUO" más abajo.

Por ejemplo, para crear un paquete para hola mundo, use el siguiente comando:

$ mkbundle -o hello --simple hello.exe

Puede configurar opciones que se pasarán al tiempo de ejecución de Mono directamente a su ejecutable, para esto, use la bandera --options. Por ejemplo, lo siguiente deshabilita la inserción en línea, pasando la opción de línea de comandos "-O=-inline" al ejecutable incrustado:

$ mkbundle -o hello --options -O=-inline --simple hello.exe
La versión simple permite la compilación cruzada, esto requiere que un tiempo de
ejecución de Mono esté instalado en ~/.mono/targets/TARGET/mono para que esté
disponible. Puede usar "--local-targets" para listar todos los destinos
disponibles, y el argumento "--cross" para especificar el destino,
así:
	$ mkbundle --local-targets	
	Destinos disponibles:
		default	- Mono del Sistema Actual
		4.4.0-macosx-x86
		4.4.0-debian-8-arm64
	$ mkbundle --cross 4.4.0-debian-8-powerpc hello.exe -o hello-debian

Lo anterior empaquetará su biblioteca nativa en hello-debian para un sistema Debian 8 ejecutándose en una máquina PowerPC.

Proporcionamos binarios preempaquetados para Mono para varias arquitecturas, que le permiten compilar de forma cruzada. Use --list-targets para obtener una lista de todos los destinos compatibles, y use la bandera --fetch-target para obtener un destino que no tenga instalado, así:

$ mkbundle --list-targets
Destinos de compilación cruzada disponibles:
4.4.0-linux-libc2.13-amd64
4.4.0-linux-libc2.13-armel
4.4.0-linux-libc2.13-armhf
4.4.0-linux-libc2.13-i386
4.4.0-macos-10.7-amd64
4.4.0-macos-10.7-i386
4.4.2-linux-libc2.13-amd64
4.4.2-linux-libc2.13-armel
4.4.2-linux-libc2.13-armhf
4.4.2-linux-libc2.13-i386
4.4.2-macos-10.7-amd64
4.4.2-macos-10.7-i386
$ mkbundle --fetch-target 4.4.2-macos-10.7-i386

Y luego puede producir un binario que se ejecutará en Mono de 32 bits en MacOS:

$ mkbundle --cross 4.4.2-macos-10.7-i386 hello.exe -o hello-macos

Los destinos descargados se almacenan en el directorio ~/.mono/targets.

OPCIONES

--config ARCHIVO
Especifica que un archivo de configuración DLLMAP Mono también debe ser empaquetado. En los modos simple y de compilación cruzada, si no se especifica ningún archivo de configuración, se elige el del destino actual (ya sea el del sistema en el caso del modo simple, o el que provino del destino de compilación cruzada en el caso del modo de compilación cruzada).
--config-dir DIR
Cuando se pasa, DIR se establecerá para la variable de entorno MONO_CFG_DIR.
--cross destino
Úselo para solicitar a mkbundle que genere un binario compilado de forma cruzada. Crea un paquete para la plataforma de destino especificada. El destino debe ser un directorio en ~/.mono/targets/ que contenga una instalación de SDK producida por la herramienta mono-package-runtime. Puede obtener una lista de las versiones precompiladas del tiempo de ejecución usando --list-targets y puede obtener un destino específico usando la opción de línea de comandos --fetch-target.

Esta bandera es mutuamente excluyente con --sdk que se usa para especificar una ruta absoluta para resolver el tiempo de ejecución de Mono y la opción --runtime que se usa para construir manualmente el paquete multiplataforma.

--deps
Esta opción empaquetará todos los ensamblados referenciados para los ensamblados listados en la opción de línea de comandos. Esto es útil para distribuir una imagen autocontenida.
--env CLAVE=VALOR
Úselo para codificar en tiempo de ejecución una variable de entorno para que CLAVE se mapee a VALOR. Esto es útil en escenarios donde desea habilitar ciertas opciones de configuración del tiempo de ejecución de Mono que se controlan mediante variables de entorno.
--fetch-target destino
Descarga un tiempo de ejecución precompilado para el destino especificado del sitio de distribución de Mono.
--i18n codificación
Especifica qué tablas de codificación se enviarán con el ejecutable. Por defecto, Mono envía el ensamblado de soporte I18N.dll y el ensamblado I18N.West.dll. Si su aplicación utilizará System.Text.Encoding.GetEncoding con codificaciones distintas a las de Oeste, debe especificarlas aquí.

Puede usar el parámetro none para solicitar que no se empaqueten codificaciones implícitas, incluida la I18N.dll de soporte; use esta opción si ha ejecutado un enlazador en el suyo.

Puede usar la bandera all para empaquetar todas las codificaciones disponibles.

O puede usar una lista separada por comas de las palabras CJK, MidWest, Other, Rare y West para especificar qué ensamblados de codificación se distribuirán.

-L ruta
Agrega `ruta` a la lista de búsqueda de ensamblados. Las reglas son las mismas que para las banderas -lib: o -L del compilador.
--library [LIB,]RUTA
Incrusta el archivo de biblioteca dinámica señalado por `RUTA' y opcionalmente le da el nombre `LIB' al ejecutable empaquetado. Esto se usa para enviar dependencias de bibliotecas nativas que se desempaquetan al inicio y se cargan desde el tiempo de ejecución. Se deben especificar múltiples bibliotecas en orden de dependencia, donde las posteriores en la línea de comandos dependen de las anteriores.
--lists-targets
Lista todos los destinos de compilación cruzada locales disponibles como binarios precompilados en el servidor de distribución de Mono.
--local-targets
Lista todos los destinos de compilación cruzada locales disponibles.
--cil-strip RUTA
Proporciona un eliminador de CIL que mkbundle usará si es posible. El uso previsto es ayudar a reducir el tamaño del archivo en AOT.
--in-tree ruta/a/la/raíz/del/código/fuente/de/mono
Proporciona a mkbundle un repositorio de código fuente de mono del cual obtener las cabeceras necesarias para la compilación. Esto permite que mkbundle se ejecute fuera del árbol de código fuente del proyecto, útil para trabajar con múltiples tiempos de ejecución y para probar sin instalar.
--managed-linker RUTA
Proporciona a mkbundle acceso a un enlazador administrado para preprocesar los ensamblados.
--machine-config ARCHIVO
Utiliza el ARCHIVO dado como archivo machine.config para la aplicación generada. La configuración de la máquina contiene un archivo XML que se utiliza en las APIs de System.Configuration para configurar la pila de .NET. Típicamente es $prefix/etc/mono/4.5/machine.config.

Si desea deshabilitar este empaquetado automático, puede usar la bandera --no-machine-config. En los modos simple y de compilación cruzada, si no se especifica ningún archivo machine.config, se elige el del destino actual (ya sea el del sistema en el caso del modo simple, o el que provino del destino de compilación cruzada para el modo de compilación cruzada).

--no-config
En el modo simple o de compilación cruzada, esto evita que mkbundle empaquete automáticamente un archivo de configuración.
--nodeps
Este es el valor predeterminado: mkbundle solo incluirá los ensamblados que se especificaron en la línea de comandos para reducir el tamaño del resultado.
--no-machine-config
Evita que mkbundle incluya automáticamente un archivo machine.config en el ejecutable generado. Esto es útil si planea empaquetar su propio archivo machine.config o si no necesita uno.
-o ARCHIVO
Especifique el nombre del archivo de salida. Si no se proporciona, el nombre del archivo de salida será el del primer ensamblado especificado en la línea de comandos.
--options OPTIONS
Se utiliza para pasar opciones directamente al tiempo de ejecución de Mono. Por ejemplo, para deshabilitar la optimización de inserción en línea, puede usar: --options -O=-inline.
--runtime RUTA
Este modo permite especificar la ruta a un directorio de instalación de Mono que debe usarse para crear el ejecutable empaquetado. Esto es útil si tiene una instalación personalizada de Mono que desea usar para la compilación cruzada. Esta opción es mutuamente excluyente con --cross y --sdk.
--sdk RUTA
Especifica la ruta a un SDK de Mono. Esto le permite a mkbundle usar el Mono SDK especificado para crear el ejecutable empaquetado. Esta opción es mutuamente excluyente con --cross y --runtime.
--simple
Este modo genera un archivo ejecutable más pequeño que depende del tiempo de ejecución de Mono instalado en el sistema de destino. No incrusta el tiempo de ejecución de Mono, lo que resulta en un tamaño de archivo más pequeño, pero requiere que Mono esté instalado en la máquina donde se ejecutará el programa.
--static
Genera un ejecutable estático. Esto significa que el ejecutable no dependerá de ninguna biblioteca externa de Mono y será completamente autónomo. Esto resulta en un archivo de tamaño considerablemente mayor.
--target TARGET
Especifica el destino para la compilación cruzada. Esto es necesario cuando se usa la opción --cross y le dice a mkbundle qué plataforma de destino específica debe empaquetar. Debe ser un nombre de destino válido que mkbundle pueda entender (por ejemplo, '4.4.0-debian-8-powerpc').
--use-sysconfig
Utiliza el archivo de configuración del sistema (`mono-runtime-common`) para la compilación cruzada. Esto significa que mkbundle buscará y utilizará la configuración del sistema existente en lugar de la que viene con el destino de compilación cruzada.

EJEMPLOS

Para crear un ejecutable autocontenido para una aplicación llamada MyApp:

$ mkbundle --deps MyApp.exe -o MyApp

Para crear un ejecutable para una plataforma de destino específica (por ejemplo, ARM):

$ mkbundle --cross 4.4.0-linux-libc2.13-armhf --deps MyApp.exe -o MyApp-arm

Para incluir bibliotecas nativas junto con el ejecutable:

$ mkbundle --library libnative.so MyApp.exe -o MyApp

Cuando se especifica esta bandera, mkbundle resolverá el tiempo de ejecución, las bibliotecas del framework, los recursos no gestionados y los archivos de configuración desde los archivos ubicados en este directorio.

Esta bandera es mutuamente excluyente con --cross

--target-server SERVIDOR
Por defecto, la herramienta mkbundle descargará los tiempos de ejecución de destino de un servidor Mono; puedes especificar un servidor diferente para proporcionar tiempos de ejecución compilados cruzadamente.
--mono-api-struct-path ARCHIVO
ARCHIVO apunta a un archivo con la definición de la estructura BundleMonoAPI que contiene los punteros requeridos a varias funciones de la API de Mono utilizadas en el código generado. Este mecanismo está destinado a ser utilizado por terceros que integran el tiempo de ejecución de Mono y lo cargan e inicializan dinámicamente como parte del inicio de la aplicación, en cuyo caso las APIs de Mono no estarán disponibles para el cargador de bibliotecas compartidas y el paquete fallará (un ejemplo de dicho tercero que lo integra es Xamarin.Android).

Después de proporcionar el ARCHIVO de definición, el integrador debe llamar a la función void initialize_mono_api (const BundleMonoAPI *info) que se encuentra en el código generado **antes** de llamar a void mono_mkbundle_init (). La estructura pasada a initialize_mono_api no necesita ser asignada dinámicamente ya que su contenido se copia a la estructura local en el código generado y no se retiene ni se utiliza ningún puntero a la estructura pasada después de que initialize_mono_api retorna.

La lista de punteros no se documenta aquí. En su lugar, por favor, consulta el archivo bundle-mono-api.inc que se encuentra en el directorio fuente de mkbundle en tu árbol fuente de Mono (mcs/tools/mkbundle) o en el repositorio de GitHub de Mono, https://github.com/mono/mono/blob/master/mcs/tools/mkbundle/bundle-mono-api.inc

Ten en cuenta que tu estructura debe coincidir con la esperada por tu versión del tiempo de ejecución de Mono.

El archivo también debe definir la función mkbundle_log_error con la siguiente firma:

static void mkbundle_log_error (const char *format, ...) {}

La función debe implementar la API de registro específica del integrador.

EMBEDDING ANTIGUO

El antiguo sistema de embedding compila un pequeño stub de C que incrusta el código C y compila el ejecutable resultante usando el compilador del sistema. Esto requiere una instalación funcional de compilador C y solo funciona para agrupar binarios para el host actual.

La característica aún está disponible, pero recomendamos el nuevo modo, más simple, rápido y conveniente.

Por ejemplo, para crear un paquete para hola mundo, usa el siguiente comando:

$ mkbundle -o hello hello.exe

Lo anterior incrustará hello.exe en un programa nativo llamado "hello". Ten en cuenta que la imagen producida todavía contiene la imagen CIL y no se realiza precompilación.

Además, es posible controlar si mkbundle debe compilar el ejecutable resultante o no con la opción -c. Esto es útil si deseas enlazar bibliotecas adicionales o controlar la salida generada con más detalle. Por ejemplo, esto podría usarse para enlazar algunas bibliotecas estáticamente:

$ mkbundle -c -o host.c -oo bundles.o --deps hello.exe
$ cc host.c bundles.o /usr/lib/libmono.a -lc -lrt

También puedes usar mkbundle para generar un paquete que puedas usar al incrustar el tiempo de ejecución de Mono en una aplicación nativa. En ese caso, usa las opciones -c y --nomain. El archivo host.c resultante no tendrá una función main(). Llama a mono_mkbundle_init() antes de inicializar el JIT en tu código para que los ensamblados empaquetados estén disponibles para el tiempo de ejecución incrustado.

OPCIONES DE EMBEDDING ANTIGUO

Estas opciones solo se pueden usar en lugar de usar las opciones --cross, --runtime o --simple.

-c
Produce el archivo stub, no compila el stub resultante.
-oo nombre_archivo
Especifica el nombre que se usará para el archivo objeto auxiliar que contiene el paquete.
--keeptemp
Por defecto, mkbundle eliminará los archivos temporales que usa para producir el paquete. Esta opción mantiene el archivo.
--nomain
Con la opción -c, genera el stub host sin una función main().
--static
Por defecto, mkbundle enlaza dinámicamente a mono y glib. Esta opción hace que enlace estáticamente en su lugar.
-z
Comprime los ensamblados antes de incrustarlos. Esto resulta en archivos ejecutables más pequeños, pero aumenta el tiempo de inicio y requiere que zlib esté instalado en el sistema de destino.

Opciones AOT

Estas opciones admiten un mkbundle que utiliza compilación AOT con enlazado estático. Se requiere una cadena de herramientas de compilador nativo.

--aot-runtime RUTA
Proporciona la ruta al tiempo de ejecución de mono para usar en el AOT de los ensamblados.
--aot-dedup
(Experimental) Deduplica métodos AOT'ed basándose en un acrónimo único de nombres de métodos.
--aot-mode MODO
MODO puede ser "full" o "llvmonly" en este momento. Actualmente, mkbundle soporta tres modos AOT. El modo predeterminado (esta opción no establecida) realizará AOT de métodos pero recurrirá a la generación de código en tiempo de ejecución donde es mucho más rápido u ofrece un perfil de compatibilidad más completo. La configuración "full" generará los stubs necesarios para no requerir la generación de código en tiempo de ejecución. La configuración "llvmonly" hace lo mismo, pero fuerza a que toda la generación de código pase por el backend de llvm.

WINDOWS

Si estás utilizando el antiguo sistema de embedding en sistemas Windows, es posible usar una cadena de herramientas similar a Unix como la de cygwin e instalar los paquetes gcc, gcc-mingw o usar la cadena de herramientas VC de Visual Studio 2015/2017 junto con Clang para Visual Studio como ensamblador. Clang se puede instalar como un componente individual, "Clang/C2", usando el instalador de Visual Studio.

Usando la cadena de herramientas de Visual Studio, mkbundle, por defecto, usará el último compilador y enlazador de Visual Studio instalado, así como el SDK de Windows. Si se ejecuta desde uno de los prompts de comandos de desarrollador de Visual Studio, mkbundle recuperará la información directamente de ese entorno de compilación.

VARIABLES DE ENTORNO

AS
Comando del ensamblador. El valor predeterminado es "as". Para Visual Studio, el predeterminado es "clang.exe". Si "clang.exe" para Visual Studio no está instalado, mkbundle recurrirá a usar "as".
CC
Comando del compilador C. El valor predeterminado es "cc" para Linux, "gcc" para cygwin y "cl.exe" para Visual Studio.
MONO_BUNDLED_OPTIONS
Opciones a pasar al tiempo de ejecución de Mono empaquetado, separadas por espacios. Consulta la página del manual de mono(1) o ejecuta mono --help.

VARIABLES DE ENTORNO DE VISUAL STUDIO PARA WINDOWS

VisualStudioVersion
Versión de Visual Studio utilizada en la compilación de mkbundle. Predeterminada, la última versión instalada de Visual Studio. Valores: "14.0" para Visual Studio 2015 o "15.0" para Visual Studio 2017.
WindowsSdkVersion
Versión del SDK de Windows utilizada en la compilación de mkbundle. Predeterminada/desconocida, la última versión instalada del SDK de Windows. Valores: "8.1", "10.0.10240.0", "10.0.15063.0" etc.
VSCMD_ARG_TGT_ARCH
Arquitectura de destino de salida utilizada en la compilación de mkbundle. Predeterminada/desconocida, utiliza la arquitectura del tiempo de ejecución de .NET que ejecuta mkbundle. Valores: "x86" o "x64". NOTA: al ejecutar desde un prompt de comandos de Visual Studio, esta variable ya debería estar establecida por el prompt de comandos y coincidir con el resto de ese entorno de compilación.
INCLUDE
Anula todas las rutas de inclusión personalizadas pasadas a "cl.exe". Predefinición

WINDOWS VISUAL STUDIO ENVIRONMENT VARIABLES

The following environment variables can be used to override default linker settings.

LIBPATH
Override all custom library paths passed to link.exe. Predefined by Visual Studio developer command prompt or auto detected by mkbundle when undefined.
LIB
Override all custom library paths passed to link.exe. Predefined by Visual Studio developer command prompt or auto detected by mkbundle when undefined.
MONOPREFIX
Use a custom Mono SDK install root matching the output target architecture (x86/x64). Default, mkbundle will look for installed Mono SDK’s matching targeted architecture.
MONOLIB
Use a different mono library name or an absolute path to the mono library passed to linker. Default, mkbundle will use default mono library name depending on mkbundle dynamic/static use case. NOTE, supplied mono library needs to match mkbundle dynamic/static use case and target architecture.
VCCRT
Override C-runtime library linker settings. Default "MD", mkbundle will use dynamic C-runtime linking on Windows compatible with Mono SDK distribution. If a custom built Mono runtime using static C-Runtime linkage is used, setting this variable to "MT" will link using static C-runtime libraries.
VCSUBSYSTEM
Override Windows subsystem. Default, "windows". If console subsystem is preferred, use "console". NOTE, if console output is expected from output target process then set this variable to "console".
