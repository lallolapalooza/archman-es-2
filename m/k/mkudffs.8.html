MKUDFFS(8) Manual del Administrador del Sistema MKUDFFS(8)

NOMBRE

mkudffs — crear un sistema de archivos UDF

SINOPSIS

mkudffs [ opciones ] dispositivo [ conteo-de-bloques ]

DESCRIPCIÓN

mkudffs se utiliza para crear un sistema de archivos UDF en un dispositivo (normalmente un disco). dispositivo es el archivo especial correspondiente al dispositivo (por ejemplo, /dev/hdX) o imagen de archivo. conteo-de-bloques es el número de bloques en el dispositivo. Si se omite, mkudffs calcula automáticamente el tamaño del sistema de archivos. El orden de las opciones importa. La opción de codificación debe ser la primera y las opciones para anular la configuración predeterminada implícita por el tipo de medio o la revisión de UDF deben estar después de la opción que están anulando.

OPCIONES

-h,--ayuda
Muestra el uso y la lista de opciones.
-l,--etiqueta= etiqueta
Especifica la etiqueta UDF. La etiqueta UDF es sinónimo de especificar ambas opciones --lvid y --vid. Si se omite, la etiqueta de mkudffs es LinuxUDF. (Opción disponible desde mkudffs 1.1)
-u,--uuid= uuid
Especifica el uuid UDF. Debe ser exactamente 16 dígitos hexadecimales en minúsculas y se utiliza para los primeros 16 caracteres de la opción --fullvsid. Si se omite, el uuid de mkudffs se genera a partir de la hora local y un número aleatorio. (Opción disponible desde mkudffs 1.1)
-b,--tamaniobloque= tamaño-bloque
Especifica el tamaño de los bloques en bytes. Un tamaño de bloque válido para un sistema de archivos UDF es una potencia de dos en el rango de 512 a 32768 y debe coincidir con el tamaño lógico (sector) del dispositivo. Si se omite, el tamaño de bloque de mkudffs se establece en el tamaño lógico de bloque (sector) del dispositivo. Si el tamaño lógico de bloque (sector) se desconoce (por ejemplo, al crear una imagen de disco), entonces para --tipomedio=hd se utiliza un tamaño de bloque de 512 y para otros tipos de medio de 2048. (Antes de mkudffs 1.1, el valor predeterminado era siempre 2048 independientemente de --tipomedio)
-m,--tipomedio= tipo-medio
Especifica el tipo de medio. Debe especificarse antes de --udfrevision. El valor predeterminado se autodetecta. Cuando la autodetección no funciona (por ejemplo, al crear una imagen de disco), se asume el valor hd. Los tipos de medio válidos son:
hd
HD (Disco Duro)
worm
WORM (Write Once Read Many)
mo
MO (Magneto-Óptico)
cd
CD-ROM (CD de solo lectura)
cdr
CD-R (CD grabable)
cdrw
CD-RW (CD de lectura-escritura)
dvd
DVD-ROM (DVD de solo lectura)
dvdr
DVD-R (DVD grabable)
dvdrw
DVD-RW (DVD de lectura-escritura)
dvdram
DVD-RAM (Memoria de acceso aleatorio DVD)
bdr
BD-R (Disco Blu-ray grabable)
(La variante de opción corta -m y los valores cd, dvdr, bdr están disponibles desde mkudffs 2.0 y la autodetección es compatible desde mkudffs 2.2)
-r,--udfrevision= revision-udf
Especifica la revisión UDF a utilizar, ya sea en BCD hexadecimal (por ejemplo, 0x0201) o decimal (por ejemplo, 2.01). Las revisiones válidas son 1.01, 1.02, 1.50, 2.00, 2.01, 2.50 y 2.60. Si se omite, la revisión UDF de mkudffs es 2.01, excepto para los discos Blu-ray, que es 2.50. Las revisiones UDF superiores a 2.01 son experimentales. La opción debe especificarse después de --tipomedio. (Los valores en formato decimal y las revisiones UDF superiores a 2.01 son compatibles desde mkudffs 2.0, la revisión UDF 1.01 es compatible desde mkudffs 2.1)
-n,--no-escribir
En realidad no, no escribir en dispositivo. Solo simular y mostrar lo que sucedería con dispositivo. Útil para determinar la ubicación calculada de diferentes bloques UDF. (Opción disponible desde mkudffs 2.0)
--nuevo-archivo
Crea un nuevo archivo de imagen especificado por dispositivo con conteo-de-bloques y falla si el archivo ya existe. Si se omite, mkudffs crea un nuevo archivo de imagen solo en caso de que aún no exista. (Opción disponible desde mkudffs 2.0)
--lvid= identificador-volumen-logico
Especifica el Identificador de Volumen Lógico. Si se omite, el Identificador de Volumen Lógico de mkudffs es LinuxUDF. La mayoría de las implementaciones UDF utilizan este identificador como etiqueta de disco.
--vid= identificador-volumen
Especifica el Identificador de Volumen. Si se omite, el Identificador de Volumen de mkudffs es LinuxUDF.
--vsid= identificador-conjunto-volumen
Especifica el carácter 17 al 127 de Identificador de Conjunto de Volumen. Si se omite, el Identificador de Conjunto de Volumen de mkudffs es LinuxUDF.
--fsid= identificador-conjunto-archivos
Especifica el Identificador de Conjunto de Archivos. Si se omite, el Identificador de Conjunto de Archivos de mkudffs es LinuxUDF.
--fullvsid= identificador-conjunto-volumen-completo
Especifica el Identificador de Conjunto de Volumen completo. Anula las opciones anteriores --uuid y --vsid. (Opción disponible desde mkudffs 1.1)
--propietario= nombre-propietario
Especifica el nombre del Propietario, la persona que crea el medio o el sistema de archivos. Se almacena en UDF Logical Volume Info1, parte del Descriptor de Volumen de Uso de Implementación UDF. (Opción disponible desde mkudffs 2.3)
--organizacion= nombre-organizacion
Especifica el nombre de la Organización responsable de crear el medio o el sistema de archivos. Se almacena en UDF Logical Volume Info2, parte del Descriptor de Volumen de Uso de Implementación UDF. (Opción disponible desde mkudffs 2.3)
--contacto= informacion-contacto
Especifica la información de Contacto del medio o sistema de archivos. Se almacena en UDF Logical Volume Info3, parte del Descriptor de Volumen de Uso de Implementación UDF. (Opción disponible desde mkudffs 2.3)
--uid= uid
Especifica el uid de la raíz (/) del directorio. Si se omite, el uid de mkudffs es 0. El valor especial -1 significa uid inválido o no especificado. (Opción disponible desde mkudffs 1.1)
--gid= gid
Especifica el gid de la raíz (/) del directorio. Si se omite, el gid de mkudffs es 0. El valor especial -1 significa gid inválido o no especificado. (Opción disponible desde mkudffs 1.1)
--modo= modo
Especifica los permisos en modo octal de la raíz (/) del directorio. Si se omite, el modo de mkudffs es 0755. (Opción disponible desde mkudffs 2.0)
--solo-lectura
Esta opción especifica que todo el disco UDF debe tratarse como de solo lectura. Establece la bandera de dominio SoftWriteProtect en el Descriptor de Volumen Lógico y en el Descriptor de Conjunto de Archivos. Además, para los tipos de medios regrabables (hd, dvdram, dvdrw) establece el Tipo de Acceso UDF a solo lectura. (Opción disponible desde mkudffs 2.2)
--areadeboot= relleno
Especifica cómo llenar el área de arranque UDF, que son los primeros 32 kB del disco y no se utilizan por UDF en sí. La opción
mbr sólo tiene sentido cuando se ejecuta mkudffs en disco completo, no en una sola partición. Las opciones válidas son:
preserve
conservar el área de arranque UDF existente, no tocarla (por defecto para tipos de medios diferentes de hd)
erase
borrar el área de arranque UDF existente, llenarla con ceros (por defecto para tipo de medio hd en particiones y en discos extraíbles)
mbr
poner una tabla MBR con una partición que comienza en el sector 0 (incluye la propia MBR) y abarca todo el dispositivo de disco, necesario solo para discos duros no extraíbles utilizados en sistemas Microsoft Windows (por defecto para tipo de medio hd en discos duros no extraíbles sin particiones), ver sección DISCO COMPLETO VS PARTICIÓN
mbr:sec-size
igual que mbr pero estableciendo explícitamente el tamaño del sector MBR a sec-size, el valor por defecto de sec-size es el tamaño del bloque lógico (sector) del dispositivo con un valor de reserva de 512 bytes
(Opción disponible desde mkudffs 2.0)
--strategy= strategy
Especificar la estrategia de asignación a utilizar. Las estrategias válidas son 4 y 4096. Si se omite, la estrategia de mkudffs se basa en --media-type.
--spartable, --spartable= spartable-number
Habilitar el uso de la Tabla de Reposición (Sparing Table). Opcionalmente, especificar también el número de tablas de reposición. Los números válidos son 1–4. Cuando se omite el número de tablas de reposición, se escriben dos tablas en el disco. Si se omite la opción, el uso de la Tabla de Reposición depende del tipo de medio. (Opción anterior a mkudffs 2.0 solo disponible para tipo de medio cdrw)
--sparspace= num-of-entires
Especificar el número de entradas en la Tabla de Reposición. Si se omite, el número por defecto de entradas es 1024, pero depende del tipo de medio. (Opción disponible desde mkudffs 2.0)
--packetlen= length
Longitud del paquete en número de bloques utilizada para la alineación. Todas las estructuras UDF continuas se alinearán a paquetes. También especifica el tamaño del Espacio de Reposición y la longitud del paquete en la Tabla de Reposición. Debería coincidir con la longitud de ECC/paquete del dispositivo. Si se omite, el valor por defecto para discos DVD es de 16 bloques, para discos CD/BD es de 32 bloques y en otros casos 1 bloque. (Opción anterior a mkudffs 2.1 solo disponible para tipos de medio cdrw y dvdrw)
--vat
Habilitar el uso de la Tabla de Asignación Virtual (VAT). Si se omite, el uso depende del tipo de medio. (Opción disponible desde mkudffs 2.0)
--startblock= start-block
Especificar la ubicación del bloque donde comienza el sistema de archivos UDF.

Normalmente, el bloque de inicio es 0, pero al crear la segunda o siguiente sesión para un disco óptico UDF multisesión, es la ubicación del bloque donde comienza esa nueva sesión.

Al actualizar un archivo de imagen UDF multisesión existente, mkudffs sobrescribe solo los bloques de datos de una nueva sesión en la posición del bloque de inicio en el archivo de imagen.

Al crear un nuevo archivo de imagen UDF, mkudffs solo almacena los bloques de datos de una nueva sesión al principio del archivo de imagen. Por lo tanto, los datos para el bloque de inicio se escribirían en el bloque cero en lugar del bloque de inicio. Dicha imagen sin los bloques iniciales (donde se ubican las sesiones anteriores) es adecuada para grabar una nueva sesión en el disco óptico. Pero no puede ser leída ni detectada por ninguna herramienta UDF hasta que los bloques cero iniciales (o las sesiones anteriores) se antepongan al archivo de imagen.

Para calcular la posición donde debería comenzar una nueva sesión de un disco óptico particular, se requiere utilizar software que se utilizará para grabar la imagen recién creada. Así, por ejemplo, si para grabar se utiliza wodim(1), entonces el segundo valor en la salida de la llamada wodim -msinfo es el bloque de inicio. De manera similar, para la llamada a cdrecord(1) cdrecord -msinfo o para la llamada a cdrdao(1) cdrdao msinfo o para la llamada a xorriso(1) xorriso -as cdrecord dev=/dev/cdrw -msinfo.

(Opción disponible desde mkudffs 2.3)

--minblocks= min-num-of-blocks
Especificar el número mínimo de bloques a escribir en el disco con Tabla de Asignación Virtual.

Esta opción afecta la posición del bloque donde se escribe la Tabla de Asignación Virtual. Y en caso de que se use la opción --closed, también afecta la posición del bloque del segundo Puntero al Descriptor del Volumen de Ancla.

El valor por defecto para el tipo de medio cdr es 300. Este es un valor seguro por defecto para permitir la grabación de imágenes de disco CD-R en modo Track-at-Once. Este modo requiere grabar la imagen con un tamaño mínimo de 300 sectores. La grabación de discos CD-R en otros modos (por ejemplo, Disc-at-Once o Packet-Writing) puede permitir utilizar también imágenes de disco más pequeñas.

Para todos los demás tipos de medios, no hay un límite mínimo por defecto.

(Opción disponible desde mkudffs 2.3)

--closed
Cerrar el disco con Tabla de Asignación Virtual. El AVDP también se escribe al final del disco. Por defecto, el disco con Tabla de Asignación Virtual no se cierra.
--space= space
Especificar el Conjunto de Espacio (Space Set). El Conjunto de Espacio No Asignado (Unallocated) se utiliza para medios cuyos bloques pueden asignarse inmediatamente. El Conjunto de Espacio Liberado (Freed) se utiliza para medios cuyos bloques necesitan ser preparados/borrados especialmente antes de la asignación. En la Tabla de Espacio se almacena la lista de extensiones no asignadas. En el Mapa de Bits de Espacio se almacena un mapa de bits de los bloques no asignados. No se utiliza para VAT.
freedbitmap
Mapa de Bits Liberado
freedtable
Tabla de Espacio Liberado
unallocbitmap
Mapa de Bits No Asignado (por defecto)
unalloctable
Tabla de Espacio No Asignado
--ad= ad
Especificar los Descriptores de Asignación del directorio raíz (/).
inicb
Descriptores de Asignación en ICB (por defecto)
short
Descriptores de Asignación Cortos
long
Descriptores de Asignación Largos
--noefe
No utilizar Entradas de Archivo Extendidas para el directorio raíz (/). Afecta solo a UDF 2.00 o superior. Debe especificarse después de --udfrev.
--locale
Tratar las opciones de cadena de identificador como cadenas codificadas según la configuración regional actual (por defecto). Debe especificarse como el primer argumento. (Opción disponible desde mkudffs 2.0)
--u8
Tratar las opciones de cadena de identificador como cadenas codificadas en formato Unicode Comprimido OSTA de 8 bits sin el byte de ID de compresión inicial, lo que equivale a Latin1 (ISO-8859-1). Debe especificarse como primer argumento.
--u16
Tratar las opciones de cadena de identificador como cadenas codificadas en formato Unicode Comprimido OSTA de 16 bits sin el byte de ID de compresión inicial, lo que equivale a UTF-16BE. Tenga en cuenta que no es posible incluir el byte cero en las opciones de línea de comandos, por lo tanto, cualquier carácter que tenga al menos un byte cero no puede ser proporcionado (esto se aplica a todos los caracteres Latin1). Debe especificarse como el primer argumento.
--utf8
Tratar las opciones de cadena de identificador como cadenas codificadas en UTF-8. Debe especificarse como el primer argumento. (Antes de mkudffs 2.0 esta era la opción por defecto)

NAME

mkudffs - make an UDF filesystem

SYNOPSIS

mkudffs [-v] [-o] [-l label] [-u] [-U] [-b blocksize] [-a alligment] [--bootarea=mbr] [--utf8] [--u16] [--hardlink] device [filesystem-size]

DESCRIPTION

The mkudffs utility is used to create an Universal Disk Format (UDF) filesystem on a storage device.

UDF is a standard filesystem for optical media, but it is also supported by some operating systems for hard drives and flash media.

The following table lists operating system support for UDF filesystems with different revisions.

Operating System Revision Max. Read Max. Write
Windows 1.02 98 98
1.50 Me, 2000, XP Me, 2000, XP
Windows Vista and newer 1.50 2.01 2.01
2.00 2.01 2.01
2.01 2.60 2.50
Mac OS 9.1 – 9.2 1.50 1.50
9.3 2.01 none
Mac OS X 10.0 – 10.3 1.50 1.50
10.4 2.01 2.01
10.5 (and new) 2.60 2.50
FreeBSD 5 (and new) 1.50 none
7 (and new) 2.01 2.01
NetBSD 4.0 (and new) 2.60 2.60
OpenBSD 3.8 – 3.9 1.02 none
4.0 – 4.6 1.50
4.7 (and new) 2.60
Solaris 7 (and new) 1.50 1.50
AIX 5.2 (and new) 2.01 2.01

Note that Windows 98 and Windows Me can read UDF filesystem only from CD and DVD optical discs, not from hard disks.

BLOCK SIZE

In most cases, operating systems are unable to mount UDF filesystem if UDF block size differs from logical sector size of the device. Typically hard disks have sector size 512 bytes and optical media 2048 bytes. Therefore UDF block size must match the logical sector size of the device.

Linux kernel prior to version 2.6.30 used hardcoded UDF block size of 2048 bytes independently of logical sector size, therefore it was not able to automatically mount UDF filesystem if block size differed from 2048. Since 2.6.30 and prior to 4.11 Linux kernel used a logical sector size of the device as UDF block size, plus it tried fallback to 2048. Since 4.11 it uses logical sector size and fallbacks to any valid block size between logical sector size and 4096. Therefore since version 2.6.30 Linux kernel can automatically mount UDF filesystems correctly if UDF block size matches device logical sector size and since version 4.11 can automatically also mount devices which sector size does not match UDF block size. In any case and also for Linux kernel prior to version 2.6.30, different UDF block size (which is not autodetected) can be manually specified via bs=blocksize mount parameter.

WHOLE DISK VS PARTITION

UDF filesystem is supposed to be formatted on the whole media and not to the partitioned hard disk. Mac OS X systems enforce this rule and reject to automatically mount UDF filesystem unless it is formatted on the whole unpartitioned hard disk. Possible partition table (e.g. MBR or GPT) on disk with valid UDF filesystem is ignored. On the other hand, Microsoft Windows systems are unable to detect non-removable hard disks without MBR or GPT partition table. Removable disks do not have this restriction. A consequence is that non-removable hard disks formatted to UDF by Windows Vista+ are not recognized by Mac OS X systems and vice-versa. Note that manual mount of UDF partition on partitioned hard disk on Mac OS X system is possible and working (e.g. by running commands: mkdir /Volumes/DriveName && mount_udf /dev/disk1s1 /Volumes/DriveName). But there is no known way to mount an unpartitioned non-removable disk on Windows system.

Thanks to reserved and unused UDF boot area (first 32kB of UDF filesystem) it is possible to deal with this problem, by putting MBR on such non-removable hard disk just for compatibility reasons with Windows. Such MBR table would contain one partition which starts at sector 0 (includes MBR itself) and spans whole disk device. So the whole disk device and also the first partition on disk points to same sectors. Therefore UDF filesystem can be mounted either from whole disk device (needed for Mac OS X systems) or from first partition (needed for Microsoft Windows systems).

Linux kernel ignores MBR table if contains partition which starts at sector 0. Normally Linux kernel can detect and mount UDF filesystem either on a partition or on whole disk device. It does not have any restrictions.

mkudffs option --bootarea=mbr put such MBR table for compatibility with Microsoft Windows systems into disk when formatting.

LINUX LABEL BUGS

In most cases Logical Volume Identifier is used as UDF label. But Linux libblkid prior to version 2.26 used Volume Identifier. Therefore mkudffs --label for compatibility reasons set both Logical Volume Identifier and Volume Identifier.

Linux libblkid prior to version 2.30 incorrectly processed non-ASCII identifier strings encoded in 8-bit OSTA Compressed Unicode format. Therefore mkudffs since version 2.0 for compatibility reasons tries to encode a non-ASCII identifier strings in 16-bit OSTA Compressed Unicode format and then fallbacks to 8-bit format.

For more information about UDF Label and UUID see udflabel(8) section UDF LABEL AND UUID.

EXIT STATUS

mkudffs returns 0 if successful, non-zero if there are problems.

LIMITATIONS

mkudffs cannot create UDF 2.50 Metadata partition, therefore it does not support UDF revisions higher than 2.01 for non Write Once media yet. So there is no support for Blu-ray discs which needs UDF 2.50 (except for Blu-ray Disc Recordable which does not require Metadata partition).

mkudffs prior to version 2.2 was unable to process Unicode strings with code points above U+FFFF. When option --utf8 was specified then input strings were limited to 3-byte UTF-8 sequences and when option --u16 was specified then input strings were limited just to UCS-2BE strings (subset of UTF-16BE).

BUGS

mkudffs prior to version 1.1 was unable to process non-ASCII characters from identifier strings in --utf8 mode, --vsid option was completely broken and --blocksize must have been manually specified for hard disks as default value was hardcoded for optical disks. mkudffs prior to version 2.0 generated broken and unreadable cdr disc images.
