mkosi Changelog

v25

•
En lugar de usar bubblewrap, el aislamiento ahora se realiza con una nueva herramienta mkosi-sandbox. Esta herramienta tiene una API pública y puede utilizarse independientemente de mkosi.
•
Las compilaciones de imágenes ahora se realizan en un espacio de nombres de usuario con un solo usuario cuando se ejecuta sin privilegios en lugar de usar newuidmap/newgidmap. Al ejecutarse sin privilegios, todos los archivos y directorios de la imagen serán propiedad del usuario que la invoca (y de root dentro de cualquier archivo producido). Cualquier intento de cambiar la propiedad de archivos a otros usuarios en scripts fallará a menos que la nueva variable de entorno $MKOSI_CHROOT_SUPPRESS_CHOWN se establezca en un valor verdadero.
•
mkosi ya no reduce privilegios al usuario que llama cuando se ejecuta como root para varios pasos.
•
Un nuevo verbo cat-config mostrará todos los archivos de configuración que se incluyeron para cada imagen configurada.
•
Se añadió soporte para Azure Linux
•
Se añadió soporte para Kali Linux
•
Si mkosi.version es ejecutable, ahora lo ejecutamos y leemos la versión de la salida estándar.
•
Se añadió --wipe-build-dir para eliminar el directorio de compilación antes de recompilar la imagen.
•
Se introdujo RepositoryKeyFetch= para controlar si se obtienen las claves GPG de distribución de forma remota. Esta configuración está **deshabilitada** por defecto por razones de seguridad, excepto al compilar imágenes basadas en rpm o Arch Linux en Ubuntu.
•
Ahora manejamos SIGHUP de forma elegante
•
Las configuraciones universales que toman una colección de valores ya no se pueden añadir en subimágenes. El uso de árboles de gestores de paquetes en subimágenes deberá trasladarse a la imagen de nivel superior. Del mismo modo, los repositorios deberán habilitarse en la imagen de nivel superior.
•
Los metadatos del repositorio ya no se copian en las imágenes.
•
Los metadatos del repositorio de los árboles base ya no se utilizan.
•
Los árboles de gestores de paquetes ahora se llaman árboles sandbox.
•
Los árboles de gestores de paquetes (árboles sandbox) ya no utilizan los árboles esqueleto como su valor predeterminado si no están establecidos.
•
Nota para empaquetadores: Las páginas del manual se han movido a resources/man y ahora incluyen páginas del manual para mkosi-initrd y mkosi-sandbox.
•
InitrdInclude= se eliminó. Si estás usando InitrdInclude=, por favor, compila tu initrd a través de una subimagen en mkosi.images que contenga Include=mkosi-initrd y cualquier personalización que desees añadir y utiliza la configuración Initrds= para usarla como initrd para la imagen principal en lugar del initrd predeterminado.
•
Se añadió History= para que mkosi guarde la configuración utilizada para compilar la imagen y la reutilice cuando se invoquen verbos como qemu, boot, ... sin -f.
•
Se introdujo la nueva sección [Build] y se movieron varias configuraciones a ella.
•
Se movió Include= a la sección [Include].
•
Se añadió el verbo sysupdate como un envoltorio para systemd-sysupdate, que lo invoca con las definiciones de mkosi.sysupdate.
•
Se añadió RuntimeHome= para montar el directorio home actual en /root al ejecutar un comando que arranca la imagen
•
Más directorios además de /etc y /usr se recogen ahora de los árboles sandbox (anteriormente conocidos como árboles de gestor de paquetes).
•
La configuración del perfil de mkosi.profiles ahora se analiza después de mkosi.conf.d en lugar de antes. Para establecer valores predeterminados para su uso en mkosi.conf.d basándose en el perfil configurado, usa un dropin temprano en mkosi.conf.d que coincida con el perfil configurado.
•
Profile= se renombra a Profiles= y ahora toma una lista separada por comas de perfiles. Los scripts ahora reciben $PROFILES con una lista separada por espacios de perfiles en lugar de $PROFILE. El especificador %p para perfiles se elimina.
•
Se recogen ahora múltiples scripts sync, prepare, build, postinst, finalize, postoutput y clean de mkosi.$SCRIPT.d.
•
run0 se utiliza ahora automáticamente para escalar privilegios para comandos que lo necesitan, como el verbo burn.
•
/usr/share/keyrings y /usr/share/distribution-gpg-keys ya no se recogen automáticamente del árbol de herramientas cuando ToolsTreeCertificates= está establecido, ya que no son certificados, usa un árbol sandbox en su lugar. Esto permite anular las claves de SignedBy= para repositorios APT.
•
Las credenciales agetty.autologin y login.noauth ya no se establecen incondicionalmente.
•
Se eliminó el acceso al directorio de salida en los scripts de compilación. Para colocar artefactos del directorio de compilación en el directorio de salida, cópialos del directorio de compilación al directorio de salida en un script post-instalación que sí tenga acceso al directorio de compilación y al directorio de salida.
•
BuildDirectory= ya no está disponible en PrepareScripts=. Si necesitas adquirir archivos para el proceso de compilación, colócalos en un lugar apropiado dentro de $BUILDROOT para que puedan ser cacheados al compilar incrementalmente.
•
Al usar un árbol de herramientas y un sandbox relajado para ejecutar un comando (qemu, nspawn, ...), ahora mantenemos intactas todas las entradas de $PATH fuera de /usr. Ten en cuenta que esto puede causar problemas si una entrada de $PATH contiene binarios enlazados contra bibliotecas en /usr del host.
•
Se introdujo un nuevo especificador %I que se resuelve al nombre de la subimagen actual cuando se usa en una configuración bajo mkosi.images/. Esto difiere de %o ya que siempre es el nombre del archivo de configuración sin extensión (o el nombre del directorio).
•
Si se encuentra /dev/fuse en el contexto del host, también se hace disponible en el contexto del sandbox.
•
Se añadió un verbo sandbox para ejecutar un comando dentro de un sandbox mkosi relajado (el mismo sandbox en el que se ejecutan mkosi vm, mkosi boot, ...).
•
Los proveedores OpenSSL ahora son compatibles como fuentes de claves para las diversas configuraciones de claves si se utiliza una versión de systemd lo suficientemente reciente (257 o posterior).
•
Se añadió soporte para cargar certificados X.509 desde proveedores OpenSSL si se utiliza una versión de systemd lo suficientemente reciente (257 o posterior).
•
Se añadió ToolsTreePackageDirectories=
•
Se añadió --kernel-image= a mkosi-initrd para especificar la imagen del kernel a utilizar al compilar un UKI.
•
Establecer una configuración basada en colección a una cadena vacía a través de la CLI y luego añadir a la misma configuración ahora anulará las configuraciones provenientes de los archivos de configuración, mientras que anteriormente los valores de la CLI se añadirían a los valores de los archivos de configuración.
•
La configuración predeterminada de mkosi-initrd ahora incluye varios módulos de kernel adicionales por defecto.
•
Los verbos coredumpctl y journalctl ahora operarán siempre sobre la imagen, incluso si ForwardJournal= está configurado.
•
Se actualizó la versión predeterminada de Fedora a 41.
•
Se añadió el formato de salida addon para compilar complementos de UKI.
•
Se renombró la sección [Host] a [Runtime]

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

Consulta https://systemd.io/DISCOVERABLE_PARTITIONS para obtener detalles sobre imágenes de disco firmadas. Esta información es utilizada por systemd-nspawn, systemd-dissect, systemd-sysext, systemd-portabled y la configuración RootImage= de systemd (entre otros) para validar criptográficamente los sistemas de archivos de la imagen antes de usarlos.

When --prepare-script=/--build-script=/--finalize-script= is used with an empty argument, the corresponding script will not be called.

Python 3.7 is the minimal supported version.

v10

•
Minimum supported Python version is now 3.7.
•
Automatic configuration of the network for Arch Linux was removed to bring different distros more in line with each other. To add it back, add a postinstall script to configure your network manager of choice.
•
The --default option was changed to not affect the search location of mkosi.default.d/. mkosi now always searches for mkosi.default.d/ in the working directory.
•
quiet was dropped from the default kernel command line.
•
--source-file-transfer and --source-file-transfer-final now accept an empty value as the argument which can be used to override a previous setting.
•
A new command mkosi serve can be used to serve build artifacts using a small embedded HTTP server. This is useful for machinectl pull-raw ... and machinectl pull-tar ....
•
A new command mkosi genkey can be used to generate secure boot keys for use with mkosi’s --secure-boot options. The number of days the keys should remain valid can be specified via --secure-boot-valid-days= and their CN via --secure-boot-common-name=.
•
When booting images with qemu, firmware that supports Secure Boot will be used if available.
•
--source-resolve-symlinks and --source-resolve-symlinks-final options are added to control how symlinks in the build sources are handled when --source-file-transfer[-final]=copy-all is used.
•
--build-environment= option was added to set variables for the build script.
•
--usr-only option was added to build images that comprise only the /usr/ directory, instead of the whole root file system. This is useful for stateless systems where /etc/ and /var/ are populated by systemd-tmpfiles/systemd-sysusers and related calls at boot, or systems that are originally shipped without a root file system, but where systemd-repart adds one on the first boot.
•
Support for “image versions” has been added. The version number can be set with --version-number=. It is included in the default output filename and passed as $IMAGE_VERSION to the build script. In addition, mkosi bump can be used to increase the version number by one, and --auto-bump can be used to increase it automatically after successful builds.
•
Support for “image identifiers” has been added. The id can be set with --image=id and is passed to the build script as $IMAGE_ID.
•
The list of packages to install can be configured with --base-packages=. With --base-packages=no, only packages specified with --packages= will be installed. With --base-packages=conditional, various packages will be installed “conditionally”, i.e. only if some other package is otherwise pulled in. For example, systemd-udev may be installed only if systemd is listed in --packages=.
•
CPIO output format has been added. This is useful for kernel initramfs images.
•
Output compression can be configured with --compress-fs= and --compress-output=, and support for zstd has been added.
•
--ssh-key= option was added to control the ssh key used to connect to the image.
•
--remove-files= option was added to remove file from the generated images.
•
Inline comments are now allowed in config files (anything from # until the end of the line will be ignored).
•
The development branch was renamed from master to main.

v9

Highlighted Changes

•
The mkosi Github action now defaults to the current release of mkosi instead of the tip of the master branch.
•
Add a ssh verb and accompanying --ssh option. The latter sets up SSH keys for direct SSH access into a booted image, whereas the former can be used to start an SSH connection to the image.
•
Allow for distribution specific mkosi.* files in subdirectories of mkosi.default.d/. These files are only processed if a subdirectory named after the target distribution of the image is found in mkosi.default.d/.
•
The summary of used options for the image is now only printed when building the image for the first time or when the summary verb is used.
•
All of mkosi’s output, except for the build script, will now go to stderr. There was no clear policy on this before and this choice makes it easier to use images generated and booted via mkosi with language servers using stdin and stdout for communication.
•
--source-file-transfer now defaults to copy-git-others to also include untracked files.
•
black is now used as a code style and conformance with it is checked in CI.
•
Add a new --ephemeral option to boot into a temporary snapshot of the image that will be thrown away on shutdown.
•
Add a new option --network-veth to set up a virtual Ethernet link between the host and the image for usage with nspawn or QEMU
•
Add a new --autologin option to automatically log into the root account upon boot of the image. This is useful when using mkosi for boot tests.
•
Add a new --hostonly option to generate host specific initrds. This is useful when using mkosi for boot tests.
•
Add a new --install-directory option and special directory mkosi.installdir/ that will be used as $DESTDIR for the build script, so that the contents of this directory can be shared between builds.
•
Add a new --include-directory option and special directory mkosi.includedir/ that will be mounted at /usr/include during the build. This way headers files installed during the build can be made available to the host system, which is useful for usage with language servers.
•
Add a new --source-file-transfer-final option to complement --source-file-transfer. It does the same --source-file-transfer does for the build image, but for the final one.
•
Add a new --tar-strip-selinux-context option to remove SELinux xattrs. This is useful when an image with a target distribution not using SELinux is generated on a host that is using it.
•
Document the --no-chown option. Using this option, artifacts generated by mkosi are not chowned to the user invoking mkosi when it is invoked via sudo. It has been with as for a while, but hasn’t been documented until now.
