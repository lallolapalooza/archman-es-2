mkdir(2) Manual de llamadas al sistema mkdir(2)

NOMBRE

mkdir, mkdirat - crear un directorio

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/stat.h>
int mkdir(const char *path, mode_t mode);
#include <fcntl.h>           /* Definición de constantes AT_* */
#include <sys/stat.h>
int mkdirat(int dirfd, const char *path, mode_t mode);
Requisitos de Macro de Prueba de Funciones para glibc (ver feature_test_macros(7)):

mkdirat():

    Desde glibc 2.10:
        _POSIX_C_SOURCE >= 200809L
    Antes de glibc 2.10:
        _ATFILE_SOURCE

DESCRIPCION

mkdir() intenta crear un directorio llamado path.

El argumento mode especifica el modo para el nuevo directorio (ver inode(7)). Se modifica por el umask del proceso de la manera habitual: en ausencia de una ACL predeterminada, el modo del directorio creado es (mode & ~umask & 0777). Si otros bits de mode se tienen en cuenta para el directorio creado depende del sistema operativo. Para Linux, ver VERSIONES más abajo.

El directorio recién creado será propiedad del ID de usuario efectivo del proceso. Si el directorio que contiene el archivo tiene el bit set-group-ID activado, o si el sistema de archivos está montado con semántica de grupo BSD (mount -o bsdgroups o, de forma sinónima, mount -o grpid), el nuevo directorio heredará la propiedad de grupo de su padre; de lo contrario, será propiedad del ID de grupo efectivo del proceso.

Si el directorio padre tiene el bit set-group-ID activado, el nuevo directorio también lo tendrá.

mkdirat()

La llamada al sistema mkdirat() opera exactamente de la misma manera que mkdir(), excepto por las diferencias descritas aquí.

Si path es relativo, se interpreta en relación con el directorio al que se refiere el descriptor de archivo dirfd (en lugar de en relación con el directorio de trabajo actual del proceso llamante, como hace mkdir() para un nombre de ruta relativo).

Si path es relativo y dirfd es el valor especial AT_FDCWD, entonces path se interpreta en relación con el directorio de trabajo actual del proceso llamante (como mkdir()).

Si path es absoluto, dirfd se ignora.

Ver openat(2) para una explicación de la necesidad de mkdirat().

VALOR DE RETORNO

mkdir() y mkdirat() devuelven cero en caso de éxito. En caso de error, devuelven -1 y errno se establece para indicar el error.

ERRORES

EACCES
El directorio padre no permite permisos de escritura al proceso, o uno de los directorios en path no permitía permisos de búsqueda. (Ver también path_resolution(7)).
EBADF
(mkdirat()) path es relativo pero dirfd no es AT_FDCWD ni un descriptor de archivo válido.
EDQUOT
La cuota del usuario de bloques de disco o inodos en el sistema de archivos se ha agotado.
EEXIST
path ya existe (no necesariamente como un directorio). Esto incluye el caso en que path sea un enlace simbólico, colgante o no.
EFAULT
path apunta fuera de su espacio de direcciones accesible.
EINVAL
El componente final ("nombre base") del nuevo directorio path es inválido (por ejemplo, contiene caracteres no permitidos por el sistema de archivos subyacente).
ELOOP
Se encontraron demasiados enlaces simbólicos al resolver path.
EMLINK
El número de enlaces al directorio padre excedería LINK_MAX.
ENAMETOOLONG
path era demasiado largo.
ENOENT
Un componente del directorio en path no existe o es un enlace simbólico colgante.
ENOMEM
No había suficiente memoria del kernel disponible.
ENOSPC
El dispositivo que contiene path no tiene espacio para el nuevo directorio.
ENOSPC
El nuevo directorio no se puede crear porque la cuota de disco del usuario está agotada.
ENOTDIR
Un componente utilizado como directorio en path no es, de hecho, un directorio.
ENOTDIR
(mkdirat()) path es relativo y dirfd es un descriptor de archivo que se refiere a un archivo que no es un directorio.
EPERM
El sistema de archivos que contiene path no admite la creación de directorios.
EROFS
path se refiere a un archivo en un sistema de archivos de solo lectura.
EOVERFLOW
Las asignaciones de UID o GID (ver user_namespaces(7)) no se han configurado.

VERSIONES

En Linux, además de los bits de permiso, también se respeta el bit modeS_ISVTX.

notas glibc

En kernels más antiguos donde mkdirat() no está disponible, la función de envoltura de glibc recurre al uso de mkdir(). Cuando path es relativo, glibc construye un nombre de ruta basado en el enlace simbólico en /proc/self/fd que corresponde al argumento dirfd.

ESTANDARES

POSIX.1-2024.

HISTORIA

mkdir()
SVr4, BSD, POSIX.1-2001.
mkdirat()
POSIX.1-2008. Linux 2.6.16, glibc 2.4.

NOTAS

Existen muchas peculiaridades en el protocolo subyacente a NFS. Algunas de ellas afectan a mkdir().
