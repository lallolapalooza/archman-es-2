MKVPROPEDIT(1) Comandos de usuario MKVPROPEDIT(1)

NOMBRE

mkvpropedit - Modifica las propiedades de archivos Matroska(TM) existentes sin una remucción completa

SINOPSIS

mkvpropedit [opciones] {archivo-fuente} {acciones}

DESCRIPCIÓN

Este programa analiza un archivo Matroska(TM) existente y modifica algunas de sus propiedades. Luego escribe esas modificaciones en el archivo existente. Entre las propiedades que se pueden cambiar se encuentran los elementos de información del segmento (por ejemplo, el título) y las cabeceras de pista (por ejemplo, el código de idioma, la marca de 'pista predeterminada' o el nombre).

Opciones:

-l, --list-property-names

Enumera todos los nombres de propiedades conocidos y editables, su tipo (cadena, entero, booleano, etc.) y una breve descripción. El programa sale después. Por lo tanto, no es necesario proporcionar el parámetro archivo-fuente.

-p, --parse-mode modo

Establece el modo de análisis. El parámetro 'modo' puede ser 'fast' (que también es el predeterminado) o 'full'. El modo 'fast' no analiza todo el archivo, sino que utiliza los elementos meta seek para localizar los elementos requeridos de un archivo fuente. En el 99% de los casos, esto es suficiente. Pero para archivos que no contienen elementos meta seek o que están dañados, el usuario podría tener que establecer el modo de análisis 'full'. Un escaneo completo de un archivo puede llevar un par de minutos, mientras que un escaneo rápido solo lleva segundos.

Acciones que tratan propiedades de pista e información de segmento:

-e, --edit selector

Establece la sección del archivo Matroska(TM) (información del segmento o cabeceras de una pista determinada) en la que operan todas las acciones siguientes de agregar, establecer y eliminar. Esta opción se puede usar varias veces para realizar modificaciones en más de un elemento.

Por defecto, mkvpropedit(1) editará la sección de información del segmento.

Consulte la sección sobre selectores de edición para una descripción completa de la sintaxis.

-a, --add nombre=valor

Agrega una propiedad nombre con el valor valor. La propiedad se agregará incluso si dicha propiedad ya existe. Tenga en cuenta que la mayoría de las propiedades son únicas y no se pueden duplicar.

-s, --set nombre=valor

Establece todas las ocurrencias de la propiedad nombre al valor valor. Si no existe dicha propiedad, se agregará.

-d, --delete nombre

Elimina todas las ocurrencias de la propiedad nombre. Tenga en cuenta que algunas propiedades son necesarias y no se pueden eliminar.

Acciones que tratan etiquetas y capítulos:

-t, --tags selector:archivo

Agrega o reemplaza etiquetas en el archivo con las del archivo o las elimina si el archivo está vacío. mkvpropedit(1) lee el mismo formato de etiquetas XML que mkvmerge(1) lee.

El selector debe ser una de las palabras all, global o track. Para all, mkvpropedit(1) reemplazará o eliminará todas las etiquetas de un archivo. Con global, solo se reemplazarán o eliminarán las etiquetas globales.

Con track, mkvpropedit(1) reemplazará las etiquetas de una pista específica. Además, las etiquetas leídas del archivo se asignarán a la misma pista. La pista se especifica de la misma manera que se especifican los selectores de edición (ver más abajo), por ejemplo, --tags track:a1:new-audio-tags.xml.

--add-track-statistics-tags

Calcula estadísticas para todas las pistas de un archivo y agrega nuevas etiquetas de estadísticas para ellas. Si el archivo ya contiene dichas etiquetas, se actualizarán.

--delete-track-statistics-tags

Elimina todas las etiquetas de estadísticas de pista existentes de un archivo. Si el archivo no contiene etiquetas de estadísticas de pista, no se modificará.

-c, --chapters archivo

Agrega o reemplaza capítulos en el archivo con los del archivo o los elimina si el archivo está vacío. mkvpropedit(1) lee los formatos de capítulos XML y simples que mkvmerge(1) lee.

Acciones para manejar adjuntos:

--add-attachment archivo

Agrega un nuevo adjunto desde archivo.

Si la opción --attachment-name se usó antes que esta opción, entonces su valor se utiliza como el nuevo nombre del adjunto. De lo contrario, se deriva de archivo.

Si la opción --attachment-mime-type se usó antes que esta opción, entonces su valor se utiliza como el nuevo tipo MIME del adjunto. De lo contrario, se detecta automáticamente a partir del contenido de archivo.

Si la opción --attachment-description se usó antes que esta opción, entonces su valor se utiliza como la nueva descripción del adjunto. De lo contrario, no se establecerá ninguna descripción.

Si la opción --attachment-uid se usó antes que esta opción, entonces su valor se utiliza como el nuevo UID del adjunto. De lo contrario, se generará automáticamente un UID aleatorio.

--replace-attachment selector:archivo

Reemplaza uno o más adjuntos que coinciden con selector con el archivo archivo. Si más de un adjunto existente coincide con selector, entonces todos sus contenidos se reemplazarán con el contenido de archivo.

El selector puede tener una de las cuatro formas. Se explican a continuación en la sección de selectores de adjuntos.

Si la opción --attachment-name se usó antes que esta opción, entonces su valor se establece como el nuevo nombre para cada adjunto modificado. De lo contrario, los nombres no se cambian.

Si la opción --attachment-mime-type se usó antes que esta opción, entonces su valor se establece como el nuevo tipo MIME para cada adjunto modificado. De lo contrario, los tipos MIME no se cambian.

Si la opción --attachment-description se usó antes que esta opción, entonces su valor se establece como la nueva descripción para cada adjunto modificado. De lo contrario, las descripciones no se cambian.

Si la opción --attachment-uid se usó antes que esta opción, entonces su valor se establece como el nuevo UID para cada adjunto modificado. De lo contrario, los UID no se cambian.

--update-attachment selector

Establece las propiedades de uno o más adjuntos que coinciden con selector. Si más de un adjunto existente coincide con selector, entonces todas sus propiedades se actualizarán.

El selector puede tener una de las cuatro formas. Se explican a continuación en la sección de selectores de adjuntos.

Si la opción --attachment-name se usó antes que esta opción, entonces su valor se establece como el nuevo nombre para cada adjunto modificado. De lo contrario, los nombres no se cambian.

Si la opción --attachment-mime-type se usó antes que esta opción, entonces su valor se establece como el nuevo tipo MIME para cada adjunto modificado. De lo contrario, los tipos MIME no se cambian.

Si la opción --attachment-description se usó antes que esta opción, entonces su valor se establece como la nueva descripción para cada adjunto modificado. De lo contrario, las descripciones no se cambian.

Options for attachment actions:

\n

--attachment-name name

\n
Sets the name to use for the following\n --add-attachment or --replace-attachment operation.

\n

--enable-legacy-font-mime-types

\n
Enables the use of legacy MIME types for certain types of\n font attachments. For example, 'application/x-truetype-font' will be used for\n TrueType fonts instead of 'fonts/ttf'.\n

This affects both adding new attachments and replacing existing\n attachments, but only if the new MIME type isn't specified. Other existing\n attachments aren't changed.

\n

The affected MIME types are 'font/sfnt', 'font/ttf' and\n 'font/collection' which are all mapped to 'application/x-truetype-fonts' and\n 'font/otf' which is mapped to 'application/vnd.ms-opentype'.

\n

Other options:

\n

--disable-language-ietf

\n
Normally when the user requests changes to the 'language'\n track header property, mkvpropedit(1) will apply the same change to the\n new LanguageIETF track header element in addition to the legacy Language\n element. If this option is used, the change is only applied to the legacy\n Language element.\n

This option does not affect changes requested via the\n 'language-ietf' track header property.

\n
\n

--normalize-language-ietf mode

\n
Enables normalizing all IETF BCP 47 language tags to\n either their canonical form with mode 'canonical', to their extended language\n subtags form with mode 'extlang' or turns it off with mode 'off'. By default\n normalization to the canonical form is applied.\n

In the canonical form all subtags for which preferred values exist\n are replaced by those preferred values. This converts e.g. 'zh-yue-jyutping'\n to 'yue-jyutping' or 'fr-FX' to 'fr-FR'.

\n

For the extended language subtags form the canonical form is built\n first. Afterwards all primary languages for which an extended language\n subtag exists are replaced by that extended language subtag and its prefix.\n This converts e.g. 'yue-jyutping' back to 'zh-yue-jyutping' but has no\n effect on 'fr-FR' as 'fr' is not an extended language subtag.

\n

This normalization is only applied to elements that are actually\n changed:

\n
•When editing track headers only those track\n language elements that are set via edit specifications are affected. Languages\n of tracks that aren't edited aren't changed. Editing a track but setting only\n properties other than the language won't affect the language either.
\n
•When editing chapters all language elements of\n all chapter elements are affected as existing chapters are always fully\n replaced.
\n
•When editing tags only the language elements of\n the tags that are actually replaced are affected. For example, when you\n replace global tags then existing track tags aren't affected.
\n

The best way to normalize all existing language tags in a file is\n to remux it with mkvmerge(1) and set its '--normalize-language-ietf' option to the desired mode.

EDIT SELECTORS

\n

The --edit option sets the Matroska(TM) file section\n (segment information or a certain track's headers) that all following add, set and delete actions operate on. This stays valid until the next\n --edit option is found. The argument to this option is called the\n edit selector.

\n

By default mkvpropedit(1) will edit the segment information\n section.

\n
\n

Segment information

\n

The segment information can be selected with one of these three\n words: 'info', 'segment_info' or 'segmentinfo'. It contains properties like\n the segment title or the segment UID.

\n
\n
\n

Track headers

\n

Track headers can be selected with a slightly more complex\n selector. All variations start with 'track:'. The track header properties\n include elements like the language code, 'default track' flag or the track's\n name.

\n

track:n

\n
If the parameter n is a number then the nth\n track will be selected. The track order is the same that mkvmerge(1)'s\n --identify option outputs.\n

Numbering starts at 1.

\n
\n

track:tn

\n
If the parameter starts with a single character t\n followed by a n then the nth track of a specific track type will\n be selected. The track type parameter t must be one of these four\n characters: 'a' for an audio track, 'b' for a button track, 's' for a subtitle\n track and 'v' for a video track. The track order is the same that\n mkvmerge(1)'s --identify option outputs.\n

Numbering starts at 1.

\n
\n

track:=uid

\n
If the parameter starts with a '=' followed by a number\n uid, the track whose track UID element equals the given uid will\n be selected. Track UIDs can be obtained with mkvinfo(1).
\n

track:@number

\n
If the parameter starts with a '@' followed by a number\n number, the track whose track number element equals this number\n will be selected. Track numbers can be obtained with mkvinfo(1).
\n
\n
\n

Notes

\n

Due to the nature of the track edit selectors it is possible that\n several selectors actually match the same track headers. In such cases all\n actions for those edit selectors will be combined and executed in the order\n in which they're given on the command line.

\n
\n
\n
\n

ATTACHMENT SELECTORS

\n

An attachment selector is used with the two actions\n --replace-attachment and --delete-attachment. It can have one\n of the following four forms:

\n
1.Selection by attachment ID. In this form the selector\n is simply a number, the attachment's ID as output by mkvmerge(1)'s\n identification command.
\n
2.Selection by attachment UID (unique ID). In this form\n the selector is the equal sign = followed by a number, the attachment's unique\n ID as output by mkvmerge(1)'s verbose identification command.
\n
3.Selection by attachment name. In this form the\n selector is the literal word name: followed by the existing attachment's name.\n If this selector is used with --replace-attachment then colons within\n the name to match must be escaped as \\c.
\n
4.Selection by MIME type. In this form the selector is\n the literal word mime-type: followed by the existing attachment's MIME type.\n If this selector is used with --replace-attachment then colons within\n the MIME type to match must be escaped as \\c.
\n
\n
\n

LANGUAGE HANDLING

\n

mkvpropedit(1) mostly tries to do the right thing by\n default. Therefore changes to the language property will cause\n" } ] mkvpropedit(1) aplica el mismo cambio tanto al nuevo elemento "LanguageIETF" como al antiguo elemento "Language", de forma similar a como mkvmerge(1) aplica el idioma a ambos elementos. Por ejemplo, al usar mkvpropedit movie.mkv --edit track:2 --set language=zh-TW, el elemento "LanguageIETF" se establecerá en zh-TW y el antiguo elemento "Language" en chi.

Además, hay una nueva propiedad de cabecera de pista llamada language-ietf que se puede establecer o eliminar. Los cambios en esta propiedad solo se aplican al nuevo elemento de cabecera de pista "LanguageIETF". Una advertencia es que el antiguo elemento de cabecera de pista "Language" es un elemento obligatorio en Matroska, lo que significa que incluso si no está presente en el archivo, tiene un valor implícito. Cuando el usuario solo establece la propiedad language-ietf pero no la propiedad language, mkvpropedit(1) agregará el antiguo elemento "Language" en ciertos casos y lo establecerá en und (que significa "no determinado") ya que el usuario no especificó un valor para él.

Al leer archivos XML de capítulos o etiquetas, mkvpropedit(1) funciona como lo hace mkvmerge(1).

La creación de los nuevos elementos se puede deshabilitar completamente con la opción de línea de comandos `--disable-language-ietf`, que opera en los tres nuevos elementos.

Puedes elegir el método de normalización aplicado a las subetiquetas de idioma extendidas con el parámetro --normalize-language-ietf.

EJEMPLOS

El siguiente ejemplo edita un archivo llamado 'movie.mkv'. Establece el título del segmento y modifica el código de idioma de una pista de audio y una de subtítulos. Ten en cuenta que este ejemplo se puede acortar omitiendo la primera opción --edit porque la edición del elemento de información del segmento es la opción predeterminada para todas las opciones que se encuentran antes de la primera opción --edit de todos modos.

$ mkvpropedit movie.mkv --edit info --set "title=La película" --edit track:a1 --set language=fre --edit track:a2 --set language=ita

El segundo ejemplo elimina la 'bandera de pista predeterminada' de la primera pista de subtítulos y la establece para la segunda. Ten en cuenta que mkvpropedit(1), a diferencia de mkvmerge(1), no establece automáticamente la 'bandera de pista predeterminada' de otras pistas en '0' si se establece en '1' para una pista diferente.

$ mkvpropedit movie.mkv --edit track:s1 --set flag-default=0 --edit track:s2 --set flag-default=1

Reemplazar las etiquetas de la segunda pista de subtítulos en un archivo se ve así:

$ mkvpropedit movie.mkv --tags track:s2:new-subtitle-tags.xml

Eliminar todas las etiquetas requiere omitir el nombre del archivo:

$ mkvpropedit movie.mkv --tags all:

Reemplazar los capítulos en un archivo se ve así:

$ mkvpropedit movie.mkv --chapters new-chapters.xml

Eliminar todos los capítulos requiere omitir el nombre del archivo:

$ mkvpropedit movie.mkv --chapters ''

Agregar un archivo de fuente (Arial.ttf) como un adjunto:

$ mkvpropedit movie.mkv --add-attachment Arial.ttf

Agregar un archivo de fuente (89719823.ttf) como un adjunto y proporcionar información ya que en realidad es solo Arial:

$ mkvpropedit movie.mkv --attachment-name Arial.ttf --attachment-description 'La fuente Arial como una fuente TrueType' --attachment-mime-type application/x-truetype-font --add-attachment 89719823.ttf

Reemplazar un archivo de fuente adjunto (Comic.ttf) con otro (Arial.ttf):

$ mkvpropedit movie.mkv --attachment-name Arial.ttf --attachment-description 'La fuente Arial como una fuente TrueType' --replace-attachment name:Comic.ttf:Arial.ttf

Eliminar el segundo archivo adjunto, sea cual sea:

$ mkvpropedit movie.mkv --delete-attachment 2

Eliminar todas las fuentes adjuntas por tipo MIME:

$ mkvpropedit movie.mkv --delete-attachment mime-type:application/x-truetype-font

CÓDIGOS DE SALIDA

mkvpropedit(1) sale con uno de los tres códigos de salida:

•0 -- Este código de salida significa que la modificación se completó con éxito.
•1 -- En este caso, mkvpropedit(1) ha generado al menos una advertencia, pero la modificación continuó. Una advertencia se antepone con el texto 'Advertencia:'. Dependiendo de los problemas involucrados, los archivos resultantes pueden estar bien o no. Se insta al usuario a revisar tanto la advertencia como los archivos resultantes.
•2 -- Este código de salida se utiliza después de que ocurrió un error. mkvpropedit(1) se aborta justo después de mostrar el mensaje de error. Los mensajes de error van desde argumentos de línea de comandos incorrectos, errores de lectura/escritura, hasta archivos rotos.

Para una discusión en profundidad sobre cómo todas las herramientas del conjunto de herramientas MKVToolNix manejan las conversiones de juegos de caracteres, la codificación de entrada/salida, la codificación de la línea de comandos y la codificación de la consola, consulte la sección con el mismo nombre en la página man de mkvmerge(1).

VARIABLES DE ENTORNO

mkvpropedit(1) utiliza las variables predeterminadas que determinan la configuración regional del sistema (por ejemplo, LANG y la familia LC_*). Variables adicionales:

MKVPROPEDIT_DEBUG, MKVTOOLNIX_DEBUG y su forma corta MTX_DEBUG

El contenido se trata como si se hubiera pasado a través de la opción --debug.

MKVPROPEDIT_ENGAGE, MKVTOOLNIX_ENGAGE y su forma corta MTX_ENGAGE

El contenido se trata como si se hubiera pasado a través de la opción --engage.
