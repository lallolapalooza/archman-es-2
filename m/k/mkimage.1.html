MKIMAGE(1) Manual de Comandos Generales MKIMAGE(1)

NOMBRE

mkimage - generar imágenes para U-Boot

SINOPSIS

mkimage [-T tipo] -l nombre-archivo-imagen
mkimage [opción ...] [-T tipo] nombre-archivo-imagen
mkimage [opción ...] -f archivo-fuente-árbol-imagen|auto|auto-conf nombre-archivo-imagen
mkimage [opción ...] -F nombre-archivo-imagen

DESCRIPCIÓN

El comando mkimage se utiliza para crear imágenes para su uso con el cargador de arranque U-Boot. Estas imágenes pueden contener el kernel de Linux, el blob del árbol de dispositivos, la imagen del sistema de archivos raíz, imágenes de firmware, etc., ya sea por separado o combinados.

mkimage admite muchos formatos de imagen. Algunos de estos formatos pueden ser utilizados por el firmware de arranque embebido para cargar U-Boot. Otros pueden ser utilizados por U-Boot para cargar Linux (o algún otro kernel):

El formato de imagen heredado concatena las partes individuales (por ejemplo, la imagen del kernel, el blob del árbol de dispositivos y la imagen del disco RAM) y agrega una cabecera de 64 bytes que contiene información sobre la arquitectura de destino, el sistema operativo, el tipo de imagen, el método de compresión, los puntos de entrada, la marca de tiempo, las sumas de verificación, etc.

El nuevo formato *FIT* (Flattened Image Tree) permite una mayor flexibilidad en el manejo de imágenes de diversos tipos y también mejora la protección de la integridad de las imágenes con sumas de verificación más robustas. También admite el arranque verificado.

OPCIONES

Opciones generales

-h
--help
Imprime un mensaje de ayuda y sale.
-l
--list
mkimage lista la información contenida en la cabecera de una imagen U-Boot existente.
-s
--no-copy
No copie los datos de la imagen. Dependiendo del tipo de imagen, esto puede crear solo la cabecera, todo excepto los datos de la imagen, o nada en absoluto.
-T tipo-imagen
--type tipo-imagen
Analiza el archivo de imagen como tipo-imagen. Pase list como tipo-imagen para ver la lista de tipos de imagen admitidos. Si esta opción está ausente, entonces se utiliza por defecto kernel (imagen heredada). Si esta opción está ausente cuando se pasa -l, entonces mkimage intentará detectar automáticamente el tipo de imagen. No todos los tipos de imagen admiten la detección automática, por lo que puede ser necesario pasar -T explícitamente.
Al crear una imagen FIT con -f, el tipo de imagen siempre se establece en flat_dt. En este caso, -T especifica la propiedad ‘type’ del nodo de la imagen. Si -T está ausente, entonces la propiedad ‘type’ se establecerá por defecto en kernel.
-q
--quiet
Silencioso. No imprime la cabecera de la imagen.
-v
--verbose
Detallado. Imprime los nombres de archivo a medida que se agregan a la imagen.
-V
--version
Imprime la información de la versión y sale.

Opciones generales de creación de imágenes

-A arquitectura
--architecture arquitectura
Establece la arquitectura. Pase -h como arquitectura para ver la lista de arquitecturas admitidas. Si -A está ausente, se predetermina en ppc.
-O so
--os so
Establece el sistema operativo. El comando bootm de U-Boot cambia el método de arranque según el tipo de SO. Pase -h como so para ver la lista de SO admitidos. Si -O está ausente, se predetermina en linux.
-C tipo-compresión
--compression tipo-compresión
Establece el tipo de compresión. Los datos de la imagen ya deben haber sido comprimidos usando este tipo de compresión. mkimage no comprimirá los datos de la imagen automáticamente. Pase -h como tipo-compresión para ver la lista de tipos de compresión admitidos. Si -C está ausente, se predetermina en gzip.
-a dirección-carga
--load-address dirección-carga
Establece la dirección absoluta a la que se cargarán los datos de la imagen. dirección-carga se interpretará como un número hexadecimal.
-e punto-entrada
--entry-point punto-entrada
Establece la dirección absoluta del punto de entrada de la imagen. El comando bootm de U-Boot saltará a esta dirección después de cargar la imagen. punto-entrada se interpretará como un número hexadecimal.
-n configuración-primaria
--config configuración-primaria
Las imágenes pueden requerir configuración adicional no especificada con otras opciones, a menudo en un formato específico del tipo de imagen. Los tipos de imagen que admiten esta opción y el formato de su configuración se enumeran en CONFIGURACIÓN.
-R configuración-secundaria
--secondary-config configuración-secundaria
Algunos tipos de imagen admiten un segundo conjunto de datos de configuración. Los tipos de imagen que admiten configuración secundaria y su formato de configuración se enumeran en CONFIGURACIÓN.
-d archivo-datos-imagen
--image archivo-datos-imagen
Utiliza los datos de la imagen del archivo-datos-imagen. Si el tipo-imagen es multi, entonces se pueden especificar múltiples imágenes, separadas por dos puntos:
archivo-datos-imagen[:archivo-datos-imagen...]
-x
--xip
Establece la bandera XIP (ejecutar en el lugar). El comando bootm de U-Boot no cargará los datos de la imagen, y en su lugar asumirá que ya son accesibles en la dirección de carga (como a través de flash mapeado en memoria).

--comment comentario
Especifica un comentario que se agregará al firmar. Esto es típicamente un mensaje

Crea una imagen FIT que contiene un kernel firmado, usando el modo automático. No se requiere archivo .its.

mkimage -f auto -A arm -O linux -T kernel -C none -a 43e00000 -e 0 \
	-d vmlinuz -k /secreto/claves-firma -g dev -o sha256,rsa2048 kernel.itb

Crea una imagen FIT que contiene un kernel y algunos archivos de árbol de dispositivos, firmando cada configuración, usando el modo automático. Además, la clave pública necesaria para verificar las firmas se agrega a u-boot.dtb con la propiedad required = "conf".

mkimage -f auto-conf -A arm -O linux -T kernel -C none -a 43e00000 \
	-e 0 -d vmlinuz -b /ruta/a/file-1.dtb -b /ruta/a/file-2.dtb \
	-k /carpeta/con/claves-firma -g dev -o sha256,rsa2048 \
	-K u-boot.dtb -r kernel.itb

Convierte una imagen FIT existente de cualquiera de los tres tipos de almacenamiento de datos (datos internos, datos externos con offset o datos externos con posición) a otro tipo de almacenamiento de datos.

// convierte FIT de datos internos a datos con posición
mkimage -p 0x20000 -F internal_data.itb
// convierte FIT de datos con posición a datos con offset
mkimage -E -F external_data-position.itb
// convierte FIT de datos con offset a datos internos
mkimage -F external_data-offset.itb
