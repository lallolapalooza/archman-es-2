MKDIR(3P) Manual del programador POSIX MKDIR(3P)

PROLOG

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

mkdir, mkdirat — crear un directorio

SINOPSIS

#include <sys/stat.h>
int mkdir(const char *path, mode_t mode);
#include <fcntl.h>
int mkdirat(int fd, const char *path, mode_t mode);

DESCRIPCIÓN

La función mkdir() creará un nuevo directorio con el nombre path. Los bits de permisos de archivo del nuevo directorio se inicializarán a partir de mode. Estos bits de permisos de archivo del argumento mode serán modificados por la máscara de creación de archivos del proceso.

Cuando los bits en mode, distintos de los bits de permisos de archivo, están establecidos, el significado de estos bits adicionales es definido por la implementación.

El ID de usuario del directorio se establecerá en el ID de usuario efectivo del proceso. El ID de grupo del directorio se establecerá en el ID de grupo del directorio padre o en el ID de grupo efectivo del proceso. Las implementaciones deberán proporcionar una forma de inicializar el ID de grupo del directorio al ID de grupo del directorio padre. Las implementaciones pueden, pero no están obligadas a, proporcionar una forma definida por la implementación para inicializar el ID de grupo del directorio al ID de grupo efectivo del proceso que llama.

El directorio recién creado será un directorio vacío.

Si path apunta a un enlace simbólico, mkdir() fallará y establecerá errno a [EEXIST].

Tras la finalización exitosa, mkdir() marcará para actualización las marcas de tiempo del último acceso a datos, última modificación de datos y último cambio de estado del archivo del directorio. Asimismo, se marcarán para actualización las marcas de tiempo de la última modificación de datos y del último cambio de estado del archivo del directorio que contiene la nueva entrada.

La función mkdirat() será equivalente a la función mkdir() excepto en el caso en que path especifique una ruta relativa. En este caso, el nuevo directorio se creará relativo al directorio asociado con el descriptor de archivo fd en lugar del directorio de trabajo actual. Si el modo de acceso de la descripción del archivo abierto asociado con el descriptor de archivo no es O_SEARCH, la función comprobará si se permiten las búsquedas de directorios utilizando los permisos actuales del directorio subyacente al descriptor de archivo. Si el modo de acceso es O_SEARCH, la función no realizará la comprobación.

Si a mkdirat() se le pasa el valor especial AT_FDCWD en el parámetro fd, se utilizará el directorio de trabajo actual y el comportamiento será idéntico al de una llamada a mkdir().

VALOR DE RETORNO

Tras la finalización exitosa, estas funciones devolverán 0. De lo contrario, estas funciones devolverán -1 y establecerán errno para indicar el error. Si se devuelve -1, no se creará ningún directorio.

ERRORES

Estas funciones fallarán si:

EACCES
Se deniega el permiso de búsqueda en un componente del prefijo de ruta, o se deniega el permiso de escritura en el directorio padre del directorio a crear.
EEXIST
El archivo nombrado ya existe.
ELOOP
Existe un bucle en los enlaces simbólicos encontrados durante la resolución del argumento path.
EMLINK
El recuento de enlaces del directorio padre superaría {LINK_MAX}.
ENAMETOOLONG

La longitud de un componente de un nombre de ruta es mayor que {NAME_MAX}.
ENOENT
Un componente del prefijo de ruta especificado por path no nombra un directorio existente o path es una cadena vacía.
ENOSPC
El sistema de archivos no contiene suficiente espacio para albergar el contenido del nuevo directorio o para extender el directorio padre del nuevo directorio.
ENOTDIR
Un componente del prefijo de ruta nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio.
EROFS
El directorio padre reside en un sistema de archivos de solo lectura.

Además, la función mkdirat() fallará si:

EACCES
El modo de acceso de la descripción del archivo abierto asociado con fd no es O_SEARCH y los permisos del directorio subyacente a fd no permiten búsquedas de directorios.
EBADF
El argumento path no especifica una ruta absoluta y el argumento fd no es ni AT_FDCWD ni un descriptor de archivo válido abierto para lectura o búsqueda.
ENOTDIR
El argumento path no es una ruta absoluta y fd es un descriptor de archivo asociado con un archivo que no es un directorio.

Estas funciones pueden fallar si:

ELOOP
Se encontraron más de {SYMLOOP_MAX} enlaces simbólicos durante la resolución del argumento path.
ENAMETOOLONG

La longitud de un nombre de ruta excede {PATH_MAX}, o la resolución del nombre de ruta de un enlace simbólico produjo un resultado intermedio con una longitud que excede {PATH_MAX}.

EJEMPLOS

Creación de un Directorio

El siguiente ejemplo muestra cómo crear un directorio llamado /home/cnd/mod1, con permisos de lectura/escritura/ejecución para el propietario y el grupo, y con permisos de lectura/ejecución para otros.

#include <sys/types.h>
#include <sys/stat.h>
int status;
...
status = mkdir("/home/cnd/mod1", S_IRWXU | S_IRWXG | S_IROTH | S_IXOTH);

USO PARA APLICACIONES

Ninguno.

JUSTIFICACIÓN

La función mkdir() se originó en 4.2 BSD y se agregó a System V en la Versión 3.0.

4.3 BSD detecta [ENAMETOOLONG].

El estándar POSIX.1‐1990 requería que el ID de grupo de un directorio recién creado se estableciera en el ID de grupo de su directorio padre o en el ID de grupo efectivo del proceso creador. FIPS 151‐2 requería que las implementaciones proporcionaran una forma de establecer el ID de grupo en el ID de grupo del directorio contenedor, pero no prohibía que las implementaciones también admitieran una forma de establecer el ID de grupo en el ID de grupo efectivo del proceso creador. Las aplicaciones compatibles no deben asumir qué ID de grupo se utilizará. Si es importante, una aplicación puede usar chown() para establecer el ID de grupo después de que se cree el directorio, o determinar bajo qué condiciones la implementación establecerá el ID de grupo deseado.

El propósito de la función mkdirat() es crear un directorio en directorios distintos del directorio de trabajo actual sin exposición a condiciones de carrera. Cualquier parte de la ruta de un archivo podría modificarse en paralelo a la llamada a mkdir(), lo que daría lugar a un comportamiento no especificado. Al abrir un descriptor de archivo para el directorio de destino y utilizar la función mkdirat(), se puede garantizar que el nuevo directorio se ubicará relativo al directorio deseado.
