FMTUTIL(1) Comandos de usuario FMTUTIL(1)

NOMBRE

fmtutil - gestionar formatos TeX y bases Metafont, por usuario
fmtutil-sys - gestionar formatos TeX y bases Metafont, a nivel de sistema
mktexfmt - crear un formato TeX o una base Metafont

SINOPSIS

fmtutil [-user|-sys] [OPCION] ... [COMANDO]
fmtutil-sys [OPCION] ... [COMANDO]
fmtutil-user [OPCION] ... [COMANDO]
mktexfmt FORMAT.fmt|BASE.base|NOMBREFMT

DESCRIPCIÓN

fmtutil versión r65989 (2023-02-20 22:52:59 +0100)

Reconstruye y gestiona formatos TeX y bases Metafont, denominados colectivamente "formatos" aquí. (MetaPost ya no utiliza las "mems" del pasado.)

Si no se opera en modo mktexfmt, se debe proporcionar exactamente un comando, generalmente no se deben especificar sufijos de nombre de archivo, no se permiten argumentos que no sean opciones y se pueden generar múltiples formatos.

Si el nombre del comando termina en mktexfmt, solo se puede crear un formato. Las únicas opciones admitidas son --help y --version, y la línea de comandos debe ser un nombre de formato, con extensión, o un nombre simple que se pasa como argumento a --byfmt (ver más abajo). El nombre completo del archivo generado (si lo hay) se escribe en la salida estándar, y nada más. Los directorios del sistema se utilizan si son escribibles, de lo contrario, los directorios del usuario.

Por defecto, el estado de retorno es cero si todos los formatos solicitados se construyen correctamente, de lo contrario es distinto de cero.

AMBIENTE

Explicación de los árboles y ficheros normalmente utilizados:

Si se especifica --cnffile en la línea de comandos (posiblemente varias veces), se usan sus valores. De lo contrario, fmtutil lee todos los ficheros fmtutil.cnf encontrados ejecutando "kpsewhich -all fmtutil.cnf", en el orden devuelto por kpsewhich. Los ficheros especificados mediante --cnffile se intentan cargar directamente primero, y si no se encuentran y los nombres de fichero no contienen partes de directorio, se buscan a través de kpsewhich.
En cualquier caso, si se encuentran múltiples ficheros fmtutil.cnf, se fusionan todas las definiciones de formatos encontradas en todos los ficheros fmtutil.cnf.
Por lo tanto, si existen ficheros fmtutil.cnf en todos los árboles, y se usa la disposición por defecto tal como se distribuye con TeX Live, se leen los siguientes ficheros, en el orden dado.
Para fmtutil-sys:
TEXMFSYSCONFIG $TEXLIVE/YYYY/texmf-config/web2c/fmtutil.cnf
TEXMFSYSVAR    $TEXLIVE/YYYY/texmf-var/web2c/fmtutil.cnf
TEXMFLOCAL     $TEXLIVE/texmf-local/web2c/fmtutil.cnf
TEXMFDIST      $TEXLIVE/YYYY/texmf-dist/web2c/fmtutil.cnf
Para fmtutil-user:
TEXMFCONFIG    $HOME/.texliveYYYY/texmf-config/web2c/fmtutil.cnf
TEXMFVAR       $HOME/.texliveYYYY/texmf-var/web2c/fmtutil.cnf
TEXMFHOME      $HOME/texmf/web2c/fmtutil.cnf
TEXMFSYSCONFIG $TEXLIVE/YYYY/texmf-config/web2c/fmtutil.cnf
TEXMFSYSVAR    $TEXLIVE/YYYY/texmf-var/web2c/fmtutil.cnf
TEXMFLOCAL     $TEXLIVE/texmf-local/web2c/fmtutil.cnf
TEXMFDIST      $TEXLIVE/YYYY/texmf-dist/web2c/fmtutil.cnf
(donde YYYY es la versión de lanzamiento de TeX Live).
De acuerdo con las acciones, fmtutil podría actualizar uno de los ficheros cnf existentes o crear un nuevo fmtutil.cnf, como se describe a continuación.

Dónde se escriben los ficheros de formato:

Por defecto, los ficheros de formato se escriben (o reescriben) en $TEXMFSYSVAR/ENGINE por fmtutil-sys, y $TEXMFVAR/ENGINE por fmtutil-user, donde /ENGINE es un subdirectorio con el nombre del motor utilizado, como por ejemplo "pdftex".
Para mktexfmt, se utiliza TEXMFSYSVAR si es escribible, de lo contrario TEXMFVAR.
Si se especifica la opción --fmtdir=DIR, se utiliza DIR en lugar de TEXMF[SYS]VAR, pero el subdirectorio /ENGINE todavía se usa por defecto.
En todos los casos, si se especifica la opción --no-engine-subdir, se omite el subdirectorio /ENGINE.

Dónde se guardan los cambios de configuración:

Si se proporcionan ficheros de configuración en la línea de comandos, entonces se utilizará el primero proporcionado para guardar cualquier cambio de --enable o --disable.

NAME

mktexfmt - create format files

SYNOPSIS

mktexfmt [OPTION...]

DESCRIPTION

The mktexfmt script creates format files (also known as initex files, or engines) for TeX.

It consults a set of configuration files to determine which formats to create. The search path for these files is as follows:

1) the file $TEXMFCONFIG/web2c/fmtutil.cnf (if it exists and is writable), otherwise the file $TEXMFLOCAL/web2c/fmtutil.cnf (if it exists and is writable), otherwise the file $TEXMFDIST/web2c/fmtutil.cnf (if it exists).
2) The file listed first by kpsewhich --all (equivalently, the one returned by "kpsewhich fmtutil.cnf"), is used.
3) If neither of the above two are present and changes are made, a new config file is created in $TEXMFCONFIG/web2c/fmtutil.cnf.

In general, the idea is that if a given config file is not writable, a higher-level one can be used. That way, the distribution's settings can be overridden system-wide using TEXMFLOCAL, and system settings can be overridden again in a particular user's TEXMFHOME or TEXMFCONF.

Resolving multiple definitions of a format:

If a format is defined in more than one config file, then the definition coming from the first-listed fmtutil.cnf is used.

Disabling formats:

fmtutil.cnf files with higher priority (listed earlier) can disable formats in lower priority (listed later) fmtutil.cnf files by writing a line like this in the higher-priority fmtutil.cnf file:
#! <fmtname> <enginename> <hyphen> <args>
The #! must be at the beginning of the line, with at least one space or tab afterward, and there must be whitespace between each word on the list.
For example, you can disable the luajitlatex format by creating the file $TEXMFCONFIG/web2c/fmtutil.cnf with the line
#! luajitlatex luajittex language.dat,language.dat.lua lualatex.ini
(As it happens, the luajittex-related formats are precisely why the --no-error-if-no-engine option exists, since luajittex cannot be compiled on all platforms. So this is not needed.)

fmtutil-user (fmtutil -user) vs. fmtutil-sys (fmtutil -sys):

When fmtutil-sys is run or the command line option -sys is used, TEXMFSYSCONFIG and TEXMFSYSVAR are used instead of TEXMFCONFIG and TEXMFVAR, respectively. This is the primary difference between fmtutil-sys and fmtutil-user.
See https://tug.org/texlive/scripts-sys-user.html for details.
Other locations may be used if you give them on the command line, or these trees don't exist, or you are not using the original TeX Live.

Supporting development binaries:

If an engine name ends with "-dev", formats are created in the respective directory with the -dev stripped. This allows for easily running development binaries in parallel with the released binaries.

OPTIONS

There are no command line options.

ENVIRONMENT

The behavior of mktexfmt is affected by the TeX directory structure and associated environment variables. See tex(1) for details.
