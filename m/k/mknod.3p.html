MKNOD(3P) Manual del programador POSIX MKNOD(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

mknod, mknodat — crear directorio, archivo especial o archivo regular

SINOPSIS

#include <sys/stat.h>
int mknod(const char *path, mode_t mode, dev_t dev);
#include <fcntl.h>
int mknodat(int fd, const char *path, mode_t mode, dev_t dev);

DESCRIPCIÓN

La función mknod() creará un nuevo archivo con el nombre apuntado por el argumento path.

El tipo de archivo para path se combina mediante OR bit a bit con el argumento mode, y la aplicación seleccionará una de las siguientes constantes simbólicas:

Nombre Descripción
S_IFIFO Especial FIFO
S_IFCHR Especial de caracteres (no portable)
S_IFDIR Directorio (no portable)
S_IFBLK Especial de bloques (no portable)
S_IFREG Regular (no portable)

El único uso portable de mknod() es crear un archivo especial FIFO. Si mode no es S_IFIFO o dev no es 0, el comportamiento de mknod() no está especificado.

Los permisos para el nuevo archivo se combinan mediante OR bit a bit con el argumento mode, y pueden seleccionarse de cualquier combinación de las siguientes constantes simbólicas:

Nombre Descripción
S_ISUID Establecer ID de usuario al ejecutar.
S_ISGID Establecer ID de grupo al ejecutar.
S_IRWXU Leer, escribir o ejecutar (buscar) por propietario.
S_IRUSR Leer por propietario.
S_IWUSR Escribir por propietario.
S_IXUSR Ejecutar (buscar) por propietario.
S_IRWXG Leer, escribir o ejecutar (buscar) por grupo.
S_IRGRP Leer por grupo.
S_IWGRP Escribir por grupo.
S_IXGRP Ejecutar (buscar) por grupo.
S_IRWXO Leer, escribir o ejecutar (buscar) por otros.
S_IROTH Leer por otros.
S_IWOTH Escribir por otros.
S_IXOTH Ejecutar (buscar) por otros.
S_ISVTX En directorios, bandera de eliminación restringida.

El ID de usuario del archivo se inicializará al ID de usuario efectivo del proceso. El ID de grupo del archivo se inicializará al ID de grupo efectivo del proceso o al ID de grupo del directorio padre. Las implementaciones proporcionarán una forma de inicializar el ID de grupo del archivo al ID de grupo del directorio padre. Las implementaciones pueden, pero no están obligadas a, proporcionar una forma definida por la implementación para inicializar el ID de grupo del archivo al ID de grupo efectivo del proceso que llama.

Los bits de permisos de propietario, grupo y otros de mode serán modificados por la máscara de creación de permisos de archivo del proceso. La función mknod() borrará cada bit cuyo bit correspondiente en la máscara de creación de permisos de archivo del proceso esté establecido.

Si path nombra un enlace simbólico, mknod() fallará y establecerá errno a [EEXIST].

Tras su finalización exitosa, mknod() marcará para actualización los últimos tiempos de acceso a datos, modificación de datos y cambio de estado del archivo. Además, se marcarán para actualización los últimos tiempos de modificación de datos y cambio de estado del directorio que contiene la nueva entrada.

Solo un proceso con privilegios apropiados puede invocar mknod() para tipos de archivo distintos de especial FIFO.

La función mknodat() será equivalente a la función mknod() excepto en el caso en que path especifique una ruta relativa. En este caso, el directorio recién creado, el archivo especial o el archivo regular se ubicarán en relación con el directorio asociado con el descriptor de archivo fd en lugar del directorio de trabajo actual. Si el modo de acceso de la descripción de archivo abierto asociado con el descriptor de archivo no es O_SEARCH, la función verificará si las búsquedas de directorio están permitidas utilizando los permisos actuales del directorio subyacente al descriptor de archivo. Si el modo de acceso es O_SEARCH, la función no realizará la verificación.

Si se pasa mknodat() el valor especial AT_FDCWD en el parámetro fd, se utilizará el directorio de trabajo actual y el comportamiento será idéntico al de una llamada a mknod().

VALOR DE RETORNO

Tras su finalización exitosa, estas funciones devolverán 0. De lo contrario, estas funciones devolverán -1 y establecerán errno para indicar el error. Si se devuelve -1, el nuevo archivo no se creará.

ERRORES

Estas funciones fallarán si:

EACCES
Un componente del prefijo de ruta niega permiso de búsqueda, o se niega el permiso de escritura en el directorio padre.
EEXIST
El archivo con el nombre especificado ya existe.
EINVAL
Existe un argumento inválido.
EIO
Se produjo un error de E/S al acceder al sistema de archivos.
ELOOP
Existe un bucle en los enlaces simbólicos encontrados durante la resolución del argumento path.
ENAMETOOLONG

La longitud de un componente de una ruta de acceso es mayor que {NAME_MAX}.
ENOENT
Un componente del prefijo de ruta de path no nombra un archivo existente o path es una cadena vacía.
ENOENT o ENOTDIR

El argumento path contiene al menos un carácter que no es <barra> y termina con uno o más caracteres <barra> finales. Si path sin los caracteres <barra> finales nombrara un archivo existente, no se producirá un error [ENOENT].
ENOSPC
El directorio que contendría el nuevo archivo no puede extenderse o el sistema de archivos está sin recursos de asignación de archivos.
ENOTDIR
Un componente del prefijo de ruta nombra un archivo existente que no es un directorio ni un enlace simbólico a un directorio.
EPERM
El proceso invocador no tiene los privilegios apropiados y el tipo de archivo no es especial FIFO.
EROFS
El directorio en el que se va a crear el archivo está ubicado en un sistema de archivos de solo lectura.

La función mknodat() fallará si:

EACCES

El modo de acceso de la descripción de archivo abierta asociada con fd no es O_SEARCH y los permisos del directorio subyacente a fd no permiten búsquedas de directorios.

El argumento path no especifica una ruta absoluta y el argumento fd no es ni AT_FDCWD ni un descriptor de archivo válido abierto para lectura o búsqueda.
ENOTDIR
El argumento path no es una ruta absoluta y fd es un descriptor de archivo asociado con un archivo que no es un directorio.

Estas funciones pueden fallar si:

ELOOP
Se encontraron más de {SYMLOOP_MAX} enlaces simbólicos durante la resolución del argumento path.
ENAMETOOLONG

La longitud de un nombre de ruta excede {PATH_MAX}, o la resolución del nombre de ruta de un enlace simbólico produjo un resultado intermedio con una longitud que excede {PATH_MAX}.

Las siguientes secciones son informativas.

EJEMPLOS

Creación de un archivo especial FIFO

El siguiente ejemplo muestra cómo crear un archivo especial FIFO llamado /home/cnd/mod_done, con permisos de lectura/escritura para el propietario, y con permisos de lectura para el grupo y otros.

#include <sys/types.h>
#include <sys/stat.h>
dev_t dev;
int   status;
...
status  = mknod("/home/cnd/mod_done", S_IFIFO | S_IWUSR |
    S_IRUSR | S_IRGRP | S_IROTH, dev);

USO DE APLICACIONES

Se prefiere la función mkfifo() sobre esta función para crear archivos especiales FIFO.

FUNDAMENTO

El estándar POSIX.1-1990 requería que el ID de grupo de un archivo recién creado se estableciera en el ID de grupo de su directorio padre o en el ID de grupo efectivo del proceso creador. FIPS 151-2 requería que las implementaciones proporcionaran una forma de establecer el ID de grupo en el ID de grupo del directorio que lo contiene, pero no prohibía que las implementaciones también admitieran una forma de establecer el ID de grupo en el ID de grupo efectivo del proceso creador. Las aplicaciones compatibles no deben asumir qué ID de grupo se utilizará. Si importa, una aplicación puede usar chown() para establecer el ID de grupo después de crear el archivo, o determinar bajo qué condiciones la implementación establecerá el ID de grupo deseado.

El propósito de la función mknodat() es crear directorios, archivos especiales o archivos regulares en directorios distintos del directorio de trabajo actual sin exposición a condiciones de carrera. Cualquier parte de la ruta de un archivo podría modificarse en paralelo a una llamada a mknod(), lo que resultaría en un comportamiento no especificado. Al abrir un descriptor de archivo para el directorio de destino y utilizar la función mknodat(), se puede garantizar que el directorio, archivo especial o archivo regular recién creado se ubique en relación con el directorio deseado.
