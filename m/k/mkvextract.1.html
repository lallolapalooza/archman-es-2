MKVEXTRACT(1) Comandos de usuario MKVEXTRACT(1)

NOMBRE

mkvextract - extraer pistas de archivos Matroska(TM) a otros archivos

SINOPSIS

mkvextract {nombre-archivo-fuente} {modo1} [opciones] [especificación-extracción1] [modo2] [opciones] [especificación-extracción2] [...]

DESCRIPCIÓN

Este programa extrae partes específicas de un archivo Matroska(TM) a otros formatos útiles. El primer argumento es el nombre del archivo fuente, que debe ser un archivo Matroska(TM).

Todos los demás argumentos cambian a un modo de extracción determinado, modifican opciones para el modo actualmente activo o especifican qué extraer y a qué archivo. Se pueden usar múltiples modos en la misma invocación de mkvextract, permitiendo la extracción de múltiples elementos en una sola pasada. La mayoría de las opciones solo se pueden usar en ciertos modos, con pocas opciones aplicables a todos los modos.

Actualmente se admite la extracción de pistas, etiquetas, adjuntos, capítulos, hojas CUE, marcas de tiempo y señales (cues).

Opciones comunes

Las siguientes opciones están disponibles en todos los modos y solo se describen una vez en esta sección.

-f, --parse-fully

Establece el modo de análisis a 'completo'. El modo por defecto no analiza el archivo completo, sino que utiliza los elementos de búsqueda de metadatos para localizar los elementos requeridos de un archivo fuente. En el 99% de los casos, esto es suficiente. Pero para archivos que no contienen elementos de búsqueda de metadatos o que están dañados, el usuario podría tener que usar este modo. Un escaneo completo de un archivo puede llevar un par de minutos, mientras que un escaneo rápido solo toma segundos.

--command-line-charset juego-de-caracteres

Establece el juego de caracteres desde el cual se convierten las cadenas proporcionadas en la línea de comandos. Por defecto, utiliza el juego de caracteres dado por la configuración regional actual del sistema.

--output-charset juego-de-caracteres

Establece el juego de caracteres al cual se convierten las cadenas que se van a emitir. Por defecto, utiliza el juego de caracteres dado por la configuración regional actual del sistema.

-r, --redirect-output nombre-archivo

Escribe todos los mensajes en el archivo nombre-archivo en lugar de en la consola. Si bien esto se puede hacer fácilmente con la redirección de salida, hay casos en los que esta opción es necesaria: cuando la terminal reinterpreta la salida antes de escribirla en un archivo. Se respeta el juego de caracteres establecido con --output-charset.

--flush-on-close

Indica al programa que vacíe todos los datos almacenados en caché en la memoria al almacenamiento cuando cierre los archivos abiertos para escritura. Esto se puede usar para prevenir la pérdida de datos en cortes de energía o para eludir ciertos problemas en el sistema operativo o controladores. La desventaja es que la multiplexación llevará más tiempo, ya que mkvmerge esperará hasta que todos los datos se hayan escrito en el almacenamiento antes de salir. Consulte los problemas #2469 y #2480 en el rastreador de errores de MKVToolNix para discusiones en profundidad sobre los pros y los contras.

--ui-language código

Fuerza el uso de las traducciones para el idioma código (por ejemplo, 'de_DE' para las traducciones al alemán). Introducir 'list' como código hará que el programa emita una lista de traducciones disponibles.

--abort-on-warnings

Indica al programa que aborte después de que se emita la primera advertencia. El código de salida del programa será 1.

--debug tema

Activa la depuración para una característica específica. Esta opción solo es útil para desarrolladores.

--engage característica

Activa características experimentales. Se puede solicitar una lista de características disponibles con mkvextract --engage list. Estas características no están destinadas a ser utilizadas en situaciones normales.

--gui-mode

Activa el modo GUI. En este modo, se pueden emitir líneas con formato especial que pueden indicar a una GUI controladora lo que está sucediendo. Estos mensajes siguen el formato '#GUI#mensaje'. El mensaje puede ir seguido de pares clave/valor como en '#GUI#mensaje#clave1=valor1#clave2=valor2...'. Ni los mensajes ni las claves se traducen y siempre se emiten en inglés.

-v, --verbose

Sé verboso y muestra todos los elementos importantes de Matroska(TM) a medida que se leen.

-h, --help

Muestra información de uso y sale.

-V, --version

Muestra información de la versión y sale.

@archivo-opciones.json

Lee argumentos adicionales de la línea de comandos del archivo archivo-opciones. Para una explicación completa de los formatos admitidos para dichos archivos, consulte la sección llamada "Archivos de opciones" en la página del manual de mkvmerge(1).

Modo de extracción de pistas

Sintaxis: mkvextract nombre-archivo-fuente tracks [opciones] TID1:nombre-archivo-salida1 [TID2:nombre-archivo-salida2 ...]

Las siguientes opciones de línea de comandos están disponibles para cada pista en el modo de extracción 'tracks'. Deben aparecer antes de la especificación de pista (ver más abajo) a la que se deben aplicar.

-c juego-de-caracteres

Establece el juego de caracteres al cual se convierte la siguiente pista de subtítulos de texto. Solo es válido si el ID de pista siguiente apunta a una pista de subtítulos de texto. Por defecto es UTF-8.

--blockadd nivel

Conserva solo las adiciones de bloque (BlockAdditions) hasta este nivel. Por defecto, se conservan todos los niveles. Esta opción solo afecta a ciertos tipos de códecs como WAVPACK4.

--cuesheet

Hace que mkvextract(1) extraiga una hoja CUE de la información de capítulos y los datos de etiquetas para la siguiente pista en un archivo cuyo nombre es el nombre de salida de la pista con '.cue' añadido.

--raw

Extrae los datos sin procesar a un archivo sin ningún dato de contenedor alrededor. A diferencia de la opción --fullraw, esta opción no hace que el contenido del elemento CodecPrivate se escriba en el archivo. Este modo funciona con todos los CodecIDs, incluso aquellos que mkvextract(1) no admite de otra manera, pero los archivos resultantes podrían no ser utilizables.

--fullraw

Extrae los datos sin procesar a un archivo sin ningún dato de contenedor alrededor. El contenido del elemento CodecPrivate se escribirá en el archivo primero si la pista contiene dicho elemento de encabezado. Este modo funciona con todos los CodecIDs, incluso aquellos que mkvextract(1) no admite de otra manera, pero los archivos resultantes podrían no ser utilizables.

TID:nombre-salida

Provoca la extracción de la pista con el ID TID al archivo nombre-salida si existe tal pista en el archivo fuente. Esta opción se puede proporcionar varias veces. Los IDs de las pistas son los mismos que los que emite la opción --identify de mkvmerge(1).

Cada nombre de salida debe usarse solo una vez. La excepción son las pistas RealAudio y RealVideo. Si usa el mismo nombre para diferentes pistas, esas pistas se guardarán en el mismo archivo. Ejemplo:

$ mkvextract input.mkv tracks 0:video.h264 2:output-two-vobsub-tracks.idx 3:output-two-vobsub-tracks.idx

Modo de extracción de adjuntos

Sintaxis: mkvextract nombre-archivo-fuente attachments AID1:nombre-archivo-salida1 [AID2:nombre-archivo-salida2 ...]

Este modo extrae adjuntos de un archivo Matroska(TM). Cada adjunto está identificado por un ID numérico. Puede obtener estos IDs usando la opción --identify de mkvmerge(1). La sintaxis para especificar qué extraer es: el ID del adjunto seguido de dos puntos (:) seguido del nombre del archivo de salida.

$ mkvextract input.mkv attachments 1:cover.jpg 2:font.ttf

La opción --attachment-name se puede usar para especificar un nombre de archivo para el adjunto saliente, para que coincida con el nombre del archivo original del adjunto.

El nombre del archivo es opcional. Si no se proporciona, el adjunto se guardará en un archivo con el nombre derivado del ID del adjunto y su MIME type.

Modo de extracción de capítulos

Sintaxis: mkvextract nombre-archivo-fuente chapters nombre-archivo-salida

Este modo extrae la información de capítulos del archivo Matroska(TM) y la guarda en el archivo especificado. El formato del archivo de salida es el de una hoja CUE.

$ mkvextract input.mkv chapters chapters.cue

Modo de extracción de etiquetas

Sintaxis: mkvextract nombre-archivo-fuente tags nombre-archivo-salida

Este modo extrae las etiquetas (tags) del archivo Matroska(TM) y las guarda en el archivo especificado. El formato del archivo de salida es XML, tal como se define en la especificación Matroska.

$ mkvextract input.mkv tags tags.xml

Modo de extracción de hojas CUE

Sintaxis: mkvextract nombre-archivo-fuente cues nombre-archivo-salida

Este modo extrae la información de la hoja CUE (que describe las pistas de audio y sus segmentos) del archivo Matroska(TM) y la guarda en el archivo especificado. El formato del archivo de salida es el de una hoja CUE.

$ mkvextract input.mkv cues cues.cue

Modo de extracción de marcas de tiempo

Sintaxis: mkvextract nombre-archivo-fuente timestamps TID:nombre-archivo-salida

Este modo extrae la información de marcas de tiempo de la pista especificada del archivo Matroska(TM) y la guarda en el archivo especificado. El formato del archivo de salida es texto plano, con una marca de tiempo por línea.

$ mkvextract input.mkv timestamps 2:timestamps.txt

Modo de extracción de señales (cues)

Sintaxis: mkvextract nombre-archivo-fuente cues nombre-archivo-salida

Este modo extrae la información de las señales (cues) del archivo Matroska(TM) y la guarda en el archivo especificado. El formato del archivo de salida es texto plano, con una señal por línea.

$ mkvextract input.mkv cues cues.txt

EJEMPLOS

Extraer la pista de vídeo (ID 1) y la pista de audio (ID 2) de pelicula.mkv a pelicula.h264 y pelicula.ac3 respectivamente:

$ mkvextract pelicula.mkv tracks 1:pelicula.h264 2:pelicula.ac3

Extraer la pista de vídeo (ID 1) como H.264 crudo y la pista de subtítulos (ID 3) como SRT de video.mkv:

$ mkvextract video.mkv tracks --fullraw 1:video.h264 3:subtitles.srt

Extraer todos los adjuntos de archivo.mkv:

$ mkvextract archivo.mkv attachments

Extraer la hoja CUE de audio.mkv y guardarla como audio.cue:

$ mkvextract audio.mkv chapters audio.cue

Extraer las etiquetas de multimedia.mkv y guardarlas como etiquetas.xml:

$ mkvextract multimedia.mkv tags etiquetas.xml

Modo de extracción de archivos adjuntos

Sintaxis: mkvextract archivo-fuente attachments [opciones] AID1:nombre-salida1 [AID2:nombre-salida2 ...]

AID:nombre-salida

Causa la extracción del archivo adjunto con el ID AID al archivo nombre-salida si dicho archivo adjunto existe en el archivo fuente. Si se deja vacío nombre-salida, se utilizará en su lugar el nombre del archivo adjunto dentro del archivo Matroska(TM). Esta opción se puede especificar varias veces. Los IDs de los archivos adjuntos son los mismos que los que muestra la opción --identify de mkvmerge(1).

Modo de extracción de capítulos

Sintaxis: mkvextract archivo-fuente chapters [opciones] archivo-salida.xml

-s, --simple

Exporta la información de los capítulos en el formato simple utilizado en las herramientas OGM (CHAPTER01=..., CHAPTER01NAME=...). En este modo, se debe descartar cierta información. Por defecto, se exportan los capítulos en formato XML.

--simple-language idioma

Si se habilita el formato simple, mkvextract(1) solo exportará una entrada por cada átomo de capítulo encontrado, incluso si un átomo de capítulo contiene más de un nombre de capítulo. Por defecto, mkvextract(1) utilizará el primer nombre de capítulo encontrado para cada átomo, independientemente de su idioma.

El uso de esta opción permite al usuario determinar qué nombres de capítulo se exportan si los átomos contienen más de un nombre de capítulo. El parámetro idioma debe ser un código ISO 639-1 o ISO 639-2.

Los capítulos se escriben en el archivo de salida especificado. Por defecto, se utiliza el formato XML entendido por mkvmerge(1). Si no se encuentran capítulos en el archivo, el archivo de salida no se crea.

Modo de extracción de etiquetas

Sintaxis: mkvextract archivo-fuente tags [opciones] archivo-salida.xml

-T, --no-track-tags

Exporta solo las etiquetas que no son específicas de la pista.

Las etiquetas se escriben en el archivo de salida especificado en el formato XML entendido por mkvmerge(1). Si no se encuentran etiquetas en el archivo, el archivo de salida no se crea.

Modo de extracción de hoja de cues

Sintaxis: mkvextract archivo-fuente cuesheet [opciones] archivo-salida.cue

La hoja de cues se escribe en el archivo de salida especificado. Si no se encuentran capítulos o etiquetas en el archivo, el archivo de salida no se crea.

Modo de extracción de marcas de tiempo

Sintaxis: mkvextract archivo-fuente timestamps_v2 [opciones] TID1:nombre-archivo-salida1 [TID2:nombre-archivo-salida2 ...]

TID:nombre-salida

Causa la extracción de las marcas de tiempo de la pista con el ID TID al archivo nombre-salida si dicha pista existe en el archivo fuente. Esta opción se puede especificar varias veces. Los IDs de las pistas son los mismos que los que muestra la opción --identify de mkvmerge(1).

Ejemplo:

$ mkvextract input.mkv timestamps_v2 1:ts-track1.txt 2:ts-track2.txt

Modo de extracción de cues

Sintaxis: mkvextract archivo-fuente cues [opciones] TID1:nombre-archivo-salida1 [TID2:nombre-archivo-salida2 ...]

TID:nombre-archivo-salida

Causa la extracción de los cues de la pista con el ID TID al archivo nombre-salida si dicha pista existe en el archivo fuente. Esta opción se puede especificar varias veces. Los IDs de las pistas son los mismos que los que muestra la opción --identify de mkvmerge(1) y no los números contenidos en el elemento CueTrack.

El formato de salida es un formato de texto simple: una línea por elemento CuePoint con pares clave=valor. Si un elemento opcional no está presente en un CuePoint (por ejemplo, CueDuration), se mostrará un guion como valor.

Ejemplo:

timestamp=00:00:13.305000000 duration=- cluster_position=757741 relative_position=11

Las claves posibles son:

timestamp

La marca de tiempo del punto de cue con precisión de nanosegundos. El formato es HH:MM:SS.nnnnnnnnn. Este elemento siempre está establecido.

duration

La duración del punto de cue con precisión de nanosegundos. El formato es HH:MM:SS.nnnnnnnnn.

cluster_position

La posición absoluta en bytes dentro del archivo Matroska(TM) donde comienza el clúster que contiene el elemento referenciado.

Nota
Dentro del archivo Matroska(TM), CueClusterPosition es relativo al offset de inicio de datos del segmento. Sin embargo, el valor mostrado por el modo de extracción de cues de mkvextract(1) contiene ya ese offset y es un offset absoluto desde el principio del archivo.

relative_position

La posición relativa en bytes dentro del clúster donde comienza el elemento BlockGroup o SimpleBlock al que se refiere el punto de cue.

Nota
Dentro del archivo Matroska(TM), CueRelativePosition es relativo al offset de inicio de datos del clúster. Sin embargo, el valor mostrado por el modo de extracción de cues de mkvextract(1) es relativo al ID del clúster. La posición absoluta dentro del archivo se puede calcular sumando cluster_position y relative_position.

Ejemplo:

$ mkvextract input.mkv cues 1:cues-track1.txt 2:cues-track2.txt

EJEMPLOS

Extracción simultánea de capítulos y etiquetas en sus respectivos formatos XML:

$ mkvextract movie.mkv chapters movie-chapters.xml tags movie-tags.xml

Extracción simultánea de un par de pistas y sus respectivas marcas de tiempo:

$ mkvextract "Another Movie.mkv" tracks 0:video.h265 "1:main audio.aac" "2:director's comments.aac" timestamps_v2 "0:timestamps video.txt" "1:timestamps main audio.txt" "2:timestamps director's comments.txt"

Extracción de capítulos en formato Ogg/OGM y re-codificación de una pista de subtítulos de texto a otro conjunto de caracteres:

$ mkvextract "My Movie.mkv" chapters --simple "My Chapters.txt" tracks -c MS-ANSI "2:My Subtitles.srt"

Para una discusión en profundidad sobre cómo todas las herramientas del conjunto MKVToolNix manejan las conversiones de juegos de caracteres, la codificación de entrada/salida, la codificación de la línea de comandos y la codificación de la consola, consulte la sección del mismo nombre en la página man de mkvmerge(1).

FORMATOS DE ARCHIVO DE SALIDA

La decisión sobre el formato de salida se basa en el tipo de pista, no en la extensión utilizada para el nombre del archivo de salida. Actualmente, se admiten los siguientes tipos de pistas:

A_AAC/MPEG2/*, A_AAC/MPEG4/*, A_AAC

Todos los archivos AAC se escribirán en un archivo AAC con encabezados ADTS antes de cada paquete. Los encabezados ADTS no contendrán el campo de énfasis obsoleto.

A_AC3, A_EAC3

Estos se extraerán a archivos AC-3 sin procesar.

A_ALAC

Las pistas ALAC se escribirán en archivos CAF.

A_DTS

Estos se extraerán a archivos DTS sin procesar.

A_FLAC

Las pistas FLAC se escribirán en archivos FLAC sin procesar.

A_MPEG/L2

Las transmisiones MPEG-1 Audio Layer II se extraerán a archivos MP2 sin procesar.

A_MPEG/L3

Estos se extraerán a archivos MP3 sin procesar.

A_OPUS

Las pistas Opus(TM) se escribirán en archivos OggOpus(TM).

A_PCM/INT/LIT, A_PCM/INT/BIG

Los datos PCM sin procesar se escribirán en un archivo WAV. Los datos de enteros big-endian se convertirán a datos little-endian durante el proceso.

A_REAL/*

Las pistas RealAudio(TM) se escribirán en archivos RealMedia(TM).

A_TRUEHD, A_MLP

Estos se extraerán a archivos TrueHD/MLP sin procesar.

A_TTA1

Las pistas TrueAudio(TM) se escribirán en archivos TTA. Tenga en cuenta que debido a la precisión limitada de las marcas de tiempo de Matroska(TM), el encabezado del archivo extraído diferirá en dos campos: data_length (el número total de muestras en el archivo) y la CRC.

A_VORBIS

El audio Vorbis se escribirá en un archivo OggVorbis(TM).

A_WAVPACK4

Las pistas WavPack(TM) se escribirán en archivos WV.

S_HDMV/PGS

Los subtítulos PGS se escribirán como archivos SUP.

S_HDMV/TEXTST

Los subtítulos TextST se escribirán en un formato de archivo especial inventado para mkvmerge(1) y mkvextract(1).

S_KATE

Las transmisiones Kate(TM) se escribirán dentro de un contenedor Ogg(TM).

S_TEXT/SSA, S_TEXT/ASS, S_SSA, S_ASS

Los subtítulos de texto SSA y ASS se escribirán como archivos SSA/ASS respectivamente.

S_TEXT/UTF8, S_TEXT/ASCII

Los subtítulos de texto simple se escribirán como archivos SRT.

S_VOBSUB

Los subtítulos VobSub(TM) se escribirán como archivos SUB junto con los archivos de índice correspondientes, como archivos IDX.

NAME

mkvextract(1) – extract tracks from Matroska files

SYNOPSIS

mkvextract [-h|--help] [-v|--version] [-r|--redirect-io] [-a LANG-LIST|--audio-tracks LANG-LIST] [-s LANG-LIST|--subtitle-tracks LANG-LIST] [-d TRACK-IDS|--tracks TRACK-IDS] [-b TRACK-IDS|--blocktracks TRACK-IDS] [-t ID|--tags ID] [-c ID|--chapters ID] [-a ID|--attachments ID] [--no-chapters] [--no-tags] [--no-attachments] [--chapter-charset CHARSET] [--tags-charset CHARSET] [--redirect-stderr FILE] [--debug DEBUG-OPTIONS] [--engage FEATURE[+*]] [SOURCE-FILE] [OUTPUT-FILE(S)]

DESCRIPTION

mkvextract is a tool for extracting tracks from Matroska files into separate files. It can also extract chapters, tags and attachments.

The program can be invoked in two ways:

  • mkvextract tracks --audio-tracks all --subtitle-tracks all input.mkv

    This will extract all audio and subtitle tracks from input.mkv into separate files. The output filenames will be generated automatically, based on the track's type, language and ID.

  • mkvextract chapters --chapters 0 input.mkv output.xml

    This will extract the chapters from input.mkv into the file output.xml.

The tracks, chapters, tags and attachments are the different modules of mkvextract. Each module can be selected by specifying its name as the first argument.

If SOURCE-FILE is omitted, mkvextract will try to detect it from standard input.

If OUTPUT-FILE(S) are omitted, mkvextract will write to stdout if the module supports it (e.g. chapters, tags), otherwise it will generate filenames automatically.

If SOURCE-FILE is omitted and mkvextract is not reading from standard input, it will read from the file named -.

Multiple OUTPUT-FILE(S) can be specified for the tracks module. If not enough output filenames are given, the remaining tracks will be written to stdout.

See the man pages for the individual modules for more detailed information on the options for each module.

EXAMPLES

mkvextract tracks --tracks 1:a --tracks 2:s input.mkv Extract track number 1 as audio and track number 2 as subtitle.

mkvextract tracks --audio-tracks eng --subtitle-tracks all input.mkv Extract the English audio track and all subtitle tracks.

mkvextract chapters --chapters 0 input.mkv chapters.xml Extract the chapters into the file chapters.xml.

mkvextract tags --tags 0 input.mkv tags.xml Extract the tags into the file tags.xml.

mkvextract attachments --attachments all input.mkv Extract all attachments.

TEXT FILES AND CHARACTER SET CONVERSIONS

Most text-based subtitle formats and the chapter/tag XML files are written using the UTF-8 character set. The user can specify the character set for the output files with the options --charset and --tags-charset. The default character set is UTF-8.

OUTPUT FILE FORMATS

The following output file formats are supported:

S_TEXT/ASS

Advanced SubStation Alpha subtitles will be written as ASS files.

S_TEXT/SRT

SubRip subtitles will be written as SRT files.

S_TEXT/SSA

SubStation Alpha subtitles will be written as SSA files.

S_TEXT/USF

USF text subtitles will be written as USF files.

S_TEXT/WEBVTT

WebVTT text subtitles will be written as WebVTT files.

V_MPEG1, V_MPEG2

MPEG-1 and MPEG-2 video tracks will be written as MPEG elementary streams.

V_MPEG4/ISO/AVC

H.264 / AVC video tracks are written to H.264 elementary streams which can be processed further with e.g. MP4Box(TM) from the GPAC(TM) package.

V_MPEG4/ISO/HEVC

H.265 / HEVC video tracks are written to H.265 elementary streams which can be processed further with e.g. MP4Box(TM) from the GPAC(TM) package.

V_MS/VFW/FOURCC

Fixed FPS video tracks with this CodecID are written to AVI files.

V_REAL/*

RealVideo(TM) tracks are written to RealMedia(TM) files.

V_THEORA

Theora(TM) streams will be written within an Ogg(TM) container

V_VP8, V_VP9

VP8 / VP9 tracks are written to IVF files.

Tags

Tags are converted to a XML format. This format is the same that mkvmerge(1) supports for reading tags.

Attachments

Attachments are written to the output file as they are. No conversion whatsoever is done.

Chapters

Chapters are converted to a XML format. This format is the same that mkvmerge(1) supports for reading chapters. Alternatively a stripped-down version can be output in the simple OGM style format.

Timestamps

Timestamps are first sorted and then output as a timestamp v2 format compliant file ready to be fed to mkvmerge(1). The extraction to other formats (v1, v3 and v4) is not supported.

EXIT CODES

mkvextract(1) exits with one of three exit codes:

•0 -- This exit code means that extraction has completed successfully.
•1 -- In this case mkvextract(1) has output at least one warning, but extraction did continue. A warning is prefixed with the text 'Warning:'. Depending on the issues involved the resulting files might be ok or not. The user is urged to check both the warning and the resulting files.
•2 -- This exit code is used after an error occurred. mkvextract(1) aborts right after outputting the error message. Error messages range from wrong command line arguments over read/write errors to broken files.

ENVIRONMENT VARIABLES

mkvextract(1) uses the default variables that determine the system's locale (e.g. LANG and the LC_* family). Additional variables:

MKVEXTRACT_DEBUG, MKVTOOLNIX_DEBUG and its short form MTX_DEBUG

The content is treated as if it had been passed via the --debug option.

MKVEXTRACT_ENGAGE, MKVTOOLNIX_ENGAGE and its short form MTX_ENGAGE
