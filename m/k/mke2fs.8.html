NOMBRE

mke2fs - crear un sistema de archivos ext2/ext3/ext4

SINOPSIS

mke2fs [ -c | -l nombre-archivo ] [ -b tamaño-bloque ] [ -C tamaño-cluster ] [ -d directorio-raiz|archivo-tar ] [ -D ] [ -g bloques-por-grupo ] [ -G numero-de-grupos ] [ -i bytes-por-inodo ] [ -I tamaño-inodo ] [ -j ] [ -J opciones-journal ] [ -N numero-de-inodos ] [ -n ] [ -m porcentaje-bloques-reservados ] [ -o os-creador ] [ -O [^]caracteristica[,...] ] [ -q ] [ -E opciones-extendidas ] [ -v ] [ -F ] [ -L etiqueta-volumen ] [ -M ultimo-directorio-montado ] [ -S ] [ -t tipo-fs ] [ -T tipo-uso ] [ -U UUID ] [ -V ] [ -e comportamiento-errores ] [ -z archivo-deshacer ] dispositivo [ tamaño-fs ]

mke2fs -O journal_dev [ -b tamaño-bloque ] [ -L etiqueta-volumen ] [ -n ] [ -q ] [ -v ] journal-externo [ tamaño-fs ]

DESCRIPCIÓN

mke2fs se utiliza para crear un sistema de archivos ext2, ext3 o ext4, normalmente en una partición (o archivo) de disco denominada por dispositivo.

El tamaño del sistema de archivos se especifica mediante tamaño-fs. Si tamaño-fs no tiene un sufijo, se interpreta como kilobytes de potencia de dos, a menos que se especifique la opción -b tamaño-bloque, en cuyo caso tamaño-fs se interpreta como el número de bloques de tamaño-bloque. Si tamaño-fs tiene el sufijo 'k', 'm', 'g', 't' (en mayúsculas o minúsculas), se interpreta en kilobytes, megabytes, gigabytes, terabytes, etc., de potencia de dos. Si se omite tamaño-fs, mke2fs creará el sistema de archivos basándose en el tamaño del dispositivo.

Si mke2fs se ejecuta como mkfs.XXX (es decir, mkfs.ext2, mkfs.ext3 o mkfs.ext4), se implica la opción -t XXX; por lo tanto, mkfs.ext3 creará un sistema de archivos para usar con ext3, mkfs.ext4 creará un sistema de archivos para usar con ext4, y así sucesivamente.

Los valores predeterminados de los parámetros para el sistema de archivos recién creado, si no se anulan con las opciones que se enumeran a continuación, se controlan mediante el archivo de configuración /etc/mke2fs.conf. Consulte la página del manual de mke2fs.conf(5) para obtener más detalles.

OPCIONES

-b tamaño-bloque
Especifica el tamaño de los bloques en bytes. Los valores válidos de tamaño-bloque son potencias de dos de 1024 a 65536 (sin embargo, tenga en cuenta que el kernel solo puede montar sistemas de archivos con un tamaño de bloque menor o igual al tamaño de página del sistema (4k en sistemas x86, hasta 64k en ppc64 o aarch64 dependiendo de la configuración del kernel). Si se omite, el tamaño-bloque se determina heurísticamente por el tamaño del sistema de archivos y el uso esperado del sistema de archivos (ver la opción -T). En la mayoría de los casos comunes, el tamaño de bloque predeterminado es 4k. Si tamaño-bloque va precedido por un signo negativo ('-'), entonces mke2fs utilizará heurísticas para determinar el tamaño de bloque apropiado, con la restricción de que el tamaño de bloque será de al menos tamaño-bloque bytes. Esto es útil para ciertos dispositivos de hardware que requieren que el tamaño de bloque sea un múltiplo de 2k.
-c
Comprueba el dispositivo en busca de bloques defectuosos antes de crear el sistema de archivos. Si esta opción se especifica dos veces, se utiliza una prueba de lectura-escritura más lenta en lugar de una prueba rápida de solo lectura.
-C tamaño-cluster
Especifica el tamaño del cluster en bytes para sistemas de archivos que usan la característica bigalloc. Los valores válidos de tamaño-cluster van de 2 a 32768 veces el tamaño de bloque del sistema de archivos y deben ser una potencia de 2. El tamaño-cluster solo se puede especificar si la característica bigalloc está habilitada. (Consulte la página del manual de ext4(5) para obtener más detalles sobre bigalloc.) El tamaño de cluster predeterminado si bigalloc está habilitado es 16 veces el tamaño de bloque.
-d directorio-raiz|archivo-tar
Copia el contenido del directorio o archivo tar dado en el directorio raíz del sistema de archivos. La entrada de archivo tar solo está disponible si mke2fs se compiló con soporte para libarchive habilitado y si la biblioteca compartida libarchive está disponible en tiempo de ejecución. El valor especial "-" leerá un archivo tar de la entrada estándar.
-D
Utiliza I/O directo al escribir en el disco. Esto evita que mke2fs ensucie mucha memoria caché de búfer, lo que puede afectar a otras aplicaciones que se ejecutan en un servidor ocupado. Sin embargo, esta opción hará que mke2fs se ejecute mucho más lentamente, por lo que existe una compensación al usar I/O directo.
-e comportamiento-errores
Cambia el comportamiento del código del kernel cuando se detectan errores. En todos los casos, un error del sistema de archivos provocará que e2fsck(8) compruebe el sistema de archivos en el próximo arranque. comportamiento-errores puede ser uno de los siguientes:
continuar
Continuar la ejecución normal.
remount-ro
Remontar el sistema de archivos como solo lectura.
panic
Causar un pánico del kernel.
-E opciones-extendidas
Establecer opciones extendidas para el sistema de archivos. Las opciones extendidas se separan con comas y pueden tomar un argumento usando el signo igual ('='). La opción -E era anteriormente -R en versiones anteriores de mke2fs. La opción -R todavía se acepta para compatibilidad con versiones anteriores, pero está obsoleta. Las siguientes opciones extendidas son compatibles:
assume_storage_prezeroed[= <0 para deshabilitar, 1 para habilitar>]
Si está habilitado, mke2fs asume que el dispositivo de almacenamiento ha sido pre-cerificado, omite la puesta a cero del journal y de las tablas de inodos, y anota las marcas de los grupos de bloques para indicar que la tabla de inodos ha sido puesta a cero.
discard
Intenta descartar bloques en el momento de la creación del sistema de archivos (descartar bloques inicialmente es útil en dispositivos de estado sólido y en almacenamiento escaso / aprovisionado dinámicamente). Cuando el dispositivo anuncia que el descarte también pone a cero los datos (cualquier lectura posterior al descarte y antes de la escritura devuelve cero), marque todas las tablas de inodos no puestas a cero como puestas a cero. Esto acelera significativamente la inicialización del sistema de archivos. Esto está establecido por defecto.
encoding=nombre-codificación
Habilita la característica casefold en el superbloque y establece nombre-codificación como la codificación a utilizar. Si nombre-codificación no se especifica, se utiliza la codificación definida en mke2fs.conf(5).
encoding_flags=banderas-codificación
Define parámetros para las operaciones de codificación de caracteres de nombres de archivo. Si una bandera no se cambia mediante este parámetro, se utiliza su valor predeterminado. banderas-codificación debe ser una lista de banderas separadas por comas para habilitarlas. Para deshabilitar una bandera, añádala a la lista con el prefijo "no".

La única bandera que se puede establecer en este momento es strict, lo que significa que las cadenas no válidas deben ser rechazadas por el sistema de archivos. En la configuración predeterminada, la bandera strict está deshabilitada.

lazy_itable_init[= <0 para deshabilitar, 1 para habilitar>]
Si está habilitada y la característica uninit_bg está habilitada, la tabla de inodos no será completamente inicializada por mke2fs. Esto acelera notablemente la inicialización del sistema de archivos, pero requiere que el kernel termine de inicializar el sistema de archivos en segundo plano la primera vez que se monte. Si se omite el valor de la opción, se establece por defecto en 1 para habilitar la inicialización diferida de la tabla de inodos.
lazy_journal_init[=
-F
Fuerza la creación del sistema de archivos, incluso si el dispositivo de destino parece estar ya ocupado con un sistema de archivos. Esto es necesario si se va a crear un sistema de archivos en un dispositivo que ya contiene un sistema de archivos y que no está montado.
-f
Este es un alias para la opción -F. Se incluye por compatibilidad con versiones anteriores.
-g bloques-por-grupo
Especifica el número de bloques en cada grupo de bloques. El valor máximo permitido es 32768. Si se omite, mke2fs intentará elegir un valor razonable basado en el tamaño del sistema de archivos.
-G numero-de-grupos
Especifica el número de grupos de bloques. Esto se usa para crear sistemas de archivos grandes con un número predeterminado de grupos de bloques. Solo se permite si el sistema de archivos tiene la característica ‘flex_bg’. Si se especifica, reemplaza la opción -g.
-i bytes-por-inodo
Especifica la relación entre bytes y inodos. Para cada N bytes del espacio del dispositivo, se asignará un inodo. Por ejemplo, si se especifica bytes-por-inodo como 2048, se asignará un inodo por cada 2K de espacio del dispositivo. El valor predeterminado es 0, lo que significa que mke2fs se basará en el tamaño del sistema de archivos y en las características del sistema de archivos para determinar el número de inodos. Es mejor omitir esta opción y dejar que mke2fs elija el valor predeterminado, a menos que sepa lo que está haciendo. El valor predeterminado se puede encontrar en el archivo de configuración /etc/mke2fs.conf.
-I tamaño-inodo
Especifica el tamaño de los inodos en bytes. El tamaño debe ser una potencia de dos, entre 128 y 2048 bytes. Los tamaños de inodo más grandes pueden almacenar más atributos extendidos, pero desperdician más espacio en sistemas de archivos pequeños. El valor predeterminado es 256 bytes si se usa ext3 y 128 bytes si se usa ext2. Este valor se puede cambiar y es el valor predeterminado para todos los inodos creados. Si se especifica el tamaño de inodo mayor que 128, entonces el sistema de archivos ext3 no será compatible con versiones anteriores de kernels que no admitan tamaños de inodo más grandes.
-j
Crea el sistema de archivos con el journal ext3. Si se especifica la opción -j, mke2fs intentará crear el journal en el mismo dispositivo que el sistema de archivos principal. El tamaño del journal es 1/1000 de la capacidad del sistema de archivos, o 8192 bloques, lo que sea menor.
-J journal-options
Crea el sistema de archivos con un journal ext3. Esta opción está seguida por una lista de opciones de journal, separadas por comas. Las opciones de journal disponibles son:
device=journal-device
El journal se creará en el dispositivo especificado por journal-device. Este dispositivo debe ser un dispositivo de bloque sin montar y con un tamaño de al menos 8 MiB.
size=journal-size
Especifica el tamaño del journal en bloques de 1k. El tamaño del journal debe ser una potencia de 2, y no menos de 1024 bloques (1 MiB) ni más de 1048576 bloques (1 TiB). El tamaño predeterminado del journal si no se especifica es 1/1000 de la capacidad del sistema de archivos, o 8192 bloques (8 MiB), lo que sea menor.
jnl_location=ubicación
Si se crea un journal interno, esta opción especifica si debe estar en el principio del dispositivo (loc=beginning) o en el final (loc=end). Por defecto, se coloca al principio.
-L etiqueta-volumen
Establece la etiqueta del volumen del sistema de archivos a etiqueta-volumen. La longitud máxima de la etiqueta del volumen es de 16 bytes.
-l nombre-archivo
Comprueba el dispositivo en busca de bloques defectuosos. La lista de bloques defectuosos se lee del archivo especificado por nombre-archivo. Si nombre-archivo es un guion (-), la lista de bloques defectuosos se lee de la entrada estándar.
-m porcentaje-bloques-reservados
Especifica el porcentaje de bloques que se reservarán para el superusuario. El valor predeterminado es 5%.
-M ultimo-directorio-montado
Establece el campo de último directorio montado en el superbloque del sistema de archivos.
-n
No crear el sistema de archivos. Esta opción se puede usar con la opción -c para comprobar si hay bloques defectuosos en el dispositivo sin modificarlo.
-N numero-de-inodos
Establece el número de inodos que se crearán. Esto solo es efectivo si la opción -i no se ha especificado. Si tanto -i como -N se especifican, se utiliza la opción -i. Si ninguna de las dos opciones se especifica, mke2fs intentará calcular un número razonable de inodos basándose en el tamaño del sistema de archivos.
-o os-creador
Establece el campo de creador del sistema de archivos del superbloque. Los valores típicos son ‘linux’ (predeterminado), ‘gnuh’, ‘ Hurd’, ‘mips’, ‘FreeBSD’, etc.
-O [^]caracteristica[,...]
Crea un sistema de archivos con las características especificadas en la lista separada por comas. Si una característica va precedida por un signo de intercalación (^) , se deshabilitará en lugar de habilitarse. El comando -O seguido de ‘^has_journal’ se utiliza para crear un sistema de archivos ext2. El comando -O seguido de ‘has_journal’ (o la omisión de esta opción) se utiliza para crear un sistema de archivos ext3. Para crear un sistema de archivos ext4, se deben habilitar las características ‘extents’ y ‘huge_file’. Las características admitidas son:

El comando mke2fs -O help imprimirá una lista de todas las características compatibles con la versión instalada de e2fsprogs.

-q
Modo silencioso. No muestra ningún mensaje en stdout.
-S
Escribe la tabla de inodos en el dispositivo. Esto es útil si se va a utilizar la entrada del journal para recuperar un sistema de archivos dañado después de que se haya creado el sistema de archivos.
-t tipo-fs
Especifica el tipo de sistema de archivos que se va a crear. Los tipos admitidos son ext2, ext3 y ext4.
-T tipo-uso
Especifica el tipo de uso para el sistema de archivos. Esto afectará a los parámetros predeterminados utilizados para crear el sistema de archivos, como el tamaño del bloque, el número de inodos, etc. Los tipos de uso admitidos son: floppy, small, default, large, y hibernate. El valor predeterminado es default.
-U UUID
Establece el UUID del sistema de archivos al valor especificado. El formato del UUID es una cadena hexadecimal mayúscula de 32 caracteres separada por guiones en el formato 8-4-4-4-12.
-v
Modo detallado. Muestra más información mientras se crea el sistema de archivos.
-V
Muestra la versión de mke2fs y sale.
-e comportamiento-errores
Este es un alias para la opción -e. Se incluye por compatibilidad con versiones anteriores.
-z archivo-deshacer
Escribe una imagen de deshacer al archivo especificado por archivo-deshacer. Esto se puede utilizar para deshacer las modificaciones realizadas por mke2fs. Tenga en cuenta que el uso de esta opción puede ralentizar significativamente la creación del sistema de archivos. Si el nombre del archivo es un guion (-), la imagen de deshacer se escribe en la salida estándar.

MKE2FS REVIRUS JOURNAL_DEV

Si mke2fs se invoca con la opción -O journal_dev, entonces el primer argumento del dispositivo es el dispositivo que contiene el journal y el segundo argumento es el dispositivo del sistema de archivos principal. Esto se utiliza para crear un journal externo para un sistema de archivos existente. El dispositivo de journal debe ser lo suficientemente grande para contener el journal (al menos 8 MiB).

EJEMPLOS

Para crear un sistema de archivos ext3 en el dispositivo /dev/hda1 con una etiqueta de volumen "datos":

mke2fs -j -L datos /dev/hda1

Para crear un sistema de archivos ext4 con un tamaño de bloque de 4096 bytes, reservando el 2% de los bloques para el superusuario y con una etiqueta de volumen "logs":

mke2fs -t ext4 -b 4096 -m 2 -L logs /dev/sda1

Para crear un sistema de archivos ext2 en el dispositivo /dev/sdb1 y luego comprobar si hay bloques defectuosos:

mke2fs -c /dev/sdb1

Para crear un sistema de archivos ext4 en el dispositivo /dev/sdc1 con la característica `flex_bg` habilitada:

mke2fs -O flex_bg /dev/sdc1

Para crear un sistema de archivos ext4 en el dispositivo /dev/sdc1 con la característica `metadata_csum` habilitada:

mke2fs -O metadata_csum /dev/sdc1

<0 para deshabilitar, 1 para habilitar>
Si está habilitado, el inode del journal no se pondrá completamente a cero mediante mke2fs. Esto acelera notablemente la inicialización del sistema de archivos, pero conlleva un pequeño riesgo si el sistema falla antes de que el journal se haya sobrescrito por completo una vez. Si el valor de la opción se omite, por defecto será 1, lo que habilita el puesto a cero perezoso del inode del journal.
mmp_update_interval=intervalo
Ajusta el intervalo inicial de actualización del MMP a intervalo segundos. Especificar un intervalo de 0 significa usar el intervalo por defecto. El intervalo especificado debe ser inferior a 300 segundos. Requiere que la característica mmp esté habilitada. nodiscard No intentes descartar bloques en el momento de la creación del sistema de archivos (mkfs).
no_copy_xattrs
Normalmente, mke2fs copiará los atributos extendidos de los archivos en la jerarquía de directorios especificada a través de la opción (opcional) -d. Esto deshabilitará la copia y dejará los archivos en el nuevo sistema de archivos sin ningún atributo extendido.
num_backup_sb=<0|1|2>
Si la característica del sistema de archivos sparse_super2 está habilitada, esta opción controla si se crearán 0, 1 o 2 superbloques de respaldo en el sistema de archivos.
offset=offset
Crea el sistema de archivos en un desplazamiento desde el principio del dispositivo o archivo. Esto puede ser útil al crear imágenes de disco para máquinas virtuales.
orphan_file_size=tamaño
Establece el tamaño del archivo para rastrear inodes desvinculados pero aún abiertos y inodes con operaciones de truncamiento en curso. Un archivo más grande permite una mejor escalabilidad, reservando algunos bloques por CPU es lo ideal.
packed_meta_blocks[= <0 para deshabilitar, 1 para habilitar>]
Coloca los mapas de bits de asignación y la tabla de inodes al principio del disco. Esta opción requiere que la característica del sistema de archivos flex_bg esté habilitada para que tenga efecto, y también creará el journal al principio del sistema de archivos. Esta opción es útil para dispositivos flash que utilizan flash SLC al principio del disco. También maximiza el rango de bloques de datos contiguos, lo que puede ser útil para ciertos casos de uso especializados, como las unidades Shingled (SMR) soportadas.
quotatype
Especifica los tipos de cuotas (usrquota, grpquota, prjquota) que deben estar habilitados en el sistema de archivos creado. El argumento de esta opción extendida debe ser una lista separada por dos puntos. Esta opción solo tiene efecto si se establece la característica quota. Los tipos de cuota por defecto a inicializar si no se especifica esta opción son las cuotas de usuario y grupo. Si la característica de proyecto está habilitada, también se inicializarán las cuotas de proyecto.
resize=max-online-resize
Reserva suficiente espacio para que la tabla descriptora de grupos de bloques pueda crecer y soportar un sistema de archivos con max-online-resize bloques.
revision=fs-revision
Especifica el número de revisión del sistema de archivos. Los sistemas de archivos de revisión 0 proporcionan compatibilidad con los kernels Linux anteriores a la versión 1.2 (anteriores a 1995). Esto solo es necesario para pruebas o para personas que quieran usar sistemas Linux muy antiguos e históricos. La revisión actual por defecto (soportada por todos los sistemas Linux modernos) es la revisión 1.
root_owner[=uid:gid]
Especifica el ID numérico de usuario y grupo del directorio raíz. Si no se especifica UID:GID, se utilizará el ID de usuario y grupo del usuario que ejecuta mke2fs. En mke2fs 1.42 y anteriores, el UID y GID del directorio raíz se establecían por defecto al UID y GID del usuario que ejecutaba el comando mke2fs. La opción root_owner= permite especificar explícitamente estos valores y evitar efectos secundarios para usuarios que no esperan que el contenido del sistema de archivos cambie en función del usuario que ejecuta mke2fs.
root_perms[=permisos]
Especifica los permisos del directorio raíz en formato octal. Si no se especifican permisos, los permisos del directorio raíz se establecerán de acuerdo con la máscara umask del sistema de archivos por defecto.
stride=stride-size
Configura el sistema de archivos para un array RAID con un tamaño de grupo de stride-size bloques del sistema de archivos. Este es el número de bloques que se leen o escriben en el disco antes de pasar al siguiente disco, lo que a veces se denomina tamaño de fragmento (chunk size). Esto afecta principalmente a la colocación de metadatos del sistema de archivos como los mapas de bits en el momento de la creación (mke2fs) para evitar colocarlos en un solo disco, lo que puede perjudicar el rendimiento. También puede ser utilizado por el asignador de bloques.
stripe_width=stripe-width
Configura el sistema de archivos para un array RAID con stripe-width bloques del sistema de archivos por franja (stripe). Esto es típicamente stride-size * N, donde N es el número de discos que almacenan datos en el RAID (por ejemplo, para RAID 5 hay un disco de paridad, por lo que N será el número de discos en el array menos 1). Esto permite que el asignador de bloques evite, en la medida de lo posible, escrituras de lectura-modificación-escritura de la paridad en una franja RAID cuando se escriben los datos.
test_fs
Establece un indicador en el superbloque del sistema de archivos que indica que puede montarse utilizando código de kernel experimental, como el sistema de archivos ext4dev.
-F
Obliga a mke2fs a crear un sistema de archivos, incluso si el dispositivo especificado no es una partición en un dispositivo especial de bloques, o si otros parámetros no tienen sentido. Para obligar a mke2fs a crear un sistema de archivos incluso si el sistema de archivos parece estar en uso o montado (algo verdaderamente peligroso de hacer), esta opción debe especificarse dos veces.
-g bloques-por-grupo
Especifica el número de bloques en un grupo de bloques. Generalmente, no hay razón para que el usuario establezca este parámetro, ya que el valor por defecto es óptimo para el sistema de archivos. (Para administradores que están creando sistemas de archivos en arrays RAID, es preferible usar el parámetro RAID stride como parte de la opción -E en lugar de manipular el número de bloques por grupo). Esta opción se utiliza generalmente por desarrolladores que crean casos de prueba.
Si la característica bigalloc está habilitada, la opción -g especificará el número de clústeres en un grupo de bloques.
-G número-de-grupos
Especifica el número de grupos de bloques que se empaquetarán para crear un grupo de bloques virtual más grande (o grupo "flex_bg") en un sistema de archivos ext4. Esto mejora la localidad de los metadatos y el rendimiento en cargas de trabajo intensivas en metadatos. El número de grupos debe ser una potencia de 2 y solo puede especificarse si la característica del sistema de archivos flex_bg está habilitada.
-i bytes-por-inode
Especifica la relación bytes/inode. mke2fs crea un inode por cada bytes-per-inode bytes de espacio en el disco. Cuanto mayor sea la relación bytes-per-inode, menos inodes se crearán. Este valor generalmente no debe ser menor que el tamaño de bloque del sistema de archivos, ya que en ese caso se crearían más inodes de los que se pueden utilizar. Tenga en cuenta que no es posible cambiar esta relación en un sistema de archivos después de su creación, así que tenga cuidado al decidir el valor correcto para este parámetro. Tenga en cuenta que el redimensionamiento de un sistema de archivos cambia el número de inodes para mantener esta relación.
-I tamaño-de-inode
Especifica el tamaño de cada inode en bytes. El valor de tamaño-de-inode debe ser una potencia de 2 mayor o igual a 128. Cuanto mayor sea el tamaño-de-inode, más espacio consumirá la tabla de inodes, lo que reduce el espacio utilizable en el sistema de archivos y también puede afectar negativamente al rendimiento. No es posible cambiar este valor después de que se crea el sistema de archivos.
Los sistemas de archivos con un tamaño de inode de 128 bytes no soportan marcas de tiempo posteriores al 19 de enero de 2038. Los inodes de 256 bytes o más grandes soportarán marcas de tiempo extendidas, IDs de proyecto y la capacidad de almacenar algunos atributos extendidos en la tabla de inodes para mejorar el rendimiento.
El tamaño de inode por defecto está controlado por el archivo mke2fs.conf(5). En el archivo mke2fs.conf incluido con e2fsprogs, el tamaño de inode por defecto es de 256 bytes para todos los sistemas de archivos, excepto para GNU Hurd, ya que solo soporta inodes de 128 bytes.
-j
Crea el sistema de archivos con un journal ext3. Si la opción -J no se especifica, se utilizarán los parámetros del journal por defecto para crear un journal de tamaño apropiado (dado el tamaño del sistema de archivos) almacenado dentro del sistema de archivos. Tenga en cuenta que debe estar utilizando un kernel que tenga soporte ext3 para poder utilizar realmente el journal.
-J opciones-de-journal
Crea el journal ext3 utilizando las opciones especificadas en la línea de comandos. Las opciones del journal se separan por comas y pueden tomar un argumento usando el signo igual ('='). Las siguientes opciones de journal son compatibles:
device=journal-externo
Adjunta el sistema de archivos al dispositivo de bloques del journal ubicado en journal-externo. El journal externo debe haber sido creado previamente utilizando el comando
mke2fs -O journal_dev journal-externo
Tenga en cuenta que journal-externo debe haber sido creado con el mismo tamaño de bloque que el nuevo sistema de archivos. Además, aunque existe soporte para adjuntar múltiples sistemas de archivos a un único journal externo, el kernel de Linux y e2fsck(8) actualmente no soportan journals externos compartidos.
En lugar de especificar un nombre de dispositivo directamente, journal-externo también puede especificarse mediante LABEL=etiqueta o UUID=UUID para localizar el journal externo por la etiqueta del volumen o el UUID almacenado en el superbloque ext2 al inicio del journal. Utilice dumpe2fs(8) para mostrar la etiqueta del volumen y el UUID de un dispositivo de journal. Ver también la opción -L de tune2fs(8).
fast_commit_size=tamaño-commit-rápido
Crea un área de journal de commit rápido adicional de tamaño tamaño-commit-rápido kilobytes. Esta opción solo es válida si el feature fast_commit está habilitado en el sistema de archivos. Si esta opción no se especifica y el feature fast_commit está activado, el tamaño del área de commit rápido por defecto será de tamaño-journal / 64 megabytes. El tamaño total del journal con el feature fast_commit activado es tamaño-journal + ( tamaño-commit-rápido * 1024) megabytes. El tamaño total del journal no puede exceder los 10.240.000 bloques del sistema de archivos o la mitad del tamaño total del sistema de archivos (lo que sea menor).
location=ubicación-journal
Especifica la ubicación del journal. El argumento ubicación-journal puede especificarse como un número de bloque, o si el número tiene un sufijo de unidad (por ejemplo, 'M', 'G', etc.) interpretarlo como el desplazamiento desde el inicio del sistema de archivos.
size=tamaño-journal
Crea un journal interno (es decir, almacenado dentro del sistema de archivos) de tamaño tamaño-journal megabytes. El tamaño del journal debe ser de al menos 1024 bloques del sistema de archivos (es decir, 1MB si se usan bloques de 1k, 4MB si se usan bloques de 4k, etc.) y no puede exceder los 10.240.000 bloques del sistema de archivos o la mitad del tamaño total del sistema de archivos (lo que sea menor).
Solo se puede dar una de las opciones size o device para un sistema de archivos.
-l nombre-archivo
Lee la lista de bloques defectuosos del nombre-archivo. Ten en cuenta que los números de bloque en la lista de bloques defectuosos deben generarse utilizando el mismo tamaño de bloque que utiliza mke2fs. Como resultado, la opción -c de mke2fs es un método mucho más sencillo y menos propenso a errores para comprobar un disco en busca de bloques defectuosos antes de formatearlo, ya que mke2fs pasará automáticamente los parámetros correctos al programa badblocks.
-L nueva-etiqueta-volumen
Establece la etiqueta del volumen para el sistema de archivos a nueva-etiqueta-volumen. La longitud máxima de la etiqueta del volumen es de 16 bytes.
-m porcentaje-bloques-reservados
Especifica el porcentaje de bloques del sistema de archivos reservados para el superusuario. Esto evita la fragmentación y permite que los demonios propiedad de root, como syslogd(8), continúen funcionando correctamente después de que los procesos no privilegiados no puedan escribir en el sistema de archivos. El porcentaje por defecto es del 5%.
-M directorio-ultimo-montaje
Establece el directorio de último montaje para el sistema de archivos. Esto puede ser útil para utilidades que utilizan el directorio de último montaje para determinar dónde se debe montar el sistema de archivos.
-n
Hace que mke2fs no cree realmente un sistema de archivos, sino que muestre lo que haría si creara un sistema de archivos. Esto se puede utilizar para determinar la ubicación de los superbloques de copia de seguridad para un sistema de archivos determinado, siempre y cuando se utilicen los parámetros de mke2fs que se pasaron cuando se creó originalmente el sistema de archivos. (¡Con la opción -n añadida, por supuesto!)
-N numero-de-inodes
Anula el cálculo por defecto del número de inodos que deben reservarse para el sistema de archivos (que se basa en el número de bloques y la relación bytes-por-inodo). Esto permite al usuario especificar directamente el número deseado de inodos.
-o sistema-operativo-creador
Anula el valor por defecto del campo "sistema operativo creador" del sistema de archivos. El campo creador se establece por defecto al nombre del SO para el que se compiló el ejecutable mke2fs.
-O [^]feature[,...]
Crea un sistema de archivos con los features (opciones del sistema de archivos) dados, anulando las opciones por defecto del sistema de archivos. Los features que están habilitados por defecto se especifican por la relación base_features, ya sea en la sección [defaults] del archivo de configuración /etc/mke2fs.conf, o en las subsecciones [fs_types] para los tipos de uso según lo especificado por la opción -T, modificado además por la relación features que se encuentra en las subsecciones [fs_types] para el sistema de archivos y los tipos de uso. Consulte la página del manual mke2fs.conf(5) para obtener más detalles. La configuración específica del tipo de sistema de archivos que se encuentra en la sección [fs_types] anulará la configuración por defecto global que se encuentra en [defaults].

El conjunto de features del sistema de archivos se editará además utilizando el conjunto de features especificado por esta opción, o si esta opción no se proporciona, utilizando la relación default_features para el tipo de sistema de archivos que se está creando, o en la sección [defaults] del archivo de configuración.

El conjunto de features del sistema de archivos consta de una lista de features, separados por comas, que se habilitarán. Para deshabilitar un feature, simplemente anteponga al nombre del feature un carácter de intercalación ('^'). Los features con dependencias no se eliminarán correctamente. El feature pseudo-sistema de archivos "none" borrará todos los features del sistema de archivos.

Para obtener más información sobre los features que se pueden establecer, consulte la página del manual ext4(5).

-q
Ejecución silenciosa. Útil si mke2fs se ejecuta en un script. -S Escribe solo el superbloque y los descriptores de grupo. Esta es una medida extrema que debe tomarse solo en el caso muy improbable de que todos los superbloques y superbloques de copia de seguridad estén corruptos, y los usuarios experimentados deseen un último recurso de recuperación. Hace que mke2fs reinicialice el superbloque y los descriptores de grupo, sin tocar la tabla de inodos ni los bitmaps de bloques e inodos. El programa e2fsck debe ejecutarse inmediatamente después de usar esta opción, y no hay garantía de que se pueda recuperar ningún dato. Debido a la gran variedad de opciones posibles para mke2fs que afectan a la disposición en disco, es fundamental especificar exactamente las mismas opciones de formato, como tamaño de bloque, tipo de sistema de archivos, flags de features y otros parámetros ajustables al usar esta opción, o el sistema de archivos se corromperá aún más. En algunos casos, como sistemas de archivos que han sido redimensionados, o a los que se les han habilitado features después del formato, es imposible sobrescribir correctamente todos los superbloques, y ocurrirá al menos algo de corrupción en el sistema de archivos. Es mejor ejecutar esto en una copia completa del sistema de archivos para poder probar otras opciones si esta no funciona.
-t tipo-sistema-archivos
Especifica el tipo de sistema de archivos (es decir, ext2, ext3, ext4, etc.) que se va a crear. Si esta opción no se especifica, mke2fs elegirá un valor por defecto, ya sea por cómo se ejecutó el comando (por ejemplo, usando un nombre como mkfs.ext2, mkfs.ext3, etc.) o por un valor por defecto definido por el archivo /etc/mke2fs.conf. Esta opción controla qué opciones del sistema de archivos se utilizan por defecto, basándose en la sección de configuración fstypes en /etc/mke2fs.conf.

Si se utiliza la opción -O para añadir o eliminar explícitamente opciones del sistema de archivos que deben establecerse en el sistema de archivos recién creado, el sistema de archivos resultante puede no ser compatible con el tipo-sistema-archivos solicitado. (por ejemplo, "mke2fs -t ext3 -O extent /dev/sdXX" creará un sistema de archivos que no es compatible con la implementación ext3 encontrada en el kernel de Linux; y "mke2fs -t ext3 -O ^has_journal /dev/hdXX" creará un sistema de archivos que no tiene journal y, por lo tanto, no será compatible con el código del sistema de archivos ext3 en el kernel de Linux).

-T tipo-uso[,...]
Especifica cómo se va a utilizar el sistema de archivos, para que mke2fs pueda elegir parámetros óptimos del sistema de archivos para ese uso. Los tipos de uso que se admiten se definen en el archivo de configuración /etc/mke2fs.conf. El usuario puede especificar uno o más tipos de uso utilizando una lista separada por comas.

Si esta opción no se especifica, mke2fs elegirá un único tipo de uso por defecto basado en el tamaño del sistema de archivos a crear. Si el tamaño del sistema de archivos es inferior a 3 megabytes, mke2fs utilizará el tipo de sistema de archivos floppy. Si el tamaño del sistema de archivos es mayor o igual a 3 pero inferior a 512 megabytes, mke2fs(8) utilizará el tipo de sistema de archivos small. Si el tamaño del sistema de archivos es mayor o igual a 4 terabytes pero inferior a 16 terabytes, mke2fs(8) utilizará el tipo de sistema de archivos big. Si el tamaño del sistema de archivos es mayor o igual a 16 terabytes, mke2fs(8) utilizará el tipo de sistema de archivos huge. De lo contrario, mke2fs(8) utilizará el tipo de sistema de archivos por defecto default.

-U UUID
Establece el identificador universalmente único (UUID) del sistema de archivos a UUID. El formato del UUID es una serie de dígitos hexadecimales separados por guiones, así: "c1b9d5a2-f162-11cf-9ece-0020afc76f16". El parámetro UUID también puede ser uno de los siguientes:
clear
borra el UUID del sistema de archivos
random
genera un nuevo UUID generado aleatoriamente
time
genera un nuevo UUID basado en el tiempo
-v
Ejecución detallada.
-V
Imprime el número de versión de mke2fs y sale.
-z archivo-deshacer
Antes de sobrescribir un bloque del sistema de archivos, escribe el contenido anterior del bloque en un archivo de deshacer. Este archivo de deshacer se puede utilizar con e2undo(8) para restaurar el contenido anterior del sistema de archivos si algo sale mal. Si se pasa la cadena vacía como argumento de archivo-deshacer, el archivo de deshacer se escribirá en un archivo llamado mke2fs-dispositivo.e2undo en el directorio especificado a través de la variable de entorno E2FSPROGS_UNDO_DIR o

DIRECTIVAS DEL ARCHIVO DE CONFIGURACIÓN

fs_dir
Define el directorio donde se almacenarán los sistemas de archivos.
mke2fs_dir
Define el directorio donde se almacenarán los archivos de instantánea de MKE2FS.
undo_dir
Define el directorio donde se almacenarán los archivos de deshacer. Si no se establece, el archivo de deshacer no se utiliza.

ADVERTENCIA: El archivo de deshacer no se puede usar para recuperarse de un corte de energía o un bloqueo del sistema.

ENTORNO

MKE2FS_SYNC
Si se establece en un valor entero distinto de cero, su valor se utiliza para determinar la frecuencia con la que se llama a sync(2) durante la inicialización de la tabla de inodos.
MKE2FS_CONFIG
Determina la ubicación del archivo de configuración (consulte mke2fs.conf(5)).
MKE2FS_FIRST_META_BG
Si se establece en un valor entero distinto de cero, su valor se utiliza para determinar el primer grupo de metadatos. Esto es principalmente para fines de depuración.
MKE2FS_DEVICE_SECTSIZE
Si se establece en un valor entero distinto de cero, su valor se utiliza para determinar el tamaño lógico de sector del dispositivo.
MKE2FS_DEVICE_PHYS_SECTSIZE
Si se establece en un valor entero distinto de cero, su valor se utiliza para determinar el tamaño físico de sector del dispositivo.
MKE2FS_SKIP_CHECK_MSG
Si está establecido, no se muestra el mensaje de comprobación automática del sistema de archivos causada por el recuento de montaje o el intervalo de comprobación.
