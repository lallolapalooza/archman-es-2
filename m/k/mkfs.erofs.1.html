MKFS.EROFS(1) Manual de Comandos Generales MKFS.EROFS(1)

NOMBRE

mkfs.erofs - herramienta para crear un sistema de archivos EROFS

SINOPSIS

mkfs.erofs [OPCIONES] DESTINO FUENTE

DESCRIPCIÓN

EROFS es un nuevo sistema de archivos de solo lectura mejorado y ligero para Linux con diseños modernos (p. ej., sin buffer head, metadatos reducidos, xattrs/datos en línea, etc.) para escenarios que requieren altas prestaciones de solo lectura, como el sistema operativo Android para smartphones y LIVECDs.

También proporciona soporte de compresión de salida de tamaño fijo, que mejora la densidad de almacenamiento, mantiene índices de compresión relativamente altos, lo cual es más útil para lograr altas prestaciones en dispositivos integrados con memoria limitada, ya que tiene una sobrecarga de memoria imperceptible y minimiza el thrashing de la caché de páginas.

mkfs.erofs se utiliza para crear dicha imagen de sistema de archivos EROFS DESTINO a partir del directorio o archivo tar FUENTE.

OPCIONES

-z algoritmo-compresion[,#][:...]
Establece un algoritmo primario para la compresión de datos, que puede ser configurado con un nivel de compresión opcional. Se pueden especificar algoritmos alternativos separados por dos puntos. Consulte la salida de mkfs.erofs --help para ver una lista de los algoritmos con los que está compilado mkfs.erofs y los rangos de niveles de cada uno.
-b tamaño-bloque
Establece el tamaño de bloque fundamental del sistema de archivos en bytes. En otras palabras, especifica la cantidad más pequeña de datos que se puede acceder a la vez. El valor predeterminado es el tamaño de página del sistema. No puede ser inferior a 512 bytes.
-C tamaño-max-pcluster
Especifica el tamaño máximo del clúster físico comprimido en bytes. Esto puede hacer que se habilite la función de pcluster grande (Linux v5.13+).
-d #
Especifica el nivel de mensajes de depuración. El valor predeterminado es 2, que muestra mensajes de advertencia básicos.
-x #
Limita cuántos xattrs se incluirán en línea. El valor predeterminado es 2. Deshabilita el almacenamiento de xattrs si es < 0.
-E [^]opcion-extendida[,...]
Establece opciones extendidas para el sistema de archivos. Las opciones extendidas se separan por comas y pueden tomar un argumento adicional usando el signo igual ('='). Para deshabilitar una función, generalmente se antepone al nombre de la opción extendida un carácter de intercalación ('^'). Se admiten las siguientes opciones extendidas:
all-fragments
Registra forzosamente los archivos completos en un inode especial para una mejor compresión y puede tomar un argumento como tamaño de pcluster del inode empaquetado en bytes. (Linux v6.1+)
dedupe
Habilita la deduplicación global de datos comprimidos para minimizar los datos duplicados en el sistema de archivos. Puede reducir aún más el tamaño de la imagen cuando se usa con -E fragments. (Linux v6.1+)
force-inode-compact
Fuerza la generación de inodos compactos (de 32 bytes).
force-inode-extended
Fuerza la generación de inodos extendidos (de 64 bytes).
force-inode-blockmap
Fuerza la generación del formato de fragmento de inode como una matriz de direcciones de bloque de 4 bytes.
force-chunk-indexes
Genera forzosamente el formato de fragmento de inode como un índice de fragmento de 8 bytes (con ID de dispositivo).
[^]fragdedupe[=<inode|full>]
Establece el modo para la deduplicación de datos de fragmento. Solo es efectivo cuando se usa junto con -E(all)-fragments. Si se antepone un carácter de intercalación ('^'), la deduplicación de datos de fragmento se deshabilita.
inode
Deduplica los datos del fragmento solo cuando los datos del inode son idénticos. Esta opción resultará en una generación de imagen más rápida con la base de código actual.
full
Deduplica siempre los datos del fragmento si es posible.
fragments[=tamaño]
Empaqueta la parte final (pcluster) de los archivos comprimidos, o archivos completos, en un inode especial para tamaños de imagen más pequeños, y puede tomar un argumento como tamaño de pcluster del inode empaquetado en bytes. (Linux v6.1+)
^inline_data
No incluir datos en línea de archivos regulares. Típicamente es útil para habilitar FSDAX (Linux 5.15+), sin embargo, puede haber otros casos de uso.
legacy-compress
Deshabilita la "descompresión in situ" y los "índices compactados", para compatibilidad con Linux pre-v5.4.
xattr-name-filter
Habilita un filtro de nombres para atributos extendidos para optimizar las búsquedas negativas. (Linux v6.6+).
ztailpacking
Empaqueta la parte final (pcluster) de los archivos comprimidos en sus metadatos para ahorrar más espacio y E/S de la parte final. (Linux v5.17+)
-L etiqueta-volumen
Establece la etiqueta del volumen para el sistema de archivos en etiqueta-volumen. La longitud máxima de la etiqueta del volumen es de 15 bytes.
-T #
Especifica una marca de tiempo UNIX para la hora de creación de la imagen para compilaciones reproducibles. Si no se especifica --mkfs-time, se comportará como --all-time: estableciendo todos los archivos a la marca de tiempo UNIX especificada en lugar de usar las horas de modificación de los archivos fuente.
-U UUID
Establece el identificador único universal (UUID) del sistema de archivos en UUID. El formato del UUID es una serie de dígitos hexadecimales separados por guiones, así: "c1b9d5a2-f162-11cf-9ece-0020afc76f16". El parámetro UUID también puede ser uno de los siguientes:
clear
borra el UUID del sistema de archivos.
random
genera un nuevo UUID generado aleatoriamente.
--all-root
Hace que todos los archivos sean propiedad de root.
--all-time
(usado junto con -T) establece todos los archivos a la marca de tiempo fija. Este es el comportamiento predeterminado.
--blobdev archivo
Especifica un dispositivo blob adicional para almacenar datos basados en fragmentos.
--chunksize #
Genera archivos basados en fragmentos con fragmentos de #-bytes.
--compress-hints archivo
Aplica una estrategia de compresión por archivo. Cada línea en archivo se define por tokens separados por espacios en la siguiente forma. Opcionalmente, en lugar del algoritmo primario dado, se pueden especificar algoritmos alternativos con índice-algoritmo explícitamente:
<tamaño-pcluster-en-bytes> [índice-algoritmo] <patrón-coincidencia>

Los patrones-coincidencia son expresiones regulares extendidas, que coinciden con rutas absolutas dentro del sistema de archivos de salida, sin una barra inicial (/).

--dsunit=#
Alinea todas las direcciones de bloque de datos a múltiplos de #.
--exclude-path=ruta
Ignora el archivo que coincide con la ruta literal exacta. Puede proporcionar múltiples opciones --exclude-path.
--exclude-regex=expresion-regular
Ignora los archivos que coinciden con la expresión regular extendida dada. Puede proporcionar múltiples opciones --exclude-regex.
--file-contexts=archivo
Lee la configuración/las anulaciones de etiquetas SELinux del archivo en el formato selinux_file(5).
--force-uid=UID
Establece todos los UID de archivo a UID.
--force-gid=GID
Establece todos los GID de archivo a GID.
--fsalignblks=#
Especifica la alineación del tamaño del dispositivo primario (normalmente el tamaño del sistema de archivos) en bloques.
--gid-offset=GIDOFFSET
Suma GIDOFFSET a todos los GID de archivo. Cuando esta opción se usa junto con --force-gid, los GID de archivo finales se establecen a GID + GID-OFFSET.
-V, --version
Imprime el número de versión y sale.
-h, --help
Muestra la cadena de ayuda y sale.
--ignore-mtime
Ignora la hora de modificación del archivo siempre que cause que mkfs.erofs use inodos extendidos en lugar de inodos compactos. Cuando no se usa una marca de tiempo fija, esto puede reducir el tamaño total de los metadatos. Implícito por -E force-inode-compact.
--max-extent-bytes #
Especifica el tamaño máximo de extensión descomprimida en bytes.
--mkfs-time
(usado junto con -T) la marca de tiempo dada solo se aplica a la hora de compilación.
--preserve-mtime
Usa inodos extendidos en lugar de inodos compactos si la hora de modificación del archivo desbordaría los inodos compactos. Este es el comportamiento predeterminado. Anula --ignore-mtime.
--sort=MODO
Orden de clasificación de datos de inodos para tarballs como entrada.

MODO puede ser none o path.

none: No se especifica un orden de datos particular para la imagen de destino para evitar sobrecarga innecesaria; actualmente, surte efecto si se especifica `-E^inline_data` y no se aplica ninguna compresión.

path: El orden de los datos sigue estrictamente el orden de generación del árbol. (predeterminado)

--tar, --tar=MODO
Trata SOURCE como un tarball o un "headerball" similar a un tarball en lugar de un directorio.

MODO puede ser f, i, o headerball.

f: Genera una imagen EROFS completa a partir de un tarball regular. (predeterminado)

i: Genera una imagen EROFS solo de metadatos a partir de un tarball regular. Solo se agregarán metadatos como dentries, inodos y xattrs a la imagen, sin datos de archivo. Los usos para tales imágenes incluyen ser una capa en un sistema de archivos superpuesto con otras capas solo de datos.

headerball: Genera una imagen EROFS solo de metadatos a partir de un flujo idéntico a un tarball excepto que los datos de archivo no están presentes después de cada encabezado de archivo. Puede mejorar el rendimiento especialmente cuando SOURCE no es buscable.

--uid-offset=UIDOFFSET
Suma UIDOFFSET a todos los UID de archivo. Cuando esta opción se usa junto con --force-uid, los UID de archivo finales se establecen a UID + UIDOFFSET.
--ungzip[=archivo]
Filtra los flujos de tarball a través de gzip. Opcionalmente, se pueden volcar flujos sin procesar juntos.
--unxz[=archivo]
Filtra los flujos de tarball a través de xz, lzma o lzip. Opcionalmente, se pueden volcar flujos sin procesar juntos.
--vmdk-desc=ARCHIVO
Genera un archivo descriptor VMDK para fusionar sub-sistemas de archivos, que se puede usar para índice de tar o modo de reconstrucción.
--xattr-prefix=PREFIJO
Especifica un prefijo de espacio de nombres de atributo extendido personalizado para ahorrar espacio, por ejemplo, "trusted.overlay.". Puede proporcionar varias opciones --xattr-prefix (Linux v6.4+).
