NOMBRE

mkosi-sandbox — Ejecuta comandos en un sandbox personalizado

SINOPSIS

mkosi-sandbox [opciones...] comando [argumentos]

DESCRIPCIÓN

mkosi-sandbox ejecuta el comando dado en un sandbox personalizado. El sandbox se configura especificando opciones de línea de comandos que configuran partes individuales del sandbox.

Si no se especifica ningún comando, mkosi-sandbox iniciará bash en el sandbox.

Tenga en cuenta que este sandbox no está diseñado para ser un límite de seguridad. Su propósito es permitir la ejecución de comandos en un entorno aislado para que no se vean afectados por el sistema anfitrión.

OPCIONES

--tmpfs DST
Monta un nuevo tmpfs en DST dentro del sandbox.
--dev DST
Configura un /dev privado en DST dentro del sandbox. Este /dev privado solo contendrá los nodos de dispositivo básicos requeridos para un sandbox funcional (por ejemplo, /dev/null) y ningún dispositivo real.
--proc DST
Monta /proc del host en DST dentro del sandbox.
--dir DST
Crea un directorio y todos sus directorios padre faltantes en DST dentro del sandbox. Todos los directorios se crean con permisos 755, a menos que la ruta termine en /tmp o /var/tmp, en cuyo caso se crean con permisos 1777.
--bind SRC DST
La ruta de origen SRC se monta de forma recursiva (bind mount) en DST dentro del sandbox. El punto de montaje se crea en el sandbox si aún no existe. También se crean los directorios padre faltantes en el sandbox.
--bind-try SRC DST
Similar a --bind, pero no falla si la ruta de origen no existe.
--ro-bind SRC DST
Similar a --bind, pero realiza un montaje recursivo de solo lectura (readonly bind mount).
--ro-bind-try SRC DST
Similar a --bind-try, pero realiza un montaje recursivo de solo lectura (readonly bind mount).
--symlink SRC DST
Crea un enlace simbólico en DST dentro del sandbox que apunta a SRC. Si DST ya existe y es un archivo o enlace simbólico, se crea un enlace simbólico temporal y se monta sobre DST.
--write DATA DST
Escribe la cadena de DATA en DST dentro del sandbox.
--overlay-lowerdir DIR
Añade DIR del host como un nuevo directorio inferior para el siguiente montaje overlayfs.
--overlay-upperdir DIR
Establece el directorio superior para el siguiente montaje overlayfs en DIR del host. Si se establece en tmpfs, el upperdir y el workdir serán subdirectorios de un montaje tmpfs nuevo.
--overlay-workdir DIR
Establece el directorio de trabajo para el siguiente montaje overlayfs en DIR del host.
--overlay DST
Monta un nuevo sistema de archivos overlay en DST dentro del sandbox. Los directorios inferiores, el directorio superior y el directorio de trabajo se especifican usando las opciones --overlay-lowerdir, --overlay-upperdir y --overlay-workdir respectivamente. Después de analizar cada opción --overlay, las otras opciones de overlay se reinician.
--unsetenv NAME
Elimina la variable de entorno NAME en el sandbox.
--setenv NAME VALUE
Establece la variable de entorno NAME a VALUE en el sandbox.
--chdir DIR
Cambia el directorio de trabajo a DIR en el sandbox.
--same-dir
Cambia el directorio de trabajo en el sandbox al directorio de trabajo actual en el que se invoca mkosi-sandbox en el host.
--become-root
Mapea el usuario actual al usuario root dentro del sandbox. Si esta opción no se especifica, el usuario actual se mapea a sí mismo en el sandbox. Independientemente de si esta opción se especifica o no, el usuario actual tendrá un conjunto completo de capacidades ambientales en el sandbox. Esto incluye CAP_SYS_ADMIN, lo que significa que el proceso invocado en el sandbox podrá realizar montajes bind y otras operaciones.

Si mkosi-sandbox se invoca como usuario root, esta opción no hará nada.

--suppress-chown
Especificar esta opción hace que todas las llamadas a chown() o llamadas al sistema similares se conviertan en una operación nula (noop) en el sandbox. Esto es principalmente útil al invocar gestores de paquetes en el sandbox que podrían intentar realizar chown() a archivos de diferentes usuarios o grupos, lo cual fallaría a menos que mkosi-sandbox sea invocado por un usuario privilegiado.
--unshare-net
Especificar esta opción hace que mkosi-sandbox descomparta un espacio de nombres de red si es posible.
--unshare-ipc
Especificar esta opción hace que mkosi-sandbox descomparta un espacio de nombres IPC si es posible.
--exec-fd FD
El FD especificado se cerrará cuando mkosi-sandbox llame a execvp(). Esto es útil para esperar hasta que toda la lógica de configuración haya finalizado antes de continuar la ejecución en el proceso padre que invoca a mkosi-sandbox.
--version
Muestra la versión del paquete.
--help, -h
Muestra información de uso breve.

EJEMPLOS

Inicia bash en el directorio de trabajo actual en su propio espacio de nombres de red como el usuario actual.

mkosi-sandbox --bind / / --same-dir --unshare-net

Ejecuta id como usuario root en un sandbox con solo /usr del host más los enlaces simbólicos necesarios para poder ejecutar comandos.

mkosi-sandbox \
    --ro-bind /usr /usr \
    --symlink usr/bin /bin \
    --symlink usr/bin /bin \
    --symlink usr/lib /lib \
    --symlink usr/lib64 /lib64 \
    --symlink usr/sbin /sbin \
    --dev /dev \
    --proc /proc \
    --tmpfs /tmp \
    --become-root \
    id
