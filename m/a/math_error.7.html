math_error(7) Manual de información miscelánea math_error(7)

NOMBRE

math_error - detección de errores de funciones matemáticas

SINOPSIS

#include <math.h>
#include <errno.h>
#include <fenv.h>

DESCRIPCIÓN

Cuando ocurre un error, la mayoría de las funciones de la biblioteca indican este hecho devolviendo un valor especial (por ejemplo, -1 o NULL). Debido a que típicamente devuelven un número de punto flotante, las funciones matemáticas declaradas en <math.h> indican un error utilizando otros mecanismos. Hay dos mecanismos de reporte de errores: el más antiguo establece errno; el más nuevo utiliza el mecanismo de excepción de punto flotante (el uso de feclearexcept(3) y fetestexcept(3), como se describe a continuación) descrito en fenv(3).

Un programa portable que necesita verificar errores de una función matemática debe establecer errno a cero y hacer la siguiente llamada


feclearexcept(FE_ALL_EXCEPT);

antes de llamar a una función matemática.

Al regresar de la función matemática, si errno es distinto de cero, o la siguiente llamada (ver fenv(3)) devuelve un valor distinto de cero


fetestexcept(FE_INVALID | FE_DIVBYZERO | FE_OVERFLOW |
             FE_UNDERFLOW);

entonces ocurrió un error en la función matemática.

Las condiciones de error que pueden ocurrir para las funciones matemáticas se describen a continuación.

Error de dominio

Un error de dominio ocurre cuando a una función matemática se le proporciona un argumento cuyo valor cae fuera del dominio para el cual está definida la función (por ejemplo, dar un argumento negativo a log(3)). Cuando ocurre un error de dominio, las funciones matemáticas comúnmente devuelven un NaN (aunque algunas funciones devuelven un valor diferente en este caso); errno se establece a EDOM, y se genera una excepción de punto flotante "inválida" (FE_INVALID).

Error de polo

Un error de polo ocurre cuando el resultado matemático de una función es un infinito exacto (por ejemplo, el logaritmo de 0 es infinito negativo). Cuando ocurre un error de polo, la función devuelve el valor (con signo) HUGE_VAL, HUGE_VALF, o HUGE_VALL, dependiendo de si el tipo de resultado de la función es double, float, o long double. El signo del resultado es el que es matemáticamente correcto para la función. errno se establece a ERANGE, y se genera una excepción de punto flotante de "división por cero" (FE_DIVBYZERO).

Error de rango

Un error de rango ocurre cuando la magnitud del resultado de la función significa que no puede representarse en el tipo de resultado de la función. El valor de retorno de la función depende de si el error de rango fue un desbordamiento o un subdesbordamiento.

Un resultado de punto flotante se desborda si el resultado es finito, pero es demasiado grande para representarse en el tipo de resultado. Cuando ocurre un desbordamiento, la función devuelve el valor HUGE_VAL, HUGE_VALF, o HUGE_VALL, dependiendo de si el tipo de resultado de la función es double, float, o long double. errno se establece a ERANGE, y se genera una excepción de punto flotante de "desbordamiento" (FE_OVERFLOW).

Un resultado de punto flotante se subdesborda si el resultado es demasiado pequeño para representarse en el tipo de resultado. Si ocurre un subdesbordamiento, una función matemática típicamente devuelve 0.0 (C99 dice que una función debe devolver "un valor definido por la implementación cuya magnitud no sea mayor que el número positivo normalizado más pequeño en el tipo especificado"). errno puede establecerse a ERANGE, y puede generarse una excepción de punto flotante de "subdesbordamiento" (FE_UNDERFLOW).

Algunas funciones entregan un error de rango si el valor del argumento proporcionado, o el resultado correcto de la función, fuera subnormal. Un valor subnormal es aquel que no es cero, pero con una magnitud tan pequeña que no puede presentarse en forma normalizada (es decir, con un 1 en el bit más significativo del significando). La representación de un número subnormal contendrá uno o más ceros iniciales en el significando.

NOTAS

El identificador math_errhandling especificado por C99 y POSIX.1 no es compatible con glibc. Se supone que este identificador indica cuál de los dos mecanismos de notificación de errores (errno, excepciones recuperables a través de fetestexcept(3)) está en uso. Los estándares requieren que al menos uno esté en uso, pero permiten que ambos estén disponibles. La situación actual (glibc 2.8) en glibc es confusa. La mayoría (pero no todas) las funciones generan excepciones en caso de error. Algunas también establecen errno. Algunas pocas funciones establecen errno, pero no generan una excepción. Unas pocas hacen ninguna de las dos cosas. Consulte las páginas del manual individuales para obtener más detalles.

Para evitar las complejidades de usar errno y fetestexcept(3) para la verificación de errores, a menudo se aconseja que se verifiquen los valores de argumento incorrectos antes de cada llamada. Por ejemplo, el siguiente código asegura que el argumento de log(3) no sea un NaN ni cero (error de polo) o menor que cero (error de dominio):


double x, r;
if (isnan(x) || islessequal(x, 0)) {
    /* Manejar error de NaN / polo / dominio */
}
r = log(x);

La discusión en esta página no se aplica a las funciones matemáticas complejas (es decir, las declaradas por <complex.h>), las cuales en general no se les exige que devuelvan errores según C99 y POSIX.1.

La opción -fno-math-errno de gcc(1) hace que el ejecutable emplee implementaciones de algunas funciones matemáticas que son más rápidas que las implementaciones estándar, pero no establecen errno en caso de error. (La opción -ffast-math de gcc(1) también habilita -fno-math-errno.) Un error aún se puede verificar usando fetestexcept(3).
