MARKDOWN(7) Manual de Información Miscelánea MARKDOWN(7)

NOMBRE

Markdown — La sintaxis de formato de texto Markdown

DESCRIPCIÓN

Filosofía

Markdown está diseñado para ser lo más fácil de leer y escribir posible.

Sin embargo, la legibilidad es lo que más se enfatiza. Un documento formateado en Markdown debería poder publicarse tal cual, como texto plano, sin que parezca marcado con etiquetas o instrucciones de formato. Si bien la sintaxis de Markdown se ha visto influenciada por varios filtros de texto a HTML existentes —incluyendo Setext, atx, Textile, reStructuredText, Grutatext y EtText — la fuente de inspiración más grande para la sintaxis de Markdown es el formato del correo electrónico de texto plano.

Para ello, la sintaxis de Markdown se compone enteramente de caracteres de puntuación, los cuales han sido cuidadosamente elegidos para que se parezcan a lo que significan. Por ejemplo, los asteriscos alrededor de una palabra realmente parecen *énfasis*. Las listas de Markdown se ven como, bueno, listas. Incluso las citas en bloque parecen pasajes de texto citados, suponiendo que alguna vez hayas usado correo electrónico.

HTML en línea

Markdown tiene un solo propósito: servir como formato para escribir para la web.

Markdown no es un reemplazo para HTML, ni siquiera se acerca. Su sintaxis es muy pequeña, correspondiente solo a un subconjunto muy pequeño de etiquetas HTML. La idea no es crear una sintaxis que facilite la inserción de etiquetas HTML. En mi opinión, las etiquetas HTML ya son fáciles de insertar. La idea de Markdown es facilitar la lectura, escritura y edición de prosa. HTML es un formato de publicación; Markdown es un formato de escritura. Por lo tanto, la sintaxis de formato de Markdown solo aborda problemas que se pueden transmitir en texto plano.

Para cualquier marcado que no esté cubierto por la sintaxis de Markdown, simplemente usa HTML. No hay necesidad de prefijarlo o delimitarlo para indicar que estás cambiando de Markdown a HTML; simplemente usa las etiquetas.

Las únicas restricciones son que los elementos HTML de nivel de bloque —por ejemplo, <div>, <table>, <pre>, <p>, etc. — deben estar separados del contenido circundante por líneas en blanco, y las etiquetas de inicio y fin del bloque no deben estar indentadas con tabulaciones o espacios. Markdown es lo suficientemente inteligente como para no agregar etiquetas <p> adicionales (no deseadas) alrededor de las etiquetas HTML de nivel de bloque.

Por ejemplo, para agregar una tabla HTML a un artículo de Markdown:

Este es un párrafo normal.

<table>
    <tr>
        <td>Foo</td>
    </tr>
</table>

Este es otro párrafo normal.

Ten en cuenta que la sintaxis de formato de Markdown no se procesa dentro de las etiquetas HTML de nivel de bloque. Por ejemplo, no puedes usar *énfasis* al estilo Markdown dentro de un bloque HTML.

Las etiquetas HTML de nivel de span —por ejemplo, <span>, <cite> o <del> — se pueden usar en cualquier lugar dentro de un párrafo, elemento de lista o encabezado de Markdown. Si lo deseas, incluso puedes usar etiquetas HTML en lugar de formato Markdown; por ejemplo, si prefieres usar etiquetas HTML <a> o <img> en lugar de la sintaxis de enlaces o imágenes de Markdown, adelante.

A diferencia de las etiquetas HTML de nivel de bloque, la sintaxis de Markdown *sí* se procesa dentro de las etiquetas de nivel de span.

Escape Automático para Caracteres Especiales

En HTML, hay dos caracteres que requieren un tratamiento especial: `<` y `&`. Los corchetes angulares de apertura se usan para iniciar etiquetas; los ampersands se usan para denotar entidades HTML. Si deseas usarlos como caracteres literales, debes escaparlos como entidades, por ejemplo, `&lt;` y `&amp;`.

Los ampersands en particular son un problema para los escritores web. Si deseas escribir sobre 'AT&T', necesitas escribir '`AT&amp;T`'. Incluso necesitas escapar los ampersands dentro de las URL. Por lo tanto, si deseas enlazar a:

http://images.google.com/images?num=30&q=larry+bird

necesitas codificar la URL como:

http://images.google.com/images?num=30&amp;q=larry+bird

en el atributo `href` de tu etiqueta de anclaje. No hace falta decir que esto es fácil de olvidar y es probablemente la fuente más común de errores de validación HTML en sitios web bien marcados.

Markdown te permite usar estos caracteres de forma natural, encargándose de todo el escape necesario por ti. Si usas un ampersand como parte de una entidad HTML, permanece sin cambios; de lo contrario, se traducirá a `&amp;`.

Así que, si deseas incluir un símbolo de copyright en tu artículo, puedes escribir:

&copy;

y Markdown lo dejará en paz. Pero si escribes:

AT&T

Markdown lo traducirá a:

AT&amp;T

Del mismo modo, dado que Markdown admite HTML en línea, si usas corchetes angulares como delimitadores para etiquetas HTML, Markdown los tratará como tales. Pero si escribes:

4 < 5

Markdown lo traducirá a:

4 &lt; 5

Sin embargo, dentro de las expansiones de código y bloques de código de Markdown, los corchetes angulares y los ampersands *siempre* se codifican automáticamente. Esto facilita el uso de Markdown para escribir sobre código HTML. (A diferencia del HTML sin procesar, que es un formato terrible para escribir sobre sintaxis HTML, ya que cada `<` y `&` en tu código de ejemplo debe escaparse).

Elementos de Bloque

Párrafos y Saltos de Línea

Un párrafo es simplemente una o más líneas consecutivas de texto, separadas por una o más líneas en blanco. (Una línea en blanco es cualquier línea que parezca una línea en blanco: una línea que contenga solo espacios o tabulaciones se considera en blanco). Los párrafos normales no deben estar indentados con espacios o tabulaciones.

La implicación de la regla "una o más líneas consecutivas de texto" es que Markdown admite párrafos de texto "con saltos de línea duros". Esto difiere significativamente de la mayoría de los otros formateadores de texto a HTML (incluida la opción "Convertir saltos de línea" de Movable Type), que traducen cada carácter de salto de línea en un párrafo a una etiqueta `
`.

Cuando *quieras* insertar una etiqueta de salto `
` usando Markdown, termina una línea con dos o más espacios, luego presiona enter.

Sí, esto requiere un poco más de esfuerzo para crear un `
`, pero una regla simplista de "cada salto de línea es un `
`" no funcionaría para Markdown. Las citas en bloque
al estilo de correo electrónico de Markdown y los elementos de lista multiparágrafo funcionan mejor —y se ven mejor— cuando los formateas con saltos de línea duros.

Encabezados

Markdown admite dos estilos de encabezados: Setext y atx.

Los encabezados de estilo Setext se "subrayan" usando signos de igual (para encabezados de primer nivel) y guiones (para encabezados de segundo nivel). Por ejemplo:

Este es un H1
=============

Este es un H2
-------------

Cualquier número de `=` o `-` subrayados funcionará.

Los encabezados de estilo Atx usan de 1 a 6 caracteres de almohadilla al principio de la línea, correspondientes a los niveles de encabezado 1-6. Por ejemplo:

# Este es un H1

## Este es un H2

###### Este es un H6

Opcionalmente, puedes

y encabezados de estilo "close" atx. Esto es puramente estético: puedes usarlo si crees que se ve mejor. Los hashes de cierre ni siquiera necesitan coincidir con el número de hashes utilizados para abrir el encabezado. (El número de hashes de apertura determina el nivel del encabezado). :

# Esto es un H1 #

## Esto es un H2 ##

### Esto es un H3 ######

Citas en bloque

Markdown utiliza caracteres de estilo de correo electrónico `>` para citar en bloque. Si estás familiarizado con citar pasajes de texto en un mensaje de correo electrónico, entonces sabes cómo crear una cita en bloque en Markdown. Se ve mejor si ajustas el texto y pones un `>` antes de cada línea:

> Esta es una cita en bloque con dos párrafos. Lorem ipsum
> dolor sit amet, consectetuer adipiscing elit. Aliquam
> hendrerit mi posuere lectus. Vestibulum enim wisi,
> viverra nec, fringilla in, laoreet vitae, risus.
>
> Donec sit amet nisl. Aliquam semper ipsum sit amet
> velit. Suspendisse id sem consectetuer libero luctus
> adipiscing.

Markdown te permite ser perezoso y solo poner el `>` antes de la primera línea de un párrafo con ajuste de línea:

> Esta es una cita en bloque con dos párrafos. Lorem ipsum
dolor sit amet, consectetuer adipiscing elit. Aliquam
hendrerit mi posuere lectus. Vestibulum enim wisi,
viverra nec, fringilla in, laoreet vitae, risus.

> Donec sit amet nisl. Aliquam semper ipsum sit amet
 velit. Suspendisse id sem consectetuer libero luctus
  adipiscing.

Las citas en bloque pueden anidarse (es decir, una cita en bloque dentro de otra cita en bloque) añadiendo niveles adicionales de `>`:

> Este es el primer nivel de cita.
>
> > Esta es una cita en bloque anidada.
>
> De vuelta al primer nivel.

Las citas en bloque pueden contener otros elementos de Markdown, incluyendo encabezados, listas y bloques de código:

> ## Este es un encabezado.
>
> 1.   Este es el primer elemento de la lista.
> 2.   Este es el segundo elemento de la lista.
>
> Aquí hay un ejemplo de código:
>
>     return shell_exec("echo $input | $markdown_script");

Cualquier editor de texto decente debería facilitar la cita al estilo del correo electrónico. Por ejemplo, con BBEdit, puedes hacer una selección y elegir Aumentar nivel de cita del menú Texto.

Listas

Markdown soporta listas ordenadas (numeradas) y no ordenadas (con viñetas).

Las listas no ordenadas usan asteriscos, signos más e guiones — intercambiables — como marcadores de lista:

*   Rojo
*   Verde
*   Azul

es equivalente a:

+   Rojo
+   Verde
+   Azul

y:

-   Rojo
-   Verde
-   Azul

Las listas ordenadas usan números seguidos de puntos:

1.  Bird
2.  McHale
3.  Parish

Es importante notar que los números reales que uses para marcar la lista no tienen efecto en la salida HTML que Markdown produce. El HTML que Markdown produce a partir de la lista anterior es:

<ol>
<li>Bird</li>
<li>McHale</li>
<li>Parish</li>
</ol>

Si en su lugar escribieras la lista en Markdown de esta manera:

1.  Bird
1.  McHale
1.  Parish

o incluso:

3. Bird
1. McHale
8. Parish

obtendrías exactamente la misma salida HTML. El punto es que, si quieres, puedes usar números ordinales en tus listas ordenadas de Markdown, para que los números en tu fuente coincidan con los números en tu HTML publicado. Pero si quieres ser perezoso, no tienes que hacerlo.

Sin embargo, si usas numeración de lista perezosa, aún debes comenzar la lista con el número 1. En algún momento en el futuro, Markdown puede soportar el inicio de listas ordenadas en un número arbitrario.

Los marcadores de lista normalmente comienzan en el margen izquierdo, pero pueden ser indentados hasta tres espacios. Los marcadores de lista deben ir seguidos de uno o más espacios o un tabulador.

Para que las listas se vean bien, puedes envolver los elementos con indentaciones colgantes:

    *   Lorem ipsum dolor sit amet, consectetuer adipiscing
	elit. Aliquam hendrerit mi posuere lectus. Vestibulum
	enim wisi, viverra nec, fringilla in, laoreet vitae,
	risus.
    *   Donec sit amet nisl. Aliquam semper ipsum sit amet
velit. Suspendisse id sem consectetuer libero luctus
	adipiscing.

Pero si quieres ser perezoso, no tienes que hacerlo:

*   Lorem ipsum dolor sit amet, consectetuer adipiscing
elit. Aliquam hendrerit mi posuere lectus. Vestibulum
enim wisi, viverra nec, fringilla in, laoreet vitae,
risus.
*   Donec sit amet nisl. Aliquam semper ipsum sit amet
velit. Suspendisse id sem consectetuer libero luctus
adipiscing.

Si los elementos de la lista están separados por líneas en blanco, Markdown envolverá los elementos en etiquetas `<p>` en la salida HTML. Por ejemplo, esta entrada:

*   Bird
*   Magic

se convertirá en:

<ul>
<li>Bird</li>
<li>Magic</li>
</ul>

Pero esto:

*   Bird

*   Magic

se convertirá en:

<ul>
<li><p>Bird</p></li>
<li><p>Magic</p></li>
</ul>

Los elementos de la lista pueden constar de varios párrafos. Cada párrafo subsiguiente en un elemento de lista debe estar indentado por 4 espacios o un tabulador:

    1.  Este es un elemento de lista con dos párrafos. Lorem ipsum
	dolor sit amet, consectetuer adipiscing elit. Aliquam
	hendrerit mi posuere lectus.

        Vestibulum enim wisi, viverra nec, fringilla in,
	laoreet vitae, risus. Donec sit amet nisl. Aliquam
	semper ipsum sit amet velit.

    2.  Suspendisse id sem consectetuer libero luctus
	adipiscing.

Se ve bien si indentas cada línea de los párrafos subsiguientes, pero aquí de nuevo, Markdown te permitirá ser perezoso:

    *   Este es un elemento de lista con dos párrafos.

        Este es el segundo párrafo del elemento de la lista.
	Solo se requiere indentar la primera línea. Lorem
	ipsum dolor sit amet, consectetuer adipiscing elit.

    *   Otro elemento en la misma lista.

Para poner una cita en bloque dentro de un elemento de lista, los delimitadores `>` de la cita en bloque deben estar indentados:

*   Un elemento de lista con una cita en bloque:

    > Esta es una cita en bloque
    > dentro de un elemento de lista.

Para poner un bloque de código dentro de un elemento de lista, el bloque de código debe estar indentado *dos veces* — 8 espacios o dos tabuladores:

*   Un elemento de lista con un bloque de código:

        <code goes here>

Vale la pena señalar que es posible activar una lista ordenada por accidente, escribiendo algo como esto:

1986. Qué gran temporada.

En otras palabras, una secuencia de *número-punto-espacio* al principio de una línea. Para evitar esto, puedes escapar el punto con una barra invertida:

1986\. Qué gran temporada.

Bloques de código

Los bloques de código preformateados se utilizan para escribir sobre programación o código fuente de marcado. En lugar de formar párrafos normales, las líneas de un bloque de código se interpretan literalmente. Markdown envuelve un bloque de código tanto en etiquetas `<pre>` como `<code>`.

Para producir un bloque de código en Markdown, simplemente indenta cada línea del bloque con al menos 4 espacios o 1 tabulador. Por ejemplo, dada esta entrada:

Este es un párrafo normal:

    Este es un bloque de código.

Markdown generará:

<p>Este es un párrafo normal:</p>

<pre><code>Este es un bloque de código.
</code></pre>

Se elimina un nivel de indentación — 4 espacios o 1 tabulador — de cada línea del bloque de código. Por ejemplo, esto:

Aquí hay un ejemplo de AppleScript:

    tell application "Foo"
        beep
    end tell

se convertirá en:

<p>Aquí hay un ejemplo de AppleScript:</p>

<pre><code>tell application "Foo"
    beep
end tell
</code></pre>

Un bloque de código continúa hasta que llega a una línea que no está indentada (o el final del artículo).

Dentro de un bloque de código, los ampersands (`&`) y los corchetes angulares (`<` y `>`) se convierten automáticamente en entidades HTML. Esto hace que sea muy fácil incluir código fuente HTML de ejemplo usando Markdown — simplemente pégalo e indéntalo, y Markdown se encargará de codificar los ampersands y corchetes angulares. Por ejemplo, esto:

<div class="footer">
    &copy; 2004 Foo Corporation
</div>

se convertirá en:

<pre><code>&lt;div class="footer"&gt;
    &amp;copy; 2004 Foo Corporation
&lt;/div&gt;
</code></pre>

La sintaxis normal de Markdown no se procesa dentro de los bloques de código. Por ejemplo, los asteriscos son solo asteriscos literales dentro de un bloque de código. Esto significa que también es fácil usar Markdown para escribir sobre la propia sintaxis de Markdown.

Reglas horizontales

Puedes producir una etiqueta de regla horizontal (`<hr />`) colocando tres o más guiones, asteriscos o guiones bajos en una línea por sí mismos. Si lo deseas, puedes usar espacios entre los guiones o asteriscos. Cada una de las siguientes líneas producirá una regla horizontal:

* * *

***

*****

- - -

---------------------------------------

Enlaces

Markdown permite dos estilos de enlaces: inline y de referencia.

Para crear un enlace inline, usa la sintaxis de enlaces de Markdown:

[Texto del enlace](URL "Título opcional")

Por ejemplo:

This is [an example](http://example.com/ "Title") inline link.

[This link](http://example.net/) has no title attribute.

Producirá:

<p>This is <a href="http://example.com/" title="Title">
an example</a> inline link.</p>

<p><a href="http://example.net/">This link</a> has no
title attribute.</p>

Si te refieres a un recurso local en el mismo servidor, puedes usar rutas relativas:

See my [About](/about/) page for details.

Los enlaces de estilo de referencia utilizan un segundo conjunto de corchetes, dentro de los cuales colocas una etiqueta de tu elección para identificar el enlace:

This is [an example][id] reference-style link.

Opcionalmente, puedes usar un espacio para separar los conjuntos de corchetes:

This is [an example] [id] reference-style link.

Luego, en cualquier lugar del documento, defines la etiqueta de tu enlace así, en una línea separada:

[id]: http://example.com/  "Optional Title Here"

Es decir:

  • Corchetes que contienen el identificador del enlace (opcionalmente indentado desde el margen izquierdo usando hasta tres espacios);
  • seguido de dos puntos;
  • seguido de uno o más espacios (o tabulaciones);
  • seguido de la URL del enlace;
  • opcionalmente seguido de un atributo de título para el enlace, encerrado entre comillas dobles o simples, o encerrado entre paréntesis.

Las siguientes tres definiciones de enlace son equivalentes:

[foo]: http://example.com/  "Optional Title Here"
[foo]: http://example.com/  'Optional Title Here'
[foo]: http://example.com/  (Optional Title Here)

Nota: Existe un error conocido en Markdown.pl 1.0.1 que impide que las comillas simples se utilicen para delimitar los títulos de los enlaces.

La URL del enlace puede ir, opcionalmente, rodeada de corchetes angulares:

[id]: <http://example.com/>  "Optional Title Here"

Puedes colocar el atributo de título en la siguiente línea y usar espacios o tabulaciones adicionales para el relleno, lo que tiende a verse mejor con URLs más largas:

[id]: http://example.com/longish/path/to/resource/here
    "Optional Title Here"

Las definiciones de enlace solo se utilizan para crear enlaces durante el procesamiento de Markdown y se eliminan de tu documento en la salida HTML.

Los nombres de definición de enlace pueden constar de letras, números, espacios y signos de puntuación, pero no distinguen entre mayúsculas y minúsculas. Por ejemplo, estos dos enlaces:

[link text][a]
[link text][A]

son equivalentes.

El atajo de nombre de enlace implícito te permite omitir el nombre del enlace, en cuyo caso el texto del enlace se utiliza como nombre. Simplemente usa un conjunto vacío de corchetes; por ejemplo, para enlazar la palabra "Google" con el sitio web google.com, simplemente puedes escribir:

[Google][]

Y luego definir el enlace:

[Google]: http://google.com/

Dado que los nombres de enlace pueden contener espacios, este atajo incluso funciona para varias palabras en el texto del enlace:

Visit [Daring Fireball][] for more information.

Y luego definir el enlace:

[Daring Fireball]: http://daringfireball.net/

Las definiciones de enlace se pueden colocar en cualquier lugar de tu documento Markdown. Tiendo a colocarlas inmediatamente después de cada párrafo en el que se utilizan, pero si lo deseas, puedes colocarlas todas al final de tu documento, de forma similar a las notas al pie.

Aquí tienes un ejemplo de enlaces de referencia en acción:

I get 10 times more traffic from [Google] [1] than from
[Yahoo] [2] or [MSN] [3].

  [1]: http://google.com/        "Google"
  [2]: http://search.yahoo.com/  "Yahoo Search"
  [3]: http://search.msn.com/    "MSN Search"

Usando el atajo de nombre de enlace implícito, podrías escribir en su lugar:

I get 10 times more traffic from [Google][] than from
[Yahoo][] or [MSN][].

  [google]: http://google.com/        "Google"
  [yahoo]:  http://search.yahoo.com/  "Yahoo Search"
  [msn]:    http://search.msn.com/    "MSN Search"

Ambos ejemplos anteriores producirán la siguiente salida HTML:

<p>I get 10 times more traffic from <a href="http://google.com/"
title="Google">Google</a> than from
<a href="http://search.yahoo.com/" title="Yahoo Search">Yahoo</a>
or
<a href="http://search.msn.com/" title="MSN Search">MSN</a>.</p>

Para comparar, aquí está el mismo párrafo escrito usando el estilo de enlace en línea de Markdown:

I get 10 times more traffic from
[Google](http://google.com/ "Google") than from
[Yahoo](http://search.yahoo.com/ "Yahoo Search") or
[MSN](http://search.msn.com/ "MSN Search").

El propósito de los enlaces de estilo de referencia no es que sean más fáciles de escribir. El propósito es que con los enlaces de estilo de referencia, la fuente de tu documento sea mucho más legible. Compara los ejemplos anteriores: usando enlaces de estilo de referencia, el párrafo en sí tiene solo 81 caracteres; con enlaces de estilo en línea, tiene 176 caracteres; y como HTML plano, tiene 234 caracteres. En el HTML plano, hay más marcas que texto.

Con los enlaces de estilo de referencia de Markdown, un documento fuente se parece mucho más al resultado final, tal como se muestra en un navegador. Al permitirte mover los metadatos relacionados con las marcas fuera del párrafo, puedes agregar enlaces sin interrumpir el flujo narrativo de tu prosa.

Énfasis

Markdown trata los asteriscos (`*`) y los guiones bajos (`_`) como indicadores de énfasis. El texto rodeado por un `*` o `_` se envolverá con una etiqueta HTML `<em>`; dobles `*` o `_` se envolverán con una etiqueta HTML `<strong>`. Por ejemplo, esta entrada:

*single asterisks*

_single underscores_

**double asterisks**

__double underscores__

producirá:

<em>single asterisks</em>

<em>single underscores</em>

<strong>double asterisks</strong>

<strong>double underscores</strong>

Puedes usar el estilo que prefieras; la única restricción es que el mismo carácter debe usarse para abrir y cerrar un intervalo de énfasis.

El énfasis se puede usar en medio de una palabra:

un*fucking*believable

Pero si rodeas un `*` o `_` con espacios, se tratará como un asterisco o guion bajo literal.

Para producir un asterisco o guion bajo literal en una posición donde de otro modo se usaría como delimitador de énfasis, puedes escaparlo con una barra invertida:

\*this text is surrounded by literal asterisks\*

Código

Para indicar un tramo de código, rodéalo con comillas invertidas (`` ` ``). A diferencia de un bloque de código preformateado, un tramo de código indica código dentro de un párrafo normal. Por ejemplo:

Use the `printf()` function.

producirá:

<p>Use the <code>printf()</code> function.</p>

Para incluir un carácter de comilla invertida literal dentro de un tramo de código, puedes usar múltiples comillas invertidas como delimitadores de apertura y cierre:

``There is a literal backtick (`) here.``

lo que producirá esto:

<p><code>There is a literal backtick (`) here.</code></p>

Los delimitadores de comillas invertidas que rodean un tramo de código pueden incluir espacios: uno después de la apertura, uno antes del cierre. Esto te permite colocar caracteres de comillas invertidas literales al principio o al final de un tramo de código:

A single backtick in a code span: `` ` ``

A backtick-delimited string in a code span: `` `foo` ``

producirá:

<p>A single backtick in a code span: <code>`</code></p>

<p>A backtick-delimited string in a code span: <code>`foo`</code></p>

Con un tramo de código, los ampersands y los corchetes angulares se codifican automáticamente como entidades HTML, lo que facilita la inclusión de etiquetas HTML de ejemplo. Markdown convertirá esto:

Please don't use any `<blink>` tags.

en:

<p>Please don't use any <code>&lt;blink&gt;</code> tags.</p>

Puedes escribir esto:

`&#8212;` is the decimal-encoded equivalent of `&mdash;`.

para producir:

<p><code>&amp;#8212;</code> is the decimal-encoded
equivalent of <code>&amp;mdash;</code>.</p>

Imágenes

Hay que admitir que es bastante difícil idear una sintaxis "natural" para colocar imágenes en un formato de texto plano.

Markdown utiliza una sintaxis de imágenes que pretende parecerse a la sintaxis de los enlaces, permitiendo dos estilos: inline y de referencia.

La sintaxis de imágenes en línea se ve así:

![Alt text](/path/to/img.jpg)

![Alt text](/path/to/img.jpg =Optional size "Optional title")

Es decir:

  • Un signo de exclamación: `!`;
  • seguido de un conjunto de corchetes, que contiene el texto del atributo `alt` para la imagen;
  • seguido de un conjunto de paréntesis, que contiene la URL o ruta a la imagen, un atributo `size` opcional (en formato ancho x alto) precedido por un `=`, y un atributo `title` opcional encerrado entre comillas dobles o simples, o entre paréntesis.

Por ejemplo, esto:

![A cheesy grin](/assets/images/grin.jpg "Grinning Cat")

producirá:

<p><img src="/assets/images/grin.jpg" alt="A cheesy grin" title="Grinning Cat" /></p>

La sintaxis de imágenes de referencia es idéntica a la de los enlaces de referencia, con la salvedad de un signo de exclamación inicial:

![Alt text][id]

![Alt text][id =Optional size "Optional title"]

La definición de la imagen va en otra parte del documento, de forma similar a las definiciones de enlaces de referencia:

[id]: url/to/image.jpg

[id]: url/to/image.jpg =Optional size
[id]: url/to/image.jpg "Optional Title Here"
[id]: url/to/image.jpg =Optional size "Optional Title Here"

Y las tres definiciones de imagen anteriores son equivalentes a estas tres definiciones de enlace:

[foo]: /path/to/img.jpg        "Optional Title Here"
[foo]: /path/to/img.jpg        'Optional Title Here'
[foo]: /path/to/img.jpg        (Optional Title Here)

Al igual que con las definiciones de enlaces, las definiciones de imágenes pueden colocarse en cualquier parte del documento.

Aquí tienes un ejemplo de imágenes de referencia en acción:

I solemnly swear that I'm embarking
on no         [adverb]         [what].

      [adverb]: http://www.google.com/dictionary/bad/adverb.html
      [what]:   http://www.google.com/dictionary/bad/what.html

Esto producirá:

<p>I solemnly swear that I'm embarking
on no <a href="http://www.google.com/dictionary/bad/adverb.html">adverb</a>
<a href="http://www.google.com/dictionary/bad/what.html">what</a>.</p>

Usando la sintaxis de imagen de referencia, el ejemplo anterior se vería así:

I solemnly swear that I'm embarking
on no         ![adverb][adverb]         ![what][what].

      [adverb]: http://www.google.com/dictionary/bad/adverb.html
      [what]:   http://www.google.com/dictionary/bad/what.html

Tenga en cuenta que el texto alternativo de la imagen se extrae del texto del enlace (por ejemplo, `adverb` en el caso de `![adverb][adverb]`). El atributo `title` se puede especificar en la definición de la imagen, como en:

[foo]: /path/to/img.jpg "Optional Title Here"

Si no se especifica `title`, el atributo `title` HTML de la imagen no se establecerá.

Markdown también soporta la especificación del tamaño de la imagen directamente en la sintaxis de enlace o definición. Para hacer esto, agregue un signo de igual (`=`) seguido de la dimensión deseada después de la URL de la imagen. Puede especificar solo el ancho, o ambos ancho y alto en el formato `ancho x alto`.

![Paul Smith](http://example.com/image.jpg =500x300 "Image Title")
![Paul Smith](http://example.com/image.jpg =500 "Image Title")
![Paul Smith][id]

[id]: http://example.com/image.jpg =500x300 "Image Title"

Esto produce:

<img src="http://example.com/image.jpg" width="500" height="300" alt="Paul Smith" title="Image Title" />
<img src="http://example.com/image.jpg" width="500" alt="Paul Smith" title="Image Title" />

Si se especifica solo el ancho, se omite la altura (y viceversa). Si se especifica un valor de tamaño inválido, se ignora. El tamaño se aplica solo a la etiqueta `img` HTML.

NAME

markdown - an API for processing Markdown, a text-to-HTML conversion tool

DESCRIPTION

This document describes the syntax for writing documents in Markdown. Markdown is a text-to-HTML conversion tool for web writers. Markdown allows you to write using an easy-to-read, easy-to-write plain text format, then convert it to structurally valid XHTML (or HTML).

This document describes the syntax for the Markdown format. It is intended to be usable either as a README file, or as a document that you can convert yourself from Markdown to HTML.

The main rule of any markup formatting is that it should be formatted in the simplest way possible.

This document is encoded in UTF-8.

Syntax Overview

The point is that you should be able to read Markdown-formatted text on the Web as-is. It should look like simple plain text, like it's meant to be. The intention is that Markdown syntax is a subset of `text/html` syntax. Specifically, any Markdown-marked-up paragraph (block level) text should be treated as a phrase element, and any visually distinct block of text between two newlines should be a block-level element. The syntax for inline and block-level markup are designed to convey their meaning with as little ambiguity as possible.

Block Elements

Paragraphs

A paragraph is simply one or more consecutive lines of text, separated by one or more blank lines. (A blank line is a line that your editor thinks is empty; this merely means that it contains no visible whitespace characters.)

Headers

Markdown supports two styles of headers, by mimicking GFM and Setext-style headers. Setext-style headers are underlined, while GFM-style headers use a hash mark (#) for each level.

This is an H1
============

This is an H2
------------

# This is an H1
## This is an H2
### This is an H3

Blockquotes

Markdown treats email-style “greater-than” signs preceding lines as blockquote delimiters. This makes it easy to quote other items. You can nest blockquotes.

> This is a blockquote.
> It can span multiple lines.
>> This is a nested blockquote.
> Back to the first level.

Lists

Markdown supports ordered and unordered lists.

Unordered lists use asterisks, plus signs, or hyphens as list markers.

*   Red
*   Green
*   Blue

-   Milk
-   Eggs
-   Bread

+   Apples
+   Oranges
+   Bananas

Ordered lists use numbers followed by periods.

1.  First item
2.  Second item
3.  Third item

You can nest lists, but to do so, the nesting level must be indented by at least four spaces or a tab:

*   First item
    *   Nested item 1
    *   Nested item 2
        *   Nested item 1.1
*   Second item

Code Blocks

Markdown allows you to use preformatted code blocks in a fairly natural way. To do this, simply indent every line of the block, by 4 spaces or 1 tab.

Here is a code block:

    <code>
    This is code.
    </code>

As with the rest of Markdown, the idea is to make it easy to write. It requires nothing more than you'd typically do to format code in an email.

Horizontal Rules

You can draw horizontal rules (“thematic breaks”) by placing three or more hyphens, asterisks, or underscores on a line by themselves.

---

***

___

Span Elements

Emphasis

Markdown marks up email-style emphasis and strong emphasis using `*` or `_`.

*This text will be italic*
_This will also be italic_

*This text will be bold*
_This will also be bold_

***This text will be bold italic***
___This will also be bold italic___

Code

Inline Markdown code text is enclosed in backticks.

Use the `printf()` function.

Links

Markdown has two styles of links: inline, and reference-style.

The syntax for inline links is this:

[This is an inline link](http://www.example.com "Optional title")

And for reference-style links:

[This is a reference-style link][some-id]

[some-id]: http://www.example.com "Optional title"

The]`id` can be any case-insensitive textual identifier, including numbers, punctuation, and spaces.

Reference-style links are useful for places where you'll use a URL multiple times, especially for long URLs.

Images are the same syntax as links, but with a preceding exclamation mark:

Inline images: ![Alt text](/url/to/image.png "Optional title")

Reference-style images:
![Alt text][id]

Reference-style image syntax looks like this:

![Alt text][id]

Where "id" is the name of a defined image reference. Image references are defined using syntax identical to link references:

[id]: url/to/image  =Optional size "Optional title attribute"

Miscellaneous

Automatic Links

Markdown supports a shortcut style for creating "automatic" links for URLs and email addresses: simply surround the URL or email address with angle brackets. What this means is that if you want to
show the actual text of a URL or email address, and also have it be
a clickable link, you can do this:

<http://example.com/>

Markdown will turn this into:

<a href="http://example.com/">http://example.com/</a>

Automatic links for email addresses work similarly, except that Markdown will also perform a bit of randomized decimal and hex entity-encoding to help obscure your address from address-harvesting spambots. For example, Markdown will turn this:

<address@example.com>

into something like this:

<a href="&#x6D;&#x61;&#x6C;&#x74;&#x6F;:&#x61;&#x64;&#x64;&#x72;&#x65;
&#115;&#115;&#64;&#101;&#120;&#x61;&#109;&#x70;&#x6C;e&#x2E;&#99;&#111;
&#109;">&#x61;&#x64;&#x64;&#x72;&#x65;&#115;&#115;&#64;&#101;&#120;&#x61;
&#109;&#x70;&#x6C;e&#x2E;&#99;&#111;&#109;</a>

which will render in a browser as a clickable link to "address@example.com".

(This sort of entity-encoding trick will indeed fool many, if not most, address-harvesting bots, but it definitely won't fool all of them. It's better than nothing, but an address published in this way will probably eventually start receiving spam.)

Backslash Escapes

Markdown allows you to use backslash escapes to generate literal characters which would otherwise have special meaning in Markdown's formatting syntax. For example, if you wanted to surround a word with literal asterisks (instead of an HTML `<em>` tag), you add backslashes before the asterisks, like this:

\*literal asterisks\*
