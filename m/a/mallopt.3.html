NOMBRE

mallopt - establecer parámetros de asignación de memoria

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <malloc.h>
int mallopt(int param, int value);

DESCRIPCIÓN

La función mallopt() ajusta parámetros que controlan el comportamiento de las funciones de asignación de memoria (ver malloc(3)). El argumento param especifica el parámetro a modificar, y value especifica el nuevo valor para dicho parámetro.

Los siguientes valores pueden especificarse para param:

M_ARENA_MAX
Si este parámetro tiene un valor distinto de cero, define un límite estricto en el número máximo de arenas que se pueden crear. Una arena representa un pool de memoria que puede ser utilizado por llamadas a malloc(3) (y similares) para atender solicitudes de asignación. Las arenas son seguras para hilos y, por lo tanto, pueden tener múltiples solicitudes de memoria concurrentes. La contrapartida es entre el número de hilos y el número de arenas. Cuantas más arenas tenga, menor será la contención por hilo, pero mayor será el uso de memoria.
El valor predeterminado de este parámetro es 0, lo que significa que el límite en el número de arenas se determina según la configuración de M_ARENA_TEST.
Este parámetro ha estado disponible desde glibc 2.10 a través de --enable-experimental-malloc, y desde glibc 2.15 por defecto. En algunas versiones del asignador no había límite en el número de arenas creadas (por ejemplo, CentOS 5, RHEL 5).
Al emplear versiones más recientes de glibc, las aplicaciones pueden en algunos casos exhibir alta contención al acceder a las arenas. En estos casos, puede ser beneficioso aumentar M_ARENA_MAX para que coincida con el número de hilos. Esto es similar en comportamiento a las estrategias tomadas por tcmalloc y jemalloc (por ejemplo, pools de asignación por hilo).
M_ARENA_TEST
Este parámetro especifica un valor, en número de arenas creadas, en cuyo punto se examinará la configuración del sistema para determinar un límite estricto en el número de arenas creadas. (Ver M_ARENA_MAX para la definición de una arena).
El cálculo del límite estricto de arenas depende de la implementación y generalmente se calcula como un múltiplo del número de CPUs disponibles. Una vez que se calcula el límite estricto, el resultado es final y restringe el número total de arenas.
El valor predeterminado para el parámetro M_ARENA_TEST es 2 en sistemas donde sizeof(long) es 4; de lo contrario, el valor predeterminado es 8.
Este parámetro ha estado disponible desde glibc 2.10 a través de --enable-experimental-malloc, y desde glibc 2.15 por defecto.
El valor de M_ARENA_TEST no se utiliza cuando M_ARENA_MAX tiene un valor distinto de cero.
M_CHECK_ACTION
Establecer este parámetro controla cómo responde glibc cuando se detectan varios tipos de errores de programación (por ejemplo, liberar el mismo puntero dos veces). Los 3 bits menos significativos (2, 1 y 0) del valor asignado a este parámetro determinan el comportamiento de glibc, como sigue:
Bit 0
Si este bit está establecido, se imprime un mensaje de una sola línea en stderr que proporciona detalles sobre el error. El mensaje comienza con la cadena "*** glibc detected ***", seguido del nombre del programa, el nombre de la función de asignación de memoria en la que se detectó el error, una breve descripción del error y la dirección de memoria donde se detectó el error.
Bit 1
Si este bit está establecido, entonces, después de imprimir cualquier mensaje de error especificado por el bit 0, el programa termina llamando a abort(3). Desde glibc 2.4, si el bit 0 también está establecido, entonces, entre la impresión del mensaje de error y la interrupción, el programa también imprime un rastreo de pila al estilo de backtrace(3), e imprime el mapeo de memoria del proceso al estilo de /proc/pid/maps (ver proc(5)).
Bit 2 (desde glibc 2.4)
Este bit solo tiene efecto si el bit 0 también está establecido. Si este bit está establecido, entonces el mensaje de una sola línea que describe el error se simplifica para contener solo el nombre de la función donde se detectó el error y la breve descripción del error.
Los bits restantes en value se ignoran.
Combinando los detalles anteriores, los siguientes valores numéricos son significativos para M_CHECK_ACTION:
0
Ignorar las condiciones de error; continuar la ejecución (con resultados indefinidos).
1
Imprimir un mensaje de error detallado y continuar la ejecución.
2
Abortar el programa.
3
Imprimir mensaje de error detallado, rastreo de pila y mapeos de memoria, y abortar el programa.
5
Imprimir un mensaje de error simple y continuar la ejecución.
7
Imprimir mensaje de error simple, rastreo de pila y mapeos de memoria, y abortar el programa.
Desde glibc 2.3.4, el valor predeterminado para el parámetro M_CHECK_ACTION es 3. En glibc 2.3.3 y anteriores, el valor predeterminado es 1.
Usar un valor de M_CHECK_ACTION distinto de cero puede ser útil porque de lo contrario un bloqueo podría ocurrir mucho más tarde, y la causa real del problema sería entonces muy difícil de rastrear.
M_MMAP_MAX
Este parámetro especifica el número máximo de solicitudes de asignación que pueden ser atendidas simultáneamente utilizando mmap(2). Este parámetro existe porque algunos sistemas tienen un número limitado de tablas internas para uso por mmap(2), y usar más que unas pocas de ellas puede degradar el rendimiento.
El valor predeterminado es 65.536, un valor que no tiene un significado especial y que solo sirve como salvaguarda. Establecer este parámetro a 0 deshabilita el uso de mmap(2) para atender solicitudes de asignación grandes.
M_MMAP_THRESHOLD
Para asignaciones mayores o iguales al límite especificado (en bytes) por M_MMAP_THRESHOLD que no pueden ser satisfechas desde la lista de libres, las funciones de asignación de memoria emplean mmap(2) en lugar de incrementar el break del programa usando sbrk(2).
Asignar memoria usando mmap(2) tiene la ventaja significativa de que los bloques de memoria asignados siempre pueden ser liberados independientemente al sistema. (En contraste, el heap solo puede ser recortado si se libera memoria en su extremo superior). Por otro lado, hay algunas desventajas en el uso de mmap(2): el espacio desasignado no se coloca en la lista de libres para su reutilización por asignaciones posteriores; la memoria puede desperdiciarse porque las asignaciones de mmap(2) deben estar alineadas a página; y el kernel debe realizar la costosa tarea de poner a cero la memoria asignada a través de mmap(2). El equilibrio de estos factores lleva a una configuración predeterminada de 128*1024 para el parámetro M_MMAP_THRESHOLD.
El límite inferior para este parámetro es 0. El límite superior es DEFAULT_MMAP_THRESHOLD_MAX: 512*1024 en sistemas de 32 bits o 4*1024*1024*sizeof(long) en sistemas de 64 bits.
Nota: Hoy en día, glibc utiliza un umbral de mmap dinámico por defecto. El valor inicial del umbral es 128*1024, pero cuando los bloques mayores que el umbral actual e menores o iguales a DEFAULT_MMAP_THRESHOLD_MAX son liberados, el umbral se ajusta hacia arriba al tamaño del bloque liberado. mallopt - Configurar parámetros del asignador de memoria

SYNOPSIS

#include <malloc.h>
int mallopt(int parameter, int value);

DESCRIPTION

La función mallopt() se utiliza para modificar parámetros del asignador de memoria glibc. Actualmente, solo se admite el parámetro M_CHECK_ACTION. Las llamadas subsiguientes a malloc() y sus funciones relacionadas (como calloc(), realloc(), y free()) se comportarán de acuerdo con el nuevo valor.

El parámetro M_CHECK_ACTION controla la acción que realiza el asignador de memoria de glibc cuando detecta un error de corrupción de memoria o de puntero no válido. El valor de value puede ser uno de los siguientes:

0
No hacer nada y continuar. El programa puede o no fallar más tarde.
1
Devolver NULL en las llamadas subsiguientes a malloc() y similares si se detecta un error. Sin embargo, el programa continuará ejecutándose.
2
Imprimir un mensaje de error en stderr y terminar el programa con exit(3). Esto es lo que sucede por defecto si no se llama a mallopt().
3
Igual que 0, pero además imprime un mensaje de error en stderr.

Otros valores para value no están definidos y darán lugar a un comportamiento indefinido.

El parámetro M_CHECK_ACTION solo puede configurarse una vez. Las llamadas posteriores a mallopt() con M_CHECK_ACTION serán ignoradas.

El valor predeterminado para M_CHECK_ACTION es 2.

RETURN VALUE

En caso de éxito, mallopt() devuelve 1. En caso de error (por ejemplo, si se intenta configurar M_CHECK_ACTION más de una vez, o si se proporciona un value no válido), devuelve 0 y establece errno en consecuencia.

ERRORS

errno puede establecerse en EINVAL si se intenta configurar M_CHECK_ACTION más de una vez, o si se proporciona un value no válido.

VERSIONS

La opción M_CHECK_ACTION se introdujo en la versión 2.5 de Glibc.

STANDARDS

Esta función no es parte de ningún estándar.

HISTORY

La opción M_CHECK_ACTION se introdujo en la versión 2.5 de Glibc.

BUGS

Solo se admite el parámetro M_CHECK_ACTION. Cualquier otro parámetro no definido dará lugar a un comportamiento indefinido.

El parámetro M_CHECK_ACTION solo puede configurarse una vez. Las llamadas posteriores a mallopt() con M_CHECK_ACTION serán ignoradas.

EXAMPLES

El siguiente ejemplo demuestra cómo configurar M_CHECK_ACTION a 0 para ignorar los errores:

$ ./a.out 0;             # Ignorar error y continuar
main(): returned from first free() call
main(): returned from second free() call

La siguiente ejecución muestra cómo configurar el mismo parámetro usando la variable de entorno MALLOC_CHECK_:

$ MALLOC_CHECK_=1 ./a.out;
main(): returned from first free() call
*** glibc detected *** ./a.out: free(): invalid pointer: 0x092c2008 ***
main(): returned from second free() call

Fuente del programa

#include <malloc.h>
#include <stdio.h>
#include <stdlib.h>
int
main(int argc, char *argv[])
{
    char *p;
    if (argc > 1) {
        if (mallopt(M_CHECK_ACTION, atoi(argv[1])) != 1) {
            fprintf(stderr, "mallopt() failed");
            exit(EXIT_FAILURE);
        }
    }
    p = malloc(1000);
    if (p == NULL) {
        fprintf(stderr, "malloc() failed");
        exit(EXIT_FAILURE);
    }
    free(p);
    printf("%s(): returned from first free() call\n", __func__);
    free(p);
    printf("%s(): returned from second free() call\n", __func__);
    exit(EXIT_SUCCESS);
}
