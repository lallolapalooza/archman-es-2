MARIADB(1) Sistema de Bases de Datos MariaDB MARIADB(1)

NOMBRE

mariadb - la herramienta de línea de comandos de MariaDB (mysql ahora es un enlace simbólico a mariadb)

SINOPSIS

mariadb [opciones] nombre_bd

DESCRIPCIÓN

mariadb es un shell SQL simple (con capacidades de lectura de GNU). Soporta uso interactivo y no interactivo. Cuando se usa interactivamente, los resultados de las consultas se presentan en formato de tabla ASCII. Cuando se usa no interactivamente (por ejemplo, como un filtro), el resultado se presenta en formato separado por tabulaciones. El formato de salida se puede cambiar usando opciones de línea de comandos.

Si tienes problemas debido a memoria insuficiente para conjuntos de resultados grandes, usa la opción --quick. Esto fuerza a mariadb a recuperar los resultados del servidor fila por fila en lugar de recuperar todo el conjunto de resultados y almacenarlo en búfer en memoria antes de mostrarlo. Esto se hace devolviendo el conjunto de resultados usando la función de API C mariadb_use_result() en la biblioteca cliente/servidor en lugar de mysql_store_result().

Usar mariadb es muy fácil. Invocalo desde el prompt de tu intérprete de comandos de la siguiente manera:

shell> mariadb nombre_bd

O:

shell> mariadb --user=nombre_usuario --password=tu_contraseña nombre_bd

Luego escribe una sentencia SQL, termínala con “;”, \g, o \G y presiona Enter.

Escribir Control-C hace que mariadb intente matar la sentencia actual. Si esto no se puede hacer, o se escribe Control-C de nuevo antes de que la sentencia sea matada, mariadb sale.

Puedes ejecutar sentencias SQL en un archivo de script (archivo batch) así:

shell> mariadb nombre_bd < script.sql > salida.tab

OPCIONES DE MARIADB

mariadb soporta las siguientes opciones, las cuales pueden ser especificadas en la línea de comandos o en los grupos de archivos de opciones [mariadb], [client], [client-server] o [client-mariadb]. mariadb también soporta las opciones para procesar archivos de opciones.

•--help, -?, -I

Muestra un mensaje de ayuda y sale.

•--abort-source-on-error

Aborta las operaciones de 'source nombre_archivo' en caso de errores.

•--auto-rehash

Habilita el re-hashing automático. Esta opción está activada por defecto, lo que habilita la finalización de nombres de bases de datos, tablas y columnas. Usa --disable-auto-rehash, --no-auto-rehash, o --skip-auto-rehash para deshabilitar el re-hashing. Esto hace que mariadb inicie más rápido, pero debes emitir el comando rehash si deseas usar la finalización de nombres.

Para completar un nombre, ingresa la primera parte y presiona Tab. Si el nombre es inequívoco, mariadb lo completa. De lo contrario, puedes presionar Tab nuevamente para ver los nombres posibles que comienzan con lo que has escrito hasta ahora. La finalización no ocurre si no hay una base de datos por defecto.

•--auto-vertical-output

Cambia automáticamente al modo de salida vertical si el resultado es más ancho que el ancho de la terminal.

•--batch, -B

Imprime los resultados usando tabulación como separador de columnas, con cada fila en una nueva línea. Con esta opción, mariadb no usa el archivo de historial.

El modo batch resulta en un formato de salida no tabular y el escapado de caracteres especiales. El escapado puede ser deshabilitado usando el modo raw; consulta la descripción de la opción --raw.

•--binary-mode

El modo binario permite que ciertas secuencias de caracteres se procesen como datos que de otro modo serían tratados con un significado especial por el analizador. Específicamente, este interruptor desactiva el análisis de todos los comandos del cliente excepto \C y DELIMITER en modo no interactivo (es decir, cuando el modo binario se combina con 1) entrada canalizada, 2) la opción --batch de mariadb, o 3) el comando 'source'). Además, en modo binario, las ocurrencias de '\r\n' y '\0' ASCII se conservan dentro de las cadenas, mientras que por defecto, '\r\n' se traduce a '\n' y '\0' no está permitido en la entrada del usuario.

•--character-sets-dir=ruta

El directorio donde se instalan los conjuntos de caracteres.

•--column-names

Escribe los nombres de las columnas en los resultados.

•--column-type-info, -m

Muestra metadatos del conjunto de resultados.

•--comments, -c

Si conservar los comentarios en las sentencias enviadas al servidor. El valor predeterminado es --skip-comments (descartar comentarios), habilita con --comments (conservar comentarios).

•--compress, -C

Comprime toda la información enviada entre el cliente y el servidor si ambos soportan compresión.

•--connect-timeout=segundos

Establece el número de segundos antes de que expire el tiempo de espera de la conexión. (Valor predeterminado es 0.)

•--database=nombre_bd, -D nombre_bd

La base de datos a usar.

•--debug[=opciones_debug], -# [opciones_debug]

Escribe un registro de depuración. Una cadena típica de opciones_debug es 'd:t:o,nombre_archivo'. El valor predeterminado es 'd:t:o,/tmp/mysql.trace'.

•--debug-check

Imprime información de depuración al salir del programa.

•--debug-info, -T

Imprime información de depuración y estadísticas de uso de memoria y CPU al salir del programa.

•--default-auth=nombre

Plugin de autenticación del lado del cliente por defecto a usar.

•--default-character-set=nombre_juego_caracteres

Usa nombre_juego_caracteres como el conjunto de caracteres predeterminado para el cliente y la conexión.

Un problema común que puede ocurrir cuando el sistema operativo usa utf8 u otro conjunto de caracteres multibyte es que la salida del cliente mariadb está mal formateada, debido a que el cliente MariaDB usa el conjunto de caracteres latin1 por defecto. Generalmente puedes solucionar estos problemas usando esta opción para forzar al cliente a usar el conjunto de caracteres del sistema en su lugar.

•--defaults-extra-file=nombre_archivo

Establece nombre_archivo como el archivo del cual leer las opciones predeterminadas después de que se hayan leído los archivos de opciones globales. Debe ser dada como la primera opción.

•--defaults-file=nombre_archivo

Establece nombre_archivo como el archivo del cual leer las opciones predeterminadas, anulando los archivos de opciones globales. Debe ser dada como la primera opción.

•--defaults-group-suffix=sufijo

Además de los grupos nombrados en la línea de comandos, lee grupos que tengan el sufijo dado.

•--delimiter=str

Establece el delimitador de sentencia. El valor predeterminado es el carácter de punto y coma (“;”).

•--disable-named-commands

Deshabilita comandos nombrados. Usa solo la forma \* o usa comandos nombrados solo al principio de una línea que termine en punto y coma (“;”). mariadb inicia con esta opción *activada* por defecto. Sin embargo, incluso con esta opción, los comandos de formato largo aún funcionan desde la primera línea. Consulta la sección llamada “COMANDOS DE MARIADB”.

•--enable-cleartext-plugin

Opción obsoleta. Existe solo para compatibilidad con MySQL.

•--execute=sentencia, -e sentencia

Ejecuta la sentencia y sale. Deshabilita --force y el archivo de historial. El formato de salida predeterminado es similar al producido con --batch.

•--force, -f

Continúa incluso si ocurre un error SQL. Establece --abort-source-on-error a 0.

•--host=nombre_host, -h nombre_host

Conéctate al servidor MariaDB en el host dado.

•--html, -H

Produce salida HTML.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

•--ignore-spaces, -i

Ignora los espacios después de los nombres de las funciones. Permite tener espacios (incluidos caracteres de tabulación y caracteres de nueva línea) entre el nombre de la función y '('. La desventaja es que esto hace que las funciones integradas se conviertan en palabras reservadas.

•--init-command=str

Comando SQL para ejecutar al conectarse al servidor MariaDB. Se volverá a ejecutar automáticamente al reconectarse.

•--line-numbers

Escribe números de línea para los errores. Desactiva esto con --skip-line-numbers.

•--local-infile[={0|1}]

Habilita o deshabilita la capacidad LOCAL para LOAD DATA INFILE. Sin valor, la opción habilita LOCAL. La opción puede darse como --local-infile=0 o --local-infile=1 para deshabilitar o habilitar explícitamente LOCAL. Habilitar LOCAL no tiene efecto si el servidor tampoco lo admite.

•--max-allowed-packet=num

Establece la longitud máxima del paquete para enviar o recibir del servidor. (Valor predeterminado: 16 MB, máximo 1 GB).

•--max-join-size=num

Establece el límite automático de filas en una unión al usar --safe-updates. (Valor predeterminado: 1.000.000).

•--named-commands, -G

Habilita comandos mariadb con nombre. Se permiten comandos en formato largo, no solo en formato corto. Por ejemplo, tanto quit como \q son reconocidos. Usa --skip-named-commands para deshabilitar los comandos con nombre. Consulta la sección llamada "COMANDOS DE MARIADB". Deshabilitado por defecto.

•--net-buffer-length=size

Establece el tamaño del búfer para la comunicación TCP/IP y de socket. (Valor predeterminado: 16 KB).

•--no-auto-rehash, -A

Esto tiene el mismo efecto que --skip-auto-rehash. Consulta la descripción de --auto-rehash.

•--no-beep, -b

No emitir pitidos cuando ocurran errores.

•--no-defaults

No leer opciones predeterminadas de ningún archivo de opciones. Esto debe proporcionarse como primer argumento.

•--one-database, -o

Ignora sentencias excepto aquellas que ocurren mientras la base de datos predeterminada es la que se nombra en la línea de comandos. Este filtrado es limitado y se basa solo en sentencias USE. Esto es útil para omitir actualizaciones a otras bases de datos en el registro binario.

•--pager[=command]

Utiliza el comando dado para paginar la salida de la consulta. Si se omite el comando, el paginador predeterminado es el valor de tu variable de entorno PAGER. Los paginadores válidos son less, more, cat [> filename], y similares. Esta opción solo funciona en Unix y solo en modo interactivo. Para deshabilitar la paginación, usa --skip-pager. La sección llamada "COMANDOS DE MARIADB" discute más sobre la paginación de salida.

•--password[=password], -p[password]

La contraseña a usar al conectarse al servidor. Si usas la forma corta de la opción (-p), *no* puedes tener un espacio entre la opción y la contraseña. Si omites el valor de password después de la opción --password o -p en la línea de comandos, mariadb te pedirá una.

Especificar una contraseña en la línea de comandos debe considerarse inseguro. Puedes usar un archivo de opciones para evitar proporcionar la contraseña en la línea de comandos.

•--pipe, -W

En Windows, conéctate al servidor a través de una tubería con nombre. Esta opción solo se aplica si el servidor admite conexiones por tubería con nombre.

•--plugin-dir=dir_name

Directorio para los plugins del lado del cliente.

•--port=port_num, -P port_num

El número de puerto TCP/IP a usar para la conexión o 0 para usar el predeterminado, en orden de preferencia: my.cnf, $MYSQL_TCP_PORT, /etc/services, predeterminado integrado (3306). Fuerza --protocol=tcp cuando se especifica en la línea de comandos sin otras propiedades de conexión.

•--print-defaults

Imprime la lista de argumentos del programa y sale. Esto debe proporcionarse como primer argumento.

•--progress-reports

Obtiene informes de progreso para comandos de larga duración (como ALTER TABLE). (Activado por defecto; usa --skip-progress-reports para deshabilitar).

•--prompt=format_str

Establece el prompt al formato especificado. Las secuencias especiales que el prompt puede contener se describen en la sección llamada "COMANDOS DE MARIADB".

•--protocol={TCP|SOCKET|PIPE|MEMORY}

El protocolo de conexión a utilizar para conectarse al servidor. Es útil cuando los demás parámetros de conexión normalmente provocarían el uso de un protocolo diferente al que deseas.

•--quick, -q

No almacenar en caché el resultado de cada consulta, imprime cada fila a medida que se recibe. Esto puede ralentizar el servidor si la salida se suspende. Con esta opción, mariadb no utiliza el archivo de historial.

•--raw, -r

Para la salida tabular, el "recuadro" alrededor de las columnas permite distinguir un valor de columna de otro. Para la salida no tabular (como la que se produce en modo por lotes o cuando se da la opción --batch o --silent), los caracteres especiales se escapan en la salida para que puedan identificarse fácilmente. La nueva línea, la tabulación, NUL y la barra invertida se escriben como \n, \t, \0 y \\. La opción --raw deshabilita este escape de caracteres.

El siguiente ejemplo demuestra la salida tabular versus no tabular y el uso del modo raw para deshabilitar el escape:

% mariadb
mariadb> SELECT CHAR(92);
+----------+
| CHAR(92) |
+----------+
| \        |
+----------+
% mariadb -s
mariadb> SELECT CHAR(92);
CHAR(92)
\\
% mariadb -s -r
mariadb> SELECT CHAR(92);
CHAR(92)
\
•--reconnect

Si se pierde la conexión con el servidor, intenta reconectar automáticamente. Se realiza un solo intento de reconexión cada vez que se pierde la conexión. Habilitado por defecto, para deshabilitar usa --skip-reconnect o --disable-reconnect.

•--safe-updates, --i-am-a-dummy, -U

Permite solo las sentencias UPDATE y DELETE que especifican qué filas modificar utilizando valores de clave. Si has establecido esta opción en un archivo de opciones, puedes anularla utilizando --safe-updates en la línea de comandos. Consulta la sección llamada "CONSEJOS DE MARIADB" para obtener más información sobre esta opción.

•--secure-auth

No enviar contraseñas al servidor en formato antiguo (anterior a 4.1.1). Esto evita conexiones excepto para servidores que usan el formato de contraseña más nuevo.

•--select-limit=limit

Establece el límite automático para SELECT al usar --safe-updates. (Valor predeterminado: 1.000).

•--server-arg=name

Envía name como un parámetro al servidor embebido.

•--show-warnings

Hace que se muestren las advertencias después de cada sentencia si las hay. Esta opción se aplica al modo interactivo y por lotes.

•--sigint-ignore

Ignora las señales SIGINT (típicamente el resultado de presionar Control-C).

•--silent, -s

Modo silencioso. Produce menos salida. Esta opción se puede dar varias veces para producir cada vez menos salida.

Esta opción da como resultado un formato de salida no tabular y el escape de caracteres especiales. El escape puede deshabilitarse usando el modo raw; consulta la descripción de la opción --raw.

•--skip-auto-rehash

Deshabilita el rehashing automático. Sinónimo de --disable-auto-rehash.

•--skip-column-names, -N

No escribir nombres de columna en los resultados.

•--skip-line-numbers, -L

No escribir números de línea para los errores. Útil cuando deseas comparar archivos de resultados que incluyen mensajes de error.

•--socket=path, -S path

Para conexiones a localhost, el archivo de socket Unix a usar o, en Windows, el nombre de la tubería con nombre a usar. Fuerza --protocol=socket cuando se especifica en la línea de comandos sin otras propiedades de conexión; en Windows, fuerza --protocol=pipe.

•--ssl

Habilita SSL para la conexión (habilitado automáticamente con otras banderas). Deshabilita con --skip-ssl.

•--ssl-ca=name

Archivo CA en formato PEM (consulta la documentación de OpenSSL, implica --ssl).

•--ssl-capath=name

Directorio CA (consulta la documentación de OpenSSL, implica --ssl).

•--ssl-cert=name

Certificado X509 en formato PEM (consulta la documentación de OpenSSL, implica --ssl).

•--ssl-cipher=name

Cifrado SSL a usar (consulta la documentación de OpenSSL, implica --ssl).

•--ssl-key=name

Clave X509 en formato PEM (consulta la documentación de OpenSSL, implica --ssl).

•--ssl-crl=name

Lista de revocación de certificados (consulta la documentación de OpenSSL, implica --ssl).

•--ssl-crlpath=name

Ruta de la lista de revocación de certificados (consulta la documentación de OpenSSL, implica --ssl).

•--ssl-verify-server-cert

Verifica el "Nombre Común" del servidor en su certificado contra el nombre de host utilizado al conectarse. Esta opción está deshabilitada por defecto.

•--table, -t

Muestra la salida en formato de tabla. Este es el valor predeterminado para uso interactivo, pero se puede usar para producir salida en formato de tabla en modo por lotes.

•--tee=file_name

Añade una copia de la salida al archivo dado. Esta opción solo funciona en modo interactivo. La sección llamada "COMANDOS DE MARIADB" discute más sobre los archivos tee.

•--unbuffered, -n

Fl

use el búfer después de cada consulta.

•--user=nombre_usuario, -u nombre_usuario

El nombre de usuario de MariaDB que se utilizará al conectarse al servidor.

•--verbose, -v

Modo detallado. Produce más información sobre lo que hace el programa. Esta opción se puede especificar varias veces para producir más y más información. (Por ejemplo, -v -v -v produce formato de salida de tabla incluso en modo por lotes).

•--version, -V

Muestra información de la versión y sale.

•--vertical, -E

Imprime las filas de salida de la consulta verticalmente (una línea por valor de columna). Sin esta opción, puede especificar la salida vertical para sentencias individuales terminándolas con \G.

•--wait, -w

Si la conexión no se puede establecer, espera y reintenta en lugar de abortar.

•--xml, -X

Produce salida XML. La salida cuando se utiliza --xml con mariadb coincide con la de mariadb-dump --xml. Ver mariadb-dump(1) para más detalles.

La salida XML también utiliza un espacio de nombres XML, como se muestra aquí:

También puede establecer las siguientes variables utilizando --nombre_var=valor.

•connect_timeout

El número de segundos antes de que expire el tiempo de espera de la conexión. (Valor predeterminado: 0).

•max_allowed_packet

La longitud máxima del paquete a enviar o recibir del servidor. (Valor predeterminado: 16MB).

•max_join_size

El límite automático para las filas en una unión al usar --safe-updates. (Valor predeterminado: 1,000,000).

•net_buffer_length

El tamaño del búfer para la comunicación TCP/IP y de socket. (Valor predeterminado: 16KB).

•select_limit

El límite automático para las sentencias SELECT al usar --safe-updates. (Valor predeterminado: 1,000).

En Unix, el cliente mariadb escribe un registro de las sentencias ejecutadas en un archivo de historial. Por defecto, este archivo se llama .mariadb_history y se crea en su directorio principal. Para compatibilidad con versiones anteriores, se utilizará .mariadb_history si está presente y .mariadb_history falta. Para especificar un archivo diferente, establezca el valor de la variable de entorno MARIADB_HISTFILE. La variable de entorno MYSQL_HISTFILE se utilizará si MARIADB_HISTFILE no está presente.

El archivo .mariadb_history debe protegerse con un modo de acceso restrictivo porque se puede escribir información confidencial en él, como el texto de las sentencias SQL que contienen contraseñas.

Si no desea mantener un archivo de historial, primero elimine .mariadb_history si existe y luego utilice cualquiera de las siguientes técnicas:

•Establezca la variable MARIADB_HISTFILE en /dev/null. Para que esta configuración tenga efecto cada vez que inicie sesión, colóquela en uno de los archivos de inicio de su shell.
•Cree .mariadb_history como un enlace simbólico a /dev/null: 
shell> ln -s /dev/null $HOME/.mariadb_history

Solo necesita hacer esto una vez.

COMANDOS MARIADB

mariadb envía cada sentencia SQL que emite al servidor para que se ejecute. También hay un conjunto de comandos que mariadb interpreta por sí mismo. Para obtener una lista de estos comandos, escriba help o \h en el indicador mariadb>:

mariadb> help
List of all MariaDB commands:
Note that all text commands must be first on line and end with ';'
?         (\?) Synonym for 'help'.
clear     (\c) Clear command.
connect   (\r) Reconnect to the server. Optional arguments are db and host.
delimiter (\d) Set statement delimiter.
edit      (\e) Edit command with $EDITOR.
ego       (\G) Send command to mariadb server, display result vertically.
exit      (\q) Exit mariadb. Same as quit.
go        (\g) Send command to mariadb server.
help      (\h) Display this help.
nopager   (\n) Disable pager, print to stdout.
notee     (\t) Don't write into outfile.
pager     (\P) Set PAGER [to_pager]. Print the query results via PAGER.
print     (\p) Print current command.
prompt    (\R) Change your mariadb prompt.
quit      (\q) Quit mariadb.
rehash    (\#) Rebuild completion hash.
source    (\.) Execute an SQL script file. Takes a file name as an argument.
status    (\s) Get status information from the server.
system    (\!) Execute a system shell command.
tee       (\T) Set outfile [to_outfile]. Append everything into given
               outfile.
use       (\u) Use another database. Takes database name as argument.
charset   (\C) Switch to another charset. Might be needed for processing
               binlog with multi-byte charsets.
warnings  (\W) Show warnings after every statement.
nowarning (\w) Don't show warnings after every statement.
For server side help, type 'help contents'

Cada comando tiene una forma larga y una forma corta. La forma larga no distingue entre mayúsculas y minúsculas; la forma corta sí. La forma larga puede ir seguida de un terminador de punto y coma opcional, pero la forma corta no.

El uso de comandos de forma corta dentro de comentarios multi-línea /* ... */ no está soportado.

•help [arg], \h [arg], \? [arg], ? [arg]

Muestra un mensaje de ayuda que enumera los comandos disponibles de mariadb.

Si proporciona un argumento al comando help, mariadb lo utiliza como cadena de búsqueda para acceder a la ayuda del lado del servidor. Para más información, ver la sección llamada “AYUDA DEL SERVIDOR MARIADB”.

•charset nombre_juego_caracteres, \C nombre_juego_caracteres

Cambia el conjunto de caracteres predeterminado y emite una sentencia SET NAMES. Esto permite que el conjunto de caracteres se mantenga sincronizado en el cliente y el servidor si mariadb se ejecuta con reconexión automática habilitada (lo cual no es recomendable), ya que el conjunto de caracteres especificado se utiliza para las reconexiones.

•clear, \c

Borra la entrada actual. Úselo si cambia de opinión sobre la ejecución de la sentencia que está introduciendo.

•connect [nombre_bd nombre_host]], \r [nombre_bd nombre_host]]

Reconecta al servidor. Los argumentos opcionales de nombre de base de datos y nombre de host se pueden proporcionar para especificar la base de datos predeterminada o el host donde se está ejecutando el servidor. Si se omiten, se utilizan los valores actuales.

•delimiter str, \d str

Cambia la cadena que mariadb interpreta como separador entre sentencias SQL. El valor predeterminado es el carácter de punto y coma (“;”).

El delimitador se puede especificar como un argumento sin comillas o entre comillas. Las comillas se pueden hacer con comillas simples (') o dobles ("). Para incluir una comilla dentro de una cadena entre comillas, ponga la cadena entre comillas con el otro tipo de comilla o escape la comilla con una barra invertida ("\"). Se debe evitar la barra invertida fuera de las cadenas entre comillas, ya que es el carácter de escape para MariaDB. Para un argumento sin comillas, el delimitador se lee hasta el primer espacio o final de línea. Para un argumento entre comillas, el delimitador se lee hasta la comilla coincidente en la línea.

Cuando el delimitador reconocido por mariadb se establece en algo diferente del valor predeterminado de “;”, las instancias de ese carácter se envían al servidor sin interpretación. Sin embargo, el servidor mismo interpreta “;” como un delimitador de sentencia y procesa las sentencias en consecuencia. Este comportamiento en el lado del servidor entra en juego para la ejecución de múltiples sentencias y para el análisis del cuerpo de procedimientos y funciones almacenadas, disparadores y eventos.

•edit, \e

El comando edit solo funciona en Unix.

Envía la sentencia actual al servidor para que se ejecute y muestra el resultado en formato vertical.

•go, \g

Envía la sentencia actual al servidor para que se ejecute.

MARIA DB CLIENT CONTROL COMMANDS

•pager [program]

A pager is a program that accepts text input and displays it one screen at a time. The mariadb client supports output paging through the pager command. You can specify a program to use as the pager. For example, to use the more program, you would issue the following command:

mariadb> pager more

To disable paging, use the nopager command:

mariadb> nopager

If you issue the pager command with no argument, mariadb prints the name of the program that is currently being used as the pager.

The pager is set to the pager that was set on the command line, or stdout if no pager was specified.

Output paging works only in Unix because it uses the popen() function, which does not exist on Windows. For Windows, the tee option can be used instead to save query output, although it is not as convenient as pager for browsing output in some situations.

•print, \p

Print the current input statement without executing it.

•prompt [str], \R [str]

Reconfigure the mariadb prompt to the given string. The special character sequences that can be used in the prompt are described later in this section.

If you specify the prompt command with no argument, mariadb resets the prompt to the default of mariadb>.

•quit, \q

Exit mariadb.

•rehash, \#

Rebuild the completion hash that enables database, table, and column name completion while you are entering statements. (See the description for the --auto-rehash option.)

•source file_name, \. file_name

Read the named file and executes the statements contained therein. On Windows, you can specify path name separators as / or \\.

•status, \s

Provide status information about the connection and the server you are using. If you are running in --safe-updates mode, status also prints the values for the mariadb variables that affect your queries.

•system command, \! command

Execute the given command using your default command interpreter.

The system command works only in Unix.

•tee [file_name], \T [file_name]

By using the --tee option when you invoke mariadb, you can log statements and their output. All the data displayed on the screen is appended into a given file. This can be very useful for debugging purposes also. mariadb flushes results to the file after each statement, just before it prints its next prompt. Tee functionality works only in interactive mode.

You can enable this feature interactively with the tee command. Without a parameter, the previous file is used. The tee file can be disabled with the notee command. Executing tee again re-enables logging.

•use db_name, \u db_name

Use db_name as the default database.

•warnings, \W

Here are a few tips about the pager command:

•You can use it to write to a file and the results go only to the file: 
mariadb> pager cat > /tmp/log.txt

You can also pass any options for the program that you want to use as your pager:

mariadb> pager less -n -i -S
•In the preceding example, note the -S option. You may find it very useful for browsing wide query results. Sometimes a very wide result set is difficult to read on the screen. The -S option to less can make the result set much more readable because you can scroll it horizontally using the left-arrow and right-arrow keys. You can also use -S interactively within less to switch the horizontal-browse mode on and off. For more information, read the less manual page: 
shell> man less
•The -F and -X options may be used with less to cause it to exit if output fits on one screen, which is convenient when no scrolling is necessary: 
mariadb> pager less -n -i -S -F -X
•You can specify very complex pager commands for handling query output: 
mariadb> pager cat | tee /dr1/tmp/res.txt \
          | tee /dr2/tmp/res2.txt | less -n -i -S

In this example, the command would send query results to two files in two different directories on two different file systems mounted on /dr1 and /dr2, yet still display the results onscreen via less.

You can also combine the tee and pager functions. Have a tee file enabled and pager set to less, and you are able to browse the results using the less program and still have everything appended into a file the same time. The difference between the Unix tee used with the pager command and the mariadb built-in tee command is that the built-in tee works even if you do not have the Unix tee available. The built-in tee also logs everything that is printed on the screen, whereas the Unix tee used with pager does not log quite that much. Additionally, tee file logging can be turned on and off interactively from within mariadb. This is useful when you want to log some queries to a file, but not others.

shell> mariadb --prompt="(\u@\h) [\d]> "
(user@host) [database]>

[mariadb]
prompt="\\r:\\m:\\s> "

NAME

mariadb - MariaDB command-line client

SYNOPSIS

mariadb [options] [database_name]

DESCRIPTION

The mariadb program is a console interface to the MariaDB server. It supports interactive command execution and batch processing of SQL statements.

mariadb provides a command-line interface to MariaDB. It can be used interactively from the keyboard, or it can be used to execute SQL statements read from a file.

MARIADB OPTIONS

The mariadb client supports a wide range of options. The most common ones include:

-?, --help
Display a help message and exit.
-A, --no-auto-rehash
Disable automatic rehashing. With rehashing enabled, mariadb automatically rebuilds its table and column name completion cache. Disabling it may speed up startup slightly for clients that connect to servers with a very large number of databases.
--auto-vertical-output
Automatically switch to vertical output format (\G) when the output is wider than the terminal width.
-c, --skip-column-names
Do not write column names in results. Useful when you want only the query results, for example, when piping the output to another program.
-C, --compress
Compress client/server protocol communication.
-e, --execute=query
Execute the given query and exit.
-f, --force
Continue executing even if errors occur.
-h, --host=host_name
Connect to the specified host.
-H, --html
Produce HTML output.
-i, --ignore-space
Interpret sequences of spaces as a single space.
-l, --local-infile[=value]
Enable or disable the ability to read local files with LOAD DATA INFILE. The optional value can be 0 or 1 to disable or enable respectively. If the value is omitted, it defaults to 1 (enabled).
-L, --skip-line-numbers
Suppress line number in error messages.
-m, --more-results
Fetch all results for a query before running the next query.
-n, --skip-pager
Do not use a pager for output.
-N, --skip-column-numbers
Same as -c, --skip-column-names.
-O, --skip-opt
Deprecated. Ignored.
-p, --password[=password]
The password to use when connecting to the server. If password is not given explicitly, mariadb prompts for one.
-P, --port=port_num
The TCP/IP port number to use for the connection.
--prompt=format_str
Use the specified string to prompt the user for input. The format string may include special sequences that are expanded by mariadb.
-q, --quiet
Be more quiet. Suppress the logging of commands into the history file.
-r, --raw
Produce less output. No newline after each row. Useful when piping output to another program.
-S, --socket=path/to/socket
The Unix socket file to use for connection.
--safe-updates
Enable safe updates mode. This option is helpful for beginners as it prevents accidental deletion of rows without a WHERE clause or LIMIT clause. See the MARIADB TIPS section below for more details.
-s, --silent
Be even more quiet. Suppress the logging of commands into the history file.
-t, --table
Output in table format. This is the default.
-T, --tab=file_name
Write table contents to one or more files. The files are named by appending the column name to the specified filename. This option implies -s (silent).
-u, --user=user_name
The user name to use when connecting to the server.
-v, --verbose
Write more information. Verbose mode. Print executed statements before they are executed.
-V, --version
Display version information and exit.
-w, --where=where_condition
Quote the where_condition and use it as the WHERE clause for SQL statements.
--xml
Produce XML output.

The full list of options can be found by running mariadb --help.

\c, --cancel

\h, --help

Execute a system command.
\r, --reconnect

\s, --status
Show the server status.
\t, --tables

\u, --use
Use database. Followed by database name.

EXECUTING SQL STATEMENTS FROM A TEXT FILE

The mariadb client typically is used interactively, like this:

shell> mariadb db_name

However, it is also possible to put your SQL statements in a file and then tell mariadb to read its input from that file. To do so, create a text file text_file that contains the statements you wish to execute. Then invoke mariadb as shown here:

shell> mariadb db_name < text_file

If you place a USE db_name statement as the first statement in the file, it is unnecessary to specify the database name on the command line:

shell> mariadb < text_file

If you are already running mariadb, you can execute an SQL script file using the source command or \. command:

mariadb> source file_name
mariadb> \. file_name

Sometimes you may want your script to display progress information to the user. For this you can insert statements like this:

SELECT '<info_to_display>' AS ' ';

The statement shown outputs <info_to_display>.

You can also invoke mariadb with the --verbose option, which causes each statement to be displayed before the result that it produces.

mariadb ignores Unicode byte order mark (BOM) characters at the beginning of input files. Presence of a BOM does not cause mariadb to change its default character set. To do that, invoke mariadb with an option such as --default-character-set=utf8.

Using the --safe-updates Option

For beginners, a useful startup option is --safe-updates (or --i-am-a-dummy, which has the same effect). It is helpful for cases when you might have issued a DELETE FROM tbl_name statement but forgotten the WHERE clause. Normally, such a statement deletes all rows from the table. With --safe-updates, you can delete rows only by specifying the key values that identify them. This helps prevent accidents.

When you use the --safe-updates option, mariadb issues the following statement when it connects to the MariaDB server:

SET sql_safe_updates=1, sql_select_limit=1000, sql_max_join_size=1000000;

The SET statement has the following effects:

•You are not allowed to execute an UPDATE or DELETE statement unless you specify a key constraint in the WHERE clause or provide a LIMIT clause (or both). For example: 
UPDATE tbl_name SET not_key_column=val WHERE key_column=val;
UPDATE tbl_name SET not_key_column=val LIMIT 1;
•The server limits all large SELECT results to 1,000 rows unless the statement includes a LIMIT clause.
•The server aborts multiple-table SELECT statements that probably need to examine more than 1,000,000 row combinations.

To specify limits different from 1,000 and 1,000,000, you can override the defaults by using the --select-limit and --max-join-size options:

shell> mariadb --safe-updates --select-limit=500 --max-join-size=10000

Disabling mariadb Auto-Reconnect

If the mariadb client loses its connection to the server while sending a statement, it immediately and automatically tries to reconnect once to the server and send the statement again. However, even if mariadb succeeds in reconnecting, your first connection has ended and all your previous session objects and settings are lost: temporary tables, the autocommit mode, and user-defined and session variables. Also, any current transaction rolls back. This behavior may be dangerous for you, as in the following example where the server was shut down and restarted between the first and second statements without you knowing it:

mariadb> SET @a=1;
Query OK, 0 rows affected (0.05 sec)
mariadb> INSERT INTO t VALUES(@a);
ERROR 2006: MariaDB server has gone away
No connection. Trying to reconnect...
Connection id:    1
Current database: test
Query OK, 1 row affected (1.30 sec)
mariadb> SELECT * FROM t;
+------+
| a    |
+------+
| NULL |
+------+
1 row in set (0.05 sec)

The @a user variable has been lost with the connection, and after the reconnection it is undefined. If it is important to have mariadb terminate with an error if the connection has been lost, you can start the mariadb client with the --skip-reconnect option.
