MAIRIX(1) Manual de Comandos Generales MAIRIX(1)

NOMBRE

mairix - indexar y buscar carpetas de correo

SINOPSIS

Indexación

mairix [ -v|--verbose ] [ -p|--purge ] [ -f|--rcfile mairixrc ] [ -F|--fast-index ] [ --force-hash-key-new-database hash ]

Búsqueda

mairix [ -v|--verbose ] [ -f|--rcfile mairixrc ] [ -r|--raw-output ] [ -x|--excerpt-output ] [ -H|--force-hardlinks ] [ -o|--mfolder mfolder ] [ -a|--augment ] [ -t|--threads ] patrones-de-búsqueda

Otro

mairix [ -h|--help ]

mairix [ -V|--version ]

mairix [ -d|--dump ]

DESCRIPCIÓN

mairix indexa y busca una colección de mensajes de correo. Las carpetas que contienen los mensajes para indexar se definen en el archivo de configuración. La etapa de indexación produce un archivo de base de datos. El archivo de base de datos proporciona acceso rápido a los detalles de los mensajes indexados durante las operaciones de búsqueda. Una búsqueda normalmente produce una carpeta (llamada mfolder) que contiene los mensajes coincidentes. Sin embargo, existe un modo bruto (-r) que simplemente lista los mensajes coincidentes.

Puede operar con los siguientes tipos de carpetas

  • maildir
  • MH (compatible con los formatos de carpeta MH utilizados por xmh, sylpheed, claws-mail, nnml (Gnus) y evolution)
  • mbox (incluyendo mboxes que han sido comprimidas con gzip o bzip2)
  • MMDF (incluyendo los comprimidos con gzip o bzip2)
  • IMAP: carpetas remotas en un servidor IMAP

Si se utilizan carpetas de origen maildir o MH, y una búsqueda genera sus coincidencias en una mfolder en formato maildir o MH, se utilizan enlaces simbólicos para referenciar los mensajes originales dentro de la mfolder. Sin embargo, si se involucran carpetas mbox o MMDF, se hacen copias de los mensajes. Si se utilizan carpetas IMAP tanto para las fuentes de resultados como para las de origen, se realizan copias de mensajes en el servidor IMAP. Con carpetas de origen IMAP y cualquier otro tipo de carpeta de resultados, los mensajes se descargan del servidor IMAP para ser escritos en la carpeta de resultados. Con una carpeta de resultados IMAP y cualquier otro tipo de carpetas de origen, los mensajes se suben al servidor IMAP para ser añadidos a la carpeta de resultados.

OPCIONES

mairix decide si se requiere indexación o búsqueda observando la presencia de cualquier patrones-de-búsqueda en la línea de comandos.

Modos especiales

-h, --help

Muestra un resumen de uso y sale.
-V, --version
Muestra la versión del programa y sale.
-d

Volca el contenido de la base de datos en formato legible para humanos a la salida estándar.

Opciones generales

-f mairixrc

--rcfile mairixrc

Especifica un archivo de configuración alternativo a utilizar. El archivo de configuración predeterminado es ~/.mairixrc.
-v, --verbose

Hace la salida más detallada.
-Q, --no-integrity-checks

Normalmente mairix realiza algunas pruebas internas de integridad en la base de datos. La opción -Q elimina estas comprobaciones, haciendo que mairix se ejecute más rápido, pero será menos probable que detecte problemas internos si aparecen errores.

La directiva nochecks en el archivo rc tiene el mismo efecto.

--unlock

mairix bloquea su archivo de base de datos durante cualquier operación de indexación o búsqueda para evitar que múltiples ejecuciones de indexación interfieran entre sí, o que una ejecución de indexación interfiera con las ejecuciones de búsqueda. La opción --unlock elimina el archivo de bloqueo antes de realizar la operación de indexación o búsqueda solicitada. Esta es una forma conveniente de limpiar un archivo de bloqueo obsoleto si una ejecución anterior falló por alguna razón o fue abortada.

Opciones de indexación

-p, --purge

Provoca que los mensajes obsoletos (muertos) se eliminen de la base de datos durante una ejecución de indexación. (Normalmente, los mensajes obsoletos permanecen en la base de datos debido al costo adicional de compactar el espacio que ocupan).
-F, --fast-index

Al procesar carpetas maildir y MH, mairix normalmente compara el mtime y el tamaño de cada mensaje contra los valores almacenados en la base de datos. Si han cambiado, el mensaje se volverá a escanear. Esta comprobación requiere que cada archivo de mensaje sea inspeccionado. Para un gran número de mensajes en estos tipos de carpetas, esto puede suponer una sobrecarga considerable.

Esta opción le indica a mairix que asuma que cuando un mensaje actualmente en disco tiene un nombre que coincide con uno ya en la base de datos, debe asumir que el mensaje no ha cambiado.

Una ejecución de indexación posterior sin usar esta opción corregirá cualquier reescaneo que se haya omitido debido a su uso.

--force-hash-key-new-database hash

Esta opción solo debe usarse para depuración.
Si se crea una nueva base de datos, hash se utiliza como clave de hash, en lugar de un hash aleatorio.

Opciones de búsqueda

-a, --augment

Añade los mensajes coincidentes recién encontrados a la mfolder actual en lugar de crear la mfolder desde cero.
-t, --threads

Además de devolver los mensajes coincidentes, también devuelve todos los mensajes del mismo hilo que una de las coincidencias reales.
-r, --raw-output

En lugar de crear una mfolder que contenga los mensajes coincidentes, solo muestra sus rutas en la salida estándar.
-x, --excerpt-output

En lugar de crear una mfolder que contenga los mensajes coincidentes, muestra un extracto de sus cabeceras en la salida estándar. El extracto muestra Para, Cc, De y Asunto y Fecha. Con carpetas de origen IMAP, esto requiere la descarga de cada mensaje coincidente del servidor IMAP.
-H, --force-hardlinks

En lugar de crear enlaces simbólicos, fuerza el uso de enlaces físicos. Esto ayuda a los clientes de correo como alpine a darse cuenta de que hay nuevos correos en la carpeta de búsqueda.
-o mfolder

--mfolder mfolder

Especifica una ruta alternativa temporal para la mfolder a usar, anulando la directiva mfolder en el archivo rc.

mairix se negará a generar resultados de búsqueda en cualquier carpeta que parezca estar entre las que se indexan. Esto es para prevenir la eliminación accidental de correos electrónicos.

Patrones de búsqueda

t:palabra

Coincide palabra en la cabecera To:.
c:palabra


Coincide palabra en la cabecera Cc:.
f:palabra

Coincide palabra en la cabecera From:.
s:palabra

Coincide palabra en la cabecera Subject:.
m:palabra

Coincide palabra en la cabecera Message-ID:.
b:palabra

Coincide palabra en el cuerpo del mensaje.

Se considera que el cuerpo del mensaje es cualquier parte del cuerpo de tipo text/plain o text/html. Para text/html, se ignora el texto dentro de las etiquetas meta. En particular, las URL dentro de las etiquetas <A HREF="..."> no se indexan actualmente. Se ignoran los archivos adjuntos no textuales. Si hay un archivo adjunto de tipo message/rfc822, se analiza y la coincidencia se realiza también en este sub-mensaje. Si ocurre una coincidencia, el mensaje que lo contiene se considera que tiene una coincidencia.

d:[especificación-fecha-inicio]-[especificación-fecha-fin]

Coincide con mensajes cuyas cabeceras Date: se encuentran en el rango específico.
z:[tamaño-mínimo]-[tamaño-máximo]

Coincide con mensajes cuyo tamaño se encuentra en el rango especificado. Si se omite el argumento tamaño-mínimo, por defecto es cero. Si se omite el argumento tamaño-máximo, por defecto es tamaño infinito.

Por ejemplo, para que coincidan mensajes de entre 10 kilobytes y 20 kilobytes de tamaño, se puede usar el siguiente término de búsqueda:

mairix z:10k-20k

El sufijo 'k' en un número significa multiplicar por 1024, y el sufijo 'M' en un número significa multiplicar por 1024*1024.

n:palabra

Coincide palabra ocurriendo como el nombre de un archivo adjunto en el mensaje. Dado que los nombres de los archivos adjuntos suelen ser largos, esta opción se usaría normalmente en la forma de subcadena. Así
mairix n:mairix=

coincidiría con todos los mensajes que tienen archivos adjuntos cuyos nombres contienen la subcadena mairix.

El nombre del archivo adjunto se determina a partir de los calificadores name=xxx o filename=xxx en las cabeceras Content-Type: y Content-Disposition:, respectivamente.

F:flags

Coincide con mensajes con configuraciones de banderas particulares. Las banderas disponibles son 's' que significa visto, 'r' que significa respondido, y 'f' que significa marcado. Las banderas no distinguen entre mayúsculas y minúsculas. Una letra de bandera puede ir precedida de un '-' para negar su sentido. Por lo tanto, 
mairix F:-s d:1w-

coincidiría con cualquier mensaje no leído de menos de una semana de antigüedad, y

mairix F:f-r d:-1m

coincidiría con cualquier mensaje marcado de más de un mes de antigüedad al que aún no hayas respondido.

Tenga en cuenta que los caracteres de las banderas y sus significados coinciden con los utilizados como letras sufijo en los nombres de archivo de mensajes en carpetas maildir.

Buscar una coincidencia entre más de una parte de un mensaje

Se pueden agrupar varias partes del cuerpo si se busca una coincidencia en alguna de ellas. Algunos ejemplos comunes son:

tc:palabra

Coincide palabra en la cabecera To: o Cc: (o ambas).
bs:palabra

Coincide palabra en la cabecera Subject: o en el cuerpo del mensaje (o ambas).

El patrón de búsqueda a: es una abreviatura de tcf:; es decir, coincide con la palabra en las cabeceras To:, Cc: o From:. ("a" significa "dirección" en este caso.)

Palabras de coincidencia

El argumento palabra para las cadenas de búsqueda puede tener varias formas.

~palabra

Coincide con mensajes que no contienen la palabra.
palabra1,palabra2

Esto coincide si ambas palabras coinciden en la parte del mensaje especificada.
palabra1/palabra2

Esto coincide si alguna de las palabras coincide en la parte del mensaje especificada.
subcadena=

Coincide con cualquier palabra que contenga subcadena como subcadena.
subcadena=N

Coincide con cualquier palabra que contenga subcadena, permitiendo hasta N errores en la coincidencia. Por ejemplo, si N es 1, se permite un solo error, donde un error puede ser:
  • una letra faltante
  • una letra extra
  • una letra diferente.
^subcadena=

Coincide con cualquier palabra que contenga subcadena como subcadena, con el requisito de que subcadena aparezca al principio de la palabra coincidente.

La precedencia importa

El orden de enlace de las construcciones es:

1.
Los argumentos individuales de la línea de comandos definen condiciones separadas que se combinan con AND (Y).
2.
Dentro de un argumento único, las letras antes de los dos puntos definen a qué partes del mensaje se aplica la expresión. Si no hay dos puntos, la expresión se aplica a todas las cabeceras listadas anteriormente y al cuerpo.
3.
Después de los dos puntos, las barras separan disyunciones separadas, que se combinan con OR (O).
4.
Cada disyunción puede contener conjunciones separadas, que se separan por comas. Estas condiciones se combinan con AND (Y).
5.
Cada conjunción puede comenzar con una tilde para negarla, y puede ir seguida de una barra para indicar una coincidencia de subcadena, opcionalmente seguida de un entero para definir el número máximo de errores permitidos.

Especificación de fecha

Esta sección describe la sintaxis utilizada para especificar fechas al buscar usando la opción `d:'.

Las fechas se especifican como un rango. Se pueden especificar tanto el inicio como el fin del rango. Alternativamente, si se omite el inicio, se considera el principio del tiempo. Si se omite el fin, se considera la hora actual.

Hay 4 formatos básicos:

d:inicio-fin

Especificar explícitamente tanto el inicio como el fin.
d:inicio-
Especificar el inicio, el fin es la hora actual.
d:-fin
Especificar el fin, el inicio es 'hace mucho tiempo' (es decir, lo suficientemente temprano como para incluir cualquier mensaje).
d:período
Especificar el inicio y el fin implícitamente, como el inicio y el fin del período dado.

El inicio y el fin se pueden especificar de forma absoluta o relativa. Un punto final relativo se da como un número seguido de una sola letra que define la escala:

letra significa ejemplo significado
d días 3d 3 días
w semanas 2w 2 semanas (14 días)
m meses 5m 5 meses (150 días)
y años 4y 4 años (4*365 días)

Los meses siempre se tratan como 30 días, y los años como 365 días, a este efecto.

Los tiempos absolutos se pueden especificar de muchas formas. Algunas formas tienen diferentes significados cuando definen una fecha de inicio que cuando definen una fecha de fin. Cuando una sola expresión especifica tanto el inicio como el fin (es decir, cuando el argumento de d: no contiene un '-'), generalmente tendrá diferentes interpretaciones en los dos casos.

En los ejemplos a continuación, supongamos que la fecha actual es domingo 18 de mayo de 2003 (cuando empecé a escribir este material.)

NAME

mairix

email searcher

SYNOPSIS

mairix [-] [search expression]

DESCRIPTION

mairix is an email indexer and searcher. It indexes your email in order to allow fast searching of it. It is intended for people who have large volumes of email and who want to be able to find messages quickly. It is also intended for those who wish to use a command line interface.

The index is built up by running mairix in indexing mode:

mairix -I -m /path/to/mail/folder

This will create a file called .mairix in the current directory. You can also specify a different name for the index file:

mairix -I -m /path/to/mail/folder -f ~/.mairix_index

Indexing can also be done from a maildir-style folder:

mairix -I -m ~/Maildir

If you use -m to specify a directory which contains your mail, and it is not a maildir, then it is assumed to be an MH-style folder. If you have mail in both formats, you will need to index them separately.

Once the index is built, you can search it. The search expression is a series of criteria, which are ANDed together. The criteria are:

a:address
match messages sent or received from address. The address can be partial, and the match is case insensitive.
b:body
match messages containing the string body in the body of the message.
c:string
match messages containing the string string in the control file. This is only applicable for MH-style folders, and is not generally used.
C:string
match messages containing the string string in the control file. As with c: this is only applicable for MH-style folders.
d:date range
match messages within the specified date range. See the DATE RANGES section below.
f:From:
match messages sent from the specified address.
H:header
match messages containing the string header in any header.
M:message id
match messages with the specified message id.
o:string
match messages containing the string string in the other fields. This is only applicable for MH-style folders.
s:subject
match messages containing the string subject in the subject line. This match is case insensitive.
t:To:
match messages sent to the specified address.
T:string
match messages containing the string string in the thiophenames file. This is only applicable for MH-style folders.
U:string
match messages containing the string string in the thiophenames file. As with T: this is only applicable for MH-style folders.
v:string
match messages containing the string string in the drafts file. This is only applicable for MH-style folders.
x:string
match messages containing the string string in the followup file. This is only applicable for MH-style folders.

The search expression can optionally be preceded by a hyphen, which will cause the search to be run in reverse, i.e. find messages that do not match the expression.

The default behaviour is to print the matching message headers.

If the search expression is omitted, then all messages in the index are printed.

Options may be specified in a file called ~/.mairixrc. This file is read before any options on the command line. Options in the file are space separated.

OPTIONS

-a, --all
Include all messages in the index. By default, only messages dated within the last year are included.
-c, --count
Only print the number of matching messages.
-d, --date
Search dates only.
-f, --index-file file
Use file as the index file.
-h, --help
Print a help message and exit.
-I, --index
Index the mail folder. This option may be followed by a list of options which modify the indexing behaviour.
-m, --mail-dir dir
Use dir as the mail folder.
-o, --output-file file
Write the output to file instead of standard output.
-p, --print
Print the matching messages (default).
-q, --quiet
Do not print any output.
-r, --reverse
Reverse the search order.
-s, --sort key
Sort the output by the specified key. The key can be any of the search keys, or the date.
-v, --version
Print the version number and exit.

The following options can be used when indexing:

-i, --index-type type
Set the index type. Valid types are: ascii, binary, compressed, compressed_ascii, compressed_binary. The default is binary.
-x, --mformat format
Set the mail folder format. Valid formats are: maildir, mh. The default is mh.
-n, --newer-than days
Only index messages newer than days.
-e, --older-than days
Only index messages older than days.
-t, --threads num
Use num threads for indexing.

The following options can be used when searching:

-l, --limit num
Limit the number of results to num.
-m, --match-folder folder
Store matching messages in folder.
-M, --move
Move matching messages to the match folder.

The following options are for formatting the output:

-F, --format fmt

  • The start date is always taken to be on or before the end date.

SETTING UP THE MATCH FOLDER

If the match folder does not exist when running in search mode, it is automatically created. For 'mformat=maildir' (the default), this should be all you need to do. If you use 'mformat=mh', you may have to run some commands before your mailer will recognize the folder. e.g. for mutt, you could do

mkdir -p /home/richard/Mail/mfolder
touch /home/richard/Mail/mfolder/.mh_sequences

which seems to work. Alternatively, within mutt, you could set MBOX_TYPE to 'mh' and save a message to '+mfolder' to have mutt set up the structure for you in advance.

If you use Sylpheed, the best way seems to be to create the new folder from within Sylpheed before letting mairix write into it.

EXAMPLES

Suppose my email address is <richard@doesnt.exist>.

Either of the following will match all messages newer than 3 months from me with the word 'chrony' in the subject line:

mairix d:3m- f:richard+doesnt+exist s:chrony
mairix d:3m- f:richard@doesnt.exist s:chrony

Suppose I don't mind a few spurious matches on the address, I want a wider date range, and I suspect that some messages I replied to might have had the subject keyword spelt wrongly (let's allow up to 2 errors):

mairix d:6m- f:richard s:chrony=2

NOTES

mairix works exclusively in terms of words. The index that's built in indexing mode contains a table of which words occur in which messages. Hence, the search capability is based on finding messages that contain particular words. mairix defines a word as any string of alphanumeric characters + underscore. Any whitespace, punctuation, hyphens etc are treated as word boundaries.

mairix has special handling for the To:, Cc: and From: headers. Besides the normal word scan, these headers are scanned a second time, where the characters '@', '-' and '.' are also treated as word characters. This allows most (if not all) email addresses to appear in the database as single words. So if you have a mail from wibble@foobar.zzz, it will match on both these searches

mairix f:foobar
mairix f:wibble@foobar.zzz

It should be clear by now that the searching cannot be used to find messages matching general regular expressions. This has never been much of a limitation. Most searches are for particular keywords that were in the messages, or details of the recipients, or the approximate date.

It's also worth pointing out that there is no 'locality' information stored, so you can't search for messages that have one words 'close' to some other word. For every message and every word, there is a simple yes/no condition stored - whether the message contains the word in a particular header or in the body. So far this has proved to be adequate. mairix has a similar feel to using an Internet search engine.
