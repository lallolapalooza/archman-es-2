makefiles(4L) FORMATOS DE ARCHIVO GMD FOKUS makefiles(4L)

NOMBRE

makefiles - guía de usuario para compilar proyectos en diferentes plataformas

SINOPSIS

make [objetivo]
gmake [objetivo]
smake [objetivo]

El objetivo puede ser uno de los siguientes:

.help
para obtener una lista de objetivos posibles y una breve descripción.
all
para construir los objetivos predeterminados
install
para construir e instalar los objetivos predeterminados (ver INS_BASE y INS_KBASE para aprender cómo modificar la ruta de instalación).
ibins
para construir e instalar un objetivo en SRCROOT/bins
depend
para reconstruir las reglas de dependencia para todos los objetivos predeterminados. Nota: Todos los archivos de dependencia se reconstruirán automáticamente en la próxima ejecución de `make` antes de ser incluidos.
clean
para eliminar archivos core y todos los archivos objeto intermedios.
clobber
para eliminar los objetivos de clean, todos los archivos de dependencia y todos los objetivos finales
distclean
para eliminar los objetivos de clean y clobber y todos los archivos creados para todas las arquitecturas.
tags
para crear etiquetas compatibles con vi(1)
TAGS
para crear etiquetas compatibles con emacs(1)
config
reservado para uso futuro.
rmtarget
para eliminar el objetivo predeterminado
relink
para eliminar el objetivo predeterminado y volver a crearlo inmediatamente. Esto se puede usar para cambiar, por ejemplo, LD_RUN_PATH en el ejecutable.

DESCRIPCIÓN

Makefiles es un conjunto de reglas que permite compilar proyectos estructurados con makefiles pequeños y de estructura uniforme. Todas las reglas se encuentran en un directorio central. La compilación de proyectos en diferentes plataformas se puede realizar simultáneamente sin necesidad de modificar ninguno de los makefiles ubicados en los directorios de los proyectos.

Makefiles es un conjunto de herramientas de portabilidad de alto nivel, superior a autoconf y más fácil de usar.

Se admiten tres programas make: Sunpro make, GNU make y smake.

BSDmake podría ser compatible si admite correctamente las reglas de coincidencia de patrones.

El objetivo principal de diseño fue tener un conjunto de makefiles pequeños y fáciles de leer, cada uno ubicado en el directorio hoja del proyecto y, por lo tanto, llamado leaf-makefile.

Cada uno de estos leaf-makefile, de hecho, no contiene ninguna regla. Simplemente define algunas macros para el programa make e incluye dos archivos de un depósito central de reglas de make. Los archivos incluidos y los archivos que se incluyen recursivamente definen las reglas necesarias para compilar el proyecto.

Cada leaf-makefile se forma de manera muy simple:

•
Primero define dos macros que definen la ubicación relativa del directorio raíz del proyecto y el nombre del directorio que contiene el conjunto completo de reglas, y luego incluye el archivo de reglas rules.top del directorio que forma el depósito central de reglas. Solo tiene que editar la macro SRCROOT para reflejar la ubicación relativa del directorio raíz del proyecto.
•
La siguiente parte de un leaf-makefile define macros que describen el objetivo y el origen. Solo puede haber un objetivo por leaf-makefile. Por supuesto, puede haber muchos archivos fuente, que son necesarios para crear ese objetivo. Si desea crear más de un objetivo en un directorio específico, debe colocar más de un makefile en ese directorio. Esta es la parte de un makefile que describe un objetivo único. Edite esta parte para que contenga todos los archivos fuente, todos los archivos de inclusión locales y todas las banderas de tiempo de compilación no globales que sean necesarias para su objetivo. Para un objetivo típico, esto es tan simple como completar un formulario.
•
Cada leaf-makefile finalmente incluye un archivo del directorio de reglas que contiene las reglas para el tipo apropiado de objetivo que se va a crear a partir de este leaf-makefile.

El makefile en cada directorio debe llamarse Makefile. Si desea tener más de un makefile en un directorio específico, debe elegir nombres diferentes para los otros makefiles.

Existen reglas para los siguientes tipos de objetivos:

comandos
Las reglas de make para comandos de nivel de usuario como cat, ls, etc. se encuentran en el archivo rules.cmd
drivers
Las reglas de make para controladores de dispositivos se encuentran en el archivo rules.drv
bibliotecas
Las reglas de make para bibliotecas no compartidas se encuentran en el archivo rules.lib
bibliotecas compartidas
Las reglas de make para bibliotecas compartidas se encuentran en el archivo rules.shl
archivos localizados
Las reglas de make para archivos localizados se encuentran en el archivo rules.loc
archivos no localizados
Las reglas de make para archivos no localizados se encuentran en el archivo rules.aux
scripts de shell
Las reglas de make para scripts de shell (una variante de archivos localizados) se encuentran en el archivo rules.scr
páginas del manual
Las reglas de make para páginas del manual (una variante de archivos localizados) se encuentran en el archivo rules.man
makefiles desviados
Las reglas de make para proyectos que necesitan tener más de un makefile en un directorio específico se encuentran en el archivo rules.mks Contiene una regla que desvía a los sub makefiles listados. Cada sub makefile puede ser de cualquier tipo.
directorios
Las reglas de make para subdirectorios se encuentran en el archivo rules.dir

La siguiente es una descripción de las macros más importantes utilizadas dentro de las reglas de make. NOTA: es posible que no todas se puedan cambiar en un makefile específico. ASOPTX
puede usarse si desea agregar banderas a las banderas del ensamblador desde la línea de comandos. Use: make 'ASOPTX=valor'
C_ARCH

No cambie esta macro.

DEFINCDIRS
una lista de directorios que se buscan de forma predeterminada además de los directorios de inclusión del sistema. Si esta macro no está configurada, se utiliza $(SRCROOT)/include.
DIRNAME
esta macro debe establecerse en el makefile que se encuentra en el directorio $(SRCROOT). El valor debe establecerse en el nombre del directorio donde se encuentra el makefile o en SRCROOT. El valor de esta macro se actualiza automáticamente para seguir la jerarquía de directorios. No cambie esta macro en un makefile que no sea el makefile en la raíz de origen.
DIRS
esta macro debe establecerse en un makefile que se encuentra en un directorio que contiene directorios de derivación. Debe contener una lista de nombres de directorios a los que van las derivaciones, por ejemplo, DIRS= libfoo libbar libgarbage.
HFILES
para el funcionamiento normal, los makefiles encontrarán automáticamente qué archivos de inclusión son necesarios para la compilación. Sin embargo, si desea crear un archivo de etiquetas que incluya etiquetas para definiciones que ocurren dentro de archivos de inclusión, debe establecer HFILES como una lista de archivos de inclusión que contengan dichas definiciones.
INCDIRS
esta macro normalmente será una copia de DEFINCDIRS. Sin embargo, puede especificar un valor diferente en un makefile de hoja o desde la línea de comandos. Esto anulará el valor predeterminado.
INS_BASE
esta macro debe especificarse en el archivo $(DEFLTSROOT)/$(DEFLTSDIR)/Defaults o $(DEFLTSROOT)/$(DEFLTSDIR)/Defaults.$(O_ARCH). Debe contener el nombre de la ruta de la raíz para instalar los objetivos generales del proyecto. Consulte INSDIR.
INS_KBASE
esta macro debe especificarse en el archivo $(DEFLTSROOT)/$(DEFLTSDIR)/Defaults o $(DEFLTSROOT)/$(DEFLTSDIR)/Defaults.$(O_ARCH). Debe contener el nombre de la ruta de la raíz para instalar los módulos del kernel del proyecto. Consulte INSDIR.
INSDIR
esta macro debe especificarse en el makefile de hoja. Debe contener el nombre de la ruta de un directorio relativo a INS_BASE o INS_KBASE. El objetivo se instalará en $(INS_BASE)/$(INSDIR).
INSGRP

INSMODE

INSUSR

Actualmente solo se soporta gmake como valor alternativo para MAKEPROG. Si quieres usar un programa `make` no soportado, debes verificar si soporta las características necesarias para los makefiles. Debes escribir tus propios archivos de reglas para ese programa `make`. Si quieres usar gmake, deberías hacer setenv MAKEPROG gmake antes de iniciar gmake o usar un script de shell que haga este trabajo por ti.

Esta macro contiene el nombre del sufijo de archivo para tablas. No cambie esta macro.
MARCH
esta macro contiene la arquitectura de la máquina para la máquina de destino (por ejemplo, sun3 sun4 ip22 i86pc i586 9000-725 aviion). Se establece en la salida de arch convertida a minúsculas. En sistemas donde M_ARCH no está disponible, se establece en el contenido de K_ARCH.
No cambie esta macro a menos que desee hacer una compilación cruzada.
O_ARCH
esta macro contiene el nombre del sistema operativo convertido a minúsculas. Por lo general, es la salida de: uname -s. Puede contener un nombre modificado si las reglas de compilación para diferentes versiones del sistema operativo difieren (por ejemplo, en SunOS y Solaris, el nombre oficial del sistema operativo en ambos casos es SunOS).
No cambie esta macro.
OARCH
esta macro contiene la arquitectura de objeto que se utiliza para subdirectorios dependientes de la arquitectura. Se establece en: $(PARCH)-$(O_ARCH)-$(C_ARCH).
No cambie esta macro.
OARCHDIR
esta macro contiene la concatenación de OBJ/ y $(OARCH).
No cambie esta macro.
OFILES
esta macro contiene la lista de objetos que son la lista de dependencias para el objetivo. Se construye a partir de la lista de archivos fuente de ensamblador, archivos fuente C, archivos fuente lex y archivos fuente yacc.
No cambie esta macro.
OINCSDIR
esta macro contiene la concatenación de $(SRCROOT)/incs/ y $(OARCH). Es la ubicación donde se colocarán los archivos de inclusión que se crean durante una ejecución de make y están sujetos a uso global.
No cambie esta macro.
OLIBSDIR
esta macro contiene la concatenación de $(SRCROOT)/libs/ y $(OARCH). Es la ubicación donde se colocarán las bibliotecas que se crean durante una ejecución de make.
No cambie esta macro.
OSDEFS
esta macro contiene definiciones específicas del sistema operativo para el preprocesador C.
No cambie esta macro.
OSNAME
el nombre sin modificar del sistema operativo convertido a minúsculas. Véase O_ARCH.
No cambie esta macro.
OSREL
la versión del sistema operativo.
No cambie esta macro.
P_ARCH
esta macro contiene la arquitectura del procesador para la máquina de destino (por ejemplo, mc68020 mc88200 sparc pentium). Se establece en la salida de uname -p convertida a minúsculas. En sistemas donde P_ARCH no está disponible, se establece en el contenido de K_ARCH.
No cambie esta macro.
PARCH
esta macro contiene la arquitectura del procesador para la máquina de destino (por ejemplo, mc68020 mc88200 sparc pentium). Se establece en la salida de uname -p convertida a minúsculas. En sistemas donde P_ARCH no está disponible, se establece en el contenido de K_ARCH.
No cambie esta macro a menos que desee hacer una compilación cruzada.
RULESDIR
el valor de esta macro debe establecerse antes de incluir el archivo de reglas $(SRCROOT)/$(RULESDIR/rules.top. Si desea probar el comportamiento de una versión modificada de los makefiles en RULESDIR, copie una versión en un directorio alternativo, modifique uno o más archivos en él y luego use make con un valor diferente de RULESDIR, que apunte al directorio alternativo.
RUNPATH
se evalúa en sistemas donde se soporta LD_RUN_PATH. Contiene la ruta de búsqueda de bibliotecas predeterminada para objetivos enlazados dinámicamente en tiempo de ejecución. Esta ruta de búsqueda se almacenará dentro del objetivo. Normalmente se establece en el archivo $(DEFLTSROOT)/$(DEFLTSDIR)/Defaults o $(DEFLTSROOT)/$(DEFLTSDIR)/Defaults.$(O_ARCH). Tenga en cuenta que los sistemas más antiguos también utilizarán LD_LIBRARY_PATH para este propósito.
SCRFILE
esta macro debe establecerse en un makefile de hoja para que los scripts de shell definan la fuente de ese archivo de script.
SRCFILE
esta macro debe establecerse en un makefile de hoja para que los archivos localizados definan la fuente de ese archivo.
SRCROOT
esta macro contiene la posición relativa a la raíz del directorio fuente del proyecto. El valor de esta macro debe establecerse antes de incluir el archivo de reglas $(SRCROOT)/$(RULESDIR/rules.top. SRCROOT debe establecerse en ../.. si el makefile de hoja apropiado se encuentra dos niveles de directorio por debajo de la raíz fuente.
SUBARCHDIR
puede establecerse para colocar los archivos objeto y el objetivo en un directorio diferente al habitual. SUBARCHDIR modificará el valor de ARCHDIR. Si desea crear un objetivo que se compile para dbx, puede usar: make COPTX=-g SUBARCHDIR=-dbx.
TARGET
todos los makefiles que no se refieren a objetivos de biblioteca o sub makes / sub dir makes, deben definir TARGET como el nombre del archivo de salida de la operación de enlace final.
TARGETLIB
todos los makefiles que se utilizan para crear bibliotecas deben definir TARGETLIB como la parte central de la biblioteca de destino. Si desea crear, por ejemplo, libfoo, defina TARGETLIB= foo. Esto es necesario para permitir que los sistemas operativos tengan diferentes convenciones de nomenclatura para las bibliotecas. Si está creando una biblioteca no compartida, el ejemplo anterior daría como resultado un nombre de archivo: libfoo.a para el objetivo real.
TARGETMAN
esta macro debe establecerse en un makefile de hoja para las páginas de manual para definir el nombre base de esa página de manual (sin incluir el sufijo).
XMK_FILE
los makefiles que deseen instalar páginas de manual deben establecer XMK_FILE en Makefile.man para evitar tener que instalar un archivo make de desvío. El archivo make que se encuentra en XMK_FILE solo se procesará si make se llama con el objetivo install.

COMIENZO

Para configurar un nuevo proyecto, primero copie los directorios RULES y TEMPLATES y todo su contenido en el directorio raíz del proyecto.

Luego copie un makefile de nivel superior, un archivo Defaults y un archivo Targetdirs.archname en el directorio raíz del proyecto.

Luego cree los siguientes directorios: cmd, lib, include.

Ahora comience a crear directorios de destino, por ejemplo, debajo de cmd y lib. No olvide crear un makefile y un archivo Targetdirs.archname apropiado en cada directorio nodo.

EJEMPLOS

Si desea configurar una copia privada de partes de un proyecto, debe elegir un directorio dentro de su árbol de directorios que se convertirá en el directorio raíz fuente del proyecto sombra. Luego cree enlaces simbólicos llamados RULES y TEMPLATES al directorio raíz real. Si no desea modificar los archivos de inclusión globales, cree también un enlace simbólico al directorio include, de lo contrario, copie el directorio include y su contenido. copie el makefile de nivel superior, el archivo Defaults y el archivo Targetdirs.archname.

Finalmente, copie el subárbol deseado junto con todos los makefiles y los archivos Targetdirs.archname que se encuentran en los directorios por encima de su parte del proyecto que desea tener por separado.

NOTAS

El alcance de este manual se limita al uso de leaf makefiles. Si desea realizar cambios en las reglas de make, consulte makerules(4).

Los makefiles se pueden usar con Sunpro make, Gnu make y smake. Aunque Gnu make funciona en muchas plataformas, no tiene una salida de depuración útil.

Utilice Sunpro make o smake si tiene problemas con un makefile. Ambos, Sunpro make y smake, tienen una opción -D que le permite ver los makefiles después de la primera expansión. Utilice esta opción si duda si su makefile se está expandiendo correctamente y si se incluyen las reglas correctas. También hay una opción -d que proporciona una salida de depuración mientras make se está ejecutando. Si desea más salida, utilice -dd, -ddd y así sucesivamente.

Smake tiene una opción -xM que le muestra la dependencia de inclusión para las reglas de make.
