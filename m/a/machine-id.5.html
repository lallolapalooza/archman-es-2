NOMBRE

machine-id - Archivo de configuración de ID de máquina local

SINOPSIS

/etc/machine-id

DESCRIPCIÓN

El archivo /etc/machine-id contiene el ID de máquina único del sistema local que se establece durante la instalación o el arranque. El ID de máquina es un único ID hexadecimal de 32 caracteres, en minúsculas y terminado en nueva línea. Cuando se decodifica de hexadecimal, esto corresponde a un valor de 16 bytes/128 bits. Este ID no puede ser todo ceros.

El ID de máquina se genera generalmente a partir de una fuente aleatoria durante la instalación del sistema o el primer arranque y se mantiene constante para todos los arranques posteriores. Opcionalmente, para sistemas sin estado, se genera durante la ejecución en las primeras etapas del arranque si es necesario.

El ID de máquina se puede establecer, por ejemplo, al arrancar en red, con el parámetro de línea de comandos del kernel systemd.machine_id= o pasando la opción --machine-id= a systemd. Un ID especificado de esta manera tiene mayor prioridad y se utilizará en lugar del ID almacenado en /etc/machine-id.

El ID de máquina no cambia en función de la configuración local o de red ni cuando se reemplaza el hardware. Debido a esto y a su mayor longitud, es un reemplazo más útil de la llamada gethostid(3) que especifica POSIX.

Este ID de máquina se adhiere al mismo formato y lógica que el ID de máquina de D-Bus.

Este ID identifica de forma única el host. Debe considerarse "confidencial" y no debe exponerse en entornos no confiables, en particular en la red. Si una aplicación necesita un identificador único y estable vinculado a la máquina, no debe utilizar directamente el ID de máquina ni ninguna parte de él. En su lugar, el ID de máquina debe ser hasheado con una función criptográfica de hash con clave, utilizando una clave fija y específica de la aplicación. De esa manera, el ID será adecuadamente único y se derivará de forma constante del ID de máquina, pero no habrá forma de recuperar el ID de máquina original del ID específico de la aplicación. La API sd_id128_get_machine_app_specific(3) proporciona una implementación de dicho algoritmo.

INICIALIZACIÓN

Cada máquina debe tener un ID no vacío en operación normal. El ID de cada máquina debe ser único. Para lograr estos objetivos, /etc/machine-id puede inicializarse de varias maneras.

Para instalaciones normales del sistema operativo, donde se crea una imagen personalizada para una máquina específica, /etc/machine-id debe poblarse durante la instalación.

systemd-machine-id-setup(1) puede ser utilizado por herramientas de instalación para inicializar el ID de máquina en el momento de la instalación, pero /etc/machine-id también puede ser escrito por cualquier otro medio.

Para imágenes de sistema operativo que se crean una vez y se usan en múltiples máquinas, por ejemplo, para contenedores o en la nube, /etc/machine-id debe estar ausente o ser un archivo vacío en la imagen del sistema de archivos genérico (la diferencia entre ambas opciones se describe en "Semántica de primer arranque" más abajo). Se generará un ID durante el arranque y se guardará en este archivo si es posible. Tener un archivo vacío en su lugar es recomendable porque permite que un archivo temporal sea montado sobre el archivo real, en caso de que la imagen se use en modo de solo lectura y cuando /etc se monte en modo de solo lectura en las primeras etapas del arranque. Ver también Construcción Segura de Imágenes[1].

systemd-firstboot(1) puede usarse para inicializar /etc/machine-id en imágenes de sistema montadas (pero no arrancadas).

Cuando una máquina arranca con systemd(1), se establecerá el ID de la máquina. Si se especifican las opciones systemd.machine_id= o --machine-id= (ver la primera sección), se utilizará este valor. De lo contrario, se utilizará el valor en /etc/machine-id. Si este archivo está vacío o falta, systemd intentará usar el ID de máquina de D-Bus de /var/lib/dbus/machine-id, el valor de la opción de línea de comandos del kernel container_uuid, el product_uuid de DMI de KVM o el vm,uuid del devicetree (en sistemas KVM), el uuid del hipervisor Xen y, finalmente, un UUID generado aleatoriamente. systemd.machine_id=firmware puede ser establecido para generar el ID de máquina a partir del firmware.

Después de establecer el ID de máquina, systemd(1) intentará guardarlo en /etc/machine-id. Si falla, intentará montar un archivo temporal sobre /etc/machine-id. Es un error si el sistema de archivos está en modo de solo lectura y no contiene un archivo /etc/machine-id (posiblemente vacío).

systemd-machine-id-commit.service(8) intentará escribir el ID de máquina en el sistema de archivos si /etc/machine-id o /etc/ están en modo de solo lectura durante las primeras etapas del arranque pero se vuelven escribibles más tarde.

SEMÁNTICA DE PRIMER ARRANQUE

/etc/machine-id se utiliza para decidir si un arranque es el primero. Las reglas son las siguientes:

1.El argumento de línea de comandos del kernel systemd.condition_first_boot= puede ser utilizado para anular la lógica de autodetección, ver kernel-command-line(7).
2.De lo contrario, si /etc/machine-id no existe, es un primer arranque. Durante las primeras etapas del arranque, systemd escribirá "uninitialized\n" en este archivo y montará sobre él un archivo temporal que contiene el ID de máquina real. Más tarde (después de alcanzar first-boot-complete.target), el ID de máquina real se escribirá en disco.
3.Si /etc/machine-id contiene la cadena "uninitialized", un arranque también se considera el primer arranque. Se aplica el mismo mecanismo que el anterior.
4.Si /etc/machine-id existe y está vacío, un arranque no se considera el primer arranque. systemd aún así montará sobre él un archivo que contiene el ID de máquina real y más tarde intentará confirmarlo en el disco (si /etc/ es escribible).
5.Si /etc/machine-id ya contiene un ID de máquina válido, no es un primer arranque.

Si según las reglas anteriores se detecta un primer arranque, se ejecutarán las unidades con ConditionFirstBoot=yes y systemd realizará pasos de inicialización adicionales, en particular preconfigurando unidades.

RELACIÓN CON LOS UUID OSF

Tenga en cuenta que el ID de máquina históricamente no es un UUID OSF como se define en la RFC 4122[2], ni un GUID de Microsoft; sin embargo, a partir de systemd v30, los ID de máquina generados recientemente califican como UUIDs Variante 1 Versión 4, según la RFC 4122.

Para mantener la compatibilidad con las instalaciones existentes, una aplicación que requiera un UUID estrictamente compatible con la RFC 4122 debe decodificar el ID de máquina y luego (de forma no reversible) aplicar las siguientes operaciones para convertirlo en un UUID Variante 1 Versión 4 válido según la RFC 4122. Con "id" siendo un array de caracteres sin firmar:

/* Establecer la versión del UUID a 4 --- generación verdaderamente aleatoria */
id[6] = (id[6] & 0x0F) | 0x40;
/* Establecer la variante del UUID a DCE */
id[8] = (id[8] & 0x3F) | 0x80;

(Este código está inspirado en "generate_random_uuid()" de drivers/char/random.c de las fuentes del kernel de Linux).

HISTORIA

El formato simple de archivo de configuración de /etc/machine-id se origina en el archivo /var/lib/dbus/machine-id introducido por D-Bus. De hecho, este último archivo puede ser un enlace simbólico a /etc/machine-id.
