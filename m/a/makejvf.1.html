makejvf(1)

MAKEJVF(1) Manual de Comandos Generales MAKEJVF(1)

NOMBRE

makejvf - Crea un archivo VF japonés a partir de un archivo TFM japonés de TeX

SINOPSIS

makejvf [<opciones>] <archivo TFM de TeX> <TFM de fuente PS>

DESCRIPCIÓN

makejvf es una herramienta para generar un archivo VF japonés a partir de un archivo TFM japonés de TeX (JFM) para usarlo con dvips.

Al procesar textos japoneses, pTeX hace referencia a JFM (min10.tfm, jis.tfm etc.), que incluye definiciones de algunos anchos de caracteres diferentes y espacios/kerning métricos. Para la mayoría de los signos de puntuación y comillas, los anchos de los caracteres se truncan a menos de 1 zw (ancho zenkaku; el ancho de los caracteres Kanji ordinarios), y se insertan espacios/kerning métricos como sustituto.
Por otro lado, en las fuentes PS japonesas, todos los signos de puntuación y comillas tienen los mismos anchos de caracteres que los caracteres Kanji ordinarios. Por esta razón, cuando dvips procesa el DVI resultante, estos caracteres deben desplazarse hacia la izquierda por la cantidad de espacio/kerning insertado.
Para lograr esto, se requieren fuentes virtuales (VF) y archivos TFM de PS; Cuando VF contiene los comandos de desplazamiento de caracteres, el TFM de fuente PS puede tener los anchos exactos de los caracteres de las fuentes PS.
El programa makejvf se puede utilizar para este propósito. Toma como entrada un archivo JFM de pTeX (denominado <archivo TFM de TeX> en SINOPSIS más arriba), y produce un archivo VF correspondiente (con el mismo nombre base que <archivo TFM de TeX>) y un archivo JFM para un archivo TFM de fuente PS (<TFM de fuente PS> arriba).

OPCIONES

-C
Modo condensado ("Cho-tai").
-K <PS-TFM>
Mapea los caracteres Kana (más exactamente, no Kanji) a otro archivo TFM J de fuente PS llamado <PS-TFM>.
-b <entero>
Desplazamiento de la línea base; el entero representa un valor relativo, utilizando la altura del carácter como base de 1000. Cuando se especifica un entero positivo, los caracteres se bajan. Cuando se especifica un entero negativo, los caracteres se suben.
-m
Reemplaza las comillas simples/dobles (', '') con comillas primas simples/dobles (el llamado "minute") en escritura vertical. El reemplazo se realiza manipulando los glifos de prima y doble prima (JIS 0x216C y 0x216D; Unicode U+2032 y U+2033), no al insertar glifos reales diseñados para comillas (Unicode U+301D y U+301E/U+301F).
-a <archivo AFM>
Nombre del archivo AFM de entrada utilizado para el modo Kana-tsume. Esta opción no está soportada.
-k <entero>
Margen de Kana-tsume (espacios más estrechos entre caracteres Kana); el entero representa un valor relativo, utilizando el ancho del carácter como base de 1000. Esta opción debe ir acompañada de la opción -a. Esta opción no está soportada.
-i
Inicia el ID de fuente mapeada desde el número 0 en la salida VF (por defecto, makejvf usa el número 1).
-e
Modo mejorado; el desplazamiento horizontal se determina a partir de la tabla de espacios/kerning del archivo JFM de entrada.
Por defecto, makejvf utiliza el valor codificado como desplazamiento horizontal, que está (mayoritariamente) optimizado para fuentes japonesas. Cuando se habilita el modo mejorado (opción -e), el desplazamiento se determina a partir del archivo TFM (JFM) de pTeX de entrada, lo que probablemente producirá un VF más adecuado para el JFM.
Para la mayoría de los JFM japoneses estándar (como jis.tfm y sus derivados), los VF de salida de ambos modos no tendrán diferencias significativas. Para JFM de chino simplificado/tradicional (como upschrm-h.tfm y uptchrm-h.tfm), el VF de salida del modo mejorado será mejor. Para min10.tfm y sus derivados, el modo mejorado nunca debe habilitarse, ya que la caracterización en min10.tfm no es estándar.
-t <archivo CNF>
Utiliza <archivo CNF> como archivo de configuración.
-O
Omite las entradas en VF para caracteres con métricas por defecto. Esta opción no se permite usar con la opción -t.
-u <Conjunto de caracteres>
Modo UCS. Los conjuntos de caracteres disponibles son: gb (GB = Chino Simplificado), cns (CNS = Chino Tradicional), ks (KS = Coreano), jis (JIS = Japonés), jisq (solo comillas JIS), custom (CHARSET definido por el usuario desde <archivo CNF>; ver la sección FORMATO DEL ARCHIVO DE CONFIGURACIÓN).
Las siguientes opciones son efectivas solo en modo UCS:
-J <PS-TFM>
Mapea comillas simples/dobles a otro TFM de fuente PS codificado en JIS.
-U <PS-TFM>
Mapea comillas simples/dobles a otro TFM de fuente PS codificado en UCS.
-3
Utiliza set3, es decir, habilita el soporte para caracteres no BMP (con modo UCS). Por defecto, makejvf no produce >=U+10000, para reducir el tamaño del archivo y evitar problemas con controladores DVI antiguos. Las versiones recientes de dvipdfmx y otros pueden manejar VF con >=U+10000 (= set3 en lenguaje DVI), por lo tanto, -3 puede ser útil.
-H
Usa Katakana de medio ancho.

EJEMPLO

Si desea usar min10 como Ryumin-Light-H, ejecute

makejvf min10.tfm rml
Esto genera min10.vf y rml.tfm. Coloque estos archivos en un directorio apropiado dentro del árbol TEXMF, y agregue la siguiente línea a psfonts.map.

rml Ryumin-Light-H

FORMATO DEL ARCHIVO DE CONFIGURACIÓN

Con la opción -t, puede proporcionar a makejvf configuraciones personalizadas para generar VF. La sintaxis es:


% línea de comentario
MOVE <código> <derecha> <abajo>


REPLACE <código> <nuevo código>
CHARSET <código>,<código>,<código>..<código>,<código>,
+ <código>,<código>..<código>

Cada línea debe comenzar con un comando y debe estar separada por TAB. Las líneas que comienzan con % son comentarios, y las líneas vacías se ignoran.
El comando MOVE especifica la cantidad de desplazamiento horizontal/vertical para el carácter individual <código>. El comando REPLACE reemplaza el carácter <código> con <nuevo código>. El comando CHARSET establece el conjunto de caracteres personalizado del VF de salida; el carácter + continúa desde la línea anterior.
Un ejemplo de uso se puede encontrar en el proyecto uptex-fonts. Vea el repositorio de GitHub

https://github.com/texjporg/uptex-fonts.

makejvf(1)

makejvf - Create Japanese font information file.

NAME
makejvf - Create Japanese font information file.
SYNOPSIS

makejvf [ OPTION ]... [ INPUT ]...

DESCRIPTION

The makejvf utility creates a Japanese font information file (.jvf) from PostScript Type 1 font files for Japanese.

A .jvf file contains information about the Japanese font, such as its encoding, character set, and metrics. This information is used by TeX programs to correctly handle Japanese characters.

OPTIONS

This command follows the usual GNU command line syntax, with long options starting with two dashes (-). A summary of options is included below.

-h, --help
Show a help message and exit.
-v, --version
Output version information and exit.
EXAMPLE

To create a .jvf file for a Japanese font named myfont.pfb, you would run the following command: 

                    makejvf myfont.pfb

This will create a file named myfont.jvf in the current directory.

CONFIGURATION FILE FORMAT

The .jvf file is a plain text file with the following format: 

                    # Comment lines start with #
                    <FontName> <Encoding> <MaxChar>
                    <CharName> <CodePoint> <Width>
                    ...
  • <FontName>: The name of the font.
  • <Encoding>: The encoding of the font (e.g., JIS, EUC).
  • <MaxChar>: The maximum character code in the font.
  • <CharName>: The name of the character.
  • <CodePoint>: The character code point.
  • <Width>: The width of the character.
