NOMBRE

mausezahn - generador de paquetes rápido y versátil con CLI de Cisco

SINOPSIS

mausezahn { [opciones] "<cadena-argumentos> | <cadena-hexadecimal>" }

DESCRIPCIÓN

mausezahn es un generador de tráfico rápido que te permite enviar casi cualquier paquete posible e imposible. A diferencia de trafgen(8), la configuración de paquetes de mausezahn es a nivel de protocolo en lugar de nivel de bytes, y mausezahn también viene con una interfaz de línea de comandos (CLI) integrada similar a Cisco, lo que lo hace adecuado como caja generadora de tráfico de red en tu laboratorio de red.

Además de los laboratorios de red, también se puede utilizar como herramienta didáctica y para auditorías de seguridad, incluyendo pruebas de penetración y de denegación de servicio (DoS). Como generador de tráfico, mausezahn también es capaz de probar redes multicast IP o redes VoIP. Se pueden alcanzar tasas de paquetes cercanas al límite físico, dependiendo de la plataforma de hardware.

mausezahn soporta dos modos, ''modo directo'' y ''modo interactivo'' multihilo.

El ''modo directo'' te permite crear un paquete directamente en la línea de comandos y cada parámetro del paquete se especifica en la lista de argumentos al llamar a mausezahn.

El ''modo interactivo'' es un modo de configuración multihilo avanzado con su propia interfaz de línea de comandos (CLI). Este modo te permite crear un número arbitrario de tipos de paquetes y flujos en paralelo, cada uno con diferentes parámetros.

El modo interactivo utiliza un framework de protocolo completamente rediseñado y más flexible llamado ''mops'' (sistema de paquetes propio de mausezahn). La apariencia de la CLI es muy similar a la interfaz de línea de comandos de Cisco IOS^tm.

Puedes iniciar el modo interactivo ejecutando mausezahn con el argumento ''-x'' (puede seguir un número de puerto opcional, de lo contrario es 25542). Luego usa telnet(1) para conectarte a esta instancia de mausezahn. Si no se especifica lo contrario, la combinación de inicio de sesión y contraseña por defecto es mz:mz y la contraseña de habilitación es: mops. Esto se puede cambiar en /etc/netsniff-ng/mausezahn.conf.

El modo directo soporta dos esquemas de especificación: el esquema ''raw-layer-2'', donde se puede especificar cada byte que se va a enviar, y el esquema de ''capa superior'', donde se utilizan generadores de paquetes (usando la opción ''-t'').

Para usar el esquema ''raw-layer-2'', simplemente especifica el frame deseado como una secuencia hexadecimal (la ''cadena-hexadecimal''), como por ejemplo:


mausezahn eth0 "00:ab:cd:ef:00 00:00:00:00:00:01 08:00 ca:fe:ba:be"

En este ejemplo, los espacios en blanco dentro de la cadena de bytes son opcionales y separan los campos Ethernet (dirección de destino y origen, campo de tipo y una carga útil corta). Las únicas opciones adicionales soportadas son ''-a'', ''-b'', ''-c'' y ''-p''. La longitud del frame debe ser mayor o igual a 15 bytes.

El esquema de ''capa superior'' se activa usando la opción ''-t <tipo-paquete>''. Esta opción activa un generador de paquetes y, además del ''tipo-paquete'', se puede especificar una ''cadena-argumentos'' opcional. La ''cadena-argumentos'' contiene parámetros específicos del paquete, como flags TCP, números de puerto, etc. (ver sección de ejemplos).

OPCIONES

mausezahn proporciona ayuda integrada específica del contexto. Añade la palabra clave
''help'' después de las opciones de configuración. Las opciones más importantes son:

-x [<puerto>]

Inicia mausezahn en modo interactivo con una CLI similar a Cisco. Usa telnet para iniciar sesión en la instancia local de mausezahn. Si no se ha especificado ningún puerto, se usa el puerto 25542 por defecto.

-6

Especifica el modo IPv6 (IPv4 es el predeterminado).

-l <IP>

Especifica la dirección IP a la que mausezahn debe enlazarse en modo interactivo, por defecto: 0.0.0.0.

-R <PRIO>

Establece la prioridad de los paquetes enviados. Esto configura SO_PRIORITY en el socket a través del cual se envían los paquetes. Los números de prioridad habituales son 0..15, pero el valor también puede ser un ID de clase para fines de clasificación Qdisc. En ese caso, un ID de clase como 1234:5678 se especificaría como 0x12345678.

-v

Modo detallado. La opción -V en mayúscula es aún más detallada.

-S

Modo de simulación, es decir, no poner nada en el cable. Esto se combina típicamente con el modo detallado.

-q

Modo silencioso donde solo se muestran advertencias y errores.

-c <conteo>

Envía el paquete conteo veces (por defecto: 1, infinito: 0).

-d <retraso>

Aplica un retraso entre transmisiones. El valor del retraso se puede especificar en microsegundos (por defecto, no se necesita unidad adicional), o en milisegundos (por ejemplo, 100m o 100msec), o en segundos (por ejemplo, 100s o 100sec). Nota: mops también soporta resolución de retraso en nanosegundos si lo necesitas (ver modo interactivo).

-r

Multiplica el retraso especificado por un valor aleatorio.

-p <longitud>

Rellena el frame bruto hasta la longitud especificada usando bytes cero. Ten en cuenta que para frames de capa 2 brutos la longitud especificada define la longitud total del frame, mientras que para paquetes de capa superior se especifican el número de bytes de relleno adicionales.

-a <mac-origen|palabra-clave>

Usa la dirección MAC de origen especificada con notación hexadecimal como 00:00:aa:bb:cc:dd. Por defecto se usará la dirección MAC de la interfaz. Las palabras clave ''rand'' y ''own'' se refieren a una dirección MAC aleatoria (solo se crean direcciones unicast) y la propia dirección, respectivamente. También puedes usar las palabras clave mencionadas a continuación, aunque las direcciones MAC de origen de tipo broadcast son inválidas oficialmente.

-b <mac-destino|palabra-clave>

Usa la dirección MAC de destino especificada. Por defecto, se envía un broadcast en modo raw-layer-2 o a la dirección MAC de los hosts de destino o de la interfaz gateway en modo normal (IP). Puedes usar las mismas palabras clave mencionadas anteriormente, así como ''bc'' o ''bcast'', ''cisco'' y ''stp''.

-A <ip-origen|rango|rand>

Usa la dirección IP de origen especificada, por defecto es la dirección de la propia interfaz. Opcionalmente, la palabra clave ''rand'' puede usarse de nuevo para una dirección IP de origen aleatoria o se puede especificar un rango, como ''192.168.1.1-192.168.1.100'' o ''10.1.0.0/16''. Además, se puede especificar un nombre DNS para el que mausezahn intentará determinar la dirección IP correspondiente automáticamente.

-B <ip-destino|rango>

Usa la dirección IP de destino especificada (por defecto es broadcast, es decir, 255.255.255.255). Al igual que con la dirección de origen (ver arriba), también puedes especificar un rango o un nombre DNS.

-t <tipo-paquete [ayuda] | ayuda>

Crea el tipo de paquete especificado usando el generador de paquetes integrado. Actualmente, los tipos de paquete soportados son: ''arp'', ''bpdu'', ''ip'', ''udp'', ''tcp'', ''rtp'' y ''dns''. Actualmente, también hay soporte limitado para ''icmp''. Escribe
''-t help'' para verificar qué generadores de paquetes soporta tu versión actual de mausezahn. Además, para cualquier tipo de paquete en particular, por ejemplo ''tcp'', escribe
''mausezahn -t tcp help'' para recibir una ayuda más detallada.

Ayuda específica del contexto.

-T <tipo-paquete>

Haz que esta instancia de mausezahn sea la estación receptora. Actualmente, solo ''rtp'' es una opción aquí y proporciona mediciones precisas de jitter. Para este propósito, inicia otra instancia de mausezahn en la estación emisora y la estación receptora local mostrará estadísticas de jitter. Consulta ''mausezahn -T rtp help'' para obtener ayuda detallada.

-Q <[CoS:]vlan> [, <[CoS:]vlan>, ...]

Especifica la etiqueta VLAN 802.1Q y opcionalmente la Clase de Servicio. Se puede especificar un número arbitrario de etiquetas VLAN (es decir, puedes simular QinQ o incluso QinQinQinQ...). Múltiples etiquetas deben separarse por comas o puntos (por ejemplo, "5:10,20,2:30"). Las etiquetas VLAN no son compatibles con paquetes ARP y BPDU (en cuyo caso podrías especificar el marco completo en hexadecimal usando la interfaz de capa 2 cruda de mausezahn).

-M <etiqueta[:cos[:ttl]][bos]> [, <etiqueta...>]

Especifica una etiqueta MPLS o incluso una pila de etiquetas MPLS. Opcionalmente, para cada etiqueta se pueden especificar los bits experimentales (generalmente la Clase de Servicio, CoS) y el Tiempo de Vida (TTL). Si estás realmente loco puedes establecer y quitar el bit Bottom of Stack (BoS) para cada etiqueta usando la opción ''S'' (establecer) y ''s'' (quitar). Por defecto, el BoS se establece automática y correctamente. Cualquier otra configuración conducirá a marcos inválidos. Ingresa ''-M help'' para obtener instrucciones y ejemplos detallados.

-P <carga-útil-ascii>

Especifica una carga útil de texto plano. Alternativamente, cada tipo de paquete admite una especificación hexadecimal de la carga útil (ver, por ejemplo, ''-t udp help'').

-f <nombre-archivo>

Lee la carga útil ASCII del archivo especificado.

-F <nombre-archivo>

Lee la carga útil hexadecimal del archivo especificado. De hecho, este archivo también debe ser un archivo de texto ASCII, pero debe contener dígitos hexadecimales, por ejemplo, "aa:bb:cc:0f:e6...". También puedes usar espacios como caracteres de separación.

EJEMPLO DE USO

Para ejemplos más completos, consulta las dos siguientes secciones HOWTO.

mausezahn eth0 -c 0 -d 2s -t bpdu vlan=5

Envía marcos BPDU para la VLAN 5, tal como se usa en el tipo PVST+ de STP de Cisco. Por defecto, mausezahn asume que deseas convertirte en el puente raíz.

mausezahn eth0 -c 128000 -a rand -p 64

Realiza un ataque de desbordamiento de tabla CAM.

mausezahn eth0 -c 0 -Q 5,100 -t tcp flags=syn,dp=1-1023 -p 20 -A rand -B 10.100.100.0/24

Realiza un ataque de inundación SYN a otra VLAN utilizando VLAN hopping. Esto solo funciona si estás conectado a la misma VLAN que está configurada como VLAN nativa en el trunk. Asumimos que la VLAN víctima es la VLAN 100 y la VLAN nativa es la VLAN 5. Atacaremos a cada host en la VLAN 100 que utilice un prefijo IP de 10.100.100.0/24, también probaremos todos los puertos entre 1 y 1023 y utilizaremos una dirección IP de origen aleatoria.

mausezahn eth0 -c 0 -d 10msec -B 230.1.1.1 -t udp dp=32000,dscp=46 -P Paquete de prueba de multidifusión

Envía paquetes de multidifusión IP al grupo de multidifusión 230.1.1.1 utilizando una cabecera UDP con puerto de destino 32000 y establece el campo DSCP de IP a EF (46). Envía un marco cada 10 ms.

mausezahn eth0 -Q 6:420 -M 100,200,300:5 -A 172.30.0.0/16 -B target.anynetwork.foo -t udp sp=666,dp=1-65535 -p 1000 -c 10

Envía paquetes UDP al host de destino target.anynetwork.foo utilizando todos los puertos de destino posibles y envía cada paquete con todas las direcciones de origen posibles del rango 172.30.0.0/16; además, utiliza un puerto de origen de 666 y tres etiquetas MPLS, 100, 200 y 300, la externa (300) con campo QoS 5. Envía el marco con una etiqueta VLAN 420 y CoS 6; rellena opcionalmente con 1000 bytes y repite todo 10 veces.

mausezahn -t syslog sev=3 -P El reactor principal alcanzó una temperatura crítica. -A 192.168.33.42 -B 10.1.1.9 -c 6 -d 10s

Envía seis mensajes syslog falsificados con severidad 3 a un servidor Syslog 10.1.1.9; utiliza una dirección IP de origen falsificada 192.168.33.42 y deja que mausezahn decida qué interfaz local usar. Usa un retardo entre paquetes de 10 segundos.

mausezahn -t tcp flags=syn|urg|rst, sp=145, dp=145, win=0, s=0-4294967295, ds=1500, urg=666 -a bcast -b bcast -A bcast -B 10.1.1.6 -p 5

Envía un paquete TCP inválido con solo una carga útil de 5 bytes como broadcast de capa 2 y también utiliza la dirección MAC de broadcast como dirección de origen. El destino debe ser 10.1.1.6 pero utiliza una dirección de origen de broadcast. El puerto de origen y destino debe ser 145 y el tamaño de la ventana 0. Establece las banderas TCP SYN, URG y RST simultáneamente y barre todo el espacio de números de secuencia TCP con un incremento de 1500. Finalmente, establece el puntero urgente a 666, es decir, apuntando a ningún lugar.

ARCHIVO DE CONFIGURACIÓN

Cuando mausezahn se ejecuta en modo interactivo, busca y lee automáticamente un archivo de configuración en /etc/netsniff-ng/mausezahn.conf para opciones personalizadas si el archivo está disponible, de lo contrario, utiliza los valores predeterminados establecidos en tiempo de compilación.

Archivo de config: /etc/netsniff-ng/mausezahn.conf

El archivo de configuración contiene líneas de la forma:

opción = valor

Opciones compatibles en el archivo de configuración son:

Opción: Descripción:

user Nombre de usuario para autenticación (por defecto: mz)
password Contraseña para autenticación (por defecto: mz)
enable Contraseña para entrar en modo privilegiado (por defecto: mops)
port Puerto de escucha para la CLI (por defecto: 25542)
listen-addr Dirección IP para enlazar la CLI (por defecto: 0.0.0.0)
management-only Establecer interfaz de gestión (no se permite tráfico de datos)
cli-device Interfaz para enlazar la CLI (por defecto: todas) *no implementado completamente*
automops Ruta al archivo automops (contiene datos XML que describen protocolos) *en desarrollo*

Ejemplo:


$ cat /etc/netsniff-ng/mausezahn.conf
user = mzadmin
password = mzpasswd
enable = privilege-mode-passwd
port = 65000
listen-addr = 127.0.0.1

GUÍA RÁPIDA DEL MODO INTERACTIVO

Telnet:

El uso del modo interactivo requiere iniciar mausezahn como servidor:


# mausezahn -x

Ahora puedes conectarte por telnet a ese servidor usando el número de puerto por defecto 25542, pero también se puede especificar un número de puerto arbitrario:


# mausezahn -x 99
mausezahn acepta conexiones telnet entrantes en el puerto 99.
mz: Problemas al abrir el archivo de configuración. Se usarán los valores predeterminados

Ya sea desde otra terminal o desde otro host, intenta conectarte por telnet al servidor mausezahn:


caprica$ telnet galactica 99
Intentando 192.168.0.4...
Conectado a galactica.
Carácter de escape es '^]'.
mausezahn <versión>


Username: mz
Password: mz


mz> enable
Password: mops
mz#

Se recomienda configurar tus propias credenciales de inicio de sesión en /etc/netsniff-ng/mausezahn.conf (ver sección del archivo de configuración).

Básicos:

Dado que has llegado al prompt de mausezahn, intentemos algunos comandos comunes. Puedes usar el carácter '?' en cualquier momento para obtener ayuda contextual. Ten en cuenta que las formas abreviadas de comandos tipo Cisco se aceptan en modo interactivo. Por ejemplo, puedes usar "sh pac" en lugar de "show packet"; otro ejemplo común es usar "config t" en lugar de "configure terminal". Para mayor legibilidad, este manual continuará con los comandos completos.

Primero, probemos el comando show:


mz# show ?

mausezahn mantiene su propia tabla ARP y observa anomalías. Hay una entrada para cada interfaz física (sin embargo, este host solo tiene una):


mz# show arp
Intf Índice Dirección IP Dirección MAC último Ch UCast BCast Info
----------------------------------------------------------------------------------
eth0 [1] D 192.168.0.1 00:09:5b:9a:15:84 23:44:41 1 1 0 0000

La columna Ch nos dice que la dirección MAC anunciada solo ha cambiado una vez (= cuando se aprendió). Las columnas Ucast y BCast nos dicen cuántas veces esta entrada fue anunciada respectivamente vía unicast o broadcast.

Notamos que ya existe un proceso de paquete definido por el sistema; ha sido creado y utilizado solo una vez (durante el inicio) por el servicio ARP de mausezahn. Actualmente, su estado es `config`, lo que significa que el proceso está durmiendo.

mz(config-pkt-2)# ip address source random

En el ejemplo anterior, configuramos un rango de direcciones (se deben direccionar todos los hosts en la red 10.1.1.0). Además, falsificamos nuestra dirección IP de origen. Por supuesto, también podemos agregar una o más etiquetas VLAN y/o MPLS:

DIRECT MODE HOWTO

How to specify hexadecimal digits:

Many arguments allow direct byte input. Bytes are represented as two hexadecimal digits. Multiple bytes must be separated either by spaces, colons, or dashes - whichever you prefer. The following byte strings are equivalent:


"aa:bb cc-dd-ee ff 01 02 03-04 05"
"aa bb cc dd ee ff:01:02:03:04 05"

To begin with, you may want to send an arbitrary fancy (possibly invalid) frame right through your network card:


mausezahn ff:ff:ff:ff:ff:ff:ff:ff:ff:ff:ff:ff:08:00:ca:fe:ba:be


or equivalent but more readable:


mausezahn ff:ff:ff:ff:ff:ff-ff:ff:ff:ff:ff:ff-08:00-ca:fe:ba:be

Basic operations:

All major command line options are listed when you execute mausezahn without arguments. For practical usage, keep the following special (not so widely known) options in mind:


-r Multiplies the specified delay with a random value.
-p <length> Pad the raw frame to specified length (using random bytes).
-P <ASCII Payload> Use the specified ASCII payload.
-f <filename> Read the ASCII payload from a file.
-F <filename> Read the hexadecimal payload from a file.
-S Simulation mode: DOES NOT put anything on the wire.
This is typically combined with one of the verbose
modes (-v or V).

Many options require a keyword or a number but the -t option is an exception since it requires both a packet type (such as ip, udp, dns, etc) and an argument string which is specific for that packet type. Here are some simple examples:


mausezahn -t help
mausezahn -t tcp help
mausezahn eth3 -t udp sp=69,dp=69,p=ca:fe:ba:be

Note: Don't forget that on the CLI the Linux shell (usually the Bash) interprets spaces as a delimiting character. That is, if you are specifying an argument that consists of multiple words with spaces in between, you MUST group these within quotes. For example, instead of


mausezahn eth0 -t udp sp=1,dp=80,p=00:11:22:33


you could either omit the spaces


mausezahn eth0 -t udp sp=1,dp=80,p=00:11:22:33


or, for greater safety, use quotes:


mausezahn eth0 -t udp "sp=1,dp=80,p=00:11:22:33"

In order to monitor what's going on, you can enable the verbose mode using the -v option. The opposite is the quiet mode (-q) which will keep mausezahn absolutely quiet (except for error messages and warnings.)

Don't confuse the payload argument p=... with the padding option -p. The latter is used outside the quotes!

The automatic packet builder:

An important argument is -t which invokes a packet builder. Currently there are packet builders for ARP, BPDU, CDP, IP, partly ICMP, UDP, TCP, RTP, DNS, and SYSLOG. (Additionally you can insert a VLAN tag or a MPLS label stack but this works independently of the packet builder.)

You get context specific help for every packet builder using the help keyword, such as:


mausezahn -t bpdu help
mausezahn -t tcp help

For every packet you may specify an optional payload. This can be done either via hexadecimal notation using the payload (or short p) argument or directly as ASCII text using the -P option:


mausezahn eth0 -t ip -P "Hello World" # ASCII payload
mausezahn eth0 -t ip p=68:65:6c:6c:6f:20:77:6f:72:6c:64 # hex payload
mausezahn eth0 -t ip "proto=89, \
p=68:65:6c:6c:6f:20:77:6f:72:6c:64, \ # same with other
ttl=1" # IP arguments

Note: The raw link access mode only accepts hexadecimal payloads (because you specify everything in hexadecimal here.)

Packet count and delay:

By default only one packet is sent. If you want to send more packets then use the count option -c <count>. When count is zero then mausezahn will send forever. By default, mausezahn sends at maximum speed (and this is really fast ;-)). If you don't want to overwhelm your network devices or have other reasons to send at a slower rate then you might want to specify a delay using the -d <delay> option.

If you only specify a numeric value it is interpreted in microsecond units. Alternatively, for easier use, you might specify units such as seconds, sec, milliseconds, or msec. (You can also abbreviate this with s or m.) Note: Don't use spaces between the value and the unit! Here are typical examples:

Send an infinite number of frames as fast as possible:


mausezahn -c 0 "aa bb cc dd ...."

Send 100,000 frames with a 50 msec interval:


mausezahn -c 100000 -d 50msec "aa bb cc dd ...."

Send an unlimited number of BPDU frames in a 2 second interval:


mausezahn -c 0 -d 2s -t bpdu conf

Note: mausezahn does not support fractional numbers. If you want to specify for example 2.5 seconds then express this in milliseconds (2500 msec).

Source and destination addresses:

As a mnemonic trick keep in mind that all packets run from "A" to "B". You can always specify source and destination MAC addresses using the -a and -b options, respectively. These options also allow keywords such as rand, own, bpdu, cisco, and others.

Similarly, you can specify source and destination IP addresses using the -A and -B options, respectively. These options also support FQDNs (i.e. domain names) and ranges such as 192.168.0.0/24 or 10.0.0.11-10.0.3.22. Additionally, the source address option supports the rand keyword (ideal for "attacks").

Note: When you use the packet builder for IP-based packets (e.g. UDP or TCP) then mausezahn automatically cares about correct MAC and IP addresses (i.e. it performs ARP, DHCP, and DNS for you). But when you specify at least a single link-layer address (or any other L2 option such as a VLAN tag or MPLS header) then ARP is disabled and you must care for the Ethernet destination address for yourself.

mausezahn eth0 "ff:ff:ff:ff:ff:ff ff:ff:ff:ff:ff:ff 00:00 ca:fe:ba:be"

Acceso de enlace directo

El acceso directo de enlace permite el relleno automático usando la opción -p <longitud total del trama>. Esto le permite rellenar un trama L2 crudo a la longitud deseada. Debe especificar la longitud total, y la longitud total del trama debe tener al menos 15 bytes por razones técnicas. Se utilizan cero bytes para el relleno.

`-- ARP:

mausezahn proporciona una interfaz simple para el paquete ARP. Puede especificar el método ARP (solicitud|respuesta) y hasta cuatro argumentos: sendermac, targetmac, senderip, targetip, o de forma abreviada smac, tmac, sip, tip. Por defecto, se envía una respuesta ARP con las direcciones de su propia interfaz como dirección MAC y IP de origen, y una dirección MAC y IP de destino de broadcast. Envíe una solicitud ARP gratuita (como se usa para la detección de direcciones IP duplicadas):


mausezahn eth0 -t arp

Envenenamiento de caché ARP:


mausezahn eth0 -t arp "respuesta, senderip=192.168.0.1, targetmac=00:00:0c:01:02:03, \
targetip=172.16.1.50"


donde por defecto la dirección MAC de origen de su interfaz se usará como sendermac, senderip denota la dirección IP falsificada, targetmac y targetip identifican al receptor. Por defecto, la dirección MAC de origen Ethernet es la MAC de su interfaz y la dirección de destino es la dirección de broadcast. Puede cambiar esto usando las banderas -a y -b.

`-- BPDU:

mausezahn proporciona una interfaz simple para el formato de trama BPDU 802.1D (utilizado para crear el Spanning Tree en redes puenteadas). Por defecto, se envían BPDUs estándar IEEE 802.1D y se asume que su computadora quiere convertirse en el puente raíz (rid=bid). Opcionalmente, la dirección de destino 802.3 puede ser una dirección MAC especificada, broadcast, MAC propia o la dirección MAC de Cisco PVST+. La dirección MAC de destino se puede especificar usando el comando -b que, además de direcciones MAC, acepta palabras clave como bcast, own, pvst o stp (por defecto). PVST+ también es compatible. Simplemente especifique la VLAN para la que desea enviar una BPDU:


mausezahn eth0 -t bpdu "vlan=123, rid=2000"

Consulte mausezahn -t bpdu help para más detalles.

`-- CDP:

mausezahn puede enviar mensajes de Cisco Discovery Protocol (CDP) ya que este protocolo tiene relevancia de seguridad. Por supuesto, son posibles muchos trucos sucios; por ejemplo, se pueden crear TLVs arbitrarios (usando el argumento de carga útil hexadecimal, por ejemplo, p=00:0e:00:07:01:01:90) y si desea estresar la base de datos CDP de algún dispositivo, mausezahn puede enviar cada mensaje CDP con un system-id diferente usando la palabra clave change:


mausezahn -t cdp change -c 0

Algunos routers y switches pueden tener problemas graves ;-) Consulte mausezahn -t cdp help para más detalles.

`-- Etiquetas VLAN 802.1Q:

mausezahn permite el etiquetado VLAN simple para paquetes IP (y otros de capa superior). Simplemente use la opción -Q <[CoS:]VLAN>, como -Q 10 o -Q 3:921. Por defecto, CoS=0. Por ejemplo, envíe un paquete TCP en la VLAN 500 usando CoS=7:


mausezahn eth0 -t tcp -Q 7:500 "dp=80, flags=rst, p=aa:aa:aa"

¡Puedes crear tantas etiquetas VLAN como quieras! Esto es interesante para crear encapsulaciones QinQ o VLAN hopping: Envía un paquete UDP con etiquetas VLAN 100 (externa) y 651 (interna):


mausezahn eth0 -t udp "dp=8888, sp=13442" -P "Mausezahn es genial" -Q 100,651

No sé si esto es útil en alguna parte, pero al menos es posible:


mausezahn eth0 -t udp "dp=8888, sp=13442" -P "Mausezahn es genial" \
-Q 6:5,7:732,5:331,5,6

Mezclarlo con MPLS:


mausezahn eth0 -t udp "dp=8888, sp=13442" -P "Mausezahn es genial" -Q 100,651 -M 314

Cuando esté en modo crudo de Capa 2, debe crear la etiqueta VLAN completamente usted mismo. Por ejemplo, si desea enviar un trama en la VLAN 5 usando CoS 0, simplemente especifique 81:00 como campo de tipo y para los siguientes dos bytes los valores CoS (PCP), DEI (CFI) e ID de VLAN (todos juntos conocidos como TCI):


mausezahn eth0 -b bc -a rand "81:00 00:05 08:00 aa-aa-aa-aa-aa-aa-aa-aa-aa"

`-- Etiquetas MPLS:

mausezahn le permite insertar uno o más encabezados MPLS. Simplemente use la opción -M <label:CoS:TTL:BoS> donde solo la etiqueta es obligatoria. Si especifica un segundo número, se interpretará como los bits experimentales (la CoS usualmente). Si especifica un tercer número, se interpretará como TTL. Por defecto, el TTL se establece en 255. La bandera Bottom of Stack (BoS) se establece automáticamente, de lo contrario el trama sería inválido, pero si lo desea, también puede establecerla o eliminarla usando los argumentos S (establecer) y s (eliminar). Tenga en cuenta que BoS debe ser el último argumento en cada definición de encabezado MPLS. Aquí hay algunos ejemplos:

Usar etiqueta MPLS 214:


mausezahn eth0 -M 214 -t tcp "dp=80" -P "HTTP..." -B myhost.com

Usar tres etiquetas (la 214 es ahora la externa):


mausezahn eth0 -M 9999,51,214 -t tcp "dp=80" -P "HTTP..." -B myhost.com

Usar dos etiquetas, una con CoS=5 y TTL=1, la otra con CoS=7:


mausezahn eth0 -M 100:5:1,500:7 -t tcp "dp=80" -P "HTTP..." -B myhost.com

Eliminar la bandera BoS (lo que resultará en un trama inválido):


mausezahn eth0 -M 214:s -t tcp "dp=80" -P "HTTP..." -B myhost.com

Capa 3-7:

Los paquetes IP, UDP y TCP se pueden rellenar usando la opción -p. Actualmente se utiliza 0x42 como byte de relleno ('la respuesta'). No puede rellenar paquetes DNS (sería inútil de todos modos).

`-- IP:

mausezahn le permite enviar cualquier paquete IP mal formado o correcto. Cada campo en el encabezado IP puede ser manipulado. Las direcciones IP se pueden especificar a través de las opciones -A y -B, que denotan la dirección de origen y destino, respectivamente. También puede especificar un rango de direcciones o un nombre de host (FQDN). Además, la dirección de origen también puede ser aleatoria. Por defecto, la dirección de origen es la IP de su interfaz y la dirección de destino es una dirección de broadcast. Aquí hay algunos ejemplos:

Carga útil ASCII:


mausezahn eth0 -t ip -A rand -B 192.168.1.0/24 -P "hola mundo"

Carga útil hexadecimal:


mausezahn eth0 -t ip -A 10.1.0.1-10.1.255.254 -B 255.255.255.255 p=ca:fe:ba:be

Usará la dirección IP de origen correcta:


mausezahn eth0 -t ip -B www.xyz.com

El byte Tipo de Servicio (ToS) se puede especificar directamente mediante dos dígitos hexadecimales, lo que significa que también puede configurar fácilmente los bits de Notificación de Congestión Explícita (ECN) (LSB 1 y 2), o puede que solo desee especificar un valor DSCP común (bits 3-8) usando un número decimal (0..63):

Paquete enviado con DSCP = Expedited Forwarding (EF):


mausezahn eth0 -t ip dscp=46,ttl=1,proto=1,p=08:00:5a:a2:de:ad:be:af

Si deja la suma de verificación como cero (o no especificada), la suma de verificación correcta se calculará automáticamente. Tenga en cuenta que solo puede usar una suma de verificación incorrecta cuando también especifica al menos un campo L2 manualmente.

`-- UDP:

mausezahn admite la generación fácil de datagramas UDP. Simplemente especifique la dirección de destino (opción -B) y opcionalmente una dirección de origen arbitraria (opción -A) y como argumentos puede especificar los números de puerto usando los argumentos dp (puerto de destino) y sp (puerto de origen) y una carga útil. También puede especificar fácilmente un rango completo de puertos que resultará en el envío de múltiples paquetes. Aquí hay algunos ejemplos:

Enviar paquetes de prueba al rango de puertos RTP:


mausezahn eth0 -B 192.168.1.1 -t udp "dp=16384-32767, \
p=A1:00:CC:00:00:AB:CD:EE:EE:DD:DD:00"

Enviar una solicitud DNS como broadcast local (a menudo un router local responde):


mausezahn eth0 -t udp dp=53,p=c5-2f-01-00-00-01-00-00-00-00-00-00-03-77-77-\
77-03-78-79-7a-03-63-6f-6d-00-00-01-00-01"

Además, puede especificar la longitud y la suma de verificación usando los argumentos len y sum (se establecerán correctamente por defecto). Nota: varios protocolos tienen los mismos argumentos como len (longitud) y sum (suma de verificación). Si especificó un paquete de tipo UDP (a través de -t udp) y desea modificar la longitud IP, use las palabras clave alternativas iplen e ipsum. Tenga en cuenta también que debe especificar al menos un campo L2 que le indica a mausezahn que construya todo sin la ayuda de su kernel (el kernel no permitiría modificar la suma de verificación IP y la longitud IP).

`-- ICMP:

mausezahn actualmente solo admite los siguientes métodos ICMP: PING (solicitud de eco), Redirección (varios tipos), Irreparable (varios tipos). Se admitirán tipos ICMP adicionales en el futuro. Actualmente, tendría que adaptarlos usted mismo, por ejemplo, utilizando el generador de paquetes IP (estableciendo proto=1). Use mausezahn -t icmp help para obtener ayuda sobre las opciones implementadas actualmente.

`-- TCP:

mausezahn le permite adaptar fácilmente cualquier paquete TCP. De manera similar a UDP, puede especificar puertos de origen y destino (rangos) usando los argumentos sp y dp. Luego puede especificar directamente las banderas deseadas usando un "|" como delimitador si desea especificar varias banderas. Por ejemplo, un ataque SYN-Flood contra el host 1.1.1.1 usando una dirección IP de origen aleatoria y utilizando periódicamente los 1023 puertos bien conocidos podría crearse a través de:

-P "¡Buenos días! Esto es un ataque SYN Flood. \
Lamentamos cualquier inconveniente."

NAME

mausezahn - a network traffic analysis and generation tool

SYNOPSIS

mausezahn [ OPTIONS ] [ PACKETS ]

DESCRIPTION

Mausezahn is a versatile tool for analyzing and generating network traffic. It supports a wide range of protocols and can be used for various purposes, including network testing, debugging, and security analysis.

INTERACTIVE MODE HOWTO

To enter interactive mode, run mausezahn without any packet specifications. You can then build and send packets step by step.

DIRECT MODE HOWTO

In direct mode, you specify the packet details directly on the command line using the available options. This is useful for scripting and automated tasks.

NOTE

This manual page provides a brief overview of mausezahn. For detailed information and advanced usage, please refer to the official documentation.
