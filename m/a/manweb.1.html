Documentación de Referencia de Manweb(0) Documentación de Referencia de Manweb(0)

NOMBRE

manweb - examinar la documentación de netpbm (y otras)

SINOPSIS

manweb -help

manweb [-config=archivo_config] [tema [ subtema ... ] ]

EJEMPLOS

manweb

Esto obtiene un índice maestro de la documentación.

manweb netpbm

Esto obtiene la página principal de documentación del paquete Netpbm, con hipervínculos al resto de la documentación.

manweb netpbm pngtopam

Esto va directamente a la página de documentación del programa Pngtopam del paquete Netpbm.

manweb pngtopam

Esto también va directamente a la página de documentación del programa Pngtopam del paquete Netpbm, si eso es lo que se ejecutaría en respuesta a un comando de shell pngtopam (la variable de entorno PATH está involucrada).

manweb 3 fopen

Esto obtiene la página de manual tradicional para la subrutina fopen() usando man.

manweb cp

Esto obtiene el manual de GNU Info para el programa cp, usando info.

DESCRIPCIÓN

manweb muestra documentación de referencia a través de comandos rápidos de shell. Es un reemplazo para el conocido man.

Diferencias Entre Man y Manweb

Las ventajas de manweb sobre man son:


  • Puede acceder a la documentación que está en la web mundial en lugar de
    tener copias instaladas localmente. Esto ahorra trabajo de instalación y
    obtiene documentación más actualizada.


  • La documentación puede estar en HTML, que es más conocido, más útil y más
    expresivo que el formato nroff/troff utilizado por man.


  • manweb organiza sus temas en un árbol para documentación multinivel.
    man está diseñado para un solo nivel de documentación. Por
    ejemplo, puede tener una página de manual para cada comando de shell, pero
    no para los subcomandos de un comando de shell. Y no puede tener
    adecuadamente páginas de manual para los miembros de múltiples bibliotecas
    de subrutinas.


  • La documentación puede estar hipervinculada.

No es necesario involucrar servidores web; la documentación puede estar en archivos locales. No es necesario involucrar gráficos; el navegador lynx funciona bien en el mismo tipo de terminales en los que funciona man.

manweb encuentra la documentación que especifica y llama a un navegador web de su elección para mostrarla. La documentación que manweb encuentra puede ser un archivo HTML en su sistema, en cuyo caso, manweb le da una URL file: a su navegador, o una URL explícita. Esa URL explícita podría ser una URL http: que se refiere a un archivo HTML en un servidor web en algún lugar, o cualquier otra cosa que su navegador entienda.

Si manweb no encuentra ni un archivo HTML ni una URL, pero sus parámetros parecen poder significar algo para man, manweb llama a man. Por lo tanto, puede usar un solo comando para acceder a la gran cantidad de páginas de manual tradicionales, más cualquier documentación más nueva de manweb. Puede hacer que "man" sea un alias de shell de "manweb".

manweb también encuentra documentación de Info. Busca el tema que especifica como un tema de Info después de buscar documentación HTML y de URL y antes de ejecutar man. Si manweb encuentra un tema de Info correspondiente, ejecuta el programa info sobre él. Info es el sistema de documentación que el proyecto GNU inventó para, entre otras cosas, reemplazar las páginas de manual tradicionales de Unix. Sin embargo, HTML y la World Wide Web se inventaron poco después, por lo que Info fracasó. Pero todavía hay mucho software de GNU que está documentado como temas de Info.

Cómo Manweb Encuentra Documentación

manweb pasa una URL a un navegador web. Esta sección explica cómo los parámetros de invocación de su manweb se convierten en esa URL.

La búsqueda de manweb comienza en el directorio "web directory". Ese es el valor de la palabra clave webdir en su archivo de configuración de manweb, o el predeterminado /usr/man/web.

Sus parámetros de invocación forman una "cadena de temas". Yendo de izquierda a derecha, el primer parámetro es el tema principal, el segundo es un subtema del tema principal, y así sucesivamente.

Veamos el caso simple donde especifica exactamente un parámetro, un tema principal. Lo llamaremos temaprincipal y veremos 4 formas en las que manweb podría encontrarlo:

  • Si manweb encuentra un archivo llamado temaprincipal.html
    en el directorio web, la URL que manweb pasa al
    navegador es solo una URL file: que especifica ese archivo
    .html.

  • Si no hay archivo .html, pero hay un archivo llamado
    temaprincipal.url, el contenido de la primera línea de
    ese archivo .url es lo que manweb pasa al navegador. No
    interpreta el contenido en absoluto. Si es basura, el navegador se
    atraganta con él.

  • Si no hay ni archivo .html ni .url, pero hay un
    directorio llamado temaprincipal, manweb busca en el
    directorio un archivo llamado index.html. Si hay uno,
    manweb pasa una URL file: que especifica ese archivo
    index.html al navegador. Si no hay
    index.html, manweb usa una URL file: que
    especifica el propio directorio.

  • Si manweb no encuentra la documentación de ninguna de las
    formas anteriores, busca en su ruta de búsqueda de ejecutables (tal como
    se define en su variable de entorno PATH) un programa llamado
    temaprincipal. Si encuentra uno, busca en el directorio
    que contiene el programa un archivo llamado doc.url. Si
    encuentra uno, agrega temaprincipal.html a la
    primera línea del archivo y pasa eso al navegador. A menos que
    la primera línea *no* termine con una barra (slash) — en ese
    caso, manweb pasa la primera línea del archivo sin
    modificar al navegador.

Se vuelve un poco más interesante cuando hay subtemas. Mirando cada uno de los 4 casos anteriores:


  • Donde existe temaprincipal.html, los subtemas son
    inválidos. Recibe un mensaje de advertencia y los subtemas son
    ignorados.


  • Donde no hay archivo .html pero existe temaprincipal.url,
    manweb agrega la cadena de subtemas a la URL que obtiene del
    archivo .url como en el siguiente ejemplo: el archivo .url contiene
    http://acme.com/productxyz/ y los subtemas son
    create y
    database. La URL que manweb pasa al navegador es
    http://acme.com/productxyz/create/database.html.

    manweb no verifica que este tipo de adición tenga algún
    sentido para la URL en cuestión, excepto que si la URL en el
    archivo .url no termina con una barra (/), manweb
    emite una advertencia y no agrega nada (ignora los subtemas).


  • Donde no hay ni archivo .html ni .url, pero hay un directorio
    temaprincipal, manweb entra recursivamente en ese
    directorio y comienza una búsqueda completamente nueva usando el primer
    subtema como tema principal y el resto de los subtemas como subtemas
    de ese.


  • Cuando hay subtemas, lo de PATH no tiene sentido,
    así que manweb no lo hace.

    Si proporciona subtemas, lo de PATH descrito anteriormente para un tema no se aplica.

Si no se encuentra nada, manweb llama a man para intentar que sea él quien lo resuelva. Por lo tanto, un tema que no se encuentra en la web puede aparecer si tiene una página de manual tradicional.

Si manweb no encuentra un tema de ninguna de estas maneras, llama a man. Por lo tanto, puede usar un solo comando para acceder a la gran cantidad de páginas de manual tradicionales, más cualquier documentación más nueva de manweb.

Si sus parámetros parecen ser un nombre de archivo de un solo componente sin un punto (como en "cp"), manweb lo trata como un tema principal. Si parece ser un número seguido de un nombre de archivo (como en "3 fopen"), lo trata como una página de manual tradicional.

CONFIGURACIÓN

Puede especificar un archivo de configuración alternativo con la palabra clave -config=archivo_config. Si no lo hace, manweb busca un archivo llamado .manwebinit en su directorio principal.

El archivo de configuración puede contener las siguientes palabras clave:

webdir=directorio

Este es el directorio en el que manweb busca documentación local en formato HTML (y archivos .url y subdirectorios). El valor predeterminado es /usr/man/web.

browser=comando

Este es el comando que manweb ejecuta para mostrar la documentación. El valor predeterminado es lynx, porque es muy común y funciona bien en las mismas terminales en las que funciona man. Si desea usar su navegador web gráfico favorito, como Firefox o Chrome, este es el lugar para hacerlo. Por ejemplo, si usa Firefox, puede poner:

browser=firefox

O si prefiere usar el navegador web gráfico predeterminado del sistema:

browser=xdg-open

manweb(1)

NAME

manweb - view web-based manual pages

SYNOPSIS

manweb [manweb arguments] [utility] [utility arguments]...

manweb [manweb arguments] -man utility [utility arguments]...

DESCRIPTION

manweb is a frontend to the man(1) command that displays manual pages as web pages. When it invokes man(1) to get the raw manual page, it then uses a web browser to display it.

If no arguments are supplied, manweb displays a web page with a list of all installed utilities, hyperlinked to their respective manual pages.

A common use for manweb is to display the manual page for a utility that is not yet installed on the system, or to display it in a more convenient format.

The web directory

The web pages are stored in a directory structure that mimics that of the normal manual pages. The web pages are typically stored in /usr/man/web. This directory is expected to contain subdirectories such as man1, man2, etc., and each of these subdirectories is expected to contain the web pages for the utilities that belong in that section.

If you give no parameters at all, manweb generates a URL for the web directory itself as described above for subdirectories.

The above is simplified by the assumption of a single web directory. In reality, the webdir keyword in the configuration file can specify a chain of web directories. manweb searches each one in turn, doing all the kinds of searches in each web directory before moving on to the next one.

The Configuration File

The default location of the manweb configuration file is /etc/manweb.conf. But you can override this with the environment variable MANWEB_CONF_FILE, and override that with the -config invocation option.

Lines starting with "#" are comments and are ignored, as are blank lines.

All other lines have the format keyword=value. The keywords defined are:

webdir


A colon-delimited sequence of directories to search for
documentation as described above. If you
don't specify this, the default is /usr/man/web alone.

browser


The file specification manweb of the web browser manweb
is to invoke
to display documentation (except when it uses man to display
a conventional man page).
If the file specification does not include a slash, manweb
searches for the file in the PATH search path.

If you don't specify this, the default is the value of the
BROWSER environment variable, and if that is not set,
lynx.

Example:

# Configuration file for Manweb
webdir=/usr/share/manweb
browser=netscape

Differences Between Man and Manweb

The primary difference between man and manweb is that manweb displays manual pages in a web browser, while man displays them in a terminal.

manweb also has some additional features, such as the ability to search for manual pages by keyword, and to display manual pages in different formats.
