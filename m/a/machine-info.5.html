NOMBRE

machine-info - Archivo de información de la máquina local

SINOPSIS

/etc/machine-info

DESCRIPCIÓN

El archivo /etc/machine-info contiene metadatos de la máquina.

El formato de machine-info es una lista de asignaciones de variables separadas por saltos de línea, compatibles con el shell, ignorando comentarios y líneas vacías. Es posible cargar la configuración desde scripts de shell, sin embargo, más allá de simples asignaciones de variables, no se admiten funcionalidades del shell, lo que permite a las aplicaciones leer el archivo sin implementar un motor de ejecución compatible con shell. Consulte os-release(5) para una descripción detallada del formato.

/etc/machine-info contiene metadatos sobre la máquina que son establecidos por el usuario o administrador. La configuración establecida aquí tiene la máxima precedencia. Cuando no se establece, se pueden determinar valores apropiados automáticamente, basándose en la información del hardware u otros archivos de configuración. Por lo tanto, está perfectamente bien que este archivo no exista.

Puede utilizar hostnamectl(1) para cambiar la configuración de este archivo desde la línea de comandos.

OPCIONES

Los siguientes parámetros de metadatos de la máquina se pueden establecer utilizando /etc/machine-info:

Información de la máquina

PRETTY_HOSTNAME=

Una cadena de identificador de máquina bonita, legible por humanos y en formato UTF-8. Debe contener un nombre como "Portátil de Lennart", útil para presentar al usuario y que no sufre limitaciones de sintaxis de los nombres de dominio de Internet. Si es posible, el nombre de host de Internet configurado en /etc/hostname debe ser similar a este. Por ejemplo: si este valor es "Ordenador de Lennart", un nombre de host de Internet de "ordenador-de-lennart" podría ser una buena opción. Si este parámetro no está establecido, una aplicación debería recurrir al nombre de host de Internet para fines de presentación.

ICON_NAME=

Un icono que identifica esta máquina según la Especificación de Nomenclatura de Iconos XDG[1]. Si este parámetro no está establecido, una aplicación debería recurrir a "computer" o un nombre de icono similar.

CHASSIS=

El tipo de chasis. Actualmente, los siguientes tipos de chasis están definidos: "desktop", "laptop", "convertible", "server", "tablet", "handset", "watch" y "embedded", así como los tipos de chasis especiales "vm" y "container" para sistemas virtualizados que carecen de un chasis físico inmediato.

Tenga en cuenta que la mayoría de los sistemas permiten la detección del tipo de chasis automáticamente (basándose en información del firmware o similar). Esta configuración solo debe usarse para anular una detección errónea o para configurar manualmente el tipo de chasis donde la detección automática no está disponible.

Añadido en la versión 197.

DEPLOYMENT=

Describe el entorno de despliegue del sistema. Se sugiere uno de los siguientes: "development", "integration", "staging", "production".

Añadido en la versión 216.

LOCATION=

Describe la ubicación del sistema si es aplicable y se conoce. Toma una cadena libre y amigable para humanos. Puede ser tan genérica como "Berlín, Alemania" o tan específica como "Rack Izquierdo, 2ª Estantería".

Añadido en la versión 216.

HARDWARE_VENDOR=

Especifica el proveedor del hardware. Si no se especifica, se utilizará el proveedor de hardware establecido en DMI o hwdb(7).

Añadido en la versión 251.

HARDWARE_MODEL=

Especifica el modelo del hardware. Si no se especifica, se utilizará el modelo de hardware establecido en DMI o hwdb(7).

Añadido en la versión 251.

HARDWARE_SKU=

Especifica el SKU (Unidad de Mantenimiento de Stock) del hardware. Si no se especifica, se utilizará el SKU de hardware establecido en DMI.

Añadido en la versión 258.

HARDWARE_VERSION=

Especifica la versión del hardware. Si no se especifica, se utilizará la versión de hardware establecida en DMI.

Añadido en la versión 258.

Campos personalizados

Los proveedores de sistemas operativos y los administradores de systemd pueden extender el formato del archivo e introducir nuevos campos. Es altamente recomendable prefijar los nuevos campos con un nombre específico del SO para evitar conflictos de nombres. Las aplicaciones que lean este archivo deben ignorar los campos desconocidos.

Ejemplo: "_LOCAL_EMERGENCY_CONTACT="usuario@ejemplo.org"".

EJEMPLO

PRETTY_HOSTNAME="Tablet de Lennart"
ICON_NAME=computer-tablet
CHASSIS=tablet
DEPLOYMENT=production
