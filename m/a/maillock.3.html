MAILOCK(3) Manual del programador de Linux MAILOCK(3)

NOMBRE

maillock, mailunlock, touchlock - gestiona archivos de bloqueo de buzón

SINOPSIS

#include <maillock.h>

cc [ flag ... ] archivo ... -llockfile [ libreria ]

int maillock( const char *usuario, int reintentos );
void mailunlock( void );
void touchlock( void );

DESCRIPCIÓN

La función maillock intenta crear un archivo de bloqueo para el buzón del usuario de una manera segura (o resistente) para NFS. El algoritmo se documenta en lockfile_create(3).

El buzón se encuentra típicamente en /var/mail. El nombre del archivo de bloqueo se convierte entonces en /var/mail/NOMBREDEUSUARIO.lock. Si la variable de entorno $MAIL está establecida y termina con el mismo nombre de usuario que el nombre de usuario pasado a maillock(), entonces ese archivo se toma como el buzón a bloquear en su lugar.

No hay una buena manera de saber si un archivo de bloqueo está obsoleto. Por lo tanto, si el archivo de bloqueo tiene más de 5 minutos, será eliminado. Por eso se proporciona la función touchlock: mientras se mantiene el bloqueo, necesita ser actualizado regularmente (cada minuto aproximadamente) llamando a touchlock () .

Finalmente, la función mailunlock elimina el archivo de bloqueo.

VALORES DE RETORNO

maillock devuelve uno de los siguientes códigos de estado:

   #define L_SUCCESS   0    /* Archivo de bloqueo creado                     */
   #define L_NAMELEN   1    /* Nombre del destinatario demasiado largo (> 13 caracteres) */
   #define L_TMPLOCK   2    /* Error al crear archivo de bloqueo temporal          */
   #define L_TMPWRITE  3    /* No se puede escribir el PID en el archivo de bloqueo temporal     */
   #define L_MAXTRYS   4    /* Falló después del número máximo de intentos       */
   #define L_ERROR     5    /* Error desconocido; compruebe errno           */
   #define L_RMSTALE   8    /* Falló al eliminar el archivo de bloqueo obsoleto       */

NOTAS

Estas funciones no son seguras para hilos. Si necesita funciones seguras para hilos, o si necesita bloquear otros archivos tipo buzón que no se encuentran en la ubicación estándar, use lockfile_create(3) en su lugar.

Estas funciones llaman a lockfile_create(3) para hacer el trabajo. Esa función puede iniciar un ejecutable con el grupo establecido para hacer el bloqueo real si el proceso actual no tiene suficientes privilegios.

Existen algunos problemas al vaciar la caché de atributos del kernel si está usando NFS; consulte la página del manual de lockfile_create(3).
