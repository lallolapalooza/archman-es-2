NOMBRE

roff — referencia del lenguaje roff para mandoc

DESCRIPCIÓN

El lenguaje roff es un lenguaje de formato de texto de propósito general. Dado que las implementaciones tradicionales de los lenguajes de formato de manual mdoc(7) y man(7) se basan en él, muchos manuales del mundo real utilizan un pequeño número de solicitudes y secuencias de escape de roff intercaladas con su código mdoc(7) o man(7). Para formatear correctamente dichos manuales, la utilidad mandoc(1) admite un subconjunto de solicitudes y escapes de roff. Aunque esta página del manual enumera todas las solicitudes y secuencias de escape de roff, solo contiene información parcial sobre las solicitudes no admitidas por mandoc(1) y sobre las características del lenguaje que no son relevantes para las páginas del manual. Para manuales completos de roff, consulte la sección VER TAMBIÉN.

Las líneas de entrada que comienzan con el carácter de control ‘.’ se analizan para detectar solicitudes y macros. Dichas líneas se denominan “líneas de solicitud” o “líneas de macro”, respectivamente. Las solicitudes cambian el estado de procesamiento y manipulan el formato; algunas macros también definen la estructura del documento y producen salida formateada. La comilla simple ("'") se acepta como carácter de control alternativo, tratado por mandoc(1) igual que ‘.’

Las líneas que no comienzan con caracteres de control se denominan “líneas de texto”. Proporcionan texto de formato libre para ser impreso; el formato del texto depende del contexto de procesamiento respectivo.

SINTAXIS DEL LENGUAJE

Los documentos roff solo pueden contener caracteres ASCII imprimibles de 7 bits, el carácter de espacio y, en ciertas circunstancias, el carácter de tabulación. El carácter de barra invertida ‘\’ indica el inicio de una secuencia de escape, utilizada por ejemplo para Comentarios y Caracteres Especiales. Para una lista completa de secuencias de escape, consulte la REFERENCIA DE SECUENCIAS DE ESCAPARTE a continuación.

Comentarios

El texto que sigue a una comilla doble escapada ‘\"’, ya sea en una solicitud, macro o línea de texto, se ignora hasta el final de la línea. Una línea de solicitud que comienza con un carácter de control y una secuencia de escape de comentario ‘.\"’ también se ignora. Además, las líneas de solicitud con solo un carácter de control y espacios en blanco finales opcionales se eliminan de la entrada.

Ejemplos:

.\" Esta es una línea de comentario.
.\" La siguiente línea se ignora:
.
.Sh EJEMPLOS \" Esto también es un comentario.
texto de ejemplo \" Y esto también.

Caracteres Especiales

Los caracteres especiales se utilizan para codificar glifos especiales y se renderizan de manera diferente en los distintos medios de salida. Pueden aparecer en líneas de solicitud, macro y texto. Las secuencias comienzan con el carácter de escape ‘\’ seguido de un paréntesis abierto ‘(’ para secuencias de dos caracteres; un corchete abierto ‘[’ para secuencias de n caracteres (terminadas en un corchete cerrado ‘]’); o una secuencia de un solo carácter.

Ejemplos:

\(em
Secuencia de escape de raya em de dos letras.
\e
Secuencia de escape de barra invertida de una letra.

Vea mandoc_char(7) para obtener una lista completa.

Selección de fuente

En los documentos mdoc(7) y man(7), las fuentes generalmente se seleccionan con macros. La secuencia de escape \f y la solicitud ft se pueden usar para cambiar manualmente la fuente, pero esto no se recomienda en los documentos mdoc(7). Tales cambios manuales de fuente son anulados por muchas macros posteriores.

Las siguientes fuentes son compatibles:

Una fuente que es tanto en negrita como en cursiva.

Fuente de ancho fijo en negrita. Igual que B en la salida de terminal.

Fuente de ancho fijo en cursiva. Igual que I en la salida de terminal.

Fuente de ancho fijo regular. Igual que R en la salida de terminal.

Un alias para CR.

Fuente en cursiva.
P
Volver a la fuente anterior. Si una macro causó un cambio de fuente desde la última secuencia de escape \f o solicitud ft, esto vuelve a la fuente anterior al último cambio de fuente en la macro en lugar de a la fuente anterior al último cambio manual de fuente.

Un alias para I.

Ejemplos:

Espacios en blanco

Los espacios en blanco consisten en el carácter de espacio. En las líneas de texto, los espacios en blanco se conservan dentro de una línea. En las líneas de solicitud y macro, los espacios en blanco delimitan argumentos y se descartan.

Los espacios finales sin escapar se eliminan de la entrada de línea de texto a menos que se encuentren en un contexto literal. En general, se desaconsejan los espacios en blanco al final de cualquier línea de entrada por razones de portabilidad. En el raro caso de que se necesite un carácter de espacio al final de una línea de entrada, se puede forzar mediante ‘\ \&’.

Se pueden producir caracteres de espacio literales en la salida utilizando secuencias de escape. En las líneas de macro, también se pueden incluir en los argumentos utilizando comillas; consulte la sección SINTAXIS DE MACROS para obtener más detalles.

Las líneas de texto en blanco, que pueden incluir espacios en blanco, solo están permitidas dentro de contextos literales. Si el primer carácter de una línea de texto es un espacio, esa línea se imprime con una nueva línea inicial.

Anchos de escalado

Muchas solicitudes y macros admiten anchos escalados para sus argumentos. La sintaxis de un ancho escalado es ‘[+-]?[0-9]*.[0-9]*[:unidad:]’, donde un decimal debe ir precedido o seguido de al menos un dígito.

Se aceptan las siguientes unidades de escalado:

c
centímetro
i
pulgada
P
pica (1/6 pulgada)
p
punto (1/72 pulgada)
f
escala 'u' por 65536
v
espacio vertical predeterminado
m
ancho del carácter 'm' (em) renderizado
n
ancho del carácter 'n' (en) renderizado
u
espacio horizontal predeterminado para la terminal
M
mini-em (1/100 em)

Usar algo que no sea 'm', 'n' o 'v' es necesariamente no portátil entre medios de salida. Ver COMPATIBILITY.

Si no se proporciona una unidad de escala, el valor numérico se interpreta según las reglas predeterminadas de 'v' para los espacios verticales y 'u' para los horizontales.

Ejemplos:

.Bl -tag -width 2i
indentación de lista etiquetada de dos pulgadas en mdoc(7)
.HP 2i
indentación de lista etiquetada de dos pulgadas en man(7)
.sp 2v
dos espacios verticales

Espaciado de Frases

Cada frase debe terminar al final de una línea de entrada. Al hacer esto, un formateador podrá aplicar la cantidad adecuada de espaciado después del punto final (sin escapar), signo de exclamación o signo de interrogación seguido de cero o más delimitadores de cierre de frase que no sean de frase ('\)', ']', '\'', '"').

El espaciado adecuado también se conserva de manera inteligente si una frase termina en el límite de una línea de macro.

Si una línea de entrada termina con un punto, exclamación o signo de interrogación que no es el final de una frase, agregue un espacio de ancho cero ('\&').

Ejemplos:

No termine frases a mitad de línea como esta.  En su lugar,
termine una frase como esta.
Una macro terminaría así:
.Xr mandoc 1 .
Una abreviatura al final de una línea de entrada necesita escaparse, p. ej.\&
así.

SINTAXIS DE SOLICITUD

Una línea de solicitud o macro consta de:

  1. el carácter de control '.' o ''' al principio de la línea,
  2. opcionalmente una cantidad arbitraria de espacios en blanco,
  3. el nombre de la solicitud o la macro, que es una palabra de longitud arbitraria, terminada por espacios en blanco,
  4. y cero o más argumentos delimitados por espacios en blanco.

Por lo tanto, las siguientes líneas de solicitud son todas equivalentes:

.ig end
.ig    end
.   ig end

SINTAXIS DE MACRO

Las macros son proporcionadas por los lenguajes mdoc(7) y man(7) y pueden ser definidas por la solicitud de. Cuando se llaman, siguen la misma sintaxis que las solicitudes, excepto que los argumentos de macro pueden ser opcionalmente entrecomillados encerrándolos entre comillas dobles ('"'). El texto entrecomillado, incluso si contiene espacios en blanco o causaría una invocación de macro si no estuviera entrecomillado, siempre se considera texto literal. Dentro del texto entrecomillado, pares de comillas dobles ('""') se resuelven a comillas dobles simples.

Para ser reconocido como el comienzo de un argumento entrecomillado, el carácter de comilla de apertura debe ir precedido por un espacio en blanco. Un argumento entrecomillado se extiende hasta el siguiente carácter de comilla doble que no forma parte de un par, o hasta el final de la línea de entrada, lo que ocurra primero. Se desaconseja omitir el carácter de comilla doble de terminación al final de la línea. Para mayor claridad, si siguen más argumentos en la misma línea de entrada, se recomienda seguir el carácter de comilla doble de terminación con un espacio en blanco; en caso de que el siguiente carácter después del carácter de comilla doble de terminación sea cualquier otra cosa, se considerará el comienzo del siguiente argumento sin entrecomillar.

Tanto en argumentos entrecomillados como sin entrecomillar, los pares de barras invertidas ('\\') se resuelven a barras invertidas simples. En argumentos sin entrecomillar, los espacios en blanco se pueden incluir alternativamente precediéndolos con una barra invertida ('\ '), pero entrecomillar suele ser mejor para la claridad.

Ejemplos:

.Fn strlen "const char *s"
Agrupa los argumentos "const char *s" en un argumento de función. Si se omite, "const", "char" y "*s" se considerarían argumentos separados.
.Op "Fl a"
Considera "Fl a" como texto literal en lugar de una macro de bandera.

ie condición cuerpo
La mitad "si" de una condicional if/else. El resultado de la condicional se empuja a una pila utilizada por invocaciones posteriores de el, que pueden estar separadas por cualquier entrada intermedia (o no existir en absoluto). Su sintaxis es equivalente a if.
if condición cuerpo
Inicia una condicional. Esta solicitud también se puede escribir de la siguiente manera: 
.if condición \{cuerpo
cuerpo ...\}
.if condición \{\
cuerpo ...
.\}

La condición es una expresión booleana. Actualmente, mandoc(1) soporta el siguiente subconjunto de condicionales de roff:

  • Si '!' se antepone a condición, se invierte lógicamente.
  • Si el primer carácter de condición es 'n' (modo nroff) o 'o' (página impar), se evalúa como verdadero, y el cuerpo comienza con el siguiente carácter.
  • Si el primer carácter de condición es 'e' (página par), 't' (modo troff) o 'v' (modo vroff), se evalúa como falso, y el cuerpo comienza con el siguiente carácter.
  • Si el primer carácter de condición es 'c' (carácter disponible), se evalúa como verdadero si el siguiente carácter es un carácter ASCII o una secuencia de escape de carácter válida, o como falso en caso contrario. El cuerpo comienza con el carácter siguiente a ese carácter siguiente.
  • Si el primer carácter de condición es 'd', se evalúa como verdadero si el resto de condición es el nombre de una macro o cadena definida por el usuario existente; de lo contrario, se evalúa como falso.
  • Si el primer carácter de condición es 'r', se evalúa como verdadero si el resto de condición es el nombre de un registro numérico existente; de lo contrario, se evalúa como falso.
  • Si la condición comienza con un paréntesis o con un número entero con signo opcional, se evalúa según las reglas de Expresiones numéricas explicadas a continuación. Se evalúa como verdadero si el resultado es positivo, o como falso si el resultado es cero o negativo.
  • De lo contrario, el primer carácter de condición se considera un delimitador y se evalúa como verdadero si la cadena que se extiende desde su primera a su segunda ocurrencia es igual a la cadena que se extiende desde su segunda a su tercera ocurrencia.
  • Si la condición no se puede analizar, se evalúa como falso.

Si una condicional es falsa, sus hijos no se procesan, pero se interpretan sintácticamente para preservar la integridad del documento de entrada. Por lo tanto,

.if t .ig

descartará el '.ig', lo que puede llevar a resultados interesantes, pero

.if t .if t \{\

continuará interpretando sintácticamente hasta el cierre del bloque de la condicional final. Las subcondicionales, en este caso, heredan obviamente el valor de verdad del padre.

Si la sección cuerpo se inicia con una llave escapada '\{', el alcance continúa hasta el final de la línea de entrada que contiene la secuencia de escape de llave de cierre coincidente '\}'. Si el cuerpo no está entre llaves, el alcance continúa hasta el final de la línea. Si la condición va seguida de un cuerpo en la misma línea, ya sea después de una llave o no, entonces las solicitudes y macros deben comenzar con un carácter de control. Generalmente es más intuitivo, en este caso, escribir

.if condición \{\
.solicitud
.\}

que tener la solicitud o macro a continuación como

.if condición \{.solicitud

El alcance de una condicional siempre se analiza, pero solo se ejecuta si la condicional se evalúa como verdadera.

Tenga en cuenta que el '\}' se convierte en una secuencia de escape de ancho cero si no se pasa como una macro independiente '.\}'. Por ejemplo,

.Fl a \} b

resultará en que '\}' se considere un argumento de la macro 'Fl'.

COMPATIBILIDAD

La implementación del lenguaje roff de mandoc(1) es incompleta. Las principales características no implementadas incluyen:

  • Por razones de seguridad, mandoc(1) nunca lee ni escribe archivos externos, excepto a través de solicitudes so con rutas relativas seguras.
  • No hay separación automática de sílabas, ni ajuste al margen derecho, y soporte muy limitado para centrar; la salida siempre está alineada a la izquierda.
  • Falta el soporte para establecer tabuladores y caracteres de relleno, y el soporte para cambiar manualmente la sangría es limitado.
  • La unidad de escala ‘u’ es la unidad de terminal predeterminada. En los sistemas troff tradicionales, esta unidad cambia según el medio de salida.
  • Las mediciones de ancho se implementan de forma rudimentaria y a menudo producen resultados incorrectos. El soporte para solicitudes y escapes de movimiento explícitos es limitado.
  • No existe el concepto de páginas de salida, no hay soporte para flotantes, dibujo gráfico ni inclusión de imágenes; la salida del terminal es siempre continua.
  • Las solicitudes relacionadas con el color, familias de fuentes, tamaños de fuentes y manipulación de glifos se ignoran. El soporte de fuentes es muy limitado. No se implementa el kerning y no se producen ligaduras.
  • El carácter de control de macro "'" no suprime los saltos de línea de salida.
  • No se implementan derivaciones ni entornos, y el soporte para trampas es muy incompleto.
  • No se soporta el uso de macros dentro del código tbl(7).

La semántica especial del registro numérico nS es una particularidad de los manuales de OpenBSD y no es compatible con otras implementaciones de mdoc(7).

NAME

roff, troff, nroff, groff - roff language and macros

DESCRIPTION

This manual describes the roff language, which is used to format documents. The roff language is a markup language that allows users to control the layout and appearance of text. It is used for creating documents such as manuals, reports, and books.

The roff language consists of a set of requests and macros that can be used to format text. Requests are commands that control the formatting of text, such as setting margins, changing fonts, and inserting page breaks. Macros are predefined sets of requests that can be used to create complex formatting structures, such as tables and figures.

The roff language is processed by a roff formatter, such as troff, nroff, or groff. These formatters take roff source code as input and produce formatted output as output. The output can be in various formats, such as PostScript, PDF, or plain text.

LANGUAGE SYNTAX

roff programs consist of lines of text. Each line can contain zero or more requests, followed by zero or more arguments.

A request is a command that tells the roff formatter to perform a specific action. Requests are typically one or two characters long, followed by a period. For example, the .br request inserts a line break.

An argument is a value that is passed to a request. Arguments can be numbers, strings, or other requests.

Macros are similar to requests, but they are typically longer and more descriptive. Macros are defined using the .de request. For example, the following macro definition defines a macro named HEADING that formats a heading:

.de HEADING
.B
.sp 1
..

This macro definition defines a macro named HEADING that first sets the text to bold using the .B request, then inserts a vertical space of 1 em using the .sp 1 request.

REQUEST SYNTAX

The general syntax for a roff request is:

[.<<tab>>][.<character>...][.<character>][.<tab>][<arguments>]

Requests usually start with a period (.). They can be followed by one or more characters that identify the request. Optional arguments can follow the request, separated by spaces.

MACRO SYNTAX

Macros are defined using the .de request. The syntax is:

.de <macroname>
...
..

Macros are invoked by preceding their name with a period. For example, to invoke the HEADING macro defined earlier:

.HEADING

REQUEST REFERENCE

This section provides a brief overview of some common roff requests.

  • .ad: Adjust the right margin.
  • .b: Set text to bold.
  • .br: Insert a line break.
  • .c: Concatenate lines.
  • .ce: Center text.
  • .de: Define a macro.
  • .di: Divert output to a temporary buffer.
  • .ds: Define a string.
  • .i: Set text to italic.
  • .in: Indent text.
  • .it: Repeat a command.
  • .l: Set line length.
  • .ll: Set line length.
  • .ls: Set line spacing.
  • .na: Do not adjust the right margin.
  • .nf: Do not format text.
  • .nj: Do not adjust hyphenation.
  • .nr: Define a number register.
  • .ns: No-space mode.
  • .pi: Set paragraph indentation.
  • .pl: Set page length.
  • .pm: Set page margin.
  • .ps: Set point size.
  • .r: Set text to roman.
  • .re: Resume output from a diverted buffer.
  • .rh: Set right header.
  • .rm: Remove a macro or string.
  • .rn: Rename a number register.
  • .rs: Resume output from a diverted buffer.
  • .s: Set spacing.
  • .sc: Set sentence continuation.
  • .sk: Skip lines.
  • .sp: Insert vertical space.
  • .ss: Set string substitution.
  • .ta: Set tab stops.
  • .ti: Set temporary indentation.
  • .tl: Set title.
  • .tm: Send message to terminal.
  • .tr: Translate characters.
  • .u: Set text to underlined.
  • .uh: Set underline header.
  • .ul: Underline text.
  • .vs: Set vertical spacing.

ESCAPE SEQUENCE REFERENCE

roff uses escape sequences to represent special characters and formatting commands. Escape sequences begin with a backslash (\) followed by one or more characters.

  • \b: Bold text.
  • \f: Change font.
  • \i: Italic text.
  • \l: Line drawing.
  • \n: Number register.
  • \o: Overstrike characters.
  • \s: Change point size.
  • \t: Tab character.
  • \v: Vertical motion.
  • \w: Width of a string.
  • \x: Escape character.
  • \%: Ignore.
  • \: Literal backslash.

HISTORY

The roff language was originally developed by Joseph F. Ossanna for AT&T UNIX Version 1. He implemented roff in PDP-11 assembly language. Joseph F. Ossanna improved roff and renamed it nroff for AT&T UNIX Version 2. He then ported nroff to C as troff, which Brian W. Kernighan released with AT&T UNIX Version 7. In 1989, James Clark reimplemented troff in C++, naming it groff.
