MARIADB-CHECK(1) Sistema de Base de Datos MariaDB MARIADB-CHECK(1)

NOMBRE

mariadb-check - programa de mantenimiento de tablas (mariadb-check es ahora un enlace simbólico a mariadb-check)

SINOPSIS

mariadb-check [opciones] [nombre_db [nombre_tabla ...]]

DESCRIPCIÓN

El cliente mariadb-check realiza mantenimiento de tablas: comprueba, repara, optimiza o analiza tablas.

Cada tabla se bloquea y, por lo tanto, no está disponible para otras sesiones mientras se está procesando; sin embargo, para las operaciones de verificación, la tabla se bloquea solo con un bloqueo de LECTURA. Las operaciones de mantenimiento de tablas pueden consumir mucho tiempo, en particular para tablas grandes. Si utiliza la opción --databases o --all-databases para procesar todas las tablas en una o más bases de datos, una invocación de mariadb-check podría tardar mucho tiempo. (Esto también se aplica a mariadb-upgrade porque ese programa invoca a mariadb-check para verificar todas las tablas y repararlas si es necesario).

mariadb-check es similar en función a myisamchk, pero funciona de manera diferente. La principal diferencia operativa es que mariadb-check debe usarse cuando el servidor mariadbd se está ejecutando, mientras que myisamchk debe usarse cuando no lo está. El beneficio de usar mariadb-check es que no tiene que detener el servidor para realizar el mantenimiento de tablas.

mariadb-check utiliza las sentencias SQL CHECK TABLE, REPAIR TABLE, ANALYZE TABLE y OPTIMIZE TABLE de una manera conveniente para el usuario. Determina qué sentencias usar para la operación que desea realizar y luego envía las sentencias al servidor para que se ejecuten.

El motor de almacenamiento MyISAM admite las cuatro operaciones de mantenimiento, por lo que mariadb-check puede usarse para realizar cualquiera de ellas en tablas MyISAM. Otros motores de almacenamiento no necesariamente admiten todas las operaciones. En tales casos, se muestra un mensaje de error. Por ejemplo, si test.t es una tabla MEMORY, un intento de verificarla produce este resultado:

shell> mariadb-check test t
test.t
note     : El motor de almacenamiento para la tabla no admite la verificación

Si mariadb-check no puede reparar una tabla, consulte la Base de Conocimiento de MariaDB para estrategias de reparación manual de tablas. Este será el caso, por ejemplo, para las tablas InnoDB, que pueden ser verificadas con CHECK TABLE, pero no reparadas con REPAIR TABLE.

El uso de mariadb-check con tablas particionadas no está soportado.


Precaución

Es mejor hacer una copia de seguridad de una tabla antes de realizar una operación de reparación de tablas; bajo algunas circunstancias, la operación podría causar pérdida de datos. Las causas posibles incluyen, pero no se limitan a, errores del sistema de archivos.

Hay tres formas generales de invocar mariadb-check:

shell> mariadb-check [opciones] nombre_db [nombre_tabla ...]
shell> mariadb-check [opciones] --databases nombre_db ...
shell> mariadb-check [opciones] --all-databases

Si no nombra ninguna tabla después de nombre_db o si usa la opción --databases o --all-databases, se verifican bases de datos enteras.

mariadb-check tiene una característica especial en comparación con otros programas cliente. El comportamiento predeterminado de verificar tablas (--check) se puede cambiar renombrando el binario. Si desea tener una herramienta que repare tablas por defecto, simplemente debe hacer una copia de mariadb-check llamada mariadb-repair, o crear un enlace simbólico a mariadb-check llamado mariadb-repair. Si invoca mariadb-repair, este repara tablas.

Los siguientes nombres pueden usarse para cambiar el comportamiento predeterminado de mariadb-check.

mariadb-repair La opción predeterminada es --repair
mysqlanalyze La opción predeterminada es --analyze
mysqloptimize La opción predeterminada es --optimize

mariadb-check admite las siguientes opciones, que se pueden especificar en la línea de comandos o en los grupos de archivos de opciones [mariadb-check] y [client]. Las opciones -c, -r, -a y -o se excluyen mutuamente.

•--help, -?

Muestra un mensaje de ayuda y sale.

•--all-databases, -A

Comprueba todas las tablas en todas las bases de datos. Esto es lo mismo que usar la opción --databases y nombrar todas las bases de datos en la línea de comandos.

•--all-in-1, -1

En lugar de emitir una sentencia para cada tabla, ejecuta una única sentencia para cada base de datos que nombra todas las tablas de esa base de datos a procesar.

•--analyze, -a

Analiza las tablas.

•--auto-repair

Si una tabla verificada está corrupta, la corrige automáticamente. Cualquier reparación necesaria se realiza después de que todas las tablas hayan sido verificadas.

•--character-sets-dir=ruta

El directorio donde están instalados los conjuntos de caracteres.

•--check, -c

Verifica las tablas en busca de errores. Esta es la operación predeterminada.

•--check-only-changed, -C

Verifica solo las tablas que han cambiado desde la última verificación o que no se han cerrado correctamente.

•--check-upgrade, -g

Invoca CHECK TABLE con la opción FOR UPGRADE para verificar tablas en busca de incompatibilidades con la versión actual del servidor. Esta opción habilita automáticamente las opciones --fix-db-names y --fix-table-names.

•--compress

Comprime toda la información enviada entre el cliente y el servidor si ambos admiten la compresión.

•--databases, -B

Procesa todas las tablas en las bases de datos nombradas. Normalmente, mariadb-check trata el primer argumento de nombre en la línea de comandos como un nombre de base de datos y los nombres siguientes como nombres de tabla. Con esta opción, trata todos los argumentos de nombre como nombres de base de datos.

•--debug[=opciones_debug], -# [opciones_debug]

Escribe un registro de depuración. Una cadena de opciones_debug típica es 'd:t:o,nombre_archivo'. El valor predeterminado es 'd:t:o'.

•--debug-check

Imprime información de depuración cuando el programa sale.

•--debug-info

Imprime información de depuración y estadísticas de uso de memoria y CPU cuando el programa sale.

•--default-auth=nombre

Plugin de autenticación predeterminado del lado del cliente a usar.

•--default-character-set=nombre_conjunto

Usa nombre_conjunto como el conjunto de caracteres predeterminado.

•--defaults-extra-file=archivo

Establece archivo como el archivo para leer las opciones predeterminadas después de que se hayan leído los archivos de opciones globales. Debe darse como primera opción.

•--defaults-file=archivo

Establece archivo como el archivo para leer las opciones predeterminadas, anula los archivos de opciones globales. Debe darse como primera opción.

•--extended, -e

Si está utilizando esta opción para verificar tablas, asegura que son 100% consistentes pero lleva mucho tiempo.

Si está utilizando esta opción para reparar tablas, forzará el uso del método antiguo y lento de reparación con keycache, en lugar de la reparación mucho más rápida por ordenación.

•--fast, -F

Verifica solo las tablas que no se han cerrado correctamente.

•--fix-db-names

Convierte los nombres de bases de datos al formato utilizado desde MySQL 5.1. Solo se ven afectados los nombres de bases de datos que contienen caracteres especiales.

•--fix-table-names

Convierte los nombres de tablas (incluidas las vistas) al formato utilizado desde MySQL 5.1. Solo se ven afectados los nombres de tablas que contienen caracteres especiales.

•--flush,

Cierra cada tabla después de

CHECK.

Esto es útil si no desea que las tablas comprobadas ocupen espacio en las cachés después de la comprobación.

--force, -f

Continúa incluso si ocurre un error SQL.

--host=host_name, -h host_name

Conéctate al servidor MariaDB en el host dado.

--medium-check, -m

Realiza una comprobación más rápida que una operación --extended. Esto solo encuentra el 99.99% de todos los errores, lo que debería ser suficiente en la mayoría de los casos.

--no-defaults

No lea las opciones predeterminadas de ningún archivo de opciones. Esto debe proporcionarse como primer argumento.

--optimize, -o

Optimiza las tablas.

--password[=password], -p[password]

La contraseña a usar al conectarse al servidor. Si usa la forma corta de opción (-p), no puede haber un espacio entre la opción y la contraseña. Si omite el valor de contraseña después de la opción --password o -p en la línea de comandos, mariadb-check le pedirá una.

Especificar una contraseña en la línea de comandos debe considerarse inseguro. Puede usar un archivo de opciones para evitar proporcionar la contraseña en la línea de comandos.

--persistent, -Z

Se utiliza con ANALYZE TABLE para añadir la opción PERSISTENT FOR ALL.

--pipe, -W

En Windows, conéctate al servidor a través de una tubería con nombre. Esta opción solo se aplica si el servidor admite conexiones por tuberías con nombre.

--plugin-dir=name


Directorio para los plugins del lado del cliente.

--port=port_num, -P port_num

El número de puerto TCP/IP a usar para la conexión. Fuerza --protocol=tcp cuando se especifica en la línea de comandos sin otras propiedades de conexión.

--print-defaults

Imprime la lista de argumentos del programa y sale. Esto debe proporcionarse como primer argumento.

--process-tables

Realiza la operación solicitada en las tablas. Predeterminado a activado; usa --skip-process-tables para deshabilitar.

--process-views=val

Realiza la operación solicitada (solo CHECK VIEW o REPAIR VIEW). Los valores posibles son NO, YES (corrige la suma de verificación, si es necesario, añade el campo mariadb-version), UPGRADE_FROM_MYSQL (igual que YES y alterna el algoritmo MERGE<->TEMPTABLE.

--protocol={TCP|SOCKET|PIPE|MEMORY}

El protocolo de conexión a usar para conectarse al servidor. Es útil cuando los otros parámetros de conexión normalmente causarían que se usara un protocolo diferente al que desea.

--quick, -q

Si está utilizando esta opción para comprobar tablas, evita que la comprobación escanee las filas para buscar enlaces incorrectos. Este es el método de comprobación más rápido.

Si está utilizando esta opción para reparar tablas, intenta reparar solo el árbol de índices. Este es el método de reparación más rápido.

--repair, -r

Realiza una reparación que puede arreglar casi todo excepto las claves únicas que no son únicas.

--silent, -s

Modo silencioso. Imprime solo mensajes de error.

--skip-database=db_name

No procesar la base de datos (sensible a mayúsculas y minúsculas) especificada como argumento.

--socket=path, -S path

Para conexiones a localhost, el archivo de socket Unix a usar, o, en Windows, el nombre de la tubería con nombre a usar. Fuerza --protocol=socket cuando se especifica en la línea de comandos sin otras propiedades de conexión; en Windows, fuerza --protocol=pipe.

--ssl

Habilita SSL para la conexión (habilitado automáticamente con otras banderas). Deshabilita con --skip-ssl.

--ssl-ca=name

Archivo CA en formato PEM (consulta la documentación de OpenSSL, implica --ssl).

--ssl-capath=name

Directorio CA (consulta la documentación de OpenSSL, implica --ssl).

--ssl-cert=name

Certificado X509 en formato PEM (consulta la documentación de OpenSSL, implica --ssl).

--ssl-cipher=name

Cifrado SSL a usar (consulta la documentación de OpenSSL, implica --ssl).

--ssl-key=name

Clave X509 en formato PEM (consulta la documentación de OpenSSL, implica --ssl).

--ssl-crl=name

Lista de revocación de certificados (consulta la documentación de OpenSSL, implica --ssl).

--ssl-crlpath=name

Ruta de la lista de revocación de certificados (consulta la documentación de OpenSSL, implica --ssl).

--ssl-verify-server-cert

Verifica el "Common Name" del servidor en su certificado contra el nombre de host utilizado al conectarse. Esta opción está deshabilitada por defecto.

--tables

Anula la opción --databases o -B. Todos los nombres de argumento que siguen a la opción se consideran nombres de tabla.

--use-frm

Para operaciones de reparación en tablas MyISAM, obtén la estructura de la tabla del archivo .frm para que la tabla pueda repararse incluso si la cabecera .MYI está corrupta.

--user=user_name, -u user_name

El nombre de usuario de MariaDB a usar al conectarse al servidor.

--verbose, -v

Modo detallado. Imprime información sobre las diversas etapas de la operación del programa. Usar una opción --verbose te dará más información sobre lo que está haciendo mariadb-check.

Usar dos opciones --verbose también te dará información de conexión.

Usarlo 3 veces imprimirá todos los CHECK, RENAME y ALTER TABLE durante la fase de comprobación.

--version, -V

Muestra información de la versión y sale.

--write-binlog

Esta opción está habilitada por defecto, de modo que las sentencias ANALYZE TABLE, OPTIMIZE TABLE y REPAIR TABLE generadas por mariadb-check se escriben en el log binario. Usa --skip-write-binlog para que NO_WRITE_TO_BINLOG se añada a las sentencias para que no se registren. Usa --skip-write-binlog cuando estas sentencias no deban enviarse a esclavos de replicación o ejecutarse al usar los logs binarios para la recuperación desde una copia de seguridad.
