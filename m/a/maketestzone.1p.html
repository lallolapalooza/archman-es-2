NOMBRE

generaterecords - genera una zona de prueba DNSSEC que puede ser usada para DNSSEC

SINOPSIS

generaterecords -v -d mytestzone.example.com

DESCRIPCIÓN

El script generaterecords genera un archivo de zona, dado un nombre de dominio, que luego es firmado y modificado para invalidar porciones de los datos de maneras particulares. Cada registro generado se nombra apropiadamente según cómo se modifican los datos de seguridad (el registro gooda contendrá un registro A con datos DNSSEC válidos, pero el registro badseca contendrá un registro A donde la firma ha sido modificada para invalidarla).

Los resultados de este proceso pueden luego ser servidos y los validadores seguros de prueba, aplicaciones y otro software pueden ser lanzados contra él para ver si fallan o tienen éxito correctamente bajo las políticas de seguridad DNS que se están implementando.

Después de que los archivos son generados, considera ejecutar donuts sobre ellos para ver cómo los datos han sido manipulados para ser inválidos.

PRE-REQUISITOS

zonesigner del proyecto dnssec-tools software bind 9.3.1 o superior

CÓMO EMPEZAR

Para empezar a crear una nueva zona, necesitarás decirle a zonesigner que cree nuevas claves para todas las nuevas zonas que maketestzone crea. Por lo tanto, la primera ejecución de maketestzone debería ser así:

Primera Vez:
maketestzone -k [OTRAS OPCIONES DESEADAS]

Después de eso, los archivos de zona generados pueden ser cargados y servidos en un servidor de prueba.

Una vez cada 30 días (por defecto a través de zonesigner) el script necesitará ser re-ejecutado para recrear los registros y resignar los datos para que las marcas de fecha de la firma permanezcan válidas (o en algunos casos inválidas).

Cada 30 días:
maketestzone [OTRAS OPCIONES DESEADAS]

EJEMPLOS

Para generar una zona de prueba para example.com con los registros A y AAAA estándar de DNSSEC:

Ejemplo:
maketestzone -d example.com --a-addr 192.168.0.1 --aaaa-addr 2000:0000:0000:0000:0000:0000:0000:0001

Para generar la misma zona y luego ejecutar donuts para la depuración:

Ejemplo:
maketestzone -d example.com -D --a-addr 192.168.0.1 --aaaa-addr 2000:0000:0000:0000:0000:0000:0000:0001

Para generar una zona de prueba para example.com y obtener un archivo de configuración de bind para probar los registros de forma segura:

Ejemplo:
maketestzone -d example.com --bind-config=zone.conf

Para generar una zona de prueba para example.com y obtener un script de prueba para dig:

Ejemplo:
maketestzone -d example.com --sh-test-out=test.sh

NOMBRE

maketestzone - crea un archivo de zona de prueba de DNSSEC

SINOPSIS

 maketestzone [options] file ...

DESCRIPCIÓN

El script maketestzone toma un archivo de zona normal (en formato BIND) y crea un archivo de zona que se puede utilizar para probar una variedad de características de DNSSEC.

Actualmente, maketestzone puede simular:

  • NSEC vs. NSEC3
  • Zonas con o sin ZSK rodadas
  • Zonas con o sin KSK rodadas
  • Zonas con diferentes longitud de clave KSK
  • Zonas con múltiples clave activas
  • Zonas con diferentes longitud de clave ZSK
  • Zonas con diferentes algoritmos de firma

Un archivo de zona de prueba se crea sobre la marcha al leer el archivo de zona de entrada.

PRE-REQUISITOS

Para usar maketestzone se necesita un Perl con los módulos Net::DNS y DNS::SEC.

EMPEZANDO

El uso más básico de maketestzone es simplemente pasar un archivo de zona de entrada como argumento. Por defecto, el script imprimirá la salida al STDOUT.

 maketestzone db.example.com

Esto imprimirá el contenido modificado de db.example.com en la salida estándar. Puede redirigir esto a un archivo para usarlo posteriormente:

 maketestzone db.example.com > db.example.com.test

También puede pasar varios archivos de zona, y todos se procesarán en orden:

 maketestzone db.example.com db.example.net > all_test_zones

Por defecto, maketestzone solo aplica modificaciones que resulten en la creación de NSEC. Ver la sección de OPCIONES para ver cómo activar NSEC3 y otras modificaciones.

OPCIONES

-h
Mostrar un resumen de ayuda (se prefieren indicadores cortos)
--help
Mostrar un resumen de ayuda (se prefieren indicadores largos)
--help-full
Mostrar todas las opciones de ayuda (tanto cortas como largas)
--version
Mostrar el número de versión del script.

AÑADIENDO NUEVA SALIDA

La siguiente sección discute cómo extender la herramienta maketestzone con nuevas modificaciones de salida.

AÑADIENDO INFORMACIÓN DE LEYENDA

Para la salida HTML de la leyenda, el hash %LegendInformation contiene un nombre de clave y una descripción para cada tipo de modificación.

AÑADIENDO NUEVAS DIFERENCIAS DE SUBZONA

El hash %zonesigner_domain_opts enumera argumentos adicionales sobre cómo se llama a zonesigner para varios subdominios. Por lo tanto, puede crear subzonas adicionales con diferentes opciones de zonesigner para probar otros parámetros operativos entre el padre y el hijo. Por ejemplo:

'rollzsk-ns.' . $opts{'d'} => '-rollzsk',

Fuerza a la subzona de prueba rollzsk-ns a rodar su zsk cuando la zona está firmada.

AÑADIENDO NUEVAS MODIFICACIONES DE REGISTROS

Maketestzone se encuentra en sus primeras etapas de desarrollo, pero ya tiene los inicios de un sistema extensible que le permite modificar registros a voluntad basándose en ganchos de regexp => subrutina.

Para agregar una nueva modificación, agregue una nueva palabra clave a las banderas predeterminadas 'p' y opcionalmente 'P' (o agréguela en tiempo de ejecución), y luego agregue una nueva función a la lista de callbacks definidas en el hash %destroyFunctions que se basa en su nueva palabra clave. Cuando el archivo se está analizando y encuentra un registro que coincide con su expresión, se llamará a su función. Se pueden agregar argumentos a la función pasando una referencia de arreglo donde el primer argumento es la subrutina a llamar y los restantes son argumentos adicionales. Las líneas de salida deben imprimirse en el manejador de archivo $fh.

Aquí hay un ejemplo de función que elimina la firma RRSIG del siguiente registro:

sub delete_signature {
    # los primeros 2 argumentos siempre se pasan; el otro estaba en la
    # referencia de array con la que se registró la subrutina.
    my ($name, $type, $expr) = @_;
    Verbose("  deleting signatures of $_[0]");
    # imprime la línea actual
    print $fh $_;
    my $inrec = 0;
    while (<I>) {
      # un nuevo registro de nombre significa que hemos terminado.
      last if /^\w/;
      # estamos en un registro rrsig de varias líneas
      $inrec = 1 if (/$expr\s+$type/);
      # imprime la línea si no estamos en el registro rrsig
      print $fh $_ if (!$inrec);
      # cuando terminamos con la última línea del registro rrsig, marcamos este punto
      $inrec = 0 if (/\)/);
    }
}

Luego se registra dentro de %destroyFunctions. Aquí hay un ejemplo de registro de la función para eliminar la firma en un registro DS:

'^(nosig[-\w]+).*IN\s+NS\s+' => [\&delete_signature, 'DS', 'RRSIG'],
