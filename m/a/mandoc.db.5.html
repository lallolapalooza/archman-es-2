MANDOC.DB(5) Manual de formatos de archivo MANDOC.DB(5)

NOMBRE

mandoc.db — base de datos de páginas del manual

DESCRIPCIÓN

El formato de archivo mandoc.db se utiliza para almacenar información sobre las páginas del manual instaladas para facilitar la búsqueda semántica de manuales. Cada árbol de páginas del manual contiene su propio archivo mandoc.db; véanse ARCHIVOS para ver ejemplos.

Estos archivos de base de datos son generados por makewhatis(8) y utilizados por man(1), apropos(1) y whatis(1).

El formato de archivo utiliza tres tipos de datos:

  • Números enteros con signo de 32 bits en orden de bytes big endian (de red)
  • Cadenas terminadas en NUL
  • Listas de cadenas terminadas en NUL, terminadas por un segundo carácter NUL

Los números están alineados a límites de cuatro bytes; cuando siguen a cadenas o listas de cadenas, se produce un relleno con caracteres NUL adicionales. Algunos números, pero no todos, apuntan a posiciones en el archivo. Estos punteros se miden en bytes, y el primer byte del archivo se considera el byte 0.

Cada archivo consta de:

  • Un número mágico, 0x3a7d0cdb.
  • Un número de versión, actualmente 1.
  • Un puntero a la tabla de macros.
  • Un puntero al número mágico final.
  • La tabla de páginas (longitud variable).
  • La tabla de macros (longitud variable).
  • El número mágico nuevamente, 0x3a7d0cdb.

La tabla de páginas contiene una entrada por cada archivo físico de página del manual, sin importar cuántos enlaces duros y simbólicos pueda tener en el sistema de archivos. La tabla de páginas consta de:

  • El número de páginas en la base de datos.
  • Para cada página:
    • Un puntero a la lista de nombres.
    • Un puntero a la lista de secciones.
    • Un puntero a la lista de arquitecturas o 0 si la página es independiente de la máquina.
    • Un puntero a la cadena de descripción de una línea.
    • Un puntero a la lista de nombres de archivo.
  • Para cada página, la lista de nombres. A cada nombre le precede un solo byte que indica las fuentes del nombre. El significado de los bits es:
    • 0x10: El nombre aparece en un nombre de archivo.
    • 0x08: El nombre aparece en una línea de encabezado, es decir, en una macro .Dt o .TH.
    • 0x04: El nombre es el primero en la línea de título, es decir, aparece en la primera macro .Nm en la sección NAME.
    • 0x02: El nombre aparece en cualquier macro .Nm en la sección NAME.
    • 0x01: El nombre aparece en un bloque .Nm en la sección SYNOPSIS.
  • Para cada página, la lista de secciones. Cada sección se proporciona como una cadena, no como un número.
  • Para cada página dependiente de la arquitectura, la lista de arquitecturas.
  • Para cada página, la cadena de descripción de una línea tomada de la macro .Nd.
  • Para cada página, la lista de nombres de archivo relativos a la raíz del manpath respectivo. Esta lista incluye enlaces duros, enlaces simbólicos y enlaces simulados con solicitudes roff(7) .so. Al primer nombre de archivo le precede un solo byte que tiene la siguiente significación:
    • FORM_SRC = 0x01: El formato del archivo es mdoc(7) o man(7).
    • FORM_CAT = 0x02: La página del manual está preformateada.
  • Cero a tres bytes NUL para relleno.

La tabla de macros consta de:

  • El número de claves de macro diferentes, actualmente 36. El orden de las macros se define en <mansearch.h> y el significado de las claves de macro está documentado en apropos(1).
  • Para cada clave de macro, un puntero a la tabla de macros respectiva.
  • Para cada clave de macro, la tabla de macros (longitud variable).

Cada tabla de macros consta de:

  • El número de entradas en la tabla.
  • Para cada entrada:
    • Un puntero al valor de la clave de macro. Cada valor es una cadena de texto tomada de alguna invocación de macro.
    • Un puntero a la lista de páginas.
  • Para cada entrada, el valor de la clave de macro.
  • Cero a tres bytes NUL para relleno.
  • Para cada entrada, uno o más punteros a páginas en la tabla de páginas, apuntando al puntero a la lista de nombres, seguido del número 0.

ARCHIVOS

/usr/share/man/mandoc.db
La base de datos de páginas del manual para el sistema base.
/usr/X11R6/man/mandoc.db
Lo mismo para el Sistema de Ventanas X(7).
/usr/local/man/mandoc.db
Lo mismo para packages(7).

Un programa para volcar archivos mandoc.db en un formato legible por humanos adecuado para diff(1) se proporciona en el directorio /usr/src/regress/usr.bin/mandoc/db/dbm_dump/.

VER TAMBIÉN

apropos(1), man(1), whatis(1), makewhatis(8)

HISTORIA

Una base de datos de páginas del manual /usr/lib/whatis apareció por primera vez en 2BSD. El formato actual apareció por primera vez en OpenBSD 6.1.

AUTORES

La versión original de makewhatis(8) fue escrita por Bill Joy en 1979. El formato de base de datos actual fue diseñado por Ingo Schwarze <schwarze@openbsd.org> en 2016.
