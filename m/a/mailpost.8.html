NOMBRE

mailpost - Alimentar un mensaje de correo electrónico en un grupo de noticias

SINOPSIS

mailpost [-hn] [-a dirección] [-b base de datos] [-c tiempo de espera] [-d distribución] [-f dirección] [-m lista de correo] [-o comando de salida] [-p puerto] [-r dirección] [-t directorio temporal] [-x encabezado[:encabezado...]] [-z encabezado[:encabezado...]] grupos de noticias

DESCRIPCIÓN

El programa mailpost lee un mensaje de correo electrónico correctamente formateado desde la entrada estándar y lo alimenta a inews para publicarlo en un servidor de noticias. grupos de noticias es una lista de nombres de grupos separados por espacios en blanco a los que se publicará el artículo (se debe especificar al menos un grupo de noticias).

Antes de alimentar el artículo a inews, comprueba que el artículo no se haya visto antes y cambia algunos campos de encabezado (limpia algunos campos de encabezado de direcciones, elimina algunos como X-Complaints-To y X-Trace, y antepone "X-" a los campos de encabezado desconocidos). Los campos de encabezado Received y *-To también se modifican para evitar el spam al gateway (se eliminan el nombre del servidor de noticias o el nombre de dominio establecidos en fromhost, pathhost y domain en inn.conf).

Si el artículo se ha visto antes (mailpost registra el ID del mensaje de cada artículo que maneja), el artículo se descartará con un estado de error distinto de cero. Otros errores harán que el artículo se envíe por correo al administrador de noticias (seleccionado en el momento de la configuración y por defecto "usenet").

Normalmente, mailpost es ejecutado por sendmail(8) a través de una entrada de alias:

local-mail-wreck-bikes: "|<pathbin en inn.conf>/mailpost
    -b /var/spool/mailpost -t /tmp -d local local.bicycles.racing"

Las opciones -b y -t son útiles para cambiar los directorios utilizados por mailpost por defecto. De hecho, aunque se recomienda ejecutar mailpost como el usuario de noticias, a menudo se ejecuta como otro usuario, en particular el usuario de correo. Por lo tanto, debe asegurarse de crear y establecer como escribibles por el usuario con el que se ejecuta mailpost los directorios donde colocar la base de datos y los archivos temporales. Además, mailpost debe ser ejecutable por ese usuario.

En lugar de /var/spool/mailpost, se puede especificar el directorio de spool de correo, o cualquier otro directorio donde el proceso mailpost tenga acceso de escritura.

Una práctica común para hacer gateway de un grupo de noticias a una lista de correo es crear un grupo de noticias moderado (ejecutando, por ejemplo, el comando "ctlinnd newgroup local.bicycles.racing m") y establecer la dirección de moderación para este grupo de noticias en el archivo moderators en pathetc a la dirección de la lista de correo. Si agrega una opción -a en el ejemplo anterior, entonces, por un lado, cuando se envía un mensaje a la lista de correo, se ejecutará mailpost, lo marcará como aprobado y el mensaje llegará directamente al grupo de noticias. Por otro lado, cuando se publica un mensaje en el grupo de noticias, normalmente no tiene un campo de encabezado Approved, por lo que se enviará (por nnrpd) a la dirección de la lista de correo configurada en el archivo moderators, lo que significa que el mensaje llega a la lista de correo y, como cualquier otro mensaje publicado en la lista de correo, será procesado por mailpost, aprobado y finalmente llegará al grupo de noticias.

OPCIONES

-a dirección
Si se utiliza la opción -a, dirección (que suele ser la dirección de correo electrónico del remitente) se añade al artículo como cuerpo de un campo de encabezado Approved. Es útil si uno de los grupos de noticias a los que se debe publicar el artículo está moderado. (Por supuesto, esta opción solo debe añadirse si se supone que debe autoaprobar sus publicaciones).

Asegúrese de que la conexión del lector realizada por inews para publicar el artículo tenga permiso para publicar artículos aprobados (ver la letra "A" en el parámetro access de los bloques de acceso en readers.conf).

-b base de datos
Si se utiliza la opción -b, se define la ubicación de la base de datos persistente utilizada para almacenar los IDs de mensaje de los artículos enviados. Esto es para evitar que los artículos entren en bucle si una puerta de enlace de noticias a correo los devuelve aquí. Esta opción puede ser necesaria si el proceso mailpost no tiene acceso de escritura al directorio de la base de datos de noticias (en particular cuando se ejecuta como usuario de correo). El valor predeterminado es pathdb como se establece en inn.conf.

Asegúrese de que la ubicación especificada exista y sea escribible por el usuario con el que se ejecuta mailpost.

-c tiempo de espera
La opción -c indica un período de tiempo para esperar antes de publicar. Si se reciben mensajes duplicados en este intervalo (por cualquier instancia de mailpost que utilice la misma base de datos), el artículo solo se publica una vez, pero con el campo de encabezado Newsgroups modificado para crosspostear el artículo a todos los grupos indicados. Las unidades para tiempo de espera son segundos; un valor razonable puede ser de decenas a cientos de segundos, o incluso más, dependiendo de cuánto tiempo pueda retrasarse el correo en su sistema.
-d distribución
Si se utiliza la opción -d, el valor proporcionado se añade al artículo como cuerpo del campo de encabezado Distribution.
-f dirección
La opción -f es un sinónimo de la opción -r.
-h
Imprimir información de uso y salir.
-m lista de correo
Si se utiliza la opción -m, el valor proporcionado se añade al artículo en un campo de encabezado List-ID, si dicho campo de encabezado no existe ya.
-n
Si se utiliza la opción -n, no se publica ningún artículo ni se envía ningún correo en caso de error. Todo se escribe en la salida estándar.
-o comando de salida
Especifica el programa al que se debe enviar el artículo resultante procesado por mailpost. Para fines de depuración, se puede usar "-o cat". El valor predeterminado es "inews -S -h".
-p puerto
Especifica el puerto en el que nnrpd está escuchando, utilizado para la publicación de artículos. Si se proporciona, -p se pasa a inews.
-r dirección
Se utiliza una heurística para determinar un valor razonable para el cuerpo del campo de encabezado Path. La opción -r indica qué usar si no se puede determinar ningún otro valor.
-t directorio temporal
Si se utiliza la opción -t, se define la ubicación del directorio a utilizar para almacenar temporalmente los mensajes de error que se envían al administrador de noticias. Esta opción puede ser necesaria si el valor predeterminado se refiere a una ruta que no existe o si el proceso mailpost no tiene acceso de escritura a ella (en particular cuando se ejecuta como usuario de correo). Por defecto, se intentan dos rutas: pathtmp como se establece en inn.conf, y luego /var/tmp si pathtmp no es escribible.

Asegúrese de que la ubicación especificada exista y sea escribible por el usuario con el que se ejecuta mailpost.

-x encabezado[:encabezado...]
Una lista separada por dos puntos de campos de encabezado adicionales que deben tratarse como campos de encabezado conocidos; estos campos de encabezado se pasarán a inews sin anteponerles "X-".

Por defecto, los campos de encabezado conocidos son:

Archive
Archived-At
Comments
Content-*
Date
Distribution
From
Injection-Date
Keywords
List-ID
Message-ID
MIME-*
Organization
References
Return-Path
Sender
Subject
Summary
-z encabezado[:encabezado...]
Una lista separada por dos puntos de campos de encabezado adicionales que deben eliminarse.

Por defecto, los campos de encabezado eliminados son:

X-Complaints-To
X-Trace

ARCHIVOS

ruta_binario/mailpost
El propio script Perl utilizado para alimentar un mensaje de correo electrónico a un grupo de noticias.
ruta_bbdd/mailpost-msgid.dir y ruta_bbdd/mailpost-msgid.pag
Los archivos de base de datos predeterminados que registran los ID de mensaje vistos previamente.
