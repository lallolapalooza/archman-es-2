NOMBRE

math.h — declaraciones matemáticas

SINOPSIS

#include <math.h>

DESCRIPCIÓN

Parte de la funcionalidad descrita en esta página de referencia amplía el estándar ISO C. Las aplicaciones deberán definir la macro de prueba adecuada (consulte el volumen de Interfaces del Sistema de POSIX.1‐2017, Sección 2.2, El Entorno de Compilación) para habilitar la visibilidad de estos símbolos en esta cabecera.

La cabecera <math.h> definirá al menos los siguientes tipos:

float_t
Un tipo de punto flotante real, al menos tan ancho como float.
double_t
Un tipo de punto flotante real, al menos tan ancho como double, y al menos tan ancho como float_t.

Si FLT_EVAL_METHOD es igual a 0, float_t y double_t serán float y double, respectivamente; si FLT_EVAL_METHOD es igual a 1, ambos serán double; si FLT_EVAL_METHOD es igual a 2, ambos serán long double; para otros valores de FLT_EVAL_METHOD, son de lo contrario definidos por la implementación.

La cabecera <math.h> definirá las siguientes macros:

HUGE_VAL
Una expresión constante double positiva, no necesariamente representable como un float. Se utiliza como valor de error devuelto por la biblioteca matemática. HUGE_VAL se evalúa como infinito positivo en sistemas que soportan IEEE Std 754‐1985.
HUGE_VALF
Una expresión constante float positiva. Se utiliza como valor de error devuelto por la biblioteca matemática. HUGE_VALF se evalúa como infinito positivo en sistemas que soportan IEEE Std 754‐1985.
HUGE_VALL
Una expresión constante long double positiva. Se utiliza como valor de error devuelto por la biblioteca matemática. HUGE_VALL se evalúa como infinito positivo en sistemas que soportan IEEE Std 754‐1985.
INFINITY
Una expresión constante de tipo float que representa infinito positivo o sin signo, si está disponible; de lo contrario, una constante positiva de tipo float que se desborda en tiempo de compilación.
NAN
Una expresión constante de tipo float que representa un NaN tranquilo (quiet NaN). Esta macro solo se define si la implementación soporta NaNs tranquilos para el tipo float.

Las siguientes macros se definirán para la clasificación de números. Representan los tipos mutuamente excluyentes de valores de punto flotante. Se expanden a expresiones constantes enteras con valores distintos. Clasificaciones de punto flotante adicionales definidas por la implementación, con definiciones de macro que comienzan con FP_ y una letra mayúscula, también pueden ser especificadas por la implementación.

FP_INFINITE FP_NAN FP_NORMAL FP_SUBNORMAL FP_ZERO

Las siguientes macros opcionales indican si la familia de funciones fma() es rápida en comparación con el código directo:

FP_FAST_FMA FP_FAST_FMAF FP_FAST_FMAL

Si se define, la macro FP_FAST_FMA se expandirá a la constante entera 1 e indicará que la función fma() generalmente se ejecuta aproximadamente tan rápido como, o más rápido que, una multiplicación y una suma de operandos double. Si no se define, la velocidad de ejecución no se especifica. Las otras macros tienen el significado equivalente para las versiones float y long double.

For a finite argument, if the correct value is not representable in the type of the return value, the behavior is implementation-defined. The behavior of each of the functions defined in <math.h> is specified in the System Interfaces volume of POSIX.1‐2017 for all representable values of its input arguments, except where stated otherwise. Each function shall execute as if it were single operation without generating any externally visible exceptional conditions.

The following sections are informative.

APPLICATION USAGE

The FP_CONTRACT pragma can be used to allow (if the state is on) or disallow (if the state is off) the implementation to contract expressions. Each pragma can occur either outside external declarations or preceding all explicit declarations and statements inside a compound statement. When outside external declarations, the pragma takes effect from its occurrence until another FP_CONTRACT pragma is encountered, or until the end of the translation unit. When inside a compound statement, the pragma takes effect from its occurrence until another FP_CONTRACT pragma is encountered (including within a nested compound statement), or until the end of the compound statement; at the end of a compound statement the state for the pragma is restored to its condition just before the compound statement. If this pragma is used in any other context, the behavior is undefined. The default state (on or off) for the pragma is implementation-defined.

Applications should use FLT_MAX as described in the <float.h> header instead of the obsolescent MAXFLOAT.

Note that if FLT_EVAL_METHOD is neither 0 nor 1, then some constants might not compare equal as expected; for example, (double)M_PI == M_PI can fail.

RATIONALE

Before the ISO/IEC 9899:1999 standard, the math library was defined only for the floating type double. All the names formed by appending 'f' or 'l' to a name in <math.h> were reserved to allow for the definition of float and long double libraries; and the ISO/IEC 9899:1999 standard provides for all three versions of math functions.

The functions ecvt(), fcvt(), and gcvt() have been dropped from the ISO C standard since their capability is available through sprintf().

NAME

math.h - mathematics conventions

SYNOPSIS

#include <math.h>

DESCRIPTION

The documentation for the mathematical functions described in this section is provided in the individual manual pages, such as exp(3m), log(3m), sqrt(3m), and so on. The functions described in this section are part of the math library, libm.

The following functions are required:

    acos      acosh     asin      asinh     atan      atan2     atanh
    ceil      cos       cosh      drem      exp       fabs      floor
    fmod      frexp     hypot     ldexp     log       log10     mdexp
    pow       sin       sinh      sqrt      tan       tanh

The following functions are optional:

    .       .       .       .       .       .       .
    .       .       .       .       .       .       .
    .       .       .       .       .       .       .

The optional functions are expected to be provided on systems where floating-point arithmetic is supported.

The following macros are defined:

HUGE_VAL
A positive double-precision floating-point expression representing infinity. If this is not representable, then a very large positive double-precision floating-point number is used.

The following constants are defined:

M_PI
The value of pi.
M_PI_2
The value of pi/2.
M_PI_4
The value of pi/4.
M_SQRT2
The value of the square root of 2.
M_SQRT1_2
The value of 1/sqrt(2).
M_LN2
The value of log_e(2).
M_LN10
The value of log_e(10).
M_E
The value of e.
M_LOG2E
The value of log_2(e).
M_LOG10E
The value of log_10(e).

These constants are provided for convenience, but are not required by the POSIX standard. Their availability may be controlled by defining _USE_MATH_DEFINES before including <math.h>.

APPLICATION USAGE

Applications should include the <math.h> header file when using any of the mathematical functions or constants. It is recommended that applications link with the math library, libm, by specifying -lm on the link line.

RATIONALE

The POSIX standard requires a set of mathematical functions to be available to applications. These functions are part of the standard C math library.

The POSIX standard specifies certain functions as required and others as optional. The optional functions are expected to be provided on systems that support floating-point arithmetic. This allows for implementations that may not have floating-point hardware to omit these functions.

The standard also defines the HUGE_VAL macro, which is used to indicate overflow conditions. The value of HUGE_VAL should be a positive double-precision floating-point expression representing infinity. If infinity is not representable, a very large positive double-precision floating-point number should be used.

Several mathematical constants are also provided for convenience. These constants are not part of the POSIX standard but are commonly available in many implementations. Their availability can be controlled by defining _USE_MATH_DEFINES before including <math.h>.

FUTURE DIRECTIONS

Future versions of the POSIX standard may include additional mathematical functions or constants. The standard is expected to evolve to keep pace with advancements in mathematics and computer science.
