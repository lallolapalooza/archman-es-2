NOMBRE

masscan - Escáner rápido de puertos en Internet

SINOPSIS

masscan <direcciones IP/rangos> -p puertos opciones

DESCRIPCIÓN

masscan es un escáner de puertos a escala de Internet, útil para exploraciones a gran escala de Internet o de redes internas. Mientras que la tasa de transmisión por defecto es de solo 100 paquetes/segundo, opcionalmente puede alcanzar hasta 25 millones de paquetes/segundo, una tasa suficiente para escanear Internet en 3 minutos para un solo puerto.

OPCIONES

  • <ip/rango>: cualquier cosa en la línea de comandos que no tenga el prefijo ´-´ se asume que es una dirección IP o rango. Hay tres formatos válidos. El primero es una dirección IPv4 única como "192.168.0.1". El segundo es un rango como "10.0.0.1-10.0.0.100". El tercero es una dirección CIDR, como "0.0.0.0/0". Se debe especificar al menos un objetivo. Se pueden especificar múltiples objetivos. Esto se puede especificar como múltiples opciones separadas por espacio, o se pueden separar por una coma como una única opción, como por ejemplo 10.0.0.0/8,192.168.0.1.
  • --range <ip/rango>: lo mismo que la especificación del rango de objetivos descrita anteriormente, excepto como un parámetro con nombre en lugar de uno sin nombre.
  • -p <puertos, --ports <puertos>: especifica los puertos a escanear. Se puede especificar un solo puerto, como -p80. Se puede especificar un rango de puertos, como -p 20-25. Se puede especificar una lista de puertos/rangos, como -p80,20-25. También se pueden especificar puertos UDP, como --ports U:161,U:1024-1100.
  • --banners: especifica que se deben capturar banners, como versiones de servidores HTTP, campos de título HTML, etc. Solo se admiten algunos protocolos.
  • --rate <paquetes-por-segundo>: especifica la tasa deseada para la transmisión de paquetes. Pueden ser números muy pequeños, como 0.1 para transmitir paquetes a tasas de uno cada 10 segundos, o números muy grandes como 10000000, que intenta transmitir a 10 millones de paquetes/segundo. En mi experiencia, Windows puede manejar 250 mil paquetes por segundo, y las últimas versiones de Linux pueden manejar 2.5 millones de paquetes por segundo. Se necesita el controlador PF_RING para alcanzar los 25 millones de paquetes/segundo.
  • -c <nombre_archivo>, --conf <nombre_archivo>: lee un archivo de configuración. El formato del archivo de configuración se describe a continuación.
  • --resume <nombre_archivo>: lo mismo que --conf, excepto que algunas opciones se establecen automáticamente, como --append-output. El formato del archivo de configuración se describe a continuación.
  • --echo: no ejecutar, sino volcar la configuración actual a un archivo. Este archivo luego se puede usar con la opción -c. El formato de esta salida se describe a continuación bajo ´ARCHIVO DE CONFIGURACIÓN´.
  • -e <nombre_interfaz>, --adapter <nombre_interfaz>: usa la interfaz de red sin procesar con nombre, como "eth0" o "dna1". Si no se especifica, se utilizará la primera interfaz de red encontrada con una puerta de enlace predeterminada.
  • --adapter-ip <dirección_ip>: envía paquetes usando esta dirección IP. Si no se especifica, se utilizará la primera dirección IP vinculada a la interfaz de red. En lugar de una única dirección IP, se puede especificar un rango. NOTA: El tamaño del rango debe ser una potencia par de 2, como 1, 2, 4, 8, 16, 1024, etc. direcciones.
  • --adapter-port <puerto>: envía paquetes usando este número de puerto como origen. Si no se especifica, se elegirá un puerto aleatorio en el rango 40000 a 60000. Este puerto debe ser filtrado por el firewall del host (como iptables) para evitar que la pila de red del host interfiera con los paquetes entrantes. En lugar de un único puerto, se puede especificar un rango, como 40000-40003. NOTA: El tamaño del rango debe ser una potencia par de 2, como el ejemplo anterior que tiene un total de 4 direcciones.
  • --adapter-mac <dirección_mac>: envía paquetes usando esta como la dirección MAC de origen. Si no se especifica, se utilizará la primera dirección MAC vinculada a la interfaz de red.
  • --router-mac <dirección_mac>: envía paquetes a esta dirección MAC como destino. Si no se especifica, se buscará la dirección de la puerta de enlace de la interfaz de red mediante ARP.
  • --ping: indica que el escaneo debe incluir una solicitud de eco ICMP. Esto se puede incluir con escaneos TCP y UDP.
  • --exclude <ip/rango>: bloquea una dirección IP o rango, impidiendo que sea escaneada. Esto anula cualquier especificación de objetivo, garantizando que esta dirección/rango no será escaneada. Tiene el mismo formato que la especificación normal de objetivo.
  • --excludefile <nombre_archivo>: lee una lista de rangos a excluir, en el mismo formato de objetivo descrito anteriormente. Estos rangos anulan cualquier objetivo, impidiendo que sean escaneados.
  • --append-output: hace que la salida se añada al archivo, en lugar de sobrescribir el archivo.
  • --iflist: lista las interfaces de red disponibles y luego sale.
  • --retries: el número de reintentos de envío, a intervalos de 1 segundo. Tenga en cuenta que dado que este escáner no tiene estado, los reintentos se envían independientemente de si ya se han recibido respuestas.
  • --nmap: imprime ayuda sobre alternativas compatibles con nmap para estas opciones.
  • --pcap-payloads: lee paquetes de un archivo libpcap que contiene paquetes y extrae las cargas útiles UDP, asociando esas cargas útiles con el puerto de destino. Estas cargas útiles se utilizarán al enviar paquetes UDP con el puerto de destino coincidente. Solo se recordará una carga útil por puerto. Similar a --nmap-payloads.
  • --nmap-payloads <nombre_archivo>: lee un archivo en el mismo formato que el archivo nmap nmap-payloads. Contiene cargas útiles UDP, para que podamos enviar paquetes UDP útiles en lugar de vacíos. Similar a --pcap-payloads.
  • --http-user-agent <user-agent>: reemplaza el campo user-agent existente con el valor indicado al realizar solicitudes HTTP.
  • --open-only: informa solo los puertos abiertos, no los puertos cerrados.
  • --pcap <nombre_archivo>: guarda los paquetes recibidos (pero no los paquetes transmitidos) en el archivo con formato libpcap.
  • --packet-trace: imprime un resumen de los paquetes enviados y recibidos. Esto es útil a bajas tasas, como unos pocos paquetes por segundo, pero abrumará la terminal a altas tasas.
  • --pfring: fuerza el uso del controlador PF_RING. El programa saldrá si los controladores PF_RING DNA no están disponibles.
  • --resume-index: el punto en el escaneo en el que se pausó.
  • --resume-count: el número máximo de sondas a enviar antes de salir. Esto es útil con --resume-index para dividir un escaneo y repartirlo entre múltiples instancias, aunque la opción --shards podría ser mejor.
  • --shards <x>/<y>: divide el escaneo entre instancias. x es el ID para este escaneo, mientras que y es el número total de instancias. Por ejemplo, --shards 1/2 le dice a una instancia que envíe cada segundo paquete, comenzando desde el índice 0. Del mismo modo, --shards 2/2 envía cada segundo paquete, pero comenzando desde el índice 1, para que no se superponga con el primer ejemplo.
  • --rotate <tiempo>: rota el archivo de salida, renombrándolo con la marca de tiempo actual y moviéndolo a un directorio separado. El tiempo se especifica en número de segundos, como "3600" para una hora. O, se pueden especificar unidades de tiempo, como "hourly", o "6hours", o "10min". Los tiempos se alinean en un límite par, por lo que si se especifica "daily", el archivo se rotará todos los días a medianoche.
  • --rotate-offset <tiempo>: un desplazamiento en el tiempo. Esto es para acomodar zonas horarias.
  • --rotate-dir <directorio>: al rotar el archivo, esto especifica a qué directorio mover el archivo. Un directorio útil es /var/log/masscan.
  • --seed <entero>: un entero que inicializa el generador de números aleatorios. Usar una semilla diferente hará que los paquetes se envíen en un orden aleatorio diferente. En lugar de un entero, se puede especificar la cadena time, que inicializa usando la marca de tiempo local, generando automáticamente un orden aleatorio diferente de escaneos. Si no se especifica ninguna semilla, time es el valor predeterminado.
  • --regress: ejecuta una prueba de regresión, devuelve ´0´ en caso de éxito y ´1´ en caso de fallo.
  • --ttl <num>: especifica el TTL de los paquetes salientes, por defecto es 255.
  • --wait <segundos>: especifica el número de segundos después de que se complete la transmisión para esperar los paquetes recibidos antes de salir del programa. El valor predeterminado es 10 se

MASS SCAN — Escáner de puertos de red extremadamente rápido

masscan es un escáner de puertos de red extremadamente rápido. Es capaz de escanear todo Internet en unos pocos minutos, encontrando puertos abiertos.

El objetivo de este proyecto es encontrar servidores expuestos en Internet. Una de las tareas más comunes en este campo es la búsqueda de servidores que ejecuten un servicio particular, por ejemplo, servidores web (puerto 80) o servidores SSH (puerto 22). Si bien existen muchas herramientas para hacer esto, como Nmap, escanean Internet a velocidades mucho más lentas.

masscan está diseñado para escanear Internet en minutos. Para hacer esto, utiliza una arquitectura asíncrona, muy similar a la forma en que se implementan los servidores web de alto rendimiento. En lugar de usar un solo hilo para cada conexión, utiliza un único hilo para administrar todas las conexiones y enviarles paquetes.

Una de las principales diferencias entre masscan y otras herramientas de escaneo es su capacidad para escanear todo Internet en un período de tiempo muy corto. Esto es posible debido a su uso de la técnica de "port scanning asíncrono". Esta técnica permite que el escáner envíe un gran número de paquetes de red simultáneamente, sin esperar una respuesta de cada uno antes de enviar el siguiente.

Otra característica importante de masscan es su capacidad para personalizar el rango de direcciones IP y puertos que se van a escanear. Esto permite a los usuarios enfocar sus escaneos en áreas específicas de la red, lo que puede ser útil para diversas tareas de seguridad.

Para obtener más información sobre masscan, puede consultar su página web: https://github.com/robertdavidgraham/masscan.
