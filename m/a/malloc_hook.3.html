__malloc_hook(3) Manual de Funciones de Biblioteca __malloc_hook(3)

NOMBRE

__malloc_hook, __malloc_initialize_hook, __memalign_hook, __free_hook, __realloc_hook, __after_morecore_hook - variables de depuración de malloc (OBSOLETO)

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <malloc.h>
typeof(void *(size_t size, const void *caller))
    *volatile  __malloc_hook;
typeof(void *(void *p, size_t size, const void *caller))
    *volatile  __realloc_hook;
typeof(void *(size_t align, size_t size, const void *caller))
    *volatile  __memalign_hook;
typeof(void *(void *p, const void *caller))
    *volatile  __free_hook;
typeof(void (void))            *__malloc_initialize_hook;
typeof(void (void)) *volatile   __after_mrecore_hook;

DESCRIPCIÓN

La biblioteca C de GNU permite modificar el comportamiento de malloc(3), realloc(3) y free(3) especificando funciones de gancho apropiadas. Puedes usar estos ganchos para ayudar a depurar programas que utilizan asignación dinámica de memoria, por ejemplo.

La variable __malloc_initialize_hook apunta a una función que se llama una vez cuando se inicializa la implementación de malloc. Esta es una variable débil, por lo que puede ser sobrescrita en la aplicación con una definición como la siguiente:


typeof(void (void))  *__malloc_initialize_hook = my_init_hook;

Ahora la función my_init_hook() puede realizar la inicialización de todos los ganchos.

Las cuatro funciones apuntadas por __malloc_hook, __realloc_hook, __memalign_hook, __free_hook tienen un prototipo similar a las funciones malloc(3), realloc(3), memalign(3), free(3), respectivamente, excepto que tienen un argumento final caller que proporciona la dirección del llamador de malloc(3), etc.

La variable __after_morecore_hook apunta a una función que se llama cada vez después de que se haya solicitado más memoria a sbrk(2).

ESTANDARES

GNU.

NOTAS

El uso de estas funciones de gancho no es seguro en programas multihilo y ahora están obsoletas. A partir de glibc 2.24, la variable __malloc_initialize_hook ha sido eliminada de la API, y a partir de glibc 2.34, todas las variables de gancho han sido eliminadas de la API. Los programadores deberían, en su lugar, interceptar las llamadas a las funciones relevantes definiendo y exportando malloc(), free(), realloc() y calloc().

EJEMPLOS

Aquí hay un breve ejemplo de cómo usar estas variables.

#include <stdio.h>
#include <malloc.h>
/* Prototipos para nuestros ganchos */
static void my_init_hook(void);
static void *my_malloc_hook(size_t, const void *);
/* Variables para guardar los ganchos originales */
static typeof(void *(size_t, const void *))  *old_malloc_hook;
/* Sobrescribir el gancho de inicialización de la biblioteca C */
typeof(void (void))  *__malloc_initialize_hook = my_init_hook;
static void
my_init_hook(void)
{
    old_malloc_hook = __malloc_hook;
    __malloc_hook = my_malloc_hook;
}
static void *
my_malloc_hook(size_t size, const void *caller)
{
    void *result;
    /* Restaurar todos los ganchos antiguos */
    __malloc_hook = old_malloc_hook;
    /* Llamar recursivamente */
    result = malloc(size);
    /* Guardar los ganchos subyacentes */
    old_malloc_hook = __malloc_hook;
    /* printf() podría llamar a malloc(), así que protégelo también */
    printf("malloc(%zu) llamado desde %p devuelve %p\n",
            size, caller, result);
    /* Restaurar nuestros propios ganchos */
    __malloc_hook = my_malloc_hook;
    return result;
}
