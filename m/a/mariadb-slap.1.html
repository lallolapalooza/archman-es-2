MARIADB-SLAP(1) Sistema de bases de datos MariaDB MARIADB-SLAP(1)

NOMBRE

mariadb-slap - cliente de emulación de carga (mariadb-slap es ahora un enlace simbólico a mariadb-slap)

SINOPSIS

mariadb-slap [opciones]

DESCRIPCIÓN

mariadb-slap es un programa de diagnóstico diseñado para emular la carga de clientes para un servidor MariaDB e informar el tiempo de cada etapa. Funciona como si varios clientes estuvieran accediendo al servidor.

Invoque mariadb-slap de la siguiente manera:

shell> mariadb-slap [opciones]

Algunas opciones como --create o --query le permiten especificar una cadena que contiene una sentencia SQL o un archivo que contiene sentencias. Si especifica un archivo, por defecto debe contener una sentencia por línea. (Es decir, el delimitador de sentencia implícito es el carácter de nueva línea). Use la opción --delimiter para especificar un delimitador diferente, lo que le permite especificar sentencias que abarcan múltiples líneas o colocar múltiples sentencias en una sola línea. No puede incluir comentarios en un archivo; mariadb-slap no los entiende.

mariadb-slap se ejecuta en tres etapas:

1. Crear el esquema, la tabla y, opcionalmente, cualquier programa almacenado o datos que desee utilizar para la prueba. Esta etapa utiliza una única conexión de cliente.
2. Ejecutar la prueba de carga. Esta etapa puede utilizar múltiples conexiones de cliente.
3. Limpiar (desconectar, eliminar la tabla si se especifica). Esta etapa utiliza una única conexión de cliente.

Ejemplos:

Proporcione sus propias sentencias SQL de creación y consulta, con 50 clientes consultando y 200 selecciones para cada uno:

mariadb-slap --delimiter=";" \
  --create="CREATE TABLE a (b int);INSERT INTO a VALUES (23)" \
  --query="SELECT * FROM a" --concurrency=50 --iterations=200

Permita que mariadb-slap construya la sentencia SQL de consulta con una tabla de dos columnas INT y tres columnas VARCHAR. Use cinco clientes consultando 20 veces cada uno. No cree la tabla ni inserte los datos (es decir, use el esquema y los datos de la prueba anterior):

mariadb-slap --concurrency=5 --iterations=20 \
  --number-int-cols=2 --number-char-cols=3 \
  --auto-generate-sql

Indique al programa que cargue las sentencias SQL de creación, inserción y consulta desde los archivos especificados, donde el archivo create.sql tiene múltiples sentencias de creación de tabla delimitadas por ';' y múltiples sentencias de inserción delimitadas por ';'. El archivo --query tendrá múltiples consultas delimitadas por ';'. Ejecute todas las sentencias de carga, luego ejecute todas las consultas del archivo de consulta con cinco clientes (cinco veces cada uno):

mariadb-slap --concurrency=5 \
  --iterations=5 --query=query.sql --create=create.sql \
  --delimiter=";"

mariadb-slap admite las siguientes opciones, que se pueden especificar en la línea de comandos o en los grupos de archivos de opciones [mariadb-slap] y [client]. mariadb-slap también admite las opciones para procesar archivos de opciones.

•--help, -?

Mostrar un mensaje de ayuda y salir.

•--auto-generate-sql, -a

Generar sentencias SQL automáticamente cuando no se proporcionan en archivos o mediante opciones de línea de comandos.

•--auto-generate-sql-add-autoincrement

Agregar una columna AUTO_INCREMENT a las tablas generadas automáticamente.

•--auto-generate-sql-execute-number=N

Especificar cuántas consultas generar automáticamente.

•--auto-generate-sql-guid-primary

Agregar una clave primaria basada en GUID a las tablas generadas automáticamente.

•--auto-generate-sql-load-type=tipo

Especificar el tipo de carga de prueba. Los valores permitidos son read (escanear tablas), write (insertar en tablas), key (leer claves primarias), update (actualizar claves primarias) o mixed (la mitad inserciones, la mitad selecciones de escaneo). El valor predeterminado es mixed.

•--auto-generate-sql-secondary-indexes=N

Especificar cuántos índices secundarios agregar a las tablas generadas automáticamente. Por defecto, no se agrega ninguno.

•--auto-generate-sql-unique-query-number=N

Cuántas consultas diferentes generar para pruebas automáticas. Por ejemplo, si ejecuta una prueba de clave que realiza 1000 selecciones, puede usar esta opción con un valor de 1000 para ejecutar 1000 consultas únicas, o con un valor de 50 para realizar 50 selecciones diferentes. El valor predeterminado es 10.

•--auto-generate-sql-unique-write-number=N

Cuántas consultas diferentes generar para --auto-generate-sql-write-number. El valor predeterminado es 10.

•--auto-generate-sql-write-number=N

Cuántas inserciones de filas realizar en cada hilo. El valor predeterminado es 100.

•--commit=N

Cuántas sentencias ejecutar antes de confirmar. El valor predeterminado es 0 (no se realizan confirmaciones).

•--compress, -C

Comprimir toda la información enviada entre el cliente y el servidor si ambos admiten la compresión.

•--concurrency=N, -c N

El número de clientes a simular al emitir la sentencia SELECT.

•--create=valor

El archivo o cadena que contiene la sentencia a utilizar para crear la tabla.

•--create-schema=valor

El esquema en el que ejecutar las pruebas.

•--csv[=nombre_archivo]

Generar salida en formato de valores separados por comas. La salida va al archivo con nombre, o a la salida estándar si no se proporciona ningún archivo.

•--debug[=opciones_depuracion], -# [opciones_depuracion]

Escribir un registro de depuración. Una cadena típica de opciones_depuracion es 'd:t:o,nombre_archivo'. El valor predeterminado es '/tmp/mariadb-slap.trace'.

•--debug-check

Imprimir información de depuración cuando el programa salga.

•--debug-info, -T

Imprimir información de depuración y estadísticas de uso de memoria y CPU cuando el programa salga.

•--default-auth=nombre

Plugin del lado del cliente de autenticación predeterminado a usar.

•--defaults-extra-file=nombre_archivo

Establecer nombre_archivo como el archivo del que leer las opciones predeterminadas después de que se hayan leído los archivos de opciones globales. Debe darse como la primera opción.

•--defaults-file=nombre_archivo

Establecer nombre_archivo como el archivo del que leer las opciones predeterminadas, anular los archivos de opciones globales. Debe darse como la primera opción.

•--delimiter=str, -F str

El delimitador a usar en las sentencias SQL proporcionadas en archivos o mediante opciones de línea de comandos.

•--detach=N

Desconectar (cerrar y reabrir) cada conexión después de cada N sentencias. El valor predeterminado es 0 (las conexiones no se desconectan).

•--engine=nombre_motor, -e nombre_motor

Lista separada por comas de los motores de almacenamiento a utilizar para crear la tabla. La prueba se ejecuta para cada motor. También puede especificar una opción para un motor después de dos puntos, por ejemplo memory:max_row=2300.

•--host=nombre_host, -h nombre_host

Conectar al servidor MariaDB en el host dado.

•--init-command=str

Comando SQL para ejecutar al conectarse al servidor MariaDB. Se volverá a ejecutar automáticamente al reconectarse.

•--iterations=N, -i N

El número de veces que se ejecutarán las pruebas.

•--no-defaults

No leer opciones predeterminadas de ningún archivo de opciones. Esto debe darse como primer argumento.
