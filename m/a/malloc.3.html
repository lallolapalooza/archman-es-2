malloc(3)

malloc(3) Manual de Funciones de Biblioteca malloc(3)

NOMBRE

malloc, free, calloc, realloc, reallocarray - asignar y liberar memoria dinámica

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <stdlib.h>
void *malloc(size_t size);
void free(void *_Nullable p);
void *calloc(size_t n, size_t size);
void *realloc(void *_Nullable p, size_t size);
void *reallocarray(void *_Nullable p, size_t n, size_t size);
Requisitos de Macro de Prueba de Funciones para glibc (ver feature_test_macros(7)):

reallocarray():

    Desde glibc 2.29:
        _DEFAULT_SOURCE
    glibc 2.28 y anteriores:
        _GNU_SOURCE

DESCRIPCIÓN

malloc()

La función malloc() asigna size bytes y devuelve un puntero a la memoria asignada. La memoria no está inicializada. Si size es 0, entonces malloc() devuelve un valor de puntero único que más tarde se puede pasar correctamente a free(). (Ver "Comportamiento no portable" para problemas de portabilidad).

free()

La función free() libera el espacio de memoria apuntado por p, que debe haber sido devuelto por una llamada anterior a malloc() o funciones relacionadas. De lo contrario, o si p ya ha sido liberado, ocurre un comportamiento indefinido. Si p es NULL, no se realiza ninguna operación.

calloc()

La función calloc() asigna memoria para un array de n elementos de size bytes cada uno y devuelve un puntero a la memoria asignada. La memoria se establece a cero. Si n o size es 0, entonces calloc() devuelve un valor de puntero único que más tarde se puede pasar correctamente a free().

Si la multiplicación de n y size resultara en un desbordamiento de enteros, entonces calloc() devuelve un error. Por el contrario, no se detectaría un desbordamiento de enteros en la siguiente llamada a malloc(), con el resultado de que se asignaría un bloque de memoria de tamaño incorrecto:


malloc(n * size);

realloc()

La función realloc() cambia el tamaño del bloque de memoria apuntado por p a size bytes. Los contenidos de la memoria no cambiarán en el rango desde el inicio de la región hasta el mínimo del tamaño antiguo y el nuevo. Si el nuevo tamaño es mayor que el tamaño antiguo, la memoria añadida no se inicializará.

Si p es NULL, entonces la llamada es equivalente a malloc(size), para todos los valores de size.

Si size es igual a cero, y p no es NULL, entonces la llamada es equivalente a free(p) (pero ver "Comportamiento no portable" para problemas de portabilidad).

A menos que p sea NULL, debe haber sido devuelto por una llamada anterior a malloc o funciones relacionadas. Si el área apuntada fue movida, se realiza un free(p).

reallocarray()

La función reallocarray() cambia el tamaño (y posiblemente mueve) el bloque de memoria apuntado por p para que sea lo suficientemente grande para un array de n elementos, cada uno de los cuales tiene size bytes. Es equivalente a la llamada


realloc(p, n * size);

Sin embargo, a diferencia de esa llamada a realloc(), reallocarray() falla de forma segura en el caso en que la multiplicación pudiera desbordarse. Si ocurre tal desbordamiento, reallocarray() devuelve un error.

VALOR DE RETORNO

Las funciones malloc(), calloc(), realloc() y reallocarray() devuelven un puntero a la memoria asignada, que está adecuadamente alineado para cualquier tipo que quepa en el tamaño solicitado o menos. En caso de error, estas funciones devuelven NULL y establecen errno. Intentar asignar más de PTRDIFF_MAX bytes se considera un error, ya que un objeto tan grande podría causar que la posterior resta de punteros se desborde.

La función free() no devuelve valor y preserva errno.

Las funciones realloc() y reallocarray() devuelven NULL si p no es NULL y el tamaño solicitado es cero; esto no se considera un error. (Ver "Comportamiento no portable" para problemas de portabilidad). De lo contrario, el puntero devuelto puede ser el mismo que p si la asignación no se movió (por ejemplo, había espacio para expandir la asignación en su lugar), o diferente de p si la asignación se movió a una nueva dirección. Si estas funciones fallan, el bloque original no se modifica; no se libera ni se mueve.

ERRORES

calloc(), malloc(), realloc() y reallocarray() pueden fallar con el siguiente error:

ENOMEM
Sin memoria. Posiblemente, la aplicación alcanzó el límite RLIMIT_AS o RLIMIT_DATA descrito en getrlimit(2). Otra razón podría ser que el número de mapeos creados por el proceso llamante excedió el límite especificado en /proc/sys/vm/max_map_count.

realloc(p, 0)

El comportamiento de realloc(p, 0) en glibc no se ajusta a ninguna de las versiones de C99, C11, POSIX.1-2001, POSIX.1-2004, POSIX.1-2008, POSIX.1-2013, POSIX.1-2017 o POSIX.1-2024. La especificación C17 se modificó para que fuera conforme, pero esa especificación hizo imposible escribir código que determinara de forma fiable si el puntero de entrada se libera después de realloc(p, 0), y C23 lo cambió de nuevo para que esto sea un comportamiento indefinido, reconociendo que la especificación C17 era lo suficientemente amplia, por lo que un comportamiento indefinido no era peor que eso.

reallocarray() sufre los mismos problemas en glibc.

musl libc y los BSD se ajustan a todas las versiones de ISO C y POSIX.1.

gnulib proporciona el módulo realloc-posix, que proporciona envoltorios realloc() y reallocarray() que se ajustan a todas las versiones de ISO C y POSIX.1.

Existe una propuesta para estandarizar el comportamiento de BSD: https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3621.txt.
