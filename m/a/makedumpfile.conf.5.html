MAKEDUMPFILE.CONF(5) Manual de Administrador del Sistema de Linux MAKEDUMPFILE.CONF(5)

NOMBRE

makedumpfile.conf - El archivo de configuración del filtro para makedumpfile(8).

DESCRIPCIÓN

El archivo makedumpfile.conf es un archivo de configuración para la herramienta makedumpfile. El archivo makedumpfile.conf contiene los comandos de borrado para filtrar los datos deseados del kernel del vmcore al crear DUMPFILE usando la herramienta makedumpfile. makedumpfile lee la configuración del filtro y construye la lista de direcciones de memoria y sus tamaños después de procesar los comandos del filtro. Las ubicaciones de memoria que requieren ser filtradas son luego enmascaradas con el carácter X (58 en Hexadecimal).

FORMATO DEL ARCHIVO

El archivo consiste en secciones de módulos que contienen comandos de filtro. Una sección comienza con el nombre de la sección entre corchetes y continúa hasta que comienza la siguiente sección.

"["<NombreModulo>"]"
<ComandosFiltro>

donde
"[" es el carácter [
"]" es el carácter ]

<NombreModulo>
es 'vmlinux' o el nombre de un módulo del kernel de Linux.
<ComandosFiltro>
es una lista de uno o más comandos de filtro como se describe en la sección COMANDOS DE FILTRO de esta página del manual.

El nombre de la sección indica el nombre de un módulo del kernel (incluyendo vmlinux) al que pertenecen los símbolos especificados en los comandos de borrado subsiguientes. La sección sin nombre tiene por defecto la sección [vmlinux]. Sin embargo, un usuario también puede definir explícitamente la sección [vmlinux]. Las secciones ayudan a la herramienta makedumpfile a seleccionar el archivo de depuración de kernel o módulo apropiado antes de procesar los comandos de borrado subsiguientes. Antes de seleccionar el archivo de depuración apropiado, el nombre del módulo se valida contra los módulos cargados del vmcore. Si no se encuentra coincidencia, la sección se ignora y makedumpfile salta a la siguiente sección de módulo. Si se encuentra una coincidencia, makedumpfile intentará cargar el archivo de depuración del módulo correspondiente. Si la depuración del módulo no está disponible, makedumpfile omitirá la sección con un mensaje de advertencia.

COMANDOS DE FILTRO

comando filtro

Un comando de filtro es un comando de borrado o una construcción de bucle. Cada comando de borrado y construcción de bucle debe comenzar en una nueva línea. Cada comando de filtro describe los datos en el volcado que deben ser borrados. Sintaxis:

<ComandosBorrado>|<ConstruccionBucle>

donde

<ComandosBorrado>
Se describe en la subsección comando borrado de esta página del manual.
<ConstruccionBucle>
Se describe en la subsección Construcción de bucle de esta página del manual.

comando borrado

Borra un tamaño especificado de datos del kernel referidos por un símbolo del kernel/módulo especificado o su componente miembro. La sintaxis del comando de borrado es:

erase <Símbolo>[.miembro[...]] [size <ValorTamaño>[K|M]]
erase <Símbolo>[.miembro[...]] [size <SímboloTamaño>]
erase <Símbolo>[.miembro[...]] [nullify]

donde

<Símbolo>
Un nombre de símbolo (variable) del kernel o módulo que forma parte de los símbolos globales /proc/kallsyms.
<ValorTamaño>
Un valor entero positivo como tamaño de los datos en bytes a borrar. Los sufijos 'K' y 'M' se pueden usar para especificar kilobytes y megabytes respectivamente, donde K significa 1024 bytes y M significa 1024^2 = 1048576 bytes. Los sufijos no distinguen entre mayúsculas y minúsculas.
<SímboloTamaño>
Una expresión simple de la forma <Símbolo>[.miembro[...]] que denota un símbolo que contiene un valor entero positivo como tamaño de los datos en bytes a borrar.
<Símbolo>[.miembro[...]]
Una expresión simple que resulta en un nombre de símbolo global del kernel o sus componentes miembro. La expresión siempre usa el operador '.' para especificar el componente miembro del símbolo del kernel o su miembro, independientemente de si es de tipo puntero o no.
miembro[...]
Miembro o componente de miembro en <Símbolo>.

El comando erase toma dos argumentos: 1. el nombre del símbolo del kernel o sus componentes miembro y 2. el tamaño de los datos referidos por el argumento (1) O la palabra clave nullify. El segundo argumento size O nullify es opcional. La unidad para el valor del tamaño está en bytes. Si no se especifica la opción size, el tamaño del primer argumento se determina según su tipo de dato usando la información dwarf del archivo de depuración. En el caso del tipo de dato 'char *', la longitud de la cadena apuntada por el puntero 'char *' se determina con un límite superior de 1024. El size se puede especificar en dos formas: 1. un valor entero como se explicó anteriormente (<ValorTamaño>) y 2. una expresión simple en la forma de <Símbolo>[.miembro[...]]] que resulta en una variable de tipo base (entero).

Si el <Símbolo> especificado es de tipo 'void *', entonces el usuario debe proporcionar la opción size o nullify, de lo contrario, el comando de borrado no tendrá ningún efecto.

La opción nullify solo funciona si el <Símbolo> especificado es un puntero. En lugar de borrar los datos apuntados por el puntero especificado, nullify borra el valor del puntero y lo establece a '0' (NULL). Tenga en cuenta que al anular los valores de los punteros se puede afectar la capacidad de depuración del DUMPFILE creado. Use la opción nullify solo cuando el tamaño de los datos a borrar no se conoce. Ejemplo: datos apuntados por un puntero 'void *'.

Veamos el archivo makedumpfile.conf del siguiente ejemplo, que se configuró para borrar datos deseados del kernel del módulo del kernel con el nombre mymodule. En las líneas 1 y 3, el usuario no especificó la opción de tamaño al borrar los símbolos 'array_var' y 'mystruct1.name'. En su lugar, el usuario depende de makedumpfile para determinar automáticamente los tamaños a borrar, es decir, 100 bytes para 'array_var' y 11 bytes para 'mystruct1.name'. En la línea 2, al borrar el miembro 'mystruct1.buffer', el usuario especificó el valor de tamaño 25 frente al tamaño real de 50. En este caso, el size especificado por el usuario tiene prioridad y makedumpfile borra solo 25 bytes de 'mystruct1.buffer'. En la línea 4, el tamaño de los datos apuntados por el puntero void * 'mystruct1.addr1' es desconocido. Por lo tanto, se especificó la opción nullify para restablecer el valor del puntero a NULL. En la línea 5, 'mystruct2.addr_size' se especifica como argumento size para determinar el tamaño de los datos apuntados por el puntero void * 'mystruct2.addr'.

Ejemplo:

Suponiendo que el siguiente fragmento de código proviene del módulo del kernel 'mymodule':

struct s1 {
char *name;
void *addr1;
void *addr2;
char buffer[50];
};
struct s2 {
void *addr;
long addr_size;
};

/* Símbolos globales */
char array_var[100];
struct s1 mystruct1;
struct s2 *mystruct2;

int foo()
{
...
s1.name = "Hola Mundo";
...
}

makedumpfile.conf:
[mymodule]
erase array_var
erase mystruct1.buffer size 25
erase mystruct1.name
erase mystruct1.addr1 nullify
# Suponiendo que addr2 apunta a 1024 bytes
erase mystruct1.addr2 size 1K
erase mystruct2.addr size mystruct2.addr_size
EOF

Construcción de bucle

Una Construcción de Bucle permite al usuario recorrer los elementos de una lista enlazada o un arreglo y borrar los contenidos de datos a los que hace referencia cada elemento.

for <id> in {<VarArreglo> |
<VarEstructura> via <MiembroSiguiente> |
<VarCabezaLista> within <NombreEstructura>:<MiembroCabezaLista>}
erase <id>[.ExpresionMiembro] [size <ExpresionTamaño>|nullify]
[erase <id>...]
[...]
endfor

donde

FILTER COMMANDS

<id>
Nombre arbitrario utilizado para referirse temporalmente a elementos de la lista. Esto también se llama variable de iteración.
<ArrayVar>
Una expresión simple en forma de <Símbolo>[.miembro[...]] que resulta en una variable de matriz.
<StructVar>
Una expresión simple en forma de <Símbolo>[.miembro[...]] que resulta en una variable que apunta a una estructura.
<NextMember>
Miembro dentro de <StructVar> que apunta a un objeto del mismo tipo que <StructVar>.
<ListHeadVar>
Una expresión simple en forma de <Símbolo>[.miembro[...]] que resulta en una variable de tipo struct list_head.
<StructName>
Nombre del tipo de estructura que se puede recorrer utilizando la variable HEAD <ListHeadVar> y que contiene un miembro llamado <ListHeadMember>.
<ListHeadMember>
Nombre de un miembro en <StructName>, de tipo struct list_head.
<MemberExpression>
Una expresión simple en forma de [.miembro[...]] para especificar un miembro o componente de un elemento en <ArrayVar>, <StructVar> o <StructName>.
<SizeExpression>
Valor de tamaño en forma de <SizeValue>, <id>[.MemberExpression] o <Símbolo>[.miembro[...]].

La construcción de bucle for permite iterar sobre listas de elementos en una matriz o listas enlazadas. Cada elemento de la lista se asigna a la variable de iteración <id>. El tipo de la variable de iteración se determina por el de los elementos de la lista. La entrada especificada después de la terminal 'in' se llama entrada LIST. La entrada LIST puede ser una variable de matriz, una variable/puntero de estructura o una variable de tipo struct list_head. El conjunto de comandos erase especificados entre for y endfor se ejecutará para cada elemento de la entrada LIST.

Si la entrada LIST especificada es una variable de matriz, el bucle se ejecutará para cada elemento de la matriz. El tamaño de la matriz se determinará utilizando información de enano.

Si la entrada LIST especificada es una variable/puntero de estructura, se debe especificar un miembro de recorrido (<NextMember>) utilizando la terminal 'via'. El bucle for continuará hasta que el valor del miembro de recorrido sea NULL o coincida con la dirección del primer nodo <StructVar> si es una lista enlazada circular.

Si la entrada LIST se especifica utilizando una variable de tipo struct list_head, se debe usar la terminal within para especificar el nombre de la estructura <StructName> que la rodea, junto con el miembro de tipo struct list_head después de ':', que forma parte de la lista enlazada. En la declaración de borrado, <id> denota la estructura que contiene la list_head (ELEMENT_OF).

El siguiente ejemplo ilustra cómo utilizar la construcción de bucles para recorrer matrices, listas enlazadas a través del miembro next y list_head.

Ejemplo:

Suponiendo que el siguiente fragmento de código proviene del módulo del kernel 'mymodule':

struct s1 {
struct *next;
struct list_head list;
char private[100];
void *key;
long key_size;
};

/* Símbolos globales */
struct s1 mystruct1;
static LIST_HEAD(s1_list_head);
struct s1 myarray[100];

void foo()
{
struct s1 *s1_ptr;
...
...
s1_ptr = malloc(...);
...
...
list_add(&s1_ptr->list, &s1_list_head);
...
}

makedumpfile.conf:
[mymodule]
# borrar campos privados de la lista que comienza con mystruct1 conectada a través del
# miembro 'next':
for mys1 in mystruct1 via next
erase mys1.private
erase mys1.key size mys1.key_size
endfor

# borrar campos privados de la lista que comienza con la variable list_head
# s1_list_head.
for mys1 in s1_list_head.next within s1:list
erase mys1.private
erase mys1.key size mys1.key_size
endfor

# borrar campos privados de todos los elementos de la matriz myarray:
for mys1 in myarray
erase mys1.private
erase mys1.key size mys1.key_size
endfor
EOF

En el ejemplo anterior, la primera construcción for recorre la lista enlazada a través de una variable de estructura especificada mystruct1 de tipo struct s1. La lista enlazada se puede recorrer utilizando el miembro 'next' de mystruct1. Por lo tanto, se ha utilizado una terminal via para especificar el nombre del miembro de recorrido 'next'.

La segunda construcción for recorre la lista enlazada a través de una variable especificada struct list_head s1_list_head.next. El símbolo global s1_list_head es la dirección de inicio de la lista enlazada y su miembro next apunta a la dirección del miembro de tipo struct list_head 'list' de struct s1. Por lo tanto, se utiliza una terminal within para especificar el nombre de la estructura 's1' que se puede recorrer utilizando la variable s1_list_head.next junto con el nombre del miembro de tipo struct list_head 'list', que forma parte de la lista enlazada que comienza desde el símbolo global s1_list_head.

La tercera construcción for recorre los elementos de la matriz especificados a través de una variable de matriz myarray.
