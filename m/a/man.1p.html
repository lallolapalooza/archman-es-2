MAN(1P) Manual del Programador POSIX MAN(1P)

PROLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

man — mostrar documentación del sistema

SINTAXIS

man [-k] nombre...

DESCRIPCIÓN

La utilidad man escribirá información sobre cada uno de los operandos nombre. Si nombre es el nombre de una utilidad estándar, man como mínimo escribirá un mensaje que describa la sintaxis utilizada por la utilidad estándar, sus opciones y operandos. Si hay más información disponible, la utilidad man la proporcionará de una manera definida por la implementación.

Una implementación puede proporcionar información para valores de nombre distintos de las utilidades estándar. Las utilidades estándar que se enumeran como opcionales y que no son compatibles con la implementación, bien causarán que se muestre un mensaje breve indicando ese hecho, o bien causarán una visualización completa de la información como se describió anteriormente.

OPCIONES

La utilidad man se ajustará al volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de Sintaxis de Utilidad.

La siguiente opción deberá ser compatible:

-k
Interpretar los operandos nombre como palabras clave a utilizar en la búsqueda de una base de datos de resumen de utilidades que contenga una entrada breve del propósito para cada utilidad estándar y escribir líneas de la base de datos de resumen que coincidan con alguna de las palabras clave. La búsqueda por palabras clave producirá resultados equivalentes a la salida del siguiente comando:
grep -Ei '
nombre
nombre
...
' base-de-datos-resumen

Esto asume que la base-de-datos-resumen es un archivo de texto con una entrada por línea; esta organización no es requerida y el ejemplo que usa grep -Ei es meramente ilustrativo del tipo de búsqueda previsto. La entrada de propósito que se incluirá en la base de datos consistirá en una descripción concisa del propósito de la utilidad.

OPERANDOS

El siguiente operando deberá ser compatible:

nombre
Una palabra clave o el nombre de una utilidad estándar. Cuando -k no se especifica y nombre no representa una de las utilidades estándar, los resultados no están especificados.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de man:

LANG
Proporcionar un valor predeterminado para las variables de internacionalización que no estén establecidas o estén vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de configuración regional).
LC_ALL
Si se establece en una cadena de valor no vacía, anulará los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determinar la configuración regional para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en comparación con caracteres multibyte en los argumentos y en la base de datos de resumen). El valor de LC_CTYPE no necesita afectar al formato de la información escrita sobre los operandos nombre.
LC_MESSAGES

Determinar la configuración regional que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida estándar de error y los mensajes informativos escritos en la salida estándar.
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.
PAGER
Determinar un comando de filtrado de salida para escribir la salida en un terminal. Cualquier cadena aceptable como operando cadena_comando para el comando sh -c será válida. Cuando la salida estándar sea un dispositivo de terminal, la salida de la página de referencia se canalizará a través del comando. Si la variable PAGER está vacía o no está establecida, el comando será more o alguna otra utilidad paginadora documentada en la documentación del sistema.

EVENTOS ASÍNCRONOS

Predeterminado.

SALIDA ESTÁNDAR

La utilidad man escribirá texto que describe la sintaxis de la utilidad nombre, sus opciones y sus operandos, o, cuando se especifica -k, líneas de la base de datos de resumen. El formato de este texto está definido por la implementación.

SALIDA DE ERROR ESTÁNDAR

La salida estándar de error se utilizará para mensajes de diagnóstico, y también puede usarse para mensajes informativos de formato no especificado.

RATIFICACION

Se reconoce que la utilidad man solo tiene una utilidad mínima tal como se especifica. La opinión de los desarrolladores del estándar estaba fuertemente dividida en cuanto a cuánta o qué poca información debería requerirse que man proporcionara. Sin embargo, consideraron que la provisión de alguna forma portable de acceder a la documentación ayudaría a la portabilidad del usuario. Los argumentos en contra de una especificación más completa fueron:

*
Grandes cantidades de documentación no deberían ser requeridas en un sistema que no tiene espacio en disco en exceso.
*
El sistema de manuales actual no presenta la información de una manera que facilite en gran medida la portabilidad del usuario.
*
Un ``mejor sistema de ayuda'' es actualmente un área en la que los proveedores sienten que pueden agregar valor a sus implementaciones POSIX.

Se consideró la opción -f, pero debido a diferencias de implementación, no se incluyó en este volumen de POSIX.1‐2017.

La descripción se modificó para ser más específica sobre lo que se debe mostrar para una utilidad. Los desarrolladores del estándar consideraron que era insuficiente permitir la visualización solo de la sintaxis sin dar una breve descripción de lo que hace cada opción y operando.

La entrada de ``propósito'' a incluir en la base de datos puede ser similar al título de la sección (menos el prefijo numérico) de este volumen de POSIX.1‐2017 para cada utilidad. Estos títulos son similares a los utilizados en sistemas históricos para este propósito.

La advertencia en la descripción de LC_CTYPE se añadió porque no es un requisito que una implementación proporcione páginas de referencia para todas sus localidades soportadas en cada sistema; cambiar LC_CTYPE no traduce necesariamente la página de referencia a otro idioma. Esto es equivalente al estado actual de LC_MESSAGES en POSIX.1-2008 — las mensajes específicos de la localidad aún no son un requisito.

La variable histórica MANPATH no se incluye en POSIX porque no se hace ningún intento de especificar convenciones de nomenclatura para los archivos de páginas de referencia, ni siquiera de exigir que sean archivos. En algunas implementaciones podrían ser una base de datos real, un archivo hipertexto, o incluso cadenas fijas dentro del ejecutable man. Los desarrolladores del estándar consideraron que la portabilidad de las páginas de referencia estaba fuera de su ámbito de trabajo. Sin embargo, los usuarios deben ser conscientes de que MANPATH está implementado en varios sistemas históricos y que se puede utilizar para adaptar el patrón de búsqueda de páginas de referencia de las diversas categorías (utilidades, funciones, formatos de archivo, etc.) cuando el administrador del sistema revela la ubicación y las convenciones para las páginas de referencia en el sistema.

La búsqueda por palabras clave puede basarse al menos en el texto de los títulos de las secciones de estas descripciones de utilidad, y la implementación puede añadir más palabras clave. El término ``títulos de sección'' se refiere a las cadenas como:

man — Muestra la documentación del sistema
ps — Informa del estado del proceso
