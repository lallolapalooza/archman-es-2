MAN(7) Miscellaneous Information Manual MAN(7)

NAME

man — lenguaje de formato heredado para páginas man

DESCRIPTION

El lenguaje man fue el lenguaje de formato estándar para las páginas de manual de AT&T UNIX desde 1979 hasta 1989. No lo use para escribir nuevas páginas de manual: es un lenguaje puramente de presentación y carece de soporte para marcado semántico. Utilice el lenguaje mdoc(7), en su lugar.

En un documento man, las líneas que comienzan con el carácter de control ‘.’ se denominan “líneas de macro”. La primera palabra es el nombre de la macro. Generalmente consta de dos letras mayúsculas. Para obtener una lista de macros portátiles, vea RESUMEN DE MACROS. Las palabras que siguen al nombre de la macro son argumentos para la macro.

Las líneas que no comienzan con el carácter de control se denominan “líneas de texto”. Proporcionan texto de formato libre para ser impreso; el formato del texto depende del contexto de procesamiento respectivo:

.SH Las líneas de macro cambian el estado de control.
Las líneas de texto se interpretan dentro del estado actual.

Muchos aspectos de la sintaxis básica del lenguaje man se basan en el lenguaje roff(7); vea las secciones SINTAXIS DEL LENGUAJE y SINTAXIS DE MACROS en el manual de roff(7) para más detalles, en particular con respecto a comentarios, secuencias de escape, espacios en blanco y comillas.

Cada documento man comienza con la macro TH especificando el nombre y la sección del documento, seguido de la sección NOMBRE formateada de la siguiente manera:

.TH PROGNAME 1 1979-01-10
.SH NAME
\fBprogname\fR \(en una línea sobre lo que hace

RESUMEN DE MACROS

Este resumen está ordenado de manera que las macros de propósito similar se listan juntas. Las macros obsoletas y no portátiles no se incluyen en el resumen, pero se pueden encontrar en la referencia alfabética a continuación.

Metadatos de encabezado y pie de página de la página

TH establecer el título: nombre sección fecha [fuente [volumen]]
AT mostrar la versión de AT&T UNIX en el pie de página (<= 1 argumento)
UC mostrar la versión de BSD en el pie de página (<= 1 argumento)

TP párrafo etiquetado: [ancho]

REFERENCIA DE MACROS

Esta sección es una referencia canónica de todas las macros, organizadas alfabéticamente. Para el alcance de macros individuales, vea SINTAXIS DE MACROS.

AT
Establece el volumen para el pie de página para compatibilidad con páginas man de las versiones de AT&T UNIX. Los argumentos opcionales especifican de qué versión proviene. Esta macro es una extensión que apareció por primera vez en 4.3BSD.
B
El texto se renderiza en negrita.
BI
El texto se renderiza alternativamente en negrita y cursiva. Por lo tanto, ‘.BI this word and that’ hace que ‘this’ y ‘and’ se rendericen en negrita, mientras que ‘word’ y ‘that’ se renderizan en cursiva. Los espacios en blanco entre argumentos se omiten en la salida.

Ejemplo:

.BI bold italic bold italic
BR
El texto se renderiza alternativamente en negrita y romana (la fuente predeterminada). Los espacios en blanco entre argumentos se omiten en la salida. Vea también BI.
DT
Restaura las posiciones de tabulación predeterminadas. Están a intervalos de 0.5 pulgadas. Esto no tiene ningún efecto a menos que las posiciones de tabulación se hayan modificado con la solicitud ta de roff(7).
EE
Esta es una extensión no estándar de AT&T UNIX Versión 9, adoptada posteriormente por GNU. En mandoc(1), hace lo mismo que la solicitud fi de roff(7) (cambiar a modo de relleno).
EX
Esta es una extensión no estándar de AT&T UNIX Versión 9, adoptada posteriormente por GNU. En mandoc(1), hace lo mismo que la solicitud nf de roff(7) (cambiar a modo sin relleno).
HP
Comienza un párrafo cuya línea de salida inicial está justificada a la izquierda, pero las líneas de salida subsiguientes tienen sangría, con la siguiente sintaxis:
.HP [ancho]

El argumento ancho es un roff(7) ancho de escala. Si se especifica, se guarda para los márgenes izquierdos de párrafos posteriores; si no se especifica, se usa el ancho guardado o el predeterminado.

Esta macro es portable, pero está obsoleta porque no tiene una buena representación en la salida HTML, usualmente terminando indistinguible de PP.

I
El texto se renderiza en cursiva.
IB
El texto se renderiza alternativamente en cursiva y negrita. El espacio en blanco entre argumentos se omite en la salida. Ver también BI.
IP
Inicia un párrafo con sangría con la siguiente sintaxis:
.IP [cabeza [ancho]]

El argumento ancho es un roff(7) ancho de escala que define el margen izquierdo. Se guarda para los márgenes izquierdos de párrafos posteriores; si no se especifica, se usa el ancho guardado o el predeterminado.

El argumento cabeza se usa como término de encabezado, alineado al margen izquierdo. Esto es útil para párrafos con viñetas y similares.

IR
El texto se renderiza alternativamente en cursiva y en tipo romano (la fuente predeterminada). El espacio en blanco entre argumentos se omite en la salida. Ver también BI.
LP
Un sinónimo de PP.
ME
Finaliza un bloque de correo iniciado con MT. Esta es una extensión no estándar de GNU.
MT
Inicia un bloque de correo. Esta es una extensión no estándar de GNU. Tiene la siguiente sintaxis: 
.MT dirección
descripción del enlace a mostrar
.ME
OP
Argumento opcional de línea de comandos. Esta es una extensión no estándar de DWB. Tiene la siguiente sintaxis:
.OP clave [valor]

La clave suele ser una bandera de línea de comandos y valor su argumento.

P
Este sinónimo de PP es una extensión de AT&T System III UNIX adoptada posteriormente por 4.3BSD.
PD
Especifica el espacio vertical que se insertará antes de cada nuevo párrafo.
La sintaxis es la siguiente:
.PD [altura]

El argumento altura es un roff(7) ancho de escala. Por defecto es 1v. Si se omite la unidad, se asume v.

Esta macro afecta al espaciado antes de las instancias posteriores de HP, IP, LP, P, PP, SH, SS, SY y TP.

PP
Inicia un párrafo sin decorar. El ámbito de un párrafo se cierra con un párrafo, subsección, sección o fin de archivo posterior. El ancho guardado del margen izquierdo del párrafo se restablece al valor predeterminado.
RB
El texto se renderiza alternativamente en tipo romano (la fuente predeterminada) y negrita. El espacio en blanco entre argumentos se omite en la salida. Ver también BI.
RE
Cierra explícitamente el ámbito de una RS anterior. El margen izquierdo predeterminado se restaura al estado anterior a esa invocación de RS.

La sintaxis es la siguiente:

.RE [nivel]

Sin argumento, se cierra el bloque RS más reciente. Si nivel es 1, se cierran todos los bloques RS abiertos. De lo contrario, permanecen abiertos nivel − 1 bloques RS anidados.

RI
El texto se renderiza alternativamente en tipo romano (la fuente predeterminada) y cursiva. El espacio en blanco entre argumentos se omite en la salida. Ver también BI.
RS
Restablece temporalmente el margen izquierdo predeterminado. Esto tiene la siguiente sintaxis:
.RS [ancho]

El argumento ancho es un roff(7) ancho de escala. Si no se especifica, se usa el ancho guardado o el predeterminado.

Ver también RE.

SB
El texto se renderiza en tamaño pequeño (un punto más pequeño que la fuente predeterminada) en negrita. Esta macro es una extensión que probablemente apareció por primera vez en SunOS 4.0 y fue adoptada posteriormente por GNU y por 4.4BSD.
SH
Inicia una sección. El ámbito de una sección solo se cierra con otra sección o el fin del archivo. El ancho del margen izquierdo del párrafo se restablece al predeterminado.
SM
El texto se renderiza en tamaño pequeño (un punto más pequeño que la fuente predeterminada).
SS
Inicia una subsección. El ámbito de una subsección se cierra con una subsección, sección o fin de archivo posteriores. El ancho del margen izquierdo del párrafo se restablece al predeterminado.
SY
Inicia un bloque de sinopsis con la siguiente sintaxis: 
.SY comando
argumentos
.YS

Esta es una extensión no estándar de GNU y rara vez se usa incluso en las páginas man de GNU. El formato es similar a IP.

TH
Establece el nombre de la página del manual para usarlo en la cabecera y pie de página con la siguiente sintaxis:
.TH nombre sección fecha [fuente [volumen]]

Convencionalmente, el nombre del documento se escribe en mayúsculas. La sección suele ser un solo dígito, en algunos casos seguido de una letra. El formato recomendado para la fecha es YYYY-MM-DD según lo especificado en el estándar ISO-8601; si el argumento no se ajusta, se imprime tal cual. Si la fecha está vacía o no se especifica, se usa la fecha actual. La fuente opcional especifica la organización que proporciona la utilidad. Cuando no se especifica, mandoc(1) usa su argumento -Ios. La cadena volumen reemplaza el título de volumen predeterminado de la sección.

Ejemplos:

.TH CVS 5 1992-02-12 GNU
TP
Inicia un párrafo donde la cabeza, si excede el ancho de sangría, va seguida de un salto de línea; si no, el cuerpo sigue en la misma línea después de avanzar al ancho de sangría. Las líneas de salida subsiguientes están indentadas. La sintaxis es la siguiente: 
.TP [ancho]
cabeza \" una línea
cuerpo

El argumento ancho es un roff(7) ancho de escala. Si se especifica, se guarda para los márgenes izquierdos de párrafos posteriores; si no se especifica, se usa el ancho guardado o el predeterminado.

TQ
Similar a TP, excepto que no se inserta espaciado vertical antes del párrafo. Esta es una extensión no estándar de GNU y rara vez se usa incluso en las páginas man de GNU.
UC
Establece el volumen para el pie de página para compatibilidad con las páginas man de las versiones BSD. El primer argumento opcional especifica de qué versión proviene. Esta macro es una extensión que apareció por primera vez en 3BSD.
UE
Finaliza un bloque de identificador uniforme de recurso iniciado con UR. Esta es una extensión no estándar de GNU.
UR
Inicia un bloque de identificador uniforme de recurso. Esta es una extensión no estándar de GNU. Tiene la siguiente sintaxis: 
.UR uri
descripción del enlace a mostrar
.UE
YS
Finaliza un bloque de sinopsis iniciado con SY. Esta es una extensión no estándar de GNU.
in
Indenta relativo a la indentación actual:
.in [ancho]

Si ancho

ESQUEMA

The man macros are used to format manual pages. The mandoc utility can process documents written using these macros.

The set of man macros is divided into several groups:

  • macros for document structure
  • macros for physical markup
  • macros for accents
  • compatibility macros

For more details, see man(7).

DESCRIPCIÓN

The man macros are a set of roff(7) macros originally designed for writing manual pages. They are also known as groff-man macros when used with groff(1).

The man macros can be divided into two main groups: those that specify formatting of document elements, and those that specify font changes.

Macros de estructura de documentos

These macros define the structure of the manual page.

TH title section subtitle date os manual
Defines the title, section, subtitle, date, operating system, and manual name. This macro must be the first macro in the document.
AU name
Specifies the author of the manual page. This macro can be repeated.
CA name
Specifies the copyright holder. This macro can be repeated.
DT table
Defines the date to be used in the header. If table is given, the date is left-aligned; otherwise, it is right-aligned.
I name
Used for section titles. The name argument is the section title.
IP tag width
Starts an indented paragraph. The optional tag argument is displayed at the beginning of the paragraph, and the optional width argument specifies the width of the indentation.
LP
Starts a simple left-aligned paragraph.
P
Starts a simple paragraph.
PD above
Specifies the vertical distance between paragraphs. The optional above argument specifies the distance above the paragraph.
PP
Starts a new paragraph, with extra vertical space before it.
RE name
Ends a section or sub-section. The optional name argument specifies the name of the section or sub-section to end.
RS indent
Starts an indented block. The optional indent argument specifies the amount of indentation.
SH name
Starts a section. The optional name argument is the section name.
SS name
Starts a sub-section. The optional name argument is the sub-section name.
SY name
Starts a synonym list. The optional name argument is the name of the command or function.
TP width
Starts a paragraph with a hanging indent. The optional width argument specifies the width of the hanging indent.

Macros de marcado físico

These macros are used for emphasis and other forms of physical markup.

B name
Formats the text in bold.
BI name
Formats the text in bold and italics.
BR name
Formats the text in bold and roman.
I name
Formats the text in italics.
IB name
Formats the text in italics and bold.
IR name
Formats the text in italics and roman.
RB name
Formats the text in roman and bold.
RI name
Formats the text in roman and italics.
SB name
Formats the text in small bold.
SM name
Formats the text in small roman.
UC
Uppercase the text.

Macros de acento

These macros are used to add accents to characters.

ac accent character
Adds an accent to a character.
na accent character
Adds an accent to a character.

Macros de compatibilidad

These macros are provided for compatibility with older versions of man.

AT
Marks text as being part of the AT&T UNIX system.
EE
Ends an example section.
EX
Starts an example section.
OP name
Used to specify options in the SYNOPSIS section.
TH
This macro is now obsolete and should not be used.

The man macros also support the roff(7) font escapes \f, \F, and \fB.

Desplazamientos de párrafo

The man macros support paragraph offsets, which are used to control the vertical spacing between paragraphs. The offset is specified by the PD macro.

The man macros also support a page offset, which is used to control the vertical spacing between pages. The offset is specified by the PO macro.

If the PO macro is signed, the new offset is relative. Otherwise, it is absolute. This value is reset upon the next paragraph, section, or sub-section.

SINTAXIS DE MACROS

The man macros are classified by scope: line scope or block scope. Line macros are only scoped to the current line (and, in some situations, the subsequent line). Block macros are scoped to the current line and subsequent lines until closed by another block macro.

Macros de línea

Line macros are generally scoped to the current line, with the body consisting of zero or more arguments. If a macro is scoped to the next line and the line arguments are empty, the next line, which must be text, is used instead. Thus:

.I
foo

is equivalent to ‘.I foo’. If next-line macros are invoked consecutively, only the last is used. If a next-line macro is followed by a non-next-line macro, an error is raised.

The syntax is as follows:

.YO [body...]
[body...]

Macros de bloque

Block macros comprise a head and body. As with in-line macros, the head is scoped to the current line and, in one circumstance, the next line (the next-line stipulations as in Macros de línea apply here as well).

The syntax is as follows:

.YO [head...]
[head...]
[body...]

The closure of body scope may be to the section, where a macro is closed by SH; sub-section, closed by a section or SS; or paragraph, closed by a section, sub-section, HP, IP, LP, P, PP, RE, SY, or TP. No closure refers to an explicit block closing macro.

As a rule, block macros may not be nested; thus, calling a block macro while another block macro scope is open, and the open scope is not implicitly closed, is syntactically incorrect.

If a block macro is next-line scoped, it may only be followed by in-line macros for decorating text.

Manejo de fuentes

In man documents, both macros de marcado físico and roff(7) ‘\f’ font escape sequences can be used to choose fonts. In text lines, the effect of manual font selection by escape sequences only lasts until the next macro invocation; in macro lines, it only lasts until the end of the macro scope. Note that macros like BR open and close a font scope for each argument.

HISTORIA

The man language first appeared as a macro package for the roff typesetting system in Version 7 AT&T UNIX.

The stand-alone implementation that is part of the mandoc(1) utility first appeared in OpenBSD 4.6.
