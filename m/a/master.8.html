MASTER(8) Manual del Administrador del Sistema MASTER(8)

NOMBRE

master - Proceso maestro de Postfix

SINOPSIS

master [-Dditvw] [-c dir_config] [-e tiempo_salida]

DESCRIPCIÓN


El demonio master(8) es el proceso residente que ejecuta los demonios de Postfix bajo demanda: demonios para enviar o recibir mensajes a través de la red, demonios para entregar correo localmente, etc. Estos demonios se crean bajo demanda hasta un número máximo configurable por servicio.

Los demonios de Postfix terminan voluntariamente, ya sea después de estar inactivos durante un período de tiempo configurable, o después de haber atendido un número configurable de solicitudes. Las excepciones a esta regla son el gestor de cola residente, el servidor de verificación de direcciones y el servidor de caché de sesiones TLS y números pseudoaleatorios.

El comportamiento del demonio master(8) se controla mediante el archivo de configuración master.cf, como se describe en master(5).

Opciones:

-c dir_config
Lee los archivos de configuración main.cf y master.cf en el directorio especificado en lugar del directorio de configuración predeterminado. Esto también anula los archivos de configuración para otros procesos demonio de Postfix.
-D
Después de la inicialización, ejecuta un depurador en el proceso maestro. El comando de depuración se especifica con debugger_command en el archivo de configuración global main.cf.
-d
No redirige stdin, stdout o stderr a /dev/null, y no descarta la terminal de control. Esto solo debe usarse para depuración.
-e tiempo_salida
Termina el proceso maestro después de tiempo_salida segundos. Los procesos hijos terminan a su conveniencia.
-i
Habilita el modo init: no se convierte en un líder de sesión o grupo de procesos; y similar a -s, no redirige stdout a /dev/null, de modo que "maillog_file = /dev/stdout" funcione. Este modo solo está permitido si el ID del proceso es 1.

Esta función está disponible en Postfix 3.3 y posteriores.

-s
No redirige stdout a /dev/null, de modo que "maillog_file = /dev/stdout" funcione.

Esta función está disponible en Postfix 3.4 y posteriores.

-t
Modo de prueba. Devuelve un estado de salida cero cuando el archivo de bloqueo master.pid no existe o cuando ese archivo no está bloqueado. Esto es evidencia de que el demonio master(8) no se está ejecutando.
-v
Habilita el registro detallado con fines de depuración. Esta opción se pasa a los procesos hijos. Múltiples opciones -v hacen que el software sea cada vez más detallado.
-w
Espera en un proceso ficticio en primer plano, mientras que el demonio maestro real se inicializa en un proceso en segundo plano. El proceso ficticio en primer plano devuelve un estado de salida cero solo si la inicialización del demonio maestro es exitosa, y si se completa en un tiempo razonable.

Esta función está disponible en Postfix 2.10 y posteriores.

Señales:

SIGHUP
Al recibir una señal HUP (por ejemplo, después de "postfix reload"), el proceso maestro vuelve a leer sus archivos de configuración. Si un servicio ha sido eliminado del archivo master.cf, sus procesos en ejecución se terminan inmediatamente. De lo contrario, se permite que los procesos en ejecución terminen tan pronto como sea conveniente, de modo que los cambios en la configuración solo afecten a las nuevas solicitudes de servicio.
SIGTERM
Al recibir una señal TERM (por ejemplo, después de "postfix abort"), el proceso maestro pasa la señal a sus procesos hijos y termina. Esto es útil para un apagado de emergencia. Normalmente, uno solo terminaría el maestro ("postfix stop") y permitiría que los procesos en ejecución terminen lo que están haciendo.

DIAGNÓSTICOS


Los problemas se informan a syslogd(8) o postlogd(8). El estado de salida es distinto de cero en caso de problemas, incluidos los problemas al inicializarse como un proceso demonio maestro en segundo plano.

ENTORNO

MAIL_DEBUG
Después de la inicialización, inicia un depurador según se especifica con el parámetro de configuración debugger_command en el archivo de configuración main.cf.
MAIL_CONFIG
Directorio con los archivos de configuración de Postfix.

PARÁMETROS DE CONFIGURACIÓN

A diferencia de la mayoría de los procesos demonio de Postfix, el servidor master(8) no recoge automáticamente los cambios en main.cf. Los cambios en master.cf nunca se recogen automáticamente. Utilice el comando "postfix reload" después de un cambio de configuración.

CONTROLES DE RECURSOS Y TASAS

default_process_limit (100)
El número máximo predeterminado de procesos hijos de Postfix que proporcionan un servicio determinado.
max_idle (100s)
El tiempo máximo que un proceso demonio de Postfix inactivo espera una conexión entrante antes de terminar voluntariamente.
max_use (100)
El número máximo de conexiones entrantes que un proceso demonio de Postfix atenderá antes de terminar voluntariamente.
service_throttle_time (60s)
Cuánto tiempo espera el maestro de Postfix master(8) antes de crear un servidor que parezca estar funcionando mal.

Disponible en la versión 2.6 de Postfix y posteriores:

master_service_disable (vacío)
Deshabilita selectivamente los puertos del oyente de master(8) por tipo de servicio o por nombre y tipo de servicio.

CONTROLES VARIOS

config_directory (ver la salida de 'postconf -d')
La ubicación predeterminada de los archivos de configuración main.cf y master.cf de Postfix.
daemon_directory (ver la salida de 'postconf -d')
El directorio con los programas de soporte y los programas demonio de Postfix.
debugger_command (vacío)
El comando externo a ejecutar cuando un programa demonio de Postfix se invoca con la opción -D.
inet_interfaces (all)
Las direcciones de la interfaz de red local en las que recibe correo este sistema de correo.
inet_protocols (ver la salida de 'postconf -d')
Los protocolos de Internet que Postfix intentará utilizar al establecer o aceptar conexiones.
import_environment (ver la salida de 'postconf -d')
La lista de variables de entorno que un proceso privilegiado de Postfix importará de un proceso padre que no sea de Postfix, o anulaciones de entorno nombre=valor.
mail_owner (postfix)
La cuenta del sistema UNIX que posee la cola de Postfix y la mayoría de los demonios de Postfix.

NAME

master - Postfix master process control

SYNOPSIS

master [ -q queue_name ] [ -e error_code ] [ -t ]

DESCRIPTION

The master process is the Postfix parent process. It reads the master configuration file (master.cf) and starts child processes that handle mail queue management and network server requests.

The master process waits for child processes to terminate, and restarts them if they exit unexpectedly. It also responds to control requests from the postfix command.

The master process logs its actions to syslog.

DIAGNOSTICS

Errors are logged to syslogd(8). When the master process is started with the -q option, it will exit with an error code of 1 upon encountering a configuration error, and 0 otherwise.

ENVIRONMENT

The master process is typically started by the postfix startup script.

CONFIGURATION PARAMETERS

The behavior of Postfix master processes is described in master(5).

RESOURCE AND RATE CONTROLS

The following parameters are used by the master process to control Postfix daemon processes.

daemon_timeout (1800s)
The time limit for each Postfix daemon process to terminate gracefully. If a daemon process does not terminate within this time, the master process will kill it forcefully.
process_group_limit (10)
The maximum number of child processes that the master process will start for any single Postfix daemon. This limit prevents runaway processes from exhausting system resources.
service_restart_delay (60s)
The delay before the master process restarts a service that has exited prematurely. This prevents rapid restart loops.
master_service_list_enable (yes)
When enabled (the default), the master process will start services that are listed in the master configuration file.
master_service_list_disable (no)
When enabled, the master process will not start services that are listed in the master configuration file.

MISCELLANEOUS CONTROLS

process_id (read-only)
The process ID of a Postfix command or daemon process.
process_name (read-only)
The process name of a Postfix command or daemon process.
queue_directory (see 'postconf -d' output)
The location of the Postfix top-level queue directory.
syslog_facility (mail)
The syslog facility of Postfix logging.
syslog_name (see 'postconf -d' output)
A prefix that is prepended to the process name in syslog records, so that, for example, "smtpd" becomes "prefix/smtpd".

Available in Postfix 3.3 and later:

service_name (read-only)
The master.cf service name of a Postfix daemon process.

Available in Postfix 3.6 and later:

known_tcp_ports (lmtp=24, smtp=25, smtps=submissions=465, submission=587)
Optional setting that avoids lookups in the services(5) database.

FILES

To expand the directory names below into their actual values, use the command "postconf config_directory" etc.

$config_directory/main.cf, global configuration file.
$config_directory/master.cf, master server configuration file.
$queue_directory/pid/master.pid, master lock file.
$data_directory/master.lock, master lock file.
