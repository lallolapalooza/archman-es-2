NOMBRE

sendmail - Interfaz de compatibilidad de Postfix con Sendmail

SINOPSIS

sendmail [opción ...] [destinatario ...]
mailq
sendmail -bp
newaliases
sendmail -I

DESCRIPCIÓN


El comando sendmail(1) de Postfix implementa la interfaz de compatibilidad de Postfix con Sendmail. Por motivos de compatibilidad con aplicaciones existentes, se reconocen algunas opciones de línea de comandos de Sendmail pero se ignoran silenciosamente.

Por defecto, sendmail(1) de Postfix lee un mensaje de la entrada estándar hasta EOF o hasta que lee una línea con solo un carácter ., y organiza su entrega. sendmail(1) de Postfix se basa en el comando postdrop(1) para crear un archivo de cola en el directorio maildrop.

Se proporcionan alias de comando específicos para otros modos de operación comunes:

mailq
Lista la cola de correo. Cada entrada muestra el ID del archivo de cola, el tamaño del mensaje, la hora de llegada, el remitente y los destinatarios que aún deben ser entregados. Si el correo no se pudo entregar en el último intento, se muestra el motivo de la falla. La cadena del ID de la cola va seguida de un carácter de estado opcional:
*
El mensaje está en la cola activa, es decir, el mensaje está seleccionado para entrega.
!
El mensaje está en la cola hold (retenido), es decir, no se realizarán más intentos de entrega hasta que el correo se retire de la retención.
#
El mensaje está forzado a expirar. Consulte las opciones -e o -f de postsuper(1).
Este modo de operación se implementa ejecutando el comando postqueue(1).
newaliases
Inicializa la base de datos de alias. Si no se especifica ningún archivo de entrada (con la opción -oA, véase más abajo), el programa procesa el o los archivos especificados con el parámetro de configuración alias_database. Si no se especifica ningún tipo de base de datos de alias, el programa utiliza el tipo especificado con el parámetro de configuración default_database_type. Este modo de operación se implementa ejecutando el comando postalias(1).

Nota: puede tardar un minuto o más antes de que una actualización de la base de datos de alias sea visible. Utilice el comando "postfix reload" para eliminar este retraso.

Estas y otras características se pueden seleccionar especificando la combinación apropiada de opciones de línea de comandos. Algunas características se controlan mediante parámetros en el archivo de configuración main.cf.

Se reconocen las siguientes opciones:

-Am (ignorado)
-Ac (ignorado)
Postfix sendmail utiliza el mismo archivo de configuración independientemente de si un mensaje es una entrega inicial o no.
-B tipo_cuerpo
El tipo MIME del cuerpo del mensaje: 7BIT o 8BITMIME.
-bd
Entrar en modo demonio. Este modo de operación se implementa ejecutando el comando "postfix start".
-bh (ignorado)
-bH (ignorado)
Postfix no tiene una base de datos persistente de estado del host.
-bi
Inicializar la base de datos de alias. Consulte el comando newaliases anterior.
-bl
Entrar en modo demonio. Para aceptar solo conexiones locales como con la opción -bl de Sendmail, especifique "inet_interfaces = loopback" en el archivo de configuración main.cf de Postfix.
-bm
Leer correo de la entrada estándar y organizar su entrega. Este es el modo de operación por defecto.
-bp
Listar la cola de correo. Consulte el comando mailq anterior.
-bs
Modo de servidor SMTP independiente. Leer comandos SMTP de la entrada estándar y escribir respuestas en la salida estándar. En modo de servidor SMTP independiente, el reenvío de correo y otros controles de acceso están deshabilitados por defecto. Para habilitarlos, ejecute el proceso como el usuario mail_owner.

Este modo de operación se implementa ejecutando el demonio smtpd(8).

-bv
No recolectar ni entregar un mensaje. En su lugar, enviar un informe por correo después de verificar cada dirección de destinatario. Esto es útil para probar la reescritura de direcciones y las configuraciones de enrutamiento.

Esta característica está disponible en Postfix versión 2.1 y posteriores.

-C archivo_config
-C directorio_config
El nombre de la ruta del archivo main.cf de Postfix, o de su directorio padre. Esta información se ignora en las versiones de Postfix anteriores a la 2.3.

Con Postfix versión 3.2 y posteriores, un directorio no predeterminado debe estar autorizado en el archivo main.cf por defecto, a través de los parámetros alternate_config_directories o multi_instance_directories.

Con todas las versiones de Postfix, puede especificar un nombre de directorio con la variable de entorno MAIL_CONFIG para anular la ubicación de los archivos de configuración.

-F nombre_completo
Establece el nombre completo del remitente. Esto anula la variable de entorno NAME y solo se utiliza con mensajes que no tienen una cabecera de mensaje From:.
-f remitente
Establece la dirección del remitente del sobre. Esta es la dirección a la que se envían los problemas de entrega. Con las versiones de Postfix anteriores a la 2.1, la cabecera del mensaje Errors-To: anula la dirección de retorno de errores.
-G
Envío de gateway (reenvío), en contraposición al envío de usuario inicial. O bien no reescribe las direcciones en absoluto, o actualiza las direcciones incompletas con la información de dominio especificada con remote_header_rewrite_domain.

Esta opción se ignora antes de Postfix versión 2.3.

-h conteo_saltos (ignorado)
Límite de saltos. Utilice en su lugar el parámetro de configuración hopcount_limit.
-I
Inicializar la base de datos de alias. Consulte el comando newaliases anterior.
-i
Al leer un mensaje de la entrada estándar, no tratar una línea con solo un carácter . como el final de la entrada.
-L etiqueta (ignorado)
La etiqueta de registro. Utilice en su lugar el parámetro de configuración syslog_name.
-m (ignorado)
Compatibilidad hacia atrás.
-N dsn (predeterminado: 'delay, failure')
Control de notificación de estado de entrega. Especifique una lista separada por comas con uno o más de failure (enviar notificación cuando falla la entrega), delay (enviar notificación cuando la entrega se retrasa), o success (enviar notificación cuando se entrega el mensaje); o especifique never (no enviar ninguna notificación).

Esta característica está disponible en Postfix 2.3 y posteriores.

-n (ignorado)
Compatibilidad hacia atrás.
-oAbase_datos_alias
Base de datos de alias no predeterminada. Especifique ruta_archivo o tipo:ruta_archivo. Consulte postalias(1) para más detalles.
-O opción=valor (ignorado)
Establece la opción nombrada a valor. Utilice el parámetro de configuración equivalente en main.cf en su lugar.
-o7 (ignorado)
-o8 (ignorado)
Para enviar contenido de 8 bits o binario, utilice un apropiado

OPTIONS

-B type
The message body type. The supported types are "8bitmime" and "7bit". Use the -B option to specify the MIME encapsulation and specify the appropriate -B command-line option.
-oi
When reading a message from standard input, don't treat a line with only a . character as the end of input.
-om (ignored)
The sender is never eliminated from alias etc. expansions.
-o x value (ignored)
Set option x to value. Use the equivalent configuration parameter in main.cf instead.
-r sender
Set the envelope sender address. This is the address where delivery problems are sent to. With Postfix versions before 2.1, the Errors-To: message header overrides the error return address.
-R return
Delivery status notification control. Specify "hdrs" to return only the header when a message bounces, "full" to return a full copy (the default behavior).

The -R option specifies an upper bound; Postfix will return only the header, when a full copy would exceed the bounce_size_limit setting.

This option is ignored before Postfix version 2.10.

-q
Attempt to deliver all queued mail. This is implemented by executing the postqueue(1) command.

Warning: flushing undeliverable mail frequently will result in poor delivery performance of all other mail.

-qinterval (ignored)
The interval between queue runs. Use the queue_run_delay configuration parameter instead.
-qIqueueid
Schedule immediate delivery of mail with the specified queue ID. This option is implemented by executing the postqueue(1) command, and is available with Postfix version 2.4 and later.
-qRsite
Schedule immediate delivery of all mail that is queued for the named site. This option accepts only site names that are eligible for the "fast flush" service, and is implemented by executing the postqueue(1) command. See flush(8) for more information about the "fast flush" service.
-qSsite
This command is not implemented. Use the slower "sendmail -q" command instead.
-t
Extract recipients from message headers. These are added to any recipients specified on the command line.

With Postfix versions prior to 2.1, this option requires that no recipient addresses are specified on the command line.

-U (ignored)
Initial user submission.
-V envid
Specify the envelope ID for notification by servers that support DSN.

This feature is available in Postfix 2.3 and later.

-XV (Postfix 2.2 and earlier: -V)
Variable Envelope Return Path. Given an envelope sender address of the form owner-listname@origin, each recipient user@domain receives mail with a personalized envelope sender address.

By default, the personalized envelope sender address is owner-listname+user=domain@origin. The default + and = characters are configurable with the default_verp_delimiters configuration parameter.

-XVxy (Postfix 2.2 and earlier: -Vxy)
As -XV, but uses x and y as the VERP delimiter characters, instead of the characters specified with the default_verp_delimiters configuration parameter.
-v
Send an email report of the first delivery attempt (Postfix versions 2.1 and later). Mail delivery always happens in the background. When multiple -v options are given, enable verbose logging for debugging purposes.
-X log_file (ignored)
Log mailer traffic. Use the debug_peer_list and debug_peer_level configuration parameters instead.

SEGURIDAD

Por diseño, este programa no tiene privilegios de usuario (o grupo). Está preparado para manejar contenido de mensajes de usuarios no confiables, posiblemente remotos.

Sin embargo, como la mayoría de los programas de Postfix, este programa no aplica una política de seguridad en sus argumentos de línea de comandos. En su lugar, se basa en el sistema UNIX para aplicar políticas de acceso basadas en los IDs de usuario y grupo efectivos del proceso. Concretamente, esto significa que ejecutar comandos de Postfix como root (desde sudo o equivalente) en nombre de un usuario que no es root probablemente creará oportunidades de escalada de privilegios.

Si una aplicación ejecuta algún programa de Postfix en nombre de usuarios que no tienen acceso normal de shell a los comandos de Postfix, entonces esa aplicación DEBE restringir los argumentos de línea de comandos especificados por el usuario para evitar la escalada de privilegios.

  • Filtre todos los argumentos de línea de comandos, por ejemplo, argumentos que contengan una ruta de archivo o que especifiquen un método de acceso a base de datos. Estas comprobaciones de ruta de archivo deben rechazar enlaces simbólicos o duros controlados por el usuario a archivos sensibles, y no deben ser vulnerables a ataques de concurrencia TOCTOU.
  • Deshabilite el procesamiento de opciones de comando para todos los argumentos de comando que contengan datos especificados por el usuario. Por ejemplo, la línea de comandos de Postfix sendmail(1) DEBE estructurarse de la siguiente manera: 
        /ruta/a/sendmail argumentos-del-sistema -- argumentos-del-usuario

    Aquí, el "--" deshabilita el procesamiento de opciones de comando para todos los argumentos-del-usuario que siguen.

Sin el "--", un usuario malintencionado podría habilitar opciones de comando de Postfix sendmail(1), especificando una dirección de correo electrónico que comience con "-".

DIAGNÓSTICOS


Los problemas se registran en syslogd(8) o postlogd(8), y en el flujo de error estándar.

NAME

mailq — mail system queue information

SYNOPSIS

mailq [-A] [-h] [-L] [-v]

DESCRIPTION

The mailq command is an alias for postqueue -p. It displays the contents of the Postfix mail queue.

For compatibility with the sendmail(1) command, mailq is implemented as a symbolic link to postqueue.

The command displays information about undelivered mail. The output is similar to the output of the mailq command from sendmail(1), but with additional information that is useful for Postfix administration.

The output is sorted by queue file type, then by message arrival time.

       (Mail system is down)

       -Queue ID- --Size-- --Arrival Time-- --Sender/Recipient--
  E3A772593A       453 Mon Dec 19 10:03:04  <>
(user: alice)
                                          jane@example.com
  5005A2593B      1010 Mon Dec 19 10:05:08  alice@example.com
(user: bob)
                                          <>

Total-queue-size = 1463

The output columns are:

Queue ID
The unique message identifier in the queue.
Size
The message size in bytes.
Arrival Time
The time the message arrived in the queue.
Sender/Recipient
The sender and recipient addresses. If the message has multiple recipients, they are listed one per line, indented under the sender.

If the mail system is down, the first line will indicate that.

The command displays the total queue size and the number of messages in the queue.

OPTIONS

-A
Print all queue entries, not just those for the current host. This option is not relevant for non-sendmail compatibility commands.
-h
Display the top N entries in the queue, where N is specified by the q_display_max parameter in main.cf. The default is 20.
-L
Produce output in a format suitable for consumption by the Postfix sendmail command line interface. This option is not relevant for non-sendmail compatibility commands.
-v
Verbose mode. Displays more detailed information about the queue entries. The exact information displayed depends on the Postfix version and configuration. This option is not relevant for non-sendmail compatibility commands.

ENVIRONMENT

The following environment variables are used by mailq:

MAIL_CONFIG
To specify an alternative configuration file. The default is /etc/postfix/main.cf.
MAIL_SHELL
Specifies the default shell for mail delivery. Not used by mailq.
MAIL_SPOOL_DIR
Specifies the location of the mail queue. The default is /var/spool/postfix.

DIAGNOSTICS

The mailq command exits with status 0 on success, and non-zero on error.

Error messages are sent to standard error.

CONFIGURATION PARAMETERS

The mailq command is affected by the following global Postfix configuration parameters:

queue_directory
The top-level directory of the mail queue. Default: /var/spool/postfix.
q_display_max
The maximum number of queue entries to display with the -h option. Default: 20.

COMPATIBILITY CONTROLS

The mailq command is an alias for postqueue -p. Therefore, it is affected by all the compatibility controls of postqueue.

fork_attempts (5)
The maximal number of attempts to fork() a child process.
fork_delay (1s)
The delay between attempts to fork() a child process.
hopcount_limit (50)
The maximal number of Received: message headers that is allowed in the primary message headers.
queue_run_delay (300s)
The time between deferred queue scans by the queue manager; prior to Postfix 2.4 the default value was 1000s.

FAST FLUSH CONTROLS

The ETRN_README file describes configuration and operation details for the Postfix "fast flush" service.

fast_flush_domains ($relay_domains)
Optional list of destinations that are eligible for per-destination logfiles with mail that is queued to those destinations.

VERP CONTROLS

The VERP_README file describes configuration and operation details of Postfix support for variable envelope return path addresses.

default_verp_delimiters (+=)
The two default VERP delimiter characters.
verp_delimiter_filter (-=+)
The characters Postfix accepts as VERP delimiter characters on the Postfix sendmail(1) command line and in SMTP commands.

MISCELLANEOUS CONTROLS

alias_database (see 'postconf -d' output)
The alias databases for local(8) delivery that are updated with "newaliases" or with "sendmail -bi".
command_directory (see 'postconf -d' output)
The location of all postfix administrative commands.
config_directory (see 'postconf -d' output)
The default location of the Postfix main.cf and master.cf configuration files.
daemon_directory (see 'postconf -d' output)
The directory with Postfix support programs and daemon programs.
default_database_type (see 'postconf -d' output)
The default database type for use in newaliases(1), postalias(1) and postmap(1) commands.
delay_warning_time (0h)
The time after which the sender receives a copy of the message headers of mail that is still queued.
import_environment (see 'postconf -d' output)
The list of environment variables that a privileged Postfix process will import from a non-Postfix parent process, or name=value environment overrides.
mail_owner (postfix)
The UNIX system account that owns the Postfix queue and most Postfix daemon processes.
queue_directory (see 'postconf -d' output)
The location of the Postfix top-level queue directory.
remote_header_rewrite_domain (empty)
Rewrite or add message headers in mail from remote clients if the remote_header_rewrite_domain parameter value is non-empty, updating incomplete addresses with the domain specified in the remote_header_rewrite_domain parameter, and adding missing headers.
syslog_facility (mail)
The syslog facility of Postfix logging.
syslog_name (see 'postconf -d' output)
A prefix that is prepended to the process name in syslog records, so that, for example, "smtpd" becomes "prefix/smtpd".

Postfix 3.2 and later:

alternate_config_directories (empty)
A list of non-default Postfix configuration directories that may be specified with "-c config_directory" on the command line (in the case of sendmail(1), with the "-C" option), or via the MAIL_CONFIG environment parameter.
multi_instance_directories (empty)
An optional list of non-default Postfix configuration directories; these directories belong to additional Postfix instances that share the Postfix executable files and documentation with the default Postfix instance, and that are started, stopped, etc., together with the default Postfix instance.
