NOMBRE

makerules - guía del programador del sistema para compilar proyectos en diferentes plataformas

SINOPSIS

SRCROOT= ..
RULESDIR= RULES
include $(SRCROOT)/$(RULESDIR)/rules.top
definiciones locales aquí
include $(SRCROOT)/$(RULESDIR)/rules.*

Ver el capítulo TIPOS DE DESTINO ACTUALMENTE SOPORTADOS para posibles valores de rules.*.

DESCRIPCIÓN

Makerules es un conjunto de reglas que permite la compilación de proyectos estructurados con makefiles pequeños y de estructura uniforme. Todas las reglas se encuentran en un directorio central. La compilación de los proyectos en diferentes plataformas se puede hacer simultáneamente sin necesidad de modificar ninguno de los makefiles que se encuentran en los directorios de los proyectos.

Makerules es un conjunto de herramientas de portabilidad de alto nivel, superiores a autoconf y más fáciles de usar.

Actualmente se admiten tres programas de make: Sunpro make, GNU make y smake. Si desea agregar soporte para otros programas de make, lea las secciones sobre los requisitos mínimos para un programa de make y sobre la estructura del sistema de reglas de make.

Este manual ayudará a los programadores que necesiten realizar modificaciones en el propio sistema de reglas de make. Si desea saber algo sobre cómo usar el sistema de makefiles, consulte makefiles(4).

El principal objetivo de diseño fue no tener ninguna definición en más de un lugar en las reglas de make. Esto implica que los programadores del sistema que deseen agregar o modificar reglas deben seguir este objetivo para no destruir la funcionalidad en otros lugares.

El resultado visible para el usuario es un conjunto de makefiles pequeños y fáciles de leer, cada uno ubicado en el directorio hoja del proyecto y, por lo tanto, llamado makefile de hoja.

Cada uno de estos makefiles de hoja, de hecho, no contiene ninguna regla. Simplemente define algunas macros para el programa make e incluye dos archivos de un repositorio central de reglas de make. Estos archivos incluidos definen las reglas que se necesitan para compilar el proyecto.

Cada makefile de hoja se forma de manera muy simple:

•
Primero define dos macros que definen la ubicación relativa del directorio raíz del proyecto y el nombre del directorio que contiene el conjunto completo de reglas, y luego incluye el archivo de reglas rules.top del directorio que forma el repositorio central de reglas. Solo tiene que editar la macro SRCROOT para reflejar la ubicación relativa del directorio raíz del proyecto.
•
La siguiente parte de un makefile de hoja define macros que describen el destino y la fuente. Solo puede haber un destino por makefile de hoja. Por supuesto, puede haber muchos archivos fuente que se necesiten para crear ese destino. Si desea crear más de un destino en un directorio específico, debe colocar más de un makefile en ese directorio. Esta es la parte de un makefile que describe un destino único. Edite esta parte para que contenga todos los archivos fuente, todos los archivos de inclusión locales y todos los indicadores de tiempo de compilación no globales que se necesiten para su destino. Para un destino típico, esto es tan simple como rellenar un formulario.
•
Cada makefile de hoja finalmente incluye un archivo del directorio de reglas que contiene reglas para el tipo de destino apropiado que se creará a partir de este makefile de hoja.

El makefile en cada directorio debe llamarse Makefile. Si desea tener más de un makefile en un directorio específico, debe elegir nombres diferentes para los otros makefiles.

Tipos de Destino Actualmente Soportados

Existen reglas para los siguientes tipos de destinos:

comandos
Las reglas de make para comandos de nivel de usuario como cat, ls, etc., se encuentran en el archivo rules.cmd
controladores
Las reglas de make para controladores de dispositivos se encuentran en el archivo rules.drv
bibliotecas
Las reglas de make para bibliotecas no compartidas se encuentran en el archivo rules.lib
bibliotecas compartidas
Las reglas de make para bibliotecas compartidas se encuentran en el archivo rules.shl
archivos localizados
Las reglas de make para archivos localizados se encuentran en el archivo rules.loc
archivos no localizados
Las reglas de make para archivos no localizados se encuentran en el archivo rules.aux
scripts de shell
Las reglas de make para scripts de shell (una variante de archivos localizados) se encuentran en el archivo rules.scr
páginas del manual
Las reglas de make para páginas del manual (una variante de archivos localizados) se encuentran en el archivo rules.man
makefiles desviados
Las reglas de make para proyectos que necesitan tener más de un makefile en un directorio específico se encuentran en el archivo rules.mks Contiene una regla que desvía a los sub makefiles listados. Cada sub makefile puede ser de cualquier tipo.
directorios
Las reglas de make para subdirectorios se encuentran en el archivo rules.dir

Requisitos Mínimos Para Un Programa de Make

Las reglas de make actualmente tienen soporte para Sunpro make, GNU make y smake. Si desea agregar soporte para otros programas de make, necesitan tener algunas características mínimas que van más allá de las capacidades del programa make estándar de UNIX. BSDmake podría ser soportado si soporta reglas de coincidencia de patrones correctamente.

incluir
El programa de make debe ser capaz de incluir recursivamente otros archivos desde un makefile. El nombre del archivo a incluir debe permitir que sea una macro. El programa de make debe ser capaz de hacer esto de manera que si el archivo que debe incluirse es el resultado de una regla de make. Por ejemplo, si el archivo a incluir no existe o está obsoleto, debería construirse antes de intentar incluirlo.
agregar a una macro
Una referencia de macro de la forma:

macro += valor_a_agregar

debe agregar valor_a_agregar a la cadena que está actualmente en macro.

reemplazo de macro con sufijo
Una referencia de macro de la forma:

salida= $(macro:cadena1=cadena2)

debe reemplazar un sufijo cadena1 por cadena2 en todas las palabras que se encuentran en macro, donde cadena1 es un sufijo o una palabra a reemplazar en la definición de la macro, y cadena2 es el sufijo o palabra de reemplazo. Cadena1 y cadena2 deben ser reemplazadas correctamente incluso si son macros en sí mismas. Las palabras en el valor de una macro están separadas por ESPACIO, TAB y caracteres de NUEVA LÍNEA escapados.

reemplazo de macro con patrón
Una referencia de macro de la forma:

salida= $(macro:op%os=np%ns)

debe reemplazar un patrón central en macro, donde op es el prefijo existente (antiguo) y os es el sufijo existente (antiguo), np y ns son el nuevo prefijo y el nuevo sufijo, respectivamente, y el patrón que coincide con % (una cadena de cero o más caracteres), se transfiere del valor que se está reemplazando. Por ejemplo:

PROGRAMA=fabricar
DEBUG= $(PROGRAMA:%=tmp/%-g)

establece el valor de DEBUG a tmp/fabricate-g. Op, os, np y ns deben ser reemplazados correctamente incluso si son macros en sí mismas.

INTRODUCTION

Este documento describe la estructura del sistema de reglas de make utilizado por el sistema de compilación de software propietario de Sun Microsystems. Explica cómo se manejan los valores predeterminados y cómo se nombran y organizan las macros para garantizar la compatibilidad y la legibilidad. El objetivo es proporcionar un método consistente para la construcción de software en diferentes plataformas y entornos.

GUARANTEED DEFAULT VALUES

En la construcción de software, a menudo es necesario definir un valor predeterminado para una macro si no se proporciona un valor explícito. Sin embargo, no todos los programas de make admiten estructuras if then else, por lo que se debe utilizar un método diferente.

El método utilizado en las reglas de make se implementa mediante el uso de la sustitución de macros de sufijo y la sustitución de macros de patrón.

Primero, se define una macro que contiene un sufijo único:

# Definir una galleta única mágica
_UNIQ= .XxZzy-

Esta macro se utiliza para todos los lugares donde es necesario tener una macro con un valor predeterminado garantizado. El siguiente ejemplo muestra el algoritmo básico que se utiliza para implementar la frase: Si $(MAKE_NAME) contiene un valor, entonces $(XMAKEPROG) se establecerá en $(MAKE_NAME) si no $(XMAKEPROG) se establecerá en $(MAKEPROG).

_MAKEPROG= $(_UNIQ)$(MAKE_NAME)
__MAKEPROG= $(_MAKEPROG:$(_UNIQ)=$(MAKEPROG))
XMAKEPROG= $(__MAKEPROG:$(_UNIQ)%=%)

La primera línea de este ejemplo establece la macro _MAKEPROG en la concatenación del valor de MAKE_NAME y .XxZzy-. Si la macro MAKE_NAME está vacía en este momento, _MAKEPROG contendrá solo .XxZzy-.

En la segunda línea, __MAKEPROG se establece en el valor de _MAKEPROG. Si _MAKEPROG contiene solo .XxZzy-, esto implica que .XxZzy- es el sufijo. Este sufijo se reemplaza luego por el valor de MAKEPROG, en este caso __MAKEPROG contendrá el valor no modificado de MAKEPROG. Si _MAKEPROG contiene una concatenación de .XxZzy- y algo más, .XxZzy- no será un sufijo, sino un prefijo de _MAKEPROG y por esta razón __MAKEPROG contendrá el valor no modificado de _MAKEPROG, que es una concatenación de .XxZzy- y el valor de MAKE_NAME.

En la tercera línea, XMAKEPROG se establece en el valor de __MAKEPROG. Si __MAKEPROG tiene el prefijo .XxZzy- en este momento, .XxZzy- se eliminará.

La Estructura en los nombres de macros de Make

Los nombres utilizados para las macros de make están estructurados de manera que permiten usar grep(1) para buscar los nombres en las reglas de make. Para permitir esto, ningún nombre debe ser una subcadena de otro nombre.

Si un comando necesita opciones que deben especificarse en macros, hay una macro de make llamada XXXFLAGS. Esto cumple con las reglas habituales del archivo make. Existen macros de make internas llamadas XXXOPTS y XXXOPTX que se combinarán para XXXFLAGS:

LDFLAGS= $(LDOPTS) $(LDOPTX)

Donde XXXOPTS es el nombre de la macro que se utiliza internamente y XXXOPTX es el nombre de la macro que puede ser utilizada desde la línea de comandos del programa make. Por lo tanto, XXXOPTX se utiliza para añadir al contenido de XXXFLAGS. Si el valor de XXXFLAGS necesita ser sobrescrito, XXXOPTS puede ser utilizado dentro de los flags de la línea de comandos del programa make.

La Estructura del Sistema de Reglas de Make

La Estructura de las Reglas Básicas en rules.top

El archivo RULES/rules.top primero incluye un archivo de reglas que depende del programa make que se utiliza. El nombre de este archivo es RULES/mk-makeprog.id donde makeprog debe ser reemplazado por el nombre real del programa make, por ejemplo, make, gmake, smake. El propósito de este archivo es configurar una lista de macros que identifican el sistema donde se está compilando actualmente el proyecto. Estas macros tienen valores que contienen solo letras minúsculas y definen:

la arquitectura del procesador
Si dos sistemas ejecutan el mismo sistema operativo, este es un valor único si un programa simple de nivel de usuario no necesita ser recompilado para ejecutarse en el otro sistema. Los valores posibles son sparc, mc68020, pentium. Esta es la salida de uname -p. El valor se almacena en P_ARCH.
la arquitectura del kernel
Si dos sistemas pueden usar el mismo valor para P_ARCH pero un programa de nivel de usuario muy dependiente del sistema necesita ser recompilado para ejecutarse en el otro sistema, estos dos sistemas tienen arquitecturas de kernel diferentes. Esta es la salida de uname -m. Los valores posibles son sun3, sun4c, sun4m. El valor se almacena en K_ARCH.
la arquitectura de la máquina
Una macro obsoleta que solo es útil en sistemas Sun. No la use, use P_ARCH en su lugar. Esta es la salida de arch. Los valores posibles son sun3, sun4. El valor se almacena en M_ARCH.
el nombre del host
El nombre de la máquina donde se realiza la compilación. Esta es la salida de uname -n. El valor se almacena en HOSTNAME.
el nombre del sistema operativo
Esta es la salida de uname -s. Los valores posibles son sunos, dgux, hp-ux, irix. El valor se almacena en OSNAME.
la versión del sistema operativo
Esta es la salida de uname -r. Los valores posibles son 5.5, 4.1.4. El valor se almacena en OSREL.

El siguiente archivo a incluir desde RULES/rules.top es RULES/os-sistema operativo.id. Define las macros O_ARCH y -O_ARCH y puede modificar una de las macros definidas en RULES/mk-makeprog.id. Las macros O_ARCH y -O_ARCH se utilizan para distinguir entre diferentes sistemas operativos. Los nombres de los archivos de configuración del compilador tienen -O_ARCH como parte central. En algunos sistemas operativos, por ejemplo, SunOS y DG-UX, es necesario distinguir entre SunOS 4.x y SunOS 5.x o DG-UX 3.x y DG-UX 4.x.

El siguiente archivo a incluir desde RULES/rules.top es Defaults. Define las macros DEFCCOM , DEFINCDIRS , LDPATH , RUNPATH , INS_BASE y INS_KBASE. Si las definiciones tienen que ser diferentes en diferentes sistemas, este archivo puede contener una línea en la forma:

include $(SRCROOT)/Defaults.$(O_ARCH)

Las definiciones reales deben moverse a estos archivos.

A continuación, después de establecer algunos valores predeterminados internos, RULES/rules.top incluye el archivo de configuración del compilador con el nombre:

$(SRCROOT)/$(RULESDIR)/$(XARCH).rul

Este archivo contiene toda la información dependiente del sistema necesaria para configurar el compilador C en el sistema apropiado. Es una mala idea crear uno nuevo desde cero. Eche un vistazo a los otros archivos de configuración del compilador y modifique un archivo similar para sus necesidades. Tenga en cuenta que básicamente hay dos criterios importantes en un archivo de configuración del compilador. Uno es si el sistema utiliza el formato de encabezado ELF o no. El otro es si el sistema utiliza librerías compartidas o no.

La Estructura de las Reglas Específicas de la Aplicación

Los archivos de reglas específicos de la aplicación están diseñados de tal manera que incluyen todo lo necesario para esa tarea específica. Los archivos de reglas específicos de la aplicación son:

$(RULES)/rules.aux
Reglas para instalar archivos auxiliares no localizados.
$(RULES)/rules.cmd
Reglas para comandos como sh.
$(RULES)/rules.dir
Reglas para subdirectorios.
$(RULES)/rules.drv
Reglas para drivers cargables.
$(RULES)/rules.lib
Reglas para librerías estáticas.
$(RULES)/rules.loc
Reglas para instalar archivos auxiliares localizados.
$(RULES)/rules.man
Reglas para instalar páginas de manual localizadas.
$(RULES)/rules.mks
Reglas para sub-makefiles.
$(RULES)/rules.mod
Reglas para módulos de stream cargables.
$(RULES)/rules.scr
Reglas para instalar scripts de shell localizados.
$(RULES)/rules.shl
Reglas para librerías compartidas.

Comprendiendo la Estructura del Sistema de Reglas de Make

Para comprender la estructura del sistema de reglas de make al realizar cambios, intente usar la bandera -xM en el programa smake. Esta bandera imprimirá la lista de dependencias de inclusión (es decir, una lista que le indica qué reglas de make se incluyen desde qué otra regla).

Tenga en cuenta que algunas de las reglas dependen del programa make. Si desea realizar cambios en estas reglas, es posible que deba colocar las definiciones en archivos de reglas separados para cada programa make apropiado. Eche un vistazo al directorio RULES para ver algunos ejemplos.

makefiles(4), make(1), gmake(1), smake(1).

DIAGNÓSTICOS

Los mensajes de diagnóstico dependen del programa make. Consulte la página de manual apropiada.

NOTAS

Las reglas de make se pueden usar con Sunpro make, Gnu make y smake. Aunque Gnu make se ejecuta en muchas plataformas, no tiene una salida de depuración útil.

Utilice Sunpro make o smake si tiene problemas con un archivo makefile. Sunpro make y smake, ambos tienen una opción -D, que le permite ver los archivos makefile después de la primera expansión. Utilice esta opción si tiene dudas de que su archivo makefile se esté expandiendo correctamente y si se incluyen las reglas correctas. También hay una opción -d que proporciona salida de depuración.

DIAGNOSTICS

The program returns exit code 0 if the build was successful, and non-zero otherwise. Errors are reported to stderr.

There is a set of options to increase the verbosity of the output. If you want more output, use -d, -dd, -ddd and so on.

Smake has an option -xM that shows you the include dependency for make rules.
