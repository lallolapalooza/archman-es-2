NOMBRE

makedbz - Reconstruye archivos dbz

SINOPSIS

makedbz [-io] [-f nombrearchivo] [-s tamaño]

DESCRIPCIÓN

makedbz reconstruye la base de datos dbz (también conocida como el archivo history). El nombre predeterminado del archivo de texto es pathdb/history; para especificar un nombre diferente, use la opción -f.

OPCIONES

-f nombrearchivo
Si se utiliza la opción -f, los archivos de la base de datos se nombrarán "nombrearchivo.dir", "nombrearchivo.index", y "nombrearchivo.hash". Si no se utiliza la opción -f, se crea un enlace temporal al nombre "history.n" y los archivos de la base de datos se escriben como "history.n.index" , "history.n.hash" y "history.n.dir".
-i
Para ignorar la base de datos antigua al determinar el tamaño de la nueva que se va a crear, utilice la opción -i. El uso de las opciones -o o -s implica la opción -i.

Cuando se ignora la base de datos antigua y no se especifica un tamaño con -s, makedbz contará el número de líneas del archivo de texto history actual, añadirá un 10% a ese recuento (para los próximos artículos que lleguen), y otro 50% (o 100% si se usa el formato de hash etiquetado más lento) para determinar el tamaño de la nueva base de datos a crear. El objetivo es optimizar el rendimiento de la base de datos, manteniéndola por debajo de 2/3 de su tamaño (o 1/2 con el formato de hash etiquetado).

Si no existe ningún archivo de texto history, el nuevo tendrá el tamaño de creación predeterminado (ver -s).

-o
Si se utiliza la opción -o, no se crea el enlace temporal a "history.n" (o el nombre especificado por la opción -f) y se sobrescriben los archivos history existentes. Si existe la base de datos antigua, makedbz la usará para determinar el tamaño de la nueva base de datos (ver -i).
-s tamaño
makedbz también ignorará cualquier base de datos antigua si se utiliza la opción -s para especificar el número aproximado de entradas en la nueva base de datos. Especificar con precisión el tamaño es una optimización que creará una base de datos más eficiente. El servidor de noticias seguirá aceptando más artículos, pero será más lento. El tamaño se mide en pares clave-valor (es decir, líneas). (El tamaño debe ser el tamaño final estimado del archivo, típicamente el tamaño del archivo antiguo).

El tamaño efectivo utilizado será mayor, para optimizar el rendimiento de la base de datos. Para más información, ver -i y la discusión de dbzfresh y dbzsize en libinn_dbz(3).

El valor predeterminado es 6.666.666 al crear una nueva base de datos history. (Si se utiliza el formato de hash etiquetado más lento, el valor predeterminado es 500.000).
