MAKEDUMPFILE(8) Manual de Administrador del Sistema de Linux MAKEDUMPFILE(8)

NOMBRE

makedumpfile - crea un volcado pequeño de kdump

SINOPSIS

makedumpfile [OPCIÓN] [-x VMLINUX|-i VMCOREINFO] VMCORE DUMPFILE
makedumpfile -F [OPCIÓN] [-x VMLINUX|-i VMCOREINFO] VMCORE
makedumpfile [OPCIÓN] -x VMLINUX [--config ARCHIVO_CONFIGURACION_FILTRO] [--eppic MACRO_EPPIC] VMCORE DUMPFILE
makedumpfile -R DUMPFILE
makedumpfile --split [OPCIÓN] [-x VMLINUX|-i VMCOREINFO] VMCORE DUMPFILE1 DUMPFILE2 [DUMPFILE3 ..]
makedumpfile [OPCIÓN] [-x VMLINUX|-i VMCOREINFO] --num-threads NUMERO_HILOS VMCORE DUMPFILE
makedumpfile --reassemble DUMPFILE1 DUMPFILE2 [DUMPFILE3 ..] DUMPFILE
makedumpfile -g VMCOREINFO -x VMLINUX
makedumpfile [OPCIÓN] [--xen-syms XEN-SYMS|--xen-vmcoreinfo VMCOREINFO] VMCORE DUMPFILE
makedumpfile --dump-dmesg [--partial-dmesg] [-x VMLINUX|-i VMCOREINFO] VMCORE ARCHIVO_LOG
makedumpfile [OPCIÓN] -x VMLINUX --diskset=VMCORE1 --diskset=VMCORE2 [--diskset=VMCORE3 ..] DUMPFILE
makedumpfile -h
makedumpfile -v

DESCRIPCIÓN

Con kdump, la imagen de memoria del primer kernel (llamado "kernel en pánico") puede ser tomada como /proc/vmcore mientras se ejecuta el segundo kernel (llamado "kernel kdump" o "kernel de captura"). Este documento representa /proc/vmcore como VMCORE. makedumpfile crea un DUMPFILE pequeño comprimiendo los datos del volcado o excluyendo páginas innecesarias para el análisis, o ambas cosas. makedumpfile necesita la información de depuración del primer kernel para distinguir las páginas innecesarias analizando cómo el primer kernel usa la memoria. La información puede ser obtenida de VMLINUX o VMCOREINFO.

makedumpfile puede excluir los siguientes tipos de páginas al copiar VMCORE a DUMPFILE, y un usuario puede elegir qué tipo de páginas se excluirán.
- Páginas llenas de ceros
- Páginas de caché sin bandera privada (caché no privada)
- Páginas de caché con bandera privada (caché privada)
- Páginas de datos de procesos de usuario
- Páginas libres

makedumpfile proporciona dos formatos de DUMPFILE (formato ELF y formato comprimido de kdump). Por defecto, makedumpfile crea un DUMPFILE en formato comprimido de kdump. El formato comprimido de kdump solo es legible con la utilidad crash y puede ser más pequeño que el formato ELF debido al soporte de compresión. El formato ELF es legible con GDB y la utilidad crash. Si un usuario desea usar GDB, el formato DUMPFILE debe especificarse explícitamente como formato ELF.

Además de la exclusión de páginas innecesarias mencionada anteriormente, makedumpfile permite al usuario filtrar datos específicos del kernel. El archivo de configuración del filtro puede usarse para especificar símbolos de kernel/módulo y sus miembros que deben ser filtrados a través de la sintaxis del comando erase. makedumpfile lee la configuración del filtro y construye la lista de direcciones de memoria y sus tamaños después de procesar los comandos de filtro. Las ubicaciones de memoria que requieren ser filtradas son entonces envenenadas con el carácter 'X' (58 en hexadecimal). Consulte makedumpfile.conf(5) para el formato del archivo.

Las macros Eppic también pueden usarse para especificar símbolos de kernel y sus miembros que necesitan ser filtrados. Eppic proporciona semántica de C, incluyendo construcciones de lenguaje como sentencias condicionales, operadores lógicos y aritméticos, funciones, bucles anidados para recorrer y eliminar datos del kernel. --eppic requiere eppic_makedumpfile.so y la biblioteca eppic. eppic_makedumpfile.so puede ser compilado desde el código fuente de makedumpfile. Consulte http://code.google.com/p/eppic/ para compilar la biblioteca eppic libeppic.a y para más información sobre cómo escribir macros eppic. NOTA: actualmente Rust no es compatible con esta función.

Para analizar el uso de memoria del primer kernel, makedumpfile puede consultar VMCOREINFO en lugar de VMLINUX. VMCOREINFO contiene la información del primer kernel (tamaño de estructura, desplazamiento de campo, etc.), y VMCOREINFO es lo suficientemente pequeño como para ser incluido en el initrd del segundo kernel.
Si el segundo kernel se ejecuta en su initrd sin montar un sistema de archivos root, makedumpfile no puede consultar VMLINUX porque el initrd del segundo kernel no puede incluir un archivo grande como VMLINUX. Para solucionar el problema, makedumpfile crea VMCOREINFO de antemano, y consulta VMCOREINFO en lugar de VMLINUX mientras se ejecuta el segundo kernel.
VMCORE ha contenido VMCOREINFO desde linux-2.6.24, y un usuario no necesita especificar la opción -x ni -i.

Si el segundo kernel se ejecuta en su initrd sin montar ningún sistema de archivos, un usuario necesita transportar los datos del volcado a un host remoto. Para transportar los datos del volcado por SSH, makedumpfile saca los datos del volcado en el formato intermedio (formato aplanado) a la salida estándar. Al canalizar los datos de salida a SSH, un usuario puede transportar los datos del volcado a un host remoto. Tenga en cuenta que las herramientas de análisis (utilidad crash antes de la versión 5.1.2 o GDB) no pueden leer el formato aplanado directamente, por lo que en un host remoto los datos recibidos en formato aplanado deben ser reorganizados a un formato DUMPFILE legible por makedumpfile (o makedumpfile-R.pl).

makedumpfile puede leer un DUMPFILE en formato comprimido de kdump en lugar de VMCORE y volver a filtrarlo. Esta característica es útil en situaciones en las que los usuarios necesitan reducir el tamaño del archivo DUMPFILE para enviarlo a algún lugar por ftp/scp/etc. (Si todos los tipos de página, especificados por un nuevo dump_level, ya están excluidos de un DUMPFILE original, un nuevo DUMPFILE será el mismo que un DUMPFILE original.)
Por ejemplo, makedumpfile puede crear un DUMPFILE de dump_level 31 a partir de uno de dump_level 3 como el siguiente:
Ejemplo:
# makedumpfile -c -d 3 /proc/vmcore dumpfile.1
# makedumpfile -c -d 31 dumpfile.1 dumpfile.2

makedumpfile puede leer VMCORE(s) en tres tipos de formatos sadump: formato de partición única, formato diskset y formato de copia de seguridad de medios, y puede convertir cada uno de ellos al formato comprimido de kdump con procesamiento de filtrado y compresión. Tenga en cuenta que para los VMCORE(s) creados por sadump, siempre debe pasar VMLINUX con la opción -x. Además, para pasar múltiples VMCORE(s) creados en una configuración de diskset, debe usar la opción --diskset.

OPCIONES

-c,-l,-p,-z
Comprime los datos del volcado por página usando la siguiente biblioteca de compresión respectivamente:
-c : zlib
-l : lzo
-p : snappy
-z : zstd
(Las opciones -l, -p y -z requieren USELZO=on, USESNAPPY=on y USEZSTD=on respectivamente al compilar makedumpfile)
Un usuario no puede especificar esta opción con la opción -E, ya que el formato ELF no soporta datos comprimidos.
Ejemplo:
# makedumpfile -c -d 31 -x vmlinux /proc/vmcore dumpfile
-d nivel_volcado
Especifica el tipo de página innecesaria para el análisis.
Las páginas del tipo especificado no se copian a DUMPFILE. El tipo de página marcado en la siguiente tabla se excluye. Un usuario puede especificar múltiples tipos de página configurando la suma de cada tipo de página para el nivel_volcado. El máximo de nivel_volcado es 31. Tenga en cuenta que un nivel_volcado para filtrado de volcado Xen es 0 o 1 en una máquina distinta de x86_64. En una máquina x86_64, incluso un nivel_volcado de 2 o superior será efectivo si especifica el vmlinux de domain-0 con la opción -x. Entonces, las páginas se excluyen solo de domain-0.
Si se especifican múltiples niveles_volcado con el delimitador ',', makedumpfile reintenta crear DUMPFILE usando el siguiente nivel_volcado cuando el tamaño de un volcado excede el límite especificado con '-L' o cuando ocurre un error de "No hay espacio en el dispositivo". Por ejemplo, si nivel_volcado es "11,31" y makedumpfile falla con nivel_volcado 11, makedumpfile reintenta con nivel_volcado 31.
Ejemplo:
# makedumpfile -d 11 -x vmlinux /proc/vmcore dumpfile
# makedumpfile -d 11,31 -x vmlinux /proc/vmcore dumpfile
Nivel base:
nivel_volcado consta de cinco

--non-mmap
Nunca uses mmap(2) para leer VMCORE, incluso si es compatible con mmap(2). Generalmente, leer VMCORE con mmap(2) es más rápido que sin él, por lo que los usuarios comunes no necesitan especificar esta opción. Esta opción es principalmente para depuración.
Ejemplo:
# makedumpfile --non-mmap -d 31 -x vmlinux /proc/vmcore dumpfile
--xen-syms XEN-SYMS
Especifica los XEN-SYMS con información de depuración para analizar el uso de memoria de xen. Esta opción extrae la parte de xen y domain-0.
Ejemplo:
# makedumpfile -E --xen-syms xen-syms /proc/vmcore dumpfile
--xen-vmcoreinfo VMCOREINFO
Especifica VMCOREINFO en lugar de XEN-SYMS para analizar el uso de memoria de xen.
VMCOREINFO debe crearse de antemano con makedumpfile usando la opción -g, y contiene la información de xen.
Ejemplo:
# makedumpfile -E --xen-vmcoreinfo VMCOREINFO /proc/vmcore dumpfile
-X
Excluye todas las páginas de dominio de usuario de VMCORE de Xen kdump, y extrae la parte de xen y domain-0. Si VMCORE contiene VMCOREINFO para Xen, no es necesario especificar --xen-syms y --xen-vmcoreinfo.
Ejemplo:
# makedumpfile -E -X /proc/vmcore dumpfile
--xen_phys_start xen_phys_start_address
Esta opción es solo para x86_64. Especifica la xen_phys_start_address, si el código/datos de xen es reubicable y VMCORE no contiene xen_phys_start_address en el CRASHINFO. xen_phys_start_address se puede obtener de la línea de "Hypervisor code and data" en /proc/iomem. Por ejemplo, especifica 0xcee00000 como xen_phys_start_address si /proc/iomem es el siguiente:
-------------------------------------------------------
# cat /proc/iomem
...
cee00000-cfd99999 : Hypervisor code and data
...
-------------------------------------------------------

Ejemplo:
# makedumpfile -E -X --xen_phys_start 0xcee00000 /proc/vmcore dumpfile

--vtop virtual_address
Esta opción es útil cuando el usuario depura el problema de traducción de la dirección virtual. Si se especifica virtual_address, se imprime su dirección física. Facilita la depuración al comparar la salida de esta opción con la del subcomando "vtop" de la utilidad crash. La opción "--vtop" solo imprime la salida de traducción y no afecta la creación del volcado.
--dump-dmesg
Esta opción anula el comportamiento normal de makedumpfile. En lugar de comprimir y filtrar un VMCORE para hacerlo más pequeño, simplemente extrae el registro dmesg de un VMCORE y lo escribe en el LOGFILE especificado. Si un VMCORE no contiene VMCOREINFO para dmesg, es necesario especificar [-x VMLINUX] o [-i VMCOREINFO].

Ejemplo:
# makedumpfile --dump-dmesg /proc/vmcore dmesgfile
# makedumpfile --dump-dmesg -x vmlinux /proc/vmcore dmesgfile

--partial-dmesg
Esta opción hará que --dump-dmesg extraiga solo los registros dmesg desde que el búfer se borró por última vez en el kernel fallido, a través de "dmesg --clear", por ejemplo.
--mem-usage
Esta opción actualmente es compatible con x86_64, arm64, ppc64 y s390x. Se utiliza para mostrar los números de página del sistema actual en diferentes usos. Debe ejecutarse en el primer kernel. Con su ayuda, el usuario puede saber cuántas páginas se pueden volcar cuando se especifica un dump_level diferente. Analiza los segmentos de programa 'System Ram' y 'kernel text' de /proc/kcore, excluyendo el rango de crashkernel, y luego calcula el número de páginas de diferentes tipos por vmcoreinfo. Por lo tanto, actualmente se debe especificar /proc/kcore explícitamente.

Ejemplo:
# makedumpfile --mem-usage /proc/kcore

--diskset=VMCORE
Especifica múltiples VMCOREs creados en la configuración del conjunto de discos sadump tantas veces como el número de VMCOREs en orden ascendente de izquierda a derecha. Los VMCOREs se ensamblan en un único DUMPFILE.

Ejemplo:
# makedumpfile -x vmlinux --diskset=vmcore1 --diskset=vmcore2 dumpfile

-D
Imprime mensajes de depuración.
-h (--help)
Muestra el mensaje de ayuda y el estado de soporte de LZO/snappy (habilitado/deshabilitado).
-v
Muestra la versión de makedumpfile.
--check-params
Solo verifica si los parámetros de la línea de comandos son válidos o no, y sale. Es preferible que se proporcione como primer parámetro.
--dry-run
No escribe el archivo de volcado de salida mientras realiza las operaciones especificadas por otras opciones. Esta opción no se puede usar con las opciones --dump-dmesg, --reassemble y -g.
--show-stats
Muestra los mensajes del informe. Esta es una alternativa a habilitar el bit 4 en el nivel proporcionado a --message-level.

VARIABLES DE ENTORNO

TMPDIR
Esta variable de entorno se utiliza en el entorno del primer kernel para un archivo de mapa de bits de memoria temporal. Si su máquina tiene mucha memoria y usa un tmpfs pequeño en /tmp, makedumpfile puede fallar por falta de memoria debido a que makedumpfile crea un archivo de mapa de bits de memoria temporal muy grande en este caso. Para evitar este fallo, debe especificar la opción --work-dir para usar el sistema de archivos en el almacenamiento para el archivo del mapa de bits.

DIAGNÓSTICOS

makedumpfile sale con el siguiente valor.

0 : makedumpfile tuvo éxito.
1 : makedumpfile falló sin las siguientes razones.
2 : makedumpfile falló debido a la diferencia de versión entre VMLINUX y VMCORE.
