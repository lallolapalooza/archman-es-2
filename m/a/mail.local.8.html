MAIL.LOCAL(8) Manual del Administrador del Sistema MAIL.LOCAL(8)

NOMBRE

mail.local — almacena el correo en un buzón

SINOPSIS

mail.local [-Ll] [-f remitente] usuario ...

DESCRIPCIÓN

mail.local lee la entrada estándar hasta un fin de archivo y la anexa al archivo de correo de cada usuario. El usuario debe ser un nombre de usuario válido.

Las opciones son las siguientes:

-f remitente
Especifica el nombre del remitente.
-L
No crea un archivo nombredeusuario.lock mientras bloquea la cola.
-l
Por compatibilidad, solicita que se utilicen archivos llamados nombredeusuario.lock para el bloqueo. (Este es el comportamiento por defecto).

Los mensajes de correo individuales en el buzón están delimitados por una línea vacía seguida de una línea que comienza con la cadena “From ”. Una línea que contiene la cadena “From ”, el nombre del remitente y una marca de tiempo se antepone a cada mensaje de correo entregado. Se añade una línea en blanco a cada mensaje. Se antepone un signo de mayor que (‘>’) a cualquier línea del mensaje que pueda confundirse con una línea delimitadora de “From ”.

Se han realizado esfuerzos significativos para garantizar que mail.local actúe de la manera más segura posible si el directorio de cola tiene el modo 1777 o 755. El modo por defecto 755 es más seguro, pero impide que los clientes de correo utilicen el bloqueo estilo nombredeusuario.lock. El uso de 1777 es más flexible en un entorno de cola compartida NFS, por lo que muchos sitios lo utilizan. Sin embargo, conlleva algunos riesgos, como que los atacantes llenen el disco de la cola. Algunos de estos problemas pueden mitigarse haciendo de la cola un sistema de archivos separado y aplicándole cuotas. No se recomienda el uso de ningún modo que no sea 1777 y 755 para el directorio de cola, pero puede funcionar correctamente.

El buzón siempre se bloquea usando flock(2) mientras se anexan los correos. A menos que se especifique la opción -L, también se utiliza un archivo nombredeusuario.lock.

Si el servicio biff(1) es devuelto por getservbyname(3), se notifica al servidor biff del correo entregado.

ENTORNO

TZ
Se utiliza para establecer la zona horaria apropiada en la marca de tiempo.

ARCHIVOS

/tmp/local.XXXXXXXXXX
archivos temporales
/var/mail/usuario
directorio del buzón del usuario

ESTADO DE SALIDA

La utilidad mail.local sale con código  0 en caso de éxito y  >0 si ocurre un error.

VER TAMBIÉN

biff(1), mail(1), flock(2), getservbyname(3), comsat(8), smtpd(8)

HISTORIA

Un superconjunto de mail.local (que maneja la lectura del buzón así como la entrega de correo) apareció en la Versión 7 AT&T UNIX como el programa mail(1).

INCONVENIENTES

El uso de cuotas en /var/mail puede ser problemático si se utiliza sendmail(8) como MTA, ya que solicita a mail.local que entregue un mensaje a varios destinatarios si es posible. Esto causa problemas en un entorno de cuotas, ya que un mensaje puede entregarse a algunos usuarios pero no a otros debido a las cuotas de disco. A pesar de que el mensaje se entregó a algunos de los destinatarios, mail.local saldrá con un código de salida > 0, lo que hará que sendmail(8) intente la redistribución más tarde. Eso significa que algunos usuarios seguirán recibiendo el mismo mensaje cada vez que sendmail(8) ejecute su cola. Este problema no existe para los usuarios de smtpd(8).

Si está ejecutando sendmail(8) y tiene cuotas de disco en /var/mail, es imperativo que desactive el indicador del mailer “m” para el mailer ‘local’. Para hacer esto, localice la línea que comienza con “Mlocal” en /etc/mail/sendmail.cf y elimine la “m” de la sección de indicadores, denotada por “F=”. Alternativamente, puede anular los indicadores de mailer por defecto añadiendo la línea:

define(`LOCAL_MAILER_FLAGS', `rn9S')dnl

a su archivo “.mc” (este es el archivo fuente que se utiliza para generar /etc/mail/sendmail.cf).
