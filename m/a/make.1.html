MAKE(1) Comandos de usuario MAKE(1)

NOMBRE

make - Utilidad GNU Make para mantener grupos de programas

SINOPSIS

make [OPCIÓN]... [OBJETIVO]...

DESCRIPCIÓN

La utilidad make determinará automáticamente qué piezas de un programa grande necesitan ser recompiladas y emitirá los comandos para recompilarlas. El manual describe la implementación GNU de make, que fue escrita por Richard Stallman y Roland McGrath, y actualmente es mantenida por Paul Smith. Nuestros ejemplos muestran programas en C, ya que son muy comunes, pero puedes usar make con cualquier lenguaje de programación cuyo compilador pueda ejecutarse con un comando de shell. De hecho, make no se limita a programas. Puedes usarlo para describir cualquier tarea donde algunos archivos deban actualizarse automáticamente a partir de otros cuando estos últimos cambien.

Para prepararte para usar make, debes escribir un archivo llamado makefile que describa las relaciones entre los archivos de tu programa y proporcione comandos para actualizar cada archivo. En un programa, típicamente el archivo ejecutable se actualiza a partir de archivos objeto, que a su vez se crean compilando archivos fuente.

Una vez que exista un makefile adecuado, cada vez que cambies algunos archivos fuente, este simple comando de shell:

make

será suficiente para realizar todas las recompilaciones necesarias. El programa make utiliza la descripción del makefile y los tiempos de última modificación de los archivos para decidir cuáles de los archivos necesitan ser actualizados. Para cada uno de esos archivos, emite los comandos registrados en el makefile.

make ejecuta comandos en el makefile para actualizar uno o más objetivos, donde objetivo es típicamente un programa. Si no está presente la opción -f, make buscará los makefiles GNUmakefile, makefile y Makefile, en ese orden.

Normalmente deberías llamar a tu makefile makefile o Makefile. (Recomendamos Makefile porque aparece prominentemente cerca del principio de la lista del directorio, justo al lado de otros archivos importantes como README.) El primer nombre que se comprueba, GNUmakefile, no se recomienda para la mayoría de los makefiles. Debes usar este nombre si tienes un makefile específico de GNU Make y que no será entendido por otras versiones de make. Si makefile es '-', se leerá la entrada estándar.

make actualiza un objetivo si depende de archivos prerrequisito que han sido modificados desde que el objetivo se modificó por última vez, o si el objetivo no existe.

OPCIONES

-b, -m
Estas opciones se ignoran por compatibilidad con otras versiones de make.
-B, --always-make
Construir incondicionalmente todos los objetivos.
-C dir, --directory=dir
Cambiar al directorio dir antes de leer los makefiles o hacer cualquier otra cosa. Si se especifican múltiples opciones -C, cada una se interpreta en relación con la anterior: -C / -C etc es equivalente a -C /etc. Esto se usa típicamente con invocaciones recursivas de make.
-d
Imprimir información de depuración además del procesamiento normal. La información de depuración indica qué archivos se están considerando para reconstruir, qué tiempos de archivo se están comparando y con qué resultados, qué archivos necesitan ser reconstruidos, qué reglas implícitas se consideran y cuáles se aplican, todo lo interesante sobre cómo make decide qué hacer.
--debug[=FLAGS]
Imprimir información de depuración además del procesamiento normal. Si se omiten los FLAGS, el comportamiento es el mismo que si se especificara -d. Los FLAGS pueden ser cualquiera o todos los siguientes nombres, separados por comas o espacios. Solo el primer carácter es significativo: el resto puede omitirse: all para toda la salida de depuración (igual que usar -d), basic para depuración básica, verbose para depuración básica más detallada, implicit para mostrar operaciones de búsqueda de reglas implícitas, jobs para detalles sobre la invocación de comandos, makefile para depurar mientras se reconstruyen los makefiles, print muestra todas las recetas que se ejecutan incluso si son silenciosas, y why muestra la razón por la que make decidió reconstruir cada objetivo. Usa none para deshabilitar todas las banderas de depuración anteriores.
-e, --environment-overrides
Dar a las variables tomadas del entorno precedencia sobre las variables de los makefiles.
-E cadena, --eval cadena
Interpretar cadena usando la función eval, antes de analizar cualquier makefile.
-f archivo, --file=archivo, --makefile=ARCHIVO
Usar archivo como un makefile.
-i, --ignore-errors
Ignorar todos los errores en los comandos ejecutados para reconstruir archivos.
-I dir, --include-dir=dir
Especifica un directorio dir para buscar makefiles incluidos. Si se usan varios opciones -I para especificar varios directorios, los directorios se buscan en el orden especificado. A diferencia de los argumentos de otras banderas de make, los directorios dados con opciones -I pueden venir directamente después de la bandera: -Idir es válido, así como -I dir. Esta sintaxis está permitida por compatibilidad con la bandera -I del preprocesador C.
-j [trabajos], --jobs[=trabajos]
Especifica el número de trabajos (comandos) a ejecutar simultáneamente. Si hay más de una opción -j, la última es efectiva. Si la opción -j se da sin argumento, make no limitará el número de trabajos que pueden ejecutarse simultáneamente.
--jobserver-style=estilo
El estilo del servidor de trabajos a utilizar. El estilo puede ser uno de fifo, pipe o sem (solo Windows).
-k, --keep-going
Continuar tanto como sea posible después de un error. Mientras el objetivo que falló, y aquellos que dependen de él, no puedan ser reconstruidos, las otras dependencias de estos objetivos pueden procesarse de todos modos.
-l [carga], --load-average[=carga]
Especifica que no se deben iniciar nuevos trabajos (comandos) si hay otros trabajos en ejecución y el promedio de carga es al menos carga (un número de punto flotante). Sin argumento, elimina un límite de carga anterior.
-L, --check-symlink-times
Usar el mtime más reciente entre los enlaces simbólicos y el objetivo.
-n, --just-print, --dry-run, --recon
Imprimir los comandos que se ejecutarían, pero no ejecutarlos (excepto en ciertas circunstancias).
-o archivo, --old-file=archivo, --assume-old=archivo
No reconstruir el archivo archivo incluso si es más antiguo que sus dependencias, y no reconstruir nada debido a cambios en archivo. Esencialmente, el archivo se trata como muy antiguo y sus reglas se ignoran.
-O[tipo], --output-sync[=tipo]
Al ejecutar varios trabajos en paralelo con -j, asegurar que la salida de cada trabajo se recoja junta en lugar de intercalarse con la salida de otros trabajos. Si no se especifica tipo o es target, la salida de toda la receta para cada objetivo se agrupa. Si tipo es line, la salida de cada línea de comando dentro de una receta se agrupa. Si tipo

NAME

make - GNU Build Utility

SYNOPSIS

make [-b | -old-make] [-e] [-f Makefile] [-i] [-I dir] [-l load] [-m dir] [-n] [-o] [-p] [-q] [-r] [-R] [-s] [-S] [-t] [-v] [-w] [-W file] [MAKEFILES...] [TARGETS...]

DESCRIPTION

GNU make utility reads the current directory for files named Makefile or makefile. It then finds the target goal, which is, by default, the first target specified in the Makefiles. Make then determines all the files that need to be rebuilt to satisfy that goal. Finally, it issues commands to the shell to update the files as necessary.

A Makefile is a group of explicit rules about how to derive the targets. A rule normally consists of a target, its prerequisites, and the commands to be executed. A target is typically a file name.

When you invoke make, it is most common to simply type make and have it rebuild the first target defined in the Makefile. You can also specify targets on the command line.

OPTIONS

-b, --old-make
Pretend. Ignored.
-d
Print a lot of debugging information about why make decided what to do. This includes information obtained from the make program's internal database, and from the makefiles. This option is very verbose.
-e, --environment-override
Give variables defined in the environment precedence over variables defined in Makefiles. By default, variables defined in Makefiles override environment variables.
-f, --file=Makefile, --input=Makefile
Use the specified file as the makefile. If multiple -f options are given, make will use them in the order specified, processing them like a single sequence. If no -f option is given, make will try to use Makefile and makefile, in that order.
-i, --ignore-errors
All commands of make will be ignored. If any command returns a non-zero exit status the way make normally does, make will continue anyway.
-I, --include=dir
This option adds a directory to the list of directories that are searched for included Makefiles. For example, if you have a common set of macros in a file ../commonstuff/globals.mk and you want to include it, you would use -I ../commonstuff in your Makefile. This option can be used multiple times. If it is used after -f, the directories are added after the Makefile has been read.
-k, --keep-going
Like the default, but continue as much as possible. A command wanting to update files is run only if it depends on files that were successfully updated. So, if a command fails, make continues to rebuild the other targets that do not depend on the file that failed.
--no-keep-going
Cancel the effect of the -k option.
-l, --load-average=load
With this option, make will not run any more jobs if the system load average is greater than load. GNU make takes this value and compares it to the system load average and runs only that many jobs. For example, if you specify -l 4.0, make will not run more than 4 jobs simultaneously.
-m, --directory=dir
This option specifies a list of directories in which make will search for Makefiles. This is similar to the -I option but for Makefiles themselves rather than included Makefiles. You can specify this option multiple times. The directories are searched in the order given.
-n, --just-print, --dry-run
Print the commands that would be executed, but do not execute them.
-o
This option is ignored.
-O, --output-sync[=type]
Controls synchronization of output from recursive make invocations. The valid values for type are target, recursive, and none. If type is target, output is grouped by target. If type is recursive, output from an entire recursive make is grouped together. If type is none output synchronization is disabled.
-p, --print-data-base
Print the data base (rules and variable values) that results from reading the makefiles; then execute as usual or as otherwise specified. This also prints the version information given by the -v switch (see below). To print the data base without trying to remake any files, use make -p -f/dev/null.
-q, --question
``Question mode''. Do not run any commands, or print anything; just return an exit status that is zero if the specified targets are already up to date, nonzero otherwise.
-r, --no-builtin-rules
Eliminate use of the built-in implicit rules. Also clear out the default list of suffixes for suffix rules.
-R, --no-builtin-variables
Don't define any built-in variables.
-s, --silent, --quiet
Silent operation; do not print the commands as they are executed.
--no-silent
Cancel the effect of the -s option.
-S, --no-keep-going, --stop
Cancel the effect of the -k option.
-t, --touch
Touch files (mark them up to date without really changing them) instead of running their commands. This is used to pretend that the commands were done, in order to fool future invocations of make.
--trace
Information about the disposition of each target is printed (why the target is being rebuilt and what commands are run to rebuild it).
-v, --version
Print the version of the make program plus a copyright, a list of authors and a notice that there is no warranty.
-w, --print-directory
Print a message containing the working directory before and after other processing. This may be useful for tracking down errors from complicated nests of recursive make commands.
--no-print-directory
Turn off -w, even if it was turned on implicitly.
--shuffle[=MODE]
Enable shuffling of goal and prerequisite ordering. MODE is one of none to disable shuffle mode, random to shuffle prerequisites in random order, reverse to consider prerequisites in reverse order, or an integer <seed> which enables random mode with a specific seed value. If MODE is omitted the default is random.
-W file, --what-if=file, --new-file=file, --assume-new=file
Pretend that the target file has just been modified. When used with the -n flag, this shows you what would happen if you were to modify that file. Without -n, it is almost the same as running a touch command on the given file before running make, except that the modification time is changed only in the imagination of make.
--warn-undefined-variables
Warn when an undefined variable is referenced.

ESTADO DE SALIDA

GNU Make exits with a status of zero if all makefiles were successfully parsed and no targets that were built failed. A status of one will be returned if the -q flag was used and make determines that a target needs to be rebuilt. A status of two will be returned if any errors were encountered.

VER TAMBIÉN

The full documentation for make is maintained as a Texinfo manual. If the info and make programs are properly installed at your site, the command

info make

should give you access to the complete manual.

ERRORES

See the chapter ``Problems and Bugs'' in The GNU Make Manual.
