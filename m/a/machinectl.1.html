NOMBRE

machinectl - Controla el gestor de máquinas de systemd

SINOPSIS

machinectl [OPCIONES...] {COMANDO} [NOMBRE...]

DESCRIPCIÓN

machinectl puede ser utilizado para inspeccionar y controlar el estado del gestor de registro de máquinas y contenedores de systemd(1) systemd-machined.service(8).

machinectl puede ser utilizado para ejecutar operaciones en máquinas e imágenes. Las máquinas en este sentido se consideran instancias en ejecución de:

•Máquinas Virtuales (VMs) que virtualizan hardware para ejecutar instancias completas de sistema operativo (SO) (incluyendo sus kernels) en un entorno virtualizado sobre el SO anfitrión.
•Contenedores que comparten el hardware y el kernel del SO anfitrión, para ejecutar instancias de espacio de usuario del SO sobre el SO anfitrión.
•El propio sistema anfitrión.

Las máquinas se identifican por nombres que siguen las mismas reglas que los nombres de host de UNIX y DNS. Para detalles, véase más abajo.

Las máquinas se instancian a partir de imágenes de disco o sistema de archivos que frecuentemente — pero no necesariamente — llevan el mismo nombre que las máquinas que se ejecutan desde ellas. Las imágenes en este sentido pueden ser:

•Árboles de directorios que contienen un SO, incluyendo los directorios de nivel superior /usr/, /etc/, etc.
•Subvolúmenes de btrfs que contienen árboles de SO, similares a árboles de directorios regulares.
•Archivos binarios de imagen de disco "raw" que contienen tablas de particiones MBR o GPT y sistemas de archivos Linux.
•Similarmente, dispositivos de bloque que contienen tablas de particiones MBR o GPT y sistemas de archivos.
•El árbol del sistema de archivos del propio SO anfitrión.

Las imágenes pueden ser descargadas, importadas y exportadas a través de la herramienta importctl(1).

COMANDOS

Se entienden los siguientes comandos:

Comandos de Máquina

list

Lista las máquinas virtuales y contenedores en ejecución (en línea) actualmente. Para enumerar imágenes de máquina que pueden ser iniciadas, use list-images (ver más abajo). Tenga en cuenta que este comando oculta la máquina especial ".host" por defecto. Use la opción --all para mostrarla.

Añadido en la versión 206.

status NOMBRE...

Muestra información de estado en tiempo de ejecución sobre una o más máquinas virtuales y contenedores, seguida de los datos de registro más recientes de la journal. Esta función está destinada a generar una salida legible por humanos. Si busca una salida interpretable por máquina, use show en su lugar. Tenga en cuenta que los datos de registro mostrados son reportados por el gestor de máquinas virtuales o contenedores, y frecuentemente contienen la salida de la consola de la máquina, pero no necesariamente los contenidos de la journal de la máquina en sí.

Añadido en la versión 206.

show [NOMBRE...]

Muestra propiedades de una o más máquinas virtuales o contenedores registrados o del propio gestor. Si no se especifica ningún argumento, se mostrarán las propiedades del gestor. Si se especifica un NOMBRE, se mostrarán las propiedades de esta máquina virtual o contenedor. Por defecto, se suprimen las propiedades vacías. Use --all para mostrarlas también. Para seleccionar propiedades específicas a mostrar, use --property=. Este comando está destinado a ser utilizado cuando se requiere una salida interpretable por máquina, y no imprime el árbol de grupos de control ni las entradas de journal. Use status si busca una salida formateada legible por humanos.

Añadido en la versión 206.

start NOMBRE...

Inicia un contenedor como un servicio del sistema, usando systemd-nspawn(1). Esto inicia systemd-nspawn@.service, instanciado para el nombre de máquina especificado, similar al efecto de systemctl start sobre el nombre del servicio. systemd-nspawn busca una imagen de contenedor por el nombre especificado en /var/lib/machines/ (y otras rutas de búsqueda, ver más abajo) y la ejecuta. Use list-images (ver más abajo) para listar las imágenes de contenedor disponibles para iniciar.

Tenga en cuenta que systemd-machined.service(8) también interactúa con una variedad de otros gestores de contenedores y VMs, systemd-nspawn es solo una implementación de ello. La mayoría de los comandos disponibles en machinectl pueden ser utilizados en contenedores o VMs controlados por otros gestores, no solo systemd-nspawn. Iniciar VMs e imágenes de contenedor en esos gestores requiere herramientas específicas del gestor.

Para interactuar con un contenedor en la línea de comandos con acceso completo a la consola del contenedor, por favor, invoque systemd-nspawn directamente. Para detener un contenedor en ejecución use machinectl poweroff.

Añadido en la versión 219.

login [NOMBRE]

Abre una sesión interactiva de inicio de terminal en un contenedor o en el host local. Si se proporciona un argumento, se refiere al contenedor de máquina al que conectarse. Si no se especifica ninguno, o el nombre del contenedor se especifica como una cadena vacía, o se especifica el nombre especial de máquina ".host" (ver más abajo), la conexión se realiza al host local. Esto creará una conexión TTY a un contenedor específico o al host local y solicitará la ejecución de un getty en él. Tenga en cuenta que esto solo es compatible con contenedores que ejecutan systemd(1) como sistema de inicio.

Este comando abrirá un prompt de inicio de sesión completo en el contenedor o en el host local, que luego pedirá nombre de usuario y contraseña. Use shell (ver más abajo) o systemd-run(1) con la opción --machine= para invocar directamente un solo comando, ya sea interactivamente o en segundo plano.

Añadido en la versión 209.

shell [[NOMBRE@]NOMBRE [RUTA [ARGUMENTOS...]]]

Abre una sesión de shell interactiva en un contenedor o en el host local. El primer argumento se refiere al contenedor de máquina al que conectarse. Si no se especifica ninguno, o el nombre de la máquina se especifica como una cadena vacía, o se especifica el nombre especial de máquina ".host" (ver más abajo), la conexión se realiza al host local. Esto funciona de manera similar a login, pero invoca inmediatamente un proceso de usuario. Este comando ejecuta el ejecutable especificado con los argumentos especificados, o el shell por defecto para el usuario si no se especifica ninguno, o /bin/sh si no se encuentra ningún shell por defecto. Por defecto, --uid=, o prefijando el nombre de la máquina con un nombre de usuario y un carácter "@", se puede seleccionar un usuario diferente. Use --setenv= para establecer variables de entorno para el proceso ejecutado.

Tenga en cuenta que machinectl shell no propaga el código de salida/estado del proceso de shell invocado. Use systemd-run en su lugar si esa información es requerida (ver más abajo).

Usar el comando shell sin argumentos (invocando así el shell o comando ejecutado en el host local), es en muchos sentidos similar a una sesión de su(1), pero, a diferencia de su, aísla completamente la nueva sesión de la sesión original, de modo que no comparte ninguna propiedad de proceso o sesión y se encuentra en un estado limpio y bien definido. Será rastreado en nuevas sesiones utmp, de inicio de sesión, de auditoría, de seguridad y de keyring, y no heredará ninguna variable de entorno ni límite de recursos, entre otras propiedades.

Tenga en cuenta que systemd-run(1) con su opción --machine= puede ser utilizado en lugar del comando machinectl shell, y permite la operación no interactiva, una configuración más detallada y de bajo nivel de la unidad invocada, así como el acceso a la información del tiempo de ejecución y del código de salida/estado del proceso invocado. En particular, use la opción --wait de systemd-run para propagar la información del estado de salida del proceso invocado. Use la opción --pty de systemd-run para adquirir un shell interactivo, de manera similar a machinectl shell. En general, systemd-run es preferible para fines de scripting. Sin embargo, tenga en cuenta que systemd-run puede requerir privilegios más altos que machinectl shell.

Añadido en la versión 225.

stop NOMBRE...

Detiene una máquina virtual o contenedor en ejecución, usando la misma lógica que systemctl stop aplicada a systemd-nspawn@.service. Esto envía una señal SIGTERM al proceso principal del contenedor, y si este no termina en un tiempo razonable, envía SIGKILL.

Añadido en la versión 206.

terminate NOMBRE...

Termina una máquina virtual o contenedor en ejecución inmediatamente, enviando la señal SIGKILL al proceso principal del contenedor.

Añadido en la versión 206.

kill NOMBRE [SIGNAL]

Envía una señal a la máquina virtual o contenedor en ejecución especificado. Por defecto se envía SIGKILL. Utilice esta opción para enviar cualquier otra señal.

Añadido en la versión 211.

set-password [NOMBRE]

Establece la contraseña de usuario root en una máquina virtual o contenedor. Si se omite el argumento, se utiliza la máquina registrada local ".host". El nombre de usuario y la contraseña se solicitan interactivamente. El cambio de contraseña se aplica a la imagen subyacente y será visible en futuras ejecuciones de la máquina.

Añadido en la versión 209.

set-hostname HOSTNAME [NOMBRE]

Establece el nombre de host de una máquina virtual o contenedor. Si se omite el argumento, se utiliza la máquina registrada local ".host". El cambio se aplica a la ejecución actual de la máquina y se guardará para futuras ejecuciones.

Añadido en la versión 215.

oom NOMBRE...

Ejecuta una operación de falta de memoria (OOM) en una máquina virtual o contenedor. Esto sólo es relevante para máquinas que se ejecutan en sistemas que soportan el control de OOM (como el control cgroups OOM). Esto resulta en la terminación de uno o más procesos dentro de la máquina.

Añadido en la versión 211.

terminate-all [--since=TIME]

Termina todas las máquinas virtuales y contenedores en ejecución. Use la opción --since= para limitar la operación a máquinas iniciadas hace menos de TIME.

Añadido en la versión 219.

remove NOMBRE...

Elimina una o más máquinas virtuales o contenedores registrados. Solo se pueden eliminar máquinas que no están actualmente en ejecución. Para eliminar una imagen de máquina de disco, use machinectl delete.

IDENTIFICACIÓN DE MÁQUINA

Los nombres de máquina pueden contener letras (a-z, A-Z), números (0-9), guiones (-) y puntos (.). Sin embargo, no deben empezar ni terminar con un guion o un punto. La longitud máxima de un nombre de máquina es de 255 caracteres.

El nombre de máquina especial .host se refiere al sistema anfitrión local.

Los nombres de máquina se utilizan como identificadores para:

•Unidades de servicio de systemd (por ejemplo, systemd-nspawn@mycontainer.service).
•Grupos de control de systemd (por ejemplo, machine.slice/mycontainer.scope).
•Directorios en /run/machines/ (por ejemplo, /run/machines/mycontainer).

Además de los nombres de host, las máquinas también pueden ser identificadas por sus nombres de unidad de systemd (por ejemplo, systemd-nspawn@mycontainer.service).

OPCIONES

Los siguientes conjuntos de opciones se entienden:

Opciones Generales

-h, --help

Muestra un mensaje de ayuda y sale.

--version

Muestra la información de la versión y sale.

--no-pager

Deshabilita el uso de paginador para la salida de texto.

-H, --machine NOMBRE

Se conecta a una máquina remota o contenedora. Si se utiliza con un nombre de host, se conecta al servicio remoto systemd. Si se utiliza con un nombre de máquina, se conecta al gestor de máquinas local. Tenga en cuenta que el gestor de máquinas de systemd es una interfaz de bajo nivel, y la mayoría de las operaciones sólo están disponibles localmente.

-M, --user NOMBRE

Se conecta a una máquina remota controlada por systemd-machined. Este comando sólo funciona con systemd-machined.

-q, --quiet

Suprime la salida informativa.

-o, --output FORMATO

Cambia el formato de salida. Actualmente sólo se admite `json`.

-p, --property NOMBRE

Selecciona una propiedad específica para mostrar con el comando `show`.

-a, --all

Muestra todas las propiedades, incluidas las vacías.

Opciones de Bus

--user-bus

Se conecta al bus de sistema del usuario.

--system-bus

Se conecta al bus de sistema.

ESTADO DE SALIDA

Los comandos de machinectl devuelven 0 si el comando tuvo éxito, y un valor distinto de cero si ocurrió un error.

EJEMPLOS

Listar todas las máquinas en ejecución:

$ machinectl list

Mostrar el estado de una máquina específica:

$ machinectl status mycontainer

Iniciar una máquina:

$ machinectl start mycontainer

Detener una máquina:

$ machinectl stop mycontainer

Eliminar una máquina registrada:

$ machinectl remove mycontainer

Listar todas las imágenes de máquina disponibles:

$ machinectl list-images --all

Eliminar una imagen de máquina:

$ machinectl delete myimage

Abrir un shell en la máquina anfitriona:

$ machinectl shell .host

Abrir un shell en un contenedor:

$ machinectl shell mycontainer

Abrir un shell como un usuario específico en un contenedor:

$ machinectl shell mycontainer@user

Ejecutar un comando en un contenedor y esperar a que termine:

$ systemd-run --machine=mycontainer --wait some-command

Descargar una imagen de máquina:

$ machinectl pull fedora-latest

Crear una nueva imagen de máquina vacía:

$ machinectl mkdir new-container

Establecer la contraseña de root para una máquina:

$ machinectl set-password mycontainer

Comandos de Gestión de Contenedores

enable NAME...

Habilita uno o más contenedores para que se inicien automáticamente en el arranque del sistema. Esto es similar a usar systemctl enable en el nombre del servicio.

Este comando recarga implícitamente la configuración del gestor del sistema después de completar la operación. Ten en cuenta que este comando no inicia ni apaga implícitamente los contenedores que se están operando. Si esto es deseado, combina el comando con el modificador --now.

Añadido en la versión 219.

disable NAME...

Deshabilita uno o más contenedores para que no se inicien automáticamente en el arranque del sistema. Esto es similar a usar systemctl disable en el nombre del servicio.

Este comando recarga implícitamente la configuración del gestor del sistema después de completar la operación. Ten en cuenta que este comando no inicia ni apaga implícitamente los contenedores que se están operando. Si esto es deseado, combina el comando con el modificador --now.

Añadido en la versión 219.

poweroff NAME...

Apaga uno o más contenedores. Esto activará un apagado enviando SIGRTMIN+4 al proceso init del contenedor, lo que provoca que los sistemas init compatibles con systemd se apaguen limpiamente. Usa stop como alias para poweroff. Esta operación no funciona en contenedores que no ejecutan un sistema init compatible con systemd(1), como sysvinit. Usa terminate (ver abajo) para terminar inmediatamente un contenedor o VM, sin apagarlo limpiamente.

Añadido en la versión 212.

reboot NAME...

Reinicia uno o más contenedores. Esto activará un reinicio enviando SIGINT al proceso init del contenedor, lo que es aproximadamente equivalente a presionar Ctrl+Alt+Del en un sistema no contenedorizado, y es compatible con contenedores que ejecutan cualquier sistema de gestión. Usa restart como alias para reboot.

Añadido en la versión 209.

terminate NAME...

Termina inmediatamente una máquina virtual o un contenedor, sin apagarlo limpiamente. Esto mata todos los procesos de la máquina virtual o el contenedor y desasigna todos los recursos adjuntos a esa instancia. Usa poweroff para emitir una solicitud de apagado limpio.

Añadido en la versión 206.

kill NAME...

Envía una señal a uno o más procesos de la máquina virtual o contenedor. Esto se refiere a los procesos vistos por el host, no a los procesos dentro de la máquina virtual o el contenedor. Usa --kill-whom= para seleccionar qué proceso matar. Usa --signal= para seleccionar la señal a enviar.

Añadido en la versión 206.

bind NAME PATH [PATH]

Monta por enlace un archivo o directorio del host en el contenedor especificado. El primer argumento de ruta es el archivo o directorio fuente en el host, el segundo argumento de ruta es el archivo o directorio destino en el contenedor. Cuando este último se omite, la ruta de destino en el contenedor es la misma que la ruta de origen en el host. Cuando se combina con el modificador --read-only, se crea un montaje por enlace de solo lectura. Cuando se combina con el modificador --mkdir, la ruta de destino se crea primero antes de aplicar el montaje. Ten en cuenta que esta opción actualmente solo se admite para contenedores systemd-nspawn(1), y solo si no se usa el espacio de nombres de usuario (--private-users). Este comando admite el montaje por enlace de directorios, archivos regulares, nodos de dispositivos, nodos de sockets AF_UNIX y nodos FIFO.

MACHINE AND IMAGE NAMES

The machinectl tool operates on machines and images whose names must be chosen following strict rules. Machine names must be suitable for use as hostnames following a conservative subset of DNS and UNIX/Linux semantics. Specifically, they must consist of one or more non-empty label strings, separated by dots. No leading or trailing dots are allowed. No sequences of multiple dots are allowed. The label strings may only consist of alphanumeric characters as well as the dash. The maximum length of a machine name is 64 characters.

A special machine with the name ".host" refers to the running host system itself. This is useful for execution operations or inspecting the host system as well. Note that machinectl list will not show this special machine unless the --all switch is specified.

Requirements on image names are less strict, however, they must be valid UTF-8, must be suitable as file names (hence not be the single or double dot, and not include a slash), and may not contain control characters. Since many operations search for an image by the name of a requested machine, it is recommended to name images in the same strict fashion as machines.

A special image with the name ".host" refers to the image of the running host system. It hence conceptually maps to the special ".host" machine name described above. Note that machinectl list-images will not show this special image either, unless --all is specified.

FILES AND DIRECTORIES

Machine images are preferably stored in /var/lib/machines/, but are also searched for in /usr/local/lib/machines/ and /usr/lib/machines/. For compatibility reasons, the directory /var/lib/container/ is searched, too. Note that images stored below /usr/ are always considered read-only. It is possible to symlink machines images from other directories into /var/lib/machines/ to make them available for control with machinectl.

Note that some image operations are only supported, efficient or atomic on btrfs file systems.

Disk images are understood by systemd-nspawn(1) and machinectl in three formats:

•A simple directory tree, containing the files and directories of the container to boot.
•Subvolumes (on btrfs file systems), which are similar to the simple directories, described above. However, they have additional benefits, such as efficient cloning and quota reporting.
•"Raw" disk images, i.e. binary images of disks with a GPT or MBR partition table. Images of this type are regular files with the suffix ".raw".

See systemd-nspawn(1) for more information on image formats, in particular its --directory= and --image= options.

EXAMPLES

Example 1. Download an Ubuntu RAW image, set a root password in it, start it as a service

# importctl pull-raw -mN \
      https://cloud-images.ubuntu.com/jammy/current/jammy-server-cloudimg-amd64-disk-kvm.img \
      jammy
# systemd-firstboot --image=/var/lib/machines/jammy.raw --prompt-root-password --force
# machinectl start jammy
# machinectl login jammy

This downloads the specified .raw image and makes it available under the local name "jammy". Then, a root password is set with systemd-firstboot(1). Afterwards the machine is started as system service. With the last command a login prompt into the container is requested.

ENVIRONMENT

$SYSTEMD_LOG_LEVEL

The maximum log level of emitted messages (messages with a higher log level, i.e. less important ones, will be suppressed). Takes a comma-separated list of values. A value may be either one of (in order of decreasing importance) emerg, alert, crit, err, warning, notice, info, debug, or an inte
ger en el rango 0...7. Consulte syslog(3) para obtener más información. Cada valor puede opcionalmente ir precedido de uno de console, syslog, kmsg o journal seguido de dos puntos para establecer el nivel de registro máximo para ese destino de registro específico (por ejemplo, SYSTEMD_LOG_LEVEL=debug,console:info especifica registrar a nivel de depuración excepto cuando se registra en la consola, que debe estar en nivel de información). Tenga en cuenta que el nivel de registro máximo global tiene prioridad sobre cualquier nivel de registro máximo por destino.

$SYSTEMD_LOG_COLOR

Un booleano. Si es verdadero, los mensajes escritos en el tty se colorearán según la prioridad.

Esta configuración solo es útil cuando los mensajes se escriben directamente en la terminal, ya que journalctl(1) y otras herramientas que muestran los registros colorearán los mensajes según el nivel de registro por sí mismas.

$SYSTEMD_LOG_TIME

Un booleano. Si es verdadero, los mensajes de registro de la consola se antepondrán con una marca de tiempo.

Esta configuración solo es útil cuando los mensajes se escriben directamente en la terminal o en un archivo, ya que journalctl(1) y otras herramientas que muestran los registros añadirán marcas de tiempo basándose en los metadatos de la entrada por sí mismas.

$SYSTEMD_LOG_LOCATION

Un booleano. Si es verdadero, los mensajes se antepondrán con un nombre de archivo y un número de línea en el código fuente donde se origina el mensaje.

Tenga en cuenta que la ubicación del registro a menudo se adjunta como metadatos a las entradas del journal de todos modos. Incluirla directamente en el texto del mensaje puede ser conveniente al depurar programas.

$SYSTEMD_LOG_TID

Un booleano. Si es verdadero, los mensajes se antepondrán con el ID de hilo numérico (TID) actual.

Tenga en cuenta que esta información se adjunta como metadatos a las entradas del journal de todos modos. Incluirla directamente en el texto del mensaje puede ser conveniente al depurar programas.

$SYSTEMD_LOG_TARGET

El destino de los mensajes de registro. Uno de console (registrar en el tty conectado), console-prefixed (registrar en el tty conectado pero con prefijos que codifican el nivel de registro y la "facilidad", consulte syslog(3), kmsg (registrar en el búfer de registro circular del kernel), journal (registrar en el journal), journal-or-kmsg (registrar en el journal si está disponible y en kmsg en caso contrario), auto (determinar el destino de registro apropiado automáticamente, el predeterminado), null (desactivar la salida de registro).

$SYSTEMD_LOG_RATELIMIT_KMSG

Si se debe limitar la velocidad de kmsg o no. Toma un booleano. Por defecto es "true". Si está deshabilitado, systemd no limitará la velocidad de los mensajes escritos en kmsg.

$SYSTEMD_PAGER, $PAGER

Paginador a utilizar cuando no se proporciona --no-pager. Se utiliza $SYSTEMD_PAGER si está establecido; de lo contrario, se utiliza $PAGER. Si ni $SYSTEMD_PAGER ni $PAGER están establecidos, se prueban una serie de implementaciones de paginadores conocidos en orden, incluyendo less(1) y more(1), hasta que se encuentre uno. Si no se descubre ninguna implementación de paginador, no se invoca ningún paginador. Establecer estas variables de entorno en una cadena vacía o en el valor "cat" equivale a pasar --no-pager.

Nota: si no está establecido $SYSTEMD_PAGERSECURE, $SYSTEMD_PAGER y $PAGER solo se pueden usar para deshabilitar el paginador (con "cat" o ""), y de lo contrario se ignoran.

$SYSTEMD_LESS

Sobrescribe las opciones pasadas a less (por defecto "FRSXMK").

Los usuarios pueden querer cambiar dos opciones en particular:

K

Esta opción instruye al paginador a salir inmediatamente cuando se presiona Ctrl+C. Para permitir que less maneje Ctrl+C por sí mismo y vuelva al prompt de comandos del paginador, desactive esta opción.

Si el valor de $SYSTEMD_LESS no incluye "K", y el paginador invocado es less, Ctrl+C será ignorado por el ejecutable, y deberá ser manejado por el paginador.

X

Esta opción instruye al paginador a no enviar cadenas de inicialización y desinicialización de termcap a la terminal. Está establecida por defecto para permitir que la salida del comando permanezca visible en la terminal incluso después de que el paginador salga. Sin embargo, esto impide que algunas funcionalidades del paginador funcionen, en particular, la salida paginada no se puede desplazar con el ratón.

Tenga en cuenta que establecer la variable de entorno normal $LESS no tiene efecto para las invocaciones de less por herramientas de systemd.

Consulte less(1) para obtener más discusión.

$SYSTEMD_LESSCHARSET

Sobrescribe el conjunto de caracteres pasado a less (por defecto "utf-8", si se determina que la terminal invocadora es compatible con UTF-8).

Tenga en cuenta que establecer la variable de entorno normal $LESSCHARSET no tiene efecto para las invocaciones de less por herramientas de systemd.

$SYSTEMD_PAGERSECURE

Comandos de paginadores comunes como less(1), además de "paginar", es decir, desplazarse por la salida, admiten abrir o escribir en otros archivos y ejecutar comandos de shell arbitrarios. Cuando se invocan comandos con privilegios elevados, por ejemplo, bajo sudo(8) o pkexec(1), el paginador se convierte en un límite de seguridad. Se debe tener cuidado de que solo se utilicen programas con funcionalidad estrictamente limitada como paginadores, y no se permitan características interactivas no deseadas como la apertura o creación de nuevos archivos o el inicio de subprocesos. El "modo seguro" para el paginador puede habilitarse como se describe a continuación, si el paginador lo admite (la mayoría de los paginadores no están escritos de manera que tengan esto en cuenta). Se recomienda habilitar explícitamente el "modo seguro" o deshabilitar completamente el paginador usando --no-pager o PAGER=cat al permitir que usuarios no confiables ejecuten comandos con privilegios elevados.

Esta opción toma un argumento booleano. Cuando se establece en verdadero, el "modo seguro" del paginador está habilitado. En "modo seguro", se establecerá LESSSECURE=1 al invocar el paginador, lo que instruye al paginador a deshabilitar los comandos que abren o crean nuevos archivos o inician nuevos subprocesos. Actualmente, solo se sabe que less(1) entiende esta variable e implementa el "modo seguro".

Cuando se establece en falso, no se impone ninguna limitación al paginador. Establecer SYSTEMD_PAGERSECURE=0 o no eliminarlo del entorno heredado puede permitir al usuario invocar comandos arbitrarios.

Cuando $SYSTEMD_PAGERSECURE no está establecido, las herramientas de systemd intentan determinar automáticamente si se debe habilitar el "modo seguro" y si el paginador lo admite. El "modo seguro" se habilita si la UID efectiva no es la misma que la del propietario de la sesión de inicio de sesión, consulte geteuid(2) y sd_pid_get_owner_uid(3), o cuando se ejecuta bajo sudo(8) o herramientas similares (se establece $SUDO_UID [1]). En esos casos, se establecerá SYSTEMD_PAGERSECURE=1 y los paginadores que no se sabe que implementen el "modo seguro" no se utilizarán en absoluto. Tenga en cuenta que esta autodetección solo cubre los mecanismos más comunes para elevar privilegios y está destinada a la conveniencia. Se recomienda establecer explícitamente $SYSTEMD_PAGERSECURE o deshabilitar el paginador.

Tenga en cuenta que si las variables $SYSTEMD_PAGER o $PAGER deben ser respetadas, aparte de para deshabilitar el paginador, también se debe establecer $SYSTEMD_PAGERSECURE.

$SYSTEMD_COLORS

Toma un argumento booleano. Cuando es verdadero, systemd y utilidades relacionadas usarán colores en su salida, de lo contrario la salida será monocromática. Además, la variable puede tomar uno de los siguientes valores especiales: "16", "256" para restringir el uso de colores a los 16 o 256 colores ANSI base, respectivamente. Esto se puede especificar para anular la decisión automática basada en $TERM y a qué está conectada la consola.

$SYSTEMD_URLIFY

El valor debe ser un booleano. Controla si se deben generar enlaces clickables en la salida para emuladores de terminal que lo admitan. Esto se puede especificar para anular la decisión que systemd toma basándose en $TERM y otras condiciones.

CONTROL DE MÁQUINAS DE SYSTEMD

NAME

machinectl — control de máquinas de systemd

SYNOPSIS

machinectl [OPCIONES] COMMAND

DESCRIPTION

machinectl es una utilidad para controlar y gestionar máquinas gestoras de systemd (machinectl.service(5)). Permite a los usuarios interactuar con las máquinas creadas y gestionadas por systemd-machined(8).

COMMANDS

Los siguientes comandos están disponibles:

list
Lista todas las máquinas que se están ejecutando actualmente.
NAME
Muestra información detallada sobre la máquina especificada por NAME.
NAME command ...
Ejecuta un comando en la máquina especificada por NAME. El comando y sus argumentos se pasan directamente a la máquina.
NAME shell
Inicia una shell interactiva dentro de la máquina especificada por NAME.
NAME login
Inicia una sesión de inicio de sesión interactiva dentro de la máquina especificada por NAME.
NAME terminate
Termina la máquina especificada por NAME.
NAME stop
Detiene la máquina especificada por NAME. Esto es similar a terminate, pero permite que la máquina se reinicie automáticamente si está configurada para hacerlo.
NAME start ...
Inicia una nueva máquina. Los argumentos que siguen a start se pasan a systemd-nspawn(1) y se utilizan para configurar y lanzar la máquina.
NAME pull ...
Descarga una imagen de máquina de un registro remoto. Los argumentos que siguen a pull se pasan a systemd-nspawn(1).
NAME add ...
Añade un nuevo dispositivo de almacenamiento a la máquina especificada por NAME. Los argumentos que siguen a add se pasan a systemd-nspawn(1).
NAME remove ...
Elimina un dispositivo de almacenamiento de la máquina especificada por NAME. Los argumentos que siguen a remove se pasan a systemd-nspawn(1).
NAME bind ...
Vincula un directorio del host a un directorio dentro de la máquina especificada por NAME. Los argumentos que siguen a bind se pasan a systemd-nspawn(1).
NAME unbind ...
Elimina un vínculo de directorio de la máquina especificada por NAME. Los argumentos que siguen a unbind se pasan a systemd-nspawn(1).
NAME snapshot ...
Crea una instantánea de la máquina especificada por NAME. Los argumentos que siguen a snapshot se pasan a systemd-nspawn(1).
NAME revert ...
Revierte la máquina especificada por NAME a una instantánea anterior. Los argumentos que siguen a revert se pasan a systemd-nspawn(1).
NAME clone ...
Clona la máquina especificada por NAME. Los argumentos que siguen a clone se pasan a systemd-nspawn(1).
NAME delete
Elimina la máquina especificada por NAME y su imagen de disco asociada.
NAME enter ...
Entra en la máquina especificada por NAME. Esto es similar a shell, pero permite especificar un comando a ejecutar en lugar de iniciar una shell interactiva.
NAME copy-from ...
Copia un archivo o directorio desde la máquina especificada por NAME al host. Los argumentos que siguen a copy-from especifican el origen en la máquina y el destino en el host.
NAME copy-to ...
Copia un archivo o directorio desde el host a la máquina especificada por NAME. Los argumentos que siguen a copy-to especifican el origen en el host y el destino en la máquina.

OPTIONS

Las siguientes opciones están disponibles:

-h, --help
Muestra un mensaje de ayuda y sale.
-v, --version
Muestra la versión e información de licencia y sale.
-q, --quiet
Suprime la salida informativa.
-H, --host=HOST
Controla una máquina remota en el host especificado por HOST.
-M, --machine=MACHINE
Selecciona una máquina específica para interactuar. Esto es útil cuando se tiene varias máquinas con el mismo nombre. Si no se especifica, se selecciona la máquina por defecto.

EXIT STATUS

Los códigos de salida son los definidos por systemd.service(5).

EXAMPLES

machinectl list

Lista todas las máquinas en ejecución.

machinectl my-container command /bin/bash

Ejecuta /bin/bash dentro de la máquina llamada my-container.

machinectl my-container shell

Abre una shell interactiva dentro de la máquina llamada my-container.

machinectl pull fedora-latest fedora

Descarga la última imagen de Fedora y la llama fedora.

ENVIRONMENT

machinectl respeta las siguientes variables de entorno:

$MACHINECTL_DIR
Especifica el directorio donde se almacenan las imágenes y configuraciones de las máquinas. Si no se establece, se utiliza /var/lib/machines.
