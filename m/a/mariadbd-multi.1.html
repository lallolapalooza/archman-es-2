MARIADBD-MULTI(1) Sistema de bases de datos MariaDB MARIADBD-MULTI(1)

NOMBRE

mariadbd-multi - gestionar múltiples servidores MariaDB (mariadbd-multi es ahora un enlace simbólico a mariadbd-multi)

SINOPSIS

mariadbd-multi [opciones] {start|stop|report} [GNR[,GNR] ...]

DESCRIPCIÓN

mariadbd-multi está diseñado para gestionar varios procesos mariadbd que escuchan conexiones en diferentes archivos de socket Unix y puertos TCP/IP. Puede iniciar o detener servidores, o informar de su estado actual.

mariadbd-multi busca grupos llamados [mariadbdN] en my.cnf (o en el archivo especificado por la opción --config-file). N puede ser cualquier entero positivo. Este número se denomina en la siguiente discusión número de grupo de opciones, o GNR. Los números de grupo distinguen unos grupos de opciones de otros y se utilizan como argumentos para mariadbd-multi para especificar qué servidores desea iniciar, detener u obtener un informe de estado. Las opciones listadas en estos grupos son las mismas que utilizaría en el grupo [mariadbd] usado para iniciar mariadbd. Sin embargo, al usar múltiples servidores, es necesario que cada uno utilice su propio valor para opciones como el archivo de socket Unix y el número de puerto TCP/IP.

Para invocar mariadbd-multi, utilice la siguiente sintaxis:

shell> mariadbd-multi [opciones] {start|stop|report} [GNR[,GNR] ...]

start, stop y report indican qué operación realizar. Puede realizar la operación designada para un solo servidor o para varios servidores, dependiendo de la lista GNR que sigue al nombre de la opción. Si no hay lista, mariadbd-multi realiza la operación para todos los servidores en el archivo de opciones.

Cada valor GNR representa un número de grupo de opciones o un rango de números de grupo. El valor debe ser el número al final del nombre del grupo en el archivo de opciones. Por ejemplo, el GNR para un grupo llamado [mariadbd17] es 17. Para especificar un rango de números, separe el primer y último número con un guion. El valor GNR 10-13 representa los grupos [mariadbd10] a [mariadbd13]. Se pueden especificar múltiples grupos o rangos de grupos en la línea de comandos, separados por comas. No debe haber espacios en blanco (espacios o tabulaciones) en la lista GNR; todo lo que siga a un espacio en blanco se ignorará.

Este comando inicia un solo servidor utilizando el grupo de opciones [mariadbd17]:

shell> mariadbd-multi start 17

Este comando detiene varios servidores, utilizando los grupos de opciones [mariadbd8] y [mariadbd10] a [mariadbd13]:

shell> mariadbd-multi stop 8,10-13

Para un ejemplo de cómo configurar un archivo de opciones, utilice este comando:

shell> mariadbd-multi --example

mariadbd-multi busca archivos de opciones en las siguientes ubicaciones:

•Con --no-defaults, no se leen archivos de opciones.
•Con --defaults-file=nombre_archivo, solo se lee el archivo nombrado.
•De lo contrario, se leen los archivos de opciones en la lista estándar de ubicaciones, incluido cualquier archivo nombrado por la opción --defaults-extra-file=nombre_archivo, si se proporciona. (Si la opción se da varias veces, se usa el último valor).

Los archivos de opciones leídos buscan los grupos de opciones [mariadbd-multi] y [mariadbdN]. El grupo [mariadbd-multi] puede usarse para opciones de mariadbd-multi. Los grupos [mariadbdN] pueden usarse para opciones pasadas a instancias específicas de mariadbd.

Los grupos [mariadbd] o [mariadbd_safe] pueden usarse para opciones comunes leídas por todas las instancias de mariadbd o mariadbd_safe. Puede especificar una opción --defaults-file=nombre_archivo para usar un archivo de configuración diferente para esa instancia, en cuyo caso los grupos [mariadbd] o [mariadbd_safe] de ese archivo se usarán para esa instancia.

mariadbd-multi soporta las siguientes opciones.

•--help

Mostrar un mensaje de ayuda y salir.

•--example

Mostrar un archivo de opciones de ejemplo.

•--log=nombre_archivo

Especificar el nombre del archivo de registro. Si el archivo existe, la salida del registro se añadirá al final.

•--mariadb-admin=nombre_programa

El binario mariadb-admin a utilizar para detener servidores.

•--mariadbd=nombre_programa

El binario mariadbd a utilizar. Tenga en cuenta que también puede especificar mariadbd_safe como valor para esta opción. Si usa mariadbd_safe para iniciar el servidor, puede incluir las opciones mariadbd o ledir en el grupo de opciones [mariadbdN] correspondiente. Estas opciones indican el nombre del servidor que mariadbd_safe debe iniciar y la ruta del directorio donde se encuentra el servidor. (Ver las descripciones de estas opciones en mariadbd_safe(1)). Ejemplo:

[mariadbd38]
mariadbd = mariadbd-debug
ledir  = /opt/local/mysql/libexec
•--no-log

Imprimir la información del registro en stdout en lugar de en el archivo de registro. Por defecto, la salida va al archivo de registro.

•--password=contraseña

La contraseña de la cuenta MariaDB a utilizar al invocar mariadb-admin. Tenga en cuenta que el valor de la contraseña no es opcional para esta opción, a diferencia de otros programas de MariaDB.

•--silent

Modo silencioso; desactiva las advertencias.

•--tcp-ip

Conéctese a los servidores MariaDB a través del puerto TCP/IP en lugar del socket UNIX. Esto afecta a la detención y al informe. Si falta un archivo de socket, el servidor puede seguir funcionando, pero solo se puede acceder a él a través del puerto TCP/IP. Por defecto, la conexión se realiza a través del socket UNIX. Esta opción afecta a las operaciones de stop y report.

•--user=nombre_usuario

El nombre de usuario de la cuenta MariaDB a utilizar al invocar mariadb-admin.

•--verbose

Ser más verboso.

•--version

Mostrar información de la versión y salir.

•--wsrep-new-cluster

Inicializar un clúster.

Algunas notas sobre mariadbd-multi:

•Lo más importante: Antes de usar mariadbd-multi, asegúrese de que entiende el significado de las opciones que se pasan a los servidores mariadbd y por qué querría tener procesos mariadbd separados. Tenga cuidado con los peligros de usar múltiples servidores mariadbd con el mismo directorio de datos. Use directorios de datos separados, a menos que sepa lo que está haciendo. Iniciar múltiples servidores con el mismo directorio de datos no le da rendimiento adicional en un sistema con hilos.
•Importante: Asegúrese de que el directorio de datos de cada servidor sea completamente accesible para la cuenta Unix con la que se inicia el proceso mariadbd específico. No use la cuenta de root de Unix para esto, a menos que sepa lo que está haciendo.
•Asegúrese de que la cuenta MariaDB utilizada para detener los servidores mariadbd (con el programa mariadbadmin) tenga el mismo nombre de usuario y contraseña para cada servidor. Además, asegúrese de que la cuenta tenga el privilegio SHUTDOWN. Si los servidores que desea gestionar tienen nombres de usuario o contraseñas diferentes para las cuentas administrativas, es posible que desee crear una cuenta en cada servidor que tenga el mismo nombre de usuario y contraseña. Por ejemplo, podría configurar una cuenta común multi_admin ejecutando los siguientes comandos para cada servidor: 
shell> mariadb -u root -S /tmp/mariadb.sock -p
Enter password:
mariadb> GRANT SHUTDOWN ON *.*
    -> TO 'multi_admin'@'localhost' IDENTIFIED BY 'multipass';

Cambie los parámetros de conexión apropiadamente al conectarse a cada uno. Tenga en cuenta que la parte del nombre de host del nombre de la cuenta debe permitirle conectarse como multi_admin desde el host donde desea ejecutar mariadbd-multi.

DESCRIPTION

El script mariadbd-multi permite iniciar, detener y reinicializar múltiples servidores mariadb simultáneamente. Cada servidor mariadb se configura y se ejecuta por separado, pero el script los gestiona desde un único archivo de configuración.

El archivo de configuración principal para mariadbd-multi contiene secciones para el propio script mariadbd-multi (la sección [mariadbd-multi]) y secciones separadas para cada servidor mariadb que se gestionará (por ejemplo, [mariadbd2], [mariadbd3], etc.).

Las opciones dentro de la sección [mariadbd-multi] se aplican a todas las instancias de servidor mariadb gestionadas por el script. Estas opciones incluyen:

mariadbd
Especifica la ruta al ejecutable del servidor mariadb o al script de inicio, como mariadbd-safe. Si se usa mariadbd-safe, este se encargará de iniciar y monitorizar el servidor mariadb.
mariadb-admin
Especifica la ruta al ejecutable mariadb-admin.
user
El nombre de usuario de Unix bajo el cual se ejecutarán los servidores mariadb. Si no se especifica aquí, cada servidor individual puede tener su propia opción user en su sección correspondiente.
password
La contraseña asociada con el usuario especificado anteriormente para operaciones administrativas.

Cada sección que comienza con [mariadbdN] (donde N es un número) define la configuración para una instancia individual del servidor mariadb. Las opciones comunes que se pueden especificar en estas secciones incluyen:

socket
La ruta al archivo de socket de Unix que utilizará este servidor mariadb. Cada servidor debe tener un socket único.
port
El número de puerto TCP/IP que utilizará este servidor mariadb. Cada servidor debe usar un puerto único.
pid-file
La ruta al archivo PID para este proceso mariadb. Cada servidor debe tener su propio archivo PID único.
datadir
El directorio de datos para este servidor mariadb. Cada servidor debe tener su propio directorio de datos único.
language
El directorio de idioma para los mensajes de error de este servidor mariadb.
user
El nombre de usuario de Unix bajo el cual se ejecutará este servidor mariadb específico. Si no se especifica, se utilizará el usuario definido en la sección [mariadbd-multi] o, en su defecto, el usuario que ejecuta el script.

Si un host tiene múltiples direcciones de red, puede usar --bind-address para hacer que diferentes servidores escuchen en diferentes interfaces.

•La opción --pid-file es muy importante si está usando mariadbd-safe para iniciar mariadbd (por ejemplo, --mariadbd=mariadbd-safe). Cada mariadbd debe tener su propio archivo PID. La ventaja de usar mariadbd-safe en lugar de mariadbd es que mariadbd-safe monitorea su proceso mariadbd y lo reinicia si el proceso termina debido a una señal enviada usando kill -9 o por otras razones, como un fallo de segmentación. Tenga en cuenta que el script mariadbd-safe podría requerir que lo inicie desde un lugar específico. Esto significa que es posible que deba cambiar la ubicación a un directorio determinado antes de ejecutar mariadbd-multi. Si tiene problemas para iniciar, consulte el script mariadbd-safe. Verifique especialmente las líneas: 
----------------------------------------------------------------
MY_PWD=`pwd`
# Check if we are starting this relative (for the binary release)
if test -d $MY_PWD/data/mariadb -a \
   -f ./share/mariadb/english/errmsg.sys -a \
   -x ./bin/mariadbd
----------------------------------------------------------------

La prueba realizada por estas líneas debe ser exitosa, o podría encontrar problemas. Consulte mariadbd-safe(1).

•Es posible que desee utilizar la opción --user para mariadbd, pero para hacerlo necesita ejecutar el script mariadbd-multi como el usuario root de Unix. Tener la opción en el archivo de opciones no importa; solo recibirá una advertencia si no es el superusuario y los procesos mariadbd se inician bajo su propia cuenta de Unix.

El siguiente ejemplo muestra cómo podría configurar un archivo de opciones para usar con mariadbd-multi. El orden en que se inician o detienen los programas mariadbd depende del orden en que aparecen en el archivo de opciones. Los números de grupo no necesitan formar una secuencia ininterrumpida. Los primeros y quintos grupos [mariadbdN] se omitieron intencionalmente del ejemplo para ilustrar que puede haber "huecos" en el archivo de opciones. Esto le da más flexibilidad.

# Este archivo probablemente debería estar en tu directorio de inicio (~/.my.cnf)
# o /etc/my.cnf
# Versión 2.1 por Jani Tolonen
[mariadbd-multi]
mariadbd     = /usr/local/bin/mariadbd-safe
mariadb-admin = /usr/local/bin/mariadb-admin
user       = multi_admin
password   = multipass
[mariadbd2]
socket     = /tmp/mariadb.sock2
port       = 3307
pid-file   = /usr/local/mysql/var2/hostname.pid2
datadir    = /usr/local/mysql/var2
language   = /usr/local/share/mariadb/english
user       = john
[mariadbd3]
socket     = /tmp/mysql.sock3
port       = 3308
pid-file   = /usr/local/mysql/var3/hostname.pid3
datadir    = /usr/local/mysql/var3
language   = /usr/local/share/mariadb/swedish
user       = monty
[mariadbd4]
socket     = /tmp/mysql.sock4
port       = 3309
pid-file   = /usr/local/mysql/var4/hostname.pid4
datadir    = /usr/local/mysql/var4
language   = /usr/local/share/mariadb/estonia
user       = tonu
[mariadbd6]
socket     = /tmp/mysql.sock6
port       = 3311
pid-file   = /usr/local/mysql/var6/hostname.pid6
datadir    = /usr/local/mysql/var6
language   = /usr/local/share/mariadb/japanese
user       = jani
