makecert(1)

Paquete: mono

Licencias: GPL, LGPL2.1, MPL

Mono(MakeCert) Mono(MakeCert)

NOMBRE

MakeCert - Crea certificados X.509 para fines de prueba

SINOPSIS

makecert [opciones] certificado

DESCRIPCIÓN

Crea un certificado X.509 utilizando la información proporcionada. Esto es útil para probar firmas Authenticode, tecnologías SSL y S/MIME.

PARÁMETROS

-# número
Especifica el número de serie del certificado.
-n dn
Especifica el Nombre Distinguido (DN) del sujeto.
-in dn
Especifica el Nombre Distinguido (DN) del emisor.
-r
Crea un certificado autofirmado, también llamado raíz.
-iv archivo.pvk
Especifica el archivo de clave privada (.PVK) para el emisor. La clave privada en el archivo especificado se utilizará para firmar el nuevo certificado.
-ic archivo_cert
Extrae el nombre del emisor del archivo de certificado especificado; es decir, el nombre del sujeto del certificado especificado se convierte en el nombre del emisor del nuevo certificado.
-in nombre
Utiliza el nombre del emisor del parámetro especificado.
-ik contenedor
Especifica el nombre del contenedor de claves a utilizar para el emisor.
-iky [firma | intercambio | #]
Especifica el número de clave a utilizar en el proveedor (cuando se usa con -ik).
-ip proveedor
Especifica el proveedor criptográfico a utilizar para el emisor.
-ir [máquinamáquina | usuariousuario]
Especifica que el proveedor buscará en los contenedores de claves del usuario o de la máquina para el emisor.
-iy número
Especifica el tipo de proveedor a utilizar para el emisor.
-sv archivo.pvk
Especifica el archivo de clave privada (.PVK) para el sujeto. La parte pública de la clave se insertará en el certificado creado. Si no existe, se creará el archivo especificado con un nuevo par de claves (por defecto, un par de claves RSA de 1024 bits).
-sk contenedor
Especifica el nombre del contenedor de claves a utilizar para el sujeto.
-sky [firma | intercambio | #]
Especifica el número de clave a utilizar en el proveedor (cuando se usa con -sk).
-sp proveedor
Especifica el proveedor criptográfico a utilizar para el sujeto.
-sr [máquinamáquina | usuariousuario]
Especifica que el proveedor buscará en los contenedores de claves del usuario o de la máquina para el sujeto.
-sy número
Especifica el tipo de proveedor a utilizar para el emisor.
-a hash
Selecciona el algoritmo hash. Solo se admiten los algoritmos MD5 y SHA1.
-b fecha
La fecha desde la cual el certificado es válido (notBefore).
-e fecha
La fecha hasta la cual el certificado es válido (notAfter).
-m número
Especifica el período de validez del certificado en meses. Esto se suma a la fecha de validez notBefore, que puede establecerse con -b o que por defecto será la fecha/hora actual.
-cy [autoridad|entidadfinal]
Restricciones básicas. Selecciona certificado de autoridad o de entidad final. Solo los certificados de autoridad pueden utilizarse para firmar otros certificados (-ic). La entidad final puede ser utilizada por clientes (por ejemplo, Authenticode, S/MIME) o servidores (por ejemplo, SSL).
-h número
Agrega una restricción de longitud de ruta a la cadena de certificados. Esto solo es aplicable a certificados que tienen BasicConstraint establecido como Autoridad (-cy authority). Se utiliza para limitar la cadena de certificados que pueden emitirse bajo esta autoridad.
-alt nombre_archivo
Agrega una extensión subjectAltName al certificado. Cada línea de 'nombre_archivo' se agregará como una entrada DNS de la extensión. Esta opción es útil si desea crear un único certificado SSL para que funcione en varios hosts que no comparten un nombre de dominio común (es decir, CN=*.dominio.com no funcionaría).
-eku oid[,oid]
Agrega algunos OID de uso extendido de clave al certificado.
-p12 archivo.p12 contraseña
Crea un nuevo archivo PKCS#12 que contenga tanto los certificados (el sujeto y posiblemente el del emisor) como la clave privada. El archivo PKCS#12 está protegido con la contraseña especificada. Esta opción es exclusiva de mono.
-?
Ayuda (muestra este mensaje de ayuda)
-!
Ayuda extendida (para opciones avanzadas)

EJEMPLOS

Crear un certificado SSL de prueba (es decir, no confiable) es fácil una vez que conoces el nombre de tu host. El siguiente comando creará un certificado de prueba para un servidor SSL:

$ hostname 
pollux
$ makecert -r -eku 1.3.6.1.5.5.7.3.1 -n "CN=pollux" -sv pollux.pvk pollux.cer
Éxito

En particular, en el ejemplo anterior, los parámetros utilizados para construir este certificado de prueba fueron:

-r
Crea un certificado autofirmado (es decir, sin jerarquía).
-eku 1.3.6.1.5.5.7.3.1
Opcional (ya que lamentablemente la mayoría de los clientes no lo requieren). Esto indica que tu certificado está destinado a la autenticación del lado del servidor.
-n
Nombre Común (CN) = Nombre del host. Esto es verificado por el cliente SSL y debe coincidir con el host conectado (o de lo contrario, obtendrás una advertencia, un error o *¡sorpresa!* nada).
-sv clave_privada.pvk
El archivo de clave privada. La clave (par de claves RSA de 1024 bits) se generará automáticamente si el archivo especificado no existe.
pollux.cer
El certificado SSL que se creará para tu host.

RESTRICCIONES CONOCIDAS

En comparación con la versión de Windows, algunas opciones no son compatibles (-$, -d, -l, -nscp, -is, -sc, -ss). Tampoco se admiten archivos PVK con contraseñas.
