M4(1P) Manual del programador POSIX M4(1P)

PROLOG

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

m4 — procesador de macros

SINOPSIS

m4 [-s] [-D nombre[=valor]]... [-U nombre]... archivo...

DESCRIPCIÓN

La utilidad m4 es un procesador de macros que procesará uno o más archivos de texto, procesándolos de acuerdo con sus sentencias de macro incluidas, y escribirá los resultados en la salida estándar.

OPCIONES

La utilidad m4 se ajustará al volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Guías de sintaxis de utilidades, excepto que el orden de las opciones -D y -U será significativo, y las opciones pueden intercalarse con operandos.

Se admitirán las siguientes opciones:

-s
Habilita la salida de sincronización de línea para la fase del preprocesador c99 (es decir, directivas #line).
-D nombre[=valor]

Define nombre a valor o a nulo si se omite =valor.
-U nombre
Anula la definición de nombre.

OPERANDOS

Se admitirá el siguiente operando:

archivo
Una ruta de un archivo de texto que se procesará. Si no se proporciona archivo, o si es '-', se leerá la entrada estándar.

ENTRADA ESTÁNDAR

La entrada estándar será un archivo de texto que se utilizará si no se proporciona ningún operando archivo, o si es '-'.

ARCHIVOS DE ENTRADA

El archivo de entrada nombrado por el operando archivo será un archivo de texto.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de m4:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en una cadena de valor no vacía, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en comparación con caracteres multibyte en argumentos y archivos de entrada).
LC_MESSAGES

Determina la localización que debe utilizarse para afectar el formato y contenido de los mensajes de diagnóstico escritos en la salida de error estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Predeterminado.

SALIDA ESTÁNDAR

La salida estándar será la misma que la de los archivos de entrada, después de ser procesada para la expansión de macros.

ERROR ESTÁNDAR

El error estándar se utilizará para mostrar cadenas con la macro errprint, el rastreo de macros habilitado por la macro traceon, el texto definido para macros escritas por la macro dumpdef, o para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

La utilidad m4 comparará cada token de la entrada con el conjunto de macros integradas y definidas por el usuario. Si el token coincide con el nombre de una macro, entonces el token será reemplazado por el texto de definición de la macro, si lo hay, y se volverá a escanear para buscar nombres de macro coincidentes. Una vez que ninguna parte del token coincida con el nombre de una macro, se escribirá en la salida estándar. Las macros pueden tener argumentos, en cuyo caso los argumentos se sustituirán en el texto de definición antes de que se vuelva a escanear.

Las llamadas a macros tienen la forma:

nombre(arg1, arg2, ..., argn)

Los nombres de macro consistirán en letras, dígitos y guiones bajos, donde el primer carácter no es un dígito. Los tokens que no tengan esta forma no se tratarán como macros.

La aplicación garantizará que el <paréntesis izquierdo> siga inmediatamente al nombre de la macro. Si un token que coincide con el nombre de una macro no va seguido de un <paréntesis izquierdo>, se tratará como un uso de esa macro sin argumentos.

Si un nombre de macro va seguido de un <paréntesis izquierdo>, sus argumentos son los tokens separados por <coma> entre el <paréntesis izquierdo> y el <paréntesis derecho> correspondiente. Los espacios en blanco sin comillas que preceden a cada argumento se ignoran. Se conservan todos los demás caracteres, incluidos los espacios en blanco finales. Los caracteres de <coma> encerrados entre caracteres de <paréntesis izquierdo> y <paréntesis derecho> no delimitan argumentos.

Los argumentos se definen y referencian posicionalmente. La cadena "$1" en el texto de definición se reemplazará por el primer argumento. Los sistemas admitirán al menos nueve argumentos; solo los primeros nueve se pueden referenciar, utilizando las cadenas "$1" a "$9", inclusive. La cadena "$0" se reemplaza con el nombre de la macro. La cadena "$#" se reemplaza por el número de argumentos como una cadena. La cadena "$*" se reemplaza por una lista de todos los argumentos, separados por caracteres de <coma>. La cadena "$@" se reemplaza por una lista de todos los argumentos separados por caracteres de <coma>, y cada argumento se cita utilizando las cadenas de cita izquierda y derecha actuales. La cadena "${" produce un comportamiento no especificado.

Si se suministran menos argumentos de los que hay en la definición de la macro, los argumentos omitidos se consideran nulos. No es un error si se suministran más argumentos de los que hay en la definición de la macro.

No se da ningún significado especial a ningún carácter encerrado entre cadenas de cita izquierda y derecha coincidentes, pero las propias cadenas de cita se descartan. Por defecto, la cadena de cita izquierda consta de una tilde (acento grave) y la cadena de cita derecha consta de una comilla (apóstrofe); consulte también la macro changequote.

Los comentarios se escriben pero no se buscan nombres de macro coincidentes; por defecto, la cadena de inicio de comentario consta del carácter de <signo de número> y la cadena de fin de comentario consta de un <salto de línea>. Consulte también las macros changecom y dnl.

La utilidad m4 pondrá a disposición las siguientes macros integradas. Pueden redefinirse, pero una vez hecho esto, se pierde el significado original. Sus valores serán nulos a menos que se indique lo contrario. En las descripciones siguientes, el término texto de definición se refiere al valor de la macro; el segundo argumento de la macro define, entre otras cosas. Excepto para el primer argumento de la macro eval, todos los argumentos numéricos de las macros integradas se interpretarán como valores decimales. Las cadenas de valor producidas como texto de definición de las macros integradas decr, divnum, incr, index, len y sysval estarán en forma de una constante decimal.

como se define en el lenguaje C.

changecom
La macro changecom establecerá las cadenas de inicio y fin de comentario. Sin argumentos, el mecanismo de comentario se deshabilitará. Con un solo argumento no nulo, ese argumento se convertirá en el comentario de inicio y la etiqueta <nueva línea> se convertirá en la cadena de fin de comentario. Con dos argumentos no nulos, el primer argumento se convertirá en la cadena de comentario de inicio y el segundo argumento se convertirá en la cadena de fin de comentario. El comportamiento no está especificado si se proporciona algún argumento pero es nulo. Los sistemas deberán admitir cadenas de comentarios de al menos cinco caracteres.
changequote
La macro changequote establecerá las cadenas de inicio y fin de comillas. Sin argumentos, las cadenas de comillas se establecerán en los valores predeterminados (es decir, `'). El comportamiento no está especificado si hay un solo argumento o si alguno de los argumentos es nulo. Con dos argumentos no nulos, el primer argumento se convertirá en la cadena de inicio de comillas y el segundo argumento se convertirá en la cadena de fin de comillas. Los sistemas deberán admitir cadenas de comillas de al menos cinco caracteres.
decr
El texto definitorio de la macro decr será su primer argumento disminuido en 1. Será un error especificar un argumento que contenga caracteres no numéricos. El comportamiento no está especificado si decr no va seguido inmediatamente por un <paréntesis izquierdo>.
define
El segundo argumento se convertirá en el texto definitorio de la macro cuyo nombre es el primer argumento. No está especificado si la macro define elimina todas las definiciones previas de la macro nombrada por su primer argumento o conserva todas excepto la definición actual de la macro. El comportamiento no está especificado si define no va seguido inmediatamente por un <paréntesis izquierdo>.
defn
El texto definitorio de la macro defn será la definición entrecomillada (usando las cadenas de comillas actuales) de sus argumentos. El comportamiento no está especificado si defn no va seguido inmediatamente por un <paréntesis izquierdo>.
divert
La utilidad m4 mantiene nueve búferes temporales, numerados del 1 al 9, inclusive. Cuando se haya procesado la última entrada, cualquier salida que se haya colocado en estos búferes se escribirá en la salida estándar en orden numérico de los búferes. La macro divert desviará la salida futura al búfer especificado por su argumento. Especificar ningún argumento o un argumento de 0 reanudará el proceso de salida normal. La salida desviada a un flujo con un número negativo se descartará. El comportamiento se define por la implementación si se especifica un número de flujo mayor que 9. Será un error especificar un argumento que contenga caracteres no numéricos.
divnum
El texto definitorio de la macro divnum será el número del flujo de salida actual como una cadena.
dnl
La macro dnl hará que m4 descarte todos los caracteres de entrada hasta e incluyendo la siguiente <nueva línea>.
dumpdef
La macro dumpdef escribirá el texto definido en el error estándar para cada una de las macros especificadas como argumentos, o, si no se especifican argumentos, para todas las macros.
errprint
La macro errprint escribirá sus argumentos en el error estándar. El comportamiento no está especificado si errprint no va seguido inmediatamente por un <paréntesis izquierdo>.
eval
La macro eval evaluará su primer argumento como una expresión aritmética, utilizando aritmética de enteros con signo con una precisión de al menos 32 bits. Al menos los siguientes operadores del lenguaje C deberán ser compatibles, con precedencia, asociatividad y comportamiento como se describe en la Sección 1.1.2.1, Precisión y Operaciones Aritméticas:
()
unary +
unary -
~
!
binary *
/
%
binary +
binary -
<<
>>
<
<=
>
>=
==
!=
binary &
^
|
&&
||

Los sistemas deberán admitir números octales y hexadecimales como en el estándar ISO C. El segundo argumento, si se especifica, establecerá la base para el resultado; si el argumento está en blanco o no se especifica, el valor predeterminado es 10. El comportamiento no está especificado si la base está fuera del rango de 2 a 36, inclusive. El tercer argumento, si se especifica, establece el número mínimo de dígitos en el resultado. El comportamiento no está especificado si el tercer argumento es menor que cero. Será un error especificar el segundo o tercer argumento que contenga caracteres no numéricos. El comportamiento no está especificado si eval no va seguido inmediatamente por un <paréntesis izquierdo>.

ifdef
Si el primer argumento de la macro ifdef está definido, el texto definitorio será el segundo argumento. De lo contrario, el texto definitorio será el tercer argumento, si se especifica, o la cadena nula, si no. El comportamiento no está especificado si ifdef no va seguido inmediatamente por un <paréntesis izquierdo>.
ifelse
La macro ifelse toma tres o más argumentos. Si los dos primeros argumentos se comparan como cadenas iguales (después de la expansión de macros de ambos argumentos), el texto definitorio será el tercer argumento. Si los dos primeros argumentos no se comparan como cadenas iguales y hay tres argumentos, el texto definitorio será nulo. Si los dos primeros argumentos no se comparan como cadenas iguales y hay cuatro o cinco argumentos, el texto definitorio será el cuarto argumento. Si los dos primeros argumentos no se comparan como cadenas iguales y hay seis o más argumentos, los primeros tres argumentos se descartarán y el procesamiento se reiniciará con los argumentos restantes. El comportamiento no está especificado si ifelse no va seguido inmediatamente por un <paréntesis izquierdo>.
include
El texto definitorio para la macro include será el contenido del archivo nombrado por el primer argumento. Será un error si el archivo no se puede leer. El comportamiento no está especificado si include no va seguido inmediatamente por un <paréntesis izquierdo>.
incr
El texto definitorio de la macro incr será su primer argumento incrementado en 1. Será un error especificar un argumento que contenga caracteres no numéricos. El comportamiento no está especificado si incr no va seguido inmediatamente por un <paréntesis izquierdo>.
index
El texto definitorio de la macro index será la primera posición de carácter (como una cadena) en el primer argumento donde comienza una cadena que coincide con el segundo argumento (origen cero), o -1 si el segundo argumento no se encuentra. El comportamiento no está especificado si index no va seguido inmediatamente por un <paréntesis izquierdo>.
len
El texto definitorio de la macro len será la longitud (como una cadena) del primer argumento. El comportamiento no está especificado si len no va seguido inmediatamente por un <paréntesis izquierdo>.
m4exit
Salir de la utilidad m4. Si se especifica el primer argumento, será el código de salida. Si no se especifica ningún argumento, el código de salida será cero. Será un error especificar un argumento que contenga caracteres no numéricos. Si el primer argumento es cero o no se especifica ningún argumento, y previamente ha ocurrido un error (por ejemplo, un operando de archivo que no se pudo abrir), no está especificado si el estado de salida es cero o no cero.
m4wrap
El primer argumento se procesará al llegar al final del archivo (EOF). Si la macro m4wrap se utiliza varias veces, los argumentos especificados se procesarán en el orden en que se procesaron las macros m4wrap. El comportamiento no está especificado si m4wrap no va seguido inmediatamente por un <paréntesis izquierdo>.
maketemp
El texto definitorio será el primer argumento, con cualquier carácter 'X' final reemplazado por el ID de proceso actual como una cadena. El comportamiento no está especificado si maketemp no va seguido inmediatamente por un <paréntesis izquierdo>.
mkstemp
El texto definitorio será como si fuera la ruta resultante después de una llamada exitosa a la función mkstemp() definida en el volumen de Interfaces del Sistema de POSIX.1‐2017 llamada con el primer argumento de la invocación de la macro. Si se crea un archivo, ese archivo se cerrará. Si no se pudo crear un archivo, la utilidad m4 escribirá un mensaje de diagnóstico en el error estándar y continuará procesando la entrada, pero su estado de salida final será distinto de cero; el texto definitorio de la macro será la cadena vacía. El comportamiento no está especificado si mkstemp no va seguido inmediatamente por un <paréntesis izquierdo>.
popdef
La macro popdef eliminará la definición actual de sus argumentos, reemplazando esa definición con la anterior. Si no hay una definición anterior, la macro no está definida. El comportamiento no está especificado si popdef no va seguido inmediatamente por un <paréntesis izquierdo>.
pushdef
La macro pushdef será equivalente a la macro define con la excepción de que conservará cualquier definición actual para su posterior recuperación utilizando la macro popdef. El comportamiento no está especificado si pushdef no va seguido inmediatamente por un <paréntesis izquierdo>.
shift
El texto definitorio para la macro shift será una lista separada por comas de sus argumentos, excepto el primero. Cada argumento se entrecomillará utilizando las cadenas de comillas actuales. El comportamiento no está especificado si shift no va seguido inmediatamente por un <paréntesis izquierdo>.
sinclude
La macro sinclude será equivalente a la macro include, excepto que no será un error si el archi
le inaccesible. El comportamiento no está especificado si sinclude no va seguido inmediatamente por un <paréntesis-izquierdo>.
substr
El texto que define la macro substr será la subcadena del primer argumento comenzando en la posición de carácter de desplazamiento cero especificada por el segundo argumento. El tercer argumento, si se especifica, será el número de caracteres a seleccionar; si no se especifica, los caracteres desde el punto de inicio hasta el final del primer argumento se convertirán en el texto que define. No será un error especificar un punto de inicio más allá del final del primer argumento y el texto que define será nulo. Será un error especificar un argumento que contenga caracteres no numéricos. El comportamiento no está especificado si substr no va seguido inmediatamente por un <paréntesis-izquierdo>.
syscmd
La macro syscmd interpretará su primer argumento como una línea de comando de shell. El texto que define será el resultado en cadena de ese comando. El resultado en cadena no se volverá a escanear en busca de macros mientras se establece el texto que define. La utilidad m4 no realizará ninguna redirección de salida. El valor de estado de salida del comando se puede recuperar utilizando la macro sysval. El comportamiento no está especificado si syscmd no va seguido inmediatamente por un <paréntesis-izquierdo>.
sysval
El texto que define la macro sysval será el valor de salida de la utilidad invocada por última vez por la macro syscmd (como cadena).
traceon
La macro traceon habilitará el rastreo de las macros especificadas como argumentos o, si no se especifican argumentos, de todas las macros. La salida del rastreo se escribirá en el error estándar en un formato no especificado.
traceoff
La macro traceoff deshabilitará el rastreo de las macros especificadas como argumentos o, si no se especifican argumentos, de todas las macros.
translit
El texto que define la macro translit será el primer argumento con cada carácter que ocurra en el segundo argumento reemplazado por el carácter correspondiente del tercer argumento. Si no se especifica ningún carácter de reemplazo para algún carácter de origen porque el segundo argumento es más largo que el tercer argumento, ese carácter se eliminará del primer argumento en el texto que define translit. El comportamiento no está especificado si el carácter '-' aparece dentro del segundo o tercer argumento en cualquier lugar que no sea el primer o último carácter. El comportamiento no está especificado si el mismo carácter aparece más de una vez en el segundo argumento. El comportamiento no está especificado si translit no va seguido inmediatamente por un <paréntesis-izquierdo>.
undefine
La macro undefine eliminará todas las definiciones (incluidas las preservadas utilizando la macro pushdef) de las macros nombradas por sus argumentos. El comportamiento no está especificado si undefine no va seguido inmediatamente por un <paréntesis-izquierdo>.
undivert
La macro undivert causará la salida inmediata de cualquier texto en buffers temporales nombrados como argumentos, o de todos los buffers temporales si no se especifican argumentos. Los buffers se pueden redirigir a otros buffers temporales. La redirección descartará el contenido del buffer temporal. El comportamiento no está especificado si un argumento contiene caracteres no numéricos.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
Finalización exitosa.
>0
Ocurrió un error

Si se utiliza la macro m4exit, el valor de salida puede ser especificado por el archivo de entrada.

CONSECUENCIAS DE LOS ERRORES

Predeterminadas.

Las siguientes secciones son informativas.

USO DE LA APLICACIÓN

La macro defn es útil para renombrar macros, especialmente las integradas.

Dado que eval delega al estándar ISO C, algunas operaciones tienen comportamiento indefinido. En algunas implementaciones, la división o el resto por cero causan una señal fatal, incluso si la división ocurre en la rama de cortocircuito de "&&" o "||". Cualquier operación que desborde en aritmética con signo produce comportamiento indefinido. Del mismo modo, usar los operadores de desplazamiento con una cantidad de desplazamiento que no sea positiva y menor que la precisión es indefinido, al igual que desplazar un número negativo a la derecha. Históricamente, no todas las implementaciones respetaron las reglas de precedencia del lenguaje C: '~' y '!' eran menores que '=='; '==' y '!=' no eran menores que '<'; y '|' no era menor que '^'; el uso liberal de "()" puede forzar la precedencia deseada incluso con estas implementaciones que no cumplen. Además, algunas implementaciones tradicionales trataron '^' como un operador de exponenciación, aunque la mayoría de las implementaciones ahora usan "**" como una extensión para este propósito.

Cuando una macro ha sido definida múltiples veces a través de la macro pushdef, no está especificado si la macro define alterará solo la definición más reciente (como si fuera con popdef y pushdef), o reemplazará toda la pila de definiciones con una única definición (como si fuera con undefine y pushdef). Una aplicación que desee un comportamiento particular para la macro define en este caso puede redefinirla en consecuencia.

Las aplicaciones deben usar la macro mkstemp en lugar de la macro obsoleta maketemp para crear archivos temporales.

EJEMPLOS

Si el archivo m4src contiene las líneas:

El valor de `VER' es "VER".
ifdef(`VER', ``VER'' está definido como VER., VER no está definido.)
ifelse(VER, 1, ``VER'' es `VER'.)
ifelse(VER, 2, ``VER'' es `VER'., ``VER'' no es 2.)
end

entonces el comando

m4 m4src

o el comando:

m4 -U VER m4src

produce la salida:

El valor de VER es "VER".
VER no está definido.
VER no es 2.
end

El comando:

m4 -D VER m4src

produce la salida:

El valor de VER es "".
VER está definido como .
VER no es 2.
end

El comando:

m4 -D VER=1 m4src

produce la salida:

El valor de VER es "1".
VER está definido como 1.
VER es 1.
VER no es 2.
end

El comando:

m4 -D VER=2 m4src

produce la salida:

El valor de VER es "2".
VER está definido como 2.
VER es 2.
end

FUNDAMENTO RACIONAL

El comportamiento histórico basado en System V trataba "${" en una definición de macro como dos caracteres literales. Sin embargo, esta secuencia se deja sin especificar para que las implementaciones puedan ofrecer extensiones como "${11}" que significa el undécimo parámetro posicional. Las macros aún se pueden definir con el uso apropiado de comillas anidadas para resultar en un "${" literal en la salida después de que el reescaneo elimine las comillas anidadas.

En la macro integrada translit, el comportamiento histórico basado en System V trataba '-' como literal; el comportamiento de GNU lo trata como un rango. Esta versión del estándar permite cualquiera de los dos comportamientos.
