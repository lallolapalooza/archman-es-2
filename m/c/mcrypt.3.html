NOMBRE

libmcrypt - biblioteca de cifrado/descifrado

SINOPSIS

[ver también mcrypt.h para más información]

DESCRIPCIÓN

libmcrypt es una biblioteca de cifrado de datos. La biblioteca es segura para hilos (thread-safe) y proporciona funciones de cifrado y descifrado. Esta versión de la biblioteca soporta muchos algoritmos de cifrado y modos de cifrado. Algunos algoritmos soportados son: SERPENT, RIJNDAEL, 3DES, GOST, SAFER+, CAST-256, RC2, XTEA, 3WAY, TWOFISH, BLOWFISH, ARCFOUR, WAKE y más.

OFB, CBC, ECB, nOFB, nCFB y CFB son los modos en los que todos los algoritmos pueden funcionar. ECB, CBC cifran en bloques, pero CTR, nCFB, nOFB, CFB y OFB en bytes (flujos). Tenga en cuenta que CFB y OFB en el resto del documento representan el modo "CFB u OFB de 8 bits". Los modos nOFB y nCFB representan un modo OFB/CFB de n bits, donde n se utiliza para representar el tamaño del bloque del algoritmo. La biblioteca soporta un modo adicional STREAM para incluir algunos algoritmos de flujo como WAKE o ARCFOUR.

En esta versión de la biblioteca, todos los modos y algoritmos son modulares, lo que significa que el algoritmo y el modo se cargan en tiempo de ejecución. De esta manera, se pueden añadir algoritmos y modos de forma más rápida y mucho más sencilla.

LibMcrypt incluye los siguientes algoritmos simétricos (de bloque):

DES: El algoritmo DES tradicional diseñado por IBM y la NSA de EE. UU. Utiliza una clave de 56 bits y un bloque de 64 bits. Actualmente se considera un algoritmo débil, debido a su pequeño tamaño de clave (nunca fue diseñado para su uso con datos clasificados).

3DES o Triple DES: DES pero con cifrado múltiple (triple). Cifra el texto plano una vez, luego lo descifra con la segunda clave y lo vuelve a cifrar con la tercera clave (se usa modo cbc externo para cbc). Mucho mejor que el DES tradicional ya que la clave ahora es de 168 bits (en realidad, la longitud efectiva de la clave es de 112 bits debido al ataque meet-in-the-middle).

CAST-128: CAST fue diseñado en Canadá por Carlisle Adams y Stafford Tavares. El algoritmo original utilizaba una clave y un bloque de 64 bits. El algoritmo aquí es CAST-128 (también llamado CAST5), que tiene una clave de 128 bits y un tamaño de bloque de 64 bits.

CAST-256: CAST-256 fue diseñado por Carlisle Adams. Es un cifrado simétrico diseñado de acuerdo con el procedimiento de diseño CAST. Es una extensión de CAST-128, que tiene un tamaño de bloque de 128 bits y un tamaño de clave de hasta 256 bits.

xTEA: TEA son las siglas de Tiny Encryption Algorithm (Algoritmo de Cifrado Diminuto). Es un cifrado Feistel diseñado por David Wheeler y Roger M. Needham. El TEA original estaba destinado a ser utilizado en aplicaciones donde el tamaño del código es primordial, o donde es necesario que alguien recuerde el algoritmo y lo codifique en una máquina arbitraria más tarde. El algoritmo utilizado aquí es la versión extendida de TEA y tiene un tamaño de clave de 128 bits y un tamaño de bloque de 64 bits.

3-WAY: El algoritmo 3way diseñado por Joan Daemen. Utiliza una clave y un tamaño de bloque de 96 bits.

SKIPJACK: SKIPJACK fue diseñado por la NSA de EE. UU. Era parte de la propuesta fallida del Estándar de Cifrado de Escrow (EES) ("Clipper") (FIPS 185). Opera en bloques de 64 bits y utiliza una clave de 80 bits. SKIPJACK se proporciona solo como un módulo adicional para libmcrypt.

BLOWFISH: El algoritmo Blowfish diseñado por Bruce Schneier. Es mejor y más rápido que DES. Puede usar una clave de hasta 448 bits.

TWOFISH: Twofish fue diseñado por Bruce Schneier, Doug Whiting, John Kelsey, Chris Hall, David Wagner para Counterpane systems. Diseñado para ser altamente seguro y altamente flexible. Utiliza un tamaño de bloque de 128 bits y tamaños de clave de 128, 192 y 256 bits. (Twofish es el algoritmo predeterminado)

LOKI97: LOKI97 fue diseñado por Lawrie Brown y Josef Pieprzyk. Tiene una longitud de bloque de 128 bits y un programador de claves de 256 bits, que puede inicializarse utilizando claves de 128, 192 o 256 bits. Ha evolucionado a partir de los cifrados de bloque anteriores de 64 bits LOKI89 y LOKI91, con un programador de claves reforzado y un espacio de claves más grande.

RC2: RC2 (RC significa Rivest Cipher) fue diseñado por Ron Rivest. Utiliza un tamaño de bloque de 64 bits y un tamaño de clave de 8 a 1024 bits. Está optimizado para microprocesadores de 16 bits (reflejando su antigüedad). Se describe en el RFC2268.

ARCFOUR: RC4 fue diseñado por Ron Rivest. Durante varios años, este algoritmo se consideró un secreto comercial y no se dispuso de detalles. En septiembre de 1994, alguien publicó el código fuente en la lista de correo cypherpunks. Aunque el código fuente ahora está disponible, RC4 es una marca registrada de RSADSI, por lo que se incluye un cifrado compatible llamado ARCFOUR en la distribución de mcrypt. Es un cifrado de flujo y tiene una clave máxima de 2048 bits.

RC6: RC6 fue diseñado por Ron Rivest para RSA labs. En mcrypt, utiliza un tamaño de bloque de 128 bits y un tamaño de clave de 128/192/256 bits. Consulte RSA Labs y Ron Rivest para cualquier asunto de derechos de autor, patente o licencia del algoritmo RC6. RC6 se proporciona solo como un módulo adicional para libmcrypt.

RIJNDAEL: Rijndael es un cifrado de bloque, diseñado por Joan Daemen y Vincent Rijmen, y fue aprobado como el Estándar de Cifrado Avanzado (AES) de EE. UU., FIPS-197. El cifrado tiene una longitud de bloque y una longitud de clave variables. Rijndael se puede implementar de manera muy eficiente en una amplia gama de procesadores y en hardware. El diseño de Rijndael estuvo fuertemente influenciado por el diseño del cifrado de bloque Square. Existen tres versiones de este algoritmo, a saber: RIJNDAEL-128 (el ganador del AES), RIJNDAEL-192, RIJNDAEL-256. Los números 128, 192 y 256 representan la longitud del tamaño del bloque.

MARS: MARS es un cifrado de bloque de 128 bits diseñado por IBM como candidato para el Estándar de Cifrado Avanzado. Consulte a IBM para cualquier asunto de derechos de autor, patente o licencia del algoritmo MARS. MARS se proporciona solo como un módulo adicional para libmcrypt.

PANAMA: PANAMA es un módulo criptográfico que puede usarse tanto como función hash criptográfica como cifrado de flujo. Fue diseñado por Joan Daemen y Craig Clapp. PANAMA (el cifrado de flujo) se incluye en libmcrypt.

WAKE: WAKE son las siglas de Word Auto Key Encryption, y es un sistema de cifrado para cifrado de alta seguridad y velocidad media de bloques. WAKE fue diseñado por David J. Wheeler. Está diseñado para ser rápido en la mayoría de las computadoras y se basa en el uso repetido de tablas y en tener un gran espacio de estado.

SERPENT: Serpent es un cifrado de bloque de 128 bits diseñado por Ross Anderson, Eli Biham y Lars Knudsen como candidato para el Estándar de Cifrado Avanzado. El diseño de Serpent se limitó a mecanismos bien comprendidos, de modo que pudiera confiar en la amplia experiencia en criptoanálisis de cifrado de bloque, y lograr el nivel más alto de seguridad práctica de que no se encontraría ningún ataque de atajo. Serpent tiene el doble de rondas de las necesarias, para bloquear todos los ataques de atajo actualmente conocidos. A pesar de estas estrictas restricciones de diseño, Serpent es más rápido que DES.

IDEA: IDEA son las siglas de International Data Encryption Algorithm y fue diseñado por Xuejia Lai y James Massey. Opera en bloques de 64 bits y utiliza una clave de 128 bits. Consulte Ascom-Tech AG para cualquier asunto de derechos de autor, patente o licencia del algoritmo IDEA. IDEA se proporciona solo como un módulo adicional para libmcrypt.

ENIGMA (crypt de UNIX): Una máquina de un solo rotor diseñada siguiendo las líneas de Enigma pero considerablemente trivializada. Muy fácil de romper para un criptoanalista hábil. Sugiero no usarlo. Añadido solo por completitud.

GOST: Un antiguo algoritmo de la unión soviética. Un acrónimo de "Gosudarstvennyi Standard" o Estándar Gubernamental. Utiliza una clave de 256 bits y un bloque de 64 bits.
Las S-boxes utilizadas aquí se describen en el libro Applied Cryptography de Bruce Schneier. Se utilizaron en una aplicación para el Banco Central de la Federación Rusa.
Algunas citas de gost.c: El estándar está escrito por A. Zabotin (líder del proyecto), G.P. Glazkov y V.B. Isaeva. Fue aceptado e introducido en uso por acción del Comité de Estándares del Estado de la URSS el 2 de junio de 1989 como No. 1409. Debía revisarse en 1993, pero es cuestionable si alguien desea asumir esta obligación de la URSS.
Este código se basa en el borrador de traducción del 25 de noviembre de 1993 de Aleksandr Malchik, con Whitfield Diffie, del Estándar Gubernamental de la URSS GOST 28149-89, "Algoritmo de Transformación Criptográfica", efectivo el 1 de julio de 1990. (Whitfield.Diffie@eng.sun.com) Algunos detalles han sido aclarados por el artículo "Soviet Encryption Algorithm" de Josef Pieprzyk y Leonid Tombak de la Universidad de Wollongong, Nueva Gales del Sur. (josef/leo@cs.adfa.oz.au)

SAFER: SAFER (Secure And Fast Encryption Routine) es un cifrado de bloque desarrollado por el Prof. J.L. Massey en el Instituto Federal Suizo de Tecnología. Existen cuatro versiones de este algoritmo, a saber: SAFER K-64, SAFER K-128, SAFER SK-64 y SAFER SK-128. Los números 64 y 128 representan

d para la longitud de la clave seleccionada por el usuario, 'K' representa el esquema de claves original y 'SK' representa el esquema de claves fortalecido (en el que se han eliminado algunas de las "debilidades" del esquema de claves original). En mcrypt solo se utilizan SAFER SK-64 y SAFER SK-128.

SAFER+: SAFER+ fue diseñado por el Prof. J.L. Massey, el Prof. Gurgen H. Khachatrian y el Dr. Melsik K. Kuregian para Cylink. SAFER+ se basa en la familia existente de cifrados SAFER y proporciona un tamaño de bloque de 128 bits y longitudes de clave de 128, 192 y 256 bits.

Una breve descripción de los modos compatibles con libmcrypt:

STREAM: El modo utilizado con cifradores de flujo. En este modo, el flujo de claves del cifrador se combina mediante XOR con el texto plano. Por lo tanto, NO debes usar la misma clave nunca.

ECB: El modo Electronic CodeBook. Es el modo más sencillo de usar con un cifrador de bloque. Cifra cada bloque de forma independiente. Es un modo de bloque, por lo que la longitud del texto plano debe ser un múltiplo del tamaño del bloque (n*tamaño_bloque).

CBC: El modo Cipher Block Chaining. Es mejor que ECB, ya que el texto plano se combina mediante XOR con el texto cifrado anterior. Se debe colocar un bloque aleatorio como primer bloque (IV) para que el mismo bloque o mensajes se cifren siempre de forma diferente. Es un modo de bloque, por lo que la longitud del texto plano debe ser un múltiplo del tamaño del bloque (n*tamaño_bloque).

CFB: El modo Cipher-Feedback (en 8 bits). Es un cifrador de flujo auto-sincronizante implementado a partir de un cifrador de bloque. Este es el mejor modo para cifrar cadenas o flujos. Este modo requiere un IV.

OFB: El modo Output-Feedback (en 8 bits). Es un cifrador de flujo síncrono implementado a partir de un cifrador de bloque. Está diseñado para usarse en líneas con ruido, porque los bloques de texto cifrado corruptos no corrompen los bloques de texto plano que les siguen. Inseguro (debido a que se usa en modo de 8 bits), por lo que se recomienda no usarlo. Añadido solo por completitud.

nOFB: El modo Output-Feedback (en n bits). n es el tamaño del bloque del algoritmo. Es un cifrador de flujo síncrono implementado a partir de un cifrador de bloque. Está diseñado para usarse en líneas con ruido, porque los bloques de texto cifrado corruptos no corrompen los bloques de texto plano que les siguen. Este modo opera en flujos.

nCFB: El modo Cipher-Feedback (en n bits). n es el tamaño del bloque del algoritmo. Es un cifrador de flujo auto-sincronizante implementado a partir de un cifrador de bloque. Este modo opera en flujos.

CTR: El modo Counter. Es un cifrador de flujo implementado a partir de un cifrador de bloque. Este modo utiliza el cifrador para cifrar un conjunto de bloques de entrada, llamados contadores, para producir bloques que se combinarán mediante XOR con el texto plano. En libmcrypt, el contador es el IV proporcionado, que se incrementa en cada paso. Este modo opera en flujos.

Recuperación de errores en estos modos: Si se eliminan o pierden bytes del archivo o flujo en los modos ECB, CTR, CBC y OFB, es imposible recuperarlos, aunque los modos CFB y nCFB sí lo harán. Si se alteran algunos bytes, se ve afectado un bloque completo de texto plano en los modos ECB, nOFB y CTR, dos bloques en los modos CBC, nCFB y CFB, pero solo el byte correspondiente en el modo OFB.

El cifrado se puede realizar de la siguiente manera:

Una llamada a la función: MCRYPT mcrypt_module_open( char *algorithm, char* algorithm_directory, char* mode, char* mode_directory);

Esta función asocia el algoritmo y el modo especificados. El nombre del algoritmo se especifica en `algorithm`, por ejemplo, "twofish", y `algorithm_directory` es el directorio donde se encuentra el algoritmo (puede ser nulo si es el predeterminado). Lo mismo aplica para el modo. La biblioteca se cierra llamando a `mcrypt_module_close()`, pero no debes llamar a esa función si `mcrypt_generic_end()` se llama antes. Normalmente devuelve un descriptor de cifrado, o `MCRYPT_FAILED` en caso de error.

Una llamada a la función: int mcrypt_generic_init( MCRYPT td, void *key, int lenofkey, void *IV);

Esta función inicializa todos los búferes para el hilo especificado. El valor máximo de `lenofkey` debe ser el obtenido al llamar a `mcrypt_get_key_size()` y cualquier valor menor que este es legal. Ten en cuenta que `Lenofkey` debe especificarse en bytes, no en bits. El IV normalmente debe tener el tamaño del bloque del algoritmo, pero debes obtener el tamaño llamando a `mcrypt_get_iv_size()`. El IV se ignora en ECB. El IV DEBE existir en los modos CFB, CBC, STREAM, nOFB y OFB. Debe ser aleatorio y único (pero no secreto). Se debe usar el mismo IV para cifrar/descifrar. Después de llamar a esta función, puedes usar el descriptor para cifrar o descifrar (no ambos). Devuelve un valor negativo en caso de error.

Para cifrar ahora, llama a:

int mcrypt_generic( MCRYPT td, void *plaintext, int len);

Esta es la función principal de cifrado. `td` es el descriptor de cifrado devuelto por `mcrypt_generic_init()`. `plaintext` es el texto plano que deseas cifrar y `len` debe ser la longitud (en bytes) del texto plano y debe ser k*tamaño_bloque_del_algoritmo si se usa en un modo que opera en bloques (cbc, ecb, nofb), o lo que sea cuando se usa en cfb u ofb que operan en flujos. El texto plano se reemplaza por el texto cifrado. Devuelve 0 en caso de éxito.

Para descifrar, puedes llamar a:

int mdecrypt_generic( MCRYPT td, void *ciphertext, int len);

La función de descifrado. Es casi idéntica a `mcrypt_generic`. Devuelve 0 en caso de éxito.

Cuando hayas terminado, deberías llamar a:

int mcrypt_generic_end( MCRYPT td);

Esta función termina el cifrado especificado por el descriptor de cifrado (td). En realidad, limpia todos los búferes y cierra todos los módulos utilizados. Devuelve un valor negativo en caso de error. **Esta función está obsoleta.** Usa `mcrypt_generic_deinit()` y `mcrypt_module_close()` en su lugar.

int mcrypt_generic_deinit( MCRYPT td);

Esta función termina el cifrado especificado por el descriptor de cifrado (td). En realidad, limpia todos los búferes. La diferencia con `mcrypt_generic_end()` es que esta función no cierra los módulos utilizados. Por lo tanto, deberías usar `mcrypt_module_close()`. Al usar esta función, ganas velocidad si utilizas los mismos módulos para varios cifrados. Devuelve un valor negativo en caso de error.

int mcrypt_module_close( MCRYPT td);

Esta función cierra los módulos utilizados por el descriptor td.

Estas son algunas funciones adicionales que operan sobre módulos que han sido abiertos: Estas funciones tienen el prefijo `mcrypt_enc_*`.

int mcrypt_enc_set_state(MCRYPT td, void *state, int size); Esta función establece el estado del algoritmo. Solo se puede usar con algoritmos de bloque y ciertos modos como CBC, CFB, etc. Es útil si deseas reiniciar o iniciar un cifrado diferente rápidamente. Devuelve cero en caso de éxito. El estado es la salida de `mcrypt_enc_get_state()`.

Devuelve los tamaños de clave admitidos por el algoritmo especificado por el descriptor de cifrado. DESCRIPTION

The mcrypt_module_open function opens a module for the specified algorithm and mode. If lib_dir is NULL, it uses the default directory for algorithms. If mode_dir is NULL, it uses the default directory for modes. The function returns a handle of type MCRYPT on success, or MCRYPT_FAILED on failure.

The mcrypt_enc_get_iv_size function returns the size of the initialization vector for the encryption handle td.

The mcrypt_enc_get_key_size function returns the key size for the encryption handle td.

The mcrypt_enc_is_block_algorithm and mcrypt_enc_is_block_mode functions return true if the algorithm or mode operate on blocks, respectively.

The mcrypt_enc_get_algorithms_dir and mcrypt_enc_get_modes_dir functions return the default directories where algorithms and modes are searched for.

The mcrypt_generic_init function initializes the encryption handle td with the given key and IV. It returns 0 on success, or a negative value on failure.

The mcrypt_generic and mdecrypt_generic functions encrypt and decrypt, respectively, the data in data with length len.

The mcrypt_generic_end function deinitializes the encryption handle td. It should be called before mcrypt_module_close.

The mcrypt_generic_deinit function deinitializes the encryption handle td. It should be called before mcrypt_module_close.

The mcrypt_module_close function closes the module opened by mcrypt_module_open.

int mcrypt_get_key_size( char* algorithm, char* directory);

Returns the maximum supported key size of the algorithm.

int* mcrypt_module_get_algo_supported_key_sizes( char* algorithm, char* directory, int* sizes);

Returns the key sizes supported by the algorithm. If sizes is zero and returns NULL then all key sizes between 1 and mcrypt_get_key_size() are supported by the algorithm. If it is 1 then only the mcrypt_get_key_size() size is supported and sizes[0] is equal to it. If it is greater than 1 then that number specifies the number of elements in sizes which are the key sizes that the algorithm supports. This function differs to mcrypt_enc_get_supported_key_sizes(), because the return value here is allocated (not static), thus it should be freed.

char** mcrypt_list_algorithms ( char* libdir, int* size);

Returns a pointer to a character array containing all the mcrypt algorithms located in the libdir, or if it is NULL, in the default directory. The size is the number of the character arrays. The arrays are allocated internally and should be freed by using mcrypt_free_p().

char** mcrypt_list_modes ( char* libdir, int *size);

Returns a pointer to a character array containing all the mcrypt modes located in the libdir, or if it is NULL, in the default directory. The size is the number of the character arrays. The arrays should be freed by using mcrypt_free_p().

void mcrypt_free_p (char **p, int size);

Frees the pointer to array returned by previous functions.

void mcrypt_free (void *ptr);

Frees the memory used by the pointer.

void mcrypt_perror(int err);

This function prints a human readable description of the error 'err' in the stderr. The err should be a value returned by mcrypt_generic_init().

const char* mcrypt_strerror(int err);

This function returns a human readable description of the error 'err'. The err should be a value returned by mcrypt_generic_init().

int mcrypt_mutex_register ( void (*mutex_lock)(void) , void (*mutex_unlock)(void) );

This function is only used in multithreaded application and only if compiled with dynamic module loading support. This is actually used internally in libltdl. Except for the dynamic module loading libmcrypt is thread safe.

Some example programs follow here. Compile as "cc prog.c -lmcrypt", or "cc prog.c -lmcrypt -lltdl" depending on your installation. Libltdl is used for opening dynamic libraries (modules).

/* First example: Encrypts stdin to stdout using TWOFISH with 128 bit key and CFB */
#include <mcrypt.h>
#include <stdio.h>
#include <stdlib.h>
/* #include <mhash.h> */
main() {
  MCRYPT td;
  int i;
  char *key;
  char password[20];
  char block_buffer;
  char *IV;
  int keysize=16; /* 128 bits */
  key=calloc(1, keysize);
  strcpy(password, "A_large_key");
/* Generate the key using the password */
/*  mhash_keygen( KEYGEN_MCRYPT, MHASH_MD5, key, keysize, NULL, 0, password, strlen(password));
 */
  memmove( key, password, strlen(password));
  td = mcrypt_module_open("twofish", NULL, "cfb", NULL);
  if (td==MCRYPT_FAILED) {
     return 1;
  }
  IV = malloc(mcrypt_enc_get_iv_size(td));
/* Put random data in IV. Note these are not real random data,
 * consider using /dev/random or /dev/urandom.
 */
  /*  srand(time(0)); */
  for (i=0; i< mcrypt_enc_get_iv_size( td); i++) {
    IV[i]=rand();
  }
  i=mcrypt_generic_init( td, key, keysize, IV);
  if (i<0) {
     mcrypt_perror(i);
     return 1;
  }
  /* Encryption in CFB is performed in bytes */
  while ( fread (&block_buffer, 1, 1, stdin) == 1 ) {
      mcrypt_generic (td, &block_buffer, 1);
/* Comment above and uncomment this to decrypt */
/*    mdecrypt_generic (td, &block_buffer, 1);  */
      fwrite ( &block_buffer, 1, 1, stdout);
  }
/* Deinit the encryption thread, and unload the module */
  mcrypt_generic_end(td);
  return 0;
}
/* Second Example: encrypts using CBC and SAFER+ with 192 bits key */
#include <mcrypt.h>
#include <stdio.h>
#include <stdlib.h>
main() {
  MCRYPT td;
  int i;
  char *key; /* created using mcrypt_gen_key */
  char *block_buffer;
  char *IV;
  int blocksize;
  int keysize = 24; /* 192 bits == 24 bytes */
  key = calloc(1, keysize);
  strcpy(key, "A_large_and_random_key");
  td = mcrypt_module_open("saferplus", NULL, "cbc", NULL);
  blocksize = mcrypt_enc_get_block_size(td);
  block_buffer = malloc(blocksize);
/* but unfortunately this does not fill all the key so the rest bytes are
 * padded with zeros. Try to use large keys or convert them with mcrypt_gen_key().
 */
  IV=malloc(mcrypt_enc_get_iv_size(td));
/* Put random data in IV. Note these are not real random data,
 * consider using /dev/random or /dev/urandom.
 */
/* srand(time(0)); */
  for (i=0; i < mcrypt_enc_get_iv_size(td); i++) {
    IV[i]=rand();
  }
  mcrypt_generic_init( td, key, keysize, IV);
  /* Encryption in CBC is performed in blocks */
  while ( fread (block_buffer, 1, blocksize, stdin) == blocksize ) {
      mcrypt_generic (td, block_buffer, blocksize);
/*      mdecrypt_generic (td, block_buffer, blocksize); */
      fwrite ( block_buffer, 1, blocksize, stdout);
  }
/* deinitialize the encryption thread */
  mcrypt_generic_deinit (td);
/* Unload the loaded module */
  mcrypt_module_close(td);
  return 0;
}
