mctp(7) Manual de Información Miscelánea mctp(7)

NOMBRE

mctp - Protocolo de Transporte de Componentes de Gestión

SINOPSIS

#include <linux/mctp.h>  /* Constantes de dirección y protocolo MCTP */
#include <sys/socket.h>
socket_mctp = socket(AF_MCTP, SOCK_DGRAM, 0);

DESCRIPCIÓN

Linux implementa el Protocolo de Transporte de Componentes de Gestión (MCTP), especificado por la especificación DSP0236 de DMTF, actualmente en la versión 1. Este es un protocolo sin conexión, típicamente usado entre dispositivos dentro de un sistema servidor. La fiabilidad y el orden de los mensajes no están garantizados, pero los límites de los mensajes se conservan.

La API para la mensajería MCTP utiliza una interfaz de sockets estándar, usando la clase de llamadas al sistema sendto(2) y recvfrom(2) para transferir mensajes. Los mensajes pueden fragmentarse en paquetes antes de la transmisión y reensamblarse en el punto final remoto. Esta fragmentación y reensamblaje es transparente para el espacio de usuario.

Formato de dirección

Las direcciones MCTP (también referidas como EID, o Identificadores de Punto Final) son valores de un solo byte, tipificados como mctp_eid_t. Los paquetes entre un punto final local y remoto se identifican por los EID de origen y destino, más un valor de etiqueta de tres bits.

Los datos de direccionamiento se pasan en las llamadas al sistema de socket a través de una estructura sockaddr_mctp, definida como:


typedef uint8_t        mctp_eid_t;
struct mctp_addr {
    mctp_eid_t         s_addr;
};
struct sockaddr_mctp {
    unsigned short     smctp_family;  /* = AF_MCTP */
    uint16_t           __smctp_pad0;
    int                smctp_network; /* identificador de red local */
    struct mctp_addr   smctp_addr;    /* EID */
    uint8_t            smctp_type;    /* byte de tipo de mensaje */
    uint8_t            smctp_tag;     /* valor de etiqueta y propietario */
    uint8_t            __smctp_pad1;
};

Envío de mensajes

Los mensajes pueden transmitirse usando las llamadas al sistema sendto(2) y sendmsg(2), proporcionando una estructura sockaddr_mctp que describe los parámetros de direccionamiento.


ssize_t               n;
const char            *buf;
struct sockaddr_mctp  addr;
/* los campos no utilizados deben ser cero */
memset(&addr, 0, sizeof(addr));
/* establecer destino del mensaje */
addr.smctp_family = AF_MCTP;
addr.smctp_network = 0;
addr.smctp_addr.s_addr = 8;  /* EID remoto */
addr.smctp_tag = MCTP_TAG_OWNER;
addr.smctp_type = MYPROGRAM_MCTP_TYPE_ECHO;  /* tipo de ejemplo */
buf = "hola, mundo!"
n = sendto(sd, buf, 13, 0,
           (struct sockaddr *) &addr, sizeof(addr));

Aquí, el remitente es el propietario de la etiqueta del mensaje; por lo tanto, se utiliza MCTP_TAG_OWNER como datos de la etiqueta. El kernel asignará un valor de etiqueta específico para este mensaje. Si no hay ninguna etiqueta disponible, sendto(2) devolverá un error, con errno establecido en EBUSY. Esta etiqueta asignada permanece asociada al socket, de modo que cualquier respuesta al mensaje enviado será recibida por el mismo socket.

Enviar un mensaje MCTP requiere la capacidad CAP_NET_RAW.

Recepción de mensajes

Los mensajes pueden recibirse usando las llamadas al sistema recvfrom(2) y recvmsg(2).


char                  buf[13];
socklen_t             addrlen;
struct sockaddr_mctp  addr;
addrlen = sizeof(addr);
n = recvfrom(sd, buf, sizeof(buf), 0,
             (struct sockaddr *) &addr, &addrlen);

Para recibir un mensaje entrante, el receptor necesitará haber enviado previamente un mensaje al mismo punto final, o haber realizado una llamada a bind(2) para recibir todos los mensajes de un tipo determinado:


struct sockaddr_mctp  addr;
addr.smctp_family = AF_MCTP;
addr.smctp_network = MCTP_NET_ANY;
addr.smctp_addr.s_addr = MCTP_ADDR_ANY;
addr.smctp_type = MYPROGRAM_MCTP_TYPE_ECHO;  /* nuestro tipo 'echo' */
int rc = bind(sd, (struct sockaddr *) &addr, sizeof(addr));

Esta llamada requiere la capacidad CAP_NET_BIND_SERVICE, y resultará en que el socket reciba todos los mensajes enviados a EID asignados localmente, para el tipo de mensaje especificado.

Después de que recvfrom(2) o recvmsg(2) devuelvan una condición de éxito, el argumento de dirección proporcionado se poblará con la red y el EID del remitente, así como el valor de etiqueta utilizado para el mensaje. Cualquier respuesta a este mensaje debe pasar la misma dirección y valor de etiqueta (con el bit TO borrado) para indicar que está dirigido al mismo punto final remoto.
