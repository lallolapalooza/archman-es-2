NOMBRE

mc - Shell visual para sistemas tipo Unix.

SINOPSIS

mc [-abcCdfhPstuUVx] [-l log] [dir1 [dir2]] [-e [file] ...] [-v file]

DESCRIPCIÓN

GNU Midnight Commander es un navegador de directorios/gestor de archivos para sistemas operativos tipo Unix.

OPCIONES

-a, --stickchars
Deshabilita el uso de caracteres gráficos para dibujar líneas.
-b, --nocolor
Fuerza la visualización en blanco y negro.
-c, --color
Fuerza el modo de color, por favor consulta la sección Colores para más información.
-C arg, --colors=arg
Especifica un conjunto de colores diferente en la línea de comandos. El formato de arg está documentado en la sección Colores.
--configure-options
Muestra las opciones de configuración.
-d, --nomouse
Deshabilita el soporte del ratón.
-e [file], --edit[=file]
Inicia el editor interno. Si se especifica el archivo, ábrelo al inicio. Ver también mcedit (1).
-f, --datadir
Muestra las rutas de búsqueda compiladas para los archivos de Midnight Commander.
-F, --datadir-info
Muestra información extendida sobre las rutas compiladas para Midnight Commander.
-g, --oldmouse
Fuerza un modo de ratón de "seguimiento normal". Se usa al ejecutarse en terminales compatibles con xterm (tmux/screen).
-k, --resetsoft
Restablece las teclas blandas a sus valores predeterminados de la base de datos termcap/terminfo. Solo útil en terminales HP cuando las teclas de función no funcionan.
-K file, --keymap=file
Especifica un nombre de archivo de mapa de teclas en la línea de comandos.
-l file, --ftplog=file
Guarda el diálogo ftpfs con el servidor en el archivo.
--nokeymap
No carga las asignaciones de teclas desde ningún archivo, usa las teclas predeterminadas codificadas.
-P file, --printwd=file
Imprime el último directorio de trabajo al archivo especificado. Esta opción no está pensada para usarse directamente. En cambio, se usa desde un script de shell especial que cambia automáticamente el directorio actual del shell al último directorio en el que estuvo Midnight Commander. Carga el archivo /usr/lib/mc/mc.sh (usuarios de bash y zsh) o /usr/lib/mc.csh (usuarios de tcsh) respectivamente para definir mc como un alias al script de shell apropiado.
-s, --slow
Activa el modo de terminal lento, en este modo el programa no dibujará caracteres de dibujo de línea costosos y desactivará el modo detallado.
-S arg, --skin=arg
Especifica un nombre de skin en la línea de comandos. La tecnología de los skins se documenta en la sección Skins.
-t, --termcap
Solo se usa si el código fue compilado con S-Lang y terminfo: hace que Midnight Commander use el valor de la variable TERMCAP para la información del terminal en lugar de la información de la base de datos de terminales de todo el sistema.
-u, --nosubshell
Deshabilita el uso del subshell (solo tiene sentido si Midnight Commander ha sido compilado con soporte para subshell).
-U, --subshell
Habilita el uso del soporte para subshell (solo tiene sentido si Midnight Commander fue compilado con el soporte para subshell establecido como una característica opcional).
-v file, --view=file
Inicia el visor interno para ver el archivo especificado. Ver también mcview (1).
-V, --version
Muestra la versión del programa.
-x, --xterm
Fuerza el modo xterm. Se usa al ejecutarse en terminales compatibles con xterm (dos modos de pantalla y capaz de enviar secuencias de escape del ratón).
-X, --no-x11
No usar X11 para obtener el estado de los modificadores Alt, Ctrl, Shift

Si se especifican ambas rutas, la primera ruta es el directorio que se mostrará en el panel activo; la segunda ruta es el directorio que se mostrará en el otro panel.

Si se especifica una ruta, la ruta es el directorio que se mostrará en el panel activo; el valor de "other_dir" de panels.ini es el directorio que se mostrará en el panel pasivo.

Si no se especifican rutas, se muestra el directorio actual en el panel activo; el valor de "other_dir" de panels.ini es el directorio que se mostrará en el panel pasivo.

VISIÓN GENERAL

La pantalla de Midnight Commander se divide en cuatro partes. Casi todo el espacio de la pantalla lo ocupan dos paneles de directorios. Por defecto, la segunda línea desde abajo de la pantalla es la línea de comandos del shell, y la última línea muestra las etiquetas de las teclas de función. La línea superior es la línea de la barra de menús. La línea de la barra de menús puede no ser visible, pero aparece si haces clic en la línea superior con el ratón o presionas la tecla F9.

Midnight Commander proporciona una vista de dos directorios a la vez. Uno de los paneles es el panel actual (una barra de selección está en el panel actual). Casi todas las operaciones se realizan en el panel actual. Algunas operaciones de archivos como Renombrar y Copiar usan por defecto el directorio del panel no seleccionado como destino (no te preocupes, siempre te pedirán confirmación primero). Para más información, consulta las secciones sobre los Paneles de Directorios, los Menús Izquierdo y Derecho y el Menú de Archivos.

Puedes ejecutar comandos del sistema desde Midnight Commander simplemente escribiéndolos. Todo lo que escribas aparecerá en la línea de comandos del shell, y cuando presiones Enter, Midnight Commander ejecutará la línea de comandos que escribiste; lee las secciones Línea de Comandos del Shell y Teclas de la Línea de Entrada para aprender más sobre la línea de comandos.

Soporte del Ratón

Midnight Commander viene con soporte para ratón. Se activa siempre que estés ejecutando en un terminal xterm(1) (incluso funciona si tomas una conexión telnet, ssh o rlogin a otra máquina desde el xterm) o si estás ejecutando en una consola Linux y tienes el servidor de ratón gpm en ejecución.

Cuando haces clic izquierdo en un archivo en los paneles de directorios, ese archivo se selecciona; si haces clic con el botón derecho, el archivo se marca (o desmarca, dependiendo del estado anterior).

Hacer doble clic en un archivo intentará ejecutar el comando si es un programa ejecutable; y si el archivo de extensión tiene un programa especificado para la extensión del archivo, se ejecuta el programa especificado.

Además, es posible ejecutar los comandos asignados a las etiquetas de las teclas de función haciendo clic en ellas.

La tasa de repetición automática predeterminada para los botones del ratón es de 400 milisegundos. Esto se puede cambiar a otros valores editando el archivo ~/.config/mc/ini y cambiando el parámetro mouse_repeat_rate.

Si estás ejecutando Midnight Commander con el soporte del ratón, puedes obtener el comportamiento predeterminado del ratón (cortar y pegar texto) manteniendo presionada la tecla Shift.

Línea de Comandos del Shell

Esta sección enumera las teclas que son útiles para evitar escribir en exceso al ingresar comandos del shell.

Alt-Enter
copia el nombre del archivo actualmente seleccionado a la línea de comandos.
C-Enter
igual que Alt-Enter. Puede que no funcione en sistemas remotos y algunos terminales.
C-S-Enter
copia la ruta completa del archivo actualmente seleccionado a la línea de comandos. Puede que no funcione en sistemas remotos y algunos terminales.
Alt-Tab
realiza la autocorrección de nombres de archivo, comandos, variables, nombres de usuario y nombres de host.
C-x t, C-x C-t
copia los archivos marcados (o si no hay archivos marcados, el archivo seleccionado) del panel actual (C-x t) o del otro panel (C-x C-t) a la línea de comandos.
C-x p, C-x C-p
la primera secuencia de teclas copia el nombre de la ruta actual a la línea de comandos, y la segunda copia el nombre de la ruta del panel no seleccionado a la línea de comandos.
C-q
el comando de comillas se puede usar para insertar caracteres que de otra manera son interpretados por Midnight Commander (como el símbolo '+')
Alt-p, Alt-n
usa estas teclas para navegar por el historial de comandos. Alt-p te lleva a la última entrada, Alt-n te lleva a la siguiente.
Alt-h
muestra el historial de la línea de entrada actual.

Teclas Generales de Movimiento

El visor de ayuda, el visor de archivos y el árbol de directorios utilizan código común para manejar el movimiento. Por lo tanto, aceptan exactamente las mismas teclas. Cada uno de ellos también acepta algunas teclas propias.

Otras partes de Midnight Commander utilizan algunas de las mismas teclas de movimiento, por lo que esta sección puede ser útil también para esas partes.

Arriba, C-p
se mueve una línea hacia atrás.
Abajo, C-n
se mueve una línea hacia adelante.
Página Anterior, Re Pág, Alt-v
se mueve una página hacia arriba.
Página Siguiente, Av Pág, C-v
se mueve una página hacia abajo.
Inicio, A1
se mueve al principio.
Fin, C1
se mueve al final.

El visor de ayuda y el visor de archivos aceptan las siguientes teclas además de las mencionadas anteriormente:

b, C-b, C-h, Retroceso, Supr
se mueve una página hacia arriba.
Barra espaciadora
se mueve una página hacia abajo.
u, d
mueve media página hacia arriba o hacia abajo.
g, G
mueve al principio o al final.

Barra de Menú

La barra de menú aparece al presionar F9 o al hacer clic con el ratón en la fila superior de la pantalla. La barra de menú tiene cinco menús: "Izquierda", "Archivo", "Comando", "Opciones" y "Derecha".

Los Menús Izquierdo y Derecho permiten modificar la apariencia de los paneles de directorio izquierdo y derecho.

El Menú Archivo enumera las acciones que puedes realizar en el archivo actualmente seleccionado o en los archivos marcados.

El Menú Comando enumera las acciones que son más generales y no tienen relación con el archivo actualmente seleccionado o los archivos marcados.

El Menú Opciones enumera las acciones que te permiten personalizar Midnight Commander.

Menús Izquierdo y Derecho (Arriba y Abajo)

La apariencia de los paneles de directorio se puede cambiar desde los menús Izquierdo y Derecho (se llaman Arriba y Abajo cuando se elige la división horizontal del panel desde el diálogo de opciones de Diseño).

Formato de Listado...

La vista de modo de listado se utiliza para mostrar un listado de archivos, hay cuatro formatos de listado diferentes disponibles: Completo, Breve, Largo y Usuario. La vista de directorio completa muestra el nombre del archivo, el tamaño del archivo y la hora de modificación.

La vista breve muestra solo el nombre del archivo y tiene de 1 a 9 columnas (mostrando así más archivos a diferencia de otras vistas). La vista larga es similar a la salida del comando ls -l. La vista larga ocupa todo el ancho de la pantalla.

Si eliges el formato de visualización "Usuario", entonces tienes que especificar el formato de visualización.

El formato de visualización de usuario debe comenzar con un especificador de tamaño de panel. Este puede ser "half" o "full", y especifican un panel de media pantalla y un panel de pantalla completa respectivamente.

Después del tamaño del panel, puedes especificar cuántos listados caben en el panel, uno al lado del otro (en otras palabras: cuántas veces repetir los campos horizontalmente). Esto tiene un valor predeterminado de 1. Puedes cambiar esto agregando un número del 1 al 9 a la cadena de formato.

Después de esto, agregas el nombre de los campos con un especificador de tamaño opcional. Estos son los campos disponibles que puedes mostrar:

name
muestra el nombre del archivo.
size
muestra el tamaño del archivo.
bsize
es una forma alternativa del formato size. Muestra el tamaño de los archivos y para directorios solo muestra SUB-DIR o UP--DIR.
type
muestra un campo de tipo de un carácter de ancho. un asterisco si el archivo está marcado, un espacio si no lo está.

última hora de modificación del archivo.

última hora de acceso del archivo.
ctime
hora de cambio de estado del archivo.
perm
una cadena que representa los bits de permiso actuales del archivo.

un valor octal con los bits de permiso actuales del archivo.
nlink
el número de enlaces al archivo.

Enlace (C-x l)

Crea un enlace duro al archivo actual.

Enlace simbólico relativo (C-x v)

Crea un enlace simbólico relativo al archivo actual.

Para aquellos que no saben qué son los enlaces: crear un enlace a un archivo es un poco como copiar el archivo, pero tanto el nombre del archivo de origen como el nombre del archivo de destino representan la misma imagen de archivo. Por ejemplo, si editas uno de estos archivos, todos los cambios que realices aparecerán en ambos archivos. Algunas personas llaman a los enlaces alias o atajos.

Un enlace duro aparece como un archivo real. Después de crearlo, no hay forma de saber cuál es el original y cuál es el enlace. Si eliminas cualquiera de ellos, el otro permanece intacto. Es muy difícil notar que los archivos representan la misma imagen. Usa enlaces duros cuando ni siquiera quieras saberlo.

Un enlace simbólico es una referencia al nombre del archivo original. Si el archivo original se elimina, el enlace simbólico es inútil. Es bastante fácil notar que los archivos representan la misma imagen. Midnight Commander muestra un signo "@" delante del nombre del archivo si es un enlace simbólico a algún lugar (excepto a un directorio, donde muestra una tilde (~)). El archivo original al que apunta el enlace se muestra en la línea mini-estado si la opción Mostrar mini-estado está habilitada. Usa enlaces simbólicos cuando quieras evitar la confusión que pueden causar los enlaces duros.

Cuando presiones "C-x s", Midnight Commander rellenará automáticamente la ruta completa + nombre de archivo del archivo original y sugerirá un nombre para el enlace. Puedes cambiar cualquiera de ellos.

A veces, es posible que desees cambiar la ruta absoluta del original por una ruta relativa. Una ruta absoluta comienza desde el directorio raíz:

/home/frodo/mc/mc -> /home/frodo/new/mc

Un enlace relativo describe la ubicación del archivo original a partir de la ubicación del propio enlace:

/home/frodo/mc/mc -> ../new/mc

Puedes forzar a Midnight Commander a sugerir una ruta relativa presionando "C-x v" en lugar de "C-x s".

Buscar archivo

La función Buscar archivo primero pregunta por el directorio de inicio para la búsqueda y el nombre del archivo a buscar. Al presionar el botón Árbol, puede seleccionar el directorio de inicio desde la figura del árbol de directorios.

El campo de entrada "Nombre de archivo" contiene un patrón de nombre de archivo a buscar. Se interpreta como un patrón de shell o como una expresión regular dependiendo del estado de la casilla de verificación "Usar patrones de shell". Un valor vacío es válido y coincide con cualquier nombre de archivo.

El campo de entrada "Contenido" contiene una cadena para buscar dentro de los archivos. Deje este campo vacío para deshabilitar la búsqueda del contenido de los archivos.

La opción "Palabras completas" permite seleccionar solo aquellos archivos que contienen coincidencias que forman palabras completas. Como grep -w.

Puede iniciar la búsqueda presionando el botón OK. Durante la búsqueda, puede detenerla desde el botón Detener y continuar desde el botón Iniciar.

Puede navegar por la lista de archivos con las teclas de flecha arriba y abajo. El botón Cambiar directorio cambiará al directorio del archivo actualmente seleccionado. El botón Otra vez solicitará los parámetros para una nueva búsqueda. El botón Salir cancela la operación de búsqueda. El botón Panelizar colocará los archivos encontrados en el panel de directorio actual para que pueda realizar operaciones adicionales sobre ellos (ver, copiar, mover, eliminar, etc.). Para volver a la lista normal de archivos, cambie de directorio a "..".

La casilla de verificación 'Habilitar directorios a ignorar' y el campo de entrada debajo de ella permiten configurar la lista de directorios que deben omitirse durante la búsqueda de archivos (por ejemplo, puede querer evitar búsquedas en un CD-ROM o en un directorio NFS que está montado a través de un enlace lento). Los componentes de la lista deben estar separados por dos puntos, aquí hay un ejemplo:

/cdrom:/nfs/wuarchive:/afs

También se admiten rutas relativas. El siguiente ejemplo muestra cómo omitir directorios especiales de sistemas de control de versiones:

/cdrom:/nfs/wuarchive:/afs:.svn:.git:CVS

Atención: el campo de entrada puede contener un punto (.), esto significa la ruta absoluta actual.

Puede considerar usar el comando Panelizar externo para algunas operaciones. El comando Buscar archivo es solo para consultas simples, mientras que al usar Panelizar externo puede realizar búsquedas tan misteriosas como desee.

Panelizar externo

Panelizar externo le permite ejecutar un programa externo y hacer que la salida de ese programa sea el contenido del panel actual.

Por ejemplo, si desea manipular en uno de los paneles todos los enlaces simbólicos en el directorio actual, puede usar la panelización externa para ejecutar el siguiente comando:

find . -type l -print

Una vez completado el comando, el contenido del directorio del panel ya no será la lista del directorio actual, sino todos los archivos que son enlaces simbólicos.

Si desea panelizar todos los archivos que se han descargado de su servidor FTP, puede usar este comando awk para extraer el nombre del archivo de los archivos de registro de transferencia:

awk '$9 ~! /incoming/ { print $9 }' < /var/log/xferlog

Es posible que desee guardar comandos de panelización de uso frecuente bajo un nombre descriptivo, para que pueda recordarlos rápidamente. Lo hace escribiendo el comando en la línea de entrada y presionando el botón Agregar nuevo. Luego ingresa un nombre bajo el cual desea guardar el comando. La próxima vez, simplemente elige ese comando de la lista y no tiene que escribirlo de nuevo.

Editar Archivo de Menú

El menú de usuario es un menú de acciones útiles que pueden ser personalizadas por el usuario. Cuando accedes al menú de usuario, se usa el archivo .mc.menu del directorio actual si existe, pero solo si es propiedad del usuario o de root y no es escribible por todos. Si no se encuentra tal archivo, se intenta con ~/.config/mc/menu de la misma manera, y de lo contrario, mc utiliza el menú predeterminado del sistema /usr/share/mc/mc.menu.

El formato del archivo de menú es muy simple. Las líneas que comienzan con cualquier cosa que no sea un espacio o tabulador se consideran entradas para el menú (para poder usarlo como una tecla de acceso rápido, el primer carácter debe ser una letra). Todas las líneas que comienzan con un espacio o un tabulador son los comandos que se ejecutarán cuando se seleccione la entrada.

Cuando se selecciona una opción, todas las líneas de comando de la opción se copian a un archivo temporal en el directorio temporal (generalmente /usr/tmp) y luego se ejecuta ese archivo. Esto permite al usuario colocar construcciones normales del shell en los menús. También se realiza una sustitución simple de macros antes de ejecutar el código del menú. Para más información, consulta sustitución de macros.

Aquí hay un ejemplo de archivo mc.menu:

A	Volcar el archivo seleccionado actualmente
	od -c %f
B	Editar un informe de error y enviarlo a root
	I=`mktemp ${MC_TMPDIR:-/tmp}/mail.XXXXXX` || exit 1
	vi $I
	mail -s "Error de Midnight Commander" root < $I
	rm -f $I
M	Leer correo
	emacs -f rmail
N	Leer noticias de Usenet
	emacs -f gnus
H	Llamar al navegador hipertexto info
	info
J	Copiar el directorio actual al otro panel recursivamente
	tar cf - . | (cd %D && tar xvpf -)
K	Crear una distribución del subdirectorio actual
	echo -n "Nombre del archivo de distribución: "
	read tar
	ln -s %d `dirname %d`/$tar
	cd ..

Condiciones Predeterminadas

Cada entrada del menú puede ir precedida por una condición. La condición debe comenzar en la primera columna con un carácter '='. Si la condición es verdadera, la entrada del menú será la entrada predeterminada.

Sintaxis de la condición: 	= <sub-condición>
  o:			= <sub-condición> | <sub-condición> ...
  o:			= <sub-condición> & <sub-condición> ...
La sub-condición es una de las siguientes:
  y <patrón>		¿coincide el patrón del archivo actual?
			(solo para el menú de edición)
  f <patrón>		¿coincide el archivo actual con el patrón?
  F <patrón>		¿coincide el otro archivo con el patrón?
  d <patrón>		¿coincide el directorio actual con el patrón?
  D <patrón>		¿coincide el otro directorio con el patrón?
  t <tipo>		¿es el archivo actual de tipo?
  T <tipo>		¿es el otro archivo de tipo?
  x <nombre_archivo>		¿es el nombre del archivo ejecutable?
  ! <sub-condición>		niega el resultado de la sub-condición

El patrón es un patrón normal del shell o una expresión regular, según la opción de patrones del shell. Puedes anular el valor global de la opción de patrones del shell escribiendo "shell_patterns=x" en la primera línea del archivo de menú (donde "x" es 0 o 1).

El tipo es uno o más de los siguientes caracteres:

  n	no es un directorio
  r	archivo regular
  d	directorio
  l	enlace
  c	dispositivo de caracteres
  b	dispositivo de bloques
  f	FIFO (tubería)
  s	socket
  x	archivo ejecutable
  t	etiquetado

Por ejemplo, 'rlf' significa archivo regular, enlace o fifo. El tipo 't' es un poco especial porque actúa sobre el panel en lugar de sobre el archivo. La condición '=t t' es verdadera si hay archivos etiquetados en el panel actual y falsa si no.

Si la condición comienza con '=?' en lugar de '=' se mostrará un rastro de depuración cada vez que se calcule el valor de la condición.

Las condiciones se calculan de izquierda a derecha. Esto significa

= f *.tar.gz | f *.tgz & t n
se calcula como 
( (f *.tar.gz) | (f *.tgz) ) & (t n)

Aquí hay un ejemplo del uso de condiciones:

= f *.tar.gz | f *.tgz & t n
L	Listar el contenido de un archivo tar comprimido
	gzip -cd %f | tar xvf -

Condiciones de Adición

Si la condición comienza con '+' (o '+?') en lugar de '=' (o '=?') es una condición de adición. Si la condición es verdadera, la entrada del menú se incluirá en el menú. Si la condición es falsa, la entrada del menú no se incluirá en el menú.

Puedes combinar condiciones predeterminadas y de adición comenzando la condición con '+=' o '=+' (o '+=?' o '=+?' si deseas un rastro de depuración). Si deseas usar dos condiciones diferentes, una para agregar y otra para establecer como predeterminada, puedes preceder una entrada de menú con dos líneas de condición, una que comience con '+' y otra que comience con '='.

Los comentarios comienzan con '#'. Las líneas de comentario adicionales deben comenzar con '#', espacio o tabulador.

FS Virtual

Esta opción le permite controlar la configuración del Sistema de Archivos Virtual.

Midnight Commander mantiene en memoria la información relacionada con algunos de los sistemas de archivos virtuales para acelerar el acceso a los archivos en el sistema de archivos (por ejemplo, listados de directorios obtenidos de servidores FTP).

Además, para acceder al contenido de archivos comprimidos (por ejemplo, archivos tar comprimidos), Midnight Commander necesita crear archivos temporales sin comprimir en su disco.

Dado que tanto la información en memoria como los archivos temporales en disco consumen recursos, es posible que desee ajustar los parámetros de la información en caché para disminuir el uso de recursos o maximizar la velocidad de acceso a los sistemas de archivos utilizados con frecuencia.

Debido al formato de los archivos tar, el sistema de archivos Tar necesita leer todo el archivo solo para cargar las entradas de los archivos. Dado que la mayoría de los archivos tar suelen estar comprimidos (los archivos tar sin comprimir son especies en extinción), el sistema de archivos tar tiene que descomprimir el archivo en el disco en una ubicación temporal y luego acceder al archivo sin comprimir como un archivo tar normal.

Ahora, dado que a todos nos gusta explorar archivos y archivos tar por todo el disco, es común que salga de un archivo tar y vuelva a entrar en él más tarde. Dado que la descompresión es lenta, Midnight Commander almacenará en caché la información en memoria durante un tiempo limitado. Cuando expire el tiempo de espera, se liberarán todos los recursos asociados con el sistema de archivos. El tiempo de espera predeterminado se establece en un minuto.

El Sistema de Archivos FTP (ftpfs) le permite explorar directorios en servidores FTP remotos. Tiene varias opciones.

contraseña anónima ftp es la contraseña utilizada cuando inicia sesión como "anonymous". Algunos sitios requieren una dirección de correo electrónico válida. Por otro lado, probablemente no querrá dar su dirección de correo electrónico real a sitios no confiables, especialmente si no está utilizando filtrado de spam.

ftpfs mantiene el listado de directorios que obtiene de un servidor FTP en una caché. El tiempo de expiración de la caché se puede configurar con la opción tiempo de espera de caché de directorios de ftpfs. Un valor bajo para esta opción puede ralentizar cada operación en ftpfs porque cada operación requeriría enviar una solicitud al servidor FTP.

Puede definir un host proxy FTP para realizar FTP. Tenga en cuenta que la mayoría de los firewalls modernos son completamente transparentes, al menos para FTP pasivo (ver más abajo), por lo que los proxies FTP se consideran obsoletos.

Si Usar siempre proxy ftp no está configurado, puede usar el signo de exclamación para habilitar el proxy para hosts específicos. Consulte Sistema de Archivos FTP para ver ejemplos.

Si esta opción está configurada, el programa hará dos cosas: consultar el archivo /etc/mc/mc.no_proxy en busca de líneas que contengan nombres de host que sean locales (si el nombre de host comienza con un punto, se asume que es un dominio) y asumir que cualquier nombre de host sin puntos en sus nombres es accesible directamente. Todos los demás hosts se accederán a través del proxy FTP especificado.

Puede habilitar el uso del archivo ~/.netrc, que guarda nombres de usuario y contraseñas para servidores ftp. Consulte netrc (5) para obtener la descripción del formato de .netrc.

Usar modo pasivo habilita el uso del modo pasivo de FTP, cuando la conexión para la transferencia de datos es iniciada por el cliente, no por el servidor. Esta opción se recomienda y está habilitada por defecto. Si esta opción está desactivada, la conexión de datos es iniciada por el servidor. Esto puede no funcionar con algunos firewalls.

Puede ejecutar comandos escribiéndolos directamente en la línea de entrada de Midnight Commander, o seleccionando el programa que desea ejecutar con la barra de selección en uno de los paneles y pulsando Intro.

Si pulsa Intro sobre un archivo que no es ejecutable, Midnight Commander compara la extensión del archivo seleccionado con las extensiones en el Archivo de Extensiones. Si encuentra una coincidencia, se ejecuta el código asociado a esa extensión. Se realiza una expansión de macro muy simple antes de ejecutar el comando.

El comando interno cd

El comando cd es interpretado por Midnight Commander, no se pasa al intérprete de comandos para su ejecución. Por lo tanto, puede que no maneje toda la expansión de macros y sustitución que su intérprete hace, aunque sí hace algunas de ellas:

Sustitución de tilde. El (~) se sustituirá por su directorio personal, si añade un nombre de usuario después de la tilde, se sustituirá por el directorio de inicio del usuario especificado.

Por ejemplo, ~guest es el directorio personal del usuario guest, mientras que ~/guest es el directorio guest en su directorio personal.

Directorio anterior. Puede saltar al directorio en el que estaba anteriormente utilizando el nombre especial de directorio '-' de la siguiente manera: cd -

Directorios CDPATH. Si el directorio especificado al comando cd no está en el directorio actual, entonces Midnight Commander usa el valor de la variable de entorno CDPATH para buscar el directorio en cualquiera de los directorios nombrados.

Por ejemplo, podría establecer su variable CDPATH a ~/src:/usr/src, permitiéndole cambiar su directorio a cualquiera de los directorios dentro de los directorios ~/src y /usr/src, desde cualquier lugar del sistema de archivos utilizando su nombre relativo (por ejemplo, cd linux podría llevarle a /usr/src/linux).

Soporte de subshell

El soporte de subshell es una opción de compilación, que funciona con los shells: bash, ash (BusyBox y Debian), (o/m)ksh, tcsh, zsh y fish.

Cuando el soporte de subshell está activo, Midnight Commander iniciará una copia concurrente de su shell (el definido en la variable SHELL y si no está definido, el del archivo /etc/passwd) y lo ejecutará en un pseudo terminal, en lugar de invocar un nuevo shell cada vez que ejecute un comando, el comando se pasará al subshell

Los usuarios de bash pueden especificar comandos de inicio en ~/.local/share/mc/bashrc (fallback ~/.bashrc) y mapas de teclado especiales en ~/.local/share/mc/inputrc (fallback ~/.inputrc).

Los usuarios de ash/dash (BusyBox o Debian) pueden especificar comandos de inicio en ~/.local/share/mc/ashrc (fallback ~/.profile).

Los usuarios de ksh/oksh (variantes de PD ksh) pueden especificar comandos de inicio en ~/.local/share/mc/kshrc (fallback ENV o ~/.profile).

Los usuarios de mksh (MirBSD ksh) pueden especificar comandos de inicio en ~/.local/share/mc/mkshrc (fallback ENV o ~/.mkshrc).

Los usuarios de zsh pueden especificar comandos de inicio en ~/.local/share/mc/.zshrc (fallback ~/.zshrc).

Los usuarios de tcsh, fish actualmente no pueden especificar comandos de inicio específicos de mc. Tienen que confiar en los archivos de inicio específicos de su shell.

Los siguientes párrafos son relevantes solo cuando el soporte de subshell está activo:

Chmod

La ventana Chmod se utiliza para cambiar los bits de atributo de un grupo de archivos y directorios. Se puede invocar con la combinación de teclas C-x c.

La ventana Chmod tiene dos partes: Permisos y Archivo.

En la sección Archivo se muestra el nombre del archivo o directorio y sus permisos en formato octal, así como su propietario y grupo.

En la sección Permisos hay un conjunto de casillas de verificación que corresponden a los bits de atributo del archivo. A medida que cambias los bits de atributo, puedes ver cómo cambia el valor octal en la sección Archivo.

Para moverse entre los widgets (botones y casillas de verificación) usa las teclas de flecha o la tecla Tab. Para cambiar el estado de las casillas de verificación o para seleccionar un botón usa Espacio. También puedes usar las teclas de acceso rápido en los botones para activarlos rápidamente. Las teclas de acceso rápido se muestran como letras resaltadas en los botones.

Para establecer los bits de atributo, usa la tecla Enter.

Al trabajar con un grupo de archivos o directorios, simplemente haz clic en los bits que deseas establecer o borrar. Una vez que hayas seleccionado los bits que deseas cambiar, selecciona uno de los botones de acción (Establecer marcados o Borrar marcados).

Finalmente, para establecer los atributos exactamente a los especificados, puedes usar el botón [Establecer todos], que actuará sobre todos los archivos marcados.

[Todos marcados] establece solo los atributos marcados en todos los archivos seleccionados

[Establecer marcados] establece los bits marcados en los atributos de todos los archivos seleccionados

[Borrar marcados] borra los bits marcados en los atributos de todos los archivos seleccionados

[Establecer] establece los atributos de un archivo

[Cancelar] cancela el comando Chmod

Chown Avanzado

El comando Chown Avanzado es el comando Chmod y Chown combinado en una sola ventana. Puedes cambiar los permisos y el propietario/grupo de los archivos a la vez.

La lista de indicadores de atributos disponibles se representa como un conjunto de casillas de verificación que corresponden a los indicadores de atributos (ver chattr(1) para más detalles). [Establecer marcados] establece los indicadores marcados en los atributos de todos los archivos seleccionados.

[Borrar marcados] borra los indicadores marcados en los atributos de todos los archivos seleccionados.

Copia/Renombrado con Máscara

Las operaciones de copia/movimiento te permiten traducir los nombres de los archivos de forma sencilla. Para hacerlo, debes especificar la máscara de origen correcta y, generalmente, en la parte final del destino especificar algunos comodines. Todos los archivos que coincidan con la máscara de origen se copian/renombran según la máscara de destino. Si hay archivos marcados, solo se renombran los archivos marcados que coincidan con la máscara de origen.

Hay otras opciones que puedes configurar:

Seguir enlaces

determina si se crean los enlaces simbólicos y duros en el directorio de origen (recursivamente en subdirectorios) como nuevos enlaces en el directorio de destino o si deseas copiar su contenido.

Entrar en subdirectorios

determina el comportamiento cuando el directorio de origen está a punto de ser copiado, pero el directorio de destino ya existe. La acción predeterminada es copiar el contenido del directorio de origen en el directorio de destino. Habilitar esta opción hace que se copie el propio directorio de origen en el directorio de destino.

Por ejemplo, quieres copiar el directorio /foo que contiene el archivo bar a /bla/foo, que es un directorio ya existente. Normalmente (cuando Entrar en subdirectorios no está configurado), mc copiaría el archivo /foo/bar al archivo /bla/foo/bar. Al habilitar esta opción, se creará el directorio /bla/foo/foo, y /foo/bar se copiará en /bla/foo/foo/bar

Preservar atributos

determina si se deben preservar los permisos, las marcas de tiempo y (si eres root) la propiedad de los archivos originales. Si esta opción no está configurada, se respetará el valor actual de la umask.

Usar patrones de shell

Cuando esta opción está activada, puedes usar los comodines '*' y '?' en la máscara de origen. Funcionan como en el shell. En la máscara de destino solo se permiten los comodines '*' y '\'. El primer comodín '*' en la máscara de destino corresponde al primer grupo de comodines en la máscara de origen, el segundo '*' corresponde al segundo grupo y así sucesivamente. El comodín '\1' corresponde al primer grupo de comodines en la máscara de origen, el comodín '\2' corresponde al segundo grupo y así sucesivamente hasta '\9'. El comodín '\0' es el nombre de archivo completo del archivo de origen.

Dos ejemplos:

Si la máscara de origen es "*.tar.gz", el destino es "/bla/*.tgz" y el archivo a copiar es "foo.tar.gz", la copia será "foo.tgz" en "/bla".

Supongamos que quieres intercambiar la base del nombre y la extensión para que "file.c" se convierta en "c.file" y así sucesivamente. La máscara de origen para esto es "*.*" y el destino es "\2.\1".

Usar patrones de shell desactivados

Cuando la opción de patrones de shell está desactivada, el MC no hace agrupación automática. Debes usar expresiones '\(...\)' en la máscara de origen para especificar el significado de los comodines en la máscara de destino. Esto es más flexible pero también requiere más escritura. De lo contrario, las máscaras de destino son similares a la situación cuando la opción de patrones de shell está activada.

Dos ejemplos:

Si la máscara de origen es "^\(.*\)\.tar\.gz$", el destino es "/bla/*.tgz" y el archivo a copiar es "foo.tar.gz", la copia será "/bla/foo.tgz".

Supongamos que quieres intercambiar la base del nombre y la extensión para que "file.c" se convierta en "c.file" y así sucesivamente. La máscara de origen para esto es "^\(.*\)\.\(.*\)$" y el destino es "\2.\1".

Conversiones de mayúsculas/minúsculas

También puedes cambiar las mayúsculas/minúsculas de los nombres de archivo. Si usas '\u' o '\l' en la máscara de destino, el siguiente carácter se convertirá a mayúscula o minúscula respectivamente.

Si usas '\U' o '\L' en la máscara de destino, los siguientes caracteres se convertirán a mayúscula o minúscula respectivamente hasta el siguiente '\E' o el siguiente '\U', '\L' o el final del nombre del archivo.

Los '\u' y '\l' son más fuertes que '\U' y '\L'.

Por ejemplo, si la máscara de origen es '*' (*Usar patrones de shell* activado) o '^\(.*\)$' (*Usar patrones de shell* desactivado) y la máscara de destino es '\L\u*' los nombres de archivo se convertirán para tener la inicial en mayúscula y el resto en minúscula.

También puedes usar '\' como carácter de escape. Por ejemplo, '\\' es una barra invertida y '\*' es un asterisco.

Con enlaces simbólicos absolutos esto no hace nada, pero si tienes uno relativo, recomputará su valor, añadiendo los ../ necesarios y otras partes del directorio y haciendo el valor lo más corto posible (la mayoría de los sistemas de archivos modernos guardan enlaces simbólicos cortos dentro de los inodos y por lo tanto no desperdician mucho espacio en disco).

Completion

Let Midnight Commander type for you.

Attempt to perform completion on the text before current position. MC attempts completion treating the text as variable (if the text begins with $), username (if the text begins with ~), hostname (if the text begins with @) or command (if you are on the command line in the position where you might type a command, possible completions then include shell reserved words and shell built-in commands as well) in turn. If none of these matches, filename completion is attempted.

Filename, username, variable and hostname completion works on all input lines, command completion is command line specific. If the completion is ambiguous (there are more different possibilities), MC beeps and the following action depends on the setting of the Complete: show all option in the Configuration dialog. If it is enabled, a list of all possibilities pops up next to the current position and you can select with the arrow keys and Enter the correct entry. You can also type the first letters in which the possibilities differ to move to a subset of all possibilities and complete as much as possible. If you press Alt-Tab again, only the subset will be shown in the listbox, otherwise the first item which matches all the previous characters will be highlighted. As soon as there is no ambiguity, dialog disappears, but you can hide it by canceling keys Esc, F10 and left and right arrow keys. If Complete: show all is disabled, the dialog pops up only if you press Alt-Tab for the second time, for the first time MC just beeps.

Virtual File System

Midnight Commander is provided with a code layer to access the file system; this code layer is known as the virtual file system switch. The virtual file system switch allows Midnight Commander to manipulate files not located on the Unix file system.

Currently, Midnight Commander is packaged with some Virtual File Systems (VFS): the local file system, used for accessing the regular Unix file system; the ftpfs, used to manipulate files on remote systems with the FTP protocol; the tarfs, used to manipulate tar and compressed tar files; the undelfs, used to recover deleted files on ext2 file systems (the default file system for Linux systems), shell (for manipulating files over shell connections such as rsh and ssh). If the code was compiled with sftpfs (for manipulating files over SFTP connections).

A generic extfs (EXTernal virtual File System) is provided in order to easily expand VFS capabilities using scripts and external software.

The VFS switch code will interpret all of the path names used and will forward them to the correct file system, the formats used for each one of the file systems is described later in their own section.

FTP File System

The FTP File System (ftpfs) allows you to manipulate files on remote machines. To actually use it, you can use the FTP link item in the menu or directly change your current directory using the cd command to a path name that looks like this:

ftp://[!][user[:pass]@]machine[:port]/[remote-dir]

The user, port and remote-dir elements are optional. If you specify the user element, Midnight Commander will login to the remote machine as that user, otherwise it will use anonymous login or the login name from the ~/.netrc file. The optional pass element is the password used for the connection. Using the password in the VFS directory name is not recommended, because it can appear on the screen in clear text and can be saved to the directory history.

To enable using FTP proxy, prepend ! (an exclamation sign) to the hostname.

Examples:

    ftp://ftp.nuclecu.unam.mx/linux/local
    ftp://tsx-11.mit.edu/pub/linux/packages
    ftp://!behind.firewall.edu/pub
    ftp://guest@remote-host.com:40/pub
    ftp://miguel:xxx@server/pub

Please check the Virtual File System dialog box for ftpfs options.

Tar File System

The tar file system provides you with read-only access to your tar files and compressed tar files by using the chdir command. To change your directory to a tar file, you change your current directory to the tar file by using the following syntax:

/filename.tar/utar://[dir-inside-tar]

The mc.ext.ini file already provides a shortcut for tar files, this means that usually you just point to a tar file and press return to enter into the tar file, see the Edit Extension File section for details on how this is done.

Examples:

    mc-3.0.tar.gz/utar://mc-3.0/vfs
    /ftp/GCC/gcc-2.7.0.tar/utar://

>El último especifica la ruta completa del archivo tar.

Transferencia de archivos a través del sistema de archivos de shell

El sistema de archivos shell es un sistema de archivos basado en red que te permite manipular los archivos en una máquina remota como si fueran locales. Para usar esto, el otro lado debe tener un shell compatible con bash.

Para conectarte a una máquina remota, solo necesitas cambiar de directorio a un directorio especial cuyo nombre tiene el siguiente formato:

sh://[usuario@]máquina[:opciones]/[directorio-remoto]

Los elementos usuario, opciones y directorio-remoto son opcionales. Si especificas el elemento usuario, Midnight Commander intentará iniciar sesión en la máquina remota como ese usuario; de lo contrario, utilizará tu nombre de inicio de sesión.

Las opciones disponibles son:

  'C' - usar compresión;
  'r' - usar rsh en lugar de ssh;
  puerto - especificar el puerto utilizado por el servidor remoto.
Si el elemento directorio-remoto está presente, tu directorio actual en la máquina remota se establecerá a este.

Ejemplos:

    sh://onlyrsh.mx:r/linux/local
    sh://joe@want.compression.edu:C/private
    sh://joe@noncompressed.ssh.edu/private
    sh://joe@somehost.ssh.edu:2222/private

SFTP (Protocolo de Transferencia de Archivos SSH) sistema de archivos

El sistema de archivos SFTP es un sistema de archivos basado en red que te permite manipular los archivos en una máquina remota como si fueran locales.

Para conectarte a una máquina remota, solo necesitas cambiar de directorio a un directorio especial cuyo nombre tiene el siguiente formato:

sftp://[usuario@]máquina:[puerto]/[directorio-remoto]

Los elementos usuario, puerto y directorio-remoto son opcionales. Si especificas el elemento usuario, Midnight Commander intentará iniciar sesión en la máquina remota como ese usuario; de lo contrario, utilizará tu nombre de inicio de sesión. puerto - especifica el puerto utilizado por el servidor remoto (22 por defecto). Si el elemento directorio-remoto está presente, tu directorio actual en la máquina remota se establecerá a este.

Ejemplos:

    sftp://onlyrsh.mx/linux/local
    sftp://joe:contraseña@want.compression.edu/private
    sftp://joe@noncompressed.ssh.edu/private
    sftp://joe@somehost.ssh.edu:2222/private

Al establecer la conexión, la huella digital de la clave del servidor se verifica utilizando el archivo ~/.ssh/known_hosts. Si el par host/clave no se encuentra o se encuentra el host pero la clave no coincide, se mostrará un mensaje apropiado. Hay tres botones en el cuadro de diálogo del mensaje:

[Sí] agrega el nuevo par host/clave al archivo ~/.ssh/known_hosts y continúa.

[Ignorar] no agrega el nuevo par host/clave al archivo ~/.ssh/known_hosts, pero continúa de todos modos (bajo tu propio riesgo).

[No] aborta la conexión.

Sistema de archivos de recuperación de archivos

En sistemas Linux, si solicitaste a la configuración que utilizara las instalaciones de recuperación de archivos de ext2fs, tendrás disponible el sistema de archivos de recuperación. La recuperación de archivos eliminados solo está disponible en sistemas de archivos ext2. El sistema de archivos de recuperación es solo una interfaz a la biblioteca ext2fs para recuperar los nombres de todos los archivos eliminados en un ext2fs y proporciona y permite extraer los archivos seleccionados en una partición regular.

Para usar este sistema de archivos, debes cambiar de directorio al nombre de archivo especial formado por el prefijo "undel://" y el nombre del archivo donde reside el sistema de archivos real.

Por ejemplo, para recuperar archivos eliminados en la segunda partición del primer disco SCSI en Linux, usarías el siguiente nombre de ruta:

    undel://sda2

Puede llevar un tiempo para que undelfs cargue la información requerida antes de que comiences a navegar por los archivos allí.

  cd documents.zip/uzip://

TERMINAL DATABASES

Midnight Commander proporciona una forma de corregir la base de datos de su terminal del sistema sin necesidad de privilegios de root. Midnight Commander busca en el archivo de inicialización del sistema (el archivo mc.lib ubicado en el directorio de bibliotecas de Midnight Commander) y en el archivo ~/.config/mc/ini para la sección "terminal:su-nombre-de-terminal" y luego para la sección "terminal:general", cada línea de la sección contiene un símbolo de clave que desea definir, seguido de un signo igual y la definición de la clave. Puede usar la forma especial \e para representar el carácter de escape y ^x para representar el carácter de control-x.

Los símbolos de clave posibles son:

f0 a f20     Teclas de función f0-f20
bs            retroceso (backspace)
home          tecla inicio (home)
end           tecla fin (end)
up            tecla de flecha arriba
down          tecla de flecha abajo
left          tecla de flecha izquierda
right         tecla de flecha derecha
pgdn          tecla de avance de página (page down)
pgup          tecla de retroceso de página (page up)
insert        carácter de inserción
delete        carácter de eliminación
complete      para realizar la completación

Por ejemplo, para definir la tecla de inserción como Escape + [ + O + p, establezca esto en el archivo ini:

insert=\e[Op

Ahora también puede usar aprendiendo teclas extendidas. Por ejemplo:

    ctrl-alt-right=\e[[1;6C
    ctrl-alt-left=\e[[1;6D

Esto significa que ctrl+alt+izquierda envía una secuencia de escape \e[[1;6D y, por lo tanto, Midnight Commander interpreta "\e[[1;6D" como C-Alt-Izquierda.

El símbolo de clave complete representa las secuencias de escape utilizadas para invocar el proceso de completación, esto se invoca con Alt-tab, pero puede definir otras teclas para realizar el mismo trabajo (en esos teclados con toneladas de teclas agradables y sin usar en todas partes).

ARCHIVOS

Las rutas completas a continuación pueden variar entre instalaciones. También se ven afectadas por la variable de entorno MC_DATADIR. Si se establece, su valor se utiliza en lugar de /usr/share/mc en las rutas a continuación.

/usr/share/mc/help/mc.hlp

El archivo de ayuda del programa.

/usr/share/mc/mc.ext.ini

El archivo de extensiones predeterminado a nivel de sistema.

~/.config/mc/mc.ext.ini

Las extensiones propias del usuario, la vista de configuración y el archivo de configuración de edición. Anulan el contenido de los archivos sistémicos si están presentes.

/etc/mc/mc.ini
/usr/share/mc/mc.ini

Archivos de configuración del sistema para Midnight Commander, utilizados solo si el usuario no tiene su propio archivo ~/.config/mc/ini. Si /etc/mc/mc.ini existe, /usr/share/mc/mc.ini no se utiliza.

/usr/share/mc/mc.lib

Configuraciones globales para Midnight Commander. La configuración en este archivo afecta a todos los usuarios, tengan o no ~/.config/mc/ini. Actualmente, solo la configuración de la terminal se carga desde mc.lib.

~/.config/mc/ini

Configuración propia del usuario. Si este archivo está presente, la configuración se carga desde aquí en lugar del archivo de inicio del sistema.

/usr/share/mc/hints/mc.hint

Este archivo contiene las sugerencias mostradas por el programa.

/usr/share/mc/mc.menu

Este archivo contiene el menú de aplicaciones predeterminado a nivel de sistema.

~/.config/mc/menu

Menú de aplicaciones propio del usuario. Si este archivo está presente, se utiliza en lugar del menú de aplicaciones del sistema.

~/.cache/mc/Tree

La lista de directorios para las funciones de árbol de directorios y vista de árbol.

~/.local/share/mc.menu

Menú definido por el usuario local. Si este archivo está presente, se utiliza en lugar del menú de aplicaciones del hogar o del sistema.

Para cambiar el directorio raíz predeterminado de MC, puede usar la variable de entorno MC_PROFILE_ROOT. El valor de MC_PROFILE_ROOT debe ser una ruta absoluta. Si MC_PROFILE_ROOT no está establecido o está vacío, se utiliza la variable HOME. Si HOME no está establecido o está vacío, los directorios de MC se obtienen de la biblioteca GLib.
