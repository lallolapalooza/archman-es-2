NOMBRE

mqttui-clean-retained - Limpia mensajes retenidos del broker

SINOPSIS

mqttui clean-retained [--timeout] [--dry-run] [-b|--broker] [-u|--username] [--password] [-i|--client-id] [--client-cert] [--client-key] [--insecure] [-h|--help] <TEMA>

DESCRIPCIÓN

Limpia mensajes retenidos del broker.

Esto funciona suscribiéndose al tema y esperando mensajes con la bandera retenida. Luego, se publica un mensaje con una carga útil vacía y retenida, lo que borra el tema en el broker. Termina en el primer mensaje no retenido o cuando se alcanza el tiempo de espera.

OPCIONES

--timeout=SEGUNDOS [por defecto: 5]
Cuando no se recibe ningún mensaje durante el tiempo indicado, la operación se considera completada.
--dry-run
No limpiar temas, solo registrarlos.
-h, --help
Imprime la ayuda (ver un resumen con '-h').
<TEMA>
Tema que se limpia.

Soporta filtros como 'foo/bar/#'.

CONEXIÓN MQTT

-b, --broker=URL [por defecto: mqtt://localhost]
URL que representa cómo conectarse al broker MQTT.

Ejemplos: `mqtt://localhost` `mqtt://localhost:1883` `mqtts://localhost` `mqtts://localhost:8883` `ws://localhost/path` `ws://localhost:9001/path` `wss://localhost/path` `wss://localhost:9001/path`

También se puede especificar con la variable de entorno MQTTUI_BROKER.
-u, --username=CADENA
Nombre de usuario para acceder al broker mqtt.

Acceso anónimo cuando no se proporciona.

También se puede especificar con la variable de entorno MQTTUI_USERNAME.
--password=CADENA
Contraseña para acceder al broker mqtt.

Considere usar una conexión con TLS al broker. De lo contrario, la contraseña se transportará en texto plano.

Pasar la contraseña por línea de comandos es inseguro, ya que se puede leer del historial. Debería pasarla a través de una variable de entorno.

También se puede especificar con la variable de entorno MQTTUI_PASSWORD.
-i, --client-id=CADENA
Especifica el ID del cliente con el que conectar.
También se puede especificar con la variable de entorno MQTTUI_CLIENTID.
--client-cert=RUTA_ARCHIVO
Ruta al archivo del certificado de cliente TLS.

Se utiliza junto con --client-key para habilitar la autenticación de cliente TLS. El archivo debe ser un certificado X.509 codificado en DER serializado a PEM.

También se puede especificar con la variable de entorno MQTTUI_CLIENT_CERTIFICATE.
--client-key=RUTA_ARCHIVO
Ruta a la clave privada del cliente TLS.

Se utiliza junto con --client-cert para habilitar la autenticación de cliente TLS. El archivo debe ser un archivo ASN.1 codificado en DER en formato PKCS#8 serializado a PEM.

También se puede especificar con la variable de entorno MQTTUI_CLIENT_PRIVATE_KEY.
--insecure
Permitir conexiones TLS inseguras.
