NOMBRE

mq_overview - descripción general de las colas de mensajes POSIX

DESCRIPCIÓN

Las colas de mensajes POSIX permiten a los procesos intercambiar datos en forma de mensajes. Esta API es distinta de la proporcionada por las colas de mensajes de System V (msgget(2), msgsnd(2), msgrcv(2), etc.), pero proporciona una funcionalidad similar.

Las colas de mensajes se crean y abren usando mq_open(3); esta función devuelve un descriptor de cola de mensajes (mqd_t), que se utiliza para referirse a la cola de mensajes abierta en llamadas posteriores. Cada cola de mensajes se identifica por un nombre de la forma /algún_nombre; es decir, una cadena terminada en nulo de hasta NAME_MAX (es decir, 255) caracteres que consisten en una barra inicial, seguida de uno o más caracteres, ninguno de los cuales son barras. Dos procesos pueden operar en la misma cola pasando el mismo nombre a mq_open(3).

Los mensajes se transfieren hacia y desde una cola usando mq_send(3) y mq_receive(3). Cuando un proceso ha terminado de usar la cola, la cierra usando mq_close(3), y cuando la cola ya no es necesaria, se puede eliminar usando mq_unlink(3). Los atributos de la cola se pueden recuperar y (en algunos casos) modificar usando mq_getattr(3) y mq_setattr(3). Un proceso puede solicitar notificación asíncrona de la llegada de un mensaje a una cola previamente vacía usando mq_notify(3).

Un descriptor de cola de mensajes es una referencia a una descripción abierta de cola de mensajes (ver open(2)). Después de un fork(2), un hijo hereda copias de los descriptores de cola de mensajes de su padre, y estos descriptores se refieren a las mismas descripciones abiertas de cola de mensajes que los descriptores de cola de mensajes correspondientes en el padre. Los descriptores de cola de mensajes correspondientes en los dos procesos comparten las banderas (mq_flags) que están asociadas con la descripción abierta de la cola de mensajes.

Cada mensaje tiene una prioridad asociada, y los mensajes se entregan siempre al proceso receptor por prioridad más alta primero. Las prioridades de los mensajes van desde 0 (baja) hasta sysconf(_SC_MQ_PRIO_MAX) - 1 (alta). En Linux, sysconf(_SC_MQ_PRIO_MAX) devuelve 32768, pero POSIX.1 solo requiere que una implementación soporte al menos prioridades en el rango de 0 a 31; algunas implementaciones solo proporcionan este rango.

El resto de esta sección describe algunos detalles específicos de la implementación de Linux de las colas de mensajes POSIX.

Interfaces de librería y llamadas al sistema

En la mayoría de los casos, las interfaces de librería mq_*() mencionadas anteriormente se implementan sobre llamadas al sistema subyacentes del mismo nombre. Las desviaciones de este esquema se indican en la siguiente tabla:

mq_getattr(3) mq_getsetattr(2)
mq_notify(3) mq_notify(2)
mq_open(3) mq_open(2)

mq_send(3) mq_timedsend(2)
mq_setattr(3) mq_getsetattr(2)

Versiones

Las colas de mensajes POSIX han sido soportadas desde Linux 2.6.6. El soporte de glibc ha estado disponible desde glibc 2.3.4.

Configuración del kernel

El soporte para colas de mensajes POSIX es configurable a través de la opción de configuración del kernel CONFIG_POSIX_MQUEUE. Esta opción está habilitada por defecto.

Persistencia

Las colas de mensajes POSIX tienen persistencia en el kernel: si no se eliminan con mq_unlink(3), una cola de mensajes existirá hasta que el sistema se apague.

Enlazado

Los programas que utilizan la API de colas de mensajes POSIX deben compilarse con cc -lrt para enlazar contra la librería de tiempo real, librt.

Interfaces /proc

Las siguientes interfaces se pueden utilizar para limitar la cantidad de memoria del kernel consumida por las colas de mensajes POSIX y para establecer los atributos predeterminados para las nuevas colas de mensajes:

/proc/sys/fs/mqueue/msg_default (desde Linux 3.5)
Este archivo define el valor utilizado para la configuración mq_maxmsg de una nueva cola cuando la cola se crea con una llamada a mq_open(3) donde attr se especifica como NULL. El valor predeterminado para este archivo es 10. El mínimo y el máximo son los mismos que para /proc/sys/fs/mqueue/msg_max. El valor mq_maxmsg predeterminado de una nueva cola será el menor entre msg_default y msg_max. Antes de Linux 2.6.28, el mq_maxmsg predeterminado era 10; desde Linux 2.6.28 hasta Linux 3.4, el predeterminado era el valor definido para el límite de msg_max.
/proc/sys/fs/mqueue/msg_max
Este archivo se puede utilizar para ver y cambiar el valor límite máximo para el número máximo de mensajes en una cola. Este valor actúa como un límite superior para el argumento attr->mq_maxmsg proporcionado a mq_open(3). El valor predeterminado para msg_max es 10. El valor mínimo es 1 (10 antes de Linux 2.6.28). El límite superior es HARD_MSGMAX. El límite de msg_max se ignora para procesos privilegiados (CAP_SYS_RESOURCE), pero el límite superior HARD_MSGMAX se impone de todos modos.
La definición de HARD_MSGMAX ha cambiado en las versiones del kernel:
•
Hasta Linux 2.6.32: 131072 / sizeof(void *)
•
Linux 2.6.33 a Linux 3.4: (32768 * sizeof(void *) / 4)
•
Desde Linux 3.5: 65,536
/proc/sys/fs/mqueue/msgsize_default (desde Linux 3.5)
Este archivo define el valor utilizado para la configuración mq_msgsize de una nueva cola cuando la cola se crea con una llamada a mq_open(3) donde attr se especifica como NULL. El valor predeterminado para este archivo es 8192 (bytes). El mínimo y el máximo son los mismos que para /proc/sys/fs/mqueue/msgsize_max. Si msgsize_default excede msgsize_max, el valor mq_msgsize predeterminado de una nueva cola se limitará al límite de msgsize_max. Antes de Linux 2.6.28, el mq_msgsize predeterminado era 8192; desde Linux 2.6.28 hasta Linux 3.4, el predeterminado era el valor definido para el límite de msgsize_max.
/proc/sys/fs/mqueue/msgsize_max
Este archivo se puede utilizar para ver y cambiar el límite superior en el tamaño máximo del mensaje. Este valor actúa como un límite superior para el argumento attr->mq_msgsize proporcionado a mq_open(3). El valor predeterminado para msgsize_max es 8192 bytes. El valor mínimo es 128 (8192 antes de Linux 2.6.28). El límite superior para msgsize_max ha variado en las versiones del kernel:
•
Antes de Linux 2.6.28, el límite superior es INT_MAX.
•
Desde Linux 2.6.28 hasta Linux 3.4, el límite es 1,048,576.
•
Desde Linux 3.5, el límite es 16,777,216 (HARD_MSGSIZEMAX).
El límite msgsize_max se ignora para procesos privilegiados (CAP_SYS_RESOURCE), pero, desde Linux 3.5, el límite superior HARD_MSGSIZEMAX se aplica a los procesos privilegiados.

NOMBRE

mq_overview - resúmenes de colas de mensajes POSIX

DESCRIPCIÓN

Las colas de mensajes POSIX proporcionan un método para que los procesos intercambien mensajes de datos de longitud variable. Se definen en el estándar POSIX.1-2001 y están disponibles en la mayoría de los sistemas operativos similares a Unix.

Las funciones principales para interactuar con colas de mensajes POSIX son:

•
mq_open(2): crea una nueva cola de mensajes o abre una existente.
•
mq_close(3): cierra un descriptor de cola de mensajes.
•
mq_unlink(3): elimina una cola de mensajes del sistema.
•
mq_send(3): envía un mensaje a una cola de mensajes.
•
mq_receive(3): recibe un mensaje de una cola de mensajes.
•
mq_getattr(3): obtiene los atributos de una cola de mensajes.
•
mq_setattr(2): establece los atributos de una cola de mensajes.
•
mq_notify(3): registra un proceso para ser notificado cuando un mensaje llega a una cola de mensajes.

Límites del sistema

El sistema impone un límite al número de colas de mensajes que se pueden crear en todo el sistema. Este límite se controla mediante el parámetro del kernel queues_max. Puede ver y modificar el límite del sistema para el número de colas de mensajes que se pueden crear. El valor predeterminado para queues_max es 256. No hay un límite superior impuesto en el límite queues_max; los procesos privilegiados (CAP_SYS_RESOURCE) pueden exceder el límite (pero vea BUGS).

Límite de recursos

El límite de recursos RLIMIT_MSGQUEUE, que impone un límite a la cantidad de espacio que pueden consumir todas las colas de mensajes pertenecientes al ID de usuario real de un proceso, se describe en getrlimit(2).

Montaje del sistema de archivos de colas de mensajes

En Linux, las colas de mensajes se crean en un sistema de archivos virtual. (Otras implementaciones también pueden proporcionar una función de este tipo, pero es probable que los detalles difieran). Este sistema de archivos puede ser montado (por el superusuario) utilizando los siguientes comandos:


# mkdir /dev/mqueue
# mount -t mqueue none /dev/mqueue

El bit "sticky" se habilita automáticamente en el directorio de montaje.

Después de que el sistema de archivos ha sido montado, las colas de mensajes en el sistema pueden ser vistas y manipuladas utilizando los comandos que normalmente se usan para archivos (por ejemplo, ls(1) y rm(1)).

El contenido de cada archivo en el directorio consiste en una sola línea que contiene información sobre la cola:


$ cat /dev/mqueue/mymq
QSIZE:129     NOTIFY:2    SIGNO:0    NOTIFY_PID:8260

Estos campos son los siguientes:

QSIZE
Número de bytes de datos en todos los mensajes de la cola (pero vea BUGS).
NOTIFY_PID
Si este valor es distinto de cero, entonces el proceso con este PID ha utilizado mq_notify(3) para registrarse para la notificación asíncrona de mensajes, y los campos restantes describen cómo ocurre la notificación.
NOTIFY
Método de notificación: 0 es SIGEV_SIGNAL; 1 es SIGEV_NONE; y 2 es SIGEV_THREAD.
SIGNO
Número de señal a utilizar para SIGEV_SIGNAL.

Implementación en Linux de descriptores de cola de mensajes

En Linux, un descriptor de cola de mensajes es en realidad un descriptor de archivo. (POSIX no requiere tal implementación). Esto significa que un descriptor de cola de mensajes puede ser monitoreado usando select(2), poll(2), o epoll(7). Esto no es portable.

La bandera "close-on-exec" (ver open(2)) se establece automáticamente en el descriptor de archivo devuelto por mq_open(2).

Espacios de nombres IPC

Para una discusión sobre la interacción de los objetos de colas de mensajes POSIX y los espacios de nombres IPC, vea ipc_namespaces(7).

NOTAS

Las colas de mensajes System V (msgget(2), msgsnd(2), msgrcv(2), etc.) son una API más antigua para intercambiar mensajes entre procesos. Las colas de mensajes POSIX proporcionan una interfaz mejor diseñada que las colas de mensajes System V; por otro lado, las colas de mensajes POSIX son menos ampliamente disponibles (especialmente en sistemas más antiguos) que las colas de mensajes System V.

Linux actualmente (Linux 2.6.26) no soporta el uso de listas de control de acceso (ACL) para colas de mensajes POSIX.

ERRORES

Desde Linux 3.5 hasta Linux 3.14, el kernel impuso un límite de 1024 (HARD_QUEUESMAX) al valor al que se podía aumentar el límite queues_max, y el límite se aplicaba incluso a los procesos privilegiados. Este límite se eliminó en Linux 3.14, y los parches a las versiones estables de Linux 3.5.x a 3.13.x también eliminaron el límite.

Como se implementó originalmente (y se documentó), el campo QSIZE mostraba el número total de bytes (suministrados por el usuario) en todos los mensajes de la cola de mensajes. Algunos cambios en Linux 3.5 modificaron inadvertidamente el comportamiento, de modo que este campo también incluía un recuento de bytes de sobrecarga del kernel utilizados para almacenar los mensajes en la cola. Esta regresión de comportamiento se rectificó en Linux 4.2 (y versiones anteriores estables del kernel), de modo que el recuento solo incluía una vez más los bytes de datos del usuario en los mensajes de la cola.

EJEMPLOS

Un ejemplo del uso de varias funciones de cola de mensajes se muestra en mq_notify(3).
