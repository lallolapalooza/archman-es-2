MQTT(7) Convenciones y miscelánea MQTT(7)

NOMBRE

mqtt - MQ Telemetry Transport

SINOPSIS

MQTT

DESCRIPCIÓN

MQTT es un protocolo de mensajería ligero de publicación/suscripción. Es útil para usar con sensores de bajo consumo, pero es aplicable a muchos escenarios.

Este manual describe algunas de las características de MQTT versión 3.1.1/3.1, para ayudar a los usuarios finales a sacar el máximo provecho del protocolo. Para obtener información más completa sobre MQTT, consulte http://mqtt.org/.

PUBLICACIÓN/SUSCRIPCIÓN

El protocolo MQTT se basa en el principio de publicar mensajes y suscribirse a temas, o "pub/sub". Múltiples clientes se conectan a un broker y se suscriben a temas que les interesan. Los clientes también se conectan al broker y publican mensajes en temas. Muchos clientes pueden suscribirse a los mismos temas y hacer con la información lo que deseen. El broker y MQTT actúan como una interfaz simple y común para que todo se conecte. Esto significa que si tienes clientes que volcán los mensajes suscritos a una base de datos, a Twitter, Cosm o incluso a un simple archivo de texto, entonces se vuelve muy simple agregar nuevos sensores u otra entrada de datos a una base de datos, Twitter o similar.

TEMAS/SUSCRIPCIONES

Los mensajes en MQTT se publican en temas. No es necesario configurar un tema, publicar en él es suficiente. Los temas se tratan como una jerarquía, utilizando una barra (/) como separador. Esto permite la creación de una organización sensata de temas comunes, muy parecido a un sistema de archivos. Por ejemplo, varias computadoras pueden publicar la información de temperatura de sus discos duros en el siguiente tema, reemplazando el nombre de su propia computadora y disco duro según corresponda:

•sensores/NOMBRE_DE_COMPUTADORA/temperatura/NOMBRE_DISCO_DURO

Los clientes pueden recibir mensajes creando suscripciones. Una suscripción puede ser a un tema explícito, en cuyo caso solo se recibirán mensajes para ese tema, o puede incluir comodines. Hay dos comodines disponibles, + o #.

+ se puede usar como comodín para un solo nivel de jerarquía. Podría usarse con el tema anterior para obtener información de todas las computadoras y discos duros de la siguiente manera:

•sensores/+/temperatura/+

Como otro ejemplo, para un tema de "a/b/c/d", las siguientes suscripciones de ejemplo coincidirán:

•a/b/c/d
•+/b/c/d
•a/+/c/d
•a/+/+/d
•+/+/+/+

Las siguientes suscripciones no coincidirán:

•a/b/c
•b/+/c/d
•+/+/+

# se puede usar como comodín para todos los niveles restantes de jerarquía. Esto significa que debe ser el último carácter en una suscripción. Con un tema de "a/b/c/d", las siguientes suscripciones de ejemplo coincidirán:

•a/b/c/d
•#
•a/#
•a/b/#
•a/b/c/#
•+/b/c/#

Los niveles de tema de longitud cero son válidos, lo que puede llevar a un comportamiento ligeramente no obvio. Por ejemplo, un tema de "a//tema" coincidiría correctamente con una suscripción de "a/+/tema". Asimismo, los niveles de tema de longitud cero pueden existir tanto al principio como al final de una cadena de tema, por lo que "/a/tema" coincidiría con una suscripción de "+/a/tema", "#" o "/#", y un tema "a/tema/" coincidiría con una suscripción de "a/tema/+" o "a/tema/#".

CALIDAD DE SERVICIO

MQTT define tres niveles de Calidad de Servicio (QoS). La QoS define cuánto se esforzarán el broker/cliente para asegurar que se reciba un mensaje. Los mensajes pueden enviarse en cualquier nivel de QoS, y los clientes pueden intentar suscribirse a temas en cualquier nivel de QoS. Esto significa que el cliente elige la QoS máxima que recibirá. Por ejemplo, si un mensaje se publica en QoS 2 y un cliente está suscrito con QoS 0, el mensaje se entregará a ese cliente con QoS 0. Si un segundo cliente también está suscrito al mismo tema, pero con QoS 2, recibirá el mismo mensaje pero con QoS 2. Para un segundo ejemplo, si un cliente está suscrito con QoS 2 y se publica un mensaje en QoS 0, el cliente lo recibirá en QoS 0.

Niveles más altos de QoS son más confiables, pero implican mayor latencia y tienen mayores requisitos de ancho de banda.

•0: El broker/cliente entregará el mensaje una vez, sin confirmación.
•1: El broker/cliente entregará el mensaje al menos una vez, requiriendo confirmación.
•2: El broker/cliente entregará el mensaje exactamente una vez utilizando un apretón de manos de cuatro pasos.

MENSAJES RETENIDOS

Todos los mensajes pueden configurarse para ser retenidos. Esto significa que el broker guardará el mensaje incluso después de enviarlo a todos los suscriptores actuales. Si se realiza una nueva suscripción que coincide con el tema del mensaje retenido, entonces el mensaje se enviará al cliente. Esto es útil como un mecanismo de "última buena conocida". Si un tema solo se actualiza con poca frecuencia, sin un mensaje retenido, un cliente recién suscrito podría tener que esperar mucho tiempo para recibir una actualización. Con un mensaje retenido, el cliente recibirá una actualización instantánea.

SESIÓN LIMPIA / CONEXIONES DURADERAS

Al conectarse, un cliente establece el indicador "sesión limpia", que a veces también se conoce como indicador "inicio limpio". Si la sesión limpia se establece en falso, la conexión se trata como duradera. Esto significa que cuando el cliente se desconecta, cualquier suscripción que tenga permanecerá y cualquier mensaje posterior de QoS 1 o 2 se almacenará hasta que se conecte nuevamente en el futuro. Si la sesión limpia es verdadera, todas las suscripciones se eliminarán para el cliente cuando se desconecte.

VOLUNTADES

Cuando un cliente se conecta a un broker, puede informarle que tiene una voluntad. Este es un mensaje que desea que el broker envíe cuando el cliente se desconecte inesperadamente. El mensaje de voluntad tiene un tema, QoS y estado de retención al igual que cualquier otro mensaje.
