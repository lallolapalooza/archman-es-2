MQ_OPEN(3P) Manual del programador POSIX MQ_OPEN(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

mq_open — abrir una cola de mensajes (TIEMPO REAL)

SINOPSIS

#include <mqueue.h>
mqd_t mq_open(const char *name, int oflag, ...);

DESCRIPCIÓN

La función mq_open() establecerá la conexión entre un proceso y una cola de mensajes con un descriptor de cola de mensajes. Creará una descripción de cola de mensajes abierta que se refiere a la cola de mensajes, y un descriptor de cola de mensajes que se refiere a esa descripción de cola de mensajes abierta. El descriptor de cola de mensajes se utiliza en otras funciones para referirse a esa cola de mensajes. El argumento name apunta a una cadena que nombra una cola de mensajes. No está especificado si el nombre aparece en el sistema de archivos y es visible para otras funciones que toman nombres de ruta como argumentos. El argumento name se ajusta a las reglas de construcción de un nombre de ruta, excepto que la interpretación de los caracteres <barra inclinada> distintos del carácter <barra inclinada> inicial en name está definida por la implementación, y que los límites de longitud para el argumento name están definidos por la implementación y no necesitan ser los mismos que los límites de nombres de ruta {PATH_MAX} y {NAME_MAX}. Si name comienza con el carácter <barra inclinada>, entonces los procesos que llaman a mq_open() con el mismo valor de name se referirán al mismo objeto de cola de mensajes, siempre que ese nombre no haya sido eliminado. Si name no comienza con el carácter <barra inclinada>, el efecto está definido por la implementación. Si el argumento name no es el nombre de una cola de mensajes existente y no se solicita la creación, mq_open() fallará y devolverá un error.

Un descriptor de cola de mensajes puede implementarse utilizando un descriptor de archivo, en cuyo caso las aplicaciones pueden abrir hasta al menos {OPEN_MAX} colas de mensajes y archivos.

El argumento oflag solicita el acceso de recepción y/o envío deseado a la cola de mensajes. Se concederá el permiso de acceso solicitado para recibir mensajes o enviar mensajes si al proceso que llama se le concediera acceso de lectura o escritura, respectivamente, a un archivo protegido equivalente.

El valor de oflag es la OR inclusiva a nivel de bits de los valores de la siguiente lista. Las aplicaciones especificarán exactamente una de las tres primeras (modos de acceso) a continuación en el valor de oflag:

O_RDONLY
Abrir la cola de mensajes para recibir mensajes. El proceso puede utilizar el descriptor de cola de mensajes devuelto con mq_receive(), pero no mq_send(). Una cola de mensajes puede abrirse varias veces en el mismo o en diferentes procesos para recibir mensajes.
O_WRONLY
Abrir la cola para enviar mensajes. El proceso puede utilizar el descriptor de cola de mensajes devuelto con mq_send() pero no mq_receive(). Una cola de mensajes puede abrirse varias veces en el mismo o en diferentes procesos para enviar mensajes.
O_RDWR
Abrir la cola tanto para recibir como para enviar mensajes. El proceso puede utilizar cualquiera de las funciones permitidas para O_RDONLY y O_WRONLY. Una cola de mensajes puede abrirse varias veces en el mismo o en diferentes procesos para enviar mensajes.

Se puede especificar cualquier combinación de las banderas restantes en el valor de oflag:

O_CREAT
Crear una cola de mensajes. Requiere dos argumentos adicionales: mode, que será de tipo mode_t, y attr, que será un puntero a una estructura mq_attr. Si el nombre de ruta name ya se ha utilizado para crear una cola de mensajes que todavía existe, esta bandera no tendrá efecto, excepto como se indica en O_EXCL. De lo contrario, se creará una cola de mensajes sin ningún mensaje en ella. El ID de usuario de la cola de mensajes se establecerá en el ID de usuario efectivo del proceso. El ID de grupo de la cola de mensajes se establecerá en el ID de grupo efectivo del proceso; sin embargo, si el argumento name es visible en el sistema de archivos, el ID de grupo puede establecerse en el ID de grupo del directorio que lo contiene. Cuando se especifican bits en mode distintos de los bits de permisos de archivo, el efecto no está especificado. Si attr es NULL, la cola de mensajes se creará con atributos de cola de mensajes predeterminados definidos por la implementación. Si attr no es NULL y el proceso que llama tiene los privilegios apropiados sobre name, los atributos mq_maxmsg y mq_msgsize de la cola de mensajes se establecerán en los valores de los miembros correspondientes en la estructura mq_attr a la que apunta attr. Los valores de los miembros mq_flags y mq_curmsgs de la estructura mq_attr se ignorarán. Si attr no es NULL, pero el proceso que llama no tiene los privilegios apropiados sobre name, la función mq_open() fallará y devolverá un error sin crear la cola de mensajes.
O_EXCL
Si O_EXCL y O_CREAT están configurados, mq_open() fallará si la cola de mensajes name existe. La comprobación de la existencia de la cola de mensajes y la creación de la cola de mensajes si no existe será atómica con respecto a otros hilos que ejecuten mq_open() nombrando el mismo name con O_EXCL y O_CREAT configurados. Si O_EXCL está configurado y O_CREAT no lo está, el resultado no está definido.
O_NONBLOCK
Determina si una mq_send() o mq_receive() espera recursos o mensajes que no están actualmente disponibles, o falla con errno establecido en [EAGAIN]; consulte mq_send() y mq_receive() para más detalles.

La función mq_open() no añade ni elimina mensajes de la cola.

VALOR DEVUELTO

Al completarse con éxito, la función devolverá un descriptor de cola de mensajes; de lo contrario, la función devolverá (mqd_t)-1 y establecerá errno para indicar el error.

ERRORES

La función mq_open() fallará si:

EACCES
La cola de mensajes existe y los permisos especificados por oflag son denegados, o la cola de mensajes no existe y el permiso para crear la cola de mensajes es denegado.
EEXIST
O_CREAT y O_EXCL están configurados y la cola de mensajes nombrada ya existe.
EINTR
La función mq_open() fue interrumpida por una señal.
EINVAL
La función mq_open() no es compatible para el nombre dado.
EINVAL
Se especificó O_CREAT en oflag, el valor de attr no es NULL, y bien mq_maxmsg o mq_msgsize fue menor o igual a cero.
EMFILE
Demasiados descriptores de cola de mensajes o descriptores de archivo están actualmente en uso por este proceso.
ENFILE
Demasiadas colas de mensajes están actualmente abiertas en el sistema.
ENOENT
O_CREAT no está configurado y la cola de mensajes nombrada no existe.
ENOSPC
No hay suficiente espacio para la creación de la nueva cola de mensajes.

Si alguna de las siguientes condiciones ocurre, la función mq_open() puede devolver (mqd_t)-1 y establecer errno al valor correspondiente.

ENAMETOOLONG

La longitud del argumento name excede {_POSIX_PATH_MAX} en sistemas que no admiten la opción XSI o excede {_XOPEN_PATH_MAX} en sistemas XSI, o tiene un componente de nombre de ruta que es más largo que {_POSIX_NAME_MAX} en sistemas que no admiten la opción XSI.

NAME

mq_open

- open a message queue

SYNOPSIS

<mqueue.h>

mqd_t mq_open(const char *name, int oflag);
mqd_t mq_open(const char *name, int oflag,
       mode_t mode, struct mq_attr *attr);

DESCRIPTION

The mq_open() function shall create a new message queue or open an existing message queue. The name of the message queue is specified by name. The name format is implementation-defined. On POSIX systems, the name is typically a name that can be resolved using the pathname resolution rules of the implementation (for example, "/myqueue").

The oflag argument specifies the access mode and creation flags. The access mode flags are:

O_RDONLY
Open the message queue for message reading only.
O_WRONLY
Open the message queue for message writing only.
O_RDWR
Open the message queue for both message reading and writing.

Only one of the access mode flags shall be specified. The default shall be to open for both reading and writing if neither flag is specified. The implementation shall support the O_RDONLY and O_WRONLY flags.

The following creation flags can be optionally specified in oflag and are specified in the POSIX standard:

O_CREAT
If the message queue named by name does not exist, it shall be created. If O_CREAT is specified, then either O_EXCL or O_NONBLOCK (or both) must also be specified. If O_CREAT is specified, the mode and attr arguments shall be used to create the new message queue. If O_CREAT is not specified, the modeattr arguments shall be ignored.
O_EXCL
If O_CREAT is specified, and O_EXCL is also specified, and a message queue with the specified name already exists, then mq_open() shall fail.
O_NONBLOCK
If O_NONBLOCK is specified:
  • If a message is requested using mq_receive() and no message is available, the call shall return immediately.
  • If a message is sent using mq_send() and the message queue is full, the call shall return immediately.
If O_NONBLOCK is not specified:
  • If a message is requested using mq_receive() and no message is available, the call shall block until a message is available.
  • If a message is sent using mq_send() and the message queue is full, the call shall block until space becomes available.

If the O_CREAT flag is specified in oflag, then the mode argument shall specify the permissions to be set for the new message queue. The permissions are a bitmask including S_IRUSR, S_IWUSR, S_IRGRP, S_IWGRP, S_IROTH, and S_IWOTH. The permissions are interpreted similar to the mode argument of open() on the file system. The effect of the S_ISUID and S_ISGID bits shall be ignored. The group ownership of the message queue is set to the effective group ID of the calling process, and the user ownership is set to the effective user ID of the calling process.

If the O_CREAT flag is specified in oflag, and the message queue is created, then the contents of the structure pointed to by attr shall specify the initial attributes for the new message queue. If attr is NULL, then the new message queue shall be created with implementation-defined default attributes. The following attributes are defined:

mq_maxmsg
The maximum number of messages that can be stored in the queue. This value shall be greater than 0.
mq_msgsize
The maximum length in bytes of a single message. This value shall be greater than 0.

The system limits for mq_maxmsg and mq_msgsize are defined by MQ_MAXMSG and MQ_MSGSIZE, respectively, in <mqueue.h>. The mq_maxmsg shall not be larger than MQ_MAXMSG. The mq_msgsize shall not be larger than MQ_MSGSIZE.

The name argument can specify a message queue that is not associated with a file system. The format of the name is implementation-defined. On systems that follow POSIX conventions, message queue names typically start with a forward slash (//) and follow pathname resolution rules. A name must be unique for each message queue. A name longer than _POSIX_PATH_MAX (which is 255) or longer than _XOPEN_NAME_MAX on XSI systems, results in undefined behavior.

RETURN VALUE

Upon successful completion, mq_open() shall return the message queue descriptor for the specified message queue. This descriptor is a non-negative integer. Otherwise, mq_open() shall return -1 and set errno to indicate the error.

ERRORS

EACCES
Read and-or write access permissions are not allowed for the requested access mode.
EEXIST
O_CREAT and O_EXCL were both specified in oflag, and the message queue named by name already exists.
EINTR
oflag specified block-delays and the call was interrupted by a signal.
EINVAL
The value specified in oflag is invalid.
EINVAL
O_CREAT was specified, and the attr argument is not NULL, and the values specified in the mq_maxmsg or mq_msgsize fields are invalid.
EMFILE
Too many message queue descriptors are allocated for the process.
ENAMETOOLONG
The length of the name argument exceeds _POSIX_PATH_MAX or _XOPEN_NAME_MAX on XSI systems.
ENOENT
O_CREAT was not specified in oflag and the message queue named by name does not exist.
ENOSPC
O_CREAT was specified, but too many message queues have been created for the system.
ENOSYS
The mq_open() function is not implemented for the system.
ENOTSUP
The name specified is not supported by the implementation.
