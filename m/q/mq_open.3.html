mq_open(3) Manual de Funciones de Biblioteca mq_open(3)

NOMBRE

mq_open - abrir una cola de mensajes

BIBLIOTECA

Biblioteca en tiempo real (librt, -lrt)

SINOPSIS

#include <fcntl.h>           /* Para constantes O_* */
#include <sys/stat.h>        /* Para constantes de modo */
#include <mqueue.h>
mqd_t mq_open(const char *name, int oflag);
mqd_t mq_open(const char *name, int oflag, mode_t mode,
              struct mq_attr *attr);

DESCRIPCIÓN

mq_open() crea una nueva cola de mensajes POSIX o abre una cola existente. La cola se identifica por name. Para detalles sobre la construcción de name, véase mq_overview(7).

El argumento oflag especifica las banderas que controlan la operación de la llamada. (Las definiciones de los valores de las banderas se pueden obtener incluyendo <fcntl.h>.) Se debe especificar exactamente una de las siguientes opciones en oflag:

O_RDONLY
Abrir la cola solo para recibir mensajes.
O_WRONLY
Abrir la cola solo para enviar mensajes.
O_RDWR
Abrir la cola para enviar y recibir mensajes.

Se pueden incluir cero o más de las siguientes banderas adicionalmente en oflag mediante una operación OR:

O_CLOEXEC (desde Linux 2.6.26)
Establecer la bandera de cierre al ejecutar (close-on-exec) para el descriptor de la cola de mensajes. Véase open(2) para una discusión sobre por qué esta bandera es útil.
O_CREAT
Crear la cola de mensajes si no existe. El propietario (ID de usuario) de la cola de mensajes se establece al ID de usuario efectivo del proceso que llama. La propiedad de grupo (ID de grupo) se establece al ID de grupo efectivo del proceso que llama.
O_EXCL
Si se especificó O_CREAT en oflag y ya existe una cola con el name dado, fallar con el error EEXIST.
O_NONBLOCK
Abrir la cola en modo no bloqueante. En circunstancias donde mq_receive(3) y mq_send(3) normalmente bloquearían, estas funciones fallarán en su lugar con el error EAGAIN.

Si se especifica O_CREAT en oflag, se deben suministrar dos argumentos adicionales. El argumento mode especifica los permisos que se aplicarán a la nueva cola, como en open(2). (Las definiciones simbólicas de los bits de permisos se pueden obtener incluyendo <sys/stat.h>). La configuración de permisos se enmascara contra el umask del proceso.

Los campos de la estructura struct mq_attr apuntada por attr especifican el número máximo de mensajes y el tamaño máximo de mensajes que la cola permitirá. Esta estructura se define de la siguiente manera:


struct mq_attr {
    long mq_flags;       /* Banderas (ignorado para mq_open()) */
    long mq_maxmsg;      /* Máx. # de mensajes en la cola */
    long mq_msgsize;     /* Máx. tamaño de mensaje (bytes) */
    long mq_curmsgs;     /* # de mensajes actualmente en la cola
                            (ignorado para mq_open()) */
};

Solo los campos mq_maxmsg y mq_msgsize se emplean al llamar a mq_open(); los valores en los campos restantes se ignoran.

Si attr es NULL, la cola se crea con atributos por defecto definidos por la implementación. Desde Linux 3.5, se pueden usar dos archivos de /proc para controlar estos valores por defecto; véase mq_overview(7) para más detalles.

VALOR DE RETORNO

En caso de éxito, mq_open() devuelve un descriptor de cola de mensajes para usarlo con otras funciones de cola de mensajes. En caso de error, mq_open() devuelve (mqd_t) -1, y errno se establece para indicar el error.

ERRORES

EACCES
La cola existe, pero el llamador no tiene permiso para abrirla en el modo especificado.
EACCES
name contenía más de una barra.
EEXIST
Se especificaron tanto O_CREAT como O_EXCL en oflag, pero ya existe una cola con este name.
EINVAL
name no sigue el formato de mq_overview(7).
EINVAL
Se especificó O_CREAT en oflag y attr no era NULL, pero attr->mq_maxmsg o attr->mq_msqsize era inválido. Ambos campos deben ser mayores que cero. En un proceso no privilegiado (que no tiene la capacidad CAP_SYS_RESOURCE), attr->mq_maxmsg debe ser menor o igual al límite msg_max, y attr->mq_msgsize debe ser menor o igual al límite msgsize_max. Además, incluso en un proceso privilegiado, attr->mq_maxmsg no puede exceder el límite HARD_MAX. (Véase mq_overview(7) para detalles de estos límites.)
EMFILE
Se alcanzó el límite por proceso del número de descriptores de archivos y colas de mensajes abiertos (véase la descripción de RLIMIT_NOFILE en getrlimit(2)).
ENAMETOOLONG
name era demasiado largo.
ENFILE
Se alcanzó el límite a nivel de sistema del número total de archivos y colas de mensajes abiertos.
ENOENT
La bandera O_CREAT no se especificó en oflag y no existe ninguna cola con este name.
ENOENT
name era solo "/" seguido de ningún otro carácter.
ENOMEM
Memoria insuficiente.
ENOSPC
Espacio insuficiente para la creación de una nueva cola de mensajes. Probablemente ocurrió porque se encontró el límite queues_max; véase mq_overview(7).

VERSIONES

Diferencias entre biblioteca C/kernel

La función de biblioteca mq_open() se implementa sobre una llamada al sistema del mismo nombre. La función de biblioteca realiza la verificación de que name comienza con una barra (/), devolviendo el error EINVAL si no es así. La llamada al sistema del kernel espera que name no contenga una barra previa, por lo que la función de la biblioteca C pasa name sin la barra previa (es decir, name+1) a la llamada al sistema.
