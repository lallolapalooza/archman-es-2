MINIUPNPC(3) Manual de funciones de la biblioteca MINIUPNPC(3)

NOMBRE

miniupnpc - biblioteca cliente UPnP

SINOPSIS

DESCRIPCIÓN

La biblioteca miniupnpc implementa el protocolo UPnP definido para dialogar con dispositivos de puerta de enlace a Internet (IGD). También tiene la capacidad de utilizar datos recopilados por minissdpd(1) sobre dispositivos UPnP en la red para omitir el largo proceso de descubrimiento de dispositivos UPnP.

Primero, se debe usar upnpDiscover(3) para descubrir los IGD UPnP presentes en la red. Luego UPNP_GetValidIGD(3) para seleccionar el correcto. Alternativamente, UPNP_GetIGDFromUrl(3) podría usarse para omitir el proceso de descubrimiento si se conoce la URL de descripción raíz del dispositivo a utilizar. Luego, todas las funciones UPNP_* se pueden usar, como UPNP_GetConnectionTypeInfo(3), UPNP_AddPortMapping(3), etc...

ARCHIVOS DE CABECERA

miniupnpc.h
Este es el archivo de cabecera principal para la API de la biblioteca miniupnpc. Contiene todas las funciones y estructuras relacionadas con el descubrimiento de dispositivos.
upnpcommands.h
Este archivo de cabecera contiene los métodos UPnP IGD que son accesibles a través de la API de miniupnpc. El nombre de las funciones C coincide con los nombres de los métodos UPnP. Es decir: GetGenericPortMappingEntry es UPNP_GetGenericPortMappingEntry.

FUNCIONES DE API

struct UPNPDev * upnpDiscover(int delay, const char * multicastif, const char * minissdpdsock, int localport, int ipv6, int * error);
ejecuta el proceso de descubrimiento. `delay` (en milisegundos) es el tiempo máximo para esperar cualquier respuesta del dispositivo. Si está disponible, la lista de dispositivos se obtendrá de MiniSSDPd. Se usará la ruta predeterminada para el socket de minissdpd si `minissdpdsock` es NULL. Si `multicastif` no es NULL, se usará en lugar de la interfaz de multidifusión predeterminada para enviar paquetes de descubrimiento SSDP. Si `localport` se establece en UPNP_LOCAL_PORT_SAME(1), los paquetes SSDP se enviarán desde el puerto de origen 1900 (igual que el puerto de destino), si se establece en UPNP_LOCAL_PORT_ANY(0), el sistema asignará un puerto de origen, cualquier otro valor se intentará como puerto de origen. Si `ipv6` no es 0, se usará IPv6 en lugar de IPv4 para el proceso de descubrimiento.
void freeUPNPDevlist(struct UPNPDev * devlist);
libera la lista devuelta por upnpDiscover().
int UPNP_GetValidIGD(struct UPNPDev * devlist, struct UPNPUrls * urls, struct IGDdatas * data, char * lanaddr, int lanaddrlen, char * wanaddr, int wanaddrlen);
examina la lista de dispositivos devuelta por upnpDiscover(), encuentra un dispositivo de puerta de enlace a Internet UPnP activo y rellena las estructuras pasadas como argumentos con datos utilizados para la invocación de métodos UPnP.
int UPNP_GetIGDFromUrl(const char * rootdescurl, struct UPNPUrls * urls, struct IGDdatas * data, char * lanaddr, int lanaddrlen);
permite omitir la llamada a upnpDiscover() si se conoce la URL de descripción raíz XML del IGD UPnP. Rellena las estructuras pasadas como argumentos con datos utilizados para la invocación de métodos UPnP.
void GetUPNPUrls(struct UPNPUrls *, struct IGDdatas *, const char *);
void FreeUPNPUrls(struct UPNPUrls *);
