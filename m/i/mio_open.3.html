NOMBRE

mio_open, mio_close, mio_read, mio_write, mio_nfds, mio_pollfd, mio_revents, mio_eof — interfaz sndio a flujos MIDI

SINOPSIS

#include <sndio.h>

struct mio_hdl *
mio_open(const char *name, unsigned int mode, int nbio_flag);

void
mio_close(struct mio_hdl *hdl);

size_t
mio_read(struct mio_hdl *hdl, void *addr, size_t nbytes);

size_t
mio_write(struct mio_hdl *hdl, const void *addr, size_t nbytes);

int
mio_nfds(struct mio_hdl *hdl);

int
mio_pollfd(struct mio_hdl *hdl, struct pollfd *pfd, int events);

int
mio_revents(struct mio_hdl *hdl, struct pollfd *pfd);

int
mio_eof(struct mio_hdl *hdl);

DESCRIPCIÓN

La biblioteca sndio permite a los procesos usuarios acceder al hardware midi(4) y a las cajas MIDI thru y puertos de control sndiod(8) de forma uniforme.

Apertura y cierre de un flujo MIDI

Primero, la aplicación debe llamar a la función mio_open() para obtener un manejador que represente el flujo recién creado; más tarde se pasará como argumento hdl a la mayoría de las otras funciones. El parámetro name proporciona la cadena de dispositivo discutida en sndio(7). Si el programa está utilizando un solo dispositivo y no proporciona ningún selector de dispositivo, debe establecerse en MIO_PORTANY para permitir que el usuario lo seleccione utilizando la variable de entorno MIDIDEVICE.

El parámetro mode proporciona la dirección del flujo. Los siguientes son compatibles:

MIO_OUT
El flujo es solo de salida; los datos escritos en el flujo se enviarán al hardware u otros programas.
MIO_IN
El flujo es solo de entrada; los datos recibidos del hardware u otros programas deben leerse del flujo.
MIO_IN | MIO_OUT
El flujo envía y recibe datos. Este modo debe usarse en lugar de llamar a mio_open() dos veces.

Si el argumento nbio_flag es verdadero (es decir, distinto de cero), entonces las funciones mio_read() y mio_write() (ver más abajo) no serán bloqueantes.

La función mio_close() cierra el flujo y libera todos los recursos asignados asociados con el manejador de libsndio.

Envío y recepción de datos

Cuando se selecciona el modo de entrada, se debe llamar a la función mio_read() para recuperar los datos recibidos; debe llamarse con suficiente frecuencia para garantizar que los búferes internos no se desborden. Almacenará como máximo nbytes bytes en la ubicación addr. A menos que se establezca la bandera nbio_flag, se bloqueará hasta que los datos estén disponibles y solo devolverá cero en caso de error.

Cuando se selecciona el modo de salida, la función mio_write() puede ser llamada para proporcionar datos para transmitir. A menos que se establezca nbio_flag, mio_write() se bloqueará hasta que se escriba la cantidad de datos solicitada.

Operación en modo no bloqueante

Si nbio_flag está establecido en mio_open(), entonces las funciones mio_read() y mio_write() nunca se bloquearán; si no hay datos disponibles, devolverán cero inmediatamente.

Para evitar bucles de sondeo activos cuando se usa el modo no bloqueante, se puede usar la llamada al sistema poll(2) para verificar si se pueden leer o escribir datos en el flujo. La función mio_pollfd() prepara la matriz pfd de estructuras pollfd para su uso con poll(2). El tamaño óptimo de la matriz pfd, que el llamador debe preasignar, lo proporciona la función mio_nfds().

poll(2) dormirá hasta que ocurran cualquiera de los events solicitados con mio_pollfd(). Los eventos se representan como una máscara de bits de las constantes POLLIN y POLLOUT. Los eventos que despertaron a poll(2) se pueden obtener con la función mio_revents(). Si POLLIN está establecido, se puede llamar a mio_read() sin bloquear. Si POLLOUT está establecido, se puede llamar a mio_write() sin bloquear. POLLHUP puede establecerse si ocurre un error, incluso si no se solicita con mio_pollfd().

Manejo de errores

Los errores relacionados con el subsistema MIDI (como errores de hardware o conexiones caídas) y los errores de programación (como una llamada a mio_read() en un flujo solo de reproducción) se consideran fatales. Una vez que ocurre un error, todas las funciones que toman un argumento mio_hdl, excepto mio_close() y mio_eof(), dejan de funcionar (es decir, siempre devuelven 0).

VALORES DE RETORNO

La función mio_open() devuelve el manejador recién creado en caso de éxito o NULL en caso de fallo.

La función mio_pollfd() devuelve el número de estructuras pollfd llenadas. La función mio_nfds() devuelve el número de estructuras pollfd que el llamador debe preasignar para asegurarse de que mio_pollfd() nunca se desbordará.

La función mio_revents() devuelve la máscara de bits establecida por poll(2) en la matriz pfd de estructuras pollfd.
