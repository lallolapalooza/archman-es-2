migrate_pages(2) Manual de llamadas al sistema migrate_pages(2)

NOMBRE

migrate_pages - mover todas las páginas de un proceso a otro conjunto de nodos

BIBLIOTECA

Biblioteca de políticas NUMA (Acceso no uniforme a memoria) (libnuma, -lnuma)

SINOPSIS

#include <numaif.h>
long migrate_pages(int pid, unsigned long maxnode,
                   const unsigned long *old_nodes,
                   const unsigned long *new_nodes);

DESCRIPCIÓN

migrate_pages() intenta mover todas las páginas del proceso pid que se encuentran en los nodos de memoria old_nodes a los nodos de memoria en new_nodes. Las páginas que no se encuentren en ninguno de los nodos de old_nodes no se migrarán. En la medida de lo posible, el kernel mantiene la relación de topología relativa dentro de old_nodes durante la migración a new_nodes.

Los argumentos old_nodes y new_nodes son punteros a máscaras de bits de números de nodo, con hasta maxnode bits en cada máscara. Estas máscaras se mantienen como arreglos de enteros sin signo long (en el último entero long, los bits más allá de los especificados por maxnode se ignoran). El argumento maxnode es el número máximo de nodo más uno (esto es lo mismo que en mbind(2), pero diferente de select(2)).

El argumento pid es el ID del proceso cuyas páginas se van a mover. Para mover páginas en otro proceso, el llamador debe tener privilegios (CAP_SYS_NICE) o el ID de usuario real o efectivo del proceso llamante debe coincidir con el ID de usuario real o de conjunto guardado del proceso objetivo. Si pid es 0, entonces migrate_pages() mueve las páginas del proceso llamante.

Las páginas compartidas con otro proceso solo se moverán si el proceso iniciador tiene el privilegio CAP_SYS_NICE.

VALOR DE RETORNO

En caso de éxito, migrate_pages() devuelve el número de páginas que no pudieron ser movidas (es decir, un retorno de cero significa que todas las páginas se movieron con éxito). En caso de error, devuelve -1 y establece errno para indicar el error.

ERRORES

EFAULT
Parte o todo el rango de memoria especificado por old_nodes/new_nodes y maxnode apunta fuera de su espacio de direcciones accesible.
EINVAL
El valor especificado por maxnode excede un límite impuesto por el kernel. O, old_nodes o new_nodes especifica uno o más IDs de nodo que son mayores que el ID de nodo máximo admitido. O, ninguno de los IDs de nodo especificados por new_nodes está en línea y permitido por el contexto actual del cpuset del proceso, o ninguno de los nodos especificados contiene memoria.
EPERM
Privilegio insuficiente (CAP_SYS_NICE) para mover páginas del proceso especificado por pid, o privilegio insuficiente (CAP_SYS_NICE) para acceder a los nodos de destino especificados.
ESRCH
No se encontró ningún proceso que coincida con pid.

ESTÁNDARES

Linux.

HISTORIA

Linux 2.6.16.

NOTAS

Para obtener información sobre el soporte de bibliotecas, consulte numa(7).

Utilice get_mempolicy(2) con la bandera MPOL_F_MEMS_ALLOWED para obtener el conjunto de nodos que son permitidos por el cpuset del proceso llamante. Tenga en cuenta que esta información está sujeta a cambios en cualquier momento por la reconfiguración manual o automática del cpuset.

El uso de migrate_pages() puede dar lugar a páginas cuya ubicación (nodo) viole la política de memoria establecida para las direcciones especificadas (consulte mbind(2)) y/o para el proceso especificado (consulte set_mempolicy(2)). Es decir, la política de memoria no restringe los nodos de destino utilizados por migrate_pages().

El encabezado <numaif.h> no se incluye con glibc, pero requiere la instalación de libnuma-devel o un paquete similar.
