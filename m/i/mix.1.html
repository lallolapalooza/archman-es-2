MIX(1) Manual de comandos generales MIX(1)

NOMBRE

mix — La herramienta de gestión de proyectos de software

SINOPSIS

mix [TAREA] [nombre_proyecto]

elixir [OPCIONES] -S mix [TAREA] [nombre_proyecto]

DESCRIPCIÓN

mix está pensado tanto para organizar código en proyectos como para su mantenimiento. Para este último, la herramienta ofrece algunas características avanzadas como la gestión de dependencias, empaquetado, preparación de documentación, pruebas, etc.

Eche un vistazo a la sección SINOPSIS y a la segunda forma de ejecutar mix que ofrece. El punto es que la herramienta no es otra cosa que el script de Elixir, por lo tanto, puede ser invocada a través de elixir(1) de la misma manera que cualquier otro script. Es útil cuando quieres ejecutar mix con opciones particulares.

DEFINICIONES

Toda la funcionalidad de mix está representada por un conjunto de tareas. Una tarea es un fragmento de código escrito en Elixir y destinado a resolver un problema particular. Al igual que los programas, muchas tareas aceptan parámetros de entrada y/o admiten opciones que modifican ligeramente su comportamiento, pero otras no. Hay dos tipos de tareas: las que están disponibles tras la instalación de este u otro archivo (tareas locales) y las que ofrece mix (tareas integradas). La ejecutar tarea se ejecutará por defecto si no se ha especificado ninguna otra.

A pesar de que la mayor parte de mix son tareas, la página del manual no contiene la información de ayuda relacionada con cada una de ellas porque mix es autoexplicativo. Por lo tanto, utilizando la ayuda tarea, puedes obtener tanto la lista completa de tareas locales/integradas como la información relacionada con una tarea en particular.

Un archivo, en términos de Erlang/OTP, es el archivo ZIP con la extensión .ez que contiene una aplicación OTP precompilada con todas sus dependencias [1].

Una aplicación es una entidad que ayuda a combinar conjuntos de componentes en una sola unidad para simplificar su reutilización en otros sistemas [2].

AMBIENTE

MIX_ARCHIVES
Permite especificar el directorio en el que se instalarán los archivos (ver mix help archive.install). El directorio ~/.mix/archivos se utiliza para este propósito por defecto.
MIX_DEBUG
Cuando está establecido, muestra información de depuración sobre cada tarea antes de ejecutarla.
MIX_ENV
Permite especificar qué entorno se debe utilizar. El entorno dev se utiliza por defecto si no se ha especificado ninguno otro.

A veces tienes que usar un conjunto particular de valores de parámetros de configuración o realizar pasos particulares al compilar o ejecutar un proyecto (o en otros casos). Los entornos de mix permiten agrupar valores de parámetros de configuración y pasos para cambiar entre ellos especificando el entorno necesario a través de MIX_ENV.

MIX_TARGET
Permite especificar qué objetivo se debe utilizar. El objetivo host se utiliza por defecto si no se ha especificado ninguno otro.
MIX_EXS
Permite cambiar la ruta completa al archivo mix.exs (ver sección ARCHIVOS). El caso de uso más obvio es tener más de una copia de mix.exs en un proyecto, pero vale la pena señalar que MIX_EXS solo debe usarse si los entornos de mix (ver arriba) no son suficientes para resolver el problema.
MIX_HOME
ruta al directorio principal de Mix, almacena archivos de configuración y scripts utilizados por Mix
MIX_INSTALL_DIR
Especifica el directorio donde Mix.install/2 mantiene la caché de instalaciones
MIX_INSTALL_FORCE
Ejecuta Mix.install/2 con una caché de instalación vacía
MIX_PATH
Permite expandir la ruta del código. Si la variable de entorno MIX_PATH tiene un valor que consiste en múltiples rutas, deben estar separadas por dos puntos (para sistemas operativos tipo Unix) o por punto y coma (para Windows).

Como se mencionó anteriormente, hay dos tipos de tareas: locales y integradas. Estas tareas siempre son visibles para mix porque los directorios en los que se encuentran forman parte de la ruta del código. Si una tarea no pertenece ni a un tipo ni a otro, MIX_PATH te ayuda a decirle a mix dónde debe buscar la tarea.

MIX_QUIET
Cuando está establecido, no imprime mensajes informativos en la terminal.

ARCHIVOS

mix.exs
Contiene la información más significativa relacionada con el proyecto, como su nombre, versión, lista de dependencias, etc. Por regla general, el archivo se llama mix.exs y se ubica en la parte superior del árbol de fuentes del proyecto, pero puedes cambiar la ruta completa a él usando la variable de entorno MIX_EXS (ver sección AMBIENTE).
mix.lock
Permite fijar las dependencias del proyecto con un rango de versiones apropiado antes de realizar cualquier actualización. Es útil cuando sabes que tu proyecto es incompatible con versiones más nuevas de ciertas dependencias. El archivo se ubica en la parte superior del árbol de fuentes del proyecto, al igual que mix.exs (ver arriba).

NAME
mix - a build automation tool for Elixir
SYNOPSIS
mix [global-option] task [task-option] [argument...]
mix help [task]
DESCRIPTION
Mix is a tool that ships with Elixir, for managing Elixir projects. It provides a way to compile applications, manage dependencies and tasks, run tests, and much more.

Mix has a set of built-in tasks, such as:

mix new PATH
Creates a new Elixir project structure at PATH.
mix deps.get
Fetches dependencies for the current project.
mix compile
Compiles the current project.
mix test
Runs the tests for the current project.
mix run PATH
Runs the specified Elixir script.

Users can also define their own tasks and add them to the project.

DEFINITIONS
task:: The name of the task to be executed. For example, compile, test, deps.get.
argument:: Arguments passed to the task. Their meaning depends on the specific task.
global-option:: Options that apply to Mix itself, not to a specific task. For example, --help.
task-option:: Options specific to the task being executed. For example, --cover for the test task.
ENVIRONMENT
MIX_ENV:: Sets the Mix environment (e.g., dev, test, prod). Defaults to dev.
MIX_INSTALLATION_DIR:: Sets the directory where Mix installations are stored.
MIX_ARCHIVES_DIR:: Sets the directory where Mix archives are stored.
FILES
mix.exs:: The project definition file, containing dependencies, compilation options, and custom tasks.
.mix/:: Directory for Mix-specific project configurations and caches.
