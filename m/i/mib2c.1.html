NOMBRE

mib2c -- genera código plantilla para extender el agente

SINOPSIS

mib2c [-h] -c ARCHIVO_CONFIGURACION [-I RUTA] [-f NOMBRE_SALIDA] [-i][-s][-q][-S VARIABLE=VALOR] NODO_MIB

DESCRIPCIÓN

La herramienta mib2c está diseñada para tomar una porción del árbol MIB (tal como se define en un archivo MIB) y generar el código C plantilla necesario para implementar los objetos de gestión relevantes dentro de él.

Para implementar un nuevo módulo MIB, se necesitan tres archivos:

- Archivo de definición MIB
- Archivo de cabecera C
- Archivo de implementación C.

La herramienta mib2c utiliza el archivo de definición MIB para producir los dos archivos de código C. Por lo tanto, mib2c genera una plantilla que usted puede editar para añadir la lógica necesaria para obtener información del sistema operativo o de la aplicación para completar el módulo.

NODO_MIB es el nodo MIB de nivel superior para el que desea generar código. Debe proporcionar a mib2c un nodo MIB (por ejemplo, ifTable) en la línea de comandos, no un archivo MIB. Este es el error más común.

La herramienta mib2c acepta MIBs SMIv1 y SMIv2.

mib2c necesita poder encontrar y cargar un archivo MIB para generar código C para la MIB. Para permitir que mib2c encuentre el archivo MIB, establezca la variable de entorno MIBS para que incluya el archivo MIB que está utilizando. Un ejemplo de cómo establecer esta variable de entorno es:


MIBS=+NET-SNMP-TUTORIAL-MIB


o


MIBS=ALL

El primer ejemplo asegura que mib2c encuentre el MIB NET-SNMP-TUTORIAL-MIB, además de los módulos MIB predeterminados. La lista predeterminada de módulos MIB se establece cuando el conjunto se configura y compila por primera vez y corresponde básicamente a la lista de módulos que el agente soporta. El segundo ejemplo asegura que mib2c encuentre todas las MIBs en la ubicación de búsqueda de archivos MIB. La ubicación de búsqueda predeterminada para archivos MIB es /usr/share/snmp/mibs. Esta ubicación de búsqueda puede modificarse mediante la variable de entorno MIBDIRS.

Tanto los archivos MIB a cargar como la ubicación de búsqueda de archivos MIB también se pueden configurar en el archivo snmp.conf. Consulte snmp.conf(5) para obtener más información.

Los archivos *.c y *.h generados se crearán en el directorio de trabajo actual.

OPCIONES

-h
Muestra un mensaje de ayuda.
-c ARCHIVO_CONFIGURACION
Utiliza ARCHIVO_CONFIGURACION al generar código. Estos archivos se buscarán primero en el directorio actual y luego en el directorio /usr/share (que es donde se encuentran los archivos de configuración mib2c predeterminados). Ejecutar mib2c sin la opción -c ARCHIVO_CONFIGURACION mostrará una descripción de los valores válidos para ARCHIVO_CONFIGURACION, es decir, los archivos de configuración disponibles, incluidos los nuevos que usted pueda crear.
Por ejemplo,
% mib2c ifTable
mostrará una descripción de los valores actualmente disponibles para ARCHIVO_CONFIGURACION.
Los siguientes valores son compatibles con ARCHIVO_CONFIGURACION:
mib2c.mfd.conf
mib2c.scalar.conf
mib2c.int_watch.conf
mib2c.iterate.conf
mib2c.create-dataset.conf
mib2c.array-user.conf
mib2c.column_defines.conf
mib2c.column_enums.conf
GENERANDO CÓDIGO PARA OBJETOS ESCALARES:
Si está escribiendo código para algunos escalares, ejecute:

mib2c -c mib2c.scalar.conf NODO_MIB

Si desea "enlazar" mágicamente variables enteras a escalares enteros, use:

mib2c -c mib2c.int_watch.conf NODO_MIB

GENERANDO CÓDIGO PARA TABLAS:

El archivo de configuración recomendado para tablas es el archivo de configuración MIBs for Dummies, o MFD. Oculta tantos detalles de SNMP como sea posible, generando funciones pequeñas y fáciles de entender. También es el archivo de configuración más flexible y bien documentado. Vea los archivos agent/mibgroup/if-mib/ifTable/ifTable*.c como ejemplo:


mib2c -c mib2c.mfd.conf NODO_MIB

Si los datos de su tabla se encuentran en otro lugar (por ejemplo, están en el kernel y no en la memoria del agente) y necesita "iterar" sobre ellos para encontrar los datos correctos para la fila SNMP que se está accediendo. Vea el archivo agent/mibgroup/mibII/vacm_context.c como ejemplo:

mib2c -c mib2c.iterate.conf NODO_MIB

Si los datos de su tabla se mantienen en el agente (es decir, no se encuentran en una fuente externa) y están puramente basados en datos (es decir, no necesita realizar ningún trabajo cuando ocurre un establecimiento). Vea el archivo agent/mibgroup/examples/data_set.c como ejemplo de tal tabla:

mib2c -c mib2c.create-dataset.conf NODO_MIB

Si los datos de su tabla se mantienen en el agente (es decir, no se encuentran en una fuente externa), y puede mantener sus datos ordenados por el índice de la tabla, pero necesita realizar trabajo cuando ocurre un establecimiento:

mib2c -c mib2c.array-user.conf NODO_MIB

GENERANDO DEFINICIONES DE ARCHIVO DE CABECERA

Para generar solo una cabecera con una definición para cada número de columna en su tabla:

mib2c -c mib2c.column_defines.conf NODO_MIB

Para generar solo una cabecera con una definición para cada enum para cualquier columna que contenga enums:

mib2c -c mib2c.column_enums.conf NODO_MIB

GENERANDO CÓDIGO PARA LA LÍNEA DE CÓDIGO 4.X (LA API MÁS ANTIGUA)

mib2c -c mib2c.old-api.conf NODO_MIB

-IRUTA
Busca archivos de configuración en RUTA. Se pueden especificar múltiples rutas utilizando múltiples opciones -I o utilizando una con una lista de rutas separadas por comas.
-f NOMBRE_SALIDA
Coloca el código de salida en NOMBRE_SALIDA.c y NOMBRE_SALIDA.h. Normalmente, mib2c colocará el código de salida en archivos que corresponden a los nombres de tabla para los que está generando código, que probablemente es lo que usted quiere de todos modos.
-i
No ejecuta indent en el código resultante.
-s
No busca MIBNODE.sed y no ejecuta sed en el código resultante. Esto es útil para acortar nombres de variables MIB largas en el código.
-q
Ejecuta en modo "silencioso", lo que minimiza los mensajes de estado que mib2c genera.
-SVARIABLE=VALOR
Preestablece una VARIABLE, en el archivo mib2c.*.conf, al VALOR. Ninguno de los archivos de configuración mib2c.*.conf existentes utiliza actualmente esta característica, por lo que esta opción debe considerarse disponible solo para uso futuro.

EJEMPLOS

Lo siguiente genera código plantilla C para los archivos de cabecera e implementación para implementar UCD-DEMO-MIB::ucdDemoPublic.

% mib2c -c mib2c.scalar.conf ucdDemoPublic
escribiendo en ucdDemoPublic.h
escribiendo en ucdDemoPublic.c
ejecutando indent en ucdDemoPublic.h
ejecutando indent en ucdDemoPublic.c

Los archivos resultantes ucdDemoPublic.c y ucdDemoPublic.h se generan en el directorio de trabajo actual.

Lo siguiente genera código plantilla C para los archivos de cabecera e implementación para el módulo de implementación de TCP-MIB::tcpConnTable.

% mib2c -c mib2c.iterate.conf tcpConnTable
escribiendo en tcpConnTable.h
escribiendo en tcpConnTable.c
ejecutando indent en tcpConnTable.h
ejecutando indent en tcpConnTable.c

Los archivos resultantes tcpConnTable.c y tcpConnTable.h se generan en el directorio de trabajo actual.

VER TAMBIÉN

NOMBRE

mib2c - The Net-SNMP configuration tool

SINOPIS

mib2c [-h | --help] [-V | --version] [-c CONFIG] [-I DIR] [--ignore-case] [--no-ignore-case] [--prefers-source] [--override-source] [-o OUTPUT] [-d] [-D] [-v] MIB_MODULE

DESCRIPCIÓN

mib2c is a Perl script that assists in the creation of SNMP-related code. It uses a MIB file and a configuration file to generate code templates for various tasks, such as creating new management information bases (MIBs) or implementing agents.

OPCIONES

-h, --help
Show a help message and exit.
-V, --version
Show program version and exit.
-c CONFIG
Specify a configuration file. The default configuration file is based on the MIB module name (e.g., for NET-SNMP-MIB, it would look for net-snmp-mib.conf).
-I DIR
Add a directory to the search path for MIB files.
--ignore-case
Ignore case when comparing identifiers in the MIB.
--no-ignore-case
Do not ignore case when comparing identifiers in the MIB (default).
--prefers-source
Prefer source code over header files when parsing MIBs.
--override-source
Override source code preference and always use header files.
-o OUTPUT
Specify an output file for the generated code. If not specified, the output will be printed to standard output.
-d
Enable debug output.
-D
Enable very verbose debug output.
-v
Enable verbose output.

EJEMPLOS

Generate a basic agent implementation for a custom MIB module:

mib2c -c my-mib-config.conf MY-CUSTOM-MIB

Generate a MIB view implementation:

mib2c -c mibView.conf NET-SNMP-AGENT-MIB::netSnmpAgentOid
