MIB2C.CONF(5) Net-SNMP MIB2C.CONF(5)

NOMBRE

mib2c.conf - Cómo escribir archivos mib2c.conf para hacer CUALQUIER COSA basado en la entrada MIB.

SINOPSIS

% cat > mib2c.test.conf << EOF @foreach $t table@
Empezando tabla $t
@foreach $c column@
echo $t tiene columna $c con sintaxis $c.syntax
@end@

@end@ EOF

% mib2c -c mib2c.test.conf internet

DESCRIPCIÓN

El lenguaje de script mib2c.conf es un lenguaje específico de MIB diseñado para procesar fácilmente nodos MIB de la manera que usted desee. mib2c es un nombre erróneo (por razones históricas), ya que puede producir cualquier cosa (no solo código C). Busque en el directorio "local" de Net-SNMP una gran cantidad de archivos de ejemplo mib2c.*.conf y contemple el poder ante usted.

COMANDOS

Todos los comandos dentro de los archivos mib2c.conf están encerrados entre signos @. Cualquier cosa con un signo @ al principio y al final de la línea generalmente se supone que es un comando específico de mib2c. Estos se detallan aquí:

@open ARCHIVO@
escribe la salida generada en ARCHIVO. Tenga en cuenta que para las especificaciones de archivo, abrir '-' imprimirá en stdout.
@append ARCHIVO@
añade el ARCHIVO dado
@close ARCHIVO@
cierra el ARCHIVO dado
@push@
guarda las salidas actuales, luego borra las salidas. Úselo con @open@ y @pop@ para escribir en un nuevo archivo sin interferir con las salidas actuales.
@pop@
saca el nivel de la pila de proceso(). Úselo después de un @push@ para volver al conjunto anterior de archivos abiertos.
@foreach $VAR escalar@
repite la iteración sobre el código hasta @end@, estableciendo $VAR a todos los escalares conocidos
@foreach $VAR tabla@
repite la iteración sobre el código hasta @end@, estableciendo $VAR a todas las tablas conocidas
@foreach $VAR columna@
repite la iteración sobre el código hasta @end@, estableciendo $VAR a todas las columnas conocidas dentro de una tabla dada. Obviamente, esto debe llamarse dentro de una cláusula foreach-table.
@foreach $VAR noindex@
repite la iteración sobre el código hasta @end@, estableciendo $VAR a todas las columnas no indexadas conocidas dentro de una tabla dada. Obviamente, esto debe llamarse dentro de una cláusula foreach-table.
@foreach $VAR indexinterno@
repite la iteración sobre el código hasta @end@, estableciendo $VAR a todas las columnas de índice internas conocidas dentro de una tabla dada. Obviamente, esto debe llamarse dentro de una cláusula foreach-table.
@foreach $VAR indexexterno@
repite la iteración sobre el código hasta @end@, estableciendo $VAR a todas las columnas de índice externas conocidas dentro de una tabla dada. Obviamente, esto debe llamarse dentro de una cláusula foreach-table.
@foreach $VAR indice@
repite la iteración sobre el código hasta @end@, estableciendo $VAR a todos los índices conocidos dentro de una tabla dada. Obviamente, esto debe llamarse dentro de una cláusula foreach-table.
@foreach $VAR notificaciones@
repite la iteración sobre el código hasta @end@, estableciendo $VAR a todas las notificaciones conocidas
@foreach $VAR varbinds@
repite la iteración sobre el código hasta @end@, estableciendo $VAR a todos los varbinds conocidos. Obviamente, esto debe llamarse dentro de una cláusula foreach-notifications.
@foreach $ETIQUETA, $VALOR enum@
repite la iteración sobre el código hasta @end@, estableciendo $ETIQUETA y $VALOR a la etiqueta y los valores de la lista enum.
@foreach $INICIO_RANGO, $FIN_RANGO nodo RANGO@
repite la iteración sobre el código hasta @end@, estableciendo $INICIO_RANGO y $FIN_RANGO al conjunto de rango legal aceptado para un nodo MIB dado.
@foreach $var cosa a b c d@
repite la iteración sobre los valores a, b, c, d según lo asignado genéricamente (es decir, los valores se toman directamente de la lista sin expansión MIB, etc.).
@while expresion@
repite la iteración sobre el código hasta que la expresión sea falsa
@eval $VAR = expresion@
evalúa la expresión y asigna los resultados a $VAR. Esto no es un eval de perl completo, sino una especie de eval "pseudocódigo" útil para expresiones simples mientras se mantiene el mismo espacio de nombres de variables. Consulte a continuación para una exportación completa a perl.
@perleval COSA@
evalúa COSA directamente en perl. Tenga en cuenta que todas las variables mib2c interpretadas dentro de los archivos .conf están en $vars{NOMBRE} y que se imprimirá una advertencia si COSA no devuelve 0. (agregar un 'return 0;' al final de COSA es una solución alternativa).
@startperl@
@endperl@
trata todo lo que está entre estas etiquetas como código perl y lo evalúa.
@next@
reinicia foreach; solo debe usarse dentro de una condición. salta de la condición actual, luego continúa saltando hasta el final para la cláusula foreach actual.
@if expresion@
evalúa la expresión y, si la expresión es verdadera, procesa la parte contenida hasta que se alcance el @end@ apropiado. Si la expresión es falsa, se evaluará la siguiente expresión @elsif expresion@ (si existe), hasta que una expresión sea verdadera. Si no existe tal expresión y se encuentra una cláusula @else@, se evaluará.
@ifconf archivo@
Si el archivo especificado se puede encontrar en la ruta de búsqueda de archivos de configuración, y si se encuentra, procesa la parte contenida hasta que se encuentre un @end@ apropiado. Al igual que con un @if expresion@ regular, se pueden usar @elsif expresion@ y @else@.
@ifdir dir@
Si el directorio especificado existe, procesa la parte contenida hasta que se encuentre un @end@ apropiado. Al igual que con un @if expresion@ regular, se pueden usar @elsif expresion@ y @else@.
@define NOMBRE@
@enddefine@
Memoriza "cosas" entre las etiquetas define y enddefine para llamarlas más tarde como NOMBRE mediante @calldefine NOMBRE@.
@calldefine NOMBRE@
Ejecuta cosas memorizadas previamente como NOMBRE.
@printf "expresion" cosa1, cosa2, ...@
Como todos los demás printf que conoces y amas.
@run ARCHIVO@
Fuente los contenidos de ARCHIVO como un archivo mib2c, pero no afecta los archivos actualmente abiertos.
@include ARCHIVO@
Fuente los contenidos de ARCHIVO como un archivo mib2c y añade su salida a la salida actual.
@prompt $var PREGUNTA@
Presenta al usuario la PREGUNTA, espera una respuesta y la pone en $var
@print COSA@
Imprime cosas directamente en la pantalla del usuario (es decir, no a donde va la salida normal de mib2c)
@quit@
Salir (silenciosamente)
@exit@
¡Salir!

VARIABLES

Las variables en el lenguaje mib2c se parecen mucho a las variables de perl, en el sentido de que comienzan con un "$". Se pueden usar para cualquier cosa que desee, pero lo más habitual es que contengan nombres de nodos MIB procesados por cláusulas @foreach ...@.

También tienen propiedades especiales cuando son un nodo MIB, de modo que añadir sufijos especiales a ellos les permitirá ser interpretados de alguna manera. La forma más fácil de entender esto es a través de un ejemplo. Si la variable 'x' contuviera la palabra 'ifType', entonces sucederían algunas cosas mágicas. En la salida de mib2c, cada vez que se ve $x, se reemplaza por "ifType". Se pueden usar sufijos adicionales para obtener otros aspectos de ese nodo MIB. Si se ve $x.objectID, se reemplazará por el OID de ifType: ".1.3.6.1.2.1.2.2.1.3". Otros sufijos que pueden aparecer después de un punto se enumeran a continuación.

Una última cosa: puede usar cosas como $vartext que terminan inmediatamente en algún otro texto; puede usar {} para obtener una expansión adecuada de solo una parte de la entrada mib2c. Es decir, $xtext producirá "$xtext", pero ${x}text producirá "ifTypetext" en su lugar.

mib2c.conf(5) — Arch Linux man pages

NAME

mib2c.conf

configuration file for mib2c

SYNOPSIS

mib2c

mib2c.conf

DESCRIPTION

The mib2c.conf file is used by the mib2c script to control the generation of SNMP application code from MIB definitions.

The configuration file is written in a simple key=value format, with comments introduced by a hash character (#).

The configuration file uses a hierarchy of contexts, defined by the #%DEFINITIONS and #%END keywords. The top-level context is implicit.

Within a context, configuration options can be set. Some options apply to the entire configuration file, while others are specific to a particular MIB object or group of objects.

The configuration file supports the following directives:

#%DEFINITIONS
Starts a new context. The context name follows the keyword. Context names can be hierarchical, separated by slashes.
#%END
Ends the current context.
var <variable_name> = <value>
Sets a configuration variable. The variable name can be qualified with context names.

COMMANDS

The following commands can be used to control the behavior of mib2c:

mibs
Specifies the MIB files to be processed.
output_dir
Specifies the output directory for generated files.
source_dir
Specifies the source directory for MIB files.
print_success
If set to 1, mib2c will print a success message upon completion.

VARIABLES

The following variables can be used to control the generation of code for specific MIB objects:

$var.access
node's access type
$var.active
1 if var is active, 0 if not

$var.enums

$var.hasdefval
returns 1 if var has a DEFVAL clause
$var.hashint
returns 1 if var has a HINT clause
$var.hint
node's HINT
$var.isdependent
1 if var is a dependent object, 0 if not
$var.isoptimized
1 if var is optimized, 0 if not
$var.isreadonly
1 if var is read-only, 0 if not
$var.isreadwrite
1 if var is read-write, 0 if not
$var.iswritable
1 if var is writable, 0 if not
$var.lastchange
1 if an object is a LastChange object, 0 if not
$var.nodetype
node's type
$var.oid
node's OID
$var.ranges
returns 1 if var has a value range defined
$var.reference
node's reference
$var.rowstatus
1 if an object is a RowStatus object, 0 if not 'settable', 'creatable', 'lastchange', 'storagetype' and 'rowstatus' can also be used with table variables to indicate whether it contains writable, creatable, LastChange, StorageType or RowStatus column objects

$var.sparse
