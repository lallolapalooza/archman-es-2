MIFF(4) Manual de Controladores de Dispositivos MIFF(4)

NOMBRE

MIFF - Formato de Archivo de Imagen Magick

SINOPSIS

#include <image.h>

DESCRIPCIÓN

El Formato de Archivo de Imagen Magick (MIFF) es un formato independiente de la plataforma para almacenar imágenes de mapa de bits. MIFF es parte del conjunto de utilidades de manipulación de imágenes de ImageMagick para el sistema X Window. ImageMagick es capaz de convertir muchos formatos de archivo de imagen diferentes a y desde MIFF (por ejemplo, JPEG, XPM, TIFF, etc.).

Un archivo de imagen MIFF consta de dos secciones. La primera sección es una cabecera compuesta por claves que describen la imagen en formato de texto. La siguiente sección son los datos binarios de la imagen. La cabecera está separada de los datos de la imagen por un carácter : seguido inmediatamente por un salto de línea.

La cabecera MIFF está compuesta enteramente por caracteres LATIN-1. Los campos de la cabecera son combinaciones de clave y valor en formato clave=valor, con cada clave y valor separados por un signo igual (=). Cada combinación clave=valor está delimitada por al menos un carácter de control o espacio en blanco. Los comentarios pueden aparecer en la sección de cabecera y siempre están delimitados por llaves. La cabecera MIFF siempre termina con un carácter de dos puntos (:) seguido de un carácter ctrl-Z. También es común preceder los dos puntos con un salto de página y un carácter de salto de línea. El salto de página evita la visualización de datos binarios cuando se utiliza more(1) en Unix, donde el ctrl-Z tiene el mismo efecto con el comando type en la línea de comandos de Win32.

La siguiente es una lista de combinaciones clave=valor que se pueden encontrar en un archivo MIFF:

color-de-fondo=color
color-de-borde=color color-de-tapiz=color estas claves opcionales reflejan los colores de fondo, borde y tapiz de la imagen respectivamente. Un color puede ser un nombre (por ejemplo, blanco) o un valor hexadecimal (por ejemplo, #ccc).
clase=ClaseDirecta
clase=ClasePseudo el tipo de datos de imagen binaria almacenados en el archivo MIFF. Si esta clave no está presente, se asumen datos de imagen ClaseDirecta.
colores=valor
el número de colores en una imagen ClaseDirecta. Para una imagen de ClasePseudo, esta clave especifica el tamaño del mapa de colores. Si esta clave no está presente en la cabecera y la imagen es ClasePseudo, se utiliza un mapa de colores de escala de grises lineal de 256 colores con los datos de la imagen. El número máximo de entradas del mapa de colores es 65535. espacio-de-color=CMYK el espacio de color de los datos de píxeles. El valor predeterminado es RGB.
columnas=valor
el ancho de la imagen en píxeles. Esta es una clave obligatoria y no tiene valor predeterminado.
compresion=BZip
compresion=Fax compresion=JPEG compresion=LZW compresion=RLE compresion=Zip el tipo de algoritmo utilizado para comprimir los datos de la imagen. Si esta clave no está presente, se asume que los datos de la imagen no están comprimidos.
retraso <1/100 de segundo>
el retardo entre fotogramas en una secuencia de imágenes. El retardo máximo es 65535.
profundidad=8
profundidad=16 la profundidad de un solo valor de color que representa valores de 0 a 255 (profundidad 8) o 65535 (profundidad 16). Si esta clave está ausente, se asume una profundidad de 8.
disponer valor
método de disposición GIF.

Estos son los métodos válidos:

     0  No se especifica disposición.
     1  No disponer entre fotogramas.
     2  Sobrescribir fotograma con el color de fondo de la cabecera.
     3  Sobrescribir con el fotograma anterior.
gamma=valor
la gamma de la imagen. Si no se especifica, se asume una gamma de 1.0 (respuesta de brillo lineal),
id=ImageMagick
identifica el archivo como un archivo de imagen en formato MIFF. Esta clave es obligatoria y no tiene valor predeterminado. Aunque esta clave puede aparecer en cualquier lugar de la cabecera, debe comenzar como la primera clave de la cabecera en la columna 1. Esto permitirá que programas como file(1) identifiquen fácilmente el archivo como MIFF.
iteraciones valor
el número de veces que una secuencia de imágenes se repite antes de detenerse.
etiqueta={valor}
define un título corto o un pie de foto para la imagen. Si aparece algún espacio en blanco en la etiqueta, debe estar entre llaves.
tapiz=Verdadero
tapiz=Falso especifica si una imagen de ClaseDirecta tiene datos de tapiz. Los datos de tapiz son generalmente útiles para la composición de imágenes. Esta clave no tiene significado para imágenes de color pseudo.
mosaico=<ancho>x<altura>{+-}<desplazamiento-x>{+-}<desplazamiento-y>
tamaño y ubicación de las teselas individuales de una imagen compuesta. Consulte X(1) para obtener detalles sobre la especificación de la geometría.

Utilice esta clave cuando la imagen sea una composición de varias teselas diferentes. Una tesela consta de una imagen y opcionalmente un borde y una etiqueta. <ancho> es el tamaño en píxeles de cada tesela individual en la dirección horizontal y <altura> es el tamaño en la dirección vertical. Cada tesela debe tener un número igual de píxeles en ancho y un número igual en alto. Sin embargo, el ancho puede diferir de la altura. <desplazamiento-x> es el desplazamiento en número de píxeles desde el borde vertical de la imagen compuesta donde comienza la primera tesela de una fila y <desplazamiento-y> es el desplazamiento desde el borde horizontal donde comienza la primera tesela de una columna.

Si se especifica esta clave, un directorio de nombres de teselas debe seguir la cabecera de la imagen. El formato del directorio se explica a continuación.

pagina=valor
tamaño y ubicación preferidos de un lienzo de imagen.
perfil-icc=valor
el número de bytes en el perfil de color del Consorcio Internacional del Color. El perfil se define según la especificación del perfil ICC ubicada en ftp://sgigate.sgi.com/pub/icc/icc34.ps.
espacio-de-color=RGB
primario-rojo=x,y
primario-verde=x,y primario-azul=x,y punto-blanco=x,y esta clave opcional refleja los primarios de cromaticidad y el punto blanco.
intencion-renderizado=saturacion
intencion-renderizado=perceptual intencion-renderizado=absoluto intencion-renderizado=relativo La intención de renderizado es la propiedad CSS-1 que ha sido definida por el Consorcio Internacional del Color (http://www.color.org).
resolucion=<resolucion-x>x<resolucion-y>
resolución vertical y horizontal de la imagen. Consulte unidades para ver las unidades de resolución específicas (por ejemplo, píxeles por pulgada).
filas=valor
la altura de la imagen en píxeles. Esta es una clave obligatoria y no tiene valor predeterminado.
escena=valor
el número de secuencia para este archivo de imagen MIFF. Esta clave opcional se utiliza cuando un archivo de imagen MIFF es uno de una secuencia de archivos utilizados en una animación.
firma=valor
esta clave opcional contiene una cadena que identifica de forma única el contenido de píxeles de la imagen. Se recomienda el algoritmo de resumen de mensajes SHA-256 de NIST.
unidades=pixeles-por-pulgada
unidades=pixeles-por-centimetro unidades de resolución de imagen.

English

NAME

miff - Magick Image File Format

SYNOPSIS

miff: image-filename

DESCRIPTION

The MIFF format is a flexible raster image format developed by the ImageMagick group. It is used primarily as an intermediate image format for ImageMagick. It supports a wide range of features including direct pixel access, colormaps, transparency, and compression.

A MIFF file begins with a header, followed by optional ancillary data (like a montage directory or color profile), and finally the image data.

The header is a series of key=value pairs, where the keys are symbolic identifiers and the values are their corresponding data. The header is terminated by a colon (:).

Here is an example header:

<MIFF-HEADER>
    id=ImageMagick
    class=PseudoClass
    colors=256
    compression=RunlengthEncoded
    columns=1280
    rows=1024
    signature=d79e1c308aa5bbcdeea8ed63df412da9
    copyright={Copyright (c) 2001 ImageMagick Studio}
    <FF>
    :
</MIFF-HEADER>

Note that key=value combinations may be separated by newlines or spaces and may occur in any order within the header. Comments (within braces) may appear anywhere before the colon.

If you specify the montage key in the header, follow the header with a directory of image tiles. This directory consists of a name for each tile of the composite image separated by a newline character. The list is terminated with a NULL character.

If you specify the color-profile key in the header, follow the header (or montage directory if the montage key is in the header) with the binary color profile.

Next comes the binary image data itself. How the image data is formatted depends upon the class of the image as specified (or not specified) by the value of the class key in the header.

DirectClass images (class=DirectClass) are continuous-tone, images stored as RGB (red, green, blue), RGBA (red, green, blue, alpha), or CMYK (cyan, yellow, magenta, black) intensity values as defined by the colorspace key. Each intensity value is one byte in length for images of depth 8 (0..255), whereas, images of depth 16 (0..65535) require two bytes in most significant byte first order.

PseudoClass images (class=PseudoClass) are colormapped RGB images. The colormap is stored as a series of red, green, and blue pixel values, each value being a byte in size. If the image depth is 16, each colormap entry consumes two bytes with the most significant byte being first. The number of colormap entries is defined by the colors key. The colormap data occurs immediately following the header (or image directory if the montage key is in the header). PseudoClass image data is an array of index values into the color map. If there are 256 or fewer colors in the image, each byte of image data contains an index value. If the image contains more than 256 colors or the image depth is 16, the index value is stored as two contiguous bytes with the most significant byte being first. If matte is true, each colormap index is followed by a 1 or 2-byte alpha value.

The image data in a MIFF file may be uncompressed, runlength encoded, Zip compressed, or BZip compressed. The compression key in the header defines how the image data is compressed. Uncompressed pixels are just stored one scanline at a time in row order. Runlength encoded compression counts runs of identical adjacent pixels and stores the pixels followed by a length byte (the number of identical pixels minus 1). Zip and BZip compression compresses each row of an image and precedes the compressed row with the length of compressed pixel bytes as a word in most significant byte first order.

MIFF files may contain more than one image. Simply concatenate each individual image (composed of a header and image data) into one file.
