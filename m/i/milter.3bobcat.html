NOMBRE

FBB::Milter - Interfaz a las facilidades de filtro de correo de sendmail

SINOPSIS

#include <bobcat/milter>
Opción de enlace: -lmilter -lbobcat

DESCRIPCIÓN

Milter define una clase base abstracta que interactúa con las facilidades de filtro de correo (milter) de sendmail. Define una interfaz C++, basada en la suposición de que un solo programa de filtro de correo no implementa múltiples filtros de correo. La API tradicional de Milter basada en C utiliza un puntero (SMFICTX) que representa una conexión de correo y un puntero a datos "privados" específicos de la conexión, requiriendo que el constructor de Milter realice bastantes tareas administrativas. Si bien es aceptable en un entorno C, estas tareas administrativas distraen de la tarea principal: la funcionalidad de filtrado de correo del Milter. La clase FBB::Milter oculta estas tareas administrativas al programador, quien luego puede concentrarse en filtrar el correo. Los principales beneficios de Milter son, por lo tanto:

o
La administración básica es realizada por la clase Milter
o
La interfaz de la clase es más similar a C++ que la interfaz C cruda ofrecida por la API de milter.
o
Ya no se requiere administración, asignación y comunicación de datos específicos de la conexión
o
Normalmente ya no es necesario utilizar datos específicos de la conexión, como un puntero que identifica la conexión, al implementar el Milter.
o
Milter utiliza patrones de diseño actuales que imponen principios de software reutilizable, simplificando así la construcción del Milter real. Para activar un milter desde el archivo de configuración sendmail.mc, use, por ejemplo, INPUT_MAIL_FILTER(`nombre', `S=socket'), donde nombre es el nombre del milter y socket es el nombre del socket. Ver también el miembro setConnection más abajo.

ENUMERACIONES

La clase define cuatro enumeraciones. Una enumeración se usa para indicar las funciones de devolución de llamada que deben llamarse, la segunda renombra las banderas que se pueden pasar a sendmail para indicar qué acciones tiene permitido realizar el milter. La tercera define valores de estado que pueden usarse para informar a sendmail cómo procesar un mensaje. La cuarta define los valores de retorno. Las enumeraciones son:

enum CallBack
Esta enumeración contiene los siguientes valores:

o
CONNECT:
Indica que el milter define (sobrescribe) la funcionalidad de conexión. Esta es la primera función de devolución de llamada que puede ser llamada por sendmail;
o
HELO:
Indica que el milter define (sobrescribe) la funcionalidad helo. Esto indica que sendmail debe llamar a la función helo, proporcionando al milter información sobre el cliente que se conecta;
o
SENDER:
Indica que el milter define (sobrescribe) la funcionalidad de remitente. Esto indica que sendmail debe llamar a la función sender, proporcionando al milter la información del sobre del remitente;
o
RECIPIENT:
Indica que el milter define (sobrescribe) la funcionalidad de destinatario. Esto indica que sendmail debe llamar a la función recipient, proporcionando al milter la información del sobre del destinatario;
o
HEADER:
Indica que el milter define (sobrescribe) la funcionalidad de encabezado. Esto indica que sendmail debe llamar a la función header por cada encabezado de correo que se utilice en el mensaje de correo actual;
o
EOH:
Indica que el milter define (sobrescribe) la funcionalidad de fin de encabezado. Esto indica que sendmail debe llamar a la función eoh una vez que se hayan procesado todas las líneas de encabezado;
o
BODY:
Indica que el milter define (sobrescribe) la funcionalidad del cuerpo. Esto indica que sendmail debe llamar a la función body, ofreciendo el cuerpo del mensaje de correo al milter;
o
EOM:
Indica que el milter define (sobrescribe) la funcionalidad de fin de mensaje. Esto indica que sendmail debe llamar a la función eom una vez que se hayan procesado todos los elementos del mensaje de correo electrónico;
o
ABORT:
Indica que el milter define (sobrescribe) la funcionalidad de abortar. La función abort puede ser llamada por sendmail antes de llamar a eom. Debe reclamar todos los recursos utilizados por el mensaje, pero no eliminar ninguna memoria asignada por el milter, ya que ese es el trabajo de close;
o
CLOSE:
Indica que el milter define (sobrescribe) la funcionalidad de cerrar. La función close debe eliminar toda la memoria (específica de la conexión) asignada por el milter. Puede ser llamada "fuera de orden", es decir, incluso antes de que se llame a connect, y los desarrolladores deben anticipar esta posibilidad al elaborar su código de close. En particular, es incorrecto asumir que el puntero de contexto privado será algo diferente de 0 en esta devolución de llamada;
o
UNKNOWN:
Actualmente no se utiliza. Reservado para versiones que superen la versión 2 de la API de milter de sendmail;
o
DATA:
Actualmente no se utiliza. Reservado para versiones que superen la versión 3 de la API de milter de sendmail;
o
ALL_CALLBACKS:
Atajo para indicar todas las facilidades de devolución de llamada. Los valores de CallBack son banderas de bits. El operador bit_or puede usarse para combinarlos, y el operador bit_not puede usarse para eliminar una bandera de ALL_CALLBACKS (por ejemplo, ALL_CALLBACKS && ~ABORT).

Status
Esta enumeración simplifica los valores extendidos SMFIS_ utilizados por la API de C. Estos valores se pueden usar para devolver valores sfsistat:

o
ACCEPT:
Este valor es igual a SMFIS_ACCEPT, lo que indica que Sendmail debe aceptar el mensaje. Para una llamada de retorno orientada a la conexión (ver más abajo en FUNCIONES MIEMBRO VIRTUALES PROTEGIDAS), acepte esta conexión sin más procesamiento de filtros, llame a close (ver más abajo). Para otras llamadas de retorno: acepte este mensaje sin más filtrado;
o
CONTINUE:
Este valor es igual a SMFIS_CONTINUE, lo que indica que Sendmail debe continuar el procesamiento. Este es el valor predeterminado para todas las funciones de llamada de retorno que no son anuladas por la clase derivada de Milter;
o
DISCARD:
Este valor es igual a SMFIS_DISCARD, lo que indica que Sendmail debe descartar el mensaje de correo. No debe ser devuelto por una llamada de retorno orientada a la conexión. Para otras llamadas de retorno: el mensaje se acepta, pero se descarta silenciosamente;
o
REJECT:
Este valor es igual a SMFIS_REJECT, lo que indica que Sendmail debe rechazar el mensaje de correo. Para una llamada de retorno orientada a la conexión, rechace esta conexión; llame a close. Para una llamada de retorno orientada al mensaje (excepto eom o abort, ver abajo), rechace este mensaje. Para una llamada de retorno orientada al destinatario, rechace el destinatario actual (pero continúe procesando el mensaje actual);
o
TEMPFAIL:
Este valor es igual a SMFIS_TEMPFAIL, lo que indica que Sendmail debe devolver un mensaje de `temporalmente no disponible' al remitente del mensaje de correo. Para una llamada de retorno orientada al mensaje (excepto sender, ver abajo), falle para este mensaje. Para una llamada de retorno orientada a la conexión, falle para esta conexión y llame a close. Para una llamada de retorno orientada al destinatario, solo falle para el destinatario actual y continúe el procesamiento del mensaje.

Return
Esta enumeración simplifica los valores extendidos MI_ utilizados por la API de C. Sin embargo, la mayoría de los valores de retorno utilizados por la clase Milter son valores bool. Los valores Return son:

o
FAILURE:
Este valor es igual a MI_FAILURE, lo que indica que una función de la API de C no pudo realizar su tarea;
o
SUCCESS:
Este valor es igual a MI_SUCCESS, lo que indica que una función de la API de C tuvo éxito en realizar su tarea.

CONSTRUCTOR/DESTRUCTOR

o
Milter():
El constructor predeterminado está disponible para clases derivadas. No realiza ninguna acción;
o
virtual ~Milter():
El destructor (público) virtual no realiza ninguna acción: las clases derivadas pueden anular el destructor para adaptarlo a sus propias necesidades.

Los operadores de asignación sobrecargados no están disponibles.

FUNCIONES MIEMBRO ESTÁTICAS PÚBLICAS

Estas funciones forman el núcleo de la clase base Milter. Se pueden llamar para inicializar, iniciar y detener el Milter.

o
void initialize(std::string const &name, Milter &milter, callback_set callbacks = CONNECT, flag_set flags = NO_FLAGS):
Esta función inicializa la administración del Milter. Espera el nombre del filtro de correo como primer argumento. Su segundo argumento es una referencia a un objeto Milter. Dado que Milter es una clase base abstracta, el objeto real es siempre un objeto de una clase derivada de Milter. Su tercer argumento especifica las llamadas de retorno a realizar para este milter. Por defecto, se llaman las llamadas de retorno connect y close. A partir de la versión 6.04.00 de bobcat, la llamada de retorno close siempre se realiza una vez que finaliza una conexión: se puede especificar al especificar el argumento callbacks, pero si no, la llamada de retorno close aún se realiza. El último argumento define las banderas, especificando las capacidades del Milter;
o
std::string const &name():
Esta función devuelve el nombre del milter;
o
bool start():
Esta función miembro llama a smfi_main, controlando el bucle de eventos del milter. Devuelve true si el bucle de eventos termina exitosamente;
o
void stop():
Esta función miembro termina el bucle de eventos del milter, después de finalizar todos los hilos. Después de esta llamada, se puede llamar a start nuevamente para continuar el milter.

FUNCIONES MIEMBRO PROTEGIDAS

Los siguientes miembros no son virtuales. Pueden ser llamados por miembros de clases derivadas de Milter:

o
bool addHeader(std::string const &hdrName, std::string const &hdrValue):
Este miembro solo se puede llamar desde eom, y la bandera ADD_HEADERS debe haber sido especificada o fallará. Los argumentos hdrName y hdrValue deben ser cadenas no vacías. Cada línea de la cabecera debe tener menos de 2048 caracteres y menos de 998 caracteres. Si se necesitan cabeceras más largas, hágalas de varias líneas. Para hacer una cabecera de varias líneas, inserte un salto de línea (\n) seguido de al menos un carácter de espacio en blanco, como un espacio o una tabulación (\t). El salto de línea no debe ir precedido por un retorno de carro. Es responsabilidad del escritor del filtro asegurarse de que no se violen los estándares;
o
bool addRecipient(std::string const &rcptName):
Este miembro solo se puede llamar desde eom, y la bandera ADD_RECIPIENTS debe haber sido especificada o fallará;
o
bool changeHeader(std::string const &hdrName, size_t headerNr, std::string const &hdrValue):
Este miembro solo se puede llamar desde eom, y la bandera CHANGE_HEADERS debe haber sido especificada o fallará. Consulte addHeader para los requisitos de la cabecera. El parámetro headerNr es un valor de índice de cabecera basado en 1. Un valor de headerNr de 1 modificará la primera ocurrencia de una cabecera llamada hdrValue. Si headerNr es mayor que el número de veces que aparece hdrName, se agregará una nueva cabecera hdrName. Si hdrValue está vacío, la cabecera se elimina;
o
bool deleteRecipient(std::string const &rcptName):
Este miembro solo se puede llamar desde eom, y la bandera DELETE_RECIPIENTS debe haber sido especificada o fallará. Este miembro elimina al destinatario con nombre del sobre del mensaje actual;
o
SMFICTX *id() const:
Este miembro puede ser llamado por el objeto Milter para obtener un puntero que identifica su conexión de sendmail. Normalmente, no debería ser necesario llamar a este miembro;
o
bool insertHeader(size_t hdrIdx, std::string const &hdrName, std::string const &hdrValue):
Este miembro solo se puede llamar desde eom, y la bandera ADD_HEADERS debe haber sido especificada o fallará. Consulte addHeader para los requisitos de la cabecera. El parámetro headerNr es un valor de índice de cabecera. Un valor de headerNr de 0 insertará esta cabecera como la primera de las cabeceras hdrName. Si headerNr es mayor que el número de veces que aparece hdrName, se agregará una nueva cabecera hdrName;
o
bool openSocket(bool removeIfTrue = true):
Este miembro debe llamarse antes de llamar a start. Este miembro intenta crear el socket especificado por setConnection (ver más abajo). Esto permite a la aplicación que llama asegurarse de que el socket pueda crearse, posiblemente cambiando su protección (derechos de acceso) antes de que el milter comience su trabajo. Si no se llama a este miembro, se llamará implícitamente cuando se inicie run. Devuelve true si el socket pudo crearse;
o
bool quarantine(std::string const &reason):
Este miembro solo se puede llamar desde eom y hace que el MTA ponga en cuarentena el mensaje utilizando la razón dada;
o
bool replaceBody(std::string const &body):
Este miembro solo se puede llamar desde eom, y la bandera CHANGE_BODY debe haber sido especificada o fallará. Se puede llamar múltiples veces, en cuyo caso el contenido del cuerpo variado se concatena en el mensaje final. Los saltos de línea deben codificarse como CRLF;
o
bool setBacklog(size_t backlog = 5):
Este miembro debe llamarse antes de llamar a start. Establece la cola de espera del socket entrante utilizada por listen(2). Si no se llama a setBacklog, se utiliza el valor predeterminado del sistema operativo. La función devuelve false si no se pudo establecer la cola de espera según lo solicitado. Es responsabilidad del programador no llamar a esta función con un argumento 0;
o
bool setConnection(std::string const &name):
Este miembro debe llamarse antes de llamar a start. Establece el socket a través del cual el filtro se comunica con sendmail. El socket se puede especificar utilizando una de las siguientes variantes:

DESCRIPTION

The libmilter API defines a protocol that allows a mail filter to interact with the Sendmail MTA. The filter can inspect and modify the headers and body of mail messages. The filter is implemented as a service that Sendmail connects to. The libmilter API provides a C++ class interface to this protocol.

This document describes the member functions of the C++ class interface. You are expected to implement these member functions in a class that inherits from the abstract base class smf_class.

The actual implementation of the interface is in the libmilter library, which implements the protocol between the filter and Sendmail. Sendmail calls the appropriate member functions of your class instance as mail flows through it.

The parameter av is an array of strings, terminated by a null pointer. The first argument is the command name. Subsequent arguments are the parameters to the command.

The hostname parameter is the hostname of the connecting client. This is typically the result of a getpeername(2) call.

The return value sfsistat is used by Sendmail to determine how to proceed. The possible values are:

o
SMFIS_CONTINUE: Continue processing the message. Sendmail may proceed to the next step. This is the default for most functions.
o
SMFIS_REJECT: Reject the message with a temporary error. Sendmail will return a temporary failure to the sender.
o
SMFIS_ACCEPT: Accept the message as is. No further filtering will be performed.
o
SMFIS_DELETE: Delete the message. No further processing will be performed.
o
SMFIS_TEMPFAIL: Temporary failure. Sendmail will return a temporary failure to the sender, and retry later.
o
SMFIS_SKIP: Skip the rest of the filters for this message.
o
SMFIS_NOREPLY: Used by quit and close to indicate that Sendmail should not reply to the client.

The available member functions are:

o
virtual sfsistat connect(const char *hostname, char **av):
This function is called once at the beginning of a connection from Sendmail. The hostname parameter is the name of the sending host. The av parameter is a NULL-terminated array of strings, containing the SMTP connection arguments (e.g., ESMTP extensions). The first element of av is the hostname. Subsequent elements are the ESMTP extensions. SMFIS_CONTINUE is the default return value.
o
virtual sfsistat helo(const char *helohost, char **av):
This function is called once per HELO/EHLO command from the client. The helohost parameter is the domain name supplied by the client. The av parameter contains the ESMTP extensions offered by the client. SMFIS_CONTINUE is the default return value.
o
virtual sfsistat envfrom(const char **argv):
This function is called once per message, for the sender envelope address. The argv[0] parameter is the sender's envelope address. Subsequent elements of argv are the ESMTP arguments, such as SIZE or BODY=UTF8. SMFIS_TEMPFAIL, SMFIS_REJECT, SMFIS_ACCEPT, SMFIS_DELETE, SMFIS_CONTINUE, and SMFIS_SKIP may be returned.
o
virtual sfsistat envrcpt(const char **argv):
This function is called once per recipient envelope address. The argv[0] parameter is the recipient address. Subsequent elements of argv are the ESMTP arguments. SMFIS_TEMPFAIL, SMFIS_REJECT, SMFIS_ACCEPT, SMFIS_DELETE, SMFIS_CONTINUE, and SMFIS_SKIP may be returned.
o
virtual sfsistat header(const char *name, const char *value, int p):
This function is called once per header line. The name parameter is the header name, and value is the header value. The p parameter is a flag indicating if the header is presented to the user (1) or not (0). SMFIS_CONTINUE is the default return value.
o
virtual sfsistat eoh(void):
This function is called after the last header line. End Of Headers. SMFIS_CONTINUE is the default return value.
o
virtual sfsistat body(const smfi_content_t type, const char *buf, size_t len):
This function is called once per chunk of the message body. The type parameter indicates the content type (e.g., SMFI_CONTENT_TEXT, SMFI_CONTENT_UNKNOWN). The buf parameter is a pointer to the buffer containing the body chunk, and len is the length of the buffer. SMFIS_CONTINUE is the default return value.
o
virtual sfsistat xxfiheader(const char *name, const char *value, int p):
This function is called once per header line for extended filtering. This is similar to header but allows more control. SMFIS_CONTINUE is the default return value.
o
virtual sfsistat xxfibody(const smfi_content_t type, const char *buf, size_t len):
This function is called once per chunk of the message body for extended filtering. This is similar to body but allows more control. SMFIS_CONTINUE is the default return value.
o
virtual sfsistat unknown(char *buf):
This function is called when Sendmail receives an unknown command. SMFIS_CONTINUE is the default return value.
o
virtual sfsistat abort(void):
This function is called when Sendmail aborts the current transaction, e.g., due to a connection error or a QUIT command. SMFIS_CONTINUE is the default return value.
o
virtual sfsistat quit(void):
This function is called when Sendmail sends a QUIT command. SMFIS_CONTINUE is the default return value. SMFIS_NOREPLY can be returned to prevent Sendmail from sending a reply.
o
virtual sfsistat close(void):
This function is called when Sendmail closes the connection. SMFIS_CONTINUE is the default return value. SMFIS_NOREPLY can be returned to prevent Sendmail from sending a reply.
o
virtual sfsistat stats(void):
This function is called when Sendmail is shutting down. It is used to report statistics. SMFIS_CONTINUE is the default return value.
