membarrier(2) Manual de llamadas al sistema membarrier(2)

NOMBRE

membarrier - emitir barreras de memoria en un conjunto de hilos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/membarrier.h> /* Definición de las constantes MEMBARRIER_* */
#include <sys/syscall.h>      /* Definición de las constantes SYS_* */
#include <unistd.h>
int syscall(SYS_membarrier, int cmd, unsigned int flags, int cpu_id);

Nota: glibc no proporciona un envoltorio para membarrier(), lo que hace necesario el uso de syscall(2).

DESCRIPCIÓN

La llamada al sistema membarrier() ayuda a reducir la sobrecarga de las instrucciones de barrera de memoria necesarias para ordenar los accesos a memoria en sistemas multinúcleo. Sin embargo, esta llamada al sistema es más pesada que una barrera de memoria, por lo que usarla de manera efectiva *no* es tan simple como reemplazar las barreras de memoria con esta llamada al sistema, sino que requiere comprender los detalles que se detallan a continuación.

El uso de barreras de memoria debe hacerse teniendo en cuenta que una barrera de memoria siempre debe corresponder con sus contrapartes de barrera de memoria, o que el modelo de memoria de la arquitectura no requiere las barreras correspondientes.

Hay casos en los que un lado de las barreras correspondientes (al que nos referiremos como "lado rápido") se ejecuta mucho más a menudo que el otro (al que nos referiremos como "lado lento"). Este es un objetivo principal para el uso de membarrier(). La idea clave es reemplazar, para estas barreras correspondientes, las barreras de memoria del lado rápido por barreras de compilador simples, por ejemplo:


asm volatile("" : : : "memory")

y reemplazar las barreras de memoria del lado lento por llamadas a membarrier().

Esto añadirá sobrecarga al lado lento y eliminará sobrecarga del lado rápido, resultando así en un aumento general del rendimiento siempre que el lado lento sea lo suficientemente infrecuente como para que la sobrecarga de las llamadas membarrier() no supere la ganancia de rendimiento en el lado rápido.

El argumento cmd es uno de los siguientes:

MEMBARRIER_CMD_QUERY (desde Linux 4.3)
Consulta el conjunto de comandos soportados. El valor de retorno de la llamada es una máscara de bits de los comandos soportados. MEMBARRIER_CMD_QUERY, que tiene el valor 0, no está incluido en esta máscara de bits. Este comando siempre está soportado (en kernels donde se proporciona membarrier()).
MEMBARRIER_CMD_GLOBAL (desde Linux 4.16)
Asegura que todos los hilos de todos los procesos en el sistema pasen por un estado donde todos los accesos a memoria a direcciones de espacio de usuario coincidan con el orden del programa entre la entrada y la salida de la llamada al sistema membarrier(). Todos los hilos del sistema son el objetivo de este comando.
MEMBARRIER_CMD_GLOBAL_EXPEDITED (desde Linux 4.16)
Ejecuta una barrera de memoria en todos los hilos en ejecución de todos los procesos que previamente se registraron con MEMBARRIER_CMD_REGISTER_GLOBAL_EXPEDITED.
Al regresar de la llamada al sistema, el hilo que llama tiene la garantía de que todos los hilos en ejecución han pasado por un estado donde todos los accesos a memoria a direcciones de espacio de usuario coinciden con el orden del programa entre la entrada y la salida de la llamada al sistema (los hilos que no se ejecutan están, de facto, en dicho estado). Esta garantía se proporciona solo para los hilos de los procesos que previamente se registraron con MEMBARRIER_CMD_REGISTER_GLOBAL_EXPEDITED.
Dado que el registro se trata de la intención de recibir las barreras, es válido invocar MEMBARRIER_CMD_GLOBAL_EXPEDITED desde un proceso que no haya empleado MEMBARRIER_CMD_REGISTER_GLOBAL_EXPEDITED.
Los comandos "expedited" (acelerados) se completan más rápido que los no acelerados; nunca bloquean, pero tienen la desventaja de causar sobrecarga adicional.
MEMBARRIER_CMD_REGISTER_GLOBAL_EXPEDITED (desde Linux 4.16)
Registra la intención del proceso de recibir barreras de memoria MEMBARRIER_CMD_GLOBAL_EXPEDITED.
MEMBARRIER_CMD_PRIVATE_EXPEDITED (desde Linux 4.14)
Ejecuta una barrera de memoria en cada hilo en ejecución perteneciente al mismo proceso que el hilo que llama.
Al regresar de la llamada al sistema, el hilo que llama tiene la garantía de que todos sus hermanos de hilo en ejecución han pasado por un estado donde todos los accesos a memoria a direcciones de espacio de usuario coinciden con el orden del programa entre la entrada y la salida de la llamada al sistema (los hilos que no se ejecutan están, de facto, en dicho estado). Esta garantía se proporciona solo para los hilos del mismo proceso que el hilo que llama.
Los comandos "expedited" (acelerados) se completan más rápido que los no acelerados; nunca bloquean, pero tienen la desventaja de causar sobrecarga adicional.
Un proceso debe registrar su intención de usar el comando privado acelerado antes de usarlo.
MEMBARRIER_CMD_REGISTER_PRIVATE_EXPEDITED (desde Linux 4.14)
Registra la intención del proceso de usar MEMBARRIER_CMD_PRIVATE_EXPEDITED.
MEMBARRIER_CMD_PRIVATE_EXPEDITED_SYNC_CORE (desde Linux 4.16)
Además de proporcionar las garantías de ordenación de memoria descritas en MEMBARRIER_CMD_PRIVATE_EXPEDITED, al regresar de la llamada al sistema, el hilo que llama tiene la garantía de que todos sus hermanos de hilo en ejecución han ejecutado una instrucción de serialización de núcleo. Esta garantía se proporciona solo para los hilos del mismo proceso que el hilo que llama.
Los comandos "expedited" (acelerados) se completan más rápido que los no acelerados; nunca bloquean, pero tienen la desventaja de causar sobrecarga adicional.
Un proceso debe registrar su intención de usar el comando privado acelerado de sincronización de núcleo antes de usarlo.
MEMBARRIER_CMD_REGISTER_PRIVATE_EXPEDITED_SYNC_CORE (desde Linux 4.16)
Registra la intención del proceso de usar MEMBARRIER_CMD_PRIVATE_EXPEDITED_SYNC_CORE.
MEMBARRIER_CMD_PRIVATE_EXPEDITED_RSEQ (desde Linux 5.10)
Asegura que el hilo que llama, al regresar de la llamada al sistema, que todos sus hermanos de hilo en ejecución hayan reiniciado cualquier sección crítica rseq actualmente en ejecución si el parámetro flags es 0; si el parámetro flags es MEMBARRIER_CMD_FLAG_CPU, entonces esta operación se realiza solo en la CPU indicada por cpu_id. Esta garantía se proporciona solo para hilos del mismo proceso que el hilo que llama.
La barrera de memoria RSEQ solo está disponible en la forma "privada acelerada".
Un proceso debe registrar su intención de usar el comando privado acelerado rseq antes de usarlo.
MEMBARRIER_CMD_REGISTER_PRIVATE_EXPEDITED_RSEQ (desde Linux 5.10)
Registra la intención del proceso de usar MEMBARRIER_CMD_PRIVATE_EXPEDITED_RSEQ.
MEMBARRIER_CMD_SHARED (desde Linux 4.3)
Este es un alias para MEMBARRIER_CMD_GLOBAL que existe por compatibilidad con versiones anteriores de la cabecera.

El argumento flags debe especificarse como 0 a menos que el comando sea MEMBARRIER_CMD_PRIVATE_EXPEDITED_RSEQ, en cuyo caso flags puede ser 0 o MEMBARRIER_CMD_FLAG_CPU.

El argumento cpu_id solo se usa cuando flags se establece en MEMBARRIER_CMD_FLAG_CPU.

Si un comando no está soportado, se devuelve -1 y errno se establece en EINVAL.

Si el sistema operativo no soporta membarrier(), se devuelve -1 y errno se establece en ENOSYS.

VALOR DE RETORNO

En caso de éxito, se devuelve 0. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EINVAL
El comando especificado en cmd no es válido o no está soportado por la versión del kernel.
ENOSYS
La llamada al sistema membarrier() no está implementada en el kernel.
EPERM
Se intentó usar MEMBARRIER_CMD_GLOBAL, MEMBARRIER_CMD_GLOBAL_EXPEDITED o MEMBARRIER_CMD_REGISTER_GLOBAL_EXPEDITED sin los privilegios necesarios (actualmente, estas operaciones solo están permitidas para CAP_SYS_ADMIN).

CONFORMIDAD

La llamada al sistema membarrier() es específica de Linux.

VERSIÓN

Estas llamadas al sistema estuvieron disponibles por primera vez en Linux 4.3.

EJEMPLOS

Para consultar qué comandos soporta el kernel, se puede usar:

int supported_cmds = syscall(SYS_membarrier, MEMBARRIER_CMD_QUERY, 0, 0);
if (supported_cmds == -1) {
    perror("membarrier");
    exit(EXIT_FAILURE);
}
if (supported_cmds & (1 << MEMBARRIER_CMD_PRIVATE_EXPEDITED)) {
    printf("MEMBARRIER_CMD_PRIVATE_EXPEDITED is supported\n");
}

Para registrarse para recibir barreras de memoria privadas aceleradas y luego emitirlas:

int ret;
ret = syscall(SYS_membarrier, MEMBARRIER_CMD_REGISTER_PRIVATE_EXPEDITED, 0, 0);
if (ret == -1) {
    perror("MEMBARRIER_CMD_REGISTER_PRIVATE_EXPEDITED");
    exit(EXIT_FAILURE);
}
ret = syscall(SYS_membarrier, MEMBARRIER_CMD_PRIVATE_EXPEDITED, 0, 0);
if (ret == -1) {
    perror("MEMBARRIER_CMD_PRIVATE_EXPEDITED");
    exit(EXIT_FAILURE);
}

membarrier(2) — Arch Linux

NAME

membarrier — impone barreras de memoria para el hilo o todos los hilos

LIBRARY

libc, -lc

SYNOPSIS

#include <sys/syscall.h>
#include <linux/membarrier.h>

int
membarrier(int cmd, int flags, int cpu_id);

DESCRIPTION

La llamada al sistema membarrier() proporciona un medio para que un programa de usuario imponga orden en los accesos a memoria de forma controlada.

Los argumentos son:

  • cmd es el comando que se va a ejecutar.

    Los valores posibles para cmd son:

    MEMBARRIER_CMD_QUERY
    Devuelve una máscara de bits de los comandos de barrera de memoria admitidos. Si un comando no es compatible, el bit correspondiente no estará establecido en la máscara devuelta.
    MEMBARRIER_CMD_GLOBAL
    Hace que todos los hilos del proceso (excepto los hilos que se registran explícitamente para comandos privados) que ejecutan la llamada al sistema membarrier() esperen a que todos los accesos a memoria de todos los hilos se completen. Todas las escrituras antes de esta barrera son visibles para todos los hilos después de esta barrera. Todas las lecturas antes de esta barrera ven los mismos valores que ven los hilos después de esta barrera.
    MEMBARRIER_CMD_GLOBAL_EXPEDITED
    Similar a MEMBARRIER_CMD_GLOBAL, pero puede ser más rápido. No garantiza la visibilidad de las cargas de memoria antes de la barrera. Las escrituras antes de esta barrera son visibles para todos los hilos después de esta barrera. Todas las lecturas antes de esta barrera ven los mismos valores que ven los hilos después de esta barrera.
    MEMBARRIER_CMD_REGISTER_GLOBAL_EXPEDITED
    Registra el hilo que realiza la llamada para que reciba las barreras de memoria MEMBARRIER_CMD_GLOBAL_EXPEDITED y MEMBARRIER_CMD_PRIVATE_EXPEDITED_SYNC_CORE. Los hilos registrados no participan en las barreras MEMBARRIER_CMD_GLOBAL y MEMBARRIER_CMD_GLOBAL_EXPEDITED dirigidas a todos los hilos del proceso. Esto puede ser útil para implementaciones de bibliotecas de concurrencia que utilizan sus propias barreras de memoria internas y no necesitan las barreras globales más fuertes.
    MEMBARRIER_CMD_PRIVATE_EXPEDITED
    Hace que el hilo que realiza la llamada espere a que todos los accesos a memoria realizados en el programa se completen antes de que la barrera de memoria sea visible para otros hilos. Esto es útil para las optimizaciones de solo lectura en las que un hilo solo necesita garantizar que sus propias cargas de memoria se completen antes de continuar.
    MEMBARRIER_CMD_REGISTER_PRIVATE_EXPEDITED
    Registra el hilo que realiza la llamada para que reciba las barreras de memoria MEMBARRIER_CMD_PRIVATE_EXPEDITED y MEMBARRIER_CMD_PRIVATE_EXPEDITED_SYNC_CORE. Los hilos registrados no participan en las barreras MEMBARRIER_CMD_PRIVATE_EXPEDITED dirigidas a todos los hilos del proceso.
    MEMBARRIER_CMD_PRIVATE_EXPEDITED_SYNC_CORE
    Similar a MEMBARRIER_CMD_PRIVATE_EXPEDITED, pero además garantiza que todos los accesos a memoria en el hilo actual sean visibles para el núcleo de CPU especificado por cpu_id después de la barrera.
    MEMBARRIER_CMD_REGISTER_PRIVATE_EXPEDITED_SYNC_CORE
    Registra el hilo que realiza la llamada para que reciba las barreras de memoria MEMBARRIER_CMD_PRIVATE_EXPEDITED_SYNC_CORE. Los hilos registrados no participan en las barreras MEMBARRIER_CMD_PRIVATE_EXPEDITED_SYNC_CORE dirigidas a todos los hilos del proceso.

  • flags es una máscara de bits que modifica el comportamiento de la llamada al sistema. Actualmente, solo se define el siguiente bit de bandera:

    MEMBARRIER_CMD_FLAG_CPU
    Si se establece este bit, cpu_id debe especificar la CPU específica que se verá afectada por la barrera. Si no se establece, cpu_id se ignora.

  • cpu_id es el identificador de la CPU. Solo se utiliza cuando se establece MEMBARRIER_CMD_FLAG_CPU en flags. En ese caso, debe especificar la CPU de destino para este comando de barrera de memoria.

Todos los accesos a memoria realizados en el orden del programa desde cada hilo de destino están garantizados para ordenarse con respecto a membarrier().

Si utilizamos la semántica barrier() para representar una barrera del compilador que obliga a realizar accesos a memoria en el orden del programa a través de la barrera, y smp_mb() para representar barreras de memoria explícitas que fuerzan un ordenamiento completo de la memoria a través de la barrera, tenemos la siguiente tabla de ordenamiento para cada par de barrier(), membarrier(), y smp_mb(). El ordenamiento del par se detalla como (O: ordenado, X: no ordenado):

barrier() smp_mb() membarrier()
barrier() X X O
smp_mb() X O O
membarrier() O O O

RETURN VALUE

En caso de éxito, la operación MEMBARRIER_CMD_QUERY devuelve una máscara de bits de los comandos admitidos, y las operaciones MEMBARRIER_CMD_GLOBAL, MEMBARRIER_CMD_GLOBAL_EXPEDITED, MEMBARRIER_CMD_REGISTER_GLOBAL_EXPEDITED, MEMBARRIER_CMD_PRIVATE_EXPEDITED, MEMBARRIER_CMD_REGISTER_PRIVATE_EXPEDITED, MEMBARRIER_CMD_PRIVATE_EXPEDITED_SYNC_CORE y MEMBARRIER_CMD_REGISTER_PRIVATE_EXPEDITED_SYNC_CORE devuelven cero. En caso de error, se devuelve -1 y se establece errno para indicar el error.

Para un comando dado, con flags establecido en 0, se garantiza que esta llamada al sistema siempre devolverá el mismo valor hasta el reinicio. Llamadas posteriores con los mismos argumentos conducirán al mismo resultado. Por lo tanto, con flags establecido en 0, el manejo de errores solo es necesario para la primera llamada a membarrier().

ERRORS

EINVAL
cmd es inválido, o flags no es cero, o el comando MEMBARRIER_CMD_GLOBAL está deshabilitado porque se ha establecido el parámetro de CPU nohz_full, o los comandos MEMBARRIER_CMD_PRIVATE_EXPEDITED_SYNC_CORE y MEMBARRIER_CMD_REGISTER_PRIVATE_EXPEDITED_SYNC_CORE no están implementados por la arquitectura.
ENOSYS
La llamada al sistema membarrier() no está implementada por este kernel.
EPERM
El proceso actual no se registró antes de usar comandos privados acelerados.

STANDARDS

Linux.

HISTORY

Linux 4.3.

Antes de Linux 5.10, el prototipo era:


int membarrier(int cmd, int flags);

NOTES

Una instrucción de barrera de memoria es parte del conjunto de instrucciones de arquitecturas con modelos de memoria débilmente ordenados. Ordena los accesos a memoria anteriores a la barrera y posteriores a la barrera con respecto a barreras coincidentes en otros núcleos. Por ejemplo, una cerca de carga puede ordenar las cargas anteriores y posteriores a esa cerca con respecto a las escrituras ordenadas por cercas de escritura.

El orden del programa es el orden en que las instrucciones se ordenan en el código ensamblador del programa.

Ejemplos donde membarrier() puede ser útil incluyen implementaciones de bibliotecas Read-Copy-Update y recolectores de basura.

EXAMPLES

Suponiendo una aplicación multihilo donde "fast_path()" se ejecuta con mucha frecuencia, y donde "slow_path()" se ejecuta infrecuentemente, el siguiente código (x86) se puede transformar usando membarrier():


#include <stdlib.h>
static volatile int a, b;
static void
fast_path(int *read_b)
{
    a = 1;
    asm volatile ("mfence" : : : "memory");
    *read_b = b;
}
static void
slow_path(int *read_a)
{
    b = 1;
    asm volatile ("mfence" : : : "memory");
    *read_a = a;
}
int
main(void)
{
    int read_a, read_b;
    /*
     * Las aplicaciones reales llamarían a fast_path() y slow_path()
     * desde hilos diferentes.  Llamar a estos desde main() para mantener
     * este ejemplo corto.
     */
    slow_path(&read_a);
    fast_path(&read_b);
    /*
     * read_b == 0 implica read_a == 1 y
     * read_a == 0 implica read_b == 1.
     */
    if (read_b == 0 && read_a == 0)
        abort();
    exit(EXIT_SUCCESS);
}

El código anterior transformado para usar membarrier() se convierte en:


#define _GNU_SOURCE
#include <stdlib.h>
#include <stdio.h>
#include <unistd.h>
#include <sys/syscall.h>
#include <linux/membarrier.h>
static volatile int a, b;
static int
membarrier(int cmd, unsigned int flags, int cpu_id)
{
    return syscall(__NR_membarrier, cmd, flags, cpu_id);
}
static int
init_membarrier(void)
{
    int ret;
    /* Comprobar que membarrier() es compatible.  */
    ret = membarrier(MEMBARRIER_CMD_QUERY, 0, 0);
    if (ret < 0) {
        perror("membarrier");
        return -1;
    }
    if (!(ret & MEMBARRIER_CMD_GLOBAL)) {
        fprintf(stderr,
            "membarrier no soporta MEMBARRIER_CMD_GLOBAL\n");
        return -1;
    }
    return 0;
}
static void
fast_path(int *read_b)
{
    a = 1;
    asm volatile ("" : : : "memory");
    *read_b = b;
}
static void
slow_path(int *read_a)
{
    b = 1;
    membarrier(MEMBARRIER_CMD_GLOBAL, 0, 0);
    *read_a = a;
}
int
main(int argc, char *argv[])
{
    int read_a, read_b;
    if (init_membarrier())
        exit(EXIT_FAILURE);
    /*
     * Las aplicaciones reales llamarían a fast_path() y slow_path()
     * desde hilos diferentes.  Llamar a estos desde main() para mantener
     * este ejemplo corto.
     */
    slow_path(&read_a);
    fast_path(&read_b);
    /*
     * read_b == 0 implica read_a == 1 y
     * read_a == 0 implica read_b == 1.
     */
    if (read_b == 0 && read_a == 0)
        abort();
    exit(EXIT_SUCCESS);
}
