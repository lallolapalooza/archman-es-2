memfd_secret(2) Manual de Llamadas al Sistema memfd_secret(2)

NOMBRE

memfd_secret - crear un archivo anónimo basado en RAM para acceder a regiones de memoria secreta

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/syscall.h>      /* Definición de constantes SYS_* */
#include <unistd.h>
int syscall(SYS_memfd_secret, unsigned int flags);

Nota: glibc no proporciona una envoltura para memfd_secret(), lo que requiere el uso de syscall(2).

DESCRIPCIÓN

memfd_secret() crea un archivo anónimo basado en RAM y devuelve un descriptor de archivo que se refiere a él. El archivo proporciona una forma de crear y acceder a regiones de memoria con una protección más fuerte que los archivos anónimos y los mapeos de memoria anónimos habituales. Una vez que se cierran todas las referencias abiertas al archivo, se libera automáticamente. El tamaño inicial del archivo se establece en 0. Después de la llamada, el tamaño del archivo debe establecerse usando ftruncate(2).

Las áreas de memoria que respaldan el archivo creado con memfd_secret(2) solo son visibles para los procesos que tienen acceso al descriptor de archivo. La región de memoria se elimina de las tablas de páginas del kernel y solo las tablas de páginas de los procesos que poseen el descriptor de archivo mapean la memoria física correspondiente. (Por lo tanto, las páginas de la región no pueden ser accedidas por el propio kernel, de modo que, por ejemplo, los punteros a la región no se pueden pasar a las llamadas al sistema).

Los siguientes valores pueden aplicarse mediante una operación OR bitwise en flags para controlar el comportamiento de memfd_secret():

FD_CLOEXEC
Establece el indicador de cierre en el descriptor de archivo nuevo, lo que provoca que la región se elimine del proceso en execve(2). Consulte la descripción de la bandera O_CLOEXEC en open(2).

Como valor de retorno, memfd_secret() devuelve un nuevo descriptor de archivo que se refiere a un archivo anónimo. Este descriptor de archivo se abre tanto para lectura como para escritura (O_RDWR) y se establece O_LARGEFILE para el descriptor de archivo.

Con respecto a fork(2) y execve(2), se aplican las semánticas habituales para el descriptor de archivo creado por memfd_secret(). Una copia del descriptor de archivo es heredada por el hijo producido por fork(2) y se refiere al mismo archivo. El descriptor de archivo se conserva en las llamadas a execve(2), a menos que se haya establecido el indicador de cierre.

La región de memoria se bloquea en memoria de la misma manera que con mlock(2), de modo que nunca se escribirá en el intercambio (swap) y se inhibe la hibernación mientras existan descripciones de memfd_secret() activas. Sin embargo, la implementación de memfd_secret() no intentará poblar todo el rango durante la llamada a mmap(2) que adjunta la región al espacio de direcciones del proceso; en su lugar, las páginas se asignan realmente solo cuando se activan por fallo (fault). La cantidad de memoria permitida para los mapeos de memoria del descriptor de archivo obedece las mismas reglas que mlock(2) y no puede exceder RLIMIT_MEMLOCK.

VALOR DE RETORNO

En caso de éxito, memfd_secret() devuelve un nuevo descriptor de archivo. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EINVAL
flags contenía bits desconocidos.
EMFILE
Se alcanzó el límite por proceso en el número de descriptores de archivo abiertos.
EMFILE
Se alcanzó el límite del sistema en el número total de archivos abiertos.
ENOMEM
Hubo memoria insuficiente para crear un nuevo archivo anónimo.
ENOSYS
memfd_secret() no está implementado en esta arquitectura, o no se ha habilitado en la línea de comandos del kernel con secretmem_enable=1.

ESTANDARES

Linux.

HISTORIAL

Linux 5.14.

Antes de Linux 6.5, memfd_secret() estaba deshabilitado por defecto y solo estaba disponible si el administrador del sistema lo activaba usando el parámetro del kernel "secretmem.enable=y".

NOTAS

La llamada al sistema memfd_secret() está diseñada para permitir que un proceso de espacio de usuario cree un rango de memoria inaccesible para cualquier otra persona, incluido el kernel. No hay una garantía del 100% de que el kernel no pueda acceder a los rangos de memoria respaldados por memfd_secret() en ninguna circunstancia, pero aun así, es mucho más difícil exfiltrar datos de estas regiones.

memfd_secret() proporciona las siguientes protecciones:

•
Protección mejorada (en conjunción con todos los demás sistemas de prevención de ataques del kernel) contra ataques ROP. La ausencia de cualquier primitiva dentro del kernel para acceder a la memoria respaldada por memfd_secret() significa que un ataque ROP de un solo gadget no puede funcionar para realizar la exfiltración de datos. El atacante necesitaría encontrar suficientes gadgets ROP para reconstruir las entradas faltantes de la tabla de páginas, lo que aumenta significativamente la dificultad del ataque, especialmente cuando existen otras protecciones como el límite del tamaño de la pila del kernel y el cifrado del espacio de direcciones (ASLR).
•
Evita exposiciones de memoria del espacio de usuario entre procesos. Una vez que se asigna una región para un mapeo de memoria de memfd_secret(), el usuario no puede pasarlo accidentalmente al kernel para que se transmita a algún lugar. Las páginas de memoria en esta región no se pueden acceder a través del mapeo directo y están desautorizadas en get_user_pages.
•
Fortalece contra fallos explotados en el kernel. Para acceder a las áreas de memoria respaldadas por memfd_secret(), un ataque del lado del kernel necesitaría caminar por las tablas de páginas y crear nuevas, o iniciar un nuevo proceso privilegiado de espacio de usuario para realizar la exfiltración de secretos usando ptrace(2).

Para evitar posibles fugas de datos de regiones de memoria respaldadas por memfd_secret() desde una imagen de hibernación, se impide la hibernación cuando hay usuarios activos de memfd_secret().
