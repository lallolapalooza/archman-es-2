MESG(1P) Manual del programador POSIX MESG(1P)

PROLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

mesg — permitir o denegar mensajes

SINOPSIS

mesg [y|n]

DESCRIPCION

La utilidad mesg controlará si otros usuarios tienen permiso para enviar mensajes a través de write, talk u otras utilidades a un dispositivo de terminal. El dispositivo de terminal afectado se determinará buscando el primer terminal en la secuencia de dispositivos asociados con la entrada estándar, la salida estándar y el error estándar, respectivamente. Sin argumentos, mesg informará el estado actual sin cambiarlo. Los procesos con privilegios apropiados podrán enviar mensajes a la terminal independientemente del estado actual.

OPCIONES

Ninguna.

OPERANDOS

Los siguientes operandos se soportarán en la localía POSIX:

y
Otorga permiso a otros usuarios para enviar mensajes al dispositivo de terminal.
n
Deniega permiso a otros usuarios para enviar mensajes al dispositivo de terminal.

ENTRADA ESTANDAR

No utilizada.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de mesg:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localía.)
LC_ALL
Si se establece en una cadena de valor no vacía, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la localía para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en contraposición a caracteres multibyte en los argumentos).
LC_MESSAGES

Determina la localía que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos (por mesg) en el error estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASINCRONOS

Predeterminado.

SALIDA ESTANDAR

Si no se especifica ningún operando, mesg mostrará el estado actual de la terminal en un formato no especificado.

ERROR ESTANDAR

El error estándar se utilizará únicamente para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCION EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
Se permite recibir mensajes.
 1
No se permite recibir mensajes.
>1
Ocurrió un error.

CONSECUENCIAS DE ERRORES

Predeterminado.

USO DE APLICACIONES

El mecanismo por el cual se cambia el estado de mensajes de la terminal no está especificado. Por lo tanto, acciones no especificadas pueden causar que el estado de la terminal cambie después de que mesg haya completado con éxito. Estas acciones pueden incluir, entre otras: otra invocación de la utilidad mesg, procedimientos de inicio de sesión; invocación de la utilidad stty, invocación de la utilidad chmod o la función chmod(), etc.

EJEMPLOS

Ninguno.

RATONALE

La terminal cambiada por mesg es la asociada con la entrada, salida o error estándar, en lugar de la terminal de control para la sesión. Esto se debe a que los usuarios que inician sesión más de una vez deberían poder cambiar cualquiera de sus terminales de inicio de sesión sin tener que detener el trabajo que se ejecuta en esas sesiones. Esto no es un problema de seguridad que involucre las terminales de otros usuarios porque se requerirían privilegios apropiados para afectar la terminal de otro usuario.

El método de verificar cada uno de los tres primeros descriptores de archivo en secuencia hasta encontrar una terminal se adoptó de System V.

El archivo /dev/tty no se especifica para el dispositivo de terminal porque se consideró demasiado restrictivo. Los cambios típicos del entorno para el operando n son que los permisos de escritura se eliminan para otros y grupo del dispositivo apropiado. Se decidió dejar la descripción real de lo que se hace como no especificada debido a las posibles diferencias entre implementaciones.

El formato para la salida estándar no está especificado debido a las diferencias entre las implementaciones históricas. Esta salida generalmente no es útil para scripts de shell (pueden usar el estado de salida), por lo que el análisis exacto de la salida no es necesario.
