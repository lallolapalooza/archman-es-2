NOMBRE

memcached_replace_by_key - Almacenamiento y Reemplazo de Datos

SINOPSIS

#include <libmemcached/memcached.h>
Compilar y enlazar con -lmemcached

memcached_return_t memcached_add(memcached_st *ptr, const char *key, size_t key_length, const char *value, size_t value_length, time_t expiration, uint32_t flags)
memcached_return_t memcached_replace(memcached_st *ptr, const char *key, size_t key_length, const char *value, size_t value_length, time_t expiration, uint32_t flags)
memcached_return_t memcached_set_by_key(memcached_st *ptr, const char *group_key, size_t group_key_length, const char *key, size_t key_length, const char *value, size_t value_length, time_t expiration, uint32_t flags)
memcached_return_t memcached_add_by_key(memcached_st *ptr, const char *group_key, size_t group_key_length, const char *key, size_t key_length, const char *value, size_t value_length, time_t expiration, uint32_t flags)

DESCRIPCIÓN

memcached_set() escribirá un objeto en el servidor. Si ya existe un objeto, sobrescribirá lo que hay en el servidor. Si el objeto no existe, se escribirá. Si estás utilizando el modo no bloqueante, esta función siempre devolverá true a menos que ocurra un error de red.

memcached_replace() reemplaza un objeto en el servidor. Si el objeto no se encuentra en el servidor, ocurre un error.

memcached_add() añade un objeto al servidor. Si el objeto se encuentra en el servidor, ocurre un error; de lo contrario, se almacena el valor.

Los métodos memcached_set_by_key(), memcached_add_by_key() y memcached_replace_by_key() se comportan de manera similar a los métodos sin clave. La diferencia es que usan su parámetro group_key para mapear objetos a servidores específicos.

Si buscas rendimiento, memcached_set() con E/S no bloqueante es la forma más rápida de almacenar datos en el servidor.

Todas las funciones anteriores se prueban con el comportamiento MEMCACHED_BEHAVIOR_USE_UDP habilitado. Sin embargo, al usar estas operaciones con este comportamiento activado, existen límites para el tamaño del payload que se envía al servidor. La razón de estos límites es que el Servidor Memcached no permite solicitudes de múltiples datagramas y la implementación actual del servidor establece un tamaño de datagrama de 1400 bytes. Debido a la sobrecarga del protocolo, el límite real de los datos suministrados por el usuario es inferior a 1400 bytes y depende del protocolo en uso, así como de la operación que se esté ejecutando. Al ejecutar con el protocolo binario, MEMCACHED_BEHAVIOR_BINARY_PROTOCOL, el tamaño combinado de la clave, el valor, los flags y la expiración no puede exceder los 1368 bytes. Al ejecutar con el protocolo ASCII, el límite exacto fluctúa dependiendo de la función que se esté ejecutando y de si la función es una operación CAS o no. Para operaciones SET ASCII no CAS, hay al menos 1335 bytes disponibles para distribuir entre la clave, el prefijo de clave y el valor; para operaciones CAS ASCII hay al menos 1318 bytes disponibles para distribuir entre la clave, el prefijo de clave y el valor. Si el tamaño total del comando, incluida la sobrecarga, excede los 1400 bytes, se devolverá un MEMCACHED_WRITE_FAILURE.

VALOR DE RETORNO

Todos los métodos devuelven un valor de tipo memcached_return_t.

En caso de éxito, el valor será MEMCACHED_SUCCESS. Usa memcached_strerror() para traducir este valor a una cadena imprimible.

Para memcached_replace() y memcached_add(), MEMCACHED_NOTSTORED es un error legítimo en caso de colisión.
