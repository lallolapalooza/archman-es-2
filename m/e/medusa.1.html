MEDUSA(1) Manual de comandos generales MEDUSA(1)

NOMBRE

MEDUSA - Auditor de inicio de sesión de red paralelo

SINOPSIS

medusa [-h host|-H archivo] [-u nombredeusuario|-U archivo] [-p contraseña|-P archivo] [-C archivo] -M módulo [OPCIONES]

DESCRIPCIÓN

Medusa está destinado a ser un auditor de inicio de sesión modular, masivamente paralelo y rápido. El objetivo es dar soporte al mayor número posible de servicios que permiten la autenticación remota. El autor considera los siguientes puntos como algunas de las características clave de esta aplicación:

*Pruebas paralelas basadas en hilos. Las pruebas de fuerza bruta se pueden realizar de forma concurrente contra múltiples hosts, usuarios o contraseñas.

*Entrada de usuario flexible. La información del objetivo (host/usuario/contraseña) se puede especificar de diversas maneras. Por ejemplo, cada elemento puede ser una entrada única o un archivo que contenga múltiples entradas. Adicionalmente, un formato de archivo combinado permite al usuario refinar su lista de objetivos.

*Diseño modular. Cada módulo de servicio existe como un archivo .mod independiente. Esto significa que no es necesario realizar modificaciones en la aplicación principal para ampliar la lista de servicios compatibles para la auditoría de fuerza bruta.

OPCIONES

-h [OBJETIVO]
Nombre de host o dirección IP del objetivo.
-H [ARCHIVO]
Lee las especificaciones del objetivo del archivo especificado en lugar de la línea de comandos. El archivo debe contener una lista separada por saltos de línea.
-u [OBJETIVO]
Nombre de usuario del objetivo.
-U [ARCHIVO]
Lee los nombres de usuario del objetivo del archivo especificado en lugar de la línea de comandos. El archivo debe contener una lista separada por saltos de línea.
-p [OBJETIVO]
Contraseña del objetivo.
-P [ARCHIVO]
Lee las contraseñas del objetivo del archivo especificado en lugar de la línea de comandos. El archivo debe contener una lista separada por saltos de línea.
-C [ARCHIVO]
Archivo que contiene entradas combinadas. Los archivos combinados están separados por dos puntos y tienen el siguiente formato: host:usuario:contraseña. Si alguno de los tres campos está vacío, la información respectiva debe proporcionarse como un valor global único o como una lista en un archivo.

Las siguientes combinaciones son posibles en el archivo combinado: 1.) foo:bar:fud 2.) foo:bar: 3.) foo:: 4.) :bar:fud 5.) :bar: 6.) ::fud 7.) foo::fud

Medusa también soporta el uso de archivos PwDump como archivo combinado. El formato de estos archivos debe ser usuario:id:lm:ntlm:::. Buscamos ':::' al final de la primera línea para determinar si el archivo contiene la salida de PwDump.

-O [ARCHIVO]
Archivo al que se añadirán las informaciones del registro. Medusa registrará todas las credenciales de cuentas que resulten válidas o que causen un error desconocido. También registrará los tiempos de inicio y fin de una auditoría, junto con los parámetros de llamada.
-e [n/s/ns]
Comprobaciones adicionales de contraseña ([n] Sin contraseña, [s] Contraseña = Nombre de usuario). Si se utilizan ambas opciones, deben especificarse juntas ("-e ns"). Si solo se llama a una opción individual, use "-e n" o "-e s".
-M [TEXTO]
Nombre del módulo a ejecutar (sin la extensión .mod).
-m [TEXTO]
Parámetro a pasar al módulo. Esto se puede pasar varias veces con un parámetro diferente cada vez y todos ellos se enviarán al módulo (es decir, -m Param1 -m Param2, etc.)
-d
Mostrar todos los módulos conocidos.
-n [NUM]
Usar para número de puerto TCP no predeterminado.
-s
Habilitar SSL.
-g [NUM]
Abandonar después de intentar conectarse durante NUM segundos (predeterminado 3).
-r [NUM]
Esperar NUM segundos entre intentos de reintento (predeterminado 3).
-R [NUM]
Intentar NUM reintentos antes de abandonar. El número total de intentos será NUM + 1.
-c [NUM]
Establecer el número de microsegundos que se esperan durante una prueba del socket de red establecido. Algunos servicios (por ejemplo, FTP, IMAP, POP3 y SMTP) pueden estar configurados para cerrar conexiones después de un número arbitrario de intentos de inicio de sesión fallidos. Intentamos reutilizar la conexión establecida para enviar intentos de autenticación hasta que ocurra esta desconexión, momento en el cual se restablece la conexión. Para lograr esto, verificamos si el socket aún está activo antes de autenticar dentro de módulos selectos. El valor predeterminado es realizar una comprobación de 1 microsegundo. Puede ser necesario especificar valores mucho más grandes. Por ejemplo, se necesitaron 1000 microsegundos contra nuestro servidor de prueba vsftp para evitar problemas con sus mecanismos incorporados anti-fuerza bruta.
-t [NUM]
Número total de inicios de sesión que se probarán de forma concurrente. Debe tenerse en cuenta que aproximadamente t x T hilos podrían estar en ejecución en un momento dado. 381 parece ser el límite en mi host Gentoo Linux bastante básico.
-T [NUM]
Número total de hosts que se probarán de forma concurrente.
-L
Paralelizar los inicios de sesión utilizando un nombre de usuario por hilo. El valor predeterminado es procesar el nombre de usuario completo antes de continuar.
-f
Dejar de escanear el host después de encontrar el primer nombre de usuario/contraseña válido.
-F
Detener la auditoría después de encontrar el primer nombre de usuario/contraseña válido en cualquier host.
-b
Suprimir el banner de inicio.
-q
Mostrar información de uso del módulo. Esto debe usarse junto con la opción "-M". Por ejemplo, "medusa -M smbnt -q".
-v [NUM]
Nivel de verbosidad [0 - 6 (más)]. Se mostrarán todos los mensajes en el nivel especificado o por debajo. El nivel predeterminado es 5.

El desglose de los niveles de verbosidad es el siguiente: 0) SALIR DE LA APLICACIÓN 1) MENSAJE SIN ETIQUETA 2) REGISTRAR MENSAJE SIN ETIQUETA 3) MENSAJE IMPORTANTE 4) CUENTA ENCONTRADA 5) COMPROBACIÓN DE CUENTA 6) MENSAJE GENERAL

-w [NUM]
Nivel de depuración de errores [0 - 10 (más)]. Se mostrarán todos los mensajes en el nivel especificado o por debajo. El nivel predeterminado es 5.

El desglose de los niveles de error es el siguiente: 0) FATAL 1) ALERTA 2) CRÍTICO 3) ERROR 4) ADVERTENCIA 5) NOTA 6) INFO 7) DEBUG 8) DEBUG - AUDITORÍA 9) DEBUG - SERVIDOR 10) DEBUG - MÓDULO

-V
Mostrar versión.
-Z [TEXTO]
Permite reanudar de forma básica un escaneo anterior. El parámetro suministrado describe qué hosts se completaron, cuáles se probaron parcialmente y cuáles no se iniciaron. Cuando Medusa recibe una SIGINT, calculará y mostrará un "mapa de reanudación". Este mapa se puede suministrar a la siguiente ejecución. Por ejemplo, "medusa [OPCIONES USADAS PREVIAMENTE] -Z h6u1u2h8.". En este ejemplo particular, los hosts 1-5 se completaron, el host 6 se completó parcialmente (el usuario 1 se completó parcialmente y el usuario 2 y posteriores no se iniciaron), el host 7 se completó y el host 8 y posteriores no se iniciaron. Medusa analizará este mapa y omitirá hosts y usuarios según corresponda. Debe tenerse en cuenta que solo se admite la reanudación a nivel de host y usuario, no a nivel de contraseña. Si un usuario se inició previamente, pero no se completó, se probará desde el inicio de su respectiva lista de contraseñas.
