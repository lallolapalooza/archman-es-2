DESCRIPCIÓN

memaslap es una herramienta de generación de carga y benchmarking para servidores memcached. Genera una carga de trabajo configurable como hilos, concurrencia, conexiones, tiempo de ejecución, sobrescritura, tasa de fallos, tamaño de clave, tamaño de valor, proporción get/set, rendimiento esperado, etc. Además, también prueba la verificación de datos, la verificación del tiempo de expiración, UDP, protocolo binario, prueba de facebook, prueba de replicación, multi-get y reconexión, etc.

Memaslap gestiona las conexiones de red como memcached con libevent. Cada hilo de memaslap está vinculado a un núcleo de CPU, todos los hilos no se comunican entre sí, y hay varias conexiones de socket en cada hilo. Cada conexión mantiene por sí misma la distribución del tamaño de clave, la distribución del tamaño de valor y la distribución de comandos.

Puedes especificar servidores a través de la opción memaslap --servers o a través de la variable de entorno MEMCACHED_SERVERS.

CARACTERÍSTICAS

Memslap se desarrolla con los siguientes propósitos:

Gestiona conexiones de red con libevent de forma asíncrona.

Configura tanto TCP como UDP para usar E/S no bloqueante.

Mejora el paralelismo: mayor rendimiento en entornos multihilo.

Mejora la eficiencia temporal: mayor velocidad de procesamiento.

Genera claves y valores de forma más eficiente; la distribución del tamaño de clave y la distribución del tamaño de valor son configurables.

Soporta comandos get, multi-get y set; la distribución de comandos es configurable.

Soporta tasas de fallo y sobrescritura controlables.

Soporta verificación de datos y tiempo de expiración.

Soporta la volcadura periódica de información estadística.

Soporta miles de conexiones TCP.

Soporta protocolo binario.

Soporta prueba de facebook (set con TCP y multi-get con UDP) y prueba de replicación.

DETALLES

Implementación efectiva de la red.

Para memaslap, tanto TCP como UDP usan E/S de red no bloqueante. Todos los eventos de red son gestionados por libevent como memcached. El módulo de red de memaslap es similar a memcached. Libevent puede asegurar que memaslap maneje la red de manera muy eficiente.

Implementación efectiva de multihilo y concurrencia

Memslap tiene una implementación multihilo similar a memcached. Memslap crea uno o más hilos autogobernados; cada hilo está vinculado a un núcleo de CPU si la configuración de prueba del sistema lo permite.

Además, cada hilo tiene un libevent para gestionar los eventos de la red; cada hilo tiene una o más concurrencias autogobernadas; y cada concurrencia tiene una o más conexiones de socket. Todas las tareas concurrentes no se comunican entre sí, incluso si están en el mismo hilo.

Memslap puede crear miles de conexiones de socket, y cada concurrencia tiene decenas de conexiones de socket. Cada concurrencia selecciona aleatoria o secuencialmente una conexión de socket de su grupo de conexiones de socket para ejecutar, por lo que memaslap puede asegurar que cada concurrencia maneje una conexión de socket en cualquier momento dado. Los usuarios pueden especificar el número de concurrencias y conexiones de socket de cada concurrencia según su carga de trabajo esperada.

Implementación efectiva de la generación de claves y valores

Para mejorar la eficiencia temporal y espacial, memaslap crea una tabla de caracteres aleatorios con 10M de caracteres. Todos los sufijos de las claves y valores se generan a partir de esta tabla de caracteres aleatorios.

Memslap utiliza el desplazamiento en la tabla de caracteres y la longitud de la cadena para identificar una cadena. Puede ahorrar mucha memoria. Cada clave contiene dos partes, un prefijo y un sufijo. El prefijo es un uint64_t, 8 bytes. Para verificar los datos establecidos previamente, memaslap necesita asegurar que cada clave sea única, por lo que utiliza el prefijo para identificar una clave. El prefijo no puede contener caracteres ilegales, como 'r', 'n', '0' y ' '. Y memaslap tiene un algoritmo para asegurar esto.

Memslap no genera todos los objetos (pares clave-valor) al principio. Solo genera suficientes objetos para llenar la ventana de tarea (10K objetos por defecto) de cada concurrencia. Cada objeto tiene la siguiente información básica: prefijo de clave, desplazamiento del sufijo de clave en la tabla de caracteres, longitud de la clave, desplazamiento del valor en la tabla de caracteres y longitud del valor.

En el proceso de trabajo, cada concurrencia selecciona secuencial o aleatoriamente un objeto de la ventana para realizar una operación set o get. Al mismo tiempo, cada concurrencia expulsa objetos de su ventana y agrega nuevos objetos.

Programación de tareas simple pero útil

Memslap utiliza libevent para programar todas las tareas concurrentes de los hilos, y cada concurrencia programa las tareas basándose en la ventana de tareas local. Memslap asume que si cada concurrencia mantiene la misma distribución de claves, distribución de valores y distribución de comandos, desde fuera, memaslap mantiene toda la distribución como un todo. Cada ventana de tareas incluye muchos objetos, cada objeto almacena su información básica, como clave, valor, tiempo de expiración, etc. En cualquier momento, todos los objetos en la ventana mantienen la misma distribución fija de claves y valores. Si se sobrescribe un objeto, se actualizará su valor. Memslap verifica los datos o el tiempo de expiración según la información del objeto almacenada en la ventana de tareas.

Libevent selecciona qué concurrencia manejar basándose en un evento de red específico. Luego, la concurrencia selecciona qué comando (get o set) operar basándose en la distribución de comandos. Si necesita expulsar un objeto antiguo y agregar uno nuevo, para mantener la misma distribución de claves y valores, el nuevo objeto debe tener la misma longitud de clave y longitud de valor.

Si el servidor memcached tiene dos capas de caché (memoria y SSD), ejecutar memaslap con diferentes tamaños de ventana puede generar diferentes tasas de fallo de caché. Si memaslap agrega suficientes objetos en las ventanas al principio, y la caché de memcached no puede almacenar todos los objetos inicializados, entonces memaslap obtendrá algunos objetos de la segunda capa de caché. Esto provoca fallos en la primera capa de caché. Por lo tanto, el usuario puede especificar el tamaño de la ventana para obtener la tasa de fallo esperada de la primera capa de caché.

Implementación útil de multiservidores , UDP, TCP, multi-get y protocolo binario

Debido a que cada hilo es autogobernado, memaslap puede asignar diferentes hilos para manejar diferentes servidores memcached. Esta es solo una de las formas en que memaslap prueba múltiples servidores. La única limitación es que el número de servidores no puede ser mayor que el número de hilos. La otra forma de probar múltiples servidores es para pruebas de replicación. Cada concurrencia tiene una conexión de socket a cada servidor memcached. Para la implementación, memaslap puede establecer algunos objetos en un servidor memcached y obtener estos objetos de los otros servidores.

Por defecto, Memslap realiza get individual. Si el usuario especifica la opción multi-get, memaslap recopilará suficientes comandos get y empaquetará y enviará los comandos juntos.

Memslap prueba tanto el protocolo ASCII como el protocolo binario, pero se ejecuta en el protocolo ASCII por defecto. Memslap se ejecuta por defecto en el protocolo TCP, pero también prueba UDP. Como UDP no es fiable, pueden ocurrir paquetes perdidos y paquetes fuera de orden. Memslap crea un búfer de memoria para manejar estos problemas. DESCRIPCIÓN

memaslap es una herramienta de prueba de carga para memcached.

memaslap funciona de la siguiente manera:

1.
El hilo principal inicializa todas las conexiones del servidor y los hilos de usuario.
2.
Cada hilo de usuario obtiene una clave de la cola de claves. La cola de claves se prellenará con claves generadas aleatoriamente o se generarán claves aleatoriamente si se especifica el modo de generación aleatoria. A continuación, el hilo genera un comando (por ejemplo, get, set, delete).
3.
El hilo de usuario envía el comando al servidor memcached.
4.
El hilo de usuario reordena la respuesta del servidor. Si algunos paquetes se pierden, el mecanismo de tiempo de espera de espera puede garantizar que los paquetes a medio cocinar se descarten y se envíe el siguiente comando.

Multihilo y concurrencia

El alto rendimiento de memaslap se beneficia de la programación especial de hilos y concurrencia. Es importante especificar el número adecuado de ellos. El número predeterminado de hilos es 1; el número predeterminado de concurrencia es 16. El usuario puede usar "—threads" y "--concurrency" para especificar estas variables.

Si el sistema prueba la configuración de afinidad de CPU y el número de hilos especificado por el usuario es mayor que 1, memaslap intentará enlazar cada hilo a un núcleo de CPU diferente. Por lo tanto, si desea obtener el mejor rendimiento de memaslap, es mejor especificar el número de hilos igual al número de núcleos de CPU. El número de hilos especificado por el usuario también puede ser menor o mayor que el número de núcleos de CPU. Debido a la limitación de la implementación, el número de concurrencias podría ser un múltiplo del número de hilos.

1.
Para un sistema de 8 núcleos de CPU

Por ejemplo:

--threads=2 --concurrency=128

--threads=8 --concurrency=128

--threads=8 --concurrency=256

--threads=12 --concurrency=144

2.
Para un sistema de 16 núcleos de CPU

Por ejemplo:

--threads=8 --concurrency=128

--threads=16 --concurrency=256

--threads=16 --concurrency=512

--threads=24 --concurrency=288

memaslap funciona muy bien cuando se utiliza para probar el rendimiento de los servidores memcached. La mayoría de las veces, el cuello de botella es la red o el servidor. Si por alguna razón el usuario desea limitar el rendimiento de memaslap, hay dos maneras de hacerlo:

Disminuya el número de hilos y concurrencias. Utilice la opción "--tps" que proporciona memaslap para limitar el rendimiento. Esta opción permite al usuario obtener el rendimiento esperado. Por ejemplo, suponga que el rendimiento máximo es de 50 kops/s para una configuración específica, puede especificar un rendimiento igual o inferior al rendimiento máximo utilizando la opción "--tps".

La mayoría de las veces, el usuario no necesita especificar el tamaño de la ventana. El tamaño de ventana predeterminado es 10k. Para Schooner Memcached, el usuario puede especificar diferentes tamaños de ventana para obtener diferentes tasas de fallos de caché según el caso de prueba. Memslap prueba la tasa de fallos de caché entre el 0% y el 100%. Si utiliza esta utilidad para probar el rendimiento de Schooner Memcached, puede especificar un tamaño de ventana adecuado para obtener la tasa de fallos de caché esperada. La fórmula para calcular el tamaño de la ventana para una tasa de fallo de caché del 0%:

La fórmula para calcular el tamaño de la ventana para una tasa de fallo de caché del 5%:

tamaño_caché / concurrencia / (tamaño_clave + tamaño_valor) * 0.7

Verificación

Memslap prueba tanto la verificación de datos como la verificación del tiempo de expiración. El usuario puede usar "--verify=" o "-v" para especificar la proporción de verificación de datos. En teoría, prueba el 100% de verificación de datos. El usuario puede usar "--exp_verify=" o "-e" para especificar la proporción de verificación del tiempo de expiración. En teoría, prueba el 100% de verificación del tiempo de expiración. Especifique las opciones "--verbose" para obtener información de error más detallada.

Por ejemplo: --exp_verify=0.01 –verify=0.1, significa que el 1% de los objetos se establecen con tiempo de expiración, el 10% de los objetos obtenidos se verificarán. Si se obtienen los objetos, memaslap verificará el tiempo de expiración y el valor.

múltiples servidores y múltiples configuraciones

Memslap prueba múltiples servidores basándose en hilos autogestionados. Existe la limitación de que el número de servidores no puede ser mayor que el número de hilos. Memslap asigna al menos un hilo para manejar un servidor. El usuario puede usar la opción "--servers=" o "-s" para especificar múltiples servidores.

Por ejemplo:

--servers=10.1.1.1:11211,10.1.1.2:11212,10.1.1.3:11213 --threads=6 --concurrency=36

El comando anterior significa que hay 6 hilos, cada hilo tiene 6 concurrencias, y que los hilos 0 y 3 manejan el servidor 0 (10.1.1.1); los hilos 1 y 4 manejan el servidor 1 (10.1.1.2); y los hilos 2 y 5 manejan el servidor 2 (10.1.1.3).

Todos los hilos y concurrencias en memaslap se autogestionan.

Lo mismo ocurre con memaslap. El usuario puede iniciar varias instancias de memaslap. El usuario puede ejecutar memaslap en diferentes máquinas cliente para comunicarse con el mismo servidor memcached al mismo tiempo. Se recomienda que el usuario inicie diferentes memaslap en diferentes máquinas utilizando la misma configuración.

Ejecutar en modo número de ejecuciones o modo tiempo.

El memaslap predeterminado se ejecuta en modo de tiempo. El tiempo de ejecución predeterminado es de 10 minutos. Si expira el tiempo, memaslap saldrá. No especifique el modo de número de ejecuciones y el modo de tiempo al mismo tiempo; solo especifique uno.

Por ejemplo:

--time=30s (Significa que la prueba se ejecutará durante 30 segundos).

--execute_number=100000 (Significa que después de ejecutar 100000 comandos, la prueba saldrá).

Volcar información estadística periódicamente.

El usuario puede usar "--stat_freq=" o "-S" para especificar la frecuencia.

Por ejemplo:

--stat_freq=20s

Memslap volcará las estadísticas de los comandos (get y set) con una frecuencia de cada 20 segundos.

Para obtener más información sobre el formato del volcado de información estadística, consulte la sección "Formato de salida".

Obtener múltiple

El usuario puede usar "--division=" o "-d" para especificar el número de claves de obtención múltiple. Memslap, por defecto, realiza una obtención individual con TCP. Memslap también prueba la verificación de datos y la verificación del tiempo de expiración para obtenciones múltiples.

Memslap prueba la obtención múltiple tanto con TCP como con UDP. Debido a la diferente implementación del protocolo ASCII y el protocolo binario, existen algunas diferencias entre ambos. Para el protocolo ASCII, memaslap envía un comando "multi-get" al servidor una vez. Para el protocolo binario, memaslap envía varios comandos get individuales juntos como "multi-get" al servidor.

UDP y TCP

Memslap prueba tanto UDP como TCP. Para TCP, memaslap no reconecta al servidor memcached si se pierden las conexiones de socket. Si se pierden todas las conexiones de socket o si el servidor memcached falla, memaslap saldrá. Si el usuario especifica la opción "--reconnect" cuando se pierden las conexiones de socket, las reconectará.

El usuario puede usar "--udp" para habilitar la función UDP, pero UDP tiene algunas limitaciones:

UDP no puede establecer datos de más de 1400 bytes.

UDP no se prueba con el protocolo binario porque el protocolo binario de memcached no lo prueba.

UDP no prueba la reconexión.

Prueba de Facebook

Establece datos con TCP y multi-get con UDP. Especifica las siguientes opciones:

"—facebook —division=50"

Si quieres crear miles de conexiones TCP, especifica la opción

"--conn_sock=".

Por ejemplo: —facebook —division=50 —conn_sock=200

El comando anterior significa que memaslap realizará la prueba de Facebook, cada concurrencia tiene 200 conexiones de socket TCP y un socket UDP.

Memslap establece objetos con el socket TCP, y multi-gets 50 objetos a la vez con el socket UDP.

Si especificas "--division=50", el tamaño de la clave debe ser menor que 25 bytes porque el tamaño del paquete UDP es de 1400 bytes.

Prueba de replicación

Para la prueba de replicación, el usuario debe especificar al menos dos servidores memcached. El usuario puede usar la opción "—rep_write=—" para habilitar la función.

Por ejemplo:

--servers=10.1.1.1:11211,10.1.1.2:11212 ——rep_write=2

El comando anterior significa que hay 2 servidores memcached de replicación, memaslap establecerá objetos en el servidor 0 y en el servidor 1, obtendrá objetos que se establecieron previamente en el servidor 0 desde el servidor 1, y también obtendrá objetos que se establecieron previamente en el servidor 1 desde el servidor 0. Si el servidor 0 falla, memaslap solo obtendrá objetos del servidor 1. Si el servidor 0 vuelve a estar disponible, memaslap se reconectará al servidor 0. Si tanto el servidor 0 como el servidor 1 fallan, memaslap saldrá.

Soporta miles de conexiones TCP

Inicia memaslap con "--conn_sock=" o "-n" para habilitar esta función. Asegúrate de que tu sistema pueda probar la apertura de miles de archivos y la creación de miles de sockets. Sin embargo, esta función no prueba la reconexión si los sockets se desconectan.

Por ejemplo:

——threads=8 ——concurrency=128 ——conn_sock=128

El comando anterior significa que memaslap inicia 8 hilos, cada hilo tiene 16 concurrencias, cada concurrencia tiene 128 conexiones de socket TCP, y el número total de conexiones de socket TCP es 128 * 128 = 16384.

Soporta protocolo binario

Inicia memaslap con las opciones "--binary" o "-B" para habilitar esta función. Prueba todas las funciones anteriores excepto UDP, porque la última versión de memcached 1.3.3 no implementa el protocolo UDP binario.

Por ejemplo:

——binary

Dado que memcached 1.3.3 no implementa el protocolo UDP binario, memaslap no prueba UDP. Además, memcached 1.3.3 no prueba multi-get. Si especificas la opción "--division=50", simplemente envía 50 comandos get juntos como "multi-get" al servidor.

NOMBRE

memaslap - Memcached client benchmarking tool

SINOPSIS

memaslap [options...]

DESCRIPCIÓN

memaslap es un cliente de benchmarking para Memcached. El programa simula la carga del cliente para el servidor Memcached, y recopila y muestra las estadísticas del proceso.

Es muy útil para realizar la evaluación del rendimiento de Memcached.

CARACTERÍSTICAS

memaslap proporciona una serie de características para realizar pruebas de estrés del lado del cliente:

Concurrencia
Simula múltiples conexiones de cliente simultáneas.
Multihilo
Utiliza múltiples hilos para generar tráfico de cliente.
Medición de rendimiento
Mide el rendimiento del servidor Memcached en términos de operaciones por segundo (TPS), latencia, etc.
Protocolos
Soporta tanto el protocolo ASCII como el binario.
Pruebas UDP
Permite realizar pruebas de rendimiento sobre UDP.
Verificación de datos
Incluye la opción de verificar la integridad de los datos recuperados.
Configuración de la carga
Permite configurar la distribución de las operaciones get/set, el tamaño de las claves y los valores, y la expiración de los objetos.

DETALLES

memaslap simula el comportamiento de un cliente Memcached, enviando solicitudes de GET y SET al servidor. El programa puede configurarse para ajustar diversos parámetros, como el número de hilos, el número de conexiones concurrentes, la duración de la prueba y el tamaño de los datos.

Las estadísticas recopiladas incluyen tiempos de respuesta, operaciones por segundo (TPS), tasa de red, y diversas métricas de fallos (misses, timeouts, etc.). Estas estadísticas ayudan a identificar cuellos de botella y a optimizar la configuración de Memcached.

USO

El programa se ejecuta especificando los servidores Memcached de destino y diversas opciones de configuración.

Por ejemplo, para ejecutar una prueba en un servidor en localhost:11211 durante 5 segundos:

memaslap -s 127.0.0.1:11211 -S 5s

Para ejecutar una prueba durante 2 minutos con verificación de datos y un 0.05% de objetos con tiempo de expiración:

memaslap -s 127.0.0.1:11211 -t 2m -v 0.2 -e 0.05 -b

ARCHIVO DE CONFIGURACIÓN

Se puede especificar un archivo de configuración usando la opción -F o --cfg_cmd. Este archivo puede contener distribuciones para comandos, claves y valores, permitiendo una configuración de carga más compleja.

OPCIONES

-s, --servers=
Lista uno o más servidores para conectar. El número de servidores debe ser menor que el número de hilos. Ej: --servers=localhost:1234,localhost:11211
-T, --threads=
Número de hilos a iniciar, preferiblemente igual al número de núcleos de CPU. Por defecto 8.
-c, --concurrency=
Número de concurrencias a simular con la carga. Por defecto 128.
-n, --conn_sock=
Número de sockets TCP por concurrencia. Por defecto 1.
-x, --execute_number=
Número de operaciones (get y set) a ejecutar para la prueba dada. Por defecto 1000000.
-t, --time=
Cuánto tiempo se ejecutará la prueba, sufijo: s-segundos, m-minutos, h-horas, d-días. Ej: --time=2h.
-F, --cfg_cmd=
Carga el archivo de configuración para obtener la lista de distribución de comandos, claves y valores.
-w, --win_size=
Tamaño de la ventana de tareas de cada concurrencia, sufijo: K, M. Ej: --win_size=10k. Por defecto 10k.
-X, --fixed_size=
Longitud fija del valor.
-v, --verify=
La proporción de verificación de datos, ej: --verify=0.01
-d, --division=
Número de claves para multi-get a la vez. Por defecto 1, significa get individual.
-S, --stat_freq=
Frecuencia de volcado de información estadística. Sufijo: s-segundos, m-minutos. Ej: --resp_freq=10s.
-e, --exp_verify=
La proporción de objetos con tiempo de expiración, ej: --exp_verify=0.01. Por defecto ningún objeto con tiempo de expiración.
-R, --reconnect
Reconectar pruebas, cuando la conexión se cierra, se reconectará.
-U, --udp
Pruebas UDP, por defecto memaslap usa TCP. El puerto TCP y el puerto UDP del servidor deben ser iguales.
-a, --facebook
Si habilita la característica de prueba de Facebook, se configura con TCP y multi-get con UDP.
-B, --binary
Si habilita el protocolo binario. Por defecto usa el protocolo ASCII.
-P, --tps=
Rendimiento esperado, sufijo: K, ej: --tps=10k.
-p, --rep_write=
Los primeros n servidores pueden escribir datos, ej: --rep_write=2.
-b, --verbose
Si muestra información detallada cuando la verificación falla.
-h, --help
Muestra este mensaje y luego sale.
-V, --version
Muestra la versión de la aplicación y luego sale.

EJEMPLOS

memaslap -s 127.0.0.1:11211 -S 5s

memaslap -s 127.0.0.1:11211 -t 2m -v 0.2 -e 0.05 -b

memaslap -s 127.0.0.1:11211 -F config -t 2m -w 40k -S 20s -o 0.2

memaslap -s 127.0.0.1:11211 -F config -t 2m -T 4 -c 128 -d 20 -P 40k

memaslap -s 127.0.0.1:11211 -F config -t 2m -d 50 -a -n 40

memaslap -s 127.0.0.1:11211,127.0.0.1:11212 -F config -t 2m

memaslap -s 127.0.0.1:11211,127.0.0.1:11212 -F config -t 2m -p 2

NOTAS

El prefijo de este programa es variable, es decir, puede configurarse en tiempo de compilación.

Normalmente, los programas cliente de libmemcached-awesome comienzan con el prefijo mem, como memcat o memcp.

Sin embargo, puede configurarse para reemplazar el prefijo con algo más como mc; en ese caso, los programas cliente de libmemcached-awesome se llamarían mccat, mccp, etc., respectivamente.

Este es un programa contribuido.

Este programa no sigue el esquema estándar de flags/opciones.
