memfd_create(2) Manual de llamadas al sistema memfd_create(2)

NOMBRE

memfd_create - crear un archivo anónimo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#define _GNU_SOURCE         /* Ver feature_test_macros(7) */
#include <sys/mman.h>
int memfd_create(const char *name, unsigned int flags);

DESCRIPCIÓN

memfd_create() crea un archivo anónimo y devuelve un descriptor de archivo que apunta a él. El archivo se comporta como un archivo regular, por lo que puede ser modificado, truncado, mapeado en memoria, etc. Sin embargo, a diferencia de un archivo regular, reside en RAM y tiene un almacenamiento de respaldo volátil. Una vez que todas las referencias al archivo se descartan, se libera automáticamente. Se utiliza memoria anónima para todas las páginas de respaldo del archivo. Por lo tanto, los archivos creados por memfd_create() tienen la misma semántica que otras asignaciones de memoria anónima, como las asignadas usando mmap(2) con el flag MAP_ANONYMOUS.

El tamaño inicial del archivo se establece en 0. Después de la llamada, el tamaño del archivo debe establecerse usando ftruncate(2). (Alternativamente, el archivo puede ser poblado mediante llamadas a write(2) o similares.)

El nombre proporcionado en name se utiliza como nombre de archivo y se mostrará como el objetivo del enlace simbólico correspondiente en el directorio /proc/self/fd/. El nombre mostrado siempre va precedido de memfd: y sirve únicamente a efectos de depuración. Los nombres no afectan el comportamiento del descriptor de archivo, y como tales, múltiples archivos pueden tener el mismo nombre sin efectos secundarios.

Los siguientes valores pueden combinarse mediante OR bit a bit en flags para cambiar el comportamiento de memfd_create():

MFD_CLOEXEC
Establece el flag de cierre al ejecutar (close-on-exec, FD_CLOEXEC) en el nuevo descriptor de archivo. Ver la descripción del flag O_CLOEXEC en open(2) para conocer las razones por las que esto puede ser útil.
MFD_ALLOW_SEALING
Permite operaciones de sellado en este archivo. Ver la discusión de las operaciones F_ADD_SEALS y F_GET_SEALS en fcntl(2), y también NOTAS, abajo. El conjunto inicial de sellos está vacío. Si este flag no está establecido, el conjunto inicial de sellos será F_SEAL_SEAL, lo que significa que no se pueden establecer otros sellos en el archivo.
MFD_HUGETLB (desde Linux 4.14)
El archivo anónimo se creará en el sistema de archivos hugetlbfs usando páginas grandes. Ver el archivo fuente del kernel de Linux Documentation/admin-guide/mm/hugetlbpage.rst para más información sobre hugetlbfs. Especificar tanto MFD_HUGETLB como MFD_ALLOW_SEALING en flags es compatible desde Linux 4.16.
MFD_HUGE_2MB
MFD_HUGE_1GB
...
Usado en conjunción con MFD_HUGETLB para seleccionar tamaños de página hugetlb alternativos (respectivamente, 2 MB, 1 GB, ...) en sistemas que soportan múltiples tamaños de página hugetlb. Las definiciones para tamaños de página grandes conocidos se incluyen en el archivo de cabecera <linux/memfd.h>.
Para detalles sobre la codificación de tamaños de página grandes no incluidos en el archivo de cabecera, ver la discusión de las constantes con nombres similares en mmap(2).

Los bits no utilizados en flags deben ser 0.

Como valor de retorno, memfd_create() devuelve un nuevo descriptor de archivo. Este descriptor de archivo se abre tanto para lectura como para escritura (O_RDWR) y se establece O_LARGEFILE para el descriptor de archivo.

Con respecto a fork(2) y execve(2), se aplican las semánticas habituales para el descriptor de archivo creado por memfd_create(). Una copia del descriptor de archivo es heredada por el hijo producido por fork(2) y apunta al mismo archivo. El descriptor de archivo se conserva durante execve(2), a menos que se haya establecido el flag de cierre al ejecutar.

VALOR DE RETORNO

En caso de éxito, memfd_create() devuelve un nuevo descriptor de archivo. En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

EFAULT
La dirección en name apunta a memoria inválida.
EINVAL
flags incluía bits desconocidos.
EINVAL
name era demasiado largo. (El límite es 249 bytes, excluyendo el byte nulo terminador.)
EINVAL
Se especificaron tanto MFD_HUGETLB como MFD_ALLOW_SEALING en flags.
EMFILE
Se ha alcanzado el límite por proceso del número de descriptores de archivo abiertos.
ENFILE
Se ha alcanzado el límite a nivel de sistema del número total de archivos abiertos.
ENOMEM
No había suficiente memoria para crear un nuevo archivo anónimo.
EPERM
Se especificó el flag MFD_HUGETLB, pero el llamante no tenía privilegios (no tenía la capacidad CAP_IPC_LOCK) y no es miembro del grupo hugetlb_shm_group; ver la descripción de /proc/sys/vm/hugetlb_shm_group en proc_sys_vm(5).

ESTANDARES

Linux.

HISTORIA

Linux 3.17, glibc 2.27.

NOTAS

La llamada al sistema memfd_create() proporciona una alternativa sencilla a montar manualmente un sistema de archivos tmpfs(5) y crear y abrir un archivo en ese sistema de archivos. El propósito principal de memfd_create() es crear archivos y sus descriptores de archivo asociados que se utilizan con las API de sellado de archivos proporcionadas por fcntl(2).

La llamada al sistema memfd_create() también tiene usos sin sellado de archivos (que es la razón por la que el sellado de archivos está deshabilitado, a menos que se solicite explícitamente con el flag MFD_ALLOW_SEALING). En particular, se puede usar como una alternativa a la creación de archivos en tmp o como una alternativa al uso de open(2) O_TMPFILE en casos donde no hay intención de enlazar realmente el archivo resultante en el sistema de archivos.

Sellado de archivos

En ausencia de sellado de archivos, los procesos que se comunican a través de memoria compartida deben confiar entre sí, o tomar medidas para lidiar con la posibilidad de que un par no confiable manipule la región de memoria compartida de maneras problemáticas. Por ejemplo, un par no confiable podría modificar el contenido de la memoria compartida en cualquier momento, o reducir el tamaño de la región de memoria compartida. La primera posibilidad deja al proceso local vulnerable a condiciones de carrera de tiempo de comprobación a tiempo de uso (time-of-check-to-time-of-use) (generalmente manejadas copiando datos de la región de memoria compartida antes de comprobarla y usarla). La segunda posibilidad deja al proceso local vulnerable a señales SIGBUS cuando se intenta acceder a una ubicación ya no existente en la región de memoria compartida. (Para manejar esta posibilidad se requiere el uso de un manejador para la señal SIGBUS.)

Manejar pares no confiables impone complejidad adicional al código que utiliza memoria compartida. El sellado de memoria permite eliminar esa complejidad adicional, al permitir que un proceso opere con la seguridad de que su par no puede modificar th

Un ejemplo del uso del mecanismo de sellado es el siguiente:

(1)
El primer proceso crea un archivo tmpfs(5) usando memfd_create(). La llamada devuelve un descriptor de archivo que se utiliza en los pasos posteriores.
(2)
El primer proceso dimensiona el archivo creado en el paso anterior usando ftruncate(2), lo mapea usando mmap(2) y rellena la memoria compartida con los datos deseados.
(3)
El primer proceso utiliza la operación F_ADD_SEALS de fcntl(2) para colocar uno o más sellos en el archivo, con el fin de restringir modificaciones posteriores en el archivo. (Si se coloca el sello F_SEAL_WRITE, será necesario primero desmapear el mapeo escribible compartido creado en el paso anterior. De lo contrario, un comportamiento similar a F_SEAL_WRITE se puede lograr utilizando F_SEAL_FUTURE_WRITE, que evitará que escrituras futuras a través de mmap(2) y write(2) tengan éxito, manteniendo al mismo tiempo los mapeos escribibles compartidos existentes).
(4)
Un segundo proceso obtiene un descriptor de archivo para el archivo tmpfs(5) y lo mapea. Entre las posibles formas en que esto podría suceder se encuentran las siguientes:
•
El proceso que llamó a memfd_create() podría transferir el descriptor de archivo resultante al segundo proceso a través de un socket de dominio UNIX (ver unix(7) y cmsg(3)). El segundo proceso mapea el archivo usando mmap(2).
•
El segundo proceso se crea a través de fork(2) y, por lo tanto, hereda automáticamente el descriptor de archivo y el mapeo. (Tenga en cuenta que en este caso y en el siguiente, existe una relación de confianza natural entre los dos procesos, ya que se ejecutan bajo el mismo ID de usuario. Por lo tanto, el sellado de archivos normalmente no sería necesario).
•
El segundo proceso abre el archivo /proc/pid/fd/fd, donde <pid> es el PID del primer proceso (el que llamó a memfd_create()), y <fd> es el número del descriptor de archivo devuelto por la llamada a memfd_create() en ese proceso. El segundo proceso luego mapea el archivo usando mmap(2).
(5)
El segundo proceso utiliza la operación F_GET_SEALS de fcntl(2) para recuperar la máscara de bits de sellos que se ha aplicado al archivo. Esta máscara de bits se puede inspeccionar para determinar qué tipos de restricciones se han impuesto a las modificaciones del archivo. Si se desea, el segundo proceso puede aplicar sellos adicionales para imponer restricciones adicionales (siempre que el sello F_SEAL_SEAL aún no se haya aplicado).

EJEMPLOS

A continuación se muestran dos programas de ejemplo que demuestran el uso de memfd_create() y la API de sellado de archivos.

El primer programa, t_memfd_create.c, crea un archivo tmpfs(5) usando memfd_create(), establece un tamaño para el archivo, lo mapea en memoria y, opcionalmente, aplica algunos sellos al archivo. El programa acepta hasta tres argumentos de línea de comandos, de los cuales los dos primeros son obligatorios. El primer argumento es el nombre a asociar con el archivo, el segundo argumento es el tamaño a establecer para el archivo, y el tercer argumento opcional es una cadena de caracteres que especifican los sellos a aplicar al archivo.

El segundo programa, t_get_seals.c, se puede usar para abrir un archivo existente que se creó a través de memfd_create() e inspeccionar el conjunto de sellos que se han aplicado a ese archivo.

La siguiente sesión de shell demuestra el uso de estos programas. Primero creamos un archivo tmpfs(5) y le aplicamos algunos sellos:


$ ./t_memfd_create mi_archivo_memfd 4096 sw &
[1] 11775
PID: 11775; fd: 3; /proc/11775/fd/3

En este punto, el programa t_memfd_create continúa ejecutándose en segundo plano. Desde otro programa, podemos obtener un descriptor de archivo para el archivo creado por memfd_create() abriendo el archivo /proc/pid/fd que corresponde al descriptor de archivo abierto por memfd_create(). Usando esa ruta, inspeccionamos el contenido del enlace simbólico /proc/pid/fd, y usamos nuestro programa t_get_seals para ver los sellos que se han aplicado al archivo:


$ readlink /proc/11775/fd/3;
/memfd:mi_archivo_memfd (deleted)
$ ./t_get_seals /proc/11775/fd/3;
Existing seals: WRITE SHRINK

Código fuente del programa: t_memfd_create.c

#define _GNU_SOURCE
#include <err.h>
#include <fcntl.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/mman.h>
#include <sys/types.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int           fd;
    char          *name, *seals_arg;
    ssize_t       size;
    unsigned int  seals;
    if (argc < 3) {
        fprintf(stderr, "%s name size [seals]\n", argv[0]);
        fprintf(stderr, "\t'seals' puede contener cualquiera de los caracteres siguientes:\n");
        fprintf(stderr, "\t\tg - F_SEAL_GROW\n");
        fprintf(stderr, "\t\ts - F_SEAL_SHRINK\n");
        fprintf(stderr, "\t\tw - F_SEAL_WRITE\n");
        fprintf(stderr, "\t\tW - F_SEAL_FUTURE_WRITE\n");
        fprintf(stderr, "\t\tS - F_SEAL_SEAL\n");
        exit(EXIT_FAILURE);
    }
    name = argv[1];
    size = atoi(argv[2]);
    seals_arg = argv[3];
    /* Crear un archivo anónimo en tmpfs; permitir que se apliquen sellos
       al archivo.  */
    fd = memfd_create(name, MFD_ALLOW_SEALING);
    if (fd == -1)
        err(EXIT_FAILURE, "memfd_create");
    /* Dimensionar el archivo según lo especificado en la línea de comandos.  */
    if (ftruncate(fd, size) == -1)
        err(EXIT_FAILURE, "truncate");
    printf("PID: %jd; fd: %d; /proc/%jd/fd/%d\n",
           (intmax_t) getpid(), fd, (intmax_t) getpid(), fd);
    /* Código para mapear el archivo y rellenar el mapeo con datos
       omitido.  */
    /* Si se proporcionó un argumento de línea de comandos 'seals', aplicar algunos
       sellos al archivo.  */
    if (seals_arg != NULL) {
        seals = 0;
        if (strchr(seals_arg, 'g') != NULL)
            seals |= F_SEAL_GROW;
        if (strchr(seals_arg, 's') != NULL)
            seals |= F_SEAL_SHRINK;
        if (strchr(seals_arg, 'w') != NULL)
            seals |= F_SEAL_WRITE;
        if (strchr(seals_arg, 'W') != NULL)
            seals |= F_SEAL_FUTURE_WRITE;
        if (strchr(seals_arg, 'S') != NULL)
            seals |= F_SEAL_SEAL;
        if (fcntl(fd, F_ADD_SEALS, seals) == -1)
            err(EXIT_FAILURE, "fcntl");
    }
    /* Seguir ejecutándose, para que el archivo creado por memfd_create()
       continúe existiendo.  */
    pause();
    exit(EXIT_SUCCESS);
}

Código fuente del programa: t_get_seals.c

#define _GNU_SOURCE
#include <err.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
int
main(int argc, char *argv[])
{
    int           fd;
    unsigned int  seals;
    if (argc != 2) {
        fprintf(stderr, "%s /proc/PID/fd/FD\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    fd = open(argv[1], O_RDWR);
    if (fd == -1)
        err(EXIT_FAILURE, "open");
    seals = fcntl(fd, F_GET_SEALS);
    if (seals == -1)
        err(EXIT_FAILURE, "fcntl");
    printf("Sellos existentes:");
    if (seals & F_SEAL_SEAL)
        printf(" SEAL");
    if (seals & F_SEAL_GROW)
        printf(" GROW");
    if (seals & F_SEAL_WRITE)
        printf(" WRITE");
    if (seals & F_SEAL_FUTURE_WRITE)
        printf(" FUTURE_WRITE");
    if (seals & F_SEAL_SHRINK)
        printf(" SHRINK");
    printf("\n");
    /* Código para mapear el archivo y acceder al contenido del
       mapeo resultante omitido.  */
    exit(EXIT_SUCCESS);
}
