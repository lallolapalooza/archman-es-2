memcached_cas_by_key(3)

Paquete: libmemcached-awesome

Licencias: BSD

MEMCACHED_CAS_BY_KEY(3) libmemcached-awesome MEMCACHED_CAS_BY_KEY(3)

NOMBRE

memcached_cas_by_key - Almacenamiento y Reemplazo de Datos

SINOPSIS

#include <libmemcached/memcached.h>
Compilar y enlazar con -lmemcached
memcached_return_t memcached_cas(memcached_st *ptr, const char *key, size_t key_length, const char *value, size_t value_length, time_t expiration, uint32_t flags, uint64_t cas)
memcached_return_t memcached_cas_by_key(memcached_st *ptr, const char *group_key, size_t group_key_length, const char *key, size_t key_length, const char *value, size_t value_length, time_t expiration, uint32_t flags, uint64_t cas)
Parámetros
  • ptr -- puntero a una estructura memcached_st inicializada
  • group_key -- namespace de clave
  • group_key_length -- longitud de la group_key sin ningún cero al final
  • key -- la clave a comprobar
  • key_length -- la longitud de la key sin ningún cero al final
  • value -- el valor a establecer
  • value_length -- la longitud del value sin ningún cero al final
  • expiration -- tiempo de expiración como marca de tiempo unix o tiempo relativo en segundos
  • flags -- flags de 16 bits
  • cas -- el valor cas a comparar
Retorna
memcached_return_t indicando éxito

DESCRIPCIÓN

memcached_cas() sobrescribe datos en el servidor siempre que el valor cas siga siendo el mismo en el servidor. Puedes obtener el valor cas de un resultado llamando a memcached_result_cas() en una estructura memcached_result_st.

El método memcached_cas_by_key() se comporta de manera similar a los métodos sin clave. La diferencia es que utiliza el parámetro group_key para mapear objetos a servidores particulares.

memcached_cas() se prueba con el comportamiento MEMCACHED_BEHAVIOR_USE_UDP habilitado. Sin embargo, al usar estas operaciones con este comportamiento activado, existen límites para el tamaño de la carga útil que se envía al servidor. La razón de estos límites es que el Servidor Memcached no permite solicitudes multidatagramas y la implementación actual del servidor establece un tamaño de datagrama de 1400 bytes. Debido a la sobrecarga del protocolo, el límite real de los datos proporcionados por el usuario es inferior a 1400 bytes y depende del protocolo en uso, así como de la operación que se esté ejecutando. Al ejecutarse con el protocolo binario, MEMCACHED_BEHAVIOR_BINARY_PROTOCOL, el tamaño combinado de la clave, valor, flags y expiración no puede exceder los 1368 bytes. Al ejecutarse con el protocolo ASCII, el límite exacto fluctúa dependiendo de qué función se esté ejecutando y de si la función es una operación cas o no. Para operaciones set ASCII no cas, hay al menos 1335 bytes disponibles para dividir entre la clave, la clave_prefijo y el valor; para operaciones cas ASCII hay al menos 1318 bytes disponibles para dividir entre la clave, la clave_prefijo y el valor. Si el tamaño total del comando, incluida la sobrecarga, excede los 1400 bytes, se devolverá un MEMCACHED_WRITE_FAILURE.

VALOR DE RETORNO

Todos los métodos devuelven un valor de tipo memcached_return_t. En caso de éxito, el valor será MEMCACHED_SUCCESS. Utilice memcached_strerror() para traducir este valor a una cadena imprimible.
