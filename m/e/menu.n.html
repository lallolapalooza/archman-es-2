Paquete: tk

menu(n) Comandos integrados de Tk menu(n)

NOMBRE

menu, tk_menuSetFocus - Crear y manipular widgets 'menu' y barras de menú

SINOPSIS

menu nombreRuta ?opciones?
tk_menuSetFocus nombreRuta

OPCIONES ESTÁNDAR

-activebackground	-borderwidth	-foreground
-activeborderwidth	-cursor	-relief
-activeforeground	-disabledforeground	-takefocus
-background	-font

Consulte la entrada del manual de options para obtener detalles sobre las opciones estándar.

OPCIONES ESPECÍFICAS DEL WIDGET

Nombre de línea de comandos:	-postcommand
Nombre de base de datos:	postCommand
Clase de base de datos:	Command
Si se especifica esta opción, proporciona un comando Tcl para ejecutar cada vez que se muestra el menú. El comando es invocado por el comando de widget post antes de mostrar el menú. Tenga en cuenta que en Tk 8.0 en Macintosh y Windows, todos los comandos post en un sistema de menús se ejecutan antes de que se muestre cualquiera de esos menús. Esto se debe a las limitaciones de los administradores de menús de las plataformas individuales.
Nombre de línea de comandos: -selectcolor
Nombre de base de datos: selectColor
Clase de base de datos: Background
Para las entradas de menú que son casillas de verificación o botones de radio, esta opción especifica el color que se mostrará en el indicador cuando la casilla de verificación o el botón de radio esté seleccionado.
Nombre de línea de comandos: -tearoff
Nombre de base de datos: tearOff
Clase de base de datos: TearOff
Esta opción debe tener un valor booleano válido, que especifica si el menú debe incluir o no una entrada para "arrancar" (tear-off) en la parte superior. Si es así, existirá como entrada 0 del menú y las demás entradas comenzarán a numerarse a partir de 1. Las vinculaciones de menú predeterminadas se encargan de que el menú se "arranque" cuando se invoca la entrada de "arrancar". Esta opción se ignora en Aqua/macOS, donde los menús no se pueden "arrancar".
Nombre de línea de comandos: -tearoffcommand
Nombre de base de datos: tearOffCommand
Clase de base de datos: TearOffCommand
Si esta opción tiene un valor no vacío, especifica un comando Tcl para invocar cada vez que se "arranca" un menú. El comando real consistirá en el valor de esta opción, seguido de un espacio, seguido del nombre de la ventana del menú, seguido de un espacio, seguido del nombre de la ventana del menú "arrancado". Por ejemplo, si el valor de la opción es “a b” y el menú .x.y se "arranca" para crear un nuevo menú .x.tearoff1, entonces se invocará el comando “a b .x.y .x.tearoff1”. Esta opción se ignora en Aqua/macOS, donde los menús no se pueden "arrancar".
Nombre de línea de comandos: -title
Nombre de base de datos: title
Clase de base de datos: Title
La cadena se utilizará para titular la ventana creada cuando se "arranque" este menú. Si el título es NULL, entonces la ventana tendrá el título del botón de menú o el texto del elemento de cascada desde el cual se invocó este menú.
Nombre de línea de comandos: -type
Nombre de base de datos: type
Clase de base de datos: Type
Esta opción puede ser menubar, tearoff o normal, y se establece al crear el menú. Aunque la cadena devuelta por la base de datos de configuración cambiará si se modifica esta opción, esto no afecta el comportamiento del widget de menú. Esto lo utiliza el mecanismo de clonación y normalmente no se establece fuera de la biblioteca Tk.

INTRODUCCIÓN

El comando menu crea una nueva ventana de nivel superior (dada por el argumento nombreRuta) y la convierte en un widget de menú. Ese widget de menú puede usarse como una ventana emergente o aplicarse a un toplevel (con su opción -menu) para convertirlo en la barra de menú de ese nivel superior. Se pueden especificar opciones adicionales, descritas anteriormente, en la línea de comandos o en la base de datos de opciones para configurar aspectos del menú, como sus colores y fuente. El comando menu devuelve su argumento nombreRuta. En el momento en que se invoca este comando, no debe existir ninguna ventana llamada nombreRuta, pero el padre de nombreRuta debe existir.

Un menú es un widget que muestra una colección de entradas de una sola línea dispuestas en una o más columnas. Existen varios tipos diferentes de entradas, cada una con propiedades diferentes. Se pueden combinar entradas de diferentes tipos en un solo menú. Las entradas de menú no son lo mismo que los widgets de entrada. De hecho, las entradas de menú ni siquiera son widgets distintos; todo el menú es un solo widget.

Las entradas de menú se muestran con hasta tres campos separados. El campo principal es una etiqueta en forma de cadena de texto, un bitmap o una imagen, controlado por las opciones -label, -bitmap e -image para la entrada. Si se especifica la opción -accelerator para una entrada, se mostrará un segundo campo de texto a la derecha de la etiqueta. El acelerador describe típicamente una secuencia de pulsaciones de teclas que se pueden usar en la aplicación para producir el mismo resultado que invocar la entrada del menú. Esta es una opción de visualización, no establece realmente la vinculación correspondiente (lo que se puede lograr usando el comando bind). El tercer campo es un indicador. El indicador está presente solo para las entradas de casilla de verificación (checkbutton) o de radio (radiobutton). Indica si la entrada está seleccionada o no, y se muestra a la izquierda de la cadena de la entrada.

En uso normal, una entrada se activa (se muestra de manera diferente) cada vez que el puntero del ratón está sobre la entrada. Si se suelta un botón del ratón sobre la entrada, esta se invoca. El efecto de la invocación es diferente para cada tipo de entrada; estos efectos se describen a continuación en las secciones sobre entradas individuales.

Las entradas pueden estar deshabilitadas, lo que hace que sus etiquetas y aceleradores se muestren con colores más tenues. Las vinculaciones de menú predeterminadas no permitirán que una entrada deshabilitada se active o invoque. Las entradas deshabilitadas pueden volver a habilitarse, momento en el cual será posible activarlas e invocarlas nuevamente.

Cada vez que se cambia la entrada activa de un menú, se envía un evento virtual <<MenuSelect>> al menú. Luego se puede consultar el elemento activo del menú y se puede tomar una acción, como establecer texto de ayuda sensible al contexto para la entrada.

TIPOS DE ENTRADAS

ENTRADAS DE COMANDO

El tipo más común de entrada de menú es una entrada de comando, que se comporta de manera similar a un widget de botón. Cuando se invoca una entrada de comando, se ejecuta un comando Tcl. El comando Tcl se especifica con la opción -command.

ENTRADAS SEPARADORAS

Un separador es una entrada que se muestra como una línea divisoria horizontal. Un separador no se puede activar ni invocar, y no tiene otro comportamiento más allá de su apariencia.

ENTRADAS DE CASILLA DE VERIFICACIÓN

Una entrada de menú de casilla de verificación se comporta de manera similar a un widget de casilla de verificación. Cuando se invoca, alterna entre los estados seleccionado y deseleccionado. Cuando la entrada está seleccionada, se almacena un valor particular en una variable global particular (según lo determinado por las opciones -onvalue y -variable para la entrada); cuando la entrada está deseleccionada, se almacena otro valor (determinado por la opción -offvalue) en la variable global. Se muestra un cuadro indicador a la izquierda de la etiqueta en una entrada de casilla de verificación. Si la entrada está seleccionada, el centro del indicador se muestra en el color dado por la opción -selectcolor para la entrada; de lo contrario, el centro del indicador se muestra en el color de fondo del menú. Si se especifica una opción -command para una entrada de casilla de verificación, su valor se evalúa como un comando Tcl cada vez que se invoca la entrada; esto ocurre después de alternar el estado seleccionado de la entrada.

Las entradas de botón de radio se organizan en grupos de los cuales solo una entrada puede estar seleccionada a la vez. ENTRIES

A menu entry is a widget that can be displayed inside a menu. The menu widget itself does not have many options; most of the control over the menu's appearance and behavior is done on a per-entry basis. There are five types of entries: cascade, checkbutton, command, radiobutton, and separator. In addition, menus may contain tear-off entries.

COMMAND ENTRIES

A command entry is the simplest type of entry. It consists of a label and, optionally, a command to execute when the entry is selected. When a command entry is selected, its associated command is evaluated. This happens after the menu is unposted.

CHECKBUTTON ENTRIES

A checkbutton entry is a toggle button. It has a label and an associated variable (typically a boolean variable). If the variable is set to a certain value (e.g., 1), the checkbutton is displayed in its selected state (typically with a checkmark); otherwise, it is displayed in its unselected state. The checkbutton's state is automatically updated whenever the variable changes. When the checkbutton is selected, its associated variable is set to the value specified by the -onvalue option, and when it is unselected, the variable is set to the value specified by the -offvalue option. If a -command option is specified for a checkbutton entry, then its value is evaluated as a Tcl command each time the entry is invoked; this happens after toggling the button's state.

RADIOBUTTON ENTRIES

A radiobutton entry is similar to a checkbutton, but it is used in groups. All radiobutton entries in a group share the same associated variable. When a radiobutton entry is selected, its associated variable is set to the value specified by the -value option for that entry. This action causes any previously-selected entry in the same group to deselect itself. Once an entry has become selected, any change to the entry's associated variable will cause the entry to deselect itself. Grouping of radiobutton entries is determined by their associated variables: if two entries have the same associated variable then they are in the same group. An indicator diamond is displayed to the left of the label in each radiobutton entry. If the entry is selected then the indicator's center is displayed in the color given by the -selectcolor option for the entry; otherwise the indicator's center is displayed in the background color for the menu. If a -command option is specified for a radiobutton entry, then its value is evaluated as a Tcl command each time the entry is invoked; this happens after selecting the entry.

CASCADE ENTRIES

A cascade entry is one with an associated menu (determined by the -menu option). Cascade entries allow the construction of cascading menus. The postcascade widget command can be used to post and unpost the associated menu just next to of the cascade entry. The associated menu must be a child of the menu containing the cascade entry (this is needed in order for menu traversal to work correctly).

A cascade entry posts its associated menu by invoking a Tcl command of the form

menu post x y
where menu is the path name of the associated menu, and x and y are the root-window coordinates of the upper-right corner of the cascade entry. On Unix, the lower-level menu is unposted by executing a Tcl command with the form 
menu unpost
where menu is the name of the associated menu. On other platforms, the platform's native code takes care of unposting the menu.

If a -command option is specified for a cascade entry then it is evaluated as a Tcl command whenever the entry is invoked. This is not supported on Windows.

TEAR-OFF ENTRIES

A tear-off entry appears at the top of the menu if enabled with the -tearoff option. It is not like other menu entries in that it cannot be created with the add widget command and cannot be deleted with the delete widget command. When a tear-off entry is created it appears as a dashed line at the top of the menu. Under the default bindings, invoking the tear-off entry causes a torn-off copy to be made of the menu and all of its submenus.

MENUBARS

Any menu can be set as a menubar for a toplevel window (see toplevel command for syntax). On the Macintosh, whenever the toplevel is in front, this menu's cascade items will appear in the menubar across the top of the main monitor. On Windows and Unix, this menu's items will be displayed in a menubar across the top of the window. These menus will behave according to the interface guidelines of their platforms. For every menu set as a menubar, a clone menu is made. See the CLONES section for more information.

As noted, menubars may behave differently on different platforms. One example of this concerns the handling of checkbuttons and radiobuttons within the menu. While it is permitted to put these menu elements on menubars, they may not be drawn with indicators on some platforms, due to system restrictions.

SPECIAL MENUS IN MENUBARS

Certain menus in a menubar will be treated specially. On the Macintosh, access to the special Application, Window and Help menus is provided. On Windows, access to the Windows System menu in each window is provided. On X Windows, a special right-justified help menu may be provided if Motif menu compatibility is enabled. In all cases, these menus must be created with the command name of the menubar menu concatenated with the special name. So for a menubar named .menubar, on the Macintosh, the special menus would be .menubar.apple, .menubar.window and .menubar.help; on Windows, the special menu would be .menubar.system; on X Windows, the help menu would be .menubar.help.

When Tk sees a .menubar.apple menu as the first menu in a menubar on the Macintosh, that menu's contents make up the first items of the Application menu whenever the window containing the menubar is in front. After all of the Tk-defined items, the menu will have a separator, followed by all standard Application menu items. Such a .apple menu must be present in a menu when that menu is first configured as a toplevel's menubar, otherwise a default application menu (hidden from Tk) will be inserted into the menubar at that time and subsequent addition of a .apple menu will no longer result in it becoming the Application menu.

When Tk sees a .menubar.window menu on the Macintosh, the menu's contents are inserted into the standard Window menu of the user's menubar whenever the window's menubar is in front. The first items in the menu are provided by macOS, and the names of the current toplevels are automatically appended after all the Tk-defined items and a separator. The Window menu on the Mac also allows toggling the window into a fullscreen state, and managing a tabbed window interface (multiple windows grouped into a single window) if supported by that version of the operating system.

When Tk sees a .menubar.help menu on the Macintosh, the menu's contents are appended to the standard Help menu of the user's menubar whenever the window's menubar is in front. The first items in the menu are provided by macOS.

When Tk sees a System menu on Windows, its items are appended to the system menu that the menubar is attached to. This menu is tied to the application icon and can be invoked with the mouse or by typing Alt+Spacebar. Due to limitations in the Windows API, any font changes, colors, images, bitmaps, or tearoff images will not appear in the system menu.

When Tk sees a Help menu on X Windows and Motif menu compatibility is enabled the menu is moved to be last in the menubar and is right justified. Motif menu compatibility is enabled by setting the Tk option *Menu.useMotifHelp to true or by calling tk::classic::restore menu.

CLONES

When a menu is set as a menubar for a toplevel window, or when a menu is torn off, a clone of the menu is made. This clone is a menu widget in its own right, but it is a child of the original. Changes in the configuration of the original are reflected in the clone. Additionally, any cascades that are pointed to are also cloned so that menu traversal will work right. Clones are destroyed when either the tearoff or menubar goes away, or when the original menu is destroyed.

WIDGET COMMAND

The menu command creates a new Tcl command whose name is pathName. This command may be used to invoke various operations on the widget. It has the following general form:

pathName option ?arg arg ...?
Option and the args determine the exact behavior of the command.

Many of the widget commands for a menu take as one argument an indicator of which entry of the menu to operate on. These indicators are called indexes and may be specified in any of the following forms:

active
Indicates the entry that is currently active. If no entry is active then this form is equivalent to none. This form may not be abbreviated.
end
Indicates the bottommost entry in the menu. If there are no entries in the menu then this form is equivalent to none. This form may not be abbreviated.
last
Same as end.
none
Indicates “no entry at all”; this is used most commonly with the activate option to deactivate all the entries in the menu. In most cases the specification of none causes nothing to happen in the widget command. This form may not be abbreviated.
@x,y
Indicates the entry that covers the point in the menu's window specified by x and y (in pixel coordinates). If no entry covers that point, then this form is equivalent to none. If only a single number is specified, it is treated as the y-coordinate.
number
Specifies the entry numerically, where 0 corresponds to the top-most entry of the menu, 1 to the entry below it, and so on.
pattern
If the index does not satisfy one of the above forms then this form is used. Pattern is pattern-matched against the label of each entry in the menu, in order from the top down, until a matching entry is found. The rules of string match are used.

If the index could match more than one of the above forms, then the form earlier in the above list takes precedence.

The following widget commands are possible for menu widgets:

pathName activate index
Change the state of the entry indicated by index to active and redisplay it using its active colors. Any previously-active entry is deactivated. If index is specified as none, or if the specified entry is disabled, then the menu ends up with no active entry. Returns an empty string.
pathName add type ?option value option value ...?
Add a new entry to the bottom of the menu. The new entry's type is given by type and must be one of cascade, checkbutton, command, radiobutton, or separator, or a unique abbreviation of one of the above. If additional arguments are present, they specify the options listed in the MENU ENTRY OPTIONS section below. The add widget command returns an empty string.

Esta opción anula las opciones -label y -bitmap (según lo controlado por la opción -compound) pero puede restablecerse a una cadena vacía para permitir que se muestre una etiqueta textual o de bitmap. Esta opción no está disponible para entradas de separador o de "tear-off".
-indicatoron valor
Disponible solo para entradas de tipo checkbutton y radiobutton. Valor es un booleano que determina si el indicador debe mostrarse o no.
-label valor
Especifica una cadena para mostrar como etiqueta identificativa en la entrada del menú. No disponible para entradas de separador o de "tear-off".
-menu valor
Disponible solo para entradas de tipo cascade. Especifica el nombre de ruta del submenú asociado con esta entrada. El submenú debe ser un hijo del menú.
-offvalue valor
Disponible solo para entradas de tipo checkbutton. Especifica el valor que se almacenará en la variable asociada de la entrada cuando la entrada se deseleccione.
-onvalue valor
Disponible solo para entradas de tipo checkbutton. Especifica el valor que se almacenará en la variable asociada de la entrada cuando la entrada se seleccione.
-selectcolor valor
Disponible solo para entradas de tipo checkbutton y radiobutton. Especifica el color que se mostrará en el indicador cuando la entrada esté seleccionada. Si el valor es una cadena vacía (el valor por defecto), entonces la opción -selectcolor del menú determina el color del indicador.
-selectimage valor
Disponible solo para entradas de tipo checkbutton y radiobutton. Especifica una imagen para mostrar en la entrada (en lugar de la opción -image) cuando esté seleccionada. Valor es el nombre de una imagen, que debe haber sido creada por alguna invocación previa de image create. Esta opción se ignora a menos que se haya especificado la opción -image.
-state valor
Especifica uno de los tres estados para la entrada: normal, active o disabled. En el estado normal, la entrada se muestra utilizando la opción -foreground para el menú y la opción -background de la entrada o del menú. El estado activo se utiliza típicamente cuando el puntero está sobre la entrada. En el estado activo, la entrada se muestra utilizando la opción -activeforeground para el menú junto con la opción -activebackground de la entrada. El estado deshabilitado significa que la entrada debe ser insensible: las vinculaciones por defecto se negarán a activar o invocar la entrada. En este estado, la entrada se muestra de acuerdo con la opción -disabledforeground para el menú y la opción -background de la entrada. Esta opción no está disponible para entradas de separador.
-underline valor
Especifica el índice entero de un carácter para subrayar en la entrada. Esta opción también es consultada por las vinculaciones por defecto y se usa para implementar la navegación por teclado. 0 corresponde al primer carácter del texto mostrado en la entrada, 1 al siguiente carácter, y así sucesivamente. Si se muestra un bitmap o una imagen en la entrada, esta opción se ignora. Esta opción no está disponible para entradas de separador o de "tear-off".
-value valor
Disponible solo para entradas de tipo radiobutton. Especifica el valor que se almacenará en la variable asociada de la entrada cuando la entrada se seleccione. Si se especifica una cadena vacía, entonces la opción -label de la entrada se usa como valor a almacenar en la variable.
-variable valor
Disponible solo para entradas de tipo checkbutton y radiobutton. Especifica el nombre de una variable global que se establecerá cuando la entrada se seleccione. Para las entradas de tipo checkbutton, la variable también se establece cuando la entrada se deselecciona. Para las entradas de tipo radiobutton, el cambio de la variable hace que la entrada actualmente seleccionada se deseleccione.

Para las entradas de tipo checkbutton, el valor por defecto de esta opción se toma de la opción -label, y para las entradas de tipo radiobutton se utiliza un único valor fijo. Se recomienda establecer siempre la opción -variable al crear una entrada de tipo checkbutton o radiobutton.

CONFIGURACIONES DE MENÚ

Las vinculaciones por defecto soportan cuatro formas diferentes de usar menús:

Menús Desplegables en Barra de Menús
Este es el caso más común. Creas un widget de menú que se convertirá en la barra de menús. Luego añades entradas de tipo cascade a este menú, especificando los menús desplegables que deseas usar en tu barra de menús. Luego creas todos los menús desplegables. Una vez que hayas hecho esto, especifica el menú usando la opción -menu del comando de widget del toplevel. Consulta la entrada del manual de toplevel para más detalles.
Menús Desplegables en Botones de Menú
Esta es la forma compatible de hacer barras de menús. Creas un widget menubutton por cada menú de nivel superior, y típicamente organizas una serie de menubuttons en fila en una ventana de barra de menús. También creas los menús de nivel superior y cualquier submenú en cascada, y los unes con las opciones -menu en los menubuttons y las entradas de menú en cascada. El menú de nivel superior debe ser un hijo del menubutton, y cada submenú debe ser un hijo del menú que lo referencia. Una vez que hayas hecho esto, las vinculaciones por defecto permitirán a los usuarios navegar e invocar el árbol de menús a través de su menubutton; consulta la entrada del manual de menubutton para más detalles.
Menús Emergentes
Los menús emergentes típicamente se muestran en respuesta a un clic de un botón del ratón o una pulsación de tecla. Creas los menús emergentes y cualquier submenú en cascada, luego llamas al procedimiento tk_popup en el momento apropiado para mostrar el menú de nivel superior.
Menús de Opciones
Un menú de opciones consiste en un menubutton con un menú asociado que te permite seleccionar uno de varios valores. El valor actual se muestra en el menubutton y también se almacena en una variable global. Usa el procedimiento tk_optionMenu para crear menubuttons de opciones y sus menús.
Menús "Arrastrables" (Torn-off)
Creas un menú "arrastrable" invocando la entrada de tipo tear-off en la parte superior de un menú existente. Las vinculaciones por defecto crearán un nuevo menú que es una copia del menú original y lo dejarán permanentemente mostrado como una ventana de nivel superior. El menú "arrastrable" se comporta igual que el menú original.

VINCULACIONES POR DEFECTO

Tk crea automáticamente vinculaciones de clase para los menús que les dan el siguiente comportamiento por defecto:

[1]
Cuando el ratón entra en un menú, la entrada debajo del cursor del ratón se activa; a medida que el ratón se mueve por el menú, la entrada activa cambia para seguir al ratón.
[2]
Cuando el ratón sale de un menú, todas las entradas del menú se desactivan, excepto en el caso especial en que el ratón se mueve de un menú a un submenú en cascada.
[3]
Cuando se suelta un botón sobre un menú, la entrada activa (si la hay) se invoca. El menú también se desoculta a menos que sea un menú "arrastrable".
[4]
Las teclas Espacio y Enter invocan la entrada activa y desocultan el menú.
[5]
Si alguna de las entradas de un menú tiene letras subrayadas con la opción -underline, al pulsar una de las letras subrayadas (o su equivalente en mayúscula o minúscula) se invoca esa entrada y se desoculta el menú.
[6]
La tecla Escape aborta una selección de menú en curso sin invocar ninguna entrada. También desoculta el menú a menos que sea un menú "arrastrable".
[7]
Las teclas Arriba y Abajo activan la entrada superior o inferior siguiente en el menú. Cuando se alcanza un extremo del menú, la entrada activa vuelve al otro extremo.
[8]
La tecla Izquierda se mueve al siguiente menú a la izquierda. Si el menú actual es un submenú en cascada, entonces el submenú se desoculta y la entrada de menú actual se convierte en la entrada de cascada en el padre. Si el menú actual es un menú de nivel superior mostrado desde un menubutton, entonces el menubutton actual se desoculta y el siguiente menubutton a la izquierda se muestra. De lo contrario, la tecla no tiene efecto. El orden de izquierda a derecha de los menubuttons se determina por su orden de apilamiento: Tk asume que el menubutton más bajo (que por defecto es el primero creado) está a la izquierda.
[9]
La tecla Derecha se mueve al siguiente menú a la derecha. Si la entrada actual es una entrada de cascada, entonces el submenú se muestra y la entrada de menú actual se convierte en la primera entrada del submenú. De lo contrario, si el menú actual se mostró desde un menubutton, entonces el menubutton actual se desoculta y el siguiente menubutton a la derecha se muestra.

Las entradas de menú deshabilitadas no responden: no se activan e ignoran las pulsaciones y liberaciones del botón del ratón.

Varias de las vinculaciones utilizan el comando tk_menuSetFocus. Guarda el foco actual y establece el foco en su argumento pathName, que es un widget de menú.

El comportamiento de los menús se puede cambiar definiendo nuevas vinculaciones para widgets individuales o redefiniendo las vinculaciones de clase.

MENUBARS

A menu widget can be used to create a menubar for a window. In this case, the menu is typically created with the tk(n) command and then associated with the toplevel window using the configure method. For example:

.       tk_menuBar .
        menu .m
        menu .m.file -tearoff 0
        menu .m.edit -tearoff 0
        .configure -menu .m
        .m add cascade -menu .m.file -label File
        .m add cascade -menu .m.edit -label Edit

The menu widget also supports the concept of pop-up menus. These are menus that appear when the user clicks a particular mouse button over a widget. These can be created and managed using the menu widget's add command command to invoke the tk_popup procedure.

CLONES

The menu command can be used to create clones of existing menus. This is done by specifying the name of an existing menu widget as the value for the -menu option when creating the new menu. This is useful for sharing menu definitions between different toplevel windows or parts of an application.

        set menubar_menu [.toplevel .t2]
        .t2 configure -menu $menubar_menu
        set menubar_menu_clone [$menubar_menu clone]
        .t2.m add cascade -menu $menubar_menu_clone -label AnotherMenu

WIDGET COMMAND

The menu command creates a new menu widget with the name pathName. The menu command is also the object-oriented command for existing menu widgets. It can be used to invoke various operations on the menu. The general form of the command is pathName option ?arg arg ...?. Available options are described below.

MENU ENTRY OPTIONS

The following options can be specified when adding entries to a menu:

  • -accelerator keys: Specifies a key sequence that will be displayed as an accelerator next to the menu entry.
  • -activebackground color: Specifies the background color for the menu entry when the mouse pointer is over it.
  • -activeforeground color: Specifies the foreground color for the menu entry when the mouse pointer is over it.
  • -background color: Specifies the background color for the menu entry.
  • -bitmap bitmapName: Displays a bitmap instead of text.
  • -command script: Specifies a script to be executed when the menu entry is selected.
  • -compound imageOrBitmap: Specifies how to combine an image or bitmap with text.
  • -font fontName: Specifies the font for the menu entry text.
  • -foreground color: Specifies the foreground color for the menu entry.
  • -image imageName: Displays an image instead of text.
  • -label text: Specifies the text label for the menu entry.
  • -menu menuName: Creates a cascade menu.
  • -offrelief relief: Specifies the relief for a checkbutton or radiobutton when it is turned off.
  • -onrelief relief: Specifies the relief for a checkbutton or radiobutton when it is turned on.
  • -selectcolor color: Specifies the color used to indicate that a checkbutton or radiobutton is selected.
  • -selectimage imageName: Specifies an image to be displayed when a checkbutton or radiobutton is selected.
  • -separatorrelief relief: Specifies the relief for a separator line.
  • -state state: Specifies whether the menu entry is normal, disabled, or active.
  • -underline index: Specifies the index of the character in the label that should be underlined for keyboard navigation.
  • -varyingrelief relief: Specifies the relief for a menu entry that changes based on its state.

MENU CONFIGURATIONS

The following options can be specified when configuring a menu widget:

  • -activebackground color: Specifies the background color for menu entries when the mouse pointer is over them.
  • -activeforeground color: Specifies the foreground color for menu entries when the mouse pointer is over them.
  • -background color: Specifies the background color of the menu.
  • -borderwidth borderWidth: Specifies the width of the border around the menu.
  • -font fontName: Specifies the default font for menu entries.
  • -foreground color: Specifies the default foreground color for menu entries.
  • -relief relief: Specifies the relief style for the menu.
  • -selectcolor color: Specifies the color used to indicate that a checkbutton or radiobutton is selected.
  • -tearoff boolean: Specifies whether the menu can be torn off.
  • -title text: Specifies the title for the menu (for use with menubars).

DEFAULT BINDINGS

The menu widget has default bindings that provide standard menu behavior. These bindings can be modified or overridden as needed.
