NOMBRE

meek-client - El plugin de transporte del cliente meek

SINOPSIS

meek-client [OPCIONES]

DESCRIPCIÓN

meek-client es un plugin de transporte para Tor que codifica un flujo como una secuencia de peticiones y respuestas HTTP. Tiene una opción url para controlar a qué servidor de destino se dirigen las peticiones, y una opción front para el camuflaje del nombre de dominio: El nombre de dominio en la URL se reemplaza por el dominio frontal antes de realizar la petición, pero la cabecera Host dentro de la petición HTTP sigue apuntando al dominio original. La idea es enmascarar a través de un dominio que no está bloqueado a un dominio que sí lo está.

CONFIGURACIÓN

La configuración de meek-client suele realizarse en un archivo torrc.

Las opciones por puente se configuran con argumentos SOCKS (pares clave=valor en una línea Bridge). Los argumentos SOCKS posibles son:

url=URL (requerido)

La URL de una instancia de meek-server. El componente del nombre de dominio será típicamente ocultado por el valor del argumento front.

front=DOMINIO

Nombre de dominio frontal. Si se proporciona, este nombre de dominio reemplazará al nombre de dominio de url en la petición DNS y en el campo SNI de TLS. El dominio real de la URL seguirá apareciendo en la cabecera Host de las peticiones HTTP.

utls=CLIENTHELLOID

Utiliza la biblioteca uTLS con la huella digital TLS nombrada para el camuflaje de TLS. Este argumento es incompatible con la opción de línea de comandos --helper. Los valores posibles de CLIENTHELLOID son:

•HelloFirefox_56
•HelloFirefox_63
•HelloFirefox_65
•HelloFirefox_99
•HelloFirefox_102
•HelloFirefox_105
•HelloFirefox_Auto = HelloFirefox_105
•HelloChrome_58
•HelloChrome_62
•HelloChrome_70
•HelloChrome_72

Como caso especial, los valores "none" y "HelloGolang" se reconocen como alias para omitir el argumento SOCKS utls; es decir, usar TLS nativo de Go.

Para compatibilidad con versiones anteriores, cada argumento SOCKS también tiene una opción equivalente en la línea de comandos. Por ejemplo, esta configuración usando argumentos SOCKS:

Bridge meek 0.0.2.0:1 url=https://forbidden.example/ front=allowed.example
ClientTransportPlugin meek exec ./meek-client

es lo mismo que esta usando opciones de línea de comandos:

Bridge meek 0.0.2.0:1
ClientTransportPlugin meek exec ./meek-client --url=https://forbidden.example/ --front=allowed.example

Se prefieren los argumentos SOCKS a las opciones de línea de comandos porque permiten tener múltiples líneas Bridge con diferentes configuraciones. Si se proporciona un argumento SOCKS y una opción de línea de comandos para la misma configuración, el argumento SOCKS tiene precedencia.

La opción global --helper evita que meek-client realice operaciones de red por sí mismo. En su lugar, enviará todas las peticiones a través de una extensión del navegador, que debe configurarse por separado.

Se puede configurar un proxy global (que se aplica a todas las líneas Bridge) utilizando opciones especiales de torrc:

Socks4Proxy localhost:1080
Socks5Proxy localhost:1080
Socks5ProxyUsername username
Socks5ProxyPassword password
HTTPSProxy localhost:8080
HTTPSProxyAuthenticator username:password

o, de manera equivalente, utilizando la opción de línea de comandos --proxy. La opción de línea de comandos tiene precedencia.

Cuando se utiliza la opción --helper, se pueden usar proxies de tipo http, socks4a o socks5, pero no se puede usar nombre de usuario o contraseña con el proxy. Sin --helper, se pueden usar proxies de tipo http, https o socks5, y opcionalmente se puede usar un nombre de usuario y contraseña.

OPCIONES

--front=DOMINIO

Nombre de dominio frontal. Prefiere usar el argumento SOCKS front en una línea bridge sobre usar esta opción de línea de comandos.

--helper=DIRECCIÓN

Dirección de la extensión del navegador HTTP helper. Por ejemplo, --helper=127.0.0.1:7000.

--proxy=URL

URL del proxy ascendente. Por ejemplo, --proxy=http://localhost:8080/, --proxy=socks4a://localhost:1080, o --proxy=socks5://localhost:1080. También se puede configurar usando las opciones HTTPSProxy, Socks4Proxy o Socks5Proxy en un archivo torrc.

--log=NOMBRE_ARCHIVO

Nombre de un archivo al que escribir los mensajes de registro (por defecto stderr).

--url=URL

URL con la que corresponder. Prefiere usar el argumento SOCKS url en una línea bridge sobre usar esta opción de línea de comandos.

--utls=CLIENTHELLOID

Utiliza uTLS con la huella digital TLS dada para el camuflaje de TLS. Esta opción es incompatible con --helper. Prefiere usar el argumento SOCKS utls sobre usar esta opción de línea de comandos.

-h, --help

Muestra un mensaje de ayuda y sale.
