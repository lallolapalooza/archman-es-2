memcached_append_by_key(3)

Paquete: libmemcached-awesome

Licencias: BSD

MEMCACHED_APPEND_BY_KEY(3) libmemcached-awesome MEMCACHED_APPEND_BY_KEY(3)

NOMBRE

memcached_append_by_key - Añadir o Prefijar Datos

SINOPSIS

#include <libmemcached-1.0/memcached.h>
Compilar y enlazar con -lmemcached
memcached_return_t memcached_prepend(memcached_st *ptr, const char *key, size_t key_length, const char *value, size_t value_length, time_t expiration, uint32_t flags)
memcached_return_t memcached_append(memcached_st *ptr, const char *key, size_t key_length, const char *value, size_t value_length, time_t expiration, uint32_t flags)
memcached_return_t memcached_prepend_by_key(memcached_st *ptr, const char *group_key, size_t group_key_length, const char *key, size_t key_length, const char *value, size_t value_length, time_t expiration, uint32_t flags)
memcached_return_t memcached_append_by_key(memcached_st *ptr, const char *group_key, size_t group_key_length, const char *key, size_t key_length, const char *value, size_t value_length, time_t expiration, uint32_t flags)
Parámetros
  • ptr -- puntero a una estructura memcached_st inicializada
  • group_key -- espacio de nombres de la clave
  • group_key_length -- longitud del espacio de nombres de la clave sin ningún cero terminador
  • key -- la clave
  • key_length -- longitud de la clave sin ningún cero terminador
  • value -- el valor a añadir/prefijar
  • value_length -- la longitud del valor sin ningún cero terminador
  • expiration -- expiración como marca de tiempo unix o como tiempo de expiración relativo en segundos
  • flags -- flags de 16 bits
Devuelve
memcached_return_t indicando éxito

DESCRIPCIÓN

memcached_prepend() y memcached_append se utilizan para modificar información en un servidor. Todos los métodos toman una clave y una longitud de clave para almacenar el objeto. Las claves están actualmente limitadas a 250 caracteres cuando se utiliza una versión de memcached que es 1.4 o inferior, o cuando se utiliza el protocolo de texto. Debe proporcionar tanto un valor como una longitud. Opcionalmente, puede establecer un tiempo de expiración para el objeto y un valor de 16 bits (está pensado para ser utilizado como un mapa de bits). flags es un espacio de 4 bytes que se almacena junto con el valor principal. Muchas subbibliotecas hacen uso de este campo, por lo que en la mayoría de los casos los usuarios deben evitar hacer uso de él.

memcached_prepend() coloca un segmento de datos antes de la última pieza de datos almacenada. Actualmente, la expiración y la clave no se utilizan en el servidor.

memcached_append() coloca un segmento de datos al final de la última pieza de datos almacenada. Actualmente, la expiración y la clave no se utilizan en el servidor.

Los métodos memcached_prepend_by_key() y memcached_append_by_key() se comportan de manera similar a los métodos sin clave. La diferencia es que utilizan su parámetro group_key para mapear objetos a servidores particulares.

Si busca rendimiento, memcached_set() con E/S no bloqueante es la forma más rápida de almacenar datos en el servidor.

Todas las funciones anteriores se prueban con el comportamiento MEMCACHED_BEHAVIOR_USE_UDP habilitado. Sin embargo, al utilizar estas operaciones con este comportamiento activado, existen límites para el tamaño de la carga útil que se envía al servidor. La razón de estos límites es que el servidor Memcached no permite solicitudes multidatagrama y la implementación actual del servidor establece un tamaño de datagrama de 1400 bytes. Debido a la sobrecarga del protocolo, el límite real de los datos proporcionados por el usuario es inferior a 1400 bytes y depende del protocolo en uso, así como de la operación que se esté ejecutando. Al ejecutar con el protocolo binario, MEMCACHED_BEHAVIOR_BINARY_PROTOCOL, el tamaño combinado de la clave, el valor, las flags y la caducidad no puede exceder los 1368 bytes. Al ejecutar con el protocolo ASCII, el límite exacto fluctúa dependiendo de la función que se esté ejecutando y de si la función es una operación cas o no. Para operaciones set ASCII no cas, hay al menos 1335 bytes disponibles para repartir entre la clave, el prefijo de clave y el valor; para operaciones cas ASCII hay al menos 1318 bytes disponibles para repartir entre la clave, el prefijo de clave y el valor. Si el tamaño total del comando, incluida la sobrecarga, excede los 1400 bytes, se devolverá MEMCACHED_WRITE_FAILURE.

VALOR DE RETORNO

Todos los métodos devuelven un valor de tipo memcached_return_t. En caso de éxito, el valor será MEMCACHED_SUCCESS.

Utilice memcached_strerror() para traducir este valor a una cadena imprimible.
