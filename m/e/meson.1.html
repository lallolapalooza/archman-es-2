MESON(1) Comandos de usuario MESON(1)

NOMBRE

meson - un sistema de compilación de alta productividad

DESCRIPCIÓN

Meson es un sistema de compilación diseñado para optimizar la productividad del programador. Su objetivo es lograr esto proporcionando soporte simple y listo para usar para herramientas y prácticas de desarrollo de software modernas, como pruebas unitarias, informes de cobertura, Valgrind, Ccache y similares.

El ejecutable principal de Meson proporciona muchos subcomandos para acceder a toda la funcionalidad.

El comando setup

Usar Meson es simple y sigue el proceso común de dos fases de la mayoría de los sistemas de compilación. Primero, ejecutas Meson para configurar tu compilación:

meson setup [ opciones ] [ directorio de compilación ] [ directorio fuente ]

Ten en cuenta que el directorio de compilación debe ser diferente del directorio fuente. Meson no admite la compilación dentro del directorio fuente e intentar hacerlo genera un error.

Después de un paso de configuración exitoso, puedes compilar el código fuente ejecutando el comando de compilación real en el directorio de compilación. El backend predeterminado de Meson es Ninja, que se puede invocar de la siguiente manera.

ninja [ objetivo ]

Solo necesitas ejecutar el comando Meson una vez: cuando configuras por primera vez tu directorio de compilación. Después de eso, simplemente ejecutas el comando de compilación. Meson detectará automáticamente los cambios en tu árbol fuente y regenerará todos los archivos necesarios para compilar el proyecto.

Meson incluye muchas opciones integradas que se pueden usar para ajustar la configuración de un directorio de compilación; los proyectos también pueden agregar sus propias opciones. Para establecer valores para las opciones, usa el argumento de línea de comandos -D de la siguiente manera:

meson setup -Dopt1=valor1 -Dopt2=valor2 resto de la línea de comandos...

opciones:

--version
imprime el número de versión
--help
imprime la ayuda de la línea de comandos

El comando configure

meson configure proporciona una forma de configurar un proyecto Meson desde la línea de comandos. Su uso es simple:

meson configure [ directorio de compilación ] [ opciones a establecer ]

Si se omite el directorio de compilación, se usa el directorio actual en su lugar.

Si no se establecen parámetros, meson configure imprimirá el valor de todas las opciones de compilación en la consola.

Para establecer valores, usa el argumento de línea de comandos -D de la siguiente manera.

meson configure -Dopt1=valor1 -Dopt2=valor2

El comando dist

meson dist genera un archivo de lanzamiento.

meson dist [ opciones ]

opciones:

-h, --help
muestra este mensaje de ayuda y sale
-C WD
directorio en el que cambiarse antes de ejecutar
--allow-dirty
Permitir incluso cuando el repositorio contiene cambios no confirmados.
--formats FORMATOS
Lista separada por comas de los tipos de archivo a crear. Admite xztar (predeterminado), gztar y zip.
--include-subprojects
Incluir el código fuente de subproyectos que se han utilizado para la compilación.
--no-tests
No compilar ni probar los paquetes generados.

El comando install

meson install instala el proyecto.

meson install [ opciones ]

opciones:

-h, --help
muestra este mensaje de ayuda y sale
-C WD
directorio en el que cambiarse antes de ejecutar
--no-rebuild
No recompilar antes de instalar.
--only-changed
Solo sobrescribir archivos que sean más antiguos que el archivo copiado.
--quiet
No imprimir cada archivo que se instaló.
--destdir DESTDIR
Establece o anula el entorno DESTDIR. (Desde 0.57.0)
--dry-run, -n
No instala realmente, pero imprime registros. (Desde 0.57.0)
--skip-subprojects [SKIP_SUBPROJECTS]
No instalar archivos de subproyectos dados. (Desde 0.58.0)
--tags TAGS
Instalar solo objetivos que tengan una de las etiquetas dadas. (Desde 0.60.0)
--strip
Eliminar símbolos de objetivos incluso si la opción de eliminación no se estableció durante la configuración. (Desde 0.62.0)

El comando introspect

Meson introspect es un comando diseñado para facilitar la integración con otras herramientas, como los IDE. La salida de este comando está en JSON.

meson introspect [ directorio de compilación ] [ opción ]

Si se omite el directorio de compilación, se usa el directorio actual en su lugar.

opciones:

--targets
imprime todos los objetivos de nivel superior (ejecutables, bibliotecas, etc.)
--target-files
imprime los archivos fuente del objetivo dado
--buildsystem-files
imprime todos los archivos que componen el sistema de compilación (meson.build, meson.options, meson_options.txt, etc.)
--tests
imprime todas las pruebas unitarias
--help
imprime la ayuda de la línea de comandos

El comando init

meson init crea un nuevo proyecto

meson init [ opciones ] [ archivo fuente... ]

argumentos posicionales:

archivo fuente...
archivos fuente. predeterminado: todos los archivos reconocidos en el directorio actual

opciones:

-h, --help
muestra este mensaje de ayuda y sale
-C WD
directorio en el que cambiarse antes de ejecutar
-n NOMBRE, --name NOMBRE
nombre del proyecto. predeterminado: nombre del directorio actual
-e EJECUTABLE, --executable EJECUTABLE
nombre del ejecutable. predeterminado: nombre del proyecto
-d DEPS, --deps DEPS
dependencias, separadas por comas
-l {c,cpp,cs,cuda,d,fortran,java,objc,objcpp,rust,vala}, --language {c,cpp,cs,cuda,d,fortran,java,objc,objcpp,rust,vala}
idioma del proyecto. predeterminado: autodetección basada en archivos fuente
-b, --build
compilar después de generar

--builddir BUILDDIR

directorio para la compilación

-f, --force

forzar la sobrescritura de archivos y directorios existentes.

--type {executable,library}

tipo de proyecto. por defecto: proyecto basado en ejecutable

--version VERSION

versión del proyecto. por defecto: 0.1

El comando test

meson test es una herramienta auxiliar para ejecutar conjuntos de pruebas de proyectos que usan Meson. La forma predeterminada de ejecutar pruebas es invocar el comando de compilación predeterminado:

ninja [ test ]

meson test proporciona un conjunto más rico de herramientas para invocar pruebas.

meson test reconstruye automáticamente los destinos necesarios para ejecutar pruebas cuando se usa con el backend de Ninja. Tras un fallo en la compilación, meson test devolverá un código de salida de 125. Este código de salida indica a git bisect run que omita la commit actual. Por lo tanto, la bisectividad usando git se puede hacer convenientemente de esta manera.

git bisect run meson test -C build_dir

opciones:

--repeat
ejecutar pruebas tantas veces como se especifique
--gdb
ejecutar pruebas bajo gdb
--list
listar todas las pruebas disponibles
--wrapper
invocar todas las pruebas a través del envoltorio dado (por ejemplo, valgrind)
-C
cambiar al directorio dado antes de ejecutar las pruebas (debe ser la raíz del directorio de compilación).
--suite
ejecutar pruebas en este conjunto
--no-suite
no ejecutar pruebas en este conjunto
--no-stdsplit
no dividir stderr y stdout en los registros de pruebas
--benchmark
ejecutar benchmarks en lugar de pruebas
--logbase
base del nombre de archivo a utilizar para escribir los registros de pruebas
--num-processes
cuántos procesos paralelos usar para ejecutar pruebas
--verbose
no redirigir stdout y stderr
-t
un multiplicador para usar en los valores de tiempo de espera de las pruebas (generalmente algo como 100 para Valgrind)
--setup
usar la configuración de prueba especificada --slice SLICE/NUM_SLICES Dividir las pruebas en NUM_SLICES partes y ejecutar la parte número SLICE. (Desde 1.8.0)

El comando wrap

Wraptool es una utilidad auxiliar para gestionar dependencias fuente utilizando el servicio en línea wrapdb.

meson wrap < comando > [ opciones ]

Debe ejecutar este comando en el directorio fuente de nivel superior de su proyecto.

Comandos:

list
listar todos los proyectos disponibles
search
buscar proyectos por nombre
install
instalar un proyecto con el nombre dado
update
actualizar el proyecto especificado a la última versión disponible
info
mostrar versiones disponibles del proyecto especificado
status
mostrar versiones instaladas y disponibles de subproyectos usados actualmente

El comando subprojects

meson subprojects se utiliza para gestionar subproyectos.

meson subprojects [ opciones ] [ comando ]

opciones:

-h, --help
mostrar este mensaje de ayuda y salir

comandos:

update
Actualizar todos los subproyectos desde archivos wrap
checkout
Hacer checkout de una rama (solo git)
download
Asegurar que los subproyectos se descargan, incluso si no están en uso. Los subproyectos ya descargados no se modifican. Esto se puede usar para pre-descargar todos los subproyectos y evitar descargas durante la configuración.
foreach
Ejecutar un comando en cada directorio de subproyecto.
purge
Eliminar todos los artefactos de subproyectos basados en wrap
packagefiles
Gestionar la superposición de packagefiles

El comando compile

meson compile compila el proyecto.

meson compile [ opciones ] [ TARGET... ]

argumentos posicionales:

TARGET
Objetivos a compilar. Target tiene el siguiente formato: [PATH_TO_TARGET/]TARGET_NAME.TARGET_SUFFIX[:TARGET_TYPE].

opciones:

-h, --help
mostrar este mensaje de ayuda y salir
--clean
Limpiar el directorio de compilación.
-C WD
directorio en el que entrar antes de ejecutar
-j JOBS, --jobs JOBS
El número de trabajos de trabajador a ejecutar (si es compatible). Si el valor es menor que 1, el programa de compilación lo adivinará.
-l LOAD_AVERAGE, --load-average LOAD_AVERAGE
La carga promedio del sistema que se intentará mantener (si es compatible).
-v, --verbose
Mostrar más información detallada.
--ninja-args NINJA_ARGS
Argumentos a pasar a `ninja` (aplicado solo en el backend `ninja`).
--vs-args VS_ARGS
Argumentos a pasar a `msbuild` (aplicado solo en el backend `vs`).
--xcode-args XCODE_ARGS
Argumentos a pasar a `xcodebuild` (aplicado solo en el backend `xcode`).

NAME

meson - build system

DESCRIPTION

Meson is a fast, C/C++/Rust build system that aims to be simple to use, and fast.

This manual page describes the commands that Meson provides. Most commands take configuration files such as meson.build and meson_options.txt as input.

The setup command

meson setup sets up a build directory. This is the primary command to use.

meson setup [ options ] [ sourcedir ] builddir

options:

-h, --help
show this help message and exit
-w, --warning-level LEVEL
Set compiler warning level (0..4). Default is 2.
-W, --buildtype BUILDTYPE
Set build type: 'plain', 'debug', 'debugoptimized', 'release', 'minsizerel'. Default is 'debugoptimized'.
-D OPTION=VALUE
Set build option.
-f
Force setup even if build directory is not empty.
-b
Use the best available compiler.
-v
Use the fallback compiler.
-a
Use the alternative compiler.
-C CONNECTION_STRING
Use a cross file to specify cross compilation settings.
-N NATIVE_FILE
Use a native file to specify native compilation settings.
-p
Print the compiler command line.
-j N
Use N threads to compile.
-k
Continue as much as possible after a compilation error.

The configure command

meson configure changes build options of an existing build directory.

meson configure [ options ] builddir

options:

-h, --help
show this help message and exit
-D OPTION=VALUE
Set build option.
-b
List available build options.

The dist command

meson dist creates a source distribution.

meson dist [ options ] builddir

options:

-h, --help
show this help message and exit
-c COMMITS
Specifies the commits to include in the distribution.
-m MAX_COMMITS
Specifies the maximum number of commits to include.
-o OUTPUT_DIR
Specifies the output directory.

-o OUTPUT, --output OUTPUT
output file (implies having exactly one input)

When no command is specified

If you run Meson without a subcommand, it will assume you meant meson setup. However, this syntax is deprecated, and Meson will print a warning message if it is used. You should always use meson setup explicitly, instead of relying on the default.
