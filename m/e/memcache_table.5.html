NOMBRE

memcache_table - Configuración del cliente memcache de Postfix

SINOPSIS

postmap -q "cadena" memcache:/etc/postfix/nombre_archivo
postmap -q - memcache:/etc/postfix/nombre_archivo <archivo_entrada

DESCRIPCIÓN


El sistema de correo Postfix utiliza tablas opcionales para la reescritura de direcciones o el enrutamiento de correo. Estas tablas suelen estar en formato dbm o db.

Alternativamente, las tablas de búsqueda pueden especificarse como instancias de memcache. Para usar búsquedas de memcache, defina una fuente de memcache como una tabla de búsqueda en main.cf, por ejemplo:

    virtual_alias_maps = memcache:/etc/postfix/memcache-aliases.cf

El archivo /etc/postfix/memcache-aliases.cf tiene el mismo formato que el archivo main.cf de Postfix y especifica los parámetros descritos a continuación.

El cliente memcache de Postfix soporta las operaciones de búsqueda, actualización, eliminación y secuencia (primero/siguiente). La operación de secuencia requiere una base de datos de respaldo que soporte la operación.

PARÁMETROS PRINCIPALES DE MEMCACHE

memcache (por defecto: inet:localhost:11211)
El servidor memcache (nota: singular) al que Postfix intentará conectarse. Para un servidor TCP, especifique "inet:" seguido de un nombre de host o dirección, ":", y un nombre o número de puerto. Especifique una dirección IPv6 dentro de "[]". Para un servidor de dominio UNIX, especifique "unix:" seguido de la ruta del socket. Ejemplos: 
    memcache = inet:memcache.example.com:11211
    memcache = inet:127.0.0.1:11211
    memcache = inet:[fc00:8d00:189::3]:11211
    memcache = unix:/path/to/socket

NOTA: para acceder a un socket de dominio UNIX con el servidor proxymap(8), el socket debe ser accesible por el usuario no privilegiado postfix.

backup (por defecto: indefinido)
Una base de datos Postfix opcional que proporciona respaldo persistente para la base de datos memcache. El cliente memcache de Postfix actualizará la base de datos memcache cada vez que busque o modifique información en la base de datos persistente. Especifique una base de datos Postfix de tipo "type:table". Ejemplos: 
    # Caché postscreen no compartida.
    backup = btree:/var/lib/postfix/postscreen_cache_map
    # Caché postscreen compartida para procesos en el mismo host.
    backup = proxy:btree:/var/lib/postfix/postscreen_cache_map

El acceso a servidores remotos proxymap está en desarrollo.

NOTA 1: Al compartir una caché persistente de postscreen(8) o verify(8), deshabilite la limpieza automática de la caché (establezca *_cache_cleanup_interval = 0) excepto con una instancia de Postfix que será responsable de la limpieza de la caché.

NOTA 2: Cuando varias tablas comparten la misma base de datos memcache, cada tabla debe usar la característica key_format (ver más abajo) para anteponer su propia cadena única a la clave de búsqueda. De lo contrario, la limpieza automática de caché de postscreen(8) o verify(8) puede no funcionar.

NOTA 3: Cuando la base de datos de respaldo se accede con búsquedas "proxy:", el nombre completo de la base de datos de respaldo (incluyendo el prefijo "proxy:") debe especificarse en la configuración proxy_read_maps o proxy_write_maps del servidor proxymap (dependiendo de si el acceso es de solo lectura o de lectura/escritura).

flags (por defecto: 0)
Banderas opcionales que deben almacenarse junto con una actualización de memcache. Las banderas se ignoran al buscar información.
ttl (por defecto: 3600)
El tiempo de expiración en segundos de las actualizaciones de memcache.

NOTA 1: Al usar una tabla memcache como caché de postscreen(8) o verify(8) sin respaldo persistente, especifique un valor *_cache_cleanup_interval cero con todas las instancias de Postfix que usan memcache, y especifique el valor *_ttl de postscreen(8) o *_expire_time de verify(8) más grande como el valor ttl de la tabla memcache.

NOTA 2: Según la documentación del protocolo memcache, un valor mayor a 30 días (2592000 segundos) especifica la hora UNIX absoluta. Valores más pequeños son relativos a la hora de la actualización.

PARÁMETROS DE CLAVE DE MEMCACHE

key_format (por defecto: %s)
Formato de las claves de búsqueda y actualización que el cliente memcache de Postfix envía al servidor memcache. Por defecto, son las mismas que las claves de búsqueda y actualización que el cliente memcache recibe de las aplicaciones Postfix.

NOTA 1: La característica key_format no se utiliza para las solicitudes a la base de datos de respaldo.

NOTA 2: Cuando varias tablas comparten la misma base de datos memcache, cada tabla debe anteponer su propia cadena única a la clave de búsqueda. De lo contrario, la limpieza automática de caché de postscreen(8) o verify(8) puede no funcionar.

Ejemplos:

    key_format = aliases:%s
    key_format = verify:%s
    key_format = postscreen:%s

El parámetro key_format soporta las siguientes expansiones '%':

%%
Esto se reemplaza por un carácter literal '%'.
%s
Esto se reemplaza por la clave de entrada del cliente memcache.
%u
Cuando la clave de entrada es una dirección del tipo usuario@dominio, %u se reemplaza por la parte local de la dirección, entre comillas SQL. De lo contrario, %u se reemplaza por toda la cadena de búsqueda. Si la parte local está vacía, una búsqueda se suprime silenciosamente y no devuelve resultados (una actualización se omite con una advertencia).
%d
Cuando la clave de entrada es una dirección del tipo usuario@dominio, %d se reemplaza por la parte del dominio de la dirección. De lo contrario, una búsqueda se suprime silenciosamente y no devuelve resultados (una actualización se omite con una advertencia).
%[SUD]
Los equivalentes en mayúsculas de las expansiones anteriores se comportan en el parámetro key_format de forma idéntica a sus contrapartes en minúsculas.
%[1-9]
Los patrones %1, %2, ... %9 se reemplazan por el componente más significativo correspondiente del dominio de la clave de entrada. Si la clave de entrada es usuario@mail.example.com, entonces %1 es com, %2 es example y %3 es mail. Si la clave de entrada no está calificada o no tiene suficientes componentes de dominio para satisfacer todos los patrones especificados, una búsqueda se suprime silenciosamente y no devuelve resultados (una actualización se omite con una advertencia).
domain (por defecto: sin lista de dominios)
Esta característica puede reducir significativamente la carga del servidor de base de datos. Especifique una lista de nombres de dominio, rutas a archivos o bases de datos "type:table". Cuando se especifica, solo las claves completamente calificadas con una parte local *no vacía* y un dominio coincidente son elegibles para búsqueda o actualización: las búsquedas de 'usuario' simples, las búsquedas de dominio simples y las búsquedas de "@dominio" se omiten silenciosamente (las actualizaciones se omiten con una advertencia). Ejemplo: 
    domain = example.com, hash:/etc/postfix/searchdomains

CONTROLES DE ERRORES DE MEMCACHE

data_size_limit (por defecto: 10240)
La longitud máxima de datos de respuesta de memcache en bytes.
line_size_limit (por defecto: 1024)
La longitud máxima de línea de respuesta de memcache en bytes.
max_try (por defecto: 2)
El número de veces que se intenta un comando memcache antes de rendirse. El cliente memcache no reintenta un comando cuando el servidor memcache no acepta conexión.
retry_pause (por defecto: 1)
El tiempo en segundos antes de reintentar un comando memcache fallido.
timeout (por defecto: memcache_table(5) — Postfix manual pages

NOMBRE

memcache_table - Postfix interfaz de tabla de búsqueda de memcache

SINOPSIS

       /etc/postfix/main.cf:
           memcache:/ruta/a/tu/socket,alias1,alias2,...
           memcache:/ruta/a/tu/socket?timeout=300&max_memcache_connections=10

       /etc/postfix/master.cf:
           memcache_table     unix  -       -       n       -       -       lmtp
           memcache_table     inet  n       -       n       -       -       smtpd

DESCRIPCIÓN

El tipo de tabla de búsqueda memcache: permite que Postfix acceda a datos de búsqueda almacenados en uno o más servidores memcache. Los datos se almacenan en formato de par clave-valor, donde la clave es el dato de entrada buscado y el valor es el/los resultado/s deseado/s.

La sintaxis del parámetro de configuración para el tipo de tabla memcache: es la siguiente:

memcache:servidor [,alias]...

servidor es la dirección de red (host:puerto o dirección IPv4/IPv6) de un servidor memcache, o una ruta de socket de dominio Unix si el servidor memcache está ejecutándose en la máquina local. Si no se especifica un puerto, se usará el puerto predeterminado de memcache (11211).

Es posible especificar múltiples servidores memcache separados por comas. Si se especifican múltiples servidores, Postfix intentará conectarse a ellos en orden. Si un servidor no está disponible, intentará con el siguiente.

El parámetro opcional alias permite asignar un alias a un servidor memcache. Esto es útil si desea utilizar diferentes configuraciones (por ejemplo, diferentes tiempos de espera) para el mismo servidor memcache. Si se usa un alias, la sintaxis es memcache:servidor?parametro=valor[,alias]... Los parámetros disponibles son:

  • timeout: Tiempo de espera en segundos para enviar un comando memcache y recibir una respuesta. El valor predeterminado es 60 segundos.
  • max_memcache_connections: Número máximo de conexiones al servidor memcache. El valor predeterminado es 10.
  • connect_timeout: Tiempo de espera en segundos para establecer una conexión con el servidor memcache. El valor predeterminado es 10 segundos.

Si se especifica un alias, debe preceder al servidor. Por ejemplo:

memcache:alias?timeout=300:192.168.1.100:11211

Este ejemplo se conectará al servidor 192.168.1.100 en el puerto 11211, pero usará un tiempo de espera de 300 segundos y solo permitirá 10 conexiones al servidor.

Las claves de búsqueda se prefijan con el nombre del archivo de tabla de búsqueda, seguido de un dos puntos. Por ejemplo, si busca la dirección "ejemplo.com" en una tabla llamada "/etc/postfix/virtual_maps", Postfix buscará la clave "virtual_maps:ejemplo.com" en memcache.

Los valores de memcache se devuelven como cadenas de texto. Si un valor contiene múltiples entradas separadas por espacios, Postfix las tratará como entradas separadas en la tabla de búsqueda.

PARÁMETROS PRINCIPALES DE MEMCACHE

memcache_default_port (str, default: 11211)
El número de puerto predeterminado a usar cuando se conecta a un servidor memcache sin especificar un puerto.
memcache_timeout (str, default: 10)
El tiempo límite para enviar un comando memcache y recibir una respuesta.

PARÁMETROS DE CLAVE DE MEMCACHE

memcache_key_format (str, default: %s)
El formato de la clave que se almacena y se busca en memcache. Puede usar especificadores de formato de la función sprintf(3), como `%s` para la cadena de entrada completa.

CONTROLES DE ERRORES DE MEMCACHE

memcache_destination_recipient_limit (int, default: -1)
El número máximo de destinatarios permitidos en un sobre de correo electrónico cuando se utiliza una tabla memcache para la resolución de destinos. Un valor de -1 significa sin límite.
memcache_lookup_retry (boolean, default: no)
Reintentar una búsqueda de memcache si falla debido a un error temporal del servidor. Un valor de `yes` habilita los reintentos. El número de reintentos está controlado por el parámetro `max_try_addr`.
memcache_server_failure_timeout (str, default: 300)
El tiempo de espera en segundos para reintentar la conexión a un servidor memcache que ha fallado previamente. Esto evita que Postfix intente constantemente conectarse a un servidor que no responde.

ERRORES

El cliente memcache de Postfix no se puede usar para tablas sensibles a la seguridad, como alias_maps (estas pueden contener destinos "|comando y "/nombre/de/archivo"), o virtual_uid_maps, virtual_gid_maps y virtual_mailbox_maps (estas especifican privilegios de proceso de UNIX o destinos "/nombre/de/archivo"). En una implementación típica, una base de datos memcache es escribible por cualquier proceso que pueda comunicarse con el servidor memcache; en contraste, las tablas sensibles a la seguridad nunca deben ser escribibles por el usuario no privilegiado de Postfix.

El cliente memcache de Postfix requiere configuración adicional cuando se utiliza como caché para postscreen(8) o verify(8). Para obtener detalles, consulte las discusiones de los parámetros backup y ttl en la sección PARÁMETROS PRINCIPALES DE MEMCACHE anterior.
