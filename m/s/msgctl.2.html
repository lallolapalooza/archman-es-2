msgctl(2) Manual de Llamadas al Sistema msgctl(2)

NOMBRE

msgctl - operaciones de control de mensajes System V

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/msg.h>
int msgctl(int msqid, int op, struct msqid_ds *buf);

DESCRIPCIÓN

msgctl() realiza la operación de control especificada por op en la cola de mensajes System V con identificador msqid.

La estructura de datos msqid_ds se define en <sys/msg.h> de la siguiente manera:


struct msqid_ds {
    struct ipc_perm msg_perm;   /* Propiedad y permisos */
    time_t          msg_stime;  /* Hora de la última msgsnd(2) */
    time_t          msg_rtime;  /* Hora de la última msgrcv(2) */
    time_t          msg_ctime;  /* Hora de creación o última
                                   modificación por msgctl() */
    unsigned long   msg_cbytes; /* Nº de bytes en la cola */
    msgqnum_t       msg_qnum;   /* Nº de mensajes en la cola */
    msglen_t        msg_qbytes; /* Nº máximo de bytes en la cola */
    pid_t           msg_lspid;  /* PID del último msgsnd(2) */
    pid_t           msg_lrpid;  /* PID del último msgrcv(2) */
};

Los campos de la estructura msqid_ds son los siguientes:

msg_perm
Esta es una estructura ipc_perm (ver más abajo) que especifica los permisos de acceso a la cola de mensajes.
msg_stime
Hora de la última llamada al sistema msgsnd(2).
msg_rtime
Hora de la última llamada al sistema msgrcv(2).
msg_ctime
Hora de creación de la cola o hora de la última operación IPC_SET de msgctl().
msg_cbytes
Número de bytes en todos los mensajes actualmente en la cola de mensajes. Esta es una extensión no estándar de Linux que no está especificada en POSIX.
msg_qnum
Número de mensajes actualmente en la cola de mensajes.
msg_qbytes
Número máximo de bytes de texto de mensajes permitidos en la cola de mensajes.
msg_lspid
ID del proceso que realizó la última llamada al sistema msgsnd(2).
msg_lrpid
ID del proceso que realizó la última llamada al sistema msgrcv(2).

La estructura ipc_perm se define de la siguiente manera (los campos resaltados son configurables usando IPC_SET):


struct ipc_perm {
    key_t          __key;       /* Clave proporcionada a msgget(2) */
    uid_t          uid;         /* UID efectivo del propietario */
    gid_t          gid;         /* GID efectivo del propietario */
    uid_t          cuid;        /* UID efectivo del creador */
    gid_t          cgid;        /* GID efectivo del creador */
    unsigned short mode;        /* Permisos */
    unsigned short __seq;       /* Número de secuencia */
};

Los bits menos significativos de 9 de el campo mode de la estructura ipc_perm definen los permisos de acceso para la cola de mensajes. Los bits de permiso son los siguientes:

0400 Lectura por el usuario
0200 Escritura por el usuario
0040 Lectura por el grupo
0020 Escritura por el grupo
0004 Lectura por otros
0002 Escritura por otros

Los bits 0100, 0010 y 0001 (los bits de ejecución) no se utilizan por el sistema.

Los valores válidos para op son:

IPC_STAT
Copia información de la estructura de datos del kernel asociada a msqid en la estructura msqid_ds apuntada por buf. El llamador debe tener permiso de lectura sobre la cola de mensajes.
IPC_SET
Escribe los valores de algunos miembros de la estructura msqid_ds apuntada por buf en la estructura de datos del kernel asociada a esta cola de mensajes, actualizando también su miembro msg_ctime.
Se actualizan los siguientes miembros de la estructura: msg_qbytes, msg_perm.uid, msg_perm.gid y (los 9 bits menos significativos de) msg_perm.mode.
El UID efectivo del proceso llamador debe coincidir con el propietario (msg_perm.uid) o creador (msg_perm.cuid) de la cola de mensajes, o el llamador debe ser privilegiado. Se requiere el privilegio apropiado (Linux: la capacidad CAP_SYS_RESOURCE) para elevar el valor de msg_qbytes más allá del parámetro del sistema MSGMNB.
IPC_RMID
Elimina inmediatamente la cola de mensajes, despertando a todos los procesos lectores y escritores en espera (con un retorno de error y errno establecido a EIDRM). El proceso llamador debe tener los privilegios apropiados o su ID de usuario efectivo debe ser el del creador o propietario de la cola de mensajes. El tercer argumento a msgctl() se ignora en este caso.
IPC_INFO (específico de Linux)
Devuelve información sobre los límites y parámetros globales del sistema de colas de mensajes en la estructura apuntada por buf. Esta estructura es de tipo msginfo (por lo tanto, se requiere un cast), definida en <sys/msg.h> si el macro de prueba de características _GNU_SOURCE está definido:

struct msginfo {
    int msgpool; /* Tamaño en kibibytes del pool de buffers
                    utilizado para almacenar datos de mensajes;
                    no utilizado dentro del kernel */
    int msgmap;  /* Número máximo de entradas en el mapa de mensajes;
                    no utilizado dentro del kernel */
    int msgmax;  /* Número máximo de bytes que se pueden
                    escribir en un solo mensaje */
    int msgmnb;  /* Número máximo de bytes que se pueden
                    escribir en una cola; se utiliza para inicializar
                    msg_qbytes durante la creación de la cola
                    (msgget(2)) */
    int msgmni;  /* Número máximo de colas de mensajes */
    int msgssz;  /* Tamaño del segmento de mensaje;
                    no utilizado dentro del kernel */
    int msgtql;  /* Número máximo de mensajes en todas las colas
                    en el sistema; no utilizado dentro del kernel */
    unsigned short msgseg;
                 /* Número máximo de segmentos;
                    no utilizado dentro del kernel */
};

Los ajustes msgmni, msgmax y msgmnb se pueden modificar a través de archivos /proc del mismo nombre; consulte proc(5) para más detalles.
MSG_INFO (específico de Linux)
Devuelve una estructura msginfo que contiene la misma información que para IPC_INFO, excepto que los siguientes campos devuelven información sobre los recursos del sistema consumidos por las colas de mensajes: el campo msgpool devuelve el número de colas de mensajes que existen actualmente en el sistema; el campo msgmap devuelve el número total de mensajes en todas las colas del sistema; y el campo msgtql devuelve el número total de bytes en todos los mensajes en todas las colas del sistema.
MSG_STAT (específico de Linux)
Devuelve una estructura msqid_ds como para IPC_STAT. Sin embargo, msqid no es un identificador de cola, sino un índice en el array interno del kernel que mantiene información sobre todas las colas de mensajes en el sistema.
MSG_STAT_ANY (específico de Linux, desde Linux 4.17)
Devuelve una estructura msqid_ds como para MSG_STAT. Sin embargo, no se verifica el permiso de lectura en msg_perm.mode para msqid, lo que significa que cualquier usuario puede emplear esta operación (del mismo modo que cualquier usuario puede leer /proc/sysvipc/msg para obtener la información del sistema).

msgctl(2) — Arch Linux manual pages

msgctl

control operations on a POSIX message queue

msgctl

realtime, threads

SYNOPSIS

#include <sys/msg.h>

int msgctl(int msqid, int cmd, struct msqid_ds *buf);

DESCRIPTION

The msgctl() function performs the control operation specified by cmd on the message queue identified by msqid. The third argument, buf, is a pointer to a buffer storing data associated with the specified message queue. Depending on the command, this buffer may be an input, output, or both.

The structure msqid_ds is defined in <sys/msg.h> and contains at least the following fields:

msg_perm
Operation permission structure.
msg_firstid
ID of first message in queue, or 0 if empty.
msg_lastid
ID of last message in queue, or 0 if empty.
msg_qnum
Number of messages currently in queue.
msg_qbytes
Maximum number of bytes allowed for this queue's messages.
msg_lspid
PID of last process that sent a message.
msg_lrpid
PID of last process that received a message.
msg_stime
Time message queue last sent.
msg_rtime
Time message queue last received.
msg_ctime
Time message queue last changed.

The valid values for cmd are:

IPC_STAT
Copy the msqid_ds structure associated with msqid to the buffer pointed to by buf. This operation requires read, or superuser, access to the message queue.
IPC_SET
Set the value of the following members of the msqid_ds structure associated with msqid to the values in the buffer pointed to by buf: msg_qbytes (the maximum number of bytes allowed for this queue's messages). This operation requires the kernel's internal IPC_SETVAL key value to be set to 1. Changing the msg_qbytes value requires write access to the message queue. Only the owner or the superuser can change this value.
IPC_RMID
Mark the message queue indicated by msqid for destruction. The queue's data and associated buffer space will be freed after the last message is sent to or received from it. This operation requires the owner or superuser access to the message queue. The buf argument is ignored.
MSG_INFO
Returns information about message queue configuration. If msqid is 0, then buf must point to a msqid_ds structure, and the kernel fills it with system-wide message queue information. The msg_perm.key field is set to the maximum number of message queues (-1 if not available).
MSG_STAT
Returns information about a specific message queue. msqid is interpreted as an index into the kernel's internal array of message queues. If buf points to a msqid_ds structure, the kernel copies the information of the message queue at the specified index into the buffer.
MSG_STAT_ANY
Similar to MSG_STAT, but msqid is interpreted as an index (or an identifier if it's positive). If it's an index, it returns the information of the queue at that index. If it's an identifier, it returns the information of the queue associated with that identifier. This command is available since Linux 5.10.

The structure msqid_ds contains a msg_perm field, which is of type struct ipc_perm. This structure contains the following fields:

key
Owner's private key.
uid
Owner real user ID.
gid
Owner real group ID.
cuid
Creator real user ID.
cgid
Creator effective group ID.
mode
Permissions.
seq
Sequence number.

The mode field consists of 9 bits representing read/write permissions for the owner, creator, and other users. The permissions are encoded as follows:

  • 0400: Owner read permission.
  • 0200: Owner write permission.
  • 0040: Creator read permission.
  • 0020: Creator write permission.
  • 0004: Other users read permission.
  • 0002: Other users write permission.

The ipc_perm structure also contains fields related to the IPC identifier: key (the key used to create the queue), uid and gid (owner's IDs), cuid and cgid (creator's IDs), and seq (a sequence number used to disambiguate identifiers).

The following are the common commands for message queues (similar to semaphores and shared memory):

IPC_STAT
Copy the msqid_ds structure associated with msqid to the buffer pointed to by buf. This operation requires read permission.
IPC_SET
Set the value of the following members of the msqid_ds structure associated with msqid to the values in the buffer pointed to by buf: msg_perm.uid, msg_perm.gid, msg_qbytes. This operation requires write permission.
IPC_RMID
Mark the message queue indicated by msqid for destruction. The queue's data and associated buffer space will be freed after the last message is sent to or received from it. This operation requires the owner or superuser access to the message queue. The buf argument is ignored.

The following commands are Linux-specific:

IPC_INFO
Copy information about system-wide message queue configuration to the buffer pointed to by buf. The msg_perm.key field is set to the maximum number of message queues, and the other fields are unused. Requires read permission.
MSG_INFO
Similar to IPC_INFO, but returns more detailed information about all queues.
MSG_STAT
Return information about a specific message queue. msqid is interpreted as an index into the kernel's internal array of message queues. The information is copied to the buffer pointed to by buf. Requires read permission.
MSG_STAT_ANY
Similar to MSG_STAT, but msqid can be an index or an identifier. This command is available since Linux 5.10.

RETURN VALUE

On success, IPC_STAT, IPC_SET, and IPC_RMID return 0. A successful IPC_INFO or MSG_INFO operation returns the index of the highest used entry in the kernel's internal array recording information about all message queues. (This information can be used with repeated MSG_STAT or MSG_STAT_ANY operations to obtain information about all queues on the system.) A successful MSG_STAT or MSG_STAT_ANY operation returns the identifier of the queue whose index was given in msqid.

On failure, -1 is returned and errno is set to indicate the error.

ERRORS

EACCES
The argument cmd is equal to IPC_STAT or MSG_STAT, but the calling process does not have read permission on the message queue msqid, and does not have the CAP_IPC_OWNER capability in the user namespace that governs its IPC namespace.
EFAULT
The argument cmd has the value IPC_SET or IPC_STAT, but the address pointed to by buf isn't accessible.
EIDRM
The message queue was removed.
EINVAL
Invalid value for cmd or msqid. Or: for a MSG_STAT operation, the index value specified in msqid referred to an array slot that is currently unused.
EPERM
The argument cmd has the value IPC_SET or IPC_RMID, but the effective user ID of the calling process is not the creator (as found in msg_perm.cuid) or the owner (as found in msg_perm.uid) of the message queue, and the caller is not privileged (Linux: does not have the CAP_SYS_ADMIN capability).
EPERM
An attempt (IPC_SET) was made to increase msg_qbytes beyond the system parameter MSGMNB, but the caller is not privileged (Linux: does not have the CAP_SYS_RESOURCE capability).

STANDARDS

POSIX.1-2024.

HISTORY

POSIX.1-2001, SVr4.

Various fields in the struct msqid_ds were typed as short under Linux 2.2 and have become long under Linux 2.4. To take advantage of this, a recompilation under glibc-2.1.91 or later should suffice. (The kernel distinguishes old and new calls by an IPC_64 flag in cmd.)

NOTES

The IPC_INFO, MSG_STAT, and MSG_INFO operations are used by the ipcs(1) program to provide information on allocated resources. In the future these may modified or moved to a /proc filesystem interface.
