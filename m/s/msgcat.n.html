NOMBRE

msgcat - Catálogo de mensajes de Tcl

SINOPSIS

package require Tcl 8.5

package require msgcat 1.6

::msgcat::mc cadena-origen ?arg arg ...?

::msgcat::mcmax ?cadena-origen cadena-origen ...?

::msgcat::mcexists ?-exactnamespace? ?-exactlocale? cadena-origen

::msgcat::mclocale ?nuevoLocal?

::msgcat::mcpreferences

::msgcat::mcloadedlocales subcomando ?local?

::msgcat::mcload dirnombre

::msgcat::mcset local cadena-origen ?cadena-traduccion?

::msgcat::mcmset local lista-cadena-traduccion

::msgcat::mcflset cadena-origen ?cadena-traduccion?

::msgcat::mcflmset lista-cadena-traduccion

::msgcat::mcunknown local cadena-origen ?arg arg ...?

::msgcat::mcpackagelocale subcomando ?local?

::msgcat::mcpackageconfig subcomando opción ?valor?

::msgcat::mcforgetpackage

DESCRIPCIÓN

El paquete msgcat proporciona un conjunto de funciones que pueden ser utilizadas para gestionar interfaces de usuario multilingües. Las cadenas de texto se definen en un “catálogo de mensajes” que es independiente de la aplicación y que puede ser editado o localizado sin modificar el código fuente de la aplicación. Nuevos idiomas o locales pueden ser proporcionados añadiendo un nuevo archivo al catálogo de mensajes.

msgcat distingue los paquetes por su espacio de nombres. Cada paquete tiene su propio catálogo de mensajes y configuración en msgcat.

Un local es una cadena de especificación que describe el idioma de un usuario, como de_ch para el alemán suizo. En msgcat, existe un local global inicializado por el local del sistema del sistema actual. Cada paquete puede decidir usar el local global o usar un local específico del paquete.

El local global puede ser cambiado bajo demanda, por ejemplo, por un cambio de idioma iniciado por el usuario o dentro de una aplicación multiusuario como un servidor web.

COMANDOS

::msgcat::mc cadena-origen ?arg arg ...?
Devuelve una traducción de cadena-origen de acuerdo con el local actual. Si se dan argumentos adicionales después de cadena-origen, se utiliza el comando format para sustituir los argumentos adicionales en la traducción de cadena-origen.

::msgcat::mc buscará los mensajes definidos en el espacio de nombres actual para una traducción de cadena-origen; si no se encuentra ninguna, buscará en el padre del espacio de nombres actual, y así sucesivamente hasta llegar al espacio de nombres global. Si no existe ninguna cadena de traducción, se llama a ::msgcat::mcunknown y se devuelve la cadena devuelta por ::msgcat::mcunknown.

::msgcat::mc es la función principal utilizada para localizar una aplicación. En lugar de usar una cadena en inglés directamente, una aplicación puede pasar la cadena en inglés a través de ::msgcat::mc y usar el resultado. Si una aplicación se escribe para un solo idioma de esta manera, entonces es fácil añadir soporte para idiomas adicionales más tarde simplemente definiendo nuevas entradas en el catálogo de mensajes.

::msgcat::mcmax ?cadena-origen cadena-origen ...?
Dados varios strings de origen, ::msgcat::mcmax devuelve la longitud del string traducido más largo. Esto es útil al diseñar interfaces gráficas localizadas, que pueden requerir que todos los botones, por ejemplo, tengan un ancho fijo (que será el ancho del botón más ancho).
::msgcat::mcexists ?-exactnamespace? ?-exactlocale? cadena-origen
Devuelve verdadero si existe una traducción para la cadena-origen dada.
La búsqueda puede limitarse por la opción -exactnamespace para verificar solo el espacio de nombres actual y no ninguno de los espacios de nombres padres.

También puede limitarse por la opción -exactlocale para verificar solo el primer local preferido (por ejemplo, el primer elemento devuelto por ::msgcat::mcpreferences si se utiliza el local global).

::msgcat::mclocale ?nuevoLocal?
Esta función establece el local a nuevoLocal. Si se omite nuevoLocal, se devuelve el local actual, de lo contrario, el local actual se establece a nuevoLocal. msgcat almacena y compara el local de forma insensible a mayúsculas/minúsculas, y devuelve los locales en minúsculas. El local inicial se determina por el local especificado en el entorno del usuario. Consulte ESPECIFICACIÓN DEL LOCAL a continuación para una descripción del formato de la cadena del local.

Si se establece el local, se evalúa la lista de preferencias de locales. Los locales de esta lista se cargan ahora, si aún no están cargados.

::msgcat::mcpreferences
Devuelve una lista ordenada de los locales preferidos por el usuario, basándose en la especificación del idioma del usuario. La lista está ordenada de más específico a menos preferido. La lista se deriva del local actual establecido en msgcat por ::msgcat::mclocale, y no puede establecerse independientemente. Por ejemplo, si el local actual es en_US_funky, entonces ::msgcat::mcpreferences devuelve {en_us_funky en_us en {}}.
::msgcat::mcloadedlocales subcomando ?local?
Este grupo de comandos gestiona la lista de locales cargados para paquetes que no establecen un local de paquete.
El subcomando get devuelve la lista de locales cargados actualmente.

El subcomando present requiere el argumento local y devuelve verdadero si este local está cargado.

El subcomando clear elimina todos los locales y sus datos que no están en la lista de preferencias actual.

::msgcat::mcload dirnombre
Busca en el directorio especificado archivos que coincidan con las especificaciones de idioma devueltas por ::msgcat::mcloadedlocales get (o msgcat::mcpackagelocale preferences si se establece un local de paquete) (tenga en cuenta que todos están en minúsculas), extendidos por la extensión de archivo “.msg”. Cada archivo coincidente se lee en orden, asumiendo una codificación UTF-8. El contenido del archivo se evalúa entonces como un script Tcl. Esto significa que los caracteres Unicode pueden estar presentes en el archivo de mensajes directamente en su forma codificada en UTF-8, o mediante el uso de la cita de barra invertida-u reconocida por la evaluación de Tcl. Se devuelve el número de archivos de mensajes que coincidieron con la especificación y fueron cargados.

Además, la carpeta dada se almacena en la opción de configuración del paquete msgcat mcfolder para cargar eventualmente los archivos del catálogo de mensajes requeridos por un cambio de local.

::msgcat::mcset local cadena-origen ?cadena-traduccion?
Establece la traducción de cadena-origen a cadena-traduccion en el local especificado y el espacio de nombres actual. Si no se especifica cadena-traduccion, se usa cadena-origen para ambos. La función devuelve cadena-traduccion.
::msgcat::mcmset local lista-cadena-traduccion
Establece la traducción para múltiples cadenas de origen en lista-cadena-traduccion en el local especificado y el espacio de nombres actual. lista-cadena-traduccion debe tener un número par de elementos y tiene el formato {cadena-origen cadena-traduccion ?cadena-origen cadena-traduccion ...?} ::msgcat::mcmset puede ser significativamente más rápido que múltiples invocaciones de ::msgcat::mcset. La función devuelve el número de traducciones establecidas.
::msgcat::mcflset cadena-origen ?cadena-traduccion?
Establece la traducción de cadena-origen a cadena-traduccion en el espacio de nombres actual para el local implícito por el nombre del catálogo de mensajes que se carga a través de ::msgcat::mcload. Si no se especifica cadena-traduccion, se usa cadena-origen para ambos. La función devuelve cadena-traduccion.
::msgcat::mcflmset lista-cadena-traduccion
Establece la traducción para múltiples cadenas de origen en lista-cadena-traduccion en el espacio de nombres actual para el local implícito por el nombre del catálogo de mensajes que se carga a través de ::msgcat::mcload. lista-cadena-traduccion debe tener un número par de elementos y tiene el formato {cadena-origen cadena-traduccion ?cadena-origen cadena-traduccion ...?} ::msgcat::mcflmset puede ser significativamente más rápido que múltiples invocaciones de ::msgcat::mcflse

...

t. La función devuelve el número de traducciones establecidas.
::msgcat::mcunknown locale src-string ?arg arg ...?
Esta rutina es llamada por ::msgcat::mc en el caso de que una traducción para src-string no esté definida en la configuración regional actual. La acción predeterminada es devolver src-string formateado si hay algún argumento. Este procedimiento puede ser redefinido por la aplicación, por ejemplo, para registrar mensajes de error para cada cadena desconocida. El procedimiento ::msgcat::mcunknown se invoca en el mismo contexto de pila que la llamada a ::msgcat::mc. El valor de retorno de ::msgcat::mcunknown se utiliza como valor de retorno para la llamada a ::msgcat::mc.

Tenga en cuenta que esta rutina solo se llama si el paquete en cuestión no ha establecido un nombre de comando desconocido para la configuración regional del paquete.

::msgcat::mcforgetpackage
El paquete que llama borra todo su estado dentro del paquete msgcat, incluyendo todas las configuraciones y traducciones.

ESPECIFICACIÓN DE CONFIGURACIÓN REGIONAL

La configuración regional se especifica a msgcat mediante una cadena de configuración regional pasada a ::msgcat::mclocale. La cadena de configuración regional consta de un código de idioma, un código de país opcional y un código opcional específico del sistema, cada uno separado por “_”. Los códigos de país e idioma se especifican en las normas ISO-639 e ISO-3166. Por ejemplo, la configuración regional “en” especifica inglés y “en_US” especifica inglés de EE. UU.

Cuando el paquete msgcat se carga por primera vez, la configuración regional se inicializa de acuerdo con el entorno del usuario. Las variables env(LC_ALL), env(LC_MESSAGES) y env(LANG) se examinan en orden. La primera de ellas que tenga un valor no vacío se utiliza para determinar la configuración regional inicial. El valor se analiza según el patrón XPG4

language[_country][.codeset][@modifier]

para extraer sus partes. La configuración regional inicial se establece llamando a ::msgcat::mclocale con el argumento

language[_country][_modifier]

En Windows y Cygwin, si ninguna de estas variables de entorno está configurada, msgcat intentará extraer la información de configuración regional del registro. A partir de Windows Vista, el nombre de configuración regional RFC4747 "lang-script-country-options" se transforma a la configuración regional como "lang_country_script" (Ejemplo: sr-Latn-CS -> sr_cs_latin). Para Windows XP, el ID de idioma se transforma análogamente (Ejemplo: 0c1a -> sr_yu_cyrillic). Si todos estos intentos de descubrir una configuración regional inicial del entorno del usuario fallan, msgcat recurre a una configuración regional inicial de “C”.

Cuando el usuario especifica una configuración regional, se realiza una búsqueda de "mejor coincidencia" durante la traducción de cadenas. Por ejemplo, si un usuario especifica en_GB_Funky, se buscarán las configuraciones regionales “en_gb_funky”, “en_gb”, “en” y “” (la cadena vacía) en orden hasta que se encuentre una cadena de traducción coincidente. Si no hay una cadena de traducción disponible, se llamará al manejador de desconocidos.

ESPACIOS DE NOMBRES Y CATÁLOGOS DE MENSAJES

Las cadenas almacenadas en el catálogo de mensajes se almacenan en relación con el espacio de nombres desde el cual se agregaron. Esto permite que múltiples paquetes utilicen las mismas cadenas sin temor a colisiones con otros paquetes. También permite que la cadena de origen sea más corta y menos propensa a errores tipográficos.

Por ejemplo, al ejecutar el código

::msgcat::mcset en hello "hello from ::"
namespace eval foo {
    ::msgcat::mcset en hello "hello from ::foo"
}
puts [::msgcat::mc hello]
namespace eval foo {puts [::msgcat::mc hello]}

imprimirá

hello from ::
hello from ::foo

Al buscar una traducción de un mensaje, el catálogo de mensajes primero buscará en el espacio de nombres actual, luego en el padre del espacio de nombres actual, y así sucesivamente hasta llegar al espacio de nombres global. Esto permite que los espacios de nombres hijos "hereden" mensajes de su espacio de nombres padre.

Por ejemplo, al ejecutar (en la configuración regional "en") el código

::msgcat::mcset en m1 ":: message1"
::msgcat::mcset en m2 ":: message2"
::msgcat::mcset en m3 ":: message3"
namespace eval ::foo {
    ::msgcat::mcset en m2 "::foo message2"
    ::msgcat::mcset en m3 "::foo message3"
}
namespace eval ::foo::bar {
    ::msgcat::mcset en m3 "::foo::bar message3"
}
namespace import ::msgcat::mc
puts "[mc m1]; [mc m2]; [mc m3]"
namespace eval ::foo {puts "[mc m1]; [mc m2]; [mc m3]"}
namespace eval ::foo::bar {puts "[mc m1]; [mc m2]; [mc m3]"}

imprimirá

:: message1; :: message2; :: message3
:: message1; ::foo message2; ::foo message3
:: message1; ::foo message2; ::foo::bar message3

UBICACIÓN Y FORMATO DE LOS ARCHIVOS DE MENSAJES

Los archivos de mensajes se pueden ubicar en cualquier directorio, sujeto a las siguientes condiciones:

[1]
Todos los archivos de mensajes de un paquete están en el mismo directorio.
[2]
El nombre del archivo de mensajes es un especificador de configuración regional de msgcat (todo en minúsculas) seguido de ".msg". Por ejemplo:
es.msg    — español
en_gb.msg — inglés del Reino Unido

Excepción: El archivo de mensajes para la configuración regional raíz “” se llama “ROOT.msg”. Esta excepción se hace para no causar un comportamiento peculiar, como marcar el archivo de mensajes como "oculto" en sistemas de archivos Unix.

[3]
El archivo contiene una serie de llamadas a mcflset y mcflmset, estableciendo las cadenas de traducción necesarias para el idioma, probablemente dentro de un namespace eval para que todas las cadenas de origen estén vinculadas al espacio de nombres del paquete. Por ejemplo, un es.msg corto podría contener:
namespace eval ::mypackage {
    ::msgcat::mcflset "Free Beer" "Cerveza Gratis"
}

CONFIGURACIÓN DE MENSAJES RECOMENDADA PARA PAQUETES

Si un paquete se instala en un subdirectorio de tcl_pkgPath y se carga a través de package require, se recomienda el siguiente procedimiento.

[1]
Durante la instalación del paquete, cree un subdirectorio msgs dentro del directorio de su paquete.
[2]
Copie sus archivos *.msg en ese directorio.
[3]
Agregue el siguiente comando a su script de inicialización del paquete:
# cargar archivos de idioma, almacenados en el subdirectorio msgs
::msgcat::mcload [file join [file dirname [info script]] msgs]

CÓDIGOS POSICIONALES PARA LOS COMANDOS FORMAT Y SCAN

Es posible que una cadena de mensaje utilizada como argumento para format tenga parámetros dependientes de la posición que puedan necesitar ser reposicionados. Por ejemplo, puede ser sintácticamente deseable reorganizar la estructura de la oración al traducir.

format "We produced %d units in location %s" $num $city
format "In location %s we produced %d units" $city $num

Esto se puede manejar utilizando los parámetros posicionales:

format "We produced %1\$d units in location %2\$s" $num $city
format "In location %2\$s we produced %1\$d units" $num $city

De manera similar, se pueden usar parámetros posicionales con scan para extraer valores de cadenas internacionalizadas. Tenga en cuenta que no es necesario pasar la salida de ::msgcat::mc directamente a format; al pasar los valores a sustituir como argumentos, la sustitución de formato se realiza directamente.

msgcat::mc {Produced %1$d at %2$s} $num $city
# ... donde esa clave se mapea a una de las
# versiones orientadas al ser humano por msgcat::mcset

Configuración regional privada del paquete

Un paquete que utiliza msgcat puede optar por utilizar su propia configuración regional privada del paquete y su propio conjunto de configuraciones regionales cargadas, independientemente de la configuración regional global establecida por ::msgcat::mclocale.

Esto permite que un paquete cambie su configuración regional sin causar la carga o eliminación de configuraciones regionales en otros paquetes y sin invocar la devolución de llamada global de cambio de configuración regional (ver más abajo).

Esta acción está controlada por el siguiente conjunto:

::msgcat::mcpackagelocale set ?locale?
Establecer o cambiar una configuración regional privada del paquete. La configuración regional privada del paquete se establece en la locale dada si se proporciona la locale. Si no se proporciona la opción locale, el paquete se establece en modo de configuración regional privada del paquete, pero no se cambia ninguna configuración regional (por ejemplo, si la configuración regional global era válida para el paquete antes, se copia a la configuración regional privada del paquete).
Este comando puede provocar la carga de configuraciones regionales.
::msgcat::mcpackagelocale get
Devuelve la configuración regional privada del paquete o la configuración regional global, si no está establecida ninguna configuración regional privada del paquete.
::msgcat::mcpackagelocale preferences
Devuelve las preferencias privadas del paquete o las preferencias globales, si no está establecida ninguna configuración regional privada del paquete.
::msgcat::mcpackagelocale loaded
Devuelve la lista de configuraciones regionales cargadas para este paquete.
::msgcat::mcpackagelocale isset
Devuelve verdadero si está configurada una configuración regional privada del paquete.
::msgcat::mcpackagelocale unset
Anula la configuración regional privada del paquete y utiliza la configuración regional global. Carga y elimina configuraciones regionales para ajustar la lista de configuraciones regionales cargadas para el paquete a la lista global de configuraciones regionales cargadas.
::msgcat::mcpackagelocale present locale
Devuelve verdadero si la configuración regional dada está cargada para el paquete.
::msgcat::mcpackagelocale clear
Borra todas las configuraciones regionales cargadas del paquete que no estén presentes en las preferencias del paquete.

Cambio de opciones del paquete

Cada paquete que utiliza msgcat tiene un conjunto de opciones dentro de msgcat. Las opciones del paquete se describen en la siguiente sección Opciones del paquete. Cada opción del paquete puede ser establecida o eliminada individualmente utilizando el siguiente conjunto:

::msgcat::mcpackageconfig get opción
Devuelve el valor actual de la opción dada. Esta llamada devuelve un error si la opción no está establecida para el paquete.
::msgcat::mcpackageconfig isset opción
Devuelve 1 si la opción dada está establecida para el paquete, 0 en caso contrario.
::msgcat::mcpackageconfig set opción valor
Establece la opción dada al valor dado. Esto puede invocar acciones adicionales dependiendo de la opción. El valor de retorno es 0 o el número de paquetes cargados para la opción mcfolder.
::msgcat::mcpackageconfig unset opción
Elimina la opción dada para el paquete. No se realiza ninguna acción si la opción no está establecida para el paquete. Se devuelve la cadena vacía.

Opciones del paquete

Las siguientes opciones de paquete están disponibles para cada paquete:

mcfolder
Esta es la carpeta de mensajes del paquete. Esta opción es establecida por mcload y por el subcomando set. Ambas son idénticas y ambas devuelven el número de archivos de catálogo de mensajes cargados.

Establecer o cambiar este valor cargará todas las locales contenidas en las preferencias válidas para el paquete. Esto implica también invocar cualquier comando de carga establecido (ver más abajo).

Eliminar este valor deshabilitará la carga de archivos de mensajes para el paquete.

loadcmd
Este callback se invoca antes de que se cargue un conjunto de archivos de catálogo de mensajes para el paquete que tiene esta propiedad establecida.
Este callback puede ser utilizado para realizar cualquier trabajo de preparación para la carga de archivos de mensajes o para obtener los datos de los mensajes de otra fuente como una base de datos. En este caso, no se utilizan archivos de mensajes (mcfolder se elimina).

Ver la sección invocación de callback más abajo. La lista de parámetros añadida a este callback es la lista de locales a cargar.

Si este callback se cambia, se llama con las preferencias válidas para el paquete.

changecmd
Este callback se invoca cuando se realiza un cambio de locale predeterminado. Su propósito es permitir que un paquete actualice cualquier dependencia de la locale predeterminada, como mostrar la GUI en otro idioma.
Ver la sección de invocación de callback más abajo. La lista de parámetros añadida a este callback es mcpreferences. Los callbacks registrados se invocan en ningún orden particular.
unknowncmd
Utiliza un procedimiento de locale de paquete mcunknown en lugar de la versión estándar suministrada por el paquete msgcat (msgcat::mcunknown).
El procedimiento llamado debe devolver el mensaje formateado que finalmente será devuelto por msgcat::mc.

Se utiliza un manejador genérico de desconocidos si se establece como cadena vacía. Esto consiste en devolver la clave si no se dan argumentos. Con argumentos dados, se utiliza format para procesar los argumentos.

Ver la sección invocación de callback más abajo. Los argumentos añadidos son idénticos a los de ::msgcat::mcunknown.

Invocación de callback

Un paquete puede decidir registrar uno o varios callbacks, como se describe arriba.

Los callbacks se invocan si:

1. el comando de callback está establecido,

2. el comando no es la cadena vacía,

3. el espacio de nombres de registro existe.

Si una rutina llamada falla con un error, la rutina bgerror del intérprete se invoca después de completar el comando. La única excepción es el callback unknowncmd, donde un error hace que el comando mc invocador falle con ese error.

Ejemplos

Los paquetes que muestran una GUI pueden actualizar sus widgets cuando la locale global cambia. Para registrarse a un callback, utilice:

namespace eval gui {
    msgcat::mcpackageconfig changecmd updateGUI
    proc updateGUI args {
        puts "New locale is '[lindex $args 0]'."
    }
}
% msgcat::mclocale fr
fr
% New locale is 'fr'.

Si las locales (o locales adicionales) están contenidas en otra fuente como una base de datos, un paquete puede usar el callback de carga y no mcload:

namespace eval db {
    msgcat::mcpackageconfig loadcmd loadMessages
    proc loadMessages args {
        foreach locale $args {
            if {[LocaleInDB $locale]} {
                msgcat::mcmset $locale [GetLocaleList $locale]
            }
        }
    }
}

La implementación del comando clock utiliza msgcat con una locale de paquete para implementar el parámetro de línea de comandos -locale. Aquí hay algunos esbozos de la implementación:

Primero, se inicializa una locale de paquete y se desactiva la función genérica de desconocidos:

msgcat::mcpackagelocale set
msgcat::mcpackageconfig unknowncmd ""
Como ejemplo, el usuario solicita el día de la semana en una locale determinada de la siguiente manera: 
clock format [clock seconds] -format %A -locale fr
clock establece la locale del paquete a fr y busca el nombre del día de la siguiente manera: 
msgcat::mcpackagelocale set $locale
return [lindex [msgcat::mc DAYS_OF_WEEK_FULL] $day]
### Devuelve "mercredi"
Dentro de clock, algunos elementos del catálogo de mensajes requieren mucha computación y, por lo tanto, se almacenan en caché dinámicamente utilizando: 
proc ::tcl::clock::LocalizeFormat { locale format } {
    set key FORMAT_$format
    if { [::msgcat::mcexists -exactlocale -exactnamespace $key] } {
        return [mc $key]
    }
    #...cálculo costoso del formato recortado...
    mcset $locale $key $format
    return $format
}
