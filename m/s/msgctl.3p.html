MSGCTL(3P) Manual del programador POSIX MSGCTL(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

msgctl — operaciones de control de mensajes XSI

SINOPSIS

#include <sys/msg.h>
int msgctl(int msqid, int cmd, struct msqid_ds *buf);

DESCRIPCIÓN

La función msgctl() opera sobre colas de mensajes XSI (consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 3.226, Cola de Mensajes). No se especifica si esta función interopera con las instalaciones de comunicación entre procesos en tiempo real definidas en Sección 2.8, Tiempo Real.

La función msgctl() proporcionará operaciones de control de mensajes según lo especificado por cmd. Los siguientes valores para cmd, y las operaciones de control de mensajes que especifican, son:

IPC_STAT
Coloca el valor actual de cada miembro de la estructura de datos msqid_ds asociada con msqid en la estructura apuntada por buf. El contenido de esta estructura se define en <sys/msg.h>.
IPC_SET
Establece el valor de los siguientes miembros de la estructura de datos msqid_ds asociada con msqid al valor correspondiente que se encuentra en la estructura apuntada por buf:
msg_perm.uid
msg_perm.gid
msg_perm.mode
msg_qbytes

Además, la marca de tiempo msg_ctime se establecerá a la hora actual, como se describe en la Sección 2.7.1, Descripción General de IPC.

IPC_SET solo puede ser ejecutado por un proceso con privilegios apropiados o que tenga un ID de usuario efectivo igual al valor de msg_perm.cuid o msg_perm.uid en la estructura de datos msqid_ds asociada con msqid. Solo un proceso con privilegios apropiados puede aumentar el valor de msg_qbytes.

IPC_RMID
Elimina el identificador de cola de mensajes especificado por msqid del sistema y destruye la cola de mensajes y la estructura de datos msqid_ds asociada a ella. IPC_RMD solo puede ser ejecutado por un proceso con privilegios apropiados o uno que tenga un ID de usuario efectivo igual al valor de msg_perm.cuid o msg_perm.uid en la estructura de datos msqid_ds asociada con msqid.

VALOR DE RETORNO

Al completarse con éxito, msgctl() devolverá 0; de lo contrario, devolverá -1 y establecerá errno para indicar el error.

ERRORES

La función msgctl() fallará si:

EACCES
El argumento cmd es IPC_STAT y el proceso que llama no tiene permiso de lectura; consulte la Sección 2.7, Comunicación entre Procesos XSI.
EINVAL
El valor de msqid no es un identificador de cola de mensajes válido; o el valor de cmd no es un comando válido.
EPERM
El argumento cmd es IPC_RMID o IPC_SET y el ID de usuario efectivo del proceso que llama no es igual al de un proceso con privilegios apropiados y tampoco es igual al valor de msg_perm.cuid o msg_perm.uid en la estructura de datos asociada con msqid.
EPERM
El argumento cmd es IPC_SET, se está intentando aumentar el valor de msg_qbytes, y el ID de usuario efectivo del proceso que llama no tiene los privilegios apropiados.

USO POR APLICACIONES

La Extensión de Tiempo Real POSIX define interfaces alternativas para la comunicación entre procesos (IPC). Los desarrolladores de aplicaciones que necesiten usar IPC deben diseñar sus aplicaciones de manera que los módulos que utilizan las rutinas IPC descritas en la Sección 2.7, Comunicación entre Procesos XSI puedan modificarse fácilmente para utilizar las interfaces alternativas.
