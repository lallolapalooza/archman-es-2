MSGSND(3p) Manual de programador de POSIX MSGSND(3p)

PROLOG

Esta página del manual forma parte del Manual del programador de POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

msgsnd — operación de envío de mensajes XSI

SINOPSIS

#include <sys/msg.h>
int msgsnd(int msqid, const void *msgp, size_t msgsz, int msgflg);

DESCRIPCIÓN

msgsnd() opera en colas de mensajes XSI (consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 3.226, Cola de mensajes). No está especificado si esta función interopera con las instalaciones de comunicación entre procesos en tiempo real definidas en la Sección 2.8, Tiempo Real.

msgsnd() enviará un mensaje a la cola asociada con el identificador de cola de mensajes especificado por msqid.

La aplicación se asegurará de que el argumento msgp apunte a un búfer definido por el usuario que contenga primero un campo de tipo long que especifique el tipo de mensaje, y luego una porción de datos que contenga los bytes de datos del mensaje. La siguiente estructura es un ejemplo de cómo podría ser este búfer definido por el usuario:

struct mymsg {
    long   mtype;       /* Tipo de mensaje. */
    char   mtext[1];    /* Texto del mensaje. */
}

El miembro de la estructura mtype es un tipo long positivo y distinto de cero que el proceso receptor puede utilizar para la selección de mensajes.

El miembro de la estructura mtext es cualquier texto de longitud msgsz bytes. El argumento msgsz puede oscilar entre 0 y un máximo impuesto por el sistema.

El argumento msgflg especifica la acción que se tomará si una o más de las siguientes condiciones se cumplen:

*
El número de bytes ya presentes en la cola es igual a msg_qbytes; consulte <sys/msg.h>.
*
El número total de mensajes en todas las colas a nivel de sistema es igual al límite impuesto por el sistema.

Estas acciones son las siguientes:

*
Si (msgflg & IPC_NOWAIT) es distinto de cero, el mensaje no se enviará y el hilo que llama retornará inmediatamente.
*
Si (msgflg & IPC_NOWAIT) es 0, el hilo que llama suspenderá su ejecución hasta que ocurra una de las siguientes condiciones:
--
La condición que causó la suspensión ya no existe, en cuyo caso el mensaje se envía.
--
El identificador de cola de mensajes msqid se elimina del sistema; cuando esto ocurra, errno se establecerá en [EIDRM] y se devolverá -1.
--
El hilo que llama recibe una señal que debe ser capturada; en este caso, el mensaje no se envía y el hilo que llama reanuda la ejecución de la manera prescrita en sigaction().

Tras una finalización exitosa, se toman las siguientes acciones con respecto a la estructura de datos asociada con msqid; consulte <sys/msg.h>:

*
msg_qnum se incrementará en 1.
*
msg_lspid se establecerá en el ID de proceso del proceso que llama.
*
msg_stime se establecerá en la hora actual, como se describe en la Sección 2.7.1, Descripción General de IPC.

VALOR DE RETORNO

Tras una finalización exitosa, msgsnd() devolverá 0; de lo contrario, no se enviará ningún mensaje, msgsnd() devolverá -1 y errno se establecerá para indicar el error.

ERRORES

msgsnd() fallará si:

EACCES
Se deniega el permiso de operación al proceso que llama; consulte la Sección 2.7, Comunicación entre procesos XSI.
EAGAIN
El mensaje no se puede enviar por una de las razones citadas anteriormente y (msgflg & IPC_NOWAIT) es distinto de cero.
EIDRM
El identificador de cola de mensajes msqid se elimina del sistema.
EINTR
La función msgsnd() fue interrumpida por una señal.
EINVAL
El valor de msqid no es un identificador de cola de mensajes válido, o el valor de mtype es menor que 1; o el valor de msgsz es mayor que el límite impuesto por el sistema.

EJEMPLOS

Envío de un mensaje

El siguiente ejemplo envía un mensaje a la cola identificada por el argumento msqid (suponiendo que ese valor se ha establecido previamente). Esta llamada especifica que se debe informar de un error si no hay ningún mensaje disponible. El tamaño del mensaje se calcula directamente utilizando el operador sizeof.

#include <sys/msg.h>
...
int result;
int msqid;
struct message {
    long type;
    char text[20];
} msg;
msg.type = 1;
strcpy(msg.text, "Este es el mensaje 1");
...
result = msgsnd(msqid, (void *) &msg, sizeof(msg.text), IPC_NOWAIT);

USO POR LA APLICACIÓN

La Extensión POSIX de Tiempo Real define interfaces alternativas para la comunicación entre procesos (IPC). Los desarrolladores de aplicaciones que necesiten utilizar IPC deben diseñar sus aplicaciones de manera que los módulos que utilizan las rutinas IPC descritas en la Sección 2.7, Comunicación entre procesos XSI, puedan modificarse fácilmente para utilizar las interfaces alternativas.
