msgget(2) Manual de llamadas al sistema msgget(2)

NOMBRE

msgget - obtener un identificador de cola de mensajes System V

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/msg.h>
int msgget(key_t key, int msgflg);

DESCRIPCIÓN

La llamada al sistema msgget() devuelve el identificador de cola de mensajes System V asociado al valor del argumento key. Puede ser utilizada tanto para obtener el identificador de una cola de mensajes previamente creada (cuando msgflg es cero y key no tiene el valor IPC_PRIVATE), como para crear un nuevo conjunto.

Se crea una nueva cola de mensajes si key tiene el valor IPC_PRIVATE, o si key no es IPC_PRIVATE, no existe ninguna cola de mensajes con la clave key dada, y se especifica IPC_CREAT en msgflg.

Si msgflg especifica tanto IPC_CREAT como IPC_EXCL y ya existe una cola de mensajes para key, entonces msgget() falla con errno establecido a EEXIST. (Esto es análogo al efecto de la combinación O_CREAT | O_EXCL para open(2).)

En la creación, los bits menos significativos del argumento msgflg definen los permisos de la cola de mensajes. Estos bits de permiso tienen el mismo formato y semántica que los permisos especificados para el argumento mode de open(2). (Los permisos de ejecución no se utilizan.)

Si se crea una nueva cola de mensajes, su estructura de datos asociada msqid_ds (ver msgctl(2)) se inicializa de la siguiente manera:

•
msg_perm.cuid y msg_perm.uid se establecen al ID de usuario efectivo del proceso llamante.
•
msg_perm.cgid y msg_perm.gid se establecen al ID de grupo efectivo del proceso llamante.
•
Los 9 bits menos significativos de msg_perm.mode se establecen a los 9 bits menos significativos de msgflg.
•
msg_qnum, msg_lspid, msg_lrpid, msg_stime y msg_rtime se establecen a 0.
•
msg_ctime se establece a la hora actual.
•
msg_qbytes se establece al límite del sistema MSGMNB.

Si la cola de mensajes ya existe, se verifican los permisos y se comprueba si está marcada para su destrucción.

VALOR DE RETORNO

En caso de éxito, msgget() devuelve el identificador de la cola de mensajes (un entero no negativo). En caso de fallo, se devuelve -1 y se establece errno para indicar el error.

ERRORES

EACCES
Existe una cola de mensajes para key, pero el proceso llamante no tiene permiso para acceder a la cola, y no tiene la capacidad CAP_IPC_OWNER en el espacio de nombres de usuario que rige su espacio de nombres IPC.
EEXIST
Se especificaron IPC_CREAT y IPC_EXCL en msgflg, pero ya existe una cola de mensajes para key.
ENOENT
No existe ninguna cola de mensajes para key y msgflg no especificó IPC_CREAT.
ENOMEM
Se debe crear una cola de mensajes pero el sistema no tiene suficiente memoria para la nueva estructura de datos.
ENOSPC
Se debe crear una cola de mensajes pero se excedería el límite del sistema para el número máximo de colas de mensajes (MSGMNI).

ESTÁNDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2001, SVr4.

Linux

Hasta Linux 2.3.20, Linux devolvía EIDRM para un msgget() en una cola de mensajes programada para su eliminación.

NOTAS

IPC_PRIVATE no es un campo de bandera sino un tipo key_t. Si se utiliza este valor especial para key, la llamada al sistema ignora todo excepto los 9 bits menos significativos de msgflg y crea una nueva cola de mensajes (en caso de éxito).

El siguiente es un límite del sistema en los recursos de las colas de mensajes que afecta a una llamada msgget():

MSGMNI
Límite global del sistema para el número de colas de mensajes. Antes de Linux 3.19, el valor predeterminado para este límite se calculaba usando una fórmula basada en la memoria del sistema disponible. Desde Linux 3.19, el valor predeterminado es 32.000. En Linux, este límite se puede leer y modificar a través de /proc/sys/kernel/msgmni.

ERRORES DE PROGRAMACIÓN

La elección del nombre IPC_PRIVATE quizás fue desafortunada, IPC_NEW mostraría más claramente su función.
