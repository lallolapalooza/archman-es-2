NOMBRE

msmtpd - Un servidor SMTP mínimo

SINOPSIS

msmtpd [opción...]

DESCRIPCIÓN

Msmtpd es un servidor SMTP mínimo que canaliza correos a msmtp (o algún otro programa) para su entrega. Puede ser utilizado con servicios del sistema que esperan un servidor SMTP en el host local, o puede ser utilizado por usuarios finales como una forma de manejar el correo saliente a través de msmtp con clientes de correo que insisten en usar SMTP. La sección de EJEMPLOS a continuación contiene ejemplos para ambos casos de uso.
Msmtpd escucha en 127.0.0.1 puerto 25 por defecto, pero también puede ejecutarse sin sus propios sockets de red en modo inetd, donde maneja una única sesión SMTP en la entrada/salida estándar.
En la cadena que define el comando al que msmtpd canaliza cada correo, la primera ocurrencia de %F será reemplazada con la dirección del remitente del sobre. Además, todos los destinatarios del correo se añadirán como argumentos. El comando no debe escribir en la salida estándar, ya que eso alteraría la sesión SMTP.
Si el comando al que se canaliza el correo reporta un error, esto se reporta típicamente como un fallo permanente por msmtpd (código de retorno del servidor SMTP 554). El comando puede opcionalmente señalar errores temporales utilizando códigos de retorno definidos en sysexits.h, por ejemplo, 75 para EX_TEMPFAIL. Estos se reportarán como fallos temporales por msmtpd (código de retorno del servidor SMTP 451), lo que significa que el cliente debería intentar de nuevo más tarde.
Para prevenir el abuso, msmtpd permitirá solo un número limitado de sesiones SMTP concurrentes, y si la autenticación está activa y ocurre un fallo de autenticación, las futuras solicitudes de autenticación en cualquier sesión SMTP (durante un período limitado) solo se responderán después de un pequeño retraso.

OPCIONES

--version
Imprime información de la versión
--help
Imprime la ayuda
--inetd
Inicia una única sesión SMTP en stdin/stdout
--interface=ip
Escucha en la dirección IPv6 o IPv4 dada en lugar de 127.0.0.1
--port=número
Escucha en el número de puerto dado en lugar de 25
--log=ninguno|syslog|nombre_archivo
Configura el registro: ninguno (por defecto), syslog, o registro en el archivo dado.
--command=cmd
Canaliza los correos a cmd en lugar de msmtp. Asegúrate de terminar este comando con -- para separar las opciones de los argumentos.
--auth=usuario[,evalcontraseña]
Requiere autenticación con este nombre de usuario. La contraseña se obtendrá de el comando evalcontraseña dado (esto funciona igual que evalcontraseña en msmtp) o, si no se proporciona ninguno, del anillo de claves o, si eso falla, de una solicitud.

EJEMPLOS

Uso de msmtpd como servicio del sistema
Utiliza solo una interfaz local para escuchar. Ejecuta msmtpd con los derechos y permisos de usuario correctos (por ejemplo, usa CAP_NET_BIND_SERVICE para enlazar al puerto 25 en lugar de ejecutarse como root, o usa systemd con capacidades de servicio inetd). Ten en cuenta que el comando de canalización se ejecutará como el mismo usuario que msmtpd. Habilita el registro en syslog con --log=syslog.
Ejemplo para gestionar msmtpd con start-stop-daemon:
# Inicia msmtpd
start-stop-daemon --start --pidfile /var/run/msmtpd.pid --make-pidfile --chuid msmtpd --background --exec /usr/local/bin/msmtpd -- --command '/usr/local/bin/msmtp -f %F --'
# Detiene msmtpd
start-stop-daemon --stop --pidfile /var/run/msmtpd.pid --remove-pidfile --quiet --signal TERM
Uso de msmtpd para manejar el correo saliente de un cliente de correo basado en SMTP
Algunos clientes de correo no pueden enviar correo saliente con un programa como msmtp y en su lugar insisten en usar un servidor SMTP. Puedes configurar msmtpd para que sea ese servidor SMTP y le entregue tu correo saliente a msmtp.
(De manera similar, algunos clientes de correo no pueden obtener correo entrante de un buzón local e insisten en usar un servidor POP3 o IMAP. Puedes configurar mpopd para que sea ese servidor POP3 y sirva el correo entrante desde un buzón local. Consulta la sección relevante en el manual de mpop).
Para este propósito, msmtpd debería escuchar en un puerto no privilegiado, por ejemplo, 2500. Además, msmtpd debería requerir autenticación porque de lo contrario cualquiera que se conecte a él puede enviar correo usando tu cuenta, incluso si solo son otros usuarios o procesos en tu máquina local.
Usemos el nombre de usuario msmtpd-user para este propósito. Tienes dos opciones para gestionar la contraseña:

Almacena la contraseña en tu anillo de claves, por ejemplo, con secret-tool store --label=msmtpd host localhost service smtp user msmtpd-user. En este caso, usa la opción de msmtpd --auth=msmtpd-user.
Almacena la contraseña en un archivo cifrado y usa el mecanismo de evalcontraseña. Ejemplo para gpg: msmtpd ... --auth=msmtpd-user,'gpg -q -d ~/.msmtpd-password.gpg'

El comando completo sería entonces (usando el anillo de claves): msmtpd --port=2500 --auth=msmtpd-user --command='/path/to/your/msmtp -f %F --'
El software cliente de correo deberá configurarse para usar localhost en el puerto 2500 para el correo saliente a través de SMTP, y para usar autenticación con el usuario msmtpd-user y la contraseña que elegiste. El cliente de correo probablemente se quejará de que el servidor SMTP no soporta TLS, pero en este caso especial eso está bien ya que toda la comunicación entre tu cliente de correo y msmtpd permanecerá en la máquina local.
Esta configuración también funciona con múltiples cuentas de correo. Msmtp elegirá la correcta basándose en la dirección del remitente del sobre que se le proporciona a través de -f %F. No necesitas múltiples instancias de msmtpd para este propósito, y por lo tanto solo necesitas un servidor SMTP en la configuración de tu cliente de correo.
