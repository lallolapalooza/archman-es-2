MSGRCV(3P) Manual del programador POSIX MSGRCV(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual correspondiente de Linux para detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

msgrcv — operación de recepción de mensajes XSI

SINOPSIS

#include <sys/msg.h>
ssize_t msgrcv(int msqid, void *msgp, size_t msgsz, long msgtyp,
    int msgflg);

DESCRIPCIÓN

La función msgrcv() opera sobre colas de mensajes XSI (ver el volumen de Definiciones Base de POSIX.1-2017, Sección 3.226, Cola de mensajes). No está especificado si esta función interopera con las facilidades de comunicación entre procesos en tiempo real definidas en la Sección 2.8, Tiempo Real.

La función msgrcv() leerá un mensaje de la cola asociada al identificador de cola de mensajes especificado por msqid y lo colocará en el búfer definido por el usuario apuntado por msgp.

La aplicación deberá asegurarse de que el argumento msgp apunte a un búfer definido por el usuario que contenga primero un campo de tipo long especificando el tipo del mensaje, y luego una porción de datos que contenga los bytes de datos del mensaje. La siguiente estructura es un ejemplo de cómo podría ser este búfer definido por el usuario:

struct mymsg {
    long    mtype;     /* Tipo de mensaje. */
    char    mtext[1];  /* Texto del mensaje. */
}

El miembro de la estructura mtype es el tipo del mensaje recibido tal como lo especificó el proceso de envío.

El miembro de la estructura mtext es el texto del mensaje.

El argumento msgsz especifica el tamaño en bytes de mtext. El mensaje recibido se truncará a msgsz bytes si es mayor que msgsz y (msgflg & MSG_NOERROR) es distinto de cero. La parte truncada del mensaje se perderá y no se dará ninguna indicación de la truncación al proceso que llama.

Si el valor de msgsz es mayor que {SSIZE_MAX}, el resultado está definido por la implementación.

El argumento msgtyp especifica el tipo de mensaje solicitado como sigue:

*
Si msgtyp es 0, se recibirá el primer mensaje de la cola.
*
Si msgtyp es mayor que 0, se recibirá el primer mensaje de tipo msgtyp.
*
Si msgtyp es menor que 0, se recibirá el primer mensaje del tipo más bajo que sea menor o igual al valor absoluto de msgtyp.

El argumento msgflg especifica la acción que se tomará si un mensaje del tipo deseado no está en la cola. Estas son las siguientes:

*
Si (msgflg & IPC_NOWAIT) es distinto de cero, el hilo que llama retornará inmediatamente con un valor de retorno de -1 y errno establecido en [ENOMSG].
*
Si (msgflg & IPC_NOWAIT) es 0, el hilo que llama suspenderá su ejecución hasta que ocurra una de las siguientes:
--
Se coloca un mensaje del tipo deseado en la cola.
--
El identificador de cola de mensajes msqid se elimina del sistema; cuando esto ocurre, errno se establecerá en [EIDRM] y se retornará -1.
--
El hilo que llama recibe una señal que debe ser capturada; en este caso, no se recibe ningún mensaje y el hilo que llama reanuda la ejecución de la manera prescrita en sigaction().

Al completarse con éxito, se toman las siguientes acciones con respecto a la estructura de datos asociada a msqid:

*
msg_qnum se decrementará en 1.
*
msg_lrpid se establecerá en el ID del proceso del proceso que llama.
*
msg_rtime se establecerá en la hora actual, tal como se describe en la Sección 2.7.1, Descripción General de IPC.

VALOR DE RETORNO

Al completarse con éxito, msgrcv() devolverá un valor igual al número de bytes que se colocaron realmente en el búfer mtext. En caso contrario, no se recibirá ningún mensaje, msgrcv() devolverá -1 y errno se establecerá para indicar el error.

ERRORES

La función msgrcv() fallará si:

E2BIG
El valor de mtext es mayor que msgsz y (msgflg & MSG_NOERROR) es 0.
EACCES
Se niega el permiso de operación al proceso que llama; ver la Sección 2.7, Comunicación entre procesos XSI.
EIDRM
El identificador de cola de mensajes msqid se elimina del sistema.
EINTR
La función msgrcv() fue interrumpida por una señal.
EINVAL
msqid no es un identificador de cola de mensajes válido.
ENOMSG
La cola no contiene un mensaje del tipo deseado y (msgflg & IPC_NOWAIT) es distinto de cero.

EJEMPLOS

Recepción de un Mensaje

El siguiente ejemplo recibe el primer mensaje de la cola (basado en el valor del argumento msgtyp, 0). La cola se identifica por el argumento msqid (suponiendo que el valor se ha establecido previamente). Esta llamada especifica que se debe informar de un error si no hay ningún mensaje disponible, pero no si el mensaje es demasiado grande. El tamaño del mensaje se calcula directamente utilizando el operador sizeof.

#include <sys/msg.h>
...
int result;
int msqid;
struct message {
    long type;
    char text[20];
} msg;
long msgtyp = 0;
...
result = msgrcv(msqid, (void *) &msg, sizeof(msg.text),
         msgtyp, MSG_NOERROR | IPC_NOWAIT);

USO DE APLICACIONES

La Extensión de Tiempo Real POSIX define interfaces alternativas para la comunicación entre procesos (IPC). Los desarrolladores de aplicaciones que necesiten utilizar IPC deben diseñar sus aplicaciones de manera que los módulos que utilicen las rutinas IPC descritas en la Sección 2.7, Comunicación entre procesos XSI, puedan modificarse fácilmente para utilizar las interfaces alternativas.
