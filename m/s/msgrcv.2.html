MSGOP(2) Manual de Llamadas al Sistema MSGOP(2)

NOMBRE

msgrcv, msgsnd - Operaciones de colas de mensajes System V

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/msg.h>
ssize_t msgrcv(int msqid, void msgp[msgsz], size_t msgsz, long msgtyp,
               int msgflg);
int msgsnd(int msqid, const void msgp[msgsz], size_t msgsz,
               int msgflg);

DESCRIPCIÓN

Las llamadas al sistema msgsnd() y msgrcv() se utilizan para enviar mensajes a, y recibir mensajes de, una cola de mensajes de System V. El proceso que llama debe tener permiso de escritura en la cola de mensajes para poder enviar un mensaje, y permiso de lectura para recibir un mensaje.

El argumento msgp es un puntero a una estructura definida por el llamante de la siguiente forma general:


struct msgbuf {
    long mtype;       /* tipo de mensaje, debe ser > 0 */
    char mtext[1];    /* datos del mensaje */
};

El campo mtext es un array (u otra estructura) cuyo tamaño se especifica por msgsz, un valor entero no negativo. Se permiten mensajes de longitud cero (es decir, sin campo mtext). El campo mtype debe tener un valor entero estrictamente positivo. Este valor puede ser utilizado por el proceso receptor para la selección de mensajes (ver la descripción de msgrcv() más abajo).

msgsnd()

La llamada al sistema msgsnd() adjunta una copia del mensaje apuntado por msgp a la cola de mensajes identificada por msqid.

Si hay espacio suficiente en la cola, msgsnd() tiene éxito inmediatamente. La capacidad de la cola se rige por el campo msg_qbytes en la estructura de datos asociada a la cola de mensajes. Durante la creación de la cola, este campo se inicializa a MSGMNB bytes, pero este límite se puede modificar usando msgctl(2). Una cola de mensajes se considera llena si se cumple alguna de las siguientes condiciones:

•
Añadir un nuevo mensaje a la cola haría que el número total de bytes en la cola superase el tamaño máximo de la cola (el campo msg_qbytes).
•
Añadir otro mensaje a la cola haría que el número total de mensajes en la cola superase el tamaño máximo de la cola (el campo msg_qbytes). Esta comprobación es necesaria para evitar que se coloquen un número ilimitado de mensajes de longitud cero en la cola. Aunque tales mensajes no contienen datos, consumen memoria del kernel (bloqueada).

Si no hay espacio suficiente en la cola, el comportamiento por defecto de msgsnd() es bloquear hasta que haya espacio disponible. Si se especifica IPC_NOWAIT en msgflg, la llamada falla con el error EAGAIN.

Una llamada bloqueada a msgsnd() también puede fallar si:

•
se elimina la cola, en cuyo caso la llamada al sistema falla con errno establecido a EIDRM; o
•
se captura una señal, en cuyo caso la llamada al sistema falla con errno establecido a EINTR; ver signal(7). (msgsnd() nunca se reinicia automáticamente después de ser interrumpida por un manejador de señal, independientemente de la configuración del flag SA_RESTART al establecer un manejador de señal.)

Tras una finalización exitosa, la estructura de datos de la cola de mensajes se actualiza de la siguiente manera:

•
msg_lspid se establece al ID del proceso que llama.
•
msg_qnum se incrementa en 1.
•
msg_stime se establece a la hora actual.

msgrcv()

La llamada al sistema msgrcv() elimina un mensaje de la cola especificada por msqid y lo coloca en el buffer apuntado por msgp.

El argumento msgsz especifica el tamaño máximo en bytes para el miembro mtext de la estructura apuntada por el argumento msgp. Si el texto del mensaje tiene una longitud mayor que msgsz, el comportamiento depende de si MSG_NOERROR está especificado en msgflg. Si se especifica MSG_NOERROR, el texto del mensaje se truncará (y la parte truncada se perderá); si MSG_NOERROR no está especificado, el mensaje no se eliminará de la cola y la llamada al sistema fallará devolviendo -1 con errno establecido a E2BIG.

A menos que MSG_COPY se especifique en msgflg (ver más abajo), el argumento msgtyp especifica el tipo de mensaje solicitado, de la siguiente manera:

•
Si msgtyp es 0, se lee el primer mensaje de la cola.
•
Si msgtyp es mayor que 0, se lee el primer mensaje de la cola de tipo msgtyp, a menos que MSG_EXCEPT se haya especificado en msgflg, en cuyo caso se leerá el primer mensaje de la cola de tipo distinto de msgtyp.
•
Si msgtyp es menor que 0, se leerá el primer mensaje de la cola con el tipo más bajo menor o igual al valor absoluto de msgtyp.

El argumento msgflg es una máscara de bits construida mediante la combinación lógica OR de cero o más de los siguientes flags:

IPC_NOWAIT
Retornar inmediatamente si no hay un mensaje del tipo solicitado en la cola. La llamada al sistema falla con errno establecido a ENOMSG.
MSG_COPY (desde Linux 3.8)
Obtener de forma no destructiva una copia del mensaje en la posición ordinal en la cola especificada por msgtyp (los mensajes se consideran numerados a partir de 0).
Este flag debe especificarse junto con IPC_NOWAIT, con el resultado de que, si no hay un mensaje disponible en la posición dada, la llamada falla inmediatamente con el error ENOMSG. Dado que alteran el significado de msgtyp de formas ortogonales, MSG_COPY y MSG_EXCEPT no pueden especificarse ambos en msgflg.
El flag MSG_COPY se añadió para la implementación de la instalación de punto de control-restauración del kernel y solo está disponible si el kernel se compiló con la opción CONFIG_CHECKPOINT_RESTORE.
MSG_EXCEPT
Usado con msgtyp mayor que 0 para leer el primer mensaje en la cola con un tipo de mensaje diferente a msgtyp.
MSG_NOERROR
Para truncar el texto del mensaje si es más largo que msgsz bytes.

Si no hay ningún mensaje del tipo solicitado disponible y IPC_NOWAIT no está especificado en msgflg, el proceso que llama se bloquea hasta que ocurra alguna de las siguientes condiciones:

•
Se coloca un mensaje del tipo deseado en la cola.
•
La cola de mensajes se elimina del sistema. En este caso, la llamada al sistema falla con errno establecido a EIDRM.
•
El proceso que llama captura una señal. En este caso, la llamada al sistema falla con errno establecido a EINTR. (msgrcv() nunca se reinicia automáticamente después de ser interrumpida por un manejador de señal, independientemente de la configuración del flag SA_RESTART al establecer un manejador de señal.)

Tras una finalización exitosa, la estructura de datos de la cola de mensajes se actualiza de la siguiente manera:

msg_lrpid se establece al ID del proceso que llama.
msg_qnum se decrementa en 1.
msg_rtime se establece a la hora actual.

VALOR DE RETORNO

En caso de éxito, msgsnd() devuelve 0 y msgrcv() devuelve el número de bytes realmente copiados en el array mtext. En caso de fallo, ambas funciones devuelven -1 y establecen errno para indicar el error.

ERRORS

msgsnd() puede fallar con los siguientes errores:

EACCES
El proceso que llama no tiene permiso de escritura en la cola de mensajes, y no tiene la capacidad CAP_IPC_OWNER en el espacio de nombres de usuario que rige su espacio de nombres IPC.
EAGAIN
El mensaje no se puede enviar debido al límite de msg_qbytes para la cola y se especificó IPC_NOWAIT en msgflg.
EFAULT
La dirección apuntada por msgp no es accesible.
EIDRM
La cola de mensajes fue eliminada.
EINTR
Al esperar en la condición de cola de mensajes llena, el proceso capturó una señal.
EINVAL
Valor de msqid inválido, o valor de mtype no positivo, o valor de msgsz inválido (menor que 0 o mayor que el valor del sistema MSGMAX).
ENOMEM
El sistema no tiene suficiente memoria para hacer una copia del mensaje apuntado por msgp.

msgrcv() puede fallar con los siguientes errores:

E2BIG
La longitud del texto del mensaje es mayor que msgsz y MSG_NOERROR no está especificado en msgflg.
EACCES
El proceso que llama no tiene permiso de lectura en la cola de mensajes, y no tiene la capacidad CAP_IPC_OWNER en el espacio de nombres de usuario que rige su espacio de nombres IPC.
EFAULT
La dirección apuntada por msgp no es accesible.
EIDRM
Mientras el proceso esperaba para recibir un mensaje, la cola de mensajes fue eliminada.
EINTR
Mientras el proceso esperaba para recibir un mensaje, el proceso capturó una señal; ver signal(7).
EINVAL
msqid era inválido, o msgsz era menor que 0.
EINVAL (desde Linux 3.14)
msgflg especificó MSG_COPY, pero no IPC_NOWAIT.
EINVAL (desde Linux 3.14)
msgflg especificó tanto MSG_COPY como MSG_EXCEPT.
ENOMSG
Se especificó IPC_NOWAIT en msgflg y no existía ningún mensaje del tipo solicitado en la cola de mensajes.
ENOMSG
Se especificaron IPC_NOWAIT y MSG_COPY en msgflg y la cola contiene menos de msgtyp mensajes.
ENOSYS (desde Linux 3.8)
Se especificaron tanto MSG_COPY como IPC_NOWAIT en msgflg, y este kernel fue configurado sin CONFIG_CHECKPOINT_RESTORE.

ESTÁNDARES

POSIX.1-2024.

Las banderas MSG_EXCEPT y MSG_COPY son específicas de Linux; sus definiciones se pueden obtener definiendo el macro de prueba de características _GNU_SOURCE.

HISTORIA

POSIX.1-2001, SVr4.

El argumento msgp se declara como struct msgbuf * en glibc 2.0 y 2.1. Se declara como void * en glibc 2.2 y posteriores, según lo requerido por SUSv2 y SUSv3.

NOTAS

Los siguientes límites en los recursos de la cola de mensajes afectan a la llamada msgsnd():

MSGMAX
Tamaño máximo del texto de un mensaje, en bytes (valor predeterminado: 8192 bytes). En Linux, este límite se puede leer y modificar a través de /proc/sys/kernel/msgmax.
MSGMNB
Número máximo de bytes que se pueden almacenar en una cola de mensajes (valor predeterminado: 16384 bytes). En Linux, este límite se puede leer y modificar a través de /proc/sys/kernel/msgmnb. Un proceso privilegiado (Linux: un proceso con la capacidad CAP_SYS_RESOURCE) puede aumentar el tamaño de una cola de mensajes más allá de MSGMNB utilizando la operación IPC_SET de msgctl(2).

La implementación no tiene límites intrínsecos a nivel de sistema en el número de cabeceras de mensaje (MSGTQL) y el número de bytes en el grupo de mensajes (MSGPOOL).

ERRORES

En Linux 3.13 y anteriores, si se llamaba a msgrcv() con la bandera MSG_COPY, pero sin IPC_NOWAIT, y la cola de mensajes contenía menos de msgtyp mensajes, entonces la llamada se bloquearía hasta que el siguiente mensaje se escribiera en la cola. En ese momento, la llamada devolvería una copia del mensaje, *independientemente* de si ese mensaje estaba en la posición ordinal msgtyp. Este error se corrigió en Linux 3.14.

Especificar tanto MSG_COPY como MSC_EXCEPT en msgflg es un error lógico (ya que estas banderas imponen interpretaciones diferentes a msgtyp). En Linux 3.13 y anteriores, este error no fue diagnosticado por msgrcv(). Este error se corrigió en Linux 3.14.

EJEMPLOS

El programa a continuación demuestra el uso de msgsnd() y msgrcv().

El programa de ejemplo se ejecuta primero con la opción -s para enviar un mensaje y luego se vuelve a ejecutar con la opción -r para recibir un mensaje.

La siguiente sesión de shell muestra un ejemplo de ejecución del programa:


$ ./a.out -s
sent: a message at Wed Mar  4 16:25:45 2015
$ ./a.out -r
message received: a message at Wed Mar  4 16:25:45 2015

Fuente del programa

#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/ipc.h>
#include <sys/msg.h>
#include <time.h>
#include <unistd.h>
struct msgbuf {
    long mtype;
    char mtext[80];
};
static void
usage(char *prog_name, char *msg)
{
    if (msg != NULL)
        fputs(msg, stderr);
    fprintf(stderr, "Usage: %s [options]\n", prog_name);
    fprintf(stderr, "Options are:\n");
    fprintf(stderr, "-s        send message using msgsnd()\n");
    fprintf(stderr, "-r        read message using msgrcv()\n");
    fprintf(stderr, "-t        message type (default is 1)\n");
    fprintf(stderr, "-k        message queue key (default is 1234)\n");
    exit(EXIT_FAILURE);
}
static void
send_msg(int qid, int msgtype)
{
    time_t         t;
    struct msgbuf  msg;
    msg.mtype = msgtype;
    time(&t);
    snprintf(msg.mtext, sizeof(msg.mtext), "a message at %s",
             ctime(&t));
    if (msgsnd(qid, &msg, sizeof(msg.mtext),
               IPC_NOWAIT) == -1)
    {
        perror("msgsnd error");
        exit(EXIT_FAILURE);
    }
    printf("sent: %s\n", msg.mtext);
}
static void
get_msg(int qid, int msgtype)
{
    struct msgbuf msg;
    if (msgrcv(qid, &msg, sizeof(msg.mtext), msgtype,
               MSG_NOERROR | IPC_NOWAIT) == -1) {
        if (errno != ENOMSG) {
            perror("msgrcv");
            exit(EXIT_FAILURE);
        }
        printf("No message available for msgrcv()\n");
    } else {
        printf("message received: %s\n", msg.mtext);
    }
}
int
main(int argc, char *argv[])
{
    int  qid, opt;
    int  mode = 0;               /* 1 = send, 2 = receive */
    int  msgtype = 1;
    int  msgkey = 1234;
    while ((opt = getopt(argc, argv, "srt:k:")) != -1) {
        switch (opt) {
        case 's':
            mode = 1;
            break;
        case 'r':
            mode = 2;
            break;
        case 't':
            msgtype = atoi(optarg);
            if (msgtype <= 0)
                usage(argv[0], "-t option must be greater than 0\n");
            break;
        case 'k':
            msgkey = atoi(optarg);
            break;
        default:
            usage(argv[0], "Unrecognized option\n");
        }
    }
    if (mode == 0)
        usage(argv[0], "must use either -s or -r option\n");
    qid = msgget(msgkey, IPC_CREAT | 0666);
    if (qid == -1) {
        perror("msgget");
        exit(EXIT_FAILURE);
    }
    if (mode == 2)
        get_msg(qid, msgtype);
    else
        send_msg(qid, msgtype);
    exit(EXIT_SUCCESS);
}

msgrcv(2) - Arch Linux Man Pages

NAME

msgrcv - leer mensajes de una cola de mensajes

LIBRARY

Biblioteca de C estándar (libc, -lc)

SYNOPSIS

#include <sys/msg.h>

ssize_t msgrcv(int msqid, void *msgp, size_t msgsz, long msgtyp, int msgflg);

DESCRIPTION

La llamada al sistema msgrcv lee un mensaje de la cola de mensajes identificada por msqid y lo coloca en el búfer cuya dirección se especifica en msgp. El argumento msgsz especifica el tamaño en bytes del búfer al que apunta msgp. Este tamaño debe ser mayor o igual que el miembro msg_qbytes de la estructura de datos asociada a la cola de mensajes.

El argumento msgtyp especifica el tipo de mensajes que se desea leer. Este argumento determina qué mensaje se lee de la cola:

  • Si msgtyp es 0, se lee el primer mensaje de la cola.
  • Si msgtyp es mayor que 0, se lee el primer mensaje de la cola cuyo tipo coincide con msgtyp.
  • Si msgtyp es menor que 0, se lee el primer mensaje de la cola cuyo tipo es menor o igual que el valor absoluto de msgtyp.

El argumento msgflg controla el comportamiento de msgrcv:

  • Si msgflg es 0, la llamada bloquea hasta que un mensaje adecuado esté disponible.
  • Si msgflg tiene el bit IPC_NOWAIT establecido, la llamada no espera y devuelve un error si no hay un mensaje adecuado disponible.
  • Si msgflg tiene el bit IPC_LARGE establecido, el tamaño del mensaje devuelto puede ser mayor que el valor especificado en msgsz. Si el mensaje es demasiado grande para caber en el búfer, los bytes adicionales se descartan.

Al leer un mensaje, se almacena la siguiente información en la estructura de memoria a la que apunta msgp:

  • long msg_type: el tipo del mensaje.
  • char msg_text[...]: el texto del mensaje (hasta msgsz bytes).
  • ssize_t msg_len: la longitud del texto del mensaje en bytes.

La llamada al sistema msgrcv también actualiza las estadísticas asociadas a la cola de mensajes, como el tiempo del último mensaje recibido y el número de bytes en la cola.

RETURN VALUE

Al éxito, msgrcv devuelve el número de bytes copiados en el búfer de mensaje. Si ocurre un error, devuelve -1 y establece errno para indicar el error.

ERRORS

E2BIG
El texto del mensaje es más largo que el tamaño del búfer y el msgflg no tiene el bit IPC_LARGE.
EACCES
No hay permiso para leer de la cola de mensajes.
EIDRM
La cola de mensajes ha sido eliminada.
EINTR
La llamada fue interrumpida por una señal mientras estaba bloqueada.
EINVAL
msqid no es un ID de cola de mensajes válido, o msgp apunta a una dirección inválida.
ENOMSG
No hay ningún mensaje de los tipos solicitados disponible y msgflg tiene el bit IPC_NOWAIT establecido.

STANDARDS

UNIX 98, POSIX.1-2001.

HISTORY

System V.

NOTES

La función msgrcv es parte de la interfaz de IPC (Inter-Process Communication) de System V.

El tamaño del búfer msgsz debe ser lo suficientemente grande para almacenar el texto del mensaje, además de la estructura msghdr (o una estructura similar definida por el usuario) que contiene el tipo de mensaje y el texto.

Al usar IPC_NOWAIT, si no hay un mensaje disponible, msgrcv devuelve -1 y errno se establece en ENOMSG. Si la llamada se interrumpe por una señal, devuelve -1 y errno se establece en EINTR.

BUGS

La implementación de las colas de mensajes de System V puede tener limitaciones en cuanto al número de colas de mensajes y al tamaño de los mensajes que se pueden almacenar.

EXAMPLES

El siguiente ejemplo muestra cómo leer un mensaje de una cola de mensajes:

#include <sys/msg.h>
#include <stdio.h>
#include <stdlib.h>

struct msgbuf {
    long mtype;
    char mtext[200];
};

int main() {
    int msqid;
    struct msgbuf rbuf;
    ssize_t msglen;

    // Obtener la ID de la cola de mensajes (reemplazar con la ID real)
    msqid = msgget((key_t)12345, IPC_CREAT | 0666);
    if (msqid == -1) {
        perror("msgget");
        exit(1);
    }

    // Leer un mensaje (tipo 1) de la cola de mensajes
    msglen = msgrcv(msqid, &rbuf, sizeof(rbuf.mtext), 1, 0);
    if (msglen == -1) {
        perror("msgrcv");
        exit(1);
    }

    printf("Mensaje recibido (longitud %zd): %s\n", msglen, rbuf.mtext);

    // Eliminar la cola de mensajes (opcional)
    // if (msgctl(msqid, IPC_RMID, NULL) == -1) {
    //     perror("msgctl");
    //     exit(1);
    // }

    return 0;
}
