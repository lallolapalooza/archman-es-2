MSGOP(2) Manual de llamadas al sistema MSGOP(2)

NOMBRE

msgrcv, msgsnd - Operaciones de colas de mensajes de System V

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/msg.h>
ssize_t msgrcv(size_t msgsz;
               int msqid, void msgp[msgsz], size_t msgsz, long msgtyp,
               int msgflg);
int msgsnd(size_t msgsz;
               int msqid, const void msgp[msgsz], size_t msgsz,
               int msgflg);

DESCRIPCIÓN

Las llamadas al sistema msgsnd() y msgrcv() se utilizan para enviar mensajes a, y recibir mensajes de, una cola de mensajes de System V. El proceso que llama debe tener permiso de escritura en la cola de mensajes para enviar un mensaje, y permiso de lectura para recibir un mensaje.

El argumento msgp es un puntero a una estructura definida por el llamante de la siguiente forma general:


struct msgbuf {
    long mtype;       /* tipo de mensaje, debe ser > 0 */
    char mtext[1];    /* datos del mensaje */
};

El campo mtext es un array (u otra estructura) cuyo tamaño se especifica mediante msgsz, un valor entero no negativo. Se permiten mensajes de longitud cero (es decir, sin campo mtext). El campo mtype debe tener un valor entero estrictamente positivo. Este valor puede ser utilizado por el proceso receptor para la selección de mensajes (véase la descripción de msgrcv() más adelante).

msgsnd()

La llamada al sistema msgsnd() añade una copia del mensaje apuntado por msgp a la cola de mensajes cuyo identificador se especifica mediante msqid.

Si hay suficiente espacio disponible en la cola, msgsnd() tiene éxito inmediatamente. La capacidad de la cola se rige por el campo msg_qbytes en la estructura de datos asociada para la cola de mensajes. Durante la creación de la cola, este campo se inicializa a MSGMNB bytes, pero este límite se puede modificar usando msgctl(2). Una cola de mensajes se considera llena si se cumple alguna de las siguientes condiciones:

•
Añadir un nuevo mensaje a la cola haría que el número total de bytes en la cola superase el tamaño máximo de la cola (el campo msg_qbytes).
•
Añadir otro mensaje a la cola haría que el número total de mensajes en la cola superase el tamaño máximo de la cola (el campo msg_qbytes). Esta comprobación es necesaria para evitar que se coloquen un número ilimitado de mensajes de longitud cero en la cola. Aunque dichos mensajes no contienen datos, consumen memoria del kernel (bloqueada).

Si no hay suficiente espacio disponible en la cola, el comportamiento predeterminado de msgsnd() es bloquear hasta que haya espacio disponible. Si se especifica IPC_NOWAIT en msgflg, la llamada falla con el error EAGAIN.

Una llamada bloqueada a msgsnd() también puede fallar si:

•
la cola se elimina, en cuyo caso la llamada al sistema falla con errno establecido a EIDRM; o
•
se captura una señal, en cuyo caso la llamada al sistema falla con errno establecido a EINTR; véase signal(7). (msgsnd() nunca se reinicia automáticamente después de ser interrumpida por un manejador de señales, independientemente de la configuración del flag SA_RESTART al establecer un manejador de señales.)

Tras una finalización exitosa, la estructura de datos de la cola de mensajes se actualiza de la siguiente manera:

•
msg_lspid se establece al ID de proceso del proceso que llama.
•
msg_qnum se incrementa en 1.
•
msg_stime se establece a la hora actual.

msgrcv()

La llamada al sistema msgrcv() elimina un mensaje de la cola especificada por msqid y lo coloca en el buffer apuntado por msgp.

El argumento msgsz especifica el tamaño máximo en bytes para el miembro mtext de la estructura apuntada por el argumento msgp. Si el texto del mensaje tiene una longitud mayor que msgsz, el comportamiento depende de si MSG_NOERROR está especificado en msgflg. Si se especifica MSG_NOERROR, el texto del mensaje se truncará (y la parte truncada se perderá); si no se especifica MSG_NOERROR, el mensaje no se eliminará de la cola y la llamada al sistema fallará devolviendo -1 con errno establecido a E2BIG.

A menos que se especifique MSG_COPY en msgflg (véase más abajo), el argumento msgtyp especifica el tipo de mensaje solicitado, de la siguiente manera:

•
Si msgtyp es 0, se lee el primer mensaje de la cola.
•
Si msgtyp es mayor que 0, se lee el primer mensaje de la cola de tipo msgtyp, a menos que se haya especificado MSG_EXCEPT en msgflg, en cuyo caso se leerá el primer mensaje de la cola de tipo distinto de msgtyp.
•
Si msgtyp es menor que 0, se leerá el primer mensaje de la cola con el tipo más bajo menor o igual al valor absoluto de msgtyp.

El argumento msgflg es una máscara de bits construida combinando con OR cero o más de los siguientes flags:

IPC_NOWAIT
Devuelve inmediatamente si no hay un mensaje del tipo solicitado en la cola. La llamada al sistema falla con errno establecido a ENOMSG.
MSG_COPY (desde Linux 3.8)
Obtiene de forma no destructiva una copia del mensaje en la posición ordinal de la cola especificada por msgtyp (los mensajes se consideran numerados a partir de 0).
Este flag debe especificarse junto con IPC_NOWAIT, con el resultado de que, si no hay un mensaje disponible en la posición dada, la llamada falla inmediatamente con el error ENOMSG. Dado que alteran el significado de msgtyp de maneras ortogonales, MSG_COPY y MSG_EXCEPT no pueden especificarse ambos en msgflg.
El flag MSG_COPY se añadió para la implementación de la facilidad de restauración de puntos de control del kernel y solo está disponible si el kernel se compiló con la opción CONFIG_CHECKPOINT_RESTORE.
MSG_EXCEPT
Se utiliza con msgtyp mayor que 0 para leer el primer mensaje en la cola con un tipo de mensaje distinto de msgtyp.
MSG_NOERROR
Para truncar el texto del mensaje si es más largo que msgsz bytes.

Si no hay un mensaje del tipo solicitado disponible y IPC_NOWAIT no está especificado en msgflg, el proceso que llama se bloquea hasta que ocurra alguna de las siguientes condiciones:

•
Se coloca un mensaje del tipo deseado en la cola.
•
La cola de mensajes se elimina del sistema. En este caso, la llamada al sistema falla con errno establecido a EIDRM.
•
El proceso que llama captura una señal. En este caso, la llamada al sistema falla con errno establecido a EINTR. (msgrcv() nunca se reinicia automáticamente después de ser interrumpida por un manejador de señales, independientemente de la configuración del flag SA_RESTART al establecer un manejador de señales.)

Tras una finalización exitosa, la estructura de datos de la cola de mensajes se actualiza de la siguiente manera:

msg_lrpid se establece al ID de proceso del proceso que llama.
msg_qnum se decrementa en 1.
msg_rtime se establece a la hora actual.

VALOR DEVUELTO

En caso de éxito, msgsnd() devuelve 0 y msgrcv() devuelve el número de bytes copiados realmente en el array mtext. En caso de error, ambas funciones devuelven -1 y establecen errno para indicar el error.

ERRORES

E2BIG
El tamaño del texto del mensaje es mayor que msgsz y no se especificó MSG_NOERROR.
EACCES
El proceso no tiene permiso de escritura en la cola (para msgsnd()) o permiso de lectura (para msgrcv()).
EAGAIN
Se especificó IPC_NOWAIT y la cola de mensajes está llena (para msgsnd()) o no hay ningún mensaje disponible del tipo solicitado (para msgrcv()).
EFAULT
msgp apunta fuera del espacio de direcciones accesible del usuario.
EIDRM
La cola de mensajes fue eliminada mientras se esperaba para enviar o recibir un mensaje.
EINTR
Se recibió una señal mientras el proceso estaba bloqueado esperando para enviar o recibir un mensaje.
EINVAL
msqid no es un identificador de cola de mensajes válido. O bien msgsz es negativo, o bien es mayor que el valor de MSGMAX. O bien msgp es NULL. O bien se especificaron flags inválidos en msgflg (por ejemplo, tanto MSG_COPY como MSG_EXCEPT).
ENOMSG
No se encontró ningún mensaje del tipo solicitado y se especificó IPC_NOWAIT.
ENOSPC
Se alcanzó el límite de espacio en la cola de mensajes (para msgsnd()).
ENOTTY
Se especificó MSG_COPY y msgtyp no se refiere a un mensaje que existe en la cola.

ESTÁNDARES

Las llamadas al sistema msgsnd() y msgrcv() se describen en la especificación POSIX.1-2008.

HISTORIA

Estas llamadas al sistema aparecieron por primera vez en System V.

El flag MSG_COPY se añadió en Linux 3.8.

ERRORS

msgsnd() can fail with the following errors:

EACCES
El proceso que llama no tiene permiso de escritura en la cola de mensajes y no tiene la capacidad CAP_IPC_OWNER en el espacio de nombres del usuario que rige su espacio de nombres IPC.
EAGAIN
El mensaje no se puede enviar debido al límite de msg_qbytes para la cola y se especificó IPC_NOWAIT en msgflg.
EFAULT
La dirección apuntada por msgp no es accesible.
EIDRM
La cola de mensajes fue eliminada.
EINTR
Al esperar por una condición de cola de mensajes llena, el proceso recibió una señal.
EINVAL
Valor msqid inválido, o valor mtype no positivo, o valor msgsz inválido (menor que 0 o mayor que el valor del sistema MSGMAX).
ENOMEM
El sistema no tiene suficiente memoria para hacer una copia del mensaje apuntado por msgp.

msgrcv() can fail with the following errors:

E2BIG
La longitud del texto del mensaje es mayor que msgsz y no se especificó MSG_NOERROR en msgflg.
EACCES
El proceso que llama no tiene permiso de lectura en la cola de mensajes y no tiene la capacidad CAP_IPC_OWNER en el espacio de nombres del usuario que rige su espacio de nombres IPC.
EFAULT
La dirección apuntada por msgp no es accesible.
EIDRM
Mientras el proceso estaba esperando para recibir un mensaje, la cola de mensajes fue eliminada.
EINTR
Mientras el proceso estaba esperando para recibir un mensaje, el proceso recibió una señal; véase signal(7).
EINVAL
msqid era inválido, o msgsz era menor que 0.
EINVAL (desde Linux 3.14)
msgflg especificó MSG_COPY, pero no IPC_NOWAIT.
EINVAL (desde Linux 3.14)
msgflg especificó tanto MSG_COPY como MSG_EXCEPT.
ENOMSG
Se especificó IPC_NOWAIT en msgflg y no existía ningún mensaje del tipo solicitado en la cola de mensajes.
ENOMSG
Se especificaron IPC_NOWAIT y MSG_COPY en msgflg y la cola contiene menos de msgtyp mensajes.
ENOSYS (desde Linux 3.8)
Se especificaron tanto MSG_COPY como IPC_NOWAIT en msgflg, y este kernel se configuró sin CONFIG_CHECKPOINT_RESTORE.

ESTÁNDARES

POSIX.1-2024.

Las banderas MSG_EXCEPT y MSG_COPY son específicas de Linux; sus definiciones se pueden obtener definiendo el macro de prueba de características _GNU_SOURCE.

HISTORIAL

POSIX.1-2001, SVr4.

El argumento msgp se declara como struct msgbuf * en glibc 2.0 y 2.1. Se declara como void * en glibc 2.2 y posteriores, según lo requerido por SUSv2 y SUSv3.

NOTAS

Los siguientes límites en los recursos de las colas de mensajes afectan la llamada msgsnd():

MSGMAX
Tamaño máximo del texto de un mensaje, en bytes (valor predeterminado: 8192 bytes). En Linux, este límite se puede leer y modificar a través de /proc/sys/kernel/msgmax.
MSGMNB
Número máximo de bytes que pueden ser contenidos en una cola de mensajes (valor predeterminado: 16384 bytes). En Linux, este límite se puede leer y modificar a través de /proc/sys/kernel/msgmnb. Un proceso privilegiado (Linux: un proceso con la capacidad CAP_SYS_RESOURCE) puede aumentar el tamaño de una cola de mensajes más allá de MSGMNB usando la operación IPC_SET de msgctl(2).

La implementación no tiene límites intrínsecos a nivel de sistema en el número de cabeceras de mensajes (MSGTQL) y el número de bytes en el pool de mensajes (MSGPOOL).

ERRORES

En Linux 3.13 y versiones anteriores, si se llamaba a msgrcv() con la bandera MSG_COPY, pero sin IPC_NOWAIT, y la cola de mensajes contenía menos de msgtyp mensajes, entonces la llamada se bloqueaba hasta que se escribía el siguiente mensaje en la cola. En ese momento, la llamada devolvía una copia del mensaje, *independientemente* de si ese mensaje estaba en la posición ordinal msgtyp. Este error se corrigió en Linux 3.14.

Especificar tanto MSG_COPY como MSC_EXCEPT en msgflg es un error lógico (ya que estas banderas imponen interpretaciones diferentes a msgtyp). En Linux 3.13 y versiones anteriores, este error no fue diagnosticado por msgrcv(). Este error se corrigió en Linux 3.14.

EJEMPLOS

El siguiente programa demuestra el uso de msgsnd() y msgrcv().

El programa de ejemplo se ejecuta primero con la opción -s para enviar un mensaje y luego se ejecuta nuevamente con la opción -r para recibir un mensaje.

La siguiente sesión de shell muestra una ejecución de ejemplo del programa:


$ ./a.out -s
sent: a message at Wed Mar  4 16:25:45 2015
$ ./a.out -r
message received: a message at Wed Mar  4 16:25:45 2015

Fuente del programa

#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/ipc.h>
#include <sys/msg.h>
#include <time.h>
#include <unistd.h>
struct msgbuf {
    long mtype;
    char mtext[80];
};
static void
usage(char *prog_name, char *msg)
{
    if (msg != NULL)
        fputs(msg, stderr);
    fprintf(stderr, "Usage: %s [options]\n", prog_name);
    fprintf(stderr, "Options are:\n");
    fprintf(stderr, "-s        send message using msgsnd()\n");
    fprintf(stderr, "-r        read message using msgrcv()\n");
    fprintf(stderr, "-t        message type (default is 1)\n");
    fprintf(stderr, "-k        message queue key (default is 1234)\n");
    exit(EXIT_FAILURE);
}
static void
send_msg(int qid, int msgtype)
{
    time_t         t;
    struct msgbuf  msg;
    msg.mtype = msgtype;
    time(&t);
    snprintf(msg.mtext, sizeof(msg.mtext), "a message at %s",
             ctime(&t));
    if (msgsnd(qid, &msg, sizeof(msg.mtext),
               IPC_NOWAIT) == -1)
    {
        perror("msgsnd error");
        exit(EXIT_FAILURE);
    }
    printf("sent: %s\n", msg.mtext);
}
static void
get_msg(int qid, int msgtype)
{
    struct msgbuf msg;
    if (msgrcv(qid, &msg, sizeof(msg.mtext), msgtype,
               MSG_NOERROR | IPC_NOWAIT) == -1) {
        if (errno != ENOMSG) {
            perror("msgrcv");
            exit(EXIT_FAILURE);
        }
        printf("No message available for msgrcv()\n");
    } else {
        printf("message received: %s\n", msg.mtext);
    }
}
int
main(int argc, char *argv[])
{
    int  qid, opt;
    int  mode = 0;               /* 1 = send, 2 = receive */
    int  msgtype = 1;
    int  msgkey = 1234;
    while ((opt = getopt(argc, argv, "srt:k:")) != -1) {
        switch (opt) {
        case 's':
            mode = 1;
            break;
        case 'r':
            mode = 2;
            break;
        case 't':
            msgtype = atoi(optarg);
            if (msgtype <= 0)
                usage(argv[0], "-t option must be greater than 0\n");
            break;
        case 'k':
            msgkey = atoi(optarg);
            break;
        default:
            usage(argv[0], "Unrecognized option\n");
        }
    }
    if (mode == 0)
        usage(argv[0], "must use either -s or -r option\n");
    qid = msgget(msgkey, IPC_CREAT | 0666);
    if (qid == -1) {
        perror("msgget");
        exit(EXIT_FAILURE);
    }
    if (mode == 2)
        get_msg(qid, msgtype);
    else
        send_msg(qid, msgtype);
    exit(EXIT_SUCCESS);
}

NAME

msgsnd - send a message to a POSIX message queue

LIBRARY

Message Queue - POSIX API (librt)

SYNOPSIS

#include <mqueue.h>

ssize_t msgsnd(mqd_t mqdes, const void *msg_ptr, size_t msg_len, int msg_prio);

DESCRIPTION

The msgsnd() function writes the message pointed to by msg_ptr to the message queue whose descriptor is mqdes.

The msg_len argument specifies the length of the message to be sent. This length must not exceed the maximum message size that was specified when the message queue was created (see mq_open(3p)).

The msg_prio argument specifies the priority of the message. The value must be between 0 and MQ_PRIO_MAX - 1 (inclusive). Messages are dequeued in order of priority (lowest value first). If multiple messages have the same priority, they are dequeued in the order they were sent (FIFO).

If the message queue is full (i.e., the number of messages in the queue is equal to the maximum number of messages allowed for the queue), msgsnd() will block, unless mqdes was opened with the O_NONBLOCK flag. If O_NONBLOCK is set and the call would block, msgsnd() will return -1 and set errno to EAGAIN.

If msgsnd() is interrupted by a signal before it has written the message, it returns -1 and sets errno to EINTR.

If mqdes was opened with the O_NONBLOCK flag, and the message queue is full, msgsnd() will return -1 and set errno to EAGAIN.

RETURN VALUE

On success, msgsnd() returns 0. On failure, it returns -1 and sets errno to indicate the error.

ERRORS

EAGAIN
The message queue is full and O_NONBLOCK was set for the message queue descriptor.
EBADF
mqdes is not a valid message queue descriptor.
EINTR
The call was interrupted by a signal.
EINVAL
msg_len is greater than the maximum message size for this message queue, or msg_prio is invalid.
ENOMSG
This is not a valid error for msgsnd. It is listed here for completeness.
OOM
Out of memory.
SIGNAL
This is not a valid error for msgsnd. It is listed here for completeness.

STANDARDS

POSIX.1-2008

HISTORY

POSIX.1-2001

NOTES

The message queue must be created using mq_open(3p) before any messages can be sent to it.

The maximum message size is determined at the time of message queue creation. If the size of the message being sent exceeds this limit, msgsnd() will fail with EINVAL.

If the message queue is full and msgsnd() blocks, it can be interrupted by a signal. If this happens, msgsnd() returns -1 and sets errno to EINTR.

BUGS

There are no known bugs.

EXAMPLES

The following example shows how to send a message to a message queue.

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <mqueue.h>
#include <fcntl.h> // For O_* constants

#define QUEUE_NAME  "/my_queue"
#define MAX_MSG_SIZE 256
#define MSG_PRIO 0

int main() {
    mqd_t mq;
    const char *message = "Hello, message queue!";
    ssize_t msg_len = strlen(message) + 1; // Include null terminator

    // Open the message queue
    mq = mq_open(QUEUE_NAME, O_WRONLY);
    if (mq == (mqd_t)-1) {
        perror("mq_open");
        exit(EXIT_FAILURE);
    }

    // Send the message
    if (msgsnd(mq, message, msg_len, MSG_PRIO) == -1) {
        perror("msgsnd");
        mq_close(mq);
        exit(EXIT_FAILURE);
    }

    printf("Message sent successfully.\n");

    // Close the message queue
    if (mq_close(mq) == -1) {
        perror("mq_close");
        exit(EXIT_FAILURE);
    }

    return 0;
}
