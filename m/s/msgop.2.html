MSGOP(2) Manual de llamadas al sistema MSGOP(2)

NOMBRE

msgrcv, msgsnd - Operaciones de colas de mensajes de System V

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/msg.h>
ssize_t msgrcv(size_t msgsz;
               int msqid, void msgp[msgsz], size_t msgsz, long msgtyp,
               int msgflg);
int msgsnd(size_t msgsz;
               int msqid, const void msgp[msgsz], size_t msgsz,
               int msgflg);

DESCRIPCIÓN

Las llamadas al sistema msgsnd() y msgrcv() se utilizan para enviar mensajes a, y recibir mensajes de, una cola de mensajes de System V. El proceso que llama debe tener permiso de escritura en la cola de mensajes para poder enviar un mensaje, y permiso de lectura para recibir un mensaje.

El argumento msgp es un puntero a una estructura definida por el llamante de la siguiente forma general:


struct msgbuf {
    long mtype;       /* tipo de mensaje, debe ser > 0 */
    char mtext[1];    /* datos del mensaje */
};

El campo mtext es un array (u otra estructura) cuyo tamaño se especifica por msgsz, un valor entero no negativo. Se permiten mensajes de longitud cero (es decir, sin campo mtext). El campo mtype debe tener un valor entero estrictamente positivo. Este valor puede ser utilizado por el proceso receptor para la selección de mensajes (ver la descripción de msgrcv() a continuación).

msgsnd()

La llamada al sistema msgsnd() anexa una copia del mensaje apuntado por msgp a la cola de mensajes cuyo identificador se especifica por msqid.

Si hay espacio suficiente disponible en la cola, msgsnd() tiene éxito inmediatamente. La capacidad de la cola se rige por el campo msg_qbytes en la estructura de datos asociada a la cola de mensajes. Durante la creación de la cola, este campo se inicializa a MSGMNB bytes, pero este límite se puede modificar utilizando msgctl(2). Una cola de mensajes se considera llena si se cumple alguna de las siguientes condiciones:

•
Añadir un nuevo mensaje a la cola haría que el número total de bytes en la cola excediera el tamaño máximo de la cola (el campo msg_qbytes).
•
Añadir otro mensaje a la cola haría que el número total de mensajes en la cola excediera el tamaño máximo de la cola (el campo msg_qbytes). Esta comprobación es necesaria para evitar que se coloquen un número ilimitado de mensajes de longitud cero en la cola. Aunque tales mensajes no contienen datos, consumen memoria del kernel (bloqueada).

Si no hay espacio suficiente disponible en la cola, entonces el comportamiento predeterminado de msgsnd() es bloquear hasta que haya espacio disponible. Si se especifica IPC_NOWAIT en msgflg, entonces la llamada falla en su lugar con el error EAGAIN.

Una llamada bloqueada msgsnd() también puede fallar si:

•
se elimina la cola, en cuyo caso la llamada al sistema falla con errno establecido a EIDRM; o
•
se captura una señal, en cuyo caso la llamada al sistema falla con errno establecido a EINTR; ver signal(7). (msgsnd() nunca se reinicia automáticamente después de ser interrumpida por un manejador de señales, independientemente de la configuración del flag SA_RESTART al establecer un manejador de señales.)

Tras una finalización exitosa, la estructura de datos de la cola de mensajes se actualiza de la siguiente manera:

•
msg_lspid se establece al ID del proceso que llama.
•
msg_qnum se incrementa en 1.
•
msg_stime se establece a la hora actual.

msgrcv()

La llamada al sistema msgrcv() elimina un mensaje de la cola especificada por msqid y lo coloca en el buffer apuntado por msgp.

El argumento msgsz especifica el tamaño máximo en bytes para el miembro mtext de la estructura apuntada por el argumento msgp. Si el texto del mensaje tiene una longitud mayor que msgsz, entonces el comportamiento depende de si se especifica MSG_NOERROR en msgflg. Si se especifica MSG_NOERROR, entonces el texto del mensaje se truncará (y la parte truncada se perderá); si no se especifica MSG_NOERROR, entonces el mensaje no se elimina de la cola y la llamada al sistema falla devolviendo -1 con errno establecido a E2BIG.

A menos que se especifique MSG_COPY en msgflg (ver abajo), el argumento msgtyp especifica el tipo de mensaje solicitado, como sigue:

•
Si msgtyp es 0, entonces se lee el primer mensaje de la cola.
•
Si msgtyp es mayor que 0, entonces se lee el primer mensaje de la cola de tipo msgtyp, a menos que se especificara MSG_EXCEPT en msgflg, en cuyo caso se leerá el primer mensaje de la cola de tipo distinto de msgtyp.
•
Si msgtyp es menor que 0, entonces se leerá el primer mensaje de la cola con el tipo más bajo menor o igual que el valor absoluto de msgtyp.

El argumento msgflg es una máscara de bits construida mediante OR lógico de cero o más de los siguientes flags:

IPC_NOWAIT
Retornar inmediatamente si no hay ningún mensaje del tipo solicitado en la cola. La llamada al sistema falla con errno establecido a ENOMSG.
MSG_COPY (desde Linux 3.8)
Obtener de forma no destructiva una copia del mensaje en la posición ordinal en la cola especificada por msgtyp (los mensajes se consideran numerados a partir de 0).
Este flag debe especificarse junto con IPC_NOWAIT, con el resultado de que, si no hay ningún mensaje disponible en la posición dada, la llamada falla inmediatamente con el error ENOMSG. Dado que alteran el significado de msgtyp de formas ortogonales, MSG_COPY y MSG_EXCEPT no pueden especificarse ambos en msgflg.
El flag MSG_COPY se añadió para la implementación de la facilidad de checkpoint/restore del kernel y solo está disponible si el kernel se compiló con la opción CONFIG_CHECKPOINT_RESTORE.
MSG_EXCEPT
Utilizado con msgtyp mayor que 0 para leer el primer mensaje en la cola con un tipo de mensaje distinto de msgtyp.
MSG_NOERROR
Para truncar el texto del mensaje si es más largo que msgsz bytes.

Si no hay ningún mensaje del tipo solicitado disponible y no se especifica IPC_NOWAIT en msgflg, el proceso que llama se bloquea hasta que ocurra una de las siguientes condiciones:

•
Se coloca un mensaje del tipo deseado en la cola.
•
La cola de mensajes se elimina del sistema. En este caso, la llamada al sistema falla con errno establecido a EIDRM.
•
El proceso que llama captura una señal. En este caso, la llamada al sistema falla con errno establecido a EINTR. (msgrcv() nunca se reinicia automáticamente después de ser interrumpida por un manejador de señales, independientemente de la configuración del flag SA_RESTART al establecer un manejador de señales.)

Tras una finalización exitosa, la estructura de datos de la cola de mensajes se actualiza de la siguiente manera:

msg_lrpid se establece al ID del proceso que llama.
msg_qnum se decrementa en 1.
msg_rtime se establece a la hora actual.

msgop(2)

NOMBRE

msgop - operaciones sobre colas de mensajes

BIBLIOTECA

Biblioteca de C estándar (libc, -lc)

SINOPSIS

#include <sys/msg.h>

int msgget(key_t key, int msgflg);
int msgsnd(int msqid, const void *msgp, size_t msgsz, int msgflg);
ssize_t msgrcv(int msqid, void *msgp, size_t msgsz, long msgtyp, int msgflg);
int msgctl(int msqid, int cmd, struct msqid_ds *buf);

DESCRIPCIÓN

Estas funciones proporcionan una forma de comunicación entre procesos (IPC) utilizando colas de mensajes. Una cola de mensajes es una estructura de datos que almacena en búfer los mensajes que se envían de un proceso a otro. El sistema operativo gestiona las colas de mensajes.

msgget crea una nueva cola de mensajes o devuelve el identificador de una cola de mensajes existente. El argumento key es una clave que identifica la cola de mensajes. El argumento msgflg especifica los permisos y las opciones de creación. Si la clave no existe y se establece la marca IPC_CREAT, se crea una nueva cola. Si la clave existe y se establece IPC_EXCL, se produce un error.

msgsnd envía un mensaje a la cola de mensajes especificada por msqid. El mensaje se copia desde el búfer msgp al espacio del kernel. msgsz especifica el tamaño del mensaje en bytes. msgflg puede contener IPC_NOWAIT para evitar bloquearse si la cola está llena.

msgrcv recibe un mensaje de la cola de mensajes especificada por msqid. El mensaje se copia al búfer msgp. msgsz especifica el tamaño máximo del mensaje a recibir. msgtyp especifica el tipo de mensaje deseado. Si msgtyp es 0, se recibe el siguiente mensaje en la cola. Si msgtyp es positivo, se recibe el primer mensaje de ese tipo. Si msgtyp es negativo, se recibe el primer mensaje cuyo tipo sea menor o igual al valor absoluto de msgtyp. msgflg puede contener IPC_NOWAIT para evitar bloquearse si la cola está vacía o si no hay ningún mensaje del tipo deseado.

msgctl realiza operaciones de control en la cola de mensajes especificada por msqid. El argumento cmd especifica la operación a realizar (por ejemplo, IPC_STAT para obtener información sobre la cola, IPC_SET para establecer permisos, IPC_RMID para eliminar la cola). El argumento buf se utiliza para pasar o recibir datos para la operación.

VALOR DE RETORNO

En caso de éxito, msgget, msgsnd y msgctl devuelven 0. msgrcv devuelve el número de bytes leídos en caso de éxito. En caso de error, todas las funciones devuelven -1 y establecen errno en un valor apropiado.

ERRORES

Las posibles condiciones de error para estas funciones incluyen, entre otras:

  • EACCES: Se denegó el acceso a la cola de mensajes.
  • EEXIST: La cola de mensajes ya existe (con IPC_CREAT | IPC_EXCL).
  • EINVAL: msqid o cmd no es válido.
  • ENOENT: La cola de mensajes no existe.
  • ENOMSG: No hay ningún mensaje del tipo solicitado (con IPC_NOWAIT).
  • ENOSPC: Se excedió el límite del sistema para el número de colas de mensajes o el tamaño de los mensajes.
  • EOVERFLOW: Un mensaje es demasiado grande.

ESTÁNDARES

POSIX.1-2008.

HISTORIA

La implementación de colas de mensajes se introdujo en System V.

NOTAS

El tamaño máximo de un mensaje está limitado por el valor de MSGMAX y el número total de bytes en una cola de mensajes está limitado por MSGMNB.

El uso de claves IPC puede ser complejo. Se recomienda el uso de ftok para generar claves a partir de rutas de archivos.

ERRORES

No se conocen errores.

EJEMPLOS

El siguiente ejemplo muestra cómo enviar y recibir un mensaje simple:

#include <sys/msg.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>

struct msg_buffer {
    long msg_type;
    char msg_text[100];
};

int main() {
    key_t key;
    int msgq_id;
    struct msg_buffer message;
    size_t msg_size;

    // Obtener una clave para la cola de mensajes
    key = ftok("msg_example.txt", 'A');
    if (key == -1) {
        perror("ftok");
        exit(1);
    }

    // Crear o abrir la cola de mensajes
    msgq_id = msgget(key, IPC_CREAT | 0666);
    if (msgq_id == -1) {
        perror("msgget");
        exit(1);
    }

    // Preparar el mensaje para enviar
    message.msg_type = 1;
    strcpy(message.msg_text, "Hola desde el remitente!");
    msg_size = strlen(message.msg_text) + 1;

    // Enviar el mensaje
    if (msgsnd(msgq_id, &message, msg_size, 0) == -1) {
        perror("msgsnd");
        exit(1);
    }

    printf("Mensaje enviado: \"%s\"\n", message.msg_text);

    // Preparar el búfer para recibir
    memset(message.msg_text, 0, sizeof(message.msg_text));

    // Recibir el mensaje
    if (msgrcv(msgq_id, &message, sizeof(message.msg_text), 1, 0) == -1) {
        perror("msgrcv");
        exit(1);
    }

    printf("Mensaje recibido: \"%s\"\n", message.msg_text);

    // Eliminar la cola de mensajes
    if (msgctl(msgq_id, IPC_RMID, NULL) == -1) {
        perror("msgctl");
        exit(1);
    }

    return 0;
}
