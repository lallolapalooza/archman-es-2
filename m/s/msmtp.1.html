MSMTP(1) Manual de comandos generales MSMTP(1)

NOMBRE

msmtp - Un cliente SMTP

SINOPSIS

Modo Sendmail (por defecto):
msmtp [opción...] [--] destinatario...
msmtp [opción...] -t [--] [destinatario...]
Modo de configuración:
msmtp --configure <dirección de correo>
Modo de información del servidor:
msmtp [opción...] --serverinfo
Modo de inicio de cola de mensajes remota:
msmtp [opción...] --rmqs=host|@dominio|#cola

DESCRIPCIÓN

En el modo sendmail por defecto, msmtp lee un correo de la entrada estándar y lo envía a un servidor SMTP para su entrega.
En el modo de información del servidor, msmtp imprime información sobre un servidor SMTP.
En el modo de inicio de cola de mensajes remota, msmtp envía una solicitud de inicio de cola de mensajes remota para un host, dominio o cola a un servidor SMTP.

ESTADO DE SALIDA

Se utilizan los códigos de estado de salida estándar de sendmail, tal como se definen en sysexits.h.

OPCIONES

Las opciones anulan la configuración del archivo de configuración.
Son compatibles con sendmail cuando es apropiado.

Opciones generales
--version
Imprime la información de la versión, incluida la información sobre las bibliotecas utilizadas.
--help
Imprime la ayuda.
-P, --pretend
Imprime la configuración que se usaría, pero no realiza ninguna acción adicional. Se imprimirá un asterisco (`*') en lugar de tu contraseña.
-v, -d, --debug
Imprime mucha información de depuración, incluida toda la conversación con el servidor SMTP. Ten cuidado con esta opción: la salida (potencialmente peligrosa) no se sanitizará, ¡y tu contraseña podría imprimirse en un formato fácilmente decodificable!
Cambio del modo de operación
--configure=dirección de correo
Genera una configuración para la dirección de correo dada y la imprime. Esto se puede modificar o copiar sin cambios al archivo de configuración. Ten en cuenta que esto solo funciona para dominios de correo que publican registros SRV apropiados; consulta RFC 8314.
-S, --serverinfo
Imprime información sobre el servidor SMTP y sale. Esto incluye información sobre las características admitidas (límite de tamaño del correo, autenticación, TLS, DSN, ...) y sobre el certificado TLS (si TLS está activo).
--rmqs=(host|@dominio|#cola)
Envía una solicitud de inicio de cola de mensajes remota para el host, dominio o cola dados al servidor SMTP y sale.
Opciones de configuración
-C, --file=nombre_archivo
Utiliza el archivo dado en lugar de ~/.msmtprc o $XDG_CONFIG_HOME/msmtp/config como archivo de configuración del usuario.
-a, --account=nombre_cuenta
Utiliza la cuenta dada en lugar de la cuenta llamada "default". Los ajustes de esta cuenta pueden modificarse con las opciones de la línea de comandos. Esta opción no se puede usar junto con la opción --host.
--host=nombre_host
Utiliza este servidor SMTP con ajustes de la línea de comandos; no uses ningún dato del archivo de configuración. Esta opción no se puede usar junto con la opción --account.
--port=número
Establece el número de puerto al que conectarse. Consulta el comando port.
--source-ip=[IP]
Establece o anula una dirección IP a la que vincular el socket. Consulta el comando source_ip.
--proxy-host=[IP|nombre_host]
Establece o anula un proxy SOCKS a utilizar. Consulta el comando proxy_host.
--proxy-port=[número]
Establece o anula un número de puerto para el host proxy. Consulta el comando proxy_port.
--socket=[nombre_socket]
Establece o anula un nombre de socket de dominio Unix local al que conectarse. Consulta el comando socket.
--timeout=(off|segundos)
Establece o anula un tiempo de espera de red, en segundos. Consulta el comando timeout.
--protocol=(smtp|lmtp)
Establece el protocolo. Consulta el comando protocol.
--domain=[cadena]
Establece el argumento del comando EHLO (o LHLO de LMTP) de SMTP, y la parte del dominio para la cabecera Message-ID. Consulta el comando domain.
--auth[=(on|off|método)]
Habilita o deshabilita la autenticación y opcionalmente elige el método. Consulta el comando auth.
--user=[nombre_usuario]
Establece o anula el nombre de usuario para la autenticación. Consulta el comando user.
--passwordeval=[cmd]
Evalúa la contraseña para la autenticación. Consulta el comando passwordeval.
--tls[=(on|off)]
Habilita o deshabilita TLS/SSL. Consulta el comando tls.
--tls-starttls[=(on|off)]
Habilita o deshabilita STARTTLS para TLS. Consulta el comando tls_starttls.
--tls-trust-file=[archivo]
Establece o anula un archivo de confianza para TLS. Consulta el comando tls_trust_file.
--tls-crl-file=[archivo]
Obsoleto. Establece o anula un archivo de lista de revocación de certificados (CRL) para TLS. Consulta el comando tls_crl_file.
--tls-fingerprint=[huella_digital]
Establece o anula la huella digital de un certificado TLS de confianza. Consulta el comando tls_fingerprint.
--tls-key-file=[archivo]
Establece o anula un archivo de clave para TLS. Consulta el comando tls_key_file.
--tls-cert-file=[archivo]
Establece o anula un archivo de certificado para TLS. Consulta el comando tls_cert_file.
--tls-certcheck[=(on|off)]
Habilita o deshabilita la comprobación del certificado del servidor para TLS. Consulta el comando tls_certcheck.
--tls-priorities=[prioridades]
Establece o anula las prioridades TLS. Consulta el comando tls_priorities.
--tls-host-override=[host]
Establece o anula la anulación para la verificación del host TLS. Consulta el comando tls_host_override.
--tls-min-dh-prime-bits=[bits]
Obsoleto, usa --tls-priorities en su lugar. Establece o anula el tamaño mínimo en bits del primo Diffie-Hellman (DH). Consulta el comando tls_min_dh_prime_bits.
Opciones específicas del modo sendmail
-f, --from=dirección
Establece la dirección del remitente del sobre.

Establece el nombre del archivo del socket de dominio Unix al que conectarse. Esto anula tanto host/port como proxy_host/proxy_port.
timeout (off|segundos)
Establece o desactiva un tiempo de espera de red, en segundos. El argumento off significa que no se establecerá ningún tiempo de espera, lo que significa que se utilizará el valor predeterminado del sistema operativo.
protocol (smtp|lmtp)
Establece el protocolo a utilizar. Actualmente solo se admiten SMTP y LMTP. SMTP es el valor predeterminado. Consulte el comando port anterior para ver los puertos predeterminados.
domain argumento
Utilice este comando para establecer el argumento del comando EHLO (o LMTP LHLO) de SMTP y la parte del dominio de las cabeceras Message-ID si msmtp las genera (consulte el comando set_msgid_header).
El valor predeterminado localhost es inadecuado pero generalmente funciona para EHLO. Sin embargo, no tiene sentido para las cabeceras Message-ID. Consulte el comando set_msgid_header para obtener más detalles.
Las opciones posibles son la parte del dominio de su dirección de correo electrónico (proveedor.ejemplo para juan@proveedor.ejemplo) o el nombre de dominio completo de su host (si está disponible).
Se admiten los siguientes patrones de sustitución:
%H se reemplazará por $HOSTNAME o, si falla, por el nombre de host del sistema.
%C se reemplazará por el nombre canónico de %H.
%M se reemplazará por el contenido de /etc/mailname (potencialmente se utiliza un directorio diferente dependiendo de la configuración de compilación; consulte la salida de msmtp --version y busque la ubicación del archivo de configuración del sistema).
auth [(on|off|método)]
Habilita o deshabilita la autenticación y, opcionalmente, elige un método a utilizar. El argumento on elige un método automáticamente.
Normalmente se utiliza un nombre de usuario y una contraseña para la autenticación. El nombre de usuario se especifica en el archivo de configuración con el comando user. Hay cinco métodos diferentes para especificar la contraseña:
1. Añada la contraseña al llavero del sistema. Los llaveros compatibles actualmente son el llavero de Gnome y el Keychain de Mac OS X. Para el llavero de Gnome, utilice el comando secret-tool (parte de libsecret de Gnome) para almacenar contraseñas: secret-tool store --label=msmtp host mail.ejemplogratis.com service smtp user juansmith. En Mac OS X, utilice el siguiente comando: security add-internet-password -s mail.ejemplogratis.com -r smtp -a juansmith -w. En ambos ejemplos, reemplace mail.ejemplogratis.com con el nombre del servidor SMTP y juansmith con su nombre de usuario.
2. Almacene la contraseña en archivos cifrados y utilice passwordeval para especificar un comando para descifrar ese archivo, por ejemplo, utilizando GnuPG. Consulte EJEMPLOS.
3. Almacene la contraseña en el archivo de configuración utilizando el comando password. (Normalmente no se considera una buena idea almacenar contraseñas en archivos de texto sin formato. Si lo hace de todos modos, debe asegurarse de que el archivo solo pueda ser leído por usted.)
4. Almacene la contraseña en ~/.netrc. Este método probablemente esté obsoleto.
5. Escriba la contraseña en la terminal cuando sea necesario.
Se recomienda utilizar el método 1 o 2.
Existen múltiples métodos de autenticación. La mayoría de los servidores solo admiten algunos de ellos.
Los siguientes métodos de usuario/contraseña son compatibles: plain (un método simple de texto sin formato, con codificación base64, compatible con casi todos los servidores), scram-sha-1 y scram-sha-1-plus (un método que evita las contraseñas de texto sin formato y requiere que el servidor demuestre que posee la contraseña (hasheada y con sal), lo que previene algunos ataques de man-in-the-middle. La variante -plus utiliza adicionalmente información de enlace de canal TLS para garantías de seguridad aún mejores), scram-sha-256 y scram-sha-256-plus (igual pero con una función hash más fuerte), cram-md5 (un método obsoleto que evita las contraseñas de texto sin formato, pero que ya no se considera seguro), digest-md5 (un método obsoleto excesivamente complicado que evita las contraseñas de texto sin formato, pero que ya no se considera seguro), login (un método de texto sin formato no estándar similar pero peor que el método plain), ntlm (un método oscuro no estándar que ahora se considera roto; a veces requiere un parámetro de dominio especial pasado a través de ntlmdomain).
Si no se especifica ningún método, msmtp seleccionará uno automáticamente basándose en los beneficios de seguridad. Con TLS, el orden es scram-sha-256-plus, scram-sha-1-plus, scram-sha-256, scram-sha-1, plain, seguido de algunos de los métodos obsoletos si no hay nada más disponible. Sin TLS, solo se consideran scram-sha-256 y scram-sha-1.
Actualmente existen tres métodos de autenticación que no se basan en información de usuario/contraseña y deben seleccionarse manualmente: oauthbearer o su predecesor xoauth2 (se utiliza un token OAuth2 del proveedor de correo como contraseña. Consulte la documentación de su proveedor de correo para obtener detalles sobre cómo obtener este token. El comando passwordeval se puede utilizar para pasar los tokens que cambian regularmente a msmtp desde un script o una variable de entorno), external (la autenticación se realiza fuera del protocolo, típicamente enviando un certificado de cliente TLS, y el método simplemente confirma que esta autenticación tuvo éxito) y gssapi (el framework Kerberos se encarga de la autenticación segura, solo se requiere un nombre de usuario).
Depende de la biblioteca de autenticación subyacente y su versión si un método particular es compatible o no. Utilice --version para averiguar qué métodos son compatibles.
user login
Establece el nombre de usuario para la autenticación. Un argumento vacío desactiva el nombre de usuario.
password secreto
Establece la contraseña para la autenticación. Un argumento vacío desactiva la contraseña. Considere usar el comando passwordeval o un llavero en lugar de este comando, para evitar almacenar contraseñas de texto sin formato en el archivo de configuración.
passwordeval [cmd]
Establece la contraseña para la autenticación a la salida (stdout) del comando cmd. Esto se puede usar, por ejemplo, para descifrar archivos de contraseñas sobre la marcha o para consultar llaveros, y así evitar almacenar contraseñas de texto sin formato.
El comando cmd no debe interferir con la entrada estándar; en caso de duda, añada < /dev/null.
ntlmdomain [dominio]
Establece un dominio para el método de autenticación ntlm. Esto está obsoleto.
tls [(on|off)]
Habilita o deshabilita TLS (también conocido como SSL) para conexiones seguras.
Transport Layer Security (TLS) "... proporciona privacidad en las comunicaciones a través de Internet. El protocolo permite que las aplicaciones cliente/servidor se comuniquen de una manera diseñada para prevenir escuchas, manipulaciones o falsificación de mensajes" (cita de RFC2246).
Un servidor puede usar TLS en uno de dos modos: a través de un comando STARTTLS (la sesión comienza con la inicialización normal del protocolo, y TLS se inicia luego usando el comando STARTTLS del protocolo), o inmediatamente (TLS se inicializa antes de la inicialización normal del protocolo; esto requiere un puerto separado). El primer modo es el predeterminado, pero puede cambiar al segundo modo deshabilitando tls_starttls.
Cuando se inicia TLS, el servidor envía un certificado para identificarse. Para verificar la identidad del servidor, se espera que un programa cliente verifique que el certificado sea formalmente correcto y que haya sido emitido por una Autoridad Certificadora (CA) en la que el usuario confía. (También puede haber cadenas de certificados con CAs intermedias).
La lista de CAs confiables se especifica usando el comando tls_trust_file. El valor predeterminado es "system" y selecciona el valor predeterminado del sistema, pero también puede elegir usted mismo las CAs confiables.
Un problema fundamental con esto es que necesita confiar en las CAs. Como cualquier otra organización, una CA puede ser incompetente, maliciosa, subvertida por personas malintencionadas o obligada por agencias gubernamentales a comprometer a los usuarios finales sin informarles. Todas estas cosas sucedieron y continúan sucediendo en todo el mundo. La idea de tener organizaciones centrales en las que se deba confiar para que su comunicación sea segura está fundamentalmente rota.
En lugar de confiar en una CA, puede optar por confiar solo en un certificado único para el servidor al que desea conectarse. Para ello, especifique la huella digital del certificado con tls_fingerprint. Esto asegura que ningún atacante pueda suplantar la identidad del servidor presentándole un certificado fraudulento emitido por alguna CA que esté en su lista de confianza. Sin embargo, deberá actualizar la huella digital cada vez que cambie el certificado del servidor y deberá asegurarse de que el cambio sea legítimo cada vez, por ejemplo, cuando expire el certificado anterior. Esto es inconveniente, pero es el precio a pagar.
La información sobre un certificado de servidor se puede obtener con --serverinfo --tls --tls-certcheck=off. Esto incluye la CA emisora del certificado (para que pueda confiar en esa CA a través de tls_trust_file) y la huella digital del certificado (para que pueda confiar en ese certificado en particular a través de tls_fingerprint).
TLS también permite al servidor verificar la identidad del cliente. Para ello, el cliente debe presentar un certificado emitido por una CA en la que el servidor confía. Para presentar ese certificado, el cliente también necesita el archivo de clave correspondiente. Puede establecer los archivos de certificado y clave utilizando tls_cert_file y tls_key_file. Este mecanismo también se puede utilizar para autenticar usuarios, de modo que la autenticación tradicional de usuario/contraseña ya no sea necesaria. Consulte el mecanismo external en auth.
También puede utilizar certificados de cliente almacenados en algún dispositivo de autenticación externo especificando URIs de dispositivo GnuTLS en tls_cert_file y tls_key_file. Puede encontrar las URIs correctas utilizando p11tool --list-privkeys --login (p11tool está incluido con GnuTLS). Si su dispositivo requiere un PIN para acceder a los datos, puede especificarlo utilizando uno de los mecanismos de contraseña (por ejemplo, passwordeval, password).

Elige la variante TLS: iniciar TLS desde dentro de la sesión (on, predeterminado), o tunelizar la sesión a través de TLS (off).

 tls_trust_file Este establece un archivo de autoridades de certificación (CA) de confianza. El valor predeterminado es el valor especial "system", que selecciona el predeterminado del sistema. Un argumento vacío deshabilita la confianza en las CA. Si selecciona un archivo, debe estar en formato PEM y también debe usar tls_crl_file. tls_crl_file [archivo] Esto establece un archivo de lista de revocación de certificados (CRL) para TLS, para verificar los certificados revocados (un argumento vacío, que es el valor predeterminado, deshabilita esto).
OCSP es una alternativa a los archivos CRL. Cuando se usa GnuTLS, la información OCSP grapada se verificará automáticamente y se admitirá la extensión TLS MustStaple, sin embargo, no se enviarán consultas OCSP manuales cuando falte información OCSP grapada. Con otras bibliotecas TLS, el comportamiento puede ser diferente. tls_fingerprint [huella_digital] Establece la huella digital de un único certificado para aceptar para TLS. Este certificado será de confianza independientemente de su contenido (esto anula tls_trust_file). La huella digital debe ser de tipo SHA256, pero por motivos de compatibilidad con versiones anteriores también puede ser de tipo SHA1 o MD5 (evite esto). El formato debe ser 01:23:45:67:.... Use --serverinfo --tls --tls-certcheck=off --tls-fingerprint= para obtener la huella digital del certificado del servidor. tls_key_file archivo Envía un certificado de cliente al servidor (úselo junto con tls_cert_file). El archivo debe contener la clave privada de un certificado en formato PEM. Un argumento vacío deshabilita esta función. tls_cert_file archivo Envía un certificado de cliente al servidor (úselo junto con tls_key_file). El archivo debe contener un certificado en formato PEM. Un argumento vacío deshabilita esta función. tls_certcheck [(on|off)] Habilita o deshabilita las verificaciones del certificado del servidor. Están habilitadas por defecto. Deshabilitarlas anulará tls_trust_file y tls_fingerprint. El valor predeterminado lo establece la biblioteca TLS y se puede seleccionar utilizando un argumento vacío para este comando. La interpretación de la cadena de prioridades depende de la biblioteca TLS. Use --version para averiguar qué biblioteca TLS utiliza.
Para GnuTLS, consulte la sección sobre Cadenas de Prioridades en el manual.
Para libtls, la cadena de prioridades es una lista separada por espacios de cadenas de parámetros prefijadas con PROTOCOLS=, CIPHERS= o ECDHECURVES=. Estas cadenas de parámetros se pasarán a las funciones tls_config_parse_protocols, tls_config_set_ciphers y tls_config_set_ecdhecurves. Las partes no reconocidas de la cadena de prioridades se ignorarán. Ejemplo: "PROTOCOLS=TLSv1.3 CIPHERS=ECDHE-RSA-AES128-SHA256 ECDHECURVES=P-384". tls_host_override [host] Por defecto, la verificación del host TLS utiliza el nombre de host proporcionado por el comando host. Establezca en off para deshabilitar esto. dsn_notify (off|condition) Este comando establece las condiciones bajo las cuales el sistema de correo debe enviar mensajes DSN (Delivery Status Notification). El argumento off deshabilita las solicitudes DSN explícitas, lo que significa que el sistema de correo decide cuándo enviar mensajes DSN. Este es el valor predeterminado. La condición debe ser never, para nunca solicitar notificación, o una lista separada por comas (¡sin espacios!) de uno o más de los siguientes: failure, para solicitar notificación en caso de fallo de transmisión, delay, para ser notificado de retrasos en el mensaje, success, para ser notificado de la transmisión exitosa. El servidor SMTP debe admitir la extensión DSN. dsn_return (off|amount) Este comando controla cuánto de un correo se debe devolver en los mensajes DSN (Delivery Status Notification). El argumento off deshabilita las solicitudes DSN explícitas, lo que significa que el sistema de correo decide cuánto de un correo devuelve en los mensajes DSN. Este es el valor predeterminado. La cantidad debe ser headers, para devolver solo las cabeceras del mensaje, o full, para devolver el correo completo. El servidor SMTP debe admitir la extensión DSN. set_from_header [(auto|on|off)] Cuándo establecer una cabecera From: auto agrega una cabecera From si el correo no tiene una (este es el valor predeterminado), on siempre establece una cabecera From y anula cualquiera existente, y off nunca establece una cabecera From.
Si el servidor de correo rechaza el correo porque su cabecera From no coincide con la dirección del remitente del sobre (una medida común anti-spam), entonces es posible que desee establecer esta opción en on.
La cabecera From se crea basándose en la dirección del remitente del sobre. Deshabilite allow_from_override para evitar que los programas establezcan su propia dirección de remitente del sobre.

msmtp(1) Manual Page

NAME

msmtp - an SMTP client to send mail from scripts or Mutt

SYNOPSIS

msmtp [-a|--account accountname] [-A|--auto-sent] [-c|--configfile file] [-d|--debug] [-e|--envelope-from address] [-F|--from address] [-h|--help] [-i|--interactive] [-m|--message-mode mode] [-N|--no-rcpt] [-p|--passwordfile file] [-P|--predefined-address address] [-q|--quiet] [-s|--syslog facility] [-t|--test] [-v|--verbose] [-V|--version] [-w|--write-password] [recipient ...]

DESCRIPTION

msmtp is an SMTP client which is intended to be used by mail user agents like Mutt or scripts to send mail. It supports most of the features that are necessary for sending mail, like SMTP AUTH (CRAM-MD5, PLAIN, LOGIN, EXTERNAL), TLS/SSL encryption, and sender verification.

It reads the message to be sent from standard input and sends it to a specified SMTP server. The SMTP server can be specified on the command line or in a configuration file.

OPTIONS

The following options are available:

-a, --account accountname
Use the account named accountname. If not specified, the default account is used.
-A, --auto-sent
Do not ask for confirmation before sending the mail. This is the default behavior.
-c, --configfile file
Use file as configuration file. If not specified, msmtp tries to find a configuration file in the user's home directory (~/.msmtprc) or in the system-wide configuration directory (/etc/msmtprc).
-d, --debug
Print debugging information. This option can be given multiple times to increase the debug level.
-e, --envelope-from address
Use address as the sender address in the SMTP envelope. This overrides the sender address specified in the message headers.
-F, --from address
Set the sender address in the message headers to address. If not specified, the sender address is taken from the message headers.
-h, --help
Show a short help message and exit.
-i, --interactive
Ask for confirmation before sending the mail. This option is useful for testing.
-m, --message-mode mode
Set the message mode. Possible values are "plain" (default) and "html".
-N, --no-rcpt
Do not send the mail to any recipients. This option is useful for testing the configuration.
-p, --passwordfile file
Use file as password file. If not specified, msmtp tries to find a password file in the user's home directory (~/.msmtppasswd) or in the system-wide configuration directory (/etc/msmtppasswd).
-P, --predefined-address address
Use address as the sender address in the SMTP envelope. This overrides the sender address specified in the message headers. This option is equivalent to --envelope-from.
-q, --quiet
Suppress all output except for error messages.
-s, --syslog facility
Log messages to the syslog facility facility. Possible values are auth, authpriv, cron, daemon, ftp, kern, lpr, mail, mark, news, nucleu, security (same as authpriv), user, uucp, and local0 through local7.
-t, --test
Perform a test run without actually sending the mail. This option is useful for testing the configuration and authentication.
-v, --verbose
Print verbose output. This option can be given multiple times to increase the verbosity level.
-V, --version
Show version information and exit.
-w, --write-password
Write the password to the password file. This option is useful for initial setup.

USAGE

msmtp reads the mail message from standard input. The message must be in the format specified by RFC 5322 (formerly RFC 822). The recipient addresses can be specified on the command line or in the message headers.

Example:

echo "This is the body of the message." | msmtp recipient@example.com

This will send a message with the subject "This is the body of the message." to the recipient@example.com. The sender address will be taken from the message headers.

CONFIGURATION FILES

msmtp can be configured using configuration files. The default configuration file is ~/.msmtprc. If this file does not exist, msmtp tries to use /etc/msmtprc.

The configuration file is divided into sections. Each section starts with a line like account default or account myaccount. The default account is used if no account is specified on the command line.

The following options can be specified in a configuration file:

account
Specifies the name of the account. The first account defined is the default account.
host
Specifies the SMTP server hostname.
port
Specifies the SMTP server port. Defaults to 25.
tls
Specifies whether to use TLS encryption. Possible values are on, off, and smart (default). smart enables TLS if the server supports it.
tls_trust_cert
Specifies the path to the trusted certificate authority bundle. If not specified, the system's default bundle is used.
tls_fingerprint
Specifies the fingerprint of the server's TLS certificate. This is used for certificate validation.
tls_starttls
Specifies whether to use STARTTLS. Possible values are on and off (default).
tls_enable_dnssec
Specifies whether to enable DNSSEC validation for STARTTLS. Possible values are on and off (default).
tls_allow_only_cncs
Specifies whether to allow only certificates with Common Name (CN) or Subject Alternative Name (SAN) entries that match the hostname. Possible values are on and off (default).
auth
Specifies whether to use SMTP authentication. Possible values are on, off, and smart (default). smart enables authentication if the server supports it.
user
Specifies the username for SMTP authentication.
password
Specifies the password for SMTP authentication. It is recommended to use a password file instead.
passwordeval
Specifies a command to execute to obtain the password. The output of the command is used as the password.
from
Specifies the default sender address. This address is used if no sender address is specified in the message headers.
envelope_from
Specifies the default sender address for the SMTP envelope. This address is used if no envelope sender address is specified on the command line.
syslog
Specifies the syslog facility to use for logging.
logfile
Specifies a file to log messages to.

EXAMPLES

Send a simple email:

echo -e "Subject: Test email\n\nThis is the body of the email." | msmtp recipient@example.com

Send an email with a specific sender address:

echo -e "Subject: Test email\nFrom: Sender Name <sender@example.com>\n\nThis is the body of the email." | msmtp -F sender@example.com recipient@example.com

Send an email using a specific account:

echo -e "Subject: Test email\n\nThis is the body of the email." | msmtp -a work recipient@example.com

Send an email using TLS encryption and authentication:

Configuration file (~/.msmtprc):

account default
    host smtp.example.com
    port 587
    tls on
    auth on
    user your_username
    password your_password
    from your_email@example.com

Command line:

echo -e "Subject: Test email\n\nThis is the body of the email." | msmtp recipient@example.com

Send an email with an HTML body:

echo -e "Subject: Test email\nContent-Type: text/html\n\n<b>This is the body of the email in bold.</b>" | msmtp --message-mode html recipient@example.com

SMTP server hostname.

SMTP server port.

Use SMTP over SSL/TLS.

Verify TLS certificate.
MSMTPSMTPSVERIFYNAME
Verify TLS certificate hostname.

Use STARTTLS.
