Nombre

mgmt - Documentación del Protocolo de Gestión de Bluetooth

SINOPSIS

Los sockets de gestión de Bluetooth se pueden crear estableciendo el miembro hci_channel de la estructura sockaddr_hci en HCI_CHANNEL_CONTROL (ver hci(7)) al crear un socket HCI crudo:

 int mgmt_create(void)
 {
     struct sockaddr_hci addr;
     int fd;
     fd = socket(PF_BLUETOOTH, SOCK_RAW | SOCK_CLOEXEC | SOCK_NONBLOCK,
                                                             BTPROTO_HCI);
     if (fd < 0)
         return -errno;
     memset(&addr, 0, sizeof(addr));
     addr.hci_family = AF_BLUETOOTH;
     addr.hci_dev = HCI_DEV_NONE;
     addr.hci_channel = HCI_CHANNEL_CONTROL;
     if (bind(fd, (struct sockaddr *) &addr, sizeof(addr)) < 0) {
         int err = -errno;
         close(fd);
         return err;
     }
     return fd;
}

El proceso que crea el socket mgmt debe tener la capacidad CAP_NET_ADMIN (por ejemplo, root la tendría).

Packet Structures

Commands:

0    4    8   12   16   22   24   28   31   35   39   43   47
+-------------------+-------------------+-------------------+
|  Command Code     |  Controller Index |  Parameter Length |
+-------------------+-------------------+-------------------+
|                                                           |

Events:

0    4    8   12   16   22   24   28   31   35   39   43   47
+-------------------+-------------------+-------------------+
|  Event Code       |  Controller Index |  Parameter Length |
+-------------------+-------------------+-------------------+
|                                                           |

All fields are in little-endian byte order (least significant byte first).

Controller Index can have a special value <non-controller> to indicate that command or event is not related to any controller. Possible values:

Value Description
0x0000-0xFFFE <controller id>
0xFFFF <non-controller>

Error Codes

The following values have been defined for use with the Command Status and Command Complete events:

0x00 Success
0x01 Unknown Command
0x02 Not Connected
0x03 Failed
0x04 Connect Failed
0x05 Authentication Failed
0x06 Not Paired
0x07 No Resources
0x08 Timeout
0x09 Already Connected
0x0A Busy
0x0B Rejected
0x0C Not Supported
0x0D Invalid Parameters
0x0E Disconnected
0x0F Not Powered
0x10 Cancelled
0x11 Invalid Index
0x12 RFKilled
0x13 Already Paired

As a general rule all commands generate the events as specified below, however invalid lengths or unknown commands will always generate a Command Status response (with Unknown Command or Invalid Parameters status). Sending a command with an invalid Controller Index value will also always generate a Command Status event with the Invalid Index status code.

Este comando se utiliza para habilitar la función de Privacidad de Baja Energía utilizando direcciones privadas resolubles.

El valor 0x00 deshabilita el modo de privacidad, los valores 0x01 y 0x02 habilitan el modo de privacidad.

Con el valor 0x01, el kernel siempre utilizará el modo de privacidad. Esto significa que se utilizará una dirección privada resoluble cuando el controlador sea detectable y también cuando se inicie el emparejamiento.

Con el valor 0x02, el kernel utilizará un modo de privacidad limitado con una dirección privada resoluble, excepto cuando el controlador sea enlazable y detectable, en cuyo caso se utilizará la dirección de identidad.

Exponer la dirección de identidad cuando es enlazable y detectable o durante el emparejamiento iniciado puede ser un problema de privacidad. Para controladores de doble modo, esto se puede pasar por alto ya que su dirección pública se expondrá de todos modos a través de BR/EDR. El beneficio de exponer la dirección de identidad para fines de emparejamiento es que ahora es posible hacer coincidir dispositivos con topología de doble modo durante el descubrimiento de dispositivos.

Si se utiliza el valor de privacidad 0x02, entonces la base de datos GATT también debe exponer la Característica de Privacidad para que los dispositivos remotos puedan determinar si la función de privacidad está en uso o no.

En caso de que el controlador sea solo de modo LE único sin una dirección pública, se requiere configurar primero una dirección aleatoria estática. Esto es útil para cambiar un controlador a modo conectable solo para operación LE. Esto es similar al modo 0x02 del comando Set Advertising.

Al usar publicidad no conectable o escaneable, el controlador se programará con una dirección aleatoria no resoluble. Cuando el sistema es conectable, se utilizará la dirección de identidad o la dirección privada resoluble.

En ese caso, cada Instancia estará disponible durante el tiempo de Duration y después pasará a la siguiente. Este es un enfoque simple basado en round-robin.

El parámetro Timeout configura el tiempo de vida de una Instancia. En caso de que se utilice el valor 0, indica que no hay tiempo de expiración. Si se proporciona un valor de timeout, la Instancia de publicidad se eliminará automáticamente cuando pase el timeout. El valor para el timeout está en segundos. Volver a añadir una instancia ya existente (es decir, ejecutar el comando Add Advertising con un identificador de Instancia de una instancia existente) actualizará la configuración de esa instancia.

Los cambios en una instancia que se está anunciando actualmente cancelarán esa instancia y pasarán a la siguiente. Los cambios serán visibles la próxima vez que la instancia se programe para anunciarse. En caso de que una sola instancia esté activa, esto significa que los cambios serán visibles de inmediato.

Tenga en cuenta que si hay más de un patrón, se aplicará lógica O entre los patrones durante el filtrado. ...
Length
La longitud del valor del patrón en bytes.
Value
El valor del patrón en bytes.

Este comando se utiliza para configurar los parámetros de una instancia de publicidad de Bluetooth Low Energy. Se espera que este comando sea seguido por un comando Add Extended Advertising Data para completar y habilitar la instancia de publicidad.

La información de publicidad añadida con este comando no será visible inmediatamente si la publicidad está habilitada a través del comando Set Advertising. El uso del comando Set Advertising tiene prioridad sobre este comando. La información de la instancia se almacena y se anunciará una vez que la publicidad a través de Set Advertising se haya deshabilitado.

El identificador de Instancia es un valor entre 1 y el número de instancias soportadas. El valor 0 está reservado.

Con el valor Flags, se controla el tipo de publicidad y se definen las siguientes banderas:

Bit Descripción
0 Cambiar a modo Conectable
1 Anunciar como Descubrible
2 Anunciar como Descubrible Limitado
3 Añadir campo Flags a Adv_Data
4 Añadir campo TX Power a Adv_Data
5 Añadir campo Appearance a Scan_Rsp
6 Añadir Nombre Local en Scan_Rsp
7 Canal Secundario con LE 1M
8 Canal Secundario con LE 2M
9 Canal Secundario con LE Coded
10 Indica que la potencia de transmisión se puede especificar
11 Indica que el hardware soporta la descarga de publicidad
12 Se debe usar el parámetro Duration
13 Se debe usar el parámetro Timeout
14 Se deben usar los parámetros Interval
15 Se debe usar el parámetro Tx Power
16 La publicidad contendrá una respuesta de escaneo

Cuando se establece la bandera conectable, el controlador utilizará publicidad conectable no dirigida. El valor de la configuración conectable se puede sobrescribir de esta manera. Esto es útil para cambiar un controlador a modo conectable solo para operación LE. Esto es similar al modo 0x02 del comando Set Advertising.

Cuando la bandera conectable

no está establecido, el controlador utilizará publicidad basada en la configuración de conectividad. Al usar publicidad no conectable o escaneable, el controlador se programará con una dirección aleatoria no resoluble. Cuando el sistema es conectable, se utilizará la dirección de identidad o la dirección privada resoluble.

El uso de la bandera de conectabilidad es útil para el soporte del modo periférico donde BR/EDR (y/o LE) es controlado por Add Device. Esto permite hacer el periférico conectable sin tener que interferir con la configuración global de conectabilidad.

Las banderas de canal secundario se pueden usar para anunciar en el canal secundario con las PHY correspondientes. Estos bits de bandera son mutuamente excluyentes y establecer varios resultará en un error de Parámetro Inválido. Elegir LE 1M o LE 2M resultará en el uso de publicidad extendida en el canal primario con LE 1M y LE 1M o LE 2M respectivamente en el canal secundario. Elegir LE Coded resultará en el uso de publicidad extendida en los canales primario y secundario con LE Coded. No elegir ninguna de estas banderas resultará en publicidad heredada.

Para permitir que los parámetros futuros se extiendan opcionalmente en esta estructura, el miembro flags se ha utilizado para especificar cuáles de los campos de la estructura fueron establecidos deliberadamente por el llamador. Los parámetros no especificados recibirán valores predeterminados sensatos del kernel antes de que se registre la publicidad.

El parámetro Duration configura la longitud de una Instancia. El valor está en segundos. El valor predeterminado es 2 segundos.

Si solo se ha agregado una Instancia de publicidad, el valor Duration se ignorará. Solo se aplica al caso en que se configuran múltiples Instancias. En ese caso, cada Instancia estará disponible durante el tiempo Duration y luego pasará a la siguiente. Este es un simple enfoque basado en round-robin.

El parámetro Timeout configura el tiempo de vida de una Instancia. En caso de que se use el valor 0, indica que no hay tiempo de expiración. Si se proporciona un valor de timeout, la Instancia de publicidad se eliminará automáticamente cuando expire el timeout. El valor del timeout está en segundos. Apagar un controlador invalidará todas las Instancias de publicidad y no es posible agregar una nueva Instancia con un timeout cuando el controlador está apagado.

Cuando se proporciona un Timeout, Duration se resta del valor actual de Timeout de esa Instancia. Por ejemplo, una Instancia con Timeout de 5 y Duration de 2 se programará exactamente 3 veces, dos veces con 2 segundos y una vez con un segundo. Otras Instancias no tienen influencia en el Timeout.

MinInterval y MaxInterval definen los intervalos de publicidad mínimo y máximo, con unidades como número de ranuras de publicidad de .625ms. Se espera que el intervalo Max sea mayor o igual al intervalo Min, y ambos deben tener valores en el rango [0x000020, 0xFFFFFF]. Si alguna condición no se cumple, el registro fallará.

El parámetro Tx Power proporcionado solo se utilizará si el controlador lo soporta, lo cual se puede determinar por la presencia del miembro CanSetTxPower del comando Read Advertising Features.

El rango aceptable para Tx Power solicitado se define en la especificación (Versión 5.2 | Vol 4, Parte E, página 2585) como [-127, +20] dBm, y el controlador seleccionará un valor de potencia hasta el solicitado. No se garantiza que la potencia de transmisión seleccionada por el controlador coincida con la solicitada, por lo que la respuesta contendrá la potencia elegida por el controlador. Si el Tx Power solicitado está fuera del rango válido, el registro fallará.

Cuando el bit 16 de la bandera está habilitado, indica que la solicitud posterior para establecer datos de publicidad contendrá una respuesta de escaneo, y que los parámetros deben establecer un tipo de PDU que sea escaneable.

Volver a agregar una instancia existente (es decir, emitir el comando Add Extended Advertising Parameters con un identificador de instancia de una instancia existente) actualizará la configuración de esa instancia. En este caso donde no se agrega una nueva instancia, no se generará ningún evento Advertising Added. Sin embargo, si la actualización de la instancia falla, la instancia se eliminará y se generará un evento Advertising Removed.

Una instancia que se agrega o cambia mientras otra instancia se está anunciando no será visible inmediatamente, sino solo cuando la nueva/cambiada instancia sea programada por el algoritmo de publicidad round-robin.

Los cambios en una instancia que se está anunciando actualmente cancelarán esa instancia y pasarán a la siguiente. Los cambios serán visibles la próxima vez que la instancia se programe para publicidad. En caso de que una sola instancia esté activa, esto significa que los cambios serán visibles inmediatamente.

El parámetro de retorno MaxAdvDataLen indica qué tan grande puede ser la carga útil de datos en el comando posterior Add Extended Advertising Data Command, ya que tiene en cuenta los datos requeridos para las banderas seleccionadas. De manera similar, el parámetro de retorno MaxScanRspLen indica qué tan grande puede ser la respuesta de escaneo.

LE debe estar habilitado y el controlador debe estar encendido, de lo contrario se devolverá un estado de "rechazado".

Este comando genera un evento Command Complete en caso de éxito o un evento Command Status en caso de fallo.

This event indicates that the controller has received an Advertisement or Scan Result containing an AD Type matching the Mesh scan set.

The address of the sending device is returned, and must be a valid LE Address_Type.

Possible values for the Address_Type parameter:

Value Description
0 Reserved (not in use)
1 LE Public
2 LE Random

The RSSI field is a signed octet, and is the RSSI reported by the receiving controller.

The Instant field is 64 bit value that represents the instant in time the packet was received. It's value is not intended to be interpreted by the host, and is only useful if the host wants to make a timed response to the received packet (i.e. a Poll/Response).

AD_Length and AD_Data contains the Info structure of Advertising and Scan rsults. To receive this event, AD filters must be requested with the Set Mesh Receiver command, specifying which AD Types to return. All AD structures will be received in this event if any of the filtered AD Types are present.

This event will be sent to all management sockets.
