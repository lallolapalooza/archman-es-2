mbind(2) Manual de Llamadas al Sistema mbind(2)

NOMBRE

mbind - establece la política de memoria para un rango de memoria

BIBLIOTECA

Biblioteca de políticas NUMA (Non-Uniform Memory Access) (libnuma, -lnuma)

SINOPSIS

#include <numaif.h>
long mbind(unsigned long size, unsigned long maxnode;
           void addr[size], unsigned long size, int mode,
           const unsigned long nodemask[(maxnode + ULONG_WIDTH - 1)
                                        / ULONG_WIDTH],
           unsigned long maxnode, unsigned int flags);

DESCRIPCIÓN

mbind() establece la política de memoria NUMA, que consiste en un modo de política y cero o más nodos, para el rango de memoria que comienza con addr y continúa durante size bytes. La política de memoria define desde qué nodo se asigna la memoria.

Si el rango de memoria especificado por los argumentos addr y size incluye una región de memoria "anónima"—es decir, una región de memoria creada usando la llamada al sistema mmap(2) con el argumento MAP_ANONYMOUS—o un archivo mapeado en memoria, mapeado usando la llamada al sistema mmap(2) con el argumento MAP_PRIVATE, las páginas se asignarán solo de acuerdo con la política especificada cuando la aplicación escriba (almacene) en la página. Para regiones anónimas, un acceso de lectura inicial utilizará una página compartida en el kernel que contiene todos ceros. Para un archivo mapeado con MAP_PRIVATE, un acceso de lectura inicial asignará páginas de acuerdo con la política de memoria del hilo que causa que la página sea asignada. Esto puede no ser el hilo que llamó a mbind().

La política especificada se ignorará para cualquier mapeo MAP_SHARED en el rango de memoria especificado. En su lugar, las páginas se asignarán de acuerdo con la política de memoria del hilo que causa que la página sea asignada. De nuevo, esto puede no ser el hilo que llamó a mbind().

Si el rango de memoria especificado incluye una región de memoria compartida creada usando la llamada al sistema shmget(2) y adjuntada usando la llamada al sistema shmat(2), las páginas asignadas para la región de memoria anónima o compartida se asignarán de acuerdo con la política especificada, independientemente de qué proceso adjunte al segmento de memoria compartida y cause la asignación. Si, sin embargo, la región de memoria compartida fue creada con el argumento SHM_HUGETLB, las páginas grandes se asignarán de acuerdo con la política especificada solo si la asignación de página es causada por el proceso que llama a mbind() para esa región.

Por defecto, mbind() solo tiene efecto para nuevas asignaciones; si las páginas dentro del rango ya han sido tocadas antes de establecer la política, entonces la política no tiene ningún efecto. Este comportamiento por defecto puede ser anulado por los argumentos MPOL_MF_MOVE y MPOL_MF_MOVE_ALL descritos a continuación.

El argumento mode debe especificar uno de MPOL_DEFAULT, MPOL_BIND, MPOL_INTERLEAVE, MPOL_WEIGHTED_INTERLEAVE, MPOL_PREFERRED, MPOL_PREFERRED_MANY, o MPOL_LOCAL (que se describen en detalle a continuación). Todas las políticas de modo, excepto MPOL_DEFAULT, requieren que el llamante especifique el nodo o los nodos a los que se aplica el modo, a través del argumento nodemask.

El argumento mode también puede incluir un argumento opcional mode flag. Los mode flags soportados son:

MPOL_F_NUMA_BALANCING (desde Linux 5.15)
Cuando mode es MPOL_BIND, habilita el balanceo NUMA del kernel para la tarea si es soportado por el kernel. Si el argumento no es soportado por el kernel, o se usa con un mode distinto de MPOL_BIND, se devuelve -1 y errno se establece a EINVAL.
MPOL_F_STATIC_NODES (desde Linux-2.6.26)
Un nodemask no vacío especifica IDs de nodo físicos. Linux no re-mapea el nodemask cuando el hilo se mueve a un contexto de cpuset diferente, ni cuando cambia el conjunto de nodos permitidos por el contexto de cpuset actual del hilo.
MPOL_F_RELATIVE_NODES (desde Linux-2.6.26)
Un nodemask no vacío especifica IDs de nodo que son relativos al conjunto de IDs de nodo permitidos por el cpuset actual del hilo.

nodemask apunta a una máscara de bits de nodos que contiene hasta maxnode bits. El tamaño de la máscara de bits se redondea al siguiente múltiplo de sizeof(unsigned long), pero el kernel usará bits solo hasta maxnode. Un valor NULL de nodemask o un valor maxnode de cero especifica el conjunto vacío de nodos. Si el valor de maxnode es cero, el argumento nodemask se ignora. Donde se requiere un nodemask, debe contener al menos un nodo que esté en línea, permitido por el contexto actual de cpuset del hilo (a menos que se especifique el modo MPOL_F_STATIC_NODES), y contenga memoria.

El argumento mode debe incluir uno de los siguientes valores:

MPOL_DEFAULT
Este modo solicita que se elimine cualquier política no predeterminada, restaurando el comportamiento predeterminado. Cuando se aplica a un rango de memoria a través de mbind(), esto significa usar la política de memoria del hilo, que puede haber sido establecida con set_mempolicy(2). Si el modo de la política de memoria del hilo también es MPOL_DEFAULT, se utilizará la política predeterminada a nivel de sistema. La política predeterminada a nivel de sistema asigna páginas en el nodo de la CPU que activa la asignación. Para MPOL_DEFAULT, los argumentos nodemask y maxnode deben especificar el conjunto vacío de nodos.
MPOL_BIND
Este modo especifica una política estricta que restringe la asignación de memoria a los nodos especificados en nodemask. Si nodemask especifica más de un nodo, las asignaciones de página provendrán del nodo con suficiente memoria libre que esté más cerca del nodo donde ocurre la asignación. Las páginas no se asignarán desde ningún nodo no especificado en la IR nodemask. (Antes de Linux 2.6.26, las asignaciones de página provenían del nodo con el ID numérico de nodo más bajo primero, hasta que ese nodo no contenía memoria libre. Las asignaciones luego provenían del nodo con el siguiente ID de nodo más alto especificado en nodemask y así sucesivamente, hasta que ninguno de los nodos especificados contenía memoria libre).
MPOL_INTERLEAVE
Este modo especifica que las asignaciones de página se intercalen en el conjunto de nodos especificados en nodemask. Esto optimiza el ancho de banda en lugar de la latencia al distribuir páginas y accesos a memoria a esas páginas a través de múltiples nodos. Para ser efectivo, el área de memoria debe ser bastante grande, al menos 1 MB o más con un patrón de acceso bastante uniforme. Los accesos a una sola página del área todavía estarán limitados al ancho de banda de memoria de un solo nodo.
MPOL_WEIGHTED_INTERLEAVE (desde Linux 6.9)
Este modo intercalará las asignaciones de página entre los nodos especificados en nodemask de acuerdo con los pesos en /sys/kernel/mm/mempolicy/weighted_interleave. Por ejemplo, si los bits 0, 2 y 5 están establecidos en nodemask, y los contenidos de /sys/kernel/mm/mempolicy/weighted_interleave/node0, /sys/.../node2, y /sys/.../node5 son 4, 7 y 9, respectivamente, entonces las páginas en esta región se asignarán en los nodos 0, 2 y 5 en una proporción de 4:7:9.
MPOL_PREFERRED
Este modo establece el nodo preferido para la asignación. El kernel intentará asignar páginas desde este nodo primero y recurrirá a otros nodos si el nodo preferido tiene poca memoria libre. Si nodemask especifica más de un ID de nodo, el primer nodo en la máscara se seleccionará como el nodo preferido. Si los argumentos nodemask y maxnode especifican el conjunto vacío, entonces la memoria se asigna en el nodo de la CPU que activó la asignación.
MPOL_PREFERRED_MANY (desde Linux 5.15)
S
pecifica un conjunto de nodos para la asignación; véase set_mempolicy(2).
MPOL_LOCAL (desde Linux 3.8)
Este modo especifica la "asignación local"; la memoria se asigna en el nodo de la CPU que desencadenó la asignación (el nodo "local"). Los argumentos nodemask y maxnode deben especificar el conjunto vacío. Si el nodo "local" tiene poca memoria libre, el kernel intentará asignar memoria de otros nodos. El kernel asignará memoria del nodo "local" siempre que haya memoria disponible para este nodo. Si el nodo "local" no está permitido por el contexto actual del cpuset del hilo, el kernel intentará asignar memoria de otros nodos. El kernel asignará memoria del nodo "local" siempre que se permita por el contexto actual del cpuset del hilo. Por el contrario, MPOL_DEFAULT revierte a la política de memoria del hilo (que puede establecerse a través de set_mempolicy(2)); esa política puede ser algo distinto de la "asignación local".

Si se pasa MPOL_MF_STRICT en flags y mode no es MPOL_DEFAULT, entonces la llamada falla con el error EIO si las páginas existentes en el rango de memoria no siguen la política.

Si se especifica MPOL_MF_MOVE en flags, entonces el kernel intentará mover todas las páginas existentes en el rango de memoria para que sigan la política. Las páginas que se comparten con otros procesos no se moverán. Si también se especifica MPOL_MF_STRICT, entonces la llamada falla con el error EIO si algunas páginas no pudieron moverse. Si se especificó la política MPOL_INTERLEAVE, las páginas que ya residen en los nodos especificados no se moverán de forma que queden entrelazadas.

Si se pasa MPOL_MF_MOVE_ALL en flags, entonces el kernel intentará mover todas las páginas existentes en el rango de memoria independientemente de si otros procesos utilizan las páginas. El hilo que llama debe tener privilegios (CAP_SYS_NICE) para usar esta bandera. Si también se especifica MPOL_MF_STRICT, entonces la llamada falla con el error EIO si algunas páginas no pudieron moverse. Si se especificó la política MPOL_INTERLEAVE, las páginas que ya residen en los nodos especificados no se moverán de forma que queden entrelazadas.

VALOR DE RETORNO

En caso de éxito, mbind() devuelve 0; en caso de error, devuelve -1 y errno se establece para indicar el error.

ERRORES

EFAULT
Parte o la totalidad del rango de memoria especificado por nodemask y maxnode apunta fuera de su espacio de direcciones accesible. O, hubo un agujero no mapeado en el rango de memoria especificado por addr y size.
EINVAL
Se especificó un valor inválido para flags o mode; o addr + size fue menor que addr; o addr no es un múltiplo del tamaño de página del sistema. O, mode es MPOL_DEFAULT y nodemask especificó un conjunto no vacío; o mode es MPOL_BIND o MPOL_INTERLEAVE y nodemask está vacío. O, maxnode excede un límite impuesto por el kernel. O, nodemask especifica uno o más IDs de nodo que son mayores que el ID de nodo máximo admitido. O, ninguno de los IDs de nodo especificados por nodemask están en línea y permitidos por el contexto actual del cpuset del hilo, o ninguno de los nodos especificados contiene memoria. O, el argumento mode especificó tanto MPOL_F_STATIC_NODES como MPOL_F_RELATIVE_NODES.
EIO
Se especificó MPOL_MF_STRICT y una página existente ya estaba en un nodo que no sigue la política; o se especificó MPOL_MF_MOVE o MPOL_MF_MOVE_ALL y el kernel no pudo mover todas las páginas existentes en el rango.
ENOMEM
No había suficiente memoria de kernel disponible.
EPERM
El argumento flags incluía la bandera MPOL_MF_MOVE_ALL y el llamante no tiene el privilegio CAP_SYS_NICE.

ESTANDARES

Linux.

HISTORIAL

Linux 2.6.7.

El soporte para la política de páginas grandes se añadió con Linux 2.6.16. Para que la política de entrelazado sea efectiva en las asignaciones de páginas grandes, la memoria policitada necesita ser de decenas de megabytes o más.

Antes de Linux 5.7, MPOL_MF_STRICT se ignoraba en las asignaciones de páginas grandes.

MPOL_MF_MOVE y MPOL_MF_MOVE_ALL solo están disponibles en Linux 2.6.16 y posteriores.

NOTAS

Para obtener información sobre el soporte de la biblioteca, véase numa(7).

La política NUMA no se admite en un rango de archivo mapeado en memoria que se mapeó con la bandera MAP_SHARED.

El modo MPOL_DEFAULT puede tener efectos diferentes para mbind() y set_mempolicy(2). Cuando se especifica MPOL_DEFAULT para set_mempolicy(2), la política de memoria del hilo vuelve a la política predeterminada del sistema o a la asignación local. Cuando se especifica MPOL_DEFAULT para un rango de memoria usando mbind(), cualquier página asignada posteriormente para ese rango utilizará la política de memoria del hilo, según lo establecido por set_mempolicy(2). Esto elimina efectivamente la política explícita del rango especificado, "volviendo" a una política posiblemente no predeterminada. Para seleccionar la "asignación local" explícita para un rango de memoria, especifique un mode de MPOL_LOCAL o MPOL_PREFERRED con un conjunto vacío de nodos. Este método también funcionará para set_mempolicy(2).
