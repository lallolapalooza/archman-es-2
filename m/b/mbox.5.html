mbox(5) Manuales de usuario mbox(5)

NOMBRE

mbox - Formato para el almacenamiento de mensajes de correo.

DESCRIPCIÓN

Este documento describe el formato tradicionalmente utilizado por los hosts de Unix para almacenar mensajes de correo localmente. Los archivos mbox residen típicamente en el spool de correo del sistema, bajo varios nombres en los directorios Mail de los usuarios, y bajo el nombre mbox en los directorios de inicio de los usuarios.

Un mbox es un archivo de texto que contiene un número arbitrario de mensajes de correo electrónico. Cada mensaje consiste en un sello de fecha y hora, seguido de un mensaje de correo electrónico formateado de acuerdo con RFC822, RFC2822. El formato del archivo está orientado a líneas. Las líneas están separadas por caracteres de salto de línea (ASCII 10).

Una línea de sello de fecha y hora consiste en los cuatro caracteres "From", seguido de un carácter de espacio, seguido de la dirección del remitente del sobre del mensaje, seguido de espacios en blanco y seguido de una marca de tiempo. Esta línea a menudo se llama línea From_.

Se espera que la dirección del remitente sea addr-spec tal como se define en RFC2822 3.4.1. Se espera que la fecha sea date-time tal como la genera asctime(3). Por razones de compatibilidad con software heredado, los años de dos dígitos mayores o iguales a 70 deben interpretarse como los años 1970+, mientras que los años de dos dígitos menores a 70 deben interpretarse como los años 2000-2069. El software que lee archivos en este formato también debe estar preparado para aceptar información de zona horaria no numérica, como "CET DST" para la hora de Europa Central, horario de verano.

Ejemplo:

>From example@example.com Fri Jun 23 02:56:55 2000

Para evitar la mala interpretación de líneas en los cuerpos de los mensajes que comienzan con los cuatro caracteres "From", seguidos de un carácter de espacio, el agente de entrega de correo debe escapar cualquier ocurrencia de "From " al principio de una línea del cuerpo.

Hay dos esquemas de escape diferentes, el primero (MBOXO) solo escapa las líneas "From " simples en el cuerpo anteponiendo un '>' a la línea; el segundo (MBOXRD) también escapa las líneas "From " ya escapadas anteponiendo un '>' (es decir, ">From ", ">>From ", ...). Este último tiene la ventaja de que líneas como

>From the command line you can use the '-p' option

no se decodifican erróneamente ya que un MDA MBOXRD convertiría la línea en

>>From the command line you can use the '-p' option

antes de almacenarla. Además de MBOXO y MBOXRD, también existe MBOXCL, que es MBOXO con un campo "Content-Length:" con el número de bytes en el cuerpo del mensaje; algunos MUA (como mutt(1)) transforman automáticamente los buzones MBOXO en buzones MBOXCL ya que cualquier MUA MBOXO puede leer MBOXCL sin ningún problema.

Si la hora de modificación (generalmente determinada mediante stat(2)) de un archivo mbox no vacío es mayor que la hora de acceso, el archivo tiene correo nuevo. Muchos MUA colocan una cabecera Status: en cada mensaje para indicar qué mensajes ya se han leído.

BLOQUEO

Dado que los archivos mbox son accedidos frecuentemente por múltiples programas en paralelo, los archivos mbox generalmente no deben ser accedidos sin bloqueo.

Tres mecanismos de bloqueo diferentes (y combinaciones de ellos) están en uso general:

  • El bloqueo fcntl(2) se usa principalmente en sistemas recientes y compatibles con POSIX. El uso de este método de bloqueo es, en particular, aconsejable si los archivos mbox se acceden a través del Network File System (NFS), ya que parece ser la única forma de invalidar de manera confiable las cachés de los clientes NFS.
  • El bloqueo flock(2) se usa principalmente en sistemas basados en BSD.
  • El bloqueo de puntos (Dotlocking) se utiliza en todo tipo de sistemas. Para bloquear un archivo mbox llamado folder, una aplicación primero crea un archivo temporal con un nombre único en el directorio en el que reside el folder. Luego, la aplicación intenta usar la llamada al sistema link(2) para crear un enlace duro llamado folder.lock al archivo temporal. El éxito de la llamada al sistema link(2) debe verificarse adicionalmente utilizando llamadas a stat(2). Si el enlace ha tenido éxito, se considera que la carpeta de correo está bloqueada por puntos. Luego, el archivo temporal puede ser eliminado de forma segura.
Para liberar el bloqueo, una aplicación simplemente elimina el archivo folder.lock.

Si se combinan varios métodos, los implementadores deben asegurarse de utilizar las variantes de no bloqueo de las llamadas al sistema fcntl(2) y flock(2) para evitar interbloqueos.

Si se combinan varios métodos, un archivo mbox no debe considerarse bloqueado con éxito hasta que se obtengan todos los bloqueos individuales. Cuando uno de los métodos de bloqueo individuales falla, una aplicación debe liberar todos los bloqueos que adquirió con éxito y reiniciar todo el procedimiento de bloqueo desde el principio, después de un retraso adecuado.

El mecanismo de bloqueo utilizado en un sistema particular es una cuestión de política local y debe ser utilizado de manera consistente por todas las aplicaciones instaladas en el sistema que acceden a los archivos mbox. El incumplimiento de esto puede resultar en la pérdida de datos de correo electrónico y en archivos mbox corruptos.

ARCHIVOS

/var/spool/mail/$LOGNAME

Carpeta de correo entrante de $LOGNAME.

$HOME/mbox

Mensajes de correo archivados del usuario, en su directorio $HOME.

$HOME/Mail/

Un directorio en el directorio $HOME del usuario que se utiliza comúnmente para mantener carpetas en formato mbox.
