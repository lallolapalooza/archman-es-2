NOMBRE

mbuffer - buffer de medición

SINTAXIS

mbuffer [opciones]

DESCRIPCIÓN

mbuffer almacena en búfer las operaciones de E/S y muestra la tasa de rendimiento. Es multihilo, soporta conexiones de red, múltiples destinos de salida y muchas más opciones que el comando buffer estándar.

OPCIONES

-b <num>
Usa num bloques para el búfer (el valor por defecto se determina al arrancar).
-s <tamaño>
Usa bloques de tamaño bytes para el búfer (el valor por defecto se determina al arrancar).
-m <tamaño>
Usa un total de tamaño bytes para el búfer (por defecto 2% de la memoria disponible). El tamaño se puede establecer con un carácter sufijo (b y B para Byte, k para kByte, M para MByte, G para Gigabyte, y con % para un porcentaje de la memoria física total).
-L
Bloquea el búfer en memoria. Esta opción no está disponible para búferes basados en archivos y requiere que mbuffer tenga el bit SUID root (usar con precaución).
-d
Usa el tamaño de bloque del dispositivo para la salida (necesario para algunos dispositivos, ralentiza la salida).
-D <tamaño>
Asume un volumen de salida de tamaño bytes (por defecto infinito) después del cual se iniciará un cambio de volumen. Valores pequeños son útiles para la prueba oportuna de ejecuciones de múltiples volúmenes; valores precisos si tu dispositivo no señala correctamente el fin del medio. El tamaño se puede establecer con un carácter sufijo (b y B para Byte, k para kByte, M para MByte, o G para Gigabyte).
-P <num>
Comienza a escribir después de que el búfer se haya llenado hasta el num% (por defecto 0 - comenzar inmediatamente).
-p <num>
Comienza a leer después de que el búfer haya caído por debajo de la relación de llenado del num% (por defecto 100 - comenzar inmediatamente).
-i <nombre_archivo>
Usa nombre_archivo como entrada en lugar de la entrada estándar (necesita ser especificado para soporte de múltiples volúmenes). Si nombre_archivo es -, la entrada se lee de la entrada estándar.
-o <nombre_archivo>
Usa nombre_archivo como salida en lugar de la salida estándar (necesita ser especificado para soporte de múltiples volúmenes, habilitará el uso de sendfile si está disponible). Si nombre_archivo es -, la salida se escribe en la salida estándar. La opción -o se puede pasar varias veces para especificar múltiples salidas.
--append
Abre el siguiente archivo de salida dado a través de la opción -o en modo de adición.
--truncate
Trunca el siguiente archivo de salida dado a través de la opción -o al abrirlo.
-I <puerto>
Usa el puerto de red puerto como entrada en lugar de la entrada estándar. Si se proporciona un nombre de host y un puerto en el formato nombre_host:puerto, solo se permite la conexión al host dado.
-O <nombre_host:puerto>
Escribe la salida en nombre_host:puerto en lugar de la salida estándar (habilitará el uso de sendfile si está disponible). Esta opción se puede usar varias veces para enviar datos a múltiples máquinas.
-n <num>
num volúmenes en el dispositivo de entrada (requiere el uso de la opción -i para la especificación del dispositivo de entrada, pasa 0 como argumento si mbuffer debe solicitar cada nuevo volumen).
-t
Usa un archivo temporal mapeado en memoria como búfer (usar con búferes grandes).
-T <archivo>
Como -t pero usa archivo como búfer.
-l <archivo>
Registra mensajes en archivo en lugar de la salida de error estándar.
-u <num>
Pausa num microsegundos después de cada escritura. Puede aumentar el rendimiento en algunas unidades de muy bajo rendimiento (< 1 MB/seg).
-r <tasa>
Establece la tasa máxima de lectura a tasa. La tasa se puede dar en Bytes, kBytes, MBytes o GBytes por segundo. Para hacerlo, usa un sufijo apropiado (es decir, k,M,G). Esta opción es útil si tienes una cinta que es capaz de transferir datos más rápido de lo que el host puede manejar. En este caso, puedes usar esta opción para limitar la tasa de transferencia y mantener la cinta en funcionamiento. Ten en cuenta que esto es bueno para tu unidad de cinta y mejora el rendimiento general, al evitar el desgaste de la cinta.
-R <tasa>
Igual que arriba, pero para establecer el límite de transferencia para el escritor.
-f
Sobrescribe el archivo de salida si ya existe.
-a <tiempo>
El dispositivo utilizado es un cargador automático que tarda tiempo segundos en cargar una nueva cinta.
-A <cmd>
El dispositivo utilizado es un cargador automático que usa cmd para cargar el siguiente volumen. Pasa </bin/false> como comando de carga automática para suprimir el mensaje de advertencia que aparece cuando se ejecuta sin una terminal de control (por ejemplo, a través de cron). De esta manera, la carga automática fallará y mbuffer terminará con un mensaje de error al llegar al final de la cinta.
-v <nivel>
Establece el nivel de verbosidad a num. Los valores válidos son 0..6 (0 = ninguno, 1 = errores, 2 = advertencias, 4 = mensajes de información, 5 = mensajes de depuración, 6 = depuración de E/S). Los valores más altos incluyen los mensajes de los valores más bajos.
-q
Silencioso - no muestra el estado en la salida de error estándar.
-Q
Silencioso - no registra el estado en el archivo de registro.
-c
Escribe con soporte de integridad de datos síncrona. Esta opción fuerza que todas las escrituras se completen antes de continuar. Esto permite que los errores se informen antes y con mayor precisión, pero puede disminuir el rendimiento. Especialmente los sistemas con un alto nivel de soporte de integridad de datos sufren una gran penalización de rendimiento. Otros pueden parecer no afectados, pero simplemente descuidan el soporte de integridad de datos síncrona completa.
-e
Detener el procesamiento ante cualquier tipo de error.
-H, --md5
Genera un hash MD5 de los datos transferidos.
--hash <alg>
Usa el algoritmo alg, si alg es 'list' los algoritmos posibles se listan.
--pid
Imprime el PID de esta instancia. Esta opción puede ayudarte a averiguar qué instancia de mbuffer matar, si varias se están ejecutando y una se queda colgada debido a un problema de red. La impresión del PID también se puede activar añadiendo "printpid = 1" a tu archivo .mbuffer.rc.
-W <tiempo_espera>
Activa un perro guardián que se activa cada tiempo_espera segundos y comprueba si la actividad de E/S se ha detenido. Si alguno de los canales se ha detenido durante un período completo, el perro guardián escribe un mensaje de error y termina mbuffer a través de SIGINT. Ten en cuenta que el perro guardián no es consciente de las actividades de cambio de cinta. Así que elige un tiempo de espera del perro guardián mayor que el tiempo de cambio de cinta en el peor de los casos. El perro guardián se activa al analizar la opción -W o después de analizar todas las opciones. Para evitar que el perro guardián se active durante la inicialización de la red, coloca la opción -W después de -I y -O.
-4
Forzar el modo IPv4 para las siguientes opciones de E/S de red en la línea de comandos.
-6
Forzar el modo IPv6 para las siguientes opciones de E/S de red en la línea de comandos.
-0
Elegir modo IPv4/IPv6 bajo demanda.
--no-direct
Omitir el uso de O_DIRECT, por ejemplo, para habilitar la compresión en btrfs.

--tcpbuffer

Tamaño del búfer TCP en bytes. El tamaño se puede establecer con un carácter de sufijo (b y B para Byte, k para kByte, M para MByte o G para Gigabyte).
--tcptimeo tiempo
Establece el umbral de tiempo de espera de TCP. El valor predeterminado es 10 s. Los argumentos sin dimensión se interpretan como microsegundos. Las dimensiones de los argumentos pueden ser us, ms, s o sec, m o min, h.
--tapeaware
Continuar escribiendo hasta el final de la cinta. Las unidades LTO informan al sistema operativo cuando se acercan al final de la cinta, lo que Linux pasa al espacio de usuario devolviendo un error de "no queda espacio" en cada segunda operación de escritura. Normalmente, el primer error se trata como el final de la cinta y se solicita el siguiente volumen, sin embargo, con esta opción, las escrituras continuarán hasta que dos consecutivas fallen con "no queda espacio", lo que indica el final real de la cinta. Esto permitirá que quepan un poco más de datos en cada cinta.
--direct
Utilizar E/S directa para el búfer de archivos temporales.
-h, --help
Muestra la información de ayuda y sale.
-V, --version
Muestra la información de la versión y sale.

VALORES PREDETERMINADOS

Los valores predeterminados para la mayoría de las opciones se pueden establecer como pares de clave = valor en uno o más archivos de configuración. Consulte los archivos de ejemplo mbuffer.rc para ver las opciones disponibles y sus valores predeterminados. Los archivos de configuración se leen en la siguiente secuencia:

- /etc/mbuffer.rc
- $PREFIX/etc/mbuffer.rc
- $HOME/.mbuffer.rc
- $MBUFFERRC

Los valores predeterminados dados en los archivos anteriores se anulan por las opciones pasadas en la línea de comandos.

VARIABLES DE ENTORNO

Si se establece TMPDIR, mbuffer asigna almacenamiento para búferes basados en archivos en este directorio. Si TMPDIR no está configurado, se utilizará /var/tmp.
MBUFFERRC se puede usar para establecer un archivo de configuración mbuffer.rc personalizado.
MBUFFER_VOL información del id. de volumen (establecido para el comando de cargador automático).
MBUFFER_NUMIN número de bytes leídos (establecido para el comando de cargador automático).
MBUFFER_NUMOUT número de bytes escritos (establecido para el comando de cargador automático).

ARCHIVOS

$PREFIX/bin/mbuffer
/var/tmp/mbuffer-*
~/.mbuffer.rc

EJEMPLOS

Para ejecutar este programa con las opciones predeterminadas, simplemente escriba:

mbuffer

Usar mbuffer para hacer una copia de seguridad con tar en el dispositivo de cinta predeterminado. Opciones para este ejemplo: archivo temporal asignado en memoria con un tamaño de 10 Megabytes, comenzar después de que se haya llenado el 80% del búfer.

tar cf - mydirectory | gzip | mbuffer -t -m 10M -P 80 -f -o $TAPE

Usar mbuffer con 3 cintas para entrada y extraer el contenido en el directorio de trabajo actual:

mbuffer -n 3 -i $TAPE | gzip -dc | tar xf -

Usar mbuffer para escribir en múltiples volúmenes de cinta:

tar cf - /usr | mbuffer -f -o $TAPE

Escribir en múltiples cintas y borrar cada cinta antes de escribir:

tar cf - /usr | mbuffer -A "echo next tape; read a < /dev/tty; mt erase $TAPE" -f -o $TAPE

Realizar una copia de seguridad a través de la red:

servidor de cintas: mbuffer -I 8000 -f -o $TAPE

cliente de copia de seguridad: tar zcf - /home | mbuffer -O tapeserver:8000

Distribuir un árbol de directorios a múltiples máquinas:

maestro: tar cf - /tree_to_clone | mbuffer -O clone0:8000 -O clone1:8000

clones: mbuffer -I master:8000 | tar xf -

CODIGO DE SALIDA

mbuffer devuelve 0 si la operación es exitosa. Cualquier tipo de fallo generará un código de salida distinto de cero.
