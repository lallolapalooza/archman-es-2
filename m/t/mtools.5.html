Nombre

mtools.conf - Archivos de configuración de mtools

Descripción

Esta página del manual describe los archivos de configuración de mtools. Se llaman `/etc/mtools.conf' y `~/.mtoolsrc'. Si la variable de entorno MTOOLSRC está configurada, su contenido se utiliza como nombre de archivo para un tercer archivo de configuración. Estos archivos de configuración describen los siguientes elementos:

*  Flags y variables de configuración globales 
*  Flags y variables por unidad 

Ubicación de los archivos de configuración

`/etc/mtools.conf' es el archivo de configuración a nivel de sistema, y `~/.mtoolsrc' es el archivo de configuración privado del usuario.

En algunos sistemas, el archivo de configuración a nivel de sistema se llama `/etc/default/mtools.conf' en su lugar.

  Sintaxis general del archivo de configuración

Los archivos de configuración se componen de secciones. Cada sección comienza con una palabra clave que identifica la sección seguida de dos puntos. Luego siguen asignaciones de variables y flags. Las asignaciones de variables tienen el siguiente formato:

nombre=valor

Los flags son palabras clave solitarias sin un signo igual y un valor que las siga. Una sección termina al final del archivo o donde comienza la siguiente sección.

Las líneas que comienzan con una almohadilla (#) son comentarios. Los caracteres de nueva línea son equivalentes a espacios en blanco (excepto donde terminan un comentario). El archivo de configuración no distingue entre mayúsculas y minúsculas, excepto para los elementos incluidos entre comillas (como los nombres de archivo).

Valores predeterminados

Para la mayoría de las plataformas, mtools contiene valores predeterminados razonables compilados para unidades de disquete físicas. Por lo tanto, por lo general no necesitas preocuparte por el archivo de configuración si todo lo que quieres hacer con mtools es acceder a tus unidades de disquete. Por otro lado, el archivo de configuración es necesario si también quieres usar mtools para acceder a las particiones de tu disco duro y a los archivos de imagen de DOSEMU.

Variables globales

Los flags globales se pueden establecer a 1 o a 0.

Se reconocen los siguientes flags globales:

MTOOLS_SKIP_CHECK 
Si se establece en 1, mtools omite la mayoría de sus comprobaciones de seguridad. Esto es necesario para leer algunos discos de Atari que se han creado con ROMs anteriores y que de otro modo no se reconocerían.
MTOOLS_FAT_COMPATIBILITY 
Si se establece en 1, mtools omite las comprobaciones de tamaño de la FAT. Algunos discos tienen una FAT más grande de la que realmente necesitan. Estos se rechazan si esta opción no está establecida.
MTOOLS_LOWER_CASE 
Si se establece en 1, mtools muestra los nombres de archivo cortos en mayúsculas como minúsculas. Esto se ha hecho para permitir un comportamiento coherente con las versiones anteriores de mtools que no conocían los bits de mayúsculas/minúsculas.
MTOOLS_NO_VFAT 
Si se establece en 1, mtools no generará entradas VFAT para nombres de archivo que tengan mayúsculas y minúsculas combinadas, pero que de otro modo sean nombres de archivo DOS legales. Esto es útil cuando se trabaja con versiones de DOS que no pueden interpretar nombres largos VFAT, como FreeDOS.
MTOOLS_DOTTED_DIR 
En un directorio ancho, imprime el nombre corto con un punto en lugar de espacios separando el nombre base y la extensión.
MTOOLS_NAME_NUMERIC_TAIL 
Si se establece en uno (predeterminado), genera colas numéricas para todos los nombres largos (~1). Si se establece en cero, solo genera colas numéricas si de lo contrario habría un conflicto.
MTOOLS_TWENTY_FOUR_HOUR_CLOCK 
Si es 1, utiliza la notación europea para las horas (reloj de 24 horas), de lo contrario utiliza la notación del Reino Unido/EE. UU. (am/pm)
MTOOLS_LOCK_TIMEOUT 
Cuánto tiempo, en segundos, esperar a que un dispositivo bloqueado quede libre. El valor predeterminado es 30.

Ejemplo: Insertar la siguiente línea en su archivo de configuración indica a mtools que omita las comprobaciones de seguridad:

  MTOOLS_SKIP_CHECK=1

Las variables globales también se pueden establecer a través del entorno:

  export MTOOLS_SKIP_CHECK=1

Las variables de cadena globales se pueden establecer a cualquier valor:

MTOOLS_DATE_STRING 
El formato utilizado para imprimir las fechas de los archivos. Por predeterminado, es dd-mm-aaaa.

  Información&#x00A0;general

Los flags y valores por unidad se pueden describir en una sección de unidad. Una sección de unidad comienza con drive "letra_unidad" :

Luego siguen pares de variable-valor y flags.

Esta es una descripción de ejemplo de unidad:

  drive a:
    file="/dev/fd0" use_xdf=1

  Información&#x00A0;de&#x00A0;ubicación

Para cada unidad, debes describir dónde se almacenan físicamente los datos (archivo de imagen, dispositivo físico, partición, desplazamiento).

file 
El nombre del archivo o dispositivo que contiene la imagen del disco. Esto es obligatorio. El nombre del archivo debe ir entre comillas.
partition 
Indica a mtools que trate la unidad como un dispositivo particionado y que utilice la partición dada. Solo se puede acceder a las particiones primarias mediante este método, y se numeran del 1 al 4. Para particiones lógicas, utiliza la variable más general offset. La variable partition está pensada para medios extraíbles como discos Syquest, unidades ZIP y discos magneto-ópticos. Aunque DOS tradicional ve los discos Syquest y los discos magneto-ópticos como `disquetes gigantes' que no están particionados, OS/2 y Windows NT los tratan como discos duros, es decir, dispositivos particionados. El flag partition también es útil para las imágenes de disco duro de DOSEMU. No se recomienda para discos duros para los que se dispone de acceso directo a las particiones mediante montaje.
offset 
Describe dónde en el archivo comienza el sistema de archivos MS-DOS. Esto es útil para particiones lógicas en imágenes de disco duro de DOSEMU y para discos RAM ATARI. Por defecto, esto es cero, lo que significa que el sistema de archivos comienza justo al principio del dispositivo o archivo.

GEOMETRÍA Y PARÁMETROS DEL DISPOSITIVO

Hay dos formas de especificar la geometría de un disco. La primera es usando los parámetros específicos del dispositivo, y la segunda es usando las formas abreviadas descritas abajo. Si ambos métodos se utilizan, los parámetros específicos del dispositivo anulan las formas abreviadas.

GEOMETRY
Permite especificar la geometría física del medio. Esto es necesario para dispositivos que no pueden auto-detectar su geometría, o si necesita acceder a un dispositivo en un modo de geometría específico que difiere de la geometría actual del disco. Por ejemplo, podría necesitar un nodo diferente para acceder a un disco como de alta densidad o de baja densidad. La geometría se compara con la geometría real almacenada en el sector de arranque para asegurarse de que este nodo de dispositivo puede leer correctamente el disco. Si la geometría no coincide, la entrada de este disco falla y se intenta la siguiente entrada de disco con la misma letra de unidad. Consulte la sección múltiples descripciones para obtener más detalles sobre cómo proporcionar varias descripciones para una letra de unidad.
Si no se proporciona información de geometría en el archivo de configuración, se aceptan todos los discos. En Linux (y en SPARC) existen nodos de dispositivo con geometría configurable (/dev/fd0, /dev/fd1, etc.), por lo que el filtrado no es necesario (e se ignora) para las unidades de disco. (Mtools todavía realiza filtrado en archivos planos (imágenes de disco) en Linux: esto está principalmente destinado a propósitos de prueba, ya que no tengo acceso a un Unix que realmente necesite filtrado).
Si no necesita filtrado, pero aún desea una geometría predeterminada para mformatear, puede desactivar el filtrado utilizando la bandera mformat_only.
Si desea filtrado, debe proporcionar la bandera filter. Si proporciona una geometría, debe proporcionar una de las dos banderas.
GEOMETRÍA INICIAL 
En dispositivos que lo admiten (generalmente dispositivos de disquete), la información de geometría también se utiliza para establecer la geometría inicial. Esta geometría inicial se aplica al leer el sector de arranque, que contiene la geometría real. Si no se proporciona información de geometría en el archivo de configuración, o si se proporciona la bandera mformat_only, no se realiza ninguna configuración inicial.
En Linux, la geometría inicial no es realmente necesaria, ya que los dispositivos configurables pueden auto-detectar el tipo de disco con suficiente precisión (para los formatos más comunes) para leer el sector de arranque.

Información de geometría incorrecta puede llevar a errores muy extraños. Por eso, recomiendo encarecidamente que agregue la bandera mformat_only a la descripción de su dispositivo, a menos que realmente necesite filtrado o geometría inicial.

Las siguientes variables relacionadas con la geometría están disponibles:

cylinders 

tracks
El número de cilindros. (cylinders es la forma preferida, tracks se considera obsoleta)
heads 
El número de cabezales (lados).
sectors 
El número de sectores por pista.

Ejemplo: la siguiente sección de dispositivo describe una unidad de 1.44M:

  drive a:
      file="/dev/fd0H1440"
      fat_bits=12
      cylinders=80 heads=2 sectors=18
      mformat_only

Las siguientes descripciones abreviadas de geometría están disponibles:

1.44m 
disco de 3 1/2 de alta densidad. Equivalente a: fat_bits=12 cylinders=80 heads=2 sectors=18
1.2m 
disco de 5 1/4 de alta densidad. Equivalente a: fat_bits=12 cylinders=80 heads=2 sectors=15
720k 
disco de 3 1/2 de doble densidad. Equivalente a: fat_bits=12 cylinders=80 heads=2 sectors=9
360k 
disco de 5 1/4 de doble densidad. Equivalente a: fat_bits=12 cylinders=40 heads=2 sectors=9

Los formatos abreviados pueden ser modificados. Por ejemplo, 360k sectors=8 describe un disco de 320k y es equivalente a: fat_bits=12 cylinders=40 heads=2 sectors=8

  Flags de Apertura

Además, las siguientes banderas están disponibles:

sync 
Todas las operaciones de i/o se realizan de forma síncrona
nodelay 
El dispositivo o archivo se abre con la bandera O_NDELAY. Esto es necesario en algunas arquitecturas no Linux.
exclusive 
El dispositivo o archivo se abre con la bandera O_EXCL. En Linux, esto garantiza acceso exclusivo a la unidad de disquete. En la mayoría de las otras arquitecturas, y para archivos planos, no tiene ningún efecto.

  Variables&#x00A0;de&#x00A0;Propósito&#x00A0;General&#x00A0;del&#x00A0;Dispositivo

Las siguientes variables de propósito general del dispositivo están disponibles. Dependiendo de su tipo, estas variables pueden establecerse a una cadena (precmd, postcmd) o a un entero (todos los demás)

fat_bits 
El número de bits FAT. Puede ser 12 o 16. Esto rara vez es necesario, ya que casi siempre se puede deducir de la información en el sector de arranque. Por el contrario, describir el número de bits FAT puede ser perjudicial si lo hace mal. Solo debe usarlo si mtools obtiene incorrectamente el número de bits FAT auto-detectado, o si desea mformatear un disco con un número de bits FAT extraño.
codepage 
Describe la página de códigos DOS utilizada para nombres de archivo cortos. Es un número entre 1 y 999. Por defecto, se utiliza la página de códigos 850. La razón es que esta página de códigos contiene la mayoría de los caracteres que también están disponibles en ISO-Latin-1. También puede especificar una página de códigos global para todas las unidades utilizando el parámetro global default_codepage (fuera de cualquier descripción de unidad). Este parámetro existe a partir de la versión 4.0.0.
data_map 
Reasigna datos del archivo de imagen. Esto es útil para archivos de imagen que podrían necesitar la inserción de sectores adicionales rellenos de ceros. Tal es el caso, por ejemplo, de las imágenes de disquete IBM 3174. Estas imágenes representan discos de disquete con menos sectores en su primer cilindro. Estos sectores faltantes no se almacenan en la imagen, pero aún se cuentan en la disposición del sistema de archivos. El data_map permite simular estos sectores faltantes para las capas superiores de mtools. Un data_map es una secuencia separada por comas de tipo de fuente y tamaño. El tipo de fuente puede ser zero para sectores rellenos de ceros creados por el mapa, skip para datos en la imagen sin procesar que deben ignorarse (omitidos), y nada para datos que deben usarse tal cual (copiados) de la imagen sin procesar. Datamap se complementa automáticamente con un último elemento implícito de datos que se usarán tal cual desde el desplazamiento actual hasta el final del archivo. Cada tamaño es un número seguido de una unidad: s para un sector de 512 bytes, K para Kbytes, M para megabytes, G para gigabytes, y nada para bytes individuales.
Ejemplo:
data_map=1s,zero31s,28s,skip1s sería un mapa para usar con imágenes de disquete IBM 3174. El primer sector (1s, sector de arranque) se utiliza tal cual. Luego siguen 31 sectores falsos rellenos de ceros (zero31s), luego los siguientes 28 sectores de la imagen (28s) se utilizan tal cual (contienen FAT y directorio raíz), luego se omite un sector de la imagen (skip1s), y finalmente el resto de la imagen se utiliza tal cual (implícito).
precmd 
Ejecuta el comando dado antes de abrir el dispositivo. En algunas variantes de Solaris, es necesario llamar a 'volcheck -v' antes de abrir un dispositivo de disquete, para que el sistema note que realmente hay un disco en la unidad. precmd="volcheck -v" en la cláusula de dispositivo establece el comportamiento deseado.
postcmd 
Ejecuta el comando dado después de cerrar el dispositivo. Puede ser útil si mtools comparte el archivo de imagen con alguna otra aplicación, para liberar el archivo de imagen a esa aplicación.
blocksize 
Este parámetro representa un tamaño de bloque predeterminado que se usará siempre en este dispositivo. Todas las operaciones de I/O se realizan con múltiplos de este tamaño de bloque, independientemente del tamaño de sector registrado en el sector de arranque del sistema de archivos. Esto es útil para dispositivos de caracteres cuyo tamaño de sector no es 512, como por ejemplo las unidades de CD-ROM en Solaris.

Solo la variable file es obligatoria. Los otros parámetros pueden omitirse. En ese caso, se utiliza un valor predeterminado o un valor auto-detectado.

  Flags&#x00A0;de&#x00A0;Propósito&#x00A0;General&#x00A0;del&#x00A0;Dispositivo

Una bandera puede establecerse en 1 (activada) o 0 (desactivada). Si el valor se omite, se activa. Por ejemplo, scsi es equivalente a scsi=1

nolock 
Indica a mtools que no utilice bloqueo en esta unidad. Esto es necesario en sistemas con semántica de bloqueo defectuosa. Sin embargo, activar esto hace que la operación sea menos segura en casos donde varios usuarios puedan acceder a la misma unidad al mismo tiempo.
scsi 
Cuando se establece en 1, esta opción indica a mtools que utilice I/O SCSI sin procesar en lugar de las llamadas estándar de lectura/escritura para acceder al dispositivo. Actualmente, esto es compatible con HP-UX, Solaris y SunOS. Esto es necesario porque en algunas arquitecturas, como SunOS o Solaris, los medios de PC no se pueden acceder utilizando las llamadas al sistema read y write, porque el SO espera que contengan una etiqueta de disco específica de Sun.
Dado que el acceso SCSI sin procesar siempre utiliza todo el dispositivo, necesita especificar la bandera "partition" además.

Name

mtools – a set of utilities to access DOS disks.

Description

This section describes the meaning of the drive variables that can be set in `/etc/mtools.conf', `~/.mtoolsrc' or `$MTOOLSRC'.

scsi 
When set to 1, this tells mtools to use the SCSI interface to access the drive. This is required for Zip/Jaz drives on Solaris, and possibly other devices too. On Solaris, mtools must be installed setuid root if you want to access Zip/Jaz drives. Thus, if the scsi flag is given, privileged is automatically implied, unless explicitly disabled by privileged=0
Mtools uses its root privileges to open the device, and to issue the actual SCSI I/O calls. Moreover, root privileges are only used for drives described in a system-wide configuration file such as `/etc/mtools.conf', and not for those described in `~/.mtoolsrc' or `$MTOOLSRC'.
privileged 
When set to 1, this instructs mtools to use its setuid and setgid privileges for opening the given drive. This option is only valid for drives described in the system-wide configuration files (such as `/etc/mtools.conf', not `~/.mtoolsrc' or `$MTOOLSRC'). Obviously, this option is also a no op if mtools is not installed setuid or setgid. This option is implied by 'scsi=1', but again only for drives defined in system-wide configuration files. Privileged may also be set explicitly to 0, in order to tell mtools not to use its privileges for a given drive even if scsi=1 is set.
Mtools only needs to be installed setuid if you use the privileged or scsi drive variables. If you do not use these options, mtools works perfectly well even when not installed setuid root.
vold 
Instructs mtools to interpret the device name as a vold identifier rather than as a filename. The vold identifier is translated into a real filename using the media_findname() and media_oldaliases() functions of the volmgt library. This flag is only available if you configured mtools with the --enable-new-vold option before compilation.
swap 
Consider the media as a word-swapped Atari disk.
use_xdf 
If this is set to a non-zero value, mtools also tries to access this disk as an XDF disk. XDF is a high capacity format used by OS/2. This is off by default. See section XDF, for more details.
mformat_only 
Tells mtools to use the geometry for this drive only for mformatting and not for filtering.
filter 
Tells mtools to use the geometry for this drive both for mformatting and filtering.
remote 
Tells mtools to connect to floppyd (see section floppyd).

  Suministrando múltiples descripciones para una unidad

Es posible suministrar múltiples descripciones para una unidad. En ese caso, las descripciones se prueban en orden hasta que se encuentra una que encaja. Las descripciones pueden fallar por varias razones:

1. 
porque la geometría no es apropiada,
2. 
porque no hay disco en la unidad,
3. 
o por otros problemas.

Las definiciones múltiples son útiles cuando se usan dispositivos físicos que solo pueden admitir una única geometría de disco. Ejemplo:

  drive a: file="/dev/fd0H1440" 1.44m
  drive a: file="/dev/fd0H720" 720k

Esto indica a mtools que use /dev/fd0H1440 para discos de 1.44m (alta densidad) y /dev/fd0H720 para discos de 720k (doble densidad). En Linux, esta característica no es realmente necesaria, ya que el dispositivo /dev/fd0 puede manejar cualquier geometría.

También puede usar múltiples descripciones de unidad para acceder a ambas unidades físicas a través de una sola letra de unidad:

  drive z: file="/dev/fd0"
  drive z: file="/dev/fd1"

Con esta descripción, mdir z: accede a su primera unidad física si contiene un disco. Si la primera unidad no contiene un disco, mtools comprueba la segunda unidad.

Al usar múltiples archivos de configuración, las descripciones de unidad en los archivos analizados posteriormente anulan las descripciones de la misma unidad en archivos anteriores. Para evitar esto, use las palabras clave drive+ o +drive en lugar de drive. La primera añade una descripción al final de la lista (es decir, se probará la última), y la primera la añade al principio de la lista.

Ubicación de los archivos de configuración y orden de análisis

Los archivos de configuración se analizan en el siguiente orden:

1. 
valores predeterminados compilados en el código
2. 
`/etc/mtools.conf'
3. 
`~/.mtoolsrc'.
4. 
`$MTOOLSRC' (archivo señalado por la variable ambiental MTOOLSRC)

Las opciones descritas en los archivos posteriores anulan las descritas en los archivos anteriores. Las unidades definidas en archivos anteriores persisten si no son anuladas en los archivos posteriores. Por ejemplo, las unidades A y B pueden definirse en `/etc/mtools.conf' y las unidades C y D pueden definirse en `~/.mtoolsrc'. Sin embargo, si `~/.mtoolsrc' también define la unidad A, esta nueva descripción anularía la descripción de la unidad A en `/etc/mtools.conf' en lugar de añadirle. Si desea añadir una nueva descripción a una unidad ya descrita en un archivo anterior, debe usar la palabra clave +drive o drive+.

Compatibilidad con versiones anteriores de la sintaxis del archivo de configuración

La sintaxis descrita aquí es nueva para la versión mtools-3.0. La sintaxis antigua basada en líneas todavía se admite. Cada línea que comienza con una sola letra se considera una descripción de unidad usando la sintaxis antigua. Las secciones de unidad de estilo antiguo y de estilo nuevo pueden mezclarse dentro del mismo archivo de configuración, para facilitar la actualización. El soporte para la sintaxis antigua se eliminará eventualmente, y para desalentar su uso, omito intencionadamente su descripción aquí.
