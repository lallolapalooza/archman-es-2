mtrace(3) Manual de funciones de biblioteca mtrace(3)

NOMBRE

mtrace, muntrace - rastreo de malloc

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <mcheck.h>
void mtrace(void);
void muntrace(void);

DESCRIPCIÓN

La función mtrace() instala funciones de gancho para las funciones de asignación de memoria (malloc(3), realloc(3) memalign(3), free(3)). Estas funciones de gancho registran información de rastreo sobre la asignación y liberación de memoria. La información de rastreo se puede utilizar para detectar fugas de memoria y intentos de liberar memoria no asignada en un programa.

La función muntrace() deshabilita las funciones de gancho instaladas por mtrace(), de modo que la información de rastreo ya no se registre para las funciones de asignación de memoria. Si mtrace() no instaló ninguna función de gancho con éxito, muntrace() no hace nada.

Cuando se llama a mtrace(), comprueba el valor de la variable de entorno MALLOC_TRACE, que debe contener la ruta del archivo en el que se registrará la información de rastreo. Si el nombre de ruta se abre correctamente, se trunca a longitud cero.

Si MALLOC_TRACE no está establecido, o el nombre de ruta que especifica es inválido o no es escribible, entonces no se instalan funciones de gancho y mtrace() no tiene ningún efecto. En programas con ID de usuario o grupo establecidos, MALLOC_TRACE se ignora y mtrace() no tiene ningún efecto.

ATRIBUTOS

Para obtener una explicación de los términos utilizados en esta sección, consulte attributes(7).

Interfaz Atributo Valor
mtrace (), muntrace () Seguridad de hilos MT-Unsafe

ESTANDARES

GNU.

NOTAS

En el uso normal, mtrace() se llama una vez al inicio de la ejecución de un programa, y muntrace() nunca se llama.

La salida de rastreo producida después de una llamada a mtrace() es textual, pero no está diseñada para ser legible por humanos. La biblioteca C de GNU proporciona un script de Perl, mtrace(1), que interpreta el registro de rastreo y produce una salida legible por humanos. Para obtener los mejores resultados, el programa rastreado debe compilarse con la depuración habilitada, de modo que la información del número de línea se registre en el ejecutable.

El rastreo realizado por mtrace() incurre en una penalización de rendimiento (si MALLOC_TRACE apunta a un nombre de ruta válido y escribible).

ERRORES

La información del número de línea producida por mtrace(1) no es siempre precisa: las referencias al número de línea pueden apuntar a la línea anterior o siguiente (no en blanco) del código fuente.

EJEMPLOS

La siguiente sesión de shell demuestra el uso de la función mtrace() y el comando mtrace(1) en un programa que tiene fugas de memoria en dos ubicaciones diferentes. La demostración utiliza el siguiente programa:


$ cat t_mtrace.c

#include <mcheck.h>
#include <stdio.h>
#include <stdlib.h>
int
main(void)
{
    mtrace();
    for (unsigned int j = 0; j < 2; j++)
        malloc(100);            /* Nunca liberado - una fuga de memoria */
    calloc(16, 16);             /* Nunca liberado - una fuga de memoria */
    exit(EXIT_SUCCESS);
}

Cuando ejecutamos el programa de la siguiente manera, vemos que mtrace() diagnosticó fugas de memoria en dos ubicaciones diferentes del programa:


$ cc -g t_mtrace.c -o t_mtrace
$ export MALLOC_TRACE=/tmp/t
$ ./t_mtrace
$ mtrace ./t_mtrace $MALLOC_TRACE
Memoria no liberada:
-----------------
   Dirección     Tamaño     Llamador
0x084c9378     0x64  en /home/cecilia/t_mtrace.c:12
0x084c93e0     0x64  en /home/cecilia/t_mtrace.c:12
0x084c9448    0x100  en /home/cecilia/t_mtrace.c:16

Los dos primeros mensajes sobre memoria no liberada corresponden a las dos llamadas a malloc(3) dentro del bucle *for*. El mensaje final corresponde a la llamada a calloc(3) (que a su vez llama a malloc(3)).

VER TAMBIÉN

mtrace(1), malloc(3), malloc_hook(3), mcheck(3)
