MTREE(5) Manual de formatos de archivo MTREE(5)

NOMBRE

mtree — formato de archivos de jerarquía de directorios de mtree

DESCRIPCIÓN

El formato mtree es un formato textual que describe una colección de objetos del sistema de archivos. Dichos archivos se utilizan típicamente para crear o verificar jerarquías de directorios.

Formato General

Un archivo mtree consta de una serie de líneas, cada una proporcionando información sobre un único objeto del sistema de archivos. Los espacios en blanco iniciales siempre se ignoran.

Al codificar nombres de archivo o de ruta, cualquier carácter de barra invertida o carácter fuera de los 95 caracteres ASCII imprimibles debe codificarse como una barra invertida seguida de tres dígitos octales. Al leer archivos mtree, cualquier aparición de una barra invertida seguida de tres dígitos octales debe convertirse en el carácter correspondiente.

Cada línea se interpreta de forma independiente como uno de los siguientes tipos:

En blanco
Las líneas en blanco se ignoran.
Comentario
Las líneas que comienzan con # se ignoran.
Especial
Las líneas que comienzan con / son comandos especiales que influyen en la interpretación de las líneas posteriores.
Relativo
Si la primera palabra delimitada por espacios en blanco no tiene caracteres /, es el nombre de un archivo en el directorio actual. Cualquier entrada relativa que describa un directorio cambia el directorio actual.
punto-punto
Como caso especial, una entrada relativa con el nombre de archivo .. cambia el directorio actual al directorio padre. Las opciones en las entradas punto-punto siempre se ignoran.
Completo
Si la primera palabra delimitada por espacios en blanco tiene un carácter / después del primer carácter, es la ruta del archivo relativa al directorio de inicio. Puede haber varias entradas completas que describan el mismo archivo.

Algunas herramientas que procesan archivos mtree pueden requerir que las líneas múltiples que describen el mismo archivo ocurran consecutivamente. No está permitido que el mismo archivo se mencione utilizando tanto una especificación de archivo relativa como una completa.

Comandos Especiales

Actualmente se definen dos comandos especiales:

/set
Este comando define valores predeterminados para una o más palabras clave. Le siguen en la misma línea una o más definiciones de palabras clave separadas por espacios en blanco. Estas definiciones se aplican a todos los archivos posteriores que no especifican un valor para esa palabra clave.
/unset
Este comando elimina cualquier valor predeterminado establecido por un comando /set anterior. Le siguen en la misma línea una o más palabras clave separadas por espacios en blanco.

Palabras Clave

Después del nombre del archivo, una entrada completa o relativa consiste en cero o más definiciones de palabras clave separadas por espacios en blanco. Cada definición de este tipo consiste en una clave de la siguiente lista seguida inmediatamente por un signo '=' y un valor. Los programas de software que lean archivos mtree deberían advertir sobre las palabras clave no reconocidas.

Las palabras clave admitidas actualmente son las siguientes:

cksum
La suma de verificación del archivo utilizando el algoritmo predeterminado especificado por la utilidad cksum(1).
device
El número del dispositivo para tipos de archivo bloque o carácter. El valor debe tener una de las siguientes formas:
formato,mayor,menor[,subunidad]
Un dispositivo con campos mayor, menor y opcional subunidad. Su significado está especificado por el formato del sistema operativo. Consulte a continuación los formatos válidos.
número
Número opaco (tal como se almacena en el sistema de archivos).

Los siguientes valores para formato son reconocidos: nativo, 386bsd, 4bsd, bsdos, freebsd, hpux, isc, linux, netbsd, osf1, sco, solaris, sunos, svr3, svr4, y ultrix.

Consulte mknod(8) para más detalles.

contents
La ruta completa de un archivo que contiene los contenidos de este archivo.
flags
Las banderas del archivo como un nombre simbólico. Consulte chflags(1) para obtener información sobre estos nombres. Si no se van a establecer banderas, la cadena “none” puede usarse para anular el valor predeterminado actual.
gid
El grupo del archivo como un valor numérico.
gname
El grupo del archivo como un nombre simbólico.
ignore
Ignorar cualquier jerarquía de archivos debajo de este archivo.
inode
El número de inodo.
link
El objetivo del enlace simbólico cuando type=link.
md5
El resumen del mensaje MD5 del archivo.
md5digest
Un sinónimo de md5.
mode
Los permisos del archivo actual como un valor numérico (octal) o simbólico.
nlink
El número de enlaces duros que se espera que tenga el archivo.
nochange
Asegurarse de que este archivo o directorio exista, pero de lo contrario ignorar todos los atributos.
optional
El archivo es opcional; no se queje del archivo si no está en la jerarquía de archivos.
resdevice
El número del dispositivo “residente” del archivo, por ejemplo, la ID del dispositivo que contiene el archivo. Su formato es el mismo que el de device.
ripemd160digest
El resumen del mensaje RIPEMD160 del archivo.
rmd160
Un sinónimo de ripemd160digest.
rmd160digest
Un sinónimo de ripemd160digest.
sha1
El resumen del mensaje FIPS 160-1 (“SHA-1”) del archivo.

MTREE.5

file attribute database format

NAME

mtree

file attribute database format

SYNOPSIS

mtree

DESCRIPTION

The mtree utility compares the properties of files specified in a file system to a database of expected file properties. The database is typically created by running mtree with the -n option, which causes it to print a specification of the current file system contents. This specification may then be edited and used as a database for later comparisons.

The database format is a set of lines, each describing a file or directory. Each line consists of a path name, followed by white space, followed by a comma-separated list of keywords and values, each keyword identifying a file property and the value specifying the expected value of that property.

The keywords supported are:

all
Used to specify a default set of keywords and values that apply to all files. This keyword must be the first keyword in the list.
acl
The Access Control List of the file. Not supported by all file systems.
arch
A regular expression matching the architecture of the file. Only supported by SunOS.
base32
The base32 encoding of the file's MD5 checksum. This is intended for use with NFS.
base64
The base64 encoding of the file's MD5 checksum. This is intended for use with NFS.
cksum
The System V hash message digest of the file. This is calculated using the algorithm specified by the cksum(1) utility.
comment
A comment string. This keyword is ignored.
device
The device numbers for special file types. This keyword is used to specify the major and minor device numbers for character and block special files.
dir
The directory. This keyword is used to indicate that the file is a directory. It is implied if the file type is dir.
gid
The file group ID as a numeric value.
gname
The file group name as a symbolic name.
ignore
This keyword causes the file to be ignored. This is useful for omitting files from the database that are temporary or generated.
inode
The inode number of the file. This keyword is ignored.
link
The target of the symbolic link. This keyword is used to specify the target of a symbolic link. It is implied if the file type is link.
md5
The MD5 message digest of the file. This is calculated using the algorithm described in RFC 1321.
md5digest
A synonym for md5.
mode
The file permissions. This keyword is used to specify the file mode in symbolic notation (e.g., u+w, g-w, a+r) or octal notation (e.g., 644).
nlink
The number of hard links to the file.
optional
This keyword marks the file as optional. If the file does not exist, mtree will not report it as an error.
rmd160
The RIPEMD-160 message digest of the file. This is calculated using the algorithm described in FIPS PUB 180-1.
rmd160digest
A synonym for rmd160.
sha1
The FIPS 180-1 (“SHA-1”) message digest of the file.
sha1digest
A synonym for sha1.
sha256
The FIPS 180-2 (“SHA-256”) message digest of the file.
sha256digest
A synonym for sha256.
sha384
The FIPS 180-2 (“SHA-384”) message digest of the file.
sha384digest
A synonym for sha384.
sha512
The FIPS 180-2 (“SHA-512”) message digest of the file.
sha512digest
A synonym for sha512.
size
The size, in bytes, of the file.
time
The last modification time of the file.
type
The type of the file; may be set to any one of the following:
block
block special device
char
character special device
dir
directory
fifo
fifo
file
regular file
link
symbolic link
socket
socket
uid
The file owner as a numeric value.
uname
The file owner as a symbolic name.

SEE ALSO

cksum(1), find(1), mtree(8)

HISTORY

The mtree utility appeared in 4.3BSD-Reno. The MD5 digest capability was added in FreeBSD 2.1, in response to the widespread use of programs which can spoof cksum(1). The SHA-1 and RIPEMD160 digests were added in FreeBSD 4.0, as new attacks have demonstrated weaknesses in MD5. The SHA-256 digest was added in FreeBSD 6.0. Support for file flags was added in FreeBSD 4.0, and mostly comes from NetBSD. The “full” entry format was added by NetBSD.
