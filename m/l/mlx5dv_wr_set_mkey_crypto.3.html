mlx5dv_wr_set_mkey_crypto(3) Manual de Funciones de Biblioteca mlx5dv_wr_set_mkey_crypto(3)

NOMBRE

mlx5dv_wr_set_mkey_crypto - Configurar una MKey para operación criptográfica.

SINOPSIS

#include <infiniband/mlx5dv.h>
static inline void
mlx5dv_wr_set_mkey_crypto(struct mlx5dv_qp_ex *mqp,
              const struct mlx5dv_crypto_attr *attr);

DESCRIPCIÓN

Configura una MKey con propiedades criptográficas. Con esto, el dispositivo cifrará/descifrará datos al transmitir datos de memoria a la red y al recibir datos de la red a la memoria.

Para configurar una MKey con propiedades criptográficas, la MKey debe ser creada con MLX5DV_MKEY_INIT_ATTR_FLAGS_CRYPTO. Una MKey creada con MLX5DV_MKEY_INIT_ATTR_FLAGS_CRYPTO debe tener propiedades criptográficas configuradas antes de poder ser utilizada, es decir, este establecedor debe ser llamado antes de que la MKey pueda ser usada o de lo contrario el tráfico fallará, generando un CQE con error. Una llamada a este establecedor en una MKey que ya tiene propiedades criptográficas configuradas las reemplazará.

La configuración de propiedades criptográficas a una MKey se realiza especificando el estándar criptográfico que debe usarse y sus atributos, y también proporcionando la Clave de Cifrado de Datos (DEK) a utilizar para el cifrado/descifrado en sí.

La MKey representa una memoria virtualmente contigua, configurando un diseño para ella. Las propiedades criptográficas de la MKey describen si los datos en esta memoria virtualmente contigua están cifrados o en texto plano, y si deben ser cifrados/descifrados antes de transmitirlos o después de recibirlos. Dependiendo de la operación real que ocurra (TX o RX), el dispositivo hará lo "correcto" basándose en las propiedades criptográficas configuradas en la MKey.

Las MKeys pueden configurarse con propiedades de cifrado y firma al mismo tiempo llamando tanto a mlx5dv_wr_set_mkey_crypto()(3) como a mlx5dv_wr_set_mkey_sig_block()(3). En este caso, ambas operaciones, criptográfica y de firma, se realizarán de acuerdo con las propiedades de cifrado y firma configuradas en la MKey, y el orden de las operaciones se determinará por la propiedad signature_crypto_order.

Ejemplo 1 (corresponde a la fila F en la tabla a continuación):

El dominio de firma de memoria no está configurado y los datos de memoria están cifrados.

El dominio de firma de red está configurado para texto plano y los datos de red están en texto plano.

encrypt_on_tx está establecido en falso, y dado que la firma no está configurada, el valor de signature_crypto_order no importa.

Se emite un SEND usando la MKey como clave local.

Resultado: el dispositivo recopilará los datos cifrados de la MKey (usando cualquier diseño configurado a la MKey para localizar la memoria real), los descifrará usando la DEK proporcionada y transmitirá los datos descifrados a la red.

Ejemplo 1.1:

Igual que el anterior, pero se emite un RECV con la misma MKey y ocurre una recepción (RX).

Resultado: el dispositivo recibirá los datos de la red, los cifrará usando la DEK proporcionada y los dispersará a la MKey (usando cualquier diseño configurado a la MKey para localizar la memoria real).

Ejemplo 2 (corresponde a la fila C en la tabla a continuación):

El dominio de firma de memoria está configurado para no tener firma y los datos de memoria están en texto plano.

El dominio de firma de red está configurado para T10DIF cada bloque de 512 Bytes y los datos de red (incluyendo el T10DIF) están cifrados.

encrypt_on_tx está establecido en verdadero y signature_crypto_order está establecido en MLX5DV_SIGNATURE_CRYPTO_ORDER_SIGNATURE_BEFORE_CRYPTO_ON_TX. data_unit_size está establecido en MLX5DV_BLOCK_SIZE_520.

La MKey se envía a un nodo remoto que emite una RDMA_READ a esta MKey.

Resultado: el dispositivo recopilará los datos de la MKey (usando cualquier diseño configurado a la MKey para localizar la memoria real), generará un campo T10DIF adicional cada 512B de datos, cifrará los datos y el campo T10DIF recién generado usando la DEK proporcionada, y lo transmitirá a la red.

Ejemplo 2.1:

Igual que el anterior, pero el nodo remoto emite una RDMA_WRITE a esta MKey.

Resultado: el dispositivo recibirá los datos de la red, los descifrará usando la DEK proporcionada, validará cada campo T10DIF contra los 512B de datos anteriores, eliminará el campo T10DIF y dispersará los datos solos a la MKey (usando cualquier diseño configurado a la MKey para localizar la memoria real).

ARGUMENTOS

mqp
La QP donde se creó una solicitud de trabajo de configuración de MKey por mlx5dv_wr_mkey_configure().
attr
Atributos criptográficos a establecer para la MKey.

Atributos Criptográficos

Los atributos criptográficos describen el formato (cifrado o texto plano) y el diseño de los datos de entrada y salida en los dominios de memoria y red, el estándar criptográfico que debe usarse y sus atributos.

struct mlx5dv_crypto_attr {
    enum mlx5dv_crypto_standard crypto_standard;
    bool encrypt_on_tx;
    enum mlx5dv_signature_crypto_order signature_crypto_order;
    enum mlx5dv_block_size data_unit_size;
    char initial_tweak[16];
    struct mlx5dv_dek *dek;
    char keytag[8];
    uint64_t comp_mask;
};
crypto_standard
El estándar de cifrado que debe usarse, actualmente solo puede ser el siguiente valor
MLX5DV_CRYPTO_STANDARD_AES_XTS
El estándar de cifrado AES-XTS definido en IEEE Std 1619-2007.
encrypt_on_tx
Si está establecido, los datos de memoria se cifrarán durante la TX y los datos de red se descifrarán durante la RX. Si no está establecido, los datos de memoria se descifrarán durante la TX y los datos de red se cifrarán durante la RX.
signature_crypto_order
Controla el orden entre las operaciones de cifrado y firma (Por favor, ver la tabla detallada a continuación). Relevante solo si la firma está configurada. Puede ser uno de los siguientes valores
MLX5DV_SIGNATURE_CRYPTO_ORDER_SIGNATURE_AFTER_CRYPTO_ON_TX
Durante la TX, primero se realiza la operación de cifrado (cifrar/descifrar según encrypt_on_tx) y luego la operación de firma sobre los datos de memoria. Durante la RX, primero se realiza la operación de firma y luego la operación de cifrado (cifrar/descifrar según encrypt_on_tx) sobre los datos de red.
MLX5DV_SIGNATURE_CRYPTO_ORDER_SIGNATURE_BEFORE_CRYPTO_ON_TX
Durante la TX, primero se realiza la operación de firma y luego la operación de cifrado (cifrar/descifrar según encrypt_on_tx) sobre los datos de memoria. Durante la RX, primero se realiza la operación de cifrado (cifrar/descifrar según encrypt_on_tx) y luego la operación de firma sobre los datos de red.

Tabla: Significado de signature_crypto_order y encrypt_on_tx.

La tabla describe los posibles diseños de datos en los dominios de memoria y red, y el orden en que se realizan las operaciones de cifrado y firma según signature_crypto_order, encrypt_on_tx y la configuración de firma.

La columna Memoria representa el diseño de datos en el dominio de memoria.

La columna Red representa el diseño de datos en el dominio de red.

NAME

mlx5dv_wr_set_mkey_crypto_block, mlx5dv_wr_set_mkey_sig_block - Configure crypto and signature operations for MKey

SYNOPSIS

#include <mlx5dv.h>
int mlx5dv_wr_set_mkey_crypto_block(
    struct mlx5dv_wr_mkey_config *mkey_cfg,
    enum mlx5dv_crypto_block_type block_type,
    enum mlx5dv_crypto_block_encrypt_decrypt encrypt_decrypt,
    enum mlx5dv_crypto_block_direction direction,
    uint64_t data_unit_size,
    uint64_t initial_tweak,
    struct mlx5dv_dek *dek,
    uint32_t key_tag,
    uint32_t comp_mask
);
int mlx5dv_wr_set_mkey_sig_block(
    struct mlx5dv_wr_mkey_config *mkey_cfg,
    enum mlx5dv_sig_block_type block_type,
    enum mlx5dv_sig_block_direction direction,
    uint32_t sig_block_flags
);

DESCRIPTION

These functions configure the cryptographic and signature operations that will be performed by the hardware for the Memory Key (MKey) associated with the given configuration structure.

The MKey configuration is done using the mlx5dv_wr_mkey_configure() function. These functions are helpers to set up the MKey configuration structure.

The MKey crypto and signature operations can be performed on data in different domains: memory domain (host memory) and wire domain (network interface). The operations can also be performed in different orders.

The order of operations for data processing is generally as follows:

1.
Crypto operation.
2.
Signature operation in memory domain.
3.
Signature operation in wire domain.

Op1, Op2 and Op3 columns represent these operations. On TX, Op1, Op2 and Op3 are performed on memory data to produce the data layout that is specified in Wire column. On RX, Op3, Op2 and Op1 are performed on wire data to produce the data layout specified in Memory column. “SIG.mem” and “SIG.wire” represent the signature operation that is performed in memory and wire domains respectively. None means no operation is performed. The exact signature operations are determined by the signature attributes configured by mlx5dv_wr_set_mkey_sig_block().

encrypt_on_tx and signature_crypto_order columns represent the values that encrypt_on_tx and signature_crypto_order should have in order to achieve such behavior.

Memory Op1 Op2 Op3 Wire encrypt_on_tx signature_crypto_order
A data Encrypt on TX SIG.mem = none SIG.wire = none enc(data) True Doesn’t matter
B data Encrypt On TX SIG.mem = none SIG.wire = SIG enc(data)+SIG True SIGNATURE_AFTER_CRYPTO_ON_TX
C data SIG.mem = none SIG.wire = SIG Encrypt on TX enc(data+SIG) True SIGNATURE_BEFORE_CRYPTO_ON_TX
D data+SIG SIG.mem = SIG SIG.wire = none Encrypt on TX enc(data) True SIGNATURE_BEFORE_CRYPTO_ON_TX
E data+SIG1 SIG.mem = SIG1 SIG.wire = SIG2 Encrypt on TX enc(data+SIG2) True SIGNATURE_BEFORE_CRYPTO_ON_TX
F enc(data) Decrypt on TX SIG.mem = none SIG.wire = none data False Doesn’t matter
G enc(data) Decrypt on TX SIG.mem = none SIG.wire = SIG data+SIG False SIGNATURE_AFTER_CRYPTO_ON_TX
H enc(data+SIG) Decrypt on TX SIG.mem = SIG SIG.wire = none data False SIGNATURE_AFTER_CRYPTO_ON_TX
I enc(data+SIG1) Decrypt on TX SIG.mem = SIG1 SIG.wire = SIG2 data+SIG2 False SIGNATURE_AFTER_CRYPTO_ON_TX
J enc(data)+SIG SIG.mem = SIG SIG.wire = none Decrypt on TX data False SIGNATURE_BEFORE_CRYPTO_ON_TX

Notes:

•
“Encrypt on TX” also means “Decrypt on RX”, and “Decrypt on TX” also means “Encrypt on RX”.
•
When signature properties are not configured in the MKey, only crypto operations will be performed. Thus, signature_crypto_order has no meaning in this case (rows A and F), and it can be set to either one of its values.
data_unit_size
For storage, this will normally be the storage block size. The tweak is incremented after each data_unit_size during the encryption. can be one of enum mlx5dv_block_size.
initial_tweak
A value to be used during encryption of each data unit. Must be supplied in little endian. This value is incremented by the device for every data unit in the message. For storage encryption, this will normally be the LBA of the first block in the message, so that the increments represent the LBAs of the rest of the blocks in the message.
dek
The DEK to be used for the crypto operations. This DEK must be pre-loaded to the device using mlx5dv_dek_create().
key_tag
A tag that verifies that the correct DEK is being used. key_tag is optional and is valid only if the DEK was created with has_keytag set to true. If so, it must match the key tag that was provided when the DEK was created. Supllied in plaintext.
comp_mask
Reserved for future extension, must be 0 now.

RETURN VALUE

This function does not return a value.

In case of error, user will be notified later when completing the DV WRs chain.

NOTES

MKey must be created with MLX5DV_MKEY_INIT_ATTR_FLAGS_CRYPTO flag.

The last operation posted on the supplied QP should be mlx5dv_wr_mkey_configure(3), or one of its related setters, and the operation must still be open (no doorbell issued).

In case of ibv_wr_complete() failure or calling to ibv_wr_abort(), the MKey may be left in an unknown state. The next configuration of it should not assume any previous state of the MKey, i.e. signature/crypto should be re-configured or reset, as required. For example, assuming mlx5dv_wr_set_mkey_sig_block() and then ibv_wr_abort() were called, then on the next configuration of the MKey, if signature is not needed, it should be reset using MLX5DV_MKEY_CONF_FLAG_RESET_SIG_ATTR.

When configuring a MKey with AES-XTS crypto offload, and using the former for traffic (send/receive), the amount of data to send/receive must meet one of the following conditions for successful encryption/decryption process (per AES-XTS spec):

Let’s refer to the amount of data to send/receive as `job_size' 1.job_size % data_unit_size == 0 2.(job_size % 16 == 0) && (job_size % data_unit_size <= data_unit_size - 16)

For example: When data_unit_size = 512B: 1. job_size = 512B is valid (1 holds). 2. job_size = 128B is valid (2 holds). 3. job_size = 47B is invalid (neither 1 nor 2 holds).

When data_unit_size = 520B: 1. job_size = 520B is valid (1 holds). 2. job_size = 496B is valid (2 holds). 3. job_size = 512B is invalid (neither 1 nor 2 holds).

mlx5dv_wr_set_mkey_crypto(3)

mlx5dv_wr_set_mkey_crypto es una función de la API de Mellanox ConnectX-4/5/6 que permite establecer la clave de memoria (Memory Key, MKey) asociada a un Work Request (WR) para operaciones de criptografía. Esto es crucial para garantizar que los datos enviados o recibidos sean procesados correctamente por el motor de criptografía del hardware.

SINAPSIS

#include <infiniband/mlx5dv.h>
void mlx5dv_wr_set_mkey_crypto(struct mlx5dv_wr *wr, uint32_t key);

DESCRIPCIÓN

La función mlx5dv_wr_set_mkey_crypto se utiliza para asociar una clave de memoria específica a un struct mlx5dv_wr. Esta clave se utiliza posteriormente por el hardware Mellanox para identificar y autenticar los buffers de memoria involucrados en operaciones de criptografía.

El parámetro wr es un puntero a la estructura mlx5dv_wr que se está configurando. El parámetro key es el valor de la clave de memoria de 32 bits que se establecerá.

Es importante que la clave de memoria utilizada sea la correcta y que haya sido registrada previamente en el hardware. Esto generalmente se hace utilizando las funciones de gestión de memoria de la biblioteca de Mellanox.

PARÁMETROS

  • wr: Puntero a la estructura struct mlx5dv_wr a la que se aplicará la clave de memoria.
  • key: El valor de la clave de memoria de 32 bits.

VALOR DE RETORNO

Esta función no devuelve ningún valor.

EJEMPLO

A continuación, se muestra un ejemplo simplificado de cómo usar mlx5dv_wr_set_mkey_crypto:

struct mlx5dv_wr wr;
uint32_t crypto_mkey = get_crypto_memory_key(); // Función hipotética para obtener la MKey

// ... inicialización de wr ...

mlx5dv_wr_set_mkey_crypto(&wr, crypto_mkey);

// ... configuración adicional de wr y envío ...
