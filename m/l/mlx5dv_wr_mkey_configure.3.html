mlx5dv_wr_mkey_configure(3) Manual de funciones de la biblioteca mlx5dv_wr_mkey_configure(3)

NOMBRE

mlx5dv_wr_mkey_configure - Crear una solicitud de trabajo para configurar una MKEY

mlx5dv_wr_set_mkey_access_flags - Establecer las banderas de acceso de memoria para una MKEY

mlx5dv_wr_set_mkey_layout_list - Establecer un diseño de memoria para una MKEY basado en una lista SGE

mlx5dv_wr_set_mkey_layout_interleaved - Establecer un diseño de memoria intercalado para una MKEY

SINOPSIS

#include <infiniband/mlx5dv.h>
static inline void mlx5dv_wr_mkey_configure(struct mlx5dv_qp_ex *mqp,
                                            struct mlx5dv_mkey *mkey,
                                            uint8_t num_setters,
                                            struct mlx5dv_mkey_conf_attr *attr);
static inline void mlx5dv_wr_set_mkey_access_flags(struct mlx5dv_qp_ex *mqp,
                                                   uint32_t access_flags);
static inline void mlx5dv_wr_set_mkey_layout_list(struct mlx5dv_qp_ex *mqp,
                                                  uint16_t num_sges,
                                                  const struct ibv_sge *sge);
static inline void mlx5dv_wr_set_mkey_layout_interleaved(struct mlx5dv_qp_ex *mqp,
                                                         uint32_t repeat_count,
                                                         uint16_t num_interleaved,
                                                         const struct mlx5dv_mr_interleaved *data);

DESCRIPCIÓN

La API de configuración de MKEY de MLX5DV y los configuradores relacionados (mlx5dv_wr_set_mkey*) son una extensión de la API de solicitud de trabajo IBV (ibv_wr*) con características específicas para MKEY de MLX5DV.

Las MKEYs permiten la creación de espacios de direcciones virtualmente contiguos a partir de fragmentos de memoria no contiguos ya registrados con el hardware. Además, proporciona acceso a algunas características avanzadas de descarga de hardware, por ejemplo, descarga de firmas.

Estas APIs están destinadas a ser utilizadas para acceder a funcionalidades adicionales más allá de lo proporcionado por mlx5dv_wr_mr_list() y mlx5dv_wr_mr_interleaved(). Las características de MKEY se pueden habilitar opcionalmente utilizando los configuradores de configuración de mkey. Permite usar diferentes características en la misma MKEY.

USO

Para usar estas APIs, se debe crear una QP usando mlx5dv_create_qp(3) que permite establecer MLX5DV_QP_EX_WITH_MKEY_CONFIGURE en send_ops_flags.

La solicitud de trabajo de configuración de MKEY se crea llamando a mlx5dv_wr_mkey_configure(), una función constructora de WR, seguida de las funciones configuradoras requeridas. num_setters es el número de configuradores requeridos para el WR. Todos los configuradores son opcionales. num_setters puede ser cero para aplicar solo attr. Cada configurador solo se puede llamar una vez por constructor de WR.

El WR configura mkey y aplica los attr de la función constructora y los argumentos de las funciones configuradoras para él. Si mkey ya está configurado, el WR anula algunas propiedades de mkey dependiendo de los argumentos de la constructora y las funciones configuradoras (ver detalles en la descripción de los configuradores). Para borrar la configuración de mkey, use ibv_post_send() con el opcode IBV_WR_LOCAL_INV o ibv_wr_local_inv().

La implementación actual requiere que la opción IBV_SEND_INLINE esté establecida en el campo wr_flags de la estructura ibv_qp_ex antes de llamar a la función constructora. La carga útil no en línea no es actualmente compatible con esta API. Tenga en cuenta que la inserción aquí es para los datos de configuración de MKEY, no para los datos del usuario a los que hacen referencia los diseños de datos.

Una vez que la MKEY está configurada, se puede usar en solicitudes de trabajo posteriores (SEND, RDMA_READ, RDMA_WRITE, etc.). Si estas solicitudes de trabajo se publican en la misma QP, no es necesario esperar la finalización de la configuración de la MKEY. Se pueden publicar inmediatamente después del último configurador (o constructor si no hay configuradores). Por lo general, ni siquiera es necesario solicitar una finalización para la solicitud de trabajo de configuración de MKEY.

Si se solicita una finalización para la solicitud de trabajo de configuración de MKEY, se entregará con el opcode IBV_WC_DRIVER1.

Función constructora

mlx5dv_wr_mkey_configure()
Publica una solicitud de trabajo para configurar una MKEY existente. Con esta llamada sola, es posible configurar la MKEY y mantener o restablecer los atributos de firma. Esta llamada puede ir seguida de cero o más configuradores opcionales.
mqp
La QP en la que se publicará la solicitud de trabajo.
mkey
La MKEY a configurar.
num_setters
El número de configuradores que deben llamarse después de esta función.
attr
Los atributos de configuración de MKEY

Atributos de configuración de MKEY

Los atributos de configuración de MKEY se proporcionan en la estructura mlx5dv_mkey_conf_attr.

struct mlx5dv_mkey_conf_attr {
        uint32_t conf_flags;
        uint64_t comp_mask;
};
conf_flags
OR a nivel de bits de las siguientes banderas:
MLX5DV_MKEY_CONF_FLAG_RESET_SIG_ATTR
Restablece los atributos de firma de la MKEY. Si no se establece, se conservarán los atributos de firma configurados previamente.
comp_mask
Reservado para futuras extensiones, debe ser 0 por ahora.

Configuradores genéricos

mlx5dv_wr_set_mkey_access_flags()
Establece los atributos de protección de memoria para la MKEY. Si la MKEY está configurada, el configurador anula el valor anterior. Por ejemplo, se publican dos WRs de configuración de MKEY. El primero establece IBV_ACCESS_REMOTE_READ. El segundo establece IBV_ACCESS_REMOTE_WRITE. En este caso, el segundo WR anula los atributos de protección de memoria, y solo se permite IBV_ACCESS_REMOTE_WRITE para la MKEY cuando el WR se completa.
mqp
La QP en la que se creó una solicitud de trabajo de configuración de MKEY mediante mlx5dv_wr_mkey_configure().
access_flags
Los atributos de protección de memoria deseados; es 0 o el OR a nivel de bits de una o más banderas de enum ibv_access_flags.

Configuradores de diseño de datos

Los configuradores de diseño de datos definen cómo se dispersarán/recolectarán los datos a los que hace referencia la MKEY en la memoria. Para usar una MKEY con operaciones RDMA, debe configurarse con un diseño.

No más de un configurador de diseño de datos puede seguir a la función constructora. El diseño se puede actualizar en las siguientes llamadas a la función constructora.

Cuando se utiliza una MKEY en operaciones RDMA, debe usarse en modo basado en cero, es decir, el campo addr en la estructura ibv_sge es un desplazamiento en los datos totales.

mlx5dv_wr_set_mkey_layout_list()
Establece un diseño de memoria para una MKEY basado en una lista SGE. Si la MKEY está configurada y el diseño de datos fue definido por algún configurador de diseño de datos (no necesariamente este), el configurador anula el valor anterior.

El tamaño por defecto del WQE solo puede contener 4 entradas SGE. Para permitir más, la QP debe crearse con un tamaño de WQE mayor que pueda contenerlo. Esto debe hacerse utilizando el atributo max_inline_data de struct ibv_qp_cap al crear la QP.

mqp
El QP donde se creó una solicitud de trabajo de configuración de MKEY mediante mlx5dv_wr_mkey_configure().
num_sges
Número de SGEs en la lista.
sge
Puntero a la lista de estructuras ibv_sge.
mlx5dv_wr_set_mkey_layout_interleaved()
Establece un diseño de memoria intercalado para un MKEY. Si el MKEY está configurado y el diseño de datos fue definido por algún setter de diseño de datos (no necesariamente este), el setter anula el valor anterior.

El tamaño predeterminado de WQE solo puede contener 3 entradas intercaladas. Para permitir más, el QP debe crearse con un tamaño de WQE mayor que pueda contenerlo. Esto debe hacerse utilizando el atributo max_inline_data de struct ibv_qp_cap al crear el QP.

Dado que se consumirá una entrada para el encabezado intercalado, el MKEY debe crearse con una entrada más que la num_interleaved requerida.

mqp
El QP donde se creó una solicitud de trabajo de configuración de MKEY mediante mlx5dv_wr_mkey_configure().
repeat_count
La representación del diseño de data se repite repeat_count veces.
num_interleaved
Número de entradas en la representación de data.
data
Puntero a la lista de descripciones de diseño de datos intercalados.

El diseño de datos intercalados se describe mediante la estructura mlx5dv_mr_interleaved.

struct mlx5dv_mr_interleaved {
    uint64_t addr;
    uint32_t bytes_count;
    uint32_t bytes_skip;
    uint32_t lkey;
};
addr
Dirección de inicio del búfer de memoria local.
bytes_count
Número de bytes de datos a colocar en el búfer.
bytes_skip
Número de bytes a omitir en el búfer antes del siguiente bloque de datos.
lkey
Clave de la Región de Memoria local

Configuradores de firma

Los atributos de firma del MKEY permiten añadir/modificar/eliminar/validar campos de integridad al transmitir datos de memoria a red y al recibir datos de red a memoria.

Utilice los configuradores de firma para establecer/actualizar los atributos de firma del MKEY. Para restablecer los atributos de firma sin invalidar el MKEY, utilice el flag MLX5DV_MKEY_CONF_FLAG_RESET_SIG_ATTR.

mlx5dv_wr_set_mkey_sig_block()
Establece los atributos de firma de bloque del MKEY. Si el MKEY ya está configurado con los atributos de firma, el configurador anula el valor anterior. Consulte la página de manual dedicada para mlx5dv_wr_set_mkey_sig_block(3).

Configurador criptográfico

Los atributos criptográficos del MKey permiten cifrar y descifrar los datos transmitidos de memoria a red y al recibir datos de red a memoria.

Utilice el configurador criptográfico para establecer/actualizar los atributos criptográficos del MKey. Cuando el MKey se crea con MLX5DV_MKEY_INIT_ATTR_FLAGS_CRYPTO, debe configurarse con atributos criptográficos antes de que el MKey pueda ser utilizado.

mlx5dv_wr_set_mkey_crypto()
Establece los atributos criptográficos del MKey. Si el MKey ya está configurado con atributos criptográficos, el configurador anula el valor anterior. Consulte la página de manual dedicada para mlx5dv_wr_set_mkey_crypto(3).

EJEMPLOS

Creación de QP y MKEY

El siguiente código crea un QP con soporte para la operación de configuración de MKEY y un mkey indirecto.

/* Crear QP con soporte de configuración de MKEY */
struct ibv_qp_init_attr_ex attr_ex = {};
attr_ex.comp_mask |= IBV_QP_INIT_ATTR_SEND_OPS_FLAGS;
attr_ex.send_ops_flags |= IBV_QP_EX_WITH_RDMA_WRITE;
struct mlx5dv_qp_init_attr attr_dv = {};
attr_dv.comp_mask |= MLX5DV_QP_INIT_ATTR_MASK_SEND_OPS_FLAGS;
attr_dv.send_ops_flags = MLX5DV_QP_EX_WITH_MKEY_CONFIGURE;
ibv_qp *qp = mlx5dv_create_qp(ctx, attr_ex, attr_dv);
ibv_qp_ex *qpx = ibv_qp_to_qp_ex(qp);
mlx5dv_qp_ex *mqpx = mlx5dv_qp_ex_from_ibv_qp_ex(qpx);
mkey_attr.create_flags = MLX5DV_MKEY_INIT_ATTR_FLAGS_INDIRECT;
struct mlx5dv_mkey *mkey = mlx5dv_create_mkey(&mkey_attr);

Configuración de diseño de datos en lista

El siguiente código configura un MKEY que permite acceso remoto para lectura y escritura y se basa en un diseño de lista SGE con dos entradas. Cuando este MKEY se utiliza en una operación de escritura RDMA, los datos se distribuirán entre dos regiones de memoria. Los primeros 64 bytes irán a la memoria referenciada por mr1. Los siguientes 4096 bytes irán a la memoria referenciada por mr2.

ibv_wr_start(qpx);
qpx->wr_id = my_wr_id_1;
qpx->wr_flags = IBV_SEND_INLINE;
struct mlx5dv_mkey_conf_attr mkey_attr = {};
mlx5dv_wr_mkey_configure(mqpx, mkey, 2, &mkey_attr);
mlx5dv_wr_set_mkey_access_flags(mqpx, IBV_ACCESS_REMOTE_READ | IBV_ACCESS_REMOTE_WRITE);
struct ibv_sge sgl[2];
sgl[0].addr = mr1->addr;
sgl[0].length = 64;
sgl[0].lkey = mr1->lkey;
sgl[1].addr = mr2->addr;
sgl[1].length = 4096;
sgl[1].lkey = mr2->lkey;
mlx5dv_wr_set_mkey_layout_list(mqpx, 2, sgl);
ret = ibv_wr_complete(qpx);

Configuración de diseño de datos intercalado

El siguiente código configura un MKEY que permite acceso remoto para lectura y escritura y se basa en un diseño de datos intercalado con dos entradas y un contador de repetición de dos. Cuando este MKEY se utiliza en una operación de escritura RDMA, los datos se distribuirán entre dos regiones de memoria. Los primeros 512 bytes irán a la memoria referenciada por mr1 en el desplazamiento 0. Los siguientes 8 bytes irán a la memoria referenciada por mr2 en el desplazamiento 0. Los siguientes 512 bytes irán a la memoria referenciada por mr1 en el desplazamiento 516. Los siguientes 8 bytes irán a la memoria referenciada por mr2 en el desplazamiento 8.

ibv_wr_start(qpx);
qpx->wr_id = my_wr_id_1;
qpx->wr_flags = IBV_SEND_INLINE;
struct mlx5dv_mkey_conf_attr mkey_attr = {};
mlx5dv_wr_mkey_configure(mqpx, mkey, 2, &mkey_attr);
mlx5dv_wr_set_mkey_access_flags(mqpx, IBV_ACCESS_REMOTE_READ | IBV_ACCESS_REMOTE_WRITE);
struct mlx5dv_mr_interleaved data[2];
data[0].addr = mr1->addr;
data[0].bytes_count = 512;
data[0].bytes_skip = 4;
data[0].lkey = mr1->lkey;
data[1].addr = mr2->addr;
data[1].bytes_count = 8;
data[1].bytes_skip = 0;
data[1].lkey = mr2->lkey;
mlx5dv_wr_set_mkey_layout_interleaved(mqpx, 2, 2, &data);
ret = ibv_wr_complete(qpx);

NOTAS

Se debe abrir un contexto DEVX utilizando mlx5dv_open_device(3).

configure.3.en

configure - a utility for configuring system settings.

Introduction

The configure utility is a command-line tool that allows users to manage and modify various system settings. It provides a centralized interface for tasks such as network configuration, user management, service management, and more.

Installation

The configure utility is typically installed as part of the system's base installation. If it is not present, it can be installed using the system's package manager:

# pacman -S configure

Usage

The general syntax for the configure command is:

configure [options] [arguments]

Basic Usage

To view the current system configuration, simply run:

configure

To modify a specific setting, you can use the appropriate options or arguments. For example, to set the system hostname:

configure --hostname myhost.local

Options

The following options are available:

--help
Display a help message and exit.
--version
Display version information and exit.
--config-file <path>
Specify an alternative configuration file to use.
--output <path>
Specify a file to write the configuration output to.
--force
Force the operation, overwriting existing settings if necessary.
--verbose
Enable verbose output.
--quiet
Suppress non-essential output.

Examples

Set up a static IP address:

configure --network --interface eth0 --ip 192.168.1.100 --netmask 255.255.255.0 --gateway 192.168.1.1

Add a new user:

configure --user add --username newuser --password 'secretpassword' --group users,wheel

Enable the SSH service:

configure --service ssh enable

Configuration File

The primary configuration file for configure is typically located at /etc/configure.conf. This file allows for more complex and persistent configuration settings.

General Settings

The general settings section includes global options that affect the overall system behavior.

[general]
    hostname = myhost
    timezone = UTC
    locale = en_US.UTF-8

Section-Specific Settings

You can configure specific services or subsystems by creating dedicated sections.

[network.eth0]
    ip_address = 192.168.1.100
    netmask = 255.255.255.0
    gateway = 192.168.1.1

    [service.ssh]
    enabled = true
    port = 22

Hooks

configure supports a hook system that allows you to execute custom scripts before or after certain configuration changes. These hooks are defined in the configuration file.

[hooks]
    pre_network_config = /usr/local/bin/my_pre_network_script.sh
    post_user_add = /usr/local/bin/my_post_user_script.sh

Troubleshooting

If you encounter issues while using configure, check the following:

  • Ensure you have the necessary permissions to modify system settings.
  • Verify that the configuration file syntax is correct.
  • Consult the system logs for error messages (e.g., /var/log/syslog or journalctl).
  • Use the --verbose option for more detailed output.

See Also

hostname(1), useradd(8), systemctl(1)
