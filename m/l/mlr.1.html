NOMBRE

Miller -- similar a awk, sed, cut, join y sort para datos indexados por nombre como CSV y JSON tabular.

SINOPSIS

Uso: mlr [flags] {verbo} [opciones dependientes del verbo ...] {cero o más nombres de archivo}

Si no se proporcionan nombres de archivo, se lee la entrada estándar, p. ej.
mlr --csv sort -f shape ejemplo.csv

La salida de un verbo puede encadenarse como entrada a otro usando "then", p. ej.
mlr --csv stats1 -a min,mean,max -f quantity then sort -f color ejemplo.csv

Por favor, consulta 'mlr help topics' para más información. Consulta también https://miller.readthedocs.io

DESCRIPCIÓN

Miller opera sobre datos de pares clave-valor mientras que las herramientas Unix familiares operan sobre campos indexados por enteros: si la estructura de datos natural para estos últimos es el array, entonces la estructura de datos natural de Miller es el mapa hash ordenado por inserción. Esto abarca una variedad de formatos de datos, incluyendo pero no limitado a los familiares CSV, TSV y JSON. (Miller puede manejar datos indexados posicionalmente como un caso especial.) Esta página de manual documenta mlr 6.15.0.

EJEMPLOS

mlr --icsv --opprint cat ejemplo.csv
mlr --icsv --opprint sort -f shape ejemplo.csv
mlr --icsv --opprint sort -f shape -nr index ejemplo.csv
mlr --icsv --opprint cut -f flag,shape ejemplo.csv
mlr --csv filter '$color == "red"' ejemplo.csv
mlr --icsv --ojson put '$ratio = $quantity / $rate' ejemplo.csv
mlr --icsv --opprint --from ejemplo.csv sort -nr index then cut -f shape,quantity

FORMATOS DE ARCHIVO

CSV/CSV-lite: valores separados por comas con línea de encabezado separada
TSV: igual pero con tabulaciones en lugar de comas
+---------------------+
| manzana,murciélago,engranaje       |
| 1,2,3               | Registro 1: "manzana":"1", "murciélago":"2", "engranaje":"3"
| 4,5,6               | Registro 2: "manzana":"4", "murciélago":"5", "engranaje":"6"
+---------------------+
JSON (array de objetos):
+---------------------+
| [                   |
| {                   |
|  "manzana": 1,        | Registro 1: "manzana":"1", "murciélago":"2", "engranaje":"3"
|  "murciélago": 2,          |
|  "engranaje": 3           |
| },                  |
| {                   |
|   "plato": {         | Registro 2: "plato.huevo":"7",
|     "huevo": 7,       | "plato.pedernal":"8", "ajo":""
|     "pedernal": 8      |
|   },                |
|   "ajo": ""      |
| }                   |
| ]                   |
+---------------------+
Líneas JSON (secuencia de objetos de una línea):
+------------------------------------------------+
| {"manzana": 1, "murciélago": 2, "engranaje": 3}               |
| {"plato": {"huevo": 7, "pedernal": 8}, "ajo": ""} |
+------------------------------------------------+
  Registro 1: "manzana":"1", "murciélago":"2", "engranaje":"3"
  Registro 2: "plato:huevo":"7", "plato:pedernal":"8", "ajo":""
PPRINT: tabular con formato de impresión agradable
+---------------------+
| manzana murciélago engranaje       |
| 1     2   3         | Registro 1: "manzana:"1", "murciélago":"2", "engranaje":"3"
| 4     5   6         | Registro 2: "manzana":"4", "murciélago":"5", "engranaje":"6"
+---------------------+
Tabular Markdown:
+-----------------------+
| | manzana | murciélago | engranaje | |
| | ---   | --- | --- | |
| | 1     | 2   | 3   | | Registro 1: "manzana:"1", "murciélago":"2", "engranaje":"3"
| | 4     | 5   | 6   | | Registro 2: "manzana":"4", "murciélago":"5", "engranaje":"6"
+-----------------------+
XTAB: tabular transpuesta con formato de impresión agradable
+---------------------+
| manzana 1             | Registro 1: "manzana":"1", "murciélago":"2", "engranaje":"3"
| murciélago   2             |
| engranaje   3             |
|                     |
| plato 7              | Registro 2: "plato":"7", "huevo":"8"
| huevo  8              |
+---------------------+
Pares clave-valor delimitados (DKVP) (formato predeterminado de Miller):
+---------------------+
| manzana=1,murciélago=2,engranaje=3 | Registro 1: "manzana":"1", "murciélago":"2", "engranaje":"3"
| plato=7,huevo=8,pedernal  | Registro 2: "plato":"7", "huevo":"8", "3":"pedernal"
+---------------------+
NIDX: indexado numéricamente implícitamente (estilo toolkit Unix)
+---------------------+
| el rápido marrón     | Registro 1: "1":"el", "2":"rápido", "3":"marrón"
| zorro saltó          | Registro 2: "1":"zorro", "2":"saltó"
+---------------------+

COMENTARIOS-EN-DATOS FLAGS

Miller te permite poner comentarios en tus datos, como
    # Este es un comentario para un archivo CSV
    a,b,c
    1,2,3
    4,5,6
Notas:
* Los comentarios solo se respetan al principio de una línea.
* En ausencia de alguna de las cuatro opciones siguientes, los comentarios son datos como
  cualquier otro texto. (La función de comentarios en datos es opcional.)
* Cuando se usa `--pass-comments`, las líneas de comentarios se escriben a la salida estándar
  inmediatamente al ser leídas; no forman parte del flujo de registros. Los resultados
  pueden ser contraintuitivos. Una sugerencia es colocar los comentarios al principio
  de los archivos de datos.
--pass-comments          Imprime inmediatamente las líneas comentadas (precedidas por `#`)
                         dentro de la entrada.
--pass-comments-with {string}
                         Imprime inmediatamente las líneas comentadas dentro de la entrada, con
                         el prefijo especificado.
--skip-comments          Ignora las líneas comentadas (precedidas por `#`) dentro de
                         la entrada.
--skip-comments-with {string}
                         Ignora las líneas comentadas dentro de la entrada, con el prefijo
                         especificado.

DATOS-COMPRIMIDOS FLAGS

Miller ofrece algunas formas diferentes de manejar la lectura de archivos de datos
	que han sido comprimidos.
* Descompresión realizada dentro del propio proceso de Miller: `--bz2in` `--gzin` `--zin``--zstdin`
* Descompresión realizada fuera del proceso de Miller: `--prepipe` `--prepipex`
Usando `--prepipe` y `--prepipex` puedes especificar una acción que se tomará en cada archivo de entrada.
El comando prepipe debe poder leer desde la entrada estándar; se invocará con `{comando} < {nombre_archivo}`.
El comando prepipex debe tomar un nombre de archivo como argumento; se invocará con
`{comando} {nombre_archivo}`.
Ejemplos:
    mlr --prepipe gunzip
    mlr --prepipe zcat -cf
    mlr --prepipe xz -cd
    mlr --prepipe cat
Ten en cuenta que esta función es bastante general y no se limita a utilidades de descompresión.
Puedes usarla para aplicar filtros por archivo de tu elección. Para compresión de salida
(u otras utilidades), simplemente canaliza la salida:
`mlr ... | {tu comando de compresión} > nombre_archivo_de_salida_va_aqui`
Por último, ten en cuenta que si se especifica `--prepipe` o `--prepipex`, reemplaza cualquier
decisión que se pudiera haber tomado basándose en la extensión del archivo. Del mismo modo,
`--gzin`/`--bz2in`/`--zin``--zin` se ignoran si también se especifica `--prepipe`.
--bz2in                  Descomprime bzip2 dentro del proceso de Miller. Se hace
                         por defecto si el archivo termina en `.bz2`.
--gzin                   Descomprime gzip dentro del proceso de Miller. Se hace
                         por defecto si el archivo termina en `.gz`.
--prepipe {comando_descompresión}
                         Puedes, por supuesto, ya hacerlo sin esto para
                         archivos de entrada individuales, p. ej. `gunzip <
                         myfile.csv.gz | mlr ...`. Permitido en la línea de
                         comandos, pero no en `.mlrrc` para evitar la ejecución
                         inesperada de código.
--prepipe-bz2            Igual que `--prepipe bz2`, excepto que esto está permitido en
                         `.mlrrc`.
--prepipe-gunzip         Igual que `--prepipe gunzip`, excepto que esto está permitido en
                         `.mlrrc`.
--prepipe-zcat           Igual que `--prepipe zcat`, excepto que esto está permitido en
                         `.mlrrc`.
--prepipe-zstdcat        Igual que `--prepipe zstdcat`, excepto que esto está permitido
                         en `.mlrrc`.
--prepipex {comando_descompresión}
                         Como `--prepipe` con una excepción: no inserta
                         `<` entre el comando y el nombre del archivo en tiempo de ejecución. Útil
                         para algunos comandos como `unzip -qc` que no leen
                         la entrada estándar. Permitido en la línea de comandos, pero no
                         en `.mlrrc` para evitar la ejecución inesperada de código.
--zin                    Descomprime zlib dentro del proceso de Miller. Se hace
                         por defecto si el archivo termina en `.z`.
--zstdin                 Descomprime zstd dentro del proceso de Miller. Se hace
                         por defecto si el archivo termina en `.zstd`.

SOLO-CSV/TSV FLAGS

Estos son flags aplicables al formato CSV.
--allow-ragged-csv-input o --ragged o --allow-ragged-tsv-input
                         Si una línea de datos tiene menos campos que la línea de encabezado,
                         rellena las claves restantes con una cadena vacía. Si una línea de datos
                         tiene más campos que la línea de encabezado, usa etiquetas de campo enteras
                         como en el caso de encabezado implícito.
--csv-trim-leading-space Recorta los espacios iniciales en los datos CSV. Úsalo para datos
                         como '"foo", "bar' que no cumplen con RFC-4180,
                         pero son comunes.
--headerless-csv-output o --ho o --headerless-tsv-output
                         Imprime solo líneas de datos CSV/TSV; no imprime líneas de encabezado
                         CSV/TSV.
--implicit-csv-header o --headerless-csv-input o --hi o --implicit-tsv-header
                         Usa 1,2,3,... como etiquetas de campo, en lugar de la línea
                         1 de los archivos de entrada. Consejo: combínalo con `label` para
                         recrear encabezados perdidos.
--lazy-quotes            Acepta comillas que aparecen en campos sin comillas, y
                         comillas no duplicadas que aparecen en campos entre comillas.
--no-auto-unsparsify     Para salida CSV/TSV: si las claves de registro cambian de
                         una fila a otra, emite una línea en blanco y una nueva
                         línea de encabezado. Esto no cumple con RFC 4180 pero
                         es útil para datos heterogéneos.
--no-implicit-csv-header o --no-implicit-tsv-header
                         Lo opuesto a `--implicit-csv-header`. Este es
                         el comportamiento por defecto de todos modos - el uso principal es para los flags de
                         `mlr join` si tienes archivos principales que
                         no tienen encabezado pero quieres unirte a un archivo que
                         sí tiene un encabezado CSV/TSV. Entonces podrías usar `mlr
                         --csv --implicit-csv-header join
                         --no-implicit-csv-header -l
                         tu-archivo-de-union-con-encabezado.csv ...
                         tu-archivo-sin-encabezado.csv`.
--quote-all              Fuerza el doble entrecomillado de los campos CSV.
-N                       Ahorrador de pulsaciones para `--implicit-csv-header
                         --headerless-csv-output`.

SOLO-DKVP FLAGS

Estos son flags aplicables al formato DKVP.

FLAGS DE COLORIZACIÓN DE SALIDA

Miller usa colores para resaltar las salidas. Puedes especificar
preferencias de color.
Nota: La colorización de la salida no funciona en Windows.
Elementos que tienen colores:
* Claves en líneas de cabecera CSV, claves JSON, etc.
* Valores en líneas de datos CSV, valores escalares JSON, etc. en la salida
  de pruebas de regresión.
* Algunas cadenas de ayuda en línea.
Reglas para la colorización:
* Por defecto, colorea la salida solo si se escribe en stdout y stdout es una
  TTY.
    * Ejemplo: color: `mlr --csv cat foo.csv`
    * Ejemplo: sin color: `mlr --csv cat foo.csv > bar.csv`
    * Ejemplo: sin color: `mlr --csv cat foo.csv | less`
* Los colores predeterminados se eligieron ya que se ven bien con fondos de
  terminal blancos o negros, y son diferenciables con las variedades comunes
  de visión del color humano.
Mecanismos de colorización:
* Miller solo usa secuencias de escape ANSI. Esto no funciona en Windows
  excepto dentro de Cygwin.
* Requiere que la variable de entorno `TERM` esté establecida a una cadena no
  vacía.
* No intenta verificar si la terminal es capaz de ANSI de 256 colores vs.
  ANSI de 16 colores. Ten en cuenta que si los colores están en el rango
  0..15, se usan escapes ANSI de 16 colores, por lo que esto está bajo el

* Supresión/des-supresión:
    * La variable de entorno `export MLR_NO_COLOR=true` o `export NO_COLOR=true`

      colorear incluso si no es stdout+TTY.
      Por ejemplo, podrías querer usar esto al canalizar la salida de mlr
      a `less -r`.

FLAGS DE SEPARADORES

Consulta la página de documentación de Separadores para más sobre
separadores de registros, separadores de campos y separadores de pares.
Consulta también la página de documentación de Formatos de archivo, o
`mlr help file-formats`, para más sobre los formatos de archivo que Miller
soporta.
En resumen:
* Para registros DKVP como `x=1,y=2,z=3`, los campos se separan por una coma,
  los pares clave-valor se separan por una coma, y cada registro se separa
  del siguiente por un salto de línea.
* Cada formato de archivo tiene sus propios separadores predeterminados.
* La mayoría de los formatos, como CSV, no soportan separadores de pares:
  las claves están en la línea de cabecera CSV y los valores en cada línea
  de datos CSV; las claves y los valores no se colocan uno al lado del otro.
* Algunos separadores no son programables: por ejemplo, JSON usa dos puntos
  como separador de pares, pero esto no es modificable en la especificación JSON.
* Puedes establecer separadores de forma diferente entre la entrada y la
  salida de Miller — de ahí `--ifs` y `--ofs`, etc.
Notas sobre finales de línea:
* Los finales de línea predeterminados (`--irs` y `--ors`) son salto de línea
  lo que se interpreta para aceptar archivos de retorno de carro/salto de
  línea (por ejemplo, en Windows) para entrada, y para producir finales de
  línea apropiados para la plataforma en la salida.
Notas sobre todos los demás separadores:
* IPS/OPS solo se usan para formatos DKVP y XTAB, ya que solo en estos
  formatos aparecen pares clave-valor yuxtapuestos.
* IRS/ORS se ignoran para el formato XTAB. Nominalmente IFS y OFS son saltos
  de línea; los registros XTAB se separan por dos o más IFS/OFS
  consecutivos — es decir, una línea en blanco. Todo lo anterior sobre
  `--irs/--ors/--rs auto` se convierte en `--ifs/--ofs/--fs` auto para el
  formato XTAB. (Los IFS/OFS predeterminados de XTAB son "auto".)
* OFS debe ser de un solo carácter para el formato PPRINT. Esto se debe a que
  se usa con repetición para la alineación; los separadores de múltiples
  caracteres harían imposible la alineación.
* OPS puede ser de múltiples caracteres para el formato XTAB, en cuyo caso
  se deshabilita la alineación.
* FS/PS se ignoran para el formato markdown; se usa RS.
* Todas las opciones FS y PS se ignoran para el formato JSON, ya que no son
  relevantes para el formato JSON.

filter

Uso: mlr filter [opciones] {expresión DSL}
Te permite usar un lenguaje de dominio específico para filtrar programáticamente qué
registros de transmisión se emitirán.
Ver también: https://miller.readthedocs.io/en/latest/reference-verbs
Opciones:
-f {nombre de archivo} Archivo que contiene una expresión DSL (ver ejemplos a continuación). Si el nombre de archivo
   es un directorio, se cargan todos los archivos *.mlr en ese directorio.
-e {expresión} Puedes usar esto después de -f para agregar una expresión. Caso de uso de ejemplo:
   definir funciones/subrutinas en un archivo que especificas con -f, luego llamarlas
   con una expresión que especificas con -e.
(Si mezclas -e y -f, las expresiones se evalúan en el orden en que se encuentran.
Dado que las piezas de la expresión simplemente se concatenan, asegúrate de usar
puntos y comas intermedios para separar las expresiones.)
-s nombre=valor: Predefine la variable fuera de la transmisión @nombre para tener
    Así mlr put -s foo=97 '$column += @foo' es como
    mlr put 'begin {@foo = 97} $column += @foo'.
    El valor está sujeto a inferencia de tipos.
    Se puede especificar más de una vez, por ejemplo, -s nombre1=valor1 -s nombre2=valor2.
    Nota: el valor puede ser una variable de entorno, por ejemplo, -s secuencia=$SEQUENCE
-x (predeterminado falso) Imprime registros para los cuales {expresión} se evalúa como falso, no verdadero,
   es decir, invierte el sentido de la expresión de filtro.
-q No incluye el registro modificado en el flujo de salida.
   Útil cuando toda la salida deseada está en bloques begin y/o end.
-S y -F: Son operaciones nulas en Miller 6 y versiones superiores, ya que ahora la inferencia de tipos es realizada
   por los lectores de registros antes de que se ejecute filter/put. Se admiten como banderas de paso nulo
   para compatibilidad con versiones anteriores.
-h|--help Mostrar este mensaje.
Opciones de información del analizador:
-w Imprime advertencias sobre cosas como variables no inicializadas.
-W Igual que -w, pero sale del proceso si hay alguna advertencia.
-p Imprime el AST (árbol de sintaxis abstracta) de la expresión, lo que brinda total
  transparencia sobre las reglas de precedencia y asociatividad de la gramática de Miller,
  a la salida estándar.
-d Como -p pero usa un formato de expresión entre paréntesis para el AST.
-D Como -d pero con la salida toda en una línea.
-E Muestra la expresión DSL antes de imprimir el árbol de análisis.
-v Igual que -E -p.
-X Sale después de analizar pero antes de procesar la transmisión. Útil con -v/-d/-D, si solo
   quieres ver información del analizador.
Los registros pasarán el filtro dependiendo de la última declaración booleana desnuda en
la expresión DSL. Ese puede ser el resultado de <, ==, >, etc., el valor de retorno de una llamada a función
que devuelve un booleano, etc.
Ejemplos:
  mlr --csv --from example.csv filter '$color == "red"'
  mlr --csv --from example.csv filter '$color == "red" && flag == true'
Más ejemplos de expresiones de filtro:
  Primer registro en cada archivo:
    'FNR == 1'
  Submuestreo:
    'urand() < 0.001'
  Booleanos compuestos:
    '$color != "blue" && $value > 4.2'
    '($x < 0.5 && $y < 0.5) || ($x > 0.5 && $y > 0.5)'
  Regex con indicador de distinción entre mayúsculas y minúsculas
    '($name =~ "^sys.*east$") || ($name =~ "^dev.[0-9]+"i)'
  Asignaciones, luego declaración de filtro booleano desnudo:
    '$ab = $a+$b; $cd = $c+$d; $ab != $cd'
  Declaración de filtro booleano desnudo dentro de un condicional:
    'if (NR < 100) {
      $x > 0.3;
    } else {
      $x > 0.002;
    }
    '
  Usando la función de orden superior 'any' para ver si $index es 10, 20 o 30:
    'any([10,20,30], func(e) {return $index == e})'

step

Uso: mlr step [opciones]
Calcula valores dependientes de registros anteriores/posteriores, opcionalmente agrupados por categoría.
Opciones:
-a {delta,rsum,...} Nombres de los pasos: separados por comas, uno o más de:
  counter    Cuenta instancias de campo(s) entre registros sucesivos
  delta      Calcula diferencias en campo(s) entre registros sucesivos
  ewma       Media móvil ponderada exponencialmente sobre registros sucesivos
  from-first Calcula diferencias en campo(s) desde el primer registro
  ratio      Calcula ratios en campo(s) entre registros sucesivos
  rprod      Calcula productos acumulados de campo(s) entre registros sucesivos
  rsum       Calcula sumas acumuladas de campo(s) entre registros sucesivos
  shift      Alias para shift_lag
  shift_lag  Incluye valor(es) en campo(s) del registro anterior, si existe
  shift_lead Incluye valor(es) en campo(s) del registro siguiente, si existe
  slwin      Medias de ventana deslizante sobre m registros atrás y n hacia adelante. Por ejemplo, slwin_7_2 para 7 atrás y 2 hacia adelante.
-f {a,b,c}   Nombres de los campos de valor sobre los que calcular estadísticas
-g {d,e,f}   Nombres de campos opcionales para agrupar por
-F           Calcula elementos "integerables" (ej. counter) en punto flotante.
             A partir de Miller 6 esto ocurre automáticamente, pero el flag se acepta
             como no-op por compatibilidad retroactiva con Miller 5 y anteriores.
-d {x,y,z}   Pesos para EWMA. 1 significa que la muestra actual obtiene todo el peso (sin
             suavizado), cerca de under 1 es suavizado ligero, cerca de over 0 es
             suavizado pesado. Se pueden especificar múltiples pesos, ej.
             "mlr step -a ewma -f sys_load -d 0.01,0.1,0.9". El valor por defecto si se omite
             es "-d 0.5".
-o {a,b,c}   Sufijos personalizados para campos de salida EWMA. Si se omiten, estos por defecto son
             los valores -d. Si se suministran, el número de valores -o debe ser el mismo
             que el número de valores -d.
-h|--help   Muestra este mensaje.
Ejemplos:
  mlr step -a rsum -f request_size
  mlr step -a delta -f request_size -g hostname
  mlr step -a ewma -d 0.1,0.9 -f x,y
  mlr step -a ewma -d 0.1,0.9 -o smooth,rough -f x,y
  mlr step -a ewma -d 0.1,0.9 -o smooth,rough -f x,y -g group_name
  mlr step -a slwin_9_0,slwin_0_9 -f x

https://en.wikipedia.org/wiki/Moving_average#Exponential_moving_average

summary

Uso: mlr summary [opciones]
Muestra estadísticas resumidas sobre los datos de entrada.
Todos los sumarizadores:
  field_type      string, int, etc. -- si una columna tiene tipos mixtos, se imprimen todos los tipos encontrados
  count           +1 por cada instancia del campo en todos los registros del flujo de entrada
  null_count      recuento de valores de campo que son cadena vacía o null de JSON
  distinct_count  recuento de valores distintos para el campo
  mode            valor que ocurre con mayor frecuencia para el campo
  sum             suma de los valores del campo
  mean            media de los valores del campo
  stddev          desviación estándar de los valores del campo
  var             varianza de los valores del campo
  skewness        asimetría de los valores del campo
  minlen          longitud de la representación de cadena más corta para el campo
  maxlen          longitud de la representación de cadena más larga para el campo
  min             valor mínimo del campo
  p25             valor del primer cuartil del campo
  median          valor mediano del campo
  p75             valor del tercer cuartil del campo
  max             valor máximo del campo
  iqr             rango intercuartílico: p75 - p25
  lof             límite exterior inferior: p25 - 3.0 * iqr
  lif             límite interior inferior: p25 - 1.5 * iqr
  uif             límite interior superior: p75 + 1.5 * iqr
  uof             límite exterior superior: p75 + 3.0 * iqr
Sumarizadores por defecto:
  field_type count mean min max null_count distinct_count
Notas:
* min, p25, median, p75 y max funcionan tanto para cadenas como para números
* Los recuentos distintos se calculan sobre representaciones de cadena, por lo que 4.1 y 4.10 se cuentan como distintos aquí.
* Si la moda no es única en los datos de entrada, el primer valor encontrado se reporta como la moda.

sort




 (class=higher-order-functions #args=1-2) Dado un mapa o arreglo como primer argumento y cadenas de flags o una función como segundo argumento opcional, devuelve una copia ordenada de la entrada. Con un argumento, ordena los elementos del arreglo con números primero numéricamente y luego cadenas léxicamente, y los elementos del mapa de manera similar por claves del mapa. Si el segundo argumento es una cadena, puede contener cualquiera de "f" para léxico ("n" es para el predeterminado anterior), "c" para léxico insensible a mayúsculas/minúsculas, o "t" para orden natural. Un "r" adicional en esa cadena es para reversa. Un "v" adicional en esa cadena significa ordenar mapas por valor, en lugar de por clave. Si el segundo argumento es una función, entonces para arreglos debe tomar dos argumentos a y b, devolviendo < 0, 0, o > 0 como a < b, a == b, o a > b respectivamente; para mapas la función debe tomar cuatro argumentos ak, av, bk, y bv, devolviendo nuevamente < 0, 0, o > 0, usando las claves y valores de a y b.
Ejemplos:
Ordenamiento predeterminado: sort([3,"A",1,"B",22]) devuelve [1, 3, 20, "A", "B"].
  Nota: esto es números antes que cadenas.
Ordenamiento predeterminado: sort(["E","a","c","B","d"]) devuelve ["B", "E", "a", "c", "d"].
  Nota: esto es mayúsculas antes que minúsculas.
Ascendente insensible a mayúsculas/minúsculas: sort(["E","a","c","B","d"], "c") devuelve ["a", "B", "c", "d", "E"].
Descendente insensible a mayúsculas/minúsculas: sort(["E","a","c","B","d"], "cr") devuelve ["E", "d", "c", "B", "a"].
Ordenamiento natural: sort(["a1","a10","a100","a2","a20","a200"], "t") devuelve ["a1", "a2", "a10", "a20", "a100", "a200"].
Arreglo con función: sort([5,2,3,1,4], func(a,b) {return b <=> a}) devuelve [5,4,3,2,1].
Mapa con función: sort({"c":2,"a":3,"b":1}, func(ak,av,bk,bv) {return bv <=> av}) devuelve {"a":3,"c":2,"b":1}.
Mapa sin función: sort({"c":2,"a":3,"b":1}) devuelve {"a":3,"b":1,"c":2}.
Mapa sin función: sort({"c":2,"a":3,"b":1}, "v") devuelve {"b":1,"c":2,"a":3}.
Mapa sin función: sort({"c":2,"a":3,"b":1}, "vnr") devuelve {"a":3,"c":2,"b":1}.

$y = utf8_to_latin1($x)
$* = utf8_to_latin1($*)

variance

 (class=stats #args=1) Devuelve la varianza muestral de los valores en un array o mapa. Devuelve una cadena vacía (alias void) para arrays/mapas de longitud menor que dos; devuelve un error para tipos que no son arrays ni mapas.
Ejemplo:
variance([4,5,9,10,11]) es 9.7

version

 (class=boolean #args=1) Negación lógica.

 (class=boolean #args=2) AND lógico.

-

 (class=arithmetic #args=1,2) Resta como operador binario; operador de negación unaria.

 (class=string #args=2) Concatenación de cadenas. Los no-cadenas se convierten, por lo que puedes hacer "ax".98, etc.

.*

 (class=arithmetic #args=2) Multiplicación, con desbordamiento de entero a entero.

.+

.-

 (class=arithmetic #args=2) Resta, con desbordamiento de entero a entero.

./

 (class=arithmetic #args=2) División entera, redondeando hacia cero.

 (class=arithmetic #args=2) División. Entero / entero es entero cuando es exacto, de lo contrario es punto flotante: por ejemplo, 6/3 es 2 pero 6/4 es 1.5.

 (class=arithmetic #args=2) División entera al estilo python, redondeando hacia el negativo.

<

 (class=boolean #args=2) Menor que de cadena/numérico. La mezcla de números y cadenas da como resultado una comparación de cadenas.

<<

 (class=arithmetic #args=2) Desplazamiento a la izquierda bit a bit.

<=

 (class=boolean #args=2) Menor o igual que de cadena/numérico. La mezcla de números y cadenas da como resultado una comparación de cadenas.

<=>

 (class=boolean #args=2) Comparador, nominalmente para ordenar. Dada una <=> b, devuelve <0, 0, >0 como a < b, a == b, o a > b, respectivamente.

==

 (class=boolean #args=2) Igualdad de cadena/numérica. La mezcla de números y cadenas da como resultado una comparación de cadenas.

=~

 (class=boolean #args=2) La cadena (lado izquierdo) coincide con la expresión regular (lado derecho), por ejemplo, '$name =~ "^a.*b$"'. Los grupos de captura \1 a \9 se obtienen de (...) en el lado derecho, y se pueden usar dentro de declaraciones DSL posteriores. Ver también "Expresiones regulares" en https://miller.readthedocs.io.
Ejemplos:
Con sentencia if: if ($url =~ "http.*com") { ... }
Sin sentencia if: dado $line = "index ab09 file", y $line =~ "([a-z][a-z])([0-9][0-9])", entonces $label = "[\1:\2]", $label es "ab:09"

 (class=boolean #args=2) Mayor que de cadena/numérico. La mezcla de números y cadenas da como resultado una comparación de cadenas.

 (class=arithmetic #args=2) Desplazamiento a la derecha con signo bit a bit.

>>>

 (class=arithmetic #args=2) Desplazamiento a la derecha sin signo bit a bit.

 (class=boolean #args=3) Operador ternario estándar.

???

 (clase=aritmética #argumentos=2) XOR a nivel de bits.

^^

 (clase=booleano #argumentos=2) XOR lógico.

|

 (clase=aritmética #argumentos=2) OR a nivel de bits.

 (clase=booleano #argumentos=2) OR lógico.

~

 (clase=aritmética #argumentos=1) NOT a nivel de bits. Tenga cuidado con '$y=~$x' ya que =~ es el operador de coincidencia de expresiones regulares: intente '$y = ~$x'.

PALABRAS CLAVE PARA PUT Y FILTER

all

all: se usa en "emit1", "emit", "emitp" y "unset" como sinónimo de @*

begin

begin: define un bloque de sentencias para ser ejecutado antes de que se ingieran los registros de entrada. Las sentencias del cuerpo deben estar envueltas en llaves.
  Ejemplo: 'begin { @count = 0 }'

bool

bool: declara una variable local booleana en el ámbito actual de llaves.
La comprobación de tipos ocurre en la asignación: 'bool b = 1' es un error.

break

break: hace que la ejecución continúe después del cuerpo del bucle for/while/do-while actual.

call

call: se usa para invocar una subrutina definida por el usuario.
  Ejemplo: 'subr s(k,v) { print k . " es " . v} call s("a", $a)'

continue

continue: hace que la ejecución omita las sentencias restantes en el cuerpo del
bucle for/while/do-while actual. Los incrementos del bucle for todavía se aplican.

do

do: junto con "while", introduce un bucle do-while. Las sentencias del cuerpo deben estar envueltas
en llaves.

dump

dump: imprime todas las variables definidas actualmente fuera del flujo inmediatamente
a stdout como JSON.
Con >, >>, o |, los datos no van directamente a stdout, sino que se redirigen.
> y >> son para escribir y adjuntar, como en el shell, pero (como con awk) la
sobrescritura del archivo para > ocurre en la primera escritura, no por registro. | es para canalizar a
un proceso que procesará los datos. Habrá un archivo abierto por cada nombre de archivo distinto (para > y >>) o un proceso subordinado por cada valor distinto
del comando al que se canaliza (|). Las banderas de formato de salida se toman de la línea de comandos principal.
  Ejemplo: mlr --from f.dat put -q '@v[NR]=$*; end { dump }'
  Ejemplo: mlr --from f.dat put -q '@v[NR]=$*; end { dump >  "mytap.dat"}'
  Ejemplo: mlr --from f.dat put -q '@v[NR]=$*; end { dump >> "mytap.dat"}'
  Ejemplo: mlr --from f.dat put -q '@v[NR]=$*; end { dump | "jq ."}'

edump

edump: imprime todas las variables definidas actualmente fuera del flujo inmediatamente
a stderr como JSON.
  Ejemplo: mlr --from f.dat put -q '@v[NR]=$*; end { edump }'

elif

elif: la forma en que Miller escribe "else if". Las sentencias del cuerpo deben estar envueltas
en llaves.

else

else: termina una cadena if/elif/elif. Las sentencias del cuerpo deben estar envueltas
en llaves.

emit1

emit1: inserta una variable fuera del flujo en el flujo de registros de salida. A diferencia
de las otras variantes de map, los lados a lado, la indexación y la redirección no son compatibles,
pero puedes emitir cualquier expresión de valor map.
  Ejemplo: mlr --from f.dat put 'emit1 $*'
  Ejemplo: mlr --from f.dat put 'emit1 mapsum({"id": NR}, $*)'
Por favor, consulte https://miller.readthedocs.io://johnkerl.org/miller/doc para más información.

emit

emit: inserta una variable fuera del flujo en el flujo de registros de salida. Los índices del hashmap
presentes en los datos pero no asignados por los argumentos emit no se generan.
Con >, >>, o |, los datos no se convierten en parte del flujo de registros de salida, sino que se redirigen.
> y >> son para escribir y adjuntar, como en el shell, pero (como con awk) la
sobrescritura del archivo para > ocurre en la primera escritura, no por registro. | es para canalizar a
un proceso que procesará los datos. Habrá un archivo abierto por cada nombre de archivo distinto (para > y >>) o un proceso subordinado por cada valor distinto
del comando al que se canaliza (|). Las banderas de formato de salida se toman de la línea de comandos principal.
Puede usar cualquiera de las banderas de línea de comandos de formato de salida, por ejemplo, --ocsv, --ofs,
etc., para controlar el formato de la salida si la salida está redirigida. Consulte también mlr -h.
  Ejemplo: mlr --from f.dat put 'emit >  "/tmp/data-"$a, $*'
  Ejemplo: mlr --from f.dat put 'emit >  "/tmp/data-"$a, mapexcept($*, "a")'
  Ejemplo: mlr --from f.dat put '@sums[$a][$b]+=$x; emit @sums'
  Ejemplo: mlr --from f.dat put --ojson '@sums[$a][$b]+=$x; emit > "tap-"$a$b".dat", @sums'
  Ejemplo: mlr --from f.dat put '@sums[$a][$b]+=$x; emit @sums, "index1", "index2"'
  Ejemplo: mlr --from f.dat put '@sums[$a][$b]+=$x; emit @*, "index1", "index2"'
  Ejemplo: mlr --from f.dat put '@sums[$a][$b]+=$x; emit >  "mytap.dat", @*, "index1", "index2"'
  Ejemplo: mlr --from f.dat put '@sums[$a][$b]+=$x; emit >> "mytap.dat", @*, "index1", "index2"'
  Ejemplo: mlr --from f.dat put '@sums[$a][$b]+=$x; emit | "gzip > mytap.dat.gz", @*, "index1", "index2"'
  Ejemplo: mlr --from f.dat put '@sums[$a][$b]+=$x; emit > stderr, @*, "index1", "index2"'
  Ejemplo: mlr --from f.dat put '@sums[$a][$b]+=$x; emit | "grep somepattern", @*, "index1", "index2"'
Por favor, consulte https://miller.readthedocs.io://johnkerl.org/miller/doc para más información.

emitf

emitf: inserta variables fuera del flujo no indexadas lado a lado en el
flujo de registros de salida.
Con >, >>, o |, los datos no se convierten en parte del flujo de registros de salida, sino que se redirigen.
> y >> son para escribir y adjuntar, como en el shell, pero (como con awk) la
sobrescritura del archivo para > ocurre en la primera escritura, no por registro. | es para canalizar a
un proceso que procesará los datos. Habrá un archivo abierto por cada nombre de archivo distinto (para > y >>) o un proceso subordinado por cada valor distinto
del comando al que se canaliza (|). Las banderas de formato de salida se toman de la línea de comandos principal.
Puede usar cualquiera de las banderas de línea de comandos de formato de salida, por ejemplo, --ocsv, --ofs,

  Ejemplo: mlr --from f.dat put '@a=$i;@b+=$x;@c+=$y; emitf @a'
  Ejemplo: mlr --from f.dat put --oxtab '@a=$i;@b+=$x;@c+=$y; emitf > "tap-"$i".dat", @a'
  Ejemplo: mlr --from f.dat put '@a=$i;@b+=$x;@c+=$y; emitf @a, @b, @c'
  Ejemplo: mlr --from f.dat put '@a=$i;@b+=$x;@c+=$y; emitf > "mytap.dat", @a, @b, @c'
  Ejemplo: mlr --from f.dat put '@a=$i;@b+=$x;@c+=$y; emitf >> "mytap.dat", @a, @b, @c'
  Ejemplo: mlr --from f.dat put '@a=$i;@b+=$x;@c+=$y; emitf > stderr, @a, @b, @c'
  Ejemplo: mlr --from f.dat put '@a=$i;@b+=$x;@c+=$y; emitf | "grep somepattern", @a, @b, @c'

end: define un bloque de instrucciones para ser ejecutado después de que se ingieren los registros de entrada.

eprint: imprime la expresión inmediatamente en stderr.

eprintn

eprintn: imprime la expresión inmediatamente en stderr, sin salto de línea al final.

false

false: el valor literal booleano.

filter

filter: incluye/excluye el registro del flujo de registros de salida.
  Ejemplo: mlr --from f.dat put 'filter (NR == 2 || $x > 5.4)'
En lugar de put con 'filter false', puedes simplemente usar put -q. Lo siguiente
usa el registro de entrada para acumular datos pero solo imprime la suma acumulada
sin imprimir el registro de entrada:
  Ejemplo: mlr --from f.dat put -q '@running_sum += $x * $y; emit @running_sum'

float

float: declara una variable local de punto flotante en el ámbito actual entre llaves.
La comprobación de tipos ocurre en la asignación: 'float x = 0' es un error.

for

for: define un bucle for usando uno de tres estilos. Las instrucciones del cuerpo deben
estar entre llaves.
Bucle for sobre el registro de flujo:
  Ejemplo:  'for (k, v in $*) { ... }'
Bucle for sobre variables fuera de flujo:
  Ejemplo: 'for (k, v in @counts) { ... }'
  Ejemplo: 'for ((k1, k2), v in @counts) { ... }'
  Ejemplo: 'for ((k1, k2, k3), v in @*) { ... }'
Bucle for estilo C:
  Ejemplo:  'for (var i = 0, var b = 1; i < 10; i += 1, b *= 2) { ... }'

func

func: se utiliza para definir una función definida por el usuario.
  Ejemplo: 'func f(a,b) { return sqrt(a**2+b**2)} $d = f($x, $y)'

funct

funct: se utiliza para indicar que un argumento de función es una función definida por el usuario.
  Ejemplo: 'func g(num a, num b, funct f) :num { return f(a**2+b**2) }'

if

if: inicia una cadena if/elif/elif. Las instrucciones del cuerpo deben
estar entre llaves.

in

in: se utiliza en bucles for sobre registros de flujo o variables fuera de flujo.

int

int: declara una variable local entera en el ámbito actual entre llaves.
La comprobación de tipos ocurre en la asignación: 'int x = 0.0' es un error.

map

map: declara una variable local de tipo mapa en el ámbito actual entre llaves.
La comprobación de tipos ocurre en la asignación: 'map b = 0' es un error. map b = {} es

num

num: declara una variable local int/float en el ámbito actual entre llaves.

print

print: imprime la expresión inmediatamente en stdout.

printn: imprime la expresión inmediatamente en stdout, sin salto de línea al final.

return

return: especifica el valor de retorno de una función definida por el usuario.

stderr

stderr: se utiliza para tee, emit, emitf, emitp, print y dump en lugar de un nombre de archivo

stdout

stdout: se utiliza para tee, emit, emitf, emitp, print y dump en lugar de un nombre de archivo

str

str: declara una variable local de tipo cadena en el ámbito actual entre llaves.

subr

subr: se utiliza para definir una subrutina.
  Ejemplo: 'subr s(k,v) { print k . " es " . v} call s("a", $a)'

tee

tee: imprime el registro actual en el archivo especificado.
Esta es una impresión inmediata en el archivo especificado (excepto para el formato pprint
que, por supuesto, espera hasta el final del flujo de entrada para formatear toda la salida).
Los operadores > y >> son para escribir y anexar, como en la shell, pero (como con awk) la
sobrescritura del archivo para > ocurre en la primera escritura, no por registro. El operador | es para canalizar a
un proceso que procesará los datos. Habrá un archivo abierto por cada nombre de archivo distinto
(para > y >>) o un proceso subordinado por cada valor distinto del comando al que se canaliza (para |). Las banderas de formato de salida se toman de la línea de comandos principal.
Puede usar cualquiera de las banderas de comandos de formato de salida, por ejemplo, --ocsv, --ofs,
etc., para controlar el formato de la salida. Consulte también mlr -h.
emit con redirección y tee con redirección son idénticos, excepto que tee solo puede
generar $*.
  Ejemplo: mlr --from f.dat put 'tee >  "/tmp/data-".$a, $*'
  Ejemplo: mlr --from f.dat put 'tee >> "/tmp/data-".$a.$b, $*'
  Ejemplo: mlr --from f.dat put 'tee >  stderr, $*'
  Ejemplo: mlr --from f.dat put -q 'tee | "tr [a-z] [A-Z]", $*'
  Ejemplo: mlr --from f.dat put -q 'tee | "tr [a-z] [A-Z] > /tmp/data-".$a, $*'
  Ejemplo: mlr --from f.dat put -q 'tee | "gzip > /tmp/data-".$a.".gz", $*'
  Ejemplo: mlr --from f.dat put -q --ojson 'tee | "gzip > /tmp/data-".$a.".gz", $*'

true

true: el valor literal booleano.

unset

unset: borra campos del registro actual, o una variable fuera de flujo o local.
  Ejemplo: mlr --from f.dat put 'unset $x'
  Ejemplo: mlr --from f.dat put 'unset $*'
  Ejemplo: mlr --from f.dat put 'for (k, v in $*) { if (k =~ "a.*") { unset $[k] } }'

  Ejemplo: mlr --from f.dat put '...; unset @sums["green"]'
  Ejemplo: mlr --from f.dat put '...; unset @*'

var

var: declara una variable local sin tipo en el ámbito actual entre llaves.
  Ejemplos: 'var a=1', 'var xyz=""'

while

while: introduce un bucle while, o con "do", introduce un bucle do-while.
