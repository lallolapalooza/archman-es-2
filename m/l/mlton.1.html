NOMBRE

mlton - compilador de programa completo para el lenguaje de programación Standard ML (SML)

SINOPSIS

mlton [opción ...] archivo.{c|mlb|o|sml} [archivo.{c|o|s|S} ...]

DESCRIPCIÓN

MLton se ejecuta desde la línea de comandos con una colección de opciones seguidas de un nombre de archivo y una lista de archivos con los que compilar, ensamblar y enlazar. El caso más simple es ejecutar mlton foo.sml, donde foo.sml contiene un programa SML válido, en cuyo caso MLton compila el programa para producir un ejecutable foo. Dado que MLton no admite compilación separada, el programa debe ser el programa completo que desea compilar. Sin embargo, el programa puede hacer referencia a firmas y estructuras definidas en la Biblioteca Base.

Los programas más grandes, que abarcan varios archivos, se pueden compilar con el sistema ML Basis. En este caso, mlton foo.mlb compilará el programa SML completo descrito por la base foo.mlb, que puede especificar tanto archivos SML como bases adicionales. Consulte la Guía de MLton para obtener más detalles.

Las opciones de tiempo de compilación de MLton controlan el nombre del archivo de salida, la verbosidad de los mensajes de tiempo de compilación y si se realizan ciertas optimizaciones. También pueden especificar qué archivos intermedios se guardan y pueden detener el proceso de compilación de forma temprana, en algún paso intermedio, en cuyo caso la compilación se puede reanudar pasando los archivos generados a MLton. MLton utiliza el sufijo del archivo de entrada para determinar el tipo del programa de entrada. Las posibilidades son .c, .mlb, .o, .s y .sml.

Sin argumentos, MLton imprime el número de versión y sale. Para obtener un mensaje de uso, ejecute MLton con un conmutador inválido, p. ej., mlton -z. En la explicación a continuación y en el mensaje de uso, para las banderas que toman un número de opciones (p. ej., {verdadero|falso}), el primer valor que se enumera es el valor predeterminado.

Opciones de tiempo de compilación

-alinear n
Alinea objetos en memoria por la alineación especificada (4 u 8). El valor predeterminado varía según la arquitectura.
-as-opt opción
Pasa opción a gcc al compilar código ensamblador. Si desea pasar una opción al ensamblador, debe usar la sintaxis -Wa, de gcc.
-cc cc
Especifica el ejecutable para el compilador C. El compilador C también se invoca para compilar ensamblaje (archivos .s) en código objeto (archivos .o) y para enlazar código objeto en un ejecutable.
-cc-opt opción
Pasa opción a gcc al compilar código C.
-codegen {native|x86|amd64|c|llvm}
Genera código objeto nativo a través de ensamblaje amd64, código C, código LLVM o ensamblaje x86. Con -codegen native (-codegen amd64 o -codegen x86), MLton generalmente compila más rápido y genera mejor código.
-const 'nombre valor'
Establece el valor de una constante en tiempo de compilación. Aquí hay una lista de constantes disponibles, sus valores predeterminados y qué controlan.

Exn.keepHistory {false|true}
Habilita MLton.Exn.history. Existe un costo de rendimiento al establecer esto en true, tanto en el uso de memoria de las excepciones como en el tiempo de ejecución, debido al trabajo adicional que debe realizarse en cada construcción, elevación y manejo de excepciones.

-default-ann ann
Especifica anotaciones predeterminadas de ML Basis. Por ejemplo, -default-ann 'warnUnused true' hace que las advertencias de variables no utilizadas se habiliten por defecto. Los valores predeterminados pueden ser anulados por una anotación en un archivo ML Basis.
-default-type type
Especifica el enlace predeterminado para un tipo primitivo. Por ejemplo, -default-type word64 hace que el tipo de nivel superior word y la estructura de nivel superior Word en la Biblioteca Base sean iguales a Word64.word y Word64:WORD, respectivamente. De manera similar, -default-type intinf hace que el tipo de nivel superior int y la estructura de nivel superior Int en la Biblioteca Base sean iguales a IntInf.int y IntInf:INTEGER, respectivamente.
-disable-ann ann
Ignora la anotación especificada de ML Basis en cada Archivo ML Basis. Por ejemplo, para ver todas las advertencias de coincidencia y de uso no utilizado, compile con -default-ann 'warnUnused true', -disable-ann forceUsed, -disable-ann nonexhaustiveMatch, -disable-ann redundantMatch y -disable-ann warnUnused.
-export-header archivo
Escribe prototipos C en archivo para todas las funciones del programa exportadas de SML a C.
-ieee-fp {false|true}
Hace que el generador de código nativo x86 sea pedante sobre seguir el estándar de punto flotante IEEE. Por defecto, no lo es, debido al costo de rendimiento. Esto solo tiene un efecto con -codegen x86.
-inline n
Establece el umbral de inlining utilizado en el optimizador. El umbral es una medida aproximada del tamaño del código de un procedimiento. El valor predeterminado es 320.
-keep {g|o}
Guarda archivos intermedios. Si no se proporciona ningún argumento -keep, solo se guarda el archivo de salida.
g archivos .c y .s generados pasados a gcc y archivos .ll generados pasados a llvm-as
o archivos objeto (.o)
-link-opt opción
Pasa opción a gcc al enlazar. Puede usar esto para especificar rutas de búsqueda de bibliotecas, p. ej., -link-opt -Lruta, y bibliotecas para enlazar, p. ej., -link-opt -lfoo, o incluso ambos al mismo tiempo, p. ej., -link-opt '-Lruta -lfoo'. Si desea pasar una opción al enlazador, debe usar la sintaxis -Wl, de gcc, p. ej., -link-opt '-Wl,--export-dynamic'.
-llvm-as llvm-as
Especifica el ejecutable para el ensamblador LLVM de .ll a .bc; se puede usar para seleccionar una versión específica de la herramienta (p. ej., -llvm-as llvm-as-14).
-llvm-as-opt opción
Pasa opción a llvm-as al ensamblar (de .ll a .bc) código LLVM.
-llvm-llc llc
Especifica el ejecutable para el compilador de sistemas LLVM de .bc a .o; se puede usar para seleccionar una versión específica de la herramienta (p. ej., -llvm-llc llc-14).
-llvm-llc-opt opción
Pasa opción a llc al compilar (de .bc a .o) código LLVM.
-llvm-opt opt
Especifica el ejecutable para el optimizador LLVM de .bc a .bc; se puede usar para seleccionar una versión específica de la herramienta (p. ej., -llvm-opt opt-14).
-llvm-opt-opt opción
Pasa opción a opt al optimizar (de .bc a .bc) código LLVM.
-mlb-path-map archivo
Usa archivo como un mapa de ruta ML Basis para descifrar

fine additional MLB path variables. Múltiples usos de -mlb-path-map y -mlb-path-var están permitidos, con las definiciones de variables en mapas de ruta posteriores que tienen precedencia sobre las anteriores.
-mlb-path-var nombre valor
Define una variable adicional de ruta MLB. Múltiples usos de -mlb-path-map y -mlb-path-var están permitidos, con las definiciones de variables en mapas de ruta posteriores que tienen precedencia sobre las anteriores.
-output archivo
Especifica el nombre del archivo de salida final. El nombre por defecto es el nombre del archivo de entrada con su sufijo eliminado y un sufijo apropiado, posiblemente vacío, añadido.
-profile {no|alloc|count|time}
Produce un ejecutable que recopila datos de perfil. Cuando dicho ejecutable se ejecuta, producirá un archivo mlmon.out. La página man de mlprof describe cómo extraer información de este archivo.
-profile-branch {false|true}
Si es verdadero, el generador de perfiles recopilará por separado datos de perfil para cada rama de una definición de función, expresión case y expresión if.
-profile-stack {false|true}
Si es verdadero, el generador de perfiles recopilará datos de perfil para todas las funciones en la pila, no solo para la función que se está ejecutando actualmente.
-profile-val {false|true}
Si es verdadero, el generador de perfiles recopilará por separado datos de perfil para cada declaración (costosa) de val.
-runtime arg
Pasa el argumento al sistema en tiempo de ejecución a través de @MLton. El argumento se procesará antes que otros modificadores de línea de comandos de @MLton. Se permiten múltiples usos de -runtime, y pasarán todos los argumentos en orden. Si el mismo modificador de tiempo de ejecución ocurre más de una vez, entonces la última configuración tendrá efecto. No es necesario proporcionar el @MLton inicial o el -- final; estos se proporcionarán automáticamente.

Un argumento para -runtime puede contener espacios, lo que hará que el argumento se trate como una secuencia de palabras por el tiempo de ejecución. Por ejemplo, la línea de comandos:
mlton -runtime 'ram-slop 0.4' foo.sml
hará que foo se ejecute como si hubiera sido llamado como
foo @MLton ram-slop 0.4 --

Un ejecutable creado con -runtime stop no procesa argumentos de @MLton. Esto es útil para crear un ejecutable, por ejemplo, echo, que debe tratar @MLton como cualquier otro argumento de línea de comandos.
% mlton -runtime stop echo.sml

% echo @MLton --

@MLton --

-show-basis archivo
Imprime formateado en archivo la base definida por el programa de entrada.
-show-def-use archivo
Muestra información de definición-uso en archivo. Cada identificador que se define aparece en una línea, seguido en las líneas subsiguientes por la posición de cada uso.
-stop {f|g|o|tc}
Especifica cuándo detenerse.
f lista de archivos en stdout (solo tiene sentido cuando la entrada es foo.mlb)
g archivos .c y .s generados
o archivos objeto (.o)
tc después de la verificación de tipos
Si compila con -stop g o -stop o, puede reanudar la compilación ejecutando MLton en los archivos .c y .s o .o generados.
-target {self|...}
Genera un ejecutable que se ejecuta en la plataforma especificada. El valor por defecto es self, lo que significa compilar para la máquina en la que se está ejecutando MLton. Para usar cualquier otro objetivo, primero debe instalar un compilador cruzado. Consulte la Guía de MLton para obtener detalles.
-target-as-opt objetivo opción
Al igual que -as-opt, esto pasa opción a gcc al ensamblar, excepto que solo pasa opción cuando la arquitectura o el sistema operativo de destino es objetivo.
-target-cc-opt objetivo opción
Al igual que -cc-opt, esto pasa opción a gcc al compilar código C, excepto que solo pasa opción cuando la arquitectura o el sistema operativo de destino es objetivo.
-target-link-opt objetivo opción
Al igual que -link-opt, esto pasa opción a gcc al enlazar, excepto que solo pasa opción cuando la arquitectura o el sistema operativo de destino es objetivo.
-verbose {0|1|2|3}
Qué tan detallado ser sobre los pases que se están ejecutando. El valor por defecto es 0.
0 silencioso
1 llamadas al compilador, ensamblador y enlazador
2 1, más pases intermedios del compilador
3 2, más algunos tamaños de estructuras de datos

Opciones del sistema en tiempo de ejecución

Los ejecutables producidos por MLton aceptan argumentos de línea de comandos que controlan el sistema en tiempo de ejecución. Estos argumentos son opcionales y ocurren antes de los argumentos habituales del ejecutable. Para usar estas opciones, el primer argumento para el ejecutable debe ser @MLton. Los argumentos opcionales luego siguen, deben ser terminados por --, y son seguidos por cualquier argumento para el programa. Los argumentos opcionales *no* se ponen a disposición del programa SML a través de CommandLine.arguments. Por ejemplo, una llamada válida a hello-world es:
hello-world @MLton gc-summary fixed-heap 10k -- a b c
En el ejemplo anterior, CommandLine.arguments () = ["a", "b", "c"].

Se permite una secuencia de argumentos de @MLton, como en:
hello-world @MLton gc-summary -- @MLton fixed-heap 10k -- a b c

Las opciones de tiempo de ejecución también pueden controlar MLton, como en
mlton @MLton fixed-heap 0.5g -- foo.sml

fixed-heap x{k|K|m|M|g|G}
Usa un heap de tamaño fijo de tamaño x, donde x es un número real y la letra final indica sus unidades.
k o K 1024
m o M 1,048,576
g o G 1,073,741,824
Un valor de 0 significa usar casi toda la RAM presente en la máquina.

El tamaño del heap utilizado por fixed-heap incluye toda la memoria asignada por el código SML, incluida la memoria para la pila (o pilas, si hay varios hilos). Sin embargo, no incluye ninguna memoria utilizada para el propio código o memoria utilizada por variables globales C, la pila C o malloc.

gc-messages
Imprime un mensaje al principio y al final de cada recolección de basura.
gc-summary
Imprime un resumen de las estadísticas de recolección de basura al finalizar el programa.
gc-summary-file archivo
Imprime un resumen de las estadísticas de recolección de basura al finalizar el programa en el archivo especificado por archivo.
load-world mundo
Reinicia el cálculo con el archivo especificado por mundo, que debe haber sido creado por una llamada a MLton.World.save por el mismo ejecutable. Consulte la Guía de MLton para obtener detalles.
max-heap x{k|K|m|M|g|G}
Ejecuta el cálculo con un heap de tamaño automático que nunca es mayor que x, donde x es un número real y la letra final indica las unidades como con fixed-heap. El tamaño del heap para max-heap se tiene en cuenta como con fixed-heap.
may-page-heap {false|true}
Habilita la paginación del heap al disco cuando no se puede aumentar el heap a un tamaño deseado.
no-load-world
Deshabilita load-world. Esto se puede usar como argumento para el compilador a través de -runtime no-load-world para crear ejecutables que no cargarán un mundo. Esto puede ser útil para asegurar que los ejecutables set-uid no carguen algún mundo extraño.
ram-slop x
Multiplica x por la cantidad de RAM en la máquina para obtener lo que el tiempo de ejecución considera la cantidad de RAM que puede usar. Típicamente x es menor que 1, y se usa para tener en cuenta el espacio utilizado por otros programas que se ejecutan en la misma máquina.
stop
Hace que el tiempo de ejecución deje de procesar argumentos de @MLton una vez que se alcanza el siguiente --. Esto se puede usar como argumento para el compilador a través de -runtime stop para crear ejecutables que no procesan ningún argumento de @MLton.

MLton es un compilador de Standard ML.

NAME

mlton - un compilador de Standard ML

SYNOPSIS

mlton [opciones] [archivos.mlb ...]

DESCRIPTION

MLton es un compilador para Standard ML. Genera código nativo para varias arquitecturas. MLton compila programas escritos en Standard ML of New Jersey (SML/NJ) y proporciona un sistema de tiempo de ejecución compatible con SML/NJ.

El compilador MLton se invoca típicamente especificando uno o más archivos de bibliotecas (.mlb) que definen la estructura del programa. MLton compilará los archivos Source ML (.sml) y ML-Basis (.mlb) referenciados por estos archivos de bibliotecas.

El compilador puede ser invocado directamente o a través de utilidades de construcción como mlton-build.

Para más detalles, consulta la documentación de MLton, incluyendo el Manual de MLton y el Sistema de Tiempo de Ejecución de MLton.

Compile-time options

MLton soporta una amplia gama de opciones de tiempo de compilación para controlar el proceso de compilación, la optimización, la generación de código y la información de depuración. Algunas opciones comunes incluyen:

  • -allow-existing: Permite que las definiciones existan en múltiples archivos.
  • -disable-heap-compression: Deshabilita la compresión de heap en tiempo de ejecución.
  • -export-main: Exporta la función principal para la vinculación externa.
  • -heap-size: Especifica el tamaño del heap en tiempo de ejecución.
  • -link-runtime-sys: Vincula el sistema de tiempo de ejecución de MLton.
  • -o: Especifica el nombre del archivo de salida.
  • -profile: Habilita el perfilado del programa.
  • -verbose: Muestra información detallada durante la compilación.

Para una lista completa de opciones, consulta la documentación de MLton.

Runtime system options

El sistema de tiempo de ejecución de MLton también puede ser configurado a través de variables de entorno o argumentos de línea de comandos pasados al ejecutable generado. Estas opciones controlan el comportamiento del programa en tiempo de ejecución, como la gestión de memoria y el manejo de excepciones.

  • MLTON_GC_HEAP_SIZE: Establece el tamaño del heap de la recolección de basura.
  • MLTON_EXN_REGS: Controla el registro de excepciones.

Consulta el Sistema de Tiempo de Ejecución de MLton para obtener detalles.

DIAGNOSTICS

MLton proporciona mensajes de error y advertencia detallados durante la compilación. Estos mensajes suelen indicar el archivo fuente, el número de línea y la naturaleza del problema, como errores de sintaxis, violaciones de tipos o inconsistencias semánticas.

El sistema de tiempo de ejecución también puede generar diagnósticos relacionados con la gestión de memoria, excepciones no manejadas u otros problemas en tiempo de ejecución.
