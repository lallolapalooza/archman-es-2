NOMBRE

mlx5dv_dek_create - Crea una DEK

mlx5dv_dek_query - Consulta los atributos de una DEK

mlx5dv_dek_destroy - Destruye una DEK

SINOPSIS

#include <infiniband/mlx5dv.h>
struct mlx5dv_dek *mlx5dv_dek_create(struct ibv_context *context,
                     struct mlx5dv_dek_init_attr *init_attr);
int mlx5dv_dek_query(struct mlx5dv_dek *dek, struct mlx5dv_dek_attr *attr);
int mlx5dv_dek_destroy(struct mlx5dv_dek *dek);

DESCRIPCIÓN

Las Claves de Cifrado de Datos (DEKs) se utilizan para cifrar y descifrar datos transmitidos. Después de crear una DEK, se puede configurar en las MKeys para operaciones de descarga de cifrado. Las DEKs no son persistentes y se destruyen al salir del proceso. Por lo tanto, el proceso de software debe volver a crear todas las DEKs necesarias al inicio.

mlx5dv_dek_create() crea una nueva DEK con los atributos especificados en init_attr. Se devuelve un puntero a la DEK recién creada, que puede utilizarse para la consulta de DEK, la destrucción de DEK y al configurar una MKey para operaciones de descarga de cifrado.

La DEK puede estar envuelta o en texto plano, y el formato que se debe utilizar se determina por el objeto de inicio de sesión de cifrado especificado.

Para crear una DEK envuelta, la aplicación debe tener un objeto de inicio de sesión de cifrado válido antes de crear la DEK. Crear una DEK envuelta se puede realizar de dos maneras: 1. Llamar a mlx5dv_crypto_login_create() para obtener un objeto de inicio de sesión de cifrado. Indicar que la DEK está envuelta estableciendo el valor MLX5DV_DEK_INIT_ATTR_CRYPTO_LOGIN en comp_mask y pasando el objeto de inicio de sesión de cifrado en el campo crypto_login de init_attr. Rellenar los otros atributos de la DEK y crear la DEK.

2.
Llamar a mlx5dv_crypto_login(), es decir, la API antigua. Suministrar credencial, import_kek_id

Para crear una DEK en texto plano, la aplicación debe indicar que la DEK está en texto plano estableciendo el valor MLX5DV_DEK_INIT_ATTR_CRYPTO_LOGIN en comp_mask y pasando el valor NULL en el campo crypto_login de init_attr, rellenar los otros atributos de la DEK y crear la DEK.

Para utilizar la DEK creada (ya sea envuelta o en texto plano) en una MKey, no se necesita un objeto de inicio de sesión de cifrado o una sesión válida. Revocar la KEK de importación o la credencial que se utilizaron para el objeto de inicio de sesión de cifrado o la sesión (y, por lo tanto, invalidar el inicio de sesión de cifrado) no impide el uso de una DEK creada.

mlx5dv_dek_query() consulta la DEK especificada por dek y devuelve los atributos consultados en attr. No se requiere un objeto de inicio de sesión de cifrado o una sesión válida para consultar una DEK en texto plano. Por otro lado, para consultar una DEK envuelta, debe estar presente un objeto de inicio de sesión de cifrado o una sesión válida.

mlx5dv_dek_destroy() destruye la DEK especificada por dek.

ARGUMENTOS

context

El contexto del dispositivo con el que crear la DEK.

init_attr

enum mlx5dv_dek_init_attr_mask {
    MLX5DV_DEK_INIT_ATTR_CRYPTO_LOGIN = 1 << 0,
};
struct mlx5dv_dek_init_attr {
    enum mlx5dv_crypto_key_size key_size;
    bool has_keytag;
    enum mlx5dv_crypto_key_purpose key_purpose;
    struct ibv_pd *pd;
    char opaque[8];
    char key[128];
    uint64_t comp_mask; /* Use enum mlx5dv_dek_init_attr_mask */
    struct mlx5dv_crypto_login_obj *crypto_login;
};
key_size
El tamaño de la clave, puede ser uno de los siguientes:
MLX5DV_CRYPTO_KEY_SIZE_128
El tamaño de la clave es de 128 bits.
MLX5DV_CRYPTO_KEY_SIZE_256
El tamaño de la clave es de 256 bits.
has_keytag
Si la DEK tiene o no una etiqueta de clave. Si está configurado, la clave debe incluir una etiqueta de clave de 8 bytes. La etiqueta de clave se utiliza para verificar que la DEK que está utilizando una MKey es la DEK esperada. Esto se hace comparando la etiqueta de clave definida durante la creación de la DEK con la etiqueta de clave proporcionada en la configuración de cifrado de la MKey, y fallando la operación si son diferentes.
key_purpose
El propósito de la clave, actualmente solo puede ser el siguiente valor:
MLX5DV_CRYPTO_KEY_PURPOSE_AES_XTS
La clave se utilizará para el motor de cifrado AES-XTS.
pd
El dominio de protección que se asociará con la DEK.
opaque
Metadatos en texto plano para describir la clave.
key
La clave que se utilizará para el cifrado y descifrado de los datos transmitidos. Para una DEK en texto plano, se debe proporcionar key en texto plano. Para una DEK envuelta, se debe proporcionar key envuelta por la KEK de importación especificada en el inicio de sesión de cifrado. El tamaño real y la disposición de este campo dependen de los campos key_size y has_keytag proporcionados, así como del formato de la clave (texto plano o envuelta). key debe construirse según la siguiente tabla.

Construcción del campo key de la DEK.

Método de Importación Tiene Etiqueta de Clave Tamaño de Clave Disposición de Clave
Texto plano No 128 bits key1_128b + key2_128b
Texto plano No 256 bits key1_256b + key2_256b
Texto plano Sí 128 bits key1_128b + key2_128b + keytag_64b
Texto plano Sí 256 bits key1_256b + key2_256b + keytag_64b
Envuelta No 128 bits ENC(iv_64b + key1_128b + key2_128b)
Envuelta No 256 bits ENC(iv_64b + key1_256b + key2_256b)
Envuelta Sí 128 bits ENC(iv_64b + key1_128b + key2_128b + keytag_64b)
Envuelta Sí 256 bits ENC(iv_64b + key1_256b + key2_256b + keytag_64b)

Donde ENC() es el algoritmo de envoltura de claves AES y iv_64b es 0xA6A6A6A6A6A6A6A6 según la especificación de envoltura de claves AES NIST SP 800-38F.

El siguiente ejemplo muestra cómo envolver una clave de 128 bits con etiqueta de clave utilizando una KEK de importación de 128 bits en OpenSSL:

#include <openssl/evp.h>
unsigned char import_kek[16]; /* KEK de importación de 128 bits en texto plano para envolver */
unsigned char iv[8] = {0xA6, 0xA6, 0xA6, 0xA6, 0xA6, 0xA6, 0xA6, 0xA6};
/*
 * Los índices 0-15 son key1 en texto plano, los índices 16-31 son key2 en texto plano,
 * y los índices 32-39 son key_tag en texto plano.
 */
unsigned char key[40];
unsigned char wrapped_key[48];
EVP_CIPHER_CTX *ctx;
int len;
ctx = EVP_CIPHER_CTX_new();
EVP_CIPHER_CTX_set_flags(ctx, EVP_CIPHER_CTX_FLAG_WRAP_ALLOW);
EVP_EncryptInit_ex(ctx, EVP_aes_128_wrap(), NULL, import_kek, iv);
EVP_EncryptUpdate(ctx, wrapped_key, &len, key, sizeof(key));
EVP_EncryptFinal_ex(ctx, wrapped_key + len, &len);
EVP_CIPHER_CTX_free(ctx);
comp_mask
Máscara de bits que especifica qué campos de la estructura están configurados.
MLX5DV_DEK_INIT_ATTR_CRYPTO_LOGIN
El campo crypto_login de la estructura está configurado.
crypto_login
Un puntero a un objeto de inicio de sesión de cifrado válido, que debe proporcionarse si comp_mask tiene el bit MLX5DV_DEK_INIT_ATTR_CRYPTO_LOGIN establecido. Si este puntero es NULL y el bit está establecido, se crea una DEK en texto plano.

VALOR DE RETORNO

En caso de éxito, mlx5dv_dek_create() devuelve un puntero a la DEK creada. En caso de error, devuelve NULL.

En caso de éxito, mlx5dv_dek_query() y mlx5dv_dek_destroy() devuelven 0. En caso de error, devuelven un valor distinto de cero.

VER TAMBIÉN

ibv_alloc_pd(3), ibv_destroy_pd(3), mlx5dv_crypto_login_create(3)

comp_mask

Bitmask to specify which fields in the structure are valid.

Currently can be the following value:

MLX5DV_DEK_INIT_ATTR_CRYPTO_LOGIN, which indicates that crypto_login field is applicable.

crypto_login
Pointer to a crypto login object. If set to a valid crypto login object, indicates that this is a wrapped DEK that will be created using the given crypto login object. If set to NULL, indicates that this is a plaintext DEK. Must be NULL if MLX5DV_DEK_INIT_ATTR_CRYPTO_LOGIN is not set. Only relevant when comp_mask is set with MLX5DV_DEK_INIT_ATTR_CRYPTO_LOGIN

dek

Pointer to an existing DEK to query or to destroy.

attr

DEK attributes to be populated when querying a DEK.

struct mlx5dv_dek_attr {
    enum mlx5dv_dek_state state;
    char opaque[8];
    uint64_t comp_mask;
};
state
The state of the DEK, can be one of the following
MLX5DV_DEK_STATE_READY
The key is ready for use. This is the state of the key when it is first created.
MLX5DV_DEK_STATE_ERROR
The key is unusable. The key needs to be destroyed and re-created in order to be used. This can happen, for example, due to DEK memory corruption.
opaque
Plaintext metadata to describe the key.
comp_mask
Reserved for future extension, must be 0 now.

VALOR DE RETORNO

mlx5dv_dek_create() devuelve un puntero a una nueva struct mlx5dv_dek en caso de éxito. En caso de error, devuelve NULL y se establece errno.

mlx5dv_dek_query() devuelve 0 en caso de éxito y actualiza attr con los atributos del DEK consultado. En caso de error, devuelve el valor de errno.

mlx5dv_dek_destroy() devuelve 0 en caso de éxito y el valor de errno en caso de error.

VER TAMBIÉN

mlx5dv_crypto_login(3), mlx5dv_crypto_login_create(3), mlx5dv_query_device(3)
