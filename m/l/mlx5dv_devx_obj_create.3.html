NOMBRE

mlx5dv_devx_obj_create - Crea un objeto devx

mlx5dv_devx_obj_destroy - Destruye un objeto devx

mlx5dv_devx_obj_modify - Modifica un objeto devx

mlx5dv_devx_obj_query - Consulta un objeto devx

mlx5dv_devx_obj_query_async - Consulta un objeto devx en modo asíncrono

mlx5dv_devx_general_cmd - Emite un comando general a través de la interfaz devx

SINOPSIS

#include <infiniband/mlx5dv.h>
struct mlx5dv_devx_obj *
mlx5dv_devx_obj_create(struct ibv_context *context, const void *in, size_t inlen,
               void *out, size_t outlen);
int mlx5dv_devx_obj_query(struct mlx5dv_devx_obj *obj, const void *in, size_t inlen,
              void *out, size_t outlen);
int mlx5dv_devx_obj_query_async(struct mlx5dv_devx_obj *obj, const void *in,
                size_t inlen, size_t outlen,
                uint64_t wr_id,
                struct mlx5dv_devx_cmd_comp *cmd_comp);
int mlx5dv_devx_obj_modify(struct mlx5dv_devx_obj *obj, const void *in, size_t inlen,
               void *out, size_t outlen);
int mlx5dv_devx_obj_destroy(struct mlx5dv_devx_obj *obj);
int mlx5dv_devx_general_cmd(struct ibv_context *context, const void *in, size_t inlen,
                void *out, size_t outlen);

DESCRIPCIÓN

Crea / destruye / modifica / consulta un objeto devx, emite un comando general a través de la interfaz devx.

La API DEVX permite el acceso directo desde el espacio de usuario al controlador de dispositivos mlx5 utilizando el mecanismo KABI. El propósito principal es hacer que el controlador del espacio de usuario sea lo más independiente posible del kernel, de modo que las funcionalidades y comandos futuros del dispositivo puedan activarse con cambios mínimos o nulos en el kernel.

Un objeto DEVX representa algún objeto de firmware subyacente, el comando de entrada para crearlo son datos brutos proporcionados por la aplicación de usuario que deben coincidir con la especificación del dispositivo. Tras la creación exitosa, el búfer de salida incluye los datos brutos del dispositivo según su especificación; estos datos pueden utilizarse como parte de comandos de firmware relacionados con este objeto.

Una vez creado el objeto DEVX, puede ser consultado/modificado/destruido por la API mlx5dv_devx_obj_xxx() correspondiente. Tanto la entrada como la salida para estas APIs deben coincidir también con la especificación del dispositivo.

La API mlx5dv_devx_general_cmd() permite emitir un comando general que no está relacionado con un objeto, como la consulta de las capacidades del dispositivo.

La API mlx5dv_devx_obj_query_async() es similar a la API de consulta de objetos, sin embargo, se ejecuta de forma asíncrona sin bloqueo. La entrada incluye un objeto mlx5dv_devx_cmd_comp y un identificador llamado `wr_id' para este comando. La respuesta debe leerse tras el éxito con la API mlx5dv_devx_get_async_cmd_comp(). El `wr_id' que se proporcionó como entrada se devuelve como parte de la respuesta para que la aplicación sepa a qué comando está relacionada la respuesta.

Una aplicación puede migrar gradualmente al uso de DEVX según sus necesidades, no es todo o nada. Por ejemplo, puede crear un ibv_cq a través del verbo ibv_create_cq() y luego usar el cqn devuelto para crear un objeto DEVX QP mediante la API mlx5dv_devx_obj_create() que necesita ese cqn.

El ejemplo anterior puede permitir a una aplicación crear un QP con algunos atributos específicos del controlador que no se exponen en la API ibv_create_qp(), en cuyo caso no puede ser necesario ningún cambio en el usuario o en el kernel, ya que el comando de entrada llega directamente al firmware.

Los usuarios esperados para las APIs DEVX son aplicaciones que utilizan las APIs mlx5 DV y están familiarizadas con la especificación del dispositivo tanto en la ruta de control como en la de datos.

Para crear con éxito un objeto DEVX y trabajar con él, se debe crear un contexto DEVX, esto se hace mediante la API mlx5dv_open_device() con la bandera MLX5DV_CONTEXT_FLAGS_DEVX.

ARGUMENTOS

context
Contexto del dispositivo RDMA para crear la acción.
in
Un búfer que contiene los datos de entrada del comando proporcionados en un formato de especificación del dispositivo.
inlen
El tamaño del búfer in en bytes.
out
Un búfer que contiene los datos de salida del comando según el formato de especificación del dispositivo.
outlen
El tamaño del búfer out en bytes.
obj
Para consulta, modificación, destrucción: el objeto devx sobre el que operar.
wr_id
El identificador del comando cuando se trabaja en modo asíncrono.
cmd_comp
El objeto de finalización del comando para leer la respuesta en modo asíncrono.

VALOR DE RETORNO

En caso de éxito, mlx5dv_devx_create_obj devolverá un nuevo struct mlx5dv_devx_obj; en caso de error, se devolverá NULL y se establecerá errno.

En caso de éxito en las consultas, modificaciones, destrucciones y comandos generales, se devuelve 0 o el valor de errno en caso de fallo.

Si el valor de error es EREMOTEIO, outbox.status y outbox.syndrome contendrán los detalles del fallo del comando.

VER TAMBIÉN

mlx5dv_open_device, mlx5dv_devx_create_cmd_comp, mlx5dv_devx_get_async_cmd_comp
