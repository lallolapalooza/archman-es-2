mlx5dv_devx_get_event(3) Manual de funciones de biblioteca mlx5dv_devx_get_event(3)

NOMBRE

mlx5dv_devx_get_event - Obtener un evento asíncrono.

SINOPSIS

#include <infiniband/mlx5dv.h>
struct mlx5dv_devx_async_event_hdr {
    uint64_t    cookie;
    uint8_t     out_data[];
};
ssize_t mlx5dv_devx_get_event(struct mlx5dv_devx_event_channel *event_channel,
                              struct mlx5dv_devx_async_event_hdr *event_data,
                              size_t event_resp_len)

DESCRIPCIÓN

Obtiene un evento del dispositivo en el event_channel proporcionado. Después de una suscripción exitosa a través del canal de eventos llamando a mlx5dv_devx_subscribe_devx_event(), la aplicación debe utilizar esta API para obtener la respuesta una vez que ha ocurrido un evento.

Tras la respuesta, se devuelve la cookie que se proporcionó durante la suscripción y out_data incluye los datos en sí. out_data puede omitirse en caso de que el canal se haya creado con la bandera de omitir datos.

La aplicación debe proporcionar un búfer lo suficientemente grande como para contener el evento según la especificación del dispositivo; el tamaño del búfer se proporciona mediante el parámetro de entrada event_resp_len.

ARGUMENTOS

event_channel
El canal a través del cual obtener el evento.
event_data
Los datos de salida del evento asíncrono.
event_resp_len
El tamaño del búfer de salida para contener la respuesta.

VALOR DE RETORNO

En caso de éxito, mlx5dv_devx_get_event devolverá el número de bytes leídos; de lo contrario, se devolverá -1 y errno se habrá establecido.

NOTAS

En caso de que el event_channel se haya creado con la bandera de omitir datos, los eventos del mismo tipo pueden combinarse por suscripción y reportarse una vez con la cookie correspondiente. En ese modo de trabajo, el orden no se conserva entre esos eventos y otros en este canal.

Por otro lado, cuando cada evento debe contener los datos del dispositivo, se conserva el orden, sin embargo, los eventos pueden perderse debido a la falta de memoria del kernel, en cuyo caso se reportará EOVERFLOW.

VER TAMBIÉN

mlx5dv_open_device(3), mlx5dv_devx_subscribe_devx_event(3)
