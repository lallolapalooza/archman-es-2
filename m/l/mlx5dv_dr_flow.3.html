DESCRIPCIÓN

La API de Reglas Directas (mlx5dv_dr_*) permite el acceso completo de la aplicación de verbos a la funcionalidad de direccionamiento de paquetes del dispositivo.

Las reglas de flujo de direccionamiento son la combinación de atributos con un patrón de coincidencia y una lista de acciones. Las reglas pueden tener varias acciones distintas (como contar, encapsular, desencapsular antes de redirigir paquetes a una cola o puerto específico, etc.). Para gestionar el orden de ejecución de las reglas para la coincidencia del procesamiento de paquetes por parte del hardware (HW), se definen múltiples tablas de flujo en una cadena ordenada y múltiples comparadores de flujo ordenados por prioridades.

Dominio

mlx5dv_dr_domain_create() crea un objeto de dominio DR para ser utilizado con mlx5dv_dr_table_create() y mlx5dv_dr_action_create_*().

Un dominio debe ser destruido llamando a mlx5dv_dr_domain_destroy() una vez que todos los recursos dependientes sean liberados.

El dispositivo soporta los siguientes tipos de dominios:

MLX5DV_DR_DOMAIN_TYPE_NIC_RX Gestiona paquetes Ethernet recibidos en la NIC. Los paquetes en este dominio pueden ser descartados, enviados a QPs, modificados o redirigidos a tablas adicionales dentro del dominio. Comportamiento por defecto: Descartar paquete.

MLX5DV_DR_DOMAIN_TYPE_NIC_TX Gestiona paquetes Ethernet transmitidos por la NIC. Los paquetes en este dominio pueden ser descartados, modificados o redirigidos a tablas adicionales dentro del dominio. Comportamiento por defecto: Reenviar paquete al vport de la NIC (a eSwitch o al cable).

MLX5DV_DR_DOMAIN_TYPE_FDB Gestiona paquetes Ethernet en la Base de Datos de Reenvío del eSwitch para paquetes recibidos desde el cable o desde cualquier otro vport. Los paquetes en este dominio pueden ser descartados, enviados a un vport, modificados o redirigidos a tablas adicionales dentro del dominio. Comportamiento por defecto: Reenviar paquete al vport gestor del eSwitch.

mlx5dv_dr_domain_sync() se utiliza para vaciar la cola de envío de reglas. Por defecto, las reglas en un dominio se actualizan en el HW de forma asíncrona

Sincrónicamente. flags debe ser un conjunto de tipo enum mlx5dv_dr_domain_sync_flags:

MLX5DV_DR_DOMAIN_SYNC_FLAGS_SW: bloquea hasta la finalización de todas las tareas puestas en cola por software.

MLX5DV_DR_DOMAIN_SYNC_FLAGS_HW: borra la caché de hardware de dirección para forzar que el próximo paquete coincida con las últimas reglas, además del manejo de SYNC de SW.

MLX5DV_DR_DOMAIN_SYNC_FLAGS_MEM: sincroniza la memoria del dispositivo para liberar la memoria cacheada.

mlx5dv_dr_domain_set_reclaim_device_memory() se utiliza para habilitar la recuperación de memoria del dispositivo hacia el sistema cuando no está en uso, por defecto esta característica está deshabilitada.

mlx5dv_dr_domain_allow_duplicate_rules() se utiliza para permitir o evitar la inserción de reglas que coinciden en los mismos campos (duplicados) en tablas no raíz, por defecto esta característica está permitida.

Tabla

mlx5dv_dr_table_create() crea una tabla DR en el domain, en el level apropiado, y puede ser utilizada con mlx5dv_dr_matcher_create(), mlx5dv_dr_action_create_dest_table() y mlx5dv_dr_action_create_dest_root_table. Todos los paquetes comienzan a recorrer el árbol del dominio de direccionamiento en la tabla de level cero (0). Usando reglas y acciones, los paquetes pueden ser redirigidos a otras tablas en el dominio.

Una tabla debe ser destruida llamando a mlx5dv_dr_table_destroy() una vez que todos los recursos dependientes hayan sido liberados.

Matcher

mlx5dv_dr_matcher_create() crea un objeto matcher en table, con una priority ordenada (un valor más bajo se verifica primero). Un matcher puede contener múltiples reglas, todas con una mask idéntica de tipo struct mlx5dv_flow_match_parameters que representa los atributos exactos a comparar por el direccionamiento HW. El match_criteria_enable y la mask se definen en un formato de especificación del dispositivo. Solo los campos que fueron enmascarados en el matcher deben ser completados por la regla en mlx5dv_dr_rule_create().

Un matcher debe ser destruido llamando a mlx5dv_dr_matcher_destroy() una vez que todos los recursos dependientes hayan sido liberados.

mlx5dv_dr_matcher_set_layout() se utiliza para establecer parámetros de diseño específicos de un matcher, en algunas condiciones, la configuración de algunos atributos puede no ser compatible, en tales casos se devolverá ENOTSUP. flags debe ser un conjunto de tipo enum mlx5dv_dr_matcher_layout_flags:

MLX5DV_DR_MATCHER_LAYOUT_RESIZABLE: El matcher puede redimensionar su escala y recursos de acuerdo con las reglas que se insertan o eliminan.

MLX5DV_DR_MATCHER_LAYOUT_NUM_RULE: Indica una pista de la aplicación sobre el número de reglas que se espera que maneje el matcher. Esto permite la preasignación de recursos del matcher para actualizaciones de reglas más rápidas cuando se usa con el modo de diseño no redimensionable.

Acciones

Un conjunto de API de creación de acciones se define por mlx5dv_dr_action_create_*(). Todas las acciones se crean como struct mlx5dv_dr_action. Una acción debe ser destruida llamando a mlx5dv_dr_action_destroy() una vez que todas las reglas dependientes hayan sido destruidas.

Cuando se reutiliza un manejador de acción para múltiples reglas, se ejecutará la misma acción. por ejemplo: la acción `count' contará múltiples flujos de reglas en el mismo contexto de contador de flujo HW. la acción `drop' descartará paquetes de diferentes reglas de cualquier matcher.

Acción: Descartar mlx5dv_dr_action_create_drop crea una acción de terminación que descarta paquetes. No se puede mezclar con acciones de Destino.

Acción: Fallo por defecto mlx5dv_dr_action_create_default_miss crea una acción de terminación que ejecutará el comportamiento por defecto basado en el tipo de dominio.

Acción: Etiqueta mlx5dv_dr_action_create_tag crea una acción no terminante que etiqueta paquetes con tag_value. El tag_value está disponible en el CQE del paquete recibido. Válido solo en el tipo de dominio NIC_RX.

Acción: Destino mlx5dv_dr_action_create_dest_ibv_qp crea una acción de terminación que entrega el paquete a un QP, definido por ibqp. Válido solo en el tipo de dominio NIC_RX. mlx5dv_dr_action_create_dest_table crea una acción de reenvío a otra tabla de flujo, definida por table. La table de destino debe ser del mismo dominio con un nivel superior a cero. mlx5dv_dr_action_create_dest_root_table crea una acción de reenvío a otra prioridad dentro de una tabla de flujo raíz, definida por table y priority. mlx5dv_dr_action_create_dest_vport crea una acción de reenvío a un vport en el mismo domain. Válido solo en el tipo de dominio FDB. mlx5dv_dr_action_create_dest_ib_port crea una acción de reenvío a un ib_port en el mismo domain. El rango válido de puertos se basa en la capacidad phys_port_cnt_ex proporcionada por ibq_query_device_ex y es posible consultar los detalles de los puertos usando mlx5dv_query_port. La acción solo es compatible con el tipo de dominio FDB. mlx5dv_dr_action_create_dest_devx_tir crea una acción de terminación que entrega el paquete a un TIR, definido por devx_obj. Válido solo en el tipo de dominio NIC_RX.

Acción: Array mlx5dv_dr_action_create_dest_array crea una acción que replica un paquete a múltiples destinos. num_dest define el número de destinos de replicación. Cada entrada de destino dests puede ser de diferente type. Utilice el tipo MLX5DV_DR_ACTION_DEST para reenvío directo a un destino de acción. Utilice el tipo MLX5DV_DR_ACTION_DEST_REFORMAT cuando se deba realizar una acción de reformato en el paquete antes de que sea reenviado al destino de acción.

Acción: Reformateo de Paquete mlx5dv_dr_action_create_packet_reformat crea un contexto y acción de reformateo de paquete en el domain. El reformat_type, data_sz y data se definen en man mlx5dv_create_flow_action_packet_reformat.

Acción: Modificar Encabezado mlx5dv_dr_action_create_modify_header crea un contexto y acción de modificación de encabezado en el domain. El actions_sz y actions se definen en man mlx5dv_create_flow_action_modify_header.

Acción: Contador de Flujo mlx5dv_dr_action_create_flow_counter crea una acción de contador de flujo a partir de un objeto contador de flujo DEVX, basado en devx_obj y un índice de contador específico de offset en el bloque del contador.

Acción: ASO mlx5dv_dr_action_create_aso recibe un puntero a domain y crea una acción ASO a partir del objeto ASO DEVX, basado en devx_obj. Utilice offset para seleccionar el objeto ASO específico en el bloque devx_obj. Las reglas DR que utilizan esta acción pueden actualizar opcionalmente el valor del objeto ASO de acuerdo con flags para elegir el comportamiento específico deseado de este objeto. Después de que un paquete golpee la regla con el objeto ASO, el valor del objeto ASO se copiará en el return_reg_c elegido, que puede ser usado para coincidencias en reglas DR posteriores.

mlx5dv_dr_action_modify_aso modifica la acción ASO action con nuevos valores para offset, return_reg_c y flags. Solo las nuevas reglas DR que utilicen esta action usarán los valores modificados. Las reglas DR existentes no cambian los valores de acción HW almacenados.

flags puede establecerse en uno de los tipos de mlx5dv_dr_action_aso_first_hit_flags o mlx5dv_dr_action_aso_flow_meter_flags o mlx5dv_dr_action_aso_ct_flags: MLX5DV_DR_ACTION_ASO_FIRST_HIT_FLAGS_SET: se utiliza para establecer el contexto del objeto de primer golpe ASO, de lo contrario, el contexto solo se copia en el return_reg_c. MLX5DV_DR_ACTION_FLAGS_ASO_FLOW_METER_RED: se utiliza para indicar la actualización del color inicial en el valor del objeto del medidor de flujo ASO a rojo. MLX5DV_DR_ACTION_FLAGS_ASO_FLOW_METER_YELLOW: se utiliza para indicar la actualización del color inicial en el valor del objeto del medidor de flujo ASO a amarillo. MLX5DV_DR_ACTION_FLAGS_ASO_FLOW_METER_GREEN: se utiliza para indicar la actualización del color inicial en el valor del objeto del medidor de flujo ASO a verde. MLX5DV_DR_ACTION_FLAGS_ASO_FLOW_METER_UNDEFINED: se utiliza para indicar la actualización del color inicial en el valor del objeto del medidor de flujo ASO a indefinido. MLX5DV_DR_ACTION_FLAGS_ASO_CT_DIRECTION_INITIATOR: se utiliza para indicar la dirección de la conexión TCP en la que se envió el paquete SYN. MLX5DV_DR_ACTION_FLAGS_ASO_CT_DIRECTION_RESPONDER: se utiliza para indicar la dirección de la conexión TCP en la que se envió el paquete SYN-ACK.

Acción: Medidor mlx5dv_dr_action_create_flow_meter crea una acción de medidor basada en los parámetros del medidor de flujo. Los parámetros están de acuerdo con la especificación del dispositivo. mlx5dv_dr_action_modify_flow_meter modifica el action del medidor de flujo existente basado en modify_field_select. modify_field_select está de acuerdo con la especificación del dispositivo.

Acción: Muestreador mlx5dv_dr_action_create_flow_sampler crea una acción de muestreador, permitiéndonos duplicar y muestrear una porción del tráfico. Los paquetes dirigidos a la acción de muestreador serán muestreados con una probabilidad aproximada de 1/sample_ratio proporcionada en attr, y las sample_actions proporcionadas en attr se ejecutarán sobre ellos. Todos los paquetes originales serán dirigidos a la tabla predeterminada next_table en attr. Se puede proporcionar un formato de encabezado de modificación SET_ACTION en la acción de attr, que puede ejecutarse en los paquetes antes de ir a la tabla de flujo predeterminada. En algunos dispositivos, esto es necesario para establecer el valor del registro.

Flags de Acción: la acción flags puede establecerse en uno de los tipos de enum mlx5dv_dr_action_flags:

Acción: Pop VLAN mlx5dv_dr_action_create_pop_vlan crea una acción pop vlan que elimina etiquetas VLAN de la capa 2 de los paquetes.

Acción: Push VLAN mlx5dv_dr_action_create_push_vlan crea una acción push vlan que agrega etiquetas VLAN a la capa 2 de los paquetes.

MLX5DV_DR_ACTION_FLAGS_ROOT_LEVEL: se utiliza para indicar que la acción está dirigida a la tabla de flujo en el nivel=0 (RAÍZ) del dominio específico.

Regla

mlx5dv_dr_rule_create() crea una entrada de regla de direccionamiento HW en matcher. El value de tipo struct mlx5dv_flow_match_parameters contiene los valores de atributo exactos de la regla de direccionamiento a coincidir, en un formato de especificación del dispositivo. Solo los campos que fueron enmascarados en el matcher deben ser completados. HW realizará el conjunto de num_actions del array action de tipo struct mlx5dv_dr_action, una vez que un paquete coincida con el value exacto de la regla (denominado `hit').

mlx5dv_dr_rule_destroy() destruye la regla.

Otro

mlx5dv_dr_aso_other_domain_link() vincula el objeto ASO devx, devx_obj, a un dominio dmn, esto permitirá crear una regla con acción ASO utilizando el objeto dado en el dominio vinculado dmn. mlx5dv_dr_flow.3.en — rdma-core 60.0-2

DESCRIPTION

The DR (Direct Rule) API allows offloading steering rules from the host to the network adapter. This is achieved by defining flow tables, matchers, actions, and rules. The API is based on the mlx5 driver model and exposes specific objects like tables, matchers, actions, and rules.

The main objects are:

  • Table: A container for matchers and rules. The flow table type (ft_type) determines the structure and capabilities of the table. Possible values for ft_type include, but are not limited to:
    • MLX5DV_DR_FT_CONTAINER: A general-purpose container for rules.
    • MLX5DV_DR_FT_ROOT: The root table for flow steering.
    • MLX5DV_DR_FT_CVQE: Container for CVQE (Connected Virtual Queue Entry) based flows.

The create API calls will return a pointer to the relevant object: table, matcher, action, rule.

The destroy API calls will return 0 on success, or the value of errno on failure.

mlx5dv_dr_table_create creates a new DR flow table associated with the given context. ft_type specifies the type of the flow table.

mlx5dv_dr_table_destroy destroys the specified DR flow table.

mlx5dv_dr_matcher_create creates a new DR matcher within a given DR table. priority determines the order of matching within the table. match_mask specifies which fields are considered for matching. match_flags are used to specify specific matching behaviors.

mlx5dv_dr_matcher_destroy destroys the specified DR matcher.

mlx5dv_dr_action_create_* functions create various types of DR actions:

  • mlx5dv_dr_action_create_dest_table: Sets the destination for a matched flow to another DR table.
  • mlx5dv_dr_action_create_dest_tire: Sets the destination for a matched flow to a TIRE (Traffic Identification Rule Element).
  • mlx5dv_dr_action_create_tag: Associates a tag with the matched flow.
  • mlx5dv_dr_action_create_packet_box: Modifies packet headers based on provided mask, offset, and size.
  • mlx5dv_dr_action_create_flow_counter: Increments a flow counter. counter_type and counter_index specify the counter to use.
  • mlx5dv_dr_action_create_aso_entry: Links an ASO (Advanced Steering Object) entry to the flow.

mlx5dv_dr_action_destroy destroys the specified DR action.

mlx5dv_dr_rule_create creates a new DR rule within a given DR matcher. match_val provides the actual values to match against the mask. actions is an array of DR actions to perform when the rule matches.

mlx5dv_dr_rule_destroy destroys the specified DR rule.

mlx5dv_dr_rule_modify_actions modifies the actions associated with an existing rule.

mlx5dv_dr_rule_modify_match_val modifies the match values of an existing rule.

mlx5dv_dr_aso_create creates an ASO DevX object. ctx is the DR context. peer_dmn is the domain that the ASO devx object was created on. dmn is the domain that ASO devx object will be linked to. flags choose the specific wanted behavior of this object according to the flags, same as for ASO action creation flags. regc_index After a packet hits the rule with the ASO object the value of the ASO object will be copied into the regc register indicated by this param, and then we can use the value for matching in the following DR rules.

mlx5dv_dr_aso_destroy destroys the specified ASO DevX object.

mlx5dv_dr_aso_other_domain_unlink will unlink the devx_obj from the linked dmn. dmn is the domain that ASO devx object is linked to.

RETURN VALUE

The create API calls will return a pointer to the relevant object: table, matcher, action, rule. on failure, NULL will be returned and errno will be set.

The destroy API calls will returns 0 on success, or the value of errno on failure (which indicates the failure reason).

LIMITATIONS

Application can verify is a feature is supported by trail and error. No capabilities are exposed, as the combination of all the options exposed are way to large to define.

Tables are size less by definition. They are expected to grow and shrink to accommodate for all rules, according to driver capabilities. Once reaching a limit, an error is returned.

Matchers in same priority, in the same table, will have undefined ordered.

A rule with identical value pattern to another rule on a given matcher are rejected.

IP version in matcher mask and rule should be equal and set to 4, 6 or 0. # SEE ALSO

mlx5dv_open_device(3), mlx5dv_create_flow_action_packet_reformat(3), mlx5dv_create_flow_action_modify_header(3).
