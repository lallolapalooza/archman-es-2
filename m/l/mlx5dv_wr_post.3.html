NOMBRE

mlx5dv_wr_set_dc_addr - Adjuntar información de DC a la última solicitud de trabajo

mlx5dv_wr_raw_wqe - Construir una solicitud de trabajo cruda

mlx5dv_wr_memcpy - Construir una solicitud de trabajo memcpy DMA

SINOPSIS

#include <infiniband/mlx5dv.h>
static inline void mlx5dv_wr_set_dc_addr(struct mlx5dv_qp_ex *mqp,
                                         struct ibv_ah *ah,
                                         uint32_t remote_dctn,
                                         uint64_t remote_dc_key);
static inline void mlx5dv_wr_set_dc_addr_stream(struct mlx5dv_qp_ex *mqp,
                        struct ibv_ah *ah,
                        uint32_t remote_dctn,
                        uint64_t remote_dc_key,
                        uint16_t stream_id);
struct mlx5dv_mr_interleaved {
    uint64_t        addr;
    uint32_t        bytes_count;
    uint32_t        bytes_skip;
    uint32_t        lkey;
};
static inline void mlx5dv_wr_mr_interleaved(struct mlx5dv_qp_ex *mqp,
                        struct mlx5dv_mkey *mkey,
                        uint32_t access_flags, /* usar enum ibv_access_flags */
                        uint32_t repeat_count,
                        uint16_t num_interleaved,
                        struct mlx5dv_mr_interleaved *data);
static inline void mlx5dv_wr_mr_list(struct mlx5dv_qp_ex *mqp,
                      struct mlx5dv_mkey *mkey,
                      uint32_t access_flags, /* usar enum ibv_access_flags */
                      uint16_t num_sges,
                      struct ibv_sge *sge);
static inline int mlx5dv_wr_raw_wqe(struct mlx5dv_qp_ex *mqp, const void *wqe);
static inline void mlx5dv_wr_memcpy(struct mlx5dv_qp_ex *mqp_ex,
                    uint32_t dest_lkey, uint64_t dest_addr,
                    uint32_t src_lkey, uint64_t src_addr,
                    size_t length)

DESCRIPCIÓN

Las APIs de solicitud de trabajo MLX5DV (mlx5dv_wr_*) son una extensión de la API de solicitud de trabajo IBV (ibv_wr_*) con características específicas de mlx5 para solicitudes de trabajo de envío. Esto puede usarse junto o sin llamadas ibv_wr_*.

USO

Para usar estas APIs, se debe crear un QP usando mlx5dv_create_qp() con send_ops_flags de struct ibv_qp_init_attr_ex establecido.

Si el QP no soporta todos los tipos de solicitud de trabajo solicitados, la creación del QP fallará.

El mlx5dv_qp_ex se extrae del IBV_QP mediante ibv_qp_to_qp_ex() y mlx5dv_qp_ex_from_ibv_qp_ex(). Esto debe usarse para aplicar las características específicas de mlx5 en el WR publicado.

La creación de una solicitud de trabajo requiere el uso de ibv_qp_ex como se describe en el manual para ibv_wr_post y mlx5dv_qp con sus constructores y establecedores disponibles.

Constructores específicos de QP

QPs RC
mlx5dv_wr_mr_interleaved()

registra un diseño de memoria intercalado utilizando una mkey indirecta y algunos datos intercalados. El diseño de la memoria apuntada por la mkey después de su registro será la representación de datos para las entradas num_interleaved. Esta representación de diseño única se repite por repeat_count.

Los datos descritos por struct mlx5dv_mr_interleaved contendrán datos reales definidos por bytes_count y luego un relleno de bytes_skip. Después de un registro exitoso, las operaciones RDMA pueden usar esta mkey. El hardware dispersará los datos de acuerdo con el patrón. La mkey debe usarse en modo de base cero. El campo addr en su ibv_sge es un desplazamiento en los datos totales. Para crear esta mkey, se debe usar mlx5dv_create_mkey().

La implementación actual requiere que la opción IBV_SEND_INLINE esté activada en el campo ibv_qp_ex->wr_flags. Para poder tener más de 3 entradas num_interleaved, el QP debe crearse con un tamaño de WQE más grande que pueda caber. Esto debe hacerse usando el atributo max_inline_data de struct ibv_qp_cap en el momento de su creación.

Como se consumirá una entrada para la cabecera escalonada, la mkey debe crearse con una entrada más que el num_interleaved requerido.

En caso de que ibv_qp_ex->wr_flags active IBV_SEND_SIGNALED, el opcode WC reportado será MLX5DV_WC_UMR. La anulación del registro de la mkey para permitir el registro de otro patrón debe hacerse a través de ibv_post_send con el opcode IBV_WR_LOCAL_INV.

mlx5dv_wr_mr_list()

registra un diseño de memoria basado en una lista de ibv_sge. El diseño de la memoria apuntada por la mkey después de su registro se basará en la lista de sge contada por num_sges. Después de un registro exitoso, las operaciones RDMA pueden usar esta mkey, el hardware dispersará los datos de acuerdo con el patrón. La mkey debe usarse en modo de base cero, el campo addr en su ibv_sge es un desplazamiento en los datos totales.

La implementación actual requiere que la opción IBV_SEND_INLINE esté activada en el campo ibv_qp_ex->wr_flags. Para poder tener más de 4 entradas num_sge, el QP debe crearse con un tamaño de WQE más grande que pueda caber. Esto debe hacerse usando el atributo max_inline_data de struct ibv_qp_cap en el momento de su creación.

En caso de que ibv_qp_ex->wr_flags active IBV_SEND_SIGNALED, el opcode WC reportado será MLX5DV_WC_UMR. La anulación del registro de la mkey para permitir el registro de otro patrón debe hacerse a través de ibv_post_send con el opcode IBV_WR_LOCAL_INV.

QPs RC o DCI
mlx5dv_wr_memcpy()

Construye una solicitud de trabajo memcpy DMA para copiar datos de longitud length desde src_addr a dest_addr. La operación de copia se realizará utilizando la funcionalidad DMA MMO del dispositivo para copiar datos en el bus PCI.

La bandera MLX5DV_QP_EX_WITH_MEMCPY en mlx5dv_qp_init_attr.send_ops_flags debe establecerse durante la creación del QP. Si el dispositivo o el QP no lo soportan, la creación del QP fallará. La longitud máxima de memcpy soportada por el dispositivo se informa en mlx5dv_context->max_wr_memcpy_length. Un valor cero en mlx5dv_context->max_wr_memcpy_length significa que el dispositivo no soporta operaciones memcpy.

El indicador IBV_SEND_FENCE debe usarse en una solicitud de envío posterior que dependa de dest_addr de la operación memcpy.

En caso de que ibv_qp_ex->wr_flags active IBV_SEND_SIGNALED, el opcode WC reportado será MLX5DV_WC_MEMCPY.

Constructores de WQE crudo

mlx5dv_wr_raw_wqe()
Se utiliza para construir una solicitud de trabajo personalizada (WQE) y publicarla en un QP normal. El llamante necesita establecer todos los detalles del WQE (excepto los campos 'ctrl.wqe_index' y 'ctrl.signature', que son responsabilidad del controlador establecer). La bandera MLX5DV_QP_EX_WITH_RAW_WQE en mlx5_qp_attr.send_ops_flags debe establecerse.

Las wr_flags se ignoran, ya que es responsabilidad del llamante establecer las banderas en el WQE.

Independientemente del opcode de envío, el opcode de finalización del trabajo para un WQE crudo es IBV_WC_DRIVER2.

Establecedores específicos de QP

QPs DCI
mlx5dv_wr_set_dc_addr() debe llamarse para establecer las propiedades del WR DCI. La dirección de destino del trabajo se especifica mediante ah, el número de DCT remoto se especifica mediante remote_dctn y la clave DC se especifica mediante remote_dc_key. Este establecedor está disponible cuando el transporte del QP es DCI y send_ops_flags en struct ibv_qp_init_attr_ex está establecido. Los constructores y establecedores disponibles para QP DCI son los mismos que para QP RC. El QP DCI creado con MLX5DV_QP_INIT_ATTR_MASK_DCI_STREAMS puede llamar a mlx5dv_wr_set_dc_addr_stream() para definir el stream_id de la operación para permitir que el HW elija uno de los múltiples recursos DCI concurrentes. Las llamadas a mlx5dv_wr_set_dc_addr() son equivalentes a usar stream_id=0

NAME

mlx5dv_wr_post - send work request

SYNOPSIS

/* include mlx5dv.h */

int
mlx5dv_wr_post(
    struct ibv_qp *qp,
    struct ibv_send_wr *wr,
    struct ibv_send_wr **bad_wr
);

int
mlx5dv_wr_post_send(
    struct ibv_qp_ex *qp_ex,
    struct ibv_send_wr *wr,
    struct ibv_send_wr **bad_wr
);

DESCRIPTION

The mlx5dv_wr_post and mlx5dv_wr_post_send functions are used to post a send work request (WR) to a queue pair (QP). These functions are extensions provided by the MLX5 driver to allow posting WRs with advanced features not supported by the standard libibverbs API. mlx5dv_wr_post_send is an alias for mlx5dv_wr_post, but it takes a struct ibv_qp_ex as input to align with other extended API functions.

The mlx5dv_wr_post function posts a single send WR. The wr argument is a pointer to the work request to be posted. The bad_wr argument is a pointer to a pointer that will be set to the first WR in the list that failed to be posted, if an error occurs.

The mlx5dv_wr_post and mlx5dv_wr_post_send functions support advanced features such as Direct Connection (DC) QPs, which are typically used for RDMA operations between hosts within a data center. These advanced features are configured using the extended attributes of the QP and WR structures, accessed through struct ibv_qp_ex and struct mlx5dv_wr.

The primary difference from the standard ibv_post_send(3) is the ability to use extended WR types and attributes specific to the MLX5 hardware, such as those related to DC QPs.

USAGE

To use mlx5dv_wr_post or mlx5dv_wr_post_send, you first need to create an extended QP using mlx5dv_create_qp or ibv_create_qp_ex(3), and then configure the extended WR attributes. The example below demonstrates how to post a RDMA Write WR for a DC QP.

EXAMPLE

/* create DC QP type and specify the required send opcodes */
attr_ex.qp_type = IBV_QPT_DRIVER;
attr_ex.comp_mask |= IBV_QP_INIT_ATTR_SEND_OPS_FLAGS;
attr_ex.send_ops_flags |= IBV_QP_EX_WITH_RDMA_WRITE;
attr_dv.comp_mask |= MLX5DV_QP_INIT_ATTR_MASK_DC;
attr_dv.dc_init_attr.dc_type = MLX5DV_DCTYPE_DCI;
ibv_qp *qp = mlx5dv_create_qp(ctx, attr_ex, attr_dv);
ibv_qp_ex *qpx = ibv_qp_to_qp_ex(qp);
mlx5dv_qp_ex *mqpx = mlx5dv_qp_ex_from_ibv_qp_ex(qpx);
ibv_wr_start(qpx);
/* Use ibv_qp_ex object to set WR generic attributes */
qpx->wr_id = my_wr_id_1;
qpx->wr_flags = IBV_SEND_SIGNALED;
ibv_wr_rdma_write(qpx, rkey, remote_addr_1);
ibv_wr_set_sge(qpx, lkey, local_addr_1, length_1);
/* Use mlx5 DC setter using mlx5dv_qp_ex object */
mlx5dv_wr_set_wr_dc_addr(mqpx, ah, remote_dctn, remote_dc_key);
ret = ibv_wr_complete(qpx);
