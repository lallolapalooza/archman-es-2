NOMBRE

munin-run - Un programa para ejecutar plugins de Munin desde la línea de comandos

SINOPSIS

munin-run [opciones] <plugin> [ config | autoconf | snmpconf | suggest ]

DESCRIPCIÓN

munin-run es un script para ejecutar plugins de Munin desde la línea de comandos. Es útil al depurar plugins, ya que se ejecutan en las mismas condiciones que bajo munin-node.

OPCIONES

--config <archivo_configuración>
Usa <archivo> como archivo de configuración. [/etc/munin/munin-node.conf]
--servicedir <directorio>
Usa <directorio> como directorio de plugins. [/etc/munin/plugins/]
--sconfdir <directorio>
Usa <directorio> como directorio de configuración de plugins. [/etc/munin/plugin-conf.d/]
--sconffile <archivo>
Usa <archivo> como configuración de plugin. Sobrescribe sconfdir. [indefinido]
--paranoia
Solo ejecuta plugins propiedad de root y verifica permisos. [desactivado]
--ignore-systemd-properties
No intentes detectar ni aplicar las banderas de endurecimiento configuradas localmente de la unidad de servicio "munin-node". Esta detección se omite si systemd no está habilitado. Las banderas de endurecimiento pueden causar sorpresas sutiles. Por ejemplo, "ProtectHome=yes" impide que el plugin "df" determine el estado de la partición "home". [desactivado]
--help
Ver este mensaje de ayuda.
--debug
Imprime mensajes de depuración. Los mensajes de depuración se envían a STDOUT y están precedidos por "#" (esto facilita que otras partes de munin usen munin-run y aún tengan --debug activado). Solo los errores van a STDERR.
--pidebug
Depuración de plugin. Establece la variable de entorno MUNIN_DEBUG a 1 para que los plugins puedan habilitar la depuración. [desactivado]
--version
Muestra información de la versión.

NOTAS PARA USUARIOS DE SYSTEMD

El servicio "munin-node" es iniciado normalmente por systemd a través de una definición de "munin-node.service". Algunas distribuciones habilitan configuraciones de endurecimiento en este archivo de servicio para restringir el conjunto de actividades permitidas para el proceso "munin-node". Esto puede causar diferencias sorprendentes entre el resultado de "munin-run" y el servicio real "munin-node".

Un ejemplo popular de tal restricción sorprendente es "ProtectHome=yes" combinado con el plugin "df". La restricción impide silenciosamente que el plugin determine el estado de los puntos de montaje debajo de /home.

"munin-run" intenta imitar este comportamiento de "munin-node" automáticamente. Por lo tanto, la ejecución de "munin-run df" debería proporcionar la misma salida que "echo fetch df | nc localhost munin".

Si desea depurar posibles problemas de restricciones de systemd, puede usar los parámetros "--ignore-systemd-properties" y "--debug". Las anulaciones permanentes de las propiedades de systemd se pueden configurar localmente a través de "systemctl edit munin-node". Consulte "man systemd.exec" para obtener la documentación de las propiedades de systemd.
