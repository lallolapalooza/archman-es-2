NOMBRE

munged - Demonio MUNGE

SINOPSIS

munged [OPCIÓN]...

DESCRIPCIÓN

El demonio munged es responsable de autenticar clientes MUNGE locales y de atender sus solicitudes de codificación/decodificación de credenciales.

Todos los demonios munged dentro de un dominio de seguridad comparten una clave común. Se espera que todos los hosts dentro de este dominio tengan usuarios/UIDs y grupos/GIDs comunes. La clave se utiliza para proteger criptográficamente las credenciales; se crea con el comando mungekey.

Cuando se crea una credencial, munged incrusta metadatos en ella, incluido el UID y GID efectivos del cliente solicitante (según lo determinado por munged) y la hora actual (según lo determinado por el reloj local). Luego comprime los datos, calcula un código de autenticación de mensajes, cifra los datos y codifica el resultado en base64 antes de devolver la credencial al cliente.

Cuando se valida una credencial, munged primero verifica el código de autenticación de mensajes para asegurarse de que la credencial no se haya alterado posteriormente. A continuación, comprueba las restricciones de UID/GID incrustadas para determinar si al cliente solicitante se le permite decodificarla. Luego, comprueba la hora de codificación incrustada frente a la hora actual; si esta diferencia excede el tiempo de vida incrustado, la credencial ha expirado. Finalmente, comprueba si esta credencial se ha decodificado previamente en este host; si es así, la credencial se ha reproducido. Si todas las comprobaciones son correctas, los metadatos y la carga útil de la credencial se devuelven al cliente.

OPCIONES

-h, --help
Muestra un resumen de las opciones de la línea de comandos.
-L, --license
Muestra información de la licencia.
-V, --version
Muestra información de la versión.
-f, --force
Fuerza la ejecución del demonio si es posible. Esto anula las advertencias para un socket de dominio local existente, la falta de entropía para el PRNG y los permisos inseguros de archivos/directorios. Úselo con precaución ya que anular estas advertencias puede afectar la seguridad.
-F, --foreground
Ejecuta el demonio en primer plano.
-M, --mlockall
Bloquea páginas en la memoria para evitar que el demonio sea intercambiado a disco. Esto puede evitar retrasos en la autenticación bajo presión extrema de memoria. Requiere límites de bloqueo de memoria suficientes. Consulte la sección BLOQUEO DE MEMORIA a continuación.
-s, --stop
Detiene el demonio vinculado al socket y espera a que se apague. Úselo con la opción --socket para dirigirse a un demonio vinculado a una ubicación de socket no predeterminada. Esta opción sale con un estado cero si el demonio especificado se detuvo correctamente, o un estado distinto de cero en caso contrario.
-S, --socket ruta
Especifica el socket de dominio local para la comunicación con los clientes.
-v, --verbose
Sea detallado.
--auth-server-dir directorio
Especifica un directorio alternativo en el que el demonio creará la tubería utilizada para autenticar clientes. Los permisos recomendados para este directorio son 0711. Esta opción solo es válida en plataformas donde la autenticación de clientes se realiza a través de un mecanismo de paso de descriptores de archivo.
--auth-client-dir directorio
Especifica un directorio alternativo en el que los clientes crearán el archivo utilizado para autenticarse ante el demonio. Los permisos recomendados para este directorio son 1733. Esta opción solo es válida en plataformas donde la autenticación de clientes se realiza a través de un mecanismo de paso de descriptores de archivo.
--benchmark
Deshabilita temporizadores recurrentes para reducir ruido durante la evaluación comparativa. Esto afecta al grupo de entropía PRNG, al mapeo de grupos suplementarios y al hash de repetición de credenciales. No active esta opción en producción.
--group-check-mtime booleano
Especifica si se debe comprobar la hora de modificación de /etc/group antes de actualizar el mapeo de membresía de grupos suplementarios. Si este valor no es cero, la comprobación se habilitará y el mapeo no se actualizará a menos que el archivo se haya modificado desde la última actualización.
--group-update-time segundos
Especifica el número de segundos entre actualizaciones del mapeo de membresía de grupos suplementarios; este mapeo se utiliza al restringir credenciales por GID. Un valor de 0 hace que se calcule inicialmente pero nunca se actualice (a menos que lo active una SIGHUP). Un valor de -1 lo deshabilita.
--key-file ruta
Especifica una ruta alternativa para el archivo de clave.
--listen-backlog entero
Especifica el límite de cola de espera del socket; tenga en cuenta que el núcleo puede imponer un límite inferior. Un valor de 0 utiliza el valor predeterminado del software. Un valor de -1 especifica SOMAXCONN, la longitud máxima de la cola de espera definida en <sys/socket.h>.
--log-file ruta
Especifica una ruta alternativa para el archivo de registro.
--max-ttl entero
Especifica el tiempo máximo de vida (en segundos) para las credenciales. Este valor limita el TTL tanto durante la codificación como durante la decodificación. El límite superior fijo es de 3600 segundos (1 hora); el predeterminado es 3600. Reducir este valor limitará el tiempo máximo de retención de las entradas de la caché de repetición, lo cual es viable si los relojes dentro del dominio MUNGE pueden mantenerse sincronizados con un sesgo mínimo.
--num-threads entero
Especifica el número de hilos a generar para procesar solicitudes de credenciales.
--origin dirección
Especifica la dirección de origen que se codificará en los metadatos de la credencial. Puede ser un nombre de host o una dirección IPv4; también puede ser el nombre de una interfaz de red local, en cuyo caso se utilizará la primera dirección IPv4 asignada a esa interfaz. El valor predeterminado es la dirección IPv4 del nombre de host devuelto por gethostname(). La imposibilidad de resolver la dirección provocará un error; si se anula, el origen se establecerá en la dirección nula.
--pid-file ruta
Especifica una ruta alternativa para almacenar el ID de proceso del demonio.
--seed-file ruta
Especifica una ruta alternativa para el archivo de semilla PRNG.
--syslog
Redirige los mensajes de registro a syslog cuando el demonio se ejecuta en segundo plano.
--trusted-group grupo
Especifica el nombre del grupo o GID del "grupo de confianza". Esto se utiliza para las comprobaciones de permisos en una jerarquía de directorios. Los directorios con permisos de escritura de grupo están permitidos si son propiedad del grupo de confianza (o si se establece el bit adhesivo).

BLOQUEO DE MEMORIA

La opción --mlockall bloquea páginas en la memoria para evitar el intercambio bajo presión de memoria.

El uso de memoria escala con el número de hilos de trabajo, el tamaño de las bases de datos de usuarios y grupos (cuando el mapeo de grupos suplementarios está habilitado) y la tasa de decodificación de credenciales (que hace crecer la caché de repetición).

Muchos sistemas tienen un límite de bloqueo de memoria por defecto insuficiente. Se requiere un mínimo de 16 MB para la operación básica; se recomiendan 64-256 MB para configuraciones típicas. Auméntelo de una de las siguientes maneras:

Sistemas basados en systemd

Cree /etc/systemd/system/munge.service.d/memlock.conf:

[Service]
LimitMEMLOCK=256M

Th

Reload and restart

systemctl daemon-reload
systemctl restart munge.service

Límites PAM

Agregar a /etc/security/limits.conf (valores en KB):

munge  soft  memlock  262144
munge  hard  memlock  262144

En sistemas basados en systemd, los límites PAM son ignorados para los servicios. Use la configuración de systemd en su lugar.

Entorno de shell (para pruebas)

Establecer el límite antes de iniciar munged (valor en KB):

ulimit -l 262144
munged --mlockall

Consideraciones de seguridad

La caché de repetición de caché no tiene límites y crece con la tasa de decodificación de credenciales. Las entradas de repetición se conservan hasta que las credenciales expiran según su tiempo de vida (TTL). Las credenciales tienen un TTL predeterminado de 5 minutos; los clientes pueden especificar hasta el TTL máximo configurado en el munged de codificación (1 hora por defecto, configurable mediante --max-ttl). Durante la decodificación, el TTL de la credencial se limita al TTL máximo del munged de decodificación. Cuando se especifica --mlockall, las entradas de repetición se bloquean en la memoria física.

En sistemas con usuarios locales no confiables, un atacante podría codificar credenciales con el TTL máximo (1 hora por defecto) y decodificarlas repetidamente para llenar la caché de repetición. Una vez alcanzado el límite de bloqueo de memoria, es probable que munged termine al intentar asignar memoria adicional, causando una denegación de servicio.

Utilice esta opción solo en sistemas confiables donde los usuarios locales estén controlados, o establezca el límite de bloqueo de memoria en un límite superior razonable en lugar de ilimitado. Supervise el uso de memoria bloqueada de munged en sistemas de alto volumen para asegurarse de que el límite no se alcance durante la operación normal. Reducir --max-ttl puede limitar el crecimiento de la caché de repetición, pero requiere una sincronización de reloj estricta.

SEÑALES

SIGHUP
Actualiza inmediatamente el mapeo de membresía de grupo suplementario en lugar de esperar la próxima actualización programada; este mapeo se utiliza al restringir credenciales por GID.
SIGTERM
Termina el demonio.

NOTAS

Todos los relojes dentro de un dominio de seguridad deben mantenerse sincronizados dentro de la configuración de tiempo de vida de la credencial.

Si bien munged evita que una credencial dada se decodifique en un host en particular más de una vez, nada impide que una credencial se decodifique en múltiples hosts dentro del dominio de seguridad antes de que expire.
