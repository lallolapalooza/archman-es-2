MUNGE(7) Emporio MUNGE Uid 'N' Gid MUNGE(7)

NOMBRE

munge - Resumen de MUNGE

INTRODUCCIÓN

MUNGE (MUNGE Uid 'N' Gid Emporium) es un servicio de autenticación para crear y validar credenciales de usuario. Está diseñado para ser altamente escalable para su uso en un entorno de clúster HPC. Proporciona una API portable para codificar la identidad del usuario en una credencial a prueba de manipulaciones que puede ser obtenida por un cliente no confiable y reenviada por intermediarios no confiables dentro de un ámbito de seguridad. Los clientes dentro de este ámbito pueden crear y validar credenciales sin el uso de privilegios de root, puertos reservados o métodos específicos de la plataforma.

FUNDAMENTO

La necesidad de MUNGE surgió del entorno de clúster HPC. Considere el escenario en el que un demonio local que se ejecuta en un nodo de inicio de sesión recibe una solicitud de cliente y la reenvía a demonios remotos que se ejecutan en nodos de cálculo dentro del clúster. Dado que el usuario ya ha iniciado sesión en el nodo de inicio de sesión, el demonio local solo necesita un medio confiable para determinar la UID y GID del proceso cliente. Además, los demonios remotos necesitan un mecanismo para garantizar que los datos de autenticación reenviados no se hayan alterado posteriormente.

Una solución común a este problema es usar sockets de dominio Unix para determinar la identidad del cliente local y luego reenviar esta información a hosts remotos a través de conexiones rsh confiables. Pero esto presenta varios problemas nuevos. Primero, no hay una API portable para determinar la identidad de un cliente a través de un socket de dominio Unix. Segundo, las conexiones rsh deben originarse desde un puerto reservado; el número limitado de puertos reservados disponibles en un host dado limita directamente la escalabilidad. Tercero, se requieren privilegios de root para enlazar a un puerto reservado. Finalmente, los demonios remotos no tienen medio para determinar si la identidad del cliente es auténtica. MUNGE resuelve todos estos problemas.

USO

Un proceso crea una credencial solicitándola al servicio MUNGE local, ya sea a través de la llamada a la biblioteca C munge_encode() o del ejecutable munge. La credencial codificada contiene la UID y GID del proceso de origen. Este proceso envía la credencial a otro proceso dentro del ámbito de seguridad como medio para probar su identidad. El proceso receptor valida la credencial utilizando su servicio MUNGE local, ya sea a través de la llamada a la biblioteca C munge_decode() o del ejecutable unmunge. La credencial decodificada proporciona al proceso receptor un medio confiable para determinar la UID y GID del proceso de origen. Esta información se puede utilizar para decisiones de contabilidad o control de acceso.

DETALLES

El contenido de la credencial (incluidos los datos opcionales de carga útil) se cifra con una clave compartida por todos los demonios munged dentro del ámbito de seguridad. La integridad de la credencial está garantizada por un código de autenticación de mensajes (MAC). La credencial es válida por un tiempo limitado definido por su tiempo de vida (TTL); esto presupone que los relojes dentro de un ámbito de seguridad están sincronizados. El demonio munged local realiza un seguimiento de las credenciales no expiradas para evitar ataques de repetición en un host determinado. La decodificación de una credencial se puede restringir a un ID de usuario y/o grupo específico. Los datos de carga útil se pueden utilizar para fines como incrustar la dirección del destino para garantizar que la credencial solo sea válida en un host específico. El formato interno de la credencial está codificado de manera independiente de la plataforma. Y la credencial en sí está codificada en base64 para permitir su transmisión a través de casi cualquier transporte.
