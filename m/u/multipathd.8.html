MULTIPATHD(8) Manual del Administrador del Sistema MULTIPATHD(8)

NOMBRE

multipathd - Demonio de Multipath.

SINOPSIS

multipathd [-d] [-s] [-v nivel_verbosidad] [-B] [-w]

multipathd [-v nivel_verbosidad] -kcomando

multipathd [-v nivel_verbosidad] -k

DESCRIPCIÓN

El demonio multipathd se encarga de verificar las rutas fallidas. Cuando esto ocurre, reconfigurará el mapa multipath al que pertenece la ruta, de modo que este mapa recupere su máximo rendimiento y redundancia.

Con la opción -k, multipathd actúa como una utilidad cliente que envía comandos a una instancia en ejecución del demonio multipathd (ver COMANDOS más abajo).

OPCIONES

-d
Modo en primer plano. No demonizar, e imprimir todos los mensajes en stdout y stderr.
-s
Suprimir marcas de tiempo. No prefijar los mensajes de registro con una marca de tiempo.
-v nivel
Nivel de verbosidad. Imprimir información adicional mientras se ejecuta multipathd. Un nivel de 0 significa solo imprimir errores. Un nivel de 3 o superior también imprime información de depuración.
-B
Archivo de enlaces de solo lectura. multipathd no escribirá en el archivo de enlaces user_friendly_names. Si no existe ya un user_friendly_name para un dispositivo, usará su WWID como su alias.
-kcomando
multipathd ejecuta el comando dado (ver COMANDOS más abajo). Si el comando contiene espacios en blanco o caracteres especiales del shell, debe ser entrecomillado como en multipathd -k'show topology'. No se permite espacio en blanco entre -k y la cadena de comando.

Los comandos también se pueden emitir sin usar -k. En este caso, la cadena de comando no debe estar entrecomillada. Los argumentos del comando que contengan espacios en blanco o caracteres especiales aún deben estar entrecomillados, como en multipathd show paths format "%n %w"

-k
multipathd ejecuta el shell interactivo multipathc para ingresar comandos (ver COMANDOS más abajo).
-n
IGNORADO. Use la opción find_multipaths para controlar el tratamiento de dispositivos recién detectados por multipathd. Ver multipath.conf(5).
-w
Desde el kernel 4.14 se utiliza una nueva interfaz de sondeo de eventos device-mapper para actualizar los dispositivos multipath en los dmevents. Use esta bandera para forzar el uso del antiguo método de espera de eventos, basado en la creación de un hilo separado para cada dispositivo.

COMUNICACIÓN CON MULTIPATHD

Además de la CLI de multipathd, la biblioteca libmpathcmd puede usarse para enviar comandos (ver COMANDOS más abajo) al demonio multipathd desde otros programas. Por defecto, multipathd escucha tanto en el socket de espacio de nombres abstracto @/org/kernel/linux/storage/multipathd como en el archivo de socket /run/multipathd.socket. libmpathcmd utilizará cualquiera de estos sockets para conectarse a multipathd. El archivo de socket puede ser útil para comunicarse con multipathd desde diferentes espacios de nombres, ya que puede ser montado como bind en ellos, a diferencia del socket de espacio de nombres abstracto. Multipathd aceptará comandos de list|show de cualquier usuario. Todos los demás comandos deben ser emitidos por root.

Es posible cambiar los sockets en los que escucha multipathd. Si multipathd.socket está en ejecución, multipathd utilizará los sockets en los que escucha. Se pueden definir un máximo de dos sockets por multipathd.socket, y por defecto escucha en @/org/kernel/linux/storage/multipathd y /run/multipathd.socket. Si multipathd.socket no está en ejecución, se puede configurar un único socket para escuchar estableciendo la variable de entorno MULTIPATH_SOCKET_NAME al iniciar multipathd. Esta variable de entorno también debe establecerse para que los comandos CLI de multipathd (o cualquier otro programa que utilice libmpathcmd) se conecten al demonio multipathd usando un socket no predeterminado, independientemente de si ese socket se estableció para el demonio usando multipathd.socket o la variable de entorno MULTIPATH_SOCKET_NAME.

COMANDOS

Los siguientes comandos se pueden usar en modo interactivo:
list|show paths
Mostrar las rutas que multipathd está monitoreando, y su estado.
list|show paths [raw] format $formato
Mostrar las rutas que multipathd está monitoreando, usando una cadena de formato con comodines de formato de ruta. Añadir raw eliminará las cabeceras y el relleno de alineación de la salida. Ver "Comodines de formato de ruta" más abajo.
list|show path $ruta
Mostrar si la ruta $ruta está fuera de línea o en funcionamiento.
list|show maps|multipaths
Mostrar los dispositivos multipath que multipathd está monitoreando.
list|show maps|multipaths [raw] format $formato
Mostrar el estado de todos los dispositivos multipath que multipathd está monitoreando, usando una cadena de formato con comodines de formato multipath. Añadir raw eliminará las cabeceras y el relleno de alineación de la salida. Ver "Comodines de formato multipath" más abajo.
list|show maps|multipaths status
Mostrar el estado de todos los dispositivos multipath que multipathd está monitoreando.
list|show maps|multipaths stats
Mostrar algunas estadísticas de todos los dispositivos multipath que multipathd está monitoreando.
list|show maps|multipaths topology
Mostrar la topología multipath actual. Igual que 'multipath -ll'.
list|show maps|multipaths json
Mostrar información sobre todos los dispositivos multipath en formato JSON.
list|show topology
Mostrar la topología multipath actual. Igual que 'multipath -ll'.
list|show map|multipath $map topology
Mostrar la topología de un único dispositivo multipath especificado por $map, por ejemplo 36005076303ffc56200000000000010aa. Este mapa se puede obtener de 'list maps'.
list|show map|multipath $map [raw] format $formato.
Mostrar el estado del dispositivo multipath $map, usando una cadena de formato con comodines de formato multipath. Añadir raw eliminará las cabeceras y el relleno de alineación de la salida. Ver "Comodines de formato multipath" más abajo.
list|show map|multipath $map json
Mostrar información sobre el dispositivo multipath $map en formato JSON.
list|show wildcards
Mostrar los comodines de formato utilizados en comandos interactivos que toman $formato. Ver "Comodines de formato" más abajo.
list|show config
Mostrar la configuración actualmente en uso, derivada de los valores predeterminados y los valores especificados dentro del archivo de configuración /etc/multipath.conf.
list|show config local
Mostrar la configuración actualmente en uso como show config, pero limitando la sección de dispositivos a aquellos dispositivos que están realmente presentes en el sistema.
list|show blacklist
Mostrar las reglas de lista negra actualmente en uso, derivadas de los valores predeterminados y los valores especificados dentro del archivo de configuración /etc/multipath.conf.
disable [raw] $map
Deshabilitar la administración de multipath para el dispositivo especificado por $map.
enable [raw] $map
Habilitar la administración de multipath para el dispositivo especificado por $map.
reconfigure
Releer el archivo de configuración e incorporar los cambios.
systemd request
Solicitar un reinicio del servicio systemd (si está configurado para hacerlo).
quit|exit
Salir de multipathd.

Los comandos list y show son intercambiables.

NAME

multipathd ― multipath daemon

SYNOPSIS

multipathd [ -d ] [ -f ] [ -k ] [ -s ] [ -v level ]

DESCRIPTION

multipathd is a daemon that manages multipath devices. It monitors the status of individual paths to storage devices and controls the multipath device map according to the configuration file /etc/multipath.conf.

OPTIONS

-d
Daemonize.
-f
Remove all multipath devices and exit.
-k
Do not fork. This is intended for use with systemd or other init systems that manage daemons.
-s
Read the configuration file and then exit.
-v level
Set the verbosity level. Level 0 means silent, level 1 means print all actions, level 2 means print device scan results and actions, level 3 means print all path events.

COMMUNICATING WITH MULTIPATHD

multipathd communicates with the user via a control socket, which is typically located at /var/run/multipath/control. The multipath(8) command uses this socket to send commands to the daemon.

COMMANDS

The following commands can be sent to the multipathd daemon:

daemonize
Run multipathd as a daemon.
remove all devices
Remove all multipath devices.
reconfigure
Reload the configuration file.
reconfigure sysfs
Reload sysfs attributes.
show config
Show the current multipathd configuration.
show map [ -n ] [ -l ] [ -a ] [ -p path_checker ] [ -w wildcard ] [ mapname ...]
Show multipath map information. The -n option disables alias lookup. The -l option displays all devices, including those that are not part of a multipath device. The -a option displays all devices including those that are currently offline. The -p option filters the output to only show paths using the specified path checker. The -w option filters the output to only show maps matching the specified wildcard string.
show paths [ -l ] [ -a ] [ -p path_checker ] [ -w wildcard ] [ mapname ... ]
Show multipath path information. The -l option displays all devices, including those that are not part of a multipath device. The -a option displays all devices including those that are currently offline. The -p option filters the output to only show paths using the specified path checker. The -w option filters the output to only show paths matching the specified wildcard string.
show topology [ -l ] [ -a ] [ -p path_checker ] [ -w wildcard ]
Show multipath topology information. The -l option displays all devices, including those that are not part of a multipath device. The -a option displays all devices including those that are currently offline. The -p option filters the output to only show paths using the specified path checker. The -w option filters the output to only show maps matching the specified wildcard string.
switch all devices
Switch all multipath devices to the highest priority path.
switch map [ -p path_checker ] [ -w wildcard ] mapname ...
Switch the specified multipath map(s) to the highest priority path. The -p option filters the output to only show paths using the specified path checker. The -w option filters the output to only show maps matching the specified wildcard string.
fail path ...
Mark the specified path(s) as failed.
heal path ...
Mark the specified path(s) as healed.
flush map [ -w wildcard ] mapname ...
Flush the specified multipath map(s).
flush paths [ -w wildcard ]
Flush all paths.
set policy policy [ -w wildcard ] [ mapname ...]
Set the multipath policy for the specified map(s).
set queue_depth depth [ -w wildcard ] [ mapname ...]
Set the queue depth for the specified map(s).
set pg_exclusive_lock_delay delay [ -w wildcard ] [ mapname ...]
Set the PG exclusive lock delay for the specified map(s).
set pg_type type [ -w wildcard ] [ mapname ...]
Set the PG type for the specified map(s).
set pg_interval interval [ -w wildcard ] [ mapname ...]
Set the PG interval for the specified map(s).
set checker checker [ -w wildcard ] [ mapname ...]
Set the path checker for the specified map(s).
set priority priority [ -w wildcard ] [ mapname ...]
Set the priority for the specified map(s).
set stderr_threshold threshold [ -w wildcard ] [ mapname ...]
Set the stderr threshold for the specified map(s).
set path_grouping_policy policy [ -w wildcard ] [ mapname ...]
Set the path grouping policy for the specified map(s).
set path_selector selector [ -w wildcard ] [ mapname ...]
Set the path selector for the specified map(s).
set service_time_override override [ -w wildcard ] [ mapname ...]
Set the service time override for the specified map(s).
set wwid_nodename nodename [ -w wildcard ] [ mapname ...]
Set the WWID nodename for the specified map(s).
standby [ -w wildcard ] [ mapname ...]
Put the specified multipath map(s) into standby mode.
resume [ -w wildcard ] [ mapname ...]
Resume the specified multipath map(s) from standby mode.
quit
Exit multipathd.

Format Wildcards

When displaying map or path information, the following wildcards can be used in the output format string:

%x
The WWID of the device. This is the default format string for multipath maps. The value can be reset with the 'reset map $map stats' command.
%s
The vendor/product string for the device.
%v
The array vendor string for the device.
%p
The array product string for the device.
%e
The array firmware revision string for the device.
%G
The foreign library used for the device, or -- for native device-mapper multipath devices. See "FOREIGN MULTIPATH SUPPORT" in /etc/multipath.conf(5).
%g

SYSTEMD INTEGRATION

When compiled with systemd support two systemd service files are installed, multipathd.service and multipathd.socket. If enabled, the multipathd.socket service instructs systemd to intercept the CLI command socket, so that any call to the CLI interface will start-up the daemon if required. The multipathd.service file carries the definitions for controlling the multipath daemon. The daemon itself uses the sd_notify(3) interface to communicate with systemd. The following unit keywords are recognized:

WatchdogSec=
Enables the internal watchdog from systemd. multipath will send a notification via sd_notify(3) to systemd to reset the watchdog. If specified the polling_interval and max_polling_interval settings will be overridden by the watchdog settings. Please note that systemd prior to version 207 has issues which prevent the systemd-provided watchdog from working correctly. So the watchdog is not enabled per default, but has to be enabled manually by updating the multipathd.service file.
OOMScoreAdjust=
Overrides the internal OOM adjust mechanism.
LimitNOFILE=
Overrides the max_fds configuration setting.
