munge_ctx(3)

Paquete: munge

Licencias: GPL-3.0-or-later, LGPL-3.0-or-later

MUNGE_CTX(3) MUNGE Uid 'N' Gid Emporium MUNGE_CTX(3)

NOMBRE

munge_ctx_create, munge_ctx_copy, munge_ctx_destroy, munge_ctx_strerror, munge_ctx_get, munge_ctx_set - Funciones de contexto MUNGE

SINOPSIS

#include <munge.h>

munge_ctx_t munge_ctx_create (void);

munge_ctx_t munge_ctx_copy (munge_ctx_t ctx);

void munge_ctx_destroy (munge_ctx_t ctx);

const char * munge_ctx_strerror (munge_ctx_t ctx);

munge_err_t munge_ctx_get (munge_ctx_t ctx, munge_opt_t opt, ...);

munge_err_t munge_ctx_set (munge_ctx_t ctx, munge_opt_t opt, ...);

cc `pkg-config --cflags --libs munge` -o foo foo.c

DESCRIPCIÓN

La función munge_ctx_create() crea y devuelve un nuevo contexto MUNGE, o NULL si ocurre un error.

La función munge_ctx_copy() copia el contexto ctx y devuelve un nuevo contexto MUNGE, o NULL si ocurre un error.

La función munge_ctx_destroy() destruye el contexto ctx.

La función munge_ctx_strerror() devuelve una cadena de texto descriptiva que describe el número de error MUNGE según el contexto ctx, o NULL si no existe ninguna condición de error. Esto puede proporcionar un mensaje de error más detallado que el devuelto por munge_strerror().

La función munge_ctx_get() obtiene el valor de la opción opt asociada con el contexto MUNGE ctx, almacenando el resultado en el argumento de puntero posterior. Si el resultado es una cadena, esa cadena no debe ser liberada ni modificada por el llamador.

La función munge_ctx_set() establece el valor de la opción opt asociada con el contexto MUNGE ctx, utilizando el valor del argumento posterior.

VALOR DE RETORNO

Las funciones munge_ctx_create() y munge_ctx_copy() devuelven un contexto MUNGE recién asignado, o NULL si ocurre un error.

La función munge_ctx_strerror() devuelve un puntero a una cadena de texto constante terminada en nulo, o NULL si no existe ninguna condición de error. Esta cadena no debe ser liberada ni modificada por el llamador.

Las funciones munge_ctx_get() y munge_ctx_set() devuelven EMUNGE_SUCCESS en caso de éxito, o un número de error MUNGE en caso contrario.

OPCIONES DEL CONTEXTO

Las siguientes opciones del contexto pueden ser consultadas a través de munge_ctx_get() o especificadas a través de munge_ctx_set(). El tipo que sigue a cada enumeración es el tipo de variable utilizado para el argumento posterior en munge_ctx_set(), o el tipo de variable de un puntero utilizado para el argumento posterior en munge_ctx_get().

MUNGE_OPT_CIPHER_TYPE , int
Obtiene o establece el tipo de cifrado (ver TIPOS DE CIFRADO).
MUNGE_OPT_MAC_TYPE , int
Obtiene o establece el tipo de MAC (ver TIPOS DE MAC).
MUNGE_OPT_ZIP_TYPE , int
Obtiene o establece el tipo de compresión (ver TIPOS DE COMPRESIÓN).
MUNGE_OPT_REALM , char *
Obtiene o establece el reino de seguridad, donde el tipo char * es una cadena de caracteres terminada en nulo. La cadena devuelta por munge_ctx_get() no debe ser liberada ni modificada por el llamador. NO SOPORTADO ACTUALMENTE.
MUNGE_OPT_TTL , int
Obtiene o establece el tiempo de vida (en segundos) (ver TIPOS DE TTL). Este valor controla cuánto tiempo es válida la credencial una vez que ha sido codificada.
MUNGE_OPT_ADDR4 , struct in_addr
Obtiene la dirección IPv4 del host donde se codificó la credencial. Esta opción no se puede establecer explícitamente.
MUNGE_OPT_ENCODE_TIME , time_t
Obtiene la hora (en segundos desde la época) en que se codificó la credencial. Esta opción no se puede establecer explícitamente.
MUNGE_OPT_DECODE_TIME , time_t
Obtiene la hora (en segundos desde la época) en que se decodificó la credencial. Esta opción no se puede establecer explícitamente.
MUNGE_OPT_SOCKET , char *
Obtiene o establece el socket de dominio local para la conexión con munged, donde el tipo char * es una cadena de caracteres terminada en nulo. La cadena devuelta por munge_ctx_get() no debe ser liberada ni modificada por el llamador.
MUNGE_OPT_UID_RESTRICTION , uid_t
Obtiene o establece el UID permitido para decodificar la credencial (ver TIPOS DE UID Y GID). Este valor se comparará con el ID de usuario efectivo del proceso que solicita la decodificación de la credencial.
MUNGE_OPT_GID_RESTRICTION , gid_t
Obtiene o establece el GID permitido para decodificar la credencial (ver TIPOS DE UID Y GID). Este valor se comparará con el ID de grupo efectivo del proceso que solicita la decodificación de la credencial, así como con cada grupo suplementario del que sea miembro el ID de usuario efectivo de ese proceso.
MUNGE_OPT_IGNORE_TTL , int
Obtiene o establece el indicador "ignorar ttl". Si se establece en 1, se ignora los errores relacionados con TTL. munge_decode() devolverá EMUNGE_SUCCESS en lugar de EMUNGE_CRED_EXPIRED, EMUNGE_CRED_REWOUND o EMUNGE_CRED_REPLAYED.
MUNGE_OPT_IGNORE_REPLAY , int
Obtiene o establece el indicador "ignorar repetición". Si se establece en 1, se ignoran los errores de repetición. munge_decode() devolverá EMUNGE_SUCCESS en lugar de EMUNGE_CRED_REPLAYED.

TIPOS DE CIFRADO

Las credenciales pueden ser cifradas utilizando la clave secreta compartida por todos los demonios munged dentro de un reino de seguridad. Cualquiera que tenga acceso a esta clave puede usarla para descifrar una credencial, eludiendo así cualquier restricción impuesta por munged.

MUNGE_CIPHER_NONE
Especifica que se desactive el cifrado.
MUNGE_CIPHER_DEFAULT
Especifica el valor predeterminado según la configuración de munged.
MUNGE_CIPHER_BLOWFISH
Especifica el cifrado Blowfish diseñado por Bruce Schneier. Este cifrado tiene un tamaño de bloque de 64 bits y una longitud de clave variable. MUNGE lo utiliza con una clave de 128 bits en modo CBC. Es un cifrado de bloque rápido pero sufre un tiempo de configuración de clave lento. En consecuencia, su rendimiento es bajo al generar credenciales pequeñas.
MUNGE_CIPHER_CAST5
Especifica el cifrado CAST5 diseñado por Carlisle Adams y Stafford Tavares. Este cifrado tiene un tamaño de bloque de 64 bits y una longitud de clave variable. MUNGE lo utiliza con una clave de 128 bits en modo CBC.
MUNGE_CIPHER_AES128
Especifica el cifrado AES (Estándar de Cifrado Avanzado), también conocido como Rijndael. Fue diseñado por Joan Daemen y Vincent Rijmen. Este cifrado tiene un tamaño de bloque de 128 bits y una longitud de clave de 128, 192 o 256 bits. MUNGE lo utiliza aquí con una clave de 128 bits en modo CBC.
MUNGE_CIPHER_AES256
Especifica el cifrado AES (Estándar de Cifrado Avanzado), también conocido como Rijndael. Fue diseñado por Joan Daemen y Vincent Rijmen. Este cifrado tiene un tamaño de bloque de 128 bits y una longitud de clave de 128, 192 o 256 bits. MUNGE lo utiliza aquí con una clave de 256 bits en modo CBC. TIPOS DE CLAVE

La clave criptográfica utilizada para firmar las credenciales.

MUNGE_KEY_FILE
Utilice el archivo especificado en la opción --key-file para munged(8) o el valor por defecto, que es /etc/munge/munge.key.
MUNGE_KEY_URL
Descargue la clave de la URL especificada en la opción --key-url para munged(8). Tenga en cuenta que la URL debe ser segura (https).
MUNGE_KEY_DEFAULT
Especifique el valor predeterminado según la configuración de munged.

TIPOS DE MAC

El código de autenticación de mensajes (MAC) es un componente requerido de la credencial; por consiguiente, no se puede deshabilitar.

MUNGE_MAC_DEFAULT
Especifique el valor predeterminado según la configuración de munged.
MUNGE_MAC_MD5
Especifique el algoritmo MD5 diseñado por Ron Rivest y publicado en 1991. Este algoritmo tiene un resumen de mensaje de 128 bits. En 2004, se demostró un ataque de colisión exitoso contra MD5. En 2009, se publicó un ataque teórico de preimagen contra MD5. Por consiguiente, no se recomienda el uso de MD5 debido a su menor margen de seguridad.
MUNGE_MAC_SHA1
Especifique el algoritmo SHA-1 diseñado por la Agencia de Seguridad Nacional y publicado en 1995; es el sucesor del Algoritmo de Hash Seguro original (ahora llamado SHA-0) publicado en 1993. Este algoritmo tiene un resumen de mensaje de 160 bits. En 2005, se demostraron ataques de colisión exitosos contra SHA-1. En 2017, se anunció un ataque de colisión de prefijo idéntico exitoso (SHAttered). En 2020, se anunció un ataque de colisión de prefijo elegido exitoso (SHA-1 es un Shambles). Dado que aún no se ha demostrado un ataque de preimagen, SHA-1 aún debería ser seguro de usar dentro de MUNGE; sin embargo, se debe preferir el uso de una función hash SHA-2 (como SHA-256 o SHA-512).
MUNGE_MAC_RIPEMD160
Especifique el algoritmo RIPEMD-160 (RACE Integrity Primitives Evaluation Message Digest) diseñado en Europa por Hans Dobbertin, Antoon Bosselaers y Bart Preneel, y publicado en 1996. Este algoritmo tiene un resumen de mensaje de 160 bits. Es algo menos popular que SHA-1 y, en consecuencia, menos estudiado. Aunque más lento que SHA-1, se cree que tiene un margen de seguridad ligeramente mejor.
MUNGE_MAC_SHA256
Especifique el algoritmo SHA-256 diseñado por la Agencia de Seguridad Nacional y publicado en 2002; es una de las variantes SHA-2 de la familia del Algoritmo de Hash Seguro. Este algoritmo tiene un resumen de mensaje de 256 bits. En 2006, NIST comenzó a fomentar el uso de la familia de funciones hash SHA-2 para todas las aplicaciones y protocolos nuevos.
MUNGE_MAC_SHA512
Especifique el algoritmo SHA-512 diseñado por la Agencia de Seguridad Nacional y publicado en 2002; es una de las variantes SHA-2 de la familia del Algoritmo de Hash Seguro. Este algoritmo tiene un resumen de mensaje de 512 bits. En 2006, NIST comenzó a fomentar el uso de la familia de funciones hash SHA-2 para todas las aplicaciones y protocolos nuevos.

TIPOS DE COMPRESIÓN

Si se especifica un tipo de compresión, una credencial que contenga datos se comprimirá en consecuencia. Sin embargo, si los datos comprimidos resultantes son más grandes que los datos sin comprimir originales, se restaurarán los datos sin comprimir y la compresión se deshabilitará para esa credencial.

MUNGE_ZIP_NONE
Especifique que la compresión se deshabilitará. Esta es la configuración recomendada a menos que haya datos de tamaño suficiente para comprimir.
MUNGE_ZIP_DEFAULT
Especifique el valor predeterminado según la configuración de munged.
MUNGE_ZIP_BZLIB
Especifique la biblioteca bzip2 desarrollada por Julian Seward. Es más lenta y consume más memoria, pero generalmente logra una mejor compresión en datos más grandes.
MUNGE_ZIP_ZLIB
Especifique la biblioteca zlib desarrollada por Jean-loup Gailly y Mark Adler. Es más rápida y consume menos memoria, pero logra una compresión bastante buena de todos modos.

TIPOS DE TTL

El valor de tiempo de vida útil (TTL) especifica el número de segundos después de la hora de codificación en que la credencial se considera válida. Además de especificar un valor entero, están disponibles los siguientes tipos.

MUNGE_TTL_MAXIMUM
Especifique el máximo permitido por la configuración de munged.
MUNGE_TTL_DEFAULT
Especifique el valor predeterminado según la configuración de munged.

TIPOS DE UID Y GID

Las restricciones de UID y GID se pueden utilizar para restringir la decodificación de la credencial según el ID de usuario y grupo efectivo del proceso solicitante. Además de especificar un valor entero, están disponibles los siguientes tipos.

MUNGE_UID_ANY
Especifique que no se aplicará ninguna restricción de UID; este es el comportamiento predeterminado.
MUNGE_GID_ANY
Especifique que no se aplicará ninguna restricción de GID; este es el comportamiento predeterminado.

EJEMPLO

El siguiente programa de ejemplo ilustra el uso del contexto MUNGE para consultar la ubicación del socket de dominio de munged.

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <munge.h>

int
main (int argc, char *argv[])
{
    munge_ctx_t ctx;
    munge_err_t err;
    char *str;
    char buf[4096];
    uid_t uid;
    gid_t gid;
    ctx = munge_ctx_create ();
    if (ctx == NULL) {
        fprintf (stderr, "Error: Failed to create munge ctx\n");
        exit (EXIT_FAILURE);
    }
    /*  Query the socket name.  Note that the returned 'str' resides
     *    in the 'ctx' and will be de-allocated via munge_ctx_destroy().
     */
    err = munge_ctx_get (ctx, MUNGE_OPT_SOCKET, &str);
    if (err != EMUNGE_SUCCESS) {
        fprintf (stderr, "Error: Failed to get munge socket name: %s\n",
                munge_ctx_strerror (ctx));
        exit (EXIT_FAILURE);
    }
    printf ("socket=%s\n", str);
    /*  Read and decode a credential from the standard input.
     *  Ignore expired, rewound, and replayed errors.
     */
    err = munge_ctx_set (ctx, MUNGE_OPT_IGNORE_TTL, 1);
    if (err != EMUNGE_SUCCESS) {
        fprintf (stderr, "Error: Failed to set ignore-ttl opt: %s\n",
                munge_ctx_strerror (ctx));
        exit (EXIT_FAILURE);
    }
    if (fgets (buf, sizeof (buf), stdin) == NULL) {
        fprintf (stderr, "Error: Failed to read credential\n");
        exit (EXIT_FAILURE);
    }
    err = munge_decode (buf, ctx, NULL, NULL, &uid, &gid);
    if (err != EMUNGE_SUCCESS) {
        fprintf (stderr, "Error: Failed to decode credential: %s\n",
                munge_ctx_strerror (ctx));
        exit (EXIT_FAILURE);
    }
    printf ("uid=%d gid=%d\n", uid, gid);
    munge_ctx_destroy (ctx);
    exit (EXIT_SUCCESS);
}

NOTAS

El abandono de un contexto MUNGE nuevo o copiado sin destruirlo resultará en una fuga de memoria.

El contexto pasado a munge_encode() se trata como de solo lectura, excepto por el mensaje de error que se establece cuando se devuelve un error. El contexto pasado a munge_decode() se establece de acuerdo con el contexto utilizado para codificar la credencial; sin embargo, en caso de error, su configuración puede estar en un estado que no sea válido para la codificación. Por consiguiente, se deben usar contextos separados para codificar y decodificar.

Un contexto no debe compartirse entre hilos a menos que esté protegido por un mutex; sin embargo, una mejor alternativa es usar un contexto separado (o dos) para cada hilo, ya sea creando uno nuevo a través de munge_ctx_create() o copiando uno existente a través de munge_ctx_copy().
