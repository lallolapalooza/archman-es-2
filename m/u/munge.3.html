NOMBRE

munge_encode, munge_decode, munge_strerror - Funciones principales de MUNGE

SINOPSIS

#include <munge.h>

munge_err_t munge_encode (char **cred, munge_ctx_t ctx,
                          const void *buf, int len);

munge_err_t munge_decode (const char *cred, munge_ctx_t ctx,
                          void **buf, int *len, uid_t *uid, gid_t *gid);

const char * munge_strerror (munge_err_t e);

cc `pkg-config --cflags --libs munge` -o foo foo.c

DESCRIPCIÓN

La función munge_encode() crea una credencial contenida en una cadena base64 terminada en nulo. También se puede encapsular una carga útil especificada por un búfer buf de longitud len. Si el contexto MUNGE ctx es NULL, se utilizará el contexto predeterminado. Se devuelve un puntero a la credencial resultante a través de cred; en caso de error, se establece a NULL. El llamador es responsable de liberar la memoria a la que hace referencia cred.

La función munge_decode() valida la credencial terminada en nulo cred. Si el contexto MUNGE ctx no es NULL, se establecerá al que se utilizó para codificar la credencial. Si buf y len no son NULL, se asignará memoria para la carga útil encapsulada (hasta 1 MB), buf se establecerá para apuntar a estos datos y len se establecerá a su longitud. Se agregará un byte nulo adicional a estos datos de carga útil, pero no se incluirá en su longitud. Si no hay carga útil, buf se establecerá a NULL y len a 0. Para ciertos errores (es decir, EMUNGE_CRED_EXPIRED, EMUNGE_CRED_REWOUND, EMUNGE_CRED_REPLAYED), la memoria de la carga útil aún se asignará si es necesario. El llamador es responsable de liberar la memoria a la que hace referencia buf. Si uid o gid no son NULL, se establecerán al UID/GID del proceso que creó la credencial.

La función munge_strerror() devuelve una cadena de texto descriptiva que describe el número de error de MUNGE e.

VALOR DE RETORNO

Las funciones munge_encode() y munge_decode() devuelven EMUNGE_SUCCESS en caso de éxito, o un error de MUNGE en caso contrario. Si se utilizó un contexto MUNGE, puede contener un mensaje de error más detallado accesible a través de munge_ctx_strerror().

La función munge_strerror() devuelve un puntero a una cadena de texto constante terminada en nulo; esta cadena no debe ser liberada ni modificada por el llamador.

ERRORES

EMUNGE_SUCCESS
Éxito.
EMUNGE_SNAFU
Error interno.
EMUNGE_BAD_ARG
Argumento inválido.
EMUNGE_BAD_LENGTH
Se excedió la longitud máxima del mensaje según lo especificado por la configuración de munged.
EMUNGE_OVERFLOW
Se excedió la longitud máxima de un búfer.
EMUNGE_NO_MEMORY
No se pudo asignar la memoria requerida.
EMUNGE_SOCKET
No se pudo comunicar con el demonio en el socket de dominio.
EMUNGE_BAD_CRED
La credencial no coincide con el formato especificado.
EMUNGE_BAD_VERSION
La credencial contiene un número de versión no compatible.
EMUNGE_BAD_CIPHER
La credencial contiene un tipo de cifrado no compatible.
EMUNGE_BAD_MAC
La credencial contiene un tipo de MAC no compatible.
EMUNGE_BAD_ZIP
La credencial contiene un tipo de compresión no compatible.
EMUNGE_BAD_REALM
La credencial contiene un reino de seguridad no reconocido.
EMUNGE_CRED_INVALID
La credencial no es válida. Esto significa que la credencial no se pudo decodificar correctamente. Lo más probable es que las claves secretas en los hosts de codificación y decodificación no coincidan. Otra posibilidad es que la credencial se haya alterado desde que se codificó.
EMUNGE_CRED_EXPIRED
La credencial se decodificó correctamente, pero su tiempo de decodificación es posterior a su tiempo de codificación en más de su TTL. Los relojes de los hosts de codificación y decodificación podrían estar desincronizados.
EMUNGE_CRED_REWOUND
La credencial se decodificó correctamente, pero su tiempo de decodificación es anterior a su tiempo de codificación en más de su TTL. Los relojes de los hosts de codificación y decodificación están desincronizados.
EMUNGE_CRED_REPLAYED
La credencial se decodificó correctamente, pero ya se decodificó previamente en este host dentro de su desfase TTL.
EMUNGE_CRED_UNAUTHORIZED
El cliente no está autorizado para decodificar la credencial basándose en el ID de usuario y/o grupo efectivo del proceso.

EJEMPLO

El siguiente programa de ejemplo ilustra el uso de una credencial MUNGE para determinar el ID de usuario y grupo efectivo del proceso de codificación.

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <munge.h>

int
main (int argc, char *argv[])
{
    char *cred;
    munge_err_t err;
    uid_t uid;
    gid_t gid;
    err = munge_encode (&cred, NULL, NULL, 0);
    if (err != EMUNGE_SUCCESS) {
        fprintf (stderr, "Error: Failed to encode credential: %s\n",
                munge_strerror (err));
        exit (EXIT_FAILURE);
    }
    err = munge_decode (cred, NULL, NULL, NULL, &uid, &gid);
    if (err != EMUNGE_SUCCESS) {
        fprintf (stderr, "Error: Failed to decode credential: %s\n",
                munge_strerror (err));
        exit (EXIT_FAILURE);
    }
    printf ("uid=%d gid=%d\n", uid, gid);
    free (cred);
    exit (EXIT_SUCCESS);
}

NOTAS

Tanto munge_encode() como munge_decode() pueden asignar memoria que el llamador es responsable de liberar. No hacerlo dará lugar a una fuga de memoria.

NOMBRE

munge, munge_encode, munge_decode, munge_free_buffer - manipula un buffer de munge

SINOPSIS

#include <munge.h>

munge_err_t munge(munge_context_t *ctx,
                  const void *data, size_t data_len,
                  void **buffer, size_t *buffer_len);

munge_err_t munge_encode(munge_context_t *ctx,
                         const void *data, size_t data_len,
                         void **buffer, size_t *buffer_len);

munge_err_t munge_decode(munge_context_t *ctx,
                         const void *buffer, size_t buffer_len,
                         void **data, size_t *data_len);

void munge_free_buffer(void *buffer);

DESCRIPCIÓN

Estas funciones proporcionan una interfaz de programación de aplicaciones (API) para crear y procesar tokens de munge. Los tokens de munge son artefactos que se utilizan para autenticar la identidad de un proceso a otro. Son criptográficamente seguros y se generan utilizando una clave secreta compartida.

La función munge() crea un nuevo token de munge que contiene los datos especificados. El token resultante se almacena en el búfer apuntado por buffer y su longitud se almacena en buffer_len. El llamador es responsable de liberar la memoria del búfer utilizando munge_free_buffer() cuando ya no sea necesaria.

munge_encode() es un alias de munge() y se proporciona por razones de compatibilidad hacia atrás.

La función munge_decode() procesa un token de munge existente y extrae los datos originales. Los datos decodificados se almacenan en el búfer apuntado por data y su longitud se almacena en data_len. El llamador es responsable de liberar la memoria del búfer de datos utilizando munge_free_buffer() cuando ya no sea necesaria.

La función munge_free_buffer() libera la memoria asignada por munge() o munge_decode() para almacenar el token o los datos decodificados.

El parámetro ctx es un puntero a un contexto de munge válido inicializado por munge_init().

VALOR DE RETORNO

Todas las funciones de munge devuelven un valor munge_err_t que indica el resultado de la operación. Un valor de MUNGE_SUCCESS indica éxito. Otros valores indican diferentes tipos de errores. Consulte la documentación de munge_strerror() para obtener una lista completa de posibles códigos de error y sus descripciones.

ERRORES

Los errores pueden ocurrir debido a varias razones, que incluyen:

  • Contexto de munge no válido o no inicializado.
  • Errores de asignación de memoria.
  • Datos de entrada mal formados o corruptos.
  • Fallos de autenticación o verificación de firma.
  • Clave de munge incorrecta o faltante.

EJEMPLO

El siguiente ejemplo demuestra el uso básico de las funciones munge() y munge_decode():

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <munge.h>

int main() {
    munge_context_t *ctx = NULL;
    munge_err_t err;
    void *encoded_buf = NULL;
    size_t encoded_len = 0;
    void *decoded_data = NULL;
    size_t decoded_len = 0;
    const char *original_data = "¡Hola, mundo munge!";

    // Inicializar el contexto de munge
    ctx = munge_init(NULL);
    if (ctx == NULL) {
        fprintf(stderr, "Error: No se pudo inicializar el contexto de munge.\n");
        return 1;
    }

    // Crear un token de munge
    err = munge(ctx, original_data, strlen(original_data), &encoded_buf, &encoded_len);
    if (err != MUNGE_SUCCESS) {
        fprintf(stderr, "Error: munge() falló: %s\n", munge_strerror(err));
        munge_destroy(ctx);
        return 1;
    }

    printf("Datos originales: %s\n", original_data);
    printf("Token de munge creado (longitud: %zu)\n", encoded_len);

    // Decodificar el token de munge
    err = munge_decode(ctx, encoded_buf, encoded_len, &decoded_data, &decoded_len);
    if (err != MUNGE_SUCCESS) {
        fprintf(stderr, "Error: munge_decode() falló: %s\n", munge_strerror(err));
        munge_free_buffer(encoded_buf);
        munge_destroy(ctx);
        return 1;
    }

    printf("Datos decodificados: %.*s\n", (int)decoded_len, (char *)decoded_data);

    // Liberar memoria y destruir el contexto
    munge_free_buffer(encoded_buf);
    munge_free_buffer(decoded_data);
    munge_destroy(ctx);

    return 0;
}

NOTAS

Es fundamental gestionar correctamente la memoria asignada por las funciones de munge. Asegúrese de llamar siempre a munge_free_buffer() para liberar la memoria de los búferes de tokens y datos decodificados una vez que ya no se necesiten. Del mismo modo, asegúrese de llamar a munge_destroy() para liberar los recursos del contexto de munge.

Para un uso seguro, el contexto de munge debe inicializarse con una clave secreta apropiada utilizando munge_init(). La clave se puede especificar mediante el parámetro key o leyéndola del archivo de configuración predeterminado.
