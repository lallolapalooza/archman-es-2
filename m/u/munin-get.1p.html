MUNIN-GET(1p) Documentación Perl contribuida por el usuario MUNIN-GET(1p)

Nombre

munin-get - una herramienta simple para gestionar plugins desde repositorios remotos

Características

La pequeña herramienta de gestión "munin-get" soporta las siguientes acciones:

clonar uno o más repositorios git que contienen plugins de munin
se pueden usar múltiples repositorios remotos
listar todos los plugins encontrados (incluyendo la marca de tiempo de cambio y la descripción)
"instalar" un plugin (por defecto en: /var/lib/munin/munin-get-plugins)
"habilitar" un plugin (crear un enlace simbólico a /etc/munin/plugins/)
actualizar plugins (y revisar los cambios antes)

El propósito principal de esta herramienta es simplificar el proceso de uso de plugins del repositorio contrib de munin.

Uso

Todas las acciones excepto "install", "enable" y "disable" pueden ejecutarse como un usuario regular. Tenga en cuenta que los comandos no privilegiados utilizan directorios relativos a $HOME por defecto (se puede anular). Por lo tanto, se debería usar sudo o una herramienta similar para obtener privilegios. Por supuesto, todo se puede hacer como root.

El paso de "instalación" separado evita problemas potenciales con las banderas de endurecimiento de systemd u otras políticas de seguridad, que pueden impedir que el proceso de servicio "munin-node" acceda a archivos en /root/ o por debajo de /home/.

Ejemplos

Descubrir, inspeccionar, instalar, habilitar y probar un plugin

munin-get update
munin-get list
munin-get search throughput
munin-get doc contrib/traffic
munin-get install contrib/traffic
munin-get enable contrib/traffic
munin-run traffic
service munin-node restart   # para systemd: systemctl restart munin-node

Revisar y aplicar cambios del repositorio upstream

munin-get update
munin-get list-upgradeable
munin-get diff-upgradeable
munin-get upgrade

Añadir repositorios git personalizados de terceros

munin-get add-repository foo http://example.org/repos/munin-plugins.git
munin-get add-repository bar http://example.org/repos/munin-stuff.git branch-tested plugins/
munin-get update

Internos

Los repositorios se clonan debajo de ~/.cache/munin/munin-get/repositories (ver REPOSITORY_CACHE_BASE_DIR).

Se deben evitar los cambios manuales en los repositorios clonados.

El procedimiento separado de "instalación" y "habilitación" es necesario debido a posibles características de endurecimiento / espacio de nombres de procesos habilitadas para "munin-node". Por lo tanto, el destino del enlace simbólico se encuentra en una ruta que se puede esperar que sea utilizable incluso para un proceso "munin-node" restringido.

Además, la ubicación de "instalación" separada permite la revisión manual de los cambios upstream antes de aplicarlos localmente.
