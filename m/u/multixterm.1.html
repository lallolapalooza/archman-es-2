MULTIXTERM(1) Manual general de comandos MULTIXTERM(1)

NOMBRE

multixterm - controlar múltiples xterms de forma separada o conjunta

SINOPSIS

multixterm [ args ]

DESCRIPCIÓN

Multixterm crea múltiples xterms que pueden ser controlados de forma conjunta o separada.

En su forma más simple, multixterm se ejecuta sin argumentos y los comandos se introducen interactivamente en el primer campo de entrada. Presione Intro (o haga clic en el botón "new xterm") para crear un nuevo xterm ejecutando ese comando.

Las pulsaciones de teclas en la "ventana de entrada estándar" se redirigen a todos los xterms iniciados por multixterm. Los xterms pueden ser controlados por separado simplemente enfocándose en ellos.

La ventana de entrada estándar debe tener el foco para que las pulsaciones de teclas se envíen a los xterms. Cuando tiene el foco, el color cambia a aguamarina. A medida que se introducen caracteres, el color cambia a verde durante un segundo. Esto proporciona retroalimentación ya que los caracteres no se muestran en la ventana de entrada estándar.

Escribir en la ventana de entrada estándar mientras se mantiene presionadas las teclas alt o meta envía un carácter de escape antes de los caracteres escritos. Esto proporciona soporte para programas como emacs.

ARGUMENTOS

-xa
El argumento opcional -xa indica los argumentos a pasar a xterm.
-xc
El argumento opcional -xc indica un comando a ejecutar en cada xterm nombrado (ver -xn). Sin el argumento -xc, el comando es el shell actual.
-xd
El argumento opcional -xd indica un directorio donde buscar archivos que aparecerán en el menú Archivos. Por defecto, el directorio es: ~/lib/multixterm
-xf
El argumento opcional -xf indica un archivo a leer al inicio. Ver ARCHIVOS abajo para más información.
-xn
El argumento opcional -xn indica un nombre para cada xterm. Este nombre también será sustituido para cualquier %n en el argumento del comando (ver -xc).
-xv
El flag opcional -xv pone multixterm en modo verboso donde describirá algunas de las cosas que está haciendo internamente. La salida verbosa no está destinada a ser comprensible para nadie más que el autor.

Las opciones menos comunes pueden ser cambiadas por el archivo de inicio (ver ARCHIVOS abajo).

Se soportan todos los flags habituales de X y wish (es decir, -display, -name). Hay tantos que para evitar colisiones y hacerlos fáciles de recordar, todos los flags de multixterm comienzan con -x.

Si algún argumento no coincide con los flags anteriores, el resto de la línea de comandos se pone a disposición del usuario para su procesamiento. Por defecto, el resto se utiliza como una lista de nombres de xterm al estilo de -xn. El comportamiento predeterminado puede cambiarse usando el archivo .multixtermrc (ver ARCHIVO DOT abajo).

ARGUMENTOS DE LÍNEA DE COMANDOS DE EJEMPLO

El siguiente comando inicia dos xterms usando ssh a los hosts bud y dexter.

multixterm -xc "ssh %n" bud dexter

ARCHIVOS

Los archivos de comandos pueden usarse para controlar o inicializar multixterm. El menú Archivo puede usarse para invocar otros archivos. Si existen archivos en el directorio de archivos de comandos (ver -xd arriba), aparecerán en el menú Archivo. Los archivos también pueden cargarse usando Archivo->Abrir. Cualquier nombre de archivo es aceptable, pero el navegador de Archivo->Abrir tiene por defecto archivos con sufijo .mxt.

Los archivos están escritos en Tcl y pueden modificar cualquier variable o invocar cualquier procedimiento. Las variables principales de interés son 'xtermCmd' que identifica el comando (ver -xc) y 'xtermNames' que es una lista de nombres (ver -xn). El procedimiento xtermStartAll, inicia xterms para cada nombre en la lista. Otras variables y procedimientos pueden descubrirse examinando el propio multixterm.

ARCHIVO DE EJEMPLO

El siguiente archivo hace lo mismo que la línea de comandos del ejemplo anterior:

# inicia dos xterms conectados a bud y dexter
set xtermCmd "ssh %n"
set xtermNames {bud dexter}
xtermStartAll

ARCHIVO DOT

Al inicio, multixterm lee ~/.multixtermrc si está presente. Esto es similar a los archivos de comandos (ver ARCHIVOS arriba) excepto que .multixtermrc no puede llamar a xtermStartAll. En su lugar, se llama implícitamente, similar a la forma en que es implícito en el uso de -xn en la línea de comandos.

El siguiente .multixtermrc de ejemplo hace que cada xterm ejecute ssh a los hosts nombrados en la línea de comandos.

set xtermCmd "ssh %n"

Entonces multixterm podría ser llamado simplemente:

multixterm bud dexter

Si algún argumento de la línea de comandos no coincide con un flag de multixterm, el resto de la línea de comandos se pone a disposición de .multixtermrc en la variable argv. Si argv no está vacío cuando .multixtermrc retorna, se asigna a xtermNames a menos que xtermNames no esté vacío, en cuyo caso, el contenido de argv se ignora.

Los comandos de multixterm se evalúan al principio de la inicialización de multixterm. Cualquier cosa que deba hacerse al final de la inicialización (como agregar enlaces adicionales a la interfaz de usuario) puede hacerse colocando los comandos dentro de un procedimiento llamado "initLate".

MENÚS

Excepto donde se indique lo contrario, los menús se explican por sí mismos. Algunos de los menús tienen líneas discontinuas como primera entrada. Hacer clic en las líneas discontinuas "desprenderá" los menús.

SUGERENCIA DE USO - ALIASES Y ARCHIVOS DE COMANDOS

Los alias pueden usarse para almacenar invocaciones de línea de comandos largas. Los archivos de comandos también pueden usarse para almacenar dichas invocaciones, además de proporcionar una forma conveniente de compartir configuraciones.

Tcl es un lenguaje de propósito general. Por lo tanto, los archivos de comandos de multixterm pueden ser extremadamente flexibles, como cargar nombres de host de otros programas o archivos que pueden cambiar día a día. Además, los archivos de comandos pueden usarse para otros propósitos. Por ejemplo, los archivos de comandos pueden usarse para preparar secuencias de interacción comunes predefinidas. Por ejemplo, el comando para enviar la misma cadena a todos los xterms es:


xtermSend "una cadena particularmente larga"

El menú Archivo (desprendido) hace que las secuencias predefinidas sean particularmente convenientes. Las interacciones también podrían enlazarse a un botón del ratón, una pulsación de tecla o agregarse a un menú a través del archivo .multixtermrc.

El siguiente .multixtermrc hace que los xterms diminutos se organicen en mosaico horizontal y verticalmente en la pantalla. (Puede que tenga que ajustar los parámetros para su pantalla). Esto puede ser muy útil cuando se trata de un gran número de xterms.

    set yPos 0
    set xPos 0
    trace variable xtermArgs r traceArgs
    proc traceArgs {args} {
        global xPos yPos
        set ::xtermArgs "-geometry 80x12+$xPos+$yPos -font 6x10"
        if {$xPos} {
            set xPos 0
            incr yPos 145
            if {$yPos > 800} {set yPos 0}
        } else {
            set xPos 500
        }
    }

La variable xtermArgs en el código anterior es la variable que corresponde al argumento -xa.

Los xterms también pueden crearse directamente. El siguiente archivo de comandos crea tres xterms superpuestos horizontalmente:

    set xPos 0
    foreach name {bud dexter hotdog} {
        set ::xtermArgs "-geometry 80x12+$xPos+0 -font 6x10"
        set ::xtermNames $name
        xtermStartAll
        incr xPos 300
    }

SUGERENCIA DE USO - SELECCIÓN DE HOSTS POR SOBRENOMBRE

El siguiente .multixtermrc muestra un ejemplo de cómo cambiar el manejo predeterminado de los argumentos de nombres de host a un archivo que contiene nombres de host:

set xtermNames [exec cat $argv]

La siguiente es una variación, que recupera los nombres de host de la base de datos yp:

set xtermNames [exec ypcat $argv]

NAME

multixterm — Create multiple xterms and run commands in them

SYNOPSIS

multixterm [ -display display ] [ -geometry widthxheight ] [ num_xterms ] [ command ]

DESCRIPTION

Multixterm is a small utility which starts multiple xterms, and allows you to run the same command in all of them simultaneously. This is useful for system administration tasks where you need to perform the same action on multiple hosts, or start multiple identical processes.

ARGUMENTS

The optional arguments are:

-display display
Specifies the X display to use. If not specified, the value of the $DISPLAY environment variable is used.
-geometry widthxheight
Specifies the geometry of each xterm window. If not specified, the default geometry is 80 columns by 24 rows.
num_xterms
The number of xterm windows to create. If not specified, it defaults to 2.
command
The command to execute in each xterm. If not specified, the default shell (usually sh or bash) is executed.

EXAMPLE COMMAND LINE ARGUMENTS

multixterm 4 ssh host1 host2 host3 host4 starts four xterms and runs ssh hostN in each.

multixterm -geometry 120x50 3 starts three xterms, each 120 columns wide and 50 rows high.

FILES

Multixterm can read commands from an initialization file. This file is searched for in the following order:

  1. • $HOME/.multixtermrc
  2. • $HOME/lib/multixterm/*

The initialization file contains a series of Tcl commands which are executed by multixterm. These commands can be used to customize the behavior of multixterm, such as setting default hosts, defining aliases, or controlling the startup behavior of the xterms.

EXAMPLE FILE

    # This is a comment
    set default_hosts {host1 host2 host3}
    alias cluster1 {host1 host2}
    alias cluster2 {host3 host4}

DOT FILE

The .multixtermrc file is a Tcl script that is executed when multixterm starts. It can be used to define aliases for host names, set default hosts, or perform other setup tasks.

For example, to define aliases for two clusters of hosts:

        switch $argv {
            cluster1 {
                set xtermNames "bud dexter"
            }
            cluster2 {
                set xtermNames "frank hotdog weiner"
            }
        }

MENUS

Multixterm provides a menu bar with the following menus:

File
Provides options for opening and saving configuration files, and exiting multixterm.
Edit
Provides options for cutting, copying, and pasting text, as well as finding text within the xterm windows.
View
Provides options for controlling the appearance of the xterm windows, such as font size and color.
Help
Provides access to the multixterm documentation and version information.

USAGE SUGGESTION - ALIASES AND COMMAND FILES

You can define aliases in your .multixtermrc file to simplify launching multixterm with specific groups of hosts. For example:

    alias cluster1 {host1 host2}
    alias cluster2 {host3 host4 host5}

Then, you can launch multixterm with these aliases as arguments:

    multixterm cluster1
    multixterm cluster2

You can also use command files to automate more complex sequences of commands within each xterm. See the Expect documentation for details on Expect scripting.

USAGE SUGGESTION - SELECTING HOSTS BY NICKNAME

The .multixtermrc file allows you to define nicknames or aliases for groups of hosts. These nicknames can then be used as arguments to multixterm. For example, if you have the following in your .multixtermrc:

    alias webservers {server1.example.com server2.example.com}
    alias dbservers {db1.example.com db2.example.com}

You can then start multixterm with these aliases:

    multixterm webservers
    multixterm dbservers

This will launch two xterms for the webservers and three xterms for the dbservers, respectively. The exact behavior depends on how the aliases are defined. If an alias expands to multiple host names, multixterm will start an xterm for each host name in the alias.

The $argv variable in the .multixtermrc file will contain the arguments passed to multixterm. You can use a switch statement to select different configurations based on these arguments. For example, to define different sets of xterm names based on whether you specify "cluster1"

	switch $argv {
            cluster1 {
                set xtermNames "bud dexter"
            }
            cluster2 {
                set xtermNames "frank hotdog weiner"
            }
        }

COMPARE/CONTRAST

It is worth comparing multixterm to xkibitz. Multixterm connects a separate process to each xterm. xkibitz connects the same process to each xterm.

LIMITATIONS

Multixterm provides no way to remotely control scrollbars, resize, and most other window system related functions.

Because xterm has no mechanism for propagating size information to external processes, particularly for character graphic applications (e.g., vi, emacs), you may have to manually ensure that the spawned process behind each xterm has the correct size. For example, if you create or set the xterm to a size, you may have to send an explicit stty command with the correct size to the spawned process(es). Alternatively, you can add the correct size argument when an xterm is created (i.e., "-geometry 80x20").

Multixterm can only control new xterms that multixterm itself has started.

As a convenience, the File menu shows a limited number of files. To show all the files, use File->Open.

FILES

$DOTDIR/.multixtermrc initial command file
~/.multixtermrc fallback command file
~/lib/multixterm/ default command file directory

BUGS

If multixterm is killed using an uncatchable kill, the xterms are not killed. This appears to be a bug in xterm itself.

Send/expect sequences can be done in multixterm command files. However, due to the richness of the possibilities, to document it properly would take more time than the author has at present.
