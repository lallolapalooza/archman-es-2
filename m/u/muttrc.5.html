NOMBRE

muttrc - Archivo de configuración del Agente de Correo de Usuario Mutt

DESCRIPCIÓN

Un archivo de configuración de mutt consiste en una serie de "comandos". Cada línea del archivo puede contener uno o más comandos. Cuando se utilizan varios comandos, deben separarse por un punto y coma (";").

El signo de almohadilla, o numeral ("#"), se utiliza como carácter de "comentario". Puedes usarlo para anotar tu archivo de inicialización. Todo el texto después del carácter de comentario hasta el final de la línea se ignora.

Las comillas simples ("'") y las comillas dobles (""") se pueden usar para citar cadenas que contienen espacios u otros caracteres especiales. La diferencia entre los dos tipos de comillas es similar a la de muchos programas de shell populares, es decir, que una comilla simple se utiliza para especificar una cadena literal (una que no se interpreta para variables de shell o para citar con una barra invertida [ver párrafo siguiente]), mientras que las comillas dobles indican una cadena que debería ser evaluada. Por ejemplo, las comillas invertidas se evalúan dentro de las comillas dobles, pero no dentro de las comillas simples.

\ cita el siguiente carácter, al igual que en shells como bash y zsh. Por ejemplo, si deseas colocar comillas (""") dentro de una cadena, puedes usar "\" para forzar que el siguiente carácter sea literal en lugar de un carácter interpretado.

"\\" significa insertar una "\" literal en la línea. "\n" y "\r" tienen sus significados C habituales de salto de línea y retorno de carro, respectivamente.

Una "\" al final de una línea se puede usar para dividir comandos en varias líneas, siempre que los puntos de división no aparezcan en medio de los nombres de los comandos.

También es posible sustituir la salida de un comando de Unix en un archivo de inicialización. Esto se logra encerrando el comando entre comillas invertidas (`comando`).

Las variables de entorno de UNIX se pueden acceder de la misma manera que se hace en shells como sh y bash: Antepón el nombre de la variable a un signo de dólar ("$").

COMANDOS

alias [-group nombre [...]] tecla dirección [, dirección [ ... ]]
unalias [ *  | tecla ]
alias define un alias tecla para las direcciones dadas. Cada dirección se resolverá en una dirección de correo electrónico (usuario@ejemplo.com) o una dirección de correo electrónico con nombre (Nombre de Usuario <usuario@ejemplo.com>). La dirección puede especificarse en cualquiera de los formatos, o en el formato "usuario@ejemplo.com (Nombre de Usuario)". unalias elimina el alias correspondiente a la tecla dada o todos los alias cuando se utiliza "*" como argumento. El argumento opcional -group para alias hace que la(s) dirección(es) con alias se agreguen al grupo con nombre.
group [-group nombre] [-rx EXPR [ ... ]] [-addr dirección [ ... ]]
ungroup [-group nombre ] [ * | [[-rx EXPR [ ... ]] [-addr dirección [ ... ]]]
group se utiliza para agregar directamente direcciones o expresiones regulares a los grupos especificados. Las diferentes categorías de argumentos para el comando group pueden estar en cualquier orden. Las banderas -rx y -addr especifican cómo deben interpretarse las siguientes cadenas (que no pueden comenzar con un guion): como una expresión regular o como una dirección de correo electrónico, respectivamente. ungroup se utiliza para eliminar direcciones o expresiones regulares de los grupos especificados. La sintaxis es similar al comando group, sin embargo, el carácter especial * puede usarse para vaciar un grupo de todo su contenido.
Estos grupos de direcciones también pueden crearse implícitamente por los comandos alias, lists, subscribe y alternates especificando la opción opcional -group.
Una vez definidos, estos grupos de direcciones se pueden usar en patrones para buscar y limitar la visualización a mensajes que coinciden con un grupo.
alternates [-group nombre] regexp [ regexp [ ... ]]
unalternates [ *  | regexp [ regexp [ ... ]] ]
alternates se utiliza para informar a mutt sobre direcciones alternativas donde recibes correo; puedes usar expresiones regulares para especificar direcciones alternativas. Esto afecta la idea de mutt sobre los mensajes de ti y los mensajes dirigidos a ti. unalternates elimina una expresión regular de la lista de alternativas conocidas. La bandera -group hace que todas las expresiones regulares subsiguientes se agreguen al grupo con nombre.
alternative_order tipo[/subtipo] [ ... ]
unalternative_order [ *  | tipo/subtipo] [...]
El comando alternative_order te permite definir un orden de preferencia que utiliza mutt para determinar qué parte de un cuerpo multipart/alternative mostrar. Un subtipo de "*" coincide con cualquier subtipo, al igual que un subtipo vacío. unalternative_order elimina entradas de la lista ordenada o elimina toda la lista cuando se utiliza "*" como argumento.
attachments [ + | - ]disposición tipo-mime
unattachments [ + | - ]disposición tipo-mime
attachments ?
unattachments *
attachments especifica qué tipos de archivos adjuntos se utilizan para el recuento y la compatibilidad de búsqueda de archivos adjuntos de Mutt.
disposición es el tipo de Content-Disposition del archivo adjunto, ya sea inline o attachment. Puedes abreviar esto a I o A.
La primera parte de un mensaje o grupo multipart, si es inline, se cuenta por separado de otras partes inline. Especifica root o R para la disposición para contar estas como archivos adjuntos. Si esta primera parte es de tipo multipart/alternative, ten en cuenta que sus partes inline de nivel superior también se cuentan a través de la disposición root (si $count_alternatives está configurado).
disposición va precedida por un símbolo + o -. Si es un +, estás diciendo que deseas permitir que esta disposición y tipo MIME califiquen. Si es un -, estás diciendo que esta disposición y tipo MIME es una excepción a las reglas + anteriores.
tipo-mime es el tipo MIME del archivo adjunto al que deseas que el comando afecte. Un tipo MIME siempre tiene el formato principal/secundario, donde principal describe la categoría amplia del documento que estás viendo, y secundario describe el tipo específico dentro de esa categoría. La parte principal de tipo-mime debe ser texto literal (o el token especial *), pero la parte secundaria puede ser una expresión regular. (Por lo tanto, */.* coincide con cualquier tipo MIME).
Los tipos MIME que proporcionas a la directiva attachments son una especie de patrón. Cuando usas la directiva attachments, los patrones que especificas se agregan a una lista. Cuando usas unattachments, el patrón se elimina de la lista. Los patrones no se expanden ni se comparan con tipos MIME específicos en este momento, son solo texto en una lista. Solo se comparan cuando se evalúa un mensaje.
auto_view tipo[/subtipo] [ ... ]
unauto_view tipo[/subtipo] [ ... ]
Estos comandos te permiten especificar que mutt debe convertir automáticamente los tipos MIME dados a text/plain al mostrar mensajes. Para que esto funcione, debe haber una entrada mailcap(5) para el tipo MIME dado con la bandera copiousoutput establecida. Un subtipo de "*" coincide con cualquier subtipo, al igual que un subtipo vacío.
mime_lookup tipo[/subtipo] [ ... ]
unmime_lookup tipo[/subtipo] [ ... ]
Este comando te permite definir una lista de tipos de contenido MIME de "datos" para los cuales mutt intentará determinar el tipo de archivo real a partir del nombre del archivo, y no utilizará una entrada mailcap(5) dada para el tipo MIME original. Por ejemplo, puedes agregar el tipo MIME application/octet-stream a esta lista.
bind map1,map2,... tecla función<
/i>
Este comando enlaza la tecla dada para el mapa o mapas dados a la función dada. Se pueden especificar varios mapas separándolos con comas (no se permiten espacios en blanco).
Los mapas válidos son: generic, alias, attach, browser, editor, index, compose, pager, pgp, postpone, mix.
Para más información sobre teclas y funciones, consulte el Manual de Mutt. Tenga en cuenta que el nombre de la función debe especificarse sin corchetes angulares.
account-hook [!]regexp comando
Este hook se ejecuta cada vez que accede a un buzón remoto. Útil para ajustar la configuración a diferentes servidores IMAP o POP.
charset-hook alias charset
Este comando define un alias para un conjunto de caracteres. Esto es útil para mostrar correctamente mensajes que están etiquetados con un nombre de conjunto de caracteres desconocido para mutt.
iconv-hook charset local-charset
Este comando define un nombre específico del sistema para un conjunto de caracteres. Esto es útil cuando la implementación de iconv(3) de su sistema no entiende nombres de conjuntos de caracteres MIME (como iso-8859-1), sino que insiste en recibir nombres de conjuntos de caracteres específicos de la implementación (como 8859-1). En este caso específico, pondría esto en su archivo de configuración:
iconv-hook iso-8859-1 8859-1
message-hook [!]patrón comando
Antes de que mutt muestre (o formatee para responder o reenviar) un mensaje que coincide con el patrón dado (o, cuando va precedido por un signo de exclamación, no coincide con el patrón), se ejecuta el comando dado. Cuando coinciden varios message-hooks, se ejecutan en el orden en que aparecen en el archivo de configuración.
folder-hook [!]regexp comando
Cuando mutt entra en una carpeta que coincide con regexp (o, cuando regexp va precedido por un signo de exclamación, no coincide con regexp), se ejecuta el comando dado.
Cuando varios folder-hooks coinciden con una carpeta de correo dada, se ejecutan en el orden indicado en el archivo de configuración.
macro mapa tecla secuencia [ descripción ]
Este comando enlaza la secuencia de teclas dada a la tecla dada en el mapa o mapas dados. Para mapas válidos, consulte bind. Para especificar varios mapas, ponga solo una coma entre los mapas.
color objeto [ atributo ... ] color_de_fuente color_de_fondo [ regexp ]
color index [ atributo ... ] color_de_fuente color_de_fondo [ patrón ]
color compose objeto_de_composición [ atributo ... ] color_de_fuente color_de_fondo
uncolor index patrón [ patrón ... ]
Si su terminal admite color, estos comandos se pueden usar para asignar combinaciones de color_de_fuente/color_de_fondo a ciertos objetos. Los objetos válidos son: attachment, body, bold, error, header, hdrdefault, index, indicator, markers, message, normal, prompt, quoted, quotedN, search, signature, status, tilde, tree, underline. Si la barra lateral está habilitada, los siguientes objetos también son válidos: sidebar_divider, sidebar_flagged, sidebar_highlight, sidebar_indicator, sidebar_new, sidebar_spoolfile. Los objetos body y header le permiten restringir la colorización a una expresión regular. El objeto index le permite seleccionar mensajes coloreados por patrón.
Los objetos de composición válidos incluyen header, security_encrypt, security_sign, security_both, security_none.
Los colores válidos incluyen: white, black, green, magenta, blue, cyan, yellow, red, default, colorN.
Los atributos válidos incluyen: none, bold, underline, reverse y standout.
mono objeto atributo [ regexp ]
mono index atributo [ patrón ]
Para terminales que no admiten color, aún puede asignar atributos a los objetos.
[un]ignore patrón [ patrón ... ]
El comando ignore le permite especificar campos de encabezado que normalmente no desea ver. Se ignorará cualquier campo de encabezado cuya etiqueta *comience* con un patrón "ignorado".
El comando unignore le permite definir excepciones de la lista de encabezados ignorados mencionada anteriormente.
lists [-group nombre] regexp [ regexp ... ]
unlists regexp [ regexp ... ]
subscribe [-group nombre] regexp [ regexp ... ]
unsubscribe regexp [ regexp ... ]
Mutt mantiene dos listas de patrones de direcciones de listas de correo, una lista de listas de correo suscritas y una lista de listas de correo conocidas. Todas las listas de correo suscritas son conocidas. Los patrones usan expresiones regulares.
El comando lists agrega una dirección de lista de correo a la lista de listas de correo conocidas. El comando unlists elimina una lista de correo de las listas de listas de correo conocidas y suscritas. El comando subscribe agrega una lista de correo a las listas de listas de correo conocidas y suscritas. El comando unsubscribe la elimina de la lista de listas de correo suscritas. La bandera -group agrega todas las expresiones regulares subsiguientes al grupo con nombre.
mbox-hook [!]regexp buzón
Cuando mutt cambia a una carpeta de correo que coincide con regexp, buzón se usará como la carpeta "mbox", es decir, los mensajes leídos se moverán a esa carpeta al salir de la carpeta de correo.
Se aplica el primer mbox-hook coincidente.
mailboxes [[-notify | -nonotify]
           [-poll | -nopoll]
           [[-label etiqueta] | -nolabel]
           nombre_archivo] [ ... ]
unmailboxes [ * | nombre_archivo ... ]
mailboxes especifica las carpetas que pueden recibir correo y que se comprobarán en busca de mensajes nuevos. Al cambiar de carpeta, presionar espacio recorrerá las carpetas con correo nuevo. El comando unmailboxes se utiliza para eliminar un nombre de archivo de la lista de carpetas que pueden recibir correo. Si se especifica "*" como nombre de archivo, la lista se vacía.
my_hdr cadena
unmy_hdr campo
Usando my_hdr, puede definir encabezados que se agregarán a los mensajes que componga. unmy_hdr eliminará los encabezados definidos por el usuario.
hdr_order encabezado1 encabezado2 [ ... ]
Con este comando, puede especificar un orden en el que mutt intentará presentarle los encabezados al ver mensajes.
save-hook [!]patrón nombre_archivo
Cuando un mensaje coincide con patrón, el nombre de archivo predeterminado al guardarlo será el nombre_archivo dado.
fcc-hook [!]patrón nombre_archivo
Cuando un mensaje saliente coincide con patrón, el nombre de archivo predeterminado para almacenar una copia (fcc) será el nombre_archivo dado.
fcc-save-hook [!]patrón nombre_archivo
Este comando es una abreviatura de comandos idénticos fcc-hook y save-hook.
send-hook [!]patrón comando
Al componer un mensaje que coincide con patrón, se ejecuta comando. Cuando coinciden varios send-hooks, se ejecutan en el orden en que aparecen en el archivo de configuración.
send2-hook [!]patrón comando
Cada vez que se modifica un mensaje que coincide con patrón (ya sea editándolo o usando el menú de composición), se ejecuta comando. Cuando coinciden varios send2-hooks, se ejecutan en el orden en que aparecen en el archivo de configuración. Las aplicaciones posibles incluyen establecer la variable $sendmail cuando se cambia el encabezado from de un mensaje.
La ejecución de send2-hook no se activa por el uso de enter-command desde el menú de composición.
reply-hook [!]patrón comando
Al responder a un mensaje que coincide con patrón, se ejecuta comando. Cuando coinciden varios reply-hooks, se ejecutan en el orden en que aparecen en el archivo de configuración, pero todos los reply-hooks coinciden y se ejecutan antes que los send-hooks, independientemente de su orden en el archivo de configuración.
crypt-hook regexp id-clave
El comando crypt-hook proporciona un método por el cual puede especificar el ID de la clave pública que se utilizará al cifrar mensajes a un destinatario determinado. El significado de "ID de clave" debe tomarse en sentido amplio: puede ser una dirección de correo electrónico diferente, un ID de clave numérico o incluso una cadena de búsqueda arbitraria. Puede usar múltiples crypt-hooks con la misma regexp; varios crypt-hooks coincidentes dan como resultado el uso de múltiples id-claves para un destinatario.
index-format-hook nombre [!]patrón cadena-formato
Este comando se usa para inyectar cadenas de formato dyn

COMMANDS

alias name address [...]
unalias name [...]
The alias command defines an alias for one or more e-mail addresses. The unalias command removes an alias definition.
bind [!|~]key function [ key function ... ]
unbind [!|~]key [ key ... ]
These commands are used to bind keys to functions. The optional prefix “!” causes the binding to be made for the urgent key map, and “~” causes the binding to be made for the menu key map. unbind removes bindings.
color colorname type type ...
The color command is used to define colors. colorname is a standard X color name. type indicates what to color. Any number of types can be specified. The following types are known: normal, bold, underline, reverse, blink, fg, bg. For example, to make the bold attribute red and the reverse attribute white on blue, you would use: 
color red bold
color white blue reverse
define index-format format-string
undefine index-format
These commands are used to define and undefine index-format expando names. The index-format is the name of the expando, and the format-string is the string that will be substituted. See the index_format expando below for more information.
echomap key [ ... ]
This command prints the given key sequence to the message window. This is useful for debugging keybindings.
edit [type] [file]
This command launches an editor. If type is specified, it may be attach, body, attach-body, or full. The default is full. If file is specified, that file will be loaded. Otherwise, a temporary file is created.
fakefromdomain domain
This command sets the default domain name for sending mail. It is used when the sender's address does not contain a domain name.
filter type pattern command

The filter command installs a filter. Filters are used to apply Mutt commands to messages matching a given pattern. The type parameter determines when the filter is applied. The following types are recognized:
open

pending
applied when Mutt is idle.
new
applied to new mail.
The command is the Mutt command to be executed. If the command is preceded by a “!”, it will be executed in a shell. If the command is omitted, the filter is removed.

These commands provide a way to handle compressed folders. The given regexp specifies which folders are taken as compressed (e.g. "\\.gz$"). The commands tell Mutt how to uncompress a folder (open-hook), compress a folder (close-hook) or append a compressed mail to a compressed folder (append-hook). The command string is the printf(3) like format string, and it should accept two parameters: %f, which is replaced with the (compressed) folder name, and %t which is replaced with the name of the temporary folder to which to write.

score pattern value

The score commands adds value to a message's score if pattern matches it. The unscore command removes score entries from the list.
set [no|inv|&|?]variable[=value] [ ... ]
toggle variable [ ... ]
unset variable [ ... ]
reset variable [ ... ]
These commands are used to set and manipulate configuration variables.
Mutt knows four basic types of variables: boolean, number, string and quadoption. Boolean variables can be set (true), unset (false), or toggled. Number variables can be assigned a positive integer value.
String variables consist of any number of printable characters. Strings must be enclosed in quotes if they contain spaces or tabs. You may also use the “C” escape sequences \n and \t for newline and tab, respectively.
Quadoption variables are used to control whether or not to be prompted for certain actions, or to specify a default action. A value of yes will cause the action to be carried out automatically as if you had answered yes to the question. Similarly, a value of no will cause the action to be carried out as if you had answered “no.” A value of ask-yes will cause a prompt with a default answer of “yes” and ask-no will provide a default answer of “no.”
The reset command resets all given variables to the compile time defaults. If you reset the special variable all, all variables will reset to their compile time defaults.
setenv [?]variable [ value ]
unsetenv variable
These alter the environment that Mutt passes on to its child processes. You can also query current environment values by prefixing a “?” character.
sidebar_whitelist mailbox [ mailbox ...]
unsidebar_whitelist [ * | mailbox ... ]
sidebar_whitelist specifies mailboxes that will always be displayed in the sidebar, even if $sidebar_new_mail_only is set and the mailbox does not contain new mail.
unsidebar_whitelist is used to remove a mailbox from the list of whitelisted mailboxes. Use unsidebar_whitelist * to remove all mailboxes.
source filename
The given file will be evaluated as a configuration file.
spam pattern format
nospam pattern
These commands define spam-detection patterns from external spam filters, so that mutt can sort, limit, and search on ``spam tags'' or ``spam attributes'', or display them in the index. See the Mutt manual for details.
subjectrx pattern replacement
unsubjectrx [ * | pattern ]
subjectrx specifies a regular expression pattern which, if detected in a message subject, causes the subject to be replaced with the replacement value. The replacement is subject to substitutions in the same way as for the spam command: %L for the text to the left of the match, %R for text to the right of the match, and %1 for the first subgroup in the match (etc). If you simply want to erase the match, set it to “%L%R”. Any number of subjectrx commands may coexist.
Note this well: the replacement value replaces the entire subject, not just the match!
unsubjectrx removes a given subjectrx from the substitution list. If * is used as the pattern, all substitutions will be removed.
unhook [ * | hook-type ]
This command will remove all hooks of a given type, or all hooks when “*” is used as an argument. hook-type can be any of the -hook commands documented above.
mailto_allow header-field [ ... ]
unmailto_allow [ * | header-field ... ]
These commands allow the user to modify the list of allowed header fields in a mailto: URL that Mutt will include in the the generated message. By default the list contains only subject and body, as specified by RFC2368.
echo message
Prints message to the message window. After printing the message, echo will pause for the number of seconds specified by $sleep_time.
cd directory
Changes the current working directory.

PATTERNS

In various places with mutt, including some of the above mentioned hook commands, you can specify patterns to match messages.

Constructing Patterns

A simple pattern consists of a modifier of the form “~character”, possibly followed by a parameter against which mutt is supposed to match the object specified by this modifier. For some characters, the ~ may be replaced by another character to alter the behavior of the match. These are described in the list of modifiers, below.

With some of these modifiers, the object to be matched consists of several e-mail addresses. In these cases, the object is matched if at least one of these e-mail addresses matches. You can prepend a hat (“^”) character to such a pattern to indicate that all addresses must match in order to match the object.

You can construct complex patterns by combining simple patterns with logical operators. Logical AND is specified by simply concatenating two simple patterns, for instance “~C mutt-dev ~s bug”. Logical OR is specified by inserting a vertical bar (“|”) between two patterns, for instance “~C mutt-dev | ~s bug”. Additionally, you can negate a pattern by prepending a bang (“!”) character. For logical grouping, use braces (“()”). Example: “!(~t mutt|~c mutt) ~f elkins”.

Coincidencia de fechas

Los modificadores ~d y ~r se utilizan para buscar rangos de fechas, que se interpretan en tu zona horaria local.

Una fecha tiene el formato DD[/MM[/[AA]AA]], es decir, un día de dos dígitos, opcionalmente seguido de un mes de dos dígitos, opcionalmente seguido de una especificación de año. Los campos omitidos toman por defecto el mes y año actuales.

Mutt entiende especificaciones de año de dos o cuatro dígitos. Cuando se le da un año de dos dígitos, mutt interpretará los valores menores de 70 como pertenecientes al siglo XXI (es decir, “38” significa 2038 y no 1938, y “00” se interpreta como 2000), y los valores mayores o iguales a 70 como pertenecientes al siglo XX.

Ten en cuenta que este comportamiento es compatible con el Y2K, pero que mutt sí tiene un problema Y2.07K.

Alternativamente, puedes usar AAAA MM DD para especificar una fecha.

Si un rango de fechas consiste en una única fecha, el modificador en cuestión buscará esa fecha precisa. Si el rango de fechas consiste en un guion (“-”), seguido de una fecha, este rango buscará cualquier fecha anterior y hasta la fecha dada. De forma similar, una fecha seguida de un guion busca la fecha dada y cualquier momento posterior. Dos fechas, separadas por un guion, buscan cualquier fecha que se encuentre en el rango de tiempo dado.

También puedes modificar cualquier fecha absoluta dando un margen de error. Un margen de error consiste en uno de los caracteres +, -, *, seguido de un número positivo, seguido de uno de los caracteres de unidad y, m, w o d, especificando una unidad de años, meses, semanas o días. + aumenta la fecha máxima buscada por el intervalo de tiempo dado, - disminuye la fecha mínima buscada por el intervalo de tiempo dado, y * aumenta la fecha máxima y disminuye la fecha mínima buscada por el intervalo de tiempo dado. Es posible dar múltiples márgenes de error, que se acumulan. Ejemplo: 1/1/2001-1w+2w*3d

También puedes especificar desfases relativos a la fecha actual. Un desfase se especifica como uno de los caracteres <, >, =, seguido de un número positivo, seguido de uno de los caracteres de unidad y, m, w, d, H, M o S. > busca fechas que son más antiguas que la cantidad de tiempo especificada, un desfase que comienza con el carácter < busca fechas que son más recientes que la cantidad de tiempo especificada, y un desfase que comienza con el carácter = busca puntos en el tiempo que son precisamente hace la cantidad de tiempo dada.

hostname
Tipo: cadena
Predeterminado: “”
Especifica el nombre de host completo del sistema en el que se ejecuta mutt, que contiene el nombre del host y el dominio DNS al que pertenece. Se utiliza como la parte del dominio (después de "@") para las direcciones de correo electrónico locales, así como para las cabeceras Message-Id.
Su valor se determina al inicio de la siguiente manera: primero se determina el nombre de host del nodo mediante la función uname(3). Luego, se busca el dominio utilizando las funciones gethostname(2) y getaddrinfo(3). Si esas llamadas no pueden determinar el dominio, se utiliza el valor completo devuelto por uname. Opcionalmente, Mutt se puede compilar con un nombre de dominio fijo, en cuyo caso no se utiliza uno detectado.
A partir de Mutt 2.0, las operaciones descritas en el párrafo anterior se realizan después de procesar el muttrc, en lugar de antes. De esta manera, si las operaciones DNS están causando retrasos al inicio, puede evitarlos estableciendo manualmente el valor en su muttrc.
Ver también $use_domain y $hidden_host.

imap_authenticators
Tipo: cadena
Predeterminado: “”
Esta es una lista de métodos de autenticación separados por dos puntos que mutt puede intentar utilizar para iniciar sesión en un servidor IMAP, en el orden en que mutt debería probarlos. Los métodos de autenticación son "login" o el lado derecho de una cadena de capacidad IMAP "AUTH=xxx", por ejemplo, "digest-md5", "gssapi" o "cram-md5". Esta opción no distingue entre mayúsculas y minúsculas. Si está desestablecido (el valor predeterminado), mutt intentará todos los métodos disponibles, en orden de más seguro a menos seguro.
Ejemplo: 
set imap_authenticators=”gssapi:cram-md5:login”
Nota: Mutt solo recurrirá a otros métodos de autenticación si los métodos anteriores no están disponibles. Si un método está disponible pero la autenticación falla, mutt no se conectará al servidor IMAP.

* = se puede imprimir opcionalmente si no es cero
Algunas de las secuencias anteriores se pueden utilizar para imprimir opcionalmente una cadena si su valor no es cero. Por ejemplo, es posible que solo desees ver el número de mensajes marcados si existen dichos mensajes, ya que cero no es particularmente significativo. Para imprimir opcionalmente una cadena basándose en una de las secuencias anteriores, se utiliza la siguiente construcción:
%?<carácter_secuencia>?<cadena_opcional>?
donde carácter_secuencia es un carácter de la tabla anterior, y cadena_opcional es la cadena que te gustaría imprimir si carácter_secuencia no es cero. cadena_opcional puede contener otras secuencias, así como texto normal, pero no puedes anidar cadenas opcionales.
Aquí tienes un ejemplo que ilustra cómo imprimir opcionalmente el número de mensajes nuevos en un buzón:
%?n?%n mensajes nuevos.?
También puedes alternar entre dos cadenas utilizando la siguiente construcción:
%?<carácter_secuencia>?<cadena_si>&<cadena_si_no>?
Si el valor de carácter_secuencia no es cero, se expandirá cadena_si, de lo contrario se expandirá cadena_si_no.
Puedes forzar que el resultado de cualquier secuencia similar a printf(3) sea en minúsculas anteponiendo el carácter de secuencia con un guion bajo (“_”). Por ejemplo, si quieres mostrar el nombre de host local en minúsculas, usarías: “%_h”.
Si antepones la secuencia
carácter con dos puntos (“:”) carácter, mutt reemplazará cualquier punto en la expansión por guiones bajos. Esto puede ser útil con carpetas IMAP a las que no les gustan los puntos en los nombres de carpetas.

strict_threads
Tipo: booleano
Por defecto: no
Si está *establecido*, la creación de hilos solo utilizará los campos "In-Reply-To" y "References:" cuando ordenes por hilos de mensajes. Por defecto, los mensajes con el mismo asunto se agrupan en "hilos de pseudo". Esto puede no ser siempre deseable, como en un buzón personal donde puedes tener varios mensajes no relacionados con asuntos como "hola" que se agruparan. suspend
Tipo: booleano
Por defecto: sí
Cuando está *desestablecido*, mutt no se detendrá cuando el usuario presione la tecla de *suspensión* de la terminal, usualmente "^Z". Esto es útil si ejecutas mutt dentro de un xterm usando un comando como "xterm -e mutt".
text_flowed
Tipo: booleano
Por defecto: no
Cuando está *establecido*, mutt generará cuerpos "format=flowed" con un tipo de contenido de "text/plain; format=flowed". Este formato es más fácil de manejar para algunos programas de correo, y generalmente se ve como texto normal. Para hacer uso real de las características de este formato, necesitarás soporte en tu editor.
La opción solo controla los mensajes compuestos recientemente. Los mensajes pospuestos, los mensajes reenviados y los borradores (a través de -H en la línea de comandos) usarán el tipo de contenido del mensaje original.
Ten en cuenta que $indent_string se ignora cuando esta opción está *establecida*.
thorough_search
Tipo: booleano
Por defecto: sí
Afecta a las operaciones de búsqueda **~b**, **~B** y **~h** descritas en la sección "patrones". Si está *establecido*, las cabeceras y el cuerpo/archivos adjuntos de los mensajes a buscar se decodifican antes de buscar. Si está *desestablecido*, los mensajes se buscan tal como aparecen en la carpeta.
Los usuarios que busquen en archivos adjuntos o caracteres no ASCII deberían *establecer* este valor, ya que la decodificación también incluye el análisis/decodificación MIME y posibles conversiones de conjuntos de caracteres. De lo contrario, mutt intentará coincidir con el mensaje bruto recibido (por ejemplo, codificado en quoted-printable o con cabeceras codificadas), lo que puede llevar a resultados de búsqueda incorrectos.
thread_received
Tipo: booleano
Por defecto: no

tilde
Tipo: booleano
Por defecto: no
Cuando está *establecido*, el paginador interno rellenará las líneas en blanco hasta el final de la pantalla con una tilde ("~").
time_inc
Tipo: número
Por defecto: 0
Junto con $read_inc, $write_inc y $net_inc, esta variable controla la frecuencia con la que se muestran las actualizaciones de progreso. Suprime las actualizaciones a menos de $time_inc milisegundos de distancia. Esto puede mejorar el rendimiento en sistemas con terminales lentas, o cuando se ejecuta mutt en un sistema remoto.
Consulte también la sección "tuning" del manual para consideraciones de rendimiento.
timeout
Tipo: número
Por defecto: 600
Cuando Mutt está esperando entrada del usuario, ya sea inactivo en menús o en un prompt interactivo, Mutt se bloquearía hasta que hubiera entrada. Dependiendo del contexto, esto evitaría que funcionaran ciertas operaciones, como la verificación de correo nuevo o el mantenimiento de una conexión IMAP activa.
Esta variable controla cuántos segundos como máximo esperará Mutt hasta que deje de esperar entrada, realice estas operaciones y continúe esperando entrada.
Un valor de cero o menos hará que Mutt nunca se agote el tiempo de espera.

Tipo: ruta

to_chars
Tipo: cadena
Por defecto: “ +TCFL”
Controla el carácter utilizado para indicar correo dirigido a ti. El primer carácter es el que se usa cuando el correo *no* está dirigido a tu dirección. Tipo: booleano

use_8bitmime
Tipo: booleano
Predeterminado: no
Advertencia: no establezca esta variable a menos que esté utilizando una versión de sendmail que soporte el flag -B8BITMIME (como sendmail 8.8.x) o podría no poder enviar correo.
Cuando está activada, Mutt invocará $sendmail con el flag -B8BITMIME al enviar mensajes de 8 bits para habilitar la negociación ESMTP.
use_domain
Tipo: booleano
Predeterminado: sí
Cuando está activada, Mutt calificará todas las direcciones locales (aquellas sin la porción “@host”) con el valor de $hostname. Si está desactivada, ninguna dirección será calificada.
use_envelope_from
Tipo: booleano
Predeterminado: no
Cuando está activada, mutt establecerá el remitente del sobre del mensaje. Si $envelope_from_address está activada, se usará como dirección del remitente. Si está desactivada, mutt intentará derivar el remitente de la cabecera “From:”.
Tenga en cuenta que esta información se pasa al comando sendmail usando el switch de comando -f. Por lo tanto, activar esta opción no es útil si la variable $sendmail ya contiene -f o si el ejecutable al que apunta $sendmail no soporta el switch -f.
use_from
Tipo: booleano
Predeterminado: sí
Cuando está activada, Mutt generará el campo de cabecera “From:” al enviar mensajes. Si está desactivada, no se generará ningún campo de cabecera “From:” a menos que el usuario establezca explícitamente uno usando el comando “my_hdr”.
use_ipv6
Tipo: booleano
Predeterminado: sí
Cuando está activada, Mutt buscará direcciones IPv6 de los hosts a los que intente conectarse. Si esta opción está desactivada, Mutt se limitará a direcciones IPv4. Normalmente, el valor predeterminado debería funcionar.
user_agent
Tipo: booleano
Predeterminado: no
Cuando está activada, mutt agregará una cabecera “User-Agent:” a los mensajes salientes, indicando qué versión de mutt se utilizó para componerlos.
visual
Tipo: ruta

Especifica el editor visual a invocar cuando se da el comando “~v” en el editor incorporado.
wait_key
Tipo: booleano
Predeterminado: sí
Controla si Mutt te pedirá que presiones una tecla después de que se haya invocado un comando externo por las siguientes funciones: <shell-escape>, <pipe-message>, <pipe-entry>, <print-message>, y <print-entry>.
También se utiliza al ver archivos adjuntos con “auto_view”, siempre que la entrada mailcap correspondiente tenga un flag needsterminal, y el programa externo sea interactivo.
Cuando está activada, Mutt siempre pedirá una tecla. Cuando está desactivada, Mutt esperará una tecla solo si el comando externo devolvió un estado distinto de cero.
weed
Tipo: booleano
Predeterminado: sí
Cuando está activada, mutt limpiará cabeceras al mostrar, reenviar o responder a mensajes.

wrap
Tipo: número
Predeterminado: 0
Cuando se establece en un valor positivo, mutt envolverá el texto en $wrap caracteres. Cuando se establece en un valor negativo, mutt envolverá el texto de manera que queden $wrap caracteres de espacio vacío en el lado derecho de la terminal. Establecerlo a cero hace que mutt envuelva al ancho de la terminal.
Ver también $reflow_wrap.
wrap_headers
Tipo: número
Predeterminado: 78
Esta opción especifica el número de caracteres a utilizar para envolver las cabeceras de un mensaje saliente. Los valores permitidos están entre 78 y 998 inclusive.
Nota: Esta opción normalmente no debería cambiarse. RFC5233 recomienda una longitud de línea de 78 (el valor predeterminado), por lo tanto, por favor, cambie esta configuración solo cuando sepa lo que está haciendo.

Tipo: booleano
Predeterminado: sí
Controla si las búsquedas se envuelven al final.

write_bcc

Predeterminado: no
Controla si mutt escribe la cabecera “Bcc:” al preparar mensajes para ser enviados. Algunos MTA, como Exim y Courier, no eliminan la cabecera “Bcc:”; por lo tanto, es aconsejable dejarla desactivada a menos que tenga una necesidad particular de que la cabecera esté en el mensaje enviado.
Si mutt está configurado para entregar directamente vía SMTP (ver $smtp_url), esta opción no hace nada: mutt nunca escribirá la cabecera “Bcc:” en este caso.
Tenga en cuenta que esta opción solo afecta al envío de mensajes. Las copias Fcc de un mensaje siempre contendrán la cabecera “Bcc:” si existe.
write_inc
Tipo: número
Predeterminado: 10
