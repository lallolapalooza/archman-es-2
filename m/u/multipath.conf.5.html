MULTIPATH.CONF(5) Manual de Formatos de Archivo MULTIPATH.CONF(5)

NOMBRE

/etc/multipath.conf, /etc/multipath/conf.d/*.conf - archivo de configuración del demonio multipath.

DESCRIPCIÓN

/etc/multipath.conf es el archivo de configuración del demonio multipath. Se utiliza para sobrescribir la tabla de configuración incorporada de multipathd. Cualquier línea cuyo primer carácter que no sea un espacio en blanco sea un '#' se considera una línea de comentario. Las líneas vacías se ignoran.

La configuración de multipathd que se está utilizando actualmente se puede mostrar con los comandos multipath -t o multipathd show config.

Se pueden realizar configuraciones adicionales en archivos de descarte en /etc/multipath/conf.d. Los archivos que terminan en .conf en este directorio se leen en orden alfabético, después de leer /etc/multipath.conf. Utilizan la misma sintaxis que el propio /etc/multipath.conf y admiten todas las secciones y palabras clave. Si una palabra clave aparece en la misma sección en varios archivos, la última aparición prevalecerá sobre todas las demás.

SINTAXIS

El archivo de configuración contiene entradas de la forma:

<sección> {
<atributo> <valor>
...
<subsección> {
<atributo> <valor>
...
}
}

Cada sección contiene uno o más atributos o subsecciones. Las palabras clave reconocidas para atributos o subsecciones dependen de la sección en la que ocurran.

<atributo> y <valor> deben estar en una sola línea. <atributo> es una de las palabras clave enumeradas en esta página del manual. <valor> es una palabra simple (que no contiene espacios en blanco ni ninguno de los caracteres '"', '#' y '!') o *una* cadena encerrada entre comillas dobles ("..."). Fuera de una cadena entre comillas, el texto que comienza con '#' y '!' se considera un comentario y se ignora hasta el final de la línea. Dentro de una cadena entre comillas, '#' y '!' son caracteres normales, y los espacios en blanco se conservan. Para representar un carácter de comillas dobles dentro de una cadena entre comillas dobles, use dos comillas dobles consecutivas ('""'). Por lo tanto, '2.5" SSD' se puede escribir como "2.5"" SSD".

Las llaves de apertura ('{') deben seguir al nombre de la (sub)sección en la misma línea. Las llaves de cierre ('}') que marcan el final de una (sub)sección deben ser el único carácter que no sea un espacio en blanco en la línea. Los espacios en blanco se ignoran excepto dentro de las comillas, por lo tanto, la indentación que se muestra en el ejemplo anterior es útil para los lectores humanos pero no es obligatoria.

Nota sobre expresiones regulares: La sintaxis de /etc/multipath.conf permite que muchos valores de atributos se especifiquen como Expresiones Regulares Extendidas POSIX (consulte regex(7)). Estas expresiones regulares distinguen entre mayúsculas y minúsculas y no están ancladas, por lo que la expresión "bar" coincide con "barbie", "rhabarber" y "wunderbar", pero no con "Barbie". Para evitar coincidencias de subcadenas no deseadas, se puede utilizar la sintaxis estándar de expresiones regulares utilizando los caracteres especiales "^" y "$".

Se reconocen las siguientes palabras clave de *sección*:

defaults
Esta sección define los valores predeterminados para los atributos que se utilizan siempre que no se proporcionan valores en las secciones de dispositivo o multipath apropiadas.
blacklist
Esta sección define qué dispositivos deben excluirse del descubrimiento de la topología multipath.
blacklist_exceptions
Esta sección define qué dispositivos deben incluirse en el descubrimiento de la topología multipath, a pesar de estar listados en la sección blacklist.
multipaths
Esta sección define las topologías multipath. Se indexan por un Identificador Mundial Único (WWID). Para obtener detalles sobre la generación del WWID, consulte la sección Generación de WWID más adelante. Los atributos establecidos en esta sección tienen prioridad sobre todos los demás.
devices
Esta sección define la configuración específica del dispositivo. Los dispositivos se identifican por proveedor, producto y revisión.
overrides
Esta sección define valores para atributos que deben anular la configuración específica del dispositivo para todos los dispositivos.

timeout
(Opcional) El tiempo de espera para la CONSULTA, en ms.

preferredip=...
(Obligatorio) La dirección IP preferida, en notación decimal con puntos, para los objetivos iSCSI.
El valor predeterminado es: <unset>
features
Especifica cualquier característica del mapeador de dispositivos que se vaya a utilizar. La sintaxis es num lista donde num es el número, entre 0 y 8, de características en lista. Los valores posibles para la lista de características son:
queue_if_no_path
(Obsoleto, reemplazado por no_path_retry) Colas de E/S si no hay ninguna ruta activa. Idéntico a no_path_retry con el valor queue. Si se establecen ambas características, la última tendrá precedencia. Consulte PROBLEMAS CONOCIDOS.
pg_init_retries <veces>
(Desde el kernel 2.6.24) Número de veces que se reintentará pg_init, debe estar entre 1 y 50.
pg_init_delay_msecs <msecs>
(Desde el kernel 2.6.38) Número de ms antes de reintentar pg_init, debe estar entre 0 y 60000.
queue_mode <modo>
(Desde el kernel 4.8) Selecciona el modo de cola por dispositivo multipath. <modo> puede ser bio, rq o mq, que corresponden respectivamente a colas basadas en bio, colas basadas en solicitudes y colas multiqueue (blk-mq). Antes del kernel 4.20, el valor predeterminado depende del parámetro del kernel dm_mod.use_blk_mq. Es mq si este último está establecido, y rq en caso contrario. Desde el kernel 4.20, rq y mq corresponden a multiqueue de bloques. Una vez creado un dispositivo multipath, su queue_mode no se puede cambiar. Las rutas nvme:tcp solo se admiten en dispositivos multipath con queue_mode establecido en bio. multipath lo establecerá automáticamente al crear un dispositivo con rutas nvme:tcp.
El valor predeterminado es: 0
path_checker
El método predeterminado utilizado para determinar el estado de la ruta. Los verificadores síncronos (todos excepto tur y directio) harán que multipathd pause la mayoría de las actividades, esperando hasta checker_timeout segundos a que la ruta responda. Los verificadores asíncronos (tur y directio) no pausarán multipathd. En su lugar, multipathd verificará una respuesta una vez por segundo, hasta que transcurran checker_timeout segundos. Los valores posibles son:
readsector0
(Obsoleto) Lee el primer sector del dispositivo. Este verificador está quedando obsoleto, por favor, utilice tur o directio en su lugar.
tur
(Dependiente del hardware) Emite un comando TEST UNIT READY a un dispositivo SCSI.
emc_clariion
(Dependiente del hardware) Consulta la página EVPD específica de DGC/EMC 0xC0 para determinar el estado de la ruta para las familias de matrices CLARiiON CX/AX y EMC VNX y Unity.
hp_sw
(Dependiente del hardware) Comprueba el estado de la ruta para matrices HP/COMPAQ/DEC HSG80 y MSA/HSV con modo Activo/En espera exclusivamente.
rdac
(Dependiente del hardware) Comprueba el estado de la ruta para la clase LSI/Engenio/NetApp RDAC, como NetApp SANtricity E/EF Series, y matrices reacondicionadas.
directio
Lee el primer sector con E/S directa. Este verificador podría causar fallos de ruta espurios bajo alta carga. Aumentar checker_timeout puede ayudar con esto.
cciss_tur
(Dependiente del hardware) Comprueba el estado de la ruta para controladores HP/COMPAQ Smart Array (CCISS).
none
No comprueba el dispositivo, recurre a utilizar los valores recuperados de sysfs
El valor predeterminado es: tur
alias_prefix
El prefijo de user_friendly_names.
El valor predeterminado es: mpath
failback
Indica a multipathd cómo gestionar el failback de los grupos de rutas. Para seleccionar immediate o un valor, es obligatorio que el dispositivo admita un priorizador que funcione.
immediate
Vuelve inmediatamente a la ruta de mayor prioridad que contenga rutas activas.
manual
No realiza failback automático.
followover
Se utiliza para tratar con varios ordenadores que acceden a los mismos dispositivos de almacenamiento Activo/Pasivo. Solo realiza failback automático cuando la primera ruta de un grupo de rutas se activa. Esto evita que un nodo de clúster realice failback automáticamente cuando otro nodo solicitó el failover.
values > 0
Failback diferido (tiempo de aplazamiento en segundos).
El valor predeterminado es: manual
rr_min_io
Número de solicitudes de E/S que se enrutarán a una ruta antes de pasar a la siguiente en el mismo grupo de rutas. Esto es solo para multipath basado en E/S de Bloque (BIO) y solo se aplica al selector de ruta de round-robin.
El valor predeterminado es: 1000
rr_min_io_rq
Número de solicitudes de E/S que se enrutarán a una ruta antes de pasar a la siguiente en el mismo grupo de rutas. Esto es solo para multipath basado en Solicitud y solo se aplica al selector de ruta de round-robin.
El valor predeterminado es: 1
max_fds
Especifica el número máximo de descriptores de archivo que pueden ser abiertos por multipath y multipathd. Esto es equivalente a ulimit -n. Un valor de max lo establecerá al límite del sistema de /proc/sys/fs/nr_open. Si esto no se establece, el número máximo de descriptores de archivo abiertos se toma del proceso que llama. Normalmente es 1024. Para estar seguro, esto debería establecerse al número máximo de rutas más 32, si ese número es mayor que 1024.
El valor predeterminado es: max
rr_weight
Si se establece en priorities, el configurador multipath asignará pesos de ruta como "prio de ruta * rr_min_io". Los valores posibles son priorities o uniform . Solo se aplica al selector de ruta round-robin.
El valor predeterminado es: uniform
no_path_retry
Especifica qué hacer cuando todas las rutas están caídas. Los valores posibles son:
value > 0
Número de reintentos hasta que se deshabilite la cola de E/S.
fail
Para fallo inmediato (sin cola de E/S).
queue
Para no detener nunca la cola de E/S, similar a queue_if_no_path. Consulte PROBLEMAS CONOCIDOS.
El valor predeterminado es: fail
queue_without_daemon
Si se establece en no, cuando multipathd se detenga, la cola se desactivará para todos los dispositivos. Esto es útil para dispositivos que tienen configurado no_path_retry. Si una máquina se apaga mientras todas las rutas a un dispositivo están caídas, es posible que se cuelgue esperando que las E/S regresen del dispositivo después de que multipathd se haya detenido. Sin multipathd en ejecución, no se pueden restaurar los accesos a las rutas y no se puede indicar al kernel que deje de poner en cola las E/S. Establecer queue_without_daemon en no evita este problema.
El valor predeterminado es: no
checker_timeout
Especifica el tiempo de espera a utilizar para los verificadores de ruta y priorizadores, en segundos. Solo los priorizadores que emiten comandos scsi utilizan checker_timeout. Si una ruta no responde al comando del verificador después de que hayan transcurrido checker_timeout segundos, se considera inactiva.
El valor predeterminado es: en /sys/block/<dev>/device/timeout
allow_usb_devices
Si se establece en no, todos los dispositivos USB se omitirán durante el descubrimiento de rutas. Si tiene la intención de utilizar multipath en dispositivos conectados por USB, establézcalo en yes.
El valor predeterminado es: no
flush_on_last_del
Si se establece en always, multipathd deshabilitará la cola cuando se elimine la última ruta a un dispositivo. Si se establece en never, multipathd no deshabilitará la cola cuando se elimine la última ruta a un dispositivo. Dado que multipath no puede eliminar de forma segura un dispositivo mientras la cola está habilitada, establecer esto en never significa que multipathd no eliminará automáticamente un dispositivo multipath no utilizado cuyas rutas se eliminan, si está configurado para hacer cola si no hay ruta. Si se establece en unused, multipathd solo deshabilitará la cola cuando se elimine la última ruta si nada tiene actualmente el dispositivo multipath o alguna de las particiones kpartx abiertas encima de él.
El valor predeterminado es: unused
user_friendly_names
Si se establece en yes, se utiliza el archivo de enlaces /etc/multipath/bindings para asignar un alias persistente y único al multipath, en la forma de mpath<n>. Si se establece en no, se utiliza el WWID como alias. En cualquier caso, esto se anulará por cualquier alias específico en la sección multipaths.
El valor predeterminado es: no
fast_io_fail_tmo
Especifica el número de segundos que la capa SCSI esperará después de que se detecte un problema en un puerto remoto FC antes de fallar las E/S a los dispositivos en ese puerto remoto. Esto debe ser menor que dev_loss_tmo. Establecer esto en off deshabilitará el tiempo de espera.

Secciones blacklist y blacklist_exceptions

La sección blacklist se utiliza para excluir dispositivos específicos de la topología multipath. Se utiliza comúnmente para excluir discos locales o dispositivos que no son discos (como LUNs para el controlador de la cabina de almacenamiento) de ser manejados por multipath-tools.

En las secciones blacklist y blacklist_exceptions, iniciar un valor entre comillas con un signo de exclamación "!" invertirá la coincidencia del resto de la expresión regular. Por ejemplo, "!^sd[a-z]" coincidirá con todos los valores que no comiencen con "sd[a-z]". El signo de exclamación puede escaparse "\!" para que coincida con un ! literal al principio de una expresión regular. Nota: El signo de exclamación debe estar entre comillas, de lo contrario se tratará como el inicio de un comentario.

La sección blacklist_exceptions se utiliza para revertir las acciones de la sección blacklist. Esto permite incluir selectivamente ("whitelistar") dispositivos que normalmente serían excluidos a través de la sección blacklist. Un uso común es hacer una lista negra de "todo" usando una expresión regular genérica y crear entradas específicas de blacklist_exceptions para aquellos dispositivos que deberían ser manejados por multipath-tools.

Las siguientes palabras clave son reconocidas en ambas secciones. Los valores por defecto están vacíos a menos que se especifique lo contrario.

devnode
Expresión regular que coincide con los nodos del dispositivo a excluir/incluir.

La blacklist por defecto consiste en la expresión regular "!^(sd[a-z]|dasd[a-z]|nvme[0-9])". Esto hace que todos los tipos de dispositivo, excepto scsi, dasd y nvme, sean excluidos del manejo multipath por defecto.

wwid
Expresión regular para el Identificador Mundial (World Wide Identifier) de un dispositivo a excluir/incluir.
device
Subsección para la descripción del dispositivo. Esta subsección reconoce las palabras clave vendor y product. Ambas son expresiones regulares. Para una descripción completa de estas palabras clave, consulte la descripción de la sección devices.
property
Expresión regular para una propiedad de udev. Todos los dispositivos que tengan propiedades de udev coincidentes serán excluidos/incluidos. El manejo de la palabra clave property es especial, porque los dispositivos deben tener al menos una propiedad de udev en la lista blanca; de lo contrario, se tratan como en lista negra, y el mensaje "blacklisted, udev property missing" se muestra en los registros.

Nota: El comportamiento de esta opción ha cambiado en multipath-tools 0.8.2 en comparación con versiones anteriores. La inclusión en lista negra por propiedades faltantes solo se aplica a los dispositivos que tienen establecida la propiedad especificada por uid_attribute (por ejemplo, ID_SERIAL). Anteriormente, se aplicaba a todos los dispositivos, lo que podría causar que los dispositivos fueran incluidos en lista negra debido a condiciones de error de I/O temporales.

La blacklist exception por defecto es: (SCSI_IDENT_|ID_WWN), lo que hace que se incluyan los dispositivos SCSI que se comportan correctamente y los dispositivos que proporcionan un WWN (World Wide Number), y se excluyan todos los demás.

protocol
Expresión regular para el protocolo de un dispositivo a excluir/incluir.

Las cadenas de protocolo que multipath reconoce son scsi:fcp, scsi:spi, scsi:ssa, scsi:sbp, scsi:srp, scsi:iscsi, scsi:sas, scsi:adt, scsi:ata, scsi:unspec, nvme:pcie, nvme:rdma, nvme:fc, nvme:tcp, nvme:loop, nvme:apple-nvme, nvme:unspec, ccw, cciss, y undef. El protocolo que está utilizando una ruta se puede ver ejecutando multipathd show paths format "%d %P"

Para cada dispositivo, estos 5 criterios de lista negra se evalúan en el orden "property, devnode, device, protocol, wwid". Si un dispositivo resulta estar en lista negra por algún criterio, se excluye del manejo por multipathd, y los criterios posteriores ya no se evalúan. Para cada criterio, la lista blanca tiene precedencia sobre la lista negra si un dispositivo coincide con ambos.

Nota: Además de la lista negra y la lista blanca, otras opciones de configuración como find_multipaths tienen un impacto en si un dispositivo determinado es manejado por multipath-tools o no.

Generación de WWID

Multipath utiliza una Identificación Mundial Amplia (WWID) para determinar qué rutas pertenecen al mismo dispositivo. Se asume que cada ruta que presenta la misma WWID apunta al mismo dispositivo.

La WWID se genera mediante cuatro métodos (en orden de preferencia):

uid_attrs
La WWID se deriva de los atributos de udev al hacer coincidir el nombre del nodo del dispositivo; véase uid_attrs más arriba.
uid_attribute
Utiliza el valor del atributo de udev especificado; véase uid_attribute más arriba.
sysfs
Intenta determinar la WWID a partir de los atributos de sysfs. Para los dispositivos SCSI, esto significa leer la página de Datos Vitales del Producto (VPD) "Identificación del Dispositivo" (0x83).

La configuración predeterminada (usando udev y uid_attribute configurado a partir de la tabla de hardware integrada) debería funcionar bien en la mayoría de los escenarios. Los usuarios que deseen habilitar la fusión de uevent deben establecer uid_attrs.

Detección de rutas inestables

Un problema común en las configuraciones de SAN es la aparición de errores intermitentes: una ruta no es accesible, luego es accesible de nuevo por un corto tiempo, desaparece de nuevo, y así sucesivamente. Esto ocurre típicamente en interconexiones inestables. Es indeseable cambiar los grupos de rutas innecesariamente ante eventos tan frecuentes y poco fiables. multipathd admite tres métodos diferentes para detectar esta situación y lidiar con ella. Todos los métodos comparten el mismo modo de operación básico: Si se descubre que una ruta es "inestable" o "fluctuante", y parece estar en estado saludable, no se reinstaura (vuelve a usarse) inmediatamente. En su lugar, se coloca en estado de "retraso" y se vigila durante algún tiempo, y solo se reinstaura si el estado saludable parece ser estable. Si la opción marginal_pathgroups está establecida, la ruta se reinstaurará inmediatamente, pero se colocará en un grupo de rutas especial para rutas marginales. Los grupos de rutas marginales no se utilizarán hasta que se hayan probado todos los demás grupos de rutas. En el momento en que la ruta normalmente se reinstauraría, se devolverá a su grupo de rutas normal. La lógica para determinar la condición de "inestable", así como la lógica para cuándo reinstaurar, difiere entre los tres métodos.

Seguimiento de fallos de "delay_checks"
(Obsoleto) Este método está **obsoleto** y se mapea al método "san_path_err". Vea las opciones delay_watch_checks y delay_wait_checks anteriores para más información.
Seguimiento de fallos de "marginal_path"
Si se produce un segundo evento de fallo (transición bueno->malo) dentro de marginal_path_double_failed_time segundos después de un fallo, se inicia un monitoreo de alta frecuencia para la ruta afectada: se envían E/S a una tasa de 10 por segundo. Esto se hace durante marginal_path_err_sample_time segundos. Durante este período, la ruta no se reinstaura. Si la tasa de errores permanece por debajo de marginal_path_err_rate_threshold durante el período de monitoreo, la ruta se reinstaura. De lo contrario, se mantiene en estado de fallo durante marginal_path_err_recheck_gap_time, y después de eso, se monitorea de nuevo. Para este método, los intervalos de tiempo se miden en segundos.
Seguimiento de fallos de "san_path_err"
multipathd cuenta los fallos de ruta para cada ruta. Una vez que el número de fallos excede el valor dado por san_path_err_threshold, la ruta no se reinstaura durante san_path_err_recovery_time segundos. Mientras cuenta los fallos, multipathd "olvida" un fallo pasado cada "san_path_err_forget_rate" tics; por lo tanto, si los errores no ocurren con más frecuencia que una vez en el intervalo de la tasa de olvido, el recuento de fallos no aumenta y el umbral nunca se alcanza. Los tics son el tiempo entre las verificaciones de ruta por multipathd, que es variable y controlado por los parámetros polling_interval y max_polling_interval.

Este algoritmo es reemplazado por el seguimiento de fallos "marginal_path", pero sigue siendo compatible para compatibilidad con versiones anteriores.

Seguimiento de fallos "FPIN"
Los tejidos Fibre Channel pueden notificar a los hosts sobre problemas a nivel de tejido, como fallos de integridad o congestión, con las llamadas Notificaciones de Impacto en el Rendimiento del Tejido (FPIN). Al recibir las notificaciones fpin a través de ELS, multipathd moverá los estados de la ruta y el puerto afectados a marginal.

Consulte la documentación de las opciones individuales anteriores para obtener más detalles. Se **desaconseja enérgicamente** utilizar más de uno de estos métodos para cualquier mapa multipath dado, ya que los dos métodos concurrentes pueden interactuar de forma impredecible. Si el método "marginal_path" está activo, los parámetros de "san_path_err" se establecen implícitamente en 0.

SOPORTE DE MULTIPATH EXTERNO

multipath y multipathd pueden cargar bibliotecas "externas" para agregar soporte para otras tecnologías de multipathing además del device mapper de Linux. Actualmente, este soporte se limita a imprimir información detectada sobre la configuración de multipathing. En la salida de topología, los nombres de los mapas externos se anteponen con el nombre de la biblioteca externa entre corchetes, como en este ejemplo:

# multipath -ll
uuid.fedcba98-3579-4567-8765-123456789abc [nvme]:nvme4n9 NVME,Some NVMe controller,FFFFFFFF
size=167772160 features='n/a' hwhandler='ANA' wp=rw
|-+- policy='n/a' prio=50 status=optimized
| `- 4:38:1    nvme4c38n1 0:0     n/a   optimized    live
`-+- policy='n/a' prio=50 status=optimized
  `- 4:39:1    nvme4c39n1 0:0     n/a   optimized    live

La biblioteca externa "nvme" proporciona soporte para multipathing nativo NVMe en el kernel. Es parte del multipath estándar

PROBLEMAS CONOCIDOS

El uso de la opción queue_if_no_path puede provocar que los procesos en estado D se queden colgados y no puedan ser eliminados en situaciones donde todos los caminos a la LUN se desconectan. Se recomienda utilizar la opción no_path_retry en su lugar.

El uso de queue_if_no_path o no_path_retry podría llevar a un interbloqueo si la configuración de dev_loss_tmo provoca que un dispositivo se elimine mientras las E/S aún están en cola. El demonio multipath actualizará la configuración de dev_loss_tmo en consecuencia para evitar este interbloqueo. Por lo tanto, si se especifican ambos valores, el orden de precedencia es no_path_retry, queue_if_no_path, dev_loss_tmo.
