mmc(1) Manual de Comandos Generales mmc(1)

NOMBRE

mmc - una herramienta para configurar dispositivos de almacenamiento MMC

SINOPSIS

mmc [opciones] [ dispositivo-de-bloque-mmc]...

DESCRIPCIÓN

mmc-utils es una herramienta de hilo único que realizará un tipo de acción mmc especificado por el usuario.
El uso típico de mmc-utils es acceder al dispositivo mmc para configurar o leer sus registros de configuración.

OPCIONES

extcsd read dispositivo
Lee e imprime el registro csd extendido
extcsd write offset valor dispositivo
Escribe valor en el offset del extcsd del dispositivo
writeprotect boot get dispositivo
Imprime el estado de protección contra escritura de las particiones de arranque
writeprotect boot set dispositivo [número]
Establece el estado de protección contra escritura de la partición de arranque para el dispositivo.
Si se pasa número (0 o 1), solo protege esa partición de arranque eMMC especificada, de lo contrario, protege ambas.
Estará protegida contra escritura hasta el próximo arranque.
writeprotect user get dispositivo
Imprime la configuración de protección contra escritura de las áreas de usuario para <dispositivo>.
writeprotect user set tipo bloque-inicial bloques dispositivo
Establece la configuración de protección contra escritura para la región especificada del área de usuario para el dispositivo.
bloque-inicial especifica el primer bloque del área protegida.
bloques especifica el tamaño del área protegida en bloques.
¡NOTA! El área debe comenzar y terminar en los límites del Grupo de Protección contra Escritura. Use el comando "writeprotect user get" para obtener el tamaño del Grupo de Protección contra Escritura.
tipo es uno de los siguientes:
none
Borra la protección temporal contra escritura.
temp
Establece la protección temporal contra escritura.
pwron
Establece la protección contra escritura hasta el próximo encendido.
writeprotect user get dispositivo
Imprime la configuración de protección contra escritura del área de usuario para el dispositivo.
disable 512B emulation dispositivo
Establece el tamaño del sector de datos eMMC a 4KB deshabilitando la emulación en el dispositivo.
gp create dry-run longitud-KiB partición attr-enh attr-ext dispositivo
Crea una partición de propósito general para el dispositivo.
¡NOTA! Este es un cambio programable una sola vez (irreversible).
Para establecer el atributo mejorado en la partición general que se está creando, establezca attr-enh a 1, de lo contrario, establézcalo a 0.
Para establecer el atributo extendido en la partición general, establezca attr-enh a 1,2 de lo contrario, establézcalo a 0.
dry-run es uno de los siguientes:
-y
PARTITION_SETTING_COMPLETED en el extcsd se establecerá y la operación de partición tendrá efecto y se finalizará.
-c
todavía hay más configuraciones de partición pendientes - la operación de partición no tendrá efecto.
de lo contrario
Estos cambios no tendrán efecto ni ahora ni después de un ciclo de encendido.
enh_area set dry-run inicio-KiB longitud-KiB dispositivo
Habilita el área de usuario mejorada para el dispositivo.
¡NOTA! Este es un cambio programable una sola vez (irreversible). dry-run es como se describe arriba.
write_reliability set dry-run partición dispositivo
Habilita la confiabilidad de escritura por partición para el dispositivo.
¡NOTA! Este es un cambio programable una sola vez (irreversible). dry-run es como se describe arriba.
status get dispositivo
Imprime la respuesta a STATUS_SEND (CMD13).
bootpart enable partición-arranque send-ackn dispositivo
Habilita la partición de arranque para el dispositivo. Deshabilita la partición de arranque para el dispositivo si partición-arranque está establecido en 0.
Para recibir la confirmación de arranque de la tarjeta, establezca send-ackn a 1, de lo contrario, establézcalo a 0.
bootbus set modo-arranque reset-condiciones-bus-arranque ancho-bus-arranque dispositivo
Establece las condiciones del bus de arranque.
modo-arranque es uno de los siguientes: single_backward, single_hs, o dual.
reset-condiciones-bus-arranque es uno de los siguientes: x1 o retain.
ancho-bus-arranque es uno de los siguientes: x1, x4, o x8.
bkops_en modo dispositivo
Habilita la función BKOPS de eMMC en el dispositivo. La configuración automática (AUTO_EN) solo se admite en eMMC 5.0 o posterior.
¡NOTA! Establecer el modo manual (MANUAL_EN) es un cambio programable una sola vez (irreversible).
modo es uno de los siguientes:
auto
Se establece bkops automático
manual
Se establece bkops manual
hwreset enable dispositivo
Habilita permanentemente la función de reinicio H/W de eMMC en el dispositivo.
¡NOTA! Este es un cambio programable una sola vez (irreversible).
hwreset disable dispositivo
Deshabilita permanentemente la función de reinicio H/W de eMMC en el dispositivo.
¡NOTA! Este es un cambio programable una sola vez (irreversible).
sanitize dispositivo [timeout_ms]
Envía el comando Sanitize al dispositivo. Esto eliminará la región de memoria no mapeada del dispositivo.
rpmb write-key rpmb-dispositivo archivo-clave
Programa la clave de autenticación, que tiene una longitud de 32 bytes y se almacena en el archivo especificado.
También puedes especificar '-' en lugar de la ruta del archivo de clave para leer la clave desde la entrada estándar.
¡NOTA! Este es un cambio programable una sola vez (irreversible).
rpmb read-counter rpmb-dispositivo
El valor del contador para el rpmb-dispositivo se leerá en la salida estándar.
rpmb read-block rpmb-dispositivo dirección num-bloques salida-le [archivo-clave]
Se leerán bloques de 256 bytes

SYNOPSIS

mmc [-h | help] [-v] [-c] [cmd] [cmd --help]

DESCRIPTION

mmc is a utility to manage MMC/SD/SDIO cards.

It provides access to various hardware features and operations on the storage devices.

commands

rpmb read-key rpmb-device
Read RPMB key from rpmb-device. The key is written to stdout.
rpmb read-block rpmb-device address count [key-file | -]
Read count blocks starting from address from rpmb-device to output file or stdout if '-' is specified. If key is specified - read data will be verified.
rpmb write-block rpmb-device address 256-byte-data-file key-file
Block of 256 bytes will be written from data file to rpmb-device.
Also you can specify '-' instead of key file path or data file to read the data from stdin.
rpmb secure-wp-mode-on rpmb-device key-file
Enable Secure Write Protection mode.
The access to the write protection related EXT_CSD and CSD fields depends on the value of SECURE_WP_MASK bit in SECURE_WP_MODE_CONFIG field.
You can specify '-' instead of key.
rpmb secure-wp-mode-off rpmb-device key-file
Disable Secure Write Protection mode = legacy mode.
TMP_WRITE_PROTECT[12] and PERM_WRITE_PROTECT[13] are updated by CMD27.
USER_WP[171], BOOT_WP[173], and BOOT_WP_STATUS[174] are updated by CMD6.
You can specify '-' instead of key.
rpmb secure-wp-disable rpmb-device key-file
Enabling updating WP related EXT_CSD and CSD fields.
Applicable only if secure wp mode is enabled.
You can specify '-' instead of key.
rpmb secure-wp-enable rpmb-device key-file
Disabling updating WP related EXT_CSD and CSD fields.
Applicable only if secure wp mode is enabled.
You can specify '-' instead of key.
rpmb secure-wp-en-read rpmb-device [key-file]
Reads the status of the SECURE_WP_EN & SECURE_WP_MASK fields
Applicable only if secure wp mode is enabled.
You can specify '-' instead of key.
cache enable device
Enable the eMMC cache feature on the device.
NOTE! The cache is an optional feature on devices >= eMMC4.5.
cache disable device
Disable the eMMC cache feature on the device.
NOTE! The cache is an optional feature on devices >= eMMC4.5.
csd read [-h][-v] [-b bus_type] [-r register] <device-path>
Print CSD data from device-path. The device path should specify the csd sysfs file directory.
If bus_type is passed (mmc or sd), the register content must be passed as well, and no need for device path.
It is useful for cases where we are getting the register value without having the actual platform.
cid read [-h][-v] [-b bus_type] [-r register] <device-path>
Print CID data from device-path. The device path should specify the cid sysfs file directory.
If bus_type is passed (mmc or sd), the register content must be passed as well, and no need for device path.
It is useful for cases where we are getting the register value without having the actual platform.
scr read [-h][-v] [-b bus_type] [-r register] <device-path>
Print SCR data from device-path. The device path should specify the scr sysfs file directory.
If bus_type is passed (mmc or sd), the register content must be passed as well, and no need for device path.
It is useful for cases where we are getting the register value without having the actual platform.
ffu image-file-name device [chunk-bytes]
Run Field Firmware Update with image-file-name on the device.
[chunk-bytes] is optional and defaults to its max - 512k. should be in decimal bytes and sector aligned.
if [chunk-bytes] is omitted, mmc-utils will try to run ffu using the largest possible chunks: max(image-file, 512k).
opt_ffu1 image-file-name device [chunk-bytes]
Optional FFU mode 1, it's the same as 'ffu', but uses CMD23+CMD25 for repeated downloads and remains in FFU mode until completion.
opt_ffu2 image-file-name device [chunk-bytes]
Optional FFU mode 2, uses CMD25+CMD12 Open-ended Multiple-block write to download and remains in FFU mode until completion.
opt_ffu3 image-file-name device [chunk-bytes]
Optional FFU mode 3, uses CMD24 Single-block write for downloading, exiting FFU mode after each block is written.
opt_ffu4 image-file-name device [chunk-bytes]
Optional FFU mode 4, uses CMD24 Single-block write for repeated downloads, remaining in FFU mode until completion.
erase type start-address end-address device
Send Erase CMD38 with specific argument to the device.
NOTE!: This will delete all user data in the specified region of the device.
type is one of the following: legacy, discard, secure-erase, secure-trim1, secure-trim2, or trim.
gen_cmd read device [arg]
Send GEN_CMD (CMD56) to read vendor-specific format/meaning data from the device.
NOTE!: [arg] is optional and defaults to 0x1. If [arg] is specified, then [arg] must be a 32-bit hexadecimal number, prefixed with 0x/0X. And bit0 in [arg] must be 1. Normally this command is aimed to extract a device-health info from the device.
softreset device
Issues a CMD0 softreset, e.g. for testing if hardware reset for UHS works
boot_operation boot-data-file device

Does the alternative boot operation and writes the specified starting blocks of boot data into the requested file. Note some limitations:
1)
The boot operation must be configured first, e.g. via bootbus and/or bootpart commands
2)
The MMC must currently be running at the bus mode that is configured for the boot operation (HS200 and HS400 not supported at all).
3)
Only up to 512K bytes of boot data will be transferred.
4)
The MMC will perform a soft reset, if your system cannot handle that do not use the boot operation from mmc-utils.
--help | help | -h
Show the help
cmd --help
Show detailed help for that specific cmd or subset of commands.

RPMB COMMANDS

The RPMB partition on the eMMC devices is a special area used for storing cryptographically safe information signed by a special secret key.
To write and read records from this special area, authentication is needed.
The RPMB area is *only* and *exclusively* accessed using ioctl()s from user-space.
RPMB commands are send using the mmc multi-ioctl, thus ensures that the atomic nature of the rpmb access operation.
The rpmb device given as a parameter to the rpmb commands is not a block device but a char device.
This was done to help the mmc driver to account for some of the rpmb peculiarities.

EXAMPLES

RPMB examples

Program rpmb key using the stdin option:

$ echo -n AAAABBBBCCCCDDDDEEEEFFFFGGGGHHHH | mmc rpmb write-key /dev/mmcblk0rpmb -

Read 2 blocks starting address 2 and output the received content to stdout. Verify the received frames using the key (not mandatory):

$ echo -n AAAABBBBCCCCDDDDEEEEFFFFGGGGHHHH | mmc rpmb read-block /dev/mmcblk0rpmb 0x02 2 -

Read 2 blocks without verification starting address 2 and output the received content to /tmp/block:

$mmc rpmb read-block /dev/mmcblk0rpmb 0x02 2 /tmp/block

Write a string of 'a's to address 2. both the input and key uses stdin interface:

$ (awk 'BEGIN {while (c++<256) printf "a"}' | echo -n AAAABBBBCCCCDDDDEEEEFFFFGGGGHHHH) | mmc rpmb write-block /dev/mmcblk0rpmb 0x02 - -

Field Firmware Update (ffu) examples

Do ffu using max-possible chunk size: If the fluf size < 512k, it will be flushed in a single write sequence.

$ mmc ffu IO4e0aC2056001801M1100042AE1.fluf /dev/mmcblk0

Same as above, this time use a 4k chunks:

$ mmc ffu IO4e0aC2056001801M1100042AE1.fluf /dev/mmcblk0 4096
