NOMBRE

mmcli - Controlar y monitorizar el ModemManager

SINOPSIS

mmcli [OPCIÓN...]

DESCRIPCIÓN

ModemManager es un demonio de Linux impulsado por DBus que proporciona una API de alto nivel unificada para comunicarse con módems (banda ancha móvil). Actúa como una RIL (Radio Interface Layer) estándar y puede ser utilizado por diferentes gestores de conexión, como NetworkManager. Gracias a su arquitectura de plugins incorporada, ModemManager habla con tipos de módems muy diferentes y a través de puertos muy diferentes. Además de los puertos serie AT estándar, también se soportan los puertos Qualcomm-based QCDM y QMI.

OPCIONES DEL GESTOR

-B, --get-daemon-version
Obtener la versión del demonio ModemManager en ejecución.
-G, --set-logging=[ERR|WARN|INFO|DEBUG]
Establecer el nivel de registro en el demonio ModemManager. Para información de depuración, puede proporcionar DEBUG. Cada valor superior a DEBUG proporciona menos detalle. En la mayoría de los casos, ERR (para mostrar errores) son los mensajes importantes.

El modo predeterminado es ERR.

-L, --list-modems
Listar módems disponibles.
-M, --monitor-modems
Listar módems disponibles y monitorizar los módems añadidos o eliminados.
-S, --scan-modems
Escanear en busca de nuevos módems potenciales. Esto solo es útil cuando se esperan módems RS232 puros, ya que no son notificados automáticamente por el kernel.
-I, --inhibit-device=[UID]
Inhibir el uso del dispositivo específico por parte de ModemManager. El UID que se debe proporcionar es el valor de la propiedad Device expuesta por un módem dado (es decir, igual a ID_MM_PHYSDEV_UID si se establece alguno, o de lo contrario, igual a la ruta completa del dispositivo en sysfs).

Este comando no saldrá inmediatamente, ya que eso eliminaría implícitamente la inhibición. El usuario debe asegurarse de detener el proceso mmcli pulsando Ctrl+C para desinhibir el dispositivo.

Cuando un dispositivo se inhibe a través de este método, ModemManager lo deshabilitará (deteniendo así cualquier conexión en curso) y ya no lo utilizará hasta que se desinhiba.

--report-kernel-event=['KEY1=VALUE1,KEY2=VALUE2,...']
Informar manualmente de eventos del kernel, en lugar de depender de udev (por ejemplo, si el demonio se ejecuta con --no-auto-scan o si el sistema se compiló sin soporte de udev).

Las CLAVES soportadas son:

'action'
Acción a informar, una de 'add' o 'remove'. Obligatorio.
'subsystem'
Subsistema del puerto específico que se informa, por ejemplo, 'tty' (para puertos serie), 'net' (para interfaces de red) o 'usbmisc' (para puertos cdc-wdm).
'name'
Nombre del puerto que se informa, por ejemplo, 'ttyACM0', 'wwan0' o 'cdc-wdm0'.
'uid'
El UID específico del dispositivo, equivalente a la etiqueta udev ID_MM_PHYSDEV_UID. Todos los puertos informados con el mismo valor 'UID' se considerarán parte del mismo dispositivo, lo que puede ser útil para, por ejemplo, módems con múltiples TTYs de plataforma.
--report-kernel-event-auto-scan
Cuando se compila con soporte de udev pero el demonio se ejecuta con --no-auto-scan, este método puede usarse para informar automáticamente eventos del kernel basados en udev.

Este comando no saldrá inmediatamente. El usuario debe asegurarse de detener el proceso mmcli pulsando Ctrl+C para dejar de monitorizar nuevos eventos.

OPCIONES COMUNES

Todas las opciones a continuación toman un argumento RUTA o ÍNDICE. Si no se proporciona ninguna acción, se mostrará la información predeterminada sobre el módem, el portador, etc.

La RUTA y el ÍNDICE se crean automáticamente cuando se conecta el módem. Se pueden encontrar usando mmcli -L. Esto produce algo como (solo para módems):

Se encontraron 1 módems:
/org/freedesktop/ModemManager1/Modem/4

En este caso, el ÍNDICE es 4 y la RUTA es la cadena completa anterior.

Sin embargo, para los casos de portadores, SIM y SMS, la RUTA es ligeramente diferente. El _Modem_ se reemplaza con el nombre del objeto en uso, como _Bearer_. Por ejemplo:

/org/freedesktop/ModemManager1/Bearer/4
-m, --modem=[RUTA|ÍNDICE]
Especificar un módem.
-b, --bearer=[RUTA|ÍNDICE]
Especificar un portador.
-i, --sim=[RUTA|ÍNDICE]
Especificar una SIM.
-s, --sms=[RUTA|ÍNDICE]
Especificar un SMS.

OPCIONES DEL MODEM

Todas las opciones de módem a continuación utilizan el modificador --modem o -m para especificar el módem sobre el que actuar.

Algunas operaciones requieren un MODO. MODO puede ser cualquier combinación de los modos realmente soportados por el módem. En el caso perfecto, los siguientes son posibles:


'2G' - tecnologías 2G, por ejemplo, EDGE, CDMA1x
'3G' - tecnologías 3G, por ejemplo, HSPA, EV-DO
'4G' - tecnologías 4G, por ejemplo, LTE
'ANY' - para todos los modos soportados.

-w, --monitor-state
Monitorizar el estado de un módem dado.
-e, --enable
Habilitar un módem dado.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

Esto alimenta la antena, inicia el proceso de registro automático y, en general, prepara el módem para conectarse.

-d, --disable
Desactiva un módem determinado.

Esto desconecta las conexiones existentes para el módem y lo pone en modo de bajo consumo.

-r, --reset
Restablece el módem a la configuración que tenía cuando se encendió.
--factory-reset=CODE
Restablece el módem a su configuración predeterminada de fábrica original.

El CODE proporcionado es específico del proveedor. Sin el código de proveedor correcto, es poco probable que esta operación tenga éxito. Esta no es una acción común del usuario.

--command=COMMAND
Envía un COMMAND AT al módem dado. Por ejemplo, COMMAND podría ser 'AT+GMM' para sondear información del modelo del teléfono. Esta operación solo está disponible cuando ModemManager se ejecuta en modo de depuración.
--create-bearer=['KEY1=VALUE1,KEY2=VALUE2,...']
Crea un nuevo portador de datos de paquetes para un módem dado. Las KEYs y algunos VALUEs se enumeran a continuación:
'apn'
Nombre del Punto de Acceso. Requerido en 3GPP.
'ip-type'
Tipo de direccionamiento. Se proporciona como un valor de MMBearerIpFamily (por ejemplo, 'ipv4', 'ipv6', 'ipv4v6'). Opcional en 3GPP y CDMA.
'allowed-auth'
Método de autenticación a utilizar. Se proporciona como un valor de MMBearerAllowedAuth (por ejemplo, 'none|pap|chap|mschap|mschapv2|eap'). Opcional en 3GPP.
'user'
Nombre de usuario (si lo hay) requerido por la red. Opcional en 3GPP.
'password'
Contraseña (si la hay) requerida por la red. Opcional en 3GPP.
'allow-roaming'
Indicador para decir si la conexión está permitida durante el roaming, dado como un valor booleano (es decir, 'yes' o 'no'). Opcional en 3GPP.
'rm-protocol'
Protocolo de la interfaz Rm, dado como un valor MMModemCdmaRmProtocol (por ejemplo, 'async', 'packet-relay', 'packet-network-ppp', 'packet-network-slip', 'stu-iii'). Opcional en CDMA.
'number'
Número de teléfono a marcar. Requerido en POTS.
--delete-bearer=[PATH|INDEX]
Elimina un portador de un módem dado.
--set-allowed-modes=[MODE1|MODE2|...]
Establece los modos permitidos para un módem dado. Para los modos posibles, ver el principio de esta sección.
--set-preferred-mode=MODE
Establece el MODE preferido para el módem dado. El MODE DEBE ser uno de los modos permitidos como se establece con la opción --set-allowed-modes. Los posibles argumentos de MODE se detallan al principio de esta sección.
--set-current-bands=[BAND1|BAND2|...]
Establece las bandas a utilizar para un módem dado. Estos son rangos de frecuencia que el módem debe utilizar. Hay una gran cantidad de bandas admitidas y enumerarlas todas aquí sería bastante extenso. Para obtener detalles, consulte la documentación de MMModemBand.

Un ejemplo sería: 'egsm|dcs|pcs|g850' para seleccionar todas las bandas de frecuencia GSM.

--set-primary-sim-slot=[SLOT]
Solicita cambiar la ranura SIM principal.

La SLOT dada debe ser un número de ranura válido en el rango [1,N], donde N es la cantidad de ranuras SIM disponibles en el sistema.

--inhibit
Inhibe el uso del módem específico por parte de ModemManager. Este método es completamente equivalente a --inhibit-device, con la única diferencia de que en este caso, el módem debe ser administrado por el demonio en el momento en que se solicita la inhibición.

Este comando no saldrá de inmediato, ya que eso eliminaría implícitamente la inhibición. El usuario debe asegurarse de detener el proceso mmcli pulsando Ctrl+C para desinhibir el dispositivo.

Cuando un dispositivo se inhibe a través de este método, ModemManager deshabilitará el módem (por lo tanto, deteniendo cualquier conexión en curso) y ya no lo utilizará hasta que se desinhiba.

OPCIONES 3GPP

El 3rd Generation Partnership Project (3GPP) es una colaboración entre grupos de asociaciones de telecomunicaciones. Estas opciones se refieren a dispositivos que admiten 3GPP.

Se incluyen opciones para controlar las sesiones USSD (Unstructured Supplementary Service Data).

Todas las opciones 3GPP a continuación utilizan el modificador --modem o -m para especificar el módem en el que actuar.

--3gpp-scan
Escanear redes 3GPP disponibles.
--3gpp-register-home
Solicita a un módem determinado que se registre en su red doméstica.

Esto se registra con las redes predeterminadas especificadas por el módem,

--3gpp-register-in-operator=MCCMNC
Solicita a un módem determinado que se registre en la red del operador dado por MCCMNC (Mobile Country Code, Mobile Network Code). Este código se utiliza para redes móviles públicas terrestres GSM/LTE, CDMA, iDEN, TETRA y UMTS, y algunas redes móviles por satélite. La Recomendación E.212 de la UIT-T define los códigos de país móvil.
--3gpp-ussd-status
Solicita el estado de CUALQUIER sesión USSD en curso.
--3gpp-ussd-initiate=COMMAND
Solicita al módem dado que inicie una sesión USSD con COMMAND.

Por ejemplo, COMMAND podría ser '*101#' para consultar su saldo prepago actual.

--3gpp-ussd-respond=RESPONSE
Al iniciar una sesión USSD, una RESPUESTA puede ser necesaria por una solicitud originada por la red. Esta opción lo permite.
--3gpp-ussd-cancel
Cancela una sesión USSD en curso para un módem dado.
--3gpp-disable-facility-lock=FACILITY,CONTROL_KEY
Deshabilita el bloqueo de instalación seleccionado utilizando la clave de control proporcionada.
'FACILITY'
Uno de los siguientes tipos de bloqueo:
'net-pers' - personalización de red
'net-sub-pers' - personalización de subconjunto de red
'provider-pers' - personalización del proveedor
'corp-pers' - personalización corporativa
'CONTROL_KEY'
Código alfanumérico para desbloquear la instalación.

OPCIONES DE UBICACIÓN

Estas opciones detallan cómo descubrir su ubicación utilizando el Sistema de Posicionamiento Global (GPS) o directamente desde la infraestructura de su red móvil (ya sea 3GPP o 3GPP2).

Todas las opciones de ubicación deben usarse con --modem o -m.

--location-status
Muestra el estado actual para descubrir nuestra ubicación.
--location-get
Muestra toda la información de ubicación disponible.
--location-enable-3gpp
Habilita el descubrimiento de ubicación utilizando la red 3GPP.
--location-disable-3gpp
Deshabilita el descubrimiento de ubicación utilizando la red 3GPP.
--location-enable-agps-msa
Habilita el soporte A-GPS (MSA). Este comando no inicia implícitamente el motor GPS, solo especifica que A-GPS debe habilitarse cuando se inicie el motor. Por lo tanto, el usuario debe solicitar la habilitación de A-GPS antes de que se habiliten las salidas de datos sin procesar o NMEA con --location-enable-gps-raw o --location-enable-gps-nmea.
--location-disable-agps-msa
Deshabilita el soporte A-GPS (MSA).
--location-enable-agps-msb
Habilita el soporte A-GPS (MSB). Este comando no inicia implícitamente el motor GPS, solo especifica que A-GPS debe habilitarse cuando se inicie el motor. Por lo tanto, el usuario debe solicitar la habilitación de A-GPS antes de que se habiliten las salidas de datos sin procesar o NMEA con --location-enable-gps-raw o --location-enable-gps-nmea.
--location-disable-agps-msb
Deshabilita el soporte A-GPS (MSB).
--location-enable-gps-nmea
Habilita el descubrimiento de ubicación utilizando GPS y se informa con rastreos NMEA.

Este comando iniciará el motor GPS, si aún no está iniciado.

--location-disable-gps-nmea
Deshabilita el descubrimiento de ubicación utilizando GPS y rastreos NMEA.

Si la salida sin procesar no se habilita al mismo tiempo, el motor GPS se detendrá.

--location-enable-gps-raw
Habilita el descubrimiento de ubicación utilizando GPS y se informa con valor(es) sin procesar (es decir, longitud/latitud) s.

Este comando iniciará el motor GPS, si aún no está iniciado.

--location-disable-gps-raw
Deshabilita el descubrimiento de ubicación utilizando valores GPS y brutos.

Si la salida NMEA no está habilitada al mismo tiempo, el motor GPS se detendrá.

--location-enable-cdma-bs
Habilita el descubrimiento de ubicación utilizando la red 3GPP2.
--location-disable-cdma-bs
Deshabilita el descubrimiento de ubicación utilizando la red 3GPP2.
--location-enable-gps-unmanaged
Habilita el descubrimiento de ubicación utilizando GPS pero sin tomar el control del puerto tty NMEA. Esto permite que otros programas, por ejemplo, gpsd, utilicen el tty NMEA una vez que el motor GPS se haya habilitado.
--location-disable-gps-unmanaged
Deshabilita el descubrimiento de ubicación utilizando GPS y puerto no gestionado.
--location-set-gps-refresh-rate=SEC
Establece la tasa de actualización de ubicación en la interfaz DBus a SEC segundos. Si se establece en 0, la nueva ubicación se publicará en la interfaz DBus tan pronto como ModemManager la detecte.
--location-set-supl-server=[IP:PORT] o --location-set-supl-server=[FQDN:PORT]
Configura la ubicación del servidor SUPL A-GPS, especificando la dirección IP (IP:PORT) o especificando un nombre de dominio completamente calificado ([FQDN:PORT]).
--location-inject-assistance-data=[PATH]
Inyecta datos de asistencia en el módulo GNSS, cargados desde un archivo local en PATH. Los datos de asistencia deben estar en un formato esperado por el dispositivo, por ejemplo, descargados de las URL expuestas por la propiedad 'AssistanceDataServers'.
--location-set-enable-signal
Habilita la notificación de actualizaciones de ubicación a través de señales de propiedad DBus. Esto es necesario si las aplicaciones dependen de escuchar las actualizaciones de la propiedad 'Location', en lugar de consultas explícitas con el método 'GetLocation' protegido por políticas.

Las actualizaciones de esta señal de propiedad DBus están deshabilitadas por defecto.

--location-set-disable-signal
Deshabilita la notificación de actualizaciones de ubicación a través de señales de propiedad DBus.

CORE OPTIONS

-L, --list-modems
List all the modems known to ModemManager.
-m, --modem=MODEM
Select a modem to manage. MODEM can be the index of the modem, its identificator or its D-Bus path. This option can be used multiple times to select multiple modems. If not specified all modems will be used.
-s, --sms=SMS
Select an SMS to manage. SMS can be the index of the SMS, its identificator or its D-Bus path. This option can be used multiple times to select multiple SMS. If not specified all SMS will be used.
-i, --sim=SIM
Select a SIM to manage. SIM can be the index of the SIM, its identificator or its D-Bus path. This option can be used multiple times to select multiple SIMs. If not specified all SIMs will be used.
-p, --pipe
Use the given file descriptor as input. This option is used when you want to send a file to the modem, e.g. for a firmware update. If not specified the stdin will be used.

MODEM OPTIONS

--generic-connect=PATH
Connect to the modem using the given D-Bus path.
--bearer.connect=PATH
Connect to the bearer using the given D-Bus path.
--bearer.disconnect=PATH
Disconnect the bearer using the given D-Bus path.
--bearer.create=APN
Create a bearer for the given APN.

Create a bearer for the given APN, Username and Password.

EXAMPLES

Send the PIN to the SIM card

You'll need first to know which the proper path/index is for the SIM in your modem:
$ mmcli -m 0 -K | grep "modem.generic.sim" | awk -F ": " '{ print $2 }'
/org/freedesktop/ModemManager1/SIM/0

And after that, you can just use the SIM index:
$ sudo mmcli -i 0 --pin=1234
successfully sent PIN code to the SIM

Simple connect and disconnect

You can launch the simple connection process like:
$ sudo mmcli -m 0 --simple-connect="pin=1234,apn=internet"
successfully connected the modem

Then, you can disconnect it like:
$ sudo mmcli -m 0 --simple-disconnect
successfully disconnected all bearers in the modem

3GPP network scan

Scanning for 3GPP networks may really take a long time, so a specific timeout must be given:
$ sudo mmcli -m 0 --3gpp-scan --timeout=300
---------------------
3GPP scan | networks: 21403 - Orange SP (gprs, unknown)
| 21407 - Movistar (gprs, unknown)
| 21404 - YOIGO (gprs, unknown)
| 21401 - vodafone ES (gprs, unknown)

Creating a new SMS message & storing it

Using the “sm” (SIM), you can do this using:


$ sudo mmcli -m 0 --messaging-create-sms="text='Hello world',number='+1234567890'"
Successfully created new SMS:
/org/freedesktop/ModemManager1/SMS/21 (unknown)


$ sudo mmcli -s 21 --store-in-storage="sm"
successfully stored the SMS


$ sudo mmcli -s 21
-------------------------------
General | dbus path: /org/freedesktop/ModemManager1/SMS/21
-------------------------------
Content | number: +1234567890
| text: Hello world
-------------------------------
Properties | PDU type: submit
| state: stored
| smsc: unknown
| validity: 0
| class: 0
| storage: sm
| delivery report: not requested
| message reference: 0


$ sudo mmcli -m 0 --messaging-status
----------------------------
Messaging | supported storages: sm, me
| default storage: me

Sending binary SMS messages from files

As you can see below, the important part is the --messaging-create-sms-with-data and the PATH provided.


$ sudo mmcli -m 0 \
--messaging-create-sms="number='+1234567890'" \
--messaging-create-sms-with-data=/path/to/your/file
Successfully created new SMS:
/org/freedesktop/ModemManager1/SMS/22 (unknown)


$ sudo mmcli -s 22 --send
successfully sent the SMS

Listing SMS messages

When the receiver gets all the parts of the message, they can now recover the sent file with another mmcli command in their ModemManager setup:


$> sudo mmcli -m 0 --messaging-list-sms
/org/freedesktop/ModemManager1/SMS/0 (received)


$> sudo mmcli -s 0 --create-file-with-data=/path/to/the/output/file

GPS location status

You first need to check whether the modem has GPS-specific location capabilities. Note that we’ll assume the modem is exposed as index 0; if you have more than one modem, just use --list-modems to check the proper modem index:


$ mmcli -m 0 --location-status
----------------------------
Location | capabilities: 3gpp-lac-ci, gps-raw, gps-nmea
| enabled: none
| signals: no

The output says that the modem supports 3GPP Location area code/Cell ID, GPS raw and GPS-NMEA location sources. None is enabled yet, as we didn’t enable the modem, which we can do issuing:


$ sudo mmcli -m 0 --enable
successfully enabled the modem


$ mmcli -m 0 --location-status
----------------------------
Location | capabilities: 3gpp-lac-ci, gps-raw, gps-nmea
| enabled: 3gpp-lac-ci
| signals: no

GPS location technology enabling

We can start the GPS engine by enabling the RAW or NMEA GPS location sources:


$ sudo mmcli -m 0 \
--location-enable-gps-raw \
--location-enable-gps-nmea
successfully setup location gathering

If we do check again the status, we’ll see the GPS-specific locations are enabled:


$ mmcli -m 0 --location-status
--------------------------------
Location | capabilities: 3gpp-lac-ci, gps-raw, gps-nmea
| enabled: 3gpp-lac-ci, gps-raw, gps-nmea
| signals: no

GPS location retrieval

You can query all location information at the same time with a single command. If any of the specific outputs is not available, the corresponding section will be omitted from the output.


$ sudo mmcli -m 0 --location-get
-------------------------
3GPP location | Mobile country code: 214
| Mobile network code: 3
| Location area code: 21071
| Cell ID: 7033737
-------------------------
GPS NMEA traces | $GPGGA,,,,,,0,,,,,,,,*66
| $GPRMC,,V,,,,,,,,,,N*53
| $GPGSA,A,1,,,,,,,,,,,,,,,*1E
| $GPGSV,4,1,16,24,,,,29,,,,05,,,,18,,,*7A
| $GPGSV,4,2,16,22,,,,14,,,,11,,,,17,,,*7B
| $GPGSV,4,3,16,03,,,,12,,,,30,,,,13,,,*78
| $GPGSV,4,4,16,23,,,,15,,,,27,,,,07,,,*79
| $GPVTG,,T,,M,,N,,K,N*2C

A-GPS support

If A-GPS is enabled before starting the GPS engine, and if a data connection is available in the modem, the configured SUPL servers may be used to obtain a faster initial position fix.

Note that the GPS engine will not be started when just A-GPS capability is enabled. An explicit output (RAW or NMEA) is required to be enabled in order to start the GPS engine.


$ mmcli -m 0 --location-status
--------------------------------
Location | capabilities: 3gpp-lac-ci, gps-raw, gps-nmea
| enabled: 3gpp-lac-ci
| signals: yes

We need to enable one of the GPS outputs, too.


$ sudo mmcli -m 0 --location-enable-gps-nmea
successfully setup location gathering

And now, we can also enable A-GPS.


$ sudo mmcli -m 0 --location-enable-agps
successfully setup location gathering

Ejemplos

Habilitando la ayuda del módem para la localización

Al usar capacidades de localización como GPS asistido, primero debes habilitarlas. Puedes ver las capacidades disponibles con:


$ mmcli -m 0 --location-status
-----------------------------
Location | capabilities: 3gpp-lac-ci, gps-raw, gps-nmea, agps-msa, agps-msb
| enabled: 3gpp-lac-ci
| signals: no
-----------------------------
GPS | refresh rate: 30 seconds
| a-gps supl server: supl.google.com:7276


$ sudo mmcli -m 0 --location-enable-agps-msa
successfully setup location gathering


$ sudo mmcli -m 0 --location-enable-gps-nmea
successfully setup location gathering


$ sudo mmcli -m 0 --location-enable-gps-raw
successfully setup location gathering

Inyectando datos de asistencia

Si el dispositivo módem no tiene una conexión activa (p. ej., sin cobertura de red móvil) pero el sistema tiene otros medios para acceder a Internet (p. ej., WiFi), el usuario puede descargar datos de asistencia de localización e inyectarlos en el módulo.

Por ejemplo, si el dispositivo soporta datos de asistencia XTRA, el usuario puede descargarlos de uno de los servidores listados por ModemManager e inyectarlos manualmente después. Los datos de asistencia XTRA suelen ser válidos durante varios días.


$ mmcli -m 0 --location-status
--------------------------------
Location | capabilities: 3gpp-lac-ci, gps-raw, gps-nmea, agps-msa, agps-msb
| enabled: 3gpp-lac-ci
| signals: no
--------------------------------
GPS | refresh rate: 30 seconds
| a-gps supl server: supl.google.com:7276
| supported assistance: xtra
| assistance servers: https://xtrapath3.izatcloud.net/xtra3grcej.bin
| https://xtrapath1.izatcloud.net/xtra3grcej.bin
| https://xtrapath2.izatcloud.net/xtra3grcej.bin


$ wget -q https://xtrapath3.izatcloud.net/xtra3grcej.bin


$ sudo mmcli -m 0 --location-inject-assistance-data=./xtra3grcej.bin
successfully injected assistance data


$ sudo mmcli -m 0 --location-enable-gps-nmea
successfully setup location gathering


$ sudo mmcli -m 0 --location-enable-gps-raw
successfully setup location gathering

Estableciendo la lista de canales de Cell Broadcast

La lista de canales se puede establecer como una lista separada por comas de canales o intervalos de canales:


$ sudo mmcli -m 0 \
--cell-broadcast-set-channels=5370,5371,5373-5000
successfully set channels in the modem

Salida Clave-Valor

Escribir scripts de shell que utilicen mmcli para realizar operaciones con el módem es fácil cuando se usa la opción --output-keyvalue. Por ejemplo, podrías recopilar toda la información de estado principal del módem con una sola llamada y luego analizarla para leer campos individuales:


$ STATUS=$(mmcli -m 0 --output-keyvalue)
$ echo "${STATUS}" | grep "modem.generic.state " | awk -F ": " '{ print $2 }'
failed
$ echo "${STATUS}" | grep "modem.generic.state-failed-reason " | awk -F ": " '{ print $2 }'
sim-missing
