NOMBRE

MMDF - formato de buzón de Multi-channel Memorandum Distribution Facility

DESCRIPCIÓN

Este documento describe el formato de buzón de MMDF utilizado por algunos MTA y MUA (es decir, scomail(1)) para almacenar mensajes de correo localmente.

Un buzón de MMDF es un archivo de texto que contiene un número arbitrario de mensajes de correo electrónico. Cada mensaje consta de un sello postal (postmark), seguido de un mensaje de correo electrónico formateado según RFC822 / RFC2822, seguido de un sello postal. El formato del archivo está basado en líneas. Las líneas se separan por caracteres de salto de línea (ASCII 10). Una línea de sello postal consta de los cuatro caracteres "^A^A^A^A" (Control-A; ASCII 1).

Ejemplo de un buzón de MMDF que contiene dos correos:
^A^A^A^A
From: example@example.com
To: example@example.org
Subject: test

>From what I learned about the MMDF-format:
^A^A^A^A
^A^A^A^A
From: example@example.com
To: example@example.org
Subject: test 2

bar
^A^A^A^A

A diferencia de la mayoría de los otros formatos de buzón de archivo único como MBOXO y MBOXRD (ver mbox(5)), no es necesario citar/des-citar las líneas "From " en los buzones de MMDF, ya que tales líneas no tienen un significado especial en este formato.

Si el tiempo de modificación (generalmente determinado mediante stat(2)) de un archivo de buzón no vacío es mayor que el tiempo de acceso, el archivo tiene correo nuevo. Muchos MUA colocan una cabecera Status: en cada mensaje para indicar qué mensajes ya han sido leídos.

BLOQUEO

Dado que los archivos de MMDF son accedidos frecuentemente por múltiples programas en paralelo, los archivos de MMDF generalmente no deben ser accedidos sin bloqueo.

Tres mecanismos de bloqueo diferentes (y sus combinaciones) se usan generalmente:

  • El bloqueo de fcntl(2) se usa principalmente en sistemas recientes y compatibles con POSIX. El uso de este método de bloqueo es, en particular, aconsejable si los archivos de MMDF se acceden a través del Sistema de Archivos de Red (NFS), ya que parece ser la única forma de invalidar de manera confiable las cachés de los clientes NFS.
  • El bloqueo de flock(2) se usa principalmente en sistemas basados en BSD.
  • El dotlocking se usa en todo tipo de sistemas. Para bloquear un archivo de MMDF llamado folder, una aplicación primero crea un archivo temporal con un nombre único en el directorio donde reside el folder. Luego, la aplicación intenta usar la llamada al sistema link(2) para crear un enlace físico llamado folder.lock al archivo temporal. El éxito de la llamada al sistema link(2) debe ser verificado adicionalmente mediante llamadas a stat(2). Si el enlace tuvo éxito, se considera que la carpeta de correo está bloqueada (dotlocked). Luego, el archivo temporal puede ser eliminado de forma segura.
Para liberar el bloqueo, una aplicación simplemente elimina el archivo folder.lock.

Si se combinan múltiples métodos, los implementadores deben asegurarse de usar las variantes no bloqueantes de las llamadas al sistema fcntl(2) y flock(2) para evitar bloqueos mutuos (deadlocks).

Si se combinan múltiples métodos, un archivo de MMDF no debe considerarse bloqueado con éxito antes de que todos los bloqueos individuales hayan sido obtenidos. Cuando uno de los métodos de bloqueo individuales falla, una aplicación debe liberar todos los bloqueos que adquirió con éxito y reiniciar todo el procedimiento de bloqueo desde el principio, después de un retraso adecuado.

El mecanismo de bloqueo utilizado en un sistema particular es una cuestión de política local y debe ser utilizado consistentemente por todas las aplicaciones instaladas en el sistema que acceden a archivos de MMDF. No hacerlo puede resultar en la pérdida de datos de correo electrónico y en archivos de MMDF corruptos.

CONFORME A

MMDF no forma parte de ningún estándar actualmente soportado.

HISTORIA

MMDF fue desarrollado en la Universidad de Delaware por Dave Crocker.
