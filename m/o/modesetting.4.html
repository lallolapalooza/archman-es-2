MODESETTING(4) Manual de Controladores de Dispositivos MODESETTING(4)

NOMBRE

modesetting - controlador de video para dispositivo framebuffer

SINOPSIS

Section "Device"
  Identifier "nombre_dispositivo"
  Driver "modesetting"
  BusID  "pci:bus:dev:func"
  ...
EndSection

DESCRIPCIÓN

modesetting es un controlador de Xorg para dispositivos KMS. Este controlador soporta visualizaciones TrueColor en profundidades de framebuffer de 15, 16, 24 y 30 bits. Soporta RandR 1.2 para configuraciones multi-monitor. La aceleración está disponible a través de glamor para dispositivos que soporten al menos OpenGL ES 2.0 o OpenGL 2.1. Si glamor no está habilitado, se configura un framebuffer en sombra basado en la preferencia de los controladores KMS (a menos que el framebuffer sea de 24 bits por píxel, en cuyo caso siempre se usa el framebuffer en sombra).

HARDWARE SOPORTADO

El controlador modesetting soporta todo el hardware para el que esté disponible un controlador KMS. modesetting utiliza las ioctls KMS de DRM de Linux y la creación/mapeo de objetos tontos (dumb objects).

DETALLES DE CONFIGURACIÓN

Consulte xorg.conf(5) para obtener detalles generales de configuración. Esta sección solo cubre detalles de configuración específicos de este controlador.

Para este controlador no es necesario especificar modos en la sección de pantalla del archivo de configuración. El controlador modesetting puede detectar el modo de video actualmente en uso desde el controlador del kernel y lo utilizará si no hay modos de video configurados.

Para placas PCI, es posible que tenga que añadir una línea BusID a la sección Device. Consulte arriba un ejemplo de línea.

Las siguientes Options del controlador son compatibles:

Option "SWcursor" "booleano"
Selecciona el cursor de software. El valor predeterminado es off.
Option "kmsdev" "cadena"
El dispositivo framebuffer a utilizar. Predeterminado: /dev/dri/card0.
Option "ShadowFB" "booleano"
Habilita o deshabilita el uso de la capa de framebuffer en sombra. Predeterminado: on.
Option "DoubleShadow" "booleano"
Duplica la memoria del framebuffer en sombra para las actualizaciones. Cuando está habilitado, el controlador mantendrá dos copias del framebuffer en sombra. Cuando se vacía el framebuffer en sombra, se comparan las versiones antigua y nueva de la sombra, y solo se cargan en el dispositivo los bloques que han cambiado. Esto es una optimización para GPUs de clase servidor con una función de pantalla remota (típicamente VNC), donde las actualizaciones remotas se activan por cualquier escritura en el framebuffer, por lo que minimizar la cantidad de datos cargados es crucial. Esto está habilitado por defecto para dispositivos ASPEED y Matrox G200, y deshabilitado en otros casos.
Option "AccelMethod" "cadena"
Una de "glamor" o "none". Predeterminado: glamor.
Option "PageFlip" "booleano"
Habilita el volcado de página DRI3. El valor predeterminado es on.
Option "VariableRefresh" "booleano"
Habilita el soporte para habilitar la actualización variable en los CRTCs de la Pantalla cuando una aplicación adecuada realiza volcado a través de la extensión Present.
El valor predeterminado es off.
Option "AsyncFlipSecondaries" "booleano"
Utiliza volcados asíncronos para las salidas de video secundarias en configuraciones multi-pantalla. Si una pantalla tiene múltiples monitores conectados y se utiliza el volcado de página DRI3, solo uno de los monitores tendrá su volcado de página sincronizado con el vblank para una presentación sin cortes (tear-free). Este es el monitor que se utiliza para la temporización y el marcado de tiempo de la presentación, generalmente el que cubre el área de píxeles más grande de la pantalla. Todos los demás monitores ("Secundarios") no sincronizarán sus volcados. Esto puede causar algunos cortes en estas pantallas, pero evita una ralentización permanente o periódica o un molesto tartamudeo de las animaciones si no todas las salidas de video se ejecutan sincronizadas entre sí y con la misma frecuencia de actualización. No existe una solución perfecta aparte de las salidas perfectamente sincronizadas, pero esta opción puede dar resultados preferibles si las pantallas en una configuración multi-pantalla se reflejan o clonan entre sí. El valor predeterminado es off.
Option "ZaphodHeads" "cadena"
Especifica las salidas RandR a utilizar con el modo zaphod para una instancia particular del controlador. Si utiliza esta opción, debe utilizar esta opción para todas las instancias del controlador.
Por ejemplo: Option "ZaphodHeads" "LVDS,VGA-0" asignará las salidas de xrandr LVDS y VGA-0 a esta instancia del controlador.
Option "UseGammaLUT" "booleano"
Habilita o deshabilita el uso de la propiedad GAMMA_LUT, cuando está disponible. Cuando está habilitado, esta opción permite al controlador utilizar rampas de gamma con más entradas, si es compatible con el kernel. Por defecto, se utilizará GAMMA_LUT para los controladores kms que se sabe que son seguros para usar GAMMA_LUT.
