MOSH(1) Manual de comandos generales MOSH(1)

NOMBRE

mosh - shell móvil con itinerancia y eco local inteligente

SINOPSIS

mosh [opciones] [--] [usuario@]host [comando...]

DESCRIPCIÓN

mosh (mobile shell) es una aplicación de terminal remota que soporta conectividad intermitente, permite la itinerancia y proporciona eco local especulativo y edición de línea de las pulsaciones del usuario.

Comparado con ssh, mosh es más robusto — sus conexiones permanecen activas durante suspensiones y cambios de la dirección IP del cliente — y más receptivo, porque el protocolo es tolerante a la pérdida de paquetes y el cliente puede hacer eco de la mayoría de las pulsaciones inmediatamente, sin esperar una ida y vuelta de red.

mosh utiliza ssh para establecer una conexión con el host remoto y autenticarse con los medios existentes (por ejemplo, autenticación por clave pública o una contraseña). mosh ejecuta el programa auxiliar no privilegiado mosh-server en el servidor, luego cierra la conexión SSH e inicia mosh-client, que establece una conexión de datagramas de larga duración sobre UDP.

Para mejorar la receptividad, mosh ejecuta un modelo predictivo del comportamiento del servidor en segundo plano, intentando adivinar el efecto de cada pulsación en la pantalla. Realiza predicciones para la escritura normal, retroceso (backspace) y las teclas de flecha izquierda y derecha. Cuando está seguro, mosh muestra las predicciones sin esperar al servidor. El modelo predictivo debe demostrarse de nuevo en cada fila de la terminal y después de cada carácter de control, por lo que mosh evita hacer eco de contraseñas o comandos de editor que no hacen eco.

Por defecto, mosh muestra sus predicciones solo en conexiones de alta latencia y para suavizar fallos de red. (En enlaces de latencia más larga, las celdas predichas se subrayan hasta que el servidor las confirma.) Los errores de eco ocasionales se corrigen dentro de una ida y vuelta de red y no causan efectos duraderos.

mosh no soporta reenvío de X ni los usos no interactivos de SSH, incluyendo reenvío de puertos o sshfs. mosh funciona a través de traductores de direcciones de red típicos del lado del cliente, pero requiere que UDP pase entre el cliente y el servidor. Por defecto, mosh usa los puertos entre 60000 y 61000, pero permite al usuario solicitar un puerto UDP particular en su lugar.

Actualmente, mosh tiene soporte limitado para IPv6, redes de doble pila y servidores con múltiples direcciones. Al inicio de la sesión, seleccionará una única dirección de servidor IPv4 o IPv6 a la que conectarse durante la vida de la sesión.

mosh hará todo lo posible para organizar un conjunto de caracteres UTF-8 en el cliente y el servidor. El cliente debe tener variables de entorno relacionadas con la configuración regional que especifiquen UTF-8. mosh pasará estas variables del cliente a mosh-server en su línea de comandos, pero en la mayoría de los casos no necesitarán ser usadas. mosh-server primero intenta usar sus propias variables de entorno relacionadas con la configuración regional, que provienen de la configuración predeterminada del sistema (a veces /etc/default/locale) o de haber sido pasadas a través de la conexión SSH. Pero si estas variables no requieren el uso de UTF-8, mosh-server aplicará las variables de entorno relacionadas con la configuración regional del cliente y lo intentará de nuevo.

OPCIONES

Las opciones llamadas --experimental-* están sujetas a cambios o eliminación en futuras versiones de Mosh; su diseño o función aún no es definitivo.

comando
Comando a ejecutar en el host remoto. Por defecto, mosh ejecuta un shell de inicio de sesión.
--cliente=RUTA
Ruta al ayudante del cliente en la máquina local (por defecto: "mosh-client")
--servidor=COMANDO
Comando para ejecutar el ayudante del servidor en la máquina remota (por defecto: "mosh-server")

El ayudante del servidor no requiere privilegios y puede ser instalado en el directorio personal del usuario.

Esta opción puede ser utilizada para configurar variables de entorno para el servidor usando el comando env(1) para envolver el comando real del servidor. Ver mosh-server(1) para las variables de entorno disponibles.

--ssh=COMANDO
Comando OpenSSH para ejecutar remotamente mosh-server en la máquina remota (por defecto: "ssh")

Se puede especificar un puerto SSH alternativo con, por ejemplo, --ssh="ssh -p 2222".

--ssh-pty
--no-ssh-pty Habilita o deshabilita el uso de un pty por parte de ssh al conectarse a un host remoto. El valor predeterminado es habilitado.
--predict=CUÁNDO
Controla el uso del eco local especulativo. CUÁNDO por defecto es `adaptive' (muestra predicciones en enlaces más lentos y para suavizar fallos de red) y también puede ser `always` (siempre) o `never` (nunca).

La variable de entorno MOSH_PREDICTION_DISPLAY controla esta configuración permanentemente y puede adoptar los mismos tres valores.

Incluso en `always', mosh solo mostrará predicciones cuando esté seguro. Esto generalmente significa que una predicción anterior en la misma fila de la terminal ha sido confirmada por el servidor, sin caracteres de control intermedios.

-a
Sinónimo de --predict=always
-n
Sinónimo de --predict=never
--predict-overwrite
Cuando la predicción está habilitada, no insertar eco local especulativo antes del texto existente, sino sobrescribirlo en su lugar.

La variable de entorno MOSH_PREDICTION_OVERWRITE también habilita esto si su valor es 'yes'.

-o
Sinónimo de --predict-overwrite
--familia=inet
Usar solo IPv4 para la conexión SSH y la sesión Mosh.
--familia=inet6
Usar solo IPv6 para la conexión SSH y la sesión Mosh. Esto y los siguientes modos requieren los módulos IO::Socket::IP o IO::Socket::INET6 de Perl.
--familia=auto
Autodetectar IPv4 o IPv6 para hosts que solo tienen direcciones en una única familia. Los hosts con direcciones IPv4 y IPv6 generarán un error y requerirán una invocación de mosh con otra opción --familia.
--familia=all
Elegir una dirección de todas las direcciones IPv4 o IPv6 disponibles, incluso para hosts de doble pila. Esta es la opción más conveniente, pero requiere conectividad de doble pila y Mosh 1.2.5 o posterior en el servidor, al itinerar con servidores de doble pila.
--familia=preferir-inet
Similar a --familia=all, pero intenta conectarse primero a las direcciones IPv4. Este es el valor predeterminado.
--familia=preferir-inet6
Similar a --familia=all, pero intenta conectarse primero a las direcciones IPv6.
-4
Sinónimo de --familia=inet
-6
Sinónimo de --familia=inet6
-p PUERTO[:PUERTO2], --puerto=PUERTO[:PUERTO2]
Usar un puerto UDP o rango de puertos específico en el lado del servidor, por ejemplo, si este es el único puerto que se reenvía a través de un cortafuegos al servidor. Con -p 0, el servidor dejará que el sistema operativo elija un puerto UDP disponible. De lo contrario, mosh elegirá un puerto entre 60000 y 61000. Tenga en cuenta que esta opción no afecta al puerto del lado del servidor utilizado por SSH.
--enlazar-servidor={ssh|cualquiera|IP}
Controla la dirección IP a la que se enlaza mosh-server.

El valor predeterminado es `ssh', en cuyo caso el servidor responderá desde la dirección IP de la que provino la conexión SSH (según se encuentra en la variable de entorno SSH_CONNECTION). Esto es útil para servidores multihomados.
