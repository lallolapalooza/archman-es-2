MOUNT.NILFS2(8) System Manager's Manual MOUNT.NILFS2(8)

NOMBRE

mount.nilfs2 - montar un sistema de archivos NILFS2

SINOPSIS

mount -t nilfs2 [-finrvw] [-o opciones [,...]] dispositivo directorio
mount -t nilfs2 [-finrvw] [-o opciones [,...]] dispositivo | directorio

mount.nilfs2 [-fnrvw] [-o opciones [,...]] dispositivo directorio

mount.nilfs2 [-V]

DESCRIPCIÓN

mount.nilfs2 sirve para adjuntar un sistema de archivos NILFS2 en el directorio especificado directorio. Está destinado a ser ejecutado desde mount(8), e invocará al recolector de basura nilfs_cleanerd(8) después de que una llamada al sistema de montaje real haya tenido éxito. Por el contrario, umount.nilfs2(8) apagará el recolector de basura antes de desmontar el sistema de archivos.

La interfaz de línea de comandos estándar es la primera forma:


mount -t nilfs2 [opciones] dispositivo directorio
Esto le indica al kernel que adjunte el sistema de archivos NILFS2 en dispositivo en el directorio directorio. Con la segunda forma, el programa de montaje intenta averiguar un argumento faltante de dispositivo o directorio de la tabla /etc/fstab.

La tercera forma, que invoca directamente mount.nilfs2, también es utilizable ya que mount.nilfs2 mantiene por sí mismo el estado de montaje del sistema, como la lista de sistemas de archivos montados descrita en /etc/mtab. Sin embargo, la primera o la segunda forma suelen ser recomendadas, ya que algunas opciones extensas no son compatibles con la tercera forma.

OPCIONES

El conjunto completo de opciones utilizadas por una invocación de mount(8) se determina extrayendo las opciones de la tabla fstab, luego aplicando cualquier opción especificada por el argumento -o, y finalmente aplicando una opción -r o -w, cuando estén presentes.

Consulte mount(8) para ver el conjunto completo de opciones. Las opciones de uso común son las siguientes:

-V
Muestra la versión.
-f
Finge el montaje del sistema de archivos, lo que significa que se omitirá la llamada real al sistema. Esta opción se utiliza para agregar entradas para dispositivos que se montaron anteriormente con la opción -n. También se puede usar para invocar nilfs_cleanerd(8) omitido anteriormente.
-i
No llamar a mount.nilfs2. Esto deshabilita la recolección de basura y el manejo de opciones de montaje pseudo.
-n
Montar sin escribir en /etc/mtab. Esto es necesario, por ejemplo, cuando /etc está en un sistema de archivos de solo lectura.
-r
Montar el sistema de archivos en modo de solo lectura. Un sinónimo es "-o ro".
-v
Modo verboso.
-w
Montar el sistema de archivos en modo lectura/escritura. Este es el valor predeterminado. Un sinónimo es "-o rw".
-o
Las opciones se especifican con un indicador -o seguido de una cadena de opciones separadas por comas. Algunas de estas opciones solo son útiles cuando aparecen en el archivo /etc/fstab. Para las opciones estándar del sistema de archivos, consulte mount(8).

OPCIONES ESPECÍFICAS DE NILFS2

Las siguientes opciones se aplican solo al sistema de archivos NILFS2. Todas siguen el indicador -o.

barrier / nobarrier
Estas opciones habilitan/deshabilitan (el valor predeterminado es habilitado) las escrituras de barrera para la E/S de bloques a un dispositivo inferior. La escritura de barrera juega un papel importante para garantizar la consistencia de los sistemas de archivos después de una caída del sistema o una falla de alimentación. NILFS2 utiliza esta característica por defecto para asegurar la fiabilidad. Para dispositivos que no admiten la escritura de barrera, se deshabilitará automáticamente y se registrará una advertencia.
cp=número-de-punto-de-control
Especifique el número-de-punto-de-control de la instantánea a montar. Los puntos de control y las instantáneas se listan con lscp(1). Solo los puntos de control marcados como instantánea son montables con esta opción. Tenga en cuenta que la opción de montaje de solo lectura debe especificarse juntas.
errors=continue / errors=remount-ro / errors=panic
Define el comportamiento cuando se encuentra un error. (Omitir errores y simplemente marcar el sistema de archivos como erróneo y continuar, o volver a montar el sistema de archivos en modo de solo lectura, o entrar en pánico y detener el sistema.) El valor predeterminado es remount-ro. En kernels anteriores a Linux 2.6.35, continue era el valor predeterminado.
pp=período-de-protección
Especifique el período-de-protección para el demonio limpiador (en segundos). nilfs_cleanerd nunca elimina puntos de control recientes cuyo tiempo transcurrido desde su creación sea inferior a período-de-protección.
nogc
Deshabilita la recolección de basura. El demonio limpiador no se iniciará. Se puede iniciar manualmente, pero en ese caso también deberá detenerse manualmente antes de desmontar.
order=relaxed / order=strict
Especifica la semántica de orden para los datos del archivo. Los metadatos siempre se escriben para seguir la semántica POSIX sobre el orden de las operaciones del sistema de archivos.
relaxed
Aplica una semántica de orden relajada que permite escribir bloques de datos modificados en el disco sin crear un punto de control si no hay ninguna actualización de metadatos en curso. Este modo es equivalente al modo de datos ordenados del sistema de archivos ext3, excepto que las actualizaciones en los bloques de datos aún conservan la atomicidad. Esto mejorará el rendimiento de escritura síncrona para sobrescrituras. Este es el modo predeterminado.
strict
Aplica una semántica estricta en orden que preserva la secuencia de todas las operaciones de archivo, incluidas las sobrescrituras de bloques de datos. Esto significa que se garantiza que no ocurrirán adelantamientos de eventos en el sistema de archivos recuperado después de una caída. A diferencia de los sistemas de archivos con registro por diario, NILFS2 no escribe el mismo bloque dos veces en el disco. Por lo tanto, no hay una degradación significativa del rendimiento en comparación con el modo relajado, excepto para la sobrescritura de archivos.
norecovery
Deshabilita la recuperación del sistema de archivos al montarlo. Esto deshabilita todos los accesos de escritura en el dispositivo para montajes de solo lectura o instantáneas. Esta opción fallará para montajes r/w en un volumen no limpio.
discard / nodiscard
Estas opciones habilitan/deshabilitan (el valor predeterminado es deshabilitado) el uso de comandos discard/TRIM. Los comandos discard/TRIM se envían al dispositivo de bloques subyacente cuando se liberan bloques. Esto es útil para dispositivos SSD y LUNs dispersos/con aprovisionamiento ligero. (desde 2.6.34).

CÓDIGOS DE RETORNO

Los códigos de retorno de mount.nilfs2 se ajustan a los de mount(8); se podrían devolver los siguientes códigos (los bits se pueden combinar con OR):

0
éxito
1
invocación o permisos incorrectos
2
error del sistema (memoria agotada, no se puede bifurcar, no hay más dispositivos en bucle)
4
error interno
8
interrupción del usuario
16
problemas al escribir o bloquear /etc/mtab
32
fallo de montaje
64
algunos montajes tuvieron éxito
