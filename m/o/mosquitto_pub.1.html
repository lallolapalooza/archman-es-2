NOMBRE

mosquitto_pub - un cliente MQTT versión 5/3.1.1/3.1 para publicar mensajes simples

SINOPSIS

mosquitto_pub {[-h nombre-host] [--unix ruta-socket] [-p numero-puerto] [-u nombre-usuario] [-P contraseña] -t tema-mensaje... | -L URL} [-A direccion-enlace] [-c] [-d] [-D comando identificador valor] [-i id-cliente] [-I prefijo-id-cliente] [-k tiempo-mantener-vivo] [--nodelay] [-q QoS-mensaje] [--quiet] [-r] [--repeat contador] [--repeat-delay segundos] [-S] [-V version-protocolo] [-x intervalo-caducidad-sesion] {-f archivo | -l | -m mensaje | -n | -s} [--will-topic tema [--will-payload carga-util] [--will-qos qos] [--will-retain]] [[{--cafile archivo | --capath directorio} [--cert archivo] [--key archivo] [--ciphers cifrados] [--tls-version version] [--tls-alpn protocolo] [--tls-engine motor] [--keyform {pem | motor}] [--tls-engine-kpass-sha1 kpass-sha1] [--tls-use-os-certs] [--insecure]] | [--psk clave-hex --psk-identity identidad [--ciphers cifrados] [--tls-version version]]] [--proxy url-socks]

mosquitto_pub [--help]

DESCRIPCIÓN

mosquitto_pub es un cliente sencillo de MQTT versión 5 que publicará un único mensaje en un tema y saldrá.

CONEXIONES CIFRADAS

mosquitto_pub soporta conexiones cifradas con TLS. Se recomienda encarecidamente utilizar una conexión cifrada para cualquier cosa más allá de la configuración más básica.

Para habilitar conexiones TLS al usar certificados x509, se puede proporcionar una de las opciones --cafile o --capath.

Alternativamente, si se usa la opción -p 8883, se cargarán los certificados proporcionados por el sistema operativo y no se necesitarán ni --cafile ni --capath.

Para habilitar conexiones TLS al usar TLS-PSK, debes usar las opciones --psk y --psk-identity.

OPCIONES

Las siguientes opciones pueden darse en la línea de comandos, pero también pueden colocarse en un archivo de configuración ubicado en $XDG_CONFIG_HOME/mosquitto_pub o $HOME/.config/mosquitto_pub con un par de -opción valor por línea. Los valores en el archivo de configuración se usarán como valores predeterminados y pueden ser anulados usando la línea de comandos. Las excepciones a esto son las opciones de tipo de mensaje, de las cuales solo se puede especificar una. Tenga en cuenta también que actualmente algunas opciones no se pueden negar, por ejemplo, -S. Las líneas del archivo de configuración que tienen un # como primer carácter se tratan como comentarios y no se procesan más.

-A

Enlaza la conexión saliente a una dirección/nombre de host IP local. Usa este argumento si necesitas restringir la comunicación de red a una interfaz particular.

-c, --disable-clean-session

Deshabilita la 'sesión limpia' / habilita el modo de cliente persistente. Cuando se usa este argumento, se instruirá al broker a no limpiar las sesiones existentes para el mismo id de cliente cuando el cliente se conecte, y las sesiones nunca caducarán cuando el cliente se desconecte. Los clientes MQTT v5 pueden cambiar su intervalo de caducidad de sesión con el argumento -x.

Cuando una sesión se mantiene en el broker, las suscripciones para el cliente se mantendrán después de que se desconecte, junto con los mensajes posteriores de QoS 1 y QoS 2 que lleguen. Cuando el cliente se vuelva a conectar y no limpie la sesión, recibirá todos los mensajes en cola.

Si usas esta opción, el id de cliente debe establecerse manualmente con --id

--cafile

Define la ruta a un archivo que contenga certificados CA codificados en PEM en los que se confía. Se usa para habilitar la comunicación SSL.

Ver también --capath

--capath

Define la ruta a un directorio que contenga certificados CA codificados en PEM en los que se confía. Se usa para habilitar la comunicación SSL.

Para que --capath funcione correctamente, los archivos de certificado deben tener ".crt" como extensión de archivo y debes ejecutar "openssl rehash <ruta a capath>" cada vez que agregues/elimines un certificado.

Ver también --cafile

--cert

Define la ruta a un archivo que contenga un certificado codificado en PEM para este cliente, si es requerido por el servidor.

Ver también --key y la sección Conexiones Cifradas.

--ciphers

Una lista de cifrados TLS compatible con openssl para soportar en el cliente. Ver ciphers(1) para más información.

-d, --debug

Habilita mensajes de depuración.

-D, --property

Usa una propiedad MQTT v5 con esta publicación. Si usas esta opción, el cliente se configurará como un cliente MQTT v5. Esta opción tiene dos formas:

-D comando identificador valor

-D comando identificador nombre valor

comando es el identificador del comando/paquete MQTT y puede ser uno de CONNECT, PUBLISH, PUBREL, DISCONNECT, AUTH o WILL. Las propiedades disponibles para cada comando se enumeran en la sección Propiedades.

identificador es el nombre de la propiedad a añadir. Esto es como se describe en la especificación, pero con '-' como separador de palabras. Por ejemplo: payload-format-indicator. Más detalles están en la sección Propiedades.

valor es el valor de la propiedad a añadir, con un tipo de datos que es específico de la propiedad.

nombre solo se usa para la propiedad user-property como la primera de las dos cadenas en el par de cadenas. En ese caso, valor es la segunda de las cadenas del par.

-f, --file

Envía el contenido de un archivo como mensaje.

--help

Muestra información de uso.

-h, --host

Especifica el host al que conectarse. Por defecto es localhost.

-i, --id

El id a usar para este cliente. Si no se proporciona, se generará un id de cliente dependiendo de la versión de MQTT que se esté utilizando. Para v3.1.1/v3.1, el cliente genera un id de cliente en el formato mosq-XXXXXXXXXXXXXXXXXX, donde las X se reemplazan con caracteres alfanuméricos aleatorios. Para v5.0, el cliente envía un id de cliente de longitud cero, y el servidor generará un id de cliente para el cliente.

Esta opción no se puede usar al mismo tiempo que el argumento --id-prefix.

-I, --id-prefix

Proporciona un prefijo a partir del cual se construirá el id de cliente añadiendo el proceso id del cliente. Esto es útil cuando el broker está utilizando la opción clientid_prefixes. No se puede usar al mismo tiempo que el argumento --id.

--insecure

Al usar cifrado basado en certificados, esta opción deshabilita la verificación del nombre de host del servidor en el certificado del servidor. Esto puede ser útil al probar configuraciones iniciales del servidor, pero hace posible que un tercero malintencionado suplante tu servidor a través de la suplantación de DNS, por ejemplo. Usa esta opción solo para pruebas. Si necesitas recurrir a usar esta opción en un entorno de producción, tu configuración es defectuosa y no tiene sentido usar el cifrado.

-k, --keepalive

El número de segundos entre el envío de comandos PING al broker con el propósito de informarle que todavía estamos conectados y funcionando. Por defecto es 60 segundos.

--key

Define la ruta a un archivo que contenga una clave privada codificada en PEM para este cliente, si es requerida por el servidor.

VER TAMBIÉN

r.

Véase también --cert y la sección Conexiones Cifradas.

--keyform

Especifica el tipo de clave privada en uso al establecer conexiones TLS. Puede ser "pem" o "engine". Este parámetro es útil cuando se utiliza un módulo TPM y la clave privada se ha creado con él. Por defecto es "pem", lo que significa que se utilizan archivos de clave privada normales.

Véase también --tls-engine.

-L, --url

Especifica usuario, contraseña, nombre de host, puerto y tema a la vez como una URL. La URL debe tener el formato: mqtt(s)://[usuario[:contraseña]@]host[:puerto]/tema

Si el esquema es mqtt:// entonces el puerto por defecto es 1883. Si el esquema es mqtts:// entonces el puerto por defecto es 8883.

-l, --stdin-line

Envía mensajes leídos desde la entrada estándar, dividiendo las líneas separadas en mensajes separados.

-m, --message

Envía un único mensaje desde la línea de comandos.

-n, --null-message

Envía un mensaje nulo (de longitud cero).

--nodelay

Deshabilita el algoritmo de Nagle para el socket. Esto significa que la latencia de los mensajes enviados se reduce, lo que es particularmente notable para mensajes pequeños y razonablemente infrecuentes. El uso de esta opción puede resultar en el envío de más paquetes de los que serían necesarios normalmente.

-p, --port

Conéctese al puerto especificado. Si no se proporciona, se utilizará el valor por defecto de 1883 para MQTT plano o 8883 para MQTT sobre TLS.

-P, --pw

Proporcione una contraseña que se utilizará para la autenticación con el broker. Usar este argumento sin especificar también un nombre de usuario no es válido cuando se utiliza MQTT v3.1 o v3.1.1. Véase también la opción --username.

--proxy

Especifique un proxy SOCKS5 para conectarse. Se admiten los tipos de autenticación "None" y "username". La URL de socks debe tener el formato socks5h://[usuario[:contraseña]@]host[:puerto]. El prefijo del protocolo socks5h significa que los nombres de host son resueltos por el proxy. Los símbolos %25, %3A y %40 se decodifican de URL a %, : y @ respectivamente, si están presentes en el nombre de usuario o la contraseña.

Si no se proporciona nombre de usuario, no se intenta ninguna autenticación. Si no se proporciona puerto, se utiliza el valor por defecto de 1080.

Puede haber más versiones de SOCKS disponibles en el futuro, dependiendo de la demanda, y utilizarán diferentes prefijos de protocolo, como se describe en curl(1).

--psk

Proporcione la clave precompartida hexadecimal (sin prefijo 0x) que coincida con la utilizada en el broker para utilizar soporte de cifrado TLS-PSK. También debe proporcionarse --psk-identity para habilitar TLS-PSK.

--psk-identity

La identidad del cliente a utilizar con el soporte TLS-PSK. Esto puede utilizarse en lugar de un nombre de usuario si el broker está configurado para hacerlo.

-q, --qos

Especifique la calidad de servicio a utilizar para el mensaje, de 0, 1 y 2. Por defecto es 0.

--quiet

Si se proporciona este argumento, no se imprimirán errores en tiempo de ejecución. Esto excluye cualquier mensaje de error dado en caso de entrada de usuario inválida (por ejemplo, usar --port sin un puerto).

-r, --retain

Si se proporciona retain, el mensaje se conservará como un valor de "último conocido bueno" en el broker. Consulte mqtt(7) para más información. Tenga en cuenta que las cargas útiles de longitud cero nunca se conservan. Si envía un mensaje conservado de carga útil de longitud cero, eliminará cualquier mensaje conservado en el tema.

--repeat

Si el modo de publicación es -m, -f o -s (es decir, los modos en los que solo se envía un mensaje), entonces se puede utilizar --repeat para especificar que el mensaje se publicará varias veces.

Véase también --repeat-delay.

--repeat-delay

Si se utiliza --repeat, el comportamiento por defecto es publicar mensajes repetidos tan pronto como se entregue el mensaje anterior. Utilice --repeat-delay para especificar el número de segundos a esperar después de que se entregó el mensaje anterior antes de publicar el siguiente. No tiene que ser un número entero de segundos.

Tenga en cuenta que no hay garantía sobre el intervalo real entre mensajes, esta opción simplemente define el tiempo mínimo desde la entrega de un mensaje hasta el inicio de la publicación del siguiente.

-s, --stdin-file

Envía un mensaje leído desde la entrada estándar, enviando el contenido completo como un único mensaje.

-S

Utiliza búsquedas SRV para determinar a qué host conectarse. Realiza búsquedas en _mqtt._tcp.<host> cuando se utiliza junto con -h, de lo contrario utiliza _mqtt._tcp.<dominio dns local>.

-t, --topic

El tema MQTT en el que publicar el mensaje. Consulte mqtt(7) para más información sobre los temas MQTT.

--tls-alpn

Proporcione un protocolo a utilizar al conectarse a un broker que tiene múltiples protocolos disponibles en un solo puerto, por ejemplo, MQTT y WebSockets.

--tls-engine

Un ID de motor openssl válido. Estos pueden listarse con el comando openssl engine.

Véase también --keyform.

--tls-engine-kpass-sha1

SHA1 de la contraseña de la clave privada al usar un motor TLS. Algunos motores TLS, como el motor TPM, pueden requerir el uso de una contraseña para ser accedidos. Esta opción permite pasar un hash SHA1 codificado en hexadecimal de la contraseña directamente al motor, en lugar de que el usuario sea preguntado por la contraseña.

Véase también --tls-engine.

--tls-use-os-certs

Si se utiliza, cargará y confiará en los certificados CA proporcionados por el sistema operativo. Esto se puede utilizar junto con --cafile y --capath y se puede usar por sí solo para habilitar el modo TLS. Esto se establecerá por defecto si se usa -L mqtts://..., o si el puerto es 8883 y no se utilizan otras opciones de certificado.

--tls-version

Elija qué versión del protocolo TLS se debe utilizar al comunicarse con el broker. Las opciones válidas son tlsv1.3, tlsv1.2 y tlsv1.1. El valor por defecto es tlsv1.2. Debe coincidir con la versión del protocolo utilizada por el broker.

-u, --username

Proporcione un nombre de usuario que se utilizará para la autenticación con el broker. Véase también el argumento --pw.

--unix

Conéctese a un broker a través de un socket de dominio Unix local en lugar de un socket TCP. Esto es un reemplazo para -h y -L. Por ejemplo: mosquitto_pub --unix /tmp/mosquitto.sock ...

Consulte la opción socket_domain en mosquitto.conf(5) para configurar Mosquitto para escuchar en un socket Unix.

-V, --protocol-version

Especifique qué versión del protocolo MQTT se debe utilizar al conectarse al broker remoto. Puede ser 5, 311, 31, o las versiones más verbosas mqttv5, mqttv311, o mqttv31. Por defecto es 311.

--will-payload

Especifique un mensaje que será almacenado por el broker y enviado si este cliente se desconecta inesperadamente. Esto debe usarse en conjunción con --will-topic.

--will-qos

El QoS a utilizar para el Will. Por defecto es 0. Esto debe usarse en conjunción con --will-topic.

--will-retain

Si se proporciona, si el cliente se desconecta inesperadamente, el mensaje enviado se tratará como un mensaje conservado. Esto debe usarse en conjunción con --will-topic. Tenga en cuenta que las cargas útiles de longitud cero nunca se conservan. Si envía un mensaje conservado de carga útil de longitud cero, eliminará cualquier mensaje conservado en el tema.

--will-topic

El tema en el que enviar un Will, en caso de que el cliente se desconecte inesperadamente.

-x

Establece el intervalo de expiración de sesión en el paquete CONNECT. Se aplica solo a clientes MQTT v5. Establézcalo en 0-4294967294 para especificar que la sesión expirará en esa cantidad de segundos después de que el cliente se desconecte, o utilice -1, 4294967295 o ∞ para una sesión que no expire. Por defecto es -1 si también se proporciona -c, o 0 si no se proporciona -c.

Si la sesión se establece para que nunca expire, ya sea con -x o -c, entonces se debe proporcionar un ID de cliente.

WILLS

mosquitto_sub puede registrar un mensaje con el broker que se enviará si se desconecta inesperadamente. Consulte mqtt(7) para más información.

El requisito mínimo para esto es usar --will-topic para especificar en qué tema se enviará el will. Esto resultará en un mensaje no conservado, de longitud cero y con QoS 0.

Utilice los argumentos --will-retain, --will-payload y --will-qos para modificar los otros parámetros del will.

ESTADO DE SALIDA

mosquitto_sub devuelve cero en caso de éxito o un valor distinto de cero en caso de error. Si la conexión es rechazada por el broker a nivel MQTT, el código de salida es el código de razón CONNACK. Si ocurre otro error, el código de salida es un valor de retorno de libmosquitto.

Códigos CONNACK de MQTT v3.1.1:

•0 Éxito
•1 Conexión rechazada: versión de protocolo incorrecta
•2 Conexión rechazada: identificador rechazado
•3 Conexión rechazada: servidor no disponible
•4 Conexión rechazada: nombre de usuario/contraseña incorrecto
•5 Conexión rechazada: no autorizado

Códigos CONNACK de MQTT v5:

•0 Éxito
•128 Error no especificado
•129 Paquete mal formado
•130 Error de protocolo
•131 Error específico de la implementación
•132 Versión de protocolo no admitida
•133 ID de cliente no válido
•134 Nombre de usuario o contraseña incorrectos
•135 No autorizado
•136 Servidor no disponible
•137 Servidor ocupado
•138 Prohibido
•139 El servidor se está apagando
•140 Método de autenticación incorrecto
•141 Tiempo de espera de Keep alive agotado
•142 Sesión asumida
•143 Filtro de tema no válido
•144 Nombre de tema no válido
•147 Se superó el máximo de recepción
•148 Alias de tema no válido
•149 Paquete demasiado grande
•148 Tasa de mensajes demasiado alta
•151 Cuota excedida
•152 Acción administrativa
•153 Formato de carga útil no válido
•154 Retención no admitida
•155 QoS no admitido
•156 Usa otro servidor
•157 El servidor se ha movido
•158 Suscripciones compartidas no admitidas
•159 Tasa de conexión excedida
•160 Tiempo máximo de conexión
•161 IDs de suscripción no admitidos
•162 Suscripciones comodín no admitidas

EJEMPLOS

Publicar información de temperatura en localhost con QoS 1:

•mosquitto_pub -t sensors/temperature -m 32 -q 1

Publicar información de marca de tiempo y temperatura a un host remoto en un puerto no estándar y QoS 0:

•mosquitto_pub -h 192.168.1.1 -p 1885 -t sensors/temperature -m "1266193804 32"

Publicar el estado del interruptor de luz. El mensaje se establece como retenido porque puede haber un largo período de tiempo entre los eventos del interruptor de luz:

•mosquitto_pub -r -t switches/kitchen_lights/status -m "on"

Enviar el contenido de un archivo de dos maneras:

•mosquitto_pub -t my/topic -f ./data
•mosquitto_pub -t my/topic -s < ./data

Enviar datos de uso de electricidad analizados de un medidor Current Cost, leyendo desde la entrada estándar con una línea/lectura como un mensaje:

•read_cc128.pl | mosquitto_pub -t sensors/cc128 -l
