MODPROBE.D(5) modprobe.d MODPROBE.D(5)

NOMBRE

modprobe.d - Directorio de configuración para modprobe

SINOPSIS

/etc/modprobe.d/*.conf

/run/modprobe.d/*.conf

/usr/local/lib/modprobe.d/*.conf

/usr/lib/modprobe.d/*.conf

/lib/modprobe.d/*.conf

DESCRIPCIÓN

Dado que el comando modprobe puede añadir o eliminar más de un módulo, debido a que los módulos tienen dependencias, necesitamos un método para especificar qué opciones se van a usar con esos módulos. Uno puede también usarlos para crear alias convenientes: nombres alternativos para un módulo, o pueden anular el comportamiento normal de modprobe completamente para aquellos con requisitos especiales (como insertar más de un módulo).

Tenga en cuenta que los nombres de módulos y alias (como otros nombres de módulos) pueden tener - o _ en ellos: ambos son intercambiables en todos los comandos de módulos ya que la conversión de guiones bajos ocurre automáticamente.

FORMATO DE CONFIGURACIÓN

Los archivos de configuración contienen un comando por línea, y se ignoran las líneas en blanco y las que empiezan con '#' (útil para añadir comentarios). Una '\' al final de una línea provoca que continúe en la siguiente línea, lo que hace que los archivos sean un poco más limpios.

Ver la sección COMANDOS a continuación para más detalles.

DIRECTORIOS DE CONFIGURACIÓN Y PRECEDENCIA

Los archivos de configuración se leen de los directorios listados en el SINOPSIS en ese orden de precedencia. Una vez que se carga un archivo con un nombre dado, se ignora cualquier archivo con el mismo nombre en directorios posteriores.

Todos los archivos de configuración se ordenan lexicográficamente, independientemente del directorio en el que residan. Los archivos de configuración pueden ser reemplazados completamente (teniendo un nuevo archivo de configuración con el mismo nombre en un directorio de mayor prioridad) o reemplazados parcialmente (teniendo un archivo de configuración que se ordene más tarde).

NOTA: Los directorios de configuración pueden ser alterados a través de la variable de entorno MODPROBE_OPTIONS. Ver la sección ENTORNO en modprobe(8).

COMANDOS

alias patrón nombre_módulo

Esto te permite dar nombres alternativos a un módulo. Por ejemplo: "alias mi-mod nombre_módulo_muy_largo" significa que puedes usar "modprobe mi-mod" en lugar de "modprobe nombre_módulo_muy_largo". También puedes usar comodines estilo shell, así que "alias mi-mod* nombre_módulo_muy_largo" significa que "modprobe mi-mod-algo" tiene el mismo efecto. No puedes tener alias a otros alias (eso lleva a la locura), pero los alias pueden tener opciones, que se añadirán a cualquier otra opción.

Ten en cuenta que los módulos también pueden contener sus propios alias, que puedes ver usando modinfo. Estos alias se usan como último recurso (es decir, si no hay un comando real de módulo, install, remove, o alias en la configuración).

blacklist nombre_módulo

Los módulos pueden contener sus propios alias: generalmente son alias que describen los dispositivos que soportan, como "pci:123...". Estos alias "internos" pueden ser anulados por palabras clave normales de "alias", pero hay casos en los que dos o más módulos soportan los mismos dispositivos, o un módulo reclama inválidamente soportar un dispositivo que no lo hace: la palabra clave blacklist indica que todos los alias internos de ese módulo en particular deben ser ignorados.

install nombre_módulo comando...

Este comando instruye a modprobe para que ejecute tu comando en lugar de insertar el módulo en el kernel como de costumbre. El comando puede ser cualquier comando de shell: esto te permite hacer cualquier tipo de procesamiento complejo que desees. Por ejemplo, si el módulo "fred" funciona mejor con el módulo "barney" ya instalado (pero no depende de él, por lo que modprobe no lo cargará automáticamente), podrías decir "install fred /sbin/modprobe barney; /sbin/modprobe --ignore-install fred", lo que haría lo que quisieras. Nota el --ignore-install, que evita que el segundo modprobe ejecute el mismo comando install de nuevo. Ver también remove a continuación.

El futuro a largo plazo de este comando como solución al problema de proporcionar dependencias de módulos adicionales no está asegurado y se pretende reemplazar este comando con una advertencia sobre su eventual eliminación o desaprobación en algún momento en una futura versión. Su uso complica la determinación automática de las dependencias de módulos por parte de las utilidades de distribución, como mkinitrd (porque estas ahora necesitan interpretar de alguna manera lo que los comandos de install podrían estar haciendo. En un mundo perfecto, los módulos proporcionarían toda la información de dependencias sin usar este comando y se está trabajando para implementar el soporte de dependencias blandas dentro del kernel de Linux.

Si usas la cadena "$CMDLINE_OPTS" en el comando, será reemplazada por cualquier opción especificada en la línea de comandos de modprobe. Esto puede ser útil porque los usuarios esperan que "modprobe fred opt=1" pase el argumento "opt=1" al módulo, incluso si hay un comando install en el archivo de configuración. Así, nuestro ejemplo anterior se convierte en "install fred /sbin/modprobe barney; /sbin/modprobe --ignore-install fred $CMDLINE_OPTS"

options nombre_módulo opción...

Este comando te permite añadir opciones al módulo nombre_módulo (que podría ser un alias) cada vez que se inserta en el kernel: ya sea directamente (usando modprobe nombre_módulo) o porque el módulo que se está insertando depende de este módulo.

Todas las opciones se suman: pueden provenir de una option para el módulo en sí, para un alias, y en la línea de comandos.

remove nombre_módulo comando...

Esto es similar al comando install de arriba, excepto que se invoca cuando se ejecuta "modprobe -r".

softdep nombre_módulo pre: módulos... post: módulos...

El comando softdep te permite especificar dependencias de módulos blandas u opcionales. El nombre_módulo puede usarse sin que los módulos opcionales estén instalados, pero generalmente con algunas características faltantes. Por ejemplo, un controlador para un HBA de almacenamiento podría requerir que otro módulo se cargue para usar funciones de gestión.

Los módulos pre-dependencias y post-dependencias son listas de nombres y/o alias de otros módulos que modprobe intentará instalar (o eliminar) en orden antes y después del módulo principal dado en el argumento nombre_módulo.

Ejemplo: Supongamos que "softdep c pre: a b post: d e" se proporciona en la configuración. Ejecutar "modprobe c" es ahora equivalente a "modprobe a b c d e" sin el softdep. Las banderas como --use-blacklist se aplican a todos los módulos especificados, mientras que los parámetros del módulo solo se aplican al módulo c.

Nota: si hay comandos install o remove con el mismo argumento nombre_módulo, softdep tiene precedencia.

weakdep nombre_módulo módulos...

El comando weakdep te permite especificar dependencias de módulos débiles. Estos son similares a las pre-dependencias blandas, con la diferencia de que el espacio de usuario no intenta cargar esa dependencia antes del módulo especificado. En su lugar, el kernel puede solicitar uno o varios de ellos durante la inspección del módulo, dependiendo del hardware al que se esté enlazando. El propósito de los módulos débiles es permitir que un controlador especifique que puede ser necesaria cierta dependencia, por lo que debería estar presente en el sistema de archivos (por ejemplo, en initramfs) cuando se inspeccione ese módulo.

Ejemplo: Supongamos "weakdep c a b". Un programa que crea un initramfs sabe que debe añadir a, b y c al sistema de archivos ya que a y b pueden ser necesarios/deseados en tiempo de ejecución. Cuando c se carga y está siendo inspeccionado, puede emitir llamadas a request_module() haciendo que a o b también se carguen.
