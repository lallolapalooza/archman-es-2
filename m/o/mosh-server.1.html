NOMBRE

mosh-server - auxiliar del lado del servidor para mosh

SINOPSIS

mosh-server new [-s] [-v] [-i IP] [-p PUERTO[:PUERTO2]] [-c COLORES] [-- comando...]

DESCRIPCIÓN

mosh-server es un programa auxiliar para la aplicación terminal remota mosh(1).

mosh-server se enlaza a un puerto UDP alto y elige una clave de cifrado para proteger la sesión. Imprime ambos en la salida estándar, se separa de la terminal y espera a que mosh-client establezca una conexión. Saldrá si ningún cliente lo ha contactado en 60 segundos.

Por defecto, mosh-server se enlaza a un puerto entre 60000 y 61000 y ejecuta el shell de inicio de sesión del usuario.

En plataformas con utempter, mosh-server mantiene una entrada en el archivo utmp(5) para indicar su ID de proceso, si la sesión está conectada y la dirección IP actual del cliente.

mosh-server sale cuando el cliente termina la conexión.

OPCIONES

El argumento "new" debe ir primero en la línea de comandos para usar las opciones de línea de comandos.

-s
enlazar a la interfaz local utilizada para una conexión SSH entrante, dada en la variable de entorno SSH_CONNECTION (para hosts multihomados)
-v
Imprime información de depuración incluso después de separarse. Más instancias de esta opción resultarán en más información de depuración.
-i IP
dirección IP de la interfaz local a enlazar (para hosts multihomados)
-p PUERTO[:PUERTO2]
número de puerto UDP o rango de puertos a enlazar. -p 0 permitirá al sistema operativo elegir un puerto UDP disponible.
-c COLORES
número de colores a anunciar a las aplicaciones a través de TERM (por ejemplo, 8, 256)
-l NOMBRE=VALOR
variable de entorno relacionada con la configuración regional para intentar como parte de un entorno de reserva, si el entorno de inicio no especifica un conjunto de caracteres UTF-8.

VARIABLES DE ENTORNO

Estas variables permiten la configuración del comportamiento de Mosh del lado del servidor. Pueden ser establecidas por administradores en archivos de inicio/rc del sistema, /etc/login.conf, o mecanismos similares, o por usuarios en sus archivos de inicio/rc de shell. mosh-server pasa estas variables a la sesión de inicio y al shell que inicia, pero cambiarlas allí no tendrá ningún efecto.

MOSH_SERVER_NETWORK_TMOUT
Si esta variable está configurada a un número entero positivo, especifica cuánto tiempo (en segundos) mosh-server esperará para recibir una actualización del cliente antes de salir. Dado que mosh es muy útil para clientes móviles con operación y conectividad intermitentes, sugerimos establecer esta variable a un valor alto, como 604800 (una semana) o 2592000 (30 días). De lo contrario, mosh-server esperará indefinidamente a que un cliente reaparezca. Esta variable es algo similar a la variable TMOUT que se encuentra en muchos shells Bourne. Sin embargo, no es un tiempo de espera de inactividad de la sesión de inicio; solo se aplica a la conectividad de red.
MOSH_SERVER_SIGNAL_TMOUT
Si esta variable está configurada a un número entero positivo, especifica cuánto tiempo (en segundos) mosh-server ignorará SIGUSR1 mientras espera recibir una actualización del cliente. De lo contrario, SIGUSR1 siempre terminará mosh-server. Los usuarios y administradores pueden implementar scripts para limpiar sesiones Mosh desconectadas. Con esta variable configurada, un usuario o administrador puede ejecutar 
$ pkill -SIGUSR1 mosh-server

para matar sesiones desconectadas sin matar sesiones de inicio conectadas.

EJEMPLO

$ mosh-server
MOSH CONNECT 60001 UAkFedSsVJs2LfMeKyQB5g
mosh-server (mosh 1.1)
[...] (aviso de copyright omitido)
[mosh-server separado, pid = 20443]
