NOMBRE

systemd-dissect, mount.ddi - Diseccionar Imágenes de Disco Descubribles (DDI)

SINOPSIS

systemd-dissect [OPCIONES...] IMAGEN

systemd-dissect [OPCIONES...] [--mount] IMAGEN RUTA

systemd-dissect [OPCIONES...] [--umount] RUTA

systemd-dissect [OPCIONES...] [--attach] IMAGEN

systemd-dissect [OPCIONES...] [--detach] RUTA

systemd-dissect [OPCIONES...] [--list] IMAGEN

systemd-dissect [OPCIONES...] [--mtree] IMAGEN

systemd-dissect [OPCIONES...] [--with] IMAGEN [COMANDO...]

systemd-dissect [OPCIONES...] [--copy-from] IMAGEN RUTA [DESTINO]

systemd-dissect [OPCIONES...] [--copy-to] IMAGEN [ORIGEN] RUTA

systemd-dissect [OPCIONES...] [--make-archive] IMAGEN [DESTINO]

systemd-dissect [OPCIONES...] [--discover]

systemd-dissect [OPCIONES...] [--validate] IMAGEN

systemd-dissect [OPCIONES...] [--shift] IMAGEN UIDBASE

DESCRIPCIÓN

systemd-dissect es una herramienta para inspeccionar e interactuar con imágenes de disco de sistemas operativos, específicamente Imágenes de Disco Descubribles (DDI). Soporta cuatro operaciones diferentes:

1.Mostrar información general de la imagen del SO, incluyendo los datos os-release(5) de la imagen, ID de máquina, información de particiones y más.
2.Montar una imagen de SO en un directorio local. En este modo, diseccionará la imagen del SO y montará las particiones incluidas según su designación en un directorio y posiblemente subdirectorios.
3.Desmontar una imagen de SO de un directorio local. En este modo, desmontará recursivamente las particiones montadas y eliminará el dispositivo de bucle subyacente, incluyendo todos los dispositivos de subpartición.
4.Copiar archivos y directorios dentro y fuera de una imagen de SO.

La herramienta puede operar sobre tres tipos de imágenes de SO:

1.Imágenes de disco de SO que contienen un sobre de tabla de particiones GPT, con particiones marcadas según la Especificación de Particiones Descubribles[1].
2.Imágenes de disco de SO que contienen solo un sistema de archivos simple sin una tabla de particiones envolvente. (Se asume que este sistema de archivos es el sistema de archivos raíz del SO.)
3.Imágenes de disco de SO que contienen una tabla de particiones GPT o MBR, con una sola partición. (Se asume que esta partición contiene el sistema de archivos raíz del SO.)

Las imágenes de SO pueden usar cualquier tipo de sistema de archivos soportado por Linux. Además, pueden hacer uso de cifrado de disco LUKS y contener información de integridad Verity. Tenga en cuenta que las imágenes de SO que cumplan los requisitos pueden ser iniciadas con el modificador --image= de systemd-nspawn(1), y ser utilizadas como sistema de archivos raíz para servicios del sistema usando la configuración de unidad RootImage=, vea systemd.exec(5).

Tenga en cuenta que la tabla de particiones que se muestra cuando se invoca sin un modificador de comando (como se lista a continuación) no necesariamente muestra todas las particiones incluidas en la imagen, sino solo las particiones que son entendidas y consideradas parte de una imagen de disco de SO. Específicamente, se ignoran las particiones de tipos desconocidos, así como las particiones duplicadas (es decir, más de una por tipo de partición), y las particiones raíz y de /usr/ de arquitecturas no compatibles con el sistema local. En otras palabras: esta herramienta mostrará con lo que opera al montar la imagen. Para mostrar la lista completa de particiones, utilice una herramienta como fdisk(8).

El comando systemd-dissect puede invocarse como mount.ddi, en cuyo caso implementa la interfaz de "helper externo" de mount(8). Esto asegura que las imágenes de disco compatibles con systemd-dissect puedan ser montadas directamente por mount y fstab(5). Para más detalles, vea abajo.

En lugar de la ruta de la imagen, se puede especificar un directorio versión ".v/", vea systemd.v(7) para más detalles.

COMANDOS

Si no se pasan ninguno de los modificadores de comando listados a continuación, la imagen de disco especificada se abre y se muestra información general sobre la imagen y las particiones contenidas y su uso.

--mount, -m

Monta la imagen de SO especificada en el directorio especificado. Esto diseccionará la imagen, determinará el sistema de archivos raíz del SO —así como posiblemente otras particiones— y las montará en el directorio especificado. Si la imagen de SO contiene múltiples particiones marcadas con la Especificación de Particiones Descubribles[1], se establecerán múltiples montajes anidados. Este comando espera dos argumentos: una ruta a un archivo de imagen y una ruta a un directorio donde montar la imagen.

Para desmontar una imagen de SO montada de esta manera, use la operación --umount.

Cuando la imagen de SO contiene sistemas de archivos cifrados con LUKS o protegidos con integridad Verity, se configuran volúmenes apropiados y se marcan para desmontaje automático cuando se desmonta la imagen.

La imagen de SO puede especificarse como una ruta a una imagen de SO almacenada en un archivo regular o puede referirse a un nodo de dispositivo de bloque (en este último caso, el dispositivo de bloque debe ser el dispositivo "completo", es decir, no un dispositivo de partición). (Los otros comandos soportados descritos aquí también soportan esto).

Todos los sistemas de archivos montados se verifican con la implementación apropiada de fsck(8) en modo de corrección automática, a menos que se desactive explícitamente (--fsck=no) o se solicite operación de solo lectura (--read-only).

Tenga en cuenta que esta funcionalidad también está disponible en mount(8) a través de un comando como mount -t ddi myimage.raw targetdir/, así como en fstab(5). Para más detalles, vea abajo.

Añadido en la versión 247.

-M

Este es un atajo para --mount --mkdir.

Añadido en la versión 247.

--umount, -u

Desmonta una imagen de SO del directorio especificado. Este comando espera un argumento: un directorio donde se montó una imagen de SO.

Todas las particiones montadas se desmontarán recursivamente, y el dispositivo de bucle subyacente se eliminará, junto con todos sus dispositivos de subpartición.

Añadido en la versión 252.

-U

Este es un atajo para --umount --rmdir.

Añadido en la versión 252.

--attach

Adjunta la imagen de disco especificada a un dispositivo de bloque de loopback asignado automáticamente, e imprime la ruta al dispositivo de bloque de loopback en la salida estándar. Esto es similar a una invocación de losetup --find --show --partscan, pero validará la imagen como DDI antes de adjuntarla, y derivará automáticamente el tamaño de sector correcto a utilizar. Además, asegura que los dispositivos de bloque por partición se creen antes de retornar e intenta habilitar el modo de E/S directa, si es posible. Toma una ruta a un archivo de imagen de disco.

Si se combina con --quiet, se suprime la salida del nombre del dispositivo de bloque.

Añadido en la versión 254.

--detach

Desconecta la imagen de disco especificada de un dispositivo de bloque de loopback. Esto deshace el efecto de --attach arriba. Espera una ruta a un dispositivo de bloque de loopback como argumento, o la ruta al archivo de imagen subyacente. En este último caso, determinará automáticamente el dispositivo correcto a desconectar.

Añadido en la versión 254.

--list, -l

Imprime las rutas de todos los archivos y directorios en la imagen de SO o directorio especificado a la salida estándar.

Añadido en la versión 253.

--mtree

Genera un manifiesto de archivo compatible con mtree(8) de BSD para la imagen de disco o directorio especificado. Esto es útil para comparar contenidos de imágenes en detalle, incluyendo información de inodos y otros metadatos. Si bien el manifiesto generado contendrá información detallada de inodos, actualmente excluye atributos extendidos, capacidades del sistema de archivos, etiquetas MAC, indicadores de archivo chattr(1), información de subvolúmenes de btrfs(5) y varios otros metadatos de archivos. La información del contenido del archivo se muestra mediante un digest SHA256. Es posible que se agreguen campos adicionales en el futuro. Tenga en cuenta que la información de inodos
tion such as link counts, inode numbers and timestamps is excluded from the output on purpose, as it typically complicates reproducibility.

Added in version 253.

--with

Ejecuta el comando especificado con la imagen del sistema operativo montada. Montará la imagen en un directorio temporal, cambiará el directorio de trabajo actual a él e invocará la línea de comandos especificada como un proceso hijo. Una vez que el proceso finalice, desmontará la imagen de nuevo y eliminará el directorio temporal. Si no se especifica ningún comando, se invoca un shell. La imagen se monta escribible; use --read-only para cambiar a operación de solo lectura. El proceso invocado tendrá la variable de entorno $SYSTEMD_DISSECT_ROOT establecida, que contendrá el nombre de la ruta absoluta del punto de montaje temporal, es decir, el mismo directorio que se establece como directorio de trabajo actual. También tendrá la variable de entorno $SYSTEMD_DISSECT_DEVICE establecida, que contendrá el nombre de la ruta absoluta del dispositivo de bucle al que se adjuntó la imagen.

Added in version 253.

--copy-from, -x

Copia un archivo o directorio desde la imagen o directorio del sistema operativo especificado a la ubicación especificada en el sistema de archivos del host. Espera tres argumentos: una ruta a un archivo o directorio de imagen, una ruta de origen (relativa al directorio raíz de la imagen) y una ruta de destino (relativa al directorio de trabajo actual, o una ruta absoluta, ambas fuera de la imagen). Si la ruta de destino se omite o se especifica como guion ("-"), el archivo especificado se escribe en la salida estándar. Si la ruta de origen en el sistema de archivos de la imagen se refiere a un archivo regular, se copia a la ruta de destino. En este caso, también se copian el modo de acceso, los atributos extendidos y las marcas de tiempo, pero no la propiedad del archivo. Si la ruta de origen en la imagen se refiere a un directorio, se copia a la ruta de destino, recursivamente con todos los archivos y directorios contenidos, fusionándose en los directorios existentes y actualizando los archivos ya existentes. En este caso, también se copia la propiedad del archivo.

Added in version 247.

--copy-to, -a

Copia un archivo o directorio desde la ubicación especificada en el sistema de archivos del host al directorio o imagen del sistema operativo especificado. Espera tres argumentos: una ruta a un archivo o directorio de imagen, una ruta de origen (relativa al directorio de trabajo actual, o una ruta absoluta, ambas fuera de la imagen) y una ruta de destino (relativa al directorio raíz de la imagen). Si la ruta de origen se omite o se especifica como guion ("-"), los datos a escribir se leen de la entrada estándar. Si la ruta de origen en el sistema de archivos del host se refiere a un archivo regular, se copia a la ruta de destino. En este caso, también se copian el modo de acceso, los atributos extendidos y las marcas de tiempo, pero no la propiedad del archivo. Si la ruta de origen en el sistema de archivos del host se refiere a un directorio, se copia a la ruta de destino, recursivamente con todos los archivos y directorios contenidos, fusionándose en los directorios existentes y actualizando los archivos ya existentes. En este caso, también se copia la propiedad del archivo.

Al igual que con --mount, las comprobaciones del sistema de archivos se ejecutan implícitamente antes de que comience la operación de copia.

Added in version 247.

--make-archive

Genera un archivo comprimido a partir de la imagen de disco especificada. Espera dos argumentos: la ruta a la imagen de disco y, opcionalmente, la ruta del archivo comprimido de salida. Si esta última se omite, el archivo comprimido se escribe en la salida estándar. El formato del archivo comprimido se determina automáticamente a partir del nombre del archivo comprimido de salida especificado; por ejemplo, cualquier ruta con el sufijo ".tar.xz" dará como resultado un tarball de UNIX comprimido con xz (si la ruta se omite, se crea un tarball de UNIX sin comprimir). Consulte libarchive(3) para obtener una lista de formatos de archivo y esquemas de compresión compatibles.

Added in version 256.

--discover

Muestra una lista de DDI en directorios conocidos. Mostrará imágenes de disco de servicios portátiles, de máquina y extensiones de sistema/ configuración en los directorios habituales /usr/lib/machines/, /usr/lib/portables/, /usr/lib/confexts/, /var/lib/machines/, /var/lib/portables/, /var/lib/extensions/ y similares.

Added in version 253.

--validate

Valida la disposición de las particiones de una imagen de disco (DDI) y asegura que coincida con la política de imagen especificada mediante --image-policy=, si se especifica alguna. Esto analiza la tabla de particiones y sondea los sistemas de archivos en la imagen, pero no intenta montarlos (ni configurar el cifrado/autenticación de disco mediante LUKS/Verity). Lo hace teniendo en cuenta la política de disección de imágenes configurada. Dado que esta operación no monta sistemas de archivos, este comando –a diferencia de todos los demás comandos implementados por esta herramienta– no requiere privilegios distintos de la capacidad de acceder al archivo especificado. Imprime "OK" y devuelve cero si la imagen parece estar en orden y coincide con la política de disección de imágenes especificada. De lo contrario, imprime un mensaje de error y devuelve un valor distinto de cero.

Added in version 254.

--shift

Itera recursivamente a través de todos los inodos de la imagen especificada y desplaza los UID y GID de los que son propietarios los inodos al rango de UID especificado. Toma como parámetro una ruta de imagen y una base de UID. La base de UID se puede especificar numéricamente (en cuyo caso debe ser un múltiplo de 65536, y ya sea 0 o dentro del rango de UID de contenedor o extranjero, según Usuarios, Grupos, UID y GID en Sistemas systemd[2]), o como el identificador simbólico "foreign" que es un atajo a la base de UID extranjera. Este comando es útil para preparar imágenes de contenedores de directorios para uso sin privilegios. Tenga en cuenta que este comando está destinado a imágenes que utilizan solo el rango de UID/GID de 16 bits, y siempre ignora los 16 bits superiores de la propiedad actual de UID/GID, combinando los 16 bits inferiores con la base de UID de destino.

Use systemd-dissect --shift /some/container/tree foreign para desplazar una imagen de contenedor al rango de UID extranjero, o systemd-dissect --shift /some/container/tree 0 para desplazarla al rango de UID del host.

Added in version 258.

-h, --help

Imprime un texto de ayuda corto y sale.

--version

Imprime una cadena de versión corta y sale.

OPCIONES

Se entienden las siguientes opciones:

--read-only, -r

Opera en modo de solo lectura. Por defecto, --mount establecerá puntos de montaje escribibles. Si se especifica esta opción, se establecerán en modo de solo lectura en su lugar.

Added in version 247.

--fsck=no

Desactiva la comprobación automática del sistema de archivos. Por defecto, cuando se accede a una imagen para escritura (mediante --mount o --copy-to), los sistemas de archivos contenidos en la imagen del sistema operativo se comprueban automáticamente utilizando el comando fsck(8) apropiado, en modo de reparación automática. Este comportamiento se puede desactivar usando --fsck=no.

Added in version 247.

--growfs=no

Desactiva el crecimiento automático de los sistemas de archivos accedidos hasta el tamaño de su partición, si está marcado para ello en la tabla de particiones GPT. Por defecto, cuando se accede a una imagen para escritura (mediante --mount o --copy-to), los sistemas de archivos contenidos en la imagen del sistema operativo crecen automáticamente hasta el tamaño de sus particiones, si el bit 59 en las banderas de partición GPT está establecido para los tipos de partición definidos por la Especificación de Particiones Descubribles[1]. Este comportamiento se puede desactivar usando --growfs=no. Los sistemas de archivos crecen automáticamente al acceder si se cumplen todas las siguientes condiciones:
1.El sistema de archivos está montado como escribible
2.El sistema de archivos es actualmente más pequeño que la partición en la que está contenido (y, por lo tanto, se puede crecer)
3.La imagen contiene una tabla de particiones GPT
4.El sistema de archivos está almacenado en una partición definida por la Especificación de Particiones Descubribles
5.El bit 59 de las banderas de partición GPT para esta partición está establecido, según la especificación
6.No se pasa la opción --growfs=no.

Added in version 249.

--mkdir

Si se combina con --mount, el directorio donde se montará la imagen del sistema operativo se creará si falta. Tenga en cuenta que el directorio no se elimina automáticamente cuando la imagen de disco se desmonta de nuevo.

Added in version 247.

--rmdir

Si se combina con --umount, el directorio especificado donde se montó la imagen del sistema operativo se eliminará después de desmontar la imagen del sistema operativo.

Added in version 252.

--discard=

Toma uno de "disabled", "loop", "all", "crypto". Si es "disabled", la imagen se accede con el descarte de bloques vacíos desactivado. Si es "loop", el descarte está habilitado si se opera en un archivo regular. Si es "crypt", el descarte está habilitado incluso en sistemas de archivos cifrados. Si es "all", el descarte está habilitado incondicionalmente.

Added in version 247.

--in-memory

Si se especifica, se utiliza una copia en memoria de la imagen de disco especificada. Esto se puede usar para operar con acceso de escritura en una imagen (posiblemente de solo lectura), sin modificar realmente el archivo original. Esto también se puede usar para operar en una imagen de disco sin mantener ocupado el sistema de archivos de origen, para permitir que se desmonte.

Added in version 253.

--root-hash=, --root-hash-sig=, --verity-data=

Configura varios aspectos de la integridad de datos de Verity para la imagen del sistema operativo. La opción --root-hash= especifica un hash de nivel superior de Verity codificado en hexadecimal para usar al configurar la protección de integridad de Verity. La opción --root-hash-sig= especifica la ruta a un archivo que contiene una firma PKCS#7 para el hash. Esta firma se pasa al kernel durante la activación, que la comparará con las claves de firma disponibles en el keyring del kernel. La opción --verity-data= especifica una ruta a un archivo con los datos de Verity a utilizar para la imagen del sistema operativo, en caso de que se almacene en un archivo separado. Se recomienda incrustar los datos de Verity directamente en la imagen, utilizando los mecanismos de Verity en la Especificación de Particiones Descubribles[1].

Added in version 247.

--usr-hash=, --usr-hash-sig=

Similar a --root-hash= y --root-hash-sig=, pero especifica el hash y la firma para la partición /usr/. Tenga en cuenta que se pueden usar las opciones para la partición raíz o las de /usr/, pero no ambas en combinación.

Added in version 258.

--loop-ref=

Configura la cadena de "referencia" que el kernel deberá informar como archivo de respaldo para el dispositivo de bloque de bucle. Mientras que esto se supone qued puede ser una ruta o un nombre de archivo que hace referencia al archivo subyacente. Esto no se aplica y el kernel acepta cadenas de formato libre arbitrarias, elegidas por el usuario. Acepta cadenas arbitrarias de hasta 63 caracteres de longitud. Esto establece el campo ".lo_file_name" del kernel para el dispositivo de bloque. Tenga en cuenta que esto es distinto del archivo de atributo /sys/class/block/loopX/loop/backing_file que siempre informa una ruta que hace referencia al archivo subyacente real. Este último está sujeto a la traducción del espacio de nombres de montaje, mientras que el primero no.

Esta configuración es particularmente útil en combinación con el comando --attach, ya que permite referenciar posteriormente el dispositivo de bucle asignado a través de los enlaces simbólicos /dev/disk/by-loop-ref/... Ejemplo: primero, configure el dispositivo de bucle mediante systemd-dissect attach --loop-ref=quux foo.raw, y luego refiérase a él en un comando a través del nombre de archivo especificado: cfdisk /dev/disk/by-loop-ref/quux.

Añadido en la versión 254.

--loop-ref-auto

Similar a --loop-ref=, pero deriva automáticamente la cadena de referencia del nombre de archivo subyacente especificado, truncándolo si es necesario.

Añadido en la versión 258.

--mtree-hash=no

Si se combina con --mtree, desactiva la inclusión de hashes de archivos en la salida mtree. Esto hace que --mtree sea más rápido cuando opera en imágenes grandes.

Añadido en la versión 254.

--system, --user

Cuando se usa junto con --discover, controla si se buscan imágenes instaladas en todo el sistema o en los directorios del usuario en $HOME. Si no se especifica ninguno de los dos, se buscará dentro de ambos ámbitos.

Añadido en la versión 258.

--all

Si se combina con --discover, también muestra imágenes que comienzan con un punto, es decir, imágenes ocultas.

Añadido en la versión 258.

--quiet, -q

Si se combina con --attach, suprime la salida de la ruta del dispositivo de bloque de bucle utilizado.

Añadido en la versión 258.

--image-policy=policy

Toma una cadena de política de imagen como argumento, según systemd.image-policy(7). La política se aplica al operar en la imagen de disco especificada a través de --image=, vea arriba. Si no se especifica, por defecto es la política "*", es decir, se utilizan todos los sistemas de archivos reconocidos en la imagen.

--image-filter=filter

Toma una cadena de filtro de imagen como argumento, según systemd.image-filter(7). El filtro se tiene en cuenta al operar en la imagen de disco especificada a través de --image=, vea arriba. Si no se especifica, no se aplica ningún filtro.

--no-pager

No canalizar la salida a un paginador.

--no-legend

No imprimir la leyenda, es decir, los encabezados de columna y el pie de página con sugerencias.

--json=MODE

Muestra la salida formateada como JSON. Espera uno de los siguientes valores: "short" (para la salida más corta posible sin espacios en blanco redundantes ni saltos de línea), "pretty" (para una versión bonita de la misma, con sangría y saltos de línea) o "off" (para desactivar la salida JSON, por defecto).

ESTADO DE SALIDA

En caso de éxito, se devuelve 0, de lo contrario, un código de error distinto de cero. Si se utiliza el comando --with, se propaga el estado de salida del comando invocado.

INVOCACIÓN COMO /SBIN/MOUNT.DDI

El ejecutable systemd-dissect puede estar enlazado simbólicamente a /sbin/mount.ddi. Si se invoca a través de él, implementa la interfaz de "ayudante externo" de mount(8) para el tipo de sistema de archivos (pseudo) "ddi". Esto significa que las imágenes de disco conformes pueden montarse directamente a través de

# mount -t ddi myimage.raw targetdir/

de una manera mayormente equivalente a:

# systemd-dissect --mount myimage.raw targetdir/

Tenga en cuenta que dado que un solo DDI puede contener varios sistemas de archivos, debería desmontarse posteriormente con umount -R targetdir/, para operación recursiva.

Esta funcionalidad es particularmente útil para montar automáticamente DDIs al arrancar a través de simples entradas /etc/fstab. Por ejemplo:

/path/to/myimage.raw /images/myimage/ ddi defaults 0 0

Cuando se invoca de esta manera, las opciones de montaje "ro", "rw", "discard", "nodiscard" se mapean a las opciones correspondientes enumeradas anteriormente (es decir, --read-only, --discard=all, --discard=disabled). Las opciones de montaje *no* se pasan genéricamente a los sistemas de archivos dentro de las imágenes.

EJEMPLOS

Ejemplo 1. Generar un archivo tar de una imagen de disco de SO (--with)

# systemd-dissect --with foo.raw tar cz . >foo.tar.gz

o alternativamente simplemente:

Ejemplo 2. Generar un archivo tar de una imagen de disco de SO (--make-archive)

# systemd-dissect --make-archive foo.raw foo.tar.gz
