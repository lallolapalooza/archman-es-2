MONGODB_TABLE(5) Manual de formatos de archivo MONGODB_TABLE(5)

NOMBRE

mongodb_table - Configuración del cliente MongoDB de Postfix

SINOPSIS

postmap -q "cadena" mongodb:/etc/postfix/nombre_archivo
postmap -q - mongodb:/etc/postfix/nombre_archivo <archivo_entrada

DESCRIPCIÓN


El sistema de correo Postfix utiliza tablas opcionales para la reescritura de direcciones o el enrutamiento de correo. Estas tablas suelen estar en formato dbm o db.

Alternativamente, las tablas de consulta pueden especificarse como bases de datos MongoDB. Para utilizar consultas MongoDB, defina una fuente MongoDB como una tabla de consulta en main.cf, por ejemplo:

    alias_maps = mongodb:/etc/postfix/mongodb-aliases.cf

En este ejemplo, el archivo /etc/postfix/mongodb-aliases.cf tiene el mismo formato que el archivo main.cf de Postfix, y puede especificar los parámetros descritos a continuación. También es posible tener la configuración en main.cf; consulte "PARÁMETROS OBSOLETOS DE MAIN.CF" a continuación.

Se recomienda encarecidamente utilizar proxy:mongodb, para reducir el número de conexiones a la base de datos. Por ejemplo:

    alias_maps = proxy:mongodb:/etc/postfix/mongodb-aliases.cf

Nota: al utilizar proxy:mongodb:/archivo, el archivo debe ser legible por el usuario no privilegiado de Postfix (especificado con el parámetro de configuración mail_owner de Postfix).

PARÁMETROS MONGODB

uri
La URI del servidor/clúster de mongo al que Postfix intentará conectarse y consultar. Consulte https://www.mongodb.com/docs/manual/reference/connection-string/

Ejemplo:

    uri = mongodb+srv://user:pass@loclhost:27017/mail
dbname
Nombre de la base de datos de la que se leerá la información. Ejemplo: 
    dbname = mail
collection
Nombre de la colección (tabla) de la que se leerá la información. Ejemplo: 
    collection = mailbox
query_filter
La plantilla de consulta de MongoDB utilizada para buscar en la base de datos, donde %s es un sustituto de la dirección de correo electrónico que Postfix está intentando resolver. Consulte: https://www.mongodb.com/docs/manual/tutorial/query-documents/

Ejemplo:

    query_filter = {"$or": [{"username": "%s"}, {"alias.address": "%s"}], "active": 1}

Este parámetro admite las siguientes expansiones '%':

%%
Esto se reemplaza por un carácter '%' literal.
%s
Esto se reemplaza por la clave de entrada. El %s debe aparecer entre comillas, ya que todas las consultas de Postfix son cadenas que contienen (partes de) un dominio o una dirección de correo electrónico. Postfix no realiza consultas numéricas.
%u
Cuando la clave de entrada es una dirección del tipo usuario@dominio, %u se reemplaza por la parte local de la dirección. De lo contrario, %u se reemplaza por la cadena de búsqueda completa.
%d
Cuando la clave de entrada es una dirección del tipo usuario@dominio, %d se reemplaza por la parte del dominio de la dirección.
%[1-9]
Los patrones %1, %2, ... %9 se reemplazan por el componente más significativo correspondiente del dominio de la clave de entrada. Si la clave de entrada es usuario@mail.example.com, entonces %1 es com, %2 es example y %3 es mail.
En las sustituciones anteriores, los caracteres se citarán según lo requiera RFC 4627. Por ejemplo, cada carácter de comillas dobles o barra invertida se escapará con una barra invertida.
projection
Proyecciones avanzadas de consultas de MongoDB. Consulte: https://www.mongodb.com/docs/manual/tutorial/project-fields-from-query-results/
  • Si projection no está vacío, entonces result_attribute debe estar vacío.
  • Esta implementación puede extraer información solo de campos de resultado que tengan el tipo string (UTF8), integer (int32, int64) y array. Otros campos de resultado se ignorarán con una advertencia. Consulte: https://mongoc.org/libbson/current/bson_type_t.html
  • Al igual que con result_attribute, el campo _id de nivel superior (tipo OID) se elimina automáticamente de los resultados de la proyección.
result_attribute
Lista separada por comas o espacios en blanco con los nombres de los campos que se devolverán en un resultado de consulta.
  • Si result_attribute no está vacío, entonces projection debe estar vacío.
  • Al igual que con projection, el campo _id de nivel superior (tipo OID) se elimina automáticamente de los resultados de la consulta.
result_format (predeterminado: %s)
Plantilla de formato aplicada al resultado de projection o result_attribute. Se utiliza con mayor frecuencia para añadir (o preceder) texto al resultado. Este parámetro admite las siguientes expansiones '%':
%%
Esto se reemplaza por un carácter '%' literal.
%s
Esto se reemplaza por el valor del atributo de resultado. Cuando el resultado está vacío, se omite.
%u
Cuando el valor del atributo de resultado es una dirección del tipo usuario@dominio, %u se reemplaza por la parte local de la dirección. Cuando el resultado no tiene parte local, se omite.
%d
Cuando el valor de un atributo de resultado es una dirección del tipo usuario@dominio, %d se reemplaza por la parte del dominio del valor del atributo. Cuando el resultado no está cualificado, se omite.
%[SUD1-9]
Las expansiones de mayúsculas y dígitos decimales interpolan las partes de la clave de entrada en lugar del resultado. Su comportamiento es idéntico al descrito con query_filter y, de hecho, dado que la clave de entrada se conoce de antemano, las búsquedas cuya clave no contiene toda la información especificada en la plantilla de resultado se suprimen y no devuelven resultados.
Por ejemplo, usar "result_format = smtp:[%s]" permite utilizar un atributo mailHost como base de una tabla transport(5). Después de aplicar el formato de resultado, varios valores se concatenan como cadenas separadas por comas. El parámetro expansion_limit explicado a continuación permite restringir el número de valores en el resultado, lo cual es especialmente útil para mapas que deben devolver un solo valor.

El valor predeterminado %s especifica que cada valor de atributo debe usarse tal cual.

NOTA: ¡NO ponga comillas alrededor del formato de resultado! El resultado no es una cadena JSON.

domain (predeterminado: sin lista de dominios)
Esta es una lista de nombres de dominio, rutas a archivos o bases de datos de "tipo:tabla". Cuando se especifica, solo las claves de búsqueda completamente cualificadas con una parte local *no vacía* y un dominio coincidente son elegibles para la consulta: no se realizan consultas de 'usuario', consultas de dominio desnudo y consultas de "@dominio". Esto puede reducir significativamente la carga de consultas en la base de datos de backend. Ejemplo: 
    domain = postfix.org, hash:/etc/postfix/searchdomains
expansion_limit (predeterminado: 0)
Un límite en el número total de elementos de resultado devueltos (como una lista separada por comas) por una consulta contra el mapa. Un valor de cero desactiva el límite. Las consultas fallan con un error temporal si se supera el límite. Establecer el límite en 1 asegura que las consultas no devuelvan múltiples valores.

PARÁMETROS OBSOLETOS DE MAIN.CF

Los parámetros de MongoDB también se pueden definir en main.cf. Especifique como fuente MongoDB un nombre que no comience con una barra o un punto. Los parámetros de MongoDB serán entonces accesibles

como el nombre que le has dado a la fuente en su definición, un guion bajo y el nombre del parámetro. Por ejemplo, si un mapa se especifica como "mongodb:mongodb_source", el parámetro "uri" se definiría en main.cf como "mongodb_source_uri".
