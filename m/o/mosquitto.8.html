NAME

mosquitto - an MQTT broker

SYNOPSIS

mosquitto [-c config file] [-d | --daemon] [-p port number] [-v]

DESCRIPTION

mosquitto is a broker for the MQTT protocol version 5.0/3.1.1/3.1.

OPTIONS

-c, --config-file

Load configuration from a file. If not given, then the broker will listen on port 1883 bound to the loopback interface, and the default values as described in mosquitto.conf(5) are used.

Important
See the -p option for a description of changes in behaviour from 1.6.x to 2.0.

-d, --daemon

Run mosquitto in the background as a daemon. All other behaviour remains the same.

-p, --port

Listen on the port specified. May be specified up to 10 times to open multiple sockets listening on different ports.

Important
In version 1.6.x and earlier, the listener defined by -p (or the default port of 1883) would be bound to all interfaces and so be accessible from any network. It could also be used in combination with -c.

From version 2.0 onwards, the listeners defined with -p are bound to the loopback interface only, and so can only be connected to from the local machine. If both -p is used and a listener is defined in a configuration file, then the -p options are IGNORED.

-v, --verbose

Use verbose logging. This is equivalent to setting log_type to all in the configuration file. This overrides and logging options given in the configuration file.

CONFIGURATION

The broker can be configured using a configuration file as described in mosquitto.conf(5) and this is the main point of information for mosquitto. The files required for SSL/TLS support are described in mosquitto-tls(7).

PLATFORM LIMITATIONS

Some versions of Windows have limitations on the number of concurrent connections due to the Windows API being used. In modern versions of Windows, e.g. Windows 10 or Windows Server 2019, this is approximately 8192 connections. In earlier versions of Windows, this limit is 2048 connections.

MQTT SUPPORT

Mosquitto supports MQTT v5.0, v3.1.1, and v3.1.

MQTT v5.0

Mosquitto provides full MQTT v5.0 support, but some features are not used directly. The following sections describe the new features and explain where Mosquitto does not make use of a feature.

Features

Enhanced authentication

Basic MQTT authentication uses username/password checks. Enhanced authentication allows different authentication schemes to be integrated into MQTT, and even those schemes with multiple step processes. Clients request a particular type of authentication and if the broker is configured for that scheme the authentication continues. Mosquitto supports enhanced authentication through plugins.

Error handling

Most MQTT packets now have the concept of a reason code which indicates success or failure, and what the failure was. Mosquitto provides full support for reason codes, but does not make use of the reason string feature which can be used to provide a human readable error string to explain the reason code.

Flow control

The number of "in flight" messages for QoS 1 and QoS 2 can be controlled by both the client and the broker.

Request / response

MQTT v5.0 adds a request/response pattern that allows a client to publish a message and instruct the subscribers of that message where to publish a response.

Server redirection

Server redirection is the concept of telling a client to connect to a different MQTT broker, either on CONNECT or with a broker initiated DISCONNECT. Mosquitto does not currently make use of this feature.

Shared subscriptions

When multiple clients subscribe to the same shared subscription, only one client out of the group will receive each message which allows for distributing work loads.

Mosquitto proporciona soporte completo para MQTT v3.1.

MQTT v3

MQTT v3 es una versión obsoleta del protocolo que no admite la autenticación de nombre de usuario/contraseña y utilizaba la bandera clean start en el paquete CONNECT, que solo se aplicaba al inicio de una sesión. Un cliente MQTT v3 podrá conectarse correctamente a una instancia de Mosquitto que no requiera autenticación.

ESTADO DEL BROKER

Los clientes pueden obtener información sobre el broker suscribiéndose a temas en la jerarquía $SYS de la siguiente manera. Los temas marcados como estáticos solo se envían una vez por cliente al suscribirse. Todos los demás temas se actualizan cada sys_interval segundos. Si sys_interval es 0, entonces no se envían actualizaciones.

Tenga en cuenta que si está utilizando un cliente de línea de comandos para interactuar con los temas $SYS y su shell interpreta $ como una variable de entorno, deberá colocar el tema entre comillas simples '$SYS/...' o escapar el símbolo del dólar: \$SYS/... de lo contrario, $SYS se tratará como una variable de entorno.

$SYS/broker/bytes/received

El número total de bytes recibidos desde que se inició el broker.

$SYS/broker/bytes/sent

El número total de bytes enviados desde que se inició el broker.

$SYS/broker/clients/connected, $SYS/broker/clients/active (obsoleto)

El número de clientes actualmente conectados.

$SYS/broker/clients/expired

El número de clientes persistentes desconectados que han caducado y han sido eliminados a través de la opción persistent_client_expiration.

$SYS/broker/clients/disconnected, $SYS/broker/clients/inactive (obsoleto)

El número total de clientes persistentes (con clean session deshabilitado) que están registrados en el broker pero que están actualmente desconectados.

$SYS/broker/clients/maximum

El número máximo de clientes que se han conectado al broker al mismo tiempo.

$SYS/broker/clients/total

El número total de clientes activos e inactivos actualmente conectados y registrados en el broker.

$SYS/broker/connection/#

Cuando los puentes se configuran hacia/desde el broker, la práctica común es proporcionar un tema de estado que indique el estado de la conexión. Esto se proporciona dentro de $SYS/broker/connection/ por defecto. Si el valor del tema es 1 la conexión está activa, si es 0 entonces no está activa. Consulte la sección Bridges a continuación para obtener más información sobre los puentes.

$SYS/broker/heap/current size

El tamaño actual de la memoria heap en uso por mosquitto. Tenga en cuenta que este tema puede no estar disponible dependiendo de las opciones de compilación.

$SYS/broker/heap/maximum size

La mayor cantidad de memoria heap utilizada por mosquitto. Tenga en cuenta que este tema puede no estar disponible dependiendo de las opciones de compilación.

$SYS/broker/load/connections/+

La media móvil del número de paquetes CONNECT recibidos por el broker en diferentes intervalos de tiempo. El "+" final de la jerarquía puede ser 1min, 5min o 15min. El valor devuelto representa el número de conexiones recibidas en 1 minuto, promediado durante 1, 5 o 15 minutos.

$SYS/broker/load/bytes/received/+

La media móvil del número de bytes recibidos por el broker en diferentes intervalos de tiempo. El "+" final de la jerarquía puede ser 1min, 5min o 15min. El valor devuelto representa el número de bytes recibidos en 1 minuto, promediado durante 1, 5 o 15 minutos.

$SYS/broker/load/bytes/sent/+

La media móvil del número de bytes enviados por el broker en diferentes intervalos de tiempo. El "+" final de la jerarquía puede ser 1min, 5min o 15min. El valor devuelto representa el número de bytes enviados en 1 minuto, promediado durante 1, 5 o 15 minutos.

$SYS/broker/load/messages/received/+

La media móvil del número de todos los tipos de mensajes MQTT recibidos por el broker en diferentes intervalos de tiempo. El "+" final de la jerarquía puede ser 1min, 5min o 15min. El valor devuelto representa el número de mensajes recibidos en 1 minuto, promediado durante 1, 5 o 15 minutos.

$SYS/broker/load/messages/sent/+

La media móvil del número de todos los tipos de mensajes MQTT enviados por el broker en diferentes intervalos de tiempo. El "+" final de la jerarquía puede ser 1min, 5min o 15min. El valor devuelto representa el número de mensajes enviados en 1 minuto, promediado durante 1, 5 o 15 minutos.

$SYS/broker/load/publish/dropped/+

La media móvil del número de mensajes de publicación descartados por el broker en diferentes intervalos de tiempo. Esto muestra la tasa a la que los clientes duraderos que están desconectados pierden mensajes. El "+" final de la jerarquía puede ser 1min, 5min o 15min. El valor devuelto representa el número de mensajes descartados en 1 minuto, promediado durante 1, 5 o 15 minutos.

$SYS/broker/load/publish/received/+

La media móvil del número de mensajes de publicación recibidos por el broker en diferentes intervalos de tiempo. El "+" final de la jerarquía puede ser 1min, 5min o 15min. El valor devuelto representa el número de mensajes de publicación recibidos en 1 minuto, promediado durante 1, 5 o 15 minutos.

$SYS/broker/load/publish/sent/+

La media móvil del número de mensajes de publicación enviados por el broker en diferentes intervalos de tiempo. El "+" final de la jerarquía puede ser 1min, 5min o 15min. El valor devuelto representa el número de mensajes de publicación enviados en 1 minuto, promediado durante 1, 5 o 15 minutos.

$SYS/broker/load/sockets/+

La media móvil del número de conexiones de socket abiertas al broker en diferentes intervalos de tiempo. El "+" final de la jerarquía puede ser 1min, 5min o 15min. El valor devuelto representa el número de conexiones de socket en 1 minuto, promediado durante 1, 5 o 15 minutos.

$SYS/broker/messages/inflight

El número de mensajes con QoS>0 que están pendientes de acuse de recibo.

$SYS/broker/messages/received

El número total de mensajes de cualquier tipo recibidos desde que se inició el broker.

$SYS/broker/messages/sent

El número total de mensajes de cualquier tipo enviados desde que se inició el broker.

$SYS/broker/publish/messages/dropped

El número total de mensajes de publicación que han sido descartados debido a límites de inflight/queued. Consulte las opciones max_inflight_messages y max_queued_messages en mosquitto.conf(5) para obtener más información.

$SYS/broker/publish/messages/received

El número total de mensajes PUBLISH recibidos desde que se inició el broker.

$SYS/broker/publish/messages/sent

El número total de mensajes PUBLISH enviados desde que se inició el broker.

$SYS/broker/retained messages/count

El número total de mensajes retenidos activos en el broker.

$SYS/broker/store/messages/count, $SYS/broker/messages/stored (obsoleto)

El número de mensajes que se conservan actualmente en el almacén de mensajes. Esto incluye mensajes retenidos y mensajes en cola para clientes duraderos.

$SYS/broker/store/messages/bytes

El número de bytes actualmente conservados por las cargas útiles de mensajes en el almacén de mensajes. Esto incluye mensajes retenidos y mensajes en cola para clientes duraderos.

$SYS/broker/subscriptions/count

El número total de suscripciones activas en el broker.

$SYS/broker/version

La versión del broker. Estático.

SUSCRIPCIONES A TEMAS CON COMODÍN

Además de permitir que los clientes se suscriban a temas específicos, mosquitto también permite el uso de dos comodines en las suscripciones. + es el comodín utilizado para coincidir con un solo nivel de jerarquía. Por ejemplo, para un tema de "a/b/c/d", las siguientes suscripciones de ejemplo coincidirán:

•a/b/c/d
•+/b/c/d
•a/+/c/d
•a/+/+/d
•+/+/+/+

Las siguientes suscripciones no coincidirán:

•a/b/c
•b/+/c/d
•+/+/+

El segundo comodín es # y se utiliza para coincidir con todos los niveles posteriores de la jerarquía. Con un tema de "a/b/c/d", las siguientes suscripciones de ejemplo coincidirán:

•a/b/c/d
•#
•a/#
•a/b/#
•a/b/c/#
•+/b/c/#

La jerarquía $SYS no coincide con una suscripción de "#". Si desea observar toda la jerarquía $SYS, suscríbase a $SYS/#.

Tenga en cuenta que los comodines solo deben usarse solos, por lo que una suscripción de "a/b+/c" no es un uso válido de un comodín. El comodín # solo debe usarse como el último carácter de una suscripción.

PUENTES

Se pueden conectar varios brokers entre sí con la funcionalidad de puente. Esto es útil cuando se desea compartir información entre ubicaciones, pero no toda la información necesita ser compartida. Un ejemplo podría ser donde un número de usuarios ejecutan un broker para ayudar a registrar el consumo de energía y por una serie de otras razones. El consumo de energía podría compartirse a través de puentes entre todos los brokers de usuario y un broker común, permitiendo que el consumo de energía de todos los usuarios se recopile y compare. La otra información permanecería local a cada broker.

Para obtener información sobre cómo configurar puentes, consulte mosquitto.conf(5).

SEÑALES

En sistemas POSIX, Mosquitto puede recibir señales y actuar sobre ellas como se describe a continuación. Para enviar señales, use, por ejemplo, kill -HUP <ID de proceso de mosquitto>

>

SIGHUP

Al recibir la señal SIGHUP, mosquitto intentará recargar los datos del archivo de configuración, asumiendo que el argumento -c se proporcionó cuando se inició mosquitto. No todos los parámetros de configuración se pueden recargar sin reiniciar. Consulte mosquitto.conf(5) para obtener más detalles.

Si se utilizan certificados TLS, mosquitto también recargará los certificados al recibir una SIGHUP.

SIGUSR1

Al recibir la señal SIGUSR1, mosquitto escribirá la base de datos de persistencia en disco. Esta señal solo se actúa si la persistencia está habilitada.

SIGUSR2

La señal SIGUSR2 hace que mosquitto imprima el árbol de suscripción actual, junto con información sobre dónde existen mensajes retenidos. Esto está destinado solo como una característica de prueba y puede eliminarse en cualquier momento.
