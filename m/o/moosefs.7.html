NOMBRE

MooseFS - sistema de archivos distribuido tolerante a fallos, altamente fiable, escalable casi indefinidamente y rápido en el Espacio de Usuario

DESCRIPCIÓN

MooseFS es un sistema de archivos distribuido tolerante a fallos. Reparte los datos a través de varias ubicaciones físicas (servidores), que son visibles para el usuario como un solo recurso. Para operaciones de archivo estándar, MooseFS actúa como cualquier otro sistema de archivos tipo Unix:

-
estructura jerárquica (árbol de directorios)
-
almacena atributos de archivo POSIX (permisos, tiempos de último acceso y modificación)
-
soporta archivos especiales (dispositivos de bloque y caracteres, tuberías y sockets)
-
soporta enlaces simbólicos (nombres de archivo que apuntan a archivos de destino, no necesariamente en MooseFS) y enlaces duros (diferentes nombres de archivos que se refieren a los mismos datos en MooseFS)
-
soporta ACLs
-
soporta bloqueos de archivos entre todos los procesos cliente conectados
-
el acceso al sistema de archivos se puede limitar según la dirección IP y/o la contraseña

Las características distintivas de MooseFS son:

-
alta fiabilidad (se pueden almacenar varias copias de los datos en máquinas físicas separadas)
-
la capacidad se puede ampliar dinámicamente añadiendo nuevos ordenadores/discos
-
los archivos eliminados se conservan durante un período de tiempo configurable (una “papelera de reciclaje” a nivel de sistema de archivos)
-
instantáneas coherentes de archivos, incluso mientras el archivo se está escribiendo/accediendo

MooseFS consta de 4 componentes clave:

Servidores Maestro
en MooseFS CE una máquina, en MooseFS Pro cualquier número de máquinas ejecutando el binario mfsmaster, que gestiona todo el sistema de archivos, almacenando metadatos para cada archivo (información sobre tamaño, atributos y ubicación(es) del archivo, incluida toda la información sobre archivos no regulares, es decir, directorios, sockets, tuberías y dispositivos)
Servidores de Fragmentos (Chunk Servers)
cualquier número de servidores genéricos ejecutando el binario mfschunkserver, que almacena los datos de los archivos y los sincroniza entre ellos (si se supone que un archivo determinado existe en más de una copia).
Servidores Metalogger
cualquier número de servidores ejecutando el binario mfsmetalogger, todos los cuales almacenan registros de cambios de metadatos y descargan periódicamente el archivo principal de metadatos
Procesos Cliente
máquinas ejecutando los procesos mfsmount, que acceden a los archivos almacenados en el sistema de archivos MooseFS y los exponen a través de un punto de montaje regular dentro del árbol de directorios local de una máquina cliente

Además, se pueden instalar varias herramientas para ayudar en el uso del sistema:

GUI
una herramienta web de estadísticas y diagnóstico (mfsgui, actúa como un servidor HTTP simple)
CLI
herramienta de estadísticas y diagnóstico por línea de comandos mfscli
Dispositivo de Bloque
proceso cliente especial solo para Linux mfsbdev que mapea archivos únicos de MooseFS a dispositivos de bloque
HERRAMIENTAS
varias herramientas administrativas de línea de comandos

ARQUITECTURA

Desde el punto de vista del usuario, MooseFS se comporta como un sistema de archivos normal y compatible con POSIX con una capacidad casi infinitamente ampliable. Para lograr esto, el sistema fue diseñado como un sistema de archivos de red distribuido, donde diferentes procesos se ejecutan en diferentes máquinas, realizan tareas específicas para garantizar el rendimiento adecuado de todo el sistema de archivos. El Servidor Maestro almacena la información de metadatos sobre los archivos y gestiona todo el sistema de archivos. En el caso de una instalación de MooseFS Pro, con varios Servidores Maestros, solo uno de ellos (en el rol de Líder) gestiona el sistema en un momento dado, los otros (Seguidores) simplemente se mantienen al día, listos para asumir el rol de Líder en cualquier momento. El Servidor Maestro que gestiona tiene las siguientes tareas: almacena todos los metadatos del sistema de archivos (información sobre archivos y directorios), responde a las solicitudes de los procesos cliente (de montaje) cuando desean realizar cualquier operación en el sistema de archivos, supervisa el estado de los Servidores de Fragmentos y los datos almacenados, enviando solicitudes de replicación o eliminación a los Servidores de Fragmentos cuando es necesario.

Los metadatos se almacenan en la memoria del Servidor Maestro y, simultáneamente, se guardan en un disco local (como un archivo binario actualizado periódicamente y registros incrementales actualizados inmediatamente). El archivo binario principal, así como los registros, se sincronizan con los Metaloggers (si están presentes) y con los Servidores Maestros de repuesto en la versión MooseFS Pro. Los Servidores de Fragmentos almacenan los datos reales de los archivos. Todos los datos del sistema de archivos se dividen en fragmentos (de ahí el nombre de los servidores que los conservan) de un tamaño máximo de 64 MiB. Los fragmentos se conservan en varias copias en diferentes servidores según las políticas apropiadas para garantizar la seguridad de los datos. Los Servidores de Fragmentos se comunican con los procesos cliente (a petición del cliente, según lo dirigido por el maestro) para escribir o leer datos de archivos. Los fragmentos en sí se almacenan como archivos regulares en el disco duro o discos locales.

Todas las operaciones de archivo en un equipo cliente que ha montado una instancia de MooseFS son exactamente las mismas que si se tratara de cualquier otro sistema de archivos. El kernel del sistema operativo transfiere todas las operaciones de archivo al módulo FUSE, que se comunica con el proceso mfsmount. El proceso mfsmount se comunica a través de la red posteriormente con el servidor de gestión y los servidores de datos. Todo este proceso es completamente transparente para el usuario.

En cualquier momento se pueden añadir nuevos Servidores de Fragmentos al sistema para ampliar el espacio total disponible. Además, se pueden añadir nuevos discos duros a los Servidores de Fragmentos existentes. El Servidor Maestro añadirá automáticamente el espacio ”nuevo” al sistema de archivos. Por lo tanto, la capacidad de datos del sistema se puede ampliar casi indefinidamente, siempre que el Servidor Maestro pueda almacenar toda la información de metadatos relevante. El Servidor Maestro se asegurará de que todo el espacio de disco físico disponible se utilice de la manera más equilibrada posible.

En un sistema tan grande ocurrirán fallos de hardware. MooseFS reaccionará automáticamente en caso de fallo de un disco duro o de un Servidor de Fragmentos completo. La seguridad de los datos está garantizada por su almacenamiento en varias copias, de acuerdo con las políticas de almacenamiento definidas. Después de un fallo, el Servidor Maestro iniciará la replicación de las copias aún existentes de acuerdo con la política de almacenamiento del archivo en peligro, para restaurar su nivel de redundancia de seguridad requerido lo antes posible.

Los fallos de un equipo cliente (que ejecuta el proceso mfsmount) no tendrán ninguna influencia en la coherencia del sistema de archivos ni en las operaciones de otros clientes. En el peor de los casos, los datos que aún no se han enviado desde el equipo cliente fallido al Servidor Maestro y/o a los Servidores de Fragmentos pueden perderse.

PLATAFORMAS SOPORTADAS

mfsmount se basa en el mecanismo FUSE (Filesystem in USErspace), por lo que el cliente MooseFS está disponible en cualquier sistema operativo con una implementación FUSE que funcione.

El Servidor Maestro, el Metalogger y los Servidores de Fragmentos se pueden ejecutar en cualquier sistema operativo compatible con POSIX en la mayoría de los tipos y arquitecturas de procesadores principales. Los procesadores de 32 bits también funcionarán, pero tenga cuidado con la limitación de RAM y sus consecuencias. Se recomienda encarecidamente el uso de versiones de 64 bits de los sistemas operativos.
