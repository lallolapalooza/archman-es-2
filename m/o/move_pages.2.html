move_pages(2) Manual de Llamadas al Sistema move_pages(2)

NOMBRE

move_pages - mover páginas individuales de un proceso a otro nodo

BIBLIOTECA

Biblioteca de políticas NUMA (Acceso a Memoria No Uniforme) (libnuma, -lnuma)

SINOPSIS

#include <numaif.h>
long move_pages(int pid, unsigned long count, void *pages[count],
                const int nodes[count], int status[count],
                int flags);

DESCRIPCIÓN

move_pages() mueve las páginas especificadas del proceso pid a los nodos de memoria especificados por nodes. El resultado del movimiento se refleja en status. Las flags indican restricciones sobre las páginas a mover.

pid es el ID del proceso en el que se moverán las páginas. Si pid es 0, entonces move_pages() mueve las páginas del proceso que llama.

Para mover páginas en otro proceso se requieren los siguientes privilegios:

•
Hasta Linux 4.12 inclusive: el llamador debe tener privilegios (CAP_SYS_NICE) o el ID de usuario real o efectivo del proceso que llama debe coincidir con el ID de usuario real o del conjunto guardado del proceso objetivo.
•
Las reglas más antiguas permitían al llamador descubrir varias opciones de direcciones virtuales elegidas por el kernel que podían llevar a la derrota de la aleatorización del espacio de direcciones para un proceso propiedad de la misma UID que el llamador. Las reglas se cambiaron a partir de Linux 4.13. Desde Linux 4.13, el permiso se rige por una comprobación del modo de acceso ptrace PTRACE_MODE_READ_REALCREDS con respecto al proceso objetivo; ver ptrace(2).

count es el número de páginas a mover. Define el tamaño de los tres arrays pages, nodes y status.

pages es un array de punteros a las páginas que deben ser movidas. Estos son punteros que deben estar alineados a los límites de página. Las direcciones se especifican tal como las ve el proceso especificado por pid.

nodes es un array de enteros que especifican la ubicación deseada para cada página. Cada elemento del array es un número de nodo. nodes también puede ser NULL, en cuyo caso move_pages() no mueve ninguna página, sino que devolverá el nodo donde reside cada página actualmente, en el array status. Obtener el estado de cada página puede ser necesario para determinar las páginas que necesitan ser movidas.

status es un array de enteros que devuelve el estado de cada página. El array contiene valores válidos solo si move_pages() no devolvió un error. La preinicialización del array a un valor que no pueda representar un nodo numa real o un error válido del array de estado podría ayudar a identificar las páginas que han sido migradas.

flags especifica qué tipos de páginas mover. MPOL_MF_MOVE significa que solo se moverán las páginas que estén en uso exclusivo por el proceso. MPOL_MF_MOVE_ALL significa que las páginas compartidas entre múltiples procesos también pueden ser movidas. El proceso debe tener privilegios (CAP_SYS_NICE) para usar MPOL_MF_MOVE_ALL.

Estados de página en el array status

Los siguientes valores se pueden devolver en cada elemento del array status.

0..MAX_NUMNODES
Identifica el nodo en el que reside la página.
-EACCES
La página está mapeada por múltiples procesos y solo se puede mover si se especifica MPOL_MF_MOVE_ALL.
-EBUSY
La página está actualmente ocupada y no se puede mover. Inténtelo de nuevo más tarde. Esto ocurre si una página está en proceso de I/O o si otro subsistema del kernel está manteniendo una referencia a la página.
-EFAULT
Esta es una página cero o el área de memoria no está mapeada por el proceso.
-EIO
No se pudo escribir la página. La página debe ser escrita para ser movida ya que la página está sucia y el sistema de archivos no proporciona una función de migración que permitiría mover páginas sucias.
-EINVAL
Una página sucia no se puede mover. El sistema de archivos no proporciona una función de migración y no tiene capacidad para escribir páginas.
-ENOENT
La página no está presente.
-ENOMEM
No se pudo asignar memoria en el nodo de destino.

VALOR DE RETORNO

En caso de éxito, move_pages() devuelve cero. En caso de error, devuelve -1 y establece errno para indicar el error. Si se devuelve un valor positivo, es el número de páginas no migradas.

ERRORES

Valor positivo
El número de páginas no migradas si fueron el resultado de razones no fatales (desde Linux 4.17).
E2BIG
Demasiadas páginas para mover. Desde Linux 2.6.29, el kernel ya no genera este error.
EACCES
Uno de los nodos de destino no está permitido por el cpuset actual.
EFAULT
No se pudo acceder al array de parámetros.
EINVAL
Se especificaron flags distintas de MPOL_MF_MOVE y MPOL_MF_MOVE_ALL o se intentó migrar páginas de un hilo del kernel.
ENODEV
Uno de los nodos de destino no está en línea.
EPERM
El llamador especificó MPOL_MF_MOVE_ALL sin los privilegios suficientes (CAP_SYS_NICE). O, el llamador intentó mover páginas de un proceso perteneciente a otro usuario pero no tenía privilegios para hacerlo (CAP_SYS_NICE).
ESRCH
El proceso no existe.

ESTÁNDARES

Linux.

HISTORIA

Linux 2.6.18.

NOTAS

Para información sobre el soporte de bibliotecas, ver numa(7).

Use get_mempolicy(2) con la flag MPOL_F_MEMS_ALLOWED para obtener el conjunto de nodos permitidos por el cpuset actual. Tenga en cuenta que esta información está sujeta a cambios en cualquier momento por la reconfiguración manual o automática del cpuset.

El uso de esta función puede resultar en páginas cuya ubicación (nodo) viola la política de memoria establecida para las direcciones especificadas (Ver mbind(2)) y/o el proceso especificado (Ver set_mempolicy(2)). Es decir, la política de memoria no restringe los nodos de destino utilizados por move_pages().

La cabecera <numaif.h> no se incluye con glibc, pero requiere la instalación de libnuma-devel o un paquete similar.
