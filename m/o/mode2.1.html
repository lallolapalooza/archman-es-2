MODE2(1) 0.10.2" MODE2(1)

NOMBRE

mode2 - Muestra la salida del kernel disponible para los controladores de LIRC

SINOPSIS

mode2 --driver <controlador> [--device <dispositivo>] [otras opciones]

mode2 --raw --device <dispositivo> [otras opciones]

mode2 --driver <controlador> --list-devices

DESCRIPCIÓN

El propósito original de este programa ha sido verificar el funcionamiento del hardware receptor LIRC casero y ver la forma de onda IR del mando a distancia sin un costoso osciloscopio. Con el tiempo, mode2 ha evolucionado hasta convertirse en una herramienta genérica para verificar qué tipo de salida proporciona el kernel para lirc.

mode2 simplemente imprimirá las longitudes de pulso y espacio en stdout para los controladores que soportan LIRC_MODE_MODE2. Para los controladores que soportan LIRC_MODE_LIRCCODE, como las tarjetas de TV y el controlador irman, escribe los valores decodificados, en forma de enteros.

A partir de la versión 0.9.4, mode2 también puede listar los dispositivos disponibles para un controlador dado. Esto requiere soporte de enumeración, que está disponible en la mayoría de los controladores, pero no en todos.

Si se le proporciona el controlador correcto, mode2 siempre debería funcionar. Sin un controlador, la opción --raw siempre debería funcionar para los dispositivos /dev/lirc*. En el momento de escribir esto, los dispositivos usb también funcionan en la mayoría de los casos. Sin embargo, dado que es complicado obtener la ruta al dispositivo usb, estos suelen accederse mejor utilizando un controlador.

No todos los controladores requieren un dispositivo.

OPCIONES

-d --device=dispositivo
Leer del dispositivo especificado.
-H --driver=controlador
Usar el controlador especificado.
-m --mode
Escribir los datos de pulso/espacio como archivos de configuración brutos. No afecta a los controladores LIRCCODE.
-s --scope=tiempo
Activar visualización tipo 'osciloscopio' con tiempo en us por carácter. No afecta a los controladores lirccode.
-k --keep-root
No soltar privilegios de root después de abrir el dispositivo. Ver EJECUCIÓN COMO ROOT.
-l --list-devices
Listar todos los dispositivos disponibles para el controlador dado. Requiere soporte que no está presente en todos los controladores.
-g --gap=tiempo
Tratar los espacios más largos que tiempo como la separación. El tiempo está en microsegundos.
-r --raw
Acceder directamente al dispositivo. Esto está pensado principalmente para ser utilizado con los controladores rc del kernel, es decir, al acceder a los dispositivos /dev/lirc*. El uso de otros dispositivos puede funcionar, pero generalmente no está definido.
-A --driver-options=clave:valor[|clave:valor...]
Establecer la opción específica del controlador llamada clave al valor dado.
-U --plugindir=directorio
Cargar controladores desde el directorio. Ver CARGA DE CONTROLADORES.
-O, --options-file <ruta>
Archivo que contiene valores predeterminados para todas las opciones. Una ruta relativa se interpreta desde el directorio actual. Ver [ARCHIVOS] abajo.
-D --loglevel=nivel
Determina la cantidad de información de registro. [nivel] puede ser un nivel simbólico de syslog: 'error', 'warning', 'info', 'notice' o 'debug'. lirc también define tres niveles adicionales 'trace', 'trace1' y 'trace2' que proporcionan aún más mensajes ('trace2' proporcionando la mayor cantidad). Sin embargo, en el registro, estos mensajes se marcan como 'debug'. El nivel también puede ser un entero en el rango de 3 (casi sin mensajes) a 10.
-h --help
Mostrar resumen de uso.
-v --version
Mostrar versión.

EJECUCIÓN COMO ROOT

En muchos casos, mode2 necesita ejecutarse como root para acceder a dispositivos no disponibles para usuarios normales. Por otro lado, ejecutarse como root crea problemas como archivos de registro propiedad de root, preocupaciones de seguridad, etc.

Para hacer frente a esto, mode2, por defecto, suelta los privilegios de root después de abrir el dispositivo de entrada. Este soporte se basa en que los permisos de root se obtienen usando sudo(1), por ejemplo, usando

        $ sudo mode2 --raw /dev/lirc0
Si no se usa sudo, el mismo comportamiento se podría lograr utilizando la variable de entorno SUDO_USER, por ejemplo, 
        # SUDO_USER=$LOGNAME mode2 --raw /dev/lirc0
La opción --keep-root hará que mode2 mantenga los privilegios de root durante toda la ejecución.

EJEMPLOS

Invocado con un controlador de tipo MODE2, mode2 imprime los tiempos de espacio/marca:

     al@snorken $ ./mode2 --driver default --device /dev/lirc0
     Using driver default on device /dev/lirc0
     Trying device: /dev/lirc0
     Using device: /dev/lirc0
     pulse 2750
     space 800
     pulse 500
     space 350
     pulse 550
     space 350
     pulse 550
     ...
Invocado con un controlador de tipo LIRCCODE, mode2 imprime valores
    decodificados:

     Trying device: /dev/bus/usb/001/007
     Using device: /dev/bus/usb/001/007
     code: 0x14709b0000
     code: 0x14709b0000
     code: 0x14709b0000
     code: 0x14709b0000
     code: 0x14709b0000
     ...
Invocado usando mode2 --list-devices para el controlador devinput con
    un único dispositivo USB RF X10 conectado:
    $ ./mode2 --list-devices --driver devinput
    /dev/input/event12 [0bc7:0006] X10 WTI RF receiver vers:  1.10 serial: ?
    /dev/input/by-id/usb-X10_WTI_RF_receiver-event-if00 -> ../event12
    /dev/input/by-path/pci-0000:0b:00.0-usb-0:1:1.0-event -> ../event12

CARGA DE CONTROLADORES

Los controladores se cargan dinámicamente. La ruta de búsqueda utilizada para esto se determina por (prioridad descendente):

  • La opción --plugindir.
  • La entrada 'plugindir' en la sección [lircd] del archivo lirc_options.conf.
  • La variable de entorno LIRC_PLUGINDIR.
  • Un valor predeterminado codificado (/usr/lib/lirc/plugins).

ENTORNO

LIRC_LOGLEVEL
Se utiliza como último recurso cuando no hay una opción --loglevel presente. La sintaxis es la misma que para --loglevel, ver OPCIONES.

ARCHIVOS

/etc/lirc/lirc_options.conf
El archivo de opciones que contiene los valores predeterminados para las opciones de línea de comandos en la sección [mode2]. Para algunos valores, incluyendo debug, plugindir, driver y device, mode2 recurre a la sección [lircd] si no se encuentra en [mode2].
La ubicación de este archivo se puede cambiar usando la opción de línea de comandos -O/--options-file o usando la variable de entorno LIRC_OPTIONS_PATH.
~/.cache/mode2.log
Registro de depuración. Establecer la variable de entorno XDG_CACHE_HOME reubica este archivo a $XDG_CACHE_HOME/mode2.log. La cantidad de registro respeta la variable de entorno LIRC_LOGLEVEL, por defecto al valor debug en lirc_options.conf.

mode2(1)

NAME

mode2 - an LIRC IR signal viewer

SYNOPSIS

mode2 [-h|--help] [-v|--version] [-d|--device device] [-l|--list-namespace] [-m|--monitor] [-r|--raw] [-x|--x-axis]

DESCRIPTION

The mode2 utility is used to view the raw infrared signal data as received by the LIRC driver. It displays the timings of the pulses and spaces that constitute an infrared signal, which can be useful for debugging or for learning about IR protocols.

When mode2 is running, it displays a continuous stream of timings. Each line represents either a pulse (the duration the IR LED was on) or a space (the duration the IR LED was off). The timings are given in microseconds.

This utility is particularly helpful when you are trying to reverse-engineer an IR protocol or verify that your IR receiver hardware is functioning correctly.

OPTIONS

-h, --help
Display a help message and exit.
-v, --version
Display version information and exit.
-d, --device device
Specify the LIRC device to use. If not specified, mode2 will attempt to open the default device, usually /dev/lirc0.
-l, --list-namespace
List available LIRC device namespaces. This can be useful if you have multiple LIRC devices or custom configurations.
-m, --monitor
Monitor the LIRC device for incoming signals and display their timings. This is the default behavior when no other action is specified.
-r, --raw
Display the raw pulse and space timings without any interpretation. This is the default behavior.
-x, --x-axis
Enable the X-axis display, which shows a timeline of the pulses and spaces. This can provide a more visual representation of the signal.

RUNNING AS ROOT

Accessing the LIRC device, typically /dev/lirc0, usually requires root privileges. You may need to run mode2 with sudo.

Example: sudo mode2 -d /dev/lirc0

EXAMPLES

View IR signals from the default device:

sudo mode2

View IR signals from a specific device:

sudo mode2 -d /dev/lirc1

View IR signals with an X-axis timeline:

sudo mode2 -x

DRIVER LOADING

Ensure that the appropriate LIRC kernel module for your IR receiver hardware is loaded before running mode2. You can check loaded modules with lsmod and load them with modprobe (e.g., sudo modprobe lirc_dev and then the specific driver for your hardware).

ENVIRONMENT

LIRCD_SOCKET: If set, mode2 will attempt to connect to the specified LIRC daemon socket instead of directly accessing the device file. This is less common for mode2 itself.

FILES

/dev/lirc0
The default LIRC device file.
/etc/lirc/lircd.conf
LIRC configuration file for remote control definitions (not directly used by mode2, but relevant to the LIRC ecosystem).
