NOMBRE

mod_apparmor - confinamiento de AppArmor de grano fino para Apache

DESCRIPCIÓN

Un perfil de AppArmor se aplica a un programa ejecutable; si una parte del programa necesita permisos de acceso diferentes a otras partes, el programa puede "cambiar de sombrero" a través de aa_change_hat(2) a un rol diferente, también conocido como subperfil. El módulo Apache mod_apparmor utiliza el mecanismo de aa_change_hat(2) para ofrecer un confinamiento más detallado de elementos dinámicos dentro de Apache, como scripts individuales de php y perl, al tiempo que permite los beneficios de rendimiento de usar mod_php y mod_perl.

Para usar mod_apparmor con Apache, asegúrate de que mod_apparmor esté configurado para cargarse en Apache, ya sea a través de a2enmod, yast o editando manualmente los archivos de configuración de apache2(8)/httpd(8), y reinicia Apache. Asegúrate de que apparmor también esté funcionando.

Una vez que mod_apparmor se carga dentro de Apache, todas las solicitudes a Apache harán que mod_apparmor intente cambiar a un sombrero que coincida con el ServerName del servidor/vhost. Si no se encuentra dicho sombrero, primero recurrirá intentando cambiar a un sombrero compuesto por el ServerName-URI (por ejemplo, "www.example.com-/app/some.cgi"). Si no se encuentra ese sombrero, recurrirá intentando usar el sombrero nombrado por el URI (por ejemplo, "/app/some.cgi"). Si no se encuentra ese sombrero, recurrirá intentando usar el sombrero DEFAULT_URI; si este tampoco existe, recurrirá al perfil global de Apache. La mayoría de las páginas web estáticas pueden simplemente utilizar el sombrero DEFAULT_URI.

Además, antes de que lleguen solicitudes a Apache, mod_apparmor intentará cambiar de sombrero al sombrero HANDLING_UNTRUSTED_INPUT. mod_apparmor intentará usar este sombrero mientras Apache realiza el análisis inicial de una solicitud http dada, antes de que se entregue a un manejador específico (como mod_php) para su procesamiento.

Debido a que definir sombreros para cada URI/URL a menudo resulta tedioso, mod_apparmor proporciona las opciones de configuración de Apache AAHatName y AADefaultHatName.

AAHatName
AAHatName te permite especificar un sombrero que se utilizará para una directiva Apache <Directory>, <DirectoryMatch>, <Location> o <LocationMatch> (ver la documentación de Apache para más detalles). Ten en cuenta que el comportamiento de mod_apparmor puede confundirse si las directivas <Directory*> y <Location*> se entrelazan y se recomienda usar un tipo de directiva. Si el sombrero especificado por AAHatName no existe en el perfil de Apache, entonces recurre al comportamiento descrito anteriormente.
AADefaultHatName
AADefaultHatName te permite especificar un sombrero predeterminado que se utilizará para hosts virtuales y otras directivas de servidor de Apache, de modo que puedas tener valores predeterminados diferentes para diferentes hosts virtuales. Esto puede ser anulado por la directiva AAHatName y solo se verifica si no hay una AAHatName coincidente. El valor predeterminado de AADefaultHatName es el ServerName para la configuración del servidor/vhost. Si el sombrero AADefaultHatName no existe, entonces recurre al comportamiento descrito anteriormente.

RESUMEN DE SOLICITUD URI

Al perfilar con mod_apparmor, es útil tener en cuenta el siguiente orden de operaciones:

En cada solicitud URI, mod_apparmor primero aa_change_hat(2) a ^HANDLING_UNTRUSTED_INPUT, si existe.

Luego, después de realizar el análisis inicial de la solicitud, mod_apparmor:

1.
intentará aa_change_hat(2) a un sombrero AAHatName coincidente si existe y se aplica, de lo contrario
2.
intentará aa_change_hat(2) a un sombrero AADefaultHatName, ya sea el ServerName (el predeterminado) o el valor de configuración especificado por la directiva AADefaultHatName, para el servidor/vhost, de lo contrario
3.
intentará aa_change_hat(2) al ServerName-URI, de lo contrario
4.
intentará aa_change_hat(2) al URI mismo, de lo contrario
5.
intentará aa_change_hat(2) al sombrero DEFAULT_URI, si existe, de lo contrario
6.
recurrirá a la política global de Apache

ERRORES

mod_apparmor() actualmente solo soporta apache2, y solo ha sido probado con la configuración del MPM prefork -- las configuraciones enhebradas de Apache pueden no funcionar correctamente. Para usuarios de Apache 2.4, deberías habilitar el módulo mpm_prefork.

Es probable que haya otros errores al acecho; si encuentras alguno, por favor repórtalo en https://gitlab.com/apparmor/apparmor/-/issues.

VER TAMBIÉN

apparmor(7), apparmor_parser(8), aa_change_hat(2) y https://wiki.apparmor.net.
