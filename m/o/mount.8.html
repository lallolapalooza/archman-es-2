MOUNT(8) Administración del Sistema MOUNT(8)

NOMBRE

mount - montar un sistema de archivos

SINOPSIS

mount [-h|-V]

mount [-l] [-t tipo_fs]

mount -a [-fFnrsvw] [-t tipo_fs] [-O lista_opciones]

mount [-fnrsvw] [-o opciones] dispositivo|punto_montaje

mount [-fnrsvw] [-t tipo_fs] [-o opciones] dispositivo punto_montaje

mount --bind|--rbind|--move directorio_antiguo directorio_nuevo

mount --make-[shared|slave|private|unbindable|rshared|rslave|rprivate|runbindable] punto_montaje

DESCRIPCIÓN

Todos los archivos accesibles en un sistema Unix están organizados en un gran árbol, la jerarquía de archivos, con raíz en /. Estos archivos pueden estar distribuidos en varios dispositivos. El comando mount sirve para adjuntar el sistema de archivos encontrado en un dispositivo al gran árbol de archivos. A la inversa, el comando umount(8) lo desconecta de nuevo. El sistema de archivos se utiliza para controlar cómo se almacenan los datos en el dispositivo o se proporcionan de forma virtual a través de la red u otros servicios.

La forma estándar del comando mount es:

mount -t tipo dispositivo directorio

Esto le dice al kernel que adjunte el sistema de archivos encontrado en dispositivo (que es de tipo tipo) en el directorio directorio. La opción -t tipo es opcional. El comando mount suele ser capaz de detectar un sistema de archivos. Se requieren permisos de root para montar un sistema de archivos por defecto. Consulte la sección "Montajes de no superusuario" más abajo para más detalles. El contenido previo (si lo hubiera) y el propietario y modo de directorio se vuelven invisibles, y mientras este sistema de archivos permanezca montado, el nombre de ruta directorio se refiere a la raíz del sistema de archivos en dispositivo.

Si solo se proporciona el directorio o el dispositivo, por ejemplo:

mount /directorio

entonces mount busca un punto de montaje (y si no lo encuentra, un dispositivo) en el archivo /etc/fstab. Es posible usar las opciones --target o --source para evitar la interpretación ambigua del argumento proporcionado. Por ejemplo:

mount --target /punto_montaje

El mismo sistema de archivos puede montarse más de una vez, y en algunos casos (por ejemplo, sistemas de archivos de red) el mismo sistema de archivos puede montarse en el mismo punto de montaje varias veces. El comando mount no implementa ninguna política para controlar este comportamiento. Todo el comportamiento es controlado por el kernel y suele ser específico del controlador del sistema de archivos. La excepción es --all, en cuyo caso los sistemas de archivos ya montados se ignoran (ver --all más abajo para más detalles).

Listado de los montajes

El modo de listado se mantiene solo por compatibilidad hacia atrás.

Para una salida más robusta y personalizable, utilice findmnt(8), especialmente en sus scripts. Tenga en cuenta que los caracteres de control en el nombre del punto de montaje se reemplazan por '?'.

El siguiente comando lista todos los sistemas de archivos montados (de tipo tipo):

mount [-l] [-t tipo]

La opción -l añade etiquetas a este listado. Ver más abajo.

Indicando el dispositivo y el sistema de archivos

La mayoría de los dispositivos se indican mediante un nombre de archivo (de un dispositivo especial de bloque), como /dev/sda1, pero existen otras posibilidades. Por ejemplo, en el caso de un montaje NFS, dispositivo puede parecer knuth.cwi.nl:/dir.

Los nombres de dispositivo de las particiones de disco son inestables; la reconfiguración del hardware y la adición o eliminación de un dispositivo pueden provocar cambios en los nombres. Esta es la razón por la que se recomienda encarecidamente utilizar identificadores de sistema de archivos o particiones como UUID o LABEL. Los identificadores (etiquetas) actualmente soportados son:

LABEL=etiqueta

Identificador de sistema de archivos legible por humanos. Ver también -L.

UUID=uuid

Identificador universalmente único del sistema de archivos. El formato del UUID suele ser una serie de dígitos hexadecimales separados por guiones. Ver también -U.

Tenga en cuenta que mount utiliza UUIDs como cadenas. Los UUIDs de la línea de comandos o de fstab(5) no se convierten a representación binaria interna. La representación de cadena del UUID debe basarse en caracteres en minúsculas.

PARTLABEL=etiqueta

Identificador de partición legible por humanos. Este identificador es independiente del sistema de archivos y no cambia por operaciones mkfs o mkswap. Es compatible, por ejemplo, con Tablas de Particiones GUID (GPT).

PARTUUID=uuid

Identificador universalmente único de partición. Este identificador es independiente del sistema de archivos y no cambia por operaciones mkfs o mkswap. Es compatible, por ejemplo, con Tablas de Particiones GUID (GPT).

ID=id

ID del dispositivo de bloque de hardware generado por udevd. Este identificador suele basarse en WWN (identificador único de almacenamiento) y lo asigna el fabricante del hardware. Ver ls /dev/disk/by-id para más detalles, se requiere este directorio y la ejecución de udevd. No se recomienda este identificador para uso genérico, ya que el identificador no está estrictamente definido y depende de udev, las reglas de udev y el hardware.

El comando lsblk --fs proporciona una visión general de los sistemas de archivos, etiquetas y UUIDs en los dispositivos de bloque disponibles. El comando blkid -p <dispositivo> proporciona detalles sobre un sistema de archivos en el dispositivo especificado.

No olvide que no hay garantía de que los UUIDs y las etiquetas sean realmente únicos, especialmente si mueve, comparte o copia el dispositivo. Use lsblk -o +UUID,PARTUUID para verificar que los UUIDs son realmente únicos en su sistema.

La configuración recomendada es usar etiquetas (por ejemplo, UUID=uuid) en lugar de los símbolos de enlace /dev/disk/by-{label,uuid,id,partuuid,partlabel} en el archivo /etc/fstab. Las etiquetas son más legibles, robustas y portátiles. El comando mount utiliza internamente enlaces de udev, por lo que el uso de enlaces en /etc/fstab no tiene ventaja sobre las etiquetas. Para más detalles, consulte libblkid(3).

El sistema de archivos proc no está asociado a un dispositivo especial, y al montarlo, se puede usar una palabra clave arbitraria, por ejemplo, proc, en lugar de una especificación de dispositivo. (La elección habitual none no es afortunada: el mensaje de error 'none already mounted' de mount puede ser confuso).

Los archivos /etc/fstab, /etc/mtab y /proc/mounts

El archivo /etc/fstab (ver fstab(5)), puede contener líneas que describen qué dispositivos suelen montarse dónde, usando qué opciones. La ubicación por defecto del archivo fstab(5) puede ser reemplazada con la opción de línea de comandos --fstab ruta (ver más abajo para más detalles).

El comando

mount -a [-t tipo] [-O lista_opciones]

(normalmente dado en un script de arranque) hace que todos los sistemas de archivos mencionados en fstab (del tipo correcto y/o que tengan o no tengan las opciones correctas) se monten como se indica, excepto aquellos cuya línea contenga la palabra clave noauto. Añadir la opción -F hará que mount se bifurque, de modo que los sistemas de archivos se monten en paralelo.

Al montar un sistema de archivos mencionado en fstab o mtab, basta con especificar en la línea de comandos solo el dispositivo, o solo el punto de montaje.

Los programas mount y umount(8) tradicionalmente mantenían una lista de los sistemas de archivos montados actualmente.

mount -o remount,bind [-O FSTYPE_OPTS ] [-r | -w] [-t FSTYPE ] [-U UUID | -L LABEL | -D ID | -p PARTUUID | -P PARTLABEL] [--source DEVICE] [--target DIR] [--mount-type TYPE]

DESCRIPTION

The mount program is used to mount bushels of filesystems onto directories. A mount is a process of making a directory tree from another storage device or filesystem available to the local filesystem. The mount point specified by DIR must exist.

By default, mount takes a list of devices or mount points as arguments. It also accepts filesystem type parameters and mount options from the command line.

If no arguments are given to mount, it reads /etc/fstab and mounts all filesystems listed there that have the auto mount option set and are not already mounted. The command `mount -a` mounts all filesystems listed in fstab(5) that have the auto option set.

The options understood by mount are listed below. Only privileged users can mount filesystems. This can be changed by the user option in fstab(5).

The actual implementation of the mount operation is performed by the kernel. The mount program is mainly a wrapper around the mount(2) system call and the mount(8) utility.

The mount program uses libmount to provide support for various mount types and configurations.

The mount command does not support the auto mount option from fstab(5) for command line invocations. Use `mount -a` to mount all filesystems with the auto option.

The following filesystems are not automatically mounted:

  • Filesystems with the noauto option in fstab(5).
  • Loop devices that are not explicitly mentioned in fstab(5).
  • Network filesystems (unless they have the _netdev option set in fstab(5)).

The mount program uses the standard locations for filesystem configuration files: /etc/fstab. It checks for specific device identifiers (e.g., LABEL=..., UUID=..., ID=..., PARTUUID=..., PARTLABEL=...) in addition to device names (e.g., /dev/sda1).

The mount program manages the list of mounted filesystems in the file /etc/mtab. The support for regular classic /etc/mtab is completely disabled at compile time by default, because on current Linux systems it is better to make /etc/mtab a symlink to /proc/mounts instead. The regular mtab file maintained in userspace cannot reliably work with namespaces, containers and other advanced Linux features. If the regular mtab support is enabled, then it’s possible to use the file as well as the symlink.

If no arguments are given to mount, the list of mounted filesystems is printed.

If you want to override mount options from /etc/fstab, you have to use the -o option:

mount device|dir -o options

and then the mount options from the command line will be appended to the list of options from /etc/fstab. This default behaviour can be changed using the --options-mode command-line option. The usual behavior is that the last option wins if there are conflicting ones.

The mount program does not read the /etc/fstab file if both device (or LABEL, UUID, ID, PARTUUID or PARTLABEL) and dir are specified. For example, to mount device foo at /dir:

mount /dev/foo /dir

This default behaviour can be changed by using the --options-source-force command-line option to always read configuration from fstab. For non-root users mount always reads the fstab configuration.

Non-superuser mounts

Normally, only the superuser can mount filesystems. However, when fstab contains the user option on a line, anybody can mount the corresponding filesystem.

Thus, given a line

/dev/cdrom /cd iso9660 ro,user,noauto,unhide

any user can mount the iso9660 filesystem found on an inserted CDROM using the command:

mount /cd

Note that mount is very strict about non-root users and all paths specified on command line are verified before fstab is parsed or a helper program is executed. It’s strongly recommended to use a valid mountpoint to specify filesystem, otherwise mount may fail. For example it’s a bad idea to use NFS or CIFS source on command line.

Since util-linux 2.35, mount does not exit when user permissions are inadequate according to libmount’s internal security rules. Instead, it drops suid permissions and continues as regular non-root user. This behavior supports use-cases where root permissions are not necessary (e.g., fuse filesystems, user namespaces, etc).

For more details, see fstab(5). Only the user that mounted a filesystem can unmount it again. If any user should be able to unmount it, then use users instead of user in the fstab line. The owner option is similar to the user option, with the restriction that the user must be the owner of the special file. This may be useful e.g. for /dev/fd if a login script makes the console user owner of this device. The group option is similar, with the restriction that the user must be a member of the group of the special file.

The user mount option is accepted if no username is specified. If used in the format user=someone, the option is silently ignored and visible only for external mount helpers (/sbin/mount.<type>) for compatibility with some network filesystems.

Bind mount operation

Remount part of the file hierarchy somewhere else. The call is:

mount --bind olddir newdir

or by using this fstab entry:

/olddir /newdir none bind

After this call the same contents are accessible in two places.

It is important to understand that "bind" does not create any second-class or special node in the kernel VFS. The "bind" is just another operation to attach a filesystem. There is nowhere stored information that the filesystem has been attached by a "bind" operation. The olddir and newdir are independent and the olddir may be unmounted.

One can also remount a single file (on a single file). It’s also possible to use a bind mount to create a mountpoint from a regular directory, for example:

mount --bind foo foo

The bind mount call attaches only (part of) a single filesystem, not possible submounts. The entire file hierarchy including submounts can be attached a second place by using:

mount --rbind olddir newdir

Note that the filesystem mount options maintained by the kernel will remain the same as those on the original mount point. The userspace mount options (e.g., _netdev) will not be copied by mount and it’s necessary to explicitly specify the options on the mount command line.

Since util-linux 2.27 mount permits changing the mount options by passing the relevant options along with --bind. For example:

mount -o bind,ro foo foo

This feature is not supported by the Linux kernel; it is implemented in userspace by an additional mount(2) remounting system call. This solution is not atomic.

The alternative (classic) way to create a read-only bind mount is to use the remount operation, for example:

mount --bind olddir newdir

mount -o remount,bind,ro olddir newdir

Note that a read-only bind will create a read-only mountpoint (VFS entry), but the original filesystem superblock will still be writable, meaning that the olddir will be writable, but the newdir will be read-only.

It’s also possible to change nosuid, nodev, noexec, noatime, nodiratime, relatime and nosymfollow VFS entry flags via a "remount,bind" operation. The other flags (for example filesystem-specific flags) are silently ignored. The classic mount(2) system call does not allow to change mount options recursively (for example with -o rbind,ro). The recursive semantic is possible with a new mount_setattr(2) kernel system call and it’s supported since libmount from util-linux v2.39 by a new experimental "recursive" option argument (e.g. -o rbind,ro=recursive). For more details see the FILESYSTEM-INDEPENDENT MOUNT OPTIONS section.

Since util-linux 2.31, mount ignores the bind flag from /etc/fstab on a remount operation (if -o remount is specified on command line). This is necessary to fully control mount options on remount by command line. In previous versions the bind flag has been always applied and it was impossible to re-define mount options without interaction with the bind semantic. This mount behavior does not affect situations when "remount,bind" is specified in the /etc/fstab file.

Since util-linux 2.39, mount may use the new kernel mount API if it is available. This new kernel interface provides a more precise way to work with mountpoint attributes. For example, the -o bind,rw operation will create a read-write node even if the original node was read-only. This was impossible with the old classic mount(2) syscall, where the read-only VFS flag was inherited from the original node.

The move operation

Move a mounted tree to another place (atomically). The call is:

mount --move olddir newdir

This will cause the contents which previously appeared under olddir to now be accessible under newdir. The physical location of the files is not changed. Note that olddir has to be a mountpoint.

Note also that moving a mount residing under a shared mount is invalid and unsupported. Use findmnt -o TARGET,PROPAGATION to see the current propagation flags.

Shared subtree operations

Since Linux 2.6.15 it is possible to mark a mount and its submounts as shared, private, slave or unbindable. A shared mount provides the ability to create mirrors of that mount such that mounts and unmounts within any of the mirrors propagate to the other mirror. A slave mount receives propagation from its master, but not vice versa. A private mount carries no propagation abilities. An unbindable mount is a private mount which cannot be cloned through a bind operation. The detailed semantics are documented in Documentation/filesystems/sharedsubtree.txt file in the kernel source tree; see also mount_namespaces(7).

Supported operations are:

mount --make-shared mountpoint
mount --make-slave mountpoint
mount --make-private mountpoint
mount --make-unbindable mountpoint

The following commands allow one to recursively change the type of all the mounts under a given mountpoint.

mount --make-rshared mountpoint
mount --make-rslave mountpoint
mount --make-rprivate mountpoint
mount --make-runbindable mountpoint

mount does not read fstab(5) when a --make-* operation is requested. All necessary information has to be specified on the command line.

Note that the Linux kernel does not allow changing multiple propagation flags with a single mount(2) system call, and the flags cannot be mixed with other mount options and operations.

Since util-linux 2.23 the mount command can be used to do more propagation (topology) changes by one mount(2) call and do it also together with other mount operations. The propagation flags are applied by additional mount(2) system calls when the preceding mount operations were successful. Note that this use case is not atomic

. Es posible especificar las banderas de propagación en fstab(5) como opciones de montaje (private, slave, shared, unbindable, rprivate, rslave, rshared, runbindable).

Por ejemplo:

mount --make-private --make-unbindable /dev/sda1 /foo

es lo mismo que:

mount /dev/sda1 /foo
mount --make-private /foo
mount --make-unbindable /foo

OPCIONES DE LÍNEA DE COMANDOS

El conjunto completo de opciones de montaje utilizadas por una invocación de mount se determina extrayendo primero las opciones de montaje para el sistema de archivos de la tabla de fstab, luego aplicando cualquier opción especificada por el argumento -o, y finalmente aplicando una opción -r o -w, cuando está presente.

El comando mount no pasa todas las opciones de línea de comandos a los ayudantes de montaje /sbin/mount.sufijo. La interfaz entre mount y los ayudantes de montaje se describe a continuación en la sección AYUDANTES EXTERNOS.

Las opciones de línea de comandos disponibles para el comando mount son:

-a, --all

Monta todos los sistemas de archivos (de los tipos dados) mencionados en fstab (excepto aquellos cuya línea contenga la palabra clave noauto). Los sistemas de archivos se montan siguiendo su orden en fstab. El comando mount compara la fuente del sistema de archivos, el destino (y la raíz del fs para el montaje bind o btrfs) para detectar sistemas de archivos ya montados. La tabla del kernel con los sistemas de archivos ya montados se almacena en caché durante mount --all. Esto significa que se montarán todas las entradas duplicadas de fstab.

La funcionalidad correcta depende de /proc (para detectar sistemas de archivos ya montados) y de /sys (para evaluar etiquetas de sistemas de archivos como UUID= o LABEL=). Se recomienda encarecidamente montar los sistemas de archivos /proc y /sys antes de que se ejecute mount -a, o mantener /proc y /sys al principio de fstab.

La opción --all se puede usar también para operaciones de remontaje. En ese caso, todos los filtros (-t y -O) se aplican a la tabla de sistemas de archivos ya montados.

Desde la versión 2.35 es posible usar la opción de línea de comandos -o para modificar las opciones de montaje de fstab (ver también --options-mode).

Tenga en cuenta que es una mala práctica usar mount -a para verificar fstab. La solución recomendada es findmnt --verify.

-B, --bind

Remonta un subárbol en otro lugar (para que su contenido esté disponible en ambos lugares). Ver arriba, en la sección Operación de montaje bind.

-c, --no-canonicalize

No canonicalizar ninguna ruta o etiqueta durante el proceso de montaje. El comando mount canonicaliza automáticamente todas las rutas (de la línea de comandos o de fstab). Esta opción se puede usar en conjunción con la bandera -f para rutas que ya están canonicalizadas. Esta opción está destinada a ayudantes de montaje que llaman a mount -i. Se recomienda encarecidamente no usar esta opción de línea de comandos para operaciones de montaje regulares. Ver también las opciones de montaje X-mount.nocanonicalize.

Tenga en cuenta que mount no pasa esta opción a los ayudantes /sbin/mount.tipo.

-F, --fork

(Usado en conjunción con -a.) Inicia una nueva instanciación de mount para cada dispositivo. Esto realizará los montajes en diferentes dispositivos o diferentes servidores NFS en paralelo. Esto tiene la ventaja de ser más rápido; además, los tiempos de espera de NFS proceden en paralelo. Una desventaja es que el orden de las operaciones de montaje no está definido. Por lo tanto, no puede usar esta opción si desea montar tanto /usr como /usr/spool.

-f, --fake

Hace que se haga todo excepto las llamadas al sistema relacionadas con el montaje. La opción --fake fue diseñada originalmente para escribir una entrada en /etc/mtab sin montar realmente.

/etc/mtab ya no se mantiene en el espacio de usuario, y a partir de la versión 2.39, la operación de montaje puede ser una compleja cadena de operaciones con dependencias entre las llamadas al sistema. La opción --fake obliga a libmount a omitir toda la preparación de la fuente de montaje, el análisis de las opciones de montaje y el proceso de montaje real.

La diferencia entre la ejecución simulada y la real es enorme. Esta es la razón por la que la opción --fake tiene una importancia mínima para la implementación actual de mount(8) y se mantiene principalmente por compatibilidad con versiones anteriores.

-i, --internal-only

No llame al ayudante /sbin/mount.sistema de archivos aunque exista.

-L, --label etiqueta

Monta la partición que tiene la etiqueta especificada.

-l, --show-labels

Agrega las etiquetas en la salida de montaje. mount debe tener permiso para leer el dispositivo de disco (por ejemplo, ser root con set-user-ID) para que esto funcione. Se puede establecer una etiqueta así para ext2, ext3 o ext4 usando la utilidad e2label(8), o para XFS usando xfs_admin(8), o para reiserfs usando reiserfstune(8).

-M, --move

Mueve un subárbol a otro lugar. Ver arriba, en la subsección La operación de mover.

-m, --mkdir[=modo]

Permite crear un directorio de destino (punto de montaje) si aún no existe. Alias de "-o X-mount.mkdir[=modo]", el modo predeterminado es 0755. Para más detalles ver X-mount.mkdir abajo.

--map-groups, --map-users interior:_exterior_:_conteo_

Agrega el mapeo de usuario/grupo especificado a un mapa de X-mount.idmap. Estas opciones se pueden dar varias veces para construir mapeos completos para usuarios y grupos. Para más detalles ver X-mount.idmap abajo.

--map-users /proc/PID/ns/user

Usa el espacio de nombres de usuario especificado para el mapeo de usuarios y grupos en un montaje mapeado por ID. Este es un alias de "-o X-mount.idmap=/proc/PID/ns/user" y no se puede usar dos veces ni junto con el formato de opción interior:_exterior_:_conteo_ anterior. Para más detalles ver X-mount.idmap abajo.

-n, --no-mtab

Monta sin escribir en /etc/mtab. Esto es necesario, por ejemplo, cuando /etc está en un sistema de archivos de solo lectura.

-N, --namespace ns

Realiza la operación de montaje en el espacio de nombres de montaje especificado por ns. ns es el PID de un proceso que se ejecuta en ese espacio de nombres o un archivo especial que representa ese espacio de nombres.

mount cambia al espacio de nombres de montaje cuando lee /etc/fstab, escribe /etc/mtab: (o escribe en _/run/mount) y llama a mount(2), de lo contrario se ejecuta en el espacio de nombres de montaje original. Esto significa que el espacio de nombres de destino no tiene que contener bibliotecas u otros requisitos necesarios para ejecutar la llamada a mount(2).

Ver mount_namespaces(7) para más información.

-O, --test-opts opts

Limita el conjunto de sistemas de archivos a los que se aplica la opción -a. A este respecto, es como la opción -t, excepto que -O es inútil sin -a. Por ejemplo, el comando

mount -a -O no_netdev

monta todos los sistemas de archivos excepto aquellos que tienen la opción netdev especificada en el campo de opciones del archivo /etc/fstab.

Es diferente de -t en que cada opción coincide exactamente; un no inicial al principio de una opción no niega el resto.

Las opciones -t y -O son acumulativas en su efecto; es decir, el comando

mount -a -t ext2 -O _netdev

monta todos los sistemas de archivos ext2 con la opción _netdev, no todos los sistemas de archivos que son ext2 o tienen la opción _netdev especificada.

-o, --options opts

Usa las opciones de montaje especificadas. El argumento opts es una lista separada por comas. Por ejemplo:

mount LABEL=mydisk -o noatime,nodev,nosuid

Tenga en cuenta que el orden de las opciones importa, ya que la última opción gana si hay conflictos. Las opciones de la línea de comandos también sobrescriben las opciones de fstab por defecto.

Para más detalles, ver las secciones OPCIONES DE MONTAJE INDEPENDIENTES DEL SISTEMA DE ARCHIVOS y OPCIONES DE MONTAJE ESPECÍFICAS DEL SISTEMA DE ARCHIVOS.

--onlyonce

Fuerza al comando mount a verificar si el sistema de archivos ya está montado. Este comportamiento es el predeterminado para --all; de lo contrario, depende del controlador del sistema de archivos del kernel. Algunos sistemas de archivos pueden montarse más de una vez en el mismo punto de montaje (por ejemplo, tmpfs).

--options-mode modo

Controla cómo combinar las opciones de fstab/mtab con las opciones de la línea de comandos. modo puede ser uno de ignore, append, prepend o replace. Por ejemplo, append significa que las opciones de fstab se agregan a las opciones de la línea de comandos. El valor predeterminado es prepend, lo que significa que las opciones de la línea de comandos se evalúan después de las opciones de fstab. Tenga en cuenta que la última opción gana si hay conflictos.

--options-source fuente

Fuente de las opciones predeterminadas. fuente es una lista separada por comas de fstab, mtab y disable. disable deshabilita fstab y mtab y habilita --options-source-force. El valor predeterminado es fstab,mtab.

--options-source-force

Usa las opciones de fstab/mtab incluso si se especifican tanto dispositivo como directorio.

-R, --rbind

Remonta un subárbol y todos los submontajes posibles en otro lugar (para que su contenido esté disponible en ambos lugares). Ver arriba, en la subsección Operación de montaje bind.

-r, --read-only

Monta el sistema de archivos en modo de solo lectura. Un sinónimo es -o ro.

Tenga en cuenta que, dependiendo del tipo de sistema de archivos, el estado y el comportamiento del kernel, el sistema aún puede escribir en el dispositivo. Por ejemplo, ext3 y ext4 reproducirán el diario si el sistema de archivos está sucio. Para evitar este tipo de acceso de escritura, es posible que desee montar un sistema de archivos ext3 o ext4 con las opciones de montaje ro,noload o establecer el propio dispositivo de bloque en modo de solo lectura, consulte el comando blockdev(8).

-s

Tolerar opciones de montaje descuidadas en lugar de fallar. Esto ignorará las opciones de montaje no soportadas por un tipo de sistema de archivos. No todos los sistemas de archivos soportan esta opción. Actualmente, solo está soportada por el ayudante de montaje mount.nfs.

--source dispositivo

Si solo se da un argumento al comando mount, el argumento podría ser interpretado como el destino (punto de montaje) o el origen (dispositivo). Esta opción permite definir explícitamente que el argumento es el origen del montaje.

--target directorio

Si solo se da un argumento al comando mount, el argumento podría ser interpretado como el destino (punto de montaje) o el origen (dispositivo). Esta opción permite definir explícitamente que el argumento es el destino del montaje.

--target-prefix directorio

Anteponer el directorio especificado a todos los destinos de montaje. Esta opción se puede usar para seguir el fstab, pero las operaciones de montaje se realizan en otro lugar, por ejemplo:

mount --all --target-prefix /chroot -o X-mount.mkdir

monta todo desde el fstab del sistema en /chroot, todos los puntos de montaje faltantes se crean (debido a X-mount.mkdir). Ver también --fstab para usar un fstab alternativo.

-T, --fstab ruta

Especifica un archivo fstab alternativo. Si ruta es un directorio, entonces los archivos en el directorio se ordenan por strverscmp(3); los archivos que comienzan con "." o que no tienen una extensión .fstab se ignoran. La opción se puede especificar más de una vez. Esta opción está diseñada principalmente para scripts initramfs o chroot donde se especifica configuración adicional más allá de la configuración estándar del sistema.

Tenga en cuenta que mount no pasa la opción --fstab a los ayudantes /sbin/mount.tipo, lo que significa que los archivos fstab alternativos serán invisibles para los ayudantes. Esto no es un problema para los montajes normales, pero los montajes de usuario (no root) siempre requieren fstab para verificar los derechos del usuario.

-t, --types tipo_fs

El argumento que sigue a -t se utiliza para indicar el tipo de sistema de archivos. Los tipos de sistemas de archivos que actualmente se soportan dependen del kernel en ejecución. Consulte /proc/filesystems y /lib/modules/$(uname -r)/kernel/fs para obtener una lista completa de los sistemas de archivos. Los más comunes son ext2, ext3, ext4, xfs, btrfs, vfat, sysfs, proc, nfs y cifs.

Los programas mount y umount(8) soportan subtipos de sistemas de archivos. El subtipo se define mediante un sufijo '.subtype'. Por ejemplo, 'fuse.sshfs'. Se recomienda usar la notación de subtipo en lugar de añadir cualquier prefijo al origen del montaje (por ejemplo, 'sshfs#example.com' está obsoleto).

Si no se proporciona la opción -t, o si se especifica el tipo auto, mount intentará adivinar el tipo deseado. mount utiliza la biblioteca libblkid(3) para adivinar el tipo de sistema de archivos; si eso no arroja nada familiar, mount intentará leer el archivo /etc/filesystems, o, si este no existe, /proc/filesystems. Se intentarán todos los tipos de sistemas de archivos listados allí, excepto aquellos que están etiquetados como "nodev" (por ejemplo, devpts, proc y nfs). Si /etc/filesystems termina en una línea con un solo *, mount leerá /proc/filesystems después. Mientras intenta, todos los tipos de sistemas de archivos se montarán con la opción de montaje silent.

El tipo auto puede ser útil para disquetes montados por usuario. Crear un archivo /etc/filesystems puede ser útil para cambiar el orden de sondeo (por ejemplo, para intentar vfat antes que msdos o ext3 antes que ext2) o si utiliza un cargador automático de módulos del kernel.

Se pueden especificar varios tipos en una lista separada por comas, tanto para la opción -t como en una entrada de /etc/fstab. La lista de tipos de sistemas de archivos para la opción -t puede ir precedida de no para especificar los tipos de sistemas de archivos sobre los que no se debe tomar ninguna acción. El prefijo no no tiene efecto cuando se especifica en una entrada de /etc/fstab.

El prefijo no puede ser significativo con la opción -a. Por ejemplo, el comando

mount -a -t nomsdos,smbfs

monta todos los sistemas de archivos excepto los de tipo msdos y smbfs.

Para la mayoría de los tipos, todo lo que el programa mount tiene que hacer es emitir una simple llamada al sistema mount(2), y no se requiere conocimiento detallado del tipo de sistema de archivos. Sin embargo, para algunos tipos (como nfs, nfs4, cifs, smbfs, ncpfs) es necesario un código ad hoc. Los sistemas de archivos nfs, nfs4, cifs, smbfs y ncpfs tienen un programa de montaje separado. Para que sea posible tratar todos los tipos de manera uniforme, mount ejecutará el programa /sbin/mount.tipo (si existe) cuando se llame con el tipo tipo. Dado que diferentes versiones del programa smbmount tienen diferentes convenciones de llamada, /sbin/mount.smbfs puede tener que ser un script de shell que configure la llamada deseada.

-U, --uuid uuid

Monta la partición que tiene el uuid especificado.

-v, --verbose

Habilita el modo detallado. A partir de la versión 2.41, si está disponible la nueva API de montaje del kernel, también imprimirá mensajes de información del kernel.

-w, --rw, --read-write

Monta el sistema de archivos en modo lectura/escritura. Lectura/escritura es el predeterminado del kernel y el predeterminado de mount es intentar solo lectura si la llamada al sistema mount(2) anterior con banderas de lectura/escritura en dispositivos protegidos contra escritura falló.

Un sinónimo es -o rw.

Tenga en cuenta que especificar -w en la línea de comandos fuerza a mount a nunca intentar un montaje solo lectura en dispositivos protegidos contra escritura o sistemas de archivos ya montados en solo lectura.

-h, --help

Muestra el texto de ayuda y sale.

-V, --version

Muestra la versión y sale.

OPCIONES DE MONTAJE INDEPENDIENTES DEL SISTEMA DE ARCHIVOS

Algunas de estas opciones solo son útiles cuando aparecen en el archivo /etc/fstab.

Algunas de estas opciones podrían estar habilitadas o deshabilitadas por defecto en el kernel del sistema. Para verificar la configuración actual, consulte las opciones en /proc/mounts. Tenga en cuenta que los sistemas de archivos también tienen opciones de montaje predeterminadas específicas para cada sistema de archivos (vea, por ejemplo, la salida de tune2fs -l para sistemas de archivos extN).

Notas sobre Sistemas de Archivos Virtuales

El Sistema de Archivos Virtual (VFS) es la capa abstracta en el kernel que proporciona la interfaz del sistema de archivos a los programas del espacio de usuario. También proporciona una abstracción dentro del kernel que permite que coexistan diferentes implementaciones de sistemas de archivos. Algunas de las opciones de montaje solo se aplican a esta capa.

Las opciones nosuid, noexec, nodiratime, relatime, noatime, strictatime y nosymfollow son interpretadas solo por la capa del kernel del sistema de archivos virtual y se aplican al nodo del punto de montaje en lugar de al propio sistema de archivos. Para obtener una visión completa de los sistemas de archivos y las opciones VFS, intente:

findmnt -o TARGET,VFS-OPTIONS,FS-OPTIONS

Desde la v2.39, libmount puede usar una nueva interfaz de montaje del kernel para establecer los atributos VFS de forma recursiva. Para compatibilidad con versiones anteriores, esta característica no está habilitada por defecto, incluso si se ha solicitado la operación recursiva (por ejemplo, rbind). El argumento de opción nuevo "recursive" se puede especificar, por ejemplo:

mount -orbind,ro=recursive,noexec=recursive,nosuid /foo /bar

Esto enlaza recursivamente los sistemas de archivos de /foo a /bar, haciendo que /bar y todos los submontajes sean de solo lectura y no ejecutables, pero solo /bar será "nosuid". El argumento opcional "recursive" para las opciones de montaje VFS es una característica EXPERIMENTAL.

Notas sobre la Configuración de Solo Lectura

La configuración de solo lectura (ro o rw) es interpretada por el sistema de archivos virtual y el sistema de archivos, y depende de cómo se especifique la opción en la línea de comandos de mount(8). Para compatibilidad con versiones anteriores, el predeterminado es usarlo para ambas capas durante las operaciones de montaje estándar.

La operación "-o bind,remount,ro" se aplica solo al punto de montaje VFS, mientras que la operación "-o remount,ro" se aplica tanto al VFS como a la superestructura del sistema de archivos. Esta semántica permite la creación de un punto de montaje de solo lectura mientras se mantiene el sistema de archivos escribible desde otro punto de montaje.

Desde la versión 2.41, libmount tiene la capacidad de usar argumentos opcionales vfs y fs (por ejemplo, ro=fs) para especificar dónde se debe aplicar la configuración de solo lectura. Por ejemplo, usando el comando:

mount -o ro=vfs /dev/sdc1 /A

montará el sistema de archivos como de solo lectura a nivel de la superestructura, pero el nodo /A se establecerá como de solo lectura. En versiones anteriores, esto requería una operación adicional "-o bind,remount,ro" para lograr el mismo resultado.

Opciones de Montaje Genéricas

Las siguientes opciones se aplican a cualquier sistema de archivos que se esté montando, pero no todos los sistemas de archivos las respetan realmente. Por ejemplo, la opción sync solo tiene efecto en los sistemas de archivos ext2, ext3, ext4, fat, vfat, ufs y xfs.

async

Todas las E/S al sistema de archivos deben realizarse de forma asíncrona. (Ver también la opción sync.)

atime

No utilizar la característica noatime, de modo que la hora de acceso del inodo esté controlada por los valores predeterminados del kernel. Ver también las descripciones de las opciones de montaje relatime y strictatime.

noatime

No actualizar las horas de acceso de los inodos en este sistema de archivos (por ejemplo, para un acceso más rápido en el spool de noticias para acelerar los servidores de noticias). Esto funciona para todos los tipos de inodos (incluidos los directorios), por lo que implica nodiratime.

auto

Se puede montar con la opción -a.

noauto

Solo se puede montar explícitamente (es decir, la opción -a no provocará el montaje del sistema de archivos).

context=contexto, fscontext=contexto, defcontext=contexto y rootcontext=contexto

TLa opción context= es útil al montar sistemas de archivos que no admiten atributos extendidos, como un disquete o un disco duro formateado con VFAT, o sistemas que normalmente no se ejecutan bajo SELinux, como un disco formateado con ext3 o ext4 de una estación de trabajo que no sea SELinux. También puede usar context= en sistemas de archivos en los que no confía, como un disquete. También ayuda en la compatibilidad con sistemas de archivos que admiten xattr en versiones anteriores del kernel 2.4.<x>. Incluso donde se admiten xattrs, puede ahorrar tiempo al no tener que etiquetar cada archivo asignando un contexto de seguridad a todo el disco.

Una opción utilizada comúnmente para medios extraíbles es context="system_u:object_r:removable_t.

La opción fscontext= funciona para todos los sistemas de archivos, independientemente de su compatibilidad con xattr. La opción fscontext establece la etiqueta general del sistema de archivos a un contexto de seguridad específico. Esta etiqueta del sistema de archivos está separada de las etiquetas individuales de los archivos. Representa todo el sistema de archivos para ciertos tipos de verificaciones de permisos, como durante el montaje o la creación de archivos. Las etiquetas de archivos individuales aún se obtienen de los xattrs de los propios archivos. La opción context en realidad establece el contexto agregado que proporciona fscontext, además de proporcionar la misma etiqueta para archivos individuales.

Puede establecer el contexto de seguridad predeterminado para los archivos sin etiquetar utilizando la opción defcontext=. Esto anula el valor establecido para los archivos sin etiquetar en la política y requiere un sistema de archivos que admita el etiquetado de xattr.

La opción rootcontext= le permite etiquetar explícitamente el inode raíz de un FS que se está montando antes de que dicho FS o inode sea visible para el espacio de usuario. Esto resultó útil para cosas como Linux sin estado. El valor especial @target se puede usar para asignar el contexto actual de la ubicación del punto de montaje de destino.

Tenga en cuenta que el kernel rechaza cualquier solicitud de remontaje que incluya la opción context, incluso cuando no se ha modificado con respecto al contexto actual.

Advertencia: el valor de context puede contener comas, en cuyo caso el valor debe ser debidamente entrecomillado, de lo contrario, mount interpretará la coma como un separador entre las opciones de montaje. No olvide que la shell elimina las comillas y, por lo tanto, se requiere el doble entrecomillado. Por ejemplo:

mount -t tmpfs none /mnt -o \
'context="system_u:object_r:tmp_t:s0:c127,c456",noexec'

Para más detalles, vea selinux(8).

defaults

Use las opciones predeterminadas: rw, suid, dev, exec, auto, nouser y async.

Tenga en cuenta que el conjunto real de todas las opciones de montaje predeterminadas depende del kernel y del tipo de sistema de archivos. Consulte el principio de esta sección para obtener más detalles.

dev

Interpretar dispositivos especiales de caracteres o bloques en el sistema de archivos.

nodev

No interpretar dispositivos especiales de caracteres o bloques en el sistema de archivos.

diratime

Actualizar los tiempos de acceso a los inodos de los directorios en este sistema de archivos. Esta es la opción predeterminada. (Esta opción se ignora cuando se establece noatime).

nodiratime

No actualizar los tiempos de acceso a los inodos de los directorios en este sistema de archivos. (Esta opción se implica cuando se establece noatime).

dirsync

Todas las actualizaciones de directorios dentro del sistema de archivos deben realizarse de forma síncrona. Esto afecta a las siguientes llamadas al sistema: creat(2), link(2), unlink(2), symlink(2), mkdir(2), rmdir(2), mknod(2) y rename(2).

exec

Permitir la ejecución de binarios y otros archivos ejecutables.

noexec

No permitir la ejecución directa de ningún binario en el sistema de archivos montado.

group

Permitir que un usuario normal monte el sistema de archivos si uno de los grupos de ese usuario coincide con el grupo del dispositivo. Esta opción implica las opciones nosuid y nodev (a menos que se anulen mediante opciones posteriores, como en la línea de opciones group,dev,suid).

iversion

Cada vez que se modifica el inodo, se incrementará el campo i_version.

noiversion

No incrementar el campo de inodo i_version.

mand

Permitir bloqueos obligatorios en este sistema de archivos. Ver fcntl(2). Esta opción quedó obsoleta en Linux 5.15.

nomand

No permitir bloqueos obligatorios en este sistema de archivos.

_netdev

El sistema de archivos reside en un dispositivo que requiere acceso a la red (se utiliza para evitar que el sistema intente montar estos sistemas de archivos hasta que la red se haya habilitado en el sistema).

nofail

No informar errores para este dispositivo si no existe.

relatime

Actualizar los tiempos de acceso a los inodos en relación con el tiempo de modificación o cambio. El tiempo de acceso solo se actualiza si el tiempo de acceso anterior fue anterior o igual al tiempo de modificación o cambio actual. (Similar a noatime, pero no interrumpe a mutt(1) u otras aplicaciones que necesitan saber si un archivo se ha leído desde la última vez que se modificó).

Desde Linux 2.6.30, el kernel utiliza por defecto el comportamiento proporcionado por esta opción (a menos que se haya especificado noatime), y la opción strictatime es necesaria para obtener la semántica tradicional. Además, desde Linux 2.6.30, el tiempo de último acceso del archivo siempre se actualiza si tiene más de 1 día de antigüedad.

norelatime

No usar la función relatime. Consulte también la opción de montaje strictatime.

strictatime

Permite solicitar explícitamente actualizaciones completas de atime. Esto permite que el kernel utilice por defecto relatime o noatime, pero aún así permite que el espacio de usuario lo anule. Para más detalles sobre las opciones de montaje predeterminadas del sistema, consulte /proc/mounts.

nostrictatime

Utilizar el comportamiento predeterminado del kernel para las actualizaciones del tiempo de acceso a los inodos.

lazytime

Actualizar solo los tiempos (atime, mtime, ctime) en la versión en memoria del inodo del archivo.

Esta opción de montaje reduce significativamente las escrituras en la tabla de inodos para cargas de trabajo que realizan escrituras aleatorias frecuentes en archivos preasignados.

Las marcas de tiempo en disco se actualizan solo cuando:

•el inodo necesita ser actualizado por algún cambio no relacionado con las marcas de tiempo del archivo
•la aplicación utiliza fsync(2), syncfs(2) o sync(2)
•un inodo no eliminado se expulsa de la memoria
•han pasado más de 24 horas desde que el inodo se escribió en el disco.

nolazytime

No usar la función lazytime.

suid

Respetar los bits set-user-ID y set-group-ID o las capacidades de archivo al ejecutar programas desde este sistema de archivos.

nosuid

No respetar los bits set-user-ID y set-group-ID o las capacidades de archivo al ejecutar programas desde este sistema de archivos. Además, las transiciones de dominio de SELinux requieren el permiso nosuid_transition, que a su vez también necesita la capacidad de política nnp_nosuid_transition.

silent

Activar la bandera silenciosa.

loud

Desactivar la bandera silenciosa.

owner

Permitir que un usuario normal monte el sistema de archivos si ese usuario es el propietario del dispositivo. Esta opción implica las opciones nosuid y nodev (a menos que se anulen mediante opciones posteriores, como en la línea de opciones owner,dev,suid).

remount

Intentar remontar un sistema de archivos ya montado. Esto se usa comúnmente para cambiar las banderas de montaje de un sistema de archivos, especialmente para hacer que un sistema de archivos de solo lectura sea escribible. No cambia el dispositivo ni el punto de montaje.

La operación de remontaje junto con el flag bind tiene una semántica especial. Ver arriba, la subsección Operación de montaje bind.

El comportamiento predeterminado del kernel para las banderas de montaje VFS (nodev, nosuid, noexec, ro) es restablecer todas las banderas no especificadas en el remontaje. Por eso mount(8) intenta mantener la configuración actual según fstab o /proc/self/mountinfo. Este comportamiento predeterminado se puede cambiar mediante --options-mode. El cambio recursivo de las banderas de montaje (admitido desde v2.39 en sistemas con la llamada al sistema mount_setattr(2)), por ejemplo, mount -o remount,ro=recursive, no utiliza el comportamiento de "restablecer no especificado" y funciona como una operación simple de agregar/eliminar y las banderas no especificadas no se modifican.

La funcionalidad de remontaje sigue la forma estándar en que el comando mount funciona con las opciones de fstab. Esto significa que mount no lee fstab (o mtab) solo cuando se especifican tanto device como dir.

mount -o remount,rw /dev/foo /dir

Después de esta llamada, todas las opciones de montaje antiguas se reemplazan y se ignoran elementos arbitrarios de fstab (o mtab), excepto la opción loop= que es generada y mantenida internamente por el comando mount.

mount -o remount,rw /dir

Después de esta llamada, mount lee fstab y fusiona estas opciones con las opciones de la línea de comandos (-o). Si no se encuentra ningún punto de montaje en fstab, se utilizan las opciones de montaje predeterminadas de /proc/self/mountinfo.

mount permite el uso de --all para remontar todos los sistemas de archivos ya montados que coincidan con un filtro especificado (-O y -t). Por ejemplo:

mount --all -o remount,ro -t vfat

remonta todos los sistemas de archivos vfat ya montados en modo de solo lectura. Cada uno de los sistemas de archivos se remonta mediante la semántica de mount -o remount,ro /dir. Esto significa que el comando mount lee fstab o mtab y fusiona estas opciones con las opciones de la línea de comandos.

ro[=(recursive|vfs|fs)]

Montar el sistema de archivos como solo lectura. El argumento opcional es una característica experimental admitida solo por la API de montaje del kernel basada en descriptores de archivo y se ignora silenciosamente para la antigua llamada al sistema mount(2).

GENERAL OPTIONS

The recursive argument forces the VFS attribute to be applied recursively.

The vfs and fs arguments specify the layer where the read-only flag should be applied. The fs specifies the filesystem superblock (unique filesystem instance in the kernel), and vfs specifies the mount node. If no attribute is specified, then both layers are set to read-only.

For more details, please refer to the Read-only Setting Notes section.

rw[=(recursive|vfs|fs)]

Monta el sistema de archivos en modo lectura-escritura.

sync

Todas las operaciones de E/S al sistema de archivos deben realizarse de forma síncrona. En el caso de medios con un número limitado de ciclos de escritura (por ejemplo, algunas unidades flash), sync puede acortar su vida útil.

user

Permite que un usuario normal monte el sistema de archivos. El nombre del usuario que monta se escribe en el archivo mtab (o en el archivo privado libmount en /run/mount en sistemas sin un mtab regular) para que ese mismo usuario pueda desmontar el sistema de archivos nuevamente. Esta opción implica las opciones noexec, nosuid y nodev (a menos que se anulen por opciones posteriores, como en la línea de opciones user,exec,dev,suid).

nouser

Prohíbe que un usuario normal monte el sistema de archivos. Esta es la opción predeterminada; no implica ninguna otra opción.

users

Permite que cualquier usuario monte y desmonte el sistema de archivos, incluso cuando otro usuario normal lo montó. Esta opción implica las opciones noexec, nosuid y nodev (a menos que se anulen por opciones posteriores, como en la línea de opciones users,exec,dev,suid).

X-*

Todas las opciones que comienzan con "X-" se interpretan como comentarios o como opciones específicas de aplicaciones de espacio de usuario. Estas opciones no se almacenan en el espacio de usuario (por ejemplo, en el archivo mtab), ni se envían a los asistentes mount.type ni a la llamada del sistema mount(2). El formato sugerido es X-nombre_app.opción.

x-*

Lo mismo que las opciones X-*, pero se almacenan permanentemente en el espacio de usuario. Esto significa que las opciones también están disponibles para umount(8) u otras operaciones. Tenga en cuenta que mantener las opciones de montaje en el espacio de usuario es complicado, ya que es necesario utilizar herramientas basadas en libmount y no hay garantía de que las opciones siempre estarán disponibles (por ejemplo, después de una operación de montaje de movimiento o en un espacio de nombres no compartido).

Tenga en cuenta que antes de util-linux v2.30, las opciones x-* no eran mantenidas por libmount y almacenadas en el espacio de usuario (la funcionalidad era la misma que para X-* ahora), pero debido al creciente número de casos de uso (en initrd, systemd, etc.) la funcionalidad se ha extendido para mantener las configuraciones existentes de fstab utilizables sin cambios.

X-mount.auto-fstypes=lista

Especifica los tipos de sistema de archivos permitidos o prohibidos para la detección automática de sistemas de archivos.

La lista es una lista separada por comas de los nombres de los sistemas de archivos. La detección automática de sistemas de archivos se activa con el tipo de sistema de archivos "auto" o cuando no se especifica el tipo de sistema de archivos.

La lista sigue cómo mount evalúa los patrones de tipo (ver -t para más detalles). Solo se permiten los tipos de sistema de archivos especificados, o se prohíben todos los tipos especificados si la lista está precedida por "no".

Por ejemplo, X-mount.auto-fstypes="ext4,btrfs" acepta solo ext4 y btrfs, y X-mount.auto-fstypes="novfat,xfs" acepta todos los sistemas de archivos excepto vfat y xfs.

Tenga en cuenta que la coma se usa como separador entre las opciones de montaje, lo que significa que los valores de auto-fstypes deben estar debidamente entre comillas. No olvide que la shell elimina las comillas y, por lo tanto, se requieren comillas dobles. Por ejemplo:

mount -t auto -o’X-mount.auto-fstypes="noext2,ext3"' /dev/sdc1 /mnt/test

X-mount.mkdir[=modo]

Permite crear un directorio de destino (punto de montaje) si aún no existe. El argumento opcional modo especifica el modo de acceso al sistema de archivos utilizado para mkdir(2) en notación octal. El modo predeterminado es 0755. Esta funcionalidad solo es compatible para usuarios root o cuando mount se ejecuta sin permisos suid. La opción también es compatible como x-mount.mkdir, pero esta notación está obsoleta desde la v2.30. Consulte también la opción de línea de comandos --mkdir.

X-mount.nocanonicalize[=tipo]

Permite deshabilitar la canonicalización de las rutas de origen y destino del montaje. Por defecto, el comando mount resuelve todas las rutas a sus rutas absolutas sin enlaces simbólicos. Sin embargo, este comportamiento puede no ser deseado en ciertas situaciones, como al enlazar un montaje sobre un enlace simbólico, o un enlace simbólico sobre un directorio u otro enlace simbólico. El argumento opcional tipo puede ser "source" o "target" (punto de montaje). Si no se especifica ningún tipo, la canonicalización se deshabilita para ambos tipos. Esta opción de montaje no afecta la conversión de etiquetas de origen (por ejemplo, LABEL= o UUID=) ni el procesamiento de fstab.

La opción de línea de comandos --no-canonicalize anula esta opción de montaje y afecta a todas las conversiones de rutas y etiquetas en todas las situaciones, pero por compatibilidad con versiones anteriores, no modifica las banderas de las llamadas al sistema open_tree y no permite el caso de uso de montaje enlazado sobre un enlace simbólico.

Tenga en cuenta que mount(8) todavía sanitiza y canonicaliza las rutas de origen y destino especificadas en la línea de comandos por usuarios no root, independientemente de la configuración de X-mount.nocanonicalize.

X-mount.noloop

No crear ni montar un dispositivo de bucle, incluso si la fuente del montaje es un archivo regular.

X-mount.subdir=directorio

Permite montar un subdirectorio de un sistema de archivos en lugar del directorio raíz. Esto solo es efectivo cuando se adjunta una nueva instancia de un sistema de archivos al sistema. La opción se ignora silenciosamente para operaciones como remonta, montaje enlazado o movimiento.

Por ahora, esta característica se implementa mediante un montaje temporal de la raíz del directorio del sistema de archivos en un espacio de nombres no compartido y luego enlazando el subdirectorio al punto de montaje final y desmontando la raíz del sistema de archivos. El montaje del subdirectorio aparece de forma atómica para el resto del sistema, aunque se implementa mediante múltiples llamadas al sistema mount(2).

Tenga en cuenta que esta característica no funcionará en una sesión con un espacio de nombres de montaje privado no compartido (después de unshare --mount) en kernels antiguos o con mount(8) sin soporte para la API del kernel de montaje basada en descriptores de archivo. En este caso, necesita unshare --mount --propagation shared.

Esta característica es EXPERIMENTAL.

X-mount.owner=nombre_usuario|UID, X-mount.group=grupo|GID

Establece la propiedad del punto de montaje después de montar. Los nombres se resuelven en el espacio de nombres de montaje de destino, consulte -N.

X-mount.mode=modo

Establece el modo del punto de montaje después de montar.

X-mount.idmap=tipo_id:id_montaje:id_host:rango_id [tipo_id:id_montaje:id_host:rango_id], X-mount.idmap=archivo

Utilice esta opción para crear un montaje idmapped. Un montaje idmapped permite cambiar la propiedad de todos los archivos ubicados bajo un montaje de acuerdo con el mapeo de ID asociado con un espacio de nombres de usuario. El cambio de propiedad está ligado a la vida útil y localizado al montaje relevante. El mapeo de ID relevante se puede especificar de dos maneras:
•Un usuario puede especificar el mapeo de ID directamente.

El mapeo de ID debe especificarse usando la sintaxis tipo_id:id_montaje:id_host:rango_id. Especificar u como prefijo de tipo_id crea un mapeo UID, g crea un mapeo GID y omitir tipo_id o especificar b crea tanto un mapeo UID como GID. El parámetro id_montaje indica el ID inicial en el nuevo montaje. El parámetro id_host indica el ID inicial en el sistema de archivos. El parámetro rango_id indica cuántos IDs se van a mapear. Es posible especificar múltiples mapeos de ID.

Los mapeos de ID individuales deben separarse por espacios. Tenga en cuenta que en el archivo /etc/fstab, los espacios se interpretan como separadores entre campos. Para evitar esto, debe escaparlos usando \040. Por ejemplo, X-mount.idmap=0:0:1\040500:1000:1.

Por ejemplo, el mapeo de ID X-mount.idmap=u:1000:0:1 g:1001:1:2 5000:1000:2 crea un montaje idmapped donde el UID 0 se mapea al UID 1000, el GID 1 se mapea al GUID 1001, el GID 2 se mapea al GID 1002, el UID y GID 1000 se mapean a 5000, y el UID y GID 1001 se mapean a 5001 en el montaje.

Cuando un mapeo de ID se especifica directamente, se asignará un nuevo espacio de nombres de usuario con el mapeo de ID solicitado. El nuevo espacio de nombres de usuario se adjuntará al montaje.

•Un usuario puede especificar un archivo de espacio de nombres de usuario.

El espacio de nombres de usuario se adjuntará entonces al montaje y el mapeo de ID del espacio de nombres de usuario se convertirá en el mapeo de ID del montaje.

Por ejemplo, X-mount.idmap=/proc/PID/ns/user adjuntará el espacio de nombres de usuario del proceso PID al montaje.

nosymfollow

No seguir enlaces simbólicos al resolver rutas. Los enlaces simbólicos aún se pueden crear, y readlink(1), readlink(2), realpath(1) y realpath(3) siguen funcionando correctamente.

Opciones de montaje para devpts

El sistema de archivos devpts es un sistema de archivos pseudo, tradicionalmente montado en /dev/pts. Para adquirir una terminal pseudo, un proceso abre /dev/ptmx; el número de la terminal pseudo se pone a disposición del proceso y el esclavo de la terminal pseudo se puede acceder como /dev/pts/<número>.

Esta opción solo se implementa en versiones del kernel de Linux a partir de la 2.6.29. Además, esta opción solo es válida si CONFIG_DEVPTS_MULTIPLE_INSTANCES está habilitado en la configuración del kernel.

Specify FAT behavior on critical errors: panic, continue without doing anything, or remount the partition in read-only mode (default behavior).

Character set to use for converting between 8 bit characters and 16 bit Unicode characters. The default is iso8859-1. Long filenames are stored on disk in Unicode format.

Enable this only if you want to export the FAT filesystem over NFS.

stale_rw: This option maintains an index (cache) of directory inodes which is used by the nfs-related code to improve look-ups. Full file operations (read/write) over NFS are supported but with cache eviction at NFS server, this could result in spurious ESTALE errors.

This ensures that ESTALE will not be returned after a file is evicted from the inode cache. However, it means that operations such as rename, create and unlink could cause file handles that previously pointed at one file to point at a different file, potentially causing data corruption. ISO 9660 is a standard describing a filesystem structure to be used on CD-ROMs. (This filesystem type is also seen on some DVDs. See also the udf filesystem.)

Opciones de montaje para overlay

Desde Linux 3.18, el pseudo sistema de archivos overlay implementa un montaje de unión para otros sistemas de archivos.

Un sistema de archivos overlay combina dos sistemas de archivos: uno superior y uno inferior. Cuando un nombre existe en ambos sistemas de archivos, el objeto en el sistema de archivos superior es visible mientras que el objeto en el sistema de archivos inferior está oculto o, en el caso de directorios, se fusiona con el objeto superior.

El sistema de archivos inferior puede ser cualquier sistema de archivos compatible con Linux y no necesita ser escribible. El sistema de archivos inferior puede ser incluso otro overlayfs. El sistema de archivos superior normalmente será escribible y, si lo es, debe admitir la creación de atributos extendidos trusted.* y debe proporcionar un d_type válido en las respuestas de readdir, por lo que NFS no es adecuado.

Un overlay de solo lectura de dos sistemas de archivos de solo lectura puede usar cualquier tipo de sistema de archivos. Las opciones lowerdir y upperdir se combinan en un directorio fusionado utilizando:

mount -t overlay  overlay  \
  -olowerdir=/inferior,upperdir=/superior,workdir=/trabajo  /fusionado

lowerdir=directorio

Cualquier sistema de archivos, no necesita estar en un sistema de archivos escribible.

upperdir=directorio

El upperdir normalmente está en un sistema de archivos escribible.

workdir=directorio

El workdir debe ser un directorio vacío en el mismo sistema de archivos que upperdir.

userxattr

Usa el espacio de nombres xattr "user.overlay." en lugar de "trusted.overlay.". Esto es útil para montar overlayfs sin privilegios.

redirect_dir={on|off|follow|nofollow}

Si la característica redirect_dir está habilitada, entonces el directorio se copiará hacia arriba (pero no el contenido). Luego, el atributo extendido "{trusted|user}.overlay.redirect" se establece en la ruta de la ubicación original desde la raíz del overlay. Finalmente, el directorio se moverá a la nueva ubicación.

on

Las redirecciones están habilitadas.

off

Las redirecciones no se crean y solo se siguen si la característica "redirect_always_follow" está habilitada en la configuración del kernel/módulo.

follow

Las redirecciones no se crean, pero se siguen.

nofollow

Las redirecciones no se crean ni se siguen (equivalente a "redirect_dir=off" si la característica "redirect_always_follow" no está habilitada).

index={on|off}

Índice de inodos. Si esta característica está deshabilitada y un archivo con múltiples enlaces duros se copia hacia arriba, esto "romperá" el enlace. Los cambios no se propagarán a otros nombres que se refieran al mismo inodo.

uuid={on|off}

Se puede usar para reemplazar el UUID del sistema de archivos subyacente en los identificadores de archivo con nulo y, efectivamente, deshabilitar las comprobaciones de UUID. Esto puede ser útil en caso de que el disco subyacente se copie y se cambie el UUID de esa copia. Esto solo es aplicable si todos los directorios inferiores/superiores/de trabajo están en el mismo sistema de archivos, de lo contrario, volverá al comportamiento normal.

nfs_export={on|off}

Cuando los sistemas de archivos subyacentes admiten la exportación NFS y la característica "nfs_export" está habilitada, un sistema de archivos overlay puede ser exportado a NFS.

Con la característica "nfs_export", en la copia ascendente de cualquier objeto inferior, se crea una entrada de índice en el directorio de índice. El nombre de la entrada del índice es la representación hexadecimal del identificador de archivo de origen de la copia ascendente. Para un objeto que no es un directorio, la entrada del índice es un enlace duro al inodo superior. Para un objeto de directorio, la entrada del índice tiene un atributo extendido "{trusted|user}.overlay.upper" con un identificador de archivo codificado del inodo del directorio superior.

Al codificar un identificador de archivo desde un objeto del sistema de archivos overlay, se aplican las siguientes reglas:

•Para un objeto no superior, codifica un identificador de archivo inferior desde el inodo inferior
•Para un objeto indexado, codifica un identificador de archivo inferior desde el origen de la copia ascendente
•Para un objeto puramente superior y para un objeto superior existente no indexado, codifica un identificador de archivo superior desde el inodo superior

El identificador de archivo overlay codificado incluye

•Cabecera que incluye información del tipo de ruta (por ejemplo, inferior/superior)
•UUID del sistema de archivos subyacente
•Codificación del sistema de archivos subyacente del inodo subyacente

Este formato de codificación es idéntico al formato de codificación de los identificadores de archivo que se almacenan en el atributo extendido "{trusted|user}.overlay.origin". Al decodificar un identificador de archivo overlay, se siguen los siguientes pasos

•Encuentra la capa subyacente por UUID e información del tipo de ruta.
•Decodifica el identificador de archivo del sistema de archivos subyacente a dentry subyacente.
•Para un identificador de archivo inferior, busca el identificador en el directorio de índice por nombre.
•Si se encuentra un archivo blanco (whiteout) en el índice, devuelve ESTALE. Esto representa un objeto overlay que fue eliminado después de que se codificara su identificador de archivo.
•Para un no-directorio, instancia un dentry overlay desconectado desde el dentry subyacente decodificado, el tipo de ruta y el inodo del índice, si se encuentra.
•Para un directorio, usa el dentry subyacente conectado y decodificado, el tipo de ruta y el índice, para buscar un dentry overlay conectado.

La decodificación de un identificador de archivo no-directorio puede devolver un dentry desconectado. La copia ascendente de ese dentry desconectado creará una entrada de índice superior sin alias superior.

Cuando el sistema de archivos overlay tiene múltiples capas inferiores, un directorio de capa intermedia puede tener una "redirección" a un directorio inferior. Debido a que las "redirecciones" de la capa intermedia no están indexadas, un identificador de archivo inferior que se codificó desde el directorio de origen de la "redirección" no se puede usar para encontrar el directorio de capa intermedia o superior. De manera similar, un identificador de archivo inferior que se codificó desde un descendiente del directorio de origen de la "redirección" no se puede usar para reconstruir una ruta overlay conectada. Para mitigar los casos de directorios que no se pueden decodificar desde un identificador de archivo inferior, estos directorios se copian hacia arriba en la codificación y se codifican como un identificador de archivo superior. En un sistema de archivos overlay sin capa superior, esta mitigación no se puede usar. La exportación NFS en esta configuración requiere desactivar el seguimiento de redirección (por ejemplo, "redirect_dir=nofollow").

El sistema de archivos overlay no admite identificadores de archivo conectables que no sean directorios, por lo que la exportación con la configuración de exportación subtree_check de exportfs causará fallas al buscar archivos a través de NFS.

Cuando la característica de exportación NFS está habilitada, todas las entradas de índice de directorios se verifican en el momento del montaje para comprobar que los identificadores de archivo superiores no estén obsoletos. Esta verificación puede causar una sobrecarga significativa en algunos casos.

Nota: las opciones de montaje index=off,nfs_export=on son conflictivas para un montaje de lectura/escritura y resultarán en un error.

xino={on|off|auto}

La característica "xino" compone un identificador de objeto único a partir del st_ino real del objeto y un índice de fsid subyacente. La característica "xino" utiliza los bits altos del número de inodo para fsid, ya que los sistemas de archivos subyacentes rara vez utilizan los bits altos del número de inodo. En caso de que el número de inodo subyacente desborde los bits altos de xino, el sistema de archivos overlay recurrirá al comportamiento sin xino para ese inodo.

Para una descripción detallada del efectoof this option please refer to https://docs.kernel.org/filesystems/overlayfs.html

metacopy={on|off}

Cuando la característica de copia de solo metadatos está habilitada, overlayfs solo copiará metadatos (en lugar de archivos completos), cuando se realice una operación específica de metadatos como chown/chmod. El archivo completo se copiará más tarde cuando el archivo se abra para una operación de escritura.

En otras palabras, esta es una operación de copia de datos retrasada y los datos se copian cuando hay una necesidad real de modificar los datos.

volatile

Los montajes volátiles no garantizan sobrevivir a un fallo. Se recomienda encarecidamente que los montajes volátiles solo se utilicen si los datos escritos en la superposición se pueden recrear sin un esfuerzo significativo.

La ventaja de montar con la opción "volatile" es que se omiten todas las formas de llamadas sync al sistema de archivos superior.

Para evitar dar una falsa sensación de seguridad, la semántica de syncfs (y fsync) de los montajes volátiles es ligeramente diferente a la del resto de VFS. Si ocurre algún error de escritura en el sistema de archivos de upperdir después de que se realice un montaje volátil, todas las funciones sync devolverán un error. Una vez que se alcanza esta condición, el sistema de archivos no se recuperará, y cada llamada sync posterior devolverá un error, incluso si upperdir no ha experimentado un nuevo error desde la última llamada sync.

Cuando overlay se monta con la opción "volatile", se crea el directorio "$workdir/work/incompat/volatile". Durante el próximo montaje, overlay verifica la existencia de este directorio y se niega a montar si está presente. Esto es un fuerte indicador de que el usuario debe desechar los directorios upper y work y crear uno nuevo. En casos muy limitados en los que el usuario sabe que el sistema no ha fallado y que el contenido de upperdir está intacto, se puede eliminar el directorio "volatile".

Opciones de montaje para reiserfs

Reiserfs es un sistema de archivos con registro por diario (journaling).

conv

Instruye al software reiserfs versión 3.6 para montar un sistema de archivos versión 3.5, utilizando el formato 3.6 para los objetos recién creados. Este sistema de archivos ya no será compatible con las herramientas de reiserfs 3.5.

hash={rupasov|tea|r5|detect}

Elige qué función hash utilizará reiserfs para encontrar archivos dentro de los directorios.

rupasov

Un hash inventado por Yury Yu. Rupasov. Es rápido y preserva la localidad, mapeando nombres de archivo lexicográficamente cercanos a valores hash cercanos. Esta opción no debe usarse, ya que provoca una alta probabilidad de colisiones hash.

tea

Una función Davis-Meyer implementada por Jeremy Fitzhardinge. Utiliza bits de permuta de hash en el nombre. Obtiene alta aleatoriedad y, por lo tanto, baja probabilidad de colisiones hash a costa de algo de CPU. Esto puede usarse si se experimentan errores EHASHCOLLISION con el hash r5.

r5

Una versión modificada del hash rupasov. Se utiliza por defecto y es la mejor opción a menos que el sistema de archivos tenga directorios enormes y patrones de nombres de archivo inusuales.

detect

Instruye a mount para detectar qué función hash está en uso examinando el sistema de archivos que se está montando, y para escribir esta información en el superbloque de reiserfs. Esto solo es útil en el primer montaje de un sistema de archivos de formato antiguo.

hashed_relocation

Ajusta el asignador de bloques. Esto puede proporcionar mejoras de rendimiento en algunas situaciones.

no_unhashed_relocation

Ajusta el asignador de bloques. Esto puede proporcionar mejoras de rendimiento en algunas situaciones.

noborder

Deshabilita el algoritmo de asignación de bordes inventado por Yury Yu. Rupasov. Esto puede proporcionar mejoras de rendimiento en algunas situaciones.

nolog

Deshabilita el registro por diario (journaling). Esto proporcionará ligeras mejoras de rendimiento en algunas situaciones a costa de perder la recuperación rápida de reiserfs ante fallos. Incluso con esta opción activada, reiserfs todavía realiza todas las operaciones de registro por diario, excepto las escrituras reales en su área de registro. La implementación de nolog está en progreso.

notail

Por defecto, reiserfs almacena archivos pequeños y 'colas de archivo' directamente en su árbol. Esto confunde a algunas utilidades como lilo(8). Esta opción se utiliza para deshabilitar la agrupación de archivos en el árbol.

replayonly

Reproduce las transacciones que están en el diario, pero sin montar realmente el sistema de archivos. Se utiliza principalmente por reiserfsck.

resize=number

Una opción de remontaje que permite la expansión en línea de particiones reiserfs. Instruye a reiserfs para asumir que el dispositivo tiene number bloques. Esta opción está diseñada para usarse con dispositivos que están bajo gestión de volúmenes lógicos (LVM). Existe una utilidad especial resizer que se puede obtener de <ftp://ftp.namesys.com/pub/reiserfsprogs>.

user_xattr

Habilita Atributos Extendidos de Usuario. Ver la página del manual de attr(1).

acl

Habilita Listas de Control de Acceso POSIX. Ver la página del manual de acl(5).

barrier=none / barrier=flush

Esto deshabilita / habilita el uso de barreras de escritura en el código del diario. barrier=none deshabilita, barrier=flush habilita (por defecto). Esto también requiere una pila de E/S que pueda soportar barreras, y si reiserfs obtiene un error en una escritura de barrera, volverá a deshabilitar las barreras con una advertencia. Las barreras de escritura imponen el orden correcto en el disco de los commits del diario, haciendo que las cachés de escritura de disco volátiles sean seguras de usar, a costa de cierto rendimiento. Si sus discos están respaldados por batería de una forma u otra, deshabilitar las barreras puede mejorar el rendimiento de forma segura.

SOPORTE DM-VERITY

The device-mapper verity target provides read-only transparent integrity checking of block devices using kernel crypto API. The mount command can open the dm-verity device and do the integrity verification before the device filesystem is mounted. Requires libcryptsetup with in libmount (optionally via dlopen(3)). If libcryptsetup supports extracting the root hash of an already mounted device, existing devices will be automatically reused in case of a match. Mount options for dm-verity:

verity.hashdevice=ruta

Path to the hash tree device associated with the source volume to pass to dm-verity.

verity.roothash=hex

Hex-encoded hash of the root of verity.hashdevice. Mutually exclusive with verity.roothashfile.

verity.roothashfile=ruta

Path to file containing the hex-encoded hash of the root of verity.hashdevice. Mutually exclusive with verity.roothash.

verity.hashoffset=desplazamiento

If the hash tree device is embedded in the source volume, offset (default: 0) is used by dm-verity to get to the tree.

verity.fecdevice=ruta

Path to the Forward Error Correction (FEC) device associated with the source volume to pass to dm-verity. Optional. Requires kernel built with CONFIG_DM_VERITY_FEC.

verity.fecoffset=desplazamiento

If the FEC device is embedded in the source volume, offset (default: 0) is used by dm-verity to get to the FEC area. Optional.

verity.fecroots=valor

Parity bytes for FEC (default: 2). Optional.

verity.roothashsig=ruta

Path to pkcs7(1ssl) signature of root hash hex string. Requires crypt_activate_by_signed_key() from cryptsetup and kernel built with CONFIG_DM_VERITY_VERIFY_ROOTHASH_SIG. For device reuse, signatures have to be either used by all mounts of a device or by none. Optional.

verity.oncorruption=ignorar|reiniciar|pánico

Instruct the kernel to ignore, reboot or panic when corruption is detected. By default the I/O operation simply fails. Requires Linux 4.1 or newer, and libcrypsetup 2.3.4 or newer. Optional.

Supported since util-linux v2.35.

For example commands:

mksquashfs /etc /tmp/etc.raw
veritysetup format /tmp/etc.raw /tmp/etc.verity --root-hash-file=/tmp/etc.roothash
openssl smime -sign -in /tmp/etc.roothash -nocerts -inkey private.key \
-signer private.crt -noattr -binary -outform der -out /tmp/etc.roothash.p7s
mount -o verity.hashdevice=/tmp/etc.verity,verity.roothashfile=/tmp/etc.roothash,\
verity.roothashsig=/tmp/etc.roothash.p7s /tmp/etc.raw /mnt

create squashfs image from /etc directory, verity hash device and mount verified filesystem image to /mnt. The kernel will verify that the root hash is signed by a key from the kernel keyring if roothashsig is used.

SYNOPSIS

DESCRIPTION

The mount command is used to mount file systems on specified mount points. The file systems to be mounted can be specified in several ways:

  • By device file (e.g. /dev/sda1).
  • By filesystem label (e.g. LABEL=mydisk).
  • By filesystem UUID (e.g. UUID=0d9215a8-3b79-413c-863f-14d5409433b6).
  • By a file containing a list of filesystem types to try (e.g. /etc/filesystems).
  • By a file containing device, mountpoint, filesystem type, options and dump/pass values (e.g. /etc/fstab).

The mount point must be an existing directory. If the file system is not specified, and the mount point is found in /etc/fstab, then the corresponding entry is used.

The mount command is often invoked by mountall or other scripts that read /etc/fstab.

By default, mount command tries to guess the filesystem type. If it fails, it tries the types listed in /etc/filesystems.

The -a option mounts all filesystems listed in /etc/fstab that have the auto keyword set in the options field. The filesystems are mounted according to the requirements of the dump utility (i.e., any filesystem stored in /etc/fstab will be mounted).

The -B, --bind option is used for bind mounts. It mounts a subtree to another location. See also mount_namespaces(7).

The --move option moves a subtree to another location. The source directory will be unmounted first, and then mounted at the target location.

The -U, --unmount option is used for unmounting. It takes the mountpoint as an argument.

The --swap option is used for enabling swap partitions and files listed in /etc/fstab.

Loop devices

A loop device is a pseudo-device which makes a regular file accessible as a block device. This allows you to mount a file containing a filesystem, for example, a disk image.

To use a loop device, you must specify the loop option:

mount -o loop /tmp/disk.img /mnt

If you want to specify a particular loop device, you can use `-o loop=device' option:

mount -o loop=/dev/loop3 /tmp/disk.img /mnt

will set up the loop device /dev/loop3 to correspond to the file /tmp/disk.img, and then mount this device on /mnt.

If no explicit loop device is mentioned (but just an option '-o loop' is given), then mount will try to find some unused loop device and use that, for example

mount /tmp/disk.img /mnt -o loop

The mount command automatically creates a loop device from a regular file if a filesystem type is not specified or the filesystem is known for libblkid, for example:

mount /tmp/disk.img /mnt

mount -t ext4 /tmp/disk.img /mnt

This type of mount knows about three options, namely loop, offset and sizelimit, that are really options to losetup(8). (These options can be used in addition to those specific to the filesystem type.)

Since Linux 2.6.25 auto-destruction of loop devices is supported, meaning that any loop device allocated by mount will be freed by umount independently of /etc/mtab.

You can also free a loop device by hand, using losetup -d or umount -d.

Since util-linux v2.29, mount re-uses the loop device rather than initializing a new device if the same backing file is already used for some loop device with the same offset and sizelimit. This is necessary to avoid a filesystem corruption.

EXTERNAL HELPERS

The syntax of external mount helpers is:

/sbin/mount.suffix spec dir [-sfnv] [-N namespace] [-o options] [-t type.subtype]

where the suffix is the filesystem type and the -sfnvoN options have the same meaning as the normal mount options. The -t option is used for filesystems with subtypes support (for example /sbin/mount.fuse -t fuse.sshfs).

The command mount does not pass the mount options unbindable, runbindable, private, rprivate, slave, rslave, shared, rshared, auto, noauto, comment, x-*, loop, offset and sizelimit to the mount.<suffix> helpers. All other options are used in a comma-separated list as an argument to the -o option.

The exit status value of the helper is returned as the exit status of mount(8). The value 126 is sed if the mount helper program is found, but the execl() failed.

BUGS

It is possible for a corrupted filesystem to cause a crash.

Some Linux filesystems don’t support -o sync and -o dirsync (the ext2, ext3, ext4, fat and vfat filesystems do support synchronous updates (a la BSD) when mounted with the sync option).

The -o remount may not be able to change mount parameters (all ext2fs-specific parameters, except sb, are changeable with a remount, for example, but you can’t change gid or umask for the fatfs).

It is possible that the files /etc/mtab and /proc/mounts don’t match on systems with a regular mtab file. The first file is based only on the mount command options, but the content of the second file also depends on the kernel and others settings (e.g. on a remote NFS server — in certain cases the mount command may report unreliable information about an NFS mount point and the /proc/mount file usually contains more reliable information.) This is another reason to replace the mtab file with a symlink to the /proc/mounts file.

Checking files on NFS filesystems referenced by file descriptors (i.e. the fcntl and ioctl families of functions) may lead to inconsistent results due to the lack of a consistency check in the kernel even if the noac mount option is used.

The loop option with the offset or sizelimit options used may fail when using older kernels if the mount command can’t confirm that the size of the block device has been configured as requested. This situation can be worked around by using the losetup(8) command manually before calling mount with the configured loop device.
