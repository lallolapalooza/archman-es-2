NOMBRE

fuse - configuración y opciones de montaje para sistemas de archivos FUSE

DESCRIPCIÓN

FUSE (Filesystem in Userspace) es una interfaz simple para que los programas en el espacio de usuario exporten un sistema de archivos virtual al kernel de Linux. FUSE también tiene como objetivo proporcionar un método seguro para que los usuarios no privilegiados creen y monten sus propias implementaciones de sistemas de archivos.

DEFINICIONES

FUSE
El sistema de archivos en el kernel que reenvía las solicitudes a un proceso en el espacio de usuario.
sistema de archivos
El proceso en el espacio de usuario que responde a las solicitudes recibidas del kernel.
libfuse
La biblioteca compartida que la mayoría de los sistemas de archivos (en el espacio de usuario) utilizan para comunicarse con FUSE (el sistema de archivos del kernel). libfuse también proporciona la utilidad fusermount3 (o fusermount si tienes una versión anterior de libfuse) para permitir que los usuarios no privilegiados monten sistemas de archivos.
propietario del sistema de archivos
El usuario que inicia el sistema de archivos e instruye al kernel para que lo asocie con un punto de montaje particular. Esto último lo realiza típicamente el propio sistema de archivos al iniciarse. Cuando se utiliza libfuse, esto se hace llamando a la utilidad fusermount3.
cliente
Cualquier proceso que interactúe con el punto de montaje.

CONFIGURACIÓN

Algunas opciones relacionadas con la política de montaje se pueden establecer en el archivo /etc/fuse.conf. Actualmente, estas opciones son:

mount_max = NNN
Establece el número máximo de montajes FUSE permitidos para usuarios no root. El valor predeterminado es 1000.
user_allow_other
Permite a los usuarios no root especificar las opciones de montaje allow_other o allow_root (ver más abajo).
Estos límites son aplicados por la utilidad auxiliar fusermount3, por lo que pueden ser evitados por sistemas de archivos que se ejecutan como root.

OPCIONES

La mayoría de las opciones de montaje genéricas descritas en mount son compatibles (ro, rw, suid, nosuid, dev, nodev, exec, noexec, atime, noatime, sync, async, dirsync). Los sistemas de archivos se montan con nodev,nosuid por defecto, lo que solo puede ser anulado por un usuario privilegiado.

Opciones de montaje generales:

Estas son opciones de montaje específicas de FUSE que se pueden especificar para todos los sistemas de archivos:

default_permissions
Esta opción instruye al kernel para que realice su propia verificación de permisos en lugar de delegar toda la verificación de permisos al sistema de archivos. La verificación por parte del kernel se realiza además de cualquier verificación de permisos realizada por el sistema de archivos, y ambas deben tener éxito para que una operación sea permitida. El kernel realiza una verificación de permisos UNIX estándar (basada en bits de modo y propiedad de la entrada del directorio, y uid/gid del cliente).

Esta opción de montaje se activa implícitamente si el sistema de archivos habilita el soporte de ACL durante la negociación inicial de características al abrir el descriptor de archivo del dispositivo. En este caso, el kernel realiza tanto la verificación de permisos ACL como la verificación de permisos UNIX estándar.

Los sistemas de archivos que no implementan ninguna verificación de permisos generalmente deberían añadir esta opción internamente.

allow_other
Esta opción anula la medida de seguridad que restringe el acceso a los archivos al propietario del sistema de archivos, de modo que todos los usuarios (incluido root) puedan acceder a los archivos.
rootmode=M
Especifica el modo de archivo de la raíz del sistema de archivos (en representación octal).
blkdev
Monta un sistema de archivos respaldado por un dispositivo de bloques. Esta es una opción privilegiada. El dispositivo debe especificarse con la opción fsname=NAME.
blksize=N
Establece el tamaño del bloque para el sistema de archivos. Esta opción solo es válida para montajes de tipo 'fuseblk'. El valor predeterminado es 512.

En la mayoría de los casos, esta opción no debe ser especificada por el propietario del sistema de archivos, sino establecida internamente por el sistema de archivos.

max_read=N
Con esta opción se puede establecer el tamaño máximo de las operaciones de lectura. El valor predeterminado es infinito, pero típicamente el kernel impone su propio límite además de este. Un valor de cero corresponde a ningún límite.

Esta opción no debe ser especificada por el propietario del sistema de archivos. El valor correcto (u óptimo) depende de la implementación del sistema de archivos y, por lo tanto, debe ser establecido internamente por el sistema de archivos.

Esta opción de montaje está obsoleta en favor de la negociación directa a través del descriptor de archivo del dispositivo (como se hace, por ejemplo, para el tamaño máximo de las operaciones de escritura). Por el momento, los sistemas de archivos que usan libfuse y que desean limitar el tamaño de lectura deben, por lo tanto, usar esta opción de montaje *y* establecer el mismo valor nuevamente en el manejador init().

fd=N
El descriptor de archivo a utilizar para la comunicación entre el sistema de archivos en el espacio de usuario y el kernel. El descriptor de archivo debe haberse obtenido abriendo el dispositivo FUSE (/dev/fuse).

Esta opción no debe ser especificada por el propietario del sistema de archivos. Es establecida por libfuse (o, si no se usa libfuse, debe ser establecida por el propio sistema de archivos).

user_id=N
group_id=N Especifica el uid/gid numérico del propietario del montaje.

Esta opción no debe ser especificada por el propietario del sistema de archivos. Es establecida por libfuse (o, si no se usa libfuse, debe ser establecida por el propio sistema de archivos).

fsname=NAME
Establece la fuente del sistema de archivos (primer campo en /etc/mtab). El valor predeterminado es el nombre del proceso del sistema de archivos.
subtype=TYPE
Establece el tipo de sistema de archivos (tercer campo en /etc/mtab). El valor predeterminado es el nombre del proceso del sistema de archivos. Si el kernel lo soporta, /etc/mtab y /proc/mounts mostrarán el tipo de sistema de archivos como fuse.TYPE.

Si el kernel no soporta subtipos, el campo de origen será TYPE#NAME, o si la opción fsname no se especifica, solo TYPE.

Opciones de montaje específicas de libfuse:

Las siguientes opciones no se pasan realmente al kernel, sino que son interpretadas por libfuse. Se pueden especificar para todos los sistemas de archivos que usan libfuse:

allow_root
Esta opción es similar a allow_other pero el acceso a los archivos se limita al propietario del sistema de archivos y a root. Esta opción y allow_other son mutuamente excluyentes.
auto_unmount
Esta opción habilita la liberación automática del punto de montaje si el sistema de archivos termina por cualquier motivo. Normalmente, el sistema de archivos es responsable de liberar el punto de montaje, lo que significa que el punto de montaje se vuelve inaccesible si el sistema de archivos termina sin desmontar primero.

Esta opción es peligrosa y solo debe usarse después de una cuidadosa consideración de los riesgos.

Desmontar automáticamente el sistema de archivos significa que si el sistema de archivos falla, el punto de montaje puede aparecer repentinamente vacío, lo que puede tener consecuencias no deseadas. Por ejemplo, un programa de copia de seguridad y duplicación en ejecución puede concluir que todos los datos del sistema de archivos han sido eliminados y proceder a propagar esta eliminación a la copia de seguridad / sistema remoto. Si en su lugar el punto de montaje se vuelve inaccesible (el comportamiento predeterminado), la mayoría de los programas se comportarán correctamente (informarán un error).

Esta característica también puede desmontar accidentalmente el sistema de archivos incorrecto debido a condiciones de carrera. Por ejemplo, si otro sistema de archivos se montó debajo del mismo punto de montaje, o si se monta un nuevo sistema de archivos después de que el proceso FUSE haya fallado, este podría ser desmontado accidentalmente.

En este momento, esta opción implica que el sistema de archivos también se montará con nodev y nosuid (incluso cuando lo monte root). Esta restricción puede ser eliminada en el futuro.

Opciones de montaje de alto nivel:

Las siguientes opciones no se pasan realmente al kernel sino que son interpretadas por libfuse. Solo pueden especificarse para sistemas de archivos que usan la API de alto nivel de libfuse:

kernel_cache
Esta opción deshabilita el vaciado de la caché de contenidos de archivos en cada open(2). Esto solo debería habilitarse en sistemas de archivos donde los datos de los archivos nunca se cambian externamente (no a través del sistema de archivos FUSE montado). Por lo tanto, no es adecuado para sistemas de archivos de red y otros sistemas de archivos "intermedios".

NOTA: si esta opción no se especifica (y tampoco direct_io), los datos todavía se almacenan en caché después del open(2), por lo que una llamada al sistema read(2) no siempre iniciará una operación de lectura.

auto_cache
Esta opción es una alternativa a kernel_cache. En lugar de mantener incondicionalmente los datos en caché, los datos en caché se invalida en open(2) si la hora de modificación o el tamaño del archivo han cambiado desde la última vez que se abrió.
umask=M fmask=M dmask=M
Sobrescribe los bits de permisos establecidos por el sistema de archivos en st_mode. Los bits de permisos resultantes son los que faltan en el valor de la máscara, que se proporciona en representación octal. fmask y dmask (respectivamente) se pueden usar para controlar los bits de permisos de archivos y directorios por separado. umask se ve sobrescrito por las opciones individuales fmask y dmask.
uid=N
Sobrescribe el campo st_uid establecido por el sistema de archivos (N es numérico).
gid=N
Sobrescribe el campo st_gid establecido por el sistema de archivos (N es numérico).
entry_timeout=T
El tiempo de espera en segundos para el cual se almacenarán en caché las búsquedas de nombres. El valor predeterminado es 1.0 segundo. Para todas las opciones de tiempo de espera, es posible proporcionar fracciones de segundo también (por ejemplo, entry_timeout=2.8)
negative_timeout=T
El tiempo de espera en segundos para el cual se almacenará en caché una búsqueda negativa. Esto significa que, si el archivo no existía (la búsqueda devolvió ENOENT), la búsqueda solo se volverá a realizar después del tiempo de espera, y se asumirá que el archivo/directorio no existe hasta entonces. El valor predeterminado es 0.0 segundos, lo que significa que el almacenamiento en caché de búsquedas negativas está deshabilitado.
attr_timeout=T
El tiempo de espera en segundos para el cual se almacenan en caché los atributos de archivos/directorios. El valor predeterminado es 1.0 segundo.
ac_attr_timeout=T
El tiempo de espera en segundos para el cual se almacenan en caché los atributos de archivos con el fin de comprobar si auto_cache debe vaciar los datos del archivo al abrir. El valor predeterminado es el valor de attr_timeout.
noforget
remember=T
Normalmente, libfuse asigna inodos a las rutas solo mientras el kernel los conoce. Con esta opción, los inodos se asignan durante al menos T segundos (o, en el caso de noforget, durante la vida útil del sistema de archivos). Esto requerirá más memoria, pero puede ser necesario al usar aplicaciones que hacen uso de números de inodo.
modules=M1[:M2...]
Añade módulos a la pila del sistema de archivos. Los módulos se insertan en el orden en que se especifican, con el sistema de archivos original en la parte inferior de la pila.

Opciones de mount.fuse3:

Estas opciones son interpretadas por mount.fuse3 y, por lo tanto, solo están disponibles al montar un sistema de archivos a través de mount.fuse3 (como al montar a través del comando genérico mount(1) o /etc/fstab). Las opciones soportadas son:

setuid=USER
Cambia a USER y a su grupo principal antes de lanzar el proceso del sistema de archivos FUSE. mount.fuse3 debe ejecutarse como root o con CAP_SETUID y CAP_SETGID para que esto funcione.
drop_privileges
Realiza la configuración del descriptor de archivo FUSE y monta el sistema de archivos antes de lanzar el proceso del sistema de archivos FUSE. mount.fuse3 requiere privilegios para hacerlo, es decir, debe ejecutarse como root o al menos con CAP_SYS_ADMIN y CAP_SETPCAP. Lanzará el proceso del sistema de archivos completamente sin privilegios, es decir, sin capabilities(7) y sin las banderas de prctl(2) configuradas de forma que no se puedan readquirir privilegios (por ejemplo, a través de binarios setuid o fscaps). Esto reduce el riesgo en caso de que el proceso del sistema de archivos FUSE sea comprometido por datos maliciosos del sistema de archivos.

MÓDULOS FUSE (APILAMIENTO)

Los módulos son soporte para el apilamiento de sistemas de archivos en la API de alto nivel. Los módulos de sistemas de archivos pueden estar integrados en libfuse o cargarse desde un objeto compartido.

iconv

Realiza la conversión de conjuntos de caracteres de nombres de archivo. Las opciones son:

from_code=CHARSET
Conjunto de caracteres a convertir (consulte iconv -l para ver una lista de valores posibles). El valor predeterminado es UTF-8.
to_code=CHARSET
Conjunto de caracteres a convertir. El valor predeterminado se determina por la configuración regional actual.

subdir

Antepone un directorio dado a cada ruta. Las opciones son:

subdir=DIR
Directorio que se antepondrá a todas las rutas. Esta opción es *obligatoria*.
rellinks
Transforma los enlaces simbólicos absolutos en relativos.
norellinks
No transforma los enlaces simbólicos absolutos en relativos. Este es el valor predeterminado.

SEGURIDAD

El programa fusermount3 se instala con set-user-gid a fuse. Esto se hace para permitir que los usuarios del grupo fuse monten sus propias implementaciones de sistemas de archivos. Sin embargo, debe haber algunas limitaciones para evitar que usuarios malintencionados hagan cosas malas. Actualmente, estas limitaciones son:

1.
El usuario solo puede montar en un punto de montaje para el cual tiene permiso de escritura.
2.
El punto de montaje no es un directorio pegajoso que no pertenezca al usuario (como suele ser /tmp).
3.
Ningún otro usuario (incluido root) puede acceder al contenido del sistema de archivos montado.

NOTA

Los sistemas de archivos FUSE se desmontan utilizando el comando fusermount3(1) (fusermount3 -u punto_de_montaje).

nombre

mount.fuse3 - monte un sistema de archivos FUSE

sintaxis

mount.fuse3 [opciones] dispositivo punto_montaje
mount.fuse3 -o opciones punto_montaje
mount.fuse3 -h

descripción

mount.fuse3 es un programa auxiliar para montar sistemas de archivos FUSE. Se puede usar para montar sistemas de archivos de forma manual o para llamar al programa de sistema de archivos FUSE especificado.

opciones

-h, --help
Mostrar mensaje de ayuda y salir.
-V, --version
Mostrar información de versión y salir.
-o opciones
Opciones de montaje separadas por comas. Las opciones comunes de FUSE incluyen:
allow_other
Permitir que otros usuarios accedan al sistema de archivos montado.
default_permissions
Permitir que el kernel verifique los permisos.
ro
Montar el sistema de archivos en modo de solo lectura.

ejemplos

Montar un sistema de archivos FUSE: 

    mount.fuse3 mi_sistema_de_archivos /punto/de/montaje

Montar un sistema de archivos FUSE con opciones: 

    mount.fuse3 -o allow_other,ro mi_sistema_de_archivos /punto/de/montaje
