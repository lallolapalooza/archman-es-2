NOMBRE

mono-config - Configuración del formato de archivo del tiempo de ejecución de Mono

DESCRIPCIÓN

El tiempo de ejecución de Mono cargará datos de configuración del prefijo de instalación /etc/mono/config, de ~/.mono/config o del archivo al que apunte la variable de entorno MONO_CONFIG.

Para cada ensamblado cargado, también se carga un archivo de configuración con el nombre: /ruta/al/ensamblado.exe.config, así como el archivo ~/.mono/ensamblados/ENSAMBLADO/ENSAMBLADO.EXT.config.

Este archivo controla el comportamiento del tiempo de ejecución.

El archivo contiene un formato similar a XML con varias secciones, todas ellas contenidas dentro de una sección (En realidad utiliza GMarkup para analizar el archivo).

Esta página describe las extensiones específicas de Unix y de Mono para el archivo de configuración; para obtener detalles completos, consulte la página web de Mono en http://www.mono-project.com/Config.

DIRECTIVA <dllmap>

Utiliza la directiva dllmap para mapear bibliotecas compartidas a las que se hace referencia mediante P/Invoke en sus ensamblados a una biblioteca compartida diferente.

Esto se utiliza típicamente para mapear bibliotecas de Windows a nombres de bibliotecas de Unix. El elemento dllmap toma dos atributos:

dll
Debe ser la misma cadena utilizada en el atributo DllImport, opcionalmente precedida por "i:" para indicar que la cadena debe coincidir sin distinguir entre mayúsculas y minúsculas.
target
Debe ser el nombre de la biblioteca donde se puede encontrar la función: este nombre debe ser adecuado para usar con las rutinas nativas de carga de bibliotecas compartidas de la plataforma (dlopen, etc.), por lo que es posible que también desee consultar sus páginas man.

DIRECTIVA <dllentry>

Esta directiva se puede utilizar para mapear un par específico de dll/función a una biblioteca diferente y también a un nombre de función diferente. Debe aparecer dentro de un elemento dllmap con solo el atributo dll especificado.

El elemento dllentry toma 3 atributos:

dll
Esta es la biblioteca de destino, donde se puede encontrar la función.
name
Este es el nombre de la función tal como aparece en los metadatos: es el nombre del método P/Invoke.
target
Este es el nombre de la función a buscar en lugar del nombre especificado en el método P/Invoke.

Mapeo basado en el sistema operativo y la CPU

Tanto los elementos dllmap como dllentry permiten los dos atributos siguientes que facilitan el uso de un único archivo de configuración y el soporte de múltiples sistemas operativos y arquitecturas con diferentes requisitos de mapeo:

os
Este es el nombre del sistema operativo para el que se aplicará el mapeo. Los valores permitidos son: linux, osx, solaris, freebsd, openbsd, netbsd, windows, aix, hpux.
cpu
Este es el nombre de la arquitectura para la que se aplicará el mapeo. Los valores permitidos son: x86, x86-64, sparc, ppc, s390, s390x, arm, mips, alpha, hppa, ia64.
wordsize
Este es el tamaño de los registros en la arquitectura de destino, puede ser 32 o 64.

El valor del atributo para ambos atributos puede ser una lista separada por comas de los valores permitidos. Además, el primer carácter puede ser un '!' para invertir el significado. Un valor de atributo de "!windows,osx", por ejemplo, significaría que la entrada se considera en todos los sistemas operativos, excepto en Windows y OS X. No se permiten espacios en ninguna parte del valor.

Tenga en cuenta que las entradas posteriores anularán las entradas definidas anteriormente en el archivo.

EJEMPLOS

El siguiente ejemplo mapea referencias a la biblioteca compartida `cygwin1.dll' a el archivo `libc.so.6'.

<configuration>
	<dllmap dll="i:cygwin1.dll" target="libc.so.6"/>
</configuration>

Se permite que el nombre de la biblioteca en el atributo DllImport esté en cualquier variante de mayúsculas y minúsculas, como en los siguientes ejemplos:

	[DllImport ("cygwin1.dll")]
	[DllImport ("Cygwin1.dll")]
	[DllImport ("cygwiN1.Dll")]

Esto mapea el siguiente método C#:

[DllImport ("libc")]
static extern void somefunction ();

a differentfunction en libdifferent.so, pero a la misma función en la biblioteca libanother.so cuando se ejecuta en los sistemas operativos Solaris y FreeBSD.

<configuration>
	<dllmap dll="libc">
		<dllentry dll="libdifferent.so" name="somefunction" target="differentfunction" />
		<dllentry os="solaris,freebsd" dll="libanother.so" name="somefunction" target="differentfunction" />
	</dllmap>
</configuration>
