NOMBRE

mosquitto_ctrl - una herramienta para inicializar/configurar una instancia del broker Mosquitto

SINOPSIS

mosquitto_ctrl [opciones-conexión | -o archivo-config] nombre-módulo comando-módulo [opciones-comando]

opciones-conexión: {[-h nombre-host] [--unix ruta-socket] [-p número-puerto] [-u nombre-usuario] [-P contraseña] | -L URL} [-A direccion-enlace] [-c] [-d] [-i id-cliente] [-q QoS-mensaje] [--quiet] [-V version-protocolo] [[{--cafile archivo | --capath directorio} [--cert archivo] [--key archivo] [--ciphers ciphers] [--tls-version version] [--tls-alpn protocolo] [--tls-engine engine] [--keyform {pem | engine}] [--tls-engine-kpass-sha1 kpass-sha1] [--insecure]] | [--psk clave-hex --psk-identity identidad [--ciphers ciphers] [--tls-use-os-certs] [--tls-version version]]] [--proxy url-socks]

mosquitto_ctrl [--help]

DESCRIPCIÓN

mosquitto_ctrl es una herramienta para ayudar a configurar una instancia del broker Mosquitto.

CONEXIONES CIFRADAS

mosquitto_ctrl soporta conexiones cifradas con TLS. Se recomienda encarecidamente utilizar una conexión cifrada para todo uso remoto de mosquitto_ctrl.

Para habilitar conexiones TLS al usar certificados x509, se debe proporcionar uno de los dos, --cafile o --capath, como opción.

Para habilitar conexiones TLS al usar TLS-PSK, debes usar las opciones --psk y --psk-identity.

MÓDULOS

Seguridad dinámica

Autenticación y control de acceso basado en roles con usuarios y grupos. Utiliza el nombre de módulo dynsec. Ver: mosquitto_ctrl_dynsec(1)

Módulos externos

mosquitto_ctrl tiene la capacidad de cargar módulos externos en forma de bibliotecas compartidas. Por ejemplo, usar el nombre de módulo example intentará cargar el módulo externo mosquitto_ctrl_example.so o mosquitto_ctrl_example.dll, dependiendo de la plataforma. Esto permite agregar nueva funcionalidad a Mosquitto combinando un plugin y un módulo mosquitto_ctrl, sin tener que recompilar ningún código fuente de Mosquitto.

OPCIONES DE CONEXIÓN

Las siguientes opciones se pueden proporcionar en la línea de comandos, pero también se pueden colocar en un archivo de configuración ubicado en $XDG_CONFIG_HOME/mosquitto_ctrl o $HOME/.config/mosquitto_ctrl.

El archivo de configuración se puede especificar manualmente con la opción -o archivo-config.

El archivo de configuración debe tener un par de -opción valor por línea. Los valores en el archivo de configuración se utilizarán como valores predeterminados y pueden ser anulados usando la línea de comandos. Las excepciones a esto son las opciones de tipo de mensaje, de las cuales solo se puede especificar una. Tenga en cuenta también que actualmente algunas opciones no se pueden negar, por ejemplo, -S. Las líneas del archivo de configuración que tienen un # como primer carácter se tratan como comentarios y no se procesan más.

-A

Enlaza la conexión saliente a una dirección IP/nombre de host local. Usa este argumento si necesitas restringir la comunicación de red a una interfaz particular.

--cafile

Define la ruta a un archivo que contiene certificados de CA codificados en PEM que son de confianza. Se utiliza para habilitar la comunicación SSL.

Ver también --capath

--capath

Define la ruta a un directorio que contiene certificados de CA codificados en PEM que son de confianza. Se utiliza para habilitar la comunicación SSL.

Para que --capath funcione correctamente, los archivos de certificado deben tener ".crt" como extensión de archivo y debes ejecutar "openssl rehash <ruta a capath>" cada vez que añadas/elimines un certificado.

Ver también --cafile

--cert

Define la ruta a un archivo que contiene un certificado codificado en PEM para este cliente, si el servidor lo requiere.

Ver también --key.

--ciphers

Una lista de cifrados TLS compatible con openssl para soportar en el cliente. Ver ciphers(1) para más información.

-d, --debug

Habilita mensajes de depuración.

-D, --property

Usa una propiedad MQTT v5 con esta publicación. Si usas esta opción, el cliente se configurará como un cliente MQTT v5. Esta opción tiene dos formas:

-D comando identificador valor

-D comando identificador nombre valor

comando es el identificador del comando/paquete MQTT y puede ser uno de CONNECT, PUBLISH, PUBREL, DISCONNECT, AUTH o WILL. Las propiedades disponibles para cada comando se enumeran en la sección Propiedades.

identificador es el nombre de la propiedad a agregar. Esto es como se describe en la especificación, pero con '-' como separador de palabras. Por ejemplo: payload-format-indicator. Más detalles están en la sección Propiedades.

valor es el valor de la propiedad a agregar, con un tipo de dato específico de la propiedad.

nombre solo se usa para la propiedad user-property como la primera de las dos cadenas en el par de cadenas. En ese caso, valor es la segunda de las cadenas del par.

--help

Muestra información de uso.

-h, --host

Especifica el host al que conectarse. Por defecto es localhost.

-i, --id

El id a usar para este cliente. Si no se proporciona, se generará un id de cliente dependiendo de la versión de MQTT que se esté utilizando. Para v3.1.1/v3.1, el cliente genera un id de cliente en el formato mosq-XXXXXXXXXXXXXXXXXX, donde las X se reemplazan con caracteres alfanuméricos aleatorios. Para v5.0, el cliente envía un id de cliente de longitud cero, y el servidor generará un id de cliente para el cliente.

Esta opción no se puede usar al mismo tiempo que el argumento --id-prefix.

--insecure

Al usar cifrado basado en certificados, esta opción deshabilita la verificación del nombre de host del servidor en el certificado del servidor. Esto puede ser útil al probar configuraciones iniciales del servidor, pero hace posible que un tercero malintencionado se haga pasar por su servidor a través de la suplantación de DNS, por ejemplo. Utilice esta opción solo en pruebas. Si necesita recurrir a usar esta opción en un entorno de producción, su configuración es defectuosa y no tiene sentido usar cifrado.

--key

Define la ruta a un archivo que contiene una clave privada codificada en PEM para este cliente, si el servidor la requiere.

Ver también --cert.

--keyform

Especifica el tipo de clave privada en uso al realizar conexiones TLS. Puede ser "pem" o "engine". Este parámetro es útil cuando se utiliza un módulo TPM y la clave privada se ha creado con él. Por defecto es "pem", lo que significa que se utilizan archivos de clave privada normales.

Ver también --tls-engine.

-L, --url

Especifica el usuario, contraseña, nombre de host, puerto y tema a la vez como una URL. La URL debe tener el formato: mqtt(s)://[username[:password]@]host[:port]/topic

Si el esquema es mqtt://, el puerto por defecto es 1883. Si el esquema es mqtts://, el puerto por defecto es 8883.

--nodelay

Deshabilita el algoritmo de Nagle para el socket. Esto significa que la latencia de los mensajes enviados se reduce, lo que es particularmente notable para mensajes pequeños y razonablemente infrecuentes. Usar esta opción puede resultar en el envío de más paquetes de los que normalmente serían necesarios.

-o archivo-config

Especifique un archivo de configuración que contenga las opciones de conexión.

-p, --port

Especifica el puerto al que conectarse. Por defecto es 1883.

-P, --password

La contraseña para la autenticación básica, si el servidor la requiere.

--proxy

Especifica una URL de proxy SOCKS, por ejemplo, socks5://usuario:contraseña@host:puerto.

-q, --mqtt-version

El protocolo MQTT a utilizar. Los valores válidos son 3 (para MQTT v3.1.1), 4 (para MQTT v3.1) y 5 (para MQTT v5.0). El valor por defecto es 5.

--quiet

Suprime la salida de estado normal. Los mensajes de error todavía se mostrarán.

--psk

Un secreto precompartido (PSK) en formato hexadecimal para usar con TLS-PSK.

--psk-identity

La identidad PSK para usar con TLS-PSK.

--tls-alpn

Establece los protocolos ALPN para la negociación TLS. Actualmente solo se soporta el protocolo MQTT.

--tls-engine

Especifica un motor de módulo de criptografía abierto para acceder a claves privadas, por ejemplo, a través de un módulo HSM.

--tls-engine-kpass-sha1

Si se usa un motor de módulo de criptografía, esta es la contraseña (codificada en SHA1) para acceder a la clave privada.

--tls-use-os-certs

Carga certificados de CA de la base de datos de certificados del sistema operativo en lugar de usar los archivos proporcionados por --cafile o --capath.

--tls-version

La versión mínima de TLS permitida. Los valores válidos son tlsv1.0, tlsv1.1, tlsv1.2, tlsv1.3.

-u, --username

El nombre de usuario para la autenticación básica, si el servidor lo requiere.

--unix

Especifica la ruta de un socket de dominio Unix al que conectarse. Si se utiliza esta opción, se ignorarán las opciones de host y puerto.

-V, --protocol-version

La versión del protocolo MQTT a utilizar. Los valores válidos son 3 (para MQTT v3.1.1), 4 (para MQTT v3.1) y 5 (para MQTT v5.0). El valor por defecto es 5.

EJEMPLOS

Inicializar un nuevo usuario y establecer una contraseña (requiere un broker con seguridad dinámica habilitada):

mosquitto_ctrl dynsec adduser johndoe --password secret

Crear un grupo y agregarle un usuario:

mosquitto_ctrl dynsec addgroup admins
mosquitto_ctrl dynsec addtogroup admins johndoe

Otorgar al grupo 'admins' acceso completo a un tema:

mosquitto_ctrl dynsec addaclgroup admins topic readwrite test/topic/#

Conectarse a un broker en remoto y obtener una lista de temas:

mosquitto_ctrl -h hostname.example.com -u fred -P password --dynsec --listtopics

Conectarse a un broker remoto utilizando un socket Unix y obtener una lista de suscriptores:

mosquitto_ctrl --unix /var/run/mosquitto/mosquitto.sock --dynsec --listsubscriptions

Establecer una política de cuota para un usuario:

mosquitto_ctrl dynsec adduserlimit johndoe max_inflight_messages 10
