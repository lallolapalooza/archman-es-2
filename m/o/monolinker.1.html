monolinker(1)

Paquete: mono

Licencias: GPL, LGPL2.1, MPL

CIL(Enlazador) CIL(Enlazador)

NOMBRE

Enlazador CIL de Mono

SINOPSIS

monolinker [-o directorio_salida][-l ensamblados_i18n][-c omitir | copiar | enlazar] -x descriptor | -a ensamblado | -i archivo_info ...

DESCRIPCION

monolinker es un Enlazador CIL. El enlazador es una herramienta que se puede usar para distribuir solo el conjunto mínimo posible de funciones que un conjunto de programas pueda requerir para ejecutarse, en lugar de las bibliotecas completas.

El enlazador analiza el código intermedio (CIL) producido por cada compilador que tiene como objetivo la plataforma Mono, como mcs, gmcs, vbnc, booc u otros. Recorrerá todo el código que se le proporciona y eliminará todos los métodos y clases no utilizados. Esto se hace utilizando una operación de marcado y barrido sobre todo el código que se referencia.

La salida generada por el monolinker puede ser procesada posteriormente por la herramienta mkbundle para generar ejecutables nativos autocontenidos y pequeños.

No confundir con el Enlazador de Ensamblados (al), que crea ensamblados a partir de manifiestos, módulos y archivos de recursos.

OPCIONES

-d directorio_busqueda
Especifica un directorio para que el enlazador busque ensamblados.
-o directorio_salida
Especifica el directorio de salida, por defecto es 'output'.

Si especifica el directorio `.', asegúrese de no sobrescribir ensamblados importantes suyos.

-b verdadero | falso
Especifica si se deben generar símbolos de depuración o no, por defecto es falso.
-g verdadero | falso
Especifica si se debe generar un nuevo guid para cada módulo enlazado o reutilizar el existente, por defecto es verdadero.
-l ensamblados_i18n
Especifica qué hacer con los ensamblados específicos de la región

Mono tiene algunos ensamblados que contienen todo lo específico de la región:

I18N.CJK.dll
I18N.MidEast.dll
I18N.Other.dll
I18N.Rare.dll
I18N.West.dll

Por defecto, todos se copiarán al directorio de salida, pero puede especificar cuáles desea usando este comando. La elección puede ser: ninguno, todos, cjk, mideast, other, rare o west. Puede combinar los valores con una coma.

-c accion
Especifica la acción a aplicar a los ensamblados centrales.

Los ensamblados centrales son los ensamblados que pertenecen a la biblioteca de clases base, como mscorlib.dll, System.dll o System.Windows.Forms.dll.

El enlazador admite tres operaciones en estos ensamblados, puede especificar una de las siguientes acciones:

omitir
Esto indica al enlazador que los omita y no haga nada con ellos.
copiar
Esto indica al enlazador que los copie al directorio de salida,
enlazar
Esto indica al enlazador que aplique el proceso de enlazado y reduzca su tamaño.
-p accion ensamblado
Especifica por ensamblado qué acción aplicar.
-x descriptor
Usa un descriptor XML como fuente para el enlazador.

Aquí hay un ejemplo que muestra todas las posibilidades de este formato:

<linker>
	<assembly fullname="Library">
		<type fullname="Foo" />
		<type fullname="Bar" preserve="nothing" required="false" />
		<type fullname="Baz" preserve="fields" required="false" />
		<type fullname="Gazonk">
			<method signature="System.Void .ctor(System.String)" />
			<field signature="System.String _blah" />
			<field name="someFieldName" />
		</type>
	</assembly>
</linker>

En este ejemplo, el enlazador enlazará los tipos Foo, Bar, Baz y Gazonk.

El atributo preserve asegura que todos los campos del tipo Baz siempre se enlazarán, sin importar si se usan o no, pero que ni los campos ni los métodos de Bar se enlazarán si no se usan. No especificar un atributo preserve implica que estamos preservando todo en el tipo especificado.

El atributo required especifica que si el tipo no se marca, durante la operación de marcado, no se enlazará.

El tipo Gazonk se enlazará, así como su constructor que toma una cadena como parámetro, y su campo _blah.

Puede tener múltiples nodos de ensamblado.

-a ensamblados
usa un ensamblado como fuente para el enlazador.

El enlazador recorrerá todos los métodos del ensamblado para generar solo lo necesario para que este ensamblado se ejecute.

-i archivo_info
usa un archivo .info xml como fuente para el enlazador.

Un archivo info es un archivo producido por la herramienta mono-api-info. El enlazador lo usará para generar un ensamblado que contenga solo lo que la API pública definida en el archivo info necesita.

-s [PasoAntes:]NombreCompletoPaso,EnsambladoPaso[:PasoDespues]

Puede pedirle al enlazador que ejecute pasos personalizados usando el interruptor -s. Este comando toma el formato estándar NombreCompletoTipo,Ensamblado para localizar el paso. Puede personalizar su posición en el pipeline añadiéndolo antes o después de un paso.

Ejemplo:

using System;
using Mono.Linker;
using Mono.Linker.Steps;
namespace Foo {
	public class FooStep : IStep {
		public void Process (LinkContext context)
		{
			foreach (IStep step in context.Pipeline.GetSteps ()) {
				Console.WriteLine (step.GetType ().Name);
			}
		}
	}
}

Si compila esto de forma personalizada contra monolinker en un ensamblado Foo.dll, puede usar el interruptor -s de la siguiente manera. Para añadir FooStep al final del pipeline:

monolinker -s Foo.FooStep,Foo -a program.exe

Este comando añadirá FooStep después de MarkStep:

monolinker -s MarkStep:Foo.FooStep,Foo -a program.exe

Este comando añadirá FooStep antes de MarkStep:

monolinker -s Foo.FooStep,Foo:MarkStep -a program.exe

Este comando añadirá FooStep antes de MarkStep

-m ParametroPersonalizado ValorParametro
Especifica un parámetro para un paso personalizado.
