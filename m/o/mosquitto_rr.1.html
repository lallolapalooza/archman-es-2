NOMBRE

mosquitto_rr - un cliente MQTT versión 5/3.1.1 para mensajería de solicitud/respuesta

SINOPSIS

mosquitto_rr -e topic-de-respuesta {[-h nombre-host] [--unix ruta-socket] [-p numero-puerto] [-u usuario] [-P contraseña] -t topic-mensaje... | -L URL [-t topic-mensaje...] } {-f archivo | -m mensaje | -n | -s} [-A direccion-enlace] [-c] [-d] [-D comando identificador valor] [-i id-cliente] [-I prefijo-id-cliente] [-k tiempo-mantenimiento-sesion] [-N] [--nodela y] [--pretty] [-q QoS-mensaje] [-R] [-S] [-v] [-V version-protocolo] [-W tiempo-espera-procesamiento-mensaje] [-x intervalo-caducidad-sesion] [--proxy url-socks] [--quiet] [--topic-will topic [--payload-will payload] [--qos-will qos] [--retain-will]] [[{--cafile archivo | --capath directorio} [--cert archivo] [--key archivo] [--ciphers ciphers] [--tls-version version] [--tls-alpn protocolo] [--tls-engine motor] [--keyform {pem | engine}] [--tls-engine-kpass-sha1 kpass-sha1] [--tls-use-os-certs] [--insecure]] | [--psk clave-hex --psk-identity identidad [--ciphers ciphers] [--tls-version version]]]

mosquitto_rr [--help]

DESCRIPCIÓN

mosquitto_rr es un cliente MQTT versión 5/3.1.1 que puede ser utilizado para publicar un mensaje de solicitud y esperar una respuesta. Al usar MQTT v5, que es el predeterminado, mosquitto_rr utilizará la funcionalidad de Solicitud-Respuesta.

Las opciones importantes son -t, -e, y una de -f, -m, -n, y -s.

Ejemplo: mosquitto_rr -t topic-solicitud -e topic-respuesta -m mensaje

CONEXIONES CIFRADAS

mosquitto_rr soporta conexiones cifradas con TLS. Se recomienda encarecidamente utilizar una conexión cifrada para cualquier cosa más allá de la configuración más básica.

Para habilitar conexiones TLS al usar certificados x509, se puede proporcionar una de las opciones --cafile o --capath.

Alternativamente, si se utiliza la opción -p 8883, se cargarán los certificados proporcionados por el sistema operativo y no se necesitarán ni --cafile ni --capath.

Para habilitar conexiones TLS al usar TLS-PSK, debes usar las opciones --psk y --psk-identity.

OPCIONES

Las siguientes opciones pueden especificarse en la línea de comandos, pero también pueden incluirse en un archivo de configuración ubicado en $XDG_CONFIG_HOME/mosquitto_rr o $HOME/.config/mosquitto_rr con un par de -opcion valor por línea. Los valores del archivo de configuración se utilizarán como valores predeterminados y pueden ser anulados usando la línea de comandos. Las excepciones a esto son -t, que si se especifica en el archivo de configuración no será anulado. Tenga en cuenta también que actualmente algunas opciones no se pueden negar, por ejemplo, -S. Las líneas del archivo de configuración que tienen un # como primer carácter se tratan como comentarios y no se procesan más.

-A

Enlaza la conexión saliente a una dirección IP/nombre de host local. Usa este argumento si necesitas restringir la comunicación de red a una interfaz particular.

-c, --disable-clean-session

Deshabilita la 'sesión limpia' / habilita el modo de cliente persistente. Cuando se usa este argumento, se le indicará al broker que no limpie las sesiones existentes para el mismo id de cliente cuando el cliente se conecte, y las sesiones nunca caducarán cuando el cliente se desconecte. Los clientes MQTT v5 pueden cambiar su intervalo de caducidad de sesión con el argumento -x.

Cuando una sesión se persiste en el broker, las suscripciones del cliente se mantendrán después de que se desconecte, junto con los mensajes QoS 1 y QoS 2 subsiguientes que lleguen. Cuando el cliente se reconecta y no limpia la sesión, recibirá todos los mensajes en cola.

Si usas esta opción, el id de cliente debe ser establecido manualmente con --id

--cafile

Define la ruta a un archivo que contiene certificados CA codificados en PEM que son de confianza. Se utiliza para habilitar la comunicación SSL.

Ver también --capath

--capath

Define la ruta a un directorio que contiene certificados CA codificados en PEM que son de confianza. Se utiliza para habilitar la comunicación SSL.

Para que --capath funcione correctamente, los archivos de certificado deben tener ".crt" como terminación y debes ejecutar "openssl rehash <ruta a capath>" cada vez que agregues/elimines un certificado.

Ver también --cafile

--cert

Define la ruta a un archivo que contiene un certificado codificado en PEM para este cliente, si es requerido por el servidor.

Ver también --key y la sección Conexiones Cifradas.

--ciphers

Una lista de cifrados TLS compatibles con openssl para soportar en el cliente. Ver ciphers(1) para más información.

-d, --debug

Habilita mensajes de depuración.

-D, --property

Usa una propiedad MQTT v5 con esta publicación. Si usas esta opción, el cliente se configurará como un cliente MQTT v5. Esta opción tiene dos formas:

-D comando identificador valor

-D comando identificador nombre valor

comando es el comando/identificador de paquete MQTT y puede ser uno de CONNECT, PUBACK, PUBREC, PUBCOMP, SUBSCRIBE, UNSUBSCRIBE, DISCONNECT, AUTH, o WILL. Las propiedades disponibles para cada comando se enumeran en la sección Propiedades.

identificador es el nombre de la propiedad a agregar. Esto es como se describe en la especificación, pero con '-' como separador de palabras. Por ejemplo: payload-format-indicator. Más detalles en la sección Propiedades.

valor es el valor de la propiedad a agregar, con un tipo de datos específico de la propiedad.

nombre solo se utiliza para la propiedad user-property como la primera de las dos cadenas en el par de cadenas. En ese caso, valor es la segunda de las cadenas del par.

-e

Topic de respuesta. El cliente se suscribirá a este topic para esperar una respuesta.

-f, --file

Envía el contenido de un archivo como mensaje de solicitud.

-F

Especifica el formato de impresión de salida. Esta opción te permite elegir qué información de cada mensaje se imprime en la pantalla. Ver la sección Formato de Salida a continuación para detalles completos.

Esta opción anula la opción -v, pero no anula la opción -N.

--help

Muestra la información de uso.

-h, --host

Especifica el host al que conectarse. Predeterminado: localhost.

-i, --id

El id a usar para este cliente. Si no se proporciona, se generará un id de cliente dependiendo de la versión de MQTT que se esté utilizando. Para v3.1.1/v3.1, el cliente genera un id de cliente en el formato mosq-XXXXXXXXXXXXXXXXXX, donde las X se reemplazan con caracteres alfanuméricos aleatorios. Para v5.0, el cliente envía un id de cliente de longitud cero, y el servidor generará un id de cliente para el cliente.

Esta opción no se puede usar al mismo tiempo que el argumento --id-prefix.

-I, --id-prefix

Proporciona un prefijo a partir del cual se construirá el id del cliente agregando el id del proceso del cliente. Esto es útil cuando el broker está utilizando la opción clientid_prefixes. No se puede usar al mismo tiempo que el argumento --id.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

--insecure

Al usar cifrado basado en certificados, esta opción desactiva la verificación del nombre de host del servidor en el certificado del servidor. Esto puede ser útil al probar configuraciones iniciales del servidor, pero permite que un tercero malintencionado suplante su servidor mediante suplantación de DNS, por ejemplo. Use esta opción solo en pruebas. Si necesita recurrir al uso de esta opción en un entorno de producción, su configuración es defectuosa y no tiene sentido usar el cifrado.

-k, --keepalive

El número de segundos entre el envío de comandos PING al intermediario con el fin de informarle que todavía estamos conectados y funcionando. Por defecto es 60 segundos.

--key

Define la ruta a un archivo que contiene una clave privada codificada en PEM para este cliente, si el servidor lo requiere.

Ver también --cert y la sección Conexiones cifradas.

--keyform

Especifica el tipo de clave privada en uso al realizar conexiones TLS. Esto puede ser "pem" o "engine". Este parámetro es útil cuando se utiliza un módulo TPM y la clave privada se ha creado con él. Por defecto es "pem", lo que significa que se utilizan archivos de clave privada normales.

Ver también --tls-engine.

-L, --url

Especifique usuario, contraseña, nombre de host, puerto y tema a la vez como una URL. La URL debe tener el formato: mqtt(s)://[usuario[:contraseña]@]host[:puerto]/tema

Si el esquema es mqtt://, el puerto por defecto es 1883. Si el esquema es mqtts://, el puerto por defecto es 8883.

-m, --message

Envía un único mensaje de solicitud desde la línea de comandos.

-N

No añadir un carácter de fin de línea al payload al imprimir. Esto permite la transmisión de datos de payload de múltiples mensajes directamente a otra aplicación sin modificar. Solo tiene sentido cuando no se usa -v.

-n, --null-message

Envía un mensaje de solicitud nulo (de longitud cero).

--nodelay

Desactiva el algoritmo de Nagle para el socket. Esto significa que la latencia de los mensajes enviados se reduce, lo que es particularmente notable para mensajes pequeños y razonablemente infrecuentes. El uso de esta opción puede dar lugar a que se envíen más paquetes de los que normalmente serían necesarios.

-p, --port

Conéctese al puerto especificado. Si no se proporciona, se utilizará el valor predeterminado de 1883 para MQTT sin cifrar o 8883 para MQTT sobre TLS.

-P, --pw

Proporciona una contraseña que se utilizará para la autenticación con el intermediario. El uso de este argumento sin especificar también un nombre de usuario es inválido cuando se utiliza MQTT v3.1 o v3.1.1. Ver también la opción --username.

--pretty

Al usar el formato de salida JSON %j o %J, el valor predeterminado es imprimir de forma no formateada. Especificar --pretty imprime los mensajes de una manera más bonita y legible para el ser humano.

--proxy

Especifique un proxy SOCKS5 a través del cual conectarse. Se admiten los tipos de autenticación "None" y "username". La socks-url debe tener el formato socks5h://[usuario[:contraseña]@]host[:puerto]. El prefijo del protocolo socks5h significa que los nombres de host son resueltos por el proxy. Los símbolos %25, %3A y %40 se decodifican de URL a %, : y @ respectivamente, si están presentes en el nombre de usuario o la contraseña.

Si no se proporciona nombre de usuario, no se intenta ninguna autenticación. Si no se proporciona el puerto, el valor predeterminado es 1080.

Puede haber más versiones de SOCKS disponibles en el futuro, dependiendo de la demanda, y utilizarán diferentes prefijos de protocolo como se describe en curl(1).

--psk

Proporciona la clave precompartida (PSK) hexadecimal (sin prefijo 0x) que coincide con la utilizada en el intermediario para utilizar el soporte de cifrado TLS-PSK. También se debe proporcionar --psk-identity para habilitar TLS-PSK.

--psk-identity

La identidad del cliente a utilizar con el soporte TLS-PSK. Esto puede usarse en lugar de un nombre de usuario si el intermediario está configurado para hacerlo.

-q, --qos

Especifique la calidad de servicio deseada para los mensajes entrantes, de 0, 1 y 2. Por defecto es 0. Consulte mqtt(7) para obtener más información sobre QoS.

La QoS es idéntica para todos los temas a los que se suscribe en una única instancia de mosquitto_rr.

--quiet

Si se proporciona este argumento, no se imprimirán errores en tiempo de ejecución. Esto excluye cualquier mensaje de error que se muestre en caso de entrada de usuario inválida (por ejemplo, usar --port sin un puerto).

-R

Si se proporciona este argumento, los mensajes que se reciben y que tienen el bit de retención establecido no se imprimirán. Los mensajes con retención establecida son "obsoletos", en el sentido de que no se sabe cuándo se publicaron originalmente. Al suscribirse a un tema comodín, puede haber un gran número de mensajes retenidos. Este argumento suprime su visualización.

-S

Utiliza búsquedas SRV para determinar a qué host conectarse. Realiza búsquedas en _mqtt._tcp.<host> cuando se usa junto con -h, de lo contrario, utiliza _mqtt._tcp.<dominio dns local>.

-s, --stdin-file

Envía un mensaje de solicitud leído desde stdin, enviando todo el contenido como un único mensaje.

-t, --topic

El tema MQTT al que se enviará el mensaje de solicitud.

--tls-alpn

Proporciona un protocolo a utilizar al conectarse a un intermediario que tiene varios protocolos disponibles en un solo puerto, por ejemplo, MQTT y WebSockets.

--tls-engine

Un ID de motor openssl válido. Estos se pueden enumerar con el comando openssl engine.

Ver también --keyform.

--tls-engine-kpass-sha1

SHA1 de la contraseña de la clave privada al usar un motor TLS. Algunos motores TLS, como el motor TPM, pueden requerir el uso de una contraseña para acceder. Esta opción permite pasar un hash SHA1 codificado en hexadecimal de la contraseña directamente al motor, en lugar de que el usuario introduzca la contraseña.

Ver también --tls-engine.

--tls-use-os-certs

Si se usa, esto cargará y confiará en los certificados CA proporcionados por el sistema operativo. Esto se puede usar junto con --cafile y --capath y se puede usar solo para habilitar el modo TLS. Esto se establecerá por defecto si se usa -L mqtts://..., o si el puerto es 8883 y no se utilizan otras opciones de certificado.

--tls-version

Elige qué versión del protocolo TLS se utilizará al comunicarse con el intermediario. Las opciones válidas son tlsv1.3, tlsv1.2 y tlsv1.1. El valor predeterminado es tlsv1.2. Debe coincidir con la versión del protocolo utilizada por el intermediario.

-u, --username

Proporciona un nombre de usuario que se utilizará para la autenticación con el intermediario. Ver también el argumento --pw.

--unix

Conéctese a un intermediario a través de un socket de dominio de Unix local en lugar de un socket TCP. Esto reemplaza a -h y -L. Por ejemplo: mosquitto_pub --unix /tmp/mosquitto.sock ...

Consulte la opción socket_domain en mosquitto.conf(5) para configurar Mosquitto para que escuche en un socket de Unix.

-v, --verbose

Imprime los mensajes recibidos de forma detallada. Con este argumento, los mensajes se imprimirán como "tema payload". Cuando este argumento no se proporciona, los mensajes se imprimen como "payload".

-V, --protocol-version

Especifique qué versión del protocolo MQTT se utilizará al conectarse al intermediario remoto. Puede ser 5, 311, 31, o las versiones más detalladas mqttv5, mqttv311, o mqttv31. Por defecto es 5.

-W

Proporciona un tiempo de espera como un número entero de segundos. mosquitto_sub dejará de procesar mensajes y se desconectará después de que transcurra este número de segundos. El tiempo de espera comienza justo después de que el cliente se haya conectado al intermediario.

--will-payload

Especifique un mensaje que será almacenado por el intermediario y enviado si este cliente se desconecta inesperadamente. Esto debe usarse junto con --will-topic.

--will-qos

La QoS a utilizar para el Will. Por defecto es 0. Esto debe usarse junto con --will-topic.

--will-retain

Si se proporciona, si el cliente se desconecta inesperadamente, el mensaje enviado se tratará como un mensaje retenido. Esto debe usarse junto con --will-topic.

--will-topic

El tema en el que se enviará un Will, en caso de que el cliente se desconecte inesperadamente.

-x

Establece el intervalo de expiración de sesión en el paquete CONNECT. Se aplica solo a clientes MQTT v5. Establezca de 0 a 4294967294 para especificar que la sesión expirará en esa cantidad de segundos después de que el cliente se desconecte, o use -1, 4294967295 o ∞ para una sesión que no expira. Por defecto es -1 si también se da -c, o 0 si no se da -c.

Si la sesión se establece para que nunca expire, ya sea con -x o -c, entonces se debe proporcionar un id de cliente.

FORMATO DE SALIDA

Hay tres formas de formatear la salida de mosquitto_rr. En todos los casos, se añadirá un carácter de nueva línea por cada mensaje recibido, a menos que se pase el argumento -N a mosquitto_rr.

Solo payload es el formato de salida predeterminado e imprimirá el payload exactamente como se recibe.

El modo detallado se activa con -v e imprime el tema del mensaje y el payload, separados por un espacio.

La opción final es la salida formateada, que permite al usuario definir un formato de salida personalizado. El comportamiento se controla con la opción -F cadena-formato. La cadena de formato es una cadena de texto libre donde las secuencias interpretadas se reemplazan por diferentes parámetros. Las secuencias interpretadas disponibles se describen a continuación.

Se utilizan tres caracteres para iniciar una secuencia interpretada: %, @ y \. Las secuencias que comienzan con % son parámetros relacionados con el mensaje MQTT que se está imprimiendo, o son secuencias de ayuda para evitar tener que escribir cadenas de formato de fecha largas, por ejemplo. Las secuencias que comienzan con @ se pasan a la función strftime(3) (con el @ reemplazado por un % - tenga en cuenta que solo el carácter inmediatamente después del @ se pasa a st

(rftime). Esto permite la construcción de una amplia variedad de salidas basadas en tiempo. Las opciones de salida para strftime varían de una plataforma a otra, así que por favor comprueba lo que está disponible para tu plataforma. mosquitto_rr proporciona una extensión a strftime que es @N, la cual puede ser utilizada para obtener el número de nanosegundos pasados en el segundo actual. La resolución de esta opción varía dependiendo de la plataforma. La secuencia final de caracteres es \, la cual se utiliza para introducir algunos caracteres que de otro modo serían difíciles de introducir.

Parámetros relacionados con MQTT

•%% un literal %.
•%A la propiedad alias-de-tema de MQTT v5, si está presente.
•%C la propiedad tipo-de-contenido de MQTT v5, si está presente.
•%D la propiedad datos-de-correlación de MQTT v5, si está presente. Ten en cuenta que esta propiedad se especifica como datos binarios, por lo que puede producir caracteres no imprimibles.
•%E la propiedad intervalo-de-caducidad-del-mensaje de MQTT v5, si está presente.
•%F el indicador-de-formato-de-carga-útil de MQTT v5, si está presente.
•%l la longitud de la carga útil en bytes.
•%m el id del mensaje (solo relevante para mensajes con QoS>0).
•%P la propiedad propiedad-de-usuario de MQTT v5, si está presente. Se imprimirá en el formato clave:valor. Es posible que se adjunte cualquier número de propiedades de usuario a un mensaje, y que haya claves duplicadas.
•%p los bytes crudos de la carga útil (pueden producirse caracteres no imprimibles dependiendo de la carga útil).
•%q el QoS del mensaje.
•%R la propiedad tema-de-respuesta de MQTT v5, si está presente.
•%r el flag de retención para el mensaje.
•%S la propiedad identificador-de-suscripción de MQTT v5, si está presente.
•%t el tema del mensaje.
•%x la carga útil con cada byte como un número hexadecimal (en minúsculas).
•%X la carga útil con cada byte como un número hexadecimal (en mayúsculas).

Utilidades

•%I Fecha y hora en formato ISO-8601, p. ej., 2016-08-10T09:47:38+0100
•%j Salida JSON de los parámetros del mensaje y la marca de tiempo, con una carga útil entrecomillada y escapada. Por ejemplo: {"tst":"2020-05-06T22:12:00.000000+0100","topic":"greeting","qos":0,"retain":0,"payload":"hello world"}
•%J Salida JSON de los parámetros del mensaje y la marca de tiempo, con una carga útil sin entrecomillar y sin escapar; esto significa que la carga útil debe ser JSON válido. Por ejemplo: {"tst":"2020-05-06T22:12:00.000000+0100","topic":"foo","qos":0,"retain":0,"payload":{"temperature":27.0,"humidity":57}}.

Si la carga útil no es JSON válido, se imprimirá el mensaje de error "Error: La carga útil del mensaje no es JSON válido en el tema <tema>" en stderr.

•%I Fecha y hora en formato ISO-8601, p. ej., 2016-08-10T09:47:38+0100
•%U Marca de tiempo Unix con nanosegundos, p. ej., 1470818943.786368637

Parámetros relacionados con el tiempo

•@@ un literal @.
•@X pasa el carácter representado por X a la función strftime como %X. Las opciones soportadas dependen de la plataforma.
•@N el número de nanosegundos transcurridos en el segundo actual, con una resolución de tiempo variable dependiendo de la plataforma.

Caracteres de escape

•\\ un literal \.
•\0 un carácter nulo. Puede usarse para separar diferentes parámetros que puedan contener espacios (p. ej., tema, carga útil) para facilitar el procesamiento con herramientas como xargs(1).
•\a alerta/campana.
•\e la secuencia de escape, que puede usarse con códigos de color ANSI para proporcionar salida en color, por ejemplo.
•\n fin de línea.
•\r retorno de carro.
•\t tabulación horizontal.
•\v tabulación vertical.

WILLS

mosquitto_rr puede registrar un mensaje con el broker que se enviará si se desconecta inesperadamente. Ver mqtt(7) para más información.

El requisito mínimo para esto es usar --will-topic para especificar en qué tema se enviará el will. Esto resultará en un mensaje sin retención, de longitud cero y con QoS 0.

Use los argumentos --will-retain, --will-payload y --will-qos para modificar los otros parámetros del will.
