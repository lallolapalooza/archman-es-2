MODPROBE(8) modprobe MODPROBE(8)

NOMBRE

modprobe - Añadir y eliminar módulos del Kernel de Linux

SINOPSIS

modprobe [-v] [-V] [-C archivo-config] [-n] [-i] [-q] [-b] [nombre-módulo]
[parámetros-módulo...]

modprobe [-r] [-v] [-n] [-i] [nombre-módulo...]

modprobe [-c]

modprobe [--dump-modversions] [nombre-archivo]

DESCRIPCIÓN

modprobe añade o elimina inteligentemente un módulo del kernel de Linux: tenga en cuenta que, para mayor comodidad, no hay diferencia entre _ y - en los nombres de los módulos (se realiza una conversión automática de guiones bajos). modprobe busca en el directorio de módulos /usr/lib/`uname -r` todos los módulos y otros archivos, excepto los archivos de configuración opcionales (ver modprobe.d(5)). modprobe también utilizará las opciones del módulo especificadas en la línea de comandos del kernel en forma de <módulo>.<opción> y listas negras en forma de modprobe.blacklist=<módulo>.

Tenga en cuenta que, a diferencia de los kernels de Linux de la serie 2.4 (que no son compatibles con esta herramienta), esta versión de modprobe no hace nada con el módulo en sí: el trabajo de resolver símbolos y comprender parámetros se realiza dentro del kernel. Por lo tanto, el fallo del módulo a veces va acompañado de un mensaje del kernel: ver dmesg(8).

modprobe espera un archivo modules.dep.bin actualizado, tal como lo genera la utilidad depmod correspondiente que se distribuye con modprobe (ver depmod(8)). Este archivo lista los otros módulos que necesita cada módulo (si los hay), y modprobe lo utiliza para añadir o eliminar estas dependencias automáticamente.

Si se proporcionan argumentos después del nombre-módulo, se pasan al kernel (además de cualquier opción listada en el archivo de configuración).

Al cargar módulos, nombre-módulo también puede ser una ruta al módulo. Si la ruta es relativa, debe comenzar explícitamente con "./". Tenga en cuenta que esto puede fallar al usar una ruta a un módulo con dependencias que no coinciden con la base de datos depmod instalada.

OPCIONES

-a, --all

Inserta todos los nombres de módulos en la línea de comandos.

-b, --use-blacklist

Esta opción hace que modprobe aplique los comandos blacklist de los archivos de configuración (si los hay) también a los nombres de los módulos. Generalmente lo utiliza udev(7).

-C directorio, --config=directorio

Esta opción anula el directorio de configuración predeterminado. Ver modprobe.d(5).

Esta opción se pasa a través de los comandos install o remove a otros comandos modprobe en la variable de entorno MODPROBE_OPTIONS.

-c, --showconfig

Muestra la configuración efectiva del directorio de configuración y sale.

--dump-modversions

Imprime una lista de la información de versionado de módulos requerida por un módulo. Esta opción es comúnmente utilizada por las distribuciones para empaquetar un módulo del kernel de Linux utilizando las dependencias de versionado de módulos.

-d, --dirname

Directorio raíz para los módulos, por defecto /.

--first-time

Normalmente, modprobe tendrá éxito (y no hará nada) si se le pide que inserte un módulo que ya está presente o que elimine un módulo que no está presente. Esto es ideal para scripts sencillos; sin embargo, los scripts más complicados a menudo quieren saber si modprobe realmente hizo algo: esta opción hace que modprobe falle en caso de que realmente no hiciera nada.

--force-vermagic

Cada módulo contiene una pequeña cadena que contiene información importante, como las versiones del kernel y del compilador. Si un módulo no se carga y el kernel se queja de que la "magia de versión" no coincide, puede usar esta opción para eliminarla. Naturalmente, esta comprobación está ahí para protegerlo, por lo que usar esta opción es peligroso a menos que sepa lo que está haciendo.

Esto se aplica a cualquier módulo insertado: tanto al módulo (o alias) en la línea de comandos como a cualquier módulo del que dependa.

--force-modversion

Cuando los módulos se compilan con CONFIG_MODVERSIONS activado, se crea una sección que detalla las versiones de cada interfaz utilizada por (o proporcionada por) el módulo. Si un módulo no se carga y el kernel se queja de que el módulo discrepa sobre una versión de alguna interfaz, puede usar --force-modversion para eliminar la información de versión por completo. Naturalmente, esta comprobación está ahí para protegerlo, por lo que usar esta opción es peligroso a menos que sepa lo que está haciendo.

Esto se aplica a cualquier módulo insertado: tanto al módulo (o alias) en la línea de comandos como a cualquier módulo del que dependa.

-f, --force

Intenta eliminar cualquier información de versionado del módulo que de otro modo podría impedir su carga: esto es lo mismo que usar tanto --force-vermagic como --force-modversion. Naturalmente, estas comprobaciones están ahí para protegerlo, por lo que usar esta opción es peligroso a menos que sepa lo que está haciendo.

Esto se aplica a cualquier módulo insertado: tanto al módulo (o alias) en la línea de comandos como a cualquier módulo del que dependa.

-i, --ignore-install, --ignore-remove

Esta opción hace que modprobe ignore los comandos install y remove en el archivo de configuración (si los hay) para el módulo especificado en la línea de comandos (los módulos dependientes aún están sujetos a los comandos establecidos para ellos en el archivo de configuración). Actualmente, se ignorarán tanto los comandos install como remove cuando se utilice esta opción, independientemente de si la solicitud se realizó más específicamente solo con uno u otro (y no ambos) de --ignore-install o --ignore-remove. Ver modprobe.d(5).

-n, --dry-run, --show

Esta opción hace todo menos insertar o eliminar realmente los módulos (o ejecutar los comandos de instalación o eliminación). Combinada con -v, es útil para depurar problemas. Por razones históricas, tanto --dry-run como --show significan lo mismo y son intercambiables.

-q, --quiet

Con esta bandera, modprobe no imprimirá un mensaje de error si intenta eliminar o insertar un módulo que no puede encontrar (y que no es un alias o un comando install/remove). Sin embargo, seguirá devolviendo un estado de salida distinto de cero. El kernel utiliza esto para buscar de forma oportunista módulos que puedan existir utilizando request_module.

-R, --resolve-alias

Imprime todos los nombres de módulos que coinciden con un alias. Esto puede ser útil para depurar problemas de alias de módulos.

-r, --remove

Esta opción hace que modprobe elimine en lugar de insertar un módulo. Si los módulos de los que depende tampoco se utilizan, modprobe intentará eliminarlos también. A diferencia de la inserción, se puede especificar más de un módulo en la línea de comandos (no tiene sentido especificar parámetros del módulo al eliminar módulos).

Por lo general, no hay razón para eliminar módulos, pero algunos módulos defectuosos lo requieren. Es posible que el kernel de su distribución no se haya compilado para admitir la eliminación de módulos.

-w TIMEOUT_MSEC, --wait=TIMEOUT_MSEC

Esta opción hace que modprobe -r continúe intentando eliminar un módulo si falla debido a que el módulo está ocupado, es decir, su contador de referencias no es 0 en el momento en que se realiza la llamada. Modprobe intenta eliminar el módulo con un tiempo de espera incremental entre cada intento hasta el tiempo máximo de espera en milisegundos pasado en esta opción.

-S versión, --set-version=versión

Establece la versión del kernel, en lugar de usar uname(2) para decidir la versión del kernel (que determina dónde encontrar los módulos).

--show-depends

Lista las dependencias de un módulo (o alias), incluido el módulo mismo. Esto produce un conjunto (posiblemente vacío) de nombres de archivo de módulos,

ENTORNO

\n

La variable de entorno MODPROBE_OPTIONS también puede usarse para pasar\n argumentos de línea de comandos a modprobe. El formato se deja\n intencionadamente sin documentar, ya que se desaconseja su uso por parte\n de herramientas y scripts de terceros.\n

La variable de entorno se origina con la implementación de las\n reglas de instalación.\n
