NOMBRE

movescu - SCU de recuperación DICOM (C-MOVE)

SINOPSIS

movescu [opciones] peer port [dcmfile-in...]

DESCRIPCIÓN

La aplicación movescu implementa tanto un SCU para la Clase de Servicio de Consulta/Recuperación como un SCP para la Clase de Servicio de Almacenamiento. movescu soporta la funcionalidad de recuperación utilizando el mensaje C-MOVE. Envía claves de consulta a un SCP y espera respuestas. Aceptará asociaciones con el propósito de recibir imágenes enviadas como resultado de la solicitud C-MOVE. La aplicación se puede utilizar para probar SCPs de la Clase de Servicio de Consulta/Recuperación. La aplicación movescu puede iniciar la transferencia de imágenes a un tercero o recuperar imágenes para sí misma. Tenga en cuenta que el uso del término "mover" es un nombre inapropiado. La operación C-MOVE en realidad realiza una copia de imagen (no se eliminarán imágenes del SCP).

PARÁMETROS

peer        nombre de host del par DICOM
port        número de puerto tcp/ip del par
dcmfile-in  archivo(s) de consulta DICOM

NOTAS

Cada archivo suministrado en la línea de comandos se enviará al SCP como parte de una solicitud C-MOVE. El archivo de consulta debe ser un conjunto de datos DICOM válido que contenga la parte del conjunto de datos de un mensaje C-MOVE-RQ. El archivo de consulta podría, por ejemplo, crearse con la utilidad dump2dcm a partir de un script como el siguiente ejemplo:

# solicitar todas las imágenes para el paciente con ID=PAT001
(0008,0052) CS [PATIENT]     # QueryRetrieveLevel
(0010,0020) LO [PAT001]      # PatientID

I

Los atributos individuales de cada archivo enviado pueden ser modificados o complementados usando la opción -k (o --key). Por ejemplo, el comando:

movescu -k 0010,0020=PAT002 caesar 5678 patqry.dcm

causará, cuando se envíe al SCP caesar en el puerto TCP/IP 5678, que cualquier atributo PatientID en patqry.dcm tenga el valor 'PAT002'. Si dicho atributo está presente, será reemplazado; si está ausente, será insertado. La opción -k puede aparecer más de una vez. La parte del valor (después del '=') puede estar ausente, provocando que el atributo se envíe con longitud cero. No es posible reemplazar o insertar atributos dentro de secuencias usando la opción -k.

Si no se especifica ningún archivo en la línea de comandos, la consulta debe especificarse completamente con una o más opciones -k. Si se proporcionan múltiples archivos de consulta, movescu enviará múltiples solicitudes C-MOVE al SCP.

Para todos los usos de movescu, el SCP debe estar configurado para "conocer" el título AE al que se transmitirán las imágenes. Esto es necesario ya que la solicitud C-MOVE solo contiene el Título AE del destino y el SCP debe poder convertir este Título AE en la dirección TCP/IP y el número de puerto para poder enviar realmente las imágenes a través de una asociación separada.

La operación C-MOVE de la Clase de Servicio Query/Retrieve puede recuperar imágenes (cuando se utiliza la opción --port) o iniciar una copia de imágenes a un tercero.

Problemas Conocidos

movescu está diseñado para ser utilizado como una herramienta de prueba para desarrolladores de software DICOM. El archivo de claves de consulta debe crearse manualmente basándose en el contenido del SCP.

La aplicación movescu no intenta prevenir consultas incorrectas. En particular, las claves de consulta de una solicitud C-MOVE solo deben contener el atributo QueryRetrieveLevel y uno o más de los llamados "atributos de clave única" (PatientID, StudyInstanceUID, SeriesInstanceUID y SOPInstanceUID).

En caso de que el cliente de almacenamiento no finalice la conexión mientras movescu desempeña el papel de servidor de almacenamiento (es decir, se utiliza --port), sino que el cliente espere que movescu cierre la conexión de almacenamiento, movescu esperará infinitamente. En ese caso, movescu tampoco cerrará la asociación que se utilizó para emitir la solicitud C-MOVE al servidor C-MOVE.

NAME


movescu — DICOM C-MOVE SCU example application






SYNOPSIS


movescu [--help | --version] [--verbose | --debug] [--quiet] [--log-config file] [--access-control] [--config file] [--directory dir] [--output-format format] [--patient | --study | --series | --image] [--port port] [--timeout sec] [--proxy host:port] [--proxy-type type] [--proxy-auth user:pass] [--caller ae_title] [--move move_dest_ae_title] [--negotiation-request] [--max-associations count] [--max-pdu length] [--list-transfer-syntaxes] [--transfer-syntax uid] [--list-sop-classes] [--sop-class uid] [--list-image-types] [--image-type type] [--file-meta-info file] [--release-delay sec] [--abort-on-error] [--abort-delay sec] [--abort-reason code] [--peer-address host] [--peer-port port] [--peer-title ae_title] [--ae-title ae_title] [--config-name name] [--config-file file] [--check-rec] [dest_ae_title dest_host dest_port matching_keys...]






DESCRIPTION


The movescu application is an example implementation of a
    DICOM generic move SCU (Service Class User). It can be used to initiate a
    C-MOVE request to a DICOM server (SCP) and to receive the requested DICOM
    objects from the SCP. The C-MOVE operation is a general mechanism for
    retrieving DICOM objects from an SCP to a third-party AE title. The SCU
    initiates the C-MOVE request, but the SCP sends the requested objects to
    another AE title, which is also specified in the C-MOVE request.


The movescu application supports the DICOM Patient Root,
    Study Root, Series Root and Image Root query models. It can be used to query
    for patients, studies, series or images based on a set of matching keys.
    These keys are provided as DICOM tags in the command line. The requested
    images are then transferred to a specified destination AE title. The
    application acts as an SCP for the Storage Service Class (SCU for the
    Move Service Class).






PARAMETERS




dest_ae_title


The name of the destination DICOM application entity (AE). This AE title is
    used by the SCP to send the requested DICOM objects to.


dest_host


The hostname or IP address of the machine where the destination DICOM AE
    is running.


dest_port


The TCP port number on which the destination DICOM AE is listening.


matching_keys...


A list of DICOM tags and values that are used to match the DICOM objects
    to be retrieved. The tags can be specified either by their numeric tag
    value (e.g. 0010,0010) or by their DICOM keyword (e.g. PatientName).
    Values are specified as strings. If a tag appears multiple times, the last
    value is used. DICOM keywords are case-insensitive. For a list of supported
    keywords, please refer to the output of the movescu command with
    the --list-image-types option.








OPTIONS


In addition to the general command line options described in
    dcmtk(1), the following options are
    supported:




--access-control


Enable host-based access control. This option requires that the application
    is compiled with TCP wrapper support.


--abort-delay sec


Delay in seconds before sending an ABORT PDU. This option is only relevant
    if --abort-on-error is set.


--abort-on-error


Abort the C-MOVE operation if an error occurs during the transfer of
    DICOM objects. By default, the application continues processing if an
    error occurs.


--abort-reason code


DICOM reason code to be used when sending an ABORT PDU. The default value
    is 0x0000 (Code 0) which means "No Reason".


--ae-title ae_title


Set the title of the local DICOM application entity. Defaults to
    "MOVESCU".


--caller ae_title


Set the title of the calling DICOM application entity. This option is used
    to override the default AE title used for outgoing associations.


--check-rec


Check the received DICOM objects for consistency and validity according to
    the DICOM standard. This option is only effective if DICOM validation is
    enabled at compile time.


--config file


Read configuration settings from the specified file. The format of the
    configuration file is described in dcmtk(1).


--config-file file


Read configuration settings from the specified file. This option is
    equivalent to --config.


--config-name name


Set the name of the DICOM configuration profile. This option is used in
    conjunction with the --config-file option to specify which
    configuration profile within the file should be used.


--debug


Enable debug output. This option is equivalent to setting the logging level
    to DEBUG.


--directory dir


Store the received DICOM objects in the specified directory. If this option
    is not specified, the objects are stored in the current working
    directory.


--file-meta-info file


Specify a file containing File Meta Information (FMI) to be used for
    storing the received DICOM objects. If this option is not specified,
    default FMI is generated.


--help


Print a help message and exit.


--image-type type


Specify the image type to query for. This option can be used multiple times
    to query for multiple image types. For a list of supported image types,
    please refer to the output of the --list-image-types option.


--list-image-types


List all supported image types and exit.


--list-sop-classes


List all supported SOP classes and exit.


--list-transfer-syntaxes


List all supported transfer syntaxes and exit.


--log-config file


Use the specified file for logging configuration. For details, see
    dcmtk(1).


--max-associations count


Set the maximum number of parallel DICOM associations that can be
    established. Defaults to 1.


--max-pdu length


Set the maximum PDU length for outgoing DICOM associations. Defaults to
    16384 bytes.


--move move_dest_ae_title


Specify the AE title of the application entity that should receive the
    requested DICOM objects. This is the destination AE title for the C-MOVE
    operation.


--negotiation-request


Request extended negotiation for the DICOM association. This option is
    only supported if the application is compiled with support for extended
    negotiation.


--output-format format


Specify the output format for the DICOM objects. Supported formats are
    "dicom" (default) and "raw". The "raw" format writes the raw pixel data
    without any DICOM headers.


--patient


Use the Patient Root query model. This is the default query model.


--peer-address host


Set the hostname or IP address of the DICOM peer. This option is only used
    if the --peer-port and --peer-title options are also
    specified.


--peer-port port


Set the TCP port number of the DICOM peer. This option is only used if the
    --peer-address and --peer-title options are also
    specified.


--peer-title ae_title


Set the AE title of the DICOM peer. This option is only used if the
    --peer-address and --peer-port options are also
    specified.


--port port


Set the TCP port number on which the application should listen for incoming
    DICOM associations. Defaults to 104.


--proxy host:port


Use the specified proxy server for outgoing network connections. The format
    is host:port.


--proxy-auth user:pass


Set the username and password for authenticating with the proxy server.
    The format is user:pass.


--proxy-type type


Set the type of the proxy server. Supported types are "http" and "socks".
    Defaults to "http".


--quiet


Suppress all output except for fatal errors. This option is equivalent to
    setting the logging level to FATAL.


--release-delay sec


Delay in seconds before releasing the DICOM association after a successful
    transfer. Defaults to 0.


--series


Use the Series Root query model.


--sop-class uid


Specify the SOP class to query for. This option can be used multiple times
    to query for multiple SOP classes. For a list of supported SOP classes,
    please refer to the output of the --list-sop-classes option.


--study


Use the Study Root query model.


--timeout sec


Set the network timeout in seconds for blocking network operations.
    Defaults to 60 seconds.


--transfer-syntax uid


Specify the transfer syntax to be used for the DICOM association. This
    option can be used multiple times to propose multiple transfer syntaxes.
    If not specified, the default transfer syntaxes are used. For a list of
    supported transfer syntaxes, please refer to the output of the
    --list-transfer-syntaxes option.


--version


Print program version and exit.


--verbose


Enable verbose output. This option is equivalent to setting the logging
    level to INFO.

Access   Control


When compiled on Unix platforms with TCP wrapper support,
    host-based access control can be enabled with the --access-control
    command line option. In this case the access control rules defined in the
    system's host access control tables for movescu are enforced. The
    default locations of the host access control tables are
    /etc/hosts.allow and /etc/hosts.deny. Further details are
    described in hosts_access(5).







EXAMPLES


movescu --patient --port 9876 --move TEST_AE --call ARCHIVE caesar 104 q.dcm


sends the attributes contained in the DICOM file "q.dcm"
    as part of a C-MOVE request to application entity ARCHIVE on the host caesar
    at port 104 using the Patient Root query model. movescu itself uses
    the default AE title MOVESCU. The C-MOVE request will specify that images
    should be transferred to the destination AE title TEST_AE (via the
    --move option). How the SCP interprets this request depends on its
    configuration. movescu will listen on part 9876 for incoming
    associations in order to receive the requested images from the SCP.


Images can be copied to a third party by using a different
    destination AE title (e.g. --move ANOTHER_AE). Of course, the SCP
    must "know" this AE title and the destination must be acting as an
    SCP of the Storage Service Class (the storescp application can be
    used for this purpose).

    and warnings are written to the standard error stream. Using option
    --verbose also informational messages like processing details are
    reported. Option --debug can be used to get more details on the
    internal activity, e.g. for debugging purposes. Other logging levels can be
    selected using option --log-level. In --quiet mode only fatal
    errors are reported. In such very severe error events, the application will
    usually terminate. For more details on the different logging levels, see
    documentation of module "oflog".


In case the logging output should be written to file (optionally
    with logfile rotation), to syslog (Unix) or the event log (Windows) option
    --log-config can be used. This configuration file also allows for
    directing only certain messages to a particular output stream and for
    filtering certain messages based on the module or application where they are
    generated. An example configuration file is provided in
    <etcdir>/logger.cfg.






COMMAND   LINE


All command line tools use the following notation for parameters:
    square brackets enclose optional values (0-1), three trailing dots indicate
    that multiple values are allowed (1-n), a combination of both means 0 to n
    values.


Command line options are distinguished from parameters by a
    leading '+' or '-' sign, respectively. Usually, order and position of
    command line options are arbitrary (i.e. they can appear anywhere). However,
    if options are mutually exclusive the rightmost appearance is used. This
    behavior conforms to the standard evaluation rules of common Unix
  shells.


In addition, one or more command files can be specified using an
    '@' sign as a prefix to the filename (e.g. @command.txt). Such a
    command argument is replaced by the content of the corresponding text file
    (multiple whitespaces are treated as a single separator unless they appear
    between two quotation marks) prior to any further evaluation. Please note
    that a command file cannot contain another command file. This simple but
    effective approach allows one to summarize common combinations of
    options/parameters and avoids longish and confusing command lines (an
    example is provided in file <datadir>/dumppat.txt).

ENVIRONMENT


The movescu utility will attempt to load DICOM data
    dictionaries specified in the DCMDICTPATH environment variable. By
    default, i.e. if the DCMDICTPATH environment variable is not set, the
    file <datadir>/dicom.dic will be loaded unless the dictionary
    is built into the application (default for Windows).


The default behavior should be preferred and the
    DCMDICTPATH environment variable only used when alternative data
    dictionaries are required. The DCMDICTPATH environment variable has
    the same format as the Unix shell PATH variable in that a colon
    (":") separates entries. On Windows systems, a semicolon
    (";") is used as a separator. The data dictionary code will
    attempt to load each file specified in the DCMDICTPATH environment
    variable. It is an error if no data dictionary can be loaded.
