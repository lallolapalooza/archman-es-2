NOMBRE

mosquitto_sub - un cliente MQTT versión 5/3.1.1/3.1 para suscribirse a temas

SINOPSIS

mosquitto_sub {[-h hostname] [--unix ruta-socket] [-p numero-puerto] [-u usuario] [-P contraseña] -t tema-mensaje... | -L URL [-t tema-mensaje...] } [-A direccion-enlace] [-c] [-C contador-msg] [-d] [-D comando identificador valor] [-E] [-i id-cliente] [-I prefijo-id-cliente] [-k tiempo-mantenimiento] [-N] [--nodely] [--pretty] [-q QoS-mensaje] [--filtro-aleatorio probabilidad] [--eliminar-retenidos] [-R | --solo-retenidos] [--retenido-como-publicado] [-S] [-T filtrar-fuera...] [-U tema-desuscribir...] [-v] [-V version-protocolo] [-W tiempo-espera-procesamiento-mensaje] [-x intervalo-expiracion-sesion] [--proxy url-socks] [--silencioso] [--tema-will tema [--payload-will payload] [--qos-will qos] [--retain-will]] [[{--cafile archivo | --capath directorio} [--cert archivo] [--key archivo] [--tls-version version] [--tls-alpn protocolo] [--tls-engine motor] [--keyform {pem | motor}] [--tls-engine-kpass-sha1 kpass-sha1] [--tls-use-os-certs] [--inseguro]] | [--psk clave-hex --psk-identity identidad [--tls-version version]]]

mosquitto_sub [--ayuda]

DESCRIPCIÓN

mosquitto_sub es un cliente MQTT simple de la versión 5/3.1.1 que se suscribirá a temas e imprimirá los mensajes que reciba.

Además de suscribirse a temas, mosquitto_sub puede filtrar mensajes recibidos para que no se impriman (ver la opción -T) o desuscribirse de temas (ver la opción -U). Desuscribirse de temas es útil para clientes que se conectan con sesión limpia establecida en falso.

CONEXIONES CIFRADAS

mosquitto_sub soporta conexiones cifradas con TLS. Se recomienda encarecidamente que utilice una conexión cifrada para cualquier cosa más allá de la configuración más básica.

Para habilitar conexiones TLS al usar certificados x509, se puede proporcionar una de las opciones --cafile o --capath.

Alternativamente, si se utiliza la opción -p 8883, se cargarán los certificados proporcionados por el sistema operativo y no se necesitarán ni --cafile ni --capath.

Para habilitar conexiones TLS al usar TLS-PSK, debe usar las opciones --psk y --psk-identity.

OPCIONES

Las opciones a continuación pueden ser proporcionadas en la línea de comandos, pero también pueden colocarse en un archivo de configuración ubicado en $XDG_CONFIG_HOME/mosquitto_sub o $HOME/.config/mosquitto_sub con un par de -opción valor por línea. Los valores en el archivo de configuración se utilizarán como valores predeterminados y pueden ser anulados usando la línea de comandos. Las excepciones a esto son -t y -T, que si se proporcionan en el archivo de configuración no serán anulados. Tenga en cuenta también que actualmente algunas opciones no se pueden negar, por ejemplo, -S. Las líneas del archivo de configuración que tienen un # como primer carácter se tratan como comentarios y no se procesan más.

-A

Enlaza la conexión saliente a una dirección/nombre de host IP local. Utilice este argumento si necesita restringir la comunicación de red a una interfaz particular.

-c, --disable-clean-session

Deshabilita la 'sesión limpia' / habilita el modo de cliente persistente. Cuando se utiliza este argumento, se le indicará al broker que no elimine las sesiones existentes para el mismo id de cliente cuando el cliente se conecte, y las sesiones nunca expirarán cuando el cliente se desconecte. Los clientes MQTT v5 pueden cambiar su intervalo de expiración de sesión con el argumento -x.

Cuando una sesión se mantiene en el broker, las suscripciones para el cliente se mantendrán después de que se desconecte, junto con los mensajes posteriores de QoS 1 y QoS 2 que lleguen. Cuando el cliente se vuelve a conectar y no limpia la sesión, recibirá todos los mensajes en cola.

Si utiliza esta opción, el id del cliente debe establecerse manualmente con --id

--cafile

Define la ruta a un archivo que contiene certificados CA codificados en PEM que son de confianza. Se utiliza para habilitar la comunicación SSL.

Ver también --capath

--capath

Define la ruta a un directorio que contiene certificados CA codificados en PEM que son de confianza. Se utiliza para habilitar la comunicación SSL.

Para que --capath funcione correctamente, los archivos de certificado deben tener ".crt" como extensión de archivo y debe ejecutar "openssl rehash <ruta a capath>" cada vez que agregue/elimine un certificado.

Ver también --cafile

--cert

Define la ruta a un archivo que contiene un certificado codificado en PEM para este cliente, si es requerido por el servidor.

Ver también --key y la sección Conexiones Cifradas.

--ciphers

Una lista de cifrados TLS compatible con openssl para soportar en el cliente. Consulte ciphers(1) para obtener más información.

-C

Desconéctese y salga del programa inmediatamente después de recibir el número dado de mensajes. Esto puede ser útil en scripts de shell donde solo se requiere un único valor de estado, por ejemplo.

Combine con -R para imprimir solo el primer conjunto de mensajes frescos (es decir, que no tienen el indicador retenido establecido), o con -T para filtrar qué temas se procesan.

-d, --debug

Habilita mensajes de depuración.

-D, --property

Utiliza una propiedad MQTT v5 con esta publicación. Si usa esta opción, el cliente se configurará como un cliente MQTT v5. Esta opción tiene dos formas:

-D comando identificador valor

-D comando identificador nombre valor

comando es el identificador del comando/paquete MQTT y puede ser CONNECT, PUBACK, PUBREC, PUBCOMP, SUBSCRIBE, UNSUBSCRIBE, DISCONNECT, AUTH o WILL. Las propiedades disponibles para cada comando se enumeran en la sección Propiedades.

identificador es el nombre de la propiedad a agregar. Esto es como se describe en la especificación, pero con '-' como separador de palabras. Por ejemplo: payload-format-indicator. Más detalles en la sección Propiedades.

valor es el valor de la propiedad a agregar, con un tipo de dato específico de la propiedad.

nombre solo se usa para la propiedad user-property como la primera de las dos cadenas en el par de cadenas. En ese caso, valor es la segunda de las cadenas en el par.

-E

Si se proporciona esta opción, mosquitto_sub saldrá inmediatamente una vez que todas sus suscripciones hayan sido confirmadas por el broker. En conjunción con -c, esto permite que una sesión de cliente duradera se inicialice en el broker para su uso futuro sin requerir que se reciban mensajes.

-F

Especifica el formato de impresión de salida. Esta opción le permite elegir qué información de cada mensaje se imprime en la pantalla. Consulte la sección Formato de Salida a continuación para obtener detalles completos.

Esta opción anula la opción -v, pero no anula la opción -N.

--ayuda

Muestra información de uso.

-h, --host

Especifica el host al que conectarse. El valor predeterminado es localhost.

-i, --id

El id a usar para este cliente. Si no se proporciona, se generará un id de cliente dependiendo de la versión de MQTT que se esté utilizando. Para v3.1.1/v3.1, el cliente genera un id de cliente en el formato mosq-XXXXXX
XXXXXXXXXXXX, donde las X se reemplazan con caracteres alfanuméricos aleatorios. Para la v5.0, el cliente envía un id de cliente de longitud cero, y el servidor generará un id de cliente para el cliente.

Esta opción no se puede usar al mismo tiempo que el argumento --id-prefix.

-I, --id-prefix

Proporciona un prefijo a partir del cual se construirá el id del cliente, añadiendo el id de proceso del cliente. Esto es útil cuando el broker está utilizando la opción `clientid_prefixes`. No se puede usar al mismo tiempo que el argumento --id.

--insecure

Al usar cifrado basado en certificados, esta opción deshabilita la verificación del nombre de host del servidor en el certificado del servidor. Esto puede ser útil al probar configuraciones iniciales del servidor, pero hace posible que un tercero malintencionado suplante tu servidor a través de la suplantación de DNS, por ejemplo. Usa esta opción solo en pruebas únicamente. Si necesitas recurrir a usar esta opción en un entorno de producción, tu configuración es defectuosa y no tiene sentido usar cifrado.

-k, --keepalive

El número de segundos entre el envío de comandos PING al broker con el fin de informarle que todavía estamos conectados y funcionando. Por defecto son 60 segundos.

--key

Define la ruta a un archivo que contiene una clave privada codificada en PEM para este cliente, si es requerida por el servidor.

Ver también --cert y la sección Conexiones Cifradas.

--keyform

Especifica el tipo de clave privada en uso al realizar conexiones TLS. Puede ser "pem" o "engine". Este parámetro es útil cuando se está utilizando un módulo TPM y la clave privada se ha creado con él. Por defecto es "pem", lo que significa que se utilizan archivos de clave privada normales.

Ver también --tls-engine.

-L, --url

Especifica el usuario, la contraseña, el host, el puerto y el tema a la vez como una URL. La URL debe tener el formato: mqtt(s)://[usuario[:contraseña]@]host[:puerto]/tema

Si el esquema es mqtt://, el puerto por defecto es 1883. Si el esquema es mqtts://, el puerto por defecto es 8883.

-N

No añada un carácter de fin de línea al payload al imprimir. Esto permite la transmisión de datos del payload de múltiples mensajes directamente a otra aplicación sin modificaciones. Solo tiene sentido cuando no se usa -v.

--nodelay

Desactiva el algoritmo de Nagle para el socket. Esto significa que la latencia de los mensajes enviados se reduce, lo que es particularmente notable para mensajes pequeños y relativamente infrecuentes. El uso de esta opción puede resultar en el envío de más paquetes de los que normalmente serían necesarios.

-p, --port

Conéctate al puerto especificado. Si no se indica, se utilizará el valor por defecto de 1883 para MQTT sin cifrar o 8883 para MQTT sobre TLS.

-P, --pw

Proporciona una contraseña que se utilizará para autenticarse con el broker. Usar este argumento sin especificar también un nombre de usuario es inválido cuando se utiliza MQTT v3.1 o v3.1.1. Ver también la opción --username.

--pretty

Cuando se utiliza el formato de salida JSON %j o %J, el valor predeterminado es imprimir de forma no formateada. Especificar --pretty imprime los mensajes en un formato más bonito y legible para el ser humano.

--proxy

Especifica un proxy SOCKS5 a través del cual conectarse. Se admiten los tipos de autenticación "None" y "username". La socks-url debe tener el formato socks5h://[usuario[:contraseña]@]host[:puerto]. El prefijo de protocolo socks5h significa que los nombres de host son resueltos por el proxy. Los símbolos %25, %3A y %40 se decodifican en URL a %, : y @ respectivamente, si están presentes en el nombre de usuario o la contraseña.

Si no se proporciona nombre de usuario, no se intentará ninguna autenticación. Si no se proporciona el puerto, se utilizará el valor predeterminado de 1080.

Pueden estar disponibles más versiones de SOCKS en el futuro, dependiendo de la demanda, y utilizarán prefijos de protocolo diferentes según se describe en curl(1).

--psk

Proporciona la clave precompartida (psk) hexadecimal (sin prefijo 0x) que coincide con la utilizada en el broker para usar el soporte de cifrado TLS-PSK. También se debe proporcionar --psk-identity para habilitar TLS-PSK.

--psk-identity

La identidad del cliente a utilizar con el soporte TLS-PSK. Esto puede ser utilizado en lugar de un nombre de usuario si el broker está configurado para hacerlo.

-q, --qos

Especifica la calidad de servicio deseada para los mensajes entrantes, de 0, 1 y 2. Por defecto es 0. Ver mqtt(7) para más información sobre QoS.

El QoS es idéntico para todos los temas suscritos en una sola instancia de mosquitto_sub.

--quiet

Si se proporciona este argumento, no se imprimirán errores en tiempo de ejecución. Esto excluye cualquier mensaje de error dado en caso de entrada de usuario inválida (por ejemplo, usar --port sin un puerto).

-R

Si se proporciona este argumento, los mensajes que se reciban con el bit de retención establecido no se imprimirán. Los mensajes con retención establecida son "obsoletos", en el sentido de que no se sabe cuándo se publicaron originalmente. Al suscribirse a un tema comodín, puede haber un gran número de mensajes retenidos. Este argumento suprime su visualización.

--random-filter

Esta opción se puede utilizar para reducir la proporción de mensajes que imprime mosquitto_sub. El comportamiento predeterminado es imprimir todos los mensajes entrantes. Establecer la *probabilidad* a un valor de punto flotante entre 0.1 y 100.0 asegurará que, en promedio, se imprima ese porcentaje de mensajes.

--remove-retained

Si se proporciona este argumento, cuando mosquitto_sub recibe un mensaje con el bit de retención establecido, enviará un mensaje al broker para borrar ese mensaje retenido. Esto se aplica a todos los mensajes recibidos, excepto a aquellos que son filtrados por la opción -T. Esta opción sigue teniendo efecto incluso si se utiliza -R. Ver también las opciones --retain-as-published y --retained-only.

Ejemplo 1. Eliminar todos los mensajes retenidos en el servidor, asumiendo que tenemos acceso para hacerlo, y luego salir:

mosquitto_sub -t '#' --remove-retained --retained-only

Ejemplo 2. Eliminar un árbol completo, con la excepción de un solo tema:

mosquitto_sub -t 'bbc/#' -T bbc/bbc1 --remove-retained

--retained-only

Si se proporciona este argumento, solo se imprimirán los mensajes que se reciben y que tienen el bit de retención establecido. Los mensajes con retención establecida son "obsoletos", en el sentido de que no se sabe cuándo se publicaron originalmente. Con este argumento en uso, la recepción del primer mensaje no obsoleto provocará la salida del cliente. Ver también la opción --retain-as-published.

--retain-as-published

Si se proporciona este argumento, las suscripciones tendrán establecida la opción "retain as published". Esto significa que el indicador de retención en un mensaje entrante será exactamente como lo estableció el cliente que lo publicó, en lugar de indicar si el mensaje es reciente/obsoleto.

Esta opción no es válida para clientes MQTT v3.1/v3.1.1.

-S

Utiliza búsquedas SRV para determinar a qué host conectarse. Realiza búsquedas en _mqtt._tcp.<host> cuando se utiliza junto con -h, de lo contrario utiliza _mqtt._tcp.<dominio dns local>.

-t, --topic

El tema MQTT al que suscribirse. Ver mqtt(7) para más información sobre temas MQTT.

Esta opción se puede repetir para suscribirse a múltiples temas.

-T, --filter-out

Suprime la impresión de temas que coinciden con el filtro. Esto permite suscribirse a un tema comodín e imprimir solo un conjunto parcial de la jerarquía comodín.

Por ejemplo, suscríbete al árbol de BBC, pero suprime la salida de Radio 3:

•mosquitto_sub -t bbc/# -T bbc/radio3

Esta opción se puede repetir para filtrar múltiples temas o árboles de temas.

--tls-alpn

Proporciona un protocolo a utilizar al conectarse a un broker que tiene múltiples protocolos disponibles en un solo puerto, por ejemplo, MQTT y WebSockets.

--tls-engine

Un ID de motor openssl válido. Estos se pueden listar con el comando openssl engine.

Ver también --keyform.

--tls-engine-kpass-sha1

SHA1 de la contraseña de la clave privada al usar un motor TLS. Algunos motores TLS, como el motor TPM, pueden requerir el uso de una contraseña para ser accedidos. Esta opción permite pasar un hash SHA1 codificado en hexadecimal de la contraseña directamente al motor, en lugar de que el usuario introduzca la contraseña.

Ver también --tls-engine.

--tls-use-os-certs

Si se utiliza, cargará y confiará en los certificados CA proporcionados por el SO. Esto se puede usar en conjunto con --cafile y --capath y se puede usar por sí solo para habilitar el modo TLS. Esto se establecerá por defecto si se utiliza -L mqtts://..., o si el puerto es 8883 y no se utilizan otras opciones de certificado.

--tls-version

Elige qué versión del protocolo TLS utilizar al comunicarse con el broker. Las opciones válidas son tlsv1.3, tlsv1.2 y tlsv1.1. El valor predeterminado es tlsv1.2. Debe coincidir con la versión del protocolo utilizada por el broker.

-u, --username

Proporciona un nombre de usuario que se utilizará para autenticarse con el broker. Ver también el argumento --pw.

--unix

Conéctate a un broker a través de un socket de dominio Unix local en lugar de un socket TCP. Esto es un reemplazo para -h y -L. Por ejemplo: mosquitto_pub --unix /tmp/mosquitto.sock ...

Ver la opción socket_domain en mosquitto.conf(5) para configurar Mosquitto para escuchar en un socket Unix.

-U, --unsubscribe

Un tema del cual se desuscribirá. Esto puede usarse solo o en conjunción con la opción --topic y solo tiene sentido cuando se usa en conjunción con --clean-session.

Si se usa con --topic, las suscripciones se procesarán antes de las desuscripciones.

Tenga en cuenta que solo es posible desuscribirse de suscripciones que se hayan realizado previamente. No es posible hacer agujeros en suscripciones comodín. Por ejemplo, suscribirse a sensores/# y luego desuscribirse de sensores/+/temperatura

/b> como se muestra a continuación aún resultará en que los mensajes que coincidan con sensors/+/temperature se entreguen al cliente.

•mosquitto_sub -t sensors/# -U sensores/+/temperatura -v

Tenga en cuenta también que, dado que los mensajes retenidos son publicados por el broker al recibir un comando SUBSCRIBE, la suscripción y la cancelación de la suscripción al mismo tema pueden resultar en la recepción de mensajes en el cliente.

Esta opción se puede repetir para cancelar la suscripción de varios temas.

-v, --verbose

Imprimir mensajes recibidos de forma detallada. Con este argumento, los mensajes se imprimirán como "tema payload". Cuando este argumento no se proporciona, los mensajes se imprimen como "payload".

-V, --protocol-version

Especificar qué versión del protocolo MQTT se debe utilizar al conectarse al broker remoto. Puede ser 5, 311, 31, o las versiones más detalladas mqttv5, mqttv311, o mqttv31. Por defecto es 311.

-W

Proporcionar un tiempo de espera como número entero de segundos. mosquitto_sub dejará de procesar mensajes y se desconectará después de que haya transcurrido este número de segundos. El tiempo de espera comienza justo después de que el cliente se haya conectado al broker.

--will-payload

Especificar un mensaje que será almacenado por el broker y enviado si este cliente se desconecta inesperadamente. Esto debe usarse junto con --will-topic.

--will-qos

El QoS a utilizar para el Will. Por defecto es 0. Esto debe usarse junto con --will-topic.

--will-retain

Si se proporciona, si el cliente se desconecta inesperadamente, el mensaje enviado se tratará como un mensaje retenido. Esto debe usarse junto con --will-topic.

--will-topic

El tema en el que se enviará un Will, en caso de que el cliente se desconecte inesperadamente.

-x

Establecer la propiedad session-expiry-interval en el paquete CONNECT. Se aplica solo a clientes MQTT v5. Establecer a 0-4294967294 para especificar que la sesión expirará en esa cantidad de segundos después de que el cliente se desconecte, o usar -1, 4294967295, o ∞ para una sesión que no expira. Por defecto es -1 si también se da -c, o 0 si no se da -c.

Si la sesión se establece para que nunca expire, ya sea con -x o -c, entonces se debe proporcionar un id de cliente.

FORMATO DE SALIDA

Hay tres formas de formatear la salida de mosquitto_sub. En todos los casos, se agrega un carácter de nueva línea por cada mensaje recibido a menos que se pase el argumento -N a mosquitto_sub.

La salida solo de payload es el formato de salida predeterminado e imprimirá el payload exactamente como se recibe.

El modo detallado se activa con -v e imprime el tema del mensaje y el payload, separados por un espacio.

La opción final es la salida formateada, que permite al usuario definir un formato de salida personalizado. El comportamiento se controla con la opción -F cadena-formato. La cadena de formato es una cadena de texto libre donde las secuencias interpretadas se reemplazan por diferentes parámetros. Las secuencias disponibles se describen a continuación.

Se utilizan tres caracteres para iniciar una secuencia interpretada: %, @ y \. Las secuencias que comienzan con % son parámetros relacionados con el mensaje MQTT que se está imprimiendo, o son secuencias auxiliares para evitar la necesidad de escribir cadenas de formato de fecha largas, por ejemplo. Las secuencias que comienzan con @ se pasan a la función strftime(3) (con el @ reemplazado por un % - tenga en cuenta que solo el carácter inmediatamente después del @ se pasa a strftime). Esto permite la construcción de una amplia variedad de salidas basadas en tiempo. Las opciones de salida para strftime varían de una plataforma a otra, así que compruebe qué está disponible para su plataforma. mosquitto_sub proporciona una extensión a strftime, que es @N, que se puede utilizar para obtener el número de nanosegundos transcurridos en el segundo actual. La resolución de esta opción varía según la plataforma. El carácter de secuencia final es \, que se utiliza para introducir algunos caracteres que de otro modo serían difíciles de introducir.

Caracteres de indicador

Los parámetros %A, %C, %E, %F, %I, %l, %m, %p, %R, %S, %t, %x, y %X pueden tener indicadores opcionales inmediatamente después del carácter %.

0

El valor debe rellenarse con ceros. Esto se aplica a los parámetros %A, %E, %F, %l, %m, %S, %X, y %x. Se ignorará para otros parámetros. Si se usa con el indicador -, el indicador 0 se ignorará.

-

El valor se alineará a la izquierda en el ancho del campo, rellenado con espacios. El valor predeterminado es la alineación a la derecha, con relleno de 0 o espacios.

Ancho de campo

Algunos de los parámetros relacionados con MQTT se pueden formatear con una opción para establecer su ancho de campo de manera similar a los formatos regulares de estilo printf, es decir, esto establece el ancho mínimo al imprimir este parámetro. Esto se aplica a las opciones %A, %C, %E, %F, %I, %l, %m, %p, %R, %S, %t, %x, %X.

Por ejemplo, %10t establecería el ancho mínimo del campo del tema a 10 caracteres.

Ancho máximo

Algunos de los parámetros relacionados con MQTT se pueden formatear con una opción para establecer un ancho de campo máximo de manera similar a los formatos regulares de estilo printf. Esto se aplica a las opciones %C, %I, %R, %t.

Por ejemplo, %10.10t establecería el ancho mínimo del campo del tema a 10 caracteres, y el ancho máximo del tema a 10 caracteres, es decir, el campo siempre tendrá exactamente 10 caracteres de longitud.

Parámetros relacionados con MQTT

•%% un % literal.
•%A la propiedad topic-alias de MQTT v5, si está presente.
•%C la propiedad content-type de MQTT v5, si está presente.
•%D la propiedad correlation-data de MQTT v5, si está presente. Tenga en cuenta que esta propiedad se especifica como datos binarios, por lo que puede producir caracteres no imprimibles.
•%E la propiedad message-expiry-interval de MQTT v5, si está presente.
•%F la propiedad payload-format-indicator de MQTT v5, si está presente.
•%l la longitud del payload en bytes.
•%m el ID del mensaje (solo relevante para mensajes con QoS>0).
•%P la propiedad user-property de MQTT v5, si está presente. Se imprimirá en el formato clave:valor. Es posible que se adjunten cualquier número de propiedades de usuario a un mensaje, y que existan claves duplicadas.
•%p los bytes brutos del payload (puede producir caracteres no imprimibles dependiendo del payload).
•%q el QoS del mensaje.
•%R la propiedad response-topic de MQTT v5, si está presente.
•%r el indicador de retención para el mensaje.
•%S la propiedad subscription-identifier de MQTT v5, si está presente.
•%t el tema del mensaje.
•%x el payload con cada byte como un número hexadecimal (minúsculas).
•%X el payload con cada byte como un número hexadecimal (mayúsculas).

Ayudantes

•%I fecha y hora en formato ISO-8601, por ejemplo 2016-08-10T09:47:38+0100
•%j salida JSON de los parámetros del mensaje y timestamp, con un payload entrecomillado y escapado. Por ejemplo {"tst":"2020-05-06T22:12:00.000000+0100","topic":"greeting","qos":0,"retain":0,"payload":"hello world"}
•%J salida JSON de los parámetros del mensaje y timestamp, con un payload sin comillas y sin escapar - esto significa que el payload debe ser JSON válido. Por ejemplo: {"tst":"2020-05-06T22:12:00.000000+0100","topic":"foo","qos":0,"retain":0,"payload":{"temperature":27.0,"humidity":57}}.

Si el payload no es JSON válido, se imprimirá el mensaje de error "Error: Message payload is not valid JSON on topic <topic>" en stderr.

•%U timestamp Unix con nanosegundos, por ejemplo 1470818943.786368637

Parámetros relacionados con el tiempo

•@@ un @ literal.
•@X pasa el carácter representado por X a la función strftime como %X. Las opciones compatibles dependen de la plataforma.
•@N el número de nanosegundos transcurridos en el segundo actual, con una resolución de tiempo variable según la plataforma.

Caracteres de escape

•\\ una \ literal.
•\0 un carácter nulo. Se puede utilizar para separar diferentes parámetros que puedan contener espacios (por ejemplo, tema, payload) para facilitar el procesamiento con herramientas como xargs(1).
•\a alerta/campana.
•\e la secuencia de escape, que se puede utilizar con códigos de color ANSI para proporcionar salida en color, por ejemplo.
•\n fin de línea.
•\r retorno de carro.
•\t tabulación horizontal.
•\v tabulación vertical.

WILLS

mosquitto_sub puede registrar un mensaje en el broker que se enviará si se desconecta inesperadamente. Consulte mqtt(7) para obtener más información.

El requisito mínimo para esto es usar --will-topic para especificar en qué tema se enviará el will. Esto resultará en un mensaje no retenido, de longitud cero y con QoS 0.

Utilice --will-retain, --will-payload y --will-qos para modificar los otros parámetros del will.

ESTADO DE SALIDA

mosquitto_sub devuelve cero si la operación fue exitosa, o un valor distinto de cero si ocurrió un error. Si la conexión es rechazada por el broker a nivel MQTT, entonces el código de salida es el código de razón de CONNACK. Si ocurre otro error, el código de salida es un valor de retorno de libmosquitto.

Códigos CONNACK de MQTT v3.1.1:

•0 Éxito
•1 Conexión rechazada: versión de protocolo incorrecta
•2 Conexión rechazada: identificador rechazado
•3 Conexión rechazada: servidor no disponible
•4 Conexión rechazada: nombre de usuario/contraseña incorrectos
•5 Conexión rechazada: no autorizado

•0 Éxito
•128 Error no especificado
•129 Paquete malformado
•130 Error de protocolo
•131 Error específico de la implementación
•132 Versión de protocolo no admitida
•133 ID de cliente no válido
•134 Nombre de usuario o contraseña incorrectos
•135 No autorizado
•136 Servidor no disponible
•137 Servidor ocupado
•138 Prohibido
•139 El servidor se está apagando
•140 Método de autenticación incorrecto
•141 Tiempo de espera de keep-alive superado
•142 Sesión transferida
•143 Filtro de tema no válido
•144 Nombre de tema no válido
•147 Se superó el máximo de recepción
•148 Alias de tema no válido
•149 Paquete demasiado grande
•148 Tasa de mensajes demasiado alta
•151 Cuota superada

EJEMPLOS

Tenga en cuenta que estos son realmente ejemplos: las suscripciones funcionarán si las ejecuta tal como se muestran, pero debe haber algo publicando mensajes en esos temas para que usted reciba algo.

Suscribirse a información de temperatura en localhost con QoS 1:

•mosquitto_sub -t sensors/temperature -q 1

Suscribirse a actualizaciones de temperatura de disco duro en múltiples máquinas/discos duros. Esto espera que cada máquina esté publicando la temperatura de su disco duro en sensors/machines/HOSTNAME/temperature/HD_NAME.

•mosquitto_sub -t sensors/machines/+/temperature/+

Suscribirse a todos los mensajes de estado del broker:

•mosquitto_sub -v -t \$SYS/#

Especificar el formato de salida como "fecha ISO-8601 : tema : carga útil en hexadecimal"

•mosquitto_sub -F '@Y-@m-@dT@H:@M:@S@z : %t : %x' -t '#'

Especificar el formato de salida como "segundos desde la época.nanosegundos : indicador de retención : qos : mid : longitud de la carga útil"

•mosquitto_sub -F '%@s.@N : %r : %q : %m : %l' -q 2 -t '#'

Salida de tema y carga útil, pero con color donde sea compatible.

•mosquitto_sub -F '\e[92m%t \e[96m%p\e[0m' -q 2 -t '#'
