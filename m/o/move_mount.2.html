move_mount(2) Manual de llamadas al sistema move_mount(2)

NOMBRE

move_mount - mover o adjuntar objeto de montaje al sistema de archivos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <fcntl.h>          /* Definición de las constantes AT_* */
#include <sys/mount.h>
int move_mount(int from_dirfd, const char *from_path,
               int to_dirfd, const char *to_path,
               unsigned int flags);

DESCRIPCIÓN

La llamada al sistema move_mount() forma parte del conjunto de instalaciones de montaje basadas en descriptores de archivo en Linux.

move_mount() mueve el objeto de montaje indicado por from_dirfd y from_path a la ruta indicada por to_dirfd y to_path. El objeto de montaje que se mueve puede ser un punto de montaje existente en el espacio de nombres de montaje actual, o un objeto de montaje separado creado por fsmount(2) o open_tree(2) con OPEN_TREE_CLONE.

Para acceder al objeto de montaje de origen o al punto de montaje de destino, no se requieren permisos sobre el objeto en sí, pero si se proporciona alguna ruta, se requiere permiso de ejecución (búsqueda) en todos los directorios especificados en from_path o to_path.

El proceso que llama debe tener la capacidad CAP_SYS_ADMIN para mover o adjuntar un objeto de montaje.

Al igual que con las llamadas al sistema "*at()", move_mount() utiliza los argumentos from_dirfd y to_dirfd en conjunción con los argumentos from_path y to_path para determinar los objetos de origen y destino sobre los que operar (respectivamente), de la siguiente manera:

•
Si la ruta dada en *_path es absoluta, entonces el *_dirfd correspondiente se ignora.
•
Si la ruta dada en *_path es relativa y el *_dirfd correspondiente es el valor especial AT_FDCWD, entonces *_path se interpreta en relación con el directorio de trabajo actual del proceso llamador (como open(2)).
•
Si la ruta dada en *_path es relativa, entonces se interpreta en relación con el directorio al que se refiere el descriptor de archivo correspondiente *_dirfd (en lugar de en relación con el directorio de trabajo actual del proceso llamador, como hace open(2) para una ruta relativa). En este caso, el *_dirfd correspondiente debe ser un directorio que se abrió para lectura (O_RDONLY) o usando la bandera O_PATH.
•
Si *_path es una cadena vacía, y flags contiene la bandera adecuada MOVE_MOUNT_*_EMPTY_PATH, entonces el descriptor de archivo correspondiente *_dirfd se opera directamente. En este caso, el *_dirfd correspondiente puede referirse a cualquier tipo de archivo, no solo a un directorio.

Vea openat(2) para una explicación de por qué son útiles los argumentos *_dirfd.

flags se puede utilizar para controlar aspectos de la búsqueda de rutas tanto para los objetos de origen como de destino, así como otras propiedades de la operación de montaje. Un valor para flags se construye mediante OR a nivel de bits de cero o más de las siguientes constantes:

MOVE_MOUNT_F_EMPTY_PATH
Si from_path es una cadena vacía, opere en el archivo al que se refiere from_dirfd (que puede haber sido obtenido de open(2), fsmount(2), o open_tree(2)). En este caso, from_dirfd puede referirse a cualquier tipo de archivo, no solo a un directorio. Si from_dirfd es AT_FDCWD, move_mount() operará en el directorio de trabajo actual del proceso llamador.
Este es el mecanismo más común utilizado para adjuntar objetos de montaje separados producidos por fsmount(2) y open_tree(2) a un punto de montaje.
MOVE_MOUNT_T_EMPTY_PATH
Como con MOVE_MOUNT_F_EMPTY_PATH, excepto que opera sobre to_dirfd y to_path.
MOVE_MOUNT_F_SYMLINKS
Si from_path hace referencia a un enlace simbólico, desreferéncielo. El comportamiento predeterminado para move_mount() es *no seguir* los enlaces simbólicos.
MOVE_MOUNT_T_SYMLINKS
Como con MOVE_MOUNT_F_SYMLINKS, excepto que opera sobre to_dirfd y to_path.
MOVE_MOUNT_F_NO_AUTOMOUNT
No automonte el componente terminal ("nombre base") de from_path si es un directorio que es un punto de automontaje. Esto permite mover un objeto de montaje que tiene un punto de automontaje en su raíz y evita el desencadenamiento involuntario de un punto de automontaje. Esta bandera no tiene efecto si el punto de automontaje ya ha sido montado encima.
MOVE_MOUNT_T_NO_AUTOMOUNT
Como con MOVE_MOUNT_F_NO_AUTOMOUNT, excepto que opera sobre to_dirfd y to_path. Esto permite que un punto de automontaje sea montado manualmente.
MOVE_MOUNT_SET_GROUP (desde Linux 5.15)
Agrega el objeto de montaje privado-propagado adjunto indicado por to_dirfd y to_path al "grupo par" de propagación de montajes del objeto de montaje adjunto no-privado-propagado indicado por from_dirfd y from_path.
A diferencia de otras operaciones de move_mount(), esta operación no mueve ni adjunta ningún objeto de montaje. En su lugar, solo actualiza los metadatos de los objetos de montaje adjuntos. (Además, preste atención al orden de los argumentos; el objeto de montaje modificado por esta operación es el especificado por to_dirfd y to_path).
Esto hace posible crear primero un árbol de montajes que solo contenga montajes privados y luego configurar la disposición de propagación deseada después. (Vea la sección "SUBÁRBOLES COMPARTIDOS" de mount_namespaces(7) para más información sobre la propagación de montajes y los grupos pares).
MOVE_MOUNT_BENEATH (desde Linux 6.5)
Si la ruta indicada por to_dirfd y to_path es un objeto de montaje existente, en lugar de adjuntar o mover el objeto de montaje indicado por from_dirfd y from_path encima de la pila de montajes, adjúntelo o muévalo debajo del montaje superior actual en la pila de montajes.
Después de usar MOVE_MOUNT_BENEATH, es posible desmantelar (umount(2)) el montaje superior para revelar el objeto de montaje que se adjuntó debajo de él anteriormente. Esto permite el reemplazo sin problemas (y atómico) de intrincados árboles de montajes, que a su vez pueden usarse para "actualizar" un árbol de montajes con una versión más reciente.
Esta operación tiene varias restricciones:
•
Los objetos de montaje no pueden adjuntarse debajo de la raíz del sistema de archivos, incluidos los casos en que la raíz del sistema de archivos fue configurada por chroot(2) o pivot_root(2). Para montar debajo de la raíz del sistema de archivos, se debe usar pivot_root(2).
•
La ruta de destino indicada por to_dirfd y to_path no debe ser un objeto de montaje separado, como los producidos por open_tree(2) con OPEN_TREE_CLONE o fsmount(2).
•
El montaje superior actual de la pila de montajes de la ruta de destino y su montaje padre deben estar en el espacio de nombres de montaje del proceso llamador.
•
El llamador debe tener privilegios suficientes para desmantelar el montaje superior de la pila de montajes de la ruta de destino, para demostrar que tiene privilegios para revelar el montaje subyacente.

NOMBRE

move_mount - mover un montaje dentro del árbol de montajes

BIBLIOTECA

Biblioteca de C estándar (libc, -lc)

SINOPSIS

#include <sys/mount.h>
int move_mount(int from_dirfd, const char *from_path,
               int to_dirfd, const char *to_path, unsigned int flags);

DESCRIPCIÓN

La llamada al sistema move_mount() mueve un objeto de montaje (montaje) desde una ubicación (indicada por from_dirfd y from_path) a otra (indicada por to_dirfd y to_path). El origen es un objeto de montaje, que puede ser un montaje primario en el espacio de nombres de montajes del proceso o un montaje desconectado (obtenido con open_tree(2) o fsopen(2)).

El destino es un punto de montaje en el árbol de montajes del proceso. El punto de montaje de destino debe ser un directorio, y el objeto de montaje de origen se moverá para que esté montado en este punto de montaje.

Los argumentos from_dirfd y to_dirfd son descriptores de archivo que especifican el directorio raíz para las rutas relativas from_path y to_path respectivamente. Si son `AT_FDCWD`, las rutas se interpretan de forma relativa al directorio de trabajo actual.

El argumento flags puede ser 0 o una de las siguientes opciones:

MOVE_MOUNT_F_EMPTY_PATH
Si se especifica esta opción, to_path puede ser un punto de montaje existente que contenga entradas distintas de `.` y `..`. El montaje se realizará de forma que el contenido del punto de montaje de destino sea reemplazado por el contenido del montaje que se está moviendo. Si el punto de montaje de destino no está vacío, el comportamiento es indefinido en las versiones del kernel anteriores a la 5.19; en la versión 5.19 y posteriores, el montaje falla con ENOTEMPTY. Si to_path no existe, se creará como un directorio y se montará el montaje.
MOVE_MOUNT_BENEATH
Esta opción permite mover un montaje debajo de otro montaje existente. Específicamente, si se intenta mover un montaje M a un punto de montaje P, y P ya tiene un montaje adjunto A, y M se mueve debajo de A, entonces M se convertirá en un hijo de A en el árbol de montajes. La ruta de destino especificada debe ser la ruta a P, y la ruta de origen debe ser la ruta a M.

Se aplican las siguientes restricciones al usar MOVE_MOUNT_BENEATH:

•
Los eventos de propagación de montaje activados por esta operación move_mount() (como se describe en mount_namespaces(7)) se calculan basándose en el montaje padre del montaje superior actual de la pila de montajes de la ruta de destino.
•
El montaje de la ruta de destino no puede ser un ancestro en el árbol de montajes del objeto de montaje de origen.
•
El objeto de montaje de origen no debe tener ningún sobremontaje, de lo contrario, sería posible crear "montajes fantasma" (es decir, dos montajes montados en el mismo montaje padre en el mismo punto de montaje).
•
No es posible mover un montaje debajo de un montaje superior si el montaje padre del montaje superior actual se propaga al propio montaje superior. De lo contrario, MOVE_MOUNT_BENEATH haría que el objeto de montaje se propagara al montaje superior desde el montaje padre, frustrando el propósito de usar MOVE_MOUNT_BENEATH.
•
No es posible mover un montaje debajo de un montaje superior si el montaje padre del montaje superior actual se propaga al objeto de montaje que se está montando debajo. De lo contrario, esto causaría un problema de propagación similar al punto anterior, frustrando también el propósito de usar MOVE_MOUNT_BENEATH.

Si from_dirfd es un descriptor de archivo de objeto de montaje y move_mount() opera directamente sobre él, from_dirfd permanecerá asociado con el objeto de montaje después de que move_mount() tenga éxito, por lo que puede usar from_dirfd repetidamente con move_mount() y/o llamadas al sistema "*at()" tantas veces como sea necesario.

VALOR DE RETORNO

En caso de éxito, move_mount() devuelve 0. En caso de error, devuelve -1 y se establece errno para indicar el error.

ERRORES

EACCES
Se deniega el permiso de búsqueda para uno de los directorios en el prefijo de ruta de from_path o to_path. (Véase también path_resolution(7)).
EBADF
Uno de from_dirfd o to_dirfd no es un descriptor de archivo válido.
EFAULT
Uno de from_path o to_path es NULL o un puntero a una ubicación fuera del espacio de direcciones accesible del proceso llamador.
EINVAL
Se especificó un indicador no válido en flags.
EINVAL
La ruta indicada por from_dirfd y from_path no es un objeto de montaje.
EINVAL
El tipo de objeto de montaje del objeto de montaje de origen y el inodo de destino no son compatibles (es decir, el origen es un archivo pero el destino es un directorio, o viceversa).
EINVAL
El objeto de montaje de origen o la ruta de destino no están en el espacio de nombres de montajes del proceso llamador (o en un espacio de nombres de montajes anónimo del proceso llamador).
EINVAL
El montaje padre del objeto de montaje de origen tiene propagación de montaje compartida, y por lo tanto no puede ser movido (como se describe en mount_namespaces(7)).
EINVAL
El montaje de origen tiene montajes hijos MS_UNBINDABLE pero la ruta de destino reside en un árbol de montajes con propagación de montaje compartida, lo que de lo contrario haría que los montajes no enlazables se propagaran (como se describe en mount_namespaces(7)).
EINVAL
Se intentó MOVE_MOUNT_BENEATH, pero se violó una de las restricciones enumeradas.
ELOOP
Se encontraron demasiados enlaces simbólicos al resolver from_path o to_path.
ENAMETOOLONG
from_path o to_path es más largo que PATH_MAX.
ENOENT
Un componente de from_path o to_path no existe.
ENOENT
Uno de from_path o to_path es una cadena vacía, pero el indicador MOVE_MOUNT_*_EMPTY_PATH correspondiente no está especificado en flags.
ENOTDIR
Un componente del prefijo de ruta de from_path o to_path no es un directorio, o uno de from_path o to_path es relativo y el from_dirfd o to_dirfd correspondiente es un descriptor de archivo que se refiere a un archivo distinto de un directorio.
ENOMEM
El kernel no pudo asignar suficiente memoria para completar la operación.
EPERM
El proceso llamador no tiene la capacidad requerida CAP_SYS_ADMIN.

ESTÁNDARES

Linux.

HISTORIA

Linux 5.2. glibc 2.36.

EJEMPLOS

move_mount() se puede usar para mover montajes adjuntos como los siguientes:


move_mount(AT_FDCWD, "/a", AT_FDCWD, "/b", 0);

Esto movería el objeto de montaje montado en /a a /b. El procedimiento anterior es funcionalmente equivalente a la siguiente operación de montaje usando mount(2):


mount("/a", "/b", NULL, MS_MOVE, NULL);

move_mount() también se puede usar en conjunción con descriptores de archivo devueltos por open_tree(2) o open(2):


int fd = open_tree(AT_FDCWD, "/mnt", 0); /* open("/mnt", O_PATH); */
move_mount(fd, "", AT_FDCWD, "/mnt2", MOVE_MOUNT_F_EMPTY_PATH);
move_mount(fd, "", AT_FDCWD, "/mnt3", MOVE_MOUNT_F_EMPTY_PATH);
move_mount(fd, "", AT_FDCWD, "/mnt4", MOVE_MOUNT_F_EMPTY_PATH);

Esto movería el objeto de montaje montado en /mnt a /mnt2, luego a /mnt3, y luego a /mnt4.

Si el objeto de montaje de origen indicado por from_dirfd y from_path es un objeto de montaje desconectado, move_mount() puede usarse para adjuntarlo a un punto de montaje:


int fsfd, mntfd;
fsfd = fsopen("ext4", FSOPEN_CLOEXEC);
fsconfig(fsfd, FSCONFIG_SET_STRING, "source", "/dev/sda1", 0);
fsconfig(fsfd, FSCONFIG_SET_FLAG, "user_xattr", NULL, 0);
fsconfig(fsfd, FSCONFIG_CMD_CREATE, NULL, NULL, 0);
mntfd = fsmount(fsfd, FSMOUNT_CLOEXEC, MOUNT_ATTR_NODEV);
move_mount(mntfd, "", AT_FDCWD, "/home", MOVE_MOUNT_F_EMPTY_PATH);

Esto crearía un nuevo contexto de configuración del sistema de archivos para ext4, lo configuraría, crearía un objeto de montaje desconectado, y luego lo adjuntaría a /home. El procedimiento anterior es funcionalmente equivalente a la siguiente operación de montaje usando mount(2):


mount("/dev/sda1", "/home", "ext4", MS_NODEV, "user_xattr");

La misma operación también funciona con montajes bind desconectados creados con open_tree(2) con OPEN_TREE_CLONE:


int mntfd = open_tree(AT_FDCWD, "/home/cyphar", OPEN_TREE_CLONE);
move_mount(mntfd, "", AT_FDCWD, "/root", MOVE_MOUNT_F_EMPTY_PATH);

Esto crearía un nuevo montaje bind de /home/cyphar como un objeto de montaje desconectado, y luego lo adjuntaría a /root. El procedimiento anterior es funcionalmente equivalente a la siguiente operación de montaje usando mount(2):


mount("/home/cyphar", "/root", NULL, MS_BIND, NULL);

NAME

move_mount - mover un punto de montaje

SYNOPSIS

int move_mount(const char *oldpath, const char *newpath, unsigned int flags);

DESCRIPTION

La llamada al sistema move_mount mueve el punto de montaje especificado por oldpath a newpath. El directorio oldpath debe ser un punto de montaje existente, y newpath debe ser un directorio vacío.

El argumento flags puede ser 0 o uno de los siguientes valores:

  • MOVE_MOUNT_FST_IS_MOUNTPOINT: Indica que oldpath es un punto de montaje de un sistema de archivos (por ejemplo, /dev/sda1 montado en /mnt), no un directorio en sí mismo.

Esta llamada al sistema es útil para reorganizar la jerarquía de puntos de montaje en un sistema.

RETURN VALUE

En caso de éxito, move_mount devuelve 0. En caso de error, devuelve -1 y establece errno para indicar el error.

ERRORS

  • EBUSY: oldpath está ocupado o newpath no está vacío.
  • EINVAL: Se especificó un valor inválido en flags.
  • ENOENT: oldpath o newpath no existen.
  • ENOTDIR: Un componente de la ruta no es un directorio.
  • EPERM: El llamante no tiene los permisos necesarios para realizar la operación.

STANDARDS

Esta llamada al sistema es específica de Linux y no forma parte de ningún estándar POSIX.

HISTORY

La llamada al sistema move_mount se introdujo en el kernel de Linux versión 5.10.

EXAMPLES

Para mover el punto de montaje /mnt/data a /media/storage, se podría usar el siguiente código:

#include <sys/mount.h>
#include <stdio.h>
#include <errno.h>

int main() {
    const char *oldpath = "/mnt/data";
    const char *newpath = "/media/storage";
    unsigned int flags = 0; // O MOVE_MOUNT_FST_IS_MOUNTPOINT si oldpath es un dispositivo

    if (move_mount(oldpath, newpath, flags) == -1) {
        perror("move_mount");
        return 1;
    }

    printf("Punto de montaje movido de %s a %s\n", oldpath, newpath);
    return 0;
}
