Nombre

mount.crypt - montar un volumen encriptado dm-crypt

Sintaxis

mount.crypt [-nrv] [-o opciones] dispositivo directorio

Opciones

-o opciones
Establecer opciones de montaje adicionales. mount.crypt extraerá sus propias opciones reconocidas y pasará cualquier opción restante al programa de montaje subyacente. Consulte más abajo las opciones posibles.
-n
No actualizar /etc/mtab. Tenga en cuenta que esto hace imposible desmontar el volumen nombrando el contenedor; deberá pasar el punto de montaje a umount.crypt.
-r
Configurar el dispositivo loop (si es necesario) y el dispositivo criptográfico en modo de solo lectura. (El montaje en sí será necesariamente de solo lectura). Tenga en cuenta que realizar una remontada usando `mount /mnt -o remount,rw` **no** hará que el montaje sea de lectura/escritura. Los dispositivos criptográficos y de loop tendrán que ser desasociados primero.
-v
Activar la depuración y ser un poco más detallado.

Opciones de montaje

header
Un archivo de metadatos separado (desconectado) donde se almacena la cabecera LUKS. Se correlaciona con la opción `cryptsetup --header`. Si se omite, no se utiliza la característica de cabecera LUKS desconectada.
allow_discard
Habilita el soporte de paso de descarte. Esta opción no hace que el sistema de archivos se monte con descarte habilitado, pero permite que fstrim se ejecute manualmente.
no_read_workqueue
Evitar la cola de trabajo interna y procesar las solicitudes de lectura de forma síncrona.
no_write_workqueue
Evitar la cola de trabajo interna y procesar las solicitudes de escritura de forma síncrona.
cipher
El cifrado cryptsetup utilizado para el volumen encriptado. Esta opción es obligatoria para volúmenes PLAIN (no LUKS). pmt-ehd(8) utiliza por defecto la creación de volúmenes con "aes-cbc-essiv:sha256" como cifrado.
crypto_name
Seleccionar el nombre para el dispositivo criptográfico (opcional). Esta opción actualmente solo es utilizable con sistemas dm-crypt.
fsck
Ejecutar fsck en el contenedor antes de montarlo.
fsk_cipher
El cifrado OpenSSL utilizado para la clave del sistema de archivos. La palabra clave especial "none" puede usarse para evitar la descifración y pasar el contenido del archivo directamente a libcryptsetup.
fsk_hash
El hash OpenSSL utilizado para producir la clave y el IV.
fstype
El tipo exacto de sistema de archivos en el contenedor encriptado. El valor predeterminado es dejar que el kernel lo autodetecte.
hash
El hash cryptsetup utilizado para el volumen encriptado. Esto es predeterminado a ningún hash, ya que pam_mount asume volúmenes EHD con una generación de clave de sistema de archivos simple y fuerte.
keyfile
La ruta al archivo de clave. Esta opción es obligatoria para volúmenes criptográficos "normales" y no debe usarse para volúmenes LUKS.
remount
Provoca que el sistema de archivos se remonte con nuevas opciones. Tenga en cuenta que mount.crypt no puede cambiar el dispositivo loop subyacente (si corresponde) o el dispositivo criptográfico entre solo lectura y lectura/escritura una vez que se crea; solo se puede cambiar el montaje real del sistema de archivos, con límites. Si el dispositivo loop es de solo lectura, el dispositivo criptográfico será de solo lectura y cambiar el montaje a lectura/escritura será imposible. De manera similar, pasar de rw a ro solo marcará el montaje como de solo lectura, pero no el dispositivo criptográfico o loop, lo que hará imposible establecer el sistema de archivos en el que se encuentra el contenedor criptográfico en modo de solo lectura.
ro
Igual que la opción -r.
verbose
Igual que la opción -v.

Opciones de montaje obsoletas

Esta sección se proporciona como referencia.

loop
Esta opción solía configurar un dispositivo loop, ya que cryptsetup(8) espera un dispositivo de bloque. La opción se ignora porque mount.crypt puede deducirlo por sí solo.
