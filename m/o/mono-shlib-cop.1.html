mono-shlib-cop(1) Manual de Comandos Generales mono-shlib-cop(1)

NOMBRE

mono-shlib-cop - Comprobador de uso de bibliotecas compartidas

SINOPSIS

mono-shlib-cop [OPCIONES]* [NOMBRE-ARCHIVO-ENSAMBLADO]*

OPCIONES

-p, --prefijos=PREFIJO
Prefijos de instalación de Mono. Esto es para encontrar $prefijo/etc/mono/config. El valor predeterminado se basa en la ubicación de mscorlib.dll y normalmente es correcto.

DESCRIPCIÓN

mono-shlib-cop es una herramienta que inspecciona un ensamblado administrado en busca de un uso erróneo o sospechoso de bibliotecas compartidas.

La herramienta toma uno o más nombres de archivo de ensamblado e inspecciona cada ensamblado especificado.

Los errores que se comprueban incluyen:

*
¿Existe la biblioteca compartida?
*
¿Existe el símbolo solicitado dentro de la biblioteca compartida?

Las advertencias que se comprueban incluyen:

*
¿Es la biblioteca compartida de destino una biblioteca versionada? (Relevante solo en sistemas Unix, no en Mac OS X o Windows.)

En general, en la máquina del usuario solo están presentes bibliotecas versionadas como libc.so.6, y los intentos de cargar libc.so resultarán en una System.DllNotFoundException. Hay tres soluciones para esto:

1.
Exigir que el usuario instale cualquier paquete -devel que proporcione la biblioteca no versionada. Esto normalmente requiere que el usuario instale un gran número de paquetes adicionales, complicando el proceso de instalación.
2.
Usar un nombre completamente versionado en sus declaraciones DllImport. Esto requiere editar su código fuente y recompilar cada vez que necesite dirigirse a una versión diferente de la biblioteca compartida.
3.
Proporcionar un archivo ensamblado.config que contenga elementos <dllmap/> para remapear el nombre de la biblioteca compartida utilizado por su ensamblado a la biblioteca compartida versionada real presente en el sistema del usuario. Mono proporciona varias entradas <dllmap/> preexistentes, incluidas las de libc.so y libX11.so.

EJEMPLO

El siguiente código contiene ejemplos de los errores y advertencias anteriores:

using System.Runtime.InteropServices; // para DllImport
class Demo {
	[DllImport ("bad-library-name")]
	private static extern void BadLibraryName ();
	[DllImport ("libc.so")]
	private static extern void BadSymbolName ();
	[DllImport ("libcap.so")]
	private static extern int cap_clear (IntPtr cap_p);
}
Nombre de biblioteca incorrecto
Suponiendo que la biblioteca bad-library-name no existe en su máquina, Demo.BadLibraryName generará un error, ya que requiere una biblioteca compartida que no se puede cargar. Esto puede ser ignorado; consulte BUGS
Nombre de símbolo incorrecto
Demo.BadSymbolName generará un error, ya que libc.so (re-mapeado a libc.so.6 por el archivo $prefijo/etc/mono/config de Mono) no contiene la función BadSymbolName
Dependencia de biblioteca no versionada
Suponiendo que tiene el archivo libcap.so, Demo.cap_clear generará una advertencia porque, aunque libcap.so podría cargarse, libcap.so podría no existir en la máquina del usuario (en FC2, /lib/libcap.so es proporcionado por libcap-devel, y no se puede asumir que los usuarios finales tendrán instalados paquetes -devel).

CORREGIR CÓDIGO

La corrección depende de la advertencia o el error:

Nombres de bibliotecas incorrectos
Use un nombre de biblioteca válido en el atributo DllImport, o proporcione una entrada <dllmap/> para mapear su nombre de biblioteca existente a un nombre de biblioteca válido.
Nombres de símbolos incorrectos
Referencie un símbolo que realmente exista en la biblioteca de destino.
Dependencia de biblioteca no versionada
Proporcione una entrada <dllmap/> para referenciar una biblioteca debidamente versionada, o ignore la advertencia (consulte BUGS).

ENTRADAS DLLMAP

Mono busca información de mapeo del NOMBRE-DE-ENSAMBLADO. Por ejemplo, con mcs.exe, Mono leería mcs.exe.config, y para Mono.Posix.dll, Mono leería Mono.Posix.dll.config

El archivo .config es un documento XML que contiene una sección <configuration/> de nivel superior con entradas <dllmap/> anidadas, que contienen los atributos dll y target. El atributo dll debe contener la misma cadena utilizada en el valor de su atributo DllImport, y el atributo target especifica qué biblioteca compartida mono debería cargar realmente en tiempo de ejecución.

Un archivo .config de ejemplo es:

<configuration>
	<dllmap dll="gtkembedmoz" target="libgtkembedmoz.so" />
</configuration>

BUGS

*
Solo se comprueban las entradas DllImport; el IL circundante se ignora. En consecuencia, si se realiza una comprobación en tiempo de ejecución para elegir qué biblioteca compartida invocar, se informará un error aunque la biblioteca especificada nunca se utilice. Considere este código: 
using System.Runtime.InteropServices; // para DllImport
class Beep {
	[DllImport ("kernel32.dll")]
	private static extern int Beep (int dwFreq, int dwDuration);
	[DllImport ("libcurses.so")]
	private static extern int beep ();
	public static void Beep ()
	{
		if (System.IO.Path.DirectorySeparatorChar == '\\') {
			Beep (750, 300);
		}
		else {
			beep ();
		}
	}
}
Si se ejecuta mono-shlib-cop en este ensamblado, se informará un error por usar kernel32.dll, ¡aunque kernel32.dll nunca se utilizará en plataformas Unix!
*
mono-shlib-cop actualmente solo examina la extensión del archivo de biblioteca compartida para determinar si se debe generar una advertencia. Una extensión .so siempre generará una advertencia, incluso si el .so no es un enlace simbólico, no se proporciona en un paquete -devel y no hay una biblioteca compartida versionada (posibles ejemplos incluyen /usr/lib/libtcl8.4.so, /usr/lib/libubsec.so, etc.).

En consecuencia, las advertencias para cualquiera de estas bibliotecas son inútiles e incorrectas.

Windows y Mac OS X nunca generarán advertencias, ya que estas plataformas utilizan extensiones de biblioteca compartida diferentes.
