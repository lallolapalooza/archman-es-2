mount.davfs(8) Manual del Administrador del Sistema mount.davfs(8)

NOMBRE

mount.davfs - Montar un recurso WebDAV como un sistema de archivos @PACKAGE@

SINOPSIS

mount.davfs [-h | --help] [-V | --version]
mount {dir | servidor_webdav}

SINOPSIS (solo root)

mount -t davfs [-o opción[,...]] servidor_webdav directorio
mount.davfs [-o opción[,...]] servidor_webdav directorio

DESCRIPCIÓN

mount.davfs permite montar el recurso WebDAV identificado por servidor_webdav en el sistema de archivos local en directorio. WebDAV es una extensión de HTTP que permite la autoría remota y colaborativa de recursos Web, definida en RFC 4918. mount.davfs es parte de @PACKAGE@.

@PACKAGE@ permite que los documentos en un servidor Web remoto sean editados usando aplicaciones estándar. Por ejemplo, un sitio Web remoto podría ser actualizado en el lugar usando las mismas herramientas de desarrollo que crearon inicialmente el sitio. O puede usar un recurso WebDAV para documentos a los que desea acceder y editar desde diferentes ubicaciones.

@PACKAGE@ soporta TLS/SSL (si la biblioteca neon lo soporta) y proxies. mount.davfs se ejecuta como un demonio en el espacio de usuario. Se integra en el sistema de archivos virtual a través del sistema de archivos del kernel fuse. Actualmente se soporta FUSE_KERNEL_VERSION 7.

mount.davfs es invocado usualmente por el comando mount(8) al usar la opción -t davfs. Después de montar, se ejecuta como un demonio. Para desmontar se usa el comando umount(8).

servidor_webdav es la URL del servidor. Debe contener al menos el nombre del host. Opcionalmente puede contener el esquema, el puerto y la ruta. Los componentes faltantes se establecen a valores predeterminados sensatos. El componente de ruta no debe estar codificado en %, pero al introducir la URL en la línea de comandos o en /etc/fstab se deben obedecer las reglas de escape del shell o de fstab.

directorio es el punto de montaje donde se monta el recurso WebDAV. Puede ser una ruta absoluta o relativa.

fstab puede ser usado para definir montajes y opciones de montaje como de costumbre. En lugar del dispositivo, se debe proporcionar la URL del servidor WebDAV. No debe haber más de una entrada en fstab por cada punto de montaje.

OPCIONES

-V --version
Muestra la versión.
-h --help
Imprime un mensaje de ayuda.
-o
Una lista separada por comas define las opciones de montaje a usar. Las opciones disponibles son:
[no]auto
Puede (no puede) ser montado con mount -a.
Predeterminado: auto.
comment=algún comentario
Esta opción es ignorada por mount.davfs pero otros programas pueden requerir que esté presente en fstab.
conf=ruta absoluta
Un archivo de configuración de usuario alternativo. Esta opción está pensada para casos donde el archivo de configuración de usuario predeterminado en el directorio personal del usuario no puede ser usado.
Predeterminado: ~/.@PACKAGE@/@CONFIGFILE@
[no]dev
(No) interpretar dispositivos especiales de caracteres o bloques en el sistema de archivos. Esta opción solo se incluye por compatibilidad con el programa mount(8). Siempre se establecerá en nodev.
dir_mode=modo
Los bits de modo predeterminados para los directorios en el sistema de archivos montado. El valor se da en octal. Los bits s (setuid/setgid) para usuario y grupo siempre se ignoran silenciosamente.
Predeterminado: calculado a partir de la umask del usuario que monta; se asocia un bit x a cada bit r en u-g-o.
[no]exec
(No) permitir la ejecución de binarios en el sistema de archivos montado.
Predeterminado: exec. (Al montar como un usuario normal, el programa mount(8) establecerá el valor predeterminado a noexec.)
file_mode=modo
Los bits de modo predeterminados para los archivos en el sistema de archivos montado. El valor se da en octal. Los bits s (setuid/setgid) para usuario y grupo siempre se ignoran silenciosamente.
Predeterminado: calculado a partir de la umask del usuario que monta; no se establecen bits x para los archivos.
gid=grupo
El grupo al que pertenece el sistema de archivos montado. Puede ser un ID numérico o un nombre de grupo. El usuario que monta, si no es root, debe ser miembro de este grupo.
Predeterminado: el grupo principal del usuario que monta.
[no]grpid
Cuando esta opción está establecida, un archivo recién creado tomará el ID de grupo del directorio en el que se crea. Esto también se aplicará a todos los archivos que estén en el servidor y no en la caché local. (Esto se debe a que el ID de grupo no se almacena en el servidor).
Si el ID de grupo del directorio es root, esta opción se ignora.
Predeterminado: nogrpid.
[no]_netdev
El sistema de archivos necesita (no necesita) una conexión de red para funcionar. Esta información permite al sistema operativo manejar el sistema de archivos correctamente al inicio del sistema y cuando la red se apaga.
Predeterminado: _netdev
ro
Montar el sistema de archivos en modo solo lectura.
Predeterminado: rw.
rw
Montar el sistema de archivos en modo lectura-escritura.
Predeterminado: rw.
[no]suid
No permitir que los bits set-user-identifier o set-group-identifier tengan efecto. Esta opción solo se incluye por compatibilidad con el programa mount. Siempre se establecerá en nosuid.
[no]user
(No) permitir que un usuario normal monte el sistema de archivos. El nombre del usuario que monta se escribe en mtab para que pueda desmontar el sistema de archivos de nuevo. La opción user implica las opciones noexec, nosuid y nodev (a menos que se anulen por opciones posteriores). Esta opción solo tiene sentido cuando se establece en fstab.
Predeterminado: no se permite a los usuarios normales montar.
users
Al igual que user, pero cualquier usuario puede desmontar el sistema de archivos, no solo el usuario que lo montó. Esto generalmente no se recomienda. Si la opción user permite a un usuario sin privilegios montar, pero el desmontaje por parte del usuario que montó falla, la opción users puede ser una solución.
Predeterminado: solo se permite al usuario que monta desmontar el sistema de archivos.
uid=usuario
El propietario del sistema de archivos montado. Puede ser un ID numérico o un nombre de usuario. Solo cuando es montado por root, esto puede ser diferente del usuario que monta.
Predeterminado: ID del usuario que monta.
username=usuario_WebDAV
Use este nombre para autenticarse con el servidor WebDAV. Esta opción está pensada solo para su uso con pam_mount. Cuando esta opción está establecida, las credenciales en los archivos de secretos serán ignoradas. La contraseña siempre se leerá de stdin, incluso cuando la opción askauth esté establecida en 0. No la use en fstab. El nombre de usuario será visible para todos en la salida de ps.
Predeterminado: sin nombre de usuario.

POLÍTICA DE SEGURIDAD

mount.davfs necesita privilegios de root para montar. Pero ejecutar un demonio, que está conectado a internet, con privilegios de root es un riesgo de seguridad. Por lo tanto, mount.davfs cambiará su uid y gid al entrar en modo demonio.

Cuando es invocado por root, mount.davfs se ejecutará como el usuario @USER@ y el grupo @GROUP@. Esto puede cambiarse en @SYS_CONF_DIR@/@CONFIGFILE@.

Cuando es invocado por un usuario normal, se ejecutará con el ID de ese usuario y con el grupo @GROUP@.

MOUNTING WITH FSTAB

For ordinary users to be able to mount file systems using mount(8), an entry for the file system must be present in /etc/fstab. This entry must include the special option noauto so that it is not mounted automatically at boot time. It must also include the user or users option, to allow any user to mount it, or only members of the group specified by users to mount it, respectively. Furthermore, the option fscontext must be set for SELinux. This is only a weak guarantee, because the internet connection is not yet established, and the server might be malicious. This increases the risk that malicious content may be included in the file system. So @PROGRAM_NAME@ is slightly more restrictive than mount(8).

Options nosuid and nodev will always be set; even root can not change this.

For ordinary users to be able to mount, they must be member of group @GROUP@ and there must be an entry in fstab.

When the mount point given in fstab is a relative file name and the file system is mounted by an unprivileged user, the mount point must lie within the home directory of the mounting user.

If in fstab option uid and/or gid are given, an ordinary user can only mount, if her uid is the one given in option uid and he belongs to the group given in option gid.

WARNING: If root allows an ordinary user to mount a file system (using fstab) this includes the permission to read the associated credentials from @SYS_CONF_DIR@/@SECRETSFILE@ as well as the private key of the associated client certificate and the mounting user may get access to this information. You should only do this, if you might as well give this information to the user directly.

URLS AND MOUNT POINTS WITH SPACES

Special characters like spaces in pathnames are a mess. They are interpreted differently by different programs and protocols, and there are different rules for escaping.

In fstab spaces must be replaced by a three digit octal escape sequence. Write http://foo.bar/path\040with\040spaces instead of http://foo.bar/path with spaces.

For the @CONFIGFILE@ and the @SECRETSFILE@ files please see the escape and quotation rules described in the @CONFIGFILE@(5) man page.

On command line you must obey the escaping rules of the shell.

CACHING

@PROGRAM_NAME@ tries to reduce HTTP-trafic by caching and reusing data. Information about directories and files are held in memory, while downloaded files are cached on disk.

@PROGRAM_NAME@ needs to hold a local copy of all open files in the cache directory. Please make sure that enough local disk space is available.

@PROGRAM_NAME@ will consider cached information about directories and file attributes valid for a configurable time and look up this information on the server only after this time has expired (or there is other evidence that this information is stale). So if somebody else creates or deletes files on the server it may take some time before the local file system reflects this.

This will not affect the content of files and directory listings. Whenever a file is opened, the server is looked up for a newer version of the file. Please consult the manual @CONFIGFILE@(5) to see how can you configure this according your needs.

LOCKS, LOST UPDATE PROBLEM AND BACKUP FILES

WebDAV introduced locks and @PROGRAM_NAME@ uses them by default. This will in most cases prevent two people from changing the same file in parallel. But not always:

You might have disabled locks in @SYS_CONF_DIR@/@CONFIGFILE@ or ~/.@PACKAGE@/@CONFIGFILE@.

The server might not support locks (they are not mandatory).

A bad connection might prevent @PROGRAM_NAME@ from refreshing the lock in time.

Another WebDAV-client might use your lock (that is not too difficult and might even happen without intention).

@PROGRAM_NAME@ will therefore check if the file has been changed on the the server before it uploads a new version. If it finds it impossible to upload the locally changed file, it will store it in the local backup directory lost+found. You should check this directory from time to time and decide what to do with this files.

Sometimes locks held by some client on the server will not be released. Maybe the client crashes or the network connection fails. When @PROGRAM_NAME@ finds a file locked on the server, it will check whether the lock is held by @PROGRAM_NAME@ and the current user, and if so tries to reuse and release it. But this will not always succeed. So servers should automatically release locks after some time, when they are not refreshed by the client.

WebDAV allows one to lock files that don't exist (to protect the name when a client intends to create a new file). This locks will be displayed as files with size 0 and last modified date of 1970-01-01. If this locks are not released properly @PROGRAM_NAME@ may not be able to access this files. You can use cadaver(1) http://www.webdav.org/cadaver/ to remove this locks.

FILE OWNER AND PERMISSIONS

@PACKAGE@ implements Unix permissions for access control. But changing owner and permissions of a file is only local. It is intended as a means for the owner of the file system, to control whether other local users may access this file system.

The server does not know about this. From the servers point of view there is just one user (identified by the credentials) connected. Another WebDAV-client, connected to the same server, is not affected by this local changes.

There is one exception: The execute bit on files is stored as a property on the sever. You may think of this property as an information about the type of file rather than a permission. Whether the file is executable on the local system is still controlled by mount options and local permissions.

When the file system is unmounted, attributes of cached files (including owner and permissions) are stored in cache, as well as the attributs of the directories they are in. But there is no information stored about directories that do not contain cached files.

FILES

@SYS_CONF_DIR@/@CONFIGFILE@
System wide configuration file.
~/.@PACKAGE@/@CONFIGFILE@
Configuration file in the users home directory.The user configuration takes precedence over the system wide configuration. If it does not exist, @PROGRAM_NAME@ will will create a template file.
@SYS_CONF_DIR@/@SECRETSFILE@
Holds the credentials for WebDAV servers and the proxy, as well as decryption passwords for client certificates. The file must be read-writable by root only.
~/.@PACKAGE@/@SECRETSFILE@
Holds credentials for WebDAV servers and proxy, as well as decryption passwords for client certificates. The file must be read-writable by the owner only. Credentials are first looked up in the home directory of the mounting user. If not found there the system wide secrets file is consulted. If no creditentials and passwords are found they are asked from the user interactively (if not disabled). If the file does not exist, @PROGRAM_NAME@ will will create a template file.
@SYS_CONF_DIR@/@CERTS_DIR@
You may store trusted server certificates here, that can not be verified by use of the system wide CA-Certificates. This is useful when your server uses a selfmade certificate. You must configure the servercert option in @SYS_CONF_DIR@/@CONFIGFILE@ or ~/.@PACKAGE@/@CONFIGFILE@ to use it. Certificates must be in PEM format.
Be sure to verify the certificate.
~/.@PACKAGE@/@CERTS_DIR@
You may store trusted server certificates here, that can not be verified by use of the system wide CA-Certificates. This is useful when your server uses a selfmade certificate. You must configure the servercert option in ~/.@PACKAGE@/@CONFIGFILE@ to use it. Certificates must be in PEM format.
Be sure to verify the certificate.
@SYS_CONF_DIR@/@CERTS_DIR@/@CLICERTS_DIR@
To store client certificates. Certificates must be in PKCS#12 format. You must configure the clientcert option in @SYS_CONF_DIR@/@CONFIGFILE@ or ~/.@PACKAGE@/@CONFIGFILE@ to use it. This directory must be rwx by root only.
~/.@PACKAGE@/@CERTS_DIR@/@CLICERTS_DIR@
To store client certificates. Certificates must be in PKCS#12 format. You must configure the clientcert option in ~/.@PACKAGE@/@CONFIGFILE@ to use it. This directory must be rwx by the owner only.
@SYS_RUN@
PID-files of running mount.davfs processes are stored there. This directory must belong to group @USER@ with write permissions for the group and the sticky-bit set (mode 1775). The PID-files are named after the mount point of the file system.
@SYS_CACHE_DIR@
System wide directory for cached files. Used when the file system is mounted by root. It must belong do group @USER@ and read, write and execute bits for group must be set. There is a subdirectory for every mounted file system. The names of this subdirectories are created from url, mount point and user name.
~/.@PACKAGE@/cache
Cache directory in the mounting users home directory. For every mounted WebDAV resource a subdirectory is created.

@PROGRAM_NAME@ will try to create missing directories, but it will not touch @SYS_CONF_DIR@.

ENVIRONMENT

DAVFS_PASSWORD
If set, this environment variable will be used as the password for WebDAV authentication if no password is specified via the command line option and in preference to anything found in secrets files. This allows for scripted mounting without storing passwords in files or exposing them in command line arguments; especially relevant in the context of CI runners.
https_proxy http_proxy all_proxy
If no proxy is defined in the configuration file the value is taken from this environment variables. The proxy may be giv
en con o sin esquema y con o sin puerto
http_proxy=[http://]foo.bar[:3218]
Solo se usa cuando el usuario que monta es root.
no_proxy
Una lista separada por comas de nombres de dominio a los que se accederá directamente. * coincide con cualquier nombre de dominio. Un nombre de dominio que comience con . (punto) coincide con todos los subdominios.
Solo se usa cuando el usuario que monta es root.
No se aplica cuando el proxy se define en @SYS_CONF_DIR@.

EJEMPLOS

Usuario no root (ej. filomena):

Para permitir que un usuario normal monte, debe haber una entrada en fstab

http://webdav.org/dav /media/dav davfs noauto,user 0 0

Si se debe usar un proxy, esto debe configurarse en @SYS_CONF_DIR@/@CONFIGFILE@

proxy proxy.mycompany.com:8080

Las credenciales se almacenan en /home/filomena/.@PACKAGE@/@SECRETSFILE@

proxy.mycompany.com filomena "mi secreto"
/media/dav nombredeusuario.webdav contraseña

Si tienes habilitada la autenticación de dos factores y puedes proporcionar el token junto con la contraseña en forma de contraseña:token, entonces agrega la cadena '2FA' como cuarto parámetro y se te pedirá el token durante el montaje.

/media/dav nombre-usuario "p@ss\"w0rd" 2FA

Ahora el recurso WebDAV puede ser montado por el usuario filomena invocando

mount /media/dav

y desmontado por el usuario filomena invocando

umount /media/dav

Solo usuario root:

Monta el recurso https://asciigirl.com/webdav en el punto de montaje /mount/site, cifrando todo el tráfico con SSL. Las credenciales para http://webdav.org/dav se buscarán en @SYS_CONF_DIR@/@SECRETSFILE@, si no se encuentran allí se le preguntará al usuario.

mount -t davfs -o uid=otto,gid=users,mode=775 https://asciigirl.com/webdav /mount/site

Monta el recurso http://linux.org.ar/repos en /dav.

mount.davfs -o uid=otto,gid=users,mode=775 http://linux.org.ar/repos/ /dav

ERRORES

@PACKAGE@ no soporta enlaces.

Un sistema de archivos @PACKAGE@ no puede ser movido con mount --move.
