ratón(4) Manual de controladores de dispositivos ratón(4)

NOMBRE

ratón - interfaz de ratón serie

CONFIGURACIÓN

Los ratones serie se conectan a una línea de acceso telefónico serie RS232/V24, véase ttyS(4) para una descripción.

DESCRIPCIÓN

Introducción

La asignación de pines del conector habitual de 9 pines utilizado para ratones serie es:

pin nombre uso
2 RX Datos
3 TX -12 V, Imax = 10 mA
4 DTR +12 V, Imax = 10 mA
7 RTS +12 V, Imax = 10 mA
5 GND Tierra

Esta es la especificación; de hecho, 9 V son suficientes con la mayoría de los ratones.

El controlador del ratón puede reconocer un ratón bajando RTS a bajo y volviéndolo a subir. Unos 14 ms después, el ratón enviará 0x4D ('M') en la línea de datos. Después de otros 63 ms, un ratón de 3 botones compatible con Microsoft enviará 0x33 ('3').

El movimiento relativo del ratón se envía como dx (positivo significa derecha) y dy (positivo significa abajo). Varios ratones pueden funcionar a diferentes velocidades. Para seleccionar velocidades, cicla a través de las velocidades 9600, 4800, 2400 y 1200 bits/s, escribiendo cada vez los dos caracteres de la siguiente tabla y esperando 0.1 segundos. La siguiente tabla muestra las velocidades disponibles y las cadenas que las seleccionan:

bits/s cadena
9600 *q
4800 *p
2400 *o
1200 *n

El primer byte de un paquete de datos puede usarse para fines de sincronización.

Protocolo Microsoft

El protocolo de Microsoft utiliza 1 bit de inicio, 7 bits de datos, sin paridad y un bit de parada a una velocidad de 1200 bits por segundo. Los datos se envían a RxD en paquetes de 3 bytes. Los movimientos dx y dy se envían como complemento a dos; lb (rb) se establecen cuando se presiona el botón izquierdo (derecho):

byte d6 d5 d4 d3 d2 d1 d0
1 1 lb rb dy7 dy6 dx7 dx6
2 0 dx5 dx4 dx3 dx2 dx1 dx0
3 0 dy5 dy4 dy3 dy2 dy1 dy0

Protocolo Microsoft de 3 botones

Los ratones Microsoft originales solo tienen dos botones. Sin embargo, hay algunos ratones de tres botones que también utilizan el protocolo Microsoft. Al presionar o soltar el botón central se informa enviando un paquete con movimiento cero y sin botones presionados. (Por lo tanto, a diferencia de los otros dos botones, el estado del botón central no se informa en cada paquete).

Protocolo Logitech

Los ratones serie de 3 botones Logitech utilizan una extensión diferente del protocolo Microsoft: cuando el botón central está levantado, se envía el paquete de 3 bytes anterior. Cuando el botón central está presionado, se envía un paquete de 4 bytes, donde el cuarto byte tiene el valor 0x20 (o al menos tiene el bit 0x20 establecido). En particular, la pulsación del botón central se informa como 0,0,0,0x20 cuando no hay otros botones activados.

Protocolo Mousesystems

El protocolo de Mousesystems utiliza 1 bit de inicio, 8 bits de datos, sin paridad y dos bits de parada a una velocidad de 1200 bits por segundo. Los datos se envían a RxD en paquetes de 5 bytes. dx se envía como la suma de los dos valores de complemento a dos; dy se envía como la suma negada de los dos valores de complemento a dos. lb (mb, rb) se borran cuando se presiona el botón izquierdo (central, derecho):

byte d7 d6 d5 d4 d3 d2 d1 d0
1 1 0 0 0 0 lb mb rb
2 0 dxa6 dxa5 dxa4 dxa3 dxa2 dxa1 dxa0
3 0 dya6 dya5 dya4 dya3 dya2 dya1 dya0
4 0 dxb6 dxb5 dxb4 dxb3 dxb2 dxb1 dxb0
5 0 dyb6 dyb5 dyb4 dyb3 dyb2 dyb1 dyb0

Los bytes 4 y 5 describen el cambio que ocurrió desde que se transmitieron los bytes 2 y 3.

mouse(4) - Arch Linux man pages

NAME

mouse - mouse interface

DESCRIPTION

This document describes the interface of the Linux kernel mouse driver.

There are several protocols that the mouse driver can recognize. The user can select the protocol using the M_SETPROTO ioctl.

The mouse device is typically opened by a mouse-handling daemon such as gpm(8).

The mouse driver produces 3-byte packets. The first byte indicates the status of the buttons and the sign of the x and y motion. The second and third bytes indicate the magnitude of the x and y motion, respectively.

The first byte:
The least significant bit (bit 0) is 1 if the left button is pressed, 0 otherwise. Bit 1 is 1 if the middle button is pressed, 0 otherwise. Bit 2 is 1 if the right button is pressed, 0 otherwise. Bit 3 is 1 if the x-motion is positive, 0 if it is negative. Bit 4 is 1 if the y-motion is positive, 0 if it is negative. Bits 5, 6, and 7 are unused.
The second byte:
The magnitude of the x-motion. This is a signed quantity, where the sign is determined by bit 3 of the first byte.
The third byte:
The magnitude of the y-motion. This is a signed quantity, where the sign is determined by bit 4 of the first byte.

The magnitude of the motion is in the range of 1 to 127. A value of 0 indicates no motion in that direction.

The following protocols are supported:

PS/2 protocol

This is the default protocol. It uses 1 start bit, 8 data bits, no parity, and 1 stop bit. The speed is 1200 bits/sec.

MM protocol

The MM protocol uses 1 start bit, 8 data bits, odd parity, and one stop bit at the speed of 1200 bits/sec. Data is sent to RxD in 3-byte packets. dx and dy are sent as single signed values, the sign bit indicating a negative value. lb (mb, rb) are set when the left (middle, right) button is pressed:

byte d7 d6 d5 d4 d3 d2 d1 d0
1 1 0 0 dxs dys lb mb rb
2 0 dx6 dx5 dx4 dx3 dx2 dx1 dx0
3 0 dy6 dy5 dy4 dy3 dy2 dy1 dy0

MS protocol

The MS protocol is identical to the PS/2 protocol, but the mouse is configured to send absolute data.

IMPS/2 protocol

This protocol is similar to the PS/2 protocol, but the mouse reports its movements in larger increments. This is the default protocol for most modern mice.

EXPS/2 protocol

This protocol is similar to the IMPS/2 protocol, but the mouse reports its movements in even larger increments.

LM protocol

The LM protocol uses 1 start bit, 8 data bits, no parity, and 1 stop bit. The speed is 9600 bits/sec. Data is sent to RxD in 3-byte packets:

byte d7 d6 d5 d4 d3 d2 d1 d0
1 1 0 0 dxs dys lb mb rb
2 0 dx6 dx5 dx4 dx3 dx2 dx1 dx0
3 0 dy6 dy5 dy4 dy3 dy2 dy1 dy0

NetScroll protocol

This protocol is used by the NetScroll mouse. It uses 1 start bit, 8 data bits, no parity, and 1 stop bit. The speed is 1200 bits/sec. Data is sent in 4-byte packets.

byte d7 d6 d5 d4 d3 d2 d1 d0
1 1 0 0 dxs dys lb mb rb
2 0 dx6 dx5 dx4 dx3 dx2 dx1 dx0
3 0 dy6 dy5 dy4 dy3 dy2 dy1 dy0
4 0 0 0 0 0 0 0 0

GLUMS protocol

The GLUMS protocol is a 5-byte protocol used by some older mice. The first byte indicates the status of the buttons and the sign of the x and y motion. The second and third bytes indicate the magnitude of the x and y motion, respectively. The fourth and fifth bytes are unused.

The Sun protocol is the 3-byte version of the above 5-byte Mousesystems protocol: the last two bytes are not sent.

MM protocol

The MM protocol uses 1 start bit, 8 data bits, odd parity, and one stop bit at the speed of 1200 bits/sec. Data is sent to RxD in 3-byte packets. dx and dy are sent as single signed values, the sign bit indicating a negative value. lb (mb, rb) are set when the left (middle, right) button is pressed:

byte d7 d6 d5 d4 d3 d2 d1 d0
1 1 0 0 dxs dys lb mb rb
2 0 dx6 dx5 dx4 dx3 dx2 dx1 dx0
3 0 dy6 dy5 dy4 dy3 dy2 dy1 dy0
