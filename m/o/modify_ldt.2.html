modify_ldt(2) Manual de llamadas al sistema modify_ldt(2)

NOMBRE

modify_ldt - obtener o establecer una entrada LDT por proceso

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <asm/ldt.h>         /* Definición de struct user_desc */
#include <sys/syscall.h>     /* Definición de constantes SYS_* */
#include <unistd.h>
int syscall(unsigned long bytecount;
            SYS_modify_ldt, int func, void ptr[bytecount],
            unsigned long bytecount);

Nota: glibc no proporciona un envoltorio para modify_ldt(), lo que hace necesario el uso de syscall(2).

DESCRIPCIÓN

modify_ldt() lee o escribe la tabla de descriptores local (LDT) para un proceso. La LDT es un array de descriptores de segmento a los que puede hacer referencia el código del usuario. Linux permite a los procesos configurar una LDT por proceso (en realidad, por mm). Para más información sobre la LDT, consulte el Manual del Desarrollador de Software de Intel o el Manual de Programación de Arquitectura de AMD.

Cuando func es 0, modify_ldt() lee la LDT en la memoria apuntada por ptr. El número de bytes leídos es el menor entre bytecount y el tamaño real de la LDT, aunque el kernel puede actuar como si la LDT estuviera rellena con bytes adicionales de ceros al final. En caso de éxito, modify_ldt() devolverá el número de bytes leídos.

Cuando func es 1 o 0x11, modify_ldt() modifica la entrada LDT indicada por ptr->entry_number. ptr apunta a una estructura user_desc y bytecount debe ser igual al tamaño de esta estructura.

La estructura user_desc se define en <asm/ldt.h> como:


struct user_desc {
    unsigned int  entry_number;
    unsigned int  base_addr;
    unsigned int  limit;
    unsigned int  seg_32bit:1;
    unsigned int  contents:2;
    unsigned int  read_exec_only:1;
    unsigned int  limit_in_pages:1;
    unsigned int  seg_not_present:1;
    unsigned int  useable:1;
};

En Linux 2.4 y anteriores, esta estructura se llamaba modify_ldt_ldt_s.

El campo contents es el tipo de segmento (datos, datos expansibles hacia abajo, código no conformante o código conformante). Los demás campos coinciden con sus descripciones en el manual de la CPU, aunque modify_ldt() no puede establecer el bit de "accedido" definido por hardware descrito en el manual de la CPU.

Una user_desc se considera "vacía" si read_exec_only y seg_not_present se establecen a 1 y todos los demás campos son 0. Una entrada LDT puede borrarse estableciéndola a una user_desc "vacía" o, si func es 1, estableciendo tanto base como limit a 0.

Un segmento de código conformante (es decir, uno con contents==3) será rechazado si func es 1 o si seg_not_present es 0.

Cuando func es 2, modify_ldt() leerá ceros. Esto parece ser un remanente de Linux 2.4.

VALOR DE RETORNO

En caso de éxito, modify_ldt() devuelve el número real de bytes leídos (para lectura) o 0 (para escritura). En caso de error, modify_ldt() devuelve -1 y establece errno para indicar el error.

ERRORES

EFAULT
ptr apunta fuera del espacio de direcciones.
EINVAL
ptr es 0, o func es 1 y bytecount no es igual al tamaño de la estructura user_desc, o func es 1 o 0x11 y la nueva entrada LDT tiene valores inválidos.
ENOSYS
func no es 0, 1, 2 ni 0x11.

ESTNDARES

Linux.

NOTAS

modify_ldt() no debe usarse para almacenamiento local de hilos, ya que ralentiza los cambios de contexto y solo admite un número limitado de hilos. Las bibliotecas de hilos deben usar set_thread_area(2) o arch_prctl(2) en su lugar, excepto en kernels extremadamente antiguos que no admitan esas llamadas al sistema.

El uso normal para modify_ldt() es ejecutar código heredado de 16 bits o segmentado de 32 bits. Sin embargo, no todos los kernels permiten instalar segmentos de 16 bits.

Incluso en kernels de 64 bits, modify_ldt() no se puede utilizar para crear un segmento de código en modo largo (es decir, de 64 bits). El campo no documentado "lm" en user_desc no es útil y, a pesar de su nombre, no resulta en un segmento en modo largo.

ERRORES DE PROGRAMACIÓN

En kernels de 64 bits anteriores a Linux 3.19, establecer el bit "lm" en user_desc impide que el descriptor se considere vacío. Tenga en cuenta que el bit "lm" no existe en las cabeceras de 32 bits, pero estos kernels defectuosos aún lo notarán incluso cuando se establezca en un proceso de 32 bits.

VER TAMBIÉN

arch_prctl(2), set_thread_area(2), vm86(2)
