NOMBRE

fuse - formato y opciones para los sistemas de archivos fuse

DESCRIPCIÓN

FUSE (Filesystem in Userspace) es una interfaz sencilla para que programas en espacio de usuario exporten un sistema de archivos virtual al kernel de Linux. FUSE también tiene como objetivo proporcionar un método seguro para que los usuarios no privilegiados creen y monten sus propias implementaciones de sistemas de archivos.

CONFIGURACIÓN

Algunas opciones relativas a la política de montaje se pueden establecer en el archivo /etc/fuse.conf. Actualmente, estas opciones son:

mount_max = NNN
Establece el número máximo de montajes FUSE permitidos para usuarios no root. El valor predeterminado es 1000.
user_allow_other
Permite a los usuarios no root especificar las opciones de montaje allow_other o allow_root (ver más abajo).

OPCIONES

La mayoría de las opciones de montaje genéricas descritas en mount son compatibles (ro, rw, suid, nosuid, dev, nodev, exec, noexec, atime, noatime, sync, async, dirsync). Los sistemas de archivos se montan con nodev,nosuid por defecto, lo que solo puede ser anulado por un usuario privilegiado.

Opciones generales de montaje:

Estas son opciones de montaje específicas de FUSE que se pueden especificar para todos los sistemas de archivos:

default_permissions
Por defecto, FUSE no verifica los permisos de acceso a archivos; el sistema de archivos es libre de implementar su política de acceso o dejarla al mecanismo de acceso a archivos subyacente (por ejemplo, en el caso de sistemas de archivos de red). Esta opción habilita la verificación de permisos, restringiendo el acceso según el modo de archivo. Esta opción suele ser útil junto con la opción de montaje allow_other.
allow_other
Esta opción anula la medida de seguridad que restringe el acceso a archivos al usuario que monta el sistema de archivos. Por lo tanto, todos los usuarios (incluido root) pueden acceder a los archivos. Por defecto, esta opción solo está permitida para root, pero esta restricción se puede eliminar con una opción de configuración descrita en la sección anterior.
allow_root
Esta opción es similar a allow_other, pero el acceso a archivos se limita al usuario que monta el sistema de archivos y a root. Esta opción y allow_other son mutuamente excluyentes.
kernel_cache
Esta opción deshabilita el vaciado de la caché del contenido del archivo en cada open(2). Esto solo debe habilitarse en sistemas de archivos donde los datos del archivo nunca se cambian externamente (no a través del sistema de archivos FUSE montado). Por lo tanto, no es adecuado para sistemas de archivos de red y otros sistemas de archivos intermedios.

NOTA: si esta opción no se especifica (y tampoco direct_io), los datos aún se almacenan en caché después de open(2), por lo que una llamada al sistema read(2) no siempre iniciará una operación de lectura.

auto_cache
Esta opción habilita el vaciado automático de la caché de datos en open(2). La caché solo se vaciará si ha cambiado la hora de modificación o el tamaño del archivo.
large_read
Emite solicitudes de lectura grandes. Esto puede mejorar el rendimiento de algunos sistemas de archivos, pero también puede degradarlo. Esta opción solo es útil en kernels 2.4.X, ya que en los kernels 2.6 el tamaño de las solicitudes se determina automáticamente para un rendimiento óptimo.
direct_io
Esta opción deshabilita el uso de la caché de páginas (caché de contenido de archivo) en el kernel para este sistema de archivos. Esto tiene varios efectos:
1.
Cada llamada al sistema read(2) o write(2) iniciará una o más operaciones de lectura o escritura, los datos no se almacenarán en caché en el kernel.
2.
El valor de retorno de las llamadas al sistema read() y write() corresponderá a los valores de retorno de las operaciones de lectura y escritura. Esto es útil, por ejemplo, si el tamaño del archivo no se conoce de antemano (antes de leerlo).
max_read=N
Con esta opción se puede establecer el tamaño máximo de las operaciones de lectura. El valor predeterminado es infinito. Tenga en cuenta que el tamaño de las solicitudes de lectura está limitado de todos modos a 32 páginas (que son 128 kbytes en i386).
max_readahead=N
Establece el número máximo de bytes para prelectura. El valor predeterminado lo determina el kernel. En linux-2.6.22 o anterior es 131072 (128 kbytes)
max_write=N
Establece el número máximo de bytes en una sola operación de escritura. El valor predeterminado es 128 kbytes. Tenga en cuenta que, debido a varias limitaciones, el tamaño de las solicitudes de escritura puede ser mucho menor (4 kbytes). Esta limitación se eliminará en el futuro.
async_read
Realiza lecturas de forma asíncrona. Este es el valor predeterminado.
sync_read
Realiza todas las lecturas (incluso la prelectura) de forma síncrona.
hard_remove
El comportamiento predeterminado es que si se elimina un archivo abierto, el archivo se renombra a un archivo oculto (.fuse_hiddenXXX) y solo se elimina cuando el archivo se libera finalmente. Esto exime a la implementación del sistema de archivos de tener que lidiar con este problema. Esta opción deshabilita el comportamiento de ocultación, y los archivos se eliminan inmediatamente en una operación de unlink (o en una operación de rename que sobrescribe un archivo existente).

Se recomienda no utilizar la opción hard_remove. Cuando se establece hard_remove, las siguientes funciones libc fallan en archivos desvinculados (devolviendo errno de ENOENT): read(2), write(2), fsync(2), close(2), f*xattr(2), ftruncate(2), fstat(2), fchmod(2), fchown(2)

debug
Activa la impresión de información de depuración por parte de la biblioteca.
fsname=NAME
Establece el origen del sistema de archivos (primer campo en /etc/mtab). El valor predeterminado es el nombre del programa de montaje.
subtype=TYPE
Establece el tipo de sistema de archivos (tercer campo en /etc/mtab). El valor predeterminado es el nombre del programa de montaje. Si el kernel lo soporta, /etc/mtab y /proc/mounts mostrarán el tipo de sistema de archivos como fuse.TYPE.

Si el kernel no soporta subtipos, el campo de origen será TYPE#NAME, o si la opción fsname no se especifica, solo será TYPE.

use_ino
Respeta el campo st_ino en las funciones del kernel getattr() y fill_dir(). Este valor se utiliza para rellenar el campo st_ino en las funciones stat(2), lstat(2), fstat(2) y el campo d_ino en la función readdir(2). El sistema de archivos no tiene que garantizar la unicidad, sin embargo, algunas aplicaciones dependen de que este valor sea único para todo el sistema de archivos.
readdir_ino
Si la opción use_ino no se proporciona, intenta igualmente rellenar el campo d_ino en readdir(2). Si el nombre se buscó previamente y todavía está en la caché, se utilizará el número de inodo encontrado allí. De lo contrario, se establecerá en -1. Si se proporciona la opción use_ino, esta opción se ignora.
nonempty
Permite montajes sobre un archivo o directorio no vacío. Por defecto

FALLOS

se rechazan para evitar la cobertura accidental de datos, lo que podría, por ejemplo, impedir las copias de seguridad automáticas.

umask=M
Anula los bits de permisos en st_mode establecidos por el sistema de archivos. Los bits de permisos resultantes son los que faltan en el valor umask dado. El valor se da en representación octal.
uid=N
Anula el campo st_uid establecido por el sistema de archivos (N es numérico).
gid=N
Anula el campo st_gid establecido por el sistema de archivos (N es numérico).
blkdev
Monta un sistema de archivos respaldado por un dispositivo de bloque. Esta es una opción privilegiada. El dispositivo debe especificarse con la opción fsname=NAME.
entry_timeout=T
El tiempo de espera en segundos durante el cual se almacenarán en caché las búsquedas de nombres. El valor predeterminado es 1.0 segundo. Para todas las opciones de tiempo de espera, también es posible dar fracciones de segundo (por ejemplo, entry_timeout=2.8)
negative_timeout=T
El tiempo de espera en segundos durante el cual se almacenará en caché una búsqueda negativa. Esto significa que, si un archivo no existía (la búsqueda devolvió ENOENT), la búsqueda solo se repetirá después del tiempo de espera, y el archivo/directorio se asumirá que no existe hasta entonces. El valor predeterminado es 0.0 segundos, lo que significa que el almacenamiento en caché de búsquedas negativas está deshabilitado.
attr_timeout=T
El tiempo de espera en segundos durante el cual se almacenan en caché los atributos de archivos/directorios. El valor predeterminado es 1.0 segundo.
ac_attr_timeout=T
El tiempo de espera en segundos durante el cual se almacenan en caché los atributos del archivo para el propósito de verificar si auto_cache debe vaciar los datos del archivo al abrir. El valor predeterminado es el valor de attr_timeout.
intr
Permite que las solicitudes sean interrumpidas. Habilitar esta opción puede resultar en un comportamiento inesperado si el sistema de archivos no admite la interrupción de solicitudes.
intr_signal=NUM
Especifica qué número de señal se enviará al sistema de archivos cuando se interrumpa una solicitud. El valor predeterminado está codificado como USR1.
modules=M1[:M2...]
Agrega módulos a la pila del sistema de archivos. Los módulos se insertan en el orden en que se especifican, con el sistema de archivos original en la parte inferior de la pila.

MÓDULOS FUSE (APILAMIENTO)

Los módulos son un soporte de apilamiento de sistemas de archivos para la API de alto nivel. Los módulos de sistemas de archivos se pueden compilar en libfuse o cargar desde un objeto compartido.

iconv

Realiza la conversión del conjunto de caracteres de los nombres de archivo. Las opciones son:

from_code=CHARSET
Conjunto de caracteres desde el cual convertir (ver iconv -l para una lista de valores posibles). El valor predeterminado es UTF-8.
to_code=CHARSET
Conjunto de caracteres al cual convertir. El valor predeterminado se determina por la configuración regional actual.

subdir

Antepone un directorio dado a cada ruta. Las opciones son:

subdir=DIR
Directorio que se antepondrá a todas las rutas. Esta opción es obligatoria.
rellinks
Transforma los enlaces simbólicos absolutos en relativos.
norellinks
No transforma los enlaces simbólicos absolutos en relativos. Este es el valor predeterminado.

SEGURIDAD

El programa fusermount se instala con el conjunto de grupo de usuario a fuse. Esto se hace para permitir que los usuarios del grupo fuse monten sus propias implementaciones de sistemas de archivos. Sin embargo, debe haber algunas limitaciones para evitar que usuarios malintencionados hagan cosas malas. Actualmente, estas limitaciones son:

1.
El usuario solo puede montar en un punto de montaje para el cual tiene permiso de escritura.
2.
El punto de montaje no es un directorio pegajoso que no pertenece al usuario (como suele ser /tmp).
3.
Ningún otro usuario (incluido root) puede acceder al contenido del sistema de archivos montado.

NOTA

Los sistemas de archivos FUSE se desmontan usando el comando fusermount(1) (fusermount -u punto_de_montaje).
