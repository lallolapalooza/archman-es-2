Hashes Disponibles

CRC32: El algoritmo crc32 se utiliza para calcular sumas de verificación. Las dos variantes utilizadas en mhash son: MHASH_CRC32 (similar a la utilizada en ethernet) y MHASH_CRC32B (similar a la utilizada en programas ZIP).

ADLER32: El algoritmo adler32 se utiliza para calcular sumas de verificación. Es más rápido que CRC32 y se considera tan fiable como CRC32. Este algoritmo se define como MHASH_ADLER32.

MD5: El algoritmo MD5 de Ron Rivest y RSA. En mhash este algoritmo se define como MHASH_MD5.

MD4: El algoritmo MD4 de Ron Rivest y RSA. Este algoritmo se considera roto, así que no lo uses. En mhash este algoritmo se define como MHASH_MD4.

SHA1/SHA256: El algoritmo SHA de US. NIST/NSA. Este algoritmo se especifica para su uso en el Estándar de Firma Digital de NIST. En mhash estos algoritmos se definen como MHASH_SHA1 y MHASH_SHA256.

HAVAL: HAVAL es un algoritmo de hash unidireccional con longitud de salida variable. HAVAL es una modificación de MD5. Definido en mhash como: MHASH_HAVAL256, MHASH_HAVAL192, MHASH_HAVAL160, MHASH_HAVAL128.

RIPEMD160: RIPEMD-160 es una función hash criptográfica de 160 bits diseñada por Hans Dobbertin, Antoon Bosselaers y Bart Preneel. Está destinada a ser utilizada como un reemplazo seguro para las funciones hash de 128 bits MD4, MD5 y RIPEMD. MD4 y MD5 fueron desarrollados por Ron Rivest para RSA Data Security, mientras que RIPEMD fue desarrollado en el marco del proyecto de la UE RIPE (RACE Integrity Primitives Evaluation, 1988-1992). En mhash este algoritmo se define como MHASH_RIPEMD160.

TIGER: Tiger es una función hash rápida, de Eli Biham y Ross Anderson. Tiger fue diseñado para ser muy rápido en ordenadores modernos, y en particular en ordenadores de 64 bits de última generación, aunque sigue sin ser más lento que otras funciones hash sugeridas en máquinas de 32 bits. En mhash este algoritmo se define como: MHASH_TIGER, MHASH_TIGER160, MHASH_TIGER128.

GOST: El algoritmo GOST es un estándar ruso y utiliza el algoritmo de cifrado GOST para producir un valor hash de 256 bits. Este algoritmo se especifica para su uso en el Estándar de Firma Digital Ruso. En mhash este algoritmo se define como MHASH_GOST.

Algoritmos de Generación de Claves Disponibles

KEYGEN_MCRYPT: El generador de claves utilizado en mcrypt.

KEYGEN_ASIS: Simplemente devuelve la contraseña como clave binaria.

KEYGEN_HEX: Simplemente convierte una clave hexadecimal en una binaria.

KEYGEN_PKDES: La transformación utilizada en el programa de cifrado DES de Phil Karn.

KEYGEN_S2K_SIMPLE: El S2K Simple de OpenPGP (rfc2440).

KEYGEN_S2K_SALTED: El S2K con Sal de OpenPGP.

KEYGEN_S2K_ISALTED: El S2K Iterado con Sal de OpenPGP.

DESCRIPCIÓN

La biblioteca mhash proporciona una interfaz C fácil de usar para varios algoritmos de hash (también conocidos como algoritmos "unidireccionales"). Estos se pueden usar para crear sumas de verificación, resúmenes de mensajes y más. Actualmente, se admiten MD5, SHA1, GOST, TIGER, RIPE-MD160, HAVAL y varios algoritmos más. mhash admite la generación de HMAC (un mecanismo para la autenticación de mensajes utilizando funciones hash criptográficas, descrito en rfc2104). HMAC se puede utilizar para crear resúmenes de mensajes utilizando una clave secreta, de modo que estos resúmenes de mensajes no puedan ser regenerados (o reemplazados) por otra persona. Se agregó un mecanismo de generación de claves a mhash ya que los algoritmos de generación de claves suelen implicar algoritmos de hash.

FUNCIONES API

Describiremos la API de mhash en detalle ahora. El orden sigue directamente al de la SINOPSIS.

size_t mhash_count(void);
Esto devuelve el "hashid" del último hash disponible. Los hashes se numeran de 0 a "mhash_count()".
size_t mhash_get_block_size(hashid type);
Si type existe, esto devuelve el tamaño de bloque utilizado del hash type en bytes. De lo contrario, devuelve 0.
char *mhash_get_hash_name(hashid type);
Si type existe, esto devuelve el nombre del hash type. De lo contrario, se devuelve un puntero "NULL". La cadena se asigna con malloc(3) por separado, así que no olvides liberarla con free(3).
const char *mhash_get_hash_name_static(hashid type);
Si type existe, esto devuelve el nombre del hash type. De lo contrario, se devuelve un puntero "NULL".
size_t mhash_get_hash_pblock(hashid type);
Devuelve el tamaño de bloque con el que opera el algoritmo. Esto se usa en mhash_hmac_init. Si el valor de retorno es 0, no deberías usar ese algoritmo en HMAC.
hashid mhash_get_mhash_algo(MHASH src);
Devuelve el algoritmo utilizado en el estado de src.
MHASH mhash_init(hashid type);
Esto configura un contexto para comenzar a hashear usando el algoritmo type. Devuelve un descriptor para ese contexto, lo que resultará en fugas de memoria si no llamas a mhash_deinit(3) después. Devuelve "MHASH_FAILED" en caso de fallo.
MHASH mhash_hmac_init(const hashid type, void *key, int keysize, int block);
Esto configura un contexto para comenzar a hashear usando el tipo de algoritmo en modo HMAC. key debe ser un puntero a la clave y keysize su longitud. El block es el tamaño de bloque (en bytes) con el que opera el algoritmo. Debería obtenerse con mhash_get_hash_pblock(). Si es 0, por defecto es 64. Después de llamarla, deberías usar mhash() para actualizar el contexto. Devuelve un descriptor para ese contexto, lo que resultará en fugas de memoria si no llamas a mhash_hmac_deinit(3) después. Devuelve "MHASH_FAILED" en caso de fallo.
MHASH mhash_cp(MHASH src);
Esto configura un nuevo contexto utilizando el estado de src.
int mhash(MHASH thread, const void *plaintext, size_t size);
Esto actualiza el contexto descrito por thread con plaintext. size es la longitud de plaintext, que puede ser datos binarios.
int mhash_save_state_mem( MHASH thread, void *mem, int* mem_size);
