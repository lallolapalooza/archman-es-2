MARIADB-CHECK(1) Sistema de bases de datos MariaDB MARIADB-CHECK(1)

NOMBRE

mariadb-check - un programa de mantenimiento de tablas (mariadb-check es ahora un enlace simbólico a mariadb-check)

SINOPSIS

mariadb-check [opciones] [nombre_bd [nombre_tabla ...]]

DESCRIPCIÓN

El cliente mariadb-check realiza el mantenimiento de tablas: comprueba, repara, optimiza o analiza tablas.

Cada tabla se bloquea y, por lo tanto, no está disponible para otras sesiones mientras se procesa, aunque para las operaciones de comprobación, la tabla se bloquea solo con un bloqueo de LECTURA. Las operaciones de mantenimiento de tablas pueden consumir mucho tiempo, especialmente para tablas grandes. Si utiliza la opción --databases o --all-databases para procesar todas las tablas en una o más bases de datos, una invocación de mariadb-check podría tardar mucho tiempo. (Esto también es cierto para mariadb-upgrade porque ese programa invoca a mariadb-check para comprobar todas las tablas y repararlas si es necesario).

mariadb-check es similar en función a myisamchk, pero funciona de manera diferente. La principal diferencia operativa es que mariadb-check debe usarse cuando el servidor mariadbd está en ejecución, mientras que myisamchk debe usarse cuando no lo está. El beneficio de usar mariadb-check es que no tiene que detener el servidor para realizar el mantenimiento de tablas.

mariadb-check utiliza las sentencias SQL CHECK TABLE, REPAIR TABLE, ANALYZE TABLE y OPTIMIZE TABLE de una manera conveniente para el usuario. Determina qué sentencias usar para la operación que desea realizar y luego envía las sentencias al servidor para que se ejecuten.

El motor de almacenamiento MyISAM soporta las cuatro operaciones de mantenimiento, por lo que mariadb-check se puede utilizar para realizar cualquiera de ellas en tablas MyISAM. Otros motores de almacenamiento no necesariamente soportan todas las operaciones. En tales casos, se mostrará un mensaje de error. Por ejemplo, si test.t es una tabla MEMORY, un intento de comprobarla produce este resultado:

shell> mariadb-check test t
test.t
nota     : El motor de almacenamiento para la tabla no soporta la comprobación

Si mariadb-check no puede reparar una tabla, consulte la Base de Conocimiento de MariaDB para estrategias manuales de reparación de tablas. Este será el caso, por ejemplo, para tablas InnoDB, que se pueden comprobar con CHECK TABLE, pero no reparar con REPAIR TABLE.

No se admite el uso de mariadb-check con tablas particionadas.


Precaución

Es mejor hacer una copia de seguridad de una tabla antes de realizar una operación de reparación de tablas; bajo algunas circunstancias la operación podría causar pérdida de datos. Las causas posibles incluyen, entre otras, errores del sistema de archivos.

Hay tres formas generales de invocar mariadb-check:

shell> mariadb-check [opciones] nombre_bd [nombre_tabla ...]
shell> mariadb-check [opciones] --databases nombre_bd ...
shell> mariadb-check [opciones] --all-databases

Si no nombra ninguna tabla después de nombre_bd o si utiliza la opción --databases o --all-databases, se comprobarán bases de datos enteras.

mariadb-check tiene una característica especial en comparación con otros programas cliente. El comportamiento predeterminado de comprobar tablas (--check) se puede cambiar renombrando el binario. Si desea tener una herramienta que repare tablas por defecto, simplemente haga una copia de mariadb-check llamada mariadb-repair, o cree un enlace simbólico a mariadb-check llamado mariadb-repair. Si invoca mariadb-repair, repara tablas.

Los siguientes nombres se pueden usar para cambiar el comportamiento predeterminado de mariadb-check.

mariadb-repair La opción predeterminada es --repair
mysqlanalyze La opción predeterminada es --analyze
mysqloptimize La opción predeterminada es --optimize

mariadb-check soporta las siguientes opciones, que se pueden especificar en la línea de comandos o en los grupos de archivos de opciones [mariadb-check] y [client]. Las opciones -c, -r, -a y -o son exclusivas entre sí.

•--help, -?

Muestra un mensaje de ayuda y sale.

•--all-databases, -A

Comprueba todas las tablas en todas las bases de datos. Esto es lo mismo que usar la opción --databases y nombrar todas las bases de datos en la línea de comandos.

•--all-in-1, -1

En lugar de emitir una sentencia para cada tabla, ejecuta una única sentencia para cada base de datos que nombra todas las tablas de esa base de datos a procesar.

•--analyze, -a

Analiza las tablas.

•--auto-repair

Si una tabla comprobada está corrupta, la corrige automáticamente. Las reparaciones necesarias se realizan después de que todas las tablas hayan sido comprobadas.

•--character-sets-dir=ruta

El directorio donde están instalados los conjuntos de caracteres.

•--check, -c

Comprueba las tablas en busca de errores. Esta es la operación predeterminada.

•--check-only-changed, -C

Comprueba solo las tablas que han cambiado desde la última comprobación o que no se han cerrado correctamente.

•--check-upgrade, -g

Invoca CHECK TABLE con la opción FOR UPGRADE para comprobar si las tablas son incompatibles con la versión actual del servidor. Esta opción habilita automáticamente las opciones --fix-db-names y --fix-table-names.

•--compress

Comprime toda la información enviada entre el cliente y el servidor si ambos soportan la compresión.

•--databases, -B

Procesa todas las tablas en las bases de datos nombradas. Normalmente, mariadb-check trata el primer argumento de nombre en la línea de comandos como un nombre de base de datos y los nombres siguientes como nombres de tabla. Con esta opción, trata todos los argumentos de nombre como nombres de base de datos.

•--debug[=opciones_depuracion], -# [opciones_depuracion]

Escribe un registro de depuración. Una cadena típica de opciones_depuracion es 'd:t:o,nombre_archivo'. El valor predeterminado es 'd:t:o'.

•--debug-check

Imprime información de depuración cuando el programa sale.

•--debug-info

Imprime información de depuración y estadísticas de uso de memoria y CPU cuando el programa sale.

•--default-auth=nombre

Plugin cliente de autenticación predeterminado a usar.

•--default-character-set=nombre_conjunto_caracteres

Usa nombre_conjunto_caracteres como el conjunto de caracteres predeterminado.

•--defaults-extra-file=nombre_archivo

Establece nombre_archivo como el archivo del que leer opciones predeterminadas después de que se hayan leído los archivos de opciones globales. Debe especificarse como la primera opción.

•--defaults-file=nombre_archivo

Establece nombre_archivo como el archivo del que leer opciones predeterminadas, reemplazando los archivos de opciones globales. Debe especificarse como la primera opción.

•--extended, -e

Si estás usando esta opción para comprobar tablas, asegura que son 100% consistentes pero lleva mucho tiempo.

Si estás usando esta opción para reparar tablas, forzará el uso del método antiguo y lento de reparación con keycache, en lugar de la reparación mucho más rápida por ordenación.

•--fast, -F

Comprueba solo las tablas que no se han cerrado correctamente.

•--fix-db-names

Convierte los nombres de base de datos al formato utilizado desde MySQL 5.1. Solo se ven afectados los nombres de base de datos que contienen caracteres especiales.

•--fix-table-names

Convierte los nombres de tabla (incluidas las vistas) al formato utilizado desde MySQL 5.1. Solo se ven afectados los nombres de tabla que contienen caracteres especiales.

•--flush,

Descarga cada tabla después de comprobarla.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

•--compress, -C

Comprimir todas las informaciones enviadas al servidor.

•--compress-protocol=protocol


Protocolo a utilizar para la conexión con el servidor.

•--compress-uds

Utilizar el protocolo compress-uds.

•--database=db_name, -B db_name

Especifique las bases de datos que desea comprobar. Por defecto, mariadb-check comprueba todas las bases de datos.

•--debug[=debug_options], -# debug_options

Permite a los usuarios que han compilado MariaDB con las opciones de depuración habilitadas registrar información de depuración en un archivo.

•--default-auth=method


Use the specified authentication plugin.

•--defaults-extra-file=file_name

Leer opciones adicionales del archivo especificado. Este debe ser el primer argumento de línea de comandos.

•--defaults-file=file_name

Usar sólo el archivo especificado de opciones. Este debe ser el primer argumento de línea de comandos.

•--disable-local-infile, --skip-disable-local-infile

Desactivar la carga local de archivos.

•--enable-local-infile, --skip-enable-local-infile

Permitir la carga local de archivos.

•--extended, -e

Realiza una comprobación que es más lenta que la opción --quick. Esta opción escanea las filas y es una forma muy buena de detectar tablas fragmentadas.

•--fast, -F

Equivalente a --force.

•--flush, -F

Invalidar las cachés de tablas de todas las bases de datos en el servidor. Esto es útil si no desea que las tablas comprobadas ocupen espacio en las cachés después de la comprobación.

•--force, -f

Continuar incluso si ocurre un error de SQL.

•--host=host_name, -h host_name

Conectar al servidor MariaDB en el host proporcionado.

•--medium-check, -m

Realiza una comprobación más rápida que la operación --extended. Esto encuentra solo el 99.99% de todos los errores, lo que debería ser suficiente en la mayoría de los casos.

•--no-defaults

No leer las opciones predeterminadas de ningún archivo de opciones. Esto debe proporcionarse como primer argumento.

•--optimize, -o

Optimizar las tablas.

•--password[=password], -p[password]

La contraseña a utilizar al conectarse al servidor. Si utiliza la forma corta de la opción (-p), no puede haber un espacio entre la opción y la contraseña. Si omite el valor de password después de la opción --password o -p en la línea de comandos, mariadb-check le pedirá una.

Especificar una contraseña en la línea de comandos debe considerarse inseguro. Puede utilizar un archivo de opciones para evitar proporcionar la contraseña en la línea de comandos.

•--persistent, -Z

Se utiliza con ANALYZE TABLE para añadir la opción PERSISTENT FOR ALL.

•--pipe, -W

En Windows, conectar al servidor a través de una tubería con nombre. Esta opción solo se aplica si el servidor admite conexiones por tubería con nombre.

•--plugin-dir=name


Directorio para plugins del lado del cliente.

•--port=port_num, -P port_num

El número de puerto TCP/IP a utilizar para la conexión. Fuerza --protocol=tcp cuando se especifica en la línea de comandos sin otras propiedades de conexión.

•--print-defaults

Imprimir la lista de argumentos del programa y salir. Esto debe proporcionarse como primer argumento.

•--process-tables

Realizar la operación solicitada en las tablas. Predeterminado a activado; usar --skip-process-tables para deshabilitar.

•--process-views=val

Realizar la operación solicitada (solo CHECK VIEW o REPAIR VIEW). Los valores posibles son NO, YES (corregir la suma de verificación, si es necesario, añadir el campo mariadb-version), UPGRADE_FROM_MYSQL (igual que YES y alternar el algoritmo MERGE<->TEMPTABLE.

•--protocol={TCP|SOCKET|PIPE|MEMORY}

El protocolo de conexión a utilizar para conectarse al servidor. Es útil cuando los otros parámetros de conexión normalmente causarían que se utilice un protocolo diferente al deseado.

•--quick, -q

Si está utilizando esta opción para comprobar tablas, evita que la comprobación escanee las filas para detectar enlaces incorrectos. Este es el método de comprobación más rápido.

Si está utilizando esta opción para reparar tablas, intenta reparar solo el árbol de índices. Este es el método de reparación más rápido.

•--repair, -r

Realiza una reparación que puede arreglar casi todo excepto claves únicas que no son únicas.

•--silent, -s

Modo silencioso. Imprimir solo mensajes de error.

•--skip-database=db_name

No procesar la base de datos (sensible a mayúsculas y minúsculas) especificada como argumento.

•--socket=path, -S path

Para conexiones a localhost, el archivo de socket Unix a utilizar, o, en Windows, el nombre de la tubería con nombre a utilizar. Fuerza --protocol=socket cuando se especifica en la línea de comandos sin otras propiedades de conexión; en Windows, fuerza --protocol=pipe.

•--ssl

Habilitar SSL para la conexión (habilitado automáticamente con otras opciones). Deshabilitar con --skip-ssl.

•--ssl-ca=name

Archivo CA en formato PEM (consultar la documentación de OpenSSL, implica --ssl).

•--ssl-capath=name

Directorio CA (consultar la documentación de OpenSSL, implica --ssl).

•--ssl-cert=name

Certificado X509 en formato PEM (consultar la documentación de OpenSSL, implica --ssl).

•--ssl-cipher=name

Cifrado SSL a utilizar (consultar la documentación de OpenSSL, implica --ssl).

•--ssl-key=name

Clave X509 en formato PEM (consultar la documentación de OpenSSL, implica --ssl).

•--ssl-crl=name

Lista de revocación de certificados (consultar la documentación de OpenSSL, implica --ssl).

•--ssl-crlpath=name

Ruta de la lista de revocación de certificados (consultar la documentación de OpenSSL, implica --ssl).

•--ssl-verify-server-cert

Verificar el "Common Name" del servidor en su certificado contra el nombre de host utilizado al conectarse. Esta opción está deshabilitada por defecto.

•--tables

Anular la opción --databases o -B. Todos los nombres de argumento que siguen a la opción se consideran nombres de tabla.

•--use-frm

Para operaciones de reparación en tablas MyISAM, obtener la estructura de la tabla del archivo .frm para que la tabla pueda ser reparada incluso si la cabecera .MYI está corrupta.

•--user=user_name, -u user_name

El nombre de usuario de MariaDB a utilizar al conectarse al servidor.

•--verbose, -v

Modo detallado. Imprimir información sobre las diversas etapas de la operación del programa. Usar una opción --verbose te dará más información sobre lo que está haciendo mariadb-check.

Usar dos opciones --verbose también te dará información de conexión.

Usarla 3 veces imprimirá todos los CHECK, RENAME y ALTER TABLE durante la fase de comprobación.

•--version, -V

Mostrar información de versión y salir.

•--write-binlog

Esta opción está habilitada por defecto, de modo que las sentencias ANALYZE TABLE, OPTIMIZE TABLE y REPAIR TABLE generadas por mariadb-check se escriben en el log binario. Usar --skip-write-binlog para que NO_WRITE_TO_BINLOG se añada a las sentencias para que no se registren. Usar --skip-write-binlog cuando estas sentencias no deban ser enviadas a esclavos de replicación o ejecutadas al usar los logs binarios para la recuperación a partir de copias de seguridad.
