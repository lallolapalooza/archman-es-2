MARIADBD-MULTI(1) Sistema de bases de datos MariaDB MARIADBD-MULTI(1)

NOMBRE

mariadbd-multi - administrar múltiples servidores MariaDB (mariadbd-multi es ahora un enlace simbólico a mysqld_multi)

SINOPSIS

mariadbd-multi [opciones] {start|stop|report} [GNR[,GNR] ...]

DESCRIPCIÓN

mariadbd-multi está diseñado para administrar varios procesos mariadbd que escuchan conexiones en diferentes archivos de socket Unix y puertos TCP/IP. Puede iniciar o detener servidores, o informar su estado actual.

mariadbd-multi busca grupos llamados [mariadbdN] en my.cnf (o en el archivo especificado por la opción --config-file). N puede ser cualquier número entero positivo. Este número se conoce en la siguiente discusión como el número de grupo de opciones, o GNR. Los números de grupo distinguen los grupos de opciones entre sí y se utilizan como argumentos para mariadbd-multi para especificar qué servidores desea iniciar, detener u obtener un informe de estado. Las opciones listadas en estos grupos son las mismas que usaría en el grupo [mariadbd] utilizado para iniciar mariadbd. Sin embargo, al usar múltiples servidores, es necesario que cada uno use su propio valor para opciones como el archivo de socket Unix y el número de puerto TCP/IP.

Para invocar mariadbd-multi, use la siguiente sintaxis:

shell> mariadbd-multi [opciones] {start|stop|report} [GNR[,GNR] ...]

start, stop, y report indican qué operación realizar. Puede realizar la operación designada para un solo servidor o múltiples servidores, dependiendo de la lista GNR que sigue al nombre de la opción. Si no hay lista, mariadbd-multi realiza la operación para todos los servidores en el archivo de opciones.

Cada valor GNR representa un número de grupo de opciones o un rango de números de grupo. El valor debe ser el número al final del nombre del grupo en el archivo de opciones. Por ejemplo, el GNR para un grupo llamado [mariadbd17] es 17. Para especificar un rango de números, separe el primer y el último número con un guión. El valor GNR 10-13 representa los grupos [mariadbd10] a [mariadbd13]. Se pueden especificar múltiples grupos o rangos de grupos en la línea de comandos, separados por comas. No debe haber espacios en blanco (espacios o tabulaciones) en la lista GNR; cualquier cosa después de un espacio en blanco se ignora.

Este comando inicia un único servidor utilizando el grupo de opciones [mariadbd17]:

shell> mariadbd-multi start 17

Este comando detiene varios servidores, utilizando los grupos de opciones [mariadbd8] y [mariadbd10] a [mariadbd13]:

shell> mariadbd-multi stop 8,10-13

Para ver un ejemplo de cómo configurar un archivo de opciones, use este comando:

shell> mariadbd-multi --example

mariadbd-multi busca archivos de opciones en las siguientes ubicaciones:

•Con --no-defaults, no se leen archivos de opciones.
•Con --defaults-file=nombre_archivo, solo se lee el archivo nombrado.
•De lo contrario, se leen los archivos de opciones en la lista estándar de ubicaciones, incluido cualquier archivo nombrado por la opción --defaults-extra-file=nombre_archivo, si se proporciona. (Si la opción se da varias veces, se usa el último valor).

Los archivos de opciones leídos buscan los grupos de opciones [mariadbd-multi] y [mariadbdN]. El grupo [mariadbd-multi] puede usarse para opciones de mariadbd-multi. Los grupos [mariadbdN] pueden usarse para opciones pasadas a instancias específicas de mariadbd.

Los grupos [mariadbd] o [mariadbd_safe] pueden usarse para opciones comunes leídas por todas las instancias de mariadbd o mariadbd_safe. Puede especificar una opción --defaults-file=nombre_archivo para usar un archivo de configuración diferente para esa instancia, en cuyo caso los grupos [mariadbd] o [mariadbd_safe] de ese archivo se usarán para esa instancia.

mariadbd-multi admite las siguientes opciones.

•--help

Muestra un mensaje de ayuda y sale.

•--example

Muestra un archivo de opciones de ejemplo.

•--log=nombre_archivo

Especifica el nombre del archivo de registro. Si el archivo existe, la salida del registro se añade al final.

•--mariadb-admin=nombre_programa

El binario mariadb-admin a utilizar para detener servidores.

•--mariadbd=nombre_programa

El binario mariadbd a utilizar. Tenga en cuenta que también puede especificar mariadbd_safe como valor para esta opción. Si usa mariadbd_safe para iniciar el servidor, puede incluir las opciones mariadbd o ledir en el grupo de opciones [mariadbdN] correspondiente. Estas opciones indican el nombre del servidor que mariadbd_safe debe iniciar y la ruta del directorio donde se encuentra el servidor. (Ver las descripciones de estas opciones en mariadbd_safe(1).) Ejemplo:

[mariadbd38]
mariadbd = mariadbd-debug
ledir  = /opt/local/mysql/libexec
•--no-log

Imprime la información de registro en stdout en lugar de en el archivo de registro. Por defecto, la salida va al archivo de registro.

•--password=contraseña

La contraseña de la cuenta MariaDB a usar al invocar mariadb-admin. Tenga en cuenta que el valor de la contraseña no es opcional para esta opción, a diferencia de otros programas de MariaDB.

•--silent

Modo silencioso; desactiva las advertencias.

•--tcp-ip

Conéctese a los servidores MariaDB a través del puerto TCP/IP en lugar del socket UNIX. Esto afecta la detención y el reporte. Si falta un archivo de socket, el servidor aún puede estar en ejecución, pero solo se puede acceder a él a través del puerto TCP/IP. Por defecto, la conexión se realiza a través del socket UNIX. Esta opción afecta las operaciones de detención y reporte.

•--user=nombre_usuario

El nombre de usuario de la cuenta MariaDB a usar al invocar mariadb-admin.

•--verbose

Sea más verboso.

•--version

Muestra información de la versión y sale.

•--wsrep-new-cluster

Inicia un clúster.

Algunas notas sobre mariadbd-multi:

•Lo más importante: Antes de usar mariadbd-multi, asegúrese de comprender el significado de las opciones que se pasan a los servidores mariadbd y por qué querría tener procesos mariadbd separados. Tenga cuidado con los peligros de usar múltiples servidores mariadbd con el mismo directorio de datos. Use directorios de datos separados, a menos que sepa lo que está haciendo. Iniciar múltiples servidores con el mismo directorio de datos no le da rendimiento adicional en un sistema con hilos.
•Importante: Asegúrese de que el directorio de datos de cada servidor sea completamente accesible para la cuenta Unix con la que se inicia el proceso mariadbd específico. No use la cuenta root de Unix para esto, a menos que sepa lo que está haciendo.
•Asegúrese de que la cuenta MariaDB utilizada para detener los servidores mariadbd (con el programa mariadbadmin) tenga el mismo nombre de usuario y contraseña para cada servidor. Además, asegúrese de que la cuenta tenga el privilegio SHUTDOWN. Si los servidores que desea administrar tienen diferentes nombres de usuario o contraseñas para las cuentas administrativas, es posible que desee crear una cuenta en cada servidor que tenga el mismo nombre de usuario y contraseña. Por ejemplo, podría configurar una cuenta multi_admin común ejecutando los siguientes comandos para cada servidor: 
shell> mariadb -u root -S /tmp/mariadb.sock -p
Enter password:
mariadb> GRANT SHUTDOWN ON *.*
    -> TO 'multi_admin'@'localhost' IDENTIFIED BY 'multipass';

Cambie los parámetros de conexión apropiadamente al conectarse a cada uno. Tenga en cuenta que la parte del nombre de host del nombre de la cuenta debe permitirle conectarse como multi_admin desde el host donde desea ejecutar mariadbd-multi.

•El archivo de socket Unix y el número de puerto TCP/IP deben ser diferentes para cada mariadbd. (Alternativamente, si
el host tiene varias direcciones de red, puede usar --bind-address para que diferentes servidores escuchen en diferentes interfaces.)
•La opción --pid-file es muy importante si está usando mariadbd-safe para iniciar mariadbd (por ejemplo, --mariadbd=mariadbd-safe) Cada mariadbd debe tener su propio archivo de identificador de proceso. La ventaja de usar mariadbd-safe en lugar de mariadbd es que mariadbd-safe supervisa su proceso mariadbd y lo reinicia si el proceso termina debido a una señal enviada usando kill -9 o por otras razones, como un fallo de segmentación. Tenga en cuenta que el script mariadbd-safe podría requerir que lo inicie desde un lugar específico. Esto significa que es posible que tenga que cambiar de directorio a uno específico antes de ejecutar mariadbd-multi. Si tiene problemas para iniciarlo, consulte el script mariadbd-safe. Verifique especialmente las líneas: 
----------------------------------------------------------------
MY_PWD=`pwd`
# Comprobar si estamos iniciando esto de forma relativa (para la versión binaria)
if test -d $MY_PWD/data/mariadb -a \
   -f ./share/mariadb/english/errmsg.sys -a \
   -x ./bin/mariadbd
----------------------------------------------------------------

La prueba realizada por estas líneas debe ser exitosa, o podría encontrar problemas. Consulte mariadbd-safe(1).

•Es posible que desee utilizar la opción --user para mariadbd, pero para hacerlo necesita ejecutar el script mariadbd-multi como el usuario root de Unix. Tener la opción en el archivo de opciones no importa; solo recibirá una advertencia si no es el superusuario y los procesos mariadbd se inician bajo su propia cuenta de Unix.

El siguiente ejemplo muestra cómo podría configurar un archivo de opciones para usar con mariadbd-multi. El orden en que se inician o detienen los programas mariadbd depende del orden en que aparecen en el archivo de opciones. Los números de grupo no necesitan formar una secuencia ininterrumpida. Los primeros y quintos grupos [mariadbdN] se omitieron intencionalmente del ejemplo para ilustrar que puede haber "huecos" en el archivo de opciones. Esto le da más flexibilidad.

# Este archivo probablemente debería estar en su directorio de inicio (~/.my.cnf)
# o /etc/my.cnf
# Versión 2.1 por Jani Tolonen
[mariadbd-multi]
mariadbd     = /usr/local/bin/mariadbd-safe
mariadb-admin = /usr/local/bin/mariadb-admin
user       = multi_admin
password   = multipass
[mariadbd2]
socket     = /tmp/mariadb.sock2
port       = 3307
pid-file   = /usr/local/mysql/var2/hostname.pid2
datadir    = /usr/local/mysql/var2
language   = /usr/local/share/mariadb/english
user       = john
[mariadbd3]
socket     = /tmp/mysql.sock3
port       = 3308
pid-file   = /usr/local/mysql/var3/hostname.pid3
datadir    = /usr/local/mysql/var3
language   = /usr/local/share/mariadb/swedish
user       = monty
[mariadbd4]
socket     = /tmp/mysql.sock4
port       = 3309
pid-file   = /usr/local/mysql/var4/hostname.pid4
datadir    = /usr/local/mysql/var4
language   = /usr/local/share/mariadb/estonia
user       = tonu
[mariadbd6]
socket     = /tmp/mysql.sock6
port       = 3311
pid-file   = /usr/local/mysql/var6/hostname.pid6
datadir    = /usr/local/mysql/var6
language   = /usr/local/share/mariadb/japanese
user       = jani
