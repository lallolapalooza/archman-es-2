MARIADBD-SAFE(1) Sistema de Base de Datos MariaDB MARIADBD-SAFE(1)

NOMBRE

mariadbd-safe - script de inicio del servidor MariaDB (mariadbd-safe es ahora un enlace simbólico a mariadbd-safe)

SINOPSIS

mariadbd-safe opciones

DESCRIPCIÓN

mariadbd-safe es la forma recomendada de iniciar un servidor mariadbd en Unix. mariadbd-safe añade algunas características de seguridad, como reiniciar el servidor cuando ocurre un error y registrar la información de tiempo de ejecución en un archivo de registro de errores. Las descripciones del registro de errores se dan más adelante en esta sección.

mariadbd-safe intenta iniciar un ejecutable llamado mariadbd. Para anular el comportamiento predeterminado y especificar explícitamente el nombre del servidor que desea ejecutar, especifique una opción --mariadbd o --mariadbd-version para mariadbd-safe. También puede usar --ledir para indicar el directorio donde mariadbd-safe debe buscar el servidor.

Muchas de las opciones de mariadbd-safe son las mismas que las opciones de mariadbd.

Las opciones desconocidas para mariadbd-safe se pasan a mariadbd si se especifican en la línea de comandos, pero se ignoran si se especifican en los grupos [mariadbd-safe] o [mariadbd_safe] de un archivo de opciones.

mariadbd-safe lee todas las opciones de las secciones [mariadbd], [server], [mariadbd-safe] y [mariadbd_safe] en los archivos de opciones. Por ejemplo, si especifica una sección [mariadbd] como esta, mariadbd-safe encontrará y usará la opción --log-error:

[mariadbd]
log-error=error.log

Para compatibilidad con versiones anteriores, mariadbd-safe también lee las secciones [safe_mariadbd], aunque debería renombrar dichas secciones a [mariadbd-safe] en las instalaciones actuales.

mariadbd-safe admite las opciones de la siguiente lista. También lee archivos de opciones y admite las opciones para procesarlos.

•--help

Muestra un mensaje de ayuda y sale.

•--basedir=ruta

La ruta al directorio de instalación de MariaDB.

•--core-file-size=tamaño

El tamaño del archivo core que mariadbd debería poder crear. El valor de la opción se pasa a ulimit -c.

•--crash-script=archivo

Script a llamar en caso de que mariadbd falle.

•--datadir=ruta

La ruta al directorio de datos.

•--defaults-extra-file=ruta

El nombre de un archivo de opciones que se leerá además de los archivos de opciones habituales. Esta debe ser la primera opción en la línea de comandos si se usa. Si el archivo no existe o no es accesible por alguna otra razón, el servidor saldrá con un error.

•--defaults-file=nombre_archivo

El nombre de un archivo de opciones que se leerá en lugar de los archivos de opciones habituales. Esta debe ser la primera opción en la línea de comandos si se usa.

•--flush-caches

Vacía y purga búferes/cachés antes de iniciar el servidor.

•--ledir=ruta

Si mariadbd-safe no puede encontrar el servidor, use esta opción para indicar la ruta al directorio donde se encuentra el servidor.

•--log-error=nombre_archivo

Escribe el registro de errores en el archivo dado.

•--malloc-lib=lib

Carga previamente la biblioteca compartida lib si está disponible.

•--mariadbd=nombre_prog

El nombre del programa del servidor (en el directorio ledir) que desea iniciar. Esta opción es necesaria si utiliza la distribución binaria de MariaDB pero tiene el directorio de datos fuera de la distribución binaria. Si mariadbd-safe no puede encontrar el servidor, use la opción --ledir para indicar la ruta al directorio donde se encuentra el servidor.

•--mariadbd-version=sufijo

Esta opción es similar a la opción --mariadbd, pero usted especifica solo el sufijo para el nombre del programa del servidor. Se asume que el nombre base es mariadbd. Por ejemplo, si usa --mariadbd-version=debug, mariadbd-safe inicia el programa mariadbd-debug en el directorio ledir. Si el argumento para --mariadbd-version está vacío, mariadbd-safe usa mariadbd en el directorio ledir.

•--nice=prioridad

Usa el programa nice para establecer la prioridad de planificación del servidor al valor dado.

•--no-auto-restart, --nowatch, --no-watch

Sale después de iniciar mariadbd.

•--no-defaults

No lee ningún archivo de opciones. Esta debe ser la primera opción en la línea de comandos si se usa.

•--numa-interleave

Ejecuta mariadbd con su memoria intercalada en todos los nodos NUMA.

•--open-files-limit=cuenta

El número de archivos que mariadbd debería poder abrir. El valor de la opción se pasa a ulimit -n. ¡Tenga en cuenta que necesita iniciar mariadbd-safe como root para que esto funcione correctamente!

•--pid-file=nombre_archivo

El nombre de ruta del archivo de ID de proceso.

•--plugin-dir=nombre_dir

Directorio para plugins del lado del cliente.

•--port=numero_puerto

El número de puerto que el servidor debe usar al escuchar conexiones TCP/IP. El número de puerto debe ser 1024 o superior, a menos que el servidor sea iniciado por el usuario del sistema root.

•--skip-kill-mariadbd

No intentes matar procesos mariadbd errantes al inicio. Esta opción solo funciona en Linux.

•--socket=ruta

El archivo de socket Unix que el servidor debe usar al escuchar conexiones locales.

•--syslog, --skip-syslog

--syslog hace que los mensajes de error se envíen a syslog en sistemas que admiten el programa logger. --skip-syslog suprime el uso de syslog; los mensajes se escriben en un archivo de registro de errores.

•--syslog-tag=etiqueta

Para registrar en syslog, los mensajes de mariadbd-safe y mariadbd se escriben con una etiqueta de mariadbd-safe y mariadbd, respectivamente. Para especificar un sufijo para la etiqueta, use --syslog-tag=etiqueta, lo que modifica las etiquetas a ser mariadbd-safe-etiqueta y mariadbd-etiqueta.

•--timezone=zona_horaria

Establece la variable de entorno de zona horaria TZ al valor de la opción dada. Consulte la documentación de su sistema operativo para conocer los formatos de especificación de zona horaria legales.

•--user={nombre_usuario|id_usuario}

Ejecuta el servidor mariadbd como el usuario que tiene el nombre nombre_usuario o el ID de usuario numérico id_usuario. ("Usuario" en este contexto se refiere a una cuenta de inicio de sesión del sistema, no a un usuario de MariaDB listado en las tablas de concesión).

Si ejecuta mariadbd-safe con la opción --defaults-file o --defaults-extra-file para nombrar un archivo de opciones, la opción debe ser la primera dada en la línea de comandos o el archivo de opciones no se usará. Por ejemplo, este comando no usará el archivo de opciones con nombre:

mariadb> mariadbd-safe --port=numero_puerto --defaults-file=nombre_archivo

En cambio, use el siguiente comando:

mariadb> mariadbd-safe --defaults-file=nombre_archivo --port=numero_puerto

El script mariadbd-safe está escrito de tal manera que normalmente puede iniciar un servidor que se instaló a partir de una distribución de MariaDB desde el código fuente o binaria, aunque estos tipos de distribuciones típicamente instalan el servidor en ubicaciones ligeramente diferentes. mariadbd-safe espera que una de las siguientes condiciones sea verdadera:

•El servidor y las bases de datos se pueden encontrar en relación con el directorio de trabajo (el directorio desde el cual se invoca mariadbd-safe). Para las distribuciones binarias

, mariadbd-safe busca en su directorio de trabajo los directorios bin y data. Para distribuciones de origen, busca los directorios libexec y var. Esta condición se cumple si ejecutas mariadbd-safe desde tu directorio de instalación de MariaDB (por ejemplo, /usr/local/mysql para una distribución binaria).
•Si el servidor y las bases de datos no se encuentran en relación con el directorio de trabajo, mariadbd-safe intenta localizarlos por nombres de ruta absolutos. Las ubicaciones típicas son /usr/local/libexec y /usr/local/var. Las ubicaciones reales se determinan a partir de los valores configurados en la distribución en el momento de su compilación. Deberían ser correctos si MariaDB está instalado en la ubicación especificada en el momento de la configuración.

Dado que mariadbd-safe intenta encontrar el servidor y las bases de datos en relación con su propio directorio de trabajo, puedes instalar una distribución binaria de MariaDB en cualquier lugar, siempre que ejecutes mariadbd-safe desde el directorio de instalación de MariaDB:

shell> cd directorio_de_instalacion_mysql
shell> bin/mariadbd-safe &

Si mariadbd-safe falla, incluso cuando se invoca desde el directorio de instalación de MariaDB, puedes especificar las opciones --ledir y --datadir para indicar los directorios en los que se encuentran el servidor y las bases de datos en tu sistema.

Cuando utilizas mariadbd-safe para iniciar mariadbd, mariadbd-safe se encarga de que los mensajes de error (y de aviso) tanto de sí mismo como de mariadbd vayan al mismo destino.

Hay varias opciones de mariadbd-safe para controlar el destino de estos mensajes:

•--syslog: Escribe mensajes de error en syslog en sistemas que soportan el programa logger.
•--skip-syslog: No escribas mensajes de error en syslog. Los mensajes se escriben en el archivo de registro de errores predeterminado (nombre_host.err en el directorio de datos), o en un archivo con nombre si se proporciona la opción --log-error.
•--log-error=nombre_archivo: Escribe mensajes de error en el archivo de errores con nombre.

Si no se proporciona ninguna de estas opciones, la predeterminada es --skip-syslog.


Nota

Si se proporcionan tanto --syslog como --log-error, se emite una advertencia y --log-error tiene prioridad.

Cuando mariadbd-safe escribe un mensaje, los avisos van al destino de registro (syslog o archivo de registro de errores) y a stdout. Los errores van al destino de registro y a stderr.

Normalmente, no deberías editar el script mariadbd-safe. En su lugar, configura mariadbd-safe utilizando opciones de línea de comandos u opciones en la sección [mariadbd-safe] de un archivo de opciones my.cnf. En casos raros, puede ser necesario editar mariadbd-safe para que inicie el servidor correctamente. Sin embargo, si haces esto, tu versión modificada de mariadbd-safe podría ser sobrescrita si actualizas MariaDB en el futuro, por lo que deberías hacer una copia de tu versión editada que puedas reinstalar.

En NetWare, mariadbd-safe es un Módulo Cargable de NetWare (NLM) que se traslada del script original de shell de Unix. Inicia el servidor de la siguiente manera:

1. Ejecuta una serie de comprobaciones del sistema y de las opciones.
2. Ejecuta una comprobación de las tablas MyISAM.
3. Proporciona una presencia en pantalla para el servidor MariaDB.
4. Inicia mariadbd, lo monitoriza y lo reinicia si se termina con error.
5. Envía mensajes de error de mariadbd al archivo nombre_host.err en el directorio de datos.
6. Envía la salida de pantalla de mariadbd-safe al archivo nombre_host.safe en el directorio de datos.
