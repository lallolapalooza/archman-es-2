MYSQLROUTER(1) MySQL Router MYSQLROUTER(1)

NOMBRE

mysqlrouter - MySQL Router

SINOPSIS

mysqlrouter [opciones]

DESCRIPCIÓN

•Resúmenes de opciones de mysqlrouter
•Descripciones de opciones de mysqlrouter

MySQL Router acepta opciones de línea de comandos que se pasan a mysqlrouter para afectar su comportamiento, o para iniciar el router basándose en un InnoDB Cluster.

Al iniciar el Router, opcionalmente puede usar --config para especificar la ubicación del archivo de configuración principal (de lo contrario se usa la ubicación predeterminada) y --extra-config para un archivo de configuración adicional.

Las opciones de línea de comandos de inicio afectan los archivos y directorios generados que se utilizan al iniciar MySQL Router. Resúmenes de opciones de mysqlrouter Descripciones de opciones de mysqlrouter

•--version, -V
Formato de línea de comandos --version , -V

Muestra el número de versión e información relacionada de la aplicación, y sale. Por ejemplo:

$> mysqlrouter --version
MySQL Router v8.4.5 on Linux (64-bit) (GPL community edition)
•--help, -?
Formato de línea de comandos --help , -?

Muestra ayuda e información útil, y sale.

La opción --help tiene un beneficio adicional. Junto con la explicación de cada una de las opciones, la opción --help también muestra las rutas utilizadas para encontrar el archivo de configuración, y también varias rutas predeterminadas. El siguiente extracto de la salida de --help muestra un ejemplo de una máquina Ubuntu 16.04:

$> mysqlrouter --help
...
Inicia MySQL Router.
Configuración leída de los siguientes archivos en el orden dado (entre
paréntesis significa que no está disponible para lectura):
  (/etc/mysqlrouter/mysqlrouter.conf)
  /home/philip/.mysqlrouter.conf
Ruta del plugin:
  /usr/lib/x86_64-linux-gnu/mysqlrouter
Directorio de registro predeterminado:
  /var/log/mysqlrouter
Directorio de datos persistente predeterminado:
  /var/lib/mysqlrouter
Directorio de estado de ejecución predeterminado:
  /run/mysqlrouter
Uso: mysqlrouter [-V|--version] [-?|--help]
...

La sección de configuración muestra el orden de las rutas que pueden utilizarse para leer el archivo de configuración. En este caso, solo el segundo archivo es accesible.

•--bootstrap URI, -B URI
Formato de línea de comandos --bootstrap URI, -B URI
Tipo Cadena

La opción principal para realizar un inicio de MySQL Router conectándose al servidor de metadatos de InnoDB Cluster en la URI proporcionada. MySQL Router se autoconfigura basándose en la información recuperada del servidor de metadatos de InnoDB Cluster. Se solicita una contraseña si es necesario. Si no se proporciona un nombre de usuario como parte de la URI, se utiliza el nombre de usuario predeterminado "root". Consulte Conexión usando cadenas de conexión tipo URI[1] para obtener información sobre cómo usar una ruta para especificar una instancia de servidor.


Nota
Mientras que --bootstrap acepta una URI para conexiones TCP/IP, usar la opción --bootstrap-socket con un nombre de socket de dominio Unix local reemplaza la parte "host:port" de la URI pasada a la opción --bootstrap con el socket en la misma máquina.
Por defecto, el proceso de inicio realiza una configuración a nivel de sistema de MySQL Router. Solo una instancia de MySQL Router puede configurarse para operación a nivel de sistema. La instancia del sistema de MySQL Router tiene un `router_name` de "system". Si se desean instancias adicionales, utilice la opción --directory para crear instalaciones de MySQL Router autosuficientes.

URI: una instancia de servidor de un InnoDB Cluster para obtener información de metadatos. Si la URI proporcionada es una instancia de solo lectura, MySQL Router se reconecta automáticamente a una instancia de lectura y escritura en el InnoDB Cluster para poder registrar MySQL Router.

Si ya existe un archivo de configuración al iniciar MySQL Router con --bootstrap, se reutiliza el `router_id` existente en ese archivo y se produce un proceso de reconfiguración. El archivo de configuración se regenera desde cero y la cuenta del servidor de metadatos de MySQL Router se vuelve a crear, aunque con el mismo nombre.

Durante el proceso de reconfiguración, se descartan todos los cambios realizados en un archivo de configuración existente. Para personalizar un archivo de configuración y aún conservar la capacidad de reconfiguración automática (inicio), puede usar la opción de línea de comandos --extra-config para especificar un archivo de configuración adicional que se lee después del archivo de configuración principal. Estas opciones de configuración se utilizan porque este archivo de configuración adicional se carga después del archivo de configuración principal.

El proceso de inicio crea una nueva cuenta de usuario de MySQL con una contraseña generada aleatoriamente para que la use esa instancia específica de MySQL Router. Esta cuenta es utilizada por MySQL Router al conectarse al servidor de metadatos e InnoDB cluster para obtener información sobre su estado actual. Para obtener información detallada sobre este usuario, incluyendo cómo se almacena su contraseña y el privilegio de MySQL que requiere, consulte la documentación de la opción de usuario de MySQL.

El archivo de configuración generado se llama `mysqlrouter.conf`, y su ubicación depende del tipo de instancia que se esté configurando, del sistema y del paquete. Para instalaciones a nivel de sistema, el archivo de configuración generado se agrega al directorio de configuración del sistema, como `/etc` o `%PROGRAMDATA%\MySQL\MySQL Router\`. Ejecutar `mysqlrouter --help` mostrará esta ubicación.

La opción --user es requerida si se ejecuta un inicio con un superusuario (uid=0). Aunque no se recomienda, es posible forzar el uso del superusuario pasando su nombre como argumento, como `--user=root`.

Los permisos mínimos de GRANT requeridos para ejecutar --bootstrap son:

GRANT CREATE USER ON *.* TO 'usuario_inicio'@'%' WITH GRANT OPTION;
GRANT SELECT, INSERT, UPDATE, DELETE, EXECUTE ON mysql_innodb_cluster_metadata.* TO 'usuario_inicio'@'%';
GRANT SELECT ON mysql.user TO 'usuario_inicio'@'%';
GRANT SELECT ON performance_schema.replication_group_members TO 'usuario_inicio'@'%';
GRANT SELECT ON performance_schema.replication_group_member_stats TO 'usuario_inicio'@'%';
GRANT SELECT ON performance_schema.global_variables TO 'usuario_inicio'@'%';

Usar --bootstrap agrega valores predeterminados al archivo de configuración de MySQL Router generado, y algunos de estos valores predeterminados dependen de otras condiciones. A continuación, se enumeran algunas de las condiciones que afectan los valores predeterminados generados, donde predeterminado se define al pasar --bootstrap por sí solo.

--bootstrap-socket nombre_socket
Formato de línea de comandos --bootstrap-socket nombre_socket
Específico de plataforma Linux

Se utiliza junto con --bootstrap para iniciar usando un socket de dominio Unix local en lugar de TCP/IP. El valor de --bootstrap-socket reemplaza la parte "host:port" de la URI que se pasa a la opción --bootstrap.

Por ejemplo, si el servidor de metadatos de InnoDB Cluster se ejecuta en el host `localhost` y está escuchando en el puerto `6446`, y también tiene un socket de dominio Unix en `/tmp/mysql_cluster.sock`, entonces puede iniciar MySQL Router usando:

$> mysqlrouter --bootstrap 'mysql://root@localhost:6446/' --bootstrap-socket /tmp/mysql_cluster.sock

esto inicia MySQL Router usando el socket de dominio Unix para conectarse al servidor de metadatos.

•
--config path-to-config
Formato de línea de comandos --config path-to-config
Tipo Cadena

Especifica la ubicación del archivo de configuración principal.

Si no se proporciona esta opción, MySQL Router busca un archivo de configuración en las siguientes ubicaciones, en orden:

  1. El archivo de configuración especificado con la opción --config.
  2. El archivo de configuración predeterminado del sistema, como `/etc/mysqlrouter/mysqlrouter.conf`.
  3. El archivo de configuración del usuario, como `~/.mysqlrouter.conf`.
•
--extra-config path-to-extra-config
Formato de línea de comandos --extra-config path-to-extra-config
Tipo Cadena

Especifica la ubicación de un archivo de configuración adicional.

Este archivo se lee después del archivo de configuración principal, lo que permite anular las opciones establecidas en el archivo principal.

Por ejemplo, si su archivo de configuración principal tiene `log_level = INFO`, pero desea establecerlo en `DEBUG` solo para un inicio específico, puede usar:

$> mysqlrouter --config /etc/mysqlrouter/mysqlrouter.conf --extra-config /path/to/debug_config.cnf

donde `debug_config.cnf` contiene:

[log]
log_level = DEBUG
•
--directory path-to-directory
Formato de línea de comandos --directory path-to-directory
Tipo Cadena

Especifica un directorio base para la instalación de MySQL Router. Esto es útil para crear instancias de MySQL Router que no sean del sistema y que sean autosuficientes.

Cuando se usa esta opción, los archivos de configuración, logs y datos de ejecución se crean dentro del directorio especificado.

Por ejemplo:

$> mysqlrouter --bootstrap 'mysql://user@dbhost:3306/' --directory /opt/mysqlrouter_instance1

Esto creará la configuración, los logs y los directorios de estado dentro de `/opt/mysqlrouter_instance1/`. El archivo de configuración se guardará como `/opt/mysqlrouter_instance1/mysqlrouter.conf`.

•
--user username
Formato de línea de comandos --user username
Tipo Cadena

Especifica el usuario bajo el cual se ejecutará MySQL Router. Esto es especialmente importante cuando se inicia con privilegios elevados (como root) y se desea cambiar a un usuario no privilegiado por seguridad.

El usuario debe existir en el sistema y tener los permisos necesarios para acceder a los archivos y directorios de configuración y de datos.

•
--log-file path-to-log-file
Formato de línea de comandos --log-file path-to-log-file
Tipo Cadena

Especifica la ruta completa del archivo donde se escribirán los registros de MySQL Router. Si no se especifica, se utiliza la ubicación predeterminada del sistema (por ejemplo, `/var/log/mysqlrouter/mysqlrouter.log`).

•
--pid-file path-to-pid-file
Formato de línea de comandos --pid-file path-to-pid-file
Tipo Cadena

Especifica la ruta completa del archivo donde se escribirá el ID del proceso (PID) de MySQL Router. Esto es útil para la gestión de procesos, permitiendo detener o reiniciar el router.

•
--port port-number
Formato de línea de comandos --port port-number
Tipo Número

Especifica el puerto en el que escuchará MySQL Router para las conexiones entrantes. Esto solo tiene sentido si se está ejecutando MySQL Router como un proceso independiente y no a través de un inicio automático con un clúster. En la mayoría de los casos de uso con clústeres, los puertos se configuran automáticamente durante el proceso de inicio.

•
--address ip-address
Formato de línea de comandos --address ip-address
Tipo Cadena

Especifica la dirección IP en la que escuchará MySQL Router para las conexiones entrantes. De forma predeterminada, escucha en todas las interfaces (`0.0.0.0`).

•
--daemon , -d
Formato de línea de comandos --daemon , -d

Ejecuta MySQL Router en modo demonio (en segundo plano).

Cuando se utiliza esta opción, MySQL Router se desvincula del terminal y continúa ejecutándose en segundo plano. La salida estándar y los errores estándar se redirigen al archivo de registro especificado por `--log-file`.

•
--foreground , -f
Formato de línea de comandos --foreground , -f

Ejecuta MySQL Router en primer plano. Esto es útil para la depuración o cuando se gestiona el proceso con un supervisor de procesos como `systemd` o `supervisord`.

•
--skip-log-error
Formato de línea de comandos --skip-log-error

Evita que MySQL Router registre errores que no son críticos para el funcionamiento normal. Esto puede ser útil para reducir el ruido en los registros en entornos de producción muy activos.

•
--strict
Formato de línea de comandos --strict

Habilita el modo estricto. En este modo, MySQL Router generará un error y saldrá si encuentra alguna configuración no válida o imposible de aplicar. Esto es útil para garantizar que la configuración sea correcta antes de iniciar el servicio.

•**--core-file**
**Formato de línea de comandos** --core-file[={0|1}]
**Tipo** Booleano
**Valor predeterminado** 0

Escribe un archivo core si **mysqlrouter** falla. El nombre y la ubicación del archivo core dependen del sistema. En Linux, se escribe un archivo core llamado core.pid en el directorio de trabajo actual del proceso. pid representa el ID del proceso del servidor. En macOS, se escribe un archivo core llamado core.pid en el directorio /cores, si el proceso tiene el derecho com.apple.security.get-task-allow. En Solaris, use el comando **coreadm** para especificar dónde escribir el archivo core y cómo nombrarlo. En Windows, se escribe un archivo minidump llamado mysqlrouter.{pid}.dmp en el directorio de trabajo actual del proceso.

•**--directory ** **dir_path**, **-d ** **dir_path**
**Formato de línea de comandos** --directory dir_path, -d dir_path
**Tipo** Cadena

Especifica que se creará una instalación autónoma de MySQL Router en el directorio definido en lugar de configurar la instancia de router a nivel de sistema. Esto también permite crear múltiples instancias de router en el mismo sistema.

La estructura de directorios autónoma para Router es:

$path/start.sh
$path/stop.sh
$path/mysqlrouter.pid
$path/mysqlrouter.conf
$path/mysqlrouter.key
$path/run
$path/run/keyring
$path/data
$path/log
$path/log/mysqlrouter.log

Si se especifica esta opción, el archivo keyring se almacena en el directorio de estado de ejecución de esa instancia, bajo run/, en el directorio especificado, en lugar del directorio de estado de ejecución a nivel de sistema.

Si **--conf-use-sockets** también está habilitado, los archivos de socket generados también se agregan a este directorio.

•**--master-key-writer**
**Formato de línea de comandos** --master-key-writer file_path
**Tipo** Cadena

Esta opción de arranque opcional acepta un script que lee la clave maestra de STDIN. También utiliza la variable de entorno ROUTER_ID establecida por MySQL Router antes de que se llame al script **master-key-writer**.

Las opciones **master-key-writer** y **master-key-reader** deben usarse juntas, y su uso implica que la opción **master_key_file** no debe definirse en mysqlrouter.conf, ya que la clave maestra no se escribe en el archivo de clave maestra mysqlrouter.key.

Esto también se escribe en el archivo de configuración de MySQL Router generado como la opción **master-key-writer** [DEFAULT].

Contenido de ejemplo de un script bash llamado writer.sh utilizado en nuestro ejemplo:

#!/bin/bash
KID_=$(keyctl padd user ${ROUTER_ID} @us <&0)

Ejemplo de uso:

$> mysqlrouter --bootstrap=127.0.0.1:3310 --master-key-reader=./reader.sh
  --master-key-writer=./writer.sh

Esto también afecta a mysqlrouter.conf generado, por ejemplo:

[DEFAULT]
...
master-key-reader=reader.sh
master-key-writer=writer.sh
•**--master-key-reader**
**Formato de línea de comandos** --master-key-reader file_path
**Tipo** Cadena

Esta opción de arranque opcional acepta un script que escribe la clave maestra en STDOUT. También utiliza la variable de entorno ROUTER_ID establecida por MySQL Router antes de que se llame al script **master-key-reader**.

Las opciones **master-key-reader** y **master-key-writer** deben usarse juntas, y su uso implica que la opción **master_key_file** no debe definirse en mysqlrouter.conf, ya que la clave maestra no se escribe en el archivo de clave maestra mysqlrouter.key, y en su lugar utiliza el valor proporcionado por el script de esta opción.

Esto también se escribe en el archivo de configuración de MySQL Router generado como la opción **master-key-reader** [DEFAULT].

Contenido de ejemplo de un script bash llamado reader.sh utilizado en nuestro ejemplo:

#!/bin/bash
KID_=$(keyctl search @us user ${ROUTER_ID} 2>/dev/null)
if [ ! -z $KID_ ]; then
  keyctl pipe $KID_
fi

Ejemplo de uso:

$> mysqlrouter --bootstrap=127.0.0.1:3310 --master-key-reader=./reader.sh
  # O, múltiples hosts--master-key-writer=./writer.sh

Esto también afecta a mysqlrouter.conf generado, por ejemplo:

[DEFAULT]
...
master-key-reader=reader.sh
master-key-writer=writer.sh
•**--strict**
**Formato de línea de comandos** --strict
**Tipo** Cadena

Habilita el modo estricto, que por ejemplo hace que la verificación del usuario **--account** de arranque detenga el proceso de arranque en lugar de solo emitir una advertencia y continuar si el usuario proporcionado no pasa la verificación.

•**--account**
**Formato de línea de comandos** --account nombre_usuario
**Tipo** Cadena

Una opción de arranque para especificar el usuario de MySQL a utilizar, que reutiliza una cuenta de usuario de MySQL existente o crea una; el comportamiento se controla mediante la opción relacionada **--account-create**.

Con **--account**, el uso favorece la facilidad de gestión sobre la facilidad de despliegue, ya que múltiples routers pueden compartir la misma cuenta, y el nombre de usuario y la contraseña se definen manualmente en lugar de generarse automáticamente.

Establecer esta opción activa una solicitud de contraseña para esta cuenta independientemente de si la contraseña está disponible en el keyring.

El arranque sin pasar **--account** no recrea una cuenta de servidor MySQL existente.

El uso de esta opción asume que el usuario tiene suficientes derechos de acceso para Router, ya que el proceso de arranque no intenta agregar permisos faltantes a las cuentas existentes. El proceso de arranque verifica los permisos y muestra información en la consola sobre la verificación fallida. El proceso de arranque continúa a pesar de estas verificaciones fallidas, a menos que la opción opcional **--strict** también se use. Permisos requeridos de ejemplo:

GRANT USAGE ON *.* TO `theuser`@`%`
GRANT SELECT, EXECUTE ON `mysql_innodb_cluster_metadata`.* TO `theuser`@`%`
GRANT INSERT, UPDATE, DELETE ON `mysql_innodb_cluster_metadata`.`routers` TO `theuser`@`%`
GRANT INSERT, UPDATE, DELETE ON `mysql_innodb_cluster_metadata`.`v2_routers` TO `theuser`@`%`
GRANT SELECT ON `performance_schema`.`global_variables` TO `theuser`@`%`
GRANT SELECT ON `performance_schema`.`replication_group_member_stats` TO `theuser`@`%`
GRANT SELECT ON `performance_schema`.`replication_group_members` TO `theuser`@`%`

No se acepta una contraseña desde la línea de comandos. Por ejemplo, pasar "foo:bar" asume que "foo:bar" es el nombre de usuario deseado en lugar del usuario foo con la contraseña bar.

•**--account-create**
**Formato de línea de comandos** --account-create comportamiento
**Tipo** Cadena
**Valor predeterminado** if-not-exists
**Valores válidos** if-not-exists always never

Especifica la política de creación de cuentas para ayudar a prevenir un arranque accidental con la cuenta de usuario incorrecta. Los valores potenciales son:

•if-not-exists (predeterminado): Arranca de todos modos; reutiliza la cuenta si existe, de lo contrario, la crea.
•always: Solo arranca si la cuenta no existe; y la crea.
•never: Solo arranca si la cuenta ya existe; y la reutiliza.

Esta opción requiere que la opción **--account** también se use, y que **--account-host** no se use.

•**--account-host**
**Formato de línea de comandos** --account-host patrón_host
**Tipo** Cadena
**Valor predeterminado** %

El patrón de host utilizado para las cuentas creadas por MySQL Router durante el proceso de arranque. Es opcional y su valor predeterminado es '%'.

Pase esta opción varias veces para definir múltiples patrones, en cuyo caso las cuentas de MySQL generadas utilizan la misma contraseña.


Nota
Router no realiza comprobaciones de sanidad y no garantiza que el patrón autorice a Router a conectarse.

Nota
El arranque reutiliza las cuentas de Router existentes eliminando y recreando el usuario, y este proceso de recreación de usuarios se aplica a todos los hosts.
Ejemplos: 
# Un host
$> mysqlrouter --bootstrap localhost:3310 --account-host host1
# O, múltiples hosts
$> mysqlrouter --bootstrap localhost:3310 --account-host host1 --account-host host2
  --account-host host3
•**--conf-use-sockets**
**Formato de línea de comandos** --conf-use-sockets
**Específico de plataforma** Linux

Habilita sockets de dominio Unix locales.

Esta opción se utiliza durante el arranque, y habilitarla agrega la opción **socket** al archivo de configuración generado.

El nombre del archivo de socket generado depende de la opción **protocol**. Con el protocolo clásico habilitado, el archivo se llama mysql.sock para conexiones de lectura-escritura,

y mysqlro.sock para conexiones de solo lectura. Con el Protocolo X habilitado, el archivo se llama mysqlx.sock para conexiones de lectura-escritura y mysqlxro.sock para conexiones de solo lectura. Esta opción no está disponible en Windows.
•--conf-use-gr-notifications
Formato de Línea de Comandos --conf-use-gr-notifications

Habilita la opción use_gr_notifications [metadata_cache] durante el arranque. Cuando está habilitada, Router es notificado asíncronamente sobre la mayoría de los cambios del clúster. Consulte use_gr_notifications para obtener más información. Además, el uso de esta opción establece ttl=60 y auth_cache_refresh_interval=60.

•--pid-file ruta
Formato de Línea de Comandos --pid-file ruta
Tipo Cadena

Establece la ubicación del archivo PID. Esto se puede configurar de tres maneras diferentes (en orden de precedencia): esta opción de línea de comandos --pid-file, estableciendo pid_file en el archivo de configuración de Router, o definiendo la variable de entorno ROUTER_PID.

Si se especifica --bootstrap, entonces la configuración de --pid-file hace que Router falle. Esto es diferente de ROUTER_PID y la opción de configuración pid_file, que se ignoran si se especifica --bootstrap.

Si no se especifica --bootstrap, entonces lo siguiente hace que Router falle: el archivo --pid-file ya existe, pid_file o ROUTER_PID están configurados pero vacíos, o si Router no puede escribir el archivo PID.

•--report-host
Formato de Línea de Comandos --report-host nombre_host
Tipo Cadena

Define opcionalmente el nombre de host de Router en lugar de depender de la autodetención para determinar el nombre de host visible externamente registrado en metadatos durante el proceso de arranque.

Router no verifica ni confirma que el nombre de host proporcionado sea accesible, pero utiliza RFC 1123 para validar nombres de host y RFC 2181 para validar direcciones.

El nombre de host proporcionado se escribe en el campo host_name de la tabla mysql_innodb_cluster_metadata.hosts en el almacén de metadatos del clúster de MySQL InnoDB.

•--conf-skip-tcp
Formato de Línea de Comandos --conf-skip-tcp
Específico de Plataforma Linux

Omite la configuración de un puerto TCP para escuchar conexiones entrantes. Consulte también --conf-use-sockets.

Esta opción no está disponible en Windows.

•--conf-base-port puerto_num
Formato de Línea de Comandos --conf-base-port puerto_num
Tipo Entero
Valor Predeterminado 0

Valor base (primero) utilizado para los puertos TCP de escucha al establecer bind_port para cada ruta de arranque.

Este valor se utiliza para la ruta clásica de lectura-escritura, y cada puerto adicional asignado se incrementa en un valor de uno. El orden de los puertos establecidos es clásico lectura-escritura / solo lectura, y luego x lectura-escritura / solo lectura.

Establecer --conf-base-port en 0 cambia los valores predeterminados de bind_port a los siguientes valores predeterminados, que eran los siguientes: Para el protocolo clásico, Lectura/Escritura usa 6446 y Solo Lectura usa 6447, y para el protocolo X Lectura/Escritura usa 64460 y Solo Lectura usa 64470.

Ejemplo de uso:

# Ejemplo sin --conf-base-port
$> mysqlrouter --bootstrap root@localhost:3310
...
Conexiones del protocolo MySQL clásico al clúster 'devCluster':
- Conexiones de Lectura/Escritura: localhost:6446
- Conexiones de Solo Lectura: localhost:6447
Conexiones del protocolo X al clúster 'devCluster':
- Conexiones de Lectura/Escritura: localhost:6448
- Conexiones de Solo Lectura: localhost:6449
# Ejemplo que demuestra --conf-base-port establecido en 0
$> mysqlrouter --bootstrap root@localhost:3310 --conf-base-port 0
...
Conexiones del protocolo MySQL clásico al clúster 'devCluster':
- Conexiones de Lectura/Escritura: localhost:6446
- Conexiones de Solo Lectura: localhost:6447
Conexiones del protocolo X al clúster 'devCluster':
- Conexiones de Lectura/Escritura: localhost:64460
- Conexiones de Solo Lectura: localhost:64470

•--force-password-validation
Formato de Línea de Comandos --force-password-validation
Específico de Plataforma Linux

Por defecto, MySQL Router omite el mecanismo de validación de contraseñas del Servidor MySQL y, en su lugar, Router genera y utiliza una contraseña FUERTE basada en la configuración predeterminada conocida de validación de contraseñas. Esto se debe a que la validación de contraseñas puede ser configurada por el usuario y Router no puede tener en cuenta configuraciones personalizadas inusuales.

Esta opción garantiza que la validación de contraseñas (validate_password) no se omita para las contraseñas generadas, y está deshabilitada por defecto.

•--password-retries num_reintentos
Formato de Línea de Comandos --password-retries num_reintentos
Tipo Entero
Valor Predeterminado 20
Valor Mínimo 1
Valor Máximo 10000

Especifica el número de veces que MySQL Router debe intentar generar una contraseña al crear una cuenta de usuario con las reglas de validación de contraseñas. El valor predeterminado es 20. El rango válido es de 1 a 10000.

La razón más probable de falla se debe a configuraciones personalizadas de validate_password con requisitos inusuales, como un mínimo de 50 caracteres. En ese escenario de falla, ya sea --force-password-validation está configurado como verdadero y/o el plugin mysql_native_password del Servidor MySQL está deshabilitado (este plugin permite omitir la validación).

Establece un valor para una opción de configuración generada durante el arranque; esto puede establecer un valor para cualquier opción arrancada, por ejemplo:

...
max_connect_errors=0
...

Las definiciones de --conf-set-option tienen prioridad sobre los parámetros específicos de la opción para establecer un valor específico.
