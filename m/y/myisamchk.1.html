MYISAMCHK(1) Sistema de bases de datos MariaDB MYISAMCHK(1)

NOMBRE

myisamchk - utilidad de mantenimiento de tablas MyISAM

SINOPSIS

myisamchk [opciones] nombre_tabla ...

DESCRIPCIÓN

La utilidad myisamchk obtiene información sobre las tablas de su base de datos o las comprueba, repara u optimiza. myisamchk funciona con tablas MyISAM (tablas que tienen archivos .MYD y .MYI para almacenar datos e índices).

No se admite el uso de myisamchk con tablas particionadas.


Precaución

Es mejor hacer una copia de seguridad de una tabla antes de realizar una operación de reparación de tablas; en algunas circunstancias, la operación podría causar pérdida de datos. Las causas posibles incluyen, entre otras, errores del sistema de archivos.

Invoque myisamchk de esta manera:

shell> myisamchk [opciones] nombre_tabla ...

Las opciones especifican qué desea que haga myisamchk. Se describen en las siguientes secciones. También puede obtener una lista de opciones invocando myisamchk --help.

Sin opciones, myisamchk simplemente comprueba su tabla como operación predeterminada. Para obtener más información o para indicar a myisamchk que tome medidas correctivas, especifique las opciones como se describe en la discusión siguiente.

nombre_tabla es la tabla de la base de datos que desea comprobar o reparar. Si ejecuta myisamchk en un lugar que no sea el directorio de la base de datos, debe especificar la ruta al directorio de la base de datos, ya que myisamchk no tiene idea de dónde se encuentra la base de datos. De hecho, myisamchk en realidad no se preocupa de si los archivos en los que está trabajando se encuentran en un directorio de base de datos. Puede copiar los archivos que corresponden a una tabla de base de datos en otra ubicación y realizar operaciones de recuperación allí.

Puede nombrar varias tablas en la línea de comandos de myisamchk si lo desea. También puede especificar una tabla nombrando su archivo de índice (el archivo con el sufijo .MYI). Esto le permite especificar todas las tablas en un directorio utilizando el patrón *.MYI. Por ejemplo, si se encuentra en un directorio de base de datos, puede comprobar todas las tablas MyISAM en ese directorio de la siguiente manera:

shell> myisamchk *.MYI

Si no se encuentra en el directorio de la base de datos, puede comprobar todas las tablas allí especificando la ruta al directorio:

shell> myisamchk /ruta/al/directorio_base_datos/*.MYI

Incluso puede comprobar todas las tablas en todas las bases de datos especificando un comodín con la ruta al directorio de datos de MariaDB:

shell> myisamchk /ruta/al/directorio_datos/*/*.MYI

La forma recomendada de comprobar rápidamente todas las tablas MyISAM es:

shell> myisamchk --silent --fast /ruta/al/directorio_datos/*/*.MYI

Si desea comprobar todas las tablas MyISAM y reparar las que estén corruptas, puede usar el siguiente comando:

shell> myisamchk --silent --force --fast --update-state \
          --key_buffer_size=64M --sort_buffer_size=64M \
          --read_buffer_size=1M --write_buffer_size=1M \
          /ruta/al/directorio_datos/*/*.MYI

Este comando asume que tiene más de 64 MB libres. Para obtener más información sobre la asignación de memoria con myisamchk, consulte la sección llamada "USO DE MEMORIA DE MYISAMCHK".


Importante

Debe asegurarse de que ningún otro programa esté utilizando las tablas mientras ejecuta myisamchk. El medio más eficaz para hacerlo es detener el servidor MariaDB mientras ejecuta myisamchk, o bloquear todas las tablas en las que se está utilizando myisamchk.

De lo contrario, al ejecutar myisamchk, puede mostrar el siguiente mensaje de error:

advertencia: los clientes están utilizando la tabla o no la han cerrado correctamente

Esto significa que está intentando comprobar una tabla que ha sido actualizada por otro programa (como el servidor mariadb) que aún no ha cerrado el archivo o que ha muerto sin cerrar el archivo correctamente, lo que a veces puede provocar la corrupción de una o más tablas MyISAM.

Si mariadb se está ejecutando, debe forzarlo a volcar cualquier modificación de tabla que aún esté en búfer en la memoria utilizando FLUSH TABLES. Luego, debe asegurarse de que nadie esté utilizando las tablas mientras ejecuta myisamchk.

Sin embargo, la forma más fácil de evitar este problema es usar CHECK TABLE en lugar de myisamchk para comprobar las tablas.

myisamchk admite las siguientes opciones, que se pueden especificar en la línea de comandos o en el grupo de opciones [myisamchk].

OPCIONES GENERALES DE MYISAMCHK

Las opciones descritas en esta sección se pueden utilizar para cualquier tipo de operación de mantenimiento de tablas realizada por myisamchk. Las secciones siguientes describen las opciones que pertenecen solo a operaciones específicas, como la comprobación o reparación de tablas.

•--help, -?

Muestra un mensaje de ayuda y sale. Las opciones se agrupan por tipo de operación.

•--HELP, -H

Muestra un mensaje de ayuda y sale. Las opciones se presentan en una única lista.

•--debug=opciones_debug, -# opciones_debug

Escribe un registro de depuración. Una cadena típica de opciones_debug es 'd:t:o,nombre_archivo'. El valor predeterminado es 'd:t:o,/tmp/myisamchk.trace'.

•--silent, -s

Modo silencioso. Muestra salida solo cuando ocurren errores. Puede usar -s dos veces (-ss) para hacer que myisamchk sea muy silencioso.

•--verbose, -v

Modo detallado. Muestra más información sobre lo que hace el programa. Esto se puede usar con -d y -e. Use -v varias veces (-vv, -vvv) para obtener aún más salida.

•--version, -V

Muestra información de versión y sale.

•--wait, -w

En lugar de terminar con un error si la tabla está bloqueada, espera hasta que la tabla se desbloquee antes de continuar. Si está ejecutando mariadb con el bloqueo externo deshabilitado, la tabla solo puede ser bloqueada por otro comando myisamchk.

•--print-defaults

Imprime la lista de argumentos del programa y sale.

•--no-defaults

No leer las opciones predeterminadas de ningún archivo de opciones.

•--defaults-file=#

Solo leer las opciones predeterminadas del archivo proporcionado.

•--defaults-extra-file=#

Leer este archivo después de que se lean los archivos globales.

MYISAMCHK RECOVER OPTIONS

myisamchk soporta las siguientes opciones para operaciones de recuperación de tablas:

•--backup, -B

Crea una copia de seguridad del archivo .MYD como nombre_archivo-hora.BAK

•--character-sets-dir=ruta

El directorio donde se instalan los conjuntos de caracteres.

•--correct-checksum

Corrige la información de la suma de verificación de la tabla.

•--create-missing-keys

Crea índices faltantes. Esto asume que el archivo de datos es correcto y que el número de filas almacenadas en el archivo de índices es correcto. Habilita --quick.

•--data-file-length=longitud, -D longitud

La longitud máxima del archivo de datos (al recrear el archivo de datos cuando está "lleno").

•--extend-check, -e

Realiza una recuperación que intenta recuperar cada fila posible del archivo de datos. Normalmente, esto también encuentra muchas filas basura. No uses esta opción a menos que estés desesperado.

Para una descripción del formato de salida, consulta la sección llamada "INFORMACIÓN DE TABLAS DE MYISAMCHK".

•--force, -f

Sobrescribe archivos intermedios antiguos (archivos con nombres como nombre_tabla.TMD) en lugar de abortar. Añade otro --force para evitar errores de 'myisam_sort_buffer_size es demasiado pequeño'. En este caso, intentaremos realizar la recuperación con el myisam_sort_buffer_size proporcionado y asignaremos dinámicamente tantos búferes de gestión como sean necesarios.

•--keys-used=valor, -k valor

Para myisamchk, el valor de la opción es un valor de bits que indica qué índices se actualizarán. Cada bit binario del valor de la opción corresponde a un índice de tabla, donde el primer índice es el bit 0. Un valor de opción de 0 deshabilita las actualizaciones de todos los índices, lo que se puede usar para obtener inserciones más rápidas. Los índices desactivados se pueden reactivar usando myisamchk -r.

•--max-record-length=longitud

Omite filas más grandes que la longitud dada si myisamchk no puede asignar memoria para contenerlas.

•--parallel-recover, -p

Utiliza la misma técnica que -r y -n, pero crea todas las claves en paralelo, utilizando diferentes hilos. ¡Este es un código de calidad beta. Úsalo bajo tu propio riesgo!

•--quick, -q

Logra una recuperación más rápida modificando solo el archivo de índices, no el archivo de datos. Puedes especificar esta opción dos veces para forzar que myisamchk modifique el archivo de datos original en caso de claves duplicadas. NOTA: Las tablas con el archivo de datos corrupto no se pueden arreglar con esta opción.

•--recover, -r

Realiza una recuperación que puede arreglar casi cualquier problema excepto las claves únicas que no son únicas (lo cual es un error extremadamente improbable con las tablas MyISAM). Si deseas recuperar una tabla, esta es la opción a probar primero. Debes intentar --safe-recover solo si myisamchk informa que la tabla no se puede recuperar usando --recover. (En el improbable caso de que --recover falle, el archivo de datos permanece intacto).

Si tienes mucha memoria, deberías aumentar el valor de sort_buffer_size.

•--safe-recover, -o

Realiza una recuperación usando un método de recuperación antiguo que lee todas las filas en orden y actualiza todos los árboles de índices basándose en las filas encontradas. Esto es un orden de magnitud más lento que --recover, pero puede manejar un par de casos muy improbables que --recover no puede. Este método de recuperación también utiliza mucho menos espacio en disco que --recover. Normalmente, deberías intentar la recuperación primero usando --recover, y luego con --safe-recover solo si --recover falla.

Si tienes mucha memoria, deberías aumentar el valor de key_buffer_size.

•--set-collation=nombre

Especifica la colación a usar para ordenar los índices de la tabla. El nombre del conjunto de caracteres se deduce de la primera parte del nombre de la colación.

•--sort-recover, -n

Fuerza a myisamchk a usar la ordenación para resolver las claves, incluso si los archivos temporales fueran muy grandes.

•--tmpdir=ruta, -t ruta

La ruta del directorio que se utilizará para almacenar archivos temporales. Si no está configurado, myisamchk utiliza el valor de la variable de entorno TMPDIR. tmpdir se puede configurar como una lista de rutas de directorios que se utilizan sucesivamente en modo round-robin para crear archivos temporales. El carácter separador entre nombres de directorios es el dos puntos (":") en Unix y el punto y coma (";") en Windows, NetWare y OS/2.

•--unpack, -u

Descomprime una tabla que fue comprimida con myisampack.

MYISAMCHK ANALYZE OPTIONS

myisamchk soporta la siguiente opción para operaciones de análisis de tablas:

•--analyze, -a

Analiza la distribución de claves de una tabla. Esto puede acelerar las consultas si la tabla tiene datos desiguales. myisamchk almacena la distribución de claves en el archivo .MYI. Consulta la sección "MYISAMCHK RECOVER OPTIONS" para ver las opciones que influyen en cómo se tratan los valores NULL.

MYISAMCHK SORT OPTIONS

myisamchk soporta las siguientes opciones para operaciones de ordenación de tablas:

•--sort-index, -k

Ordena los índices de la tabla. Esto puede ser útil si tienes tablas que han sido modificadas con frecuencia y quieres asegurarte de que los índices estén ordenados. Es similar a ANALYZE TABLE.

•--sort-records, -R

Ordena los registros de la tabla basándose en el orden de los índices. Esto puede mejorar el rendimiento de las consultas que utilizan esos índices, especialmente después de muchas inserciones o eliminaciones.

•--sort-recover, -n

Fuerza a myisamchk a usar la ordenación para resolver las claves incluso si los archivos temporales fueran muy grandes. Esto se utiliza principalmente durante el proceso de recuperación para reconstruir los índices ordenando los datos.

MYISAMCHK PACK OPTIONS

myisamchk soporta las siguientes opciones para operaciones de empaquetado de tablas:

•--pack, -p

Empaqueta una tabla para reducir su tamaño. Esto elimina el espacio libre dentro de los registros de datos. La tabla se vuelve más pequeña y puede mejorar el rendimiento de lectura. Sin embargo, las operaciones de escritura posteriores pueden ser más lentas porque es necesario rellenar el espacio libre.

•--unpack, -u

Descomprime una tabla que fue empaquetada con myisampack.

MYISAMCHK OTHER OPTIONS

myisamchk soporta las siguientes opciones generales:

•--help, -?

Muestra un mensaje de ayuda y sale.

•--silent, -s

Modo silencioso. Omite los mensajes informativos y de estado. Solo se muestran los errores.

•--verbose, -v

Modo detallado. Muestra información adicional sobre el progreso y los resultados de la operación.

•--version, -V

Muestra la información de la versión de myisamchk y sale.

•--wait, -w

Espera si la tabla está bloqueada por otro proceso. Útil cuando se ejecuta myisamchk mientras el servidor mariadb está en funcionamiento.

Hay algunas opciones de recuperación que se pueden usar juntas:

•--recover y --safe-recover

Se utiliza --recover para la recuperación principal. Si falla, se utiliza --safe-recover. El orden es importante.

•--quick

La opción --quick se puede usar con --recover para acelerar el proceso si solo se necesita modificar el archivo de índices. También se habilita automáticamente si se usa --create-missing-keys.

•--sort-recover

Esta opción indica a myisamchk que utilice el método de ordenación para la recuperación, incluso si esto genera archivos temporales muy grandes. Se utiliza cuando los métodos de recuperación normales podrían fallar debido a la complejidad de los datos o índices.

El uso de --force se puede aplicar a operaciones de recuperación como --recover o --safe-recover para forzar la sobrescritura de archivos intermedios o para intentar realizar la recuperación con menos memoria disponible.

Si usas myisamchk para realizar una operación que modifica los índices de la tabla (como reparar o analizar), los índices FULLTEXT se reconstruirán utilizando los valores predeterminados de parámetros de longitud mínima y máxima de palabra, y el archivo de stopwords, a menos que especifiques lo contrario. Esto puede provocar fallos en las consultas.

Para evitar este problema si has modificado la longitud mínima o máxima de la palabra o el archivo de stopwords en el servidor, especifica los mismos valores de ft_min_word_len, ft_max_word_len y ft_stopword_file a myisamchk que usas para mariadbd.

shell> myisamchk --recover --ft_min_word_len=3 nombre_tabla.MYI

Para asegurarte de que myisamchk y el servidor utilizan los mismos valores para los parámetros full-text, puedes colocar cada uno en las secciones [mariadbd] y [myisamchk] de un archivo de opciones:

[mariadbd]
ft_min_word_len=3
[myisamchk]
ft_min_word_len=3

Una alternativa a usar myisamchk es utilizar REPAIR TABLE, ANALYZE TABLE, OPTIMIZE TABLE o ALTER TABLE. Estas sentencias son ejecutadas por el servidor, que conoce los valores apropiados de los parámetros full-text a utilizar.

Las opciones --safe-recover y --sort-recover son métodos alternativos de recuperación. --safe-recover es más lento pero usa menos espacio en disco, mientras que --sort-recover fuerza el uso de ordenación para la recuperación, lo que puede ser útil en casos extremos pero consume más recursos y tiempo si los archivos temporales son grandes.

Es importante tener en cuenta que --recover es el método de recuperación principal y el primero que se debe intentar. --safe-recover se usa solo si --recover falla.

MYISAMCHK CHECK OPTIONS

myisamchk soporta las siguientes opciones para operaciones de comprobación de tablas:

•--check, -c

Comprueba la tabla en busca de errores. Esta es la operación predeterminada si no se especifica ninguna opción que seleccione explícitamente un tipo de operación.

•--check-only-changed, -C

Comprueba solo las tablas que han cambiado desde la última comprobación.

•--extend-check, -e

Comprueba la tabla de forma muy exhaustiva. Esto es bastante lento si la tabla tiene muchos índices. Esta opción solo debe usarse en casos extremos. Normalmente, myisamchk o myisamchk --medium-check deberían ser capaces de determinar si hay algún error en la tabla.

Si estás usando --extend-check y tienes mucha memoria, configurar la variable key_buffer_size a un valor grande ayuda a que la operación de recuperación se ejecute más rápido.

Para una descripción del formato de salida, consulta la sección llamada "INFORMACIÓN DE TABLAS DE MYISAMCHK".

•--fast, -F

Comprueba solo las tablas que no se han cerrado correctamente.

•--force, -f

Realiza una operación de recuperación automáticamente si myisamchk encuentra algún error en la tabla. El tipo de recuperación es el mismo que el especificado con la opción --recover o -r. Los estados se actualizarán como con --update-state.

•--information, -i

Imprime estadísticas informativas sobre la tabla que se está comprobando.

•--medium-check, -m

Realiza una comprobación más rápida que una operación --extend-check. Esto encuentra solo el 99.99% de todos los errores, lo que debería ser suficiente en la mayoría de los casos.

•--read-only, -T

No marca la tabla como comprobada. Esto es útil si utilizas myisamchk para comprobar una tabla que está en uso por alguna otra aplicación que no utiliza bloqueos, como mariadbd cuando se ejecuta con el bloqueo externo deshabilitado.

•--update-state, -U

Almacena información en el archivo .MYI para indicar cuándo se comprobó la tabla y si la tabla se bloqueó. Esto debe usarse para obtener el beneficio completo de la opción --check-only-changed, pero no debes usar esta opción si el servidor mariadbd está usando la tabla y la estás ejecutando con el bloqueo externo deshabilitado.

OTRAS OPCIONES DE MYISAMCHK

myisamchk admite las siguientes opciones para acciones distintas de la comprobación y reparación de tablas:

•--analyze, -a

Analiza la distribución de los valores de las claves. Esto mejora el rendimiento de las uniones, ya que permite al optimizador de uniones elegir mejor el orden en que se unirán las tablas y qué índices debe utilizar. Para obtener información sobre la distribución de claves, utilice el comando myisamchk --description --verbose nombre_tabla o la sentencia SHOW INDEX FROM nombre_tabla.

•--block-search=offset, -b offset

Encuentra el registro al que pertenece un bloque en el desplazamiento dado.

•--description, -d

Imprime información descriptiva sobre la tabla. Especificar la opción --verbose una o dos veces produce información adicional. Consulte la sección titulada “INFORMACIÓN DE TABLAS DE MYISAMCHK”.

•--set-auto-increment[=valor], -A[valor]

Fuerza que la numeración AUTO_INCREMENT para registros nuevos comience en el valor dado (o superior, si existen registros con valores AUTO_INCREMENT tan grandes). Si no se especifica valor, los números AUTO_INCREMENT para registros nuevos comienzan con el valor más grande actual de la tabla, más uno.

•--sort-index, -S

Ordena los bloques del árbol de índices en orden de mayor a menor. Esto optimiza las búsquedas y acelera los escaneos de tablas que utilizan índices.

•--sort-records=N, -R N

Ordena los registros según un índice específico. Esto hace que sus datos estén mucho más localizados y puede acelerar las operaciones SELECT y ORDER BY basadas en rangos que utilicen este índice. (La primera vez que utilice esta opción para ordenar una tabla, puede ser muy lenta). Para determinar los números de índice de una tabla, utilice SHOW INDEX, que muestra los índices de una tabla en el mismo orden en que los ve myisamchk. Los índices se numeran a partir de 1.

Si las claves no están empaquetadas (PACK_KEYS=0), tienen la misma longitud, por lo que cuando myisamchk ordena y mueve registros, simplemente sobrescribe las direcciones de registro en el índice. Si las claves están empaquetadas (PACK_KEYS=1), myisamchk debe desempaquetar primero los bloques de claves, luego recrear los índices y volver a empaquetar los bloques de claves. (En este caso, recrear los índices es más rápido que actualizar las direcciones para cada índice).

•--stats-method=name

Especifica cómo el código de recolección de estadísticas de índices debe tratar los valores NULL. Los valores posibles de name son "nulls_unequal" (predeterminado), "nulls_equal" (emula el comportamiento de MySQL 4) y "nulls_ignored".

INFORMACIÓN DE TABLAS DE MYISAMCHK

Para obtener una descripción de una tabla MyISAM o estadísticas sobre ella, utilice los comandos que se muestran aquí. La salida de estos comandos se explica más adelante en esta sección.

•myisamchk -d nombre_tabla

Ejecuta myisamchk en modo de descripción para generar una descripción de su tabla. Si inicia el servidor MariaDB con el bloqueo externo deshabilitado, myisamchk puede informar un error para una tabla que se actualiza mientras se ejecuta. Sin embargo, dado que myisamchk no modifica la tabla en modo de descripción, no hay riesgo de dañar datos.

•myisamchk -dv nombre_tabla

Agregar -v ejecuta myisamchk en modo detallado para que produzca más información sobre la tabla. Agregar -v una segunda vez produce aún más información.

•myisamchk -eis nombre_tabla

Muestra solo la información más importante de una tabla. Esta operación es lenta porque debe leer toda la tabla.

•myisamchk -eiv nombre_tabla

Es como -eis, pero le indica lo que se está haciendo.

El argumento nombre_tabla puede ser el nombre de una tabla MyISAM o el nombre de su archivo de índice, como se describe en myisamchk(1). Se pueden proporcionar varios argumentos nombre_tabla.

Supongamos que una tabla llamada `person` tiene la siguiente estructura. (La opción MAX_ROWS de la tabla se incluye para que en el ejemplo de salida de myisamchk que se muestra más adelante, algunos valores sean más pequeños y se ajusten más fácilmente al formato de salida).

(

  last_name  VARCHAR(20) NOT NULL,
  first_name VARCHAR(20) NOT NULL,
  birth      DATE,
  death      DATE,
  PRIMARY KEY (id),
  INDEX (last_name, first_name),
  INDEX (birth)
) MAX_ROWS = 1000000;

Aquí se proporcionan explicaciones de los tipos de información que produce myisamchk. "Keyfile" se refiere al archivo de índice. "Record" y "row" son sinónimos, al igual que "field" y "column".

La parte inicial de la descripción de la tabla contiene estos valores:

• MyISAM file

Nombre del archivo de índice MyISAM.

•Record format

Formato utilizado para almacenar las filas de la tabla. Los ejemplos anteriores utilizan longitud fija. Otros valores posibles son Comprimido y Empaquetado. (Empaquetado corresponde a lo que SHOW TABLE STATUS informa como Dinámico).

•Chararacter set

Juego de caracteres predeterminado de la tabla.

•File-version

Versión del formato MyISAM. Actualmente siempre es 1.

•Creation time

Cuándo se creó el archivo de datos.

•Recover time

Cuándo se reconstruyó por última vez el archivo de índice/datos.

•Status

Marcas de estado de la tabla. Los valores posibles son crashed, open, changed, analyzed, optimized keys y sorted index pages.

•Auto increment key, Last value

El número de clave asociado a la columna AUTO_INCREMENT de la tabla y el último valor generado para esta columna. Estos campos no aparecen si no existe tal columna.

•Data records

Número de filas de la tabla.

•Deleted blocks

Cuántos bloques eliminados todavía tienen espacio reservado. Puede optimizar su tabla para minimizar este espacio. Consulte la Sección 6.6.4, “Optimización de tablas MyISAM”.

•Datafile parts

Para el formato de filas dinámicas, esto indica cuántos bloques de datos hay. Para una tabla optimizada sin filas fragmentadas, esto es lo mismo que Data records.

•Deleted data

Cuántos bytes de datos eliminados sin reclamar hay. Puede optimizar su tabla para minimizar este espacio. Consulte la Sección 6.6.4, “Optimización de tablas MyISAM”.

•Datafile pointer

Tamaño del puntero del archivo de datos, en bytes. Normalmente es de 2, 3, 4 o 5 bytes. La mayoría de las tablas se gestionan con 2 bytes, pero esto aún no se puede controlar desde MariaDB. Para tablas fijas, esto es una dirección de fila. Para tablas dinámicas, esto es una dirección de byte.

•Keyfile pointer

Tamaño del puntero del archivo de índice, en bytes. Normalmente es de 1, 2 o 3 bytes. La mayoría de las tablas se gestionan con 2 bytes, pero MariaDB lo calcula automáticamente. Siempre es una dirección de bloque.

•Max datafile length

Cuánto puede llegar a ser el archivo de datos de la tabla, en bytes.

•Max keyfile length

Cuánto puede llegar a ser el archivo de índice de la tabla, en bytes.

•Recordlength

Cuánto espacio ocupa cada fila, en bytes.

La parte de descripción de la tabla de la salida incluye una lista de todas las claves de la tabla. Para cada clave, myisamchk muestra información de bajo nivel:

•Key

El número de esta clave. Este valor solo se muestra para la primera columna de la clave. Si este valor falta, la línea corresponde a la segunda o posterior columna de una clave de varias columnas. Para la tabla que se muestra en el ejemplo, hay dos líneas de descripción de tabla para el segundo índice. Esto indica que es un índice de varias partes con dos partes.

•Start

Dónde en la fila comienza esta porción del índice.

•Len

Cuánto mide esta porción del índice. Para números empaquetados, siempre debe ser la longitud completa de la columna. Para cadenas, puede ser más corta que la longitud completa de la columna indexada, ya que puede indexar un prefijo de una columna de cadena. La longitud total de una clave de varias partes es la suma de los valores Len de todas las partes de la clave.

•Index

Si un valor de clave puede existir varias veces en el índice. Los valores posibles son unique o multip. (múltiple).

•Type

Qué tipo de datos tiene esta porción del índice. Este es un tipo de datos MyISAM con los posibles v

MYISAMCHK TABLE INFORMATION

The options for myisamchk are described in detail in the following sections. You can see this information by running myisamchk -i -v (or myisamchk -eiv for more details).

The first part of the output describes the table itself:

•Name

The name of the table.

•Rows

The number of rows.

•Recordlength

The average row length. For tables with fixed-length rows, this is the exact row length, because all rows have the same length.

•Table scan statistics

These statistics are used to optimize the table.

•Packed

The percentage of space saved by packing the character strings in the table. The strings are packed by stripping trailing spaces. This value is used for CHAR and VARCHAR columns.

•Recordspace used

The percentage of the data file that is used.

•Empty space

The percentage of the data file that is unused.

•Blocks/Record

The average number of blocks per row. For fixed-length tables, this value is always 1.0. For dynamic tables, this value indicates how fragmented the table is. A value far from 1.0 means that the table needs to be reorganized.

•Record blocks

The number of blocks (links) used for storing rows. For fixed-length tables, this is the same as the number of rows.

•Delete blocks

The number of deleted blocks that still have reserved space. You can optimize your table to minimize this space. See Section 6.6.4, “MyISAM Table Optimization”.

•Record data

The number of bytes used in the data file.

•Deleted data

The number of bytes in the data file that are deleted (unused).

•Lost space

The sum of space lost when rows are updated to a shorter length. This space cannot be reused.

•Linkdata

The total size of pointers used to link row fragments in dynamic tables.

The next part of the output describes the indexes:

•Index

The index number.

•Keyblocks used

The percentage of keyblocks that are used. This value should be close to 100%.

•Packed

The percentage of space saved by packing duplicate keys. This is used for indexes on CHAR and VARCHAR columns.

•Max levels

The depth of the B-tree for this index. This value should be as small as possible.

•Root

Address of the root index block.

•Blocksize

The size of each index block. By default this is 1024, but the value may be changed at compile time when MariaDB is built from source.

•Rec/key

This is a statistical value used by the optimizer. It tells how many rows there are per value for this index. A unique index always has a value of 1. This may be updated after a table is loaded (or greatly changed) with myisamchk -a. If this is not updated at all, a default value of 30 is given.

The last part of the output provides information about each column:

•Field

The column number.

•Start

The byte position of the column within table rows.

•Length

The length of the column in bytes.

•Nullpos, Nullbit

For columns that can be NULL, MyISAM stores NULL values as a flag in a byte. Depending on how many nullable columns there are, there can be one or more bytes used for this purpose. The Nullpos and Nullbit values, if nonempty, indicate which byte and bit contains that flag indicating whether the column is NULL.

The position and number of bytes used to store NULL flags is shown in the line for field 1. This is why there are six Field lines for the person table even though it has only five columns.

•Type

The data type. The value may contain any of the following descriptors:

•constant

All rows have the same value.

•no endspace

Do not store endspace.

•no endspace, not_always

Do not store endspace and do not do endspace compression for all values.

•no endspace, no empty

Do not store endspace. Do not store empty values.

•table-lookup

The column was converted to an ENUM.

•zerofill(N)

The most significant N bytes in the value are always 0 and are not stored.

•no zeros

Do not store zeros.

•always zero

Zero values are stored using one bit.

•Huff tree

The number of the Huffman tree associated with the column.

•Bits

The number of bits used in the Huffman tree.

The Huff tree and Bits fields are displayed if the table has been compressed with myisampack. See myisampack(1), for an example of this information.

myisamchk -eiv output includes the following information:

•Data records

The number of rows in the table.

•Deleted blocks

How many deleted blocks still have reserved space. You can optimize your table to minimize this space. See Section 6.6.4, “MyISAM Table Optimization”.

•Key

The key number.

•Keyblocks used

What percentage of the keyblocks are used. When a table has just been reorganized with myisamchk, the values are very high (very near theoretical maximum).

MariaDB tries to pack key values that have a common suffix. This can only be used for indexes on CHAR and VARCHAR columns. For long indexed strings that have similar leftmost parts, this can significantly reduce the space used. In the preceding example, the second key is 40 bytes long and a 97% reduction in space is achieved.

•Max levels

How deep the B-tree for this key is. Large tables with long key values get high values.

•Records

How many rows are in the table.

•M.recordlength

The average row length. This is the exact row length for tables with fixed-length rows, because all rows have the same length.

MariaDB strips spaces from the end of strings. The Packed value indicates the percentage of savings achieved by doing this.

•Recordspace used

What percentage of the data file is used.

•Empty space

What percentage of the data file is unused.

•Blocks/Record

Average number of blocks per row (that is, how many links a fragmented row is composed of). This is always 1.0 for fixed-format tables. This value should stay as close to 1.0 as possible. If it gets too large, you can reorganize the table. See Section 6.6.4, “MyISAM Table Optimization”.

How many blocks (links) are used. For fixed-format tables, this is the same as the number of rows.

•Deleteblocks

How many blocks (links) are deleted.

•Recorddata

How many bytes in the data file are used.

•Deleted data

How many bytes in the data file are deleted (unused).

•Lost space

If a row is updated to a shorter length, some space is lost. This is the sum of all such losses, in bytes.

•Linkdata

When the dynamic table format is used, row fragments are linked with pointers (4 to 7 bytes each). Linkdata is the sum of the amount of storage used by all such pointers.

MYISAMCHK MEMORY USAGE

Memory allocation is important when you run myisamchk. myisamchk uses no more memory than its memory-related variables are set to. If you are going to use myisamchk on very large tables, you should first decide how much memory you want it to use. The default is to use only about 3MB to perform repairs. By using larger values, you can get myisamchk to operate faster. For example, if you have more than 32MB RAM, you could use options such as these (in addition to any other options you might specify):

shell> myisamchk --sort_buffer_size=16M \
           --key_buffer_size=16M \
           --read_buffer_size=1M \
           --write_buffer_size=1M ...

Using --sort_buffer_size=16M should probably be enough for most cases.

Be aware that myisamchk uses temporary files in TMPDIR. If TMPDIR points to a memory file system, out of memory errors can easily occur. If this happens, run myisamchk with the --tmpdir=path option to specify a directory located on a file system that has more space.

When performing repair operations, myisamchk also needs a lot of disk space:

•Twice the size of the data file (the original file and a copy). This space is not needed if you do a repair with --quick; in this case, only the index file is re-created. This space must be available on the same file system as the original data file, as the copy is created in the same directory as the original.
•Space for the new index file that replaces the old one. The old index file is truncated at the start of the repair operation, so you usually ignore this space. This space must be available on the same file system as the original data file.
•When using --recover or --sort-recover (but not when using --safe-recover), you need space on disk for sorting. This space is allocated in the temporary directory (specified by TMPDIR or --tmpdir=path). The following formula yields the amount of space required: 
(largest_key + row_pointer_length) × number_of_rows × 2

You can check the length of the keys and the row_pointer_length with myisamchk -dv tbl_name (see the section called “MYISAMCHK TABLE INFORMATION”). The row_pointer_length and number_of_rows values are the Datafile pointer and Data records values in the table description. To determine the largest_key value, check the Key lines in the table description. The Len column indicates the number of bytes for each key part. For a multiple-column index, the key size is the sum of the Len values for all key parts.

If you have a problem with disk space during repair, you can try --safe-recover instead of --recover.
