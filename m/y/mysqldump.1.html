MARIADB-DUMP(1) Sistema de bases de datos MariaDB MARIADB-DUMP(1)

NOMBRE

mariadb-dump - un programa de copia de seguridad de bases de datos (mariadb-dump es ahora un enlace simbólico a mariadb-dump)

SINOPSIS

mariadb-dump [opciones] [nombre_db [nombre_tabla ...]]

DESCRIPCIÓN

El cliente mariadb-dump es un programa de copia de seguridad escrito originalmente por Igor Romanenko. Se puede utilizar para volcar una base de datos o una colección de bases de datos para su copia de seguridad o transferencia a otro servidor SQL (no necesariamente un servidor MariaDB). El volcado típicamente contiene sentencias SQL para crear la tabla, poblarla, o ambas cosas. Sin embargo, mariadb-dump también se puede utilizar para generar archivos en formato CSV, otros textos delimitados o XML.

Si está realizando una copia de seguridad en el servidor y todas sus tablas son de tipo MyISAM, considere usar mariadb-hotcopy en su lugar, ya que puede realizar copias de seguridad y restauraciones más rápidas. Vea mariadb-hotcopy(1).

Hay cuatro formas generales de invocar mariadb-dump:

shell> mariadb-dump [opciones] nombre_db [nombre_tabla ...]
shell> mariadb-dump [opciones] --databases nombre_db ...
shell> mariadb-dump [opciones] --all-databases
shell> mariadb-dump [opciones] --system={opciones}

Si no se nombran tablas después de nombre_db o si se utiliza la opción --databases o --all-databases, se vuelcan bases de datos enteras.

mariadb-dump no vuelca las bases de datos INFORMATION_SCHEMA o performance_schema por defecto. Para volcar estas, nómbrelas explícitamente en la línea de comandos, aunque también deberá usar la opción --skip-lock-tables.

Para ver una lista de las opciones que su versión de mariadb-dump soporta, ejecute mariadb-dump --help.

Algunas opciones de mariadb-dump son abreviaturas de grupos de otras opciones:

•El uso de --opt es lo mismo que especificar --add-drop-table, --add-locks, --create-options, --disable-keys, --extended-insert, --lock-tables, --quick, y --set-charset. Todas las opciones que representan --opt también están activadas por defecto porque --opt está activado por defecto.
•El uso de --compact es lo mismo que especificar las opciones --skip-add-drop-table, --skip-add-locks, --skip-comments, --skip-disable-keys, y --skip-set-charset.

Para revertir el efecto de una opción de grupo, use su forma --skip-xxx (--skip-opt o --skip-compact). También es posible seleccionar solo parte del efecto de una opción de grupo siguiéndola con opciones que habilitan o deshabilitan características específicas. Aquí hay algunos ejemplos:

•Para seleccionar el efecto de --opt excepto para algunas características, use la opción --skip para cada característica. Para deshabilitar inserciones extendidas y almacenamiento en búfer de memoria, use --opt --skip-extended-insert --skip-quick. (De hecho, --skip-extended-insert --skip-quick es suficiente porque --opt está activado por defecto.)
•Para revertir --opt para todas las características excepto la deshabilitación de índices y el bloqueo de tablas, use --skip-opt --disable-keys --lock-tables.

Cuando habilita o deshabilita selectivamente el efecto de una opción de grupo, el orden es importante porque las opciones se procesan de principio a fin. Por ejemplo, --disable-keys --lock-tables --skip-opt no tendría el efecto deseado; es lo mismo que --skip-opt por sí solo.

mariadb-dump puede recuperar y volcar contenido de tablas fila por fila, o puede recuperar todo el contenido de una tabla y almacenarlo en memoria antes de volcarlo. El almacenamiento en memoria puede ser un problema si está volcando tablas grandes. Para volcar tablas fila por fila, use la opción --quick (o --opt, que habilita --quick). La opción --opt (y por lo tanto --quick) está habilitada por defecto, así que para habilitar el almacenamiento en memoria, use --skip-quick.

Si está utilizando una versión reciente de mariadb-dump para generar un volcado que se recargará en un servidor MySQL muy antiguo, no debe usar la opción --opt o --extended-insert. Use --skip-opt en su lugar.

mariadb-dump soporta las siguientes opciones, que se pueden especificar en la línea de comandos o en los grupos de archivos de opciones [mariadb-dump] y [client]. mariadb-dump también soporta las opciones para procesar archivos de opciones.

•--help, -?

Muestra un mensaje de ayuda y sale.

•--add-drop-database

Añade una sentencia DROP DATABASE antes de cada sentencia CREATE DATABASE. Esta opción se usa típicamente junto con la opción --all-databases o --databases porque no se escriben sentencias CREATE DATABASE a menos que se especifique una de esas opciones.

•--add-drop-table

Añade una sentencia DROP TABLE antes de cada sentencia CREATE TABLE.

•--add-drop-trigger

Añade una sentencia DROP TRIGGER antes de cada sentencia CREATE TRIGGER.

•--add-locks

Rodea cada volcado de tabla con sentencias LOCK TABLES y UNLOCK TABLES. Esto resulta en inserciones más rápidas cuando se recarga el archivo de volcado.

•--all-databases, -A

Vuelca todas las tablas en todas las bases de datos. Es lo mismo que usar la opción --databases y nombrar todas las bases de datos en la línea de comandos.

•--all-tablespaces, -Y

Añade a un volcado de tabla todas las sentencias SQL necesarias para crear cualquier tablespace utilizado por una tabla NDBCLUSTER. Esta información no se incluye de otro modo en la salida de mariadb-dump. Esta opción es actualmente relevante solo para tablas de MySQL Cluster.

•--allow-keywords

Permite la creación de nombres de columna que son palabras clave. Esto funciona anteponiendo el nombre de la tabla a cada nombre de columna.

•--apply-slave-statements

Añade 'STOP SLAVE' antes de 'CHANGE MASTER' y 'START SLAVE' al final del volcado.

•--as-of=nombre

Vuelca la tabla versionada por sistema como en la marca de tiempo especificada.

•--character-sets-dir=ruta

El directorio donde se instalan los conjuntos de caracteres.

•--comments, -i

Escribe información adicional en el archivo de volcado, como la versión del programa, la versión del servidor y el host. Esta opción está activada por defecto. Para suprimir esta información adicional, use --skip-comments.

•--compact

Produce una salida más compacta. Esta opción habilita las opciones --skip-add-drop-table, --skip-add-locks, --skip-comments, --skip-disable-keys, y --skip-set-charset.

•--compatible=nombre

Produce una salida que es más compatible con otros sistemas de bases de datos o con servidores MySQL más antiguos. El valor de nombre puede ser ansi, mysql323, mysql40, postgresql, oracle, mssql, db2, maxdb, no_key_options, no_table_options, o no_field_options. Para usar varios valores, sepárelos por comas. Estos valores tienen el mismo significado que las opciones correspondientes para establecer el modo SQL del servidor.

Esta opción no garantiza la compatibilidad con otros servidores. Solo habilita aquellos valores de modo SQL que están disponibles actualmente para hacer que la salida del volcado sea más compatible. Por ejemplo, --compatible=oracle no mapea tipos de datos a tipos de Oracle ni usa sintaxis de comentarios de Oracle.

•--complete-insert, -c

Usa sentencias INSERT completas que incluyen nombres de columna.

•--compress, -C

Comprime toda la información enviada entre el cliente y el servidor si ambos soportan compresión.

•--copy-s3-tables

Por defecto, las tablas S3 se ignoran. Con esta opción activada, el archivo de resultado contendrá una sentencia CREATE para una tabla Aria similar, seguida de los datos de la tabla y terminando con un ALTER TABLE xxx ENGINE=S3.

•--create-options, -a

Incluye todas las opciones de tabla específicas de MariaDB en la sentencia CREATE TABLE.

Opciones
•--skip-create-options

Omite las opciones CREATE TABLE en la salida. Utiliza --skip-create-options para deshabilitar.

•--databases, -B

Exportar varias bases de datos. Normalmente, mariadb-dump trata el primer argumento de nombre en la línea de comandos como un nombre de base de datos y los nombres siguientes como nombres de tabla. Con esta opción, trata todos los argumentos de nombre como nombres de base de datos. Las sentencias CREATE DATABASE y USE se incluyen en la salida antes de cada nueva base de datos.

•--debug[=debug_options], -# [debug_options]

Escribe un registro de depuración. Una cadena típica de debug_options es 'd:t:o,nombre_archivo'. El valor predeterminado es 'd:t:o,/tmp/mariadb-dump.trace'.

•--debug-check

Imprime información de depuración al salir del programa.

•--debug-info

Imprime información de depuración y estadísticas de uso de memoria y CPU al salir del programa.

•--default-auth

Plugin de cliente de autenticación predeterminado a utilizar.

•--default-character-set=charset_name

Utiliza charset_name como conjunto de caracteres predeterminado. Si no se especifica ningún conjunto de caracteres, mariadb-dump utiliza utf8.

•--defaults-extra-file=filename

Establece filename como el archivo del que leer las opciones predeterminadas después de que se hayan leído los archivos de opciones globales. Debe especificarse como la primera opción.

•--defaults-file=filename

Establece filename como el archivo del que leer las opciones predeterminadas, anulando los archivos de opciones globales. Debe especificarse como la primera opción.

•--defaults-group-suffix=str,

Lee también los grupos con un sufijo de str. Por ejemplo, dado que mariadb-dump normalmente lee los grupos [client] y [mariadb-dump], --defaults-group-suffix=x haría que también leyera los grupos [mariadb-dump_x] y [client_x].

•--delayed-insert

Escribe sentencias INSERT DELAYED en lugar de sentencias INSERT.

•--delete-master-logs

En un servidor de replicación maestro, elimina los registros binarios enviando una sentencia PURGE BINARY LOGS al servidor después de realizar la operación de exportación. Esta opción habilita automáticamente --master-data.

•--dir

Exportación paralela de múltiples bases de datos. Funciona igual que --tab, con respecto a la salida (archivo sql para la definición de tabla y separado por tabulaciones para los datos, mismas opciones, por ejemplo --parallel). También permite las opciones --databases y --all-databases. Cuando se utiliza --dir, crea la estructura de directorios en el directorio de salida señalado por --dir. Para cada base de datos a exportar, habrá un directorio con el nombre de la base de datos. Todas las opciones que --tab soporta también son soportadas por --dir, en particular --parallel.

•--disable-keys, -K

Para cada tabla, rodea las sentencias INSERT con las sentencias /*!40000 ALTER TABLE tbl_name DISABLE KEYS */; y /*!40000 ALTER TABLE tbl_name ENABLE KEYS */;. Esto hace que la carga del archivo de exportación sea más rápida porque los índices se crean después de insertar todas las filas. Esta opción solo es efectiva para índices no únicos de tablas MyISAM.

•--dump-date

Si se proporciona la opción --comments, mariadb-dump produce un comentario al final de la exportación de la siguiente forma:

-- Dump completed on DATE

Sin embargo, la fecha hace que los archivos de exportación tomados en diferentes momentos parezcan diferentes, incluso si los datos son idénticos. --dump-date y --skip-dump-date controlan si la fecha se agrega al comentario. El valor predeterminado es --dump-date (incluir la fecha en el comentario). --skip-dump-date suprime la impresión de la fecha.

•--dump-history

Exporta tablas con historial. Hasta esta opción, mariadb-dump no podía leer filas históricas de tablas versionadas, por lo que los datos históricos no se respaldarían.

•--dump-slave[=value]

Se utiliza para producir un archivo de exportación desde un servidor esclavo de replicación que se pueda usar para configurar otro servidor esclavo con el mismo maestro. Hace que la posición y el nombre de archivo del registro binario del maestro se agreguen a la salida de datos exportados. Establecer el valor en 1 (el valor predeterminado) lo imprimirá como un comando CHANGE MASTER en la salida de datos exportados; si se establece en 2, ese comando se prefijará con un símbolo de comentario. Esta opción activará --lock-all-tables, a menos que también se especifique --single-transaction (en cuyo caso solo se tomará un bloqueo de lectura global durante un corto tiempo al principio de la exportación - no olvides leer sobre --single-transaction a continuación). En todos los casos, cualquier acción sobre los registros ocurrirá en el momento exacto de la exportación. La opción desactiva automáticamente --lock-tables. Usar esta opción hace que mariadb-dump detenga el hilo SQL del esclavo antes de comenzar la exportación y lo reinicie nuevamente después de completarla.

•--events, -E

Incluye los eventos del Programador de Eventos para las bases de datos exportadas en la salida.

•--extended-insert, -e

Utiliza la sintaxis INSERT de múltiples filas que incluyen varias listas VALUES. Esto resulta en un archivo de exportación más pequeño y acelera las inserciones cuando se recarga el archivo.

•--fields-terminated-by=..., --fields-enclosed-by=..., --fields-optionally-enclosed-by=..., --fields-escaped-by=...

Estas opciones se utilizan con la opción --tab y tienen el mismo significado que las cláusulas FIELDS correspondientes para LOAD DATA INFILE.

•--first-slave

Eliminado en MariaDB 5.5. Utiliza --lock-all-tables en su lugar.

•--flush-logs, -F

Vacía los archivos de registro del servidor MariaDB antes de iniciar la exportación. Esta opción requiere el privilegio RELOAD. Si usas esta opción en combinación con la opción --all-databases, los registros se vacían *para cada base de datos exportada*. La excepción es cuando se usa --lock-all-tables o --master-data: En este caso, los registros se vacían solo una vez, correspondiente al momento en que todas las tablas se bloquean. Si deseas que tu exportación y el vaciado de registros ocurran exactamente en el mismo momento, debes usar --flush-logs junto con --lock-all-tables o --master-data.

•--flush-privileges

Envía una sentencia FLUSH PRIVILEGES al servidor después de exportar la base de datos mysql. Esta opción debe usarse cada vez que la exportación contenga la base de datos mysql y cualquier otra base de datos que dependa de los datos en la base de datos mysql para una restauración adecuada.

•--force, -f

Continúa incluso si ocurre un error SQL durante la exportación de una tabla.

Un uso para esta opción es hacer que mariadb-dump continúe ejecutándose incluso cuando encuentra una vista que se ha vuelto inválida porque la definición se refiere a una tabla que ha sido eliminada. Sin --force, mariadb-dump sale con un mensaje de error. Con --force, mariadb-dump imprime el mensaje de error, pero también escribe un comentario SQL que contiene la definición de la vista en la salida de exportación y continúa ejecutándose.

•--gtid

Disponible desde MariaDB 10.0.13, y se usa junto con --master-data y --dump-slave para configurar más convenientemente un nuevo esclavo GTID. Hace que esas opciones generen sentencias SQL que configuran el esclavo para usar el ID de transacción global para conectarse al maestro en lugar de las posiciones de nombre de archivo/desplazamiento de estilo antiguo. Las posiciones de estilo antiguo todavía se incluyen en comentarios cuando se usa --gtid; de manera similar, la posición GTID se incluye en comentarios incluso si no se usa --gtid.

•--header

Se utiliza junto con --tab. Cuando está habilitado, agrega una cabecera con nombres de columna en la parte superior de los archivos txt de salida.

•--hex-blob

Exporta columnas binarias usando notación hexadecimal (por ejemplo, 'abc' se convierte en 0x616263). Los tipos de datos afectados son BINARY, VARBINARY, los tipos BLOB y BIT.

•--host=host_name, -h host_name

Exporta datos desde el servidor MariaDB en el host proporcionado. El host predeterminado es localhost.

•--ignore-table=db_name.tbl_name

No exporta la tabla dada, que debe especificarse utilizando tanto el nombre de la base de datos como el nombre de la tabla. Para ignorar múltiples tablas, usa esta opción varias veces. Esta opción también se puede usar para ignorar vistas.

•--include-master-host-port

Agrega las opciones MASTER_HOST y MASTER_PORT para la sentencia CHANGE MASTER TO cuando se utiliza la opción --dump-slave para una exportación esclava.

•--insert-ignore

Escribe sentencias INSERT IGNORE en lugar de sentencias INSERT.

•--lines-terminated-by=...

Esta opción se utiliza con la opción --tab y tiene el mismo significado que la cláusula LINES correspondiente para LOAD DATA INFILE.

•--lock-all-tables, -x

Bloquea todas las tablas en todas las bases de datos. Esto se logra adquiriendo un bloqueo de lectura global durante la exportación completa. Esta opción deshabilita automáticamente --single-transaction y --lock-tables.

•--lock-tables, -l

Para cada base de datos exportada, bloquea todas las tablas a exportar antes de exportarlas. Las tablas se bloquean con READ LOCAL para permitir inserciones concurrentes en el caso de tablas MyISAM. Para tablas transaccionales como InnoDB, --single-transaction es una opción mucho mejor que --lock-tables porque no necesita bloquear las tablas en absoluto.

Debido a que --lock-tables bloquea tablas para cada base de datos por separado, esta opción no garantiza que las tablas en el archivo de exportación sean lógicamente consistentes entre bases de datos. Las tablas en diferentes bases de datos pueden ser exportadas en estados completamente diferentes.

Utiliza --skip-lock-tables para deshabilitar.

•--log-error=file_name

Registra advertencias y errores agregándolos al archivo nombrado. El valor predeterminado es no registrar.

•--log-queries

Al restaurar la exportación, el servidor, si el registro está activado, registrará las consultas en el registro general y de consultas lentas. Predeterminado en activado; utiliza --skip-log-que

es para deshabilitar.

•--master-data[=valor]

Use esta opción para volcar un servidor de replicación maestro y producir un archivo de volcado que pueda ser usado para configurar otro servidor como esclavo del maestro. Causa que la salida del volcado incluya una sentencia CHANGE MASTER TO que indica las coordenadas del log binario (nombre de archivo y posición) del servidor volcado. Estas son las coordenadas del servidor maestro desde las cuales el esclavo debe comenzar a replicar después de cargar el archivo de volcado en el esclavo.

Si el valor de la opción es 2, la sentencia CHANGE MASTER TO se escribe como un comentario SQL, y por lo tanto es solo informativa; no tiene efecto cuando se recarga el archivo de volcado. Si el valor de la opción es 1, la sentencia no se escribe como comentario y surte efecto cuando se recarga el archivo de volcado. Si no se especifica ningún valor de opción, el valor predeterminado es 1.

Esta opción requiere el privilegio RELOAD y el log binario debe estar habilitado.

La opción --master-data desactiva automáticamente --lock-tables. También activa --lock-all-tables, a menos que también se especifique --single-transaction. En todos los casos, cualquier acción sobre los logs ocurre en el momento exacto del volcado.

También es posible configurar un esclavo volcando un esclavo existente del maestro. Para hacerlo, use el siguiente procedimiento en el esclavo existente:

1.Detenga el hilo SQL del esclavo y obtenga su estado actual: 
mariadb> STOP SLAVE SQL_THREAD;
mariadb> SHOW SLAVE STATUS;
2.De la salida de la sentencia SHOW SLAVE STATUS, las coordenadas del log binario del servidor maestro desde las cuales el nuevo esclavo debe comenzar a replicar son los valores de los campos Relay_Master_Log_File y Exec_Master_Log_Pos. Denomine esos valores como nombre_archivo y pos_archivo.
3.Vuelque el servidor esclavo: 
shell> mariadb-dump --master-data=2 --all-databases > volcado_archivo
4.Reinicie el esclavo: 
mariadb> START SLAVE;
5.En el nuevo esclavo, cargue el archivo de volcado: 
shell> mariadb < volcado_archivo
6.En el nuevo esclavo, establezca las coordenadas de replicación a las del servidor maestro obtenidas anteriormente: 
mariadb> CHANGE MASTER TO
    -> MASTER_LOG_FILE = 'nombre_archivo', MASTER_LOG_POS = pos_archivo;

La sentencia CHANGE MASTER TO también podría necesitar otros parámetros, como MASTER_HOST para apuntar el esclavo al host correcto del servidor maestro. Agregue cualquier parámetro de este tipo según sea necesario.

•--max-allowed-packet=longitud

Establece la longitud máxima del paquete a enviar o recibir del servidor.

•--max-statement-time=segundos

Establece el tiempo máximo que puede ejecutarse una sentencia antes de que el servidor la cancele por tiempo de espera. (Valor predeterminado es 0 (sin límite))

•--net-buffer-length=longitud

Establece el tamaño del búfer para la comunicación TCP/IP y socket.

•--no-autocommit

Incluye las sentencias INSERT para cada tabla volcada entre las sentencias SET autocommit = 0 y COMMIT.

•--no-create-db, -n

Esta opción suprime las sentencias CREATE DATABASE que de lo contrario se incluyen en la salida si se proporciona la opción --databases o --all-databases.

•--no-create-info, -t

No escriba sentencias CREATE TABLE que recrean cada tabla volcada.

•--no-data, -d

No escriba información de filas de tabla (es decir, no vuelque el contenido de las tablas). Esto es útil si desea volcar solo la sentencia CREATE TABLE para la tabla (por ejemplo, para crear una copia vacía de la tabla cargando el archivo de volcado).

•--no-defaults

No lea opciones predeterminadas de ningún archivo de opciones. Esto debe proporcionarse como el primer argumento.

•--no-set-names, -N

Esto tiene el mismo efecto que --skip-set-charset.

•--opt

Esta opción es un atajo. Es lo mismo que especificar --add-drop-table --add-locks --create-options --disable-keys --extended-insert --lock-tables --quick --set-charset. Debería proporcionarle una operación de volcado rápida y producir un archivo de volcado que pueda ser recargado en un servidor MariaDB rápidamente.

La opción --opt está habilitada por defecto. Use --skip-opt para deshabilitarla. Consulte la discusión al principio de esta sección para obtener información sobre cómo habilitar o deshabilitar selectivamente un subconjunto de las opciones afectadas por --opt.

•--order-by-primary

Vuelca las filas de cada tabla ordenadas por su clave primaria, o por su primer índice único, si existe dicho índice. Esto es útil al volcar una tabla MyISAM para cargarla en una tabla InnoDB, pero hará que la operación de volcado tarde considerablemente más.

•--order-by-size

Vuelca cada tabla de acuerdo a su tamaño, comenzando por la más pequeña. Útil cuando se usa --single-transaction en tablas que son truncadas/alteradas a menudo. La suposición aquí es que las tablas más pequeñas se truncan con más frecuencia, y al volcarlas primero, esto reduce la posibilidad de que un volcado --single-transaction falle con

•--parallel=#, -j

Número de trabajos de volcado de tablas ejecutados en paralelo (solo para usar con la opción --tab). Las pruebas iniciales indican que el rendimiento puede mejorar (tiempo de volcado reducido) hasta 4 veces en volcados de menor tamaño, cuando la base de datos cabe en memoria. Hay un punto en el que el disco se convierte en el cuello de botella, después del cual agregar más trabajos paralelos no mejora el rendimiento.

• --password[=contraseña], -p[contraseña]

La contraseña a usar al conectarse al servidor. Si usa la forma corta de la opción (-p), *no* puede haber un espacio entre la opción y la contraseña. Si omite el valor contraseña después de la opción --password o -p en la línea de comandos, mariadb-dump le solicitará una.

Especificar una contraseña en la línea de comandos debe ser considerado inseguro. Puede usar un archivo de opciones para evitar proporcionar la contraseña en la línea de comandos.

•--pipe, -W

En Windows, conéctese al servidor a través de una tubería con nombre. Esta opción solo se aplica si el servidor admite conexiones de tuberías con nombre.

•--plugin-dir

Directorio para plugins del lado del cliente.

•--port=num_puerto, -P num_puerto

El número de puerto TCP/IP a usar para la conexión. Fuerza --protocol=tcp cuando se especifica en la línea de comandos sin otras propiedades de conexión.

•--protocol={TCP|SOCKET|PIPE|MEMORY}

El protocolo de conexión a usar para conectarse al servidor. Es útil cuando los otros parámetros de conexión normalmente causarían que se use un protocolo diferente al que desea.

•--quick, -q

Esta opción es útil para volcar tablas grandes. Fuerza a mariadb-dump a recuperar las filas para una tabla del servidor una fila a la vez en lugar de recuperar todo el conjunto de filas y almacenarlo en búfer en memoria antes de escribirlo.

•--print-defaults

Imprime la lista de argumentos del programa y sale. Esto debe proporcionarse como el primer argumento.

•--quote-names, -Q

Comilla identificadores (como nombres de bases de datos, tablas y columnas) entre caracteres “`”. Si el modo SQL ANSI_QUOTES está habilitado, los identificadores se citan entre caracteres “"”. Esta opción está habilitada por defecto. Se puede deshabilitar con --skip-quote-names, pero esta opción debe proporcionarse después de cualquier opción como --compatible que pueda habilitar --quote-names.

•--replace

Escribe sentencias REPLACE en lugar de sentencias INSERT.

•--result-file=nombre_archivo, -r nombre_archivo

Dirige la salida a un archivo determinado. Esta opción debe usarse en Windows para evitar que los caracteres de nueva línea “\n” se conviertan en secuencias de retorno de carro/nueva línea “\r\n”. El archivo de resultado se crea y su contenido previo se sobrescribe, incluso si ocurre un error al generar el volcado.

•--routines, -R

Incluye rutinas almacenadas (procedimientos y funciones) para las bases de datos volcadas en la salida. El uso de esta opción requiere el privilegio SELECT para la tabla mysql.proc. La salida generada al usar --routines contiene sentencias CREATE PROCEDURE y CREATE FUNCTION para recrear las rutinas. Sin embargo, estas sentencias no incluyen atributos como las marcas de tiempo de creación y modificación de la rutina. Esto significa que cuando se recarguen las rutinas, se crearán con marcas de tiempo iguales al momento de la recarga.

Si requiere que las rutinas se recarguen con sus atributos de marca de tiempo originales, no use --routines. En su lugar, vuelque y recargue directamente el contenido de la tabla mysql.proc, usando una cuenta MariaDB que tenga privilegios apropiados para la base de datos mysql.

•--set-charset

Agrega SET NAMES juego_caracteres_predeterminado a la salida. Esta opción está habilitada por defecto. Para suprimir la sentencia SET NAMES, use --skip-set-charset.

•--single-transaction

Esta opción envía una sentencia SQL START TRANSACTION al servidor antes de volcar los datos. Es útil solo con tablas transaccionales como InnoDB, ya que entonces vuelca el estado consistente de la base de datos en el momento en que se emitió BEGIN sin bloquear ninguna aplicación.

Al usar esta opción, debe tener en cuenta que solo las tablas InnoDB se vuelcan en un estado consistente. Por ejemplo, cualquier tabla MyISAM o MEMORY volcada mientras se usa esta opción aún puede cambiar de estado.

Mientras se está procesando un volcado --single-transaction, para garantizar un archivo de volcado válido (contenido de tabla y coordenadas de log binario correctos), ninguna otra conexión debe usar las siguientes sentencias: ALTER TABLE, CREATE TABLE, DROP TABLE, RENAME TABLE, TRUNCATE TABLE. Una lectura consistente no está aislada de esas sentencias, por lo que el uso de laen una tabla que se va a volcar puede causar que el SELECT que realiza mariadb-dump para recuperar el contenido de la tabla obtenga contenido incorrecto o falle.

La opción --single-transaction y la opción --lock-tables son mutuamente excluyentes porque LOCK TABLES causa que cualquier transacción pendiente se confirme implícitamente.

Para volcar tablas grandes, debe combinar la opción --single-transaction con --quick.

Para conexiones a localhost, el archivo de socket Unix a usar, o, en Windows, el nombre del named pipe a usar. Fuerza --protocol=socket cuando se especifica en la línea de comandos sin otras propiedades de conexión; en Windows, fuerza --protocol=pipe.

•--ssl

Habilita SSL para la conexión (activado automáticamente con otras banderas). Deshabilita con --skip-ssl.

•--ssl-ca=nombre

Archivo CA en formato PEM (consultar documentación de OpenSSL, implica --ssl).

•--ssl-capath=nombre

Directorio CA (consultar documentación de OpenSSL, implica --ssl).

•--ssl-cert=nombre

Certificado X509 en formato PEM (consultar documentación de OpenSSL, implica --ssl).

•--ssl-cipher=nombre

Cifra SSL a usar (consultar documentación de OpenSSL, implica --ssl).

•--ssl-key=nombre

Clave X509 en formato PEM (consultar documentación de OpenSSL, implica --ssl).

•--ssl-crl=nombre

Lista de revocación de certificados (consultar documentación de OpenSSL, implica --ssl).

•--ssl-crlpath=nombre

Ruta de la lista de revocación de certificados (consultar documentación de OpenSSL, implica --ssl).

•--ssl-verify-server-cert

Verifica el "Common Name" del servidor en su certificado contra el nombre de host utilizado al conectarse. Esta opción está deshabilitada por defecto.

•--system={all, users, plugins, udfs, servers, stats, timezones}

Vuelca las tablas del sistema en la base de datos mysql en forma lógica. Esta opción está vacía por defecto.

Se pueden listar una o más opciones en una lista separada por comas.

Las opciones aquí son:

•all - un alias para habilitar todas las opciones inferiores.
•users - los usuarios, roles y sus permisos se muestran como CREATE USER, CREATE ROLE, GRANT, y SET DEFAULT ROLE (ALTER USER para MySQL-8.0+).
•plugins - los plugins activos del servidor se muestran como INSTALL PLUGIN.
•udfs - las funciones definidas por el usuario se muestran como CREATE FUNCTION.
•servers - servidores remotos (federados) como CREATE SERVER.
•stats - las tablas de estadísticas, InnoDB y Estadísticas de Tabla Independientes del Motor (EITS), se vuelcan como sentencias REPLACE INTO (o INSERT IGNORE si se especifica --insert-ignore) sin (re)crear tablas.
•timezones - las tablas del sistema relacionadas con zonas horarias se vuelcan como sentencias REPLACE INTO (o INSERT IGNORE si se especifica --insert-ignore) sin (re)crear tablas.

El formato de la salida se ve afectado por --replace y --insert-ignore. La opción --replace generará formas SQL de CREATE OR REPLACE, y también DROP IF EXISTS antes de CREATE, si una opción de CREATE OR REPLACE no está disponible.

Con --system=user (o all), y --replace, se genera SQL para producir un error si se intenta importar el volcado con un usuario de conexión que está siendo reemplazado dentro del volcado.

La opción --insert-ignore hará que se generen formas SQL de CREATE IF NOT EXIST si están disponibles.

Para estadísticas y zonas horarias, --replace y --insert-ignore tienen los efectos habituales.

Habilitar opciones específicas aquí hará que las tablas relevantes en la base de datos mysql se ignoren al volcar la base de datos mysql o --all-databases.

Para ayudar en la migración de MySQL a MariaDB, esta opción está diseñada para poder volcar información del sistema de servidores MySQL-5.7 y 8.0. El SQL generado también es compatible experimentalmente con MySQL-5.7/8.0. Sin embargo, las asignaciones de permisos/plugins específicos de la implementación no siempre son uno a uno entre MariaDB y MySQL y requerirán cambios manuales.

•--tab=ruta, -T ruta

Produce archivos de datos en formato de texto separado por tabulaciones. Para cada tabla volcada, mariadb-dump crea un archivo nombre_tabla.sql que contiene la sentencia CREATE TABLE que crea la tabla, y el servidor escribe un archivo nombre_tabla.txt que contiene sus datos. El valor de la opción es el directorio en el que se escribirán los archivos.


Nota
Esta opción solo debe usarse cuando mariadb-dump se ejecuta en la misma máquina que el servidor mariadbd. Debe tener el privilegio FILE, y el servidor debe tener permiso para escribir archivos en el directorio que especifique.
Por defecto, los archivos de datos .txt se formatean usando caracteres de tabulación entre los valores de las columnas y una nueva línea al final de cada línea. El formato se puede especificar explícitamente usando las opciones --fields-xxx y --lines-terminated-by.

Los valores de las columnas se convierten al conjunto de caracteres especificado por la opción --default-character-set.

•--tables

Anula la opción --databases o -B. mariadb-dump considera todos los argumentos de nombre que siguen a la opción como nombres de tabla.

•--triggers

Incluye los triggers para cada tabla volcada en la salida. Esta opción está habilitada por defecto; deshabilítela con --skip-triggers.

•--tz-utc

Esta opción permite que las columnas TIMESTAMP se vuelquen y se recarguen entre servidores en diferentes zonas horarias. mariadb-dump establece su zona horaria de conexión a UTC y agrega SET TIME_ZONE='+00:00' al archivo de volcado. Sin esta opción, las columnas TIMESTAMP se vuelcan y recargan en las zonas horarias locales de los servidores de origen y destino, lo que puede causar que los valores cambien si los servidores están en diferentes zonas horarias. --tz-utc también protege contra cambios debidos al horario de verano. --tz-utc está habilitado por defecto. Para deshabilitarlo, use --skip-tz-utc.

•--user=nombre_usuario, -u nombre_usuario

El nombre de usuario de MariaDB a usar al conectarse al servidor.

•--verbose, -v

Modo detallado. Imprime más información sobre lo que hace el programa.

•--version, -V

Muestra información de la versión y sale.

•--where='condicion_where', -w 'condicion_where'

Vuelca solo las filas seleccionadas por la condición WHERE dada. Las comillas alrededor de la condición son obligatorias si contiene espacios u otros caracteres especiales para su intérprete de comandos.

Ejemplos:

--where="user='jimf'"
-w"userid>1"
-w"userid<1"
•--xml, -X

También puedes establecer las siguientes variables usando la sintaxis
    --nombre_var=valor:


•max_allowed_packet

El tamaño máximo del búfer para la comunicación cliente/servidor.
    El máximo es de 1GB.




•max_statement_time

Una consulta que haya tardado más de max_statement_time segundos
    será abortada y la copia de seguridad fallará. El argumento se tratará como
    un valor decimal con precisión de microsegundos. Un valor de 0 (predeterminado)
    significa que no hay tiempo de espera. El tiempo de espera máximo es de
    31536000 segundos.




•net_buffer_length

El tamaño inicial del búfer para la comunicación cliente/servidor.
    Al crear sentencias INSERT de varias filas (como con la opción
    --extended-insert o --opt), mariadb-dump crea
    filas de hasta la longitud net_buffer_length. Si aumentas esta variable,
    también debes asegurarte de que la variable net_buffer_length en el
    servidor MariaDB sea al menos tan grande como esta.




Un uso común de mariadb-dump es para hacer una copia de
    seguridad de una base de datos completa:




shell> mariadb-dump nombre_bd > archivo-copia-seguridad.sql




Puedes cargar el archivo de volcado de nuevo en el servidor de
    esta manera:




shell> mariadb nombre_bd < archivo-copia-seguridad.sql




O de esta manera:




shell> mariadb -e "source /ruta-a-copia-seguridad/archivo-copia-seguridad.sql" nombre_bd




mariadb-dump también es muy útil para poblar bases de
    datos copiando datos de un servidor MariaDB a otro:




shell> mariadb-dump --opt nombre_bd | mariadb --host=servidor_remoto -C nombre_bd




Es posible volcar varias bases de datos con un solo comando:




shell> mariadb-dump --databases nombre_bd1 [nombre_bd2 ...] > mis_bases_de_datos.sql




Para volcar todas las bases de datos, usa la opción
    --all-databases:




shell> mariadb-dump --all-databases > todas_bases_de_datos.sql




Para tablas InnoDB, mariadb-dump proporciona una forma de
    realizar una copia de seguridad en línea:




shell> mariadb-dump --all-databases --single-transaction > todas_bases_de_datos.sql




Esta copia de seguridad adquiere un bloqueo de lectura global en
    todas las tablas (usando FLUSH TABLES WITH READ LOCK) al principio del volcado.
    Tan pronto como se adquiere este bloqueo, se leen las coordenadas del registro
    binario y se libera el bloqueo. Si se están ejecutando sentencias de
    actualización largas cuando se emite la sentencia FLUSH, el servidor MariaDB
    puede detenerse hasta que esas sentencias terminen. Después de eso, el volcado
    queda libre de bloqueos y no interfiere con las lecturas y escrituras en las
    tablas. Si las sentencias de actualización que recibe el servidor MariaDB son
    cortas (en términos de tiempo de ejecución), el período de bloqueo inicial no
    debería ser notable, incluso con muchas actualizaciones.


Para la recuperación a un punto en el tiempo (también conocida como
    "avance", cuando necesitas restaurar una copia de seguridad antigua y
    reproducir los cambios que ocurrieron desde esa copia de seguridad), a menudo
    es útil rotar el registro binario o al menos conocer las coordenadas del
    registro binario a las que corresponde el volcado:




shell> mariadb-dump --all-databases --master-data=2 > todas_bases_de_datos.sql




O:




shell> mariadb-dump --all-databases --flush-logs --master-data=2
              > todas_bases_de_datos.sql




Las opciones --master-data y --single-transaction
    se pueden usar simultáneamente, lo que proporciona una forma conveniente de
    realizar una copia de seguridad en línea adecuada para usar antes de la
    recuperación a un punto en el tiempo si las tablas se almacenan utilizando el
    motor de almacenamiento InnoDB.


Si encuentras problemas al hacer copias de seguridad de vistas,
    por favor lee la sección que cubre las restricciones de las vistas, la cual
    describe una solución alternativa para hacer copias de seguridad de vistas
    cuando esto falla debido a privilegios insuficientes.
