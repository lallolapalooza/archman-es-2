MARIADB-UPGRADE(1) Sistema de bases de datos MariaDB MARIADB-UPGRADE(1)

NOMBRE

mariadb-upgrade - comprueba tablas para la actualización de MariaDB (mariadb-upgrade es ahora un enlace simbólico a mariadb-upgrade)

SINOPSIS

mariadb-upgrade [opciones]

DESCRIPCIÓN

mariadb-upgrade examina todas las tablas de todas las bases de datos en busca de incompatibilidades con la versión actual del Servidor MariaDB. mariadb-upgrade también actualiza las tablas del sistema para que puedas aprovechar los nuevos privilegios o capacidades que se hayan podido añadir.

mariadb-upgrade debe ejecutarse cada vez que actualices MariaDB.

Si se encuentra que una tabla tiene una posible incompatibilidad, mariadb-upgrade realiza una comprobación de tabla. Si se encuentran problemas, se intenta una reparación de tabla.


Nota

En Windows Server 2008 y Windows Vista, debes ejecutar mariadb-upgrade con privilegios de administrador. Puedes hacerlo ejecutando un Símbolo del sistema como Administrador y ejecutando el comando. No hacerlo puede provocar que la actualización no se ejecute correctamente.


Precaución

Siempre debes hacer una copia de seguridad de tu instalación actual de MariaDB *antes* de realizar una actualización.

Para usar mariadb-upgrade, asegúrate de que el servidor se esté ejecutando e invócalo de la siguiente manera:

shell> mariadb-upgrade [opciones]

Después de ejecutar mariadb-upgrade, detén el servidor y reinícialo para que los cambios realizados en las tablas del sistema surtan efecto.

mariadb-upgrade ejecuta los siguientes comandos para comprobar y reparar tablas y para actualizar las tablas del sistema:

mariadb-check --all-databases --check-upgrade --auto-repair
mariadb < fix_priv_tables
mariadb-check --all-databases --check-upgrade --fix-db-names --fix-table-names

Notas sobre los comandos anteriores:

•Debido a que mariadb-upgrade invoca a mariadb-check con la opción --all-databases, procesa todas las tablas de todas las bases de datos, lo que puede llevar mucho tiempo en completarse. Cada tabla se bloquea y, por lo tanto, no está disponible para otras sesiones mientras se procesa. Las operaciones de comprobación y reparación pueden consumir mucho tiempo, especialmente para tablas grandes.
•Para obtener detalles sobre las comprobaciones que implica la opción --check-upgrade, consulta la descripción de la opción FOR UPGRADE de la declaración CHECK TABLE.
•fix_priv_tables representa un script generado internamente por mariadb-upgrade que contiene sentencias SQL para actualizar las tablas en la base de datos mysql.

Todas las tablas comprobadas y reparadas se marcan con el número de versión actual de MariaDB. Esto garantiza que la próxima vez que ejecutes mariadb-upgrade con la misma versión del servidor, pueda saber si hay necesidad de comprobar o reparar la tabla de nuevo.

mariadb-upgrade también guarda el número de versión de MariaDB en un archivo llamado mariadb-upgrade_info en el directorio de datos. Esto se utiliza para comprobar rápidamente si todas las tablas se han comprobado para esta versión, de modo que se pueda omitir la comprobación de tablas. Para ignorar este archivo y realizar la comprobación independientemente, usa la opción --force.

Por esta razón, mariadb-upgrade necesita ejecutarse como un usuario con acceso de escritura al directorio de datos.

Si instalas MariaDB desde paquetes RPM en Linux, debes instalar los RPM del servidor y del cliente. mariadb-upgrade está incluido en el RPM del servidor pero requiere el RPM del cliente porque este último incluye mariadb-check.

mariadb-upgrade admite las siguientes opciones, que se pueden especificar en la línea de comandos o en los grupos de opciones [mariadb-upgrade] y [client]. Otras opciones se pasan a mariadb-check. Por ejemplo, puede ser necesario especificar la opción --password[=contraseña]. mariadb-upgrade también admite las opciones para procesar archivos de opciones.

•--help, -?

Muestra un mensaje de ayuda breve y sale.

•--basedir=ruta

Opción antigua aceptada por compatibilidad con versiones anteriores pero ignorada.

•--character-sets-dir=ruta

Opción antigua aceptada por compatibilidad con versiones anteriores pero ignorada.

•--check-if-upgrade-is-needed

Sale con un código de estado que indica si se necesita una actualización. Devuelve 0 si la actualización es necesaria o si no se pudo determinar la versión actual, 1 si no se requiere ninguna acción.

•--datadir=ruta

Opción antigua aceptada por compatibilidad con versiones anteriores pero ignorada.

•--debug=ruta, -# ruta

Para compilaciones de depuración, genera un registro de depuración.

•--debug-check

Imprime información de depuración al salir del programa.

•--debug-info, -T

Imprime información de depuración y estadísticas de uso de memoria y CPU al salir del programa.

•--default-character-set=nombre

Opción antigua aceptada por compatibilidad con versiones anteriores pero ignorada.

•--force

Ignora el archivo mariadb-upgrade_info y fuerza la ejecución de mariadb-check incluso si mariadb-upgrade ya se ha ejecutado para la versión actual de MariaDB.

•--host

Conéctate a MariaDB en el host especificado.

•--password[=contraseña], -p[contraseña]

La contraseña a utilizar al conectarse al servidor. Si usas la forma corta de la opción (-p), *no puedes* tener un espacio entre la opción y la contraseña. Si omites el valor de contraseña después de la opción --password o -p en la línea de comandos, mariadb-upgrade te la pedirá.

Especificar una contraseña en la línea de comandos debe considerarse inseguro. Puedes usar un archivo de opciones para evitar proporcionar la contraseña en la línea de comandos.

•--port=num_puerto, -P num_puerto

El número de puerto TCP/IP a utilizar para la conexión.

•--protocol={TCP|SOCKET|PIPE|MEMORY}

El protocolo de conexión a usar para conectarse al servidor. Es útil cuando los otros parámetros de conexión causarían normalmente el uso de un protocolo diferente al deseado.

•--silent

Imprime menos información.

•--socket=ruta, -S ruta

Para conexiones a localhost, el archivo de socket Unix a usar, o, en Windows, el nombre de la tubería con nombre a usar.

•--ssl

Habilita SSL para la conexión (activado automáticamente con otras banderas). Desactiva con --skip-ssl.

•--ssl-ca=nombre

Archivo CA en formato PEM (consulta la documentación de OpenSSL, implica --ssl).

•--ssl-capath=nombre

Directorio CA (consulta la documentación de OpenSSL, implica --ssl).

•--ssl-cert=nombre

Certificado X509 en formato PEM (consulta la documentación de OpenSSL, implica --ssl).

•--ssl-cipher=nombre

Cifrado SSL a usar (consulta la documentación de OpenSSL, implica --ssl).

•--ssl-key=nombre

Clave X509 en formato PEM (consulta la documentación de OpenSSL, implica --ssl).

•--ssl-crl=nombre

Lista de revocación de certificados (consulta la documentación de OpenSSL, implica --ssl).

•--ssl-crlpath=nombre

Ruta de la lista de revocación de certificados (consulta la documentación de OpenSSL, implica --ssl).

•--ssl-verify-server-cert

Verifica el "Nombre Común" del servidor en su certificado contra el nombre de host utilizado al conectarse. Esta opción está desactivada por defecto.

•--tmpdir=ruta, -t ruta

El nombre de la ruta del directorio a utilizar para crear archivos temporales.

•--upgrade-system-tables, -s

Actualiza solo las tablas del sistema de MariaDB (por ejemplo, tablas de privilegios) y no comprueba ni repara tablas de usuario. Esta opción se utiliza principalmente cuando se está actualizando de una versión anterior de MariaDB o MySQL.

Las opciones siguientes se pasan a mariadb-check y, por lo tanto, solo se aplican cuando mariadb-upgrade llama a mariadb-check (es decir, no cuando se usa --upgrade-system-tables):

•--auto-repair

Repara automáticamente las tablas que mariadb-check considera que no están bien.

•--check-upgrade

Comprueba si las tablas están formateadas para la versión actual del servidor.

•--fix-db-names

Corrige nombres de bases de datos que no son válidos.

•--fix-table-names

Corrige nombres de tablas que no son válidos.

•--use-databases=db_names

Procesa solo las bases de datos especificadas. Si se especifica esta opción, las bases de datos especificadas se procesan incluso si no están en el archivo de opciones. Las bases de datos se separan con comas.

ARCHIVOS DE OPCIONES

El programa consume automáticamente las opciones de los siguientes archivos de opción:

client
my
defaults

El archivo de opción especificado con --defaults-extra-file=nombre_archivo se lee después de los archivos de opción predeterminados del sistema, pero antes de las opciones que se encuentran en los archivos de opción predeterminados del usuario.

>Solo actualiza las tablas del sistema en la base de datos mysql. Las tablas en otras bases de datos no son verificadas ni tocadas.

•--user=nombre_usuario, -u nombre_usuario

El nombre de usuario de MariaDB a utilizar al conectarse al servidor y no utilizando el inicio de sesión actual.

•--verbose

Muestra más información sobre el proceso. Usarlo dos veces imprimirá los argumentos de conexión; usarlo 3 veces imprimirá todos los comandos CHECK, RENAME y ALTER TABLE utilizados durante la fase de verificación; usarlo 4 veces (añadido en MariaDB 10.0.14) también escribirá todos los comandos mariadb-check utilizados; usarlo 5 veces imprimirá todos los comandos de mariadb utilizados y sus resultados mientras se ejecuta el script mariadb-fix-privilege-tables.

•--version, -V

Muestra información de la versión y sale.

•--version-check, -k

Ejecuta este programa solo si su 'versión de servidor' coincide con la versión del servidor al que se conecta. Nota: la 'versión de servidor' del programa es la versión del servidor MariaDB con el que fue compilado/distribuido. Por defecto está activado; usa --skip-version-check para deshabilitarlo.

•--write-binlog

Causa que el registro binario se habilite mientras se ejecuta mariadb-upgrade.
