MYSQL_TABLE(5) Manual de formatos de archivo MYSQL_TABLE(5)

NOMBRE

mysql_table - Configuración del cliente MySQL de Postfix

SINOPSIS

postmap -q "cadena" mysql:/etc/postfix/nombrearchivo
postmap -q - mysql:/etc/postfix/nombrearchivo <archivoinicial

DESCRIPCIÓN


El sistema de correo Postfix utiliza tablas opcionales para la reescritura de direcciones o el enrutamiento de correo. Estas tablas suelen estar en formato dbm o db.

Alternativamente, las tablas de búsqueda se pueden especificar como bases de datos MySQL. Para utilizar búsquedas de MySQL, defina una fuente MySQL como tabla de búsqueda en main.cf, por ejemplo:

    alias_maps = mysql:/etc/postfix/mysql-aliases.cf

El archivo /etc/postfix/mysql-aliases.cf tiene el mismo formato que el archivo main.cf de Postfix y puede especificar los parámetros que se describen a continuación.

PERTENENCIA A LISTAS

Al usar SQL para almacenar listas como $mynetworks, $mydestination, $relay_domains, $local_recipient_maps, etc., es importante entender que la tabla debe almacenar cada miembro de la lista como una clave separada. La búsqueda en la tabla verifica la *existencia* de la clave. Consulte "Listas frente a tablas de Postfix" en el documento DATABASE_README para una discusión.

NO cree tablas que devuelvan la lista completa de dominios en $mydestination o $relay_domains, etc., o direcciones IP en $mynetworks.

SÍ cree tablas con cada elemento coincidente como clave y con un valor arbitrario. Con bases de datos SQL, no es raro devolver la propia clave o un valor constante.

PARÁMETROS MYSQL

hosts
Los hosts a los que Postfix intentará conectarse y consultar. Especifique unix: para sockets de dominio UNIX, inet: para conexiones TCP (predeterminado). Ejemplos: 
    hosts = inet:host1.some.domain inet:host2.some.domain:port
    hosts = host1.some.domain host2.some.domain:port
    hosts = unix:/file/name

Los hosts se prueban en orden aleatorio, con todas las conexiones sobre sockets de dominio UNIX probadas antes que las conexiones TCP. Las conexiones se cierran automáticamente después de estar inactivas durante aproximadamente 1 minuto y se reabren según sea necesario. Postfix versiones 2.0 y anteriores no aleatorizan el orden de los hosts.

NOTA: si especifica localhost como nombre de host (incluso si lo antepone con inet:), MySQL se conectará al socket de dominio UNIX predeterminado. Para indicar a MySQL que se conecte a localhost a través de TCP, debe especificar

    hosts = 127.0.0.1

NOTA: si la configuración hosts especifica un servidor, este cliente asume que el destino es un balanceador de carga y se reconectará inmediatamente después de un solo error, en lugar de fallar todas las solicitudes temporalmente. Con versiones anteriores de este cliente, especifique el mismo servidor dos veces.

user
password
El nombre de usuario y la contraseña para iniciar sesión en el servidor mysql. Ejemplo: 
    user = someone
    password = some_password
dbname
El nombre de la base de datos en los servidores. Ejemplo: 
    dbname = customer_database
charset (predeterminado: utf8mb4)
El conjunto de caracteres del cliente MySQL predeterminado; esto también implica el orden de intercalación.

Este parámetro está disponible con Postfix 3.9 y versiones posteriores. Con versiones anteriores de Postfix, el valor predeterminado era elegido por la implementación de MySQL (utf8mb4 a partir de MySQL 8.0, latin1 históricamente).

idle_interval (predeterminado: 60)
El número de segundos después de los cuales se cerrará una conexión de base de datos inactiva.

Esta función está disponible en Postfix 3.9 y versiones posteriores.

retry_interval (predeterminado: 60)
El número de segundos durante los cuales se omitirá una conexión de base de datos después de un error.

NOTA: si la configuración hosts especifica un servidor, este cliente asume que el destino es un balanceador de carga y se reconectará inmediatamente después de un solo error, en lugar de fallar todas las solicitudes temporalmente. Con versiones anteriores de este cliente, especifique el mismo servidor dos veces.

Esta función está disponible en Postfix 3.9 y versiones posteriores.

query
La plantilla de consulta SQL utilizada para buscar en la base de datos, donde %s es un sustituto de la dirección que Postfix está intentando resolver, por ejemplo: 
    query = SELECT replacement FROM aliases WHERE mailbox = '%s'

Por defecto, cada consulta debe devolver un conjunto de resultados (en lugar de almacenar sus resultados en una tabla); con "require_result_set = no" (Postfix 3.2 y posteriores), la ausencia de un conjunto de resultados se trata como "no encontrado".

Este parámetro admite las siguientes expansiones de '%':

%%
Esto se reemplaza por un carácter '%' literal.
%s
Esto se reemplaza por la clave de entrada. Se utilizan comillas SQL para asegurarse de que la clave de entrada no agregue metacaracteres inesperados.
%u
Cuando la clave de entrada es una dirección del tipo usuario@dominio, %u se reemplaza por la parte local de la dirección entre comillas SQL. De lo contrario, %u se reemplaza por toda la cadena de búsqueda. Si la parte local está vacía, la consulta se suprime y no devuelve resultados.
%d
Cuando la clave de entrada es una dirección del tipo usuario@dominio, %d se reemplaza por la parte del dominio entre comillas SQL de la dirección. De lo contrario, la consulta se suprime y no devuelve resultados.
%[SUD]
Los equivalentes en mayúsculas de las expansiones anteriores se comportan en el parámetro query de manera idéntica a sus contrapartes en minúsculas. Con el parámetro result_format (ver más abajo), expanden la clave de entrada en lugar del valor del resultado.
%[1-9]
Los patrones %1, %2, ... %9 se reemplazan por el componente más significativo correspondiente del dominio de la clave de entrada. Si la clave de entrada es usuario@mail.example.com, entonces %1 es com, %2 es example y %3 es mail. Si la clave de entrada no está calificada o no tiene suficientes componentes de dominio para satisfacer todos los patrones especificados, la consulta se suprime y no devuelve resultados.
El parámetro domain descrito a continuación limita las claves de entrada a las direcciones en dominios coincidentes. Cuando el parámetro domain no está vacío, las consultas SQL para direcciones no calificadas o direcciones en dominios no coincidentes se suprimen y no devuelven resultados.

Este parámetro está disponible con Postfix 2.2. En versiones anteriores, la consulta SQL se construía a partir de los parámetros separados: select_field, table, where_field y additional_conditions. El mapeo de los parámetros antiguos a la consulta equivalente es:

    SELECT [select_field]
    FROM [table]
    WHERE [where_field] = '%s'
          [additional_conditions]

El '%s' en la cláusula WHERE se expande a la cadena de búsqueda escapada. Con Postfix 2.2, estos parámetros heredados se usan si el parámetro query no se especifica.

NOTA: NO ponga comillas alrededor del parámetro query.

result_format (predeterminado: %s)
Plantilla de formato aplicada a los atributos de resultado. Se usa más comúnmente para agregar (o anteponer) texto al resultado. Este parámetro admite las siguientes expansiones de '%':
%%
Esto se reemplaza por un carácter '%' literal.
%s
Esto se reemplaza por el valor del atributo de resultado. Cuando el resultado está vacío, se omite.
%u
Cuando el valor del atributo de resultado es una dirección del tipo usuario@dominio, %u se reemplaza por la parte local de la dirección. Cuando el resultado tiene una parte local vacía, se omite.
%d
Cuando un valor de atributo de resultado es una dirección del tipo usuario@dominio, %d se reemplaza por la parte del dominio del valor del atributo. Cuando el resultado no está calificado, se omite.
%[SUD1-9]

r-case y expansiones de dígitos decimales

Los formatos r-case y de expansiones de dígitos decimales interpolan las partes de la clave de entrada en lugar del resultado. Su comportamiento es idéntico al descrito con query, y de hecho, como la clave de entrada se conoce de antemano, las consultas cuya clave no contenga toda la información especificada en la plantilla de resultado se suprimen y no devuelven resultados.

Formato de resultado

Por ejemplo, el uso de "result_format = smtp:[%s]" permite utilizar un atributo mailHost como base de una tabla transport(5). Después de aplicar el formato de resultado, los valores múltiples se concatenan como cadenas separadas por comas. El expansion_limit y el parámetro explicados a continuación permiten restringir el número de valores en el resultado, lo cual es especialmente útil para mapas que deben devolver como máximo un valor.

El valor predeterminado %s especifica que cada valor de resultado debe usarse tal cual.

Este parámetro está disponible a partir de Postfix 2.2.

NOTA: ¡NO ponga comillas alrededor del formato de resultado!

domain (predeterminado: ninguna lista de dominios)
Esta es una lista de nombres de dominio, rutas a archivos o bases de datos de "tipo:tabla". Cuando se especifica, solo las claves de búsqueda completamente cualificadas con una parte local *no vacía* y un dominio coincidente son elegibles para la búsqueda: las búsquedas de 'usuario', búsquedas de dominio desnudo y búsquedas de "@dominio" no se realizan. Esto puede reducir significativamente la carga de consulta en el servidor MySQL.

    domain = postfix.org, hash:/etc/postfix/searchdomains

Es mejor no usar SQL para almacenar los dominios elegibles para búsquedas SQL.

Este parámetro está disponible a partir de Postfix 2.2.

NOTA: ¡NO defina este parámetro para alias locales(8), porque las claves de entrada siempre son no cualificadas!

expansion_limit (predeterminado: 0)
Un límite en el número total de elementos de resultado devueltos (como una lista separada por comas) por una búsqueda contra el mapa. Una configuración de cero deshabilita el límite. Las búsquedas fallan con un error temporal si se excede el límite. Establecer el límite a 1 asegura que las búsquedas no devuelvan múltiples valores.
option_file
Lea las opciones del archivo dado en lugar de la ubicación predeterminada de my.cnf. Esto lee las opciones del grupo de opciones [client], seguido opcionalmente por las opciones del grupo dadas con option_group.

Este parámetro está disponible a partir de Postfix 2.11.

option_group (predeterminado: Postfix >= 3.2: client, <= 3.1: vacío)
Lea las opciones del grupo dado del archivo de opciones de mysql, después de leer las opciones del grupo [client].

Postfix 3.2 y versiones posteriores leen la configuración del grupo de opciones [client] por defecto. Para deshabilitar esto, especifique no option_file y especifique "option_group =" (es decir, un valor vacío).

Postfix 3.1 y anteriores no leen la configuración del grupo de opciones [client] a menos que se especifique un valor no vacío para option_file o option_group. Para habilitar esto, especifique, por ejemplo, "option_group = client".

Este parámetro está disponible a partir de Postfix 2.11.

require_result_set (predeterminado: yes)
Si es "yes", requiere que cada consulta devuelva un conjunto de resultados. Si es "no", trata la ausencia de un conjunto de resultados como "no encontrado".

Este parámetro está disponible a partir de Postfix 3.2.

Configuraciones relacionadas con TLS

Consulte https://dev.mysql.com/doc/c-api/en/mysql-options.html o https://mariadb.com/kb/en/mysql_optionsv/ para obtener detalles sobre las características subyacentes de MYSQL_OPT_SSL_*.

tls_cert_file
Archivo que contiene el certificado X509 del cliente.

Este parámetro está disponible a partir de Postfix 2.11.

tls_key_file
Archivo que contiene la clave privada correspondiente a tls_cert_file.

Este parámetro está disponible a partir de Postfix 2.11.

tls_CAfile
Archivo que contiene los certificados X509 de todas las Autoridades de Certificación que el cliente reconocerá. Tiene prioridad sobre tls_CApath.

Este parámetro está disponible a partir de Postfix 2.11.

tls_CApath
Directorio que contiene certificados de Autoridad de Certificación X509 en archivos individuales separados.

Este parámetro está disponible a partir de Postfix 2.11.

tls_ciphers
La lista de cifrados permitidos para la encriptación SSL.

Este parámetro está disponible a partir de Postfix 2.11.

tls_verify_cert (predeterminado: no)
Verifica que el nombre del servidor coincida con el nombre común en el certificado.

Este parámetro está disponible a partir de Postfix 2.11.

Uso de procedimientos almacenados de MySQL

Postfix 3.2 y versiones posteriores admiten la llamada a un procedimiento almacenado en lugar de utilizar una instrucción SELECT en la consulta, por ejemplo:

    query = CALL lookup('%s')

Las expansiones '%' descritas anteriormente se pueden utilizar en el (los) parámetro(s) del procedimiento almacenado.

Por defecto, cada llamada a procedimiento almacenado debe devolver un conjunto de resultados, es decir, cada ruta de código debe ejecutar una instrucción SELECT que devuelva un conjunto de resultados (en lugar de almacenar sus resultados en una tabla). Con "require_result_set = no", la ausencia de un conjunto de resultados se trata como "no encontrado".

Un procedimiento almacenado no debe devolver múltiples conjuntos de resultados. Es decir, no debe haber ninguna ruta de código que ejecute múltiples instrucciones SELECT que devuelvan un resultado (en lugar de almacenar sus resultados en una tabla).

El siguiente es un ejemplo de un procedimiento almacenado que devuelve un único conjunto de resultados:

CREATE [DEFINER=`user`@`host`] PROCEDURE
`lookup`(IN `param` VARCHAR(255))
    READS SQL DATA
    SQL SECURITY INVOKER
    BEGIN
        select goto from alias where address=param;
    END

Parámetros obsoletos de main.cf

Para compatibilidad con otras tablas de búsqueda de Postfix, los parámetros de MySQL también se pueden definir en main.cf. Para hacerlo, especifique como origen MySQL un nombre que no comience con una barra o un punto. Los parámetros de MySQL serán entonces accesibles como el nombre que le ha dado al origen en su definición, un guión bajo y el nombre del parámetro. Por ejemplo, si el mapa se especifica como "mysql:nombremysql", el parámetro "hosts" se definirá en main.cf como "nombremysql_hosts".

Nota: con esta forma, las contraseñas para los orígenes MySQL se escriben en main.cf, que normalmente es legible para todos. El soporte para esta forma se eliminará en una futura versión de Postfix.

Interfaz de consulta obsoleta

Esta sección describe una interfaz que está obsoleta a partir de Postfix 2.2. Está reemplazada por la interfaz query más general descrita anteriormente. Si se define el parámetro query, los parámetros heredados descritos aquí se ignoran. Migre a la nueva interfaz, ya que la interfaz heredada puede eliminarse en una futura versión.

Los siguientes parámetros se pueden utilizar para rellenar una instrucción de plantilla SELECT de la forma:

    SELECT [select_field]
    FROM [table]
    WHERE [where_field] = '%s'
          [additional_conditions]

El especificador %s se reemplaza por la cadena de búsqueda y se escapa para que si contiene comillas simples u otros caracteres inusuales, no cause un error de análisis, o peor aún, un problema de seguridad.

select_field
El parámetro SQL "select". Ejemplo:

    select_field = forw_addr
table
El nombre de la tabla SQL "select .. from". Ejemplo:

    table = mxaliases
where_field
El parámetro SQL "select .. where". Ejemplo:

    where_field = alias
additional_conditions
Condiciones adicionales para la consulta SQL. Ejemplo:

    additional_conditions = AND status = 'paid'
