MARIADB-TEST(1) Sistema de Bases de Datos MariaDB MARIADB-TEST(1)

NOMBRE

mariadb-test - programa para ejecutar casos de prueba (mariadb-test es ahora un enlace simbólico a mariadb-test)
mariadb-test-embedded - programa para ejecutar casos de prueba embebidos

SINOPSIS

mariadb-test [opciones] [nombre_bd]

mariadb-test-embedded [opciones] [nombre_bd]

DESCRIPCIÓN

El programa mariadb-test ejecuta un caso de prueba contra un servidor MariaDB y opcionalmente compara la salida con un archivo de resultados. Este programa lee la entrada escrita en un lenguaje de prueba especial. Típicamente, invocas mariadb-test a través de mariadb-test-run.pl en lugar de invocarlo directamente.

mariadb-test-embedded es similar pero está compilado con soporte para el servidor embebido libmariadbd.

Características de mariadb-test:

•Puede enviar sentencias SQL a servidores MariaDB para su ejecución
•Puede ejecutar comandos externos del shell
•Puede probar si el resultado de una sentencia SQL o comando del shell es el esperado
•Puede conectarse a uno o más servidores mariadbd independientes y cambiar entre conexiones
•Puede conectarse a un servidor embebido (libmariadbd), si MariaDB está compilado con soporte para libmariadbd. (En este caso, el ejecutable se llama mariadb-test-embedded en lugar de mariadb-test.)

Por defecto, mariadb-test lee el caso de prueba en la entrada estándar. Para ejecutar mariadb-test de esta manera, normalmente lo invocas así:

shell> mariadb-test [opciones] [nombre_bd] < archivo_prueba

También puedes nombrar el archivo del caso de prueba con una opción --test-file=nombre_archivo.

El valor de salida de mariadb-test es 0 para éxito, 1 para fallo y 62 si omite el caso de prueba (por ejemplo, si después de verificar algunas precondiciones decide no ejecutar la prueba).

mariadb-test soporta las siguientes opciones:

•--help, -?

Muestra un mensaje de ayuda y sale.

•--basedir=nombre_dir, -b nombre_dir

El directorio base para las pruebas.

•--character-sets-dir=ruta

El directorio donde están instalados los conjuntos de caracteres.

•--compress, -C

Comprime toda la información enviada entre el cliente y el servidor si ambos soportan compresión.

•--connect-timeout=núm

Esto se puede usar para establecer el parámetro MYSQL_OPT_CONNECT_TIMEOUT de mysql_options para cambiar el número de segundos antes de que expire un intento de conexión fallido.

•--continue-on-error

Continúa la prueba incluso si obtuvimos un error. Esto es principalmente útil cuando se prueba un motor de almacenamiento para ver qué partes de un archivo de prueba puede ejecutar, o para encontrar todos los errores de sintaxis en un archivo de prueba grande recién creado.

•--cursor-protocol

Usa cursores para sentencias preparadas.

•--database=nombre_bd, -D nombre_bd

La base de datos por defecto a usar.

•--debug[=opciones_debug], -#[opciones_debug]

Escribe un registro de depuración si MariaDB está compilado con soporte de depuración. El valor por defecto de opciones_debug es 'd:t:S:i:O,/tmp/mariadb-test.trace'.

•--debug-check

Imprime información de depuración al salir del programa.

•--debug-info

Imprime información de depuración y estadísticas de uso de memoria y CPU al salir del programa.

•--host=nombre_host, -h nombre_host

Conéctate al servidor MariaDB en el host especificado.

•--logdir=nombre_dir

El directorio a usar para los archivos de registro.

•--mark-progress

Escribe el número de línea y el tiempo transcurrido en archivo_prueba.progress.

•--max-connect-retries=núm

El número máximo de intentos de conexión al servidor.

•--max-connections=núm

El número máximo de conexiones simultáneas de servidor por cliente (es decir, por prueba). Si no se establece, el máximo es 128. El límite mínimo permitido es 8, el máximo es 5120.

•--no-defaults

No leer las opciones por defecto de ningún archivo de opciones. Si se usa, esta debe ser la primera opción.

•--non-blocking-api

Usa la API de cliente no bloqueante para la comunicación.

•--overlay-dir=nombre_dir

Directorio de superposición.

•--password[=contraseña], -p[contraseña]

La contraseña a usar al conectarse al servidor. Si usas la forma corta de la opción (-p), *no puedes* tener un espacio entre la opción y la contraseña. Si omites el valor de contraseña después de la opción --password o -p en la línea de comandos, se te pedirá una.

•--plugin-dir=nombre_dir

Directorio para plugins del lado del cliente.

•--port=num_puerto, -P num_puerto

El número de puerto TCP/IP a usar para la conexión o 0 para usar el valor por defecto, en orden de preferencia: my.cnf, $MYSQL_TCP_PORT, /etc/services, valor por defecto interno (3306).

•--prologue=nombre

Incluye el contenido del archivo dado antes de procesar el contenido del archivo de prueba. El archivo incluido debe tener el mismo formato que otros archivos de prueba de mariadb-test. Esta opción tiene el mismo efecto que poner un comando --source nombre_archivo como primera línea del archivo de prueba.

•--protocol={TCP|SOCKET|PIPE|MEMORY}

El protocolo de conexión a usar para conectarse al servidor. Es útil cuando los otros parámetros de conexión normalmente causarían que se usara un protocolo distinto al que deseas.

•--ps-protocol

Usa el protocolo de sentencias preparadas para la comunicación.

•--quiet

Suprime toda la salida normal. Es un sinónimo de --silent.

•--record, -r

Registra la salida resultante de ejecutar el archivo de prueba en el archivo nombrado por la opción --result-file, si esa opción se proporciona. Es un error usar esta opción sin usar también --result-file.

•--result-file=nombre_archivo, -R nombre_archivo

Esta opción especifica el archivo para los resultados esperados del caso de prueba. --result-file, junto con --record, determina cómo mariadb-test trata los resultados reales y esperados de un caso de prueba:

•Si la prueba no produce resultados, mariadb-test sale con un mensaje de error al respecto, a menos que se proporcione --result-file y el archivo nombrado esté vacío.
•De lo contrario, si no se proporciona --result-file, mariadb-test envía los resultados de la prueba a la salida estándar.
•Con --result-file pero sin --record, mariadb-test lee los resultados esperados del archivo dado y los compara con los resultados reales. Si los resultados no coinciden, mariadb-test escribe un archivo .reject en el mismo directorio que el archivo de resultados, muestra una diferencia entre ambos archivos y sale con un error.
•Con ambas opciones --result-file y --record, mariadb-test actualiza el archivo dado escribiendo los resultados reales de la prueba en él.
•--result-format-version=#

Versión del formato de archivo de resultados a usar.

•--server-arg=valor, -A valor

Pasa el argumento como un argumento al servidor embebido. Para

NAME

mysqltest

a script to test the MariaDB server

SYNOPSIS

mysqltest [-c|--character-sets-dir=dir_name] [-C|--compress] [-e|--execute] [--defaults-file=file_name] [--server-arg=arg] [-F|--server-file=file_name] [-s|--silent] [-T|--sleep=num] [-S|--socket=path] [--sp-protocol] [--ssl] [--ssl-ca=name] [--ssl-capath=name] [--ssl-cert=name] [--ssl-cipher=name] [--ssl-key=name] [--ssl-crl=name] [--ssl-crlpath=name] [--ssl-verify-server-cert] [--suite-dir=dir_name] [-x|--test-file=file_name] [-m|--timer-file=file_name] [-t|--tmpdir=dir_name] [-u|--user=user_name] [-v|--verbose] [-V|--version] [--view-protocol]

DESCRIPTION

The mysqltest script is used to test the MariaDB server. It reads commands from standard input, or from a file specified with --test-file, and executes them against the server.

The following options are available:

•--character-sets-dir=dir_name, -c dir_name

Directory for character sets.

•--compress, -C

Use compression in the client/server protocol.

•--execute, -e

Execute the given commands and exit.

•--defaults-file=file_name

Use only the given file for default options. The server reads this file, so you can specify options like --server-arg=--tmpdir=/tmp or --server-arg=--core. Up to 64 arguments can be given.

•--server-file=file_name, -F file_name

Read arguments for the embedded server from the given file. The file should contain one argument per line.

•--silent, -s

Suppress all normal output.

•--sleep=num, -T num

Cause all sleep commands in the test case file to sleep num seconds. This option does not affect real_sleep commands.

An option value of 0 can be used, which effectively disables sleep commands in the test case.

•--socket=path, -S path

The socket file to use when connecting to localhost (which is the default host).

•--sp-protocol

Execute DML statements within a stored procedure. For every DML statement, mariadb-test creates and invokes a stored procedure that executes the statement rather than executing the statement directly.

•--ssl

Enable SSL for connection (automatically enabled with other flags). Disable with --skip-ssl.

•--ssl-ca=name

CA file in PEM format (check OpenSSL docs, implies --ssl).

•--ssl-capath=name

CA directory (check OpenSSL docs, implies --ssl).

•--ssl-cert=name

X509 cert in PEM format (check OpenSSL docs, implies --ssl).

•--ssl-cipher=name

SSL cipher to use (check OpenSSL docs, implies --ssl).

•--ssl-key=name

X509 key in PEM format (check OpenSSL docs, implies --ssl).

•--ssl-crl=name

Certificate revocation list (check OpenSSL docs, implies --ssl).

•--ssl-crlpath=name

Certificate revocation list path (check OpenSSL docs, implies --ssl).

•--ssl-verify-server-cert

Verify server's "Common Name" in its cert against hostname used when connecting. This option is disabled by default.

•--suite-dir=dir_name

Suite directory.

•--tail-lines=nn

Specify how many lines of the result to include in the output if the test fails because an SQL statement fails. The default is 0, meaning no lines of result printed.

•--test-file=file_name, -x file_name

Read test input from this file. The default is to read from the standard input.

•--timer-file=file_name, -m file_name

If given, the number of microseconds spent running the test will be written to this file. This is used by mariadb-test-run.pl for its reporting.

•--tmpdir=dir_name, -t dir_name

The temporary directory where socket files are created.

•--user=user_name, -u user_name

The MariaDB user name to use when connecting to the server.

•--verbose, -v

Verbose mode. Print out more information about what the program does.

•--version, -V

Display version information and exit.

•--view-protocol

Every SELECT statement is wrapped inside a view.
