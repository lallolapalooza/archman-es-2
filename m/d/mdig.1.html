NOMBRE

mdig - utilidad de consulta de DNS con canalización (pipelining)

SINOPSIS

mdig <{@servidor>} [-f nombre_archivo] [-h] [-v] [ [-4] | [-6] ] [-m] [-b dirección] [-p puerto#] [-c clase] [-t tipo] [-i] [-x dir] [opción_adicional...]

mdig {-h}

mdig {@servidor} {opción_global...} { {opción_local...} {consulta} ...}

DESCRIPCIÓN

mdig es una versión de consultas múltiples/con canalización de dig <#std-iscman-dig>: en lugar de esperar una respuesta después de enviar cada consulta, comienza enviando todas las consultas. Las respuestas se muestran en el orden en que se reciben, no en el orden en que se enviaron las consultas correspondientes.

Las opciones de mdig son un subconjunto de las opciones de dig <#std-iscman-dig>, y se dividen en "opciones generales", que pueden aparecer en cualquier lugar, "opciones globales", que deben aparecer antes del nombre de consulta (o se ignoran con una advertencia), y "opciones locales", que se aplican a la siguiente consulta en la línea de comandos.

La opción @servidor es una opción global obligatoria. Es el nombre o la dirección IP del servidor de nombres al que consultar. (A diferencia de dig <#std-iscman-dig>, este valor no se obtiene de /etc/resolv.conf.) Puede ser una dirección IPv4 en notación decimal punteada, una dirección IPv6 en notación delimitada por dos puntos, o un nombre de host. Cuando el argumento servidor proporcionado es un nombre de host, mdig resuelve ese nombre antes de consultar al servidor de nombres.

mdig proporciona una serie de opciones de consulta que afectan la forma en que se realizan las búsquedas y se muestran los resultados. Algunas de ellas establecen o restablecen bits de bandera en la cabecera de la consulta, otras determinan qué secciones de la respuesta se imprimen, y otras determinan las estrategias de tiempo de espera y reintento.

Cada opción de consulta se identifica por una palabra clave precedida por un signo más (+). Algunas palabras clave establecen o restablecen una opción. Estas pueden ir precedidas por la cadena no para negar el significado de esa palabra clave. Otras palabras clave asignan valores a opciones como el intervalo de tiempo de espera. Tienen el formato +palabra_clave=valor.

OPCIONES GENERALES

-f
Esta opción hace que mdig funcione en modo por lotes leyendo una lista de solicitudes de consulta a procesar del archivo nombre_archivo. El archivo contiene un número de consultas, una por línea. Cada entrada en el archivo debe organizarse de la misma manera en que se presentarían como consultas a mdig usando la interfaz de línea de comandos.
-h
Esta opción hace que mdig imprima información de ayuda detallada, con la lista completa de opciones, y salga.
-v
Esta opción hace que mdig imprima el número de versión y salga.

OPCIONES GLOBALES

-4
Esta opción fuerza a mdig a usar solo transporte de consulta IPv4.
-6
Esta opción fuerza a mdig a usar solo transporte de consulta IPv6.
-b dirección
Esta opción establece la dirección IP de origen de la consulta a dirección. Debe ser una dirección válida en una de las interfaces de red del host o "0.0.0.0" o "::". Se puede especificar un puerto opcional añadiendo "#<puerto>"
-m
Esta opción habilita la depuración del uso de memoria.
-p puerto#
Esta opción se utiliza cuando se va a consultar un número de puerto no estándar. puerto# es el número de puerto al que mdig envía sus consultas, en lugar del número de puerto DNS estándar 53. Esta opción se utiliza para probar un servidor de nombres que se ha configurado para escuchar consultas en un número de puerto no estándar.

Las opciones de consulta globales son:

+additional, +noadditional
Esta opción muestra [o no muestra] la sección adicional de una respuesta. El valor predeterminado es mostrarla.
+all, +noall
Esta opción establece o borra todas las banderas de visualización.
+answer, +noanswer
Esta opción muestra [o no muestra] la sección de respuesta de una respuesta. El valor predeterminado es mostrarla.
+authority, +noauthority
Esta opción muestra [o no muestra] la sección de autoridad de una respuesta. El valor predeterminado es mostrarla.
+besteffort, +nobesteffort
Esta opción intenta mostrar [o no mostrar] el contenido de mensajes que están mal formados. El valor predeterminado es no mostrar respuestas malformadas.
+burst
Esta opción retrasa las consultas hasta el inicio del siguiente segundo.
+cl, +nocl
Esta opción muestra [o no muestra] la CLASE al imprimir el registro.
+comments, +nocomments
Esta opción activa/desactiva la visualización de líneas de comentarios en la salida. El valor predeterminado es imprimir comentarios.
+continue, +nocontinue
Esta opción activa/desactiva la continuación ante errores (por ejemplo, tiempos de espera agotados).
+crypto, +nocrypto
Esta opción activa/desactiva la visualización de campos criptográficos en registros DNSSEC. El contenido de estos campos es innecesario para depurar la mayoría de los fallos de validación DNSSEC y eliminarlos facilita la visualización de los fallos comunes. El valor predeterminado es mostrar los campos. Cuando se omiten, se reemplazan por la cadena "[omitido]"; en el caso de DNSKEY, el ID de la clave se muestra como reemplazo, por ejemplo, [ id de clave = valor ].
+multiline, +nomultiline
Esta opción activa/desactiva la impresión de registros, como los registros SOA, en un formato verboso de varias líneas con comentarios legibles por humanos. El valor predeterminado es imprimir cada registro en una sola línea, para facilitar el análisis de la salida de mdig por máquina.
+question, +noquestion
Esta opción imprime [o no imprime] la sección de pregunta de una consulta cuando se devuelve una respuesta. El valor predeterminado es imprimir la sección de pregunta como un comentario.
+rrcomments, +norrcomments
Esta opción activa/desactiva la visualización de comentarios por registro en la salida (por ejemplo, información de clave legible por humanos sobre registros DNSKEY). El valor predeterminado es no imprimir comentarios de registro a menos que el modo multilínea esté activo.
+short, +noshort
Esta opción proporciona [o no proporciona] una respuesta concisa. El valor predeterminado es imprimir la respuesta en un formato verboso.
+split=W
Esta opción divide los campos largos en formato hexadecimal o base64 de los registros de recursos en fragmentos de W caracteres (donde W se redondea al múltiplo de 4 más cercano). +nosplit o +split=0 hace que los campos no se dividan. El valor predeterminado es de 56 caracteres, o 44 caracteres cuando el modo multilínea está activo.
+tcp, +notcp
Esta opción utiliza [o no utiliza] TCP al consultar servidores de nombres. El comportamiento predeterminado es usar UDP.
+ttlid, +nottlid
Esta opción muestra [o no muestra] el TTL al imprimir el registro.
+ttlunits, +nottlunits
Esta opción muestra [o no muestra] el TTL en unidades de tiempo legibles por humanos (por ejemplo, 3h para 3 horas). El valor predeterminado es mostrar el TTL en segundos.
+trace, +notrace
Esta opción activa [o desactiva] el modo de rastreo de consultas. Cuando está activado, mdig muestra los pasos que toma para encontrar el nombre de dominio solicitado, incluido el envío de consultas a los servidores raíz, TLD y autorizados.
+tries=N
Establece el número de intentos de reenvío de consultas a N. El valor predeterminado es 3.
+type
Esta opción se utiliza para especificar el tipo de consulta. El valor predeterminado es A.
+url
Esta opción se utiliza para especificar un servidor DNS sobre HTTPS (DoH) o DNS sobre TLS (DoT). La sintaxis es la de una URL válida, por ejemplo, https://dns.google/dns-query para DoH o tls://dns.quad9.net para DoT. Cuando se usa esta opción, la consulta se realiza mediante HTTP POST para DoH o TLS para DoT, y el nombre del servidor se toma del nombre de host de la URL. La opción @server se ignora.
+view=view
Esta opción se utiliza en un entorno de servidor de nombres con vistas para especificar qué vista se utilizará para la consulta. El valor predeterminado es la vista por defecto.
+what, +nowhat
Esta opción muestra [o no muestra] el contenido del paquete de consulta y respuesta. El valor predeterminado es no mostrarlo.
+zerosum, +nozerosum
Esta opción muestra [o no muestra] la suma de verificación de 16 bits del paquete en la salida. El valor predeterminado es no mostrarla.

OPCIONES DE CLASE

La opción -c se puede utilizar para especificar una clase de DNS distinta de la predeterminada IN (Internet). Por ejemplo, para consultar registros de clase Chaos, use -c CHAOS.

OPCIONES DE TIPO

La opción -t se puede utilizar para especificar un tipo de registro DNS distinto del predeterminado A. Por ejemplo, para consultar registros MX, use -t MX.

OPCIÓN X LOOKUP

-x addr
Esta opción realiza una búsqueda inversa de la dirección IP addr.

EJEMPLOS

Para consultar los servidores de nombres de example.com por un registro MX, use:

mdig @ns1.example.com example.com MX

Para consultar los servidores de nombres de example.com por un registro A usando un servidor de nombres en el puerto 5353, use:

mdig @ns1.example.com -p 5353 example.com A

Para consultar varios registros A para www.example.com en la clase CHAOS, use:

mdig @ns1.example.com -c CHAOS www.example.com A

Para consultar varios registros A para www.example.com y obtener una respuesta concisa, use:

mdig @ns1.example.com www.example.com A +short

Para realizar una consulta inversa para 192.168.1.1, use:

mdig -x 192.168.1.1

Para realizar una consulta inversa para 192.168.1.1 usando un servidor de nombres específico, use:

mdig @8.8.8.8 -x 192.168.1.1

Para consultar los registros DNSKEY para example.com y suprimir la visualización de campos criptográficos, use:

mdig @ns1.example.com example.com DNSKEY +nocrypto

Para consultar los registros TXT para example.com en formato multilínea, use:

mdig @ns1.example.com example.com TXT +multiline

VÉASE TAMBIÉN

dig(1), host(1), nslookup(1), resolv.conf(5)

DIAGNÓSTICOS

Cuando ocurre un error, mdig imprime un mensaje explicativo en su salida estándar de errores.

ERRORES

La opción +continue puede ser útil al interrogar a múltiples servidores de nombres que pueden no responder.

NAME

mdig — DNS lookup utility

SYNOPSIS

mdig [-?] [-b source] [-c class] [-f filename] [-i] [-k domain name keyname] [-m] [-N server] [-p port] [-q queryname] [-r] [-t type] [-u] [-v] [-x addr] [-y hmac:key] [[+]option]...

mdig [-?] [-h] [-t type] [name] [[@server]]

DESCRIPTION

The mdig utility is a tool for interrogating DNS servers. It is designed to be a simple interface to the DNS lookup logic built into BIND. mdig can also be used for testing and troubleshooting DNS servers.

When called with no arguments, mdig performs a lookup for the name specified on the command line, using the default server (which is defined in the system's resolver configuration) and the default query type (A record).

When called with arguments, mdig performs a DNS lookup for the query name and type specified on the command line. The lookup is performed against the specified server. If no server is specified, the lookup is performed against the default server.

The output of mdig is the same as that of dig, with the addition of the query options.

ANYWHERE OPTIONS

The following options can be specified anywhere on the command line:

-f filename
Read queries from filename. Each line in the file must contain a query in the same format as a command-line query. A blank line means that the query options specified on the command line should be used. A line starting with a semicolon (;) is a comment.
-i
Enable IPv6 operation.
-r
Disable recursion. By default, mdig enables recursion.
-u
Enable UDP operation. This is the default.
-v
Verbose mode. Prints debugging information to standard output.
+option
These options set various query options which control the behavior of mdig. The options are described in the LOCAL OPTIONS section.
-option
These options set various query options which control the behavior of mdig. The options are described in the LOCAL OPTIONS section.

GLOBAL OPTIONS

The following options can be specified on the command line or in a configuration file:

-b source
Use source as the source IP address for UDP or TCP queries. source can be an IP address or a hostname. If a hostname is given, mdig resolves it to an IP address.
-k domain name keyname
Retrieve a DNSSEC security key for domain name using keyname keyname. This option is used for TSIG signed queries.
-m
Enable TCP operation. By default, mdig uses UDP.
-N server
Use server as the default name server. If this option is not specified, mdig uses the name servers defined in the system's resolver configuration file (e.g. /etc/resolv.conf).
-p port
Use port for queries. The default is port 53.
-q queryname
Query for queryname. This option is a synonym for specifying the query name as the last argument on the command line.
-t type
Query for records of type type. The default is A.
-x addr
Reverse lookup a address. This is a shortcut for specifying a query of type PTR for the name. addr is an IPv4 address in dotted-decimal notation, or a colon-delimited IPv6 address.
-y hmac:key
Use the specified key, key, to validate transactions using the HMAC-MD5 message digest algorithm. hmac is the name of the algorithm, e.g. hmac-md5.
+time
Set the time value for the specified time unit. The time units are readable time units of "s", "m", "h", "d", and "w", representing seconds, minutes, hours, days, and weeks. This implies +ttlid.
+vc, +novc
This option uses [or does not use] TCP when querying name servers. This alternate syntax to +tcp is provided for backwards compatibility. The vc stands for "virtual circuit".

LOCAL OPTIONS

-c class
This option sets the query class to class. It can be any valid query class which is supported in BIND 9. The default query class is "IN".
-t type
This option sets the query type to type. It can be any valid query type which is supported in BIND 9. The default query type is "A", unless the -x option is supplied to indicate a reverse lookup with the "PTR" query type.
-x addr
Reverse lookups - mapping addresses to names - are simplified by this option. addr is an IPv4 address in dotted-decimal notation, or a colon-delimited IPv6 address. mdig automatically performs a lookup for a query name like 11.12.13.10.in-addr.arpa and sets the query type and class to PTR and IN respectively. By default, IPv6 addresses are looked up using nibble format under the IP6.ARPA domain.

The local query options are:

+aaflag, +noaaflag
This is a synonym for +aaonly, +noaaonly.
+aaonly, +noaaonly
This sets the aa flag in the query.
+adflag, +noadflag
This sets [or does not set] the AD (authentic data) bit in the query. This requests the server to return whether all of the answer and authority sections have all been validated as secure, according to the security policy of the server. AD=1 indicates that all records have been validated as secure and the answer is not from a OPT-OUT range. AD=0 indicates that some part of the answer was insecure or not validated. This bit is set by default.
+bufsize=B
This sets the UDP message buffer size advertised using EDNS0 to B bytes. The maximum and minimum sizes of this buffer are 65535 and 0 respectively. Values outside this range are rounded up or down appropriately. Values other than zero cause a EDNS query to be sent.
+cdflag, +nocdflag
This sets [or does not set] the CD (checking disabled) bit in the query. This requests the server to not perform DNSSEC validation of responses.
+cookie=####, +nocookie
This sends [or does not send] a COOKIE EDNS option, with an optional value. Replaying a COOKIE from a previous response allows the server to identify a previous client. The default is +nocookie.
+dnssec, +nodnssec
This requests that DNSSEC records be sent by setting the DNSSEC OK (DO) bit in the OPT record in the additional section of the query.
+edns[=#], +noedns
This specifies [or does not specify] the EDNS version to query with. Valid values are 0 to 255. Setting the EDNS version causes an EDNS query to be sent. +noedns clears the remembered EDNS version. EDNS is set to 0 by default.
+ednsflags[=#], +noednsflags
This sets the must-be-zero EDNS flag bits (Z bits) to the specified value. Decimal, hex, and octal encodings are accepted. Setting a named flag (e.g. DO) is silently ignored. By default, no Z bits are set.
+ednsopt[=code[:value]], +noednsopt
This specifies [or does not specify] an EDNS option with code point code and an optional payload of value as a hexadecimal string. +noednsopt clears the EDNS options to be sent.
+expire, +noexpire
This toggles sending of an EDNS Expire option.
+nsid, +nonsid
This toggles inclusion of an EDNS name server ID request when sending a query.
+recurse, +norecurse
This toggles the setting of the RD (recursion desired) bit in the query. This bit is set by default, which means mdig normally sends recursive queries.
+retry=T
This sets the number of times to retry UDP queries to server to T instead of the default, 2. Unlike +tries, this does not include the initial query.
+subnet=addr[/prefix-length], +nosubnet
This sends [or does not send] an EDNS Client Subnet option with the specified IP address or network prefix.
mdig +subnet=0.0.0.0/0, or simply mdig +subnet=0
This sends an EDNS client-subnet option with an empty address and a source prefix-length of zero, which signals a resolver that the client's address information must not be used when resolving this query.
+timeout=T
This sets the timeout for a query to T seconds. The default timeout is 5 seconds for UDP transport and 10 for TCP. An attempt to set T to less than 1 results in a query timeout of 1 second being applied.
+tries=T
This sets the number of times to try UDP queries to server to T instead of the default, 3. If T is less than or equal to zero, the number of tries is silently rounded up to 1.
+udptimeout=T
This sets the timeout between UDP query retries to T.
+unknownformat, +nounknownformat
This prints [or does not print] all RDATA in unknown RR-type presentation format (see RFC 3597 https://datatracker.ietf.org/doc/html/rfc3597.html). The default is to print RDATA for known types in the type's presentation format.
+yaml, +noyaml
This toggles printing of the responses in a detailed YAML format.
+zflag, +nozflag
This sets [or does not set] the last unassigned DNS header flag in a DNS query. This flag is off by default.
