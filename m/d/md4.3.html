NOMBRE

MD4Init, MD4Update, MD4Pad, MD4Final, MD4Transform, MD4End, MD4File, MD4FileChunk, MD4Data — calcular el resumen del mensaje “MD4” de RSA Data Security, Inc.

BIBLIOTECA

void
MD4Pad(MD4_CTX *context);

void
MD4Final(uint8_t digest[MD4_DIGEST_LENGTH], MD4_CTX *context);

void
MD4Transform(uint32_t state[4], uint8_t block[MD4_BLOCK_LENGTH]);

char *
MD4End(MD4_CTX *context, char *buf);

char *
MD4File(const char *filename, char *buf);

char *
MD4FileChunk(const char *filename, char *buf, off_t offset, off_t length);

char *
MD4Data(const uint8_t *data, size_t len, char *buf);

DESCRIPCIÓN

Las funciones MD4 calculan una suma de verificación criptográfica de 128 bits (resumen) para cualquier número de bytes de entrada. Una suma de verificación criptográfica es una función hash de un solo sentido, es decir, no se puede encontrar (excepto mediante búsqueda exhaustiva) la entrada que corresponde a una salida particular. El resultado neto es una “huella digital” de los datos de entrada, que no revela la entrada real.

MD2 es el más lento, MD4 es el más rápido y MD5 está en el medio. MD2 solo se puede utilizar para correo de mejora de la privacidad. MD4 ha sido criticado por ser demasiado débil, por lo que MD5 se desarrolló en respuesta como ``MD4 con cinturones de seguridad''. MD4 y MD5 han sido vulnerados; solo deben usarse cuando sea necesario por compatibilidad con versiones anteriores. Los ataques contra MD4 y MD5 son de la naturaleza de encontrar “colisiones” —es decir, múltiples entradas que producen el mismo valor hash; todavía es poco probable que un atacante pueda determinar la entrada original exacta dado un valor hash.

Las funciones MD4Init(), MD4Update(), y MD4Final() son las funciones principales. Asigne un MD4_CTX, inicialícelo con MD4Init(), procese los datos con MD4Update(), y finalmente extraiga el resultado usando MD4Final().

La función MD4Pad() se puede usar para aplicar relleno al resumen del mensaje como en MD4Final(), pero el contexto actual aún se puede usar con MD4Update().

La función MD4Transform() es utilizada por MD4Update() para hashear bloques de 512 bits y constituye el núcleo del algoritmo. La mayoría de los programas deberían usar la interfaz proporcionada por MD4Init(), MD4Update() y MD4Final() en lugar de llamar a MD4Transform() directamente.

MD4End() es un envoltorio para MD4Final() que convierte el valor de retorno en una cadena ASCII de MD4_DIGEST_STRING_LENGTH caracteres (incluyendo el terminador '\0') que representa los 128 bits en hexadecimal.

MD4File() calcula el resumen de un archivo y utiliza MD4End() para devolver el resultado. Si el archivo no se puede abrir, se devuelve un puntero nulo.

MD4FileChunk() se comporta como MD4File() pero calcula el resumen solo para esa porción del archivo que comienza en offset y continúa durante length bytes o hasta el final del archivo, lo que ocurra primero. Se puede especificar un length cero para leer hasta el final del archivo. Se ignora un length o offset negativo. MD4Data() calcula el resumen de un bloque de datos en memoria y utiliza MD4End() para devolver el resultado.

Al usar MD4End(), MD4File(), MD4FileChunk(), o MD4Data(), el argumento buf puede ser un puntero nulo, en cuyo caso la cadena devuelta se asigna con malloc(3) y posteriormente debe ser liberada explícitamente usando free(3) después de su uso. Si el argumento buf no es nulo, debe apuntar a al menos MD4_DIGEST_STRING_LENGTH caracteres de espacio de búfer.

NAME

md4, MD4_Init, MD4_Update, MD4_Final, MD4_End, MD4_File, MD4_FileChunk, MD4Data - MD4 message digest algorithm

LIBRARY

Message Digest (libmd, -lmd)

SYNOPSIS

#include <sys/types.h>
#include <stdio.h>
#include <md4.h>

void
MD4_Init(MD4_CTX *c);

void
MD4_Update(MD4_CTX *c, const void *data, u_int len);

void
MD4_Final(u_int8_t *digest, MD4_CTX *c);

u_int8_t *
MD4_End(MD4_CTX *c, u_int8_t *digest);

u_int8_t *
MD4_Data(const void *data, u_int len, u_int8_t *digest);

u_int8_t *
MD4_FileChunk(const char *filename, off_t offset, size_t length, u_int8_t *digest);

u_int8_t *
MD4_File(const char *filename, u_int8_t *digest);

DESCRIPTION

The MD4 algorithm is a publicly available message digest algorithm that produces a 128-bit (16-byte) message digest from a given input. The algorithm is designed to be quite fast on software implementations.

The MD4_Init() function initializes a message digest context c.

The MD4_Update() function computes the message digest for the data in the buffer data of length len.

The MD4_Final() function finishes the message digest computation. The resulting digest is stored in the digest buffer, which must be 16 bytes long. The MD4_Final() function leaves the context intact, so that MD4_Update() may be called again with new data. If the context is no longer needed, MD4_End() should be used instead.

The MD4_End() function finishes the message digest computation like MD4_Final(), but also clears the MD4_CTX structure. The result is stored in the digest buffer.

The MD4_Data() function is a convenience function that computes the MD4 message digest for the data buffer data of length len. The result is stored in the digest buffer.

The MD4_FileChunk() function computes the MD4 message digest for a portion of the file filename. The computation starts at offset and continues for length bytes. The result is stored in the digest buffer.

The MD4_File() function is a convenience function that computes the MD4 message digest for the entire file filename. The result is stored in the digest buffer.

All functions that return a u_int8_t * return the pointer to the digest buffer passed as an argument, or NULL on error.

AUTHORS

The original MD4 routines were developed by RSA Data Security, Inc., and published in the above references. This code is derived from a public domain implementation written by Colin Plumb.

The MD4End(), MD4File(), MD4FileChunk(), and MD4Data() helper functions are derived from code written by Poul-Henning Kamp.

BUGS

Collisions have been found for the full versions of both MD4 and MD5. The use of sha2(3) is recommended instead.
