MDADM.CONF(5) Manual de formatos de archivo MDADM.CONF(5)

NOMBRE

mdadm.conf - configuración para la gestión de RAID por software con mdadm

SINOPSIS

/etc/mdadm.conf

DESCRIPCIÓN

mdadm es una herramienta para crear, gestionar y supervisar dispositivos RAID utilizando el controlador md en Linux.

Algunas tareas comunes, como el ensamblaje de todas las matrices, pueden simplificarse describiendo los dispositivos y matrices en este archivo de configuración.

SINTAXIS

El archivo debe considerarse como una colección de palabras separadas por espacios en blanco (espacio, tabulador o nueva línea). Cualquier palabra que comience con un signo de almohadilla (#) inicia un comentario y esa palabra, junto con el resto de la línea, se ignora.

Los espacios pueden incluirse en una palabra utilizando comillas. Se pueden usar comillas simples (') o dobles ("). Todos los caracteres desde una comilla hasta la siguiente comilla idéntica están protegidos y no se utilizarán para separar palabras ni para iniciar nuevas cadenas entre comillas. Para incluir una comilla simple, debe estar entre comillas dobles. Para incluir una comilla doble, debe estar entre comillas simples.

Cualquier línea que comience con un espacio en blanco (espacio o tabulador) se trata como si fuera una continuación de la línea anterior.

Las líneas vacías se ignoran, pero por lo demás, cada línea (que no sea de continuación) debe comenzar con una palabra clave según se indica a continuación. Las palabras clave no distinguen entre mayúsculas y minúsculas y pueden abreviarse a 3 caracteres.

Las palabras clave son:

DEVICE
Una línea device enumera los dispositivos (dispositivos completos o particiones) que pueden contener un componente de una matriz MD. Al buscar los componentes de una matriz, mdadm explorará estos dispositivos (o cualquier dispositivo listado en la línea de comandos).

La línea device puede contener una serie de dispositivos diferentes (separados por espacios) y cada nombre de dispositivo puede contener comodines según lo definido por glob(7).

Además, puede haber varias líneas de dispositivo presentes en el archivo.

Alternativamente, una línea device puede contener una o ambas palabras containers y partitions. La palabra containers hará que mdadm busque matrices CONTAINER ensambladas y las incluya como fuente para ensamblar matrices adicionales.

La palabra partitions hará que mdadm lea /proc/partitions e incluya todos los dispositivos y particiones que se encuentren allí. mdadm no utiliza los nombres de /proc/partitions, sino solo los números de dispositivo mayor y menor. Explora /dev para encontrar el nombre que coincide con los números.

Si no hay ninguna línea DEVICE presente en ningún archivo de configuración, se asume "DEVICE partitions containers".

Por ejemplo:

DEVICE /dev/hda* /dev/hdc*
DEV /dev/sd*
DEVICE /dev/disk/by-path/pci*
DEVICE partitions
ARRAY
Las líneas ARRAY identifican las matrices reales. La segunda palabra de la línea puede ser el nombre del dispositivo donde normalmente se ensambla la matriz, como /dev/md1 o /dev/md/backup. Si el nombre no comienza con una barra ('/'), se trata como si estuviera en /dev/md/. Alternativamente, se puede dar la palabra <ignore> (con los corchetes angulares completos) en cuyo caso cualquier matriz que coincida con el resto de la línea nunca se ensamblará automáticamente. Si no se proporciona ningún nombre de dispositivo, mdadm utilizará varias heurísticas para determinar un nombre adecuado.

Las palabras posteriores identifican la matriz o identifican la matriz como miembro de un grupo. Si se proporcionan varias identidades, un dispositivo componente debe coincidir con TODAS las identidades para ser considerado una coincidencia. Cada palabra de identidad tiene una etiqueta, un signo igual y algún valor. Las etiquetas son:

uuid=
El valor debe ser un uuid de 128 bits en hexadecimal, con puntuación intercalada si se desea. Esto debe coincidir con el uuid almacenado en el superbloque.
super-minor=
El valor es un entero que indica el número menor que se almacenó en el superbloque cuando se creó la matriz. Cuando se crea una matriz como /dev/mdX, se almacena el número menor X.
devices=
El valor es una lista separada por comas de nombres de dispositivos o patrones de nombres de dispositivos. Solo los dispositivos con nombres que coincidan con una entrada en la lista se utilizarán para ensamblar la matriz. Tenga en cuenta que los dispositivos listados allí también deben estar listados en una línea DEVICE.
level=
El valor es un nivel RAID. Normalmente no se utiliza para identificar una matriz, pero se admite para que la salida de

mdadm --examine --scan

pueda usarse directamente en el archivo de configuración.

num-devices=
El valor es el número de dispositivos en una matriz activa completa. Al igual que con level=, esto es principalmente para compatibilidad con la salida de

mdadm --examine --scan.

spares=
El valor es un número de dispositivos de repuesto que se espera que tenga la matriz. El único uso de esta palabra clave y valor es el siguiente: mdadm --monitor informará sobre una matriz si se detecta que tiene menos repuestos que este número cuando --monitor se inicia o cuando se utiliza --oneshot.
spare-group=
El valor es un nombre textual para un grupo de matrices. Todas las matrices con el mismo nombre spare-group se consideran parte del mismo grupo. La importancia de un grupo de matrices es que mdadm, al monitorear las matrices, moverá un disco de repuesto de una matriz a otra dentro de un grupo si la primera matriz tenía un disco fallido o faltante pero sin repuestos.
bitmap=
La opción especifica un archivo en el que se debe encontrar un mapa de bits de intención de escritura. Al ensamblar la matriz, mdadm proporcionará este archivo al controlador md como el archivo de mapa de bits. Esto tiene la misma función que la opción --bitmap-file de --assemble.
metadata=
Especifica el formato de metadatos que tiene la matriz. Esto se reconoce principalmente para compatibilidad con la salida de mdadm -Es.
container=
Especifica que esta matriz es una matriz miembro de algún contenedor. El valor proporcionado puede ser un nombre de ruta en /dev o un UUID de la matriz contenedor.
member=
Especifica que esta matriz es una matriz miembro de algún contenedor. Cada tipo de contenedor tiene alguna forma de enumerar las matrices miembro, a menudo un simple número de secuencia. El valor identifica qué miembro de un contenedor es la matriz. Generalmente acompañará a la palabra "container=".
MAILADDR
La línea mailaddr proporciona una dirección de correo electrónico a la que se enviarán las alertas cuando mdadm se ejecute en modo --monitor (y se le haya dado la opción --scan). Solo debe haber una línea MAILADDR y debe tener una sola dirección. Las direcciones posteriores se ignoran silenciosamente.
MAILFROM
La línea mailfrom (que solo se puede abreviar a al menos 5 caracteres) proporciona una dirección que aparecerá en la dirección "De" para los correos de alerta. Esto puede ser útil si desea establecer explícitamente un dominio, ya que la dirección de remitente predeterminada es "root" sin dominio. Todas las palabras de esta línea se concatenan con espacios para formar la dirección.

Tenga en cuenta que este valor no se puede establecer a través de la línea de comandos de mdadm. Solo se puede configurar a través del archivo de configuración. Solo debe haber una línea MAILADDR y debe tener una sola dirección. Las direcciones posteriores se ignoran silenciosamente.

mdadm.conf mdadm.conf February 20, 2024 Configuration File

The mdadm.conf file is used to configure the mdadm utility. It is typically located in /etc/mdadm.conf or /etc/mdadm/mdadm.conf. This file contains configuration information that mdadm uses to manage RAID arrays.

The file can contain comments, which start with a '#'. Lines starting with '#' are ignored. Blank lines are also ignored. The file can contain the following directives:
PROGRAM
The PROGRAM line specifies a program to be run when an event occurs which requires monitoring. This program gets run with two or three arguments, they being the Event, the md device, and possibly the related component device. There should only be one program line and it should be given only one program. Any subsequent programs are silently ignored.
CREATE
The create line gives default values to be used when creating arrays, new members of arrays, and device entries for arrays. There should only be one create line. Any subsequent lines will override the previous settings. Keywords used in the CREATE line and supported values are:
owner=
group=
These can give user/group ids or names to use instead of system defaults (root/wheel or root/disk).
mode=
An octal file mode such as 0660 can be given to override the default of 0600.
metadata=
The name of the metadata format to use if none is explicitly given. This can be useful to impose a system-wide default of version-1 superblocks.
names=yes
It has been possible to create md devices with a name like md_home rather than just a number, like md3. mdadm will use the numeric alternative by default as other tools that interact with md arrays may expect only numbers. If names=yes is given in mdadm.conf then mdadm will use a name when appropriate. If names=no is given, then non-numeric md device names will not be used even if the default changes in a future release of mdadm.
bbl=no
By default, mdadm will reserve space for a bad block list (bbl) on all devices included in or added to any array that supports them. Setting bbl=no will prevent this, so newly added devices will not have a bad block log.
HOMEHOST
The homehost line gives a default value for the --homehost= option to mdadm. There should normally be only one other word on the line. It should either be a host name, or one of the special words <system>, <none> and <ignore>. If <system> is given, then the gethostname(2) systemcall is used to get the host name. This is the default. If <ignore> is given, then a flag is set so that when arrays are being auto-assembled the checking of the recorded homehost is disabled. If <ignore> is given it is also possible to give an explicit name which will be used when creating arrays. This is the only case when there can be more that one other word on the HOMEHOST line. If there are other words, or other HOMEHOST lines, they are silently ignored. If <none> is given, then the default of using gethostname(2) is over-ridden and no homehost name is assumed. When arrays are created, this host name will be stored in the metadata. When arrays are assembled using auto-assembly, arrays which do not record the correct homehost name in their metadata will be assembled using a "foreign" name. A "foreign" name alway ends with a digit string preceded by an underscore to differentiate it from any possible local name. e.g. /dev/md/1_1 or /dev/md/home_0.
HOMECLUSTER
The homcluster line gives a default value for the --homecluster= option to mdadm. It specifies the cluster name for the md device. The md device can be assembled only on the cluster which matches the name specified. If homcluster is not provided, mdadm tries to detect the cluster name automatically. There should only be one homecluster line. Any subsequent lines will be silently ignored.
AUTO
A list of names of metadata format can be given, each preceded by a plus or minus sign. Also the word homehost is allowed as is all preceded by plus or minus sign. all is usually last. When mdadm is auto-assembling an array, either via --assemble or --incremental and it finds metadata of a given type, it checks that metadata type against those listed in this line. The first match wins, where all matches anything. If a match is found that was preceded by a plus sign, the auto assembly is allowed. If the match was preceded by a minus sign, the auto assembly is disallowed. If no match is found, the auto assembly is allowed. If the metadata indicates that the array was created for this host, and the word homehost appears before any other match, then the array is treated as a valid candidate for auto-assembly. This can be used to disable all auto-assembly (so that only arrays explicitly listed in mdadm.conf or on the command line are assembled), or to disable assembly of certain metadata types which might be handled by other software. It can also be used to disable assembly of all foreign arrays - normally such arrays are assembled but given a non-deterministic name in /dev/md/. The known metadata types are 0.90, 1.x, ddf, imsm. AUTO should be given at most once. Subsequent lines are silently ignored. Thus a later config file in a config directory will not overwrite the setting in an earlier config file.
POLICY
This is used to specify what automatic behavior is allowed on devices newly appearing in the system and provides a way of marking spares that can be moved to other arrays as well as the migration domains. Domain can be defined through policy line by specifying a domain name for a number of paths from /dev/disk/by-path/. A device may belong to several domains. The domain of an array is a union of domains of all devices in that array. A spare can be automatically moved from one array to another if the set of the destination array's domains contains all the domains of the new disk or if both arrays have the same spare-group. To update hot plug configuration it is necessary to execute mdadm --udev-rules=<path_to_file> e.g. /etc/udev/rules.d/65-md-bare.rules command after changing the config file. And also run udevadm control --reload otherwise, a reboot is needed. Keywords used in the POLICY line and supported values are:
domain=
any arbitrary string
metadata=
0.9 1.x ddf or imsm
path=
file glob matching anything from /dev/disk/by-path
type=
either disk or part.
action=
include, re-add, spare, spare-same-slot, or force-spare
auto=
yes, no, or homehost.

The action item determines the automatic behavior allowed for devices matching the path and type in the same line. If a device matches several lines with different actions then the most permissive will apply. The ordering of policy lines is irrelevant to the end result.

include
allows adding a disk to an array if metadata on that disk matches that array
re-add
will include the device in the array if it appears to be a current member or a member that was recently removed and the array has a write-intent-bitmap to allow the re-add functionality.
spare
as above and additionally: if the device is bare it can become a spare if there is any array that it is a candidate for based on domains and metadata.
spare-same-slot
as above and additionally if given slot was used by an array that went degraded recently and the device plugged in has no metadata then it will be automatically added to that array (or it's container)
force-spare
as above and the disk will become a spare in remaining cases
PART-POLICY
This is similar to POLICY and accepts the same keyword assignments. It allows a consistent set of policies to applied to each of the partitions of a device. A PART-POLICY line should set type=disk and identify the path to one or more disk devices. Each partition on these disks will be treated according to the action= setting from this line. If a domain is set in the line, then the domain associated with each patition will be based on the domain, but with "-partN" appended, when N is the partition number for the partition that was found.
SYSFS
The SYSFS line lists custom values of MD device's sysfs attributes which will be stored in sysfs after the array is assembled. Multiple lines are allowed and each line has to contain the uuid or the name of the device to which it relates. Lines are applied in reverse order.
uuid=
hexadecimal identifier of MD device. This has to match the uuid stored in the superblock.
name=
name of the MD device as was given to mdadm when the array was created. It will be ignored if uuid is not empty.
MONITORDELAY
The MONITORDELAY line specifies the time in seconds to wait before checking for events. The default is 60 seconds.
mdadm.conf(5) — Arch Linux Manual Pages

NAME

mdadm.conf

configuration file for mdadm

DESCRIPTION

The mdadm.conf file contains configuration options for mdadm when it is running in monitor mode (mdadm(8)). It can also be used to define array layouts, though this is generally not recommended as mdadm can discover these from the superblock on the component devices.

The configuration file consists of a list of KEY=VALUE pairs, one per line. Lines starting with '#' are comments.

Recognised keywords are:

DEVICE
The DEVICE line takes a list of drives and/or partitions that mdadm should be aware of. These are used for detecting new arrays and for identifying devices that are spares. The list can be space or comma-separated. The argument can also take a glob pattern, e.g. /dev/sd[a-z]1 for all partitions on devices sda through sdz. It is possible to have multiple DEVICE lines.
ARRAY
The ARRAY line defines a specific RAID array. It is followed by a list of parameters. Most parameters are optional. The basic format is ARRAY [devices]. For example:

ARRAY /dev/md0

This tells mdadm that /dev/md0 exists. This is not usually necessary, as mdadm can detect arrays from the superblocks. However, it can be used to specify metadata version, UUID, devices that make up the array, spares, and other properties.

The parameters are:

devices=...
Specifies the component devices for the array. If this is given, then mdadm will only consider these devices to be part of the array. If no devices are listed, then mdadm will scan the devices listed in the DEVICE config lines.
uuid=
Specifies the UUID of the array. This is the most reliable way to identify an array.
superminor=
Specifies the minor number of the array. This is used for older metadata versions or if UUIDs are not available.
name=
Specifies the name of the array. This is typically the device name, e.g. md0. This is mainly used by the monitor daemon.
spare-group=
Assigns the array to a spare group. Spares in this group can be used for any array in the same group.
auto=
Can be yes or no. If set to yes, then mdadm will attempt to assemble the array automatically if it is not already running. If set to no, mdadm will not assemble it automatically.
metadata=
Specifies the metadata version to be used when creating new arrays. This is typically not used for existing arrays.
policy=
Defines policies for the array, such as for IMSM. See the POLICY keyword description.
MAILADDR
The address to which email alerts should be sent. This is used by the monitor daemon.
PROGRAM
The program to call when an event occurs. This is used by the monitor daemon.
CREATE
Specifies default parameters for creating new arrays. For example:

CREATE group=system mode=0640 auto=yes

This means that newly created arrays will be added to the 'system' spare-group, will have permissions 0640, and will be auto-assembled.

Recognised parameters:

group=
Assigns the new array to the specified spare group.
mode=
Sets the file permissions for the new array device node.
auto=
Determines whether the new array should be auto-assembled.
num-devices=
Specifies the number of devices to use when creating a new array. This is useful when creating a new array with spares.
HOMEHOST
Specifies the home host for an array. This is used by the monitor daemon to determine which host is responsible for managing the array.
AUTO
Specifies which arrays should be automatically assembled. Prefixes can be used, e.g. AUTO +1.x to assemble all arrays with a minor number of 1 or greater.
LOGFILE
Specifies the file to which mdadm should log events. This is used by the monitor daemon.
RUN_ARRAY_AS_ROOT
If set to no, mdadm will attempt to run array operations as the user specified by the USER directive, rather than as root. Defaults to yes.
USER
Specifies the user to run array operations as, if RUN_ARRAY_AS_ROOT is set to no.
SYSFS
This keyword can be used to override or set sysfs attributes for a given array. It is followed by the device name and then a list of attribute=value pairs. For example:

SYSFS /dev/md0 rank=3 sync_speed_max=100000

This sets the rank of /dev/md0 to 3 and the maximum sync speed to 100000 sectors/second.
MONITORDELAY
The monitordelay line gives a delay in seconds mdadm shall wait before pooling md arrays when mdadm is running in --monitor mode. -d/--delay command line argument takes precedence over the config file.

If multiple MINITORDELAY lines are provided, only first non-zero value is considered.

ENCRYPTION_NO_VERIFY
The ENCRYPTION_NO_VERIFY disables encryption verification for devices with particular encryption support detected. Currently, only verification of SATA OPAL encryption can be disabled. It does not disable ATA security encryption verification. Currently effective only for IMSM metadata. Available parameter sata_opal .

FILES

/etc/mdadm.conf

The default config file location, used when mdadm is running without --config option.

/etc/mdadm.conf.d

The default directory with config files. Used when mdadm is running without --config option, after successful reading of the /etc/mdadm.conf default config file. Files in that directory are read in lexical order.

/etc/mdadm/mdadm.conf

Alternative config file that is read, when mdadm is running without --config option and the /etc/mdadm.conf default config file was not opened successfully.

/etc/mdadm/mdadm.conf.d

The alternative directory with config files. Used when mdadm is runninng without --config option, after reading the /etc/mdadm/mdadm.conf alternative config file whether it was successful or not. Files in that directory are read in lexical order.

EXAMPLE

DEVICE /dev/sd[bcdjkl]1
DEVICE /dev/hda1 /dev/hdb1

# /dev/md0 is known by its UUID.
ARRAY /dev/md0 UUID=3aaa0122:29827cfa:5331ad66:ca767371
# /dev/md1 contains all devices with a minor number of
# 1 in the superblock.
ARRAY /dev/md1 superminor=1
# /dev/md2 is made from precisely these two devices
ARRAY /dev/md2 devices=/dev/hda1,/dev/hdb1

# /dev/md4 and /dev/md5 are a spare-group and spares
# can be moved between them
ARRAY /dev/md4 uuid=b23f3c6d:aec43a9f:fd65db85:369432df
spare-group=group1
ARRAY /dev/md5 uuid=19464854:03f71b1b:e0df2edd:246cc977
spare-group=group1
# /dev/md/home is created if need to be a partitionable md array
# any spare device number is allocated.
ARRAY /dev/md/home UUID=9187a482:5dde19d9:eea3cc4a:d646ab8b
auto=part
# One domain comprising of devices attached to specified paths is defined.
# Bare device matching first path will be made an imsm spare on hot plug.
# If more than one array is created on devices belonging to domain1 and
# one of them becomes degraded, then any imsm spare matching any path for
# given domain name can be migrated.
POLICY domain=domain1 metadata=imsm path=pci-0000:00:1f.2-scsi-*
action=spare
POLICY domain=domain1 metadata=imsm path=pci-0000:04:00.0-scsi-[01]*
action=include
MAILADDR root@mydomain.tld
PROGRAM /usr/sbin/handle-mdadm-events
CREATE group=system mode=0640 auto=part-8
HOMEHOST <system>
AUTO +1.x homehost -all
SYSFS name=/dev/md/raid5 group_thread_cnt=4 sync_speed_max=1000000
SYSFS uuid=bead5eb6:31c17a27:da120ba2:7dfda40d group_thread_cnt=4 sync_speed_max=1000000
MONITORDELAY 60
ENCRYPTION_NO_VERIFY sata_opal
