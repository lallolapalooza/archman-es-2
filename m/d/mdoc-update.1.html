mdoc-update(1)

Paquete: mono

mdoc-update(1) Manual General de Comandos mdoc-update(1)

NOMBRE

mdoc update - soporte para el formato de documentación mdoc(5)

SINOPSIS

mdoc update [OPCIONES]* ENSAMBLADOS

DESCRIPCIÓN

mdoc update es responsable de lo siguiente:

*
Crear plantillas de documentación basadas en ENSAMBLADOS. El proceso de creación de plantillas creará nuevos archivos XML de mdoc(5) para cada tipo dentro de ENSAMBLADOS, y proporcionará plantillas de documentación para cada miembro de esos tipos.
*
Actualizar plantillas de documentación basadas en ENSAMBLADOS. La documentación de mdoc(5) existente puede ser actualizada para reflejar cambios dentro de ENSAMBLADOS, como tipos y miembros añadidos, mientras se preserva la documentación existente.

En algunas circunstancias limitadas, se rastrearán los cambios de nombre, minimizando la carga de documentación cuando, por ejemplo, se renombra un parámetro.

mdoc update no depende de la documentación encontrada dentro del código fuente, aunque puede importar Comentarios de Documentación XML a través de la opción -i.

Ver mdoc(1) y mdoc(5) para más información.

OPCIONES

--delete
Permitir que mdoc update elimine miembros de los archivos de documentación. Los únicos miembros eliminados son aquellos que ya no están presentes dentro de ENSAMBLADOS y no están presentes en ninguna otra versión de ensamble.

Si un tipo ya no está presente, el archivo de documentación no se elimina, sino que se renombra para tener la extensión .remove.

La detección de versiones se realiza con los elementos //AssemblyVersion; si no hay elementos //AssemblyVersion para un <Type> o <Member/> dado, entonces el <Type> se renombrará y/o el <Member/> se eliminará.

--exceptions[=FUENTES]
EXPERIMENTAL. Esto no es 100% fiable, pero está destinado a servir como ayuda para los escritores de documentación.

Inspeccionar cuerpos de miembros para determinar qué excepciones pueden generarse a partir del miembro.

FUENTES es una lista opcional separada por comas de las siguientes fuentes que deben buscarse para encontrar excepciones:

        added   Generar solo elementos <exception/> para los miembros 
                  añadidos durante la ejecución actual del programa.
                  Esto evita que mdoc-update regenere elementos
                  <exception/> para todos los miembros (y por lo tanto,
                  previene la reinserción para miembros a los que se les
                  eliminaron los elementos <exception/>).
        all     Encontrar excepciones creadas en el miembro mismo, 
                  referencias a miembros en el mismo ensamble y 
                  referencias a miembros en ensambles dependientes.
        asm     Encontrar excepciones creadas en el miembro mismo y
                  referencias a miembros dentro del mismo ensamble
                  que el miembro.
        depasm  Encontrar excepciones creadas en el miembro mismo y
                  referencias a miembros dentro de ensambles dependientes.

Si no se proporciona FUENTES (el valor por defecto), entonces solo se documentarán las excepciones creadas dentro del miembro mismo.

LIMITACIONES: La búsqueda de excepciones está implementada actualmente buscando los tipos de excepción que se crean explícitamente basados en los tipos conocidos en tiempo de compilación. Esto tiene las siguientes limitaciones:

*
Esto no encontrará excepciones que son implícitas al IL, como NullReferenceException e IndexOutOfRangeException.
*
Esto encontrará excepciones que no se lanzan, por ejemplo: 
    public void CreateAnException ()
    {
        Exception e = new Exception ();
    }
*
Esto no "seguirá" las llamadas a delegados e interfaces: 
    public void UsesDelegates ()
    {
        Func<int, int> a = x => {throw new Exception ();};
        a (4);
    }
La función UsesDelegates() no tendrá ninguna excepción documentada.
*
Esto encontrará excepciones que "no pueden suceder", como ArgumentNullExceptions para argumentos que se "sabe" que no son nulos: 
    public void A ()
    {
        B ("este parámetro no es nulo");
    }
    public void B (string s)
    {
        if (s == null)
            throw new ArgumentNullException ("s");
    }
Para lo anterior, si se proporciona --exceptions=asm, entonces A() será documentado como lanzando una ArgumentNullException, lo cual no puede suceder.
-f=BANDERA
Especificar una bandera para alterar el comportamiento. Las banderas válidas incluyen:
no-assembly-versions
Ver la documentación de -fno-assembly-versions, abajo.
-fno-assembly-versions
No generar elementos /Type/AssemblyInfo/AssemblyVersion y /Type/Members/Member/AssemblyInfo.

Esto es útil para prevenir "agitación" durante las actualizaciones. Normalmente, si un tipo o miembro no ha cambiado pero la versión del ensamble ha cambiado, entonces todos los tipos y miembros se actualizarán para incluir un nuevo elemento //AssemblyVersion, aumentando así la cantidad de cambios que necesitan ser revisados antes de confirmar (suponiendo que todos los cambios son realmente revisados antes de confirmar).

ADVERTENCIA: Esto interactuará mal con la opción --delete, ya que --delete utiliza los elementos //AssemblyVersion para rastrear cambios de versión. Por lo tanto, si tiene un miembro que está presente en una versión temprana del ensamble y se elimina en una versión posterior, como System.Text.UTF8Encoding.GetBytes(string) (que está presente en .NET 1.0 pero no en .NET 2.0), entonces el miembro se eliminará cuando se especifiquen las opciones --delete -fno-assembly-versions, el miembro estaba presente en una versión anterior del ensamble y la versión actual del ensamble no contiene el miembro.

En consecuencia, esta opción solo debe especificarse si los tipos y miembros nunca serán eliminados de un ensamble.

-i, --import=ARCHIVO
Importar documentación encontrada dentro de ARCHIVO.

ARCHIVO puede contener XML de csc /doc o XML de ECMA-335.

-L, --lib=DIRECTORIO
Añadir DIRECTORIO a la ruta de búsqueda de ensambles, para que las dependencias de ENSAMBLADOS puedan ser encontradas sin documentar dichos ensambles.
-o, --out=DIRECTORIO
Colocar las plantillas generadas en DIRECTORIO.

Al actualizar la documentación, DIRECTORIO es también el directorio fuente.

-r=ENSAMBLE
ENSAMBLE es una dependencia para uno de ENSAMBLADOS que no debe ser documentado pero es necesario para procesar uno de ENSAMBLADOS. Añadir el directorio que contiene ENSAMBLE a la ruta de búsqueda de ensambles.

Esta opción es equivalente a especificar -L `dirname ENSAMBLE`.

--since=VERSIÓN
Al actualizar la documentación para un ensamble, si se encuentra un tipo o miembro que no existía en la versión anterior del ensamble, se insertará un elemento <since version="VERSIÓN"/>.
--type=TIPO
Solo actualizar la documentación para el tipo TIPO.
-h, -?, --help
Mostrar un mensaje de ayuda y salir.
