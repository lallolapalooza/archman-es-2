mdoc-assemble(1) Manual de Comandos Generales mdoc-assemble(1)

NOMBRE

mdoc assemble - Compila documentación para usarla en el navegador de documentación monodoc(1)

SINOPSIS

mdoc assemble [OPCIONES]+ RUTAS+

DESCRIPCIÓN

mdoc assemble crea archivos .tree y .zip a partir de RUTAS para ser utilizados en el navegador de documentación monodoc(1).

Los archivos de entrada deben tener un formato compatible, especificado con la opción --format.

Los archivos .tree y .zip se copian al directorio sources de monodoc, junto con un archivo .source que es utilizado por monodoc(1) para especificar dónde se debe mostrar la documentación.

El archivo .source tiene el siguiente formato:

  <?xml version="1.0"?>
  <monodoc>
    <node label="ETIQUETA" name="RUTA" parent="PADRE">
      <node label="ETIQUETA2" name="RUTA2" />
      <!-- ... -->
    </node>
    <source provider="PROVEEDOR" basefile="NOMBREBASEARCHIVO" path="RUTA" />
    <!-- otros elementos <source/> -->
  </monodoc>
El nodo /monodoc/node es un nodo opcional que especifica dónde se mostrará la documentación en el árbol de monodoc, y los elementos //node pueden anidarse a cualquier profundidad para crear árboles. //node/@label es la etiqueta que se mostrará dentro del árbol de monodoc.

//node/@name es el nombre del nodo del árbol de monodoc y puede usarse como valor de /monodoc/source/@path.

//node/@parent es el nombre del nodo que se utilizará como nodo padre. $MONO_INSTALL_PREFIX/lib/monodoc/monodoc.xml contiene una lista de dichos nombres, y puede ser cualquier valor de //node/@name. Si el valor //node/@parent no se encuentra, se inserta bajo el nodo "Various" del árbol.

El atributo /monodoc/source/@provider especifica qué proveedor de formato se debe usar al leer los archivos .tree y .zip; esto debe corresponder a uno de los valores de --format.

El atributo /monodoc/source/@basefile especifica el prefijo del nombre de archivo para los archivos de documentación. Debe ser el mismo prefijo que se usó con el parámetro --out. No debe haber extensión de nombre de archivo en este valor.

El atributo /monodoc/source/@path especifica el nodo padre en la vista de árbol de monodoc(1) donde se insertará la documentación. Consulte el archivo $MONO_INSTALL_PREFIX/lib/monodoc/monodoc.xml para obtener una lista de valores de RUTA (los valores de //node/@name), o puede ser un valor de //node/@name en el mismo archivo .source.

Una vez que se ha escrito NOMBREBASEARCHIVO.source, la documentación puede instalarse para que monodoc(1) la muestre con el comando:

  cp NOMBREBASEARCHIVO.source NOMBREBASEARCHIVO.tree NOMBREBASEARCHIVO.zip \
    `pkg-config monodoc --variable=sourcesdir`

OPCIONES

-f, --format=FORMATO
Especifica el formato de documentación utilizado dentro de RUTAS. Los valores válidos de FORMATO incluyen: ecma, ecmaspec, error, hb, man, simple y xhtml.

Consulte la sección FORMATOS a continuación para obtener más información sobre estos formatos.

El formato predeterminado (si no se especifica ninguno) es ecma.

La opción --format puede intercalarse con RUTAS para cambiar el formato utilizado para los parámetros restantes (hasta que se vea la siguiente opción --format), p. ej.:

  mdoc assemble -o PREFIJO A B --format=man C D --format=xhtml E
compilará los directorios A y B con el formato ecma, los archivos C y D con el formato man, y el directorio E con el formato xhtml.
-o, --out=PREFIJO
Especifica el prefijo del archivo de salida. mdoc assemble crea los archivos PREFIJO.zip y PREFIJO.tree.
-h, -?, --help
Muestra un mensaje de ayuda y sale.

FORMATOS

Se soportan los siguientes formatos de documentación:

ecma

El Formato de Documentación ECMA de Mono, un formato de documentación XML con un archivo por tipo.

Consulte la página del manual mdoc(5) para más información.

ecmaspec

El Formato de Documentación de Especificación ECMA de Mono. Este no es el formato que está buscando; es el formato utilizado para representar el estándar ECMA-334 (C#) dentro de monodoc(1). No se usa para mostrar la documentación de la biblioteca de clases; para la documentación de la biblioteca de clases, use el formato ecma.

error

El Formato de Documentación de Errores se utiliza para presentar mensajes de error detallados y se usa en el árbol de "Referencia de Errores del Compilador C#" de monodoc(1).

En este formato, RUTAS es un archivo de configuración, que contiene el XML:

    <ErrorProviderConfig>
        <FilesPath>../../mcs/errors</FilesPath>
        <Match>cs????*.cs</Match>
        <ErrorNumSubstringStart>2</ErrorNumSubstringStart>
        <ErrorNumSubstringLength>4</ErrorNumSubstringLength>
        <FriendlyFormatString>CS{0:0###}</FriendlyFormatString>
    </ErrorProviderConfig>
Los elementos significan:
/ErrorProviderConfig/FilesPath
Especifica dónde buscar los archivos.
/ErrorProviderConfig/Match
Especifica el patrón de nombre de archivo a buscar dentro del directorio /ErrorProviderConfig/FilesPath.
/ErrorProviderConfig/ErrorNumSubstringStart
Especifica dónde dentro del nombre de archivo comienza el número de error.
/ErrorProviderConfig/ErrorNumSubstringLength
Especifica cuántos caracteres después de /ErrorProviderConfig/ErrorNumSubstringStart usar para el número de error.
/ErrorProviderConfig/FriendlyFormatString
Especifica el formato/visualización del nodo en la vista de árbol de monodoc(1).

Para cada archivo encontrado, se convierte a HTML con coloración de sintaxis C# aplicada.

simple

El Formato de Documentación Simple añade recursivamente todos los archivos y directorios debajo de RUTAS. Cuando se muestran, los archivos HTML se muestran tal cual. Los archivos de texto se convierten a HTML traduciendo cada nueva línea en un elemento <br> de HTML. No se soportan otros tipos de archivo.

man

El Formato de Documentación de Páginas Man muestra páginas man de groff. (Esto no es un analizador groff completo y solo maneja las construcciones de páginas man utilizadas dentro de las páginas man de mono.)

RUTAS es un conjunto de archivos XML que contienen:

  <?xml version="1.0"?>
  <manpages>
    <manpage name="NOMBRE" page="ARCHIVO" />
  </manpages>
Puede haber múltiples elementos //manpage dentro del elemento raíz /manpage.

El atributo /manpages/manpage/@name contiene el nombre de visualización para el nodo de vista de árbol, que también es la URL de la página man cuando se usa el comando Buscar URL de monodoc(1) (antes de añadir el prefijo man:). Por lo tanto, si /manpages/manpage/@name contiene mono(1), entonces man:mono(1) puede usarse en el comando Buscar URL para ver la página man de mono(1).

El atributo /manpages/manpage/@page es el nombre del archivo que contiene la página man. Si este archivo no existe, entonces /manpages/manpage/@name no se mostrará en la vista de árbol.

xhtml

mdoc-assemble(1) - Arch Linux

SYNOPSIS

mdoc-assemble [options] files...

DESCRIPTION

The mdoc-assemble utility concatenates files that contain Mdoc(5) documentation into a single document. It takes a list of files, parses them, and generates a single Mdoc(5) document.

This is useful for creating a single man page from multiple source files. For example, you might have a main man page file and several files containing code examples. mdoc-assemble can combine these into a single, cohesive document.

The files are processed in the order they are given on the command line. Any include directives in the files are processed recursively.

OPTIONS

-r, --root root
Specifies the root directory for resolving include directives. This is useful when your documentation files are organized in a directory structure.
-h, --help
Prints a help message and exits.
-v, --version
Prints version information and exits.
