NGREP(8) Manuales de Usuario NGREP(8)

NOMBRE

ngrep - grep de red

SINOPSIS

ngrep <-hNXViwqpevxlDtTRMCu> <-IO pcap_dump > < -n num > < -d dev > < -A num > < -s snaplen > < -S limitlen > < -W normal|byline|single|none > < -c cols > < -P char > < -F file > < expresión de coincidencia > < filtro bpf >

DESCRIPCIÓN

ngrep se esfuerza por proporcionar la mayoría de las características comunes de GNU grep, aplicándolas a la capa de red. ngrep es una herramienta consciente de pcap que permitirá especificar expresiones regulares extendidas para hacer coincidir las cargas útiles de datos de los paquetes. Actualmente reconoce TCP, UDP y ICMP en interfaces Ethernet, PPP, SLIP, FDDI y null, y comprende la lógica de filtro bpf de la misma manera que herramientas de análisis de paquetes más comunes, como tcpdump(8) y snoop(1).

OPCIONES

-h
Mostrar ayuda/información de uso.
-N
Mostrar el número de subprotocolo junto con el identificador de un solo carácter (útil al observar protocolos crudos o desconocidos).
-X
Tratar la expresión de coincidencia como una cadena hexadecimal. Consulte la explicación de expresión de coincidencia a continuación.
-V
Mostrar información de la versión.
-i
Ignorar mayúsculas/minúsculas para la expresión regex.
-w
Coincidir la expresión regex como una palabra.
-q
Silencioso; no mostrar ninguna información aparte de las cabeceras de los paquetes y sus cargas útiles (si son relevantes).
-p
No poner la interfaz en modo promiscuo.
-e
Mostrar paquetes vacíos. Normalmente, los paquetes vacíos se descartan porque no tienen carga útil para buscar. Si se especifica, se mostrarán los paquetes vacíos, independientemente de la expresión regex especificada.
-v
Invertir la coincidencia; mostrar solo los paquetes que no coinciden.
-x
Mostrar el contenido del paquete como hexadecimal y ASCII.
-l
Hacer que la salida estándar tenga búfer de línea.
-C
Colorear las coincidencias en la salida del contenido del paquete.
-u
Mostrar caracteres UTF-8 en la salida del contenido del paquete.
-D
Al leer archivos pcap_dump, reproducirlos en sus intervalos de tiempo grabados (simular tiempo real).
-t
Imprimir una marca de tiempo en formato AAAA/MM/DD HH:MM:SS.UUUUUU cada vez que se coincide con un paquete.
-T
Imprimir una marca de tiempo en formato +S.UUUUUU, que indica la diferencia entre coincidencias de paquetes. Especificar una segunda vez para indicar la diferencia desde la primera coincidencia de paquete.
-R
No intentar reducir privilegios al usuario DROPPRIVS_USER (especificado en tiempo de compilación).

ngrep no hace ningún esfuerzo por validar la entrada de fuentes en vivo o fuera de línea, ya que se centra más en el rendimiento y en el manejo de grandes cantidades de datos que en la corrección del protocolo, lo cual es una suposición justa la mayoría de las veces. Sin embargo, a veces importa y, por lo tanto, como regla general, ngrep intentará ser defensivo y eliminar cualquier privilegio de root que pueda tener.

Existen escenarios donde este comportamiento puede ser un obstáculo, por lo que esta opción se proporciona a los usuarios finales que desean deshabilitar esta característica, pero deben hacerlo con una comprensión de los riesgos. Los paquetes pueden estar malformados aleatoriamente o incluso diseñados específicamente para desbordar los sniffers y tomar el control de ellos, y revocar los privilegios de root es actualmente la única mitigación de riesgos que ngrep emplea contra dicho ataque. Utilice esta opción y desactívela bajo su propio riesgo.

-c cols
Establecer explícitamente el ancho de la consola a ``cols''. Tenga en cuenta que este es el ancho de la consola y no el ancho completo de lo que ngrep imprime como cargas útiles; dependiendo del modo de salida, ngrep puede imprimir menos de ``cols'' bytes por línea (indentación).
-F file
Leer el filtro bpf del nombre de archivo especificado. Esta es una opción de compatibilidad para usuarios familiarizados con tcpdump. Tenga en cuenta que especificar ``-F'' anulará cualquier filtro bpf especificado en la línea de comandos.
-P char
Especificar un carácter alternativo para indicar caracteres no imprimibles cuando se muestran. El valor predeterminado es ``.''.
-K num
Matar conexiones TCP coincidentes (como tcpkill). El argumento numérico controla cuántos segmentos RST se envían.
-W normal|byline|single|none
Especificar una forma alternativa de mostrar paquetes, cuando no se está en modo hexadecimal. El modo ``byline'' respeta los saltos de línea incrustados, envolviendo el texto solo cuando se encuentra un salto de línea (útil para observar transacciones HTTP, por ejemplo). El modo ``none'' no envuelve bajo ninguna circunstancia (la carga útil completa se muestra en una sola línea). El modo ``single'' es conceptualmente el mismo que ``none'', excepto que todo, incluida la información de cabecera IP y de origen/destino, está en una sola línea. ``normal'' es el modo predeterminado y solo se incluye para completar. Esta opción es incompatible con ``-x''.
-s snaplen
Establecer el caplen bpf a snaplen (predeterminado 65536).
-S limitlen
Establecer el límite superior del tamaño de los paquetes que ngrep examinará. Útil para examinar solo los primeros N bytes de los paquetes sin cambiar el BPF snaplen.
-I pcap_dump
Archivo de entrada pcap_dump a ngrep. Funciona con cualquier formato de archivo de volcado compatible con pcap. Esta opción es útil para buscar una amplia gama de patrones diferentes en el mismo flujo de paquetes.
-O pcap_dump
Salida de paquetes coincidentes a un archivo de volcado compatible con pcap. Esta característica no interfiere con la salida normal a la salida estándar.
-n num
Coincidir solo num paquetes en total, luego salir.
-d dev
Por defecto, ngrep seleccionará una interfaz predeterminada para escuchar. Utilice esta opción para forzar a ngrep a escuchar en la interfaz dev.
-A num
Mostrar num paquetes de contexto de seguimiento después de que se coincida con un paquete.
expresión de coincidencia
Una expresión de coincidencia es una expresión regular extendida, o si se especifica la opción -X, una cadena que representa un valor hexadecimal. Una expresión regular extendida sigue las reglas según lo implementado por la biblioteca GNU regex. Las expresiones hexadecimales pueden ir precedidas opcionalmente por `0x'. Por ejemplo, `DEADBEEF', `0xDEADBEEF'.
filtro bpf
Selecciona un filtro que especifica qué paquetes se volcarán. Si no se proporciona un filtro bpf, se volcarán todos los paquetes IP vistos en la interfaz seleccionada. De lo contrario, solo se volcarán los paquetes para los cuales el filtro bpf sea `true'.

El filtro bpf consta de uno o más primitivas. Las primitivas suelen consistir en un id (nombre o número) precedido por uno o más calificadores. Hay tres tipos diferentes de calificador:

tipo
los calificadores indican a qué tipo de elemento se refiere el nombre o número del id. Los tipos posibles son host, net y port. Por ejemplo, `host blort', `net 1.2.3', `port 80'. Si no hay un calificador de tipo, se asume host.
dir
los calificadores especifican una dirección de transferencia particular t
o y/o desde id. Las direcciones posibles son src, dst, src or dst y src and dst. Por ejemplo, `src foo', `dst net 1.2.3', `src or dst port ftp-data'. Si no hay calificador de dirección, se asume src or dst. Para capas de enlace `null' (es decir, protocolos punto a punto como slip) se pueden usar los calificadores inbound y outbound para especificar una dirección deseada.
proto
Los calificadores están restringidos a protocolos solo de IP. Los protocolos posibles son: tcp , udp y icmp. Por ejemplo, `udp src foo' o `tcp port 21'. Si no hay calificador de protocolo, se asumen todos los protocolos consistentes con el tipo. Por ejemplo, `src foo' significa `ip and ((tcp or udp) src foo)', `net bar' significa `ip and (net bar)', y `port 53' significa `ip and ((tcp or udp) port 53)'.

Además de lo anterior, existen algunas palabras clave `primitivas' especiales que no siguen el patrón: gateway, broadcast, less, greater y expresiones aritméticas. Todas ellas se describen a continuación.

Se construyen expresiones de filtro más complejas utilizando las palabras and, or y not para combinar primitivas. Por ejemplo, `host blort and not port ftp and not port ftp-data'. Para ahorrar escritura, se pueden omitir listas de calificadores idénticas. Por ejemplo, `tcp dst port ftp or ftp-data or domain' es exactamente lo mismo que `tcp dst port ftp or tcp dst port ftp-data or tcp dst port domain'.

Las primitivas permitidas son:

dst host host
Verdadero si el campo de destino IP del paquete es host, que puede ser una dirección o un nombre.
src host host
Verdadero si el campo de origen IP del paquete es host.
host host
Verdadero si el origen o el destino IP del paquete es host. Se pueden anteponer a cualquiera de las expresiones de host anteriores las palabras clave ip, arp o rarp, como en: 
ip host
    host

que es equivalente a:
ether dst ehost
Verdadero si la dirección de destino ethernet es ehost. Ehost puede ser un nombre de /etc/ethers o un número (ver ethers(3N) para el formato numérico).
ether src ehost
Verdadero si la dirección de origen ethernet es ehost.
ether host ehost
Verdadero si la dirección de origen o destino ethernet es ehost.
gateway host
Verdadero si el paquete utilizó host como gateway. Es decir, la dirección de origen o destino ethernet fue host pero ni el origen IP ni el destino IP fueron host. Host debe ser un nombre y debe encontrarse tanto en /etc/hosts como en /etc/ethers. (Una expresión equivalente es 
ether host
    ehost
     and not host
    host

que se puede usar tanto con nombres como con números para host / ehost.)
dst net net
Verdadero si la dirección de destino IP del paquete tiene un número de red de net. Net puede ser un nombre de /etc/networks o un número de red (ver networks(4) para más detalles).
src net net
Verdadero si la dirección de origen IP del paquete tiene un número de red de net.
net net
Verdadero si la dirección de origen o destino IP del paquete tiene un número de red de net.
net net mask mask
Verdadero si la dirección IP coincide con net con la máscara de red específica. Puede calificarse con src o dst.
net net/len
Verdadero si la dirección IP coincide con net con una máscara de red de len bits de ancho. Puede calificarse con src o dst.
dst port port
Verdadero si el paquete es ip/tcp o ip/udp y tiene un valor de puerto de destino de port. El port puede ser un número o un nombre utilizado en /etc/services (ver tcp(4P) y udp(4P)). Si se usa un nombre, se comprueban tanto el número de puerto como el protocolo. Si se usa un número o un nombre ambiguo, solo se comprueba el número de puerto (por ejemplo, dst port 513 imprimirá tanto el tráfico tcp/login como el tráfico udp/who, y port domain imprimirá tanto el tráfico tcp/domain como el udp/domain).
src port port
Verdadero si el paquete tiene un valor de puerto de origen de port.
port port
Verdadero si el puerto de origen o destino del paquete es port. Se pueden anteponer a cualquiera de las expresiones de puerto anteriores las palabras clave tcp o udp, como en: 
tcp src port
    port

que coincide solo con paquetes tcp cuyo puerto de origen es port.
less length
Verdadero si el paquete tiene una longitud menor o igual a length. Esto es equivalente a: 
len <=
    length.

greater length
Verdadero si el paquete tiene una longitud mayor o igual a length. Esto es equivalente a: 
len >=
    length.

ip proto protocol
Verdadero si el paquete es un paquete IP (ver ip(4P)) del tipo de protocolo protocol. Protocol puede ser un número o uno de los nombres tcp, udp o icmp. Tenga en cuenta que los identificadores tcp y udp también son palabras clave y deben escaparse con una barra invertida (\), que es \\ en la shell C.
ip broadcast
Verdadero si el paquete es un paquete de broadcast IP. Comprueba tanto las convenciones de broadcast de todos ceros como de todos unos, y busca la máscara de subred local.
ip multicast
Verdadero si el paquete es un paquete multicast IP.
ip
Abreviatura de: 
ether proto ip
tcp, udp, icmp
Abreviaturas de: 
ip proto
    p

donde p es uno de los protocolos anteriores.
expr relop expr
Verdadero si la relación se cumple, donde relop es uno de >, <, >=, <=, =, !=, y expr es una expresión aritmética compuesta de constantes enteras (expresadas en sintaxis C estándar), los operadores binarios normales [+, -, *, /, &, |], un operador de longitud y accesores especiales de datos del paquete. Para acceder a datos dentro del paquete, use la siguiente sintaxis: 
proto [
    expr :
    size ]

Proto es uno de ip, tcp, udp o icmp, e indica la capa de protocolo para la operación de indexación. El desplazamiento de bytes, relativo a la capa de protocolo indicada, se da por expr. Size es opcional e indica el número de bytes en el campo de interés; puede ser uno, dos o cuatro, y por defecto es uno. El operador de longitud, indicado por la palabra clave len, da la longitud del paquete.

Por ejemplo, `ether[0] & 1 != 0' captura todo el tráfico multicast. La expresión `ip[0] & 0xf != 5' captura todos los paquetes IP con opciones. La expresión `ip[6:2] & 0x1fff = 0' captura solo datagramas no fragmentados y el fragmento cero de datagramas fragmentados. Esta comprobación se aplica implícitamente a las operaciones de indexación tcp y udp. Por ejemplo, tcp[0] siempre significa el primer byte de la *cabecera* TCP, y nunca el primer byte de un fragmento intermedio.

Las primitivas se pueden combinar usando:

Un grupo entre paréntesis de primitivas y operadores (los paréntesis son especiales para el shell y deben escaparse).
Negación (`!' o `not').
Concatenación (`&&' o `and').
Alternancia (`||' o `or').

La negación tiene la mayor precedencia. La alternancia y la concatenación tienen la misma precedencia y se asocian de izquierda a derecha. Tenga en cuenta que ahora se requieren tokens and explícitos, no yuxtaposición, para la concatenación.

Si se proporciona un identificador sin una palabra clave, se asume la palabra clave más reciente. Por ejemplo, 

not host vs and ace
es una abreviatura de 
not host vs and host ace
que no debe confundirse con 
not ( host vs or ace )

Los argumentos de expresión se pueden pasar a ngrep como un solo argumento o como múltiples argumentos, lo que sea más conveniente. Generalmente, si la expresión contiene metacaracteres del shell, es más fácil pasarla como un solo argumento entre comillas. Los argumentos múltiples se concatenan con espacios antes de ser analizados.

DIAGNÓSTICOS

Los errores de ngrep, libpcap y la biblioteca de expresiones regulares GNU se envían a stderr.

ESTADO DE SALIDA

La utilidad ngrep sale con uno de los siguientes valores:


0 Se encontró al menos un marco coincidente.
1 No se encontró ningún marco coincidente.
2 Ocurrió un error.
3+ El infierno se está congelando, ¡corre!

ngrep(8)

NAME

ngrep - Network grep

SYNOPSIS

ngrep [ options ] [ pattern [ interface ] ]

DESCRIPTION

ngrep is intended as a more capable replacement for Ethereal, but with a command-line interface like grep. It can be used to match network traffic against a given regular expression.

ngrep will, by default, print all packets that match the given pattern. It can also be configured to match on arbitrary fields within packets by using the -q and -p options.

OPTIONS

-d interface
Specify the network interface to sniff on. If not specified, ngrep will use the first interface it finds that is not a loopback interface.
-i
Ignore case in the pattern.
-q
Quiet mode. Do not print packet contents. Only print matching packet headers.
-p
Promiscuous mode. Sniff all packets on the network, not just those addressed to the local host. This option is only effective if the network interface is in promiscuous mode.
-w
Only match whole words.
-f file
Read patterns from file, one per line.
-l
Use line buffering for output.
-n
Match only the first n packets.
-t
Print timestamp for each packet.
-O file
Write matched packets to file in pcap format.
-h
Print help message and exit.
-V
Print version information and exit.

DIAGNOSTICS

ngrep will exit with a non-zero status if an error occurs. This includes errors such as being unable to open the specified network interface or invalid regular expression syntax.

EXIT STATUS

ngrep exits with status 0 if successful, and non-zero otherwise.
