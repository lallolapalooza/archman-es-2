NGINX(8) Manual del Administrador del Sistema NGINX(8)

NOMBRE

nginx — Servidor proxy HTTP y de reenvío, servidor proxy de correo

SINOPSIS

nginx [-?hqTtVv] [-c archivo] [-e archivo] [-g directivas] [-p prefijo] [-s señal]

DESCRIPCIÓN

nginx (pronunciado “engine x”) es un servidor proxy HTTP y de reenvío, un servidor proxy de correo y un servidor proxy TCP/UDP genérico. Es conocido por su alto rendimiento, estabilidad, rico conjunto de características, configuración simple y bajo consumo de recursos.

Las opciones son las siguientes:

-?, -h
Imprime la ayuda.
-c archivo
Utiliza un archivo de configuración alternativo archivo.
-e archivo
Utiliza un archivo de registro de errores alternativo archivo. El valor especial stderr indica que se debe usar la salida de error estándar.
-g directivas
Establece directivas de configuración globales. Consulte EJEMPLOS para obtener detalles.
-p prefijo
Establece la ruta del prefijo. El valor predeterminado es /etc/nginx.
-q
Suprime mensajes que no sean de error durante la prueba de configuración.
-s señal
Envía una señal al proceso maestro. El argumento señal puede ser uno de: stop, quit, reopen, reload. La siguiente tabla muestra las señales del sistema correspondientes:
stop
SIGTERM
quit
SIGQUIT
reopen
SIGUSR1
reload
SIGHUP
-T
Igual que -t, pero además vuelca los archivos de configuración a la salida estándar.
-t
No ejecutar, solo probar el archivo de configuración. nginx comprueba la sintaxis del archivo de configuración y luego intenta abrir los archivos referenciados en el archivo de configuración.
-V
Imprime la versión de nginx, la versión del compilador y los parámetros del script de configure.
-v
Imprime la versión de nginx.

SEÑALES

El proceso maestro de nginx puede manejar las siguientes señales:

SIGINT, SIGTERM
Apagar rápidamente.
SIGHUP
Recargar la configuración, iniciar un nuevo proceso trabajador con una nueva configuración y apagar elegantemente los procesos trabajadores antiguos.
SIGQUIT
Apagar elegantemente.
SIGUSR1
Reabrir los archivos de registro.
SIGUSR2
Actualizar el ejecutable de nginx sobre la marcha.
SIGWINCH
Apagar los procesos trabajadores elegantemente.

Aunque normalmente no hay necesidad de controlar explícitamente los procesos trabajadores, estos admiten algunas señales también:

SIGTERM
Apagar rápidamente.
SIGQUIT
Apagar elegantemente.
SIGUSR1
Reabrir los archivos de registro.

REGISTRO DE DEPURACIÓN

Para habilitar un registro de depuración, recompile nginx con la opción de depuración:

./configure --with-debug ...

Y luego establezca el nivel de debug en error_log:

error_log /ruta/al/registro debug;

También es posible habilitar la depuración para una dirección IP particular:

events {
	debug_connection 127.0.0.1;
}

ENTORNO

La variable de entorno NGINX es utilizada internamente por nginx y no debe ser establecida directamente por el usuario.

ARCHIVOS

/run/nginx.pid
Contiene el ID de proceso de nginx. El contenido de este archivo no es sensible, por lo que puede ser legible por todos.
/etc/nginx/nginx.conf
El archivo de configuración principal.
stderr
Archivo de registro de errores.

ESTADO DE SALIDA

El estado de salida es 0 en caso de éxito, o 1 si el comando falla.

EJEMPLOS

Prueba el archivo de configuración ~/mynginx.conf con directivas globales para el PID y la cantidad de procesos trabajadores:

nginx -t -c ~/mynginx.conf \
	-g "pid /var/run/mynginx.pid; worker_processes 2;"

VER TAMBIÉN

Documentación en http://nginx.org/en/docs/.

Para preguntas y soporte técnico, por favor consulte http://nginx.org/en/support.html.

HISTORIA

El desarrollo de nginx comenzó en 2002, con el primer lanzamiento público el 4 de octubre de 2004.

nginx — high performance web server and reverse proxy

Version 1.29.3
Date 2024-06-19

Manual group Arch Linux
System Linux 6.9.4-arch1-1

NAME

nginx — high performance web server and reverse proxy

SYNOPSIS

nginx [-?hVv] [-c filename] [-g directives]

DESCRIPTION

The nginx program is a high-performance web server and reverse proxy server, as well as a load balancer, HTTP cache, and general proxy server for various protocols.

Normally, nginx is started as a daemon. It can be controlled by sending signals to the master process. The master process can be found using nginx -s reload or nginx -s quit.

SIGNALS

QUIT
Gracefully shut down the master process and all of its children.
TERM, INT
Immediate shutdown of the master process and all of its children.
HUP
Gracefully reload the configuration. The master process re-reads the configuration file, starts new worker processes with a new configuration, and gracefully shuts down old worker processes.
USR1
Reopen all log files. This is useful for log rotation.
USR2
Start a new master process with the same configuration. This is used for upgrading the nginx binary without stopping the server.
WINCH
Gracefully shut down a worker process. The master process receives this signal and sends it to all worker processes. This is useful to reduce the number of worker processes.

DEBUGGING LOG

To enable debugging log, compile nginx with the --with-debug option. Then, you can use the debug level for the error_log directive.

ENVIRONMENT

No environment variables are used.

FILES

/etc/nginx/nginx.conf
main configuration file
/var/log/nginx/access.log
access log
/var/log/nginx/error.log
error log

EXIT STATUS

0

Success.

1

An error occurred.

EXAMPLES

    # Start nginx with default configuration file
    nginx

    # Start nginx with a specific configuration file
    nginx -c /etc/nginx/nginx.conf

    # Reload nginx configuration
    nginx -s reload

    # Gracefully shut down nginx
    nginx -s quit

SEE ALSO

nginx.conf(5)

HISTORY

The nginx web server was created by Igor Sysoev and initially released to the public in 2004. It has since become one of the most popular web servers in the world.
