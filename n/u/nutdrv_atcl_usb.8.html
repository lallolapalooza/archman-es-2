NUTDRV_ATCL_USB(8) Manual de NUT NUTDRV_ATCL_USB(8)

NOMBRE

nutdrv_atcl_usb - Controlador para equipos 'ATCL FOR UPS'

SINOPSIS

nutdrv_atcl_usb -h

nutdrv_atcl_usb -a NOMBRE_UPS [OPCIONES]


Nota

Esta página del manual solo documenta las características específicas del controlador nutdrv_atcl_usb. Para obtener información sobre el controlador principal, consulte nutupsdrv(8).

HARDWARE SOPORTADO

Este controlador es para hardware de SAI que se identifica como idVendor 0001 e idProduct 0000, y iManufacturer ATCL FOR UPS. Los fabricantes conocidos incluyen Kanji y Plexus.

La interfaz del SAI parece ser un chip genérico USB a serie y, para el hardware fabricado por Kanji y Plexus, el microcontrolador parece emular una interfaz de cierre de contacto tradicional. Esto se traduce solo en tres estados en ups.status: OL, OB y OB LB (similar a genericups(8)), sin otros valores de estado dinámicos informados.

Tenga en cuenta que estos identificadores USB (incluida la cadena iManufacturer) también se han visto en dispositivos que son compatibles con el subcontrolador fuji de nutdrv_qx(8), y algunos otros.

ARGUMENTOS ADICIONALES

Este controlador admite la siguiente configuración opcional:

vendor = nombre

En caso de que su cadena iManufacturer (Vendor) no coincida exactamente con ATCL FOR UPS, puede proporcionar una cadena alternativa aquí (o especificar "NULL" si el dispositivo no proporciona una cadena de proveedor pero desea que este controlador coincida).

Tenga en cuenta que un caso más probable de coincidencia errónea es que su dispositivo sea manejado por otro controlador para dispositivos 0001:0000, como nutdrv_qx(8).


Nota
Este controlador no tiene la intención de admitir configuraciones de coincidencia USB comunes a otros controladores, como vendorid, product, productid, serial, device o bus; tampoco la configuración vendor admitida aquí es una expresión regular.

ERRORES

El SAI devuelve el mismo código para "la energía de carga está apagada" que para "energía en línea". Esta condición no se observará si el NUT upsmon en modo primario se ejecuta en la máquina alimentada por el SAI, pero puede ser un problema si el SAI es monitoreado por un sistema secundario remoto.

El tiempo entre el comando de apagado y la eliminación de energía parece ser fijo en 30 segundos. Asegúrese de que el script de apagado de NUT se invoque lo más tarde posible en el procedimiento de apagado (en caso de que algunos servicios tarden más que otros en limpiarse).

La mayoría de los SAI de cierre de contacto no apagarán la carga si la energía de línea está presente. Esto puede crear una condición de carrera al usar sistemas secundarios de upsmon(8). Vea la página del manual de upsmon(8) para más información. La solución a este problema es actualizar a un SAI con protocolo inteligente de algún tipo que permita la detección y el ciclo de carga adecuado bajo comando.
