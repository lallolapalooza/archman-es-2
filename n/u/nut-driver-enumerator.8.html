NUT-DRIVER-ENUMERA(8) Manual de NUT NUT-DRIVER-ENUMERA(8)

NOMBRE

nut-driver-enumerator - Herramienta para mapear entradas de controladores NUT a instancias de servicio

SINOPSIS

nut-driver-enumerator.sh -h

nut-driver-enumerator.sh (sin argumentos)

nut-driver-enumerator.sh [--COMANDO]

DESCRIPCIÓN

El script nut-driver-enumerator.sh (también conocido como "NDE") implementa la configuración y consulta del mapeo entre las secciones de configuración del controlador NUT para cada dispositivo monitorizado individualmente, y las instancias de servicio de un marco de gestión de servicios del sistema operativo (en plataformas donde NUT ya soporta esta integración — actualmente esto cubre distribuciones Linux con systemd y sistemas derivados de la base de código Solaris 10, incluyendo Solaris Sun/Oracle propietario y numerosas distribuciones illumos de código abierto con SMF), en las que dichos controladores se envuelven para su ejecución y gestión independiente. Puede que no esté instalado en paquetes para otros sistemas operativos.

Con cada controlador NUT representado como una instancia de servicio separada, se pueden definir dependencias (p. ej., los controladores de red deben iniciarse después de que la capacidad de red aparezca en el SO, pero los controladores USB/Serie no deben esperar a eso), y pueden fallar o ponerse en mantenimiento de forma independiente (a diferencia de un servicio monolítico basado en upsdrvctl(8) que requiere que se inicien todos los configurados). Para algunos controladores especiales como dummy-ups(8), clone(8), clone-outlet(8), y failover(8), esto también puede implicar una dependencia entre instancias de servicio de diferentes controladores NUT.

Este script proporciona una interfaz uniforme para herramientas NUT adicionales como upsdrvsvcctl(8) para implementar su lógica de la forma más independiente de la plataforma posible y práctica. Actualmente no está pensado para el consumo por parte del usuario final (y por lo tanto se encuentra en el directorio libexec), y upsdrvsvcctl expone los datos y acciones más útiles con sus argumentos list y resync.

Una parte de la complejidad de la plataforma que nut-driver-enumerator.sh oculta es la diferencia de reglas para nombres de instancias de servicio válidos en varios marcos, así como las herramientas del sistema y los patrones de nomenclatura involucrados.

Dependiendo de la plataforma, el script también puede ser envoltorio de diferentes tipos de unidades de servicio para ejecutarse automáticamente (p. ej., al arrancar el sistema, o regularmente para capturar cambios en ups.conf(5) poco después de ser editado, o integrado con un monitor del sistema de archivos para activarse cuando la configuración se modifica). Algunos de estos modos tienen sentido para casos de uso con una población de dispositivos de energía raramente cambiante (o nunca), p. ej., una UPS doméstica o de oficina pequeña monitorizada de la misma manera durante años; otros pueden ayudar a automatizar un sistema de monitorización de centros de datos donde los despliegues (o descubrimientos) de dispositivos pueden ser mucho más dinámicos.

COMANDOS

nut-driver-enumerator.sh (sin argumentos)

Actualiza el envoltorio de los dispositivos en servicios

nut-driver-enumerator.sh --daemon(=freq)

Actualiza el envoltorio de los dispositivos en servicios en un bucle infinito; freq por defecto es 60 seg.

nut-driver-enumerator.sh --daemon-after(=freq)

Actualiza el envoltorio de los dispositivos en servicios en un bucle infinito; primero realiza una ejecución del bucle, luego se daemoniza (de esta manera la unidad de servicio se considera iniciada solo cuando la configuración de NUT y las instancias de controlador están sincronizadas). freq por defecto es 60 seg.

nut-driver-enumerator.sh --reconfigure

Detiene y anula el registro de todas las instancias de servicio y las recrea (p. ej., si se definió una nueva plantilla de dependencia en una nueva versión del script o paquete)

nut-driver-enumerator.sh --get-service-framework

Imprime el marco de gestión de servicios detectado en este SO

nut-driver-enumerator.sh --list-devices

Imprime la lista de dispositivos en la configuración de NUT

nut-driver-enumerator.sh --list-services

Imprime la lista de instancias de servicio que envuelven dispositivos NUT registrados (nombre completo de la unidad de servicio)

nut-driver-enumerator.sh --list-instances

Imprime la lista de instancias de servicio que envuelven dispositivos NUT registrados (solo el sufijo de instancia)

nut-driver-enumerator.sh --get-service-for-device DEV

Imprime el nombre completo de la unidad de servicio que envuelve un dispositivo NUT llamado DEV

nut-driver-enumerator.sh --get-device-for-service SVC

Imprime el nombre del dispositivo NUT para el nombre completo o el sufijo de instancia de una unidad de servicio SVC que lo envuelve

nut-driver-enumerator.sh --list-services-for-devices

Imprime una lista separada por TAB de unidades de servicio y los nombres de dispositivos NUT correspondientes que cada unidad envuelve

nut-driver-enumerator.sh --show-all-configs

Muestra la lista completa normalizada de bloques de configuración de dispositivos (lo mismo que se utiliza más adelante por el analizador del script para tomar decisiones)

nut-driver-enumerator.sh --show-device-config DEV

Muestra el bloque de configuración del dispositivo NUT especificado

nut-driver-enumerator.sh --show-device-config-value DEV KEY

Muestra una única clave de configuración del dispositivo NUT especificado

VARIABLES DE ENTORNO

Por defecto, nut-driver-enumerator.sh ejecutado sin argumentos iniciaría automáticamente cualquier instancia de servicio recién registrada que envuelva dispositivos NUT, y también reiniciaría el servicio nut-server si la configuración se hubiera modificado. La variable de entorno AUTO_START=no deshabilita esta parte de acción por defecto.

También vea abajo la variable de entorno con valor REPORT_RESTART_42=no.

DIAGNÓSTICO

nut-driver-enumerator.sh devolverá un código de salida cero si no tenía nada que hacer (todos los controladores definidos actualmente coinciden con todas las instancias de servicio definidas actualmente, uno a uno) y si no tuvo errores en su operación.

Las secciones de dispositivos NUT y las instancias de servicio del sistema diferían antes, pero ahora coinciden — así que el llamador debería probablemente reiniciar algunos servicios. Tenga en cuenta que las instancias de servicio de los controladores pueden haber sido iniciadas o detenidas según sea necesario (por AUTO_START=yes) — pero quizás los servicios upsmon o upssched deberían reiniciarse. Si pasa la variable de entorno REPORT_RESTART_42=no, este código de retorno devolverá 0 (como un código de salida sin error). En modo por defecto, tal reconfiguración no nula debería causar que el servicio nut-driver-enumerator se reinicie y esto se propagaría a otros servicios NUT que dependan de él.
