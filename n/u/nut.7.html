NUT(7) Manual de NUT NUT(7)

NOMBRE

nut - Visión general de Network UPS Tools (NUT)

DESCRIPCIÓN

Network UPS Tools (NUT) es un conjunto de herramientas gratuito y de código abierto para monitorizar y gestionar diferentes tipos de dispositivos de distribución de energía, lanzado por primera vez con este nombre en 1999 y derivado de algunos proyectos anteriores. Desde entonces, NUT se ha expandido para cubrir miles de dispositivos de cientos de proveedores y para manejar varios tipos de dispositivos (SAI, ePDU, ATS/STS, solares, IPMI de servidores blade como una especie de PDU para las blades, etc.), todo con una API y un modelo de datos consistentes, que desde entonces ha sido publicado como El "Protocolo de gestión de SAI", RFC 9271 Informativo.

Si bien el proyecto está en desarrollo activo para dar soporte a dispositivos cada vez más nuevos y sus firmwares, así como a lanzamientos de sistemas operativos, uno de los objetivos reconocidos internamente es mantener la compatibilidad con los sistemas en los que NUT podría haber sido desplegado alguna vez: incluso si los proveedores de esas cajas y sistemas operativos ya no existen, el venerable hardware merece seguir protegido con nuevos dispositivos SAI.

Aunque el desarrollo original involucró sistemas operativos compatibles con POSIX, con el tiempo también se implementó el soporte de NUT para Windows (sin embargo, a partir de la versión NUT v2.8.3, aún no está 100% completo), por lo que es posible ejecutar toda la pila de servidor y cliente como programas nativos de Windows.

La mayoría de los sistemas operativos distribuyen NUT como paquetes compilados a partir de una determinada versión, que para el proyecto es solo una instantánea mejor probada del desarrollo en curso. Algunos mantenedores de distribuciones de sistemas operativos seleccionan correcciones de versiones posteriores para actualizar sus paquetes de software mientras permanecen nominalmente en la misma línea base de versión con la que originalmente salió el lanzamiento principal de la distribución. Esto permite equilibrar la entrega de programas estables con cualidades bien conocidas y desventajas mínimas durante un largo período, pero se pierden las nuevas capacidades, características (y sí, nuevos errores) que el desarrollo en curso añade regularmente a la base de código actual del día.

Como tal, el soporte de la comunidad NUT para lanzamientos (o cualquier otro código no actual) generalmente se limita a sugerencias basadas en la experiencia, pero cualquier corrección ocurre en la rama principal de desarrollo (no hay ramas de seguimiento de lanzamientos para portar tales soluciones), y se requerirían compilaciones personalizadas de NUT para aplicarlas en un entorno de usuario final. Este flujo de trabajo está altamente automatizado en la base de código del proyecto (sus recetas y scripts), y las dependencias o kits de herramientas empaquetados necesarios para una compilación se documentan para numerosas plataformas (ver enlaces al final de esta página).

Gracias a esto, el proyecto NUT es también un líder y referencia más amplio de la comunidad de código abierto en el área de recetas de compilación y automatización de pruebas para proyectos generales de Autotools/C/C++ multiplataforma de bajo nivel.

Arquitectura NUT

El proyecto sigue una arquitectura de múltiples niveles que puede parecer un poco compleja, pero permite flexibilidad con configuraciones reales muy diferentes para manejar. En la práctica, esto implica numerosos programas (y sus archivos de configuración) que se ejecutan en los mismos o diferentes sistemas (la parte "network" en el nombre).

Muchos escenarios de implementación se exploran en el famoso libro NUT Configuration Examples mantenido por Roger Price.

Controladores NUT

El nivel más bajo comprende los controladores NUT, que son programas que pueden hablar un protocolo particular a través de ciertos medios. Algunos protocolos siguen un estándar industrial (como USB HID o SNMP), o son dialectos de un estándar de facto (como la familia de protocolos originalmente Megatec "Q*" utilizada por muchos otros proveedores), pero muchos otros son específicos del proveedor. Algunos dispositivos admiten varios tipos de conexión de medios (por ejemplo, puertos serie y/o USB, y/o SNMP para gestión en red), por lo que puede haber varios controladores NUT adecuados para elegir.

Los controladores NUT son responsables de la traducción entre los nombres de puntos de datos o comandos instantáneos estándar de NUT y las cadenas que se deben extraer para ese dispositivo en particular. Los datos se exponen a otros programas en la misma máquina siguiendo el Protocolo de Socket del Controlador/Servidor NUT, que se basa en los controles de acceso del sistema operativo para el archivo de socket local UNIX o una canalización con nombre de Windows.

Para cada dispositivo de distribución de energía monitorizado, se debe ejecutar una instancia del controlador NUT en una máquina que tenga un enlace de comunicación con ese dispositivo.


Nota

Actualmente no hay soporte para "multiplexar" información o comandos para dispositivos con acceso multimedia/controlador múltiple, por ejemplo, para obtener conexión redundante o una mejor recopilación de datos que la que proporciona un solo controlador. Para algunos dispositivos puede ser posible ejecutar varios controladores de forma independiente (probablemente para que su sistema de monitorización seleccione datos de uno u otro controlador), mientras que otros podrían habilitar solo un enlace de forma exclusiva.

Servidor de Datos NUT

Un Servidor de Datos NUT (upsd(8)) representa uno o más controladores NUT que se ejecutan en la misma máquina que él, para proporcionar acceso en red a sus datos o para pasar solicitudes de comandos instantáneos y respuestas.

Por un lado, el servidor de datos se conecta a uno o más archivos de socket locales UNIX o canalizaciones con nombre de Windows (uno para cada controlador en ejecución), y por otro lado, escucha en la red TCP/IP (puerto 3493 por defecto) para comunicarse con programas cliente locales o remotos. También es responsable de la seguridad de la comunicación para el acceso a los controladores, ya sea definiendo los nombres de las cuentas de usuario NUT y los permisos de acceso al protocolo asignados (para establecer valores o comandos; el acceso de lectura es anónimo), o manejando la parte TLS/SSL donde está habilitada.

Clientes NUT

El trabajo práctico visible para los usuarios finales se realiza mediante una multitud de clientes NUT, muchos de los cuales son distribuidos por el propio proyecto y otros son creados y mantenidos por la comunidad en general. Algunos clientes estándar notables incluyen:

•upsmon(8) es un demonio para monitorizar principalmente los estados de los SAI (a diferencia de otros tipos de dispositivos que NUT puede manejar) que alimentan algunas unidades de fuente de alimentación de este sistema en particular, y en función de cuántas PSU se requieren para que el sistema funcione, inicia un apagado local cuando demasiados SAI no están en condiciones saludables. Las instancias de este cliente permiten que un solo SAI que alimenta un rack o escritorio completo de computadoras sea visto por cada una de ellas (a través de un servidor de datos que se ejecuta en una de ellas, en una máquina realmente conectada al SAI, el sistema "primario").

Nota
El cliente upsmon típicamente se divide en dos procesos: uno sin privilegios que se ejecuta con las credenciales del usuario RUN_AS_USER configurado en el archivo upsmon.conf(5) (o una predeterminada/empaquetada como nut, monuser o nobody) que realiza la mayor parte del trabajo (incluidos los scripts de notificación llamados a través de la configuración NOTIFYCMD), y la parte que permanece propiedad de root para iniciar el apagado del sistema llamando a SHUTDOWNCMD cuando/si llega el momento.
Las implementaciones de NUT que desean un control de mayor fidelidad (por ejemplo, diferentes sistemas apagándose después de diferentes tiempos en batería) a menudo acoplan upsmon(8) con upssched(8) como su manejador de NOTIFYCMD.

El sistema "primario" es generalmente también responsable de comandar al SAI gestionado que se apague y encienda cuando la "alimentación de pared" regrese (o para reiniciar la carga si ya ha vuelto), sujeto a las capacidades del hardware del SAI. La mayoría de las integraciones de clientes también detienen el reinicio/apagado definitivo de su máquina, si su apagado fue activado por upsmon, y se reinician después de un largo retraso (si la máquina aún está activa). Este enfoque combinado permite evitar la "condición de carrera de energía", cuando de lo contrario los sistemas permanecerían apagados indefinidamente (hasta que alguien venga y los reinicie) solo porque la energía externa regresó cuando la ráfaga de apagado ya había comenzado.

•upsc(8) es un cliente de línea de comandos para acceso anónimo de solo lectura, utilizado para listar dispositivos servidos por un servidor de datos NUT, o para consultar puntos de datos reportados por un dispositivo en particular.
•NUT-Monitor(8) es un cliente GUI para acceso de solo lectura o de lectura/escritura.
•Un conjunto de clientes CGI puede ejecutarse en un servidor web como Apache o nginx para proporcionar una interfaz HTML simple a sus dispositivos.

Muchos sistemas de monitorización se integran con NUT (y a través de él, con una variedad de dispositivos de energía), utilizando clientes simples como upsc o upslog, o bibliotecas y enlaces proporcionados por el propio proyecto (por ejemplo, C, C++, Python, Java en un repositorio cercano.

•NAME

nut - Network UPS Tools - utilities and system services for managing UPSes and power distribution units

DESCRIPTION

NUT (Network UPS Tools) is a system for monitoring the status of UPS systems (and other similar devices like PDUs, Sun, APC, Eaton, MGE, Liebert, etc.) and their attached load, as well as for controlling UPS systems and initiating actions based on their status. NUT is composed of a common set of libraries, support utilities and a set of daemons (drivers, control daemons and a master server).

This page presents a broad overview of the NUT system and points to the various manual pages describing the functionality of the various components.
