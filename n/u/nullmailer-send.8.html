nullmailer-send(8) Manual del Administrador del Sistema nullmailer-send(8)

NOMBRE

nullmailer-send - Envía mensajes en cola

SINOPSIS

nullmailer-send

DESCRIPCIÓN

Este programa es responsable de coordinar la transmisión de mensajes que han sido puestos en cola por nullmailer-queue. Utiliza una variedad de módulos de protocolo para entregar los mensajes de la cola a servidores "inteligentes" remotos.

Cuando el programa se inicia, se escanea la cola para crear una lista de mensajes a enviar. La cola se vuelve a escanear cuando se activa el disparador, o después de que hayan transcurrido pausetime segundos después de la última entrega fallida. Cuando no hay mensajes en la cola, nullmailer no vuelve a escanear hasta que se active el disparador. Activar el disparador consiste en abrir la tubería con nombre del disparador y escribir un solo byte en ella, lo que hace que este programa se despierte (si no está ya procesando la cola). Este procedimiento lo realiza nullmailer-queue para garantizar que los mensajes se entreguen inmediatamente. Puede iniciar la entrega manualmente desde la línea de comandos de la siguiente manera:

    echo 1 > trigger

La entrega de mensajes consiste en leer la lista de servidores remotos y luego intentar entregar los mensajes a estos servidores de la siguiente manera. Para cada remoto en la lista, el manejador de protocolo nombrado se ejecuta una vez por cada mensaje restante en la cola. Si el manejador de protocolo tiene éxito, el mensaje se elimina de la cola y el procesamiento continúa con el siguiente mensaje. Si el manejador de protocolo informa de un error permanente o si el mensaje ha estado en la cola más tiempo que queuelifetime, el mensaje se mueve a la cola failed y se genera un mensaje de rebote con nullmailer-dsn. Si quedan mensajes en la cola, el procesamiento de los mensajes restantes continúa con el siguiente remoto. Cuando se han intentado todos los remotos, nullmailer-send duerme durante un número de segundos especificado por pausetime antes de reintentar enviar el contenido de la cola.

ARCHIVOS DE CONTROL

Todos los archivos de control se releen cada vez que se ejecuta la cola.

helohost
Establece la variable de entorno $HELOHOST que utiliza el módulo de protocolo SMTP para establecer el parámetro dado al comando HELO. Por defecto, utiliza el valor del archivo de configuración me.
maxpause
El tiempo máximo de pausa entre ejecuciones sucesivas de la cola, en segundos. Por defecto son 24 horas (86400).
pausetime
El tiempo mínimo de pausa entre ejecuciones sucesivas de la cola cuando hay mensajes en la cola, en segundos. Por defecto es 1 minuto (60). Cada vez que se alcanza este tiempo de espera, el tiempo de espera se duplica hasta un máximo de maxpause. Después de que se inyectan nuevos mensajes, el tiempo de espera se restablece. Si esto se establece en 0, nullmailer-send saldrá inmediatamente después de procesar la cola una vez (modo de un solo disparo).
queuelifetime
El tiempo máximo que un mensaje puede permanecer en la cola antes de ser considerado como fallido permanentemente, en segundos. Por defecto son 7 días (604800).
remotes
Este archivo contiene una lista de servidores remotos a los que se enviará cada mensaje. Cada línea de este archivo contiene el nombre o la dirección de un host remoto seguido de una cadena de protocolo opcional, separados por espacios en blanco. El nombre del protocolo por defecto es smtp, y puede ir seguido de opciones adicionales para ese módulo. Consulte la sección "OPCIONES DE PROTOCOLO" para ver una lista de las opciones disponibles. Las opciones pueden ir opcionalmente precedidas por --, pero esto no es obligatorio. La línea se analiza según las reglas de comillas estándar del shell. Por ejemplo, para conectarse al puerto 2525 en su host inteligente SMTP, que también requiere autenticación SMTP, e iniciar TLS con STARTTLS, utilice: 
    smarthost.dom smtp port=2525 starttls user=usuario pass='mi frase secreta'

Las líneas en blanco y las líneas que comienzan con un signo de libras (#) se ignoran.

sendtimeout
El tiempo de espera para que un módulo remoto listado anteriormente complete el envío de un mensaje antes de matarlo y volver a intentarlo, en segundos. Por defecto es 1 hora (3600). Si esto se establece en 0, nullmailer-send esperará indefinidamente a que se completen los envíos de mensajes.

OPCIONES DE PROTOCOLO

port=PUERTO
Establece un número de puerto alternativo al que conectarse en el host remoto. Por ejemplo, SMTP puede usar port=587 para el puerto alternativo de "envío" de SMTP.
user=NOMBREDEUSUARIO
Establece el nombre de usuario de autenticación SMTP.
pass=CONTRASENA
Establece la contraseña de autenticación SMTP.
source=NOMBREHOST
Establece la dirección de origen para las conexiones al host remoto.
auth-login
Forza el modo SMTP "AUTH LOGIN" en lugar de la detección automática.
tls
Conecta usando TLS. Esto cambiará automáticamente el puerto por defecto a 465.
ssl
Alias para la opción tls por compatibilidad.
starttls
Utiliza el comando STARTTLS para iniciar una sesión TLS.
x509certfile=NOMBREARCHIVO
Establece el nombre del archivo para un certificado de cliente TLS a enviar al servidor.
x509keyfile=NOMBREARCHIVO
Establece el nombre del archivo para la clave privada de un certificado de cliente TLS. Por defecto, utiliza el mismo nombre de archivo que x509certfile.
x509cafile=NOMBREARCHIVO
Establece el nombre del archivo de confianza de la autoridad certificadora TLS. Por defecto es /etc/ssl/certs/ca-certificates.crt.
x509crlfile=NOMBREARCHIVO
Establece el nombre del archivo de la lista de revocación de certificados TLS.
x509fmtder
Especifica que los archivos X.509 TLS anteriores están en formato DER en lugar de PEM.
insecure
No abortar una conexión TLS si el certificado del servidor falla la validación. Utilice esto solo si sabe que el servidor utiliza un certificado inválido.
tls-anon-auth
Utiliza la autenticación anónima TLS, reemplazando la autenticación por certificado. Esto significa que no se necesitan certificados externos ni contraseñas para establecer la conexión. Con esta opción, su conexión es vulnerable a ataques de intermediario (activos o de redirección). Sin embargo, los datos están protegidos en cuanto a integridad y cifrados contra espías pasivos. Esta opción debe usarse con la opción insecure para reconocer que sabe lo que está haciendo.

ARCHIVOS

/var/spool/nullmailer/failed
La cola de mensajes fallidos.
/var/spool/nullmailer/queue
La cola de mensajes salientes.
/var/spool/nullmailer/trigger
Un archivo disparador para forzar la entrega inmediata.
/usr/local/etc/nullmailer
El directorio de configuración.
/usr/local/libexec/nullmailer
El directorio de programas de protocolo.
