NOMBRE

nutconf - Herramienta de configuración de NUT

SINOPSIS

nutconf --help

nutconf [OPCIONES]

DESCRIPCIÓN

La herramienta nutconf se utiliza para crear y manipular archivos de configuración de NUT. También admite el escaneo de dispositivos (para sugerir la configuración de los dispositivos).

INSTALACIÓN

La función de escaneo depende de las mismas dependencias de tiempo de compilación y tiempo de ejecución que nut-scanner.

OPCIONES

-h | -help | --help

Muestra el texto de ayuda.

-v | --verbose

Aumenta la verbosidad de la salida (se puede usar varias veces).

--is-configured

Comprueba si NUT se configuró previamente.

--system

Se utilizará el directorio de configuración del sistema.

--local directorio

Establece un directorio de configuración alternativo.

--get-mode

Imprime el modo de configuración actual de NUT

--set-mode modo

Establece el modo de configuración de NUT.

Los modos conocidos son:

•standalone
•netserver
•netclient
•controlled
•manual
•none

OPCIONES DE CONFIGURACIÓN DE ENTRADAS SET/ADD

Estas opciones tienen principalmente 2 formas: --set-... o --add-....

La diferencia es que las opciones 'set' descartan la configuración anterior, mientras que las opciones 'add' la conservan.

Tenga en cuenta que estas opciones se pueden especificar varias veces en una sola ejecución (para permitir la configuración de varias entradas a la vez).

--set-monitor | --add-monitor <argumentos>

Establece/añade un monitor NUT.
•Argumentos: 
'<ups_ID>' '<host>[:<puerto>]' '<valor_potencia>' '<usuario>' '<contraseña>' '("master"|"slave")'

--set-listen | --add-listen <dirección> [<puerto>]

Establece/añade la dirección de escucha del demonio upsd(8).

--set-device | --add-device <argumentos>

Establece/añade un dispositivo (típicamente una UPS).
•Argumentos: 
'<ups_ID>' '<driver>' '<puerto>' '[atributo=<valor>]*'

Los pares atributo/valor siguen la sintaxis de configuración del dispositivo. Los dispositivos pueden tener atributos de configuración muy diferentes según el controlador. Una descripción exhaustiva de ellos está más allá de esta página de manual y se puede encontrar en la documentación de NUT.

--set-notifyflags | --add-notifyflags <tipo> <bandera>+

Establece/añade banderas de notificación para el tipo de notificación.
•Los tipos de notificación son:
•ONLINE (la red está presente)
•ONBATT (la red se ha ido)
•LOWBATT (la capacidad restante de la batería es baja)
•FSD (el apagado fue forzado)
•COMMOK (la comunicación con el dispositivo se ha establecido)
•COMMBAD (se perdió la comunicación con el dispositivo)
•SHUTDOWN (el sistema se está apagando, ahora)
•REPLBATT (la batería de la UPS necesita ser reemplazada)
•NOCOMM (el dispositivo no está disponible)
•NOPARENT (el proceso padre de upsmon murió, el apagado es imposible)
•CAL (la calibración está en curso)
•NOTCAL (la calibración ha terminado)
•OFF (la UPS está administrativamente apagada o en reposo, debería activarse con un comando)
•NOTOFF (la UPS ya no está administrativamente apagada o en reposo)
•BYPASS (en derivación = alimentado, no protegido)
•NOTBYPASS (ya no está en derivación)
•ALARM (la UPS está en estado de alarma (tiene alarmas activas))
•NOTALARM (la UPS ya no está en estado de alarma (sin alarmas activas))
•OVER (sobrecargado)
•NOTOVER (ya no está sobrecargado)
•TRIM (regula el voltaje de entrada)
•NOTTRIM (ya no regula el voltaje de entrada)
•BOOST (aumenta el voltaje de entrada)
•NOTBOOST (ya no aumenta el voltaje de entrada)
•OTHER (la UPS tiene al menos un token de estado no clasificado)
•NOTOTHER (la UPS ya no tiene tokens de estado no clasificados)
•SUSPEND_STARTING (el SO está entrando en modo de suspensión/hibernación)
•SUSPEND_FINISHED (el SO acaba de finalizar el modo de suspensión/hibernación)
•Banderas de notificación:
•SYSLOG (usar syslogd para registrar la notificación)
•WALL (enviar un mensaje a las terminales de los usuarios)
•EXEC (ejecutar un comando)
•IGNORE (no hacer nada)

--set-notifymsg <tipo> <mensaje>

Establece el mensaje para el tipo de notificación especificado.

--set-shutdowncmd <comando>

Establece el comando utilizado para apagar el sistema.

--set-user | --add-user <argumentos>

Establece/añade un usuario NUT.
•Argumentos:
•<nombre_usuario> (especifica el nombre de usuario). Para el usuario upsmon, tiene una forma especial de upsmon=(primary|master|secondary|slave) que especifica el modo de supervisión.
•password=<contraseña> establece la contraseña del usuario
•actions=<acciones> establece las acciones (se admiten SET, FSD)
•instcmds=<comando> establece los comandos instantáneos permitidos para el usuario (se pueden usar varias veces)

OPCIONES DE ESCÁNER

La disponibilidad de cada opción de escaneo depende de la disponibilidad de varias bibliotecas de terceros tanto en tiempo de compilación como en tiempo de ejecución.

Ejecute la herramienta con la opción --help para verificar qué opciones de --scan-... están realmente admitidas.

Todos los tiempos de espera están en microsegundos.

--scan-snmp <IP inicial> <IP final> [atributo=<valor>]*

Busca dispositivos SNMP en direcciones IP de un rango especificado.
•Los atributos conocidos son:
•timeout tiempo de espera del escaneo del dispositivo
•community comunidad SNMP (por defecto: public)
•sec-level nivel de seguridad (SNMPv3); uno de noAuthNoPriv authNoPriv, authPriv
•sec-name nombre de seguridad (SNMPv3); compañero obligatorio de sec-level
•auth-password contraseña de autenticación (SNMPv3); obligatoria para authNoPriv y authPriv
•priv-password contraseña de privacidad (SNMPv3); obligatoria para authPriv
•auth-protocol protocolo de autenticación (SNMPv3): MD5 o SHA, MD5 es el valor por defecto
•priv-protocol protocolo de privacidad (SNMPv3): DES o AES, DES es el valor por defecto
•peer-name nombre del par

OPTIONS

Options for the nutconf utility:

--help
Show help message and exit.
--version
Show version and exit.
--conf-file <file>
Use the specified configuration file.
--local <dir>
Use the specified directory for configuration files.
--debug <level>
Set debug level.
--verbose
Set verbose mode.
--quiet
Set quiet mode.

CONFIGURATION ENTRY SET/ADD OPTIONS

These options are used to modify the configuration files.

--set-config <entry>=<value>
Set a configuration entry.
--add-config <entry>=<value>
Add a configuration entry.
--remove-config <entry>
Remove a configuration entry.
--add-user <username> password=<password>
Add a new user with the given password.
--remove-user <username>
Remove an existing user.
--set-user-password <username> password=<password>
Change the password for an existing user.

SCANNING OPTIONS

These options are used to scan for devices.

--scan-usb [<timeout>]

Scans the USB bus for known devices

--scan-xml-http [<timeout>]

Scans for XML/HTTP devices on the network.

--scan-nut <start IP> <stop IP> <port> [<timeout>]

Scans for NUT (pseudo-)devices on the network.

--scan-avahi [<timeout>]

Scans for Avahi devices.

--scan-ipmi <start IP> <stop IP> [<attribute>=<value>]*

Scans for IPMI devices on IP addresses from the specified range.
•Known attributes are:
•username username (mandatory for IPMI/LAN)
•password user password (mandatory for IPMI/LAN)
•auth-type authentication type (see below)
•cipher-suite-id cipher suite ID (see below)
•K-g-BMC-key optional second key (???)
•priv-level priv. level
•workaround-flags
•version (1.5 or 2.0)
•Authentication types:

Specifies the IPMI 1.5 authentication type to use (NONE, STRAIGHT_PASSWORD_KEY, MD2, and MD5) with the remote host (default=MD5). This forces connection through the lan IPMI interface, thus in IPMI 1.5 mode.

•none (authentication is disabled)
•MD2
•MD5 (default)
•plain-password (no ciphering used for password sending)
•OEM
•RMCPplus
•Cipher suite IDs:

Specifies the IPMI 2.0 cipher suite ID to use.

The Cipher Suite ID identifies a set of authentication, integrity, and confidentiality algorithms to use for IPMI 2.0 communication.

The authentication algorithm identifies the algorithm to use for session setup, the integrity algorithm identifies the algorithm to use for session packet signatures, and the confidentiality algorithm identifies the algorithm to use for payload encryption (default=3).

The following cipher suite IDs are currently supported:

Code Authentication Integrity Confidentiality
0 None None None
1 HMAC-SHA1 None None
2 HMAC-SHA1 HMAC-SHA1-96 None
3 HMAC-SHA1 HMAC-SHA1-96 AES-CBC-128
6 HMAC-MD5 None None
7 HMAC-MD5 HMAC-MD5-128 None
8 HMAC-MD5 HMAC-MD5-128 AES-CBC-128
11 HMAC-MD5 MD5-128 None
12 HMAC-MD5 MD5-128 AES-CBC-128
15 HMAC-SHA256 None None
16 HMAC-SHA256 HMAC_SHA256_128 None
17 HMAC-SHA256 HMAC_SHA256_128 AES-CBC-128

--scan-serial <port>*

Scans for serial devices (of supported types) on the specified serial port(s).

EXAMPLES

To set alternative directory for configuration files:

:; nutconf --local ~/test/nut/etc

To add another user (keeping the existing ones):

:; nutconf --add-user bart password=qwerty

To scan USB devices and serial devices (on the first two ports):

:; nutconf --scan-usb --scan-serial /dev/ttyS1 /dev/ttyS2
