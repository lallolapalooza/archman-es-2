NUT.CONF(5) Manual de NUT NUT.CONF(5)

NOMBRE

nut.conf - Definiciones de UPS para Network UPS Tools

DESCRIPCIÓN

Este archivo intenta estandarizar los diversos archivos que se encuentran en diferentes instalaciones, como /etc/default/nut en sistemas basados en Debian y /etc/sysconfig/ups en sistemas basados en RedHat.

El script init de la distribución debe obtener este archivo para determinar qué componentes deben iniciarse.

Las líneas en blanco se ignoran. Las líneas con un carácter hash (#) en la primera posición de la línea también se ignoran. Se pueden utilizar para agregar comentarios.

NOTAS IMPORTANTES

•Este archivo está destinado a ser obtenido por scripts de shell, así como por marcos de gestión de servicios como systemd en Linux:
•No hay una sintaxis garantizada de exportación VAR=VAL
•No hay una expansión garantizada de variables como VAR1="$VAR2-algo" — solo asignaciones literales
•Es posible que necesite exportar VAR al obtenerlo en scripts init u otros scripts, para la propagación eventual de ciertas configuraciones a los programas NUT. Las variables no exportadas solo pueden ser consumidas por el script que "obtuvo" el archivo (y puede optar por exportarlas independientemente).
•¡NO DEBE usar espacios alrededor del signo igual!
•El soporte práctico para este archivo y su configuración varía actualmente entre diferentes paquetes de SO y scripts de ejemplo de NUT, pero debería converger con el tiempo.
•El contenido de este archivo debe ser ASCII puro (los códigos de caracteres que no estén en el rango se ignorarán con un mensaje de advertencia).

Consulte la sección EJEMPLO para ver ilustraciones.

DIRECTIVAS

MODO

Requerido. Los valores reconocidos son none, standalone, netserver y netclient. Predeterminado a none.

none

Indica que NUT no debe iniciarse automáticamente, posiblemente porque no está configurado o porque un Sistema de Gestión de Energía o algún sistema externo, se utiliza para iniciar los componentes de NUT.

standalone

Aborda una configuración local únicamente, con 1 UPS protegiendo el sistema local. Esto implica iniciar las 3 capas de NUT (driver, upsd y upsmon), con los archivos de configuración relacionados. Este modo también puede abordar la redundancia de UPS.

netserver

Al igual que la configuración standalone, pero también puede necesitar una o más directivas LISTEN específicas en upsd.conf. Dado que este MODO está abierto a la red, se debe tener especial cuidado con las preocupaciones de seguridad.

netclient

Cuando solo se requiere upsmon, posiblemente porque hay otros hosts más conectados a la UPS, el MODO debe configurarse como netclient.

ALLOW_NO_DEVICE

Opcional, predeterminado a falso. Establezca esto en verdadero para permitir el inicio del servicio del servidor de datos NUT upsd incluso si ups.conf no tiene secciones de dispositivo configuradas en este momento. Esta variable de entorno anula el valor del indicador incorporado "false" en el programa upsd, y un indicador predeterminado opcional con el mismo nombre que se puede establecer en upsd.conf.

Si desea un servidor de datos siempre en funcionamiento y que responda en la red, incluso si inicialmente no tiene nada que servir (puede ser recargado en vivo más tarde, cuando se configuren los dispositivos), esta opción es para usted.

ALLOW_NOT_ALL_LISTENERS

Opcional, predeterminado a falso. Establezca esto en verdadero para permitir el inicio del servidor de datos NUT upsd incluso si no todos los directivas LISTEN se pueden cumplir en este momento. Esta variable de entorno anula el indicador incorporado "false" en el programa upsd, y un indicador predeterminado opcional con el mismo nombre que se puede establecer en upsd.conf.

Si desea un servidor de datos siempre en funcionamiento, incluso si potencialmente no sirve a todos los clientes en cada tiempo de actividad, esta opción es para usted (tenga en cuenta que tendría que reiniciar upsd para captar la dirección IP `LISTEN`ed si aparece más tarde).

Probablemente, configurar LISTEN * es una mejor opción en tales casos.

UPSD_OPTIONS

Opcional. Establezca opciones específicas de upsd. Consulte upsd(8) para más detalles. Se ignora cuando MODO anteriormente indica que no se debe ejecutar ningún upsd.

UPSMON_OPTIONS

Opcional. Establezca opciones específicas de upsmon. Consulte upsmon(8) para más detalles. Se ignora cuando MODO anteriormente indica que no se debe ejecutar ningún upsmon.

POWEROFF_WAIT

Opcional. Al final de un apagado de emergencia del sistema, el primario de upsmon señalará a la UPS para que se apague. Esto puede fallar por varias razones. Lo más notable es el caso en que la red eléctrica vuelve durante el proceso de apagado. Consulte la sección "Carreras de potencia" en /usr/share/doc/nut/FAQ.txt.gz. El sistema esperará este tiempo para que la UPS corte la energía, y luego se reiniciará. Debería ser suficiente para agotar las baterías, en caso de que la energía de la línea continúe no estando disponible. Por otro lado, no debería ser tan largo que el sistema permanezca fuera de línea durante un tiempo irrazonable si la energía de la línea ha regresado. Consulte sleep(1) para sintaxis de tiempo compatible. Si especifica el tiempo en segundos, use el sufijo "s".

Advertencia
Esta solución alternativa puede ser peligrosa en algunas circunstancias. Por favor, lea http://bugs.debian.org/358696 para más detalles.

POWEROFF_QUIET

Opcional, predeterminado a falso. Esta configuración controla si los scripts de integración de apagado de NUT o las unidades de servicio emitirán mensajes sobre su actividad (o la falta de ella). Por defecto, pueden ser detallados, para ayudar en la resolución de problemas post-mortem a través de registros o capturas de consola. Establezca en verdadero para evitar esa gran cantidad de información, si la considera ruido.

NUT_DEBUG_LEVEL

Opcional, predeterminado a 0. Esta configuración controla la verbosidad del mensaje de depuración predeterminado que se pasa a los demonios NUT. Como variable de entorno, su prioridad se encuentra entre la configuración de DEBUG_MIN de un controlador y las opciones de línea de comandos.

NUT_DEBUG_PID

Opcionalmente, agregue el ID del proceso actual a las etiquetas con identificadores de nivel de depuración. Esto puede ser útil cuando muchos demonios NUT escriben en la misma consola o archivo de registro, como en contenedores/plugins para Home Assistant, electrodomésticos de almacenamiento...

NUT_DEBUG_SYSLOG

Opcional, no establecido por defecto. Normalmente NUT puede (intentar) usar el registro del sistema o el Registro de Eventos (WIN32), pero la variable de entorno NUT_DEBUG_SYSLOG permite omitirlo, y quizás mantener los demonios registrando en stderr (útil por ejemplo en el conjunto de pruebas de integración de NUT para no contaminar los registros del SO, o en systemd donde stderr y syslog van al mismo journal). Valores reconocidos:
Valor Descripción
stderr Deshabilitado y `background()` mantiene `stderr` adjunto
none Deshabilitado y `background()` desvincula `stderr` como de costumbre
default No deshabilitado
unset/other No deshabilitado

NUT_IGNORE_CHECKPROCNAME

Opcional, predeterminado a falso. Normalmente NUT puede (intentar) verificar que el nombre del archivo del programa coincida con el nombre asociado con un proceso en ejecución, cuando se utilizan archivos PID para enviar señales.

El modificador booleano NUT_IGNORE_CHECKPROCNAME permite omitir rápidamente dicha verificación, en caso de que cause problemas (por ejemplo, si los programas NUT fueron renombrados y no coinciden con las expectativas incorporadas).

Esta variable de entorno también se puede establecer opcionalmente en scripts init o métodos de servicio para upsd, upsmon y los controladores/upsdrvctl de NUT.

NUT_QUIET_INIT_UPSNOTIFY

NAME

nut.conf — configuration file for Network UPS Tools

DESCRIPTION

The NUT configuration file, nut.conf, is used to define the basic operating mode for the Network UPS Tools suite.

This file controls the high-level operation of the NUT daemons, specifically upsd (the control daemon) and upsmon (the monitoring daemon).

IMPORTANT NOTES

The primary use of this file is to configure the primary operation mode of the NUT daemons.

The configuration directives in this file are intended to be simple and global for the entire NUT installation.

The default settings aim to enable all components of NUT to function as expected in a typical environment.

It is recommended to consult the man pages for specific components like upsd and upsmon for more detailed configuration options.

DIRECTIVES

The following directives can be set in nut.conf:

MODE
Specifies the overall operating mode for NUT. Possible values include:
standalone
Run all NUT components (server and monitor) on the same machine.
master
Run the NUT server (upsd) on this machine. Other machines will act as clients or monitors.
slave
Run the NUT monitor (upsmon) on this machine, connecting to a master server.
none
Do not start any NUT components automatically.
UPSD_OPTIONS
Additional command-line options to pass to the upsd daemon when it is started.
UPSMON_OPTIONS
Additional command-line options to pass to the upsmon daemon when it is started.
POWEROFF_WAIT
Specifies the time to wait after initiating a shutdown of the UPS before shutting down the system. This is typically used in conjunction with upsmon to ensure that the UPS has powered down completely before the system initiates its own shutdown sequence.

If MODE is not set, or set to none, no components will be started by default.

The flags UPSD_OPTIONS and UPSMON_OPTIONS can be used to enable debugging or other runtime behaviors. For example, setting UPSD_OPTIONS="-D -1" would enable full debugging for upsd.

The POWEROFF_WAIT directive is particularly important for systems that need to gracefully shut down upon UPS battery depletion. It should be set to a duration that allows the UPS to signal the system and then power off without causing data corruption.

It is important to note that some systems may not have robust service management frameworks, or may be configured in a way that prevents NUT from reporting its status accurately. In such cases, it might be desirable to disable automatic reporting to avoid false positives that could lead to unnecessary system restarts.

Currently, such reports, which are enabled by default, help troubleshoot service startup issues and highlight instances where NUT sources (or package builds) have not taken full advantage of tighter OS service management framework integration (if one exists). This allows developers to focus on adding such integration.

Reasons to set this flag could include platforms without such a framework and not expecting one, although encouraging your favorite OS vendor or contributing development to improve it is also a valid approach.

EXAMPLE

   # /etc/nut/nut.conf.  See nut.conf(5)
   MODE=none
   UPSD_OPTIONS=""
   UPSMON_OPTIONS=""
   # POWEROFF_WAIT=15m

INTEGRATION

An init script, such as /etc/init.d/nut, is expected to source this file in order to determine which components have to be started.
