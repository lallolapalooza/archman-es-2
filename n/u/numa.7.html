numa(7) Información Miscelánea Manual numa(7)

NOMBRE

numa - resumen de la Arquitectura de Memoria No Uniforme

DESCRIPCIÓN

La Arquitectura de Memoria No Uniforme (NUMA, por sus siglas en inglés Non-Uniform Memory Access) se refiere a sistemas multiprocesador cuya memoria está dividida en múltiples nodos de memoria. El tiempo de acceso a un nodo de memoria depende de las ubicaciones relativas de la CPU que accede y del nodo accedido. (Esto contrasta con un sistema multiprocesador simétrico, donde el tiempo de acceso a toda la memoria es el mismo para todas las CPUs.) Normalmente, cada CPU en un sistema NUMA tiene un nodo de memoria local cuyos contenidos pueden ser accedidos más rápido que la memoria en el nodo local de otra CPU o la memoria en un bus compartido por todas las CPUs.

Llamadas al sistema NUMA

El kernel de Linux implementa las siguientes llamadas al sistema relacionadas con NUMA: get_mempolicy(2), mbind(2), migrate_pages(2), move_pages(2) y set_mempolicy(2). Sin embargo, las aplicaciones normalmente deberían usar la interfaz proporcionada por libnuma; véase "Soporte de biblioteca" más abajo.

/proc/pid/numa_maps (desde Linux 2.6.14)

Este archivo muestra información sobre la política de memoria y la asignación NUMA de un proceso.

Cada línea contiene información sobre un rango de memoria utilizado por el proceso, mostrando —entre otra información— la política de memoria efectiva para ese rango de memoria y en qué nodos se han asignado las páginas.

numa_maps es un archivo de solo lectura. Cuando se lee /proc/pid/numa_maps, el kernel examinará el espacio de direcciones virtual del proceso e informará cómo se utiliza la memoria. Se muestra una línea por cada rango de memoria único del proceso.

El primer campo de cada línea muestra la dirección de inicio del rango de memoria. Este campo permite una correlación con el contenido del archivo /proc/pid/maps, que contiene la dirección final del rango y otra información, como los permisos de acceso y el uso compartido.

El segundo campo muestra la política de memoria actualmente en vigencia para el rango de memoria. Tenga en cuenta que la política efectiva no es necesariamente la política instalada por el proceso para ese rango de memoria. Específicamente, si el proceso instaló una política "predeterminada" para ese rango, la política efectiva para ese rango será la política del proceso, que puede o no ser "predeterminada".

El resto de la línea contiene información sobre las páginas asignadas en el rango de memoria, de la siguiente manera:

N<nodo>=<nr_páginas>
El número de páginas asignadas en <nodo>. <nr_páginas> solo incluye las páginas mapeadas actualmente por el proceso. La migración de páginas y la recuperación de memoria pueden haber desmapeado temporalmente páginas asociadas con este rango de memoria. Estas páginas pueden volver a aparecer solo después de que el proceso intente referenciarlas. Si el rango de memoria representa un área de memoria compartida o un mapeo de archivo, otros procesos pueden tener páginas adicionales mapeadas en un rango de memoria correspondiente.
archivo=<nombre_archivo>
El archivo que respalda el rango de memoria. Si el archivo se mapea como privado, los accesos de escritura pueden haber generado páginas COW (Copy-On-Write) en este rango de memoria. Estas páginas se muestran como páginas anónimas.
heap
El rango de memoria se utiliza para el heap.
stack
El rango de memoria se utiliza para la pila.
huge
Rango de memoria grande (huge). Los recuentos de páginas mostrados son de páginas grandes y no de páginas de tamaño regular.
anon=<páginas>
El número de páginas anónimas en el rango.
dirty=<páginas>
Número de páginas sucias (dirty).
mapped=<páginas>
Número total de páginas mapeadas, si es diferente de las páginas dirty y anon.
mapmax=<contador>
Mapcount máximo (número de procesos que mapean una sola página) encontrado durante el escaneo. Esto puede usarse como un indicador del grado de uso compartido que ocurre en un rango de memoria dado.
swapcache=<contador>
Número de páginas que tienen una entrada asociada en un dispositivo de intercambio (swap).
active=<páginas>
El número de páginas en la lista activa. Este campo solo se muestra si es diferente del número de páginas en este rango. Esto significa que existen algunas páginas inactivas en el rango de memoria que el paginador podría eliminar pronto de la memoria.
writeback=<páginas>
Número de páginas que se están escribiendo actualmente en el disco.

ESTÁNDARES

Ninguno.

NOTAS

Las llamadas al sistema y la interfaz /proc de NUMA de Linux solo están disponibles si el kernel fue configurado y compilado con la opción CONFIG_NUMA.

Soporte de biblioteca

Enlaza con -lnuma para obtener las definiciones de las llamadas al sistema. libnuma y la cabecera requerida <numaif.h> están disponibles en el paquete numactl.

Sin embargo, las aplicaciones no deberían usar estas llamadas al sistema directamente. En su lugar, se recomienda la interfaz de nivel superior proporcionada por las funciones de numa(3) en el paquete numactl. El paquete numactl está disponible en ftp://oss.sgi.com/www/projects/libnuma/download/. El paquete también se incluye en algunas distribuciones de Linux. Algunas distribuciones incluyen la biblioteca de desarrollo y la cabecera en el paquete separado numactl-devel.
