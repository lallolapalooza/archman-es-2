DESCRIPCIÓN

La librería libnuma ofrece una interfaz de programación sencilla para la política NUMA (Non Uniform Memory Access - Acceso No Uniforme a Memoria) soportada por el kernel de Linux. En una arquitectura NUMA, algunas áreas de memoria tienen latencia o ancho de banda diferentes a otras.

Las políticas disponibles son intercalado de páginas (es decir, asignar en modo round-robin desde todos, o un subconjunto, de los nodos del sistema), asignación de nodo preferido (es decir, preferentemente asignar en un nodo particular), asignación local (es decir, asignar en el nodo en el que la tarea se está ejecutando actualmente), o asignación solo en nodos específicos (es decir, asignar en algún subconjunto de los nodos disponibles). También es posible vincular tareas a nodos específicos.

La política de asignación de memoria NUMA puede especificarse como un atributo por tarea, que es heredado por las tareas e hilos hijos, o como un atributo de un rango de espacio de direcciones virtuales del proceso. Las políticas de memoria NUMA especificadas para un rango de espacio de direcciones virtuales son compartidas por todas las tareas del proceso. Además, las políticas de memoria especificadas para un rango de memoria compartida asociada mediante shmat(2) o mmap(2) desde shmfs/hugetlbfs son compartidas por todos los procesos que se asocian a esa región. Las políticas de memoria para mapeos de archivos respaldados por disco compartidos actualmente se ignoran.

La política de asignación de memoria por defecto para las tareas y toda la gama de memoria es la asignación local. Esto asume que ningún ancestro ha instalado una política no predeterminada.

Para establecer una política específica globalmente para todas las asignaciones de memoria en un proceso y sus hijos, es más fácil iniciarlo con la utilidad numactl(8). Para políticas más detalladas dentro de una aplicación, se puede usar esta librería.

Todas las políticas de asignación de memoria NUMA solo surten efecto cuando una página se carga realmente en el espacio de direcciones de un proceso al acceder a ella. Las funciones numa_alloc_* se encargan de esto automáticamente.

Un nodo se define como un área donde toda la memoria tiene la misma velocidad vista desde una CPU particular. Un nodo puede contener múltiples CPUs. Las cachés se ignoran para esta definición.

La mayoría de las funciones de esta librería solo se ocupan de los nodos NUMA y su memoria. Las excepciones a esto son: numa_node_to_cpus(), numa_no

Estas funciones se ocupan de las CPU asociadas con los nodos NUMA. Consulte las descripciones a continuación para obtener más información.

Algunas de estas funciones aceptan o devuelven un puntero a struct bitmask. Un struct bitmask controla un mapa de bits de longitud arbitraria que contiene una representación de bits de los nodos. La variable predefinida numa_all_nodes_ptr apunta a un mapa de bits que tiene todos los nodos disponibles establecidos; numa_no_nodes_ptr apunta al conjunto vacío.

Antes de que se puedan usar otras llamadas en esta biblioteca, se debe llamar a numa_available(). Si devuelve -1, todas las demás funciones de esta biblioteca no están definidas.

numa_max_possible_node() devuelve el número del nodo posible más alto en un sistema. En otras palabras, el tamaño de un tipo de nodo del kernel nodemask_t (en bits) menos 1. Este número se puede obtener llamando a numa_num_possible_nodes() y restando 1.

numa_num_possible_nodes() devuelve el tamaño del mapa de nodos del kernel (tipo de nodo nodemask_t). En otras palabras, lo suficientemente grande como para representar el número máximo de nodos que el kernel puede manejar. Esto coincidirá con el valor MAX_NUMNODES del kernel. Este recuento se deriva de /proc/self/status, campo Mems_allowed.

numa_max_node() devuelve el número de nodo más alto disponible en el sistema actual. (Ver los números de nodo en /sys/devices/system/node/). Consulte también numa_num_configured_nodes().

numa_num_configured_nodes() devuelve el número de nodos de memoria en el sistema. Este recuento incluye cualquier nodo que esté actualmente deshabilitado. Este recuento se deriva de los números de nodo en /sys/devices/system/node. (Depende de que el kernel esté configurado con /sys (CONFIG_SYSFS)).

numa_get_mems_allowed() devuelve la máscara de nodos de los cuales al proceso se le permite asignar memoria en su contexto cpuset actual. Cualquier nodo que no se incluya en el mapa de bits devuelto será ignorado en cualquiera de las siguientes llamadas de política de memoria de libnuma.

numa_num_configured_cpus() devuelve el número de CPU en el sistema. Este recuento incluye cualquier CPU que esté actualmente deshabilitada. Este recuento se deriva de los números de CPU en /sys/devices/system/cpu. Si el kernel está configurado sin /sys (CONFIG_SYSFS=n), recurre al número de CPU en línea.

numa_all_nodes_ptr apunta a un mapa de bits asignado por la biblioteca con bits que representan todos los nodos en los que la tarea llamante puede asignar memoria. Este conjunto puede ser hasta todos los nodos del sistema, o hasta los nodos en el cpuset actual. El mapa de bits se asigna mediante una llamada a numa_allocate_nodemask() usando el tamaño numa_max_possible_node(). El conjunto de nodos a registrar se deriva de /proc/self/status, campo "Mems_allowed". El usuario no debe alterar este mapa de bits.

numa_no_nodes_ptr apunta a un mapa de bits asignado por la biblioteca y dejado con todos los ceros. El mapa de bits se asigna mediante una llamada a numa_allocate_nodemask() usando el tamaño numa_max_possible_node(). El usuario no debe alterar este mapa de bits.

numa_all_cpus_ptr apunta a un mapa de bits asignado por la biblioteca con bits que representan todas las CPU en las que la tarea llamante puede ejecutarse. Este conjunto puede ser hasta todas las CPU del sistema, o hasta las CPU en el cpuset actual. El mapa de bits se asigna mediante una llamada a numa_allocate_cpumask() usando el tamaño numa_num_possible_cpus(). El conjunto de CPU a registrar se deriva de /proc/self/status, campo "Cpus_allowed". El usuario no debe alterar este mapa de bits.

numa_num_task_cpus() devuelve el número de CPU que la tarea llamante puede usar. Este recuento se deriva del mapa /proc/self/status, campo "Cpus_allowed". Consulte también el mapa de bits numa_all_cpus_ptr.

numa_num_task_nodes() devuelve el número de nodos en los cuales la tarea llamante puede asignar memoria. Este recuento se deriva del mapa /proc/self/status, campo "Mems_allowed". Consulte también el mapa de bits numa_all_nodes_ptr.

numa_parse_bitmap() analiza line, que es una cadena de caracteres como la que se encuentra en /sys/devices/system/node/nodeN/cpumap en una estructura de mapa de bits. La cadena contiene la representación hexadecimal de un mapa de bits. El mapa de bits puede asignarse con numa_allocate_cpumask(). Devuelve 0 si tiene éxito. Devuelve -1 si falla. Esta función probablemente sea de poca utilidad para una aplicación de usuario, pero es utilizada internamente por libnuma.

numa_parse_nodestring() analiza una lista de cadenas de caracteres de nodos en un mapa de bits. El mapa de bits se asigna mediante numa_allocate_nodemask(). La cadena es una lista separada por comas de números de nodo o rangos de nodos. Se puede usar un "!" inicial para indicar "no" esta lista (en otras palabras, todos los nodos excepto esta lista), y se puede usar un "+" inicial para indicar que los números de nodo en la lista son relativos al cpuset de la tarea. La cadena puede ser "all" para especificar todos (numa_num_task_nodes()) los nodos. Los números de nodo están limitados por el número en el sistema. Consulte numa_max_node() y numa_num_configured_nodes().
Ejemplos: 1-5,7,10 !4-5 +0-3
Si la cadena tiene longitud 0, se devuelve el mapa de bits numa_no_nodes_ptr. Devuelve 0 si la cadena no es válida.

numa_parse_nodestring_all() es similar a numa_parse_nodestring, pero puede analizar todos los nodos posibles, no solo el conjunto de nodos actual.

numa_parse_cpustring() analiza una lista de cadenas de caracteres de CPU en un mapa de bits. El mapa de bits se asigna mediante numa_allocate_cpumask(). La cadena es una lista separada por comas de números de CPU o rangos de CPU. Se puede usar un "!" inicial para indicar "no" esta lista (en otras palabras, todas las CPU excepto esta lista), y se puede usar un "+" inicial para indicar que los números de CPU en la lista son relativos al cpuset de la tarea. La cadena puede ser "all" para especificar todas (numa_num_task_cpus()) las CPU. Los números de CPU están limitados por el número en el sistema. Consulte numa_num_task_cpus() y numa_num_configured_cpus().
Ejemplos: 1-5,7,10 !4-5 +0-3
Devuelve 0 si la cadena no es válida.

numa_parse_cpustring_all() es similar a numa_parse_cpustring, pero puede analizar todas las CPU posibles, no solo el cpuset actual.

numa_node_size() devuelve el tamaño de memoria de un nodo. Si el argumento freep no es NULL, se usaba para devolver la cantidad de memoria libre en el nodo. En caso de error, devuelve -1.

numa_node_size64() funciona igual que numa_node_size(). Esto es útil en arquitecturas de 32 bits con nodos grandes.

numa_preferred() devuelve el nodo preferido de la tarea actual. Este es el nodo del cual el kernel prefiere asignar memoria, a menos que alguna otra política lo anule.

numa_has_preferred_many() Devuelve > 0 si el sistema admite varios nodos preferidos.

numa_preferred_many() Devuelve el conjunto actual de nodos preferidos. Esto implica el conjunto vacío cuando la política no es una usada para preferencia (PREFERRED, PREFERRED_MANY, BIND). El llamador es responsable de liberar la máscara con numa_bitmask_free().

numa_set_preferred() establece el nodo preferido para la tarea actual a node. El sistema intentará asignar memoria desde el nodo preferido, pero recurrirá a otros nodos si no hay memoria disponible en el nodo preferido. Pasar un argumento node de -1 especifica la asignación local y es equivalente a llamar a numa_set_localalloc().

numa_set_preferred_many() establece el conjunto preferido de nodos para la tarea actual a nodemask. Esto es similar a numa_set_preferred() con la excepción de que utiliza una interfaz de kernel diferente para especificar varios nodos preferidos. El llamador es responsable de liberar la máscara con numa_bitmask_free().

numa_has_home_node() Devuelve 1 si el sistema admite establecer home_node para mbind y preferred_many.

numa_set_mempolicy_home_node() establece el nodo de inicio para una política de VMA presente en el rango de direcciones de la tarea. Un nodo de inicio es el nodo NUMA más cercano al cual provendrán las asignaciones de página. Los usuarios deben usarlo después de configurar una política de memoria mbind o preferred_many para el rango especificado.

numa_get_interleave_mask() devuelve la máscara de entrelazado actual si la política de asignación de memoria de la tarea está entrelazada por páginas. De lo contrario, esta función devuelve una máscara vacía.

numa_set_interleave_mask() establece la máscara de entrelazado de memoria para la tarea actual a nodemask. Todas las nuevas asignaciones de memoria se entrelazarán por páginas en todos los nodos de la máscara de entrelazado. El entrelazado se puede desactivar de nuevo pasando una máscara vacía (numa_no_nodes). El entrelazado de páginas solo ocurre en la falla de página real que introduce una nueva página en el espacio de direcciones actual. También es solo una sugerencia: el kernel recurrirá a otros nodos si no hay memoria disponible en el destino de entrelazado.

numa_interleave_memory() entrelaza size bytes de memoria página por página desde start en los nodos especificados en nodemask. El argumento size se redondeará al múltiplo del tamaño de página del sistema. Si nodemask contiene nodos que están externamente denegados a este proceso, esta llamada fallará. Esta es una función de nivel inferior para entrelazar memoria asignada pero aún no paginada. No paginada significa que la memoria se asigna usando mmap(2) o shmat(2), pero aún no ha sido accedida por el proceso actual. La memoria se entrelaza por páginas en todos los nodos especificados en nodemask. Normalmente, se debe usar numa_alloc_interleaved() para memoria privada en su lugar, pero esta función es útil para manejar áreas de memoria compartida. Para ser útil, el área de memoria debe ser de varios megabytes como mínimo (o decenas de megabytes de mapeos hugetlbfs). Si el indicador numa_set_strict() es verdadero, la operación provocará un numa_error si ya había páginas en el mapeo que no siguen la política.

numa_bind() une la tarea actual y sus hijos a los nodos especificados en nodemask. Solo se ejecutarán en las CPU de los nodos especificados y solo podrán asignar memoria de ellos. Esta función es equivalente a llamar a numa_run_on_node_mask(nodemask) seguido de numa_set_membind(nodemask). Si las tareas deben unirse a CPU individuales dentro de los nodos, considere usar numa_node_to_cpus y la llamada al sistema sched_setaffinity(2).

numa_set_localalloc() establece la política de asignación de memoria para la tarea llamante a asignación local. En este modo, el nodo preferido para la asignación de memoria es efectivamente el nodo donde se está ejecutando la tarea en el momento de la asignación de página.

numa_set_membind() establece la máscara de asignación de memoria. La tarea solo asignará memoria de los nodos establecidos en

nodemask. Pasar una nodemask vacía o una nodemask que contenga nodos distintos de los de la máscara devuelta por numa_get_mems_allowed() resultará en un error.

numa_set_membind_balancing() establece la máscara de asignación de memoria y habilita el equilibrio NUMA del kernel de Linux para la tarea si la característica es compatible con el kernel. La tarea solo asignará memoria de los nodos establecidos en nodemask. Pasar una nodemask vacía o una nodemask que contenga nodos distintos de los de la máscara devuelta por numa_get_mems_allowed() resultará en un error.

numa_get_membind() devuelve la máscara de nodos de los cuales se puede asignar memoria actualmente. Si la máscara devuelta es igual a numa_all_nodes, la asignación de memoria está permitida desde todos los nodos.

numa_alloc_onnode() asigna memoria en un nodo específico. El argumento size se redondeará a un múltiplo del tamaño de página del sistema. Si el node especificado está denegado externamente a este proceso, esta llamada fallará. Esta función es relativamente lenta en comparación con la familia de funciones de malloc(3). La memoria debe liberarse con numa_free(). En caso de error, se devuelve NULL.

numa_alloc_local() asigna size bytes de memoria en el nodo local. El argumento size se redondeará a un múltiplo del tamaño de página del sistema. Esta función es relativamente lenta en comparación con la familia de funciones de malloc(3). La memoria debe liberarse con numa_free(). En caso de error, se devuelve NULL.

numa_alloc_interleaved() asigna size bytes de memoria intercalada en todos los nodos. Esta función es relativamente lenta y solo debe usarse para áreas grandes que constan de varias páginas. La intercalación funciona a nivel de página y solo tendrá un efecto cuando el área sea grande. La memoria asignada debe liberarse con numa_free(). En caso de error, se devuelve NULL.

numa_alloc_interleaved_subset() intenta asignar size bytes de memoria intercalada en todos los nodos. El argumento size se redondeará a un múltiplo del tamaño de página del sistema. Los nodos en los que un proceso tiene permitido asignar memoria pueden estar restringidos externamente. Si este es el caso, esta función puede fallar. Esta función es relativamente lenta en comparación con la familia de funciones de malloc(3) y solo debe usarse para áreas grandes que constan de varias páginas. La intercalación funciona a nivel de página y solo tendrá un efecto cuando el área sea grande. La memoria asignada debe liberarse con numa_free(). En caso de error, se devuelve NULL.

numa_alloc() asigna size bytes de memoria con la política NUMA actual. El argumento size se redondeará a un múltiplo del tamaño de página del sistema. Esta función es relativamente lenta en comparación con la familia de funciones de malloc(3). La memoria debe liberarse con numa_free(). En caso de error, se devuelve NULL.

numa_realloc() cambia el tamaño del área de memoria apuntada por old_addr de old_size a new_size. El área de memoria apuntada por old_addr debe haber sido asignada con una de las funciones numa_alloc*. El new_size se redondeará a un múltiplo del tamaño de página del sistema. El contenido del área de memoria no cambiará hasta el mínimo de los tamaños antiguo y nuevo; la memoria recién asignada no se inicializará. La política de memoria (y los enlaces de nodo) asociados con el área de memoria original se conservarán en el área redimensionada. Por ejemplo, si el área inicial se asignó con una llamada a numa_alloc_onnode(), las nuevas páginas (si el área se amplía) se asignarán en el mismo nodo. Sin embargo, si no se estableció ninguna política de memoria para el área original, numa_realloc() no puede garantizar que las nuevas páginas se asignarán en el mismo nodo. En caso de éxito, se devuelve la dirección del área redimensionada (que puede ser diferente de la del área inicial); de lo contrario, se devuelve NULL y se establece errno para indicar el error. El puntero devuelto por numa_realloc() es adecuado para pasarlo a numa_free().

numa_free() libera size bytes de memoria a partir de start, asignados por las funciones numa_alloc_* anteriores. El argumento size se redondeará a un múltiplo del tamaño de página del sistema.

numa_run_on_node() ejecuta la tarea actual y sus hijos en un nodo específico. No migrarán a CPUs de otros nodos hasta que se restablezca la afinidad del nodo con una nueva llamada a numa_run_on_node_mask(). Pasar -1 permite que el kernel programe en todos los nodos nuevamente. En caso de éxito, se devuelve 0; en caso de error, se devuelve -1 y se establece errno para indicar el error.

numa_run_on_node_mask() ejecuta la tarea actual y sus hijos solo en los nodos especificados en nodemask. No migrarán a CPUs de otros nodos hasta que se restablezca la afinidad del nodo con una nueva llamada a numa_run_on_node_mask() o numa_run_on_node(). Pasar numa_all_nodes permite que el kernel programe en todos los nodos nuevamente. En caso de éxito, se devuelve 0; en caso de error, se devuelve -1 y se establece errno para indicar el error.

numa_run_on_node_mask_all() ejecuta la tarea actual y sus hijos solo en los nodos especificados en nodemask como numa_run_on_node_mask pero sin ninguna conciencia de cpuset.

numa_get_run_node_mask() devuelve una máscara de CPUs en las que la tarea actual tiene permitido ejecutarse.

numa_tonode_memory() coloca la memoria en un nodo específico. Las restricciones descritas para numa_interleave_memory() también se aplican aquí.

numa_tonodemask_memory() coloca la memoria en un conjunto específico de nodos. Las restricciones descritas para numa_interleave_memory() también se aplican aquí.

numa_setlocal_memory() localiza la memoria en el nodo actual. Las restricciones descritas para numa_interleave_memory() también se aplican aquí.

numa_police_memory() localiza la memoria con la política NUMA actual. Las restricciones descritas para numa_interleave_memory() también se aplican aquí. La función leerá-modificará-escribirá partes de la memoria, y es responsabilidad del llamante evitar condiciones de carrera con hilos paralelos.

numa_distance() informa la distancia en la topología de la máquina entre dos nodos. Los factores son un múltiplo de 10. Devuelve 0 cuando la distancia no se puede determinar. Un nodo tiene una distancia de 10 a sí mismo. Informar la distancia requiere una versión del kernel de Linux de 2.6.10 o posterior.

numa_set_bind_policy() especifica si las llamadas que vinculan la memoria a un nodo específico deben usar la política preferida o una política estricta. La política preferida permite que el kernel asigne memoria en otros nodos cuando no hay suficiente espacio libre en el nodo de destino. Estricto fallará la asignación en ese caso. Establecer el argumento a especifica estricto, 0 preferido. Tenga en cuenta que especificar más de un nodo no estrictamente puede usar solo el primer nodo en algunas versiones del kernel.

numa_set_strict() establece una bandera que indica si las funciones que asignan en nodos específicos deben usar una política estricta. Estricto significa que la asignación fallará si la memoria no se puede asignar en el nodo de destino. La operación predeterminada es recurrir a otros nodos. Esto no se aplica a intercalado y predeterminado.

numa_get_interleave_node() es utilizado internamente por libnuma. Probablemente no sea útil para aplicaciones de usuario. Utiliza la bandera MPOL_F_NODE de la llamada al sistema get_mempolicy, que no está destinada al uso por aplicaciones (su funcionamiento puede cambiar o eliminarse por completo en futuras versiones del kernel). Ver get_mempolicy(2).

numa_pagesize() devuelve el número de bytes en una página. Esta función es simplemente una alternativa rápida a las llamadas repetidas a la llamada al sistema getpagesize. Ver getpagesize(2).

numa_sched_getaffinity() recupera una máscara de bits de las CPUs en las que una tarea puede ejecutarse. La tarea se especifica mediante pid. Devuelve el valor de retorno de la llamada al sistema sched_getaffinity. Ver sched_getaffinity(2). La máscara de bits debe tener al menos el tamaño de la estructura de máscara de CPU del kernel. Use numa_allocate_cpumask() para asignarla. Pruebe los bits en la máscara llamando a numa_bitmask_isbitset().

numa_sched_setaffinity() establece las CPUs permitidas de una tarea en aquellas especificadas en mask. La tarea se especifica mediante pid. Devuelve el valor de retorno de la llamada al sistema sched_setaffinity. Ver sched_setaffinity(2). Puede asignar la máscara de bits con numa_allocate_cpumask(). O la máscara de bits puede ser más pequeña que la estructura de máscara de CPU del kernel. Por ejemplo, llame a numa_bitmask_alloc() usando un número máximo de CPUs de numa_num_configured_cpus(). Establezca los bits en la máscara llamando a numa_bitmask_setbit().

numa_node_to_cpus() convierte un número de nodo en una máscara de bits de CPUs. El usuario debe pasar una estructura de máscara de bits con un buffer de máscara lo suficientemente largo como para representar todas las CPUs posibles. Use numa_allocate_cpumask() para crearlo. Si la máscara de bits no es lo suficientemente larga, se establecerá errno en ERANGE y se devolverá -1. En caso de éxito, se devuelve 0.

numa_node_to_cpu_update() Marca la máscara de bits de CPUs de todos los nodos como obsoleta, luego obtiene la última máscara de bits llamando a numa_node_to_cpus(). Esto permite actualizar el estado de libnuma después de un evento de hotplug de CPU. La aplicación es responsable de detectar los eventos de hotplug de CPU.

numa_node_of_cpu() devuelve el nodo al que pertenece una CPU. Si el usuario proporciona una CPU inválida, se establecerá errno en EINVAL y se devolverá -1.

numa_allocate_cpumask () devuelve una máscara de bits de un tamaño igual a la máscara de CPU del kernel (tipo de kernel cpumask_t). En otras palabras, lo suficientemente grande como para representar NR_CPUS CPUs. Este número de CPUs se puede obtener llamando a numa_num_possible_cpus(). La máscara de bits se rellena con ceros.

numa_free_cpumask libera una máscara de CPU asignada previamente por numa_allocate_cpumask.

numa_allocate_nodemask() devuelve una máscara de bits de un tamaño igual a la máscara de nodo del kernel (tipo de kernel nodemask_t). En otras palabras, lo suficientemente grande como para representar MAX_NUMNODES nodos. Este número de nodos se puede obtener llamando a numa_num_possible_nodes(). La máscara de bits se rellena con ceros.

numa_free_nodemask() libera una máscara de nodo previamente asignada por numa_allocate_nodemask().

numa_bitmask_alloc() asigna una estructura de máscara de bits y su máscara de bits asociada. La memoria asignada para la máscara de bits contiene suficientes palabras (tipo unsigned long) para contener n bits. La máscara de bits se rellena con ceros. La estructura de máscara de bits apunta a la máscara de bits y contiene el valor n.

numa_bitmask_clearall() establece todos los bits de la máscara de bits a 0. La estructura de máscara de bits apunta a la máscara de bits y contiene su tamaño ( bmp ->size). Siempre se devuelve el valor de bmp. Tenga en cuenta que numa_bitmask_alloc() crea una máscara de bits rellena con ceros.

numa_bitmask_clearbit() establece un bit especificado en una máscara de bits a 0. Nada

DESCRIPTION

numa_bitmask_alloc() allocates a bitmask structure that can hold bits up to n. It returns a pointer to the allocated bitmask structure. If n is zero, NULL is returned. A bitmask structure contains an array of unsigned long integers which hold the actual bits and a field to store the size of the bitmask.

numa_bitmask_clearbit() sets a specified bit in a bit mask to 0. Nothing is done if n is greater than the size of the bitmask (and no error is returned). The value of bmp is always returned.

numa_bitmask_clearall() sets all bits in the bit mask to 0. The bitmask structure points to the bit mask and contains its size ( bmp ->size). The value of bmp is always returned.

numa_bitmask_to_nodemask() copies the bit mask body (the array of unsigned long integers) of the bitmask structure pointed to by bmp to a nodemask_t structure. It returns a pointer to the nodemask_t structure. The size of the nodemask_t structure is fixed and determined by the kernel. If the bitmask body is larger than the nodemask_t structure, the copy is truncated. If the bitmask body is smaller, the rest of the nodemask_t structure is zero-filled.

numa_bitmask_from_nodemask() copies the nodemask_t structure pointed to by nodemask to the bit mask body of the bitmask structure pointed to by bmp. The bitmask structure bmp must already exist and be large enough to hold the nodemask_t structure. If the nodemask_t structure is larger than the bitmask body, the copy is truncated. If the nodemask_t structure is smaller, the rest of the bitmask body is zero-filled.

The function numa_bitmask_free() deallocates the memory of both the bitmask structure pointed to by bmp and the bit mask. It is an error to attempt to free this bitmask twice.

numa_bitmask_equal() returns 1 if two bitmasks are equal. It returns 0 if they are not equal. If the bitmask structures control bit masks of different sizes, the "missing" trailing bits of the smaller bit mask are considered to be 0.

numa_bitmask_isbitset() returns the value of a specified bit in a bit mask. If the n value is greater than the size of the bit map, 0 is returned.

numa_bitmask_nbytes() returns the size (in bytes) of the bit mask controlled by bmp. The bit masks are always full words (type unsigned long), and the returned size is the actual size of all those words.

numa_bitmask_setall() sets all bits in the bit mask to 1. The bitmask structure points to the bit mask and contains its size ( bmp ->size). The value of bmp is always returned.

numa_bitmask_setbit() sets a specified bit in a bit mask to 1. Nothing is done if n is greater than the size of the bitmask (and no error is returned). The value of bmp is always returned.

numa_bitmask_weight() returns a count of the bits that are set in the body of the bitmask pointed to by the bmp argument.

numa_move_pages() moves a list of pages in the address space of the currently executing or current process. It simply uses the move_pages system call.
pid - ID of task. If not valid, use the current task.
count - Number of pages.
pages - List of pages to move.
nodes - List of nodes to which pages can be moved.
status - Field to which status is to be returned.
flags - MPOL_MF_MOVE or MPOL_MF_MOVE_ALL
See move_pages(2).

numa_migrate_pages() simply uses the migrate_pages system call to cause the pages of the calling task, or a specified task, to be migated from one set of nodes to another. See migrate_pages(2). The bit masks representing the nodes should be allocated with numa_allocate_nodemask() , or with numa_bitmask_alloc() using an n value returned from numa_num_possible_nodes(). A task's current node set can be gotten by calling numa_get_membind(). Bits in the tonodes mask can be set by calls to numa_bitmask_setbit().

numa_error() is a libnuma internal function that can be overridden by the user program. This function is called with a char * argument when a libnuma function fails. Overriding the library internal definition makes it possible to specify a different error handling strategy when a libnuma function fails. It does not affect numa_available(). The numa_error() function defined in libnuma prints an error on stderr and terminates the program if numa_exit_on_error is set to a non-zero value. The default value of numa_exit_on_error is zero.

numa_warn() is a libnuma internal function that can be also overridden by the user program. It is called to warn the user when a libnuma function encounters a non-fatal error. The default implementation prints a warning to stderr. The first argument is a unique number identifying each warning. After that there is a printf(3)-style format string and a variable number of arguments. numa_warn exits the program when numa_exit_on_warn is set to a non-zero value. The default value of numa_exit_on_warn is zero.

Compatibility with libnuma version 1

Binaries that were compiled for libnuma version 1 need not be re-compiled to run with libnuma version 2.
Source codes written for libnuma version 1 may be re-compiled without change with version 2 installed. To do so, in the code's Makefile add this option to CFLAGS: -DNUMA_VERSION1_COMPATIBILITY

THREAD SAFETY

numa_set_bind_policy and numa_exit_on_error are process global. The other calls are thread safe.
