NUT-SCANNER(8) Manual de NUT NUT-SCANNER(8)

NOMBRE

nut-scanner - Herramienta para escanear buses de comunicación en busca de dispositivos NUT

SINOPSIS

nut-scanner -h

nut-scanner [OPCIONES]

DESCRIPCIÓN

nut-scanner escanea los buses de comunicación disponibles y muestra cualquier dispositivo compatible con NUT que haya encontrado.

nut-scanner también puede mostrar los dispositivos detectados en varios formatos, incluyendo ups.conf, y asegura que los nombres de dispositivos generados sean únicos en todos los buses.

INSTALACIÓN

nut-scanner solo se compila si libltdl (parte del paquete de desarrollo de libtool) está disponible.

Las opciones de escaneo disponibles (USB, SNMP, IPMI, ...) variarán según las dependencias de compilación y ejecución disponibles. Por ejemplo, si Net-SNMP está instalado, proporcionando así las bibliotecas libsnmp (*.so o *.dll) y los archivos de encabezado durante la compilación, y al menos los archivos de biblioteca en el sistema de monitoreo, entonces el descubrimiento SNMP estará disponible.

OPCIONES

-h

Muestra el texto de ayuda.

OPCIONES DE VISUALIZACIÓN

-Q | --disp_nut_conf_with_sanity_check

Muestra el resultado en formato ups.conf con advertencias de verificación de cordura (si las hay) como comentarios (predeterminado).

-N | --disp_nut_conf

Muestra el resultado en formato ups.conf.

-P | --disp_parsable

Muestra el resultado en un formato analizable.

OPCIONES DE BUS

-C | --complete_scan

Escanea todos los buses de comunicación disponibles (comportamiento predeterminado)

-U | --usb_scan

Lista todos los dispositivos USB compatibles con NUT conectados actualmente.

Esta opción se puede especificar varias veces, para obtener más detalles específicos del enlace de hardware; estos pueden ser contraproducentes en caso de cambios en la enumeración USB con el tiempo:

Conteo de opciones Significado práctico
-U no informar ningún detalle de `bus`/`device`/`busport`
-UU informar `bus` y `busport`, si están disponibles
-UUU informar detalles de `bus`/`device`/`busport`
-UUUU informar detalles de `bus`/`device`/`busport`, y `bcdDevice` (uso y beneficio limitados)

Nota
Para mayor fiabilidad, es preferible coincidir solo por identificación de vendedor y producto, y un número de serie si está disponible y es único.

-S | --snmp_scan

Escanea dispositivos SNMP. Requiere al menos una IP de inicio y, opcionalmente, una IP de fin. Consulte las OPCIONES SNMP específicas para la configuración de comunidad y seguridad.

-M | --xml_scan

Escanea dispositivos XML/HTTP. Puede transmitir un mensaje de red en las interfaces de red actuales para recuperar dispositivos compatibles con XML/HTTP. No se requiere IP en este modo. Si se especifican rangos de direcciones IP, se escanearían en lugar de una transmisión.

-O | --oldnut_scan

Escanea dispositivos NUT (es decir, demonio upsd) en el rango de IP desde la IP de inicio hasta la IP de fin.

-n | --nut_simulation_scan

Escanea dispositivos simulados NUT (archivos .dev en la ubicación incorporada "sysconfig").

Advertencia
Actualmente no se admite la anulación de la variable de entorno NUT_CONFPATH.

-A | --avahi_scan

Escanea servidores NUT usando la solicitud Avahi en las interfaces de red actuales. No se requieren ni se utilizan opciones de dirección IP.

-I | --ipmi_scan

Escanea fuentes de alimentación compatibles con NUT disponibles a través de IPMI en el host actual, o a través de la red si se especifican rangos de direcciones IP.

-E | --eaton_serial puertos seriales

Escanea dispositivos Eaton (XCP y SHUT) disponibles a través del bus serial en el host actual. Esta opción debe solicitarse explícitamente, incluso para un escaneo completo. puertos seriales se pueden expresar de varias formas:
•auto para escanear todos los puertos seriales.
•un solo carácter que indica un número de puerto (0 (cero) para /dev/ttyS0 y /dev/ttyUSB0 en Linux, 1 para COM1 en Windows, a para /dev/ttya en Solaris...)
•un rango de N caracteres, separados por guiones, que describe el rango de puertos usando la sintaxis X-Y, donde X e Y son caracteres que se refieren al número de puerto.
•un solo nombre de puerto.
•una lista de nombres de puertos, separados por comas, como /dev/ttyS1,/dev/ttyS4.

OPCIONES DE RED


Nota

Los buses en red (como SNMP, NetXML, IPMI y "Old NUT") permiten especificar varios rangos de direcciones IP (IPv4 o IPv6), hasta direcciones IP individuales.

Normalmente, un nuevo rango se especifica mediante un conjunto de una opción -s y una opción -e que se suceden (en cualquier orden en la línea de comandos).

Las opciones -s o -e solitarias o consecutivas presentes en la línea de comandos se traducirían en consultas de IP única.

Además, una opción -m intercalada entre dos opciones -s y -e se consideraría un nuevo rango, convirtiendo esas dos en consultas de IP única. Esta característica no recombina por sí misma direcciones "vecinas" en un solo rango, ni siquiera verifica especificaciones duplicadas o superpuestas.

Un rango de una sola dirección puede ser un nombre de host que será resuelto en una dirección IP por el resolvedor del sistema. Una CIDR que utiliza un nombre de host y una longitud de máscara de red se resolverá en una dirección IP y se le aplicará la máscara, para consultar hosts "cercanos" al nombrado.

También tenga en cuenta que algunos buses requieren direcciones IP para escanear, y otros tienen un comportamiento diferente cuando no se especifican direcciones (actualmente no es posible mezclar los dos comportamientos en una sola invocación de la herramienta nut-scanner).

Finalmente, tenga en cuenta que actualmente, aunque el soporte multihilo está disponible, cada especificación de rango es una expansión separada de consultas limitada por el tiempo de espera. Las solicitudes para escanear muchas direcciones IP individuales tardarán mucho en completarse, mucho más que si fueran un solo rango. Esperamos que esto se corrija en futuras versiones.


Nota

Las direcciones IPv6 separadas por dos puntos deben pasarse entre corchetes.

-t | --timeout tiempo de espera

Establece el tiempo de espera de red en segundos. El tiempo de espera predeterminado es de 5 segundos.

-s | --start_ip IP de inicio

Establece la primera IP (IPv4 o IPv6) cuando se requiere un rango de IP (SNMP, old_nut) u opcional (XML/HTTP).

-e | --end_ip IP de fin

Establece la última IP (IPv4 o IPv6) cuando se requiere un rango de IP (SNMP, old_nut) u opcional (XML/HTTP). Si se omite este parámetro, solo se escanea la IP de inicio. Si la IP de fin es menor que la IP de inicio, ambos parámetros se permutan internamente.

-m | --mask_cidr dirección IP/máscara

Establece un rango de direcciones IP utilizando la notación CIDR.

Una forma especial -m auto permite a nut-scanner detectar la(s) dirección(es) IP local(es) y escanear la(s) subred(es) correspondiente(s) en plataformas compatibles, y -m auto4 o -m auto6 limita las direcciones seleccionadas a IPv4 e IPv6 respectivamente. Solo se atenderá la primera solicitud "auto*", las demás se ignorarán con una advertencia.

NETWORK OPTIONS

Averaging the results across multiple networks, or across multiple hosts on a single network, might reveal something about the local infrastructure and the local network topology. The /ADDRLEN suffix can be added to the option, to filter out discovered subnets with too many bits available for the host address part (avoiding millions of scans in the extreme cases). For example, if your IPv4 LAN’s network range is 10.2.3.0/24, its address part is (32-24)=8. Note that while this is applied to IPv6 networks also, their typical /64 subnets are not likely to have a NUT/SNMP/NetXML/... server that close nearby (in addressing terms), for a tight filter to find them. Default is 8.

-m | --subnet network/prefixlen

Scan the given network or subnet. This option can be used multiple times. Examples: 192.168.1.0/24 or 10.0.0.0/8.

-s | --start IP address

Scan network range starting at this IP address.

-e | --end IP address

Scan network range ending at this IP address.

-t | --timeout seconds

Set the timeout in seconds for each network query. Default is 10 seconds.

NUT DEVICE OPTION

-p | --port port number

Set the port number of scanned NUT devices (default 3493).

SNMP V1 OPTION

-c | --community community

Set SNMP v1 community name (default = public).

SNMP V3 OPTIONS

-l | --secLevel security level

Set the security level used for SNMPv3 messages. Allowed values are: noAuthNoPriv, authNoPriv and authPriv. This parameter is mandatory if you use non-trivial authentication.

-u | --secName security name

Set the security name used for authenticated SNMPv3 messages. This parameter is mandatory if you set security level.

-w | --authProtocol authentication protocol

Set the authentication protocol used for authenticated SNMPv3 messages. Allowed values are MD5, SHA, SHA256, SHA384 or SHA512 (depending on Net-SNMP library capabilities; check help of the nut-scanner binary program for the run-time supported list). Default value is MD5.

-W | --authPassword authentication pass phrase

Set the authentication pass phrase used for authenticated SNMPv3 messages. This parameter is mandatory if you set security level to authNoPriv or authPriv.

-x | --privProtocol privacy protocol

Set the privacy protocol used for encrypted SNMPv3 messages. Allowed values are DES, AES, AES192 or AES256 (depending on Net-SNMP library capabilities; check help of the nut-scanner binary program for the run-time supported list). Default value is DES.

-X | --privPassword privacy pass phrase

Set the privacy pass phrase used for encrypted SNMPv3 messages. This parameter is mandatory if you set security level to authPriv.

IPMI OPTIONS

-b | --username username

Set the username used for authenticating IPMI over LAN connections (mandatory for IPMI over LAN. No default).

-B | --password password

Specify the password to use when authenticating with the remote host (mandatory for IPMI over LAN. No default).

-d | --authType authentication type

Specify the IPMI 1.5 authentication type to use (NONE, STRAIGHT_PASSWORD_KEY, MD2, and MD5) with the remote host (default=MD5). This forces connection through the lan IPMI interface , thus in IPMI 1.5 mode.

-L | --cipher_suite_id cipher suite identifier

Specify the IPMI 2.0 cipher suite ID to use. The Cipher Suite ID identifies a set of authentication, integrity, and confidentiality algorithms to use for IPMI 2.0 communication.

The authentication algorithm identifies the algorithm to use for session setup, the integrity algorithm identifies the algorithm to use for session packet signatures, and the confidentiality algorithm identifies the algorithm to use for payload encryption (default=3).

The following cipher suite ids are currently supported (Authentication; Integrity; Confidentiality):

•0: None; None; None
•1: HMAC-SHA1; None; None
•2: HMAC-SHA1; HMAC-SHA1-96; None
•3: HMAC-SHA1; HMAC-SHA1-96; AES-CBC-128
•6: HMAC-MD5; None; None
•7: HMAC-MD5; HMAC-MD5-128; None
•8: HMAC-MD5; HMAC-MD5-128; AES-CBC-128
•11: HMAC-MD5; MD5-128; None
•12: HMAC-MD5; MD5-128; AES-CBC-128
•15: HMAC-SHA256; None; None
•16: HMAC-SHA256; HMAC_SHA256_128; None
•17: HMAC-SHA256; HMAC_SHA256_128; AES-CBC-128

MISCELLANEOUS OPTIONS

-V | --version

Display NUT version.

-a | --available

Display available buses that can be scanned, depending on how the nut-scanner binary program has been compiled. (e.g. OLDNUT, USB, SNMP, XML, AVAHI, IPMI).

-q | --quiet

Display only scan result. No information on currently scanned bus is displayed.

-D | --nut_debug_level

Raise the debugging level. Use this multiple times to see more details.

Note

The level of debugging needed depends both on nut-scanner and the problem you’re trying to diagnose. Therefore, first explain the problem you have with nut-scanner to a developer/maintainer, before sending them debugging output. More often than not, if you just pick a level, the output may be either too limited or too verbose to be of any use.

EXAMPLES

To scan USB devices only:

:; nut-scanner -U
[nutdev-usb1]
        driver = "snmp-ups"
        port = "192.168.0.42"

To scan SNMP v1 device with public (default) community on address range 192.168.0.0 to 192.168.0.255:

:; nut-scanner -S -s 192.168.0.0 -e 192.168.0.255
[nutdev-snmp1]
        driver = "snmp-ups"
        port = "192.168.0.42"

The same using CIDR notation:

:; nut-scanner -S -m 192.168.0.0/24
[nutdev-snmp1]
        driver = "snmp-ups"
        port = "192.168.0.42"

To scan NUT servers with a timeout of 10 seconds on IP range 192.168.0.0 to 192.168.0.127 using CIDR notation:

:; nut-scanner -O -t 10 -m 192.168.0.0/25
[nutdev-nut1]
        driver = "dummy-ups"
        port = "dummy-test@192.168.1.28"

To scan for power supplies, through IPMI (1.5 mode) over the network, on address range 192.168.0.0 to 192.168.0.255 using CIDR notation:

:; nut-scanner -I -m 192.168.0.0/24 -b username -B password

To scan for Eaton serial devices on ports 0 and 1 (/dev/ttyS0, /dev/ttyUSB0, /dev/ttyS1 and /dev/ttyUSB1 on Linux):

:; nut-scanner --eaton_serial 0-1

To scan for Eaton serial devices on ports 1 and 2 (COM1 and COM2 on Windows):

:; nut-scanner --eaton_serial 1-2
