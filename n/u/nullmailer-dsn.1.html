NOMBRE

nullmailer-dsn - Reinterpreta un mensaje en cola en una notificación de estado de entrega (DSN)

SINOPSIS

nullmailer-dsn [ opciones ] código-de-estado < mensaje

DESCRIPCIÓN

Este programa lee un mensaje de la cola de nullmailer desde la entrada estándar, lo transforma en una notificación de estado de entrega y escribe el resultado en la salida estándar. La salida está formateada para ser alimentada a nullmailer-queue.

Todos los tiempos en las opciones se expresan en segundos desde la medianoche GMT del 1 de enero de 1970 (la época UNIX).

OPCIONES

--diagnostic-code=CADENA
Establece el código de diagnóstico real emitido por el transporte de correo. Debe tener el formato "tipo; texto", donde tipo sería típicamente el nombre del protocolo, como SMTP. Esto añade una cabecera Diagnostic-Code para cada destinatario.
--envelope-id=CADENA
ID original del sobre. Establecer esto añade una cabecera Original-Envelope-Id a la sección de estado de entrega.
--last-attempt=TIEMPO
Establece la hora del último intento de entrega. Por defecto, es la hora de acceso del mensaje de entrada. Esto establece la fecha en la cabecera Last-Attempt-Date para cada destinatario.
--max-lines=NÚMERO
Establece el número máximo de líneas del mensaje original a copiar en el mensaje generado. Un valor de cero copia solo la cabecera original. Los valores negativos copian el mensaje completo. Por defecto, es bouncelines más abajo, o cero si este está vacío.
--orig-timestamp=TIEMPO
Establece la hora del mensaje original. Por defecto, es la hora de cambio del mensaje de entrada. Esto establece la fecha en la cabecera Arrival-Date en la sección de estado de entrega.
--remote=CADENA
Establece el nombre del servidor MTA remoto. Esto añade una cabecera Remote-MTA para cada destinatario.
--retry-until=TIEMPO
Establece la hora del (futuro) intento de entrega final. Sin valor por defecto. Esto añade una cabecera Will-Retry-Until para cada destinatario.

VALOR DE RETORNO

Sale con 0 si tuvo éxito, de lo contrario, imprime un mensaje diagnóstico en la salida de error y sale con 1.

ARCHIVOS DE CONTROL

adminaddr
Si doublebounceto está vacío, los rebotes dobles se envían a esta dirección en su lugar. Si no se configura ninguna dirección, no se generan rebotes dobles.
bouncelines
Establece el número máximo de líneas del mensaje original a copiar. Puede ser anulado por --max-lines como se describe arriba.
bounceto
La dirección a la que se deben enviar todos los rebotes. Si está vacía, se utiliza la dirección del remitente original.
defaultdomain
El contenido de este archivo se añade a cualquier nombre de host que no contenga un punto (excepto localhost), incluyendo defaulthost e idhost. Por defecto, es el valor del archivo de control me, si existe, de lo contrario, el nombre literal defaultdomain.
defaulthost
El contenido de este archivo se añade a cualquier dirección a la que le falte un nombre de host. Por defecto, es el valor del archivo de control me, si existe, de lo contrario, el nombre literal defaulthost.
doublebounceto
Si el remitente original estaba vacío (el mensaje original era un estado de entrega o una notificación de disposición), el rebote doble se envía a la dirección en este archivo.
idhost
El contenido de este archivo se utiliza al construir la cadena de message-id para el mensaje. Por defecto, es el valor canonizado de defaulthost.
me
El nombre de host completo del ordenador que ejecuta nullmailer. Por defecto, es el nombre literal me.
