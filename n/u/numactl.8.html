NOMBRE

numactl - Controla la política NUMA para procesos o memoria compartida

SINOPSIS

numactl [ --all ] [ --balancing ] [ --interleave nodes ] [ --weighted-interleave nodes ] [ --preferred node ] [ --preferred-many nodes ] [ --membind nodes ] [ --cpunodebind nodes ] [ --physcpubind cpus ] [ --localalloc ] [--] comando {argumentos ...}
numactl --show
numactl --hardware [--cpu-compress]
numactl --version
numactl [ --huge ] [ --offset offset ] [ --shmmode shmmode ] [ --length length ] [ --strict ]
[ --shmid id ] --shm shmkeyfile | --file tmpfsfile
[ --touch ] [ --dump ] [ --dump-nodes ] política de memoria

DESCRIPCIÓN

numactl ejecuta procesos con una política específica de planificación NUMA o de ubicación de memoria. La política se establece para el comando y es heredada por todos sus hijos. Además, puede establecer políticas persistentes para segmentos de memoria compartida o archivos.

Utilice -- antes del comando si está utilizando opciones de comando que puedan confundirse con opciones de numactl.

nodes puede especificarse como N,N,N o N-N o N,N-N o N-N,N-N y así sucesivamente. Los nodes relativos pueden especificarse como +N,N,N o +N-N o +N,N-N y así sucesivamente. El + indica que los números de nodo son relativos al conjunto de nodos permitidos del proceso en su cpuset actual. La notación !N-N indica la inversa de N-N, es decir, todos los nodos excepto N-N. Si se utiliza con la notación +, especifique !+N-N. Cuando se especifica same, se utiliza la máscara de nodo anterior especificada en la línea de comandos. all significa todos los nodos en el cpuset actual.

En lugar de un número, un nodo también puede ser:

netdev:DEV El nodo conectado al dispositivo de red DEV.
file:PATH El nodo del dispositivo de bloque de PATH.
ip:HOST El nodo del dispositivo de red de HOST
block:PATH El nodo del dispositivo de bloque PATH
pci:[seg:]bus:dev[:func] El nodo de un dispositivo PCI.

Tenga en cuenta que block solo resuelve los nombres de dispositivos de bloque del kernel para nombres udev; para /dev use file:

Los ajustes de política son:
--all, -a
Desactiva la conciencia predeterminada del cpuset, para que el usuario pueda utilizar todas las CPU/nodos posibles para los siguientes ajustes de política.
--interleave=nodes, -i nodes
Establece una política de intercalado de memoria. La memoria se asignará utilizando el método de ronda en nodes. Cuando la memoria no pueda asignarse en el destino de intercalado actual, se recurrirá a otros nodos. Se pueden especificar varios nodos en --interleave, --membind y --cpunodebind.
--weighted-interleave=nodes, -w nodes
Establece una política de intercalado de memoria ponderada. La memoria se asignará utilizando la proporción ponderada para cada nodo, que se puede leer de /sys/kernel/mm/mempolicy/weighted_interleave/node*. Cuando la memoria no pueda asignarse en el destino de intercalado actual, se recurrirá a otros nodos.
--membind=nodes, -m nodes
Solo asignar memoria de los nodos. La asignación fallará cuando no haya suficiente memoria disponible en estos nodos. Los nodes pueden especificarse como se indica arriba.
--cpunodebind=nodes, -N nodes
Ejecutar comando solo en las CPU de los nodes. Tenga en cuenta que los nodos pueden constar de varias CPU. Los nodes pueden especificarse como se indica arriba.
--physcpubind=cpus, -C cpus
Ejecutar proceso solo en las cpus. Esto acepta números de cpu como se muestran en los campos de processor de /proc/cpuinfo, o cpus relativas según el cpuset actual. Puede especificar "all", lo que significa todas las cpus del cpuset actual. Las cpus físicas pueden especificarse como N,N,N o N-N o N,N-N o N-N,N-N y así sucesivamente. Las cpus relativas pueden especificarse como +N,N,N o +N-N o +N,N-N y así sucesivamente. El + indica que los números de cpu son relativos al conjunto de cpus permitidas del proceso en su cpuset actual. La notación !N-N indica la inversa de N-N, es decir, todas las cpus excepto N-N. Si se utiliza con la notación +, especifique !+N-N.
--localalloc, -l
Intentar asignar en el nodo actual del proceso, pero si la memoria no puede asignarse allí, se recurrirá a otros nodos.
--preferred=node, -p node
Preferentemente asignar memoria en el node, pero si la memoria no puede asignarse allí, se recurrirá a otros nodos. Esta opción solo toma un número de nodo. Se puede utilizar notación relativa.
--balancing, -b
Habilitar el equilibrio NUMA del kernel de Linux para el proceso si es soportado por el kernel. Esto solo debe usarse con --membind, -m solamente, de lo contrario se ignora.
--preferred-many=nodes, -P nodes
Preferentemente asignar memoria en los nodes, pero si la memoria no puede asignarse allí, se recurrirá a otros nodos. Esta opción toma una máscara de nodos preferidos donde el nodo más cercano a local se considera el más preferido. Se puede utilizar notación relativa.
--show, -s
Mostrar la configuración de la política NUMA del proceso actual.
--hardware, -H
Mostrar el inventario de nodos disponibles en el sistema. Cuando la opción --cpu-compress está activada, muestra rangos de CPU. Esto no es predeterminado y no rompe ningún script existente.
Numactl puede configurar la política para un segmento de memoria compartida SYSV o un archivo en shmfs/hugetlbfs.
--version
imprime la versión del paquete numactl y sale.
Los siguientes ajustes de política son persistentes y serán utilizados por
todos los mapeos de esa memoria compartida. El orden de las opciones es importante aquí. La especificación debe incluir al menos uno de --shm, --shmid, --file para especificar el segmento de memoria compartida o archivo y una política de memoria como se describe arriba ( --interleave, --localalloc, --preferred, --preferred-many, --membind ).
--huge
Al crear un segmento de memoria compartida SYSV, utiliza páginas grandes. Solo válido antes de --shmid o --shm
--offset
Especifica el desplazamiento dentro del segmento de memoria compartida. Predeterminado 0. Las unidades válidas son m (para MB), g (para GB), k (para KB), de lo contrario especifica bytes.
--strict
Genera un error cuando una página en el área con política en el segmento de memoria compartida ya se ha cargado con una política conflictiva. El predeterminado es ignorar esto silenciosamente.
--shmmode shmmode
Solo válido antes de --shmid o --shm Al crear un segmento de memoria compartida, establécelo en el modo numérico shmmode.
--length length
Aplica la política al rango length en el segmento de memoria compartida o hace que la longitud del segmento sea larga. El predeterminado es usar la longitud restante. Requerido cuando se crea un segmento de memoria compartida y especifica la longitud del nuevo segmento. Las unidades válidas son m (para MB), g (para GB), k (para KB), de lo contrario especifica bytes.
--shmid id
Crea o usa un segmento de memoria compartida con el ID numérico id
--shm shmkeyfile
Crea o usa un segmento de memoria compartida, con el ID generado usando ftok(3) desde shmkeyfile
--file tmpfsfile
Establece la política para un archivo en tmpfs o hugetlbfs
--touch
Toca todas las páginas en el área policied del segmento de memoria compartida y así las carga con la política especificada.
--dump
Imprime el contenido del área policied del segmento de memoria compartida en la salida estándar.
--dump-nodes
Imprime el contenido del área policied del segmento de memoria compartida y la lista de nodos de memoria de cada página en la salida estándar.

EJEMPLOS

Ejecuta myprogram con la política de memoria intercalada en los nodos 0 y 1:

numactl --interleave=0,1 myprogram

Ejecuta myprogram solo en la CPU 1 y asigna memoria solo en el nodo 0:

numactl --physcpubind=1 --membind=0 myprogram

Ejecuta myprogram con equilibrio NUMA habilitado y memoria preferida en el nodo 0, recurriendo a otros nodos si es necesario:

numactl --balancing --preferred=0 myprogram

Establece la política de memoria para un segmento de memoria compartida creado con ftok (usando /tmp/shmfile) para que se asigne en el nodo 0 y mantenga la política para todas las asignaciones futuras:

numactl --shm /tmp/shmfile --membind=0 myprogram

VER TAMBIÉN

getent(3), mempolicy(3), hwloc(7), cpuset(7), migp(8)

OPCIONES

--touch
Toca las páginas para forzar la aplicación de la política de forma temprana. Por defecto, no las toca; la política se aplica cuando una aplicación mapea y accede a una página.
--dump
Volca la política en el rango especificado.
--dump-nodes
Volca todos los nodos del rango especificado (¡muy verboso!).
Especificadores de nodo válidos
all Todos los nodos
numero Número de nodo
numero1{,numero2} Nodo numero1 y Nodo numero2
numero1-numero2 Nodos del numero1 al numero2
! nodos Invierte la selección de la especificación siguiente.

EJEMPLOS

numactl --physcpubind=+0-4,8-12 myapplic arguments Ejecuta myapplic en los cpus 0-4 y 8-12 del cpuset actual.

numactl --interleave=all bigdatabase arguments Ejecuta la base de datos grande con su memoria intercalada en todas las CPUs.

numactl --weighted-interleave=all bigdatabase arguments Ejecuta la base de datos grande con su memoria intercalada con una relación ponderada en todas las CPUs.

numactl --cpunodebind=0 --membind=0,1 process Ejecuta process en el nodo 0 con memoria asignada en los nodos 0 y 1.

numactl --cpunodebind=0 --membind=0,1 -- process -l Ejecuta process como el anterior, pero con una opción (-l) que se confundiría con una opción de numactl.

numactl --cpunodebind=0 --balancing --membind=0,1 process Ejecuta process en el nodo 0 con memoria asignada en los nodos 0 y 1. Optimiza la colocación de páginas con el mecanismo de balanceo NUMA del kernel de Linux si es posible.

numactl --cpunodebind=netdev:eth0 --membind=netdev:eth0 network-server Ejecuta network-server en el nodo del dispositivo de red eth0 con su memoria también en el mismo nodo.

numactl --preferred=1 numactl --show Establece el nodo preferido 1 y muestra el estado resultante.

numactl --preferred-many=0x3 numactl --show Establece los nodos preferidos 1 y 2, y muestra el estado resultante.

numactl --length 1g --shm /tmp/shmkey --interleave=all Intercala toda la región de memoria compartida sysv de tamaño 1g especificada por /tmp/shmkey sobre todos los nodos.

Coloca un archivo tmpfs en 2 nodos:
numactl --membind=2 dd if=/dev/zero of=/dev/shm/A bs=1M count=1024
numactl --membind=3 dd if=/dev/zero of=/dev/shm/A seek=1024 bs=1M count=1024

numactl --localalloc /dev/shm/file Restablece la política para el archivo de memoria compartida file a la política localalloc por defecto.

NOTAS

Requiere un kernel compatible con políticas NUMA.

El comando no se ejecuta usando un shell. Si desea utilizar metacaracteres del shell en el hijo, use sh -c como envoltorio.

Establecer la política para un archivo hugetlbfs actualmente no funciona porque no puede ser extendido por truncate.

Los segmentos de memoria compartida más grandes que el espacio de direcciones de numactl no pueden ser completamente gestionados por políticas. Esto podría ser un problema en arquitecturas de 32 bits. Cambiarlo pieza por pieza podría funcionar.

El antiguo --cpubind que acepta números de nodo, no números de CPU, está obsoleto y reemplazado por las nuevas opciones --cpunodebind y --physcpubind.

ARCHIVOS

/proc/cpuinfo para la lista de CPUs activas. Ver proc(5) para detalles.

/sys/devices/system/node/node*/numastat para estadísticas de aciertos de memoria NUMA.
