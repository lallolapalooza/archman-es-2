ncftp(1) Manual de Comandos Generales ncftp(1)

NOMBRE

ncftp - Programa explorador para el Protocolo de Transferencia de Archivos

SINOPSIS

ncftp [host]

ncftp [ftp://host.name/directorio/]

DESCRIPCIÓN

El propósito de ncftp es proporcionar una interfaz potente y flexible al Protocolo de Transferencia de Archivos estándar de Internet. Está destinado a reemplazar el programa ftp predeterminado que viene con el sistema.

Aunque el programa parece bastante espartano, encontrarás que ncftp tiene una gran cantidad de valiosas características de rendimiento y uso. El programa fue diseñado con énfasis en la usabilidad, y hace todo lo que puede por ti automáticamente para que puedas hacer lo que esperas hacer con un programa de transferencia de archivos, que es transferir archivos entre dos sistemas interconectados.

Algunas de las características más interesantes incluyen medidores de progreso, finalización de nombres de archivo, edición de línea de comandos, procesamiento en segundo plano, reanudación automática de descargas, marcadores, listados de directorios cacheados, reintento de conexión a hosts, trabajo con firewalls y proxies, descarga de árboles de directorios completos, etc., etc.

La distribución de ncftp viene con los útiles programas de utilidad ncftpget(1) y ncftpput(1) que fueron diseñados para hacer FTP desde la línea de comandos. En particular, son muy útiles para scripts de shell. Esta versión de ncftp ya no hace FTP desde la línea de comandos, ya que el programa principal ncftp es más un programa tipo explorador.

OPCIONES

El programa te permite especificar un host o una URL de directorio en la línea de comandos. Esto es un sinónimo de ejecutar ncftp y luego usar el comando open. Se permiten algunas banderas de línea de comandos con este modo:

-u XX
Usa el nombre de usuario XX en lugar de anónimo.
-p XX
Usa la contraseña XX con el nombre de usuario.
-j XX
Usa la cuenta XX además del nombre de usuario y la contraseña (obsoleto).
-P XX
Usa el número de puerto XX en lugar del puerto de servicio FTP predeterminado (21).

INTRODUCCIÓN AL SHELL DE COMANDOS

Al ejecutar el programa, se te presenta un prompt de comandos donde escribes comandos para el shell del programa. Normalmente querrás abrir un sistema de archivos remoto para transferir archivos hacia y desde el sistema de archivos de tu máquina local. Para hacer eso, necesitas conocer el nombre simbólico del sistema remoto, o su dirección de Protocolo de Internet (IP). Por ejemplo, un nombre simbólico podría ser ``typhoon.unl.edu,'' y su dirección IP podría ser ``129.93.33.24.'' Para abrir una conexión a ese sistema, usas el comando open del programa:


open typhoon.unl.edu
open 129.93.33.24

Ambas intentan abrir la máquina llamada typhoon en la Universidad de Nebraska. Usar el nombre simbólico es la forma preferida, porque las direcciones IP pueden cambiar sin previo aviso, mientras que los nombres simbólicos suelen permanecer iguales.

Cuando abres un sistema de archivos remoto, necesitas tener permiso. El sistema de autenticación del Protocolo FTP es muy similar al de iniciar sesión en tu cuenta. Tienes que proporcionar un nombre de cuenta y su contraseña para acceder a los archivos de esa cuenta. Sin embargo, la mayoría de los sistemas remotos que tienen algo que podría interesarte no requieren un nombre de cuenta para su uso. A menudo puedes obtener acceso anónimo a un sistema de archivos remoto e intercambiar archivos que se han hecho públicamente accesibles. El programa intenta obtener permiso anónimo a un sistema remoto por defecto. Lo que realmente sucede es que el programa intenta usar ``anonymous'' como nombre de cuenta, y cuando se le solicita la contraseña, usa tu dirección de correo electrónico como cortesía al mantenedor del sistema remoto. También puedes hacer que el programa intente usar una cuenta específica. Eso se explicará más adelante.

Después de que el comando open se complete exitosamente, estás conectado al sistema remoto e has iniciado sesión. Ahora deberías ver que el prompt de comandos cambia para reflejar el nombre del directorio remoto actual. Para ver qué hay en el directorio remoto actual, puedes usar los comandos ls y dir del programa. El primero es conciso, prefiere más archivos remotos en menos espacio de pantalla, y el segundo es más verboso, dando información detallada sobre cada elemento en el directorio.

Puedes usar el comando cd del programa para moverte a otros directorios en el sistema remoto. El comando cd se comporta de manera muy similar al comando del mismo nombre en el shell Bourne y Korn.

El propósito del programa es intercambiar datos con otros sistemas. Puedes usar el comando get del programa para copiar un archivo del sistema remoto a tu sistema local:


get README.txt

El programa mostrará el progreso de la transferencia en la pantalla, para que puedas saber cuánto falta antes de que la transferencia termine. Cuando la transferencia termine, puedes ingresar más comandos al shell de comandos del programa.

Puedes usar el comando put del programa para copiar un archivo de tu sistema al sistema remoto:


put something.tar

Cuando hayas terminado de usar el sistema remoto, puedes abrir otro o usar el comando quit.

Antes de salir, es posible que desees guardar la configuración de la sesión FTP actual para más tarde. Puedes usar el comando bookmark para guardar una entrada en tu archivo $HOME/.ncftp/bookmarks. Cuando usas el comando bookmark, también especificas un nombre de marcador, de modo que la próxima vez, en lugar de abrir el nombre de host completo, puedes usar el nombre del marcador. Un marcador actúa de forma muy similar a uno para tu navegador web, ya que guarda el directorio remoto en el que estabas, el nombre de cuenta que usaste, etc., y otra información aprendida para que la próxima vez que uses el marcador requiera el menor esfuerzo posible de tu parte.

REFERENCIA DE COMANDOS

help
El primer comando que debes conocer es help. Si simplemente escribes

help

desde el shell de comandos, el programa imprime los nombres de todos los comandos soportados. A partir de ahí, puedes obtener ayuda específica para un comando escribiendo el comando después, por ejemplo:

help open

imprime información sobre el comando open.
ascii
Este comando establece el tipo de transferencia a texto ASCII. Esto es útil para transferencias de solo texto porque el concepto de archivos de texto difiere entre sistemas operativos. Por ejemplo, en UNIX, un archivo de texto denota saltos de línea con el carácter de salto de línea (linefeed), mientras que en MS-DOS un salto de línea se denota tanto por un carácter de retorno de carro (carriage return) como por un carácter de salto de línea. Por lo tanto, para transferencias de datos que consideras texto, puedes usar ascii para asegurarte de que tanto el sistema remoto como el local realicen la traducción adecuadamente. El tipo de transferencia predeterminado que usa ncftp no es ASCII, sino binario directo.
bgget y bgput
Estos comandos corresponden a los comandos get y put explicados a continuación, excepto que realizan el trabajo en segundo plano. Normalmente, cuando haces un get, el programa realiza la descarga inmediatamente y no te devuelve el control hasta que la descarga se completa. Las transferencias en segundo plano son útiles porque puedes seguir explorando el sistema de archivos remoto e incluso abrir otros sistemas. De hecho, son realizadas por un proceso demonio, por lo que incluso si cierras la sesión de tu host UNIX, el demonio debería seguir realizando tus transferencias. El demonio también reintentará automáticamente las transferencias hasta que finalicen. Para saber cuándo han terminado los trabajos en segundo plano, debes examinar el archivo $HOME/.ncftp/spool/log, o ejecutar el comando jobs dentro de NcFTP.
Tanto los comandos bgget como bgput te permiten programar cuándo realizar las transferencias. Toman un parámetro ``-@'', cuyo argumento es una fecha del formato AAAA MM DD hh ss (año de cuatro dígitos, mes, día, hora, minuto, segundo). Por ejemplo, para programar una descarga a las 3 AM del 6 de noviembre, podrías intentar:

bgget -@ 1997110603000

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

0 /pub/idstuff/quake/q2_100.zip
bgstart
Este comando le indica a ncftp que inicie inmediatamente las transferencias en segundo plano que ha solicitado, lo que simplemente ejecuta una copia del programa ncftpbatch que es responsable de los trabajos en segundo plano. Normalmente, el programa iniciará el trabajo en segundo plano tan pronto como cierre el sitio actual, abra un nuevo sitio o salga del programa. La razón de esto es que, dado que muchos usuarios todavía utilizan enlaces de acceso telefónico lentos, iniciar las transferencias ralentizaría las cosas hasta casi detenerse, lo que dificultaría la navegación por el sistema remoto. Una ventaja adicional de iniciar el trabajo en segundo plano cuando cierra el sitio es que ncftp puede pasar esa conexión abierta al programa ncftpbatch. Eso es bueno cuando el sitio está siempre ocupado, para que el trabajo en segundo plano no tenga que esperar y volver a iniciar sesión para realizar su trabajo.
binary
Establece el tipo de transferencia a binario puro, de modo que no se realice ninguna traducción en los datos transferidos. De todos modos, este es el valor predeterminado, ya que la mayoría de los archivos están en formato binario.
bookmark
Guarda la configuración de la sesión actual para su uso posterior. Esto es útil para guardar el sistema remoto y el directorio de trabajo remoto para que pueda reanudar rápidamente donde lo dejó en otro momento. Los datos de marcador se almacenan en su archivo $HOME/.ncftp/bookmarks.
bookmarks
Enumera el contenido de su archivo $HOME/.ncftp/bookmarks en un formato legible para humanos. Puede utilizar este comando para recordar el nombre del marcador de un marcador guardado previamente, de modo que pueda utilizar el comando open con él.
cat
Actúa como el comando ``/bin/cat'' de UNIX, pero para archivos remotos. Esto descarga el archivo que especifique y lo muestra directamente en la pantalla. Probablemente encontrará el comando page más útil, ya que le permite ver el archivo pantalla por pantalla en lugar de imprimir todo el archivo a la vez.
cd
Cambia el directorio de trabajo en el host remoto. Utilice este comando para moverse a diferentes áreas del servidor remoto. Si acaba de abrir un nuevo sitio, es posible que se encuentre en el directorio raíz. Quizás había un directorio llamado ``/pub/news/comp.sources.d'' del que alguien le habló. Desde el directorio raíz, podría:

cd pub
cd news
cd comp.sources.d

o, de forma más concisa,

cd /pub/news/comp.sources.d

Luego, comandos como get, put y ls podrían usarse para referirse a elementos en ese directorio.
Algunos shells en el entorno UNIX tienen una característica que me gusta, que es cambiar al directorio anterior. Al igual que esos shells, puede hacer:

cd -

para cambiar al último directorio en el que se encontraba.
chmod
Actúa como el comando ``/bin/chmod'' de UNIX, pero para archivos remotos. Sin embargo, este no es un comando estándar, por lo que los servidores FTP remotos pueden no admitirlo.
close
Lo desconecta del servidor remoto. El programa hace esto automáticamente cuando es necesario, por lo que puede simplemente abrir otros sitios o salir del programa sin preocuparse por cerrar la conexión manualmente.
debug
Este comando es principalmente para pruebas internas. Podría escribir

debug 1

para activar el modo de depuración. Luego podría ver todos los mensajes entre el programa y el servidor remoto, y las cosas que solo se imprimen en modo de depuración. Sin embargo, esta información también está disponible en el archivo $HOME/.ncftp/trace, que se crea cada vez que ejecuta ncftp. Si necesita informar un error, envíe un archivo trace si puede.
dir
Imprime una lista detallada del directorio. Intenta comportarse como el comando ``/bin/ls -l'' de UNIX. Si el servidor remoto parece ser un host UNIX, también puede usar las mismas opciones que usaría con ls, por ejemplo

dir -rt

intentaría actuar como

/bin/ls -lrt

lo haría en UNIX.
edit
Descarga en un archivo temporal para editarlo en el host local, luego carga el archivo modificado de nuevo en el host remoto.
get
Copia archivos del directorio de trabajo actual en el host remoto a su directorio de trabajo actual. Para colocar una copia de ``README'' y ``README.too'' en su directorio local, podría intentar:

get README README.too

También podría lograr eso usando una expresión comodín, como:

get README*

Este comando es similar al comportamiento del comando mget de otros programas FTP. Para recuperar un archivo remoto pero darle un nombre diferente en su host, puede usar la opción ``-z''. Este ejemplo muestra cómo descargar un archivo llamado ReadMe.txt pero nombrarlo localmente como README:

get -z ReadMe.txt README

El programa intenta ``reanudar'' las descargas de forma predeterminada. Esto significa que si el servidor FTP remoto perdió la conexión y solo pudo enviar 490 kilobytes de un archivo de 500 kilobytes, podría volver a conectarse al servidor FTP y hacer otro get con el mismo nombre de archivo y obtendría los últimos 10 kilobytes, en lugar de recuperar todo el archivo nuevamente. Hay algunas ocasiones en las que es posible que no desee ese comportamiento. Para desactivarlo, puede usar la opción ``-f''.
También hay momentos en los que desea agregar a un archivo existente. Puede hacerlo utilizando la opción ``-A'', por ejemplo

get -A log.11

agregarí­a a un archivo llamado ``log.11'' si existiera localmente.
Otra cosa que puede hacer es eliminar un archivo remoto después de descargarlo. Esto puede ser útil cuando un host remoto espera que se elimine un archivo cuando se ha recuperado. Use la opción doble D, como ``get -DD'' para hacer esto.
El comando get también le permite recuperar árboles de directorios completos. Aunque puede que no funcione con algunos sistemas remotos, puede intentar ``get -R'' con un directorio para descargar el directorio y su contenido.
Al usar la opción ``-R'', también puede usar la opción ``-T'' para deshabilitar el modo TAR automático sobre la marcha para descargar árboles de directorios completos. El programa utiliza TAR siempre que es posible, ya que esto generalmente conserva los enlaces simbólicos y los permisos de archivo. El modo TAR también puede resultar en transferencias más rápidas para directorios que contienen muchos archivos pequeños, ya que se puede usar una única conexión de datos en lugar de una conexión de datos FTP para cada archivo pequeño. La desventaja de usar TAR es que fuerza la descarga de todo el directorio, incluso si ya ha descargado una parte de él anteriormente, por lo que es posible que desee usar esta opción si desea reanudar la descarga de un directorio.
jobs
Muestra la lista de tareas en segundo plano de NcFTP que se están ejecutando actualmente. Esto en realidad solo ejecuta ncftpbatch -l por usted.
lcd
El comando lcd es el primero de varios comandos "l" que funcionan con el host local. Este cambia el directorio de trabajo actual en el host local. Si desea descargar archivos en un directorio local diferente, podría usar lcd para cambiar a ese directorio y luego realizar sus descargas.
lchmod
Ejecuta ``/bin/chmod'' en el host local.
lls
Otro comando local que resulta útil es el comando lls, que ejecuta ``/bin/ls'' en el host local y muestra los resultados en la ventana del programa. Puede usar las mismas opciones con lls que usaría en su shell de comandos, por lo que puede hacer cosas como:

lcd ~/doc
lls -lrt p*.txt

lmkdir
Ejecuta ``/bin/mkdir'' en el host local.
lookup
El programa también tiene una interfaz incorporada al servicio de nombres a través del comando lookup. Esto significa que puede buscar entradas para hosts remotos, como:

lookup cse.unl.edu ftp.cs.unl.edu sphygmomanometer.unl.edu

imprime:

cse.unl.edu               129.93.33.1
typhoon.unl.edu           129.93.33.24
sphygmomanometer.unl.edu  129.93.33.126

También hay una opción más detallada, habilitada con ``-v,'' es decir:

lookup -v cse.unl.edu ftp.cs.unl.edu

imprime:

cse.unl.edu:
    Name:     cse.unl.edu
    Address:  129.93.33.1
ftp.cs.unl.edu:
    Name:     typhoon.unl.edu
    Alias:    ftp.cs.unl.edu
    Address:  129.93.33.24

También puedes dar direcciones IP, así que esto también funcionaría:

lookup 129.93.33.24

imprime:

typhoon.unl.edu           129.93.33.24

lpage
Muestra un archivo local página por página, con su programa $PAGER preferido.
lpwd
Imprime el directorio local actual. Utilice este comando cuando olvide dónde se encuentra en su máquina local.
lrename
Ejecuta ``/bin/mv'' en el host local.

COMMAND REFERENCE

lrm
Ejecuta ``/bin/rm'' en el host local.
lrmdir
Ejecuta ``/bin/rmdir'' en el host local.
ls
Imprime una lista de directorios del sistema remoto. Intenta comportarse como el comando ``/bin/ls -CF'' de UNIX. Si el servidor remoto parece ser un host UNIX, también puedes usar las mismas opciones que usarías con ls, por ejemplo

ls -rt

intentaría comportarse como

/bin/ls -CFrt

lo haría en UNIX.
ncftp tiene un potente sistema incorporado para manejar listas de directorios. Intenta almacenar en caché cada una, por lo que si lista el mismo directorio, lo más probable es que se muestre instantáneamente. Detrás de escena, ncftp siempre intenta una lista larga y luego la reformatea según sea necesario. Así que incluso si tu primera lista de un directorio fue un ``ls'' normal que mostró los archivos en columnas, tu próxima lista podría ser ``ls -lrt'' y ncftp aún usaría la lista de directorios en caché para mostrar rápidamente la información para ti!
mkdir
Crea un nuevo directorio en el host remoto. Para muchos archivos públicos, no tendrás los permisos de acceso adecuados para hacerlo.
open
Establece una conexión de control FTP a un host remoto. Por defecto, ncftp inicia sesión de forma anónima en el host remoto. Puede que desees usar una cuenta de usuario específica al iniciar sesión, para que puedas usar la opción ``-u'' para especificar qué usuario. Este ejemplo muestra cómo abrir el host ``bowser.nintendo.co.jp'' usando el nombre de usuario ``mario'':

open -u mario bowser.nintendo.co.jp

Aquí hay una lista de opciones disponibles para usar con el comando open:
-u XX Usa el nombre de usuario XX en lugar de anónimo.
-p XX Usa la contraseña XX con el nombre de usuario.
-j XX Usa la cuenta XX además del nombre de usuario y la contraseña (obsoleto).
-P XX Usa el número de puerto XX en lugar del puerto de servicio FTP predeterminado (21).
page
Navega un archivo remoto página por página, usando tu programa $PAGER. Esto es útil para leer README en el host remoto sin descargarlos primero.
pdir y pls
Estos comandos son equivalentes a dir y ls respectivamente, solo que alimentan su salida a tu paginador. Estos comandos son útiles si la lista de directorios se desplaza fuera de tu pantalla.
put
Copia archivos desde el host local al directorio de trabajo actual de la máquina remota. Para colocar una copia de ``xx.zip'' y ``yy.zip'' en el directorio remoto, podrías intentar:

put xx.zip yy.zip

También podrías lograr eso usando una expresión comodín, como:

put *.zip

Este comando es similar al comportamiento del comando mput de otros programas FTP. Para enviar un archivo remoto pero darle un nombre diferente en tu host, puedes usar la opción ``-z''. Este ejemplo muestra cómo subir un archivo llamado ``ncftpd-2.0.6.tar.gz'' pero nombrarlo remotamente como ``NFTPD206.TGZ'':

put -z ncftpd-2.0.6.tar.gz NFTPD206.TGZ

El programa no intenta ``reanudar'' las cargas por defecto. Si quieres reanudar una carga, usa la opción ``-z''.
También hay momentos en los que quieres añadir contenido a un archivo remoto existente. Puedes hacerlo usando la opción ``-A'', por ejemplo

put -A log11.txt

añadiría contenido a un archivo llamado ``log11.txt'' si existiera en el servidor remoto.
Otra cosa que puedes hacer es eliminar un archivo local después de subirlo. Usa la opción doble D, como ``put -DD'' para hacer esto.
El comando put también te permite enviar árboles de directorios completos. Debería funcionar en todos los sistemas remotos, por lo que puedes probar ``put -R'' con un directorio para subir el directorio y su contenido.
pwd
Imprime el directorio de trabajo remoto actual. Una parte de la ruta también se muestra en el prompt de la shell.
quit
Por supuesto, cuando termines de usar el programa, escribe quit para finalizar el programa (También podrías usar bye, exit, o ^D).
quote
Esto se puede usar para enviar un comando directo del Protocolo FTP al servidor remoto. Generalmente esto no es muy útil para el usuario promedio.
rename
Si necesitas cambiar el nombre de un archivo remoto, puedes usar el comando rename, como:

rename SPHYGMTR.TAR sphygmomanometer-2.3.1.tar

rhelp
Envía una solicitud de ayuda al servidor remoto. A menudo se imprime la lista de comandos del Protocolo FTP, y a veces alguna otra información que es realmente útil, como cómo contactar al administrador del sitio.
Dependiendo del servidor remoto, también puedes darle un parámetro al servidor, como:

rhelp NLST

Un servidor respondió:

Sintaxis: NLST [ <espacio> nombre-ruta ]

rm
Si necesitas eliminar un archivo remoto, puedes intentar el comando rm. La mayoría de las veces esto no funcionará porque no tendrás los permisos de acceso adecuados. Este comando no acepta ninguna opción, por lo que no puedes eliminar un árbol completo usando opciones ``-rf'' como puedes hacer en UNIX.
rmdir
De manera similar, el comando rmdir elimina un directorio. Dependiendo del servidor remoto, es posible que puedas eliminar un directorio no vacío, así que ten cuidado.
set
Esto te permite configurar algunas variables del programa, que se guardan entre ejecuciones en el archivo $HOME/.ncftp/prefs. La sintaxis básica es:

set <opción> <valor>

Por ejemplo, para cambiar el valor que usas para la contraseña anónima, podrías hacer:

set anon-password devnull@example.com

Consulta la siguiente sección para ver una lista de cosas que puedes cambiar.
show
Esto te permite mostrar las variables del programa. Puedes hacer ``show all'' para mostrar todas ellas, o dar un nombre de variable para mostrar solo esa, como:

show anon-password

site
Un comando poco común que podrías tener que usar algún día es site. El Protocolo FTP permite comandos ``específicos del sitio''. Estos comandos ``site'' varían, por supuesto, como:

site chmod 644 README

En realidad, el comando chmod de ncftp hace realmente lo anterior.
Intenta hacer uno de estos para ver qué admite el servidor remoto, si es que alguno:

rhelp SITE
site help

type
Es posible que necesites cambiar los tipos de transferencia durante una sesión con un servidor. Puedes usar el comando type para hacer esto. Intenta uno de estos:

type ascii
type binary
type image

El comando ascii es equivalente a ``type a'', y el comando binary es equivalente a ``type i'' y ``type b''.
umask
Establece el umask del proceso en el servidor remoto, si este tiene algún concepto de umask, es decir:

umask 077

Sin embargo, este no es un comando estándar, por lo que los servidores FTP remotos pueden no admitirlo.
version
Este comando muestra información sobre la edición particular del programa que estás utilizando y cómo se instaló en tu sistema.

REFERENCIA DE VARIABLES

anon-password
Especifica qué usar como contraseña al iniciar sesión de forma anónima. La convención de Internet ha sido usar tu dirección de correo electrónico como cortesía para el administrador del sitio. Si cambias esto, ten en cuenta que algunos sitios requieren (es decir, verifican) direcciones de correo electrónico válidas.
auto-resume
NcFTP 3 ahora pregunta al usuario por defecto cuando intentas descargar un archivo que ya existe localmente, o subir un archivo que ya existe remotamente. Las versiones anteriores del programa adivinaban automáticamente si sobrescribir el archivo existente o intentar reanudar donde lo dejó, pero a veces el programa adivinaba mal. Si prefieres que el programa adivine siempre qué acción tomar, establece esta variable a yes, de lo contrario, déjala en no y el programa te preguntará qué acción tomar.
auto-ascii
Si se establece en una lista de extensiones delimitadas por el carácter de barra vertical, los archivos con estas extensiones se enviarán en modo ASCII incluso si el modo binario está activo. Esta opción te permite transferir la mayoría de los archivos en binario, con la excepción de algunos tipos de archivos bien conocidos que deben enviarse en ASCII. Esta opción está habilitada por defecto y se establece en una lista de extensiones comunes (por ejemplo, .txt y .html).
autosave-bookmark-changes
Con la llegada de la versión 3 de NcFTP, el programa trata los marcadores más como lo harías con tu navegador web, lo que significa que una vez que marcas el sitio, el directorio remoto es estático. Si estableces esta variable a yes, entonces el programa actualizará automáticamente el directorio remoto de inicio del marcador con el directorio en el que te encuentres.

NAME

ncftp - an advanced, easy-to-use, and scriptable FTP client.

SYNOPSIS

ncftp [-d debug_level] [-f rcfile] [-F] [-h] [-V] [-v] [-u] [-P port] [-p proxy] [-t timeout] [-u] [-V] [-X] [hostname] [path]

DESCRIPTION

NcFTP is an advanced, interactive FTP client. It is designed to be easier to use and more powerful than the standard FTP client found in most UNIX operating systems. NcFTP supports automatic downloading of files, automatic uploading of directories, bookmarking, command-line editing, directory name completion, and more.

The hostname and path arguments can be used to specify the FTP server and the directory to connect to. If not specified, NcFTP will start without connecting to any server.

NcFTP has a built-in help system. Type help at the NcFTP prompt to get a list of available commands.

OPTIONS

-d debug_level
Sets the debugging level. Higher values produce more output.
-f rcfile
Specifies an alternative configuration file.
-F
Don't try to download any files.
-h
Display a help message and exit.
-V
Display version information and exit.
-v
Verbose mode. Enables more informative messages.
-u
Force login as anonymous user.
-P port
Connect to the specified port number on the remote host.
-p proxy
Use the specified proxy server.
-t timeout
Set the connection timeout to timeout seconds.
-X
Use passive mode for data connections.

FILES

~/.ncftp/rc
User-specific configuration file.
/etc/ncftp/ncftp.conf
System-wide configuration file.

ENVIRONMENT

NcFTP recognizes the following environment variables:

FTP_HOST
Default FTP host.
FTP_USER
Default FTP username.
FTP_PASS
Default FTP password.

BUGS

Please report bugs to the NcFTP bug tracking system at http://bugs.ncftp.com/.
