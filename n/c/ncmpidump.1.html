ncmpidump(1) PnetCDF utilities ncmpidump(1)

NOMBRE

ncmpidump - Convierte archivos netCDF a formato ASCII (CDL)

SINOPSIS

ncmpidump [-ch] [-v var1,...] [-b lang] [-f lang] [-l len] [-n name] [-p f_digits[,d_digits]] archivo

ncmpidump -k archivo

DESCRIPCIÓN

ncmpidump genera una representación ASCII de un archivo netCDF especificado en la salida estándar. La representación ASCII tiene un formato llamado CDL (``network Common Data form Language'') que puede ser visto, editado o utilizado como entrada para ncmpigen. ncmpigen es un programa complementario que puede generar un archivo netCDF binario a partir de un archivo CDL. Por lo tanto, ncmpigen y ncmpidump pueden usarse de forma inversa para transformar la representación de datos entre representaciones binarias y ASCII. Consulte ncmpigen para obtener una descripción de CDL y las representaciones netCDF.

ncmpidump también puede usarse para determinar qué tipo de archivo netCDF se utiliza (qué variante del formato de archivo netCDF) con la opción -k.

ncmpidump define un formato predeterminado utilizado para cada tipo de dato netCDF, pero esto puede cambiarse si se define un atributo `C_format' para una variable netCDF. En este caso, ncmpidump usará el atributo `C_format' para formatear cada valor. Por ejemplo, si se sabe que los datos de punto flotante para la variable netCDF `Z' solo son precisos hasta tres dígitos significativos, sería apropiado usar el atributo de variable

Z:C_format = "%.3g"

ncmpidump también puede usarse como un simple navegador para archivos de datos netCDF, para mostrar los nombres y tamaños de las dimensiones; los nombres, tipos y formas de las variables; los nombres y valores de los atributos; y opcionalmente, los valores de los datos para todas las variables o variables seleccionadas en un archivo netCDF.

ncmpidump usa `_' para representar valores de datos que son iguales a `_FillValue', un atributo para una variable, destinado a representar datos que aún no han sido escritos. Si una variable no tiene un atributo `_FillValue', se usará el valor de relleno predeterminado para el tipo de la variable si la variable no es de tipo byte.

OPCIONES

-c
Muestra los valores de las variables de coordenada (variables que también son dimensiones) así como las declaraciones de todas las dimensiones, variables y valores de atributos. Los valores de datos de las variables no coordinadas no se incluyen en la salida. Esta es la opción más adecuada para una vista rápida de la estructura y contenido de un archivo netCDF.
-h
Muestra solo la información de la cabecera en la salida, es decir, las declaraciones de dimensiones, variables y atributos, pero ningún valor de dato para ninguna variable. La salida es idéntica a usar la opción -c, excepto que los valores de las variables de coordenada no se incluyen. (Como máximo, se puede presentar una de las opciones -c o -h.)
-v var1,...,varn
La salida incluirá los valores de datos para las variables especificadas, además de las declaraciones de todas las dimensiones, variables y atributos. Se debe especificar una o más variables por nombre en la lista separada por comas que sigue a esta opción. La lista debe ser un único argumento para el comando, por lo tanto, no puede contener espacios u otros caracteres de espacio en blanco. Las variables nombradas deben ser variables netCDF válidas en el archivo de entrada. El valor predeterminado, sin esta opción y en ausencia de las opciones -c o -h, es incluir los valores de datos para todas las variables en la salida.
-b lang
Una breve anotación en forma de comentario CDL (texto que comienza con los caracteres ``//'') se incluirá en la sección de datos de la salida para cada `fila' de datos, para ayudar a identificar los valores de datos para variables multidimensionales. Si lang comienza con `C' o `c', se usarán convenciones del lenguaje C (índices basados en cero, última dimensión variando más rápido). Si lang comienza con `F' o `f', se usarán convenciones del lenguaje Fortran (índices basados en uno, primera dimensión variando más rápido). En cualquier caso, los datos se presentarán en el mismo orden; solo las anotaciones diferirán. Esta opción es útil para navegar a través de grandes volúmenes de datos multidimensionales.
-f lang
Anotaciones completas en forma de comentarios CDL finales (texto que comienza con los caracteres ``//'') para cada valor de dato (excepto caracteres individuales en arreglos de caracteres) se incluirán en la sección de datos. Si lang comienza con `C' o `c', se usarán convenciones del lenguaje C (índices basados en cero, última dimensión variando más rápido). Si lang comienza con `F' o `f', se usarán convenciones del lenguaje Fortran (índices basados en uno, primera dimensión variando más rápido). En cualquier caso, los datos se presentarán en el mismo orden; solo las anotaciones diferirán. Esta opción puede ser útil para canalizar datos a otros filtros, ya que cada valor de dato aparece en una línea separada, completamente identificado.
-l len
Cambia la longitud máxima de línea predeterminada (80) utilizada en el formateo de listas de valores de datos no caracteres.
-n name
CDL requiere un nombre para un conjunto de datos netCDF, para ser usado por ncmpigen -b para generar un nombre de archivo netCDF predeterminado. Por defecto, ncmpidump construye este nombre a partir del último componente de la ruta del archivo netCDF de entrada, eliminando cualquier extensión que tenga. Use la opción -n para especificar un nombre diferente. Aunque el nombre del archivo de salida utilizado por ncmpigen -b puede especificarse, puede ser prudente hacer que ncmpidump cambie el nombre predeterminado para evitar sobrescribir inadvertidamente un archivo netCDF valioso al usar ncmpidump, editar el archivo CDL resultante y usar ncmpigen -b para generar un nuevo archivo netCDF a partir del CDL editado.
-p float_digits[,double_digits]
Especifica la precisión predeterminada (número de dígitos significativos) a utilizar al mostrar valores de datos de punto flotante o de doble precisión para atributos y variables. Si se especifica, este valor anulará el valor del atributo `C_format' para cualquier variable que tenga dicho atributo. Los datos de punto flotante se mostrarán con float_digits dígitos significativos. Si también se especifica double_digits, los valores de doble precisión se mostrarán con esa cantidad de dígitos significativos. En ausencia de cualquier especificación de -p, los datos de punto flotante y de doble precisión se muestran con 7 y 15 dígitos significativos respectivamente. Los archivos CDL pueden ser más pequeños si se requiere menos precisión. Si se especifican ambas precisiones, la de punto flotante y la de doble precisión, los dos valores deben aparecer separados por una coma (sin espacios) como un único argumento para el comando. Si realmente desea que se represente hasta el último bit de precisión del archivo netCDF en el archivo CDL para todos los valores de punto flotante posibles, deberá especificarlo con -p 9,17 (según el Teorema 15 del artículo listado en REFERENCIAS).
-k
Informa el tipo de archivo netCDF: clásico, offset 64-bit o datos 64-bit. Antes de la versión 3.6 de netCDF, solo existía un tipo de archivo netCDF, designado como `clásico' (también conocido como variante de formato 1 o CDF-1). El soporte para archivos grandes introdujo otra variante del formato, designada como `offset 64-bit' (conocida como variante de formato 2 o CDF-2). El soporte para datos grandes introdujo otra variante del formato, designada como `datos 64-bit' (conocida como variante de formato 5 o CDF-5).

EJEMPLOS

Observe la estructura de los datos en el archivo netCDF `foo.nc':

ncmpidump -c foo.nc

Genere una versión CDL anotada de la estructura y los datos en el archivo netCDF `foo.nc', usando indexación estilo C para las anotaciones:

ncmpidump -b c foo.nc > foo.cdl

Muestre los datos solo para las variables `uwind' y `vwind' del archivo netCDF `foo.nc', y muestre los datos de punto flotante con solo tres dígitos significativos de precisión:

ncmpidump -v uwind,vwind -p 3 foo.nc

Genere una lista de datos completamente anotada (un valor de dato por línea) para la variable `omega', usando convenciones Fortran para los índices, y cambiando el nombre netCDF

Para especificar el nombre del conjunto de datos en el archivo CDL resultante como `omega':

ncmpidump -v omega -f fortran -n omega foo.nc > Z.cdl

ERRORES

Los arreglos de caracteres que contienen un byte nulo se tratan como cadenas C, por lo que ningún carácter después del byte nulo aparecerá en la salida.

Los arreglos multidimensionales de cadenas de caracteres no se manejan bien, ya que la sintaxis CDL para dividir una cadena de caracteres larga en varias líneas más cortas es débil.

Debería haber una forma de especificar que los datos se muestren en orden de 'registro', es decir, con todos los valores de las variables de 'registro' juntos que tienen el mismo valor de la dimensión de registro.
