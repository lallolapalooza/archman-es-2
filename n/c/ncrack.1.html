NOMBRE

ncrack - Herramienta de cracking de autenticación de red

SINOPSIS

ncrack [Opciones] { *especificación del objetivo* }

DESCRIPCIÓN

Ncrack es una herramienta de código abierto para el cracking de autenticación de red. Fue diseñado para cracking paralelo de alta velocidad utilizando un motor dinámico que puede adaptarse a diferentes situaciones de red. Ncrack también se puede ajustar de forma extensiva para casos especiales, aunque los parámetros predeterminados son lo suficientemente genéricos como para cubrir casi todas las situaciones. Está construido sobre una arquitectura modular que permite una fácil extensión para admitir protocolos adicionales. Ncrack está diseñado para empresas y profesionales de la seguridad para auditar redes grandes en busca de contraseñas predeterminadas o débiles de manera rápida y confiable. También se puede utilizar para realizar ataques de fuerza bruta bastante sofisticados e intensivos contra servicios individuales.


Advertencia

Ncrack es un proyecto iniciado en el verano de 2009. Si bien ya es útil para algunos propósitos, todavía es software incompleto y de calidad beta. Puedes ayudar probándolo e informando cualquier problema como se describe en la sección llamada "BUGS".

La salida de Ncrack es una lista de credenciales encontradas, si las hay, para cada uno de los objetivos especificados. Ncrack también puede imprimir un informe interactivo del progreso hasta el momento y posiblemente información de depuración adicional que pueda ayudar a rastrear problemas, si el usuario seleccionó esa opción.

Un escaneo típico de Ncrack se muestra en el Ejemplo 1. Los únicos argumentos de Ncrack utilizados en este ejemplo son las dos direcciones IP de destino junto con los puertos correspondientes para cada una de ellas. Los dos puertos de ejemplo 21 y 22 se resuelven automáticamente a los servicios predeterminados que se escuchan en ellos: ftp y ssh.

ESPECIFICACIÓN DEL OBJETIVO

Todo lo que no sea una opción (o argumento de opción) en la línea de comandos de Ncrack se trata como una especificación de host de destino. El caso más simple es especificar una dirección IP de destino o un nombre de host. Tenga en cuenta que también debe especificar un servicio para intentar descifrar para los objetivos seleccionados. Ncrack es muy flexible en la especificación de hosts/servicios. Si bien los nombres de host y las direcciones IP se pueden definir con la flexibilidad a la que probablemente esté acostumbrado de Nmap, los servicios junto con las opciones específicas del servicio tienen un estilo de especificación único que permite aprovechar una combinación de características.

A veces, deseará descifrar una red completa de hosts adyacentes. Para esto, Ncrack admite la dirección en estilo CIDR. Puede agregar /numbits a una dirección IPv4 o nombre de host y Ncrack intentará descifrar cada dirección IP para la que los primeros numbits sean los mismos que para la IP o nombre de host de referencia dados. Por ejemplo, 192.168.10.0/24 enviaría sondas a los 256 hosts entre 192.168.10.0 (binario: 11000000 10101000 00001010 00000000) y 192.168.10.255 (binario: 11000000 10101000 00001010 11111111), ambos inclusive. 192.168.10.40/24 descifraría exactamente los mismos objetivos. Dado que el host scanme.nmap.org se encuentra en la dirección IP 64.13.134.52, la especificación scanme.nmap.org/16 enviaría sondas a los 65,536 direcciones IP entre 64.13.0.0 y 64.13.255.255. El valor más pequeño permitido es /0, que apunta a toda Internet. El valor más grande es /32, que apunta solo al host o dirección IP nombrada porque todos los bits de la dirección están fijados.

La notación CIDR es corta pero no siempre lo suficientemente flexible. Por ejemplo, es posible que desee enviar sondas a 192.168.0.0/16 pero omitir cualquier IP que termine en .0 o .255 porque pueden usarse como direcciones de red y difusión de subred. ESPECIFICACIÓN DE OBJETIVOS

Por defecto, Ncrack intentará auditar un único objetivo, el especificado en la línea de comandos. Se puede especificar una lista de objetivos de varias maneras:

Hostname
Se puede proporcionar un nombre de host, como scanme.nmap.org. Ncrack lo resolverá a una dirección IP y auditará ese host.
Dirección IP
Se puede proporcionar una dirección IP en formato decimal punteado, como 192.168.0.1.
Rango de octetos
Se puede especificar rangos de direcciones IP. Por ejemplo, 192.168.0-255.1-254 omitirá todas las direcciones en el rango que terminen en .0 o .255, y 192.168.3-5,7.1 apuntará a las cuatro direcciones 192.168.3.1, 192.168.4.1, 192.168.5.1 y 192.168.7.1. Se puede omitir cualquiera de los lados de un rango; los valores predeterminados son 0 a la izquierda y 255 a la derecha. Usar - por sí solo es lo mismo que 0-255, pero recuerda usar 0- en el primer octeto para que la especificación del objetivo no parezca una opción de línea de comandos. Los rangos no tienen por qué limitarse a los octetos finales: el especificador enviará sondeos a todas las direcciones IP en Internet que terminen en 13.37. Este tipo de muestreo amplio puede ser útil para encuestas e investigaciones en Internet.
Notación CIDR
Ncrack admite la notación CIDR (Classless Inter-Domain Routing) para especificar rangos de direcciones. Por ejemplo, 192.168.0.0/24 se dirigirá a todos los hosts de la subred 192.168.0.0 a 192.168.0.255.

Ncrack acepta múltiples especificaciones de host en la línea de comandos, y no necesitan ser del mismo tipo. El comando ncrack scanme.nmap.org 192.168.0.0/8 10.0.0,1,3-7.- -p22 hace lo que esperarías.

Si bien los objetivos generalmente se especifican en las líneas de comandos, las siguientes opciones también están disponibles para controlar la selección de objetivos:

-iX nombrearchivoentrada (Entrada del formato de salida XML de Nmap).

Lee las especificaciones de objetivos/servicios de un archivo de salida XML de Nmap. El archivo XML de Nmap se crea escaneando hosts y especificando la opción -oX de Nmap. Ncrack analizará automáticamente las direcciones IP y los puertos y servicios correspondientes que estén *abiertos* y utilizará estos objetivos para la auditoría de autenticación. Esta es una opción realmente útil, ya que permite combinar estas dos herramientas, Nmap y Ncrack, para crackear solo aquellos servicios que están seguros de estar abiertos. Además, si se ha habilitado la detección de versiones en Nmap (opción -sV), Ncrack utilizará esos hallazgos para reconocer y crackear aquellos servicios que son compatibles pero que están escuchando en puertos no predeterminados. Por ejemplo, si un host tiene un servidor escuchando en el puerto 41414 y Nmap ha identificado que es un servicio SSH, Ncrack usará esa información para crackearlo usando el módulo SSH. Por supuesto, Ncrack ignorará los puertos/servicios abiertos que no sean compatibles con el cracking de autenticación por sus módulos.

-iN nombrearchivoentrada (Entrada del formato de salida Normal de Nmap).

Lee las especificaciones de objetivos/servicios de un archivo de salida Normal de Nmap. El archivo Normal de Nmap se crea escaneando hosts y especificando la opción -oN de Nmap. Esto funciona exactamente como la opción -iX de Ncrack, la única diferencia es el formato del archivo de entrada.

-iL nombrearchivoentrada (Entrada de lista).

Lee las especificaciones de objetivos del archivo nombrearchivoentrada. Pasar una gran lista de hosts a menudo es incómodo en la línea de comandos, sin embargo, es un deseo común. Por ejemplo, es posible que desees crackear una lista de servidores muy específicos que se han especificado para pruebas de penetración. Simplemente genera la lista de hosts a crackear y pasa ese nombre de archivo a Ncrack como argumento de la opción -iL. Las entradas pueden estar en cualquiera de los formatos aceptados por Ncrack en la línea de comandos (dirección IP, nombre de host, CIDR, rangos de octetos o la sintaxis especial de host-servicio de Ncrack. Cada entrada debe estar separada por uno o más espacios, tabulaciones o saltos de línea. Puedes especificar un guion (-) como nombre de archivo si deseas que Ncrack lea los hosts de la entrada estándar en lugar de un archivo real. Ten en cuenta, sin embargo, que si los hosts se especifican sin ningún servicio, deberás proporcionar también servicios/puertos para los objetivos usando la opción -p.

--exclude host1[, host2[, ...]] (Excluir hosts/redes).

Especifica una lista separada por comas de objetivos a excluir del escaneo, incluso si forman parte del rango general de red que especificas. La lista que pasas utiliza la sintaxis normal de Ncrack, por lo que puede incluir nombres de host, bloques de red CIDR, rangos de octetos, etc. Esto puede ser útil cuando la red que deseas escanear incluye servidores críticos de misión intocables, sistemas que se sabe que reaccionan negativamente a cargas pesadas, o subredes administradas por otras personas.

--excludefile archivoexclusión (Lista de exclusión de archivo).

Esto ofrece la misma funcionalidad que la opción --exclude, excepto que los objetivos excluidos se proporcionan en un archivo archivoexclusión delimitado por saltos de línea, espacios o tabulaciones en lugar de en la línea de comandos.

ESPECIFICACIÓN DE SERVICIO

Ninguna sesión de cracking se puede llevar a cabo sin apuntar a un servicio determinado para atacar. La especificación de servicio es uno de los subsistemas más flexibles de Ncrack y colabora con la especificación de objetivos de manera que permite aplicar diferentes combinaciones de opciones. Para que Ncrack comience a ejecutarse, deberás especificar al menos un host objetivo y un servicio asociado para atacar. Ncrack proporciona formas de especificar un servicio por su número de puerto predeterminado, por su nombre (tal como se extrae del archivo ncrack-services) o ambos. Normalmente, solo necesitas definir el nombre y el número de puerto en el caso especial en que sepas que un servicio en particular está escuchando en un puerto no predeterminado.

Ncrack ofrece dos formas distintas de aplicar los servicios a tus objetivos: especificación de servicio por host y especificación global.

Especificación de servicio por host

Los servicios especificados en este modo se escriben junto al host y se aplican solo a él. Ten en cuenta, sin embargo, que la especificación de objetivos permite comodines/máscaras de red, lo que significa esencialmente que aplicar un formato de especificación de servicio por host a ese objetivo en particular afectará a todos los expandidos como resultado. El formato general es:

[nombre-servicio]://objetivo:[número-puerto]

donde objetivo es un nombre de host o dirección IP en cualquiera de los formatos descritos en la sección de especificación de objetivos, [nombre-servicio] es uno de los nombres de servicio comunes definidos en el archivo ncrack-services (por ejemplo, ssh, http) y [número-puerto] es lo que obviamente significa. Ncrack puede determinar los números de puerto predeterminados para cada uno de los servicios que soporta, así como deducir el nombre del servicio cuando se ha especificado un número de puerto predeterminado. Especificar ambos solo tiene sentido cuando el usuario tiene conocimiento previo de un servicio escuchando en un número de puerto no predeterminado. Esto se puede determinar fácilmente utilizando la detección de versiones como la que ofrece la opción -sV de Nmap.

Ejemplo 2. Ejemplo de especificación de servicio por host

$ ncrack scanme.nmap.org:22 ftp://10.0.0.10 ssh://192.168.1.*:5910

El comando anterior intentará crackear los hosts: scanme.nmap.org en el servicio SSH (puerto predeterminado 22), 10.0.0.10 en el servicio FTP (puerto predeterminado 21) y 192.168.1.0 - 192.168.1.255 (toda esta subred C) en el servicio SSH en el puerto no predeterminado 5910 que se ha especificado explícitamente. En este último caso, Ncrack no podría determinar que los hosts de la subred se escanearán contra el servicio SSH en ese puerto en particular sin que el usuario lo solicite explícitamente, ya que no hay ningún mapeo del número de puerto 5910 al servicio SSH.

Especificación global de servicio

Los servicios especificados en este modo se aplican a *todos* los hosts que no se han asociado con el formato de especificación de servicio por host. Esto se hace usando la opción -p. Si bien esta función puede ser similar a la de Nmap, debes intentar no confundirla, ya que la funcionalidad es de naturaleza ligeramente diferente. Los servicios se pueden especificar usando directivas separadas por comas del formato general:

-p [servicio1]:[número-puerto1],[servicio2]:[número-puerto2],...

Como de costumbre, no necesitas especificar el nombre del servicio y el número de puerto, ya que Ncrack conoce los mapeos de los servicios predeterminados a los números de puerto predeterminados. Ten cuidado de no incluir ningún espacio entre cada nombre de servicio y/o número de puerto, ya que Ncrack pensará que el argumento después del espacio es un objetivo según la regla "todo lo que no sea una opción es una especificación de objetivo".

Ejemplo 3. Ejemplo de especificación global de servicio

$ ncrack scanme.nmap.org 10.0.0.120-122 192.168.2.0/24 -p 22,ftp:3210,telnet

El comando anterior intentará crackear todos los hosts especificados scanme.nmap.org, 10.0.0.120, 10.0.0.121, 10.0.0.122 y la subred de clase C de 192.168.2.0 contra los siguientes servicios: servicio SSH (mapeado desde el puerto predeterminado 22), servicio FTP en el puerto no predeterminado 3210 y servicio TELNET en el puerto predeterminado 23.

Por supuesto, Ncrack te permite combinar ambos modos de especificación de servicio si lo consideras necesario. Normalmente, solo necesitarás especificar un par de servicios, pero crackear muchos hosts contra muchos servicios diferentes podría ser un proyecto a largo plazo para redes grandes que necesitan ser auditadas consistentemente en busca de contraseñas débiles. Si tienes dudas sobre qué hosts y servicios se crackearán con el comando actual, puedes usar la opción -sL (ver más abajo para la explicación).

OPCIONES DE SERVICIO

Aparte de la especificación general de servicio, Ncrack te permite proporcionar una multitud de opciones que se aplican a cada uno o a un subconjunto de tus objetivos. Las opciones incluyen optimizaciones de tiempo y rendimiento (que se analizan a fondo en una sección separada), habilitación/deshabilitación de SSL y otros parámetros específicos del módulo, como la ruta URL relativa para el módulo HTTP. Las opciones se pueden definir de varias maneras, que incluyen: opciones por host, opciones por módulo y opciones globales. Dado que se puede utilizar una combinación de estas opciones, existe una jerarquía estricta de precedencia que se discutirá más adelante.

Opciones por Host

Las opciones en este modo se aplican solo al(los) host(s) a los que se refieren y se escriben junto a él según el siguiente formato:

[nombre-servicio]://objetivo:[número-puerto],opt1=valopt1,opt2=valopt,...

El formato relativo a la especificación del servicio que precede a las opciones se ha explicado en la sección anterior. optN se refiere a cualquiera de los nombres de opción disponibles (seguirá una lista a continuación), mientras que valoptN determina el valor de esa opción y depende de su naturaleza. Por ejemplo, la mayoría de las opciones relacionadas con el tiempo esperan recibir números como valores, mientras que la opción path obviamente necesita un argumento de cadena.

Opciones por Módulo

Las opciones en este modo se aplican a todos los hosts que están asociados con el servicio/módulo en particular. Esto se logra usando -m que se define con el formato:

-m servicio-

SERVICE OPTIONS

Ncrack supports both service-specific and global options that can be used to fine-tune the scanning process. Options can be specified in one of three modes:

Per-host Options

This is the most specific mode. Options are specified directly after the target hostname or IP address, separated by a comma. The format is as follows:

hostname:portopt1=optval1,opt2=optval2,...

This option can be invoked multiple times, for as many different services as you might need to define service-wide applicable options. Each iteration of this option must refer to only one service. However, to avoid confusion, this option had better not be called more than one time for the same service, although this is allowed and the last iteration will take precedence over the previous ones for all redefined option values.

Global Options

Options in this mode apply to all hosts regardless of which service they are associated with. This is accomplished using the -g as follows:

-g opt1=optval1,opt2=optval2,...

This acts as a convenience option, where you can apply options to all services globally. Everything else regarding the available options and option values is the same as the previous modes.

List of available Service Options

Below follows a list of all the currently available service options. You can apply them with any of the three modes described above. The last six of the options are timing related and will be analyzed in Section "Timing and Performance" of this manual.

ssl: enable SSL over this service
path: path-name used in modules like HTTP (´=´ needs escaping if used)
db: used in modules like MongoDB to specify the database
domain: used in modules like WinRM to specify the domain
cl (min connection limit): minimum number of concurrent parallel connections
CL (max connection limit): maximum number of concurrent parallel connections
at (authentication tries): authentication attempts per connection
cd (connection delay): delay time between each connection initiation
cr (connection retries): caps number of service connection attempts
to (time-out): maximum cracking time for service, regardless of success so far

ssl (Enable/Disable SSL over service)

By enabling SSL, Ncrack will try to open a TCP connection and then negotiate a SSL session with the target. Everything will then be transparently encrypted and decrypted. However, since Ncrack´s job is to provide speed rather than strong crypto, the algorithms and ciphers for SSL are chosen on an efficiency basis. Possible values for this option are ´yes´ but just specifying ssl would be enough. Thus, this is the only option that doesn´t need to be written in the opt=optval format. By default, SSL is disabled for all services except those that are stricly dependent on it like HTTPS.

path <name> (Path name for relative URLs)

Some services like HTTP or SVN usually require a specific path in the URL. This option takes that pathname string as its value. The path is always relative to the hostname or IP address, so if you want to target something like http://foobar.com/login.php the path must take the value path=login.php . The initial ´/´ is added if you omit it. However, it is usually better if you explicitly specify it at the end of pathnames that are directories. For example, to crack the directory for http://foobar.com/protected-dir/ , it would be better if you wrote it as path=protected-dir/ . This is to avoid the (very) slight probability of a false positive, because there are cases where Web servers might reply with a "301 Moved Permanently" for a non-successful attempt. They normally send that reply, when a successful attempt is made for a requested password-protected path which has omitted the ending ´/´ but the requested source is actually a directory. Consequently, Ncrack regards that reply as having succeeded in the authentication attempt.

Also be careful with the symbol ´=´, since it is used by Ncrack for argument parsing and you will have to espace it if it is included in the URL.

By default, the path-name is initialized to ´/´, but will be ignored by services that do not require it.

db <name> (Database name)

Some services like MongoDB require a specific database name to crack. This option allows you to specify the database.

By default, the db name for MongoDB is initialized to ´admin´ but will be ignored by services that do not require it.

domain <name> (Domain name)

Some services like WinRM require a specific domain to crack. This option allows you to specify the domain.

By default, the domain name for WinRM is initialized to ´Workstation´ but will be ignored by services that do not require it.

Service Option Hierarchy

As already noted, Ncrack allows a combination of the three different modes of service option specification. In that case, there is a strict hierarchy that resolves the order in which conflicting values for these options take precedence over each other. The order is as follows, leftmost being the highest priority and rightmost the lowest one:

Per-host options > Per-module options > Global options > Timing-Template (for timing options only)

The concept of the "Timing-Template" will be explained in the Section "Timing and Performance", but for now, just have in mind that its values have the least prevalence over everything else and essentially act as defaults for everything timing-related. Global options specified with -g have the directly higher precedence, while -m per-module options are immediately higher. In the top of the hierarcy reside the per-host options which are essentially the most specific ones. Consequently, you can see that the pattern is: the more specific the higher the precedence.

Example 4. Service Option Hierarchy example

$ ncrack scanme.nmap.org:22,cl=10,at=1 10.0.0.120 10.0.0.20 -p 21 -m ftp:CL=1 -g CL=3

The example demonstrates the hierarchy precedence. The services that are going to be cracked are SSH for scanme.nmap.org and FTP for hosts 10.0.0.120, 10.0.0.20. No particular timing-template has been specified and thus the default will be used (Normal - 3). The per-host options for scanme.nmap.org define that the minimum connection limit (cl) is 10 and that Ncrack should attempt only 1 authentication try (at) per connection. These values would override any other for service SSH of host scanme.nmap.org if there were conflicts with other modes. Since a global option of -g CL=3 was defined and there is no other higher-precedence for service SSH and scanme.nmap.org in particular, this value will also be applied. As for the FTP targets, the per-module -m ftp:CL=1 defined for all FTP services will override the equivalent global one. All these can get quite complex if overused, but they are not expected to be leveraged by the average Ncrack user anyway. Complicated network scanning scenarios might require them, though. Se especifica en segundos por defecto, aunque puedes añadir 'ms', 'm' o 'h' al valor para especificar milisegundos, minutos u horas ('s' para segundos es redundante). cl num-conexionesmin; CL num-conexionesmax (Ajustar el número de conexiones paralelas concurrentes)

Límite de Conexión

Estas opciones controlan el número total de conexiones que pueden estar pendientes para cualquier servicio al mismo tiempo. Normalmente, Ncrack intenta ajustar dinámicamente el número de conexiones para cada objetivo individual contando cuántos paquetes perdidos o fallos de conexión ocurren. Si ocurre una condición de red extraña, que indica que algo puede estar yendo mal, como que el host esté descartando todos los nuevos intentos de conexión, entonces Ncrack reducirá inmediatamente el número total de conexiones que llegan al servicio. Sin embargo, las limitaciones del número mínimo o máximo de conexiones que tendrán lugar pueden ser anuladas usando estas dos opciones. Ajustándolas adecuadamente, puedes optimizar esencialmente el rendimiento, si puedes manejar la parte complicada de saber o descubrir los propios límites de tu objetivo. La convención aquí es que cl con letras minúsculas se refiere al límite mínimo de conexión, mientras que CL con letras mayúsculas se refiere al número máximo de conexiones.

El uso más común es establecer cl (límite mínimo de conexión) para objetivos que estás casi seguro de que soportarán muchas conexiones en cualquier momento dado. Esta es una opción arriesgada con la que jugar, ya que establecerla demasiado alta podría ser más perjudicial que beneficioso al atacar efectivamente al objetivo con un ataque de denegación de servicio (DoS) y activar reglas de firewall que restrinjan tu dirección IP.

Por otro lado, para misiones más sigilosas, establecer CL (límite máximo de conexión) a un valor bajo podría ser lo que buscas. Sin embargo, establecerlo demasiado bajo seguramente tendrá un gran impacto en la velocidad general de cracking. Para máxima discreción, esto puede combinarse con el cd (retraso de conexión) descrito a continuación.

at num-intentos (Ajustar intentos de autenticación por conexión)

Intentos de Autenticación

Usando esta opción, puedes ordenar a Ncrack que limite los intentos de autenticación que lleva a cabo por conexión. Ncrack inicialmente envía una sonda de reconocimiento que le permite calcular el número máximo de tales intentos de autenticación y a partir de ahí siempre intenta usar ese número. La mayoría de los servicios imponen un límite superior al número de autenticaciones por conexión y en la mayoría de los casos encontrar ese máximo conduce a un mejor rendimiento.

Establecer esta opción a valores más bajos puede darte una bonificación de sigilo, ya que servicios como SSH tienden a registrar intentos fallidos después de un cierto número de intentos de autenticación por conexión. Utilizan eso como métrica en lugar de contar el número total de intentos de autenticación o conexiones por dirección IP (lo cual suele ser hecho por un firewall). Consecuentemente, un número de 1 o 2 intentos de autenticación podría eludir el registro en algunos casos.

Ten en cuenta que establecer esta opción a un valor alto no tendrá ningún efecto si Ncrack se da cuenta de que el servidor no permite tantos intentos por conexión. En este caso, simplemente usará ese número máximo e ignorará tu configuración.

cd tiempo (Ajustar el tiempo de retraso entre cada nueva conexión)

Retraso de Conexión

Esta opción define esencialmente el retraso impuesto entre cada nueva conexión. Ncrack esperará la cantidad de tiempo que especifiques en el valor de esta opción, antes de iniciar una nueva conexión contra el servicio dado. Cuanto más alto lo establezcas, más lento será el rendimiento de Ncrack, pero más sigiloso será tu ataque.

Ncrack por defecto intenta iniciar nuevas conexiones lo más rápido posible dado que las nuevas sondas realmente se permiten enviar y no están restringidas por parámetros como el Límite de Conexión, que puede aumentar o disminuir dinámicamente. Aunque este enfoque logra una velocidad vertiginosa siempre que el host permanezca receptivo, puede llevar a una serie de desastres como la activación de un firewall, la disminución del ancho de banda del objetivo o el tuyo, e incluso que el servicio probado sufra un ataque de denegación de servicio. Ajustando cuidadosamente esta opción, puedes potencialmente evitar estas situaciones molestas.

cr max-reintentos-conexion (Ajustar el número máximo de reintentos de conexión)

Reintentos de Conexión

Esta opción permite al usuario especificar la cantidad máxima de intentos fallidos consecutivos contra ese servicio en particular. Si en algún momento, durante la sesión de cracking, Ncrack falla al conectarse contra ese servicio en particular, entonces dejará de intentar crackearlo por completo.

to tiempo (Ajustar el tiempo máximo general de cracking)

Tiempo de Espera

Define cuánto tiempo va a pasar Ncrack intentando crackear el servicio, antes de rendirse independientemente de si ha encontrado alguna credencial hasta el momento. Sin embargo, cualquier token de autenticación descubierto hasta ese momento, se almacenará y se imprimirá normalmente. Ncrack marca un servicio como finalizado cuando se agota la iteración de listas de nombres de usuario/contraseñas o cuando ya no puede crackearlo por alguna razón seria. Si Ncrack termina de crackear un servicio antes del tiempo especificado en esta opción, entonces no se tendrá en cuenta en absoluto.

A veces, tienes una ventana de tiempo limitada para escanear/crackear tus hosts. Esto puede ocurrir por diversas razones. Una común sería que la actividad normal del usuario no debe ser interrumpida y como Ncrack puede ser muy agresivo, podría permitirse escanear los hosts solo durante un período de tiempo determinado, como las horas nocturnas. Escanear durante ciertas horas también es probable que haga un ataque menos detectable.

No olvides que Ncrack te permite especificar la unidad de tiempo añadiendo 'ms', 'm' o 'h' para milisegundos, minutos u horas (segundos es la unidad de tiempo por defecto). Usarlas en esta opción en particular es muy conveniente, ya que puedes especificar algo como to=8h para darle a Ncrack un total de 8 horas para crackear ese servicio. Configurar cronjobs para escaneos programados en combinación con esta opción también podría ser una buena idea.

-T paranoid|sneaky|polite|normal|aggressive|insane (Establecer una plantilla de tiempo).

Si bien los controles de tiempo granulares discutidos en la sección anterior son potentes y efectivos, a algunas personas les resultan confusos. Además, elegir los valores apropiados a veces puede llevar más tiempo que el escaneo que intentas optimizar. Por lo tanto, Ncrack ofrece un enfoque más sencillo, con seis plantillas de tiempo. Puedes especificarlas con la opción -T y su número (0-5) o su nombre. Los nombres de las plantillas son paranoid (0), sneaky (1), polite (2), normal (3), aggressive (4) e insane (5). Los dos primeros son para evasión de IDS. El modo polite ralentiza el escaneo para usar menos ancho de banda y recursos de la máquina objetivo. El modo normal es el predeterminado y, por lo tanto, -T3 no hace nada. El modo aggressive acelera los escaneos asumiendo que estás en una red razonablemente rápida y fiable. Finalmente, el modo insane asume que estás en una red extraordinariamente rápida o estás dispuesto a sacrificar algo de precisión por velocidad.

Estas plantillas permiten al usuario especificar cuán agresivo desea ser, dejando que Ncrack elija los valores de tiempo exactos. Si sabes que el servicio de red va a soportar un gran número de conexiones, podrías intentar usar la plantilla aggressive de -T4. Incluso así, esto se aconseja principalmente para servicios que residen en la red local. Pasar al modo insane -T5 no se recomienda, a menos que sepas absolutamente lo que estás haciendo.

Si bien -T0 y -T1 pueden ser útiles para evitar alertas de IDS, tardarán un tiempo extraordinario en crackear incluso unos pocos servicios. Para un escaneo tan largo, podrías preferir establecer los valores de tiempo exactos que necesitas en lugar de depender de los valores predefinidos de -T0 y -T1.

AUTENTICACIÓN

Esta sección describe las formas de especificar tus propias listas de nombres de usuario y contraseñas, así como los modos disponibles de iteración sobre ellas. Ncrack viene con una variedad de listas de nombres de usuario y contraseñas que residen bajo el directorio 'lists' del archivo tarball de origen y luego se instalan bajo el directorio de datos de Ncrack, que normalmente es /usr/local/share/ncrack o /usr/share/ncrack. Puedes omitir la especificación de cualquier lista y Ncrack utilizará las predeterminadas, que contienen algunos de los nombres de usuario y contraseñas más comunes. La lista de contraseñas está ordenada por frecuencia, con las contraseñas más comunes al principio de la lista, por lo que se intentarán primero. Las listas se han derivado de una combinación de ordenación de archivos de contraseñas filtrados públicamente y otras técnicas.

-U archivo (Especificar lista de nombres de usuario)

Especifica tu propia lista de nombres de usuario proporcionando la ruta al archivo como argumento a esta opción.

Los nombres de usuario para entornos específicos se pueden recopilar de numerosas maneras, incluyendo la recolección de direcciones de correo electrónico en el sitio web de la empresa, la búsqueda de información en bases de datos whois, el uso de la técnica SMTP VRFY en servidores de correo vulnerables o a través de ingeniería social.

-P archivo (Especificar lista de contraseñas)

Especifica tu propia lista de contraseñas proporcionando la ruta al archivo como argumento a esta opción.

Las contraseñas comunes suelen derivarse de listas filtradas como resultado de intrusiones exitosas en sitios públicos como foros u otros lugares de redes sociales. Una gran parte de ellas ya se han divulgado públicamente y algunas de estas se han utilizado para ensamblar las propias listas de Ncrack.

--user lista-nombres-usuario (Especificar lista de nombres de usuario separada por comas en la línea de comandos)

Especifica tus propios nombres de usuario directamente en la línea de comandos como una lista separada por comas.

--pass lista-contraseñas (Especificar lista de contraseñas separada por comas en la línea de comandos)

Especifica tus propias contraseñas directamente en la línea de comandos como una lista separada por comas.

--passwords-first (Invertir la forma en que las contraseñas

rds son iterados)

Ncrack por defecto itera la lista de nombres de usuario por cada contraseña. Con esta opción, puedes invertir eso. Por ejemplo, dada la lista de nombres de usuario de -> "root, guest, admin" y la lista de contraseñas de "test, 12345, q1w2e3r4" Ncrack normalmente las recorrerá así -> root:test, guest:test, admin:test, root:12345 etc. Al habilitar esta opción, las recorrerá así -> root:test, root:12345, root:q1w2e3r4, guest:test etc.

La mayoría de las herramientas de cracking de autenticación de red prefieren por defecto iterar la lista de contraseñas por cada nombre de usuario. Esto, sin embargo, es ineficaz en comparación con la iteración opuesta en la mayoría de los casos. Esto se mantiene cierto por la simple razón de que las listas de contraseñas suelen estar ordenadas por frecuencia, lo que significa que cuanto más común sea una contraseña, más cerca del principio de la lista de contraseñas estará. Por lo tanto, iterar sobre todos los nombres de usuario para las contraseñas más comunes primero, generalmente tiene más posibilidades de obtener un resultado positivo. Con la iteración de --passwords-first, las contraseñas muy comunes podrían ni siquiera ser probadas para ciertos nombres de usuario si el usuario decide abortar la sesión temprano. Sin embargo, esta opción podría ser valiosa para casos en los que el atacante conoce y ha verificado previamente que la lista de nombres de usuario contiene nombres de usuario reales, en lugar de hacer fuerza bruta ciegamente a través de ellos.

--pairwise (Elegir nombres de usuario y contraseñas en pares)

Habilitar esta opción hará que Ncrack itere la lista de nombres de usuario y contraseñas eligiéndolos en pares. Por ejemplo, dada la lista de nombres de usuario de "root, guest, admin" y la lista de contraseñas de "test, 12345, q1w2e3r4" Ncrack las recorrerá así: "root:test", "guest:12345", "admin:q1w2e3r4". Esto es particularmente útil cuando se dispone de conocimiento interno de la infraestructura probada y se han creado listas especiales de nombres de usuario y contraseñas.

SALIDA

Cualquier herramienta de seguridad es solo tan útil como la salida que genera. Pruebas y algoritmos complejos tienen poco valor si no se presentan de manera organizada y comprensible. Por supuesto, ningún formato único puede complacer a todos. Así que Ncrack ofrece varios formatos, incluyendo el modo interactivo para que los humanos lo lean directamente y XML para un fácil análisis por software.

Además de ofrecer diferentes formatos de salida, Ncrack proporciona opciones para controlar la verbosidad de la salida y los mensajes de depuración. Los tipos de salida se pueden enviar a la salida estándar o a archivos con nombre, a los que Ncrack puede añadir o sobrescribir.

Ncrack hace que la salida esté disponible en tres formatos diferentes. El predeterminado se llama salida interactiva, y se envía a la salida estándar (stdout). También hay una salida normal, que es similar a la interactiva excepto que muestra menos información de tiempo de ejecución y advertencias ya que se espera que se analice después de que el escaneo se complete en lugar de interactivamente.

La salida XML es uno de los tipos de salida más importantes, ya que puede ser convertida a HTML, fácilmente analizada por programas como las interfaces gráficas de usuario de Ncrack, o importada en bases de datos. Actualmente, la salida XML no ha sido implementada.

Mientras que la salida interactiva es la predeterminada y no tiene opciones de línea de comandos asociadas, los otros dos formatos utilizan la misma sintaxis. Toman un argumento, que es el nombre del archivo donde se deben almacenar los resultados. Se pueden especificar múltiples formatos, pero cada formato solo se puede especificar una vez. Por ejemplo, podrías querer guardar la salida normal para tu propia revisión mientras guardas XML del mismo escaneo para análisis programático. Podrías hacer esto con las opciones -oX myscan.xml -oN myscan.ncrack. Si bien este capítulo utiliza nombres simples como myscan.xml por brevedad, generalmente se recomiendan nombres más descriptivos. Los nombres elegidos son una cuestión de preferencia personal. Un esquema podría ser usar nombres de archivo largos que incorporen la fecha del escaneo y una o dos palabras que describan el escaneo, colocados en un directorio con el nombre de la empresa que está siendo escaneada.

Si bien estas opciones guardan los resultados en archivos, Ncrack sigue imprimiendo la salida interactiva en stdout como de costumbre. Por ejemplo, el comando nmap -oX myscan.xml [objetivo] imprime XML en myscan.xml y llena la salida estándar con los mismos resultados interactivos que habría impreso si -oX no se hubiera especificado en absoluto. Puedes cambiar esto pasando un guion como argumento a uno de los tipos de formato. Esto hace que Ncrack desactive la salida interactiva, y en su lugar imprima los resultados en el formato que especificaste al flujo de salida estándar. Por lo tanto, el comando nmap -oX - objetivo enviará solo salida XML a stdout. Los errores graves aún pueden ser impresos al flujo de error normal, stderr.

A diferencia de algunos argumentos de Ncrack, el espacio entre el indicador de opción de archivo de registro (como -oX) y el nombre del archivo o guion es obligatorio.

Todos estos argumentos soportan conversiones tipo strftime en el nombre del archivo. %H, %M, %S, %m, %d, %y y %Y son exactamente iguales que en strftime. %T es lo mismo que %H%M%S, %R es lo mismo que %H%M y %D es lo mismo que %m%d%y. Un % seguido de cualquier otro carácter simplemente produce ese carácter (%% te da un símbolo de porcentaje). Así, -oX ´scan-%T-%D.xml´ usará un archivo XML con el formato scan-144840-121307.xml.

Ncrack también ofrece opciones para controlar la verbosidad del escaneo y para añadir a los archivos de salida en lugar de sobrescribirlos. Todas estas opciones se describen a continuación.

Formatos de Salida de Ncrack

-oN especificador_archivo (salida normal) .

Solicita que la salida normal se dirija al archivo especificado. Como se discutió anteriormente, esto difiere ligeramente de la salida interactiva.

-oX especificador_archivo (salida XML) .

Solicita que la salida XML se dirija al archivo especificado.

-oA nombre_base (Salida a todos los formatos) .

Como una conveniencia, puedes especificar -oA nombre_base para almacenar los resultados del escaneo en formatos normal y XML a la vez. Se almacenan en nombre_base.ncrack y nombre_base.xml respectivamente. Como con la mayoría de los programas, puedes prefijar los nombres de archivo con una ruta de directorio, como ~/ncracklogs/foocorp/ en Unix o c:\hacking\sco en Windows.

Opciones de verbosidad y depuración

-v (Aumentar nivel de verbosidad) .

Aumenta el nivel de verbosidad, haciendo que Ncrack imprima más información sobre el escaneo en progreso. Las credenciales se muestran a medida que se encuentran y se imprime más información estadística al final. Úsalo dos veces o más para una verbosidad aún mayor.

-d [nivel] (Aumentar o establecer nivel de depuración) .

Cuando incluso el modo detallado no proporciona suficientes datos para ti, ¡la depuración está disponible para inundarte con mucho más! Al igual que con la opción de verbosidad (-v), la depuración se habilita con una bandera de línea de comandos (-d) y el nivel de depuración se puede aumentar especificándolo varias veces. Alternativamente, puedes establecer un nivel de depuración dando un argumento a -d. Por ejemplo, -d10 establece el nivel diez. Ese es el nivel efectivo más alto y producirá miles de líneas, a menos que tu sesión de cracking vaya realmente lenta.

La salida de depuración es útil cuando se sospecha de un error en Ncrack, o si simplemente estás confundido sobre lo que está haciendo Ncrack y por qué. Como esta característica está principalmente destinada a los desarrolladores, las líneas de depuración no siempre son autoexplicativas. Si no entiendes una línea, tus únicos recursos son ignorarla, buscarla en el código fuente, o pedir ayuda a la lista de desarrollo (nmap-dev). Algunas líneas son autoexplicativas, pero los mensajes se vuelven más oscuros a medida que aumenta el nivel de depuración.

--nsock-trace nivel (Establecer nivel de rastreo nsock) .

Esta opción está destinada principalmente a desarrolladores, ya que habilitarla activará la salida de depuración de la biblioteca Nsock. Nsock es la biblioteca subyacente para el manejo de sockets en paralelo. Tendrás que especificar un cierto nivel para esta opción. El rango válido es de 0 a 10. Normalmente, un nivel de 1 o 2 es suficiente para obtener una buena visión general de las operaciones de red que ocurren detrás de escena. Nsock imprime esa información a stdout por defecto.

--log-errors (Registrar errores/advertencias en el archivo de salida en modo normal) .

Las advertencias y errores impresos por Ncrack generalmente van solo a la pantalla (salida interactiva), dejando los archivos de salida en formato normal (generalmente especificados con -oN) sin desorden. Cuando deseas ver esos mensajes en el archivo de salida normal que especificaste, añade esta opción. Es útil cuando no estás viendo la salida interactiva o cuando deseas registrar errores al depurar un problema. Los mensajes de error y advertencia seguirán apareciendo también en modo interactivo. Esto no funcionará para la mayoría de los errores relacionados con argumentos de línea de comandos incorrectos porque Ncrack puede que aún no haya inicializado sus archivos de salida.

Una alternativa a --log-errors es redirigir la salida interactiva (incluyendo el flujo de error estándar) a un archivo. La mayoría de las shells de Unix facilitan este enfoque, aunque puede ser difícil en Windows.

Opciones de salida misceláneas

--append-output (Añadir a los archivos de salida en lugar de sobrescribirlos) .

Cuando especificas un nombre de archivo a una bandera de formato de salida como -oX o -oN, ese archivo se sobrescribe por defecto. Si prefieres conservar el contenido existente del archivo y añadir los nuevos resultados, especifica la opción --append-output. Todos los nombres de archivo de salida especificados en esa ejecución de Ncrack se añadirán en lugar de ser sobrescritos. Esto no funciona bien para datos de escaneo XML (-oX) ya que el archivo resultante generalmente no se analizará correctamente hasta que lo corrijas manualmente.

MÓDULOS

Ncrack viene con una gran cantidad de módulos de autenticación para diferentes servicios. Aquí hay una lista de algunos de los módulos más comunes y las peculiaridades de su autenticación:

Módulo FTP

El Protocolo de Transferencia de Archivos (FTP) es un protocolo antiguo utilizado para la transferencia de archivos. El módulo FTP prueba las credenciales utilizando el comando USER y PASS.

Módulo SSH

El Protocolo de Shell Segura (SSH) es un protocolo de red criptográfico para operar servicios de red de forma segura sobre una red desprotegida. El módulo SSH puede probar tanto la autenticación de usuario como la autenticación de clave pública.

Módulo Telnet

El Protocolo de Telnet es un protocolo de red de texto plano utilizado para el acceso interactivo a la línea de comandos. Debido a su falta de seguridad, su uso ha disminuido en favor de SSH. El módulo Telnet simula un cliente Telnet e intenta iniciar sesión con credenciales proporcionadas.

Módulo POP3

El Protocolo de Oficina de Correos versión 3 (POP3) es un protocolo de nivel de aplicación que utiliza Internet para recibir correo electrónico de un servidor remoto a un cliente de correo local. El módulo POP3 utiliza los comandos USER y PASS para autenticar clientes para recuperar mensajes de correo electrónico de un servidor de correo. El comando LOGIN es el mecanismo de autenticación más simple, rápido y compatible para IMAP.

Módulo IMAP

El Protocolo de Acceso a Mensajes de Internet (IMAP) es un protocolo de nivel de aplicación que utiliza Internet para la gestión de correo electrónico en un servidor remoto. Los clientes de correo electrónico utilizan IMAP para recuperar mensajes de correo electrónico de un servidor de correo. El módulo IMAP utiliza los comandos USER y PASS para autenticar clientes para recuperar mensajes de correo electrónico de un servidor de correo. El comando LOGIN es el mecanismo de autenticación más simple, rápido y compatible para IMAP.

Módulo SIP

El Protocolo de Inicio de Sesión (SIP) es un protocolo basado en texto, muy similar a HTTP en su estructura. La aplicación más común de SIP es en la telefonía por Internet para llamadas de voz y video. Casi todas las empresas tienen infraestructura que admite conferencias y parte de ellas se basan en SIP, lo que convierte la parte de autenticación en un vector de amenaza significativo.

Módulo Redis

Redis es uno de los servidores de caché más utilizados y la base de datos NoSQL más popular. A pesar de su reputación, el mecanismo de autenticación es muy simple, solo permite una contraseña para proteger el acceso remoto al servicio. Debido al alto rendimiento de Redis y al hecho de que solo se necesitan 2 paquetes para la fase de autenticación, Ncrack puede intentar muchas contraseñas en paralelo (http://redis.io/commands/AUTH). Especificar una lista de nombres de usuario o un solo nombre de usuario no tendrá ningún efecto en este módulo, ya que Redis solo trata con contraseñas.

Módulo PostgreSQL

PostgreSQL se utiliza a menudo como base de datos backend. El módulo PostgreSQL admite la autenticación md5, que es el método de autenticación de contraseñas más frecuente.

Módulo MySQL

El módulo MySQL admite la autenticación nativa.

Módulo MySQL

El módulo MSSQL admite la autenticación mixta.

Módulo MongoDB

El módulo MongoDB admite la autenticación MongoDB-CR y SCRAM-SHA-1. La opción pairwise y passwords-first se ignorará para el módulo MongoDB, debido a que no son eficientes contra MongoDB. La forma óptima de hackear MongoDB es aprovechar una vulnerabilidad de enumeración de usuarios inherente a su mecanismo de autenticación, que Ncrack explota.

Módulo Cassandra

Apache Cassandra es una popular base de datos NoSQL que a menudo se deja insegura con credenciales débiles o sin autenticación.

Módulo OWA

Outlook Web App permite a los usuarios acceder al buzón de un servidor Microsoft Exchange desde un navegador web y experimentar Microsoft Outlook sin un cliente de correo. El módulo admite la autenticación básica.

Módulo WinRM

Windows Remote Management (WinRM) es la implementación de Microsoft del Protocolo WS-Management, un protocolo estándar basado en SOAP (Simple Object Access Protocol) y compatible con firewall que permite que hardware y sistemas operativos, de diferentes proveedores, interoperen. Se utiliza a menudo para administrar máquinas Windows. El módulo admite la autenticación básica y Negotiate.

Módulo DICOM

Digital Imaging and Communications in Medicine (DICOM) es un protocolo utilizado ampliamente en entornos de atención médica. Lo más común es que se utilice tanto como formato de archivo como protocolo de red por los Sistemas de Archivado y Comunicación de Imágenes (PACS). El cliente de un servicio DICOM se llama usuario de clase de servicio (SCU) y el servidor, proveedor de clase de servicio (SCP). DICOM es muy único en cómo autentica a los clientes con los servidores; existen potencialmente de uno a tres pasos involucrados: Asociación, Servicio de Búsqueda y Recuperación de Imágenes.

Asociación: Este es el paso inicial que requieren casi todos los servidores PACS. Al enviar una solicitud A-ASSOCIATE con el Título de Entidad de Aplicación (AET) correcto, el cliente se asocia con el servidor y luego puede realizar solicitudes de consulta / recuperación en los siguientes pasos. Este es el modo que Ncrack soporta actualmente iterando a través del campo username. Por lo tanto, para hacer fuerza bruta de la AET del servidor, puede especificar una lista de AETs usando la opción -U y luego especificar una contraseña nula. Ejemplo: ncrack dicom://127.0.0.1 -U aet.txt --pass DOESNOTMATTER

Servicio de Búsqueda: Este paso implica poder consultar al servidor PACS para obtener estudios de pacientes asociados con imágenes DICOM. Esto ocurre después de que el cliente ha realizado la fase de Asociación. Se debe enviar una solicitud C-FIND con la AET de llamada correcta. Conocer la AET de cliente permitida correcta (o AET de llamada) es requerido por los servidores PACS configurados de forma segura. Muchos servidores PACS por defecto no requieren esto.

Recuperación de Imágenes: Este paso permite a un cliente recuperar imágenes DICOM. Los servidores PACS más endurecidos requerirán que el cliente tenga una IP permitida específica configurada para poder enviar una solicitud C-MOVE / C-STORE después de que se hayan realizado los dos pasos anteriores.

Módulo MQTT

El protocolo Message Queueing Telemetry Transport (MQTT) es un protocolo máquina a máquina de publicación/suscripción que permite a los clientes IoT publicar en un broker. Cada dispositivo cliente se suscribe a un tema de interés particular y recibe mensajes de los publicadores. Por lo general, la autenticación MQTT es opcional y, cuando está habilitada, se puede realizar fuerza bruta con mucha facilidad, ya que solo requiere el envío de un único paquete MQTT CONNECT por cada par de credenciales intentado.

Módulo Wordpress

WordPress es uno de los sistemas de gestión de contenido más populares. Este módulo ataca el punto final de administración web. Por defecto, intentará "wp-login.php", pero puede cambiarlo especificando la ruta path. Por ejemplo: ncrack wp://127.0.0.1,path=/non-default/wp-login.php

Módulo CVS

El Sistema de Control de Versiones Concurrente (CVS) es un sistema de control de revisiones en el desarrollo de software. Aunque no es tan popular hoy en día, hay muchos servidores CVS antiguos y obsoletos que podrían tener credenciales predeterminadas o débiles.
