NCDUMP(1) UTILIDADES UNIDATA NCDUMP(1)

NOMBRE

ncdump - Convierte un archivo netCDF a formato de texto (CDL)

SINOPSIS

ncdump [-chistxwF] [-v var1,...] [-b lang] [-f lang] [-l len] [-n name] [-p d_digitos[,d_digitos_dobles]] [-g grp1,...] archivo

ncdump -k archivo

DESCRIPCIÓN

La utilidad ncdump genera una representación textual de un archivo netCDF especificado en la salida estándar, excluyendo opcionalmente algunos o todos los datos de las variables en la salida. La representación textual tiene un formato llamado CDL (network Common Data form Language) que puede ser visto, editado o utilizado como entrada para ncgen, un programa complementario que puede generar un archivo netCDF binario a partir de un archivo CDL. Por lo tanto, ncgen y ncdump pueden ser inversos para transformar la representación de los datos entre formatos binarios y textuales. Consulte la documentación de ncgen para una descripción de CDL y las representaciones netCDF.

ncdump también puede ser utilizado para determinar qué tipo de archivo netCDF se está utilizando (qué variante del formato de archivo netCDF) con la opción -k.

Si el soporte DAP se habilitó cuando se compiló ncdump, el nombre del archivo puede especificar una URL DAP. Esto permite a ncdump acceder a fuentes de datos de servidores DAP, incluyendo datos en otros formatos que no sean netCDF. Cuando se utiliza con URL DAP, ncdump muestra la traducción del modelo de datos DAP al modelo de datos netCDF.

ncdump también puede ser utilizado como un simple explorador de archivos de datos netCDF, para mostrar los nombres y longitudes de las dimensiones; nombres y tipos de variables, y formas; nombres y valores de atributos; y opcionalmente, los valores de los datos para todas las variables o variables seleccionadas en un archivo netCDF. Para archivos netCDF-4, los grupos y los tipos definidos por el usuario también se incluyen en la salida de ncdump.

ncdump utiliza `_' para representar valores de datos que son iguales al atributo `_FillValue' de una variable, que se utiliza para representar datos que aún no han sido escritos. Si una variable no tiene el atributo `_FillValue', se utiliza el valor de relleno predeterminado para el tipo de la variable a menos que la variable sea de tipo byte.

ncdump define un formato de visualización predeterminado para cada tipo de datos netCDF, pero esto puede cambiarse si se define un atributo `C_format' para una variable netCDF. En este caso, ncdump usará el atributo `C_format' para formatear cada valor. Por ejemplo, si se sabe que los datos de punto flotante para la variable netCDF `Z' tienen solo tres dígitos significativos, sería apropiado usar el atributo de variable

Z:C_format = "%.3g"

OPCIONES

-c
Muestra los valores de las variables de coordenada (variables 1D con los mismos nombres que las dimensiones) además de las declaraciones de todas las dimensiones, variables, valores de atributos, grupos y tipos definidos por el usuario. Los valores de datos de las variables no coordenadas no se incluyen en la salida. Esta es generalmente la opción más adecuada para una vista rápida de la estructura y el contenido de un archivo netCDF.
-h
Muestra solo la información de cabecera en la salida, es decir, muestra solo las declaraciones de las dimensiones, variables, atributos, grupos y tipos definidos por el usuario del archivo de entrada, pero no los valores de datos de ninguna variable. La salida es idéntica a usar la opción -c, excepto que no se incluyen los valores de las variables de coordenada. (Como máximo, una de las opciones -c o -h puede estar presente).
-v var1,...
La salida incluirá valores de datos para las variables especificadas, además de las declaraciones de todas las dimensiones, variables y atributos. Se deben especificar una o más variables por nombre en la lista separada por comas que sigue a esta opción. La lista debe ser un solo argumento para el comando, por lo tanto, no puede contener espacios en blanco sin escapar u otros caracteres de espacio en blanco. Las variables nombradas deben ser variables netCDF válidas en el archivo de entrada. Una variable dentro de un grupo en un archivo netCDF-4 puede especificarse con un nombre de ruta absoluto, como `/GroupA/GroupA2/var'. El uso de un nombre de ruta relativo como `var' o `grp/var' especifica todos los nombres de variables coincidentes en el archivo. El valor predeterminado, sin esta opción y en ausencia de las opciones -c o -h, es incluir los valores de datos para todas las variables en la salida.
-b [c|f]
Una breve anotación en forma de comentario CDL (texto que comienza con los caracteres ``//'') se incluirá en la sección de datos de la salida para cada `fila' de datos, para ayudar a identificar los valores de datos para variables multidimensionales. Si lang comienza con `C' o `c', se utilizarán convenciones del lenguaje C (índices basados en cero, la última dimensión varía más rápido). Si lang comienza con `F' o `f', se utilizarán convenciones del lenguaje Fortran (índices basados en uno, la primera dimensión varía más rápido). En cualquier caso, los datos se presentarán en el mismo orden; solo las anotaciones diferirán. Esta opción puede ser útil para explorar grandes volúmenes de datos multidimensionales.
-f [c|f]
Anotaciones completas en forma de comentarios CDL al final (texto que comienza con los caracteres ``//'') para cada valor de dato (excepto los caracteres individuales en arreglos de caracteres) se incluirán en la sección de datos. Si lang comienza con `C' o `c', se utilizarán convenciones del lenguaje C. Si lang comienza con `F' o `f', se utilizarán convenciones del lenguaje Fortran. En cualquier caso, los datos se presentarán en el mismo orden; solo las anotaciones diferirán. Esta opción puede ser útil para pasar datos a otros filtros, ya que cada valor de dato aparece en una línea separada, completamente identificado. (Como máximo, una de las opciones '-b' o '-f' puede estar presente).
-l longitud
Cambia la longitud máxima de línea predeterminada (80) utilizada en el formato de listas de valores de datos no caracteres.
-n nombre
CDL requiere un nombre para un archivo netCDF, para ser utilizado por ncgen -b en la generación de un nombre de archivo netCDF predeterminado. Por defecto, ncdump construye este nombre a partir del último componente del nombre de archivo del archivo netCDF de entrada, eliminando cualquier extensión que tenga. Use la opción -n para especificar un nombre diferente. Aunque el nombre del archivo de salida utilizado por ncgen -b puede especificarse, puede ser prudente hacer que ncdump cambie el nombre predeterminado para evitar sobrescribir inadvertidamente un archivo netCDF valioso al usar ncdump, editar el archivo CDL resultante y usar ncgen -b para generar un nuevo archivo netCDF a partir del archivo CDL editado.
-p digitos_flotantes[,digitos_dobles]
Especifica la precisión predeterminada (número de dígitos significativos) a utilizar en la visualización de valores de datos de punto flotante o de doble precisión para atributos y variables. Si se especifica, este valor anula el valor del atributo C_format, si lo hay, para una variable. Los datos de punto flotante se mostrarán con digitos_flotantes dígitos significativos. Si también se especifica digitos_dobles, los valores de doble precisión se mostrarán con esa cantidad de dígitos significativos. En ausencia de cualquier especificación de -p, los datos de punto flotante y de doble precisión se muestran con 7 y 15 dígitos significativos respectivamente. Los archivos CDL pueden hacerse más pequeños si se requiere menos precisión. Si se especifican tanto la precisión de punto flotante como la de doble, los dos valores deben aparecer separados por una coma (sin espacios) como un solo argumento para el comando. (Para representar cada bit de precisión en un archivo CDL para todos los posibles valores de punto flotante se requeriría -p 9,17).
-k
Muestra el tipo de archivo netCDF al que hace referencia la ruta, uno de `classic', `64-bit offset', `netCDF-4', o `netCDF-4 classic model'. Antes de la versión 3.6, solo existía un tipo de archivo netCDF, designado como `classic' (también conocido como variante de formato 1). El soporte para archivos grandes introdujo otra variante del formato, designada como `64-bit offset' (conocida como variante de formato 2). NetCDF-4, utiliza una tercera variante del formato, `netCDF-4' (variante de formato 3). Otro variante de formato, designada `netCDF-4 classic model' (variante de formato 4), está restringida a las características admitidas por el modelo de datos netCDF-3 pero representadas utilizando el formato HDF5, de modo que un programa netCDF-3 no modificado pueda leer o escribir el archivo simplemente volviendo a enlazar con la biblioteca netCDF-4. La cadena de texto generada al usar la opción `-k' puede proporcionarse como el valor de la opción `-k' a n

ncdump(1) — Arch Linux

NAME

ncdump — print NetCDF data in a text file

SYNOPSIS

ncdump [ -b big_or_little ] [ -c ] [ -d dim,... ] [ -e ] [ -f format ] [ -h ] [ -i ] [ -l byte_limit ] [ -n name ] [ -p rel_prec ] [ -s ] [ -t ] [ -v var,... ] [ -g grp,... ] [ -w ] [ -x ] [ -F ] [ file ]

DESCRIPTION

The ncdump utility is a simple ASCII representation of a netCDF file. It is intended to be a human-readable representation of a netCDF file, and is intended to be used as a filter, that is,

ncdump file | more

or

ncdump file > file.cdl

The netCDF version of CDL is generated as the standard output. If the output is redirected, a file in CDL format is created, which can be used as input to ncgen(1) to recreate the original netCDF file.

If no file is specified, or if the file is specified as a hyphen (-), then the standard input is used.

When ncdump is used to generate CDL, it prints the entire file, unless restricted by the -v or -g options. The default, without the -c or -h options, is to print the data values as well as the structure.

The -c option produces a fully-annotated CDL file, with data values printed, using C-style indexing, e.g. data[0][1][2]. The default without this option is to use Fortran-style indexing, e.g. data(0,1,2).

The -h option prints only the header information (i.e. the structure) of the netCDF file, not the data values. The default is to print both header and data values.

The following options are available:

OPTIONS

-b big_or_little
Output binary data in the specified big or little-endian format. This option only applies when writing data values, and will be ignored if the output is in CDL format (the default).
-c
Use C-style indexing (e.g. data[0][1][2]) instead of Fortran-style indexing (e.g. data(0,1,2)) in the output. This option is particularly useful when generating CDL output for use with the ncgen(1) utility.
-d dim,...
For netCDF-4 files, the output will include data values only for the specified dimensions. One or more dimensions must be specified by name in the comma-delimited list following this option. The list must be a single argument to the command. The named dimensions must be valid netCDF dimensions in the input-file. A dimension in a netCDF-4 file may be specified with an absolute or relative path name. Use of a relative path name specifies all matching dimension names in the file. The default, without this option and in the absence of the -c or -h options, is to include data values for all dimensions in the output.
-e
Same as the '-i' option, except output time data as date-time strings with ISO-8601 standard 'T' separator, instead of a blank.
-f format
Specifies the output format for the netCDF dataset. Currently, the following formats are supported:
classic
NetCDF classic format.
64-bit offset
NetCDF 64-bit offset format.
netCDF-4
NetCDF-4 format.
netCDF-4 classic model
NetCDF-4 classic model format.
This option only affects the output when creating a new netCDF file using ncgen(1). This option is not used when dumping a netCDF file to CDL format.
-h
Output only the header information (metadata) of the netCDF file. Do not print the data values.
-i
Same as the '-t' option, except output time data as date-time strings with ISO-8601 standard 'T' separator, instead of a blank.
-l byte_limit
Set the byte limit for the number of values displayed for each variable. The default is 1000. A value of 0 disables the limit.
-n name
Set the name of the netCDF dataset in the CDL output. The default is to use the base name of the input file. This option is not used when dumping a netCDF file to CDL format.
-p rel_prec
Set the default relative precision for floating-point values. The default is 5. This option is not used when dumping a netCDF file to CDL format.
-s
Output special virtual attributes that provide performance-related information about the file format and variable properties for netCDF-4 data. These special virtual attributes are not actually part of the data, they are merely a convenient way to display miscellaneous properties of the data in CDL (and eventually NcML). They include `_ChunkSizes', `_DeflateLevel', `_Endianness', `_Fletcher32', `_Format', `_NoFill', `_Shuffle', and `_Storage'. `_ChunkSizes' is a list of chunk sizes for each dimension of the variable. `_DeflateLevel' is an integer between 0 and 9 inclusive if compression has been specified for the variable. `_Endianness' is either `little' or `big', depending on how the variable was stored when first written. `_Fletcher32' is `true' if the checksum property was set for the variable. `_Format' is a global attribute specifying the netCDF format variant, one of `classic', `64-bit offset', `netCDF-4', or `netCDF-4 classic model'. `_NoFill' is `true' if the persistent NoFill property was set for the variable when it was defined. `_Shuffle' is `true' if use of the shuffle filter was specified for the variable. `_Storage' is `contiguous' or `compact' or `chunked', depending on how the variable's data is stored.
-t
Controls display of time data, if stored in a variable that uses a udunits compliant time representation such as `days since 1970-01-01' or `seconds since 2009-03-15 12:01:17', a variable identified in a "bounds" attribute of such a time variable, or a numeric attribute of a time variable. If this option is specified, time data values are displayed as human-readable date-time strings rather than numerical values, interpreted in terms of a `calendar' variable attribute, if specified. For numeric attributes of time variables, the human-readable time value is displayed after the actual value, in an associated CDL comment. Calendar attribute values interpreted with this option include the CF Conventions values `gregorian' or `standard', `proleptic_gregorian', `noleap' or `365_day', `all_leap' or `366_day', `360_day', and `julian'.
-v var,...
Output data values only for the specified variables. One or more variables must be specified by name in the comma-delimited list following this option. The list must be a single argument to the command. The named variables must be valid netCDF variables in the input-file. A variable in a netCDF-4 file may be specified with an absolute or relative path name. Use of a relative path name specifies all matching variable names in the file. The default, without this option and in the absence of the -c or -h options, is to include data values for all variables in the output.
-w
For file names that request remote access using DAP URLs, access data with client-side caching of entire variables.
-x
Output XML (NcML) instead of CDL. The NcML does not include data values. The NcML output option currently only works for netCDF classic model data.
-F
Use _Filter and _Codecs attributes in place of _Fletcher32, _Shuffle, and _Deflate.

EXAMPLES

Look at the structure of the data in the netCDF file `foo.nc':

ncdump -c foo.nc

Produce an annotated CDL version of the structure and data in the netCDF file `foo.nc', using C-style indexing for the annotations:

ncdump -b c foo.nc > foo.cdl

Output data for only the variables `uwind' and `vwind' from the netCDF file `foo.nc', and show the floating-point data with only three significant digits of precision:

ncdump -v uwind,vwind -p 3 foo.nc

Produce a fully-annotated (one data value per line) listing of the data for the variable `omega', using Fortran conventions for indices, and changing the netCDF dataset name in the resulting CDL file to `omega':

ncdump -v omega -f fortran -n omega foo.nc > Z.cdl

SEE ALSO

ncgen(1), netcdf(3)

BUGS

Character arrays that contain a null-byte are treated like C strings, so no characters after the null byte appear in the output.

Multidimensional character string arrays are not handled well, since the CDL syntax for breaking a long character string into several shorter lines is weak.

There should be a way to specify that the data should be displayed in `record' order, that is with the all the values for `record' variables together that have the same value of the record dimension.
