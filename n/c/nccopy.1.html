NCCOPY(1) UTILIDADES UNIDATA NCCOPY(1)

NOMBRE

nccopy - Copia un archivo netCDF, modificando opcionalmente el formato, la compresión o la fragmentación en la salida.

SINOPSIS

nccopy [-k nombre_tipo ] [-codigo_tipo] [-d n ] [-s] [-c especificacion_fragmentacion ] [-u] [-w] [-[v|V] var1,...] [-[g|G] grp1,...] [-m tamano_buffer ] [-h cache_fragmentacion ] [-e elementos_cache ] [-r] [-F especificacion_filtros ] [-L n ] [-M n ] archivo_entrada archivo_salida

DESCRIPCIÓN

La utilidad nccopy copia un archivo netCDF de entrada en cualquier variante de formato compatible a un archivo netCDF de salida, convirtiendo opcionalmente la salida a cualquier variante de formato netCDF compatible, comprimiendo los datos o refragmentando los datos. Por ejemplo, si se compiló con la biblioteca netCDF-3, un archivo netCDF clásico puede copiarse a un archivo netCDF de desplazamiento de 64 bits, permitiendo variables más grandes. Si se compiló con la biblioteca netCDF-4, un archivo netCDF clásico puede copiarse a un archivo netCDF-4 o también a un archivo de modelo clásico netCDF-4, permitiendo la compresión de datos, cambios eficientes de esquema, tamaños de variables más grandes y el uso de otras características de netCDF-4.

Si no se especifica ningún formato de salida, ni con -k nombre_tipo ni con -codigo_tipo, entonces la salida usará el mismo formato que la entrada, a menos que la entrada sea clásica o de desplazamiento de 64 bits y se especifique fragmentación o compresión, en cuyo caso la salida será de formato de modelo clásico netCDF-4. Intentar realizar algunos tipos de conversión de formato resultará en un error, si la conversión no es posible. Por ejemplo, un intento de copiar un archivo netCDF-4 que utiliza características del modelo mejorado, como grupos o cadenas de longitud variable, a cualquiera de los otros tipos de formatos netCDF que utilizan el modelo clásico resultará en un error.

nccopy también sirve como un ejemplo de programa netCDF-4 genérico, con su capacidad para leer cualquier archivo netCDF válido y manejar grupos anidados, cadenas y tipos definidos por el usuario, incluyendo tipos compuestos arbitrariamente anidados, tipos de longitud variable y datos de cualquier tipo netCDF-4 válido.

Si se habilitó el soporte DAP cuando se compiló nccopy, el nombre del archivo puede especificar una URL DAP. Esto puede usarse para convertir datos en servidores DAP a archivos netCDF locales.

OPCIONES

-k nombre_tipo
Usa el nombre del formato para especificar el tipo de archivo que se creará y, por inferencia, el modelo de datos (es decir, netcdf-3 (clásico) o netcdf-4 (mejorado)). Los argumentos posibles son:
'nc3' o 'classic' => formato clásico netCDF
'nc6' o '64-bit offset' => formato de 64 bits netCDF
'nc4' o 'netCDF-4' => formato netCDF-4 (modelo de datos mejorado)
'nc7' o 'netCDF-4 classic model' => formato de modelo clásico netCDF-4
Nota: Los antiguos números de formato '1', '2', '3', '4', equivalentes a los nombres de formato 'nc3', 'nc6', 'nc4' o 'nc7' respectivamente, también se aceptan pero están obsoletos, debido a la fácil confusión entre números de formato y nombres de formato.
[-codigo_tipo]
Usa el código numérico del formato (en lugar del nombre del formato) para especificar el tipo de archivo que se creará y, por inferencia, el modelo de datos (es decir, netcdf-3 (clásico) frente a netcdf-4 (mejorado)). Los códigos numéricos son:
3 => formato clásico netcdf
6 => formato de 64 bits netCDF
4 => formato netCDF-4 (modelo de datos mejorado)
7 => formato de modelo clásico netCDF-4

El código numérico "7" se usa porque "7=3+4", especificando el formato que usa el modelo de datos netCDF-3 para compatibilidad con el formato de almacenamiento netCDF-4 para rendimiento. Se debe dar crédito a NCO por el uso de estos códigos numéricos en lugar de los antiguos y confusos números de formato.

-d n
Para la salida netCDF-4, incluyendo el modelo clásico netCDF-4, especifica el nivel de descompresión (nivel de compresión) para los datos de las variables de salida. 0 corresponde a ninguna compresión y 9 a compresión máxima, y niveles más altos de compresión requieren marginalmente más tiempo para comprimir o descomprimir que los niveles más bajos. Como efecto secundario, especificar un nivel de compresión de 0 (a través de "-d 0") desactiva realmente la descompresión por completo. La compresión lograda también puede depender de los parámetros de fragmentación de salida. Si se especifica esta opción para un archivo de entrada de formato clásico o de desplazamiento de 64 bits, no es necesario especificar también que la salida sea del modelo clásico netCDF-4, ya que ese será el predeterminado. Si esta opción no se especifica y el archivo de entrada tiene variables comprimidas, la compresión se conservará en la salida, utilizando la misma fragmentación que en la entrada por predeterminado.
Tenga en cuenta que nccopy requiere que todas las variables se compriman utilizando el mismo nivel de compresión, pero la API no tiene tal restricción. Con un programa puede personalizar la compresión para cada variable independientemente.
-s
Para la salida netCDF-4, incluyendo el modelo clásico netCDF-4, especifica la reorganización de los bytes de los datos de las variables antes de la compresión o después de la descompresión. La reorganización se refiere a la intercalación de bytes en un bloque para que los primeros bytes de todos los valores sean contiguos en el almacenamiento, seguidos por todos los segundos bytes, y así sucesivamente, lo que a menudo mejora la compresión. Esta opción se ignora a menos que se especifique un nivel de descompresión distinto de cero. Usar -d0 para especificar ninguna descompresión en datos de entrada que han sido comprimidos y reorganizados desactiva tanto la compresión como la reorganización en la salida.
-u
Convierte las dimensiones de tamaño ilimitado en la entrada a dimensiones de tamaño fijo en la salida. Esto puede acelerar el acceso variable por variable, pero ralentizar el acceso registro por registro a múltiples variables a lo largo de una dimensión ilimitada.
-w
Mantiene la salida en memoria (como un archivo netCDF sin disco) hasta que se cierra la salida, momento en el cual el archivo de salida se escribe en disco. Esto puede acelerar enormemente operaciones como la conversión de dimensiones ilimitadas a fijas (opción -u), la fragmentación, la refragmentación o la compresión de la entrada. Requiere que la memoria disponible sea lo suficientemente grande como para contener el archivo de salida. Esta opción puede proporcionar una aceleración mayor que la optimización cuidadosa de las opciones -m, -h o -e, y ciertamente es mucho más simple.
-c especificacion_fragmentacion
Para la salida netCDF-4, incluyendo el modelo clásico netCDF-4, especifica la fragmentación (teselado multidimensional) para los datos de las variables en la salida. Esto es útil para especificar las unidades de acceso al disco, compresión u otros filtros como sumas de verificación. Cambiar la fragmentación en un archivo netCDF también puede acelerar enormemente el acceso, eligiendo formas de fragmentación que sean apropiadas para los patrones de acceso más comunes.
El argumento especificacion_fragmentacion tiene varias formas. La primera forma es la forma original, obsoleta, y es una cadena de asociaciones separadas por comas, cada una especificando un nombre de dimensión, un carácter '/' y opcionalmente la longitud de fragmentación correspondiente para esa dimensión. No debe haber espacios en la cadena de especificación de fragmentación, excepto posiblemente espacios escapados que forman parte de un nombre de dimensión. Una especificación de fragmentación nombra al menos una dimensión, y puede omitir dimensiones que no van a ser fragmentadas o para las cuales se desea la longitud de fragmentación predeterminada. Si un nombre de dimensión va seguido de un carácter '/' pero sin una longitud de fragmentación subsiguiente, se asume la longitud de dimensión real. Si se copia un archivo de modelo clásico a un archivo de salida netCDF-4 y no se nombran todas las dimensiones en la especificación de fragmentación, las dimensiones sin nombre también usarán la longitud de dimensión real para la longitud de fragmentación. Un ejemplo de especificación de fragmentación para variables que usan dimensiones 'm' y 'n' podría ser 'm/100,n/200' para especificar fragmentos de 100 por 200. Para ver la fragmentación resultante de la copia con una especificación de fragmentación, use la opción '-s' de ncdump en el archivo de salida.
La especificación de fragmentación '/' que omite todos los nombres de dimensión y las longitudes de fragmentación correspondientes especifica que no se realizará ninguna fragmentación en la salida, por lo que puede usarse para desenfragmentar todas las variables fragmentadas. Para ver la fragmentación resultante de la copia con una especificación de fragmentación, use la opción '-s' de ncdump en el archivo de salida.
Como optimización de E/S, nccopy tiene un umbral para el tamaño mínimo de variables no registradas que se fragmentan, actualmente 8192 bytes. La bandera -M puede usarse para anular este valor.

Si necesita personalizar la fragmentación para variables de forma independiente, deberá usar la segunda forma de `chunkspec`. Esta segunda forma de `chunkspec` tiene esta sintaxis: var:n1,n2,...,nn. Esto asume que la variable llamada "var" tiene un rango n. La fragmentación que se aplicará a cada dimensión de la variable se especifica mediante los valores de n1 a nn. Esta segunda forma de especificación de fragmentación se puede repetir varias veces para especificar la fragmentación exacta para diferentes variables. Si la variable se especifica pero no se especifican tamaños de fragmento (es decir, -c var:), la fragmentación se deshabilita para esa variable. Si la misma variable se especifica más de una vez, la segunda y subsiguientes especificaciones se ignoran. Además, esta segunda forma, fragmentación por variable, tiene prioridad sobre cualquier fragmentación por dimensión, excepto el caso simple de "/".
La tercera forma de `chunkspec` tiene la sintaxis: var:compact o var:contiguous. Esto intenta explícitamente establecer el tipo de almacenamiento de la variable como compacto o contiguo, respectivamente. Estos pueden ser anulados si otras banderas requieren que la variable se fragmente.
-v var1,...
La salida incluirá los valores de datos para las variables especificadas, además de las declaraciones de todas las dimensiones, variables y atributos. Se debe especificar una o más variables por nombre en la lista separada por comas que sigue a esta opción. La lista debe ser un único argumento para el comando, por lo tanto, no puede contener espacios en blanco sin escapar u otros caracteres de espacio en blanco. Las variables nombradas deben ser variables netCDF válidas en el archivo de entrada. Una variable dentro de un grupo en un archivo netCDF-4 puede especificarse con un nombre de ruta absoluta, como "/GroupA/GroupA2/var". El uso de un nombre de ruta relativa como 'var' o "grp/var" especifica todos los nombres de variables coincidentes en el archivo. El valor predeterminado, sin esta opción, es incluir los valores de datos para todas las variables en la salida.
-V var1,...
La salida incluirá solo las variables especificadas, pero todas las dimensiones y atributos globales o de grupo. Se debe especificar una o más variables por nombre en la lista separada por comas que sigue a esta opción. La lista debe ser un único argumento para el comando, por lo tanto, no puede contener espacios en blanco sin escapar u otros caracteres de espacio en blanco. Las variables nombradas deben ser variables netCDF válidas en el archivo de entrada. Una variable dentro de un grupo en un archivo netCDF-4 puede especificarse con un nombre de ruta absoluta, como '/GroupA/GroupA2/var'. El uso de un nombre de ruta relativa como 'var' o 'grp/var' especifica todos los nombres de variables coincidentes en el archivo. El valor predeterminado, sin esta opción, es incluir todas las variables en la salida.
-g grp1,...
La salida incluirá valores de datos solo para los grupos especificados. Se debe especificar uno o más grupos por nombre en la lista separada por comas que sigue a esta opción. La lista debe ser un único argumento para el comando. Los grupos nombrados deben ser grupos netCDF válidos en el archivo de entrada. El valor predeterminado, sin esta opción, es incluir valores de datos para todos los grupos en la salida.
-G grp1,...
La salida incluirá solo los grupos especificados. Se debe especificar uno o más grupos por nombre en la lista separada por comas que sigue a esta opción. La lista debe ser un único argumento para el comando. Los grupos nombrados deben ser grupos netCDF válidos en el archivo de entrada. El valor predeterminado, sin esta opción, es incluir todos los grupos en la salida.
-m bufsize
Un número entero o de punto flotante que especifica el tamaño, en bytes, del búfer de copia utilizado para copiar variables grandes. Un sufijo de K, M, G o T multiplica el tamaño del búfer de copia por mil, millón, mil millones o billón, respectivamente. El valor predeterminado es 5 Mbytes, pero se incrementará si es necesario para contener al menos un fragmento de variables fragmentadas netCDF-4 en el archivo de entrada. Es posible que desee especificar un valor mayor que el predeterminado para copiar archivos grandes a través de redes de alta latencia. Usar la opción '-w' puede proporcionar un mejor rendimiento, si la salida cabe en la memoria.
-h chunk_cache
Para la salida netCDF-4, incluido el modelo clásico netCDF-4, un número entero o de punto flotante que especifica el tamaño en bytes de la caché de fragmentos asignada para cada variable fragmentada. Esto no es una propiedad del archivo, sino simplemente un parámetro de ajuste de rendimiento para evitar comprimir o descomprimir los mismos datos varias veces al copiar y cambiar las formas de los fragmentos. Un sufijo de K, M, G o T multiplica el tamaño de la caché de fragmentos por mil, millón, mil millones o billón, respectivamente. El valor predeterminado es 4.194304 Mbytes (o lo que se haya especificado para la constante de configuración CHUNK_CACHE_SIZE cuando se compiló la biblioteca netCDF). Idealmente, la utilidad nccopy debería aceptar solo un tamaño de búfer de memoria y dividirlo de manera óptima entre un búfer de copia y una caché de fragmentos, pero aún no se ha implementado ningún algoritmo general para calcular el tamaño óptimo de la caché de fragmentos. Usar la opción '-w' puede proporcionar un mejor rendimiento, si la salida cabe en la memoria.
-e cache_elems
Para la salida netCDF-4, incluido el modelo clásico netCDF-4, especifica el número de fragmentos que la caché de fragmentos puede contener. Un sufijo de K, M, G o T multiplica el número de fragmentos que se pueden mantener en la caché por mil, millón, mil millones o billón, respectivamente. Esto no es una propiedad del archivo, sino simplemente un parámetro de ajuste de rendimiento para evitar comprimir o descomprimir los mismos datos varias veces al copiar y cambiar las formas de los fragmentos. El valor predeterminado es 1009 (o lo que se haya especificado para la constante de configuración CHUNK_CACHE_NELEMS cuando se compiló la biblioteca netCDF). Idealmente, la utilidad nccopy determinaría un valor óptimo para este parámetro, pero aún no se ha implementado ningún algoritmo general para calcular el número óptimo de elementos de caché de fragmentos.
-r
Lee un archivo de entrada netCDF clásico o de 64 bits de desplazamiento en un archivo netCDF sin disco en memoria antes de copiar. Requiere que el archivo de entrada sea lo suficientemente pequeño como para caber en memoria. Para nccopy, esto no parece proporcionar ninguna mejora de velocidad significativa, por lo que puede que no sea una opción útil.
-L n
Establece el nivel de registro; solo se puede usar si nccopy admite netCDF-4 (mejorado).
-M n
Establece el tamaño mínimo del fragmento; solo se puede usar si nccopy admite netCDF-4 (mejorado).
-F filterspec
Para la salida netCDF-4, incluido el modelo clásico netCDF-4, especifica un filtro para aplicar a un conjunto especificado de variables en la salida. Por regla general, el filtro es un algoritmo de compresión/descompresión con un identificador numérico único asignado por HDF Group (ver https://support.hdfgroup.org/services/filters.html).
El argumento filterspec tiene esta forma general.
fqn1|fqn2...,filterid,param1,param2...paramn o *,filterid,param1,param2...paramn
Un fqn (nombre completamente calificado) es el nombre de una variable prefijado por sus grupos contenedores con los nombres de grupo separados por una barra diagonal ('/'). Un ejemplo podría ser /g1/g2/var. Alternativamente, solo se puede dar el nombre de la variable si está en el grupo raíz: por ejemplo, var. Se pueden usar barras invertidas para escapar según sea necesario. Una advertencia: el separador '|' es un carácter reservado de bash, por lo que probablemente necesitará poner el spec del filtro entre comillas de algún tipo o escaparlo de otra manera.
El filterid es un entero positivo sin signo que representa el id asignado por HDFgroup al filtro. Después del id hay una secuencia de parámetros que definen la operación del filtro. Cada parámetro es un entero sin signo de 32 bits.
Este parámetro se puede repetir varias veces con diferentes nombres de variables.

EJEMPLOS

Crea una copia de foo1.nc, un archivo netCDF de cualquier tipo, a foo2.nc, un archivo netCDF del mismo tipo:

nccopy foo1.nc foo2.nc

Tenga en cuenta que la copia anterior no será tan rápida como el uso de cp u otra utilidad de copia simple, porque el archivo se copia utilizando únicamente la API netCDF. Si el archivo de entrada tiene bytes adicionales después del final de los datos netCDF, esos no se copiarán, porque no son accesibles a través de la interfaz netCDF. Si el archivo original se generó en modo "Sin relleno" de modo que los valores de relleno no se almacenan para relleno para la alineación de datos, el archivo de salida puede tener bytes de relleno diferentes.

Convierte un archivo de modelo clásico netCDF-4, compressed.nc, que utiliza compresión, a un archivo clásico netCDF-3, classic.nc:

nccopy -k classic compressed.nc classic.nc

Tenga en cuenta que se podría usar 'nc3' en lugar de 'classic'.

Descarga la variable 'time_bnds' y sus atributos asociados de un servidor OPeNDAP y copia el resultado a un archivo netCDF llamado 'tb.nc':

nccopy 'http://test.opendap.org/opendap/data/nc/sst.mnmean.nc.gz?time_bnds' tb.nc

Tenga en cuenta que las URL que nombran variables específicas como argumentos de línea de comandos generalmente deben entrecomillarse, para evitar que el shell interprete caracteres especiales como '?'.

Comprime todas las variables en el archivo de entrada foo.nc, un archivo netCDF de cualquier tipo, al archivo de salida bar.nc:

nccopy -d1 foo.nc bar.nc

Si foo.nc era un archivo netCDF clásico o de 64 bits de desplazamiento, bar.nc será un archivo netCDF de modelo clásico netCDF-4, porque los formatos clásico y de 64 bits de desplazamiento no admiten la compresión. Si foo.nc era un archivo netCDF-4 con algunas variables comprimidas usando varios niveles de deflación, la salida también será un archivo netCDF-4 del mismo tipo, pero todas las variables, incluidas las variables no comprimidas en la entrada, usarán ahora el nivel de deflación 1.

Suponga que los datos de entrada incluyen variables de cuadrícula que utilizan las dimensiones de tiempo, latitud, longitud, con 1000 tiempos por 1000 latitudes por 1000 longitudes, y que la dimensión de tiempo varía más lentamente. Suponga también que los usuarios desean acceso rápido a los datos en todos los tiempos para un pequeño conjunto de puntos lat-lon. Acceder a los datos para 1000 tiempos normalmente requeriría acceder a 1000 bloques de disco, lo que puede ser lento.

Reorganizar los datos en fragmentos en disco que tienen

all the time en cada fragmento para unas pocas coordenadas de latitud y longitud aceleraría enormemente dicho acceso. Para fragmentar los datos en el archivo de entrada slow.nc, un archivo netCDF de cualquier tipo, al archivo de salida fast.nc, puede usar:

nccopy -c time/1000,lat/40,lon/40 slow.nc fast.nc

para especificar fragmentos de datos de 1000 tiempos, 40 latitudes y 40 longitudes. Si tuviera suficiente memoria para contener el archivo de salida, podría acelerar significativamente la operación de re-fragmentación creando la salida en memoria antes de escribirla en disco al cerrar (usando la opción -w):

nccopy -w -c time/1000,lat/40,lon/40 slow.nc fast.nc

Alternativamente, se podría escribir esto usando la especificación de fragmentación alternativa y específica de la variable, asumiendo que 'times', 'lat' y 'lon' son variables.

nccopy -c time:1000 -c lat:40 -c lon:40 slow.nc fast.nc

Reglas de Fragmentación

El conjunto completo de reglas de fragmentación se captura aquí. Como resumen general, estas reglas conservan todas las propiedades de fragmentación del archivo de entrada. Estas reglas solo se aplican cuando el formato de salida seleccionado admite la fragmentación, es decir, para las variantes netcdf-4.

La especificación de fragmentación específica de la variable debe ser obvia y se traduce directamente a la llamada a la API correspondiente "nc_def_var_chunking".

La especificación original de fragmentación por dimensión requiere cierta interpretación por parte de nccopy. Las siguientes reglas se aplican en el orden dado de forma independiente para cada variable que se copia de la entrada a la salida. Las reglas están escritas asumiendo que estamos intentando determinar la fragmentación para una variable de salida dada Vout que proviene de una variable de entrada Vin.

1.
Si no hay una opción '-c' que se aplique a una variable y la variable de entrada correspondiente es contigua o la entrada es alguna variante netcdf-3, entonces deje que la biblioteca netcdf-c tome todas las decisiones de fragmentación.
2.
Para cada dimensión de Vout especificada explícitamente en la línea de comandos (usando la opción '-c'), aplique el valor de fragmentación para esa dimensión independientemente del formato de entrada o las propiedades de entrada.
3.
Para las dimensiones de Vout que no se nombran en la línea de comandos en una opción '-c', conserve los tamaños de fragmento de la variable de entrada correspondiente, si está fragmentada.
4.
Si Vin es contigua, y ninguna de sus dimensiones se nombra en la línea de comandos, y no se exige fragmentación por otras opciones, entonces haga que Vout sea contigua.
5.
Si la variable de entrada es contigua (o es alguna variante netcdf-3) y no hay opciones que requieran fragmentación, o se especifica el caso especial '/' para la opción '-c', entonces la variable de salida V se marca como contigua.
6.
Caso final y predeterminado: algunos o todos los tamaños de fragmento no se determinan por la línea de comandos o la variable de entrada. Esto incluye los casos de entrada no fragmentados como netcdf-3, cdf5 y DAP. En estos casos, conserve todos los tamaños de fragmento determinados por las reglas anteriores y use el tamaño completo de la dimensión como predeterminado. La excepción son las dimensiones ilimitadas, donde el valor predeterminado es de 4 megabytes.
