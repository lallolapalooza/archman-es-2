ncurses(3X) Llamadas a la biblioteca ncurses(3X)

NOMBRE

ncurses - interfaz de terminal de celdas de caracteres con salida optimizada

SINOPSIS

#include <curses.h>

DESCRIPCIÓN

La biblioteca "new curses" ofrece al programador un medio independiente de la terminal para leer la entrada del teclado y del ratón, y actualizar terminales de celdas de caracteres con una salida optimizada para minimizar las actualizaciones de pantalla. ncurses reemplaza las bibliotecas curses de System V Release 4 Unix ("SVr4") y 4.4BSD Unix, cuyo desarrollo cesó en la década de 1990. Este documento describe la versión 6.5 de ncurses (parche 20240427).

ncurses permite el control del contenido de la pantalla de la terminal; la abstracción y subdivisión de la misma con ventanas y pads; la lectura de entrada de terminal; el control de las opciones de entrada y salida de terminal; rutinas de consulta del entorno; manipulación de color; la definición y uso de teclas de etiquetas suaves; acceso a capacidades de terminfo; una interfaz de compatibilidad con termcap; y una abstracción de la API del sistema para manipular la terminal (como termios(3)).

ncurses implementa la interfaz estándar descrita por X/Open Curses Issue 7. En muchos detalles de comportamiento no estandarizados por X/Open, ncurses emula la biblioteca curses de SVr4 y proporciona numerosas extensiones útiles.

Las páginas del manual de ncurses emplean varias secciones para aclarar aspectos de uso e interoperabilidad con otras implementaciones de curses.

  • "NOTAS" describe problemas y advertencias de los que cualquier usuario de la API de ncurses debería ser consciente, como las limitaciones en el tamaño de un tipo integral subyacente o la disponibilidad de una macro preprocesador exclusiva de una definición de función (lo que impide que su dirección sea tomada). Esta sección también describe detalles de implementación que serán significativos para el programador pero que no están estandarizados.
  • "EXTENSIÓNES" presenta innovaciones de ncurses más allá del estándar X/Open Curses y/o la implementación curses de SVr4. Se denominan extensiones para indicar que no pueden implementarse únicamente utilizando la API de la biblioteca, sino que requieren acceso al estado interno de la biblioteca.
  • "PORTABILIDAD" discute aspectos (más allá del uso de extensiones) que deben considerarse al escribir para un estándar curses, o para múltiples implementaciones.
  • "HISTORIA" examina puntos de detalle en ncurses y otras implementaciones de curses a lo largo de las décadas de su desarrollo, particularmente donde el precedente o la inercia han frustrado un mejor diseño (y, en algunos casos, donde dicha inercia se ha superado).

Una aplicación curses debe enlazarse con la biblioteca; use la opción -lncurses en su compilador o enlazador. Una versión de depuración de la biblioteca puede estar disponible; si es así, enlácela con -lncurses_g. (Su integrador de sistemas puede haber instalado estas bibliotecas de tal manera que pueda usar las opciones -lcurses y -lcurses_g, respectivamente). La biblioteca ncurses_g genera registros de rastreo (en un archivo llamado trace en el directorio actual) que describen las acciones de ncurses. Consulte la sección "CONFIGURACIONES ALTERNATIVAS" más abajo.

Estructura de la aplicación

Una aplicación curses utiliza información del entorno local del sistema; setlocale(3) la prepara para las llamadas a la biblioteca curses.

setlocale(LC_ALL, "");

Si el entorno local no se inicializa de esta manera, la biblioteca asume que los caracteres son imprimibles como en ISO 8859-1, para funcionar con ciertos programas heredados. Debe inicializar el entorno local; no espere un comportamiento coherente de la biblioteca cuando no se haya configurado el entorno local.

initscr(3X) o newterm(3X) deben llamarse para inicializar curses antes de usar cualquier función que trate con ventanas y pantallas.

Para obtener entrada carácter por carácter sin eco (la mayoría de los programas interactivos orientados a pantalla lo desean), use la siguiente secuencia.

initscr(); cbreak(); noecho();

La mayoría de las aplicaciones realizan una configuración adicional de la siguiente manera.

intrflush(stdscr, FALSE);
keypad(stdscr, TRUE);

Un programa curses luego a menudo entra en un bucle de eventos de algún tipo. Llame a endwin(3X) antes de salir.

Visión general

Una biblioteca curses abstrae la pantalla de la terminal representando toda o parte de ella como una estructura de datos WINDOW. Una ventana es una cuadrícula rectangular de celdas de caracteres, dirigida por coordenadas de fila y columna (y, x), con la esquina superior izquierda como (0, 0). Una ventana llamada stdscr, del mismo tamaño que la pantalla de la terminal, siempre está disponible. Cree otras con newwin(3X).

Una biblioteca curses no gestiona ventanas superpuestas (pero consulte más abajo). Puede usar stdscr para gestionar una ventana que llene la pantalla, o dividir la pantalla en ventanas no superpuestas y no usar stdscr en absoluto. Mezclar los dos enfoques dará lugar a efectos impredecibles y no deseados.

Las funciones permiten la manipulación de una ventana y el cursor que identifica la celda dentro de ella en la que se producirá la próxima operación de salida. Entre ellas, las más básicas son move(3X) y addch(3X): estas colocan el cursor y escriben un carácter en stdscr, respectivamente.

Los cambios frecuentes en la pantalla de la terminal pueden causar parpadeo desagradable o un uso ineficiente del canal de comunicación con el dispositivo, por lo que la biblioteca generalmente no lo actualiza automáticamente. Por lo tanto, después de usar las funciones de curses para acumular un conjunto de actualizaciones deseadas que tengan sentido presentar juntas, llame a refresh(3X) para indicar a la biblioteca que haga que la pantalla del usuario se vea como stdscr. La biblioteca optimiza su salida calculando un número mínimo de operaciones para mutar la pantalla desde su estado anterior de refresh al nuevo. La optimización efectiva exige información precisa sobre el dispositivo terminal: la gestión de dicha información es dominio de la API de terminfo(3X), una característica de toda implementación estándar de curses.

También se pueden manipular ventanas especiales llamadas pads. Estas son ventanas que no están restringidas al tamaño de la pantalla de la terminal y cuyo contenido no necesita mostrarse por completo. Consulte curs_pad(3X).

Además de dibujar caracteres en la pantalla, se pueden admitir atributos y colores, haciendo que los caracteres aparezcan en modos como subrayado, video inverso o en color en terminales que admiten dichas mejoras de visualización. Consulte curs_attr(3X).

curses predefine constantes para un pequeño conjunto de gráficos de dibujo de formularios correspondientes al Conjunto de Caracteres Alternativo (ACS) de DEC, una característica de VT100 y otras terminales. Consulte waddch(3X).

curses se implementa utilizando el controlador de terminal del sistema operativo; los eventos de pulsación de teclas se reciben no como códigos de escaneo, sino como secuencias de bytes. Las teclas gráficas (teclas alfanuméricas y de puntuación, y el espacio) aparecen tal cual. Todo lo demás, incluidos los tabuladores, las teclas Intro/Retorno, de teclado, de flecha y de función, aparece como un carácter de control o una secuencia de escape multibyte. curses las traduce a códigos de tecla únicos. Consulte getch(3X).

ncurses proporciona reimplementaciones de las bibliotecas SVr4 panel(3X), form(3X) y menu(3X) para facilitar la construcción de interfaces de usuario con curses.

Inicialización

La selección de un valor apropiado de TERM en el entorno del proceso es esencial para el correcto funcionamiento de las bibliotecas curses y terminfo. Un sistema bien configurado selecciona un valor TERM correcto automáticamente; tset(1) puede ayudar a solucionar situaciones exóticas.

Si cambia el tipo de terminal, exporte la variable de entorno TERM antes de ejecutar la aplicación.

DESCRIPTION

This document describes the functions that are part of the curses library interface. The functions are grouped by function and interface. A complete list of functions is available in the function name index below.

The curses library provides functions for writing to the screen. It allows applications to control the terminal screen, draw lines, display text, and accept user input. It provides an abstraction layer for terminal capabilities.

The curses library is a set of functions that can be used to control any terminal screen. It has been designed to use the terminfo(5) database to find out how to use the terminal screen.

For applications using the curses library, the terminal type is assumed to be specified by the environment variable TERM. If this variable is not set, the library uses a default terminal type.

The terminfo database contains descriptions of terminal capabilities. The library uses these descriptions to control the terminal. If the terminal type is not found in the database, the library uses a default set of capabilities.

Initialization and cleanup are handled by the functions initscr, endwin, newterm, and delscreen. These functions initialize the curses library and set up the terminal for curses applications. They also handle cleanup of the terminal when the application exits.

The curses library provides functions for manipulating windows. Windows are rectangular regions on the screen. The functions allow applications to create, destroy, and manipulate windows. They also allow applications to draw text and graphics within windows.

Input and output are handled by the functions getch, getstr, addch, and addstr. These functions allow applications to read user input and display text on the screen. They also provide functions for controlling the cursor and attributes such as color and highlighting.

The curses library provides functions for handling colors. These functions allow applications to display text in different colors and with different attributes. The functions also allow applications to query the terminal's color capabilities.

TERMINAL TYPES

The curses library determines the terminal type from the environment variable TERM. If this variable is not set, or if the terminal type is not found in the terminfo database, the library uses a default terminal type. The terminal type can be overridden using the environment variable TERMINFO.

If the environment variable TERMINFO is set, curses looks first in the directory specified by TERMINFO for the terminal type description. If it is not found there, it then looks in the default location (usually /usr/share/terminfo).

The terminfo database is used to describe the capabilities of terminals. The library uses this information to control the terminal. For example, the database contains information about how to clear the screen, move the cursor, and change attributes such as color and highlighting.

Initialization of the terminal for curses applications is done using the initscr, newterm, and setupterm functions. These functions initialize the curses library and set up the terminal for curses applications. They also handle cleanup of the terminal when the application exits.

The function tset or the command “tput init” can be used to initialize the terminal. See subsection “Tabs and Initialization” of terminfo(5).

If the environment variables LINES and COLUMNS are set, or if the curses program is executing in a graphical windowing environment, the information obtained thence overrides that obtained by terminfo. An ncurses extension supports resizable terminals; see wresize(3X).

If the environment variable TERMINFO is defined, a curses program checks first for a terminal type description in the location it identifies. TERMINFO is useful for developing experimental type descriptions or when write permission to /usr/share/terminfo is not available.

See section “ENVIRONMENT” below.

Naming Conventions

curses offers many functions in variant forms using a regular set of alternatives to the name of an elemental one. Those prefixed with “w” require a WINDOW pointer argument; those with a “mv” prefix first perform cursor movement using wmove(3X); a “mvw” prefix indicates both. The “w” function is typically the elemental one; the removal of this prefix usually indicates operation on stdscr.

Four functions prefixed with “p” require a pad argument.

In function synopses, ncurses man pages apply the following names to parameters.

bf bool (TRUE or FALSE)
c a char or int
ch a chtype
wc a wchar_t or wint_t
wch a cchar_t
win pointer to a WINDOW
pad pointer to a WINDOW that is a pad

Wide and Non-wide Character Configurations

This manual page describes functions that appear in any configuration of the library. There are two common configurations; see section “ALTERNATE CONFIGURATIONS” below.

ncurses
is the library in its “non-wide” configuration, handling only eight-bit characters. It stores a character combined with attributes in a chtype datum, which is often an alias of int.
Attributes alone (with no corresponding character) can be stored in variables of chtype or attr_t type. In either case, they are represented as an integral bit mask.
Each cell of a WINDOW is stored as a chtype.
ncursesw
is the library in its “wide” configuration, which handles character encodings requiring a larger data type than char (a byte-sized type) can represent. It adds about one third more calls using additional data types that can store such multibyte characters.
cchar_t
corresponds to the non-wide configuration's chtype. It always a structure type, because it stores more data than fit into a standard scalar type. A character code may not be representable as a char, and moreover more than one character may occupy a cell (as with accent marks and other diacritics). Each character is of type wchar_t; a complex character contains one spacing character and zero or more non-spacing characters (see below). Attributes and color data are stored in separate fields of the structure, not combined as in chtype.

Each cell of a WINDOW is stored as a cchar_t.

setcchar(3X) and getcchar(3X) store and retrieve cchar_t data. The wide library API of ncurses depends on two data types standardized by ISO C95.

wchar_t
stores a wide character. Like chtype, it may be an alias of int. Depending on the character encoding, a wide character may be spacing, meaning that it occupies a character cell by itself and typically accompanies cursor advancement, or non-spacing, meaning that it occupies the same cell as a spacing character, is often regarded as a “modifier” of the base glyph with which it combines, and typically does not advance the cursor.
wint_t
can store a wchar_t or the constant WEOF, analogously to the int-sized character manipulation functions of ISO C and its constant EOF.
The wide library provides additional functions that complement those in the non-wide library where the size of the underlying character type is significant. A somewhat regular naming convention relates many of the wide variants to their non-wide counterparts; where a non-wide function name contains “ch” or “str”, prefix it with “_w” to obtain the wide counterpart. For example, waddch becomes wadd_wch. (Exceptions that add only “w” comprise addwstr, inwstr, and their variants.)
This convention is inapplicable to some non-wide function names, so other transformations are used for the wide configuration: the window background management function “bkgd” becomes “bkgrnd”; the window border-drawing and -clearing functions are suffixed with “_set”; and character attribute manipulation functions like “attron” become “attr_on”.
