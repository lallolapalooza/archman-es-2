ntpq(1) Comandos de usuario ntpq(1)

NOMBRE

ntpq - programa de consulta NTP estándar

SINOPSIS

ntpq [-flags] [-flag [valor]] [--nombre-opcion[[=| ]valor]] [ host ...]

DESCRIPCIÓN

La utilidad ntpq se utiliza para consultar servidores NTP para monitorizar las operaciones y el rendimiento de NTP, solicitando información sobre el estado actual y/o cambios en ese estado. El programa puede ejecutarse en modo interactivo o controlarse mediante argumentos de línea de comandos. Se pueden ensamblar solicitudes para leer y escribir variables arbitrarias, con opciones de salida en formato bruto y con formato bonito disponibles. La utilidad ntpq también puede obtener e imprimir una lista de pares en un formato común enviando múltiples consultas al servidor.

Si se incluye una o más opciones de solicitud en la línea de comandos cuando se ejecuta ntpq, cada una de las solicitudes se enviará a los servidores NTP que se ejecutan en cada uno de los hosts proporcionados en la línea de comandos, o en localhost por defecto. Si no se proporcionan opciones de solicitud, ntpq intentará leer comandos de la entrada estándar y ejecutarlos en el servidor NTP que se ejecuta en el primer host proporcionado en la línea de comandos, volviendo a usar localhost por defecto cuando no se especifica ningún otro host. La utilidad ntpq solicitará comandos si la entrada estándar es un dispositivo de terminal.

ntpq utiliza paquetes NTP de modo 6 para comunicarse con el servidor NTP y, por lo tanto, se puede utilizar para consultar cualquier servidor compatible en la red que lo permita. Tenga en cuenta que dado que NTP es un protocolo UDP, esta comunicación será algo poco fiable, especialmente en grandes distancias en términos de topología de red. La utilidad ntpq realiza un intento de retransmitir solicitudes y cancelará las solicitudes si no se recibe respuesta del host remoto dentro de un tiempo de espera adecuado.

Tenga en cuenta que en contextos donde se espera un nombre de host, un calificador -4 anterior al nombre del host fuerza la resolución al espacio de nombres IPv4, mientras que un calificador -6 fuerza la resolución al espacio de nombres IPv6. Para ver ejemplos y uso, consulte la página "Técnicas de depuración de NTP".

La especificación de una opción de línea de comandos que no sea -i o -n hará que la consulta (las consultas) especificada (s) se envíe (n) inmediatamente a los host (s) indicados. De lo contrario, ntpq intentará leer comandos en formato interactivo de la entrada estándar.

Comandos internos

Los comandos en formato interactivo consisten en una palabra clave seguida de cero a cuatro argumentos. Solo se necesitan escribir suficientes caracteres de la palabra clave completa para identificar de forma única el comando.

Varios comandos en formato interactivo se ejecutan completamente dentro de la propia utilidad ntpq y no dan lugar a que se envíen solicitudes NTP a un servidor. Estos se describen a continuación.

? [comando]

ayuda [comando]

Un ‘?’ por sí solo imprimirá una lista de todos los comandos conocidos por ntpq. Un ‘?’ seguido de un nombre de comando imprimirá información sobre la función y el uso del comando.
addvars nombre[=valor][,...]

rmvars nombre[,...]

clearvars

showvars

Los argumentos de este comando consisten en una lista de elementos de la forma nombre[=valor], donde el =valor
se ignora y se puede omitir en las solicitudes al servidor para leer variables. La utilidad ntpq mantiene una lista interna en la que se pueden ensamblar los datos que se incluirán en los mensajes, y mostrar o establecer utilizando los comandos readlist y writelist descritos a continuación. El comando addvars permite agregar variables y sus valores opcionales a la lista. Si se va a agregar más de una variable, la lista debe estar separada por comas y no contener espacios en blanco. El comando rmvars se puede usar para eliminar variables individuales de la lista, mientras que el comando clearvars elimina todas las variables de la lista. El comando showvars muestra la lista actual de variables opcionales.
authenticate [yes|no]

Normalmente, ntpq no autentica las solicitudes a menos que sean solicitudes de escritura. El comando authenticate yes hace que ntpq envíe autenticación con todas las solicitudes que realiza. Las solicitudes autenticadas hacen que algunos servidores manejen las solicitudes de manera ligeramente diferente. El comando authenticate hace que ntpq muestre si está autenticando solicitudes actualmente o no.
cooked

Hace que la salida de los comandos de consulta se "formatee", de modo que las variables que son reconocidas por ntpq tengan sus valores reformateados para el consumo humano. Las variables que ntpq no pudo decodificar completamente se marcan con un ‘?’ al final.
debug [more|less|off]

Sin argumento, muestra el nivel de depuración actual. De lo contrario, el nivel de depuración se cambia según lo indicado.
delay [milisegundos]

Especifica un intervalo de tiempo que se agregará a las marcas de tiempo incluidas en las solicitudes que requieren autenticación. Esto se usa para habilitar (poco fiable) la reconfiguración del servidor en rutas de red con retrasos largos o entre máquinas cuyos relojes no están sincronizados. De hecho, el servidor ahora no requiere marcas de tiempo en solicitudes autenticadas, por lo que este comando puede estar obsoleto. Sin argumentos, muestra el retraso actual.
drefid [hash|ipv4]

Muestra los refids como IPv4 o hash. Sin argumentos, muestra si los refids se muestran como direcciones IPv4 o hashes.
exit

Sale de ntpq.
host [nombre]

Establece el host al que se enviarán las consultas futuras. El nombre puede ser un nombre de host o una dirección numérica. Sin argumentos, muestra el host actual.
hostnames [yes|no]

Si se especifica yes, se imprimen nombres de host en las pantallas de información. Si se especifica no, se imprimen direcciones numéricas en su lugar. El valor predeterminado es yes, a menos que se modifique mediante el interruptor -n de la línea de comandos. Sin argumentos, muestra si se muestran nombres de host o direcciones numéricas.
keyid [keyid]

Este comando permite especificar un número de clave que se utilizará para autenticar las solicitudes de configuración. Debe corresponder al número de clave controlkey con el que el servidor se ha configurado para este propósito. Sin argumentos, muestra el keyid actual.
keytype [digest]

Especifica el algoritmo de resumen (digest) a utilizar para autenticar solicitudes, con el valor predeterminado MD5. Si ntpq se compiló con soporte de OpenSSL y OpenSSL está instalado, digest puede ser cualquier algoritmo de resumen de mensajes compatible con OpenSSL. Si no se proporciona ningún argumento, se muestra el algoritmo de resumen (digest) keytype actual utilizado.
ntpversion [1|2|3|4]

Establece el número de versión NTP que ntpq declara en los paquetes. Por defecto es 3, y tenga en cuenta que los mensajes de control de modo 6 (y los modos, de hecho) no existían en la versión 1 de NTP. Parece que no quedan servidores que exijan la versión 1. Sin argumento, muestra la versión NTP actual que se utilizará al comunicarse con los servidores.
passwd

Este comando le pide que escriba una contraseña (que no se mostrará)

Query Commands

authenticate [password]

This command is used to authenticate configuration requests. The password must correspond to the key configured for use by the NTP server for this purpose if such requests are to be successful.
poll [n] [verbose]

Consultar a un servidor NTP en modo cliente n veces. Poll no implementado todavía.
quit

Salir de ntpq.
raw

Hace que toda la salida de los comandos de consulta se imprima tal como se recibió del servidor remoto. La única formateo/interpretación que se realiza en los datos es la transformación de datos no ASCII en un formato imprimible (pero apenas comprensible).
timeout [milliseconds]

Especifica un período de tiempo de espera para las respuestas a las consultas del servidor. El valor predeterminado es de aproximadamente 5000 milisegundos. Sin argumentos, muestra el período de tiempo de espera actual. Tenga en cuenta que dado que ntpq reintenta cada consulta una vez después de un tiempo de espera, el tiempo total de espera para un tiempo de espera será el doble del valor de tiempo de espera establecido.
version

Muestra la versión del programa ntpq.

Comandos de Mensajes de Control

Los IDs de asociación se utilizan para identificar variables del sistema, de pares y del reloj. Las variables del sistema se les asigna un ID de asociación de cero y un espacio de nombres del sistema, mientras que a cada asociación se le asigna un ID de asociación distinto de cero y un espacio de nombres de pares. La mayoría de los comandos de control envían un solo mensaje al servidor y esperan un solo mensaje de respuesta. Las excepciones son el comando peers, que envía una serie de mensajes, y los comandos mreadlist y mreadvar, que iteran sobre un rango de asociaciones.

clocklist [associd]

Muestra todas las variables del reloj en la lista de variables para aquellas asociaciones que soportan un reloj de referencia.
clockvar [associd] [name[=value][] ,...]

Muestra una lista de variables del reloj para aquellas asociaciones que soportan un reloj de referencia.
:config línea de comando de configuración

Envía el resto de la línea de comando, incluyendo espacios en blanco, al servidor como un comando de configuración en tiempo de ejecución en el mismo formato que una línea en el archivo de configuración. Este comando es experimental hasta nuevo aviso y aclaración. Se requiere autenticación, por supuesto.

Envía cada línea de nombre_archivo al servidor como comandos de configuración en tiempo de ejecución en el mismo formato que las líneas en el archivo de configuración. Este comando es experimental hasta nuevo aviso y aclaración. Se requiere autenticación.
ifstats

Muestra el estado y las estadísticas de los contadores para cada dirección de interfaz de red local: número de interfaz, nombre de interfaz y dirección o broadcast, drops, flags, ttl, mc, received, sent, send failed, peers, uptime. Se requiere autenticación.
iostats

Muestra estadísticas de E/S de red y de reloj de referencia: tiempo desde el reinicio, búferes de recepción, búferes de recepción libres, búferes de recepción utilizados, recargas de bajo nivel, paquetes descartados, paquetes ignorados, paquetes recibidos, paquetes enviados, fallos de envío de paquetes, activaciones de entrada, activaciones de entrada útiles.

Muestra estadísticas de bucle del kernel y PPS: associd, status, offset del pll, frecuencia del pll, error máximo, error estimado, estado del kernel, constante de tiempo del pll, precisión, tolerancia de frecuencia, frecuencia pps, estabilidad pps, jitter pps, intervalo de calibración, ciclos de calibración, jitter excedido, estabilidad excedida, errores de calibración. Al igual que con la salida de otros ntpq, los tiempos están en milisegundos; los valores muy pequeños pueden mostrarse en notación exponencial. El valor de precisión que se muestra también está en milisegundos, a diferencia de la variable del sistema de precisión.
lassociations

Realiza la misma función que el comando associations, excepto que muestra asociaciones movilizadas y no movilizadas, incluyendo todos los clientes.
lopeers [-4|-6]

Muestra una lista de todos los pares y clientes que muestran dstadr (asociados con la versión IP dada).
lpassociations

Muestra la última lista de asociaciones obtenida, incluyendo todos los clientes.
lpeers [-4|-6]

Muestra una lista de todos los pares y clientes (asociados con la versión IP dada).
monstats

Muestra el estado, estadísticas y límites del módulo de monitorización: habilitado, direcciones, direcciones pico, direcciones máximas, recarga por encima del recuento, recarga más antigua que, kilobytes, kilobytes máximos.
mreadlist associdlo associdhi

Realiza la misma función que el comando readlist para un rango de IDs de asociación.
mreadvar associdlo associdhi [name][,...]

Este rango puede determinarse a partir de la lista mostrada por cualquier comando que muestre asociaciones.
mrv associdlo associdhi [name][,...]

Realiza la misma función que el comando readvar para un rango de IDs de asociación. Este rango puede determinarse a partir de la lista mostrada por cualquier comando que muestre asociaciones.
mrulist [limited | kod | mincount=count | laddr=localaddr | sort=[-]sortorder | resany=hexmask | resall=hexmask]

Muestra los recuentos de tráfico de las direcciones de origen vistas más recientemente, recopilados y mantenidos por el módulo de monitorización. Con la excepción de sort=[-]sortorder, las opciones filtran la lista devuelta por ntpd(8). Las opciones limited y kod devuelven solo entradas que representan direcciones de clientes de las cuales el último paquete recibido activó un descarte o una respuesta KoD. La opción mincount=count filtra entradas que representan menos de count paquetes. La opción laddr=localaddr filtra entradas de paquetes recibidos en cualquier dirección local que no sea localaddr. resany=hexmask y resall=hexmask filtran entradas que no contienen o que contienen menos de todos, respectivamente, de los bits en hexmask, que debe comenzar con 0x. El sortorder predeterminado es lstint y puede ser addr, avgint, count, lstint, o cualquiera de ellos precedido por ‘-’ para invertir el orden de clasificación. Las columnas de salida son:

readlist [associd]

rl [associd]

Muestra todas las variables del sistema o del peer. Si se omite el associd, se asume que es cero.
readvar [associd name[=value] [, ...]]

rv [associd name[=value] [, ...]]

Muestra las variables especificadas del sistema o del peer. Si associd es cero, las variables provienen del espacio de nombres de Variables del Sistema, de lo contrario, provienen del espacio de nombres de Variables de Peer. Se requiere el associd, ya que el mismo nombre puede ocurrir en ambos espacios. Si no se incluye ningún name, se muestran todas las variables operativas en el espacio de nombres. En este caso únicamente, si se omite el associd, se asume que es cero. Se especifican múltiples nombres con separadores de coma y sin espacios. Tenga en cuenta que los valores de tiempo se representan en milisegundos y los valores de frecuencia en partes por millón (PPM). Algunas marcas de tiempo NTP se representan en el formato AAAAMM DD TTTT, donde AAAA es el año, MM el mes del año, DD el día del mes y TTTT la hora del día.
reslist

Muestra la lista de control de acceso (restrict) para ntpq. Se requiere autenticación.
saveconfig filename

Guarda la configuración actual, incluyendo cualquier modificación en tiempo de ejecución realizada por :config o config-from-file, en el archivo del host del servidor NTP filename. Este comando será rechazado por el servidor a menos que aparezca en el archivo de configuración de ntpd(8). filename puede usar especificadores de formato de date(1) para sustituir la fecha y hora actuales, por ejemplo,
saveconfig ntp-%Y%m%d-%H%M%S.conf.
El nombre de archivo utilizado se almacena en la variable del sistema savedconfig. Se requiere autenticación.

Muestra el tiempo de actividad del sistema y los recuentos de paquetes mantenidos en el módulo de protocolo: tiempo de actividad, reinicio de sysstats, paquetes recibidos, versión actual, versión anterior, longitud o formato erróneos, autenticación fallida, declinado, restringido, limitación de velocidad, respuestas KoD, procesados para tiempo.
timerstats

Muestra los contadores del temporizador de intervalo: tiempo desde el reinicio, desbordamientos del temporizador, llamadas a transmitir.
writelist associd

Establece todas las variables del sistema o del peer incluidas en la lista de variables.
writevar associd name=value [, ...]

Establece las variables especificadas en la lista de variables. Si el associd es cero, las variables provienen del espacio de nombres de Variables del Sistema, de lo contrario, provienen del espacio de nombres de Variables de Peer. Se requiere el associd, ya que el mismo nombre puede ocurrir en ambos espacios. Se requiere autenticación.

Palabras de Estado y Códigos Kiss

El estado actual del programa operativo se muestra en un conjunto de palabras de estado mantenidas por el sistema. La información de estado también está disponible por asociación. Estas palabras se muestran mediante los comandos readlist y associations tanto en hexadecimal como en cadenas de bits cortas decodificadas. Los códigos, las cadenas y las explicaciones cortas se documentan en la página. La página también incluye una lista de mensajes del sistema y del peer, cuyo código más reciente se incluye en la palabra de estado.

La información resultante de las transiciones de estado de la máquina de protocolo se muestra utilizando un conjunto informal de cadenas ASCII llamado El propósito original era para paquetes kiss-o'-death (KoD) enviados por el servidor para informar al cliente de una condición inusual. Ahora se muestran, cuando es apropiado, en el campo del identificador de referencia en varias tablas.

OPCIONES

-4, --ipv4

Forzar la resolución de nombres IPv4. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: ipv6.

Forzar la resolución de los siguientes nombres de host en la línea de comandos al espacio de nombres IPv4.

-6, --ipv6

Forzar la resolución de nombres IPv6. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: ipv4.

Forzar la resolución de los siguientes nombres de host en la línea de comandos al espacio de nombres IPv6.

-c comando, --command=comando

Ejecutar un comando y salir. Esta opción puede aparecer un número ilimitado de veces.

El siguiente argumento se interpreta como un comando de formato interactivo y se añade a la lista de comandos a ejecutar en los hosts especificados.

-d, --debug-level

Aumentar el nivel de verbosidad de depuración. Esta opción puede aparecer un número ilimitado de veces.
-D número, --set-debug-level=número

Establecer el nivel de verbosidad de depuración. Esta opción puede aparecer un número ilimitado de veces. Esta opción toma un número entero como argumento.
-i, --interactive

Forzar que ntpq opere en modo interactivo. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: command, peers.

Forzar que ntpq opere en modo interactivo. Se mostrarán indicaciones en la salida estándar y se leerán comandos de la entrada estándar.

-n, --numeric

Direcciones de host numéricas.

Mostrar todas las direcciones de host en formato numérico de cuadruplete punteado en lugar de convertirlas a los nombres de host canónicos.

--old-rv

Mostrar siempre la línea de estado con readvar.

Por defecto, ntpq ahora suprime la línea associd=... que precede a la salida de readvar (alias rv) cuando se solicita una única variable, como ntpq -c "rv 0 offset". Esta opción hace que ntpq incluya ambas líneas de salida para un readvar de una sola variable. Usar una variable de entorno para preestablecer esta opción en un script hará que tanto el ntpq antiguo como el nuevo se comporten de manera idéntica en este aspecto.

-p, --peers

Mostrar una lista de los peers. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: interactive.

Mostrar una lista de los peers conocidos por el servidor, así como un resumen de su estado. Esto es equivalente al comando interactivo 'peers'.

-r palabra clave, --refid=palabra clave

Establecer el tipo de visualización predeterminado para los refids S2+. Esta opción toma una palabra clave como argumento. El argumento establece un valor de enumeración que puede ser probado comparándolo con la macro del valor de la opción. Las palabras clave disponibles son: 
hash ipv4
o su equivalente numérico.

La palabra clave predeterminada para esta opción es:
ipv4

Establecer el formato de visualización predeterminado para los refids S2+.

-u, --unconnected

Usar UDP no conectado para comunicarse con ntpd (predeterminado en Windows).

Abrir una asociación UDP no conectada a ntpd (el predeterminado en Windows).

-w, --wide

Mostrar el valor completo de 'remote'.

Mostrar el valor completo de 'remote'. Si esto requiere más de 15 caracteres, mostrar el valor completo, emitir una nueva línea y continuar la visualización de datos correctamente indentada en la siguiente línea.

-?, --help

Mostrar información de uso y salir.
-!, --more-help

Pasar la información de uso extendida a través de un paginador.
-> [archivo de configuración], --save-opts [=archivo de configuración]

Guardar el estado de las opciones en archivo de configuración. El predeterminado es el último archivo de configuración listado en la sección AJUSTES DE OPCIONES, más abajo. El comando saldrá después de actualizar el archivo de configuración.
-< archivo de configuración, --load-opts=archivo de configuración, --no-load-opts

Cargar opciones desde archivo de configuración. La forma no-load-opts deshabilitará la carga de archivos de configuración/RC/INI anteriores. --no-load-opts se procesa temprano, fuera de orden.
--version [{v|c|n}]

Mostrar la versión del programa y salir. El modo predeterminado es `v', una versión simple. El modo `c' mostrará información de copyright y `n' mostrará el aviso de copyright completo.
