ntpdc(1) Comandos de Usuario ntpdc(1)

NOMBRE

ntpdc - programa de control específico del proveedor para NTPD

SINOPSIS

ntpdc [-flags] [-flag [valor]] [--nombre-opcion[[=| ]valor]] [ host ...]

DESCRIPCIÓN

ntpdc está obsoleto. Por favor, use ntpq(1) en su lugar. Puede hacer todo lo que ntpdc solía hacer, y lo hace utilizando una interfaz mucho más sensata.

ntpdc es un programa de utilidad que se utiliza para consultar a ntpd(1) sobre su estado actual y solicitar cambios en ese estado. Utiliza los formatos de mensajes de control del modo 7 de NTP descritos en el código fuente. El programa puede ejecutarse en modo interactivo o controlarse mediante argumentos de línea de comandos. Se dispone de información detallada sobre el estado y las estadísticas a través de la interfaz de ntpdc . Además, casi todas las opciones de configuración que se pueden especificar al inicio utilizando el archivo de configuración de ntpd también se pueden especificar en tiempo de ejecución utilizando ntpdc.

OPCIONES

-4, --ipv4

Forzar la resolución de nombres DNS de IPv4. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: ipv6.

Fuerza la resolución DNS de los siguientes nombres de host en la línea de comandos al espacio de nombres IPv4.

-6, --ipv6

Forzar la resolución de nombres DNS de IPv6. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: ipv4.

Fuerza la resolución DNS de los siguientes nombres de host en la línea de comandos al espacio de nombres IPv6.

-c comando, --comando=comando

ejecutar un comando y salir. Esta opción puede aparecer un número ilimitado de veces.

El siguiente argumento se interpreta como un comando de formato interactivo y se añade a la lista de comandos que se ejecutarán en los host(s) especificados.

-d, --nivel-depuracion

Aumentar el nivel de verbosidad de depuración. Esta opción puede aparecer un número ilimitado de veces.
-D número, --establecer-nivel-depuracion=número

Establecer el nivel de verbosidad de depuración. Esta opción puede aparecer un número ilimitado de veces. Esta opción toma un número entero como argumento.
-i, --interactivo

Forzar a ntpq a operar en modo interactivo. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: comando, listpeers, peers, showpeers.

Forzar a ntpq a operar en modo interactivo. Se mostrarán indicadores en la salida estándar y se leerán los comandos de la entrada estándar.

-l, --listar-pares

Mostrar una lista de los pares. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: comando.

Muestra una lista de los pares conocidos por el servidor, así como un resumen de su estado. Esto es equivalente al comando interactivo 'listpeers'.

-n, --numerico

direcciones de host numéricas.

Muestra todas las direcciones de host en formato numérico de cuádruple punto en lugar de convertirlas a nombres de host canónicos.

-p, --pares

Mostrar una lista de los pares. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: comando.

Muestra una lista de los pares conocidos por el servidor, así como un resumen de su estado. Esto es equivalente al comando interactivo 'peers'.

-s, --mostrar-pares

Mostrar una lista de los pares. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: comando.

Muestra una lista de los pares conocidos por el servidor, así como un resumen de su estado. Esto es equivalente al comando interactivo 'dmpeers'.

-u, --no-conectado

Usar UDP no conectado para comunicarse con ntpd (predeterminado en Windows).

Abre una asociación UDP no conectada con ntpd (el valor predeterminado en Windows).

-?, --ayuda

Muestra información de uso y sale.
-!, --mas-ayuda

Pasa la información de uso extendida a través de un paginador.
-> [archivo_cfg], --guardar-opciones [=archivo_cfg]

Guarda el estado de las opciones en archivo_cfg. El valor predeterminado es el último archivo de configuración listado en la sección PREAJUSTES DE OPCIONES, abajo. El comando saldrá después de actualizar el archivo de configuración.
-< archivo_cfg, --cargar-opciones=archivo_cfg, --no-cargar-opciones

Carga las opciones desde archivo_cfg. La forma no-cargar-opciones desactivará la carga de archivos de configuración/rc/ini anteriores. --no-cargar-opciones se maneja temprano, fuera de orden.
--version [{v|c|n}]

Muestra la versión del programa y sale. El modo predeterminado es `v', una versión simple. El modo `c' mostrará información de derechos de autor y `n' mostrará el aviso de derechos de autor completo.

PREAJUSTES DE OPCIONES

Cualquier opción que no esté marcada como no preajustable puede ser preajustada cargando valores de archivos de configuración ("RC" o ".INI") y valores de variables de entorno llamadas:

  NTPDC_<nombre-opcion> o NTPDC

Los preajustes ambientales tienen prioridad (se procesan más tarde que) sobre los archivos de configuración. Los archivos homerc son "$HOME" y ".". Si alguno de estos son directorios, entonces se busca el archivo .ntprc dentro de esos directorios.

USO

Si se incluyen una o más opciones de solicitud en la línea de comandos cuando se ejecuta ntpdc, cada una de las solicitudes se enviará a los servidores NTP que se ejecutan en cada uno de los hosts dados como argumentos de línea de comandos, o en localhost por defecto. Si no se proporcionan opciones de solicitud, ntpdc intentará leer comandos de la entrada estándar y ejecutarlos en el servidor NTP que se ejecuta en el primer host proporcionado en la línea de comandos, volviendo a utilizar localhost cuando no se especifica ningún otro host. La utilidad ntpdc pedirá comandos si la entrada estándar es un dispositivo de terminal.

La utilidad ntpdc utiliza paquetes NTP del modo 7 para comunicarse con el servidor NTP, y por lo tanto puede ser utilizada para consultar cualquier servidor compatible en la red que lo permita. Tenga en cuenta que dado que NTP es un protocolo UDP, esta comunicación será algo poco fiable, especialmente a largas distancias en términos de topología de red. La utilidad ntpdc no intenta retransmitir solicitudes y las solicitudes de tiempo de espera si no se recibe respuesta del host remoto dentro de un tiempo de espera adecuado.

El funcionamiento de ntpdc es específico de la implementación particular del demonio ntpd(1) y se puede esperar que funcione solo con esta y quizás algunas versiones anteriores del demonio. Las solicitudes de una utilidad ntpdc remota que afecten el estado del servidor local deben ser autenticadas, lo que requiere que tanto el programa remoto como el servidor local compartan una clave e identificador de clave comunes.

Tenga en cuenta que en contextos donde se espera un nombre de host, un calificador -4 que precede al nombre de host fuerza la resolución DNS al espacio de nombres IPv4, mientras que un calificador -6 fuerza la resolución DNS al espacio de nombres IPv6. Especificar una opción de línea de comandos que no sea -i o -n hará que la consulta especificada (consultas) se envíe inmediatamente a los hosts indicados. De lo contrario, ntpdc intentará leer comandos de formato interactivo de la entrada estándar.

Comandos interactivos

Los comandos de formato interactivo consisten en una palabra clave seguida de cero a cuatro argumentos. Solo se necesitan suficientes caracteres de la palabra clave completa para identificarla de forma única

ntpdc COMMAND SYNTAX

All commands must be typed on a single line. The output of a command is normally sent to the standard output, but optionally the output of individual commands may be sent to a file by appending a ‘>’, followed by a file name, to the command line.

A number of interactive format commands are executed entirely within the ntpdc utility itself and do not result in NTP mode 7 requests being sent to a server. These are described following.

? command_keyword

help command_keyword

A ‘?’ will print a list of all the command keywords known to this incarnation of ntpdc. A ‘?’ followed by a command keyword will print function and usage information about the command. This command is probably a better source of information about ntpq(1) than this manual page.
delay milliseconds

Specify a time interval to be added to timestamps included in requests which require authentication. This is used to enable (unreliable) server reconfiguration over long delay network paths or between machines whose clocks are unsynchronized. Actually the server does not now require timestamps in authenticated requests, so this command may be obsolete.
host hostname

Set the host to which future queries will be sent. Hostname may be either a host name or a numeric address.
hostnames [yes | no]

If yes is specified, host names are printed in information displays. If no is specified, numeric addresses are printed instead. The default is yes, unless modified using the command line -n switch.
keyid keyid

This command allows the specification of a key number to be used to authenticate configuration requests. This must correspond to a key number the server has been configured to use for this purpose.
quit

Exit ntpdc.
passwd

This command prompts you to type in a password (which will not be echoed) which will be used to authenticate configuration requests. The password must correspond to the key configured for use by the NTP server for this purpose if such requests are to be successful.
timeout milliseconds

Specify a timeout period for responses to server queries. The default is about 8000 milliseconds. Note that since ntpdc retries each query once after a timeout, the total waiting time for a timeout will be twice the timeout value set.

Control Message Commands

Query commands result in NTP mode 7 packets containing requests for information being sent to the server. These are read-only commands in that they make no modification of the server configuration state.

listpeers

Obtains and prints a brief list of the peers for which the server is maintaining state. These should include all configured peer associations as well as those peers whose stratum is such that they are considered by the server to be possible future synchronization candidates.
peers

Obtains a list of peers for which the server is maintaining state, along with a summary of that state. Summary information includes the address of the remote peer, the local interface address (0.0.0.0 if a local address has yet to be determined), the stratum of the remote peer (a stratum of 16 indicates the remote peer is unsynchronized), the polling interval, in seconds, the reachability register, in octal, and the current estimated delay, offset and dispersion of the peer, all in seconds.

The character in the left margin indicates the mode this peer entry is operating in. A ‘+’ denotes symmetric active, a ‘-’ indicates symmetric passive, a ‘=’ means the remote server is being polled in client mode, a ‘^’ indicates that the server is broadcasting to this address, a ‘~’ denotes that the remote peer is sending broadcasts and a ‘~’ denotes that the remote peer is sending broadcasts and a ‘*’ marks the peer the server is currently synchronizing to.

The contents of the host field may be one of four forms. It may be a host name, an IP address, a reference clock implementation name with its parameter or REFCLK() On hostnames no only IP-addresses will be displayed.

dmpeers

A slightly different peer summary list. Identical to the output of the peers command, except for the character in the leftmost column. Characters only appear beside peers which were included in the final stage of the clock selection algorithm. A ‘.’ indicates that this peer was cast off in the falseticker detection, while a ‘+’ indicates that the peer made it through. A ‘*’ denotes the peer the server is currently synchronizing with.
showpeer peer_address [...]

Shows a detailed display of the current peer variables for one or more peers. Most of these values are described in the NTP Version 2 specification.
pstats peer_address [...]

Show per-peer statistic counters associated with the specified peer(s).
clockstat clock_peer_address [...]

Obtain and print information concerning a peer clock. The values obtained provide information on the setting of fudge factors and other clock performance information.
kerninfo

Obtain and print kernel phase-lock loop operating parameters. This information is available only if the kernel has been specially modified for a precision timekeeping function.
loopinfo [oneline | multiline]

Print the values of selected loop filter variables. The loop filter is the part of NTP which deals with adjusting the local system clock. The ‘offset’ is the last offset given to the loop filter by the packet processing code. The ‘frequency’ is the frequency error of the local clock in parts-per-million (ppm). The ‘time_const’ controls the stiffness of the phase-lock loop and thus the speed at which it can adapt to oscillator drift. The ‘watchdog timer’ value is the number of seconds which have elapsed since the last sample offset was given to the loop filter. The oneline and multiline options specify the format in which this information is to be printed, with multiline as the default.
sysinfo

Print a variety of system state variables, i.e., state related to the local server. All except the last four lines are described in the NTP Version 3 specification, RFC-1305.

The ‘system flags’ show various system flags, some of which can be set and cleared by the enable and disable configuration commands, respectively. These are the auth, bclient, monitor, pll, pps and stats flags. See the ntpd(1) documentation for the meaning of these flags. There are two additional flags which are read only, the kernel_pll and kernel_pps. These flags indicate the synchronization status when the precision time kernel modifications are in use. The ‘kernel_pll’ indicates that the local clock is being disciplined by the kernel, while the ‘kernel_pps’ indicates the kernel discipline is provided by the PPS signal.

The ‘stability’ is the residual frequency error remaining after the system frequency correction is applied and is intended for maintenance and debugging. In most architectures, this value will initially decrease from as high as 500 ppm to a nominal value in the range .01 to 0.1 ppm. If it remains high for some time after starting the daemon, something may be wrong with the local clock, or the value of the kernel variable kern.clockrate.tick may be incorrect.

The ‘broadcastdelay’ shows the default broadcast delay, as set by the broadcastdelay configuration command.

The ‘authdelay’ shows the default authentication delay, as set by the authdelay configuration command.

sysstats

Print statistics counters maintained in the protocol module.
memstats

Print statistics counters related to memory allocation code.
iostats

Print statistics counters maintained in the input-output module.
timerstats

Print statistics counters maintained in the timer/event queue support code.
reslist

Obtain and print the server's restriction list. This list is (usually) printed in sorted order and may help to understand how the restrictions are applied.
monlist [version]

Obtain and print traffic counts collected and maintained by the monitor facility. The version number should not normally need to be specified.
clkbug clock_peer_address [...]

Obtener información de depuración para un controlador de reloj de referencia. Esta información solo la proporcionan algunos controladores de reloj y es en su mayoría irrecuperable sin una copia del código fuente del controlador a mano.

Solicitudes de Configuración en Tiempo de Ejecución

Todas las solicitudes que causan cambios de estado en el servidor son autenticadas por el servidor utilizando una clave NTP configurada (la instalación también puede ser deshabilitada por el servidor al no configurar una clave). El número de clave y la clave correspondiente también deben ser conocidos por ntpdc. Esto se puede hacer usando los comandos keyid y passwd, el último de los cuales solicitará en la terminal una contraseña para usar como clave de cifrado. También se le solicitarán automáticamente tanto el número de clave como la contraseña la primera vez que se introduzca un comando que resulte en una solicitud autenticada al servidor. La autenticación no solo proporciona verificación de que el solicitante tiene permiso para realizar dichos cambios, sino que también ofrece un grado adicional de protección contra errores de transmisión.

Las solicitudes autenticadas siempre incluyen una marca de tiempo en los datos del paquete, que se incluye en el cálculo del código de autenticación. El servidor compara esta marca de tiempo con su marca de tiempo de recepción. Si difieren en más de una pequeña cantidad, la solicitud se rechaza. Esto se hace por dos razones. Primero, hace que los ataques de repetición simples contra el servidor, por parte de alguien que pueda estar escuchando el tráfico en su LAN, sean mucho más difíciles. Segundo, dificulta la solicitud de cambios de configuración a su servidor desde hosts topológicamente remotos. Si bien la instalación de reconfiguración funcionará bien con un servidor en el host local, y puede funcionar adecuadamente entre hosts sincronizados en el tiempo en la misma LAN, funcionará muy mal para hosts más distantes. Como tal, si se eligen contraseñas razonables, se tiene cuidado en la distribución y protección de las claves y se aplican las restricciones apropiadas de dirección de origen, la instalación de reconfiguración en tiempo de ejecución debería proporcionar un nivel de seguridad adecuado.

Los siguientes comandos realizan solicitudes autenticadas.

addpeer peer_address [keyid] [version] [prefer]

Agrega una asociación de par configurada en la dirección dada y operando en modo activo simétrico. Tenga en cuenta que una asociación existente con el mismo par puede eliminarse cuando se ejecuta este comando, o simplemente puede convertirse para ajustarse a la nueva configuración, según corresponda. Si el keyid opcional es un entero distinto de cero, todos los paquetes salientes al servidor remoto tendrán un campo de autenticación adjunto cifrado con esta clave. Si el valor es 0 (o no se proporciona), no se realizará ninguna autenticación. La version puede ser 1, 2 o 3 y por defecto es 3. La palabra clave prefer indica un par preferido (y por lo tanto se utilizará principalmente para la sincronización del reloj si es posible). El par preferido también determina la validez de la señal PPS: si el par preferido es adecuado para la sincronización, también lo es la señal PPS.
addserver peer_address [keyid] [version] [prefer]

Idéntico al comando addpeer, excepto que el modo de operación es cliente.
broadcast peer_address [keyid] [version] [prefer]

Idéntico al comando addpeer, excepto que el modo de operación es difusión. En este caso, se requiere un identificador de clave y una clave válidos. El parámetro peer_address puede ser la dirección de difusión de la red local o una dirección de grupo multicast asignada a NTP. Si es una dirección multicast, se requiere un kernel con capacidad de multicast.
unconfig peer_address [...]

Este comando provoca la eliminación del bit configurado de los pares especificados. En muchos casos, esto provocará la eliminación de la asociación de par. Cuando sea apropiado, sin embargo, la asociación puede persistir en un modo no configurado si el par remoto está dispuesto a continuar de esta manera.
fudge peer_address [time1] [time2] [stratum] [refid]

Este comando proporciona una forma de establecer ciertos datos para un reloj de referencia. Consulte la lista de códigos fuente para obtener más información.
enable [auth | bclient | calibrate | kernel | monitor | ntp | pps | stats]

disable [auth | bclient | calibrate | kernel | monitor | ntp | pps | stats]

Estos comandos funcionan de la misma manera que los comandos de archivo de configuración enable y disable de ntpd(1).
auth

Permite que el servidor se sincronice con pares no configurados solo si el par ha sido autenticado correctamente utilizando criptografía de clave pública o clave privada. El valor predeterminado para este indicador es habilitar.
bclient

Permite que el servidor escuche un mensaje de un servidor de difusión o multicast, como en el comando multicastclient con la dirección predeterminada. El valor predeterminado para este indicador es deshabilitar.
calibrate

Permite la función de calibración para relojes de referencia. El valor predeterminado para este indicador es deshabilitar.
kernel

Permite la disciplina de tiempo del kernel, si está disponible. El valor predeterminado para este indicador es habilitar si hay soporte disponible, de lo contrario, deshabilitar.
monitor

Permite la instalación de monitoreo. Consulte la documentación aquí sobre el comando monlist o para obtener más información. El valor predeterminado para este indicador es habilitar.
ntp

Permite la disciplina de tiempo y frecuencia. En efecto, este interruptor abre y cierra el bucle de retroalimentación, lo cual es útil para pruebas. El valor predeterminado para este indicador es habilitar.
pps

Permite la señal de pulso por segundo (PPS) cuando la frecuencia y el tiempo son disciplinados por las modificaciones del kernel de tiempo de precisión. Consulte la página "Un modelo de kernel para la gestión precisa del tiempo" (disponible como parte de la documentación HTML proporcionada en /usr/share/doc/ntp) para obtener más información. El valor predeterminado para este indicador es deshabilitar.
stats

Permite la instalación de estadísticas. Consulte la sección Opciones de monitoreo de ntp.conf(5) para obtener más información. El valor predeterminado para este indicador es deshabilitar.
restrict address mask flag [...]

Este comando funciona de la misma manera que los comandos de archivo de configuración restrict de ntpd(1).
unrestrict address mask flag [...]

Anula la restricción de la entrada coincidente de la lista de restricciones.
delrestrict address mask [ntpport]

Elimina la entrada coincidente de la lista de restricciones.
readkeys

Provoca que el conjunto actual de claves de autenticación se elimine y se obtenga un nuevo conjunto al volver a leer el archivo de claves (que debe haber sido especificado en el archivo de configuración de ntpd(1)). Esto permite cambiar las claves de cifrado sin reiniciar el servidor.
trustedkey keyid [...]

untrustedkey keyid [...]

Estos comandos funcionan de la misma manera que los comandos de archivo de configuración trustedkey y untrustedkey de ntpd(1).
authinfo

Devuelve información sobre el módulo de autenticación, incluidas las claves conocidas y los recuentos de cifrados y descifrados que se han realizado.
traps

Muestra las trampas establecidas en el servidor. Consulte la lista de códigos fuente para obtener más información.
addtrap address [port] [interface]

Establece una trampa para mensajes asíncronos. Consulte la lista de códigos fuente para obtener más información.
clrtrap address [port] [interface]

Borra una trampa para mensajes asíncronos. Consulte la lista de códigos fuente para obtener más información.
reset

Borra los contadores de estadísticas en varios módulos del servidor. Consulte la lista de códigos fuente para obtener más información.
