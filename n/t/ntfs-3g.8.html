NTFS-3G(8) Manual del Administrador del Sistema NTFS-3G(8)

NOMBRE

ntfs-3g - Driver NTFS de Tercera Generación de Lectura/Escritura

SINOPSIS

ntfs-3g [-o opción[,...]] volumen punto_montaje
mount -t ntfs-3g [-o opción[,...]] volumen punto_montaje
lowntfs-3g [-o opción[,...]] volumen punto_montaje
mount -t lowntfs-3g [-o opción[,...]] volumen punto_montaje

DESCRIPCIÓN

ntfs-3g es un driver NTFS, que puede crear, eliminar, renombrar, mover archivos, directorios, enlaces duros y flujos; puede leer y escribir archivos, incluyendo flujos, archivos dispersos y archivos comprimidos transparentemente; puede manejar archivos especiales como enlaces simbólicos, dispositivos y FIFOs; además proporciona gestión estándar de la propiedad y permisos de archivos, incluyendo ACLs POSIX.

Viene en dos variantes, ntfs-3g y lowntfs-3g, con unas pocas diferencias mencionadas más abajo en las descripciones de las opciones relevantes.

El volumen a montar puede ser un dispositivo de bloque o un archivo de imagen, ya sea utilizando el comando mount o iniciando el disco.

Hibernación y reinicio rápido de Windows

En computadoras que pueden arrancar dualmente en Windows o Linux, Windows debe ser completamente apagado antes de arrancar en Linux, de lo contrario, los sistemas de archivos NTFS en discos internos pueden quedar en un estado inconsistente y los cambios realizados por Linux pueden ser ignorados por Windows.

Por lo tanto, Windows no puede dejarse en hibernación al iniciar Linux, para evitar inconsistencias. Además, la función de reinicio rápido disponible en sistemas Windows recientes debe ser deshabilitada. Esto se puede lograr ejecutando como Administrador el comando de Windows que deshabilita tanto la hibernación como el reinicio rápido:

powercfg /h off

Si Windows está hibernado o su reinicio rápido está habilitado, las particiones en discos internos se montarán forzosamente en modo de solo lectura.

Manejo de Accesos y Seguridad

Por defecto, los archivos y directorios son propiedad del usuario y grupo efectivos del proceso de montaje, y todos tienen permisos completos de lectura, escritura, ejecución y navegación de directorios. También puede asignar permisos a un solo usuario usando las opciones uid y/o gid junto con las opciones umask, o fmask y dmask.

Al hacer esto, todos los usuarios de Windows tienen acceso completo a los archivos creados por ntfs-3g.

Pero, al establecer la opción permissions, puede beneficiarse de las características completas de propiedad y permisos según lo definido por POSIX. Además, al definir un mapeo de usuario de Windows a Linux, las propiedades y permisos se aplican incluso a usuarios de Windows y viceversa.

Si ntfs-3g está configurado como setuid-root, los usuarios no root también podrán montar volúmenes.

Compatibilidad de Nombres de Archivo de Windows

NTFS soporta varios espacios de nombres para nombres de archivo: DOS, Win32 y POSIX. Mientras que el driver ntfs-3g maneja todos ellos, siempre crea nuevos archivos en el espacio de nombres POSIX por razones de máxima portabilidad e interoperabilidad. Esto significa que los nombres de archivo distinguen entre mayúsculas y minúsculas y se permiten todos los caracteres excepto '/' y '\0'. Esto es perfectamente legal en Windows, aunque algunas aplicaciones pueden confundirse. La opción windows_names puede usarse para aplicar restricciones de Windows a los nuevos nombres de archivo.

Flujos de Datos Alternativos (ADS)

NTFS almacena todos los datos en flujos. Cada archivo tiene exactamente un flujo de datos sin nombre y puede tener muchos flujos de datos con nombre. El tamaño de un archivo es el tamaño de su flujo de datos sin nombre. Por defecto, ntfs-3g solo leerá el flujo de datos sin nombre.

Usando la opción streams_interface=windows, con el driver ntfs-3g (no es posible con lowntfs-3g), podrá leer cualquier flujo de datos con nombre, simplemente especificando el nombre del flujo después de dos puntos. Por ejemplo:

cat some.mp3:artist

Los flujos de datos con nombre actúan como archivos normales, por lo que puede leerlos, escribir en ellos e incluso eliminarlos (usando rm). Puede listar todos los flujos de datos con nombre que tiene un archivo obteniendo el atributo extendido ntfs.streams.list.

OPCIONES

A continuación se presenta un resumen de las opciones que ntfs-3g acepta.

acl
Permite establecer ACLs de Posix en archivos creados y usarlas para el control de acceso. Esta opción solo está disponible en compilaciones específicas. Está habilitada por defecto cuando existe un archivo de mapeo de usuario y la opción de montaje permissions no está establecida.
allow_other
Esta opción anula la medida de seguridad que restringe el acceso a los archivos al usuario que monta el sistema de archivos. Esta opción solo está permitida para root, pero esta restricción puede ser anulada por la opción user_allow_other en el archivo /etc/fuse.conf.
atime, noatime, relatime
La opción atime actualiza la hora de acceso del inodo para cada acceso.

La opción noatime deshabilita las actualizaciones de la hora de acceso del inodo, lo que puede acelerar las operaciones de archivos y evitar que los discos de suspensión (portátiles) giren con demasiada frecuencia, ahorrando así energía y prolongando la vida útil del disco.

La opción relatime es muy similar a noatime. Actualiza las horas de acceso del inodo en relación con la hora de modificación o cambio. La hora de acceso solo se actualiza si la hora de acceso anterior era anterior a la hora de modificación o cambio actual. A diferencia de noatime, esta opción no interrumpe aplicaciones que necesitan saber si un archivo ha sido leído desde la última vez que se modificó. Este es el comportamiento por defecto.

big_writes
Esta opción evita que fuse divida los búferes de escritura en fragmentos de 4K, permitiendo que los búferes de escritura grandes se transfieran de la aplicación en un solo paso (hasta cierto límite del sistema, generalmente 128K bytes).
compression
Esta opción permite crear nuevos archivos comprimidos transparentemente en directorios marcados para compresión. Un directorio se marca para compresión estableciendo el bit 11 (valor 0x00000800) en su atributo de Windows. En dicho directorio, los nuevos archivos se crean comprimidos y los nuevos subdirectorios se marcan para compresión. La opción y la bandera no tienen efecto en archivos existentes. Actualmente esta es la opción por defecto.
debug
Hace que ntfs-3g (o lowntfs-3g) imprima mucha salida de depuración de libntfs-3g y FUSE.
delay_mtime[= valor]
Solo actualiza la hora de modificación del archivo y la hora de cambio del archivo cuando este se cierra o cuando ha transcurrido el retraso indicado desde la última actualización. El argumento es un número de segundos, con un valor por defecto de 60. Esto es principalmente útil para archivos grandes que se mantienen abiertos durante mucho tiempo y se escriben en ellos sin cambiar su tamaño, como bases de datos o imágenes de sistemas de archivos montadas como bucle.
dmask=valor
Establece la máscara de bits de los permisos del directorio que no están presentes. El valor se da en octal. El valor por defecto es 0, lo que significa acceso completo para todos.
efs_raw
Esta opción solo debe usarse en situaciones de copia de seguridad o restauración. Cambia el tamaño aparente de los archivos y el comportamiento de las operaciones de lectura y escritura para que los archivos cifrados puedan guardarse y restaurarse sin ser descifrados. El atributo extendido user.ntfs.efsinfo también debe guardarse y restaurarse para que el archivo pueda ser descifrado.
fmask=valor
Establece la máscara de bits de los permisos del archivo que no están presentes. El valor se da en octal. El valor por defecto es 0, lo que significa acceso completo para todos.
force
Fuer

es: la opción está obsoleta. Ha sido reemplazada por las opciones recover y norecover.
hide_dot_files
Establece el atributo oculto en el atributo NTFS para los archivos y directorios creados cuyo primer carácter del nombre es un punto. Dichos archivos y directorios normalmente no aparecen en las listas de directorios y, cuando se establece el atributo, tampoco aparecen en las visualizaciones de directorios de Windows. Cuando un archivo se renombra o se enlaza con un nombre nuevo, el atributo oculto se ajusta al nombre más reciente.
hide_hid_files
Oculta los archivos y directorios ocultos en las listas de directorios, siendo archivos y directorios ocultos aquellos cuyos atributos NTFS tienen establecido el indicador de oculto. Los archivos ocultos no se seleccionarán al usar comodines en comandos, pero todos los archivos y directorios seguirán siendo accesibles por su nombre completo, por ejemplo, siempre puedes mostrar el directorio de la papelera de reciclaje de Windows con: "ls -ld '$RECYCLE.BIN'".
ignore_case (solo con lowntfs-3g)
Ignora las mayúsculas y minúsculas al acceder a un archivo (FOO, Foo, foo, etc. designan el mismo archivo). Todos los archivos se muestran en minúsculas en las listas de directorios.
inherit
Al crear un archivo nuevo, establece sus protecciones iniciales según las reglas de herencia definidas en el directorio padre. Estas reglas se desvían de las especificaciones de Posix, pero ofrecen una mejor compatibilidad con Windows. Se requiere la opción permissions (o **acl**) o un archivo de mapeo de usuarios válido para que esta opción sea efectiva.
locale=valor
Esta opción puede ser útil si deseas un entorno de localización específico del idioma. Sin embargo, se desaconseja, ya que provoca que los archivos con caracteres intraducibles no sean visibles.
max_read=valor
Con esta opción se puede establecer el tamaño máximo de las operaciones de lectura. El valor predeterminado es infinito. Ten en cuenta que el tamaño de las solicitudes de lectura está limitado de todos modos por el sistema (generalmente a 128 kbytes).
no_def_opts
Por defecto, ntfs-3g actúa como si se establecieran silent (ignora los errores de permisos cuando los permisos no están habilitados), allow_other (permite que cualquier usuario acceda a los archivos) y nonempty (permite montar en directorios no vacíos), y no_def_opts cancela estas opciones predeterminadas.
no_detach
Hace que ntfs-3g no se desvincule de la terminal e imprima alguna salida de depuración.
nocompression
Esta opción deshabilita la creación de nuevos archivos transparentemente comprimidos en directorios marcados para compresión. Los archivos comprimidos existentes aún se pueden leer y actualizar.
norecover
No intentes montar una partición que no fue desmontada correctamente por Windows.
permissions
Establece permisos estándar en los archivos creados y utiliza control de acceso estándar. Esta opción se establece por defecto cuando hay un archivo de mapeo de usuarios presente.
posix_nlink
Calcula el número de enlaces duros de un archivo o directorio según las especificaciones POSIX. Cuando esta opción no está establecida, se establece un recuento de 1 para los directorios, y se tiene en cuenta el nombre corto de los archivos. El uso de la opción implica una penalización, ya que el recuento no se almacena y debe calcularse.
recover
Recupera e intenta montar una partición que no fue desmontada correctamente por Windows. Se borra el archivo de registro de Windows, lo que puede causar inconsistencias. Actualmente esta es la opción predeterminada.
remove_hiberfile
Cuando el volumen NTFS está hibernado, se deniega un montaje de lectura-escritura y se fuerza un montaje de solo lectura. Se necesita o bien reanudar Windows y apagarlo correctamente, o usar esta opción que eliminará el archivo de hibernación de Windows. Ten en cuenta que esto significa que la sesión de Windows guardada se perderá por completo. Usa esta opción bajo tu propia responsabilidad.
ro
Monta el sistema de archivos en modo de solo lectura. Útil si Windows está hibernado o el archivo de registro de NTFS no está limpio.
show_sys_files
Muestra los metarchivos en las listas de directorios. De lo contrario, el comportamiento predeterminado es ocultar los metarchivos, que son archivos especiales utilizados para almacenar la estructura NTFS. Ten en cuenta que incluso cuando se especifica esta opción, "$MFT" puede no ser visible debido a un error de glibc. Además, independientemente de show_sys_files, todos los archivos son accesibles por nombre, por ejemplo, siempre puedes hacer "ls -l '$UpCase'".
silent
No hace nada, sin devolver ningún error, en las operaciones chmod y chown y en los errores de comprobación de permisos, cuando la opción permissions no está establecida y no hay un archivo de mapeo de usuarios definido. Esta opción está activada por defecto, y cuando se desactiva (a través de la opción no_def_opts) se deben establecer los parámetros de propiedad y permisos.
special_files=modo
Esta opción selecciona un modo para representar un archivo especial que se va a crear (enlace simbólico, socket, fifo, dispositivo de caracteres o bloque). El modo puede ser interix o wsl, y los archivos existentes en cualquiera de los modos se reconocen independientemente del modo seleccionado. Interix es el modo tradicional, utilizado por defecto, y wsl es interoperable con WSL de Windows, pero no es compatible con versiones de Windows anteriores a Windows 10. Ninguno de los modos es interoperable con Windows.
streams_interface=modo
Esta opción controla cómo el usuario puede acceder a los Flujos de Datos Alternativos (ADS) o, en otras palabras, flujos de datos con nombre. El modo se puede establecer en none, windows o xattr. Si la opción se establece en none, el usuario no tendrá acceso a los flujos de datos con nombre. Si se establece en windows (no es posible con lowntfs-3g), entonces el usuario puede acceder a ellos como en Windows (por ejemplo, cat file:stream). Si se establece en xattr, los flujos de datos con nombre se mapean a atributos extendidos y un usuario puede manipularlos usando las utilidades {get,set}fattr. El valor predeterminado es xattr.
uid=valor y gid=valor
Establece el propietario y el grupo de archivos y directorios. Los valores son numéricos. Los valores predeterminados son el uid y gid del proceso actual.
umask=valor
Establece la máscara de bits de los permisos de archivo y directorio que no están presentes. El valor se da en octal. El valor predeterminado es 0, lo que significa acceso completo para todos.
usermapping=nombre-archivo
Utiliza el archivo nombre-archivo como archivo de mapeo de usuarios en lugar del predeterminado .NTFS-3G/UserMapping. Si nombre-archivo define una ruta completa, el archivo debe estar ubicado en una partición montada previamente. Si define una ruta relativa, se interpreta en relación con la raíz de la partición NTFS que se está montando.
Cuando se define un archivo de mapeo de usuarios, las opciones uid=, gid=, umask=, fmask=, dmask= y silent se ignoran.
user_xattr
Lo mismo que streams_interface=xattr.
windows_names
Esta opción evita que se creen archivos, directorios y atributos extendidos con un nombre no permitido por Windows, porque

- contiene algún carácter no permitido,
- o el último carácter es un espacio o un punto,
- o el nombre está reservado.

Los caracteres prohibidos son los nueve caracteres " * / : < > ? \ | y aquellos cuyo código es inferior a 0x20, y los nombres reservados son CON, PRN, AUX, NUL, COM1..COM9, LPT1..LPT9, sin sufijo o seguidos de un punto.

Los archivos existentes de este tipo aún se pueden leer (y renombrar).

MAPPING DE USUARIOS

NTFS utiliza identificadores específicos para registrar la propiedad de los archivos en lugar de los uid (identificador de usuario) y gid (identificador de grupo) utilizados por Linux. Como consecuencia, se debe definir un mapeo entre los identificadores para que las propiedades se registren en los archivos NTFS y sean reconocidas.

Por defecto, este mapeo se obtiene del archivo .NTFS-3G/UserMapping ubicado en la partición NTFS. La opción usermapping= se puede usar para definir otra ubicación. Cuando se establece la opción **permissions** y no se encuentra un archivo de mapeo, se utiliza un mapeo predeterminado.

Cada línea en el archivo de mapeo de usuarios define un mapeo. Está organizada en tres campos separados por dos puntos. El primer campo identifica un uid, el segundo campo identifica un gid y el tercero identifica el SID correspondiente, conocido como un SID. El uid y el gid son opcionales y no se recomienda definir ambos para el mismo SID.

Si no se necesita interoperación con Windows, puedes usar la opción permissions para definir un mapeo estándar. Alternativamente, puedes definir tu propio mapeo estableciendo un único mapeo predeterminado sin uid ni gid. En ambos casos, los archivos creados en Linux aparecerán para Windows como propiedad de un usuario extranjero, y los archivos creados en Windows aparecerán para Linux como propiedad de root. Simplemente copia el ejemplo a continuación y reemplaza los números de 9 y 10 dígitos por cualquier número no mayor que 4294967295. El comportamiento resultante es el mismo que el de la opción permission con ninguna opción de propiedad y sin archivo de mapeo de usuarios disponible.

::S-1-5-21-3141592653-589793238-462643383-10000

Si se necesita una fuerte interoperación con Windows, el mapeo debe definirse para cada usuario y grupo conocido por ambos sistemas, y los SIDs utilizados por Windows deben recopilarse. Esto conducirá a un archivo de mapeo de usuarios como:

NAME

ntfs-3g

read and write NTFS filesystem driver

SYNOPSIS

ntfs-3g [options] device mountpoint

mount -t ntfs-3g [options] device mountpoint

DESCRIPTION

ntfs-3g is an open source NTFS driver that can be used for mounting Microsoft Windows partitions. It supports reading and writing to NTFS partitions with better stability and performance than the current in-kernel NTFS driver. It also supports NTFS features that are not supported by the in-kernel driver, such as journaling, compression, and encryption.

OPTIONS

The following options are supported:

-o option[,option]...
Comma-separated list of mount options. Some common options include:
  • ro Mount read-only.
  • rw Mount read-write (default).
  • user Allow any user to mount and unmount the filesystem. Implies fsck.unmounted.
  • users Allow any user to mount and unmount the filesystem. Implies fsck.unmounted.
  • owner Allow the owner of the device file to mount and unmount the filesystem.
  • remount attempt to remount the filesystem with different options.
  • permissions Enable standard Linux permissions. This option is recommended for better compatibility with Linux applications.
  • force Mount the filesystem even if it is marked as dirty or hibernated. Use with caution.
  • =value
  • =value
  • =value
  • noacl Disable POSIX ACL support.
  • acl Enable POSIX ACL support (default).
  • For a complete list of options, see the ntfs-3g.conf(5) manual page.

USER MAPPING

If the permissions option is used, ntfs-3g can map Windows SIDs (Security Identifiers) to Linux UIDs and GIDs. This mapping can be configured using a user mapping file. The default user mapping file is usually located at /etc/ntfs-3g/ntbusers-hostname.map or /etc/ntfs-3g/ntbusers.map.

The format of the user mapping file is as follows:

windows_sid = uid:gid

For example, to map the Windows SID S-1-5-21-3141592653-589793238-462643383-500 to the Linux UID 1000 and GID 100:

S-1-5-21-3141592653-589793238-462643383-500 = 1000:100

The utility ntfsusermap may be used to create such a user mapping file.

EXAMPLES

Mount /dev/sda1 to /mnt/windows:

ntfs-3g /dev/sda1 /mnt/windows

or
mount -t ntfs-3g /dev/sda1 /mnt/windows
Mount the ntfs data partition /dev/sda3 to /mnt/data with standard Linux permissions applied :

ntfs-3g -o permissions /dev/sda3 /mnt/data

or
mount -t ntfs-3g -o permissions /dev/sda3 /mnt/data
Read-only mount /dev/sda5 to /home/user/mnt and make user with uid 1000 to be the owner of all files:

ntfs-3g /dev/sda5 /home/user/mnt -o ro,uid=1000

/etc/fstab entry for the above (the sixth and last field has to be zero to avoid a file system check at boot time) :

/dev/sda5 /home/user/mnt ntfs-3g ro,uid=1000 0 0

Unmount /mnt/windows:

umount /mnt/windows

EXIT CODES

To facilitate the use of the ntfs-3g driver in scripts, an exit code is returned to give an indication of the mountability status of a volume. Value 0 means success, and all other ones mean an error. The unique error codes are documented in the ntfs-3g.probe(8) manual page.
