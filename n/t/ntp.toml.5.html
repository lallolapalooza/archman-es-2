NOMBRE

ntp.toml - archivo de configuración para el demonio ntp ntpd-rs

DESCRIPCIÓN

La configuración de ntpd-rs se realiza en el formato de configuración ntp.toml. El formato TOML es en muchos sentidos similar a un INI simple con varias extensiones que permiten una sintaxis similar a JSON.

El archivo de configuración de ntpd-rs consta de varias secciones, cada una de las cuales configura una parte separada del proceso del demonio ntp. Cada una de las secciones se describe en el resto de este documento. Muchas configuraciones tendrán valores predeterminados, que se indicarán con cada configuración mostrada.

El demonio NTP solo admite conexiones cliente-servidor unicast. La mayor parte del tráfico NTP, especialmente a través de Internet pública, utiliza casi exclusivamente este modo, por lo que no se considera una limitación práctica para la mayoría de los escenarios.

MODOS DE ORIGEN

El demonio NTP admite diferentes tipos de orígenes (ver la sección a continuación para más detalles). Para establecer el tipo de origen, puede configurar el campo `mode` con cualquiera de estas opciones:

server
Un origen de servidor se conecta a un único servidor NTP específico. Si se pierde una conexión, se intentará reconectar al origen.
pool
Un origen de pool recupera múltiples servidores NTP resolviendo un nombre de host a través de DNS. Luego, intenta conectarse a varios de estos servidores al mismo tiempo. Si se pierde una conexión, se recuperará un nuevo servidor del pool.
nts
Conéctese a un único origen de Network Time Security (NTS). El protocolo NTS utiliza un handshake TLS para intercambiar secretos con un servidor para permitir verificar que los mensajes NTP no han sido manipulados. Tenga en cuenta que el protocolo TLS requiere que tanto el cliente como el servidor tengan una idea aproximada de la hora actual.
sock
Un origen sock se conecta a un socket GPSd para obtener datos de tiempo de receptores GPS. Tenga en cuenta que GPSd debe reiniciarse después de iniciar ntpd-rs para que GPSd se conecte al socket.
pps
Un origen pps se conecta a un dispositivo Pulse Per Second, que por defecto se asume que envía un pulso cada segundo redondeado. Dado que estos dispositivos solo proporcionan datos periódicos, no cuentan para minimum-agreeing-sources.

CONFIGURACIÓN

[source-defaults]

Parte del comportamiento de un origen es configurable. Puede establecer valores predeterminados para esas configuraciones en la sección [source-defaults].

poll-interval-limits = { min = min, max = max } ({ min = 4, max = 10})
Especifica el límite de la frecuencia con la que se consulta un origen para obtener un nuevo tiempo. Para la mayoría de las instancias, los valores predeterminados serán adecuados. El mínimo y el máximo se dan como el log2 del número de segundos (es decir, dos elevado a la potencia del intervalo). Un intervalo de 4 equivale a 16 segundos, 10 da como resultado un intervalo de 1024 segundos. Si se especifica, se deben especificar tanto el mínimo como el máximo.
initial-poll-interval = intervalo (4)
Intervalo de sondeo inicial utilizado al inicio. El valor se da como el log2 del número de segundos (es decir, dos elevado a la potencia del intervalo). El valor predeterminado de 4 da como resultado un intervalo de 16 segundos.

[[source]]

Cada [[source]] es un conjunto de uno o más orígenes de tiempo desde los cuales el demonio obtendrá información de tiempo. Se puede configurar cualquier número de orígenes repitiendo una sección [[source]] (tenga en cuenta los corchetes dobles) tantas veces como sea necesario. Cada origen puede configurarse para conectarse a una ubicación remota específica. Se admiten varios modos para conectarse a orígenes. Si se han configurado menos de minimum-agreeing-sources orígenes de tiempo, no se sincronizará ningún tiempo con el reloj local. Tenga en cuenta que un pool cuenta como múltiples orígenes de tiempo.

mode = modo
Especifique uno de los modos de origen que admite ntpd-rs: server, pool, nts, sock o pps. Para una descripción de los diferentes modos de origen, consulte la sección MODOS DE ORIGEN.
address = dirección
Especifique la dirección remota del origen. Para los orígenes de servidor, esta será la dirección remota del servidor NTP. Para los pools, será la dirección DNS del pool NTP y para NTS será la dirección del servidor de intercambio de claves. La dirección del servidor puede incluir un número de puerto adjuntando dos puntos (:) seguidos de un número de puerto. Si no se especifica, el demonio se conectará a los servidores server y pool a través del puerto 123, para los orígenes nts el puerto predeterminado es 4460.
certificate-authority = cert
Solo se puede establecer en orígenes con modo nts. Ruta a un certificado para una autoridad de certificación adicional a usar, además de las autoridades de certificación especificadas por la configuración del sistema. Tenga en cuenta que esto no se puede usar para especificar un certificado autofirmado.
count = número (4)
Solo se puede establecer en orígenes con modo pool. Especifica el número máximo de servidores a los que el demonio intentará conectarse desde un pool. El demonio seguirá intentando obtener más orígenes del pool cuando se pierdan las conexiones, hasta el máximo especificado por esta configuración.
ignore = direcciones ip
Solo modo pool. Especifica una lista de direcciones IP de servidores en el pool que no deben usarse. Por ejemplo: ["127.0.0.1"]. Vacío por defecto.
measurement_noise_estimate = Varianza de ruido (segundos al cuadrado)
Solo modo pps y sock. Obsoleto, use precision en su lugar.
precision = Desviación estándar del ruido (segundos)
Solo modo pps y sock. Precisión del origen. Esta debe ser una estimación del tamaño del ruido de medición esperado. Técnicamente definido como el límite de desviación estándar de 1 en el error de medición. Esto es necesario ya que los orígenes sock y pps no tienen una buena manera de estimar su propio error.
poll-interval-limits = { min = min, max = max } (predeterminados de [source-defaults])
Especifica el límite de la frecuencia con la que se consulta un origen para obtener un nuevo tiempo. Para la mayoría de las instancias, los valores predeterminados serán adecuados. El mínimo y el máximo se dan como el log2 del número de segundos (es decir, dos elevado a la potencia del intervalo). Un intervalo de 4 equivale a 16 segundos, 10 da como resultado un intervalo de 1024 segundos. Si solo se especifica uno de los dos límites, el otro se hereda de [source-defaults]
initial-poll-interval = intervalo (predeterminados de [source-defaults])
Intervalo de sondeo inicial utilizado al inicio. El valor se da como el log2 del número de segundos (es decir, dos elevado a la potencia del intervalo). El valor predeterminado de 4 da como resultado un intervalo de 16 segundos.

ntp-version

ntp-version = 4 | 5 | "auto" (4)
Qué versión de NTP usar para esta fuente. Por defecto, utiliza la versión NTP 4. Puedes usar 5 para establecer la versión del protocolo a la especificación del borrador NTPv5, pero tu fuente debe soportar el mismo borrador. Para usar el protocolo de actualización experimental, establece la versión NTP a "auto". Esto utiliza un paquete NTPv4 especialmente construido para intentar una actualización a la versión del borrador NTPv5 soportada si la fuente también soporta la misma versión del borrador. El soporte NTPv5 está actualmente en beta y aún puede cambiar de forma incompatible con versiones anteriores.

[[server]]

El demonio NTP puede configurarse para distribuir la hora a través de cualquier número de secciones [[server]]. Si no se han definido dichas secciones, el demonio se ejecuta en modo solo cliente. Se puede configurar cualquier número de servidores repitiendo la sección [[server]] (nota los corchetes dobles) tantas veces como sea necesario. Cada servidor puede servir una dirección de socket específica o escuchar en todas las interfaces de red disponibles en un puerto específico. Los servidores siempre sirven la hora del reloj del sistema.

listen = socketaddr
Dirección de un socket UDP en el que el servidor debe escuchar las solicitudes NTP entrantes. Se especifica como una dirección IP de interfaz, dos puntos y un número de puerto. El número de puerto estándar para NTP es el puerto UDP 123. Se admiten tanto IPv4 como IPv6. Por ejemplo, para escuchar en localhost en el puerto 123 en IPv4 puedes usar 127.0.0.1:123. Puedes escuchar en todas las interfaces de red disponibles a la vez usando 0.0.0.0:123 para IPv4 o [::]:123 para IPv6.
rate-limiting-cache-size = size (0)
Número de elementos en la caché de limitación de velocidad. Como máximo se conservan size elementos en la caché. Esto significa que si más de size clientes diferentes intentan conectarse al servidor con demasiada frecuencia, el tamaño de la caché tendrá una funcionalidad reducida, ya que la información de limitación de velocidad se pierde cuando nuevos clientes se conectan al servidor. Si se establece a cero, la caché no se utiliza, que es el valor predeterminado.
rate-limiting-cutoff-ms = cutoff (0)
Tiempo mínimo entre dos solicitudes del mismo cliente. Si una solicitud se envió antes de la hora de corte, se le pedirá al cliente que reduzca la velocidad de sus solicitudes respondiendo el servidor con un paquete con el código de "kiss" NTP RATE. En ese caso, no se devolverá ninguna medición de tiempo real al cliente. Si se establece a cero, no se aplica ninguna limitación de velocidad, que es el valor predeterminado.
allowlist = { filter = [ subnet, .. ], action = "deny" | "ignore" } (unset)
Permite solo a cualquier número de subredes filtradas conectarse al demonio. Cualquier IP que coincida con una de las subredes especificadas tiene permiso para contactar a este servidor. Las subredes deben especificarse en notación CIDR (una dirección IP seguida de una barra y el número de bits enmascarados, por ejemplo 127.0.0.1/8 o 192.168.1.1/24). La acción determina qué medida se toma para las direcciones IP que no están en ninguna de las subredes especificadas. Cuando se usa deny, se devuelve un paquete explícito con el código de "kiss" NTP DENY al remitente, indicando que no tienen permiso para hacerlo. Cuando se especifica ignore, los mensajes se descartan sin enviar ninguna respuesta. El valor predeterminado es equivalente a permitir cualquier dirección IP, y sería equivalente a establecer el filtro en ["0.0.0.0/0", "::/0"], con cualquiera de las acciones.
denylist = { filter = [ subnet, .. ], action = "deny" | "ignore" } (unset)
No permite que ningún número de subredes filtradas se conecte al demonio. Cualquier IP que coincida con una de las subredes especificadas no tiene permiso para contactar a este servidor. Las subredes deben especificarse en notación CIDR (una dirección IP seguida de una barra y el número de bits enmascarados, por ejemplo 127.0.0.1/8 o 192.168.1.1/24). La acción determina qué medida se toma para las direcciones IP que se encuentran en cualquiera de las subredes especificadas. Cuando se usa deny, se devuelve un paquete explícito con el código de "kiss" NTP DENY al remitente, indicando que no tienen permiso para hacerlo. Cuando se especifica ignore, los mensajes se descartan sin enviar ninguna respuesta. El valor predeterminado es equivalente a permitir cualquier dirección IP, y sería equivalente a establecer el filtro en [], con cualquiera de las acciones.
require-nts = true | false | "deny" | "ignore" (false)
Si las solicitudes entrantes al servidor deben tener NTS habilitado. Cuando se establece en true o "ignore", cualquier mensaje que no tenga NTS habilitado será ignorado. Cuando se establece en "deny", los mensajes que no tengan NTS habilitado serán explícitamente denegados con un código de "kiss" NTP DENY. Cuando se establece en false (el valor predeterminado), los mensajes NTP normales también están permitidos.
accept-ntp-versions = [ 3 | 4 | 5, .. ] ([3, 4])
Una matriz de versiones NTP que son aceptadas por el servidor. Por defecto, solo se admiten paquetes NTPv3 y NTPv4. Para permitir también los paquetes NTPv5 en borrador, puedes establecer este valor en [3, 4, 5]. El soporte NTPv5 está actualmente en beta y aún puede cambiar de forma incompatible con versiones anteriores.

[observability]

La configuración en esta sección configura cómo se puede observar el comportamiento del demonio. Actualmente, el demonio puede observarse a través de los registros o recuperando varias métricas clave a través de ntp-ctl(8) o a través de ntp-metrics-exporter(8).

log-level = "trace" | "debug" | "info" | "warn" | "error" (unset)
Establece el nivel de registro para los mensajes impresos en stdout. El nivel más bajo trace proporciona información muy detallada sobre todo lo que sucede en el demonio, mientras que el nivel más alto error solo registra las condiciones de error en el demonio. Los niveles superiores al nivel de registro dado también se registran. Si no está configurado (el valor predeterminado), el registro se deshabilitará por completo.
ansi-colors = true | false (true)
Se puede usar para deshabilitar códigos de escape ANSI en los registros. Por defecto, se utilizan códigos de escape ANSI para agregar algunos colores y otro formato a los registros.
observation-path = path (unset)
Ruta donde el demonio creará un socket de dominio Unix de observación. Este socket es utilizado por ntp-ctl y ntp-metrics-exporter para leer el estado actual del demonio. Si no está configurado (el valor predeterminado), no se creará ningún socket de observación y no es posible usar ntp-ctl o ntp-metrics-exporter para observar el demonio.
observation-permissions = mode (0o666)
Los permisos del sistema de archivos con los que se debe crear el socket de observación. Advertencia: Siempre debes escribir este número con el prefijo octal 0o, de lo contrario, tus permisos podrían interpretarse incorrectamente. El valor predeterminado debería ser suficiente para la mayoría de las aplicaciones sin embargo.
metrics-exporter-listen = socketaddr (127.0.0.1:9975)
La dirección de escucha que se utiliza para el ntp-metrics-exporter(8).

[keyset]

El conjunto de claves configura la infraestructura de claves interna para paquetes NTS. Ten en cuenta que esto está separado del certificado TLS y la clave privada; para esos, consulta la configuración relevante en la sección [[nts-ke-server]].

stale-key-count = count (7)
Número máximo de claves antiguas a retener en la caché. Cada vez que las claves se rotan, las claves antiguas se vuelven inválidas, pero los clientes aún pueden tener cookies NTS cifradas con cualquiera de las claves antiguas.
key-rotation-interval = seconds (86400)
Tiempo entre eventos de rotación de claves. Cada vez que transcurren seconds, se generará una nueva clave interna para crear cookies NTS. Por defecto, esto se establece en un día.
key-storage-path = path (unset)
Si se establece, almacena las claves NTS internas en el archivo indicado por path. Esto permite que las claves sobrevivan a un reinicio del servidor. Si no está configurado, los clientes que usan NTS pueden necesitar rehacer una operación de intercambio de claves para obtener nuevas cookies NTS. El demonio no creará ningún directorio padre si no existen. Creará el archivo si no existe.

[[nts-ke-server]]

El demonio puede configurarse para operar como un servidor de intercambio de claves NTS repitiendo cualquier número de secciones [[nts-ke-server]]. Si no se han definido dichas secciones, el demonio no ofrecerá ningún servicio de intercambio de claves NTS. Todos los servidores NTS-KE utilizan el conjunto de claves compartido. El propósito del servidor de intercambio de claves es distribuir de forma segura las cookies a los clientes. Estas cookies se pueden usar luego en paquetes NTP con el servidor normal para v

[ntp-client]

This section of the configuration deals with the NTP client settings, how the daemon should behave when it is acting as a client to remote NTP servers.

trust-ntpd-with-root-distance = bool (false)
If this is enabled, the client will trust the root distance reported by the remote NTP server. This can be used to disable the check that verifies that the reported root distance is not excessively large. This is useful for verifying that the traffic was not tampered with.

listen = socket
Dirección de un socket TCP en el que el servidor debe escuchar las solicitudes de intercambio de claves NTS entrantes. Se especifica como una dirección IP de interfaz, dos puntos y un número de puerto. El número de puerto estándar para un servidor de intercambio de claves NTS es el puerto TCP 4460. Se admiten tanto IPv4 como IPv6. Por ejemplo, para escuchar en localhost puerto 4460 en IPv4 puede usar 127.0.0.1:4460. Puede escuchar en todas las interfaces de red disponibles a la vez usando 0.0.0.0:4460 para IPv4 o [::]:4460 para IPv6.
certificate-chain-path = path
Ruta a una cadena de certificados para el certificado público que el servidor ofrece a los clientes.
private-key-path = path
Ruta a la clave privada asociada con el certificado del servidor en la cadena de certificados.
key-exchange-timeout-ms = timeout (1000)
Tiempo de espera en milisegundos durante el cual puede tener lugar un intercambio de claves. Si se excede el tiempo de espera, la conexión se cerrará.
concurrent-connections = number (512)
Número máximo de conexiones concurrentes que manejará el servidor de intercambio de claves. Las conexiones por encima del umbral se mantendrán en una cola a nivel del sistema operativo.

ntp-port = port Número de puerto que el servidor de intercambio de claves debe indicar a los clientes que utilicen. Debe usarse cuando el número de puerto del servidor NTP no sea el predeterminado.

ntp-server = server-name Dirección del servidor (ya sea como IP o como nombre de dominio) donde los clientes pueden encontrar el servidor NTP. Debe usarse cuando este nombre no coincida con el nombre del servidor de intercambio de claves NTS.

accept-ntp-versions = [ 4 | 5, .. ] ([4])
Una matriz de versiones NTP que son aceptadas por el servidor. Por defecto, solo se admite NTS para paquetes NTPv4. Para permitir también la negociación de NTS para paquetes NTPv5 en borrador, puede establecer este valor en [4, 5]. El soporte de NTPv5 está actualmente en beta y aún puede cambiar de forma incompatible con versiones anteriores.

[synchronization]

Esta sección de la configuración se centra en cómo se recopila la información de tiempo de las fuentes de tiempo y cómo se aplica al reloj del sistema.

minimum-agreeing-sources = count (3)
El número mínimo de fuentes que deben estar de acuerdo en la hora actual antes de que el demonio realice cualquier operación de ajuste del reloj. Tenga en cuenta que si ha configurado menos fuentes que esta cantidad, esto puede resultar en que el demonio nunca actualice el reloj.
single-step-panic-threshold = seconds | { forward = forward, backward = backward } (1000)
El umbral en segundos en el que el demonio saldrá completamente (es decir, entrará en pánico) cuando ocurra un único salto que no sea de inicio. Generalmente, durante la operación normal, el reloj de su sistema debe estar algo cerca de la hora a la que está sincronizado. Como tal, es muy improbable que ocurra un salto tan grande, y el demonio saldrá para prevenir cualquier error accidental. Si se establece en el valor "inf", se permitirá cualquier salto. Puede configurarse como un solo número de segundos para saltos hacia adelante y hacia atrás, o como valores separados para saltos hacia adelante y hacia atrás.
startup-step-panic-threshold = seconds | { forward = forward, backward = backward } ({ forward = “inf”, backward = “86400” })
El umbral en segundos en el que el demonio saldrá completamente (es decir, entrará en pánico) cuando ocurra un salto al inicio. El valor predeterminado permite cualquier salto hacia adelante, pero evita saltos hacia atrás mayores a un día. Generalmente, los relojes de las computadoras que no están sincronizados irán por detrás del tiempo real, en lugar de ir por delante. Si una computadora va por delante y retrocede un gran período de tiempo, esto generalmente indica un problema. Si se establece en el valor "inf", se permitirá cualquier salto. Puede configurarse como un solo número de segundos para saltos hacia adelante y hacia atrás, o como valores separados para saltos hacia adelante y hacia atrás. Al usar esto, el comando force-sync de ntp-ctl aún se puede utilizar para establecer manualmente la hora del sistema más allá de estos límites, para recuperarse de un reloj de sistema defectuoso.
accumulated-step-panic-threshold = seconds (unset)
Cada vez que el demonio ajusta la hora en lugar de ajustarla lentamente usando cambios de frecuencia, este contador se incrementa en el valor absoluto del salto (es decir, se cuentan tanto los saltos hacia adelante como hacia atrás). Cuando se alcanza este umbral, el demonio saldrá inmediatamente (es decir, entrará en pánico). Durante la operación normal, es poco probable que ocurran saltos, y como tal, los saltos pueden indicar que alguien o algo está provocando saltos ilícitos. Sin embargo, por defecto, este mecanismo de pánico está deshabilitado. Está deshabilitado si se deja sin establecer o si se establece en el valor 0.
warn-on-jump = bool (true)
¿Debería el demonio emitir una advertencia al ajustar el reloj? Estos saltos pueden ser problemáticos para otro software, por ejemplo, para servidores de bases de datos. Esta configuración se puede usar para deshabilitar en sistemas donde los saltos son esperados y no perjudiciales para otro software.
local-stratum = stratum (16)
Establece el estrato del reloj NTP del reloj del sistema cuando no hay fuentes de tiempo NTP configuradas, o cuando la hora aún no se ha sincronizado desde una fuente de tiempo NTP. Se puede utilizar en servidores para indicar que existen mecanismos externos que sincronizan el reloj.
reference-id = reference-id (XNON)
Establece el ID de referencia del reloj NTP informado cuando local-stratum se establece en 1. Esto se utiliza para indicar la fuente de la referencia de tiempo (GPS, etc.).

[synchronization.algorithm]

Advertencia: la sección de algoritmos contiene principalmente ajustes internos del algoritmo que generalmente no necesitan ser cambiados. Sin embargo, se ofrecen aquí para casos de uso específicos. Estos ajustes se consideran detalles de implementación y, como tales, pueden cambiar en futuras versiones de ntpd-rs.

precision-low-probability = probability (1/3)
Límite de probabilidad por debajo del cual comenzamos a movernos hacia la disminución de nuestra estimación de precisión. Unidad: probabilidad, 0-1
precision-high-probability = probability (2/3)
Límite de probabilidad por encima del cual comenzamos a movernos hacia el aumento de nuestra estimación de precisión. Unidad: probabilidad, 0-1
precision-hysteresis = hysteresis (16)
Cantidad de histéresis al cambiar la estimación de precisión. Unidad: recuento, 1+
precision-minimum-weight = weight (0.1)
Límite inferior en la cantidad de efecto que tiene nuestra estimación de precisión sobre la estimación total de ruido antes de permitir la disminución de la estimación de precisión. Unidad: peso, 0-1
poll-interval-low-weight = weight (0.4)
Cantidad en la que una medición contribuye al estado, por debajo de la cual comenzamos a aumentar el intervalo de sondeo. Unidad: peso, 0-1
poll-interval-high-weight = weight (0.6)
Cantidad en la que una medición contribuye al estado, por encima de la cual comenzamos a disminuir el intervalo de sondeo. Unidad: peso, 0-1
poll-interval-hysteresis = hysteresis (16)
Cantidad de histéresis al cambiar el intervalo de sondeo. Unidad: recuento, 1+
poll-interval-step-threshold = threshold (1e-6)
Umbral de probabilidad para cuando una medición se considera una observación atípica lo suficientemente significativa como para decidir que algo extraño está sucediendo y necesitamos hacer más mediciones. Unidad: probabilidad, 0-1
delay-outlier-threshold = threshold (5.0)
Umbral (en número de desviaciones estándar) por encima del cual se rechazan las mediciones con un retraso de red significativamente mayor. Unidad: desviaciones estándar, 0+
initial-wander = wander (1e-8)
Estimación inicial de la deriva del reloj de la combinación de nuestro reloj local y el de la fuente. Unidad: s/s^2
initial-frequency-uncertainty = uncertainty (100e-6)
Incertidumbre inicial de la diferencia de frecuencia entre nuestro reloj y el de la fuente. Unidad: s/s
maximum-source-uncertainty = uncertainty (0.25)
Incertidumbre máxima de la fuente antes de que comencemos a ignorarla. Tenga en cuenta que esta es la incertidumbre combinada debido al ruido y posible error de asimetría (ver también pesos a continuación). Unidad: segundos
range-statistical-weight = weight (2.0)
Peso de la incertidumbre estadística al construir rangos de solapamiento. Unidad: desviaciones estándar, 0+
range-delay-weight = weight (0)

CONFIGURATION

The ntpd-rs configuration file is TOML format and is typically located at “/etc/ntpd-rs.toml”. Refer to configuration documentation for more details.

# The configuration file is divided into sections.
# The most important section is 'sources' which defines the NTP sources.
# See 'SOURCE MODES' for more details.

sources = [
    { type = "Ntp", address = "pool.ntp.org" },
    { type = "Ntp", address = "time.cloudflare.com" },
    # Add more sources here
]

# Global settings can be defined here.
[settings]
# Default time source for system clock
default_source = "pool.ntp.org"

# Enable logging to syslog
# syslog = true

# Log level can be set to:
# debug, info, warn, error
# log_level = "info"

# How often to check for updates to the configuration file
# configuration_update_interval = "1h"


# Settings related to clock steering
[settings.steer]
# How far from 0 (in multiples of the uncertainty) should the offset be
# before we correct. Unit: standard deviations, 0+
