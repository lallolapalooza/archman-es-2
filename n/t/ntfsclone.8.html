NTFSCLONE(8) Manual del Administrador del Sistema NTFSCLONE(8)

NOMBRE

ntfsclone - Clonación, imagen, restauración o rescate eficiente de un NTFS

SINOPSIS

ntfsclone [OPCIONES] ORIGEN
ntfsclone --save-image [OPCIONES] ORIGEN
ntfsclone --restore-image [OPCIONES] ORIGEN
ntfsclone --metadata [OPCIONES] ORIGEN

DESCRIPCIÓN

ntfsclone clonará (copiará, guardará, hará una copia de seguridad, restaurará) o rescatará eficientemente un sistema de archivos NTFS a un archivo disperso, una imagen, un dispositivo (partición) o la salida estándar. Funciona a nivel de sector del disco y solo copia los datos utilizados. El espacio de disco no utilizado se vuelve cero (clonación a archivo disperso), se codifica con códigos de control (guardado en formato de imagen especial), se deja sin cambios (clonación a disco/partición) o se rellena con ceros (clonación a salida estándar).

ntfsclone puede ser útil para hacer copias de seguridad, una instantánea exacta de un sistema de archivos NTFS y restaurarla más tarde, o para que los desarrolladores prueben la funcionalidad de lectura/escritura de NTFS, solucionen problemas/investiguen problemas de los usuarios utilizando la clonación sin el riesgo de destruir el sistema de archivos original.

La clonación, si no utiliza el formato de imagen especial, es una copia exacta del sistema de archivos NTFS original de sector a sector, por lo que también se puede montar igual que el sistema de archivos NTFS original. Por ejemplo, si clona a un archivo y el kernel tiene el dispositivo de loopback y soporte NTFS, entonces el archivo se puede montar como:

mount -t ntfs -o loop ntfsclone.img /mnt/ntfsclone

Clonación de Windows

Si desea copiar, mover o restaurar una partición de sistema o de arranque a otra computadora, o a un disco o partición diferente (por ejemplo, hda1->hda2, hda1->hdb1 o a un desplazamiento de sector de disco diferente), deberá tener precaución adicional.

Por lo general, Windows no podrá arrancar, a menos que copie, mueva o restaure NTFS en la misma partición que comienza en el mismo sector en el mismo tipo de disco, con la misma configuración de cilindros heredada del BIOS que la partición y el disco originales tenían.

La utilidad ntfsclone garantiza hacer una copia exacta de NTFS, pero no se ocupará de los problemas de arranque. Esto es intencional: ntfsclone es un sistema de archivos, no una utilidad del sistema. Su objetivo es solo la clonación de NTFS, no la clonación de Windows. Por lo tanto, ntfsclone puede utilizarse como un bloque de construcción muy rápido y confiable para la clonación de Windows, pero por sí solo no es suficiente.

Archivos dispersos

Un archivo es disperso si tiene bloques no asignados (agujeros). El tamaño reportado de tales archivos es siempre mayor que el espacio en disco que consumen. El comando du puede indicar el espacio real en disco utilizado por un archivo disperso. Los agujeros siempre se leen como ceros. Todos los principales sistemas de archivos de Linux como ext2, ext3, reiserfs, Reiser4, JFS y XFS admiten archivos dispersos, pero por ejemplo el sistema de archivos de CD-ROM ISO 9600 no.

Manejo de archivos dispersos grandes

Hasta la fecha, Linux proporciona soporte inadecuado para administrar (tar, cp, gzip, gunzip, bzip2, bunzip2, cat, etc.) archivos dispersos grandes. El único sistema de archivos principal de Linux que tiene soporte para el manejo eficiente de archivos dispersos es XFS mediante la llamada ioctl(2) XFS_IOC_GETBMAPX. Sin embargo, ninguna de las utilidades comunes lo soporta. Esto significa que cuando comprime, copia, comprime con gzip, comprime con bzip2, etc., un archivo disperso grande, siempre leerá el archivo completo, incluso si utiliza las opciones de "soporte disperso".

bzip2(1) comprime archivos dispersos grandes mucho mejor que gzip(1), pero también lo hace mucho más lento. Además, ninguno de ellos maneja archivos dispersos grandes de manera eficiente desde el punto de vista del uso del espacio en disco durante la descompresión.

Actualmente, la forma más eficiente, tanto en velocidad como en espacio, de comprimir y descomprimir archivos dispersos grandes mediante herramientas comunes sería usar tar(1) con las opciones -S (manejar archivos dispersos "eficientemente") y -j (filtrar el archivo a través de bzip2). Aunque tar todavía lee y analiza el archivo completo, no pasa los bloques de datos grandes que solo contienen ceros a los filtros y también evita escribir grandes cantidades de ceros en el disco innecesariamente. Pero dado que tar no puede crear un archivo desde la entrada estándar, no puede hacer esto sobre la marcha simplemente leyendo la salida estándar de ntfsclone. Aún más triste, el uso de la opción -S resulta en una pérdida de datos grave desde finales de 2004 y los mantenedores de GNU tar no han lanzado versiones corregidas hasta el día de hoy.

El formato de imagen especial

También es posible, de hecho se recomienda, guardar un sistema de archivos NTFS en un formato de imagen especial. En lugar de representar los bloques no asignados como agujeros, se codifican usando códigos de control. Por lo tanto, la imagen ahorra espacio sin requerir soporte para archivos dispersos. El formato de imagen es ideal para transmitir imágenes de sistemas de archivos a través de la red y similares, y se puede usar como reemplazo de Ghost o Partition Image si se combina con otras herramientas. La desventaja es que no puede montar la imagen directamente, primero debe restaurarla.

Para guardar una imagen usando el formato de imagen especial, use la opción -s o --save-image. Para restaurar una imagen, use la opción -r o --restore-image. Tenga en cuenta que puede restaurar imágenes desde la entrada estándar utilizando '-' como argumento ORIGEN.

Clonación solo de metadatos

Una de las características de ntfsclone es que también puede guardar solo los metadatos de NTFS usando la opción -m o --metadata y la clonación seguirá siendo montable. En este caso, todo el contenido de archivos que no sean metadatos se perderá y leerlos dará como resultado siempre ceros.

La imagen de solo metadatos se puede comprimir muy bien, generalmente a no más de 1-8 MB, por lo que es fácil de transferir para investigación, resolución de problemas.

En este modo de ntfsclone, NINGUNO de los datos del usuario se guarda, incluidos los datos del usuario residente incrustados en los metadatos. Todo se rellena con ceros. Además, todas las marcas de tiempo de archivos, los espacios eliminados y no utilizados dentro de los metadatos se rellenan con ceros. Por lo tanto, este modo es inapropiado, por ejemplo, para análisis forenses. Este modo se puede combinar con --save-image para crear un archivo de formato de imagen especial en lugar de un archivo disperso.

Tenga en cuenta que los nombres de archivo no se eliminan. Pueden contener información confidencial, así que piense dos veces antes de enviar dicha imagen a alguien.

OPCIONES

A continuación se muestra un resumen de todas las opciones que acepta ntfsclone. Casi todas las opciones tienen dos nombres equivalentes. El nombre corto va precedido de - y el nombre largo va precedido de --. Cualquier opción de una sola letra que no tome un argumento se puede combinar en un solo comando, por ejemplo, -fv es equivalente a -f -v. Las opciones de nombre largo se pueden abreviar a cualquier prefijo único de su nombre.

-o, --output ARCHIVO
Clonar NTFS al ARCHIVO inexistente. Si ARCHIVO es '-' entonces clonar a la salida estándar. Esta opción no se puede utilizar para crear una partición, use --overwrite para una partición existente.
-O, --overwrite ARCHIVO
Clonar NTFS a ARCHIVO, que puede ser una partición existente o un archivo regular que se sobrescribirá si existe.
-s, --save-image
Guardar en el formato de imagen especial. Esta es la forma más eficiente en términos de espacio y velocidad si la creación de imágenes se realiza en la salida estándar, por ejemplo, para compresión de imágenes, cifrado o transmisión a través de una red.
-r, --restore-image
Restaurar desde el formato de imagen especial especificado por el argumento ORIGEN. Si el ORIGEN es '-' entonces la imagen se lee desde la entrada estándar.
-n, --no-action
Probar la consistencia de una imagen guardada simulando su restauración sin escribir nada. Los datos NTFS contenidos en la imagen no se prueban. La opción --restore-image también debe estar presente, y las opciones --output y --overwrite deben omitirse.

ntfsclone(8) — ntfs-3g 2022.10.3

NAME

ntfsclone — copy NTFS filesystems (or parts of it)

SYNOPSIS

ntfsclone [options] source_device destination_file | destination_device

ntfsclone [options] --save-image source_device image_file

ntfsclone [options] --restore-image source_image_file destination_device | destination_file

DESCRIPTION

ntfsclone is a utility to copy NTFS filesystems. It can be used to backup and restore NTFS volumes or to clone them to another partition or a file. The tool works at the lowest, sector level and it is able to copy even very large filesystems with great efficiency. It is possible to copy only the used part of the filesystem, or even only the metadata. ntfsclone works without mounting the NTFS volume and it does not need write permissions on the volume.

The primary difference between ntfsclone and dd is that ntfsclone knows the filesystem structure and can optimize the copy process. It can skip unused clusters and copy even very large filesystems to smaller partitions or files, if the used space fits. It can also work with sparse files to save disk space on destination.

A copy created by ntfsclone can be restored using ntfsclone itself, or using dd. Special image files can also be created and restored.

It is strongly recommended to run ntfsclone from a Linux system and to clone to/from NTFS partitions or files on Linux, or FAT partitions or files on Linux.

It is also recommended to unmount the filesystem before cloning, but ntfsclone can also work if the filesystem is not mounted, or if it is marked 'dirty' (i.e. not properly unmounted).

OPTIONS

-o, --output FILE
Write the filesystem image to FILE instead of a device. If FILE is a dash (-), then the output is written to standard output. The output file is sparse by default.
-p, --partition N
Clone the Nth partition of the disk instead of the whole disk. For example, use -p 1 to clone the first partition.
-i, --image-file FILE
Read the filesystem image from FILE. If FILE is a dash (-), then the input is read from standard input.
-s, --save-image
Save the filesystem image to a special image file. The image file can be compressed using gzip or bzip2 and it can also contain multiple partitions. This option is implied when the output file is specified with --output and the source is a device.
-r, --restore-image
Restore the filesystem image from a special image file. This option is implied when the input file is specified with --image-file and the destination is a device or a file.
-w, --overwrite DEVICE | FILE
Overwrite the specified DEVICE or FILE. This option is required when the destination is a device or a file that already exists.
--overwrite
This is an alias for --overwrite. It is used for compatibility with older versions.
-a, --allow-overwrite
Allow overwriting the destination device or file if it is not empty. This option is useful for cloning to a partition that is not entirely empty, but has enough free space for the clone. The existing contents of the destination will be destroyed.
-f, --force
Forces ntfsclone to proceed if the filesystem is marked "dirty" for consistency check.
-q, --quiet
Do not display any progress-bars during operation.
--rescue
Ignore disk read errors so disks having bad sectors, e.g. dying disks, can be rescued the most efficiently way, with minimal stress on them. Ntfsclone works at the lowest, sector level in this mode too thus more data can be rescued. The contents of the unreadable sectors are filled by character '?' and the beginning of such sectors are marked by "BadSectoR\0".
-m, --metadata
Clone ONLY METADATA (for NTFS experts). Only cloning to a (sparse) file is allowed, unless used the option --save-image is also used. You can't metadata-only clone to a device.
--ignore-fs-check
Ignore the result of the filesystem consistency check. This option is allowed to be used only with the --metadata option, for the safety of user's data. The clusters which cause the inconsistency are saved too.
-t, --preserve-timestamps
Do not wipe the timestamps, to be used only with the --metadata option.
--full-logfile
Include the Windows log file in the copy. This is only useful for extracting metadata, saving or cloning a file system which was not properly unmounted from Windows.
--new-serial, or
--new-half-serial
Set a new random serial number to the clone. The serial number is a 64 bit number used to identify the device during the mounting process, so it has to be changed to enable the original file system and the clone to be mounted at the same time on the same computer.

The option --new-half-serial only changes the upper part of the serial number, keeping the lower part which is used by Windows unchanged.

The options --new-serial and --new-half-serial can only be used when cloning a file system of restoring from an image.

The serial number is not the volume UUID used by Windows to locate files which have been moved to another volume.

-h, --help
Show a list of options with a brief description of each one.

EXIT CODES

The exit code is 0 on success, non-zero otherwise.

EXAMPLES

Clone NTFS on /dev/hda1 to /dev/hdc1:

ntfsclone --overwrite /dev/hdc1 /dev/hda1

Save an NTFS to a file in the special image format:

ntfsclone --save-image --output backup.img /dev/hda1

Restore an NTFS from a special image file to its original partition:

ntfsclone --restore-image --overwrite /dev/hda1 backup.img

Save an NTFS into a compressed image file:

ntfsclone --save-image -o - /dev/hda1 | gzip -c > backup.img.gz

Restore an NTFS volume from a compressed image file:

gunzip -c backup.img.gz | ntfsclone --restore-image --overwrite /dev/hda1 -

Backup an NTFS volume to a remote host, using ssh. Please note, that ssh may ask for a password!

ntfsclone --save-image --output - /dev/hda1 | gzip -c | ssh host 'cat > backup.img.gz'

Restore an NTFS volume from a remote host via ssh. Please note, that ssh may ask for a password!

ssh host 'cat backup.img.gz' | gunzip -c | ntfsclone --restore-image --overwrite /dev/hda1 -

Stream an image file from a web server and restore it to a partition:

wget -qO - http://server/backup.img | ntfsclone --restore-image --overwrite /dev/hda1 -

Clone an NTFS volume to a non-existent file:

ntfsclone --output ntfs-clone.img /dev/hda1

Pack NTFS metadata for NTFS experts. Please note that bzip2 runs very long but results usually at least 10 times smaller archives than gzip on a sparse file.

ntfsclone --metadata --output ntfsmeta.img /dev/hda1
bzip2 ntfsmeta.img

Or, outputting to a compressed image :
ntfsclone -mst --output - /dev/hda1 | bzip2 > ntfsmeta.bz2

Unpacking NTFS metadata into a sparse file:

bunzip2 -c ntfsmeta.img.bz2 | cp --sparse=always /proc/self/fd/0 ntfsmeta.img

KNOWN ISSUES

There are no known problems with ntfsclone. If you think you have found a problem then please send an email describing it to the development team: ntfs-3g-devel@lists.sf.net

Sometimes it might appear ntfsclone froze if the clone is on ReiserFS and even CTRL-C won't stop it. This is not a bug in ntfsclone, however it's due to ReiserFS being extremely inefficient creating large sparse files and not handling signals during this operation. This ReiserFS problem was improved in kernel 2.4.22. XFS, JFS and ext3 don't have this problem.
