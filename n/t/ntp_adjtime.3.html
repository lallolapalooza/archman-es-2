adjtimex(2) Manual de llamadas al sistema adjtimex(2)

NOMBRE

adjtimex, clock_adjtime, ntp_adjtime - ajustar el reloj del kernel

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/timex.h>
int adjtimex(struct timex *buf);
int clock_adjtime(clockid_t clk_id, struct timex *buf);
int ntp_adjtime(struct timex *buf);

DESCRIPCIÓN

Linux utiliza el algoritmo de ajuste de reloj de David L. Mills (ver RFC 5905). La llamada al sistema adjtimex() lee y opcionalmente establece parámetros de ajuste para este algoritmo. Toma un puntero a una estructura timex, actualiza los parámetros del kernel desde (campos seleccionados) y devuelve la misma estructura actualizada con los valores actuales del kernel. Esta estructura se declara como sigue:


struct timex {
    int  modes;      /* Selector de modo */
    long offset;     /* Desfase de tiempo; nanosegundos, si el
                        indicador de estado STA_NANO está
                        activado, de lo contrario microsegundos */
    long freq;       /* Desfase de frecuencia; ver NOTAS para unidades */
    long maxerror;   /* Error máximo (microsegundos) */
    long esterror;   /* Error estimado (microsegundos) */
    int  status;     /* Comando/estado del reloj */
    long constant;   /* Constante de tiempo PLL (bucle de enganche de fase) */
    long precision;  /* Precisión del reloj
                        (microsegundos, solo lectura) */
    long tolerance;  /* Tolerancia de frecuencia del reloj (solo lectura);
                        ver NOTAS para unidades */
    struct timeval time;
                     /* Tiempo actual (solo lectura, excepto para
                        ADJ_SETOFFSET); al regresar, time.tv_usec
                        contiene nanosegundos, de lo contrario
                        microsegundos */
    long tick;       /* Microsegundos entre ticks del reloj */
    long ppsfreq;    /* Frecuencia PPS (pulso por segundo)
                        (solo lectura); ver NOTAS para unidades */
    long jitter;     /* Jitter PPS (solo lectura); nanosegundos, si
                        el indicador de estado STA_NANO está
                        activado, de lo contrario microsegundos */
    int  shift;      /* Duración del intervalo PPS
                        (segundos, solo lectura) */
    long stabil;     /* Estabilidad PPS (solo lectura);
                        ver NOTAS para unidades */
    long jitcnt;     /* Contador PPS de eventos de límite de jitter excedido
                        (solo lectura) */
    long calcnt;     /* Contador PPS de intervalos de calibración
                        (solo lectura) */
    long errcnt;     /* Contador PPS de errores de calibración
                        (solo lectura) */
    long stbcnt;     /* Contador PPS de eventos de límite de estabilidad excedido
                        (solo lectura) */
    int  tai;        /* Desfase TAI, establecido por operación ADJ_TAI
                        anterior (segundos, solo lectura,
                        desde Linux 2.6.26) */
    /* Bytes de relleno adicionales para permitir futuras expansiones */
};

El campo modes determina qué parámetros, si los hay, se establecen. (Como se describe más adelante en esta página, las constantes utilizadas para ntp_adjtime() son equivalentes pero tienen nombres diferentes). Es una máscara de bits que contiene una combinación a nivel de bits de cero o más de los siguientes bits:

ADJ_OFFSET
Establece el desfase de tiempo desde buf.offset. Desde Linux 2.6.26, el valor proporcionado se limita al rango (-0.5s, +0.5s). En kernels más antiguos, se produce un error EINVAL si el valor proporcionado está fuera de rango.
ADJ_FREQUENCY
Establece el desfase de frecuencia desde buf.freq. Desde Linux 2.6.26, el valor proporcionado se limita al rango (-32768000, +32768000). En kernels más antiguos, se produce un error EINVAL si el valor proporcionado está fuera de rango.
ADJ_MAXERROR
Establece el error de tiempo máximo desde buf.maxerror.
ADJ_ESTERROR
Establece el error de tiempo estimado desde buf.esterror.
ADJ_STATUS
Establece los bits de estado del reloj desde buf.status. Se proporciona una descripción de estos bits a continuación.
ADJ_TIMECONST
Establece la constante de tiempo PLL desde buf.constant. Si el indicador de estado STA_NANO (ver más abajo) está claro, el kernel suma 4 a este valor.
ADJ_SETOFFSET (desde Linux 2.6.39)
Añade buf.time al tiempo actual. Si buf.status incluye el indicador ADJ_NANO, entonces buf.time.tv_usec se interpreta como un valor de nanosegundos; de lo contrario, se interpreta como microsegundos.
El valor de buf.time es la suma de sus dos campos, pero el campo buf.time.tv_usec siempre debe ser no negativo. El siguiente ejemplo muestra cómo normalizar un timeval con resolución de nanosegundos.

while (buf.time.tv_usec < 0) {
    buf.time.tv_sec  -= 1;
    buf.time.tv_usec += 1000000000;
}

ADJ_MICRO (desde Linux 2.6.26)
Selecciona resolución de microsegundos.
ADJ_NANO (desde Linux 2.6.26)
Selecciona resolución de nanosegundos. Solo se debe especificar ADJ_MICRO o ADJ_NANO.
ADJ_TAI (desde Linux 2.6.26)
Establece el desfase TAI (Tiempo Internacional Atómico) desde buf.constant.
ADJ_TAI no debe usarse junto con ADJ_TIMECONST, ya que este último modo también utiliza el campo buf.constant.
Para una explicación completa de TAI y la diferencia entre TAI y UTC, ver BIPM
ADJ_TICK
Establece el valor de tick desde buf.tick.

Alternativamente, modes puede especificarse como cualquiera de los siguientes valores (máscara multibit), en cuyo caso no se deben especificar otros bits en modes:

ADJ_OFFSET_SINGLESHOT
El antiguo adjtime(3): ajusta (gradualmente) el tiempo por el valor especificado en buf.offset, que especifica un ajuste en microsegundos.
ADJ_OFFSET_SS_READ (funcional desde Linux 2.6.28)
Devuelve (en buf.offset) la cantidad restante de tiempo a ajustar después de una operación anterior ADJ_OFFSET_SINGLESHOT. Esta característica se añadió en Linux 2.6.24, pero no funcionó correctamente hasta Linux 2.6.28.

Los usuarios ordinarios están limitados a un valor de 0 o ADJ_OFFSET_SS_READ para modes. Solo el superusuario puede establecer cualquier parámetro.

El campo buf.status es una máscara de bits que se utiliza para establecer y/o recuperar bits de estado asociados con la implementación NTP. Algunos bits en la máscara se pueden leer y escribir, mientras que otros son de solo lectura.

STA_PLL (lectura-escritura)
Habilita actualizaciones de bucle de enganche de fase (PLL) a través de ADJ_OFFSET.
STA_PPSFREQ (lectura-escritura)
Habilita la disciplina de frecuencia PPS (pulso por segundo).
STA_PPSTIME (lectura-escritura)
Habilita la disciplina de tiempo PPS.
STA_FLL (lectura-escritura)
Selecciona el modo de bucle de enganche de frecuencia (FLL).
STA_INS (lectura-escritura)
Inserta un segundo intercalar después del último segundo del día UTC, extendiendo así el último minuto del día en un segundo. La inserción de segundos intercalares ocurrirá cada día, mientras este indicador permanezca activado.
STA_DEL (lectura-escritura)
Elimina un segundo intercalar en el último segundo del día UTC. La eliminación de segundos intercalares ocurrirá cada día, mientras este indicador permanezca activado.
STA_UNSYNC (lectura-escritura)
Reloj no sincronizado.

AJUSTE DEL RELOJ DEL SISTEMA

La llamada al sistema adjtimex() se utiliza para ajustar el reloj del sistema. El argumento adj_time es un puntero a una estructura timex que se utiliza para especificar los parámetros de ajuste.

La estructura timex se define como sigue:

struct timex {
    int modes;       // Flags para especificar qué miembros de la estructura se van a ajustar
    long offset;     // El desplazamiento del tiempo de hardware en microsegundos
    long freq;       // El desplazamiento de frecuencia del oscilador en partes por
                     // (2^16 / 1.000.000) partes por segundo
    long maxerror;   // El máximo error del reloj en microsegundos
    long esterror;   // El error estimado del reloj en microsegundos
    int  status;     // Banderas de estado del reloj
    long constant;   // Constante de calibración (obsoleta)
    long precision;  // Precisión del reloj en microsegundos (valor de salida)
    long tolerance;  // Tolerancia del oscilador en microsegundos (valor de salida)
    struct timeval time; // El tiempo actual (valor de salida)
    long tick;       // El número de microsegundos por tick del sistema (valor de salida)
    // ... (otros miembros para compatibilidad y expansión)
};

El miembro modes es una máscara de bits que indica qué miembros de la estructura timex deben ser ajustados. Los valores posibles para modes son:

ADJ_OFFSET (read-write)
Ajusta el tiempo del reloj por la cantidad especificada en offset. Este es un ajuste de "disparo único" que no se ve afectado por la frecuencia del reloj. Si se establece este modo, el valor de freq se establece en 0.
ADJ_FREQUENCY (read-write)
Ajusta la frecuencia del reloj por la cantidad especificada en freq. Este ajuste tiene como objetivo corregir la deriva a largo plazo del reloj.
ADJ_MAXERROR (read-write)
Establece el valor del máximo error del reloj en maxerror.
ADJ_ESTERROR (read-write)
Establece el valor del error estimado del reloj en esterror.
ADJ_STATUS (read-write)
Establece el valor de las banderas de estado del reloj en status. Las siguientes banderas de estado se pueden establecer o borrar:
STA_PLL (read-write)
El circuito de control de fase (PLL) está activo.
STA_PPM (read-write)
El circuito de control de frecuencia (PPM) está activo.
STA_ Accuracy (read-write)
El reloj es preciso.
STA_UNSYNC (read-write)
El reloj no está sincronizado.
STA_BROADCAST (read-write)
El reloj está operando en modo de difusión.
STA_USABLE (read-write)
El reloj es utilizable.
ADJ_TIMECODE (read-write)
Establece el código de tiempo en timecode.
ADJ_MICRO (read-write)
Establece la resolución del reloj en microsegundos.
ADJ_NANOSECOND (read-write)
Establece la resolución del reloj en nanosegundos.
ADJ_OFFSET_SINGLESHOT (read-write)
Ajusta el tiempo del reloj por la cantidad especificada en offset. A diferencia de ADJ_OFFSET, este ajuste es "a corto plazo" y no afecta a la frecuencia del reloj.
ADJ_OFFSET_SS_READ (read-only)
Lee el valor actual del ajuste de tiempo de "disparo único".
ADJ_TICK (read-write)
Ajusta el valor del tick del sistema en tick.
ADJ_NANO (read-write; since Linux 2.6.26)
Establece la resolución del reloj en nanosegundos. Es un sinónimo de ADJ_NANOSECOND.
ADJ_MICRO (read-write; since Linux 2.6.26)
Establece la resolución del reloj en microsegundos. Es un sinónimo de ADJ_OFFSET_SS_READ.
STA_FREQHOLD (read-write)
Mantener la frecuencia. Normalmente, los ajustes realizados a través de ADJ_OFFSET resultan en ajustes de frecuencia amortiguados. Así, una sola llamada corrige el desplazamiento actual, pero a medida que se realizan desplazamientos en la misma dirección repetidamente, los pequeños ajustes de frecuencia se acumularán para corregir la desviación a largo plazo.
Esta bandera evita que se realice el pequeño ajuste de frecuencia al corregir un valor de ADJ_OFFSET.
STA_PPSSIGNAL (read-only)
Hay presente una señal PPS (pulso por segundo) válida.
STA_PPSJITTER (read-only)
Se excedió la fluctuación de la señal PPS.
STA_PPSWANDER (read-only)
Se excedió la deriva de la señal PPS.
STA_PPSERROR (read-only)
Error de calibración de la señal PPS.
STA_CLOCKERR (read-only)
Fallo del hardware del reloj.
STA_NANO (read-only; since Linux 2.6.26)
Resolución (0 = microsegundo, 1 = nanosegundo). Se establece mediante ADJ_NANO, se borra mediante ADJ_MICRO.
STA_MODE (since Linux 2.6.26)
Modo (0 = Bucle de enganche de fase, 1 = Bucle de enganche de frecuencia).
STA_CLK (read-only; since Linux 2.6.26)
Fuente del reloj (0 = A, 1 = B); actualmente no se utiliza.

Los intentos de establecer bits de estado de solo lectura se ignoran silenciosamente.

clock_adjtime ()

La llamada al sistema clock_adjtime() (añadida en Linux 2.6.39) se comporta como adjtimex() pero toma un argumento adicional clk_id para especificar el reloj particular sobre el que actuar.

ntp_adjtime ()

La función de biblioteca ntp_adjtime() (descrita en la API de Programa de Aplicación del Kernel de NTP, KAPI) es una interfaz más portable para realizar la misma tarea que adjtimex(). Aparte de los siguientes puntos, es idéntica a adjtimex():

•
Las constantes utilizadas en modes se prefijan con "MOD_" en lugar de "ADJ_", y tienen los mismos sufijos (por lo tanto, MOD_OFFSET, MOD_FREQUENCY, y así sucesivamente), salvo las excepciones mencionadas en los siguientes puntos.
•
MOD_CLKA es el sinónimo de ADJ_OFFSET_SINGLESHOT.
•
MOD_CLKB es el sinónimo de ADJ_TICK.
•
No hay sinónimo para ADJ_OFFSET_SS_READ, que no se describe en la KAPI.

VALOR_DE_RETORNO

En caso de éxito, adjtimex() y ntp_adjtime() devuelven el estado del reloj; es decir, uno de los siguientes valores:

TIME_OK
Reloj sincronizado, no hay ajuste de segundo intercalar pendiente.
TIME_INS
Indica que se añadirá un segundo intercalar al final del día UTC.
TIME_DEL
Indica que se eliminará un segundo intercalar al final del día UTC.
TIME_OOP
La inserción de un segundo intercalar está en curso.
TIME_WAIT
Se ha completado la inserción o eliminación de un segundo intercalar. Este valor se devolverá hasta la próxima operación de ADJ_STATUS que borre las banderas STA_INS y STA_DEL.
TIME_ERROR
El reloj del sistema no está sincronizado con un servidor fiable. Este valor se devuelve cuando se cumple alguna de las siguientes condiciones:
•
Se establece STA_UNSYNC o STA_CLOCKERR.
•
STA_PPSSIGNAL está claro y se establece STA_PPSFREQ o STA_PPSTIME.
•
STA_PPSTIME y STA_PPSJITTER están ambos establecidos.
•
STA_PPSFREQ está establecido y se establece STA_PPSWANDER o STA_PPSJITTER.
El nombre simbólico TIME_BAD es un sinónimo de TIME_ERROR, proporcionado para compatibilidad con versiones anteriores.

Tenga en cuenta que a partir de Linux 3.4, la llamada opera de forma asíncrona y el valor de retorno generalmente no reflejará un cambio de estado causado por la propia llamada.

En caso de error, estas llamadas devuelven -1 y establecen errno para indicar el error.

ERRORES

EFAULT
buf no apunta a memoria escribible.
EINVAL (before Linux 2.6.26)
Se intentó establecer buf.freq a un valor fuera del rango (-33554432, +33554432).
EINVAL (before Linux 2.6.26)
Se intentó establecer buf.offset a un valor fuera del rango permitido. Antes de Linux 2.0, el rango permitido era (-131072, +131072). A partir de Linux 2.0, el rango permitido era (-512000, +512000).
EINVAL
Se intentó establecer buf.status a un valor distinto de los listados anteriormente.
EINVAL
El clk_id proporcionado a clock_adjtime() es inválido por una de dos razones. O bien el valor del ID de reloj positivo codificado en sistema duro estilo System-V está fuera de rango, o el clk_id dinámico no se refiere a una instancia válida de un objeto de reloj. Véase clock_gettime(2) para una discusión de los relojes dinámicos.
EINVAL
Se intentó establecer buf.tick a un valor fuera del rango 900000/HZ a 1100000/HZ, donde HZ es la frecuencia de interrupción del temporizador del sistema.
ENODEV
El dispositivo conectable en caliente (como USB, por ejemplo) representado por un clk_id dinámico ha desaparecido después de que se abriera su dispositivo de caracteres. Véase clock_gettime(2) para una discusión de los relojes dinámicos.
EOPNOTSUPP
El clk_id proporcionado no soporta el ajuste.
EPERM
buf.modes no es ni 0 ni ADJ_OFFSET_SS_READ, y el llamante no tiene privilegios suficientes. En Linux, se requiere la capacidad CAP_SYS_TIME.

NOTAS

En la estructura timex, freq, ppsfreq, y stabil son ppm (partes por millón) con una parte fraccional de 16 bits, lo que significa que un valor de 1 en uno de esos campos en realidad significa 2^-16 ppm, y 2^16=65536 es 1 ppm. Este es el caso tanto para los valores de entrada (en el caso de freq) como para los valores de salida.

El procesamiento de segundos intercalares activado por STA_INS y STA_DEL lo realiza el kernel en contexto de temporizador. Por lo tanto, se necesitará un tick para que el segundo intercalar se inserte o elimine.
