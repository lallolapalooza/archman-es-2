NTPD.CONF(5) Manual de formatos de archivo NTPD.CONF(5)

NOMBRE

ntpd.conf — Archivo de configuración del demonio del Protocolo de Tiempo de Red

DESCRIPCIÓN

Esta página del manual describe el formato del archivo de configuración de ntpd(8).

ntpd.conf tiene el siguiente formato:

Las líneas vacías y las líneas que comienzan con el carácter ‘#’ se ignoran.

Las palabras clave se pueden especificar varias veces dentro del archivo de configuración. Las opciones de configuración básicas son las siguientes:

escuchar en dirección [rtable id-tabla]
ntpd(8) tiene la capacidad de sincronizar el reloj local con servidores NTP remotos y, si esta directiva se especifica, puede actuar como servidor NTP en sí mismo, redistribuyendo el reloj local.

Especifique una dirección IP local o un nombre de host en el que el demonio ntpd(8) deba escuchar para permitir la sincronización de clientes remotos. Si aparece múltiples veces, ntpd(8) escuchará en cada dirección dada. Si se da ‘*’ como dirección, ntpd(8) escuchará en todas las direcciones locales utilizando la tabla de enrutamiento especificada. ntpd(8) no escucha en ninguna dirección por defecto. La palabra clave opcional rtable especificará en qué tabla de enrutamiento escuchar, si el sistema operativo soporta rdomains. Por defecto ntpd(8) escuchará utilizando la tabla de enrutamiento actual. Por ejemplo:

escuchar en *

o

escuchar en 127.0.0.1
escuchar en ::1
escuchar en 127.0.0.1 rtable 4
consultar desde direcciónorigen
Especifique una dirección IP local que el demonio ntpd(8) deba usar para las consultas salientes a los servidores especificados posteriormente, lo cual es útil en máquinas con múltiples interfaces. Por ejemplo: 
consultar desde 192.0.2.1
consultar desde 2001:db8::1
sensor dispositivo [correccion microsegundos] [refid cadena-ID] [estratum valor-estratum] [confiable] [peso valor-peso]
Especifique un dispositivo sensor de tiempo delta ntpd(8) a usar, si el sistema operativo soporta sensores. El sensor se puede especificar varias veces: ntpd(8) usará cada sensor dado que realmente exista. Los sensores inexistentes se ignoran. Si se da ‘*’ como nombre de dispositivo, ntpd(8) usará todos los sensores de tiempo delta que encuentre. ntpd(8) no usa ningún sensor de tiempo delta por defecto. Por ejemplo: 
sensor *
sensor nmea0

Se puede proporcionar una correccion en microsegundos para compensar el desfase del sensor. La corrección máxima es de 127 segundos. Por ejemplo, si un receptor DCF77 tiene un retraso de 70 ms respecto a la hora real:

sensor udcf0 correccion 70000

Se puede proporcionar un refid cadena-ID de hasta 4 caracteres ASCII para publicar el tipo de sensor a los clientes. RFC 2030 sugiere algunos identificadores de referencia comunes, pero se pueden idear nuevos identificadores "según sea apropiado". Si no se proporciona un ID-string, ntpd(8) usará un ID de referencia genérico. Por ejemplo:

sensor nmea0 refid GPS

La palabra clave stratum se puede usar para cambiar el valor de stratum del valor predeterminado de 1.

La palabra clave trusted indica que la hora aprendida es segura, confiable y no vulnerable a ataques de man-in-the-middle, por lo que se omite la validación de constraints. Esto es útil para la corrección al arrancar en entornos donde no se pueden usar constraints.

La palabra clave weight permite un control más fino sobre la importancia relativa de las fuentes de tiempo (servidores o dispositivos sensores). Los pesos se especifican en el rango de 1 a 10; si no se proporciona peso, el valor predeterminado es 1. Un servidor con un peso de 5, por ejemplo, tendrá cinco veces más influencia en el cálculo del desfase horario que un servidor con un peso de 1.

servidor dirección [confiable] [peso valor-peso]
Especifique la dirección IP o el nombre de host de un servidor NTP para sincronizar. Si aparece varias veces, ntpd(8) intentará sincronizarse con todos los servidores especificados. Si un nombre de host se resuelve a múltiples direcciones IPv4 y/o IPv6, ntpd(8) usa la primera dirección. Si no obtiene respuesta, ntpd(8) lo intenta de nuevo con la siguiente dirección y continúa hasta que encuentra una dirección que funciona. Por ejemplo: 
servidor 10.0.0.2 peso 5
servidor ntp.example.org peso 1

Para proporcionar redundancia, es una buena práctica configurar múltiples servidores. En general, la mejor precisión se obtiene utilizando servidores que tengan una baja latencia de red.

servidores dirección [confiable] [peso valor-peso]
Al igual que con servidor, especifique la dirección IP o el nombre de host de un servidor NTP para sincronizar. Si aparece varias veces, ntpd(8) intentará sincronizarse con todos los servidores especificados. En caso de que el nombre de host se resuelva a múltiples direcciones IP, ntpd(8) intentará sincronizarse con todas ellas. Por ejemplo: 
servidores pool.ntp.org
servidores pool.ntp.org peso 5

RESTRICCIONES

ntpd(8) puede configurarse para consultar la ‘Fecha’ de servidores HTTPS confiables a través de TLS. Esta información de tiempo no se utiliza para la precisión, sino que actúa como una restricción autenticada, reduciendo así el impacto de ataques de man-in-the-middle NTP no autenticados. Los paquetes NTP recibidos con información de tiempo que caiga fuera de un rango cercano a la restricción serán descartados y dichos servidores NTP serán marcados como inválidos.

El soporte para restricciones solo está disponible si ntpd(8) ha sido enlazado con libtls de LibreSSL. Configurar una restricción sin libtls hace que ntpd(8) registre un mensaje de advertencia al inicio.

restriccion desde url [ip...]
Especifique la URL, la dirección IP o el nombre de host de un servidor HTTPS para proporcionar una restricción. Si la URL va seguida de una o más direcciones, se probarán la URL y las direcciones hasta encontrar una que funcione. La ruta de la URL y el nombre del certificado esperado siempre se toman de la URL especificada. Si restriccion desde se usa más de una vez, ntpd(8) calculará una mediana de restricción a partir de todos los servidores especificados. 
servidor ntp.example.org
restriccion desde www.example.com
restriccion desde "https://9.9.9.9" "2620:fe::9"
restricciones desde url
Al igual que con restriccion desde, especifique la URL, la dirección IP o el nombre de host de un servidor HT

DESCRIPCIÓN

El archivo de configuración ntpd.conf contiene directivas que se utilizan para configurar el demonio del servicio de tiempo de red NTP (openntpd).

Cada directiva ocupa una línea, puede ir seguida de comentarios que comienzan con el carácter #. Las directivas reconocidas son:

servers
Especifica los servidores NTP que debe consultar el cliente. La directiva servers puede aparecer varias veces. La sintaxis es servers host [prefer]. Si se especifica prefer, este servidor se prefiere sobre otros. El servidor puede ser un nombre de host o una dirección IP. Si el nombre de host se resuelve en varias direcciones IP, ntpd calculará un valor mediano de la restricción de todas ellas. Por ejemplo:
servers pool.ntp.org
servers ntp.example.com prefer
constraints
Especifica un host desde el que se obtienen restricciones de tiempo. La directiva constraints puede aparecer varias veces. La sintaxis es constraints host. El host puede ser un nombre de host o una URL. Si el nombre de host se resuelve en varias direcciones IP, ntpd calculará un valor mediano de la restricción de todas ellas. Por ejemplo:
servers pool.ntp.org
constraints from "https://www.google.com/"
