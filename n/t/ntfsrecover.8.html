NTFSRECOVER(8) Manual del Administrador del Sistema NTFSRECOVER(8)

NOMBRE

ntfsrecover - Recupera actualizaciones confirmadas por Windows en un volumen NTFS

SINOPSIS

ntfsrecover [opciones] dispositivo

DESCRIPCIÓN

ntfsrecover aplica al metadato las actualizaciones que fueron solicitadas en Windows pero que no pudieron completarse porque fueron interrumpidas por algún evento como un corte de energía, un fallo de hardware, un fallo de software o la desconexión del dispositivo. Al hacerlo, el sistema de archivos se restaura a un estado consistente; sin embargo, las actualizaciones de datos de usuario aún pueden perderse.

La actualización del sistema de archivos generalmente requiere la actualización de varios registros que deberían completarse para mantener la consistencia del sistema de archivos. Por ejemplo, la creación de un nuevo archivo requiere reservar un número de inodo (establecer un bit en un mapa de bits), crear un registro de archivo (almacenar el nombre y los atributos del archivo) y registrar el archivo en un directorio (localizar el archivo a partir de alguna ruta). Cuando ocurre un evento desafortunado, y una de estas actualizaciones pudo realizarse pero no todas, el sistema de archivos queda inconsistente.

Un grupo de actualizaciones que deben realizarse para mantener la consistencia se denomina transacción, y el final de las actualizaciones dentro de una transacción se denomina confirmación de la transacción.

Para protegerse de eventos desafortunados, Windows primero registra en un archivo especial todas las solicitudes de actualización de metadatos sin aplicar ninguna, hasta que se conoce la confirmación. Si el evento ocurre antes de la confirmación, no se ha realizado ninguna actualización y el sistema de archivos es consistente. Si el evento ocurre después de la actualización, el archivo de registro puede ser analizado posteriormente y las transacciones que fueron confirmadas pueden ser reejecutadas, restaurando así la integridad del sistema de archivos.

ntfsrecover examina de manera similar el archivo de registro y aplica las actualizaciones dentro de las transacciones confirmadas que Windows no pudo realizar.

Actualmente, ntfs-3g no registra las actualizaciones, por lo que ntfsrecover no puede usarse para restaurar la consistencia después de que ocurrió un evento desafortunado mientras el sistema de archivos estaba siendo actualizado por Linux.

OPCIONES

A continuación se muestra un resumen de todas las opciones que acepta ntfsrecover. El uso normal es no utilizar ninguna opción, ya que la mayoría de estas opciones están orientadas a las necesidades de los desarrolladores.

Casi todas las opciones tienen dos nombres equivalentes. El nombre corto va precedido por - y el nombre largo va precedido por --. Las opciones de una sola letra que no toman un argumento se pueden combinar en un solo comando, por ejemplo, -bv es equivalente a -b -v. Los nombres largos de las opciones se pueden abreviar a cualquier prefijo único de su nombre.

-b, --backward
Examina las acciones descritas en el archivo de registro hacia atrás, desde la última hasta la primera, sin aplicar ninguna actualización. Esto puede abarcar registros generados durante varias sesiones, y cuando Windows se reinicia, a menudo no retoma la escritura donde terminó la sesión anterior, lo que genera errores y una mala secuenciación al examinar el archivo de registro completo.
-c, --clusters RANGO-DE-CLUSTERES
Restringe la salida generada al usar las opciones -b -f -u -p a las acciones que operan en un clúster dentro del rango de clústeres dado. RANGO-DE-CLUSTERES se define por los números de clúster inicial y final separados por un guion, por ejemplo, 100-109 o 0x3e8-0x3ff. Un solo número significa restringir a un solo clúster. Los primeros cuatro bloques de registro tienen un papel especial y siempre se muestran.
-f, --forward NUM
Examina las acciones descritas en el archivo de registro hacia adelante, desde la primera hasta la última, sin aplicar ninguna actualización. Como el archivo de registro se reutiliza circularmente, la primera acción no es generalmente la más antigua. Además, cuando Windows se reinicia, a menudo no retoma la escritura donde terminó las sesiones anteriores, y esto genera errores al examinar un archivo de registro generado durante varias sesiones.
-h, --help
Muestra información de ayuda.
-k, --kill-fast-restart
Cuando Windows se ha interrumpido con el modo de reinicio rápido activado, parte de los cambios pendientes se mantienen en la caché de Windows y solo la misma versión de Windows puede recuperarlos. Esta opción se puede usar para aplicar los cambios registrados en el archivo de registro y descartar los de la caché de Windows. Esto es peligroso y puede causar pérdida de datos.
-n, --no-action
No aplica ninguna modificación, útil cuando se usan las opciones -p, -s o -u.
-p, --play CUENTA
Deshace CUENTA conjuntos de transacciones y rehace uno solo, siendo un conjunto de transacciones todas las transacciones entre dos puntos de control consecutivos. Esto es útil para reproducir algunas transacciones en el pasado. Como pocas acciones son irrecuperables, esto no siempre es posible.
-r, --range RANGO-DE-BLOQUES
Examina las acciones descritas en el archivo de registro hacia adelante, restringido al rango de bloques del archivo de registro solicitado, sin aplicar ninguna actualización. Los primeros cuatro bloques de registro tienen un papel especial y siempre se examinan.
-s, --sync
Sincroniza el sistema de archivos aplicando las acciones confirmadas que no se habían sincronizado previamente. Esta es la opción predeterminada, utilizada cuando no están presentes ninguna de las opciones -n, -f, -r, -p y -u.

La opción -s se puede repetir para solicitar la aplicación de las acciones confirmadas mencionadas en la página de reinicio obsoleta. Esto es útil para probar situaciones en las que la última página de reinicio no se puede leer, aunque en realidad se pueda leer.

-t, --transactions CUENTA
Muestra los parámetros de transacción al examinar el archivo de registro con una de las opciones --forward, --backward o --range.
-u, --undo CUENTA
Deshace CUENTA conjuntos de transacciones, restableciendo así el sistema de archivos a algún punto de control en el pasado, siendo un conjunto de transacciones todas las transacciones entre dos puntos de control consecutivos. Como pocas acciones son irrecuperables, esto no siempre es posible.
-v, --verbose
Muestra más mensajes de depuración/advertencia/error. Esta opción se puede usar dos veces para mostrar aún más información.
-V, --version
Muestra el número de versión, los derechos de autor y la licencia de ntfsrecover.

EJEMPLOS

Sincroniza un volumen NTFS en /dev/sda1.

ntfsrecover -s /dev/sda1

Muestra todas las acciones que actualizaron un clúster en el rango de 100 a 119:

ntfsrecover --verbose --backward --clusters=100-119 /dev/sda1
