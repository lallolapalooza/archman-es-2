NTFSRESIZE(8) Manual del Administrador del Sistema NTFSRESIZE(8)

NOMBRE

ntfsresize - redimensionar un sistema de archivos NTFS sin pérdida de datos

SINOPSIS

ntfsresize [OPCIONES] --info(-mb-only) DISPOSITIVO
ntfsresize [OPCIONES] [--size TAMAÑO[k|M|G]] DISPOSITIVO

DESCRIPCIÓN

El programa ntfsresize redimensiona de forma segura sistemas de archivos NTFS de Windows XP, Windows Server 2003, Windows 2000, Windows NT4 y Longhorn sin pérdida de datos. Todas las versiones de NTFS son soportadas, utilizadas por Windows de 32 y 64 bits. La desfragmentación NO es requerida antes de redimensionar ya que el programa puede reubicar datos si es necesario, sin arriesgar la integridad de los datos.

Ntfsresize puede ser utilizado para reducir o agrandar cualquier sistema de archivos NTFS ubicado en un DISPOSITIVO desmontado (generalmente una partición de disco). El nuevo sistema de archivos cabrá en un DISPOSITIVO cuyo tamaño deseado sea de TAMAÑO bytes. El parámetro TAMAÑO puede tener uno de los modificadores opcionales k, M, G, que significa que el parámetro TAMAÑO se da en kilo-, mega- o gigabytes respectivamente. Ntfsresize se ajusta a los estándares SI, ATA, IEEE y de los fabricantes de discos utilizando k=10^3, M=10^6 y G=10^9.

Si se omiten tanto --info(-mb-only) como --size, el sistema de archivos NTFS se agrandará para que coincida con el tamaño del DISPOSITIVO subyacente.

Para redimensionar un sistema de archivos en una partición, debes redimensionar TANTO el sistema de archivos como la partición editando la tabla de particiones en el disco. De forma similar a otros redimensionadores de sistemas de archivos de línea de comandos, ntfsresize no manipula el tamaño de las particiones, por lo tanto, para hacerlo debes usar también una herramienta de particionamiento de disco, por ejemplo fdisk(8). Alternativamente, podrías usar uno de los muchos particionadores amigables para el usuario que usan ntfsresize internamente, como DiskDrake de Mandriva, QTParted, YaST Partitioner de SUSE/Novell, EVMS de IBM, GParted o Partman de Debian/Ubuntu.

¡IMPORTANTE! Es una buena práctica hacer COPIAS DE SEGURIDAD REGULARES de tus datos valiosos, especialmente antes de usar CUALQUIER herramienta de particionamiento. Para hacerlo para NTFS, podrías usar ntfsclone(8). ¡No olvides guardar también la tabla de particiones!

Reducción

Si deseas reducir una partición NTFS, primero usa ntfsresize para reducir el tamaño del sistema de archivos. Luego, podrías usar fdisk(8) para reducir el tamaño de la partición eliminando la partición y recreándola con el tamaño más pequeño. No hagas la partición más pequeña que el nuevo tamaño de NTFS, de lo contrario no podrás arrancar. Si lo hiciste a pesar de todo, simplemente recrea la partición para que sea tan grande como NTFS.

Ampliación

Para ampliar un sistema de archivos NTFS, primero debes ampliar el tamaño de la partición subyacente. Esto se puede hacer usando fdisk(8) eliminando la partición y recreándola con un tamaño mayor. Asegúrate de que no se solape con otra partición existente. Puedes ampliar hacia arriba (primer sector sin cambios) o hacia abajo (último sector sin cambios), pero no puedes ampliar en ambos extremos en un solo paso. Si fusionas dos particiones NTFS, solo una de ellas puede expandirse a la partición fusionada. Después de haber ampliado la partición, puedes usar ntfsresize para ampliar el tamaño del sistema de archivos.

Particionado

Al recrear la partición con una herramienta de particionamiento de disco, asegúrate de crearla en el mismo sector de inicio y con el mismo tipo de partición que antes. De lo contrario, no podrás acceder a tu sistema de archivos. Usa el comando 'u' de fdisk para cambiar a la unidad de sector confiable desde la unidad de cilindro predeterminada.

Asegúrate también de establecer la bandera de arranque para la partición si existía antes. Si no lo haces, es posible que no puedas arrancar tu ordenador desde el disco.

OPCIONES

A continuación se muestra un resumen de todas las opciones que acepta ntfsresize. Casi todas las opciones tienen dos nombres equivalentes. El nombre corto va precedido de - y el nombre largo va precedido de --. Cualquier opción de una sola letra, que no tome un argumento, puede combinarse en un solo comando, por ejemplo, -fv es equivalente a -f -v. Las opciones con nombre largo pueden abreviarse a cualquier prefijo único de su nombre.

-c, --check
Usando esta opción, ntfsresize solo comprobará el dispositivo para asegurar que está listo para ser redimensionado. Si no lo está, imprimirá cualquier error detectado. Si el dispositivo está bien, no se imprimirá nada.
-i, --info
Usando esta opción sin --expand, ntfsresize determinará el tamaño mínimo teóricamente posible para un sistema de archivos reducido. La mayoría de las veces el resultado es el espacio ya utilizado en el sistema de archivos. Ntfsresize se negará a reducir a un tamaño menor que el obtenido con esta opción y, dependiendo de varios factores, podría no ser capaz de reducir muy cerca de este tamaño teórico. Aunque la integridad de tus datos nunca debería estar en riesgo, todavía se recomienda encarecidamente hacer una prueba usando la opción --no-action antes del redimensionamiento real.

Prácticamente, el tamaño mínimo reducido suele estar alrededor de "espacio usado" + (20-200 MB). Ten en cuenta también que Windows podría necesitar aproximadamente 50-100 MB de espacio libre para arrancar de forma segura.

Si se usa en asociación con la opción --expand, ntfsresize determinará el tamaño mínimo de expansión hacia abajo y los incrementos posibles al tamaño. Estos son recuentos exactos de bytes que no deben redondearse. Esta opción puede usarse después de que la partición haya sido ampliada siempre que el límite superior no haya cambiado.

Esta opción nunca causa cambios en el sistema de archivos, el dispositivo se abre en modo de solo lectura.

-m, --info-mb-only
Al igual que la opción info, solo imprime el tamaño reducible en MB. No imprime nada si el tamaño de reducción es el mismo que el tamaño original (en MB). Esta opción no puede usarse en asociación con la opción --expand.
-s, --size TAMAÑO[k|M|G]
Redimensiona el sistema de archivos para que quepa en una partición cuyo tamaño es TAMAÑO[k|M|G] bytes, desplazando su final y manteniendo su principio sin cambios. El tamaño del sistema de archivos se establece para ser al menos un sector más pequeño que la partición. Los modificadores opcionales k, M, G significan que el parámetro TAMAÑO se da en kilo-, mega- o gigabytes respectivamente. De acuerdo con los estándares, k=10^3, M=10^6 y G=10^9. También se permiten ki=2^10, Mi=2^20 y Gi=2^30. Usa esta opción primero con --no-action.
-x, --expand
Expande el sistema de archivos al tamaño actual de la partición, desplazando su principio y manteniendo su final sin cambios. Los metadatos se recrean en el espacio expandido y no se relocalizan datos de usuario. Esto es incompatible con la opción -s (o --size) y solo puede hacerse si el espacio expandido es un múltiplo exacto del tamaño del clúster. También debe ser lo suficientemente grande para albergar los nuevos metadatos.

Si la expansión se interrumpe por alguna razón (corte de electricidad, etc.), puedes reiniciar el redimensionamiento, ya que los datos y metadatos originales se han mantenido sin cambios.

Nota: expandir una partición y sistema de archivos de sistema de Windows hacia abajo puede llevar a que el registro u otros archivos no coincidan con la nueva disposición del sistema, o a que algunos archivos importantes se ubiquen demasiado lejos del principio de la partición, haciendo que Windows no pueda arrancar.

-f, --force
Fuerza a ntfsresize a continuar con la operación de redimensionamiento, ya sea sin pedir una confirmación explícita, o si el sistema de archivos está marcado para una verificación de consistencia. Duplica la opción (-ff, --force --force) para evitar pedir confirmación incluso si el sistema de archivos está marcado para verificación.

Por favor, ten en cuenta que ntfsresize siempre marca el sistema de archivos para verificación de consistencia antes de una operación de redimensionamiento real y lo deja así por seguridad adicional. Por lo tanto, si NTFS fue marcado por ntfsresize, es seguro usar esta opción. Si necesitas redimensionar varias veces sin arrancar en Windows entre cada paso de redimensionamiento, debes usar esta opción.

OPCIONES

-n, --no-action
Utilice esta opción para realizar una ejecución de prueba antes de la operación de redimensionamiento real. El volumen se abrirá en modo de solo lectura y ntfsresize mostrará lo que haría si estuviera redimensionando el sistema de archivos. Continúe con el redimensionamiento real solo si la ejecución de prueba se completó correctamente.
-b, --bad-sectors
Soporta discos con errores de hardware, sectores defectuosos con los que ntfsresize se negaría a trabajar por defecto.

Antes de usar esta opción, se recomienda encarecidamente hacer una copia de seguridad con ntfsclone(8) usando la opción --rescue, y luego ejecutar 'chkdsk /f /r volumen:' en Windows desde la línea de comandos. Si la garantía del disco todavía es válida, reemplácelo. Está defectuoso. Tenga en cuenta también que ningún software puede reparar este tipo de errores de hardware. Lo máximo que pueden hacer es evitar los defectos permanentes.

Esta opción no tiene ningún efecto si el disco está impecable.

-P, --no-progress-bar
No muestre las barras de progreso.
-v, --verbose
Más salida.
-V, --version
Imprimir el número de versión de ntfsresize y salir.
-h, --help
Mostrar la ayuda y salir.

CÓDIGOS DE SALIDA

El código de salida es 0 en caso de éxito, distinto de cero en caso contrario.

PROBLEMAS CONOCIDOS

No se conocen problemas de fiabilidad. Si encuentra un error, envíe un correo electrónico describiendo el problema al equipo de desarrollo a:
ntfs-3g-devel@lists.sf.net

Actualmente existen algunas restricciones que rara vez se encuentran: los sistemas de archivos con sectores defectuosos desconocidos, la reubicación de la primera extensión de $MFT y el redimensionamiento en medio de una extensión de $MFTMirr aún no son compatibles. Estos casos se detectan y el redimensionamiento se limita a un tamaño seguro o se muestra el tamaño seguro más cercano.

Ntfsresize programa una verificación de consistencia de NTFS y, después del primer arranque en Windows, debe ver chkdsk ejecutándose sobre un fondo azul. Esto es intencional y no necesita preocuparse. Windows puede forzar un reinicio rápido después de la verificación de consistencia. Además, después de repartitionar su disco y dependiendo de la configuración del hardware, también puede aparecer el mensaje de Windows Cambio de configuración del sistema. Simplemente acéptelo y reinicie de nuevo.

La semántica de manejo de la geometría del disco (ioctl HDIO_GETGEO) ha cambiado de forma incompatible en los núcleos de Linux 2.6 y esto provocó multitud de corrupciones en la tabla de particiones, lo que resultó en sistemas Windows que no arrancaban, incluso si NTFS era consistente, si parted(8) estaba involucrado de alguna manera. Este problema a menudo se atribuyó a ntfsresize, pero en realidad es completamente independiente de NTFS, y por lo tanto de ntfsresize. Además, ntfsresize nunca toca la tabla de particiones. Al cambiar el 'Modo de acceso al disco' a LBA en la BIOS, el arranque vuelve a funcionar, la mayoría de las veces. Puede encontrar más información sobre este problema en la sección de Solución de problemas de la FAQ de Ntfsresize a continuación referida.
