NTLM_AUTH(1) Comandos de usuario NTLM_AUTH(1)

NOMBRE

ntlm_auth - herramienta para permitir el acceso externo a la función de autenticación NTLM de Winbind

SINOPSIS

ntlm_auth

DESCRIPCIÓN

Esta herramienta forma parte del conjunto de utilidades de samba(7).

ntlm_auth es una utilidad auxiliar que autentica usuarios utilizando la autenticación NT/LM. Devuelve 0 si el usuario es autenticado con éxito y 1 si se denegó el acceso. ntlm_auth utiliza winbind para acceder a los datos de usuario y autenticación de un dominio. Esta utilidad está pensada solo para ser utilizada por otros programas (actualmente Squid y mod_ntlm_winbind).

REQUISITOS OPERATIVOS

El demonio winbindd(8) debe estar operativo para que muchos de estos comandos funcionen.

Algunos de estos comandos también requieren acceso al directorio winbindd_privileged en $LOCKDIR. Esto debe hacerse ejecutando este comando como root o proporcionando acceso de grupo al directorio winbindd_privileged. Por razones de seguridad, este directorio no debe ser accesible para todos.

OPCIONES

--helper-protocol=PROTO

Opera como un ayudante basado en stdio. Los protocolos de ayudante válidos son:

squid-2.4-basic

Ayudante del lado del servidor para usar con la autenticación básica (texto plano) de Squid 2.4.

squid-2.5-basic

Ayudante del lado del servidor para usar con la autenticación básica (texto plano) de Squid 2.5.

squid-2.5-ntlmssp

Ayudante del lado del servidor para usar con la autenticación NTLMSSP de Squid 2.5.

Requiere acceso al directorio winbindd_privileged en $LOCKDIR. El protocolo utilizado se describe aquí: http://devel.squid-cache.org/ntlm/squid_helper_protocol.html. Este protocolo se ha ampliado para permitir que el paquete Negotiate de NTLMSSP se incluya como argumento para el comando YR. (Evitando así la pérdida de información en el intercambio de protocolos).

ntlmssp-client-1

Ayudante del lado del cliente para usar con programas externos arbitrarios que deseen utilizar el conocimiento de autenticación NTLMSSP de Samba.

Este ayudante es un cliente y, como tal, puede ser ejecutado por cualquier usuario. El protocolo utilizado es efectivamente el inverso del protocolo anterior. Un comando YR (sin argumentos) inicia el intercambio de autenticación.

gss-spnego

Ayudante del lado del servidor que implementa GSS-SPNEGO. Esto utiliza un protocolo que es casi el mismo que squid-2.5-ntlmssp, pero tiene algunas diferencias sutiles que no están documentadas fuera del código fuente en esta etapa.

Requiere acceso al directorio winbindd_privileged en $LOCKDIR.

gss-spnego-client

Ayudante del lado del cliente que implementa GSS-SPNEGO. Esto también utiliza un protocolo similar a los ayudantes anteriores, pero actualmente no está documentado.

ntlm-server-1

Protocolo de ayudante del lado del servidor, destinado a ser utilizado por un servidor RADIUS o el plugin 'winbind' para pppd, para la provisión de autenticación MSCHAP y MSCHAPv2.

Este protocolo consta de líneas de la forma: Parámetro: valor y Parámetro:: valor codificado en Base64. La presencia de un único punto . indica que un lado ha terminado de suministrar datos al otro. (Lo que a su vez podría hacer que el ayudante autentique al usuario).

Actualmente, los parámetros implementados desde el programa externo al ayudante son:

Username

El nombre de usuario, esperado en el charset unix de Samba.

Ejemplos:

Username: bob

Username:: Ym9i

NT-Domain

El dominio del usuario, esperado en el charset unix de Samba.

Ejemplos:

NT-Domain: WORKGROUP

NT-Domain:: V09SS0dST1VQ

Full-Username

El nombre de usuario completamente calificado, esperado en el charset unix de Samba y calificado con el separador de winbind.

Ejemplos:

Full-Username: WORKGROUP\bob

Full-Username:: V09SS0dST1VQYm9i

LANMAN-Challenge

El valor del desafío LANMAN de 8 bytes, generado aleatoriamente por el servidor, o (en casos como MSCHAPv2) generado de alguna manera tanto por el servidor como por el cliente.

Ejemplos:

LANMAN-Challenge: 0102030405060708

LANMAN-Response

El valor de respuesta LANMAN de 24 bytes, calculado a partir de la contraseña del usuario y el desafío LANMAN proporcionado. Típicamente, esto es proporcionado por un cliente que desea autenticarse a través de la red.

Ejemplos:

LANMAN-Response: 0102030405060708090A0B0C0D0E0F101112131415161718

NT-Response

La respuesta NT de >= 24 bytes calculada a partir de la contraseña del usuario y el desafío LANMAN proporcionado. Típicamente, esto es proporcionado por un cliente que desea autenticarse a través de la red.

Ejemplos:

NT-Response: 0102030405060708090A0B0C0D0E0F10111213141516171

Password

La contraseña del usuario. Esto sería proporcionado por un cliente de red, si el ayudante se está utilizando en una situación heredada que expone contraseñas en texto plano de esta manera.

Ejemplos:

Password: samba2

Password:: c2FtYmEy

Request-User-Session-Key

Tras una autenticación exitosa, devuelve la clave de sesión de usuario asociada con el inicio de sesión.

Ejemplos:

Request-User-Session-Key: Yes

Request-LanMan-Session-Key

Tras una autenticación exitosa, devuelve la clave de sesión LANMAN asociada con el inicio de sesión.

Ejemplos:

Request-LanMan-Session-Key: Yes

Advertencia
Los implementadores deben tener cuidado de codificar en base64 cualquier dato (como nombres de usuario/contraseñas) que pueda contener datos maliciosos del usuario, como una nueva línea. También pueden necesitar decodificar cadenas del ayudante, que de manera similar pueden haber sido codificadas en base64.

--username=NOMBREDEUSUARIO

Especificar el nombre de usuario a autenticar.

--domain=DOMINIO

Especificar el dominio del usuario a autenticar.

--workstation=ESTACIONDETRABAJO

Especificar la estación de trabajo desde la que se autenticó el usuario.

--challenge=CADENA

Desafío NTLM (en HEXADECIMAL).

--lm-response=RESPUESTA

Respuesta LM al desafío (en HEXADECIMAL).

--nt-response=RESPUESTA

Respuesta NT o NTLMv2 al desafío (en HEXADECIMAL).

--password=CONTRASENA

Contraseña en texto plano del usuario.

Si no se especifica en la línea de comandos, se solicitará cuando sea necesario.

Para los roles de servidor basados en NTLMSSP, este parámetro especifica la contraseña esperada, lo que permite probar sin que winbindd esté operativo.

--request-lm-key

Recuperar la clave de sesión LM.

--request-nt-key

Solicitar la clave NT.

--diagnostics

Realizar diagnósticos en la cadena de autenticación. Utiliza la contraseña de --password o solicita una.

--require-membership-of={SID|Nombre}

Requerir que un usuario sea miembro del grupo especificado (ya sea por nombre o SID) para que la autenticación tenga éxito.

--pam-winbind-conf=NOMBREARCHIVO

Definir la ruta al archivo pam_winbind.conf.

--target-hostname=NOMBREHOST

Definir el nombre de host de destino.

--target-service=SERVICIO

Definir el servicio de destino.

--use-cached-creds

Indica si se deben utilizar las credenciales almacenadas en caché por winbindd.

--allow-mschapv2

Permitir explícitamente MSCHAPv2.

--offline-logon

Permitir inicios de sesión sin conexión para autenticación de texto plano.

-?|--help

Imprimir un resumen de las opciones de la línea de comandos.

--usage

Mostrar un breve mensaje de uso.

-d|--debuglevel=nivel

nivel es un entero de 0 a 10. El valor predeterminado si no se especifica este parámetro es 1 para aplicaciones cliente.

Cuanto mayor sea el t

VALOR

El valor, cuanto más detallado sea, más información se registrará en los archivos de registro sobre las actividades del servidor. En el nivel 0, solo se registrarán errores críticos y advertencias graves. El nivel 1 es un nivel razonable para la operación diaria: genera una pequeña cantidad de información sobre las operaciones realizadas.

Los niveles superiores a 1 generarán una cantidad considerable de datos de registro y solo deben usarse al investigar un problema. Los niveles superiores a 3 están diseñados para ser utilizados únicamente por los desarrolladores y generan ENORMES cantidades de datos de registro, la mayoría de los cuales son extremadamente crípticos.

Tenga en cuenta que la especificación de este parámetro aquí anulará el parámetro log level en el archivo /etc/samba/smb.conf.

--debug-stdout

Esto redirigirá la salida de depuración a STDOUT. Por defecto, todos los clientes registran en STDERR.

--configfile=<archivo de configuración>

El archivo especificado contiene los detalles de configuración requeridos por el cliente. La información en este archivo puede ser general para el cliente y el servidor o solo proporcionar opciones específicas del cliente, como client smb encrypt. Consulte /etc/samba/smb.conf para obtener más información. El nombre del archivo de configuración predeterminado se determina en el momento de la compilación.

--option=<nombre>=<valor>

Establezca la opción smb.conf(5) "<nombre>" al valor "<valor>" desde la línea de comandos. Esto anula los valores predeterminados compilados y las opciones leídas del archivo de configuración. Si un nombre o un valor incluye un espacio, envuelva todo --option=name=value entre comillas.

-V|--version

Imprime el número de versión del programa.

CONFIGURACIÓN DE EJEMPLO

Para configurar ntlm_auth para su uso por squid 2.5, con autenticación básica y NTLMSSP, lo siguiente debería colocarse en el archivo squid.conf.

auth_param ntlm program ntlm_auth --helper-protocol=squid-2.5-ntlmssp
auth_param basic program ntlm_auth --helper-protocol=squid-2.5-basic
auth_param basic children 5
auth_param basic realm Squid proxy-caching web server
auth_param basic credentialsttl 2 hours

Nota

Este ejemplo asume que ntlm_auth ha sido instalado en su ruta y que los permisos de grupo en winbindd_privileged son como se describe anteriormente.

Para configurar ntlm_auth para su uso por squid 2.5 con limitación de grupo además del ejemplo anterior, lo siguiente debería agregarse al archivo squid.conf.

auth_param ntlm program ntlm_auth --helper-protocol=squid-2.5-ntlmssp --require-membership-of='WORKGROUP\Domain Users'
auth_param basic program ntlm_auth --helper-protocol=squid-2.5-basic --require-membership-of='WORKGROUP\Domain Users'

SOLUCIÓN DE PROBLEMAS

Si está experimentando problemas con la autenticación de Internet Explorer ejecutándose en MS Windows 9X o Millennium Edition contra el ayudante de autenticación NTLMSSP de ntlm_auth (--helper-protocol=squid-2.5-ntlmssp), lea el artículo de la Base de datos de conocimiento de Microsoft #239869 y siga las instrucciones descritas allí.
