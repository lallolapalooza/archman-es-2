Nombre

nix-store --add-fixed - agregar rutas al almacén usando el algoritmo de hash dado

Sinopsis

nix-store --add-fixed [--recursive] algoritmo rutas…

Descripción

La operación --add-fixed agrega las rutas especificadas al almacén de Nix. A diferencia de --add, las rutas se registran utilizando el algoritmo de hash especificado, lo que resulta en la misma ruta de salida que una derivación de salida fija. Esto puede ser útil para fuentes que no están disponibles desde una URL pública o que se han roto desde que se escribió la expresión de descarga.

Esta operación tiene las siguientes opciones:

•
--recursive
Usa el modo de hash recursivo en lugar de plano, utilizado al agregar directorios al almacén.

Opciones

Las siguientes opciones están permitidas para todas las operaciones de nix-store, pero pueden no tener efecto siempre.

•
--add-root ruta
Hace que el resultado de una realización (--realise y --force-realise) se registre como una raíz del recolector de basura. Se creará ruta como un enlace simbólico a la ruta de almacén resultante. Además, se creará un enlace simbólico con un nombre único a ruta en /nix/var/nix/gcroots/auto/. Por ejemplo:
$ nix-store --add-root /home/eelco/bla/resultado --realise ...
$ ls -l /nix/var/nix/gcroots/auto
lrwxrwxrwx    1 ... 2005-03-13 21:10 dn54lcypm8f8... -> /home/eelco/bla/resultado
$ ls -l /home/eelco/bla/resultado
lrwxrwxrwx    1 ... 2005-03-13 21:10 /home/eelco/bla/resultado -> /nix/store/1r11343n6qd4...-f-spot-0.0.10
Por lo tanto, cuando se elimina /home/eelco/bla/resultado, la raíz del recolector de basura en el directorio auto se convierte en un enlace simbólico colgante y será ignorada por el recolector.
Advertencia
Tenga en cuenta que no es posible mover o renombrar raíces del recolector de basura, ya que el enlace simbólico en el directorio auto seguirá apuntando a la ubicación antigua.
Si hay varios resultados, se crearán varios enlaces simbólicos numerando secuencialmente los enlaces simbólicos más allá del primero (por ejemplo, foo, foo-2, foo-3, y así sucesivamente).

La mayoría de los comandos de Nix aceptan las siguientes opciones de línea de comandos:

•

•

•
1 "Informativo"

•
2 "Hablador"
Imprime más mensajes informativos.
•
3 "Charla"
Imprime aún más mensajes informativos.
•
4 "Depuración"
Imprime información de depuración.
•
5 "Vómito"
Imprime una gran cantidad de información de depuración.
•
--quiet
Disminuye el nivel de verbosidad de los mensajes de diagnóstico impresos en la salida estándar de error. Esta es la opción inversa a -v / --verbose.
Esta opción se puede especificar repetidamente. Consulte la lista anterior de niveles de verbosidad.
•
--log-format formato
Esta opción se puede usar para cambiar la salida del formato de registro, con formato siendo uno de:
•
raw
Este es el formato crudo, tal como lo emite nix-build.
•
internal-json
Emite los registros de forma estructurada.
Advertencia
Si bien el esquema en sí es relativamente estable, el formato de los mensajes de error (específicamente del campo msg) puede cambiar entre versiones.
•
bar
Solo muestra una barra de progreso durante las compilaciones.
•
bar-with-logs
Muestra los registros crudos, con la barra de progreso en la parte inferior.
•
--no-build-output / -Q
Por defecto, la salida escrita por los constructores a la salida estándar y a la salida estándar de error se refleja en la salida estándar de error del comando Nix. Esta opción suprime este comportamiento. Tenga en cuenta que la salida y el error estándar del constructor siempre se escriben en un archivo de registro en prefijo/nix/var/log/nix.
•
--max-jobs / -j número
Establece el número máximo de trabajos de compilación que Nix realizará en paralelo al número especificado. Especifique auto para usar el número de CPU del sistema. El valor predeterminado es el especificado por la configuración max-jobs, que a su vez tiene como valor predeterminado 1. Un valor más alto es útil en sistemas SMP o para explotar la latencia de E/S.
Establecerlo en 0 deshabilita la compilación en la máquina local, lo que es útil cuando desea que las compilaciones ocurran solo en constructores remotos.
•
--cores
Establece el valor de la variable de entorno NIX_BUILD_CORES en la invocación de los constructores. Los constructores pueden usar esta variable a su discreción.

Por defecto, usa el valor de la configuración cores, si está establecida, o 1 en caso contrario. El valor 0 significa que el constructor debe usar todos los núcleos de CPU disponibles en el sistema.
•
--max-silent-time
Establece el número máximo de segundos que un constructor puede pasar sin producir ninguna salida en la salida estándar o el error estándar. El valor por defecto lo especifica la configuración max-silent-time. 0 significa sin tiempo de espera.
•
--timeout
Establece el número máximo de segundos que un constructor puede ejecutarse. El valor por defecto lo especifica la configuración timeout. 0 significa sin tiempo de espera.
•
--keep-going / -k
Continúa en caso de fallos en la compilación, en la mayor medida posible. Es decir, si falla la compilación de una entrada de alguna derivación, Nix compilará las otras entradas, pero no la derivación en sí. Sin esta opción, Nix se detiene si falla alguna compilación (excepto las compilaciones de sustitutos), posiblemente matando las compilaciones en curso (en caso de compilaciones paralelas o distribuidas).
•
--keep-failed / -K
Especifica que en caso de fallo en la compilación, el directorio temporal (generalmente en /tmp) en el que se realiza la compilación no debe ser eliminado. La ruta del directorio de compilación se imprime como un mensaje informativo.
•
--fallback
Siempre que Nix intente compilar una derivación para la cual se conocen sustitutos para cada ruta de salida, pero la realización de las rutas de salida a través de los sustitutos falla, recurre a la compilación de la derivación.
El escenario más común en el que esto es útil es cuando hemos registrado sustitutos para realizar la distribución binaria desde, por ejemplo, un repositorio de red. Si el repositorio está caído, la realización de la derivación fallará. Cuando se especifica esta opción, Nix compilará la derivación en su lugar. Por lo tanto, la instalación desde binarios recurre a la instalación desde el código fuente. Esta opción no es la predeterminada, ya que generalmente no es deseable que un fallo transitorio en la obtención de los sustitutos conduzca a una compilación completa desde el código fuente (con el consumo de recursos relacionado).
•
--readonly-mode
Cuando se utiliza esta opción, no se intenta abrir la base de datos de Nix. La mayoría de las operaciones de Nix necesitan acceso a la base de datos, por lo que esas operaciones fallarán.
•
--arg nombre valor
Esta opción es aceptada por nix-env, nix-instantiate, nix-shell y nix-build. Al evaluar expresiones Nix, el evaluador de expresiones intentará automáticamente llamar a las funciones que encuentre. Puede llamar automáticamente a funciones para las que cada argumento tiene un valor predeterminado (por ejemplo, { argName ? defaultValue }: ...).
Con --arg, también puede llamar a funciones que tienen argumentos sin valor predeterminado (o anular un valor predeterminado). Es decir, si el evaluador encuentra una función con un argumento llamado nombre, la llamará con el valor valor.
Por ejemplo, el default.nix principal en Nixpkgs es en realidad una función:
{ # El sistema (por ejemplo, `i686-linux') para el que se compilan los paquetes.
system ? builtins.currentSystem
...
}: ...
Así que si llama a esta expresión Nix (por ejemplo, cuando hace nix-env --install --attr pkgname), la función se llamará automáticamente usando el valor builtins.currentSystem para el argumento system. Puede anular esto usando --arg, por ejemplo, nix-env --install --attr pkgname --arg system \"i686-freebsd\". (Tenga en cuenta que como el argumento es una cadena literal de Nix, debe escapar las comillas.)
•
--argstr nombre valor
Esta opción es como --arg, solo que el valor no es una expresión Nix sino una cadena. Así que en lugar de --arg system \"i686-linux\" (las comillas externas son para mantener la consola feliz) puede decir --argstr system i686-linux.
•
--attr / -A rutaAttr
Selecciona un atributo de la expresión Nix de nivel superior que se está evaluando. (Solo nix-env, nix-instantiate, nix-build y nix-shell.) La ruta de atributos rutaAttr es una secuencia de nombres de atributos separados por puntos. Por ejemplo, dada una expresión Nix de nivel superior e, la ruta de atributos xorg.xorgserver haría que se utilizara la expresión e.xorg.xorgserver. Consulte nix-env --install para ver algunos ejemplos concretos.
Además de los nombres de atributos, también puede especificar índices de arrays. Por ejemplo, la ruta de atributos foo.3.bar selecciona el atributo bar del cuarto elemento del array en el atributo foo de la expresión de nivel superior.
•
--expr / -E
Interpreta los argumentos de la línea de comandos como una lista de expresiones Nix para ser analizadas y evaluadas, en lugar de como una lista de nombres de archivo de expresiones Nix. (Solo nix-instantiate, nix-build y nix-shell.)
Para nix-shell, esta opción se usa comúnmente para proporcionarle un shell en el que pueda compilar los paquetes devueltos por la expresión. Si desea obtener un shell que contenga los paquetes *compilados* listos para usar, proporcione su expresión a la opción de conveniencia nix-shell --packages en su lugar.
•
-I / --include ruta
Añade una entrada a la lista de rutas de búsqueda utilizadas para resolver rutas de búsqueda. Esta opción puede especificarse varias veces.
Las rutas añadidas a través de -I tienen precedencia sobre la configuración nix-path y la variable de entorno NIX_PATH.
•
--option nombre valor
Establece la opción de configuración de Nix nombre en valor. Esto anula la configuración del archivo de configuración de Nix (véase nix.conf5).
•
--repair
Repara rutas de almacenamiento corruptas o faltantes volviendo a descargarlas o recompilándolas. Tenga en cuenta que esto es lento porque requiere calcular un hash criptográfico del contenido de cada ruta en el cierre de la compilación. Tenga también en cuenta la advertencia bajo nix-store --repair-path.

Nota

Consulte man nix.conf para anular la configuración con flags de línea de comandos.

Name

nix-store --realizar operaciones sobre la tienda Nix

SYNOPSIS

nix-store [option...] command [argument...]

DESCRIPTION

El comando nix-store es la interfaz de bajo nivel para la tienda Nix. Normalmente, no necesitarás usarlo directamente; en su lugar, usarás comandos de nivel superior como nix-env, nix-build y nix-shell.

El propósito principal de nix-store es construir una o más derivaciones y añadir sus resultados a la tienda Nix.

Store commands

•
--add-fixed
Añade un archivo a la tienda Nix y devuelve su hash de contenido. La derivación del archivo se construirá usando el hash especificado.
El hash se puede especificar en forma de un hash de contenido Nix (por ejemplo, sha256:09c5100978273d36676168a1f769702e17971627391744098335a441124d8d92). Nix comprueba que el archivo que se está añadiendo tenga este hash. Si no coincide, Nix lanzará un error.
•
--add-unsquashed
Similar a --add-fixed, pero no se intenta reducir la derivación, lo que permite añadir archivos que no son una derivación reducida. Se usa para añadir derivaciones no reducidas a la tienda.
•
--build
Construye una o más derivaciones. Por defecto, sólo se construyen las derivaciones que aún no están en la tienda Nix.
Si una derivación ya existe en la tienda Nix, no se construirá de nuevo. Sin embargo, si se especifica --force, la derivación se reconstruirá aunque ya exista en la tienda.
•
--deriver
Devuelve la derivación que produce un registro de la tienda dado. Es decir, si /nix/store/...-foo es un registro de la tienda, nix-store --deriver /nix/store/...-foo devolverá la derivación que lo produjo.
•
--diff
Compara dos registros de la tienda y muestra las diferencias.
•
--export-store-path
Escribe un registro de la tienda en la salida estándar en formato binario. Este formato está destinado a ser importado por --import-store-path.
•
--find-output
Encuentra el registro de la tienda para una salida específica de una derivación dada.
•
--force
Fuerza la reconstrucción de las derivaciones incluso si ya existen en la tienda Nix.
•
--gc-paths
Devuelve una lista de todos los registros de la tienda que son accesibles desde los registros especificados (o todos los registros si no se especifica ninguno).
•
--import-store-path
Lee un registro de la tienda de la entrada estándar en formato binario y lo añade a la tienda Nix. Este formato se usa para la transferencia entre máquinas Nix.
•
--query
Pregunta sobre los registros de la tienda Nix. Con este comando, puedes obtener información sobre un registro de la tienda, como su derivación o sus dependencias.
•
--references
Devuelve una lista de todos los registros de la tienda que son referenciados por los registros especificados.
•
--references-to
Devuelve una lista de todos los registros de la tienda que referencian los registros especificados.
•
--register-validity
Registra la validez de los registros especificados de la tienda. Se usa para mantener el registro de la tienda coherente.
•
--requisites
Devuelve una lista de todos los registros de la tienda que son requeridos por los registros especificados (incluyendo las propias derivaciones).
•
--set-stale
Marca los registros especificados de la tienda como obsoletos. Se usa para la recolección de basura.
•
--tree-hash
Calcula el hash de contenido de un árbol de archivos.
•
--unpack
Desempaqueta un registro de la tienda en el directorio de trabajo actual.
•
--verify-store-path
Verifica la validez de un registro de la tienda.

Options

•
NIX_PATH
Una lista de rutas de búsqueda para las importaciones Nix (por ejemplo, <nixpkgs>). Si se establece a una cadena vacía, la resolución de rutas de búsqueda siempre fallará.
Ejemplo
$ NIX_PATH= nix-instantiate --eval '<nixpkgs>'
error: file 'nixpkgs' was not found in the Nix search path (add it using $NIX_PATH or -I)
•
NIX_IGNORE_SYMLINK_STORE
Normalmente, el directorio de la tienda Nix (típicamente /nix/store) no tiene permitido contener ningún componente de enlace simbólico. Esto es para prevenir construcciones "impuras". Los constructores a veces "canonicen" rutas resolviendo todos los componentes de enlace simbólico. Por lo tanto, las construcciones en diferentes máquinas (con /nix/store resolviendo a ubicaciones diferentes) podrían producir resultados diferentes. Esto generalmente no es un problema, excepto cuando las construcciones se despliegan en máquinas donde /nix/store resuelve de manera diferente. Si estás seguro de que no vas a hacer eso, puedes establecer NIX_IGNORE_SYMLINK_STORE a 1.
Ten en cuenta que si estás enlazando simbólicamente la tienda Nix para poder ponerla en un sistema de archivos distinto del sistema de archivos raíz, en Linux es mejor usar puntos de montaje bind, por ejemplo:
$ mkdir /nix
$ mount -o bind /mnt/otherdisk/nix /nix
Consulta la página del manual de mount 8 para más detalles.
•
NIX_STORE_DIR
Anula la ubicación del directorio de la tienda Nix (por defecto prefix/store).
•
NIX_DATA_DIR
Anula la ubicación del directorio de datos estáticos de Nix (por defecto prefix/share).
•
NIX_LOG_DIR
Anula la ubicación del directorio de registro de Nix (por defecto prefix/var/log/nix).
•
NIX_STATE_DIR
Anula la ubicación del directorio de estado de Nix (por defecto prefix/var/nix).
•
NIX_CONF_DIR
Anula la ubicación del directorio de configuración del sistema Nix (por defecto prefix/etc/nix).
•
NIX_CONFIG
Aplica configuraciones desde la configuración Nix del entorno. El contenido se trata como si se hubiera leído de un archivo de configuración Nix. Las configuraciones están separadas por el carácter de nueva línea.
•
NIX_USER_CONF_FILES
Anula la ubicación de los archivos de configuración de usuario de Nix desde donde cargar.
Los valores por defecto son las ubicaciones según la Especificación de Directorios Base de XDG. Consulta la subsección Directorios Base de XDG para más detalles.
La variable se trata como una lista separada por el token :.
•
TMPDIR
Utiliza el directorio especificado para almacenar archivos temporales. En particular, esto incluye directorios de construcción temporales; estos pueden ocupar una cantidad sustancial de espacio en disco. El valor por defecto es /tmp.
•
NIX_REMOTE
Esta variable debe establecerse a daemon si quieres usar el demonio Nix para ejecutar operaciones Nix. Esto es necesario en las instalaciones Nix multiusuario. Si el socket Unix del demonio Nix está en alguna ruta no estándar, esta variable debe establecerse a unix://path/to/socket. De lo contrario, debe dejarse sin establecer.
•
NIX_SHOW_STATS
Si se establece a 1, Nix imprimirá algunas estadísticas de evaluación, como el número de valores asignados.
•
NIX_COUNT_CALLS
Si se establece a 1, Nix imprimirá cuántas veces se llamaron las funciones durante la evaluación de expresiones Nix. Esto es útil para perfilar tus expresiones Nix.
•
GC_INITIAL_HEAP_SIZE
Si Nix ha sido configurado para usar el recolector de basura Boehm, esta variable establece el tamaño inicial del montón en bytes. Por defecto es 384 MiB. Establecerlo a un valor bajo reduce el consumo de memoria, pero aumentará el tiempo de ejecución debido a la sobrecarga de la recolección de basura.

Directorios Base de XDG

Nix sigue la Especificación de Directorios Base de XDG.

Por compatibilidad con versiones anteriores, los comandos Nix seguirán el estándar sólo cuando use-xdg-base-directories esté habilitado. Los comandos Nix nuevos (experimentales) cumplen con el estándar por defecto.

Las siguientes variables de entorno se utilizan para determinar las ubicaciones de varios archivos de estado y configuración:

  • [XDG_CONFIG_HOME]{#env-XDGCONFIGHOME} (por defecto ~/.config)
  • [XDG_STATE_HOME]{#env-XDGSTATEHOME} (por defecto ~/.local/state)
  • [XDG_CACHE_HOME]{#env-XDGCACHEHOME} (por defecto ~/.cache)

Ejemplo

$ nix-store --add-fixed sha256 ./hello-2.10.tar.gz
/nix/store/3x7dwzq014bblazs7kq20p9hyzz0qh8g-hello-2.10.tar.gz
