nix-env(1) Manual de comandos generales nix-env(1)

Nombre

nix-env - manipular o consultar entornos de usuario Nix

Sinopsis

nix-env operación [opciones] [argumentos] [--option nombre valor] [--arg nombre valor] [--argstr nombre valor] [{--file | -f} ruta] [{--profile | -p} ruta] [--system-filter sistema] [--dry-run]

Descripción

El comando nix-env se utiliza para manipular entornos de usuario Nix. Los entornos de usuario son conjuntos de paquetes de software disponibles para un usuario en un momento dado. En otras palabras, son una vista sintetizada de los programas disponibles en el almacén de Nix. Puede haber muchos entornos de usuario: diferentes usuarios pueden tener diferentes entornos, y los usuarios individuales pueden cambiar entre diferentes entornos.

nix-env toma exactamente una bandera de operación que indica el subcomando a realizar. Las siguientes operaciones están disponibles:

  • --install
  • --upgrade
  • --uninstall
  • --set
  • --set-flag
  • --query
  • --switch-profile
  • --list-generations
  • --delete-generations
  • --switch-generation
  • --rollback

Estas páginas se pueden ver sin conexión:

•
man nix-env-<operación>.
Ejemplo: man nix-env-install
•
nix-env --help --<operación>
Ejemplo: nix-env --help --install

Fuentes de paquetes

nix-env puede obtener paquetes de múltiples fuentes:

•
Un conjunto de atributos de derivaciones de:
  • La expresión Nix predeterminada (por defecto)
  • Un archivo Nix, especificado a través de --file
  • Un perfil, especificado a través de --from-profile
  • Una expresión Nix que es una función que toma la expresión predeterminada como argumento, especificada a través de --from-expression
•
Una ruta del almacén

Selectores

Varias operaciones, como nix-env --query y nix-env --install, toman una lista de argumentos que especifican los paquetes sobre los que operar.

Los paquetes se identifican basándose en una parte de nombre y una parte de versión de un nombre de derivación simbólico:

  • nombre: Todo hasta, pero sin incluir, el primer guion (-) que *no* está seguido por una letra.
  • versión: El resto, excluyendo el guion separador.

Ejemplo

nix-env analiza el nombre de derivación simbólico apache-httpd-2.0.48 como:

{
  "nombre": "apache-httpd",
  "version": "2.0.48"
}

Ejemplo

nix-env analiza el nombre de derivación simbólico firefox.* como:

{
  "nombre": "firefox.*",
  "version": ""
}

Las partes de nombre de los argumentos a nix-env se tratan como expresiones regulares extendidas y se comparan con las partes de nombre de los nombres de derivación en la fuente del paquete. La comparación distingue entre mayúsculas y minúsculas. La expresión regular puede ir seguida opcionalmente por un guion (-) y un número de versión; si se omite, cualquier versión del paquete coincidirá. Para obtener detalles sobre expresiones regulares, consulte regex(7).

Ejemplo

Patrones comunes para encontrar nombres de paquetes con nix-env:

•
firefox
Coincide con el nombre del paquete firefox y cualquier versión.
•
firefox-32.0
Coincide con el nombre del paquete firefox y la versión 32.0.
•
gtk\\+
Coincide con el nombre del paquete gtk+. El carácter + debe escaparse usando una barra invertida (\) para evitar que se interprete como un cuantificador, y la barra invertida debe escaparse a su vez con otra barra invertida para garantizar que el shell la pase.
•
.\*
Coincide con cualquier nombre de paquete. Este es el valor predeterminado para la mayoría de los comandos.
•
'.*zip.*'
Coincide con cualquier nombre de paquete que contenga la cadena zip. Tenga en cuenta los puntos: '*zip*' no funciona, porque en una expresión regular, el carácter * se interpreta como un cuantificador.
•
'.*(firefox|chromium).*'
Coincide con cualquier nombre de paquete que contenga las cadenas firefox o chromium.

Archivos

nix-env opera sobre los siguientes archivos.

Expresión Nix predeterminada

La fuente para las expresiones Nix predeterminadas utilizadas por nix-env:

  • ~/.nix-defexpr
  • $XDG_STATE_HOME/nix/defexpr si use-xdg-base-directories está establecido en true.

Se carga de la siguiente manera:

  • Si la expresión predeterminada es un archivo, se carga como una expresión Nix.
  • Si la expresión predeterminada es un directorio que contiene un archivo default.nix, ese archivo default.nix se carga como una expresión Nix.
  • Si la expresión predeterminada es un directorio sin un archivo default.nix, se espera que sea un conjunto de atributos de Nix y se cargará como tal.

Name

nix-env - administer the user environment

Synopsis

nix-env [ -h | --help ] [ -q | --query ] [ -i | --install ] [ -u | --upgrade ] [ -e | --uninstall ] [ -p | --profile PROFILE ] [ -f | --file FILE ] [ --arg ARG ] [ --argstr ARG ] [ --attr ATTR ] [ --dry-run ] [ --json ] [ --profile-name NAME ] [ --rollback ] [ --set-flag FLAG VALUE ] [ -v | --verbose ] [ --option OPTION ] [ --fallback-shell ] [ --debugger ] [ ATTR... ]

Description

nix-env is the command-line interface to the Nix package manager for managing users’ environments. It allows users to install, upgrade, and remove packages from their user environment.

A user environment is essentially a collection of symbolic links in the Nix store that point to installed packages. nix-env manages these links through profiles.

Default Nix expression

When nix-env needs to evaluate a Nix expression to determine the packages to install or upgrade, it first looks for a default Nix expression in the directory ~/.nix-defexpr.

  • If the directory ~/.nix-defexpr/default.nix exists, it is used as the default Nix expression.
  • Otherwise, ~/.nix-defexpr is traversed. All files ending in .nix are loaded as Nix expressions and combined into an attribute set. The attributes are named after the files they came from. Subdirectories are traversed recursively, but their names are not added to the attribute paths. The file manifest.nix is always ignored.

Then, the resulting expression is interpreted like this:

  • If the expression is an attribute set, it is used as the default Nix expression.
  • If the expression is a function, an empty set is passed as argument and the return value is used as the default Nix expression.

For example, if the default expression contains two files, foo.nix and bar.nix, then the default Nix expression will be equivalent to

{
  foo = import ~/.nix-defexpr/foo.nix;
  bar = import ~/.nix-defexpr/bar.nix;
}

The file manifest.nix is always ignored.

The command nix-channel places a symlink to the user’s current channels profile in this directory. This makes all subscribed channels available as attributes in the default expression.

User channel link

A symlink that ensures that nix-env can find your channels:

  • ~/.nix-defexpr/channels
  • $XDG_STATE_HOME/defexpr/channels if use-xdg-base-directories is set to true.

This symlink points to:

  • $XDG_STATE_HOME/profiles/channels for regular users
  • $NIX_STATE_DIR/profiles/per-user/root/channels for root

In a multi-user installation, you may also have ~/.nix-defexpr/channels_root, which links to the channels of the root user.nix-env: ../nix-env.md

Profiles

A directory that contains links to profiles managed by nix-env and nix profile:

  • $XDG_STATE_HOME/nix/profiles for regular users
  • $NIX_STATE_DIR/profiles/per-user/root if the user is root

A profile is a directory of symlinks to files in the Nix store.

Filesystem layout

Profiles are versioned as follows. When using a profile named path, path is a symlink to path-N-link, where N is the version of the profile. In turn, path-N-link is a symlink to a path in the Nix store. For example:

lrwxrwxrwx 1 alice users 51 Oct 28 16:18 /home/alice/.local/state/nix/profiles/profile-5-link -> /nix/store/q69xad13ghpf7ir87h0b2gd28lafjj1j-profile
lrwxrwxrwx 1 alice users 51 Oct 29 13:20 /home/alice/.local/state/nix/profiles/profile-6-link -> /nix/store/6bvhpysd7vwz7k3b0pndn7ifi5xr32dg-profile
lrwxrwxrwx 1 alice users 51 Nov 25 14:35 /home/alice/.local/state/nix/profiles/profile-7-link -> /nix/store/mp0x6xnsg0b8qhswy6riqvimai4gm677-profile

User profile link

A symbolic link to the user’s current profile:

  • ~/.nix-profile
  • $XDG_STATE_HOME/nix/profile if use-xdg-base-directories is set to true.

By default, this symlink points to:

  • $XDG_STATE_HOME/nix/profiles/profile for regular users
  • $NIX_STATE_DIR/profiles/per-user/root/profile for root

The PATH environment variable should include /bin subdirectory of the profile link (e.g. ~/.nix-profile/bin) for the user environment to be visible to the user. The installer sets this up by default, unless you enable use-xdg-base-directories.
