Nombre

nix-env --list-generations - listar generaciones de perfil

Sinopsis

nix-env --list-generations

Descripción

Esta operación imprime una lista de todas las generaciones existentes actualmente para el perfil activo. Estas pueden ser cambiadas usando la operación --switch-generation. También imprime la fecha de creación de la generación e indica la generación actual.

Opciones

Las siguientes opciones están permitidas para todas las operaciones de nix-env, pero pueden no tener un efecto siempre.

•
--file / -f ruta
Especifica la expresión Nix (designada abajo como la expresión Nix activa) utilizada por las operaciones --install, --upgrade y --query --available para obtener derivaciones. El valor predeterminado es ~/.nix-defexpr.
Si el argumento comienza con http:// o https://, se interpreta como la URL de un archivo tar que se descargará y descomprimirá en una ubicación temporal. El archivo tar debe incluir un único directorio de nivel superior que contenga al menos un archivo llamado default.nix.
•
--profile / -p ruta
Especifica el perfil que será utilizado por aquellas operaciones que operan sobre un perfil (designado abajo como el perfil activo). Un perfil es una secuencia de entornos de usuario llamados generaciones, una de las cuales es la generación actual.
•
--dry-run
Para las operaciones --install, --upgrade, --uninstall, --switch-generation, --delete-generations y --rollback, este indicador hará que nix-env imprima lo que se haría si este indicador no se hubiera especificado, sin hacerlo realmente.
--dry-run también imprime qué rutas serán sustituidas (es decir, descargadas) y qué rutas se construirán desde el origen (porque no hay sustituto disponible).
•
--system-filter sistema
Por defecto, las operaciones como --query --available muestran derivaciones que coinciden con cualquier plataforma. Esta opción te permite usar derivaciones para la plataforma sistema especificada.

Opciones Comunes

La mayoría de los comandos de Nix aceptan las siguientes opciones de línea de comandos:

•
--help
Imprime un resumen de la sintaxis del comando y sale.
•
--version
Imprime el número de versión de Nix en la salida estándar y sale.
•
--verbose / -v
Aumenta el nivel de verbosidad de los mensajes de diagnóstico impresos en la salida de error estándar. Para cada operación de Nix, la información impresa en la salida estándar está bien definida; cualquier información de diagnóstico se imprime en la salida de error estándar, nunca en la salida estándar.
Esta opción puede especificarse repetidamente. Actualmente, existen los siguientes niveles de verbosidad:
•
0 «Solo errores»
Solo imprime mensajes explicando por qué falló la invocación de Nix.
•
1 «Informativo»
Imprime mensajes *útiles* sobre lo que está haciendo Nix. Este es el valor predeterminado.
•
2 «Locuaz»
Imprime más mensajes informativos.
•
3 «Habla mucho»
Imprime aún más mensajes informativos.
•
4 «Depuración»
Imprime información de depuración.
•
5 «Vomitar»
Imprime enormes cantidades de información de depuración.
•
--quiet
Disminuye el nivel de verbosidad de los mensajes de diagnóstico impresos en la salida de error estándar. Esta es la opción inversa a -v / --verbose.
Esta opción puede especificarse repetidamente. Vea la lista anterior de niveles de verbosidad.
•
--log-format formato
Esta opción puede usarse para cambiar el formato de salida del registro, con formato siendo uno de:
•
raw
Este es el formato crudo, tal como lo emite nix-build.
•
internal-json
Emite los registros en un formato estructurado.
Advertencia
Aunque el esquema en sí es relativamente estable, el formato de los mensajes de error (específicamente del campo msg) puede cambiar entre versiones.
•
bar
Solo muestra una barra de progreso durante las compilaciones.
•
bar-with-logs
Muestra los registros crudos, con la barra de progreso en la parte inferior.
•
--no-build-output / -Q
Por defecto, la salida escrita por los constructores a la salida estándar y al error estándar se refleja en el error estándar del comando Nix. Esta opción suprime este comportamiento. Tenga en cuenta que la salida estándar y el error del constructor siempre se escriben en un archivo de registro en prefix/nix/var/log/nix.
•
--max-jobs / -j número
Establece el número máximo de trabajos de compilación que Nix realizará en paralelo al número especificado. Especifique auto para usar el número de CPUs del sistema. El valor predeterminado es el especificado en la configuración max-jobs, que a su vez tiene un valor predeterminado de 1. Un valor más alto es útil en sistemas SMP o para explotar la latencia de E/S.
Establecerlo en 0 deshabilita la compilación en la máquina local, lo cual es útil cuando desea que las compilaciones ocurran solo en constructores remotos.

Una lista separada por dos puntos de entradas del path de búsqueda utilizadas para resolver paths de búsqueda.
Esta variable de entorno anula el valor del ajuste de configuración de nix-path .
Puede extenderse usando la opción -I .
Ejemplo
$ export NIX_PATH=`/home/eelco/Dev:nixos-config=/etc/nixos
Si NIX_PATH se establece en una cadena vacía, la resolución de los paths de búsqueda siempre fallará.
Ejemplo
$ NIX_PATH= nix-instantiate --eval '<nixpkgs>'
error: file 'nixpkgs' was not found in the Nix search path (add it using $NIX_PATH or -I)
•
NIX_IGNORE_SYMLINK_STORE
Normalmente, el directorio del Nix store (típicamente /nix/store) no tiene permitido contener ningún componente de enlace simbólico. Esto es para prevenir construcciones "impuras". Los constructores a veces "canonizan" paths resolviendo todos los componentes de enlace simbólico. Por lo tanto, las construcciones en diferentes máquinas (con /nix/store resolviendo a ubicaciones diferentes) podrían producir resultados diferentes. Esto generalmente no es un problema, excepto cuando las construcciones se despliegan en máquinas donde /nix/store resuelve de manera diferente. Si estás seguro de que no vas a hacer eso, puedes establecer NIX_IGNORE_SYMLINK_STORE a 1.
Ten en cuenta que si estás creando enlaces simbólicos al Nix store para poder ponerlo en un sistema de archivos diferente al del sistema de archivos raíz, en Linux es mejor usar puntos de montaje bind, por ejemplo:
$ mkdir /nix
$ mount -o bind /mnt/otherdisk/nix /nix
Consulta la página del manual mount 8 para más detalles.

NIX_STORE_DIR
Anula la ubicación del Nix store (por defecto prefix/store).
•
NIX_DATA_DIR
Anula la ubicación del directorio de datos estáticos de Nix (por defecto prefix/share).
•
NIX_LOG_DIR
Anula la ubicación del directorio de logs de Nix (por defecto prefix/var/log/nix).
•
NIX_STATE_DIR
Anula la ubicación del directorio de estado de Nix (por defecto prefix/var/nix).
•
NIX_CONF_DIR
Anula la ubicación del directorio de configuración del sistema Nix (por defecto prefix/etc/nix).
•
NIX_CONFIG
Aplica configuraciones de Nix desde el entorno. El contenido se trata como si se hubiera leído de un archivo de configuración de Nix. Los ajustes están separados por el carácter de nueva línea.
•
NIX_USER_CONF_FILES
Anula la ubicación de los archivos de configuración de usuario de Nix desde donde cargar.
Los valores por defecto son las ubicaciones según la Especificación de Directorios Base XDG . Consulte la subsección Directorios Base XDG para más detalles.
La variable se trata como una lista separada por el token :.
•
TMPDIR
Utiliza el directorio especificado para almacenar archivos temporales. En particular, esto incluye directorios temporales de construcción; estos pueden ocupar cantidades sustanciales de espacio en disco. El valor por defecto es /tmp.
•
NIX_REMOTE
Esta variable debe establecerse en daemon si deseas utilizar el demonio Nix para ejecutar operaciones de Nix. Esto es necesario en instalaciones de Nix multiusuario . Si el socket Unix del demonio Nix se encuentra en alguna ruta no estándar, esta variable debe establecerse en unix://path/to/socket. De lo contrario, debe dejarse sin establecer.
•
NIX_SHOW_STATS
Si se establece en 1, Nix imprimirá algunas estadísticas de evaluación, como el número de valores asignados.
•
NIX_COUNT_CALLS
Si se establece en 1, Nix imprimirá cuántas veces se llamaron las funciones durante la evaluación de expresiones Nix. Esto es útil para perfilar tus expresiones Nix.
•
GC_INITIAL_HEAP_SIZE
Si Nix se ha configurado para utilizar el recolector de basura de Boehm, esta variable establece el tamaño inicial del heap en bytes. Por defecto es 384 MiB. Establecerlo en un valor bajo reduce el consumo de memoria, pero aumentará el tiempo de ejecución debido a la sobrecarga de la recolección de basura.

Directorios Base XDG

Nix sigue la Especificación de Directorios Base XDG .

Por compatibilidad con versiones anteriores, los comandos de Nix seguirán el estándar solo cuando use-xdg-base-directories esté habilitado. Los comandos Nix nuevos (experimentales) se ajustan al estándar por defecto.

Las siguientes variables de entorno se utilizan para determinar las ubicaciones de varios archivos de estado y configuración:

  • [XDG_CONFIG_HOME]{#env-XDGCONFIGHOME} (por defecto ~/.config)
  • [XDG_STATE_HOME]{#env-XDGSTATEHOME} (por defecto ~/.local/state)
  • [XDG_CACHE_HOME]{#env-XDGCACHEHOME} (por defecto ~/.cache)
