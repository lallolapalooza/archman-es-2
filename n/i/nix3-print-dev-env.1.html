Paquete: nix

Licencias: LGPL-2.1-only

nix3-print-dev-env(1) Manual de Comandos Generales nix3-print-dev-env(1)

Advertencia
Este programa es experimental y su interfaz está sujeta a cambios.

Nombre

nix print-dev-env - imprime código de shell que puede ser cargado por bash para reproducir el entorno de compilación de una derivación

Sinopsis

nix print-dev-env [opción…] instalable

Ejemplos

•
Aplica el entorno de compilación de GNU hello al shell actual:
# . <(nix print-dev-env nixpkgs#hello)
•
Obtén el entorno de compilación en formato JSON:
# nix print-dev-env nixpkgs#hello --json
La salida se verá así:
{
"bashFunctions": {
  "buildPhase": " \n    runHook preBuild;\n...",
  ...
},
"variables": {
  "src": {
    "type": "exported",
    "value": "/nix/store/3x7dwzq014bblazs7kq20p9hyzz0qh8g-hello-2.10.tar.gz"
  },
  "postUnpackHooks": {
    "type": "array",
    "value": ["_updateSourceDateEpochFromSourceRoot"]
  },
  ...
}
}

Descripción

Este comando imprime un script de shell que puede ser cargado por bash y que establece las variables y funciones de shell definidas por el proceso de compilación de instalable. Esto permite obtener un entorno de compilación similar en tu shell actual en lugar de en un subshell (como con nix develop).

Con --json, la salida es una serialización JSON de las variables y funciones definidas por el proceso de compilación.

Opciones

•
--json
Produce salida en formato JSON, adecuada para ser consumida por otro programa.
•
--profile ruta
El perfil sobre el cual operar.
•
--redirect instalable dir_salidas
Redirige una ruta de la tienda a una ubicación mutable.

Opciones comunes de evaluación

•
--arg nombre expresión
Pasa el valor expresión como el argumento nombre a las funciones de Nix.
•
--arg-from-file nombre ruta
Pasa el contenido del archivo ruta como el argumento nombre a las funciones de Nix.
•
--arg-from-stdin nombre
Pasa el contenido de stdin como el argumento nombre a las funciones de Nix.
•
--argstr nombre cadena
Pasa la cadena cadena como el argumento nombre a las funciones de Nix.
•
--debugger
Inicia un entorno interactivo si la evaluación falla.
•
--eval-store url-tienda
La URL de la tienda Nix a usar para la evaluación, es decir, para almacenar derivaciones (.drv) y las entradas referenciadas por ellas.
•
--impure
Permite el acceso a rutas mutables y repositorios.
•
--include / -I ruta
Añade ruta a las entradas de la ruta de búsqueda utilizadas para resolver rutas de búsqueda
Esta opción se puede dar varias veces.
Las rutas añadidas a través de -I tienen prioridad sobre la configuración nix-path y la variable de entorno NIX_PATH.
•
--override-flake ref-original ref-resuelta
Sobrescribe los registros de flakes, redirigiendo ref-original a ref-resuelta.

Opciones comunes relacionadas con flakes

•
--commit-lock-file
Confirma los cambios en el archivo de bloqueo del flake.
•
--inputs-from url-flake
Usa las entradas del flake especificado como entradas de registro.
•
--no-registries
No permite búsquedas en los registros de flakes.
OBSOLETO
Usa --no-use-registries en su lugar.
•
--no-update-lock-file
No permite ninguna actualización del archivo de bloqueo del flake.
•
--no-write-lock-file
No escribe el archivo de bloqueo recién generado del flake.
•
--output-lock-file ruta-archivo-lock-flake
Escribe el archivo de bloqueo especificado en lugar de flake.lock dentro del flake de nivel superior.
•
--override-input ruta-entrada url-flake
Sobrescribe una entrada de flake específica (por ejemplo, dwarffs/nixpkgs). Esto implica --no-write-lock-file.
•
--recreate-lock-file
Recrea el archivo de bloqueo del flake desde cero.
OBSOLETO
Usa nix flake update en su lugar.
•
--reference-lock-file archivo-lock-flake

Opciones relacionadas con el bloqueo de flakess

•
--commit-lockfile
Commit the project's lock file to Git.
•
--flake-lock flake-lock
Read the given lock file instead of flake.lock within the top-level flake.
•
--update-input input-path
Actualizar una entrada de flake específica (ignorando su entrada anterior en el archivo de bloqueo).
OBSOLETO
Utilice nix flake update en su lugar.

Opciones relacionadas con el registro

•
--debug
Establecer el nivel de verbosidad del registro en 'debug'.
•
--log-format format
Establecer el formato de la salida del registro; uno de raw, internal-json, bar o bar-with-logs.
•
--print-build-logs / -L
Imprimir registros de compilación completos en el error estándar.
•
--quiet
Disminuir el nivel de verbosidad del registro.
•
--verbose / -v
Aumentar el nivel de verbosidad del registro.

Opciones globales varias

•
--help
Mostrar información de uso.
•
--offline
Desactivar sustitutos y considerar todos los archivos descargados previamente como actualizados.
•
--option name value
Establecer la configuración de Nix name en value (anulando nix.conf).
•
--refresh
Considerar todos los archivos descargados previamente como desactualizados.
•
--repair
Durante la evaluación, reescribir archivos faltantes o corruptos en la tienda Nix. Durante la compilación, recompilar rutas de tienda faltantes o corruptas.
•
--version
Mostrar información de la versión.

Opciones que cambian la interpretación de instalables

•
--expr expr
Interpretar instalables como rutas de atributos relativas a la expresión Nix expr.
•
--file / -f file
Interpretar instalables como rutas de atributos relativas a la expresión Nix almacenada en file. Si file es el carácter -, entonces se leerá una expresión Nix de la entrada estándar. Implica --impure.

Nota

Ver man nix.conf para anular la configuración con indicadores de línea de comandos.
