NIKTO(1) Escáner de vulnerabilidades NIKTO(1)

NOMBRE

nikto - Escanear servidor web en busca de vulnerabilidades conocidas

SINOPSIS

nikto [opciones...]

DESCRIPCIÓN

Examinar un servidor web para encontrar posibles problemas y vulnerabilidades de seguridad, incluyendo:

•Configuraciones erróneas del servidor y del software
•Archivos y programas predeterminados
•Archivos y programas inseguros
•Servidores y programas obsoletos

Nikto se basa en LibWhisker (de RFP) y puede ejecutarse en cualquier plataforma que tenga un entorno Perl. Admite SSL, proxies, autenticación de host, codificación de ataques y más. Se puede actualizar automáticamente desde la línea de comandos y admite la presentación opcional de datos de versiones actualizadas a los mantenedores.

OPCIONES

A continuación se presentan todas las opciones de la línea de comandos de Nikto y sus explicaciones. Una versión breve de este texto está disponible ejecutando Nikto con la opción -H (-Help).

-Cgidirs

Escanear estos directorios CGI. Se pueden usar las palabras especiales "none" o "all" para escanear todos los directorios CGI o ninguno, (respectivamente). Se puede especificar un valor literal para un directorio CGI, como "/cgi-test/" (debe incluir la barra final). Si esta opción no se especifica, se probarán todos los directorios CGI listados en nikto.conf.

-config

Especificar un archivo de configuración alternativo para usar en lugar de nikto.conf ubicado en el directorio de instalación.

-dbcheck

Comprobar bases de datos de escaneo en busca de errores de sintaxis.

-Display

Controlar la salida que muestra Nikto. Consulte el Capítulo 5 para obtener información detallada sobre estas opciones. Utilice el número de referencia o la letra para especificar el tipo, se pueden usar varios:

1 - Mostrar redirecciones

2 - Mostrar cookies recibidas

3 - Mostrar todas las respuestas 200/OK

4 - Mostrar URL que requieren autenticación

D - Salida de depuración

V - Salida detallada

-evasion

Especificar la técnica de codificación de LibWhisker a usar (consulte la documentación de LibWhisker para obtener información detallada sobre estas). Utilice el número de referencia para especificar el tipo, se pueden usar varios:

1 - Codificación URI aleatoria (no UTF8)

2 - Autoreferencia de directorio (/./)

3 - Finalización prematura de URL

4 - Añadir cadena aleatoria larga al principio

5 - Parámetro falso

6 - TAB como separador de solicitud

7 - Cambiar la capitalización de la URL

8 - Usar el separador de directorios de Windows (\)

A - Usar un retorno de carro (0x0d) como separador de solicitud

B - Usar el valor binario 0x0b como separador de solicitud

-findonly

Solo descubrir los puertos HTTP(S), no realizar un escaneo de seguridad. Esto intentará conectarse con HTTP o HTTPS e informará la cabecera Server.

-Format

Guardar el archivo de salida especificado con la opción -o (-output) en este formato. Si no se especifica, el valor predeterminado se tomará de la extensión del archivo especificada en la opción -output. Los formatos válidos son:

csv - una lista separada por comas

htm - un informe HTML

txt - un informe de texto

xml - un informe XML

-host

Host(s) a los que dirigirse. Puede ser una dirección IP, nombre de host o archivo de texto de hosts. Se puede usar un guion solo (-) para la salida estándar. También puede analizar la salida estilo nmap -oG

-Help

Mostrar información de ayuda extendida.

-id

ID y contraseña a usar para la autenticación básica de host. El formato es "id:contraseña".

-list-plugins

Listará todos los plugins que Nikto puede ejecutar contra los objetivos y luego saldrá sin realizar un escaneo. Estos se pueden ajustar para una sesión usando la opción -plugins.

El formato de salida es:

Plugin nombre

 nombre completo - descripción

 Escrito por autor, Copyright (C) copyright

-mutate

Especificar la técnica de mutación. Una mutación hará que Nikto combine pruebas o intente adivinar valores. Estas técnicas pueden lanzar una gran cantidad de pruebas contra el objetivo. Utilice el número de referencia para especificar el tipo, se pueden usar varios:

1 - Probar todos los archivos con todos los directorios raíz

2 - Adivinar nombres de archivos de contraseña

3 - Enumerar nombres de usuario a través de Apache (solicitudes de tipo /~usuario)

4 - Enumerar nombres de usuario a través de cgiwrap (solicitudes de tipo /cgi-bin/cgiwrap/~usuario)

5 - Intentar fuerza bruta de nombres de subdominios, asumir que el nombre del host es el dominio padre

6 - Intentar adivinar nombres de directorios del archivo de diccionario proporcionado

-mutate-options

Proporcionar información adicional para mutaciones, por ejemplo, un archivo de diccionario.

-nointeractive

Deshabilitar funciones interactivas.

-nolookup

No realizar búsquedas de nombres en direcciones IP.

-nossl

No usar SSL para conectarse al servidor.

-no404

Deshabilitar la verificación de 404 (archivo no encontrado). Esto reducirá el número total de solicitudes realizadas al servidor web y puede ser preferible al verificar un servidor en un enlace lento o un dispositivo integrado. Esto generalmente conducirá a un mayor número de falsos positivos descubiertos.

-output

Escribir la salida en el archivo especificado. El formato utilizado se tomará de la extensión del archivo. Esto se puede anular usando la opción -Format (por ejemplo, para escribir archivos de texto con una extensión diferente. Los archivos existentes tendrán información nueva añadida).

-plugins

Seleccionar qué plugins se ejecutarán en los objetivos especificados. Se debe proporcionar una lista separada por comas que enumere los nombres de los plugins. Los nombres se pueden encontrar usando -list-plugins.

Hay dos entradas especiales: ALL, que especifica que se ejecutarán todos los plugins y NONE, que especifica que no se ejecutará ningún plugin. El valor predeterminado es ALL.

-port

Puerto(s) TCP a los que dirigirse. Para probar más de un puerto en el mismo host, especifique la lista de puertos en la opción -p (-port). Los puertos se pueden especificar como un rango (es decir, 80-90) o como una lista separada por comas (es decir, 80,88,90). Si no se especifica, se usa el puerto 80.

-Pause

Segundos (entero o punto flotante) para retrasar entre cada prueba.

-root

Añadir el valor especificado al principio de cada solicitud. Esto es útil para probar aplicaciones o servidores web que tienen todos sus archivos bajo un cierto directorio.

-ssl

Probar solo SSL en los puertos especificados. Usar esta opción acelerará drásticamente las solicitudes a los puertos HTTPS, ya que de lo contrario, la solicitud HTTP tendrá que agotar el tiempo de espera primero.

-Single

Realizar una única solicitud a un servidor de destino. Nikto solicitará todas las opciones que se puedan especificar y luego informará la salida detallada. Consulte el Capítulo 5 para obtener información detallada.

-timeout

Segundos a esperar antes de agotar el tiempo de espera de una solicitud. El tiempo de espera predeterminado es de 10 segundos.

-Tuning

Las opciones de ajuste controlarán la prueba que Nikto utilizará contra un objetivo. Por defecto, si se especifican opciones, solo se realizarán esas pruebas. Si se utiliza la opción "x", se invertirá la lógica y solo se excluirán esas pruebas. Utilice el número de referencia o la letra para especificar el tipo, se pueden usar varios:

0 - Carga de archivos

1 - Archivo interesante / Visto en registros

2 - Configuración errónea / Archivo predeterminado

3 - Divulgación de información

4 - Inyección (XSS/Script/HTML)

5 - Recuperación remota de archivos - Dentro de la raíz web

6 - Denegación de servicio

7 - Recuperación remota de archivos - En todo el servidor

8 - Ejecución de comandos / Shell remoto

9 - Inyección SQL

a - Omisión de autenticación

b - Identificación de software

c - Inclusión remota de código

x - Opciones de ajuste inversas (es decir, incluir todas excepto las especificadas)

La cadena dada se analizará de izquierda a derecha, cualquier carácter x se aplicará a todos los caracteres a la derecha del carácter.

class="Pp">-useproxy

Utiliza el proxy HTTP definido en el archivo de configuración, o proporcionado como argumento en el formato http://servidor:puerto.

-update

Actualiza los plugins y las bases de datos directamente desde cirt.net.

-Version

Muestra las versiones del software Nikto, de los plugins y de la base de datos.

-vhost

Especifica el encabezado Host que se enviará al objetivo.

ARCHIVOS

nikto.conf

El archivo de configuración de Nikto. Establece las opciones globales de Nikto. Pueden existir varios archivos nikto.conf y se analizan en el orden siguiente. A medida que se carga cada archivo de configuración, anula cualquier configuración previamente establecida:
•A nivel de sistema (ej. /etc/nikto.conf)
•Directorio de inicio (ej. $HOME/nikto.conf)
•Directorio actual (ej. ./nikto.conf)

${NIKTO_DIR}/plugins/db*

Los archivos db son las bases de datos que nikto utiliza para comprobar vulnerabilidades y problemas en el servidor web.

${NIKTO_DIR}/plugins/*.plugin

Todos los plugins de nikto se encuentran aquí. Nikto es simplemente un script envoltorio para gestionar la CLI y pasarla a los plugins.

${NIKTO_DIR}/templates

Contiene las plantillas para los formatos de salida de nikto.

ERRORES

Las características actuales no son compatibles:

•Proxies SOCKS
