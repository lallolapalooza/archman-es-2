nix-env-install(1)

Paquete: nix

Licencias: LGPL-2.1-only

nix-env --install(1) Manual de Comandos Generales nix-env --install(1)

Nombre

nix-env --install - agregar paquetes al entorno del usuario

Sinopsis

nix-env {--install | -i} args... [{--prebuilt-only | -b}] [{--attr | -A}] [--from-expression] [-E] [--from-profile ruta] [--preserve-installed | -P] [--remove-all | -r]

Descripción

La operación --install crea un nuevo entorno de usuario. Se basa en la generación actual del perfil activo, a la cual se agrega un conjunto de rutas del almacén descritas por args.

Los argumentos args se mapean a rutas del almacén de varias maneras posibles:

•
Por defecto, args es un conjunto de derivaciones que denotan derivaciones en la expresión Nix por defecto. Estas son realizadas, y las rutas de salida resultantes se instalan. Las derivaciones instaladas actualmente con un nombre igual al nombre de una derivación que se está agregando se eliminan a menos que se especifique la opción --preserve-installed.
Si hay múltiples derivaciones que coinciden con un nombre en args y que tienen el mismo nombre (por ejemplo, gcc-3.3.6 y gcc-4.1.1), se utiliza la derivación con la mayor prioridad. Una derivación puede definir una prioridad declarando el atributo meta.priority. Este atributo debe ser un número, donde un valor más alto denota una prioridad más baja. La prioridad por defecto es 5.
Si hay múltiples derivaciones coincidentes con la misma prioridad, se instalará la derivación con la versión más alta.
Puede forzar la instalación de múltiples derivaciones con el mismo nombre siendo específico con las versiones. Por ejemplo, nix-env --install gcc-3.3.6 gcc-4.1.1 instalará ambas versiones de GCC (¡y probablemente cause un conflicto en el entorno del usuario!).
•
Si se especifica --attr / -A, los argumentos son rutas de atributos que seleccionan atributos de la expresión Nix por defecto. Esto es más rápido que usar nombres de derivación y no ambiguo. Muestre las rutas de atributos de los paquetes disponibles con nix-env --query:
nix-env --query --available --attr-path
  • Si se proporciona --from-profile ruta, args es un conjunto de nombres que denotan rutas de almacén instaladas en el perfil ruta. Esta es una forma fácil de copiar elementos del entorno del usuario de un perfil a otro.
  • Si se proporciona --from-expression, args son funciones del lenguaje Nix que se llaman con la expresión Nix por defecto como su único argumento. Las derivaciones devueltas por esas llamadas a funciones se instalan. Esto permite especificar derivaciones de forma no ambigua, lo cual es necesario si hay múltiples derivaciones con el mismo nombre.
  • Si args son derivaciones de almacén, entonces estas son realizadas, y las rutas de salida resultantes se instalan.
  • Si args son rutas de almacén que no son derivaciones de almacén, entonces estas son realizadas e instaladas.
  • Por defecto, todas las salidas se instalan para cada derivación. Esto puede ser anulado agregando un atributo meta.outputsToInstall en la derivación que liste un subconjunto de los nombres de salida.
Ejemplo:
El archivo example.nix define una derivación con dos salidas foo y bar, cada una conteniendo un archivo.
# example.nix
let
pkgs = import <nixpkgs> {};
command = ''
  ${pkgs.coreutils}/bin/mkdir -p $foo $bar
  echo foo > $foo/foo-file
  echo bar > $bar/bar-file
'';
in
derivation {
name = "example";
builder = "${pkgs.bash}/bin/bash";
args = [ "-c" command ];
outputs = [ "foo" "bar" ];
system = builtins.currentSystem;
}
Instalar desde esta expresión Nix hará que los archivos de ambas salidas aparezcan en el perfil actual.
$ nix-env --install --file example.nix
instalando 'example'
$ ls ~/.nix-profile
foo-file
bar-file
manifest.nix
Agregar meta.outputsToInstall a esa derivación hará que nix-env solo instale archivos de las salidas especificadas.
# example-outputs.nix
import ./example.nix // { meta.outputsToInstall = [ "bar" ]; }
$ nix-env --install --file example-outputs.nix
instalando 'example'
$ ls ~/.nix-profile
bar-file
manifest.nix

Opciones

•
--prebuilt-only / -b
Usar solo derivaciones para las cuales se registre un sustituto, es decir, haya un binario precompilado disponible que se pueda descargar en lugar de construir la derivación. Por lo tanto, no se compilarán paquetes desde el código fuente.
•
--preserve-installed / -P
No eliminar derivaciones con un nombre que coincida con una de las derivaciones que se están instalando. Por lo general, intentar tener dos versiones del mismo paquete instaladas en la misma generación de un perfil provocará un error en la construcción de la generación, debido a colisiones de nombres de archivo entre las dos versiones. Sin embargo, este no es el caso para todos los paquetes.
•
--remove-all / -r
Eliminar primero todos los paquetes instalados previamente. Esto es equivalente a ejecutar nix-env --uninstall '.*' primero, excepto que todo sucede en una sola transacción.

Opciones

Las siguientes opciones están permitidas para todas las operaciones de nix-env, pero pueden no tener siempre un efecto.

•
--file / -f ruta
Especifica la expresión Nix (designada a continuación como la expresión Nix activa) utilizada por las operaciones --install, --upgrade y --query --available para obtener derivaciones. El valor por defecto es ~/.nix-defexpr.
Si el argumento comienza con http:// o https://, se interpreta como la URL de un archivo tarball que se descargará y desempaquetará en una ubicación temporal. El archivo tarball debe incluir un único directorio de nivel superior que contenga al menos un archivo llamado default.nix.
•
--profile / -p ruta
Especifica el prof

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

OPTIONS

•
--dry-run
Para las operaciones --install, --upgrade, --uninstall, --switch-generation, --delete-generations y --rollback, esta opción hará que nix-env imprima lo que *haría* si no se hubiera especificado, sin hacerlo realmente.
--dry-run también imprime qué rutas se sustituirán (es decir, se descargarán) y qué rutas se construirán a partir del código fuente (porque no hay sustituto disponible).
•
--system-filter sistema
Por defecto, operaciones como --query --available muestran derivaciones que coinciden con cualquier plataforma. Esta opción permite usar derivaciones para la plataforma especificada sistema.

Opciones Comunes

La mayoría de los comandos de Nix aceptan las siguientes opciones de línea de comandos:

•
--help
Imprime un resumen de la sintaxis del comando y sale.
•
--version
Imprime el número de versión de Nix en la salida estándar y sale.
•
--verbose / -v
Aumenta el nivel de verbosidad de los mensajes de diagnóstico impresos en la salida estándar de error. Para cada operación de Nix, la información impresa en la salida estándar está bien definida; cualquier información de diagnóstico se imprime en la salida estándar de error, nunca en la salida estándar.
Esta opción se puede especificar repetidamente. Actualmente, existen los siguientes niveles de verbosidad:
•
0 "Solo errores"
Solo imprime mensajes que expliquen por qué falló la invocación de Nix.
•
1 "Informativo"
Imprime mensajes *útiles* sobre lo que está haciendo Nix. Este es el valor por defecto.
•
2 "Hablador"
Imprime más mensajes informativos.
•
3 "Charlatán"
Imprime aún más mensajes informativos.
•
4 "Depuración"
Imprime información de depuración.
•
5 "Vómito"
Imprime enormes cantidades de información de depuración.
•
--quiet
Disminuye el nivel de verbosidad de los mensajes de diagnóstico impresos en la salida estándar de error. Esta es la opción inversa a -v / --verbose.
Esta opción se puede especificar repetidamente. Ver la lista anterior de niveles de verbosidad.
•
--log-format formato
Esta opción se puede usar para cambiar la salida del formato del registro, siendo formato uno de:
•
raw
Este es el formato crudo, tal como lo produce nix-build.
•
internal-json
Salida de los registros en un formato estructurado.
Advertencia
Aunque el esquema en sí es relativamente estable, el formato de los mensajes de error (específicamente del campo msg) puede cambiar entre versiones.
•
bar
Solo muestra una barra de progreso durante las compilaciones.
•
bar-with-logs
Muestra los registros crudos, con la barra de progreso en la parte inferior.
•
--no-build-output / -Q
Por defecto, la salida escrita por los constructores en la salida estándar y la salida estándar de error se repite en la salida estándar de error del comando Nix. Esta opción suprime este comportamiento. Tenga en cuenta que la salida estándar y el error del constructor siempre se escriben en un archivo de registro en prefix/nix/var/log/nix.
•
--max-jobs / -j número
Establece el número máximo de trabajos de construcción que Nix realizará en paralelo al número especificado. Especifique auto para usar el número de CPUs del sistema. El valor predeterminado es el especificado por la configuración max-jobs, que a su vez tiene como valor predeterminado 1. Un valor más alto es útil en sistemas SMP o para explotar la latencia de E/S.
Establecerlo en 0 prohíbe la construcción en la máquina local, lo cual es útil cuando se desea que las construcciones ocurran solo en constructores remotos.
•
--cores
Establece el valor de la variable de entorno NIX_BUILD_CORES en la invocación de los constructores. Los constructores pueden usar esta variable a su discreción para controlar la cantidad máxima de paralelismo. Por ejemplo, en Nixpkgs, si el atributo de derivación enableParallelBuilding está establecido en true, el constructor pasa el flag -jN a GNU Make. Tiene como valor predeterminado el valor de la configuración cores, si está establecida, o 1 en caso contrario. El valor 0 significa que el constructor debe usar todos los núcleos de CPU disponibles en el sistema.
•
--max-silent-time
Establece el número máximo de segundos que un constructor puede pasar sin producir datos en la salida estándar o la salida estándar de error. El valor predeterminado es el especificado por la configuración max-silent-time. 0 significa sin tiempo de espera.
•
--timeout
Establece el número máximo de segundos que un constructor puede ejecutarse. El valor predeterminado es el especificado por la configuración timeout. 0 significa sin tiempo de espera.
•
--keep-going / -k
Continuar en caso de fallos de construcción, en la mayor medida posible. Es decir, si la construcción de una entrada de alguna derivación falla, Nix aún construirá las otras entradas, pero no la derivación en sí. Sin esta opción, Nix se detiene si falla alguna construcción (excepto las construcciones de sustitutos), posiblemente matando las construcciones en curso (en caso de construcciones paralelas o distribuidas).
•
--keep-failed / -K
Especifica que en caso de fallo de construcción, el directorio temporal (generalmente en /tmp) en el que tiene lugar la construcción no debe ser eliminado. La ruta del directorio de construcción se imprime como un mensaje informativo.
•
--fallback
Siempre que Nix intente construir una derivación para la cual se conocen sustitutos para cada ruta de salida, pero la realización de las rutas de salida a través de los sustitutos falla, recurrirá a la construcción de la derivación.
El escenario más común en el que esto es útil es cuando hemos registrado sustitutos para realizar la distribución binaria desde, por ejemplo, un repositorio de red. Si el repositorio está caído, la realización de la derivación fallará. Cuando se especifica esta opción, Nix construirá la derivación en su lugar. Por lo tanto, la instalación desde binarios recurre a la instalación desde el código fuente. Esta opción no es la predeterminada, ya que generalmente no es deseable que un fallo transitorio en la obtención de los sustitutos conduzca a una compilación completa desde el código fuente (con el consumo relacionado de recursos).
•
--readonly-mode
Cuando se utiliza esta opción, no se intenta abrir la base de datos de Nix. La mayoría de las operaciones de Nix necesitan acceso a la base de datos, por lo que esas operaciones fallarán.
•
--arg nombre valor
Esta opción es aceptada por
nix-env, nix-instantiate, nix-shell y nix-build. Al evaluar expresiones Nix, el evaluador de expresiones intentará automáticamente llamar a las funciones que encuentre. Puede llamar automáticamente a funciones para las que cada argumento tenga un valor predeterminado (p. ej., { argName ? defaultValue }: ...).
Con --arg, también puedes llamar a funciones que tengan argumentos sin valor predeterminado (o anular un valor predeterminado). Es decir, si el evaluador encuentra una función con un argumento llamado nombre, la llamará con el valor valor.
Por ejemplo, el default.nix de nivel superior en Nixpkgs es en realidad una función:
{ # El sistema (p. ej., `i686-linux') para el que se construirán los paquetes.
system ? builtins.currentSystem
...
}: ...
Así que si llamas a esta expresión Nix (por ejemplo, al hacer nix-env --install --attr pkgname), la función se llamará automáticamente usando el valor builtins.currentSystem para el argumento system. Puedes anular esto usando --arg, p. ej., nix-env --install --attr pkgname --arg system \"i686-freebsd\". (Ten en cuenta que como el argumento es un literal de cadena Nix, debes escapar las comillas.)
•
--argstr nombre valor
Esta opción es como --arg, solo que el valor no es una expresión Nix sino una cadena. Así que en lugar de --arg system \"i686-linux\" (las comillas exteriores son para mantener la consola contenta) puedes decir --argstr system i686-linux.
•
--attr / -A attrPath
Selecciona un atributo de la expresión Nix de nivel superior que se está evaluando. (Solo nix-env, nix-instantiate, nix-build y nix-shell.) La ruta de atributo attrPath es una secuencia de nombres de atributos separados por puntos. Por ejemplo, dada una expresión Nix de nivel superior e, la ruta de atributo xorg.xorgserver haría que se usara la expresión e.xorg.xorgserver. Ver nix-env --install para algunos ejemplos concretos.
Además de los nombres de atributos, también puedes especificar índices de matriz. Por ejemplo, la ruta de atributo foo.3.bar selecciona el atributo bar del cuarto elemento de la matriz en el atributo foo de la expresión de nivel superior.
•
--expr / -E
Interpreta los argumentos de la línea de comandos como una lista de expresiones Nix para analizar y evaluar, en lugar de como una lista de nombres de archivo de expresiones Nix. (Solo nix-instantiate, nix-build y nix-shell.)
Para nix-shell, esta opción se usa comúnmente para darte un shell en el que puedas construir los paquetes devueltos por la expresión. Si quieres obtener un shell que contenga los paquetes *construidos* listos para usar, dale tu expresión a la opción de conveniencia nix-shell --packages en su lugar.
•
-I / --include ruta
Añade una entrada a la lista de rutas de búsqueda utilizadas para resolver rutas de búsqueda. Esta opción se puede especificar varias veces.
Las rutas añadidas a través de -I tienen precedencia sobre la configuración de nix-path y la variable de entorno NIX_PATH.
•
--option nombre valor
Establece la opción de configuración Nix nombre a valor. Esto anula la configuración en el archivo de configuración Nix (ver nix.conf5).
•
--repair
Repara rutas de almacén corruptas o faltantes redescargándolas o reconstruyéndolas. Ten en cuenta que esto es lento porque requiere calcular un hash criptográfico del contenido de cada ruta en el cierre de la construcción. Ten también en cuenta la advertencia bajo nix-store --repair-path.

Nota

Ver man nix.conf para anular la configuración con indicadores de línea de comandos.

Variables de entorno

•
NIX_PROFILE
Ubicación del perfil Nix. Por defecto, es el destino del enlace simbólico ~/.nix-profile, si existe, o /nix/var/nix/profiles/default en caso contrario.

Variables de entorno comunes

La mayoría de los comandos Nix interpretan las siguientes variables de entorno:

•
IN_NIX_SHELL
Indicador que informa si el entorno actual fue configurado por nix-shell. Puede tener los valores pure o impure.
•
NIX_PATH
Una lista separada por dos puntos de entradas de rutas de búsqueda utilizadas para resolver rutas de búsqueda.
Esta variable de entorno anula el valor de la configuración nix-path.
Puede extenderse utilizando la opción -I.
Ejemplo
$ export NIX_PATH=`/home/eelco/Dev:nixos-config=/etc/nixos
Si NIX_PATH está configurado como una cadena vacía, la resolución de rutas de búsqueda fallará siempre.
Ejemplo
$ NIX_PATH= nix-instantiate --eval '<nixpkgs>'
error: file 'nixpkgs' was not found in the Nix search path (add it using $NIX_PATH or -I)
•
NIX_IGNORE_SYMLINK_STORE
Normalmente, el directorio de almacén Nix (típicamente /nix/store) no tiene permitido contener ningún componente de enlace simbólico. Esto es para prevenir construcciones "impuras". Los constructores a veces "canonicalizan" las rutas resolviendo todos los componentes de enlace simbólico. Por lo tanto, las construcciones en diferentes máquinas (con /nix/store resolviendo a ubicaciones diferentes) podrían producir resultados diferentes. Esto generalmente no es un problema, excepto cuando las construcciones se implementan en máquinas donde /nix/store se resuelve de manera diferente. Si estás seguro de que no vas a hacer eso, puedes establecer NIX_IGNORE_SYMLINK_STORE a 1.
Ten en cuenta que si estás enlazando simbólicamente el almacén Nix para poder ponerlo en un sistema de archivos diferente al del sistema de archivos raíz, en Linux es mejor usar puntos de montaje bind, por ejemplo:
$ mkdir /nix
$ mount -o bind /mnt/otherdisk/nix /nix
Consulta la página del manual de mount 8 para obtener detalles.
•
NIX_STORE_DIR
Anula la ubicación del almacén Nix (por defecto prefix/store).
•
NIX_DATA_DIR
Anula la ubicación del directorio de datos estáticos de Nix (por defecto prefix/share).
•
NIX_LOG_DIR
Anula la ubicación del directorio de registros de Nix (por defecto prefix/var/log/nix).
•
NIX_STATE_DIR
Anula la ubicación del directorio de estado de Nix (por defecto prefix/var/nix).
•
NIX_CONF_DIR
Anula la ubicación del directorio de configuración Nix del sistema (por defecto prefix/etc/nix).
•
NIX_CONFIG
Aplica configuraciones de Nix desde el entorno. El contenido se trata como si se hubiera leído de un archivo de configuración de Nix. Las configuraciones se separan por el carácter de nueva línea.

Variables de entorno

NIX_USER_CONF_FILES
Sobrescribe la ubicación de los archivos de configuración de usuario de Nix que se cargarán.
Los valores predeterminados son las ubicaciones según la Especificación de directorios base XDG. Consulte la subsección Directorios base XDG para obtener más detalles.
La variable se trata como una lista separada por el token :.
TMPDIR
Utiliza el directorio especificado para almacenar archivos temporales. En particular, esto incluye directorios de compilación temporales; estos pueden ocupar una cantidad considerable de espacio en disco. El valor predeterminado es /tmp.
NIX_REMOTE
Esta variable debe establecerse en daemon si desea utilizar el demonio de Nix para ejecutar operaciones de Nix. Esto es necesario en las instalaciones de Nix multiusuario. Si el socket Unix del demonio de Nix se encuentra en una ruta no estándar, esta variable debe establecerse en unix://ruta/al/socket. De lo contrario, debe dejarse sin establecer.
NIX_SHOW_STATS
Si se establece en 1, Nix imprimirá algunas estadísticas de evaluación, como el número de valores asignados.
NIX_COUNT_CALLS
Si se establece en 1, Nix imprimirá con qué frecuencia se llamaron las funciones durante la evaluación de la expresión de Nix. Esto es útil para perfilar sus expresiones de Nix.
GC_INITIAL_HEAP_SIZE
Si Nix se ha configurado para utilizar el recolector de basura de Boehm, esta variable establece el tamaño inicial del montón en bytes. El valor predeterminado es 384 MiB. Establecerlo en un valor bajo reduce el consumo de memoria, pero aumentará el tiempo de ejecución debido a la sobrecarga de la recolección de basura.

Directorios base XDG

Nix sigue la Especificación de directorios base XDG.

Por motivos de compatibilidad, los comandos de Nix seguirán el estándar solo cuando use-xdg-base-directories esté habilitado. Los nuevos comandos de Nix (experimentales) cumplen con el estándar por defecto.

Las siguientes variables de entorno se utilizan para determinar las ubicaciones de varios archivos de estado y configuración:

  • [XDG_CONFIG_HOME]{#env-XDGCONFIGHOME} (predeterminado ~/.config)
  • [XDG_STATE_HOME]{#env-XDGSTATEHOME} (predeterminado ~/.local/state)
  • [XDG_CACHE_HOME]{#env-XDGCACHEHOME} (predeterminado ~/.cache)

Ejemplos

Para instalar un paquete utilizando una ruta de atributo específica del expresión Nix activa:

$ nix-env --install --attr gcc40mips
installing `gcc-4.0.2'
$ nix-env --install --attr xorg.xorgserver
installing `xorg-server-1.2.0'

Para instalar una versión específica de gcc utilizando el nombre de la derivación:

$ nix-env --install gcc-3.3.2
installing `gcc-3.3.2'
uninstalling `gcc-3.1'

Se prefiere el uso de la ruta de atributo para seleccionar un paquete, ya que es mucho más rápido y no habrá coincidencias múltiples.

Observe que la versión instalada previamente se elimina, ya que no se especificó --preserve-installed.

Para instalar una versión arbitraria:

$ nix-env --install gcc
installing `gcc-3.3.2'

Para instalar todas las derivaciones en la expresión Nix foo.nix:

$ nix-env --file ~/foo.nix --install '.*'

Para copiar la ruta de la tienda con el nombre simbólico gcc de otro perfil:

$ nix-env --install --from-profile /nix/var/nix/profiles/foo gcc

Para instalar una derivación de tienda específica:

$ nix-env --install /nix/store/fibjb1bfbpm5mrsxc4mh2d8n37sxh91i-gcc-3.4.3.drv

Para instalar una ruta de salida específica:

$ nix-env --install /nix/store/y3cgx0xj1p4iv9x0pnnmdhr8iyg741vk-gcc-3.4.3

Para instalar desde una expresión Nix especificada en la línea de comandos:

$ nix-env --file ./foo.nix --install --expr \
    'f: (f {system = "i686-linux";}).subversionWithJava'

Es decir, esto se evalúa a (f: (f {system = "i686-linux";}).subversionWithJava) (import ./foo.nix), seleccionando así el atributo subversionWithJava del conjunto devuelto al llamar a la función definida en ./foo.nix.

Una ejecución en seco le indica qué rutas se descargarán o compilarán desde el código fuente:

$ nix-env --file '<nixpkgs>' --install --attr hello --dry-run
(dry run; not doing anything)
installing ‘hello-2.10’
this path will be fetched (0.04 MiB download, 0.19 MiB unpacked):
  /nix/store/wkhdf9jinag5750mqlax6z2zbwhqb76n-hello-2.10
  ...

Para instalar Firefox desde la última revisión en el canal Nixpkgs/NixOS 14.12:

$ nix-env --file https://github.com/NixOS/nixpkgs/archive/nixos-14.12.tar.gz --install --attr firefox
