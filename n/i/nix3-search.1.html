nix3-search(1) Manual de comandos generales nix3-search(1)

Advertencia
Este programa es experimental y su interfaz está sujeta a cambios.

Nombre

nix search - buscar paquetes

Sinopsis

nix search [opción…] instalable regex…

Ejemplos

•
Mostrar todos los paquetes en el flake nixpkgs:
# nix search nixpkgs ^
* legacyPackages.x86_64-linux.AMB-plugins (0.8.1)
Un conjunto de plugins ladspa de ambisonics
* legacyPackages.x86_64-linux.ArchiSteamFarm (4.3.1.0)
Aplicación con el propósito principal de poner en inactivo tarjetas de Steam de múltiples cuentas simultáneamente
…
•
Mostrar paquetes en el flake nixpkgs que contengan blender en su nombre o descripción:
# nix search nixpkgs blender
* legacyPackages.x86_64-linux.blender (2.91.0)
Sistema de Creación/Animación/Publicación 3D
•
Buscar paquetes debajo del atributo gnome3 en Nixpkgs:
# nix search nixpkgs#gnome3 vala
* legacyPackages.x86_64-linux.gnome3.vala (0.48.9)
Compilador para el sistema de tipos GObject
•
Mostrar todos los paquetes en el flake en el directorio actual:
# nix search . ^
•
Buscar Firefox o Chromium:
# nix search nixpkgs 'firefox|chromium'
•
Buscar paquetes que contengan git y ya sea frontend o gui:
# nix search nixpkgs git 'frontend|gui'
•
Buscar paquetes que contengan neovim pero ocultar aquellos que contengan gui o python:
# nix search nixpkgs neovim --exclude 'python|gui'
o
# nix search nixpkgs neovim --exclude 'python' --exclude 'gui'

Descripción

nix search busca en instalables (que pueden ser evaluados, es decir, un flake o expresión Nix, pero no una ruta de tienda o una ruta de derivación de tienda) paquetes cuyos nombres o descripciones coincidan con todas las expresiones regulares regex. Para cada paquete coincidente, imprime el nombre completo del atributo (desde la raíz del instalable), la versión y el campo meta.description, resaltando las subcadenas que coincidieron con las expresiones regulares.

Para mostrar todos los paquetes, usa la expresión regular ^. A diferencia de .*, evita resaltar todo el nombre y la descripción de cada paquete.

Ten en cuenta que en este contexto, ^ es el carácter regex para hacer coincidir el inicio de una cadena, *no* el delimitador para seleccionar una salida de derivación.

Atributos de salida de flake

Si no se proporciona un atributo de salida de flake, nix search busca paquetes:

  • Directamente debajo de packages.<system>.
  • Debajo de legacyPackages.<system>, recursando en conjuntos de atributos que contienen un atributo recurseForDerivations = true.

Opciones

•
--exclude / -e regex
Ocultar paquetes cuya ruta de atributo, nombre o descripción contengan regex.
•
--json
Producir salida en formato JSON, adecuada para el consumo por otro programa.

Opciones comunes de evaluación

•
--arg name expr
Pasar el valor expr como argumento name a las funciones Nix.
•
--arg-from-file name path
Pasar el contenido del archivo path como argumento name a las funciones Nix.
•
--arg-from-stdin name
Pasar el contenido de stdin como argumento name a las funciones Nix.
•
--argstr name string
Pasar la cadena string como argumento name a las funciones Nix.
•
--debugger
Iniciar un entorno interactivo si la evaluación falla.
•
--eval-store store-url
La URL de la tienda Nix a utilizar para la evaluación, es decir, para almacenar derivaciones (.drv files) y las entradas referenciadas por ellas.
•
--impure
Permitir el acceso a rutas y repositorios mutables.
•
--include / -I path
Añadir path a las entradas de ruta de búsqueda utilizadas para resolver rutas de consulta
Esta opción se puede dar varias veces.
Las rutas añadidas a través de -I tienen prioridad sobre la configuración nix-path y la variable de entorno NIX_PATH.
•
--override-flake original-ref resolved-ref
Sobrescribir los registros de flakes, redirigiendo original-ref a resolved-ref.

Opciones comunes relacionadas con flakes

•
--commit-lock-file
Confirmar cambios en el archivo de bloqueo del flake.
•
--inputs-from flake-url
Utilizar las entradas del flake especificado como entradas de registro.
•
--no-registries
No permitir búsquedas en los registros de flakes.
OBSOLETO
Usar --no-use-regist

NAME

nix - Content-addressable path-based build system

SYNOPSIS

nix [option...] command [args...]

nix [option...] --help | -v | --version

DESCRIPTION

Nix is a powerful package manager for Linux and other Unix-like systems that focuses on enabling reliable and reproducible builds. It provides atomic upgrades and rollbacks, can be used to manage multiple versions of a package, and features a unique «content-addressable» store.

This manual page provides an overview of the Nix command-line interface. It is not intended to be a complete reference, but rather to provide a starting point for users who are new to Nix or need a quick reminder of common commands and options.

For more detailed information, please refer to the official Nix documentation:

  • Nix Manual: https://nixos.org/manual/nix/stable/

  • Nix Command Reference: https://nixos.org/command-ref/index.html

This manual page is a consolidated view of many Nix commands and their options. It is organized into the following sections:

  • Flake output attributes
  • Options

Flake output attributes

When Nix evaluates a flake, it exposes a set of outputs. These outputs can be accessed using attribute paths. For example, if a flake has an output named `packages`, you can access it using `my-flake#packages`.

The following are common flake output attributes:

devShell

A development shell environment. Use nix develop to enter this shell.

packages

A collection of packages. You can access individual packages using attribute paths, e.g. my-flake#packages.default.

apps

A collection of runnable applications. You can run these using nix run, e.g. nix run my-flake#my-app.

nixosConfigurations

NixOS system configurations. These can be built or deployed using nix build or nixos-rebuild respectively.

Options

Nix supports a wide range of command-line options that can modify its behavior. These options are generally grouped by their functionality.

Flake lock file management

•
--commit-lockfile
Atomically commit the flake's lock file to the Git repository.
•
--editor editor-command
Use the specified editor command to edit the lock file.
•
--flake-lock flake-lock-path
Use the specified file as the flake lock file.
•
--re-lock
Recreate the flake's lock file from scratch.
DEPRECATED
Use nix flake update instead.
•
--update-lock-file
Allow updates to the flake's lock file.
DEPRECATED
Use nix flake update instead.
•
--no-update-lock-file
Do not allow any updates to the flake's lock file.
•
--no-write-lock-file
Do not write the flake's newly generated lock file.
•
--output-lock-file flake-lock-path
Write the given lock file instead of flake.lock within the top-level flake.
•
--override-input input-path flake-url
Override a specific flake input (e.g. dwarffs/nixpkgs). This implies --no-write-lock-file.
•
--recreate-lock-file
Recreate the flake's lock file from scratch.
DEPRECATED
Use nix flake update instead.
•
--reference-lock-file flake-lock-path
Read the given lock file instead of flake.lock within the top-level flake.
•
--update-input input-path
Update a specific flake input (ignoring its previous entry in the lock file).
DEPRECATED
Use nix flake update instead.

Logging-related options

•
--debug
Set the logging verbosity level to ‘debug’.
•
--log-format format
Set the format of log output; one of raw, internal-json, bar or bar-with-logs.
•
--print-build-logs / -L
Print full build logs on standard error.
•
--quiet
Decrease the logging verbosity level.
•
--verbose / -v
Increase the logging verbosity level.

Miscellaneous global options

•
--help
Show usage information.
•
--offline
Disable substituters and consider all previously downloaded files up-to-date.
•
--option name value
Set the Nix configuration setting name to value (overriding nix.conf).
•
--refresh
Consider all previously downloaded files out-of-date.
•
--repair
During evaluation, rewrite missing or corrupted files in the Nix store. During building, rebuild missing or corrupted store paths.
•
--version
Show version information.

Options that change the interpretation of installables

•
--expr expr
Interpret installables as attribute paths relative to the Nix expression expr.
•
--file / -f file
Interpret installables as attribute paths relative to the Nix expression stored in file. If file is the character -, then a Nix expression will be read from standard input. Implies --impure.

Note

See man nix.conf for overriding configuration settings with command line flags.
