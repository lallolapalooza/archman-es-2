nix3-store-diff-closures(1) Manual de comandos generales nix3-store-diff-closures(1)

Advertencia
Este programa es experimental y su interfaz está sujeta a cambios.

Nombre

nix store diff-closures - muestra qué paquetes y versiones se añadieron y eliminaron entre dos clausuras

Sinopsis

nix store diff-closures [opción…] antes después

Ejemplos

•
Muestra qué se añadió y eliminó entre dos versiones del perfil del sistema NixOS:
# nix store diff-closures /nix/var/nix/profiles/system-655-link /nix/var/nix/profiles/system-658-link
acpi-call: 2020-04-07-5.8.16 → 2020-04-07-5.8.18
baloo-widgets: 20.08.1 → 20.08.2
bluez-qt: +12.6 KiB
dolphin: 20.08.1 → 20.08.2, +13.9 KiB
kdeconnect: 20.08.2 → ∅, -6597.8 KiB
kdeconnect-kde: ∅ → 20.08.2, +6599.7 KiB
…

Descripción

Este comando muestra las diferencias entre las dos clausuras antes y después con respecto a la adición, eliminación o cambio de versión de paquetes, así como cambios en los tamaños de las rutas de la tienda.

Para cada nombre de paquete en las dos clausuras (donde un nombre de paquete se define como el componente de nombre de una ruta de la tienda excluyendo la versión), si hay un cambio en el conjunto de versiones del paquete, o un cambio en el tamaño de las rutas de la tienda de más de 8 KiB, imprime una línea como esta:

dolphin: 20.08.1 → 20.08.2, +13.9 KiB

No se muestra ningún cambio de tamaño si es inferior al umbral. Si el paquete no existe en la clausura antes o después, se representa usando ∅ (conjunto vacío) en el lado apropiado de la flecha. Si un paquete tiene una cadena de versión vacía, la versión se representa como ε (épsilon).

Puede haber múltiples versiones de un paquete en cada clausura. En ese caso, solo se muestran las versiones cambiadas. Por lo tanto,

libfoo: 1.2, 1.3 → 1.4

deja abierta la posibilidad de que existan otras versiones (por ejemplo, 1.1) que existen en ambas clausuras.

Description

The nix-store command is a low-level interface to the Nix store, a read-only cache of all the packages and other software components on the system. It is primarily used internally by Nix, but it offers commands for inspecting the store, building derivations, and managing the store.

This manual page documents the most common subcommands. For a complete list, run nix-store --help.

Subcommands

--optimize
Removes unused store paths and replaces identical paths with links to a single copy.
--query
Queries information about store paths. Common options include:
--requisites
Print all direct and indirect build-time dependencies of the given paths.
--references
Print all direct and indirect run-time dependencies of the given paths.
--tree
Print a tree of all dependencies.
--out-paths
Print the output paths of the given derivations.
--drvs
Print the derivations that produce the given paths.
--all
Query all information about the specified paths.
--delete
Removes the specified store paths and all paths that depend on them (if they are not referenced elsewhere).
--gc
Runs the garbage collector to remove unreferenced store paths. Use with caution.
--add-root
Adds a root reference to a store path. Roots are used to keep store paths from being garbage collected.
--drop-root
Removes a root reference.
--realize
Builds the given derivations. This is typically done by nix-build.
--run-derivations
Runs derivations. This is a low-level command used to execute the build process defined in a derivation file.
--export-store-path
Exports the contents of one or more store paths to a tarball.
--import-store-path
Imports store paths from a tarball previously created with --export-store-path.
--dump
Dumps the Nix database to standard output.
--load-db
Loads the Nix database from standard input.
--verify-path-from-file
Verifies the integrity of store paths listed in a file.

Examples

List all store paths:

$ nix-store --query --all /nix/store/path...

Query the build-time dependencies of a package:

$ nix-store --query --requisites /nix/store/path-mypackage

Garbage collect unreferenced store paths:

$ nix-store --gc

Build a derivation:

$ nix-store --realize /nix/store/drv-path...

Export a store path to a tarball:

$ nix-store --export-store-path /nix/store/path... > paths.tgz

Import store paths from a tarball:

$ nix-store --import-store-path < paths.tgz
