Advertencia

Nombre

nix eval - evalúa una expresión Nix

Sinopsis

nix eval [opción…] instalaable

Ejemplos

•
Evalúa una expresión Nix dada en la línea de comandos:
# nix eval --expr '1 + 2'
•
Evalúa una expresión Nix a JSON:
# nix eval --json --expr '{ x = 1; }'
{"x":1}
•
Evalúa una expresión Nix desde un archivo:
# nix eval --file ./mi-nixpkgs hello.name
•
Obtiene la versión actual del flake nixpkgs:
# nix eval --raw nixpkgs#lib.version
•
Imprime la ruta de la tienda del paquete Hello:
# nix eval --raw nixpkgs#hello
•
Obtiene una lista de comprobaciones en el flake nix:
# nix eval nix#checks.x86_64-linux --apply builtins.attrNames
•
Genera un directorio con el contenido especificado:
# nix eval --write-to ./out --expr '{ foo = "bar"; subdir.bla = "123"; }'
# cat ./out/foo
bar
# cat ./out/subdir/bla
123

Descripción

Este comando evalúa la expresión Nix dada e imprime el resultado en la salida estándar.

Formato de salida

nix eval puede producir salida en varios formatos:

  • Por defecto, el resultado de la evaluación se imprime como una expresión Nix.
  • Con --json, el resultado de la evaluación se imprime en formato JSON. Ten en cuenta que esto falla si el resultado contiene valores que no son representables como JSON, como funciones.
  • Con --raw, el resultado de la evaluación debe ser una cadena, que se imprime verbatim, sin comillas ni escapes.
  • Con --write-to ruta, el resultado de la evaluación debe ser una cadena o un conjunto de atributos anidado cuyos valores hoja sean cadenas. Estas cadenas se escriben en archivos llamados ruta/rutas_atributos. ruta no debe existir previamente.

Opciones

•
--apply expr
Aplica la función expr a cada argumento.
•
--json
Produce salida en formato JSON, adecuada para el consumo por otro programa.
•
--raw
Imprime cadenas sin comillas ni escapes.
•
--read-only
No instancia cada derivación evaluada. Esto mejora el rendimiento, pero puede causar errores al acceder a las rutas de la tienda de derivaciones durante la evaluación.
•
--write-to ruta
Escribe una cadena o un conjunto de atributos de cadenas en ruta.

Opciones comunes de evaluación

•
--arg nombre expr
Pasa el valor expr como argumento nombre a las funciones Nix.
•
--arg-from-file nombre ruta
Pasa el contenido del archivo ruta como argumento nombre a las funciones Nix.
•
--arg-from-stdin nombre
Pasa el contenido de stdin como argumento nombre a las funciones Nix.
•
--argstr nombre cadena
Pasa la cadena cadena como argumento nombre a las funciones Nix.
•
--debugger
Inicia un entorno interactivo si la evaluación falla.
•
--eval-store url-tienda
La URL de la tienda Nix a usar para la evaluación, es decir, para almacenar las derivaciones (.drv) y las entradas referenciadas por ellas.
•
--impure
Permite el acceso a rutas y repositorios mutables.
•
--include / -I ruta
Añade ruta a las entradas de la ruta de búsqueda utilizadas para resolver las rutas de búsqueda
Esta opción puede darse varias veces.
Las rutas añadidas a través de -I tienen precedencia sobre el ajuste de configuración nix-path y la variable de entorno NIX_PATH .
•
--override-flake ref-original ref-resuelto
Sobrescribe los registros de flakes, redirigiendo ref-original a ref-resuelto.

Opciones comunes relacionadas con flakes

•
--commit-lock-file
Confirma los cambios en el archivo de bloqueo del flake.
•
--inputs-from flake-url
Utiliza las entradas del flake especificado como entradas de registro.
•
--no-registries
No permite búsquedas en los registros de flakes.
OBSOLETO
Usa --no-use-registries en su lugar.
•
--no-update-lock-file
No permite ninguna actualización del archivo de bloqueo del flake.
•
--no-write-lock-file
No escribe el archivo de bloqueo recién generado del flake.
•
--output-lock-file ruta
Escribe el nuevo archivo de bloqueo del flake en ruta.
•
--rebuild-lock-file
Reconstruye el archivo de bloqueo del flake. Esto puede ser necesario si las entradas de sub-flake han cambiado y necesitas reflejar esos cambios en el archivo de bloqueo.
•
--use-dry-run
No actualiza el archivo de bloqueo si la evaluación no produce un registro de flake.
•
--use-flake-addr flake-addr
Invalida la forma en que el registro de flakes determina la dirección de los flakes.
•
--use-flake-fallback
Usa el fallback para las direcciones de flakes.
•
--use-flake-registry flake-registry
Usa el registro de flakes especificado en la ruta.
•
--use-flake-sources
Usa las fuentes de los flakes como registro.

NAME

nix3-flake-update - update inputs in a flake.lock file

SYNOPSIS

nix flake update [options] [installables...]

EXAMPLES

•
Update all inputs in flake.lock
$ nix flake update
•
Update a specific input
$ nix flake update --update-input nixpkgs
•
Update multiple inputs
$ nix flake update --update-input nixpkgs --update-input home-manager
•
Use a specific flake lock file
$ nix flake update --flake-lock-path my-lock-file.lock
•
Recreate the lock file from scratch
$ nix flake update --recreate-lock-file
•
Override a specific input to point to a different flake URL
$ nix flake update --override-input nixpkgs github:NixOS/nixpkgs/nixos-unstable

DESCRIPTION

The command nix flake update updates inputs specified in flake.lock(5), or recreates the entire lock file if no inputs are specified.

The behaviour of nix flake update depends on the arguments provided:

  • If one or more installables are given, the command attempts to update the specified flake inputs. The inputs are identified by their name (e.g. nixpkgs). If an input is specified multiple times, the last one takes precedence.
  • If no installables are given, the command updates all inputs listed in the flake lock file.

The command honours the flake.lock file in the current directory by default. This can be changed using the --flake-lock-path option.

The command writes the updated lock file back to disk by default. This can be prevented using the --no-write-lock-file option.

The command supports overriding specific inputs using --override-input. This option implies --no-write-lock-file, as the updated lock file is not written.

The command supports recreating the lock file from scratch using --recreate-lock-file. This option is deprecated and nix flake update should be used instead.

The command supports updating a specific input using --update-input. This option is deprecated and nix flake update should be used instead.

Options

•
--commit-lock-file lock-file-commit
Update the lock file and commit the changes to the Git repository.
•
--flake-lock-path flake-lock-path
Write the given lock file instead of flake.lock within the top-level flake.
•
--no-write-lock-file
Do not write the updated lock file back to disk.
•
--override-input input-path flake-url
Override a specific flake input (e.g. dwarffs/nixpkgs). This implies --no-write-lock-file.
•
--recreate-lock-file
Recreate the flake’s lock file from scratch.
DEPRECATED
Use nix flake update instead.
•
--reference-lock-file flake-lock-path
Read the given lock file instead of flake.lock within the top-level flake.
•
--update-input input-path
Update a specific flake input (ignoring its previous entry in the lock file).
DEPRECATED
Use nix flake update instead.

Logging-related options

•
--debug
Set the logging verbosity level to ‘debug’.
•
--log-format format
Set the format of log output; one of raw, internal-json, bar or bar-with-logs.
•
--print-build-logs / -L
Print full build logs on standard error.
•
--quiet
Decrease the logging verbosity level.
•
--verbose / -v
Increase the logging verbosity level.

Miscellaneous global options

•
--help
Show usage information.
•
--offline
Disable substituters and consider all previously downloaded files up-to-date.
•
--option name value
Set the Nix configuration setting name to value (overriding nix.conf).
•
--refresh
Consider all previously downloaded files out-of-date.
•
--repair
During evaluation, rewrite missing or corrupted files in the Nix store. During building, rebuild missing or corrupted store paths.
•
--version
Show version information.

Options that change the interpretation of installables

•
--expr expr
Interpret installables as attribute paths relative to the Nix expression expr.
•
--file / -f file
Interpret installables as attribute paths relative to the Nix expression stored in file. If file is the character -, then a Nix expression will be read from standard input. Implies --impure.
