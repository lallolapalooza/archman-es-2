nix3-flake-check(1) Manual de Comandos Generales nix3-flake-check(1)

Advertencia
Este programa es experimental y su interfaz está sujeta a cambios.

Nombre

nix flake check - verifica que el flake se evalúe y ejecuta sus pruebas

Sinopsis

nix flake check [opción…] flake-url

Ejemplos

•
Evalúa el flake en el directorio actual y construye sus verificaciones:
# nix flake check
•
Verifica que el flake patchelf se evalúe, pero no construye sus verificaciones:
# nix flake check --no-build github:NixOS/patchelf

Descripción

Este comando verifica que el flake especificado por la referencia de flake flake-url pueda evaluarse exitosamente (como se detalla a continuación), y que las derivaciones especificadas por la salida checks del flake puedan construirse exitosamente.

Si la opción keep-going se establece en true, Nix continuará evaluando tanto como pueda e informará los errores a medida que los encuentre. De lo contrario, se detendrá ante el primer error.

Verificaciones de evaluación

Los siguientes atributos de salida del flake deben ser derivaciones:

  • checks.system.name
  • defaultPackage.system
  • devShell.system
  • devShells.system.name
  • nixosConfigurations.name.config.system.build.toplevel
  • packages.system.name

Los siguientes atributos de salida del flake deben ser definiciones de aplicaciones:

  • apps.system.name
  • defaultApp.system

Los siguientes atributos de salida del flake deben ser definiciones de plantillas:

  • defaultTemplate
  • templates.name

Los siguientes atributos de salida del flake deben ser *superposiciones de Nixpkgs*:

  • overlay
  • overlays.name

Los siguientes atributos de salida del flake deben ser *módulos NixOS*:

  • nixosModule
  • nixosModules.name

Los siguientes atributos de salida del flake deben ser bundlers:

  • bundlers.name
  • defaultBundler

Además, la salida hydraJobs se evalúa de la misma manera que hydra-eval-jobs de Hydra (es decir, como un conjunto de atributos de derivaciones anidados arbitrariamente). Del mismo modo, la salida legacyPackages.system se evalúa como nix-env --query --available.

Opciones

•
--all-systems
Verifica las salidas para todos los sistemas.
•
--no-build
No construir verificaciones.

Opciones comunes de evaluación

•
--arg nombre expr
Pasa el valor expr como el argumento nombre a las funciones Nix.
•
--arg-from-file nombre ruta
Pasa el contenido del archivo ruta como el argumento nombre a las funciones Nix.
•
--arg-from-stdin nombre
Pasa el contenido de stdin como el argumento nombre a las funciones Nix.
•
--argstr nombre cadena
Pasa la cadena cadena como el argumento nombre a las funciones Nix.
•
--debugger
Inicia un entorno interactivo si la evaluación falla.
•
--eval-store url-store
La URL del store Nix a utilizar para la evaluación, es decir, para almacenar derivaciones (.drv archivos) y las entradas a las que hacen referencia.
•
--impure
Permite el acceso a rutas y repositorios mutables.
•
--include / -I ruta
Añade ruta a las entradas de la ruta de búsqueda utilizadas para resolver rutas de búsqueda
Esta opción se puede dar varias veces.
Las rutas añadidas a través de -I tienen prioridad sobre la configuración nix-path y la variable de entorno NIX_PATH.
•
--override-flake ref-original ref-resuelto
Anula los registros de flakes, redirigiendo ref-original a ref-resuelto.

Opciones comunes relacionadas con flakes

•
--commit-lock-file
Confirma los cambios en el archivo de bloqueo del flake.
•
--inputs-from flake-url
Utiliza las entradas del flake especificado como entradas de registro.
•
--no-registries
No permite búsquedas en los registros de flakes.
OBSOLETO
Utiliza --no-use-registries en su lugar.
•
--no-update-lock-file
No permite ninguna actualización del archivo de bloqueo del flake.

NAME

nix-flake-check - Check flake inputs and outputs

SYNOPSIS

nix flake check [-L<info> | -v | --verbose | --quiet] [--log-format format] [--show-trace] [--no-warn-dirty] [--commit commit] [--eval-store eval-store] [--allow-unsafe-native-code-substitution] [--option name value] [-I paths] [--extra-experimental-feature feature] [--json] [--print-derivations] [--no-write-lock-file] [--output-lock-file flake-lock-path] [--override-input input-path flake-url] [--recreate-lock-file] [--reference-lock-file flake-lock-path] [--update-input input-path] [--debug] [--print-build-logs] [--help] [--offline] [--refresh] [--repair] [--version] [--read-only-store] [--substituters urls] [--trusted-public-keys keys] [--accept-flake-config] [--accept-flake-lockfile] [--accept-flake-output-filter filter] [--flake-output-filter filter] [--system system] [--json-trace] [--json-input-derivation] [--legacy-parallel-building] [--compress-outputs] [--no-compress-outputs] [--max-jobs n] [--keep-failed] [--keep-going] [--icarus] [--no-link] [--impure] [--file file] [--expr expr] [--arg name value] [--argjson name json-value] [--argstr name string-value] [--include glob] [--exclude glob] [--allow-dirty] [--allow-broken] [--allow-unfree] [--impure-shared-modules] [--rebuild policy] [--access-control-script file] [--access-control-script-args args] [--flake-attribute attr] [-- flake-url] [[flake-url]]

EXAMPLES

      Check all outputs of a flake:
        $ nix flake check

      Check a specific flake output:
        $ nix flake check --flake-attribute checks.my-app

      Check a flake located in a subdirectory:
        $ nix flake check --flake-url ./my-flake

DESCRIPTION

Checks the outputs of a flake. This command works by evaluating the flake, then attempting to build and test all outputs that are marked as checkable (e.g. outputs named checks.* or devShells.*).

By default, Nix will check all outputs of the flake. This can be restricted using --flake-attribute (or -A), which selects a specific flake output to check.

If the flake contains any outputs that are explicitly marked as checkable (e.g. checks.*), Nix will only check those outputs. Otherwise, Nix will attempt to build and check all outputs in the flake.

Note that Nix will try to discover checkable outputs based on their names. For example, checks.my-app will be checked, but apps.my-app will not be checked unless it is explicitly specified.

For more information on flake outputs, see flake outputs.

This command is essentially a convenience wrapper around nix build and nix run.

Flake lock file handling

The nix flake check command updates the flake lock file (typically flake.lock) if inputs are changed or if the lock file doesn’t exist. The following options can be used to control this behavior:

•
--no-write-lock-file
Do not write the flake’s newly generated lock file.
•
--output-lock-file flake-lock-path
Write the given lock file instead of flake.lock within the top-level flake.
•
--override-input input-path flake-url
Override a specific flake input (e.g. dwarffs/nixpkgs). This implies --no-write-lock-file.
•
--recreate-lock-file
Recreate the flake’s lock file from scratch.
DEPRECATED
Use nix flake update instead.
•
--reference-lock-file flake-lock-path
Read the given lock file instead of flake.lock within the top-level flake.
•
--update-input input-path
Update a specific flake input (ignoring its previous entry in the lock file).
DEPRECATED
Use nix flake update instead.
