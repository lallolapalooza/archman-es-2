Nombre

nix-env --switch-profile - establecer el entorno del usuario al perfil dado

Sinopsis

nix-env {--switch-profile | -S} ruta

Descripción

Esta operación hace que ruta sea el perfil actual para el usuario. Es decir, el enlace simbólico ~/.nix-profile se hace que apunte a ruta.

Opciones

Las siguientes opciones están permitidas para todas las operaciones de nix-env, pero pueden no tener siempre un efecto.

•
--file / -f ruta
Especifica la expresión Nix (designada abajo como la expresión Nix activa) utilizada por las operaciones --install, --upgrade y --query --available para obtener derivaciones. La predeterminada es ~/.nix-defexpr.
Si el argumento comienza con http:// o https://, se interpreta como la URL de un archivo tar que se descargará y descomprimirá en una ubicación temporal. El archivo tar debe incluir un único directorio de nivel superior que contenga al menos un archivo llamado default.nix.
•
--profile / -p ruta
Especifica el perfil a ser utilizado por aquellas operaciones que operan en un perfil (designado abajo como el perfil activo). Un perfil es una secuencia de entornos de usuario llamados generaciones, una de las cuales es la generación actual.
•
--dry-run
Para las operaciones --install, --upgrade, --uninstall, --switch-generation, --delete-generations y --rollback, esta bandera hará que nix-env imprima lo que se haría si esta bandera no se hubiera especificado, sin hacerlo realmente.
--dry-run también imprime qué rutas serán sustituidas (es decir, descargadas) y qué rutas se construirán desde la fuente (porque no hay sustituto disponible).
•
--system-filter sistema
Por defecto, las operaciones como --query --available muestran derivaciones que coinciden con cualquier plataforma. Esta opción te permite usar derivaciones para la plataforma sistema especificada.

Esta opción se puede especificar repetidamente. Ver la lista anterior de niveles de verbosidad.
•
--log-format formato

bar

bar-with-logs

Esta opción suprime este comportamiento. Tenga en cuenta que la salida estándar y el error del constructor siempre se escriben en un archivo de registro en prefijo/nix/var/log/nix.

Establece el número máximo de trabajos de compilación que Nix realizará en paralelo al número especificado. Especifique auto para usar el número de CPUs en el sistema. El valor predeterminado se especifica en la configuración max-jobs, que a su vez tiene como valor predeterminado 1. Un valor más alto es útil en sistemas SMP o para aprovechar la latencia de E/S.
Establecerlo en 0 deshabilita la compilación en la máquina local, lo cual es útil cuando solo desea que las compilaciones ocurran en constructores remotos.

Opciones

•
--cores
Establece el valor de la variable de entorno NIX_BUILD_CORES en la invocación de los constructores. Los constructores pueden usar esta variable a su discreción para controlar la cantidad máxima de paralelismo. Por ejemplo, en Nixpkgs, si el atributo de derivación enableParallelBuilding se establece en true, el constructor pasa la bandera -jN a GNU Make. Por defecto, toma el valor de la configuración de cores, si está definida, o 1 en caso contrario. El valor 0 significa que el constructor debe usar todos los núcleos de CPU disponibles en el sistema.
•
--max-silent-time
Establece el número máximo de segundos que un constructor puede pasar sin producir ninguna salida en la salida estándar o error estándar. El valor por defecto lo especifica la configuración max-silent-time. 0 significa que no hay tiempo de espera.
•
--timeout
Establece el número máximo de segundos que un constructor puede ejecutarse. El valor por defecto lo especifica la configuración timeout. 0 significa que no hay tiempo de espera.
•
--keep-going / -k
Continúa en caso de fallos en la construcción, en la mayor medida posible. Es decir, si falla la construcción de una entrada de alguna derivación, Nix continuará construyendo las otras entradas, pero no la derivación en sí. Sin esta opción, Nix se detiene si alguna construcción falla (excepto las construcciones de sustitutos), posiblemente matando las construcciones en curso (en caso de construcciones paralelas o distribuidas).
•
--keep-failed / -K
Especifica que en caso de fallo en la construcción, el directorio temporal (generalmente en /tmp) en el que se realiza la construcción no debe ser eliminado. La ruta del directorio de construcción se imprime como un mensaje informativo.
•
--fallback
Siempre que Nix intente construir una derivación para la cual se conocen sustitutos para cada ruta de salida, pero la realización de las rutas de salida a través de los sustitutos falla, recurre a la construcción de la derivación.
El escenario más común en el que esto es útil es cuando hemos registrado sustitutos para realizar la distribución binaria desde, por ejemplo, un repositorio de red. Si el repositorio está caído, la realización de la derivación fallará. Cuando se especifica esta opción, Nix construirá la derivación en su lugar. Por lo tanto, la instalación desde binarios recurre a la instalación desde el código fuente. Esta opción no es la predeterminada ya que generalmente no es deseable que un fallo transitorio al obtener los sustitutos conduzca a una construcción completa desde el código fuente (con el consumo de recursos relacionado).
•
--readonly-mode
Cuando se utiliza esta opción, no se intenta abrir la base de datos de Nix. La mayoría de las operaciones de Nix necesitan acceso a la base de datos, por lo que esas operaciones fallarán.
•
--arg nombre valor
Esta opción es aceptada por nix-env, nix-instantiate, nix-shell y nix-build. Al evaluar expresiones Nix, el evaluador de expresiones intentará automáticamente llamar a las funciones que encuentre. Puede llamar automáticamente a funciones para las que todos los argumentos tienen un valor predeterminado (por ejemplo, { argName ? defaultValue }: ...).
Con --arg, también puedes llamar a funciones que tienen argumentos sin valor predeterminado (o anular un valor predeterminado). Es decir, si el evaluador encuentra una función con un argumento llamado nombre, la llamará con el valor valor.
Por ejemplo, el default.nix de nivel superior en Nixpkgs es en realidad una función:
{ # El sistema (por ejemplo, `i686-linux') para el cual construir los paquetes.
system ? builtins.currentSystem
...
}: ...
Por lo tanto, si llamas a esta expresión Nix (por ejemplo, cuando haces nix-env --install --attr pkgname), la función se llamará automáticamente usando el valor builtins.currentSystem para el argumento system. Puedes anular esto usando --arg, por ejemplo, nix-env --install --attr pkgname --arg system \"i686-freebsd\". (Ten en cuenta que como el argumento es una cadena literal de Nix, debes escapar las comillas.)
•
--argstr nombre valor
Esta opción es como --arg, solo que el valor no es una expresión Nix sino una cadena. Así que en lugar de --arg system \"i686-linux\" (las comillas exteriores son para que el shell las maneje) puedes decir --argstr system i686-linux.
•
--attr / -A rutaAttr
Selecciona un atributo de la expresión Nix de nivel superior que se está evaluando. (Solo nix-env, nix-instantiate, nix-build y nix-shell.) La ruta de atributos rutaAttr es una secuencia de nombres de atributos separados por puntos. Por ejemplo, dada una expresión Nix de nivel superior e, la ruta de atributos xorg.xorgserver haría que se usara la expresión e.xorg.xorgserver. Consulta nix-env --install para ver algunos ejemplos concretos.
Además de los nombres de atributos, también puedes especificar índices de array. Por ejemplo, la ruta de atributos foo.3.bar selecciona el atributo bar del cuarto elemento del array en el atributo foo de la expresión de nivel superior.
•
--expr / -E
Interpreta los argumentos de la línea de comandos como una lista de expresiones Nix para ser analizadas y evaluadas, en lugar de como una lista de nombres de archivo de expresiones Nix. (Solo nix-instantiate, nix-build y nix-shell.)
Para nix-shell, esta opción se usa comúnmente para proporcionarte un shell en el que puedas construir los paquetes devueltos por la expresión. Si quieres obtener un shell que contenga los paquetes *construidos* listos para usar, dale tu expresión a la bandera de conveniencia nix-shell --packages en su lugar.
•
-I / --include ruta
Añade una entrada a la lista de rutas de búsqueda utilizadas para resolver rutas de búsqueda. Esta opción se puede dar varias veces.
Las rutas añadidas a través de -I tienen prioridad sobre la configuración nix-path y la variable de entorno NIX_PATH.
•
--option nombre valor
Establece la opción de configuración de Nix nombre a valor. Esto anula la configuración en el archivo de configuración de Nix (ver nix.conf5).
•
--repair
Repara rutas de la tienda corruptas o faltantes volviendo a descargarlas o reconstruyéndolas. Ten en cuenta que esto es lento porque requiere calcular un hash criptográfico del contenido de cada ruta en el cierre de la construcción. También ten en cuenta la advertencia en nix-store --repair-path.

nix-env(1) — archlinux.org

Name

nix-env — user environment management

Synopsis

nix-env [option...] {command | action}

Description

This command manages a user’s Nix profile, which is a collection of installed packages and the package sets they depend on. It allows you to install, upgrade, and remove packages, and to switch between different generations of your environment.

The primary interface to the Nix package manager is nix(1). The older command-line interface, like nix-env(1), is deprecated but still available.

Options

The following options are available:

--profile profile
The Nix profile to operate on. Defaults to ~/.nix-profile.

Environment variables

Nix uses a number of environment variables to customize its behavior. These can be set before running Nix commands.

•
NIX_PATH
A list of directories used to resolve lookup paths.
This environment variable overrides the value of the nix-path configuration setting.
It can be extended using the -I option.
Example
$ export NIX_PATH=`/home/eelco/Dev:nixos-config=/etc/nixos
If NIX_PATH is set to an empty string, resolving search paths will always fail.
Example
$ NIX_PATH= nix-instantiate --eval '<nixpkgs>'
error: file 'nixpkgs' was not found in the Nix search path (add it using $NIX_PATH or -I)
•
NIX_IGNORE_SYMLINK_STORE
Normally, the Nix store directory (typically /nix/store) is not allowed to contain any symlink components. This is to prevent “impure” builds. Builders sometimes “canonicalise” paths by resolving all symlink components. Thus, builds on different machines (with /nix/store resolving to different locations) could yield different results. This is generally not a problem, except when builds are deployed to machines where /nix/store resolves differently. If you are sure that you’re not going to do that, you can set NIX_IGNORE_SYMLINK_STORE to 1.
Note that if you’re symlinking the Nix store so that you can put it on another file system than the root file system, on Linux you’re better off using bind mount points, e.g.,
$ mkdir /nix
$ mount -o bind /mnt/otherdisk/nix /nix
Consult the mount 8 manual page for details.
•
NIX_STORE_DIR
Overrides the location of the Nix store (default prefix/store).
•
NIX_DATA_DIR
Overrides the location of the Nix static data directory (default prefix/share).
•
NIX_LOG_DIR
Overrides the location of the Nix log directory (default prefix/var/log/nix).
•
NIX_STATE_DIR
Overrides the location of the Nix state directory (default prefix/var/nix).
•
NIX_CONF_DIR
Overrides the location of the system Nix configuration directory (default prefix/etc/nix).
•
NIX_CONFIG
Applies settings from Nix configuration from the environment. The content is treated as if it was read from a Nix configuration file. Settings are separated by the newline character.
•
NIX_USER_CONF_FILES
Overrides the location of the Nix user configuration files to load from.
The default are the locations according to the XDG Base Directory Specification. See the XDG Base Directories sub-section for details.
The variable is treated as a list separated by the : token.
•
TMPDIR
Use the specified directory to store temporary files. In particular, this includes temporary build directories; these can take up substantial amounts of disk space. The default is /tmp.
•
NIX_REMOTE
This variable should be set to daemon if you want to use the Nix daemon to execute Nix operations. This is necessary in multi-user Nix installations. If the Nix daemon’s Unix socket is at some non-standard path, this variable should be set to unix://path/to/socket. Otherwise, it should be left unset.
•
NIX_SHOW_STATS
If set to 1, Nix will print some evaluation statistics, such as the number of values allocated.
•
NIX_COUNT_CALLS
If set to 1, Nix will print how often functions were called during Nix expression evaluation. This is useful for profiling your Nix expressions.
•
GC_INITIAL_HEAP_SIZE
If Nix has been configured to use the Boehm garbage collector, this variable sets the initial size of the heap in bytes. It defaults to 384 MiB. Setting it to a low value reduces memory consumption, but will increase runtime due to the overhead of garbage collection.

XDG Base Directories

Nix follows the XDG Base Directory Specification.

For backwards compatibility, Nix commands will follow the standard only when use-xdg-base-directories is enabled. New Nix commands (experimental) conform to the standard by default.

The following environment variables are used to determine locations of various state and configuration files:

  • [XDG_CONFIG_HOME]{#env-XDGCONFIGHOME} (default ~/.config)
  • [XDG_STATE_HOME]{#env-XDGSTATEHOME} (default ~/.local/state)
  • [XDG_CACHE_HOME]{#env-XDGCACHEHOME} (default ~/.cache)
