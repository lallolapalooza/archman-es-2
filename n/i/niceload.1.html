NICELOAD(1) parallel NICELOAD(1)

NOMBRE

niceload - ralentiza un programa cuando la carga promedio está por encima de un cierto límite

SINOPSIS

niceload [-v] [-h] [-n nice] [-I io] [-L load] [-M mem] [-N] [--sensor programa] [-t tiempo] [-s tiempo|-f factor] ( comando | -p PID [-p PID ...] | --prg programa )

DESCRIPCIÓN

GNU niceload ralentizará un programa cuando la carga promedio (u otra actividad del sistema) esté por encima de un cierto límite. Cuando se alcanza el límite, el programa se suspenderá durante un tiempo. Luego se reanudará durante un tiempo. Después, se volverá a comprobar la carga promedio y se reiniciará el ciclo.

En lugar de la carga promedio, niceload puede monitorizar la E/S de disco, la cantidad de memoria libre o la actividad de paginación.

Si la carga es 3.00, la configuración predeterminada ejecutará un programa así:

ejecutar 1 segundo, suspender (3.00-1.00) segundos, ejecutar 1 segundo, suspender (3.00-1.00) segundos, ejecutar 1 segundo, ...

OPCIONES

-B
--battery
Suspender si el sistema está funcionando con batería. Abreviatura de: -l -1 --sensor 'cat /sys/class/power_supply/BAT0/status /proc/acpi/battery/BAT0/state 2>/dev/null | grep -i -q discharging; echo $?'
-f FACTOR
--factor FACTOR
Factor de tiempo de suspensión. Establece dinámicamente -s como cantidad por encima del límite * factor. El valor predeterminado es 1.
-H
--hard
Límite estricto. --hard suspenderá el proceso hasta que el sistema esté por debajo de los límites. El valor predeterminado es --soft.
--io limitación_io
-I limitación_io
Límite para E/S. La cantidad de E/S de disco se calculará como un valor de 0 a 10, donde 0 es sin E/S y 10 es que al menos un disco está saturado al 100%.

--io establecerá tanto --start-io como --run-io.

--load limitación_carga
-L limitación_carga
Límite para la carga promedio.

--load establecerá tanto --start-load como --run-load.

--mem limitación_mem
-M limitación_mem
Límite para la memoria libre. Esta es la cantidad de bytes disponibles como libres + caché. Este límite se trata de forma opuesta a otros límites: si el sistema está por encima del límite, el programa se ejecutará, si está por debajo del límite, el programa se detendrá.

limitación_mem puede ir seguido de K, M, G, T o P, que multiplicarían el tamaño por 1024, 1048576, 1073741824 o 1099511627776 respectivamente.

--mem establecerá tanto --start-mem como --run-mem.

--noswap
-N
Sin paginación. Si el sistema está paginando tanto de entrada como de salida, es un buen indicio de que el sistema tiene estrés de memoria.

--noswap estará por encima del límite si el sistema está paginando tanto de entrada como de salida.

--noswap establecerá tanto --start-noswap como --run-noswap.

--net
Abreviatura de --nethops 3.
--nethops h
Nice de red. Pausar si la conexión a Internet está sobrecargada.

niceload encuentra un enrutador a h saltos de la Internet. Hace ping a este enrutador cada segundo. Si la latencia es más de un 50% mayor que la mediana, se considera que está por encima del límite.

--nethops se puede combinar con --hard. Sin --hard, el programa puede ser capaz de poner en cola tanto tráfico que tardará más que el tiempo de --suspend en despejarlo. --hard es útil para el tráfico que no se ve afectado negativamente por ser suspendido durante un tiempo más largo.

--nethops se puede combinar con un --suspend alto. De esta manera, se puede permitir que un programa realice un poco de tráfico de vez en cuando. Esto es útil para mantener la conexión activa.

-n niceness
--nice niceness
Establece la niceness. Ver nice(1).
-p PID[,PID]
--pid PID[,PID]
IDs de proceso de los procesos a suspender. Puedes especificar varios IDs de proceso con múltiples -p PID o separando los PIDs con coma.
--prg programa
--program programa
Nombre del programa en ejecución a suspender. Puedes especificar varios programas con múltiples --prg programa. Si no se encuentran procesos con el nombre programa, niceload buscará subcadenas que contengan programa.
--quote
-q
Citar la línea de comandos. Útil si el comando contiene caracteres como *, $, >, y " que no deben ser interpretados por el shell.
--run-io limitación_io
--ri limitación_io
--run-load limitación_carga
--rl limitación_carga
--run-mem limitación_mem
--rm limitación_mem
Límite de ejecución. El programa en ejecución se ralentizará si el sistema está por encima del límite. Ver: --io, --load, --mem, --noswap.
--sensor programa sensor
Leer sensor. Usa programa sensor para leer un sensor.

Esto mantendrá la temperatura de la CPU por debajo de 80°C en GNU/Linux:

niceload -l 80000 -f 0.001 --sensor 'sort -n /sys/devices/platform/coretemp*/temp*_input' gzip *

Esto se detendrá si el espacio en disco es < 100000.

niceload -H -l -100000 --sensor "df . | awk '{ print \$4 }'" echo
--start-io limitación_io
--si limitación_io
--start-load limitación_carga
--sl limitación_carga
--start-mem limitación_mem
--sm limitación_mem
Límite de inicio. El programa no se iniciará hasta que el sistema esté por debajo del límite. Ver: --io, --load, --mem, --noswap.
--soft
-S
Límite flexible. niceload suspenderá un proceso durante un tiempo y luego lo dejará ejecutarse durante un segundo, ralentizando así un proceso solo mientras el sistema está por encima de uno de los límites dados. Esta es la opción predeterminada.
--suspend SEG
-s SEG
Tiempo de suspensión. Suspende el comando durante esta cantidad de segundos cuando se alcanza la carga promedio máxima.
--recheck SEG
-t SEG
Tiempo de reevaluación de la carga. Duerme SEG segundos antes de volver a comprobar la carga.
-v
Verbosidad. Imprime mensajes informativos sobre lo que está sucediendo. Esto es útil para depurar.
-h
--help
Muestra un mensaje de ayuda y sal.

EJEMPLOS

Para ejecutar gzip con prioridad baja si la carga es superior a 2.0:

        $ niceload -L 2.0 gzip file.tar

Para detener temporalmente el proceso con PID 1234 si la memoria libre cae por debajo de 100MB:

        $ niceload -M 100M -p 1234 --memlimit 100M

Para suspender el proceso con PID 1234 durante 10 segundos si la carga supera los 4.0, y no iniciar hasta que la carga esté por debajo de 1.0:

        $ niceload -s 10 -L 4.0 --sl 1.0 -p 1234

Para reducir la velocidad de todos los procesos de firefox si el uso de E/S de disco es alto (superior a 7), suspendiendo durante 5 segundos cada vez:

        $ niceload -s 5 --prg firefox -I 7

Para suspender los procesos que consumen mucha CPU cuando el sistema está funcionando con batería:

        $ niceload --battery -n -10 --prg bash /path/to/heavy_cpu_script.sh

niceload(1) — Arch Linux

NAME

niceload - runs a command with a ceiling on the load average.

SYNOPSIS

niceload [-L loadlimit] [-f factor] [-q] [-v] [-h] [-V] command [arguments]

niceload [-L loadlimit] [-f factor] [-q] [-v] [-h] [-V] [--run-mem memory] command [arguments]

DESCRIPTION

niceload runs a command, but throttles it if the system load average exceeds a certain limit. This is useful for running commands that might otherwise starve the system for CPU or I/O, such as updatedb or rsync.

The load limit is checked every second by default. If the load average is above the limit, the process is suspended until the load average drops below the limit. The suspending is done by sending SIGSTOP and SIGCONT signals to the process. The frequency of checks can be controlled by the -f option.

The load average is the average number of processes in the run queue (running or waiting to run) over the last 1, 5, and 15 minutes. niceload uses the 1 minute load average by default.

If the --run-mem option is used, niceload will also attempt to ensure that there is enough memory available for disk caching. It does this by suspending the command if the available memory drops below the specified limit.

OPTIONS

-L loadlimit
Set the maximum load average. Default is 1.0. If the load average is higher than this value, the process is suspended. The load average is checked every second. This value refers to the 1 minute load average.
-f factor
Set the sleep factor. When the load average is above the limit, the process is suspended for factor seconds. Default is 1.0 second.
-q
Quiet mode. Suppress informational messages about suspending and resuming the process.
-v
Verbose mode. Print extra information about what is happening. Use -v until you know what you are doing.
-h
Print a help message and exit.
-V
Print version information and exit.
--hard
This option is ignored.
--run-mem memory
Ensure that at least memory is available for disk cache. memory can be specified in bytes or with a suffix like K, M, or G (e.g., 100M, 2G). If the available memory drops below this limit, the command is suspended. The check is performed every second.

If no command is specified, niceload reads commands from standard input.

EXAMPLE: See niceload in action

In terminal 1 run: top

In terminal 2 run:

niceload -q perl -e '$|=1;do{$l==$r or print "."; $l=$r}until(($r=time-$^T)>50)'

This will print a '.' every second for 50 seconds and consume a lot of CPU. When the load rises to 1.0, the process is suspended.

EXAMPLE: Run updatedb

Running updatedb can often starve the system for disk I/O and thus result in a high load.

Run updatedb but suspend updatedb if the load is above 2.00:

niceload -L 2 updatedb

EXAMPLE: Run rsync

rsync can, just like updatedb, starve the system for disk I/O and thus result in a high load.

Run rsync but keep load below 3.4. If load reaches 7 sleep for (7-3.4)*12 seconds:

niceload -L 3.4 -f 12 rsync -Ha /home/ /backup/home/

EXAMPLE: Ensure enough disk cache

Assume the program foo uses 2 GB files intensively. foo will run fast if the files are in disk cache and be slow as a crawl if they are not in the cache.

To ensure 2 GB are reserved for disk cache run:

niceload --hard --run-mem 2g foo

This will not guarantee that the 2 GB memory will be used for the files for foo, but it will stop foo if the memory for disk cache is too low.

ENVIRONMENT VARIABLES

None. In future versions $NICELOAD will be able to contain default settings.

EXIT STATUS

Exit status should be the same as the command being run (untested).
