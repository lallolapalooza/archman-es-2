nix3-env-shell(1)

Paquete: nix

Licencias: LGPL-2.1-only

nix3-env-shell(1) Manual de Comandos Generales nix3-env-shell(1)

Advertencia
Este programa es experimental y su interfaz está sujeta a cambios.

Nombre

nix env shell - ejecutar un shell en el que los paquetes especificados estén disponibles

Sintaxis

nix env shell [opción…] instalables…

Ejemplos

•
Iniciar un shell que proporcione youtube-dl desde el flake de nixpkgs:
# nix shell nixpkgs#youtube-dl
# youtube-dl --version
2020.11.01.1
•
Iniciar un shell que proporcione GNU Hello de NixOS 20.03:
# nix shell nixpkgs/nixos-20.03#hello
•
Ejecutar GNU Hello:
# nix shell nixpkgs#hello --command hello --greeting 'Hi everybody!'
Hi everybody!
•
Ejecutar múltiples comandos en un entorno de shell:
# nix shell nixpkgs#gnumake --command sh -c "cd src && make"
•
Ejecutar GNU Hello en un almacén chroot:
# nix shell --store ~/my-nix nixpkgs#hello --command hello
•
Iniciar un shell que proporcione GNU Hello en un almacén chroot:
# nix shell --store ~/my-nix nixpkgs#hello nixpkgs#bashInteractive --command bash
Tenga en cuenta que es necesario especificar bash explícitamente porque su shell predeterminado (por ejemplo, /bin/bash) generalmente no existirá en el chroot.

Descripción

nix shell ejecuta un comando en un entorno en el que la variable $PATH proporciona los instalables especificados. Si no se especifica ningún comando, inicia el shell predeterminado de su cuenta de usuario especificado por $SHELL.

Uso como intérprete #!

Puede usar nix como intérprete de scripts para permitir que los scripts escritos en lenguajes arbitrarios obtengan sus propias dependencias a través de Nix. Esto se hace iniciando el script con las siguientes líneas:

#! /usr/bin/env nix
#! nix shell installables --command real-interpreter

donde real-interpreter es el intérprete de script “real” que será invocado por nix shell después de que haya obtenido las dependencias y inicializado el entorno, y instalables son los nombres de atributos de las dependencias en Nixpkgs.

Las líneas que comienzan con #! nix especifican opciones (ver arriba). Tenga en cuenta que no puede escribir #! /usr/bin/env nix shell -i ... porque muchos sistemas operativos solo permiten un argumento en las líneas #!.

Por ejemplo, aquí hay un script de Python que depende de Python y del paquete prettytable:

#! /usr/bin/env nix
#! nix shell github:tomberek/-#python3With.prettytable --command python
import prettytable
# Imprime una tabla simple.
t = prettytable.PrettyTable(["N", "N^2"])
for n in range(1, 10): t.add_row([n, n * n])
print t

De manera similar, lo siguiente es un script de Perl que especifica que requiere Perl y los paquetes HTML::TokeParser::Simple y LWP:

#! /usr/bin/env nix
#! nix shell github:tomberek/-#perlWith.HTMLTokeParserSimple.LWP --command perl -x
use HTML::TokeParser::Simple;
# Recupera nixos.org e imprime todos los href.
my $p = HTML::TokeParser::Simple->new(url => 'http://nixos.org/');
while (my $token = $p->get_tag("a")) {
    my $href = $token->get_attr("href");
    print "$href\n" if $href;
}

A veces necesita pasar una expresión Nix simple para personalizar un paquete como Terraform:

#! /usr/bin/env nix
#! nix shell --impure --expr ``
#! nix with (import (builtins.getFlake ''nixpkgs'') {});
#! nix terraform.withPlugins (plugins: [ plugins.openstack ])
#! nix ``
#! nix --command bash
terraform "$@"

Nota

Debe usar comillas invertidas dobles (``) al pasar una expresión Nix simple en un shebang de nix shell.

Finalmente, utilizando la fusión de múltiples shebangs de nix shell, el siguiente script Haskell utiliza una rama específica de Nixpkgs/NixOS (la rama estable 21.11):

#!/usr/bin/env nix
#!nix shell --override-input nixpkgs github:NixOS/nixpkgs/nixos-21.11
#!nix github:tomberek/-#haskellWith.download-curl.tagsoup --command runghc
import Network.Curl.Download
import Text.HTML.TagSoup
import Data.Either
import Data.ByteString.Char8 (unpack)
-- Recupera nixos.org e imprime todos los href.
main = do
  resp <- openURI "https://nixos.org/"
  let tags = filter (isTagOpenName "a") $ parseTags $ unpack $ fromRight undefined resp
  let tags' = map (fromAttrib "href") tags
  mapM_ putStrLn $ filter (/= "") tags'

Si desea ser aún más preciso, puede especificar una revisión específica de Nixpkgs:

#!nix shell --override-input nixpkgs github:NixOS/nixpkgs/eabc38219184cc3e04a974fe31857d8e0eac098d

También puede utilizar una expresión Nix para construir sus propias dependencias. Por ejemplo, el ejemplo de Python podría haberse escrito como:

#! /usr/bin/env nix
#! nix shell --impure --file deps.nix -i python

donde el archivo deps.nix en el mismo directorio que el script #! contiene:

with import <nixpkgs> {};
python3.withPackages (ps: with ps; [ prettytable ])

Opciones

•
--command / -c comando args
Comando y argumentos a ejecutar, por defecto es $SHELL
•
--ignore-environment / -i
Borra todo el entorno (excepto los especificados con --keep).
•
--keep / -k nombre
Conserva la variable de entorno nombre.
•
--stdin
Lee instalables de la entrada estándar. No se aplica ningún instalable predeterminado.
•
--unset / -u nombre
Anula la variable de entorno nombre.

Opciones comunes de evaluación

•
--arg nombre expr
Pasa el valor expr como el argumento nombre a las funciones de Nix.
•
--arg-from-file nombre ruta
Pasa el contenido del archivo ruta como el argumento nombre a las funciones de Nix.
•
--arg-from-stdin nombre
Pasa el contenido de stdin como el argumento nombre a las funciones de Nix.
•
--argstr nombre cadena
Pasa la cadena cadena como el argumento nombre a las funciones de Nix.

OPTIONS

Command-line flags for the nix command. This is not the complete list of options; run nix --help for a list of all options.

Most options can also be set in the Nix configuration file nix.conf.

Common options

•
--debugger
Start an interactive environment if evaluation fails.
•
--eval-store store-url
The URL of the Nix store to use for evaluation, i.e. to store derivations (.drv files) and inputs referenced by them.
•
--impure
Allow access to mutable paths and repositories.
•
--include / -I path
Add path to search path entries used to resolve lookup paths
This option may be given multiple times.
Paths added through -I take precedence over the nix-path configuration setting and the NIX_PATH environment variable.
•
--override-flake original-ref resolved-ref
Override the flake registries, redirecting original-ref to resolved-ref.

Common flake-related options

•
--commit-lock-file
Commit changes to the flake’s lock file.
•
--inputs-from flake-url
Use the inputs of the specified flake as registry entries.
•
--no-registries
Don’t allow lookups in the flake registries.
DEPRECATED
Use --no-use-registries instead.
•
--no-update-lock-file
Do not allow any updates to the flake’s lock file.
•
--no-write-lock-file
Do not write the flake’s newly generated lock file.
•
--output-lock-file flake-lock-path
Write the given lock file instead of flake.lock within the top-level flake.
•
--override-input input-path flake-url
Override a specific flake input (e.g. dwarffs/nixpkgs). This implies --no-write-lock-file.
•
--recreate-lock-file
Recreate the flake’s lock file from scratch.
DEPRECATED
Use nix flake update instead.
•
--reference-lock-file flake-lock-path
Read the given lock file instead of flake.lock within the top-level flake.
•
--update-input input-path
Update a specific flake input (ignoring its previous entry in the lock file).
DEPRECATED
Use nix flake update instead.

Logging-related options

•
--debug
Set the logging verbosity level to ‘debug’.
•
--log-format format
Set the format of log output; one of raw, internal-json, bar or bar-with-logs.
•
--print-build-logs / -L
Print full build logs on standard error.
•
--quiet
Decrease the logging verbosity level.
•
--verbose / -v
Increase the logging verbosity level.

Miscellaneous global options

•
--help
Show usage information.
•
--offline
Disable substituters and consider all previously downloaded files up-to-date.
•
--option name value
Set the Nix configuration setting name to value (overriding nix.conf).
•
--refresh
Consider all previously downloaded files out-of-date.
•
--repair
During evaluation, rewrite missing or corrupted files in the Nix store. During building, rebuild missing or corrupted store paths.
•
--version
Show version information.

Options that change the interpretation of installables

•
--expr expr
Interpret installables as attribute paths relative to the Nix expression expr.
•
--file / -f file
Interpret installables as attribute paths relative to the Nix expression stored in file. If file is the character -, then a Nix expression will be read from standard input. Implies --impure.

nix3-env-shell(1)

NAME

nix-env, nix-shell - Make an environment available in which you can run arbitrary commands.

SYNOPSIS

nix-env [-q] [-qa pattern] [-i|--install] [-iA ...] [-e|--uninstall] [-p path] [-f file] [--attr attr] [--drv-path] [--out-link name] [--graph] [--json] [--option name value] [--flake url] [--impure] [--pure] [--profile profile] [--set] [--set-flag flag value] [--split-root] [--switch] [--test-result] [--unset] [--unset-flag flag] [--usage] [--version] [paths ...]

nix-shell [options] [--args args] [--attr attr] [--command command] [--drv-path] [--failure-handled] [--file file] [--graph] [--impure] [--log-build-output] [--master-lock] [--no-build-output] [--option name value] [--out-link name] [--package package] [--pure] [--quiet] [--realise] [--show-trace] [--substitutes url] [--test-result] [--usage] [--version] [paths ...]

DESCRIPTION

This manual page describes the `nix-env` and `nix-shell` commands. They are used to build and manage sets of packages, and to enter a shell environment where those packages are available.

`nix-env` is primarily used to install, uninstall, and manage packages in a user's profile. It allows users to install Nix packages without needing root privileges.

`nix-shell` creates a development environment (a shell) where specified packages are available. This is useful for building software, running commands that depend on specific libraries or tools, or testing package environments. By default, `nix-shell` creates an interactive shell. You can also use it to execute a single command within a specific environment using the --command option.

Use as a #!-interpreter

You can use nix-shell as an interpreter for scripts. For example, a Python script could start with:

#! /nix/store/...-nix-shell/bin/nix-shell
#! nix-shell -i python3
#! nix-shell -p python3Packages.requests
#! nix-shell --pure -p nodejs
import requests
import nodejs.process

print("Hello world!")

The first line is the path to the nix-shell executable. The second line, #! nix-shell -i python3, tells nix-shell to use python3 as the interpreter. The third line, #! nix-shell -p python3Packages.requests, specifies that the requests Python package should be available in the environment. The fourth line, #! nix-shell --pure -p nodejs, uses the --pure flag to ensure a clean environment and specifies that the nodejs package should be available.

When nix-shell is invoked in this manner, it evaluates the Nix expression and then executes the script using the specified interpreter. This allows you to create self-contained scripts that have all their dependencies declared directly in the script's shebang line.

Options

nix-env and nix-shell share many options, but some are specific to each command.

-q, --query
Query the current environment. This is the default action for nix-env if no other action is specified.
-qa pattern, --query --available pattern
Query available packages matching the given pattern.
-i ARG, --install ARG
Install the specified package(s). ARG can be a package name, a path to a Nix expression, or an attribute path.
-iA attribute
Install the package specified by the attribute name in the Nixpkgs collection.
-e ARG, --uninstall ARG
Uninstall the specified package(s). ARG is usually the name of the package as it appears in the user's profile.
-p path, --profile path
Manipulate the specified profile. The default is the user's current profile.
-f file, --file file
Use the Nix expression in file as the source for packages or environments. This can be a path to a file or a URL.
--attr attr
Select an attribute attr from the Nix expression. Used with -f or when specifying a flake.
--drv-path
Output the derivation path instead of the store path.
--out-link name
Create a symbolic link named name in the current directory pointing to the resulting store path.
--graph
Output a graphviz graph of the dependencies.
--json
Output results in JSON format.
--option name value
Set a Nix configuration option.
--flake url
Specify a flake URL (e.g., github:owner/repo or git+file:///path/to/repo).
--impure
Allow the shell environment to be impure (e.g., have access to $PATH from the parent environment). This is the default for nix-shell unless --pure is specified.
--pure
Ensure the shell environment is pure. This means it has minimal access to the outside environment (e.g., no access to $PATH).
--profile profile
Specify the profile to operate on. Defaults to the user's current profile.
--set
Set the specified package(s) in the profile, replacing any existing packages.
--set-flag flag value
Set a specific flag for a package in the profile.
--split-root
Split the Nix store into multiple roots.
--switch
Atomically switch the profile to the new set of packages.
--test-result
Output test results.
--unset
Remove the specified package(s) from the profile.
--unset-flag flag
Unset a specific flag for a package in the profile.
--usage
Print usage information and exit.
--version
Print the Nix version and exit.
--args args
(nix-shell specific) Pass arguments to the shell script.
--command command
(nix-shell specific) Execute a single command within the environment and then exit.
--failure-handled
(nix-shell specific) Indicate that build failures should be handled gracefully.
--log-build-output
(nix-shell specific) Log the build output.
--master-lock
(nix-shell specific) Use a master lock file.
--no-build-output
(nix-shell specific) Do not show build output.
--package package
(nix-shell specific) Specifies a package to make available in the shell. Equivalent to -p.
--realise
(nix-shell specific) Realise the specified paths.
--show-trace
(nix-shell specific) Show the Nix evaluation trace.
--substitutes url
(nix-shell specific) Specify a substitute server URL.
