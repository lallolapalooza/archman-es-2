nix3-derivation-show(1) Manual de Comandos Generales nix3-derivation-show(1)

Advertencia
Este programa es experimental y su interfaz está sujeto a cambios.

Nombre

nix derivation show - muestra el contenido de una derivación del store

Sinopsis

nix derivation show [opción…] instalables…

Ejemplos

•
Muestra la derivación del store que resulta de evaluar el paquete Hello:
# nix derivation show nixpkgs#hello
{
"/nix/store/s6rn4jz1sin56rf4qj5b5v8jxjm32hlk-hello-2.10.drv": {
  …
}
}
•
Muestra el grafo de derivación completo (si está disponible) que produjo tu sistema NixOS:
# nix derivation show -r /run/current-system
•
Imprime todos los archivos obtenidos usando fetchurl por el grafo de dependencias de Firefox:
# nix derivation show -r nixpkgs#firefox \
| jq -r '.[] | select(.outputs.out.hash and .env.urls) | .env.urls' \
| uniq | sort
Nota que .outputs.out.hash selecciona derivaciones de salida fija (derivaciones que producen salida con un hash de contenido especificado), mientras que .env.urls selecciona derivaciones con un atributo urls.

Descripción

Este comando imprime en la salida estándar una representación JSON de las derivaciones del store a las que se evalúan instalables.

Las derivaciones del store son usadas internamente por Nix. Son rutas del store con la extensión .drv que representan el grafo de dependencias en tiempo de compilación al que se evalúa una expresión Nix.

Por defecto, este comando solo muestra derivaciones de nivel superior, pero con --recursive, también muestra sus dependencias.

Opciones

•
--recursive / -r
Incluye las dependencias de las derivaciones especificadas.
•
--stdin
Lee instalables desde la entrada estándar. No se aplica ningún instalable predeterminado.

Opciones comunes de evaluación

•
--arg nombre expr
Pasa el valor expr como argumento nombre a funciones Nix.
•
--arg-from-file nombre ruta
Pasa el contenido del archivo ruta como argumento nombre a funciones Nix.
•
--arg-from-stdin nombre
Pasa el contenido de stdin como argumento nombre a funciones Nix.
•
--argstr nombre cadena
Pasa la cadena cadena como argumento nombre a funciones Nix.
•
--debugger
Inicia un entorno interactivo si la evaluación falla.
•
--eval-store url-del-store
La URL del store Nix a usar para la evaluación, es decir, para almacenar derivaciones (.drv files) y las entradas referenciadas por ellas.
•
--impure
Permite el acceso a rutas y repositorios mutables.
•
--include / -I ruta
Añade ruta a las entradas de la ruta de búsqueda usadas para resolver rutas de búsqueda
Esta opción se puede dar varias veces.
Las rutas añadidas a través de -I tienen precedencia sobre el ajuste de configuración nix-path y la variable de entorno NIX_PATH.
•
--override-flake ref-original ref-resuelto
Anula los registros de flake, redirigiendo ref-original a ref-resuelto.

Opciones comunes relacionadas con flakes

•
--commit-lock-file
Confirma los cambios en el archivo lock del flake.
•
--inputs-from url-del-flake
Usa las entradas del flake especificado como entradas de registro.
•
--no-registries
No permite búsquedas en los registros de flakes.
OBSOLETO
Usa --no-use-registries en su lugar.
•
--no-update-lock-file
No permite ninguna actualización del archivo lock del flake.
•
--no-write-lock-file
No escribe el archivo lock recién generado del flake.
•
--output-lock-file ruta-del-archivo-lock-del-flake
Escribe el archivo lock dado en lugar de flake.lock dentro del flake de nivel superior.
•
--override-input ruta-de-entrada url-del-flake
Anula una entrada de flake específica (por ejemplo, dwarffs/nixpkgs). Esto implica --no-write-lock-file.
•
--recreate-lock-file
Recrea el archivo lock del flake desde cero.

DESCRIPTION

The Nix store is the directory (usually /nix/store) where Nix stores all the packages and other build products. The nix-store utility provides low-level operations on the Nix store.

It is mostly intended for use by other Nix commands, but can be useful for diagnostics and low-level store manipulation.

The following operations are supported:

--query (or -q) path...

Query the Nix store for information about the given store paths. This includes the output hash, the derivation that produced it, and its references.

--verify [--repair] [path...]

Verify the integrity of the contents of the Nix store. If --repair is given, Nix will attempt to re-download any corrupted or missing paths. If no paths are specified, the entire store is verified.

--optimise

Remove redundant paths from the Nix store. This is similar to running nix-collect-garbage but without deleting unreferenced paths.

--delete path...

Delete the given store paths from the Nix store. Note that this is a dangerous operation and should only be performed on paths that are no longer needed and are not referenced by any other paths or GC roots.

--register [--read-only] real-name output-path output-hash file...

Register a new path in the Nix store. real-name is the desired name for the path in the store (e.g. /nix/store/<hash>-<name>). output-path is the desired output path. output-hash is the hash of the output. file... are the actual files to be added to the store. If --read-only is specified, the resulting store path will be read-only.

--load-derivation file

Load a derivation from the given file. This is typically used by Nix itself to load derivations from the Nix store.

--build-stream [--json] file

Build a derivation from the given file and stream the output to standard output. If --json is specified, the output will be in JSON format.

--realise [-r] [derivation...]

Realize the given derivations. This means building them if they are not already in the store. This is similar to running nix-build.

--export-derivation path

Export the derivation that produced the given store path to standard output.

--diff-closures path1 path2

Compute the difference between the closure of path1 and path2.

--hash path

Compute the hash of the given store path.

--roots

List all garbage collection roots.

--references path...

List all direct references of the given store paths.

--requisites path...

List all references (direct and indirect) of the given store paths.

--gc [--delete-old] [--check-content]

Run the garbage collector. This will remove all store paths that are not referenced by any garbage collection root. If --delete-old is specified, it will also delete old generations that are no longer referenced. If --check-content is specified, it will check the content of all paths before deleting them.

--drop path

Drop the given store path from the list of garbage collection roots. This means that the path will be considered for garbage collection.

--add-root path name

Add the given store path to the list of garbage collection roots under the name name.

--remove-root name

Remove the garbage collection root named name.

--rollback generations

Roll back to the previous generations. This is typically used to undo recent system upgrades.

--query-build-limit

Query the maximum number of concurrent builds.

--set-build-limit limit

Set the maximum number of concurrent builds to limit.

--query-valid-until path

Query the validity date of the given store path.

--set-valid-until path date

Set the validity date of the given store path to date. The date format is YYYY-MM-DD.

--query-validity path

Query the validity of the given store path.

--query-path-info path

Query information about the given store path, including its size, references, and derivation.

--query-path-from-hash hash

Query the store path corresponding to the given hash.

--query-valid-generations

List all valid generations in the Nix store.

--query-path path

Query the store path corresponding to the given path. This is primarily used to canonicalize store paths.

--query-substitutes path...

List all known substitutes for the given store paths.

--query-required path...

List all paths required by the given store paths.

--query-unkown-references path...

List all unknown references of the given store paths.

--query-needed-by path...

List all paths that require the given store paths.

--query-grep pattern

Find store paths matching the given pattern.

--query-whiteouts path...

List all whiteouts in the given store paths.

--query-available-outputs path

List all available outputs for the given store path.

--query-out-of-date

List all store paths that are out of date.

--query-builds

--query-invalid

--read-log path

Read the build log for the given store path.

--cat-log path

Print the build log for the given store path to standard output.

Start a Nix store server. This server can be used by other Nix daemons to access the Nix store remotely. The server will listen on the given port or file descriptor. If --max-silent-time is specified, the server will shut down after seconds of inactivity.

--file / -f file
Interpret installables as attribute paths relative to the Nix expression stored in file. If file is the character -, then a Nix expression will be read from standard input. Implies --impure.

Note

See man nix.conf for overriding configuration settings with command line flags.
