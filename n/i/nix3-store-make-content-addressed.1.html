nix3-store-make-content-addressed(1) General Commands Manual nix3-store-make-content-addressed(1)

Advertencia
Este programa es experimental y su interfaz está sujeto a cambios.

Nombre

nix store make-content-addressed - reescribe una ruta o cierre a formato direccionado por contenido

Sinopsis

nix store make-content-addressed [opción…] instalables…

Ejemplos

•
Crea una representación direccionada por contenido del cierre de GNU Hello:
# nix store make-content-addressed nixpkgs#hello
…
reescrito '/nix/store/v5sv61sszx301i0x6xysaqzla09nksnd-hello-2.10' a '/nix/store/5skmmcb9svys5lj3kbsrjg7vf2irid63-hello-2.10'
Dado que las rutas resultantes están direccionadas por contenido, siempre son de confianza y no necesitan firmas para ser copiadas a otra tienda:
# nix copy --to /tmp/nix --trusted-public-keys '' /nix/store/5skmmcb9svys5lj3kbsrjg7vf2irid63-hello-2.10
Por el contrario, el cierre original está direccionado por entrada, por lo que necesita firmas para ser de confianza:
# nix copy --to /tmp/nix --trusted-public-keys '' nixpkgs#hello
no se puede añadir la ruta '/nix/store/zy9wbxwcygrwnh8n2w9qbbcr6zk87m26-libunistring-0.9.10' porque carece de firma por una clave de confianza
•
Crea una representación direccionada por contenido del cierre del sistema NixOS actual:
# nix store make-content-addressed /run/current-system

Descripción

Este comando convierte el cierre de las rutas de la tienda especificadas por los instalables a formato direccionado por contenido.

Las rutas de la tienda Nix suelen estar direccionadas por entrada, lo que significa que la parte hash de la ruta de la tienda se calcula a partir del contenido de la derivación (es decir, el grafo de dependencias en tiempo de compilación). Las rutas direccionadas por entrada necesitan ser firmadas por una clave de confianza si se desea importarlas a una tienda, porque necesitamos confiar en que el contenido de la ruta fue realmente construido por la derivación.

Por el contrario, en una ruta direccionada por contenido, la parte hash se calcula a partir del contenido de la ruta. Esto permite verificar el contenido de la ruta sin información adicional como firmas. Esto significa que un comando como

# nix store build /nix/store/5skmmcb9svys5lj3kbsrjg7vf2irid63-hello-2.10 \
    --substituters https://my-cache.example.org

se realizará correctamente incluso si la caché binaria https://my-cache.example.org no presenta ninguna firma.

Examples

Evaluate and build the default package set from the Nixpkgs flake:

$ nix build nixpkgs

Build a specific package from Nixpkgs:

$ nix build nixpkgs#hello

Enter a shell with the development environment of a flake:

$ nix develop

Enter a shell with the development environment of a specific flake package:

$ nix develop nixpkgs#legacyPackages.x86_64-linux.my-custom-package

Run a command in an environment defined by a flake:

$ nix run nixpkgs#cowsay -- hello world

Show information about a flake output:

$ nix show-derivation nixpkgs#hello

Evaluate an expression from a Nix file and print its result:

$ nix eval --expr 'with import ./my-nixpkgs {}; hello'

Evaluate an expression relative to a specific flake input:

$ nix eval --expr 'pkgs.hello' --input-flake nixpkgs=github:NixOS/nixpkgs/nixos-unstable

Get the derivation of a Nix store path:

$ nix derivation /nix/store/....-hello-2.10

Get the output path of a derivation:

$ nix output-path /nix/store/....-hello-2.10

Run a command in an environment specified by a Nix file:

$ nix run -f my-app.nix

Run a command in an environment specified by a Nix expression from stdin:

$ echo 'with import <nixpkgs> {}; runCommand "x" {} "touch $out"' | nix run -f -

Instantiate a flake, without building anything:

$ nix build --no-link nixpkgs

Build a flake, but don't write to the lock file:

$ nix build --no-write-lock-file nixpkgs

Build a flake, overriding one of its inputs:

$ nix build --override-input nixpkgs=https://github.com/NixOS/nixpkgs/archive/7c3d2e0e.tar.gz nixpkgs

Build a flake, but use a different lock file:

$ nix build --reference-lock-file my-other-flake.lock nixpkgs

Build a flake, updating a specific input (and writing the result to the lock file):

$ nix build --update-input nixpkgs nixpkgs

Recreate the lock file from scratch:

$ nix flake lock --flake .

Description

The Nix command-line tool is the primary interface for interacting with the Nix package manager. It supports a wide range of subcommands and options for managing packages, evaluating expressions, and working with flakes.

The fundamental concept in Nix is the Nix store, a directory (usually /nix/store) where all packages and build products are stored. Each store path is identified by a cryptographic hash of its contents and build instructions, guaranteeing that packages are immutable and reproducible.

Flakes are a newer, experimental feature that provides a standard way to organize Nix code and manage dependencies. They consist of a flake.nix file defining inputs and outputs, and a flake.lock file pinning the exact versions of inputs.

The command-line tool can operate on installables, which are references to packages or Nix expressions. These can be flake references (like nixpkgs#hello), paths to Nix files (like ./my-package.nix), or attribute paths within a Nix expression (like { pkgs ? import <nixpkgs> {} }: pkgs.hello).

Flake-related options

•
--accept-flake-config
Accept the flake configuration and don't ask for confirmation.
•
--accept-flake-unsafe-access
Allow flakes to access the Nix store, user directories, or network resources.
•
--flake flake-url
Evaluate the flake at the given URL.
•
--impure
Allow access to the Nix store, user directories, or network resources.
•
--input-flake name=flake-url
Override or add a flake input during evaluation.
•
--no-link
Do not create symbolic links to the outputs of the specified store paths.
•
--no-write-lock-file
Do not write to the flake lock file. This implies --no-input- Tersus.
•
--override-input input-path flake-url
Override a specific flake input (e.g. dwarffs/nixpkgs). This implies --no-write-lock-file.
•
--recreate-lock-file
Recreate the flake’s lock file from scratch.
DEPRECATED
Use nix flake update instead.
•
--reference-lock-file flake-lock-path
Read the given lock file instead of flake.lock within the top-level flake.
•
--update-input input-path
Update a specific flake input (ignoring its previous entry in the lock file).
DEPRECATED
Use nix flake update instead.
