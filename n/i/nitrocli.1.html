NITROCLI(1) Manual de Comandos Generales NITROCLI(1)

NOMBRE

nitrocli - acceder a dispositivos Nitrokey

SINOPSIS

nitrocli comando [argumentos]

DESCRIPCIÓN

nitrocli proporciona acceso a los dispositivos Nitrokey. Soporta el Nitrokey Pro, el Nitrokey Storage y el Librem Key. Se puede utilizar para acceder al volumen cifrado, al generador de contraseñas de un solo uso y a la caja de contraseñas.

Selección de dispositivo

Por defecto, nitrocli se conecta a cualquier dispositivo Nitrokey conectado. Puede utilizar las opciones --model, --serial-number y --usb-path para seleccionar el dispositivo al que conectarse. nitrocli falla si más de un dispositivo Nitrokey conectado coincide con este filtro o si hay varios dispositivos Nitrokey conectados y ninguna de las opciones de filtro está configurada. Utilice el comando list para listar todos los dispositivos conectados con su ruta USB, modelo y número de serie (si está disponible).

OPCIONES

-m, --model librem|pro|storage
Restringe las conexiones al modelo de dispositivo dado, véase la sección Selección de dispositivo.
--serial-number número-de-serie
Restringe las conexiones al número de serie dado, véase la sección Selección de dispositivo. número-de-serie debe ser una cadena hexadecimal con un prefijo opcional 0x. Esta opción puede establecerse varias veces para permitir cualquiera de los números de serie dados. Los dispositivos Nitrokey Storage nunca coinciden con esta restricción ya que no exponen su número de serie en el descriptor del dispositivo USB.
--usb-path ruta-usb
Restringe las conexiones a la ruta USB dada, véase la sección Selección de dispositivo.
--no-cache
Si esta opción está configurada, nitrocli no almacenará en caché ningún secreto consultado utilizando gpg-agent(1), sino que los solicitará cada vez que sean necesarios. Tenga en cuenta que esta opción no causa que se borren los secretos cacheados. Si un secreto ya está en la caché, se ignorará, pero por lo demás permanecerá intacto. Utilice el comando pin clear para borrar los secretos de la caché.
-v, --verbose
Habilita el registro adicional y controla su verbosidad. El registro habilitado a través de esta opción aparecerá en el flujo de error estándar. Esta opción puede proporcionarse varias veces. Una única aparición mostrará advertencias adicionales. Los comandos enviados al dispositivo se mostrarán cuando se proporcione tres veces y la comunicación completa del dispositivo estará disponible con cuatro apariciones. Proporcionar esta opción cinco veces habilita la máxima verbosidad.
-V, --version
Imprime la versión de nitrocli y sale.

COMANDOS

General

nitrocli list [-n|--no-connect]
Lista todos los dispositivos Nitrokey conectados. Este comando imprime una lista de la ruta USB, el modelo y el número de serie de todos los dispositivos Nitrokey conectados. Para acceder al número de serie de un dispositivo Nitrokey Storage, nitrocli tiene que conectarse a él. Para omitir el número de serie de los dispositivos Nitrokey Storage en lugar de conectarse a ellos, configure la opción --no-connect.
nitrocli status
Imprime el estado del dispositivo Nitrokey conectado, incluyendo el número de serie del stick, la versión del firmware y el contador de reintentos del PIN. Si el dispositivo es un Nitrokey Storage, también imprime información relacionada con el almacenamiento, incluyendo el número de serie de la tarjeta SD, el uso de la tarjeta SD durante este ciclo de alimentación, el estado de cifrado y el estado de los volúmenes.
nitrocli lock
Bloquea el Nitrokey. Este comando bloquea la caja de contraseñas (véase la sección Caja de contraseñas). En el Nitrokey Storage, también cerrará cualquier volumen cifrado o oculto activo (véase la sección Almacenamiento).
nitrocli reset [--only-aes-key]
Realiza un restablecimiento de fábrica en el Nitrokey. Este comando realiza un restablecimiento de fábrica en la tarjeta inteligente OpenPGP, borra el almacenamiento flash y crea una nueva clave AES. El PIN de usuario se restablece a 123456, el PIN de administrador a 12345678.

Si la opción --only-aes-key está configurada, el comando no realiza un restablecimiento de fábrica completo, sino que solo crea una nueva clave AES. La clave AES se utiliza, por ejemplo, para cifrar la caja de contraseñas.

Este comando requiere el PIN de administrador. Para evitar llamadas accidentales a este comando, el usuario debe introducir el PIN aunque haya sido cacheado.

Almacenamiento

El Nitrokey Storage viene con un área de almacenamiento. Esta área se compone de una región *no cifrada* y una *cifrada* de tamaños fijos, cada una disponible para el usuario en forma de dispositivos de bloque. La región cifrada puede opcionalmente superponerse con hasta cuatro volúmenes *ocultos*. Debido a esta superposición (que es necesaria para garantizar la plausibilidad de la negación de la existencia de volúmenes ocultos), la responsabilidad de asegurar que los datos en el volumen cifrado no se solapen con los datos de uno de los volúmenes ocultos recae en el usuario.

nitrocli unencrypted set modo
Cambia el modo de lectura/escritura del volumen. modo es el tipo de modo a cambiar: read-write para hacer el volumen legible y escribible o read-only para hacerlo solo legible. Este comando requiere el PIN de administrador.

Tenga en cuenta que este comando requiere la versión de firmware 0.51 o superior. Las versiones anteriores no son compatibles.

nitrocli encrypted open
Abre el volumen cifrado en el Nitrokey Storage. El PIN de usuario que se requiere para abrir el volumen se consulta utilizando pinentry(1) y se almacena en caché por gpg-agent(1).
nitrocli encrypted close
Cierra el volumen cifrado en el Nitrokey Storage.
nitrocli hidden create ranura inicio fin
Crea un nuevo volumen oculto dentro del volumen cifrado. ranura debe indicar una de las cuatro ranuras disponibles. inicio y fin representan, respectivamente, la posición de inicio y fin del volumen oculto dentro del volumen cifrado, como un porcentaje del tamaño del volumen cifrado. Este comando requiere una contraseña que se utilizará posteriormente para buscar el volumen oculto a abrir. A diferencia de un PIN, esta contraseña no se almacena en caché por gpg-agent(1).

Como guía para crear nuevos volúmenes ocultos, el comando status proporciona un rango de la tarjeta SD que no ha sido escrito durante este ciclo de alimentación.

nitrocli hidden open
Abre un volumen oculto. El volumen a abrir se determina en función de la contraseña introducida, que debe tener un mínimo de seis caracteres. Solo un volumen oculto puede estar activo en cualquier momento y los volúmenes abiertos previamente se cerrarán automáticamente. De manera similar, el volumen cifrado se cerrará si estaba abierto.
nitrocli hidden close
Cierra un volumen oculto.
nitrocli fill [-a|--attach
Llena la tarjeta SD con datos aleatorios, sobrescribiendo todos los datos existentes. Esta operación tarda aproximadamente una hora en finalizar para una tarjeta SD de 16 GiB. No se puede cancelar, incluso si el proceso nitrocli se termina antes de que finalice.

Este comando requiere el PIN de administrador. Para evitar llamadas accidentales a este comando, el usuario debe introducir el PIN aunque haya sido cacheado.

Si la opción --attach está configurada, este comando no iniciará una nueva operación de llenado. En su lugar, comprueba si hay una operación de llenado en curso

Contraseñas de un solo uso

El Nitrokey Pro, el Nitrokey Storage y el Librem Key soportan la generación de contraseñas de un solo uso utilizando el algoritmo HOTP según RFC 4226 o el algoritmo TOTP según RFC 6238. Los datos requeridos –un nombre y el secreto– se almacenan en ranuras. Actualmente, los dispositivos Nitrokey proporcionan tres ranuras HOTP y 15 ranuras TOTP. Las ranuras se numeran por algoritmo empezando desde cero.

El algoritmo TOTP es una versión modificada del algoritmo HOTP que también utiliza la hora actual. Por lo tanto, el reloj del Nitrokey debe sincronizarse con el reloj de la aplicación que solicita la contraseña de un solo uso.

nitrocli otp get ranura [-a|--algorithm algoritmo] [-t|--time hora]
Generar una contraseña de un solo uso. ranura es el número de la ranura desde la que generar la contraseña. algoritmo es el algoritmo OTP a utilizar. Los valores posibles son hotp para el algoritmo HOTP según RFC 4226 y totp para el algoritmo TOTP según RFC 6238 (por defecto). Por defecto, este comando establece la hora del Nitrokey a la hora del sistema si se selecciona el algoritmo TOTP. Si se establece --time, se establece a hora en su lugar, que debe ser una marca de tiempo Unix (es decir, el número de segundos desde 1970-01-01 00:00:00 UTC). Este comando puede requerir el PIN de usuario (ver la sección Configuración).
nitrocli otp set ranura nombre secreto|- [-a|--algorithm algoritmo] [-d|--digits dígitos] [-c|--counter contador] [-t|--time-window ventana-de-tiempo] [-f|--format ascii|base32|hex]
Configurar una ranura de contraseña de un solo uso. ranura es el número de la ranura a configurar. nombre es el nombre de la ranura (no puede estar vacío). secreto es el valor secreto a almacenar en esa ranura. Si secreto se establece a -, el secreto se lee de la entrada estándar.

La opción --format especifica el formato del secreto. Si se establece a ascii, cada carácter del secreto dado se interpreta como el código ASCII de un byte. Si se establece a base32, el secreto se interpreta como una cadena base32 según RFC 4648. Si se establece a hex, cada dos caracteres se interpretan como el valor hexadecimal de un byte. El valor por defecto es base32.

algoritmo es el algoritmo OTP a utilizar. Los valores posibles son hotp para el algoritmo HOTP según RFC 4226 y totp para el algoritmo TOTP según RFC 6238 (por defecto). dígitos es el número de dígitos que debe tener la contraseña de un solo uso. Los valores permitidos son 6 y 8 (por defecto: 6). contador es el contador inicial si se utiliza el algoritmo HOTP (por defecto: 0). ventana-de-tiempo es la ventana de tiempo utilizada con TOTP en segundos (por defecto: 30).

nitrocli otp clear ranura [-a|--algorithm algoritmo]
Eliminar el nombre y el secreto almacenados en una ranura de contraseña de un solo uso. ranura es el número de la ranura a borrar. algoritmo es el algoritmo OTP a utilizar. Los valores posibles son hotp para el algoritmo HOTP según RFC 4226 y totp para el algoritmo TOTP según RFC 6238 (por defecto).
nitrocli otp status [-a|--all]
Listar todas las ranuras OTP. Si --all no está establecido, las ranuras vacías se ignoran.

Configuración

Los dispositivos Nitrokey tienen cuatro configuraciones: las teclas Bloq Num, Bloq Mayús y Bloq Despl se pueden mapear a una ranura HOTP, y la generación de OTP se puede configurar para requerir el PIN de usuario.

nitrocli config get
Imprimir la configuración actual del Nitrokey.
nitrocli config set [[-n|--num-lock ranura] | [-N|--no-num-lock]] [[-c|--caps-lock ranura] | [-C|--no-caps-lock]] [[-s|--scroll-lock ranura] | [-S|--no-scroll-lock]] [[-o|--otp-pin] | [-O|--no-otp-pin]]
Actualizar la configuración del Nitrokey. Este comando requiere el PIN de administrador.

Con las opciones --num-lock, --caps-lock y --scroll-lock, se pueden establecer los enlaces respectivos. ranura es el número de la ranura HOTP a la que enlazar la tecla. Si se establece --no-num-lock, --no-caps-lock o --no-scroll-lock, el enlace respectivo se desactiva. Las dos opciones correspondientes son mutuamente excluyentes.

Si se establece --otp-pin, se requerirá el PIN de usuario para generar contraseñas de un solo uso utilizando el comando otp get. Si se establece --no-otp-pin, la generación de OTP se puede realizar sin PIN. Estas dos opciones son mutuamente excluyentes.

Caja fuerte de contraseñas

El Nitrokey Pro, el Nitrokey Storage y el Librem Key proporcionan una caja fuerte de contraseñas (PWS) con 16 ranuras. En cada una de estas ranuras se puede almacenar un nombre, un inicio de sesión y una contraseña. La PWS no está cifrada, pero está protegida con el PIN de usuario por el firmware. Una vez que la PWS se desbloquea con uno de los comandos que se enumeran a continuación, se puede acceder a ella sin autenticación. Puede usar el comando lock para bloquear la caja fuerte de contraseñas.

nitrocli pws get ranura [-n|--name] [-l|--login] [-p|--password] [-q|--quiet]
Imprimir el contenido de una ranura PWS. ranura es el número de la ranura. Por defecto, este comando imprime el nombre, el inicio de sesión y la contraseña (en ese orden). Si se establece una o más de las opciones --name, --login y --password, solo se imprimen los campos seleccionados. El orden de los campos nunca cambia.

Los campos se imprimen junto con una etiqueta. Utilice la opción --quiet para suprimir las etiquetas y mostrar solo los valores almacenados en la ranura PWS.

nitrocli pws add [-s|--slot ranura] nombre inicio-de-sesion contraseña|-
Añadir una nueva ranura PWS. Si se establece la opción --slot, este comando escribe los datos en la ranura dada y falla si la ranura ya está programada. Si la opción --slot no está establecida, este comando localiza la primera ranura PWS libre y establece su contenido a los valores dados. Falla si todas las ranuras PWS están programadas.

Si contraseña se establece a -, la contraseña se lee de la entrada estándar.

nitrocli pws update ranura [-n|--name nombre] [-l|--login inicio-de-sesion] [-p|--password contraseña|-]
Actualizar el contenido de una ranura PWS programada. ranura es el número de la ranura a escribir. Este comando solo establece los datos proporcionados con las opciones --name, --login y --password y no sobrescribe los otros campos de la ranura.

Si contraseña se establece a -, la contraseña se lee de la entrada estándar.

nitrocli pws clear ranura
Eliminar los datos almacenados en una ranura PWS. ranura es el número de la ranura a borrar.
nitrocli pws status [-a|--all]
Listar todas las ranuras PWS. Si --all no está establecido, las ranuras vacías se ignoran.

PINs

Los dispositivos Nitrokey tienen dos PINs: el PIN de usuario y el PIN de administrador. El PIN de usuario debe tener al menos seis caracteres, y el PIN de administrador al menos ocho. El PIN de usuario se requiere para comandos como otp get (dependiendo de la configuración) y para todos los comandos pws. El PIN de administrador se requiere generalmente para cambiar la configuración del dispositivo.

Cada PIN tiene un contador de reintentos que se decrementa con cada entrada incorrecta del PIN y se reinicia si el PIN se introduce correctamente. El contador de reintentos inicial es de tres. Si el contador de reintentos para el PIN de usuario es cero, puede usar el comando pin unblock para desbloquear y restablecer el PIN de usuario. Si el contador de reintentos para el PIN de administrador es cero, deberá realizar un restablecimiento de fábrica utilizando el comando reset o gpg(1). Utilice el comando status para verificar los contadores de reintentos.

nitrocli pin clear
Borrar los PINs cacheados por los otros comandos. Tenga en cuenta que los PINs cacheados están asociados con el dispositivo al que pertenecen y el comando clear solo borrará el PIN para el dispositivo que se está utilizando actualmente, no para todos los demás.
nitrocli pin set tipo
Cambiar un PIN. tipo es el tipo de PIN que se cambiará: admin para cambiar el PIN de administrador o user para cambiar el PIN de usuario. Este comando solo funciona si el contador de reintentos para el tipo de PIN es al menos uno. (Use el comando status para verificar los contadores de reintentos).
nitrocli pin unblock
Desbloquear y restablecer el PIN de usuario. Este comando requiere el PIN de administrador. El PIN de administrador no se puede desbloquear. Esta operación es equivalente a la opción de desbloqueo de PIN proporcionada por gpg(1) (utilizando la opción --change-pin).

Extensiones

Además de los comandos integrados anteriores, nitrocli soporta funcionalidades proporcionadas por el usuario en forma de extensiones. Una extensión puede ser cualquier archivo ejecutable cuyo nombre de archivo comience con "nitrocli-" y que sea descubrible mediante búsqueda a través de la variable de entorno PATH. Estos ejecutables pueden ser invocados como subcomandos regulares (sin necesidad del prefijo; por ejemplo, una extensión con el nombre "nitrocli-otp-cache" podría ser invocada como "nitrocli otp-cache").

Se puede encontrar más información sobre cómo escribir extensiones en la sección Extensiones más abajo.

ARCHIVO DE CONFIGURACIÓN

nitrocli intenta leer el archivo de configuración en ${XDG_CONFIG_HOME}/nitrocli/config.toml (o ${HOME}/nitrocli/config.toml si la variable de entorno XDG_CONFIG_HOME no está establecida). Se utiliza para establecer valores predeterminados para las opciones que se enumeran a continuación.

También puede establecer la variable de entorno NITROCLI_KEY para sobrescribir la configuración de key (consulte la sección Entorno). Tenga en cuenta que los argumentos de la línea de comandos sobrescriben tanto el archivo de configuración como las variables de entorno.

Los siguientes valores pueden establecerse en el archivo de configuración:

model
Restringe las conexiones al modelo de dispositivo dado (cadena, predeterminado: no establecido, consulte --model).
serial_numbers
Restringe las conexiones a los números de serie dados (lista de cadenas, predeterminado: vacía, consulte --serial-number).
usb_path
Restringe las conexiones a la ruta USB dada (cadena, predeterminado: no establecido, consulte --usb-path).
no_cache
Si se establece en true, no almacena en caché ningún secreto consultado (booleano, predeterminado: false, consulte --no-cache).
verbosity
Establece el nivel de registro (entero, predeterminado: 0, consulte --verbose).

El archivo de configuración debe utilizar el formato TOML, por ejemplo:


model = "pro"
serial_numbers = ["0xf00baa", "deadbeef"]
usb_path = "0001:0006:02"
no_cache = false
verbosity = 0

ENTORNO

El programa respeta dos conjuntos de variables de entorno, todas prefijadas con "NITROCLI_".

Configuración

El primer conjunto controla la configuración básica del programa. Estas variables reflejan las opciones de línea de comandos y la configuración del archivo de configuración correspondientes. Son:

NITROCLI_MODEL
Restringe las conexiones al modelo de dispositivo dado (cadena, predeterminado: no establecido, consulte --model).
NITROCLI_SERIAL_NUMBERS
Restringe las conexiones a la lista de números de serie dada (lista de cadenas separadas por comas, predeterminado: vacía, consulte --serial-number).
NITROCLI_USB_PATH
Restringe las conexiones a la ruta USB dada (cadena, predeterminado: no establecido, consulte --usb-path).
NITROCLI_NO_CACHE
Si se establece en true, no almacena en caché ningún secreto consultado (booleano, predeterminado: false, consulte --no-cache).
NITROCLI_VERBOSITY
Establece el nivel de registro (entero, predeterminado: 0, consulte --verbose).

Entrada de contraseña y PIN

El segundo conjunto se puede utilizar para proporcionar datos de contraseña y PIN al programa para suprimir la entrada interactiva a través de pinentry(1) para operaciones que de lo contrario la solicitarían. Se reconocen las siguientes variables:

NITROCLI_ADMIN_PIN
El PIN de administrador a utilizar.
NITROCLI_USER_PIN
El PIN de usuario a utilizar.
NITROCLI_NEW_ADMIN_PIN
El nuevo PIN de administrador a establecer. Esta variable solo es utilizada por el comando pin set para el tipo admin.
NITROCLI_NEW_USER_PIN
El nuevo PIN de usuario a establecer. Esta variable solo es utilizada por el comando pin set para el tipo user.
NITROCLI_PASSWORD
Una contraseña utilizada por comandos que requieren una (por ejemplo, hidden open).

EXTENSIONES

nitrocli admite extensiones proporcionadas por el usuario que son archivos ejecutables cuyos nombres de archivo comienzan con "nitrocli-" y que se pueden descubrir mediante la búsqueda a través de la variable de entorno PATH.

El programa transmite información básica de configuración a cualquier extensión que se inicie de esta manera. Específicamente, establecerá cada variable de entorno según lo descrito en la subsección de Configuración de la sección Entorno anterior, si se estableció la configuración correspondiente del programa nitrocli. Además, se establecerán las siguientes variables:

NITROCLI_BINARY
La ruta absoluta al binario de nitrocli a través del cual se invocó la extensión. Esta ruta puede usarse para invocar recursivamente nitrocli para implementar cierta funcionalidad.
NITROCLI_RESOLVED_USB_PATH
La ruta USB del dispositivo al que se conectaría nitrocli según las opciones --model, --serial-number y --usb-path. Si no hay ningún dispositivo Nitrokey coincidente, o si varios dispositivos coinciden con las opciones, la variable de entorno no se establece.

Todas las demás variables presentes en el entorno se pasarán a la extensión sin cambios.

Las versiones más recientes del programa se reservan el derecho de establecer variables de entorno adicionales dentro del espacio de nombres "NITROCLI_". Como tal, se recomienda que las extensiones no definan variables personalizadas con este prefijo. Sin embargo, "NITROCLI_EXT_" se proporciona específicamente para este propósito. Para evitar aún más conflictos entre extensiones, se recomienda que este prefijo vaya seguido del nombre de la extensión (en mayúsculas).

Las extensiones pueden, opcionalmente, leer o escribir datos persistentes de diversas formas. De manera similar al programa principal, las extensiones deben seguir la Especificación de Directorios Base de XDG como guía sobre dónde almacenar dichos datos. Más específicamente, se deben seguir las siguientes convenciones:

Para datos de configuración, ${XDG_CONFIG_HOME}/extension/ es el directorio preferido, donde extension es el nombre completo de la extensión, incluido el prefijo "nitrocli-". El formato de configuración recomendado es TOML. Si solo se utiliza un único archivo de configuración, config.toml es el nombre recomendado.

De manera similar, los datos regulares deben residir en ${XDG_DATA_HOME}/extension/ y los datos cacheados deben almacenarse en ${XDG_CACHE_HOME}/extension/.

ARCHIVOS

${XDG_CONFIG_HOME}/nitrocli/config.toml
${HOME}/nitrocli/config.toml
Archivo de configuración del usuario, consulte la sección Archivo de configuración.

EJEMPLOS

Almacenamiento

Crea un volumen oculto en la primera ranura disponible, comenzando a la mitad del tamaño del volumen cifrado (es decir, 50%) y extendiéndose hasta su final (100%):


$ nitrocli hidden create 0 50 100

Contraseñas de un solo uso

Configura una ranura de contraseña de un solo uso con una representación hexadecimal del secreto:


$ nitrocli otp set 0 test-rfc4226 3132333435363738393031323334353637383930 \
    --format hex --algorithm hotp
$ nitrocli otp set 1 test-foobar 666F6F626172 --format hex --algorithm hotp
$ nitrocli otp set 0 test-rfc6238 3132333435363738393031323334353637383930 \
    --format hex --algorithm totp --digits 8

Configura una ranura de contraseña de un solo uso con una representación ASCII del secreto:


$ nitrocli otp set 0 test-rfc4226 12345678901234567890 --format ascii \
    --algorithm hotp
$ nitrocli otp set 1 test-foobar foobar --format ascii --algorithm hotp
$ nitrocli otp set 0 test-rfc6238 12345678901234567890 --format ascii \
    --algorithm totp --digits 8

Configura una ranura de contraseña de un solo uso con una representación base32 del secreto:


$ nitrocli otp set 0 test-rfc4226 gezdgnbvgy3tqojqgezdgnbvgy3tqojq \
    --algorithm hotp
$ nitrocli otp set 1 test-foobar mzxw6ytboi====== --algorithm hotp
$ nitrocli otp set 0 test-rfc6238 gezdgnbvgy3tqojqgezdgnbvgy3tqojq \
    --algorithm totp --digits 8

Genera una contraseña de un solo uso:


$ nitrocli otp get 0 --algorithm hotp
755224
$ nitrocli otp get 0 --algorithm totp --time 1234567890
89005924

Borra una ranura de contraseña de un solo uso:


$ nitrocli otp clear 0 --algorithm hotp

Configuración

Consulta la configuración:


$ nitrocli config get
Config:
numlock binding: not set
capslock binding: not set
scrollock binding: not set
require user PIN for OTP: true

Cambia la configuración:


$ nitrocli config set --otp-pin

Caja de contraseñas

Configura una ranura PWS:


$ nitrocli pws add example.org john.doe passw0rd
Added PWS slot 0

Obtiene los datos de una ranura:


$ nitrocli pws get 0
name: example.org
login: john.doe
password: passw0rd

Copia la contraseña al portapapeles (requiere xclip(1)).


$ nitrocli pws get 0 --password --quiet | xclip -in

Consulta las ranuras PWS:


$ nitrocli pws status
slot    name
0       example.org
24-04-2021
