nix-store-delete(1)

Paquete: nix

Licencias: LGPL-2.1-only

nix-store --delete(1) Manual de comandos generales nix-store --delete(1)

Nombre

nix-store --delete - eliminar rutas del almacén

Sinopsis

nix-store --delete [--ignore-liveness] rutas…

Descripción

La operación --delete elimina las rutas del almacén rutas del almacén Nix, pero solo si es seguro hacerlo; es decir, cuando la ruta no es alcanzable desde una raíz del recolector de basura. Esto significa que solo puedes eliminar rutas que también serían eliminadas por nix-store --gc. Por lo tanto, --delete es una versión más específica de --gc.

Con la opción --ignore-liveness, la alcanzabilidad desde las raíces se ignora. Sin embargo, la ruta aún no se eliminará si hay otras rutas en el almacén que la referencian (es decir, que dependen de ella).

Opciones

Las siguientes opciones están permitidas para todas las operaciones de nix-store, pero puede que no siempre tengan efecto.

•
--add-root ruta
Hace que el resultado de una realización (--realise y --force-realise) se registre como una raíz del recolector de basura. Se creará ruta como un enlace simbólico a la ruta del almacén resultante. Además, se creará un enlace simbólico con un nombre único a ruta en /nix/var/nix/gcroots/auto/. Por ejemplo,
$ nix-store --add-root /home/eelco/bla/result --realise ...
$ ls -l /nix/var/nix/gcroots/auto
lrwxrwxrwx    1 ... 2005-03-13 21:10 dn54lcypm8f8... -> /home/eelco/bla/result
$ ls -l /home/eelco/bla/result
lrwxrwxrwx    1 ... 2005-03-13 21:10 /home/eelco/bla/result -> /nix/store/1r11343n6qd4...-f-spot-0.0.10
Por lo tanto, cuando se elimine /home/eelco/bla/result, la raíz del GC en el directorio auto se convertirá en un enlace simbólico colgante y será ignorada por el recolector.
Advertencia
Tenga en cuenta que no es posible mover o renombrar raíces de GC, ya que el enlace simbólico en el directorio auto seguirá apuntando a la ubicación anterior.
Si hay varios resultados, se crearán varios enlaces simbólicos numerando secuencialmente los enlaces simbólicos más allá del primero (por ejemplo, foo, foo-2, foo-3, y así sucesivamente).

--keep-failed / -K
Especifica que, en caso de fallo de compilación, el directorio temporal (generalmente en /tmp) en el que se realiza la compilación no debe eliminarse. Se imprime la ruta del directorio de compilación como un mensaje informativo.
•
--fallback
Siempre que Nix intente compilar una derivación para la que se conocen sustitutos para cada ruta de salida, pero la realización de las rutas de salida a través de los sustitutos falla, recurre a la compilación de la derivación.
El escenario más común en el que esto es útil es cuando hemos registrado sustitutos para realizar la distribución binaria desde, por ejemplo, un repositorio de red. Si el repositorio no está disponible, la realización de la derivación fallará. Cuando se especifica esta opción, Nix compilará la derivación en su lugar. Por lo tanto, la instalación desde binarios recurre a la instalación desde el código fuente. Esta opción no es la predeterminada, ya que generalmente no es deseable que un fallo transitorio en la obtención de los sustitutos conduzca a una compilación completa desde el código fuente (con el consumo relacionado de recursos).
•
--readonly-mode
Cuando se utiliza esta opción, no se intenta abrir la base de datos de Nix. La mayoría de las operaciones de Nix necesitan acceso a la base de datos, por lo que esas operaciones fallarán.
•
--arg nombre valor
Esta opción es aceptada por nix-env, nix-instantiate, nix-shell y nix-build. Al evaluar expresiones Nix, el evaluador de expresiones intentará automáticamente llamar a las funciones que encuentra. Puede llamar automáticamente a funciones para las que todos los argumentos tienen un valor predeterminado (por ejemplo, { argName ? defaultValue }: ...).
Con --arg, también puedes llamar a funciones que tienen argumentos sin valor predeterminado (o anular un valor predeterminado). Es decir, si el evaluador encuentra una función con un argumento llamado nombre, la llamará con el valor valor.
Por ejemplo, el default.nix de nivel superior en Nixpkgs es en realidad una función:
{ # El sistema (por ejemplo, `i686-linux') para el cual compilar los paquetes.
system ? builtins.currentSystem
...
}: ...
Por lo tanto, si llamas a esta expresión Nix (por ejemplo, cuando haces nix-env --install --attr pkgname), la función se llamará automáticamente usando el valor builtins.currentSystem para el argumento system. Puedes anularlo usando --arg, por ejemplo, nix-env --install --attr pkgname --arg system \"i686-freebsd\". (Ten en cuenta que, dado que el argumento es un literal de cadena Nix, debes escapar las comillas.)
•
--argstr nombre valor
Esta opción es como --arg, solo que el valor no es una expresión Nix sino una cadena. Así que, en lugar de --arg system \"i686-linux\" (las comillas exteriores son para que el shell funcione correctamente), puedes decir --argstr system i686-linux.
•
--attr / -A rutaAttr
Selecciona un atributo de la expresión Nix de nivel superior que se está evaluando. (Solo nix-env, nix-instantiate, nix-build y nix-shell.) La ruta de atributo rutaAttr es una secuencia de nombres de atributos separados por puntos. Por ejemplo, dada una expresión Nix de nivel superior e, la ruta de atributo xorg.xorgserver haría que se utilizara la expresión e.xorg.xorgserver. Consulte nix-env --install para ver algunos ejemplos concretos.
Además de los nombres de atributos, también puedes especificar índices de matrices. Por ejemplo, la ruta de atributo foo.3.bar selecciona el atributo bar del cuarto elemento de la matriz en el atributo foo de la expresión de nivel superior.
•
--expr / -E
Interpreta los argumentos de la línea de comandos como una lista de expresiones Nix a analizar y evaluar, en lugar de como una lista de nombres de archivos de expresiones Nix. (Solo nix-instantiate, nix-build y nix-shell.)
Para nix-shell, esta opción se usa comúnmente para proporcionarte un shell en el que puedas compilar los paquetes devueltos por la expresión. Si deseas obtener un shell que contenga los paquetes compilados listos para su uso, proporciona tu expresión a la bandera de conveniencia nix-shell --packages en su lugar.
•
-I / --include ruta
Añade una entrada a la lista de rutas de búsqueda utilizadas para resolver rutas de búsqueda. Esta opción se puede especificar varias veces.
Las rutas añadidas a través de -I tienen prioridad sobre la configuración nix-path y la variable de entorno NIX_PATH.
•
--option nombre valor
Establece la opción de configuración de Nix nombre a valor. Esto anula la configuración en el archivo de configuración de Nix (ver nix.conf5).
•
--repair
Repara rutas de la tienda corruptas o faltantes volviendo a descargarlas o recompilándolas. Ten en cuenta que esto es lento porque requiere calcular un hash criptográfico del contenido de cada ruta en el cierre de la compilación. Ten en cuenta también la advertencia en nix-store --repair-path.

Nota

Consulta man nix.conf para anular la configuración con indicadores de línea de comandos.

NIX_PATH

Specifies the locations where Nix looks for Nix expressions. These are colon-separated lists of paths. For example: /nix/var/nix/profiles/per-user/root/channels:/nix/var/nix/cciochannels. Each path can be a string like name=path, where name is the name used in Nix expressions (e.g. <nixpkgs>) and path is the absolute path to the Nix expressions on the filesystem. If the name= prefix is omitted, the path is added to the search path, but cannot be referenced by name.
If NIX_PATH is not set, Nix uses the default search path, which is currently /nix/var/nix/profiles/per-user/root/channels (for the root user), ~/.nix-defexpr/channels (for the current user) and <nixpkgs> which points to /nix/var/nix/profiles/per-user/root/channels/nixpkgs (for the root user) or ~/.nix-defexpr/channels/nixpkgs (for the current user).
Nix expressions can reference paths in the search path using the <name> syntax, e.g. <nixpkgs>/some/package.nix. Nix searches the paths defined in NIX_PATH for a matching name. If Nix finds a matching name, it appends the rest of the path, and uses that.
For example, if NIX_PATH is set to mychannel=/path/to/my/channel, then <mychannel>/file.txt resolves to /path/to/my/channel/file.txt.
The contents of NIX_PATH are also used by Nix commands that take an environment to evaluate Nix expressions, such as nix-instantiate and nix-build. These commands will always fail if any search paths will fail.
Example
$ NIX_PATH= nix-instantiate --eval '<nixpkgs>'
error: file 'nixpkgs' was not found in the Nix search path (add it using $NIX_PATH or -I)
•
NIX_IGNORE_SYMLINK_STORE
Normally, the Nix store directory (typically /nix/store) is not allowed to contain any symlink components. This is to prevent “impure” builds. Builders sometimes “canonicalise” paths by resolving all symlink components. Thus, builds on different machines (with /nix/store resolving to different locations) could yield different results. This is generally not a problem, except when builds are deployed to machines where /nix/store resolves differently. If you are sure that you’re not going to do that, you can set NIX_IGNORE_SYMLINK_STORE to 1.
Note that if you’re symlinking the Nix store so that you can put it on another file system than the root file system, on Linux you’re better off using bind mount points, e.g.,
$ mkdir /nix
$ mount -o bind /mnt/otherdisk/nix /nix
Consult the mount 8 manual page for details.

GC_INITIAL_HEAP_SIZE
If Nix has been configured to use the Boehm garbage collector, this variable sets the initial size of the heap in bytes. It defaults to 384 MiB. Setting it to a low value reduces memory consumption, but will increase runtime due to the overhead of garbage collection.

XDG Base Directories

Nix follows the XDG Base Directory Specification.

For backwards compatibility, Nix commands will follow the standard only when use-xdg-base-directories is enabled. New Nix commands (experimental) conform to the standard by default.

The following environment variables are used to determine locations of various state and configuration files:

  • [XDG_STATE_HOME]{#env-XDGSTATEHOME} (default ~/.local/state)
  • [XDG_CACHE_HOME]{#env-XDGCACHEHOME} (default ~/.cache)
