nice(2) Manual de llamadas al sistema nice(2)

NOMBRE

nice - cambiar la prioridad de un proceso

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
int nice(int inc);
Requisitos de Macro de Prueba de Funciones para glibc (ver feature_test_macros(7)):

nice():

    _XOPEN_SOURCE
        || /* Desde glibc 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */ _BSD_SOURCE || _SVID_SOURCE

DESCRIPCIÓN

nice() añade inc al valor nice del hilo que la llama. (Un valor nice más alto significa menor prioridad.)

El rango del valor nice es de +19 (baja prioridad) a -20 (alta prioridad). Los intentos de establecer un valor nice fuera del rango se limitan a dicho rango.

Tradicionalmente, solo un proceso privilegiado podía disminuir el valor nice (es decir, establecer una prioridad más alta). Sin embargo, desde Linux 2.6.12, un proceso no privilegiado puede disminuir el valor nice de un proceso objetivo que tenga un límite blando adecuado de RLIMIT_NICE; ver getrlimit(2) para más detalles.

VALOR DE RETORNO

En caso de éxito, se devuelve el nuevo valor nice (pero ver VERSIONES más abajo). En caso de error, se devuelve -1 y se establece errno para indicar el error.

Una llamada exitosa puede devolver legítimamente -1. Para detectar un error, establezca errno a 0 antes de la llamada y compruebe si es distinto de cero después de que nice() devuelva -1.

ERRORES

EPERM
El proceso que llama intentó aumentar su prioridad proporcionando un inc negativo pero carece de privilegios suficientes. En Linux, se requiere la capacidad CAP_SYS_NICE. (Pero ver la discusión sobre el límite de recursos RLIMIT_NICE en setrlimit(2)).

VERSIONES

Diferencias entre la biblioteca C y el kernel

POSIX.1 especifica que nice() debe devolver el nuevo valor nice. Sin embargo, la llamada al sistema Linux sin procesar devuelve 0 en caso de éxito. Asimismo, la función envolvente nice() proporcionada en glibc 2.2.3 y anteriores devuelve 0 en caso de éxito.

Desde glibc 2.2.4, la función envolvente nice() proporcionada por glibc garantiza la conformidad con POSIX.1 llamando a getpriority(2) para obtener el nuevo valor nice, que luego se devuelve al llamante.

ESTANDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2001, SVr4, 4.3BSD.

NOTAS

Para más detalles sobre el valor nice, ver sched(7).

Nota: la adición de la característica "autogroup" en Linux 2.6.38 significa que el valor nice ya no tiene su efecto tradicional en muchas circunstancias. Para más detalles, ver sched(7).

VER TAMBIÉN

nice(1), renice(1), fork(2), getpriority(2), getrlimit(2), setpriority(2), capabilities(7), sched(7)
