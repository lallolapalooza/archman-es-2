NICE(1P) Manual del programador POSIX NICE(1P)

PROLOG

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

nice — invocar una utilidad con un valor de nice modificado

SINAPSIS

nice [-n incremento] utilidad [argumento...]

DESCRIPCIÓN

La utilidad nice invocará una utilidad, solicitando que se ejecute con un valor de nice diferente (consulte el volumen de Definiciones Base de POSIX.1‑2017, Sección 3.244, Valor de Nice). Sin opciones, la utilidad ejecutada se ejecutará con un valor de nice que es una cantidad definida por la implementación, mayor o igual al valor de nice del proceso actual. Si el usuario carece de los privilegios apropiados para afectar el valor de nice de la manera solicitada, la utilidad nice no afectará el valor de nice; en este caso, se puede escribir un mensaje de advertencia en el error estándar, pero esto no impedirá la invocación de utilidad ni afectará el estado de salida.

OPCIONES

La utilidad nice se ajustará al volumen de Definiciones Base de POSIX.1‑2017, Sección 12.2, Directrices de Sintaxis de Utilidades.

Se admite la siguiente opción:

-n incremento
Un entero decimal positivo o negativo que tendrá el mismo efecto en la ejecución de la utilidad que si la utilidad hubiera llamado a la función nice() con el valor numérico del argumento de opción incremento.

OPERANDOS

Se admitirán los siguientes operandos:

utilidad
El nombre de una utilidad que se va a invocar. Si el operando utilidad nombra alguna de las utilidades integradas especiales en la Sección 2.14, Utilidades Integradas Especiales, los resultados no están definidos.
argumento
Cualquier cadena que se proporcione como argumento al invocar la utilidad nombrada por el operando utilidad.

ENTRADA ESTÁNDAR

No se utiliza.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de nice:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‑2017, Sección 8.2, Variables de Internacionalización para la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en comparación con caracteres multibyte en los argumentos).
LC_MESSAGES

Determina la localización que se debe utilizar para afectar el formato y el contenido de los mensajes de diagnóstico escritos en el error estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.
PATH
Determina la ruta de búsqueda utilizada para localizar la utilidad que se invocará. Consulte el volumen de Definiciones Base de POSIX.1‑2017, Capítulo 8, Variables de Entorno.

EVENTOS ASÍNCRONOS

Predeterminado.

SALIDA ESTÁNDAR

No se utiliza.

ERROR ESTÁNDAR

El error estándar se utilizará únicamente para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Si se invoca utilidad, el estado de salida de nice será el estado de salida de utilidad; de lo contrario, la utilidad nice saldrá con uno de los siguientes valores:

1-125
Ocurrió un error en la utilidad nice.
  126
Se encontró la utilidad especificada por utilidad pero no se pudo invocar.
  127
No se pudo encontrar la utilidad especificada por utilidad.

CONSECUENCIAS DE LOS ERRORES

Predeterminado.

Las siguientes secciones son informativas.

USO DE LA APLICACIÓN

Los únicos usos portátiles garantizados de esta utilidad son:

nice utilidad

Ejecuta utilidad con el valor de nice predeterminado más alto o igual.
nice -n <entero positivo> utilidad

Ejecuta utilidad con un valor de nice más alto.

En algunas implementaciones no tienen un efecto perceptible en la utilidad invocada y en otras son exactamente equivalentes.

Los sistemas históricos con frecuencia han admitido el <entero positivo> hasta 20. Dado que no hay penalización por error al adivinar un número demasiado alto, los usuarios sin acceso al documento de conformidad del sistema (para ver qué límites están realmente vigentes) podrían usar el rango histórico de 1 a 20 o intentar usar números muy grandes si el trabajo debe tener una prioridad realmente baja.

El valor de nice de un proceso se puede mostrar usando el comando:

ps -o nice

Las utilidades command, env, nice, nohup, time y xargs han sido especificadas para usar el código de salida 127 si ocurre un error para que las aplicaciones puedan distinguir entre "fallo al encontrar una utilidad" y "utilidad invocada salió con una indicación de error". El valor 127 fue elegido porque no se usa comúnmente para otros significados; la mayoría de las utilidades usan valores pequeños para "condiciones de error normales" y los valores superiores a 128 pueden confundirse con la terminación debido a la recepción de una señal. El valor 126 fue elegido de manera similar para indicar que la utilidad se pudo encontrar, pero no invocar. Algunos scripts producen mensajes de error significativos que diferencian los casos 126 y 127. La distinción entre los códigos de salida 126 y 127 se basa en la práctica de KornShell que usa 127 cuando todos los intentos de exec de la utilidad fallan con [ENOENT], y usa 126 cuando cualquier intento de exec de la utilidad falla por cualquier otro motivo.

EJEMPLOS

Ninguno.

This page is a man page about the nice utility provided by the POSIX.1‐2017 standard. It is part of the man-pages package.

NAME

nice

- invoke a utility with an enhanced scheduling priority

SYNOPSIS

nice [-increment] [utility [argument ...]]

nice --help

nice --version [operand]

DESCRIPTION

The nice utility invokes the specified utility with an enhanced scheduling priority. The scheduling priority of a process is a value used by the system to determine the order in which processes are run. Higher priority processes are generally run before lower priority processes.

The default priority of a process is determined by the system. The nice utility allows a process to adjust its priority. Increasing the nice value decreases the scheduling priority. Decreasing the nice value increases the scheduling priority.

The increment value is a decimal integer. Positive values increase the nice value (lower the priority), and negative values decrease the nice value (raise the priority). If no increment is specified, a default increment is used. The default increment is specified by the implementation, but shall be positive.

If no utility is specified, the standard output shall be written to standard output, and the return value shall be the exit status of the shell.

The range of values for the nice value is implementation-defined. Users can only increase the nice value (decrease the scheduling priority) unless they have appropriate privileges. Processes with appropriate privileges can decrease the nice value (increase the scheduling priority) or set it to any valid value.

When a user without appropriate privileges attempts to decrease the nice value, the nice utility shall not change the nice value and shall write a diagnostic message to standard error indicating the action attempted. It shall then execute the utility with the original nice value. This is considered an error according to POSIX.1‐2017.

If the utility is invoked, the exit status of nice shall be the exit status of the specified utility. Otherwise, the exit status of nice shall be the exit status of the shell.

OPTIONS

nice shall conform to the Base Definitions volume of POSIX.1‐2017, Section 12.2, Utility Syntax Guidelines.

--help
Display a help message and exit.
--version [operand]
Output version information and exit.

OPERANDS

The following operands are supported:

-increment
A decimal integer used to adjust the scheduling priority. A positive value increases the nice value (lowers the priority), and a negative value decreases the nice value (raises the priority). If omitted, a default positive value is used.
utility [argument ...]
The command to be executed with the adjusted priority, along with any arguments it requires.

STDIN

Not used.

INPUT FILES

None.

ENVIRONMENT VARIABLES

None.

ASYNCHRONOUS EVENTS

Default.

STDOUT

If no utility is specified, the standard output of nice is the standard output of the shell.

STDERR

Diagnostic messages are written to standard error.

OUTPUT FILES

None.

EXTENDED DESCRIPTION

None.

EXIT STATUS

When the utility is invoked, the exit status of nice shall be the exit status of the specified utility. Otherwise, the exit status of nice shall be the exit status of the shell.

The nice utility shall exit with a value greater than 128 if the utility could not be executed.

CONSEQUENCES OF ERRORS

None.

APPLICATION USAGE

The nice utility cannot be used to run shell compound commands, pipelines, or asynchronous lists.

EXAMPLES

To run command myprog with a niceness value increased by 5:

nice -5 myprog

To run command myprog with the default niceness increase:

nice myprog

RATIONALE

The POSIX standard specifies that if a user without appropriate privileges provides a negative increment, the behavior should be as if the user had invoked the command nice -0 utility. This means the niceness value is not changed, but the utility is still executed. The system shall write a "permission denied" message to standard error, as specified by the standard, but the utility should still run. This differs from some historical implementations that would not run the utility at all.

The C shell has a built-in version of nice that has a different interface from the one described in this volume of POSIX.1‐2017.

The term "utility" is used, rather than "command", to highlight the fact that shell compound commands, pipelines, and so on, cannot be used. Special built-ins also cannot be used. However, "utility" includes user application programs and shell scripts, not just utilities defined in this volume of POSIX.1‐2017.

Historical implementations of nice provide a nice value range of 40 or 41 discrete steps, with the default nice value being the midpoint of that range. By default, they raise the nice value of the executed utility by 10.

Some historical documentation states that the increment value must be within a fixed range. This is misleading; the valid increment values on any invocation are determined by the current process nice value, which is not always the default.

The definition of nice value is not intended to suggest that all processes in a system have priorities that are comparable. Scheduling policy extensions such as the realtime priorities in the System Interfaces volume of POSIX.1‐2017 make the notion of a single underlying priority for all scheduling policies problematic. Some implementations may implement the nice-related features to affect all processes on the system, others to affect just the general time-sharing activities implied by this volume of POSIX.1‐2017, and others may have no effect at all. Because of the use of "implementation-defined" in nice and renice, a wide range of implementation strategies are possible.

Earlier versions of this standard allowed a -increment option. This form is no longer specified by POSIX.1‐2008 but may be present in some implementations.
