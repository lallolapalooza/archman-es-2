nptl(7) Manual de Información Miscelánea nptl(7)

NOMBRE

nptl - Native POSIX Threads Library

DESCRIPCIÓN

NPTL (Native POSIX Threads Library) es la implementación de hilos POSIX de la biblioteca C de GNU que se utiliza en los sistemas Linux modernos.

NPTL y señales

NPTL utiliza internamente las dos primeras señales en tiempo real (números de señal 32 y 33). Una de estas señales se utiliza para admitir la cancelación de hilos y temporizadores POSIX (consulte timer_create(2)); la otra se utiliza como parte de un mecanismo que garantiza que todos los hilos de un proceso siempre tengan las mismas UID y GID, según lo requiere POSIX. Estas señales no se pueden utilizar en aplicaciones.

Para evitar el uso accidental de estas señales en aplicaciones, que podría interferir con el funcionamiento de la implementación de NPTL, varias funciones de la biblioteca glibc y funciones de envoltorio de llamadas al sistema intentan ocultar estas señales a las aplicaciones, de la siguiente manera:

•
SIGRTMIN se define con el valor 34 (en lugar de 32).
•
Las interfaces sigwaitinfo(2), sigtimedwait(2) y sigwait(3) ignoran silenciosamente las solicitudes para esperar estas dos señales si se especifican en el argumento del conjunto de señales de estas llamadas.
•
Las interfaces sigprocmask(2) y pthread_sigmask(3) ignoran silenciosamente los intentos de bloquear estas dos señales.
•
Las interfaces sigaction(2), pthread_kill(3) y pthread_sigqueue(3) fallan con el error EINVAL (lo que indica un número de señal inválido) si se especifican estas señales.
•
sigfillset(3) no incluye estas dos señales cuando crea un conjunto de señales completo.

NPTL y cambios de credenciales del proceso

A nivel del kernel de Linux, las credenciales (identificadores de usuario y grupo) son un atributo por hilo. Sin embargo, POSIX requiere que todos los hilos POSIX en un proceso tengan las mismas credenciales. Para adaptarse a este requisito, la implementación de NPTL envuelve todas las llamadas al sistema que cambian las credenciales del proceso con funciones que, además de invocar la llamada al sistema subyacente, organizan que todos los demás hilos del proceso también cambien sus credenciales.

La implementación de cada una de estas llamadas al sistema implica el uso de una señal en tiempo real que se envía (usando tgkill(2)) a cada uno de los otros hilos que deben cambiar sus credenciales. Antes de enviar estas señales, el hilo que está cambiando las credenciales guarda las nuevas credenciales y registra la llamada al sistema que se está empleando en un búfer global. Un manejador de señales en el hilo o hilos receptores recupera esta información y luego utiliza la misma llamada al sistema para cambiar sus credenciales.

Se proporcionan funciones de envoltorio que emplean esta técnica para setgid(2), setuid(2), setegid(2), seteuid(2), setregid(2), setreuid(2), setresgid(2), setresuid(2) y setgroups(2).

ESTÁNDARES

Para obtener detalles sobre la conformidad de NPTL con el estándar POSIX, consulte pthreads(7).

NOTAS

POSIX dice que cualquier hilo en cualquier proceso con acceso a la memoria que contenga un mutex compartido por proceso (PTHREAD_PROCESS_SHARED) puede operar sobre ese mutex. Sin embargo, en sistemas x86 de 64 bits, la definición del mutex para x86-64 es incompatible con la definición del mutex para i386, lo que significa que los binarios de 32 y 64 bits no pueden compartir mutexes en sistemas x86-64.
