NOMBRE

nping - Herramienta de generación de paquetes de red / utilidad ping

SINOPSIS

nping [Opciones] {objetivos}

DESCRIPCIÓN

Nping es una herramienta de código abierto para la generación de paquetes de red, el análisis de respuestas y la medición del tiempo de respuesta. Nping permite a los usuarios generar paquetes de red de una amplia gama de protocolos, permitiéndoles ajustar prácticamente cualquier campo de las cabeceras de protocolo. Si bien Nping puede usarse como una utilidad ping simple para detectar hosts activos, también puede usarse como un generador de paquetes en bruto para pruebas de estrés de la pila de red, envenenamiento de ARP, ataques de Denegación de Servicio, rastreo de rutas y otros propósitos.

Además, Nping ofrece un modo de operación especial llamado "Modo Eco", que permite a los usuarios ver cómo cambian las sondas generadas en tránsito, revelando las diferencias entre los paquetes transmitidos y los paquetes recibidos en el otro extremo. Consulte la sección "Modo Eco" para obtener más detalles.

La salida de Nping es una lista de los paquetes que se envían y reciben. El nivel de detalle depende de las opciones utilizadas.

Un ejemplo típico de ejecución de Nping se muestra en el Ejemplo 1. Los únicos argumentos de Nping utilizados en este ejemplo son -c, para especificar el número de veces a atacar a cada host, --tcp para especificar el Modo de Sonda TCP, -p 80,433 para especificar los puertos de destino; y luego los dos nombres de host de destino.

ESPECIFICACIÓN DEL OBJETIVO

Todo lo que no sea una opción o un argumento de opción en la línea de comandos de Nping se trata como una especificación de host de destino. Nping utiliza la misma sintaxis para las especificaciones de destino que Nmap.

Nping admite la resolución de direcciones estilo CIDR. Puede añadir /numbits a una dirección IPv4 o nombre de host y Nping enviará sondeos a todas las direcciones IP para las que los primeros numbits sean iguales a los de la IP o nombre de host de referencia. Por ejemplo, 192.168.10.0/24 enviará sondeos a los 256 hosts entre 192.168.10.0 (binario: 11000000 10101000 00001010 00000000) y 192.168.10.255 (binario: 11000000 10101000 00001010 11111111), inclusive. 192.168.10.40/24 enviará sondeos exactamente a los mismos destinos. Dado que el host scanme.nmap.org está en la dirección IP 64.13.134.52, la especificación scanme.nmap.org/16 enviará sondeos a las 65.536 direcciones IP entre 64.13.0.0 y 64.13.255.255. El valor mínimo permitido es /0, que apunta a toda Internet. El valor máximo es /32, que apunta solo al host o dirección IP nombrada porque todos los bits de la dirección están fijos.

La notación CIDR es concisa pero no siempre lo suficientemente flexible. Por ejemplo, puede que desee enviar sondeos a 192.168.0.0/16 pero omitir cualquier IP que termine en .0 o .255 porque pueden usarse como direcciones de red y difusión de subred. Nping admite esto a través de la direccionamiento de rangos de octetos. En lugar de especificar una dirección IP normal, puede especificar una lista separada por comas de números o rangos para cada octeto. Por ejemplo, 192.168.0-255.1-254 omitirá todas las direcciones en el rango que terminan en .0 o .255, y 192.168.3-5,7.1 apuntará a las cuatro direcciones 192.168.3.1, 192.168.4.1, 192.168.5.1 y 192.168.7.1. Se puede omitir cualquiera de los lados de un rango; los valores predeterminados son 0 a la izquierda y 255 a la derecha. Usar un guión solo es lo mismo que 0-255, pero recuerde usar 0- en el primer octeto para que la especificación de destino no parezca una opción de línea de comandos. Los rangos no necesitan limitarse a los octetos finales: el especificador 0-.-.13.37 enviará sondeos a todas las direcciones IP en Internet que terminen en .13.37. Este tipo de muestreo amplio puede ser útil para encuestas e investigación en Internet.

Las direcciones IPv6 solo se pueden especificar por su dirección IPv6 o nombre de host completamente calificados. CIDR y los rangos de octetos no son compatibles con IPv6 porque rara vez son útiles.

Nping acepta múltiples especificaciones de host en la línea de comandos, y no tienen que ser del mismo tipo. El comando nping scanme.nmap.org 192.168.0.0/8 10.0.0,1,3-7.- hace lo que se esperaría.

ESPECIFICACIÓN DE OPCIONES

Nping está diseñado para ser muy flexible y adaptarse a una amplia variedad de necesidades. Al igual que con la mayoría de las herramientas de línea de comandos, su comportamiento se puede ajustar mediante opciones de línea de comandos. Estos principios generales se aplican a los argumentos de opciones, a menos que se indique lo contrario.

Las opciones que toman números enteros pueden aceptar valores especificados en base decimal, octal o hexadecimal. Cuando un número comienza con 0x, se tratará como hexadecimal; cuando simplemente comienza con 0, se tratará como octal. De lo contrario, Nping asumirá que el número se ha especificado en base 10. Prácticamente todos los números que se pueden suministrar desde la línea de comandos no son firmados, por lo que, como regla general, el valor mínimo es cero. Los usuarios también pueden especificar la palabra random o rand para que Nping genere un valor aleatorio dentro del rango esperado.

Las direcciones IP se pueden proporcionar como direcciones IPv4 (por ejemplo, 192.168.1.1), direcciones IPv6 (por ejemplo, 2001:db8:85a3::8e4c:760:7146) o nombres de host, que se resolverán utilizando el servidor DNS predeterminado configurado en el sistema host.

Las opciones que toman direcciones MAC aceptan el formato habitual de 6 bytes hexadecimales separados por dos puntos (por ejemplo, 00:50:56:d4:01:98). También se pueden usar guiones en lugar de dos puntos (por ejemplo, 00-50-56-c0-00-08). La palabra especial random o rand establece una dirección aleatoria y la palabra broadcast o bcast establece ff:ff:ff:ff:ff:ff.

OPERACIÓN GENERAL

A diferencia de otras herramientas de ping y generación de paquetes, Nping admite múltiples especificaciones de hosts y puertos de destino. Si bien esto proporciona una gran flexibilidad, no está claro cómo Nping maneja situaciones en las que hay más de un host y/o más de un puerto al que enviar sondeos. Esta sección explica cómo se comporta Nping en estos casos.

Cuando se especifican varios hosts de destino, Nping rota entre ellos de forma cíclica. Esto da a los hosts lentos más tiempo para enviar sus respuestas antes de enviarles otro sondeo. Los puertos también se programan utilizando el método cíclico. Por lo tanto, a menos que solo se especifique un puerto, Nping nunca envía dos sondeos al mismo host y puerto de destino de forma consecutiva.

El bucle alrededor de los destinos es el "bucle interno" y el bucle alrededor de los puertos es el "bucle externo". Todos los destinos recibirán un sondeo para un puerto determinado antes de pasar al siguiente puerto. Entre sondeos, Nping espera una cantidad de tiempo configurable llamada "retraso entre sondeos", que se controla mediante la opción --delay. Estos ejemplos muestran cómo funciona.

MODOS DE SONDEO

Nping admite una amplia variedad de protocolos. Aunque en algunos casos Nping puede determinar automáticamente el modo a partir de las opciones utilizadas, generalmente es una buena idea especificarlo explícitamente.

--tcp-connect (Modo TCP Connect)

El modo TCP Connect es el modo predeterminado cuando un usuario no tiene privilegios de paquetes crudos. En lugar de escribir paquetes crudos como la mayoría de los otros modos, Nping solicita al sistema operativo subyacente que establezca una conexión con la máquina y el puerto de destino emitiendo la llamada al sistema connect. Esta es la misma llamada al sistema de alto nivel que los navegadores web, los clientes P2P y la mayoría de las otras aplicaciones habilitadas para red utilizan para establecer una conexión. Es parte de una interfaz de programación conocida como la API de Sockets de Berkeley. En lugar de leer respuestas de paquetes crudos del cable, Nping usa esta API para obtener información de estado sobre cada intento de conexión. Por esta razón, no podrá ver el contenido de los paquetes que se envían o reciben, sino solo información de estado sobre el establecimiento de la conexión TCP que está teniendo lugar.

--tcp (Modo TCP)

TCP es el modo que permite a los usuarios crear y enviar cualquier tipo de paquete TCP. Los paquetes TCP se envían incrustados en paquetes IP que también se pueden ajustar. Este modo se puede utilizar para muchos propósitos diferentes. Por ejemplo, podría intentar descubrir puertos abiertos enviando mensajes TCP SYN sin completar el handshake de tres vías. Esta técnica a menudo se conoce como escaneo de media apertura, porque no abre una conexión TCP completa. Envía un paquete SYN, como si fuera a abrir una conexión real, y luego espera una respuesta. Un SYN/ACK indica que el puerto está abierto, mientras que un RST indica que está cerrado. Si no se recibe respuesta, se podría suponer que algún dispositivo de red intermedio está filtrando las respuestas. Otro uso podría ser ver cómo se comporta una pila TCP/IP remota cuando recibe un paquete no conforme a RFC, como uno con las banderas SYN y RST establecidas. Uno también podría hacer algo malvado creando paquetes RST personalizados utilizando una dirección IP falsificada con la intención de cerrar una conexión TCP activa.

--udp (Modo UDP)

El modo UDP puede tener dos comportamientos diferentes. En circunstancias normales, permite a los usuarios crear paquetes IP/UDP personalizados. Sin embargo, si Nping es ejecutado por un usuario sin privilegios de paquetes crudos y no se solicitan cambios en las cabeceras de protocolo predeterminadas, Nping entra en el modo UDP no privilegiado que básicamente envía paquetes UDP a los hosts y puertos de destino especificados utilizando la llamada al sistema sendto. Tenga en cuenta que en este modo no privilegiado no es posible ver la información de cabecera de bajo nivel de los paquetes en la red, sino solo información de estado sobre la cantidad de bytes que se transmiten y reciben. El modo UDP se puede utilizar para interactuar con cualquier servidor basado en UDP. Los ejemplos incluyen servidores DNS, servidores de streaming, servidores de juegos en línea y daemons de knock de puertos/autorización de un solo paquete.

--icmp (Modo ICMP)

El modo ICMP es el modo predeterminado cuando el usuario ejecuta Nping con privilegios de paquete crudo. Se puede crear cualquier tipo de mensaje ICMP. El tipo ICMP predeterminado es Echo, es decir, ping. El modo ICMP se puede utilizar
para muchos propósitos diferentes, desde una simple solicitud de marca de tiempo o una máscara de red hasta la transmisión de mensajes de destino inalcanzable falsos, redireccionamientos personalizados y anuncios de enrutador.

--arp (modo ARP/RARP)

ARP le permite crear y enviar algunos paquetes diferentes relacionados con ARP. Estos incluyen solicitudes y respuestas ARP, RARP, DRARP e InARP. Este modo se puede utilizar para realizar descubrimientos de host de bajo nivel y llevar a cabo ataques de envenenamiento de caché ARP.

--traceroute (modo Traceroute)

Traceroute no es un modo en sí mismo, sino un complemento para los modos TCP, UDP e ICMP. Cuando se especifica esta opción, Nping establecerá el valor TTL de IP de la primera sonda a 1. Cuando el siguiente enrutador reciba el paquete, lo descartará debido a la expiración del TTL y generará un mensaje ICMP de destino inalcanzable. La siguiente sonda tendrá un TTL de 2, por lo que el primer enrutador reenviará el paquete mientras que el segundo enrutador será el que descarte el paquete y genere el mensaje ICMP. La tercera sonda tendrá un valor TTL de 3 y así sucesivamente. Al examinar las direcciones de origen de todos esos mensajes ICMP de Destino Inalcanzable, es posible determinar la ruta que toman las sondas hasta que llegan a su destino final.

MODO TCP CONNECT

-p espec_puerto, --dest-port espec_puerto (Puertos de destino)

Esta opción especifica a qué puertos desea intentar conectarse. Puede ser un solo puerto, una lista de puertos separados por comas (por ejemplo, 80,443,8080), un rango (por ejemplo, 1-1023) y cualquier combinación de estos (por ejemplo, 21-25,80,443,1024-2048). Los valores de inicio y/o fin de un rango pueden omitirse, lo que hace que Nping use 1 y 65535, respectivamente. Por lo tanto, puede especificar -p- para apuntar a puertos del 1 al 65535. Se permite usar el puerto cero si se especifica explícitamente.

-g numero_puerto, --source-port numero_puerto (Suplantar puerto de origen)

Esta opción solicita a Nping que utilice el puerto especificado como puerto de origen para las conexiones TCP. Tenga en cuenta que esto podría no funcionar en todos los sistemas o podría requerir privilegios de root. El valor especificado debe ser un entero en el rango [0-65535].

MODO TCP

-p espec_puerto, --dest-port espec_puerto (Puertos de destino)

Esta opción especifica a qué puertos de destino desea enviar sondas. Puede ser un solo puerto, una lista de puertos separados por comas (por ejemplo, 80,443,8080), un rango (por ejemplo, 1-1023) y cualquier combinación de estos (por ejemplo, 21-25,80,443,1024-2048). Los valores de inicio y/o fin de un rango pueden omitirse, lo que hace que Nping use 1 y 65535, respectivamente. Por lo tanto, puede especificar -p- para apuntar a puertos del 1 al 65535. Se permite usar el puerto cero si se especifica explícitamente.

-g numero_puerto, --source-port numero_puerto (Suplantar puerto de origen)

Esta opción solicita a Nping que utilice el puerto especificado como puerto de origen para las conexiones TCP. Tenga en cuenta que esto podría no funcionar en todos los sistemas o podría requerir privilegios de root. El valor especificado debe ser un entero en el rango [0-65535].

--seq numero_secuencia (Número de Secuencia)

Especifica el número de secuencia TCP. En los paquetes SYN, este es el número de secuencia inicial (ISN). En una transmisión normal, esto corresponde al número de secuencia del primer byte de datos en el segmento. numero_secuencia debe ser un número en el rango [0-4294967295].

--flags flags (Banderas TCP)

Esta opción especifica qué banderas deben establecerse en el paquete TCP. flags se puede especificar de tres maneras diferentes:
1.Como una lista de banderas separadas por comas, por ejemplo, --flags syn,ack,rst
2.Como una lista de iniciales de banderas de un solo carácter, por ejemplo, --flags SAR le dice a Nping que establezca las banderas SYN, ACK y RST.
3.Como un número hexadecimal de 8 bits, donde el número proporcionado es el valor exacto que se colocará en el campo de banderas de la cabecera TCP. El número debe comenzar con el prefijo 0x y debe estar en el rango [0x00-0xFF], por ejemplo, --flags 0x20 establece la bandera URG ya que 0x20 corresponde a 00100000 binario y la bandera URG está representada por el tercer bit.

Hay 8 banderas posibles para establecer: CWR, ECN, URG, ACK, PSH, RST, SYN y FIN. El valor especial ALL significa establecer todas las banderas. NONE significa no establecer ninguna bandera. Es importante que si no desea que se establezca ninguna bandera, lo solicite explícitamente, ya que en algunos casos la bandera SYN puede establecerse por defecto. Aquí hay una breve descripción del significado de cada bandera:

CWR (Ventana de Congestión Reducida)

Establecida por un remitente con capacidad ECN cuando reduce su ventana de congestión (debido a un tiempo de espera de retransmisión, una retransmisión rápida o en respuesta a una notificación ECN.

ECN (Notificación Explícita de Congestión)

Durante el handshake de tres vías, indica que el remitente es capaz de realizar notificación explícita de congestión. Normalmente significa que se recibió un paquete con la bandera de Congestión de IP Experimentada establecida durante la transmisión normal. Consulte RFC 3168 para obtener más información.

URG (Urgente)

El segmento es urgente y el campo del puntero urgente contiene información válida.

ACK (Acuse de Recibo)

El segmento lleva un acuse de recibo y el valor del número de acuse de recibo es válido y contiene el siguiente número de secuencia que se espera del receptor.

PSH (Push)

Los datos de este segmento deben enviarse inmediatamente a la capa de aplicación al llegar.

RST (Restablecer)

Hubo algún problema y el remitente quiere abortar la conexión.

SYN (Sincronizar)

El segmento es una solicitud para sincronizar los números de secuencia y establecer una conexión. El campo del número de secuencia contiene el número de secuencia inicial del remitente.

FIN (Finalizar)

El remitente desea cerrar la conexión.

--win tamaño (Tamaño de Ventana)

Especifica el tamaño de la ventana TCP, es decir, el número de octetos que el remitente del segmento está dispuesto a aceptar del receptor a la vez. Este suele ser el tamaño del búfer de recepción que el sistema operativo asigna para una determinada conexión. tamaño debe ser un número en el rango [0-65535].

--badsum (Suma de Verificación Inválida)

Solicita a Nping que utilice una suma de verificación TCP inválida para los paquetes enviados a los hosts de destino. Dado que prácticamente todas las pilas IP de los hosts descartan adecuadamente estos paquetes, cualquier respuesta recibida probablemente provenga de un firewall o un IDS que no se molestó en verificar la suma de verificación. Para obtener más detalles sobre esta técnica, consulte https://nmap.org/p60-12.html.

MODO ICMP

--icmp-type tipo (Tipo ICMP)

Esta opción especifica qué tipo de mensajes ICMP se deben generar. tipo se puede proporcionar de dos maneras. Puede utilizar los números de tipo oficiales asignados por IANA[1] (por ejemplo, --icmp-type 8 para ICMP Echo Request), o puede usar cualquiera de los mnemónicos listados en la sección "Tipos ICMP".

--icmp-code código (Código ICMP)

Esta opción especifica qué código ICMP se debe incluir en los mensajes ICMP generados. código se puede proporcionar de dos maneras. Puede utilizar los números de código oficiales asignados por IANA[1] (por ejemplo, --icmp-code 1 para Tiempo de Excedencia de Reensamblaje de Fragmento), o puede usar cualquiera de los mnemónicos listados en la sección "Códigos ICMP".

--icmp-id id (Identificador ICMP)

Esta opción especifica el valor del identificador utilizado en algunos de los mensajes ICMP. En general, se utiliza para hacer coincidir los mensajes de solicitud y respuesta. id debe ser un número en el rango [0-65535].

--icmp-seq sec (Secuencia ICMP)

Esta opción especifica el valor del campo del número de secuencia utilizado en algunos mensajes ICMP. En general, se utiliza para hacer coincidir los mensajes de solicitud y respuesta. id debe ser un número en el rango [0-65535].

--icmp-redirect-addr dirección (Dirección de Redireccionamiento ICMP)

Esta opción establece el campo de dirección en los mensajes de Redireccionamiento ICMP. En otras palabras, establece la dirección IP del enrutador que debe usarse al enviar datagramas IP al destino original. dirección puede ser una dirección IPv4 o un nombre de host.

--icmp-param-pointer puntero (Puntero de Problema de Parámetro ICMP)

Esta opción especifica el puntero que indica la ubicación del problema en los mensajes de Problema de Parámetro ICMP. puntero debe ser un número en el rango [0-255]. Normalmente, esta opción solo se utiliza cuando el código ICMP se establece en 0 ("El puntero indica el error").

--icmp-advert-lifetime ttl (Vida Útil del Anuncio de Enrutador ICMP)

Esta opción especifica la vida útil del anuncio del enrutador, es decir, el número de segundos que la información contenida en un Anuncio de Enrutador ICMP puede considerarse válida. ttl debe ser un entero positivo en el rango [0-65535].

--icmp-advert-entry addr,pref (Entrada de Anuncio de Router ICMP)

Esta opción agrega una entrada de Anuncio de Router a un mensaje de Anuncio de Router ICMP. El parámetro debe ser dos valores separados por una coma. addr es la IP del router y se puede especificar como una dirección IP en notación de puntos decimales o como un nombre de host. pref es el nivel de preferencia para la IP especificada. Debe ser un número en el rango [0-4294967295]. Un ejemplo es --icmp-advert-entry 192.168.128.1,3.

--icmp-orig-time timestamp (Timestamp de Origen ICMP)

Esta opción establece el Timestamp de Origen en los mensajes de Timestamp ICMP. El Timestamp de Origen se expresa como el número de milisegundos desde la medianoche UTC y corresponde al momento en que el remitente tocó por última vez el mensaje de Timestamp antes de su transmisión. timestamp se puede especificar como un tiempo regular (por ejemplo, 10s, 3h, 1000ms) o la cadena especial now. Puedes sumar o restar valores a now, por ejemplo --icmp-orig-time now-2s, --icmp-orig-time now+1h, --icmp-orig-time now+200ms.

--icmp-recv-time timestamp (Timestamp de Recepción ICMP)

Esta opción establece el Timestamp de Recepción en los mensajes de Timestamp ICMP. El Timestamp de Recepción se expresa como el número de milisegundos desde la medianoche UTC y corresponde al momento en que el que responde tocó por primera vez el mensaje de Timestamp al recibirlo. timestamp es igual que con --icmp-orig-time.

--icmp-trans-time timestamp (Timestamp de Transmisión ICMP)

Esta opción establece el Timestamp de Transmisión en los mensajes de Timestamp ICMP. El Timestamp de Transmisión se expresa como el número de milisegundos desde la medianoche UTC y corresponde al momento en que el que responde tocó por última vez el mensaje de Timestamp antes de su transmisión. timestamp es igual que con --icmp-orig-time.

Tipos ICMP

Estos identificadores se pueden usar como mnemotecnia para los números de tipo ICMP dados a la opción --icmp-type. En general, hay tres formas de cada identificador: el nombre completo (por ejemplo, destination-unreachable), el nombre corto (por ejemplo, dest-unr) o las iniciales (por ejemplo, du). En los tipos ICMP que solicitan algo, se omite la palabra "request".

echo-reply, echo-rep, er

Respuesta de Eco (tipo 0). Este mensaje se envía en respuesta a un mensaje de Solicitud de Eco.

destination-unreachable, dest-unr, du

Destino Inalcanzable (tipo 3). Este mensaje indica que un datagrama no pudo ser entregado a su destino.

source-quench, sour-que, sq

Sonda de Origen (tipo 4). Este mensaje es utilizado por un dispositivo IP congestionado para indicar a otro dispositivo que está enviando paquetes demasiado rápido y que debe reducir la velocidad.

redirect, redi, r

Redirección (tipo 5). Este mensaje es utilizado normalmente por los routers para informar a un host de que existe una mejor ruta para el envío de datagramas. Véase también la opción --icmp-redirect-addr.

echo-request, echo, e

Solicitud de Eco (tipo 8). Este mensaje se utiliza para probar la conectividad de otro dispositivo en una red.

router-advertisement, rout-adv, ra

Anuncio de Router (tipo 9). Este mensaje es utilizado por los routers para informar a los hosts de su existencia y capacidades. Véase también la opción --icmp-advert-lifetime.

router-solicitation, rout-sol, rs

Solicitud de Router (tipo 10). Este mensaje es utilizado por los hosts para solicitar mensajes de Anuncio de Router a cualquier router que esté escuchando.

time-exceeded, time-exc, te

Tiempo Excedido (tipo 11). Este mensaje es generado por algún dispositivo intermedio (normalmente un router) para indicar que un datagrama ha sido descartado antes de llegar a su destino porque el TTL de IP expiró.

parameter-problem, member-pro, pp

Problema de Parámetro (tipo 12). Este mensaje se utiliza cuando un dispositivo encuentra un problema con un parámetro en una cabecera IP y no puede continuar procesándolo. Véase también la opción --icmp-param-pointer.

timestamp, time, tm

Solicitud de Timestamp (tipo 13). Este mensaje se utiliza para solicitar a un dispositivo que envíe un valor de timestamp para el cálculo del tiempo de propagación y la sincronización del reloj. Véase también --icmp-orig-time, --icmp-recv-time y --icmp-trans-time.

timestamp-reply, time-rep, tr

Respuesta de Timestamp (tipo 14). Este mensaje se envía en respuesta a un mensaje de Solicitud de Timestamp.

information, info, i

Solicitud de Información (tipo 15). Este mensaje está ahora obsoleto, pero originalmente se utilizaba para solicitar información de configuración a otro dispositivo.

information-reply, info-rep, ir

Respuesta de Información (tipo 16). Este mensaje está ahora obsoleto, pero originalmente se enviaba en respuesta a un mensaje de Solicitud de Información para proporcionar información de configuración.

mask-request, mask, m

Solicitud de Máscara de Red (tipo 17). Este mensaje se utiliza para pedir a un dispositivo que envíe su máscara de subred.

mask-reply, mask-rep, mr

Respuesta de Máscara de Red (tipo 18). Este mensaje contiene una máscara de subred y se envía en respuesta a un mensaje de Solicitud de Máscara de Red.

traceroute, trace, tc

Traceroute (tipo 30). Este mensaje normalmente lo envía un dispositivo intermedio cuando recibe un datagrama IP con una opción de traceroute. Los mensajes ICMP Traceroute todavía son experimentales, véase RFC 1393 para más información.

Códigos ICMP

Estos identificadores se pueden usar como mnemotecnia para los números de código ICMP dados a la opción --icmp-code. Se enumeran según el tipo ICMP al que corresponden.

Destino Inalcanzable

network-unreachable, netw-unr, net

Código 0. No se pudo entregar el datagrama a su red de destino (probablemente debido a algún problema de enrutamiento).

host-unreachable, host-unr, host

Código 1. El datagrama se entregó a la red de destino, pero fue imposible alcanzar el host especificado (probablemente debido a algún problema de enrutamiento).

protocol-unreachable, prot-unr, proto

Código 2. El protocolo especificado en el campo Protocolo del datagrama IP no es compatible con el host al que se entregó el datagrama.

port-unreachable, port-unr, port

Código 3. El puerto de destino TCP/UDP no era válido.

needs-fragmentation, need-fra, frag

Código 4. El datagrama tenía el bit DF establecido pero era demasiado grande para la MTU de la siguiente red física, por lo que tuvo que ser descartado.

source-route-failed, sour-rou, routefail

Código 5. El datagrama IP tenía una opción de Ruta de Origen pero un router no pudo pasarlo al siguiente salto.

network-unknown, netw-unk, net?

Código 6. La red de destino es desconocida. Este código nunca se utiliza. En su lugar, se utiliza Red de Destino Inalcanzable.

host-unknown, host-unk, host?

Código 7. El host especificado es desconocido. Normalmente lo genera un router local al host de destino para informar de una dirección incorrecta.

host-isolated, host-iso, isolated

Código 8. Host de Origen Aislado. No se utiliza.

network-prohibited, netw-pro, !net

Código 9. La comunicación con la red de destino está administrativamente prohibida (el dispositivo de origen no tiene permitido enviar paquetes a la red de destino).

host-prohibited, host-pro, !host

Código 10. La comunicación con el host de destino está administrativamente prohibida. (Se permite al dispositivo de origen enviar paquetes a la red de destino, pero no al dispositivo de destino).

network-tos, unreachable-network-tos, netw-tos, tosnet

Código 11. Red de destino inalcanzable porque no puede proporcionar el tipo de servicio especificado en el campo TOS de IP.

host-tos, unreachable-host-tos, toshost

Código 12. Host de destino inalcanzable porque no puede proporcionar el tipo de servicio especificado en el campo TOS de IP.

communication-prohibited, comm-pro, !comm

Código 13. No se pudo reenviar el datagrama debido a un filtrado que bloquea el mensaje según su contenido.

host-precedence-violation, precedence-violation, prec-vio, violation

Código 14. No se permite el valor de precedencia en el campo TOS de IP.

precedence-cutoff, prec-cut, cutoff

Código 15. El valor de precedencia en el campo TOS de IP es inferior al mínimo permitido para la red.

Redirección

redirect-network, redi-net, net

Código 0. Redirige todos los datagramas futuros con la misma red de destino que el datagrama original, al router especificado en el campo Dirección. El uso de este código está prohibido por la RFC 1812.

redirect-host, redi-host, host

Código 1. Redirige todos los datagramas futuros con el mismo host de destino que el datagrama original, al router especificado en el campo Dirección.

redirect-network-tos, redi-ntos, redir-ntos

Código 2. Redirige todos los datagramas futuros con la misma red de destino y valor TOS de IP que el datagrama original, al router especificado en el campo Dirección. El uso de este código está prohibido por la RFC 1812.

redirect-host-tos, redi-htos, redir-htos

Código 3. Redirige todos los datagramas futuros con el mismo host de destino y valor TOS de IP que el datagrama original, al router especificado en el campo Dirección.

Anuncio de Router

normal-advertisement, norm-adv, normal, zero, default, def

Código 0. Anuncio de router normal. En Mobile IP: el agente de movilidad puede actuar como router para datagramas IP no relacionados con nodos móviles.

not-route-common-traffic, not-rou, mobile-ip, !route, !commontraffic

Código 16. Se utiliza para Mobile IP. El agente de movilidad no enruta el tráfico común. Todos los agentes externos deben reenviar a un router predeterminado cualquier datagrama recibido de un nodo móvil registrado.

Tiempo Excedido

ttl-exceeded-in-transit, ttl-exc, ttl-transit

Código 0. El Tiempo de Vida de IP expiró durante el tránsito.

fragment-reassembly-time-exceeded, frag-exc, frag-time

Código 1. Se excedió el tiempo de reensamblaje de fragmentos.

MODO ARP

--arp-type tipo (Tipo ICMP)

Esta opción especifica qué tipo de mensajes ARP se deben generar. tipo se puede proporcionar de dos maneras diferentes. Puedes usar los números oficiales asignados por IANA[2] (por ejemplo, --arp-type 1 para Solicitud ARP), o puedes usar uno de los mnemónicos de la sección llamada "Tipos ARP".

--arp-sender-mac mac (Dirección MAC del remitente)

Esta opción establece el campo Dirección de Hardware del Remitente de la cabecera ARP. Aunque ARP soporta muchos tipos de direcciones de capa de enlace, actualmente Nping solo soporta direcciones MAC. mac debe especificarse utilizando la notación MAC tradicional (por ejemplo, 00:0a:8a:32:f4:ae). También puedes usar guiones como separadores (por ejemplo, 00-0a-8a-32-f4-ae).

--arp-sender-ip dir (Dirección IP del remitente)

Esta opción establece el campo IP del Remitente de la cabecera ARP. dir puede ser una dirección IPv4 o un nombre de host.

--arp-target-mac mac (Dirección MAC del objetivo)

Esta opción establece el campo Dirección de Hardware del Objetivo de la cabecera ARP.

--arp-target-ip dir (Dirección IP del objetivo)

Esta opción establece el campo IP del Objetivo de la cabecera ARP.

Tipos ARP

Estos identificadores pueden usarse como mnemónicos para los números de tipo ARP dados a la opción --arp-type.

arp-request, arp, a

Solicitud ARP (tipo 1). Las solicitudes ARP se utilizan para traducir direcciones de capa de red (normalmente direcciones IP) a direcciones de capa de enlace (generalmente direcciones MAC). Básicamente, una solicitud ARP es un mensaje difundido que pregunta al host en el mismo segmento de red que tiene una dirección IP dada que proporcione su dirección MAC.

arp-reply, arp-rep, ar

Respuesta ARP (tipo 2). Una respuesta ARP es un mensaje que un host envía en respuesta a una solicitud ARP para proporcionar su dirección de capa de enlace.

rarp-request, rarp, r

Solicitudes RARP (tipo 3). Las solicitudes RARP se utilizan para traducir una dirección de capa de enlace (normalmente una dirección MAC) a una dirección de capa de red (generalmente una dirección IP). Básicamente, una solicitud RARP es un mensaje difundido enviado por un host que quiere saber su propia dirección IP porque no tiene ninguna. Fue el primer protocolo diseñado para resolver el problema del arranque. Sin embargo, RARP está ahora obsoleto y se usa DHCP en su lugar. Para más información sobre RARP, ver RFC 903.

rarp-reply, rarp-rep, rr

Respuesta RARP (tipo 4). Una respuesta RARP es un mensaje enviado en respuesta a una solicitud RARP para proporcionar una dirección IP al host que envió la solicitud RARP en primer lugar.

drarp-request, drarp, d

Solicitud RARP Dinámica (tipo 5). RARP Dinámica es una extensión de RARP utilizada para obtener o asignar una dirección de capa de red a partir de una dirección de capa de enlace fija. DRARP se usó principalmente en plataformas Sun Microsystems a finales de los 90, pero ahora ya no se usa. Ver RFC 1931 para más información.

drarp-reply, drarp-rep, dr

Respuesta RARP Dinámica (tipo 6). Un mensaje de respuesta DRARP es un mensaje enviado en respuesta a una solicitud RARP para proporcionar una dirección de capa de red.

drarp-error, drarp-err, de

Error DRARP (tipo 7). Los mensajes de Error DRARP se envían normalmente en respuesta a solicitudes DRARP para informar de algún error. En los mensajes de Error DRARP, el campo Dirección de Protocolo de Objetivo se utiliza para transportar un código de error (normalmente en el primer byte). El código de error pretende indicar por qué no se devuelve ninguna dirección de protocolo de objetivo. Para más información ver RFC 1931.

inarp-request, inarp, i

Solicitud ARP Inversa (tipo 8). Las solicitudes InARP se utilizan para traducir una dirección de capa de enlace a una dirección de capa de red. Es similar a una solicitud RARP, pero en este caso, el remitente de la solicitud InARP quiere conocer la dirección de capa de red de otro nodo, no su propia dirección. InARP se usa principalmente en redes Frame Relay y ATM. Para más información ver RFC 2390.

inarp-reply, inarp-rep, ir

Respuesta ARP Inversa (tipo 9). Los mensajes de respuesta InARP se envían en respuesta a solicitudes InARP para proporcionar la dirección de capa de red asociada al host que tiene una dirección de capa de enlace dada.

arp-nak, an

ARP NAK (tipo 10). Los mensajes ARP NAK son una extensión del protocolo ATMARP y se utilizan para mejorar la robustez del mecanismo del servidor ATMARP. Con ARP NAK, un cliente puede determinar la diferencia entre un fallo catastrófico del servidor y un fallo de búsqueda en la tabla ATMARP. Ver RFC 1577 para más información.

OPCIONES IPV4

-S dir, --source-ip dir (Dirección IP de Origen)

Establece la dirección IP de origen. Esta opción te permite especificar una dirección IP personalizada que se utilizará como dirección IP de origen en los paquetes enviados. Esto permite falsificar el remitente de los paquetes. dir puede ser una dirección IPv4 o un nombre de host.

--dest-ip dir (Dirección IP de Destino)

Añade un objetivo a la lista de objetivos de Nping. Esta opción se proporciona por coherencia, pero su uso está obsoleto en favor de especificaciones de objetivos sencillas. Ver la sección llamada "ESPECIFICACIÓN DEL OBJETIVO".

--tos tos (Tipo de Servicio)

Establece el campo TOS de IP. El campo TOS se utiliza para transportar información que proporcione características de calidad de servicio. Normalmente se utiliza para soportar una técnica llamada Servicios Diferenciados. Ver RFC 2474 para más información. tos debe ser un número en el rango [0-255].

--id id (Identificación)

Establece el campo Identificación de IPv4. El campo Identificación es un valor de 16 bits que es común a todos los fragmentos que pertenecen a un mensaje particular. El valor es utilizado por el receptor para reensamblar el mensaje original a partir de los fragmentos recibidos. id debe ser un número en el rango [0-65535].

--df (No Fragmentar)

Establece el bit No Fragmentar en los paquetes enviados. Cuando un datagrama IP tiene su bandera DF activada, los dispositivos intermedios no tienen permitido fragmentarlo, por lo que si necesita viajar a través de una red con una MTU más pequeña que la longitud del datagrama, el datagrama tendrá que ser descartado. Normalmente se genera un mensaje ICMP Destino Inalcanzable y se envía de vuelta al remitente.

--mf (Más Fragmentos)

Establece el bit Más Fragmentos en los paquetes enviados. La bandera MF se establece para indicar al receptor que el datagrama actual es un fragmento de algún datagrama más grande. Cuando se establece a cero, indica que el datagrama actual es el último fragmento del conjunto o que es el único fragmento.

--evil (Reservado / Maligno)

Establece el bit Reservado / Maligno en los paquetes enviados. La bandera Maligna ayuda a los firewalls y otros sistemas de seguridad de red a distinguir entre datagramas que tienen intenciones maliciosas y aquellos que son meramente inusuales. Cuando se establece, indica que el datagrama tiene intenciones malignas, instruyendo a los sistemas inseguros a sucumbir. Establecerlo a cero indica ninguna intención maligna. La opción se implica si la variable de entorno SCRIPT_KIDDIE está configurada a un valor distinto de cero.

--ttl saltos (Tiempo de Vida)

Establece el campo Tiempo de Vida (TTL) de IPv4 en los paquetes enviados al valor dado. El campo TTL especifica cuánto tiempo se permite que exista el datagrama en la red. Originalmente estaba previsto que representara un número de segundos, pero en realidad representa el número de saltos que un paquete puede recorrer antes de ser descartado. El TTL intenta evitar una situación en la que los datagramas no entregables se reenvíen continuamente de un router a otro sin fin. saltos debe ser un número en el rango [0-255].

--badsum-ip (Suma de comprobación IP inválida)

Pide a Nping que utilice una suma de comprobación IP inválida para los paquetes enviados a los hosts de destino. Tenga en cuenta que algunos sistemas (como la mayoría de los kernels de Linux) pueden corregir la suma de comprobación antes de colocar el paquete en la red, por lo que incluso si Nping muestra la suma de comprobación incorrecta en su salida, los paquetes pueden ser corregidos transparentemente por el kernel.

--ip-options R|S [ruta]|L [ruta]|T|U ..., --ip-options cadena hexadecimal (Opciones IP)

El protocolo IP ofrece varias opciones que pueden colocarse en las cabeceras de los paquetes. A diferencia de las ubicuas opciones TCP, las opciones IP rara vez se ven debido a preocupaciones prácticas y de seguridad. De hecho, muchos routers de Internet bloquean las opciones más peligrosas, como el enrutamiento de origen. Sin embargo, las opciones aún pueden ser útiles en algunos casos para determinar y manipular la ruta de red hacia las máquinas de destino. Por ejemplo, puede ser capaz de utilizar la opción de registro de ruta para determinar un camino hacia un objetivo incluso cuando los enfoques más tradicionales de tipo traceroute fallan. O si sus paquetes están siendo descartados por un determinado firewall, puede ser capaz de especificar una ruta diferente con las opciones de enrutamiento de origen estricto o suelto.

La forma más potente de especificar opciones IP es simplemente pasar datos hexadecimales como argumento a --ip-options. Anteponga a cada valor de byte hexadecimal \x. Puede repetir ciertos caracteres siguiendo con un asterisco y luego el número de veces que desea que se repitan. Por ejemplo, \x01\x07\x04\x00*4 es lo mismo que \x01\x07\x04\x00\x00\x00\x00.

Tenga en cuenta que si especifica un número de bytes que no es un múltiplo de cuatro, se establecerá una longitud de cabecera IP incorrecta en el paquete IP. La razón de esto es que el campo de longitud de cabecera IP solo puede expresar múltiplos de cuatro. En esos casos, la longitud se calcula dividiendo la longitud de la cabecera por 4 y redondeando hacia abajo. Esto afectará la forma en que se interpreta la cabecera que sigue a la cabecera IP, mostrando información falsa en Nping o en la salida de cualquier sniffer. Aunque este tipo de situación podría ser útil para algunas pruebas de estrés de pila, los usuarios normalmente querrían especificar relleno, de modo que se establezca la longitud correcta de la cabecera.

Nping también ofrece un mecanismo de acceso directo para especificar opciones. Simplemente pase la letra R, T o U para solicitar las opciones de registro de ruta, registro de marca de tiempo o ambas juntas, respectivamente. El enrutamiento de origen suelto o estricto puede especificarse con una L o S seguida de un espacio y luego una lista de direcciones IP separadas por espacios.

OPCIONES IPV6

-6, --ipv6 (Usar IPv6)

Indica a Nping que use la versión 6 de IP en lugar de la IPv4 predeterminada. Generalmente, es una buena idea especificar esta opción lo antes posible en la línea de comandos para que Nping pueda analizarla pronto y sepa de antemano que el resto de los parámetros se refieren a IPv6. La sintaxis del comando es la misma de siempre, excepto que también se añade la opción -6. Por supuesto, debe usar la sintaxis IPv6 si especifica una dirección en lugar de un nombre de host. Una dirección podría parecerse a 3ffe:7501:4819:2000:210:f3ff:fe03:14d0, por lo que se recomiendan los nombres de host.

Aunque IPv6 no ha conquistado el mundo exactamente, tiene un uso significativo en algunos países (generalmente asiáticos) y la mayoría de los sistemas operativos modernos lo soportan. Para usar Nping con IPv6, tanto el origen como el destino de sus paquetes deben estar configurados para IPv6. Si su ISP (como la mayoría) no le asigna direcciones IPv6, hay túneles gratuitos disponibles que funcionan bien con Nping. Puede usar el servicio gratuito de túnel IPv6 en http://www.tunnelbroker.net.

Tenga en cuenta que el soporte para IPv6 sigue siendo altamente experimental y muchos modos y opciones pueden no funcionar con él.

Establece la Etiqueta de Flujo IPv6. Representa el número de saltos que un paquete puede atravesar antes de ser descartado. Al igual que con el TTL en IPv4, el Límite de Saltos de IPv6 intenta evitar una situación en la que los datagramas no entregables sigan siendo reenviados de un router a otro sin fin. saltos debe ser un número en el rango [0–255].

OPCIONES ETHERNET

En la mayoría de los casos, Nping envía paquetes a nivel de IP cruda. Esto significa que Nping crea sus propios paquetes IP y los transmite a través de un socket crudo. Sin embargo, en algunos casos puede ser necesario enviar paquetes a nivel de Ethernet cruda. Esto ocurre, por ejemplo, cuando Nping se ejecuta en Windows (ya que Microsoft ha deshabilitado el soporte de sockets crudos desde Windows XP SP2), o cuando se le pide a Nping que envíe paquetes ARP. Dado que en algunos casos es necesario construir tramas Ethernet, Nping ofrece algunas opciones para manipular los diferentes campos.

--dest-mac mac (Dirección MAC de Destino Ethernet)

Esta opción establece la dirección MAC de destino que se debe establecer en los frames Ethernet salientes. Esto es útil en caso de que Nping no pueda determinar la dirección MAC del siguiente salto o cuando desee enrutar las sondas a través de un router que no sea la puerta de enlace predeterminada configurada. La dirección MAC debe tener el formato habitual de seis bytes separados por dos puntos, por ejemplo, 00:50:56:d4:01:98. Alternativamente, se pueden usar guiones en lugar de dos puntos. Use la palabra random o rand para generar una dirección aleatoria, y broadcast o bcast para usar ff:ff:ff:ff:ff:ff. Si configura una dirección MAC de destino errónea, sus sondas podrían no llegar a los objetivos previstos.

--source-mac mac (Dirección MAC de Origen Ethernet)

Esta opción establece la dirección MAC de origen que se debe establecer en los frames Ethernet salientes. Esto es útil en caso de que Nping no pueda determinar la dirección MAC de su interfaz de red o cuando desee inyectar tráfico en la red ocultando la dirección real de su tarjeta de red. La sintaxis es la misma que para --dest-mac. Si configura una dirección MAC de origen errónea, es posible que no reciba las respuestas de las sondas.

MODO ECO

El "Modo Eco" es una técnica novedosa implementada por Nping que permite a los usuarios ver cómo cambian los paquetes de red en tránsito, desde el host donde se originaron hasta la máquina de destino. Básicamente, el Modo Eco convierte a Nping en dos piezas diferentes: el servidor Eco y el cliente Eco. El servidor Eco es un servicio de red que tiene la capacidad de capturar paquetes de la red y enviar una copia ("eco") al cliente de origen a través de un canal TCP lateral. El cliente Eco es la parte que genera dichos paquetes de red, los transmite al servidor y recibe su versión "eco" a través de un canal TCP que ha establecido previamente con el servidor Eco.

Este esquema permite al cliente ver

```que los paquetes que envía y lo que realmente recibe el servidor. Al hacer que el servidor envíe copias de los paquetes recibidos a través del canal lateral, dispositivos como NAT se vuelven inmediatamente aparentes para el cliente porque nota los cambios en la dirección IP de origen (y quizás incluso en el puerto de origen). Otros dispositivos como los que realizan modelado de tráfico, que cambian los tamaños de la ventana TCP o agregan opciones TCP de forma transparente entre hosts, también se revelan.

El modo Eco también es útil para solucionar problemas de enrutamiento y firewalls. Entre otras cosas, se puede utilizar para determinar si el tráfico generado por el cliente Nping se está descartando en tránsito y nunca llega a su destino, o si son las respuestas las que no regresan al cliente.

Internamente, el cliente y el servidor se comunican a través de un canal cifrado y autenticado, utilizando el Protocolo de Eco Nping (NEP), cuya especificación técnica se puede encontrar en https://nmap.org/svn/nping/docs/EchoProtoRFC.txt

Los siguientes párrafos describen las diferentes opciones disponibles en el modo Eco de Nping.

--ec contraseña, --echo-client contraseña (Ejecutar cliente Eco)

Esta opción indica a Nping que se ejecute como cliente Eco. contraseña es una secuencia de caracteres ASCII que se utiliza para generar las claves criptográficas necesarias para el cifrado y la autenticación en una sesión determinada. La contraseña debe ser un secreto que también conozca el servidor, y puede contener cualquier cantidad de caracteres ASCII imprimibles. Las contraseñas que contengan espacios en blanco o caracteres especiales deben ir entre comillas dobles.

Al ejecutar Nping como cliente Eco, la mayoría de las opciones de los modos de sondeo raw normales se aplican. El cliente puede configurarse para enviar sondeos específicos utilizando indicadores como --tcp, --icmp o --udp. Los campos de encabezado del protocolo se pueden manipular normalmente utilizando las opciones apropiadas (por ejemplo, --ttl, --seq, --icmp-type, etc.). Las únicas excepciones son los indicadores relacionados con ARP, que no son compatibles en el modo Eco, ya que protocolos como ARP están estrechamente relacionados con la capa de enlace de datos y sus sondeos no pueden atravesar diferentes segmentos de red.

--es contraseña, --echo-server contraseña (Ejecutar servidor Eco)

Esta opción indica a Nping que se ejecute como servidor Eco. contraseña es una secuencia de caracteres ASCII que se utiliza para generar las claves criptográficas necesarias para el cifrado y la autenticación en una sesión determinada. La contraseña debe ser un secreto que también conozcan los clientes, y puede contener cualquier cantidad de caracteres ASCII imprimibles. Las contraseñas que contengan espacios en blanco o caracteres especiales deben ir entre comillas dobles. Tenga en cuenta que, aunque no se recomienda, es posible utilizar contraseñas vacías, proporcionando --echo-server "". Sin embargo, si lo que desea es configurar un servidor Eco abierto, es mejor utilizar la opción --no-crypto. Consulte a continuación para obtener más detalles.

--ep puerto, --echo-port puerto (Establecer número de puerto TCP Eco)

Esta opción solicita a Nping que utilice el número de puerto TCP especificado para la conexión del canal lateral Eco. Si esta opción se utiliza con --echo-server, especifica el puerto en el que el servidor escucha las conexiones. Si se utiliza con --echo-client, especifica el puerto al que conectarse en el host remoto. Por defecto, se utiliza el número de puerto 9929.

--nc, --no-crypto (Desactivar cifrado y autenticación)

Esta opción solicita a Nping que no utilice operaciones criptográficas durante una sesión Eco. En términos prácticos, esto significa que los datos de la sesión del canal lateral Eco se transmitirán en texto plano, y el servidor o cliente no realizarán ninguna autenticación durante la fase de establecimiento de la sesión. Cuando se utiliza --no-crypto, se ignora la contraseña proporcionada con --echo-server o --echo-client.

Esta opción debe especificarse si Nping se compiló sin soporte openSSL. Tenga en cuenta que, por razones técnicas, todavía se debe proporcionar una contraseña después de los indicadores --echo-client o --echo-server, aunque se ignorará.

El indicador --no-crypto puede ser útil al configurar un servidor Eco público, ya que permite a los usuarios conectarse al servidor Eco sin necesidad de ninguna contraseña o secreto compartido. Sin embargo, se recomienda encarecidamente no utilizar --no-crypto a menos que sea absolutamente necesario. Los servidores Eco públicos deben configurarse para usar la contraseña "public" o la contraseña vacía (--echo-server "") ya que el uso de la criptografía no solo proporciona confidencialidad y autenticación, sino también integridad de mensajes.

--once (Servir a un cliente y salir)

Esta opción solicita al servidor Eco que salga después de servir a un cliente. Esto es útil cuando solo se desea establecer una única sesión Eco, ya que elimina la necesidad de acceder al host remoto para apagar el servidor.

--safe-payloads (Poner a cero los datos de la aplicación antes de hacer eco de un paquete)

Esta opción solicita al servidor Eco que borre cualquier dato de la capa de aplicación que se encuentre en los paquetes del cliente antes de hacer eco de ellos. Cuando la opción está habilitada, el servidor Eco analiza los paquetes recibidos de los clientes Eco e intenta determinar si contienen datos más allá de la capa de transporte. Si se encuentran dichos datos, se sobrescriben con ceros antes de transmitir los paquetes al cliente Eco apropiado.

Los servidores Eco pueden manejar múltiples clientes simultáneos que ejecutan múltiples sesiones de eco en paralelo. Para determinar qué paquete debe repetirse a qué cliente y a través de qué sesión, el servidor Eco utiliza un algoritmo heurístico. Aunque hemos tomado todas las medidas de seguridad que pudimos imaginar para evitar que un cliente reciba un paquete repetido que no generó, siempre existe el riesgo de que nuestro algoritmo cometa un error y entregue un paquete al cliente equivocado. La opción --safe-payloads es útil para servidores Eco públicos o despliegues críticos donde ese tipo de error no puede permitirse.

OPCIONES DE TIEMPO Y RENDIMIENTO

--delay tiempo (Retraso entre sondeos)

Esta opción le permite controlar cuánto tiempo esperará Nping antes de enviar el siguiente sondeo. Al igual que en muchas otras herramientas de ping, el retraso predeterminado es de un segundo. tiempo debe ser un número entero o flotante positivo. Por defecto, se especifica en segundos; sin embargo, puede dar una unidad explícita añadiendo ms para milisegundos, s para segundos, m para minutos o h para horas (por ejemplo, 2.5s, 45m, 2h).

--rate tasa (Enviar sondeos a una tasa dada)

Esta opción especifica el número de sondeos que Nping debe enviar por segundo. Esta opción y --delay son inversas; --rate 20 es lo mismo que --delay 0.05. Si se utilizan ambas opciones, solo cuenta la última en la lista de parámetros.

OPCIONES MISCELÁNEAS

-h, --help (Mostrar ayuda)

Muestra información de ayuda y sale.

-V, --version (Mostrar versión)

Muestra el número de versión del programa y sale.

-c rondas, --count rondas (Detenerse después de un número dado de rondas)

Esta opción le permite especificar el número de veces que Nping debe intentar enviar un sondeo.
mes que Nping debería iterar sobre hosts de destino (y en algunos casos puertos de destino). Nping llama a estos "rondas". En una ejecución básica con un solo destino (y un solo puerto de destino en modos TCP/UDP), el número de rondas coincide con el número de sondas enviadas al host de destino. Sin embargo, en ejecuciones más complejas donde Nping se ejecuta contra múltiples destinos y múltiples puertos, el número de rondas es el número de veces que Nping envía un conjunto completo de sondas que cubre todas las IPs de destino y todos los puertos de destino. Por ejemplo, si a Nping se le pide enviar paquetes TCP SYN a los hosts 192.168.1.0-255 y a los puertos 80 y 433, entonces 256 × 2 = 512 paquetes se envían en una ronda. Así que si especificas -c 100, Nping iterará sobre los diferentes hosts y puertos de destino 100 veces, enviando un total de 256 × 2 × 100 = 51200 paquetes. Por defecto, Nping se ejecuta durante 5 rondas. Si se especifica un valor de 0, Nping se ejecutará continuamente.

-e nombre, --interface nombre (Establecer la interfaz de red a utilizar)

Esta opción le dice a Nping qué interfaz debe usarse para enviar y recibir paquetes. Nping debería ser capaz de detectarlo automáticamente, pero te lo dirá si no puede. nombre debe ser el nombre de una interfaz de red existente con una dirección IP asignada.

--privileged (Asumir que el usuario tiene privilegios completos)

Le dice a Nping que simplemente asuma que tiene privilegios suficientes para realizar envíos de sockets crudos, sniffing de paquetes y operaciones similares que normalmente requieren privilegios especiales. Por defecto, Nping se cierra si tales operaciones son solicitadas por un usuario que no tiene privilegios de root o administrador. Esta opción puede ser útil en Linux, BSD o sistemas similares que pueden configurarse para permitir que usuarios sin privilegios realicen transmisiones de paquetes crudos. La variable de entorno NPING_PRIVILEGED puede configurarse como una alternativa al uso de --privileged.

--unprivileged (Asumir que el usuario carece de privilegios de socket crudo)

Esta opción es lo opuesto a --privileged. Le dice a Nping que trate al usuario como si careciera de privilegios de socket crudo de red y de sniffing. Esto es útil para pruebas, depuración o cuando la funcionalidad de red cruda de su sistema operativo está rota de alguna manera. La variable de entorno NPING_UNPRIVILEGED puede configurarse como una alternativa al uso de --unprivileged.

--send-eth (Enviar usando ethernet crudo)

Pide a Nping que envíe paquetes en la capa de ethernet crudo (enlace de datos) en lugar de la capa IP superior (red). Por defecto, Nping elige la que generalmente es mejor para la plataforma en la que se está ejecutando. Los sockets crudos (capa IP) son generalmente más eficientes para máquinas Unix, mientras que los marcos de ethernet son necesarios para el funcionamiento de Windows ya que Microsoft deshabilitó el soporte de sockets crudos. Nping todavía usa paquetes IP crudos a pesar de esta opción cuando no hay otra opción (como conexiones no ethernet).

--send-ip (Enviar a nivel IP crudo)

Pide a Nping que envíe paquetes a través de sockets IP crudos en lugar de enviar tramas ethernet de nivel inferior. Es el complemento de la opción --send-eth.

--bpf-filter especificación de filtro --filter especificación de filtro (Establecer filtro BPF personalizado)

Esta opción le permite usar un filtro BPF personalizado. Por defecto, Nping elige un filtro que está destinado a capturar las respuestas más comunes a las sondas particulares que se envían. Por ejemplo, al enviar paquetes TCP, el filtro se establece para capturar paquetes cuyo puerto de destino coincide con el puerto de origen de la sonda o mensajes de error ICMP que pueden ser generados por el destino o cualquier dispositivo intermedio como resultado de la sonda. Si por alguna razón espera paquetes extraños en respuesta a las sondas enviadas o simplemente desea hacer sniffing de un tipo particular de tráfico, puede especificar un filtro personalizado usando la sintaxis BPF utilizada por herramientas como tcpdump. Consulte la documentación en http://www.tcpdump.org/ para más información.

-H, --hide-sent (No mostrar paquetes enviados)

Esta opción le dice a Nping que no imprima información sobre los paquetes enviados. Esto puede ser útil cuando se usan retrasos muy cortos entre sondas (es decir, al inundar), ya que imprimir información en la salida estándar tiene un costo computacional y deshabilitarlo probablemente puede acelerar un poco las cosas. También, puede ser útil cuando se usa Nping para detectar hosts activos o puertos abiertos (por ejemplo, enviando sondas a todos los puertos TCP en una subred /24). En ese caso, los usuarios pueden no querer ver miles de sondas enviadas, sino solo las respuestas generadas por hosts activos.

-N, --no-capture (No intentar capturar respuestas)

Esta opción le dice a Nping que omita la captura de paquetes. Esto significa que los paquetes en respuesta a las sondas enviadas no se procesarán ni se mostrarán. Esto puede ser útil al realizar pruebas de inundación y estrés de la pila de red. Tenga en cuenta que cuando se especifica esta opción, la mayoría de las estadísticas que se muestran al final de la ejecución serán inútiles. Esta opción no funciona con el modo TCP Connect.

OPCIONES DE SALIDA

-v[nivel], --verbose [nivel] (Aumentar o establecer el nivel de verbosidad)

Aumenta el nivel de verbosidad, haciendo que Nping imprima más información durante su ejecución. Hay 9 niveles de verbosidad (-4 a 4). Cada instancia de -v incrementa el nivel de verbosidad en uno (desde su valor predeterminado, nivel 0). Cada instancia de la opción -q decrementa el nivel de verbosidad en uno. Alternativamente, puede especificar el nivel directamente, como en -v3 o -v-1. Estos son los niveles disponibles:

Nivel -4

Sin salida alguna. En algunas circunstancias, es posible que no desee que Nping produzca ninguna salida (como cuando uno de sus compañeros de trabajo le está observando por encima del hombro). En ese caso, el nivel -4 puede ser útil porque, aunque no verá ningún paquete de respuesta, las sondas aún se enviarán.

Nivel -3

Como el nivel -4, pero muestra mensajes de error fatales para que pueda ver si Nping se está ejecutando o si falló debido a algún error.

Nivel -2

Como el nivel -3, pero también muestra advertencias y errores recuperables.

Nivel -1

Muestra información de ejecución tradicional (versión, hora de inicio, estadísticas, etc.) pero no muestra paquetes enviados o recibidos.

Nivel 0

Este es el nivel de verbosidad predeterminado. Se comporta como el nivel -1 pero también muestra paquetes enviados y recibidos y otra información importante.

Nivel 1

Como el nivel 0, pero muestra información detallada sobre tiempos, flags, detalles del protocolo, etc.

Nivel 2

Como el nivel 1, pero muestra información muy detallada sobre paquetes enviados y recibidos y otra información interesante.

Nivel 3

Como el nivel 2, pero también muestra el volcado hexadecimal crudo de paquetes enviados y recibidos.

Nivel 4 y superior

Igual que el nivel 3.

-q[nivel], --reduce-verbosity [nivel] (Disminuir el nivel de verbosidad)

Disminuye el nivel de verbosidad, haciendo que Nping imprima menos información durante su ejecución.

-d[nivel] (Aumentar o establecer el nivel de depuración)

Cuando incluso el modo detallado no proporciona suficientes datos para usted, ¡la depuración está disponible para inundarlo con mucho más! Al igual que con -v, la depuración se habilita con una bandera en la línea de comandos -d y el nivel de depuración se puede aumentar especificándolo varias veces. Hay 7 niveles de depuración (0 a 6). Cada instancia de -d incrementa el nivel de depuración en uno. Proporcione un argumento a -d para establecer el nivel directamente; por ejemplo, -d4.

La salida de depuración es útil cuando sospecha un error en Nping, o si simplemente no entiende lo que está haciendo Nping y por qué. Como esta característica está pensada principalmente para desarrolladores, las líneas de depuración no siempre son autoexplicativas. Puede obtener algo como

NSOCK (1.0000s) Callback: TIMER SUCCESS for EID 12; tcpconnect_event_handler(): Received callback of type TIMER with status SUCCESS

Si no entiende una línea, sus únicos recursos son ignorarla, buscarla en el código fuente o solicitar ayuda a la lista de desarrollo (nmap-dev). Algunas líneas son autoexplicativas, pero los mensajes se vuelven más oscuros a medida que aumenta el nivel de depuración. Estos son los niveles disponibles:

Nivel 0

Nivel 0. Sin información de depuración. Este es el nivel predeterminado.

Nivel 1

En este nivel, solo se imprimirá información de depuración muy importante o de alto nivel.

Nivel 2

Como el nivel 1, pero también muestra información de depuración importante o de nivel medio.

Nivel 3

Como el nivel 2, pero también muestra información de depuración regular y de bajo nivel.

Nivel 4

Como el nivel 3, pero también muestra mensajes que solo un verdadero fanático de Nping querría ver.

Nivel 5

Como el nivel 4, pero habilita información de depuración básica relacionada con bibliotecas externas como Nsock.

Nivel 6

Como el nivel 5, pero habilita información de depuración completa y muy detallada relacionada con bibliotecas externas como Nsock.

Si nada de esto funciona, crea un Issue en nuestro rastreador (http://issues.nmap.org) y/o envía un informe de error a <dev@nmap.org>. Por favor, incluye todo lo que hayas aprendido sobre el problema, así como la versión de Nping que estás utilizando y la versión del sistema operativo en el que se está ejecutando. Otras sugerencias para mejorar Nping también pueden enviarse a la lista de desarrollo de Nmap.
