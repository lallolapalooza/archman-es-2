NOMBRE

nvidia-persistenced - Un demonio para mantener el estado persistente del software en el controlador NVIDIA.

SINOPSIS

nvidia-persistenced

DESCRIPCIÓN

La utilidad nvidia-persistenced se utiliza para habilitar el estado persistente del software en el controlador NVIDIA. Cuando el modo de persistencia está habilitado, el demonio evita que el controlador libere el estado del dispositivo cuando el dispositivo no está en uso. Esto puede mejorar el tiempo de inicio de nuevos clientes en este escenario.

OPCIONES

-v, --version
Imprime la versión de la utilidad y sale.
-h, --help
Imprime información de uso para las opciones de la línea de comandos y sale.
-V, --verbose
Controla cuánta información se imprime. Por defecto, nvidia-persistenced solo imprimirá errores y advertencias en syslog para eventos inesperados, así como notificaciones de inicio y apagado. Especificar esta bandera hará que nvidia-persistenced también imprima notificaciones en syslog sobre transiciones de estado, como cuando el modo de persistencia se habilita o deshabilita, y mensajes informativos al iniciar y salir.
-u NOMBRE_DE_USUARIO, --user=NOMBRE_DE_USUARIO
Ejecuta nvidia-persistenced con los permisos de usuario del usuario especificado por el argumento NOMBRE_DE_USUARIO. Este usuario debe tener acceso de escritura al directorio /var/run/nvidia-persistenced. Si este directorio no existe, nvidia-persistenced intentará crearlo antes de cambiar los IDs de usuario y grupo del proceso. Si esta opción no se proporciona, nvidia-persistenced no intentará cambiar el ID de usuario del proceso.
-g NOMBRE_DE_GRUPO, --group=NOMBRE_DE_GRUPO
Ejecuta nvidia-persistenced con los permisos de grupo del grupo especificado por el argumento NOMBRE_DE_GRUPO. Si se proporcionan tanto esta opción como la opción --user, esta opción tendrá prioridad al determinar el ID de grupo a usar. Si esta opción no se proporciona, nvidia-persistenced utilizará el ID de grupo primario del usuario especificado por el argumento de la opción --user. Si la opción --user tampoco se proporciona, nvidia-persistenced no intentará cambiar el ID de grupo del proceso.
--persistence-mode, --no-persistence-mode
Por defecto, nvidia-persistenced se inicia con el modo de persistencia habilitado para todos los dispositivos. Usa '--no-persistence-mode' para forzar la deshabilitación del modo de persistencia para todos los dispositivos al inicio.
--uvm-persistence-mode, --no-uvm-persistence-mode
Por defecto, nvidia-persistenced se inicia con el modo de persistencia UVM deshabilitado para todos los dispositivos. Usa '--uvm-persistence-mode' para forzar el modo de persistencia UVM para los dispositivos compatibles al inicio. Cuando el modo de persistencia UVM está habilitado, una GPU no puede entrar en el estado de bajo consumo PCI-Express Runtime D3. Consulte el capítulo sobre Gestión de Energía PCI-Express Runtime D3 (RTD3) del README del controlador gráfico acelerado de Linux de NVIDIA. Habilitar el modo de persistencia UVM puede resultar en un uso adicional de memoria de GPU reportado, incluso cuando no se están ejecutando aplicaciones.
--nvidia-cfg-path=RUTA
La biblioteca nvidia-cfg se utiliza para comunicarse con el módulo del kernel de NVIDIA para consultar y gestionar las GPU en el sistema. Esta biblioteca es requerida por nvidia-persistenced. Esta opción le dice a nvidia-persistenced dónde buscar esta biblioteca (en caso de que no pueda encontrarla por sí misma). Normalmente, esta opción no debería ser necesaria.

INSTALACIÓN

Cuando se instala mediante nvidia-installer, se instalan scripts de inicio de muestra para iniciar el demonio para algunos de los sistemas de inicio más comunes como el archivo tar comprimido /usr/share/doc/NVIDIA_GLX-1.0/sample/nvidia-persistenced-init.tar.bz2. Estos scripts de inicio deben ser personalizados para la distribución del usuario e instalados en la ubicación adecuada por el usuario para ejecutar nvidia-persistenced al inicio del sistema.

Una vez que el script de inicio está instalado para que el demonio se ejecute, los usuarios normalmente no necesitarán interactuar manualmente con nvidia-persistenced: las utilidades de gestión de NVIDIA, como nvidia-smi, pueden comunicarse con él automáticamente según sea necesario para gestionar el modo de persistencia.

Consulte la sección "Uso de la utilidad nvidia-persistenced" del README del controlador gráfico de Linux de NVIDIA para obtener más información, información sobre la instalación de la utilidad nvidia-persistenced para que se ejecute al inicio del sistema, y consejos para la solución de problemas.

PRIVILEGIOS

El demonio no requiere privilegios de root para ejecutarse, y puede ejecutarse de forma segura como un usuario sin privilegios, dado que su directorio de tiempo de ejecución, /var/run/nvidia-persistenced, se crea para ese usuario y es propiedad de él antes de iniciar el demonio. nvidia-persistenced también requiere acceso de lectura y escritura a los archivos de dispositivo de caracteres de NVIDIA. Si los permisos de los archivos de dispositivo se han alterado a través de alguna de las opciones del módulo del kernel de NVIDIA NVreg_DeviceFileUID, NVreg_DeviceFile_GID o NVreg_DeviceFileMode, nvidia-persistenced necesitará ejecutarse como un usuario adecuado.

Si el demonio se inicia con privilegios de root, la opción --user puede usarse en su lugar para indicar que el demonio debe renunciar a sus privilegios y ejecutarse como el usuario especificado después de configurar su directorio de tiempo de ejecución. El uso de esta opción puede hacer que el demonio no pueda eliminar el directorio /var/run/nvidia-persistenced cuando se finaliza, si el usuario especificado no tiene permisos de escritura en /var/run. En este caso, la eliminación del directorio debe ser manejada por un script posterior a la ejecución. Consulte los scripts de inicio de muestra proporcionados en /usr/share/doc/NVIDIA_GLX-1.0/sample/nvidia-persistenced-init.tar.bz2 para ver ejemplos de este comportamiento.

El demonio utiliza indirectamente nvidia-modprobe a través de la biblioteca nvidia-cfg para cargar el módulo del kernel de NVIDIA y crear los archivos de dispositivo de caracteres de NVIDIA después de que el demonio haya renunciado a sus privilegios de root, si es que tuvo alguno. Si nvidia-modprobe no está instalado, el demonio podría no iniciarse correctamente si no se ejecuta con privilegios de root.

OTROS

El código fuente de nvidia-persistenced está disponible aquí:

EJEMPLOS

nvidia-persistenced
Inicia el Demonio de Persistencia NVIDIA con el modo de persistencia habilitado para todos los dispositivos NVIDIA.
nvidia-persistenced --no-persistence-mode
Inicia el Demonio de Persistencia NVIDIA con el modo de persistencia deshabilitado para todos los dispositivos NVIDIA.
nvidia-persistenced --user=foo
Inicia el Demonio de Persistencia NVIDIA para que se ejecute como el usuario 'foo'.
