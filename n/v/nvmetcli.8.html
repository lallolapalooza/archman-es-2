NOMBRE

nvmetcli - Configurar un destino NVMe-over-Fabrics.

USO

nvmetcli
nvmetcli clear
nvmetcli restore [archivo.json]

DESCRIPCIÓN

nvmetcli es un programa utilizado para ver, editar, guardar y iniciar un destino NVMe del kernel de Linux, utilizado para la configuración de red NVMe-over-Fabrics. Permite a un administrador exportar un recurso de almacenamiento (como dispositivos NVMe, archivos y volúmenes) a un dispositivo de bloque local y exponerlos a sistemas remotos basándose en la especificación NVMe-over-Fabrics de http://www.nvmexpress.org.

nvmetcli se ejecuta como root y tiene dos modos:

1. Un shell de configuración interactivo
2. Modo de línea de comandos que utiliza un argumento

ANTECEDENTES

El término NQN utilizado en esta página del manual es el formato Nombre Calificado NVMe que un punto final NVMe (dispositivo, subsistema, etc.) debe seguir para garantizar un nombre único bajo el estándar NVMe. Se puede usar cualquier nombre en un sistema de red, pero si no sigue el formato NQN, puede que no sea único en una red NVMe-over-Fabrics.

Tenga en cuenta que algunos de los campos establecidos para un puerto de Destino NVMe en modo interactivo se definen en la sección "Página de Registro de Descubrimiento" de la especificación NVMe-over-Fabrics. Cada Destino NVMe tiene un mecanismo de controlador de descubrimiento que un Host NVMe puede usar para determinar los subsistemas NVM que puede acceder. nvmetcli se puede usar para agregar un nuevo registro al controlador de descubrimiento después de cada nueva entrada de subsistema y entrada de puerto a la que se vincula la entrada de subsistema recién creada (consulte las secciones OPCIONES y EJEMPLOS). Cada Host NVMe solo podrá ver las entradas de descubrimiento definidas en /subsystems/[NOMBRE NQN]/allowed_hosts y el puerto IP al que está conectado al Destino NVMe. Un Host NVMe puede recuperar estos registros de descubrimiento a través de la herramienta nvme-cli (https://github.com/linux-nvme/nvme-cli).

OPCIONES

Shell de Configuración Interactiva

Para iniciar el shell de configuración interactivo, escriba nvmetcli en la línea de comandos. nvmetcli interactúa con el subsistema configfs del destino NVMe del kernel de Linux, comenzando en los directorios base de nvmetcli /port, /subsystem y /host. Los cambios de configuración introducidos por el administrador se aplican inmediatamente a la configuración del destino del kernel. Los siguientes comandos se pueden usar en el modo de shell de configuración interactiva:

cd Permite moverse por el árbol.
ls Lista el contenido del nodo actual del árbol.
create [nombre NQN]/[#] Crea un nuevo objeto usando el nombre o número especificado. Si no se especifica un [nombre NQN]/[#], se utilizará una entrada aleatoria.
delete [nombre NQN]/[#] Elimina un objeto con el nombre o número especificado.
set attr allow_any_host=[0/1] Se utiliza en /subsystems/[nombre NQN] para especificar si algún Host NVMe puede conectarse al subsistema.
set device path=[ruta del dispositivo] Se utiliza en /subsystems/[nombre NQN]/namespaces para establecer el dispositivo (de almacenamiento) a utilizar.
set device nguid=[cadena] Se utiliza en /subsystems/[nombre NQN]/namespaces para establecer el ID único del dispositivo en el namespace definido.
enable/disable Se utiliza en /subsystems/[nombre NQN]/namespaces para habilitar y deshabilitar el namespace.
set addr [campo de página de registro de descubrimiento]=[cadena] Se utiliza en /ports/[#] para crear un puerto al que se permite el acceso. Consulte EJEMPLOS para más información.
saveconfig [archivo.json] Guarda la configuración del Destino NVMe en formato .json. Sin especificar el nombre del archivo, se guardará como /etc/nvmet/config.json. Este archivo está en formato JSON y se puede editar directamente con su editor de archivos preferido.
exit Sale del modo de shell de configuración interactiva.

Modo de Línea de Comandos

Escribir nvmetcli [cmd] en la línea de comandos ejecutará un comando y no entrará en el shell de configuración interactiva.

restore [archivo.json] Carga una configuración de Destino NVMe guardada. Sin especificar el nombre del archivo, utilizará /etc/nvmet/config.json.
clear Borra la configuración actual del Destino NVMe.
ls Muestra la configuración actual del Destino NVMe.

EJEMPLOS

Asegúrese de ejecutar nvmetcli como root, que el módulo nvmet esté cargado, que sus dispositivos y todos los módulos dependientes estén cargados, y que configfs esté montado en /sys/kernel/config usando:

mount -t configfs none /sys/kernel/config

La siguiente sección recorre un ejemplo de configuración.

•Para empezar con el modo interactivo y el prompt del comando nvmetcli, escriba (como root):
# ./nvmetcli
...>
•Crea un subsistema. Si no especifica un nombre, se generará un NQN, que probablemente sea la mejor opción. No lo hacemos aquí, ya que el nombre sería aleatorio:
> cd /subsystems
...> create testnqn
•Agrega acceso para un Host NVMe específico por su NQN:
...> cd /hosts
...> create hostnqn
...> cd /subsystems/testnqn
...> set attr allow_any_host=0
...> cd /subsystems/testnqn/allowed_hosts/
...> create hostnqn
•Elimina el acceso de un subsistema eliminando el Host NQN:
...> cd /subsystems/testnqn/allowed_hosts/
...> delete hostnqn
•Alternativamente, esto permite que cualquier Host se conecte al subsistema. Úselo solo en entornos estrictamente controlados:
...> cd /subsystems/testnqn/
...> set attr allow_any_host=1
•Crea un nuevo namespace. Si no especifica un ID de namespace, se utilizará el primer ID no utilizado:
...> cd /subsystems/testnqn/namespaces
...> create 1
...> cd 1
...> set device path=/dev/nvme0n1
...> enable

Tenga en cuenta que en la configuración anterior, el atributo device_nguid no tiene que establecerse para una funcionalidad de Destino NVMe correcta (pero para hacer coincidir correctamente un namespace con el dispositivo exacto durante las operaciones de limpieza y restauración, se recomienda establecer el parámetro device_nguid).

•Crea un puerto de loopback que se puede usar con el módulo nvme-loop en la misma máquina física...
...> cd /ports/
...> create 1
...> cd 1/
...> set addr trtype=loop
...> cd subsystems/
...> create testnqn
•o crea un puerto RDMA (IB, RoCE, iWarp) usando direccionamiento IPv4. 4420 es el puerto predeterminado asignado por IANA para NVMe over Fabrics usando RDMA:
...> cd /ports/
...> create 2
...> cd 2/
...> set addr trtype=rdma
...> set addr adrfam=ipv4
...> set addr traddr=192.168.6.68
...> set addr trsvcid=4420
...> cd subsystems/
...> create testnqn
•o crea un puerto FC. traddr es el WWNN/WWPN del puerto FC.
...> cd /ports/
...> create 3
...> cd 3/
...> set addr trtype=fc
...> set addr adrfam=f

nvmetcli(8)

NAME

nvmetcli - A command-line interface for managing NVMe Targets

USAGE

nvmetcli [options] [command]

DESCRIPTION

The nvmetcli utility provides a command-line interface for configuring and managing NVMe Target devices and subsystems on a Linux system. It allows users to create, delete, and modify NVMe Target configurations, including ports, controllers, namespaces, and subsystems.

BACKGROUND

NVMe Targets are used in NVMe over Fabrics (NVMe-oF) to expose NVMe namespaces over a network. nvmetcli simplifies the management of these targets by providing a consistent interface to the underlying NVMe Target subsystem in the Linux kernel.

OPTIONS

The nvmetcli utility supports various options to control its behavior, such as setting the target directory, enabling verbose output, and specifying configuration files.

-h, --help
Display help information.
-v, --version
Display version information.
-C, --config <file>
Specify an alternative configuration file.
-d, --debug
Enable debug output.
-t, --target <dir>
Specify the NVMe Target sysfs directory.

EXAMPLES

• Creating an NVMe Target port and controller:
./nvmetcli
...> create port traddr=nn-0x1000000044001123:pn-0x2000000055001123 trsvcid=none
...> create controller traddr=nn-0x1000000044001123:pn-0x2000000055001123 trsvcid=none
...> set addr traddr=nn-0x1000000044001123:pn-0x2000000055001123 trsvcid=none
...> set addr trsvcid=none
...> cd subsystems/
...> create testnqn
• Saving the NVMe Target configuration:
./nvmetcli
...> saveconfig test.json
• Loading an NVMe Target configuration:
  ./nvmetcli restore test.json
• Clearing a current NVMe Target
  configuration:
  ./nvmetcli clear

ADDITIONAL INFORMATION

nvmetcli has the ability to start and stop the NVMe Target configuration on boot and shutdown through the systemctl Linux utility via a .service file. nvmetcli package comes with nvmet.service which when installed, it can automatically restore the default, saved NVMe Target configuration from /etc/nvmet/config.json. nvmet.service can be installed in directories such as /lib/systemd/system.

To explicitly enable the service, type:

  systemctl enable nvmet

To explicitly disable the service, type:

  systemctl disable nvmet

See also systemctl(1).
