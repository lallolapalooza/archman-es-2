NOMBRE

nvme-fw-download - Descarga una imagen de firmware NVMe completa o parcial.

SINOPSIS

nvme fw-download <dispositivo> [--fw=<archivo-firmware> | -f <archivo-firmware>]
                        [--xfer=<tamaño-transferencia> | -x <tamaño-transferencia>]
                        [--offset=<offset> | -O <offset>]
                        [--output-format=<fmt> | -o <fmt>] [--verbose | -v]
                        [--timeout=<tiempo-espera> | -t <tiempo-espera>]

DESCRIPCIÓN

El comando Firmware Image Download se utiliza para descargar toda o parte de la imagen de firmware para una futura actualización al controlador. El comando Firmware Image Download puede enviarse mientras otros comandos en la Cola de Envío de Administración o las Colas de Envío de E/S están pendientes. El comando Firmware Image Download copia la nueva imagen de firmware (en su totalidad o en parte) al controlador.

La imagen de firmware puede constar de múltiples partes que se descargan individualmente con comandos separados de Firmware Image Download. Cada comando Firmware Image Download incluye un Desplazamiento Dword y un Número de Dwords que especifican un rango de Dwords. El software del host debe asegurarse de que las partes del firmware no tengan rangos de Dwords que se superpongan. Las porciones de firmware pueden enviarse fuera de orden al controlador.

La nueva imagen de firmware no se aplica como parte del comando Firmware Image Download. Se aplica después de un reinicio, donde la imagen a aplicar y la ranura de firmware a la que debe confirmarse se especifican con el comando Firmware Commit (nvme fw-commit <args>).

Nota: nvme-cli debe asignar un buffer de memoria contiguo (lineal) y mapear el binario del firmware en él. Para hacer esto, nvme-cli primero intenta asignar el buffer usando páginas TLB grandes (huge pages). Si la asignación con páginas grandes falla, recurre a usar posix_memalign() combinado con madvise(), aunque esto también es probable que falle.

Para aumentar la probabilidad de éxito, es posible que desee preasignar un número de páginas grandes antes de iniciar la descarga de firmware:

echo 20 > /proc/sys/vm/nr_hugepages

Para más detalles, consulte: https://www.kernel.org/doc/Documentation/vm/hugetlbpage.txt

OPCIONES

-f <archivo-firmware>, --fw=<archivo-firmware>

Argumento requerido. Especifica la ruta al archivo de firmware del dispositivo en su sistema que será leído por el programa y enviado al dispositivo.

-x <tamaño-transferencia>, --xfer=<tamaño-transferencia>

Especifica el tamaño para dividir cada transferencia. Esto es útil si el dispositivo tiene un requisito de tamaño de transferencia máximo para el firmware. Por defecto es 4k.

-O <offset>, --offset=<offset>

Especifica el desplazamiento inicial en dwords. Esto es realmente útil solo si su firmware está dividido en varios archivos; de lo contrario, el desplazamiento comienza en cero y se ajusta automáticamente en función del tamaño de transferencia (xfer) proporcionado.

-o <fmt>, --output-format=<fmt>

Establece el formato de reporte en normal, json o binary. Solo se puede usar un formato de salida a la vez.

-v, --verbose

Aumenta el detalle de la información en la salida.

-t <tiempo-espera>, --timeout=<tiempo-espera>

Anula el valor de tiempo de espera predeterminado. En milisegundos.

EJEMPLOS

•Transferir un firmware de 128KiB a la vez: 
# nvme fw-download /dev/nvme0 --fw=/ruta/a/nvme.fw --xfer=0x20000
