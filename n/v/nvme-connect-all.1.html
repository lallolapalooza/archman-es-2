NVME-CONNECT-ALL(1) Manual NVMe NVME-CONNECT-ALL(1)

NOMBRE

nvme-connect-all - Descubre y conecta a controladores de redes.

SINOPSIS

nvme connect-all [--transport=<trtype> | -t <trtype>]
                        [--nqn=<subnqn> | -n <subnqn>]
                        [--traddr=<traddr> | -a <traddr>]
                        [--trsvcid=<trsvcid> | -s <trsvcid>]
                        [--host-traddr=<traddr> | -w <traddr>]
                        [--host-iface=<iface> | -f <iface>]
                        [--hostnqn=<hostnqn> | -q <hostnqn>]
                        [--hostid=<hostid> | -I <hostid>]
                        [--raw=<filename> | -r <filename>]
                        [--device=<device> | -d <device>]
                        [--config=<filename> | -J <cfg>]
                        [--keep-alive-tmo=<sec> | -k <sec>]
                        [--reconnect-delay=<#> | -c <#>]
                        [--ctrl-loss-tmo=<#>     | -l <#>]
                        [--nr-io-queues=<#> | -i <#>]
                        [--nr-write-queues=<#> | -W <#>]
                        [--nr-poll-queues=<#> | -P <#>]
                        [--queue-size=<#> | -Q <#>] [--keyring=<#>]
                        [--tls_key=<#>] [--hdr-digest | -g] [--data-digest | -G]
                        [--persistent | -p] [--tls] [--concat] [--quiet]
                        [--dump-config | -O] [--nbft] [--no-nbft]
                        [--nbft-path=<STR>] [--context=<STR>]
                        [--output-format=<fmt> | -o <fmt>] [--verbose | -v]

DESCRIPCIÓN

Envía una o más solicitudes de Descubrimiento a un Controlador de Descubrimiento NVMe sobre Redes y crea controladores para los registros de descubrimiento devueltos.

Si no se proporcionan parámetros, nvme connect-all intentará encontrar un archivo /etc/nvme/discovery.conf para usar y suministrar una lista de comandos connect-all para ejecutar. Si no existe el archivo /etc/nvme/discovery.conf, el comando terminará con un error.

De lo contrario, se debe especificar un Controlador de Descubrimiento específico usando --transport, --traddr y, si es necesario, --trsvcid, y se enviará una solicitud de Descubrimiento al Controlador de Descubrimiento especificado.

Consulte la documentación del comando nvme-discover(1) para obtener más información.

OPCIONES

-t <trtype>, --transport=<trtype>

Este campo especifica la red de comunicaciones utilizada para una red NVMe sobre Redes. Los valores de cadena actuales incluyen:
Valor Definición
rdma La red de comunicaciones es una red rdma (RoCE, iWARP, Infiniband, rdma básico, etc.)
fc En progreso La red de comunicaciones es una red Fibre Channel.
tcp La red de comunicaciones es una red TCP/IP.
loop Conéctese a un destino NVMe sobre Redes en el host local

-n <subnqn>, --nqn <subnqn>

Este campo especifica el nombre del subsistema NVMe al que conectarse.

-a <traddr>, --traddr=<traddr>

Este campo especifica la dirección de red del Controlador de Descubrimiento. Para redes que utilizan direccionamiento IP (por ejemplo, rdma), esta debe ser una dirección basada en IP (por ejemplo, IPv4).

-s <trsvcid>, --trsvcid=<trsvcid>

Este campo especifica el id de servicio de transporte. Para redes que utilizan direccionamiento IP (por ejemplo, rdma), este campo es el número de puerto. Por defecto, el número de puerto IP para la red RDMA es 4420.

-w <traddr>, --host-traddr=<traddr>

Este campo especifica la dirección de red utilizada en el host para conectarse al Controlador. Para TCP, esto establece la dirección de origen en el socket.

-f <iface>, --host-iface=<iface>

Este campo especifica la interfaz de red utilizada en el host para conectarse al Controlador (por ejemplo, IP eth1, enp2s0, enx78e7d1ea46da). Esto fuerza la conexión a realizarse en una interfaz específica en lugar de dejar que el sistema decida.

-q <hostnqn>, --hostnqn=<hostnqn>

Anula el NQN de Host predeterminado que identifica al Host NVMe. Si esta opción no se especifica, el valor predeterminado se lee primero de /etc/nvme/hostnqn. Si ese archivo no existe, se utiliza el valor NQN generado automáticamente del módulo del kernel del Host NVMe. El NQN de Host identifica de forma única al Host NVMe y puede ser utilizado por el Controlador de Descubrimiento para controlar qué recursos del Destino NVMe se asignan al Host NVMe para una conexión.

-I <hostid>, --hostid=<hostid>

UUID (Identificador Universalmente Único) que se descubrirá y que debe ser formateado.

-r <filename>, --raw=<filename>

Este campo tomará la salida del comando nvme connect-all y la volcará a un archivo binario sin procesar. Por defecto, nvme connect-all volcará la salida a stdout.

-d <device>, --device=<device>

Este campo toma un dispositivo como entrada. Debe ser un dispositivo persistente asociado con un Controlador de Descubrimiento creado previamente por el comando "connect-all" o "discover". <device> sigue el formato nvme*, por ejemplo, nvme0, nvme1.

-J <filename>, --config=<filename>

Utiliza el archivo de configuración JSON especificado en lugar del archivo predeterminado /etc/nvme/config.json o none para no leer un archivo de configuración existente. El formato del archivo de configuración JSON se documenta en https://github.com/linux-nvme/libnvme/blob/master/doc/config-schema.json

-k <#>, --keep-alive-tmo=<#>

Anula el tiempo de espera de conexión activa predeterminado (en segundos). Esta opción se ignorará para el descubrimiento, pero se pasará a la llamada de conexión posterior.

-c <#>, --reconnect-delay=<#>

Anula el retraso predeterminado (en segundos) antes de que se intente reconectar después de una pérdida de conexión.

-l <#>, --ctrl-loss-tmo=<#>

Anula el período de tiempo de espera de pérdida del controlador predeterminado (en segundos).

-i <#>, --nr-io-queues=<#>

Anula el número predeterminado de colas de E/S creadas por el controlador. Esta opción se ignorará para el descubrimiento, pero se pasará a la llamada de conexión posterior.

-W <#>, --nr-write-queues=<#>

Añade colas adicionales que se utilizarán para E/S de escritura.

-P <#>, --nr-poll-queues=<#>

Añade colas adicionales que se utilizarán para E/S de baja latencia de sondeo.

-Q <#>, --queue-size=<#>

Anula el número predeterminado de elementos en las colas de E/S creadas por el controlador. Esta opción se ignorará para el descubrimiento, pero se pasará a la llamada de conexión posterior.

--keyring=<#>

Llavero para la búsqueda de claves TLS.

--tls_key=<#>

Clave TLS para la conexión (TCP).

-g, --hdr-digest

Genera/verifica el resumen de encabezado (TCP).

-G, --data-digest

Genera/verifica el resumen de datos (TCP).

-p, --persistent

No eliminar el controlador de descubrimiento después de recuperar la página de registro de descubrimiento.

--tls

Habilita el cifrado TLS (TCP).

--concat

Habilita la concatenación segura (TCP).

--quiet

Suprime los mensajes de error.

-O, --dump-config

Imprime el archivo de configuración JSON resultante en stdout.

--nbft

Solo mira las tablas NBFT

--no-nbft

No mires las tablas NBFT

--nbft-path=<STR>

Utiliza una ruta definida por el usuario a las tablas NBFT

--context <STR>

Establece el contexto de ejecución a <STR>. Esto permite coordinar la gestión de

nvme-connect-all(1)

NAME

nvme-connect-all - Connect to NVMe resources returned by the Discover Controller, based on discovery logs, or NBFT.

SYNOPSIS

nvme connect-all [OPTIONS]

DESCRIPTION

The nvme connect-all command discovers NVMe targets using the NVMe-MI Discovery Log page or the NVMe Base Firmware Table (NBFT) and then attempts to connect to those discovered targets. This is intended for use by host initiators to discover and connect to NVMe targets on the network or fabric.

The command can take its input from either the NVMe-MI Discovery Log page (via nvme discover) or from the NBFT structure found in system firmware.

If no discovery options are specified (e.g. no --transport, --traddr, etc.), the command will search for NBFT tables in the system's ACPI tables. If found, it will parse these tables and attempt to connect to the specified targets.

If NBFT is not found, or if explicit discovery options are provided, the command will behave like nvme discover followed by nvme connect for each discovered target.

Valid discovery methods:

•

NBFT: Look for NBFT tables in system firmware (ACPI). Can specify a path to a NBFT table using --nbft-path.

•

NVMe-MI Discovery Log: Use nvme discover parameters (transport, address, etc.) to query a discovery controller. The results from this discovery will be used for connection attempts.

OPTIONS

The options are the same as for nvme-discover(1) and nvme-connect(1).

Commonly used options include:

-a <address>, --traddr=<address>

The IP address or hostname of the discovery controller or target.

-f <id>, --device-id=<id>

NVMe Device ID for the target.

-h, --help

Provide help information for the command.

-i, --initiator

Show initiator information.

-n <nqn>, --hostnqn=<nqn>

NVMe Qualified Name (NQN) of the host initiator.

--nbft

Use the default system NBFT table for discovery.

--nbft-path=<path>

Use the specified NBFT table file for discovery.

-o <fmt>, --output-format=<fmt>

Set the reporting format to normal, json or binary. Only one output format can be used at a time.

-v, --verbose

Increase the information detail in the output.

EXAMPLES

•Connect to all records returned by the Discover Controller with IP4 address 192.168.1.3 for all resources allocated for NVMe Host name host1-rogue-nqn on the RDMA network. Port 4420 is used by default: 
# nvme connect-all --transport=rdma --traddr=192.168.1.3 \
--hostnqn=host1-rogue-nqn
•Issue a nvme connect-all command using the default system defined NBFT tables: 
# nvme connect-all --nbft
•Issue a nvme connect-all command with a user-defined path for the NBFT table: 
# nvme connet-all --nbft-path=/sys/firmware/acpi/tables/NBFT1
•Issue a nvme connect-all command using a /etc/nvme/discovery.conf file: 
# Machine default 'nvme discover' commands. Query the
# Discovery Controller's two ports (some resources may only
# be accessible on a single port). Note an official
# nqn (Host) name defined in the NVMe specification is being used
# in this example.
-t rdma -a 192.168.69.33 -s 4420 -q nqn.2014-08.com.example:nvme:nvm-subsystem-sn-d78432
-t rdma -a 192.168.1.4   -s 4420 -q nqn.2014-08.com.example:nvme:nvm-subsystem-sn-d78432
At the prompt type "nvme connect-all".
