NOMBRE

nvme-huawei-id-ctrl - Envía el comando NVMe Identify Controller, devuelve el resultado y la estructura

SINOPSIS

nvme huawei id-ctrl <dispositivo> [--vendor-specific | -v] [--raw-binary | -b]
                        [--output-format=<fmt> | -o <fmt>]

DESCRIPCIÓN

Para el dispositivo NVMe proporcionado, envía un comando de identificación del controlador y proporciona el resultado y la estructura devuelta.

El parámetro <dispositivo> es obligatorio y puede ser el dispositivo de caracteres NVMe (ej. /dev/nvme0) o un dispositivo de bloques de namespace (ej. /dev/nvme0n1).

Esto solo funcionará en dispositivos Huawei que soporten esta función. Los resultados para cualquier otro dispositivo no están definidos.

En caso de éxito, la estructura puede ser devuelta de varias maneras dependiendo de las opciones; la estructura puede ser analizada por el programa o el buffer crudo puede ser impreso en la salida estándar.

Si el programa debe decodificar la salida para facilitar su lectura, esta versión decodificará las porciones de la estructura únicas del proveedor Huawei.

OPCIONES

-b, --raw-binary

Imprime el buffer crudo en la salida estándar. La estructura no es analizada por el programa. Esto anula las opciones específicas del proveedor y de lectura humana.

-v, --vendor-specific

Además de analizar los campos conocidos, esta opción volcará la región específica del proveedor de la estructura en formato hexadecimal con interpretación ASCII.

-H, --human-readable

Esta opción analizará y formateará muchos de los campos de bits en formatos legibles por humanos.

-o <fmt>, --output-format=<fmt>

Establece el formato de reporte a normal, json o binary. Solo se puede usar un formato de salida a la vez.

EJEMPLOS

•Hacer que el programa interprete el buffer devuelto y muestre los campos conocidos en un formato legible por humanos: 
# nvme huawei id-ctrl /dev/nvme0
