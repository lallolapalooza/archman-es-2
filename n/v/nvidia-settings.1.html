NOMBRE

nvidia-settings - configura el controlador gráfico NVIDIA

SINOPSIS

nvidia-settings [opciones]
nvidia-settings [opciones] --no-config
nvidia-settings [opciones] --load-config-only
nvidia-settings [opciones] {--query=attr | --assign=attr=valor} ...
nvidia-settings [opciones] --glxinfo

Opciones: [-vh] [--config=archivo_config] [-c pantalla_ctrl]
[--verbose={ninguno | errores | deprecaciones | advertencias | todos}]
[--describe={todos | lista | nombre_atributo}]

attr tiene el formato: PANTALLA/nombre_atributo[dispositivos_pantalla]

DESCRIPCIÓN

La utilidad nvidia-settings es una herramienta para configurar el controlador gráfico NVIDIA. Opera comunicándose con el controlador X de NVIDIA, consultando y actualizando el estado según corresponda. Esta comunicación se realiza a través de las extensiones X NV-CONTROL, GLX, XVideo y RandR.

Valores como brillo y gamma, atributos XVideo, temperatura y configuraciones de OpenGL se pueden consultar y configurar a través de nvidia-settings.

Cuando nvidia-settings se inicia, lee la configuración actual de su archivo de configuración y envía esos ajustes al servidor X. Luego, muestra una interfaz gráfica de usuario (GUI) para configurar los ajustes actuales. Cuando nvidia-settings sale, consulta la configuración actual del servidor X y la guarda en el archivo de configuración.

OPCIONES

-v, --version
Imprime la versión de nvidia-settings y sale.
-h, --help
Imprime la información de uso y sale.
--config=CONFIG
Usa el archivo de configuración CONFIG en lugar del predeterminado ~/.nvidia-settings-rc
-c PANTALLA_CTRL, --ctrl-display=PANTALLA_CTRL
Controla la pantalla X especificada. Si esta opción no se proporciona, entonces nvidia-settings controlará la pantalla especificada por '--display'; si eso no se proporciona, entonces se utiliza la variable de entorno $DISPLAY.
-l, --load-config-only
Carga el archivo de configuración, envía los valores especificados en él al servidor X y sale. Este modo de operación es útil para colocarlo en tu archivo xinitrc, por ejemplo.
-n, --no-config
No carga el archivo de configuración. Este modo de operación es útil si nvidia-settings tiene dificultades para iniciarse debido a problemas para aplicar la configuración del archivo.
-r, --rewrite-config-file
Escribe la configuración del servidor X en el archivo de configuración y sale, sin iniciar la interfaz gráfica de usuario. Ver la sección EJEMPLOS.
-V VERBOSE, --verbose=VERBOSE
Controla cuánta información se imprime. Los valores válidos son 'ninguno' (no imprimir mensajes de estado), 'errores' (imprimir mensajes de error), 'deprecaciones' (imprimir mensajes de error y de deprecación), 'advertencias' (imprimir mensajes de error, de deprecación y de advertencia), y 'todos' (imprimir mensajes de error, de deprecación, de advertencia y otros mensajes informativos). Por defecto, se establece 'deprecaciones'.
-a ASIGNACION, --assign=ASIGNACION
El argumento ASIGNACION de la opción de línea de comandos '--assign' tiene el formato:


{PANTALLA}/{nombre_atributo}[{dispositivos_pantalla}]={valor}

Esto asigna el atributo {nombre_atributo} al valor {valor} en la Pantalla X {PANTALLA}. {PANTALLA} sigue la sintaxis usual de {host}:{pantalla}.{screen} de la variable de entorno DISPLAY y es opcional; cuando no se especifica, se implica siguiendo la misma regla que la opción --ctrl-display. Si la pantalla X no se especifica, la asignación se realiza a todas las pantallas X. Tenga en cuenta que el '/' solo es requerido cuando {PANTALLA} está presente.

{PANTALLA} puede incluir adicionalmente una especificación de destino para dirigir una asignación a algo que no sea una pantalla X. Una especificación de destino está contenida entre corchetes y consiste en un nombre de tipo de destino, dos puntos y el ID del destino. El nombre del tipo de destino puede ser uno de screen , gpu , framelock , fan , thermalsensor , svp , o dpy; el ID del destino es el índice en la lista de destinos (para ese tipo de destino). La especificación de destino se puede usar en {PANTALLA} donde se pueda usar una pantalla X, siguiendo la sintaxis {host}:{pantalla}[{tipo_destino}:{id_destino}]. Consulte la salida de


nvidia-settings -q todos

para obtener información sobre qué tipos de destino se pueden usar con qué atributos. Consulte la salida de


nvidia-settings -q pantallas -q gpus -q framelocks -q ventiladores -q sensores_termicos -q svps -q dpys

para obtener listas de destinos para cada tipo de destino.

La porción [{dispositivos_pantalla}] también es opcional; si no se especifica, el atributo se asigna a todos los dispositivos de pantalla.

Algunos ejemplos:


-a FSAA=5
-a localhost:0.0/DigitalVibrance[CRT-0]=0
--assign="SyncToVBlank=1"
-a [gpu:0]/DigitalVibrance[DFP-1]=63

-q CONSULTA, --query=CONSULTA
El argumento CONSULTA de la opción de línea de comandos '--query' tiene el formato:


{PANTALLA}/{nombre_atributo}[{dispositivos_pantalla}]

Esto consulta el valor actual del atributo {nombre_atributo} en la Pantalla X {PANTALLA}. La sintaxis es la misma que la de la opción '--assign', sin '= {valor}'; especifique '-q pantallas', '-q gpus', '-q framelocks', '-q ventiladores', '-q sensores_termicos', '-q svps', o '-q dpys' para consultar una lista de pantallas X, GPUs, dispositivos Frame Lock, Sistemas de Computación Visual, Dispositivos, Ventiladores, Sensores Térmicos, Transceptores 3D Vision Pro o Dispositivos de Pantalla, respectivamente, que estén presentes en la Pantalla X {PANTALLA}. Especifique '-q todos' para consultar todos los atributos.

-t, --terse
Al consultar valores de atributos con la opción de línea de comandos '--query', solo imprima el valor actual, en lugar de la descripción más detallada del atributo, sus valores válidos y su valor actual.
-d, --display-device-string
Al imprimir valores de atributos en respuesta a la opción '--query', si el valor del atributo es una máscara de dispositivo de pantalla, imprima el valor como una lista de dispositivos de pantalla (por ejemplo, "CRT-0, DFP-0"), en lugar de una máscara de bits hexadecimal (por ejemplo, 0x00010001).
-g, --glxinfo
Imprime Información GLX para la pantalla X y sale.
-E, --eglinfo
Imprime Información EGL para la pantalla X y sale.
-k, --vulkaninfo
Imprime Información Vulkan para la pantalla X y sale.
-e DESCRIBIR, --describe=DESCRIBIR
Imprime información sobre un atributo particular. Especifique 'todos' para listar las descripciones de todos los atributos. Especifique 'lista' para listar los nombres de los atributos sin descripciones.
-p PAGINA, --page=PAGINA
El argumento PAGINA de la opción de línea de comandos '--page' selecciona una página particular en la interfaz de usuario de nvidia-settings para mostrar al iniciar nvidia-settings. Los valores válidos son los nombres de página en la vista de árbol en el lado izquierdo de la interfaz de usuario de nvidia-settings; por ejemplo,


--page="Pantalla X 0"

4. SINTAXIS DE CONSULTA Y ASIGNACIÓN

El comando nvidia-settings puede ser invocado desde la línea de comandos para consultar o asignar valores a atributos del controlador NVIDIA. La sintaxis general para consultar es:

        nvidia-settings --query <atributo> [<atributo>]...

Y para asignar un valor a un atributo:

        nvidia-settings --assign <atributo>=<valor> [<atributo>=<valor>]...

Los atributos pueden ser especificados como un nombre simple, o con una especificación de destino más compleja. Un destino puede especificar un tipo de destino y un ID de destino.

Los tipos de destino soportados incluyen:

gpu
target para una GPU
dpy
target para una pantalla de X (display)
tv
target para un dispositivo de TV-out
ccd
target para un chip de color
desktop
target para un escritorio
engine
target para un motor de renderizado
framelock
target para un dispositivo de bloqueo de fotogramas
fan
target para un ventilador
thermalsensor
target para un sensor térmico
s v p
target para un SVP
dm
target para un dispositivo de monitor
pd
target para un dispositivo de pantalla
dfp
target para una pantalla plana digital
connector
target para un conector

Un ID de destino es un entero que identifica una instancia específica de un tipo de destino. Por ejemplo, para consultar el atributo DigitalVibrance del primer DVI-I de salida conectado, podrías escribir:

nvidia-settings --query [DVI-I-1]/DigitalVibrance

El nombre del destino también puede ser simplemente un nombre de tipo de destino, en cuyo caso se consultarán todos los destinos de ese tipo. Por ejemplo, consultar el BusRate de todas las GPUs se puede hacer así:

nvidia-settings --query [gpu]/BusRate

La especificación del destino también puede incluir un calificador de destino. Esto es útil para limitar el procesamiento a un subconjunto de destinos, basándose en una relación existente con otros destinos. El calificador de destino se especifica anteponiendo un nombre de tipo de destino, dos puntos, el ID del destino y un punto a la especificación existente. Solo se puede especificar un calificador.

Por ejemplo, consultar el RefreshRate de todos los dispositivos DFP en la GPU 1 se puede hacer así:

nvidia-settings --query [GPU:1.DPY:DFP]/RefreshRate

Del mismo modo, un nombre de destino simple (o un nombre de tipo de destino) puede usarse como calificador. Por ejemplo, para consultar el BusType de todas las GPUs que tienen DFPs se puede hacer así:

nvidia-settings --query [DFP.GPU]/BusType

Consulta la salida de

        nvidia-settings --query all

para ver qué tipos de destino se pueden usar con cada atributo. Consulta la salida de

        nvidia-settings --query screens --query gpus --query framelocks --query fans --query thermalsensors --query svps --query dpys

para obtener listas de destinos para cada tipo de destino.

Para habilitar el soporte para los atributos "GPUGraphicsClockOffset" y "GPUMemoryTransferRateOffset", asegúrate de que la opción de configuración X "Coolbits" incluya el valor "8" en la máscara de bits. Para más detalles, consulta la documentación de la opción "Coolbits" en el archivo README del controlador NVIDIA. Consulta el atributo de cadena "GPUPerfModes" para ver una lista de los modos de rendimiento disponibles:

nvidia-settings --query GPUPerfModes

Cada modo de rendimiento se presenta como una lista separada por comas de pares "token=valor". Cada conjunto de tokens de modo de rendimiento está separado por un ";". El token "perf" indica el nivel de rendimiento. Los tokens "*editable" indican qué dominios dentro del nivel de rendimiento pueden tener un desplazamiento aplicado. Los atributos "GPUGraphicsClockOffset" y "GPUMemoryTransferRateOffset" se mapean respectivamente a los tokens "nvclock" y "memtransferrate" de los niveles de rendimiento en la cadena "GPUPerfModes".

Ten en cuenta que los atributos de manipulación de reloj "GPUGraphicsClockOffset" y "GPUMemoryTransferRateOffset" se aplican a los desplazamientos de niveles de rendimiento específicos. El nivel de rendimiento se especifica entre corchetes después del nombre del atributo. Por ejemplo, para consultar el "GPUGraphicsClockOffset" para el nivel de rendimiento 2:

nvidia-settings --query GPUGraphicsClockOffset[2]

La opción --assign se puede usar para asignar un nuevo valor a un atributo. Los valores válidos para un atributo se informan cuando se consulta el atributo. La sintaxis para --assign es la misma que para --query, con el requisito adicional de que las asignaciones también tengan un signo igual y el nuevo valor. Por ejemplo:

        nvidia-settings --assign FSAA=2
        nvidia-settings --assign [CRT-1]/DigitalVibrance=9
        nvidia-settings --assign [gpu:0]/DigitalVibrance=0
        nvidia-settings --assign [gpu:0]/GPUGraphicsClockOffset[2]=10

Se pueden especificar múltiples consultas y asignaciones en la línea de comandos para una única invocación de nvidia-settings. Las asignaciones se procesan en el orden en que se introducen en la línea de comandos. Si se realizan múltiples asignaciones al mismo atributo o a múltiples atributos con dependencias, las asignaciones posteriores tendrán prioridad.

Si se pasan las opciones --query o --assign a nvidia-settings, no se presentará la GUI y nvidia-settings saldrá después de procesar las asignaciones y/o consultas. En este caso, la configuración contenida en el archivo de configuración ~/.nvidia-settings-rc no se cargará automáticamente en el servidor X, ni se actualizará automáticamente el archivo de configuración ~/.nvidia-settings-rc para reflejar las asignaciones de atributos hechas a través de la opción --assign.

5. NOMBRES DE PANTALLA X EN EL ARCHIVO DE CONFIGURACIÓN

En la sección de Interfaz de Línea de Comandos de arriba, se señaló que puedes especificar un atributo sin calificadores de Pantalla X, solo con un calificador de pantalla X, o con un nombre de Pantalla X completo. Por ejemplo:

        nvidia-settings --query FSAA
        nvidia-settings --query 0/FSAA
        nvidia-settings --query alpha.example.org:0/FSAA

En los dos primeros casos, se usará la Pantalla X predeterminada, en el segundo caso, se puede anular la pantalla de la Pantalla X predeterminada, y en el tercer caso, se puede anular toda la Pantalla X predeterminada.

Las mismas posibilidades están disponibles en el archivo de configuración ~/.nvidia-settings-rc.

Por ejemplo, en un entorno de laboratorio de computación, podrías iniciar sesión en cualquiera de las múltiples estaciones de trabajo, y tu directorio de inicio se monta a través de NFS en cada estación de trabajo. En tal situación, podrías querer que tu archivo ~/.nvidia-settings-rc sea aplicable a todas las estaciones de trabajo. Por lo tanto, no querrías que tu archivo de configuración califique cada atributo con un Nombre de Pantalla X. Deja la opción "Incluir Nombres de Pantalla X en el Archivo de Configuración" desmarcada en la página de Configuración de nvidia-settings (esta es la opción predeterminada).

Puede haber casos en los que sí quieras que los atributos en el archivo de configuración sean calificados con el nombre de la Pantalla X. Si sabes lo que estás haciendo y quieres que los atributos del archivo de configuración sean calificados con una Pantalla X, marca la opción "Incluir Nombres de Pantalla X en el Archivo de Configuración" en la página de Configuración de nvidia-settings.

En el entorno típico de usuario doméstico donde tu directorio de inicio es local a una computadora y solo estás configurando una Pantalla X, entonces no importa si la configuración de cada atributo está calificada con un Nombre de Pantalla X.

6. CONEXIÓN A SERVIDORES X REMOTO

nvidia-settings es un cliente X, pero utiliza dos conexiones X separadas: una para mostrar la GUI y otra para comunicar las solicitudes NV-CONTROL. Estas dos conexiones X no necesitan ser al mismo servidor X. Por ejemplo, podrías ejecutar nvidia-settings en la computadora alpha.example.org, exportar la pantalla a la computadora beta.example.org, pero estar configurando el servidor X en la computadora gamma.example.org:

        nvidia-settings --display=beta.example.org:0 \
            --ctrl-display=gamma.example.org:0

Si no se especifica --ctrl-display, entonces la Pantalla X a controlar es la que indica --display. Si tampoco se especifica --display, entonces se usa la variable de entorno $DISPLAY.

Ten en cuenta, sin embargo, que necesitarás tener permisos X configurados de tal manera que puedas establecer una conexión X desde la computadora en la que estás ejecutando nvidia-settings (alpha.example.org) a la computadora donde estás mostrando la GUI (beta.example.org) y a la computadora cuya Pantalla X estás configurando (gamma.example.org).

El mecanismo más simple, común y menos seguro para hacer esto es usar 'xhost' para permitir el acceso desde la computadora en la que estás ejecutando nvidia-settings.

        (emitido desde beta.example.org)
        xhost +alpha.example.org
        (emitido desde gamma.example.org)
        xhost +alpha.example.org

Esto permitirá que todos los clientes X ejecutados en alpha.example.org se conecten y muestren en el servidor X de beta.example.org y configuren el servidor X de gamma.example.org.

Por favor, consulta las páginas man de xauth(1) y xhost(1), o consulta la documentación de tu sistema sobre aplicaciones X remotas y seguridad. También podrías buscar en Google términos como "seguridad X remota" o "Ventanas X remotas", y ver documentos como el mini-HOWTO de Aplicaciones X Remotas:


⟨ http://www.tldp.org/HOWTO/Remote-X-Apps.html ⟩

Por favor, ten en cuenta también que el servidor X remoto a controlar debe estar usando el controlador X de NVIDIA.

7. LICENCIA

El código fuente de nvidia-settings se publica bajo la GPL. La versión oficial más reciente del código fuente está disponible aquí:


⟨ https://download.nvidia.com/XFree86/nvidia-settings/ ⟩

Ten en cuenta que nvidia-settings es simplemente un cliente NV-CONTROL. Utiliza la extensión X NV-CONTROL para comunicarse con el servidor X de NVIDIA para consultar la configuración actual y realizar cambios en la configuración.

Puedes hacer adiciones directamente a nvidia-settings, o escribir tu propio cliente NV-CONTROL, usando nvidia-settings como ejemplo.

La documentación sobre la extensión NV-CONTROL y clientes de ejemplo adicionales están disponibles en el archivo tar de la fuente de nvidia-settings. Los parches se pueden enviar a linux-bugs@nvidia.com.

nvidia-settings --load-config-only
Carga la configuración almacenada en ~/.nvidia-settings-rc y sale.
nvidia-settings --rewrite-config-file
Escribe la configuración actual del servidor X en ~/.nv

EJEMPLOS

nvidia-settings --assign CurrentMetaMode="GPU-0.DPY-1.<X>x<Y>@<RefreshRate> { ViewportIn: 0 0 1920 1080 } { ViewportOut: 0 0 1920 1080 }"
Esto establece el modo meta actual a una resolución específica y frecuencia de actualización. Reemplace <X>, <Y> y <RefreshRate> con los valores deseados. El modo meta le permite configurar pantallas conectadas a la misma GPU de formas complejas, como la combinación de múltiples pantallas en una sola pantalla lógica. Por defecto, este valor se guarda en el archivo ~/.nvidia-settings-rc y sale.
nvidia-settings --query FSAA
Consulta el valor de la configuración de antialiasing de pantalla completa (FSAA).
nvidia-settings --assign RedGamma=2.0 --assign BlueGamma=2.0 --assign GreenGamma=2.0
Establece la gamma de la pantalla a 2.0.
