NOMBRE

nvme-read - Envía un comando NVMe Read, proporciona resultados

SINOPSIS

nvme-read <dispositivo> [--start-block=<slba> | -s <slba>]
                        [--block-count=<nlb> | -c <nlb>]
                        [--block-size=<tamaño> | -b <tamaño>]
                        [--data-size=<tamaño> | -z <tamaño>]
                        [--metadata-size=<tamaño> | -y <tamaño>]
                        [--ref-tag=<etiqueta-ref> | -r <etiqueta-ref>]
                        [--data=<archivo-datos> | -d <archivo-datos>]
                        [--metadata=<archivo-metadatos> | -M <archivo-metadatos>]
                        [--prinfo=<prinfo> | -p <prinfo>]
                        [--app-tag-mask=<máscara-app> | -m <máscara-app>]
                        [--app-tag=<etiqueta-app> | -a <etiqueta-app>]
                        [--limited-retry | -l] [--force-unit-access | -f]
                        [--dir-type=<tipo> | -T <tipo>]
                        [--dir-spec=<espec> | -S <espec>] [--dsm=<dsm> | -D <dsm>]
                        [--show-command | -V] [--dry-run | -w] [--latency | -t]
                        [--storage-tag<etiqueta-almacenamiento> | -g <etiqueta-almacenamiento>]
                        [--storage-tag-check | -C] [--force]
                        [--output-format=<fmt> | -o <fmt>] [--verbose | -v]
                        [--timeout=<timeout>]

DESCRIPCIÓN

El comando Read lee los bloques lógicos especificados por el comando desde el medio y los copia al búfer de datos de datos proporcionado. Utilizará stdout por defecto si no proporcionas un archivo.

OPCIONES

-s <slba>, --start-block=<slba>

Bloque de inicio.

-c, --block-count

El número de bloques a transferir. Este es un valor basado en ceros para alinearse con el uso que hace el kernel de este campo. (es decir, 0 significa transferir 1 bloque).

-b <tamaño>, --block-size=<tamaño>

Si se especifica, el tamaño del bloque lógico en bytes, con metatamaño describiendo también el tamaño de metadatos para un bloque individual. Se descubre mediante identify namespace de lo contrario.

-z <tamaño>, --data-size=<tamaño>

Tamaño de los datos, en bytes.

-y <tamaño>, --metadata-size=<tamaño>

Tamaño de los metadatos en bytes.

-d <archivo-datos>, --data=<archivo-datos>

Archivo de datos. Si no se proporciona ninguno, los contenidos se envían a STDOUT.

-M <archivo-metadatos>, --metadata=<archivo-metadatos>

Archivo de metadatos, si es necesario.

-p <prinfo>, --prinfo=<prinfo>

Definición del campo de Información de Protección.
Bit Descripción
3 PRACT: Acción de Información de Protección. Cuando se establece en 1, PI se elimina/inserta en lectura/escritura cuando el tamaño de metadatos del formato de bloque es 8. Cuando se establece en 0, los metadatos se pasan.
2:0 PRCHK: Verificación de Información de Protección:
2 Establecido en 1 habilita la verificación de la etiqueta de guardia
1 Establecido en 1 habilita la verificación de la etiqueta de aplicación
0 Establecido en 1 habilita la verificación de la etiqueta de referencia

-r <etiqueta-ref>, --ref-tag=<etiqueta-ref>

Etiqueta de referencia opcional cuando se usa con información de protección.

-m <máscara-app>, --app-tag-mask=<máscara-app>

Máscara de etiqueta de aplicación opcional cuando se usa con información de protección.

-f, --force-unit-access

Establece el indicador force-unit access.

-T <tipo>, --dir-type=<tipo>

Tipo de directiva opcional. La herramienta nvme-cli solo verifica que el valor esté en el rango definido para el tipo de directiva, aunque la especificación NVMe (1.3a) define solo una directiva, 01h, para los identificadores de flujo de escritura.

-S <espec>, --dir-spec=<espec>

Campo opcional para las especificaciones de la directiva. Cuando se usa con flujos de escritura, este valor se define como el identificador del flujo de escritura. La herramienta nvme-cli no validará si el flujo solicitado está dentro de las capacidades del controlador.

-D <dsm>, --dsm=<dsm>

Los atributos opcionales de gestión del conjunto de datos para este comando. El argumento para esto son los 8 bits menos significativos del campo DSM en un comando de escritura; los 16 bits más significativos del campo provienen del campo específico de la directiva, si se utiliza. Esto puede usarse para establecer atributos para los LBA que se están escribiendo, como frecuencia de acceso, tipo, latencia, entre otras cosas, así como tipos aún por definir. Consulte la especificación NVMe para un desglose detallado de cómo usar este campo.

-V, --show-cmd

Imprime el comando que se enviará.

-w, --dry-run

No envíes el comando realmente. Si quieres usar la opción --dry-run, la opción --show-cmd *debe* estar establecida. De lo contrario, la opción --dry-run será *ignorada*.

-t, --latency

Imprime la latencia que tardó la llamada IOCTL (en microsegundos).

-g <etiqueta-almacenamiento>, --storage-tag=<etiqueta-almacenamiento>

Etiqueta de Almacenamiento Lógico de Tamaño Variable Esperado (ELBST).

-C, --storage-tag-check

Este indicador habilita la verificación del campo Etiqueta de Almacenamiento como parte del procesamiento de protección de datos de extremo a extremo.

--force

Ignora que el namespace esté actualmente ocupado y realiza la operación a pesar de ello.

-o <fmt>, --output-format=<fmt>

Establece el formato de informe en normal, json o binary. Solo se puede usar un formato de salida a la vez.

-v, --verbose

Aumenta el detalle de la información en la salida.

--timeout=<timeout>

Anula el valor de tiempo de espera predeterminado. En milisegundos.
