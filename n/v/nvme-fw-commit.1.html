NOMBRE

nvme-fw-commit - Se utiliza para verificar y confirmar una imagen de firmware.

SINOPSIS

nvme fw-commit <dispositivo> [--slot=<slot> | -s <slot>]
                        [--action=<action> | -a <action>]
                        [--bpid=<boot-partid> | -b <boot-partid>]
                        [--output-format=<fmt> | -o <fmt>] [--verbose | -v]
                        [--timeout=<timeout> | -t <timeout>]

DESCRIPCIÓN

Para el dispositivo NVMe dado, envía un comando de administración de confirmación de firmware nvme y proporciona los resultados.

El comando de Confirmación de Firmware se utiliza para verificar que se ha descargado una imagen de firmware válida y para confirmar esa revisión en una ranura de firmware específica. El host puede seleccionar la imagen de firmware a confirmar en el próximo reinicio del controlador (CC.EN transiciones de '1' a '0', un reinicio a nivel de función PCI y/u otros reinicios del controlador o del subsistema NVM) como parte de este comando. La revisión de firmware que se está ejecutando actualmente se puede determinar a partir del campo Revisión de Firmware de la estructura de datos Identify Controller, como se indica en la página de registro de Información de Ranura de Firmware.

No se toma ninguna acción adicional automáticamente para reiniciar el dispositivo, lo cual generalmente se requiere para completar el proceso de activación. Si su kernel y controlador son lo suficientemente recientes, puede confirmar el firmware emitiendo un reinicio a través de sysfs de Linux, por ejemplo:

 # echo 1 > /sys/class/nvme/nvme0/device/reset

Si su kernel no es lo suficientemente reciente, deberá eliminar y agregar el dispositivo de alguna otra manera.

OPCIONES

-a <acción>, --action=<acción>

Acción de Confirmación: Este campo especifica la acción que se toma sobre la imagen descargada con el comando Firmware Image Download o sobre una imagen descargada y colocada previamente.
Valor Definición
0 La imagen descargada reemplaza la imagen indicada por el campo Firmware Slot. Esta imagen no se activa.
1 La imagen descargada reemplaza la imagen indicada por el campo Firmware Slot. Esta imagen se activa en el próximo reinicio.
2 La imagen indicada por el campo Firmware Slot se activa en el próximo reinicio.
3 Se solicita que la imagen especificada por el campo Firmware Slot se active inmediatamente sin reinicio.
6 La imagen descargada reemplaza la Partición de Arranque especificada por el campo Boot Partition ID.
7 Marcar la Partición de Arranque especificada en el campo BPID como activa y actualizar BPINFO.ABPID.

-s <slot>, --slot=<slot>

Ranura de Firmware: Especifica la ranura de firmware que se utilizará para la Acción de Confirmación, si corresponde. Si el valor especificado es 0h, entonces el controlador elegirá la ranura de firmware (ranuras 1 - 7) a utilizar para la operación.

--bpid=<id-partición-arranque>, -b <id-partición-arranque>

Especifica la partición de Arranque que se utilizará para la Acción de Confirmación, si corresponde (por defecto: 0).

-o <fmt>, --output-format=<fmt>

Establece el formato de informe en normal, json o binary. Solo se puede usar un formato de salida a la vez.

-v, --verbose

Aumenta el nivel de detalle de la información en la salida.

-t <timeout>, --timeout=<timeout>

Anula el valor de tiempo de espera predeterminado. En milisegundos.

EJEMPLOS

• confirmar el último firmware descargado en la ranura 1. 
# nvme fw-commit /dev/nvme0 --slot=1 --action=2
