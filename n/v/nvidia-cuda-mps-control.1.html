nvidia-cuda-mps-control(1) NVIDIA nvidia-cuda-mps-control(1)

NOMBRE

nvidia-cuda-mps-control - Programa de gestión del Servicio Multi-Proceso de NVIDIA CUDA

SINOPSIS

nvidia-cuda-mps-control [-d | -f]

DESCRIPCIÓN

MPS es un servicio en tiempo de ejecución diseñado para permitir que múltiples procesos MPI que utilizan CUDA se ejecuten concurrentemente de una manera transparente para el programa MPI. Un programa CUDA se ejecuta en modo MPS si el demonio de control MPS se está ejecutando en el sistema.

Cuando CUDA se inicializa por primera vez en un programa, el controlador CUDA intenta conectarse al demonio de control MPS. Si el intento de conexión falla, el programa continúa ejecutándose como lo haría normalmente sin MPS. Si, sin embargo, el intento de conexión al demonio de control tiene éxito, el controlador CUDA solicita al demonio que inicie un servidor MPS en su nombre. Si ya hay un servidor MPS en ejecución y el ID de usuario de ese proceso servidor coincide con el del proceso cliente solicitante, el demonio de control simplemente se lo notifica al proceso cliente, que luego procede a conectarse al servidor. Si no hay ningún servidor MPS en ejecución en el sistema, el demonio de control inicia un servidor MPS con el mismo ID de usuario (UID) que el del proceso cliente solicitante. Si ya hay un servidor MPS en ejecución, pero con un ID de usuario diferente al del proceso cliente, el demonio de control solicita al servidor existente que se apague tan pronto como todos sus clientes hayan terminado. Una vez que el servidor existente se ha terminado, el demonio de control inicia un nuevo servidor con el ID de usuario igual al del proceso cliente en cola.

El servidor MPS crea el contexto de GPU compartido y gestiona sus clientes. Un servidor MPS puede admitir una cantidad finita de contextos CUDA determinada por la arquitectura de hardware en la que se está ejecutando. Para la capacidad de cómputo SM 3.5 a SM 6.0, el límite es de 16 clientes por GPU a la vez. La capacidad de cómputo SM 7.0 tiene un límite de 48. MPS es transparente para los programas CUDA, con toda la complejidad de la comunicación entre el proceso cliente, el servidor y el demonio de control oculta dentro de los binarios del controlador.

Actualmente, CUDA MPS solo está disponible en Linux de 64 bits, requiere un dispositivo que admita la dirección virtual unificada (UVA) y tenga una capacidad de cómputo SM 3.5 o superior. Las aplicaciones que requieren APIs anteriores a CUDA 4.0 no son compatibles con CUDA MPS. Ciertas capacidades solo están disponibles a partir de la capacidad de cómputo SM 7.0.

Consulte la documentación de MPS en NVIDiA Docs para obtener más detalles.

OPCIONES

-d

Inicia el demonio de control MPS en modo de segundo plano, asumiendo que el usuario tiene suficiente privilegio (por ejemplo, root). El proceso padre sale cuando el demonio de control ha comenzado a escuchar las conexiones de los clientes.

-f

Inicia el demonio de control MPS en modo de primer plano, asumiendo que el usuario tiene suficiente privilegio (por ejemplo, root). Los mensajes de depuración se envían a la salida estándar.

-multiuser-server

Relaja el requisito de un solo UID de usuario, permitiendo que cualquier UID se conecte y comparta un servidor MPS iniciado como root.

-h, --help

Imprime un mensaje de ayuda.

<sin argumentos>

Inicia la interfaz de usuario de gestión de front-end para el demonio de control MPS, que debe iniciarse primero. La interfaz de usuario de front-end sigue leyendo comandos desde la entrada estándar hasta EOF. Los comandos están separados por el carácter de nueva línea. Si se emite un comando inválido y es rechazado, se imprimirá un mensaje de error en stdout. El estado de salida de la interfaz de usuario de front-end es cero si la comunicación con el demonio es exitosa. Se devuelve un valor distinto de cero si no se encuentra el demonio o si la conexión con el demonio se interrumpe inesperadamente. Consulte el comando "quit" a continuación para obtener más información sobre el estado de salida.

Comandos compatibles con el demonio de control MPS:

obtener_lista_servidores
Imprime una lista de PIDs de todos los servidores MPS.
obtener_estado_servidor PID
Imprime el estado del servidor con el PID dado.
iniciar_servidor -uid UID
Inicia un nuevo servidor MPS para el usuario especificado (UID).
apagar_servidor PID [-f]
Apaga el servidor MPS con el PID dado. El servidor MPS solo sale después de que todos los clientes se desconectan y el servidor MPS puede aceptar nuevos clientes mientras hay un cliente conectado. -f fuerza un apagado inmediato. Si un cliente inicia un kernel defectuoso que se ejecuta para siempre, puede ser necesario un apagado forzado del servidor MPS, ya que el servidor MPS crea y emite trabajo de GPU en nombre de sus clientes.
obtener_lista_clientes PID
Imprime una lista de PIDs de todos los clientes conectados al servidor MPS con el PID dado.
salir [-t TIEMPO_ESPERA]
Apaga el proceso demonio de control MPS y todos los servidores MPS. El demonio de control MPS deja de aceptar nuevos clientes mientras espera que los servidores MPS y los clientes MPS actuales terminen. Si se especifica TIEMPO_ESPERA (en segundos), el demonio forzará el apagado de los servidores MPS si todavía están en ejecución después de TIEMPO_ESPERA segundos.

Este comando es síncrono. La interfaz de usuario de front-end espera a que el demonio se apague y luego devuelve el estado de salida del demonio. El estado de salida es cero si todos los servidores MPS han salido correctamente.

Comandos disponibles para el demonio de control MPS de Volta:
obtener_lista_clientes_dispositivo PID
Enumera los dispositivos y PIDs de las aplicaciones cliente que enumeraron este dispositivo. Opcionalmente, toma el PID de la instancia del servidor.
establecer_porcentaje_hilos_activos_predeterminado porcentaje
Establece el porcentaje de hilos activos predeterminado para los servidores MPS. Si ya hay un servidor iniciado, este comando solo afectará al próximo servidor. El valor establecido se pierde si se ejecuta un comando de salida. El valor predeterminado es 100.
obtener_porcentaje_hilos_activos_predeterminado
Consulta el porcentaje actual de hilos disponibles predeterminado.
establecer_porcentaje_hilos_activos PID porcentaje
Establece el porcentaje de hilos activos para la instancia del servidor MPS del PID dado. Todos los clientes creados con ese servidor posteriormente observarán el nuevo límite. Los clientes existentes no se ven afectados.
obtener_porcentaje_hilos_activos PID
Consulta el porcentaje actual de hilos disponibles de la instancia del servidor MPS del PID dado.
establecer_limite_memoria_fijada_dispositivo_predeterminado dev valor
Establece el límite de memoria fijada del dispositivo predeterminado para los servidores MPS. Si ya hay un servidor iniciado, este comando solo afectará al próximo servidor. El valor debe tener la forma de un entero seguido de un calificador, ya sea "G" o "M", que especifica el valor en Gigabytes o Megabytes respectivamente.
obtener_limite_memoria_fijada_dispositivo_predeterminado dev
Consulta el límite actual de memoria fijada predeterminado para el dispositivo.
establecer_limite_memoria_fijada_dispositivo PID dev valor
Sobrescribe el límite de memoria fijada del dispositivo para el servidor MPS del PID dado. Todos los clientes creados con ese servidor posteriormente observarán el nuevo límite. Los clientes existentes no se ven afectados.

nvidia-cuda-mps-control(1) - Arch Linux Man Pages

NAME

nvidia-cuda-mps-control - control the NVIDIA CUDA Multi-Process Service

SYNOPSIS

nvidia-cuda-mps-control [ -d | -k | -k server PID ] [ -h | --help ]

DESCRIPTION

The nvidia-cuda-mps-control utility provides a way to control the NVIDIA CUDA Multi-Process Service (MPS). MPS allows multiple client processes to share a single GPU. The MPS control daemon is a daemon that manages MPS servers. MPS servers, in turn, manage MPS clients.

MPS is intended to improve GPU utilization by allowing multiple CUDA client processes to share a single GPU. Without MPS, only one client process can use a GPU at a time.

MPS can improve GPU utilization in situations where multiple processes are running concurrently and each process would otherwise use only a fraction of the GPU's compute capacity.

MPS is not a replacement for CUDA streams or CUDA events. It is designed to improve GPU utilization when multiple independent processes are using the GPU. For applications that need to achieve the highest possible performance for a single task, MPS may reduce performance.

OPTIONS

-d
Starts the MPS control daemon in the foreground. The MPS control daemon must be running for clients to connect to it.
-k [server PID]
Terminates the MPS control daemon. If server PID is specified, only the specified MPS server process is terminated. If server PID is not specified, all MPS server processes are terminated, and the MPS control daemon is shut down. Note that this will also terminate all MPS clients currently running on the specified server or all servers.
-h | --help
Prints a usage message and exits.

The following commands can be issued to the MPS control daemon while it is running:

get_num_mps_servers
Query the number of MPS server processes currently running.
get_mps_server_pids
Query the PIDs of all MPS server processes currently running.
get_client_pids [server PID]
Query the PIDs of all client processes connected to the MPS server process specified by server PID. If server PID is not specified, it queries the PIDs of all client processes connected to any MPS server.
get_client_processes [server PID]
Reports a snapshot of the current client processes connected to the MPS server process specified by server PID. If server PID is not specified, it reports the status of clients connected to all MPS servers. The output format is similar to the ps command.
get_default_device_pinned_mem_limit PID dev
Query the current device pinned memory limit of the MPS server instance of the given PID for the device dev.
terminate_client server PID client PID
Terminates all the outstanding GPU work of the MPS client process of the given client PID running on the MPS server denoted by <server PID>.
ps [-p PID]
Reports a snapshot of the current client processes.
set_default_client_priority priority
Set the client priority level that will be used for new clients. Priority values are only considered as hints to the CUDA driver and can be ignored or overriden depending on platform. priority follows a convention where smaller numbers are higher priorities, and the default priority value is 0. The only other supported value for priority is 1, which represents a below-normal priority level.
get_default_client_priority
Query the current priority value that will be used for new clients.

ENVIRONMENT

CUDA_MPS_PIPE_DIRECTORY
Specify the directory that contains the named pipes and UNIX domain sockets used for communication among the MPS control, MPS server, and MPS clients. The value of this environment variable should be consistent in the MPS control daemon and all MPS client processes. Default directory is /tmp/nvidia-mps
CUDA_MPS_LOG_DIRECTORY
Specify the directory that contains the MPS log files. This variable is used by the MPS control daemon only. Default directory is /var/log/nvidia-mps
CUDA_VISIBLE_DEVICES
Specify which CUDA devices are visible to the control daemon. Takes either an index value or UUID.
CUDA_DEVICE_MAX_CONNECTIONS
Specify the preferred number of connections between the host and device.
CUDA_MPS_ACTIVE_THREAD_PERCENTAGE
Specify the portion of available threads that clients can use on Volta+ hardware. Setting this for the control daemon will set the default active thread percentage for all servers spawned, while setting this for a client or client context will constrain the active thread percentage for that unit and cannot be higher than the active thread percentage value set for the control daemon.
CUDA_MPS_ENABLE_PER_CTX_DEVICE_MULTIPROCESSOR_PARTITIONING
Specify whether individual client contexts are allowed to have different values for CUDA_MPS_ACTIVE_THREAD_PERCENTAGE.
CUDA_MPS_PINNED_DEVICE_MEM_LIMIT
Specify the amount of GPU memory available to MPS client processes.
CUDA_MPS_CLIENT_PRIORITY
Specify the default client priority value at initialization.

FILES

Log files created by the MPS control daemon in the specified directory

control.log
Record startup and shutdown of MPS control daemon, user commands issued with their results, and status of MPS servers.
server.log
Record startup and shutdown of MPS servers, and status of MPS clients.
