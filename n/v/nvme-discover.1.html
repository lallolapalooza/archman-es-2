NVME-DISCOVER(1) Manual NVMe NVME-DISCOVER(1)

NOMBRE

nvme-discover - Envía una solicitud de página de registro Get a un controlador de descubrimiento.

SINOPSIS

nvme discover [--transport=<trtype> | -t <trtype>]
                        [--nqn=<subnqn> | -n <subnqn>]
                        [--traddr=<traddr> | -a <traddr>]
                        [--trsvcid=<trsvcid> | -s <trsvcid>]
                        [--host-traddr=<traddr> | -w <traddr>]
                        [--host-iface=<iface> | -f <iface>]
                        [--hostnqn=<hostnqn> | -q <hostnqn>]
                        [--hostid=<hostid> | -I <hostid>]
                        [--raw=<filename> | -r <filename>]
                        [--device=<device> | -d <device>]
                        [--config=<filename> | -J <filename>]
                        [--keep-alive-tmo=<sec> | -k <sec>]
                        [--reconnect-delay=<#> | -c <#>]
                        [--ctrl-loss-tmo=<#> | -l <#>]
                        [--nr-io-queues=<#> | -i <#>]
                        [--nr-write-queues=<#> | -W <#>]
                        [--nr-poll-queues=<#> | -P <#>]
                        [--queue-size=<#> | -Q <#>] [--keyring=<#>]
                        [--tls_key=<#>] [--hdr-digest | -g] [--data-digest | -G]
                        [--persistent | -p] [--quiet] [--tls] [--concat]
                        [--dump-config | -O] [--output-format=<fmt> | -o <fmt>]
                        [--force] [--nbft] [--no-nbft] [--nbft-path=<STR>]
                        [--context=<STR>]
                        [--output-format=<fmt> | -o <fmt>] [--verbose | -v]

DESCRIPCIÓN

Envía una o más solicitudes de página de registro Get a un controlador de descubrimiento NVMe sobre Fabrics.

Si no se proporcionan parámetros, nvme discover intentará encontrar un archivo /etc/nvme/discovery.conf para usarlo y proporcionar una lista de comandos de descubrimiento para ejecutar. Si no existe el archivo /etc/nvme/discovery.conf, el comando terminará con un error.

De lo contrario, se debe especificar un controlador de descubrimiento específico utilizando las opciones --transport, --traddr y, si es necesario, --trsvcid. Luego, se enviará una solicitud de descubrimiento al controlador de descubrimiento especificado.

ANTECEDENTES

La especificación NVMe sobre Fabrics define el concepto de un Controlador de Descubrimiento que un Host NVMe puede consultar en una red de fabric para descubrir subsistemas NVMe contenidos en Objetivos NVMe a los que puede conectarse en la red. El Controlador de Descubrimiento devolverá Páginas de Registro de Descubrimiento que proporcionarán al Host NVMe información específica (como la dirección de red y el NQN único del subsistema) que el Host NVMe puede usar para emitir un comando de conexión NVMe para conectarse a un recurso de almacenamiento contenido en ese subsistema NVMe en el Objetivo NVMe.

Tenga en cuenta que la especificación base de NVMe define el formato NQN (NVMe Qualified Name) que debe seguir un punto final NVMe (dispositivo, subsistema, etc.) para garantizar un nombre único según el estándar NVMe. En particular, el Host NQN identifica de forma única al Host NVMe y puede ser utilizado por el Controlador de Descubrimiento para controlar qué recursos del Objetivo NVMe se asignan al Host NVMe para una conexión.

Un Controlador de Descubrimiento tiene su propio NQN definido en la especificación NVMe sobre Fabrics, nqn.2014-08.org.nvmexpress.discovery. Todos los Controladores de Descubrimiento deben usar este nombre NQN. Este NQN es utilizado por defecto por nvme-cli para el comando discover.

OPCIONES

-t <trtype>, --transport=<trtype>

Este campo especifica la red de fabric que se está utilizando para una red NVMe sobre Fabrics. Los valores de cadena actuales incluyen:
Valor Definición
rdma La red de fabric es una red rdma (RoCE, iWARP, Infiniband, rdma básico, etc.)
fc EN DESARROLLO La red de fabric es una red Fibre Channel.
tcp La red de fabric es una red TCP/IP.
loop Conectar a un objetivo NVMe sobre Fabrics en el host local

-n <subnqn>, --nqn <subnqn>

Este campo especifica el nombre del subsistema NVMe al que conectarse.

-a <traddr>, --traddr=<traddr>

Este campo especifica la dirección de red del Controlador de Descubrimiento. Para transportes que utilizan direccionamiento IP (por ejemplo, rdma), esta debe ser una dirección basada en IP (por ejemplo, IPv4).

-s <trsvcid>, --trsvcid=<trsvcid>

Este campo especifica el id. de servicio de transporte. Para transportes que utilizan direccionamiento IP (por ejemplo, rdma), este campo es el número de puerto. Por defecto, el número de puerto IP para el transporte RDMA es 4420.

-w <traddr>, --host-traddr=<traddr>

Este campo especifica la dirección de red utilizada en el host para conectarse al Controlador. Para TCP, esto establece la dirección de origen en el socket.

-f <iface>, --host-iface=<iface>

Este campo especifica la interfaz de red utilizada en el host para conectarse al Controlador (por ejemplo, IP eth1, enp2s0, enx78e7d1ea46da). Esto fuerza que la conexión se realice en una interfaz específica en lugar de dejar que el sistema decida.

-q <hostnqn>, --hostnqn=<hostnqn>

Anula el NQN de host predeterminado que identifica al Host NVMe. Si no se especifica esta opción, el valor predeterminado se lee primero de /etc/nvme/hostnqn. Si ese archivo no existe, se utiliza a continuación el valor NQN autogenerado del módulo del kernel del Host NVMe.

-I <hostid>, --hostid=<hostid>

UUID (Identificador Único Universal) a descubrir, que debe estar formateado.

-r <filename>, --raw=<filename>

Este campo tomará la salida del comando nvme discover y la volcará a un archivo binario crudo. Por defecto, nvme discover volcará la salida a stdout.

-d <device>, --device=<device>

Este campo toma un dispositivo como entrada. Debe ser un dispositivo persistente asociado con un Controlador de Descubrimiento creado previamente por el comando "connect-all" o "discover". <device> sigue el formato nvme*, por ejemplo, nvme0, nvme1.

-J <filename>, --config=<filename>

Utilice el archivo de configuración JSON especificado en lugar del archivo predeterminado /etc/nvme/config.json o *none* para no leer un archivo de configuración existente. El formato del archivo de configuración JSON se documenta en https://github.com/linux-nvme/libnvme/blob/master/doc/config-schema.json

-k <#>, --keep-alive-tmo=<#>

Anula el tiempo de espera de latido predeterminado (en segundos). Esta opción se ignorará para el descubrimiento y solo se implementa por completitud.

-c <#>, --reconnect-delay=<#>

Anula el retraso de reconexión predeterminado (en segundos) después de una pérdida de conexión.

-l <#>, --ctrl-loss-tmo=<#>

Anula el período de tiempo de espera de pérdida de controlador predeterminado (en segundos).

-i <#>, --nr-io-queues=<#>

Anula el número predeterminado de colas de E/S creadas por el controlador. Esta opción se ignorará para el descubrimiento y solo se implementa por completitud.

-W <#>, --nr-write-queues=<#>

Añade colas adicionales que se utilizarán para E/S de escritura.

-P <#>, --nr-poll-queues=<#>

Añade colas adicionales que se utilizarán para E/S de baja latencia de sondeo.

-Q <#>, --queue-size=<#>

Anula el número predeterminado de elementos en las colas de E/S creadas por el controlador, que se puede encontrar en drivers/nvme/host/fabrics.h. Esta opción se ignorará para el descubrimiento y solo se implementa por completitud.

--keyring=<#>

Llavero para la búsqueda de claves TLS.

--tls_key=<#>

Clave TLS para la conexión
nvme-discover(8)

NAME

nvme-discover - NVMe discovery controller functions.

SYNOPSIS

nvme discover [generic options] [transport options] [discovery options]

DESCRIPTION

The nvme-discover tool is a low-level tool intended to provide access to the NVMe discovery controller. It allows you to query the discovery controller for information about discoverable controllers and namespaces.

BACKGROUND

The NVMe transport protocol allows for discovery of targets. This protocol uses a discovery controller to announce the available controllers and their associated namespaces. The nvme-discover tool is designed to interact with this discovery controller.

This command is intended to be run as root or with privileges sufficient to open NVMe device access.

OPTIONS

All of the generic nvme(1) options are available, as well as the following:

-t <transport>, --transport=<transport>

The transport type to use for discovery. Supported types are: tcp, rdma, fcp, fabrics.

-a <address>, --traddr=<address>

The transport address of the discovery controller.

-s <port>, --trsvcid=<port>

The transport service identifier (port) of the discovery controller.

-q <hostnqn>, --hostnqn=<hostnqn>

The NVMe Qualified Name (NQN) of the host. This is used to identify the host when connecting to the discovery controller.

-h <subsysnqn>, --subsysnqn=<subsysnqn>

The NVMe Qualified Name (NQN) of the subsystem. This is used to request discovery information for a specific subsystem.

-l, --list

Retrieve and display the list of discoverable controllers and namespaces from the discovery controller.

-d, --delete

Delete an entry from the discovery controller. The entry to delete is specified by the combination of transport address, transport service identifier, and host NQN.

-m, --multipath

Enable multipathing support.

-N, --namespace-report

Retrieve and display namespace information from the discovery controller.

-S, --serial-number

Retrieve and display serial number information from the discovery controller.

-i, --insecure

Disable security (e.g. TLS) for the connection.

-k, --key-revocation-list

Retrieve and display the key revocation list from the discovery controller.

-c, --cert

Retrieve and display the certificate from the discovery controller.

-r, --root-cert

Retrieve and display the root certificate from the discovery controller.

-g, --hdr-digest

Generates/verifies header digest (TCP).

-G, --data-digest

Generates/verifies data digest (TCP).

-p, --persistent

Don’t remove the discovery controller after retrieving the discovery log page.

--tls

Enable TLS encryption (TCP).

--concat

Enable secure concatenation (TCP).

--quiet

Suppress already connected errors.

-O, --dump-config

Print out resulting JSON configuration file to stdout.

-o <fmt>, --output-format=<fmt>

Set the reporting format to normal, json or binary. Only one output format can be used at a time.

--force

Disable the built-in persistent discover connection rules. Combined with --persistent flag, always create new persistent discovery connection.

--nbft

Only look at NBFT tables

--no-nbft

Do not look at NBFT tables

--nbft-path=<STR>

Use a user-defined path to the NBFT tables

--context <STR>

Set the execution context to <STR>. This allows to coordinate the management of the global resources.

-o <fmt>, --output-format=<fmt>

Set the reporting format to normal, json or binary. Only one output format can be used at a time.

-v, --verbose

Increase the information detail in the output.

EXAMPLES

•Query the Discover Controller with IP4 address 192.168.1.3 for all resources allocated for NVMe Host name host1-rogue-nqn on the RDMA network. Port 4420 is used by default: 
# nvme discover --transport=rdma --traddr=192.168.1.3 \
--hostnqn=host1-rogue-nqn
•Issue a nvme discover command using the default system defined NBFT tables: 
# nvme discover --nbft
•Issue a nvme discover command with a user-defined path for the NBFT table: 
# nvme discover --nbft-path=/sys/firmware/acpi/tables/NBFT1
•Issue a nvme discover command using a /etc/nvme/discovery.conf file: 
# Machine default 'nvme discover' commands. Query the
# Discovery Controller's two ports (some resources may only
# be accessible on a single port). Note an official
# nqn (Host) name defined in the NVMe specification is being used
# in this example.
-t rdma -a 192.168.69.33 -s 4420 -q nqn.2014-08.com.example:nvme:nvm-subsystem-sn-d78432
-t rdma -a 192.168.1.4   -s 4420 -q nqn.2014-08.com.example:nvme:nvm-subsystem-sn-d78432
At the prompt type "nvme discover".
