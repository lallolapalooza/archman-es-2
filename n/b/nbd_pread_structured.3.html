Paquete: libnbd

nbd_pread_structured(3) LIBNBD nbd_pread_structured(3)

NOMBRE

nbd_pread_structured - leer desde el servidor NBD

SINOPSIS

#include <libnbd.h>
typedef struct {
  int (*callback) (void *user_data, const void *subbuf,
                   size_t count, uint64_t offset,
                   unsigned status, int *error);
  void *user_data;
  void (*free) (void *user_data);
} nbd_chunk_callback;
int nbd_pread_structured (
      struct nbd_handle *h, void *buf, size_t count,
      uint64_t offset, nbd_chunk_callback chunk_callback,
      uint32_t flags
    );

DESCRIPCIÓN

Emite un comando de lectura al servidor NBD para el rango que comienza en "offset" y termina en "offset" + "count" - 1. La respuesta del servidor puede subdividirse en fragmentos que pueden llegar desordenados antes de reensamblarse en el búfer original; la función de devolución de llamada (callback) de "chunk" se utiliza para notificar después de que llega cada fragmento, y puede realizar verificaciones adicionales en la respuesta del servidor. La función de devolución de llamada no puede llamar a las APIs de "nbd_*" en el mismo manejador (handle) ya que este tiene el bloqueo del manejador y causará un interbloqueo (deadlock). Si la función de devolución de llamada devuelve -1, y no se ha detectado ningún error anterior, el comando de lectura general fallará con cualquier valor distinto de cero almacenado en el parámetro "error" de la función de devolución de llamada (con un valor predeterminado de "EPROTO"); pero los fragmentos posteriores seguirán invocando la función de devolución de llamada.

La función "chunk" se llama una vez por fragmento de datos recibido, con el "user_data" pasado a esta función. Los parámetros "subbuf" y "count" representan el subconjunto del búfer original que acaba de ser poblado con resultados del servidor (en C, "subbuf" siempre apunta dentro del "buf" original; pero esta garantía puede no extenderse a otros enlaces de lenguaje). El parámetro "offset" representa el desplazamiento absoluto en el que "subbuf" comienza dentro de la imagen (tenga en cuenta que este no es el desplazamiento relativo de "subbuf" dentro del búfer original "buf"). Los cambios en "error" en la salida se ignoran a menos que la función de devolución de llamada falle. El significado de entrada del parámetro "error" está controlado por el parámetro "status", que es uno de:

"LIBNBD_READ_DATA" = 1
"subbuf" se pobló con "count" bytes de datos. En la entrada, "error" contiene el valor errno de cualquier error detectado previamente, o cero.
"LIBNBD_READ_HOLE" = 2
"subbuf" representa un agujero (hole), y contiene "count" bytes NUL. En la entrada, "error" contiene el valor errno de cualquier error detectado previamente, o cero.
"LIBNBD_READ_ERROR" = 3
"count" es 0, por lo que "subbuf" no se puede utilizar. En la entrada, "error" contiene el valor errno reportado por el servidor como ocurrido al leer ese "offset", independientemente de si se ha detectado algún error anterior.

Las futuras extensiones de NBD pueden permitir otros valores para "status", pero esos no se devolverán a un cliente que no haya optado por solicitar dichas extensiones. Si el servidor no cumple con las especificaciones, es posible que la función "chunk" se llame más veces de las que espera o con "count" 0 para "LIBNBD_READ_DATA" o "LIBNBD_READ_HOLE". También es posible que la función "chunk" no se llame en absoluto (en particular, "LIBNBD_READ_ERROR" se usa solo cuando un error está asociado con un desplazamiento particular, y no cuando el servidor informa un error genérico), pero se garantiza que la función de devolución de llamada se llamó al menos una vez si la lectura general tuvo éxito. Libnbd no valida que el servidor haya obedecido el requisito de que una llamada de lectura no debe tener fragmentos superpuestos y no debe tener éxito sin suficientes fragmentos para cubrir toda la solicitud.

Tenga en cuenta que libnbd actualmente impone un tamaño máximo de búfer de lectura de 64MiB, incluso si el servidor permitiera un búfer más grande en una sola transacción; los intentos de exceder esto resultarán en un error "ERANGE". El servidor puede imponer un límite menor, que se puede obtener con nbd_get_block_size(3).

El parámetro "flags" puede ser 0 para ninguna bandera, o puede contener "LIBNBD_CMD_FLAG_DF" significando que el servidor no debe responder con más de un fragmento (si eso es compatible - algunos servidores no pueden hacer esto, ver nbd_can_df(3)). Libnbd no valida que el servidor realmente obedezca la bandera.

Tenga en cuenta que si este comando falla, y nbd_get_pread_initialize(3) devuelve verdadero, entonces libnbd sanitizó "buf", pero no se especifica si el contenido de "buf" se leerá como cero o como resultados parciales del servidor. Si nbd_get_pread_initialize(3) devuelve falso, entonces libnbd no sanitizó "buf", y los contenidos son indefinidos en caso de fallo.

Por defecto, libnbd rechazará los intentos de usar esta función con parámetros que probablemente resulten en un fallo del servidor, como solicitar una bandera de comando desconocida. La función nbd_set_strict_mode(3) puede usarse para alterar qué escenarios deben esperar una respuesta del servidor en lugar de fallar rápidamente.

VALOR DE RETORNO

Si la llamada es exitosa, la función devuelve 0.

ERRORES

En caso de error, se devuelve -1.

Consulte "MANEJO DE ERRORES" en libnbd(3) para obtener más detalles sobre el error.

Los siguientes parámetros no deben ser NULL: "h", "buf". Para más información vea "Parámetros que no deben ser NULL" en libnbd(3).

ESTADO DEL MANEJADOR

nbd_pread_structured puede llamarse cuando el manejador se encuentra en el siguiente estado:

┌─────────────────────────────────────┬─────────────────────────┐
│ Manejador creado, antes de conectar │ ❌ error                │
│ Conectando                          │ ❌ error                │
│ Conectando y handshake (opt_mode) │ ❌ error                │
│ Conectado al servidor             │ ✅ permitido            │
│ Conexión cerrada                 │ ❌ error                │
│ Manejador muerto                  │ ❌ error                │
└─────────────────────────────────────┴─────────────────────────┘

VERSIÓN

Esta función apareció por primera vez en libnbd 1.0.

Si necesita probar si esta función está disponible en tiempo de compilación, compruebe si la siguiente macro está definida:

#define LIBNBD_HAVE_NBD_PREAD_STRUCTURED 1
