nbtscan(1) escanea redes buscando información de nombres NetBIOS nbtscan(1)

NOMBRE

nbtscan - escanea redes en busca de información de nombres NetBIOS

SINOPSIS

nbtscan [-v] [-d] [-e] [-l] [-t tiempo_espera] [-b ancho_banda] [-r] [-q]
        [-s separador] [-h] [-m reintentos] [-f nombre_archivo | objetivo]

DESCRIPCIÓN

NBTscan es un programa para escanear redes IP en busca de información de nombres NetBIOS. Envía una consulta de estado NetBIOS a cada dirección en el rango proporcionado y lista la información recibida en un formato legible por humanos. Para cada host que responde, lista la dirección IP, el nombre del equipo NetBIOS, el nombre del usuario conectado y la dirección MAC (como la de Ethernet).

NBTscan produce un informe como este:

    Dirección IP     Nombre NetBIOS  Servidor    Usuario           Dirección MAC
    -----------------------------------------------------------------------
    192.168.1.2    MIORDENADOR             JDOE           00-a0-c9-12-34-56
    192.168.1.5    ORDENADORWIN98  <servidor>  RROE           00-a0-c9-78-90-00
    192.168.1.123  SERVIDORDPT     <servidor>  ADMINISTRATOR  08-00-09-12-34-56
La primera columna lista la dirección IP del host que responde. La segunda columna es el nombre del equipo. La tercera columna indica si este equipo comparte o puede compartir archivos o impresoras. Para una máquina NT, significa que el Servicio de Servidor está en ejecución en este equipo. Para Windows 95, significa que la casilla "Quiero poder dar a otros acceso a mis archivos" o "Quiero poder permitir a otros imprimir en mi(s) impresora(s)" está marcada (en Panel de Control/Red/Compartir archivos e impresoras). La mayoría de las veces significa que este equipo comparte archivos. La tercera columna muestra el nombre de usuario. Si nadie ha iniciado sesión desde este equipo, es el mismo que el nombre del equipo. La última columna muestra la dirección MAC del adaptador.

Si se ejecuta con la opción -v, NBTscan lista la tabla de nombres NetBIOS completa para cada dirección que responde. La salida se ve así:

    Tabla de nombres NetBIOS para el Host 192.168.1.123:
    Nombre             Servicio          Tipo
    ----------------------------------------
    SERVIDORDPT        <00>             ÚNICO
    SERVIDORDPT        <20>             ÚNICO
    DEPARTAMENTO       <00>             GRUPO
    DEPARTAMENTO       <1c>             GRUPO
    DEPARTAMENTO       <1b>             ÚNICO
    DEPARTAMENTO       <1e>             GRUPO
    SERVIDORDPT        <03>             ÚNICO
    DEPARTAMENTO       <1d>             ÚNICO
    ??__MSBROWSE__?    <01>             GRUPO
    INet~Services      <1c>             GRUPO
    IS~SERVIDORDPT     <00>             ÚNICO
    SERVIDORDPT        <01>             ÚNICO
    Dirección del adaptador: 00-a0-c9-12-34-56
    ----------------------------------------

OPCIONES

A continuación se incluye un resumen de las opciones.

-v
Salida detallada. Imprime todos los nombres recibidos de cada host.
-d
Volcar paquetes. Imprime el contenido completo del paquete. No se puede usar con las opciones -v, -s o -h.
-e
Formato de salida en formato /etc/hosts.
-l
Formato de salida en formato lmhosts.
-t <tiempo_espera>
Espera tiempo_espera segundos para obtener una respuesta. Por defecto es 1.
-b <ancho_banda>
Limitación de salida. Ralentiza la salida para que no utilice más de ancho_banda bps. Útil en enlaces lentos, para que las consultas de salida no se descarten.
-r
Usa el puerto local 137 para los escaneos. Solo los equipos Win95 responden a esto. Necesitas ser root para usar esta opción.
-q
Suprime banners y mensajes de error.
-s <separador>
Salida amigable para scripts. No imprima encabezados de columna y registro, separe los campos con separador.
-h
Imprime nombres legibles por humanos para los servicios. Solo se puede usar con la opción -v.
-m <reintentos>
Número de reintentos. Por defecto 0.
-f <nombre_archivo>
Toma las direcciones IP a escanear del archivo "nombre_archivo"
objetivo
NBTscan es una herramienta de línea de comandos. Debes proporcionar al menos un argumento, el rango de direcciones, en una de las tres formas:
xxx.xxx.xxx.xxx
IP individual en notación decimal con puntos. Ejemplo: 192.168.1.1
xxx.xxx.xxx.xxx/xx
Dirección de red y máscara de subred. Ejemplo: 192.168.1.0/24
xxx.xxx.xxx.xxx-xxx
Rango de direcciones. Ejemplo: 192.168.1.1-127. Esto escaneará todas las direcciones desde 192.168.1.1 hasta 192.168.1.127

EJEMPLOS

Escanea la red de clase C completa:

    nbtscan 192.168.1.0/24
Escanea la red de clase C completa, usando el puerto 137: 
    nbtscan -r 192.168.1.0/24
Escanea un rango desde 192.168.1.25 hasta 192.168.1.137: 
    nbtscan 192.168.1.25-137
Escanea la red de clase C. Imprime los resultados en formato amigable para scripts usando dos puntos como separador de campos: 
    nbtscan -v -s : 192.168.1.0/24
El último comando produce una salida como esta: 
    192.168.0.1:NT_SERVER:00U
    192.168.0.1:MI_DOMINIO:00G
    192.168.0.1:ADMINISTRATOR:03U
    192.168.0.2:OTRA_MAQUINA:00U
    ...
Escanea las direcciones IP especificadas en el archivo iplist: 
    nbtscan -f iplist

FAQ

1.
What are these "remote IP", "MAC address", "hostname", "user" and "domain" fields?

R: They are fields related to NetBIOS (Network Basic Input/Output System) service, which is used by Windows for network resource sharing. nbtscan queries the remote host for NetBIOS information. It works using UDP port 137. It is only implemented by Windows (and some software on Unix such as Samba).

2.
Why do I get "Connection reset by peer" errors on Windows 2000?

R: NBTscan uses port 137 UDP for sending queries. If the port is closed on destination host destination will reply with ICMP "Port unreachable" message. Most operating system will ignore this message. Windows 2000 reports it to the application as "Connection reset by peer" error. Just ignore it.

3.
Why NBTscan doesn't scan for shares? Are you going to add share scanning to NBTscan?

R: No. NBTscan uses UDP for what it does. That makes it very fast. Share scanning requires TCP. For one thing, it will make nbtscan more slow. Also adding share scanning means adding a lot of new code to nbtscan. There is a lot of good share scanners around, so there is no reason to duplicate that work.

4.
Why do I get 00-00-00-00-00-00 instead of MAC address when I scan a Samba box?

R: Because that's what Samba send in response to the query. Nbtscan just prints out what it gets.
