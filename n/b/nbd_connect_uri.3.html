Paquete: libnbd

nbd_connect_uri(3) LIBNBD nbd_connect_uri(3)

NOMBRE

nbd_connect_uri - conectar a URI NBD

SINOPSIS

#include <libnbd.h>
int nbd_connect_uri (
      struct nbd_handle *h, const char *uri
    );

DESCRIPCIÓN

Conecta (sincrónicamente) a un servidor NBD y exporta especificando la URI NBD. Las URIs NBD son una forma estándar de especificar un punto final de dispositivo de bloque de red, utilizando una sintaxis como "nbd://example.com" que es conveniente, bien definida y a prueba de futuro.

Esta llamada funciona analizando el parámetro URI y llamando a nbd_set_export_name(3) y nbd_set_tls(3) y otras llamadas según sea necesario, seguidas de nbd_connect_tcp(3), nbd_connect_unix(3) o nbd_connect_vsock(3).

Esta llamada devuelve cuando se ha realizado la conexión. Por defecto, esto procede hasta la fase de transmisión, pero nbd_set_opt_mode(3) puede usarse para el control manual sobre la negociación de opciones realizada antes de la fase de transmisión.

Ejemplos de URIs admitidas

"nbd://example.com"
Conéctese a través de TCP, sin cifrar, a "example.com" puerto 10809.
"nbds://example.com"
Conéctese a través de TCP con TLS, a "example.com" puerto 10809. Si el servidor no admite TLS, esto fallará.
"nbd+unix:///foo?socket=/tmp/nbd.sock"
Conéctese a través del socket de dominio Unix /tmp/nbd.sock a un servidor NBD en ejecución localmente. El nombre de exportación se establece en "foo" (tenga en cuenta que no hay ningún carácter "/" inicial).
"nbds+unix://alice@/?socket=/tmp/nbd.sock&tls-certificates=certs"
Conéctese a través de un socket de dominio Unix, habilitando TLS y estableciendo la ruta a un directorio que contenga certificados y claves.
"nbd+vsock:///"
En este escenario, libnbd se está ejecutando en una máquina virtual. Conéctese a través de "AF_VSOCK" a un servidor NBD en ejecución en el hipervisor.
"nbd+ssh://server/"
Conéctese al servidor remoto "server" usando Secure Shell, y canalice NBD a un servidor NBD escuchando en el puerto 10809.

Esquema URI

El esquema es la parte anterior a los primeros ":". Los siguientes esquemas son compatibles en la versión actual de libnbd:

"nbd:"
Conéctese a través de TCP sin usar TLS.
"nbds:"
Conéctese a través de TCP. Se requiere TLS y la conexión fallará si el servidor no admite TLS.
"nbd+unix:"
"nbds+unix:"
Conéctese a través de un socket de dominio Unix, con o sin TLS respectivamente. El parámetro "socket" es obligatorio.
"nbd+vsock:"
"nbds+vsock:"
Conéctese a través del transporte "AF_VSOCK", con o sin TLS respectivamente. Puede usar nbd_supports_vsock(3) para ver si esta compilación de libnbd admite "AF_VSOCK".
"nbd+ssh:"
"nbds+ssh:"
Experimental

Canalice NBD a través de una conexión Secure Shell. Esto requiere que ssh(1) esté instalado localmente, y que nc(1) (del proyecto nmap) esté instalado en el servidor remoto.

Autoridad URI

La parte de autoridad de la URI "[username@][servername][:port]" se analiza según el transporte. Para TCP especifica el servidor al que conectarse y el número de puerto opcional. Para "+unix" no debería estar presente. Para "+vsock" el nombre del servidor es el CID numérico (ej. 2 para conectarse al host), y el número de puerto opcional puede estar presente. Para "+ssh" el servidor Secure Shell y el puerto opcional. Si el "username" está presente, se usa para la autenticación TLS.

Nombre de exportación URI

Para todos los transportes, puede estar presente un nombre de exportación, analizado de acuerdo con la especificación URI NBD. Tenga en cuenta que el carácter inicial "/" no forma parte del nombre de exportación:

URI                    nombre de exportación
nbd://localhost/       ""        (cadena vacía)
nbd://localhost/export "export"

Es posible anular el nombre de exportación mediante programación utilizando nbd_set_opt_mode(3) para habilitar el modo de opciones, luego utilizando nbd_set_export_name(3) y nbd_opt_go(3) como parte de la negociación posterior.

Consulta URI

Finalmente, la parte de consulta de la URI puede contener:

socket=SOCKET
Especifica el socket de dominio Unix en el que conectarse. Debe estar presente para el transporte "+unix", es opcional para "+ssh", y no debe estar presente para los otros transportes.
tls-certificates=DIR
Establece el directorio de certificados. Ver nbd_set_tls_certificates(3). Tenga en cuenta que esto no está permitido por defecto; ver la siguiente sección.
tls-psk-file=PSKFILE
Establece el archivo PSK. Ver nbd_set_tls_psk_file(3). Tenga en cuenta que esto no está permitido por defecto; ver la siguiente sección.
tls-hostname="SERVER"
Establece el nombre de host TLS. Ver nbd_set_tls_hostname(3).
tls-verify-peer=false
No verifica el certificado del servidor. Ver nbd_set_tls_verify_peer(3). El valor predeterminado es "true".

Deshabilitar características URI

Por razones de seguridad, es posible que desee deshabilitar ciertas características de URI. El prefiltrado de URIs es propenso a errores y no debe intentarse. En su lugar, use las API de libnbd a continuación para controlar lo que puede aparecer en las URIs. Tenga en cuenta que debe llamar a estas funciones en el mismo manejador antes de llamar a nbd_connect_uri(3) o nbd_aio_connect_uri(3).

Transportes TCP, socket de dominio Unix, "AF_VSOCK" o SSH
Predeterminado: todos permitidos

Para seleccionar qué transportes están permitidos, llame a nbd_set_uri_allow_transports(3).

TLS
Predeterminado: se permiten conexiones no TLS y TLS

Para forzar TLS apagado o encendido en las URIs, llame a nbd_set_uri_allow_tls(3).

Conexión a socket de dominio Unix en el sistema de archivos local
Predeterminado: permitido

Para evitar esto, debe deshabilitar el transporte "+unix" usando nbd_set_uri_allow_transports(3).

Lectura de archivos locales
Predeterminado: denegado

Para permitir que las URIs contengan referencias a archivos locales (por ejemplo, para parámetros como "tls-psk-file"), llame a nbd_set_uri_allow_local_file(3).

Características opcionales

Esta llamada fallará si libnbd no se compiló con libxml2; puedes comprobar si este es el caso con nbd_supports_uri(3).

El soporte para URIs que requieren TLS fallará si libnbd no se compiló con gnutls; puedes comprobar si este es el caso con nbd_supports_tls(3).

Construir una URI a partir de una conexión existente

Ver nbd_get_uri(3).

Ver si una cadena es una URI NBD

Ver nbd_is_uri(3).

Diferencias con el análisis de URIs NBD de qemu y glib

qemu(1) también soporta URIs NBD y tiene un analizador de URIs separado. En qemu ≤ 9.0 esto se hizo usando su propio analizador. En qemu ≥ 9.1 esto se hace usando las funciones "g_uri" de glib. El analizador actual (basado en glib) no analiza la parte del nombre de exportación de la URI exactamente de la misma manera que libnbd, lo que puede hacer que las URIs funcionen en libnbd pero no en qemu o viceversa. Solo las URIs que usan nombres de exportación deberían verse afectadas. Para obtener detalles, consulta https://gitlab.com/qemu-project/qemu/-/issues/2584.

Limitaciones en los números de puerto vsock

El protocolo vsock(7) permite puertos sin signo de 32 bits, reservando los puertos 0, 1 y 2 para propósitos especiales. En Linux, los puertos < 1024 están reservados para procesos privilegiados.

libxml2 (usado para analizar la URI) impone restricciones adicionales. libxml2 < 2.9 limitaba los números de puerto a 99,999,999. libxml2 ≥ 2.9 limita los números de puerto a ≤ 0x7fff_ffff (31 bits).

VALOR DE RETORNO

Si la llamada es exitosa, la función devuelve 0.

ERRORES

En caso de error, se devuelve -1.

Consulta "MANEJO DE ERRORES" en libnbd(3) para saber cómo obtener más detalles del error.

Los siguientes parámetros no deben ser NULL: "h", "uri". Para más información, consulta "Parámetros no nulos" en libnbd(3).

ESTADO DEL MANEJADOR

Se puede llamar a nbd_connect_uri cuando el manejador está en el siguiente estado:

┌─────────────────────────────────────┬─────────────────────────┐
│ Manejador creado, antes de conectar   │ ✅ permitido              │
│ Conectando                          │ ❌ error                │
│ Conectando y handshake (opt_mode) │ ❌ error                │
│ Conectado al servidor             │ ❌ error                │
│ Conexión cerrada                   │ ❌ error                │
│ Manejador muerto                    │ ❌ error                │
└─────────────────────────────────────┴─────────────────────────┘

EJEMPLO

Este ejemplo también está disponible como examples/connect-uri.c en el código fuente de libnbd.

/* Este ejemplo muestra cómo conectarse a un servidor NBD
 * usando la URI NBD del servidor.
 *
 * Para probar esto con una versión reciente de nbdkit
 * que soporte la sintaxis '$uri', haz:
 *
 * nbdkit -U - random 1M \
 *   --run './connect-uri $uri'
 *
 * Para probar la conexión a un servidor NBD remoto
 * que escucha en el puerto 10809, haz:
 *
 * ./connect-uri nbd://remote/
 */
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>
#include <string.h>
#include <stdint.h>
#include <inttypes.h>
#include <libnbd.h>
int
main (int argc, char *argv[])
{
  struct nbd_handle *nbd;
  char *s;
  int64_t size;
  if (argc != 2) {
    fprintf (stderr, "uso: %s URI\n",
             argv[0]);
    exit (EXIT_FAILURE);
  }
  /* Crear el manejador de libnbd. */
  nbd = nbd_create ();
  if (nbd == NULL) {
    fprintf (stderr, "%s\n", nbd_get_error ());
    exit (EXIT_FAILURE);
  }
  /* Solicitar información completa
   * (para nbd_get_canonical_export_name abajo)
   */
#if LIBNBD_HAVE_NBD_SET_FULL_INFO
  if (nbd_set_full_info (nbd, true) == -1) {
    fprintf (stderr, "%s\n", nbd_get_error ());
    exit (EXIT_FAILURE);
  }
#endif
  /* Conectarse a la URI NBD. */
  printf ("conectando a %s ...\n", argv[1]);
  fflush (stdout);
  if (nbd_connect_uri (nbd, argv[1]) == -1) {
    fprintf (stderr, "%s\n", nbd_get_error ());
    exit (EXIT_FAILURE);
  }
  printf ("conectado\n");
  /* Imprimir la URI, el nombre de exportación, el tamaño y otra información. */
  printf ("URI solicitada: %s\n", argv[1]);
  s = nbd_get_uri (nbd);
  printf ("URI generada: %s\n", s ? s : "NULL");
  free (s);
  size = nbd_get_size (nbd);
  if (size == -1) {
    fprintf (stderr, "%s\n", nbd_get_error ());
    exit (EXIT_FAILURE);
  }
  printf ("tamaño: %" PRIi64 "\n", size);
  s = nbd_get_export_name (nbd);
  printf ("nombre de exportación solicitado: %s\n", s ? s : "NULL");
  free (s);
#if LIBNBD_HAVE_NBD_GET_CANONICAL_EXPORT_NAME
  s = nbd_get_canonical_export_name (nbd);
  printf ("nombre de exportación canónico: %s\n", s ? s : "NULL");
  free (s);
#endif
#if LIBNBD_HAVE_NBD_GET_EXPORT_DESCRIPTION
  s = nbd_get_export_description (nbd);
  printf ("descripción de exportación: %s\n", s ? s : "NULL");
  free (s);
#endif
  /* Cerrar el manejador de libnbd. */
  nbd_close (nbd);
  exit (EXIT_SUCCESS);
}
