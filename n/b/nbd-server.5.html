NOMBRE

/etc/nbd-server/config - archivo de configuración para nbd-server

SINOPSIS

/etc/nbd-server/config

DESCRIPCIÓN

Este archivo permite configurar nbd-server.

Aunque /etc/nbd-server/config es el archivo de configuración predeterminado, esto puede variar con la opción -C de nbd-server(1).

El archivo de configuración consta de líneas de encabezado de sección, líneas de comentarios y líneas de opciones.

Un encabezado de sección es un nombre único encerrado entre corchetes ("[" y "]"). Un encabezado de sección denota el comienzo de una sección; una sección continúa hasta la siguiente sección o el final del archivo, lo que ocurra primero. La primera sección en el archivo de configuración debe llamarse generic y se utiliza para opciones globales que se aplican a más de una exportación. Esta sección siempre debe estar presente, incluso si no contiene opciones. Cada otra sección define una exportación; los nombres de estas secciones no son importantes, excepto que debe tener cuidado de asegurarse de que cada nombre de sección sea único. El nombre de la sección se utiliza como nombre de la exportación en caso de que el cliente se conecte con un nombre en lugar de un puerto para especificar una exportación, y por lo tanto debe ser único.

Una línea de comentario es una línea que comienza con un espacio en blanco opcional, seguido de un signo de almohadilla ("#"), y continúa hasta el final de la línea. Los comentarios no se pueden usar en líneas de opciones o líneas de encabezado de sección.

Una línea de opción es una línea que comienza con un nombre de opción, seguido de un signo igual ("="), seguido del valor de la opción. Una opción puede ser de tipo cadena, de tipo entero o de tipo booleano. El valor de una opción booleana se puede denotar con true o false (es decir, no yes, no, on, off, 1 o 0). Todos los booleanos tienen el valor predeterminado false a menos que se especifique lo contrario. Ningún valor puede ser citado; siempre ingréselo directamente. Para una opción de cadena, se eliminan los espacios en blanco iniciales (pero no los espacios en blanco finales).

OPCIONES PARA LA SECCIÓN [GENERIC]

allowlist
Opcional; booleano

Si se permite al cliente obtener una lista de exportaciones de este servidor. Si está habilitado, el cliente puede ejecutar nbd-client -l para obtener una lista de exportaciones en este servidor.

cacertfile
Opcional; cadena

Si se establece esta opción, debe contener una ruta a un certificado X.509 CA en formato PEM utilizado para validar los certificados de cliente suministrados por el cliente. Si esta opción no está establecida, los certificados del cliente no se verificarán.

certfile
Opcional; cadena

Si se establece esta opción, debe contener una ruta a un certificado público X.509 en formato PEM utilizado para la negociación TLS con el cliente. Si se establece keyfile pero no certfile, el servidor intentará leer el certificado de la ruta especificada por keyfile.

force_tls
Opcional; booleano.

Cambia el servidor al modo FORCEDTLS.

Nota: esto no es lo mismo que habilitar la opción force_tls para cada exportación individualmente. Esto último permitirá que se emitan ciertas opciones durante la negociación (por ejemplo, la opción "listar exportaciones", incluso si esto devolviera un conjunto de resultados vacío), mientras que habilitar esta opción deshabilitará el uso de cualquier opción que se emita durante la negociación, aparte de la propia opción STARTTLS (para cambiar el transporte a TLS).

Usar el modo FORCEDTLS debería resultar en un entorno más seguro, ya que el servidor no permitirá que se realice ninguna comunicación a menos que se haya negociado TLS. Sin embargo, también hace imposible configurar una exportación no cifrada en beneficio de clientes más antiguos, o para clientes que desean intercambiar y no bloquearse.

Usar este parámetro sin especificar también un valor para los otros parámetros relacionados con TLS es posible, pero poco práctico.

group
Opcional; cadena.

El nombre del grupo con el que debe ejecutarse este servidor. Si este parámetro no se especifica, nbd-server no intentará cambiar su GID (por lo que el GID con el que se ejecuta será el grupo primario del usuario que inicia nbd-server). Si se especifica, nbd-server cambiará su GID después de abrir puertos, pero antes de aceptar conexiones o abrir archivos.

includedir
Opcional; cadena

El argumento debe ser un directorio que contenga archivos con extensión '.conf'; estos archivos se analizarán como si fueran parte del archivo de configuración. Tenga en cuenta que estos archivos de configuración adicionales no pueden contener una sección [generic]; cualquier configuración que deba ir en la sección genérica debe colocarse en el archivo de configuración principal.

Si este argumento no se especifica, no se buscará ningún directorio. Si se especifica pero el directorio no existe, nbd-server saldrá con un mensaje de error apropiado; si se especifica pero el directorio dado está vacío, nbd-server continuará (a menos que no se hayan configurado exportaciones en absoluto, en cuyo caso saldrá con un mensaje de error apropiado)

keyfile
Opcional; cadena

Si se establece esta opción, debe contener una ruta a una clave privada X.509 en formato PEM utilizada para la negociación TLS con el cliente. Esta opción debe establecerse para habilitar TLS.

listenaddr
Opcional; cadena

Si se establece esta opción, debe contener una lista separada por comas de las direcciones IP locales en las que debemos escuchar las conexiones de nbd-client(8). Si no se establece, nbd-server escuchará en "::, 0.0.0.0", lo que provoca que nbd-server escuche en todas las direcciones IPv4 e IPv6 locales. Para limitar a IPv6, especifique la dirección como "::". Para limitar a IPv4, especifique como "0.0.0.0".

max_threads
Opcional; entero; predeterminado 4

Desde NBD 3.12, nbd-server leerá las solicitudes en un hilo principal, pero manejará estas solicitudes y el envío de la respuesta en varios hilos trabajadores separados, que se comparten entre todas las exportaciones. Con este parámetro, puede configurar el número de estos hilos trabajadores.

El valor predeterminado debería ser razonable para un servidor de un solo disco de doble núcleo. Es posible que desee aumentarlo si tiene un servidor potente que hace poco más que servir NBD.

oldstyle
Opcional; booleano

En versiones de nbd-server entre 2.9.17 y 3.9.1, cuando esta opción se establecía en true, nbd-server exportaba todas las exportaciones en un puerto separado con el antiguo protocolo de handshake (pre-2.9.17). En ese caso, la opción 'port' para exportaciones individuales era obligatoria.

Sin embargo, desde la versión 3.10 de nbd-server, esta opción ya no es compatible, y cualquier intento de usarla resultará en que nbd-server salga con un mensaje de error apropiado.

port
Opcional; cadena

El puerto en el que se escuchará para las conexiones de nbd-client de estilo nuevo. Si no se especifica, se utiliza el puerto asignado por IANA 10809.

splice
Opcional; booleano

Permite al servidor usar la llamada al sistema splice() para manejar las llamadas de lectura o escritura cuando sea posible. Usar splice puede acelerar significativamente el manejo de tales llamadas. Desafortunadamente, splice no se puede usar en combinación con TLS o el modo copyonwrite, y solo funcionará para solicitudes de menos de 1MiB.

Para manejar estas situaciones, el servidor saldrá con un mensaje de error apropiado si splice y copyonwrite están habilitados para una exportación; ignorará silenciosamente la opción splice si TLS está habilitado, recurriendo a lecturas y escrituras normales; y de manera similar recurrirá a lecturas normales cuando el tamaño de la solicitud exceda 1MiB.

user

OPTIONS FOR THE SERVER

user
Opcional; cadena.

El nombre del usuario con el que debe ejecutarse este servidor. Si este parámetro no se especifica, nbd-server no intentará cambiar su UID (por lo que el UID con el que se ejecute será el usuario que inicia nbd-server). Si se especifica, nbd-server cambiará su UID después de abrir puertos, pero antes de aceptar conexiones o abrir archivos.

unixsock
Opcional; cadena

Ruta para un socket de dominio UNIX.

Si se especifica, el servidor escuchará en un socket de dominio UNIX con el nombre especificado. Solo la negociación de estilo nuevo es compatible con los sockets de dominio UNIX. Si se utiliza un socket de dominio UNIX, el servidor no escuchará conexiones TCP.

duallisten
Opcional; booleano

Si es verdadero, y se especifica unixsock, el servidor escuchará tanto en el socket de dominio UNIX configurado como en cualquier socket TCP o SDP configurado. Por defecto es falso.

tlsprio
Opcional; cadena; por defecto NORMAL:-VERS-TLS-ALL:+VERS-TLS1.2:%SERVER_PRECEDENCE

Esta opción permite configurar la cadena de prioridad de GnuTLS, que se utiliza para seleccionar los algoritmos que GnuTLS permitirá negociar con el cliente. La especificación NBD STARTTLS requiere que los clientes y servidores exijan TLS1.2 o superior por defecto, por lo que la cadena predeterminada deshabilita todas las versiones anteriores del protocolo TLS.

No todas las versiones de GnuTLS admiten la bandera %SERVER_PRECEDENCE, que existe para indicar que el servidor no debe prestar atención a las preferencias de algoritmos seleccionadas por el cliente. Si estás utilizando una versión anterior de GnuTLS (por ejemplo, 2.12), puede ser necesario especificar una cadena de prioridad que no incluya la bandera %SERVER_PRECEDENCE.

Para obtener una explicación de los posibles valores de esta opción, consulta el capítulo "Priority strings" en la documentación de GnuTLS.

OPCIONES PARA SECCIONES DE EXPORTACIÓN

authfile
Opcional; cadena; por defecto vacía

El nombre del archivo de autorización para esta exportación. Este archivo debe contener una línea por dirección IP o por red (que debe especificarse en estilo CIDR red/máscara). Se omiten las líneas vacías, al igual que cualquier contenido después de una almohadilla ('#') en cualquier línea.

Si el archivo no existe, se permite que todos se conecten. Si el archivo existe pero está vacío, no se permite que nadie se conecte. De lo contrario, nbd-server solo permitirá que se conecten clientes cuya dirección IP esté listada en este archivo.

Corresponde a la opción -l en la línea de comandos. Sin embargo, ten en cuenta que para la línea de comandos, el valor predeterminado es /etc/nbd-server/allow.

copyonwrite
Opcional; booleano.

Si esta es una exportación de copia en escritura. Si lo es, entonces cualquier escritura en esta exportación no se escribirá en el archivo maestro, sino en un archivo separado que se eliminará al desconectar. El resultado de usar esta opción es que nbd-server será algo más lento y que cualquier escritura se perderá al desconectar.

Corresponde a la opción -c en la línea de comandos

cowdir
Opcional; cadena.

Especifica dónde escribir los archivos de diferencias de copia en escritura. Si esta opción está ausente, los archivos de copia en escritura se escribirán en el mismo directorio que el archivo base de exportación. Útil para exportar archivos en modo de copia en escritura desde un directorio al que el usuario que ejecuta nbd-server no tiene acceso de escritura.

Si el modo de copia en escritura no está activo, esta opción no tiene efecto.

exportname
Requerido; cadena.

El nombre del archivo (o dispositivo de bloque) que se exportará. Debe ser una ruta y nombre de archivo completamente calificados; no se permiten rutas relativas. Si se usa junto con temporary, especifica una plantilla para el archivo temporal en cuestión, y por lo tanto puede usarse para controlar el directorio en el que se crea. Si el archivo no existe, pero se establece filesize, se creará el archivo.

Tenga en cuenta que nbd-server solo intentará encontrar y abrir el archivo exportado cuando un cliente se conecte realmente; como resultado, nbd-server debe poder abrir y leer este archivo después de cambiar al usuario y grupo especificados mediante las opciones user y group; además, nbd-server solo detectará errores en esta opción tras la conexión de un cliente.

Cuando se especifica en la línea de comandos, debe ser el segundo argumento.

Nota: este no es el "exportname" tal como se define en el documento del protocolo, y que es el nombre que nbd-client necesita pasar para seleccionar la exportación correcta; la sección se utiliza para eso. El nombre del archivo a exportar se denomina exportname en el archivo de configuración por razones históricas, y no se puede cambiar fácilmente.

filesize
Opcional; entero; por defecto autodetectado.

Deshabilita la autodetección del tamaño del archivo o dispositivo de bloque, y especifica forzosamente un tamaño. Los tamaños deben especificarse en bytes. Si la opción multifile está activa, esta opción especifica el tamaño de la exportación **completa**, no de los archivos individuales. Si el archivo no está presente, se crea un único archivo de este tamaño.

Cuando se especifica en la línea de comandos, debe ser el tercer argumento.

flush
Opcional; booleano.

Cuando esta opción está habilitada, nbd-server informará al cliente que admite y desea recibir solicitudes de purga (flush) cuando la capa del elevador las reciba. La recepción de una solicitud de purga provocará un fdatasync() (o, si la opción sync está establecida, un fsync()) en el almacenamiento de backend. Esto aumenta la fiabilidad en caso de un cierre inadecuado a expensas de una degradación del rendimiento. Esta opción no tendrá ningún efecto a menos que sea compatible con el cliente.

force_tls
Opcional; booleano.

Requerir el uso de TLS para que esta exportación esté disponible.

Cuando esta opción se ha habilitado para una exportación, los clientes que no negocian TLS no verán la exportación al solicitar una lista de exportaciones, y no podrán conectarse a ella.

Es posible habilitar esta opción cuando no se han configurado credenciales TLS en la sección [generic], pero es absurdo.

fua
Opcional; booleano.

Cuando esta opción está habilitada, nbd-server informará al cliente que admite y desea recibir comandos fua (force unit access) cuando la capa del elevador los reciba. La recepción de un comando de acceso forzado a la unidad provocará que el comando especificado se sincronice con el almacenamiento de backend utilizando sync_file_range() si es compatible, o fdatasync() en caso contrario. Esto aumenta la fiabilidad en caso de un cierre inadecuado a expensas de una degradación del rendimiento. Esta opción no tendrá ningún efecto a menos que sea compatible con el cliente.

listenaddr
Opcional; cadena

Ignorado, conservado por compatibilidad con el obsoleto

maxconnections
Opcional; entero

Si se especifica, limita el número de conexiones abiertas para esta exportación.

multifile
Opcional; booleano.

Si esta opción se establece en verdadero, nbd-server buscará archivos del tipo exportname.entero, siendo exportname el nombre de archivo que de otro modo se habría utilizado (después de la transformación del nombre para virtualización, si la hubo, se realizó) y entero un número entero, comenzando por 0 y terminando cuando no se encuentren más archivos.

El tamaño de los archivos individuales se autodetectará, **incluso** si se ha especificado la opción filesize.

Corresponde a la opción -m en la línea de comandos.

treefiles
Opcional; booleano.

Si esta opción se establece en verdadero, nbd-server buscará archivos del tipo exportname/TREEXXXX/.../FILEXXXX, siendo exportname el nombre de archivo que de otro modo se habría utilizado (después de la transformación del nombre para virtualización, si la hubo, se realizó) y TREEXXXX y FILEXXXX nombres de directorio y ruta autogenerados para archivos de bloque individuales.

Los archivos y directorios se crean automáticamente. Los archivos se eliminarán si el bloque correspondiente se marca como no utilizado. El tamaño de los archivos de bloque individuales se fija en 4096 bytes. Habrá como máximo 1024 archivos/subdirectorios por carpeta. Se creará un nivel de anidación apropiado de subdirectorios para crear un sistema de archivos de bytes filesize en total, formando un dispositivo de bloque virtual.

Esta característica es útil para proporcionar un dispositivo de bloque virtual en un sistema de archivos subyacente que no maneja bien archivos grandes, por ejemplo, fuse/ftpfs, davfs u otros sistemas de archivos de red.

Esta característica es mutuamente excluyente con la opción -m y tendrá precedencia si se proporcionan ambas. No hay una opción de línea de comandos correspondiente, ya que el control de línea de comandos se considera obsoleto. Sin embargo, puedes especificar un archivo de configuración personalizado con la opción -C. La opción filesize **debe** especificarse al usar esta característica.

postrun
Opcional; cadena

Si se especifica, se asume que es un comando que se ejecutará cuando un cliente se haya desconectado. Esto puede ser útil para limpiar lo que prerun haya configurado, para registrar algo, o similar.

Si la cadena literal '%s' está presente en el comando, será reemplazada por el nombre del archivo que acaba de cerrarse.

nbd-server - network block device server

nbd-server [-C config] [-d] [-f] [-L] [-o options] [-p] [-q] [-t timeout] [-u] [-U]

The nbd-server is a server for the network block device (NBD) protocol. It exports block devices or files to clients over the network. The server can export block devices, regular files, or logical volumes. The export is transmitted over TCP/IP using the NBD protocol.

Configuration is done via a configuration file specified with the -C option. The default configuration file is /etc/nbd-server/nbd-server.conf.

The configuration file consists of zero or more sections. Each section starts with a section name enclosed in square brackets, e.g. [generic]. Within each section are zero or more key/value pairs, one per line. Lines starting with a '#' character are commented out.

There are two standard sections: [generic] and [exports]. Other sections can be defined and referenced by exports.

The [generic] section contains options that apply to the server as a whole. The [exports] section can contain multiple export definitions. Each export definition is a section whose name is the export name as it will be presented to the client.

Exports can be defined inline in the [exports] section, or they can be defined in separate sections. If an export is defined in its own section, the name of that section is the export name.

If an option is specified in the configuration file and also on the command line, the command line option takes precedence.

exportname
Optional; string.

This is the name of the export. It can be a block device (e.g. /dev/sda1), a regular file (e.g. /var/lib/nbd/mydisk.img), or a logical volume (e.g. vg01/lv01).

This option is required for all exports.

postrun
Optional; string.

If specified, then this command will be ran after a client has disconnected from the server. The command may contain the literal string '%s', which will be replaced by the filename of the export. This is mainly useful for cleanup operations.

If the command returns a non-zero exit status, the disconnect is logged but otherwise ignored.

The postrun command is ignored if the postrun option is not set in the generic section.

prerun
Optional; string

If specified, then this command will be ran after a client has connected to the server (and has been accepted), but before the server starts serving. If the command contains the literal string '%s', then this string will be replaced by the filename of the file which nbd-server wants to export.

This is useful to create export files on the fly, or to verify that a file can be used for export, to write something to a log file, or similar.

If the command runs with a nonzero exit status, then nbd-server will assume the export will fail, and refuse to serve it.

readonly
Optional; boolean.

Disallow writes to the device. If this option is specified, nbd-server will issue an error to any client that tries to write to the device.

Use of this option in conjunction with copyonwrite is possible, but silly.

Corresponds to the -r option on the command line.

rotational
Optional; boolean.

When this option is enabled, nbd-server will inform the client that it would prefer it to send requests in elevator (i.e., optimized) order, perhaps because it has a backing store and no local elevator. By default, the client uses QUEUE_FLAG_NONROT, which effectively restricts the function of the elevator to block merges. By specifying this flag on the server, the client will not use QUEUE_FLAG_NONROT, meaning the client elevator will perform normal elevator ordering of I/O requests. Note that even when the backing store is on rotating media, it is not normally necessary to specify this flag, as the server's elevator algorithm will be used. This flag is only required where the server will not be using an elevator algorithm or where the elevator algorithm is effectively neutered (e.g. with the sync option set). This option will have no effect unless supported by the client.

sdp
Optional; boolean.

When this option is enabled, nbd-server will use the Socket Direct Protocol (SDP) to serve the export, rather than just IP. This is faster, but requires special hardware (usually something like InfiniBand) and support in the kernel.

Additionally, support for this option must be enabled at compile time, using the --enable-sdp option to the configure script. If this option is found in a configuration file and nbd-server does not have support for SDP, then nbd-server will exit with an error message.

sparse_cow
Optional; boolean.

When this option is enabled, nbd-server will use sparse files to implement the copy-on-write option; such files take up less space then they appear to, which allows nbd-server to handle the file as if it was just as large as the block device it's for.

If this option is disabled, nbd-server will map every newly written block to the end of the copy-on-write file, which means that nbd-server will have to lseek(2) to the right position after every 4096-byte block.

Using this option may be faster when much is being written during a connection.

sync
Optional; boolean.

When this option is enabled, nbd-server will call an fsync() after every write to the backend storage. Calling fsync() increases reliability in case of an unclean shutdown of nbd-server; but, depending on the file system used on the nbd-server side, may degrade performance. The use of this option isn't always necessary; e.g., on ext3 filesystems, it is recommended that it is not enabled, since it seriously reduces performance on ext3 filesystems while not importantly impacting reliability.

temporary
Optional; boolean.

Create a temporary export with a name based on exportname (this can be used to set the directory). A unique filename is created, which is unlinked as soon as it is created, and therefore the export will not persist between invocations of nbd-server. Set the size of the file using the filesize option. This option is incompatible with the multifile option.

When specified on the command line, this should be the third argument.

timeout
Optional; integer; default 0

How many seconds a connection may be idle for this export. When a connection is idle for a longer time, nbd-server will forcibly disconnect the connection. If you specify 0 (the default), then a connection may be idle forever.

Corresponds to the -a option on the command line

transactionlog
Optional; string

If specified, then this pathname is used to generate a transaction log. A transaction log is a binary file consisting of the requests sent to and the replies received by the server, but excluding any data (so, for a write command, it records the offset and length of the write but not the data written). It is therefore relatively safe to distribute to a third party. Note that the transaction log does not include the negotiation sequence. Transaction logs are mainly useful for debugging. The program nbd-tester-client distributed with the source to this program can reply a transaction log against a server and perform a data integrity test. Note that the transaction log is written to for every client opened. If it is necessary to maintain separate transaction logs for each client, the prerun script should rename the transaction log (which will just have been opened in order to avoid transaction logs overwriting eachother. This action should be race-free.

trim
Optional; boolean

When this option is activated, the server announces it supports the NBD_CMD_TRIM command for the export. This command allows the server to discard the data from the disk, but does not require it to.

virtstyle
Optional; string; default "ipliteral"

Defines the style of virtualization. Virtualization allows one to create one export that will serve a different file depending on the IP address that is connecting. When virtualization is active, the exportname parameter needs to contain the string '%s'; this will then be replaced by the IP address of the client connecting, in accordance with the option selected here. The result of this transformation is then used as the filename to be opened.

When a client connects over a UNIX domain socket, the literal string "unix" is used in lieu of a client IP address.

There are four types of virtualization that nbd-server supports:

none
No virtualization. Will attempt to open the filename as it was written, even if it contains '%s' in the name.
ipliteral
The %s is replaced by the IP address of the connecting host is used as-is. For IPv4, this is done in dotted-quad notation; for IPv6, in hexadecimal form with leading zeros omitted.

As an example, if a client connects from 192.168.1.100 and exportname is specified as /export/%s, then nbd-server will attempt to serve /export/192.168.1.100. For IPv6, with a client connecting from 2001:6f8:32f::39, the filename would be /export/2001:6f8:32f:0:0:0:0:39

iphash
Same as above, except that nbd-server will replace the dots in the IP address by forward slashes ('/'); in the same example, nbd-server would open /export/192/168/1/100 instead.

Since there are no dots in most IPv6 addresses, the effect of using this option when IPv6 is in use is indistinguishable from the ipliteral option. It was thought that having to create an eight-deep directory structure would not be as useful.

cidrhash
This option requires one to add a space and a number after it. nbd-server will use the number as a network mask in CIDR style, and use that as a hash cutoff point. In the above example, if virtstyle has been specified as cidrhash 16, then nbd-server will try to open /export/192.168.0.0/192.168.1.100; if virtstyle were specified as cidrhash 26, then nbd-server will try to open /export/192.168.1.64/192.168.1.100.

For IPv6, in the above example, with cidrhash 42, the filename would be /export/2001:32f:6c0:0:0:0:0:0/2001:32f:6f8:0:0:0:0:39.

tlsonly
Optional; boolean.

When this option is enabled, nbd-server will only serve the export using the TLS extension. If this option is not supplied, TLS is optional, unless tlsonly is set in the generic section. In order for TLS to work at all, the keyfile option must be specified in the generic section.

waitfile
Optional; string.

When this option is set, nbd-server will allow writes to this export, but not reads, until the server is sent a SIGUSR1 command. Any writes to the export will be stored in a diff file with the same algorithm as for the copy-on-write option. In particular, this means that the cowdir option is in effect for this option, too.

The backend file (as per the exportname parameter) need not exist until the SIGUSR1 signal is sent to the server.

Once SIGUSR1 is received, nbd-server will open the main export file, and start merging all outstanding writes into it. Once this operation finishes, the diff file will be removed, and the server will allow normal use of the export.

Foreground. Do not daemonize. This is useful for running nbd-server under an init system like systemd.
-L
List exports. Print a list of all available exports to standard output, and exit.
-o options
Comma separated list of export-specific options. These options are passed to the export handling code, and are specific to the type of export being served. See EXPORT OPTIONS below.
-p
Pidfile. Create a pid file at /var/run/nbd-server.pid.
-q
Quiet. Suppress informational messages.
-t timeout
Timeout. Set the connection timeout to timeout seconds. If a connection is idle for longer than this, it will be disconnected. A value of 0 means no timeout.
-u
No user. Do not change the user ID. By default, nbd-server changes its user ID to 'nobody' for security reasons.
-U
Use UNIX domain sockets. Allow clients to connect via UNIX domain sockets. The path to the socket is specified in the configuration file. Default is /var/run/nbd-server.

The following options can be specified in the configuration file within an export section, or using the -o command line option.

blocksize
Optional; integer; default 1024

The block size of the export. This must be a power of 2. Clients will not be able to perform I/O operations on multiples of this block size.

copyonwrite
Optional; string.

Enable copy-on-write for this export. When enabled, writes to the export will be stored in a separate file, leaving the original export unchanged. The filename of the copy-on-write file is determined by the cowdir option, or defaults to the export name with .cow appended.

The copyonwrite option requires the cowdir option to be set, or the default copy-on-write filename to be accessible.

cowdir
Optional; string.

The directory in which to store copy-on-write files. If not specified, copy-on-write files will be stored in the same directory as the original export.

filesize
Optional; integer.

The size of the export in bytes. This option is only relevant when exporting a regular file. If not specified, the size of the file is used.

fixed
Optional; boolean.

When this option is enabled, nbd-server will not allow writes to the export. This is equivalent to setting the readonly option.

multifile
Optional; boolean.

When this option is enabled, nbd-server will serve multiple files as a single export. This is useful for exporting filesystems that are split across multiple files. The filenames are specified in the exportname option, separated by commas.

This option is incompatible with the temporary option.

postrun
Optional; string.

If specified, then this command will be ran after a client has disconnected from the server. The command may contain the literal string '%s', which will be replaced by the filename of the export. This is mainly useful for cleanup operations.

If the command returns a non-zero exit status, the disconnect is logged but otherwise ignored.

The postrun command is ignored if the postrun option is not set in the generic section.

prerun
Optional; string

If specified, then this command will be ran after a client has connected to the server (and has been accepted), but before the server starts serving. If the command contains the literal string '%s', then this string will be replaced by the filename of the file which nbd-server wants to export.

This is useful to create export files on the fly, or to verify that a file can be used for export, to write something to a log file, or similar.

If the command runs with a nonzero exit status, then nbd-server will assume the export will fail, and refuse to serve it.

readonly
Optional; boolean.

Disallow writes to the device. If this option is specified, nbd-server will issue an error to any client that tries to write to the device.

Use of this option in conjunction with copyonwrite is possible, but silly.

Corresponds to the -r option on the command line.

rotational
Optional; boolean.

When this option is enabled, nbd-server will inform the client that it would prefer it to send requests in elevator (i.e., optimized) order, perhaps because it has a backing store and no local elevator. By default, the client uses QUEUE_FLAG_NONROT, which effectively restricts the function of the elevator to block merges. By specifying this flag on the server, the client will not use QUEUE_FLAG_NONROT, meaning the client elevator will perform normal elevator ordering of I/O requests. Note that even when the backing store is on rotating media, it is not normally necessary to specify this flag, as the server's elevator algorithm will be used. This flag is only required where the server will not be using an elevator algorithm or where the elevator algorithm is effectively neutered (e.g. with the sync option set). This option will have no effect unless supported by the client.

sdp
Optional; boolean.

When this option is enabled, nbd-server will use the Socket Direct Protocol (SDP) to serve the export, rather than just IP. This is faster, but requires special hardware (usually something like InfiniBand) and support in the kernel.

Additionally, support for this option must be enabled at compile time, using the --enable-sdp option to the configure script. If this option is found in a configuration file and nbd-server does not have support for SDP, then nbd-server will exit with an error message.

sparse_cow
Optional; boolean.

When this option is enabled, nbd-server will use sparse files to implement the copy-on-write option; such files take up less space then they appear to, which allows nbd-server to handle the file as if it was just as large as the block device it's for.

If this option is disabled, nbd-server will map every newly written block to the end of the copy-on-write file, which means that nbd-server will have to lseek(2) to the right position after every 4096-byte block.

Using this option may be faster when much is being written during a connection.

sync
Optional; boolean.

When this option is enabled, nbd-server will call an fsync() after every write to the backend storage. Calling fsync() increases reliability in case of an unclean shutdown of nbd-server; but, depending on the file system used on the nbd-server side, may degrade performance. The use of this option isn't always necessary; e.g., on ext3 filesystems, it is recommended that it is not enabled, since it seriously reduces performance on ext3 filesystems while not importantly impacting reliability.

temporary
Optional; boolean.

Create a temporary export with a name based on exportname (this can be used to set the directory). A unique filename is created, which is unlinked as soon as it is created, and therefore the export will not persist between invocations of nbd-server. Set the size of the file using the filesize option. This option is incompatible with the multifile option.

When specified on the command line, this should be the third argument.

timeout
Optional; integer; default 0

How many seconds a connection may be idle for this export. When a connection is idle for a longer time, nbd-server will forcibly disconnect the connection. If you specify 0 (the default), then a connection may be idle forever.

Corresponds to the -a option on the command line

transactionlog
Optional; string

If specified, then this pathname is used to generate a transaction log. A transaction log is a binary file consisting of the requests sent to and the replies received by the server, but excluding any data (so, for a write command, it records the offset and length of the write but not the data written). It is therefore relatively safe to distribute to a third party. Note that the transaction log does not include the negotiation sequence. Transaction logs are mainly useful for debugging. The program nbd-tester-client distributed with the source to this program can reply a transaction log against a server and perform a data integrity test. Note that the transaction log is written to for every client opened. If it is necessary to maintain separate transaction logs for each client, the prerun script should rename the transaction log (which will just have been opened in order to avoid transaction logs overwriting eachother. This action should be race-free.

trim
Optional; boolean

When this option is activated, the server announces it supports the NBD_CMD_TRIM command for the export. This command allows the server to discard the data from the disk, but does not require it to.

virtstyle
Optional; string; default "ipliteral"

Defines the style of virtualization. Virtualization allows one to create one export that will serve a different file depending on the IP address that is connecting. When virtualization is active, the exportname parameter needs to contain the string '%s'; this will then be replaced by the IP address of the client connecting, in accordance with the option selected here. The result of this transformation is then used as the filename to be opened.

When a client connects over a UNIX domain socket, the literal string "unix" is used in lieu of a client IP address.

There are four types of virtualization that nbd-server supports:

none
No virtualization. Will attempt to open the filename as it was written, even if it contains '%s' in the name.
ipliteral
The %s is replaced by the IP address of the connecting host is used as-is. For IPv4, this is done in dotted-quad notation; for IPv6, in hexadecimal form with leading zeros omitted.

As an example, if a client connects from 192.168.1.100 and exportname is specified as /export/%s, then nbd-server will attempt to serve /export/192.168.1.100. For IPv6, with a client connecting from 2001:6f8:32f::39, the filename would be /export/2001:6f8:32f:0:0:0:0:39

iphash
Same as above, except that nbd-server will replace the dots in the IP address by forward slashes ('/'); in the same example, nbd-server would open /export/192/168/1/100 instead.

Since there are no dots in most IPv6 addresses, the effect of using this option when IPv6 is in use is indistinguishable from the ipliteral option. It was thought that having to create an eight-deep directory structure would not be as useful.

cidrhash
This option requires one to add a space and a number after it. nbd-server will use the number as a network mask in CIDR style, and use that as a hash cutoff point. In the above example, if virtstyle has been specified as cidrhash 16, then nbd-server will try to open /export/192.168.0.0/192.168.1.100; if virtstyle were specified as cidrhash 26, then nbd-server will try to open /export/192.168.1.64/192.168.1.100.

For IPv6, in the above example, with cidrhash 42, the filename would be /export/2001:32f:6c0:0:0:0:0:0/2001:32f:6f8:0:0:0:0:39.

tlsonly
Optional; boolean.

When this option is enabled, nbd-server will only serve the export using the TLS extension. If this option is not supplied, TLS is optional, unless tlsonly is set in the generic section. In order for TLS to work at all, the keyfile option must be specified in the generic section.

waitfile
Optional; string.

When this option is set, nbd-server will allow writes to this export, but not reads, until the server is sent a SIGUSR1 command. Any writes to the export will be stored in a diff file with the same algorithm as for the copy-on-write option. In particular, this means that the cowdir option is in effect for this option, too.

The backend file (as per the exportname parameter) need not exist until the SIGUSR1 signal is sent to the server.

Once SIGUSR1 is received, nbd-server will open the main export file, and start merging all outstanding writes into it. Once this operation finishes, the diff file will be removed, and the server will allow normal use of the export.

OPTIONS FOR EXPORT SECTIONS

exportname
This option specifies the path to the block device or file that should be exported. The exportname option can be specified multiple times for different export points.
authfile
This option specifies a file that contains a list of clients that are allowed to connect to this export point. Each line in the file should contain an IP address or a network range in CIDR notation. If this option is not specified, then all clients are allowed to connect.
readonly
This option specifies that the export should be read-only. If this option is not specified, then the export is read-write.
password
This option specifies a password that clients must provide to connect to this export point. The password will be sent in clear text, so it is recommended to use this option only over secure networks.
multi-export
This option allows multiple clients to connect to the same export point. By default, only one client is allowed to connect to an export point.
live
This option enables out-of-band live migration of an export from one server to another. This option cannot be combined with the copy-on-write option.

EJEMPLOS

Un archivo de configuración simple de nbd-server se vería así:

      [generic]
      [export]
          exportname = /export/blkdev

Para aumentar la seguridad, se podría querer crear un archivo de autorización y establecer el UID y GID con los que ejecutarse:

      [generic]
          user = nbd
          group = nbd
      [export]
          exportname = /export/blkdev
          authfile = /etc/nbd-server/allow

Con /etc/nbd-server/allow conteniendo lo siguiente:

      127.0.0.1
      192.168.0.0/8
      192.168.1.1
