NOMBRE

nbd-client - conectarse a un servidor que ejecuta nbd-server(1), para utilizar su dispositivo de bloque exportado

SINOPSIS

nbd-client host [ puerto ] dispositivo-nbd [ -connections num ] [ -sdp ] [ -swap ] [ -persist ] [ -nofork ] [ -nonetlink ] [ -systemd-mark ] [ -readonly ] [ -preinit ] [ -block-size tamaño-bloque ] [ -size bytes ] [ -timeout segundos ] [ -name nombre ] [ -certfile archivo-cert ] [ -keyfile archivo-clave ] [ -cacertfile archivo-ca-cert ] [ -tlshostname nombre-host ] [ -priority cadena-prioridad-gnutls ]

nbd-client -unix ruta dispositivo-nbd [ -connections num ] [ -sdp ] [ -swap ] [ -persist ] [ -nofork ] [ -nonetlink ] [ -systemd-mark ] [ -readonly ] [ -preinit ] [ -block-size tamaño-bloque ] [ -size bytes ] [ -timeout segundos ] [ -name nombre ]

nbd-client dispositivo-nbd

nbd-client -d dispositivo-nbd

nbd-client -c dispositivo-nbd

nbd-client -l host [ puerto ]

nbd-client [ -netlink ] -l host

DESCRIPCIÓN

Con nbd-client, puede conectarse a un servidor que ejecuta nbd-server, utilizando así espacio en disco sin procesar de ese servidor como un dispositivo de bloque en el cliente local.

Para hacer esto, se necesita soporte del Kernel de Linux, en forma del Dispositivo de Bloque de Red (NBD). Cuando lo tenga, ya sea en el kernel o como un módulo, puede conectarse a un servidor NBD y usar su archivo exportado a través de un archivo especial de bloque con modo mayor 43.

Opcionalmente, las opciones largas también se pueden especificar con dos guiones.

OPCIONES

Se soportan las siguientes opciones:

-block-size tamaño-bloque
-b
Utiliza un tamaño de bloque de "tamaño-bloque". El valor predeterminado es 512; los valores permitidos son 512, 1024, 2048 o 4096.
-connections num
-C
Utiliza num conexiones al servidor, para permitir acelerar el manejo de solicitudes, a costa de un mayor uso de recursos en el servidor. El uso de esta opción requiere soporte del kernel disponible primero con Linux 4.9.
host
El nombre de host o la dirección IP de la máquina que ejecuta nbd-server. Desde la versión 2.9.15, las utilidades NBD soportan IPv6.
-timeout segundos
-t
Establece el tiempo de espera de la conexión a "segundos". Para que esto funcione, necesita un kernel con soporte para la llamada ioctl NBD_SET_TIMEOUT; esto se introdujo en el árbol de Linus el 2007-10-11 y será parte del kernel 2.6.24.
puerto
El puerto TCP en el que se está ejecutando nbd-server en el servidor.

El número de puerto es 10809 por defecto, el número de puerto asignado por IANA para el protocolo NBD.

Las versiones anteriores de las herramientas nbd soportaban una versión anterior del protocolo de negociación conocido como "oldstyle". Este protocolo ya no se soporta a partir de la versión 3.11 de las herramientas de soporte nbd.

dispositivo-nbd
El archivo especial de bloque (entrada de /dev) al que debe conectarse este nbd-client, especificado como una ruta completa.

Cuando se utiliza el modo en el que no se especifica ni el nombre de host ni el nombre de exportación, nbd-client buscará la configuración necesaria en el archivo nbdtab. Para más información, consulte nbdtab(5).

-check
-c
Verifica si el dispositivo nbd especificado está conectado.

Si el dispositivo está conectado, nbd-client saldrá con un estado de salida de 0 e imprimirá el PID de la instancia de nbd-client que lo conectó en la salida estándar.

Si el dispositivo no está conectado o no existe (por ejemplo, porque el módulo nbd no se cargó), nbd-client saldrá con un estado de salida de 1 y no imprimirá nada en la salida estándar.

Si ocurrió un error, nbd-client saldrá con un estado de salida de 2, y tampoco imprimirá nada en la salida estándar.

-disconnect
-d
Desconecta el dispositivo nbd especificado del servidor.
-list
-l
Solicita al servidor una lista de las exportaciones disponibles. Si el servidor está exportando a través de IPv6 además de IPv4, esto listará todas las exportaciones dos veces; de lo contrario, debería listarlas todas una sola vez.

Tenga en cuenta que esta opción **solo** funciona con procesos nbd-server que ejecutan la versión 3.1 o superior, y debe estar habilitada en la configuración del servidor (con la opción "allowlist") antes de que pueda ser utilizada.

-nonetlink
-L
A partir de la versión 3.17, nbd-client utilizará por defecto la interfaz netlink para configurar un dispositivo NBD. Esta opción permite utilizar la interfaz ioctl() anterior para configurar el dispositivo.

Esta opción solo está disponible si nbd-client fue compilado contra libnl-genl. Si no es así, nbd-client solo podrá utilizar la interfaz ioctl (y la opción no estará disponible).

Tenga en cuenta que una versión futura de nbd-client **requerirá** el uso de netlink, pero aún no se ha decidido cuándo será ese el caso.

-persist
-p
Cuando se especifica esta opción, nbd-client intentará reconectar inmediatamente un dispositivo nbd si la conexión se interrumpe inesperadamente debido a la pérdida del servidor o algo similar.
-preinit
-P
Cuando se especifica esta opción, nbd-client omitirá la negociación habitual con el servidor y entregará el socket al kernel inmediatamente después de conectarse. Úselo solo cuando se conecte a servidores NBD especializados diseñados específicamente para ello. Esto requiere especificar el tamaño del dispositivo a través de la opción -B, y no soporta TLS.
-readonly
-R
Cuando se especifica esta opción, nbd-client indicará al kernel que trate el dispositivo como de solo lectura, incluso si el servidor permitiera escrituras.
-size bytes
-B bytes
Forza el tamaño del dispositivo al número especificado de bytes, en lugar de usar el valor de la negociación del servidor. Debe ser un múltiplo del tamaño de bloque. Si se usa preinit (-P) para omitir la negociación, esta opción es requerida.
-sdp
-S
Conéctese al servidor utilizando el protocolo Socket Direct Protocol (SDP), en lugar de IP. Consulte nbd-server(5) para más detalles.
-swap
-s
Especifica que este dispositivo NBD se utilizará como espacio de intercambio. Esta opción intenta prevenir deadlocks realizando mlockall() y ajustando la puntuación del oom-killer en un momento apropiado. Sin embargo, no garantiza que tales deadlocks puedan ser evitados.

NAME

nbd-client

Network Block Device client

SYNOPSIS

nbd-client [--systemd-mark | -m] [--nofork | -n] [--no-optgo | -g] [--name exportname | -N exportname] [--unix path | -u path] [--certfile file | -F file] [--keyfile file | -K file] [--cacertfile file | -A file] [--tlshostname hostname | -H hostname] [--priority gnutls priority string | -y gnutls priority string] [-swap] [-d] [--version] [--help] [host [port]] nbdid

nbd-client -c

DESCRIPTION

The nbd-client utility is used to connect to an NBD (Network Block Device) server, and to make the exported block device available to the client machine as a local block device.

The client will create a new device node, typically named /dev/nbd* (the exact name is specified by the nbdid argument), and makes the NBD server's export available at this device node.

To use the device, you typically first run nbd-client to connect to the server. After the connection is established, the device node will be available. You can then use standard tools like fdisk, mkfs, mount, etc. on the device node.

To disconnect, you must first unmount any filesystem that might be mounted on the device node, and then run nbd-client -d nbdid.

If the -swap option is given, the device node is marked as usable for swapping. This has implications for how the kernel handles memory pressure, see the TLS SUPPORT section below.

If the -c option is given, nbd-client will attempt to connect to all configured NBD devices (e.g. from /etc/nbd-tab) automatically.

The -d option disconnects an existing NBD device.

The -v option prints version information.

OPTIONS

-systemd-mark
-m
El sistema de inicio systemd requiere que los procesos que no deben ser terminados al apagar se marquen apropiadamente reemplazando la primera letra de su argv[0] con un signo '@'.

Esta opción hará que nbd-client lo haga.

Tenga en cuenta que esto solo funciona si nbd-client se ejecuta desde un initrd; es decir, systemd ignorará dicha marca si se ejecuta desde un archivo de unidad de systemd o desde la línea de comandos.

-nofork
-n
Especifica que el cliente NBD no debe separarse y convertirse en un demonio. Esto es principalmente útil para depuración.

Tenga en cuenta que nbd-client aún se bifurcará una vez para activar una actualización de la tabla de particiones del nodo del dispositivo. No es posible deshabilitar esto.

-no-optgo
-g
Deshabilita el uso del mensaje de protocolo NBD_OPT_GO, y fuerza el uso de NBD_OPT_EXPORT_NAME en su lugar.

El protocolo NBD tiene dos fases: la fase de negociación y la fase de transmisión. Para pasar de la negociación a la transmisión, los clientes más antiguos enviaban el mensaje NBD_OPT_EXPORT_NAME, para el cual el servidor no podía producir un mensaje de error en caso de que el nombre de exportación no existiera (o el cliente tuviera permisos insuficientes para acceder a él). Debido a esas limitaciones, se creó un mensaje de reemplazo, NBD_OPT_GO, que permite al servidor responder con un error en caso de cualquier problema.

El protocolo permite que un servidor descarte un mensaje que no entiende; sin embargo, desafortunadamente algunas implementaciones (incluidas versiones antiguas de nbd-server) no manejaron esa situación correctamente y se desincronizaron con el cliente cuando este enviaba un mensaje que el servidor no entendía.

Al enviar NBD_OPT_GO, nbd-client intentará hacer lo correcto y recurrirá a NBD_OPT_EXPORT_NAME. Sin embargo, cuando el servidor tiene el error descrito anteriormente, esto no funciona. En tal situación, el cliente emitirá un diagnóstico que sugiere el uso de esta opción.

Tenga en cuenta que también existe una opción correspondiente para nbdtab.

-name
-N
Especifica el nombre de la exportación que queremos usar. Si no se especifica, nbd-client solicitará una exportación "default", si existe una en el servidor.
-unix
-u
Conéctese al servidor a través de un socket de dominio Unix en ruta, en lugar de a un servidor a través de un socket TCP. El servidor debe estar escuchando en el socket dado.
-certfile archivo
-F
Use el archivo especificado como certificado de cliente para la autenticación TLS con el servidor.
-keyfile archivo
-K
Use el archivo especificado como clave privada para el certificado de cliente.
-cacertfile archivo
-A
Use el archivo especificado como certificado de CA para la autenticación TLS con el servidor.
-tlshostname nombrehost
-H
Use el nombre de host especificado para el contexto TLS. Si no se especifica, se utilizará el nombre de host utilizado para conectarse al servidor.
-priority cadena de prioridad de gnutls
-y
Pase la cadena de prioridad especificada a GnuTLS. Esto se puede usar para configurar la conexión TLS; consulte la documentación de GnuTLS para obtener más detalles.

El valor predeterminado para esta opción es NORMAL:-VERS-TLS-ALL:+VERS-TLS1.2.

-swap
Marque el dispositivo NBD como apropiado para ser utilizado como área de intercambio (swap). Esto puede tener implicaciones de rendimiento y seguridad, especialmente cuando se utiliza junto con TLS. Vea la sección TLS SUPPORT para más detalles.
-d
Desconecta un dispositivo NBD existente. Por ejemplo, nbd-client -d /dev/nbd0 desconectará el dispositivo NBD0.
-c
Intenta conectar todos los dispositivos NBD configurados (por ejemplo, en /etc/nbd-tab).
--version
Muestra la información de la versión y sale.
--help
Muestra un mensaje de ayuda y sale.

SOPORTE TLS

Habilitar cualquiera de las opciones relacionadas con TLS hace que el cliente utilice el comando NBD_OPT_STARTTLS para actualizar la conexión a TLS. Dado que negociar el soporte TLS desde el espacio de usuario para un socket del kernel sería muy complejo (incluso si pasar claves al espacio del kernel fuera posible, lo cual no es), la forma en que esto se implementa es que el proceso nbd-client crea un par de sockets, uno de los cuales entrega al kernel y el otro se entrega a un proxy de cifrado/descifrado. Esto tiene el efecto de que toda la comunicación se cifrará antes de ser enviada por la red; sin embargo, hacer esto no es seguro en combinación con el intercambio en un dispositivo NBD:

Para liberar memoria mediante intercambio, el kernel necesita estar seguro de que la escritura en el dispositivo nbd se ha completado. Para ello, necesita poder recibir una respuesta de NBD_CMD_WRITE que le informe que la escritura se ha completado con éxito y que la memoria puede ser liberada. Sin embargo, recibir datos a través de la red requiere que el kernel **allocate** memoria primero, lo cual es imposible si tenemos poca memoria (una situación probable al intentar intercambiar). Esto probablemente causará un interbloqueo cuando tengamos poca memoria y haya mucho tráfico de red.

Para remediar esta situación, el kernel establece la opción PF_MEMALLOC en el socket nbd; cuando tiene poca memoria, descarta todos los paquetes excepto aquellos destinados a un socket con esa opción configurada, confiando en el sistema de retransmisión normal de TCP para garantizar que los datos no se pierdan. Esto evita el interbloqueo descrito anteriormente.

Sin embargo, la opción PF_MEMALLOC se establece en el socket que está conectado al dispositivo nbd, no en el socket cifrado conectado al proxy de cifrado/descifrado. Como tal, cuando se utiliza TLS, la opción PF_MEMALLOC no se establece en el socket que realmente recibe datos de la red, lo que significa que el interbloqueo reaparece.

Por esta razón, si se utiliza la opción -swap cuando TLS está en uso, nbd-client emitirá una advertencia apropiada.

EJEMPLOS

Algunos ejemplos de uso de nbd-client:

•
Para conectarse a un servidor que se ejecuta en el puerto 2000 en el host "server.domain.com", utilizando el archivo especial de bloque del cliente "/dev/nbd0":

nbd-client server.domain.com 2000 /dev/nbd0

•
Para conectarse a un servidor que se ejecuta en el puerto 2001 en el host "swapserver.domain.com", utilizando el archivo especial de bloque del cliente "/dev/nbd1", para fines de intercambio:

nbd-client swapserver.domain.com 2001 /dev/nbd1 -swap

•
Para desconectar la conexión anterior nuevamente (después de asegurarse de que el archivo especial de bloque ya no esté en uso):

nbd-client -d /dev/nbd1
