NOMBRE

nbdcopy - copiar hacia y desde un servidor NBD

SINOPSIS

nbdcopy [--allocated] [-C N|--connections=N]
        [--destination-is-zero|--target-is-zero] [--flush]
        [--no-extents] [-p|--progress|--progress=FD]
        [--queue-size=N] [--request-size=N] [-R N|--requests=N]
        [-S N|--sparse=N] [--synchronous] [-T N|--threads=N]
        [-v|--verbose]
        FUENTE DESTINO
FUENTE, DESTINO := - | ARCHIVO | DISPOSITIVO | NBD-URI | [ CMD ARG ... ]
DESTINO += null:
nbdcopy --help
nbdcopy -V|--version

EJEMPLOS

nbdcopy nbd://example.com local.img

Esto copia todo desde el servidor NBD en "example.com" a un archivo local llamado local.img.

nbdcopy nbd://example.com - | file -

Esto transmite la primera parte del disco en el servidor NBD en "example.com" al comando file(1). Nótese aquí que "-" significa transmitir a stdout (y por lo tanto al pipe hacia el comando file).

nbdinfo(1) es otra forma de detectar el contenido en un servidor NBD.

nbdcopy -p /dev/sdX "nbd+unix:///?socket=/tmp/unixsock"

Copia el disco duro local completo "/dev/sdX" al servidor NBD que escucha en el socket de dominio Unix /tmp/unixsock. Debido a la opción -p, esto mostrará una barra de progreso.

nbdcopy nbd://server1 nbd://server2

Copia un disco completo de un servidor NBD a otro.

nbdcopy -- [ qemu-nbd -r -f qcow2 https://example.com/disk.qcow2 ] -

Ejecuta qemu-nbd(8) como un subproceso para abrir la URL "https://example.com/disk.qcow2", que luego se transmite a stdout ("-"), convirtiéndose a bloques de datos en formato raw. Nota "--" para evitar que las banderas de qemu-nbd se interpreten como banderas de nbdcopy.

cat disk1 disk2 | nbdcopy -- - [ qemu-nbd -f qcow2 output.qcow2 ]

Concatena dos imágenes de disco en formato raw en el archivo qcow2 output.qcow2. El archivo de salida tiene que ser precreado.

nbdcopy nbd://server null:

Lee el contenido del servidor NBD tan rápido como sea posible y lo descarta (lo escribe a un dispositivo nulo virtual). Esto es útil para benchmarking de servidores NBD y/o nbdcopy.

DESCRIPCIÓN

nbdcopy copia hacia y desde un servidor NBD. Puede subir un archivo local a un servidor NBD, o descargar el contenido de un servidor NBD a un archivo local, dispositivo o stdin/stdout. También puede copiar entre servidores NBD.

El archivo local puede ser un archivo, un dispositivo de bloques (ej. "/dev/cdrom"), o "-" que significa transmitir desde stdin o transmitir a stdout.

El servidor NBD puede especificarse usando una URI NBD (como "nbd://localhost"). El servidor NBD puede ser local o remoto, y se puede usar encriptación si libnbd fue compilado con soporte de encriptación. Alternativamente, puedes usar corchetes alrededor de un comando qemu-nbd(8) o nbdkit(1) para ejecutar el servidor NBD como un subproceso de nbdcopy.

El destino puede ser la palabra especial "null:" para descartar la salida.

Para operaciones de copia más complejas, incluyendo la conversión entre formatos de disco, usa "qemu-img convert", consulta qemu-img(1).

OPCIONES

--help
Muestra la ayuda breve de la línea de comandos y sale.
--allocated
Normalmente nbdcopy intenta crear una salida dispersa (con agujeros) si el destino lo soporta. Lo hace de dos maneras: o bien usando información de extensiones del origen para copiar agujeros (ver --no-extents), o detectando secuencias de ceros (ver -S). Si usas --allocated, nbdcopy crea una salida completamente asignada y no dispersa en el destino.
-C N
--connections=N
Establece el número máximo de conexiones NBD ("multi-conn"). Por defecto, nbdcopy intentará usar multi-conn con hasta 4 conexiones si el servidor NBD lo soporta. Si se copia entre servidores NBD, nbdcopy no podrá usar multi-conn si alguno de los servidores no lo soporta.
--destination-is-zero
--target-is-zero
Asume que el destino ya está cero. Esto permite a nbdcopy omitir la copia de bloques de ceros desde el origen al destino. Esto no es seguro a menos que el dispositivo de destino ya esté cero. (--target-is-zero se proporciona por compatibilidad con qemu-img(1).)
--flush
Descarga las escrituras para asegurar que todo se ha escrito en almacenamiento persistente antes de que nbdcopy salga.
--no-extents
Normalmente nbdcopy utiliza metadatos de extensión para saltarse partes del disco de origen que contienen agujeros. Si usas esta bandera, nbdcopy ignora la información de extensión y lee todo, lo cual suele ser más lento. Podrías usar esta bandera en dos situaciones: el servidor NBD de origen tiene información de metadatos incorrecta; o la consulta de extensiones del origen es muy lenta, por lo que es más rápido simplemente leer todos los datos.
-p
--progress
Muestra una barra de progreso.
--progress=FD
Escribe una barra de progreso en el descriptor de archivo "FD" (un número) en un formato que puede ser fácilmente analizado por otros programas. nbdcopy escribirá periódicamente la cadena "N/100\n" (donde N es un entero entre 0 y 100) al descriptor de archivo.

Para que nbdcopy escriba la barra de progreso a un archivo, puedes usar los siguientes comandos de shell:

exec 3>/tmp/progress
nbdcopy --progress=3 ...
exec 3>&-
--queue-size=N
Establece el número máximo de bytes a poner en cola para solicitudes en curso. El valor por defecto es 16 MiB, permitiendo hasta 64 solicitudes de 256k por conexión NBD. Si usas un --request-size mayor, puede que quieras aumentar este valor.
--request-size=N
Establece el tamaño máximo de solicitud en bytes. El valor máximo es 32 MiB, especificado por el protocolo NBD.
-R N
--requests=N
Establece el número máximo de solicitudes en curso por conexión NBD.
-S N
--sparse=N
Detecta todos los bloques cero de tamaño N (bytes) y los hace dispersos en la salida. También puedes desactivar la detección de dispersión usando -S 0. El valor por defecto es 4096 bytes, o el tamaño de bloque preferido del destino, lo que sea mayor.
--synchronous
Realiza todas las operaciones de I/O de forma síncrona. Esto hace que nbdcopy sea mucho más lento, pero garantiza que las escrituras se completen en el disco antes de que la operación de copia regrese. Esto es útil para probar la latencia de E/S del servidor NBD.
-T N
--threads=N
Establece el número de hilos de trabajo a usar para operaciones de E/S de disco. El valor por defecto es 4. Si este valor se establece en 0, nbdcopy usará un solo hilo.
-v
--verbose
Aumenta la verbosidad de la salida. Puedes usar esta opción varias veces para aumentar aún más la verbosidad.
--version
Muestra información sobre la versión y sale.
