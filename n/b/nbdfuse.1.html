NOMBRE

nbdfuse - montar un dispositivo de bloque de red en el sistema de archivos local

SINOPSIS

nbdfuse [-C N|--connections N] [-d] [-o FUSE-OPTION] [-P PIDFILE]
        [-r] [-s] [-v|--verbose]
        PUNTO_MONTAJE[/NOMBRE_ARCHIVO] URI
nbdfuse PUNTO_MONTAJE[/NOMBRE_ARCHIVO] [ COMANDO [ARGUMENTOS ...] ]
nbdfuse PUNTO_MONTAJE[/NOMBRE_ARCHIVO] --command COMANDO [ARGUMENTOS ...]
nbdfuse PUNTO_MONTAJE[/NOMBRE_ARCHIVO] --fd N
nbdfuse PUNTO_MONTAJE[/NOMBRE_ARCHIVO] --tcp HOST PUERTO
nbdfuse PUNTO_MONTAJE[/NOMBRE_ARCHIVO] --unixSOCKET
nbdfuse PUNTO_MONTAJE[/NOMBRE_ARCHIVO] --vsock CID PUERTO

Para desmontar:

fusermount3 -u PUNTO_MONTAJE

Otras opciones:

nbdfuse --help
nbdfuse --fuse-help
nbdfuse -V|--version

DESCRIPCIÓN

nbdfuse se utiliza para montar un Dispositivo de Bloque de Red (NBD) en el sistema de archivos local. El archivo virtual NBD se monta en PUNTO_MONTAJE/NOMBRE_ARCHIVO (por defecto PUNTO_MONTAJE/nbd). Las lecturas y escrituras en el archivo virtual se convierten en lecturas y escrituras en el dispositivo NBD.

En nbdfuse ≥ 1.6 también puedes crear un punto de montaje "desnudo" montando sobre cualquier archivo regular llamado PUNTO_MONTAJE (el contenido existente del archivo no importa).

El propio servidor NBD puede ser local o remoto. El servidor puede especificarse como una URI NBD (como "nbd://localhost"), o como un servidor NBD ejecutándose como un subproceso de nbdfuse (usando "[ ... ]"), o de varias otras maneras (ver "MODOS").

Utiliza "fusermount3 -u PUNTO_MONTAJE" para desmontar el sistema de archivos después de haberlo utilizado.

EJEMPLOS

Presentar un servidor NBD remoto como un archivo local

Si hay un servidor NBD remoto ejecutándose en "example.com" en el número de puerto NBD por defecto (10809), puedes convertirlo en un archivo local haciendo:

$ mkdir dir
$ nbdfuse dir nbd://example.com &
$ ls -l dir/
total 0
-rw-rw-rw-. 1 nbd nbd 1073741824 Jan  1 10:10 nbd

El archivo se llama dir/nbd y puedes leer y escribir en él como si fuera un archivo normal. Ten en cuenta que las escrituras en el archivo se escribirán en el servidor NBD remoto. Después de usarlo, desmóntalo:

$ fusermount3 -u dir
$ rmdir dir

Usar nbdkit para crear un archivo respaldado por un disco RAM temporal

Usando "[ ... ]" puedes ejecutar un servidor NBD como subproceso. En este ejemplo nbdkit(1) se usa para crear un archivo temporal respaldado por un disco RAM:

$ mkdir dir
$ nbdfuse dir/ramdisk [ nbdkit --exit-with-parent memory 1G ] &
$ ls -l dir/
total 0
-rw-rw-rw-. 1 nbd nbd 1073741824 Jan  1 10:10 ramdisk
$ dd if=/dev/urandom bs=1M count=100 of=mp/ramdisk conv=notrunc,nocreat
100+0 records in
100+0 records out
104857600 bytes (105 MB, 100 MiB) copied, 2.08319 s, 50.3 MB/s

Cuando hayas terminado con el disco RAM, puedes desmontarlo como se indica a continuación, lo que provocará que nbdkit salga y que el contenido del disco RAM se descarte:

$ fusermount3 -u dir
$ rmdir dir

Usar qemu-nbd para leer y modificar un archivo qcow2

Puedes usar qemu-nbd(8) como subproceso para abrir cualquier formato de archivo que qemu entienda:

$ mkdir dir
$ nbdfuse dir/file.raw [ qemu-nbd -f qcow2 file.qcow2 ] &
$ ls -l dir/
total 0
-rw-rw-rw-. 1 nbd nbd 1073741824 Jan  1 10:10 file.raw

El archivo dir/file.raw está en formato raw, respaldado por file.qcow2. Cualquier cambio realizado en dir/file.raw se reflejará en el archivo qcow2. Para desmontar el archivo haz:

$ fusermount3 -u dir
$ rmdir dir

Usar nbdkit para crear un archivo local desde un archivo en un servidor web

nbdkit(1) es capaz tanto de acceder como de descomprimir transparentemente imágenes de disco remotas en servidores web, por lo que puedes convertirlas en archivos virtuales:

$ mkdir dir
$ nbdfuse dir/disk.iso \
      [ nbdkit --exit-with-parent \
               curl --filter=xz \
               http://builder.libguestfs.org/fedora-30.xz ] &
$ ls -l dir/
total 0
-rw-rw-rw-. 1 nbd nbd 6442450944 Jan  1 10:10 disk.iso
$ file dir/disk.iso
dir/disk.iso: DOS/MBR boot sector
$ qemu-system-x86_64 -m 4G \
      -drive file=dir/disk.iso,format=raw,if=virtio,snapshot=on
$ fusermount3 -u dir

En este ejemplo hemos utilizado el archivo virtual para arrancar qemu, pero qemu puede acceder de manera mucho más eficiente a los servidores NBD directamente, por lo que en el mundo real ese sería el método preferido.

OPCIONES

--help
Mostrar ayuda breve de la línea de comandos y salir.
-C N
--connections N
Si se usa multi-conn, usar N conexiones al servidor. El valor por defecto es 4.

Multi-conn está habilitado por defecto cuando es posible. Los modos que ejecutan un subproceso, como --command, no pueden usar multi-conn. El modo --fd tampoco puede usar multi-conn. Además, el servidor debe anunciar multi-conn (usa nbdinfo(1) para consultar lo que el servidor soporta).

Ver "MODELO DE HILOS" abajo.

-C 1
--connections 1
Deshabilitar multi-conn. Usar solo una conexión al servidor NBD. Ver "MODELO DE HILOS" abajo.
--fuse-help
Mostrar opciones de FUSE y salir. Ver -o abajo.
-o OPCIÓN-FUSE
Pasar opciones adicionales a FUSE. Para obtener una lista de todas las opciones adicionales soportadas por FUSE, usa --fuse-help.

Algunas opciones FUSE potencialmente útiles:

-o allow_other
Permitir que otros usuarios vean el sistema de archivos. Esta opción no tiene ningún efecto a menos que la habilites globalmente en /etc/fuse.conf.
-o kernel_cache
Permitir al kernel cachear archivos (reduce el número de lecturas que tienen que pasar por la API de libnbd(3)). Esto es generalmente una buena idea si puedes permitirte el uso de memoria adicional.
-o uid=N
-o gid=N
Usa estas opciones para mapear UIDs y GIDs.
-P ARCHIVO_PID
--pidfile ARCHIVO_PID
Cuando nbdfuse esté listo para servir, escribe el ID del proceso (PID) de nbdfuse en ARCHIVO_PID. Esto se puede usar en scripts para esperar hasta que nbdfuse esté listo. Ten en cuenta que no debes intentar matar nbdfuse. Usa "fusermount3 -u" para desmontar el punto de montaje, lo que hará que nbdfuse salga limpiamente.
-r
--readonly
Acceder al dispositivo de bloque de red en modo de solo lectura. El archivo virtual tendrá permisos de solo lectura, y cualquier escritura devolverá errores.

Si el servidor NBD remoto está en modo de solo lectura, este indicador se añade automáticamente. (Comprueba el campo "is_read_only:" en la salida de nbdinfo(1)).

-s
Usar operaciones FUSE en un solo hilo. Ver "MODELO DE HILOS" abajo.
-v
--verbose
-V / --version
Mostrar la versión del programa y salir.

MODOS

Se debe especificar uno de los siguientes argumentos para decirle a nbdfuse cómo conectarse al servidor NBD:

URI
Conectarse a un servidor NBD en la URI especificada. Las URI admitidas son nbd://host[:port], nbds://host[:port] (para SSL/TLS, requiere la opción --tls-ca-file o --tls-ca-dir), nbdmk://host[:port] y nbd://host[:port]/path/to/disk.img (para montar un disco específico en un servidor que aloja varios discos).

--command CMD [ARGS ...]
Ejecutar el comando especificado como un subproceso y conectarse a él. El comando debe ser un programa que actúe como un servidor NBD. El programa se ejecutará con el descriptor de archivo 3 conectado a su stdin y el descriptor de archivo 4 conectado a su stdout. El programa debe implementar el protocolo NBD en estos descriptores de archivo.
--fd N
Conectarse a un servidor NBD que ya está ejecutándose y ha abierto los descriptores de archivo de entrada/salida y el descriptor de archivo de control. N es el descriptor de archivo de control (por ejemplo, 3).
--tcp HOST PORT
Conectarse a un servidor NBD en HOST y PUERTO usando TCP. Equivalente a nbd://HOST:PORT.
--unixSOCKET
Conectarse a un servidor NBD a través de un socket Unix. El socket Unix debe ser creado por el proceso nbdfuse. Esto es útil si quieres iniciar un servidor NBD como un subproceso y quieres que nbdfuse se conecte a él usando un socket Unix. En este modo, nbdfuse espera hasta que el socket Unix sea creado por el proceso del servidor.
--vsock CID PORT
Conectarse a un servidor NBD a través de vsock. CID es el ID del contexto del hipervisor y PORT es el puerto vsock.
"[ ... ]"
Cuando el primer argumento después de PUNTO_MONTAJE o PUNTO_MONTAJE/NOMBRE_ARCHIVO es una cadena entre corchetes, se interpreta como un comando para ejecutar como subproceso. Por ejemplo, nbdfuse mp [ nbdkit memory 1G ].

MODELO DE HILOS

Por defecto, nbdfuse utiliza el modelo de hilos multiconexión de FUSE. Esto significa que el kernel de Linux puede enviar múltiples solicitudes de E/S simultáneamente a nbdfuse. Para que esto funcione, nbdfuse utiliza varios hilos de conexión NBD, de modo que las solicitudes se puedan procesar en paralelo.

Si el servidor NBD no soporta multi-conn, o si prefieres usar un solo hilo, puedes deshabilitar multi-conn usando la opción -C 1 o --connections 1. En este caso, nbdfuse usará un solo hilo para procesar las solicitudes NBD. Sin embargo, esto puede afectar al rendimiento si el servidor NBD es lento o si hay muchas solicitudes pendientes.

La opción -s fuerza el uso de operaciones FUSE monohilo. Esto significa que FUSE solo enviará una solicitud a la vez. Esto puede ser útil para depurar o si el servidor NBD no es seguro para hilos.

SEGUIMIENTO DE ERRORES

Los errores se imprimen en stderr. Si se usa el modo verbose, también se imprimirán los mensajes de depuración.

Para desvincular y ver la salida de error, usa un formato como:

$ nbdfuse /mnt/nbd nbd://server > /dev/null

Si el proceso de nbdfuse falla, puedes necesitar desmontar el punto de montaje manualmente:

$ fusermount3 -u /mnt/nbd

NAME

nbdfuse

mount an NBD server as a FUSE filesystem

SYNOPSIS

nbdfuse [ -d ] [ -V ] [ --version ] [ -C connections ] [ -s ] [ -f ] [ -o FUSE option ]... MOUNTPOINT MODE

DESCRIPTION

nbdfuse is a FUSE client for the Network Block Device protocol. It allows you to mount an NBD server on a local directory, making it appear as a regular filesystem. This allows you to access the NBD server using standard Linux tools like ls, cp, mv, rm, etc.

It uses the libnbd library to connect to the NBD server.

EXAMPLES

Mount an NBD server exporting an export named "disk" over TLS on the remote host "example.com" to the local directory "/mnt/mydisk":

nbdfuse /mnt/mydisk nbds://example.com/disk

Mount an NBD server running on stdin/stdout (e.g., nbdkit -s) to "/mnt/mydisk":

nbdfuse /mnt/mydisk --command nbdkit -s disk.img

Mount an NBD server connected via TCP to host "192.168.0.1" port "10809" to "/mnt/mydisk":

nbdfuse /mnt/mydisk --tcp 192.168.0.1 10809

OPTIONS

-d
Activar mensajes detallados a stderr. Esto habilita la depuración de libnbd y otros mensajes. La opción -d es un alias, utilizada por compatibilidad con otros programas FUSE.
-V
--version
Mostrar el nombre del paquete y la versión y salir.

MODOS

Los modos se utilizan para seleccionar el servidor NBD. Los modos posibles son:

nbdfuse PUNTO_MONTAJE URI
Este modo utiliza una URI NBD (ver nbd_connect_uri(3) y https://github.com/NetworkBlockDevice/nbd/blob/master/doc/uri.md). Por ejemplo, esto especifica una conexión cifrada con TLS a "example.com" puerto 10809, con nombre de exportación "disk": 
nbdfuse dir nbds://example.com/disk
nbdfuse PUNTO_MONTAJE [ CMD [ARGS ...] ]
Ejecutar un servidor NBD como un subproceso. En este modo, se puede ejecutar un servidor NBD directamente desde la línea de comandos con nbdfuse comunicándose con el servidor a través de un socket. Esto requiere que el servidor NBD admita la activación de sockets systemd. Consulte "EJEMPLOS" arriba y nbd_connect_systemd_socket_activation(3).
nbdfuse PUNTO_MONTAJE --command CMD [ARGS ...]
Seleccionar modo de comando. En este modo, se puede ejecutar un servidor NBD directamente desde la línea de comandos con nbdfuse comunicándose con el servidor a través de la entrada/salida estándar del servidor. Normalmente, utilizaría esto con "nbdkit -s". Ver nbd_connect_command(3).
nbdfuse PUNTO_MONTAJE --fd N
Seleccionar modo de descriptor de archivo. En este modo, se pasa un socket conectado a nbdfuse. nbdfuse se conecta al socket en el descriptor de archivo numerado. Ver también nbd_connect_socket(3).
nbdfuse PUNTO_MONTAJE --tcp HOST PUERTO
Seleccionar modo TCP. Conectarse a un servidor NBD en un host y puerto a través de un socket TCP sin cifrar. Ver también nbd_connect_tcp(3).
nbdfuse PUNTO_MONTAJE --unix SOCKET
Seleccionar modo Unix. Conectarse a un servidor NBD en un socket de dominio Unix. Ver también nbd_connect_unix(3).
nbdfuse PUNTO_MONTAJE --vsock CID PUERTO
Seleccionar modo vsock. Conectarse a un servidor NBD en un socket "AF_VSOCK". Ver también nbd_connect_vsock(3).

MODELO DE HILOS

Esta sección describe cómo funciona la versión actual de nbdfuse. Versiones anteriores funcionaron de manera diferente en el pasado, y versiones futuras pueden funcionar de manera diferente en el futuro.

nbdfuse siempre es multihilo.

nbdfuse intentará abrir múltiples conexiones de red al servidor NBD si es posible (llamado "multi-conn"). Esto generalmente mejora el rendimiento. Algunas cosas que *deshabilitan* multi-conn son:

  • usar "[ CMD ... ]" o --command o modos --fd
  • usar -C 1
  • el servidor NBD no anuncia multi-conn (verificar usando nbdinfo(1))

Puede controlar cuántas conexiones se realizan utilizando la bandera -C.

nbdfuse ejecuta un hilo por conexión para atender los comandos NBD (estos se llaman "hilos de operación"). Además, FUSE en sí crea múltiples hilos para lidiar con las solicitudes que provienen del módulo del kernel fuse.ko. El número de hilos que FUSE puede crear se describe en la documentación de FUSE, pero con muchos accesos paralelos al archivo virtual, puede haber muchos más hilos FUSE creados que hilos de operación, y esto debería conducir a un buen rendimiento. Las solicitudes FUSE (como leer, escribir o recortar) se multiplexan en los hilos de operación (= conexiones) al azar. Cada hilo de operación puede manejar múltiples solicitudes en paralelo.

Usar la bandera -s hace que FUSE ejecute un solo hilo, pero todavía puede haber múltiples hilos de operación.

NOTAS

Montaje en bucle

Es tentador (y posible) montar el archivo en bucle. Sin embargo, esto será muy lento y a veces puede provocar un interbloqueo. Mejores alternativas son usar nbd-client(8) o qemu-nbd(8), o de forma más segura libguestfs(3), guestfish(1) o guestmount(1) que pueden acceder a servidores NBD.

Como forma de acceder a servidores NBD

Puede usar esto para acceder a servidores NBD, pero generalmente es mejor (y definitivamente mucho más rápido) usar libnbd(3) directamente en su lugar. Para acceder a servidores NBD desde la línea de comandos, consulte nbdsh(1). Para copiar hacia y desde un servidor NBD, use nbdcopy(1).

COMPARACIÓN CON OTRAS HERRAMIENTAS

Comparado con "nbd-client"

Este programa es similar en concepto a nbd-client(8) (que convierte NBD en nodos de dispositivo /dev/nbdX), excepto:

  • nbd-client es más rápido porque usa un módulo de kernel especial
  • nbd-client requiere ser root, pero nbdfuse puede ser utilizado por cualquier usuario
  • los archivos virtuales de nbdfuse se pueden montar en cualquier lugar del sistema de archivos
  • nbdfuse usa libnbd para hablar con el servidor NBD
  • nbdfuse requiere soporte FUSE en el kernel

Comparado con "qemu-nbd"

qemu-nbd(8) también puede adjuntarse a nodos de dispositivo /dev/nbdX. Las diferencias con nbdfuse son similares a la lista anterior.

    nbdfuse(1)

    NAME

    nbdfuse - mounts a Network Block Device (NBD) server as a FUSE filesystem

    SYNOPSIS

    nbdfuse [OPTIONS] URI MOUNTPOINT

    DESCRIPTION

    nbdfuse is a FUSE (Filesystem in Userspace) client for the Network Block Device (NBD) protocol. It allows you to mount an NBD server as a block device or as a filesystem. When mounted as a filesystem, you can interact with the NBD server's storage as if it were a local disk.

    The URI parameter specifies the NBD server to connect to. It can be in the format:

    • nbd://host:port
    • nbds://host:port (for TLS/SSL encrypted connections)
    • nbd://host/exportname
    • nbds://host/exportname

    The MOUNTPOINT parameter specifies the directory where the NBD device will be mounted.

    OPTIONS

    -h, --help
    Show help message and exit.
    -V, --version
    Print version information and exit.
    -c, --connect-timeout SECONDS
    Set the connection timeout in seconds. Default is 10.
    -k, --keep-alive SECONDS
    Set the keep-alive interval in seconds. Default is 30.
    -t, --tls-cipher CIPHER
    Specify the TLS cipher suite to use. Requires OpenSSL.
    -C, --tls-cafile FILE
    Specify the CA certificate file for TLS/SSL verification.
    -K, --tls-certfile FILE
    Specify the client certificate file for TLS/SSL authentication.
    -p, --tls-keyfile FILE
    Specify the client private key file for TLS/SSL authentication.
    -f, --foreground
    Run nbdfuse in the foreground.
    -d, --debug
    Enable debug output.
    -o options
    Mount options (see `mount.fuse(8)`).

    EXAMPLE

    Mount an NBD server at nbd://example.com/myexport to the directory /mnt/nbd:

    nbdfuse nbd://example.com/myexport /mnt/nbd

    THREAD MODEL

    nbdfuse uses a single thread for handling FUSE requests and communicates with the NBD server asynchronously.

    NOTES

    nbdfuse requires FUSE to be installed and configured on your system.

    When mounting as a filesystem, nbdfuse presents the NBD device as a raw block device. This means you can format it with a filesystem (e.g., ext4, XFS) and mount it like any other block device.

    For secure connections (nbds://), ensure that the server is configured with TLS/SSL and that you provide the necessary certificate files if required.

    COMPARISON TO OTHER TOOLS

    Unlike the standard nbd-client command, which typically mounts the NBD device as a raw block device (e.g., /dev/nbdX), nbdfuse directly integrates with FUSE to present the NBD server's storage as a mountable filesystem.

    fuse(8), mount.fuse(8), nbd-client(8)
