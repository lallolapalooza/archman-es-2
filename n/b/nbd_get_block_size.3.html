nbd_get_block_size(3) LIBNBD nbd_get_block_size(3)

NOMBRE

nbd_get_block_size - devuelve una restricción específica de tamaño de bloque del servidor

SINOPSIS

#include <libnbd.h>
int64_t nbd_get_block_size (
          struct nbd_handle *h, int size_type
        );

DESCRIPCIÓN

Devuelve una restricción específica de tamaño de bloque anunciada por el servidor. Si se devuelve cero, significa que el servidor no anunció ninguna restricción.

Las restricciones son sugerencias. Los servidores difieren en su comportamiento en cuanto a si imponen o no las restricciones.

El parámetro "size_type" selecciona qué restricción leer. Puede ser una de las siguientes:

"LIBNBD_SIZE_MINIMUM" = 0
Si no es cero, será una potencia de 2 entre 1 y 64k; cualquier solicitud del cliente que no esté alineada en longitud o desplazamiento a este tamaño es probable que falle con "EINVAL". El tamaño de la imagen generalmente también será un múltiplo de este valor (si no es así, los últimos bytes son inaccesibles mientras se obedecen las restricciones de alineación).

Si es cero (lo que significa que el servidor no devolvió información), es más seguro asumir un tamaño de bloque mínimo de 512, aunque muchos servidores admiten un tamaño de bloque mínimo de 1.

Si el servidor proporciona una restricción, entonces libnbd, por defecto, respeta esa restricción en el lado del cliente a menos que "LIBNBD_STRICT_ALIGN" se desactive en nbd_set_strict_mode(3).

"LIBNBD_SIZE_PREFERRED" = 1
Si no es cero, esta es una potencia de 2 que representa el tamaño preferido para E/S eficientes. Las solicitudes más pequeñas pueden incurrir en sobrecarga, como ciclos de lectura-modificación-escritura que no estarán presentes al usar E/S que sea un múltiplo de este valor. Este valor puede ser mayor que el tamaño de la exportación.

Si es cero (lo que significa que el servidor no devolvió información), usar 4k como tamaño de bloque preferido tiende a dar un rendimiento decente.

"LIBNBD_SIZE_MAXIMUM" = 2
Si no es cero, representa la longitud máxima que el servidor está dispuesto a manejar durante nbd_pread(3) o nbd_pwrite(3). Otras funciones como nbd_zero(3) aún pueden usar tamaños más grandes. Tenga en cuenta que esta función devuelve lo que el servidor anunció, pero libnbd en sí mismo impone un máximo de 64M.

Si es cero (lo que significa que el servidor no devolvió información), algunos servidores NBD se desconectarán abruptamente si una transacción envía o recibe más de 32M de datos.

"LIBNBD_SIZE_PAYLOAD" = 3
Este valor no lo anuncia el servidor, sino que representa el tamaño máximo de carga útil saliente para una conexión dada que libnbd aplicará, a menos que "LIBNBD_STRICT_PAYLOAD" se desactive en nbd_set_strict_mode(3). Siempre es distinto de cero: nunca menor que 1M, nunca mayor que 64M, y coincide con "LIBNBD_SIZE_MAXIMUM" cuando sea posible.

Las extensiones NBD futuras pueden resultar en valores de "size_type" adicionales. Tenga en cuenta que, por defecto, libnbd solicita todos los tamaños de bloque disponibles, pero un servidor puede diferir en los tamaños que elige informar si nbd_set_request_block_size(3) altera si el cliente solicita tamaños.

Esta llamada no bloquea, porque devuelve datos que se guardan en el manejador desde el handshake del protocolo NBD.

VALOR DE RETORNO

Esta llamada devuelve un entero con signo de 64 bits ≥ 0.

ERRORES

En caso de error, se devuelve -1.

Consulte "MANEJO DE ERRORES" en libnbd(3) para obtener más detalles sobre cómo obtener información adicional sobre el error.

Los siguientes parámetros no deben ser NULL: "h". Para más información, consulte "Parámetros no nulos" en libnbd(3).

ESTADO DEL MANEJADOR

Se puede llamar a nbd_get_block_size cuando el manejador se encuentra en los siguientes estados:

┌─────────────────────────────────────┬─────────────────────────┐
│ Manejador creado, antes de conectar │ ❌ error                │
│ Conectando                          │ ❌ error                │
│ Conectando y handshake (opt_mode) │ ✅ permitido              │
│ Conectado al servidor             │ ✅ permitido              │
│ Conexión cerrada                   │ ✅ permitido              │
│ Manejador muerto                    │ ❌ error                │
└─────────────────────────────────────┴─────────────────────────┘

VERSIÓN

Esta función apareció por primera vez en libnbd 1.4.

Si necesita probar si esta función está disponible en tiempo de compilación, compruebe si está definido el siguiente macro:

#define LIBNBD_HAVE_NBD_GET_BLOCK_SIZE 1

nbd_get_block_size(3)

NAME

nbd_get_block_size - get the preferred block size

nbd_get_opt_block_size - get the preferred block size

SYNOPSIS


#include <libnbd.h>

int nbd_get_block_size (NBD_HOST host);
int nbd_get_opt_block_size (NBD_HOST host);

DESCRIPTION

These functions return the preferred block size of the NBD server connection. This is the size of blocks the server would prefer to transfer, and it may be related to the server's internal storage or filesystem block size.

The functions take one argument:

  • host: An opaque pointer to the NBD server connection returned by nbd_connect_simple() or nbd_connect_host().

The return value is the preferred block size in bytes. If the server does not support this option, or if an error occurs, it returns 0.

nbd_get_opt_block_size is an alias for nbd_get_block_size.

RETURN VALUE

On success, returns the preferred block size in bytes.

On error, returns 0. Check errno for more information.

ERRORS

No specific errors are documented for this function. However, if the NBD connection is not valid or if the server does not support this option, it will return 0.

HANDLE STATE

The NBD handle must be in the connected state.

VERSION

These functions first appeared in libnbd version 1.0.

nbd_connect_simple(3), nbd_connect_host(3), nbd_get_min_block_size(3)
