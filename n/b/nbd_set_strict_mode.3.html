nbd_set_strict_mode(3)

Paquete: libnbd

nbd_set_strict_mode(3) LIBNBD nbd_set_strict_mode(3)

NOMBRE

nbd_set_strict_mode - controlar la estrictez con la que se sigue el protocolo NBD

SINOPSIS

#include <libnbd.h>
int nbd_set_strict_mode (
      struct nbd_handle *h, uint32_t flags
    );

DESCRIPCIÓN

Por defecto, libnbd intenta detectar solicitudes que desencadenarían un comportamiento indefinido en el protocolo NBD, y las rechaza en el lado del cliente sin causar ningún tráfico de red, en lugar de arriesgarse a un comportamiento indefinido del servidor. Sin embargo, para pruebas de integración, puede ser útil relajar la estrictez de libnbd, para forzarlo a enviar dichas solicitudes a través de la red para probar la robustez del servidor al tratar con dicho tráfico.

El argumento "flags" es una máscara de bits, que incluye cero o más de las siguientes banderas de estrictez:

"LIBNBD_STRICT_COMMANDS" = 0x1
Si se establece, esta bandera rechaza solicitudes del cliente que no cumplen con el conjunto de banderas del servidor anunciadas (por ejemplo, intentar una escritura en un servidor de solo lectura, o intentar usar "LIBNBD_CMD_FLAG_FUA" cuando nbd_can_fua(3) devolvió falso). Si está desestablecida, esta bandera confía en que el servidor rechace comandos inesperados.
"LIBNBD_STRICT_FLAGS" = 0x2
Si se establece, esta bandera rechaza solicitudes del cliente que intentan establecer una bandera de comando no reconocida por libnbd (aquellas fuera de "LIBNBD_CMD_FLAG_MASK"), o una bandera no asociada normalmente con un comando (como usar "LIBNBD_CMD_FLAG_FUA" en un comando de lectura). Si está desestablecida, todas las banderas se envían al servidor, incluso si el envío de una bandera así puede hacer que el servidor cambie su respuesta de una manera que confunda a libnbd, quizás causando un bloqueo o terminando la conexión.

Las banderas que son conocidas por libnbd como asociadas con un comando dado (como "LIBNBD_CMD_FLAG_DF" para nbd_pread_structured(3) controlada por nbd_can_df(3)) se controlan en su lugar con "LIBNBD_STRICT_COMMANDS"; y "LIBNBD_CMD_FLAG_PAYLOAD_LEN" es gestionada automáticamente por libnbd a menos que "LIBNBD_STRICT_AUTO_FLAG" esté deshabilitada.

Tenga en cuenta que el protocolo NBD solo admite 16 bits de banderas de comandos, aunque la API de libnbd usa "uint32_t"; los bits fuera del rango permitido por el protocolo son siempre un error del lado del cliente.

"LIBNBD_STRICT_BOUNDS" = 0x4
Si se establece, esta bandera rechaza solicitudes del cliente que excederían los límites de exportación sin enviar ningún tráfico al servidor. Si está desestablecida, esta bandera confía en que el servidor detecte solicitudes fuera de límites.
"LIBNBD_STRICT_ZERO_SIZE" = 0x8
Si se establece, esta bandera rechaza solicitudes del cliente con longitud 0. Si está desestablecida, permite solicitudes de longitud cero al servidor, lo que puede producir resultados indefinidos.
"LIBNBD_STRICT_ALIGN" = 0x10
Si se establece, y el servidor proporcionó tamaños mínimos de bloque (ver "LIBNBD_SIZE_MINIMUM" para nbd_get_block_size(3)), esta bandera rechaza solicitudes del cliente que no tengan la longitud y el desplazamiento alineados con los requisitos mínimos del servidor. Si está desestablecida, se envían solicitudes desalineadas al servidor, donde depende del servidor si honra o rechaza la solicitud.
"LIBNBD_STRICT_PAYLOAD" = 0x20
Si se establece, el cliente se niega a enviar un comando al servidor con más que el máximo de carga útil saliente de libnbd (ver "LIBNBD_SIZE_PAYLOAD" para nbd_get_block_size(3)), independientemente de si el servidor anunció un tamaño máximo de bloque. Si está desestablecida, se pueden intentar solicitudes de gran tamaño de hasta 64MiB, aunque las solicitudes mayores de 32MiB pueden hacer que algunos servidores se desconecten.
"LIBNBD_STRICT_AUTO_FLAG" = 0x40
Si se establece, los comandos que aceptan la bandera "LIBNBD_CMD_FLAG_PAYLOAD_LEN" (como nbd_pwrite(3) y nbd_block_status_filter(3)) ignoran la presencia o ausencia de esa bandera por parte del llamante, enviando en su lugar el valor por cable que coincide con las expectativas del servidor basándose en si se negociaron encabezados extendidos al establecer la conexión. Si está desestablecida, el llamante asume la responsabilidad de si la bandera de longitud de carga útil está establecida o desestablecida durante el comando afectado, lo que puede ser útil durante las pruebas de integración pero es más probable que conduzca a un comportamiento indefinido.

Para mayor comodidad, la constante "LIBNBD_STRICT_MASK" está disponible para describir todas las banderas de estrictez admitidas por esta compilación de libnbd. Las versiones futuras de libnbd pueden agregar más banderas, que probablemente estarán habilitadas por defecto para un filtrado adicional del lado del cliente. Como tal, al intentar relajar solo un bit específico mientras se mantienen las comprobaciones restantes en el lado del cliente, es más aconsejable llamar primero a nbd_get_strict_mode(3) y modificar ese valor, en lugar de establecer ciegamente un valor constante.

VALOR DE RETORNO

Si la llamada es exitosa, la función devuelve 0.

ERRORES

En caso de error, se devuelve -1.

Consulte "MANEJO DE ERRORES" en libnbd(3) para obtener más detalles sobre el error.

Los siguientes parámetros no deben ser NULL: "h". Para más información, consulte "Parámetros no NULL" en libnbd(3).

VERSIÓN

Esta función apareció por primera vez en libnbd 1.6.

Si necesita probar si esta función está disponible en tiempo de compilación, compruebe si el siguiente macro está definido:

#define LIBNBD_HAVE_NBD_SET_STRICT_MODE 1

nbd_set_strict_mode

nbd_set_strict_mode - enable or disable strict mode

NAME

nbd_set_strict_mode - enable or disable strict mode

SYNOPSIS

#include <libnbd.h>

int nbd_set_strict_mode (NBD_CONTEXT *ctx, int enabled);

DESCRIPTION

Set strict mode for the NBD context ctx. If enabled is non-zero, strict mode is enabled. If enabled is zero, strict mode is disabled.

When strict mode is enabled, libnbd will check for common errors and report them. This can be useful for debugging your application. For example, if you attempt to disconnect from a server that is not connected, strict mode will cause a fatal error. Without strict mode, this would fail silently and the program would continue.

Strict mode is disabled by default.

RETURN VALUE

On success, return 0. On error, return -1 and set the error indicator in ctx.

ERRORS

This function can fail with errors described in nbd_clear_error(3).

VERSION

This function was introduced in version 1.2.

nbd_connect(3), nbd_disconnect(3), nbd_get_strict_mode(3).
