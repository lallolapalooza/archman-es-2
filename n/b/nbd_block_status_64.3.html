nbd_block_status_64(3)

Paquete: libnbd

Licencias: LGPL-2.1-or-later

nbd_block_status_64(3) LIBNBD nbd_block_status_64(3)

NOMBRE

nbd_block_status_64 - envía el comando de estado de bloque, con callback de 64 bits

SINOPSIS

#include <libnbd.h>
typedef struct {
  int (*callback) (void *user_data,
                   const char *metacontext,
                   uint64_t offset, nbd_extent *entries,
                   size_t nr_entries, int *error);
  void *user_data;
  void (*free) (void *user_data);
} nbd_extent64_callback;
int nbd_block_status_64 (
      struct nbd_handle *h, uint64_t count,
      uint64_t offset,
      nbd_extent64_callback extent64_callback,
      uint32_t flags
    );

DESCRIPCIÓN

Emite el comando de estado de bloque al servidor NBD. Si es soportado por el servidor, esto hace que se devuelva información de contexto de metadatos sobre bloques a partir del desplazamiento especificado. El parámetro "count" es una pista: el servidor puede optar por devolver menos estado, o el bloque final puede extenderse más allá del rango solicitado. Cuando se soportan múltiples contextos, el número de bloques y la longitud acumulada de esos bloques no necesitan ser idénticos entre contextos; este comando generalmente devuelve el estado de todos los contextos negociados, mientras que algunos servidores también soportan una solicitud filtrada (ver nbd_can_block_status_payload(3), nbd_block_status_filter(3)).

Tenga en cuenta que no todos los servidores soportan un "count" de 4GiB o mayor; nbd_get_extended_headers_negotiated(3) indica qué servidores analizarán una solicitud mayor a 32 bits. El protocolo NBD aún no tiene una forma para que un cliente sepa si el servidor aplicará un tamaño máximo de estado de bloque aún menor, aunque una futura extensión puede agregar una restricción visible en nbd_get_block_size(3).

Dependiendo de qué contextos de metadatos se habilitaron antes de conectar (ver nbd_add_meta_context(3)) y cuáles son soportados por el servidor (ver nbd_can_meta_context(3)), esta llamada devuelve información sobre extensiones llamando a la función "extent64". El callback no puede llamar a las APIs "nbd_*" en el mismo manejador ya que este mantiene el bloqueo del manejador y causará un interbloqueo. Si el callback devuelve -1, y no se ha detectado ningún error anterior, entonces el comando general de estado de bloque fallará con cualquier valor distinto de cero almacenado en el parámetro "error" del callback (con un valor por defecto de "EPROTO"); pero los contextos adicionales seguirán invocando el callback.

La función "extent64" se llama una vez por tipo de metadatos disponibles, con el "user_data" pasado a esta función. El parámetro "metacontext" es una cadena como "base:allocation". El array "entries" es un array de estructuras nbd_extent, que contiene la longitud (en bytes) del bloque y un campo de estado/flags que es específico del contexto de metadatos. El número de entradas del array pasadas a la función es "nr_entries". El documento del protocolo NBD en la sección sobre "NBD_REPLY_TYPE_BLOCK_STATUS" describe el significado de este array; para contextos conocidos por libnbd, <libnbd.h> contiene constantes que comienzan con "LIBNBD_STATE_" que pueden ayudar a descifrar los valores. Al entrar en el callback, el parámetro "error" contiene el valor errno de cualquier error detectado previamente.

Es posible que la función de extensión se llame más veces de las que espera (si el servidor tiene errores), así que siempre verifique el campo "metacontext" para asegurarse de que está recibiendo los datos que espera. También es posible que la función de extensión no se llame en absoluto, incluso para contextos de metadatos que haya solicitado. Esto indica que el servidor no soporta el contexto o por alguna otra razón no puede devolver los datos.

El parámetro "flags" puede ser 0 para ninguna bandera, o puede contener "LIBNBD_CMD_FLAG_REQ_ONE" que significa que el servidor debe devolver solo una extensión por contexto de metadatos donde esa extensión no exceda "count" bytes; sin embargo, libnbd no valida que el servidor haya obedecido la bandera.

Por defecto, libnbd rechazará los intentos de usar esta función con parámetros que probablemente resulten en un fallo del servidor, como solicitar una bandera de comando desconocida. La función nbd_set_strict_mode(3) puede ser utilizada para alterar qué escenarios deben esperar una respuesta del servidor en lugar de fallar rápidamente.

VALOR DE RETORNO

Si la llamada es exitosa, la función devuelve 0.

ERRORES

En caso de error, se devuelve -1.

Consulte "MANEJO DE ERRORES" en libnbd(3) para saber cómo obtener más detalles del error.

Los siguientes parámetros no deben ser NULL: "h". Para más información vea "Parámetros no nulos" en libnbd(3).

ESTADO DEL MANEJADOR

nbd_block_status_64 puede ser llamado cuando el manejador está en el siguiente estado:

┌─────────────────────────────────────┬─────────────────────────┐
│ Manejador creado, antes de conectar │ ❌ error                │
│ Conectando                          │ ❌ error                │
│ Conectando y handshake (opt_mode) │ ❌ error                │
│ Conectado al servidor             │ ✅ permitido              │
│ Conexión cerrada                   │ ❌ error                │
│ Manejador muerto                    │ ❌ error                │
└─────────────────────────────────────┴─────────────────────────┘

VERSIÓN

Esta función apareció por primera vez en libnbd 1.18.

Si necesita probar si esta función está disponible en tiempo de compilación, compruebe si la siguiente macro está definida:

#define LIBNBD_HAVE_NBD_BLOCK_STATUS_64 1
