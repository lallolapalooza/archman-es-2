NOMBRE

nbd-server - servir un archivo como dispositivo de bloques a otros ordenadores que ejecuten el sistema operativo GNU/Linux(tm) o GNU/Hurd

SINOPSIS

nbd-server [ip@]puerto nombre_archivo [ tamaño ] [ -r ] [ -m ] [ -c ] [ -l nombre_archivo_lista_hosts ] [ -o nombre_seccion ] [ -C archivo_config ] [ -M max_conexiones ] [ -V ] [ -n ] [ -d ]

DESCRIPCIÓN

nbd-server es el servidor para el Dispositivo de Bloques de Red (NBD) de Linux. Con NBD, un cliente puede usar un archivo, exportado a través de la red desde un servidor, como un dispositivo de bloques. Luego puede ser utilizado para cualquier propósito que pueda usarse un dispositivo de bloques normal (disco duro, CD-ROM, ...).

NBD puede ser útil para clientes sin disco que necesiten espacio de intercambio (swap), pero también puedes crear un sistema de archivos en él y utilizarlo como si fuera un sistema de archivos local.

nbd-server implementa cierta seguridad a través de un archivo llamado "/etc/nbd-server/allow" (por defecto; se puede elegir un archivo diferente con la opción '-l' o a través de una especificación en el archivo de configuración). Este archivo debe listar las direcciones IP o las máscaras de red de los clientes que tienen permiso para conectarse. Si no existe, todos los clientes pueden conectarse. Si el archivo está vacío, ningún cliente puede conectarse.

Ten en cuenta que, si bien la línea de comandos permite especificar una exportación, el uso de esta opción está obsoleto. Se prefiere utilizar un archivo de configuración en su lugar, cuyo formato se define en nbd-server(5).

Mientras nbd-server está en ejecución, se pueden añadir nuevas exportaciones reescribiendo los archivos de configuración y luego enviando SIGHUP a nbd-server. SIGHUP hace que nbd-server vuelva a leer sus archivos de configuración y comience a servir todas las nuevas exportaciones que no se servían antes. La reconfiguración no modifica ninguna exportación existente, solo añade nuevas.

OPCIONES

ip
La dirección IP en la que el servidor debe escuchar. Puede ser una dirección IPv4, una dirección IPv6 o un nombre de host. En este último caso, nbd-server realizará una búsqueda del nombre especificado y escuchará en la primera dirección devuelta. Para compatibilidad con versiones anteriores de nbd-server, si se especifica una dirección IPv4, el signo @ que sirve de separador entre la dirección y el puerto puede ser reemplazado por dos puntos.
Si este parámetro no se especifica, nbd-server escuchará en todas las direcciones locales tanto IPv4 como IPv6. Para limitarlo a IPv4, especifica la dirección como 0.0.0.0; para limitarlo a IPv6, especifica como ::.
puerto
El puerto en el que el servidor debe escuchar. Un puerto válido es cualquier número entre 1 y 65536; si se usa 0, nbd-server escuchará en stdin (para que nbd-server pueda ser ejecutado desde inetd)
nombre_archivo
El nombre del archivo que debe ser exportado. Puede ser cualquier archivo, incluyendo dispositivos de bloques "reales" (es decir, un archivo de /dev). Si el nombre del archivo incluye la cadena literal "%s", entonces este %s será sustituido con la dirección IP del cliente que intenta conectarse.
tamaño
El tamaño del dispositivo de bloques en el lado del cliente. Esto es especialmente útil en combinación con la opción -m.

Opcionalmente, puede ir seguido de una de K, k, M o m, en cuyo caso el tamaño se multiplicará por 1024 (K o k) o 1048576 (M o m)

-r
Exportar el archivo en modo de solo lectura. Si un cliente intenta escribir en un archivo exportado de solo lectura, recibirá un error, pero la conexión permanecerá activa.
-m
Trabajar con múltiples archivos. Esto puede usarse para exportar dispositivos de bloques que son más grandes que el tamaño de archivo máximo permitido en un sistema de archivos dado; es decir, cuando el sistema de archivos no permite archivos de más de 2 GB (lo cual es cierto para Linux 2.2 y anteriores), puedes usar esta opción para almacenar los datos en múltiples archivos y exportar un sistema de archivos más grande, si es necesario.

Para usar esta opción, debes crear un número de archivos con nombres en el formato "nombre.X", donde "nombre" se proporciona como argumento de nombre de archivo a nbd-server, y "X" es un número que comienza en 0 y aumenta para cada archivo.

Se planea permitir más flexibilidad para esta opción en versiones futuras.

-c
Copiar al escribir (Copy on Write). Cuando se proporciona esta opción, las operaciones de escritura no se realizan en el archivo exportado, sino en un archivo separado. Este archivo separado se elimina cuando se cierra la conexión, lo que significa que servir de esta manera ralentizará nbd-server (especialmente en dispositivos de bloques grandes con muchas escrituras), y que después de desconectar y reconectar el cliente o el servidor, todos los cambios se perderán.
-C
Especificar archivo de configuración. El archivo de configuración por defecto, si este parámetro no se especifica, es /etc/nbd-server/config.

Ten en cuenta que el archivo de configuración siempre se analiza y se utilizan las entradas del archivo, incluso si se especifica un servidor adicional en la línea de comandos. Para deshabilitar el archivo de configuración por completo, muévelo o usa la opción -C para apuntar a nbd-server(1) a un archivo de configuración inexistente o vacío.

También ten en cuenta que si se especifica un archivo de configuración vacío, incompleto o inválido, nbd-server mostrará una advertencia sobre el fallo al analizar el archivo de configuración. Si la línea de comandos contiene una configuración completa, esta advertencia es inofensiva y puede ser ignorada.

-M
Especificar el número máximo de conexiones abiertas. Si este parámetro no se especifica, no se establece ningún límite.
-V
Mostrar la versión de nbd-server y salir.
-n
No demonizar el proceso principal. A diferencia de -d, esto todavía permite bifurcar el proceso de servicio para un cliente desde el proceso principal.
-d
No bifurcar. Útil para depuración. Implica -n.
nombre_archivo_lista_hosts
Este argumento debe contener una lista de direcciones IP de hosts que pueden conectarse al servidor. Los comodines **no** están permitidos. Si el archivo no existe, se ignora (y cualquier host puede conectarse); si el archivo existe pero está vacío, ningún host puede conectarse. Por defecto, se usa el nombre 'nbd_server.allow', y se busca en el directorio actual, a menos que nbd-server se compile como un demonio, en cuyo caso se busca en el directorio raíz.
nombre_seccion
Si se da el argumento -o en la línea de comandos, entonces nbd-server generará una sección de archivo de configuración con este nombre como encabezado que es funcionalmente equivalente a las otras opciones especificadas en la línea de comandos, y saldrá. Esto es útil para migrar archivos de configuración de scripts de inicio de nbd-server anteriores a la versión 2.9 al nuevo formato.

EJEMPLOS

Algunos ejemplos de uso de nbd-server:

•
Para exportar el archivo /export/nbd/exp-bl-dev en el puerto 2000:

nbd-server 2000 /export/nbd/exp-bl-dev

•
Para exportar el mismo archivo en modo de solo lectura:

nbd-server 2000 /export/nbd/exp-bl-dev -r

•
Para exportar el mismo archivo en modo de lectura/escritura, pero asegurando que los cambios se pierdan después de reiniciar el cliente o el servidor:

nbd-server 2000 /export/nbd/exp-bl-dev -c
