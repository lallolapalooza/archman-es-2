nbd_aio_get_direction(3) LIBNBD nbd_aio_get_direction(3)

NOMBRE

nbd_aio_get_direction - devuelve la dirección de lectura o escritura

SINOPSIS

#include <libnbd.h>
unsigned nbd_aio_get_direction (
           struct nbd_handle *h
         );

DESCRIPCIÓN

Devuelve la dirección actual de esta conexión, lo que significa si esperamos a continuación leer datos del servidor, escribir datos al servidor, o ambos. Devuelve

0
No se espera que interactuemos con el descriptor de archivo del servidor desde el estado actual. No vale la pena intentar usar poll(2); si la conexión no está muerta, entonces el progreso de la máquina de estados debe provenir de algún otro medio, como nbd_aio_connect(3).
"LIBNBD_AIO_DIRECTION_READ" = 1
Se espera a continuación leer del servidor. Si se utiliza poll(2), establecería "events = POLLIN". Si "revents" devuelve "POLLIN" o "POLLHUP", entonces se llamaría a nbd_aio_notify_read(3).

Tenga en cuenta que una vez que libnbd alcanza nbd_aio_is_ready(3), esta dirección se devuelve incluso cuando no hay comandos en curso (ver nbd_aio_in_flight(3)). En un uso de un solo hilo de libnbd, no vale la pena hacer polling hasta después de emitir un comando, ya que de lo contrario el servidor nunca activará el polling. En un escenario multihilo, puede tener un hilo iniciando un bucle de polling antes de cualquier comando, pero cualquier otro hilo que emita un comando necesitará una forma de sacar al hilo de polling del polling en caso de que la emisión del comando cambie la dirección de polling necesaria. Las formas posibles de hacerlo incluyen hacer polling de actividad en una tubería a sí mismo, o usar pthread_kill(3) para enviar una señal que se enmascara excepto durante ppoll(2).

"LIBNBD_AIO_DIRECTION_WRITE" = 2
Se espera a continuación escribir al servidor. Si se utiliza poll(2), establecería "events = POLLOUT". Si "revents" devuelve "POLLOUT", entonces se llamaría a nbd_aio_notify_write(3).
"LIBNBD_AIO_DIRECTION_BOTH" = 3
Se espera a continuación leer o escribir al servidor. Si se utiliza poll(2), establecería "events = POLLIN|POLLOUT". Si solo se devuelve uno de "POLLIN" o "POLLOUT", vea lo anterior. Sin embargo, si se devuelven ambos, es mejor llamar solo a nbd_aio_notify_read(3), ya que procesar la respuesta del servidor puede cambiar el estado de la conexión e invalidar la necesidad de escribir más comandos.

VALOR DE RETORNO

Esta llamada devuelve una máscara de bits.

ERRORES

Esta función no falla.

Los siguientes parámetros no deben ser NULL: "h". Para más información, consulte "Parámetros no nulos" en libnbd(3).

VERSIÓN

Esta función apareció por primera vez en libnbd 1.0.

Si necesita probar si esta función está disponible en tiempo de compilación, verifique si el siguiente macro está definido:

#define LIBNBD_HAVE_NBD_AIO_GET_DIRECTION 1
