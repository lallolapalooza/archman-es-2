NOMBRE

notmuch-new - incorporar correo nuevo a la base de datos de notmuch

SINOPSIS

notmuch new [opciones]

DESCRIPCIÓN

Busca e importa cualquier mensaje nuevo a la base de datos.

El comando new escanea todos los subdirectorios de la base de datos, realizando indexación de texto completo en los mensajes nuevos que se encuentran. Cada mensaje nuevo se etiquetará automáticamente con las etiquetas inbox (bandeja de entrada) y unread (no leído).

Deberías ejecutar notmuch new una vez después de ejecutar notmuch por primera vez para crear la base de datos inicial. La primera ejecución puede tardar mucho si tienes una cantidad significativa de correo (varios cientos de miles de mensajes o más). Posteriormente, deberías ejecutar notmuch new cada vez que se entregue correo nuevo y desees incorporarlo a la base de datos. Estas ejecuciones posteriores serán mucho más rápidas que la ejecución inicial.

Invocar notmuch sin ningún argumento de comando ejecutará new si notmuch se ha completado previamente, pero notmuch new no se ha ejecutado antes.

notmuch new actualiza las etiquetas según los cambios de bandera de maildir si la opción de configuración maildir.synchronize_flags está habilitada. Ver notmuch-config para más detalles.

El comando new soporta ganchos (hooks). Ver notmuch-hooks para más detalles sobre ganchos.

Las opciones soportadas para new incluyen

--no-hooks
Evita que se ejecuten los ganchos.
--quiet
No imprima el progreso ni los resultados.
--verbose
Imprime los nombres de los archivos que se están procesando. Se ignora cuando se combina con --quiet.
--decrypt=(true|nostash|auto|false)
Si es true, al encontrar un mensaje cifrado, intenta descifrarlo durante la indexación y almacena temporalmente cualquier clave de sesión descubierta. Si es auto, intenta usar cualquier clave de sesión que ya se sepa que pertenece a este mensaje, pero no intentes usar las claves secretas del usuario. Si el descifrado es exitoso, indexa el texto plano del mensaje.

Ten en cuenta que el índice es probablemente suficiente (y la clave de sesión es ciertamente suficiente) para reconstruir el texto plano del mensaje en sí, ¡así que asegúrate de que el índice de mensajes de notmuch esté adecuadamente protegido! NO USES --decrypt=true o --decrypt=nostash sin considerar la seguridad de tu índice.

Ver también index.decrypt en notmuch-config.

--full-scan
Por defecto, notmuch-new utiliza los tiempos de modificación de los directorios (mtimes) para optimizar el escaneo de directorios en busca de correo nuevo. Esta opción desactiva esa optimización.

CONFIGURACIÓN

La indexación se ve influenciada por las opciones de configuración index.decrypt, index.header.<prefix> y new.ignore. El etiquetado se controla mediante new.tags y maildir.synchronize_flags. Ver notmuch-config para detalles.

ESTADO DE SALIDA

Este comando soporta el siguiente código de estado de salida especial

75 (EX_TEMPFAIL)
Ocurrió un fallo temporal; se invita al usuario a intentarlo de nuevo.
