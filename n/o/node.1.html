NOMBRE

node — entorno de ejecución de JavaScript del lado del servidor

SINOPSIS

node [opciones] [opciones-de-v8] [-e cadena | script.js | -] [--] [argumentos ...]

node inspect [-e cadena | script.js | - | <host>:<puerto>] ...

node [--v8-options]

DESCRIPCIÓN

Node.js es un conjunto de bibliotecas para JavaScript que permite utilizarlo fuera del navegador. Se centra principalmente en la creación de clientes y servidores de red sencillos y fáciles de construir.

Ejecute node sin argumentos para iniciar un REPL.

OPCIONES

-
Alias para stdin, análogo al uso de - en otras utilidades de línea de comandos. El script a ejecutar se lee desde stdin, y los argumentos restantes se pasan al script.
--
Indica el final de las opciones de la línea de comandos. Pasa el resto de los argumentos al script.

Si no se proporciona ningún nombre de archivo de script o un script de evaluación/impresión antes de esto, el siguiente argumento se utilizará como nombre de archivo de script.

--v8-options
Imprimir opciones de línea de comandos de V8.
--v8-pool-size=num
Establecer el tamaño del grupo de hilos de V8 que se utilizará para asignar trabajos en segundo plano. Si se establece en 0, V8 elegirá un tamaño apropiado para el grupo de hilos basándose en el número de procesadores en línea. Si el valor proporcionado es mayor que el máximo de V8, se elegirá el valor más grande.
--watch
Inicia Node.js en modo de observación. Cuando está en modo de observación, los cambios en los archivos observados hacen que el proceso de Node.js se reinicie.

Por defecto, el modo de observación observará el punto de entrada y cualquier módulo requerido o importado. Usa --watch-path para especificar qué rutas observar.

--watch-path
Inicia Node.js en modo de observación y especifica qué rutas observar. Cuando está en modo de observación, los cambios en las rutas observadas hacen que el proceso de Node.js se reinicie.

Esto deshabilitará la observación de módulos requeridos o importados, incluso cuando se use en combinación con --watch.

--watch-kill-signal
Personaliza la señal enviada al proceso en reinicios en modo de observación.
--zero-fill-buffers
Llena automáticamente con ceros todas las instancias de Buffer recién asignadas.
-c, --check
Verifica la sintaxis del script sin ejecutarlo. Sale con un código de error si el script es inválido.
-e, --eval string
Evalúa string como JavaScript.
-h, --help
Imprime las opciones de la línea de comandos. La salida de esta opción es menos detallada que este documento.
-i, --interactive
Abre el REPL incluso si la entrada estándar no parece ser una terminal.
-p, --print string
Idéntico a -e, pero imprime el resultado.
-r, --require module
Precarga el module especificado al inicio. Sigue las reglas de resolución de módulos de `require()`. module puede ser una ruta a un archivo o un nombre de módulo de Node.js.
-v, --version
Imprime la versión de node.

ENTORNO

FORCE_COLOR
Se utiliza para habilitar la salida con color ANSI. El valor puede ser uno de: 1, true, o una cadena vacía para indicar soporte de 16 colores, 2 para indicar soporte de 256 colores, o 3 para indicar soporte de 16 millones de colores. Cuando se usa y se establece en un valor compatible, tanto las variables de entorno NO_COLOR como NODE_DISABLE_COLORS se ignoran. DESCRIPCIÓN

Node.js es una plataforma de ejecución de JavaScript del lado del servidor construida sobre el motor V8 de Chrome. Node.js permite a los desarrolladores crear aplicaciones escalables del lado del servidor con JavaScript.

El binario node puede ser utilizado de varias maneras:

  • Ejecutar un archivo JavaScript: node mi_archivo.js
  • Ejecutar JavaScript desde la entrada estándar: cat mi_archivo.js | node
  • Ejecutar un fragmento de código JavaScript directamente: node -e "console.log('Hola Mundo');"
  • Evaluar una expresión JavaScript y mostrar su valor: node -p "process.platform"
  • Ejecutar un script con opciones de V8: node --v8-options

Si se invoca sin argumentos, node entrará en el intérprete interactivo de la consola.

Las opciones que comienzan con un guion (`-`) son opciones de línea de comandos de Node.js. Las opciones que comienzan con dos guiones (`--`) son opciones del motor V8. Las opciones de V8 pueden cambiar con el tiempo; use node --v8-options para ver la lista actual.

AMBIENTE

NODE_ACCEPT_UNCAUGHT_EXCEPTION
Si está configurada, las excepciones no capturadas se aceptarán en lugar de hacer que el proceso Node.js falle. Esto solo afecta a las solicitudes enviadas a través de fetch(). El soporte para otros métodos incorporados de http y https está en curso.
NODE_EXTRA_CA_CERTS file
Permite especificar un archivo de certificados de Autoridad de Certificación (CA) adicional para usarlo al validar conexiones SSL/TLS. Los certificados en este archivo se agregarán a los certificados de CA de confianza preexistentes.

Si se especifica la opción --use-openssl-ca, este archivo será ignorado.

NODE_NO_WARNINGS
Si está configurada, suprime la emisión de todas las advertencias.
NODE_OPTIONS
Se utiliza para pasar opciones al tiempo de ejecución de Node.js. Las opciones se analizan de la misma manera que los argumentos de la línea de comandos. Si se especifica la opción --node-options en la línea de comandos, esta variable de entorno será ignorada.
NODE_PEDANTIC_REQUIRE ，
Si está configurada, require() lanzará un ERR_REQUIRE_ESM si se intenta cargar un módulo ESM con require().
NODE_PRESERVE_SYMLINKS
Si está configurada, los enlaces simbólicos no se resolverán al obtener acceso a los módulos cargados. Esto es similar a pasar la opción de línea de comandos --preserve-symlinks.
NODE_REDIRECT_WARNINGS file
Redirige todas las advertencias a file. Similar a la opción --redirect-warnings.
NODE_TLS_MAX_VERSION
Establece la versión máxima de TLS que utilizará Node.js. Los valores posibles son `TLSv1.0`, `TLSv1.1`, `TLSv1.2`, y `TLSv1.3`.
NODE_TLS_MIN_VERSION
Establece la versión mínima de TLS que utilizará Node.js. Los valores posibles son `TLSv1.0`, `TLSv1.1`, `TLSv1.2`, y `TLSv1.3`.
NODE_USE_SYSTEM_CA
Similar a --use-system-ca. Usa los certificados CA de confianza presentes en el almacén del sistema, además de los certificados en el almacén CA de Mozilla incluido y los certificados de NODE_EXTRA_CA_CERTS.
NODE_V8_COVERAGE dir
Cuando está configurada, Node.js escribe información de cobertura de código JavaScript en dir.
OPENSSL_CONF file
Carga un archivo de configuración de OpenSSL al inicio. Entre otros usos, esto puede usarse para habilitar criptografía compatible con FIPS si Node.js se compila con ./configure --openssl-fips.

Si se utiliza la opción de línea de comandos --openssl-config, esta variable de entorno se ignora.

SSL_CERT_DIR dir
Si --use-openssl-ca está habilitado, esto anula y establece el directorio de OpenSSL que contiene los certificados de confianza.
SSL_CERT_FILE file
Si --use-openssl-ca está habilitado, esto anula y establece el archivo de OpenSSL que contiene los certificados de confianza.
TZ
Especifica la configuración de zona horaria.
UV_THREADPOOL_SIZE size
Establece el número de hilos utilizados en el pool de hilos de libuv a size.
