DESCRIPTION

Ncplanes are the fundamental drawing object of Notcurses. All output functions take a struct ncplane as an argument. They can be any size, and placed anywhere. In addition to its framebuffer--a rectilinear matrix of nccells (see notcurses_cell(3))--an ncplane is defined by:

•
a base nccell, used for any cell on the plane without a glyph,
•
the egcpool backing its nccells,
•
a current cursor location,
•
a current style, foreground channel, and background channel,
•
its geometry,
•
a configured user pointer,
•
position relative to the standard plane,
•
the plane, if any, to which it is bound,
•
the next plane bound by the plane to which it is bound,
•
the head of the list of its bound planes,
•
its resize methodology,
•
whether a sprixel (see notcurses_visual(3)) is associated,
•
its z-index, and
•
a name (used only for debugging).

New planes can be created with ncplane_create. If a plane is bound to another, x and y coordinates are relative to the plane to which it is bound, and if this latter plane moves, all its bound planes move along with it. When a plane is destroyed, all planes bound to it (directly or transitively) are destroyed.

If the NCPLANE_OPTION_HORALIGNED flag is provided, x is interpreted as an ncalign_e rather than an absolute position. If the NCPLANE_OPTION_VERALIGNED flag is provided, y is interpreted as an ncalign_e rather than an absolute postiion. Either way, all positions are relative to the parent plane. ncplane_resize_realign should usually be used together with these flags, so that the plane is automatically realigned upon a resize of its parent.

If the NCPLANE_OPTION_MARGINALIZED flag is provided, neither NCPLANE_OPTION_HORALIGNED nor NCPLANE_OPTION_VERALIGNED may be provided, and rows and cols must both be 0. y and x will be interpreted as top and left margins. margin_b and margin_r will be interpreted as bottom and right margins. The plane will take the maximum space possible subject to its parent planes and these margins. The plane cannot become smaller than 1x1 (the margins are best-effort). ncplane_resize_marginalized should usually be used together with this flag, so that the plane is automatically resized.

ncplane_reparent detaches the plane n from any plane to which it is bound, and binds it to newparent. Its children are reparented to its previous parent. The standard plane cannot be reparented. If newparent is NULL, the plane becomes the root plane of a new, unrendered stack. When ncplane_reparent_family is used, all planes bound to n move along with it during a reparenting operation. See Piles below.

ncplane_destroy destroys a particular ncplane, after which it must not be used again. notcurses_drop_planes destroys all ncplanes other than the stdplane. Any references to such planes are, of course, invalidated. It is undefined to destroy a plane concurrently with any other operation involving that plane, or any operation involving the z-axis.

It is an error for two threads to concurrently mutate a single ncplane. So long as rendering is not taking place, however, multiple threads may safely output to multiple ncplanes. So long as all threads are readers, multiple threads may work with a single ncplane. A reading function is any which accepts a const struct ncplane.

A plane can be moved relative to its parent plane's origin with ncplane_move_yx. If the plane has no parent, the move is relative to the rendering area. A plane can be moved off-screen entirely, in which case it will not be visible following rasterization; it can also be partially off-screen.

A plane has a virtual cursor; set its new position with ncplane_cursor_move_yx. Specifying -1 as one or both coordinates will hold that axis constant. You may move a cursor relatively to its current position with ncplane_cursor_move_rel. Unless coordinates are specified for a call, action takes place at the plane's virtual cursor, which automatically moves along with output. The current virtual cursor location can be acquired with ncplane_cursor_yx.

ncplane_yx returns the coordinates of the specified plane's origin, relative to the plane to which it is bound. Either or both of y and x may be NULL. ncplane_y and ncplane_x allow a single component of this coordinate pair to be obtained.

ncplane_abs_yx devuelve las coordenadas del origen del plano especificado en relación con su pila.

ncplane_translate traduce las coordenadas expresadas en relación con el plano src, y escribe las coordenadas de esa celda en relación con dst. La celda no necesita intersecar con dst, aunque esto producirá coordenadas que no son válidas para escribir o leer en dst. Si dst es NULL, se toma para referirse al plano estándar. ncplane_translate_abs toma coordenadas expresadas en relación con el plano estándar y devuelve coordenadas en relación con dst, devolviendo false si las coordenadas no son válidas para dst.

ncplane_mergedown escribe en dst el fotograma que se renderizaría si solo src y dst existieran en el eje z, y dst representara la totalidad de la región de renderizado. Solo las celdas donde src se cruza con dst podrían experimentar cambios. Es un error fusionar un plano sobre sí mismo.

ncplane_erase pone a cero todas las celdas del plano, vuelca el egcpool y mueve el cursor al inicio. La celda base se conserva, al igual que los atributos activos. ncplane_erase_region hace lo mismo para una subregión del plano. Para esta última, proporcione 0 para ylen y/o xlen para borrar a través de esa dimensión, comenzando en el punto especificado. Proporcione -1 para ystart y/o xstart para usar la posición actual del cursor a lo largo de ese eje como punto de partida. Valores negativos de ylen y xlen mueven hacia arriba y hacia la izquierda desde la coordenada de inicio; valores positivos de ylen y xlen mueven hacia abajo y hacia la derecha desde el mismo punto. Consulte BUGS a continuación.

Cuando se redimensiona un plano (ya sea por ncplane_resize, SIGWINCH o cualquier otro mecanismo), se realiza una recursión en profundidad sobre sus hijos. Cada plano hijo que tenga un resizecb no NULL verá que su callback se invoca después de redimensionar el plano de su padre. Si devuelve un valor distinto de cero, la cascada de redimensionamiento termina, devolviendo un valor distinto de cero. De lo contrario, el redimensionamiento procede recursivamente.

ncplane_move_top y ncplane_move_bottom extraen su argumento n del eje z, y lo reinsertan en la parte superior o inferior, respectivamente, de su pila. Ambas funciones son O(1). ncplane_move_family_top y ncplane_move_family_bottom hacen lo mismo, y mueven a todos los descendientes vinculados junto con el plano. Se mantendrá el orden entre el plano y sus descendientes. Por ejemplo, suponga una pila con A en la parte superior de su eje z, seguido por B, C, D y E, donde E está vinculado a C. Llamar a ncplane_move_family_top en C dará como resultado el orden CEABD. Llamar a ncplane_move_family_bottom en C dará como resultado el orden ABDCE. Llamar a ncplane_move_family_top o ncplane_move_top en E dará como resultado EABCD. Llamar a ncplane_move_family_bottom en E no tiene ningún efecto. Estas dos funciones son O(N) en el número de planos en la pila.

ncplane_move_above y ncplane_move_below mueven el argumento n por encima o por debajo, respectivamente, del argumento targ. Ambas operan en O(1).

ncplane_at_yx y ncplane_at_yx_cell recuperan el contenido del plano en la coordenada especificada. El contenido se devuelve tal como se utilizará durante la renderización, e integra cualquier celda base según corresponda. Si se llama en las columnas secundarias de un glifo ancho, ncplane_at_yx devuelve el EGC, y por lo tanto no se puede utilizar para distinguir entre columnas primarias y secundarias. ncplane_at_yx_cell, sin embargo, conserva esta información: recuperar una columna secundaria de un glifo ancho con ncplane_at_yx_cell rellenará el argumento nccell de tal manera que nccell_extended_gcluster(3) devuelva una cadena vacía, y nccell_wide_right_p(3) devuelva true.

Si se invoca ncplane_at_yx en un plano de sprixel, se devolverá la secuencia de control para cualquier coordenada válida (tenga en cuenta que esta puede ser bastante grande). Esto no se aplica a ncplane_at_yx_cell, que devolverá un error.

ncplane_set_name establece el nombre del plano, liberando cualquier nombre anterior. name puede ser NULL. ncplane_set_name duplica internamente el nombre proporcionado.

Celda base

Cada plano tiene una celda base, inicializada a ceros. Al renderizar, las celdas del plano se examinan por turnos. Cada celda tiene tres elementos de renderización independientes: su EGC, su canal de primer plano y su canal de fondo. Cualquier canal predeterminado se reemplaza con el canal correspondiente de la celda base de ese plano. ncplane_erase no tiene efecto en la celda base. Llamar a ncplane_erase en un plano cuya celda base es una 'A' morada da como resultado (a efectos de renderización) un plano compuesto enteramente por 'A's moradas.

ncplane_set_base_cell utiliza la nccell c (que debe estar vinculada al ncplane ncp, y debe ser la primera nccell de una secuencia multicolumna) para establecer la celda base. ncplane_set_base hace lo mismo con egc, stylemask y channels.

Pilas

Un único contexto de Notcurses se compone de una o más pilas. Una pila es un conjunto de uno o más ncplanes, incluyendo los ordenamientos parciales formados por sus punteros de enlace y eje z. Una pila tiene un ncplane superior e inferior (podría ser un solo plano), y uno o más planos raíz (planos que están enlazados a sí mismos). Múltiples hilos pueden operar concurrentemente en pilas distintas, incluso modificando una mientras se renderiza otra.

Cada plano pertenece a una y solo una pila. Por defecto, un plano forma parte de la misma pila que contiene el plano al que está enlazado. Si se utiliza ncpile_create en lugar de ncplane_create, el plano devuelto se convierte en el plano raíz, superior e inferior de una nueva pila. Como plano raíz, está enlazado a sí mismo. También se puede crear una nueva pila re-parentando un plano a sí mismo, aunque si el plano ya es un plano raíz, esto no tiene ningún efecto.

Cuando un plano se mueve a una pila diferente (nueva o preexistente), cualquier plano que estuviera enlazado a él se re-enlazará a su padre anterior. Si el plano era el plano raíz de alguna pila, cualquier plano enlazado se convierte en plano raíz. El nuevo plano se coloca inmediatamente encima de su nuevo padre en el eje z de su nueva pila. Cuando se utiliza ncplane_reparent_family, todos los planos enlazados al plano re-parentado se mueven junto con él. Se mantiene su orden z relativo.

Hay más información disponible en notcurses_pile(3).

Enlace

Los planos de una pila forman un bosque dirigido acíclico. Los planos enlazados a sí mismos forman los planos raíz de la pila. Cada plano es un plano raíz, o está enlazado a otro plano en su pila. Un plano y sus descendientes forman una familia. Cuando un plano se mueve usando ncplane_move_yx, su familia se mueve junto con él.

Desplazamiento

Todos los planos, incluido el plano estándar, se crean con el desplazamiento desactivado. Controle el desplazamiento por plano con ncplane_set_scrolling. Intentar imprimir más allá del final de una línea se detendrá en el límite del plano e indicará un error. En un plano de 10 columnas de ancho y dos filas de alto, imprimir "0123456789" en el origen debería tener éxito, pero imprimir "01234567890" fallará por defecto en el undécimo carácter. En cualquier caso, el cursor quedará en la ubicación 0x10; debe moverse antes de que se pueda realizar más impresión. Si el desplazamiento está habilitado, la primera fila se llenará con 0123456789, la segunda fila tendrá un 0 escrito en su primera columna y el cursor terminará en 1x1. Tenga en cuenta que sigue siendo un error intentar mover manualmente el cursor fuera del plano o especificar una salida fuera del plano. El dibujo de bordes no genera desplazamiento; intentar dibujar una caja de 2x11 en nuestro plano de 2x10 resultará en un error y ninguna salida. Cuando el desplazamiento está habilitado y se produce una salida mientras el cursor está más allá del final de la última fila, se descarta la primera fila, se mueven todas las demás filas hacia arriba, se borra la última fila y la salida comienza al principio de la última fila. Esto no ocurre hasta que se genera la salida (es decir, es posible llenar un plano cuando el desplazamiento está habilitado).

Crear un plano con el flag NCPLANE_OPTION_VSCROLL es equivalente a llamar inmediatamente a ncplane_set_scrolling en ese plano con un argumento de true.

Por defecto, los planos enlazados a un plano con desplazamiento se desplazarán junto con él, si se cruzan con el plano. Esto se puede deshabilitar creándolos con el flag NCPLANE_OPTION_FIXED.

Autocrecimiento

Normalmente, una vez que la salida llega al límite derecho de un plano, es imposible colocar más salida a menos que primero se mueva el cursor. Si el desplazamiento está habilitado, el cursor se moverá automáticamente hacia abajo y hacia la izquierda en este caso, pero al llegar a la esquina inferior derecha del plano, es imposible colocar más salida sin un evento de desplazamiento. Si el autocrecimiento está activo, el plano se ampliará automáticamente para acomodar la salida. Si el desplazamiento está desactivado, el crecimiento se produce hacia la derecha; de lo contrario, se produce en la parte inferior. El plano solo crece en una dimensión. El autocrecimiento no se puede habilitar para el plano estándar.

Crear un plano con el flag NCPLANE_OPTION_AUTOGROW es equivalente a llamar inmediatamente a ncplane_set_autogrow en ese plano con un argumento de true.

Mapas de bits

ncplane_pixel_geom recupera detalles de geometría de píxeles. pxy y pxx devuelven el tamaño del plano en píxeles. celldimy y celldimx devuelven el tamaño de una celda en píxeles (estos deberían ser iguales en todos los planos). maxbmapy y maxbmapx describen el mapa de bits más grande que se puede mostrar en el plano. Cualquier parámetro (excepto n) puede ser NULL.

Cuando se hace un blit a un plano usando ncvisual_blit y NCBLIT_PIXEL (ver ncp is a direct child of the standard plane). If ncp is NULL, the standard plane is moved.

ncplane_resize resizes a plane. It takes the plane ncp, the new dimensions (height, width), and the new starting coordinates (y, x). The coordinates are relative to the plane's parent. If ncp is NULL, the standard plane is resized.

ncplane_translate translates a plane ncp by the given delta (dy, dx). This is equivalent to ncplane_move, but uses relative coordinates.

ncplane_translate_abs translates a plane ncp to the given absolute coordinates (y, x). These coordinates are relative to the plane's parent. This is equivalent to ncplane_move.

ncplane_base returns the dimensions and location of the base cell of the plane ncp. The base cell is the cell at (y, x) within the plane's coordinate system. The provided ncell will be populated with the relevant attributes.

ncplane_set_base sets the base cell of the plane ncp. All subsequent output will be offset by the dimensions of this base cell. This is useful for creating windows with borders. The dims argument is a pointer to an ncdims structure. If dims is NULL, the dimensions of the plane are reset to default.

ncplane_rasterize converts the entire contents of the plane ncp to a sprixel. This operation is irreversible. A sprixel is a block of pixels. The sprixel is then blitted to the standard plane, overwriting any previous contents.

ncplane_set_userptr associates an arbitrary pointer with the plane ncp. This pointer is returned by ncplane_userptr. It is the responsibility of the caller to manage the memory pointed to by the user pointer.

ncplane_userptr returns the user pointer associated with the plane ncp.

ncplane_set_scrolling enables or disables scrolling for the plane ncp. If scrolling is true, the plane will scroll when the cursor reaches the bottom row. Otherwise, it will wrap around.

ncplane_get_scrolling returns true if scrolling is enabled for the plane ncp, and false otherwise.

ncplane_above returns the plane directly above ncp in the z-stack. Returns NULL if ncp is the topmost plane.

ncplane_below returns the plane directly below ncp in the z-stack. Returns NULL if ncp is the bottommost plane.

ncplane_focused returns the plane that currently has input focus. Returns NULL if no plane has focus.

ncplane_set_focus sets the input focus to the plane ncp. Returns true if the plane was successfully given focus, and false otherwise. A plane must be visible and not disabled to receive focus.

ncplane_at_yx and ncplane_at_cursor return a dynamically allocated string representing the Extended Graphic Character (EGC) at the specified cell (y, x) or cursor position, respectively. If the cell is empty, an empty string is returned. If the cell contains a literal character, that character is returned. If the cell contains a sprixel, a representation of the sprixel is returned. The caller must free the returned string.

ncplane_at_yx_cell and ncplane_at_cursor_cell return the nccell at the specified cell (y, x) or cursor position, respectively. The nccell is populated with the character, attributes, and pixel data at that cell. The caller must release the returned nccell using nccell_release(3).

ncplane_as_rgba returns a dynamically allocated array of uint32_t, each representing a single RGBA pixel. The array is in row-major order. The dimensions of the plane are stored in the provided ncdims structure. The caller must free the returned array.

ncplane_erase erases the entire plane ncp. All cells are reset to their default state.

ncplane_erase_region erases a rectangular region of the plane ncp. The region is defined by the coordinates (ystart, xstart) and (yend, xend). The coordinates are inclusive. A value of -1 for ystart or xstart indicates the top or left edge of the plane, respectively. A value of -1 for yend or xend indicates the bottom or right edge of the plane, respectively.

ncplane_cursor_move_yx moves the cursor to the specified coordinates (y, x) within the plane ncp. If ncp is NULL, the standard plane's cursor is moved. Coordinates outside the plane are clipped. A value of -1 for y or x refers to the current position of the cursor.

ncplane_cursor_move_rel moves the cursor relative to its current position within the plane ncp. If ncp is NULL, the standard plane's cursor is moved. Coordinates outside the plane are clipped.

ncplane_cursor_move_to moves the cursor to the specified cell, identified by the ncpos structure.

ncplane_cursor_move_up, ncplane_cursor_move_down, ncplane_cursor_move_left, and ncplane_cursor_move_right move the cursor one cell in the specified direction within the plane ncp. If ncp is NULL, the standard plane's cursor is moved. Movement is clipped to the plane boundaries.

ncplane_charbox draws a character box in the plane ncp. The box is drawn using the specified character attributes. The dimensions of the box are given by rows and cols, and the top-left corner is at (y, x). The character used for the box is specified by ch.

ncplane_set_name sets the name of the plane ncp to the string name. Names are primarily for debugging purposes.

ncplane_name returns a dynamically allocated string containing the name of the plane ncp. The caller must free the returned string. If the plane has no name, NULL is returned.

ncplane_quiet_term forces the plane to render without its sprixel. This is useful for certain escape sequences that do not play well with sprixels, such as notcurses_visual(3), it ceases to accept cell-based output. The sprixel will remain associated until a new sprixel is blitted to the plane, the plane is resized, the plane is erased, or the plane is destroyed. The base cell of a sprixelated plane has no effect; if the sprixel is not even multiples of the cell geometry, the "excess plane" is ignored during rendering.

RETURN VALUES

ncplane_create and ncplane_dup return a new struct ncplane on success, or NULL on failure.

ncplane_userptr returns the configured user pointer for the ncplane, and cannot fail.

ncplane_below returns the plane below the specified ncplane. If the provided plane is the bottommost plane, NULL is returned. It cannot fail.

ncplane_set_scrolling returns true if scrolling was previously enabled, and false otherwise.

ncplane_at_yx and ncplane_at_cursor return a heap-allocated copy of the EGC at the relevant cell, or NULL if the cell is invalid. The caller should free this result. ncplane_at_yx_cell and ncplane_at_cursor_cell instead load these values into an nccell, which is invalidated if the associated plane is destroyed. The caller should release this nccell with nccell_release.

ncplane_as_rgba returns a heap-allocated array of uint32_t values, each representing a single RGBA pixel, or NULL on failure.

ncplane_erase_region returns -1 if ystart or xstart are less than -1, or outside the plane.

ncplane_cursor_move_yx returns -1 if the coordinates are beyond the dimensions of the specified plane (except for the special value -1).

ncplane_cursor_move_rel returns -1 if the coordinates are beyond the dimensions of the specified plane.

ncplane_name returns a heap-allocated copy of the plane's name, or NULL if it has no name (or on error).

Functions returning int return 0 on success, and non-zero on error.

All other functions cannot fail (and return void).

NOTES

BUGS

ncplane_at_yx doesn't yet account for bitmap-based graphics (see notcurses_visual(3)). Whatever glyph-based contents existed on the plane when the bitmap was blitted will continue to be returned.

When the alternate screen is not used (see notcurses_init(3)), the contents of the terminal at startup remain present until obliterated on a cell-by-cell basis. ncplane_erase and ncplane_erase_region cannot be used to clear the terminal of startup content. If you want the screen cleared on startup, but do not want to use (or rely on) the alternate screen, use something like:

ncplane_set_base(notcurses_stdplane(nc), " ", 0, 0);
notcurses_render(nc);

or simply:

notcurses_refresh(nc);
