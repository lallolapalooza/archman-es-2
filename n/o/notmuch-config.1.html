NOMBRE

notmuch-config - acceder al archivo de configuración de notmuch

SINOPSIS

notmuch config get <sección>.<ítem>

notmuch config set [--database] <sección>.<ítem> [valor ...]

notmuch config list

DESCRIPCIÓN

El comando config puede usarse para obtener o establecer ajustes en el archivo de configuración de notmuch y en la base de datos correspondiente.

get
El valor del ítem de configuración especificado se imprime en la salida estándar. Si el ítem tiene múltiples valores (es una lista), cada valor está separado por un carácter de nueva línea.
set
El ítem de configuración especificado se establece al valor dado. Para especificar un ítem de múltiples valores (una lista), proporcione cada valor como un argumento separado en la línea de comandos.

Si no se proporcionan valores, el ítem de configuración especificado se eliminará del archivo de configuración.

Con la opción --database, actualiza los metadatos de configuración almacenados en la base de datos, en lugar del archivo de configuración de texto por defecto.

list
Cada ítem de configuración se imprime en la salida estándar, cada uno en una línea separada del formato:
sección.ítem=valor

No hay espacio adicional alrededor de los caracteres de punto o signo igual. En un ítem de múltiples valores (una lista), los valores están separados por puntos y coma.

Los ítems de configuración disponibles se describen a continuación. Las rutas no absolutas se presumen relativas a $HOME para los ítems de la sección database.

built_with.<nombre>
Característica de tiempo de compilación <nombre>. Las posibilidades actuales incluyen "retry_lock" (opción de configuración, incluida por defecto). (desde notmuch 0.30, "compact" y "field_processor" siempre se incluyen.)
database.autocommit
Con qué frecuencia se confirman las transacciones en disco. 0 significa esperar hasta que el comando se complete, de lo contrario un entero n especifica confirmar en disco después de cada n transacciones completadas.

Historial: este valor de configuración se introdujo en notmuch 0.33.

database.backup_dir
Directorio donde almacenar volcados de etiquetas al actualizar la base de datos.

Historial: este valor de configuración se introdujo en notmuch 0.32.

Por defecto: Un directorio hermano de la base de datos Xapian llamado backups.

database.hook_dir
Directorio que contiene los hooks ejecutados por los comandos de notmuch. Ver notmuch-hooks.

Historial: este valor de configuración se introdujo en notmuch 0.32.

Por defecto: Ver HOOKS, más abajo.

database.mail_root
El directorio de nivel superior donde reside actualmente tu correo y a donde se entregará el correo en el futuro. Los archivos deben ser mensajes de correo electrónico individuales.

Historial: este valor de configuración se introdujo en notmuch 0.32.

Por defecto: Para compatibilidad con configuraciones más antiguas, se utiliza el valor de database.path si database.mail_root no está establecido.

database.path
Notmuch almacenará su base de datos aquí, (en un subdirectorio llamado .notmuch si database.mail_root no está establecido).

Por defecto: ver UBICACIÓN DE LA BASE DE DATOS

git.path
Ubicación por defecto para el repositorio git para notmuch-git.
git.safe_fraction
Algunas operaciones de notmuch-git comprueban que la fracción de mensajes cambiados (en la base de datos o en git, según corresponda) no sea demasiado grande. Este ítem controla qué fracción de mensajes totales se considera "no demasiado grande".
git.tag_prefix
Prefijo (filtro) de etiqueta por defecto para notmuch-git.
index.as_text
Lista de expresiones regulares (sin delimitadores) para tipos MIME que se indexarán como texto. Actualmente, esto se aplica solo a los adjuntos. Por defecto, la expresión regular coincide en cualquier parte del tipo de contenido; si el usuario desea una coincidencia anclada, debe incluir anclajes en sus expresiones regulares.

Historial: Este valor de configuración se introdujo en notmuch 0.38.

index.decrypt
Política para descifrar mensajes cifrados durante la indexación. Debe ser uno de: false, auto, nostash, o true.

Al indexar un mensaje de correo electrónico cifrado, si esta variable se establece en true, notmuch intentará descifrar el mensaje y indexar el texto plano, almacenando en caché una copia de las claves de sesión descubiertas para el mensaje. Si es auto, intentará indexar el texto plano si ya se conoce una clave de sesión almacenada en caché para el mensaje (por ejemplo, de una copia anterior), pero no intentará acceder a tus claves secretas. Usa false para evitar descifrar incluso cuando ya hay una clave de sesión en caché.

nostash es lo mismo que true excepto que no almacenará en caché las claves de sesión recién descubiertas en la base de datos.

Desde la línea de comandos (es decir, durante notmuch-new, notmuch-insert, o notmuch-reindex), el usuario puede anular la política de descifrado almacenada en la base de datos con la opción --decrypt=.

Aquí hay una tabla que resume la funcionalidad de cada una de estas políticas:

false auto nostash true
Indexar texto plano usando claves de sesión en caché X X X
Indexar texto plano usando claves secretas X X
Almacenar en caché claves de sesión X
Eliminar claves de sesión en caché al reindexar X

Las claves de sesión en caché se guardan en la base de datos como propiedades asociadas al mensaje. Ver session-key en notmuch-properties para más detalles sobre cómo pueden ser útiles.

VARIABLES DE CONFIGURACIÓN

index.decrypt
Si se establece en true, then notmuch will attempt to decrypt messages on index time. This requires that you have your GPG private keys available on the machine where you are running notmuch, and that your private keys are not password protected, or that they are available via an agent.

If set to nostash, notmuch will attempt to decrypt messages on index time, but will not stash the cleartext. This is a middle ground between auto (which stashes cleartext) and true (which tries to decrypt but does not stash cleartext).

Be aware that the notmuch index is likely sufficient (and a stashed session key is certainly sufficient) to reconstruct the cleartext of the message itself, so please ensure that the notmuch message index is adequately protected. DO NOT USE index.decrypt=true or index.decrypt=nostash without considering the security of your index.

Default: auto.

index.header.<prefix>
Define the query prefix <prefix>, based on a mail header. For example index.header.List=List-Id will add a probabilistic prefix List: that searches the List-Id field. User defined prefixes must not start with 'a'...'z'; in particular adding a prefix with same name as a predefined prefix is not supported. See notmuch-search-terms for a list of existing prefixes, and an explanation of probabilistic prefixes.
maildir.synchronize_flags
If true, then the following maildir flags (in message filenames) will be synchronized with the corresponding notmuch tags:
Flag Tag
D draft
F flagged
P passed
R replied
S unread (added when 'S' flag is not present)

The notmuch-new command will notice flag changes in filenames and update tags, while the notmuch-tag and notmuch-restore commands will notice tag changes and update flags in filenames.

If there have been any changes in the maildir (new messages added, old ones removed or renamed, maildir flags changed, etc.), it is advisable to run notmuch-new before notmuch-tag or notmuch-restore commands to ensure the tag changes are properly synchronized to the maildir flags, as the commands expect the database and maildir to be in sync.

Default: true.

new.ignore
A list to specify files and directories that will not be searched for messages by notmuch-new. Each entry in the list is either:

A file or a directory name, without path, that will be ignored, regardless of the location in the mail store directory hierarchy.

Or:

A regular expression delimited with // that will be matched against the path of the file or directory relative to the database path. Matching files and directories will be ignored. The beginning and end of string must be explicitly anchored. For example, /.*/foo$/ would match "bar/foo" and "bar/baz/foo", but not "foo" or "bar/foobar".

Default: empty list.

new.tags
A list of tags that will be added to all messages incorporated by notmuch new.

Default: unread;inbox.

query.<name>
Expansion for named query called <name>. See notmuch-search-terms for more information about named queries.
search.exclude_tags
A list of tags that will be excluded from search results by default. Using an excluded tag in a query will override that exclusion.

Default: empty list. Note that notmuch puts deleted;spam here when creating new configuration file.

search.authors_separator
The string to separate authors when showing a thread.

Default: ,

search.authors_matched_separator
The string to separate matched from non-matched authors when showing a thread.

Default: |

show.extra_headers
By default notmuch-show includes the following headers in structured output if they are present in the message: Subject, From, To, Cc, Bcc, Reply-To, Date. This option allows the specification of a list of further headers to output.

History: This configuration value was introduced in notmuch 0.35.

Default: empty list.

squery.<name>
Expansion for named query called <name>, using s-expression syntax. See notmuch-sexp-queries for more information about s-expression queries.
user.name
Your full name.

Default: $NAME variable if set, otherwise read from /etc/passwd.

user.other_email
A list of other email addresses at which you receive email (see also, user.primary_email)

Default: not set.

user.primary_email
Your primary email address.

Default: $EMAIL variable if set, otherwise constructed from the username and hostname of the current machine.

ARCHIVOS

CONFIGURACIÓN

Orden de búsqueda del archivo de configuración de Notmuch:

1.
Archivo especificado por la opción global notmuch --config; consulte notmuch.
2.
Archivo especificado por la variable de entorno NOTMUCH_CONFIG.
3.
$XDG_CONFIG_HOME/notmuch/<profile>/config donde <profile> se define por la variable de entorno NOTMUCH_PROFILE si está establecida, $XDG_CONFIG_HOME/notmuch/default/config en caso contrario.
4.
$HOME/.notmuch-config.<profile> donde <profile> se define por la variable de entorno NOTMUCH_PROFILE si está establecida, $HOME/.notmuch-config en caso contrario.

UBICACIÓN DE LA BASE DE DATOS

Orden de búsqueda de la base de datos de Notmuch:

1.
Directorio especificado por la variable de entorno NOTMUCH_DATABASE.
2.
Directorio especificado por la clave de configuración database.path.
3.
$XDG_DATA_HOME/notmuch/<profile> donde <profile> se define por la variable de entorno NOTMUCH_PROFILE si está establecida, $XDG_DATA_HOME/notmuch/default en caso contrario.
4.
Directorio especificado por la variable de entorno MAILDIR.
5.
$HOME/mail

HOOKS

Orden de búsqueda del directorio de hooks de Notmuch:

1.
Directorio especificado por la opción de configuración database.hook_dir.
2.
$XDG_CONFIG_HOME/notmuch/<profile>/hooks donde <profile> se define por la variable de entorno NOTMUCH_PROFILE si está establecida, $XDG_CONFIG_HOME/notmuch/default/hooks en caso contrario.
3.
<database.path>/.notmuch/hooks
