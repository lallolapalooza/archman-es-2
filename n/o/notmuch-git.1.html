NOMBRE

notmuch-git - gestionar etiquetas de notmuch con git

SINOPSIS

notmuch git [-h] [-N] [-C repo] [-p prefijo] [-v] [-l nivel de registro] subcomando

nmbug [-h] [-C repo] [-p prefijo] [-v] [-l nivel de registro] subcomando

DESCRIPCIÓN

Gestiona etiquetas de notmuch con Git.

OPCIONES

Opciones admitidas para notmuch git incluyen

-h, --help
mostrar mensaje de ayuda y salir
-N, --nmbug
Establece los valores predeterminados para --tag-prefix y --git-dir adecuados para el rastreador de errores de notmuch
-C <repo>, --git-dir <repo>
Operar en el repositorio git repo. Ver UBICACIÓN DEL REPOSITORIO para los valores predeterminados.
-p <prefijo>, --tag-prefix <prefijo>
Operar solo en etiquetas con el prefijo prefijo. Ver VALOR DEL PREFIJO para los valores predeterminados.
-v, --version
mostrar número de versión de notmuch-git y salir
-l <nivel>, --log-level <nivel>
Verbosidad del registro, uno de: critical, error, warning, info, debug. El valor predeterminado es warning.

SUBCOMANDOS

Para obtener ayuda sobre un subcomando particular, ejecuta: 'notmuch-git ... <comando> --help'.

archive [tree-ish] [arg ...]

Volcar un archivo tar de un conjunto de etiquetas confirmadas usando 'git archive'. Ver CONTENIDO DEL REPOSITORIO para detalles del contenido del archivo.

tree-ish

El árbol o commit para producir un archivo. El valor predeterminado es 'HEAD'.

arg
checkout [-f|--force]

Actualizar la base de datos de notmuch desde git.

Esto es principalmente útil para descartar tus cambios en notmuch relativos a git.

[-f|--force]

Anular las comprobaciones que impiden modificar etiquetas para grandes fracciones de mensajes en la base de datos. Ver también git.safe_fraction.

clone <repositorio>

Crear un repositorio local de notmuch git desde una fuente remota.

Esto envuelve 'git clone', agregando algunas opciones para evitar la creación de un árbol de trabajo mientras se conservan las ramas de seguimiento remoto y los remotos.

repositorio
commit [-f|--force] [mensaje]

Confirmar etiquetas que coinciden con prefijos desde la base de datos de notmuch en git.

mensaje

Texto opcional para el mensaje de confirmación.

-f|--force

Anular las comprobaciones que impiden modificar etiquetas para grandes fracciones de mensajes en la base de datos. Ver también git.safe_fraction.

fetch [remoto]

Obtener cambios del repositorio remoto.

remoto

Anular el valor predeterminado configurado en branch.<nombre>.remote para obtener cambios de un repositorio remoto particular (por ejemplo, origin).

help

Mostrar ayuda breve para un comando de notmuch git.

init [--format-version=N]

Crear un repositorio vacío de notmuch git.

Esto envuelve 'git init' con algunos pasos adicionales para soportar comandos de estado y confirmación posteriores.

--format-version=N

Crear un repositorio en la versión de formato N. Por defecto, notmuch-git utiliza la versión más alta soportada, que es la mejor opción para la mayoría de los casos de uso.

log [arg ...]

Un envoltorio para 'git log'.

arg

Los argumentos adicionales se pasan a 'git log'.

Después de ejecutar notmuch git fetch, puedes inspeccionar los cambios con

$ notmuch git log HEAD..@{upstream}
merge [referencia]

Fusionar cambios de 'referencia' en HEAD y cargar el resultado en notmuch.

referencia

Referencia, normalmente otras cabezas de rama, para fusionar en nuestra rama. El valor predeterminado es @{upstream}.

pull [repositorio] [refspec ...]

Obtener (fusionar) cambios del repositorio remoto a notmuch.

pull es equivalente a fetch seguido de merge. Usamos el repositorio configurado en git para tu rama actual (branch.<nombre>.repository, probablemente origin, y branch.<nombre>.merge, probablemente master o main).

repositorio

El repositorio "remoto" que es la fuente del pull. Este parámetro puede ser una URL (ver la sección GIT URLS en notmuch-git(1) — archman

NAME

notmuch-git — manage Notmuch tags as git objects

SYNOPSIS

notmuch-git command [options]

DESCRIPTION

notmuch-git is a tool to manage Notmuch tags as git objects. This allows users to version control their tags, and use standard git tools to manage them.

The following commands are supported:

clone repository [branch]

Clone a git repository containing Notmuch tags, and import them into the local Notmuch database.

repository
branch

The branch to clone. If not specified, the remote's default branch (usually master or main) is cloned.

fetch [repository] [refspec]

Fetch updates from a remote repository and import them into the local Notmuch database.

repository
refspec
push [repository] [refspec]

Push the local notmuch git git state to a remote repository.

repository
refspec
status

Show pending updates in notmuch or git repo.

Prints lines of the form

ng Message-Id tag

where n is a single character representing notmuch database status

A

Tag is present in notmuch database, but not committed to git (equivalently, tag has been deleted in git repo, e.g. by a pull, but not restored to notmuch database).

D

Tag is present in git repo, but not restored to notmuch database (equivalently, tag has been deleted in notmuch).

U

Message is unknown (missing from local notmuch database).

The second character g (if present) represents a difference between local and upstream branches. Typically notmuch git fetch needs to be run to update this.

a

Tag is present in upstream, but not in the local git branch.

d

Tag is present in local git branch, but not upstream.

REPOSITORY CONTENTS

The tags are stored in the git repo (and exported) as a set of empty files. These empty files are contained within a directory named after the message-id.

In what follows encode() represents a POSIX filesystem safe encoding. The encoding preserves alphanumerics, and the characters +-_@=.,:. All other octets are replaced with % followed by a two digit hex number.

Currently notmuch-git can read any format version, but can only create (via init) version 1 repositories.

Version 0

This is the legacy format created by the nmbug tool prior to release 0.37. For a message with Message-Id id, for each tag tag, there is an empty file with path

tags/ encode (id) / encode (tag)

Version 1

In format version 1 and later, the format version is contained in a top level file called FORMAT.

For a message with Message-Id id, for each tag tag, there is an empty file with path

tags/ hash1 (id) / hash2 (id) encode (id) / encode (tag)

The hash functions each represent one byte of the blake2b hex digest.

Compared to version 0, this reduces the number of subdirectories within each directory.

REPOSITORY LOCATION

notmuch-git uses the first of the following with a non-empty value to locate the git repository.

  • Option --git-dir.
  • Environment variable NOTMUCH_GIT_DIR.
  • Configuration item git.path
  • If invoked as nmbug or with the --nmbug option, $HOME/.nmbug; otherwise $XDG_DATA_HOME/notmuch/$NOTMUCH_PROFILE/git.

PREFIX VALUE

notmuch-git uses the first of the following with a non-null value to define the tag prefix.

  • Option --tag-prefix.
  • Environment variable NOTMUCH_GIT_PREFIX.
  • Configuration item git.tag_prefix.
  • If invoked as nmbug or with the --nmbug option, notmuch::, otherwise the empty string.

ENVIRONMENT

Variable NOTMUCH_PROFILE influences REPOSITORY LOCATION. If it is unset, 'default' is assumed.

NOTMUCH_GIT_DIR
Default location of git repository. Overridden by --git-dir.
NOTMUCH_GIT_PREFIX
Default tag prefix (filter). Overridden by --tag-prefix.
