NOTMUCH-SHOW(1) notmuch NOTMUCH-SHOW(1)

NOMBRE

notmuch-show - muestra mensajes que coinciden con los términos de búsqueda dados

SINOPSIS

notmuch show [opción ...] <término-de-búsqueda> ...

DESCRIPCIÓN

Muestra todos los mensajes que coinciden con los términos de búsqueda.

Ver notmuch-search-terms para detalles de la sintaxis soportada para <términos-de-búsqueda>.

Los mensajes se agruparán y ordenarán según el encadenamiento (todas las respuestas a un mensaje particular aparecerán inmediatamente después de ese mensaje en orden de fecha). La salida no está indentada por defecto, pero se imprimen etiquetas de profundidad para que un post-procesador (como la interfaz de emacs para notmuch) pueda realizar una indentación adecuada.

Las opciones soportadas para show incluyen

--duplicado=N
Número de duplicado de salida N. La numeración comienza desde 1 y coincide con el orden utilizado por search --duplicate y search --output=files
--entire-thread=(true|false)
Si es verdadero, notmuch show emite todos los mensajes del hilo de cualquier mensaje que coincida con los términos de búsqueda; si es falso, solo emite los mensajes que coinciden. Para --format=json y --format=sexp esto es verdadero por defecto. Para otros formatos, esto es falso por defecto.
--format=(text|json|sexp|mbox|raw)
text (por defecto para mensajes)
El formato de texto plano por defecto tiene todas las partes MIME de contenido de texto decodificadas. Varios componentes en la salida (message, header, body, attachment y part MIME) estarán delimitados por marcadores fáciles de analizar. Cada marcador consiste en un carácter Control-L (ASCII decimal 12), el nombre del marcador y luego una llave de apertura o cierre ('{' o '}'), para abrir o cerrar el componente. Para un mensaje MIME multipart, estas partes estarán anidadas.
json
La salida está formateada con Notación de Objetos Javascript (JSON). Este formato es más robusto que el formato de texto para procesamiento automatizado. La estructura anidada de los mensajes MIME multipart se refleja en la salida JSON anidada. Por defecto, la salida JSON incluye todos los mensajes de un hilo coincidente; es decir, por defecto, --format=json establece --entire-thread. El llamador puede deshabilitar este comportamiento estableciendo --entire-thread=false. La salida JSON siempre se codifica como UTF-8 y cualquier contenido de mensaje incluido en la salida se convertirá de zona horaria a UTF-8.
sexp
La salida está formateada como el equivalente de expresión s (sexp) de Lisp del formato JSON anterior. Los objetos se formatean como listas de propiedades cuyas claves son palabras clave (símbolos precedidos por dos puntos). Verdadero se formatea como t y tanto falso como nulo se formatean como nil. Al igual que con JSON, la salida s-expression siempre se codifica como UTF-8.
mbox
Todos los mensajes coincidentes se emiten en el formato tradicional de mbox de Unix, con cada mensaje prefijado por una línea que comienza con "From " y una línea en blanco que separa cada mensaje. Las líneas en el contenido del mensaje que comienzan con "From " (precedidas por cero o más caracteres '>') tienen un carácter '>' adicional. Este escape reversible se denomina formato "mboxrd" y se describe en detalle aquí:
http://homepage.ntlworld.com/jonathan.deboynepollard/FGA/mail-mbox-formats.html
raw (por defecto si se proporciona --part)
Escribe los bytes brutos de la parte MIME dada de un mensaje a la salida estándar. Para este formato, es un error especificar una consulta que coincida con más de un mensaje.

Si la parte especificada es una parte hoja, esto emite el cuerpo de la parte después de realizar la decodificación de la transferencia de contenido (pero sin conversión de zona horaria). Esto es adecuado para guardar archivos adjuntos, por ejemplo.

Para una parte multipart o de mensaje, la salida incluye las cabeceras de la parte además del cuerpo (incluyendo todas las partes hijas). No se realiza decodificación porque las partes multipart y de mensaje no pueden tener codificación de transferencia de contenido no trivial. Los consumidores de esto pueden necesitar implementar decodificación MIME y funciones similares.

--format-version=N
Utiliza la versión especificada del formato de salida estructurada. Esto está destinado a programas que invocan notmuch internamente. Si se omite, se utilizará la última versión compatible.
--part=N
Emite la única parte MIME decodificada N de un solo mensaje. Los términos de búsqueda deben coincidir con un solo mensaje. Las partes del mensaje se numeran en un recorrido en profundidad de la estructura MIME del mensaje y se identifican en los formatos de salida 'json', 'sexp' o 'text'.

Tenga en cuenta que incluso un mensaje sin estructura MIME o una única parte de cuerpo todavía tiene dos partes MIME: la parte 0 es el mensaje completo (cabeceras y cuerpo) y la parte 1 es solo el cuerpo.

--sort=(newest-first|oldest-first)
Esta opción se puede utilizar para presentar los resultados en orden cronológico (oldest-first) o en orden cronológico inverso (newest-first).

Solo los hilos completos se reordenan. El orden de los mensajes dentro de cada hilo no se verá afectado por esta bandera, ya que ese orden siempre lo determinan las respuestas del hilo.

Por defecto, los resultados se mostrarán en orden cronológico inverso (es decir, los resultados más nuevos se mostrarán primero).

--offset=[-]N
Omite mostrar los primeros N resultados. Con el '-', comience en el N-ésimo resultado desde el final.
--limit=N
Limita el número de resultados mostrados a N.
--verify
Calcula e informa la validez de cualquier firma criptográfica MIME encontrada en el contenido seleccionado (por ejemplo, partes "multipart/signed"). Se informará el estado de la firma (actualmente solo soportado con --format=json y --format=sexp), y la parte multipart/signed será reemplazada por los datos firmados.
--decrypt=(false|auto|true|stash)
Si es true, descifra cualquier parte cifrada MIME encontrada en el contenido seleccionado (por ejemplo, partes "multipart/encrypted"). Se informará el estado del descifrado (actualmente solo soportado con --format=json y --format=sexp) y, en caso de descifrado exitoso, la parte multipart/encrypted será reemplazada por el contenido descifrado.

stash se comporta como true, pero tras un descifrado exitoso también almacenará la clave de sesión del mensaje en la base de datos, e indexará el texto plano del mensaje, permitiendo el descifrado automático en el futuro.

Si es auto, y ya se conoce una clave de sesión para el mensaje, se descifrará, pero notmuch no intentará acceder a las claves del usuario.

Use false para evitar incluso el descifrado automático.

notmuch-show(1) — notmuch-runtime

SYNOPSIS

notmuch show [options] search-term...

DESCRIPTION

The notmuch show command displays messages that match the given search-terms. By default, it displays the most recent message matching the search terms. If the search terms specify a thread (e.g. by using thread: search term), all messages in the thread will be shown.

The available options are:

--format=(text|json|sexp|mbox)
Specify the output format. Default is text.
--output=(file|stdout)
Specify the output destination. Default is stdout.
--output-file=FILE
Specify the output file name when --output=file is used.
--part=N
Show only the Nth part of a message. Parts are numbered starting from 1. The default is to show all parts.
--entire-thread
Show the entire thread containing the matched messages, rather than just the matched messages themselves. This option is only meaningful when the search terms specify a single thread.
--decrypt=(true|false|auto|stash)

Controls whether and how to attempt to decrypt message bodies. The default is auto.

false
Never attempt to decrypt message bodies. The raw, possibly encrypted, bodies are shown.
auto
Attempt to decrypt message bodies if the session key is already known. Otherwise, use secret keys to decrypt.
true
Always attempt to decrypt message bodies, using secret keys if necessary. This is equivalent to setting --decrypt=auto and also stashing any newly recovered session keys.
stash
Always attempt to decrypt message bodies, using secret keys if necessary. This is equivalent to setting --decrypt=auto and also stashing any newly recovered session keys.

Here is a table that summarizes each of these policies:

false auto true stash
Show cleartext if session key is already known X X X
Use secret keys to show cleartext X X
Stash any newly recovered session keys, reindexing message if found X

Note: --decrypt=stash requires write access to the database. Otherwise, notmuch show operates entirely in read-only mode.

Default: auto

--exclude=(true|false)

Specify whether to omit threads only matching search.exclude_tags from the search results (the default) or not. In either case the excluded message will be marked with the exclude flag (except when output=mbox when there is nowhere to put the flag).

If --entire-thread is specified then complete threads are returned regardless (with the excluded flag being set when appropriate) but threads that only match in an excluded message are not returned when --exclude=true.

The default is --exclude=true.

--body=(true|false)

If true (the default) notmuch show includes the bodies of the messages in the output; if false, bodies are omitted. --body=false is only implemented for the text, json and sexp formats and it is incompatible with --part > 0.

This is useful if the caller only needs the headers as body-less output is much faster and substantially smaller.

--include-html

Include "text/html" parts as part of the output (currently only supported with --format=text, --format=json and --format=sexp). By default, unless --part=N is used to select a specific part or --include-html is used to include all "text/html" parts, no part with content type "text/html" is included in the output.

A common use of notmuch show is to display a single thread of email messages. For this, use a search term of "thread:<thread-id>" as can be seen in the first column of output from the notmuch-search command.

CONFIGURATION

Structured output (json / sexp) is influenced by the configuration option show.extra_headers. See notmuch-config for details.

EXIT STATUS

This command supports the following special exit status codes

20
The requested format version is too old.
21
The requested format version is too new.
