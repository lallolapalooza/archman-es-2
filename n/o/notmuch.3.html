notmuch_status_t notmuch_database_index_file (notmuch_database_t * database, const char * filename, notmuch_indexopts_t * indexopts, notmuch_message_t ** message)

Añade un archivo de mensaje a una base de datos, indexándolo para su recuperación mediante búsquedas futuras. Si ya existe un mensaje con el mismo ID de mensaje que el archivo especificado, sus índices se fusionarán y este nuevo nombre de archivo también se asociará con el mensaje existente.

Aquí, 'filename' debe ser una ruta relativa a la ruta de 'database' (ver notmuch_database_get_path), o bien debe ser un nombre de archivo absoluto con componentes iniciales que coincidan con la ruta de 'database'.

El archivo debe ser un único mensaje de correo electrónico (no un mbox con múltiples mensajes) que se espera que permanezca en su ubicación actual, (ya que la base de datos notmuch hará referencia al nombre del archivo y no copiará todo el contenido del archivo).

Si otro mensaje con el mismo ID de mensaje ya existe en la base de datos, en lugar de crear un nuevo mensaje, esto añade los términos de búsqueda del archivo identificado al índice del mensaje existente y añade 'filename' a la lista de nombres de archivo conocidos para el mensaje.

El parámetro 'indexopts' puede ser NULL (lo que significa usar las opciones de indexación predeterminadas de la base de datos) o puede ser una elección explícita de opciones de indexación que deben regir la indexación de este 'filename' específico.

Si 'message' no es NULL, entonces, tras una devolución exitosa (NOTMUCH_STATUS_SUCCESS o NOTMUCH_STATUS_DUPLICATE_MESSAGE_ID) '*message' se inicializará como un objeto de mensaje que puede usarse para cosas como añadir etiquetas al mensaje recién añadido. El usuario debe llamar a notmuch_message_destroy cuando haya terminado con el mensaje. En caso de fallo, '*message' se establecerá a NULL.

Valor de retorno:

NOTMUCH_STATUS_SUCCESS: Mensaje añadido con éxito a la base de datos.

NOTMUCH_STATUS_XAPIAN_EXCEPTION: Se produjo una excepción de Xapian, el mensaje no se añadió.

NOTMUCH_STATUS_DUPLICATE_MESSAGE_ID: El mensaje tiene el mismo ID de mensaje que otro mensaje ya presente en la base de datos. El nuevo nombre de archivo se añadió con éxito al mensaje en la base de datos (si no estaba ya presente) y se devuelve el mensaje existente.

NOTMUCH_STATUS_FILE_ERROR: Se produjo un error al intentar abrir el archivo (como permiso denegado o archivo no encontrado, etc.). No se añadió nada a la base de datos.

NOTMUCH_STATUS_FILE_NOT_EMAIL: el contenido de filename no parece ser un mensaje de correo electrónico. No se añadió nada a la base de datos.

NOTMUCH_STATUS_READ_ONLY_DATABASE: La base de datos se abrió en modo de solo lectura, por lo que no se puede añadir ningún mensaje.

NOTMUCH_STATUS_UPGRADE_REQUIRED: El llamador debe actualizar la base de datos para usar esta función.

notmuch_status_t notmuch_message_freeze (notmuch_message_t * message)

Congela el estado actual del 'message' en la base de datos. Esto significa que los cambios en el estado del mensaje (a través de notmuch_message_add_tag, notmuch_message_remove_tag y notmuch_message_remove_all_tags) no se confirmarán en la base de datos hasta que el mensaje se descongele con notmuch_message_thaw.

Múltiples llamadas a freeze/thaw son válidas y estas llamadas se "apilan". Es decir, debe haber tantas llamadas a thaw como a freeze antes de que un mensaje se descongele realmente.

La capacidad de hacer freeze/thaw permite transacciones seguras para cambiar los valores de las etiquetas. Por ejemplo, establecer explícitamente un mensaje para que tenga un conjunto dado de etiquetas podría verse así:

notmuch_message_freeze (message);

notmuch_message_remove_all_tags (message);

for (i = 0; i < NUM_TAGS; i++) notmuch_message_add_tag (message, tags[i]);

notmuch_message_thaw (message);

Con freeze/thaw usado de esta manera, se garantiza que el mensaje en la base de datos tendrá, o bien el conjunto completo de valores de etiqueta originales, o bien el conjunto completo de nuevos valores de etiqueta, pero nada intermedio.

Imagínese el ejemplo anterior sin freeze/thaw y la operación se interrumpe de alguna manera. Esto podría resultar en que el mensaje quede sin etiquetas si la interrupción ocurrió después de notmuch_message_remove_all_tags pero antes de notmuch_message_add_tag.

Valor de retorno:

NOTMUCH_STATUS_SUCCESS: Mensaje congelado correctamente.

NOTMUCH_STATUS_READ_ONLY_DATABASE: La base de datos se abrió en modo de solo lectura, por lo que el mensaje no se puede modificar.
