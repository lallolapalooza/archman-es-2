DESCRIPCIÓN

Las celdas componen el búfer de fotogramas asociado a cada plano, con una celda por coordenada direccionable. Normalmente no necesitarás interactuar directamente con los objetos nccell.

Cada nccell contiene exactamente un clúster de grafemas extendido. Si el EGC está codificado en UTF-8 con cuatro o menos bytes (todos los puntos de código Unicode a partir de Unicode 13 se pueden codificar en no más de cuatro bytes UTF-8), se codifica directamente en el campo gcluster del nccell, y no se necesita almacenamiento adicional. De lo contrario, el EGC se almacena como una cadena UTF-8 terminada en nulo en algún egcpool subyacente. Los Egcpools están asociados con los ncplanes, por lo que los nccells deben considerarse asociados con los ncplanes. De hecho, ncplane_erase destruye el almacenamiento subyacente de todas las celdas de un plano, invalidándolas. Esta asociación se forma en el momento de nccell_load, nccell_prime o nccell_duplicate. Todas estas funciones llaman primero a nccell_release, al igual que nccell_load_egc32, nccell_load_char y nccell_load_ucs32. Cuando haya terminado de usar un nccell completamente, llame a nccell_release. ncplane_destroy liberará la memoria utilizada por el nccell, pero el egcpool subyacente tiene un tamaño máximo de 16MiB, y la falta de liberación de nccells puede bloquear la salida nueva eventualmente. Escribir sobre las celdas de un ncplane las libera automáticamente.

nccell_extended_gcluster proporciona un manejador terminado en nulo para el EGC. Esto debe considerarse invalidado por cambios en el nccell o en el egcpool. El manejador no se asigna en el montón; no intente free(3). Se puede obtener una copia asignada en el montón con nccell_strdup.

ncstrwidth_valid devuelve el número de columnas ocupadas por una cadena UTF-8 válida, o -1 si se encuentra un error. En cualquier caso, el número de bytes y columnas válidos consumidos antes del error se guardan en validbytes y validwidth (suponiendo que no sean NULL).

nccell_fg_palindex extrae el índice de paleta del canal de primer plano de una celda. El canal debe ser de paleta

NAME

notcurses_cell - structure and functions for manipulating Notcurses cells

SYNOPSIS

#include <notcurses/notcurses.h>

typedef struct nccell

int nccell_set_fg_rgb8(nccell *c, uint8_t r, uint8_t g, uint8_t b);

int nccell_set_bg_rgb8_clipped(nccell *c, uint8_t r, uint8_t g, uint8_t b);

int nccell_load(nccell *c, const char *utf8str);

size_t ncstrwidth(const char *str);

size_t ncstrwidth_valid(const char *str);

int nccell_extended_gcluster(const nccell *c);

DESCRIPTION

A nccell is the fundamental visible unit in Notcurses. It represents a single cell on the screen, potentially spanning multiple columns for wide characters. Cells are composed of a foreground channel, a background channel, and a Unicode character (or sequence). Unicode characters are generally represented as UTF-8 encoded strings within Notcurses, though they are not necessarily contiguous on the screen. The term "gcluster" (grapheme cluster) is often used interchangeably with "character" in this context. A cell can contain at most one gcluster.

The foreground and background channels control the color and styling of the cell. These channels have three modes: default, direct RGB, and palette-indexed. The default color is determined by the terminal's default foreground or background color, respectively. Direct RGB colors are specified using 24-bit RGB values (8 bits per channel). Palette-indexed colors are specified using an index into the terminal's color palette. Notcurses supports 256-color palettes, so valid indices range from 0 to 255. NCPALETTESIZE, defined in notcurses/notcurses.h, is 256.

nccell_set_fg_rgb8 and nccell_set_bg_rgb8 set the foreground and background color, respectively, to the provided 8-bit RGB values. nccell_set_fg_default and nccell_set_bg_default reset the respective channels to their default values. nccell_set_fg_palindex and nccell_set_bg_palindex set the channels to palette-indexed mode. The index must be less than NCPALETTESIZE. Use nccell_fg_palindex and nccell_bg_palindex to retrieve the palette index, and nccell_has_fg_palindex and nccell_has_bg_palindex to check if a cell is in palette-indexed mode.

nccell_set_fg_rgb8_clipped and nccell_set_bg_rgb8_clipped are similar to their non-clipped counterparts, but they will clamp the RGB values to the nearest representable color in the terminal's current color mode if the provided value is outside the representable range. This is useful when dealing with terminals that do not support full 24-bit color.

nccell_load, nccell_load_bytes, nccell_set_to_egc, nccell_set_to_egc_bytes, nccell_set_to_bytes, nccell_set_to_lenient_egc, nccell_set_to_lenient_egc_bytes, and nccell_set_to_lenient_bytes all set the cell's character to the provided input. The various functions offer different ways to specify the input (UTF-8 string, raw bytes) and different levels of validation. nccell_load and nccell_set_to_egc expect valid UTF-8. nccell_load_bytes, nccell_set_to_bytes, nccell_set_to_lenient_egc_bytes, and nccell_set_to_lenient_bytes treat the input as raw bytes. nccell_set_to_lenient_* variants are more permissive with malformed UTF-8.

nccell_extract and nccell_extract_bytes retrieve the cell's character as a UTF-8 string or raw bytes, respectively. Ensure the buffer provided is large enough to hold the character data. The maximum size of a cell's character data is returned by nccell_object_size.

nccell_duplicate and nccell_copy both copy the contents of one cell to another. nccell_duplicate is intended for use with cells that have dynamically allocated character data, while nccell_copy is for cells with statically allocated character data. In practice, nccell_copy is sufficient for most use cases.

nccell_reset and nccell_init initialize a cell to a default state (empty character, default colors). nccell_reset is intended for cells that have been used, while nccell_init is for newly allocated cells.

nccellcmp compares two cells. It returns a negative integer if c1 is less than c2, 0 if they are equal, and a positive integer if c1 is greater than c2. The comparison is based on the character data and then the foreground and background channels.

nccell_cols returns the number of columns occupied by the cell's character. This is typically 1 for most ASCII characters and can be 0, 2, or more for wide characters or combining characters. The behavior is based on the wcwidth(3) function. ncstrwidth and ncstrwidth_valid are equivalent functions for calculating the screen width of a UTF-8 encoded string.

nccell_extended_gcluster returns a non-zero value if the cell contains an extended grapheme cluster (i.e., a character that requires more than a single cell). This can happen with certain Unicode characters or sequences. If the cell contains a sprixel (a pixel-based graphic), this function returns 0. Note that calling this function on a sprixel is undefined behavior, and it is recommended to check if a cell is a sprixel first using ncvisual_implemented.

If a cell's foreground or background channel is set to palette-indexed mode, and the provided index is out of range (i.e., >= NCPALETTESIZE), the behavior is undefined. Verify palette indexing with nccell_fg_palindex or nccell_bg_palindex. A cell's foreground channel can be set to palette-indexed mode (and have the index set) with nccell_set_fg_palindex. The index must be less than NCPALETTESIZE. Replace fg with bg to operate on the background channel.

RETURN VALUES

nccell_load and similar functions return the number of bytes loaded from the EGC, or -1 on failure. They can fail due to either an invalid UTF-8 input, or the backing egcpool reaching its maximum size.

nccell_set_fg_rgb8 and similar functions will return -1 if provided invalid inputs, and 0 otherwise.

nccellcmp returns a negative integer, 0, or a positive integer if c1 is less than, equal to, or more than c2, respectively.

nccell_extended_gcluster returns NULL if called on a sprixel (see notcurses_visual(3).

nccell_cols returns the number of columns occupied by c, according to wcwidth(3)*. ncstrwidth is an equivalent for strings. ncstrwidth_valid returns the same value as ncstrwidth.

NOTES

cell was renamed to nccell in Notcurses 2.2.0, so as not to bleed such a common term into the (single, global) C namespace. cell will be retained as an alias until Notcurses 3.0. Likewise, many functions prefixed with cell have been renamed to start with nccell.
