NOMBRE

notmuch-insert - agregar un mensaje a la base de datos de maildir y notmuch

SINOPSIS

notmuch insert [opción ...] [+<etiqueta>|-<etiqueta> ...]

DESCRIPCIÓN

notmuch insert lee un mensaje de la entrada estándar y lo entrega en el directorio maildir dado por la opción de configuración database.mail_root, luego incorpora el mensaje a la base de datos de notmuch. Es una alternativa a usar una herramienta separada para entregar el mensaje y luego ejecutar notmuch-new después.

El nuevo mensaje se etiquetará con las etiquetas especificadas por la opción de configuración new.tags, y luego por las operaciones especificadas en la línea de comandos: las etiquetas precedidas por '+' se añaden mientras que las precedidas por '-' se eliminan.

Si el nuevo mensaje es un duplicado de un mensaje existente en la base de datos (tiene el mismo ID de mensaje), se agregará a la carpeta de maildir y a la base de datos de notmuch, pero las etiquetas no cambiarán.

El comando insert soporta hooks. Consulte notmuch-hooks para más detalles sobre los hooks.

Los argumentos de las opciones deben aparecer antes que cualquier argumento de operación de etiqueta. Las opciones compatibles para insert incluyen:

--carpeta=<carpeta>
Entrega el mensaje a la carpeta especificada, relativa al directorio principal dado por el valor de database.mail_root. El valor por defecto es la cadena vacía, lo que significa entregar en el directorio principal.
--crear-carpeta
Intenta crear la carpeta nombrada por la opción --carpeta, si no existe. De lo contrario, la carpeta debe existir para que la entrega de correo sea exitosa.
--mantener
Conserva el archivo del mensaje si la indexación falla, y conserva el mensaje indexado si falla la aplicación de etiquetas o la sincronización de banderas de maildir. Ignora estos errores y devuelve el estado de salida 0 para indicar una entrega de correo exitosa.
--no-hooks
Impide la ejecución de los hooks.
--legible-por-todos
Al escribir correo en el buzón, permite que sea leído por usuarios distintos del usuario actual. Tenga en cuenta que esto no anula la umask. Por defecto, el correo entregado solo es legible por el usuario actual.
--descifrar=(verdadero|nostash|automático|falso)
Si es verdadero y el mensaje está cifrado, intenta descifrar el mensaje durante la indexación, almacenando en caché las claves de sesión descubiertas. Si es automático, y notmuch ya conoce una clave de sesión para el mensaje, intentará descifrar usando esa clave de sesión pero no accederá a las claves secretas del usuario. Si el descifrado es exitoso, indexa el texto plano. En cualquier caso, el mensaje siempre se almacena en disco en su forma original (texto cifrado).

nostash es lo mismo que verdadero excepto que no almacenará en caché las claves de sesión recién descubiertas en la base de datos.

Tenga en cuenta que el índice probablemente sea suficiente (y una clave de sesión almacenada en caché es ciertamente suficiente) para reconstruir el texto plano del mensaje en sí, ¡así que asegúrese de que el índice de mensajes de notmuch esté adecuadamente protegido. NO USE --descifrar=verdadero o --descifrar=nostash sin considerar la seguridad de su índice.

Consulte también index.decrypt en notmuch-config.

CONFIGURACIÓN

La indexación está influenciada por las opciones de configuración index.decrypt y index.header.<prefijo>. El etiquetado se controla mediante las opciones new.tags y maildir.synchronize_flags. Consulte notmuch-config para obtener detalles.

ESTADO DE SALIDA

Este comando devuelve el estado de salida 0 en caso de entrega exitosa del correo, no cero en caso contrario. El valor predeterminado es indicar una entrega de correo fallida ante cualquier error, incluidos la entrega del archivo del mensaje al sistema de archivos, la indexación del mensaje en la base de datos de Notmuch, el cambio de etiquetas y la sincronización de etiquetas con las banderas de maildir. La opción --mantener puede usarse para aceptar una entrega exitosa del archivo del mensaje.

Este comando admite el siguiente código de estado de salida especial para errores que son muy probablemente de naturaleza temporal, por ejemplo, fallo al obtener un bloqueo de escritura de la base de datos.

75 (EX_TEMPFAIL)
Ocurrió un fallo temporal; se invita al usuario a intentarlo de nuevo.

El estado de salida del hook post-insert no afecta al estado de salida del comando insert.
