Se utilizarán los argumentos del sistema (sys.args).

[--archivo-osm ARCHIVO]
[--continuar {importar-desde-archivo,cargar-datos,indexacion,postproceso-db}]

Crea una nueva base de datos de Nominatim a partir de un archivo OSM.

Este subcomando configura una nueva base de datos de Nominatim desde cero, comenzando por crear una nueva base de datos en PostgreSQL. El usuario que ejecuta este comando necesita derechos de superusuario sobre la base de datos.

ARGUMENTOS PREDETERMINADOS 'nominatim importar'

Directorio base de la instalación de Nominatim (predeterminado: /var/lib/nominatim/)
-j NUM, --hilos NUM
Número de hilos paralelos a utilizar.

ARGUMENTOS REQUERIDOS 'nominatim importar'

--archivo-osm ARCHIVO
Archivo OSM a importar (repetir para importar múltiples archivos).
--continuar {importar-desde-archivo,cargar-datos,indexacion,postproceso-db}
Continuar una importación que fue interrumpida.

ARGUMENTOS OPCIONALES 'nominatim importar'

--cache-osm2pgsql TAMANO
Tamaño de la caché a ser utilizada por osm2pgsql (en MB).
--solo-reverso
No crear tablas ni índices para la búsqueda.
--sin-particiones
No particionar los índices de búsqueda (acelera la importación de extractos de países individuales).
--sin-actualizaciones
No mantener tablas que solo son necesarias para actualizar la base de datos posteriormente.
--offline
No intentar cargar ningún dato adicional de internet.

Continuar la importación incluso cuando hay errores en el SQL.
--index-sin-analisis
No realizar operaciones de análisis durante la indexación (solo para expertos).
--preparar-base-datos
Crear la base de datos pero no importar ningún dato.

COMANDO 'nominatim congelar'

uso: nominatim congelar [-h] [-q] [-v] [--directorio-proyecto DIR] [-j NUM]

Hace que la base de datos sea de solo lectura.

Aproximadamente la mitad de los datos en la base de datos de Nominatim se conservan solo para poder mantener los datos actualizados con los nuevos cambios realizados en OpenStreetMap. Este comando elimina todos estos datos y solo conserva la parte necesaria para la geocodificación en sí.

Este comando tiene el mismo efecto que la opción `--sin-actualizaciones` para las importaciones.

COMANDO 'nominatim estado'

uso: nominatim estado [-h] [-q] [-v] [--directorio-proyecto DIR] [-j NUM]

Muestra el estado de la base de datos de Nominatim.

ARGUMENTOS PREDETERMINADOS 'nominatim estado'

-q, --silencioso
Imprime solo mensajes de error.
-v, --verboso
Aumenta la verbosidad de la salida.
--directorio-proyecto DIR
Directorio base de la instalación de Nominatim (predeterminado: /var/lib/nominatim/)
-j NUM, --hilos NUM
Número de hilos paralelos a utilizar.
un servicio en línea que proporciona actualizaciones regulares (archivos diff de OSM) para el planeta o la actualización que proporcionan. El OSMF proporciona el servicio de replicación principal para el planeta completo en https://planet.osm.org/replication/ pero existen otros proveedores de extractos de datos de OSM que también brindan dicho servicio.

Este subcomando permite configurar dicho servicio de replicación y descargar e importar actualizaciones a intervalos regulares. Necesitas llamar a '--init' una vez para configurar el proceso o cada vez que cambies los parámetros de configuración de la replicación. Sin argumentos, el subcomando entrará en un bucle y aplicará continuamente las actualizaciones a medida que estén disponibles. Proporcionar `--once` solo descarga e importa el siguiente lote de actualizaciones.

ARGUMENTOS PREDETERMINADOS 'nominatim replication'

-q, --quiet
Imprimir solo mensajes de error
-v, --verbose
Aumentar el nivel de detalle de la salida
--project-dir DIR
Directorio base de la instalación de Nominatim (predeterminado: /var/lib/nominatim/)
-j NUM, --threads NUM
Número de hilos paralelos a utilizar

ARGUMENTOS PARA LA INICIALIZACIÓN 'nominatim replication'

--init
Inicializar el proceso de actualización
--no-update-functions
No actualizar la función de disparador para admitir actualizaciones diferenciales (EXPERTO)

ARGUMENTOS PARA LAS ACTUALIZACIONES 'nominatim replication'

--check-for-updates
Comprobar si hay nuevas actualizaciones disponibles y salir
--once
Descargar y aplicar actualizaciones solo una vez. Cuando no está configurado, las actualizaciones se aplican continuamente
--catch-up
Descargar y aplicar actualizaciones hasta que no haya más datos nuevos disponibles en el servidor
--no-index
No indexar los datos nuevos. Solo utilizable junto con --once
--osm2pgsql-cache SIZE
Tamaño de la caché a ser utilizada por osm2pgsql (en MB)

PARÁMETROS DE DESCARGA 'nominatim replication'

--socket-timeout SOCKET_TIMEOUT
Establecer el tiempo de espera para las descargas de archivos

uso: nominatim special-phrases [-h] [-q] [-v] [--project-dir DIR] [-j NUM]
[--import-from-wiki] [--import-from-csv FILE]
[--no-replace] [--min MIN]

Importar frases especiales.

Las frases especiales son términos de búsqueda que limitan el tipo de objeto que debe buscarse. Por ejemplo, podrías querer buscar en muchos idiomas, lo cual se puede importar con este comando.

También puedes proporcionar tus propias frases en un archivo CSV. El archivo necesita tener las siguientes cinco columnas:
* phrase - el término esperado para la búsqueda
* class - la clave de etiqueta OSM del tipo de objeto
* type - el valor de la etiqueta OSM del tipo de objeto
* operator - el tipo de búsqueda a realizar (uno de: in, near, name, -)
* plural - si el término es plural o no (S/N)

Se puede encontrar un archivo de ejemplo en las fuentes de Nominatim en

La importación se puede configurar adicionalmente para ignorar pares clave/valor específicos. Esto es particularmente útil al importar frases de la wiki. La configuración predeterminada excluye algunas etiquetas muy comunes como building=yes. La configuración se puede personalizar colocando un archivo `phrase-settings.json` con reglas personalizadas en el directorio del proyecto o utilizando la opción `--config` para apuntar a otro archivo de configuración.

COMANDO 'nominatim add-data'

--relation ID | --tiger-data DIR) [--use-main-api]
[--osm2pgsql-cache SIZE]
[--socket-timeout SOCKET_TIMEOUT]

Añadir datos adicionales desde un archivo o una fuente en línea.

Este comando permite añadir o actualizar los datos de búsqueda en la base de datos. Los datos pueden provenir de un archivo OSM o se pueden descargar objetos OSM individuales directamente desde la API de OSM. Esta función solo carga los datos en la base de datos. Después, aún deben integrarse en el índice de búsqueda. Utiliza el comando `nominatim index` para eso.

El comando también se puede usar para añadir datos externos que no sean de OSM a la base de datos. Actualmente, el único formato compatible son los datos de números de casa TIGER. Consulta la documentación en línea en https://nominatim.org/release-docs/latest/customize/Tiger/ para más información.

-j NUM, --threads NUM
Número de hilos paralelos a utilizar

FUENTE 'nominatim add-data'

Importar datos desde un archivo OSM o archivo diff
--diff FILE
Importar datos desde un archivo diff de OSM (obsoleto: usa --file)

Importar un nodo individual desde la API
--way ID
Importar una vía individual desde la API

Importar una relación individual desde la API
--tiger-data DIR
Añadir números de casa de la base de datos del censo TIGER de EE. UU.

Tamaño de la caché a ser utilizada por osm2pgsql (en MB)

Establecer el tiempo de espera para las descargas de archivos

COMANDO 'nominatim index'

[--boundaries-only] [--no-boundaries] [--minrank RANK]
[--maxrank RANK]

Reindexar todos los datos nuevos y modificados.

La indexación es el proceso de calcular las direcciones y los términos de búsqueda para los lugares en la base de datos. Cada vez que se añaden o modifican datos, la indexación debe ejecutarse. Las importaciones y las actualizaciones de replicación se encargan automáticamente de la indexación. Para otros casos, esta función permite ejecutar la indexación manualmente.
