NOMBRE

notmuch-dump - crea una exportación en texto plano de las etiquetas de cada mensaje

SINOPSIS

notmuch dump [--gzip] [--format=(batch-tag|sup)] [--output=<archivo>] [--] [<término-de-búsqueda> ...]

DESCRIPCIÓN

Exporta las etiquetas para los mensajes que coinciden con los términos de búsqueda dados.

La salida se dirige al archivo especificado, si existe, o a la salida estándar.

Estas etiquetas son los únicos datos en la base de datos de notmuch que no se pueden recrear a partir de los propios mensajes. La salida de notmuch dump es por lo tanto lo único crítico de respaldar (y mucho más amigable para copias de seguridad incrementales que los archivos nativos de la base de datos.)

Ver notmuch-search-terms para detalles de la sintaxis soportada para <términos-de-búsqueda>. Sin términos de búsqueda, se generará una exportación de todos los mensajes en la base de datos. Un argumento -- instruye a notmuch a que los argumentos restantes son términos de búsqueda.

Las opciones soportadas para dump incluyen:

--gzip
Comprime la salida en un formato compatible con gzip(1).
--format=(sup|batch-tag)
notmuch restore soporta dos formatos de exportación en texto plano, ambos con un id de mensaje por línea, seguido de una lista de etiquetas.
batch-tag
El formato de exportación predeterminado batch-tag está diseñado para ser más robusto frente a ids de mensaje mal formados y etiquetas que contienen espacios en blanco o caracteres no ascii(7). Cada línea tiene el formato:
+<*etiqueta-codificada*\ > +<*etiqueta-codificada*\ > ... -- id:<*id-de-mensaje-entrecomillado*\ >

Las etiquetas se codifican en hexadecimal reemplazando cada byte que no coincide con la expresión regular [A-Za-z0-9@=.,_+-] con %nn donde nn es la codificación hexadecimal de dos dígitos. El ID del mensaje es una consulta Xapian válida, entrecomillada usando las reglas de comillas de términos booleanos de Xapian: si el ID contiene espacios en blanco o un paréntesis de cierre o comienza con una comilla doble, debe estar entre comillas dobles y las comillas dobles dentro del ID deben duplicarse. El lector atento notará que este es un caso especial del formato de entrada por lotes para notmuch-tag; tenga en cuenta que la consulta de un solo ID de mensaje es obligatoria para notmuch-restore.

sup
El formato de archivo de exportación sup está elegido específicamente para ser compatible con el formato de los archivos producidos por sup-dump(1). Por lo tanto, si anteriormente ha estado usando sup para correo, entonces el comando notmuch-restore le proporciona una forma de importar todas sus etiquetas (o etiquetas como las llama sup). Cada línea tiene el siguiente formato:
<*id-de-mensaje*\ > **(** <*etiqueta*\ > ... **)**

con cero o más etiquetas separadas por espacios. Tenga en cuenta que los IDs de mensaje (malformados) pueden contener caracteres arbitrarios distintos de nulo. Tenga en cuenta también que las etiquetas con espacios no se restaurarán correctamente con este formato.

--include=(config|properties|tags)
Controla qué tipo de metadatos se incluyen en la salida.
config
Exporta los datos de configuración almacenados en la base de datos. Cada línea comienza con "#@ ", seguido de un par clave-valor separado por espacios. Tanto la clave como el valor se codifican en hexadecimal si es necesario.
properties
Exporta metadatos (clave, valor) por mensaje. Cada línea comienza con "#= ", seguido de un ID de mensaje y una lista de pares clave=valor separados por espacios. Los IDs, claves y valores se codifican en hexadecimal si es necesario. Ver notmuch-properties para más detalles.
tags
Exporta metadatos booleanos por mensaje, es decir, etiquetas. Ver format arriba para la descripción de la salida.

El valor predeterminado es incluir todos los tipos de datos disponibles. La opción se puede especificar varias veces para seleccionar un subconjunto. A partir de la versión 3 del formato de exportación, hay una línea de encabezado con el siguiente formato:

#notmuch-dump <*formato*>:<*versión*> <*incluido*>

donde <incluido> es una lista separada por comas de las opciones anteriores.

--output=<nombre-de-archivo>
Escribe la salida en el archivo dado en lugar de stdout.
