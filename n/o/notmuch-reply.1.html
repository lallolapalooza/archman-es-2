NOMBRE

notmuch-reply - construye una plantilla de respuesta para un conjunto de mensajes

SINOPSIS

notmuch reply [opción ...] <término-de-búsqueda> ...

DESCRIPCIÓN

Construye una plantilla de respuesta para un conjunto de mensajes.

Para facilitar la respuesta al correo electrónico, notmuch reply toma un conjunto existente de mensajes y construye una plantilla de correo adecuada. Su dirección A: se establece de acuerdo con el correo electrónico original de la siguiente manera: si la cabecera Reply-to: está presente y es diferente de cualquier dirección A:/Cc: existente, se utiliza; de lo contrario, se usa la cabecera De:. A menos que se especifique --reply-to=sender, los valores de las cabeceras A: y Cc: se copian, pero sin incluir ninguna de las direcciones de correo electrónico del usuario actual (tal como se configuran en primary_mail u other_email en el archivo .notmuch-config) en la lista de destinatarios.

También construye un asunto nuevo adecuado, incluyendo Re: al principio (si no está ya presente), y añadiendo los IDs de mensaje de los mensajes a los que se responde a la lista References y estableciendo correctamente el campo In-Reply-To:.

Finalmente, el contenido original de los correos electrónicos se cita precediendo cada línea con '> ' y se incluye en el cuerpo.

El resultado de la plantilla de mensaje se muestra en la salida estándar.

Las opciones admitidas para reply incluyen

--duplicate=N
Responder al duplicado número N. La numeración comienza en 1 y coincide con el orden utilizado por show --duplicate y search --output=files.
--format=(default|json|sexp|headers-only)
default
Incluye el asunto y el cuerpo del mensaje citado como un mensaje RFC 2822.
json
Produce una salida JSON que contiene las cabeceras de un mensaje de respuesta y el contenido del mensaje original. Esta salida puede ser utilizada por un cliente para crear un mensaje de respuesta de forma inteligente.
sexp
Produce una salida S-Expression que contiene las cabeceras de un mensaje de respuesta y el contenido del mensaje original. Esta salida puede ser utilizada por un cliente para crear un mensaje de respuesta de forma inteligente.
headers-only
Solo produce cabeceras In-Reply-To, References, To, Cc y Bcc.
--format-version=N
Utiliza la versión especificada del formato de salida estructurada. Esto está pensado para programas que invocan notmuch internamente. Si se omite, se utilizará la última versión compatible.
--reply-to=(all|sender)
all (predeterminado)
Responde a todas las direcciones.
sender
Responde solo al remitente. Si se responde al propio mensaje del usuario (la cabecera Reply-to: o De: es una de las direcciones de correo electrónico configuradas del usuario), intenta las cabeceras A:, Cc:, y Cco: en ese orden, y copia los valores del primer campo que contenga algo distinto de solo las direcciones del usuario.
--decrypt=(false|auto|true)
Si es true, descifra cualquier parte cifrada MIME encontrada en el contenido seleccionado (es decir, partes "multipart/encrypted"). Se informará del estado del descifrado (actualmente solo compatible con --format=json y --format=sexp), y en caso de descifrado exitoso, la parte multipart/encrypted será reemplazada por el contenido descifrado.

Si es auto, y ya se conoce una clave de sesión para el mensaje, entonces se descifrará, pero notmuch no intentará acceder a las claves secretas del usuario.

Use false para evitar incluso el descifrado automático.

Predeterminado: auto

Consulte notmuch-search-terms para obtener detalles sobre la sintaxis admitida para <search-terms>.

Nota: Lo más común es usar notmuch reply con una cadena de búsqueda que coincida con un solo mensaje (como id:<message-id>), pero puede ser útil responder a varios mensajes a la vez. Por ejemplo, cuando una serie de parches se envían en un solo hilo, responder a todo el hilo permite que la respuesta comente los problemas encontrados en varios parches. El formato predeterminado admite responder a varios mensajes a la vez, pero los formatos JSON y S-Expression no.

ESTADO DE SALIDA

Este comando admite los siguientes códigos de estado de salida especiales

20
La versión del formato solicitada es demasiado antigua.
21
La versión del formato solicitada es demasiado nueva.
