NOSETESTS(1) nose NOSETESTS(1)

NOMBRE

nosetests - Pruebas más amigables para Python

PRUEBAS MÁS AMIGABLES PARA PYTHON

SINOPSIS

nosetests [opciones] [nombres]

DESCRIPCIÓN

nose recopila automáticamente pruebas de archivos fuente de Python, directorios y paquetes encontrados en su directorio de trabajo (que por defecto es el directorio de trabajo actual). Cualquier archivo fuente de Python, directorio o paquete que coincida con la expresión regular testMatch (por defecto: (?:^|[b_.-])[Tt]est) será recopilado como una prueba (o fuente para la recopilación de pruebas). Además, todos los demás paquetes encontrados en el directorio de trabajo serán examinados en busca de archivos fuente de Python o directorios que coincidan con testMatch. El descubrimiento de paquetes desciende hasta el final del árbol, por lo que package.tests, package.sub.tests y package.sub.sub2.tests serán todos recopilados.

Dentro de un directorio o paquete de pruebas, cualquier archivo fuente de Python que coincida con testMatch será examinado en busca de casos de prueba. Dentro de un módulo de prueba, las funciones y clases cuyos nombres coincidan con testMatch y las subclases de TestCase con cualquier nombre se cargarán y ejecutarán como pruebas. Las pruebas pueden usar la palabra clave assert o lanzar AssertionErrors para indicar fallos en la prueba. Las subclases de TestCase pueden hacer lo mismo o usar los varios métodos de TestCase disponibles.

Es importante tener en cuenta que el comportamiento por defecto de nose es no incluir pruebas de archivos ejecutables. Para incluir pruebas de tales archivos, elimine su bit de ejecución o use la bandera --exe (ver la sección 'Opciones' más abajo).

Seleccionar Pruebas

Para especificar qué pruebas ejecutar, pase los nombres de las pruebas en la línea de comandos:

nosetests only_test_this.py

Los nombres de pruebas especificados pueden ser nombres de archivos o módulos, y opcionalmente pueden indicar el caso de prueba a ejecutar separando el nombre del módulo o archivo del nombre del caso de prueba con dos puntos. Los nombres de archivo pueden ser relativos o absolutos. Ejemplos:

nosetests test.module
nosetests another.test:TestCase.test_method
nosetests a.test:TestCase
nosetests /ruta/a/archivo/de/prueba.py:test_function

También puede cambiar el directorio de trabajo donde nose busca pruebas usando el interruptor -w:

nosetests -w /ruta/a/las/pruebas

Tenga en cuenta, sin embargo, que el soporte para múltiples argumentos -w ahora está obsoleto y se eliminará en una versión futura. A partir de nose 0.10, puede obtener el mismo comportamiento especificando los directorios de destino sin el interruptor -w:

nosetests /ruta/a/las/pruebas /otra/ruta/a/las/pruebas

Una mayor personalización de la selección y carga de pruebas es posible mediante el uso de plugins.

La salida de resultados de pruebas es idéntica a la de unittest, excepto por las características adicionales (clases de error y características proporcionadas por plugins como captura de salida e introspección de assert) detalladas en las opciones a continuación.

Configuración

Además de pasar opciones de línea de comandos, también puede colocar opciones de configuración en el archivo setup.cfg de su proyecto, o en un archivo .noserc o nose.cfg en su directorio de inicio. En cualquiera de estos archivos de configuración de estilo ini estándar, coloca su configuración de nosetests en una sección [nosetests]. Las opciones son las mismas que en la línea de comandos, con el prefijo -- eliminado. Para opciones que son interruptores simples, debe proporcionar un valor:

[nosetests]
verbosity=3
with-doctest=1

Todos los archivos de configuración que se encuentren serán cargados y sus opciones combinadas. Puede anular la carga estándar de archivos de configuración con la opción -c.

Usando Plugins

Hay numerosos plugins de nose disponibles a través de easy_install y en otros lugares. Para usar un plugin, simplemente instálelo. El plugin agregará opciones de línea de comandos a nosetests. Para verificar que el plugin está instalado, ejecute:

nosetests --plugins

Puede agregar -v o -vv a ese comando para mostrar más información sobre cada plugin.

Si está ejecutando nose.main() o nose.run() desde un script, puede especificar una lista de plugins a usar pasando una lista de plugins con el argumento de palabra clave plugins.

Plugins 0.9

nose 1.0 puede usar ALGUNOS plugins que fueron escritos para nose 0.9. El administrador de plugins por defecto inserta un envoltorio de compatibilidad alrededor de los plugins 0.9 que adapta las llamadas a la API de plugins modificadas. Sin embargo, los plugins que acceden a los internos de nose probablemente fallarán, especialmente si intentan acceder a clases de casos de prueba o suites de pruebas. Por ejemplo, los plugins que intentan determinar si una prueba pasada a startTest es una prueba individual o una suite fallarán, en parte porque las suites ya no se pasan a startTest y en parte porque es probable que el plugin intente averiguar si la prueba es una instancia de una clase que ya no existe.

Plugins 0.10 y 0.11

Todos los plugins escritos para nose 0.10 y 0.11 deberían funcionar con nose 1.0.
