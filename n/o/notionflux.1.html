NOMBRE

notionflux — Control remoto Lua para notion

SINOPSIS

notionflux [-R | -e código-lua | archivo]

DESCRIPCIÓN

notionflux es una herramienta para enviar scripts al motor de scripting Lua dentro del gestor de ventanas notion(1). El script puede así acceder a la API interna de Lua de notion.

Hay dos modos de operación, interactivo y por lotes. El modo interactivo se habilita ejecutando notionflux con su entrada estándar conectada a una terminal y sin pasar ninguna opción de línea de comandos.

De lo contrario, se habilita el modo por lotes:

-R
Forzar el modo por lotes incluso si la entrada estándar está conectada a una terminal. El código Lua se lee desde la entrada estándar hasta que se alcanza el fin de archivo, se envía a notion para su procesamiento, y el resultado se lee y se muestra.
-e código
Casi igual que lo anterior, excepto que en lugar de leer desde la entrada estándar, el parámetro de línea de comandos código se envía para su procesamiento.
archivo
Se evalúa el contenido del archivo.

MODO INTERACTIVO

Este modo es similar a ejecutar una shell interactiva de lua(1). Hay autocompletado con tabulación para la API Lua de notion, así como edición de línea.

El código que se ha introducido se evalúa por notion tan pronto como es una sentencia Lua completa. El resultado se muestra después de lo cual se puede introducir la siguiente sentencia.

ENTORNO

DISPLAY
La variable de entorno DISPLAY debe estar configurada en un servidor X que ejecute notion para que notionflux pueda obtener la ruta del socket.

SEGURIDAD

notionflux se conecta a notion(1) a través de un socket de dominio Unix. Este socket se crea con permisos de lectura/escritura solo para el usuario que inició notion. La ruta del socket se puede consultar con el siguiente comando:

$ xprop -root _NOTION_MOD_NOTIONFLUX_SOCKET
_NOTION_MOD_NOTIONFLUX_SOCKET(STRING) = "/tmp/fileuj6onu"

EJEMPLOS

El comando

$ notionflux -e "return notioncore.current():name()"
"emacs: notionflux.1"

mostrará el título de la ventana actualmente enfocada, mientras que

$ notionflux -e "print(notioncore.current():name())"
"emacs: notionflux.1"
nil

recopilará los mensajes y los imprimirá antes de regresar. Para escribir en la salida estándar de notion (normalmente ~/.xsession-errors), como solía hacer print en versiones anteriores de notionflux, utilice

$ notionflux -e 'io.stdout:write("hola .xsession-errors!\n")'
nil

Usando redirección de entrada:

$ echo "return notioncore.current()" | notionflux
WClientWin: 0x9bb6b8

Usando el modo interactivo:

$ notionflux
lua> notioncore.current():rootwin_of()
WRootWin: 0x8c9688
lua> do
...>   local x = 42 -- Lua usa el ámbito global por defecto, no ensucies
...>   return x
...> end
42
lua> ^D

En cualquier respuesta de mod_notionflux, las cadenas se citan de una manera que se puede pegar directamente de nuevo en un intérprete de Lua para obtener la misma cadena, mientras que otros tipos se convierten a su representación de cadena usando tostring(). Por eso hay comillas alrededor de la respuesta en el primer ejemplo donde nil (que es el valor de retorno de un bloque que no tiene una declaración de retorno) no las tiene.

HISTORIA

Un comando ionflux apareció en ion3 alrededor de 2004. Fue adaptado a notion por el equipo de desarrollo de notion cuando notion se bifurcó de ion3 en 2010.

AUTORES

notionflux fue reescrito en 2019 por El equipo de desarrollo de Notion bajo la licencia GNU GPL para añadir el modo interactivo.

ERRORES

Actualmente, el script debe tener 4095 bytes o menos. Si necesita más, considere pasar un nombre de archivo, que se pasa a notion para su evaluación y, por lo tanto, evita este límite.
