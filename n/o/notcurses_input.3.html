NOMBRE

notcurses_input - entrada a través de notcurses

SINOPSIS

#include <notcurses/notcurses.h>

struct timespec;
struct notcurses;
typedef enum {
  NCTYPE_UNKNOWN,
  NCTYPE_PRESS,
  NCTYPE_REPEAT,
  NCTYPE_RELEASE,
} ncintype_e;
// Un evento de entrada. Las coordenadas de celda actualmente solo se definen para
// eventos del ratón. No se garantiza que podamos establecer los modificadores para una
// ncinput dada. Abarcamos puntos de código Unicode individuales, no EGC completos.
// FIXME para abi4, combinar los booleanos en |modifiers|
typedef struct ncinput {
  uint32_t id;       // Punto de código Unicode o evento NCKEY sintetizado
  int y, x;          // Coordenada y/x de celda del evento, -1 para indefinido
  char utf8[5];      // Representación utf8, si existe
  // OBSOLETO ¡no usar! desaparecerá en la versión 4.0
  bool alt;          // ¿se mantuvo pulsada la tecla Alt?
  bool shift;        // ¿se mantuvo pulsada la tecla Shift?
  bool ctrl;         // ¿se mantuvo pulsada la tecla Ctrl?
  // FIN DE OBSOLESCENCIA
  ncintype_e evtype;
  unsigned modifiers;// máscara de bits sobre NCKEY_MOD_*
  int ypx, xpx;      // desplazamientos de píxeles dentro de la celda, -1 para indefinido
  uint32_t eff_text[5];  // Representación utf32 efectiva, teniendo en cuenta las teclas
                     // modificadoras. Esto pueden ser múltiples puntos de código.
                     // El array está terminado con cero.
} ncinput;
#define NCMICE_NO_EVENTS     0
#define NCMICE_MOVE_EVENT    0x1
#define NCMICE_BUTTON_EVENT  0x2
#define NCMICE_DRAG_EVENT    0x4
#define NCMICE_ALL_EVENTS    0x7

bool nckey_mouse_p(uint32_t r);

bool ncinput_nomod_p(const ncinput* ni);

uint32_t notcurses_get(struct notcurses* n, const struct timespec* ts, ncinput* ni);

int notcurses_getvec(struct notcurses* n, const struct timespec* ts, ncinput* ni, int vcount);

uint32_t notcurses_get_nblock(struct notcurses* n, ncinput* ni);

uint32_t notcurses_get_blocking(struct notcurses* n, ncinput* ni);

int notcurses_mice_enable(struct notcurses* n, unsigned eventmask);

int notcurses_mice_disable(struct notcurses* n);

int notcurses_inputready_fd(struct notcurses* n);

static inline bool ncinput_equal_p(const ncinput* n1, const ncinput* n2);

int notcurses_linesigs_disable(struct notcurses* n);

int notcurses_linesigs_enable(struct notcurses* n);

bool ncinput_shift_p(const struct ncinput* n);

bool ncinput_ctrl_p(const struct ncinput* n);

bool ncinput_alt_p(const struct ncinput* n);

bool ncinput_meta_p(const struct ncinput* n);

bool ncinput_super_p(const struct ncinput* n);

bool ncinput_hyper_p(const struct ncinput* n);

DESCRIPCIÓN

notcurses soporta la entrada desde teclados y ratones, y cualquier dispositivo que se les parezca. El soporte de ratón requiere un intermediario como GPM, Wayland o Xorg, y debe habilitarse explícitamente a través de notcurses_mice_enable. Se soporta el rango completo de 32 bits de Unicode (ver unicode(7)), con eventos sintetizados mapeados por encima de los 1.114.112 puntos de código de los diecisiete Planos de Unicode 14.0. Los caracteres Unicode se devuelven directamente como UCS-32, un punto de código a la vez. Cuando la entrada tiene una representación UTF8, se escribe en utf8; este campo siempre está terminado en NUL.

notcurses toma su entrada de teclado de stdin, que se pondrá en modo no bloqueante durante la operación. La terminal se pone en modo no canónico (ver termios(3)), y por lo tanto las teclas se reciben sin buffer de línea. notcurses mantiene su propio buffer de caracteres de entrada, que intentará llenar cada vez que lea.

notcurses_get permite especificar un struct timespec como tiempo de espera. Si ts es NULL, notcurses_get se bloqueará hasta que lea entrada, o sea interrumpido por una señal. Si sus valores son ceros, no habrá bloqueo. De lo contrario, ts especifica un tiempo absoluto límite (tomado contra CLOCK_MONOTONIC; ver clock_gettime(2)). Al expirar el tiempo de espera, se devuelve 0. Los detalles del evento se informarán en ni, a menos que ni sea NULL.

notcurses_inputready_fd proporciona un descriptor de archivo adecuado para su uso con multiplexores de E/S como poll(2). Este descriptor de archivo puede o no ser el descriptor de archivo de entrada real. Si es legible, se puede llamar a notcurses_get sin posibilidad de bloqueo.

ncinput_equal_p compara dos estructuras ncinput para igualdad de datos (es decir, sin considerar el padding), devolviendo true si representan la misma entrada (aunque no necesariamente el mismo evento de entrada). Tenga en cuenta que NCTYPE_UNKNOWN y NCTYPE_PRESS se consideran equivalentes a efectos de ncinput_equal_p.

notcurses_linesigs_disable deshabilita la conversión de entradas INTR, QUIT, SUSP y DSUSP en SIGINT, SIGQUIT y SIGTSTP. Estas conversiones están habilitadas por defecto. notcurses_linesigs_enable deshace esta acción, pero las señales intermedias se pierden permanentemente.

ncinput_shift_p, ncinput_ctrl_p, ncinput_alt_p y ncinput_meta_p prueban n para ver si el modificador relevante está establecido. Esto es preferible a acceder directamente a los miembros de la estructura.

Ratones

Para los eventos del ratón, se establecen los campos adicionales y, x, ypx y xpx. Estos campos no son significativos para los eventos de pulsación de teclas. Los eventos del ratón se pueden distinguir utilizando el predicado nckey_mouse_p. NCMICE_MOVE_EVENT solicita eventos cada vez que el ratón se mueve sin botones pulsados. NCMICE_DRAG_EVENT solicita eventos cuando el ratón se mueve con botones pulsados. NCMICE_BUTTON_EVENT solicita eventos cuando el estado del botón cambia. NCMICE_ALL_EVENTS se proporciona por conveniencia y para la preparación ante cambios futuros en la API (aunque no en la ABI).

Pulsaciones de teclas sintetizadas

Muchas teclas no tienen una representación Unicode, y mucho menos ASCII. Ejemplos incluyen las teclas modificadoras (Alt, Meta, etc.), las teclas de "función" y las teclas de flecha del teclado numérico. Las teclas especiales disponibles para la terminal se definen en la entrada terminfo(5), que notcurses carga al inicio. Al recibir un código de escape que coincide con una capacidad de entrada de terminfo, notcurses sintetiza un valor especial. Una secuencia de escape debe llegar en su totalidad a notcurses; quedarse sin entrada en medio de una secuencia de escape hará que esta sea rechazada. Asimismo, cualquier error al procesar una secuencia de escape hará que el análisis léxico se interrumpa, y la secuencia hasta el momento se reproducirá como pulsaciones de teclas literales independientes.

La lista completa de teclas sintetizadas (hay bastante más de cien) se puede encontrar en <notcurses/notcurses.h>. Para más detalles, consulte terminfo(5).

NCKEY_RESIZE

A menos que se haya inhibido el manejador de SIGWINCH (ver notcurses_init), Notcurses capturará automáticamente los redimensionamientos de pantalla y sintetizará un evento NCKEY_RESIZE. Al recibir este evento, el usuario puede llamar a notcurses_refresh para forzar un reajuste inmediato, o simplemente esperar a la próxima llamada a notcurses_render, momento en el cual notcurses captará el redimensionamiento por sí mismo. Si se inhibe el manejador de SIGWINCH, nunca se genera NCKEY_RESIZE.

NCKEY_SIGNAL

A menos que se haya inhibido el manejador de SIGWINCH (ver notcurses_init), Notcurses capturará SIGCONT

b>, y sintetizar un evento NCKEY_SIGNAL. Esto típicamente indica que el programa ha sido reiniciado después de ser pausado o enviado al segundo plano. La siguiente rasterización será una reconstrucción completa de la pantalla, como si se hubiera llamado a notcurses_refresh; el usuario podría desear llamar a notcurses_refresh inmediatamente por sí mismo.

NCKEY_EOF

Al llegar al final de la entrada, se devolverá NCKEY_EOF. En este punto, cualquier llamada posterior devolverá inmediatamente NCKEY_EOF. Tenga en cuenta que esto no resulta necesariamente de presionar, por ejemplo, Ctrl+D.

VALORES DE RETORNO

En caso de error, la familia de funciones get devuelve (uint32_t)-1. La causa del error puede determinarse usando errno(3). A menos que el error sea temporal (especialmente, por ejemplo, EINTR), es probable que notcurses_get no se pueda llamar de forma útil inmediatamente. En caso de tiempo de espera agotado, se devuelve 0. De lo contrario, se devuelve el valor UCS-32 de un punto de código Unicode, o un evento sintetizado.

Si se encuentra un error antes de que notcurses_getvec haya leído alguna entrada, devolverá -1. Si se agota el tiempo de espera antes de leer alguna entrada, devolverá 0. De lo contrario, devuelve el número de objetos ncinput escritos.

notcurses_mice_enable devuelve 0 en caso de éxito y un valor distinto de cero en caso de fallo, al igual que notcurses_mice_disable. El éxito no significa necesariamente que haya un ratón disponible ni que se generarán todos los eventos solicitados.

ncinput_equal_p devuelve true si las dos estructuras ncinput representan la misma entrada (aunque no necesariamente el mismo evento de entrada), y false en caso contrario.

NOTAS

Al igual que cualquier otra función de notcurses, es un error llamar a notcurses_get durante o después de una llamada a notcurses_stop. Si un hilo siempre está esperando entrada bloqueante, puede ser complicado garantizar que esto no suceda.

Solo un hilo puede acceder a la pila de entrada a la vez, pero a diferencia de casi todas las demás funciones de notcurses, notcurses_get y sus similares pueden llamarse simultáneamente con notcurses_render.

No utilice simplemente poll en el descriptor de archivo asociado con stdin para probar la disponibilidad de entrada. En su lugar, utilice el descriptor de archivo devuelto por notcurses_inputready_fd para garantizar la compatibilidad con versiones futuras de Notcurses (es posible que las versiones futuras procesen la entrada en sus propios contextos).

La lista completa de eventos sintetizados está disponible en <notcurses/nckeys.h>.

En la API4, los varios campos de modificadores bool desaparecerán y estos estados se fusionarán en la máscara de bits modifiers. Se recomienda utilizar ncinput_shift_p y similares para que su código sea compatible con el futuro.

ERRORES

Notcurses intenta utilizar los protocolos XTMODKEYS y Kitty de desambiguación de teclado. Cuando se admiten, eliminan la mayoría de estos problemas.

La tecla Mayús se indica tradicionalmente de forma no explícita junto con el texto Unicode típico. Si, por ejemplo, se utiliza Mayús para generar una letra mayúscula 'A', id será igual a 'A' y shift será false. Del mismo modo, cuando se presiona Ctrl junto con una letra, la letra se informará actualmente siempre en su forma mayúscula. Por ejemplo, si se presionan Mayús, Ctrl y 'a', esto es indistinguible de Ctrl y 'A'.

Ctrl presionado junto con 'J' o 'M', ya sea que se presione Mayús o no, actualmente se registra como NCKEY_ENTER. Esto probablemente cambiará en el futuro.

Cuando se utiliza el protocolo de desambiguación de teclado Kitty, la mayoría de estos problemas se resuelven. Puede determinar si el protocolo está en uso examinando la salida de notcurses-info(1). Si se indica la propiedad kbd, está utilizando el protocolo Kitty.

Tenga en cuenta que eff_text siempre devolverá el valor de texto efectivo de la tecla, teniendo en cuenta cualquier tecla meta presionada. (Por lo tanto, shift-a siempre devolverá 'A' en este campo, independientemente de si se utiliza el protocolo de desambiguación de teclado Kitty). Sin embargo, este campo generalmente solo se puede confiar en eventos NCTYPE_PRESS y NCTYPE_REPEAT. Tenga en cuenta también que este es un array (terminado en cero) ya que puede devolver varios puntos de código.

Los eventos del ratón en los márgenes izquierdos nunca se entregarán a la aplicación (como es la intención), pero los eventos del ratón en los márgenes inferiores y derechos a veces pueden serlo si el evento ocurre antes de un redimensionamiento de la ventana.

Los campos ypx y xpx actualmente nunca son válidos (es decir, siempre son -1). Esto debería corregirse en el futuro utilizando el protocolo de ratón SGR PixelMode.

En algunos sistemas operativos, CLOCK_REALTIME se utiliza como base para los tiempos de espera en lugar de CLOCK_MONOTONIC. Esto debería corregirse.
