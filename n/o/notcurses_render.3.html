notcurses_render(3) Manual de funciones de biblioteca notcurses_render(3)

NOMBRE

notcurses_render - sincronizar la pantalla física con una pila virtual

SINOPSIS

#include <notcurses/notcurses.h>

int ncpile_render(struct ncplane* n);

int ncpile_rasterize(struct ncplane* n);

int notcurses_render(struct notcurses* nc);

char* notcurses_at_yx(struct notcurses* nc, unsigned yoff, unsigned xoff, uint16_t* styles, uint64_t* channels);

int ncpile_render_to_file(struct ncplane* p, FILE* fp);

int ncpile_render_to_buffer(struct ncplane* p, char** buf, size_t* buflen);

DESCRIPCIÓN

Renderizar reduce una pila de ncplanes a un único plano, procediendo de arriba hacia abajo a lo largo del eje z de la pila. El resultado es una matriz de nccells (ver notcurses_cell). Rasterizar toma esta matriz, junto con el estado actual del área visual, y produce un flujo de secuencias de control optimizadas y EGCs para la terminal. Al escribir este flujo en la terminal, la pantalla física se sincroniza con algunas de las pilas de planos.

ncpile_render realiza la primera de estas tareas para la pila de la que n forma parte. La salida se mantiene internamente; llamar a ncpile_render de nuevo en la misma pila reemplazará este estado con una nueva renderización. Múltiples pilas pueden ser renderizadas concurrentemente. ncpile_rasterize realiza la rasterización y escribe el resultado en la terminal. Es una llamada bloqueante, y solo una operación de rasterización puede proceder a la vez. notcurses_render llama a ncpile_render y ncpile_rasterize en el plano estándar, para compatibilidad con versiones anteriores. Es una llamada bloqueante exclusiva.

Es necesario llamar a ncpile_rasterize o notcurses_render para generar cualquier salida visible; las diversas llamadas de notcurses_output(3) solo dibujan en los ncplanes virtuales. La mayoría de las estadísticas de notcurses se actualizan como resultado de una renderización (ver notcurses_stats(3)), y la geometría de la pantalla se refresca (similar a notcurses_refresh(3)) después de la renderización.

Mientras se llama a notcurses_render, no debe llamar a ninguna otra función que modifique la misma pila. Otras pilas pueden ser accedidas y modificadas libremente. La pila que se está renderizando puede ser accedida, pero no modificada.

ncpile_render_to_buffer realiza los procesos de render y raster de ncpile_render y ncpile_rasterize, pero no escribe el buffer resultante en la terminal. El usuario es responsable de escribir el buffer en la terminal en su totalidad. Si hay un error, los fotogramas subsiguientes estarán fuera de sincronización, y se debe llamar a notcurses_refresh(3).

Una operación de renderización consta de dos fases lógicas: la generación de la escena renderizada y el blitting de esta escena a la terminal (estas dos fases podrían de hecho intercalarse, transmitiendo la salida a medida que se renderiza). La generación del fotograma requiere la determinación de un cluster de grafemas extendido, color de primer plano, color de fondo y estilo para cada celda de la terminal física. La escritura de la escena requiere la síntesis de un conjunto de caracteres codificados en UTF-8 y códigos de escape apropiados para la terminal (confiando en terminfo(5)), y la escritura de esta secuencia al FILE de salida.

Cada celda puede ser renderizada de forma aislada, aunque la síntesis del flujo conlleva dependencias entre celdas.

Algoritmo de renderización de celdas

Recordemos que existe un orden total en los N ncplanes, y que el plano estándar siempre existe, con geometría igual a la pantalla física. Cada celda de la pantalla física es así intersectada por un subconjunto totalmente ordenado de planos P0, P1...Pi, donde 0 < i ≤ N. En cada celda, la renderización comienza en el plano intersecante superior P0. El algoritmo desciende hasta que:

•
ha bloqueado un cluster de grafemas extendido, y colores de primer plano/fondo, o
•
se han examinado todos los i planos

En cada plano P, consideramos una celda C. Esta celda es la celda intersecante, a menos que esa celda no tenga EGC. En ese caso, C es la celda predeterminada del plano.

•
Si aún no hemos determinado un EGC, y C tiene un EGC distinto de cero, utilizamos el EGC y el estilo de C.
•
Si aún no hemos bloqueado un color de primer plano, y C no es transparente al primer plano, utilizamos el color de primer plano de C (ver BUGS abajo). Si C es NCALPHA_OPAQUE, bloqueamos el color.
•
Si aún no hemos bloqueado un color de fondo, y C no es transparente al fondo, utilizamos el color de fondo de C (ver BUGS abajo). Si C es NCALPHA_OPAQUE, bloqueamos el color.

Si el algoritmo concluye sin un EGC, la celda se renderiza sin glifo y con un fondo predeterminado. Si el algoritmo concluye sin un color bloqueado, se utiliza el color tal como se ha calculado hasta ahora.

notcurses_at_yx recupera una celda *tal como se ha renderizado*. El EGC de esa celda se copia y se devuelve; debe ser liberado con free(3) por el llamador. Si la celda es una columna secundaria de un glifo ancho, aún así se devuelve el glifo.

VALORES DE RETORNO

En caso de éxito, se devuelve 0. En caso de error, se devuelve un valor distinto de cero. Un éxito dará como resultado el incremento de la estadística renders en 1. Un error dará como resultado el incremento de la estadística failed_renders en 1.

notcurses_at_yx devuelve una copia asignada en heap del EGC de la celda en caso de éxito, y NULL en caso de error.

ERRORES CONOCIDOS

Además de los colores RGB, es posible utilizar el "color de primer plano predeterminado" y el "color de fondo predeterminado" heredados de la terminal. Dado que notcurses no sabe cuáles son estos colores, no se consideran a efectos de mezcla de colores.

notcurses_render(3) — notcurses 3.0.0

NAME

notcurses_render — dibuja en la pantalla el estado de notcurses

SYNOPSIS

#include <notcurses/notcurses.h>

int notcurses_render(notcurses* nc);

DESCRIPTION

notcurses_render es el corazón de la operación de actualización de la pantalla de notcurses. Se debe llamar después de haber realizado cualquier cambio en el estado de notcurses, y antes de que el usuario pueda verlos.

Los cambios realizados a través de las API de notcurses (como notcurses_scroll(3), notcurses_plane_putstr(3), notcurses_input(3), etc.) se mantienen en un búfer de memoria. notcurses_render compara este búfer con el búfer de pantalla que está visible actualmente, calcula las diferencias y emite los códigos de escape ANSI apropiados para actualizar solo las partes modificadas de la pantalla. Este es un proceso llamado diferenciación.

Se garantiza que cada llamada a notcurses_render sea idempotente; si se llama varias veces seguidas sin cambios intermedios, no se emitirán códigos de escape adicionales.

Cuando se llama por primera vez después de notcurses_init(3), notcurses_render vaciará la pantalla de la terminal y la llenará con el estado inicial del plano principal.

Si notcurses_render devuelve un valor distinto de cero, se garantiza que se producirá un error. Cualquier llamada posterior a una API de notcurses, incluida notcurses_destroy(3), puede seguir fallando. Si se produce un error, el estado de notcurses está indefinido. Se debe llamar a notcurses_destroy(3) para intentar limpiar, pero la terminación es la única forma segura de recuperarse. El valor de retorno puede ser NCOK (éxito) o NCERR_* (un código de error).

RETURN VALUE

notcurses_render devuelve NCOK en caso de éxito, o uno de los siguientes códigos de error en caso de fallo:

  • NCERR_SYSTEM_ERROR: Ocurrió un error del sistema al escribir en la terminal.
  • NCERR_NOTINITTED: Se intentó renderizar antes de que se inicializara notcurses.
  • NCERR_NOMEM: No se pudo asignar memoria para el búfer de renderizado.
  • NCERR_REPLACE: Se intentó reemplazar un plano no existente.
  • NCERR_INVALID_DIMENSIONS: Se intentó asignar un plano con dimensiones cero.

BUGS

En algunos casos, la diferenciación puede ser menos eficiente de lo esperado. Esto se debe a que la diferenciación solo considera los cambios dentro de un plano. Si se mueve un plano, solo se actualizará el área afectada por el movimiento. Esto podría dejar artefactos de los contenidos anteriores del plano en la pantalla, que solo se borrarían en la siguiente llamada a notcurses_render.
