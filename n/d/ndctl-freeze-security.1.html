NDCTL-FREEZE-SECURITY(1) Manual de ndctl NDCTL-FREEZE-SECURITY(1)

NOMBRE

ndctl-freeze-security - Establece los DIMM especificados para rechazar futuras operaciones de seguridad

SINOPSIS

ndctl freeze-security <nmem0> [<nmem1>..<nmemN>] [<opciones>]

DESCRIPCIÓN

Impide que se realicen más operaciones de seguridad en los DIMM especificados hasta el próximo reinicio. Esto se utiliza en escenarios donde el administrador ha realizado todas las acciones de seguridad esperadas para el arranque actual y desea que el DIMM aplique / bloquee el estado actual.

EJEMPLOS

$ ndctl list -d nmem0
[
  {
    "dev":"nmem0",
    "id":"cdab-0a-07e0-ffffffff",
    "handle":0,
    "phys_id":0,
    "security":"unlocked"
  }
]
$ ndctl freeze-security  nmem0
security froze 1 nmem.
$ ndctl list -d nmem0
[
  {
    "dev":"nmem0",
    "id":"cdab-0a-07e0-ffffffff",
    "handle":0,
    "phys_id":0,
    "security":"unlocked",
    "security_frozen":true
  },
]

OPCIONES

<dimm>

Un nombre de dispositivo nmemX, o un número de ID de DIMM. Restringe la operación a los DIMM especificados. La palabra clave all puede especificarse para indicar la ausencia de cualquier restricción; sin embargo, esto es lo mismo que no proporcionar ninguna opción --dimm.

-b, --bus=

Un número de ID de bus, o una cadena de proveedor (por ejemplo, "ACPI.NFIT"). Restringe la operación a los buses especificados. La palabra clave all puede especificarse para indicar la ausencia de cualquier restricción; sin embargo, esto es lo mismo que no proporcionar ninguna opción --bus.

-v, --verbose

Emite mensajes de depuración.

TEORÍA DE OPERACIÓN

Las Especificaciones de Dispositivos Específicos de Intel (DSM) v1.7 y v1.8 [1] introdujeron las siguientes operaciones de gestión de seguridad: habilitar frase de contraseña, actualizar frase de contraseña, desbloquear DIMM, deshabilitar seguridad, congelar seguridad, borrar de forma segura (criptográfica), sobrescribir, habilitar frase de contraseña maestra, actualizar frase de contraseña maestra y borrar de forma segura con frase de contraseña maestra.

La gestión de seguridad para NVDIMM se compone de dos partes. El frontend utiliza el marco de gestión de claves de Linux (claves cifradas y de confianza [2]) para almacenar las frases de contraseña cifradas en el keyring gestionado por el kernel. La interfaz para esto es la utilidad keyutils, que utiliza las API de gestión de claves en el kernel de Linux. El backend toma la carga útil descifrada (que es la frase de contraseña del DIMM) y la pasa al DIMM.

A diferencia de otros DSM que son compuestos por libndctl y enviados al kernel a través de una llamada ioctl, los DSM de seguridad se gestionan a través del atributo security de sysfs bajo el dispositivo dimm. Se escribe un key-ID en el atributo security y el kernel extrae el material de clave asociado del keyring de usuario que es mantenido por el kernel.

El proceso de seguridad comienza con la generación de una clave maestra que se utiliza para sellar (cifrar) la frase de contraseña del DIMM. Puede haber una clave maestra común utilizada para cifrar la frase de contraseña de cada DIMM, o se puede generar una clave separada para cada DIMM. La clave maestra también se conoce como clave-cifradora-de-clave (kek). La kek puede ser generada por el TPM (Módulo de Plataforma Confiable) en el sistema, o alternativamente, la Clave Maestra del Sistema también puede usarse como la kek.

Para fines de prueba, también se puede usar una clave de usuario con una carga útil aleatorizada como kek. Ver [2] para más detalles. Para realizar cualquier operación de seguridad, se espera que la kek se haya agregado al keyring de usuario del kernel como se muestra en el siguiente ejemplo:

# keyctl show
Session Keyring
 736023423 --alswrv      0     0  keyring: _ses
 675104189 --alswrv      0 65534   \_ keyring: _uid.0
 680187394 --alswrv      0     0       \_ trusted: nvdimm-master

Antes de realizar cualquiera de las operaciones de seguridad, todas las regiones asociadas con el DIMM en cuestión deben ser deshabilitadas. Para la operación de sobrescritura, además de las regiones, el dimm también debe ser deshabilitado.

[1] http://pmem.io/documents/NVDIMM_DSM_Interface-V1.8.pdf
[2] https://www.kernel.org/doc/Documentation/security/keys/trusted-encrypted.rst

Las siguientes subsecciones describen los detalles de cada función de seguridad.

DESBLOQUEAR

El desbloqueo lo realiza el kernel, sin embargo, debe ocurrir un paso de preparación antes de que el kernel pueda emitir el DSM de desbloqueo. Se espera que desde el initramfs, se ejecute un comando de configuración (ndctl load-keys) antes de que el módulo libnvdimm sea cargado por modprobe. Este comando inyectará la kek y las frases de contraseña cifradas en el keyring de usuario del kernel. Durante la sonda del controlador libnvdimm, se realizará lo siguiente:

1. Comprueba el estado de seguridad del dispositivo y ve si el DIMM está bloqueado
2. Solicita la frase de contraseña cifrada asociada del keyring de usuario del kernel
3. Utiliza la kek para descifrar la frase de contraseña
4. Crea el DSM de desbloqueo, copia la carga útil descifrada en el DSM
5. Emite el DSM para desbloquear el DIMM

Si el DIMM ya está desbloqueado, el kernel intentará revalidar la frase de contraseña. Si no podemos revalidar la frase de contraseña, el kernel congelará la seguridad y prohibirá cualquier cambio adicional en la configuración de seguridad. Hay un parámetro del módulo del kernel disponible para anular este comportamiento.

CONFIGURAR CONTRASEÑA DE USUARIO

Para configurar la frase de contraseña de un DIMM, se espera que la kek a utilizar esté presente en el keyring de usuario del kernel. La kek cifra la frase de contraseña del DIMM utilizando el formato de clave enc32. La frase de contraseña en texto plano nunca es proporcionada ni visible para el usuario. En su lugar, es generada aleatoriamente por el kernel y el espacio de usuario no tiene acceso a ella. Tras el cifrado, un blob binario de la frase de contraseña se escribe en el directorio de almacenamiento de blobs de frases de contraseña (/etc/ndctl/keys). El usuario es responsable de hacer copias de seguridad de los blobs de frases de contraseña en una ubicación segura.

ACTUALIZAR CONTRASEÑA DE USUARIO

La operación de actualizar la frase de contraseña de usuario utiliza el mismo comando DSM que la habilitación de la frase de contraseña de usuario. La mayor parte del trabajo se realiza en el lado de la gestión de claves. El usuario tiene la opción de proporcionar una nueva kek para la nueva frase de contraseña, pero continuar utilizando la kek existente también es aceptable. Las siguientes operaciones se realizan para actualizar-contraseña:

1. Elimina la frase de contraseña cifrada del keyring de usuario del kernel.
2. Renombra el blob de la frase de contraseña a old.
3. Carga este blob de frase de contraseña antiguo en el keyring con el nombre "old".
4. Crea la nueva frase de contraseña y la cifra con la kek.
5. Envía el DSM con las frases de contraseña antiguas y nuevas descifradas.
6. Elimina la frase de contraseña antigua y el blob de la frase de contraseña del keyring.

ELIMINAR CONTRASEÑA DE USUARIO

El key-ID de la frase de contraseña a eliminar se escribe en sysfs. El kernel luego envía el DSM para deshabilitar la seguridad, y la frase de contraseña se elimina del keyring, y el blob de frase de contraseña asociado se elimina.

BORRADO CRIPTOGRÁFICO (SEGURO)

Esta operación es similar a eliminar-contraseña. El kernel emite una instrucción WBINVD antes y después de la operación para garantizar que no haya corrupción de datos por una caché de CPU obsoleta. Utilice el comando sanitize-dimm de ndctl con la opción --crypto-erase para realizar esta operación.

SOBRESCRITURA

La operación de sobrescritura requiere que el DIMM no esté bloqueado y que las regiones asociadas estén deshabilitadas. El proceso de sobrescritura se inicia con el DSM. El kernel pasa el DSM a la NVMDIMM, que sobrescribe los datos con el patrón de bits específico.

Este se invoca usando la opción --overwrite para ndctl sanitize-dimm. La operación de sobrescritura borra todo el NVDIMM. La operación puede llevar una cantidad de tiempo significativa. NOTA: Cuando el comando se completa con éxito, solo significa que la sobrescritura se ha iniciado con éxito, y no que la sobrescritura se haya completado. Posteriormente, ndctl wait-overwrite puede ser utilizado para esperar a que los NVDIMM que están realizando la sobrescritura terminen. Tras la finalización exitosa de una sobrescritura, la instrucción WBINVD es emitida por el kernel. Si se suministran ambas opciones, --crypto-erase y --overwrite, entonces la criptoeliminación se realiza antes de la sobrescritura.

BLOQUEO_DE_SEGURIDAD

Esta operación no requiere una contraseña. Esto provocará que cualquier comando de seguridad, excepto una consulta de estado, quede bloqueado hasta el próximo inicio.

CONFIGURACIÓN,_ACTUALIZACIÓN_y_CRIPTOELIMINACIÓN_de_CONTRASEÑA_MAESTRA

Estas operaciones son similares a la habilitación y actualización de la contraseña de usuario. La única diferencia es que se utiliza una contraseña diferente. La contraseña maestra no tiene relación con la clave maestra (kek) que se utiliza para el cifrado de cualquier contraseña.
