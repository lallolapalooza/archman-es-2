LD(1) Herramientas de desarrollo de GNU LD(1)

NOMBRE

ld - El enlazador GNU

SINOPSIS

ld [opciones] archivo_objeto ...

DESCRIPCIÓN

ld combina una serie de archivos objeto y de archivo, reubica sus datos y resuelve referencias de símbolos. Normalmente, el último paso en la compilación de un programa es ejecutar ld.

ld acepta archivos de lenguaje de comandos del enlazador escritos en un superconjunto de la sintaxis del lenguaje de comandos del editor de enlaces de AT&T, para proporcionar un control explícito y total sobre el proceso de enlazado.

Esta página del manual no describe el lenguaje de comandos; consulte la entrada de ld en "info" para obtener detalles completos sobre el lenguaje de comandos y otros aspectos del enlazador GNU.

Esta versión de ld utiliza las bibliotecas BFD de propósito general para operar sobre archivos objeto. Esto permite a ld leer, combinar y escribir archivos objeto en muchos formatos diferentes (por ejemplo, COFF o "a.out"). Se pueden enlazar formatos diferentes para producir cualquier tipo de archivo objeto disponible.

Además de su flexibilidad, el enlazador GNU es más útil que otros enlazadores al proporcionar información diagnóstica. Muchos enlazadores abandonan la ejecución inmediatamente al encontrar un error; siempre que sea posible, ld continúa la ejecución, permitiéndole identificar otros errores (o, en algunos casos, obtener un archivo de salida a pesar del error).

El enlazador GNU ld está diseñado para cubrir una amplia gama de situaciones y para ser lo más compatible posible con otros enlazadores. Como resultado, tiene muchas opciones para controlar su comportamiento.

OPCIONES

El enlazador admite una gran cantidad de opciones de línea de comandos, pero en la práctica pocas se utilizan en un contexto particular. Por ejemplo, un uso frecuente de ld es enlazar archivos objeto estándar de Unix en un sistema Unix estándar y compatible. En un sistema así, para enlazar un archivo "hello.o":

ld -o <salida> /lib/crt0.o hello.o -lc

Esto le indica a ld que produzca un archivo llamado salida como resultado de enlazar el archivo "/lib/crt0.o" con "hello.o" y la biblioteca "libc.a", que provendrá de los directorios de búsqueda estándar. (Consulte la discusión de la opción -l a continuación).

Algunas de las opciones de línea de comandos de ld pueden especificarse en cualquier punto de la línea de comandos. Sin embargo, las opciones que se refieren a archivos, como -l o -T, hacen que el archivo se lea en el punto en que aparece la opción en la línea de comandos, en relación con los archivos objeto y otras opciones de archivo. Repetir opciones no relacionadas con archivos con un argumento diferente tendrá un efecto nulo o anulará las ocurrencias previas (las más a la izquierda en la línea de comandos) de esa opción. Las opciones que se pueden especificar de forma significativa varias veces se indican en las descripciones a continuación.

Los argumentos que no son opciones son archivos objeto o archivos que se enlazarán juntos. Pueden seguir, preceder o mezclarse con las opciones de la línea de comandos, excepto que un argumento de archivo objeto no puede colocarse entre una opción y su argumento.

Normalmente, el enlazador se invoca con al menos un archivo objeto, pero puede especificar otras formas de archivos de entrada binarios usando -l, -R y el lenguaje de comandos del script. Si no se especifican archivos de entrada binarios en absoluto, el enlazador no produce ninguna salida y emite el mensaje No input files (No hay archivos de entrada).

Si el enlazador no puede reconocer el formato de un archivo objeto, asumirá que es un script de enlazador. Un script especificado de esta manera complementa el script principal del enlazador utilizado para el enlace (ya sea el script principal predeterminado o el especificado usando -T). Esta característica permite al enlazador enlazar con un archivo que parece ser un objeto o un archivo, pero que en realidad solo define algunos valores de símbolo, o utiliza "INPUT" o "GROUP" para cargar otros objetos. Especificar un script de esta manera simplemente complementa el script principal del enlazador, con los comandos adicionales colocados después del script principal; use la opción -T para reemplazar completamente el script principal predeterminado, pero tenga en cuenta el efecto del comando "INSERT".

Para las opciones cuyos nombres son una sola letra, los argumentos de opción deben seguir la letra de opción sin espacios intermedios, o darse como argumentos separados inmediatamente después de la opción que los requiere.

Para las opciones cuyos nombres son múltiples letras, un guion o dos pueden preceder al nombre de la opción; por ejemplo, -trace-symbol y --trace-symbol son equivalentes. Nota: hay una excepción a esta regla. Las opciones de múltiples letras que comienzan con una 'o' minúscula solo pueden ir precedidas por dos guiones. Esto es para reducir la confusión con la opción -o. Por lo tanto, por ejemplo, -omagic establece el nombre del archivo de salida a magic, mientras que --omagic establece la bandera NMAGIC en la salida.

Los argumentos para las opciones de múltiples letras deben estar separados del nombre de la opción por un signo igual, o darse como argumentos separados inmediatamente después de la opción que los requiere. Por ejemplo, --trace-symbol foo y --trace-symbol=foo son equivalentes. Se aceptan abreviaturas únicas de los nombres de las opciones de múltiples letras.

Nota: si el enlazador se invoca indirectamente, a través de un controlador de compilador (por ejemplo, gcc), entonces todas las opciones de línea de comandos del enlazador deben ir precedidas por -Wl, (o lo que sea apropiado para el controlador de compilador particular), de esta manera:

gcc -Wl,--start-group foo.o bar.o -Wl,--end-group

Esto es importante, ya que de lo contrario el programa controlador de compilador puede omitir silenciosamente las opciones del enlazador, lo que resulta en un enlace incorrecto. También puede surgir confusión al pasar opciones que requieren valores a través de un controlador, ya que el uso de un espacio entre la opción y el argumento actúa como un separador y hace que el controlador pase solo la opción al enlazador y el argumento al compilador. En este caso, es más sencillo usar las formas unidas de las opciones de una sola letra y de múltiples letras, como:

gcc foo.o bar.o -Wl,-eENTRY -Wl,-Map=a.map

Aquí hay una tabla de los modificadores genéricos de línea de comandos aceptados por el enlazador GNU:

@archivo
Lea las opciones de la línea de comandos desde archivo. Las opciones leídas se insertan en lugar de la opción original @archivo. Si archivo no existe o no se puede leer, la opción se tratará literalmente y no se eliminará.

Las opciones en archivo están separadas por espacios en blanco. Se puede incluir un carácter de espacio en blanco en una opción rodeando la opción completa con comillas simples o dobles. Se puede incluir cualquier carácter (incluido una barra invertida) prefijando el carácter que se va a incluir con una barra invertida. El archivo puede contener opciones adicionales @archivo; dichas opciones se procesarán recursivamente.

-a palabra_clave
Esta opción se admite para compatibilidad con HP/UX. El argumento palabra_clave debe ser una de las cadenas archive, shared o default. -aarchive es funcionalmente equivalente a -Bstatic, y las otras dos palabras clave son funcionalmente equivalentes a -Bdynamic. Esta opción se puede usar cualquier número de veces.
--audit AUDITLIB
Añade AUDITLIB a la entrada "DT_AUDIT" de la sección dinámica. AUDITLIB no se comprueba su existencia, ni utilizará el DT_SONAME especificado en la biblioteca. Si el enlazador encuentra un objeto con una entrada de auditoría mientras busca bibliotecas compartidas, añadirá una entrada "DT_DEPAUDIT" correspondiente en el archivo de salida. Esta opción solo es significativa en plataformas ELF que admiten la interfaz rtld-audit.

Incluso cuando ld está configurado para admitir formatos de objeto alternativos, normalmente no necesita especificarlo, ya que ld debería estar configurado para esperar el formato

--mri-script=archivo-de-comandos-MRI
Para compatibilidad con enlazadores producidos por MRI, ld acepta archivos de script escritos en un lenguaje de comandos alternativo y restringido, descrito en la sección Archivos de Script Compatibles con MRI de la documentación de GNU ld. Introduzca los archivos de script MRI con la opción -c; utilice la opción -T para ejecutar scripts de enlazador escritos en el lenguaje de scripting de propósito general de ld. Si archivo-de-comandos-MRI no existe, ld lo busca en los directorios especificados por cualquier opción -L.
-d
-dc
-dp
Estas tres opciones son equivalentes; se admiten múltiples formas para compatibilidad con otros enlazadores. Asignan espacio a símbolos comunes incluso si se especifica un archivo de salida relocalizable (con -r). El comando de script "FORCE_COMMON_ALLOCATION" tiene el mismo efecto.
--depaudit BIBLIOTECA-AUDIT
-P BIBLIOTECA-AUDIT
Añade BIBLIOTECA-AUDIT a la entrada "DT_DEPAUDIT" de la sección dinámica. BIBLIOTECA-AUDIT no se comprueba su existencia, ni utilizará el DT_SONAME especificado en la biblioteca. Si se especifica varias veces "DT_DEPAUDIT" contendrá una lista separada por dos puntos de las interfaces de auditoría a utilizar. Esta opción solo es significativa en plataformas ELF que admiten la interfaz rtld-audit. La opción -P se proporciona para compatibilidad con Solaris.
--enable-linker-version
Habilita la directiva de script del enlazador "LINKER_VERSION", descrita en Datos de Sección de Salida. Si esta directiva se utiliza en un script del enlazador y esta opción ha sido habilitada, entonces se insertará una cadena que contiene la versión del enlazador en el punto actual.

Nota: la ubicación de esta opción en la línea de comandos del enlazador es significativa. Solo afectará a los scripts del enlazador que vienen después de ella en la línea de comandos, o que están integrados en el enlazador.

--disable-linker-version
Deshabilita la directiva de script del enlazador "LINKER_VERSION", de modo que no inserte una cadena de versión. Este es el valor predeterminado.
--enable-non-contiguous-regions
Esta opción evita generar un error si una sección de entrada no encaja en una sección de salida coincidente. El enlazador intenta asignar la sección de entrada a secciones de salida coincidentes subsiguientes, y solo genera un error si ninguna sección de salida es lo suficientemente grande. Esto es útil cuando hay varias regiones de memoria no contiguas disponibles y la sección de entrada no requiere una en particular. El orden en que se evalúan las secciones de entrada no cambia, por ejemplo: 
MEMORY {
  MEM1 (rwx) : ORIGIN = 0x1000, LENGTH = 0x14
  MEM2 (rwx) : ORIGIN = 0x1000, LENGTH = 0x40
  MEM3 (rwx) : ORIGIN = 0x2000, LENGTH = 0x40
}
SECTIONS {
  mem1 : { *(.data.*); } > MEM1
  mem2 : { *(.data.*); } > MEM2
  mem3 : { *(.data.*); } > MEM3
}

con secciones de entrada:
.data.1: tamaño 8
.data.2: tamaño 0x10
.data.3: tamaño 4

resulta en que .data.1 se asigna a mem1, y .data.2 y .data.3
se asignan a mem2, aunque .data.3 cabría en mem3.

Esta opción es incompatible con las sentencias INSERT porque cambia la forma en que las secciones de entrada se mapean a las secciones de salida.

--enable-non-contiguous-regions-warnings
Esta opción habilita advertencias cuando "--enable-non-contiguous-regions" permite coincidencias posiblemente inesperadas en el mapeo de secciones, lo que potencialmente podría llevar a descartar silenciosamente una sección en lugar de fallar porque no encaja en ninguna región de salida.
-e entrada
--entry=entrada
Usa entrada como el símbolo explícito para comenzar la ejecución de tu programa, en lugar del punto de entrada predeterminado. Si no hay un símbolo llamado entrada, el enlazador intentará interpretar entrada como un número y lo usará como la dirección de entrada (el número se interpretará en base 10; puedes usar un prefijo 0x para base 16, o un prefijo 0 para base 8).
--exclude-libs bib,bib,...
Especifica una lista de bibliotecas de archivo de las cuales no se deben exportar símbolos automáticamente. Los nombres de biblioteca pueden estar delimitados por comas o dos puntos. Especificar "--exclude-libs ALL" excluye los símbolos de todas las bibliotecas de archivo de la exportación automática. Esta opción solo está disponible para el puerto i386 PE del enlazador y para puertos dirigidos a ELF. Para i386 PE, los símbolos listados explícitamente en un archivo .def todavía se exportan, independientemente de esta opción. Para puertos dirigidos a ELF, los símbolos afectados por esta opción se tratarán como ocultos.
--exclude-modules-for-implib modulo,modulo,...
Especifica una lista de archivos objeto o miembros de archivo, de los cuales no se deben exportar símbolos automáticamente, pero que deben copiarse íntegramente a la biblioteca de importación que se está generando durante el enlace. Los nombres de módulo pueden estar delimitados por comas o dos puntos, y deben coincidir exactamente con los nombres de archivo utilizados por ld para abrir los archivos; para miembros de archivo, este es simplemente el nombre del miembro, pero para archivos objeto el nombre listado debe incluir y coincidir precisamente cualquier ruta utilizada para especificar el archivo de entrada en la línea de comandos del enlazador. Esta opción solo está disponible para el puerto i386 PE del enlazador. Los símbolos listados explícitamente en un archivo .def todavía se exportan, independientemente de esta opción.
-E
--export-dynamic
--no-export-dynamic
Al crear un ejecutable enlazado dinámicamente, usar la opción -E o la opción --export-dynamic hace que el enlazador agregue todos los símbolos a la tabla de símbolos dinámica. La tabla de símbolos dinámica es el conjunto de símbolos que son visibles desde objetos dinámicos en tiempo de ejecución.

Si no utiliza ninguna de estas opciones (o utiliza la opción --no-export-dynamic para restaurar el comportamiento predeterminado), la tabla de símbolos dinámica normalmente contendrá solo aquellos símbolos que son referenciados por algún objeto dinámico mencionado en el enlace.

Si utiliza "dlopen" para cargar un objeto dinámico que necesita referirse a los símbolos definidos por el programa, en lugar de algún otro objeto dinámico, entonces probablemente necesitará usar esta opción al enlazar el programa en sí.

También puede usar la lista dinámica para controlar qué símbolos se deben agregar a la tabla de símbolos dinámica si el formato de salida lo admite. Consulte la descripción de --dynamic-list.

Tenga en cuenta que esta opción es específica de los puertos dirigidos a ELF. Los destinos PE admiten una función similar para exportar todos los símbolos de una DLL o EXE; consulte la descripción de --export-all-symbols a continuación.

--export-dynamic-symbol=glob
Al crear un ejecutable enlazado dinámicamente, los símbolos que coincidan con glob se agregarán a la tabla de símbolos dinámica. Al crear una biblioteca compartida, las referencias a símbolos que coincidan con glob no se vincularán a las definiciones dentro de la biblioteca compartida. Esta opción no tiene efecto al crear una biblioteca compartida y no se especifican -Bsymbolic o --dynamic-list. Esta opción solo es significativa en plataformas ELF que admiten bibliotecas compartidas.
--export-dynamic-symbol-list=archivo
Especifique un --export-dynamic-symbol por cada patrón en el archivo. El formato del archivo es el mismo que el nodo de versión sin alcance ni nombre de nodo. Consulte VERSION para obtener más información.
-EB
Enlaza objetos big-endian. Esto afecta al formato de salida predeterminado.
-EL
Enlaza objetos little-endian. Esto afecta al formato de salida predeterminado.
-f nombre
--auxiliary=nombre
Al crear un objeto compartido ELF, establece el campo interno DT_AUXILIARY al nombre especificado. Esto le dice al enlazador dinámico que la tabla de símbolos del objeto compartido debe usarse como un filtro auxiliar en la tabla de símbolos del objeto compartido nombre.

Si posteriormente enlaza un programa contra este objeto de filtro, entonces, al ejecutar el programa, el enlazador dinámico verá el campo DT_AUXILIARY. Si el enlazador dinámico resuelve algún símbolo del objeto de filtro, primero comprobará si hay una definición en el objeto compartido nombre. Si la hay, se usará en lugar de la definición en el objeto de filtro. El objeto compartido nombre no necesita existir. Por lo tanto, el objeto compartido nombre puede usarse para proporcionar una implementación alternativa de ciertas funciones, quizás para depuración o para rendimiento específico de la máquina.

Esta opción puede especificarse más de una vez. Las entradas DT_AUXILIARY se crearán en el orden en que aparezcan en la línea de comandos.

-F nombre
--filter=nombre
Al crear un objeto compartido ELF, establezca el campo interno DT_FILTER al nombre especificado. Esto le dice al enlazador dinámico que la tabla de símbolos del objeto compartido que se está creando debe usarse como un filtro en la tabla de símbolos del objeto compartido nombre.

Si posteriormente enlaza un programa contra este objeto de filtro, entonces, cuando ejecute el programa, el enlazador dinámico verá el campo DT_FILTER. El enlazador dinámico resolverá los símbolos de acuerdo con la tabla de símbolos del objeto de filtro como de costumbre, pero en realidad se enlazará a las definiciones encontradas en el objeto compartido nombre. Por lo tanto, el objeto de filtro se puede usar para seleccionar un subconjunto de los símbolos proporcionados por el objeto nombre.

Algunos enlazadores antiguos utilizaban la opción -F a lo largo de una cadena de herramientas de compilación para especificar el formato del archivo objeto para los archivos objeto de entrada y salida. El enlazador GNU utiliza otros mecanismos para este propósito: las opciones -b, --format, --oformat, el comando "TARGET" en los scripts del enlazador y la variable de entorno "GNUTARGET". El enlazador GNU ignorará la opción -F cuando no esté creando un objeto compartido ELF.

-fini=nombre
Al crear un ejecutable o un objeto compartido ELF, llame a NOMBRE cuando el ejecutable o el objeto compartido se descargue, estableciendo DT_FINI a la dirección de la función. Por defecto, el enlazador utiliza "_fini" como la función a llamar.
-g
Ignorado. Proporcionado para compatibilidad con otras herramientas.
-G valor
--gpsize=valor
Establezca el tamaño máximo de los objetos a optimizar usando el registro GP a tamaño. Esto solo es significativo para formatos de archivo objeto como MIPS ELF que admiten la colocación de objetos grandes y pequeños en diferentes secciones. Esto se ignora para otros formatos de archivo objeto.
-h nombre
-soname=nombre
Al crear un objeto compartido ELF, establezca el campo interno DT_SONAME al nombre especificado. Cuando un ejecutable se enlaza con un objeto compartido que tiene un campo DT_SONAME, entonces, cuando se ejecuta el ejecutable, el enlazador dinámico intentará cargar el objeto compartido especificado por el campo DT_SONAME en lugar de usar el nombre de archivo dado al enlazador.
-i
Realice un enlace incremental (igual que la opción -r).
-init=nombre
Al crear un ejecutable o un objeto compartido ELF, llame a NOMBRE cuando el ejecutable o el objeto compartido se cargue, estableciendo DT_INIT a la dirección de la función. Por defecto, el enlazador utiliza "_init" como la función a llamar.
-l especnom
--library=especnom
Agregue el archivo de biblioteca o objeto especificado por especnom a la lista de archivos a enlazar. Esta opción se puede usar cualquier número de veces. Si especnom tiene la forma :nombrearchivo, ld buscará en la ruta de la biblioteca un archivo llamado nombrearchivo, de lo contrario, buscará en la ruta de la biblioteca un archivo llamado libespecnom.a.

En sistemas que admiten bibliotecas compartidas, ld también puede buscar archivos distintos de libespecnom.a. Específicamente, en sistemas ELF y SunOS, ld buscará en un directorio una biblioteca llamada libespecnom.so antes de buscar una llamada libespecnom.a. (Por convención, una extensión ".so" indica una biblioteca compartida). Tenga en cuenta que este comportamiento no se aplica a :nombrearchivo, que siempre especifica un archivo llamado nombrearchivo.

El enlazador buscará en un archivo de biblioteca solo una vez, en la ubicación en la que se especifica en la línea de comandos. Si el archivo de biblioteca define un símbolo que no estaba definido en algún objeto que apareció antes que el archivo de biblioteca en la línea de comandos, el enlazador incluirá los archivos apropiados del archivo de biblioteca. Sin embargo, un símbolo no definido en un objeto que aparece más tarde en la línea de comandos no hará que el enlazador busque nuevamente el archivo de biblioteca.

Vea la opción -( para una forma de forzar al enlazador a buscar archivos de biblioteca múltiples veces.

Puede enumerar el mismo archivo de biblioteca varias veces en la línea de comandos.

Este tipo de búsqueda de archivos de biblioteca es estándar para los enlazadores de Unix. Sin embargo, si está utilizando ld en AIX, tenga en cuenta que es diferente del comportamiento del enlazador de AIX.

-L dirbuscar
--library-path=dirbuscar
Agregue la ruta dirbuscar a la lista de rutas que ld buscará para bibliotecas de archivos y scripts de control de ld. Puede usar esta opción cualquier número de veces. Los directorios se buscan en el orden en que se especifican en la línea de comandos. Los directorios especificados en la línea de comandos se buscan antes que los directorios predeterminados. Todas las opciones -L se aplican a todas las opciones -l, independientemente del orden en que aparezcan las opciones. Las opciones -L no afectan cómo ld busca un script de enlazador a menos que se especifique la opción -T.

Si dirbuscar comienza con "=" o $SYSROOT, entonces este prefijo será reemplazado por el prefijo sysroot, controlado por la opción --sysroot, o especificado cuando se configuró el enlazador.

El conjunto predeterminado de rutas buscadas (sin ser especificadas con -L) depende de qué modo de emulación esté utilizando ld, y en algunos casos también de cómo fue configurado.

Las rutas también se pueden especificar en un script de enlace con el comando "SEARCH_DIR". Los directorios especificados de esta manera se buscan en el punto en que aparece el script de enlazador en la línea de comandos.

-m emulación
Emule el enlazador emulación. Puede enumerar las emulaciones disponibles con las opciones --verbose o -V.

Si no se utiliza la opción -m, la emulación se toma de la variable de entorno "LDEMULATION", si esta está definida.

De lo contrario, la emulación predeterminada depende de cómo se configuró el enlazador.

--remap-inputs=patrón=nombrearchivo
--remap-inputs-file=archivo
Estas opciones permiten que los nombres de los archivos de entrada se cambien antes de que el enlazador intente abrirlos. La opción --remap-inputs=foo.o=bar.o hará que cualquier intento de cargar un archivo llamado foo.o intente en su lugar cargar un archivo llamado bar.o. Se permiten patrones comodín en el primer nombre de archivo, por lo que --remap-inputs=foo*.o=bar.o renombrará cualquier archivo de entrada que coincida con foo*.o a bar.o.

Una forma alternativa de la opción --remap-inputs-file=nombrearchivo permite leer las reasignaciones desde un archivo. Cada línea en el archivo puede contener una única reasignación. Las líneas en blanco se ignoran. Cualquier cosa desde un carácter de almohadilla (#) hasta el final de una línea se considera un comentario y también se ignora. El patrón de mapeo puede separarse del nombre de archivo por espacios en blanco o un carácter de igual (=).

Las opciones se pueden especificar varias veces. Sus contenidos se acumulan. Las reasignaciones se procesarán en el orden en que aparecen en la línea de comandos, y si provienen de un archivo, en el orden en que aparecen en el archivo. Si se realiza una coincidencia, no se realizará ninguna verificación adicional para ese nombre de archivo.

Si el nombre de archivo de reemplazo es /dev/null o simplemente NUL, la reasignación realmente hará que el archivo de entrada se ignore. Esta puede ser una forma conveniente de experimentar eliminando archivos de entrada de un entorno de compilación complicado.

Tenga en cuenta que esta opción depende de la posición y solo afecta a los nombres de archivo que vienen después de ella en la línea de comandos. Por lo tanto:

ld foo.o --remap-inputs=foo.o=bar.o

No tendrá ningún efecto, mientras que:

ld --remap-inputs=foo.o=bar.o foo.o

Renombrará el archivo de entrada foo.o a bar.o.

Nota: estas opciones también afectan a los archivos referenciados por las declaraciones INPUT en los scripts del enlazador. Pero dado que los scripts del enlazador se procesan después de leer toda la línea de comandos, la posición de las opciones de reasignación en la línea de comandos no es significativa.

Si la opción verbose está habilitada, se informarán las coincidencias de reasignaciones, aunque nuevamente la opción verbose debe estar habilitada en la línea de comandos *antes* de que aparezcan los nombres de archivo reasignados.

Si las opciones -Map o --print-map están habilitadas, la lista de reasignaciones se incluirá en la salida del mapa.

--reduce-memory-overheads
Esta opción reduce los requisitos de memoria en tiempo de ejecución de ld, a costa de la velocidad de enlazado. Se introdujo para seleccionar el antiguo algoritmo O(n^2) para la generación de archivos de mapa de enlaces, en lugar del nuevo algoritmo O(n) que utiliza aproximadamente un 40% más de memoria para el almacenamiento de símbolos.

Otro efecto del cambio es establecer el tamaño por defecto de la tabla hash a 1021, lo que de nuevo ahorra memoria a costa de alargar el tiempo de ejecución del enlazador. Sin embargo, esto no se hace si se ha utilizado el modificador --hash-size.

El modificador --reduce-memory-overheads también puede utilizarse para habilitar otros intercambios en futuras versiones del enlazador.

Las siguientes observaciones pertenecen a la implementación original de la característica y hoy en día son obsoletas para los destinos Cygwin y MinGW.

Nota: El uso de la extensión 'auto-import' provocará que la sección de texto del archivo de imagen se haga escribible. Esto no se ajusta a la especificación del formato PE-COFF publicada por Microsoft.

Nota: El uso de la extensión 'auto-import' también provocará que los datos de solo lectura que normalmente se colocarían en la sección .rdata se coloquen en la sección .data en su lugar. Esto es para solucionar un problema con las constantes que se describe aquí: http://www.cygwin.com/ml/cygwin/2004-09/msg01101.html

El uso de 'auto-import' generalmente "simplemente funcionará", pero a veces puede ver este mensaje:

"la variable '' no se puede autoimportar. Lea la documentación de ld para "--enable-auto-import" para obtener detalles."

Este mensaje ocurre cuando alguna (sub)expresión accede a una dirección dada finalmente por la suma de dos constantes (las tablas de importación de Win32 solo permiten una). Los casos en los que esto puede ocurrir incluyen el acceso a campos miembros de variables struct importadas de una DLL, así como el uso de un índice constante en una variable array importada de una DLL. Cualquier variable de múltiples palabras (arrays, structs, long long, etc.) puede desencadenar esta condición de error. Sin embargo, independientemente del tipo de dato exacto de la variable exportada que cause el problema, ld siempre la detectará, emitirá la advertencia y saldrá.

Hay varias formas de abordar esta dificultad, independientemente del tipo de dato de la variable exportada:

Una forma es usar el interruptor --enable-runtime-pseudo-reloc. Esto deja la tarea de ajustar las referencias en su código cliente para el entorno de tiempo de ejecución, por lo que este método solo funciona cuando el entorno de tiempo de ejecución admite esta característica.

Una segunda solución es forzar que una de las 'constantes' sea una variable, es decir, desconocida y no optimizable en tiempo de compilación. Para arrays, hay dos posibilidades: a) hacer que el índice (la dirección del array) sea una variable, o b) hacer que el índice 'constante' sea una variable. Por lo tanto:

extern type extern_array[];
extern_array[1] -->
   { volatile type *t=extern_array; t[1] }

o

extern type extern_array[];
extern_array[1] -->
   { volatile int t=1; extern_array[t] }

Para structs (y la mayoría de los otros tipos de datos de múltiples palabras), la única opción es hacer que la struct en sí (o el long long, o el ...) sea una variable:

extern struct s extern_struct;
extern_struct.field -->
   { volatile struct s *t=&extern_struct; t->field }

o

extern long long extern_ll;
extern_ll -->
  { volatile long long * local_ll=&extern_ll; *local_ll }

Un tercer método para tratar esta dificultad es abandonar 'auto-import' para el símbolo en cuestión y marcarlo con "__declspec(dllimport)". Sin embargo, en la práctica, esto requiere usar #defines en tiempo de compilación para indicar si está compilando una DLL, compilando código cliente que se enlazará a la DLL, o simplemente compilando/enlazando a una biblioteca estática. Al elegir entre los diversos métodos para resolver el problema de 'dirección directa con desplazamiento constante', debe considerar el uso típico en el mundo real:

Original:

--foo.h
extern int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  printf("%d\n",arr[1]);
}

Solución 1:

--foo.h
extern int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  /* Este workaround es para win32 y cygwin; no "optimizar" */
  volatile int *parr = arr;
  printf("%d\n",parr[1]);
}

Solución 2:

--foo.h
/* Nota: se asume auto-export (sin __declspec(dllexport)) */
#if (defined(_WIN32) || defined(__CYGWIN__)) && \
  !(defined(FOO_BUILD_DLL) || defined(FOO_STATIC))
#define FOO_IMPORT __declspec(dllimport)
#else
#define FOO_IMPORT
#endif
extern FOO_IMPORT int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  printf("%d\n",arr[1]);
}

Una cuarta forma de evitar este problema es refactorizar su biblioteca para utilizar una interfaz funcional en lugar de una interfaz de datos para las variables problemáticas (por ejemplo, funciones accesoras set_foo() y get_foo()).

Estas opciones controlan la generación de instrucciones compactas por el enlazador en las entradas PLT para MIPS R6.
--no-ignore-branch-isa
Estas opciones controlan las comprobaciones de reubicación de ramas para transiciones de modo ISA inválidas. Si se usa "--ignore-branch-isa", entonces el enlazador acepta cualquier reubicación de rama y cualquier transición de modo ISA requerida se pierde en el cálculo de la reubicación, excepto en algunos casos de instrucciones "BAL" que cumplen las condiciones de relajación y se convierten en instrucciones equivalentes "JALX" a medida que se calcula la reubicación asociada. Por defecto o si se usa "--no-ignore-branch-isa" se realiza una comprobación que provoca la pérdida de una transición de modo ISA para producir un error.

ENTORNO

Puedes cambiar el comportamiento de ld con las variables de entorno "GNUTARGET", "LDEMULATION" y "COLLECT_NO_DEMANGLE".

"GNUTARGET" determina el formato del objeto del archivo de entrada si no usas -b (o su sinónimo --format). Su valor debe ser uno de los nombres BFD para un formato de entrada. Si no hay "GNUTARGET" en el entorno, ld usa el formato natural del objetivo. Si "GNUTARGET" está configurado como "default" entonces BFD intenta descubrir el formato de entrada examinando los archivos binarios de entrada; este método a menudo tiene éxito, pero hay ambigüedades potenciales, ya que no hay un método para garantizar que el número mágico utilizado para especificar los formatos de archivo objeto sea único. Sin embargo, el procedimiento de configuración para BFD en cada sistema coloca el formato convencional para ese sistema primero en la lista de búsqueda, por lo que las ambigüedades se resuelven a favor de la convención.

"LDEMULATION" determina la emulación predeterminada si no usas la opción -m. La emulación puede afectar varios aspectos del comportamiento del enlazador, particularmente el script de enlazador predeterminado. Puedes listar las emulaciones disponibles con las opciones --verbose o -V. Si la opción -m no se usa, y la variable de entorno "LDEMULATION" no está definida, la emulación predeterminada depende de cómo se configuró el enlazador.
