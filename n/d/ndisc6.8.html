NDISC6(8) Manual del Administrador del Sistema NDISC6(8)

NOMBRE

ndisc6 - Herramienta de Descubrimiento de Vecinos ICMPv6

SINOPSIS

ndisc6 [-1mnqv] [-r intentos] [-s ip_origen] [-w espera_ms] <dirección_IPv6> <interfaz>

DESCRIPCIÓN

NDisc6 es un programa Unix que implementa el Descubrimiento de Vecinos ICMPv6 en el espacio de usuario (normalmente lo hace el kernel). Se utiliza para buscar la dirección de capa de enlace (dirección de capa 2, MAC en el caso de Ethernet) de cualquier nodo IPv6 en la red.

Se debe especificar la dirección IPv6 del nodo, así como la interfaz de red en la que realizar la búsqueda.

OPCIONES

-1 o --single
Salir tan pronto como se reciba el primer anuncio (por defecto).
-h o --help
Mostrar ayuda y salir.
-m o --multiple
Esperar posibles anuncios duplicados e imprimir todos ellos.
-n o --numeric
Si el primer parámetro no es una dirección IPv6 válida, no intentar resolverla como un nombre de host DNS.
-q o --quiet
Mostrar solo la dirección de capa de enlace. No mostrar nada en caso de fallo. Esto es principalmente útil cuando se llama al programa desde un script de shell.
-r intentos o --retry intentos
Enviar la solicitud de Descubrimiento de Vecinos ICMPv6 tantas veces hasta recibir una respuesta, o abortar. Por defecto, ndisc6 intentará 3 veces antes de abortar (MAX_MULTICAST_SOLICIT y MAX_UNICAST_SOLICIT de RFC2461).
-s ip_origen o --source ip_origen
Especificar la dirección IPv6 a usar como origen para los paquetes de solicitud de vecino.
-V o --version
Mostrar la versión del programa y la licencia, y salir.
-v o --verbose
Mostrar información detallada. Esta es la opción por defecto.
-w espera_ms o --wait espera_ms
Esperar espera_ms milisegundos por una respuesta antes de reintentar. Por defecto, ndisc6 espera 1 segundo entre cada intento (RETRANS_TIMER de RFC2461).

Si ndisc6 no recibe ninguna respuesta después del número especificado de intentos esperando espera_ms milisegundos cada vez, saldrá con el código 2. En caso de error, saldrá con el código 1. En caso contrario, saldrá con el código 0. Esto hace posible usar el código de salida para ver si un host está en la red o no.

DIAGNÓSTICOS

Si no recibe respuesta mientras sabe que el host remoto está activo, lo más probable es que no esté en la red, es decir, que deba cruzar uno o más routers para alcanzarlo. Por diseño, los nodos IPv6 ignoran los paquetes de Descubrimiento de Vecinos ICMPv6 recibidos de nodos que no están en el mismo enlace (segmento Ethernet), por motivos de seguridad. Técnicamente, esto se hace asegurando que el Límite de Saltos (TTL) sea 255.

Tenga en cuenta que no puede usar ndisc6 para buscar la dirección de capa de enlace del host local.

SEGURIDAD

ndisc6 debe tener los permisos de setuid a root para permitir su uso por usuarios no privilegiados. Soltará sus privilegios de root antes de cualquier intento de enviar o recibir datos de la red para reducir el posible impacto de una vulnerabilidad de seguridad.
