NDCTL-INJECT-ERROR(1) Manual de ndctl NDCTL-INJECT-ERROR(1)

NOMBRE

ndctl-inject-error - inyecta errores de medios en un desplazamiento de espacio de nombres

SINOPSIS

ndctl inject-error <espacio de nombres> [<opciones>]

TEORÍA DE OPERACIÓN

La capacidad de una REGIÓN NVDIMM (espacio contiguo de memoria persistente) se accede a través de uno o más dispositivos NAMESPACE. REGIÓN es el término de Linux para lo que ACPI y UEFI llaman un conjunto de intercalado DIMM, o un rango de direcciones físicas del sistema que se intercala (por el controlador de memoria) a través de uno o más módulos de memoria.

La especificación UEFI define el Protocolo de Etiqueta NVDIMM como la combinación de métodos de acceso al área de etiqueta y un formato de datos para el aprovisionamiento de uno o más objetos NAMESPACE a partir de una REGIÓN. Tenga en cuenta que el soporte de etiquetas es opcional y si Linux no detecta la capacidad de etiqueta, automáticamente instanciará un espacio de nombres "sin etiqueta" por región. Ejemplos de espacios de nombres sin etiqueta son los creados por la opción de línea de comandos memmap=ss!nn del kernel (ver el wiki de nvdimm en kernel.org), o NVDIMMs sin un índice de espacio de nombres válido en su área de etiqueta.


Nota

Los espacios de nombres sin etiqueta carecen de muchas de las características de sus primos
ricos en etiquetas. Por ejemplo, su tamaño no se puede modificar, ni se pueden destruir completamente (es decir, recuperar el espacio). Una operación de destrucción pondrá a cero cualquier metadato específico del modo. Finalmente, para las operaciones de creación de espacios de nombres sin etiqueta, ndctl omite las comprobaciones de disponibilidad de capacidad de región y siempre satisface la solicitud utilizando la capacidad completa de la región. La única operación de reconfiguración compatible con un espacio de nombres sin etiqueta es el cambio de su modo.

Un espacio de nombres se puede aprovisionar para operar en uno de 4 modos, fsdax, devdax, sector y raw. Aquí están los modelos de uso esperados para estos modos:

•fsdax: El modo Filesystem-DAX es el modo predeterminado de un espacio de nombres al especificar ndctl create-namespace sin opciones. Crea un dispositivo de bloque (/dev/pmemX[.Y]) que admite las capacidades DAX de los sistemas de archivos Linux (xfs y ext4 hasta la fecha). DAX elimina la caché de páginas de la ruta de I/O y permite que mmap(2) establezca mapeos directos a medios de memoria persistente. La capacidad DAX permite que las cargas de trabajo / conjuntos de trabajo que excederían la capacidad de la caché de páginas escalen hasta la capacidad de la memoria persistente. Las cargas de trabajo que caben en la caché de páginas o realizan transferencias de datos masivas pueden no ver beneficios de DAX. En caso de duda, elija este modo.
•devdax: El modo Device-DAX habilita capacidades de mapeo DAX mmap(2) similares a Filesystem-DAX. Sin embargo, en lugar de un dispositivo de bloque que puede admitir un sistema de archivos habilitado para DAX, este modo emite un único archivo de dispositivo de caracteres (/dev/daxX.Y). Use este modo para asignar memoria persistente a una máquina virtual, registrar memoria persistente para RDMA o cuando se necesiten mapeos gigantescos.
•sector: Use este modo para alojar sistemas de archivos heredados que no verifican los metadatos o aplicaciones que no están preparadas para sectores rotos después de un fallo. El uso esperado para este modo es para pequeños volúmenes de arranque. Este modo es compatible con otros sistemas operativos.
•raw: El modo Raw es efectivamente solo un disco de memoria que no admite DAX. Típicamente, esto indica un espacio de nombres que fue creado por herramientas u otro sistema operativo que no sabía cómo crear un espacio de nombres en modo fsdax o devdax de Linux. Este modo es compatible con otros sistemas operativos, pero nuevamente, no admite la operación DAX.

ndctl-inject-error se puede usar para solicitar a la plataforma que simule errores de medios en el espacio de direcciones NVDIMM para ayudar a depurar y desarrollar funciones relacionadas con el manejo de errores.

Por defecto, inyectar un error en realidad solo inyecta un error en los primeros n bytes del bloque, donde n es el resultado de ndctl_cmd_ars_cap_get_size(). En otras palabras, solo inyectamos una unidad ars por sector. Esto es suficiente para que Linux marque todo el sector como defectuoso, y aparecerá como tal en las diversas listas de bloques defectuosos del kernel. Si se están inyectando múltiples bloques, solo se inyectarán los primeros n bytes de cada bloque especificado como errores. Esto se puede anular con la opción --saturate, que forzará la inyección de todo el bloque como un error.


Advertencia

Estos comandos son PELIGROSOS y pueden causar pérdida de datos. Solo se
proporcionan para fines de prueba y depuración.

EJEMPLOS

Inyectar errores en namespace0.0 en el bloque 12 para 2 bloques (es decir, 12, 13)

ndctl inject-error --block=12 --count=2 namespace0.0

Verificar el estado de los errores inyectados en namespace0.0

ndctl inject-error --status namespace0.0

Desinyectar errores en el bloque 12 para 2 bloques en namespace0.0

ndctl inject-error --uninject --block=12 --count=2 namespace0.0

OPCIONES

-B, --block=

Desplazamiento de bloque del espacio de nombres en bloques de 512 bytes donde se inyectará el error. 
NOTA: El desplazamiento se interpreta de diferentes maneras según el "modo"
del espacio de nombres. Para el modo "raw", el desplazamiento es el desplazamiento base del espacio de nombres. Para el modo "fsdax" (es decir, un espacio de nombres "pfn"), el desplazamiento es relativo a la parte visible por el usuario del espacio de nombres, y se tendrá en cuenta el desplazamiento introducido por los metadatos del kernel. Para un espacio de nombres en modo "sector" (es decir, un espacio de nombres "BTT"), el desplazamiento es relativo al espacio de nombres base, ya que los detalles de traducción de BTT son internos al kernel y no se pueden tener en cuenta al inyectar
errores.

-n, --count=

Número de bloques a inyectar como errores. Esto también está en términos de bloques fijos de 512 bytes.

-d, --uninject

Esta opción solicitará a la plataforma que elimine cualquier error inyectado para el desplazamiento de bloque y la cuenta especificados. 
ADVERTENCIA: Esto no borrará el seguimiento de bloques defectuosos interno del kernel;
solo se pueden borrar haciendo una escritura en las ubicaciones afectadas.
Por lo tanto, use la opción --clear solo si sabe exactamente lo que está haciendo. Para uso normal, los errores inyectados solo deben borrarse realizando escrituras. No espere tener los datos originales intactos después de inyectar un error y borrarlo usando --clear; se perderán, ya que la única forma "real" de borrar la ubicación del error es escribir en ella o ponerla a cero (truncar/agujerear).

-t, --status

Esta opción recuperará el estado de los errores inyectados. Tenga en cuenta que esto no recuperará todos los errores conocidos/latentes (es decir, los no inyectados), y NO es equivalente a realizar un Barrido de Rango de Direcciones.

-N, --no-notify

Esta opción solo es válida al inyectar errores. Por defecto, el comando de inyección de errores solicitará al firmware de la plataforma que active una notificación en el kernel, pidiéndole que actualice su estado de errores conocidos. Con esta opción, el error todavía se inyectará, el kernel no recibirá una notificación y el error aparecerá como un error de medios latente cuando se acceda a la ubicación. Si el firmware de la plataforma no admite esta función, esto no tendrá ningún efecto.

-S, --saturate

Esta opción fuerza la inyección o desinyección de errores para cubrir todo el rango de direcciones cubierto por el(los) bloque(s) especificado(s).

-v, --verbose

Emitir mensajes de depuración para el proceso de inyección de errores

-u, --human

Formatear números que representan tamaños de almacenamiento o desplazamientos como cadenas legibles por humanos con unidades en lugar de los datos numéricos crudos predeterminados, amigables para la máquina. Convertir otros campos numéricos a cadenas hexadecimales.

-r, --region=

Un nombre de dispositivo regionX o un número de ID de región. Restringir la operación a la(s) región(es) especificada(s). La palabra clave all se puede especificar para indicar la falta de restricción, sin embargo, esto es lo mismo que no proporcionar la opción --region en absoluto.

-b, --bus=

Un número de ID de bus o una cadena de proveedor (por ejemplo, "ACPI.NFIT"). Restringir la operación al(los) bus(es) especificado(s). La palabra clave all se puede especificar para indicar la falta de restricción, sin embargo, esto es lo mismo que no proporcionar la opción --bus en absoluto.

NAME

ndctl-inject-error - inject an error into a persistent memory device

SYNOPSIS

ndctl inject-error [-d LIBNDCTL_DEVICE] [--force] [--bus=BUS] [--device=DEVICE] [--type=TYPE] [--location=LOCATION] [--num-errors=NUM_ERRORS] [--interval=INTERVAL]

THEORY OF OPERATION

The ndctl-inject-error command is used to inject errors into a persistent memory (PMEM) device. This can be useful for testing error handling mechanisms and other fault-tolerance features of the system.

The command supports injecting various types of errors, such as correctable errors (CE) and uncorrectable errors (UCE). The type of error to inject can be specified using the --type option.

The command also allows specifying the target device, bus, and location for the error injection. The --bus, --device, and --location options can be used for this purpose. If no specific device is provided, the command may attempt to inject errors into all available PMEM devices.

The --num-errors option controls the number of errors to inject, and the --interval option specifies the time interval between injected errors.

The --force option can be used to override certain safety checks and force the error injection, even if it might lead to data corruption or instability.

EXAMPLES

Inject a single correctable error (CE) into the PMEM device with ID 0:

ndctl inject-error --bus=0 --device=0 --type=ce --num-errors=1

Inject 10 uncorrectable errors (UCE) into all PMEM devices with a 1-second interval:

ndctl inject-error --type=uce --num-errors=10 --interval=1

Force injection of a correctable error into a specific device (use with caution):

ndctl inject-error -d namespace0.0 --type=ce --force

OPTIONS

-d LIBNDCTL_DEVICE
Specify the libndctl device name to inject errors into. This can be a specific device name like namespace0.0 or a general path like /dev/pmem0.
--force
Force the error injection. This option may override safety checks and could potentially lead to data loss or system instability. Use with extreme caution.
--bus=BUS
Specify the bus number of the PMEM device.
--device=DEVICE
Specify the device number of the PMEM device.
--type=TYPE
Specify the type of error to inject. Supported types may include ce (correctable error) and uce (uncorrectable error). Check the documentation for supported values.
--location=LOCATION
Specify the error location within the device, if supported by the hardware and driver.
--num-errors=NUM_ERRORS
The number of errors to inject. Defaults to 1 if not specified.
--interval=INTERVAL
The interval in seconds between injecting errors. This is only applicable when injecting more than one error.

El comando ndctl-inject-error se utiliza para inyectar errores en un dispositivo de memoria persistente (PMEM). Esto puede ser útil para probar mecanismos de manejo de errores y otras características de tolerancia a fallos del sistema.

El comando soporta la inyección de varios tipos de errores, como errores corregibles (CE) y errores incorregibles (UCE). El tipo de error a inyectar se puede especificar usando la opción --type.

La opción --force se puede usar para anular ciertas verificaciones de seguridad y forzar la inyección de errores, incluso si esto pudiera provocar corrupción de datos o inestabilidad.

Forzar la inyección de un error corregible en un dispositivo específico (usar con precaución):
