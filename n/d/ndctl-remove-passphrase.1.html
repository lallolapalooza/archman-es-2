NDCTL-REMOVE-PASSPHRASE(1) ndctl Manual NDCTL-REMOVE-PASSPHRASE(1)

NOMBRE

ndctl-remove-passphrase - Detiene un DIMM de bloquearse ante pérdida de energía y requerir una contraseña para acceder a los medios

SINOPSIS

ndctl remove-passphrase <nmem0> [<nmem1>..<nmemN>] [<opciones>]

DESCRIPCIÓN

Busca en el keyring del usuario una contraseña cifrada para el NVDIMM en cuestión. Si no se encuentra, intenta cargar el blob de la contraseña. Después de deshabilitar la contraseña, elimina la clave-ID del keyring, así como el blob de la contraseña del sistema de archivos.

OPCIONES

<dimm>

Un nombre de dispositivo nmemX, o un número de ID de dimm. Restringe la operación a los dimms especificados. La palabra clave all puede especificarse para indicar la ausencia de cualquier restricción; sin embargo, esto es lo mismo que no suministrar ninguna opción --dimm.

-b, --bus=

Un número de ID de bus, o una cadena de proveedor (por ejemplo, "ACPI.NFIT"). Restringe la operación a los buses especificados. La palabra clave all puede especificarse para indicar la ausencia de cualquier restricción; sin embargo, esto es lo mismo que no suministrar ninguna opción --bus.

-v, --verbose

Emite mensajes de depuración.

-m, --master-passphrase

Indica que estamos gestionando la contraseña maestra en lugar de la contraseña del usuario.

TEORÍA DE OPERACIÓN

Las Especificaciones de Métodos Específicos del Dispositivo (DSM) de Intel v1.7 y v1.8 [1] introdujeron las siguientes operaciones de gestión de seguridad: habilitar contraseña, actualizar contraseña, desbloquear DIMM, deshabilitar seguridad, congelar seguridad, borrado seguro (criptográfico), sobrescribir, habilitar contraseña maestra, actualizar contraseña maestra y borrado seguro de contraseña maestra.

La gestión de seguridad para NVDIMMs consta de dos partes. El frontend utiliza el framework de gestión de claves de Linux (claves confiables y cifradas [2]) para almacenar las contraseñas cifradas en el keyring gestionado por el kernel. La interfaz para esto es la utilidad keyutils, que utiliza las APIs de gestión de claves en el kernel de Linux. El backend toma el payload descifrado (que es la contraseña del DIMM) y se lo pasa al DIMM.

A diferencia de otros DSM, que son compuestos por libndctl y enviados al kernel a través de una llamada ioctl, los DSM de seguridad se gestionan a través del atributo security de sysfs bajo el dispositivo dimm. Se escribe una key-ID en el atributo security y el kernel extrae el material de clave asociado del keyring del usuario mantenido por el kernel.

El proceso de seguridad comienza con la generación de una clave maestra que se utiliza para sellar (cifrar) la contraseña del DIMM. Puede haber una única clave maestra común que se utilice para cifrar la contraseña de cada DIMM, o se puede generar una clave separada para cada DIMM. La clave maestra también se conoce como clave de cifrado de clave (key-encryption-key, kek). La kek puede ser generada por el TPM (Trusted Platform Module) en el sistema, o alternativamente, la Clave Maestra del Sistema también puede usarse como kek.

Para fines de prueba, también se puede usar una clave de usuario con un payload aleatorio como kek. Consulte [2] para obtener más detalles. Para realizar cualquier operación de seguridad, se espera que la kek se haya agregado al keyring de usuario del kernel, como se muestra en el siguiente ejemplo:

# keyctl show
Session Keyring
 736023423 --alswrv      0     0  keyring: _ses
 675104189 --alswrv      0 65534   \_ keyring: _uid.0
 680187394 --alswrv      0     0       \_ trusted: nvdimm-master

Antes de realizar cualquiera de las operaciones de seguridad, todas las regiones asociadas con el DIMM en cuestión deben deshabilitarse. Para la operación de sobrescribir, además de las regiones, el dimm también debe deshabilitarse.

[1] http://pmem.io/documents/NVDIMM_DSM_Interface-V1.8.pdf
[2] https://www.kernel.org/doc/Documentation/security/keys/trusted-encrypted.rst

Las siguientes subsecciones describen los detalles de cada característica de seguridad.

DESBLOQUEAR

El desbloqueo lo realiza el kernel, sin embargo, se debe realizar un paso de preparación antes de que el kernel pueda emitir el DSM de desbloqueo. Se espera que desde el initramfs, se ejecute un comando de configuración (ndctl load-keys) antes de que el módulo libnvdimm sea cargado por modprobe. Este comando inyectará la kek y las contraseñas cifradas en el keyring de usuario del kernel. Durante la sonda del driver libnvdimm, realizará lo siguiente:

1.Verificará el estado de seguridad del dispositivo y verá si el DIMM está bloqueado
2.Solicitará el blob de contraseña cifrada asociado del keyring de usuario del kernel
3.Usará la kek para descifrar el blob de contraseña
4.Creará el DSM de desbloqueo, copiará el payload descifrado en el DSM
5.Emitirá el DSM para desbloquear el DIMM

Si el DIMM ya está desbloqueado, el kernel intentará revalidar la contraseña. Si no logramos revalidar la contraseña, el kernel congelará la seguridad y prohibirá cualquier cambio posterior en la configuración de seguridad. Hay un parámetro de módulo del kernel disponible para anular este comportamiento.

CONFIGURAR CONTRASEÑA DE USUARIO

Para configurar la contraseña de un DIMM, se espera que la kek a utilizar esté presente en el keyring de usuario del kernel. La kek cifra la contraseña del DIMM utilizando el formato de clave enc32. La contraseña en texto plano nunca es proporcionada ni visible para el usuario. En su lugar, es generada aleatoriamente por el kernel y el espacio de usuario no tiene acceso a ella. Tras el cifrado, se escribe un blob binario de la contraseña en el directorio de almacenamiento de blobs de contraseña (/etc/ndctl/keys). El usuario es responsable de hacer copias de seguridad de los blobs de contraseña en una ubicación segura.

ACTUALIZAR CONTRASEÑA DE USUARIO

La operación de actualización de contraseña de usuario utiliza el mismo comando DSM que la habilitación de contraseña de usuario. La mayor parte del trabajo se realiza en el lado de la gestión de claves. El usuario tiene la opción de proporcionar una nueva kek para la nueva contraseña, pero continuar usando la kek existente también es aceptable. Las siguientes operaciones se realizan para update-passphrase:

1.Elimina la contraseña cifrada del keyring de usuario del kernel.
2.Renombra el blob de contraseña a old.
3.Carga este blob de contraseña antiguo en el keyring con el nombre "old".
4.Crea la nueva contraseña y la cifra con la kek.
5.Envía el DSM con las contraseñas descifradas antigua y nueva.
6.Elimina la contraseña antigua y el blob de contraseña del keyring.

ELIMINAR CONTRASEÑA DE USUARIO

La key-ID de la contraseña a eliminar se escribe en sysfs. Luego, el kernel envía el DSM para deshabilitar la seguridad, y la contraseña se elimina del keyring, y el blob de contraseña asociado se borra.

BORRADO CRIPTOGRÁFICO (SEGURO)

Esta operación es similar a remove-passphrase. El kernel emite una instrucción WBINVD antes y después de la operación para asegurar que no haya corrupción de datos debido a una caché de CPU obsoleta. Utilice el comando sanitize-dimm de ndctl con la opción --crypto-erase para realizar esta operación.

SOBRESCRITURA

Esto se invoca usando la opción --overwrite para el comando sanitize-dimm de ndctl. La operación de sobrescritura borra todo el NVDIMM. La operación puede llevar una cantidad de tiempo considerable. NOTA: Cuando el comando retorna con éxito, solo significa que la sobrescritura se ha iniciado correctamente, y no que la sobrescritura esté completa. ndctl-remove-passphrase(1) — ndctl

NAME

ndctl-remove-passphrase — remove security passphrase from Intel Optane™ persistent memory

SYNOPSIS

ndctl remove-passphrase [-a | --all] [-d DEV | --device=DEV] [-p PASS | --passphrase=PASS]

DESCRIPTION

The ndctl-remove-passphrase command removes a security passphrase from a given namespace or all namespaces on a given device. If no device is specified, then all devices are processed. If no passphrase is provided via the command line, the user will be prompted to enter the passphrase interactively.

Removing the passphrase will disable security features that rely on it (e.g. data encryption). It is recommended to erase the data on the namespace before removing the passphrase to prevent unauthorized access to data.

See also ndctl-setup-passphrase(1) and ndctl-update-passphrase(1).

OPTIONS

-a, --all
Process all namespaces on the specified device. Without this option, only the first namespace found will be processed.
-d DEV, --device=DEV
Process the specified DEV. The device may be specified as a path (e.g. /dev/ndctl0) or as a PCI address.
-p PASS, --passphrase=PASS
Specify the passphrase to be used. If this option is not provided, the user will be interactively prompted for the passphrase.

THEORY OF OPERATION

This command interacts with the Intel Memory Technology (MT) Security Subsystem of the Persistent Memory Controller. The MT Security Subsystem supports a security feature that allows namespaces to be locked down with a passphrase. When a namespace is locked, any operation that modifies the namespace or its metadata requires the correct passphrase to be supplied. This includes operations like setup-namespace, update-namespace, and disable-namespace. Operations that query the status of the namespace, such as list-namespaces, do not require a passphrase.

The security passphrase is an AES-XTS key, which is derived from the user-supplied passphrase. The AES-XTS key is used to encrypt the namespace data and metadata. The namespace passphrase is itself encrypted and stored as part of the namespace metadata.

The remove-passphrase command removes the security passphrase from the namespace. This operation requires the current passphrase to be supplied. Once the passphrase is removed, the namespace is no longer encrypted and can be modified without a passphrase.

The remove-passphrase command can be used in conjunction with the --crypto-erase and --overwrite options. The --crypto-erase option erases the namespace by generating a new encryption key and discarding the old one. This effectively renders the previous data unrecoverable. The --overwrite option erases the namespace by overwriting the entire contents with zeros. If both --crypto-erase and --overwrite options are supplied, then crypto-erase is performed before overwrite.

The WBINVD instruction is issued by the kernel. If both --crypto-erase and --overwrite options are supplied, then crypto-erase is performed before overwrite.

SECURITY FREEZE

This operation does not require a passphrase. This will cause any security command other than a status query to be locked out until the next boot.

MASTER PASSPHRASE SETUP, UPDATE, and CRYPTO ERASE

These operations are similar to the user passphrase enable and update. The only difference is that a different passphrase is used. The master passphrase has no relation to the master key (kek) which is used for encryption of either passphrase.
