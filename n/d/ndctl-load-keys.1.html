NOMBRE

ndctl-load-keys - Carga la kek y las contraseñas cifradas en el almacén de claves

SINOPSIS

ndctl load-keys [<opciones>]

DESCRIPCIÓN

El comando load-keys carga la clave maestra (kek) y las contraseñas cifradas de todos los NVDIMM en el almacén de claves del usuario mantenido por el kernel. Se espera que el comando se llame durante la inicialización y antes de que se cargue el módulo del kernel libnvdimm, típicamente desde un initrd. Esto se configura típicamente usando una configuración de modprobe que llama al comando antes de cargar el módulo.


Nota

Se espera que todos los archivos de claves tengan el formato: nvdimm_<id>_nombre_host
El carácter '_' se usa para delimitar los diferentes componentes en el nombre del archivo. Dentro del nombre del host, el carácter '_' está permitido ya que es el último componente del nombre del archivo.


Nota

Este comando normalmente nunca es llamado directamente por un usuario.

OPCIONES

-p, --key-path=

Ruta a donde residen los archivos relacionados con las claves. Este parámetro es opcional y la ubicación predeterminada es /etc/ndctl/keys.

-t, --tpm-handle=

Proporciona un identificador de TPM (debería ser una cadena como 0x81000001). Si la ruta de las claves (/etc/ndctl/keys) contiene un archivo llamado tpm.handle que contiene la cadena del identificador, entonces esta opción puede omitirse y el identificador del TPM se obtendrá del archivo. Si ambos están presentes, entonces esta opción anulará (pero no sobrescribirá) cualquier cosa que esté en el archivo.

TEORÍA DE OPERACIÓN

Los Métodos Específicos del Dispositivo Intel (DSM) especificación v1.7 y v1.8 [1] introdujeron las siguientes operaciones de gestión de seguridad: habilitar contraseña, actualizar contraseña, desbloquear DIMM, desactivar seguridad, congelar seguridad, borrar de forma segura (criptográfica), sobrescribir, habilitar contraseña maestra, actualizar contraseña maestra y borrado seguro de contraseña maestra.

La gestión de seguridad para los NVDIMM consta de dos partes. El frontend utiliza el framework de gestión de claves de Linux (claves cifradas y de confianza [2]) para almacenar las contraseñas cifradas en el almacén de claves gestionado por el kernel. La interfaz para esto es la utilidad keyutils que utiliza las API de gestión de claves en el kernel de Linux. El backend toma la carga útil descifrada (que es la contraseña del DIMM) y la pasa al DIMM.

A diferencia de otros DSMs que son compuestos por libndctl y enviados al kernel a través de un ioctl, los DSMs de seguridad se gestionan a través del atributo security de sysfs bajo el dispositivo dimm. Se escribe un key-ID en el atributo security y el kernel extrae el material de clave asociado del almacén de claves del usuario mantenido por el kernel.

El proceso de seguridad comienza con la generación de una clave maestra que se utiliza para sellar (cifrar) la contraseña del DIMM. Puede haber una clave maestra común que se utiliza para cifrar la contraseña de cada DIMM, o se puede generar una clave separada para cada DIMM. La clave maestra también se conoce como clave de cifrado de clave (kek). La kek puede ser generada por el TPM (Trusted Platform Module) en el sistema, o alternativamente, la Clave Maestra del Sistema también puede usarse como la kek.

Para fines de prueba, una clave de usuario con carga útil aleatoria también se puede usar como kek. Ver [2] para más detalles. Para realizar cualquier operación de seguridad, se espera que la kek se haya agregado al almacén de claves del usuario del kernel como se muestra en el siguiente ejemplo:

# keyctl show
Session Keyring
 736023423 --alswrv      0     0  keyring: _ses
 675104189 --alswrv      0 65534   \_ keyring: _uid.0
 680187394 --alswrv      0     0       \_ trusted: nvdimm-master

Antes de realizar cualquiera de las operaciones de seguridad, todas las regiones asociadas con el DIMM en cuestión deben ser deshabilitadas. Para la operación de sobrescribir, además de las regiones, el dimm también debe ser deshabilitado.

[1] http://pmem.io/documents/NVDIMM_DSM_Interface-V1.8.pdf
[2] https://www.kernel.org/doc/Documentation/security/keys/trusted-encrypted.rst

Las siguientes subsecciones describen los detalles de cada función de seguridad.

DESBLOQUEAR

El desbloqueo lo realiza el kernel, sin embargo, debe ocurrir un paso de preparación antes de que el kernel pueda emitir el DSM de desbloqueo. Se espera que desde el initramfs, un comando de configuración (ndctl load-keys) se ejecute antes de que el módulo libnvdimm sea cargado por modprobe. Este comando inyectará la kek y las contraseñas cifradas en el almacén de claves del usuario del kernel. Durante el probe del controlador libnvdimm, hará lo siguiente:

1.Verifica el estado de seguridad del dispositivo y ve si el DIMM está bloqueado
2.Solicita la contraseña cifrada asociada del almacén de claves del usuario del kernel
3.Usa la kek para descifrar la contraseña
4.Crea el DSM de desbloqueo, copia la carga útil descifrada en el DSM
5.Emite el DSM para desbloquear el DIMM

Si el DIMM ya está desbloqueado, el kernel intentará revalidar la contraseña. Si no logramos revalidar la contraseña, el kernel congelará la seguridad y prohibirá cualquier cambio adicional en la configuración de seguridad. Hay un parámetro del módulo del kernel disponible para anular este comportamiento.

CONFIGURAR CONTRASEÑA DE USUARIO

Para configurar la contraseña de un DIMM, se espera que la kek a utilizar esté presente en el almacén de claves del usuario del kernel. La kek cifra la contraseña del DIMM usando el formato de clave enc32. La contraseña en texto plano nunca es proporcionada ni visible para el usuario. En su lugar, es generada aleatoriamente por el kernel y el espacio de usuario no tiene acceso a ella. Tras el cifrado, un blob binario de la contraseña se escribe en el directorio de almacenamiento de blobs de contraseñas (/etc/ndctl/keys). El usuario es responsable de hacer copias de seguridad de los blobs de contraseñas en una ubicación segura.

ACTUALIZAR CONTRASEÑA DE USUARIO

La operación de actualización de contraseña de usuario utiliza el mismo comando DSM que la habilitación de contraseña de usuario. La mayor parte del trabajo se realiza en el lado de la gestión de claves. El usuario tiene la opción de proporcionar una nueva kek para la nueva contraseña, pero continuar usando la kek existente también es aceptable. Las siguientes operaciones se realizan para actualizar-contraseña:

1.Elimina la contraseña cifrada del almacén de claves del usuario del kernel.
2.Renombra el blob de contraseña a old.
3.Carga este blob de contraseña antiguo en el almacén de claves con un nombre "old".
4.Crea la nueva contraseña y la cifra con la kek.
5.Envía el DSM con las contraseñas descifradas antiguas y nuevas.
6.Elimina la contraseña antigua y el blob de contraseña del almacén de claves.

ELIMINAR CONTRASEÑA DE USUARIO

El key-ID de la contraseña a eliminar se escribe en sysfs. El kernel luego envía el DSM para deshabilitar la seguridad, y la contraseña se elimina del almacén de claves, y el blob de contraseña asociado se elimina.

BORRADO CRIPTO (SEGURO)

Esta operación es similar a eliminar-contraseña. El kernel emite una instrucción WBINVD antes y después de la operación para asegurar que no haya corrupción de datos por una caché de CPU obsoleta. Usa el comando sanitize-dimm de ndctl con la opción --crypto-erase para realizar esta operación.

NAME

ndctl-load-keys - load security keys into the NVDIMM namespace

SYNOPSIS

ndctl load-keys [--key=path] [--passphrase-file=path] [--passphrase=string] [--crypto-erase] [--overwrite] [--force]

DESCRIPTION

The ndctl load-keys command loads the security keys into the NVDIMM namespace. The keys can be loaded from a file specified with --key, or from a passphrase provided via a file using --passphrase-file or directly using --passphrase.

By default, the command will attempt to load the key for the NVDIMM namespace security, if it has been previously set. If the security key has not been set, the command will initialize the security key using the provided key or passphrase.

If the NVDIMM namespace has been previously locked with a security passphrase, ndctl load-keys will attempt to unlock it using the provided passphrase. If the unlock is successful, the namespace will be ready to have its security key loaded. If the unlock fails, the command will fail.

If the NVDIMM namespace has not been previously locked, ndctl load-keys will initialize the security by setting the security key using the provided key or passphrase.

The --force option can be used to force the operation, even if the NVDIMM namespace security is already set. This can be useful for resetting the security key or re-initializing the security features.

OPTIONS

--key=path
Specifies the path to a file containing the security key to be loaded.
--passphrase-file=path
Specifies the path to a file containing the security passphrase.
--passphrase=string
Specifies the security passphrase as a string.
--crypto-erase
Perform a crypto erase on the NVDIMM namespace before loading the security key. This is a secure erase method that encrypts the namespace with a new random key, effectively rendering the old data irrecoverable.
--overwrite
Perform an overwrite on the NVDIMM namespace before loading the security key. This is a destructive erase method that overwrites the entire namespace with a pattern of zeroes. This operation can take a significant amount of time.
--force
Force the operation. This will overwrite any existing security key or passphrase, and re-initialize the security features of the NVDIMM namespace.

THEORY OF OPERATION

The NVDIMM security subsystem provides a mechanism for protecting data stored on NVDIMMs from unauthorized access. It supports two primary security operations: encryption and erase.

When the security is enabled on an NVDIMM namespace, the data stored within that namespace is encrypted using a symmetric key. This key, referred to as the namespace key, is generated randomly and is unique to each namespace. The namespace key itself is protected by a master key, often referred to as the key encryption key (KEK).

The KEK is derived from a user-provided passphrase or a separately provided security key. This allows users to control access to their NVDIMM data by managing the passphrase or key. The NVDIMM firmware is responsible for securely storing and managing the KEK and the namespace keys.

The ndctl load-keys command interacts with the NVDIMM security subsystem to manage these keys. Specifically:

  • Passphrase Handling: The command accepts a passphrase either directly via the command line or from a file. This passphrase is used to derive the KEK. If a passphrase is already set on the NVDIMM namespace, the provided passphrase must match to unlock the namespace for further operations. If no passphrase is set, the provided passphrase will be used to initialize the security.

  • Key Loading: The command can also load a pre-generated security key from a file using the --key option. This key is used directly as the KEK, bypassing the need for passphrase derivation.

  • Security Erase Operations:

    • Crypto Erase (--crypto-erase): This is the most secure and recommended erase method. It involves generating a new, random namespace key and encrypting the entire namespace with it. The old namespace key becomes inaccessible, effectively making the previous data irrecoverable without knowing the new KEK. The old KEK derived from the old passphrase is discarded.

    • Overwrite (--overwrite): This method performs a standard data overwrite by writing a pattern (typically zeros) across the entire NVDIMM namespace. While this destroys the data, it is generally considered less secure than crypto erase, as sophisticated techniques might potentially recover residual data. The ndctl wait-overwrite command can be used to monitor the progress of this operation.

  • Forcing Operations (--force): This option allows the user to bypass certain checks and force the loading of keys or initiation of erase operations, even if the namespace is already secured or has existing keys. Use with caution, as it can lead to unintended data loss or security configurations.

Important Note on Overwrite: Initiating an overwrite operation using ndctl load-keys --overwrite does not mean the overwrite is complete. It only signifies that the overwrite process has been successfully started. You must subsequently use ndctl wait-overwrite to monitor the progress and confirm the completion of the overwrite process. After a successful overwrite, the kernel issues the WBINVD instruction. If both --crypto-erase and --overwrite options are provided, the crypto-erase operation is performed before the overwrite.

SECURITY FREEZE

This operation does not require a passphrase. This will cause any security command other than a status query to be locked out until the next boot.

MASTER PASSPHRASE SETUP, UPDATE, and CRYPTO ERASE

These operations are similar to the user passphrase enable and update. The only difference is that a different passphrase is used. The master passphrase has no relation to the master key (kek) which is used for encryption of either passphrase.
