NDCTL-UPDATE-PASSPHRASE(1) Manual de ndctl NDCTL-UPDATE-PASSPHRASE(1)

NOMBRE

ndctl update-passphrase - actualiza la contraseña de seguridad para un NVDIMM

SINOPSIS

ndctl update-passphrase <nmem0> [<nmem1>..<nmemN>] [<opciones>]

DESCRIPCIÓN

Actualiza la contraseña de seguridad para uno o más NVDIMMs. Prerrequisitos para que el comando tenga éxito:

1.La kek (clave de cifrado de clave) se ha cargado en el keyring de usuario del kernel.
2.setup-passphrase se ha ejecutado correctamente en el NVDIMM.
•Alternativamente, el NVDIMM está desbloqueado.

Los blobs de clave actualizados se crearán en el directorio /etc/ndctl/keys con un formato de nombre de archivo de "nvdimm_<id-único-dimm>_<nombre-host>.blob".

OPCIONES

<dimm>

Un nombre de dispositivo nmemX, o un número de ID de dimm. Restringe la operación al(los) dimm(s) especificado(s). La palabra clave all puede especificarse para indicar la ausencia de cualquier restricción, sin embargo, esto es lo mismo que no proporcionar ninguna opción --dimm.

-b, --bus=

Un número de ID de bus, o una cadena de proveedor (por ejemplo, "ACPI.NFIT"). Restringe la operación al(los) bus(es) especificado(s). La palabra clave all puede especificarse para indicar la ausencia de cualquier restricción, sin embargo, esto es lo mismo que no proporcionar ninguna opción --bus.

-k, --key_handle=

Identificador para la kek maestra (clave de cifrado de clave) que se utilizará para sellar las contraseñas para el(los) DIMM(s) dado(s). El formato es: <tipo de clave>:<descripción de clave>, por ejemplo trusted:nvdimm-master
NOTA: Se espera que la kek se haya cargado en el keyring de usuario.

-m, --master-passphrase

Indica que estamos gestionando la contraseña maestra en lugar de la contraseña de usuario.

-v, --verbose

Emite mensajes de depuración.

TEORÍA DE OPERACIÓN

Las Especificaciones de Métodos Específicos del Dispositivo de Intel (DSM) v1.7 y v1.8 [1] introdujeron las siguientes operaciones de gestión de seguridad: habilitar contraseña, actualizar contraseña, desbloquear DIMM, deshabilitar seguridad, congelar seguridad, borrar (criptográficamente) borrar, sobrescribir, habilitar contraseña maestra, actualizar contraseña maestra y borrar de forma segura la contraseña maestra.

La gestión de seguridad para NVDIMMs consta de dos partes. El front-end utiliza el marco de gestión de claves de Linux (claves confiables y cifradas [2]) para almacenar las contraseñas cifradas en el keyring gestionado por el kernel. La interfaz para esto es la utilidad keyutils que utiliza las APIs de gestión de claves en el kernel de Linux. El back-end toma la carga útil descifrada (que es la contraseña del DIMM) y la pasa al DIMM.

A diferencia de otros DSM, que son compuestos por libndctl y enviados al kernel a través de un ioctl, los DSM de seguridad se gestionan a través del atributo security de sysfs bajo el dispositivo dimm. Se escribe un ID de clave en el atributo security y el kernel extrae el material de clave asociado del keyring de usuario que es mantenido por el kernel.

El proceso de seguridad comienza con la generación de una clave maestra que se utiliza para sellar (cifrar) la contraseña del DIMM. Puede haber una clave maestra común que se utiliza para cifrar la contraseña de cada DIMM, o se puede generar una clave separada para cada DIMM. La kek (clave de cifrado de clave) también se conoce como clave de cifrado de clave. La kek puede ser generada por el TPM (Módulo de Plataforma Confiable) en el sistema, o alternativamente, la Clave Maestra del Sistema también puede usarse como la kek.

Para fines de prueba, una clave de usuario con carga útil aleatoria también puede usarse como una kek. Ver [2] para más detalles. Para realizar cualquier operación de seguridad, se espera que la kek se haya agregado al keyring de usuario del kernel como se muestra en el ejemplo a continuación:

# keyctl show
Clave de sesión
 736023423 --alswrv      0     0  keyring: _ses
 675104189 --alswrv      0 65534   \_ keyring: _uid.0
 680187394 --alswrv      0     0       \_ trusted: nvdimm-master

Antes de realizar cualquiera de las operaciones de seguridad, todas las regiones asociadas con el DIMM en cuestión deben deshabilitarse. Para la operación de sobrescritura, además de las regiones, el dimm también debe deshabilitarse.

[1] http://pmem.io/documents/NVDIMM_DSM_Interface-V1.8.pdf
[2] https://www.kernel.org/doc/Documentation/security/keys/trusted-encrypted.rst

Las siguientes subsecciones describen los detalles de cada característica de seguridad.

DESBLOQUEAR

El desbloqueo lo realiza el kernel, sin embargo, debe haber un paso de preparación antes de que el kernel pueda emitir el DSM de desbloqueo. Se espera que, desde el initramfs, se ejecute un comando de configuración (ndctl load-keys) antes de que el módulo libnvdimm sea cargado por modprobe. Este comando inyectará la kek y las contraseñas cifradas en el keyring de usuario del kernel. Durante la sonda del controlador libnvdimm, se:

1.Verificará el estado de seguridad del dispositivo y se comprobará si el DIMM está bloqueado.
2.Se solicitará la contraseña cifrada asociada al keyring de usuario del kernel.
3.Se utilizará la kek para descifrar la contraseña.
4.Se creará el DSM de desbloqueo y se copiará la carga útil descifrada en el DSM.
5.Se emitirá el DSM para desbloquear el DIMM.

Si el DIMM ya está desbloqueado, el kernel intentará revalidar la contraseña. Si no logramos revalidar la contraseña, el kernel congelará la seguridad y no permitirá más cambios de configuración de seguridad. Hay un parámetro del módulo del kernel disponible para anular este comportamiento.

CONFIGURAR CONTRASEÑA USUARIO

Para configurar la contraseña de un DIMM, se espera que la kek a utilizar esté presente en el keyring de usuario del kernel. La kek cifra la contraseña del DIMM utilizando el formato de clave enc32. La contraseña en texto plano nunca es proporcionada ni visible para el usuario. En su lugar, es generada aleatoriamente por el kernel y el espacio de usuario no tiene acceso a ella. Tras el cifrado, se escribe un blob binario de la contraseña en el directorio de almacenamiento de blobs de contraseña (/etc/ndctl/keys). El usuario es responsable de hacer copias de seguridad de los blobs de contraseña en una ubicación segura.

ACTUALIZAR CONTRASEÑA USUARIO

La operación de actualizar contraseña de usuario utiliza el mismo comando DSM que la habilitación de contraseña de usuario. La mayor parte del trabajo se realiza en el lado de la gestión de claves. El usuario tiene la opción de proporcionar una nueva kek para la nueva contraseña, pero continuar usando la kek existente también es aceptable. Las siguientes operaciones se realizan para update-passphrase:

1.Se elimina la contraseña cifrada del keyring de usuario del kernel.
2.Se renombra el blob de contraseña a old.
3.Se carga este blob de contraseña antiguo en el keyring con un nombre "old".
4.Se crea la nueva contraseña y se cifra con la kek.
5.Se envía el DSM con las contraseñas antiguas y nuevas descifradas.
6.Se elimina la contraseña antigua y el blob de contraseña del keyring.

ELIMINAR CONTRASEÑA USUARIO

El ID de clave de la contraseña a eliminar se escribe en sysfs. El kernel luego envía el DSM para deshabilitar la seguridad, y la contraseña se elimina del keyring, y el blob de contraseña asociado se elimina.

BORRADO CRIPTOGRÁFICO (SEGURO)

Esta operación es similar a eliminar-contraseña. El kernel emite una instrucción WBINVD antes y después de la operación para asegurar que no haya corrupción de datos por una caché de CPU obsoleta. Use el comando sanitize-dimm de ndctl con la opción --crypto-erase para realizar este

NAME

ndctl-sanitize-dimm - sanitize NVDIMM(s)

SYNOPSIS

ndctl sanitize-dimm [--region REGION] [--namespace NAMESPACE] [--all] [--user-passphrase PASSPHRASE] [--master-passphrase PASSPHRASE] [--crypto-erase] [--overwrite] [--security-freeze]

DESCRIPTION

The ndctl sanitize-dimm command is used to sanitize NVDIMMs. Sanitization is the process of securely erasing the data contained within the NVDIMM. There are multiple methods of sanitization supported, including cryptographic erase and overwriting the entire device.

Depending on the security policy of the NVDIMM, sanitization operations may require the user-passphrase or master-passphrase. If the NVDIMM has a user passphrase configured, and the command is not provided with a matching user passphrase, the command will fail. Similarly, if the NVDIMM has a master passphrase configured, and the command is not provided with a matching master passphrase, the command will fail.

If neither passphrase is provided, and the NVDIMM has a passphrase configured, the command will fail. If the NVDIMM has no passphrase configured, the operation will proceed without requiring a passphrase.

If the NVDIMM has both a user and master passphrase configured, the user passphrase must be supplied. The master passphrase is not required for sanitization.

Multiple NVDIMMs can be selected for sanitization using --region, --namespace, or --all options. If no target is specified, the command defaults to sanitizing all NVDIMMs.

The available sanitization operations are:

CRYPTO-ERASE
This operation securely erases the NVDIMM by instructing the device to internally destroy the encryption key associated with the NVDIMM's data. This is the fastest and most secure method of sanitization, provided the NVDIMM supports it.
OVERWRITE
This operation securely erases the NVDIMM by overwriting all data on the device with a specified pattern (often zeros). This operation can be time-consuming.
SECURITY-FREEZE
This command locks NVDIMM security-related commands until the next system boot. It does not require a passphrase.

If multiple sanitization operations are requested (e.g., --crypto-erase and --overwrite), they will be performed in the order specified. However, CRYPTO-ERASE is typically performed before OVERWRITE if both are requested, as it is more efficient.

OPTIONS

The following options are available:

--region REGION
Specifies the target region for the sanitization operation. REGION can be an integer ID or a name.
--namespace NAMESPACE
Specifies the target namespace for the sanitization operation. NAMESPACE can be an integer ID or a name.
--all
Applies the sanitization operation to all NVDIMMs managed by ndctl.
--user-passphrase PASSPHRASE
Provides the user passphrase for NVDIMMs that are locked with a user passphrase. This is required for most security operations if a user passphrase is set.
--master-passphrase PASSPHRASE
Provides the master passphrase for NVDIMMs that are locked with a master passphrase. Note that the user passphrase is generally used for security operations like sanitization, not the master passphrase.
--crypto-erase
Initiates a cryptographic erase operation. This is the preferred method for sanitization if supported by the NVDIMM.
--overwrite
Initiates an overwrite operation, which wipes the entire NVDIMM by writing data over it. This operation can take a significant amount of time.
--security-freeze
Locks down security settings on the NVDIMM until the next boot. Any subsequent security command (except status query) will be denied until the system is rebooted.

THEORY OF OPERATION

When ndctl sanitize-dimm is invoked with the --crypto-erase option, it sends a command to the NVDIMM instructing it to perform a cryptographic erase. This is typically achieved by the NVDIMM discarding its internal encryption key, rendering the data inaccessible.

When invoked with the --overwrite option, it initiates an overwrite operation. The operation can take a significant amount of time. NOTE: When the command returns successfully, it just means overwrite has been successfully started, and not that the overwrite is complete. Subsequently, ndctl wait-overwrite can be used to wait for the NVDIMMs that are performing overwrite. Upon successful completion of an overwrite, the WBINVD instruction is issued by the kernel. If both --crypto-erase and --overwrite options are supplied, then crypto-erase is performed before overwrite.

The --security-freeze operation does not require a passphrase. This will cause any security command other than a status query to be locked out until the next boot.

The master passphrase operations (SETUP, UPDATE, and CRYPTO ERASE) are similar to the user passphrase enable and update. The only difference is that a different passphrase is used. The master passphrase has no relation to the master key (kek) which is used for encryption of either passphrase.
