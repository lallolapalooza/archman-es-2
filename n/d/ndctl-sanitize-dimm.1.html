NOMBRE

ndctl-sanitize-dimm - Realiza una destrucción criptográfica o una sobrescritura del contenido del(los) NVDIMM(s) especificado(s)

SINOPSIS

ndctl sanitize-dimm <nmem0> [<nmem1>..<nmemN>] [<opciones>]

DESCRIPCIÓN

El comando sanitize-dimm realiza una destrucción criptográfica del contenido del NVDIMM especificado. Mezcla los datos, así como cualquier metadato o bloque de información, pero no modifica las etiquetas de los espacios de nombres. Por lo tanto, cualquier espacio de nombres en regiones asociadas con el NVDIMM especificado se conservará, pero terminará en modo raw (crudo).

Además, una vez completado este comando, la seguridad y la contraseña para el NVDIMM especificado se deshabilitarán, y la contraseña y cualquier material de clave también se eliminarán del keyring y del directorio de claves de ndctl en /etc/ndctl/keys.

El comando admite dos métodos diferentes para realizar el borrado criptográfico. El predeterminado es crypto-erase (borrado criptográfico), pero además, hay una opción de overwrite (sobrescritura) disponible que sobrescribe no solo el área de datos, sino también el área de etiquetas, perdiendo así el registro de cualquier espacio de nombres en el que participe el NVDIMM especificado.

OPCIONES

<dimm>

Un nombre de dispositivo nmemX, o un número de ID de dimm. Restringe la operación al(los) dimm(s) especificado(s). La palabra clave all (todo) puede especificarse para indicar la ausencia de restricción alguna, sin embargo, esto es lo mismo que no proporcionar una opción --dimm en absoluto.

-b, --bus=

Un número de ID de bus, o una cadena de proveedor (por ejemplo, "ACPI.NFIT"). Restringe la operación al(los) bus(es) especificado(s). La palabra clave all puede especificarse para indicar la ausencia de restricción alguna, sin embargo, esto es lo mismo que no proporcionar una opción --bus en absoluto.

-c, --crypto-erase

Reemplaza la clave de cifrado del medio en el NVDIMM, haciendo que todos los datos existentes se lean como texto cifrado con la nueva clave. Esto no cambia los datos de la etiqueta. Los espacios de nombres se revierten al modo crudo.

-o, --overwrite

Borra todo el DIMM, incluidos los datos de la etiqueta. Esto puede llevar un tiempo considerable y el comando no es bloqueante. Con esta opción, la solicitud de sobrescritura simplemente se envía al NVDIMM y la finalización es asíncrona. Dependiendo del medio y la capacidad, la sobrescritura puede llevar desde decenas de minutos hasta muchas horas.

-m, --master-passphrase

Indica que se está utilizando la contraseña maestra para realizar el borrado. Esto solo es aplicable a la opción crypto-erase.

-z, --zero-key

Pasar una clave con una carga útil que solo contenga ceros.

--verbose

Emite mensajes de depuración.

TEORÍA DE OPERACIÓN

Los Métodos Específicos del Dispositivo Intel (DSM) v1.7 y v1.8 [1] introdujeron las siguientes operaciones de gestión de seguridad: habilitar contraseña, actualizar contraseña, desbloquear DIMM, deshabilitar seguridad, congelar seguridad, borrado seguro (criptográfico), sobrescritura, habilitar contraseña maestra, actualizar contraseña maestra y borrado seguro con contraseña maestra.

La gestión de seguridad para los NVDIMM consta de dos partes. El frontend utiliza el framework de gestión de claves de Linux (claves confiables y cifradas [2]) para almacenar las contraseñas cifradas en el keyring administrado por el kernel. La interfaz para esto es la utilidad keyutils que utiliza las API de gestión de claves en el kernel de Linux. El backend toma la carga útil descifrada (que es la contraseña del DIMM) y la pasa al DIMM.

A diferencia de otros DSM que son compuestos por libndctl y enviados al kernel a través de un ioctl, los DSM de seguridad se gestionan a través del atributo security de sysfs bajo el dispositivo dimm. Se escribe un key-ID en el atributo security y el kernel extrae el material de clave asociado del keyring de usuario que es mantenido por el kernel.

El proceso de seguridad comienza con la generación de una clave maestra que se utiliza para sellar (cifrar) la contraseña del DIMM. Puede haber una única clave maestra común que se utiliza para cifrar la contraseña de cada DIMM, o se puede generar una clave separada para cada DIMM. La clave maestra también se conoce como clave de cifrado de clave (kek - key-encryption-key). La kek puede ser generada por el TPM (Trusted Platform Module) del sistema, o alternativamente, la Clave Maestra del Sistema también puede usarse como la kek.

Para fines de prueba, una clave de usuario con carga útil aleatoria también puede usarse como kek. Ver [2] para más detalles. Para realizar cualquier operación de seguridad, se espera que la kek haya sido agregada al keyring de usuario del kernel, como se muestra en el siguiente ejemplo:

# keyctl show
Session Keyring
 736023423 --alswrv      0     0  keyring: _ses
 675104189 --alswrv      0 65534   \_ keyring: _uid.0
 680187394 --alswrv      0     0       \_ trusted: nvdimm-master

Antes de realizar cualquiera de las operaciones de seguridad, todas las regiones asociadas con el DIMM en cuestión deben ser deshabilitadas. Para la operación de sobrescritura, además de las regiones, el dimm también debe ser deshabilitado.

[1] http://pmem.io/documents/NVDIMM_DSM_Interface-V1.8.pdf
[2] https://www.kernel.org/doc/Documentation/security/keys/trusted-encrypted.rst

Las siguientes subsecciones describen los detalles de cada función de seguridad.

DESBLOQUEAR

El desbloqueo lo realiza el kernel, sin embargo, debe ocurrir un paso de preparación antes de que el kernel pueda emitir el DSM de desbloqueo. Se espera que desde el initramfs, se ejecute un comando de configuración (load-keys de ndctl) antes de que el módulo libnvdimm sea cargado por modprobe. Este comando inyectará la kek y las contraseñas cifradas en el keyring de usuario del kernel. Durante la sonda del controlador libnvdimm, se realizará lo siguiente:

1.Verificar el estado de seguridad del dispositivo y ver si el DIMM está bloqueado.
2.Solicitar la contraseña cifrada asociada del keyring de usuario del kernel.
3.Usar la kek para descifrar la contraseña.
4.Crear el DSM de desbloqueo, copiar la carga útil descifrada en el DSM.
5.Emitir el DSM para desbloquear el DIMM.

Si el DIMM ya está desbloqueado, el kernel intentará revalidar la contraseña. Si no se logra revalidar la contraseña, el kernel congelará la seguridad y prohibirá cualquier cambio posterior en la configuración de seguridad. Hay un parámetro del módulo del kernel disponible para anular este comportamiento.

CONFIGURAR_CONTRASENA_DE_USUARIO

Para configurar la contraseña de un DIMM, se espera que la kek que se utilizará esté presente en el keyring de usuario del kernel. La kek cifra la contraseña del DIMM utilizando el formato de clave enc32. La contraseña en texto plano nunca se proporciona ni se hace visible al usuario. En cambio, es generada aleatoriamente por el kernel y el espacio de usuario no tiene acceso a ella. Tras el cifrado, un blob binario de la contraseña se escribe en el directorio de almacenamiento de blobs de contraseñas (/etc/ndctl/keys). El usuario es responsable de hacer copias de seguridad de los blobs de contraseñas en una ubicación segura.

ACTUALIZAR_CONTRASENA_DE_USUARIO

La operación de actualización de la contraseña de usuario utiliza el mismo comando DSM que la habilitación de la contraseña de usuario. La mayor parte del trabajo se realiza en el lado de la gestión de claves. El usuario tiene la opción de proporcionar una nueva kek para la nueva contraseña, pero continuar usando la kek existente también es aceptable. Las siguientes operaciones se realizan para update-passphrase (actualizar contraseña):

1.Eliminar la contraseña cifrada del keyring de usuario del kernel.
2.Renombrar el blob de contraseña a old (antiguo).
3.Cargar este blob de contraseña antiguo en el keyring con el nombre "old".
4.Crear la nueva contraseña y cifrarla con la kek.
5.Enviar el DSM con las contraseñas descifradas antigua y nueva.
6.Eliminar la contraseña antigua y el blob de contraseña del keyring.

ELIMINAR_USE

Remove the user passphrase from the DIMM. This is an operation that takes the DIMM passphrase and performs the following:

1.Check to see if the DIMM is locked.
2.Take the DIMM passphrase from the kernel user keyring.
3.Create the erase DSM and copy the decrypted payload into the DSM.
4.Issue the DSM to the DIMM.

And, on successful completion of the DSM:

5.Remove the passphrase blob from /etc/ndctl/keys.
6.Remove the passphrase from the kernel user keyring.

DESHABILITAR_SEGURIDAD

Disable security is another DSM command that accepts the DIMM passphrase. On successful completion of the command, the security of the DIMM is disabled. Additionally, the passphrase and any key material related to the DIMM is removed from the kernel keyring, and the passphrase blob is removed from /etc/ndctl/keys.

CONGELAR_SEGURIDAD

Freeze security is a DSM that when issued, locks the security subsystem of the DIMM. This means that no further security related DSMs can be issued to the DIMM. This is generally done when the DIMM is configured with a passphrase, and the system administrator wishes to prevent any further changes to the security configuration.

BORRADO_SEGURO_(BORRADO_CRIPTOGRÁFICO)

Secure erase, or crypto erase, is a DSM that accepts the DIMM passphrase. On successful completion of the command, the security subsystem of the DIMM is disabled, and the passphrase and any key material is removed from the kernel keyring, and the passphrase blob is removed from /etc/ndctl/keys.

This operation essentially replaces the media encryption key on the DIMM with a new key. This causes all existing data to appear as cipher text. Note that this does not affect label data. Namespaces are reverted to raw mode.

SOBRESCRITURA

Overwrite is a DSM that does not accept the DIMM passphrase. The operation, when issued, causes the entire contents of the DIMM to be overwritten. This includes the data area, as well as the label area. This operation is non-blocking and is asynchronous. The command submits the request to the DIMM, and the DIMM performs the operation in the background.

The completion of the overwrite operation is indicated by the DIMM’s security state transitioning to the disabled state. This can take a significant amount of time, depending on the capacity and type of the DIMM, ranging from tens of minutes to many hours.

The following sub-sections detail the commands for each security feature.

EJEMPLOS

Sanitize (crypto erase) the contents of nmem0. This will result in the NVDIMM being reverted to raw mode.

# ndctl sanitize-dimm nmem0 --crypto-erase

Sanitize (overwrite) the contents of nmem0 and nmem1. This will result in the NVDIMMs being reverted to raw mode, and all label information will be lost.

# ndctl sanitize-dimm nmem0 nmem1 --overwrite

Sanitize (crypto erase) the contents of nmem0 using the master passphrase.

# ndctl sanitize-dimm nmem0 --crypto-erase --master-passphrase

NAME

ndctl-sanitize-dimm - sanitize Non-Volatile Memory (NVDIMM) devices

SYNOPSIS

ndctl sanitize-dimm
[--force | --audit] [--quiet] [--verbose] [OPTIONS] [DIMM_IDENT ...]

DESCRIPTION

Sanitize NVDIMM devices. Sanitization is a process of securely erasing data from a storage device. This command supports the following sanitization methods:

  • Remove Passphrase
  • Crypto Erase
  • Overwrite
  • Security Freeze
  • Master Passphrase Setup, Update, and Crypto Erase

Sanitization operations require privileges. They must be executed as root or with appropriate capabilities.

Only one sanitization operation can be performed at a time per NVDIMM. The DIMM_IDENT argument can be used to specify which NVDIMM device to sanitize. If not specified, the command will attempt to sanitize all NVDIMM devices that support the requested operation.

The command syntax is designed to sanitize the specified NVDIMM devices. For example, to remove the user passphrase from all NVDIMMs, run ndctl sanitize-dimm --remove-passphrase. To perform a crypto erase on a specific NVDIMM identified by namespace ID 1, run ndctl sanitize-dimm --crypto-erase 1.

The command returns an exit code of 0 upon success, and a non-zero value otherwise.

OPTIONS

--remove-passphrase
Remove the user passphrase from the NVDIMM device. This operation requires the current passphrase to be provided when prompted.
--crypto-erase
Perform a crypto erase of the NVDIMM device. This operation uses the cryptographic key embedded in the NVDIMM controller to encrypt all stored data, effectively rendering it unrecoverable. This operation does not require a passphrase.
--overwrite
Overwrite the entire NVDIMM device with a pattern of zeros. This operation can be time-consuming.
--security-freeze
Freeze the security state of the NVDIMM device. Once frozen, any security command other than a status query will be locked out until the next system reboot.
--master-passphrase-setup
Set up a master passphrase for the NVDIMM device. This is typically done during the initial configuration of the device.
--master-passphrase-update
Update the existing master passphrase for the NVDIMM device.
--master-passphrase-crypto-erase
Perform a crypto erase using the master passphrase. This operation requires the current master passphrase.
--force
Force the operation even if it is potentially unsafe. Use with caution.
--audit
Perform an audit of the NVDIMM security state without making any changes. This is useful for verifying the current security configuration.
--quiet
Suppress output messages, except for errors.
--verbose
Enable verbose output, providing more detailed information about the operation.

THEORY OF OPERATION

REMOVE USER PASSPHRASE

The key-ID for the passphrase to be removed is written to sysfs. The kernel then sends the DSM to disable security, and the passphrase is then removed from the keyring, and the associated passphrase blob is deleted.

CRYPTO (SECURE) ERASE

This operation is similar to remove-passphrase. The kernel issues a WBINVD instruction before and after the operation to ensure no data corruption from a stale CPU cache. Use ndctl’s sanitize-dimm command with the --crypto-erase option to perform this operation.

OVERWRITE

This is invoked using --overwrite option for ndctl sanitize-dimm. The overwrite operation wipes the entire NVDIMM. The operation can take a significant amount of time. NOTE: When the command returns successfully, it just means overwrite has been successfully started, and not that the overwrite is complete. Subsequently, ndctl wait-overwrite can be used to wait for the NVDIMMs that are performing overwrite. Upon successful completion of an overwrite, the WBINVD instruction is issued by the kernel. If both --crypto-erase and --overwrite options are supplied, then crypto-erase is performed before overwrite.

SECURITY FREEZE

This operation does not require a passphrase. This will cause any security command other than a status query to be locked out until the next boot.

MASTER PASSPHRASE SETUP, UPDATE, and CRYPTO ERASE

These operations are similar to the user passphrase enable and update. The only difference is that a different passphrase is used. The master passphrase has no relation to the master key (kek) which is used for encryption of either passphrase.
