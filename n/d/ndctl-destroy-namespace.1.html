Paquete: ndctl

NDCTL-DESTROY-NAMESPACE(1) Manual de ndctl NDCTL-DESTROY-NAMESPACE(1)

NOMBRE

ndctl-destroy-namespace - destruir el/los espacio(s) de nombres dado(s)

SINOPSIS

ndctl destroy-namespace <espacio-de-nombres> [<opciones>]

TEORÍA DE OPERACIÓN

La capacidad de una REGIÓN NVDIMM (espacio contiguo de memoria persistente) se accede a través de uno o más dispositivos NAMESPACE. REGIÓN es el término de Linux para lo que ACPI y UEFI llaman un conjunto de intercalación de DIMM, o un rango de direcciones físicas del sistema que se distribuye (por el controlador de memoria) a través de uno o más módulos de memoria.

La especificación UEFI define el Protocolo de Etiqueta NVDIMM como la combinación de métodos de acceso al área de etiquetas y un formato de datos para aprovisionar uno o más objetos NAMESPACE desde una REGIÓN. Tenga en cuenta que el soporte de etiquetas es opcional y si Linux no detecta la capacidad de etiquetas, instanciará automáticamente un espacio de nombres "sin etiquetas" por región. Ejemplos de espacios de nombres sin etiquetas son los creados por la opción de línea de comandos memmap=ss!nn del kernel (ver la wiki de nvdimm en kernel.org), o NVDIMMs sin un índice de espacio de nombres válido en su área de etiquetas.


Nota

Los espacios de nombres sin etiquetas carecen de muchas de las características de sus
primos con etiquetas enriquecidas. Por ejemplo, su tamaño no se puede modificar, ni se pueden destruir completamente (es decir, recuperar el espacio). Una operación de destrucción pondrá a cero cualquier metadato específico del modo. Finalmente, para las operaciones de creación de espacios de nombres en espacios de nombres sin etiquetas, ndctl omite las comprobaciones de disponibilidad de capacidad de la región y siempre satisface la solicitud utilizando la capacidad total de la región. La única operación de reconfiguración compatible con un espacio de nombres sin etiquetas es cambiar su modo.

Un espacio de nombres se puede aprovisionar para operar en uno de 4 modos: fsdax, devdax, sector y raw. Aquí están los modelos de uso esperados para estos modos:

•fsdax: El modo Filesystem-DAX es el modo predeterminado de un espacio de nombres al especificar ndctl create-namespace sin opciones. Crea un dispositivo de bloque (/dev/pmemX[.Y]) que admite las capacidades DAX de los sistemas de archivos de Linux (xfs y ext4 hasta la fecha). DAX elimina la caché de páginas de la ruta de E/S y permite que mmap(2) establezca mapeos directos a medios de memoria persistente. La capacidad DAX permite que las cargas de trabajo / conjuntos de trabajo que exceden la capacidad de la caché de páginas escalen hasta la capacidad de la memoria persistente. Es posible que las cargas de trabajo que caben en la caché de páginas o que realizan transferencias de datos masivas no vean ningún beneficio de DAX. En caso de duda, elija este modo.
•devdax: El modo Device-DAX habilita capacidades de mapeo DAX mmap(2) similares a Filesystem-DAX. Sin embargo, en lugar de un dispositivo de bloque que puede admitir un sistema de archivos habilitado para DAX, este modo emite un único archivo de dispositivo de caracteres (/dev/daxX.Y). Utilice este modo para asignar memoria persistente a una máquina virtual, registrar memoria persistente para RDMA o cuando se necesiten mapeos gigantescos.
•sector: Utilice este modo para alojar sistemas de archivos heredados que no verifican la suma de comprobación de metadatos o aplicaciones que no están preparadas para sectores corruptos después de una caída. El uso esperado para este modo es para pequeños volúmenes de arranque. Este modo es compatible con otros sistemas operativos.
•raw: El modo raw es efectivamente solo un disco de memoria que no admite DAX. Típicamente, esto indica un espacio de nombres que fue creado por herramientas u otro sistema operativo que no sabía cómo crear un espacio de nombres fsdax o devdax de Linux. Este modo es compatible con otros sistemas operativos, pero nuevamente, no admite la operación DAX.

OPCIONES

<espacio-de-nombres>

Un nombre de dispositivo namespaceX.Y. La palabra clave all se puede especificar para realizar la operación en cada espacio de nombres del sistema, opcionalmente filtrado por región (ver opción --region).

-r, --region=

Un nombre de dispositivo regionX, o un número de ID de región. Restringe la operación a la(s) región(es) especificada(s). La palabra clave all se puede especificar para indicar la falta de cualquier restricción, sin embargo, esto es lo mismo que no proporcionar una opción --region.

-b, --bus=

Un número de ID de bus, o una cadena de proveedor (por ejemplo, "ACPI.NFIT"). Restringe la operación al(los) bus(es) especificado(s). La palabra clave all se puede especificar para indicar la falta de cualquier restricción, sin embargo, esto es lo mismo que no proporcionar una opción --bus.

-v, --verbose

Emite mensajes de depuración para la operación del espacio de nombres.

-f, --force

A menos que se especifique esta opción, la operación destroy namespace fallará si el espacio de nombres está actualmente activo. Especificar --force hace que el espacio de nombres se deshabilite antes de intentar la operación. Sin embargo, si el espacio de nombres está montado, las operaciones disable namespace y destroy namespace se abortarán. El espacio de nombres debe ser desmontado antes de ser destruido.
