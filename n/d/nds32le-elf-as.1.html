OPTIONS

-ah
include high-level source
-al
include assembly
-ali
include assembly with ginsn
-am
include macro expansions
-an
omit forms processing
-as

=file
set the name of the listing file

You may combine these options; for example, use -aln for assembly listing without forms processing. The =file option, if used, must be the last one. By itself, -a defaults to -ahls.

--alternate
Begin in alternate macro mode.
--compress-debug-sections
Compress DWARF debug sections using zlib with SHF_COMPRESSED from the ELF ABI. The resulting object file may not be compatible with older linkers and object file utilities. Note if compression would make a given section larger then it is not compressed.
--compress-debug-sections=none
--compress-debug-sections=zlib
--compress-debug-sections=zlib-gnu
--compress-debug-sections=zlib-gabi
--compress-debug-sections=zstd
These options control how DWARF debug sections are compressed. --compress-debug-sections=none is equivalent to --nocompress-debug-sections. --compress-debug-sections=zlib and --compress-debug-sections=zlib-gabi are equivalent to --compress-debug-sections. --compress-debug-sections=zlib-gnu compresses DWARF debug sections using the obsoleted zlib-gnu format. The debug sections are renamed to begin with .zdebug. --compress-debug-sections=zstd compresses DWARF debug sections using zstd. Note - if compression would actually make a section larger, then it is not compressed nor renamed.
--nocompress-debug-sections
Do not compress DWARF debug sections. This is usually the default for all targets except the x86/x86_64, but a configure time option can be used to override this.
-D

-mbig-obj
En la plataforma PE/COFF, esta opción fuerza el uso del formato de archivo de objeto grande, que permite más de 32768 secciones.
-momit-lock-prefix=no
-momit-lock-prefix=yes
Estas opciones controlan cómo el ensamblador debe codificar el prefijo lock. Esta opción está pensada como una solución alternativa para procesadores que fallan con el prefijo lock. Esta opción solo se puede usar de forma segura con computadoras de un solo núcleo y un solo hilo. -momit-lock-prefix=yes omitirá todos los prefijos lock. -momit-lock-prefix=no codificará el prefijo lock como de costumbre, que es el valor predeterminado.
-mfence-as-lock-add=no
-mfence-as-lock-add=yes
Estas opciones controlan cómo el ensamblador debe codificar lfence, mfence y sfence. -mfence-as-lock-add=yes codificará lfence, mfence y sfence como lock addl $0x0, (%rsp) en modo de 64 bits y lock addl $0x0, (%esp) en modo de 32 bits. -mfence-as-lock-add=no codificará lfence, mfence y sfence como de costumbre, que es el valor predeterminado.
-mrelax-relocations=no
-mrelax-relocations=yes
Estas opciones controlan si el ensamblador debe generar relocalizaciones relax, R_386_GOT32X, en modo de 32 bits, o R_X86_64_GOTPCRELX y R_X86_64_REX_GOTPCRELX, en modo de 64 bits. -mrelax-relocations=yes generará relocalizaciones relax. -mrelax-relocations=no no generará relocalizaciones relax. El valor predeterminado se puede controlar mediante la opción de configuración --enable-x86-relax-relocations.
-malign-branch-boundary=NUM
Esta opción controla cómo el ensamblador debe alinear saltos con prefijos de segmento o NOP. NUM debe ser una potencia de 2. Debe ser 0 o no menos de 16. Los saltos se alinearán dentro del límite de NUM bytes. -malign-branch-boundary=0, que es el valor predeterminado, no alinea los saltos.
-malign-branch=TYPE[+TYPE...]
Esta opción especifica los tipos de saltos a alinear. TYPE es una combinación de jcc, que alinea saltos condicionales, fused, que alinea saltos condicionales fusionados, jmp, que alinea saltos incondicionales, call que alinea llamadas, ret, que alinea retornos, indirect, que alinea saltos y llamadas indirectos. El valor predeterminado es -malign-branch=jcc+fused+jmp.
-malign-branch-prefix-size=NUM
Esta opción especifica el número máximo de prefijos en una instrucción para alinear saltos. NUM debe estar entre 0 y 5. El valor predeterminado de NUM es 5.
-mbranches-within-32B-boundaries
Esta opción alinea saltos condicionales, saltos condicionales fusionados y saltos incondicionales dentro de un límite de 32 bytes con hasta 5 prefijos de segmento en una instrucción. Es equivalente a -malign-branch-boundary=32 -malign-branch=jcc+fused+jmp -malign-branch-prefix-size=5. El valor predeterminado no alinea los saltos.
-mlfence-after-load=no
-mlfence-after-load=yes
Estas opciones controlan si el ensamblador debe generar lfence después de instrucciones de carga. -mlfence-after-load=yes generará lfence. -mlfence-after-load=no no generará lfence, que es el valor predeterminado.
-mlfence-before-indirect-branch=none
-mlfence-before-indirect-branch=all
-mlfence-before-indirect-branch=register
-mlfence-before-indirect-branch=memory
Estas opciones controlan si el ensamblador debe generar lfence antes de instrucciones de salto cercano indirecto. -mlfence-before-indirect-branch=all generará lfence antes de un salto cercano indirecto a través de registro y emitirá una advertencia antes de un salto cercano indirecto a través de memoria. También establece implícitamente -mlfence-before-ret=shl cuando no hay un -mlfence-before-ret= explícito. -mlfence-before-indirect-branch=register generará lfence antes de un salto cercano indirecto a través de registro. -mlfence-before-indirect-branch=memory emitirá una advertencia antes de un salto cercano indirecto a través de memoria. -mlfence-before-indirect-branch=none no generará lfence ni emitirá advertencias, que es el valor predeterminado. Tenga en cuenta que lfence no se generará antes de un salto cercano indirecto a través de registro con -mlfence-after-load=yes, ya que lfence se generará después de cargar el registro de destino del salto.
-mlfence-before-ret=none
-mlfence-before-ret=shl
-mlfence-before-ret=or
-mlfence-before-ret=yes
-mlfence-before-ret=not
Estas opciones controlan si el ensamblador debe generar lfence antes de ret. -mlfence-before-ret=or generará la instrucción or con lfence. -mlfence-before-ret=shl/yes generará la instrucción shl con lfence. -mlfence-before-ret=not generará la instrucción not con lfence. -mlfence-before-ret=none no generará lfence, que es el valor predeterminado.
-mx86-used-note=no
-mx86-used-note=yes
Estas opciones controlan si el ensamblador debe generar las notas de propiedad GNU GNU_PROPERTY_X86_ISA_1_USED y GNU_PROPERTY_X86_FEATURE_2_USED. El valor predeterminado se puede controlar mediante la opción de configuración --enable-x86-used-note.
-mevexrcig=rne
-mevexrcig=rd
-mevexrcig=ru
-mevexrcig=rz
Estas opciones controlan cómo el ensamblador debe codificar instrucciones EVEX solo SAE. -mevexrcig=rne codificará los bits RC de la instrucción EVEX con 00, que es el valor predeterminado. -mevexrcig=rd, -mevexrcig=ru y -mevexrcig=rz codificarán las instrucciones EVEX solo SAE con los bits RC 01, 10 y 11, respectivamente.
-mamd64
-mintel64
Esta opción especifica que el ensamblador solo debe aceptar ISA AMD64 o Intel64 en modo de 64 bits. El valor predeterminado es aceptar ISA comunes, solo Intel64 y AMD64.
-O0 | -O | -O1 | -O2 | -Os
Optimiza la codificación de instrucciones con un tamaño de instrucción menor. -O y -O1 codifican instrucciones de carga de registro de 64 bits con un inmediato de 64 bits como instrucciones de carga de registro de 32 bits con inmediatos de 31 o 32 bits, codifican instrucciones de limpieza de registro de 64 bits como instrucciones de limpieza de registro de 32 bits, codifican instrucciones de limpieza de registro vectorial VEX/EVEX de 256/512 bits como instrucciones de limpieza de registro vectorial VEX de 128 bits, codifican instrucciones de carga/almacenamiento de registro vectorial EVEX de 128/256 bits como instrucciones de carga/almacenamiento de registro vectorial VEX, y codifican instrucciones lógicas enteras empaquetadas EVEX de 128/256 bits como lógicas enteras empaquetadas VEX de 128/256 bits.

-O2 incluye la optimización de -O1 además de codificar instrucciones de limpieza de registro vectorial EVEX de 256/512 bits como instrucciones de limpieza de registro vectorial EVEX de 128 bits. En modo de 64 bits, las instrucciones codificadas con VEX con operandos fuente conmutativos también intercambiarán sus operandos fuente si esto permite usar la forma de prefijo VEX de 2 bytes en lugar de la de 3 bytes. Ciertas formas de AND, así como OR con el mismo operando (de registro) especificado dos veces, también se cambiarán a TEST.

-Os incluye la optimización de -O2 además de codificar pruebas de registro de 16, 32 y 64 bits con un inmediato como prueba de registro de 8 bits con un inmediato. -O0 desactiva esta optimización.

Esta página de manual documenta las opciones de la línea de comandos para el ensamblador as.

La versión de as que se está ejecutando se puede identificar por la salida de la opción --version. El ensamblador puede ser configurado para un procesador específico de la familia Xtensa, o para Z80.

DESCRIPCIÓN

El comando as lee los archivos de entrada, los cuales contienen el código fuente de ensamblaje, y genera los archivos objeto correspondientes. Si no se especifican archivos de entrada, se lee la entrada estándar. La salida se escribe en un archivo llamado a.out por defecto, o en el archivo especificado por la opción -o.

Las opciones de línea de comandos que no son específicas de una arquitectura o de un modelo de procesador particular se aplican a todas las configuraciones.

Las siguientes opciones son disponibles cuando as está configurado para un procesador Xtensa.

--longcalls | --no-longcalls
Habilita o deshabilita la transformación de instrucciones de llamada para permitir llamadas a través de un mayor rango de direcciones. Esta opción debería usarse cuando los objetivos de llamada pueden estar potencialmente fuera de rango. Puede degradar tanto el tamaño del código como el rendimiento, pero el enlazador generalmente puede optimizar la sobrecarga innecesaria cuando una llamada termina dentro del rango. El valor predeterminado es --no-longcalls.
--transform | --no-transform
Habilita o deshabilita todas las transformaciones del ensamblador de instrucciones Xtensa, incluyendo tanto la relajación como la optimización. El valor predeterminado es --transform; --no-transform solo debería usarse en los raros casos en que las instrucciones deben ser exactamente como se especifican en el código fuente de ensamblaje. Usar --no-transform causa que los operandos de instrucciones fuera de rango sean errores.
--rename-section nombreantiguo=nombrenuevo
Renombra la sección nombreantiguo a nombrenuevo. Esta opción puede usarse múltiples veces para renombrar múltiples secciones.
--trampolines | --no-trampolines
Habilita o deshabilita la transformación de instrucciones de salto para permitir saltos a través de un mayor rango de direcciones. Esta opción debería usarse cuando los objetivos de salto pueden estar potencialmente fuera de rango. En ausencia de tales saltos, esta opción no afecta el tamaño del código ni el rendimiento. El valor predeterminado es --trampolines.
--abi-windowed | --abi-call0
Elige la etiqueta ABI escrita en la sección ".xtensa.info". La etiqueta ABI indica la ABI del código de ensamblaje. El enlazador emite una advertencia al intentar enlazar archivos objeto con etiquetas ABI inconsistentes. La ABI predeterminada es elegida por la configuración del núcleo Xtensa.

Las siguientes opciones están disponibles cuando as está configurado para un procesador Z80.

Opciones de línea de comandos

-march=CPU[-EXT...][+EXT...]
Esta opción especifica el procesador de destino. El ensamblador emitirá un mensaje de error si se intenta ensamblar una instrucción que no se ejecutará en el procesador de destino. Los siguientes nombres de procesador son reconocidos: "z80", "z180", "ez80", "gbz80", "z80n", "r800". Además del conjunto de instrucciones básico, se puede indicar al ensamblador que acepte algunas mnemónicas de extensión. Por ejemplo, "-march=z180+sli+infc" extiende z180 con instrucciones SLI e IN F,(C). Las siguientes extensiones son actualmente soportadas: "full" (todas las instrucciones conocidas), "adl" (modo CPU ADL por defecto, solo eZ80), "sli" (instrucción conocida como SLI, SLL o SL1), "xyhl" (instrucciones con mitades de registros índice: IXL, IXH, IYL, IYH), "xdcb" (instrucciones como RotOp (II+d),R y BitOp n,(II+d),R), "infc" (instrucción IN F,(C) o IN (C)), "outc0" (instrucción OUT (C),0). Tenga en cuenta que en lugar de extender un conjunto de instrucciones básico, las mnemónicas de extensión que comienzan con "-" revocan la funcionalidad respectiva: "-march=z80-full+xyhl" primero elimina todas las extensiones predeterminadas y solo agrega soporte para las mitades de los registros índice.

Si esta opción no se especifica, se asume "-march=z80+xyhl+infc".

-local-prefix=prefijo

-colonless
Acepta etiquetas sin dos puntos. Todos los símbolos al principio de una línea se tratan como etiquetas.
-sdcc
Acepta código de ensamblador producido por SDCC.
-fp-s=FORMATO

-fp-d=FORMATO
