NDCTL-UPDATE-FIRMWARE(1) Manual de ndctl NDCTL-UPDATE-FIRMWARE(1)

NOMBRE

ndctl-update-firmware - actualiza el firmware del dispositivo dado

SINOPSIS

ndctl update-firmware <dimm> [<opciones>]

DESCRIPCIÓN

Proporciona una interfaz genérica para actualizar el firmware de NVDIMM. El uso de esto depende del soporte para la "familia" de NVDIMM en libndctl, el kernel necesita habilitar ese conjunto de comandos, y el dispositivo en sí necesita implementar el comando. Use "ndctl list -DF" para interrogar si la actualización de firmware está habilitada. Por ejemplo:

ndctl list -DFu -d nmem1
{
  "dev":"nmem1",
  "id":"cdab-0a-07e0-ffffffff",
  "handle":"0",
  "phys_id":"0",
  "security":"disabled",
  "firmware":{
    "current_version":"0",
    "can_update":true
  }
}

OPCIONES

<dimm>

Un nombre de dispositivo nmemX, o un número de ID de dimm. Restringe la operación a los dimm especificados. La palabra clave all se puede especificar para indicar la falta de restricción, sin embargo esto es lo mismo que no proporcionar una opción --dimm en absoluto.

-b, --bus=

Un número de ID de bus, o una cadena de proveedor (por ejemplo, "ACPI.NFIT"). Restringe la operación a los buses especificados. La palabra clave all se puede especificar para indicar la falta de restricción, sin embargo esto es lo mismo que no proporcionar una opción --bus en absoluto.

-f, --firmware

Archivo de firmware utilizado para realizar la actualización

-i, --force

Ignora el escaneo de rango de direcciones en curso e intenta enviar la actualización de firmware, o ignora los desbordamientos de activación de firmware y fuerza la activación de los dispositivos.

-A, --arm

Activa un dispositivo para la activación del firmware. Esto se habilita por defecto cuando se especifica una imagen de firmware. Especifique --no-arm para deshabilitar este valor predeterminado. De lo contrario, sin una imagen de firmware, esta opción se puede utilizar para activar manualmente un dispositivo para la activación del firmware. Cuando un dispositivo pasa de inactivo a activo, la plataforma recalcula el tiempo de activación del firmware y lo compara con el tiempo máximo soportado por la plataforma. Si el tiempo de activación excede el máximo de la plataforma, el intento de activación se aborta:
ndctl update-firmware --arm --bus=nfit_test.0 all
  Error: update firmware: nmem4: arm aborted, tripped overflow
[
  {
    "dev":"nmem1",
    "id":"cdab-0a-07e0-ffffffff",
    "handle":"0",
    "phys_id":"0",
    "security":"disabled",
    "firmware":{
      "current_version":"0",
      "can_update":true
    }
  },
  {
    "dev":"nmem3",
    "id":"cdab-0a-07e0-fffeffff",
    "handle":"0x100",
    "phys_id":"0x2",
    "security":"disabled",
    "firmware":{
      "current_version":"0",
      "can_update":true
    }
  },
  {
    "dev":"nmem2",
    "id":"cdab-0a-07e0-feffffff",
    "handle":"0x1",
    "phys_id":"0x1",
    "security":"disabled",
    "firmware":{
      "current_version":"0",
      "can_update":true
    }
  }
]
updated 3 nmems.
Es posible, pero no recomendable, ignorar los desbordamientos de tiempo
con la opción --force. En cualquier momento para ver el estado 'activado' del
bus, haga:
ndctl list -BF -b nfit_test.0
[
  {
    "provider":"nfit_test.0",
    "dev":"ndbus2",
    "scrub_state":"idle",
    "firmware":{
      "activate_method":"suspend",
      "activate_state":"overflow"
    }
  }
]

-D, --disarm

Desactiva los dispositivos después de cargar el archivo de firmware, o desactiva manualmente los dispositivos cuando no se especifica una imagen de firmware. --no-disarm no es aceptado.

-v, --verbose

Emite mensajes de depuración para el proceso de verificación del namespace.
