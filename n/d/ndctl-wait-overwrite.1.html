NOMBRE

ndctl-wait-overwrite - esperar a que una operación de sobrescritura se complete

SINOPSIS

ndctl wait-overwrite <nmem0> [<nmem1>..<nmemN>] [<opciones>]

DESCRIPCIÓN

El kernel proporciona un archivo sysfs capaz de POLL(2) (security) para indicar el estado de la sobrescritura. Este comando espera un cambio en el estado de este archivo en todos los dimms especificados.

OPCIONES

<dimm>

Un nombre de dispositivo nmemX, o un ID de dimm. Restringe la operación al dimm(s) especificado(s). La palabra clave all puede ser especificada para indicar la falta de cualquier restricción, sin embargo esto es lo mismo que no proporcionar una opción --dimm en absoluto.

-b, --bus=

Un ID de bus, o una cadena de proveedor (por ejemplo, "ACPI.NFIT"). Restringe la operación al bus(es) especificado(s). La palabra clave all puede ser especificada para indicar la falta de cualquier restricción, sin embargo esto es lo mismo que no proporcionar una opción --bus en absoluto.

-v, --verbose

Emite mensajes de depuración.

TEORÍA DE OPERACIÓN

La Especificación de Métodos Específicos del Dispositivo Intel (DSM) v1.7 y v1.8 [1] introdujo las siguientes operaciones de gestión de seguridad: habilitar contraseña, actualizar contraseña, desbloquear DIMM, deshabilitar seguridad, congelar seguridad, borrado seguro (criptográfico), sobrescritura, habilitar contraseña maestra, actualizar contraseña maestra y borrado seguro de contraseña maestra.

La gestión de seguridad para NVDIMMs consta de dos partes. El frontend utiliza el framework de gestión de claves de Linux (claves cifradas y de confianza [2]) para almacenar las contraseñas cifradas en el keyring gestionado por el kernel. La interfaz para esto es la utilidad keyutils que usa las API de gestión de claves en el kernel de Linux. El backend toma la carga útil descifrada (que es la contraseña del DIMM) y la pasa al DIMM.

A diferencia de otros DSM que son compuestos por libndctl y enviados al kernel a través de un ioctl, los DSM de seguridad se gestionan a través del atributo security de sysfs bajo el dispositivo dimm. Se escribe un key-ID en el atributo security y el kernel extrae el material de clave asociado del keyring de usuario que es mantenido por el kernel.

El proceso de seguridad comienza con la generación de una clave maestra que se utiliza para sellar (cifrar) la contraseña del DIMM. Puede haber una única clave maestra común que se usa para cifrar la contraseña de cada DIMM, o se puede generar una clave separada para cada DIMM. La clave maestra también se conoce como clave de cifrado de clave (kek). El kek puede ser generado por el TPM (Trusted Platform Module) en el sistema, o alternativamente, la Clave Maestra del Sistema también puede ser utilizada como el kek

Con fines de prueba, una clave de usuario con carga útil aleatoria también puede usarse como kek. Ver [2] para más detalles. Para realizar cualquier operación de seguridad, se espera que el kek se haya añadido al keyring de usuario del kernel como se muestra en el ejemplo a continuación:

# keyctl show
Session Keyring
 736023423 --alswrv      0     0  keyring: _ses
 675104189 --alswrv      0 65534   \_ keyring: _uid.0
 680187394 --alswrv      0     0       \_ trusted: nvdimm-master

Antes de realizar cualquiera de las operaciones de seguridad, todas las regiones asociadas con el DIMM en cuestión deben ser deshabilitadas. Para la operación de sobrescritura, además de las regiones, el dimm también debe ser deshabilitado.

[1] http://pmem.io/documents/NVDIMM_DSM_Interface-V1.8.pdf
[2] https://www.kernel.org/doc/Documentation/security/keys/trusted-encrypted.rst

Las siguientes subsecciones describen los detalles de cada característica de seguridad.

DESBLOQUEAR

El desbloqueo es realizado por el kernel, sin embargo, un paso de preparación debe ocurrir antes de que el DSM de desbloqueo pueda ser emitido por el kernel. Se espera que desde el initramfs, se ejecute un comando de configuración (ndctl load-keys) antes de que el módulo libnvdimm sea cargado por modprobe. Este comando inyectará el kek y las contraseñas cifradas en el keyring de usuario del kernel. Durante la sonda del controlador libnvdimm, se realizará lo siguiente:

1.Verificar el estado de seguridad del dispositivo y ver si el DIMM está bloqueado
2.Solicitar la contraseña cifrada asociada del keyring de usuario del kernel
3.Usar el kek para descifrar la contraseña
4.Crear el DSM de desbloqueo, copiar la carga útil descifrada en el DSM
5.Emitir el DSM para desbloquear el DIMM

Si el DIMM ya está desbloqueado, el kernel intentará revalidar la contraseña. Si no logramos revalidar la contraseña, el kernel congelará la seguridad y prohibirá cualquier cambio adicional en la configuración de seguridad. Hay un parámetro de módulo del kernel disponible para anular este comportamiento.

CONFIGURAR CONTRASEÑA DE USUARIO

Para configurar la contraseña de un DIMM, se espera que el kek a utilizar esté presente en el keyring de usuario del kernel. El kek cifra la contraseña del DIMM usando el formato de clave enc32. La contraseña en texto plano nunca es proporcionada ni visible por el usuario. En su lugar, es generada aleatoriamente por el kernel y el espacio de usuario no tiene acceso a ella. Tras el cifrado, un blob binario de la contraseña se escribe en el directorio de almacenamiento de blobs de contraseñas (/etc/ndctl/keys). El usuario es responsable de hacer copias de seguridad de los blobs de contraseñas en una ubicación segura.

ACTUALIZAR CONTRASEÑA DE USUARIO

La operación de actualizar la contraseña de usuario utiliza el mismo comando DSM que habilitar la contraseña de usuario. La mayor parte del trabajo se realiza en el lado de la gestión de claves. El usuario tiene la opción de proporcionar un nuevo kek para la nueva contraseña, pero continuar usando el kek existente también es aceptable. Las siguientes operaciones se realizan para actualizar-contraseña:

1.Eliminar la contraseña cifrada del keyring de usuario del kernel.
2.Renombrar el blob de contraseña a old.
3.Cargar este blob de contraseña antiguo en el keyring con un nombre de "old".
4.Crear la nueva contraseña y cifrarla con el kek.
5.Enviar el DSM con las contraseñas descifradas antigua y nueva.
6.Eliminar la contraseña antigua y el blob de contraseña del keyring.

ELIMINAR CONTRASEÑA DE USUARIO

El key-ID de la contraseña a eliminar se escribe en sysfs. El kernel luego envía el DSM para deshabilitar la seguridad, y la contraseña se elimina del keyring, y el blob de contraseña asociado se elimina.

BORRADO CRIPTOGRÁFICO (SEGURO)

Esta operación es similar a remove-passphrase. El kernel emite una instrucción WBINVD antes y después de la operación para asegurar que no haya corrupción de datos de una caché de CPU obsoleta. Utilice el comando sanitize-dimm de ndctl con la opción --crypto-erase para realizar esta operación.

SOBRESCRITURA

Esto se invoca usando la opción --overwrite para el sanitize-dimm de ndctl. La operación de sobrescritura borra todo el NVDIMM. La operación puede llevar una cantidad de tiempo considerable. NOTA: Cuando el comando se completa con éxito, solo significa que la sobrescritura se ha iniciado correctamente, y no que la sobrescritura esté completa. Posteriormente, ndctl wait-overwrite se puede usar para esperar a los NVDIMMs que están realizando la sobrescritura. Tras la finalización exitosa de una sobrescritura, el kernel emite la instrucción WBINVD. Si se proporcionan las opciones --crypto-erase y --overwrite, entonces se realiza crypto-erase antes de la sobrescritura.

SEG

SEGURIDAD CONGELAR

Esta operación no requiere una contraseña. Esto provocará que cualquier comando de seguridad que no sea una consulta de estado quede bloqueado hasta el próximo reinicio.

CONFIGURACIÓN, ACTUALIZACIÓN y BORRADO CRIPTOGRÁFICO DE LA CONTRASEÑA MAESTRA

Estas operaciones son similares a la habilitación y actualización de la contraseña del usuario. La única diferencia es que se utiliza una contraseña diferente. La contraseña maestra no tiene relación con la clave maestra (kek) que se utiliza para la encriptación de cualquier contraseña.
