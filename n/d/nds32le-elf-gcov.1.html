DESCRIPCIÓN

gcov es un programa de prueba de cobertura. Úselo junto con GCC para analizar sus programas y ayudar a crear código más eficiente y rápido, y para descubrir partes no probadas de su programa. Puede usar gcov como una herramienta de perfilado para ayudar a descubrir dónde sus esfuerzos de optimización afectarán mejor a su código. También puede usar gcov junto con la otra herramienta de perfilado, gprof, para evaluar qué partes de su código utilizan la mayor cantidad de tiempo de cómputo.

Las herramientas de perfilado le ayudan a analizar el rendimiento de su código. Usando un perfilador como gcov o gprof, puede obtener estadísticas básicas de rendimiento, tales como:

  • con qué frecuencia se ejecuta cada línea de código
  • qué líneas de código se ejecutan realmente
  • cuánto tiempo de cómputo utiliza cada sección de código

Una vez que conozca estas cosas sobre cómo funciona su código cuando se compila, puede examinar cada módulo para ver cuáles deberían optimizarse. gcov le ayuda a determinar dónde trabajar en la optimización.

Los desarrolladores de software también utilizan las pruebas de cobertura junto con conjuntos de pruebas (testsuites) para asegurarse de que el software es realmente lo suficientemente bueno para un lanzamiento. Los conjuntos de pruebas pueden verificar que un programa funciona como se espera; un programa de cobertura verifica cuánto del programa es ejercido por el conjunto de pruebas. Los desarrolladores pueden entonces determinar qué tipos de casos de prueba necesitan agregarse a los conjuntos de pruebas para crear tanto mejores pruebas como un mejor producto final.

Debería compilar su código sin optimización si planea usar gcov porque la optimización, al combinar algunas líneas de código en una función, puede no darle tanta información como necesita para buscar `puntos calientes' donde el código utiliza una gran cantidad de tiempo de cómputo. Del mismo modo, debido a que gcov acumula estadísticas por línea (en la resolución más baja), funciona mejor con un estilo de programación que coloca solo una instrucción por línea. Si utiliza macros complicadas que se expanden a bucles u otras estructuras de control, las estadísticas son menos útiles: solo informan sobre la línea donde aparece la llamada a la macro. Si sus macros complicadas se comportan como funciones, puede reemplazarlas con funciones en línea para resolver este problema.

gcov crea un archivo de registro llamado archivo_fuente.gcov que indica cuántas veces se ha ejecutado cada línea de un archivo fuente archivo_fuente.c. Puede usar estos archivos de registro junto con gprof para ayudar a ajustar el rendimiento de sus programas. gprof proporciona información de tiempo que puede usar junto con la información que obtiene de gcov.

gcov solo funciona en código compilado con GCC. No es compatible con ningún otro mecanismo de perfilado o prueba de cobertura.

OPCIONES

-a
--all-blocks
Escribe recuentos de ejecución individuales para cada bloque básico. Normalmente, gcov solo muestra los recuentos de ejecución para los bloques principales de una línea. Con esta opción, puede determinar si los bloques dentro de una sola línea no se están ejecutando.
-b
--branch-probabilities
Escribe las frecuencias de ramificación en el archivo de salida y la información resumen de ramificación en la salida estándar. Esta opción le permite ver con qué frecuencia se tomó cada ramificación en su programa. Las ramificaciones incondicionales no se mostrarán, a menos que se proporcione la opción -u.
-c
--branch-counts
Escribe las frecuencias de ramificación como el número de ramificaciones tomadas, en lugar del porcentaje de ramificaciones tomadas.
-g
--conditions
Escribe la cobertura de condiciones en el archivo de salida y la información resumen de condiciones en la salida estándar. Esta opción le permite ver si las condiciones en su programa tuvieron al menos una vez un efecto independiente en el resultado de la expresión booleana (cobertura de decisión/condición modificada). Esto requiere que compile el código fuente con -fcondition-coverage.
-d
--display-progress
Muestra el progreso en la salida estándar.
-f
--function-summaries
Muestra resúmenes para cada función además del resumen a nivel de archivo.
-h
--help
Muestra ayuda sobre el uso de gcov (en la salida estándar) y sale sin realizar ningún procesamiento adicional.
-j
--json-format
Genera el archivo gcov en un formato intermedio JSON fácil de analizar que no requiere código fuente para su generación. El archivo JSON se comprime con el algoritmo de compresión gzip y los archivos tienen la extensión .gcov.json.gz.

    -H
    --human-readable
    Escribe los recuentos en formato legible por humanos (como 24.6k).
    -k
    --use-colors
    Usa colores para las líneas de código que tienen cobertura cero. Usamos color rojo para líneas no excepcionales y cian para las excepcionales. Los mismos colores se usan para bloques básicos con la opción -a.

    --long-file-names
    Crea nombres de archivo largos para los archivos fuente incluidos. Si usas la opción -p, tanto el nombre del archivo que incluye como el incluido serán rutas completas.

    --demangled-names
    Muestra los nombres de función desmangleados en la salida. Por defecto, se muestran los nombres de función mangled.
    -n
    --no-output
    No crear el archivo de salida gcov.
    -o directorio|archivo
    --object-directory directorio
    --object-file archivo
    Especifica el directorio que contiene los archivos de datos de gcov, o la ruta del archivo objeto. Los archivos de datos .gcno y .gcda se buscan utilizando esta opción. Si se especifica un directorio, los archivos de datos están en ese directorio y se nombran según el nombre del archivo de entrada, sin su extensión. Si se especifica un archivo aquí, los archivos de datos se nombran según ese archivo, sin su extensión.
    -p
    --preserve-paths
    Conserva la información completa de la ruta en los nombres de los archivos .gcov generados. Sin esta opción, solo se utiliza el componente del nombre del archivo. Con esta opción, se utilizan todos los directorios, con los caracteres / traducidos a caracteres #, los componentes de directorio . eliminados y los componentes .. irremovables renombrados a ^. Esto es útil si los archivos fuente están en varios directorios diferentes.
    -q
    --use-hotness-colors
    Emite salida coloreada similar a perf para líneas activas. La leyenda de la escala de colores se imprime al principio del archivo de salida.
    -r
    --relative-only
    Solo muestra información sobre archivos fuente con un nombre de ruta relativo (después de la omisión del prefijo fuente). Las rutas absolutas suelen ser archivos de cabecera del sistema y la cobertura de cualquier función insertada en ellos normalmente no es interesante.
    -s directorio
    --source-prefix directorio
    Un prefijo para los nombres de archivos fuente a eliminar al generar los archivos de cobertura de salida. Esta opción es útil cuando se compila en un directorio separado, y no se desea la ruta al directorio fuente al determinar los nombres de los archivos de salida. Tenga en cuenta que esta detección de prefijo se aplica antes de determinar si el archivo fuente es absoluto.
    -t
    --stdout
    Salida al estándar de salida en lugar de archivos de salida.
    -u
    --unconditional-branches
    Cuando se dan probabilidades de rama, incluye las de las ramas incondicionales. Las ramas incondicionales normalmente no son interesantes.
    -v
    --version
    Muestra el número de versión de gcov (en la salida estándar) y sale sin procesar más.
    -w
    --verbose
    Imprime información detallada relacionada con bloques básicos y arcos.
    -x
    --hash-filenames
    Al usar --preserve-paths, gcov usa la ruta completa de los archivos fuente para crear un nombre de archivo de salida. Esto puede llevar a nombres de archivo largos que pueden exceder los límites del sistema de archivos. Esta opción crea nombres de la forma archivo-fuente##md5.gcov, donde el componente archivo-fuente es la parte final del nombre de archivo y el componente md5 se calcula a partir del nombre mangled completo que se habría utilizado de otra manera. La opción es una alternativa a --preserve-paths en sistemas que tienen un límite en el sistema de archivos.

    gcov debe ejecutarse con el directorio actual siendo el mismo que cuando se invocó al compilador. De lo contrario, no podrá localizar los archivos fuente. gcov produce archivos llamados nombremangled.gcov en el directorio actual. Estos contienen la información de cobertura del archivo fuente al que corresponden. Se produce un archivo .gcov por cada archivo fuente (o de cabecera) que contiene código, que fue compilado para producir los archivos de datos. La parte nombremangled del nombre del archivo de salida suele ser simplemente el nombre del archivo fuente, pero puede ser algo más complicado si se dan las opciones -l o -p. Consulte esas opciones para obtener detalles.

    Si invoca gcov con varios archivos de entrada, las contribuciones de cada archivo de entrada se suman. Normalmente lo invocaría con la misma lista de archivos que el enlace final de su ejecutable.

    Los archivos .gcov contienen campos separados por : junto con el código fuente del programa. El formato es

    <contador_ejecucion>:<numero_linea>:<texto_linea_fuente>

    Puede aparecer información adicional de bloques después de cada línea, cuando se solicita mediante una opción de línea de comandos. El contador_ejecucion es - para las líneas que no contienen código. Las líneas no ejecutadas se marcan como ##### o =====, dependiendo de si son alcanzables por rutas no excepcionales o solo por rutas excepcionales como los manejadores de excepciones de C++, respectivamente. Dada la opción -a, los bloques no ejecutados se marcan como $$$$$ o %%%%%, dependiendo de si un bloque básico es alcanzable a través de rutas no excepcionales o excepcionales. Los bloques básicos ejecutados que tienen una sentencia con un contador_ejecucion cero terminan con el carácter * y se colorean con color magenta con la opción -k. Esta funcionalidad no se soporta en Ada.

    Tenga en cuenta que GCC puede eliminar por completo los cuerpos de las funciones que no son necesarias, por ejemplo, si se insertan en todas partes. Dichas funciones se marcan con -, lo que puede ser confuso. Utilice la opción -fkeep-inline-f
