DESCRIPCIÓN

La utilidad GNU objcopy copia el contenido de un archivo objeto a otro. objcopy utiliza la Biblioteca GNU BFD para leer y escribir los archivos objeto. Puede escribir el archivo objeto de destino en un formato diferente al del archivo objeto de origen. El comportamiento exacto de objcopy se controla mediante opciones de línea de comandos. Tenga en cuenta que objcopy debería ser capaz de copiar un archivo completamente enlazado entre dos formatos cualesquiera. Sin embargo, copiar un archivo objeto reubicable entre dos formatos cualesquiera puede no funcionar como se espera.

objcopy crea archivos temporales para realizar sus traducciones y los elimina después. objcopy utiliza BFD para realizar todo su trabajo de traducción; tiene acceso a todos los formatos descritos en BFD y, por lo tanto, puede reconocer la mayoría de los formatos sin que se le indique explícitamente.

objcopy se puede utilizar para generar registros S utilizando un destino de salida srec (por ejemplo, use -O srec).

objcopy se puede utilizar para generar un archivo binario crudo utilizando un destino de salida binary (por ejemplo, use -O binary). Cuando objcopy genera un archivo binario crudo, esencialmente producirá un volcado de memoria del contenido del archivo objeto de entrada. Toda la información de símbolos y reubicaciones se descartará. El volcado de memoria comenzará en la dirección de carga de la sección más baja copiada en el archivo de salida.

Al generar un archivo de registro S o un archivo binario crudo, puede ser útil usar -S para eliminar secciones que contienen información de depuración. En algunos casos, -R será útil para eliminar secciones que contienen información que no es necesaria para el archivo binario.

Nota: objcopy no puede cambiar el orden de bytes (endianness) de sus archivos de entrada. Si el formato de entrada tiene un orden de bytes (algunos formatos no lo tienen), objcopy solo puede copiar las entradas en formatos de archivo que tengan el mismo orden de bytes o que no tengan orden de bytes (por ejemplo, srec). (Sin embargo, consulte la opción --reverse-bytes).

Copia solo las secciones indicadas del archivo de entrada al archivo de salida. Esta opción se puede dar varias veces. Ten en cuenta que usar esta opción de forma inapropiada puede hacer que el archivo de salida no sea utilizable. Se aceptan caracteres comodín en patrónsección.

Si el primer carácter de patrónsección es un signo de exclamación (!) entonces las secciones coincidentes no se copiarán, incluso si un uso anterior de --only-section en la misma línea de comandos las copiaría de otra manera. Por ejemplo:

copiará todas las secciones que coincidan con '.text.*' pero no la sección '.text.foo'.

Si el primer carácter de patrónsección es un signo de exclamación (!) entonces las secciones coincidentes no se eliminarán, incluso si un uso anterior de --remove-section en la misma línea de comandos las eliminaría de otra manera. Por ejemplo:

-b byte
--byte=byte
Si se ha habilitado la intercalación mediante la opción --interleave, entonces el rango de bytes a conservar comenzará en el byte-ésimo byte. byte puede estar en el rango de 0 a amplitud-1, donde amplitud es el valor dado por la opción --interleave.
-i [amplitud]
--interleave[=amplitud]
Copia solo un rango de cada amplitud bytes. (Los datos de cabecera no se ven afectados). Selecciona qué byte del rango inicia la copia con la opción --byte. Selecciona la anchura del rango con la opción --interleave-width.

Esta opción es útil para crear archivos para programar ROM. Se suele usar con un destino de salida "srec". Ten en cuenta que objcopy se quejará si no especificas también la opción --byte.

La amplitud de intercalación predeterminada es 4, por lo que con --byte establecido en 0, objcopy copiaría el primer byte de cada cuatro bytes de la entrada a la salida.

--interleave-width=anchura
Cuando se utiliza con la opción --interleave, copia anchura bytes a la vez. El inicio del rango de bytes a copiar se establece con la opción --byte, y la extensión del rango se establece con la opción --interleave.

El valor predeterminado para esta opción es 1. El valor de anchura más el valor de byte establecido por la opción --byte no debe exceder la amplitud de intercalación establecida por la opción --interleave.

Esta opción se puede usar para crear imágenes para dos flashes de 16 bits intercalados en un bus de 32 bits pasando -b 0 -i 4 --interleave-width=2 y -b 2 -i 4 --interleave-width=2 a dos comandos objcopy. Si la entrada fuera '12345678', las salidas serían '1256' y '3478' respectivamente.

-p
--preserve-dates
Establece las fechas de acceso y modificación del archivo de salida para que sean las mismas que las del archivo de entrada.

Esta opción también copia la fecha almacenada en la cabecera de un archivo en formato PE, a menos que la variable de entorno SOURCE_DATE_EPOCH esté definida. Si está definida, esta variable se utilizará como la fecha almacenada en la cabecera, interpretada como el número de segundos desde la época Unix.

--debugging
Convert debugging information, if possible. This is not the default because only certain debugging formats are supported, and the conversion process can be time consuming.
--gap-fill val
Fill gaps between sections with val. This operation applies to the load address (LMA) of the sections. It is done by increasing the size of the section with the lower address, and filling in the extra space created with val.
--pad-to address
Pad the output file up to the load address address. This is done by increasing the size of the last section. The extra space is filled in with the value specified by --gap-fill (default zero).
--set-start val
Set the start address (also known as the entry address) of the new file to val. Not all object file formats support setting the start address.
--change-start incr
--adjust-start incr
Change the start address (also known as the entry address) by adding incr. Not all object file formats support setting the start address.
--change-addresses incr
--adjust-vma incr
Change the VMA and LMA addresses of all sections, as well as the start address, by adding incr. Some object file formats do not permit section addresses to be changed arbitrarily. Note that this does not relocate the sections; if the program expects sections to be loaded at a certain address, and this option is used to change the sections such that they are loaded at a different address, the program may fail.
--change-section-address sectionpattern{=,+,-}val
--adjust-section-vma sectionpattern{=,+,-}val
Set or change both the VMA address and the LMA address of any section matching sectionpattern. If = is used, the section address is set to val. Otherwise, val is added to or subtracted from the section address. See the comments under --change-addresses, above. If sectionpattern does not match any sections in the input file, a warning will be issued, unless --no-change-warnings is used.
--change-section-lma sectionpattern{=,+,-}val
Set or change the LMA address of any sections matching sectionpattern. The LMA address is the address where the section will be loaded into memory at program load time. Normally this is the same as the VMA address, which is the address of the section at program run time, but on some systems, especially those where a program is held in ROM, the two can be different. If = is used, the section address is set to val. Otherwise, val is added to or subtracted from the section address. See the comments under --change-addresses, above. If sectionpattern does not match any sections in the input file, a warning will be issued, unless --no-change-warnings is used.
--change-section-vma sectionpattern{=,+,-}val
Set or change the VMA address of any section matching sectionpattern. The VMA address is the address where the section will be located once the program has started executing. Normally this is the same as the LMA address, which is the address where the section will be loaded into memory, but on some systems, especially those where a program is held in ROM, the two can be different. If = is used, the section address is set to val. Otherwise, val is added to or subtracted from the section address. See the comments under --change-addresses, above. If sectionpattern does not match any sections in the input file, a warning will be issued, unless --no-change-warnings is used.
--change-warnings
--adjust-warnings
If --change-section-address or --change-section-lma or --change-section-vma is used, and the section pattern does not match any sections, issue a warning. This is the default.
--no-change-warnings
--no-adjust-warnings
Do not issue a warning if --change-section-address or --adjust-section-lma or --adjust-section-vma is used, even if the section pattern does not match any sections.
--set-section-flags sectionpattern=flags
Set the flags for any sections matching sectionpattern. The flags argument is a comma separated string of flag names. The recognized names are alloc, contents, load, noload, readonly, code, data, rom, exclude, share, debug, and large. You can set the contents flag for a section which does not have contents, but it is not meaningful to clear the contents flag of a section which does have contents--just remove the section instead. Not all flags are meaningful for all object file formats. In particular the share flag is only meaningful for COFF format files and not for ELF format files. The ELF x86-64 specific flag large corresponds to SHF_X86_64_LARGE.
--set-section-alignment sectionpattern=align
Set the alignment for any sections matching sectionpattern. align specifies the alignment in bytes and must be a power of two, i.e. 1, 2, 4, 8....
--add-section sectionname=filename
Add a new section named sectionname while copying the file. The contents of the new section are taken from the file filename. The size of the section will be the size of the file. This option only works on file formats which can support sections with arbitrary names. Note - it may be necessary to use the --set-section-flags option to set the attributes of the newly created section.
--dump-section sectionname=filename
Place the contents of section named sectionname into the file filename, overwriting any contents that may have been there previously. This option is the inverse of --add-section. This option is similar to the --only-section option except that it does not create a formatted file, it just dumps the contents as raw binary data, without applying any relocations. The option can be specified more than once.
--update-section sectionname=filename
Replace the existing contents of a section named sectionname with the contents of file filename. The size of the section will be adjusted to the size of the file. The section flags for sectionname will be unchanged. For ELF format files the section to segment mapping will also remain unchanged, something which is not possible using --remove-section followed by --add-section. The option can be specified more than once.

Note - it is possible to use --rename-section and --update-section to both update and rename a section from one command line. In this case, pass the original section name to --update-section, and the original and new section names to --rename-section.

--add-symbol name=[section:]value[,flags]
Add a new symbol named name while copying the file. This option may be specified multiple times. If the section is given, the symbol will be associated with and relative to that section, otherwise it will be an ABS symbol. Specifying an undefined section will result in a fatal error. There is no check for the value, it will be taken as specified. Symbol flags can be specified and not all flags will be meaningful for all object file formats. By default, the symbol will be global. The special flag 'before=othersym' will insert the new symbol in front of the specified othersym, otherwise the symbol(s) will be added at the end of the symbol table in the order they appear.
--rename-section oldname=newname[,flags]
Rename a section from oldname to newname, optionally changing the section's flags to flags in the process. This has the advantage over using a linker script to perform the rename in that the output stays as an object file and does not become a linked executable. This option accepts the same set of flags as the --set-section-flags option.

This option is particularly helpful when the input format is binary, since this will always create a section called .data. If for example, you wanted instead to create a section called .rodata containing binary data you could use the following command line to achieve it:

objcopy -I binary -O <output_format> -B <architecture> \
 --rename-section .data=.rodata,alloc,load,readonly,data,contents \
 <input_binary_fi
objcopy

February 2023 objcopy — copy and translate object files objcopy [OPTION...] [source] [destination] The objcopy utility copies, possibly with modifications, an object file to another object file. It can be used to change the format of an object file, or to delete or change parts of the object file. It can be used for instance to produce stripped versions of object files that have had all their debugging information removed. objcopy can translate the object file from source to destination. If destination is not specified, it is assumed to be the same as source. If source is not specified, it is assumed to be standard input. If destination is not specified, it is assumed to be standard output. The object code format is determined from the file itself, but this can be overridden using the -I and -O options. Note that objcopy does not support the creation of multiple output files. You may need to use multiple invocations if you wish to create more than one output file from a single input file.
--keep-section-symbols
Al extraer símbolos de un archivo, quizás con --strip-debug o --strip-unneeded, conserva cualquier símbolo que especifique nombres de sección, los cuales de otra manera serían extraídos.
--keep-file-symbols
Al extraer símbolos de un archivo, quizás con --strip-debug o --strip-unneeded, conserva cualquier símbolo que especifique nombres de archivos fuente, los cuales de otra manera serían extraídos.
--only-keep-debug
Extrae un archivo, eliminando el contenido de cualquier sección que no sería extraída por --strip-debug y dejando intactas las secciones de depuración. En archivos ELF, esto preserva todas las secciones de notas en la salida.

Nota: las cabeceras de sección de las secciones extraídas se conservan, incluyendo sus tamaños, pero el contenido de la sección se descarta. Las cabeceras de sección se conservan para que otras herramientas puedan vincular el archivo de información de depuración con el ejecutable real, incluso si ese ejecutable ha sido reubicado a un espacio de direcciones diferente.

La intención es que esta opción se utilice junto con --add-gnu-debuglink para crear un ejecutable de dos partes. Una, un binario extraído que ocupará menos espacio en RAM y en una distribución, y la segunda, un archivo de información de depuración que solo se necesita si se requieren capacidades de depuración. El procedimiento sugerido para crear estos archivos es el siguiente:

1.<Enlaza el ejecutable como de costumbre. Suponiendo que se llama>
"foo" entonces...
1.<Ejecuta "objcopy --only-keep-debug foo foo.dbg" para>
crear un archivo que contenga la información de depuración.
1.<Ejecuta "objcopy --strip-debug foo" para crear un>
ejecutable extraído.
1.<Ejecuta "objcopy --add-gnu-debuglink=foo.dbg foo">
para añadir un enlace a la información de depuración en el ejecutable extraído.

Nota: la elección de ".dbg" como extensión para el archivo de información de depuración es arbitraria. También el paso "--only-keep-debug" es opcional. En su lugar, puedes hacer esto:

1.<Enlaza el ejecutable como de costumbre.>
1.<Copia "foo" a "foo.full">
1.<Ejecuta "objcopy --strip-debug foo">
1.<Ejecuta "objcopy --add-gnu-debuglink=foo.full foo">

es decir, el archivo al que apunta --add-gnu-debuglink puede ser el ejecutable completo. No tiene por qué ser un archivo creado por el interruptor --only-keep-debug.

Nota: este interruptor solo está destinado a ser utilizado en archivos completamente enlazados. No tiene sentido usarlo en archivos objeto donde la información de depuración puede estar incompleta. Además, la característica gnu_debuglink actualmente solo admite la presencia de un nombre de archivo que contenga información de depuración, no múltiples nombres de archivo en una base de uno por archivo objeto.

--strip-dwo
Elimina el contenido de todas las secciones DWARF .dwo, dejando intactas las secciones de depuración restantes y todos los símbolos. Esta opción está pensada para ser utilizada por el compilador como parte de la opción -gsplit-dwarf, que divide la información de depuración entre el archivo .o y un archivo .dwo separado. El compilador genera toda la información de depuración en el mismo archivo, luego utiliza la opción --extract-dwo para copiar las secciones .dwo al archivo .dwo y, a continuación, la opción --strip-dwo para eliminar esas secciones del archivo .o original.
--extract-dwo
Extrae el contenido de todas las secciones DWARF .dwo. Consulte la opción --strip-dwo para obtener más información.
--file-alignment num
Especifica la alineación de archivos. Las secciones en el archivo siempre comenzarán en desplazamientos de archivo que sean múltiplos de este número. El valor predeterminado es 512. [Esta opción es específica para objetivos PE.]
--heap reserve
--heap reserve,commit
Especifica el número de bytes de memoria a reservar (y opcionalmente confirmar) para ser utilizados como heap para este programa. [Esta opción es específica para objetivos PE.]
--image-base value
Utiliza value como la dirección base de tu programa o dll. Esta es la ubicación de memoria más baja que se utilizará cuando tu programa o dll se cargue. Para reducir la necesidad de reubicación y mejorar el rendimiento de tus dlls, cada una debe tener una dirección base única y no superponerse con ninguna otra dll. El valor predeterminado es 0x400000 para ejecutables y 0x10000000 para dlls. [Esta opción es específica para objetivos PE.]
--section-alignment num
Establece el campo de alineación de secciones en la cabecera PE. Las secciones en memoria siempre comenzarán en direcciones que sean múltiplos de este número. El valor predeterminado es 0x1000. [Esta opción es específica para objetivos PE.]
--stack reserve
--stack reserve,commit
Especifica el número de bytes de memoria a reservar (y opcionalmente confirmar) para ser utilizados como stack para este programa. [Esta opción es específica para objetivos PE.]
--subsystem which
--subsystem which:major
--subsystem which:major.minor
Especifica el subsistema bajo el cual se ejecutará tu programa. Los valores legales para which son "native", "windows", "console", "posix", "efi-app", "efi-bsd", "efi-rtd", "sal-rtd" y "xbox". Opcionalmente, también puedes establecer la versión del subsistema. También se aceptan valores numéricos para which. [Esta opción es específica para objetivos PE.]
--extract-symbol
Conserva las marcas de sección y los símbolos del archivo pero elimina todos los datos de las secciones. Específicamente, la opción:
*<elimina el contenido de todas las secciones;>
*<establece el tamaño de cada sección a cero; y>
*<establece la dirección de inicio del archivo a cero.>

Esta opción se utiliza para crear un archivo .sym para un kernel VxWorks. También puede ser una forma útil de reducir el tamaño de un archivo de entrada del enlazador --just-symbols.

--compress-debug-sections
Comprime las secciones de depuración DWARF usando zlib con SHF_COMPRESSED de la ABI ELF. Nota: si la compresión realmente hiciera una sección más grande, entonces no se comprime.
--compress-debug-sections=none
--compress-debug-sections=zlib
--compress-debug-sections=zlib-gnu
--compress-debug-sections=zlib-gabi
--compress-debug-sections=zstd
Para archivos ELF, estas opciones controlan cómo se comprimen las secciones de depuración DWARF. --compress-debug-sections=none es equivalente a --decompress-debug-sections. --compress-debug-sections=zlib y --compress-debug-sections=zlib-gabi son equivalentes a --compress-debug-sections. --compress-debug-sections=zlib-gnu comprime las secciones de depuración DWARF utilizando el formato obsoleto zlib-gnu. Las secciones de depuración se renombran para que comiencen con .zdebug. --compress-debug-sections=zstd comprime las secciones de depuración DWARF utilizando zstd. Nota: si la compresión realmente hiciera una sección más grande, entonces no se comprime ni se renombra.
--decompress-debug-sections
Descomprime las secciones de depuración DWARF. Para una sección .zdebug, se restaura el nombre original.
--elf-stt-common=yes
--elf-stt-common=no
Para archivos ELF, estas opciones controlan si los símbolos comunes deben convertirse al tipo "STT_COMMON" o "STT_OBJECT". --elf-stt-common=yes convierte el tipo de símbolo común a "STT_COMMON". --elf-stt-common=no convierte el tipo de símbolo común a "STT_OBJECT".
--merge-notes
--no-merge-notes
Para archivos ELF, intenta (o no intenta) reducir el tamaño de cualquier sección de tipo SHT_NOTE eliminando notas duplicadas.
-V
--version
Muestra el número de versión de objcopy.
--verilog-data-width=bytes
Para la salida Verilog, esta opción controla el número de bytes convertidos para cada elemento de datos de salida. El objetivo de entrada controla el orden de bytes de la conversión.
-v
--verbose
Salida detallada: lista todos los archivos objeto modificados. En el caso de archivos, objcopy -V lista todos los miembros del archivo.
--help
Muestra un resumen de las opciones de objcopy.
--info
Muestra una lista con todas las arquitecturas y formatos de objeto disponibles.

El archivo puede contener en sí mismo opciones adicionales de @archivo; dichas opciones se procesarán recursivamente.
