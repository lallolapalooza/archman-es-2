NDCTL-SETUP-PASSPHRASE(1) Manual de ndctl NDCTL-SETUP-PASSPHRASE(1)

NOMBRE

ndctl-setup-passphrase - configura y habilita la contraseña de seguridad para un NVDIMM

SINOPSIS

ndctl setup-passphrase <nmem0> [<nmem1>..<nmemN>] -k <manejador_clave> [<opciones>]

DESCRIPCIÓN

Configura y habilita una contraseña de seguridad para uno o más NVDIMM.

Para que este comando tenga éxito, se espera que la clave maestra se haya cargado previamente en el keyring del usuario. Se puede encontrar más información sobre cómo hacer esto en la documentación del kernel en: https://www.kernel.org/doc/html/latest/security/keys/trusted-encrypted.html

Los blobs de contraseña se crean en el directorio /etc/ndctl/keys con un formato de nombre de archivo de "nvdimm_<id_unico_dimm>_<nombre_host>.blob"

El comando fallará si la contraseña ya está en el keyring del usuario o si ya existe un blob de contraseña en /etc/ndctl/keys.

OPCIONES

<dimm>

Un nombre de dispositivo nmemX, o un número de ID de dimm. Restringe la operación a los dimm especificados. La palabra clave all puede especificarse para indicar la falta de restricción, sin embargo, esto es lo mismo que no proporcionar la opción --dimm.

-b, --bus=

Un número de ID de bus, o una cadena de proveedor (por ejemplo, "ACPI.NFIT"). Restringe la operación a los buses especificados. La palabra clave all puede especificarse para indicar la falta de restricción, sin embargo, esto es lo mismo que no proporcionar la opción --bus.

-k, --key_handle=

Manejador para la kek (clave de cifrado de clave) maestra que se utilizará para sellar la(s) contraseña(s) para el(los) DIMM(s) dado(s). El formato es: <tipo_clave>:<descripción_clave> por ejemplo, trusted:nvdimm-master
NOTA: Se espera que la kek se haya cargado en el keyring del usuario.

-m, --master-passphrase

Indica que estamos gestionando la contraseña maestra en lugar de la contraseña de usuario.

-v, --verbose

Emite mensajes de depuración.

TEORÍA DE OPERACIÓN

Los Métodos Específicos del Dispositivo Intel (DSM) especificación v1.7 y v1.8 [1] introdujeron las siguientes operaciones de gestión de seguridad: habilitar contraseña, actualizar contraseña, desbloquear DIMM, deshabilitar seguridad, congelar seguridad, borrado seguro (criptográfico), sobrescribir, habilitar contraseña maestra, actualizar contraseña maestra y borrado seguro de contraseña maestra.

La gestión de seguridad para NVDIMMs consta de dos partes. El front-end utiliza el marco de gestión de claves de Linux (claves confiables y cifradas [2]) para almacenar las contraseñas cifradas en el keyring gestionado por el kernel. La interfaz para esto es la utilidad keyutils que utiliza las APIs de gestión de claves en el kernel de Linux. El back-end toma la carga útil descifrada (que es la contraseña del DIMM) y la pasa al DIMM.

A diferencia de otros DSM que son compuestos por libndctl y enviados al kernel a través de un ioctl, los DSM de seguridad se gestionan a través del atributo sysfs security bajo el dispositivo dimm. Se escribe un key-ID en el atributo security y el kernel extrae el material de clave asociado del keyring del usuario que mantiene el kernel.

El proceso de seguridad comienza con la generación de una clave maestra que se utiliza para sellar (cifrar) la contraseña para el DIMM. Puede haber una clave maestra común que se utiliza para cifrar la contraseña de cada DIMM, o se puede generar una clave separada para cada DIMM. La clave maestra también se conoce como clave de cifrado de clave (kek). La kek puede ser generada por el TPM (Módulo de Plataforma Confiable) en el sistema, o alternativamente, la Clave Maestra del Sistema también puede usarse como kek

Para fines de prueba, una clave de usuario con carga útil aleatoria también se puede usar como kek. Consulte [2] para obtener detalles. Para realizar cualquier operación de seguridad, se espera que la kek se haya agregado al keyring de usuario del kernel como se muestra en el siguiente ejemplo:

# keyctl show
Clave de sesión
 736023423 --alswrv      0     0  keyring: _ses
 675104189 --alswrv      0 65534   \_ keyring: _uid.0
 680187394 --alswrv      0     0       \_ trusted: nvdimm-master

Antes de realizar cualquiera de las operaciones de seguridad, se deben deshabilitar todas las regiones asociadas con el DIMM en cuestión. Para la operación de sobrescribir, además de las regiones, también se debe deshabilitar el dimm.

[1] http://pmem.io/documents/NVDIMM_DSM_Interface-V1.8.pdf
[2] https://www.kernel.org/doc/Documentation/security/keys/trusted-encrypted.rst

Las siguientes subsecciones describen los detalles de cada característica de seguridad.

DESBLOQUEAR

El desbloqueo lo realiza el kernel, sin embargo, un paso de preparación debe ocurrir antes de que el kernel pueda emitir el DSM de desbloqueo. Se espera que, desde el initramfs, se ejecute un comando de configuración (ndctl load-keys) antes de que el módulo libnvdimm sea cargado por modprobe. Este comando inyectará la kek y las contraseñas cifradas en el keyring de usuario del kernel. Durante la sonda del controlador libnvdimm, realizará lo siguiente:

1.Comprobar el estado de seguridad del dispositivo y ver si el DIMM está bloqueado
2.Solicitar la contraseña cifrada asociada del keyring de usuario del kernel
3.Utilizar la kek para descifrar la contraseña
4.Crear el DSM de desbloqueo, copiar la carga útil descifrada en el DSM
5.Emitir el DSM para desbloquear el DIMM

Si el DIMM ya está desbloqueado, el kernel intentará revalidar la contraseña. Si no logramos revalidar la contraseña, el kernel congelará la seguridad y prohibirá cualquier cambio posterior en la configuración de seguridad. Hay un parámetro de módulo del kernel disponible para anular este comportamiento.

CONFIGURAR CONTRASEÑA DE USUARIO

Para configurar la contraseña de un DIMM, se espera que la kek a utilizar esté presente en el keyring de usuario del kernel. La kek cifra la contraseña del DIMM utilizando el formato de clave enc32. La contraseña en texto plano nunca es proporcionada ni visible para el usuario. En su lugar, es generada aleatoriamente por el kernel y el espacio de usuario no tiene acceso a ella. Tras el cifrado, un blob binario de la contraseña se escribe en el directorio de almacenamiento de blobs de contraseña (/etc/ndctl/keys). El usuario es responsable de hacer una copia de seguridad de los blobs de contraseña en una ubicación segura.

ACTUALIZAR CONTRASEÑA DE USUARIO

La operación de actualización de la contraseña de usuario utiliza el mismo comando DSM que la habilitación de la contraseña de usuario. La mayor parte del trabajo se realiza en el lado de la gestión de claves. El usuario tiene la opción de proporcionar una nueva kek para la nueva contraseña, pero continuar utilizando la kek existente también es aceptable. Las siguientes operaciones se realizan para actualizar-contraseña:

1.Eliminar la contraseña cifrada del keyring de usuario del kernel.
2.Renombrar el blob de contraseña a old.
3.Cargar este blob de contraseña antiguo en el keyring con el nombre "old".
4.Crear la nueva contraseña y cifrarla con la kek.
5.Enviar el DSM con las contraseñas antiguas y nuevas descifradas.
6.Eliminar la contraseña antigua y el blob de contraseña del keyring.

ELIMINAR CONTRASEÑA DE USUARIO

El key-ID de la contraseña a eliminar se escribe en sysfs. El kernel luego envía el DSM para deshabilitar la seguridad, y la contraseña se elimina del keyring, y el blob de contraseña asociado se elimina.

TEORÍA DE OPERACIÓN

CRYPTO ERASE

La operación es similar a remove-passphrase. El kernel emite una instrucción WBINVD antes y después de la operación para garantizar que no haya corrupción de datos debido a una caché de CPU obsoleta. Utilice el comando sanitize-dimm de ndctl con la opción --crypto-erase para realizar esta operación.

SOBREESCRIBIR

Esto se invoca usando la opción --overwrite para sanitize-dimm de ndctl. La operación de sobrescritura borra todo el NVDIMM. La operación puede llevar una cantidad significativa de tiempo. NOTA: Cuando el comando se completa con éxito, solo significa que la sobrescritura se ha iniciado correctamente, y no que la sobrescritura se ha completado. Posteriormente, se puede usar ndctl wait-overwrite para esperar a los NVDIMMs que están realizando la sobrescritura. Una vez completada con éxito una sobrescritura, el kernel emite la instrucción WBINVD. Si se proporcionan las opciones --crypto-erase y --overwrite, entonces crypto-erase se realiza antes de overwrite.

SECURITY FREEZE

Esta operación no requiere una contraseña. Esto provocará que cualquier comando de seguridad que no sea una consulta de estado se bloquee hasta el próximo reinicio.

CONFIGURACIÓN, ACTUALIZACIÓN Y BORRADO CRIPTO DE LA CONTRASEÑA MAESTRA

Estas operaciones son similares a la habilitación y actualización de la contraseña de usuario. La única diferencia es que se utiliza una contraseña diferente. La contraseña maestra no tiene relación con la clave maestra (kek) que se utiliza para cifrar cualquiera de las contraseñas.
