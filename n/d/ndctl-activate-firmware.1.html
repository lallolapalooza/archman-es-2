NDCTL-ACTIVATE-FIRMWARE(1) Manual de ndctl NDCTL-ACTIVATE-FIRMWARE(1)

NOMBRE

ndctl-activate-firmware - activa el firmware preparado en los dispositivos de memoria

SINOPSIS

ndctl activate-firmware [<id-bus> <id-bus2> ... <id-busN>] [<opciones>]

Algunos dispositivos de memoria persistente ejecutan un firmware localmente en el dispositivo / "DIMM" para realizar tareas como la gestión de medios, el aprovisionamiento de capacidad y la monitorización de la salud. El proceso de actualización de ese firmware típicamente implica un reinicio porque tiene implicaciones para las transacciones de memoria en curso. Sin embargo, los reinicios pueden ser costosos para sistemas que no pueden tolerar tiempos de inactividad prolongados.

El kernel detecta plataformas que exponen soporte para la activación de firmware en tiempo de ejecución (FWA). El ndctl update-firmware prepara nuevos binarios de firmware, pero si la plataforma soporta FWA, también armará los dispositivos para la activación. Luego, ndctl activate-firmware puede intentar activar el firmware en vivo. Sin embargo, si la plataforma indica que el controlador de memoria se desconectará durante la actualización ("activate_method == suspend"), la política predeterminada para la activación del firmware es inyectar un ciclo de hibernación truncado para congelar dispositivos y aplicaciones antes de que la plataforma inyecte la inactividad forzada, y luego reanudar el sistema.

PELIGRO el comando activate-firmware incluye una opción --force para indicar al controlador que omita el ciclo de hibernación y realice la actualización "en vivo". Es decir, organiza las aplicaciones y dispositivos para que compitan contra el período de inactividad inyectado por la plataforma. Esta opción solo debe usarse con conocimiento explícito de que el tiempo de inactividad de la plataforma no provocará violaciones de tiempo de espera de finalización para ningún dispositivo en el sistema.

EJEMPLOS

Comprobar si hay algún bus que soporte la activación sin desencadenar una activación:

# ndctl activate-firmware all --dry-run
ACPI.NFIT: ndbus1: no tiene dispositivos que soporten actualización de firmware.
nfit_test.1: ndbus3: no tiene dispositivos que soporten actualización de firmware.
e820: ndbus0: no tiene dispositivos que soporten actualización de firmware.
[
  {
    "provider":"nfit_test.0",
    "dev":"ndbus1",
    "scrub_state":"idle",
    "firmware":{
      "activate_method":"suspend",
      "activate_state":"idle"
    },
    "dimms":[
      {
...

Comprobar si un bus específico soporta la activación sin realizar una activación:

# ndctl activate-firmware nfit_test.0 --dry-run --force
[
  {
    "provider":"nfit_test.0",
    "dev":"ndbus2",
    "scrub_state":"idle",
    "firmware":{
      "activate_method":"suspend",
      "activate_state":"idle"
    },
    "dimms":[
...
]

El resultado es equivalente a ndctl list -BFDu tras una activación exitosa.

El comando ndctl list también puede enumerar el método de activación predeterminado:

# ndctl list -b nfit_test.0 -BF
[
  {
    "provider":"nfit_test.0",
    "dev":"ndbus2",
    "scrub_state":"idle",
    "firmware":{
      "activate_method":"suspend",
      "activate_state":"idle"
    }
  }
]

OPCIONES

-n, --dry-run

Realiza todas las acciones relacionadas con la activación, incluyendo el cumplimiento de --idle y --force, pero omite la ejecución final de la activación. Las anulaciones se deshacen antes de que el comando se complete. Las anulaciones fallidas se informarán como mensajes de error.

-I, --idle

Implícito por defecto, esta opción controla si la plataforma intentará aumentar el tiempo de espera de finalización de todos los dispositivos del sistema y validará que el tiempo de espera máximo de finalización satisface el tiempo necesario para realizar la activación. Este paso de validación puede ser anulado especificando --no-idle.

-f, --force

El método de activación toma por defecto la propiedad informada "bus.firmware.activate_method". Cuando el método es "live", esta opción --force se ignora. Cuando el método es "reset", no se intenta la activación en tiempo de ejecución. Cuando el método es "suspend", esta opción indica al controlador que omita el ciclo de hibernación para activar el firmware en el bus. Cuando el "activate_method" informado es "suspend", el controlador del kernel puede soportar anular el requisito de suspensión y en su lugar emitir la activación de firmware en vivo. PRECAUCIÓN esto puede llevar a un comportamiento indefinido del sistema si se violan los tiempos de espera de finalización del dispositivo para operaciones de memoria en curso.

-v, --verbose

Emite mensajes de depuración para el procedimiento de activación del firmware.
