NMCLI(1) Manual de Comandos Generales NMCLI(1)

NOMBRE

nmcli - herramienta de línea de comandos para controlar NetworkManager

SINOPSIS

nmcli [OPCIONES...] {help | general | networking | radio | connection | device | agent | monitor} [COMANDO] [ARGUMENTOS...]

DESCRIPCIÓN

nmcli es una herramienta de línea de comandos para controlar NetworkManager e informar sobre el estado de la red. Puede ser utilizado como un reemplazo para nm-applet u otros clientes gráficos. nmcli se utiliza para crear, mostrar, editar, eliminar, activar y desactivar conexiones de red, así como para controlar y mostrar el estado de los dispositivos de red. Consulte nmcli-examples(7) para ver ejemplos de nmcli listos para usar.

Usos típicos incluyen:

•Scripts: Utilice NetworkManager a través de nmcli en lugar de gestionar las conexiones de red manualmente. nmcli admite un formato de salida conciso que es más adecuado para el procesamiento de scripts. Tenga en cuenta que NetworkManager también puede ejecutar scripts, denominados "scripts de dispatcher", en respuesta a eventos de red. Consulte NetworkManager(8) para obtener detalles sobre estos scripts de dispatcher.
•Servidores, máquinas sin cabeza y terminales: nmcli se puede utilizar para controlar NetworkManager sin una GUI, incluyendo la creación, edición, inicio y detención de conexiones de red y la visualización del estado de la red.

OPCIONES

-a | --ask

Al usar esta opción, nmcli se detendrá y pedirá argumentos requeridos que falten, por lo que no se debe usar esta opción para fines no interactivos como scripts. Esta opción controla, por ejemplo, si se le pedirá una contraseña si es necesaria para conectarse a una red.

-c | --colors {yes | no | auto}

Esta opción controla la salida en color (usando secuencias de escape de terminal). yes habilita los colores, no los deshabilita, auto solo produce colores cuando la salida estándar se dirige a una terminal. El valor predeterminado es auto.

Los colores reales utilizados se configuran como se describe en terminal-colors.d(5). Por favor, consulte la sección COLORS para ver una lista de nombres de colores compatibles con nmcli.

Si la variable de entorno NO_COLOR está establecida (a cualquier valor no vacío), entonces el coloreado se deshabilita con el modo "auto". Si la variable de entorno CLICOLOR_FORCE está establecida (a cualquier valor no vacío), entonces el coloreado se habilita con el modo "auto". Habilitar explícitamente el coloreado anula la variable de entorno.

--complete-args

En lugar de realizar la acción deseada, nmcli listará las posibles completaciones para el último argumento. Esto es útil para implementar la compleción de argumentos en el shell.

El estado de salida indicará éxito o devolverá un código 65 para indicar que el último argumento es un nombre de archivo.

NetworkManager incluye soporte de compleción de comandos para GNU Bash.

-e | --escape {yes | no}

Si escapar los caracteres : y \ en el modo tabular conciso. El carácter de escape es \.

Si se omite, el valor predeterminado es yes.

-f | --fields {campo1,campo2... | all | common}

Esta opción se utiliza para especificar qué campos (nombres de columna) se deben imprimir. Los nombres de campo válidos difieren para comandos específicos. Enumere los campos disponibles proporcionando un valor inválido a la opción --fields. all se utiliza para imprimir todos los valores de campo válidos del comando. common se utiliza para imprimir los valores de campo comunes del comando.

Si se omite, el valor predeterminado es common.

-g | --get-values {campo1,campo2... | all | common}

Esta opción se utiliza para imprimir valores de campos específicos. Es básicamente un atajo para --mode tabular --terse --fields y es una forma conveniente de recuperar valores para campos particulares. Los valores se imprimen uno por línea sin encabezados.

Si se especifica una sección en lugar de un campo, se imprimirá el nombre de la sección seguido de los valores separados por dos puntos de los campos que pertenecen a esa sección, todo en la misma línea.

-h | --help

Imprimir información de ayuda.

-m | --mode {tabular | multiline}

Cambiar entre la salida tabular y multilínea:

tabular

La salida es una tabla donde cada línea describe una sola entrada. Las columnas definen propiedades particulares de la entrada.

multiline

Cada entrada consta de múltiples líneas, cada propiedad en su propia línea. Los valores se prefijan con el nombre de la propiedad.

Si se omite, el valor predeterminado es tabular para la mayoría de los comandos. Para los comandos que producen información más estructurada, que no se puede mostrar en una sola línea, el valor predeterminado es multiline. Actualmente, son:

•nmcli connection show ID
•nmcli device show

-p | --pretty

La salida es bonita. Esto hace que nmcli produzca salidas fácilmente legibles para humanos, es decir, los valores están alineados, se imprimen encabezados, etc.

-s | --show-secrets

Al usar esta opción, nmcli mostrará contraseñas y secretos que puedan estar presentes en la salida de una operación. Esta opción también influye en el eco de las contraseñas escritas por el usuario como entrada.

-t | --terse

La salida es concisa. Este modo está diseñado y es adecuado para el procesamiento por computadora (script).

--offline

Trabajar sin un demonio. Hace que los comandos connection add y connection modify acepten y produzcan datos de conexión a través de la entrada/salida estándar. Normalmente, nmcli se comunicaría con el servicio NetworkManager.

El formato de los datos de conexión (archivo de clave) se describe en el manual nm-settings-keyfile(5).

-v | --version

Mostrar la versión de nmcli.

-w | --wait segundos

Esta opción establece un período de tiempo de espera durante el cual nmcli esperará a que NetworkManager finalice las operaciones. Es especialmente útil para comandos que pueden tardar más en completarse, por ejemplo, la activación de conexiones.

Especificar un valor de 0 instruye a nmcli a no esperar, sino a salir inmediatamente con un estado de éxito. El valor predeterminado depende del comando ejecutado.

COMANDOS GENERALES

nmcli general {status | hostname | permissions | logging | reload} [ARGUMENTOS...]

Utilice este comando para mostrar el estado y los permisos de NetworkManager. También puede obtener y cambiar el nombre de host del sistema, así como el nivel de registro y los dominios de NetworkManager.

status

Muestra el estado general de NetworkManager. Esta es la acción predeterminada, cuando no se proporciona ningún comando adicional para nmcli general.

hostname [hostname]

Obtiene y cambia el nombre de host del sistema. Sin argumentos, imprime el nombre de host configurado actualmente. Cuando se proporciona un nombre de host, se entregará a NetworkManager para que se establezca como el nuevo nombre de host del sistema.

Tenga en cuenta que el término nombre de host del "sistema" también puede ser referido como "persistente" o "estático" por otros programas o herramientas. El nombre de host se almacena en el archivo /etc/hostname en la mayoría de las distribuciones. Por ejemplo, el servicio systemd-hostnamed utiliza el término nombre de host "estático" y solo lee el archivo /etc/hostname cuando se inicia.

permissions

Muestra los permisos que tiene un llamador para varias operaciones autenticadas que proporciona NetworkManager, como habilitar y deshabilitar redes, cambiar el estado de Wi-Fi y WWAN, modificar conexiones, etc.

logging [level level] [domains domains...]

Obtiene y cambia el nivel de registro y los dominios de NetworkManager. Sin ningún argumento, se muestra el nivel de registro y los dominios actuales. Para cambiar el estado de registro, proporcione los parámetros level y/o domain. Consulte NetworkManager.conf(5) para ver los valores de nivel y dominio disponibles.

reload [flags...]

Recarga la configuración de NetworkManager y realiza ciertas actualizaciones, como vaciar cachés o reescribir externas

COMANDOS DE CONTROL DE RED

nmcli networking {on | off | connectivity} [ARGUMENTOS...]

Consulta el estado de la red de NetworkManager, habilita y deshabilita la red.

on, off

Habilita o deshabilita el control de red por parte de NetworkManager. Todas las interfaces gestionadas por NetworkManager se desactivan cuando la red se deshabilita.

connectivity [check]

Obtiene el estado de conectividad de red. El argumento opcional check indica a NetworkManager que vuelva a comprobar la conectividad; de lo contrario, se muestra el último estado de conectividad conocido sin volver a comprobar.

Los estados posibles son:

none

el host no está conectado a ninguna red.

portal

el host está detrás de un portal cautivo y no puede acceder a Internet completamente.

limited

el host está conectado a una red, pero no tiene acceso a Internet.

full

el host está conectado a una red y tiene acceso completo a Internet.

unknown

no se puede determinar el estado de conectividad.

COMANDOS DE CONTROL DE TRANSMISIÓN DE RADIO

nmcli radio {all | wifi | wwan} [ARGUMENTOS...]

Muestra el estado de los interruptores de radio, o habilita y deshabilita los interruptores.

wifi [on | off]

Muestra o establece el estado de Wi-Fi en NetworkManager. Si no se proporcionan argumentos, se imprime el estado de Wi-Fi; on habilita Wi-Fi; off deshabilita Wi-Fi.

wwan [on | off]

Muestra o establece el estado de WWAN (banda ancha móvil) en NetworkManager. Si no se proporcionan argumentos, se imprime el estado de banda ancha móvil; on habilita la banda ancha móvil, off la deshabilita.

all [on | off]

Muestra o establece todos los interruptores de radio mencionados anteriormente al mismo tiempo.

MONITOR DE ACTIVIDAD

nmcli monitor

Observa la actividad de NetworkManager. Supervisa cambios en el estado de conectividad, dispositivos o perfiles de conexión.

Consulte también nmcli connection monitor y nmcli device monitor para supervisar cambios en dispositivos o conexiones específicas.

COMANDOS DE GESTIÓN DE CONEXIONES

nmcli connection {show | up | down | modify | add | edit | clone | delete | monitor | reload | load | import | export | migrate} [ARGUMENTOS...]

NetworkManager almacena toda la configuración de red como "conexiones", que son colecciones de datos (detalles de Capa 2, direccionamiento IP, etc.) que describen cómo crear o conectarse a una red. Una conexión está "activa" cuando un dispositivo utiliza la configuración de esa conexión para crear o conectarse a una red. Puede haber varias conexiones que se apliquen a un dispositivo, pero solo una de ellas puede estar activa en ese dispositivo en un momento dado. Las conexiones adicionales se pueden utilizar para permitir un cambio rápido entre diferentes redes y configuraciones.

Considere una máquina que normalmente está conectada a una red habilitada para DHCP, pero a veces está conectada a una red de prueba que utiliza direccionamiento IP estático. En lugar de reconfigurar manualmente eth0 cada vez que se cambia la red, la configuración se puede guardar como dos conexiones que se aplican a eth0, una para DHCP (llamada default) y otra con los detalles de direccionamiento estático (llamada testing). Al conectarse a la red habilitada para DHCP, el usuario ejecutaría nmcli con up default, y al conectarse a la red estática, el usuario ejecutaría nmcli con up testing.

show [--active] [--order [+-]category:...]

Lista los perfiles de conexión en memoria y en disco, algunos de los cuales pueden estar activos si un dispositivo está utilizando ese perfil de conexión. Sin parámetro, se listan todos los perfiles. Cuando se especifica la opción --active, solo se muestran los perfiles activos.

La opción --order se puede usar para obtener un orden personalizado de las conexiones. Las conexiones se pueden ordenar por estado activo (active), nombre (name), tipo (type) o ruta de D-Bus (path). Si las conexiones son iguales según una categoría de ordenación, se puede especificar una categoría adicional. El orden de clasificación predeterminado es equivalente a --order active:name:path. + o ningún prefijo significa ordenación en orden ascendente (alfabético o numérico), - significa orden inverso (descendente). Los nombres de las categorías se pueden abreviar (por ejemplo, --order -a:na).

show [--active] [id | uuid | path | apath] ID...

Muestra detalles de las conexiones especificadas. Por defecto, se muestra tanto la configuración estática como los datos de la conexión activa. Cuando se especifica la opción --active, solo se tienen en cuenta los perfiles activos. Utilice la opción global --show-secrets para mostrar los secretos asociados con el perfil.

Las palabras clave id, uuid, path y apath se pueden utilizar si ID es ambiguo. Las palabras clave opcionales que especifican ID son:

id

el ID denota un nombre de conexión.

uuid

el ID denota un UUID de conexión.

path

el ID denota una ruta de conexión estática de D-Bus en el formato de /org/freedesktop/NetworkManager/Settings/num o solo num.

apath

el ID denota una ruta de conexión activa de D-Bus en el formato de /org/freedesktop/NetworkManager/ActiveConnection/num o solo num.

Es posible filtrar la salida utilizando la opción global --fields. Utilice los siguientes valores:

profile

solo muestra la configuración del perfil estático.

active

solo muestra los datos de la conexión activa (cuando el perfil está activo).

También puede especificar campos concretos. Para la configuración estática, utilice los nombres de configuración y propiedad descritos en la página del manual nm-settings-nmcli(5). Para datos activos, utilice GENERAL, IP4, DHCP4, IP6, DHCP6, VPN.

Cuando no se da ningún comando a nmcli connection, la acción predeterminada es nmcli connection show.

up [id | uuid | path] ID [ifname ifname] [ap BSSID] [passwd-file file]

Activa una conexión. La conexión se identifica por su nombre, UUID o ruta de D-Bus. Si ID es ambiguo, se puede utilizar una palabra clave id, uuid o path. Cuando se requiere un dispositivo específico para activar la conexión, se debe proporcionar la opción ifname con el nombre de la interfaz. Si no se proporciona ID, se requiere ifname, y NetworkManager activará la mejor conexión disponible para el ifname dado. En el caso de una conexión VPN, la opción ifname especifica el dispositivo de la conexión base. La opción ap especifica a qué AP en particular debe conectarse en caso de una conexión Wi-Fi.

Si la opción --wait no se especifica, el tiempo de espera por defecto será de 90 segundos.

Consulte connection show arriba para ver la descripción de las palabras clave que especifican ID.

Las opciones disponibles son:

ifname

interfaz que se utilizará para la activación.

ap

BSSID del AP al que el comando debe conectarse (para conexiones Wi-Fi).

passwd-file

algunas redes pueden requerir credenciales durante la activación. Puede proporcionar estas credenciales utilizando esta opción. Cada línea del archivo debe contener una contraseña en el formato: 
nombre_configuración.nombre_propiedad:la contraseña

Por ejemplo, para Wi-Fi WPA con PSK, la línea sería

802-11-wireless-security.psk:secreto12345

Para la contraseña de 802.1X, la línea sería

802-1x.password:mi contraseña 1X

nmcli también acepta las cadenas wifi-sec y wifi en lugar de 802-11-wireless-security. Cuando NetworkManager requiere una contraseña y no se proporciona, nmcli la solicitará cuando se ejecute con --ask. Si no se pasó --ask, NetworkManager puede solicitar a otro agente de secretos que pueda estar en ejecución (típicamente un agente de secretos gráfico, como nm-applet o gnome-shell).

down [id | uuid | path | apath] ID...

Desactiva una conexión de un dispositivo sin impedir que el dispositivo se active automáticamente más. Se pueden pasar varias conexiones al comando.

Tenga en cuenta que este comando desactiva la conexión activa especificada, pero el dispositivo en el que estaba activa la conexión, todavía está listo para conectarse y realizará la activación automática buscando una conexión adecuada que tenga el indicador 'autoconnect' establecido. Tenga en cuenta que el perfil de conexión que se desactiva se bloquea internamente para que no se conecte automáticamente de nuevo. Por lo tanto, no se conectará automáticamente hasta el reinicio o hasta que el usuario realice una acción que u

autodesconexión, como modificar el perfil o activarlo explícitamente.

En la mayoría de los casos, es posible que desee utilizar el comando device down en su lugar.

La conexión se identifica por su nombre, UUID o ruta de D-Bus. Si ID es ambiguo, se puede usar la palabra clave id, uuid, path o apath.

Consulte connection show más arriba para ver la descripción de las palabras clave que especifican ID.

Si no se especifica la opción --wait, el tiempo de espera predeterminado será de 10 segundos.

modify [--temporary] [id | uuid | path] [ID] {option value | [+|-]setting.property value}...

Añade, modifica o elimina propiedades en el perfil de conexión.

Para establecer la propiedad, simplemente especifique el nombre de la propiedad seguido del valor. Un valor vacío ("") restablece el valor de la propiedad a su valor predeterminado.

Consulte nm-settings-nmcli(5) para obtener una referencia completa de los nombres de configuración y propiedades, sus descripciones y valores predeterminados. El setting y la property se pueden abreviar siempre que sean únicos.

Si desea añadir un elemento o una bandera al valor existente, utilice el prefijo + para el nombre de la propiedad o alias. Si desea eliminar elementos de una propiedad de tipo contenedor o de bandera, utilice el prefijo -. Para ciertas propiedades, también puede eliminar elementos especificando los índices (basados en cero). Los modificadores + y - solo tienen un efecto real en las propiedades que los admiten. Estas son, por ejemplo, propiedades multivalor (contenedores) o banderas como ipv4.dns, ip4, ipv4.addresses, bond.options, 802-1x.phase1-auth-flags, etc.

La conexión se identifica por su nombre, UUID o ruta de D-Bus. Si ID es ambiguo, se puede usar la palabra clave id, uuid o path. El ID no se utiliza con la opción global --offline.

Cuando se utiliza la opción global --offline, el comando lee la conexión desde la entrada estándar y muestra la conexión modificada en la salida estándar en lugar de hacer que el demonio NetworkManager actúe sobre la conexión especificada.

Además de las propiedades y valores, se aceptan dos opciones especiales:

save

Controla si la conexión debe ser persistente, es decir, si NetworkManager debe almacenarla en disco (predeterminado: sí).

--

Si se encuentra un único argumento --, se ignora. Esto es para la compatibilidad con versiones anteriores de nmcli.

Cuando se utiliza la opción global --offline, el comando imprime la conexión resultante en la salida estándar en lugar de añadir realmente la conexión a través del demonio NetworkManager.

edit {[id | uuid | path] ID | [type type] [con-name name] }

Edita una conexión existente o añade una nueva, utilizando un editor interactivo.

La conexión existente se identifica por su nombre, UUID o ruta de D-Bus. Si ID es ambiguo, se puede usar la palabra clave id, uuid o path. Consulte connection show más arriba para ver la descripción de las palabras clave que especifican ID. No proporcionar un ID significa que se añadirá una nueva conexión.

El editor interactivo le guiará a través de la edición de la conexión y le permitirá cambiar los parámetros de la conexión según sus necesidades, mediante una sencilla interfaz controlada por menús. El editor indica qué configuraciones y propiedades se pueden modificar y proporciona ayuda en línea.

Opciones disponibles:

type

tipo de la nueva conexión; los tipos válidos son los mismos que para el comando connection add.

con-name

nombre para la nueva conexión. Se puede cambiar más tarde en el editor.

Consulte también nm-settings-nmcli(5) para ver todos los nombres de configuración y propiedades de NetworkManager, y sus descripciones; y nmcli-examples(7) para ver sesiones de ejemplo del editor.

clone [--temporary] [id | uuid | path] ID new_name

Clona una conexión. La conexión a clonar se identifica por su nombre, UUID o ruta de D-Bus. Si ID es ambiguo, se puede usar la palabra clave id, uuid o path. Consulte connection show más arriba para ver la descripción de las palabras clave que especifican ID. new_name es el nombre de la nueva conexión clonada. La nueva conexión será una copia exacta excepto por las propiedades connection.id (new_name) y connection.uuid (generado).

El nuevo perfil de conexión se guardará como persistente a menos que se especifique la opción --temporary, en cuyo caso el nuevo perfil no existirá después de reiniciar NetworkManager.

delete [id | uuid | path] ID...

Elimina una conexión configurada. La conexión a eliminar se identifica por su nombre, UUID o ruta de D-Bus. Si ID es ambiguo, se puede usar la palabra clave id, uuid o path. Consulte connection show más arriba para ver la descripción de las palabras clave que especifican ID.

Si no se especifica la opción --wait, el tiempo de espera predeterminado será de 10 segundos.

monitor [id | uuid | path] ID...

Supervisa la actividad del perfil de conexión. Este comando imprime una línea cada vez que la conexión especificada cambia. La conexión a supervisar se identifica por su nombre, UUID o ruta de D-Bus. Si ID es ambiguo, se puede usar la palabra clave id, uuid o path. Consulte connection show más arriba para ver la descripción de las palabras clave que especifican ID.

Supervisa todos los perfiles de conexión en caso de que no se especifique ninguno. El comando termina cuando desaparecen todas las conexiones supervisadas. Si desea supervisar la creación de conexiones, considere usar el monitor global con el comando nmcli monitor.

reload

Recarga todos los archivos de conexión desde el disco. NetworkManager no supervisa los cambios en la conexión. Por lo tanto, debe utilizar este comando para indicar a NetworkManager que vuelva a leer los perfiles de conexión del disco cuando se hayan realizado cambios en ellos.

load filename...

Carga/recarga uno o más archivos de conexión desde el disco. Úselo después de editar manualmente un archivo de conexión para asegurarse de que NetworkManager conozca su estado más reciente.

import [--temporary] type type file file

Importa una configuración externa/foránea como un perfil de conexión de NetworkManager. El tipo del archivo de entrada se especifica mediante la opción type.

Por el momento, solo se admiten configuraciones de VPN. La configuración es importada por los plugins de VPN de NetworkManager. Los valores de type son los mismos que para la opción vpn-type en nmcli connection add. Las configuraciones de VPN son importadas por los plugins de VPN. Por lo tanto, el plugin de VPN adecuado debe estar instalado para que nmcli pueda importar los datos.

El perfil de conexión importado se guardará como persistente a menos que se especifique la opción --temporary, en cuyo caso el nuevo perfil no existirá después de reiniciar NetworkManager.

export [id | uuid | path] ID [file]

Exporta una conexión.

están especificados, el comando actúa sobre todas las conexiones disponibles. Por lo tanto, sin argumentos, el comando migra todos los perfiles de conexión al plugin de archivo de claves.

nmcli device {status | show | set | up | connect | reapply | modify | down | disconnect | delete | monitor | wifi | lldp | checkpoint} [ARGUMENTOS...]

Muestra y gestiona interfaces de red.

status

Muestra el estado de los dispositivos.

Esta es la acción predeterminada si no se especifica ningún comando para nmcli device.

show [ifname]

Muestra información detallada sobre los dispositivos. Sin un argumento, se examinan todos los dispositivos. Para obtener información sobre un dispositivo específico, se debe proporcionar el nombre de la interfaz.

set [ifname] ifname [autoconnect {yes | no}] [managed {yes | no}]

Establece las propiedades del dispositivo.

up ifname

Conecta el dispositivo. NetworkManager intentará encontrar una conexión adecuada que se activará. También considerará las conexiones que no estén configuradas para conectarse automáticamente.

Si no existe ninguna conexión compatible, se creará y activará un nuevo perfil con la configuración predeterminada. Esto diferencia nmcli connection up ifname "$DEVICE" de nmcli device up "$DEVICE"

Si la opción --wait no está especificada, el tiempo de espera predeterminado será de 90 segundos.

connect ifname

Alias del comando up. Antes de la versión 1.34.0, up no era compatible.

reapply ifname

Intenta actualizar el dispositivo con los cambios en la conexión activa actualmente realizada desde la última vez que se aplicaron.

modify ifname {option value | [+|-]setting.property value}...

Modifica la configuración actualmente activa en el dispositivo.

Este comando le permite realizar cambios temporales en una configuración activa en un dispositivo particular. Los cambios no se conservan en el perfil de conexión.

Consulte nm-settings-nmcli(5) para obtener la lista de propiedades disponibles. Tenga en cuenta que algunas propiedades no se pueden cambiar en un dispositivo ya conectado.

down ifname...

Desconecta un dispositivo e impide que el dispositivo active automáticamente conexiones adicionales sin intervención del usuario/manual. Tenga en cuenta que desconectar dispositivos de software puede significar que los dispositivos desaparecerán.

Si la opción --wait no está especificada, el tiempo de espera predeterminado será de 10 segundos.

disconnect ifname...

Alias del comando down. Antes de la versión 1.34.0, down no era compatible.

delete ifname...

Elimina un dispositivo. El comando elimina la interfaz del sistema. Tenga en cuenta que esto solo funciona para dispositivos de software como bonds, bridges, teams, etc. Los dispositivos de hardware (como Ethernet) no pueden ser eliminados por el comando.

Si la opción --wait no está especificada, el tiempo de espera predeterminado será de 10 segundos.

monitor [ifname...]

Supervisa la actividad del dispositivo. Este comando imprime una línea cada vez que los dispositivos especificados cambian de estado.

Supervisa todos los dispositivos si no se especifica ninguna interfaz. El monitor termina cuando desaparecen todos los dispositivos especificados. Si desea supervisar la adición de dispositivos, considere utilizar el monitor global con el comando nmcli monitor.

wifi [list [--rescan | auto | no | yes] [ifname ifname] [bssid BSSID]]

Enumera los puntos de acceso Wi-Fi disponibles. Las opciones ifname y bssid se pueden usar para enumerar AP para una interfaz en particular o con un BSSID específico, respectivamente.

Por defecto, nmcli se asegura de que la lista de puntos de acceso no tenga más de 30 segundos y activa un escaneo de red si es necesario. La opción --rescan se puede usar para forzar o deshabilitar el escaneo, independientemente de cuán reciente sea la lista de puntos de acceso.

wifi connect (B)SSID [password password] [wep-key-type {key | phrase}] [ifname ifname] [bssid BSSID] [name name] [private {yes | no}] [hidden {yes | no}]

Conéctese a una red Wi-Fi especificada por SSID o BSSID. El comando encuentra una conexión coincidente o crea una y luego la activa en un dispositivo. Este es el homólogo en línea de comandos de hacer clic en un SSID en un cliente gráfico. Si ya existe una conexión para la red, es posible activar la conexión existente de la siguiente manera: nmcli con up id name. Tenga en cuenta que solo las redes abiertas, WEP y WPA-PSK son compatibles si no existe una conexión previa. También se asume que la configuración IP se obtiene a través de DHCP.

Si la opción --wait no está especificada, el tiempo de espera predeterminado será de 90 segundos.

Las opciones disponibles son:

password

contraseña para redes seguras (WEP o WPA).

wep-key-type

tipo de clave WEP, ya sea key para clave ASCII/HEX o phrase para frase de contraseña.

ifname

interfaz que se utilizará para la activación.

bssid

si se especifica, la conexión creada se limitará solo al BSSID.

name

si se especifica, la conexión usará el nombre (de lo contrario, NM creará un nombre).

private

si se establece en yes, la conexión solo será visible para el usuario que la creó. De lo contrario, la conexión es a nivel de sistema, que es el valor predeterminado.

hidden

establecido en yes al conectarse por primera vez a un AP que no transmite su SSID. De lo contrario, el SSID no se encontraría y el intento de conexión fallaría.

wifi hotspot [ifname ifname] [con-name name] [ssid SSID] [band {a | bg}] [channel channel] [password password]

Crea un punto de acceso Wi-Fi. El comando crea un perfil de conexión de punto de acceso según las capacidades del dispositivo Wi-Fi y lo activa en el dispositivo. El punto de acceso está protegido con WPA si el dispositivo/controlador lo admite, de lo contrario se utiliza WEP. Utilice connection down o device down para detener el punto de acceso.

Los parámetros del punto de acceso se pueden influenciar con los parámetros opcionales:

ifname

qué dispositivo Wi-Fi se utiliza.

con-name

nombre del perfil de conexión del punto de acceso creado.

ssid

SSID del punto de acceso.

band

banda Wi-Fi a utilizar.

channel

canal Wi-Fi a utilizar.

password

contraseña a utilizar para el punto de acceso creado. Si no se proporciona, nmcli generará una contraseña. La contraseña es una clave precompartida WPA o una clave WEP.

Tenga en cuenta que la opción global --show-secrets se puede usar para mostrar la contraseña del punto de acceso. Es útil especialmente cuando la contraseña fue generada.

wifi rescan [ifname ifname] [ssid SSID...]

Solicita que NetworkManager escanee inmediatamente en busca de puntos de acceso disponibles. NetworkManager escanea las redes Wi-Fi periódicamente, pero en algunos casos puede ser útil iniciar el escaneo manualmente (por ejemplo, después de reanudar el ordenador). Al usar ssid, es posible escanear un SSID específico, lo cual es útil para APs con SSIDs ocultos. Puede proporcionar varios parámetros ssid para escanear más SSIDs.

Este comando no muestra los AP, utilice nmcli device wifi list para eso.

wifi show-password [ifname ifname]

Muestra los detalles de las redes Wi-Fi activas, incluidos los secretos.

lldp [list [ifname ifname]]

Muestra información sobre dispositivos vecinos aprendida a través del Protocolo de Descubrimiento de Capa de Enlace (LLDP). La opción ifname se puede usar para enumerar vecinos solo para una interfaz dada. El protocolo debe estar habilitado en la configuración de la conexión.

checkpoint [--timeout seconds] [ifname...] -- COMMAND...

Ejecuta el comando con un punto de control de configuración tomado y solicita una confirmación al finalizar. Cuando no se proporciona la confirmación, el punto de control se restaura automáticamente después del tiempo de espera.

Esto permite realizar cambios de configuración disruptivos en conexiones remotas con la opción de restaurar la configuración de red a un estado conocido y bueno en caso de error.

Si se especifica una lista de nombres de interfaz, se toma el punto de control, el punto de control solo se toma en los dispositivos especificados. De lo contrario, se toma un punto de control para todos los dispositivos.

Actualmente, el tiempo de espera predeterminado es de 15 segundos. Esto puede cambiar en una versión futura.

EJEMPLOS

nmcli connection modify em1 connection.autoconnect yes

habilita la conexión automática para la interfaz em1.

nmcli -p -t -f NAME,UUID con show

muestra los nombres y UUIDs de todas las conexiones. La opción -p muestra el progreso, y la opción -t la salida en formato "thin" para ser procesada fácilmente por scripts.

nmcli -p con up id "My wired connection"

activa el perfil de conexión con el nombre "My wired connection".

nmcli -p con up "My wired connection" ifname eth0

activa el perfil de conexión con el nombre "My wired connection" en la interfaz eth0. La opción -p hace que nmcli muestre el progreso de la activación.

nmcli con up 6b028a27-6dc9-4411-9886-e9ad1dd43761 ap 00:3A:98:7C:42:D3

conecta la conexión Wi-Fi con el UUID 6b028a27-6dc9-4411-9886-e9ad1dd43761 al AP con BSSID 00:3A:98:7C:42:D3.

nmcli device status

muestra el estado de todos los dispositivos.

nmcli dev down em2

desconecta una conexión en la interfaz em2 y marca el dispositivo como no disponible para autoconexión. Como resultado, no se activará ninguna conexión automáticamente en el dispositivo hasta que el 'autoconnect' del dispositivo se establezca en TRUE o el usuario active manualmente una conexión.

nmcli -f GENERAL,WIFI-PROPERTIES dev show wlan0

muestra detalles de la interfaz wlan0; solo se mostrarán las secciones GENERAL y WIFI-PROPERTIES.

nmcli -f CONNECTIONS device show wlp3s0

muestra todos los perfiles de conexión disponibles para tu interfaz Wi-Fi wlp3s0.

nmcli dev wifi

lista los puntos de acceso Wi-Fi disponibles conocidos por NetworkManager.

nmcli dev wifi con "Cafe Hotspot 1" password caffeine name "My cafe"

crea una nueva conexión llamada "My cafe" y luego la conecta al SSID "Cafe Hotspot 1" usando la contraseña "caffeine". Esto es principalmente útil al conectarse a "Cafe Hotspot 1" por primera vez. La próxima vez, es mejor usar nmcli con up id "My cafe" para que el perfil de conexión existente pueda ser utilizado y no se cree uno adicional.

nmcli -s dev wifi hotspot con-name QuickHotspot

crea un perfil de hotspot y lo conecta. Imprime la contraseña del hotspot que el usuario debería usar para conectarse al hotspot desde otros dispositivos.

nmcli dev modify em1 ipv4.method shared

inicia el uso compartido de la conexión IPv4 usando el dispositivo em1. El uso compartido estará activo hasta que el dispositivo se desconecte.

nmcli dev modify em1 ipv6.address 2001:db8::a:bad:c0de

añade temporalmente una dirección IP a un dispositivo. La dirección se eliminará cuando la misma conexión se active de nuevo.

nmcli connection add type ethernet autoconnect no ifname eth0

añade de forma no interactiva una conexión Ethernet vinculada a la interfaz eth0 con configuración IP automática (DHCP), y deshabilita la bandera de autoconexión de la conexión.

nmcli c a ifname Maxipes-fik type vlan dev eth0 id 55

añade de forma no interactiva una conexión VLAN con ID 55. La conexión usará eth0 y la interfaz VLAN se llamará Maxipes-fik.

nmcli c a ifname eth0 type ethernet ipv4.method disabled ipv6.method link-local

añade de forma no interactiva una conexión que usará la interfaz Ethernet eth0 y solo tendrá configurada una dirección IPv6 link-local.

nmcli connection edit ethernet-em1-2

edita la conexión existente "ethernet-em1-2" en el editor interactivo.

nmcli connection edit type ethernet con-name "yet another Ethernet connection"

añade una nueva conexión Ethernet en el editor interactivo.

nmcli con mod ethernet-2 connection.autoconnect no

modifica la propiedad 'autoconnect' en la configuración 'connection' de la conexión 'ethernet-2'.

nmcli con mod "Home Wi-Fi" wifi.mtu 1350

modifica la propiedad 'mtu' en la configuración 'wifi' de la conexión "Home Wi-Fi".

nmcli con mod em1-1 ipv4.method manual ipv4.addr "192.168.1.23/24 192.168.1.1, 10.10.1.5/8, 10.0.0.11"

establece el direccionamiento manual y las direcciones en el perfil em1-1.

nmcli con modify ABC +ipv4.dns 8.8.8.8

añade un servidor DNS público de Google a los servidores DNS en el perfil ABC.

nmcli con modify ABC -ipv4.addresses "192.168.100.25/24 192.168.1.1"

elimina la dirección IP especificada del perfil (estático) ABC.

nmcli con import type openvpn file ~/Downloads/frootvpn.ovpn

importa una configuración de OpenVPN a NetworkManager.

nmcli con export corp-vpnc /home/joe/corpvpn.conf

exporta el perfil VPN corp-vpnc de NetworkManager como una configuración estándar de Cisco (vpnc).

NOTAS

nmcli acepta abreviaturas, siempre que sean un prefijo único en el conjunto de opciones posibles. A medida que se añaden nuevas opciones, estas abreviaturas no garantizan seguir siendo únicas. Por lo tanto, para scripting y compatibilidad a largo plazo, se recomienda encarecidamente escribir los nombres completos de las opciones.
