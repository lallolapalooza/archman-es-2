NOMBRE

nmbd - Servidor de nombres NetBIOS para proporcionar servicios de nombres NetBIOS sobre IP a los clientes

SINOPSIS

nmbd [-D|--daemon] [-i|--interactive] [-F|--foreground] [--no-process-group] [-b|--build-options] [-p <número(s) de puerto>] [-P <nivel de perfilado>] [-d <nivel de depuración>] [--debug-stdout] [--configfile=<archivo de configuración>] [--option=<nombre>=<valor>] [-l|--log-basename <directorio de registro>] [--leak-report] [--leak-report-full] [-V|--version]

DESCRIPCIÓN

Este programa forma parte del conjunto de samba(7).

nmbd es un servidor que comprende y puede responder a solicitudes de servicio de nombres NetBIOS sobre IP, como las producidas por clientes SMB/CIFS como Windows 95/98/ME, Windows NT, Windows 2000, Windows XP y clientes LanManager. También participa en los protocolos de navegación que componen la vista del "Entorno de red" de Windows.

Los clientes SMB/CIFS, al iniciarse, pueden desear localizar un servidor SMB/CIFS. Es decir, desean saber qué número IP está utilizando un host especificado.

Entre otros servicios, nmbd escuchará dichas solicitudes y, si se especifica su propio nombre NetBIOS, responderá con el número IP del host en el que se está ejecutando. Su "propio nombre NetBIOS" es, por defecto, el nombre DNS principal del host en el que se está ejecutando, pero esto puede ser anulado por netbios name en /etc/samba/smb.conf. Por lo tanto, nmbd responderá a consultas broadcast de su(s) propio(s) nombre(s). Se pueden establecer nombres adicionales para que nmbd responda a través de parámetros en el archivo de configuración smb.conf(5).

nmbd también puede ser utilizado como servidor WINS (Windows Internet Name Server). Lo que básicamente significa es que actuará como un servidor de base de datos WINS, creando una base de datos a partir de las solicitudes de registro de nombres que recibe y respondiendo a las consultas de los clientes para esos nombres.

Además, nmbd puede actuar como proxy WINS, retransmitiendo consultas broadcast de clientes que no entienden cómo hablar el protocolo WINS a un servidor WINS.

OPCIONES

-D|--daemon

Si se especifica, este parámetro hace que nmbd opere como un demonio. Es decir, se desvincula y se ejecuta en segundo plano, atendiendo solicitudes en el puerto apropiado. Por defecto, nmbd operará como demonio si se lanza desde una línea de comandos. nmbd también puede ser operado desde el meta-demonio inetd, aunque no se recomienda.

-F|--foreground

Si se especifica, este parámetro hace que el proceso principal de nmbd no se convierta en demonio, es decir, no se duplique y se desvincule de la terminal. Todavía se crean procesos hijos de forma normal para atender cada solicitud de conexión, pero el proceso principal no sale. Este modo de operación es adecuado para ejecutar nmbd bajo supervisores de procesos como supervise y svscan del paquete daemontools de Daniel J. Bernstein, o el monitor de procesos AIX.

-i|--interactive

Si se especifica este parámetro, el servidor se ejecutará "interactivamente", no como un demonio, incluso si el servidor se ejecuta desde la línea de comandos de una shell. Establecer este parámetro anula el modo demonio implícito cuando se ejecuta desde la línea de comandos. nmbd también registra en la salida estándar, como si se hubiera dado el parámetro -S.

-H|--hosts <nombre de archivo>

Archivo lmhosts de NetBIOS. El archivo lmhosts es una lista de nombres NetBIOS a direcciones IP que es cargada por el servidor nmbd y utilizada a través del mecanismo de resolución de nombres name resolve order descrito en smb.conf(5) para resolver cualquier consulta de nombre NetBIOS necesaria por el servidor. Tenga en cuenta que el contenido de este archivo NO es utilizado por nmbd para responder a ninguna consulta de nombres. Añadir una línea a este archivo afecta a la resolución de nombres NetBIOS desde este host SOLO.

La ruta por defecto a este archivo está compilada en Samba como parte del proceso de compilación. Las rutas por defecto comunes son /usr/local/samba/lib/lmhosts, /usr/samba/lib/lmhosts o /etc/samba/lmhosts. Consulte la página del manual de lmhosts(5) para obtener detalles sobre el contenido de este archivo.

-p|--port <número de puerto UDP>

El número de puerto UDP es un valor entero positivo. Esta opción cambia el número de puerto UDP por defecto (normalmente 137) al que nmbd responde a las consultas de nombres. ¡No use esta opción a menos que sea un experto, en cuyo caso no necesitará ayuda!

--no-process-group

No crear un nuevo grupo de procesos para nmbd.

-d|--debuglevel=nivel

nivel es un entero de 0 a 10. El valor por defecto si no se especifica este parámetro es 0.

Cuanto mayor sea este valor, más detalles se registrarán en los archivos de registro sobre las actividades del servidor. En el nivel 0, solo se registrarán errores críticos y advertencias serias. El nivel 1 es un nivel razonable para el funcionamiento diario, ya que genera una pequeña cantidad de información sobre las operaciones realizadas.

Los niveles superiores a 1 generarán una cantidad considerable de datos de registro y solo deben usarse al investigar un problema. Los niveles superiores a 3 están diseñados para ser utilizados solo por desarrolladores y generan ENORMES cantidades de datos de registro, la mayor parte de los cuales es extremadamente críptica.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro log level en el archivo /etc/samba/smb.conf.

--debug-stdout

Redirigirá la salida de depuración a STDOUT. Por defecto, los demonios del servidor registran en un archivo de registro.

--configfile=ARCHIVO_CONFIGURACION

El archivo especificado contiene los detalles de configuración requeridos por el servidor. La información de este archivo incluye información específica del servidor, como qué archivo printcap usar, así como descripciones de todos los servicios que el servidor debe proporcionar. Consulte /etc/samba/smb.conf para obtener más información. El nombre del archivo de configuración por defecto se determina en tiempo de compilación.

--option=<nombre>=<valor>

Establece la opción smb.conf(5) "<nombre>" al valor "<valor>" desde la línea de comandos. Esto anula los valores predeterminados compilados en la configuración y las opciones leídas del archivo de configuración. Si un nombre o un valor incluyen un espacio, envuelva la opción completa --option=nombre=valor entre comillas.

-l|--log-basename=<directorio de registro>

Nombre base para los archivos de registro/depuración. Se añadirá la extensión ".progname" (por ejemplo, log.smbclient, log.smbd, etc...). El archivo de registro nunca es eliminado por el cliente.

--leak-report

Habilita la generación de informes de fugas de memoria de talloc al salir.

--leak-report-full

Habilita la generación de informes completos de fugas de memoria de talloc al salir.

-V|--version

Imprime el número de versión del programa.

-?|--help

Imprime un resumen de las opciones de la línea de comandos.

--usage

Muestra un breve mensaje de uso.

ARCHIVOS

/etc/inetd.conf

Si el servidor va a ser ejecutado por el meta-demonio inetd, este archivo debe contener la información de inicio adecuada para el meta-demonio.

/etc/rc

o cualquier script de inicialización que use su sistema).

Si se ejecuta el servidor como demonio al inicio, este archivo deberá contener una secuencia de inicio apropiada para el servidor.

/etc/services

Si se ejecuta el servidor a través del meta-demonio inetd, este archivo debe contener un mapeo del nombre del servicio (por ejemplo, netbios-ssn) al puerto del servicio (por ejemplo, 139) y al tipo de protocolo (por ejemplo, tcp).

/usr/local/samba/lib/smb.conf

Esta es la ubicación por defecto del archivo de configuración del servidor smb.conf(5). Otros lugares comunes donde los sistemas instalan este archivo son /usr/samba/lib/smb.conf y /etc/samba/smb.conf.

Cuando se ejecuta como servidor WINS (consulte el parámetro wins support en la página del manual de smb.conf(5)), nmbd almacenará la base de datos WINS en el archivo wins.dat en el directorio var/locks configurado donde sea que Samba haya sido configurado para instalarse.

Si nmbd actúa como browse master (consulte el parámetro local master en la página del manual de smb.conf(5), nmbd almacenará la base de datos de navegación en el archivo browse.dat en el directorio var/locks configurado donde sea que Samba haya sido configurado para instalarse.

SEÑALES

Para apagar un proceso nmbd, se recomienda NO usar SIGKILL (-9), excepto como último recurso, ya que esto puede dejar la base de datos de nombres en un estado inconsistente. La forma correcta de terminar nmbd es enviarle una señal SIGTERM (-15) y esperar a que muera por sí sola.

nmbd aceptará SIGHUP, lo que hará que vuelque sus listas de nombres en el archivo namelist.debug en el directorio /usr/local/samba/var/locks (o el directorio var/locks configurado donde sea que Samba se haya configurado para instalarse). Esto también hará que nmbd vuelque su base de datos de servidor en el archivo log.nmb. Además, la señal causará la recarga de la configuración de nmbd.

En lugar de enviar una señal SIGHUP, se puede enviar una solicitud para volcar las listas de nombres en el archivo y recargar un archivo de configuración utilizando el programa smbcontrol(1).

El nivel de registro de depuración de nmbd se puede aumentar o disminuir utilizando smbcontrol(1) (las señales SIGUSR[1|2] ya no se utilizan desde Samba 2.2). Esto permite diagnosticar problemas transitorios, mientras se sigue ejecutando a un nivel de registro normalmente bajo.
