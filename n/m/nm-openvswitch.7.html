NM-OPENVSWITCH(7) Visión general del soporte de NetworkManager para Open vSwitch NM-OPENVSWITCH(7)

NOMBRE

nm-openvswitch - visión general del soporte de NetworkManager para Open vSwitch

DESCRIPCIÓN

NetworkManager incluye soporte básico para Open vSwitch, suficiente para configurar configuraciones simples de Open vSwitch. No es exhaustivo y no expone toda la funcionalidad que proporciona Open vSwitch. Para implementaciones grandes o complicadas, se recomienda a los usuarios utilizar las herramientas nativas que se incluyen con Open vSwitch. Este documento busca proporcionar una visión general de la funcionalidad que proporciona actualmente NetworkManager, sus capacidades y limitaciones.

En primer lugar y lo más importante: NetworkManager aplica la configuración modificando directamente la OVSDB. Su modelo de configuración sigue de cerca el modelo de base de datos OVSDB y no proporciona el nivel de abstracción que proporciona ovs-vsctl.

En términos prácticos, esto significa lo siguiente:

•NetworkManager solo habla con una única instancia de OVSDB a través de un socket de dominio UNIX.
•La configuración se compone de Puentes (Bridges), Puertos (Ports) e Interfaces. Las Interfaces siempre están adjuntas a Puertos, y los Puertos siempre están adjuntos a Puentes.
•NetworkManager solo crea Puentes, Puertos e Interfaces que usted solicita. A diferencia de ovs-vsctl, no crea la interfaz local ni su puerto automáticamente.
•No se puede adjuntar una Interfaz directamente a un Puente. Siempre se necesita un Puerto, incluso si solo tiene una interfaz.
•No hay VLANs. El etiquetado VLAN se habilita estableciendo una propiedad ovs-port.tag en un Puerto.
•Tampoco hay bonds (agrupaciones de enlaces). La agrupación se habilita esclavizando múltiples Interfaces a un Puerto y se configura estableciendo propiedades en un puerto.

PUENTES

Los Puentes se representan mediante conexiones del tipo ovs-bridge. Debido a las limitaciones de OVSDB, los Puentes "vacíos" (sin Puertos) no pueden existir. NetworkManager inserta los registros para los Puentes en OVSDB cuando se adjunta un Puerto.

Limitación conocida: cuando se elimina el último puerto propiedad de NetworkManager, el puente también se elimina, incluso si hay otros puertos adjuntos externamente.

PUERTOS

Los Puertos se representan mediante conexiones del tipo ovs-port. Debido a las limitaciones de OVSDB, los Puertos "vacíos" (sin Interfaces) no pueden existir. Los Puertos también se pueden configurar para realizar etiquetado VLAN o Bonding. NetworkManager inserta los registros para los Puertos en OVSDB cuando se adjunta una Interfaz. Los Puertos deben estar adjuntos a un Puente.

Limitación conocida: cuando se elimina la última interfaz propiedad de NetworkManager, el puerto también se elimina, incluso si hay otras interfaces adjuntas externamente.

INTERFACES

Las Interfaces se representan mediante conexiones adjuntas a un Puerto. Las interfaces del sistema (que tienen un enlace Linux correspondiente) tienen un tipo de conexión respectivo del enlace (por ejemplo, "wired", "bond", "dummy", etc.). Otras interfaces (interfaces "internal" o "patch") son de tipo ovs-interface. Las entradas OVSDB se insertan al adjuntarlas a un Puerto.

EJEMPLOS

Ejemplo 1. Creación de un Puente con una única Interfaz interna

$ nmcli conn add type ovs-bridge conn.interface bridge0
Conexión 'ovs-bridge-bridge0' (d10fc64d-1d48-4394-a1b8-e1aea72f27d5) añadida con éxito.
$ nmcli conn add type ovs-port conn.interface port0 controller bridge0
Conexión 'ovs-port-port0' (5ae22bae-bba4-4815-9ade-7e635633e1f0) añadida con éxito.
$ nmcli conn add type ovs-interface port-type ovs-port conn.interface iface0 \
  controller port0 ipv4.method manual ipv4.address 192.0.2.1/24
Conexión 'ovs-interface-iface0' (3640d2a1-a2fd-4718-92f1-cffadb5b6cdc) añadida con éxito.

Como se mencionó anteriormente, necesita crear un Puerto incluso para una sola interfaz. Además, antes de añadir la Interfaz, los dispositivos Bridge y Port aparecen activos, pero aún no están configurados en OVSDB. Puede inspeccionar los resultados con ovs-vsctl show.

Ejemplo 2. Añadir una interfaz Linux a un Puente

$ nmcli conn add type ovs-port conn.interface port1 controller bridge0
Conexión 'ovs-port-port1' (67d041eb-8e7b-4458-afee-a1d07c9c4552) añadida con éxito.
$ nmcli conn add type ethernet conn.interface eth0 controller port1
Conexión 'ovs-slave-eth0' (d459c45c-cf78-4c1c-b4b7-505e71379624) añadida con éxito.

De nuevo, necesita un puerto.

Ejemplo 3. Creación de una VLAN

$ nmcli conn add type ovs-port conn.interface port2 controller bridge0 ovs-port.tag 120
Conexión 'ovs-port-port2' (3994c093-4ef7-4549-a4fd-627b831c3cb8) añadida con éxito.
$ nmcli conn add type ethernet conn.interface eth1 controller port2
Conexión 'ovs-slave-eth1' (099be06e-71ad-484d-8d5a-fcadc5f207f5) añadida con éxito.

Es solo un puerto con una etiqueta.

Ejemplo 4. Creación de un Bond

$ nmcli conn add type ovs-port conn.interface bond0 controller bridge0
Conexión 'ovs-port-bond0' (d154ebf9-e999-4e1b-a084-a3de53d25d8a) añadida con éxito.
$ nmcli conn add type ethernet conn.interface eth2 controller bond0
Conexión 'ovs-slave-eth2' (475ac1bf-30b2-4534-a877-27f33f58b082) añadida con éxito.
$ nmcli conn add type ethernet conn.interface eth3 controller bond0
Conexión 'ovs-slave-eth3' (8dedeecb-ed12-482b-b77a-24a4fb835136) añadida con éxito.

Es solo un Puerto con múltiples interfaces. Consulte el manual de nm-settings-nmcli para las opciones de Bonding que puede usar con "nmcli c add" o "nmcli c modify". Incluso podría establecer una etiqueta VLAN en el mismo Puerto para realizar etiquetado VLAN y bonding al mismo tiempo.

ERRORES

•No todas las capacidades de Open vSwitch están soportadas.
•Los dispositivos Open vSwitch no exponen muchas propiedades útiles en D-Bus.

Probablemente muchos más.
