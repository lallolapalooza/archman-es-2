NOMBRE

nm-settings-nmcli - Descripción de configuraciones y propiedades de los perfiles de conexión de NetworkManager para nmcli

DESCRIPCIÓN

NetworkManager se basa en un concepto de perfiles de conexión, a veces denominados solo conexiones. Estos perfiles de conexión contienen una configuración de red. Cuando NetworkManager activa un perfil de conexión en un dispositivo de red, se aplicará la configuración y se establecerá una conexión de red activa. Los usuarios son libres de crear tantos perfiles de conexión como consideren oportunos. De este modo, son flexibles al tener diversas configuraciones de red para diferentes necesidades de red.

NetworkManager proporciona una API para configurar perfiles de conexión, para activarlos y configurar la red, e inspeccionar la configuración de red actual. La herramienta de línea de comandos nmcli es una aplicación cliente de NetworkManager que utiliza esta API. Consulte nmcli(1) para obtener más detalles.

Con comandos como nmcli connection add, nmcli connection modify y nmcli connection show, se pueden crear, modificar e inspeccionar perfiles de conexión. Un perfil consta de propiedades. En D-Bus, esto sigue el formato descrito en nm-settings-dbus(5), mientras que esta página del manual describe el formato de configuración tal como lo espera nmcli.

Las configuraciones y propiedades que se muestran en las tablas a continuación enumeran todas las opciones de configuración de conexión disponibles. Sin embargo, tenga en cuenta que no todas las configuraciones son aplicables a todos los tipos de conexión. El editor nmcli connection editor también tiene un comando describe integrado que puede mostrar la descripción de configuraciones y propiedades particulares de esta página.

La configuración y la propiedad se pueden abreviar siempre que sean únicas. La lista a continuación también muestra alias que se pueden usar sin calificar en lugar del nombre completo. Por ejemplo, connection.interface-name e ifname se refieren a la misma propiedad.

configuración conexión

Configuraciones generales del perfil de conexión.

Propiedades:

connection.auth-retries

El número de reintentos para la autenticación. Cero significa intentar indefinidamente; -1 significa usar un valor predeterminado global. Si el valor predeterminado global no está establecido, los reintentos de autenticación serán 3 veces antes de fallar la conexión.

Actualmente, esto solo se aplica a la autenticación 802-1x.

Formato: entero

Valores válidos: -1 - 2147483647

connection.autoconnect

Alias: autoconnect

Si la conexión debe conectarse automáticamente o no por NetworkManager cuando los recursos para la conexión estén disponibles. TRUE para activar automáticamente la conexión, FALSE para requerir intervención manual para activar la conexión.

Autoconnect ocurre cuando las circunstancias son adecuadas. Eso significa, por ejemplo, que el dispositivo está actualmente administrado y no activo. Autoconnect, por lo tanto, nunca reemplaza ni compite con un perfil ya activo.

Tenga en cuenta que autoconnect no está implementado para perfiles VPN. Consulte "secondaries" como alternativa para conectar automáticamente perfiles VPN.

Dependiendo de "connection.multi-connect", un perfil puede (auto)conectarse solo una vez a la vez o varias veces.

Si varios perfiles están listos para autoconectar en el mismo dispositivo, se elige el que tenga una mejor "connection.autoconnect-priority". Si las prioridades son iguales, entonces se activa el perfil conectado más recientemente. Si los perfiles no se conectaron antes o su "connection.timestamp" es idéntico, la elección no está definida.

Formato: booleano

Valores válidos: true/yes/on, false/no/off

connection.autoconnect-ports

Si los puertos de esta conexión deben activarse automáticamente o no cuando NetworkManager active esta conexión. Esto solo tiene un efecto real para las conexiones de controlador. Las propiedades "autoconnect", "autoconnect-priority" y "autoconnect-retries" no están relacionadas con esta configuración. Los valores permitidos son: 0: dejar las conexiones de puerto sin tocar, 1: activar todas las conexiones de puerto con esta conexión, -1: predeterminado. Si se establece -1 (predeterminado), se lee la configuración global connection.autoconnect-ports para determinar el valor real. Si también es predeterminado, esto retrocede a 0.

Formato: elección (NMTernary)

Valores válidos: default (-1), false (0), true (1)

connection.autoconnect-priority

La prioridad de autoconexión en el rango de -999 a 999. Si la conexión está configurada para autoconectar, se preferirán las conexiones con mayor prioridad. El número más alto significa mayor prioridad. El valor predeterminado es 0. Tenga en cuenta que esta propiedad solo es importante si hay más de un perfil candidato para seleccionar para autoconectar. En caso de prioridad igual, se elige el perfil utilizado más recientemente.

Formato: entero

Valores válidos: -999 - 999

connection.autoconnect-retries

El número de veces que se debe intentar una conexión al activarla automáticamente antes de darse por vencido. Cero significa para siempre, -1 significa el valor predeterminado global (4 veces si no se anula). Establecer esto en 1 significa intentar la activación solo una vez antes de bloquear el autoconnect. Tenga en cuenta que después de un tiempo de espera, NetworkManager intentará autoconectar de nuevo.

Formato: entero

Valores válidos: -1 - 2147483647

Valores especiales: default (-1), forever (0)

connection.autoconnect-slaves

Si los puertos de esta conexión deben activarse automáticamente o no cuando NetworkManager active esta conexión. Esto solo tiene un efecto real para las conexiones de controlador. Las propiedades "autoconnect", "autoconnect-priority" y "autoconnect-retries" no están relacionadas con esta configuración. Los valores permitidos son: 0: dejar las conexiones de puerto sin tocar, 1: activar todas las conexiones de puerto con esta conexión, -1: predeterminado. Si se establece -1 (predeterminado), se lee la configuración global connection.autoconnect-slaves para determinar el valor real. Si también es predeterminado, esto retrocede a 0.

Obsoleto 1.46. Utilice "autoconnect-ports" en su lugar, esto es solo un alias.

Formato: elección (NMSettingConnectionAutoconnectSlaves)

Valores válidos: default (-1), no (0), yes (1)

connection.controller

Alias: controller

Nombre de la interfaz del dispositivo controlador o UUID de la conexión controladora.

Formato: cadena

connection.dns-over-tls

Si DNSOverTls (dns-over-tls) está habilitado para la conexión. DNSOverTls es una tecnología que utiliza TLS para cifrar el tráfico DNS.

Los valores permitidos son: "yes" (2) usar DNSOverTls y deshabilitar la reversión, "opportunistic" (1) usar DNSOverTls pero permitir la reversión a resolución sin cifrar, "no" (0) no usar nunca DNSOverTls. Si no se especifica "default", depende del plugin utilizado. Systemd-resolved utiliza la configuración global.

Esta característica requiere un plugin que soporte DNSOverTls. De lo contrario, la configuración no tendrá ningún efecto. Un plugin de este tipo es dns-systemd-resolved.

Formato: elección (NMSettingConnectionDnsOverTls)

Valores válidos: default (-1), no (0), opportunistic (1), yes (2)

connection.down-on-poweroff

Si la conexión se desactivará antes de que el sistema se apague. El valor predeterminado es "default" (-1). Cuando se especifica el valor predeterminado, se busca el valor global de la configuración de NetworkManager, si no está establecido, se considera como "no" (0).

Formato: elección (NMSettingConnectionDownOnPoweroff)

Valores válidos: default (-1), no (0), yes (1)

connection.gateway-ping-timeout

Si es mayor que cero, retrasa el éxito de la asignación de IP hasta que se alcance el tiempo de espera o una puerta de enlace IP responda a un ping.

Formato: entero

Valores válidos: 0 - 600

connection.id

Alias: con-name

Un identificador único legible por humanos para la conexión, como "Wi-Fi del trabajo" o "T-Mobile 3G".

Formato: cadena

connection.interface-name

Alias: ifname

El nombre de la interfaz de red a la que está vinculada esta conexión. Si no se establece, la conexión puede adjuntarse a cualquier interfaz del tipo apropiado (sujeto a las restricciones impuestas por otras configuraciones).

Para dispositivos de software, esto especifica el nombre del dispositivo creado.

Para tipos de conexión donde los nombres de interfaz no se pueden hacer persistentes fácilmente

(por ejemplo, banda ancha móvil o Ethernet USB), esta propiedad no debe utilizarse. Establecer esta propiedad restringe las interfaces con las que se puede usar una conexión y, si los nombres de las interfaces cambian o se reordenan, la conexión puede aplicarse a la interfaz incorrecta.

Formato: cadena

connection.ip-ping-addresses

La propiedad especifica una lista de direcciones IP de destino para realizar ping. Cuando se establecen varios destinos, NetworkManager iniciará varios procesos de ping en paralelo. Esta propiedad solo se puede establecer si se establece connection.ip-ping-timeout. El ip-ping-timeout se utiliza para retrasar el éxito de la asignación de IP hasta que se alcance el tiempo de espera especificado (en segundos) o una dirección IP de destino responda a un ping. La configuración de "ip-ping-addresses" puede retrasar el alcance de systemd's network-online.target debido a la espera de que las operaciones de ping se completen o se agote el tiempo de espera.

Formato: lista de direcciones IPv4 o IPv6

connection.ip-ping-addresses-require-all

La propiedad determina si es suficiente que cualquier verificación de ping tenga éxito entre "ip-ping-addresses", o si todas las verificaciones de ping deben tener éxito para "ip-ping-addresses".

Formato: elección (NMTernary)

Valores válidos: default (-1), false/no (0), true/yes (1)

connection.ip-ping-timeout

Si es mayor que cero, retrasa el éxito de la asignación de IP hasta que se alcance el tiempo de espera especificado (en segundos) o una dirección IP de destino responda a un ping. La propiedad especifica el tiempo de espera para "ip-ping-addresses". Esta propiedad es incompatible con "gateway-ping-timeout"; no puedes establecer estas dos propiedades al mismo tiempo.

Formato: entero

Valores válidos: 0 - 600

connection.lldp

Si LLDP está habilitado para la conexión.

Formato: elección (NMSettingConnectionLldp)

Valores válidos: default (-1), disable (0), enable-rx/enable (1)

connection.llmnr

Si la Resolución de Nombres Multicast de Enlace Local (LLMNR) está habilitada para la conexión. LLMNR es un protocolo basado en el formato de paquetes del Sistema de Nombres de Dominio (DNS) que permite a los hosts IPv4 y IPv6 realizar la resolución de nombres para hosts en el mismo enlace local.

Los valores permitidos son: "yes" (2) para registrar el nombre de host y resolver para la conexión, "no" (0) para deshabilitar LLMNR para la interfaz, "resolve" (1) para no registrar el nombre de host pero permitir la resolución de nombres de host LLMNR. Si no se especifica, "default" en última instancia depende del plugin DNS (que para systemd-resolved actualmente significa "yes").

Esta función requiere un plugin que soporte LLMNR. De lo contrario, la configuración no tendrá ningún efecto. Un plugin de este tipo es dns-systemd-resolved.

Formato: elección (NMSettingConnectionLlmnr)

Valores válidos: default (-1), no (0), resolve (1), yes (2)

connection.master

Alias: master

Nombre de la interfaz del dispositivo controlador o UUID de la conexión controladora.

Obsoleto en 1.46. Use "controller" en su lugar; esto es solo un alias.

Formato: cadena

connection.mdns

Si mDNS está habilitado para la conexión.

Los valores permitidos son: "yes" (2) para registrar el nombre de host y resolver para la conexión, "no" (0) para deshabilitar mDNS para la interfaz, "resolve" (1) para no registrar el nombre de host pero permitir la resolución de nombres de host mDNS y "default" (-1) para permitir la búsqueda de un valor predeterminado global en NetworkManager.conf. Si no se especifica, "default" en última instancia depende del plugin DNS.

Esta función requiere un plugin que soporte mDNS. De lo contrario, la configuración no tendrá ningún efecto. Actualmente, el único plugin DNS compatible es systemd-resolved. Para systemd-resolved, el valor predeterminado se puede configurar mediante la configuración MulticastDNS= en resolved.conf.

Formato: elección (NMSettingConnectionMdns)

Valores válidos: default (-1), no (0), resolve (1), yes (2)

connection.metered

Si la conexión tiene consumo medido.

Al actualizar esta propiedad en una conexión actualmente activada, el cambio surte efecto inmediatamente.

Formato: ternario

Valores válidos: true/yes/on, false/no/off, default/unknown

connection.mptcp-flags

Si se deben configurar los puntos finales de MPTCP y las banderas de dirección. Si MPTCP está habilitado en NetworkManager, configurará las direcciones de la interfaz como puntos finales de MPTCP. Tenga en cuenta que las direcciones de loopback IPv4 (127.0.0.0/8), las direcciones IPv4 de enlace local (169.254.0.0/16), la dirección de loopback IPv6 (::1), las direcciones IPv6 de enlace local (fe80::/10), las direcciones locales únicas IPv6 (ULA, fc00::/7) y las direcciones de extensión de privacidad IPv6 (rfc3041, ipv6.ip6-privacy) se excluirán de la configuración como puntos finales.

Si es "disabled" (0x1), el manejo de MPTCP para la interfaz está deshabilitado y no se registran puntos finales.

La bandera "enabled" (0x2) significa que el manejo de MPTCP está habilitado. Esta bandera también se puede inferir de la presencia de otras banderas.

Incluso cuando está habilitado, el manejo de MPTCP estará por defecto deshabilitado a menos que "/proc/sys/net/mptcp/enabled" sysctl esté activado. NetworkManager no cambia el sysctl y esto depende del administrador o la distribución. Para configurar puntos finales incluso si el sysctl está deshabilitado, se puede usar la bandera "also-without-sysctl" (0x4). En ese caso, NetworkManager no mira el sysctl y configura puntos finales independientemente.

Incluso cuando está habilitado, NetworkManager solo configurará puntos finales de MPTCP para una determinada familia de direcciones si hay una ruta predeterminada unicast (0.0.0.0/0 o ::/0) en la tabla de enrutamiento principal. La bandera "also-without-default-route" (0x8) puede anular esto.

Cuando el manejo de MPTCP está habilitado, los puntos finales se configuran con las banderas de dirección especificadas "signal" (0x10), "subflow" (0x20), "backup" (0x40), "fullmesh" (0x80). Consulte la página del manual ip-mptcp(8) para obtener información adicional sobre las banderas.

Si las banderas son cero (0x0), se respeta el valor predeterminado global de la conexión de NetworkManager.conf. Si aún no se especifica, el valor de respaldo es "enabled,subflow". Tenga en cuenta que esto significa que MPTCP se realiza por defecto dependiendo del sysctl "/proc/sys/net/mptcp/enabled".

NetworkManager no cambia los límites de MPTCP ni habilita MPTCP a través de "/proc/sys/net/mptcp/enabled". Esa es una configuración del host que el administrador puede cambiar a través de sysctl e ip-mptcp.

El filtrado inverso de ruta estricto (rp_filter) interrumpe muchos casos de uso de MPTCP, por lo que cuando el manejo de MPTCP para direcciones IPv4 en la interfaz está habilitado, NetworkManager relajaría el filtrado inverso de ruta estricto (1) a la configuración suelta (2).

Formato: banderas (NMMptcpFlags)

Valores válidos: none/default (0x0), disabled (0x1), enabled (0x2), also-without-sysctl (0x4), also-without-default-route (0x8), signal (0x10), subflow (0x20), backup (0x40), fullmesh (0x80)

connection.mud-url

Si está configurado, se establece en una URL de Descripción de Uso del Fabricante (MUD) que apunta a las políticas de red recomendadas por el fabricante para dispositivos IoT. Se transmite como una opción DHCPv4 o DHCPv6. El valor debe ser una URL válida que comience con "https://".

Se permite el valor especial "none" para indicar que no se utiliza ninguna URL MUD.

Si el valor por perfil no se especifica (el valor predeterminado), se consulta un valor predeterminado global de la conexión. Si aún no se especifica, el valor predeterminado final es "none".

Formato: cadena

connection.multi-connect

Especifica si el perfil puede estar activo varias veces en un momento dado. El valor es de tipo NMConnectionMultiConnect.

Formato: elección (NMConnectionMultiConnect)

Valores válidos: default (0), single (1), manual-multiple (2), multiple (3)

connection.permissions

Una matriz de cadenas que define qué acceso tiene un usuario determinado a esta conexión. Si es NULL o está vacía, se permite que todos los usuarios accedan a esta conexión; de lo contrario, se permite el acceso a los usuarios si y solo si están en esta lista. Cuando no está vacía, la conexión solo puede estar activa cuando uno de los usuarios especificados ha iniciado sesión en una sesión activa. Cada entrada tiene el formato "[type]:[id]:[reserved]"; por ejemplo, "user:dcbw:blah".

En este momento, solo se permite el tipo "user". Cualquier otro valor se ignora y se reserva para uso futuro. [id] es el nombre de usuario al que se refiere este permiso, que no puede contener el carácter ":". Cualquier información [reserved] presente debe ignorarse y se reserva para uso futuro. [type], [id] y [reserved] deben ser UTF-8 válidos.

Formato: lista de cadenas

connection.port-type

Alias: port-type

Nombre de configuración del tipo de dispositivo de la conexión controladora de este puerto (por ejemplo, "bond"), o NULL si esta conexión no es un puerto.

Formato: cadena

Valores válidos: bond, bridge, ovs-bridge, ovs-port, team, vrf

connection.secondaries

Lista de UUID de conexión que deben activarse cuando la conexión base en sí misma se activa. Actualmente, solo se admiten conexiones VPN.

Formato: lista de cadenas

connection.slave-type

Alias: slave-type

Nombre de configuración del tipo de dispositivo de la conexión controladora de este puerto (por ejemplo, "bond"), o NULL si esta conexión no es un puerto.

Obsoleto en 1.46. Use "port-type" en su lugar; esto es solo un alias.

Formato: cadena

Valores válidos: bond, bridge, ovs-bridge, ovs-port, team, vrf

connection.stable-id

Esto representa la identidad de la conexión utilizada para varios propósitos. Permite configurar múltiples perfiles para compartir la identidad. Además, el stable-id puede contener marcadores de posición que se sustituyen dinámicamente y de forma determinista según el contexto.

El stable-id se utiliza para generar direcciones privadas estables IPv6 con ipv6.addr-gen-mode=stable-privacy. También se utiliza para sembrar la dirección MAC clonada generada para ethernet.cloned-mac-address=stable y wifi.cloned-mac-address=stable. También se utiliza para derivar el identificador del cliente DHCP con ipv4.dhcp-client-id=stable, el DUID DHCPv6 con ipv6.dhcp-duid=stable-[llt,ll,uuid] y el IAID DHCP con ipv4.iaid=stable e ipv6.iaid=stable.

Tenga en cuenta que, según el contexto en el que se utilice, otros parámetros también se siembran en el algoritmo de generación. Por ejemplo, a menudo se incluye también una clave por host, para que diferentes sistemas generen IDs diferentes. O con ipv6.addr-gen-mode=stable-privacy, también el nombre del dispositivo

incluida, de modo que diferentes interfaces produzcan diferentes direcciones. La clave por host es la identidad de su máquina y se almacena en /var/lib/NetworkManager/secret_key. Consulte el manual de NetworkManager(8) sobre la clave secreta y la identidad del host.

El carácter '$' se trata de forma especial para realizar sustituciones dinámicas en el momento de la activación. Actualmente, se admiten "${CONNECTION}", "${DEVICE}", "${MAC}", "${NETWORK_SSID}", "${BOOT}", "${RANDOM}". Estos crean efectivamente identificadores únicos por conexión, por dispositivo, por SSID, por arranque o cada vez. "${CONNECTION}" utiliza el uuid de la conexión del perfil, "${DEVICE}" utiliza el nombre de la interfaz del dispositivo y "${MAC}" la dirección MAC permanente del dispositivo. "${NETWORK_SSID}" utiliza el SSID para redes Wi-Fi y recurre a "${CONNECTION}" en otras redes. Los patrones no reconocidos que siguen a '$' se tratan literalmente, sin embargo, están reservados para uso futuro. Por lo tanto, se recomienda evitar '$' o escaparlo como "$$". Por ejemplo, configúrelo en "${CONNECTION}-${BOOT}-${DEVICE}" para crear un ID único para esta conexión que cambie con cada reinicio y difiera según la interfaz en la que se active el perfil.

Si el valor no está configurado, se consulta un valor predeterminado global de la conexión. Si el valor aún no está configurado, el valor predeterminado es "default${CONNECTION}" para generar un ID único por perfil de conexión.

Formato: cadena

connection.timestamp

La hora, en segundos desde la Época Unix, en que la conexión fue _exitosamente_ activada por última vez.

NetworkManager actualiza la marca de tiempo de la conexión periódicamente cuando la conexión está activa para garantizar que una conexión activa tenga la marca de tiempo más reciente. La propiedad solo está destinada a la lectura (los cambios en esta propiedad no se conservarán).

Formato: solo lectura

connection.type

Alias: type

Tipo base de la conexión. Para conexiones dependientes de hardware, debe contener el nombre de configuración del tipo de hardware específico (es decir, "802-3-ethernet" o "802-11-wireless" o "bluetooth", etc.), y para conexiones no dependientes de hardware como VPN o de otro tipo, debe contener el nombre de configuración de ese tipo de configuración (es decir, "vpn" o "bridge", etc.).

Formato: cadena

Valores válidos: 6lowpan, 802-11-olpc-mesh, 802-11-wireless, 802-3-ethernet, adsl, bluetooth, bond, bridge, cdma, dummy, generic, gsm, hsr, infiniband, ip-tunnel, ipvlan, loopback, macsec, macvlan, ovs-bridge, ovs-interface, ovs-port, pppoe, team, tun, veth, vlan, vpn, vrf, vxlan, wifi-p2p, wimax, wireguard, wpan

connection.uuid

El uuid de la conexión es el identificador real de un perfil. No puede cambiar y debe ser único. Por lo tanto, a menudo es mejor referirse a un perfil por UUID, por ejemplo, con `nmcli connection up uuid $UUID`.

El UUID no se puede cambiar, excepto en modo offline. En ese caso, los valores especiales "new", "generate" y "" están permitidos para generar un nuevo UUID aleatorio.

Formato: un identificador universalmente único (UUID) válido según RFC4122.

connection.wait-activation-delay

Tiempo en milisegundos para esperar a que la conexión se considere activada. La espera comenzará después del evento del dispatcher pre-up.

El valor 0 significa sin tiempo de espera. El valor predeterminado es -1, que actualmente tiene el mismo significado que sin tiempo de espera.

Formato: entero

Valores válidos: -1 - 2147483647

connection.wait-device-timeout

Tiempo de espera en milisegundos para esperar el dispositivo al inicio. Durante el arranque, los dispositivos pueden tardar en ser detectados por el controlador. Esta propiedad provocará un retraso en NetworkManager-wait-online.service y nm-online para dar tiempo al dispositivo a aparecer. Esto funciona esperando el tiempo de espera especificado hasta que un dispositivo compatible con el perfil esté disponible y gestionado.

El valor 0 significa sin tiempo de espera. El valor predeterminado es -1, que actualmente tiene el mismo significado que sin tiempo de espera.

Formato: entero

Valores válidos: -1 - 2147483647

connection.zone

El nivel de confianza de la conexión. Cadena de texto insensible a mayúsculas y minúsculas de formato libre (por ejemplo, "Home", "Work", "Public"). Una zona NULL o no especificada significa que la conexión se colocará en la zona predeterminada definida por el firewall.

Al actualizar esta propiedad en una conexión activada actualmente, el cambio surte efecto inmediatamente.

Formato: cadena

Configuración de 6LoWPAN.

Propiedades:

6lowpan.parent

Alias: dev

Si se proporciona, especifica el nombre de la interfaz primaria o el UUID de la conexión primaria desde la cual se creará esta interfaz 6LowPAN.

Formato: cadena

Configuración de 802-1x

Configuración de Autenticación IEEE 802.1x.

Propiedades:

802-1x.altsubject-matches

Lista de cadenas para comparar con el altSubjectName del certificado presentado por el servidor de autenticación. Si la lista está vacía, no se realiza ninguna verificación del altSubjectName del certificado del servidor.

Formato: lista de cadenas

802-1x.anonymous-identity

Cadena de identidad anónima para los métodos de autenticación EAP. Se utiliza como identidad sin cifrar con tipos EAP que admiten identidad tunelizada diferente, como EAP-TTLS.

Formato: cadena

802-1x.auth-timeout

Un tiempo de espera para la autenticación. Cero significa el valor predeterminado global; si el valor predeterminado global no está configurado, el tiempo de espera de autenticación es de 25 segundos.

Formato: entero

Valores válidos: 0 - 2147483647

802-1x.ca-cert

Contiene la ruta al certificado CA si es utilizado por el método EAP especificado en la propiedad 802-1x.eap.

Esta propiedad puede no estar configurada incluso si el método EAP admite certificados CA, ¡pero esto permite ataques de hombre en el medio y NO se recomienda!

ipv4.dhcp-client-id

Una cadena que se envía al servidor DHCP para identificar la máquina local que el servidor DHCP puede utilizar para personalizar el arrendamiento y las opciones DHCP. Cuando la propiedad es una cadena hexadecimal ('aa:bb:cc') se interpreta como un ID de cliente binario, en cuyo caso se supone que el primer byte es el campo 'tipo' según RFC 2132 sección 9.14 y los bytes restantes pueden ser una dirección de hardware (por ejemplo, '01:xx:xx:xx:xx:xx:xx' donde 1 es el tipo Ethernet ARP y el resto es una dirección MAC). Si la propiedad no es una cadena hexadecimal, se considera un ID de cliente que no es de dirección de hardware y el campo 'tipo' se establece en 0.

Los valores especiales "mac" y "perm-mac" son compatibles, que utilizan la dirección MAC actual o permanente del dispositivo para generar un identificador de cliente con tipo ethernet (01). Actualmente, estas opciones solo funcionan para enlaces de tipo ethernet.

El valor especial "duid" genera un identificador de cliente compatible con RFC4361 basado en "ipv4.dhcp-iaid" y utiliza un DUID generado al hacer hash de /etc/machine-id.

El valor especial "stable" es compatible para generar un ID de cliente de tipo 0 basado en el stable-id (consulte connection.stable-id) y una clave por host. Si establece el stable-id, es posible que desee incluir el especificador "${DEVICE}" o "${MAC}" para obtener una clave por dispositivo.

El valor especial "none" evita que se envíe cualquier identificador de cliente. Tenga en cuenta que esto normalmente no se recomienda.

Si no se establece, se utiliza un valor predeterminado configurado globalmente en NetworkManager.conf. Si aún no se establece, el valor predeterminado depende del plugin DHCP. El cliente DHCP interno tendrá por defecto "mac" y el plugin dhclient intentará usar uno de su archivo de configuración si está presente, o no enviará ningún client-id de lo contrario.

ipv4.dns-priority

Prioridad de los servidores DNS.

La prioridad relativa de los servidores DNS especificados por esta configuración. Un valor numérico más bajo es mejor (mayor prioridad).

Los valores negativos tienen el efecto especial de excluir otras configuraciones con un valor de prioridad numérica mayor; por lo tanto, en presencia de al menos una prioridad negativa, solo se utilizarán los servidores DNS de las conexiones con el valor de prioridad más bajo. Para evitar todas las fugas de DNS, establezca la prioridad del perfil que debe usarse en el valor más negativo de todos los perfiles de conexión activos.

Cero selecciona un valor predeterminado configurado globalmente. Si este último falta o también es cero, el valor predeterminado es 50 para VPNs (incluido WireGuard) y 100 para otras conexiones.

Tenga en cuenta que la prioridad es para ordenar la configuración DNS para múltiples conexiones activas. No distingue entre múltiples servidores DNS dentro del mismo perfil de conexión.

Cuando varios dispositivos tienen configuraciones con la misma prioridad, las VPN se considerarán primero, luego los dispositivos con la mejor ruta predeterminada (métrica más baja) y luego todos los demás dispositivos.

Al usar dns=predeterminado, los servidores con mayor prioridad estarán en la parte superior de resolv.conf. Para priorizar un servidor dado sobre otro dentro de la misma conexión, simplemente especifíquelos en el orden deseado. Tenga en cuenta que comúnmente el resolvedor intenta los servidores de nombres en /etc/resolv.conf en el orden en que se enumeran, procediendo con el siguiente servidor en la lista en caso de fallo. Consulte, por ejemplo, la opción "rotate" de la configuración dns-options. Si hay prioridades DNS negativas, entonces solo se considerarán los servidores de nombres de los dispositivos con esa prioridad más baja.

Al usar un resolvedor DNS que admita reenvío condicional o DNS dividido (con la configuración dns=dnsmasq o dns=systemd-resolved), cada conexión se utiliza para consultar dominios en su lista de búsqueda. Los dominios de búsqueda determinan a qué servidores DNS preguntar, y la prioridad DNS se utiliza para priorizar servidores DNS según el dominio. Las consultas para dominios que no están presentes en ninguna lista de búsqueda se enrutan a través de conexiones que tienen el dominio comodín especial '~.', que se agrega automáticamente a las conexiones con la ruta predeterminada (o se puede agregar manualmente). Cuando varias conexiones especifican el mismo dominio, gana la que tenga la mejor prioridad (valor numérico más bajo). Si un subdominio está configurado en otra interfaz, se aceptará independientemente de la prioridad, a menos que el dominio padre en la otra interfaz tenga una prioridad negativa, lo que hace que el subdominio se sombree. Con DNS dividido, puede evitar fugas de DNS no deseadas configurando adecuadamente las prioridades DNS y los dominios de búsqueda, de modo que solo se configuren servidores de nombres de la interfaz deseada.

ipv6.addr-gen-mode

Configura el método para crear el identificador de interfaz IPv6 de las direcciones con Autoconfiguración de Direcciones IPv6 Sin Estado RFC4862 y direcciones de Enlace Local.

Los valores permitidos son: "eui64" (0), "stable-privacy" (1), "default" (3) o "default-or-eui64" (2).

Si la propiedad se establece en "eui64", las direcciones se generarán utilizando el token de interfaz derivado de la dirección de hardware. Esto hace que la parte del host de la dirección se mantenga constante, lo que permite rastrear la presencia del host cuando cambia de red. La dirección cambia cuando se reemplaza el hardware de la interfaz. Si se detecta una dirección duplicada, tampoco hay un recurso de respaldo para generar otra dirección. Cuando se configura, el "ipv6.token" se usa en lugar de la dirección MAC para generar direcciones para la autoconfiguración sin estado.

Si la propiedad se establece en "stable-privacy", el identificador de interfaz se genera según lo especificado por RFC7217. Esto funciona hasheando una clave específica del host (ver manual de NetworkManager(8)), el nombre de la interfaz, la propiedad "connection.stable-id" de la conexión y el prefijo de la dirección. Esto mejora la privacidad al dificultar el uso de la dirección para rastrear la presencia del host, y la dirección es estable cuando se reemplaza el hardware de la interfaz de red.

Los valores especiales "default" y "default-or-eui64" recurrirán al valor predeterminado global de la conexión según se documenta en el manual de NetworkManager.conf(5). Si el valor predeterminado global no se especifica, el valor de recurso será "stable-privacy" o "eui64", respectivamente.

Si no se especifica, al crear un nuevo perfil, el valor por defecto es "default".

Tenga en cuenta que esta configuración es distinta de las Extensiones de Privacidad configuradas mediante la propiedad "ip6-privacy" y no afecta a las direcciones temporales configuradas con esta opción.

ipv6.method

Establece el método de conexión IPv6. Puede establecer uno de los siguientes valores:
•"auto" - Habilita la auto-configuración IPv6. Por defecto, NetworkManager utiliza Anuncios de Router y, si el router anuncia el indicador "managed", NetworkManager solicita una dirección y prefijo IPv6 a un servidor DHCPv6.
•"dhcp" - Solicita una dirección y prefijo IPv6 a un servidor DHCPv6. Tenga en cuenta que DHCPv6 no tiene opciones para proporcionar rutas y la puerta de enlace predeterminada. Como consecuencia, al usar el método "dhcp", las conexiones se limitan a su propia subred.
•"manual" - Habilita la configuración de direcciones IPv6 estáticas en la interfaz. Tenga en cuenta que debe establecer al menos una dirección IP y un prefijo en la propiedad "ipv6.addresses".
•"disabled" - Deshabilita el protocolo IPv6 en este perfil de conexión.
•"ignore" - Configura NetworkManager para no realizar ningún cambio en la configuración IPv6 de la interfaz. Por ejemplo, puede usar la característica "accept_ra" del kernel para aceptar Anuncios de Router.
•"shared" - Proporciona acceso a la red a otros ordenadores. NetworkManager solicita un prefijo a un servidor DHCPv6 upstream, asigna una dirección a la interfaz y anuncia el prefijo a los clientes que se conectan a esta interfaz.
•"link-local" - Asigna una dirección de enlace local aleatoria de la subred fe80::/64 a la interfaz.

Isi establece "auto", "dhcp", "manual", "ignore" o "shared", NetworkManager asigna, además de la dirección global, una dirección IPv6 de enlace local a la interfaz. Esto cumple con RFC 4291.

el número de bytes utilizado como 'déficit' en el algoritmo de colas justas. Por defecto se establece en 1514 bytes, que corresponde a la MTU de Ethernet más la longitud de la cabecera de hardware de 14 bytes.

Cuando es TRUE, fuerza la negociación automática de velocidad y modo dúplex. 802-3-ethernet.cloned-mac-address

Alias: cloned-mac

Si se especifica, solicita que el dispositivo utilice esta dirección MAC en su lugar. Esto se conoce como clonación o suplantación de MAC.

Además de especificar explícitamente una dirección MAC, se admiten los valores especiales "preserve", "permanent", "random" y "stable". "preserve" significa no tocar la dirección MAC al activarla. "permanent" significa utilizar la dirección de hardware permanente si el dispositivo tiene una (de lo contrario, se trata como "preserve"). "random" crea una dirección MAC aleatoria en cada conexión. "stable" crea una dirección MAC hasheada basada en connection.stable-id y una clave dependiente de la máquina.

Si no se especifica, el valor puede ser sobrescrito por valores predeterminados globales, consulte el manual de NetworkManager.conf. Si aún no se especifica, el valor predeterminado es "preserve" (versiones anteriores de NetworkManager pueden usar un valor predeterminado diferente).

En D-Bus, este campo se expresa como "assigned-mac-address" o el obsoleto "cloned-mac-address".

Formato: dirección MAC

Valores especiales: preserve, permanent, random, stable

802-3-ethernet.duplex

Cuando se establece un valor, "half" o "full", configura el dispositivo para usar el modo dúplex especificado. Si "auto-negotiate" es "yes", el modo dúplex especificado será el único anunciado durante la negociación del enlace: esto solo funciona para las especificaciones BASE-T 802.3 y es útil para forzar modos gigabit, ya que en estos casos la negociación del enlace es obligatoria. Si el valor no está establecido (el valor predeterminado), la configuración del enlace se omitirá (si "auto-negotiate" es "no", el valor predeterminado) o se negociará automáticamente (si "auto-negotiate" es "yes") y el dispositivo local anunciará todos los modos dúplex compatibles. Debe establecerse junto con la propiedad "speed" si se especifica. Antes de especificar un modo dúplex, asegúrese de que su dispositivo lo admita.

Formato: cadena

Valores válidos: half, full

802-3-ethernet.generate-mac-address-mask

Con la configuración "cloned-mac-address" en "random" o "stable", por defecto todos los bits de la dirección MAC se codifican y se crea una dirección MAC asignada localmente y de unidifusión. Esta propiedad permite especificar que ciertos bits son fijos. Tenga en cuenta que el bit menos significativo de la primera dirección MAC siempre se establecerá para crear una dirección MAC de unidifusión.

Si la propiedad es NULL, es elegible para ser sobrescrita por una configuración de conexión predeterminada. Si el valor sigue siendo NULL o una cadena vacía, el valor predeterminado es crear una dirección MAC asignada localmente y de unidifusión.

Si el valor contiene una dirección MAC, esta dirección se utiliza como máscara. Los bits establecidos de la máscara se rellenarán con la dirección MAC actual del dispositivo, mientras que los bits no establecidos están sujetos a aleatorización. Establecer "FE:FF:FF:00:00:00" significa preservar el OUI de la dirección MAC actual y solo aleatorizar los 3 bytes inferiores utilizando el algoritmo "random" o "stable".

Si el valor contiene una dirección MAC adicional después de la máscara, esta dirección se utiliza en lugar de la dirección MAC actual para rellenar los bits que no se aleatorizarán. Por ejemplo, un valor de "FE:FF:FF:00:00:00 68:F7:28:00:00:00" establecerá el OUI de la dirección MAC en 68:F7:28, mientras que los bits inferiores se aleatorizarán. Un valor de "02:00:00:00:00:00 00:00:00:00:00:00" creará una dirección MAC grabada completamente codificada.

Si el valor contiene más de una dirección MAC adicional, se elige una de ellas aleatoriamente. Por ejemplo, "02:00:00:00:00:00 00:00:00:00:00:00 02:00:00:00:00:00" creará una dirección MAC completamente codificada, administrada local o globalmente de forma aleatoria.

802-11-wireless.generate-mac-address-mask

With "cloned-mac-address" setting "random" or "stable", by default all bits of the MAC address are scrambled and a locally-administered, unicast MAC address is created. This property allows one to specify that certain bits are fixed. Note that the least significant bit of the first MAC address will always be unset to create a unicast MAC address.

If the property is NULL, it is eligible to be overwritten by a default connection setting. If the value is still NULL or an empty string, the default is to create a locally-administered, unicast MAC address.

If the value contains one MAC address, this address is used as mask. The set bits of the mask are to be filled with the current MAC address of the device, while the unset bits are subject to randomization. Setting "FE:FF:FF:00:00:00" means to preserve the OUI of the current MAC address and only randomize the lower 3 bytes using the "random" or "stable" algorithm.

If the value contains one additional MAC address after the mask, this address is used instead of the current MAC address to fill the bits that shall not be randomized. For example, a value of "FE:FF:FF:00:00:00 68:F7:28:00:00:00" will set the OUI of the MAC address to 68:F7:28, while the lower bits are randomized. A value of "02:00:00:00:00:00 00:00:00:00:00:00" will create a fully scrambled globally-administered, burned-in MAC address.

If the value contains more than one additional MAC addresses, one of them is chosen randomly. For example, "02:00:00:00:00:00 00:00:00:00:00:00 02:00:00:00:00:00" will create a fully scrambled MAC address, randomly locally or globally administered.

Tipos de bandera de secreto:

Cada contraseña o propiedad secreta en una configuración tiene una propiedad de flags asociada que describe cómo manejar ese secreto. La propiedad flags es un campo de bits que contiene cero o más de los siguientes valores combinados lógicamente mediante OR.

•0x0 (ninguno) - el sistema es responsable de proporcionar y almacenar este secreto. Esto puede ser necesario para que los secretos estén disponibles antes de que el usuario inicie sesión. También significa comúnmente que el secreto se almacenará en texto plano en el disco, accesible solo para root. Por ejemplo, a través del plugin de configuración de archivo de claves como se describe en la sección "PLUGINS" de NetworkManager.conf(5).
•0x1 (propiedad-del-agente) - un agente de secreto de sesión de usuario es responsable de proporcionar y almacenar este secreto; cuando sea necesario, se pedirá a los agentes que lo proporcionen.
•0x2 (no-guardado) - este secreto no debe guardarse sino que debe solicitarse al usuario cada vez que sea necesario. Esta bandera debe utilizarse para secretos de clave de un solo uso, códigos PIN de tokens de hardware, o si el usuario simplemente no desea guardar el secreto.
•0x4 (no-requerido) - en algunas situaciones no se puede determinar automáticamente si un secreto es requerido o no. Esta bandera sugiere que el secreto no es requerido y no debe solicitarse al usuario.
