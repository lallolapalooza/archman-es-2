NOMBRE

nmbug - gestiona errores de notmuch con git

SINOPSIS

notmuch git [-h] [-N] [-C repo] [-p prefijo] [-v] [-l nivel de registro] subcomando

nmbug [-h] [-C repo] [-p prefijo] [-v] [-l nivel de registro] subcomando

DESCRIPCIÓN

Gestiona etiquetas de notmuch con Git.

OPCIONES

Opciones admitidas para notmuch git:

-h, --help
muestra el mensaje de ayuda y sale
-N, --nmbug
Establece los valores predeterminados para --tag-prefix y --git-dir adecuados para el rastreador de errores de notmuch
-C <repo>, --git-dir <repo>
Opera en el repositorio git repo. Consulta UBICACIÓN DEL REPOSITORIO para ver los valores predeterminados.
-p <prefijo>, --tag-prefix <prefijo>
Opera solo en etiquetas con el prefijo prefijo. Consulta VALOR DEL PREFIJO para ver los valores predeterminados.
-v, --version
muestra el número de versión de notmuch-git y sale
-l <nivel>, --log-level <nivel>
Verbosidad del registro, una de: crítico, error, advertencia, info, depuración. El valor predeterminado es advertencia.

SUBCOMANDOS

Para obtener ayuda sobre un subcomando particular, ejecuta: 'notmuch-git ... <comando> --help'.

archivo [tree-ish] [arg ...]

Exporta un archivo tar de un conjunto de etiquetas confirmadas usando 'git archive'. Consulta CONTENIDOS DEL REPOSITORIO para obtener detalles sobre los contenidos del archivo.

tree-ish

El árbol o commit para el que se producirá un archivo. El valor predeterminado es 'HEAD'.

arg
checkout [-f|--force]

Actualiza la base de datos de notmuch desde git.

Esto es principalmente útil para descartar tus cambios en notmuch en relación con git.

[-f|--force]

Anula las comprobaciones que impiden modificar etiquetas para grandes fracciones de mensajes en la base de datos. Consulta también git.safe_fraction.

clone <repositorio>

Crea un repositorio local de notmuch git a partir de una fuente remota.

Esto envuelve 'git clone', añadiendo algunas opciones para evitar la creación de un árbol de trabajo mientras se conservan las ramas de seguimiento remoto y los upstream.

repositorio
commit [-f|--force] [mensaje]

Confirma etiquetas que coinciden con prefijos de la base de datos de notmuch en git.

mensaje

Texto opcional para el mensaje de confirmación.

-f|--force

Anula las comprobaciones que impiden modificar etiquetas para grandes fracciones de mensajes en la base de datos. Consulta también git.safe_fraction.

fetch [remoto]

Descarga cambios del repositorio remoto.

remoto

Anula la configuración predeterminada en branch.<nombre>.remote para descargar desde un repositorio remoto particular (por ejemplo, origin).

help

Muestra ayuda breve para un comando de notmuch git.

init [--format-version=N]

Crea un repositorio vacío de notmuch git.

Esto envuelve 'git init' con algunos pasos adicionales para soportar comandos de estado y confirmación posteriores.

--format-version=N

Crea un repositorio en la versión de formato N. Por defecto, notmuch-git utiliza la versión más alta compatible, que es la mejor opción para la mayoría de los casos de uso.

log [arg ...]

Un envoltorio para 'git log'.

arg

Los argumentos adicionales se pasarán a 'git log'.

Después de ejecutar notmuch git fetch, puedes inspeccionar los cambios con

$ notmuch git log HEAD..@{upstream}
merge [referencia]

Fusiona los cambios de 'referencia' en HEAD y carga el resultado en notmuch.

referencia

Referencia, generalmente otras cabezas de rama, a fusionar en nuestra rama. El valor predeterminado es @{upstream}.

Descarga (fusiona) cambios del repositorio remoto a notmuch.

pull es equivalente a fetch seguido de merge. Usamos el repositorio configurado en git para tu rama actual (branch.<nombre>.repository, probablemente origin, y branch.<nombre>.merge, probablemente master o main).

NOMBRE

nmbug - manage notmuch tags as a git repository

SINOPSIS

nmbug command [options] [args...]

DESCRIPCIÓN

The nmbug utility allows you to manage your notmuch tags as a git repository. It maps your notmuch tags to git branches. This is useful for keeping track of your email conversation history and for sharing it with others.

The following commands are available:

clone [repository]

Clone a notmuch git repository. This command is equivalent to running git clone. It also initializes the notmuch database from the cloned repository.

repository
fetch [repository] [refspec]

Fetch changes from a remote repository and update the notmuch database. This command is equivalent to running git fetch. It then updates the notmuch database to reflect the fetched changes.

repository
refspec
init [--nmbug] [--git-dir=directory] [--tag-prefix=prefix]

Initialize a new notmuch git repository. This command creates a new git repository and initializes the notmuch database.

--nmbug

Use the nmbug directory structure for the repository. This is the default if the command is invoked as nmbug.

--git-dir=directory

Set the directory for the git repository. Defaults to $XDG_DATA_HOME/notmuch/$NOTMUCH_PROFILE/git or $HOME/.nmbug/git.

--tag-prefix=prefix

Set the prefix for tags. Defaults to $NOTMUCH_GIT_PREFIX or "notmuch::" (if --nmbug is used).

pull [repository] [refspec]

Fetch from and integrate with another repository or a local branch. This command is equivalent to running git pull. It fetches changes from the specified repository and then merges them into the current branch. The notmuch database is updated accordingly.

repository
refspec
push [repository] [refspec]

Push the local notmuch git git state to a remote repository.

repository
refspec
status

Show pending updates in notmuch or git repo.

Prints lines of the form

ng Message-Id tag

where n is a single character representing notmuch database status

A

Tag is present in notmuch database, but not committed to git (equivalently, tag has been deleted in git repo, e.g. by a pull, but not restored to notmuch database).

D

Tag is present in git repo, but not restored to notmuch database (equivalently, tag has been deleted in notmuch).

U

Message is unknown (missing from local notmuch database).

The second character g (if present) represents a difference between local and upstream branches. Typically notmuch git fetch needs to be run to update this.

a

Tag is present in upstream, but not in the local git branch.

d

Tag is present in local git branch, but not upstream.

CONTENIDO DEL REPOSITORIO

Los tags se almacenan en el repositorio git (y se exportan) como un conjunto de archivos vacíos. Estos archivos vacíos están contenidos en un directorio con el nombre del id del mensaje.

En lo que sigue, encode() representa una codificación segura para el sistema de archivos POSIX. La codificación preserva los caracteres alfanuméricos y los caracteres +-_@=.,:. Todos los demás octetos se reemplazan con % seguido de un número hexadecimal de dos dígitos.

Actualmente, notmuch-git puede leer cualquier versión de formato, pero solo puede crear (a través de init) repositorios de versión 1.

Versión 0

Este es el formato heredado creado por la herramienta nmbug antes del lanzamiento 0.37. Para un mensaje con Message-Id id, para cada tag tag, hay un archivo vacío con la ruta

tags/ encode(id) / encode(tag)

Versión 1

En el formato versión 1 y posteriores, la versión del formato se encuentra en un archivo de nivel superior llamado FORMAT.

Para un mensaje con Message-Id id, para cada tag tag, hay un archivo vacío con la ruta

tags/ hash1(id) / hash2(id) encode(id) / encode(tag)

Las funciones hash representan cada byte del digest hexadecimal de blake2b.

En comparación con la versión 0, esto reduce el número de subdirectorios dentro de cada directorio.

UBICACIÓN DEL REPOSITORIO

notmuch-git utiliza el primero de los siguientes con un valor no vacío para localizar el repositorio git.

  • Opción --git-dir.
  • Variable de entorno NOTMUCH_GIT_DIR.
  • Elemento de configuración git.path
  • Si se invoca como nmbug o con la opción --nmbug, $HOME/.nmbug; de lo contrario, $XDG_DATA_HOME/notmuch/$NOTMUCH_PROFILE/git.

VALOR DEL PREFIJO

notmuch-git utiliza el primero de los siguientes con un valor no nulo para definir el prefijo del tag.

  • Opción --tag-prefix.
  • Variable de entorno NOTMUCH_GIT_PREFIX.
  • Elemento de configuración git.tag_prefix.
  • Si se invoca como nmbug o con la opción --nmbug, notmuch::, de lo contrario, la cadena vacía.

ENTORNO

La variable NOTMUCH_PROFILE influye en la UBICACIÓN DEL REPOSITORIO. Si no está establecida, se asume 'default'.

NOTMUCH_GIT_DIR
Ubicación predeterminada del repositorio git. Anulado por --git-dir.
NOTMUCH_GIT_PREFIX
Prefijo de tag (filtro) predeterminado. Anulado por --tag-prefix.
