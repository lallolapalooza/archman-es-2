NOMBRE

nmcli-examples - ejemplos de uso de nmcli

SINOPSIS

nmcli [OPCIONES...]

DESCRIPCIÓN

nmcli es un cliente de línea de comandos para NetworkManager. Permite controlar NetworkManager e informar su estado. Para más información, consulte la página del manual nmcli(1).

El propósito de esta página del manual es proporcionarle varios ejemplos y escenarios de uso de nmcli.

Ejemplo 6. Cambiar el registro de NetworkManager

$ nmcli g log level DEBUG domains CORE,ETHER,IP
$ nmcli g log level INFO domains DEFAULT

El primer comando hace que NetworkManager registre en nivel DEBUG, y solo para los dominios CORE, ETHER e IP. El segundo comando restaura el estado de registro predeterminado. Consulte la página del manual NetworkManager.conf(5) para ver los niveles y dominios de registro disponibles.

Ejemplo 7. Activar un perfil de conexión VPN que requiere entrada interactiva de contraseña

$ nmcli --ask con up my-vpn-con

Este comando activa un perfil de conexión VPN permitiendo a nmcli interactuar con el usuario ('--ask'): esto permitirá a nmcli solicitar la contraseña de la VPN en la línea de comandos cuando los password-flags estén configurados en '0x02' ('siempre preguntar', ver nm-settings-nmcli(5)). Esto es particularmente útil para VPN basadas en OTP, ya que el usuario necesita que se le solicite la contraseña cada vez que se activa la conexión.

Ejemplo 8. Añadir un controlador de bonding y dos perfiles de conexión de puerto

$ nmcli con add type bond ifname mybond0 mode active-backup
$ nmcli con add type ethernet ifname eth1 controller mybond0
$ nmcli con add type ethernet ifname eth2 controller mybond0

Este ejemplo demuestra la adición de una conexión de controlador bond y dos puertos. El primer comando añade una conexión de controlador bond, nombrando la interfaz bonding como mybond0 y usando el modo active-backup. Los dos comandos siguientes añaden conexiones de puerto, ambas adjuntas como puerto a mybond0. El primer puerto se asociará a la interfaz eth1, el segundo a eth2.

Ejemplo 9. Añadir un controlador team y dos perfiles de conexión de puerto

$ nmcli con add type team con-name Team1 ifname Team1 config team1-controller-json.conf
$ nmcli con add type ethernet con-name Team1-port1 ifname em1 controller Team1
$ nmcli con add type ethernet con-name Team1-port2 ifname em2 controller Team1

Este ejemplo demuestra la adición de un perfil de conexión de controlador team y dos puertos. Es muy similar al ejemplo de bonding. El primer comando añade un perfil de controlador team, nombrando la interfaz team y el perfil Team1. La configuración del team para el controlador se lee del archivo team1-controller-json.conf. Más tarde, puede cambiar la configuración con el comando modify (nmcli con modify Team1 team.config team1-controller-another-json.conf). Los dos últimos comandos añaden perfiles de puerto, ambos adjuntos como puerto a Team1. El primer puerto se asociará a la interfaz em1, el segundo a em2. NAME

nmcli-examples — Examples for nmcli

SYNOPSIS

nmcli [ OPTIONS ] OBJECT { COMMAND | help }

OBJECT := { connection | connection | device | general | radio | agent }

DESCRIPTION

This document provides examples of how to use the nmcli command-line tool to manage network connections.

EXAMPLES

Example 3. Create a new Wi-Fi connection profile

$ nmcli connection add type wifi con-name MyWifi ifname wlan0 ssid MyWifi

Example 4. Set Wi-Fi password

$ nmcli connection modify MyWifi wifi-sec.psk MyPassword

Example 5. Connect to a Wi-Fi network

$ nmcli connection up MyWifi

Example 6. Disconnect from a network

$ nmcli connection down MyWifi

Example 7. Delete a connection profile

$ nmcli connection delete MyWifi

Example 17. Perfiles de conexión Bluetooth

NetworkManager soporta tanto la conexión a dispositivos NAP como DUN como cliente. También soporta compartir la red a través de un servidor NAP.

Para conexiones de cliente NAP, NetworkManager crea automáticamente un perfil en memoria adecuado para los dispositivos emparejados si no hay ninguno disponible. Puede usar ese perfil generado directamente, pero también puede modificarlo y persistirlo, lo que evitará que se recree automáticamente. También puede crear un perfil desde cero. Por ejemplo, lo siguiente usa DHCP y autoconfiguración IPv6 para la configuración de la dirección:

$ nmcli connection add type bluetooth con-name "Perfil para mi dispositivo Bluetooth (NAP)" autoconnect no bluetooth.type panu bluetooth.bdaddr "$BDADDR"

Para conexiones DUN, el usuario necesita configurar los ajustes del módem y, por lo tanto, no se crea ningún perfil automáticamente. Los ajustes del módem dependen de su dispositivo y usted necesita una sección "gsm" o "csma". Por ejemplo,

$ nmcli connection add type bluetooth con-name "Perfil para mi dispositivo Bluetooth (DUN)" autoconnect no bluetooth.type dun bluetooth.bdaddr "$BDADDR" gsm.apn apn.com

Finalmente, puede crear un punto de acceso Bluetooth. BlueZ implementa estos como un dispositivo puente, por lo que dichos perfiles también tienen una sección de puente. Además, probablemente querrá establecer los métodos IP como "compartido", para que los clientes obtengan direccionamiento IP automático. Tenga en cuenta que el método IPv4 "compartido" requiere que dnsmasq esté disponible.

$ nmcli connection add type bluetooth con-name "Mi punto de acceso Bluetooth" autoconnect no ifname btnap0 bluetooth.type nap ipv4.method shared ipv6.method shared

Example 18. Uso sin conexión

$ nmcli --offline con add type ethernet '
  conn.id eth0 \
  conn.interface-name eth0 \
  >/sysroot/etc/NetworkManager/system-connections/eth0.nmconnection

Crea un archivo de conexión en formato keyfile sin usar el servicio NetworkManager. Esto permite el uso de la sintaxis familiar de nmcli en situaciones donde el servicio no se está ejecutando, como durante la instalación del sistema de aprovisionamiento de imágenes y asegura que el archivo resultante tenga el formato correcto.

$ nmcli --offline con modify type ethernet '
  conn.id eth0-ipv6 \
  ipv4.method disabled \
  </sysroot/etc/NetworkManager/system-connections/eth0.nmconnection \
  >/sysroot/etc/NetworkManager/system-connections/eth0-ipv6.nmconnection

Lee y escribe un archivo de conexión sin usar el servicio NetworkManager, modificando algunas propiedades en el proceso.

Esto permite la creación de plantillas de perfiles de conexión utilizando la sintaxis familiar de nmcli en situaciones donde el servicio no se está ejecutando.

Example 19. Punto de control y restauración de dispositivo

$ nmcli dev checkpoint eth0 -- nmcli dev dis eth0
Device 'eth0' successfully disconnected.
Type "Yes" to commit the changes: No
Checkpoint was removed.

En este ejemplo, el dispositivo eth0 se desconectó con el punto de control de eth0 tomado. El usuario no confirmó que el cambio es bueno, por lo que eth0 volvió al estado en que se encontraba cuando se tomó el punto de control.

Si el comando que se está ejecutando interrumpe involuntariamente la conexión remota (como una sesión de ssh(1)) a la propia máquina en la que se está ejecutando, el usuario no podría confirmar el éxito y la conectividad finalmente se restauraría después de un tiempo de espera.

Si, por otro lado, el comando resulta exitoso, el usuario podría simplemente confirmar, haciendo que el punto de control se abandone sin revertir:

$ nmcli dev checkpoint -- ip link del br0
Type "Yes" to commit the changes: Yes
