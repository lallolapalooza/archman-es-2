NOMBRE

nm-settings-keyfile - Descripción del plugin de configuración keyfile

DESCRIPCIÓN

NetworkManager se basa en el concepto de perfiles de conexión que contienen la configuración de red (ver nm-settings-nmcli(5) para más detalles). Los perfiles pueden almacenarse en varios formatos. NetworkManager utiliza plugins para leer y escribir los datos. Los plugins se pueden configurar en NetworkManager.conf(5).

El plugin keyfile es el plugin genérico que soporta todos los tipos de conexión y capacidades que NetworkManager tiene. Los archivos están en un formato tipo .ini y se encuentran en /etc/NetworkManager/system-connections/, /usr/lib/NetworkManager/system-connections/ y /run/NetworkManager/system-connections/. Este plugin siempre está habilitado y se usará automáticamente para almacenar cualquier conexión que no sea compatible con ningún otro plugin activo. Por seguridad, ignorará los archivos que sean legibles o escribibles por cualquier usuario que no sea 'root', ya que las claves privadas y las contraseñas pueden almacenarse en texto plano dentro del archivo.

FORMATO DEL ARCHIVO

El formato de configuración keyfile es un formato simple tipo .ini. Consiste en secciones (grupos) de pares clave-valor. Se puede encontrar más información sobre el formato genérico de archivos clave en formato de archivo clave de GLib[1] (Las líneas que comienzan con '#' son comentarios, las listas se separan con ';', etc.).

Cada sección corresponde a un nombre de configuración según se describe en la especificación de configuración (nm-settings-nmcli(5)). Cada par clave/valor en una sección es una de las propiedades de la especificación.

La mayoría de las propiedades se escriben en el mismo formato que la especificación en el keyfile. Sin embargo, algunos valores son inconvenientes para las personas de usar, por lo que se almacenan en el keyfile de maneras más legibles. Estas propiedades que difieren de la especificación se describen a continuación. Un ejemplo podrían ser las direcciones IP que no se escriben como arrays de enteros, sino más razonablemente como "1.2.3.4/12 1.2.3.254". Además, algunas listas de valores complejos (direcciones, rutas, reglas de enrutamiento), en lugar de usar una lista separada por punto y coma, usan un par clave-valor por elemento de lista, con la clave siendo el singular del nombre de la propiedad seguido del índice numérico (es decir, address1, address2, ...).

Los usuarios pueden crear o modificar los archivos de configuración keyfile manualmente, incluso si esa no es la forma recomendada de gestionar los perfiles. Sin embargo, si deciden hacerlo, deben informar a NetworkManager sobre sus cambios (por ejemplo, a través de nmcli con (re)load).

Ejemplos de configuración de keyfile.

Una configuración de ejemplo para una red ethernet:
[connection]
id=Main eth0
uuid=27afa607-ee36-43f0-b8c3-9d245cdc4bb3
type=802-3-ethernet
autoconnect=true
[ipv4]
method=auto
[802-3-ethernet]
mac-address=00:23:5a:47:1f:71

Una configuración de ejemplo para WPA-EAP (PEAP con MSCHAPv2) y contraseña que siempre se pregunta:
[connection]
id=CompanyWIFI
uuid=cdac6154-a33b-4b15-9904-666772cfa5ee
type=wifi
autoconnect=false
[wifi]
ssid=CorpWLAN
mode=infrastructure
security=802-11-wireless-security
[wifi-security]
key-mgmt=wpa-eap
[ipv4]
method=auto
[ipv6]
method=auto
[802-1x]
eap=peap;
identity=joe
ca-cert=/home/joe/.cert/corp.crt
phase1-peapver=1
phase2-auth=mschapv2
password-flags=2

Una configuración de ejemplo para openvpn:
[connection]
id=RedHat-openvpn
uuid=7f9b3356-b210-4c0e-8123-bd116c9c280f
type=vpn
timestamp=1385401165
[vpn]
service-type=org.freedesktop.NetworkManager.openvpn
connection-type=password
password-flags=3
remote=ovpn.my-company.com
cipher=AES-256-CBC
reneg-seconds=0
port=443
username=joe
ca=/etc/openvpn/ISCA.pem
tls-remote=ovpn.my-company.com
[ipv6]
method=auto
[ipv4]
method=auto
ignore-auto-dns=true
never-default=true

Una configuración de ejemplo para un bridge y un puerto de bridge:
[connection]                                 [connection]
id=MainBridge                                id=br-port-1
uuid=171ae855-a0ab-42b6-bd0c-60f5812eea9d    uuid=d6e8ae98-71f8-4b3d-9d2d-2e26048fe794
interface-name=MainBridge                    interface-name=em1
type=bridge                                  type=ethernet
                                             controller=MainBridge
[bridge]                                     port-type=bridge
interface-name=MainBridge

Una configuración de ejemplo para una VLAN:
[connection]
id=VLAN for building 4A
uuid=8ce1c9e0-ce7a-4d2c-aa28-077dda09dd7e
interface-name=VLAN-4A
type=vlan
[vlan]
interface-name=VLAN-4A
parent=eth0
id=4

DETALLES

Las variables del plugin keyfile para la mayoría de las propiedades de NetworkManager tienen un mapeo uno a uno. Esto significa que una propiedad de NetworkManager se almacena en el keyfile como una variable del mismo nombre y en el mismo formato. Hay varias excepciones a esta regla, principalmente para hacer que la sintaxis de keyfile sea más fácil para los humanos. Las excepciones manejadas especialmente por el plugin keyfile se enumeran a continuación. Consulte nm-settings-nmcli(5) para todas las configuraciones y propiedades disponibles y su descripción.

Alias de nombres. Algunos de los nombres de configuración de NetworkManager son algo difíciles de escribir o recordar. Por lo tanto, keyfile introduce alias que se pueden usar en lugar de los nombres.

nombre de configuración alias de keyfile
802-3-ethernet = ethernet
802-11-wireless = wifi
802-11-wireless-security = wifi-security

Marcas de secreto

Cada propiedad secreta en una configuración de NetworkManager tiene una propiedad asociada de
flags que describe cómo manejar ese secreto. En el plugin keyfile, el valor de la variable -flags es un número decimal (0 - 7) definido como la suma de los siguientes valores:

•0 - (propiedad de NM) - el sistema es responsable de proporcionar y almacenar este secreto.
•1 - (propiedad del agente) - un agente de sesión de usuario es responsable de proporcionar y almacenar este secreto; cuando sea necesario, se solicitará a los agentes que lo proporcionen.
•2 - (no guardado) - este secreto no debe guardarse, sino solicitarse al usuario cada vez que sea necesario.
•4 - (no requerido) - en algunas situaciones, no se puede determinar automáticamente si un secreto es necesario o no. Esta marca indica que el secreto no es necesario y no se debe solicitar al usuario.
