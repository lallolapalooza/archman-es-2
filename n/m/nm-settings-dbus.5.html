NOMBRE

nm-settings-dbus - Descripción de la configuración y propiedades de los perfiles de conexión de NetworkManager en la API D-Bus

DESCRIPCIÓN

NetworkManager se basa en el concepto de perfiles de conexión, a veces denominados solo conexiones. Estos perfiles de conexión contienen la configuración de red. Cuando NetworkManager activa un perfil de conexión en un dispositivo de red, la configuración se aplicará y se establecerá una conexión de red activa. Los usuarios son libres de crear tantos perfiles de conexión como consideren oportuno. Por lo tanto, son flexibles para tener varias configuraciones de red para diferentes necesidades de red. Los perfiles de conexión son manejados por NetworkManager a través del servicio de configuración y se exportan en D-Bus (objetos /org/freedesktop/NetworkManager/Settings/<num>). Los objetos conceptuales se pueden describir de la siguiente manera:

Conexión (perfil)

Un grupo específico, encapsulado e independiente de configuraciones que describe toda la configuración necesaria para conectarse a una red específica. Se hace referencia a ella mediante un identificador único llamado UUID. Una conexión está vinculada a un tipo de dispositivo específico, pero no necesariamente a un dispositivo de hardware específico. Está compuesta por uno o más objetos de Configuración.

Configuración

Un grupo de pares clave/valor relacionados que describen una parte específica de una Conexión (perfil). Las claves de configuración y los valores permitidos se describen en las tablas a continuación. Las claves también se conocen como propiedades. Los desarrolladores pueden encontrar los objetos de configuración y sus propiedades en las fuentes de libnm-core. Busque las funciones *_class_init cerca del final de cada archivo de origen de configuración.

Las configuraciones y propiedades que se muestran en las tablas a continuación enumeran todas las opciones de configuración de conexión disponibles. Sin embargo, tenga en cuenta que no todas las configuraciones son aplicables a todos los tipos de conexión. NetworkManager proporciona una herramienta de línea de comandos nmcli que permite la configuración directa de las configuraciones y propiedades de acuerdo con el tipo de perfil de conexión. El editor de conexiones de nmcli también tiene un comando incorporado describe que puede mostrar la descripción de configuraciones y propiedades particulares de esta página.

auth-retries int32 -1 El número de reintentos de autenticación. Cero significa intentar indefinidamente; -1 significa usar un valor predeterminado global. Si el valor predeterminado global no está establecido, los reintentos de autenticación se realizan 3 veces antes de fallar la conexión. Actualmente, esto solo se aplica a la autenticación 802-1x.
autoconnect boolean TRUE Si la conexión debe conectarse automáticamente o no cuando los recursos para la conexión estén disponibles. TRUE para activar automáticamente la conexión, FALSE para requerir intervención manual para activar la conexión. La autoconexión ocurre cuando las circunstancias son adecuadas. Eso significa, por ejemplo, que el dispositivo está actualmente gestionado y no activo. Por lo tanto, la autoconexión nunca reemplaza ni compite con un perfil ya activo. Tenga en cuenta que la autoconexión no está implementada para perfiles VPN. Consulte "secondaries" como alternativa para conectar automáticamente perfiles VPN. Si varios perfiles están listos para autoconectarse en el mismo dispositivo, se elige el que tiene una "connection.autoconnect-priority" mejor. Si las prioridades son iguales, se activa el perfil conectado más recientemente. Si los perfiles no se conectaron anteriormente o su "connection.timestamp" es idéntico, la elección no está definida. Dependiendo de "connection.multi-connect", un perfil puede (auto)conectarse solo una vez a la vez o varias veces.
autoconnect-ports int32 -1 Si los puertos de esta conexión deben activarse automáticamente o no cuando NetworkManager active esta conexión. Esto solo tiene un efecto real para las conexiones de controlador. Las propiedades "autoconnect", "autoconnect-priority" y "autoconnect-retries" no están relacionadas con esta configuración. Los valores permitidos son: 0: dejar las conexiones de puerto sin cambios, 1: activar todas las conexiones de puerto con esta conexión, -1: predeterminado. Si se establece -1 (predeterminado), se lee el valor global de connection.autoconnect-ports para determinar el valor real. Si también es predeterminado, esto se reduce a 0.
autoconnect-priority int32 0 La prioridad de autoconexión en el rango de -999 a 999. Si la conexión está configurada para autoconectarse, se preferirán las conexiones con mayor prioridad. Un número mayor significa mayor prioridad. El valor predeterminado es 0. Tenga en cuenta que esta propiedad solo importa si hay más de un perfil candidato para seleccionar para la autoconexión. En caso de prioridad igual, se elige el perfil utilizado más recientemente.
autoconnect-retries int32 -1 El número de veces que se debe intentar activar una conexión al autoactivarla antes de rendirse. Cero significa para siempre, -1 significa el valor predeterminado global (4 veces si no se reemplaza). Establecer esto en 1 significa intentar la activación solo una vez antes de bloquear la autoconexión. Tenga en cuenta que después de un tiempo de espera, NetworkManager intentará autoconectarse nuevamente.

Esto solo tiene un efecto real para las conexiones de controlador. Las propiedades "autoconnect", "autoconnect-priority" y "autoconnect-retries" no están relacionadas con esta configuración. Los valores permitidos son: 0: dejar las conexiones de puerto sin cambios, 1: activar todas las conexiones de puerto con esta conexión, -1: predeterminado. Si se establece -1 (predeterminado), se lee el valor global de connection.autoconnect-slaves para determinar el valor real. Si también es predeterminado, esto se reduce a 0. Obsoleto en 1.46. Use "autoconnect-ports" en su lugar, esto es solo un alias.
controller string   Nombre de la interfaz del dispositivo controlador o UUID de la conexión controladora.
dns-over-tls int32 -1 Si DNSOverTls (dns-over-tls) está habilitado para la conexión. DNSOverTls es una tecnología que utiliza TLS para cifrar el tráfico de DNS. Los valores permitidos son: "yes" (2) usar DNSOverTls y deshabilitar la recuperación, "opportunistic" (1) usar DNSOverTls pero permitir la recuperación a resolución no cifrada, "no" (0) nunca usar DNSOverTls. Si no se especifica "default", depende del plugin utilizado. Systemd-resolved utiliza la configuración global. Esta característica requiere un plugin que admita DNSOverTls. De lo contrario, la configuración no tiene efecto. Un plugin de este tipo es dns-systemd-resolved.
down-on-poweroff int32 -1 Si la conexión se cerrará antes de que el sistema se apague. El valor predeterminado es -1 (predeterminado). Cuando se especifica el valor predeterminado, se busca el valor global de la configuración de NetworkManager; si no está establecido, se considera 0 (no).

Si no está establecido, la conexión se puede adjuntar a cualquier interfaz del tipo apropiado (sujeto a las restricciones impuestas por otras configuraciones). Para dispositivos de software, esto especifica el nombre del dispositivo creado. net.dns-priority int32 0 Prioridad de los servidores DNS. La prioridad relativa de los servidores DNS especificados por esta configuración. Un valor numérico más bajo es mejor (mayor prioridad). Para priorizar un servidor determinado sobre otro dentro de la misma conexión, simplemente especifíquelos en el orden deseado. Tenga en cuenta que comúnmente el resolvedor intenta los servidores de nombres en /etc/resolv.conf en el orden en que aparecen, y procede con el siguiente servidor en la lista en caso de fallo. Vea, por ejemplo, la opción "rotate" de la configuración de opciones de DNS. Si hay alguna prioridad de DNS negativa, entonces solo se considerarán los servidores de nombres de los dispositivos con esa prioridad más baja. Al utilizar un resolvedor de DNS que admita reenvío condicional o DNS dividido (con la configuración dns=dnsmasq o dns=systemd-resolved), cada conexión se utiliza para consultar dominios en su lista de búsqueda. Los dominios de búsqueda determinan a qué servidores de nombres preguntar, y la prioridad de DNS se utiliza para priorizar los servidores de nombres según el dominio. Las consultas de dominios que no están presentes en ninguna lista de búsqueda se enrutan a través de conexiones que tienen el dominio comodín especial '~.', que se agrega automáticamente a las conexiones con la ruta predeterminada (o se puede agregar manualmente). Cuando varias conexiones especifican el mismo dominio, gana el que tenga la mejor prioridad (el valor numérico más bajo). Si se configura un subdominio en otra interfaz, se aceptará independientemente de la prioridad, a menos que el dominio padre en la otra interfaz tenga una prioridad negativa, lo que hace que el subdominio sea sombreado. Con DNS dividido, se pueden evitar fugas de DNS no deseadas configurando adecuadamente las prioridades de DNS y los dominios de búsqueda, de modo que solo se configuren los servidores de nombres de la interfaz deseada.

he El `match` se evalúa como verdadero si al menos uno de los elementos opcionales coincide (OR lógico). Si hay elementos obligatorios, todos deben coincidir (AND lógico). Por defecto, un elemento es opcional. Esto significa que un elemento `"foo"` se comporta igual que `|foo`. Secret flag types:

Each password or secret property in a setting has an associated flags property that describes how to handle that secret. The flags property is a bitfield that contains zero or more of the following values logically OR-ed together.

•0x0 (none) - the system is responsible for providing and storing this secret. This may be required so that secrets are already available before the user logs in. It also commonly means that the secret will be stored in plain text on disk, accessible to root only. For example via the keyfile settings plugin as described in the "PLUGINS" section in NetworkManager.conf(5).
•0x1 (agent-owned) - a user-session secret agent is responsible for providing and storing this secret; when it is required, agents will be asked to provide it.
•0x2 (not-saved) - this secret should not be saved but should be requested from the user each time it is required. This flag should be used for One-Time-Pad secrets, PIN codes from hardware tokens, or if the user simply does not want to save the secret.
•0x4 (not-required) - in some situations it cannot be automatically determined that a secret is required or not. This flag hints that the secret is not required and should not be requested from the user.
