NOMBRE

nm-initrd-generator - generador de configuración temprana de NetworkManager al arrancar

SINOPSIS

nm-initrd-generator [OPCIONES...] -- [CMDLINE...]

DESCRIPCIÓN

nm-initrd-generator escanea la línea de comandos en busca de opciones relevantes para la configuración de red y crea archivos de configuración para una instancia temprana de NetworkManager ejecutada desde el disco RAM inicial durante el arranque temprano.

OPCIONES

-c | --connections-dir ruta

Directorio de salida de conexiones.

-p | --persistent-connections-dir ruta

Directorio de conexiones persistentes. Si existe, rd.neednet no generará una conexión predeterminada en ausencia de otras opciones.

-i | --initrd-data-dir ruta

Directorio de salida para datos del initrd (por ejemplo, nombre de host).

-d | --sysfs-dir ruta

El punto de montaje de sysfs.

-r | --run-config-dir ruta

Directorio de salida para archivos de configuración.

-s | --stdout

Volcar conexiones a la salida estándar. Útil para depuración.

CMDLINE

Las opciones que aparecen en la línea de comandos del kernel. Se reconocen las siguientes opciones:
ip
rd.route
bridge
bond
team
vlan
ib.pkey
bootdev
nameserver
net.ifnames
rd.peerdns
rd.iscsi.ibft
rd.nvmf.nonbft
rd.bootif
rd.neednet
rd.ethtool
rd.net.dns
rd.net.dns-backend
rd.net.dns-resolve-mode
rd.net.timeout.dhcp
rd.net.dhcp.client-id
rd.net.dhcp.retry
rd.net.dhcp.vendor-class
rd.net.dhcp.dscp
rd.net.timeout.carrier
rd.znet
rd.znet_ifname
BOOTIF
Consulte el manual de dracut.cmdline(7) para obtener la documentación sobre el formato preciso de los valores admitidos.

DIFERENCIAS CON EL MÓDULO NETWORK-LEGACY DE DRACUT

nm-initrd-generator genera un conjunto de conexiones que luego son configuradas por la instancia de NetworkManager que se ejecuta en el initrd. Existen algunas diferencias de comportamiento en comparación con el módulo network-legacy de dracut:

•Cuando una interfaz se configura con una dirección estática y una puerta de enlace, el módulo network-legacy espera a que la puerta de enlace responda a las solicitudes arping antes de continuar, mientras que NetworkManager no lo hace.
•network-legacy configura las interfaces una por una en el orden en que son anunciadas por udev. Si varias interfaces especifican un nombre de host (desde la línea de comandos o desde DHCP), gana el de la última interfaz activada. Con NetworkManager, los nombres de host de la línea de comandos tienen mayor precedencia que los de DHCP, y gana el último que aparece en la línea de comandos.
•NetworkManager admite el argumento ib.pkey=PADRE.PKEY para configurar una partición Infiniband en el dispositivo padre IPoIB PADRE utilizando la clave de partición especificada PKEY. La clave de partición debe estar en notación hexadecimal sin el prefijo "0x", por ejemplo, "ib.pkey=ib0.8004".
•NetworkManager admite la opción de línea de comandos del kernel rd.ethtool=INTERFACE:AUTONEG:SPEED para configurar los parámetros de configuración de la NIC de ethtool AUTONEG y SPEED. Se debe especificar la INTERFACE que se está configurando, y los otros parámetros son opcionales y pueden dejarse en blanco. Cuando se establece SPEED, el modo dúplex se establece automáticamente en 'full'. INTERFACE acepta valores de cadena, AUTONEG acepta valores booleanos (true y false / on u off / 0 o 1), y SPEED acepta valores enteros positivos.
•NetworkManager admite la opción de línea de comandos del kernel rd.net.dns-backend=VALOR para configurar el modo de procesamiento de DNS. Consulte la descripción de la clave "dns" en el párrafo "sección principal" de NetworkManager.conf(5). Por ejemplo: rd.net.dns-backend=systemd-resolved, rd.net.dns-backend=dnsconfd
•NetworkManager admite la opción de línea de comandos del kernel rd.net.dns=SERVIDOR para configurar un servidor DNS global (no específico de la interfaz). La opción se puede especificar varias veces para añadir más de un servidor. Cada servidor se puede especificar como una IP simple o como una URI según la descripción en el párrafo "secciones globales de dns-domains" de NetworkManager.conf(5). Por ejemplo: rd.net.dns=2001:db8::1, rd.net.dns=dns+tls://192.0.2.0, rd.net.dns=dns+tls://[2001:db8::2]:5353#example.org. Además, admite la configuración de la clave "resolve-mode" en la configuración global de DNS a través de la opción de línea de comandos rd.net.dns-resolve-mode.
•NetworkManager admite la opción de línea de comandos del kernel rd.net.dhcp.dscp={CS0|CS4|CS6} para establecer un valor DSCP (TOS) específico en la cabecera IP de los mensajes DHCP.
•NetworkManager admite la opción de línea de comandos del kernel rd.net.dhcp.client-id=interfaz:id-cliente para establecer un identificador de cliente DHCPv4 específico para la interfaz dada. El id-cliente se puede especificar como una secuencia de bytes en formato hexadecimal separado por guiones, o como el carácter '@' seguido de una cadena no vacía. Al utilizar el segundo formato, NetworkManager antepone un byte cero a la cadena dada, según la sección 9.14 de RFC 2132. Consulte la sección "ipv4.dhcp-client-id" de nm-settings-nmcli(5) para obtener más detalles. Ejemplos: rd.net.dhcp.client-id=eth0:01-52-54-00-45-87-42, rd.net.dhcp.client-id=enp1s0:@example.com.

ESTADO DE SALIDA

nm-initrd-generator sale con estado 0. Ignora las opciones no reconocidas e imprime un mensaje de error si encuentra una opción mal formada.

VER TAMBIÉN

dracut.cmdline(7), NetworkManager(8), nm-settings-nmcli(5).

nm-initrd-generator - Genera el contenido de /etc/dracut.conf.d/network.conf para el módulo de red de dracut

SYNOPSIS

nm-initrd-generator [-b | --bootloader] [-s | --systemd] [-o | --overwrite] [-p | --print] [-d | --debug] [-v | --verbose] [--version] [--help]

DESCRIPTION

nm-initrd-generator es un script auxiliar para el módulo de red de dracut. Genera el archivo /etc/dracut.conf.d/network.conf, que configura el módulo de red de dracut para que use NetworkManager para la configuración de red durante la fase inicial de arranque.

Este script solo debe ejecutarse como parte del proceso de reconstrucción de initramfs de dracut. No intente ejecutarlo manualmente.

El contenido de /etc/dracut.conf.d/network.conf se genera según los ajustes de NetworkManager en el momento de la ejecución. Actualmente, esto incluye la adición de la opción nm_dracut_force_ifnames, que instruye al módulo de red de dracut para que prefiera los nombres de interfaz persistentes (si están disponibles) para evitar cambios inesperados de nombres de interfaz durante el arranque.

OPTIONS

-b, --bootloader
Indica que el script se está ejecutando en el contexto del gestor de arranque (como GRUB, LILO, etc.). Esto afecta a qué configuraciones de red se aplican.
-s, --systemd
Indica que el script se está ejecutando en el contexto de systemd. Esto también afecta a las configuraciones de red aplicadas.
-o, --overwrite
Sobrescribe el archivo /etc/dracut.conf.d/network.conf existente si ya existe. De forma predeterminada, el script no sobrescribe el archivo si ya está presente para evitar cambios no deseados.
-p, --print
Imprime el contenido generado de /etc/dracut.conf.d/network.conf en la salida estándar en lugar de escribirlo en el archivo. Esto es útil para la depuración.
-d, --debug
Habilita la salida de depuración.
-v, --verbose
Aumenta el nivel de detalle de la salida.
--version
Muestra la información de la versión y sale.
--help
Muestra un mensaje de ayuda y sale.

DIFERENCIAS CON EL MÓDULO NETWORK-LEGACY DE DRACUT

El módulo network-legacy de dracut proporciona una funcionalidad de red básica durante el arranque. Sin embargo, no se integra con NetworkManager y puede no manejar configuraciones de red complejas o dinámicas tan bien como el módulo basado en NetworkManager.

nm-initrd-generator, en combinación con el módulo de red de dracut, ofrece una forma más moderna y flexible de configurar la red en el initramfs, aprovechando las capacidades de NetworkManager. Esto incluye el soporte para configuraciones de red más complejas como DHCPv6, enlazado de interfaces y planes de red definidos por el usuario.

ESTADO DE SALIDA

0 si la generación del archivo fue exitosa.

1 si ocurrió un error.

VER TAMBIÉN

dracut(8), NetworkManager(8)
