NM(1P) Manual del Programador POSIX NM(1P)

PROLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

nm — escribe la lista de nombres de un archivo objeto (DESARROLLO)

SINOPSIS

nm [-APv] [-g|-u] [-t formato] archivo...
nm [-APv] [-efox] [-g|-u] [-t formato] archivo...

DESCRIPCION

La utilidad nm mostrará información simbólica que aparece en el archivo objeto, archivo ejecutable o biblioteca de archivos objeto nombrada por archivo. Si no hay información simbólica disponible para un archivo de entrada válido, la utilidad nm informará de ese hecho, pero no lo considerará una condición de error.

La base predeterminada utilizada cuando se escriben valores numéricos no está especificada. En sistemas conformes a XSI, será decimal si la opción -P no se especifica.

OPCIONES

La utilidad nm cumplirá con el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de sintaxis de utilidad.

Se admitirán las siguientes opciones:

-A
Escribe la ruta completa o el nombre de la biblioteca de un objeto en cada línea.
-e
Escribe solo información de símbolos externos (globales) y estáticos.
-f
Produce salida completa. Escribe símbolos redundantes (.text, .data y .bss), normalmente suprimidos.
-g
Escribe solo información de símbolos externos (globales).
-o
Escribe valores numéricos en octal (equivalente a -t o).
-P
Escribe información en un formato de salida portable, como se especifica en la sección STDOUT.
-t formato
Escribe cada valor numérico en el formato especificado. El formato dependerá del único carácter utilizado como argumento de opción formato:
d
decimal (predeterminado si -P no se especifica).
o
octal.
x
hexadecimal (predeterminado si -P se especifica).
-u
Escribe solo símbolos indefinidos.
-v
Ordena la salida por valor en lugar de por nombre de símbolo.
-x
Escribe valores numéricos en hexadecimal (equivalente a -t x).

OPERANDOS

Se admitirá el siguiente operando:

archivo
Una ruta de un archivo objeto, archivo ejecutable o biblioteca de archivos objeto.

ENTRADA ESTÁNDAR

Consulte la sección ARCHIVOS DE ENTRADA.

ARCHIVOS DE ENTRADA

El archivo de entrada será un archivo objeto, una biblioteca de archivos objeto cuyo formato sea el mismo que el producido por la utilidad ar para la vinculación, o un archivo ejecutable. La utilidad nm puede aceptar formatos de biblioteca de objetos adicionales definidos por la implementación para el archivo de entrada.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de nm:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de configuración regional.)
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_COLLATE

Determina la configuración regional para la información de ordenación de caracteres para las secuencias de ordenación de nombres de símbolos y valores de símbolos.
LC_CTYPE
Determina la configuración regional para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en los argumentos).
LC_MESSAGES

Determina la configuración regional que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida estándar de error.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASINCRONOS

Predeterminado.

SALIDA ESTÁNDAR

Si hay información simbólica presente en los archivos de entrada, entonces para cada archivo o para cada miembro de un archivo, la utilidad nm escribirá la siguiente información en la salida estándar. Por defecto, el formato no está especificado, pero la salida se ordenará por nombre de símbolo según la secuencia de ordenación en la configuración regional actual.

*
Nombre de la biblioteca u objeto, si se especifica -A
*
Nombre del símbolo
*
Tipo de símbolo, que será uno de los siguientes caracteres individuales o un tipo definido por la implementación representado por un carácter individual:
A
Símbolo absoluto global.
a
Símbolo absoluto local.
B
Símbolo global de ``bss'' (es decir, espacio de datos no inicializado).
b
Símbolo local de bss.
D
Símbolo de datos global.
d
Símbolo de datos local.
T
Símbolo de texto global.
t
Símbolo de texto local.
U
Símbolo indefinido.
*
Valor del símbolo
*
El tamaño asociado con el símbolo, si corresponde

Esta información puede complementarse con información adicional específica de la implementación.

Si se especifica la opción -P, la información anterior se mostrará utilizando el siguiente formato portable. Las tres versiones difieren según si se especificó -t d, -t o, o -t x, respectivamente:

"%s%s %s %d %d\n", <nombre de biblioteca/objeto>, <nombre>, <tipo>,
    <valor>, <tamaño>
"%s%s %s %o %o\n", <nombre de biblioteca/objeto>, <nombre>, <tipo>,
    <valor>, <tamaño>
"%s%s %s %x %x\n", <nombre de biblioteca/objeto>, <nombre>, <tipo>,
    <valor>, <tamaño>

donde <nombre de biblioteca/objeto> se formateará de la siguiente manera:

*
Si -A no se especifica, <nombre de biblioteca/objeto> será una cadena vacía.
*
Si se especifica -A y el operando archivo correspondiente no nombra

nm(1) — Arch Linux man pages

NAME

nm - list symbols from object files

SYNOPSIS

nm [
-A | -o ] [
-P ] [
-a | -g | -u ] [
-t format ] [
-r ] [
-X{32|64|off} ] [
-l ] [
-h ] [
-p ] [
-C ] [
-d ] [
-j ] [
-k ] [
-S ] [
-T ] [
-v ] [
-x ] [
-s ] [
-L ] [
-D ] [
-R ] [
-U ] [
-X{32|64} ] [
-? ]—
file...

DESCRIPTION

The nm utility displays the symbols for each relocatable object file specified by file. If file specifies more than one file, the output for each file is preceded by a header indicating the file name. If no options are specified, nm writes the symbols defined in each object file, followed by the symbols referenced by each object file.

The output for each symbol consists of the symbol's value, symbol type, and symbol name.

The default output format is implementation-defined.

The -P option produces output in the portable format.

OPTIONS

The nm utility shall conform to the Base Definitions volume of POSIX.1-2017, Section 12.2, Utility Syntax Guidelines.

The following options shall be supported:

-A
Same as -o.
-C
Demangle C++ symbol names.
-d
Same as -g.
-D
Print dynamic symbols.
-g
Display only external (global) symbols.
-h
Do not list symbols in dynamic sections.
-j
Print only the symbol name for each argument.
-k
Print symbols in the specified format.
-l
Print the filename and line number for the symbol in the output.
-L
Search directories specified by -L for shared objects.
-o
Precede each output line with the name of the object file it came from. This is the default if more than one file is specified.
-p
Do not demangle C++ symbol names.
-P
Print the symbol names in a portable format.
-r
Reverse the order of the symbols.
-R
Print the name of the shared library that contains the symbol.
-S
Print the size of the symbol.
-s
Print the symbol information in hexadecimal.
-t format
The format argument shall be a string containing one or more of the characters:
d
Decimal.
o
Octal.
x
Hexadecimal.
i
Address (hexadecimal).
-T
Print the symbol information in decimal.
-u
Display only undefined symbols.
-U
Print only undefined symbols.
-v
Print the symbol version information.
-x
Print the symbol information in hexadecimal.
-X{32|64|off}
Specifies the object file format. 32 for 32-bit objects, 64 for 64-bit objects, off to disable.

OPERANDS

The following operand shall be supported:

file
A path to a relocatable object file or archive.

STDIN

Not used.

INPUT FILES

Object files, typically in the ELF format.

ENVIRONMENT VARIABLES

The environment variables LC_ALL, LC_CTYPE, and LC_MESSAGES affect the execution of nm as described in base(1).

The NLSPATH environment variable affects the location of message catalogs used by nm.

ASYNCHRONOUS EVENTS

Default.

STDOUT

The standard output shall contain the symbols from the input object files.

The format of the output lines is described below.

If -P is specified, the output format shall be:

*
If the corresponding file operand does not name a library:
"%-18s %-10s %s\n", <symbol name>, <symbol type>, <symbol value>
*
If the corresponding file operand names a library, and the symbol is found within that library. In this case, <object file> shall be the name of the file in the library containing the symbol:
"%-18s %-10s %s[%s]\n", <symbol name>, <symbol type>, <symbol value>, <object file>

If -P is not specified, the format is implementation-defined. However, the following conventions shall apply:

*
If -A or -o is specified, each line of output shall be preceded by the name of the file from which it was derived, in the form:
"%s: ", <file>
*
If -A is specified and the corresponding file operand names a library. In this case, <object file> shall name the object file in the library containing the symbol being described:
"%s[%s]: ", <file>, <object file>

If -A is not specified, then if more than one file operand is specified or if only one file operand is specified and it names a library, nm shall write a line identifying the object containing the following symbols before the lines containing those symbols, in the form:

*
If the corresponding file operand does not name a library:
"%s:\n", <file>
*
If the corresponding file operand names a library; in this case, <object file> shall be the name of the file in the library containing the following symbols:
"%s[%s]:\n", <file>, <object file>

If -P is specified, but -t is not, the format shall be as if -t x had been specified.

STDERR

The standard error shall be used only for diagnostic messages.

OUTPUT FILES

None.

EXTENDED DESCRIPTION

None.

EXIT STATUS

The following exit values shall be returned:

 0
Successful completion.
>0
An error occurred.

CONSEQUENCES OF ERRORS

Default.

The following sections are informative.

APPLICATION USAGE

Mechanisms for dynamic linking make this utility less meaningful when applied to an executable file because a dynamically linked executable may omit numerous library routines that would be found in a statically linked executable.

EXAMPLES

None.

RATIONALE

Historical implementations of nm have used different bases for numeric output and supplied different default types of symbols that were reported. The -t format option, similar to that used in od and strings, can be used to specify the numeric base; -g and -u can be used to restrict the amount of output or the types of symbols included in the output.

The compromise of using -t format versus using -d, -o, and other similar options was necessary because of differences in the meaning of -o between implementations. The -o option from BSD has been provided here as -A to avoid confusion with the -o from System V (which has been provided here as -t and as -o on XSI-conformant systems).

The option list was significantly reduced from that provided by historical implementations.

The nm description is a subset of both the System V and BSD nm utilities with no specified default output.

It was recognized that mechanisms for dynamic linking make this utility less meaningful when applied to an executable file (because a dynamically linked executable file may omit numerous library routines that would be found in a statically linked executable file), but the value of nm during software development was judged to outweigh other limitations.

The default output format of nm is not specified because of differences in historical implementations. The -P option was added to allow some type of portable output format. After a comparison of the different formats used in SunOS, BSD, SVR3, and SVR4, it was decided to create one that did not match the current format of any of these four systems. The format devised is easy to parse by humans, easy to parse in shell scripts, and does not need to vary depending on locale (because no English descriptions are included). All of the systems currently have the information available to use this format.

The format given in nm STDOUT uses <space> characters between the fields, which may be any number of <blank> characters required to align the columns. The single-character types were selected to match historical practice, and the requirement that implementation additions also be single characters made parsing the information easier for shell scripts.
