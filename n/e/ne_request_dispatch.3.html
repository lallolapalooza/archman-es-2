ne_request_dispatch(3)

Paquete: neon

Licencias: LGPL-2.0-or-later

NE_REQUEST_CREATE(3) Referencia de la API de neon NE_REQUEST_CREATE(3)

NOMBRE

ne_request_create, ne_request_dispatch, ne_request_destroy - manejo de solicitudes HTTP de bajo nivel

SINOPSIS

#include <ne_request.h>

ne_request *ne_request_create(ne_session *session, const char *method, const char *target);

int ne_request_dispatch(ne_request *req);

void ne_request_destroy(ne_request *req);

DESCRIPCIÓN

El objeto ne_request representa una solicitud HTTP y la respuesta asociada. La función ne_request_create crea un nuevo objeto de solicitud para la session dada. El recurso de destino para la solicitud se identifica mediante el target, parámetro, y el método que se realizará en ese recurso a través del parámetro method.

La cadena target utilizada debe cumplir con la definición de request-target dada en RFC 9112[1]. Normalmente, adoptará la forma de ruta absoluta, que opcionalmente incluye una cadena de consulta.

Para despachar una solicitud y procesar la respuesta, se puede utilizar la función ne_request_dispatch. Una alternativa es utilizar la combinación (más compleja, pero más flexible) de las funciones ne_begin_request, ne_end_request y ne_read_response_block; consulte ne_begin_request. El despacho de una solicitud puede requerir múltiples iteraciones de envío de una solicitud y recepción de respuesta, por ejemplo, si se utiliza autenticación (consulte ne_set_server_auth), o si una conexión persistente expira; esto lo maneja internamente ne_request_dispatch.

Para agregar encabezados adicionales en la solicitud, se pueden utilizar las funciones ne_add_request_header y ne_print_request_header. Para incluir un cuerpo de mensaje con la solicitud, se puede utilizar una de las funciones ne_set_request_body_buffer, ne_set_request_body_fd o ne_set_request_body_provider.

El valor de retorno de ne_request_dispatch indica meramente si la solicitud se envió y la respuesta se leyó correctamente. Para descubrir el resultado de la operación, use ne_get_status, junto con cualquier procesamiento de los encabezados de respuesta y el cuerpo del mensaje.

Una solicitud solo se puede despachar una vez: llamar a ne_request_dispatch más de una vez en un único objeto ne_request produce un comportamiento indefinido. Una vez que todo el procesamiento asociado con el objeto de solicitud se completa, use la función ne_request_destroy para destruir los recursos asociados con él. Cualquier uso posterior del objeto de solicitud produce un comportamiento indefinido.

Los métodos de solicitud se consideran idempotentes[2] por defecto. Para una solicitud que utiliza un método no idempotente como POST, se debe deshabilitar el flag NE_REQFLAG_IDEMPOTENT usando ne_set_request_flag.

VALOR DE RETORNO

La función ne_request_create devuelve un puntero a un objeto de solicitud (y nunca NULL).

La función ne_request_dispatch devuelve cero si la solicitud se despachó correctamente y un código de error distinto de cero en caso contrario, como se describe en la siguiente sección.

CÓDIGOS DE ERROR

Los códigos de error tienen un valor distinto de cero y corresponden a una definición de macro NE_*, como se enumera a continuación. Las versiones futuras de neon pueden introducir definiciones de códigos de error adicionales. Las funciones que devuelven un código de error y tienen un objeto de sesión asociado establecen la cadena de error de la sesión (consulte ne_get_error) a menos que se documente lo contrario.

NE_ERROR

La solicitud falló (consulte la cadena de error de la sesión)

NE_LOOKUP

La búsqueda DNS para el servidor (o servidor proxy) falló.

NE_AUTH

La autenticación falló en el servidor.

NE_PROXYAUTH

La autenticación falló en el servidor proxy.

NE_CONNECT

No se pudo establecer una conexión con el servidor.

NE_TIMEOUT

Ocurrió un tiempo de espera mientras se esperaba la respuesta del servidor.

NE_REDIRECT

Se devolvió una redirección válida. Nota: Solo se devuelve si el manejo de redirección está registrado para la sesión usando ne_redirect_register.

NOTAS

Los parámetros path, method y target de ne_request_create se utilizan directamente en los datos de la solicitud sin validación, por lo que no deben provenir de fuentes no confiables. Por ejemplo, permitir la inserción de caracteres CR, LF u otros caracteres de control sin escapar en estos parámetros puede dar lugar a un comportamiento inesperado o inseguro.

neon no impone ninguna restricción de longitud en los datos de entrada de la solicitud.

EJEMPLO

Un ejemplo de aplicación de una operación MKCOL al recurso en la ubicación http://www.example.com/foo/bar/:

ne_session *sess = ne_session_create("http", "www.example.com", 80);
ne_request *req = ne_request_create(sess, "MKCOL", "/foo/bar/");
if (ne_request_dispatch(req)) {
   printf("La solicitud falló: %s\n", ne_get_error(sess));
}
ne_request_destroy(req);
