NEWUSERS(8) Comandos de administración del sistema NEWUSERS(8)

NOMBRE

newusers - actualizar y crear nuevos usuarios por lotes

SINOPSIS

newusers [opciones] [archivo]

DESCRIPCIÓN

El comando newusers lee un archivo (o la entrada estándar por defecto) y utiliza esta información para actualizar un conjunto de usuarios existentes o para crear nuevos usuarios. Cada línea tiene el mismo formato que el archivo de contraseñas estándar (ver passwd(5)) con las excepciones que se explican a continuación:

nombre_contraseña:contraseña_contraseña:uid_contraseña:gid_contraseña:gecos_contraseña:dir_contraseña:shell_contraseña

nombre_contraseña

Este es el nombre del usuario.

Puede ser el nombre de un nuevo usuario o el nombre de un usuario existente (o un usuario creado previamente por newusers). En caso de un usuario existente, la información del usuario será modificada, de lo contrario se creará un nuevo usuario.

contraseña_contraseña

Este campo se cifrará y se utilizará como el nuevo valor de la contraseña cifrada.

uid_contraseña

Este campo se utiliza para definir el UID del usuario.

Si el campo está vacío, newusers definirá automáticamente un nuevo UID (no utilizado).

Si este campo contiene un número, este número se utilizará como el UID.

Si este campo contiene el nombre de un usuario existente (o el nombre de un usuario creado previamente por newusers), se utilizará el UID del usuario especificado.

Si se cambia el UID de un usuario existente, la propiedad de los archivos del usuario deberá arreglarse manualmente.

gid_contraseña

Este campo se utiliza para definir el ID de grupo principal del usuario.

Si este campo contiene el nombre de un grupo existente (o un grupo creado previamente por newusers), el GID de este grupo se utilizará como el ID de grupo principal del usuario.

Si este campo es un número, este número se utilizará como el ID de grupo principal del usuario. Si no existen grupos con este GID, se creará un nuevo grupo con este GID y el nombre del usuario.

Si este campo está vacío, se creará un nuevo grupo con el nombre del usuario y newusers definirá automáticamente un GID que se utilizará como ID de grupo principal para el usuario y como GID para el nuevo grupo.

Si este campo contiene el nombre de un grupo que no existe (y que no fue creado previamente por newusers), se creará un nuevo grupo con el nombre especificado y newusers definirá automáticamente un GID que se utilizará como ID de grupo principal para el usuario y como GID para el nuevo grupo.

gecos_contraseña

Este campo se copia en el campo GECOS del usuario.

dir_contraseña

Este campo se utiliza para definir el directorio personal del usuario.

Si este campo no especifica un directorio existente, se creará el directorio especificado, con la propiedad establecida en el usuario que se está creando o actualizando y su grupo principal. Tenga en cuenta que newusers no crea los directorios padres del directorio personal del nuevo usuario. El comando newusers fallará al crear el directorio personal si los directorios padres no existen, y enviará un mensaje a stderr informando al usuario del fallo. El comando newusers no se detendrá ni devolverá un fallo al shell que lo llama si falla al crear el directorio personal, continuará procesando el lote de nuevos usuarios especificados.

Si se cambia el directorio personal de un usuario existente, newusers no moverá ni copiará el contenido del directorio antiguo a la nueva ubicación. Esto debe hacerse manualmente.

shell_contraseña

Este campo define el shell del usuario. No se realizan comprobaciones sobre este campo.

newusers primero intenta crear o modificar todos los usuarios especificados, y luego escribe estos cambios en las bases de datos de usuarios o grupos. Si ocurre un error (excepto en las escrituras finales en las bases de datos), no se confirmarán cambios en las bases de datos.

Durante este primer pase, los usuarios se crean con una contraseña bloqueada (y las contraseñas no se cambian para los usuarios que no se crean). Se utiliza un segundo pase para actualizar las contraseñas usando PAM. Los fallos al actualizar una contraseña se informan, pero no detendrán las actualizaciones de otras contraseñas.

Este comando está destinado a ser utilizado en un entorno de sistema grande donde muchas cuentas se actualizan a la vez.

OPCIONES

Las opciones que se aplican al comando newusers son:

--badname 

Permitir nombres que no cumplen con los estándares.

-h, --help

Mostrar mensaje de ayuda y salir.

-r, --system

Crear una cuenta de sistema.

Los usuarios del sistema se crearán sin información de envejecimiento en /etc/shadow, y sus identificadores numéricos se elegirán en el rango SYS_UID_MIN-SYS_UID_MAX, definidos en login.defs, en lugar de UID_MIN-UID_MAX (y sus contrapartes GID para la creación de grupos).

-R, --root CHROOT_DIR

Aplicar cambios en el directorio CHROOT_DIR y utilizar los archivos de configuración del directorio CHROOT_DIR. Solo se admiten rutas absolutas.

ADVERTENCIAS

El archivo de entrada debe estar protegido ya que contiene contraseñas sin cifrar.

CONFIGURACIÓN

Las siguientes variables de configuración en /etc/login.defs cambian el comportamiento de esta herramienta:

GID_MAX (número), GID_MIN (número)

Rango de IDs de grupo utilizados para la creación de grupos regulares por useradd, groupadd o newusers.

El valor por defecto para GID_MIN (resp. GID_MAX) es 1000 (resp. 60000).

HOME_MODE (número)

El modo para los nuevos directorios personales. Si no se especifica, se utiliza la UMASK para crear el modo.

useradd y newusers utilizan esto para establecer el modo del directorio personal que crean.

MAX_MEMBERS_PER_GROUP (número)

Máximo de miembros por entrada de grupo. Cuando se alcanza el máximo, se inicia una nueva entrada de grupo (línea) en /etc/group (con el mismo nombre, la misma contraseña y el mismo GID).

El valor por defecto es 0, lo que significa que no hay límites en el número de miembros de un grupo.

Esta característica (grupo dividido) permite limitar la longitud de las líneas en el archivo de grupo. Esto es útil para asegurarse de que las líneas de los grupos NIS no superen los 1024 caracteres.

Si necesita aplicar dicho límite, puede usar 25.

Nota: los grupos divididos pueden no ser compatibles con todas las herramientas (incluso dentro de la suite de herramientas Shadow). No debe usar esta variable a menos que realmente la necesite.

PASS_MAX_DAYS (número)

El número máximo de días que se puede usar una contraseña. Si la contraseña es más antigua que esto, se forzará un cambio de contraseña. Si no se especifica, se asumirá -1 (lo que deshabilita la restricción).

PASS_MIN_DAYS (número)

El número mínimo de días permitidos entre cambios de contraseña. Cualquier intento de cambio de contraseña antes de esto será rechazado. Si no se especifica, se asumirá 0 (lo que deshabilita la restricción).

PASS_WARN_AGE (número)

El número de días de aviso antes de que expire una contraseña. Cero significa que el aviso solo se da el día de la expiración, un valor de -1 significa que no se da ningún aviso. Si no se especifica, no se proporcionará ningún aviso.

SUB_GID_MIN (número), SUB_GID_MAX (número), SUB_GID_COUNT (número)

Si existe /etc/subuid, los comandos useradd y newusers (a menos que el usuario ya tenga IDs de grupo subordinados) asignan SUB_GID_COUNT IDs de grupo no utilizados del rango SUB_GID_MIN a SUB_GID_MAX para cada nuevo usuario.

Los valores por defecto de

or SUB_GID_MIN, SUB_GID_MAX, SUB_GID_COUNT son respectivamente 100000, 600100000 y 65536.

SUB_UID_MIN (número), SUB_UID_MAX (número), SUB_UID_COUNT (número)

Si /etc/subuid existe, los comandos useradd y newusers (a menos que el usuario ya tenga IDs de usuario subordinados) asignan SUB_UID_COUNT IDs de usuario no utilizados del rango SUB_UID_MIN a SUB_UID_MAX para cada nuevo usuario.

Los valores predeterminados para SUB_UID_MIN, SUB_UID_MAX, SUB_UID_COUNT son respectivamente 100000, 600100000 y 65536.

SYS_GID_MAX (número), SYS_GID_MIN (número)

Rango de IDs de grupo utilizados para la creación de grupos del sistema por useradd, groupadd o newusers.

El valor predeterminado para SYS_GID_MIN (respectivamente SYS_GID_MAX) es 101 (respectivamente GID_MIN-1).

SYS_UID_MAX (número), SYS_UID_MIN (número)

Rango de IDs de usuario utilizados para la creación de usuarios del sistema por useradd o newusers.

El valor predeterminado para SYS_UID_MIN (respectivamente SYS_UID_MAX) es 101 (respectivamente UID_MIN-1).

UID_MAX (número), UID_MIN (número)

Rango de IDs de usuario utilizados para la creación de usuarios regulares por useradd o newusers.

El valor predeterminado para UID_MIN (respectivamente UID_MAX) es 1000 (respectivamente 60000).

UMASK (número)

La máscara de creación de archivos se inicializa con este valor. Si no se especifica, la máscara se inicializará a 022.

useradd y newusers utilizan esta máscara para establecer el modo del directorio de inicio que crean si HOME_MODE no está configurado.

También es utilizado por pam_umask como valor umask predeterminado.
