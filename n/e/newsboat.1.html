NOMBRE

newsboat - un lector de feeds RSS/Atom para terminales de texto

SINOPSIS

newsboat [-r] [-e] [-i archivo_opml] [-u archivo_urls] [-c archivo_cache] [-C archivo_config] [-X] [-o] [-x comando...] [-h]

DESCRIPCIÓN

Newsboat es un lector de feeds RSS/Atom para terminales de texto. RSS y Atom son varios formatos XML ampliamente utilizados para transmitir, publicar y sindicar artículos, por ejemplo, noticias o artículos de blogs. Newsboat está diseñado para ser utilizado en terminales de texto en sistemas Unix o similares a Unix, como GNU/Linux, BSD o macOS.

OPCIONES

-h, --help

Muestra la ayuda

-r, --refresh-on-start

Actualiza los feeds al iniciar

-e, --export-to-opml

Exporta los feeds como OPML a la salida estándar. Actualmente exporta OPML 1.0, perdiendo toda la información de etiquetas, pero esto está sujeto a cambios a 2.0 en el futuro.

--export-to-opml2

Exporta los feeds como OPML 2.0, incluyendo etiquetas, a la salida estándar

-X, --vacuum

Compacta la caché mediante: 1) la recuperación del espacio que quedó vacío cuando se eliminaron datos; y 2) la desfragmentación de las entradas en la caché. Esto no elimina las entradas; para eso, consulta las configuraciones cleanup-on-quit, delete-read-articles-on-quit, keep-articles-days y max-items.

--cleanup

Elimina las entradas no referenciadas de la caché y sale de Newsboat. Los feeds y sus artículos se eliminarán si la url del feed ya no está en el archivo urls.

Adicionalmente, si la configuración delete-read-articles-on-quit está activada, se eliminarán todos los artículos leídos (incluyendo los artículos de feeds que aún están en el archivo urls).

-v, -V, --version

Obtiene información de la versión de Newsboat y de las bibliotecas que utiliza

-i archivo_opml, --import-from-opml=archivo_opml

Importa un archivo OPML

-u archivo_urls, --url-file=archivo_urls

Utiliza un archivo de URLs alternativo

-c archivo_cache, --cache-file=archivo_cache

Utiliza un archivo de caché alternativo

-C archivo_config, --config-file=archivo_config

Utiliza un archivo de configuración alternativo

--queue-file=archivo_cola

Utiliza un archivo de cola alternativo

--search-history-file=archivo_historial_busqueda

Utiliza un archivo de historial de búsqueda alternativo

--cmdline-history-file=archivo_historial_linea_comandos

Utiliza un archivo de historial de línea de comandos alternativo

-x comando ..., --execute=comando...

Ejecuta uno o más comandos para ejecutar Newsboat de forma desatendida. Los comandos actualmente disponibles son reload y print-unread.

-l nivel_log, --log-level=nivel_log

Genera un archivo de log con un cierto nivel_log (valores válidos: 1 a 6, para error del usuario, crítico, error, advertencia, información y depuración respectivamente). El nombre del archivo puede especificarse usando la opción --log-file. Si no se especifica, se genera un nombre de archivo del tipo newsboat_<fecha-hora>.log

-d archivo_log, --log-file=archivo_log

Utiliza este archivo_log como salida al registrar mensajes de depuración. Ten en cuenta que esto solo funciona cuando se proporciona un nivel de log.

-E archivo, --export-to-file=archivo

Exporta una lista de artículos leídos (resp. sus GUID). Esto se puede utilizar para transferir información sobre artículos leídos entre diferentes ordenadores.

-I archivo, --import-from-file=archivo

Importa una lista de artículos leídos y los marca como leídos si están en la caché. Esto debe usarse junto con el parámetro de línea de comandos -E.

Añadir Feeds

Para añadir feeds a Newsboat, puedes simplemente añadir una URL de feed por línea al archivo de configuración ~/.newsboat/urls:

http://rss.cnn.com/rss/cnn_topstories.rss
http://newsrss.bbc.co.uk/rss/newsonline_world_edition/front_page/rss.xml

También puedes importar un archivo OPML ejecutando newsboat -i blogroll.opml

Añadir comentarios Las líneas que comienzan con # pueden contener lo que quieras. Newsboat ignora los comentarios, pero pueden servir como documentación para ti. Ten en cuenta que comentar URLs para propósitos de depuración podría llevar a una pérdida de datos inesperada, consulta cleanup-on-quit para más detalles.

Feeds con acceso restringido

Si necesitas añadir URLs que tienen acceso restringido, simplemente proporciona el nombre de usuario/contraseña:

https://username:password@hostname.domain.tld/feed.rss

En caso de que haya un @ en el nombre de usuario, necesitas escribirlo como %40.

Para proteger los nombres de usuario y las contraseñas, asegúrate de restringir el acceso de lectura para ~/.newsboat/urls a ti y opcionalmente a tu grupo:

$ chmod u=rw,g=r,o= ~/.newsboat/urls

Newsboat se asegura de no mostrar nombres de usuario y contraseñas en su interfaz de usuario.

Archivos locales como feeds

También puedes configurar archivos locales como feeds, prefijando la ruta local con file:// y añadiéndola al archivo urls:

file:///var/log/rss_eventlog.xml

Primera Interacción con la UI

La interfaz de usuario principal de Newsboat consta de tres vistas:

Vista de Lista de Feeds → Vista de Lista de Artículos → Vista de Artículo

Puedes profundizar en estas vistas presionando Enter y volver a la vista anterior presionando Q. Presionar Q en la Vista de Lista de Feeds — o presionar Shift + Q desde cualquier lugar — cierra Newsboat.

También puedes buscar en los títulos o contenidos de los artículos presionando / en la Vista de Lista de Feeds o en la Vista de Lista de Artículos. En la Vista de Lista de Feeds se toman en cuenta todos los artículos de todos los feeds. En la Vista de Lista de Artículos se toman en cuenta los artículos del feed actual. Al abrir un artículo desde un diálogo de resultados de búsqueda, la frase de búsqueda se resalta.

HISTORIAL DE BÚSQUEDAS

El historial de todas sus búsquedas se guarda en el sistema de archivos, en el archivo history.search (almacenado junto al archivo cache.db). Por defecto, se almacenan las últimas 100 frases de búsqueda.

Puede influir en la cantidad de frases de búsqueda que se almacenan configurando history-limit.

Vista de lista de feeds

Cuando inicia Newsboat, se le presenta una lista de los feeds que agregó previamente.

Ahora puede:

•Presionar Shift + R para descargar artículos de todos los feeds.
•Presionar R para descargar artículos del feed seleccionado.
•Presionar / para buscar en todos los artículos de todos los feeds.
•Presionar Enter para ir a la lista de artículos de un feed seleccionado.
•Presionar Q para cerrar Newsboat.

Artículos locales Newsboat conserva los artículos que descarga. Cuando inicia Newsboat de nuevo y recarga un feed, los artículos antiguos todavía se pueden leer aunque ya no estén en los feeds RSS actuales. El número máximo de artículos se controla mediante max-items.

Caché Newsboat utiliza una serie de medidas para preservar el ancho de banda de los usuarios y de los proveedores de feeds mediante el uso de descargas HTTP condicionales. Guarda los valores de los encabezados de respuesta "Last-Modified" y "ETag" de cada feed (si están presentes) y le indica al servidor HTTP del feed que solo envíe datos si el feed se ha actualizado. Esto no solo acelera las descargas de feeds RSS sin actualizaciones nuevas, sino que también reduce la cantidad de datos transferidos por solicitud.

Puede deshabilitar la descarga HTTP condicional por feed configurando always-download.

Vista de lista de artículos

Después de ingresar a un feed, puede ver la lista de artículos disponibles por su título. Una N a la izquierda indica que un artículo aún no se ha leído.

Ahora puede:

•Presionar Q para volver a la Vista de lista de feeds.
•Presionar / para buscar en todos los artículos de este feed.
•Presionar Enter para leer un artículo seleccionado.

Vista de artículo

En un artículo, puede desplazarse por el texto y leerlo. Cada enlace en el artículo tiene un número al lado.

Ahora puede:

•Presionar cualquier número para abrir un enlace de artículo en el navegador. Para números mayores que 9, escriba #, luego el número y presione Enter.
•Presionar O para abrir el artículo en el navegador.
•Presionar Q para volver a la Vista de lista de artículos.

Vista del navegador A veces, el contenido de un artículo está vacío o es solo un resumen o una descripción corta. Siempre puede presionar O para ver el artículo completo en un navegador. El navegador predeterminado es lynx.

Puede usar el navegador de su elección configurando browser.

CONFIGURACIÓN

Varios aspectos de Newsboat se pueden configurar a través de un archivo config, que se almacena junto al archivo urls. Una línea de configuración tiene el siguiente aspecto general:

<comando-config> <arg1> ...

El archivo de configuración puede contener comentarios, que comienzan con el carácter # y continúan hasta el final de la línea.

Contribución del usuario Newsboat también viene con contenido aportado por usuarios, como scripts y temas de color. El contenido aportado por usuarios se puede encontrar en /usr/share/doc/newsboat/contrib/. Se anima a los usuarios finales a echar un vistazo, ya que pueden encontrar algo útil.

Ejemplo

Un ejemplo de configuración es el siguiente

# un comentario
max-items        100 # estos comentarios también son posibles
browser          links
show-read-feeds  no
unbind-key       R
bind             ^R feedlist reload-all

Dividir líneas largas en varias

Configuraciones como macros e ignore-article pueden ser bastante largas. Una línea larga se puede dividir en varias usando barras invertidas. Una barra invertida debe ser el último carácter de la línea y la concatenará inmediatamente con la siguiente línea. Es importante que nada siga a la \ en la misma línea, de lo contrario, el carácter \ se trata "tal cual". Por ejemplo:

macro p open; \
reload; quit; \
quit;         \
quit -- "Abre, recarga y luego se asegura de salir de newsboat"

Tenga en cuenta que una barra invertida solo hace que Newsboat ignore la siguiente nueva línea. No hace nada más. Por ejemplo, esta opción bien formateada:

ignore-article \
    "*" \
    "author =~ \"(\
        John Doe| \
        Mary Sue \
    )\""

no se convierte en esto:

ignore-article "*" "author =~ \"(John Doe|Mary Sue)\""

En cambio, como solo se eliminan las nuevas líneas, se convierte en esto:

ignore-article     "*"     "author =~ \"(        John Doe|         Mary Sue     )\""

Por esta razón, tenga en cuenta dónde está dividiendo las líneas, ya que podría importar.

Usar comillas dobles

EN RESUMEN Use comillas dobles para cadenas que contengan espacios o comillas dobles. Escapa las comillas dobles (use \") y las barras invertidas (use \\). No escape nada fuera de las comillas dobles y no use comillas simples para citar; Newsboat no lo admite.

Muchas de las opciones de Newsboat esperan cadenas como argumentos, ya sean comandos, contraseñas, títulos de diálogo, URL, etc. Algunas opciones incluso aceptan múltiples cadenas a la vez. Estas cadenas pueden contener espacios, lo que podría confundir a Newsboat, ya que ya utiliza espacios para separar los nombres de las opciones de los argumentos de las opciones.

Para ayudar a Newsboat a comprender su intención, ponga tales cadenas entre comillas dobles:

browser "firefox --new-tab %u"

¿Qué pasa si necesita una comilla doble dentro de una cadena? Escápela con una barra invertida:

ocnews-password "ComillasDesbalanceadas\"SonTanDivertidas!"

¿Y qué pasa con la propia barra invertida? ¡Escápela también! Suponga que tiene un programa llamado mi paginador favorito y desea ver artículos con él. Newsboat finalmente pasa comandos al shell, y el shell espera que los espacios se escapen si desea que se conserven. Pero dado que Newsboat interpreta las barras invertidas, debe agregar otra capa de escape. Por lo tanto, terminará con un comando como este:

pager "/usr/bin/mi\\ paginador\\ favorito"

Evaluación del Shell

También es posible integrar la salida de comandos externos en la configuración. El texto entre dos comillas invertidas ` se evalúa como un comando de shell y se utiliza su salida. Esto funciona de manera similar a la evaluación de comillas invertidas en shells compatibles con Bourne y permite a los usuarios utilizar información externa del sistema dentro de la configuración.

Escapado

Las comillas invertidas y los caracteres # se pueden escapar con una barra invertida (por ejemplo, \` y \#). En este caso, se reemplazan con ` o # literales en la configuración.

Vinculaciones de teclas

Las nuevas vinculaciones de teclas descritas aquí son compatibles desde Newsboat 2.39.

Puede vincular una tecla (o secuencia de teclas) a una operación (o lista de operaciones) con el comando de configuración bind.

La sintaxis de una vinculación es la siguiente:

bind <secuencia-tecla> <diálogo>[,<diálogo>] <lista-operaciones> [-- "<descripción>"]

Advertencia: Limitaciones

Las vinculaciones que comparten un prefijo deben tener todas la misma longitud; de lo contrario, solo se crea la última vinculación.

Por ejemplo:

bind ab todas partes ...
bind abc todas partes ...

solo creará una vinculación para abc. Reordenar los comandos creará una vinculación para ab.

Esto evita la ambigüedad cuando se presiona ab y Newsboat no sabe si ya debe ejecutar la vinculación para ab o si el usuario va a presionar c a continuación, activando la otra vinculación.

Para tener ambas vinculaciones, ya sea:

•renómbrelas para que tengan prefijos diferentes (por ejemplo, ab y bcd), o
•hágalas de la misma longitud (por ejemplo, renombre ab a abd para que coincida con la longitud de abc).

Secuencia de teclas

Las teclas en minúsculas, mayúsculas y caracteres especiales se escriben literalmente.

Las combinaciones de teclas con Ctrl se escriben usando el acento circunflejo ^. Por ejemplo, Ctrl + R equivale a ^R. Tenga en cuenta que todas las combinaciones de teclas relacionadas con Ctrl deben escribirse en mayúsculas.

Alternativamente, las combinaciones de teclas usando Shift o Ctrl se pueden escribir como <S-a> y <C-a>, para Shift + A y Ctrl + A, respectivamente. Tenga en cuenta que esta sintaxis alternativa solo funciona con el comando bind. No es compatible con el comando más antiguo bind-key.

•<ENTER> (tecla Enter)
•<BACKSPACE> (tecla de retroceso

Nuevos Estilos de Asignación de Teclas

Este es el estilo más nuevo y flexible de asignación de teclas. La sintaxis es la siguiente:

bind <key-sequence> <dialog> <operation>

Secuencia de Teclas

Una secuencia de teclas puede consistir en una o más teclas. Las teclas especiales están entre corchetes.

•<LEFT> (cursor a la izquierda)
•<RIGHT> (cursor a la derecha)
•<UP> (cursor arriba)
•<DOWN> (cursor abajo)
•<PPAGE> (cursor página arriba)
•<NPAGE> (cursor página abajo)
•<HOME> (cursor al principio de la lista/artículo)
•<END> (cursor al final de la lista/artículo)
•<ESC> (tecla Esc)
•<TAB> (tecla Tab)
•<LT> (tecla <)
•<GT> (tecla >)
•<^> (tecla ^, también se puede especificar como solo ^ si no va seguida de una letra)
•<F1> a <F12> (tecla F1 a F12)

Se pueden colocar varias teclas en secuencia. Por ejemplo, gg significa presionar la tecla g dos veces y ^O<ENTER> significa presionar Ctrl + O seguido de Enter. Presionar Esc cancelará una entrada de múltiples teclas.

Diálogo

Un diálogo es un contexto en el que la asignación de teclas está activa. Los diálogos disponibles son:

•everywhere
•feedlist
•filebrowser
•help
•articlelist
•article
•tagselection
•filterselection
•urlview
•podboat
•dirbrowser
•searchresultslist

Se pueden especificar varios diálogos con una coma entre ellos. Por ejemplo:

bind k feedlist,articlelist,urlview up
bind j feedlist,articlelist,urlview down

o usando everywhere para aplicar la asignación en todos los diálogos:

bind k everywhere up
bind j everywhere down

Lista de Operaciones

Las operaciones se ejecutan al presionar la secuencia de teclas correspondiente. Para una lista completa de operaciones disponibles, consulte [_newsboat_operations] y [_podboat_operations].

Se pueden especificar varias operaciones escribiéndolas separadas por un punto y coma. Algunas operaciones permiten especificar un argumento, por ejemplo, set <opción de configuración> <valor de configuración> se puede usar para cambiar una opción de configuración.

Se puede usar una secuencia con dos guiones seguidos de texto entre comillas dobles para añadir una descripción a una asignación (por ejemplo, -- "alguna descripción"). Si está presente, la descripción se muestra en el diálogo de ayuda.

En combinación, esto podría verse así:

bind of everywhere set browser "firefox" ; open-in-browser -- "Abrir en Firefox"

El ejemplo anterior significa que al presionar o seguido de f se cambiará el navegador configurado a firefox y luego se ejecutará el comando open-in-browser para abrir el feed/artículo en el navegador configurado.

bind es similar a las macros pero más flexible. Las macros se configuran globalmente, mientras que bind se puede aplicar a diálogos específicos. Además, las macros siempre requieren presionar 2 teclas (macro-prefix seguido de una tecla específica de la macro), mientras que bind puede especificar una secuencia de teclas de cualquier longitud.

Colores

Es posible configurar ajustes de color personalizados en Newsboat. La configuración básica de sintaxis es:

color <elemento> <color de primer plano> <color de fondo> [<atributo> ...]

Esto significa que si configuras colores para un cierto elemento, necesitas proporcionar un color de primer plano y un color de fondo como mínimo. Los siguientes colores son compatibles:

•black
•red
•green
•yellow
•blue
•magenta
•cyan
•white
•default
•color<n>, por ejemplo, color123

El color default significa que se utilizará el color predeterminado del terminal. El nombre de color color<n> (donde <n> es un número decimal que no empieza con cero) se puede utilizar si tu terminal admite 256 colores (por ejemplo, gnome-terminal, o xterm con TERM establecido en xterm-256color). Newsboat contiene soporte para terminales de 256 colores desde la versión 2.1. Para una tabla completa de colores y sus números correspondientes, consulta https://www.calmar.ws/vim/256-xterm-24bit-rgb-color-chart.html.

Opcionalmente, también puedes añadir uno o más atributos. Los siguientes atributos son compatibles:

•standout
•underline
•reverse
•blink
•dim
•bold
•protect
•invis

Actualmente, los siguientes elementos son compatibles:

•background: el fondo de la aplicación
•listnormal: un elemento de lista normal
•listfocus: el elemento de lista seleccionado actualmente
•listnormal_unread: un elemento de lista no leído
•listfocus_unread: el elemento de lista no leído seleccionado actualmente
•title (añadido en 2.25): el título del diálogo actual, que suele estar en la parte superior de la pantalla (pero véase show-title-bar y swap-title-and-hints). Si no especificas un estilo para este elemento, se utiliza el estilo info.
•info: la barra de pistas, que suele estar en la parte inferior de la pantalla (pero véase show-keymap-hint y swap-title-and-hints)
•hint-key (añadido en 2.25): una tecla en la barra de pistas. Si no especificas un estilo para este elemento, se utiliza el estilo info.
•hint-keys-delimiter (añadido en 2.25): la coma que separa las teclas en la barra de pistas. Si no especificas un estilo para este elemento, se utiliza el estilo info.
•hint-separator (añadido en 2.25): los dos puntos que separan las teclas de sus descripciones en la barra de pistas. Si no especificas un estilo para este elemento, se utiliza el estilo info.
•hint-description (añadido en 2.25): una descripción de una tecla en la barra de pistas. Si no especificas un estilo para este elemento, se utiliza el estilo info.
•article: el texto del artículo
•end-of-text-marker: líneas de relleno (~) debajo de bloques de texto

color background        white   blue   bold
color hint-key            yellow  blue   bold
color hint-keys-delimiter white   blue
color hint-separator      white   blue   bold

COMANDOS DE CONFIGURACIÓN

La <dirección> opcional puede ser asc para orden ascendente o desc para orden descendente. Tenga en cuenta que la dirección no afecta a la ordenación aleatoria. Además, las direcciones para fecha están invertidas: desc significa que los elementos más nuevos están primero, mientras que asc significa que los elementos más antiguos están primero. TAGGING

Newsboat comes with the possibility to categorize or "tag", as we call it, RSS feeds. Every RSS feed can be assigned 0 or more tags. Within Newsboat, you can then select to only show RSS feeds that match a certain tag. That makes it easy to categorize your feeds in a flexible and powerful way.

Usually, the urls file contains one RSS feed URL per line. To assign a tag to an RSS feed, simply attach it as a single word, separated by blanks such as space or tab. If the tag needs to contain spaces, you must use quotes (") around the tag (see example below). An example urls file may look like this:

https://blog.fefe.de/rss.xml?html interesting conspiracy news "cool stuff"
https://rss.orf.at/news.xml news orf
https://www.heise.de/newsticker/heise.rdf news interesting

When you now start Newsboat with this configuration, you can press T to select a tag. When you select the tag "news", you will see all three RSS feeds. Pressing T again and e.g. selecting the "conspiracy" tag, you will only see the https://blog.fefe.de/rss.xml?html RSS feed. Pressing Ctrl + T clears the current tag, and again shows all RSS feeds, regardless of their assigned tags.

A special type of tag are tags that start with the tilde character (~). When such a tag is found, the feed title is set to the tag name (excluding the ~ character). These type of tags are ignored when any kind of "first tag" property is used. With this feature, you can give feeds any title you want in your feed list:

https://rss.orf.at/news.xml "~ORF News"

Another special type of tag are tags that start with the exclamation mark (!). When such a tag is found, the feed is hidden from the regular list of feeds and its content can only be found through a query feed.

https://rss.orf.at/news.xml ! news
http://feeds.bbci.co.uk/news/world/rss.xml ! news
"query:News from around the globe:tags # \"news\""

In this example, the first two feeds won’t appear in the feedlist, but their articles will still be accessible through the query feed titled "News from around the globe". The "hidden" tags in this example don’t even have names, because their only use is to hide the feed that they’re tagging.

CONFIGURING NEWSBOAT

Newsboat supports two types of scripts: "exec" and "filter". An "exec" script can be any program that gets executed and whose output is interpreted as RSS feed, while "filter" scripts are fed with the content of a configured URL and whose output is interpreted as RSS feed.

The configuration is simple and straight-forward. Just add to your urls file configuration lines like the following ones:

exec:~/bin/execurl-script
filter:~/bin/filter-script:https://some.test/url

The first line shows how to add an execurl script to your configuration: start the line with exec: and then immediately append the path of the script that shall be executed. If this script requires additional parameters, simply use quotes (see Using Double Quotes for details):

"exec:~/bin/execurl-script param1 param2"

The second line shows how to add a filter script to your configuration: start the line with filter:, then immediately append the path of the script, then append a colon (:), and then append the URL of the file that shall be fed to the script. Again, if the script requires any parameters, simply quote the whole thing:

"filter:~/bin/filter-script param1 param2:https://url/foobar"

In both cases, the tagging feature as described above is still available:

exec:~/bin/execurl-script tag1 tag2 "quoted tag"
filter:~/bin/filter-script:https://some.test/url tag3 tag4 tag5

If you need to write your own extension, see this short guide for an introduction. A collection of existing scripts and filters might help, too.

Newsboat comes with an example exec script which shows one way to generate an RSS channel. It also includes a way to see which exact arguments are passed to the script by Newsboat. This example can be found in the doc/examples subdirectory.

COMMAND LINE

Like other text-oriented software, Newsboat contains an internal commandline to modify configuration variables ad hoc and to run own commands. It provides a flexible access to the functionality of Newsboat which is especially useful for advanced users.

To start the commandline, type :. You will see a ":" prompt at the bottom of the screen, similar to tools like vi(m) or mutt. You can now enter commands. Pressing the Enter key executes the command (possibly giving feedback to the user) and closes the commandline. You can cancel entering commands by pressing the Esc key. The history of all the commands that you enter will be saved to the history.cmdline file, stored next to the cache.db file. The backlog is limited to 100 entries by default, but can be influenced by setting the history-limit configuration variable. To disable history saving, set the history-limit to 0.

The commandline provides you with some help if you can’t remember the full names of commandline commands. By pressing the Tab key, Newsboat will try to automatically complete your command. If there is more than one possible completion, you can subsequently press the Tab key to cycle through all results. If no match is found, no suggestion will be inserted into the commandline. For the set command, the completion also works for configuration variable names.

In addition, some common key combination such as Ctrl + G (to cancel input), Ctrl + K (to delete text from the cursor position to the end of line), Ctrl + U (to clear the whole line) and Ctrl + W (to delete the word before the current cursor position) were added.

Please be aware that the input history of both the command line and the search functions are saved to the filesystems, to the files history.cmdline resp. history.search (stored next to the cache.db file). By default, the last 100 entries are saved, but this can be configured (configuration variable history-limit) and also totally disabled (by setting said variable to 0).

FILES

By default, Newsboat stores all the files in a traditional Unix fashion, i.e. in a "dotdir" located at ~/.newsboat. However, it also supports a modern way, XDG Base Directory Specification https://standards.freedesktop.org/basedir-spec/basedir-spec-latest.html, which splits the files between the following locations:

1.$XDG_CONFIG_HOME/newsboat/ (XDG_CONFIG_HOME defaults to ~/.config)
2.$XDG_DATA_HOME/newsboat/ (XDG_DATA_HOME defaults to ~/.local/share)

If the newsboat directory exists under XDG_CONFIG_HOME, then Newsboat will use XDG directories (creating the data directory if necessary). Otherwise, Newsboat will default to ~/.newsboat.

If you’re currently using ~/.newsboat/ but wish to migrate to XDG directories, you should move the files as follows:

config, urls

to $XDG_CONFIG_HOME/newsboat/

cache.db, history.search, history.cmdline, queue

to $XDG_DATA_HOME/newsboat/

Newsboat and Podboat also create "lock files". These prevent you from starting two instances of the same program, and thus from corrupting your data. Newsboat and Podboat remove these files when you quit the program, so there is no need to copy them anywhere — just be aware of them in case you write scripts that work with cache.db or queue. By default, lock files are located as follows:

dotdir XDG
Newsboat ~/.newsboat/cache.db.lock $XDG_DATA_HOME/newsboat/cache.db.lock
Podboat ~/.newsboat/pb-lock.pid $XDG_DATA_HOME/newsboat/.lock

Newsboat places the lock file next to the cache file, so if you specify cache-file setting or pass —cache-file command-line argument, the path to the lock file will change too. Podboat’s lock can be placed elsewhere using —lock-file command-line argument.

dotfiles

~/.newsboat/config

~/.newsboat/urls

XDG

$XDG_CONFIG_HOME/newsboat/config

$XDG_CONFIG_HOME/newsboat/urls

Note: if the XDG_CONFIG_HOME environment variable is not set, Newsboat behaves as if it was set to ~/.config.
