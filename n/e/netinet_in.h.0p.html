NOMBRE

netinet/in.h — Familia de direcciones de Internet

SINOPSIS

#include <netinet/in.h>

DESCRIPCIÓN

El archivo de cabecera <netinet/in.h> definirá los siguientes tipos:

in_port_t
Equivalente al tipo uint16_t como se describe en <inttypes.h>.
in_addr_t
Equivalente al tipo uint32_t como se describe en <inttypes.h>.

El archivo de cabecera <netinet_in.h> definirá el tipo sa_family_t como se describe en <sys/socket.h>.

El archivo de cabecera <netinet_in.h> definirá los tipos uint8_t y uint32_t como se describen en <inttypes.h>. La inclusión del archivo de cabecera <netinet/in.h> también puede hacer visibles todos los símbolos de <inttypes.h> y <sys/socket.h>.

El archivo de cabecera <netinet/in.h> definirá la estructura in_addr, que contendrá al menos el siguiente miembro:

in_addr_t  s_addr

El archivo de cabecera <netinet/in.h> definirá la estructura sockaddr_in, que contendrá al menos los siguientes miembros:

sa_family_t     sin_family   AF_INET.
in_port_t       sin_port     Número de puerto.
struct in_addr  sin_addr     Dirección IP.

Los miembros sin_port y sin_addr estarán en orden de bytes de red.

La estructura sockaddr_in se utiliza para almacenar direcciones para la familia de direcciones de Internet. Las aplicaciones convertirán punteros a este tipo a struct sockaddr * para su uso con funciones de socket.

El archivo de cabecera <netinet/in.h> definirá la estructura in6_addr, que contendrá al menos el siguiente miembro:

uint8_t s6_addr[16]

Esta matriz se utiliza para contener una dirección IPv6 de 128 bits, almacenada en orden de bytes de red.

El archivo de cabecera <netinet/in.h> definirá la estructura sockaddr_in6, que contendrá al menos los siguientes miembros:

sa_family_t      sin6_family    AF_INET6.
in_port_t        sin6_port      Número de puerto.
uint32_t         sin6_flowinfo  Clase de tráfico IPv6 e información de flujo.
struct in6_addr  sin6_addr      Dirección IPv6.
uint32_t         sin6_scope_id  Conjunto de interfaces para un ámbito.

Los miembros sin6_port y sin6_addr estarán en orden de bytes de red.

Antes de llamar a una función de este estándar que lea valores de una estructura sockaddr_in6 (por ejemplo, bind() o connect()), la aplicación deberá asegurarse de que todos los miembros de la estructura, incluidos los miembros adicionales no estándar, si los hubiere, estén inicializados. Si la estructura sockaddr_in6 tiene un miembro no estándar y ese miembro tiene un valor distinto del que resultaría de la inicialización por defecto, el comportamiento de cualquier función de este estándar que lea valores de la estructura sockaddr_in6 es definido por la implementación. Todas las funciones de este estándar que devuelvan datos en una estructura sockaddr_in6 (por ejemplo, getaddrinfo() o accept()) inicializarán la estructura de una manera que cumpla los requisitos anteriores, y se asegurarán de que cada miembro no estándar, si lo hubiere, tenga un valor que produzca el mismo comportamiento que la inicialización por defecto tendría en todas las funciones de este estándar que lean valores de una estructura sockaddr_in6.

El campo sin6_scope_id es un entero de 32 bits que identifica un conjunto de interfaces según corresponda al ámbito de la dirección contenida en el campo sin6_addr. Para una sin6_addr de ámbito de enlace, la aplicación deberá asegurarse de que sin6_scope_id sea un índice de enlace. Para una sin6_addr de ámbito de sitio, la aplicación deberá asegurarse de que sin6_scope_id sea un índice de sitio. El mapeo de sin6_scope_id a una interfaz o conjunto de interfaces está definido por la implementación.

El archivo de cabecera <netinet/in.h> declarará la siguiente variable externa:

const struct in6_addr in6addr_any

Esta variable es inicializada por el sistema para contener la dirección IPv6 comodín. El archivo de cabecera <netinet/in.h> también define la macro IN6ADDR_ANY_INIT. Esta macro debe ser constante en tiempo de compilación y puede usarse para inicializar una variable de tipo struct in6_addr a la dirección IPv6 comodín.

El archivo de cabecera <netinet/in.h> declarará la siguiente variable externa:

const struct in6_addr in6addr_loopback

Esta variable es inicializada por el sistema para contener la dirección IPv6 de bucle interno. El archivo de cabecera <netinet/in.h> también define la macro IN6ADDR_LOOPBACK_INIT. Esta macro debe ser constante en tiempo de compilación y puede usarse para inicializar una variable de tipo struct in6_addr a la dirección IPv6 de bucle interno.

El archivo de cabecera <netinet/in.h> definirá la estructura ipv6_mreq, que contendrá al menos los siguientes miembros:

struct in6_addr  ipv6mr_multiaddr  Dirección multicast IPv6.
unsigned         ipv6mr_interface  Índice de interfaz.

El archivo de cabecera <netinet/in.h> definirá las siguientes constantes simbólicas para su uso como valores del argumento level de getsockopt() y setsockopt():

IPPROTO_IP
Protocolo de Internet.
IPPROTO_IPV6
Protocolo de Internet versión 6.
IPPROTO_ICMP
Protocolo de mensajes de control.
IPPROTO_RAW
Protocolo de paquetes IP crudos.
IPPROTO_TCP
Protocolo de control de transmisión.
IPPROTO_UDP
Protocolo de datagramas de usuario.

El archivo de cabecera <netinet/in.h> definirá la siguiente constante simbólica para su uso como dirección local en la estructura pasada a bind():

INADDR_ANY
Dirección comodín IPv4.

El archivo de cabecera <netinet/in.h> definirá la siguiente constante simbólica para su uso como dirección de destino en las estructuras pasadas a connect(), sendmsg() y sendto():

INADDR_BROADCAST
Dirección de broadcast IPv4.

El archivo de cabecera <netinet/in.h> definirá la siguiente constante simbólica, con el valor especificado, para ayudar a las aplicaciones a declarar buffers del tamaño adecuado para almacenar direcciones IPv4 en formato de cadena:

INET_ADDRSTRLEN
16. Longitud del formato de cadena para IP.

Las funciones htonl(), htons(), ntohl() y ntohs() estarán disponibles como se describe en <arpa/inet.h>. La inclusión del archivo de cabecera <netinet/in.h> también puede hacer visibles todos los símbolos de <arpa/inet.h>.

El archivo de cabecera <netinet/in.h> definirá la siguiente constante simbólica, con el valor especificado, para ayudar a las aplicaciones a declarar buffers del tamaño adecuado para almacenar direcciones IPv6 en formato de cadena:

INET6_ADDRSTRLEN
46. Longitud del formato de cadena para IPv6.

El archivo de cabecera <netinet/in.h> definirá las siguientes constantes simbólicas, con valores enteros distintos, para su uso en el argumento option_name en las funciones getsockopt() o setsockopt() a nivel de protocolo IPPROTO_IPV6:

IPV6_JOIN_GROUP
Unirse a un grupo multicast.
IPV6_LEAVE_GROUP
Abandonar un grupo multicast.

NAME

netinet_in.h – IPv4 and IPv6 constants and structures

SYNOPSIS

#include <netinet/in.h>

DESCRIPTION

The <netinet/in.h> header defines constants and structures used for internet protocol version 4 (IPv4) and internet protocol version 6 (IPv6) socket programming. It includes definitions for socket address structures, constants for IP addresses, and options that can be set on sockets.

The following socket option level and name constants are defined for use with getsockopt() and setsockopt():

IPV6_JOIN_GROUP
Join a multicast group.
IPV6_LEAVE_GROUP
Quit a multicast group.
IPV6_MULTICAST_HOPS

Multicast hop limit.
IPV6_MULTICAST_IF
Interface to use for outgoing multicast packets.
IPV6_MULTICAST_LOOP

Multicast packets are delivered back to the local application.
IPV6_UNICAST_HOPS
Unicast hop limit.
IPV6_V6ONLY
Restrict AF_INET6 socket to IPv6 communications only.

The <netinet/in.h> header shall define the following macros that test for special IPv6 addresses. Each macro is of type int and takes a single argument of type const struct in6_addr *:

IN6_IS_ADDR_UNSPECIFIED

Unspecified address.
IN6_IS_ADDR_LOOPBACK

Loopback address.
IN6_IS_ADDR_MULTICAST

Multicast address.
IN6_IS_ADDR_LINKLOCAL

Unicast link-local address.
IN6_IS_ADDR_SITELOCAL

Unicast site-local address.
IN6_IS_ADDR_V4MAPPED

IPv4 mapped address.
IN6_IS_ADDR_V4COMPAT

IPv4-compatible address.
IN6_IS_ADDR_MC_NODELOCAL

Multicast node-local address.
IN6_IS_ADDR_MC_LINKLOCAL

Multicast link-local address.
IN6_IS_ADDR_MC_SITELOCAL

Multicast site-local address.
IN6_IS_ADDR_MC_ORGLOCAL

Multicast organization-local address.
IN6_IS_ADDR_MC_GLOBAL

Multicast global address.

The following sections are informative.

APPLICATION USAGE

Although applications are required to initialize all members (including any non-standard ones) of a sockaddr_in6 structure, the same is not required for the sockaddr_in structure, since historically many applications only initialized the standard members. Despite this, applications are encouraged to initialize sockaddr_in structures in a manner similar to the required initialization of sockaddr_in6 structures.

Although it is common practice to initialize a sockaddr_in6 structure using:

struct sockaddr_in6 sa;
memset(&sa, 0, sizeof sa);

this method is not portable according to this standard, because the structure can contain pointer or floating-point members that are not required to have an all-bits-zero representation after default initialization. Portable methods make use of default initialization; for example:

struct sockaddr_in6 sa = { 0 };

or:

static struct sockaddr_in6 sa_init;
struct sockaddr_in6 sa = sa_init;

A future version of this standard may require that a pointer object with an all-bits-zero representation is a null pointer, and that sockaddr_in6 does not have any floating-point members if a floating-point object with an all-bits-zero representation does not have the value 0.0.

RATIONALE

The INADDR_ANY and INADDR_BROADCAST values are byte-order-neutral and thus their byte order is not specified. Many implementations have additional constants as extensions, such as INADDR_LOOPBACK, that are not byte-order-neutral. Traditionally, these constants are in host byte order, requiring the use of htonl() when using them in a sockaddr_in structure.
