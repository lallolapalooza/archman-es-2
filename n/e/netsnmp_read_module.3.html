DESCRIPCIÓN

Las funciones que manejan módulos MIB se dividen en cuatro grupos: aquellas que manejan la inicialización y el cierre, la lectura y el análisis de archivos MIB, la búsqueda en el árbol MIB y las rutinas de salida.

Inicialización y Cierre

add_mibdir se utiliza para añadir el directorio especificado a la lista de ubicaciones que se buscan para encontrar archivos que contienen módulos MIB. Nótese que esto no carga realmente los módulos MIB ubicados en ese directorio, sino que es simplemente un paso de inicialización para hacerlos disponibles para netsnmp_read_module. Esta función devuelve un recuento de los archivos encontrados en el directorio, o -1 si hay un error. Debe llamarse *antes* de invocar netsnmp_init_mib.

netsnmp_init_mib configura la ruta de búsqueda del directorio MIB (utilizando add_mibdir), configura el marco interno de la MIB y luego carga los módulos MIB apropiados (utilizando netsnmp_read_module y read_mib). Ver la sección VARIABLES DE ENTORNO para más detalles.
Debe llamarse antes que cualquier otra rutina que manipule o acceda al árbol MIB (pero después de cualquier llamada adicional a add_mibdir).

shutdown_mib borrará la información que fue recopilada por netsnmp_read_module, add_mibdir y add_module_replacement. Se recomienda encarecidamente no invocar shutdown_mib mientras haya sesiones SNMP siendo gestionadas activamente.

Lectura y Análisis de MIBs

netsnmp_read_module toma el nombre de un módulo MIB (que no necesariamente tiene que ser el mismo que el nombre del archivo que contiene el módulo), lo localiza dentro de la lista configurada de directorios MIB, y carga las definiciones del módulo en el árbol MIB activo. También carga cualquier módulo MIB listado en la cláusula IMPORTS de este módulo.

read_mib es similar, pero toma el nombre del archivo que contiene el módulo MIB. Nótese que este archivo no necesita estar ubicado dentro de la lista de búsqueda del directorio MIB (aunque sí los módulos listados en la cláusula IMPORTS).

read_all_mibs leerá todos los módulos MIB encontrados en la lista de búsqueda del directorio MIB.

En general, el analizador es silencioso sobre las rarezas que ve en los archivos MIB. Para que se informen advertencias, llame a snmp_set_mib_warnings con un nivel de 1 (o 2 para aún más advertencias).

add_module_replacement puede usarse para permitir que los nuevos módulos MIB obsoleten a los más antiguos, sin necesidad de modificar las cláusulas IMPORTS de otros módulos. Toma los nombres de los módulos antiguo y nuevo, junto con una indicación de qué partes del módulo antiguo están afectadas.

etiqueta longitud carga el nuevo módulo cuando:
NULL 0 siempre (el módulo antiguo es un subconjunto estricto del
nuevo)
nombre 0 solo para la etiqueta dada
nombre distinto de 0 para cualquier identificador con este prefijo
También puede usarse para manejar errores en los identificadores de módulo utilizados en las cláusulas IMPORTS de MIB (como referirse a RFC1213 en lugar de RFC1213-MIB).

Búsqueda en el Árbol MIB

read_objid toma una cadena que contiene una versión textual de un identificador de objeto (en forma numérica o descriptiva), y lo transforma en la lista correspondiente de sub-identificadores. Esto se devuelve en el parámetro output, con el número de sub-identificadores devuelto a través de out_len. Cuando se llama, out_len debe contener la longitud máxima del array output. Si se están procesando múltiples identificadores de objeto, esta longitud debe restablecerse antes de cada llamada. Esta función devuelve un valor de 1 si tiene éxito al analizar la cadena y 0 en caso contrario.

snmp_parse_oid es similar, pero devuelve un puntero al buffer OID analizado (o NULL).

get_module_node toma un descriptor y el nombre de un módulo, y devuelve la lista OID correspondiente, de la misma manera que read_objid arriba.
Si el nombre del módulo se especifica como "ANY", esta rutina asumirá que el descriptor dado es único dentro del árbol y devolverá la entrada correspondiente. Si esta suposición no es válida, el comportamiento en cuanto a qué variable se devuelve depende de la implementación.

Salida

print_mib imprimirá una representación del árbol MIB actualmente activo al puntero FILE especificado.

print_objid tomará un identificador de objeto (como el devuelto por read_objid, snmp_parse_oid o get_module_node), e imprimirá la forma textual de este OID en la salida estándar.

fprint_objid hace lo mismo, pero imprime al puntero FILE especificado por el parámetro inicial.

snprint_objid imprime la misma información en el buffer apuntado por buf, que tiene una longitud de len. Devuelve el número de caracteres impresos, o -1 si el buffer no era lo suficientemente grande. En este último caso, buf típicamente contendrá una versión truncada de la información (pero este comportamiento no está garantizado).

print_description, fprint_description y snprint_description toman un identificador de objeto similar e imprimen una versión de la definición MIB para ese objeto, junto con el OID completo. El argumento width controla cómo se distribuye el OID.

netsnmp_read_module(3) — netsnmp API

NAME

netsnmp_read_module, init_mib, read_all_mibs, read_mib, free_mib — manage MIB trees

SYNOPSIS

#include <net-snmp/mib_api.h>


int netsnmp_read_module(const char *name);
int init_mib(void);
int read_all_mibs(void);
int read_mib(const char *filename);
void free_mib(void);

DESCRIPTION

These functions manage the loading and unloading of MIB (Management Information Base) modules. MIB modules are used to define the structure and syntax of SNMP management information.

init_mib() initializes the MIB system. It loads a default set of MIB modules based on the configuration of the Net-SNMP library. This function should be called before any other MIB-related functions.

netsnmp_read_module(name) loads a specific MIB module named name. If the module has already been loaded, this function does nothing.

read_all_mibs() loads all available MIB modules found in the configured MIB directories. This is a convenient way to load all MIBs if you don't know their specific names.

read_mib(filename) loads MIB definitions from a specific file named filename. This is useful for loading custom MIB files that are not part of the standard Net-SNMP distribution.

free_mib() unloads all loaded MIB modules and frees any associated memory. This function should be called when MIB management is no longer needed, typically before the program exits.

It is important to call snmp_set_save_descriptions(1)before calling init_mib (or similar).

ENVIRONMENT VARIABLES

The main use of environmental variables with respect to these API calls is to configure which MIB modules should be loaded, and where they are located.

MIBDIRS
A colon separated list of directories to search for MIB modules.
Default: /usr/share/snmp/mibs
Used by init_mib, netsnmp_read_module, read_all_mibs and (implicitly) by read_mib.
MIBS
A colon separated list of MIB modules to load.
The default list of modules will depend on how the Net-SNMP software was originally compiled, but is typically:
IP-MIB:IF-MIB:TCP-MIB:UDP-MIB:SNMPv2-MIB:RFC1213-MIB:UCD-SNMP-MIB:HOST-RESOURCES-MIB
If the value of the MIBS environmental variable starts with a '+' character, then these MIB modules will be added to the default list. Otherwise these modules (plus any that they IMPORT from) will be loaded instead of the default list.
If the MIBS environmental variable has the value ALL then read_all_mibs will be called to load the full collection of all available MIB modules.
Used by init_mib only.
MIBFILES
A colon separated list of files to load.
Default: (none)
Used by init_mib only.
