NOMBRE

neomuttrc - Archivo de configuración para el Agente de Usuario de Correo NeoMutt (MUA)

DESCRIPCIÓN

Un archivo de configuración de NeoMutt consta de una serie de "comandos". Cada línea del archivo puede contener uno o más comandos. Cuando se utilizan varios comandos, deben estar separados por un punto y coma (";").

La almohadilla, o signo de número ("#"), se utiliza como carácter de "comentario". Puedes usarlo para anotar tu archivo de inicialización. Todo texto posterior al carácter de comentario hasta el final de la línea se ignora.

Las comillas simples ("'") y las comillas dobles (""") se pueden usar para citar cadenas que contienen espacios u otros caracteres especiales. La diferencia entre los dos tipos de comillas es similar a la de muchos programas de shell populares, es decir, que las comillas simples se utilizan para especificar una cadena literal (que no se interpreta para variables de shell o para citar con una barra invertida [ver párrafo siguiente]), mientras que las comillas dobles indican una cadena que debe evaluarse. Por ejemplo, las comillas invertidas se evalúan dentro de comillas dobles, pero no dentro de comillas simples.

La barra invertida ("\") cita el siguiente carácter, al igual que en los shells como Bash y Zsh. Por ejemplo, si quieres poner comillas ("") dentro de una cadena, puedes usar la barra invertida ("\") para forzar que el siguiente carácter sea literal en lugar de un carácter interpretado.

"\\" significa insertar una barra invertida literal ("\") en la línea. "\n" y "\r" tienen sus significados C habituales de salto de línea (LF) y retorno de carro (CR), respectivamente.

Una barra invertida ("\") al final de una línea se puede usar para dividir comandos en varias líneas, siempre que los puntos de división no aparezcan en medio de nombres de comandos.

También es posible sustituir la salida de un comando de Unix en un archivo de inicialización. Esto se logra encerrando el comando entre comillas invertidas (``comando'').

Las variables de entorno de Unix se pueden acceder de la misma manera que en shells como sh y Bash: anteponga el nombre de la variable a un signo de dólar ("$").

COMANDOS

Comandos de configuración

Los siguientes son los comandos entendidos por NeoMutt:

account-hook regex comando
Este hook se ejecuta cada vez que accedes a un buzón remoto. Útil para ajustar la configuración a diferentes servidores IMAP o POP.
alias [ -group nombre ... ] clave dirección [, dirección ... ]
unalias [ -group nombre ... ] { * | clave ... }
alias define una clave sustituta para la(s) dirección(es) dada(s). Cada dirección se resolverá en una dirección de correo electrónico (usuario@ejemplo.com) o una dirección de correo electrónico con nombre (Nombre de Usuario <usuario@ejemplo.com>). La dirección puede especificarse en cualquiera de los formatos, o en el formato "usuario@ejemplo.com (Nombre de Usuario)".
Nota: Si quieres crear un alias para más de una dirección, debes separar las direcciones con una coma (",").
unalias elimina el alias correspondiente a la clave dada o todos los alias cuando se usa "*" como argumento.
La bandera opcional -group hace que la(s) dirección(es) se agreguen o eliminen del grupo con el nombre especificado.
alternates [ -group nombre ... ] regex [ regex ... ]
unalternates [ -group nombre ... ] { * | regex ... }
alternates se usa para informar a NeoMutt sobre direcciones alternativas donde recibes correo; puedes usar expresiones regulares (regex) para especificar direcciones alternativas. Esto afecta la idea que tiene NeoMutt sobre los mensajes tuyos y los mensajes dirigidos a ti.
unalternates se puede usar para escribir excepciones a la expresión regular de alternates. Para eliminar una expresión regular de la lista de alternatives, usa el comando unalternates con exactamente la misma regex o usa "*" para eliminar todas las entradas.
La bandera opcional -group hace que todas las expresiones regulares subsiguientes se agreguen o eliminen del grupo con el nombre especificado.
alternative_order tipo-mime[/subtipo-mime] [ tipo-mime[/subtipo-mime] ... ]
unalternative_order { * | tipo-mime[/subtipo-mime] ... }
El comando alternative_order te permite definir un orden de preferencia que utiliza NeoMutt para determinar qué parte de un cuerpo multipart/alternative mostrar. Un subtipo-mime de "*" coincide con cualquier subtipo de multipart/alternative, al igual que un subtipo-mime vacío.
unalternative_order elimina entradas de la lista ordenada o elimina la lista completa cuando se usa "*" como argumento.
attachments { + | - }disposition tipo-mime [ tipo-mime ... ]
unattachments { + | - }disposition tipo-mime [ tipo-mime ... ]
attachments ?
unattachments *
Puedes hacer que tu índice de mensajes muestre el número de adjuntos que califican en cada mensaje, o buscar mensajes por recuento de adjuntos. También puedes configurar qué tipos de adjuntos califican para esta función con los comandos attachments y unattachments.
disposition es el tipo Content-Disposition del adjunto; ya sea inline o attachment. Puedes abreviarlo a I o A.
La disposición va precedida por un símbolo "+" o "-". Si es un "+", estás diciendo que quieres permitir que esta disposición y tipo MIME califiquen. Si es un "-", estás diciendo que esta disposición y tipo MIME es una excepción a las reglas "+" anteriores.
tipo-mime es el tipo MIME del adjunto que quieres que afecte el comando. Un tipo MIME siempre tiene el formato mayor/menor. La parte principal de tipo-mime debe ser texto literal (o el token especial "*"), pero la parte menor puede ser una expresión regular. Por lo tanto, "*/.*" coincide con cualquier tipo MIME.
Ten en cuenta que la primera parte MIME se trata de forma ligeramente diferente: es casi siempre el texto del mensaje. Por lo tanto, no se cuenta como un adjunto si su disposición es inline y no es un tipo MIME multipart/* o message/*.
Ingresar el comando "attachments ?" como un comando listará tu configuración actual en formato neomuttrc, para que pueda ser copiado en otro lugar.
Ingresar el comando "unattachments *" como un comando borrará todas las configuraciones de adjuntos.
auto_view tipo-mime[/subtipo-mime] [ tipo-mime[/subtipo-mime] ... ]
unauto_view { * | tipo-mime[/subtipo-mime] ... }
Estos comandos te permiten especificar que NeoMutt debe convertir automáticamente los tipos-mime dados a text/plain al mostrar mensajes. Para que esto funcione, debe haber una entrada mailcap(5) para el tipo-mime dado con la opción copiousoutput establecida. Un subtipo-mime de "*" coincide con cualquier subtipo de multipart/alternative, al igual que un subtipo-mime vacío.
bind mapa[,mapa ... ] tecla función
unbind { * | mapa | [,mapa...]} [ tecla ]
Este comando te permite cambiar las combinaciones de teclas predeterminadas o definir combinaciones adicionales (operación invocada al presionar una tecla).
mapa especifica en qué menú pertenece la combinación. Se pueden especificar varios mapas separándolos con comas (no se permiten espacios adicionales). Los mapas definidos actualmente son: alias, attach, browser, compose, editor, generic, index, mix, pager, pgp, postpone, query y smime.
tecla es la tecla (o secuencia de teclas) que deseas enlazar, por ejemplo, "\Ca" para control-A. Además, tecla puede especificarse como un número octal de tres dígitos.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

mber prefijado con un “\” o como un nombre simbólico. La función <what-key> se puede usar para explorar nombres de códigos de tecla y nombres simbólicos para las teclas en su teclado.
function especifica qué acción tomar cuando se presiona una tecla. Tenga en cuenta que el nombre de la función debe especificarse sin corchetes angulares.
La ausencia de una secuencia de teclas en el comando unbind significa desvincular todas las vinculaciones en los menús dados en map.
Para obtener más información sobre teclas y funciones, consulte el manual de NeoMutt.
charset-hook alias charset
iconv-hook charset local-charset
charset-hook define un alias para un conjunto de caracteres. Esto es útil para mostrar correctamente los mensajes que están etiquetados con un nombre de conjunto de caracteres que NeoMutt no conoce.
iconv-hook define un nombre específico del sistema para un conjunto de caracteres. Esto es útil cuando la implementación de iconv(3) de su sistema no entiende los nombres de conjuntos de caracteres MIME (como iso-8859-1), sino que insiste en recibir nombres de conjuntos de caracteres específicos de la implementación (como 8859-1). En este caso específico, pondría “iconv-hook iso-8859-1 8859-1” en su archivo de configuración.
color object [ attribute ... ] foreground background
color { header | body } [ attribute ... ] foreground background regex
color status foreground background [regex [ num ]]
color index-object [ attribute ... ] foreground background pattern
color compose-object foreground background
color compose-object [ attribute ... ] foreground background
uncolor { index-object | header | body } { * | pattern ... }
Si su terminal admite color, estos comandos se pueden usar para asignar combinaciones de primer plano/fondo a ciertos objetos. Los objetos definidos actualmente son: attach_headers, attachment, body, bold, error, hdrdefault, header, index, index_author, index_collapsed, index_date, index_flags, index_label, index_number, index_size, index_subject, index_tag, index_tags, indicator, markers, message, normal, progress, prompt, quoted, quotedN, search, signature, status, stripe_even, stripe_odd, tilde, tree, underline.
Si la barra lateral está habilitada, los siguientes objetos también son válidos: sidebar_background, sidebar_divider, sidebar_flagged, sidebar_highlight, sidebar_indicator, sidebar_new, sidebar_ordinary, sidebar_spool_file.
Los objetos body y header le permiten restringir la coloración a una expresión regular. El index-object le permite seleccionar mensajes coloreados por patrón.
header y body coinciden con regex en el encabezado/cuerpo de un mensaje, index-object puede coincidir con pattern en el índice del mensaje. Tenga en cuenta que las búsquedas del lado del servidor IMAP (=b, =B, =h) no son compatibles con los patrones de color del índice.
El objeto status acepta opcionalmente una expresión regular y un número de coincidencia. Si se proporciona la expresión regular, solo las partes coincidentes se colorean. Si además se proporciona el número de coincidencia, solo esa subcoincidencia de la expresión regular se colorea.
Los objetos de composición válidos incluyen compose_header, compose_security_encrypt, compose_security_sign, compose_security_both, compose_security_none.
Los colores válidos incluyen: default, black, red, green, yellow, blue, magenta, cyan, white, #RRGGBB, colorN.
Los atributos válidos incluyen: none, bold, underline, reverse y standout.
El comando uncolor solo se puede aplicar a los objetos de índice, encabezado y cuerpo. Elimina entradas de la lista. Debe especificar el mismo pattern especificado en el comando color para que se elimine. El patrón “*” es un token especial que significa borrar la lista de colores de todas las entradas.
Para más información sobre la coloración, consulte el manual de NeoMutt.
crypt-hook regex keyid
El comando crypt-hook proporciona un método por el cual puede especificar la ID de la clave pública que se utilizará al cifrar mensajes a un destinatario determinado. El significado de keyid debe tomarse en sentido amplio: puede ser una dirección de correo electrónico diferente, un keyid numérico o incluso una cadena de búsqueda arbitraria. Puede usar múltiples crypt-hooks con la misma regex; múltiples crypt-hooks coincidentes dan como resultado el uso de múltiples keyids para un destinatario.
index-format-hook name [!]pattern format-string
Este comando se utiliza para inyectar cadenas de formato dinámicamente en $index_format basándose en la coincidencia de patrones con el mensaje actual.
El expando $index_format %@name@ especifica un marcador de posición para la inyección. Los index-format-hooks con el mismo name se emparejan usando pattern contra el mensaje actual. El emparejamiento se realiza en el orden especificado en el .neomuttrc, utilizándose la primera coincidencia. Luego, el format-string del hook se sustituye y evalúa.
exec function [ function ... ]
Este comando se puede utilizar para ejecutar cualquier function. Las funciones se enumeran en la referencia de funciones. “exec function” es equivalente a “push <function>”.
fcc-save-hook pattern mailbox
fcc-hook pattern mailbox
save-hook pattern mailbox
fcc-save-hook es un atajo, equivalente a realizar tanto un fcc-hook como un save-hook con sus argumentos, incluida la expansión % en mailbox según $index_format.
fcc-hook se utiliza para guardar correo saliente en un buzón que no sea $record. NeoMutt busca en la lista inicial de destinatarios del mensaje la primera pattern coincidente y utiliza mailbox como buzón “Fcc:” predeterminado. Si no se encuentra ninguna coincidencia, el mensaje se guardará en el buzón $record.
save-hook se utiliza para anular el buzón predeterminado utilizado al guardar mensajes. mailbox se utilizará como predeterminado si el mensaje coincide con pattern.
Para proporcionar más flexibilidad y buenos valores predeterminados, NeoMutt aplica los expansores de $index_format a mailbox después de que haya sido expandido. Consulte la sección PATTERNS a continuación o la sección “Coincidencia de mensajes en hooks” en el manual de NeoMutt para obtener información sobre el formato exacto de pattern.
folder-hook [-noregex] regex command
Cuando NeoMutt entra en una carpeta que coincide con regex (o, cuando regex va precedido por un signo de exclamación, no coincide con regex), se ejecuta el command dado. El modificador -noregex controla si regex se considera una coincidencia de cadena simple o una coincidencia de expresión regular completa.
Cuando varios folder-hooks coinciden con una carpeta de correo dada, se ejecutan en el orden especificado en el archivo de configuración.
group [ -group name ... ] { -rx regex ... | -addr address ... }
ungroup [ -group name ... ] { * | -rx regex ... | -addr address ... }
group se utiliza para agregar directamente direcciones o expresiones regulares al grupo o grupos especificados. Las diferentes categorías de argumentos para el comando group pueden estar en cualquier orden. Las banderas -rx y -addr especifican cómo se deben interpretar las siguientes cadenas (que no pueden comenzar con un guion): como una expresión regular o como una dirección de correo electrónico, respectivamente.
ungroup se utiliza para eliminar direcciones o expresiones regulares de los grupos especificados. La sintaxis es similar al comando group, sin embargo, el carácter especial “*” se puede usar para vaciar un grupo de todo su contenido.
Estos grupos de direcciones también se pueden crear implícitamente mediante los comandos alias, lists, subscribe y alternates especificando la opción opcional -group.
Una vez definidos, estos grupos de direcciones se pueden utilizar en patrones para buscar y limitar la visualización a mensajes que coincidan con un grupo.
hdr_order header [ header ... ]
unhdr_order { * | header ... }
Con el comando hdr_order puede especificar un orden en el que NeoMutt intentará presentarle estos encabezados al ver mensajes.
“unhdr_order *” borrará todos los encabezados anteriores de la lista de orden, eliminando así los efectos de orden de encabezado establecidos por el archivo de inicio del sistema.

ignore string [ string ... ]
unignore { * | string ... }
El comando ignore te permite especificar campos de encabezado que normalmente no quieres ver en el paginador. No necesitas especificar el nombre completo del campo de encabezado. Por ejemplo, “ignore content-” ignorará todos los campos de encabezado que comiencen con la cadena “content-”, “ignore *” ignorará todos los encabezados.
Para eliminar un token previamente agregado de la lista, usa el comando unignore. Por ejemplo, “unignore *” eliminará todos los tokens de la lista de ignorados.
lists [ -group name ... ] regex [ regex ... ]
unlists [ -group name ... ] { * | regex ... }
subscribe [ -group name ... ] regex [ regex ... ]
unsubscribe [ -group name ... ] { * | regex ... }
NeoMutt mantiene dos listas de expresiones regulares de direcciones de listas de correo: una lista de listas de correo suscritas y una lista de listas de correo conocidas. Todas las listas de correo suscritas son conocidas.
El comando lists agrega una dirección de lista de correo a la lista de listas de correo conocidas. El comando unlists elimina una lista de correo de las listas de listas de correo conocidas y suscritas.
El comando subscribe agrega una lista de correo a las listas de listas de correo conocidas y suscritas. El comando unsubscribe la elimina de la lista de listas de correo suscritas.
La bandera -group agrega todas las expresiones regulares subsiguientes al grupo name.
macro menu[,menu ... ] key sequence [ description ]
unmacro { * | menu | [,menu...]} [ key ]
Este comando vincula la secuencia de teclas dada a la key dada en el menú o menús dados. Para menús definidos actualmente, consulta el comando bind anterior. Para especificar múltiples menús, pon solo una coma entre los menús.
Opcionalmente, puedes especificar un texto descriptivo después de sequence, que se mostrará en las pantallas de ayuda si contienen una description.
La secuencia de teclas faltante en el comando unmacro significa anular todas las macros en los menús dados en menu.

           [[-notify | -nonotify]
           [-poll | -nopoll]
           mailbox] [ ... ]

unmailboxes { * | mailbox ... }
mailboxes especifica las carpetas que pueden recibir correo y que se verificarán en busca de mensajes nuevos. Al cambiar de carpetas, presionar espacio te permitirá recorrer las carpetas con correo nuevo.
named-mailboxes es una alternativa a mailboxes -label label. NeoMutt puede configurarse para mostrar la etiqueta en lugar de la ruta del buzón.
El comando unmailboxes se utiliza para eliminar un nombre de archivo de la lista de carpetas que pueden recibir correo. Si se especifica “*” como nombre de archivo, la lista se vacía.
mailto_allow { * | header-field ... }
unmailto_allow { * | header-field ... }
Como medida de seguridad, NeoMutt solo agregará header-fields aprobados por el usuario de una URL mailto:. Esto es necesario ya que NeoMutt manejará ciertos header-fields, como Attach, de manera especial. Los comandos mailto_allow y unmailto_allow permiten al usuario modificar la lista de encabezados aprobados.
NeoMutt inicializa la lista predeterminada para contener solo los header-fields Subject y Body, que son los únicos requisitos especificados por la especificación mailto: en RFC2368, y los encabezados Cc, In-Reply-To, References para ayudar con las respuestas a listas de correo.

mbox-hook [-noregex] regex mailbox
Cuando NeoMutt cambia a una carpeta de correo que coincide con regex, mailbox se usará como la carpeta “mbox”, es decir, los mensajes leídos se moverán a esa carpeta cuando se salga de la carpeta de correo. El modificador -noregex controla si regex se compara como una simple igualdad de cadena o como una coincidencia de expresión regular completa.
Tenga en cuenta que la ejecución de mbox-hook depende de la variable de configuración $move. Si se establece en “no” (el valor predeterminado), no se ejecutarán los mbox-hook.
El primer mbox-hook coincidente se aplica.
message-hook pattern command
Antes de que NeoMutt muestre (o formatee para responder o reenviar) un mensaje que coincida con el pattern dado (o, cuando está precedido por un signo de exclamación, no coincide con el pattern), se ejecuta el command dado. Cuando coinciden múltiples message-hooks, se ejecutan en el orden en que aparecen en el archivo de configuración.

Este comando te permite definir una lista de tipos de contenido MIME de “datos” para los cuales NeoMutt intentará determinar el tipo de archivo real a partir del nombre del archivo, y no utilizará una entrada de mailcap(5) dada para el tipo MIME original. Por ejemplo, puedes agregar el tipo MIME application/octet-stream a esta lista.
Además, el comando unmime_lookup puede usarse para deshabilitar esta función para cualquier tipo MIME particular si se hubiera configurado, por ejemplo, en un neomuttrc global.

Usando my_hdr, puedes definir encabezados que se agregarán a los mensajes que compones. unmy_hdr eliminará los encabezados definidos por el usuario.
open-hook regex "shell-command"
close-hook regex "shell-command"
append-hook regex "shell-command"
Estos comandos proporcionan una forma de manejar carpetas comprimidas. El regex dado especifica qué carpetas se consideran comprimidas (por ejemplo, “\.gz$”). Los comandos le dicen a NeoMutt cómo descomprimir una carpeta (open-hook), comprimir una carpeta (close-hook) o agregar correo comprimido a una carpeta comprimida (append-hook). El shell-command es una cadena de formato similar a printf(3) y debe contener dos marcadores de posición para los nombres de archivo de origen (%f) y destino (%t) que deben colocarse entre comillas simples para evitar expansiones de shell no deseadas. Ejemplos:
append-hook '\.gz$' "gzip --stdout '%t' >> '%f'"
close-hook '\.gz$' "gzip --stdout '%t' > '%f'"
open-hook '\.gz$' "gzip --stdout --decompress '%f' > '%t'"

push string
Este comando agrega la string nombrada al principio del búfer del teclado. La cadena puede contener caracteres de control, nombres de teclas y nombres de funciones como la cadena de secuencia en el comando macro. Puedes usarla para ejecutar automáticamente una secuencia de comandos al inicio, o al ingresar a carpetas específicas.
Para usar funciones, es importante usar corchetes angulares (“<” y “>”) para que NeoMutt reconozca la entrada como un nombre de función. De lo contrario, simulará pulsaciones de teclas individuales.
reply-hook pattern command
send-hook pattern command
send2-hook pattern command
Estos comandos se pueden usar para ejecutar comandos de configuración arbitrarios basados en los destinatarios del mensaje. pattern se usa para coincidir con el mensaje, consulta la sección “Coincidencia de mensajes en Hooks” del manual para más detalles. command se ejecuta cuando pattern coincide.
reply-hook se compara con el mensaje al que estás respondiendo, en lugar del mensaje que estás enviando. send-hook se compara con todos los mensajes, tanto nuevos como respuestas. Nota: los reply-hooks se comparan antes que los send-hook, independientemente del orden especificado en el archivo de configuración del usuario.
send2-hook se compara cada vez que se modifica un mensaje, ya sea editándolo o usando el menú de composición para cambiar sus destinatarios o asunto. send2-hook se ejecuta después de send-hook y puede, por ejemplo, usarse para establecer parámetros como la variable $sendmail según la dirección del remitente del mensaje. Nota: los send-hooks solo se ejecutan una vez después de obtener la lista inicial de destinatarios.

Comandos de Puntuación y Variables

score pattern value
unscore { * | pattern }
El comando score añade una entrada de puntuación a la lista de entradas de puntuación. La entrada de puntuación se define por un pattern y un value. Los patrones se describen en la sección PATTERNS más abajo. El value es un entero positivo o negativo. La puntuación final de un mensaje es la suma total de todas las entradas de puntuación coincidentes.
El comando unscore elimina entradas de puntuación de la lista. Debe especificar el mismo pattern que especificó en el comando score para que se elimine. El patrón “*” es un token especial que significa borrar la lista de todas las entradas de puntuación.
set { [ no | inv | & | ? ]variable } [ ... ]
set { variable=valor | variable+=incremento | variable-=decremento } [ ... ]
unset variable  [ variable ... ]
reset variable  [ variable ... ]
toggle variable [ variable ... ]
set variable ?
Estos comandos se utilizan para establecer y manipular las variables de configuración.
NeoMutt conoce cuatro tipos básicos de variables: booleanas, numéricas, de cadena, lista de cadenas y quadoption. Las variables booleanas pueden ser set (verdadero), unset (falso) o toggled. Las variables numéricas pueden tener asignado un valor entero positivo. El valor de las variables numéricas puede incrementarse con “+=” y decrementarse con “-=”. Las variables de lista de cadenas usan “+=” para añadir un incremento a la lista de cadenas y “-=” para eliminar un decremento de la lista de cadenas.
Las variables de cadena consisten en cualquier número de caracteres imprimibles y deben ir entre comillas si contienen espacios o tabulaciones. También puede usar las secuencias de escape “\n” y “\t” para nueva línea y tabulación, respectivamente. El contenido de las variables de cadena puede extenderse usando “+=”.
Las variables quadoption se utilizan para controlar si se le debe preguntar por ciertas acciones o para especificar una acción predeterminada. Un valor de yes hará que la acción se lleve a cabo automáticamente como si hubiera respondido “sí” a la pregunta. Del mismo modo, un valor de no hará que la acción se lleve a cabo como si hubiera respondido “no”. Un valor de ask-yes provocará una pregunta con una respuesta predeterminada de “sí” y ask-no proporcionará una respuesta predeterminada de “no”.
El comando toggle antepone automáticamente el prefijo “inv” a todas las variables especificadas. El comando unset antepone automáticamente el prefijo “no” a todas las variables especificadas. Si utiliza el comando set y antepone “&” a la variable, esto tiene el mismo comportamiento que el comando reset.
El comando reset restablece todas las variables dadas a los valores predeterminados en el momento de la compilación. Con el comando reset existe la variable especial all, que le permite restablecer todas las variables a sus valores predeterminados del sistema.
Usando la función <enter-command>, puede consultar el valor de una variable sufijando el nombre de la variable con un signo de interrogación: “:set allow_8bit?”. La sintaxis antigua de consulta con prefijo (“:set ?allow_8bit”) todavía es compatible.
setenv { ?variable | variable valor }
unsetenv variable
Puede alterar el entorno que NeoMutt pasa a sus procesos hijos usando los operadores setenv y unsetenv.
También puede consultar los valores actuales del entorno anteponiendo un carácter “?”.
sidebar_pin buzon [ buzon ...]
sidebar_unpin { * | buzon ... }
El comando sidebar_pin especifica los buzones que siempre se mostrarán en la barra lateral, incluso si $sidebar_new_mail_only está configurado y el buzon no contiene correo nuevo.
El comando sidebar_unpin se utiliza para eliminar un buzon de la lista de buzones que se muestran siempre. Utilice “sidebar_unpin *” para eliminar todos los buzones.
source nombre_archivo
Este comando permite la inclusión de comandos de inicialización desde otros archivos. Si el nombre_archivo comienza con una tilde (“~”), se expandirá a la ruta de su directorio de inicio.
Si el nombre_archivo termina con una barra vertical (“|”), entonces el nombre_archivo se considera un programa ejecutable del cual leer entrada (por ejemplo, “source ~/bin/myscript|””).
Si el nombre de archivo es relativo y el comando source se ejecuta desde el contexto de un archivo de configuración, entonces el nombre de archivo se interpreta relativo al directorio de ese archivo de configuración. Si el comando se ejecuta fuera de un archivo de configuración, por ejemplo, desde el prompt, entonces el nombre de archivo se interpreta relativo al directorio de trabajo actual (ver cd para saber cómo cambiar el directorio de trabajo actual en tiempo de ejecución).
Nota: Un hook recuerda el archivo de configuración en el que se definió y establece el contexto a ese archivo al ejecutar sus comandos. Como resultado, un comando source dentro de un hook se ejecuta en el contexto del archivo de configuración en el que se definió el hook. Por lo tanto, los nombres de archivo relativos se interpretan relativos al archivo de configuración en el que está definido el hook.
spam regex formato
nospam { * | regex }
NeoMutt tiene soporte generalizado para filtros externos de puntuación de spam. Al definir sus regex de spam con los comandos spam y nospam, puede limitar, buscar y ordenar su correo basándose en sus atributos de spam, según lo determinado por el filtro externo. También puede mostrar los atributos de spam en su visualización de índice usando el selector %H en la variable $index_format. (Consejo: intente "%<H?[%H] >" para mostrar las etiquetas de spam solo cuando están definidas para un mensaje determinado).
Para más información sobre filtros de puntuación de spam, consulte la sección “Detección de Spam” en el manual de NeoMutt.
subjectrx regex reemplazo
unsubjectrx { * | regex }
El comando subjectrx especifica una expresión regular que, si se detecta en el asunto de un mensaje, hace que el asunto sea reemplazado con el reemplazo. El reemplazo está sujeto a sustituciones de la misma manera que para el comando spam: %L para el texto a la izquierda de la coincidencia, %R para el texto a la derecha de la coincidencia, y %1 para el primer subgrupo en la coincidencia (etc.). Si simplemente desea borrar la coincidencia, establézcalo en “%L%R”. Puede coexistir cualquier número de comandos subjectrx.
Tenga en cuenta esto: ¡el valor de reemplazo reemplaza todo el asunto, no solo la coincidencia!
unsubjectrx elimina un subjectrx dado de la lista de sustitución. Si “*” se usa como argumento, se eliminarán todas las sustituciones.
subscribe-to imap-folder-uri
unsubscribe-from imap-folder-uri
Indica al servidor IMAP que se suscriba o anule la suscripción de la carpeta imap-folder-uri. El argumento debe ser una URI IMAP, por ejemplo, “subscribe-to imaps://mail.example.org/inbox”.
La suscripción es una característica del protocolo IMAP donde el servidor gestiona una lista de carpetas suscritas. Esta lista puede ser consultada por clientes como NeoMutt.
NeoMutt utiliza esa lista en diversas situaciones, ver $imap_list_subscribed y $imap_check_subscribed.
timeout-hook comando
startup-hook comando
shutdown-hook comando
La función Global Hooks introduce estos hooks en NeoMutt. Se llaman cuando ocurren eventos globales en NeoMutt. startup-hook y shutdown-hook son los más propensos a ser útiles para los usuarios de notmuch(1).
timeout-hook ejecuta un comando periódicamente cuando NeoMutt busca correo nuevo. Este hook se llama cada $timeout segundos.
Antes de que NeoMutt abra la primera carpeta al iniciar, NeoMutt ejecutará el startup-hook para el comando dado.
Antes de que NeoMutt esté a punto de salir, y antes de que la carpeta se cierre, NeoMutt ejecutará el shutdown-hook para el comando dado.
unhook { * | tipo-hook }
Este comando le permite eliminar hooks que haya definido previamente. Puede eliminar todos los hooks proporcionando el carácter “*” como argumento, o puede eliminar todos los hooks de un tipo-hook específico diciendo algo como “unhook send-hook”.

COINCIDENCIA DE PATRONES

NeoMutt puede filtrar los mensajes utilizando patrones. Los patrones son cadenas de texto que se comparan con diferentes atributos de los mensajes. A continuación se enumeran los tipos de patrones disponibles:

 ~<(PATTERN) mensajes cuyo padre inmediato coincide con PATTERN, ej. respuestas a tus mensajes: ~<(~P)
 ~>(PATTERN) mensajes que tienen un hijo inmediato que coincide con PATTERN, ej. mensajes a los que respondiste: ~>(~P)
 ~ EXPR expresión regular que coincide con el cuerpo del mensaje.
 ~b EXPR expresión regular que coincide con el cuerpo y las cabeceras del mensaje.
 ~c PATTERN coincide con los mensajes que están en el campo 'Cc:'.
 ~C PATTERN coincide con los mensajes que están en el campo 'Cc:' o 'Bcc:'.
 ~d DATE coincide con los mensajes enviados/recibidos en una fecha específica.
 ~D DATE coincide con los mensajes enviados/recibidos después de una fecha específica.
 ~e EXPR coincide con los mensajes que tienen una cabecera cuyo valor coincide con EXPR.
 ~f PATTERN coincide con los mensajes enviados por la persona especificada en PATTERN.
 ~F PATTERN coincide con los mensajes enviados por la persona especificada en PATTERN (sin distinción entre mayúsculas y minúsculas).
 ~g GROUP coincide con los mensajes enviados a un grupo especificado.
 ~h HEADER coincide con los mensajes que tienen una cabecera especificada.
 ~H HEADER coincide con los mensajes que tienen una cabecera especificada (sin distinción entre mayúsculas y minúsculas).
 ~i PATTERN coincide con los mensajes de un buzón especificado.
 ~I PATTERN coincide con los mensajes de un buzón especificado (sin distinción entre mayúsculas y minúsculas).
 ~l PATTERN coincide con los mensajes que tienen una etiqueta especificada.
 ~m NUMBERS coincide con los mensajes especificados por número de mensaje.
 ~n PATTERN coincide con los mensajes que tienen un asunto especificado.
 ~N PATTERN coincide con los mensajes que tienen un asunto especificado (sin distinción entre mayúsculas y minúsculas).
 ~o PATTERN coincide con los mensajes que tienen un destinatario especificado.
 ~O PATTERN coincide con los mensajes que tienen un destinatario especificado (sin distinción entre mayúsculas y minúsculas).
 ~p PATTERN coincide con los mensajes que tienen un destinatario especificado en el campo 'Para:'.
 ~P PATTERN coincide con los mensajes que tienen un destinatario especificado en el campo 'Para:' o 'Ccp:'.
 ~q PATTERN coincide con los mensajes que tienen una cita especificada.
 ~r DATE coincide con los mensajes recibidos en una fecha especificada.
 ~s EXPR expresión regular que coincide con el asunto del mensaje.
 ~S EXPR expresión regular que coincide con el asunto del mensaje (sin distinción entre mayúsculas y minúsculas).
 ~t PATTERN coincide con los mensajes que tienen un destinatario especificado en el campo 'Para:' o 'Cc:'.
 ~T PATTERN coincide con los mensajes que tienen un destinatario especificado en el campo 'Para:', 'Cc:' o 'Ccp:'.
 ~u PATTERN coincide con los mensajes que tienen una cabecera especificada y cuyo valor coincide con PATTERN.
 ~v PATTERN coincide con los mensajes que tienen una cabecera especificada y cuyo valor coincide con PATTERN (sin distinción entre mayúsculas y minúsculas).
 ~w PATTERN coincide con los mensajes que tienen una cabecera especificada y cuyo valor coincide con PATTERN.
 ~W PATTERN coincide con los mensajes que tienen una cabecera especificada y cuyo valor coincide con PATTERN (sin distinción entre mayúsculas y minúsculas).
 ~x NUMBERS coincide con los mensajes que tienen una cabecera especificada y cuyo valor coincide con NUMBERS.
 ~X NUMBERS coincide con los mensajes que tienen una cabecera especificada y cuyo valor coincide con NUMBERS (sin distinción entre mayúsculas y minúsculas).
 ~y PATTERN coincide con los mensajes que tienen una etiqueta especificada.
 ~z PATTERN coincide con los mensajes que tienen un nombre de archivo adjunto especificado.
 ~A PATTERN coincide con todos los mensajes en hilos que contienen mensajes tuyos: ~(~P)
 ~<(PATTERN) mensajes cuyo padre inmediato coincide con PATTERN, ej. respuestas a tus mensajes: ~<(~P)
 ~>(PATTERN) mensajes que tienen un hijo inmediato que coincide con PATTERN, ej. mensajes a los que respondiste: ~>(~P)
 Donde EXPR es una expresión regular y GROUP es un grupo de direcciones.
 *) Los rangos de números de mensaje (introducidos por “~m”) son aún más generales y potentes que los otros tipos de rangos. Continúe leyendo y consulte la sección “Rangos de Mensajes” del manual.

 ***) Los sufijos “K” y “M” están permitidos para especificar kilobytes y megabytes respectivamente.

Se debe prestar especial atención al usar expresiones regulares dentro de los patrones. Específicamente, el analizador de NeoMutt para estos patrones eliminará un nivel de barra invertida (“\”), que normalmente se usa para escapar. Si su intención es usar una barra invertida en la expresión regular, necesitará usar dos barras invertidas (“\\”) en su lugar.

Puede forzar a NeoMutt a tratar EXPR como una simple STRING en lugar de una expresión regular utilizando “=” en lugar de “~” en el nombre del patrón. Por ejemplo, “=b *.*” encontrará todos los mensajes que contengan la STRING literal “*.*”. Las coincidencias de subcadenas simples son menos potentes que las expresiones regulares, pero pueden ser considerablemente más rápidas. Esto es especialmente cierto para las carpetas IMAP, ya que las coincidencias de subcadenas se pueden realizar en el servidor en lugar de recuperar cada mensaje. IMAP trata “=h” de forma especial: debe tener el formato “Cabecera: subcadena” y no coincidirá parcialmente con los nombres de las cabeceras. La parte subcadena puede omitirse si simplemente desea encontrar mensajes que contengan una cabecera particular sin tener en cuenta su valor.

Los patrones que coinciden con listas de direcciones (notablemente c, C, p, P y t) coinciden si hay al menos una coincidencia en toda la lista. Si desea asegurarse de que todos los elementos de esa lista coinciden, necesita prefijar su patrón con “^”.

Este ejemplo coincide con todos los correos que sólo tienen destinatarios de Alemania.

Coincidencia de todas las direcciones en listas de direcciones: ^~C \.de$

Puede restringir la coincidencia de patrones de direcciones a alias que haya definido con el modificador “@”. Este ejemplo coincide con mensajes cuyos destinatarios son todos de Alemania y que son conocidos en su lista de alias.

Coincidencia restringida a alias: ^@~C \.de$

Para coincidir con cualquier alias definido, use una expresión regular que coincida con cualquier cadena. Este ejemplo coincide con mensajes cuyos remitentes son alias conocidos.

Coincidencia de cualquier alias definido: @~f .

Anidamiento y Operadores Booleanos

El AND lógico se realiza especificando más de un criterio.

Por ejemplo: ~t trabajo ~f smith

seleccionaría mensajes que contengan la palabra “trabajo” en la lista de destinatarios y que tengan la palabra “smith” en el campo de cabecera “De:”.

NeoMutt también reconoce los siguientes operadores para crear patrones de búsqueda más complejos:

• “!” — operador NOT lógico
• “|” — operador OR lógico
• “()” — operador de agrupación lógica

Aquí hay un ejemplo que ilustra un patrón de búsqueda complejo. Este patrón seleccionará todos los mensajes que no contienen “trabajo” en el campo “Para:” o “Cc:” y que son de “smith”.

Uso de operadores booleanos en patrones: !(~t trabajo|~c trabajo) ~f smith

Aquí hay un ejemplo que usa espacios en blanco en la expresión regular (note los delimitadores de “'” y “"”). Para que esto coincida, el asunto del correo debe coincidir con “^Trabajo +De +Mismo$” y debe ser de “Jim +Alguien” o “Ed +OtroAlguien”:

Escapar regex: '~s "^Trabajo +De +Mismo$" ~f ("Jim +Alguien"|"Ed +OtroAlguien")'

Nota: Si una expresión regular contiene paréntesis o una barra vertical (“|”), debe encerrar la expresión entre comillas dobles o simples ya que esos caracteres también se utilizan para separar diferentes partes del lenguaje de patrones de NeoMutt.

Por ejemplo: ~f "usuario@(casa\.org|trabajo\.com)"

Sin las comillas, los paréntesis no terminarían. Esto se separaría en dos patrones OR: ~f usuario@(casa\.org y trabajo\.com). Nunca son lo que quieres.

NeoMutt soporta dos tipos de fechas, absolutas y relativas para el patrón “~d” y “~r”.

Fechas Absolutas
Las fechas deben estar en formato dd[/mm[/[CC]AA]] (día, mes, siglo y año; todas las partes, con excepción del día, son opcionales, por defecto el mes y año actuales). Un ejemplo de un rango de fechas válido es:
Limitar a mensajes coincidentes: ~d 20/1/95-31/10

Alternativamente, puede usar AAAAmmdd para especificar una fecha.

Cuando se le da un año de dos dígitos, NeoMutt interpretará valores menores que “70” como pertenecientes al siglo XXI (es decir, “38” significa 2038 y no 1938, y “00” se interpreta como 2000), y valores mayores o iguales a “70” como pertenecientes al siglo XX.

Si omite la fecha mínima (primera) y sólo especifica -dd/mm/AA, se seleccionarán todos los mensajes anteriores a la fecha dada. Si omite la fecha máxima (segunda) y especifica dd/mm/AA-, se seleccionarán todos los mensajes posteriores a la fecha dada. Si especifica una sola fecha sin guion (“-”), solo se seleccionarán los mensajes enviados/recibidos en la fecha dada.

Puede añadir márgenes de error a las fechas absolutas. Un márgen de error es un signo (“+” o “-”), seguido de un dígito, seguido de una de las unidades en la tabla “Unidades de Fecha” a continuación. Como caso especial, puede reemplazar el signo por un carácter “*”, que es equivalente a dar márgenes de error iguales de suma y resta.

 Unidad de Fecha d w m y
 Descripción Días Semanas Meses Años
 Unidad de Fecha S M H
 Descripción Segundos Minutos Horas

Ejemplo: Para seleccionar cualquier mensaje de hace dos semanas alrededor del 15 de enero de 2001, usaría el siguiente patrón:

Limitar a mensajes coincidentes: ~d 15/1/2001*2w

Es posible dar múltiples márgenes de error:

que se acumulan: ~d 1/1/2001-1w+2w*3d
Fechas Relativas
Este tipo de fecha es relativo a la fecha actual y se puede especificar como:
• “<offset” para mensajes más nuevos que offset unidades
• “=offset” para mensajes exactamente offset unidades de antigüedad
• “>offset” para mensajes más antiguos que offset unidades

offset se especifica como un número positivo con una de las unidades de la tabla “Unidades de Fecha”.

Ejemplo: Para seleccionar mensajes de hace menos de 1 mes, usaría:

Limitar a mensajes coincidentes: ~d <1m

Nota: Todas las fechas utilizadas al buscar son relativas a la zona horaria local, por lo que a menos que cambie la configuración de su $index_format para incluir un formato “%[...]”, estas no son las fechas que se muestran en el índice principal.

VARIABLES DE CONFIGURACION

abort_backspace
Tipo: booleano
Por defecto: yes
Si está activado, presionar retroceso en un aviso vacío cancela el aviso.
abort_key
Tipo: cadena
Por defecto: "007"
Especifica la tecla que se puede usar para cancelar avisos. El formato es el mismo que se usa en i
n "bind" comandos. El valor predeterminado es equivalente a "Ctrl-G". Tenga en cuenta que la tecla especificada no debe usarse en otros enlaces, ya que la operación de abortar tiene mayor prioridad y el enlace no tendrá el efecto deseado.
Ejemplo: 
set abort_key = "<Esc>"
Tenga en cuenta que al usar <Esc> como tecla de abortar, también puede desear establecer la variable de entorno ESCDELAY a un valor bajo o incluso 0, lo que reducirá el tiempo que ncurses espera para distinguir las pulsaciones singulares de la tecla <Esc> del inicio de una secuencia de escape del terminal. El tiempo predeterminado es de 1000 milisegundos y, por lo tanto, bastante notable.
abort_noattach
Tipo: quadoption
Predeterminado: no
Si se establece en sí, al componer mensajes que contienen la expresión regular especificada por $abort_noattach_regex y no se proporcionan adjuntos, se abortará la composición. Si se establece en no, la composición de mensajes como tal nunca se abortará.
Ejemplo: 
set abort_noattach_regex = "\\<attach(|ed|ments?)\\>"
abort_noattach_regex
Tipo: expresión regular
Predeterminado: "\<(attach|attached|attachments?)\>"
Especifica una expresión regular para comparar con el cuerpo del mensaje, para determinar si se mencionó un adjunto pero se olvidó por error. Si coincide, se consultará $abort_noattach para determinar si se abortará el envío del mensaje.
Al igual que otras expresiones regulares en NeoMutt, la búsqueda distingue entre mayúsculas y minúsculas si el patrón contiene al menos una letra mayúscula, y no distingue entre mayúsculas y minúsculas en caso contrario.
abort_nosubject
Tipo: quadoption
Predeterminado: preguntar-sí
Si se establece en sí, al componer mensajes y no se proporciona asunto en el aviso de asunto, se abortará la composición. Si se establece en no, la composición de mensajes sin asunto proporcionado en el aviso de asunto nunca se abortará.
abort_unmodified
Tipo: quadoption
Predeterminado: sí
Si se establece en sí, la composición se abortará automáticamente después de editar el cuerpo del mensaje si no se realizan cambios en el archivo (esta verificación solo ocurre después de la primera edición del archivo). Cuando se establece en no, la composición nunca se abortará.
account_command
Tipo: comando
Predeterminado: ""
Si se establece, este comando se utiliza para recuperar credenciales de cuenta. El comando se invoca pasando una serie de argumentos --clave valor con los detalles de la cuenta a buscar. El comando escribe en la salida estándar una serie de líneas clave: valor. Los argumentos admitidos actualmente son --hostname, --username y --type, donde type puede ser cualquiera de imap, imaps, pop, pops, smtp, smtps, nntp y nntps. Las líneas de salida admitidas actualmente son login, username y password.
alias_file
Tipo: ruta
Predeterminado: "~/.neomuttrc"
El archivo predeterminado en el que se guardarán las alias creadas por la función <create-alias>. Las entradas agregadas a este archivo se codifican en el conjunto de caracteres especificado por $config_charset si está establecido o el conjunto de caracteres actual en caso contrario.
Nota: NeoMutt no cargará automáticamente este archivo; debe usar explícitamente el comando "source" para que se ejecute en caso de que esta opción apunte a un archivo de alias dedicado.
El valor predeterminado para esta opción es el archivo neomuttrc actualmente en uso, o "~/.neomuttrc" si no se encontró ningún neomuttrc de usuario.

allow_ansi
Tipo: booleano
Predeterminado: no
Controla si los códigos de color ANSI en los mensajes (y etiquetas de color en mensajes de texto enriquecido) deben interpretarse. Los mensajes que contienen estos códigos son raros, pero si esta opción está establecida, su texto se coloreará en consecuencia. Tenga en cuenta que esto puede anular sus opciones de color, e incluso presentar un problema de seguridad, ya que un mensaje podría incluir una línea como

y darle el mismo color que su color de adjunto (ver también $crypt_timestamp).

assumed_charset

set assumed_charset="iso-2022-jp:euc-jp:shift_jis:utf-8"

attach_charset
Tipo: lista de cadenas
Predeterminado: ""
Esta variable es una lista de esquemas de codificación de caracteres, separados por dos puntos, para los archivos adjuntos de texto. NeoMutt usa esta configuración para adivinar en qué codificación están los archivos que se adjuntan para convertirlos a un conjunto de caracteres adecuado dado en $send_charset.
Si está *desestablecida*, se usará el valor de $charset en su lugar. Por ejemplo, la siguiente configuración funcionaría para el manejo de texto japonés: 
set attach_charset="iso-2022-jp:euc-jp:shift_jis:utf-8"
Nota: para usuarios japoneses, "iso-2022-*" debe ir al principio del valor como se muestra arriba si se incluye.

Supongamos que $external_search_command está establecido en "mairix_filter", y mairix_filter es un script que ejecuta el antiguo pero muy apreciado indexador mairix con los argumentos dados a mairix_filter, en el modo "raw" de mairix, produciendo en la salida estándar una lista de Message-IDs, uno por línea.

imap_fetch_chunk_size
Tipo: número (long)
Valor predeterminado: 0
Cuando se establece en un valor mayor que 0, las nuevas cabeceras se descargarán en grupos de esta cantidad de cabeceras por solicitud. Si tiene un buzón muy grande, esto podría evitar un tiempo de espera y desconexión al abrir el buzón, enviando un FETCH por cada conjunto de esta cantidad de cabeceras, en lugar de un solo FETCH para todas las nuevas cabeceras.
imap_headers
Tipo: cadena
Valor predeterminado: ""
NeoMutt solicita estos campos de cabecera además de las cabeceras predeterminadas ("Date:", "From:", "Sender:", "Subject:", "To:", "Cc:", "Message-Id:", "References:", "Content-Type:", "Content-Description:", "In-Reply-To:", "Reply-To:", "Lines:", "List-Post:", "X-Label:") de los servidores IMAP antes de mostrar el menú de índice. Puede que desee añadir más cabeceras para la detección de spam.
Nota: Esta es una lista separada por espacios, los elementos deben estar en mayúsculas y no contener dos puntos, por ejemplo, "X-BOGOSITY X-SPAM-STATUS" para los campos de cabecera "X-Bogosity:" y "X-Spam-Status:".
imap_idle
Tipo: booleano
Valor predeterminado: no
Cuando está *activado*, NeoMutt intentará usar la extensión IMAP IDLE para comprobar si hay correo nuevo en el buzón actual. Algunos servidores (dovecot fue la inspiración para esta opción) reaccionan mal a la implementación de NeoMutt. Si su conexión parece congelarse periódicamente, intente desactivar esta opción.
imap_keep_alive
Tipo: número
Valor predeterminado: 300
Esta variable especifica el tiempo máximo en segundos que NeoMutt esperará antes de sondear las conexiones IMAP abiertas, para evitar que el servidor las cierre antes de que NeoMutt haya terminado con ellas. El valor predeterminado está muy dentro del tiempo mínimo especificado por RFC (30 minutos) antes de que un servidor pueda hacer esto, pero en la práctica el RFC se viola de vez en cuando. Reduzca este número si se encuentra desconectado de su servidor IMAP debido a inactividad.
imap_list_subscribed
Tipo: booleano
Valor predeterminado: no
Esta variable configura si la navegación por carpetas IMAP buscará solo las carpetas suscritas o todas las carpetas. Esto se puede alternar en el navegador IMAP con la función <toggle-subscribed>.
imap_login
Tipo: cadena
Valor predeterminado: ""
Su nombre de usuario en el servidor IMAP.
Esta variable tiene como valor predeterminado el valor de $imap_user.
imap_oauth_refresh_command
Tipo: comando
Valor predeterminado: ""
El comando a ejecutar para generar un token de actualización OAUTH para autorizar su conexión a su servidor IMAP. Este comando se ejecutará en cada intento de conexión que utilice los mecanismos de autenticación OAUTHBEARER o XOAUTH2. Consulte "oauth" para obtener más detalles.
imap_pass
Tipo: cadena
Valor predeterminado: ""
Especifica la contraseña de su cuenta IMAP. Si no está *configurada*, NeoMutt le pedirá su contraseña cuando invoque la función <imap-fetch-mail> *o intente abrir una carpeta IMAP.
Advertencia: solo debe usar esta opción cuando se encuentre en una máquina bastante segura, ya que el superusuario puede leer su neomuttrc incluso si usted es el único que puede leer el archivo.
imap_passive
Tipo: booleano
Valor predeterminado: sí
Cuando está *activado*, NeoMutt no abrirá nuevas conexiones IMAP para comprobar si hay correo nuevo. NeoMutt solo comprobará si hay correo nuevo a través de las conexiones IMAP existentes. Esto es útil si no desea que se le pida pares de usuario/contraseña al invocar NeoMutt, o si abrir la conexión es lento.
imap_peek
Tipo: booleano
Valor predeterminado: sí
Cuando está *activado*, NeoMutt evitará marcar implícitamente su correo como leído cada vez que descargue un mensaje del servidor. Esto es generalmente bueno, pero puede hacer que cerrar una carpeta IMAP sea un poco más lento. Esta opción existe para apaciguar a los acelerados.
imap_pipeline_depth
Tipo: número
Valor predeterminado: 15
Controla el número de comandos IMAP que pueden estar en cola antes de ser enviados al servidor. Una tubería más profunda reduce la cantidad de tiempo que NeoMutt debe esperar al servidor y puede hacer que los servidores IMAP se sientan mucho más receptivos. Pero no todos los servidores manejan correctamente los comandos en tubería, por lo que si tiene problemas, podría intentar establecer esta variable en 0.
Nota: Los cambios en esta variable no tienen efecto en las conexiones abiertas.
imap_poll_timeout
Tipo: número
Valor predeterminado: 15
Esta variable especifica el tiempo máximo en segundos que NeoMutt esperará una respuesta al sondear las conexiones IMAP en busca de correo nuevo, antes de que se agote el tiempo de espera y se cierre la conexión. Establézcalo en 0 para deshabilitar el tiempo de espera.
imap_qresync
Tipo: booleano
Valor predeterminado: no
Cuando está *activado*, NeoMutt utilizará la extensión QRESYNC (RFC7162) si es anunciada por el servidor. La implementación actual de NeoMutt es básica, utilizada solo para la descarga inicial de mensajes y actualizaciones de banderas.
Nota: esta función está actualmente en fase experimental. Si experimenta un comportamiento extraño, como mensajes duplicados o faltantes, por favor, envíe un informe de error para informarnos.
imap_rfc5161
Tipo: booleano
Valor predeterminado: sí
Cuando está *activado*, NeoMutt utilizará la extensión IMAP ENABLE (RFC5161) para seleccionar CAPABILITIES. Algunos servidores (notablemente Coremail System IMap Server) no responden correctamente a los comandos ENABLE, lo que podría hacer que NeoMutt se cuelgue. Si su conexión parece congelarse al iniciar sesión, intente desactivar esta opción. Véase también https://github.com/neomutt/neomutt/issues/1689
imap_send_id
Tipo: booleano
Valor predeterminado: no
Cuando está *activado*, NeoMutt enviará un comando IMAP ID (RFC2971) al servidor al iniciar sesión si este lo anuncia. Este comando proporciona información sobre el cliente IMAP, como "NeoMutt" y la versión actual.
imap_server_noise
Tipo: booleano
Valor predeterminado: sí
Cuando está *activado*, NeoMutt mostrará mensajes de advertencia del servidor IMAP como mensajes de error. Dado que estos mensajes a menudo son inofensivos, o se generan debido a problemas de configuración en el servidor que están fuera del alcance del usuario, es posible que desee suprimirlos en algún momento.
imap_user
Tipo: cadena
Valor predeterminado: ""
El nombre del usuario cuyo correo pretende acceder en el servidor IMAP.
Esta variable tiene como valor predeterminado su nombre de usuario en la máquina local.
implicit_auto_view
Tipo: booleano
Valor predeterminado: no
Si se establece en "sí", NeoMutt buscará una entrada de mailcap con el flag "copiousoutput" activado para *cada* adjunto MIME para el que no tenga un visor interno definido. Si se encuentra dicha entrada, NeoMutt utilizará el visor definido en esa entrada para convertir la parte del cuerpo a formato de texto.

reply_regex
Tipo: expresión regular
Por defecto: ""^((re|aw|sv)(\[[0-9]+\])*:[ \t]*)*""
Una expresión regular utilizada para reconocer mensajes de respuesta al hilar y responder. El valor por defecto corresponde al prefijo latino estándar "Re:".
Este valor puede haber sido localizado por el traductor para su idioma, añadiendo otros prefijos comunes en el idioma. Puede añadir sus propios prefijos añadiendo dentro de "^(re)". Por ejemplo: "^(re|sv)" o "^(re|aw|sv)".
La segunda expresión entre paréntesis coincide con cero o más números entre corchetes que siguen al prefijo, como "Re[1]: ". El corchete izquierdo inicial "\[" significa un carácter de corchete izquierdo literal. Tenga en cuenta que la barra invertida debe duplicarse cuando se usa dentro de una cadena entre comillas dobles en el neomuttrc. "[0-9]+" significa uno o más números. "\]" significa un corchete derecho literal. Finalmente, toda la expresión entre paréntesis tiene un sufijo "*", lo que significa que puede ocurrir cero o más veces.
La última parte coincide con dos puntos seguidos de un espacio o tabulación opcional. Tenga en cuenta que "\t" se convierte en una tabulación literal dentro de una cadena entre comillas dobles. Si usa una cadena entre comillas simples, tendría que escribir un carácter de tabulación real y necesitaría convertir las barras invertidas dobles en barras invertidas simples.
Nota: el resultado de esta coincidencia de regex contra el asunto se almacena en la caché de encabezados. Mutt no es lo suficientemente inteligente como para invalidar una entrada de caché de encabezados basándose en el cambio de $reply_regex, por lo que si no ve valores correctos en el índice, intente desactivar temporalmente la caché de encabezados. Si eso soluciona el problema, entonces una vez que la variable esté configurada a su gusto, elimine sus archivos de caché de encabezados obsoletos y vuelva a activar la caché de encabezados.

Tipo: booleano
Por defecto: no
Si está activado, los archivos de borrador (especificados con -H en la línea de comandos) se procesan de manera similar a cuando se reanuda un mensaje pospuesto. No se solicita a los destinatarios; no se evalúan los send-hooks; no se produce ninguna expansión de alias; no se añaden encabezados definidos por el usuario ni firmas al mensaje.

Tipo: booleano
Por defecto: sí

La primera vez que se guarda un archivo de borrador, NeoMutt añadirá un encabezado, X-Mutt-Resume-Draft, al archivo guardado. La próxima vez que se lea el archivo de borrador, si NeoMutt ve el encabezado, configurará $resume_draft_files.
Esta opción está diseñada para evitar que se apliquen múltiples firmas, encabezados definidos por el usuario y otros efectos de procesamiento varias veces al archivo de borrador.
reverse_alias
Tipo: booleano
Por defecto: no
Esta variable controla si NeoMutt mostrará o no el nombre "personal" de sus alias en el menú de índice si encuentra un alias que coincide con el remitente del mensaje. Por ejemplo, si tiene el siguiente alias: 
alias juser abd30425@somewhere.net (Joe User)
y luego recibe un correo que contiene el siguiente encabezado: 
From: abd30425@somewhere.net
Se mostraría en el menú de índice como "Joe User" en lugar de "abd30425@somewhere.net". Esto es útil cuando la dirección de correo electrónico de la persona no es amigable para los humanos.
reverse_name
Tipo: booleano
Por defecto: no
A veces puede ocurrir que reciba un correo en una máquina determinada, mueva los mensajes a otra máquina y responda a algunos de los mensajes desde allí. Si esta variable está activada, la línea From: por defecto de los mensajes de respuesta se construye utilizando la dirección donde recibió los mensajes a los que está respondiendo, si esa dirección coincide con sus "alternates". Si la variable está desactivada, o la dirección que se usaría no coincide con sus "alternates", la línea From: usará su dirección en la máquina actual.
Ver también el comando "alternates" y $reverse_real_name.
reverse_real_name
Tipo: booleano
Por defecto: sí
Esta variable ajusta el comportamiento de la característica $reverse_name.
Cuando está desactivada, NeoMutt eliminará la parte del nombre real de una dirección coincidente. Esto permite usar la dirección de correo electrónico sin tener que usar también lo que el remitente puso en el campo del nombre real.
Cuando está activada, NeoMutt usará la dirección coincidente tal cual.
En cualquier caso, un nombre real ausente se rellenará posteriormente utilizando el valor de $real_name.
rfc2047_parameters
Tipo: booleano
Por defecto: sí
Cuando esta variable está activada, NeoMutt decodificará los parámetros MIME codificados según RFC2047. Querrá activar esta variable cuando NeoMutt le sugiera que S
adjuntos de archivos con nombres como: 
=?iso-8859-1?Q?file=5F=E4=5F991116=2Ezip?=
=?utf-8?Q?z=C4=99ta.png?=
Cuando esta variable se establece interactivamente, el cambio no será efectivo hasta que cambies de carpeta.
Ten en cuenta que este uso de la codificación de RFC2047 está explícitamente prohibido por el estándar, pero sin embargo se encuentra en la práctica y es producido por, por ejemplo, Outlook.
También ten en cuenta que establecer este parámetro *no* tendrá el efecto de que NeoMutt genere este tipo de codificación. En cambio, NeoMutt utilizará incondicionalmente la codificación especificada en RFC2231.

Tipo: lista de cadenas
Por defecto: "us-ascii:iso-8859-1:utf-8"
Una lista de juegos de caracteres delimitada por dos puntos para mensajes salientes. NeoMutt utilizará el primer juego de caracteres en el que el texto pueda ser convertido exactamente. sendmail
Tipo: comando
Por defecto: "/usr/sbin/sendmail -oem -oi"
Especifica el programa y los argumentos utilizados para entregar el correo enviado por NeoMutt. NeoMutt espera que el programa especificado interprete los argumentos adicionales como direcciones de destinatarios. NeoMutt añade todos los destinatarios después de añadir un delimitador -- (si no está ya presente). Flags adicionales, como para $use_8bit_mime, $use_envelope_from, $dsn_notify, o $dsn_return se añadirán antes del delimitador.
Nota: Este comando se invoca de manera diferente a la mayoría de los otros comandos en NeoMutt. Se tokeniza por espacios y se invoca directamente a través de execvp(3) con una matriz de argumentos, por lo que los comandos o argumentos con espacios en ellos no son compatibles. El shell no se utiliza para ejecutar el comando, por lo que las comillas del shell tampoco son compatibles.
Ver también: $write_bcc.
sendmail_wait
Tipo: número
Por defecto: 0
Especifica el número de segundos a esperar a que el proceso $sendmail termine antes de rendirse y poner la entrega en segundo plano.
NeoMutt interpreta el valor de esta variable de la siguiente manera:
>0
número de segundos a esperar a que sendmail termine antes de continuar
0
esperar para siempre a que sendmail termine
<0
poner siempre sendmail en segundo plano sin esperar
Ten en cuenta que si especificas un valor distinto de 0, la salida del proceso hijo se colocará en un archivo temporal. Si hay algún error, se te informará de dónde encontrar la salida.

sidebar_format
Tipo: cadena
Valor predeterminado: "%D%*  %n"
Esta variable te permite personalizar la visualización de la barra lateral. Esta cadena es similar a $index_format, pero tiene su propio conjunto de secuencias tipo printf(3) :
%a

Alerta: 1 si se notifica al usuario de nuevo correo

%B

Nombre del buzón

%d
* @ Número de mensajes eliminados en el buzón
%D

Nombre descriptivo del buzón

%F
* Número de mensajes marcados en el buzón
%L
* @ Número de mensajes después de limitar
%n

"N" si el buzón tiene correo nuevo, " " (espacio) en caso contrario

%N
* Número de mensajes no leídos en el buzón (vistos o no vistos)
%o
* Número de mensajes antiguos en el buzón (no leídos, vistos)
%p

Sondeo: 1 si se comprueba si el buzón tiene correo nuevo

%r
* Número de mensajes leídos en el buzón (leídos, vistos)
%S
* Tamaño del buzón (número total de mensajes)
%t
* @ Número de mensajes etiquetados en el buzón
%Z
* Número de mensajes nuevos en el buzón (no leídos, no vistos)
%!

"!" : un mensaje marcado; "!!" : dos mensajes marcados; "n!" : n mensajes marcados (para n > 2). En caso contrario, no imprime nada.

%>X

Justifica a la derecha el resto de la cadena y rellena con "X"

%|X

Rellena hasta el final de la línea con "X"

%*X

Relleno suave con el carácter "X" como relleno

* = Se puede imprimir opcionalmente si es distinto de cero
@ = Solo aplicable a la carpeta actual
Para usar %S, %N, %F y %!, $mail_check_stats debe estar *establecido*. Cuando esté establecido de esta manera, un valor sugerido para esta opción es "%B%<F? [%F]>%* %<N?%N/>%S".

* = se puede imprimir opcionalmente si es distinto de cero
Algunas de las secuencias anteriores se pueden utilizar para imprimir opcionalmente una cadena si su valor es distinto de cero. Por ejemplo, es posible que solo desees ver el número de mensajes marcados si dichos mensajes existen, ya que cero no es particularmente significativo. Para imprimir opcionalmente una cadena basándose en una de las secuencias anteriores, se utiliza la siguiente construcción:
%<sequence_char?optional_string>
donde sequence_char es un carácter de la tabla anterior y optional_string es la cadena que te gustaría imprimir si sequence_char es distinto de cero. optional_string puede contener otras secuencias, así como texto normal.
Aquí tienes un ejemplo que ilustra cómo imprimir opcionalmente el número de mensajes nuevos en un buzón:
%<n?%n mensajes nuevos>
También puedes alternar entre dos cadenas utilizando la siguiente construcción:
%<sequence_char?if_string&else_string>
Si el valor de sequence_char es distinto de cero, se expandirá if_string, de lo contrario se expandirá else_string.
Como otro ejemplo, aquí se muestra cómo mostrar $sort y $sort_aux o $use_threads y $sort, basándose en si los hilos están habilitados con $use_threads:
%<T?%s/%S&%T/%s>
Puedes forzar que el resultado de cualquier secuencia similar a printf(3) se convierta a minúsculas prefijando el carácter de secuencia con un guion bajo ("_"). Por ejemplo, si deseas mostrar el nombre de host local en minúsculas, utilizarías: "%_h".
Si prefijas el carácter de secuencia con un dos puntos (":"), NeoMutt reemplazará los puntos en la expansión por guiones bajos. Esto puede ser útil con carpetas IMAP a las que no les gustan los puntos en los nombres de las carpetas.

Controla el formato del título del icono, siempre que "$ts_enabled" esté configurado. Esta cadena es idéntica en formato a la utilizada por "$status_format".
ts_status_format
Tipo: cadena
Predeterminado: "NeoMutt con %<m?%m mensajes&sin mensajes>%<n? [%n NUEVO]>"
Controla el formato de la línea de estado de la terminal (o título de la ventana), siempre que "$ts_enabled" se haya configurado. Esta cadena es idéntica en formato a la utilizada por "$status_format".
tunnel
Tipo: comando
Predeterminado: ""
Establecer esta variable hará que NeoMutt abra una tubería a un comando en lugar de un socket crudo. Es posible que pueda usar esto para configurar conexiones preautenticadas a su servidor IMAP/POP3/SMTP. Ejemplo: 
set tunnel="ssh -q mailhost.net /usr/local/libexec/imapd"
Nota: Para que este ejemplo funcione, debe poder iniciar sesión en la máquina remota sin tener que introducir una contraseña.
Cuando está configurado, NeoMutt utiliza la tubería para todas las conexiones remotas. Consulte "account-hook" en el manual para saber cómo utilizar diferentes comandos de tubería por conexión.
tunnel_is_secure
Tipo: booleano
Predeterminado: sí
Cuando está configurado, NeoMutt asumirá que la conexión $tunnel no necesita STARTTLS. También permitirá que las respuestas del servidor IMAP PREAUTH dentro de una tubería procedan. Esto es apropiado si $tunnel utiliza ssh o invoca directamente el servidor localmente.
Cuando está desconfigurado, NeoMutt negociará STARTTLS de acuerdo con las variables $ssl_starttls y $ssl_force_tls. Si $ssl_force_tls está configurado, NeoMutt abortará la conexión si un servidor IMAP responde con PREAUTH. Esta configuración es apropiada si $tunnel no proporciona seguridad y podría ser manipulada por atacantes.
uncollapse_jump
Tipo: booleano
Predeterminado: no
Cuando está configurado, NeoMutt saltará al siguiente mensaje no leído, si lo hay, cuando el hilo actual se despliegue.
uncollapse_new
Tipo: booleano
Predeterminado: sí
Cuando está configurado, NeoMutt desplegará automáticamente cualquier hilo colapsado que reciba un mensaje entregado recientemente. Cuando está desconfigurado, los hilos colapsados permanecerán colapsados. Sin embargo, la presencia del mensaje entregado recientemente afectará la ordenación del índice.
use_8bit_mime
Tipo: booleano
Predeterminado: no
Advertencia: no configure esta variable a menos que esté utilizando una versión de sendmail que admita el flag -B8BITMIME (como sendmail 8.8.x) o es posible que no pueda enviar correos.
Cuando está configurado, NeoMutt invocará $sendmail con el flag -B8BITMIME al enviar mensajes de 8 bits para habilitar la negociación ESMTP.
use_domain
Tipo: booleano
Predeterminado: sí
Cuando está configurado, NeoMutt calificará todas las direcciones locales (aquellas sin la porción "@host") con el valor de $hostname. Si está desconfigurado, ninguna dirección será calificada.
use_envelope_from
Tipo: booleano
Predeterminado: no
Cuando está configurado, NeoMutt establecerá el remitente del sobre del mensaje. Si $envelope_from_address está configurado, se utilizará como dirección del remitente. Si está desconfigurado, NeoMutt intentará derivar el remitente de la cabecera "From:".
Tenga en cuenta que esta información se pasa al comando sendmail utilizando el interruptor de línea de comandos -f. Por lo tanto, configurar esta opción no es útil si la variable $sendmail ya contiene -f o si el ejecutable al que apunta $sendmail no admite el interruptor -f.
use_from
Tipo: booleano
Predeterminado: sí
Cuando está configurado, NeoMutt generará el campo de cabecera "From:" al enviar mensajes. Si está desconfigurado, no se generará ningún campo de cabecera "From:" a menos que el usuario lo establezca explícitamente usando el comando "my_hdr".
use_ipv6
Tipo: booleano
Predeterminado: sí
Cuando está configurado, NeoMutt buscará direcciones IPv6 de los hosts a los que intenta conectarse. Si esta opción está desconfigurada, NeoMutt se limitará a direcciones IPv4. Normalmente, el valor predeterminado debería funcionar.
use_threads
Tipo: enumeración
Predeterminado: desconfigurado
El estilo de encadenamiento utilizado en el índice. Puede ser "flat" (sin encadenamiento), "threads" (encadenado, con sub-hilos debajo del mensaje raíz) o "reverse" (encadenado, con sub-hilos encima del mensaje raíz). Para mayor comodidad, el valor "yes" es sinónimo de "threads" y "no" es sinónimo de "flat".
Si esta variable nunca se configura, entonces $sort controla si se utiliza el encadenamiento, $sort_aux controla tanto la ordenación de hilos como de sub-hilos, y el uso de <sort-mailbox> para seleccionar hilos afecta solo a $sort. Una vez que esta variable se configura, intentar configurar $sort a un valor que contenga "threads" generará una advertencia, el valor de $sort controla la ordenación entre hilos mientras que $sort_aux controla la ordenación dentro de un hilo, y <sort-mailbox> alterna $use_threads.
Ejemplo: 
set use_threads=yes
Consulte la sección "Usar la función de hilos" para obtener más explicaciones y ejemplos.
user_agent
Tipo: booleano
Predeterminado: no
Cuando está configurado, NeoMutt agregará una cabecera "User-Agent:" a los mensajes salientes, indicando qué versión de NeoMutt se utilizó para componerlos.
virtual_spool_file
Tipo: booleano
Predeterminado: no
Este comando ahora es innecesario. $spool_file se ha ampliado para admitir descripciones de buzones como valor.
Cuando está configurado, NeoMutt utilizará el primer buzón virtual definido (ver virtual-mailboxes) como archivo de carrete.
wait_key
Tipo: booleano
Predeterminado: sí
Controla si NeoMutt le pedirá que presione una tecla después de que se haya invocado un comando externo mediante estas funciones: <shell-escape>, <pipe-message>, <pipe-entry>, <print-message> y <print-entry> comandos.
También se utiliza al ver archivos adjuntos con "auto_view", siempre que la entrada de mailcap correspondiente tenga un flag needsterminal, y el programa externo sea interactivo.
Cuando está configurado, NeoMutt siempre pedirá una tecla. Cuando está desconfigurado, NeoMutt esperará una tecla solo si el comando externo devolvió un estado distinto de cero.
weed
Tipo: booleano
Predeterminado: sí
Cuando está configurado, NeoMutt desyerbará las cabeceras al mostrar, reenviar o responder a los mensajes.
Ver también $copy_decode_weed, $pipe_decode_weed, $print_decode_weed.
wrap
Tipo: número
Predeterminado: 0
Cuando se establece en un valor positivo, NeoMutt ajustará el texto en $wrap caracteres. Cuando se establece en un valor negativo, NeoMutt ajustará el texto para que haya $wrap caracteres de espacio vacío en el lado derecho de la terminal. Establecerlo a cero hace que

NeoMutt wrap at the terminal width.

Also see $reflow_wrap.
wrap_headers
Type: number
Default: 78
This option specifies the number of characters to use for wrapping an outgoing message's headers. Allowed values are between 78 and 998 inclusive.
Note: This option usually shouldn't be changed. RFC5233 recommends a line length of 78 (the default), so please only change this setting when you know what you're doing.
wrap_search
Type: boolean
Default: yes
Controls whether searches wrap around the end.
When set, searches will wrap around the first (or last) item. When unset, incremental searches will not wrap.
write_bcc
Type: boolean
Default: no
Controls whether NeoMutt writes out the "Bcc:" header when preparing messages to be sent. Some MTAs, such as Exim and Courier, do not strip the "Bcc:" header; so it is advisable to leave this unset unless you have a particular need for the header to be in the sent message.
If NeoMutt is set to deliver directly via SMTP(see $smtp_url), this option does nothing: NeoMutt will never write out the "Bcc:" header in this case.
Note this option only affects the sending of messages. Fcc'ed copies of a message will always contain the "Bcc:" header if one exists.
write_inc
Type: number
Default: 10
When writing a mailbox, a message will be printed every $write_inc messages to indicate progress. If set to 0, only a single message will be displayed before writing a mailbox.
Also see the $read_inc, $net_inc and $time_inc variables and the "tuning" section of the manual for performance considerations.
x_comment_to
Type: boolean
Default: no
If set, NeoMutt will add "X-Comment-To:" field (that contains full name of original article author) to article that followuped to newsgroup.
