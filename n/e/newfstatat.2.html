stat(2) Manual de llamadas al sistema stat(2)

NOMBRE

stat, fstat, lstat, fstatat - obtener estado del archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/stat.h>
int stat(const char *restrict ruta,
         struct stat *restrict buf_estado);
int fstat(int fd, struct stat *buf_estado);
int lstat(const char *restrict ruta,
         struct stat *restrict buf_estado);
#include <fcntl.h>           /* Definición de las constantes AT_* */
#include <sys/stat.h>
int fstatat(int fd_dir, const char *restrict ruta,
         struct stat *restrict buf_estado, int flags);

DESCRIPCIÓN

Estas funciones devuelven información sobre un archivo, en el búfer apuntado por buf_estado. No se requieren permisos en el archivo en sí, pero—en el caso de stat(), fstatat(), y lstat()—se requiere permiso de ejecución (búsqueda) en todos los directorios en ruta que conducen al archivo.

stat() y fstatat() recuperan información sobre el archivo apuntado por ruta; las diferencias para fstatat() se describen a continuación.

lstat() es idéntico a stat(), excepto que si ruta es un enlace simbólico, entonces devuelve información sobre el enlace en sí, no sobre el archivo al que se refiere el enlace.

fstat() es idéntico a stat(), excepto que el archivo sobre el cual se debe obtener información se especifica mediante el descriptor de archivo fd.

La estructura stat

Todas estas llamadas al sistema devuelven una estructura stat (ver stat(3type)).

Nota: por razones de rendimiento y simplicidad, diferentes campos en la estructura stat pueden contener información de estado de diferentes momentos durante la ejecución de la llamada al sistema. Por ejemplo, si st_mode o st_uid son modificados por otro proceso llamando a chmod(2) o chown(2), stat() podría devolver el st_mode antiguo junto con el nuevo st_uid, o el st_uid antiguo junto con el nuevo st_mode.

fstatat()

La llamada al sistema fstatat() es una interfaz más general para acceder a la información del archivo que aún puede proporcionar exactamente el comportamiento de cada una de stat(), lstat(), y fstat().

Si ruta es relativa, entonces se interpreta en relación con el directorio al que se refiere el descriptor de archivo fd_dir (en lugar de en relación con el directorio de trabajo actual del proceso que llama, como lo hace stat() y lstat() para un nombre de ruta relativo).

Si ruta es relativa y fd_dir es el valor especial AT_FDCWD, entonces ruta se interpreta en relación con el directorio de trabajo actual del proceso que llama (como stat() y lstat()).

Si ruta es absoluta, entonces se ignora fd_dir.

flags puede ser 0, o incluir una o más de las siguientes banderas ORadas:

AT_EMPTY_PATH (desde Linux 2.6.39)
Si ruta es una cadena vacía (o NULL, desde Linux 6.11) opera en el archivo al que se refiere fd_dir (que puede haber sido obtenido usando la bandera O_PATH de open(2)). En este caso, fd_dir puede referirse a cualquier tipo de archivo, no solo a un directorio, y el comportamiento de fstatat() es similar al de fstat(). Si fd_dir es AT_FDCWD, la llamada opera en el directorio de trabajo actual. Esta bandera es específica de Linux; define _GNU_SOURCE para obtener su definición.
AT_NO_AUTOMOUNT (desde Linux 2.6.38)
No montar automáticamente el componente terminal ("nombre base") de ruta. Desde Linux 3.1 esta bandera se ignora. Desde Linux 4.11 esta bandera está implícita.
AT_SYMLINK_NOFOLLOW
Si ruta es un enlace simbólico, no lo desreferencie: en su lugar, devuelva información sobre el enlace en sí, como lstat(). (Por defecto, fstatat() desreferencia enlaces simbólicos, como stat().)

Ver openat(2) para una explicación de la necesidad de fstatat().

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y se establece la variable errno para indicar el error.

ERRORES

EACCES
Se deniega el permiso de búsqueda en uno de los directorios del prefijo de ruta de ruta. (Ver también path_resolution(7).)
EBADF
fd no es un descriptor de archivo abierto válido.
EBADF
(fstatat()) ruta es relativa pero fd_dir no es AT_FDCWD ni un descriptor de archivo válido.
EFAULT
Dirección inválida.
EINVAL
(fstatat()) Bandera inválida especificada en flags.
ELOOP
Se encontraron demasiados enlaces simbólicos al recorrer la ruta.
ENAMETOOLONG
ruta es demasiado larga.
ENOENT
Un componente de ruta no existe o es un enlace simbólico colgante.
ENOENT
ruta es una cadena vacía y AT_EMPTY_PATH no fue especificado en flags.
ENOMEM
Memoria agotada (es decir, memoria del kernel).
ENOTDIR
Un componente del prefijo de ruta de ruta no es un directorio.
ENOTDIR
(fstatat()) ruta es relativa y fd_dir es un descriptor de archivo que se refiere a un archivo que no es un directorio.
EOVERFLOW
ruta o fd se refiere a un archivo cuyo tamaño, número de inodo o número de bloques no se puede representar en, respectivamente, los tipos off_t, ino_t, o blkcnt_t. Este error puede ocurrir cuando, por ejemplo, una aplicación compilada en una plataforma de 32 bits sin -D_FILE_OFFSET_BITS=64 llama a stat() en un archivo cuyo tamaño excede (1<<31)-1 bytes.

stat(2) - Manual de Linux

SYNOPSIS

#include <sys/types.h> #include <sys/stat.h> #include <unistd.h>

int stat(const char *pathname, struct stat *statbuf);

int fstat(int fd, struct stat *statbuf);

int lstat(const char *pathname, struct stat *statbuf);

int statx(int dirfd, const char *pathname, int flags, unsigned int mask, struct statx *statxbuf);

Link with -lrt (for statx).

DESCRIPTION

The stat() function shall return information about a file. It shall fill the structure pointed to by statbuf with the status information of the file that the pathname argument points to.

The fstat() function shall be equivalent to stat(), but the file shall be the one whose file descriptor is fd.

The lstat() function shall be identical to stat() except that if pathname is a symbolic link, then it shall return information about the link itself rather than the file the link refers to.

The statx() function is a newer, more flexible function that can retrieve extended file information. It takes a directory file descriptor (dirfd), a path (pathname), flags, a mask specifying which fields to retrieve, and a pointer to a statx structure.

The stat structure contains at least the following fields:

st_mode
File's data and permissions.
st_ino
Inode number.
st_dev
ID of the device containing the file.
st_nlink
Number of hard links to the file.
st_uid
User ID of the file's owner.
st_gid
Group ID of the file's group.
st_size
Total size, in bytes, of the file.
st_atime
Time of last access.
st_mtime
Time of last modification.
st_ctime
Time of last status change.
st_blocks
Number of blocks allocated for this file.
st_blksize
Recommended I/O block size for this file.

The interpretation of st_mode, st_atime, st_mtime, and st_ctime is described in inode(7). The values of st_blocks and st_blksize are implementation-dependent.

The statx structure is more extensible and can contain a wider range of information than the older stat structure.

RETURN VALUE

On success, zero is returned. On failure, -1 is returned, and errno is set to indicate the error.

ERRORS

The stat(), fstat(), and lstat() functions shall fail if:

EACCES
Search permission is denied for any component of the required path prefix.
EBADF
fd is not a valid file descriptor for fstat().
EFAULT
statbuf points to memory that is not a valid part of the user address space.
ELOOP
Too many symbolic links were encountered in resolving pathname.
ENAMETOOLONG
A component of a file name is longer than the system limit, or the entire path name is longer than the system limit.
ENOENT
A component of pathname does not exist, or the pathname argument points to an empty string.
ENOTDIR
A component of the required path prefix is not a directory.
EOVERFLOW
The file contains a value too large to be represented in the relevant structure field.
ETXTBSY
The file is a regular file that is being executed from the network, and the file has been closed by the sender.

The stat() and lstat() functions shall also fail if:

EINVAL
An invalid value was specified for the pathname argument.
ENOMEM
Insufficient kernel memory was available to perform the operation.
ENOSYS
The implementation does not support this function.
ERANGE
A file size is too large to be represented in the structure.

The fstat() function shall also fail if:

EINVAL
fd refers to a file that is not a regular file, or if fd is invalid.

The statx() function may fail with:

EINVAL
An invalid value was specified for dirfd, pathname, flags, or mask.
ELOOP
Too many symbolic links were encountered in resolving pathname.
ENAMETOOLONG
A component of a file name is longer than the system limit, or the entire path name is longer than the system limit.
ENOENT
A component of pathname does not exist, or the pathname argument points to an empty string.
ENOTDIR
A component of the required path prefix is not a directory.
EOVERFLOW
The file contains a value too large to be represented in the relevant structure field.
EACCES
Search permission is denied for any component of the required path prefix.
ENOSPC
The requested information is not available.
ENOMEM
Insufficient kernel memory was available to perform the operation.
EBADF
dirfd is not a valid file descriptor.

STANDARDS

POSIX.1-2008. The statx() function is a Linux extension.

HISTORY

The stat(), fstat(), and lstat() functions first appeared in Version 1 AT&T UNIX.

The statx() function was introduced in Linux kernel 4.11.

POSIX.1-2008 specifies that lstat() should return valid information in all fields except the mode bits in st_mode. The use of the st_blocks and st_blksize fields may be less portable.

On 32-bit platforms, there have been different versions of the stat() system call over time to accommodate increases in the size of the stat structure. These include sys_stat(), sys_newstat(), and sys_stat64(). The glibc wrapper function hides these details. On modern 64-bit systems, there is a single stat() system call.

The underlying system call for the glibc fstatat() wrapper function is typically fstatat64() or newfstatat().

C LIBRARY/KERNEL DIFFERENCES

Over time, increases in the size of the stat structure have led to three successive versions of stat(): sys_stat() (slot __NR_oldstat), sys_newstat() (slot __NR_stat), and sys_stat64() (slot __NR_stat64) on 32-bit platforms such as i386. The first two versions were already present in Linux 1.0 (albeit with different names); the last was added in Linux 2.4. Similar remarks apply for fstat() and lstat().

The kernel-internal versions of the stat structure dealt with by the different versions are, respectively:

__old_kernel_stat
The original structure, with rather narrow fields, and no padding.
stat
Larger st_ino field and padding added to various parts of the structure to allow for future expansion.
stat64
Even larger st_ino field, larger st_uid and st_gid fields to accommodate the Linux-2.4 expansion of UIDs and GIDs to 32 bits, and various other enlarged fields and further padding in the structure. (Various padding bytes were eventually consumed in Linux 2.6, with the advent of 32-bit device IDs and nanosecond components for the timestamp fields.)

The glibc stat() wrapper function hides these details from applications, invoking the most recent version of the system call provided by the kernel, and repacking the returned information if required for old binaries.

On modern 64-bit systems, life is simpler: there is a single stat() system call and the kernel deals with a stat structure that contains fields of a sufficient size.

The underlying system call employed by the glibc fstatat() wrapper function is actually called fstatat64() or, on some architectures, newfstatat().

EXAMPLES

The following program calls lstat() and displays selected fields in the returned stat structure.

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <sys/sysmacros.h>
#include <time.h>
int
main(int argc, char *argv[])
{
    struct stat sb;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s <path>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    if (lstat(argv[1], &sb) == -1) {
        perror("lstat");
        exit(EXIT_FAILURE);
    }
    printf("ID of containing device:  [%x,%x]\n",
           major(sb.st_dev),
           minor(sb.st_dev));
    printf("File type:                ");
    switch (sb.st_mode & S_IFMT) {
    case S_IFBLK:  printf("block device\n");            break;
    case S_IFCHR:  printf("character device\n");        break;
    case S_IFDIR:  printf("directory\n");               break;
    case S_IFIFO:  printf("FIFO/pipe\n");               break;
    case S_IFLNK:  printf("symlink\n");                 break;
    case S_IFREG:  printf("regular file\n");            break;
    case S_IFSOCK: printf("socket\n");                  break;
    default:       printf("unknown?\n");                break;
    }
    printf("I-node number:            %ju\n", (uintmax_t) sb.st_ino);
    printf("Mode:                     %jo (octal)\n",
           (uintmax_t) sb.st_mode);
    printf("Link count:               %ju\n", (uintmax_t) sb.st_nlink);
    printf("Ownership:                UID=%ju   GID=%ju\n",
           (uintmax_t) sb.st_uid, (uintmax_t) sb.st_gid);
    printf("Preferred I/O block size: %jd bytes\n",
           (intmax_t) sb.st_blksize);
    printf("File size:                %jd bytes\n",
           (intmax_t) sb.st_size);
    printf("Blocks allocated:         %jd\n",
           (intmax_t) sb.st_blocks);
    printf("Last status change:       %s", ctime(&sb.st_ctime));
    printf("Last file access:         %s", ctime(&sb.st_atime));
    printf("Last file modification:   %s", ctime(&sb.st_mtime));
    exit(EXIT_SUCCESS);
}
