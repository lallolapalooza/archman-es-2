NOMBRE

nethsm-key-import - Importar una clave

SINOPSIS

nethsm key import [--format] [-k|--key-id] [-t|--tags] [-a|--auth-passphrase-file] [-c|--config] [-l|--label] [-u|--user] [-h|--help] <TIPO_CLAVE> <DATOS_CLAVE> [MECANISMOS_CLAVE]

DESCRIPCIÓN

Importar una clave

Los datos de la clave proporcionada deben ser una clave privada PKCS#8 en formato codificado ASN.1 Distinguished Encoding Rules (DER) o Privacy-Enhanced Mail (PEM). Los datos de la clave deben coincidir con el tipo de clave proporcionado.

El tipo de clave proporcionado y la lista de mecanismos de clave deben coincidir: * "Rsa" requiere uno de [RsaDecryptionRaw, RsaDecryptionPkcs1, RsaDecryptionOaepMd5, RsaDecryptionOaepSha1, RsaDecryptionOaepSha224, RsaDecryptionOaepSha256, RsaDecryptionOaepSha384, RsaDecryptionOaepSha512, RsaSignaturePkcs1, RsaSignaturePssMd5, RsaSignaturePssSha1, RsaSignaturePssSha224, RsaSignaturePssSha256, RsaSignaturePssSha384, RsaSignaturePssSha512] * "Curve25519" requiere uno de [EdDsaSignature] * "EcP256", "EcP384" y "EcP521" requieren uno de [EcdsaSignature] * "Generic" requiere al menos uno de [AesDecryptionCbc, AesEncryptionCbc]

Los usuarios a nivel de sistema con el rol "Administrador" importan claves a nivel de sistema. Los usuarios con espacio de nombres y el rol "Administrador" importan claves en su propio espacio de nombres.

Nota: Aunque la asignación de etiquetas a la nueva clave es opcional, se recomienda encarecidamente, ya que de lo contrario, ¡todos los usuarios en el mismo ámbito tendrán acceso a ella!

Requiere la autenticación de un usuario con el rol "Administrador".

OPCIONES

--format <FORMATO> [por defecto: Der]
El formato de la clave a importar

Las claves se pueden importar en formato Distinguished Encoding Rules (DER) o Privacy-Enhanced Mail (PEM).

Uno de ["Pem", "Der"].

También se puede especificar con la variable de entorno NETHSM_KEY_FORMAT.
-k, --key-id <ID_CLAVE>
Un ID único opcional asignado a la clave importada

Si no se proporciona uno, se genera uno genérico para la clave.

También se puede especificar con la variable de entorno NETHSM_KEY_ID.
-t, --tags <ETIQUETAS>
Una lista opcional de etiquetas asignadas a la clave importada

Las etiquetas en las claves se utilizan para conceder acceso a esas claves a los usuarios que portan las mismas etiquetas.

También se puede especificar con la variable de entorno NETHSM_KEY_TAGS.
-a, --auth-passphrase-file <ARCHIVO_CONTRASEÑA>
La ruta a un archivo que contiene una contraseña para la autenticación

La contraseña proporcionada en el archivo debe ser la del usuario elegido para el comando.

Esta opción se puede proporcionar varias veces, lo cual es necesario para comandos que requieren múltiples roles a la vez. Con múltiples archivos de contraseña, el orden importa, ya que los archivos se asignan al usuario respectivo proporcionado por la opción "--user".

También se puede especificar con la variable de entorno NETHSM_AUTH_PASSPHRASE_FILE.
-c, --config <CONFIG>
La ruta a un archivo de configuración personalizado

Si se especifica, se utiliza el archivo de configuración personalizado en lugar de la ubicación predeterminada del archivo de configuración.

También se puede especificar con la variable de entorno NETHSM_CONFIG.
-l, --label <ETIQUETA>
Una etiqueta que identifica de forma única un dispositivo en el archivo de configuración

Debe proporcionarse si hay más de un dispositivo configurado en el archivo de configuración.

También se puede especificar con la variable de entorno NETHSM_LABEL.
-u, --user <USUARIO>
Un nombre de usuario que se utiliza para un comando

Se puede proporcionar si no hay ningún nombre de usuario configurado en el archivo de configuración para un dispositivo. Debe proporcionarse si hay varios nombres de usuario del mismo rol de destino configurados en el archivo de configuración para un dispositivo.

Esta opción se puede proporcionar varias veces, lo cual es necesario para comandos que requieren múltiples roles a la vez.

También se puede especificar con la variable de entorno NETHSM_USER.
-h, --help
Imprimir ayuda (ver un resumen con '-h')
<TIPO_CLAVE>
El tipo de clave a importar

¡El tipo de clave debe coincidir con los datos de clave proporcionados y los mecanismos de clave elegidos!

Uno de ["AesDecryptionCbc", "AesEncryptionCbc", "EcdsaSignature", "EdDsaSignature", "RsaDecryptionOaepMd5", "RsaDecryptionOaepSha1", "RsaDecryptionOaepSha224", "RsaDecryptionOaepSha256", "RsaDecryptionOaepSha384", "RsaDecryptionOaepSha512", "RsaDecryptionPkcs1", "RsaDecryptionRaw", "RsaSignaturePkcs1", "RsaSignaturePssMd5", "RsaSignaturePssSha1", "RsaSignaturePssSha224", "RsaSignaturePssSha256", "RsaSignaturePssSha384", "RsaSignaturePssSha512"].

También se puede especificar con la variable de entorno NETHSM_KEY_TYPE.
<DATOS_CLAVE>
La ruta a una clave privada PKCS#8 en formato DER codificado ASN.1

Los datos de la clave privada deben coincidir con el tipo de clave elegido.

También se puede especificar con la variable de entorno NETHSM_KEY_DATA.
[MECANISMOS_CLAVE]
Los mecanismos proporcionados por la clave importada

¡Los mecanismos de clave deben coincidir con el tipo de clave elegido!

Al menos uno de ["AesDecryptionCbc", "AesEncryptionCbc", "EcdsaSignature", "EdDsaSignature", "RsaDecryptionOaepMd5", "RsaDecryptionOaepSha1", "RsaDecryptionOaepSha224", "RsaDecryptionOaepSha256", "RsaDecryptionOaepSha384", "RsaDecryptionOaepSha512", "RsaDecryptionPkcs1", "RsaDecryptionRaw", "RsaSignaturePkcs1", "RsaSignaturePssMd5", "RsaSignaturePssSha1", "RsaSignaturePssSha224", "RsaSignaturePssSha256", "RsaSignaturePssSha384", "RsaSignaturePssSha512"].

También se puede especificar con la variable de entorno NETHSM_KEY_MECHANISMS.
