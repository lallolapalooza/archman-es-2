SENDMAIL(1) Manual de Comandos Generales SENDMAIL(1)

NOMBRE

sendmail - Interfaz de compatibilidad de Postfix con Sendmail

SINOPSIS

sendmail [opción ...] [destinatario ...]
mailq
sendmail -bp
newaliases
sendmail -I

DESCRIPCIÓN


El comando sendmail(1) de Postfix implementa la interfaz de compatibilidad de Postfix con Sendmail. Por razones de compatibilidad con aplicaciones existentes, se reconocen algunas opciones de línea de comandos de Sendmail pero se ignoran silenciosamente.

Por defecto, sendmail(1) de Postfix lee un mensaje desde la entrada estándar hasta EOF o hasta que lee una línea que solo contiene un carácter ., y organiza su entrega. Postfix sendmail(1) se basa en el comando postdrop(1) para crear un archivo en la cola en el directorio maildrop.

Se proporcionan alias de comandos específicos para otros modos de operación comunes:

mailq
Lista la cola de correo. Cada entrada muestra el ID del archivo de la cola, el tamaño del mensaje, la hora de llegada, el remitente y los destinatarios que aún necesitan ser entregados. Si el correo no pudo ser entregado en el último intento, se muestra el motivo del fallo. La cadena del ID de la cola va seguida de un carácter de estado opcional:
*
El mensaje está en la cola activa, es decir, el mensaje está seleccionado para entrega.
!
El mensaje está en la cola de espera, es decir, no se realizarán más intentos de entrega hasta que el correo se retire de la espera.
#
El mensaje se fuerza a expirar. Consulte las opciones -e o -f de postsuper(1).
Este modo de operación se implementa ejecutando el comando postqueue(1).
newaliases
Inicializa la base de datos de alias. Si no se especifica ningún archivo de entrada (con la opción -oA, véase más abajo), el programa procesa los archivos especificados con el parámetro de configuración alias_database. Si no se especifica ningún tipo de base de datos de alias, el programa utiliza el tipo especificado con el parámetro de configuración default_database_type. Este modo de operación se implementa ejecutando el comando postalias(1).

Nota: Puede pasar un minuto o más hasta que una actualización de la base de datos de alias sea visible. Utilice el comando "postfix reload" para eliminar este retraso.

Estas y otras características se pueden seleccionar especificando la combinación adecuada de opciones de línea de comandos. Algunas características se controlan mediante parámetros en el archivo de configuración main.cf.

Se reconocen las siguientes opciones:

-Am (ignorado)
-Ac (ignorado)
Postfix sendmail utiliza el mismo archivo de configuración independientemente de si un mensaje es una presentación inicial o no.
-B tipo_cuerpo
El tipo MIME del cuerpo del mensaje: 7BIT o 8BITMIME.
-bd
Entrar en modo demonio. Este modo de operación se implementa ejecutando el comando "postfix start".
-bh (ignorado)
-bH (ignorado)
Postfix no tiene una base de datos de estado de host persistente.
-bi
Inicializar base de datos de alias. Consulte el comando newaliases más arriba.
-bl
Entrar en modo demonio. Para aceptar solo conexiones locales como con la opción -bl de Sendmail, especifique "inet_interfaces = loopback" en el archivo de configuración main.cf de Postfix.
-bm
Leer correo desde la entrada estándar y organizar su entrega. Este es el modo de operación por defecto.
-bp
Listar la cola de correo. Consulte el comando mailq más arriba.
-bs
Modo servidor SMTP independiente. Leer comandos SMTP desde la entrada estándar y escribir respuestas en la salida estándar. En el modo servidor SMTP independiente, la retransmisión de correo y otros controles de acceso están deshabilitados por defecto. Para habilitarlos, ejecute el proceso como el usuario mail_owner.

Este modo de operación se implementa ejecutando el demonio smtpd(8).

-bv
No recopilar ni entregar un mensaje. En su lugar, enviar un informe por correo después de verificar cada dirección de destinatario. Esto es útil para probar las configuraciones de reescritura y enrutamiento de direcciones.

Esta característica está disponible en Postfix versión 2.1 y posteriores.

-C archivo_config
-C directorio_config
La ruta del archivo main.cf de Postfix, o de su directorio padre. Esta información se ignora en las versiones de Postfix anteriores a la 2.3.

Con Postfix versión 3.2 y posteriores, se debe autorizar un directorio no predeterminado en el archivo main.cf predeterminado, a través de los parámetros alternate_config_directories o multi_instance_directories.

Con todas las versiones de Postfix, puede especificar una ruta de directorio con la variable de entorno MAIL_CONFIG para anular la ubicación de los archivos de configuración.

-F nombre_completo
Establece el nombre completo del remitente. Esto anula la variable de entorno NAME y solo se utiliza con mensajes que no tienen una cabecera de mensaje From:.
-f remitente
Establece la dirección del remitente del sobre. Esta es la dirección a la que se envían los problemas de entrega. Con las versiones de Postfix anteriores a la 2.1, la cabecera del mensaje Errors-To: anula la dirección de retorno de error.
-G
Presentación de puerta de enlace (retransmisión), en contraposición a la presentación de usuario inicial. O bien no reescribir las direcciones en absoluto, o actualizar las direcciones incompletas con la información de dominio especificada en remote_header_rewrite_domain.

Esta opción se ignora antes de la versión 2.3 de Postfix.

-h contar_saltos (ignorado)
Límite de saltos. Utilice el parámetro de configuración hopcount_limit en su lugar.
-I
Inicializar base de datos de alias. Consulte el comando newaliases más arriba.
-i
Al leer un mensaje desde la entrada estándar, no trate una línea que solo contiene un carácter . como el final de la entrada.
-L etiqueta (ignorado)
La etiqueta de registro. Utilice el parámetro de configuración syslog_name en su lugar.
-m (ignorado)
Compatibilidad hacia atrás.
-N dsn (por defecto: 'delay, failure')
Control de notificación de estado de entrega. Especifique una lista separada por comas con uno o más de: failure (enviar notificación cuando la entrega falla), delay (enviar notificación cuando la entrega se retrasa) o success (enviar notificación cuando el mensaje se entrega); o especifique never (no enviar ninguna notificación).

Esta característica está disponible en Postfix 2.3 y posteriores.

-n (ignorado)
Compatibilidad hacia atrás.
-oAbase_datos_alias
Base de datos de alias no predeterminada. Especifique ruta o tipo:ruta. Consulte postalias(1) para obtener más detalles.
-O opción=valor (ignorado)
Establece la opción nombrada a valor. Utilice el parámetro de configuración equivalente en main.cf en su lugar.
-o7 (ignorado)
-o8 (ignorado)
Para enviar contenido de 8 bits o binario, use un approp

OPCIONES

-B xvalue (ignorado)
Especificar el tipo de encapsulación MIME y seleccionar la opción de línea de comandos -B apropiada.
-oi
Al leer un mensaje de la entrada estándar, no tratar una línea que solo contenga un carácter . como el final de la entrada.
-om (ignorado)
El remitente nunca se elimina de las expansiones de alias, etc.
-o x value (ignorado)
Establecer la opción x en value. Utilice el parámetro de configuración equivalente en main.cf en su lugar.
-r remitente
Establecer la dirección del remitente del sobre. Esta es la dirección a la que se envían los problemas de entrega. Con las versiones de Postfix anteriores a la 2.1, la cabecera del mensaje Errors-To: anula la dirección de retorno de error.
-R retorno
Control de notificación de estado de entrega. Especifique "hdrs" para devolver solo la cabecera cuando un mensaje rebota, "full" para devolver una copia completa (el comportamiento predeterminado).

La opción -R especifica un límite superior; Postfix devolverá solo la cabecera cuando una copia completa exceda la configuración bounce_size_limit.

Esta opción se ignora antes de la versión 2.10 de Postfix.

-q
Intentar entregar todo el correo en cola. Esto se implementa ejecutando el comando postqueue(1).

Advertencia: vaciar el correo no entregable con frecuencia resultará en un bajo rendimiento de entrega de todo el demás correo.

-qintervalo (ignorado)
El intervalo entre ejecuciones de cola. Utilice el parámetro de configuración queue_run_delay en su lugar.
-qIid_cola
Programar la entrega inmediata de correo con el ID de cola especificado. Esta opción se implementa ejecutando el comando postqueue(1) y está disponible a partir de la versión 2.4 de Postfix.
-qRsitio
Programar la entrega inmediata de todo el correo que está en cola para el sitio nombrado. Esta opción solo acepta nombres de sitio que sean elegibles para el servicio de "vaciado rápido" y se implementa ejecutando el comando postqueue(1). Consulte flush(8) para obtener más información sobre el servicio de "vaciado rápido".
-qSsitio
Este comando no está implementado. Utilice el comando más lento "sendmail -q" en su lugar.
-t
Extraer destinatarios de las cabeceras del mensaje. Estos se añaden a los destinatarios especificados en la línea de comandos.

Con las versiones de Postfix anteriores a la 2.1, esta opción requiere que no se especifiquen direcciones de destinatario en la línea de comandos.

-U (ignorado)
Envío inicial de usuario.
-V envid
Especificar el ID del sobre para la notificación por parte de servidores que admiten DSN.

Esta función está disponible en Postfix 2.3 y posteriores.

-XV (Postfix 2.2 y anteriores: -V)
Ruta de retorno de sobre variable. Dada una dirección de remitente de sobre del formulario propietario-lista@origen, cada destinatario usuario@dominio recibe correo con una dirección de remitente de sobre personalizada.

Por defecto, la dirección del remitente de sobre personalizada es propietario-lista+usuario=dominio@origen. Los caracteres predeterminados + y = se pueden configurar con el parámetro de configuración default_verp_delimiters.

-XVxy (Postfix 2.2 y anteriores: -Vxy)
Igual que -XV, pero utiliza x e y como caracteres delimitadores VERP, en lugar de los caracteres especificados con el parámetro de configuración default_verp_delimiters.
-v
Enviar un informe por correo electrónico del primer intento de entrega (versiones de Postfix 2.1 y posteriores). La entrega de correo siempre ocurre en segundo plano. Cuando se proporcionan varias opciones -v, se activa el registro detallado para fines de depuración.
-X archivo_registro (ignorado)
Registrar el tráfico del agente de correo. Utilice los parámetros de configuración debug_peer_list y debug_peer_level en su lugar.

SEGURIDAD

Por diseño, este programa no tiene el id de usuario (o grupo) establecido. Está preparado para manejar contenido de mensajes de usuarios no confiables, posiblemente remotos.

Sin embargo, como la mayoría de los programas de Postfix, este programa no impone una política de seguridad en sus argumentos de línea de comandos. En su lugar, depende del sistema UNIX para imponer políticas de acceso basadas en los IDs de usuario y grupo efectivos del proceso. Concretamente, esto significa que ejecutar comandos de Postfix como root (desde sudo o equivalente) en nombre de un usuario que no sea root probablemente creará oportunidades de escalada de privilegios.

Si una aplicación ejecuta programas de Postfix en nombre de usuarios que no tienen acceso normal de shell a los comandos de Postfix, entonces esa aplicación DEBE restringir los argumentos de línea de comandos especificados por el usuario para evitar la escalada de privilegios.

  • Filtrar todos los argumentos de línea de comandos, por ejemplo, argumentos que contienen una ruta de acceso o que especifican un método de acceso a base de datos. Estas comprobaciones de ruta de acceso deben rechazar enlaces simbólicos o duros controlados por el usuario a archivos sensibles y no deben ser vulnerables a ataques de concurrencia TOCTOU.
  • Deshabilitar el procesamiento de opciones de comandos para todos los argumentos de comando que contengan datos especificados por el usuario. Por ejemplo, la línea de comandos del comando Postfix sendmail(1) DEBE estructurarse de la siguiente manera: 
        /ruta/a/sendmail argumentos_del_sistema -- argumentos_del_usuario

    Aquí, el "--" deshabilita el procesamiento de opciones de comando para todos los argumentos_del_usuario que siguen.

Sin el "--", un usuario malintencionado podría habilitar las opciones de comando del comando Postfix sendmail(1), al especificar una dirección de correo electrónico que comience con "-".

DIAGNÓSTICO


Los problemas se registran en syslogd(8) o postlogd(8), y en el flujo de error estándar.

AMBIENTE

MAIL_CONFIG
Directorio con los archivos de configuración de Postfix.
MAIL_VERBOSE (el valor no importa)
Habilitar registro detallado para fines de depuración.
MAIL_DEBUG (el valor no importa)
Habilitar depuración con un comando externo, según se especifica en el parámetro de configuración debugger_command.
NAME
El nombre completo del remitente. Esto se utiliza solo con mensajes que no tienen una cabecera de mensaje From:. Véase también la opción -F anterior.

PARÁMETROS DE CONFIGURACIÓN

Los siguientes parámetros de main.cf son especialmente relevantes para este programa. El texto a continuación solo proporciona un resumen de los parámetros. Consulte postconf(5) para obtener más detalles, incluidos ejemplos.

CONTROLES DE COMPATIBILIDAD

Disponible en Postfix 2.9 y posteriores:

sendmail_fix_line_endings (siempre)
Controla cómo el comando sendmail de Postfix convierte los finales de línea de los mensajes de correo electrónico de <CR><LF> a formato UNIX (<LF>).

CONTROLES DE SOLUCIÓN DE PROBLEMAS

El archivo DEBUG_README proporciona ejemplos de cómo solucionar problemas de un sistema Postfix.

debugger_command (vacío)
El comando externo a ejecutar cuando se invoca un programa daemon de Postfix con la opción -D.
debug_peer_level (2)
El incremento en el nivel de registro detallado cuando un destino de salto siguiente, nombre de cliente o servidor remoto, o dirección de red coincide con un patrón dado en el parámetro debug_peer_list.
debug_peer_list (vacío)
Lista opcional de patrones de destino de salto siguiente, nombre de cliente o servidor remoto, o dirección de red que, si coinciden, hacen que el nivel de registro detallado aumente en la cantidad especificada en $debug_peer_level.

CONTROLES DE ACCESO

Disponible en la versión 2.2 de Postfix y posteriores:

authorized_flush_users (estático:cualquiera)
Lista de usuarios autorizados a vaciar la cola.
authorized_mailq_users (estático:cualquiera)
Lista de usuarios autorizados a ver la cola.
authorized_submit_users (estático:cualquiera)
Lista de usuarios autorizados a enviar correo con el comando sendmail(1) (y con el comando auxiliar privilegiado postdrop(1)).

CONTROLES DE RECURSOS Y TASAS

bounce_size_limit (50000)
La cantidad máxima de texto del mensaje original que se envía en una notificación de no entrega.

CONTROLES DE SOLUCIÓN DE PROBLEMAS

fork_attempts (5)
El número máximo de intentos para fork() un proceso hijo.
fork_delay (1s)
El retraso entre intentos de fork() un proceso hijo.
hopcount_limit (50)
El número máximo de encabezados de mensaje Received: que se permiten en los encabezados de mensaje primarios.
queue_run_delay (300s)
El tiempo entre escaneos de cola diferidos por el gestor de cola; antes de Postfix 2.4, el valor predeterminado era 1000s.

CONTROLES DE FLUSH RÁPIDO

El archivo ETRN_README describe los detalles de configuración y operación para el servicio "fast flush" de Postfix.

fast_flush_domains ($relay_domains)
Lista opcional de destinos que son elegibles para archivos de registro por destino con correo que está en cola para esos destinos.

CONTROLES VERP

El archivo VERP_README describe los detalles de configuración y operación del soporte de Postfix para direcciones de ruta de retorno de sobre variables.

default_verp_delimiters (+=)
Los dos caracteres delimitadores VERP predeterminados.
verp_delimiter_filter (-=+)
Los caracteres que Postfix acepta como caracteres delimitadores VERP en la línea de comandos sendmail(1) de Postfix y en los comandos SMTP.

CONTROLES MISCELÁNEOS

alias_database (ver salida de 'postconf -d')
Las bases de datos de alias para la entrega local(8) que se actualizan con "newaliases" o con "sendmail -bi".
command_directory (ver salida de 'postconf -d')
La ubicación de todos los comandos administrativos de postfix.
config_directory (ver salida de 'postconf -d')
La ubicación predeterminada de los archivos de configuración main.cf y master.cf de Postfix.
daemon_directory (ver salida de 'postconf -d')
El directorio con los programas de soporte y programas demonio de Postfix.
default_database_type (ver salida de 'postconf -d')
El tipo de base de datos predeterminado para usar en los comandos newaliases(1), postalias(1) y postmap(1).
delay_warning_time (0h)
El tiempo después del cual el remitente recibe una copia de los encabezados del mensaje del correo que todavía está en cola.
import_environment (ver salida de 'postconf -d')
La lista de variables de entorno que un proceso privilegiado de Postfix importará de un proceso padre que no sea Postfix, o reemplazos de entorno nombre=valor.
mail_owner (postfix)
La cuenta del sistema UNIX que posee la cola de Postfix y la mayoría de los procesos demonio de Postfix.
queue_directory (ver salida de 'postconf -d')
La ubicación del directorio de cola de nivel superior de Postfix.
remote_header_rewrite_domain (vacío)
Reescribe o agrega encabezados de mensaje en el correo de clientes remotos si el valor del parámetro remote_header_rewrite_domain no está vacío, actualizando direcciones incompletas con el dominio especificado en el parámetro remote_header_rewrite_domain y agregando encabezados faltantes.
syslog_facility (mail)
La instalación de syslog del registro de Postfix.
syslog_name (ver salida de 'postconf -d')
Un prefijo que se antepone al nombre del proceso en los registros de syslog, de modo que, por ejemplo, "smtpd" se convierta en "prefijo/smtpd".

Postfix 3.2 y posteriores:

alternate_config_directories (vacío)
Una lista de directorios de configuración de Postfix no predeterminados que pueden especificarse con "-c config_directory" en la línea de comandos (en el caso de sendmail(1), con la opción "-C"), o a través del parámetro de entorno MAIL_CONFIG.
multi_instance_directories (vacío)
Una lista opcional de directorios de configuración de Postfix no predeterminados; estos directorios pertenecen a instancias adicionales de Postfix que comparten los archivos ejecutables y la documentación de Postfix con la instancia predeterminada de Postfix, y que se inician, detienen, etc., junto con la instancia predeterminada de Postfix.
