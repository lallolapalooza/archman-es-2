next(n)

Paquete: tcl

Licencias: TCL

next(n) Comandos TclOO next(n)

NOMBRE

next, nextto - invocar implementaciones de métodos de la clase base

SINOPSIS

package require TclOO
next ?arg ...?
nextto clase ?arg ...?

DESCRIPCIÓN

El comando next se utiliza para llamar a implementaciones de un método por parte de una clase, clase base o mixin que están anuladas por el método actual. Sólo se puede usar desde dentro de un método. También se usa dentro de los filtros para indicar el punto en el que un filtro llama a la implementación real (el filtro puede decidir no seguir la cadena y procesar los resultados de seguir la cadena de métodos como elija). El resultado del comando next es el resultado del siguiente método en la cadena de métodos; si no hay más métodos en la cadena de métodos, el resultado de next será un error. Los argumentos, arg, para next son los argumentos que se pasarán al siguiente método en la cadena.

El comando nextto es el mismo que el comando next, excepto que toma un argumento adicional clase que identifica una clase cuya implementación de la cadena de métodos actual (ver info object call) debe utilizarse; la implementación del método seleccionada será la proporcionada por la clase dada, y debe referirse a una invocación de no filtro existente que se encuentre más adelante en la cadena que la implementación actual.

LA CADENA DE MÉTODOS

Cuando se invoca un método de un objeto, suceden varias etapas:

[1]
Se examina la estructura del objeto, su clase, clases base, filtros y mixins, para construir una cadena de métodos, que contiene una lista de implementaciones de métodos a invocar.
[2]
Se invoca la primera implementación de método de la cadena.
[3]
Si esa implementación de método invoca el comando next, se invoca la siguiente implementación de método (con sus argumentos siendo los que se pasaron a next).
[4]
El resultado de la llamada general al método es el resultado de la implementación de método más externa; las implementaciones de método internas devuelven sus resultados a través de next.
[5]
La cadena de métodos se almacena en caché para su uso futuro.

ORDEN DE BÚSQUEDA DE MÉTODOS

Al construir la cadena de métodos, las implementaciones de métodos se buscan en el siguiente orden:

[1]
En las clases mezcladas en el objeto, en orden de recorrido de la clase. La lista de mixins se verifica en orden natural.
[2]
En las clases mezcladas en las clases del objeto, con las fuentes de mezcla buscadas en orden de recorrido de la clase. Dentro de cada clase, la lista de mixins se procesa en orden natural.
[3]
En el propio objeto.
[4]
En la clase del objeto.
[5]
En las clases base de la clase, siguiendo cada clase base de forma recursiva en el orden natural de la lista de clases base.

Cualquier implementación de método particular siempre aparecerá lo más *tarde* posible en la lista resultante de implementaciones; esto significa que si alguna clase, A, se mezcla tanto en una clase, B, como es una clase base de B, las instancias de B siempre tratarán a A como una clase base desde la perspectiva de la herencia. Esto es cierto incluso cuando la herencia múltiple se procesa indirectamente.

FILTROS

Cuando un objeto tiene una lista de nombres de filtro establecida en él, o es una instancia de una clase (o ha mezclado una clase) que tiene una lista de nombres de filtro establecida en él, antes de cada invocación de cualquier método se procesan los filtros. Las implementaciones de filtros se encuentran en orden de recorrido de la clase, al igual que las listas de nombres de filtro (cada una de las cuales se recorre en orden natural de la lista). Invocar explícitamente un método utilizado como filtro provocará que ese método se invoque dos veces, una como filtro y otra como método normal.

Cada filtro debe decidir por sí mismo si permite que la ejecución continúe hasta la implementación adecuada del método (lo que hace invocando el comando next ya que los filtros se insertan al principio de la cadena de llamadas de métodos) y es responsable de devolver el resultado de next.

Los filtros se invocan al procesar una invocación del método unknown debido a la falta de localización de una implementación de método, pero *no* al invocar constructores o destructores. (Tenga en cuenta, sin embargo, que el método destroy es un método convencional, y los filtros se invocan normalmente cuando se llama).

EJEMPLOS

Este ejemplo demuestra cómo usar el comando next para llamar a la implementación (de la clase base) de un método. El script:

oo::class create theSuperclass {
    method example {args} {
        puts "en la superclase, args = $args"
    }
}
oo::class create theSubclass {
    superclass theSuperclass
    method example {args} {
        puts "antes de encadenar desde la subclase, args = $args"
        next a {*}$args b
        next pureSynthesis
        puts "después de encadenar desde la subclase"
    }
}
theSubclass create obj
oo::objdefine obj method example args {
    puts "método por objeto, args = $args"
    next x {*}$args y
    next
}
obj example 1 2 3

imprime lo siguiente:

método por objeto, args = 1 2 3
antes de encadenar desde la subclase, args = x 1 2 3 y
en la superclase, args = a x 1 2 3 y b
en la superclase, args = pureSynthesis
después de encadenar desde la subclase
antes de encadenar desde la subclase, args =
en la superclase, args = a b
en la superclase, args = pureSynthesis
después de encadenar desde la subclase

Este ejemplo demuestra cómo construir una clase de caché simple que aplica memoización a todas las llamadas de métodos de los objetos en los que se mezcla, y muestra cómo puede afectar los tiempos de cálculo:

oo::class create cache {
    filter Memoize
    method Memoize args {
        # No filtrar las implementaciones de métodos principales
        if {[lindex [self target] 0] eq "::oo::object"} {
            return [next {*}$args]
        }
        # Comprobar si el valor ya está en la caché
        my variable ValueCache
        set key [self target],$args
        if {[info exist ValueCache($key)]} {
            return $ValueCache($key)
        }
        # Calcular valor, insertarlo en caché y devolverlo
        return [set ValueCache($key) [next {*}$args]]
    }
    method flushCache {} {
        my variable ValueCache
        unset ValueCache
        # Omitir la caché
        return -level 2 ""
    }
}
oo::object create demo
oo::objdefine demo {
    mixin cache
    method compute {a b c} {
        after 3000 ;# Simular pensamiento profundo
        return [expr {$a + $b * $c}]
    }
    method compute2 {a b c} {
        after 3000 ;# Simular pensamiento profundo
        return [expr {$a * $b + $c}]
    }
}
puts [demo compute  1 2 3]      → imprime "7" después del retardo
puts [demo compute2 4 5 6]      → imprime "26" después del retardo
puts [demo compute  1 2 3]      → imprime "7" instantáneamente
puts [demo compute2 4 5 6]      → imprime "26" instantáneamente
puts [demo compute  4 5 6]      → imprime "34" después del retardo
puts [demo compute  4 5 6]      → imprime "34" instantáneamente
puts [demo compute  1 2 3]      → imprime "7" instantáneamente
demo flushCache
puts [demo compute  1 2 3]      → imprime "7" después del retardo
