NOMBRE

ne_request_create, ne_request_dispatch, ne_request_destroy - manejo de peticiones HTTP de bajo nivel

SINOPSIS

#include <ne_request.h>

ne_request *ne_request_create(ne_session *session, const char *method, const char *target);

int ne_request_dispatch(ne_request *req);

void ne_request_destroy(ne_request *req);

DESCRIPCIÓN

El objeto ne_request representa una petición HTTP y la respuesta asociada. La función ne_request_create crea un nuevo objeto de petición para la sesión dada. El recurso destino de la petición se identifica mediante el parámetro target y el método que se realizará sobre ese recurso mediante el parámetro method.

La cadena target utilizada debe cumplir la definición de request-target dada en la RFC 9112[1]. Normalmente tomará la forma de ruta absoluta, que opcionalmente incluye una cadena de consulta.

Para enviar una petición y procesar la respuesta, se puede utilizar la función ne_request_dispatch. Una alternativa es usar la combinación (más compleja pero más flexible) de las funciones ne_begin_request, ne_end_request y ne_read_response_block; véase ne_begin_request. El envío de una petición puede requerir múltiples iteraciones de envío de una petición y recepción de una respuesta, por ejemplo si se utiliza autenticación (ver ne_set_server_auth), o si una conexión persistente caduca; esto es manejado internamente por ne_request_dispatch.

Para añadir cabeceras adicionales en la petición, se pueden usar las funciones ne_add_request_header y ne_print_request_header. Para incluir un cuerpo de mensaje con la petición, se puede usar una de las funciones ne_set_request_body_buffer, ne_set_request_body_fd o ne_set_request_body_provider.

El valor de retorno de ne_request_dispatch indica meramente si la petición se envió y la respuesta se leyó correctamente. Para descubrir el resultado de la operación, se utilizan ne_get_status, junto con el procesamiento de las cabeceras de respuesta y el cuerpo del mensaje.

Una petición solo puede enviarse una vez: llamar a ne_request_dispatch más de una vez sobre un único objeto ne_request produce un comportamiento indefinido. Una vez que todo el procesamiento asociado con el objeto de petición se completa, use la función ne_request_destroy para destruir los recursos asociados. Cualquier uso posterior del objeto de petición produce un comportamiento indefinido.

Los métodos de petición se suponen idempotentes[2] por defecto. Para una petición que utiliza un método no idempotente como POST, la bandera NE_REQFLAG_IDEMPOTENT debe ser deshabilitada usando ne_set_request_flag.

VALOR DE RETORNO

La función ne_request_create devuelve un puntero a un objeto de petición (y nunca NULL).

La función ne_request_dispatch devuelve cero si la petición se envió correctamente y un código de error distinto de cero en caso contrario, como se describe en la siguiente sección.

CÓDIGOS DE ERROR

Los códigos de error tienen un valor distinto de cero y corresponden a una definición de macro NE_* , como se enumera a continuación. Las versiones futuras de neon pueden introducir definiciones de códigos de error adicionales. Las funciones que devuelven un código de error y tienen un objeto de sesión asociado establecen la cadena de error de la sesión (ver ne_get_error) a menos que se documente lo contrario.

NE_ERROR

La petición falló (ver cadena de error de la sesión)

NE_LOOKUP

La consulta DNS para el servidor (o servidor proxy) falló.

NE_AUTH

La autenticación falló en el servidor.

NE_PROXYAUTH

La autenticación falló en el servidor proxy.

NE_CONNECT

No se pudo establecer una conexión con el servidor.

NE_TIMEOUT

Se produjo un tiempo de espera agotado mientras se esperaba la respuesta del servidor.

NE_REDIRECT

Se devolvió una redirección válida. Nota: Solo se devuelve si el manejo de redirección está registrado para la sesión usando ne_redirect_register.

NOTAS

Los parámetros path, method y target de ne_request_create se utilizan directamente en los datos de la petición sin validación, por lo que no deben tomarse de fuentes no confiables. Por ejemplo, permitir la inserción de CR, LF u otros caracteres de control sin escapar en estos parámetros puede dar lugar a un comportamiento inesperado o inseguro.

neon no impone ninguna restricción de longitud en los datos de entrada de la petición.

EJEMPLO

Un ejemplo de aplicación de una operación MKCOL al recurso en la ubicación http://www.example.com/foo/bar/:

ne_session *sess = ne_session_create("http", "www.example.com", 80);
ne_request *req = ne_request_create(sess, "MKCOL", "/foo/bar/");
if (ne_request_dispatch(req)) {
   printf("La petición falló: %s\n", ne_get_error(sess));
}
ne_request_destroy(req);
