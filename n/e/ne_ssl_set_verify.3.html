Licencias: LGPL-2.0-or-later

NE_SSL_SET_VERIFY(3) Referencia de la API de neon NE_SSL_SET_VERIFY(3)

NOMBRE

ne_ssl_set_verify - registrar una función de devolución de llamada para la verificación de certificados SSL

SINOPSIS

#include <ne_session.h>

typedef int ne_ssl_verify_fn(void *userdata, int failures, const ne_ssl_certificate *cert);

void ne_ssl_set_verify(ne_session *session, ne_ssl_verify_fn verify_fn, void *userdata);

DESCRIPCIÓN

Para habilitar la verificación manual de certificados SSL, se puede registrar una función de devolución de llamada usando ne_ssl_set_verify. Si no se registra dicha función, cuando se establece una conexión a un servidor SSL que no presenta un certificado firmado por una CA de confianza (ver ne_ssl_trust_cert), o si el certificado presentado es inválido de alguna manera, la conexión fallará.

Cuando se invoca la función de devolución de llamada, el parámetro failures proporciona una máscara de bits que indica en qué forma falló la verificación automática del certificado. El valor es igual al OR a nivel de bits de una o más de las siguientes constantes (y se garantiza que no será cero):

NE_SSL_NOTYETVALID

El certificado aún no es válido.

NE_SSL_EXPIRED

El certificado ha caducado.

NE_SSL_IDMISMATCH

El nombre de host utilizado para la sesión no coincide con el nombre de host al que se emitió el certificado.

NE_SSL_UNTRUSTED

La Autoridad Certificadora que firmó el certificado no es de confianza.

Tenga en cuenta que si se presenta alguno de los fallos NE_SSL_IDMISMATCH o NE_SSL_UNTRUSTED, la conexión puede haber sido interceptada por un tercero y no se debe asumir que es "segura".

El parámetro cert pasado a la función de devolución de llamada representa el certificado presentado por el servidor. Si el servidor presentó una cadena de certificados, la cadena se puede acceder utilizando ne_ssl_cert_signedby. El objeto cert proporcionado no es válido después de que la función de devolución de llamada regrese.

VALOR DE RETORNO

La función de devolución de llamada de verificación debe devolver cero para indicar que el certificado debe ser confiable; y distinto de cero en caso contrario (en cuyo caso, la conexión fallará).

EJEMPLOS

El siguiente código implementa una función de devolución de llamada de verificación de ejemplo, utilizando la función dump_cert de ne_ssl_cert_subject para mostrar información de certificación. Nótese que el nombre de host del servidor utilizado para la sesión se pasa como parámetro userdata a la función de devolución de llamada.

static int
my_verify(void *userdata, int failures, const ne_ssl_certificate *cert)
{
  const char *hostname = userdata;
  dump_cert(cert);
  puts("Fallo la verificación del certificado - ¡la conexión puede haber sido "
       "interceptada por un tercero!");
  if (failures & NE_SSL_IDMISMATCH) { 
    const char *id = ne_ssl_cert_identity(cert);
    if (id) 
      printf("El certificado del servidor fue emitido para '%s' y no para '%s'.\n",
             id, hostname);
    else
      printf("El certificado no fue emitido para '%s'\n", hostname);
  }
  if (failures & NE_SSL_UNTRUSTED)
    puts("El certificado no está firmado por una Autoridad Certificadora de confianza.");
  /* ... comprobar fallos de validez ... */
  if (prompt_user())
    return 1; /* fallar la verificación */
  else
    return 0; /* confiar en el certificado de todos modos */
}
int
main(...)
{
  ne_session *sess = ne_session_create("https", "some.host.name", 443);
  ne_ssl_set_verify(sess, my_verify, "some.host.name");
  ...
}
