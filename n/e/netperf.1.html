NOMBRE

netperf - un benchmark de rendimiento de red

SINOPSIS

netperf [opciones globales] -- [opciones específicas de la prueba]

DESCRIPCIÓN

Netperf es un benchmark que se puede utilizar para medir diversos aspectos del rendimiento de red. Actualmente, su enfoque está en la transferencia de datos en bloque y el rendimiento de solicitud/respuesta utilizando TCP o UDP, y la interfaz Berkeley Sockets. Además, las pruebas para DLPI y sockets de dominio Unix, y las pruebas para IPv6 pueden ser compiladas condicionalmente.

OPCIONES GLOBALES

-4
Utiliza el direccionamiento AF_INET (alias IPv4) para la conexión de control y posiblemente la de datos.
-6
Utiliza el direccionamiento AF_INET6 (alias IPv6) para la conexión de control y posiblemente la de datos.
-a espec_tamaño
Ajusta la alineación de los búferes de envío y recepción en el sistema local. Esto tiene un valor predeterminado de 8 bytes.
-A espec_tamaño
Igual que -a, pero para el sistema remoto.
-B cadena_marca
Añade cadena_marca a la salida de una prueba con banners deshabilitados.
-c [tasa]
Solicita la utilización de CPU y cálculos de demanda de servicio para el sistema local. Si se especifica el parámetro opcional de tasa, netperf utilizará ese valor en lugar de calcular la tasa.
-C [tasa]
Igual que -c, pero para el sistema remoto.
-d
Aumenta la cantidad de salida de depuración mostrada durante una prueba (posiblemente a expensas del rendimiento).
-D [segundos,unidades] (*)
Muestra resultados intermedios al menos cada segundos, utilizando unidades como estimación inicial de unidades por segundo. Esto solo está disponible cuando netperf ha sido configurado con --enable-demo.
-f GMKgmk
Cambia las unidades de medida para las pruebas *_STREAM. Las letras mayúsculas son potencias de dos, las minúsculas son potencias de diez.
-F archivo_relleno
Pre-rellena los búferes de envío con datos del archivo especificado. Esto está diseñado para proporcionar un medio para evitar búferes que se rellenan con datos que son trivialmente fáciles de comprimir. Una buena opción para un archivo que debería estar presente en cualquier sistema es esta página del manual - netperf.man. Otros archivos pueden ser proporcionados como parte de la distribución.
-h
Muestra una cadena de uso y sale.
-H nombre|ip,familia (*)
Establece el nombre de host (o dirección IP) y la familia de direcciones a utilizar para establecer la conexión de control al sistema remoto. Pasar un solo nombre sin coma solo establecerá remote_host y dejará la selección de la familia de direcciones para la conexión de control a la pila o mediante una opción de línea de comandos -4 -r -6.
-i max,min
Establece el número máximo y mínimo de iteraciones al intentar alcanzar ciertos niveles de confianza.
-j
Instruye a netperf para que calcule estadísticas adicionales sobre tiempos al ejecutar una prueba omni. La visualización de dichas estadísticas dependerá de la presencia de los selectores de salida correspondientes en la selección de salida. Estos son MIN_LATENCY, MAX_LATENCY, P50_LATENCY, P90_LATENCY, P99_LATENCY, MEAN_LATENCY y STDDEV_LATENCY.
-I nivel,[,intervalo]
Especifica el nivel de confianza (95 o 99 - 99 es el valor predeterminado) y el ancho del intervalo de confianza como un porcentaje (el valor predeterminado es 10).
-l longitud_prueba
Especifica la longitud de la prueba (predeterminado 10 segundos). Un valor negativo establece el número de transacciones de solicitud/respuesta, o el número de bytes para una prueba de flujo.
-L nombre|ip,fam (*)
Establece el nombre/IP local y/o la familia de direcciones para el socket utilizado para la conexión de control al netserver remoto.
-n num_cpus
Especifica el número de CPU en el sistema para aquellos sistemas para los que netperf no tiene forma de encontrar el número de CPU programáticamente.
-N
Esta opción indicará a netperf que no establezca una conexión de control a un netserver remoto. En su lugar, intentará establecer una conexión de datos directamente, utilizando solo la información proporcionada por los parámetros de la línea de comandos y/o los valores predeterminados internos. A menos que se proporcionen otros puertos en la línea de comandos, por defecto la conexión de datos será al puerto "discard" para una prueba "STREAM" o "SENDFILE", al puerto "echo" para una prueba "RR" o al puerto "chargen" para una prueba "MAERTS".
-o espec_tamaño
Establece un desplazamiento desde la alineación especificada con -a.
-O espec_tamaño
Igual que -o, pero para el sistema remoto.
-p num_puerto,puerto_local (*)
Dirige la conexión de control a un netserver que escucha en el puerto especificado, en lugar de utilizar una entrada "netperf" en /etc/services o el valor predeterminado interno (puerto 12865). Si se especifica ",puerto_local", la conexión de control se establecerá desde ese número de puerto local. Especificar un solo número de puerto sin coma especificará solo el número de puerto del netserver remoto y dejará la selección del número de puerto local a la pila.
-P 0|1
Mostrar (1) u ocultar (0) el banner de la prueba.
-S
Esta opción intentará establecer SO_KEEPALIVE en los extremos de la conexión de datos para pruebas que utilizan sockets BSD. Se realizará en el lado de netperf de las pruebas clásicas, y en ambos lados, netperf y netserver, de una prueba omni o migrada.
-s segundos
Esto hará que netperf duerma "segundos" segundos antes de transferir datos a través de la conexión de datos.
-t nombre_prueba
Especifica la prueba a realizar. Los nombres de prueba válidos incluyen, entre otros, y no siempre están compilados:
TCP_STREAM
TCP_SENDFILE
TCP_MAERTS
TCP_RR
TCP_CRR
UDP_STREAM
UDP_RR
DLCO_STREAM
DLCO_RR
DLCL_STREAM
DLCL_RR
STREAM_STREAM
STREAM_RR
DG_STREAM
DG_RR
SCTP_STREAM
SCTP_STREAM_MANY
SCTP_RR
SCTP_RR_MANY
LOC_CPU
REM_CPU
-T lcpu,remcpu
Solicita que netperf se vincule a la CPU lcpu y/o que netserver se vincule a la CPU rcpu.
-v verbosidad
Establece el nivel de verbosidad para la prueba (solo con -P).
-V
Muestra la versión de netperf y sale.

OPCIONES ESPECÍFICAS DE LA PRUEBA

-h
Muestra una cadena de uso basada en el nombre de prueba establecido con -t y sale.

Por favor, consulta el manual de netperf Care and Feeding of Netperf 2.5.X (doc/netperf.[pdf|html|txt]) para más información. O puedes unirte y enviar un correo electrónico a netperf-talk@netperf.org.

NOTA

Para aquellas opciones que toman dos parámetros, se debe especificar al menos uno; especificar un valor sin coma establecerá ambos parámetros a ese valor, especificar un valor con una coma inicial establecerá solo el segundo parámetro, y un valor con una coma final establecerá solo el primero. Para establecer cada parámetro con valores únicos, especifica ambos y sepáralos con una coma.

* Para estas opciones que toman dos parámetros, especificar un valor sin coma solo establecerá el primer parámetro y dejará el segundo en su valor predeterminado. Para establecer el segundo valor, debe ir precedido por una coma o ser un par separado por comas. Esto es para mantener el comportamiento anterior de netperf.

BUGS

Seguro que habrá errores. Si crees que has encontrado un error, por favor, menciónalo en netperf-talk@netperf.org. Se requiere la membresía a la lista para enviar correos a la lista. Vea http://www.netperf.org/cgi-bin/mailman/listinfo/netperf-talk . Si todo lo demás falla, envía un correo electrónico a netperf-feedback@netperf.org.
