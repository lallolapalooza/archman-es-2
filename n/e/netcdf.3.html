NETCDF(3) FUNCIONES DE BIBLIOTECA UNIDATA NETCDF(3)

NOMBRE

netcdf - Interfaz de la biblioteca Network Common Data Form (netCDF) de Unidata

SINOPSIS

#include "netcdf.h"

cc ... -lnetcdf -lhdf5_hl -lhdf5 -lz -lm

La documentación completa de las bibliotecas netCDF se puede encontrar en el sitio web de netCDF: https://www.unidata.ucar.edu/software/netcdf/.

VERSIÓN DE LA BIBLIOTECA

Este documento describe las versiones 3 y 4 de la interfaz de acceso a datos netCDF de Unidata para el lenguaje de programación C.

const char* nc_inq_libvers()

Devuelve una cadena que identifica la versión de la biblioteca netCDF y cuándo se compiló, como: "3.1a de 22 de agosto de 1996 12:57:47$".

El comando RCS ident(1) encontrará una cadena como "$Id: @(#) netcdf library version 3.1a of Sep 6 1996 15:56:26$" en la biblioteca. El comando SCCS what(1) encontrará una cadena como "netcdf library version 3.1a of Aug 23 1996 16:07:40$".

VALORES DE RETORNO

Todas las funciones netCDF (excepto nc_inq_libvers() y nc_strerror()) devuelven un estado entero.

Si este valor de estado devuelto no es igual a NC_NOERR (cero), indica que ocurrió un error. Los posibles valores de estado se definen en el archivo de inclusión del sistema <errno.h> y en "netcdf.h".

const char* nc_strerror(int status)

Devuelve una traducción textual en cadena del valor de status, como "El nombre del atributo o variable contiene caracteres ilegales" o "No existe tal archivo o directorio".

OPERACIONES DE ARCHIVO

int nc_create(const char path[], int cmode, int* ncid)

Crea un nuevo conjunto de datos netCDF en path, devolviendo un ID netCDF en ncid. El argumento cmode puede incluir el OR bitwise de las siguientes banderas: NC_NOCLOBBER para proteger conjuntos de datos existentes (por defecto, los sobrescribe silenciosamente), NC_SHARE para actualizaciones síncronas del conjunto de datos para archivos de formato clásico (por defecto, se almacenan en caché los accesos),

Cuando se crea un conjunto de datos netCDF, se abre en modo NC_WRITE. El nuevo conjunto de datos netCDF está en modo de definición. NC_64BIT_OFFSET para crear un archivo en formato de desplazamiento de 64 bits (en contraposición al formato clásico, el valor por defecto). NC_TRUE para crear un archivo netCDF-4/HDF5, y NC_CLASSIC_MODEL para garantizar que los archivos netCDF-4/HDF5 mantengan la compatibilidad con el modelo de datos clásico netCDF.

int nc__create(const char path[], int cmode, size_t initialsize, size_t* chunksize, int* ncid)

Similar a nc_create() pero tiene parámetros adicionales de ajuste de rendimiento.

El argumento initialsize establece el tamaño inicial del archivo en el momento de la creación.

Consulte nc__open() a continuación para obtener una explicación del parámetro chunksize.

int nc_open(const char path[], int mode, int* ncid)

(Corresponde a ncopen() en la versión 2)

Abre un conjunto de datos netCDF existente en path, devolviendo un ID netCDF en ncid. El tipo de acceso se describe mediante el parámetro mode, que puede incluir el OR bitwise de las siguientes banderas: NC_WRITE para acceso de lectura-escritura (por defecto solo lectura), NC_SHARE para actualizaciones síncronas del conjunto de datos (por defecto se almacenan en caché los accesos), y NC_LOCK (aún no implementado).

int nc__open(const char path[], int mode, size_t* chunksize, int* ncid)

Similar a nc_open() pero tiene un parámetro adicional de ajuste de rendimiento.

El argumento al que hace referencia chunksize controla un compromiso entre espacio y tiempo, la memoria asignada en la biblioteca netcdf frente al número de llamadas al sistema. Debido a requisitos internos, el valor no se puede establecer exactamente al valor solicitado. El valor real elegido se devuelve por referencia. Usar el valor NC_SIZEHINT_DEFAULT hace que la biblioteca elija un valor por defecto. Cómo el sistema elige el valor por defecto depende del sistema. En muchos sistemas, el "tamaño de bloque de E/S preferido" está disponible desde la llamada al sistema stat(), miembro st_blksize de la estructura struct stat. Si está disponible, se utiliza. Si no, se utiliza el doble del tamaño de página del sistema. Si no hay una llamada para descubrir el tamaño de página del sistema, simplemente establecemos el tamaño de bloque por defecto a 8192.

El tamaño de bloque es una propiedad de un descriptor netcdf abierto dado ncid, no es una propiedad persistente del conjunto de datos netcdf.

int nc_redef(int ncid)

(Corresponde a ncredef() en la versión 2)

Pone un conjunto de datos netCDF abierto en modo de definición, para que se puedan agregar o renombrar dimensiones, variables y atributos, y se puedan eliminar atributos.

int nc_enddef(int ncid)

(Corresponde a ncendef() en la versión 2)

Saca un conjunto de datos netCDF abierto del modo de definición. Los cambios realizados en el conjunto de datos netCDF mientras estaba en modo de definición se verifican y se confirman en el disco si no ocurrieron problemas. Es posible que también se escriban algunos valores de datos, consulte "PRELLENADO DE VARIABLES" a continuación. Después de una llamada exitosa, se pueden leer o escribir datos de variables en el conjunto de datos.

int nc__enddef(int ncid, size_t h_minfree, size_t v_align, size_t v_minfree, size_t r_align)

Similar a nc_enddef() pero tiene parámetros adicionales de ajuste de rendimiento.

Precaución: esta función expone detalles internos del formato de archivo netcdf versión 1. Puede que no esté disponible en futuras implementaciones de netcdf.

El formato de archivo netcdf actual tiene tres secciones, la sección de "encabezado", la sección de datos para variables de tamaño fijo y la sección de datos para variables que tienen una dimensión ilimitada (variables de registro). El encabezado comienza al principio del archivo. El índice (desplazamiento) del comienzo de las otras dos secciones está contenido en el encabezado. Típicamente, no hay espacio entre las secciones. Esto causa una sobrecarga de copia si se desea cambiar el tamaño de las secciones, como puede suceder al cambiar nombres de cosas, valores de atributos de texto, agregar atributos o agregar variables. Además, para E/S en búfer, puede haber ventajas al alinear secciones de ciertas maneras.

Los parámetros minfree permiten controlar los costos de futuras llamadas a nc_redef(), nc_enddef() solicitando que haya minfree bytes disponibles al final de la sección. El parámetro h_minfree establece el relleno al final de la sección de "encabezado". El parámetro v_minfree establece el relleno al final de la sección de datos para variables de tamaño fijo.

Los parámetros de alineación permiten establecer la alineación del comienzo de las secciones correspondientes. El comienzo de la sección se redondea hasta un índice que es un múltiplo del parámetro de alineación. El valor de la bandera NC_ALIGN_CHUNK indica a la biblioteca que use el tamaño de bloque (ver arriba) como parámetro de alineación. El parámetro v_align controla la alineación del comienzo de la sección de datos para variables de tamaño fijo. El parámetro r_align controla la alineación del comienzo de la sección de datos para variables que tienen una dimensión ilimitada (variables de registro).

El formato de archivo requiere alineación mod 4, por lo que los parámetros de alineación se redondean silenciosamente a múltiplos de 4. La llamada habitual, nc_enddef(ncid), es equivalente a nc__enddef(ncid, 0, 4, 0, 4).

El formato de archivo no contiene un valor de "tamaño de registro", este se calcula a partir de los tamaños de las variables de registro. Este desafortunado hecho nos impide proporcionar control de minfree y alineación de los "registros" en un archivo netcdf. Si agrega una variable que tiene una dimensión ilimitada, la tercera sección siempre se copiará con la variable agregada.

int nc_sync(int ncid)

(Corresponde a ncsync() en la versión 2)

A menos que la bandera NC_SHARE esté establecida en nc_open() o nc_create(), los accesos al conjunto de datos netCDF subyacente son almacenados en búfer por la biblioteca. Esta función sincroniza el estado del conjunto de datos subyacente y la biblioteca. Esto se hace automáticamente por nc_close() y nc_enddef().

int nc_abort(int ncid)

CLOSE, INQUIRE, AND DEFINE FUNCTIONS

int nc_abort(int ncid)

(Corresponde a ncabort() en la versión 2)

No necesita llamar a esta función. Esta función es llamada automáticamente por nc_close() si el netCDF estaba en modo de definición y algo sale mal con la confirmación. Si el conjunto de datos netCDF no está en modo de definición, entonces esta función es equivalente a nc_close(). Si se llama después de nc_redef(), pero antes de nc_enddef(), las nuevas definiciones no se confirman y el conjunto de datos se cierra. Si se llama después de nc_create() pero antes de nc_enddef(), el conjunto de datos desaparece.

int nc_close(int ncid)

(Corresponde a ncclose() en la versión 2)

Cierra un conjunto de datos netCDF abierto. Si el conjunto de datos está en modo de definición, se llamará a nc_enddef() antes de cerrar. Después de que un conjunto de datos se cierra, su ID puede ser reasignado a otro conjunto de datos.

Si alguno de los parámetros de retorno es un puntero NULL, la información correspondiente no se devolverá; por lo tanto, no es necesario asignar espacio para ella.
