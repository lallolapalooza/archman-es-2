NOMBRE

negotiate_kerberos_auth - Ayudante de autenticación basado en Kerberos de Squid

Versión 3.0.4sq

SINOPSIS

negotiate_kerberos_auth [-h] [-d] [-i] [-r] [-s Nombre-del-Principal-del-Servicio] [-k Nombre-del-Archivo-de-Llaves] [-c Directorio-Caché-de-Reproducción] [-t Tipo-Caché-de-Reproducción]

DESCRIPCIÓN

negotiate_kerberos_auth es un binario instalado y permite a Squid autenticar usuarios a través del protocolo Negotiate y Kerberos.

OPCIONES

-h
Muestra la ayuda del binario y la información de la sintaxis de la línea de comandos en stderr.
-d
Escribe mensajes de depuración en stderr.
-i
Escribe mensajes informativos en stderr.
-r
Elimina el reino del nombre de usuario antes de devolverlo a squid.
-s Nombre-del-Principal-del-Servicio
Proporciona el Nombre del Principal del Servicio.
-k Nombre-del-Archivo-de-Llaves
Proporciona el Nombre del Archivo de Llaves de Kerberos (Predeterminado: /etc/krb5.keytab)
-c Directorio-Caché-de-Reproducción
Proporciona el Directorio de Caché de Reproducción (Predeterminado: /var/tmp)
-t Tipo-Caché-de-Reproducción
Proporciona el Tipo de Caché de Reproducción (Predeterminado: dfl)

CONFIGURACIÓN

Este ayudante está destinado a ser utilizado como un ayudante de autenticación en squid.conf.

auth_param negotiate program /path/to/negotiate_kerberos_auth
auth_param negotiate children 10
auth_param negotiate keep_alive on

NOTA: Puede ser necesaria la siguiente modificación del archivo de inicio de squid:

Agregue las siguientes líneas al script de inicio de squid para apuntar squid a un archivo de llaves que contenga el principal del servicio HTTP/fqdn para el dominio Kerberos predeterminado. El nombre del archivo de llaves también puede ser proporcionado por la opción -k <nombre del archivo de llaves>. El fqdn debe ser el nombre del proxy establecido en IE
o firefox. No se puede usar una dirección IP.

KRB5_KTNAME=/etc/squid/HTTP.keytab export KRB5_KTNAME

Si utiliza un dominio Kerberos diferente al del que pertenece la máquina, puede apuntar squid al archivo de configuración de Kerberos separado estableciendo la siguiente variable de entorno en el script de inicio.

KRB5_CONFIG=/etc/krb5-squid.conf export KRB5_CONFIG

Kerberos puede mantener una caché de reproducción para detectar la reutilización de tickets de Kerberos (generalmente solo posible en una ventana de 5 minutos). Si squid tiene una alta carga con solicitudes de autenticación de proxy Negotiate(Kerberos), las comprobaciones de la caché de reproducción pueden generar una alta carga de CPU. Si el entorno no requiere alta seguridad, la comprobación de la caché de reproducción se puede deshabilitar para las implementaciones de Kerberos basadas en MIT agregando lo siguiente al script de inicio o usando la opción -t none.

KRB5RCACHETYPE=none export KRB5RCACHETYPE

Si negotiate_kerberos_auth no determina por alguna razón el principal de servicio correcto, puede proporcionárselo con -s HTTP/fqdn.

Si sirve múltiples reinos Kerberos, agregue un principal de servicio HTTP/fqdn@REALM por reino al archivo HTTP.keytab y use la opción -s GSS_C_NO_NAME con negotiate_kerberos_auth.
