ne_session_proxy(3)

Paquete: neon

Licencias: LGPL-2.0-or-later

NE_SESSION_PROXY(3) referencia de la API de neon NE_SESSION_PROXY(3)

NOMBRE

ne_session_proxy, ne_session_socks_proxy, ne_session_system_proxy, ne_set_addrlist - configurar servidores proxy

SINOPSIS

#include <ne_session.h>

void ne_session_proxy(ne_session *session, const char *hostname, unsigned int port);

void ne_session_system_proxy(ne_session *session, unsigned int flags);

void ne_session_socks_proxy(ne_session *session, enum ne_sock_sversion version, const char *hostname, unsigned int port, const char *username, const char *password);

void ne_set_addrlist(ne_session *session, const ne_inet_addr **addrlist, size_t count);

DESCRIPCIÓN

Una (y no más de una) de las funciones ne_session_proxy, ne_session_system_proxy, ne_session_socks_proxy, ne_set_addrlist puede ser usada para configurar un servidor proxy para un objeto de sesión dado. Si se invoca más de una función para cualquier objeto de sesión dado, solo la última llamada tiene efecto. Si se va a utilizar una de las funciones, debe ser usada antes de la creación de cualquier objeto de solicitud para la sesión.

Especificación de proxy HTTP

La función ne_session_proxy configura el uso de un servidor proxy HTTP para la sesión, cuya ubicación se proporciona mediante los parámetros hostname y port. Si el proxy requiere autenticación, se debe utilizar ne_set_proxy_auth.

Configuración del proxy del sistema

La función ne_session_system_proxy configura la sesión para usar cualquier servidor proxy especificado por la configuración del sistema. El soporte para esta función es específico de la plataforma; si no es compatible, la función no tiene ningún efecto.

Configuración del proxy SOCKS

La función ne_session_socks_proxy configura la sesión para usar un proxy SOCKS. El parámetro version indica qué versión del protocolo SOCKS se debe usar. Los parámetros hostname y port especifican la ubicación del proxy SOCKS. Tenga en cuenta que un servidor con solo una dirección IPv6 no se puede usar con SOCKS v4 o v4A. La interpretación de los otros argumentos depende de la versión especificada:

NE_SOCK_SOCKSV4 (versión 4)

El parámetro username debe ser no NULL; el parámetro password se ignora.

NE_SOCK_SOCKSV4A (versión 4A)

El parámetro username debe ser no NULL; el parámetro password se ignora.

NE_SOCK_SOCKSV5 (versión 5)

El parámetro username puede ser NULL; si es no NULL, el parámetro password también debe ser no NULL; de lo contrario, se ignora..

Anulación de la dirección del servidor de origen

La función ne_set_addrlist fuerza el uso de una dirección y puerto de una lista especificada al establecer una conexión TCP, ignorando el nombre de host y el puerto "reales" que identifican al servidor de origen para la sesión (pasados a ne_session_create). El nombre de host y el puerto "reales" del servidor de origen todavía se usarán en la cabecera Host en las solicitudes HTTP. Cuando se requiere una conexión, la biblioteca iterará a través de la lista addrlist, intentando conectarse a la dirección addrlist[0] hasta addrlist[count-1] en orden, hasta que se pueda establecer una conexión.

VALORES DE RETORNO

Ninguna de las funciones descritas aquí tiene un valor de retorno.

EJEMPLOS

Crear y destruir una sesión:

ne_session *sess;
sess = ne_session_create("http", "host.example.com", 80);
ne_session_proxy(sess, "proxy.example.com", 3128);
/* ... usar sess ... */
ne_session_destroy(sess);
