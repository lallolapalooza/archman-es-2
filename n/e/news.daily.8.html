NOMBRE

news.daily - Realiza tareas de mantenimiento diarias de Usenet

SINOPSIS

news.daily [delayrm] [expctl=ruta] [expdir=ruta] [expireover] [expireoverflags=args] [flags=args] [lowmark] [mailto=direccion] [noexpire] [noexpireover] [noexplog] [nologs] [nomail] [noprocbatch] [norenumber] [norm] [norotate] [nostat] [notdaily] [postexec=programa] [procbatchdir=ruta] [tmpdir=ruta] [/ruta/a/un/programa]

DESCRIPCION

news.daily realiza una serie de funciones administrativas importantes de Usenet. Esto incluye:

  • producir un informe de estado con innstat;
  • eliminar artículos de noticias antiguos (con expirerm si se especifica la palabra clave delayrm);
  • purgar la base de datos de resúmenes con expireover (si se especifica la palabra clave epónima correspondiente o si enableoverview es verdadero en inn.conf);
  • procesar archivos de registro y rotar los archivos de registro archivados con scanlogs;
  • procesar archivos soltados de innfeed con procbatch;
  • procesar mensajes en cola con rnews invocado con el indicador -U;
  • renumerar el archivo active con ctlinnd;
  • reconstruir el archivo history con expire;
  • eliminar cualquier archivo de socket antiguo encontrado en el directorio pathrun;
  • recopilar toda la salida y enviarla por correo.

Tenga en cuenta que este programa debe ejecutarse bajo la cuenta del administrador de noticias (generalmente "news"), no como root. Por defecto, news.daily realiza todas sus funciones y envía la salida por correo al administrador de noticias, que es el usuario especificado con --with-news-master en el momento de la configuración (es "usenet" por defecto). También puede cambiar este comportamiento con la palabra clave mailto.

Al especificar palabras clave en la línea de comandos, es posible modificar las funciones realizadas, así como cambiar los argumentos dados a expire(8) y expireover(8). news.daily debe ejecutarse una vez al día, típicamente fuera de cron(8). Dado que ralentizará el servidor mientras se ejecuta, debe ejecutarse durante períodos de bajo uso del servidor, como en medio de la noche. Para ejecutarlo a las 3 a.m., por ejemplo, agregue la siguiente entrada al archivo crontab del usuario de noticias:

0 3 * * * <ruta_bin en inn.conf>/news.daily expireover lowmark

Si está utilizando algún método de almacenamiento que no sea CNFS, agregue la palabra clave delayrm a la lista de opciones anterior para news.daily.

Se puede ejecutar con más frecuencia, pero tales invocaciones deben usar al menos la palabra clave norotate (o quizás la palabra clave notdaily) para evitar que los archivos de registro se procesen y roten demasiado rápido. El programa shlock(8) se utiliza para evitar ejecuciones simultáneas.

El programa especificado por la ruta dada /ruta/a/un/programa se ejecuta justo antes de que se realice cualquier expiración. Un uso típico es especificar un programa de expiración alternativo y usar la palabra clave noexpire. Se pueden especificar varios programas; se invocarán en orden.

PALABRAS CLAVE

Las siguientes palabras clave pueden ser utilizadas:

delayrm
Utiliza el indicador -z al invocar expire y expireover. Los nombres de los artículos a eliminar se escriben en un archivo temporal y luego se renombra después de la expiración llamando a expirerm, que a su vez llama a fastrm.
expctl=ruta
Especifica el archivo a usar como archivo expire.ctl para expire.
expdir=ruta
Por defecto, expire crea el nuevo archivo history y la base de datos en el mismo directorio que los archivos actuales. Usar esta palabra clave especifica una ubicación diferente para crear los nuevos archivos (pasando el indicador -d a expire), que luego se moverán a la ubicación correcta cuando termine.
expireover
El programa expireover se llama después de la expiración para purgar la base de datos de resúmenes. Si no se crean datos de resúmenes, la palabra clave expireover no es necesaria. Este es el caso cuando el servidor solo funciona para distribuidores (sin lectores). Por defecto, news.daily no llama a expireover a menos que enableoverview esté configurado en verdadero en inn.conf.
expireoverflags=args
Si se usa la palabra clave expireover, esta palabra clave puede usarse para especificar los indicadores que se pasarán a expireover. Si se usa la palabra clave delayrm, entonces el valor por defecto es -z y la lista de archivos eliminados; de lo contrario, el valor por defecto es -s.
flags=args
Por defecto, expire se invoca con el argumento -v1. Usar esta palabra clave cambia los argumentos a los especificados. Tenga cuidado de usar comillas si se necesitan múltiples argumentos. Esta palabra clave no tiene efecto si se usa la palabra clave noexpire.
lowmark
Si se usa la palabra clave lowmark, se usa "ctlinnd lowmark" para renumerar active. La operación normal de "ctlinnd renumber" llevará mucho tiempo. Con la palabra clave lowmark, esto tomará menos tiempo. Si se usa la palabra clave lowmark, la palabra clave norenumber no es necesaria, ya que news.daily la especifica implícitamente.

Si se proporciona la palabra clave lowmark a news.daily, entonces la palabra clave expireover también debe ser proporcionada; de lo contrario, ese tipo de renumeración no se tendrá en cuenta.

mailto=direccion
Por defecto, news.daily envía el informe por correo a la dirección del newsmaster especificada con --with-news-master en el momento de la configuración. La palabra clave mailto puede especificar una dirección diferente a la que se enviará el informe. Tenga en cuenta que usar esta palabra clave no tiene efecto si la palabra clave nomail también se especifica.
noexpire
Por defecto, expire se invoca para eliminar artículos de noticias antiguos. Usar esta palabra clave deshabilita esta función.
noexpireover
Por defecto, expireover se invoca para eliminar la base de datos de resúmenes antigua si enableoverview está configurado en inn.conf. Usar esta palabra clave deshabilita esta función.
noexplog
expire normalmente añade información a pathlog/expire.log (ver newslog(5)). Usar esta palabra clave causa que la salida de expire sea manejada como parte de la salida de news.daily. No tiene efecto si se usa la palabra clave noexpire.
nologs
Después de la expiración, se invoca scanlogs para procesar los archivos de registro. Usar esta palabra clave deshabilita todas las funciones de procesamiento de registros.
nomail
news.daily normalmente envía un mensaje de correo electrónico conteniendo los resultados al administrador. Usar esta palabra clave hace que este mensaje se envíe a stdout y stderr en su lugar. Normalmente, todas las utilidades invocadas por el script tienen su stdout y stderr redirigidos a un archivo. Si el archivo está vacío, no se envía ningún mensaje.
noprocbatch
Esta palabra clave deshabilita la ejecución de procbatch en los archivos soltados de innfeed generados en su directorio de cola. Estos archivos contienen una lista de artículos que no se enviaron correctamente a los pares. Por defecto, se procesarán y eliminarán después.
norenumber
Esta palabra clave deshabilita la operación "ctlinnd renumber". Normalmente, las marcas de agua bajas para todos los grupos de noticias se restablecen en el archivo active.
norm
>Por defecto, cualquier socket ctlinnd que no haya sido modificado en dos días será eliminado. El uso de esta palabra clave deshabilita esta función.
norotate
Por defecto, el procesamiento de logs incluye la rotación y limpieza de los archivos de log. El uso de esta palabra clave deshabilita el aspecto de rotación y limpieza del procesamiento de logs: los archivos de logs solo se escanean en busca de información y no se altera su contenido. Esta palabra clave no tiene efecto si se utiliza la palabra clave nologs. La palabra clave norotate se pasa a scanlogs si se invoca.
nostat
Esta palabra clave deshabilita el informe de estado generado por innstat. Sin esta palabra clave, el informe de estado es la primera función realizada, justo antes de obtener el bloqueo de news.daily.
notdaily
Por defecto, news.daily espera ejecutarse solo una vez al día y realiza varias acciones (como rotar logs) que normalmente solo deberían hacerse a diario. Utilice esta palabra clave en las ejecuciones adicionales de news.daily durante el día y el procesamiento normal de los archivos de logs (y su rotación) no se realizará. Esta palabra clave implica nologs.
postexec=programa
El programa especificado por la ruta dada programa se ejecuta justo después de que se completa toda la expiración. Se pueden especificar varios programas; se invocarán en orden.
procbatchdir=ruta
news.daily intenta encontrar el directorio de backlog de innfeed en innfeed.conf e innfeed-delayed.conf. En caso de que varias instancias de innfeed estén en ejecución o cuando su archivo de configuración no sea el predeterminado, la palabra clave procbatchdir se puede utilizar para especificar la ruta del directorio de backlog. Esta palabra clave se puede usar más de una vez en la línea de comandos, permitiendo especificar varios directorios de backlog.
tmpdir=ruta
Anula la configuración de pathtmp en inn.conf estableciendo la variable de entorno $TMPDIR a la ruta especificada. Varias partes del proceso de expiración, como la ordenación, utilizarán entonces esta ruta como directorio para archivos temporales.
