NOMBRE

netctl.profile - Opciones de perfil

SINOPSIS

netctl.profile

DESCRIPCIÓN

Los perfiles para netctl residen en /etc/netctl/ y son archivos de texto plano. Los archivos consisten en definiciones de variables siguiendo la sintaxis del shell bash y no se espera que ejecuten ningún código. Es bueno omitir tantas comillas como sea posible. Para algunas variables relacionadas con WPA, se aplican reglas de comillas especiales (ver abajo).

El nombre del perfil es el nombre del archivo. Los nombres de perfil no deben contener saltos de línea y no deben terminar en .action, .conf o .service. Cada vez que se lee un perfil, se incluyen todos los scripts ejecutables en /etc/netctl/hooks/ y cualquier script ejecutable en /etc/netctl/interfaces/ con el nombre de la interfaz para el perfil. El nombre del perfil actual está disponible a través de la variable Profile en el entorno de los scripts incluidos. Al iniciar o detener un perfil, el comando respectivo está disponible a través de la variable Command. Las declaraciones en un script de interfaz anulan las declaraciones en un perfil, que a su vez anulan las declaraciones en los hooks. Para cada tipo de conexión, hay archivos de perfil de ejemplo en /etc/netctl/examples/.

TIPOS DE CONEXIÓN DISPONIBLES

ethernet

Para conexiones por cable.

wireless

Para conexiones inalámbricas. Este tipo de conexión requiere que wpa_supplicant esté disponible.

bond

Para interfaces enlazadas (bonded).

bridge

Para interfaces de puente (bridge).

dummy

Para interfaces dummy.

ppp

Para conexiones PPP (actualmente solo PPPoE).

pppoe

Para conexiones PPPoE.

mobile_ppp

Para conexiones PPP de banda ancha móvil que utilizan un módem USB.

openvswitch

Para interfaces de puente Open vSwitch.

tunnel

Para interfaces de túnel.

tuntap

Para interfaces TUN/TAP.

vlan

Para VLANs en conexiones similares a ethernet.

macvlan

Para MACVLANs en conexiones similares a ethernet.

wireguard

Para interfaces WireGuard.

OPCIONES GENERALES

Description=

Una descripción del perfil.

Connection= [obligatorio para todos los perfiles]

El tipo de conexión utilizado por el perfil.

Interface= [obligatorio para todos los perfiles]

El nombre de la interfaz de red asociada. El nombre de la interfaz no debe ir entre comillas.

BindsToInterfaces=()

Un array de interfaces de red físicas que este perfil necesita antes de poder iniciarse. Para perfiles 'habilitados', systemd esperará la presencia de las interfaces especificadas antes de iniciar un perfil. Si esta variable no se especifica, se usará el valor de Interface= por defecto.

MACAddress=

Dirección MAC opcional para interfaces recién creadas. Cuando se establece en el nombre de una interfaz existente, se utiliza la dirección de esa interfaz. Los tipos de conexión que crean una interfaz y son capaces de establecer una dirección MAC son bond, bridge, dummy, vlan y macvlan.

After=()

Un array de nombres de perfiles que deben iniciarse antes de que se inicie este perfil. Esto es solo una dependencia de orden y no pretende ser una lista de perfiles que este perfil requiere. El significado es el mismo que After= en systemd.unit(5).

WaitOnline=

Establecido en 'yes' para considerar el perfil activado solo cuando está en línea. Por defecto es 'no'.

ExecUpPost=

Un comando que se ejecuta después de que se establece una conexión. Si el comando especificado devuelve algo diferente de 0 (éxito), netctl abortará y detendrá el perfil. Si se permite que el comando falle, agregue '|| true' al final del mismo.

ExecDownPre=

Un comando que se ejecuta antes de que se desconecte una conexión. Se deben tomar precauciones similares a las de ExecUpPost=.

TimeoutUp

Tiempo máximo, en segundos, para esperar a que una interfaz se active. Por defecto es '5'.

ForceConnect=

Establecido en 'yes' para forzar la conexión incluso si la interfaz está activa. No utilice esto a menos que sepa lo que está haciendo.

ExcludeAuto=

Si este perfil debe excluirse o no de la selección automática de perfiles. Por defecto es 'no' para conexiones inalámbricas y con DHCP habilitado, y 'yes' en caso contrario.

NETCTL_DEBUG=

Establecido en 'yes' para generar salida de depuración.

OPCIONES IP

Estas opciones se aplican a todas las conexiones que configuran una red habilitada para IP. En particular, estos tipos de conexión son ethernet, wireless, bond, bridge, tunnel, tuntap y vlan.

IP= [obligatorio para IPv4]

Uno de 'static', 'dhcp' o 'no', según la forma deseada de obtener una dirección.

IP6= [obligatorio para IPv6]

Uno de 'static', 'stateless', 'dhcp-noaddr', 'dhcp', 'no' o dejarlo fuera (vacío). La diferencia entre no especificar y establecerlo en 'no' radica en el manejo de paquetes de anuncio de enrutador, que se bloquea con 'no'.

Address=() [requiere IP=static]

Un array de direcciones IP con el sufijo '/<máscara de red>'. Omitir los corchetes para arrays que consisten en un solo elemento es aceptado en la sintaxis Bash.

Gateway= [requiere IP=static]

Una dirección de puerta de enlace de enrutamiento IP.

Routes=()

Un array de rutas personalizadas de la forma

‘<rango de direcciones> vía <puerta de enlace>’.

Address6=() [requiere IP6=static o IP6=stateless]

Un array de direcciones IPv6. La longitud del prefijo se puede especificar mediante la sintaxis '1234:bcd::11/64'. Es posible especificar modificadores, en particular, '1234:bcd::11/64 nodad' deshabilita la Detección de Direcciones Duplicadas para la dirección.

Gateway6= [requiere IP6=static o IP6=stateless]

Una dirección de puerta de enlace de enrutamiento IPv6.

Routes6=()

Un array de rutas personalizadas de la forma

‘<rango de direcciones> vía <puerta de enlace>’.

DHCPClient= [requiere IP=dhcp]

El nombre del cliente DHCP a utilizar. Por defecto, netctl viene con soporte para 'dhcpcd' y 'dhclient'. Los clientes pueden aceptar opciones adicionales a través de variables específicas del cliente. Las opciones de línea de comandos para dhcpcd(8) se leen de DhcpcdOptions= (por defecto es '-L'). Las opciones de línea de comandos para dhclient(8) se leen de DhclientOptions=. Por defecto es 'dhcpcd'.

DHCP6Client= [requiere IP6=dhcp o IP6=dhcp-noaddr]

El nombre del cliente DHCPv6 a utilizar. Por defecto, se admiten 'dhcpcd' y 'dhclient'. Las opciones de línea de comandos para la instancia IPv6 de dhcpcd(8) se leen de DhcpcdOptions6=. Las opciones de línea de comandos para la instancia IPv6 de dhclient(8) se leen de DhclientOptions6=. Por defecto es 'dhclient'.

DHCPReleaseOnStop=

Establecido en 'yes' para liberar el lease DHCP cuando se detiene el perfil.

OPTIONS FOR ‘MODEM’ CONNECTIONS

These options are understood for connections of the ‘modem’ type:

ModemType=

One of ‘dialup’, ‘umts’, ‘cdma’, ‘network’, or ‘custom’. Defaults to ‘dialup’.

Baud=

The speed of the serial line. Defaults to ‘115200’.

Port=

The serial port to open. Defaults to ‘/dev/modem’.

ListenPort=

The port to listen on for incoming connections. Only relevant for the ‘network’ modem type.

DialCommand=

The command to dial. Defaults to ‘ATDT%d’. Use %s for the phone number and %d for the dialing speed.

DefaultRoute=

Whether or not to use the default route provided by the peer. Defaults to ‘yes’.

UsePeerDNS=

Whether or not to use the DNS servers provided by the peer. Defaults to ‘yes’.

InitString=

A string sent to the modem before dialing. Defaults to ‘ATQ0 V1 E1 S0=0 &C1 &D2 +FCLASS=0’.

APN=

The Access Point Name for UMTS/CDMA connections.

User=

The username for UMTS/CDMA connections.

Password=

The password for UMTS/CDMA connections.

IPAddress=

The IP address to assign to the interface.

Huawei_APN=

A custom APN configuration string for Huawei modems, e.g. ‘192.168.1.1’ or a custom AT^SYSCFG=... line specified as ‘SYSCFG=...’. This generates AT commands specific to certain Huawei modems; all other devices should leave this option unset or set to ‘None’.

Init=

An initialization string sent to the modem before dialing. This string is sent after sending “ATZ”. Defaults to ‘ATQ0 V1 E1 S0=0 &C1 &D2 +FCLASS=0’.

ChatScript=

Path to a chat file. If specified, no chat script will be generated and all of the above options except User= and Password= will be ignored.

MaxFail=

The number of consecutive failed connection attempts to tolerate. A value of 0 means no limit. Defaults to ‘5’.

DefaultRoute=

Whether or not to use the default route provided by the peer. Defaults to ‘yes’.

UsePeerDNS=

Whether or not to use the DNS servers provided by the peer. Defaults to ‘yes’.

PPPUnit=

The PPP unit number in the interface name (‘ppp0’, ‘ppp1’, etc.).

OptionsFile=

A file to read additional pppd(8) options from.

RFKill=

The name of an rfkill device. When specified, the device is used to block/unblock the interface when appropriate. Names can be found in /sys/class/rfkill/rfkillX/name.

OPTIONS FOR ‘OPENVSWITCH’ CONNECTIONS

The interfaces of BindsToInterfaces= take part in the bridge named by Interface=. Only the ip options are understood for connections of the ‘openvswitch’ type.

OPTIONS FOR ‘TUNNEL’ CONNECTIONS

The name of the tunnel interface is specified in Interface=. Next to the ip options, the following are understood for connections of the ‘tunnel’ type:

Mode=

The tunnel type (e.g. ‘sit’). See ip-tunnel(8) for available modes.

Local=

The address of the local end of the tunnel.

Remote=

The address of the remote end of the tunnel.

Key= [requires Mode=gre]

A key identifying an individual traffic flow within a tunnel.

OPTIONS FOR ‘TUNTAP’ CONNECTIONS

The name of the tuntap interface is specified in Interface=. Next to the ip options, the following are understood for connections of the ‘tuntap’ type:

Mode=

Either ‘tun’, or ‘tap’.

User=

The owning user of the tun/tap interface.

Group=

The owning group of the tun/tap interface.

OPTIONS FOR ‘VLAN’ CONNECTIONS

The name of the vlan interface is specified in Interface=. The underlying physical interface is specified in BindsToInterfaces=. Hence, for vlan profiles, BindsToInterfaces= contains the name of a single network interface.

All options for connections of the ‘ethernet’ type are understood for connections of the ‘vlan’ type. Additionally, connections of the ‘vlan’ type must set a vlan identifier using VLANID=. See ip(8) for details.

OPTIONS FOR ‘MACVLAN’ CONNECTIONS

The name of the macvlan interface is specified in Interface=. The underlying physical interface is specified in BindsToInterfaces=. Hence, for macvlan profiles, BindsToInterfaces= contains the name of a single network interface.

All options for connections of the ‘ethernet’ type are understood for connections of the ‘macvlan’ type. Next to the ip options, the following are understood for connections of the ‘macvlan’ type:

Mode=

Either ‘bridge’, ‘vepa’, ‘private’, or ‘passthru’. See ip(8) for details.

OPTIONS FOR ‘WIREGUARD’ CONNECTIONS

The name of the WireGuard interface is specified in Interface=. Next to the ip options, the following are understood for connections of the ‘wireguard’ type:

WGConfigFile=

Path to a WireGuard configuration file. Defaults to /etc/wireguard/$Interface.conf.

SPECIAL QUOTING RULES

Configuration files for wpa_supplicant use non-standard quoting. Therefore, non-standard quoting rules exist for some variables for connections of the ‘wireless’ type. In particular, these variables are ESSID=, and Key=.

A variable is considered quoted by wpa_supplicant if it is enclosed in double quotes ("). A variable is considered non-quoted by wpa_supplicant if it does not start with a double quote. Hexadecimal values are specified non-quoted in configuration files of wpa_supplicant. In netctl, variables are written to wpa_supplicant configuration files quoted by default. When special quoting rules apply, it is possible to specify an unquoted (hexadecimal) value using a special syntax.

The special quoting rules of netctl are as follows. A string that starts with a literal double quote is considered non-quoted. Any other string is considered quoted. It is possible to specify quoted strings that start with a double quote by quoting manually. An extreme example is the specification of a quoted double quote: X='""""'. On the other end of the spectrum there is the non-quoted backslash: X=\"\\.

Further examples of quoted strings (all equivalent):

X=string
X="string"
X='""string"'

Further examples of non-quoted strings (all equivalent):

X=\"string
X="\"string"
X='"string'

A mnemonic is to think of the prefix ‘\"’ as saying ‘non’-‘quote’.
