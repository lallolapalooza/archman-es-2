DESCRIPCIÓN

Las funciones que tratan con módulos MIB se dividen en cuatro grupos: las que se ocupan de la inicialización y el cierre, de la lectura y el análisis de archivos MIB, de la búsqueda en el árbol MIB y de las rutinas de salida.

Inicialización y Cierre

add_mibdir se utiliza para añadir el directorio especificado a la ruta de ubicaciones que se buscan para encontrar archivos que contengan módulos MIB. Tenga en cuenta que esto no carga realmente los módulos MIB ubicados en ese directorio, sino que es simplemente un paso de inicialización para hacerlos disponibles para netsnmp_read_module. Esta función devuelve un recuento de los archivos encontrados en el directorio, o un -1 si hay un error. Debe llamarse *antes* de invocar netsnmp_init_mib.

netsnmp_init_mib configura la ruta de búsqueda de directorios MIB (utilizando add_mibdir), establece el marco interno de MIB y luego carga los módulos MIB apropiados (utilizando netsnmp_read_module y read_mib). Consulte la sección VARIABLES DE ENTORNO para obtener detalles.
Debe llamarse antes que cualquier otra rutina que manipule o acceda al árbol MIB (pero después de cualquier llamada adicional a add_mibdir).

shutdown_mib borrará la información que fue recopilada por netsnmp_read_module, add_mibdir y add_module_replacement. Se recomienda encarecidamente no invocar shutdown_mib mientras haya sesiones SNMP activamente gestionadas.

Lectura y Análisis de MIBs

netsnmp_read_module toma el nombre de un módulo MIB (que no necesariamente tiene que ser el mismo que el nombre del archivo que contiene el módulo), lo localiza dentro de la lista configurada de directorios MIB y carga las definiciones del módulo en el árbol MIB activo. También carga cualquier módulo MIB listado en la cláusula IMPORTS de este módulo.

read_mib es similar, pero toma el nombre del archivo que contiene el módulo MIB. Tenga en cuenta que este archivo no necesita estar ubicado dentro de la lista de búsqueda de directorios MIB (aunque sí los módulos listados en la cláusula IMPORTS).

read_all_mibs leerá todos los módulos MIB encontrados en la lista de búsqueda de directorios MIB.

En general, el analizador es silencioso sobre las rarezas que encuentra en los archivos MIB. Para que se informen de advertencias, llame a snmp_set_mib_warnings con un nivel de 1 (o 2 para aún más advertencias).

add_module_replacement se puede utilizar para permitir que los nuevos módulos MIB obsoleten a los anteriores, sin necesidad de modificar las cláusulas IMPORTS de otros módulos. Toma los nombres de los módulos antiguo y nuevo, junto con una indicación de qué porciones del módulo antiguo se ven afectadas.

tag len carga el nuevo módulo cuando:
NULL 0 siempre (el módulo antiguo es un subconjunto estricto del
nuevo)
nombre 0 solo para la etiqueta dada
nombre distinto de 0 para cualquier identificador con este prefijo
También se puede utilizar para manejar errores en los identificadores de módulo utilizados en las cláusulas IMPORTS de MIB (como referirse a *RFC1213* en lugar de *RFC1213-MIB*).

Búsqueda en el Árbol MIB

read_objid toma una cadena que contiene una versión textual de un identificador de objeto (en forma numérica o descriptiva) y la transforma en la lista correspondiente de subidentificadores. Esto se devuelve en el parámetro *output*, con el número de subidentificadores devuelto a través de *out_len*. Cuando se llama, *out_len* debe contener la longitud máxima del array *output*. Si se están procesando múltiples identificadores de objeto, esta longitud debe restablecerse antes de cada llamada. Esta función devuelve un valor de 1 si tiene éxito al analizar la cadena y 0 en caso contrario.

snmp_parse_oid es similar, pero devuelve un puntero al búfer OID analizado (o NULL).

get_module_node toma un descriptor y el nombre de un módulo, y devuelve la lista OID correspondiente, de la misma manera que read_objid arriba.
Si el nombre del módulo se especifica como "ANY", esta rutina asumirá que el descriptor proporcionado es único dentro del árbol y devolverá la entrada coincidente. Si esta suposición no es válida, el comportamiento en cuanto a qué variable se devuelve depende de la implementación.

Salida

print_mib imprimirá una representación del árbol MIB activo actual al puntero FILE especificado.

print_objid tomará un identificador de objeto (tal como lo devuelve read_objid, snmp_parse_oid o get_module_node) e imprimirá la forma textual de ese OID en la salida estándar.

fprint_objid hace lo mismo, pero imprime al puntero FILE especificado por el parámetro inicial.

snprint_objid imprime la misma información en el búfer apuntado por *buf*, que tiene una longitud de *len*. Devuelve el número de caracteres impresos, o -1 si el búfer no era lo suficientemente grande. En este último caso, *buf* típicamente contendrá una versión truncada de la información (pero este comportamiento no está garantizado).

print_description, fprint_description y snprint_description toman un identificador de objeto similar e imprimen una versión de la definición MIB para ese objeto, junto con el OID completo. El argumento *width* controla cómo se presenta el OID.

VARIABLES DE ENTORNO

El uso principal de las variables de entorno con respecto a estas llamadas API es configurar qué módulos MIB deben cargarse y dónde se encuentran.

MIBDIRS
Una lista separada por dos puntos de directorios para buscar módulos MIB.
Por defecto: /usr/share/snmp/mibs
Utilizado por init_mib, netsnmp_read_module, read_all_mibs y (implícitamente) por read_mib.
MIBS
Una lista separada por dos puntos de módulos MIB para cargar.
La lista por defecto de módulos dependerá de cómo se compiló originalmente el software Net-SNMP, pero típicamente es:
IP-MIB:IF-MIB:TCP-MIB:UDP-MIB:SNMPv2-MIB:RFC1213-MIB:UCD-SNMP-MIB:HOST-RESOURCES-MIB
Si el valor de la variable de entorno MIBS comienza con un carácter '+', entonces estos módulos MIB se añadirán a la lista por defecto. De lo contrario, estos módulos (más cualquiera de los que importan) se cargarán *en lugar* de la lista por defecto.
Si la variable de entorno MIBS tiene el valor ALL, entonces se llamará a read_all_mibs para cargar la colección completa de todos los módulos MIB disponibles.
Utilizado solo por init_mib.
MIBFILES
Una lista separada por dos puntos de archivos para cargar.
Por defecto: (ninguno)
Utilizado solo por init_mib.
