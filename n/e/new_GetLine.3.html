DESCRIPCIÓN

La función gl_get_line() es parte de la biblioteca tecla (ver la página del manual libtecla(3)). Si el usuario está escribiendo en una terminal, cada llamada le pide una línea de entrada, luego proporciona instalaciones de edición interactivas, similares a las del shell tcsh de Unix. Además de la edición simple de la línea de comandos, admite la recuperación de líneas de comandos introducidas previamente, la finalización con TAB de nombres de archivo y la expansión de nombres de archivo comodín en línea. La documentación de las características de edición de línea de comandos a nivel de usuario y de todas las opciones de configuración del usuario, se puede encontrar en la página del manual tecla(7). Esta página del manual se centra en la documentación para programadores interesados en usar esta biblioteca en su aplicación.

UN EJEMPLO

Lo siguiente muestra un ejemplo completo de cómo usar la función gl_get_line() para obtener entrada del usuario:

  #include <stdio.h>
  #include <locale.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  { 
    char *line;    /* La línea que el usuario escribió */
    GetLine *gl;   /* El objeto de recursos de gl_get_line() */
    setlocale(LC_CTYPE, ""); /* Adoptar la elección del usuario */
                             /* de conjunto de caracteres. */
    gl = new_GetLine(1024, 2048);
    if(!gl)
      return 1;
    while((line=gl_get_line(gl, "$ ", NULL, -1)) != NULL &&
           strcmp(line, "exit\n") != 0)
      printf("Escribiste: %s\n", line);
    gl = del_GetLine(gl);
    return 0;
  }

En el ejemplo, primero se crean los recursos necesarios para la función gl_get_line() llamando a new_GetLine(). Esto asigna la memoria utilizada en llamadas posteriores a la función gl_get_line(), incluido el búfer de historial para grabar líneas introducidas previamente. Luego se leen una o más líneas del usuario, hasta que ocurre un error o el usuario escribe exit. Finalmente, los recursos que fueron asignados por new_GetLine(), se devuelven al sistema llamando a del_GetLine(). Observe el uso del valor de retorno NULL de del_GetLine() para hacer que gl sea NULL. Esta es una medida de precaución. Si el programa intenta posteriormente pasar gl a gl_get_line(), dicha función se quejará y devolverá un error, en lugar de intentar usar el objeto de recursos eliminado.

LAS FUNCIONES UTILIZADAS EN EL EJEMPLO

Las descripciones de las funciones utilizadas en el ejemplo son las siguientes:

  GetLine *new_GetLine(size_t linelen, size_t histlen)

Esta función crea los recursos utilizados por la función gl_get_line() y devuelve un puntero opaco al objeto que los contiene. La longitud máxima de una línea de entrada se especifica a través del argumento linelen, y el número de bytes a asignar para almacenar líneas de historial se establece mediante el argumento histlen. Las líneas de historial se almacenan una tras otra en un único búfer de este tamaño. Tenga en cuenta que esto significa que el número de líneas de historial que se pueden almacenar en cualquier momento, depende de las longitudes de las líneas individuales. Si desea establecer un límite superior en el número de líneas que se pueden almacenar, consulte la función gl_limit_history() descrita más adelante. Si no desea historial en absoluto, especifique histlen como cero, y no se asignará ningún búfer de historial.

En caso de error, se imprime un mensaje en stderr y se devuelve NULL.

  GetLine *del_GetLine(GetLine *gl)

Esta función elimina los recursos que fueron devueltos por una llamada anterior a new_GetLine(). Siempre devuelve NULL (es decir, un objeto eliminado). No hace nada si el argumento gl es NULL.

  char *gl_get_line(GetLine *gl, const char *prompt,
                   const char *start_line, int start_pos);

La función gl_get_line() se puede llamar cualquier número de veces para leer la entrada del usuario. El argumento gl debe haber sido devuelto previamente por una llamada a new_GetLine(). El argumento prompt debe ser una cadena normal terminada en NUL, que especifica el prompt que se presentará al usuario. Por defecto, los prompts se muestran literalmente, pero si se habilitan con la función gl_prompt_style() (ver más adelante), los prompts pueden contener directivas para hacer subrayados, cambiar a y desde fuentes en negrita, o activar y desactivar el resaltado.

Si desea especificar el contenido inicial de la línea, para que el usuario lo edite, pase la cadena deseada a través del argumento start_line. Luego puede especificar en qué carácter de esta línea se posiciona inicialmente el cursor

Si no desea precargar la línea de esta manera, envíe start_line como NULL y establezca start_pos en -1. Tenga en cuenta que el puntero de línea devuelto por una llamada a gl_get_line() puede pasarse a la siguiente llamada a gl_get_line() a través de start_line. Esto permite que la aplicación tome la última línea introducida y, si contiene un error, la presente nuevamente al usuario para que la edite, con el cursor inicialmente posicionado donde se encontró el error.

La función gl_get_line() devuelve un puntero a la línea introducida por el usuario, o NULL en caso de error o al final de la entrada. El puntero devuelto es parte del objeto de recurso gl especificado y, por lo tanto, no debe ser liberado por el llamador, ni se debe asumir que es inmutable de una llamada a otra. Al leer de un usuario en una terminal, siempre habrá un carácter de nueva línea al final de la línea devuelta. Cuando la entrada estándar se está tomando de una tubería o un archivo, de manera similar habrá una nueva línea a menos que la línea de entrada fuera demasiado larga para almacenarla en el búfer interno. En este último caso, debería llamar a gl_get_line() nuevamente para leer el resto de la línea. Tenga en cuenta que este comportamiento hace que gl_get_line() sea similar a fgets(). De hecho, cuando stdin no está conectado a una terminal, gl_get_line() solo llama a fgets().

  const char *gl_error_message(GetLine *gl, char *buff,
                               size_t n);

El valor de retorno es un puntero al mensaje que ocurrió. Si el argumento buff es NULL, será un puntero a un búfer dentro de gl, cuyo valor probablemente cambiará en la próxima llamada a cualquier función asociada con gl_get_line(). Si el mensaje no cabe en el búfer proporcionado, se truncará para que quepa.

FORMATO OPCIONAL DEL PROMPT

Mientras que por defecto la cadena de prompt que usted especifica se muestra literalmente, sin ninguna interpretación especial de los caracteres dentro de ella, la función gl_prompt_style() se puede usar para habilitar directivas de formato opcionales dentro del prompt.

  void gl_prompt_style(GetLine *gl, GlPromptStyle style);

El argumento style, que especifica el estilo de formato, puede tomar cualquiera de los siguientes valores:

  GL_FORMAT_PROMPT   -  En este estilo, las directivas de
                        formato descritas a continuación,
                        cuando se incluyen en cadenas de
                        prompt, se interpretan de la
                        siguiente manera:
                          %B  -  Mostrar los caracteres
                                 subsiguientes en negrita.
                          %b  -  Dejar de mostrar caracteres
                                 en negrita.
                          %F  -  Hacer que los caracteres
                                 subsiguientes parpadeen.
                          %f  -  Desactivar el parpadeo de
                                 caracteres.
                          %U  -  Subrayar los caracteres
                                 subsiguientes.
                          %u  -  Dejar de subrayar caracteres.
                          %P  -  Cambiar a una fuente pálida
                                 (brillo medio).
                          %p  -  Dejar de usar la fuente
                                 pálida.
                          %S  -  Resaltar los caracteres
                                 subsiguientes (también conocido
                                 como modo de contraste).
                          %s  -  Dejar de resaltar caracteres.
                          %V  -  Activar video inverso.
                          %v  -  Desactivar video inverso.
                          %%  -  Mostrar un solo carácter %
                                 literal.
                        Por ejemplo, en este modo, una cadena de
                        prompt como "%UOK%u$ "
                        mostraría el prompt
                        "OK$ ", pero con la parte
                        OK subrayada.

                        caracteres que comienza con un carácter %
                        que no coincide con ninguna de las
                        directivas anteriores se muestra
                        literalmente, si posteriormente se
                        introduce una nueva directiva que
                        coincide, el prompt mostrado cambiará,
                        por lo que es mejor usar siempre %% para
                        mostrar un %.

                        terminales admiten todos estos atributos de
                        texto, y que algunas sustituyen un
                        atributo diferente por los que faltan.

                        se imprime literalmente. Este es el
                        estilo predeterminado.

FUENTES DE CONFIGURACION ALTERNATIVAS

Como se mencionó anteriormente, por defecto los usuarios tienen la opción de configurar el comportamiento de gl_get_line() a través de un archivo de configuración llamado .teclarc en sus directorios de inicio. El hecho de que todas las aplicaciones compartan este mismo archivo de configuración es tanto una ventaja como una desventaja. En la mayoría de los casos es una ventaja, ya que fomenta la uniformidad y libera al usuario de tener que configurar cada aplicación por separado. Sin embargo, en algunas aplicaciones, este único medio de configuración es un problema. Esto es particularmente cierto en el software embebido, donde no hay un sistema de archivos para leer un archivo de configuración, y también en aplicaciones donde se necesita una elección radicalmente diferente de asignaciones de teclas para emular una interfaz de teclado heredada. Para atender tales casos, la siguiente función permite a la aplicación controlar desde dónde se leen las informaciones de configuración.

  int gl_configure_getline(GetLine *gl,
                           const char *app_string,
                           const char *app_file,
                           const char *user_file);

Permite que los comandos de configuración que normalmente se leerían del archivo ~/.teclarc del usuario, se lean de cualquiera o ninguna de las siguientes opciones: una cadena, un archivo de configuración específico de la aplicación y/o un archivo de configuración específico del usuario. Si esta función se llama antes de la primera llamada a gl_get_line(), se deshabilita el comportamiento predeterminado de leer ~/.teclarc en la primera llamada a gl_get_line(), por lo que toda la configuración debe lograrse utilizando las fuentes de configuración especificadas con esta función.

Si app_string != NULL, entonces se interpreta como una cadena que contiene uno o más comandos de configuración, separados entre sí en la cadena por caracteres de nueva línea incrustados. Si app_file != NULL, entonces se interpreta como la ruta completa de un archivo de configuración específico de la aplicación. Si user_file != NULL, entonces se interpreta como la ruta completa de un archivo de configuración específico del usuario, como ~/.teclarc. Por ejemplo, en la siguiente llamada,

  gl_configure_getline(gl, "edit-mode vi \n nobeep",
                           "/usr/share/myapp/teclarc",
                           "~/.teclarc");

el argumento app_string hace que la aplicación que llama comience en modo de edición vi, en lugar del modo emacs predeterminado, y desactiva el uso de la campana de la terminal por parte de la biblioteca. Luego intenta leer comandos de configuración a nivel de sistema de un archivo opcional llamado /usr/share/myapp/teclarc, y finalmente lee comandos de configuración específicos del usuario de un archivo .teclarc opcional en el directorio de inicio del usuario. Tenga en cuenta que los argumentos se enumeran en orden ascendente de prioridad, y el contenido de app_string puede ser anulado por comandos en app_file, y los comandos en app_file pueden ser anulados por comandos en user_file.

Puede llamar a esta función tantas veces como sea necesario, siendo los resultados acumulativos, pero tenga en cuenta que copias de cualquier nombre de archivo especificado a través del argumento **app_fi

CUSTOMIZACIÓN DE ACCIONES DE COMPLETADO

En la sección anterior se describió la capacidad de personalizar el comportamiento de la única acción de completado predeterminada, complete-word. En esta sección se describe la capacidad de instalar funciones de acción adicionales, para que diferentes tipos de completado de palabras puedan enlazarse a diferentes secuencias de teclas. Esto se logra utilizando la función gl_completion_action().

  int gl_completion_action(GetLine *gl,
                           void *data, CplMatchFn *match_fn,
                           int list_only, const char *name,
                           const char *keyseq);

Los argumentos data y match_fn son como se describe en la página del manual de cpl_complete_word, y especifican la función de devolución de llamada que debe invocarse para identificar posibles completados. El argumento list_only determina si la acción que se está definiendo debe intentar completar la palabra lo máximo posible en la línea de entrada antes de mostrar posibles completados ambiguos, o si simplemente debe mostrar la lista de posibles completados sin tocar la línea de entrada. La primera opción se selecciona especificando un valor de 0, y la segunda especificando un valor de 1. El argumento name especifica el nombre por el cual los archivos de configuración y las invocaciones futuras de esta función deben referirse a la acción. Este debe ser el nombre de una acción de completado existente que se va a modificar, o un nuevo nombre no utilizado para una nueva acción. Finalmente, el argumento keyseq especifica la secuencia de teclas predeterminada a la que se enlazará la acción. Si es NULL, no se enlazará ninguna nueva secuencia de teclas a la acción.

Tenga en cuenta que para que el usuario pueda cambiar la secuencia de teclas enlazada a las acciones que se instalan de esta manera, cuando llame a gl_completion_action() para instalar una acción dada por primera vez, debería hacerlo entre la llamada a new_GetLine() y la primera llamada a gl_get_line(). De lo contrario, cuando se lea el archivo de configuración del usuario en la primera llamada a gl_get_line(), el nombre de su acción adicional no se conocerá y cualquier referencia a él en el archivo de configuración generará un error.

Como se discutió para gl_customize_completion(), si su función de devolución de llamada, por alguna razón, necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo.

DEFINICIÓN DE ACCIONES PERSONALIZADAS

Aunque las acciones integradas de enlace de teclas son suficientes para las necesidades de la mayoría de las aplicaciones, ocasionalmente una aplicación especializada puede necesitar definir una o más acciones personalizadas, enlazadas a secuencias de teclas específicas de la aplicación. Por ejemplo, una aplicación de ventas se beneficiaría de tener una secuencia de teclas que mostrara el nombre de la pieza correspondiente a un número de pieza que precediera al cursor. Dicha característica está claramente fuera del alcance de las funciones de acción integradas. Por lo tanto, para tales casos especiales, se proporciona la función gl_register_action().

  int gl_register_action(GetLine *gl, void *data,
			 GlActionFn *fn, const char *name,
			 const char *keyseq);

Esta función permite a la aplicación registrar una función externa, fn, que posteriormente será llamada cada vez que el usuario introduzca la secuencia de teclas especificada, keyseq, o cualquier otra secuencia de teclas que el usuario enlace posteriormente al nombre de acción especificado, name, en su archivo de configuración. El argumento data puede ser un puntero a cualquier cosa que la aplicación desee pasar a la función de acción, fn, cada vez que se invoque esa función.

La función de acción, fn, debe declararse utilizando la siguiente macro, que está definida en libtecla.h.

  #define GL_ACTION_FN(fn) GlAfterAction (fn)(GetLine *gl, \
              void *data, int count, size_t curpos, \
              const char *line)

Los argumentos gl y data son los que se pasaron previamente a gl_register_action() cuando se registró la función de acción. El argumento count es un argumento numérico que el usuario tiene la opción de introducir utilizando la acción digit-argument, antes de invocar la acción. Si el usuario no introduce un número, el argumento count se establece en 1. Nominalmente, este argumento se interpreta como un recuento de repeticiones, lo que significa que la acción debería repetirse tantas veces. En la práctica, sin embargo, para algunas acciones un recuento de repeticiones tiene poco sentido. En tales casos, las acciones pueden simplemente ignorar el argumento count o utilizar su valor para un propósito diferente.

Se pasa una copia de la línea de entrada actual en el argumento de solo lectura line. La posición actual del cursor dentro de esta cadena se da por el índice contenido en el argumento curpos. Tenga en cuenta que no se permite la manipulación directa de la línea de entrada y la posición del cursor. Esto se debe a que las reglas dictadas por varios modos, como el modo vi frente al modo emacs, el modo sin eco y el modo de inserción frente al modo de sobrescritura, etc., hacen que sea demasiado complejo para un desarrollador de aplicaciones escribir una acción de edición conforme, además de limitar los cambios futuros en los detalles internos de gl_get_line(). Una solución potencial a este dilema sería permitir que la función de acción edite la línea utilizando las acciones de edición existentes. Esto está actualmente en consideración.

Si la función de acción desea escribir texto en la terminal, sin que esto se mezcle con el texto mostrado de la línea de entrada, o leer de la terminal sin tener que manejar E/S de terminal en bruto, entonces antes de realizar cualquiera de estas operaciones, debe suspender temporalmente la edición de línea llamando a la función gl_normal_io(). Esta función vacía cualquier salida pendiente a la terminal, mueve el cursor al inicio de la línea que sigue a la última línea de terminal de la línea de entrada, luego restaura la terminal a un estado adecuado para su uso con las instalaciones de E/S estándar de C. Esto último incluye cosas como restaurar el mapeo normal de \n a \r\n y, cuando está en modo servidor, restaurar la forma de bloqueo normal de la E/S de terminal. ARCHIVOS DE HISTORIAL

Para guardar el contenido del búfer de historial antes de salir de su aplicación, y posteriormente restaurarlo cuando inicie la aplicación la próxima vez, se proporcionan las siguientes funciones.

 int gl_save_history(GetLine *gl, const char *filename,
                     const char *comment, int max_lines);
 int gl_load_history(GetLine *gl, const char *filename,
                     const char *comment);

El argumento filename especifica el nombre que se le dará al archivo de historial al guardar, o el nombre de un archivo de historial existente, al cargar. Esto puede contener expresiones de directorio de inicio y variables de entorno, como "~/.myapp_history" o "$HOME/.myapp_history".

Junto con cada línea del historial, se registra información adicional sobre ella, como cuándo fue ingresada por el usuario y cuál es su nivel de anidamiento, como un comentario que precede a la línea en el archivo de historial. Escribir esto como un comentario permite que el archivo de historial sirva también como un archivo de comandos, por si desea reproducir toda una sesión usándolo. Dado que los prefijos de comentario difieren en diferentes idiomas, el argumento comment se proporciona para especificar el prefijo de comentario. Por ejemplo, si su aplicación fuera un shell de Unix, como el shell bourne, especificaría "#" aquí. Cualquiera que sea el carácter de comentario que elija, debe especificar el mismo prefijo a gl_load_history() que usó cuando llamó a gl_save_history() para escribir el archivo de historial.

El argumento max_lines debe ser -1 para especificar que se guarden todas las líneas de la lista de historial, o un número positivo que especifique un límite superior de cuántas de las líneas más recientes se deben guardar.

Ambas funciones devuelven un valor distinto de cero en caso de error, después de escribir un mensaje de error en stderr. Tenga en cuenta que gl_load_history() no considera la no existencia de un archivo como un error.

LISTAS DE HISTORIAL MÚLTIPLES

Si su aplicación utiliza un único objeto GetLine para ingresar muchos tipos diferentes de líneas de entrada, es posible que desee que gl_get_line() distinga los diferentes tipos de líneas en la lista de historial, y solo recupere líneas que coincidan con el tipo de línea actual. Para soportar este requisito, gl_get_line() marca las líneas que se registran en la lista de historial con un identificador entero elegido por la aplicación. Inicialmente, este identificador se establece en 0 por new_GetLine(), pero puede cambiarse posteriormente llamando a gl_group_history().

  int gl_group_history(GetLine *gl, unsigned id);

El identificador entero id puede ser cualquier número elegido por la aplicación, pero tenga en cuenta que gl_save_history() y gl_load_history() preservan la asociación entre los identificadores y las líneas de entrada históricas entre invocaciones del programa, por lo que debería elegir identificadores fijos para los diferentes tipos de líneas de entrada utilizados por su aplicación.

Siempre que gl_get_line() agrega una nueva línea de entrada a la lista de historial, se registra el identificador de historial actual con ella, y cuando se le pide que recupere una línea de entrada histórica, solo recupera las líneas que están marcadas con el identificador actual.

La lista de historial se puede mostrar llamando a gl_show_history().

ARCHIVO MANUAL DEL HISTORIAL

Por defecto, cada vez que el usuario ingresa una línea, esta se agrega automáticamente a la lista de historial, justo antes de que gl_get_line() devuelva la línea al llamante. Esto es conveniente para la mayoría de las aplicaciones, pero también hay aplicaciones que necesitan un control más detallado sobre lo que se agrega a la lista de historial. En tales casos, la adición automática de líneas ingresadas a la lista de historial se puede desactivar llamando a la función gl_automatic_history().

  int gl_automatic_history(GetLine *gl, int enable);

Si se llama a esta función con su argumento enable establecido en 0, gl_get_line() no archivará automáticamente las líneas ingresadas posteriormente. El archivado automático se puede reactivar más tarde, llamando a esta función nuevamente, con su argumento enable establecido en 1. Mientras el archivado automático del historial está desactivado, la aplicación llamante puede usar gl_append_history() para agregar líneas a la lista de historial según sea necesario.

  int gl_append_history(GetLine *gl, const char *line);

El argumento line especifica la línea que se agregará a la lista de historial. Debe ser una cadena normal terminada en '\0'. Si esta cadena contiene algún carácter de nueva línea, la línea que se archiva en la lista de historial se terminará con el primero de ellos. De lo contrario, se terminará con el terminador '\0'. Si la línea es más larga que la longitud máxima de línea de entrada, que se especificó cuando se llamó a new_GetLine(), cuando se recupere, se truncará a la longitud real de la línea de gl_get_line().

Si tiene éxito, gl_append_history() devuelve 0. De lo contrario, devuelve un valor distinto de cero y establece errno en uno de los siguientes valores.

   EINVAL  -  Uno de los argumentos pasados a
              gl_append_history() era NULL.
   ENOMEM  -  La línea especificada era más larga que el tamaño
              asignado del búfer de historial (como se especificó
              al llamar a new_GetLine()), por lo que no pudo ser
              archivada.

Una descripción textual del error se puede obtener opcionalmente llamando a gl_error_message(). Tenga en cuenta que después de un error de este tipo, la lista de historial permanece en un estado válido para recibir nuevas líneas de historial, por lo que hay poco daño en simplemente ignorar el estado de retorno de gl_append_history().

CAMBIO DE TERMINALES

La función constructora new_GetLine() asume que la entrada se leerá de stdin y la salida se escribirá en stdout. La siguiente función le permite cambiar a diferentes flujos de entrada y salida.

  int gl_change_terminal(GetLine *gl, FILE *input_fp,
                         FILE *output_fp, const char *term);

El argumento gl es el objeto devuelto por new_GetLine(). El argumento input_fp especifica el flujo del que leer, y output_fp especifica el flujo en el que escribir. Solo si ambos se refieren a una terminal, se habilitará la entrada interactiva de terminal. De lo contrario, gl_get_line() simplemente llamará a fgets() para leer la entrada del comando. Si ambos flujos se refieren a una terminal, deben referirse a la misma terminal, y el tipo de esta terminal debe especificarse a través del argumento term. El valor del argumento term se busca en la base de datos de información de terminales (terminfo o termcap), para determinar qué secuencias de control especiales se necesitan para controlar varios aspectos de la terminal. new_GetLine(), por ejemplo, pasa el valor de retorno de getenv("TERM") en este argumento. Tenga en cuenta que si uno o ambos de input_fp y output_fp no se refieren a una terminal, entonces es legal pasar NULL en lugar de un tipo de terminal.

Tenga en cuenta que si desea pasar descriptores de archivo a gl_change_terminal(), puede hacerlo creando envoltorios de flujo stdio utilizando la función POSIX fdopen().

MANEJO DE EVENTOS EXTERNOS

Por defecto, gl_get_line() no devuelve hasta que el usuario haya introducido una línea de entrada completa o se produzca un error. En programas que necesitan observar E/S de otras fuentes distintas de la terminal, existen dos opciones.

  1. Utilice las funciones descritas en la página del manual
     gl_io_mode(3) para cambiar
     gl_get_line() al modo de servidor no bloqueante. En este modo,
     gl_get_line() se convierte en una función de edición de línea
     incremental y no bloqueante que se puede llamar de forma segura desde
     un bucle de eventos externo. Aunque este es un método muy versátil,
     implica asumir algunas responsabilidades que normalmente realiza
     gl_get_line() entre bastidores.
  2. Mientras gl_get_line() espera la entrada del teclado del usuario,
     puede pedirle que también observe la actividad en descriptores de archivo
     arbitrarios, como sockets de red, tuberías, etc., y que llame a funciones
     de su elección cuando se observe actividad. Esto funciona en cualquier
     sistema que tenga la llamada al sistema select(), que es la
     mayoría, si no todas, las versiones de Unix.

Registrar un descriptor de archivo para ser observado por gl_get_line() implica llamar a la función gl_watch_fd().

  int gl_watch_fd(GetLine *gl, int fd, GlFdEvent event,
                  GlFdEventFn *callback, void *data);

Si esto devuelve un valor distinto de cero, significa que sus argumentos no son válidos o que esta funcionalidad no es compatible en el sistema anfitrión.

El argumento fd es el descriptor de archivo a observar. El argumento event especifica qué tipo de actividad es de interés, elegido entre los siguientes valores enumerados:

  GLFD_READ   - Observar la llegada de datos para leer.
  GLFD_WRITE  - Observar la capacidad de escribir en el descriptor
                de archivo sin bloquear.
  GLFD_URGENT - Observar la llegada de datos urgentes fuera de banda
                en el descriptor de archivo.

El argumento callback es la función que se llamará cuando se observe la actividad seleccionada. Debe definirse con la siguiente macro, que está definida en libtecla.h.

  #define GL_FD_EVENT_FN(fn) GlFdStatus (fn)(GetLine *gl, \
                                      void *data, int fd, \
                                      GlFdEvent event)

El argumento data de la función gl_watch_fd() se pasa a la función de devolución de llamada para su propio uso, y puede apuntar a lo que desee, incluido NULL. El descriptor de archivo y el argumento del evento también se pasan a la función de devolución de llamada, lo que potencialmente permite que la misma función de devolución de llamada se registre para más de un tipo de evento y/o más de un descriptor de archivo. El valor de retorno de la función de devolución de llamada debe ser uno de los siguientes valores.

  GLFD_ABORT    - Indicar a gl_get_line() que aborte. Cuando esto
                   ocurre, gl_get_line() devuelve
                   NULL, y una llamada posterior a
                   gl_return_status() devolverá
                   GLR_FDABORT. Tenga en cuenta que si la
                   aplicación necesita que errno siempre tenga
                   un valor significativo cuando
                   gl_get_line() devuelve NULL,
                   la función de devolución de llamada debe establecer
                   errno apropiadamente.
  GLFD_REFRESH  - Redibujar la línea de entrada y luego continuar
                   esperando entrada. Devuelva esto si su
                   devolución de llamada escribió en la terminal.
  GLFD_CONTINUE - Continuar esperando entrada, sin redibujar la línea.

Tenga en cuenta que antes de llamar a la devolución de llamada, gl_get_line() bloquea la mayoría de las señales y deja instalados sus propios manejadores de señales, por lo que si necesita capturar una señal particular, deberá instalar temporalmente su propio manejador de señales y desbloquear la señal. Asegúrese de volver a bloquear la señal (si estaba bloqueada originalmente) y restaurar el manejador de señales original, si lo hubiera, antes de regresar.

Si la función de devolución de llamada necesita leer o escribir en la terminal, idealmente debería llamar primero a gl_normal_io(gl) para suspender temporalmente la edición de línea. Esto restaurará la terminal al modo canónico de E/S bloqueante y moverá el cursor al inicio de una nueva línea de terminal. Más tarde, cuando la devolución de llamada regrese, gl_get_line() notará que se llamó a gl_normal_io(), redibujará la línea de entrada y reanudará la edición. Tenga en cuenta que en este caso los valores de retorno, GLFD_REFRESH y GLFD_CONTINUE son equivalentes.

Para admitir casos en los que la función de devolución de llamada llama a una función de terceros que ocasionalmente y de forma impredecible escribe en la terminal, la conversión automática de "0 a "0 se vuelve a habilitar antes de que se llame a la función de devolución de llamada. Si la devolución de llamada sabe que la función de terceros escribió en la terminal, entonces debería devolver el valor de retorno GLFD_REFRESH, para indicar a gl_get_line() que redibuje la línea de entrada.

Para eliminar una función de devolución de llamada que registró previamente para un descriptor de archivo y evento dados, simplemente llame a gl_watch_fd() con los mismos argumentos de descriptor de archivo y event, pero con un argumento callback de 0. El argumento data se ignora en este caso.

                   GLR_BLOCKED.

Tenga en cuenta que antes de llamar a la retrollamada, gl_get_line() bloquea la mayoría de las señales y deja sus propios manejadores de señales instalados, por lo que si necesita capturar una señal particular, deberá instalar temporalmente su propio manejador de señales y desbloquear la señal. Asegúrese de volver a bloquear la señal (si estaba originalmente bloqueada) y restablecer el manejador de señales original, si lo hay, antes de regresar.

Si la función de retrollamada necesita leer o escribir en la terminal, idealmente debería llamar primero a gl_normal_io(gl) para suspender temporalmente la edición de línea. Esto restaurará la terminal al modo canónico de E/S bloqueante y moverá el cursor al inicio de una nueva línea de terminal. Más tarde, cuando la retrollamada regrese, gl_get_line() notará que se llamó a gl_normal_io(), redibujará la línea de entrada y reanudará la edición. Tenga en cuenta que en este caso los valores de retorno, GLTO_REFRESH y GLTO_CONTINUE son equivalentes.

Para admitir casos en los que la función de retrollamada llama a una función de terceros que ocasionalmente y de forma impredecible escribe en la terminal, la conversión automática de "0 a "0 se vuelve a habilitar antes de que se llame a la función de retrollamada. Si la retrollamada sabe que la función de terceros escribió en la terminal, debe devolver el valor de retorno GLTO_REFRESH para indicarle a gl_get_line() que redibuje la línea de entrada.

Tenga en cuenta que aunque el argumento de tiempo de espera incluye un componente de nanosegundo, pocos relojes de computadora tienen actualmente resoluciones más finas que unos pocos milisegundos, por lo que solicitar menos de unos pocos milisegundos es equivalente a solicitar cero segundos en muchos sistemas. Si esto fuera un problema, debería basar su selección de tiempo de espera en la resolución real del reloj del host (por ejemplo, llamando a sysconf(_SC_CLK_TCK)).

Para desactivar los tiempos de espera, simplemente llame a gl_inactivity_timeout() con un argumento callback de 0. El argumento data se ignora en este caso.

VALORES PREDETERMINADOS DE MANEJO DE SEÑALES

Por defecto, la función gl_get_line() intercepta varias señales. Esto es particularmente importante para las señales que, por defecto, terminarían el proceso, ya que la terminal debe restaurarse a un estado utilizable antes de que esto suceda. En esta sección, se describen las señales que se capturan por defecto y cómo responde gl_get_line() a ellas. El cambio de estos valores predeterminados es el tema de la siguiente sección.

Cuando se capturan el siguiente subconjunto de señales, gl_get_line() primero restaura la configuración de la terminal y el manejo de señales a cómo estaban antes de que se llamara a gl_get_line(), reenvía la señal, para permitir que los manejadores de señales de la aplicación que llama la manejen, y luego, si el proceso aún existe, gl_get_line() devuelve NULL y establece errno según se especifica a continuación.

 SIGINT  -  Esta señal se genera tanto por la tecla de
            interrupción del teclado (generalmente ^C) como
            por la tecla de interrupción del teclado.
            errno=EINTR
 SIGHUP  -  Esta señal se genera cuando sale la terminal de
            control.
            errno=ENOTTY
 SIGPIPE -  Esta señal se genera cuando un programa intenta
            escribir en una tubería cuya extremo remoto no está
            siendo leído por ningún proceso. Esto puede suceder,
            por ejemplo, si ha llamado a gl_change_terminal()
            para redirigir la salida a una tubería oculta bajo
            una pseudo terminal.
            errno=EPIPE
 SIGQUIT -  Esta señal se genera por la tecla de salida del
            teclado (generalmente ^\).
            errno=EINTR
 SIGABRT -  Esta señal se genera por la función estándar C,
            abort(). Por defecto, termina el proceso y genera
            un volcado del núcleo.
            errno=EINTR
 SIGTERM -  Esta es la señal predeterminada que el comando
            UN*X kill envía a los procesos.
            errno=EINTR

Tenga en cuenta que en el caso de todas las señales anteriores, POSIX exige que, por defecto, el proceso termine, con la adición de un volcado del núcleo en el caso de la señal SIGQUIT. En otras palabras, si la aplicación que llama no anula el manejador predeterminado proporcionando su propio manejador de señales, la recepción de la señal correspondiente terminará la aplicación antes de que gl_get_line() regrese.

Si gl_get_line() se interrumpe con errno establecido en EINTR, puede averiguar qué señal provocó la interrupción llamando a la siguiente función.

  int gl_last_signal(const GetLine *gl);

Esto devuelve el código numérico (por ejemplo, SIGINT) de la última señal recibida durante la llamada más reciente a gl_get_line(), o -1 si no se recibieron señales.

En sistemas que lo admiten, cuando se recibe una señal SIGWINCH (cambio de ventana), gl_get_line() consulta la terminal para determinar su nuevo tamaño, redibuja la línea de entrada actual para acomodar el nuevo tamaño, luego regresa a esperar la entrada del teclado del usuario. A diferencia de otras señales, esta señal no se reenvía a la aplicación.

Finalmente, las siguientes señales hacen que gl_get_line() restaure primero la configuración de la terminal y de señales a la que prevalecía antes de que se llamara a gl_get_line(), luego reenvíe la señal a la aplicación. Si el proceso aún existe después de que se entregue la señal, entonces gl_get_line() reestablece sus propios manejadores de señales, cambia la terminal de nuevo a modo crudo, redibuja la línea de entrada y vuelve a esperar la entrada de la terminal del usuario.

 SIGCONT    -  Esta señal se genera cuando se reanuda un
               proceso suspendido.
 SIGPOLL    -  En sistemas SVR4, esta señal notifica al
               proceso de un evento de E/S asíncrono. Tenga
               en cuenta que bajo 4.3+BSD, SIGIO y SIGPOLL son
               lo mismo. En otros sistemas, SIGIO es ignorada
               por defecto, por lo que gl_get_line() no
               la captura por defecto.
 SIGPWR     -  Esta señal se genera cuando ocurre una falla de
               alimentación (presumiblemente cuando el sistema
               está en un UPS).
 SIGALRM    -  Esta señal se genera cuando expira un temporizador.
 SIGUSR1    -  Una señal específica de la aplicación.
 SIGUSR2    -  Otra señal específica de la aplicación.
 SIGVTALRM  -  Esta señal se genera cuando expira un temporizador
               virtual (ver man setitimer(2)).
 SIGXCPU    -  Esta señal se genera cuando un proceso excede
               su límite de tiempo de CPU blando.
 SIGXFSZ    -  Esta señal se genera cuando un proceso excede
               su límite de tamaño de archivo blando.
 SIGTSTP    -  Esta señal se genera por la tecla de suspensión
               de la terminal, que suele ser ^Z, o la tecla de
               suspensión retardada de la terminal, que suele
               ser ^Y.
 SIGTTIN    -  Esta señal se genera si el programa intenta
               leer de la terminal mientras el programa se
               ejecuta en segundo plano.
 SIGTTOU    -  Esta señal se genera si el programa intenta
               escribir en la terminal mientras el programa se
               ejecuta en segundo plano.

Obviamente, no todas las señales anteriores son compatibles en todos los sistemas, por lo que el código para admitirlas se compila condicionalmente en la biblioteca tecla.

Tenga en cuenta que si SIGKILL o SIGPOLL, que por definición no pueden ser capturadas, o cualquiera de las señales de excepción generadas por hardware, como SIGSEGV, SIGBUS y SIGFPE, se reciben y no se manejan mientras gl_get_line() tiene la terminal en modo crudo, el programa terminará sin que la terminal se restaure a un estado utilizable. En la práctica, los shells de control de trabajos suelen restablecer la configuración de la terminal cuando un proceso renuncia a la terminal de control, por lo que esto solo es un problema con shells más antiguos.

MANEJO DE SEÑALES PERSONALIZADO

La sección anterior enumeró las señales que gl_get_line() captura por defecto y describió cómo responde a ellas. Esta sección describe cómo agregar y eliminar señales de la lista de señales capturadas, y cómo especificar cómo gl_get_line() debe responder a una señal dada.

Si no necesita que gl_get_line() haga nada en respuesta a una señal que normalmente captura, puede indicarle a gl_get_line() que ignore esa señal llamando a gl_ignore_signal().

  int gl_ignore_signal(GetLine *gl, int signo);

El argumento signo es el número de la señal (por ejemplo, SIGINT) que desea que se ignore. Si la señal especificada no es actualmente una de las que se están capturando, esta función no hace nada.

La función gl_trap_signal() le permite agregar una nueva señal a la lista que gl_get_line() captura, o modificar cómo responde

al una señal que ya atrapa.

  int gl_trap_signal(GetLine *gl, int signo, unsigned flags,
                     GlAfterSignal after, int errno_value);

El argumento signo es el número de la señal que desea que se atrape. El argumento flags es un conjunto de banderas que determinan el entorno en el que se invoca el manejador de señales de la aplicación, el argumento after le indica a gl_get_line() qué hacer después de que el manejador de señales de la aplicación regrese, y errno_value le indica a gl_get_line() qué establecer en errno si se le indica que aborte.

El argumento flags es una OR a nivel de bits de cero o más de los siguientes enumeradores:

  GLS_RESTORE_SIG  -  Restaura el entorno de señales del
                      llamador mientras maneja la señal.
  GLS_RESTORE_TTY  -  Restaura la configuración de terminal del
                      llamador mientras maneja la señal.
  GLS_RESTORE_LINE -  Mueve el cursor al inicio de la línea
                      siguiente a la línea de entrada antes de
                      invocar el manejador de señales de la
                      aplicación.
  GLS_REDRAW_LINE  -  Redibuja la línea de entrada cuando el
                      manejador de señales de la aplicación
                      regrese.
  GLS_UNBLOCK_SIG  -  Normalmente, si el programa que llama tiene
                      una señal bloqueada (man sigprocmask),
                      gl_get_line() no atrapa esa señal. Esta
                      bandera le dice a gl_get_line() que atrape
                      la señal y la desbloquee durante la
                      duración de la llamada a gl_get_line().
  GLS_DONT_FORWARD -  Si se incluye esta bandera, la señal no se
                      reenviará al manejador de señales del
                      programa que llama.

Dos combinaciones de banderas comúnmente útiles también se enumeran de la siguiente manera:

  GLS_RESTORE_ENV   = GLS_RESTORE_SIG | GLS_RESTORE_TTY |
                      GLS_REDRAW_LINE
  GLS_SUSPEND_INPUT = GLS_RESTORE_ENV | GLS_RESTORE_LINE

Si su manejador de señales, o el manejador de señales predeterminado del sistema para esta señal, si no lo ha anulado, nunca escribe en la terminal, ni suspende o termina el programa que llama, entonces puede establecer de forma segura el argumento flags a 0.

Si su manejador de señales siempre escribe en la terminal, lee de ella, o suspende o termina el programa, debe especificar el argumento flags como GL_SUSPEND_INPUT, para que:

1. El cursor no quede en medio de la línea de entrada.
2. Para que el usuario pueda escribir entrada y que esta sea
   mostrada.
3. Para que no necesite terminar cada línea de salida con
   \r\n, en lugar de solo \n.

La combinación GL_RESTORE_ENV es la misma que GL_SUSPEND_INPUT, excepto que no mueve el cursor, y si su manejador de señales no lee ni escribe nada en la terminal, el usuario no verá ninguna indicación visible de que se capturó una señal. Esto puede ser útil si tiene un manejador de señales que ocasionalmente escribe en la terminal, donde usar GL_SUSPEND_LINE haría que la línea de entrada se duplicara innecesariamente cuando no se ha escrito nada en la terminal. Dicho manejador de señales, cuando escribe en la terminal, debe asegurarse de comenzar una nueva línea al principio de su primera escritura, escribiendo una nueva línea antes de regresar. Si la señal llega mientras el usuario está introduciendo una línea que solo ocupa una línea de terminal de señal, o si el cursor está en la última línea de terminal de una línea de entrada más larga, esto tendrá el mismo efecto que GL_SUSPEND_INPUT. De lo contrario, comenzará a escribir en una línea que ya contiene parte de la línea de entrada mostrada. Esto no causa ningún daño, pero se ve un poco feo, por lo que la combinación GL_SUSPEND_INPUT es mejor si sabe que siempre va a escribir en la terminal.

El argumento after, que determina lo que hace gl_get_line() después de que regresa el manejador de señales de la aplicación (si regresa), puede tomar cualquiera de los siguientes valores:

  GLS_RETURN   - Devuelve la línea de entrada completada, como
                 si el usuario hubiera presionado la tecla de
                 retorno.
  GLS_ABORT    - Hace que gl_get_line() aborte. Cuando
                 esto sucede, gl_get_line() devuelve
                 NULL, y una llamada posterior a
                 gl_return_status() devolverá
                 GLR_SIGNAL. Tenga en cuenta que si la
                 aplicación necesita que errno siempre
                 tenga un valor significativo cuando
                 gl_get_line() devuelve NULL,
                 la función de devolución de llamada debe
                 establecer errno apropiadamente.
  GLS_CONTINUE - Reanuda la edición de la línea de comandos.

El argumento errno_value está destinado a combinarse con la opción GLS_ABORT, indicando a gl_get_line() qué establecer la variable estándar errno antes de devolver NULL al programa que llama. Sin embargo, también se puede usar con la opción GL_RETURN, en caso de que desee tener una forma de distinguir entre una línea de entrada que se introdujo usando la tecla de retorno y una que se introdujo por la recepción de una señal.

MANEJO DE SEÑALES CONFIABLE

El manejo de señales es sorprendentemente difícil de hacer de forma confiable sin condiciones de carrera. En gl_get_line() se ha puesto mucha atención para permitir que las aplicaciones realicen un manejo de señales confiable alrededor de gl_get_line(). Esta sección explica cómo hacer uso de esto.

Como ejemplo de los problemas que pueden surgir si la aplicación no está escrita correctamente, imagine que una aplicación tiene un manejador de señales SIGINT que establece una bandera global. Ahora suponga que la aplicación prueba esta bandera justo antes de invocar gl_get_line(). Si una señal SIGINT se recibe en la pequeña ventana de tiempo entre la declaración que prueba el valor de esta bandera y la declaración que llama a gl_get_line(), entonces gl_get_line() no verá la señal y no será interrumpida. Como resultado, la aplicación no podrá responder a la señal hasta que el usuario termine de introducir la línea de entrada y gl_get_line() regrese. Dependiendo de la aplicación, esto puede ser o no un desastre, pero al menos confundirá al usuario.

La forma de evitar tales problemas es hacer lo siguiente.

1. Si es necesario, use la función gl_trap_signal() para configurar gl_get_line() para que aborte cuando se capturen señales importantes.

2. Configure gl_get_line() de manera que si alguna de las señales que captura está bloqueada cuando se llama a gl_get_line(), se desbloquearán automáticamente durante los momentos en que gl_get_line() esté esperando E/S. Esto se puede hacer ya sea por señal individualmente, llamando a la función gl_trap_signal() y especificando el atributo GLS_UNBLOCK de la señal, o globalmente llamando a la función gl_catch_blocked().

     void gl_catch_blocked(GetLine *gl);


Esta función simplemente agrega el atributo
GLS_UNBLOCK a todas las señales que
actualmente está configurado para atrapar.

3. Justo antes de llamar a gl_get_line(), bloquee la entrega de todas las señales que gl_get_line() está configurado para atrapar. Esto se puede hacer usando la función POSIX sigprocmask() en conjunción con la función gl_list_signals().

      int gl_list_signals(GetLine *gl, sigset_t *set);


Esta función devuelve el conjunto de señales que
actualmente está configurado para atrapar en el
argumento set, que está en el formato
requerido por sigprocmask().

4. En el ejemplo, ahora probaría la bandera global que el manejador de señales establece, sabiendo que ahora no hay peligro de que esta bandera se establezca nuevamente hasta que gl_get_line() desbloquee sus señales mientras realiza E/S.

5. Eventualmente gl_get_line() regresa, ya sea porque se capturó una señal, ocurrió un error, o el usuario terminó de introducir su línea de entrada.

6. Ahora verificaría la bandera de señal global nuevamente, y si está establecida, respondería a ella y pondría la bandera a cero.

7. Use sigprocmask() para desbloquear las señales que estaban bloqueadas en el paso 3.

La misma técnica se puede usar alrededor de ciertas funciones POSIX conscientes de señales, como sigsetjmp() y sigsuspend(), y en particular, la primera de estas dos funciones se puede usar en conjunción con siglongjmp() para implementar el manejo de señales libre de condiciones de carrera alrededor de otras llamadas del sistema de larga duración. La forma de hacer esto se explica a continuación, mostrando cómo gl_get_line() logra atrapar señales de manera confiable alrededor de llamadas a funciones como read() y select() sin condiciones de carrera.

Lo primero que hace gl_get_line(), cada vez que se llama, es usar la función POSIX sigprocmask() para bloquear la entrega de todas las señales que está configurado para atrapar. Esto es redundante si la aplicación ya las ha bloqueado, pero no causa ningún daño. Deshace este paso justo antes de regresar.

Si las señales que se estaban atrapando se detectaron mientras los pasos anteriores se ejecutaban. Cuando esto sucede, gl_get_line() hace lo siguiente.

Primero, tenga en cuenta que cuando una llamada a siglongjmp() provoca que sigsetjmp() devuelva un valor, siempre que el argumento savesigs de sigsetjmp() no fuera cero, según lo especificado anteriormente, la máscara de proceso de señales se restaura a cómo estaba cuando se llamó a sigsetjmp(). Esta es la diferencia importante entre sigsetjmp() y el antiguo y problemático setjmp(), y es el ingrediente esencial que hace posible evitar las condiciones de carrera en el manejo de señales. Debido a esto, garantizamos que todas las señales que bloqueamos antes de llamar a sigsetjmp() se bloquean nuevamente tan pronto como se detecta alguna señal. Las siguientes sentencias, que luego se ejecutan, se garantiza que se ejecutarán sin que se detecten más señales.

1. Si así lo indican los atributos de configuración de
la señal detectada de gl_get_line(),
gl_get_line() restaura los atributos de la terminal al
estado que tenían cuando se llamó a
gl_get_line(). Esto es particularmente importante para las señales que suspenden o terminan el proceso, ya que de lo contrario la terminal quedaría en un estado inutilizable.

2. Luego, reinstala los manejadores de señales de la aplicación.

3. Luego, utiliza la función raise() de la biblioteca estándar de C
para reenviar la señal detectada a la aplicación.

3. A continuación, desbloquea la entrega de la señal que acabamos de
enviar. Esto da como resultado que la señal que se acaba de enviar
a través de raise() sea detectada por el manejador de
señales original de la aplicación, que ahora puede manejarla como
considere conveniente.

4. Si el manejador de señales devuelve el control (es decir, no termina
el proceso), gl_get_line() vuelve a bloquear la entrega de la
señal mencionada anteriormente.

5. Luego, deshace cualquier acción realizada en el primer paso de los
anteriores y redibuja la línea, si la configuración de la señal lo
requiere.

6. gl_get_line() luego reanuda el intento de leer un carácter o
se aborta, dependiendo de la configuración de la señal detectada.

Lo que hacen los pasos anteriores en esencia es tomar señales entregadas asíncronamente y manejarlas síncronamente, una a la vez, en un punto del código donde gl_get_line() tiene control total sobre su entorno.

EL TAMAÑO DE LA TERMINAL

En la mayoría de los sistemas, la combinación del ioctl TIOCGWINSZ y la señal SIGWINCH se utiliza para mantener una idea precisa del tamaño de la terminal. El tamaño de la terminal se consulta nuevamente cada vez que se llama a gl_get_line() y cada vez que se recibe una señal SIGWINCH.

En los pocos sistemas donde este mecanismo no está disponible, al inicio new_GetLine() busca primero las variables de entorno LINES y COLUMNS. Si estas no se encuentran, o contienen valores inutilizables, entonces si una base de datos de información de terminal como terminfo o termcap está disponible, se busca el tamaño predeterminado de la terminal en esta base de datos. Si esto también falla en proporcionar el tamaño de la terminal, se utiliza un tamaño predeterminado de 80 columnas por 24 líneas.

Incluso en sistemas que admiten ioctl(TIOCGWINSZ), si la terminal está en el otro extremo de una línea serial, el controlador de terminal generalmente no tiene forma de detectar cuándo ocurre un redimensionamiento o de consultar cuál es el tamaño actual. En tales casos, no se envía ningún SIGWINCH al proceso, y las dimensiones devueltas por ioctl(TIOCGWINSZ) no son correctas. La única forma de manejar tales instancias es proporcionar una manera para que el usuario ingrese un comando que le diga al sistema remoto cuál es el nuevo tamaño. Este comando llamaría entonces a la función gl_set_term_size() para informar a gl_get_line() sobre el cambio de tamaño.

  int gl_set_term_size(GetLine *gl, int ncolumn, int nline);

Los argumentos ncolumn y nline se utilizan para especificar las nuevas dimensiones de la terminal y no deben ser menores que 1. En sistemas que admiten ioctl(TIOCGWINSZ), esta función primero llama a ioctl(TIOCSWINSZ) para informar al controlador de la terminal sobre el cambio de tamaño. En el modo de servidor de E/S no bloqueante, si se está ingresando una línea actualmente, la línea de entrada se redibuja para acomodar el tamaño cambiado. Finalmente, los nuevos valores se registran en gl para su uso futuro por gl_get_line().

La función gl_terminal_size() le permite consultar el tamaño actual de la terminal e instalar un tamaño de respaldo alternativo para los casos en que el tamaño no esté disponible. Tenga en cuenta que el tamaño de la terminal no estará disponible si se lee desde una tubería o un archivo, por lo que los valores predeterminados pueden ser importantes incluso en sistemas que admiten formas de averiguar el tamaño de la terminal.

  typedef struct {
    int nline;        /* La terminal tiene nline líneas */
    int ncolumn;      /* La terminal tiene ncolumn columnas */
  } GlTerminalSize;
  GlTerminalSize gl_terminal_size(GetLine *gl,
                                  int def_ncolumn,
                                  int def_nline);

Esta función primero actualiza las dimensiones de terminal de respaldo de gl_get_line(), luego registra sus hallazgos en el valor de retorno.

def_ncolumn y def_nline especifican el número predeterminado de columnas y líneas de la terminal a utilizar si el tamaño de la terminal no se puede determinar a través de ioctl(TIOCGWINSZ) o variables de entorno.

OCULTAR LO QUE ESCRIBES

Al ingresar información confidencial, como contraseñas, es mejor no tener el texto que está ingresando reflejado en la terminal. Además, dicho texto no debe registrarse en la lista de historial, ya que alguien que encuentre su terminal desatendida podría recordarlo, o alguien que husmee en sus directorios podría verlo en su archivo de historial. Con esto en mente, la función gl_echo_mode() le permite activar y desactivar la visualización y el archivo de cualquier texto que se ingrese posteriormente en llamadas a gl_get_line().

  int gl_echo_mode(GetLine *gl, int enable);

El argumento enable especifica si el texto ingresado debe ser visible o no. Si es 0, entonces las líneas ingresadas posteriormente no serán visibles en la terminal y no se registrarán en la lista de historial. Si es 1, entonces las líneas de entrada posteriores se mostrarán a medida que se ingresan, y siempre que el historial no se haya desactivado mediante una llamada a gl_toggle_history(), también se archivarán en la lista de historial. Finalmente, si el argumento enable es -1, entonces el modo de eco se deja sin cambios, lo que le permite consultar de forma no destructiva la configuración actual a través del valor de retorno. En todos los casos, el valor de retorno de la función es 0 si el eco se deshabilitó antes de llamar a la función, y 1 si se habilitó.

Cuando el eco está desactivado, tenga en cuenta que aunque la autocompletación de tabulaciones completará invisiblemente su prefijo tanto como sea posible, las compleciones ambiguas no se mostrarán.

CONSULTAS DE UN SOLO CARACTER

Usar gl_get_line() para solicitar al usuario una respuesta de un solo carácter es inconveniente para el usuario, ya que debe presionar la tecla enter o return antes de que el carácter que escribió se devuelva al programa. Por lo tanto, se ha proporcionado la función gl_query_char() para consultas de un solo carácter como esta.

  int gl_query_char(GetLine *gl, const char *prompt,
                    char defchar);

Esta función muestra el aviso especificado al inicio de una nueva línea y espera a que el usuario escriba un carácter. Cuando el usuario escribe un carácter, gl_query_char() lo muestra a la derecha del aviso, inicia una nueva línea y luego devuelve el carácter al programa que llama. El valor de retorno de la función es el carácter que se escribió. Si la lectura tuvo que abortarse por alguna razón, se devuelve EOF en su lugar. En este último caso, la aplicación puede llamar a gl_return_status(), documentado anteriormente, para averiguar qué salió mal. Esto podría haber sido, por ejemplo, la recepción de una señal o que el temporizador de inactividad opcional se disparara.

Si el usuario simplemente presiona enter, se sustituye el valor del argumento defchar. Esto significa que cuando el usuario presiona nueva línea o retorno, el carácter especificado en defchar se muestra después del aviso, como si el usuario lo hubiera escrito, además de ser devuelto a la aplicación que llama. Si tal reemplazo no es importante, simplemente pase '0 como valor de defchar.

Si el carácter ingresado es un carácter no imprimible, se muestra simbólicamente. Por ejemplo, control-A se muestra como ^A, y los caracteres mayores que 127 se muestran en octal, precedidos por una barra invertida.

Al igual que con gl_get_line(), el eco del carácter ingresado se puede deshabilitar usando la función gl_echo_mode().

Si el proceso que llama se suspende mientras espera que el usuario escriba su respuesta, el cursor se mueve a la línea siguiente a la línea del aviso, luego cuando el proceso se reanuda, se vuelve a mostrar el aviso y gl_query_char() reanuda la espera a que el usuario escriba un carácter.

Tenga en cuenta que en el modo de servidor no bloqueante (ver gl_io_mode(3)), si se está leyendo una línea de entrada incompleta cuando se llama a gl_query_char(), la línea de entrada parcial se descarta y se borra de la terminal antes de que se muestre el nuevo aviso. La próxima llamada a gl_get_line() comenzará, por lo tanto, a editar una nueva línea.

LEER CARACTERES EN BRUTO

Mientras que la función gl_query_char() muestra visiblemente un aviso al usuario para un carácter y muestra lo que escribió, la función gl_read_char() lee un carácter de señal del usuario, sin escribir nada en la terminal, ni perturbar ninguna línea de entrada incompleta. Esto significa que se puede llamar no solo desde entre llamadas a gl_get_line(), sino también desde funciones de devolución de llamada que la aplicación ha registrado para ser llamadas por gl_get_line().

  int gl_read_char(GetLine *gl);

En caso de éxito, el valor de retorno de gl_read_char() es el carácter que se leyó. En caso de fallo, se devuelve EOF, y la función gl_return_status() puede ser llamada para averiguar qué salió mal. Las posibilidades incluyen que el temporizador de inactividad opcional se dispare, la recepción de una señal configurada para abortar gl_get_line(), o que la E/S de la terminal se bloquee, en el modo de E/S de servidor no bloqueante.

MOSTRANDO TEXTO DINÁMICAMENTE

Entre llamadas a gl_get_line(), la función gl_display_text() proporciona una forma conveniente de mostrar párrafos de texto, justificados a la izquierda y divididos en una o más líneas de terminal según las restricciones del ancho actual de la terminal. Ejemplos del uso de esta función se pueden encontrar en los programas de demostración, donde se utiliza para mostrar introducciones. En esos ejemplos también se ilustra el uso avanzado de prefijos, sufijos y líneas de relleno opcionales para dibujar un cuadro alrededor del texto.

  int gl_display_text(GetLine *gl, int indentation,
                      const char *prefix,
                      const char *suffix, int fill_char,
                      int def_width, int start,
                      const char *string);

Si gl no está conectado actualmente a una terminal, por ejemplo, si la salida de un programa que usa gl_get_line() se está enviando a otro programa o se está redirigiendo a un archivo, entonces se usa el valor del parámetro def_width como ancho de la terminal.

El argumento indentation especifica el número de caracteres que se utilizarán para indentar cada línea de salida. El argumento fill_char especifica el carácter que se utilizará para realizar esta indentación.

El argumento prefix puede ser NULL, o una cadena de caracteres para colocar al principio de cada nueva línea (después de cualquier indentación). De manera similar, el argumento suffix puede ser NULL, o una cadena de caracteres para colocar al final de cada línea. El sufijo se coloca justo contra el borde derecho de la terminal, y cualquier espacio entre su primer carácter y la última palabra de esa línea se rellena con el carácter especificado a través del argumento fill_char. Normalmente, el carácter de relleno es un espacio.

El argumento start le dice a gl_display_text() cuántos caracteres ya se han escrito en la línea de la terminal actual y, por lo tanto, le indica el índice de la columna de inicio del cursor. Dado que el valor de retorno de gl_display_text() es el índice de la columna final del cursor, al pasar el valor de retorno de una llamada al argumento start de la siguiente llamada, un párrafo que se rompe entre más de una cadena se puede componer llamando a gl_display_text() para cada porción sucesiva del párrafo. Tenga en cuenta que son necesarios caracteres de nueva línea literales al final de cada párrafo para forzar el inicio de una nueva línea.

En caso de error, gl_display_text() devuelve -1.

INSTALACIONES DE FUNCIONES DE LLAMADA

A menos que se indique lo contrario, las funciones de llamada, como las llamadas de finalización de tabulación y las llamadas de eventos, no deben llamar a ninguna función de este módulo. Las siguientes funciones, sin embargo, están diseñadas específicamente para ser utilizadas por funciones de llamada.

Llamar a la función gl_replace_prompt() desde una llamada indica a gl_get_line() que muestre un prompt diferente cuando la llamada regrese. Excepto en el modo de servidor no bloqueante, no tiene efecto si se usa entre llamadas a gl_get_line(). En modo de servidor no bloqueante (ver la página man gl_io_mode(3), cuando se usa entre dos llamadas a gl_get_line() que operan en la misma línea de entrada, la línea de entrada actual se redibujará con el nuevo prompt en la siguiente llamada a gl_get_line().

  void gl_replace_prompt(GetLine *gl, const char *prompt);

JUEGOS DE CARACTERES INTERNACIONALES

Desde la versión 1.4.0 de libtecla, gl_get_line() es compatible con 8 bits. Esto significa que todos los caracteres de 8 bits que son imprimibles en la configuración regional actual del usuario se muestran ahora literalmente y se incluyen en la línea de entrada devuelta. Suponiendo que el programa que llama contiene correctamente una llamada como la siguiente,

  setlocale(LC_CTYPE, "");

entonces la configuración regional actual se determina por la primera de las variables de entorno LC_CTYPE, LC_ALL y LANG, que se encuentre que contiene un nombre de configuración regional válido. Si ninguna de estas variables está definida, o si el programa omite llamar a setlocale, entonces se utiliza la configuración regional predeterminada C, que es US 7-bit ASCII. En la mayoría de las plataformas tipo unix, puede obtener una lista de configuraciones regionales válidas escribiendo el comando:

  locale -a

en el prompt de la shell. Se puede encontrar más documentación sobre cómo el usuario puede utilizar esto para introducir caracteres internacionales en la página man tecla(7).

SEGURIDAD DE HILOS

En un programa multihilo, debe usar la versión libtecla_r.a de la biblioteca. Esta utiliza versiones reentrantes de las funciones del sistema, donde estén disponibles. Desafortunadamente, ni terminfo ni termcap fueron diseñados para ser reentrantes, por lo que no puede usar de forma segura las funciones del módulo getline en múltiples hilos (puede usar los módulos separados de expansión de archivos y finalización de palabras en múltiples hilos, consulte las páginas man correspondientes para obtener detalles). Sin embargo, debido al uso de funciones reentrantes POSIX para buscar directorios personales, etc., es seguro usar este módulo desde un único hilo de un programa multihilo, siempre que sus otros hilos no utilicen ninguna función de termcap o terminfo.
