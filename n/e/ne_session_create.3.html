Paquete: neon

NE_SESSION_CREATE(3) Referencia de la API de neon NE_SESSION_CREATE(3)

NOMBRE

ne_session_create, ne_close_connection, ne_session_destroy - configurar sesiones HTTP

SINOPSIS

#include <ne_session.h>

ne_session *ne_session_create(const char *scheme, const char *host, unsigned int port);

void ne_close_connection(ne_session *session);

void ne_session_destroy(ne_session *session);

DESCRIPCIÓN

Un objeto ne_session representa una sesión HTTP: una agrupación lógica de una secuencia de peticiones HTTP realizadas a un servidor determinado. Cualquier petición realizada utilizando la sesión puede usar una conexión persistente, compartir credenciales de autenticación en caché y otros atributos comunes.

Se crea una nueva sesión HTTP utilizando la función ne_session_create; los parámetros host y port especifican el servidor de origen a utilizar, junto con el scheme (normalmente "http"). Antes del primer uso de ne_session_create en un proceso, se debe haber llamado a ne_sock_init para realizar cualquier inicialización global necesaria por cualquier biblioteca utilizada por neon.

Para habilitar SSL/TLS para la sesión, pase la cadena "https" como scheme, y registre una función de verificación de certificados (ver ne_ssl_set_verify) o confíe en el certificado apropiado (ver ne_ssl_trust_cert, ne_ssl_trust_default_ca).

El parámetro host debe seguir la definición de host en RFC 3986[1], que puede ser una dirección literal IP o un nombre de host registrado (DNS). Ejemplos válidos de cada uno: "198.51.100.42" (dirección literal IPv4), "[2001:db8::42]" (literal IPv6, que *DEBE* estar entre corchetes), o "www.example.com" (nombre de host DNS). La sintaxis de RFC 6874[2] para direcciones literales IPv6 de ámbito de enlace también está permitida, por ejemplo "[fe80::1%25eth0]".

El parámetro scheme se utiliza para determinar la URI de los recursos identificados durante el manejo de peticiones. Aparte del manejo especial de la cadena "https", no se realiza ninguna otra interpretación o verificación del scheme. Por ejemplo, si se configura un proxy HTTP a FTP, se podría usar un scheme "ftp" para acceder a recursos.

Para usar un servidor proxy para la sesión, debe configurarse (ver ne_session_proxy) antes de que se creen peticiones desde el objeto de sesión.

Opciones adicionales por sesión pueden modificarse utilizando la interfaz ne_set_session_flag.

Si se sabe que la sesión no se utilizará durante un período de tiempo significativo, se puede llamar a ne_close_connection para cerrar la conexión, si queda alguna abierta. El uso de esta función es completamente opcional, pero no debe llamarse si hay una petición activa utilizando la sesión.

Una vez completada la sesión, se debe llamar a ne_session_destroy para destruir los recursos asociados a la sesión. Cualquier uso posterior del puntero de sesión produce un comportamiento indefinido. El objeto de sesión no debe destruirse hasta después de que todos los objetos de petición asociados hayan sido destruidos.

NOTAS

Si se pasa un nombre de host a ne_session_create, se resolverá cuando se despache la primera petición que use la sesión; un fallo en la resolución DNS solo se puede detectar en ese momento (usando el código de error NE_LOOKUP); ver ne_request_dispatch para más detalles.

VALORES DE RETORNO

ne_session_create devolverá un puntero a un nuevo objeto de sesión (y nunca NULL).

EJEMPLOS

Crear y destruir una sesión:

ne_session *sess;
sess = ne_session_create("http", "host.example.com", 80);
/* ... usar sess ... */
ne_session_destroy(sess);
