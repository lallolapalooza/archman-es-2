NETCDF(3) FUNCIONES DE LA BIBLIOTECA UNIDATA NETCDF(3)

NOMBRE

netcdf - Interfaz de la biblioteca Unidata's Network Common Data Form (netCDF)

SINOPSIS

include netcdf.inc

La Mayoría de los Sistemas:

f77 ... -lnetcdf

Sistemas CRAY PVP:

f90 -dp -i64 ... -lnetcdf

La documentación completa para las bibliotecas netCDF se puede encontrar en el sitio web de netCDF: https://www.unidata.ucar.edu/software/netcdf/.

VERSIÓN DE LA BIBLIOTECA

Este documento describe la versión 3

de la interfaz de acceso a datos netCDF de Unidata para el lenguaje de programación FORTRAN.

character*80 nf_inq_libvers(void)

Devuelve una cadena que identifica la versión de la biblioteca netCDF y cuándo se compiló, como: "3.1a de Aug 22 1996 12:57:47 $".

El comando RCS ident(1) encontrará una cadena como "$Id: @(#) netcdf library version 3.1a of Sep 6 1996 15:56:26 $" en la biblioteca. El comando SCCS what(1) encontrará una cadena como "netcdf library version 3.1a of Aug 23 1996 16:07:40 $".

VALORES DE RETORNO

Todas las funciones netCDF (excepto nf_inq_libvers() y nf_strerror()) devuelven un estado entero.

Si este valor de estado devuelto no es igual a NF_NOERR (cero), indica que ocurrió un error. Los valores de estado posibles se definen en netcdf.inc.

character*80 nf_strerror(integer status)

Devuelve una cadena de traducción textual del valor status, como "Attribute or variable name contains illegal characters" o "No such file or directory".

OPERACIONES DE ARCHIVO

integer function nf_create(character*(*) path, integer cmode, integer ncid)

Crea un nuevo conjunto de datos netCDF en path, devolviendo un ID de netCDF en ncid. El argumento cmode puede incluir el OR bit a bit de las siguientes banderas: NF_NOCLOBBER para proteger los conjuntos de datos existentes (por defecto los borra silenciosamente), NF_SHARE para actualizaciones síncronas del conjunto de datos para archivos de formato clásico (por defecto se almacenan en búfer los accesos),

Cuando se crea un conjunto de datos netCDF, se abre en modo NF_WRITE. El nuevo conjunto de datos netCDF está en modo de definición. NF_64BIT_OFFSET para crear un archivo en formato de desplazamiento de 64 bits (en contraposición al formato clásico, que es el predeterminado).

integer function nf__create(character*(*) path, integer cmode, integer initialsize, integer chunksize, integer ncid)

Similar a nf_create() pero con parámetros adicionales de ajuste de rendimiento.

El argumento initialsize establece el tamaño inicial del archivo en el momento de la creación.

Consulte nf__open() a continuación para obtener una explicación del parámetro chunksize.

integer function nf_open(character*(*) path, integer mode, integer ncid)

(Corresponde a ncopn() en la versión 2)

Abre un conjunto de datos netCDF existente en path devolviendo un ID de netCDF en ncid. El tipo de acceso se describe mediante el parámetro mode, que puede incluir el OR bit a bit de las siguientes banderas: NF_WRITE para acceso de lectura-escritura (por defecto solo lectura), NF_SHARE para actualizaciones síncronas del conjunto de datos (por defecto se almacenan en búfer los accesos), y NF_LOCK (aún no implementado).

integer function nf__open(character*(*) path, integer mode, integer chunksize, integer ncid)

Similar a nf_open() pero con un parámetro adicional de ajuste de rendimiento.

El argumento referenciado por chunksize controla una compensación entre espacio y tiempo, memoria asignada en la biblioteca netcdf frente al número de llamadas al sistema. Debido a requisitos internos, el valor puede no establecerse exactamente al valor solicitado. El valor real elegido se devuelve por referencia. Usar el valor NF_SIZEHINT_DEFAULT hace que la biblioteca elija un valor predeterminado. Cómo el sistema elige el valor predeterminado depende del sistema. En muchos sistemas, el "tamaño de bloque de E/S preferido" está disponible mediante la llamada al sistema stat(), miembro st_blksize de la struct stat. Si esto está disponible se utiliza. De lo contrario, se utiliza el doble del tamaño de página del sistema. De lo contrario, sin una llamada para descubrir el tamaño de página del sistema, simplemente establecemos el tamaño de bloque predeterminado en 8192.

El tamaño de bloque es una propiedad de un descriptor netcdf abierto dado ncid, no es una propiedad persistente del conjunto de datos netcdf.

integer function nf_redef(integer ncid)

(Corresponde a ncredf() en la versión 2)

Pone un conjunto de datos netCDF abierto en modo de definición, para que se puedan agregar o renombrar dimensiones, variables y atributos, y se puedan eliminar atributos.

integer function nf_enddef(integer ncid)

(Corresponde a ncendf() en la versión 2)

Saca un conjunto de datos netCDF abierto del modo de definición. Los cambios realizados en el conjunto de datos netCDF mientras estaba en modo de definición se verifican y se confirman en el disco si no ocurrieron problemas. También se pueden escribir algunos valores de datos, consulte "PRELLENADO DE VARIABLES" a continuación. Después de una llamada exitosa, los datos de las variables se pueden leer o escribir en el conjunto de datos.

integer function nf__enddef(integer ncid, integer h_minfree, integer v_align, integer v_minfree, integer r_align)

Similar a nf_enddef() pero con parámetros adicionales de ajuste de rendimiento.

Precaución: esta función expone detalles internos del formato de archivo netcdf versión 1. Es posible que no esté disponible en implementaciones futuras de netcdf.

El formato de archivo netcdf actual tiene tres secciones: la sección "encabezado", la sección de datos para variables de tamaño fijo y la sección de datos para variables que tienen una dimensión ilimitada (variables de registro). El encabezado comienza al principio del archivo. El índice (desplazamiento) del inicio de las otras dos secciones está contenido en el encabezado. Típicamente, no hay espacio entre las secciones. Esto genera sobrecarga de copiado si se desea cambiar el tamaño de las secciones, como puede ocurrir al cambiar nombres de cosas, valores de atributos de texto, agregar atributos o agregar variables. Además, para E/S con búfer, puede haber ventajas en alinear las secciones de ciertas maneras.

Los parámetros minfree permiten controlar los costos de futuras llamadas a nf_redef(), nf_enddef() solicitando que haya minfree bytes disponibles al final de la sección. El parámetro h_minfree establece el relleno al final de la sección "encabezado". El parámetro v_minfree establece el relleno al final de la sección de datos para variables de tamaño fijo.

Los parámetros align permiten establecer la alineación del inicio de las secciones correspondientes. El inicio de la sección se redondea al índice que es un múltiplo del parámetro align. El valor de bandera NF_ALIGN_CHUNK indica a la biblioteca que utilice el tamaño de bloque (ver arriba) como parámetro align. El parámetro v_align controla la alineación del inicio de la sección de datos para variables de tamaño fijo. El parámetro r_align controla la alineación del inicio de la sección de datos para variables que tienen una dimensión ilimitada (variables de registro).

El formato de archivo requiere alineación mod 4, por lo que los parámetros align se redondean silenciosamente a múltiplos de 4. La llamada habitual, nf_enddef(ncid), es equivalente a nf__enddef(ncid, 0, 4, 0, 4).

El formato de archivo no contiene un valor de "tamaño de registro", este se calcula a partir de los tamaños de las variables de registro. Este desafortunado hecho nos impide proporcionar control de minfree y alineación de los "registros" en un archivo netcdf. Si agrega una variable que tiene una dimensión ilimitada, la tercera sección siempre se copiará con la nueva variable agregada.

OVERVIEW

The netCDF C API provides functions for creating, accessing, and modifying netCDF files. It is designed to be used with Fortran by translating the C function names to Fortran names and passing arguments by reference.

The names of the Fortran functions are generated by appending an underscore and the appropriate suffix (e.g., `_` followed by `i` for `integer`, `_` followed by `r` for `real`, `_` followed by `d` for `doubleprecision`). For example, the C function `nf_open` corresponds to the Fortran function `nf_open_i` (for integer arguments) or `nf_open_r` (for real arguments).

When a netCDF is opened in Fortran, the file is opened in the mode specified by the Fortran caller. The default mode is `NF_NOWRITE` (read-only). If you need to write to the file, you must specify `NF_WRITE` or `NF_SHARE` mode.

Note that when writing strings, it is important to ensure that the Fortran character variables are null-terminated. This is typically done by explicitly appending a null character (`CHAR(0)`) to the string before passing it to the netCDF function.

The C netCDF library has been extended to support Fortran string arguments. Previously, strings were passed as `character*len` arguments, and the library would automatically handle the null termination. This is now the default behavior.

FILE ACCESS FUNCTIONS

integer function nf_create(character*(*) path, integer cmode, integer ncid)

(Corresponds to nccre() in version 2)

Creates a new netCDF dataset. path is the full path to the new file. cmode is a bitmask that specifies the creation mode. Currently, the following modes are supported:

NF_CLOBBER
Overwrite the file if it already exists.
NF_NOCLOBBER
Do not overwrite the file if it already exists. Return an error if the file exists.
ncid will contain the netCDF ID of the newly created dataset.

integer function nf_open(character*(*) path, integer mode, integer ncid)

(Corresponds to ncopn() in version 2)

Opens an existing netCDF dataset. path is the full path to the file. mode specifies how the file is to be opened. The following modes are supported:

NF_NOWRITE
Open for read-only access.
NF_WRITE
Open for read-write access.
NF_SHARE
Open for read-write access, with sharing enabled.
ncid will contain the netCDF ID of the opened dataset.

integer function nf_enddef(integer ncid)

(Corresponds to ncend() in version 2)

Transitions a netCDF dataset from define mode to data mode. Any changes made to the dimensions, variables, or attributes are made permanent. This function should be called after all definitions are complete, but before any data is written.

integer function nf_redef(integer ncid)

(Corresponds to ncred() in version 2)

Transitions a netCDF dataset from data mode to define mode. This allows you to modify the dataset's metadata, such as adding or renaming dimensions, variables, or attributes. After making changes, you must call nf_enddef() to commit them.

The netCDF data model has been updated to support Fortran strings. The C netCDF library provides functions to handle these strings automatically. When a netCDF is opened, the file is opened in the mode specified by the Fortran caller. The default mode is `NF_NOWRITE` (read-only). If you need to write to the file, you must specify `NF_WRITE` or `NF_SHARE` mode.

The C netCDF library provides functions that can be used to manage the state of a netCDF file. These functions are automatically called by `nf_close()` and `nf_enddef()`. This means that you don't need to explicitly call them in most cases.

The following functions are related to managing the state of a netCDF file:

integer function nf_abort(integer ncid)

(Corresponds to ncabor() in version 2)

You don't need to call this function. This function is called automatically by nf_close() if the netCDF was in define mode and something goes wrong with the commit. If the netCDF dataset isn't in define mode, then this function is equivalent to nf_close(). If it is called after nf_redef(), but before nf_enddef(), the new definitions are not committed and the dataset is closed. If it is called after nf_create() but before nf_enddef(), the dataset disappears.

integer function nf_close(integer ncid)

(Corresponds to ncclos() in version 2)

Closes an open netCDF dataset. If the dataset is in define mode, nf_enddef() will be called before closing. After a dataset is closed, its ID may be reassigned to another dataset.

A diferencia de las variables, los atributos no tienen funciones separadas para definir y escribir valores. Esta familia de funciones define un nuevo atributo con un valor o cambia el valor de un atributo existente. Si el atributo es nuevo, o si el espacio requerido para almacenar el valor del atributo es mayor que antes, el conjunto de datos netCDF debe estar en modo de definición. El parámetro len es el número de valores de out a transferir. A menudo es uno, excepto que para nf_put_att_text() generalmente será len_trim(out).

Para estas funciones, el componente de tipo del nombre de la función se refiere al tipo en memoria del valor, mientras que el argumento xtype se refiere al tipo externo para almacenar el valor. Se produce un error NF_ERANGE si una conversión entre estos tipos no es posible. En este caso, el valor se representa con el valor de relleno apropiado para el tipo externo asociado.

integer function nf_inq_attname(integer ncid, integer varid, integer attnum, character*(*) name)

Obtiene el nombre de un atributo, dado su ID de variable y número de atributo. Esta función es útil en aplicaciones genéricas que necesitan obtener los nombres de todos los atributos asociados con una variable, ya que los atributos se acceden por nombre en lugar de por número en todas las demás funciones de atributos. El número de un atributo es más volátil que el nombre, ya que puede cambiar cuando se eliminan otros atributos de la misma variable. Los atributos para cada variable se numeran desde 1 (el primer atributo) hasta nvatts, donde nvatts es el número de atributos para la variable, como se devuelve en una llamada a nf_inq_varnatts().

Estas funciones devuelven información sobre un atributo netCDF, dado su ID de variable y nombre. La información devuelta es el tipo externo en xtype y el número de elementos en el atributo como len.

integer function nf_copy_att(integer ncid, integer varid_in, character*(*) name, integer ncid_out, integer varid_out)

Copia un atributo de un conjunto de datos netCDF a otro. También se puede utilizar para copiar un atributo de una variable a otra dentro del mismo netCDF. ncid_in es el ID netCDF de un conjunto de datos netCDF de entrada del cual se copiará el atributo. varid_in es el ID de la variable en el conjunto de datos netCDF de entrada del cual se copiará el atributo, o NF_GLOBAL para un atributo global. name es el nombre del atributo en el conjunto de datos netCDF de entrada que se va a copiar. ncid_out es el ID netCDF del conjunto de datos netCDF de salida al que se copiará el atributo. Está permitido que los ID netCDF de entrada y salida sean los mismos. El conjunto de datos netCDF de salida debe estar en modo de definición si el atributo que se va a copiar no existe ya para la variable de destino, o si causaría que un atributo de destino existente creciera.

integer function nf_rename_att(integer ncid, integer varid, character*(*) name, character*(*) newname)

Cambia el nombre de un atributo. Si el nuevo nombre es más largo que el nombre original, el netCDF debe estar en modo de definición. Si el nuevo nombre es más largo que el antiguo, el conjunto de datos netCDF debe estar en modo de definición.

DESCRIPCIONES DE ARGUMENTOS COMUNES

En esta sección definimos algunos argumentos comunes que se utilizan en la sección "DESCRIPCIONES DE FUNCIONES".

integer ncid
es el ID netCDF devuelto por una llamada anterior y exitosa a nf_open() o nf_create()
character*(*) name
es el nombre de una dimensión, variable o atributo. Los nombres de dimensiones, variables y atributos consisten en secuencias arbitrarias de caracteres alfanuméricos (así como guion bajo '_', punto '.' y guion '-') , comenzando con una letra o guion bajo. (Sin embargo, los nombres que comienzan con un guion bajo están reservados para uso del sistema). La mayúscula es significativa en los nombres de netCDF. No se permite un nombre de longitud cero.

El número máximo de caracteres permitidos
es NF_MAX_NAME.

integer xtype
especifica el tipo de datos externo de una variable o atributo netCDF y es uno de los siguientes: NF_BYTE, NF_CHAR, NF_SHORT, NF_INT, NF_FLOAT o NF_DOUBLE. Estos se utilizan para especificar enteros de 8 bits, caracteres, enteros de 16 bits, enteros de 32 bits, números de punto flotante IEEE de 32 bits y números de punto flotante IEEE de 64 bits, respectivamente.
integer dimids(1)
es un vector de ID de dimensiones y define la forma de una variable netCDF.
le. El tamaño del vector debe ser mayor o igual al rango (es decir, el número de dimensiones) de la variable (ndims). El vector debe estar ordenado por la velocidad con la que varía una dimensión: dimids(1) será el ID de la dimensión que varía más rápidamente y dimids(ndims) será el ID de la dimensión que varía más lentamente. El número máximo posible de dimensiones para una variable se da por la constante simbólica NF_MAX_VAR_DIMS.
entero dimid
es el ID de una dimensión netCDF. Los IDs de dimensión netCDF se asignan secuencialmente a partir de los enteros positivos comenzando con 1.
entero ndims
es el número total de dimensiones en un conjunto de datos netCDF o el rango (es decir, el número de dimensiones) de una variable netCDF. El valor no debe ser negativo ni mayor que la constante simbólica NF_MAX_VAR_DIMS.
entero varid
es el ID de una variable netCDF o (para las funciones de acceso a atributos) la constante simbólica NF_GLOBAL, que se utiliza para hacer referencia a atributos globales. Los IDs de variable netCDF se asignan secuencialmente a partir de los enteros positivos comenzando con 1.
entero natts
es el número de atributos globales en un conjunto de datos netCDF para la función nf_inquire() o el número de atributos asociados con una variable netCDF para la función nf_varinq().
entero index(1)
especifica las coordenadas indiciales del valor de datos netCDF que se va a acceder. Los índices comienzan en 1; por lo tanto, por ejemplo, el primer valor de datos de una variable bidimensional es (1,1). El tamaño del vector debe ser al menos el rango de la variable netCDF asociada y sus elementos deben corresponder, en orden, a las dimensiones de la variable.
entero start(1)
especifica el punto de partida para acceder a los valores de datos de una variable netCDF en términos de las coordenadas indiciales de la esquina de la sección del arreglo. Los índices comienzan en 1; por lo tanto, el primer valor de datos de una variable es (1, 1, ..., 1). El tamaño del vector debe ser al menos el rango de la variable netCDF asociada y sus elementos deben corresponder, en orden, a las dimensiones de la variable.
entero count(1)
especifica el número de índices seleccionados a lo largo de cada dimensión de la sección del arreglo. Por lo tanto, para acceder a un solo valor, por ejemplo, especifique count como (1, 1, ..., 1). Tenga en cuenta que, para E/S con saltos, este argumento debe ajustarse para ser compatible con los argumentos stride y start para que la interacción de los tres no intente acceder a una coordenada de datos inválida. Los elementos del vector count corresponden, en orden, a las dimensiones de la variable.
entero stride(1)
especifica el intervalo de muestreo a lo largo de cada dimensión de la variable netCDF. Los elementos del vector stride corresponden, en orden, a las dimensiones de la variable netCDF (stride(1) da el intervalo de muestreo a lo largo de la dimensión que varía más rápidamente de la variable netCDF). Los intervalos de muestreo se especifican en unidades independientes del tipo de elementos (un valor de 1 selecciona elementos consecutivos de la variable netCDF a lo largo de la dimensión correspondiente, un valor de 2 selecciona cada dos elementos, etc.).
imap
especifica el mapeo entre las dimensiones de una variable netCDF y la estructura en memoria del arreglo de datos interno. Los elementos del vector de mapeo de índices corresponden, en orden, a las dimensiones de la variable netCDF (imap(1) da la distancia entre elementos del arreglo interno que corresponden a la dimensión que varía más rápidamente de la variable netCDF). Las distancias entre elementos se especifican en unidades independientes del tipo de elementos (la distancia entre elementos internos que ocupan ubicaciones de memoria adyacentes es 1 y no la longitud de bytes del elemento como en netCDF 2).

PRELLENADO DE VARIABLES

Por defecto, la interfaz netCDF establece los valores de todas las variables recién definidas de longitud finita (es decir, aquellas que no tienen una dimensión ilimitada) al valor de relleno dependiente del tipo asociado a cada variable. Esto se hace cuando se llama a nf_enddef(). El valor de relleno para una variable puede cambiarse del valor por defecto definiendo el atributo `_FillValue' para la variable. Este atributo debe tener el mismo tipo que la variable y ser de longitud uno.

Las variables con una dimensión ilimitada también se prellenan, pero según sea necesario. Por ejemplo, si la primera escritura de tal variable es a la posición 5, entonces las posiciones 1 a 4 (y ninguna otra) se establecerían al valor de relleno al mismo tiempo.

Este prellenado por defecto de los valores de datos puede ser deshabilitado o mediante la operación OR lógica de la bandera NF_NOFILL en el parámetro de modo de nf_open() o nf_create(), o llamando a la función nf_set_fill() con el argumento NF_NOFILL. Para variables que no usan la dimensión ilimitada, esta llamada debe hacerse antes de nf_enddef(). Para variables que usan la dimensión ilimitada, esta llamada puede hacerse en cualquier momento.

Se puede obtener un mayor rendimiento de la interfaz netCDF utilizando esta característica, pero solo a expensas de requerir que la aplicación establezca cada valor de datos individualmente. El comportamiento de mejora del rendimiento de esta función depende de los detalles de la implementación y del formato del conjunto de datos. El valor de la bandera controlado por nf_set_fill() es por ID netCDF, no por variable ni por escritura. Permitir que esto cambie afecta el grado en que un programa puede ser paralelizado de manera efectiva. Dado todo esto, afirmamos que el uso de esta característica puede no estar disponible (o incluso ser necesario) en futuras versiones. Se advierte a los programadores que no dependan en gran medida de esta característica.

función entera nf_setfill(entero ncid, entero fillmode, entero old_fillemode)

Determina si se realizará o no el prellenado de variables (ver arriba). El conjunto de datos netCDF debe ser escribible. fillmode es NF_FILL para habilitar el prellenado (por defecto) o NF_NOFILL para deshabilitar el prellenado. Esta función devuelve la configuración anterior en old_fillmode.

DESCRIPCIONES DE FUNCIONES MPP

Funciones adicionales para usar en máquinas SGI/Cray MPP (_CRAYMPP). Estas se utilizan para establecer y consultar qué PE es la base para MPP para un netCDF particular. Estas solo son relevantes cuando se utiliza la capa de E/S Flexible de archivos "globales" de SGI/Cray y se desea que solo un subconjunto de PEs abra el archivo netCDF específico. Por razones técnicas, estas funciones están disponibles en todas las plataformas. En una plataforma que no sea SGI/Cray MPP, es como si solo el procesador disponible fuera el procesador 0.

Para usar esta característica, necesita especificar un grupo de comunicadores y llamar a glio_group_mpi() o glio_group_shmem() antes de las llamadas netCDF nf_open() y nf_create().

función entera nf__create_mp(carácter*(*) path, entero cmode, entero initialsize, entero pe, entero chunksize, entero ncid)

Similar a nf__create() pero permite establecer el PE base.

El argumento pe establece el PE base en el momento de la creación. En el entorno MPP, nf__create() y nf_create() establecen el PE base en el procesador cero por defecto.

función entera nf__open_mp(carácter*(*) path, entero mode, entero pe, entero chunksize, entero ncid)

Similar a nf__open() pero permite establecer el PE base. El argumento pe establece el PE base en el momento de la creación. En el entorno MPP, nf__open() y nf_open() establecen el PE base en el procesador cero por defecto.

función entera nf_inq_base_pe(entero ncid, entero pe)

Consulta al conjunto de datos netCDF qué PE se está utilizando como base para uso MPP. Esto es seguro de usar en cualquier momento.

función entera nf_set_base_pe(entero ncid, entero pe)

Restablece el PE base para el conjunto de datos netCDF. Realice esta operación solo cuando el grupo de comunicadores afectado se sincronice antes y después de la llamada. Esta operación es muy arriesgada y solo debe contemplarse bajo los casos más extremos.

VARIABLES DE ENTORNO

NETCDF_FFIOSPEC
Especifica los búferes de E/S de Archivos Flexibles para E/S netCDF cuando se ejecuta bajo el sistema operativo UNICOS (la variable se ignora en otros sistemas operativos). Una especificación apropiada puede aumentar en gran medida la eficiencia de las E/S netCDF, hasta el punto de que puede superar las E/S binarias de FORTRAN.
