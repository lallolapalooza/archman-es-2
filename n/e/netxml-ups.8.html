NOMBRE

netxml-ups - Controlador para equipos Eaton / MGE Network Management Card / Proxy (Protocolo XML/HTTP)

SINOPSIS

netxml-ups -h

netxml-ups -a NOMBRE_UPS [OPCIONES]


Nota

Esta página del manual solo documenta las características específicas del hardware del controlador netxml-ups. Para obtener información sobre el controlador principal, consulte nutupsdrv(8).

HARDWARE SOPORTADO

netxml-ups soporta todos los modelos recientes de Eaton / MGE que utilizan una tarjeta Network Management Card o Proxy (basada en el protocolo XML/HTTP de MGE). Esto se aplica tanto a Eaton (anteriormente MGE Office Protection Systems) como a MGE UPS SYSTEMS. Los modelos de tarjetas y proxies compatibles son:

•NMC Minislot (Ref 66102, firmware EA o posterior),
•Tarjeta Minislot SNMP/Web (Ref 66244)
•NMC Transverse (Ref 66074),
•NMC & Modbus/JBus (Ref 66103),
•Network Management Proxy,
•ePDU Monitored (versión más reciente).

Los modelos más antiguos, como la tarjeta SNMP (Ref 66062 y Ref 66045), utilizan el protocolo SNMP y deberían usar el controlador snmp-ups(8) con el parámetro mibs=mge.

ARGUMENTOS ADICIONALES

Este controlador soporta las siguientes configuraciones opcionales en el archivo ups.conf(5):

timeout=valor

El tiempo de espera para conectarse y leer desde la UPS. Por defecto es de 5 segundos. No cambie este valor a menos que sepa exactamente lo que está haciendo.

Este valor nunca debe ser superior a la mitad del valor MAXAGE especificado en upsd.conf(5), de lo contrario corre el riesgo de que upsd(8) declare el controlador obsoleto mientras espera que una conexión expire.

subscribe

Conéctese a la NMC en modo suscrito. Esto permite recibir notificaciones y alarmas más rápidamente, además de las solicitudes de sondeo estándar.

login=valor

Establezca el valor de inicio de sesión para el modo autenticado. Esta característica también necesita el argumento password y permite la configuración de valores en la tarjeta. Esta característica aún no se utiliza.

password=valor

Establezca el valor de la contraseña, necesario con el inicio de sesión para el modo autenticado. Esta característica aún no se utiliza.

shutdown_duration=valor

Establezca la duración del apagado del sistema operativo, en segundos. Esto representa el tiempo necesario para que el sistema realice un apagado limpio. Por defecto es de 120 segundos.

shutdown_timer=valor

Establezca el temporizador de apagado, en segundos. Después de valor segundos funcionando con batería, el sistema local recibirá una notificación para apagarse. Por defecto es "none" (desactivado).

do_convert_deci

Si este indicador está presente, el controlador asume que usted tiene una UPS en red MGE muy antigua (o más bien un firmware antiguo de la tarjeta de gestión de red) que proporciona ciertas mediciones que valen 10 veces más en el marcado XML.

Originalmente, dichas mediciones eran decodificadas por el controlador – pero esto es incorrecto para dispositivos más nuevos y más sensatos – por lo que este comportamiento se degradó y ahora está desactivado por defecto. Habilitar este indicador en la configuración de una instancia particular del controlador restaura el comportamiento antiguo para esas mediciones.

IMPLEMENTACIÓN

El nombre del host de la UPS en red se especifica con el valor del puerto en ups.conf, es decir:

[mgexml]
        driver = netxml-ups
        port = http://netxml-ups.example.com:80

Especificar el método para conectarse a la UPS (http, https) es obligatorio. Si el puerto es igual al predeterminado para el método especificado (80 para http, 443 para https) puede omitirse.

Para no sobrecargar las NMC antiguas con sondeos demasiado frecuentes, se recomienda aumentar el "pollinterval" (ver nutupsdrv(8) y ups.conf(5)) a al menos 5 segundos.

PROBLEMAS CONOCIDOS

Proxies HTTP(S)

No se conecte a la UPS a través de un proxy. Aunque sería trivial añadir soporte para proxies, no se recomienda y no lo pida. No solo porque impedirá al controlador establecer una conexión persistente con la UPS, sino que también añade un modo de fallo adicional. Si el proxy deja de funcionar (por cualquier motivo), el controlador ya no podrá alcanzar la UPS.

Uso de nombres de host para la NMC de la UPS

A una tarjeta de gestión de red de UPS se le puede asignar una dirección IP fija/estática o una dinámica (por ejemplo, por DHCP) en su red. Debido a esto, es posible que desee o necesite utilizar un servicio de nombres dinámico para acceder a la UPS. Tenga en cuenta que esto puede convertirse en un problema, especialmente durante cortes de energía y apagados importantes, cuando su servidor DHCP/DNS podría ya haber fallado mientras el controlador necesita resolver el nombre involucrado (especialmente durante los scripts de apagado tardío, cuando una nueva instancia del programa controlador podría iniciarse solo para indicarle a la UPS que se apague o se reinicie).

Podría ser prudente asegurarse de que el cliente del servicio de nombres de su sistema operativo pueda almacenar en caché el nombre de la UPS durante un tiempo suficiente, o utilizar el direccionamiento IP fijo (y una entrada en /etc/hosts para estar seguro, de modo que solo tenga un lugar que reconfigurar eventualmente).
