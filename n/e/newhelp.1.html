NEWHELP(1) Manual de Comandos Generales NEWHELP(1)

NOMBRE

newhelp - genera una base de datos de ayuda de métricas de rendimiento

SINOPSIS

$PCP_BINADM_DIR/newhelp [-vV?] [-D debug] [-n pmnsfile] [-o outputfile] [archivo ...]

DESCRIPCIÓN

newhelp genera los archivos de texto de ayuda de Performance Co-Pilot utilizados por los Agentes de Dominio de Métricas de Rendimiento (PMDA).

Normalmente newhelp opera en el Espacio de Nombres de Métricas de Rendimiento (PMNS) predeterminado, sin embargo, si se especifica la opción -n, se carga un espacio de nombres alternativo del archivo pmnsfile.

Cuando solo hay un archivo de entrada, el nombre base de la nueva base de datos se deriva del nombre del archivo de entrada, de lo contrario, se debe proporcionar la opción -o para nombrar explícitamente la base de datos. Si no se proporcionan archivos de entrada, newhelp lee desde el flujo de entrada estándar, en cuyo caso se debe proporcionar la opción -o.

Si el nombre del archivo de salida se determina como foo, newhelp creará foo.dir y foo.pag.

La opción -V causa que se impriman mensajes detallados mientras newhelp está analizando su entrada.

La primera línea de cada entrada en un archivo de origen de ayuda consiste en un carácter ``@'' que comienza la línea seguido de un espacio y luego el nombre de la métrica de rendimiento y una descripción de una línea de la métrica. Las líneas siguientes (hasta la próxima línea que comience con ``@'' o el final del archivo) pueden contener una descripción de ayuda detallada. Por ejemplo:

#
# Este es un ejemplo de la sintaxis de entrada de newhelp
#
@ kernel.all.cpu.idle Tiempo de inactividad de la CPU
Un recuento acumulativo del número de milisegundos
de tiempo de inactividad de la CPU, sumado sobre todos los procesadores.

Se pueden usar identificadores numéricos de métrica de tres partes (PMID) en lugar de nombres de métricas, por ejemplo, 60.0.23 en lugar de kernel.all.cpu.idle en el ejemplo anterior. Aparte de las métricas dinámicas (donde la existencia de una métrica es conocida por un PMDA, pero no es visible en el PMNS y, por lo tanto, no tiene un nombre que pueda ser conocido por newhelp), no se fomenta el uso de esta variante sintáctica.

Las líneas que comienzan con ``#'' se ignoran, al igual que las líneas en blanco en el archivo antes del primer ``@''. El texto de ayuda detallado es opcional.

Como caso especial, un nombre de ``métrica'' de la forma NNN.MM (para NNN y MM numéricos) se interpreta como una identificación de dominio de instancia, y el texto describe el dominio de instancia.

OPCIONES

Las opciones de línea de comandos disponibles son:

-o salida, --output=salida
Especifica el nombre base para los archivos de salida.
-n pmnsfile, --namespace=pmnsfile
Carga un Espacio de Nombres de Métricas de Rendimiento (PMNS(5)) alternativo desde el archivo pmnsfile.
-v version, --version=version
Establece la versión de salida. Esta opción está obsoleta, el único valor soportado es 2.
-V, --verbose
Imprime salida detallada.
-?, --help
Muestra el mensaje de uso y sale.

ARCHIVOS

$PCP_VAR_DIR/pmns/*
archivos de especificación PMNS predeterminados

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

Para variables de entorno que afectan a las herramientas de PCP, consulte pmGetOptions(3).

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a solucionar problemas, aunque la información a veces es críptica y está destinada principalmente a proporcionar orientación a los desarrolladores en lugar de a los usuarios finales. debug es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.
