NEWGRP(1P) Manual de Programador de POSIX NEWGRP(1P)

PROLOGO

Esta página del manual forma parte del Manual de Programador de POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

newgrp — cambiar a un nuevo grupo

SINOPSIS

newgrp [-l] [grupo]

DESCRIPCION

La utilidad newgrp creará un nuevo entorno de ejecución de shell con una nueva identificación de grupo real y efectiva. De los atributos enumerados en la Sección 2.12, Entorno de Ejecución del Shell, el nuevo entorno de ejecución de shell conservará el directorio de trabajo, la máscara de creación de archivos y las variables exportadas del entorno anterior (es decir, los archivos abiertos, las trampas, las variables no exportadas, las definiciones de alias, las funciones del shell y las opciones de set pueden perderse). Todos los demás aspectos del entorno del proceso que se conservan por la familia de funciones exec definidas en el Volumen de Interfaces del Sistema de POSIX.1‐2017 también se conservarán por newgrp; si otros aspectos se conservan no está especificado.

Un fallo en la asignación de las nuevas identificaciones de grupo (por ejemplo, por motivos de seguridad o de contraseña) no impedirá la creación del nuevo entorno de ejecución de shell.

La utilidad newgrp afectará a los grupos suplementarios del proceso de la siguiente manera:

*
En sistemas donde el ID de grupo efectivo está normalmente en la lista de grupos suplementarios (o siempre que el antiguo ID de grupo efectivo esté realmente en la lista de grupos suplementarios):
--
Si el nuevo ID de grupo efectivo también está en la lista de grupos suplementarios, newgrp cambiará el ID de grupo efectivo.
--
Si el nuevo ID de grupo efectivo no está en la lista de grupos suplementarios, newgrp agregará el nuevo ID de grupo efectivo a la lista, si hay espacio para agregarlo.
*
En sistemas donde el ID de grupo efectivo no está normalmente en la lista de grupos suplementarios (o siempre que el antiguo ID de grupo efectivo no esté en la lista de grupos suplementarios):
--
Si el nuevo ID de grupo efectivo está en la lista de grupos suplementarios, newgrp lo eliminará.
--
Si el antiguo ID de grupo efectivo no está en la lista suplementaria, newgrp lo agregará si hay espacio.
Nota:
El Volumen de Interfaces del Sistema de POSIX.1‐2017 no especifica si el ID de grupo efectivo de un proceso está incluido en su lista de grupos suplementarios.

Sin operandos, newgrp cambiará el grupo efectivo de nuevo a los grupos identificados en la entrada del usuario, y establecerá la lista de grupos suplementarios a ese conjunto en las entradas de la base de datos de grupos del usuario.

Si el primer argumento es '-', los resultados no están especificados.

Si se requiere una contraseña para el grupo especificado, y el usuario no está listado como miembro de ese grupo en la base de datos de grupos, se le pedirá al usuario que introduzca la contraseña correcta para ese grupo. Si el usuario está listado como miembro de ese grupo, no se solicitará ninguna contraseña. Si no se requiere ninguna contraseña para el grupo especificado, está definido por la implementación si los usuarios no listados como miembros de ese grupo pueden cambiar a ese grupo. Ya sea que se requiera o no una contraseña, los mecanismos de contabilidad o seguridad del sistema definidos por la implementación pueden imponer restricciones de autorización adicionales que pueden hacer que newgrp escriba un mensaje de diagnóstico y suprima el cambio de la identificación de grupo.

OPCIONES

La utilidad newgrp se ajustará al Volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de Sintaxis de Utilidades, excepto por el uso no especificado de '-'.

Se admitirá la siguiente opción:

-l
(La letra ele.) Cambiar el entorno a lo que se esperaría si el usuario realmente iniciara sesión de nuevo.

OPERANDOS

Se admitirá el siguiente operando:

grupo
Un nombre de grupo de la base de datos de grupos o un ID de grupo numérico no negativo. Especifica el ID de grupo al que se establecerán los ID de grupo real y efectivo. Si grupo es una cadena numérica no negativa y existe en la base de datos de grupos como un nombre de grupo (ver getgrnam()), se utilizará el ID de grupo numérico asociado con ese nombre de grupo como ID de grupo.

ENTRADA ESTÁNDAR

No utilizada.

ARCHIVOS DE ENTRADA

El archivo /dev/tty se utilizará para leer una sola línea de texto para la verificación de contraseñas, cuando sea necesario.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de newgrp:

LANG
Proporcionar un valor predeterminado para las variables de internacionalización que no estén establecidas o estén vacías. (Consulte el Volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización.)
LC_ALL
Si se establece en un valor de cadena no vacío, anulará los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determinar la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en argumentos).
LC_MESSAGES

Determinar la localización que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en el error estándar.
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Predeterminado.

SALIDA ESTÁNDAR

No utilizada.

ERROR ESTÁNDAR

El error estándar se utilizará para mensajes de diagnóstico y una cadena de indicación para una contraseña, si se requiere una. Los mensajes de diagnóstico pueden escribirse en casos en los que el estado de salida no esté disponible. Consulte la sección ESTADO DE SALIDA.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Si newgrp tiene éxito en la creación de un nuevo entorno de ejecución de shell, ya sea que la identificación de grupo se haya cambiado con éxito o no, el estado de salida será el estado de salida del shell. De lo contrario, se devolverá el siguiente valor de salida:

>0
Ocurrió un error.

El shell invocador puede terminar.

newgrp(1) — Arch Linux man pages

PROLOG

This page is a manual page for newgrp (1) of the Linux utility newgrp.

NAME

newgrp ‐ change group identification

SYNOPSIS

newgrp [-f] [group]

DESCRIPTION

The newgrp utility initiates a new shell whose parent process ID remains the same as that of the user's login shell but whose effective group ID is the specified group. This is the only practical way to change the user's working group ID.

If the optional argument group is given, it is used to specify the group name or number of the new group. If the optional argument group is not given, the user's default login group is used.

In order to enable a user to alter the group identification regardless of the rest of the system's protections, the newgrp utility resets the valid group ID, effective group ID, and the saved set group ID.

This command has been superseded by the multiple group permissions feature of POSIX.1‐2017. In some cases, it may discourage poor security practices. Group passwords may disappear in the future.

OPTIONS

-f
If the -f option is specified, and if the group ID specified by group is not a member of the user's group list, then the group password is read from the terminal.

OPERANDS

The group argument specifies the group name or number of the new group. If it is omitted, the user's default login group is used.

STDIN

If the -f option is specified, and the group ID specified by group is not a member of the user's group list, the group password is read from standard input.

INPUT FILES

/etc/group
/etc/gshadow

ENVIRONMENT VARIABLES

See sh(1)> for a description of the environment variables that affect the execution of newgrp.

ASYNCHRONOUS EVENTS

None.

STDOUT

None.

STDERR

Diagnostic messages are written to standard error.

OUTPUT FILES

None.

EXTENDED DESCRIPTION

A common implementation of newgrp is that the current shell uses exec to overlay itself with newgrp, which in turn overlays itself with a new shell after changing group. On some implementations, however, this may not occur and newgrp may be invoked as a subprocess.

The newgrp command is intended only for use from an interactive terminal. It does not offer a useful interface for the support of applications.

EXIT STATUS

The exit status of newgrp is generally inapplicable. If newgrp is used in a script, in most cases it successfully invokes a new shell and the rest of the original shell script is bypassed when the new shell exits. Used interactively, newgrp displays diagnostic messages to indicate problems. But usage such as:

newgrp foo
echo $?

is not useful because the new shell might not have access to any status newgrp may have generated (and most historical systems do not provide this status). A zero status echoed here does not necessarily indicate that the user has changed to the new group successfully. Following newgrp with the id command provides a portable means of determining whether the group change was successful or not.

CONSEQUENCES OF ERRORS

None.

APPLICATION USAGE

None.

EXAMPLES

None.

RATIONALE

Most historical implementations use one of the exec functions to implement the behavior of newgrp. Errors detected before the exec leave the environment unchanged, while errors detected after the exec leave the user in a changed environment. While it would be useful to have newgrp issue a diagnostic message to tell the user that the environment changed, it would be inappropriate to require this change to some historical implementations.

The password mechanism is allowed in the group database, but how this would be implemented is not specified.

The newgrp utility was retained in this volume of POSIX.1‐2017, even given the existence of the multiple group permissions feature in the System Interfaces volume of POSIX.1‐2017, for several reasons. First, in some implementations, the group ownership of a newly created file is determined by the group of the directory in which the file is created, as allowed by the System Interfaces volume of POSIX.1‐2017; on other implementations, the group ownership of a newly created file is determined by the effective group ID. On implementations of the latter type, newgrp allows files to be created with a specific group ownership. Finally, many implementations use the real group ID in accounting, and on such systems, newgrp allows the accounting identity of the user to be changed.
