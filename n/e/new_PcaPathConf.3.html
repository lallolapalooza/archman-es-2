DESCRIPCIÓN

El objeto PathCache es parte de la biblioteca tecla (ver la página del manual libtecla(3)).

Los objetos PathCache permiten a una aplicación buscar archivos en cualquier lista de directorios separada por dos puntos, como la variable de entorno de ejecución PATH de Unix. Los archivos en directorios absolutos se almacenan en caché en un objeto PathCache, mientras que los directorios relativos se escanean según sea necesario. Utilizando un objeto PathCache, puede buscar la ruta completa de un nombre de archivo simple, o puede obtener una lista de las posibles completaciones de un prefijo de nombre de archivo dado. Por defecto, todos los archivos en la lista de directorios son objetivos para la búsqueda y completación, pero se proporciona un mecanismo versátil para seleccionar solo tipos específicos de archivos. La aplicación obvia de esta funcionalidad es proporcionar la completación con Tab y la búsqueda de comandos ejecutables en el PATH de Unix, por lo que se proporciona una devolución de llamada opcional que rechaza todos los archivos excepto los ejecutables.

UN EJEMPLO

Bajo UNIX, el siguiente programa de ejemplo busca y muestra las rutas completas de cada uno de los nombres de comando en la línea de comandos.

  #include <stdio.h>
  #include <stdlib.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  {
    int i;
  /*
   * Crear una caché para archivos ejecutables.
   */
    PathCache *pc = new_PathCache();
    if(!pc)
      exit(1);
  /*
   * Escanear el PATH del usuario en busca de ejecutables.
   */
    if(pca_scan_path(pc, getenv("PATH"))) {
      fprintf(stderr, "%s\n", pca_last_error(pc));
      exit(1);
    }
  /*
   * Organizar para informar solo archivos ejecutables.
   */
   pca_set_check_fn(pc, cpl_check_exe, NULL);
  /*
   * Buscar y mostrar la ruta completa de cada uno de los
   * comandos listados en la línea de comandos.
   */
    for(i=1; i<argc; i++) {
      char *cmd = pca_lookup_file(pc, argv[i], -1, 0);
      printf("La ruta completa de '%s' es %s\n", argv[i],
             cmd ? cmd : "desconocido");
    }
    pc = del_PathCache(pc);  /* Limpiar */
    return 0;
  }

El siguiente es un ejemplo de lo que esto hace en mi portátil con Linux:

  $ ./example less more blob
  La ruta completa de 'less' es /usr/bin/less
  La ruta completa de 'more' es /bin/more
  La ruta completa de 'blob' es desconocido
  $

DESCRIPCIONES DE FUNCIONES

Para utilizar las funcionalidades de este módulo, primero debe asignar un objeto PathCache llamando a la función constructora new_PathCache().

  PathCache *new_PathCache(void)

Esta función crea los recursos necesarios para almacenar en caché y buscar archivos en una lista de directorios. Devuelve NULL en caso de error.

POBLANDO LA CACHÉ

Una vez que haya creado una caché, debe poblarla con archivos. Para hacer esto, llame a la función pca_scan_path().

  int pca_scan_path(PathCache *pc, const char *path);

Cada vez que se llama a esta función, descarta el contenido actual de la caché, luego escanea la lista de directorios especificada en su argumento path en busca de archivos. El argumento path debe ser una cadena que contenga una lista de directorios separados por dos puntos, como "/usr/bin:/home/mcs/bin:.". Esto puede incluir directorios especificados por rutas absolutas como "/usr/bin", así como subdirectorios especificados por rutas relativas como "." o "bin". Los archivos en los directorios absolutos se almacenan inmediatamente en caché en el objeto PathCache especificado, mientras que los subdirectorios, cuyas identidades obviamente cambian cada vez que se cambia el directorio de trabajo actual, se marcan para ser escaneados sobre la marcha cada vez que se busca un archivo.

En caso de éxito, esta función devuelve 0. En caso de error, devuelve 1, y se puede obtener una descripción del error llamando a pca_last_error(pc).

BUSCANDO ARCHIVOS

Una vez que la caché se ha poblado con archivos, puede buscar la ruta completa de un archivo, simplemente especificando su nombre de archivo a pca_lookup_file().

  char *pca_lookup_file(PathCache *pc, const char *name,
                        int name_len, int literal);

Para que sea posible pasar a esta función un nombre de archivo que en realidad forma parte de una cadena más larga, se puede usar el argumento name_len para especificar la longitud del nombre de archivo al principio del argumento name[]. Si pasa -1 para esta longitud, la longitud de la cadena se determinará con strlen(). Si la cadena name[] puede contener barras invertidas que escapan los significados especiales de los espacios y las tabulaciones dentro del nombre de archivo, dé al argumento literal el valor 0. De lo contrario, si las barras invertidas deben tratarse como caracteres normales, pase 1 para el valor del argumento literal.

COMPLETADO DE NOMBRES DE ARCHIVO

Buscar las posibles completaciones de un prefijo de nombre de archivo en la caché de nombres de archivo se logra pasando la función de devolución de llamada proporcionada pca_path_completions() a la función cpl_complete_word() (ver la página del manual cpl_complete_word(3)).

  CPL_MATCH_FN(pca_path_completions);

Esta devolución de llamada requiere que su argumento data sea un puntero a un objeto PcaPathConf. Los objetos de configuración de este tipo se asignan llamando a new_PcaPathConf().

  PcaPathConf *new_PcaPathConf(PathCache *pc);

Esta función devuelve un objeto inicializado con parámetros de configuración predeterminados, que determinan cómo se comporta la función de devolución de llamada cpl_path_completions(). Las funciones que le permiten cambiar individualmente estos parámetros se discuten a continuación.

Por defecto, la función de devolución de llamada pca_path_completions() busca hacia atrás el inicio del nombre de archivo que se está completando, buscando el primer espacio sin escapar o el inicio de la línea de entrada. Si desea especificar una ubicación diferente, llame a ppc_file_start() con el índice en el que comienza el nombre del archivo en la línea de entrada. Pasar start_index=-1 restablece el comportamiento predeterminado.

  void ppc_file_start(PcaPathConf *ppc, int start_index);

Por defecto, cuando pca_path_completions() examina un nombre de archivo en la línea de entrada, cada barra invertida solitaria en la línea de entrada se interpreta como un carácter especial que elimina cualquier significado especial del carácter que le sigue, como un espacio que debe tomarse como parte del nombre del archivo en lugar de delimitar el inicio del nombre del archivo. Por lo tanto, estas barras invertidas se ignoran al buscar completaciones y, posteriormente, se añaden antes de los espacios, tabulaciones y barras invertidas literales en la lista de completaciones. Para que las barras invertidas sin escapar se traten como caracteres normales, llame a ppc_literal_escapes() con un valor distinto de cero en su argumento literal.

  void ppc_literal_escapes(PcaPathConf *ppc, int literal);

Cuando haya terminado con una variable PcaPathConf, puede pasarla a la función destructora del_PcaPathConf() para recuperar su memoria.

  PcaPathConf *del_PcaPathConf(PcaPathConf *ppc);

SIENDO SELECTIVO

Si solo está interesado en ciertos tipos de archivos, como, por ejemplo, archivos ejecutables, o archivos cuyos nombres terminan en un sufijo particular, puede hacer que las funciones de completado y búsqueda de nombres de archivo sean selectivas en los nombres de archivo que devuelven. Esto se hace registrando una función de devolución de llamada con su objeto PathCache. English

NAME

new_PcaPathConf, del_PathCache, pca_scan_path, pca_set_check_fn, pca_last_error - path searching facilities

SYNOPSIS

  PathCache *new_PathCache(void);
  PathCache *del_PathCache(PathCache *pc);
  int pca_scan_path(PathCache *pc, const char *path,
                    const char * const *ignore, int flags);
  void pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn,
                        void *data);
  const char *pca_last_error(PathCache *pc);

DESCRIPTION

The functions in this section provide facilities for searching directories for files. They are intended to be used to help with filename completion, but they may be used for any purpose that requires searching lists of directories for files. The search is performed by the pca_scan_path() function, which takes a list of directories to be searched, and populates a cache of information about the files found in those directories. This cache can then be used to quickly determine if a given string matches any of the files found, or to generate a list of possible completions.

A PathCache object is used to hold the cache. It may be created by calling new_PathCache(), and destroyed by calling del_PathCache(). If new_PathCache() fails, it returns NULL. It is safe to pass NULL to del_PathCache().

The directories to be searched are passed to pca_scan_path() as a colon-separated list of pathnames, in the path argument. This is the same format as that used by the PATH environment variable. If the path argument is NULL, the directories listed in the PATH environment variable are searched instead. The ignore argument is a list of filenames that should be ignored when populating the cache. This list is terminated by a NULL pointer. The flags argument can be used to modify the behaviour of pca_scan_path(). Currently, the only flag defined is PCA_FOLLOW_LINKS, which causes symbolic links to be followed. Without this flag, symbolic links are ignored.

The pca_scan_path() function returns 1 if an error occurred during the scan, and 0 if the scan was successful. If an error occurred, a description of the error can be obtained by calling pca_last_error().

AN EXAMPLE

  PathCache *pc;
  char *path = getenv("PATH");

  pc = new_PathCache();
  if (!pc) {
    fprintf(stderr, "Out of memory\n");
    exit(1);
  }

  if (pca_scan_path(pc, path, NULL, 0)) {
    fprintf(stderr, "Error scanning path: %s\n", pca_last_error(pc));
    exit(1);
  }

  /* Now use the cache for completions... */

  del_PathCache(pc);

FUNCTION DESCRIPTIONS

PathCache *new_PathCache(void);
Creates and returns a new PathCache object. Returns NULL on failure.
PathCache *del_PathCache(PathCache *pc);
Frees the resources associated with a PathCache object. Returns NULL.
int pca_scan_path(PathCache *pc, const char *path, const char * const *ignore, int flags);
Scans the directories specified by path, adding entries to the PathCache object pc. If path is NULL, the value of the PATH environment variable is used. The list of filenames in ignore is skipped. flags may be used to modify behaviour (currently only PCA_FOLLOW_LINKS is supported). Returns 1 on error, 0 on success.
void pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn, void *data);
Sets a callback function check_fn, to be called for each file found during a scan. The callback is passed a pointer to arbitrary user data data, and the full pathname of the file. If the callback returns 1, the file is added to the cache. If it returns 0, the file is ignored. If check_fn is NULL, no filtering is performed. This function also invalidates the cache, forcing a rescan the next time lookups are performed.
const char *pca_last_error(PathCache *pc);
Returns a string describing the last error that occurred in the specified PathCache object.

POPULATING THE CACHE

The cache is populated by calling pca_scan_path(). This function iterates through the directories specified in the path argument, and for each file found, it calls the registered check function (see BEING SELECTIVE below). If the check function returns true, the file is added to the cache. The cache is initially empty, so the first call to pca_scan_path() will populate it. Subsequent calls will rebuild the cache from scratch.

LOOKING UP FILES

Once the cache has been populated, you can use it to look up files. The cpl_path_completions() function (see cpl_complete_word(3)) uses the cache to find possible completions for a given filename prefix. You can also iterate through the cache yourself if you need to perform custom searches.

FILENAME COMPLETION

The primary use of the PathCache is to aid filename completion. When a user is typing a command or filename, and presses the tab key, the shell can use the PathCache to generate a list of possible completions. The cpl_path_completions() function is used for this purpose. It takes the current prefix string, and returns a list of possible completions from the cache.

BEING SELECTIVE

Sometimes, you may only want to complete certain types of files. For example, you might only want to complete executable files. The pca_set_check_fn() function allows you to register a callback function that will be called for each file found during a scan. This callback function can then decide whether or not to include the file in the cache.

The callback function will be called with the full pathname of the file, plus any application-specific data that you provide, and if the callback returns 1 the filename will be reported as a match, and if it returns 0, it will be ignored. Suitable callback functions and their prototypes should be declared with the following macro. The CplCheckFn typedef is also provided in case you wish to declare pointers to such functions.

  #define CPL_CHECK_FN(fn) int (fn)(void *data, \
                                    const char *pathname)
  typedef CPL_CHECK_FN(CplCheckFn);

Registering one of these functions involves calling the pca_set_check_fn() function. In addition to the callback function, passed via the check_fn argument, you can pass a pointer to anything via the data argument. This pointer will be passed on to your callback function, via its own data argument, whenever it is called, so this provides a way to pass appplication specific data to your callback.

  void pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn,
                        void *data);

Note that these callbacks are passed the full pathname of each matching file, so the decision about whether a file is of interest can be based on any property of the file, not just its filename. As an example, the provided cpl_check_exe() callback function looks at the executable permissions of the file and the permissions of its parent directories, and only returns 1 if the user has execute permission to the file. This callback function can thus be used to lookup or complete command names found in the directories listed in the user's PATH environment variable. The example program given earlier in this man page provides a demonstration of this.

Beware that if somebody tries to complete an empty string, your callback will get called once for every file in the cache, which could number in the thousands. If your callback does anything time consuming, this could result in an unacceptable delay for the user, so callbacks should be kept short.

To improve performance, whenever one of these callbacks is called, the choice that it makes is cached, and the next time the corresponding file is looked up, instead of calling the callback again, the cached record of whether it was accepted or rejected is used. Thus if somebody tries to complete an empty string, and hits tab a second time when nothing appears to happen, there will only be one long delay, since the second pass will operate entirely from the cached dispositions of the files. These cached dipositions are discarded whenever pca_scan_path() is called, and whenever pca_set_check_fn() is called with changed callback function or data arguments.

ERROR HANDLING

If pca_scan_path() reports that an error occurred by returning 1, you can obtain a terse description of the error by calling pca_last_error(pc). This returns an internal string containing an error message.

  const char *pca_last_error(PathCache *pc);

CLEANING UP

Once you have finished using a PathCache object, you can reclaim its resources by passing it to the del_PathCache() destructor function. This takes a pointer to one of these objects, and always returns NULL.

  PathCache *del_PathCache(PathCache *pc);

THREAD SAFETY

In multi-threaded programs, you should use the libtecla_r.a version of the library. This uses POSIX reentrant functions where available (hence the _r suffix), and disables features that rely on non-reentrant system functions. In the case of this module, the only disabled feature is username completion in ~username/ expressions, in cpl_path_completions().

Using the libtecla_r.a version of the library, it is safe to use the facilities of this module in multiple threads, provided that each thread uses a separately allocated PathCache object. In other words, if two threads want to do path searching, they should each call new_PathCache() to allocate their own caches.
