NE_SET_REQUEST_BODY_(3) Referencia de la API de neon NE_SET_REQUEST_BODY_(3)

NOMBRE

ne_set_request_body_buffer, ne_set_request_body_fd, ne_set_request_body_provider - incluir un cuerpo de mensaje con una solicitud

SINOPSIS

#include <ne_request.h>

void ne_set_request_body_buffer(ne_request *req, const char *buf, size_t count);

int ne_set_request_body_fd(ne_request *req, int fd, ne_off_t begin, ne_off_t length);

typedef ssize_t (*ne_provide_body)(void *userdata, char *data, size_t buflen);

int ne_set_request_body_provider(ne_request *req, ne_off_t length, ne_provide_body provider, void *userdata);

DESCRIPCIÓN

La función ne_set_request_body_buffer especifica que se debe incluir un cuerpo de mensaje con la solicitud, el cual está almacenado en el buffer de count bytes buf.

La función ne_set_request_body_fd se puede utilizar para incluir un cuerpo de mensaje con una solicitud que se lee desde un descriptor de archivo. El cuerpo se lee desde el descriptor de archivo fd, que debe estar asociado a un archivo buscable (no a una tubería, socket o FIFO). Se leen count bytes, comenzando en el desplazamiento begin (por lo tanto, pasar begin como cero significa que el cuerpo se lee desde el principio del archivo).

Para ambas funciones anteriores, la fuente del cuerpo de la solicitud debe sobrevivir hasta que la solicitud haya sido enviada; ni el buffer de memoria pasado a ne_set_request_body_buffer ni el descriptor de archivo pasado a ne_set_request_body_fd se copian internamente.

La función ne_set_request_body_provider se puede utilizar para incluir un cuerpo de mensaje con una solicitud que es proporcionada por una función de devolución de llamada. La longitud del cuerpo pasada en el parámetro length debe ser positiva, o si se requiere un cuerpo de solicitud fragmentado, como se describe a continuación, se puede usar -1.

Antes de enviar el cuerpo, la función de devolución de llamada se invoca una vez con el parámetro buflen establecido en 0. Luego, el cuerpo se lee invocando repetidamente la función de devolución de llamada hasta que devuelva 0, lo que indica el final del cuerpo. El valor de retorno de la función de devolución de llamada debe ser el siguiente:

menor que 0

Un error; la solicitud se abortará. La cadena de error de la sesión debe establecerse a través de ne_set_error.

0

Fin del cuerpo.

entre 0 y buflen

Número de bytes de datos del cuerpo de la solicitud.

Cuerpos de solicitud fragmentados

Los cuerpos de solicitud fragmentados solo se envían cuando se utiliza ne_set_request_body_provider y se pasa -1 como length. En este caso, la longitud del cuerpo de la solicitud no tiene que determinarse con antelación. El final del cuerpo de la solicitud se indica devolviendo 0 desde la función de devolución de llamada.

Antes de utilizar un cuerpo de solicitud fragmentado, el llamador debe determinar que el servidor de origen y cualquier servidor proxy HTTP configurado admiten HTTP/1.1. Esto se puede hacer probando que ne_version_pre_http11 devuelva cero después de realizar una solicitud OPTIONS o HEAD.
