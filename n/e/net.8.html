NET(8) Herramientas de administración del sistema NET(8)

NOMBRE

net - Herramienta para la administración de servidores Samba y CIFS remotos.

SINOPSIS

net {<ads|rap|rpc>} [-h|--help] [-d|--debuglevel=NIVEL_DE_DEPURACIÓN] [--debug-stdout] [--configfile=ARCHIVO_CONFIG] [--option=nombre=valor] [-l|--log-basename=BASE_ARCHIVO_LOG] [--leak-report] [--leak-report-full] [-R|--name-resolve=ORDEN_RESOLUCIÓN_NOMBRES] [-O|--socket-options=OPCIONES_SOCKET] [-m|--max-protocol=PROTOCOLO_MÁXIMO] [-n|--netbiosname=NOMBRE_NETBIOS] [--netbios-scope=ÁMBITO] [-W|--workgroup=GRUPO_TRABAJO] [--realm=DOMINIO] [-U|--user=[DOMINIO/]USUARIO[%CONTRASEÑA]] [-N|--no-pass] [--password=CADENA] [--pw-nt-hash] [-A|--authentication-file=ARCHIVO] [-P|--machine-pass] [--simple-bind-dn=DN] [--use-kerberos=deseado|requerido|apagado] [--use-krb5-ccache=CCACHE] [--use-winbind-ccache] [--client-protection=firmar|cifrar|apagado] [-V|--version] [-w|--target-workgroup grupo_trabajo] [-I|--ipaddress direccion_ip] [-p|--port puerto] [--myname] [-S|--server servidor] [--long] [-v|--verbose] [-f|--force] [--request-timeout segundos] [-t|--timeout segundos] [--dns-ttl TTL_EN_SEGUNDOS] [-i|--stdin] [--witness-registration=UUID_REGISTRO] [--witness-net-name=REGEX] [--witness-share-name=REGEX] [--witness-ip-address=REGEX] [--witness-client-computer-name=REGEX] [--witness-apply-to-all] [--witness-new-node=ID_NODO] [--witness-new-ip=DIRECCION_IP] [--witness-forced-response=JSON]

DESCRIPCIÓN

Esta herramienta forma parte del conjunto samba(7).

La utilidad net de Samba está pensada para funcionar igual que la utilidad net disponible para Windows y DOS. El primer argumento debe usarse para especificar el protocolo a utilizar al ejecutar un comando determinado. ADS se utiliza para Active Directory, RAP se utiliza para clientes antiguos (Win9x/NT3) y RPC se puede usar para NT4 y Windows 2000. Si se omite este argumento, net intentará determinarlo automáticamente. No todos los comandos están disponibles para todos los protocolos.

-d|--debuglevel=nivel

nivel es un número entero de 0 a 10. El valor predeterminado si este parámetro no se especifica es 1 para las aplicaciones cliente.

Cuanto mayor sea este valor, más detalles se registrarán en los archivos de registro sobre las actividades del servidor. En el nivel 0, solo se registrarán errores críticos y advertencias graves. El nivel 1 es un nivel razonable para la operación diaria: genera una pequeña cantidad de información sobre las operaciones realizadas.

Los niveles superiores a 1 generarán una cantidad considerable de datos de registro y solo deben usarse al investigar un problema. Los niveles superiores a 3 están diseñados para ser utilizados únicamente por los desarrolladores y generan ENORMES cantidades de datos de registro, la mayor parte de los cuales es extremadamente críptica.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro nivel de registro en el archivo /etc/samba/smb.conf.

-R|--name-resolve=ORDEN-RESOLUCION-NOMBRES

Esta opción se utiliza para determinar qué servicios de nombres y en qué orden resolver nombres de host a direcciones IP. La opción toma una cadena separada por espacios de diferentes opciones de resolución de nombres. Lo mejor es envolver todo --name-resolve=ORDEN-RESOLUCION-NOMBRES entre comillas.

Las opciones son: "lmhosts", "host", "wins" y "bcast". Hacen que los nombres se resuelvan de la siguiente manera:

•lmhosts: Busca una dirección IP en el archivo lmhosts de Samba. Si la línea en lmhosts no tiene un tipo de nombre asociado al nombre NetBIOS (ver lmhosts(5) para más detalles) entonces cualquier tipo de nombre coincide para la búsqueda.
•host: Realiza una resolución estándar de nombre de host a dirección IP, utilizando las búsquedas /etc/hosts, NIS o DNS del sistema. Este método de resolución de nombres depende del sistema operativo; por ejemplo, en IRIX o Solaris, esto puede ser controlado por el archivo /etc/nsswitch.conf). Tenga en cuenta que este método solo se utiliza si el tipo de nombre NetBIOS que se consulta es el tipo de nombre 0x20 (servidor), de lo contrario, se ignora.
•wins: Consulta un nombre con la dirección IP listada en el parámetro wins server. Si no se ha especificado ningún servidor WINS, este método se ignorará.
•bcast: Realiza una difusión en cada una de las interfaces locales conocidas listadas en el parámetro interfaces. Este es el método de resolución de nombres menos confiable, ya que depende de que el host de destino esté en una subred conectada localmente.
Si este parámetro no está configurado, se utilizará el orden de resolución de nombres definido en el parámetro del archivo /etc/samba/smb.conf (orden de resolución de nombres).

El orden predeterminado es lmhosts, host, wins, bcast. Sin este parámetro o sin ninguna entrada en el parámetro orden de resolución de nombres del archivo /etc/samba/smb.conf, los métodos de resolución de nombres se intentarán en este orden.

-U|--user=[DOMINIO\]NOMBREDEUSUARIO[%CONTRASEÑA]

Establece el nombre de usuario SMB o el nombre de usuario y contraseña.

Si no se especifica %CONTRASEÑA, se le pedirá al usuario. El cliente primero comprobará la variable de entorno USER (que también puede contener la contraseña separada por un %), luego la variable LOGNAME (que no puede contener una contraseña) y si alguna existe, se utilizará su valor. Si estas variables de entorno no se encuentran, se puede utilizar el nombre de usuario encontrado en una caché de credenciales de Kerberos.

Una tercera opción es utilizar un archivo de credenciales que contenga la contraseña sin cifrar del nombre de usuario y la contraseña. Esta opción se proporciona principalmente para scripts en los que el administrador no desea pasar las credenciales en la línea de comandos o a través de variables de entorno. Si se utiliza este método, asegúrese de que los permisos del archivo restrinjan el acceso a usuarios no deseados. Consulte la opción -A para obtener más detalles.

Tenga cuidado al incluir contraseñas en scripts o al pasar valores proporcionados por el usuario en la línea de comandos. Por seguridad, es mejor dejar que la herramienta cliente de Samba solicite la contraseña si es necesario, u obtenga la contraseña una vez con kinit.

Aunque Samba intentará limpiar la contraseña del título del proceso (como se ve en ps), esto es después del inicio y, por lo tanto, está sujeto a una condición de carrera.

Si se especifica una contraseña en la línea de comandos y también se define esta opción, la contraseña de la línea de comandos se ignorará silenciosamente y no se utilizará ninguna contraseña.

Especifica la contraseña en la línea de comandos.

Tenga cuidado al incluir contraseñas en scripts o al pasar valores proporcionados por el usuario en la línea de comandos. Por seguridad, es mejor dejar que la herramienta cliente de Samba solicite la contraseña si es necesario, u obtenga la contraseña una vez con kinit.

[RPC|ADS] UNIRSE [TIPO] [--sin-actualizaciones-dns] [-U usuario[%contraseña]] [nombre-dns=FQDN] [crearupn=UPN] [crearordenador=OU] [contraseñamac=PASS] [nombreSO=cadena verSO=cadena] [opciones]

Unirse a un dominio. Si la cuenta ya existe en el servidor, y [TIPO] es MIEMBRO, la máquina intentará unirse automáticamente. (Suponiendo que la máquina se ha creado en el administrador del servidor) De lo contrario, se le pedirá una contraseña y se puede crear una nueva cuenta.

[TIPO] puede ser PDC, BDC o MIEMBRO para especificar el tipo de servidor que se une al dominio.

[FQDN] (solo ADS) establece el atributo dnsHostName durante la unión. El formato predeterminado es nombreNetbios.dominioDNS.

[UPN] (solo ADS) establece el atributo principalname durante la unión. El formato predeterminado es host/nombreNetbios@REALM.

[OU] (solo ADS) Precrea la cuenta de ordenador en una OU específica. La cadena de la OU se lee de arriba a abajo sin RDN, y está delimitada por '/'. Tenga en cuenta que '\' es utilizado para escapar tanto por el shell como por ldap, por lo que puede necesitar ser duplicado o cuadruplicado para pasar, y no se utiliza como delimitador.

[PASS] (solo ADS) Establece una contraseña específica en la cuenta de ordenador que se está creando al unirse.

[nombreSO=cadena verSO=Cadena] (solo ADS) Establece los atributos operatingSystem y operatingSystemVersion durante la unión. Ambos parámetros deben especificarse para que alguno de ellos tenga efecto.

ADS KEYTAB CREATE

Desde Samba 4.21.0, el archivo keytab se crea según lo especificado en sync machine password to keytab. El keytab solo se puede crear cuando la contraseña de la máquina está disponible en secrets.tdb, es decir, solo para kerberos method = secrets only y kerberos method = secrets and keytab. Con los valores predeterminados de smb.conf para kerberos method = secrets only y sync machine password to keytab (el valor predeterminado es vacío), el keytab no se genera en absoluto. El keytab con un nombre predeterminado que contiene: SPN sincronizados de AD, nombre de cuenta COMPUTER$ y principal host/dns_hostname se crea para kerberos method = secrets and keytab si falta sync machine password to keytab.

Hasta Samba 4.20, estas entradas se creaban por defecto: el nombre de cuenta COMPUTER$, el principal 'host' y los SPN sincronizados desde AD. El ejemplo a continuación genera dicho keytab:

sync machine password to keytab = /etc/krb5.keytab:spn_prefixes=host:account_name:sync_spns:sync_kvno:machine_password

No se realizan cambios en la cuenta AD del equipo.

(Eliminado!) ADS KEYTAB ADD (principal | machine | serviceclass | windows SPN)

Este comando ya no está disponible en Samba 4.21.0 y versiones posteriores. Consulte sync machine password to keytab para ver el reemplazo.

Para reemplazar, por ejemplo, una llamada a

Añada a smb.conf:

sync machine password to keytab = /path/to/keytab1:spns=wurst/brot@REALM:machine_password

y ejecute:

net ads keytab create

Descripción original de este comando:

Añade una nueva entrada de keytab, la entrada puede ser:

principal de Kerberos

Un principal de Kerberos (identificado por la presencia de '@') simplemente se añade al archivo keytab.

nombre de máquina

Un nombre de máquina (identificado por el '$' al final) se utiliza para crear un principal de Kerberos 'nombre_maquina@realm' que se añade al archivo keytab.

clase de servicio

Una clase de servicio (como 'cifs', 'html', etc.) se utiliza para crear un par de principales de Kerberos 'serviceclass/fully_qualified_dns_name@realm' y 'serviceclass/netbios_name@realm' que se añaden al archivo keytab.

Un SPN de Windows tiene el formato 'serviceclass/host:port', se utiliza para crear un principal de Kerberos 'serviceclass/host@realm' que se escribirá en el archivo keytab.

A diferencia de las versiones antiguas, este comando no modifica objetos AD del equipo. Para preservar el comportamiento de los clientes antiguos, está disponible 'net ads keytab ad_update_ads'.

USERSHARE

A partir de la versión 3.0.23, un servidor Samba admite la capacidad para que los usuarios no root agreguen recursos compartidos definidos por el usuario para ser exportados mediante los comandos "net usershare".

Para configurar esto, primero configure su /etc/samba/smb.conf agregando a la sección [global]: usershare path = /usr/local/samba/lib/usershares. Luego, cree el directorio /usr/local/samba/lib/usershares, cambie el propietario a root y establezca el propietario del grupo en el grupo UNIX que debería tener la capacidad de crear usershares, por ejemplo, un grupo llamado "serverops". Establezca los permisos en /usr/local/samba/lib/usershares en 01770. (Propietario y grupo con todo acceso, sin acceso para otros, más el sticky bit, lo que significa que un archivo en ese directorio solo puede ser renombrado o eliminado por el propietario del archivo). Finalmente, indique a smbd cuántos usershares permitirá agregando a la sección [global] de /etc/samba/smb.conf una línea como: usershare max shares = 100. Para permitir 100 definiciones de usershare. Ahora, los miembros del grupo UNIX "serverops" pueden crear recursos compartidos definidos por el usuario sobre la marcha utilizando los comandos a continuación.

Los comandos de usershare son:

net usershare add nombre_recurso path [comentario] [acl] [invitado_ok=[s|n]] - para agregar o modificar un recurso compartido definido por el usuario.
net usershare delete nombre_recurso - para eliminar un recurso compartido definido por el usuario.
net usershare info [--long] [wildcard nombre_recurso] - para imprimir información sobre un recurso compartido definido por el usuario.
net usershare list [--long] [wildcard nombre_recurso] - para listar los recursos compartidos definidos por el usuario.

USERSHARE AGREGAR nombre_recurso path [comentario] [acl] [invitado_ok=[s|n]]

Agrega o reemplaza un nuevo recurso compartido definido por el usuario, con el nombre "nombre_recurso".

"path" especifica la ruta absoluta en el sistema a exportar. Se pueden imponer restricciones, consulte los parámetros globales de /etc/samba/smb.conf: "usershare owner only", "usershare prefix allow list" y "usershare prefix deny list".

El parámetro opcional "comentario" es el comentario que aparecerá en el recurso compartido cuando sea explorado por un cliente.

El campo opcional "acl" especifica qué usuarios tienen acceso de lectura y escritura a todo el recurso compartido. Tenga en cuenta que las conexiones de invitados no están permitidas a menos que se haya establecido el parámetro "usershare allow guests" en /etc/samba/smb.conf. La definición de una ACL de recurso compartido definido por el usuario es: "usuario:permiso", donde usuario es un nombre de usuario válido en el sistema y permiso puede ser "F", "R" o "D". "F" significa "permisos completos", es decir, permisos de lectura y escritura. "D" significa "denegar" para un usuario, es decir, evitar que este usuario acceda a este recurso compartido. "R" significa "solo lectura", es decir, solo permitir el acceso de lectura a este recurso compartido (sin creación de nuevos archivos o directorios ni escritura en archivos).

El valor predeterminado si no se proporciona ningún "acl" es "Everyone:R", lo que significa que cualquier usuario autenticado tiene acceso de solo lectura.

El "invitado_ok" opcional tiene el mismo efecto que el parámetro del mismo nombre en /etc/samba/smb.conf, ya que permite el acceso de invitados a este recurso compartido definido por el usuario. Este parámetro solo está permitido si el parámetro global "usershare allow guests" se ha establecido en true en /etc/samba/smb.conf.

No hay un comando separado para modificar un recurso compartido definido por el usuario existente, simplemente use el comando "net usershare add [nombre_recurso]" usando el mismo nombre_recurso que el que desea modificar y especifique las nuevas opciones que desee. El demonio smbd de Samba detecta las modificaciones de recursos compartidos definidos por el usuario en el momento de la conexión, por lo que verá el cambio inmediatamente, no es necesario reiniciar smbd al agregar, eliminar o cambiar un recurso compartido definido por el usuario.

USERSHARE ELIMINAR nombre_recurso

Elimina el recurso compartido definido por el usuario por nombre. El demonio smbd de Samba detecta este cambio inmediatamente, aunque no desconectará a los usuarios actualmente conectados al recurso compartido eliminado.

USERSHARE INFO [--long] [wildcard nombre_recurso]

Obtiene información sobre los recursos compartidos definidos por el usuario propiedad del usuario actual que coinciden con el patrón dado, o de todos los usuarios.

net usershare info por sí solo extrae información sobre los recursos compartidos definidos por el usuario que fueron creados por el usuario actual, o los restringe a nombres de recursos compartidos que coincidan con el patrón comodín dado ('*' coincide con uno o más caracteres, '?' coincide con un solo carácter). Si también se proporciona la opción '--long', imprime información sobre los recursos compartidos definidos por el usuario creados por otros usuarios.

La información proporcionada sobre un recurso compartido se ve así: [foobar] path=/home/jeremy comment=testme usershare_acl=Everyone:F guest_ok=n Y es una lista de la configuración actual del recurso compartido definido por el usuario que se puede modificar con el comando "net usershare add".

USERSHARE LISTAR [--long] wildcard nombre_recurso

Lista todos los recursos compartidos definidos por el usuario propiedad del usuario actual que coinciden con el patrón dado, o de todos los usuarios.

net usershare list por sí solo lista los nombres de los recursos compartidos definidos por el usuario que fueron creados por el usuario actual, o restringe la lista a nombres de recursos compartidos que coincidan con el patrón comodín dado ('*' coincide con uno o más caracteres, '?' coincide con un solo carácter). Si también se proporciona la opción '--long', incluye los nombres de los recursos compartidos definidos por el usuario creados por otros usuarios.

Muestra un parámetro almacenado en el registro.

[RPC] CONF DELPARM section parameter

Elimina un parámetro almacenado en el registro.

[RPC] CONF GETINCLUDES section

Obtiene la lista de inclusiones para la sección proporcionada (global o recurso compartido).

Tenga en cuenta que, debido a la naturaleza de la base de datos del registro y la naturaleza de las directivas de inclusión, las inclusiones necesitan un tratamiento especial: los parámetros se almacenan en el registro por nombre de parámetro como nombre de valor, por lo que solo hay una instancia de un parámetro por recurso compartido. Además, no se garantiza un orden específico como en un archivo de texto. Para todos los parámetros reales, esto está perfectamente bien, pero la directiva de inclusión es más bien un meta-parámetro, para el cual, en el archivo de texto smb.conf, el lugar donde se especifica entre los otros parámetros es muy importante. Esto no se puede lograr con el simple modelo de datos smbconf del registro, por lo que hay una lista ordenada de inclusiones por recurso compartido, y esta lista se evalúa después de todos los parámetros del recurso compartido.

Tenga en cuenta además que actualmente, solo se pueden incluir archivos desde la configuración del registro. En el futuro, habrá la capacidad de incluir datos de configuración de otras claves del registro.

[RPC] CONF SETINCLUDES section [filename]+

Establece la lista de inclusiones para la sección proporcionada (global o recurso compartido) a la lista dada de uno o más nombres de archivo. Los nombres de archivo pueden contener las macros habituales de smb.conf como %I.

[RPC] CONF DELINCLUDES section

Elimina la lista de inclusiones de la sección proporcionada (global o recurso compartido).

DOM

A partir de la versión 3.2.0, Samba tiene soporte para APIs de unión y desunión remota, tanto del lado del cliente como del servidor. Windows soporta capacidades de unión remota desde Windows 2000.

Para que Samba se una o desuna remotamente, se debe utilizar una cuenta que sea miembro del grupo Domain Admins, miembro del grupo local Administrators, o un usuario al que se le conceda el privilegio SeMachineAccountPrivilege.

El soporte del lado del cliente para la unión remota está implementado en los comandos net dom, que son:

net dom join - Une un equipo remoto a un dominio.
net dom unjoin - Desune un equipo remoto de un dominio.
net dom renamecomputer - Renombra un equipo remoto unido a un dominio.

DOM UNIR dominio=DOMINIO ou=OU cuenta=CUENTA contraseña=CONTRASEÑA reiniciar

Une un equipo a un dominio. Este comando soporta los siguientes parámetros adicionales:

•DOMINIO puede ser un nombre de dominio NetBIOS (también conocido como nombre de dominio corto) o un nombre de dominio DNS para dominios de Active Directory. Al igual que en Windows, también es posible controlar qué controlador de dominio se utilizará. Esto se puede lograr añadiendo el nombre del DC con el carácter separador \. Ejemplo: MYDOM\MYDC. El parámetro DOMINIO no puede ser NULL.
•OU puede establecerse en un DN LDAP RFC 1779, como ou=misequipos,cn=Usuarios,dc=ejemplo,dc=com para crear la cuenta de la máquina en un contenedor LDAP no predeterminado. Este parámetro opcional solo se soporta al unir dominios de Active Directory.
•CUENTA define una cuenta de dominio que se utilizará para unir la máquina al dominio. Esta cuenta de dominio necesita tener privilegios suficientes para unir máquinas.
•CONTRASEÑA define la contraseña para la cuenta de dominio definida con CUENTA.
•REINICIAR es un parámetro opcional que se puede establecer para reiniciar la máquina remota después de unirse correctamente al dominio.

Tenga en cuenta que también necesita utilizar parámetros net estándar para conectarse y autenticarse en la máquina remota que desea unir. Estos parámetros adicionales incluyen: -S ordenador y -U usuario.

Ejemplo: net dom join -S xp -U XP\\administrator%secret dominio=MYDOM cuenta=MYDOM\\administrator contraseña=topsecret reiniciar.

Este ejemplo se conectaría a un equipo llamado XP como administrador local utilizando la contraseña secret, y uniría el equipo a un dominio llamado MYDOM utilizando la cuenta de administrador del dominio MYDOM y la contraseña topsecret. Después de unirse correctamente, el equipo se reiniciaría.

DOM DESUNIR cuenta=CUENTA contraseña=CONTRASEÑA reiniciar

Desune un equipo de un dominio. Este comando soporta los siguientes parámetros adicionales:

•CUENTA define una cuenta de dominio que se utilizará para desunir la máquina del dominio. Esta cuenta de dominio necesita tener privilegios suficientes para desunir máquinas.
•CONTRASEÑA define la contraseña para la cuenta de dominio definida con CUENTA.
•REINICIAR es un parámetro opcional que se puede establecer para reiniciar la máquina remota después de desunirse correctamente del dominio.

Tenga en cuenta que también necesita utilizar parámetros net estándar para conectarse y autenticarse en la máquina remota que desea desunir. Estos parámetros adicionales incluyen: -S ordenador y -U usuario.

Ejemplo: net dom unjoin -S xp -U XP\\administrator%secret cuenta=MYDOM\\administrator contraseña=topsecret reiniciar.

Este ejemplo se conectaría a un equipo llamado XP como administrador local utilizando la contraseña secret, y desuniría el equipo del dominio utilizando la cuenta de administrador del dominio MYDOM y la contraseña topsecret. Después de desunirse correctamente, el equipo se reiniciaría.

Renombra un equipo que está unido a un dominio. Este comando soporta los siguientes parámetros adicionales:

•NUEVO_NOMBRE define el nuevo nombre de la máquina en el dominio.
•CUENTA define una cuenta de dominio que se utilizará para renombrar la máquina en el dominio. Esta cuenta de dominio necesita tener privilegios suficientes para renombrar máquinas.
•CONTRASEÑA define la contraseña para la cuenta de dominio definida con CUENTA.
•REINICIAR es un parámetro opcional que se puede establecer para reiniciar la máquina remota después de renombrarla correctamente en el dominio.

Tenga en cuenta que también necesita utilizar parámetros net estándar para conectarse y autenticarse en la máquina remota que desea renombrar en el dominio. Estos parámetros adicionales incluyen: -S ordenador y -U usuario.

Ejemplo: net dom renamecomputer -S xp -U XP\\administrator%secret nuevo_nombre=XPNEW cuenta=MYDOM\\administrator contraseña=topsecret reiniciar.

Este ejemplo se conectaría a un equipo llamado XP como administrador local utilizando la contraseña secret, y renombraría el equipo unido a XPNEW utilizando la cuenta de administrador del dominio MYDOM y la contraseña topsecret. Después de renombrarse correctamente, el equipo se reiniciaría.

OFFLINEJOIN

A partir de la versión 4.15, Samba admite las API de unión sin conexión. Windows admite funcionalidades de unión sin conexión desde Windows 7 y Windows 2008 R2.

Los siguientes comandos sin conexión están implementados:

net offlinejoin provision - Proporciona una cuenta de máquina en AD.
net offlinejoin requestodj - Solicita una unión sin conexión al dominio.

OFFLINEJOIN PROVISION domain=DOMAIN machine_name=MACHINE_NAME machine_account_ou=MACHINE_ACCOUNT_OU dcname=DCNAME defpwd reuse savefile=FILENAME printblob

Proporciona una cuenta de máquina en AD. Este comando necesita conectividad de red al controlador de dominio para tener éxito. Este comando admite los siguientes parámetros adicionales:

•DOMAIN puede ser un nombre de dominio NetBIOS (también conocido como nombre de dominio corto) o un nombre de dominio DNS para Dominios de Active Directory. El parámetro DOMAIN no puede ser NULO.
•MACHINE_NAME define el nombre de la cuenta de máquina que se proporcionará en AD. El parámetro MACHINE_NAME no puede ser NULO.
•MACHINE_ACCOUNT_OU se puede establecer en un DN LDAP RFC 1779, como ou=mymachines,cn=Users,dc=example,dc=com para crear la cuenta de máquina en un contenedor LDAP no predeterminado. Este parámetro opcional solo se admite al unirse a Dominios de Active Directory.
•DCNAME define un controlador de dominio específico para crear la cuenta de máquina en AD.
•DEFPWD es un parámetro opcional que se puede establecer para forzar el uso de la contraseña predeterminada de la cuenta de máquina. No se recomienda el uso de este parámetro, ya que la contraseña predeterminada de la cuenta de máquina se puede adivinar fácilmente.
•REUSE es un parámetro opcional que se puede establecer para forzar la reutilización de una cuenta de máquina existente en AD.
•SAVEFILE es un parámetro opcional para almacenar los datos de aprovisionamiento generados en disco.
•PRINTBLOB es un parámetro opcional para imprimir los datos de aprovisionamiento generados en la salida estándar.

Ejemplo: net offlinejoin provision -U administrator%secret domain=MYDOM machine_name=MYHOST savefile=provisioning.txt

OFFLINEJOIN REQUESTODJ loadfile=FILENAME

Solicita una unión sin conexión al dominio proporcionando datos de aprovisionamiento basados en archivos. Este comando admite los siguientes parámetros adicionales:

•LOADFILE es un parámetro requerido para cargar el aprovisionamiento desde un archivo.

Ejemplo: net offlinejoin requestodj -U administrator%secret loadfile=provisioning.txt

net

DESCRIPTION

The net command is a Windows-like utility for managing Samba.

It supports the following commands:

ALIAS, FILE, GROUP, HELP, LOWERCASE, MESSAGE, PRINT, RGROUP, RUSER, RUNAS, SENDGRID, SERVER, SESSION, SHARE, STATISTICS, STOP, TDBCLOSE, TDBOPEN, TDBREOPEN, USE, USER, VIEW, WAITSTOP, WITNESS, serverid

Run net without any arguments to see a list of available commands. You can also run net help to get a list of commands, or net help COMMAND to get help on a specific command.

OPTIONS

The net command does not take any global options.

COMMANDS

WITNESS

Management of witness registrations

Note: Only supported with clustering=yes!

Machine readable output can be generated with the following option:

--json

The selection of registrations can be limited by the following options:

--witness-registration=REGISTRATION_UUID

This does a direct lookup for REGISTRATION_UUID instead of doing a database traversal.

The following options all take a POSIX Extended Regular Expression, which can further filter the selection of registrations. These options are applied as logical AND, but each REGEX allows specifying multiple strings using the pipe symbol.

--witness-net-name=REGEX

This specifies the 'server name' the client registered for monitoring.

--witness-share-name=REGEX

This specifies the 'share name' the client registered for monitoring. Note that the share name is optional in the registration, otherwise an empty string is matched.

--witness-ip-address=REGEX

This specifies the ip address the client registered for monitoring.

--witness-client-computer-name=REGEX

This specifies the client computer name the client specified in the registration. Note it is just a string chosen by the client itself.

If the update should be applied to all registrations it needs to be explicitly specified:

--witness-apply-to-all

This selects all registrations. Note: This is mutual exclusive to the above options.

Note: This only applies to registrations with a non empty share name!

The content of the SHARE_MOVE notification contains ip addresses specified by (exactly one) of the following options:

--witness-new-node=NODEID

By specifying a NODEID all ip addresses currently available on the given node are included in the response. By specifying '-1' as NODEID all ip addresses of the cluster are included in the response.

--witness-new-ip=IPADDRESS

By specifying an IPADDRESS only the specified ip address is included in the response.
