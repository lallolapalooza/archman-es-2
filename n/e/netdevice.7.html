netdevice(7) Manual de Información Miscelánea netdevice(7)

NOMBRE

netdevice - acceso de bajo nivel a dispositivos de red de Linux

SINOPSIS

#include <sys/ioctl.h>
#include <net/if.h>

DESCRIPCIÓN

Esta página del manual describe la interfaz de sockets que se utiliza para configurar dispositivos de red.

Linux admite algunos ioctls estándar para configurar dispositivos de red. Se pueden utilizar en el descriptor de archivo de cualquier socket, independientemente de su familia o tipo. La mayoría de ellos pasan una estructura ifreq:


struct ifreq {
    char ifr_name[IFNAMSIZ];  /* Nombre de la interfaz */
    union {
        struct sockaddr ifr_addr;
        struct sockaddr ifr_dstaddr;
        struct sockaddr ifr_broadaddr;
        struct sockaddr ifr_netmask;
        struct sockaddr ifr_hwaddr;
        short           ifr_flags;
        int             ifr_ifindex;
        int             ifr_metric;
        int             ifr_mtu;
        struct ifmap    ifr_map;
        char            ifr_slave[IFNAMSIZ];
        char            ifr_newname[IFNAMSIZ];
        char           *ifr_data;
    };
};

AF_INET6 es una excepción. Pasa una estructura in6_ifreq:


struct in6_ifreq {
    struct in6_addr     ifr6_addr;
    u32                 ifr6_prefixlen;
    int                 ifr6_ifindex;  /* Índice de la interfaz */
};

Normalmente, el usuario especifica qué dispositivo afectar estableciendo ifr_name con el nombre de la interfaz o ifr6_ifindex con el índice de la interfaz. Todos los demás miembros de la estructura pueden compartir memoria.

Ioctls

Si un ioctl está marcado como privilegiado, entonces usarlo requiere un ID de usuario efectivo de 0 o la capacidad CAP_NET_ADMIN. Si este no es el caso, se devolverá EPERM.

SIOCGIFNAME
Dado el ifr_ifindex, devuelve el nombre de la interfaz en ifr_name. Este es el único ioctl que devuelve su resultado en ifr_name.
SIOCGIFINDEX
Recupera el índice de la interfaz en ifr_ifindex.
SIOCGIFFLAGS
SIOCSIFFLAGS
Obtiene o establece la palabra de banderas activas del dispositivo. ifr_flags contiene una máscara de bits de los siguientes valores:
Banderas del dispositivo
IFF_UP La interfaz está activa.
IFF_BROADCAST Dirección de broadcast válida establecida.
IFF_DEBUG Bandera de depuración interna.
IFF_LOOPBACK La interfaz es una interfaz de loopback.
IFF_POINTOPOINT La interfaz es un enlace punto a punto.
IFF_RUNNING Recursos asignados.
IFF_NOARP Sin protocolo ARP, dirección de destino L2 no establecida.
IFF_PROMISC La interfaz está en modo promiscuo.
IFF_NOTRAILERS Evitar el uso de trailers.
IFF_ALLMULTI Recibir todos los paquetes multicast.
IFF_MASTER Maestro de un grupo de balanceo de carga.
IFF_SLAVE Esclavo de un grupo de balanceo de carga.
IFF_MULTICAST Soporta multicast.
IFF_PORTSEL Capaz de seleccionar el tipo de medio a través de ifmap.
IFF_AUTOMEDIA Selección automática de medios activa.
IFF_DYNAMIC Las direcciones se pierden cuando la interfaz se apaga.
IFF_LOWER_UP El controlador indica L1 activo (desde Linux 2.6.17)
IFF_DORMANT El controlador indica inactivo (desde Linux 2.6.17)
IFF_ECHO Eco de paquetes enviados (desde Linux 2.6.25)

Establecer la palabra de banderas activas es una operación privilegiada, pero cualquier proceso puede leerla.

SIOCGIFPFLAGS
SIOCSIFPFLAGS
Obtiene o establece banderas extendidas (privadas) para el dispositivo. ifr_flags contiene una máscara de bits de los siguientes valores:
Banderas privadas
IFF_802_1Q_VLAN La interfaz es un dispositivo VLAN 802.1Q.
IFF_EBRIDGE La interfaz es un dispositivo de puente Ethernet.
IFF_SLAVE_INACTIVE La interfaz es un esclavo de bonding inactivo.
IFF_MASTER_8023AD La interfaz es un maestro de bonding 802.3ad.
IFF_MASTER_ALB La interfaz es un maestro de bonding ALB.
IFF_BONDING La interfaz es un maestro o esclavo de bonding.
IFF_SLAVE_NEEDARP La interfaz necesita ARPs para validación.
IFF_ISATAP La interfaz es una interfaz ISATAP RFC4214.

Establecer las banderas de interfaz extendidas (privadas) es una operación privilegiada.

SIOCGIFADDR
SIOCSIFADDR
SIOCDIFADDR
Obtiene, establece o elimina la dirección del dispositivo utilizando ifr_addr, o ifr6_addr con ifr6_prefixlen. Establecer o eliminar la dirección de la interfaz es una operación privilegiada. Para compatibilidad, SIOCGIFADDR solo devuelve direcciones AF_INET, SIOCSIFADDR acepta direcciones AF_INET y AF_INET6, y SIOCDIFADDR elimina solo direcciones AF_INET6. Una dirección AF_INET puede ser eliminada estableciéndola a cero mediante SIOCSIFADDR.
SIOCGIFDSTADDR
SIOCSIFDSTADDR
Obtiene o establece la dirección de destino de un dispositivo punto a punto utilizando ifr_dstaddr. Para compatibilidad, solo se aceptan o devuelven direcciones AF_INET. Establecer la dirección de destino es una operación privilegiada.
SIOCGIFBRDADDR
SIOCSIFBRDADDR
Obtiene o establece la dirección de broadcast para un dispositivo utilizando ifr_brdaddr. Para compatibilidad, solo se aceptan o devuelven direcciones AF_INET. Establecer la dirección de broadcast es una operación privilegiada.
SIOCGIFNETMASK
SIOCSIFNETMASK
Obtiene o establece la máscara de red para un dispositivo utilizando ifr_netmask. Para compatibilidad, solo se aceptan o devuelven direcciones AF_INET. Establecer la máscara de red es una operación privilegiada.
SIOCGIFMETRIC
SIOCSIFMETRIC
Obtiene o establece la métrica del dispositivo utilizando ifr_metric. Actualmente no está implementado; establece ifr_metric a 0 si intentas leerlo y devuelve EOPNOTSUPP si intentas establecerlo.
SIOCGIFMTU

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

SIOCSIFMTU

Obtener o establecer la MTU (Unidad de Transferencia Máxima) de un dispositivo usando ifr_mtu. Establecer la MTU es una operación privilegiada. Establecer la MTU a valores demasiado pequeños puede causar bloqueos del kernel.
SIOCGIFHWADDR
SIOCSIFHWADDR
Obtener o establecer la dirección de hardware de un dispositivo usando ifr_hwaddr. La dirección de hardware se especifica en una struct sockaddr. sa_family contiene el tipo de dispositivo ARPHRD_*, sa_data la dirección de hardware L2 comenzando desde el byte 0. Establecer la dirección de hardware es una operación privilegiada.
SIOCSIFHWBROADCAST
Establecer la dirección de broadcast de hardware de un dispositivo desde ifr_hwaddr. Esta es una operación privilegiada.
SIOCGIFMAP
SIOCSIFMAP
Obtener o establecer los parámetros de hardware de la interfaz usando ifr_map. Establecer los parámetros es una operación privilegiada.

struct ifmap {
    unsigned long   mem_start;
    unsigned long   mem_end;
    unsigned short  base_addr;
    unsigned char   irq;
    unsigned char   dma;
    unsigned char   port;
};

La interpretación de la estructura ifmap depende del controlador del dispositivo y de la arquitectura.
SIOCADDMULTI
SIOCDELMULTI
Añadir una dirección o eliminar una dirección de los filtros multicast de la capa de enlace del dispositivo usando ifr_hwaddr. Estas son operaciones privilegiadas. Ver también packet(7) para una alternativa.
SIOCGIFTXQLEN
SIOCSIFTXQLEN
Obtener o establecer la longitud de la cola de transmisión de un dispositivo usando ifr_qlen. Establecer la longitud de la cola de transmisión es una operación privilegiada.
SIOCSIFNAME
Cambia el nombre de la interfaz especificada en ifr_name a ifr_newname. Esta es una operación privilegiada. Solo se permite cuando la interfaz no está activa.
SIOCGIFCONF
Devuelve una lista de direcciones de interfaz (capa de red). Actualmente esto significa solo direcciones de la familia AF_INET (IPv4) por compatibilidad. A diferencia de las otras, esta ioctl pasa una estructura ifconf:

struct ifconf {
    int               ifc_len; /* tamaño del buffer */
    union {
        char         *ifc_buf; /* dirección del buffer */
        struct ifreq *ifc_req; /* array de estructuras */
    };
};

Si ifc_req es NULL, SIOCGIFCONF devuelve el tamaño de buffer necesario en bytes para recibir todas las direcciones disponibles en ifc_len. De lo contrario, ifc_req contiene un puntero a un array de estructuras ifreq para ser llenado con todas las direcciones de interfaz L3 activas actualmente. ifc_len contiene el tamaño del array en bytes. Dentro de cada estructura ifreq, ifr_name recibirá el nombre de la interfaz, y ifr_addr la dirección. El número real de bytes transferidos se devuelve en ifc_len.
Si el tamaño especificado por ifc_len es insuficiente para almacenar todas las direcciones, el kernel omitirá las que excedan y devolverá éxito. No hay una forma fiable de detectar esta condición una vez que ha ocurrido. Por lo tanto, se recomienda determinar el tamaño de buffer necesario de antemano llamando a SIOCGIFCONF con ifc_req establecido a NULL, o reintentar la llamada con un buffer más grande cada vez que ifc_len al retornar difiera en menos de sizeof(struct ifreq) de su valor original.
Si ocurre un error al acceder a las estructuras ifconf o ifreq, se devolverá EFAULT.

La mayoría de los protocolos soportan sus propias ioctls para configurar opciones de interfaz específicas del protocolo. Ver las páginas man del protocolo para una descripción. Para configurar direcciones IP, ver ip(7).

Además, algunos dispositivos soportan ioctls privadas. Estas no se describen aquí.

NOTAS

SIOCGIFCONF y las otras ioctls que aceptan o devuelven solo direcciones de socket AF_INET son específicas de IP y quizás deberían documentarse mejor en ip(7).

Los nombres de las interfaces sin direcciones o que no tienen el flag IFF_RUNNING activado se pueden encontrar a través de /proc/net/dev.

Las direcciones IPv6 AF_INET6 se pueden leer de /proc/net/if_inet6 o a través de rtnetlink(7). Añadir una nueva dirección IPv6 y eliminar una dirección IPv6 existente se puede hacer a través de SIOCSIFADDR y SIOCDIFADDR o a través de rtnetlink(7). Obtener o cambiar direcciones IPv6 de destino de una interfaz punto a punto solo es posible a través de rtnetlink(7).

ERRORES

A glibc 2.1 le falta la macro ifr_newname en <net/if.h>. Añade lo siguiente a tu programa como solución alternativa:


#ifndef ifr_newname
#define ifr_newname     ifr_ifru.ifru_slave
#endif

VER TAMBIÉN

proc(5), capabilities(7), ip(7), rtnetlink(7)
