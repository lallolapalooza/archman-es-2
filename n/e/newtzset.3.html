NOMBRE

tzset - inicializa información de conversión horaria

SINOPSIS

#include <time.h>
timezone_t tzalloc(char const *TZ);
void tzfree(timezone_t tz);
void tzset(void);
/∗ Opcional y obsoleto:  ∗/
extern char *tzname[];
extern long timezone;
extern int daylight;
cc ... -ltz

DESCRIPCIÓN

La función tzalloc asigna y devuelve un objeto de zona horaria descrito por TZ.

Si TZ es un puntero nulo, tzalloc utiliza la mejor aproximación disponible a la hora local (reloj de pared), según lo especificado por el archivo en formato tzfile(5) localtime en el directorio de información de conversión horaria del sistema.

Si TZ es la cadena vacía, tzalloc utiliza la Hora Coordinada Universal (UTC), con la abreviatura "UTC" y sin corrección de segundos intercalares; consulte newctime(3) para más información sobre UT, UTC y segundos intercalares.

Si TZ no es nulo y no está vacío:

si el valor comienza con dos puntos, se utiliza como nombre de ruta de un archivo del que leer la información de conversión horaria;
si el valor no comienza con dos puntos, se utiliza primero como nombre de ruta de un archivo del que leer la información de conversión horaria y, si ese archivo no se puede leer, se utiliza directamente como una especificación de la información de conversión horaria.

Cuando el contenido de TZ se utiliza como nombre de ruta, un nombre de ruta que comience con “/” se utiliza tal cual; de lo contrario, el nombre de ruta es relativo a un directorio de información de conversión horaria del sistema. El archivo debe estar en el formato especificado en tzfile(5).

Cuando TZ se utiliza directamente como una especificación de la información de conversión horaria, debe tener la siguiente sintaxis:

stdoffset[dst[offset][,regla]]

Donde:

std y dst
Tres o más bytes que son la designación de la zona horaria estándar (std) o la alternativa (dst, como el horario de verano). Solo se requiere std; si falta dst, el horario de verano no se aplica en esta localidad. Se permiten explícitamente letras mayúsculas y minúsculas. Se permiten todos los caracteres excepto dos puntos iniciales (:), dígitos, coma (,), guion ASCII (-), signo más ASCII (+) y bytes NUL. Alternativamente, una designación puede estar rodeada por corchetes angulares < y >; en este caso, la designación puede contener cualquier carácter excepto > y NUL.
offset
Indica el valor que se debe sumar a la hora local para llegar a la Hora Coordinada Universal. El offset tiene el formato:
hh[:mm[:ss]]
Los minutos (mm) y segundos (ss) son opcionales. La hora (hh) es obligatoria y puede ser un solo dígito. El offset que sigue a std es obligatorio. Si no hay ningún offset que siga a dst, se asume que el horario de verano está una hora adelantado respecto a la hora estándar. Se pueden usar uno o más dígitos; el valor siempre se interpreta como un número decimal. La hora debe estar entre cero y 24, y los minutos (y segundos) – si están presentes – entre cero y 59. Si va precedido de un guion (“-”), la zona horaria estará al este del Meridiano de Greenwich; de lo contrario, estará al oeste (lo que puede indicarse con un signo “+” opcional precedente).
regla
Indica cuándo cambiar a y desde el horario de verano. La regla tiene el formato:
fecha/hora,fecha/hora
donde la primera fecha describe cuándo ocurre el cambio de horario estándar a horario de verano y la segunda fecha describe cuándo ocurre el cambio de regreso. Cada campo de hora describe cuándo, en la hora local actual, se realiza el cambio a la otra hora. Se asume que el horario de verano está vigente todo el año si comienza el 1 de enero a las 00:00 y termina el 31 de diciembre a las 24:00 más la diferencia entre el horario de verano y el estándar, sin dejar margen para el horario estándar en el calendario.
El formato de fecha es uno de los siguientes:
Jn
El día Juliano n (1 ≤ n ≤ 365). Los días bisiestos no se cuentan; es decir, en todos los años – incluidos los bisiestos – el 28 de febrero es el día 59 y el 1 de marzo es el día 60. Es imposible referirse explícitamente al ocasional 29 de febrero.
n
El día Juliano basado en cero (0 ≤ n ≤ 365). Se cuentan los días bisiestos y es posible referirse al 29 de febrero.
Mm.n.d
El d'ésimo día (0 ≤ d ≤ 6) de la semana n del mes m del año (1 ≤ n ≤ 5, 1 ≤ m ≤ 12, donde la semana 5 significa “el último día d del mes m” que puede ocurrir en la cuarta o quinta semana). La semana 1 es la primera semana en la que ocurre el d'ésimo día. El día cero es domingo.
El campo hora tiene el mismo formato que offset excepto que la parte de horas de hora puede variar de -167 a 167; esto permite reglas inusuales como “el sábado antes del primer domingo de marzo”. Por defecto, si no se proporciona hora, es 02:00:00.

Aquí hay algunos ejemplos de valores de TZ que especifican directamente la zona horaria.

EST5
representa la Hora Estándar del Este de EE. UU. (EST), 5 horas detrás de UT, sin horario de verano.
<+12>-12<+13>,M11.1.0,M1.2.1/147
representa la hora de Fiyi, 12 horas adelantada respecto a UT, adelantando el primer domingo de noviembre a las 02:00, y retrasando el segundo lunes de enero a las 147:00 (es decir, 03:00 del primer domingo o después del 14 de enero). Las abreviaturas para el horario estándar y de verano son “+12” y “+13”.
IST-2IDT,M3.4.4/26,M10.5.0
representa la Hora Estándar de Israel (IST) y el Horario de Verano de Israel (IDT), 2 horas adelantada respecto a UT, adelantando el cuarto jueves de marzo a las 26:00 (es decir, 02:00 del primer viernes o después del 23 de marzo) y retrasando el último domingo de octubre a las 02:00.
<-04>4<-03>,J1/0,J365/25
representa el horario de verano permanente, 3 horas detrás de UT con la abreviatura “-03”. Hay una transición simulada de regreso el 31 de diciembre a las 25:00 hora de verano (es decir, 24:00 hora estándar, equivalente al 1 de enero a las 00:00 hora estándar), y una transición simultánea de adelantamiento el 1 de enero a las 00:00 hora estándar, por lo que el horario de verano está vigente todo el año y el <-04> inicial es un marcador de posición.
<-03>3<-02>,M3.5.0/-2,M10.5.0/-1
representa la hora en Groenlandia occidental, 3 horas detrás de UT, donde los relojes siguen las reglas de la UE de adelantarse el último domingo de marzo a las 01:00 UT (-02:00 hora local, es decir, 22:00 del día anterior) y retrasarse el último domingo de octubre a las 01:00 UT (-01:00 hora local, es decir, 23:00 del día anterior). Las abreviaturas para el horario estándar y de verano son “-03” y “-02”.

NAME

tzalloc, tzfree, tzset ― timezone and time conversion functions

SYNOPSIS

#include <time.h>

#include <tz.h>

struct tz_info *
tzalloc(const char *tzname);
void
tzfree(struct tz_info *tz);
void
tzset(void);

DESCRIPTION

The tzalloc function allocates and initializes a timezone object based on the timezone specification string tzname. If tzname is NULL or an empty string, the system's default timezone is used. Otherwise, tzname is interpreted as a file path to a timezone file, or as a timezone specification string, as described in tzfile(5).

The timezone specification string format is described in tzfile(5). For compatibility, the following formats are supported:

  • If tzname starts with a '/', it is treated as a file path.
  • If tzname starts with a digit or a sign character, it is treated as a time conversion specification. This syntax is the same as that used by tzfile(5).
  • If tzname is not recognized as either of the above, it is treated as a timezone abbreviation, e.g. "EST". If the abbreviation is recognized, the system's default rules for that timezone abbreviation are used. This usage is deprecated and for backward compatibility only. It is recommended to use full timezone specifications or file paths.

A timezone specification string can contain a primary timezone abbreviation, followed by a list of daylight saving time rules. For example, "EST5EDT". The abbreviations are used to format output, and the rules are used to determine when to switch between standard and daylight saving time. The daylight saving time rules are specified in the format described in tzfile(5).

For backward compatibility, the specification of daylight saving time rules may be omitted. In this case, the default DST rules for the given timezone abbreviation are used. However, this is only for backward compatibility, and it does not work reliably. Therefore, if a TZ string directly specifies a timezone with daylight saving time, it should specify the daylight saving rules explicitly.

For compatibility with System V Release 3.1, a semicolon (;) may be used to separate the rule from the rest of the specification; this is an extension to POSIX.

The tzfree function frees a timezone object tz, which should have been successfully allocated by tzalloc. This invalidates any tm_zone pointers that tz was used to set.

The tzset function acts like tzalloc(getenv("TZ")), except it saves any resulting timezone object into internal storage that is accessed by localtime, localtime_r, and mktime. The anonymous shared timezone object is freed by the next call to tzset. If the implied call to getenv fails, tzset acts like tzalloc(nullptr); if the implied call to tzalloc fails, tzset falls back on UT.

As a side effect, the tzset function sets some external variables if the platform defines them. It sets tzname[0] and tzname[1] to pointers to strings that are time zone abbreviations to be used with standard and daylight saving time, respectively. It also sets timezone to be the number of seconds that standard time is west of the Prime Meridian, and daylight to be zero if daylight saving time is never in effect, non-zero otherwise.

RETURN VALUE

If successful, the tzalloc function returns a nonnull pointer to the newly allocated object. Otherwise, it returns a null pointer and sets errno.

ERRORS

EOVERFLOW
TZ directly specifies time conversion information, and contains an integer out of machine range or a time zone abbreviation that is too long for this platform.

The tzalloc function may also fail and set errno for any of the errors specified for the routines access(2), close(2), malloc(3), open(2), and read(2).

FILES

/etc/localtime local timezone file
/usr/share/zoneinfo timezone directory
/usr/share/zoneinfo/posixrules default DST rules (obsolete)
/usr/share/zoneinfo/GMT for UTC leap seconds

If /usr/share/zoneinfo/GMT is absent, UTC leap seconds are loaded from /usr/share/zoneinfo/GMT0 if present.

SEE ALSO

getenv(3), newctime(3), newstrftime(3), time(2), tzfile(5).

NOTES

Portable code should not rely on the contents of the external variables tzname, timezone and daylight as their contents are unspecified (and do not make sense in general) when a geographical TZ is used. In multithreaded applications behavior is undefined if one thread accesses one of these variables while another thread invokes tzset. A future version of POSIX is planned to remove these variables; callers can instead use the tm_gmtoff and tm_zone members of struct tm, or use strftime with "%z" or "%Z".
