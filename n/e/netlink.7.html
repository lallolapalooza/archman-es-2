NOMBRE

netlink - comunicación entre el kernel y el espacio de usuario (AF_NETLINK)

SINOPSIS

#include <asm/types.h>
#include <sys/socket.h>
#include <linux/netlink.h>
netlink_socket = socket(AF_NETLINK, tipo_socket, familia_netlink);

DESCRIPCIÓN

Netlink se utiliza para transferir información entre el kernel y los procesos del espacio de usuario. Consiste en una interfaz estándar basada en sockets para los procesos del espacio de usuario y una API interna del kernel para los módulos del kernel. La interfaz interna del kernel no está documentada en esta página del manual. También existe una interfaz netlink obsoleta a través de dispositivos de caracteres netlink; esta interfaz no está documentada aquí y se proporciona solo por compatibilidad con versiones anteriores.

Netlink es un servicio orientado a datagramas. Tanto SOCK_RAW como SOCK_DGRAM son valores válidos para tipo_socket. Sin embargo, el protocolo netlink no distingue entre sockets de datagramas y sockets crudos.

familia_netlink selecciona el módulo del kernel o el grupo netlink con el que comunicarse. Las familias netlink asignadas actualmente son:

NETLINK_ROUTE
Recibe actualizaciones de enrutamiento y enlaces, y puede usarse para modificar las tablas de enrutamiento (tanto IPv4 como IPv6), direcciones IP, parámetros de enlace, configuraciones de vecinos, disciplinas de cola, clases de tráfico y clasificadores de paquetes (consulte rtnetlink(7)).
NETLINK_W1 (Linux 2.6.13 a Linux 2.16.17)
Mensajes del subsistema 1-wire.
NETLINK_USERSOCK
Reservado para protocolos de sockets en modo de usuario.
NETLINK_FIREWALL (hasta e incluyendo Linux 3.4)
Transporta paquetes IPv4 de netfilter al espacio de usuario. Utilizado por el módulo del kernel ip_queue. Después de un largo período de ser declarado obsoleto (a favor de la característica más avanzada nfnetlink_queue), NETLINK_FIREWALL fue eliminado en Linux 3.5.
NETLINK_SOCK_DIAG (desde Linux 3.3)
Consulta información sobre sockets de varias familias de protocolos desde el kernel (consulte sock_diag(7)).
NETLINK_INET_DIAG (desde Linux 2.6.14)
Un sinónimo obsoleto de NETLINK_SOCK_DIAG.
NETLINK_NFLOG (hasta e incluyendo Linux 3.16)
Netfilter/iptables ULOG.
NETLINK_XFRM
IPsec.
NETLINK_SELINUX (desde Linux 2.6.4)
Notificaciones de eventos SELinux.
NETLINK_ISCSI (desde Linux 2.6.15)
Open-iSCSI.
NETLINK_AUDIT (desde Linux 2.6.6)
Auditoría.
NETLINK_FIB_LOOKUP (desde Linux 2.6.13)
Acceso a la búsqueda FIB desde el espacio de usuario.
NETLINK_CONNECTOR (desde Linux 2.6.14)
Conector del kernel. Consulte Documentation/driver-api/connector.rst (o /Documentation/connector/connector.* en Linux 5.2 y anteriores) en el árbol de fuentes del kernel de Linux para obtener más información.
NETLINK_NETFILTER (desde Linux 2.6.14)
Subsistema Netfilter.
NETLINK_SCSITRANSPORT (desde Linux 2.6.19)
Transportes SCSI.
NETLINK_RDMA (desde Linux 3.0)
Infiniband RDMA.
NETLINK_IP6_FW (hasta e incluyendo Linux 3.4)
Transporta paquetes IPv6 de netfilter al espacio de usuario. Utilizado por el módulo del kernel ip6_queue.
NETLINK_DNRTMSG
Mensajes de enrutamiento DECnet.
NETLINK_KOBJECT_UEVENT (desde Linux 2.6.10)
Mensajes del kernel al espacio de usuario.
NETLINK_GENERIC (desde Linux 2.6.15)
Familia genérica netlink para un uso simplificado de netlink.
NETLINK_CRYPTO (desde Linux 3.2)
Interfaz Netlink para solicitar información sobre cifrados registrados en la API de cifrado del kernel, así como para permitir la configuración de la API de cifrado del kernel.

Los mensajes Netlink consisten en un flujo de bytes con uno o múltiples encabezados nlmsghdr y su carga útil asociada. El flujo de bytes solo debe accederse con las macros estándar NLMSG_*. Consulte netlink(3) para obtener más información.

En mensajes multipartes (múltiples encabezados nlmsghdr con carga útil asociada en un solo flujo de bytes), el primer encabezado y todos los siguientes tienen el flag NLM_F_MULTI establecido, excepto el último encabezado que tiene el tipo NLMSG_DONE.

Después de cada nlmsghdr sigue la carga útil.


struct nlmsghdr {
    __u32 nlmsg_len;    /* Tamaño del mensaje incluyendo el encabezado */
    __u16 nlmsg_type;   /* Tipo del contenido del mensaje */
    __u16 nlmsg_flags;  /* Flags adicionales */
    __u32 nlmsg_seq;    /* Número de secuencia */
    __u32 nlmsg_pid;    /* ID del puerto del remitente */
};

nlmsg_type puede ser uno de los tipos de mensaje estándar: el mensaje NLMSG_NOOP debe ser ignorado, el mensaje NLMSG_ERROR señala un error y la carga útil contiene una estructura nlmsgerr, el mensaje NLMSG_DONE termina un mensaje multipartido. Los mensajes de error reciben la solicitud original adjunta, a menos que el usuario solicite recortar el mensaje de error, y reciben datos de error adicionales si se solicitan.


struct nlmsgerr {
    int error;        /* errno negativo o 0 para acuses de recibo */
    struct nlmsghdr msg;  /* Encabezado del mensaje que causó el error */
    /*
     * seguido por el contenido del mensaje
     * a menos que se establezca NETLINK_CAP_ACK
     * o el ACK indique éxito (error == 0).
     * Por ejemplo, mensaje Generic Netlink con atributos.
     * El tamaño del mensaje está alineado con NLMSG_ALIGN()
     */
    /*
     * seguido por TLVs definidos en enum nlmsgerr_attrs
     * si se establece NETLINK_EXT_ACK
     */
};

Una familia netlink generalmente especifica más tipos de mensaje, consulte las páginas del manual apropiadas para ello, por ejemplo, rtnetlink(7) para NETLINK_ROUTE.

Bits de flags estándar en nlmsg_flags
NLM_F_REQUEST Debe establecerse en todos los mensajes de solicitud.
NLM_F_MULTI El mensaje es parte de un mensaje multipartido terminado por NLMSG_DONE.
NLM_F_ACK Solicitud de acuse de recibo en caso de éxito.
NLM_F_ECHO Repetir esta solicitud.
Bits de flags adicionales para solicitudes GET
NLM_F_ROOT Devolver la tabla completa en lugar de una sola entrada.
NLM_F_MATCH Devolver todas las entradas que coincidan con los criterios pasados en el contenido del mensaje. Aún no implementado.
NLM_F_ATOMIC Devolver una instantánea atómica de la tabla.
NLM_F_DUMP Macro de conveniencia; equivalente a (NLM_F_ROOT|NLM_F_MATCH).

Tenga en cuenta que NLM_F_ATOMIC requiere el permiso CAP_NET_ADMIN o un UID efectivo de 0.
