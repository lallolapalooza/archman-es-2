nftw(3) Library Functions Manual nftw(3)

NOMBRE

nftw, ftw - recorrer árboles de directorios

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <ftw.h>
int nftw(const char *dirpath,
        typeof(int (const char *fpath, const struct stat *sb,
                    int typeflag, struct FTW *ftwbuf))
            *fn,
        int nopenfd, int flags);
[[deprecated]]
int ftw(const char *dirpath,
        typeof(int (const char *fpath, const struct stat *sb,
                    int typeflag))
            *fn,
        int nopenfd);
Requisitos de macro de prueba de características para glibc (ver feature_test_macros(7)):

nftw():

    _XOPEN_SOURCE >= 500

DESCRIPCIÓN

nftw() recorre el árbol de directorios ubicado bajo el directorio dirpath y llama a fn() una vez por cada entrada en el árbol. Por defecto, los directorios se manejan antes que los archivos y subdirectorios que contienen (recorrido preorder).

Para evitar agotar todos los descriptores de archivo del proceso llamador, nopenfd especifica el número máximo de directorios que nftw() mantendrá abiertos simultáneamente. Cuando la profundidad de búsqueda excede este valor, nftw() se volverá más lento porque los directorios tendrán que cerrarse y reabrirse. nftw() utiliza como máximo un descriptor de archivo por cada nivel en el árbol de directorios.

Para cada entrada encontrada en el árbol, nftw() llama a fn() con cuatro argumentos: fpath, sb, typeflag y ftwbuf. fpath es la ruta del nombre de la entrada, y se expresa ya sea como una ruta relativa al directorio de trabajo actual del proceso llamador en el momento de la llamada a nftw(), si dirpath se expresó como una ruta relativa, o como una ruta absoluta, si dirpath se expresó como una ruta absoluta. sb es un puntero a la estructura stat devuelta por una llamada a stat(2) para fpath.

El argumento typeflag pasado a fn() es un entero que tiene uno de los siguientes valores:

FTW_F
fpath es un archivo regular.
FTW_D
fpath es un directorio.
FTW_DNR
fpath es un directorio que no se puede leer.
FTW_DP
fpath es un directorio, y se especificó FTW_DEPTH en flags. (Si no se especificó FTW_DEPTH en flags, entonces los directorios siempre se visitarán con typeflag establecido en FTW_D). Todos los archivos y subdirectorios dentro de fpath han sido procesados.
FTW_NS
La llamada stat(2) falló en fpath, que no es un enlace simbólico. La causa probable es que el llamador tenía permiso de lectura sobre el directorio padre, por lo que el nombre de archivo fpath podía ser visto, pero no tenía permiso de ejecución, por lo que el archivo no podía ser alcanzado para stat(2). El contenido del búfer apuntado por sb no está definido.
FTW_SL
fpath es un enlace simbólico, y se estableció FTW_PHYS en flags.
FTW_SLN
fpath es un enlace simbólico que apunta a un archivo inexistente. (Esto solo ocurre si FTW_PHYS no está establecido). En este caso, el argumento sb pasado a fn() contiene información devuelta al realizar lstat(2) sobre el enlace simbólico "colgante". (Pero ver BUGS).

El cuarto argumento (ftwbuf) que nftw() proporciona al llamar a fn() es un puntero a una estructura de tipo FTW:


struct FTW {
    int base;
    int level;
};

base es el desplazamiento del nombre de archivo (es decir, el componente basename) en la ruta dada en fpath. level es la profundidad de fpath en el árbol de directorios, relativa a la raíz del árbol (dirpath, que tiene profundidad 0).

Para detener el recorrido del árbol, fn() devuelve un valor distinto de cero; este valor se convertirá en el valor de retorno de nftw(). Mientras fn() devuelva 0, nftw() continuará ya sea hasta que haya recorrido todo el árbol, en cuyo caso devolverá cero, o hasta que encuentre un error (como un fallo de malloc(3)), en cuyo caso devolverá -1.

Dado que nftw() utiliza estructuras de datos dinámicas, la única forma segura de salir de un recorrido de árbol es devolver un valor distinto de cero desde fn(). Para permitir que una señal termine el recorrido sin causar una fuga de memoria, haga que el manejador establezca una bandera global que fn() compruebe. No utilice longjmp(3) a menos que el programa vaya a terminar.

El argumento flags de nftw() se forma mediante la operación OR de cero o más de las siguientes banderas:

FTW_ACTIONRETVAL (desde glibc 2.3.3)
Si esta bandera específica de glibc está establecida, entonces nftw() maneja el valor de retorno de fn() de manera diferente. fn() debería devolver uno de los siguientes valores:
FTW_CONTINUE
Indica a nftw() que continúe normalmente.
FTW_SKIP_SIBLINGS
Si fn() devuelve este valor, se omitirán los hermanos de la entrada actual y el procesamiento continuará en el padre.
FTW_SKIP_SUBTREE
Si se llama a fn() con una entrada que es un directorio (typeflag es FTW_D), este valor de retorno evitará que los objetos dentro de ese directorio se pasen como argumentos a fn(). nftw() continúa procesando con el siguiente hermano del directorio.
FTW_STOP
Hace que nftw() devuelva inmediatamente el valor de retorno FTW_STOP.

Otros valores de retorno podrían asociarse con nuevas acciones en el futuro; fn() no debería devolver valores que no sean los listados anteriormente.

La macro de prueba de características _GNU_SOURCE debe estar definida (antes de incluir cualquier archivo de cabecera) para obtener la definición de FTW_ACTIONRETVAL desde <ftw.h>.

FTW_CHDIR
Si está establecido, realiza un chdir(2) a cada directorio antes de manejar su contenido. Esto es útil si el programa necesita realizar alguna acción en el directorio en el que reside fpath. (Especificar esta bandera no tiene efecto en la ruta del nombre que se pasa en el argumento fpath de fn).
FTW_DEPTH
Si está establecido, realiza un recorrido postorden, es decir, llama a fn() para el propio directorio *después* de manejar el contenido del directorio y sus subdirectorios. (Por defecto, cada directorio se maneja *antes* de su contenido).
FTW_MOUNT
Si está establecido, permanece dentro del mismo sistema de archivos (es decir, no cruza puntos de montaje).
FTW_PHYS
Si está establecido, no sigue enlaces simbólicos. (Esto es lo que quieres). Si no está establecido, se siguen los enlaces simbólicos, pero ningún archivo se informa dos veces.
Si FTW_PHYS no está establecido, pero FTW_DEPTH sí lo está, entonces la función fn() nunca se llama para un directorio que sería un descendiente de sí mismo.

ftw()

ftw() es una función más antigua que ofrece un subconjunto de la funcionalidad de nftw(). Las diferencias notables son las siguientes:

•

DESCRIPCIÓN

ftw()
La función ftw() recorre recursivamente un árbol de directorios comenzando en el directorio especificado por dirpath. Para cada archivo del árbol, llama a la función proporcionada por el puntero fn. La función fn recibe tres argumentos: el nombre de ruta completo de un archivo (fpath), un puntero a una estructura stat (sb) que contiene información sobre el archivo, y un entero (typeflag) que indica el tipo del archivo. La función fn también recibe un cuarto argumento, un puntero a una estructura FTW (ftwbuf).
nftw()
La función nftw() es una interfaz mejorada que ftw(). La principal diferencia es que nftw() toma un argumento adicional, flags, que permite modificar su comportamiento. El argumento flags es una máscara de bits que puede incluir las siguientes constantes:
FTW_ACTIONRETVAL
Permite que fn devuelva FTW_STOP para detener el recorrido. Si este flag no se establece, cualquier valor distinto de cero devuelto por fn detendrá el recorrido y será devuelto por nftw().
FTW_CHDIR
Cambia al directorio especificado por dirpath antes de comenzar el recorrido. Esto permite a fn asumir que el directorio actual es el directorio que se está recorriendo, reduciendo la longitud de las cadenas de nombres de ruta pasadas a fn.
FTW_DEPTH
Recorre un subárbol antes de visitar el propio directorio. Esto significa que fn se llamará primero para los directorios hijos antes de llamarse para el directorio padre. Si se usa FTW_DEPTH, el valor de typeflag será FTW_DP para un directorio visitado después de sus hijos.
FTW_MOUNT
No cruza los límites del sistema de archivos. Si nftw() se encuentra con un enlace simbólico a un directorio en un sistema de archivos diferente, no recorrerá ese directorio.
FTW_PHYS
No sigue los enlaces simbólicos. Por defecto, nftw() sigue los enlaces simbólicos. Si se utiliza FTW_PHYS, los enlaces simbólicos se tratarán como archivos regulares o, si no apuntan a un archivo existente, se les pasará FTW_SLN.

Los siguientes flags solo pueden ser establecidos por ftw() y siempre se pasan a fn():

FTW_SL
El archivo es un enlace simbólico. Nota: El comportamiento exacto de ftw() con FTW_SL varía entre implementaciones. Para un comportamiento predecible, se recomienda usar nftw().
FTW_SLN
El archivo es un enlace simbólico que apunta a un archivo que no existe.
FTW_DP
El directorio se ha visitado después de sus hijos (solo si se usa FTW_DEPTH).

Los siguientes valores se pasan en el argumento typeflag cuando no se especifica ningún flag o cuando los flags especificados no modifican el comportamiento predeterminado:

FTW_F
El archivo es un archivo regular.
FTW_D
El archivo es un directorio.
FTW_DNR
El archivo es un directorio que no se puede leer (el permiso de lectura no está permitido).
FTW_NS
La información sobre el archivo no se pudo obtener, por lo que es imposible determinar su tipo. Esto puede ocurrir si el archivo es un archivo inexistente o si se ha producido un error al intentar obtener su información (por ejemplo, debido a permisos insuficientes).

La función fn se llama con los siguientes argumentos:

fpath
Un puntero a una cadena de caracteres que termina en nulo, que contiene el nombre de ruta del archivo.
sb
Un puntero a una estructura stat que contiene información sobre el archivo. Si typeflag es FTW_NS o FTW_SLN, el contenido de esta estructura no está definido o puede ser el resultado de una llamada a lstat(2), respectivamente.
typeflag
Un entero que indica el tipo de archivo, según se describe anteriormente. También puede indicar el nivel actual en el árbol de directorios, empezando por 0 en el directorio raíz del recorrido.
ftwbuf
Un puntero a una estructura FTW que contiene información adicional sobre el recorrido. Contiene los siguientes campos:
base
El desplazamiento del nombre del archivo dentro de fpath.
level
El nivel de profundidad del archivo actual en el árbol de directorios, empezando por 0 en el directorio raíz.

La función ftw() es una versión obsoleta de nftw(). Las siguientes diferencias se aplican cuando se compara ftw() con nftw() sin ningún flag especificado:

ftw()
no tiene argumento flags. Se comporta igual que cuando se llama a nftw() con flags especificado como cero.
•
La función de devolución de llamada, fn(), no recibe un cuarto argumento.
•
El rango de valores que se pasa a través del argumento typeflag suministrado a fn() es menor: solo FTW_F, FTW_D, FTW_DNR, FTW_NS y (posiblemente) FTW_SL.

VALOR DE RETORNO

Estas funciones devuelven 0 si la operación es exitosa y -1 si ocurre un error.

Si fn() devuelve un valor distinto de cero, entonces el recorrido del árbol se termina y el valor devuelto por fn() se devuelve como resultado de ftw() o nftw().

Si nftw() se llama con el flag FTW_ACTIONRETVAL, entonces el único valor distinto de cero que fn() debe usar para terminar el recorrido del árbol es FTW_STOP, y ese valor se devuelve como resultado de nftw().

ATRIBUTOS

Para obtener una explicación de los términos utilizados en esta sección, consulta attributes(7).

Interfaz Atributo Valor

ftw () Seguridad en hilos MT-Safe

VERSIONES

En algunas implementaciones (por ejemplo, glibc), ftw() nunca usará FTW_SL; en otros sistemas FTW_SL ocurre solo para enlaces simbólicos que no apuntan a un archivo existente; y de nuevo en otros sistemas ftw() usará FTW_SL para cada enlace simbólico. Si fpath es un enlace simbólico y stat(2) falló, POSIX.1-2008 establece que es indefinido si se pasa FTW_NS o FTW_SL en typeflag. Para obtener resultados predecibles, usa nftw().

ESTANDARES

POSIX.1-2008.

HISTORIA

ftw()
POSIX.1-2001, SVr4, SUSv1. POSIX.1-2008 lo marca como obsoleto.
nftw()
glibc 2.1. POSIX.1-2001, SUSv1.
FTW_SL
POSIX.1-2001, SUSv1.

NOTAS

POSIX.1-2008 señala que los resultados no están especificados si fn no preserva el directorio de trabajo actual.

ERRORES

Según POSIX.1-2008, cuando el argumento typeflag pasado a fn() contiene FTW_SLN, el buffer apuntado por sb debe contener información sobre el enlace simbólico colgante (obtenido llamando a lstat(2) sobre el enlace). Las primeras versiones de glibc seguían correctamente la especificación POSIX en este punto. Sin embargo, como resultado de una regresión introducida en glibc 2.4, el contenido del buffer apuntado por sb no estaba definido cuando se pasa FTW_SLN en typeflag. (Más precisamente, el contenido del buffer se dejaba sin cambios en este caso). Esta regresión finalmente se corrigió en glibc 2.30, de modo que la implementación de glibc (una vez más) sigue la especificación POSIX.

EJEMPLOS

El siguiente programa recorre el árbol de directorios bajo la ruta mencionada en su primer argumento de línea de comandos, o bajo el directorio actual si no se proporciona ningún argumento. Muestra diversa información sobre cada archivo. El segundo argumento de línea de comandos se puede utilizar para especificar caracteres que controlan el valor asignado al argumento flags al llamar a nftw().

Código fuente del programa

#define _XOPEN_SOURCE 500
#include <ftw.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
static int
display_info(const char *fpath, const struct stat *sb,
             int tflag, struct FTW *ftwbuf)
{
    printf("%-3s %2d ",
           (tflag == FTW_D) ?   "d"   : (tflag == FTW_DNR) ? "dnr" :
           (tflag == FTW_DP) ?  "dp"  : (tflag == FTW_F) ?   "f" :
           (tflag == FTW_NS) ?  "ns"  : (tflag == FTW_SL) ?  "sl" :
           (tflag == FTW_SLN) ? "sln" : "???",
           ftwbuf->level);
    if (tflag == FTW_NS)
        printf("-------");
    else
        printf("%7jd", (intmax_t) sb->st_size);
    printf("   %-40s %d %s\n",
           fpath, ftwbuf->base, fpath + ftwbuf->base);
    return 0;           /* Para decirle a nftw() que continúe */
}
int
main(int argc, char *argv[])
{
    int flags = 0;
    if (argc > 2 && strchr(argv[2], 'd') != NULL)
        flags |= FTW_DEPTH;
    if (argc > 2 && strchr(argv[2], 'p') != NULL)
        flags |= FTW_PHYS;
    if (nftw((argc < 2) ? "." : argv[1], display_info, 20, flags)
        == -1)
    {
        perror("nftw");
        exit(EXIT_FAILURE);
    }
    exit(EXIT_SUCCESS);
}
