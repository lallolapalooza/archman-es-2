NOMBRE

nfc-emulate-uid - Herramienta de línea de comandos para emulación de objetivos NFC basada en libnfc

SINOPSIS

nfc-emulate-uid [OPCIONES] [UID]

DESCRIPCIÓN

nfc-emulate-uid es una herramienta de emulación de tarjetas que permite elegir cualquier UID de tarjeta. La emulación de tarjetas es una de las principales características añadidas en NFC. Pero para evitar el abuso de los sistemas existentes, los fabricantes del controlador NFC intencionadamente no soportaron la emulación de UIDs completamente personalizados, sino solo UIDs "aleatorios", que siempre comienzan con 0x08. La herramienta nfc-emulate-uid demuestra que esto aún se puede hacer mediante la transmisión de tramas en bruto, y el UID deseado se puede especificar opcionalmente.

Esto la convierte en una amenaza seria para los sistemas de seguridad que dependen únicamente de la unicidad del UID.

Desafortunadamente, este ejemplo no puede iniciarse directamente en modo de objetivo totalmente personalizable. Justo después de lanzar este ejemplo, tendrá que pasar por la secuencia inicial de anticoleisión codificada con el UID con prefijo 0x08. Para lograrlo, puede, por ejemplo, enviar un comando RATS (Request for Answer To Select) utilizando un segundo dispositivo NFC (colocado en el campo del objetivo) y ejecutando nfc-list o nfc-anticol. Después de este primer paso, ahora tiene un dispositivo NFC (configurado como objetivo) que realmente emula un UID personalizado. Podría verlo utilizando el segundo dispositivo NFC con nfc-list.

El control del tiempo es muy importante para una secuencia de anticoleisión exitosa:

- El emulador debe ser muy rápido en reaccionar: el uso del dispositivo ACR122 genera muchos problemas de tiempo, los dispositivos USB "solo PN53x" también generan algunos problemas de tiempo, pero un microcontrolador embebido probablemente mejoraría enormemente la situación.

- El lector no debería ser demasiado estricto con el tiempo (el estándar es muy estricto). Se sabe que el OmniKey CardMan 5321 es muy flexible con los tiempos y es una buena opción si desea experimentar con este emulador con un lector tolerante. Los lectores Nokia NFC 6212 y Pegoda son demasiado estrictos y no se dejarán engañar.

OPCIONES

UID formato de 8 dígitos hexadecimales que representa el UID deseado (el valor predeterminado es DEADBEEF).

IMPORTANTE

Los dispositivos ACR122 (como touchatag, etc.) pueden ser utilizados por este ejemplo (con problemas de tiempo), pero si algo sale mal, tendrá que desconectar/reconectar su dispositivo. Esto no es un error de libnfc, este problema se debe al MCU interno del ACR122 delante del chip NFC (PN532).
