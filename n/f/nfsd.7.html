nfsd(7) Manual de Información Miscelánea nfsd(7)

NOMBRE

nfsd - sistema de archivos especial para controlar el servidor NFS de Linux

SINOPSIS

mount -t nfsd nfsd /proc/fs/nfsd

DESCRIPCIÓN

El sistema de archivos nfsd es un sistema de archivos especial que proporciona acceso al servidor NFS de Linux. Escribir en los archivos de este sistema de archivos puede afectar al servidor. Leer de ellos puede proporcionar información sobre el servidor.

Además de este sistema de archivos, hay una colección de archivos en el sistema de archivos procfs (normalmente montado en /proc) que se utilizan para controlar el servidor NFS. Esta página del manual describe todos estos archivos.

Los programas exportfs y mountd (parte del paquete nfs-utils) esperan encontrar este sistema de archivos montado en /proc/fs/nfsd o /proc/fs/nfs.

DETALLES

Los archivos en el sistema de archivos nfsd incluyen:

exports
Este archivo contiene una lista de sistemas de archivos que están actualmente exportados y los clientes a los que se exporta cada sistema de archivos, junto con una lista de opciones de exportación para esa combinación cliente/sistema de archivos. Esto es similar al archivo /proc/fs/nfs/exports en 2.4. Una diferencia es que un cliente no necesariamente corresponde a un solo host. Puede responder a una gran colección de hosts que se tratan de manera idéntica.

Cada línea del archivo contiene un nombre de ruta, un nombre de cliente y un número de opciones entre paréntesis. Cualquier espacio, tabulación, nueva línea o carácter de barra invertida en el nombre de ruta o el nombre del cliente será reemplazado por una barra invertida seguida del código ASCII octal para ese carácter.

threads
Este archivo representa el número de hilos nfsd que se ejecutan actualmente. Leerlo mostrará el número de hilos. Escribir un número decimal ASCII hará que el número de hilos se cambie (aumente o disminuya según sea necesario) para alcanzar ese número.
filehandle
Este es un archivo algo inusual en el sentido de que lo que se lee de él depende de lo que se escribió en él. Proporciona una interfaz transaccional donde un programa puede abrir el archivo, escribir una solicitud y leer una respuesta. Si dos programas separados abren, escriben y leen al mismo tiempo, sus solicitudes no se mezclarán.

La solicitud escrita en filehandle debe ser un nombre de cliente, un nombre de ruta y un número de bytes. Esto debe ir seguido de una nueva línea, con espacios en blanco separando los campos y la cita octal de caracteres especiales.

Al escribir esto, el programa podrá leer un filehandle para esa ruta tal como se exportó al cliente dado. La longitud del filehandle será como máximo el número de bytes proporcionado.

El filehandle se representará en hexadecimal con un prefijo '\x'.

clients/
Este directorio contiene un subdirectorio para cada cliente NFSv4. Cada archivo debajo de ese subdirectorio proporciona algunos detalles sobre el cliente en formato YAML. Además, escribir "expire\n" en el archivo ctl obligará al servidor a revocar inmediatamente todo el estado que posee ese cliente.

El directorio /proc/net/rpc en el sistema de archivos procfs contiene una serie de archivos y directorios. Los archivos contienen estadísticas que pueden ser mostradas por el programa nfsstat. Los directorios contienen información sobre varias cachés que el servidor NFS mantiene para registrar los permisos de acceso que diferentes clientes tienen para diferentes sistemas de archivos. Las cachés son:

auth.unix.ip
Esta caché contiene un mapeo de dirección IP al nombre del dominio de autenticación del cual la dirección IP debe ser tratada como parte.
nfsd.export
Esta caché contiene un mapeo de directorio y dominio a opciones de exportación.
nfsd.fh
Esta caché contiene un mapeo de dominio y un identificador de sistema de archivos a un directorio. El identificador de sistema de archivos se almacena en los filehandles y consiste en un número que indica el tipo de identificador y un número de bytes hexadecimales que indican el contenido del identificador.

Cada directorio que representa una caché puede contener de 1 a 3 archivos. Son:

flush
Cuando se escribe un número de segundos desde la época (1 de enero de 1970) en este archivo, todas las entradas de la caché que se actualizaron por última vez antes de ese archivo se invalidan y se eliminan. Escribir una hora futura (en segundos desde la época) eliminará todo. Este es el único archivo que siempre estará presente.
content
Este archivo, si está presente, contiene una representación textual de cada entrada en la caché, una por línea. Si una entrada todavía está en la caché (porque se está utilizando activamente) pero ha expirado o no es válida de otra manera, se presentará como un comentario (con un carácter de hash al principio).
channel
Este archivo, si está presente, actúa como un canal para las solicitudes del servidor nfs basado en el kernel a un programa de espacio de usuario para su manejo.

Cuando el kernel necesita alguna información que no está en la caché, hace que aparezca una línea en el archivo channel que proporciona la clave para la información. Un programa de espacio de usuario debe leer esto, encontrar la respuesta y escribir una línea que contenga la clave, un tiempo de expiración y el contenido. Por ejemplo, el kernel podría hacer que nfsd 127.0.0.1
aparezca en el archivo auth.unix.ip/content. El programa de espacio de usuario podría entonces escribir nfsd 127.0.0.1 1057206953 localhost
para indicar que 127.0.0.1 debe mapearse a localhost, al menos por ahora.

Si el programa utiliza select(2) o poll(2) para descubrir si puede leer desde el channel, nunca verá un fin de archivo, pero cuando se hayan respondido todas las solicitudes, se bloqueará hasta que aparezca otra solicitud.

En el sistema de archivos /proc hay 4 archivos que se pueden utilizar para habilitar el rastreo adicional de nfsd y código relacionado. Son:
/proc/sys/sunrpc/nfs_debug
/proc/sys/sunrpc/nfsd_debug
/proc/sys/sunrpc/nlm_debug
/proc/sys/sunrpc/rpc_debug

Controlan el rastreo para el cliente NFS, el servidor NFS, el Network Lock Manager (lockd) y la capa RPC subyacente respectivamente. Se pueden leer o escribir números decimales en estos archivos. Cada número representa un patrón de bits donde los bits establecidos hacen que se habiliten ciertas clases de rastreo. Consulte los archivos de cabecera del kernel para averiguar qué número corresponde a qué rastreo.

NOTAS

Este sistema de archivos solo está disponible en los kernels de la serie Linux 2.6 y posteriores (y en las últimas partes de la serie de desarrollo 2.5 que conducen a 2.6). Esta página del manual no se aplica a 2.4 y anteriores.

Anteriormente, la llamada al sistema nfsctl se utilizaba para la comunicación entre nfsd y las utilidades de usuario. Esa llamada al sistema se eliminó en la versión del kernel 3.1. Las versiones anteriores de nfs-utils podían recurrir a nfsctl si era necesario; eso se eliminó de nfs-utils 1.3.5.
