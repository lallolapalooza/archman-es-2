NOMBRE

rpc.nfsd - proceso del servidor NFS

SINOPSIS

/usr/sbin/rpc.nfsd [opciones] nproc

DESCRIPCIÓN

El programa rpc.nfsd implementa la parte de espacio de usuario del servicio NFS. La funcionalidad principal es manejada por el módulo del kernel nfsd. El programa de espacio de usuario simplemente especifica en qué tipo de sockets debe escuchar el servicio del kernel, qué versiones de NFS debe soportar y cuántos hilos del kernel debe utilizar.

El servidor rpc.mountd proporciona un servicio auxiliar necesario para satisfacer las solicitudes de montaje de los clientes NFS.

OPCIONES

-d o --debug
Habilita el registro de mensajes de depuración.
-H o --host nombrehost
Especifica un nombre de host (o dirección) en particular en el que se aceptarán las solicitudes NFS. Por defecto, rpc.nfsd aceptará solicitudes NFS en todas las direcciones de red conocidas. Tenga en cuenta que lockd (que realiza servicios de bloqueo de archivos para NFS) aún puede aceptar solicitudes en todas las direcciones de red conocidas. Esto puede cambiar en futuras versiones del Kernel de Linux. Esta opción puede usarse varias veces para escuchar en más de una interfaz.
-S o --scope ambito
NFSv4.1 y posteriores requieren que el servidor informe un "ámbito" que los clientes utilizan para detectar si dos conexiones son al mismo servidor. Por defecto, NFSD de Linux utiliza el nombre del host como ámbito.

Es particularmente importante para configuraciones de alta disponibilidad asegurarse de que todos los nodos del servidor potenciales informen el mismo ámbito de servidor.

-p o --port puerto
Especifica un puerto diferente para escuchar las solicitudes NFS. Por defecto, rpc.nfsd escuchará en el puerto 2049.
-r o --rdma
Especifica que se deben atender las solicitudes NFS en el puerto RDMA estándar ("nfsrdma", puerto 20049).
--rdma=puerto
Escucha las solicitudes RDMA en un puerto alternativo; puede ser un número o un nombre listado en /etc/services.
-N o --no-nfs-version vers
Esta opción se puede utilizar para solicitar que rpc.nfsd no ofrezca ciertas versiones de NFS. La versión actual de rpc.nfsd puede soportar las versiones principales de NFS 3 y 4, y las versiones menores 4.0, 4.1 y 4.2.
-s o --syslog
Por defecto, rpc.nfsd registra mensajes de error (y mensajes de depuración, si están habilitados) en stderr. Esta opción hace que rpc.nfsd registre estos mensajes en syslog en su lugar. Tenga en cuenta que los errores encontrados durante el procesamiento de opciones aún se registrarán en stderr independientemente de esta opción.
-t o --tcp
Instruye al servidor NFS del kernel para que abra y escuche en un socket TCP. Este es el valor predeterminado.
-T o --no-tcp
Instruye al servidor NFS del kernel para que no abra ni escuche en un socket TCP.
-u o --udp
Instruye al servidor NFS del kernel para que abra y escuche en un socket UDP.
-U o --no-udp
Instruye al servidor NFS del kernel para que no abra ni escuche en un socket UDP. Este es el valor predeterminado.
-V o --nfs-version vers
Esta opción se puede utilizar para solicitar que rpc.nfsd ofrezca ciertas versiones de NFS. La versión actual de rpc.nfsd puede soportar las versiones principales de NFS 3 y 4, y las versiones menores 4.0, 4.1 y 4.2.
-L o --lease-time segundos
Establece el tiempo de arrendamiento utilizado para NFSv4. Esto corresponde a la frecuencia con la que los clientes necesitan confirmar su estado con el servidor. El rango válido es de 10 a 3600 segundos.
-G o --grace-time segundos
Establece el tiempo de gracia utilizado para NFSv4 y NLM (para NFSv2 y NFSv3). Las nuevas solicitudes de apertura de archivos (NFSv4) y los nuevos bloqueos de archivos (NLM) no se permitirán hasta después de que haya transcurrido este tiempo para permitir que los clientes recuperen el estado.
nproc
Especifica el número de hilos del servidor NFS. Por defecto, se inician ocho hilos. Sin embargo, para un rendimiento óptimo, se deben utilizar varios hilos. La cifra real depende del número y la carga de trabajo creada por los clientes NFS, pero un punto de partida útil son ocho hilos. Los efectos de modificar esa cifra se pueden verificar utilizando el programa nfsstat(8).

Tenga en cuenta que si el servidor NFS ya está en ejecución, las opciones para especificar el host, el puerto y el protocolo se ignorarán. El número de procesos proporcionado será la única opción considerada, y el número de procesos nfsd activos se incrementará o disminuirá para que coincida con este número. En particular, rpc.nfsd 0 detendrá todos los hilos y, por lo tanto, cerrará todas las conexiones abiertas.

ARCHIVO DE CONFIGURACIÓN

Muchas de las opciones que se pueden establecer en la línea de comandos también se pueden controlar a través de valores establecidos en la sección [nfsd] del archivo de configuración /etc/nfs.conf. Los valores reconocidos incluyen:

threads
El número de hilos a iniciar.
host
Un nombre de host, o una lista separada por comas de nombres de host, en los que rpc.nfsd escuchará. El uso de la opción --host reemplaza todos los nombres de host listados aquí.
scope
Establece el ámbito del servidor.
grace-time
El tiempo de gracia, tanto para NFSv4 como para NLM, en segundos.
lease-time
El tiempo de arrendamiento para NFSv4, en segundos.
port
Establece el puerto para TCP/UDP al que enlazarse.
rdma
Habilita el puerto RDMA (con "on" o "yes", etc.) en el puerto estándar ("nfsrdma", puerto 20049).
rdma-port
Establece un puerto RDMA alternativo.
UDP
Habilita (con "on" o "yes", etc.) o deshabilita ("off", "no") el soporte UDP.
TCP
Habilita o deshabilita el soporte TCP.
vers3
vers4
Habilita o deshabilita todas las versiones de NFSv4. Todas las versiones suelen estar habilitadas por defecto.
vers4.1
vers4.2
Establecer estas en "off" o similar deshabilitará las versiones menores seleccionadas. Establecerlas en "on" las habilitará. Los valores predeterminados son determinados por el kernel, y generalmente las versiones menores se habilitan por defecto una vez que la implementación está lo suficientemente completa.

NOTAS

Si el programa está compilado con soporte TI-RPC, habilitará todas las combinaciones de protocolos y familias de direcciones que estén marcadas como visibles en la base de datos de netconfig.

nfsd(8) — Arch Linux

NAME

nfsd — NFS deamon

SYNOPSIS

nfsd [ -H ] [ -V ] [ -h hostport [...] ] [ -p portport [...] ] [ -e exportport [...] ] [ -t tcp ] [ -u udp ] [ -r rpcbind ] [ -s socks ] [ -S sockdir ] [ -l local ] [ -d debug ] [ -o nfsvers ] [ -L logfile ] [ -f logfile ] [ -v nfsv4 ] [ -c count ] [ -m mask ] [ -a ] [ -P ] [ -N ] [ -T ] [ -K ] [ -F ] [ -U ] [ -X ] [ -R ] [ -W ] [ -O ] [ -Z ] [ -Y ] [ -M mountdport ] [ -x mountd ] [ -i lockdport ] [ -k lockd ] [ -y statdport ] [ -z statd ] [ -- nfsd-options ]

DESCRIPTION

The nfsd daemon is the server component of the Network File System (NFS) protocol. It handles NFS requests from clients and provides access to shared files and directories.

This man page describes the options and configuration of the nfsd daemon. For detailed information on NFS concepts and usage, please refer to the NFS documentation.

OPTIONS

-H
Display help message and exit.
-V
Display version information and exit.
-h hostport
Specify the host and port for NFS services.
-p portport
Specify the port for NFS services.
-e exportport
Specify the port for the export daemon.
-t tcp
Enable TCP support.
-u udp
Enable UDP support.
-r rpcbind
Specify the rpcbind daemon.
-s socks
Specify the SOCKS proxy.
-S sockdir
Specify the directory for socket files.
-l local
Bind to a local address.
-d debug
Set the debug level.
-o nfsvers
Specify the NFS version.
-L logfile
Specify the log file for NFS operations.
-f logfile
Specify the log file for file system events.
-v nfsv4
Enable NFSv4 support.
-c count
Set the number of nfsd threads.
-m mask
Set the network mask.
-a
Allow anonymous UID/GID mapping.
-P
Run in foreground mode.
-N
Disable NFSv2 support.
-T
Enable TCP only.
-K
Disable Kerberos authentication.
-F
Do not fork into the background.
-U
Use UDP only.
-X
Disable NFSv3 support.
-R
Restart the daemon.
-W
Disable write cache.
-O
Disable NFSv4 pseudo filesystem.
-Z
Disable NFSv4 ACLs.
-Y
Disable NFSv4 referrals.
-M mountdport
Specify the port for mountd.
-x mountd
Specify the mountd daemon.
-i lockdport
Specify the port for lockd.
-k lockd
Specify the lockd daemon.
-y statdport
Specify the port for statd.
-z statd
Specify the statd daemon.
-- nfsd-options
Pass additional options to the nfsd daemon.

CONFIGURATION FILE

The nfsd daemon can be configured via the /etc/nfs.conf file. This file allows you to specify various parameters and options for the NFS server.

NOTES

The nfsd daemon relies on other related daemons such as mountd, rpcbind, lockd, and statd to provide full NFS functionality.

Ensure that the necessary ports are open in your firewall to allow NFS traffic.

Exported file systems are configured in the /etc/exports file.

SEE ALSO

exports(5), mountd(8), rpcbind(8), lockd(8), statd(8)
