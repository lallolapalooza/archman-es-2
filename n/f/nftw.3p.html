NFTW(3P) Manual del Programador POSIX NFTW(3P)

PROLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

nftw — recorrer un árbol de archivos

SINOPSIS

#include <ftw.h>
int nftw(const char *path, int (*fn)(const char *,
    const struct stat *, int, struct FTW *), int fd_limit, int flags);

DESCRIPCION

La función nftw() desciende recursivamente la jerarquía de directorios con raíz en path. La función nftw() tiene un efecto similar a ftw() excepto que toma un argumento adicional flags, que es una máscara OR inclusiva de bits de cero o más de las siguientes banderas:

FTW_CHDIR
Si está activada, nftw() cambiará el directorio de trabajo actual a cada directorio a medida que informe sobre los archivos en ese directorio. Si está desactivada, nftw() no cambiará el directorio de trabajo actual.
FTW_DEPTH
Si está activada, nftw() informará sobre todos los archivos en un directorio antes de informar sobre el propio directorio. Si está desactivada, nftw() informará sobre cualquier directorio antes de informar sobre los archivos dentro de ese directorio.
FTW_MOUNT
Si está activada, nftw() solo informará sobre archivos en el mismo sistema de archivos que path. Si está desactivada, nftw() informará sobre todos los archivos encontrados durante el recorrido.
FTW_PHYS
Si está activada, nftw() realizará un recorrido físico y no seguirá los enlaces simbólicos.

Si FTW_PHYS está desactivada y FTW_DEPTH está activada, nftw() seguirá los enlaces en lugar de informarlos, pero no informará sobre ningún directorio que sea descendiente de sí mismo. Si FTW_PHYS está desactivada y FTW_DEPTH está desactivada, nftw() seguirá los enlaces en lugar de informarlos, pero no informará sobre el contenido de ningún directorio que sea descendiente de sí mismo.

En cada archivo que encuentre, nftw() llamará a la función suministrada por el usuario fn con cuatro argumentos:

*
El primer argumento es el nombre de ruta del objeto.
*
El segundo argumento es un puntero al buffer stat que contiene información sobre el objeto, rellenado como si se hubieran llamado fstatat(), stat() o lstat() para obtener la información.
*
El tercer argumento es un entero que proporciona información adicional. Su valor es uno de los siguientes:
FTW_D
El objeto es un directorio.
FTW_DNR
El objeto es un directorio que no se puede leer. La función fn no se llamará para ninguno de sus descendientes.
FTW_DP
El objeto es un directorio y se han visitado sus subdirectorios. (Esta condición solo ocurrirá si la bandera FTW_DEPTH está incluida en flags).
FTW_F
El objeto es un archivo que no es un directorio.
FTW_NS
La función stat() falló en el objeto debido a la falta de permisos adecuados. El buffer stat pasado a fn no está definido. El fallo de stat() por cualquier otro motivo se considera un error y nftw() devolverá -1.
FTW_SL
El objeto es un enlace simbólico. (Esta condición solo ocurrirá si la bandera FTW_PHYS está incluida en flags).
FTW_SLN
El objeto es un enlace simbólico que no apunta a un archivo existente. (Esta condición solo ocurrirá si la bandera FTW_PHYS no está incluida en flags).
*
El cuarto argumento es un puntero a una estructura FTW. El valor de base es el desplazamiento del nombre del archivo del objeto en el nombre de ruta pasado como primer argumento a fn. El valor de level indica la profundidad relativa a la raíz del recorrido, donde el nivel raíz es 0.

Los resultados no están definidos si la función fn proporcionada por la aplicación no preserva el directorio de trabajo actual.

El argumento fd_limit establece el número máximo de descriptores de archivo que utilizará nftw() al recorrer el árbol de archivos. Se utilizará como máximo un descriptor de archivo por nivel de directorio.

La función nftw() no necesita ser segura para hilos.

VALOR DE RETORNO

La función nftw() continuará hasta que ocurra la primera de las siguientes condiciones:

*
Una invocación de fn devolverá un valor distinto de cero, en cuyo caso nftw() devolverá ese valor.
*
La función nftw() detecta un error distinto de [EACCES] (ver FTW_DNR y FTW_NS arriba), en cuyo caso nftw() devolverá -1 y establecerá errno para indicar el error.
*
El árbol se agota, en cuyo caso nftw() devolverá 0.

ERRORES

La función nftw() fallará si:

EACCES
Se deniega el permiso de búsqueda para cualquier componente de path o se deniega el permiso de lectura para path, o fn devuelve -1 y no restablece errno.
ELOOP
Existe un bucle en los enlaces simbólicos encontrados durante la resolución del argumento path.
ENAMETOOLONG

La longitud de un componente de un nombre de ruta es mayor que {NAME_MAX}.
ENOENT
Un componente de path no apunta a un archivo existente o path es una cadena vacía.
ENOTDIR
Un componente de path apunta a un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio.
EOVERFLOW
Un campo en la estructura stat no se puede representar correctamente en el entorno de programación actual para uno o más archivos encontrados en la jerarquía de archivos.

La función nftw() puede fallar si:

ELOOP
Se encontraron más de {SYMLOOP_MAX} enlaces simbólicos durante la resolución del argumento path.
EMFILE
Todos los descriptores de archivo disponibles para el proceso están actualmente abiertos.
ENAMETOOLONG

La longitud de un nombre de ruta excede {PATH_MAX}, o la resolución del nombre de ruta de un enlace simbólico produjo un resultado intermedio con una longitud que excede {PATH_MAX}.
ENFILE
Hay demasiados archivos abiertos actualmente en el sistema.

Además, errno puede establecerse si la función apuntada por fn hace que errno se establezca.

nftw(3p) — Arch manual pages

NAME

nftw, nftw_main — file tree walk

SYNOPSIS

#include <ftw.h>

int nftw(const char *dirpath, int (*fn)(const char *, const struct stat *, int, struct FTW *), int nopenfd, int flags);

DESCRIPTION

The nftw() function recursively traverses a file hierarchy. It starts at the file or directory specified by dirpath and calls the function pointed to by fn for each item in the hierarchy. The following flags can be passed in flags:

FTW_CHDIR
Change directories as nftw() descends the hierarchy. This is the default behavior.
FTW_DEPTH
Call the user function for a directory after processing the contents of that directory.
FTW_MOUNT
Do not cross mount points.
FTW_PHYS
Call the user function for the file after processing its symbolic link information. This is the default behavior.

The fn function is called with the following parameters:

fpath
A pointer to the name of the file.
sb
A pointer to the results of calling stat() on the file.
type
The type of the object that nftw() is processing. The following values are defined:
FTW_D
A directory is being processed.
FTW_DNR
A directory is being processed, but nftw() cannot read it.
FTW_DP
A directory is being processed. This value is returned only if FTW_DP is specified in flags. The directory is being processed after its contents.
FTW_F
A file that is not a directory is being processed.
FTW_NS
The information about the file could not be retrieved.
FTW_SL
A symbolic link is being processed.
FTW_SLN
A symbolic link is being processed, but the file it points to does not exist.
ftwbuf
A pointer to an FTW structure, which contains the following members:
level
The level of depth in the tree relative to the top of the hierarchy. The topmost directory has a level of 0.
base
The offset of the filename within the path. For example, if fpath is /usr/lib, then ftwbuf->base is 4.

The nopenfd argument specifies the maximum number of file descriptors that nftw() may have open at any one time. It must be at least 1.

If the fn function returns a non-zero value, nftw() terminates and returns that value.

RETURN VALUE

If nftw() completes without error, it returns 0. If the user function returns a non-zero value, nftw() returns that value. If an error occurs during the traversal, nftw() returns -1.

ERRORS

The nftw() function may fail if:

[EBADF]
The nopenfd argument is less than 1.
[ENOTDIR]
dirpath is not a directory.
[ENOMEM]
Insufficient memory to allocate internal buffers.

The nftw() function may also fail if any of the system calls it uses internally fail. In this case, the function will return -1 and set errno to the corresponding error number.

EXAMPLES

static int display_info(const char *fpath, const struct stat *sb,
                        int tflag, struct FTW *ftwbuf)
{
    const char *type;

    switch (tflag) {
        case FTW_D:     type = "d"; break;
        case FTW_DNR:   type = "dnr"; break;
        case FTW_DP:    type = "dp"; break;
        case FTW_F:     type = "f"; break;
        case FTW_NS:    type = "ns"; break;
        case FTW_SL:    type = "sl"; break;
        case FTW_SLN:   type = "sln"; break;
        default:        type = "?"; break;
    }

    if (tflag == FTW_F) {
        if (S_ISBLK(sb->st_mode)) type = "f b";
        else if (S_ISCHR(sb->st_mode)) type = "f c";
        else if (S_ISFIFO(sb->st_mode)) type = "f p";
        else if (S_ISREG(sb->st_mode)) type = "f r";
        else if (S_ISSOCK(sb->st_mode)) type = "f s";
        else type = "f ?";
    }

    printf("%-10s %2d %8jd %s\n",
           type, ftwbuf->level, (intmax_t) sb->st_size, fpath);

    return 0; /* To tell nftw() to continue */
}

int
main(int argc, char *argv[])
{
    int flags = 0;

    /* Check for optional flags */
    if (argc > 2 && strchr(argv[2], 'd') != NULL)
        flags |= FTW_DEPTH;
    if (argc > 2 && strchr(argv[2], 'p') != NULL)
        flags |= FTW_PHYS;

    /* Walk the file tree */
    if (nftw((argc < 2) ? "." : argv[1], display_info, 20, flags) == -1)
    {
        perror("nftw");
        exit(EXIT_FAILURE);
    }

    exit(EXIT_SUCCESS);
}
// Example output for the above code when run on a directory containing:
//   ./file1.txt (regular file, size 100)
//   ./subdir/ (directory)
//   ./subdir/file2.txt (regular file, size 200)
//
// If run without flags:
// d          0          4096 .
// f r        1          100 ./file1.txt
// d          1          4096 ./subdir
// f r        2          200 ./subdir/file2.txt
//
// If run with 'd' flag (FTW_DEPTH):
// f r        1          100 ./file1.txt
// f r        2          200 ./subdir/file2.txt
// d          1          4096 ./subdir
// d          0          4096 .
//
// If run with 'p' flag (FTW_PHYS): (output is the same as without flags,
// as FTW_PHYS is the default behavior and does not change the output in this case)
// d          0          4096 .
// f r        1          100 ./file1.txt
// d          1          4096 ./subdir
// f r        2          200 ./subdir/file2.txt

The example code defines a callback function `display_info` that prints the type of file, its depth in the directory tree, its size, and its path. The `main` function parses command-line arguments to set the `flags` for `nftw`. It then calls `nftw` to traverse the directory specified on the command line (or the current directory if none is specified), using `display_info` as the callback function.

APPLICATION USAGE

The nftw() function may allocate dynamic storage during its operation. If nftw() is forcibly terminated, such as by longjmp() or siglongjmp() being executed by the function pointed to by fn or an interrupt routine, nftw() does not have a chance to free that storage, so it remains permanently allocated. A safe way to handle interrupts is to store the fact that an interrupt has occurred, and arrange to have the function pointed to by fn return a non-zero value at its next invocation.
