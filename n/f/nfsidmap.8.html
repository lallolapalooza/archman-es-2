nfsidmap(8) Manual del Administrador del Sistema nfsidmap(8)

NOMBRE

nfsidmap - El programa de llamada ascendente (upcall) de ID de NFS

SINOPSIS

nfsidmap [-v] [-t timeout] clave descripción
nfsidmap [-v] [-c]
nfsidmap [-v] [-u|-g|-r usuario]
nfsidmap -d
nfsidmap -l
nfsidmap -h

DESCRIPCIÓN

El protocolo NFSv4 representa los valores UID y GID del sistema local en la red como cadenas del formato usuario@dominio. El proceso de traducción de UID a cadena y de cadena a UID se denomina "mapeo de ID".

El sistema deriva la parte usuario de la cadena realizando una búsqueda de contraseña o grupo. El mecanismo de búsqueda está configurado en /etc/idmapd.conf.

Por defecto, la parte dominio de la cadena es el nombre de dominio DNS del sistema. También se puede especificar en /etc/idmapd.conf si el sistema es multi-homed, o si el nombre de dominio DNS del sistema no coincide con el nombre del realm de Kerberos del sistema.

Cuando el dominio no se especifica en /etc/idmapd.conf, se consultará al servidor DNS local para el registro de texto _nfsv4idmapdomain. Si el registro existe, se utilizará como dominio. Cuando el registro no existe, se utilizará la parte de dominio del nombre de dominio DNS.

El programa /usr/sbin/nfsidmap realiza las traducciones en nombre del kernel. El kernel utiliza el mecanismo de solicitud de clave (request-key) para realizar una llamada ascendente (upcall). /usr/sbin/nfsidmap es invocado por /sbin/request-key, realiza la traducción e inicializa una clave con la información resultante. El kernel luego almacena en caché los resultados de la traducción en la clave.

nfsidmap también puede borrar los resultados de mapeo de ID en caché en el kernel, o revocar una clave en particular. Una clave en caché incorrecta puede resultar en que la propiedad de archivos y directorios vuelva a ser "nobody" en los puntos de montaje NFSv4.

Además, las opciones -d y -l están disponibles para ayudar a diagnosticar misconfiguraciones. No tienen efecto en el keyring que contiene los resultados de mapeo de ID.

OPCIONES

-c
Borra todas las claves del keyring.
-d
Muestra el nombre de dominio NFSv4 efectivo del sistema en stdout.
-g usuario
Revoca la clave gid del usuario dado.
-h
Muestra el mensaje de uso.
-l
Muestra en stdout todas las claves actualmente en el keyring utilizado para almacenar en caché los resultados del mapeo de ID. Estas claves solo son visibles para el superusuario.
-r usuario
Revoca tanto la clave uid como la gid del usuario dado.
-t timeout
Establece el temporizador de expiración, en segundos, de la clave. El valor predeterminado es 600 segundos (10 minutos).
-u usuario
Revoca la clave uid del usuario dado.
-v
Aumenta la verbosidad de la salida a syslog (se puede especificar varias veces).

CONFIGURACIÓN

Será necesario modificar el archivo /etc/request-key.conf para que /sbin/request-key pueda dirigir correctamente la llamada ascendente. La siguiente línea debería añadirse antes de una llamada a keyctl negate:

create id_resolver * * /usr/sbin/nfsidmap -t 600 %k %d

Esto dirigirá todas las solicitudes de id_resolver al programa /usr/sbin/nfsidmap. El -t 600 define cuántos segundos en el futuro expirará la clave. Este es un parámetro opcional para /usr/sbin/nfsidmap y por defecto será de 600 segundos cuando no se especifique.

El sistema idmapper utiliza cuatro descripciones de clave:

uid: Busca el UID para el usuario dado
gid: Busca el GID para el grupo dado
user: Busca el nombre de usuario para el UID dado
group: Busca el nombre de grupo para el GID dado

Puede optar por manejar cualquiera de estos individualmente, en lugar de utilizar el programa genérico de llamada ascendente. Si desea utilizar su propio programa para una búsqueda de uid, debería editar su request-key.conf para que se parezca a esto:

create id_resolver uid:* * /some/other/program %k %d
create id_resolver * * /usr/sbin/nfsidmap %k %d

Observe que la nueva línea se añadió antes de la línea para el programa genérico. request-key encontrará la primera línea coincidente y ejecutará el programa correspondiente. En este caso, /some/other/program manejará todas las búsquedas de uid, y /usr/sbin/nfsidmap manejará las búsquedas de gid, user y group.

ARCHIVOS

/etc/idmapd.conf
Archivo de configuración de mapeo de ID
/etc/request-key.conf
Archivo de configuración de solicitud de clave
