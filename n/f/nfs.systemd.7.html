NOMBRE

nfs.systemd - gestión de servicios NFS a través de systemd.

SINOPSIS

nfs-utils.service
nfs-server.service
nfs-client.target
etc

DESCRIPCIÓN

El paquete nfs-utils proporciona un conjunto de archivos de unidad y generadores de systemd que permiten iniciar y gestionar los diversos servicios. Estos archivos de unidad y generadores aseguran que los servicios se inicien en el orden correcto y que los prerrequisitos estén activos antes de que comiencen los servicios dependientes. Dado que hay bastantes archivos de unidad y generadores, no está claro de inmediato cómo lograr mejor ciertos resultados. Las siguientes subsecciones intentan cubrir los problemas que es más probable que surjan.

Configuración

Los archivos de unidad systemd estándar no proporcionan una forma fácil de pasar argumentos de línea de comandos a los demonios para configurar su comportamiento. En muchos casos, dicha configuración se puede realizar realizando cambios en /etc/nfs.conf u otros archivos de configuración (ver nfs.conf(5)). Cuando eso no es conveniente, una distribución puede proporcionar archivos "drop-in" de systemd que reemplazan la configuración ExecStart= para iniciar el programa con diferentes argumentos. Por ejemplo, un archivo drop-in systemd/system/nfs-mountd.service.d/local.conf que contenga

[Service]
EnvironmentFile=/etc/sysconfig/nfs
ExecStart=
ExecStart= /usr/sbin/rpc.mountd $RPCMOUNTDOPTS
haría que la unidad nfs-mountd.service ejecutara el programa rpc.mountd usando, como argumentos, el valor dado para RPCMOUNTDOPTS en /etc/sysconfig/nfs. Esto permite una integración fluida con las herramientas de configuración existentes.

Habilitación de archivos de unidad

Hay tres archivos de unidad diseñados para ser habilitados manualmente. Todos los demás se ejecutan automáticamente según sea necesario. Los tres son:

nfs-client.target
Esto debe habilitarse en cualquier host que sirva como cliente NFS. Hay poco costo en habilitarlo transparentemente cada vez que se instala el software cliente NFS.
nfs-server.service
Esto debe habilitarse para proporcionar servicio NFS a los clientes. Inicia y configura los demonios requeridos en el orden requerido.
nfs-blkmap.service
El demonio blkmapd solo se requiere en clientes NFS que están usando pNFS (NFS paralelo), y en particular usando el protocolo de diseño blocklayout. Si va a utilizar esta extensión particular de NFS, se debe habilitar la unidad nfs-blkmap.service.

Varias otras unidades que podrían considerarse opcionales, como rpc-gssd.service, tienen cuidado de iniciarse solo si existe el archivo de configuración requerido. rpc-gssd.service no se iniciará si el archivo krb5.keytab no existe (típicamente en /etc).

Reiniciando servicios NFS

La mayoría de los demonios NFS se pueden reiniciar en cualquier momento. Recargarán cualquier estado que necesiten y continuarán atendiendo solicitudes. Sin embargo, esto rara vez es necesario.

Cuando se realizan cambios de configuración, puede ser difícil saber exactamente qué servicios deben reiniciarse para asegurar que la configuración tenga efecto. El enfoque más simple, que a menudo es el mejor, es reiniciar todo. Para ayudar con esto, se proporciona la unidad nfs-utils.service. Declara las dependencias apropiadas con otros archivos de unidad para que

systemctl restart nfs-utils
reiniciará todos los demonios NFS que estén en ejecución. Esto hará que todos los cambios de configuración surtan efecto, *excepto* los cambios en las listas de opciones de montaje en /etc/fstab o /etc/nfsmount.conf. Las opciones de montaje solo se pueden cambiar desmontando y volviendo a montar el sistema de archivos. Esta puede ser una operación disruptiva, por lo que solo debe hacerse cuando el valor justifique el costo. El comando
umount -a -t nfs; mount -a -t nfs
debería desmontar y volver a montar todos los sistemas de archivos NFS.

Enmascarando servicios no deseados

En raras ocasiones, puede haber un deseo de prohibir que se ejecuten algunos servicios, aunque normalmente forman parte de un sistema NFS que funciona. Esto puede ser necesario para reducir la carga del sistema al mínimo absoluto, o para reducir la superficie de ataque al no ejecutar demonios que no son absolutamente necesarios.

Tres servicios particulares a los que esto puede aplicarse son rpcbind, idmapd y rpc-gssd. rpcbind no forma parte del paquete nfs-utils, pero es utilizado por varios servicios NFS. Sin embargo, *no* se necesita cuando solo se usa NFSv4. Si un sitio nunca usará NFSv3 (o NFSv2) y no quiere que rpcbind esté en ejecución, el enfoque correcto es ejecutar

systemctl mask rpcbind
Esto deshabilitará rpcbind, y los diversos servicios NFS que dependen de él (y solo se necesitan para NFSv3) se negarán a iniciarse, sin interferir con la operación de los servicios NFSv4. En particular, rpc.statd no se ejecutará cuando rpcbind esté enmascarado.

idmapd solo se necesita para NFSv4, y aun así no se necesita cuando el cliente y el servidor acuerdan usar IDs de usuario en lugar de nombres de usuario para identificar a los propietarios de los archivos. Si idmapd no se necesita y no se desea, se puede enmascarar con

systemctl mask idmapd
Se asume que rpc-gssd se necesita si el archivo krb5.keytab está presente. Si un sitio necesita este archivo presente pero no desea que rpc-gssd esté en ejecución, se puede enmascarar con
systemctl mask rpc-gssd

Generadores

Los generadores de unidades de systemd son pequeños ejecutables colocados en /usr/lib/systemd/system-generators/ para extender dinámicamente la jerarquía de archivos de unidad. El paquete nfs-utils proporciona tres:

nfsroot-generator
Crea la unidad sysroot.mount para montar /sysroot a través de NFSv4 en el initrd, si detecta una de las siguientes opciones en la línea de comandos del kernel:
root=/dev/nfs nfsroot=[<server>:]<path>[,<options>]
Definido en <kernel_source>/Documentation/admin-guide/nfs/nfsroot.rst
root=nfs[4]:[<server>:]<path>[:<options>]
Definido en dracut.cmdline(7).

NOTA: Aunque "nfs" se puede usar como indicador de tipo para el punto de montaje, la unidad de montaje siempre usará "nfs4".

nfs-server-generator
Crea dependencias de ordenación entre nfs-server.service y varios montajes de sistemas de archivos: debería iniciarse antes de que se monten los puntos de montaje "nfs", en caso de que sean montajes loop-back, y después de que se monten todos los sistemas de archivos exportados, para que no haya riesgo de exportar el directorio subyacente.
rpc-pipefs-generator
Crea dependencias de ordenación entre los servicios NFS y el punto de montaje rpc_pipefs.

NAME

nfs.service, nfs.socket, nfs-client.target, nfs-server.service, nfs-utils.service - NFS systemd service units

SYNOPSIS

/usr/lib/systemd/system/nfs-client.target

/usr/lib/systemd/system/nfs-server.service

/usr/lib/systemd/system/nfs-utils.service

/usr/lib/systemd/system/nfs.service

/usr/lib/systemd/system/nfs.socket

DESCRIPTION

This manual page describes the systemd service units provided by the nfs-utils package. These units manage the Network File System (NFS) services on a Linux system.

The primary units are:

  • nfs-client.target: A target unit that can be used to enable NFS client functionality. When this target is started, it pulls in necessary services for NFS client operations.

  • nfs-server.service: The main service unit for the NFS server. It starts the necessary daemons (like rpc.mountd, rpc.nfsd, rpc.statd, rpc.lockd) to provide NFS services to clients.

  • nfs-utils.service: A general service unit that may be used for utilities or auxiliary functions related to NFS. The exact behavior of this unit can vary depending on the distribution and configuration.

  • nfs.service: This unit is often a compatibility link or a meta-service that depends on other NFS services. Its specific purpose might be to simplify enabling or starting NFS in a generic way.

  • nfs.socket: A socket unit that can be used for socket-based activation of NFS services. When a connection is made to the NFS socket, systemd can automatically start the corresponding NFS service.

These units allow for fine-grained control over NFS services using standard systemd commands like systemctl start nfs-server.service, systemctl enable nfs-client.target, etc.
