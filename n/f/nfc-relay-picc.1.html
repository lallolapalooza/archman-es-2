NOMBRE

nfc-relay-picc - Herramienta de demostración de retransmisión para ISO14443-4

SINOPSIS

nfc-relay-picc

DESCRIPCIÓN

nfc-relay-picc

Esta herramienta requiere dos dispositivos NFC. Un dispositivo (configurado como destino) emulará una etiqueta ISO/IEC 14443-4 tipo A, mientras que el segundo dispositivo (configurado como iniciador) actuará como un lector. La etiqueta genuina se puede colocar en el segundo dispositivo (iniciador) y el emulador de etiqueta (destino) se puede colocar cerca del lector original. Toda la comunicación ahora se retransmite y se muestra en la pantalla en tiempo real.

etiqueta <---> iniciador (retransmisión) <---> destino (retransmisión) <---> lector original

OPCIONES

-h
Ayuda
Lista de opciones

-q
Modo silencioso
Suprime la impresión de datos retransmitidos (mejora el tiempo)

-t
Solo modo destino (para usar en el lado del lector)
Los comandos se envían al descriptor de archivo 4
Las respuestas se leen del descriptor de archivo 3

-i
Solo modo iniciador (para usar en el lado de la etiqueta)
Los comandos se leen del descriptor de archivo 3
Las respuestas se envían al descriptor de archivo 4

-s
Intercambia los roles de los dispositivos encontrados
Normalmente, el primer dispositivo encontrado se usa como destino (emulador) y el segundo
como iniciador (lector). Al usar esta opción, estos roles se invierten.

-n N
Añade un tiempo de espera de N segundos (entero) en el bucle

EJEMPLOS

Uso básico:


nfc-relay-picc

Retransmisión remota sobre TCP/IP:


socat
TCP-LISTEN:puerto,reuseaddr
"EXEC:nfc-relay-picc -i,fdin=3,fdout=4"
socat
TCP:hostremoto:puerto
"EXEC:nfc-relay-picc -t,fdin=3,fdout=4"

NOTAS

Hay algunas diferencias con nfc-relay:

Este ejemplo solo funciona con PN532 porque se basa en su manejo interno de las especificidades de ISO14443-4.

Gracias a este manejo interno y la inyección de tramas WTX, este ejemplo funciona en lectores muy estrictos con el tiempo.
