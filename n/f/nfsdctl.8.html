NOMBRE

nfsdctl - programa de control para el servidor NFS del kernel de Linux

SINOPSIS

nfsdctl [ OPCIÓN ] COMANDO ...

DESCRIPCIÓN

nfsdctl es un programa de control y consulta para el servidor NFS dentro del kernel. Hay varios subcomandos (documentados a continuación) que permiten al administrador configurar o consultar diferentes aspectos del servidor NFS.

Para obtener información sobre el uso de los diferentes subcomandos, pase el subcomando con el parámetro --help. Por ejemplo:

nfsdctl listener --help

OPCIONES

-d, --debug

Habilitar registro de depuración

-h, --help

Imprimir texto de ayuda del programa

-s, --syslog

Registrar en syslog en lugar de en stderr (el valor por defecto)

-V, --version

Imprimir la versión del programa

SUBCOMANDOS

Cada subcomando también puede aceptar su propio conjunto de opciones y argumentos. La opción --help es estándar para todos los subcomandos:

autostart

Inicia el servidor utilizando la configuración de la sección [nfsd] de /etc/nfs.conf. Este subcomando no toma argumentos. Tenga en cuenta que si no se establece un valor de "threads=" en nfs.conf, se pondrán en línea 16 hilos del servidor.

listener

Obtener/establecer los sockets de escucha para el servidor. Ejecute esto sin argumentos para obtener una lista de los sockets en los que el servidor está escuchando actualmente. Para añadir o eliminar sockets, páselo cadenas separadas por espacios en el formato: 
{ +|- }{ protocolo }:{ dirección }:{ puerto }
Los campos son:
+ para añadir un oyente, - para eliminar uno
protocolo: nombre del protocolo (ej. tcp, udp, rdma)
dirección: nombre de host o dirección
puerto: número de puerto o nombre de servicio
Todos los campos son obligatorios, excepto la dirección. Si la dirección es una
cadena vacía, entonces los oyentes se abrirán para INADDR_ANY y IN6ADDR_ANY_INIT
para ipv6 (si está habilitado). La dirección puede ser un nombre de host o
una dirección IP. Las direcciones IPv4 deben estar en formato de cuádruple
punto. Las direcciones IPv6 deben estar en el formato estándar separado por
dos puntos y deben ir entre corchetes.

nlm

Obtener información sobre la configuración de NLM (lockd) en el espacio de nombres de red actual. Este subcomando no toma argumentos.

status

Obtener información sobre las RPCs que se están ejecutando actualmente en el servidor. Este subcomando no toma argumentos.

threads

Obtener/establecer el número de hilos nfsd en ejecución en cada grupo. Pase una lista de enteros para cambiar el número actual de hilos. Pasarles un valor de 0 detendrá el servidor NFS. Ejecute esto sin argumentos para obtener el número actual de hilos en ejecución en cada grupo.

version

Obtener/establecer las versiones NFS habilitadas para el servidor. Ejecute sin argumentos para obtener una lista de versiones soportadas y si están actualmente habilitadas o deshabilitadas. Para habilitar o deshabilitar una versión, pásele una cadena en el formato: 
{ +|- }{ MAYOR }{.{ MENOR }}
Los campos son:
+ para habilitar una versión, - para deshabilitar
MAYOR: el valor entero de la versión mayor
MENOR: el valor entero de la versión menor
El campo minorversion es opcional. Si no se proporciona, deshabilitará o
habilitará todas las minorversions para esa versión mayor.
Tenga en cuenta que las versiones solo se pueden establecer cuando no hay hilos
nfsd en ejecución.

pool-mode

Obtener/establecer el modo de grupo del host. Esto hará que el servidor inicie hilos que están anclados a la CPU o al nodo NUMA. Esto solo se puede establecer cuando no hay hilos nfsd en ejecución. 
Las opciones disponibles son:
  global:  un solo grupo grande
  percpu:  grupo por CPU
  pernode: grupo por nodo NUMA
  auto:    elegir un modo basado en la configuración del host

EJEMPLOS

Inicie el servidor con la configuración de nfs.conf:

nfsdctl autostart

Obtener una lista de los sockets de escucha actuales:

nfsdctl listener

Mostrar las versiones NFS soportadas y habilitadas:

nfsdctl version

Añadir oyente TCP en todas las direcciones (v4 y v6), puerto 2049:

nfsdctl listener +tcp::2049

Añadir oyente RDMA en 1.2.3.4 puerto 20049:

nfsdctl listener +rdma:1.2.3.4:20049

Añadir el mismo oyente en la dirección IPv6 f00::ba4 puerto 20050:

nfsdctl listener +rdma:[f00::ba4]:20050

Habilitar NFS versión 3, deshabilitar v4.0:

nfsdctl version +3 -4.0

Cambiar el número de hilos en ejecución en el primer grupo a 256:

nfsdctl threads 256

Establecer el modo de grupo a "pernode":

nfsdctl pool-mode pernode

NOTAS

nfsdctl pretende reemplazar a rpc.nfsd(8), que controla el servidor nfs utilizando los archivos bajo /proc/fs/nfsd. nfsdctl utiliza en su lugar una interfaz netlink(7) para lograr los mismos objetivos.

La mayoría de los comandos que consultan el servidor NFS pueden ser ejecutados por un usuario no privilegiado, pero la configuración del servidor típicamente requiere una cuenta con privilegios elevados.
