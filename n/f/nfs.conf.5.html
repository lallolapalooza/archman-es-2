NFS.CONF(5) Manual de formatos de archivo NFS.CONF(5)

NOMBRE

nfs.conf - configuración general para demonios y herramientas NFS

SINOPSIS

/usr/etc/nfs.conf /usr/etc/nfs.conf.d/ /etc/nfs.conf /etc/nfs.conf.d/

DESCRIPCIÓN

Estos archivos contienen la configuración específica del sitio para varios demonios NFS y otros procesos. La mayor parte de la configuración también se puede pasar a los procesos a través de argumentos de línea de comandos, pero puede ser más conveniente tener un archivo central. En particular, esto fomenta una configuración consistente entre diferentes procesos.

Cuando se proporcionan opciones de línea de comandos, estas anulan los valores establecidos en este archivo. Cuando este archivo no especifica un parámetro en particular, y no se proporciona ninguna opción de línea de comandos, cada herramienta proporciona sus propios valores predeterminados.

El formato del archivo admite múltiples secciones, cada una de las cuales puede contener múltiples asignaciones de valores. Una sección se introduce con una línea que contiene el nombre de la sección entre corchetes, por lo que

[global]
introduciría una sección llamada global. Una asignación de valor es una única línea que tiene el nombre del valor, un signo igual y una configuración para el valor, por lo que
threads = 4
establecería el valor llamado threads en la sección actual a 4. Los espacios y tabulaciones al principio y al final se ignoran, al igual que los espacios y tabulaciones alrededor del signo igual. Las comillas simples y dobles que rodean el valor asignado también se eliminan. Si la cadena resultante está vacía, se ignora toda la asignación.

Cualquier línea que comience con “#” o “;” se ignora, al igual que cualquier línea en blanco.

Si el valor asignado comenzara con un “$”, el resto se tratará como un nombre y se buscará en la sección [environment] o en el entorno del proceso (ver environ(7)). El valor encontrado se usará para este valor.

El nombre de valor include es especial. Si una sección contiene

include = /algún/nombre/de/archivo
entonces el archivo con el nombre especificado se leerá, y cualquier asignación de valor encontrada allí se agregará a la sección actual. Si el archivo contiene encabezados de sección, se crearán nuevas secciones como si el archivo incluido apareciera en lugar de la línea include. Si el nombre del archivo comienza con un guion, este se elimina antes de abrir el archivo, y si el archivo no existe, no se muestra ninguna advertencia. Normalmente, un archivo de inclusión inexistente genera una advertencia.

La búsqueda de nombres de sección y valor no distingue entre mayúsculas y minúsculas.

Donde se espera un valor booleano, se pueden usar true, t, yes, y, on, o 1 para "verdadero", mientras que false, f, no, n, off, o 0 se pueden usar para "falso". Las comparaciones no distinguen entre mayúsculas y minúsculas.

SECCIONES

Las siguientes secciones son conocidas por varios programas y pueden contener los valores nombrados dados. La mayoría de las secciones también pueden contener un valor debug, que puede ser uno o más de la lista general, call, auth, parse, all. Cuando se proporciona una lista, los miembros deben estar separados por comas. Los valores 0 y 1 también se aceptan, siendo '0' el que no realiza cambios en el nivel de depuración, y '1' equivalente a especificar 'all'.

general
Valores reconocidos: pipefs-directory.

Ver blkmapd(8), rpc.idmapd(8), y rpc.gssd(8) para más detalles.

exports
Valores reconocidos: rootdir.

Establecer rootdir en una ruta válida hace que el servidor NFS actúe como si la ruta proporcionada se estuviera anteponiendo a todas las entradas exportadas. Por ejemplo, si rootdir=/my/root, y hay una entrada en /etc/exports para /filesystem, entonces el cliente podrá montar la ruta como /filesystem, pero en el servidor, esto se resolverá a la ruta /my/root/filesystem.

exportd
Valores reconocidos: manage-gids, threads, cache-use-ipaddr, ttl, state-directory-path

Ver exportd(8) para más detalles.

Tenga en cuenta que establecer "debug = auth" para exportd es equivalente a proporcionar la opción --log-auth.

nfsd
Valores reconocidos: threads, host, scope, port, grace-time, lease-time, udp, tcp, vers3, vers4, vers4.0, vers4.1, vers4.2, rdma,

Los valores de versión y protocolo son valores booleanos como se describe anteriormente, y también son utilizados por rpc.mountd. Threads y los dos tiempos son enteros. port y rdma son nombres o números de servicio. Ver rpc.nfsd(8) para más detalles.

mountd
Valores reconocidos: manage-gids, descriptors, port, threads, reverse-lookup, cache-use-ipaddr, ttl, state-directory-path, ha-callout.

Estos, junto con los valores de protocolo y versión en la sección [nfsd], se utilizan para configurar mountd. Ver rpc.mountd(8) para más detalles.

Tenga en cuenta que establecer "debug = auth" para mountd es equivalente a proporcionar la opción --log-auth.

El valor state-directory-path en la sección [mountd] también es utilizado por exportfs(8).

statd
Valores reconocidos: port, outgoing-port, name, state-directory-path, ha-callout.

Ver rpc.statd(8) para más detalles.

lockd
Valores reconocidos: port y udp-port.

Ver rpc.statd(8) para más detalles.

sm-notify
Valores reconocidos: retry-time, outgoing-port, y outgoing-addr.

Ver sm-notify(8) para más detalles.

gssd
Valores reconocidos: verbosity, rpc-verbosity, use-memcache, use-machine-creds, use-gss-proxy, avoid-dns, limit-to-legacy-enctypes, context-timeout, rpc-timeout, keytab-file, cred-cache-directory, preferred-realm, set-home.

Ver rpc.gssd(8) para más detalles.

svcgssd
Valores reconocidos: principal.

Ver rpc.svcgssd(8) para más detalles.

exportfs
Solo se reconoce debug=.
nfsrahead
Valores reconocidos: nfs, nfsv4, default.

Ver nfsrahead(5) para más detalles.

ARCHIVOS

/usr/etc/nfs.conf
/usr/etc/nfs.conf.d/*.conf
/etc/nfs.conf
/etc/nfs.conf.d/*.conf

Varios archivos de configuración leídos en orden. Las configuraciones posteriores anulan las anteriores.
