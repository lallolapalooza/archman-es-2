NSENTER(1) Comandos de usuario NSENTER(1)

NOMBRE

nsenter - ejecutar programa en diferentes namespaces

SINOPSIS

nsenter [opciones] [programa [argumentos]]

DESCRIPCIÓN

El comando nsenter ejecuta programa en el(los) namespace(s) especificados en las opciones de línea de comandos (descritos a continuación). Si no se proporciona programa, se ejecuta "${SHELL}" (por defecto: /bin/sh).

Namespaces accesibles son:

namespace de montaje

Montar y desmontar sistemas de archivos no afectará al resto del sistema, excepto a los sistemas de archivos marcados explícitamente como compartidos (con mount --make-shared; ver mount_namespaces(7) y la discusión de la bandera CLONE_NEWNS en clone(2).

namespace UTS

Establecer el nombre de host o dominio no afectará al resto del sistema. Para más detalles, ver uts_namespaces(7).

namespace IPC

El proceso tendrá un namespace independiente para colas de mensajes POSIX, así como colas de mensajes System V, conjuntos de semáforos y segmentos de memoria compartida. Para más detalles, ver ipc_namespaces(7).

namespace de red

El proceso tendrá pilas IPv4 e IPv6 independientes, tablas de enrutamiento IP, reglas de firewall, los directorios /proc/net y /sys/class/net, sockets, etc. Para más detalles, ver network_namespaces(7).

namespace PID

Los hijos tendrán un conjunto de mapeos de PID a proceso separado del proceso nsenter. nsenter se divide por defecto si cambia el namespace PID, de modo que el nuevo programa y sus hijos compartan el mismo namespace PID y sean visibles entre sí. Si se usa --no-fork, el nuevo programa será ejecutado sin dividirse. Para más detalles, ver pid_namespaces(7).

namespace de usuario

El proceso tendrá un conjunto distinto de UIDs, GIDs y capacidades. Para más detalles, ver user_namespaces(7).

namespace cgroup

El proceso tendrá una vista virtualizada de /proc/self/cgroup, y los nuevos montajes de cgroup estarán anclados en la raíz del cgroup del namespace. Para más detalles, ver cgroup_namespaces(7).

namespace de tiempo

El proceso puede tener una vista distinta de CLOCK_MONOTONIC y/o CLOCK_BOOTTIME que puede cambiarse usando /proc/self/timens_offsets. Para más detalles, ver time_namespaces(7).

OPCIONES

Varias de las opciones siguientes que se relacionan con namespaces toman un argumento opcional archivo. Este debe ser uno de los archivos /proc/[pid]/ns/* descritos en namespaces(7), o la ruta de un montaje bind que se creó sobre uno de esos archivos.

-a, --all

Entrar en todos los namespaces del proceso objetivo usando las rutas de namespace por defecto de /proc/[pid]/ns/*. Las rutas por defecto a los namespaces del proceso objetivo pueden ser sobrescritas por opciones específicas de namespace (por ejemplo, --all --mount=[ruta]).

El namespace de usuario será ignorado si es el mismo que el namespace de usuario actual del llamador. Evita que un llamador que ha soltado capacidades las recupere a través de una llamada a setns(). Ver setns(2) para más detalles.

-t, --target PID

Especifica un proceso objetivo para obtener contextos de él. Las rutas a los contextos especificadas por pid son:

/proc/pid/ns/mnt

el namespace de montaje

/proc/pid/ns/uts

el namespace UTS

/proc/pid/ns/ipc

el namespace IPC

/proc/pid/ns/net

el namespace de red

/proc/pid/ns/pid

el namespace PID

/proc/pid/ns/user

el namespace de usuario

/proc/pid/ns/cgroup

el namespace cgroup

/proc/pid/ns/time

el namespace de tiempo

/proc/pid/root

el directorio raíz

/proc/pid/cwd

el directorio de trabajo respectivamente

-m, --mount[=archivo]

Entrar en el namespace de montaje. Si no se especifica archivo, entra en el namespace de montaje del proceso objetivo. Si se especifica archivo, entra en el namespace de montaje especificado por archivo.

-u, --uts[=archivo]

Entrar en el namespace UTS. Si no se especifica archivo, entra en el namespace UTS del proceso objetivo. Si se especifica archivo, entra en el namespace UTS especificado por archivo.

-i, --ipc[=archivo]

Entrar en el namespace IPC. Si no se especifica archivo, entra en el namespace IPC del proceso objetivo. Si se especifica archivo, entra en el namespace IPC especificado por archivo.

-n, --net[=archivo]

Entrar en el namespace de red. Si no se especifica archivo, entra en el namespace de red del proceso objetivo. Si se especifica archivo, entra en el namespace de red especificado por archivo.

-N, --net-socket fd

Entrar en el namespace de red del socket del proceso objetivo. Requiere que se especifique el proceso --target. Soporte desde Linux 5.6.

-p, --pid[=archivo]

Entrar en el namespace PID. Si no se especifica archivo, entra en el namespace PID del proceso objetivo. Si se especifica archivo, entra en el namespace PID especificado por archivo.

-U, --user[=archivo]

Entrar en el namespace de usuario. Si no se especifica archivo, entra en el namespace de usuario del proceso objetivo. Si se especifica archivo, entra en el namespace de usuario especificado por archivo. Ver también las opciones --setuid y --setgid.

--user-parent

Entrar en el namespace de usuario padre. El namespace de usuario padre se obtendrá de cualquier otro namespace habilitado. Si se combina con la opción --user, el namespace de usuario padre se obtendrá del namespace de usuario y lo reemplazará.

-C, --cgroup[=archivo]

Entrar en el namespace cgroup. Si no se especifica archivo, entra en el namespace cgroup del proceso objetivo. Si se especifica archivo, entra en el namespace cgroup especificado por archivo.

-T, --time[=archivo]

Entrar en el namespace de tiempo. Si no se especifica archivo, entra en el namespace de tiempo del proceso objetivo. Si se especifica archivo, entra en el namespace de tiempo especificado por archivo.

-G, --setgid gid

Establece el ID de grupo que se usará en el namespace entrado y descarta los grupos suplementarios. nsenter siempre establece el GID para los namespaces de usuario, por defecto es 0. Si se especifica el argumento "follow", se usa el GID del proceso objetivo.

-S, --setuid uid

Establece el ID de usuario que se usará en el namespace entrado. nsenter siempre establece el UID para los namespaces de usuario, por defecto es 0. Si se especifica el argumento "follow", se usa el UID del proceso objetivo.

--keep-caps

Cuando se da la opción --user, asegura que las capacidades otorgadas en el namespace de usuario se conserven en el proceso hijo.

--preserve-credentials

No modificar UID y GID al entrar en un namespace de usuario. Por defecto se descartan los grupos suplementarios y se establece GID y UID a 0.

-r, --root[=directorio]

Establece la raíz

nsenter(8) — util-linux — Arch Linux

NAME

nsenter - ejecutar un programa en los namespaces de otro proceso

SYNOPSIS

nsenter [-a|--all] [-t, --target PID] [-m, --mount[=directory]] [-u, --uts[=directory]] [-i, --ipc[=directory]] [-n, --net[=directory]] [-U, --user[=directory]] [-p, --pid[=directory]] [-w, --wd[=directory]] [-W, --wdns[=directory]] [-e, --env] [-F, --no-fork] [-Z, --follow-context] [-c, --join-cgroup] [-h, --help] [-V, --version] program [arguments]

DESCRIPTION

Ejecuta el program especificado con los namespaces del proceso especificado por PID. Por defecto, si no se especifica ningún namespace, el PID por defecto es el del primer proceso en ejecutarse en el sistema, que es el proceso init (PID 1).

El comando nsenter primero entra en los namespaces especificados y luego ejecuta el programa dado.

Si no se especifica ninguna opción de namespace, las opciones -a, --all o -t, --target se asumen como oblicatorias.

OPTIONS

Las siguientes opciones se utilizan para especificar los namespaces a los que se debe unir el proceso.

-t, --target PID
Especifica el PID del proceso cuyo namespaces se utilizarán. El valor por defecto es 1.
-a, --all
Entra en todos los namespaces disponibles del proceso objetivo.
-m, --mount[=directory]
Entra en el namespace de montaje. Si se especifica un directorio, se cambia el directorio raíz a ese directorio antes de que se cambien los namespaces solicitados. El directorio especificado se abre antes de que se cambien los namespaces solicitados, lo que significa que el directorio especificado funciona como un "túnel" al namespace actual.
-u, --uts[=directory]
Entra en el namespace UTS. Si se especifica un directorio, se establece el directorio raíz al directorio raíz del proceso objetivo. Si no se especifica un directorio, se establece el directorio raíz al directorio raíz del proceso objetivo. El directorio especificado se abre antes de que se cambien los namespaces solicitados.
-i, --ipc[=directory]
Entra en el namespace IPC.
-n, --net[=directory]
Entra en el namespace de red.
-U, --user[=directory]
Entra en el namespace de usuario.
-p, --pid[=directory]
Entra en el namespace PID. Si no se especifica un directorio, se establece el directorio raíz al directorio raíz del proceso objetivo. Si se especifica un directorio, se establece el directorio raíz al directorio especificado. El directorio especificado se abre antes de que se cambien los namespaces solicitados.
-w, --wd[=directory]
Establece el directorio de trabajo. Si no se especifica un directorio, se establece el directorio de trabajo al directorio de trabajo del proceso objetivo. Si se especifica un directorio, se establece el directorio de trabajo al directorio especificado. El directorio especificado se abre antes de que se cambien los namespaces solicitados, lo que significa que el directorio especificado funciona como un "túnel" al namespace actual. Vea también --wdns.
-W, --wdns[=directory]
Establece el directorio de trabajo. El directorio se abre después de cambiar a los namespaces solicitados y después de la llamada a chroot(2). Las opciones --wd y --wdns son mutuamente excluyentes.
-e, --env
Pasa variables de entorno del proceso objetivo al nuevo proceso que se está creando. Si no se proporciona esta opción, las variables de entorno permanecerán iguales que en el namespace actual.
-F, --no-fork
No hacer fork antes de ejecutar el programa especificado. Por defecto, al entrar en un namespace PID, nsenter llama a fork antes de llamar a exec para que los hijos también estén en el namespace PID recién entrado.
-Z, --follow-context
Establece el contexto de seguridad SELinux utilizado para ejecutar un nuevo proceso de acuerdo con el proceso que ya se está ejecutando especificado por el PID del --target. (El util-linux tiene que estar compilado con soporte SELinux, de lo contrario la opción no estará disponible).
-c, --join-cgroup
Añade el proceso iniciado al cgroup del proceso objetivo.
-h, --help
Muestra el texto de ayuda y sale.
-V, --version
Muestra la versión y sale.

NOTES

La opción --user-parent requiere Linux 4.9 o superior, los kernels más antiguos generarán un ioctl inapropiado para el error del dispositivo.
