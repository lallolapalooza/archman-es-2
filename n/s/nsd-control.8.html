NOMBRE

nsd-control, nsd-control-setup - Utilidad de control remoto del servidor NSD.

SINOPSIS

nsd-control [-c archivo_cfg] [-s servidor] comando

DESCRIPCIÓN

nsd-control realiza la administración remota del servidor DNS nsd(8). Lee el archivo de configuración, se contacta con el servidor nsd a través de SSL, envía el comando y muestra el resultado. Los comandos que requieren una recarga se ponen en cola y el resultado indica que el comando fue aceptado.

Las opciones disponibles son:

-h
Muestra la versión y la ayuda de las opciones de la línea de comandos.
-c archivo_cfg
El archivo de configuración a leer con los ajustes. Si no se proporciona, se utiliza el archivo de configuración predeterminado //etc/nsd/nsd.conf.
-s servidor[@puerto]
Dirección IPv4 o IPv6 del servidor a contactar. Si no se proporciona, la dirección se lee del archivo de configuración.

COMANDOS

Hay varios comandos que el servidor entiende.

start
Inicia el servidor. Simplemente ejecuta nsd(8). El ejecutable nsd no se busca en la variable de entorno PATH. En su lugar, se utiliza la ubicación predeterminada relativa al prefijo de instalación especificado en tiempo de compilación. La ubicación del ejecutable puede ser anulada estableciendo NSD_PATH en el entorno. Se inicia con el archivo de configuración especificado mediante -c o el archivo de configuración predeterminado.
stop
Detiene el servidor. El demonio del servidor se sale.
reload [<zona>]
Recarga los archivos de zona y reabre el archivo de registro. Sin argumento, lee los archivos de zona modificados. Con argumento, lee el archivo de zona para la zona dada y lo carga.
reconfig
Recarga nsd.conf y aplica los cambios en las claves TSIG y patrones de configuración, y aplica los cambios para agregar y eliminar zonas que se mencionan en la configuración. No se aplican otros cambios, como la dirección IP y el puerto de escucha y el chroot, tampoco se aplican las estadísticas por zona. Las actualizaciones de patrones significan que las opciones de configuración para las zonas (request-xfr, zonefile, notify, ...) se actualizan. También hay nuevos patrones disponibles para usar con el comando addzone.
repattern
Igual que la opción reconfig.
log_reopen
Reabre el archivo de registro, para rotar los registros que quieren mover el archivo de registro y crear un nuevo archivo de registro. El registro también se puede reabrir con kill -HUP (que también recarga todos los archivos de zona).
status
Muestra el estado del servidor. Código de salida 3 si no se está ejecutando (la conexión al puerto es rechazada), 1 en caso de error, 0 si se está ejecutando.
stats
Muestra una secuencia de líneas con formato nombre=valor con información de estadísticas, requiere que NSD esté compilado con esta opción habilitada.
stats_noreset
Igual que stats, pero no pone los contadores a cero.
addzone <nombre_de_zona> <nombre_de_patrón>
Agrega una nueva zona al servidor en ejecución. La zona se agrega al archivo zonelist en disco, por lo que permanece después de un reinicio. El nombre del patrón determina las opciones para la nueva zona. Para zonas secundarias se intenta inmediatamente una transferencia de zona. Para zonas con un archivo de zona, se intenta leer el archivo de zona.
delzone <nombre_de_zona>
Elimina la zona del servidor en ejecución. La zona se elimina del archivo zonelist en disco, del archivo nsd.db y de la memoria. Si tenía un archivo de zona, este permanece (pero puede estar desactualizado). Las zonas configuradas dentro del propio nsd.conf no se pueden eliminar de esta manera porque el demonio no escribe en el archivo nsd.conf, necesitas agregar dichas zonas al archivo zonelist para poder eliminarlas con el comando delzone.
changezone <nombre_de_zona> <nombre_de_patrón>
Cambia una zona para que use el patrón para las opciones. La zona se elimina y se agrega en una sola operación, cambiándola para que use el nuevo patrón para las opciones de la zona. Las zonas configuradas en nsd.conf no se pueden cambiar de esta manera, en su lugar edita nsd.conf (o el archivo incluido en nsd.conf) y ejecuta reconfig.
addzones
Agrega zonas leídas desde la entrada estándar de nsd-control. La entrada se lee por línea, con nombre espacio nombre_patrón en una línea. Para adiciones en bloque.
delzones
Elimina zonas leídas desde la entrada estándar de nsd-control. La entrada es un nombre por línea. Para eliminaciones en bloque.
write [<zona>]
Escribe los archivos de zona en disco, o el archivo de zona dado en disco. Se escriben las zonas que han cambiado (mediante AXFR o IXFR), o si el archivo de zona aún no se ha creado, se crea. Los componentes de directorio de la ruta del archivo de zona se crean si es necesario. Con argumento, esa zona se escribe si fue modificada; sin argumento, se escriben todas las zonas modificadas.
notify [<zona>]
Envía mensajes NOTIFY a los servidores secundarios. Envía a las direcciones IP configuradas en las listas 'notify:' para las zonas primarias alojadas en este servidor. Normalmente NSD envía mensajes NOTIFY inmediatamente cuando se actualiza una serie de zona primaria. Si se proporciona una zona, se envían notificaciones para esa zona. Se supone que estos servidores secundarios iniciarán una solicitud de transferencia de zona más tarde (a este servidor u a otro primario), esto se puede permitir a través de la configuración de la lista ACL 'provide-xfr:'. Con argumento, se procesa esa zona; sin argumento, se procesan todas las zonas.
transfer [<zona>]
Intenta actualizar las zonas secundarias que se alojan en este servidor contactando a las primarias. Las primarias se configuran a través de las listas 'request-xfr:'. Si se proporciona una zona, esa zona se actualiza. Normalmente NSD recibe una NOTIFY de las primarias (configuradas a través de la lista ACL 'allow-notify:') de que se debe transferir una nueva serie de zona. Para zonas sin contenido, NSD puede haber dejado de preguntar a menudo porque las primarias no respondieron, pero este comando restablecerá el retroceso a su tiempo de espera inicial, para reintentos frecuentes. Con argumento, se transfiere esa zona; sin argumento, se transfieren todas las zonas.
force_transfer [<zona>]
Fuerza la actualización de las zonas secundarias alojadas en este servidor. Incluso si el servidor primario tiene el mismo número de serie de la zona, se realiza una AXFR completa para obtenerla. Si desea utilizar IXFR y verificar que el número de serie aumenta, use el comando 'transfer'. Con argumento, se transfiere esa zona; sin argumento, se transfieren todas las zonas.
zonestatus [<zona>]
Imprime el estado de la zona, los números de serie y desde cuándo se han adquirido. También imprime la acción de notificación (a qué servidor) y la transferencia de zona (y de qué primaria) si hay actividad en este momento. El estado de la zona se imprime como: 'primary' (zonas primarias), 'ok' (zona secundaria actualizada), 'expired' (zona secundaria ha caducado), 'refreshing' (zona secundaria tiene transferencias activas). Los números de serie impresos son el 'served-serial' (actualmente activo), el 'commit-serial' (en recarga), el 'notified-serial' (recibió notificación, ocupado descargando los datos). Los números de serie solo se imprimen si dicho número de serie está disponible. Con argumento, se imprime esa zona; sin argumento, se imprimen todas las zonas.
serverpid
Imprime el PID del proceso del servidor. Esto se utiliza para estadísticas (y solo funciona cuando NSD está compilado con estadísticas habilitadas). Este pid no es para enviar señales de Unix, usa el pid de nsd.pid para eso, ese pid también es estable.
verbosity <número>
Cambia la verbosidad del registro.

GESTIÓN DE CLAVES TSIG

print_tsig [<nombre_clave>]
Imprime el secreto y el algoritmo para la clave TSIG con ese nombre. O lista todas las claves tsig con su nombre, secreto y algoritmo.
update_tsig <nombre> <secreto>
Cambia la clave TSIG existente con el nombre por el nuevo secreto. El secreto es una cadena codificada en base64. Los cambios son solo en memoria y se pierden en el próximo reinicio; para cambios permanentes, edita el archivo nsd.conf o un archivo incluido en él.
add_tsig <nombre> <secreto> [algo]
Añade una nueva clave TSIG con el nombre, secreto y algoritmo dados. Sin algoritmo, se usa un algoritmo predeterminado (hmac-sha256). El secreto es una cadena codificada en base64. Los cambios son solo en memoria y se pierden en el próximo reinicio; para cambios permanentes, edita el archivo nsd.conf o un archivo incluido en él.
assoc_tsig <zona> <nombre_clave>
Asocia la zona con el tsig dado. Las listas de control de acceso para notify, allow-notify, provide-xfr y request-xfr se ajustan para usar la clave dada.
del_tsig <nombre_clave>
Elimina la clave TSIG con el nombre dado. Imprime un error si la clave todavía está en uso por alguna zona. Los cambios son solo en memoria y se pierden en el próximo reinicio; para cambios permanentes, edita el archivo nsd.conf o un archivo incluido en él.
add_cookie_secret <secreto>
Añade o reemplaza un secreto de cookie de forma persistente. <secreto> debe ser una cadena hexadecimal de 128 bits.

Los secretos de cookie pueden ser de dos tipos: activo o en preparación (staging). Los secretos de cookie activos se utilizan para crear DNS Cookies, pero la verificación de una DNS Cookie tiene éxito con cualquiera de los secretos de cookie activos o en preparación. El estado de los secretos de cookie actuales se puede ver con el comando print_cookie_secrets.

Cuando aún no hay secretos de cookie configurados, el <secreto> se añade como activo. Si ya existe un secreto de cookie activo, el <secreto> se añade como en preparación o reemplaza un secreto en preparación existente.

Para "rotar" un secreto de cookie utilizado en un conjunto anycast. El nuevo secreto debe añadirse como secreto en preparación a todos los nodos del conjunto anycast. Cuando todos los nodos puedan verificar las DNS Cookies con el nuevo secreto, el nuevo secreto puede activarse con el comando activate_cookie_secret. Después de que todos los nodos tengan el nuevo secreto activo durante al menos una hora, el secreto anterior puede eliminarse con el comando drop_cookie_secret.

La persistencia se logra escribiendo en un archivo que, si está configurado con la opción cookie-secret-file en la sección server del archivo de configuración. El valor predeterminado para ese archivo es: //var/db/nsd/cookiesecrets.txt.

drop_cookie_secret
Elimina el secreto de cookie en preparación.
activate_cookie_secret
Hace que el secreto de cookie en preparación actual se convierta en activo, y el secreto de cookie activo actual se convierta en en preparación.
print_cookie_secrets
Muestra los secretos de cookie configurados actualmente con su estado.

CÓDIGO DE SALIDA

El programa nsd-control sale con el código de estado 1 en caso de error, 0 en caso de éxito.

CONFIGURACIÓN

La configuración requiere un certificado autofirmado y claves privadas tanto para el servidor como para el cliente. El script nsd-control-setup genera estos en el directorio de ejecución predeterminado, o con -d en otro directorio. Si cambias los permisos de control de acceso en los archivos de clave, puedes decidir quién puede usar nsd-control; por defecto, el propietario y el grupo, pero no todos los usuarios. El script conserva las claves privadas presentes en el directorio. Después de ejecutar el script como root, activa control-enable en nsd.conf.

CONTADORES DE ESTADÍSTICAS

El comando stats muestra una serie de contadores de estadísticas.

num.queries
número de consultas recibidas (suma de consultas tls, tcp y udp).
serverX.queries
número de consultas manejadas por el proceso del servidor. El número de procesos de servidor se establece con la sentencia de configuración server-count.
time.boot
tiempo de actividad en segundos desde que se inició el servidor. Con segundos fraccionarios.
time.elapsed
tiempo transcurrido desde el último informe de estadísticas, en segundos. Con segundos fraccionarios. Puede ser cero si se consulta rápidamente y el comando de estadísticas anterior reinicia los contadores, de modo que el siguiente reciba un informe completamente cero y con tiempo transcurrido cero.
size.db.disk
tamaño de nsd.db en disco, en bytes.
size.db.mem
tamaño de la base de datos DNS en memoria, en bytes.
size.xfrd.mem
tamaño de memoria para transferencias de zonas y notificaciones en el proceso xfrd, excluye datos TSIG, en bytes.
size.config.disk
tamaño del archivo zonelist en disco, excluye el tamaño de nsd.conf, en bytes.
size.config.mem
tamaño de los datos de configuración en memoria, se mantiene dos veces en los procesos server y xfrd, en bytes.
num.type.X
número de consultas con este tipo de consulta.
num.opcode.X
número de consultas con este opcode.
num.class.X
número de consultas con esta clase de consulta.
num.rcode.X
número de respuestas que llevaron este código de retorno.
num.edns
número de consultas con EDNS OPT.
num.ednserr
número de consultas que fallaron el análisis EDNS.
num.udp
número de consultas sobre UDP ip4.
num.udp6
número de consultas sobre UDP ip6.
num.tcp
número de conexiones sobre TCP ip4.
num.tcp6
número de conexiones sobre TCP ip6.
num.tls
número de conexiones sobre TLS ip4. Las consultas TLS no forman parte de num.tcp.
num.tls6
número de conexiones sobre TLS ip6. Las consultas TLS no forman parte de num.tcp6.
num.answer_wo_aa
número de respuestas con rcode NOERROR y sin el flag AA; esto incluye las referencias.
num.rxerr
número de consultas para las cuales falló la recepción.
num.txerr
número de respuestas para las cuales falló la transmisión.
num.raxfr
número de solicitudes AXFR de clientes (que recibieron respuesta).
num.rixfr
número de solicitudes IXFR de clientes (que recibieron respuesta).
num.truncated
número de respuestas con el flag TC establecido.
num.dropped
número de consultas que fueron descartadas porque fallaron la comprobación de sanidad.
zone.primary
número de zonas primarias servidas. Estas son zonas sin entradas 'request-xfr:'. También se muestra como 'zone.master' por compatibilidad con versiones anteriores.
zone.secondary
número de zonas secundarias servidas. Estas son zonas con entradas 'request-xfr'. También se muestra como 'zone.slave' por compatibilidad con versiones anteriores.

NAME

nsd-control — tool to control the NSD daemon

SYNOPSIS

nsd-control [-a socket] [-c configfile] [command]

DESCRIPTION

nsd-control is a tool to remotely control the NSD(8) daemon. It sends commands to the nsd daemon via a control socket. This control socket can be specified with the -a option or in the nsd.conf configuration file under the control: directive. The nsd daemon must be configured to listen on this socket. The nsd daemon checks that the user sending the command is the same user that owns the nsd process and has appropriate permissions to access the socket.

COMMANDS

The following commands are available:

start
Start the NSD daemon. If the daemon is already running, it will not start again.
stop
Stop the NSD daemon.
reload
Reload the zone data and configuration. This reads the zone data again and reloads it into the running NSD daemon. Configuration changes can also be applied with this command.
recurve [zone]
For all zones or the specified zone, expire all cached records and trigger a reload from the authoritative server.
stats
Print statistics counters. The counters are reset after printing.
stats_noreset
Print statistics counters. The counters are not reset after printing.
zone_reload [zone]
Reload the specified zone or all zones. This command forces NSD to reload the zone data from its zone files.
zone_setnon authoritative [zone]
Set the specified zone or all zones to non-authoritative. This means that NSD will no longer answer queries for these zones. This is useful when NSD is used as a secondary server and the zone is not yet loaded.
zone_setauthoritative [zone]
Set the specified zone or all zones to authoritative. This means that NSD will answer queries for these zones. This is the default state.
ping
Check if the NSD daemon is running and responding. It returns the same response as the nsd daemon sends upon receiving the command.
verbosity [level]
Set the verbosity level for the NSD daemon. Level 0 means no logging. Level 1 means errors and warnings. Level 2 means basic service information. Level 3 means detailed service information. Level 4 means debug information.
remote [ip address]
Set the remote IP address to allow queries from. If no IP address is given, all IP addresses are allowed.
local [ip address]
Set the local IP address to bind to. If no IP address is given, all IP addresses are used.
dumpdb [zone]
Dump the database for the specified zone or all zones. This dumps all records that NSD has stored for the zone.
quit
Stop the NSD daemon. Same as stop.

EXIT CODE

The exit code is 0 if the command was successful, and non-zero otherwise.

SET UP

To use nsd-control, the nsd daemon must be configured to listen on a control socket. This is done by adding the following line to the nsd.conf configuration file:

control: socket:/path/to/nsd.control

The path to the socket can be anything, but it is recommended to use a path like /run/nsd/nsd.control or /var/run/nsd.control.

The permissions of the socket file must be set correctly so that only the user running nsd and the user running nsd-control can access it. Typically, this means creating the socket file with nsd and setting its ownership to the user running nsd, and then using nsd-control as that user or as root.

If nsd-control is not run as root or as the user running nsd, you might need to adjust the permissions of the socket file or its containing directory to allow access.

STATISTIC COUNTERS

The following statistics are available:

rx_total
Total number of incoming messages.
tx_total
Total number of outgoing messages.
rx_drop
Number of incoming messages dropped.
tx_drop
Number of outgoing messages dropped.
rx_query
Number of incoming queries.
tx_answer
Number of outgoing answers.
rx_update
Number of incoming zone updates.
tx_update
Number of outgoing zone updates.
rx_notify
Number of incoming NOTIFY messages.
tx_notify
Number of outgoing NOTIFY messages.
rx_axfr
Number of incoming AXFR requests.
tx_axfr
Number of outgoing AXFR responses.
answer_nxdomain
Number of NXDOMAIN answers.
answer_ SERVFAIL
Number of SERVFAIL answers.
answer_nodata
Number of NOERROR NODATA answers.
answer_other
Number of other answers.
udp_rx
Number of UDP queries received.
udp_tx
Number of UDP answers sent.
tcp_rx
Number of TCP queries received.
tcp_tx
Number of TCP answers sent.
tcp_sessions
Number of TCP sessions.
recursion_depth
Current recursion depth.
recursion_count
Total number of recursions performed.
cache_hits
Number of cache hits.
cache_misses
Number of cache misses.
zone_counts
Number of zones loaded.
signer_count
Number of active signers.
signer_expired
Number of expired signers.
