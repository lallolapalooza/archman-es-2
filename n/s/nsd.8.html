NOMBRE

nsd - Demonio del Servidor de Nombres (NSD) versión 4.12.0.

SINOPSIS

nsd [-4] [-6] [-a direccion-ip[@puerto]] [-c archivo-config] [-d] [-h] [-i identidad] [-I nsid] [-l archivo-log] [-N numero-servidores] [-n numero-tcp-no-actual] [-P archivo-pid] [-p puerto] [-s segundos] [-t directorio-chroot] [-u nombre-usuario] [-V nivel] [-v]

DESCRIPCIÓN

NSD es una implementación completa de un servidor de nombres DNS autoritativo. Al inicio, NSD leerá el archivo de configuración y se pondrá en segundo plano para responder a las consultas en el puerto 53 o en un puerto diferente especificado con la opción -p puerto. Por defecto, NSD se enlazará a todas las interfaces locales disponibles. Utilice la opción -a direccion-ip[@puerto] para especificar una única dirección de interfaz particular a la que enlazarse. Si esta opción se da más de una vez, NSD enlazará sus sockets UDP y TCP a todas las direcciones IP especificadas por separado. Si IPv6 está habilitado cuando NSD fue compilado, también se puede especificar una dirección IPv6.

OPCIONES

Todas las opciones se pueden especificar en el archivo de configuración (argumento -c), excepto las opciones -v y -h. Si las opciones se especifican en la línea de comandos, las opciones en la línea de comandos tienen precedencia sobre las opciones en el archivo de configuración.

Normalmente, NSD debería iniciarse con el comando `nsd-control(8) start` invocado desde un script de /etc/rc.d/nsd.sh o similar al inicio del sistema operativo.

-4
Solo escuchar conexiones IPv4.
-6
Solo escuchar conexiones IPv6.
-a direccion-ip[@puerto]
Escuchar en la direccion-ip especificada. La direccion-ip debe ser especificada en formato numérico (usando la notación estándar IPv4 o IPv6). Opcionalmente, se puede dar un número de puerto. Esta bandera se puede especificar varias veces para escuchar en múltiples direcciones IP. Si esta bandera no se especifica, NSD escucha en la interfaz comodín.
-c archivo-config
Leer el archivo-config especificado en lugar del predeterminado //etc/nsd/nsd.conf. Para la descripción del formato, ver nsd.conf(5).
-d
No hacer fork, permanecer en primer plano.
-h
Imprimir información de ayuda y salir.
-i identidad
Devolver la identidad especificada al ser consultado por CH TXT ID.SERVER (Esta opción se usa para determinar qué servidor está respondiendo a las consultas cuando son anycast). El valor predeterminado es el nombre devuelto por gethostname(3).
-I nsid
Añadir el nsid especificado a la sección EDNS de la respuesta cuando se consulta con un paquete habilitado para NSID EDNS. Como una secuencia de caracteres hexadecimales o con el prefijo ascii_ y luego una cadena ascii.
-l archivo-log
Registrar mensajes en el archivo-log especificado. El valor predeterminado es registrar en stderr y syslog. Si se especifica zonesdir: en el archivo de configuración, esta ruta puede ser relativa a ese directorio.
-N numero
Iniciar numero servidores NSD. El valor predeterminado es 1. Iniciar más de un servidor solo es útil en máquinas con múltiples CPUs y/o adaptadores de red.
-n numero
El numero máximo de conexiones TCP concurrentes que cada servidor puede manejar. El valor predeterminado es 100.
-P archivo-pid
Usar el archivo-pid especificado en lugar del predeterminado específico de la plataforma, que es mayormente /run/nsd/nsd.pid. Si se especifica un zonesdir: en el archivo de configuración, esta ruta puede ser relativa a ese directorio.
-p puerto
Responder a las consultas en el puerto especificado. Normalmente este es el puerto 53.
-s segundos
Producir un volcado de estadísticas cada segundos segundos. Esto es equivalente a enviar SIGUSR1 al demonio periódicamente.
-t chroot
Especifica un directorio al que hacer chroot al inicio. Esta opción requiere que te asegures de que el socket syslogd(8) apropiado (por ejemplo, chrootdir /dev/log) esté disponible, de lo contrario NSD no producirá ninguna salida de registro.
-u nombre-usuario
Soltar los privilegios de usuario y grupo a los de nombre-usuario después de enlazar el socket. El nombre-usuario debe ser uno de: nombre de usuario, id, o id.gid. Por ejemplo: nsd, 80, o 80.80.
-V nivel
Este valor especifica el nivel de verbosidad para el registro (no de depuración). El valor predeterminado es 0.
-v
Imprimir el número de versión de NSD en la salida de error estándar y salir.

NSD reacciona a las siguientes señales:

SIGTERM

Dejar de responder a las consultas, apagar y salir normalmente.
SIGHUP

Reabrir el archivo de registro (ayuda a la rotación) y opcionalmente actualizar las claves TSIG y las zonas.
SIGUSR1

Volcar estadísticas al estilo BIND8 en el registro. Ignorado de lo contrario.

ARCHIVOS

/run/nsd/nsd.pid
el id del proceso del servidor de nombres.
//etc/nsd/nsd.conf
archivo de configuración predeterminado de NSD

DIAGNÓSTICOS

NSD registrará todos los problemas a través de la utilidad de sistema estándar daemon de syslog(8), a menos que se especifique la opción -d.

VER TAMBIÉN

nsd.conf(5), nsd-checkconf(8), nsd-control(8)
