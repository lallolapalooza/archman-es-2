NOMBRE

nsupdate - utilidad de actualización dinámica de DNS

SINOPSIS

nsupdate [-d] [-D] [-i] [-L nivel] [ [-g] | [-o] | [-l] | [-y [hmac:]nombre_clave:secreto] | [-k archivo_clave] ] [ [-S] [-K archivo_clave_tls] [-E archivo_certificado_tls] [-A archivo_ca_tls] [-H nombre_host_tls] [-O] ] [-t tiempo_espera] [-u tiempo_espera_udp] [-r reintentos_udp] [-v] [-T] [-P] [-V] [ [-4] | [-6] ] [archivo]

DESCRIPCIÓN

nsupdate se utiliza para enviar solicitudes de actualización dinámica de DNS, según se define en RFC 2136 https://datatracker.ietf.org/doc/html/rfc2136.html, a un servidor de nombres. Esto permite agregar o eliminar registros de recursos de una zona sin editar manualmente el archivo de zona. Una única solicitud de actualización puede contener solicitudes para agregar o eliminar más de un registro de recursos.

Las zonas que están bajo control dinámico a través de nsupdate o un servidor DHCP no deben editarse manualmente. Las ediciones manuales podrían entrar en conflicto con las actualizaciones dinámicas y provocar la pérdida de datos.

Los registros de recursos que se agregan o eliminan dinámicamente con nsupdate deben estar en la misma zona. Las solicitudes se envían al servidor principal de la zona, identificado por el campo MNAME del registro SOA de la zona.

Se pueden utilizar firmas de transacciones para autenticar las actualizaciones dinámicas de DNS. Estas utilizan el tipo de registro de recurso TSIG descrito en RFC 2845 https://datatracker.ietf.org/doc/html/rfc2845.html, el registro SIG(0) descrito en RFC 2535 https://datatracker.ietf.org/doc/html/rfc2535.html y RFC 2931 https://datatracker.ietf.org/doc/html/rfc2931.html, o GSS-TSIG como se describe en RFC 3645 https://datatracker.ietf.org/doc/html/rfc3645.html.

TSIG se basa en un secreto compartido que solo deben conocer nsupdate y el servidor de nombres. Por ejemplo, las sentencias adecuadas de key y server se agregan a /etc/named.conf para que el servidor de nombres pueda asociar la clave secreta y el algoritmo apropiados con la dirección IP de la aplicación cliente que utiliza la autenticación TSIG. ddns-confgen <#std-iscman-ddns-confgen> puede generar fragmentos de configuración adecuados. nsupdate utiliza las opciones -y o -k para proporcionar el secreto compartido TSIG; estas opciones son mutuamente excluyentes.

SIG(0) utiliza criptografía de clave pública. Para usar una clave SIG(0), la clave pública debe almacenarse en un registro KEY en una zona servida por el servidor de nombres.

GSS-TSIG utiliza credenciales de Kerberos. El modo estándar GSS-TSIG se activa con el indicador -g. Una variante no conforme a los estándares de GSS-TSIG utilizada por Windows 2000 se puede activar con el indicador -o.

OPCIONES

-4
Esta opción establece el uso de solo IPv4.
-6
Esta opción establece el uso de solo IPv6.
-A archivo_ca_tls
Esta opción especifica el archivo de las autoridades de certificación (CA) (en formato PEM) para verificar el certificado TLS del servidor remoto cuando se utiliza DNS-over-TLS (DoT), para lograr TLS estricto o mutuo. Cuando se utiliza, anulará los certificados del almacén de certificados global, que de lo contrario se utilizan por defecto cuando se habilita -S. Esta opción no se puede usar junto con -O e implica -S.
-C
Anula el archivo resolv.conf predeterminado. Esto está destinado únicamente a pruebas.
-d
Esta opción activa el modo de depuración, que proporciona información de seguimiento sobre las solicitudes de actualización que se realizan y las respuestas recibidas del servidor de nombres.
-D
Esta opción activa el modo de depuración adicional.
-E archivo_certificado_tls
Esta opción establece el archivo de certificados para la autenticación del transporte DNS-over-TLS (DoT) al servidor remoto. Se espera que el archivo de cadena de certificados esté en formato PEM. Esta opción implica -S y solo se puede usar con -K.
-g
Esta opción habilita el modo GSS-TSIG estándar.
-H nombre_host_tls
Esta opción hace que nsupdate utilice el nombre de host proporcionado durante la verificación del certificado TLS del servidor remoto. De lo contrario, se utiliza el nombre del servidor DNS. Esta opción implica -S.
-i
Esta opción fuerza el modo interactivo, incluso cuando la entrada estándar no es una terminal.
-k archivo_clave
Esta opción indica el archivo que contiene la clave de autenticación TSIG. Los archivos de clave pueden tener dos formatos: un único archivo que contiene una sentencia key en formato named.conf <#std-iscman-named.conf>, que puede ser generado automáticamente por ddns-confgen <#std-iscman-ddns-confgen>; o un par de archivos cuyos nombres tienen el formato K{nombre}.+157.+{aleatorio}.key y K{nombre}.+157.+{aleatorio}.private, que pueden ser generados por dnssec-keygen <#std-iscman-dnssec-keygen>. La opción -k también se puede usar para especificar una clave SIG(0) utilizada para autenticar las solicitudes de actualización dinámica de DNS. En este caso, la clave especificada no es una clave HMAC-MD5.
-K archivo_clave_tls
Esta opción establece el archivo de clave para el cifrado autenticado del transporte DNS-over-TLS (DoT) con el servidor remoto. Se espera que el archivo de clave privada esté en formato PEM. Esta opción implica -S y solo se puede usar con -E.
-l
Esta opción establece el modo solo de host local, que establece la dirección del servidor en localhost (deshabilitando el server para que la dirección del servidor no pueda ser anulada). Las conexiones al servidor local utilizan una clave TSIG encontrada en /var/run/session.key, que es generada automáticamente por named <#std-iscman-named> si alguna zona primary local tiene establecida la update-policy a local. La ubicación de este archivo de clave puede ser anulada con la opción -k.
-L nivel
Esta opción establece el nivel de depuración de registro. Si es cero, el registro está deshabilitado.
-o
Esta opción está obsoleta. Anteriormente, habilitaba una variante no conforme a los estándares de GSS-TSIG que utilizaba Windows 2000. Dado que ese sistema operativo ya ha superado su vida útil, esta opción ahora se trata como un sinónimo de -g.
-O
Esta opción habilita TLS Oportunista. Cuando se utiliza, el certificado TLS del par remoto no será verificado. Esta opción debe usarse solo con fines de depuración, y no se recomienda su uso en producción. Esta opción no se puede usar junto con -A e implica -S.
-p puerto
Esta opción establece el puerto a utilizar para las conexiones a un servidor de nombres. El valor predeterminado es 53.
-P
Esta opción imprime la lista de tipos de registros de recursos privados específicos de BIND cuyo formato es entendido por nsupdate. Ver también la opción -T.
-r reintentos_udp
Este es el número máximo de reintentos de solicitud de actualización por UDP antes de que se considere que la solicitud ha fallado.
-S
Esta opción habilita DNS-over-TLS (DoT) para las conexiones con el servidor remoto. La verificación del certificado del servidor es necesaria, a menos que se especifique lo contrario mediante las opciones -O o -H.
-t tiempo_espera
Este es el tiempo máximo en segundos que se esperará una respuesta a una solicitud de actualización por TCP o UDP antes de que se considere que la solicitud ha fallado.
-T
Esta opción imprime la lista de todos los tipos de registros de recursos cuyo formato es entendido por nsupdate. Ver también la opción -P.
-u tiempo_espera_udp
Este es el tiempo de espera en segundos para las respuestas de las consultas UDP. El valor predeterminado es 3 segundos.
-v
Esta opción habilita el modo detallado, que proporciona información más detallada que el modo de depuración.
-V
Esta opción imprime la versión de nsupdate y sale.
-y [hmac:]nombre_clave:secreto
Esta opción indica que se utilizará una clave de autenticación TSIG. El algoritmo se especifica como hmac: seguido del nombre de la clave y el secreto. El algoritmo predeterminado es hmac-md5.

ARCHIVOS

/etc/resolv.conf
Contiene la información de nombres de dominio y servidores DNS. nsupdate intentará leer este archivo para determinar la información del servidor DNS y la zona predeterminada.
/etc/named.conf
Archivos de configuración para el servidor DNS BIND. Se pueden usar sentencias de clave y servidor para configurar la autenticación y los servidores DNS.

VER TAMBIÉN

named(8), RFC 2136, RFC 2845, RFC 2535, RFC 2931, RFC 3645.

-r udpretries
Esta opción establece el número de reintentos UDP. El valor predeterminado es 3. Si es cero, solo se realiza una solicitud de actualización.
-S
Esta opción indica si se debe usar DNS-over-TLS (DoT) al consultar los servidores de nombres especificados con la sintaxis server nombre_servidor puerto en el archivo de entrada, y el servidor primario descubierto a través de una solicitud SOA. Cuando se utilizan las opciones -K y -E, se utiliza el par de certificado de cliente TLS y clave privada especificado para la autenticación (TLS mutuo). Esta opción implica -v.
-t timeout
Esta opción establece el tiempo máximo que puede tardar una solicitud de actualización antes de ser abortada. El valor predeterminado es 300 segundos. Si es cero, el tiempo de espera se deshabilita para el modo TCP. Para el modo UDP, la opción -u tiene prioridad sobre esta opción, a menos que la opción -u se establezca en cero, en cuyo caso el intervalo se calcula a partir del intervalo de tiempo de espera -t y el número de reintentos UDP. Para el modo UDP, el tiempo de espera no se puede deshabilitar y se redondeará al segundo superior si tanto -t como -u se establecen en cero.
-T
Esta opción imprime la lista de tipos de registros de recursos estándar de IANA cuyo formato es entendido por nsupdate. nsupdate sale después de que se imprimen las listas. La opción -T se puede combinar con la opción -P.

Se pueden introducir otros tipos usando TYPEXXXXX donde XXXXX es el valor decimal del tipo sin ceros iniciales. Los rdata, si están presentes, se analizan utilizando el formato rdata DESCONOCIDO, (\\# longitud cadena_hexadecimal).

-u udptimeout
Esta opción establece el intervalo de reintento UDP. El valor predeterminado es 3 segundos. Si es cero, el intervalo se calcula a partir del intervalo de tiempo de espera y el número de reintentos UDP.
-v
Esta opción especifica que se debe usar TCP incluso para solicitudes de actualización pequeñas. Por defecto, nsupdate utiliza UDP para enviar solicitudes de actualización al servidor de nombres a menos que sean demasiado grandes para caber en una solicitud UDP, en cuyo caso se utiliza TCP. TCP puede ser preferible cuando se realiza un lote de solicitudes de actualización.
-V
Esta opción imprime el número de versión y sale.
-y [hmac:]nombre_clave:secreto
Esta opción establece la clave de autenticación TSIG literal. nombre_clave es el nombre de la clave y secreto es el secreto compartido codificado en base64. hmac es el nombre del algoritmo de clave; las opciones válidas son hmac-md5, hmac-sha1, hmac-sha224, hmac-sha256, hmac-sha384 o hmac-sha512. Si no se especifica hmac, el valor predeterminado es hmac-md5 o, si MD5 estaba deshabilitado, hmac-sha256.

NOTA: Se desaconseja el uso de la opción -y porque el secreto compartido se proporciona como argumento de línea de comandos en texto claro. Esto puede ser visible en la salida de ps1 o en un archivo de historial mantenido por el shell del usuario.

FORMATO DE ENTRADA

nsupdate lee la entrada de nombre_archivo o de la entrada estándar. Cada comando se proporciona en una única línea de entrada. Algunos comandos son para fines administrativos; otros son instrucciones de actualización o verificaciones de prerrequisitos sobre el contenido de la zona. Estas verificaciones establecen condiciones de que algún nombre o conjunto de registros de recursos (RRset) existe o está ausente de la zona. Estas condiciones deben cumplirse si la solicitud de actualización completa va a tener éxito. Las actualizaciones se rechazan si fallan las pruebas de las condiciones de prerrequisito.

Cada solicitud de actualización consta de cero o más prerrequisitos y cero o más actualizaciones. Esto permite que una solicitud de actualización adecuadamente autenticada proceda si algunos registros de recursos especificados están presentes o faltan en la zona. Una línea de entrada en blanco (o el comando send) hace que los comandos acumulados se envíen como una única solicitud de actualización de DNS dinámico al servidor de nombres.

Los formatos de comando y sus significados son los siguientes:

server nombre_servidor puerto
Este comando envía todas las solicitudes de actualización dinámica al servidor de nombres nombre_servidor. Cuando no se proporciona ninguna declaración de servidor, nsupdate envía actualizaciones al servidor primario de la zona correcta. El campo MNAME del registro SOA de esa zona identifica el servidor primario de esa zona. puerto es el número de puerto en nombre_servidor al que se envían las solicitudes de actualización dinámica. Si no se especifica ningún número de puerto, se utiliza el número de puerto DNS predeterminado de 53.

Nota:

Este comando no tiene ningún efecto cuando se utiliza GSS-TSIG.
local dirección puerto
Este comando envía todas las solicitudes de actualización dinámica utilizando la dirección local. Cuando no se proporciona ninguna declaración local, nsupdate envía actualizaciones utilizando una dirección y un puerto elegidos por el sistema. puerto también se puede utilizar para forzar que las solicitudes provengan de un puerto específico. Si no se especifica ningún número de puerto, el sistema asigna uno.
zone nombre_zona
Este comando especifica que todas las actualizaciones se realizarán en la zona nombre_zona. Si no se proporciona ninguna declaración de zona, nsupdate intenta determinar la zona correcta para actualizar basándose en el resto de la entrada.
class nombre_clase
Este comando especifica la clase predeterminada. Si no se especifica ninguna clase, la clase predeterminada es IN.
ttl segundos
Este comando especifica el tiempo de vida (TTL) predeterminado, en segundos, de los registros que se van a agregar. El valor none borra el TTL predeterminado.
key hmac:nombre_clave secreto
Este comando especifica que todas las actualizaciones deben firmarse con TSIG utilizando el par nombre_clave-secreto. Si se especifica hmac, establece el algoritmo de firma en uso. El valor predeterminado es hmac-md5; si MD5 estaba deshabilitado, el valor predeterminado es hmac-sha256. El comando key anula cualquier clave especificada en la línea de comandos a través de -y o -k.
gsstsig
Este comando utiliza GSS-TSIG para firmar las actualizaciones. Esto es equivalente a especificar -g en la línea de comandos.
oldgsstsig
Este comando está obsoleto y se eliminará en una futura versión. Anteriormente, hacía que nsupdate utilizara la versión de Windows 2000 de GSS-TSIG para firmar actualizaciones. Ahora se trata como un sinónimo de gsstsig.
realm [nombre_realm]
Al usar GSS-TSIG, este comando especifica el uso de nombre_realm en lugar del realm predeterminado en krb5.conf. Si no se especifica ningún realm, se borra el realm guardado.
check-names [booleano]
Este comando activa o desactiva el procesamiento de check-names en los registros que se van a agregar. Check-names no tiene ningún efecto en los prerrequisitos ni en los registros que se van a eliminar. Por defecto, el procesamiento de check-names está activado. Si el procesamiento de check-names falla, el registro no se agrega al mensaje UPDATE.
check-svbc [booleano]
Este comando activa o desactiva el procesamiento de check-svcb en los registros que se van a agregar. Check-svcb no tiene ningún efecto en los prerrequisitos ni en los registros que se van a eliminar. Por defecto, el procesamiento de check-svcb está activado. Si el procesamiento de check-svcb falla, el registro no se agrega al mensaje UPDATE.
lease tiempo [tiempoclave]
Establece la opción EDNS Update Lease (UL) en el valor tiempo y, opcionalmente, también establece el tiempo de vida de la clave en tiempoclave en segundos. Si tiempo es none, se borran los tiempos de vida.
prereq nxdomain nombre_dominio
Este comando requiere que no exista ningún registro de recursos de ningún tipo con el nombre nombre_dominio.
prereq yxdomain nombre_dominio
Este comando requiere que exista nombre_dominio (como al menos un registro de recursos, de cualquier tipo).
prereq nxrrset nombre_dominio clase tipo
Este comando requiere que no exista ningún registro de recursos del tipo, clase y nombre_dominio especificados. Si se omite la clase, se asume IN (Internet).
prereq yxrrset nombre_dominio clase tipo
Este comando requiere que exista un registro de recursos del tipo, clase y nombre_dominio especificados. Si se omite la clase, se asume IN (Internet).
prereq yxrrset nombre_dominio clase tipo datos
Con este comando, los datos de cada conjunto de prerrequisitos de esta forma que comparten un tipo, clase y nombre_dominio comunes se combinan para formar un conjunto de RRs. Este conjunto de RRs debe coincidir exactamente con el conjunto de RRs existente en la zona en el tipo, clase y nombre_dominio dados. Los datos se escriben en la representación de texto estándar de RDATA del registro de recursos.
update delete nombre_dominio ttl clase tipo datos
Este comando elimina cualquier registro de recursos llamado nombre_dominio. Si se proporcionan tipo y datos, solo se eliminan los registros de recursos coincidentes. Se asume la clase Internet si no se proporciona clase. El ttl se ignora y solo se permite por compatibilidad.
update add nombre_dominio ttl clase tipo datos
>
Este comando agrega un nuevo registro de recurso con el ttl, clase y datos especificados.
show
Este comando muestra el mensaje actual, que contiene todos los prerrequisitos y actualizaciones especificados desde el último envío.
send
Este comando envía el mensaje actual. Esto es equivalente a introducir una línea en blanco.
answer
Este comando muestra la respuesta.
debug
Este comando activa la depuración.
version
Este comando imprime el número de versión.
help
Este comando imprime una lista de comandos.

Las líneas que comienzan con un punto y coma (;) son comentarios y se ignoran.

EJEMPLOS

Los siguientes ejemplos muestran cómo se puede usar nsupdate para insertar y eliminar registros de recursos de la zona example.com. Observe que la entrada en cada ejemplo contiene una línea en blanco al final, para que un grupo de comandos se envíe como una única solicitud de actualización dinámica al servidor de nombres principal de example.com.

# nsupdate
> update delete oldhost.example.com A
> update add newhost.example.com 86400 A 172.16.1.1
> send

Se eliminan todos los registros A de oldhost.example.com y se agrega un registro A para newhost.example.com con la dirección IP 172.16.1.1. El registro recién agregado tiene un TTL de 1 día (86400 segundos).

# nsupdate
> prereq nxdomain nickname.example.com
> update add nickname.example.com 86400 CNAME somehost.example.com
> send

La condición de prerrequisito indica al servidor de nombres que verifique si existen registros de recursos de algún tipo para nickname.example.com. Si existen, la solicitud de actualización falla. Si este nombre no existe, se agrega un CNAME para él. Esto asegura que cuando se agrega el CNAME, no pueda entrar en conflicto con la regla de larga data en la RFC 1034 https://datatracker.ietf.org/doc/html/rfc1034.html de que un nombre no debe existir como ningún otro tipo de registro si existe como un CNAME. (La regla se ha actualizado para DNSSEC en la RFC 2535 https://datatracker.ietf.org/doc/html/rfc2535.html para permitir que los CNAME tengan registros RRSIG, DNSKEY y NSEC).

ERRORES

La clave TSIG se almacena de forma redundante en dos archivos separados. Esto es una consecuencia de que nsupdate utilice la biblioteca DST para sus operaciones criptográficas y puede cambiar en futuras versiones.
