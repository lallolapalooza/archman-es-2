NOMBRE

nss-resolve, libnss_resolve.so.2 - Resolución de nombres de host a través de systemd-resolved.service

SINOPSIS

libnss_resolve.so.2

DESCRIPCIÓN

nss-resolve es un módulo plug-in para el módulo GNU Name Service Switch (NSS) de la biblioteca GNU C (glibc) que le permite resolver nombres de host a través del servicio de resolución de nombres de red local systemd-resolved(8). Reemplaza al módulo plug-in nss-dns que resuelve tradicionalmente los nombres de host a través de DNS.

Para activar el módulo NSS, añada "resolve [!UNAVAIL=return]" a la línea que empieza por "hosts:" en /etc/nsswitch.conf. Específicamente, se recomienda colocar "resolve" al principio de la línea "hosts:" de /etc/nsswitch.conf. Debe estar antes de la entrada "files", ya que systemd-resolved soporta /etc/hosts internamente, pero con caché. Por el contrario, debe estar después de "mymachines", para dar a los nombres de host asignados a VMs y contenedores locales precedencia sobre los nombres recibidos a través de DNS. Finalmente, recomendamos colocar "dns" en algún lugar después de "resolve", para recurrir a nss-dns si systemd-resolved.service no está disponible.

Tenga en cuenta que systemd-resolved sintetizará registros recurso DNS en algunos casos, por ejemplo para "localhost" y el nombre de host local actual, consulte systemd-resolved(8) para obtener la lista completa. Esto duplica la funcionalidad de nss-myhostname(8), pero aún se recomienda (ver ejemplos a continuación) mantener nss-myhostname configurado en /etc/nsswitch.conf, para mantener esos nombres resolubles si systemd-resolved no está en ejecución.

Tenga en cuenta que nss-myhostname (y nss-resolve) también resuelven en la otra dirección — de direcciones IP adjuntas localmente a nombres de host. Si confía en que esa búsqueda sea proporcionada por DNS, es posible que desee ordenar las cosas de manera diferente.

La comunicación entre nss-resolve y systemd-resolved.service se realiza a través del socket AF_UNIX /run/systemd/resolve/io.systemd.Resolve.

VARIABLES DE ENTORNO

$SYSTEMD_NSS_RESOLVE_VALIDATE

Acepta un argumento booleano. Cuando es falso, se deshabilitará la validación criptográfica de registros recurso a través de DNSSEC. Esto puede ser útil para pruebas, o cuando se sabe que el tiempo del sistema no es fiable.

Añadido en la versión 250.

$SYSTEMD_NSS_RESOLVE_SYNTHESIZE

Acepta un argumento booleano. Cuando es falso, no se devolverán registros sintetizados, por ejemplo, para el nombre de host local. Consulte la sección REGISTROS SINTETIZADOS en systemd-resolved.service(8) para más información. Esto puede ser útil para consultar los registros recurso públicos "públicos", independientemente de la configuración de la máquina local.

Añadido en la versión 250.

$SYSTEMD_NSS_RESOLVE_CACHE

Acepta un argumento booleano. Cuando es falso, systemd-resolved(8) no utilizará la caché de registros consultados previamente.

Añadido en la versión 250.

$SYSTEMD_NSS_RESOLVE_ZONE

Acepta un argumento booleano. Cuando es falso, no se devolverán respuestas utilizando registros recurso LLMNR/mDNS públicos registrados localmente.

Añadido en la versión 250.

$SYSTEMD_NSS_RESOLVE_TRUST_ANCHOR

Acepta un argumento booleano. Cuando es falso, no se utilizarán respuestas que usen anclajes de confianza configurados localmente.

Añadido en la versión 250.

$SYSTEMD_NSS_RESOLVE_NETWORK

Acepta un argumento booleano. Cuando es falso, las respuestas se devolverán sin usar la red, es decir, desde fuentes locales o la caché en systemd-resolved(8).

Añadido en la versión 250.

EJEMPLO

Aquí tienes un ejemplo de archivo /etc/nsswitch.conf que habilita nss-resolve correctamente:

passwd:         files systemd
group:          files [SUCCESS=merge] systemd
shadow:         files systemd
gshadow:        files systemd
hosts:          mymachines resolve [!UNAVAIL=return] files myhostname dns
networks:       files
protocols:      db files
services:       db files
ethers:         db files
rpc:            db files
netgroup:       nis
