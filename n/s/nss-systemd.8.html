NOMBRE

nss-systemd, libnss_systemd.so.2 - Resolución de nombres de usuario y grupo de UNIX para la búsqueda de usuarios/grupos a través de Varlink

SINOPSIS

libnss_systemd.so.2

DESCRIPCIÓN

nss-systemd es un módulo de conexión para la funcionalidad del Conmutador de Servicio de Nombres (NSS) de la Biblioteca C de GNU (glibc), que proporciona resolución de nombres de usuario y grupo de UNIX para servicios que implementan la API de Búsqueda de Registros de Usuario/Grupo a través de Varlink[1], como el gestor de sistema y servicios systemd(1) (para su función DynamicUser=, consulte systemd.exec(5) para más detalles), systemd-homed.service(8) o systemd-machined.service(8).

Este módulo también garantiza que los usuarios y grupos root y nobody (es decir, los usuarios/grupos con los UID/GID 0 y 65534) permanezcan resolubles en todo momento, incluso si no están listados en /etc/passwd o /etc/group, o si estos archivos faltan.

Este módulo utiliza preferentemente systemd-userdbd.service(8) para resolver usuarios y grupos, pero también funciona sin el servicio en ejecución.

Para activar el módulo NSS, añada "systemd" a las líneas que comienzan con "passwd:", "group:", "shadow:" y "gshadow:" en /etc/nsswitch.conf.

Se recomienda colocar "systemd" después de la entrada "files" de las líneas de /etc/nsswitch.conf para que las asignaciones basadas en /etc/passwd, /etc/group, /etc/shadow y /etc/gshadow tengan prioridad.

REGISTROS ESTÁTICOS JSON DE USUARIO/GRUPO DROP-IN

Además de los registros de usuario/grupo adquiridos a través de las interfaces IPC de Varlink mencionadas anteriormente y las cuentas raíz y de usuario ficticio sintetizadas, este módulo también pone a disposición del sistema cuentas de usuario y grupo que se definen en archivos drop-in estáticos en los directorios /etc/userdb/, /run/userdb/, /run/host/userdb/ y /usr/lib/userdb/.

Este es un mecanismo simple para proporcionar registros estáticos de usuario y grupo a través de archivos drop-in JSON. Dichos registros de usuario deben definirse en el formato descrito por la especificación de Registros de Usuario JSON[2] y colocarse en uno de los directorios mencionados anteriormente bajo un nombre de archivo compuesto por el nombre de usuario con el sufijo .user, con un modo de acceso legible por todos. También se debe crear un enlace simbólico con el nombre del registro de usuario correspondiente a su UID formateado en decimal y con el sufijo .user, apuntando al archivo de registro principal, para permitir búsquedas tanto por nombre de usuario como por UID. Opcionalmente, se pueden proporcionar datos privilegiados de registros de usuario (por ejemplo, contraseñas de UNIX hasheadas) en un par de archivos complementarios separados con el sufijo .user-privileged. Los datos deben almacenarse en un archivo regular con el nombre del nombre de usuario, con el sufijo .user-privileged, y un enlace simbólico que apunte a él, con el nombre del UID numérico utilizado formateado en decimal con el mismo sufijo. Estos archivos complementarios no deben ser legibles por nadie más que root. Ejemplo:

-rw-r--r--. 1 root root  723 May 10 foobar.user
-rw-------. 1 root root  123 May 10 foobar.user-privileged
lrwxrwxrwx. 1 root root   19 May 10 4711.user -> foobar.user
lrwxrwxrwx. 1 root root   19 May 10 4711.user-privileged -> foobar.user-privileged

De manera similar, se pueden definir registros de grupo siguiendo el formato descrito en Registro de Grupo JSON[3], utilizando los sufijos de archivo .group y .group-privileged.

Los archivos de registro primario de usuario/grupo (es decir, aquellos con los sufijos .user y .group) no deben contener la sección "privileged" como se describe en las especificaciones. Los archivos de registro privilegiado de usuario/grupo (es decir, aquellos con los sufijos .user-privileged y .group-privileged) deben contener esta sección, exclusivamente.

Además de los dos tipos de archivos de registro de usuario y los dos tipos de archivos de registro de grupo, hay un quinto tipo de archivo que puede colocarse en los directorios buscados: archivos que indican la membresía de usuarios en grupos. Específicamente, para cada par de usuario/grupo donde el usuario deba ser miembro de un grupo, se debe crear un archivo llamado "nombredeusuario:nombredegrupo.membership", es decir, el nombre de usuario de UNIX textual, seguido de dos puntos, seguido del nombre de grupo de UNIX textual, con el sufijo ".membership". El contenido de estos archivos no se lee actualmente y los archivos deben crearse vacíos. La mera existencia de estos archivos es suficiente para afectar la membresía de un usuario/grupo. Si un programa proporciona archivos de registro de usuario y/o grupo en los directorios buscados, siempre debe crear también dichos archivos, tanto para membresías de grupo primarias como auxiliares.

Tenga en cuenta que los registros de usuario/grupo estáticos generalmente no anulan los registros en conflicto en /etc/passwd o /etc/group u otras bases de datos de cuentas. De hecho, antes de incorporar estos archivos, se debe tener un nivel razonable de cuidado para evitar conflictos de nombres de usuario/grupo y UID/GID.

El servicio systemd-userdb-load-credentials.service se ejecuta automáticamente al arrancar e instala estos archivos a partir de los registros de usuario pasados a través de credenciales del sistema. Consulte userdbctl(1) y systemd.system-credentials(7) para más detalles.

CONFIGURACIÓN EN /ETC/NSSWITCH.CONF

Aquí hay un ejemplo de archivo /etc/nsswitch.conf que habilita nss-systemd correctamente:

passwd:         files systemd
group:          files [SUCCESS=merge] systemd
shadow:         files systemd
gshadow:        files systemd
hosts:          mymachines resolve [!UNAVAIL=return] files myhostname dns
networks:       files
protocols:      db files
services:       db files
ethers:         db files
rpc:            db files
netgroup:       nis

nss-systemd.8.es

nss-systemd — Servicio de resolución de nombres de red para systemd

nss-systemd es un módulo NSS (Name Service Switch) que permite a las aplicaciones resolver nombres de usuario y grupo en el sistema utilizando las bases de datos de usuarios y grupos gestionadas por systemd.

SINOPSIS

/etc/nsswitch.conf

DESCRIPCIÓN

nss-systemd es un módulo NSS (Name Service Switch) que permite a las aplicaciones resolver nombres de usuario y grupo en el sistema utilizando las bases de datos de usuarios y grupos gestionadas por systemd. Esto incluye la resolución de nombres de usuario y grupo a partir de los siguientes orígenes:

  • Archivos de usuarios y grupos locales (/etc/passwd, /etc/group)

  • Usuarios y grupos gestionados por systemd-homed.service (véase systemd-homed.service(8))

  • Usuarios y grupos añadidos a través de archivos JSON estáticos (véase más abajo)

Cuando se configura en /etc/nsswitch.conf, nss-systemd se puede utilizar para complementar o reemplazar los módulos NSS existentes para las bases de datos de usuarios y grupos.

REGISTROS ESTÁTICOS DE USUARIO/GRUPO JSON DE INICIO FIJO

Es posible añadir registros de usuario y grupo estáticos a través de archivos JSON. Estos archivos deben colocarse en el directorio /usr/lib/userdb/ o /etc/userdb/ y tener la extensión .json. systemd-userdbd.service(8) es responsable de leer estos archivos y exponerlos a través de la API de NSS.

Los archivos JSON deben seguir las especificaciones de systemd.io/USER_GROUP_API.

1.
API de Usuarios y Grupos de systemd
https://systemd.io/USER_GROUP_API
2.
Registros de Usuario JSON
https://systemd.io/USER_RECORD
3.
Registro de Grupo JSON
https://systemd.io/GROUP_RECORD

CONFIGURACIÓN EN /ETC/NSSWITCH.CONF

Para usar nss-systemd, debes añadirlo a las líneas passwd, group y shadow en tu archivo /etc/nsswitch.conf. Una configuración típica podría parecerse a la siguiente:

passwd:     files systemd
group:      files systemd
shadow:     files systemd

El orden de los módulos es importante. En este ejemplo, files se consulta primero, seguido de systemd. Esto significa que los usuarios y grupos definidos en los archivos locales tendrán prioridad sobre los gestionados por systemd.

EJEMPLO: ASIGNACIONES PROPORCIONADAS POR SYSTEMD-MACHINED.SERVICE

El servicio systemd-machined.service expone información sobre usuarios y grupos de las máquinas de contenedor y virtuales gestionadas por machinectl. Cuando nss-systemd está configurado, esta información se puede consultar de la misma manera que los usuarios y grupos locales.

Por ejemplo, si tienes una máquina virtual llamada "mi-vm" con un usuario "usuario-vm" dentro, podrías ser capaz de resolver este usuario usando:

getent passwd usuario-vm

Esto devolverá la entrada del passwd para "usuario-vm" tal como la proporciona systemd-machined.service.

VER TAMBIÉN

nsswitch.conf(5), systemd-homed.service(8), systemd-machined.service(8), systemd-userdbd.service(8)

NOTAS

La funcionalidad de nss-systemd depende de que los servicios correspondientes de systemd estén activos y funcionando correctamente.

Los registros JSON estáticos proporcionan una forma flexible de añadir usuarios y grupos que no se gestionan a través de los métodos tradicionales o de systemd-homed. Es importante asegurarse de que los archivos JSON sean válidos y sigan las especificaciones para evitar problemas de resolución.
