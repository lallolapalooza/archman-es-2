nslcd.conf(5) Manual del Administrador del Sistema nslcd.conf(5)

NOMBRE

nslcd.conf - archivo de configuración para el demonio de nombres de servicio LDAP

DESCRIPCIÓN

El paquete nss-pam-ldapd permite que los servidores de directorio LDAP se utilicen como fuente principal de información de nombres de servicio. (La información de nombres de servicio incluye típicamente usuarios, hosts, grupos y otros datos similares almacenados históricamente en archivos planos o NIS).

El archivo nslcd.conf contiene la información de configuración para ejecutar nslcd (ver nslcd(8)). El archivo contiene opciones, una en cada línea, que definen cómo se mapean las búsquedas NSS y las acciones PAM a las búsquedas LDAP.

OPCIONES

OPCIONES DE EJECUCIÓN

threads NUM
Especifica el número de hilos a iniciar que pueden manejar solicitudes y realizar consultas LDAP. Cada hilo abre una conexión separada al servidor LDAP. El valor predeterminado es iniciar 5 hilos.
uid UID
Esto especifica el ID de usuario con el que se debe ejecutar el demonio. Esto puede ser un ID numérico o un valor simbólico. Si no se especifica ningún uid, no se intentará cambiar de usuario. Tenga en cuenta que debe utilizar valores que no necesiten LDAP para resolverse.
gid GID
Esto especifica el ID de grupo con el que se debe ejecutar el demonio. Esto puede ser un ID numérico o un valor simbólico. Si no se especifica ningún gid, no se intentará cambiar de grupo. Tenga en cuenta que debe utilizar valores que no necesiten LDAP para resolverse.
log ESQUEMA [NIVEL]
Esta opción controla la forma en que se realiza el registro. El argumento ESQUEMA puede ser none, syslog o un nombre de archivo absoluto. El argumento NIVEL es opcional y especifica el nivel de registro. El nivel de registro puede ser uno de: crit, error, warning, notice, info o debug. El nivel de registro predeterminado es info. Se registran todos los mensajes con el nivel de registro especificado o superior. Esta opción se puede proporcionar varias veces. Si se omite esta opción, se asume syslog info.

OPCIONES GENERALES DE CONEXIÓN

uri URI ...
Especifica la URI LDAP del servidor al que conectarse. El esquema URI puede ser ldap, ldapi o ldaps, especificando LDAP sobre TCP, ICP o SSL respectivamente (si es compatible con la biblioteca LDAP).

Alternativamente, se puede usar el valor DNS para intentar buscar el servidor utilizando registros SRV de DNS. Por defecto se utiliza el dominio actual, pero se puede consultar otro dominio utilizando la sintaxis DNS:DOMINIO. Para convertir los registros SRV para el puerto 389 en una URI ldaps://, se puede usar DNSLDAPS.

Cuando se usa el esquema ldapi, se debe usar %2f para escapar las barras (por ejemplo, ldapi://%2fvar%2frun%2fslapd%2fldapi/), aunque la mayoría de las veces esto no debería ser necesario.

Esta opción se puede especificar varias veces y/o con más URIs en la línea, separadas por espacios. Normalmente, solo se utilizará el primer servidor, y los siguientes servirán como respaldo (ver bind_timelimit a continuación).

Si se utilizan búsquedas LDAP para la resolución de nombres de host, los nombres de host deben especificarse como una dirección IP o un nombre que pueda resolverse sin usar LDAP.

ldap_version VERSIÓN
Especifica la versión del protocolo LDAP a utilizar. El valor predeterminado es utilizar la versión máxima soportada por la biblioteca LDAP.
binddn DN
Especifica el nombre distinguido (DN) con el que enlazarse al servidor de directorio para las búsquedas. El valor predeterminado es enlazarse anónimamente.
bindpw CONTRASEÑA
Especifica las credenciales con las que enlazarse. Esta opción solo es aplicable cuando se usa con binddn anteriormente. Si establece esta opción, debe considerar cambiar los permisos del archivo nslcd.conf para otorgar acceso únicamente al usuario root.
rootpwmoddn DN
Especifica el nombre distinguido (DN) a usar cuando el usuario root intenta modificar la contraseña de un usuario utilizando el módulo PAM.

Tenga en cuenta que actualmente este DN debe existir como una entrada real en el directorio LDAP.

rootpwmodpw CONTRASEÑA
Especifica las credenciales con las que enlazarse si el usuario root intenta cambiar la contraseña de un usuario. Esta opción solo es aplicable cuando se usa con rootpwmoddn anteriormente. Si esta opción no se especifica, el módulo PAM solicita al usuario esta contraseña. Si establece esta opción, debe considerar cambiar los permisos del archivo nslcd.conf para otorgar acceso únicamente al usuario root.

OPCIONES DE AUTENTICACIÓN SASL

sasl_mech MECANISMO
Especifica el mecanismo SASL a utilizar al realizar la autenticación SASL.
sasl_realm REALM
Especifica el realm SASL a utilizar al realizar la autenticación SASL.
sasl_authcid AUTHCID
Especifica la identidad de autenticación a utilizar al realizar la autenticación SASL.
sasl_authzid AUTHZID
Especifica la identidad de autorización a utilizar al realizar la autenticación SASL. Debe especificarse en uno de los formatos: dn:<nombre distinguido> o u:<nombre de usuario>.
sasl_secprops PROPIEDADES
Especifica las propiedades de seguridad de Cyrus SASL. Los valores permitidos se describen en la página del manual de ldap.conf(5).
sasl_canonicalize yes|no
Determina si el nombre del host del servidor LDAP debe ser canónico. Si esto se establece en yes, la biblioteca LDAP realizará una búsqueda inversa del nombre del host. Por defecto, se deja en manos de la biblioteca LDAP si se realiza esta comprobación o no.

OPCIONES DE AUTENTICACIÓN KERBEROS

krb5_ccname NOMBRE
Establece el nombre de la caché de credenciales Kerberos GSS-API.

OPCIONES DE BÚSQUEDA/MAPEO

base [MAP] DN
Especifica el nombre distinguido (DN) a utilizar como base de búsqueda. Esta opción se puede proporcionar varias veces y se buscarán todas las bases especificadas.

Se puede especificar una base de búsqueda global o una específica de MAP. Si no se definen bases de búsqueda específicas de MAP, se utilizan las globales.

Si, en lugar de un DN, se especifica el valor DOMINIO, se utiliza el dominio DNS del host para construir una base de búsqueda. Se puede utilizar un valor de "" para indicar una base de búsqueda vacía (las comillas no son compatibles de otra manera para los valores de base y no todas las configuraciones del servidor LDAP admiten esto).

Si este valor no se define, se intenta buscar en el servidor LDAP configurado. Si el servidor LDAP no está disponible durante el inicio, nslcd no se iniciará.

scope [MAP] sub[tree]|one[level]|base|children
Especifica el ámbito de búsqueda (subtree, onelevel, base o children). El ámbito predeterminado es subtree; el ámbito base casi nunca es útil para búsquedas de nombres de servicio; el ámbito children no es compatible con todos los servidores.
deref never|searching|finding|always
Especifica la política para la desreferenciación de alias. La política predeterminada es nunca desreferenciar

OPTIONS DE CONFIGURATION

Les fichiers de configuration suivants sont pris en charge.

base DN
Le distinguished name (DN) de la base de recherche LDAP. Ce paramètre est obligatoire.
binddn DN
Le DN à utiliser pour lier (authentifier) au serveur LDAP. Ce DN doit avoir les autorisations nécessaires pour lire les informations utilisateur et groupe. Si ce paramètre n'est pas défini, une liaison anonyme sera tentée.
bindpw MOTDEPASSE
Le mot de passe à utiliser pour la liaison avec le binddn. Si ce paramètre est omis, le mot de passe sera demandé à l'utilisateur.
bindtimelimit SECONDES
Le temps maximum (en secondes) à attendre pour la réponse à la requête de liaison. La valeur par défaut est 10.
bindtimeout SECONDES
Le temps maximum (en secondes) à attendre pour établir une connexion avec le serveur LDAP. La valeur par défaut est 10.
canonicalize_lookup yes|no
Si ce paramètre est défini sur 'yes', nslcd essaiera de canoniser les noms d'utilisateur et de groupe avant de les rechercher dans LDAP. Cela peut être utile pour gérer les incohérences de casse ou les noms mal formés. La valeur par défaut est 'no'.
chrootdir REPERTOIRE
Exécute le démon dans un environnement chroot. Ceci est utile pour des raisons de sécurité ou pour séparer les configurations. Tous les chemins des autres options de configuration seront relatifs à ce répertoire.
connlimit NOMBRE
Nombre maximum de connexions simultanées au serveur LDAP. La valeur par défaut est 1.
dnsroots DN,...
DN de domaines qui ne doivent pas être recherchés de manière récursive. Utile pour éviter les boucles dans les recherches d'annuaires.
domain DOMAINE
Le nom de domaine LDAP à utiliser. Si ce paramètre est défini, il sera utilisé pour construire le DN de base si celui-ci n'est pas explicitement défini. Par exemple, si le domaine est 'example.com', le DN de base sera 'dc=example,dc=com'.
dereference STRATEGIE
Stratégie de déréférencement des alias pour les recherches LDAP. Les valeurs possibles sont : never (ne jamais déréférencer), searching (déréférencer uniquement lors de la recherche), finding (déréférencer lors de la recherche et de la recherche d'objets), always (toujours déréférencer). La valeur par défaut est 'finding'.
filter EXPRESSION
Un filtre LDAP global qui sera appliqué à toutes les recherches. Ce filtre sera combiné avec le filtre de recherche spécifique à chaque type de requête (par exemple, le nom d'utilisateur pour passwd).
gidnumber ATTRIBUT
L'attribut LDAP contenant le GID (Group ID) pour les entrées de groupe. La valeur par défaut est 'gidNumber'.
groupattributes ATTRIBUT,...
Attributs supplémentaires à récupérer pour les entrées de groupe. Par défaut, seuls les attributs requis par le schéma PosixGroup sont récupérés.
groupfilter EXPRESSION
Un filtre LDAP qui sera appliqué spécifiquement aux recherches de groupes. Ce filtre sera combiné avec le filtre de base et le filtre de groupe par défaut.
groupsuffix DN
DN suffixe à ajouter à la recherche de groupes. Par exemple, si la base est 'dc=example,dc=com' et que le groupsuffix est 'ou=groups', la recherche de groupes sera effectuée sous 'ou=groups,dc=example,dc=com'.
hostattr ATTRIBUT
L'attribut LDAP contenant le nom d'hôte. La valeur par défaut est 'cn'.
idle_timeout SECONDES
Temps maximum (en secondes) pendant lequel une connexion LDAP restera ouverte sans activité avant d'être fermée. La valeur par défaut est 60.
ldapscheme SCHEME
Le schéma à utiliser pour se connecter au serveur LDAP. Les valeurs possibles sont 'ldap' (port 389) et 'ldaps' (port 636). La valeur par défaut est 'ldap'.
networkattributes ATTRIBUT,...
Attributs supplémentaires à récupérer pour les entrées réseau. Par défaut, seuls les attributs requis par le schéma Network sont récupérés.
networkfilter EXPRESSION
Un filtre LDAP qui sera appliqué spécifiquement aux recherches de réseaux. Ce filtre sera combiné avec le filtre de base.
networksuffix DN
DN suffixe à ajouter à la recherche de réseaux.
nss_initgroups_fallback yes|no
Si défini sur 'yes', nslcd essaiera de calculer les groupes supplémentaires en parcourant les membres de tous les groupes si la recherche initgroups échoue. Cela peut être très lent pour les grands annuaires. La valeur par défaut est 'no'.
objectclass CLASSE
La classe d'objet LDAP à utiliser pour les entrées utilisateur. La valeur par défaut est 'posixAccount'.
pam_check_host_attr ATTRIBUT
Active la vérification de l'appartenance à un groupe basé sur l'attribut spécifié. Si l'utilisateur est membre du groupe spécifié, l'accès est accordé. Utile pour les listes de contrôle d'accès.
pam_check_service_attr ATTRIBUT
Active la vérification de l'autorisation basée sur un attribut spécifié dans l'entrée utilisateur. L'accès est accordé si la valeur de l'attribut correspond au nom du service.
pam_filter EXPRESSION
Un filtre LDAP utilisé pour limiter les utilisateurs qui peuvent s'authentifier via PAM. Par exemple, pour n'autoriser que les utilisateurs ayant un attribut 'loginShell' défini.
pam_group_membership yes|no
Si défini sur 'yes', nslcd vérifiera l'appartenance de l'utilisateur aux groupes spécifiés dans PAM. La valeur par défaut est 'no'.
pam_groupdn DN
Le DN du groupe dont les membres sont autorisés à s'authentifier. Utilisé en combinaison avec pam_group_membership.
pam_password_policy yes|no
Si défini sur 'yes', nslcd essaiera de récupérer et d'appliquer la politique de mot de passe depuis le serveur LDAP. La valeur par défaut est 'yes'.
pam_userdn ATTRIBUT
L'attribut LDAP contenant le nom d'utilisateur pour l'authentification PAM. La valeur par défaut est 'uid'.
port NUMERO
Le numéro de port LDAP sur lequel se connecter. La valeur par défaut est 389 pour 'ldap' et 636 pour 'ldaps'.
protocolnumber ATTRIBUT
L'attribut LDAP contenant le numéro de protocole. La valeur par défaut est 'protocolNumber'.
referrals yes|no
Si défini sur 'yes', nslcd suivra les renvois LDAP. La valeur par défaut est 'no'.
regex_filter REGEX
Un filtre basé sur une expression régulière POSIX étendue qui sera appliqué à toutes les recherches. La regex doit être délimitée par des caractères '/'. Le drapeau 'i' peut être ajouté pour ignorer la casse. Ceci est utilisé pour filtrer les entrées avant de les charger dans les caches du système.
rootbinddn DN
Le DN à utiliser pour les recherches qui nécessitent des privilèges root. Si ce paramètre n'est pas défini, les recherches seront effectuées avec le binddn.
rootbindpw MOTDEPASSE
Le mot de passe à utiliser pour la liaison avec le rootbinddn.
search_timeout SECONDES
Le temps maximum (en secondes) à attendre pour une réponse à une requête de recherche. La valeur par défaut est 30.
searchscope NIVEAU
Le niveau de recherche à utiliser. Les valeurs possibles sont 'base' (recherche uniquement sur la base), 'one' (recherche sur un niveau sous la base), et 'sub' (recherche sur tous les niveaux sous la base). La valeur par défaut est 'sub'.
servers HOTE[:PORT]...
Une liste de serveurs LDAP à interroger, séparés par des espaces. Si un port n'est pas spécifié, le port par défaut (389 ou 636 selon ldapscheme) sera utilisé. Si un serveur échoue, les suivants dans la liste seront tentés.
shadowlastchange ATTRIBUT
L'attribut LDAP contenant la date de la dernière modification du mot de passe pour les informations de shadow. La valeur par défaut est 'shadowLastChange'.
shadowmax ATTRIBUT
L'attribut LDAP contenant le nombre maximum de jours pendant lesquels un mot de passe est valide. La valeur par défaut est 'shadowMax'.
shadowmin ATTRIBUT
L'attribut LDAP contenant le nombre minimum de jours entre deux modifications de mot de passe. La valeur par défaut est 'shadowMin'.
shadowwarning ATTRIBUT
L'attribut LDAP contenant le nombre de jours avant l'expiration du mot de passe où un avertissement doit être affiché. La valeur par défaut est 'shadowWarning'.
ssl_ca_cert FICHIER
Le fichier du certificat d'autorité de certification (CA) à utiliser pour vérifier le certificat du serveur LDAP lors de l'utilisation de LDAPS.
ssl_cert FICHIER
Le fichier du certificat client à utiliser pour l'authentification mutuelle avec le serveur LDAP lors de l'utilisation de LDAPS.
ssl_key FICHIER
Le fichier de la clé privée du client à utiliser pour l'authentification mutuelle avec le serveur LDAP lors de l'utilisation de LDAPS.
ssh_known_hosts FICHIER
Fichier contenant les clés publiques des hôtes SSH connus. Utilisé pour vérifier l'identité des serveurs SSH lors de l'utilisation de protocoles qui s'appuient sur SSH pour l'authentification (par exemple, pour certaines fonctions de netgroup).
sudoers_attribute ATTRIBUT
L'attribut LDAP contenant les règles sudo. La valeur par défaut est 'sudoRole'.
timelimit SECONDES
Le temps maximum (en secondes) à attendre pour la réponse à une requête de recherche. La valeur par défaut est 30.
timeout SECONDES
Le temps maximum (en secondes) à attendre pour établir une connexion avec le serveur LDAP. La valeur par défaut est 10.
tls_require_cert STRATEGIE
Stratégie pour la vérification du certificat du serveur LDAP lors de l'utilisation de TLS/SSL. Les valeurs possibles sont 'never' (ne jamais vérifier), 'allow' (vérifier si le certificat est valide, mais continuer même s'il ne l'est pas), 'try' (vérifier si le certificat est valide, mais continuer même s'il ne l'est pas), 'demand' (vérifier et exiger un certificat valide), 'hard' (vérifier et exiger un certificat valide et correspondant à l'hôte). La valeur par défaut est 'hard'.
uidnumber ATTRIBUT
L'attribut LDAP contenant le UID (User ID) pour les entrées utilisateur. La valeur par défaut est 'uidNumber'.
userattributes ATTRIBUT,...
Attributs supplémentaires à récupérer pour les entrées utilisateur. Par défaut, seuls les attributs requis par le schéma PosixAccount sont récupérés.
userfilter EXPRESSION
Un filtre LDAP qui sera appliqué spécifiquement aux recherches d'utilisateurs. Ce filtre sera combiné avec le filtre de base et le filtre utilisateur par défaut.
usersuffix DN
DN suffixe à ajouter à la recherche d'utilisateurs. Par exemple, si la base est 'dc=example,dc=com' et que le usersuffix est 'ou=users', la recherche d'utilisateurs sera effectuée sous 'ou=users,dc=example,dc=com'.
uri URI
L'URI du serveur LDAP. Ceci est une alternative à la spécification de servers, port et ldapscheme. Exemple : ldap://ldap.example.com:389 ou ldaps://ldap.example.com:636.
disable_getpwnam yes|no
Si cette option est activée ('yes'), les appels à la fonction C getpwnam() ne seront pas pris en charge. Ceci est utile pour empêcher les applications qui ne sont pas prévues pour un environnement LDAP de charger toutes les entrées utilisateur. La valeur par défaut est 'no'.
disable_getgrnam yes|no
Similaire à disable_getpwnam, mais pour les entrées de groupe (getgrnam()). La valeur par défaut est 'no'.
disable_getpwent yes|no
Si cette option est activée ('yes'), les appels aux fonctions C getpwent() (qui itèrent sur toutes les entrées utilisateur) ne seront pas pris en charge. Ceci est utile pour empêcher les applications qui ne sont pas prévues pour un environnement LDAP de charger toutes les entrées utilisateur. La valeur par défaut est 'no'.
disable_getgrent yes|no
Similaire à disable_getpwent, mais pour les entrées de groupe (getgrent()). La valeur par défaut est 'no'.
disable_setspent yes|no
Si cette option est activée ('yes'), les appels à la fonction C setspent() (qui réinitialise la position dans le fichier de mots de passe) ne seront pas pris en charge. La valeur par défaut est 'no'.
disable_fullmap yes|no
Si cette option est activée ('yes'), les appels aux fonctions NSS qui provoquent le chargement de toutes les entrées utilisateur/groupe (getpwent(), getgrent(), setspent()) à partir de l'annuaire échoueront. Les applications qui dépendent de la lecture séquentielle de tous les utilisateurs et/ou groupes peuvent ne pas fonctionner correctement.

Cela peut réduire considérablement la charge du serveur LDAP dans les situations où il y a un grand nombre d'utilisateurs et/ou de groupes. Ceci est généralement utilisé dans les situations où l'accès des utilisateurs/programmes pour énumérer l'ensemble de l'annuaire est indésirable, et où le comportement de l'utilisateur/programme ne peut pas être modifié. Cette option n'est pas recommandée pour la plupart des configurations.

validnames REGEX
Cette option peut être utilisée pour spécifier comment les noms d'utilisateur et de groupe sont vérifiés dans le système. Cette expression régulière est utilisée pour vérifier tous les noms d'utilisateur et de groupe qui sont demandés et renvoyés par LDAP.

L'expression régulière doit être spécifiée comme une expression régulière étendue POSIX. L'expression elle-même doit être séparée par des barres obliques ('/') et le drapeau 'i' peut être ajouté à la fin pour indiquer que la correspondance doit être insensible à la casse. La valeur par défaut est /^[a-z0-9._@$()]([a-z0-9._@$() \\~-]*[a-z0-9._@$()~-])?$/i

ignorecase yes|no
Spécifie si les recherches pour les cartes group, netgroup, passwd, protocols, rpc, services et shadow doivent être effectuées avec une correspondance insensible à la casse. Définir cette option sur 'yes' pourrait exposer le système à des vulnérabilités de contournement d'autorisation et introduire des vulnérabilités d'empoisonnement du cache nscd qui permettent un déni de service. La valeur par défaut est d'effectuer un filtrage sensible à la casse des résultats de recherche LDAP pour les cartes ci-dessus.
pam_authc_ppolicy yes|no
Cette option spécifie si les contrôles de politique de mot de passe sont demandés et gérés par le serveur LDAP lors de l'authentification de l'utilisateur. Par défaut, les contrôles sont demandés et gérés s'ils sont disponibles.
pam_authc_search FILTER
Par défaut, nslcd effectue une recherche LDAP avec les informations d'identification de l'utilisateur après la liaison (authentification) pour s'assurer que l'opération de liaison a réussi. La recherche par défaut est une simple vérification pour voir si le DN de l'utilisateur existe.

Un filtre de recherche peut être spécifié et sera utilisé à la place. Les mêmes substitutions que pour l'option pam_authz_search seront effectuées et la recherche devra au moins retourner une entrée.

La valeur BASE peut être utilisée pour forcer la recherche par défaut du DN de l'utilisateur.

La valeur NONE peut être utilisée pour indiquer qu'aucune recherche ne doit être effectuée après la liaison. Notez que certains serveurs LDAP ne renvoient pas toujours un code d'erreur correct à la suite d'une opération de liaison échouée (par exemple, lorsqu'un mot de passe vide est fourni).

pam_authz_search FILTER
Cette option permet un réglage fin et flexible de la vérification d'autorisation qui doit être effectuée. Le filtre de recherche spécifié est exécuté et si des entrées correspondent, l'accès est accordé, sinon l'accès est refusé.

Le filtre de recherche peut contenir les références de variables suivantes : $username, $service, $ruser, $rhost, $tty, $hostname, $fqdn, $domain, $dn, et $uid. Ces références sont substituées dans le filtre de recherche en utilisant la même syntaxe que celle décrite dans la section sur les expressions de mappage d'attributs ci-dessous.

Par exemple, pour vérifier que l'utilisateur a une valeur autorisée de 'authorizedService' si l'attribut est présent (ce qui émule presque l'option pam_check_service_attr de pam_ldap de PADL) :

(&(objectClass=posixAccount)(uid=$username)(|(authorizedService=$service)(!(authorizedService=*))))

L'option pam_check_host_attr peut être émule avec :

(&(objectClass=posixAccount)(uid=$username)(|(host=$hostname)(host=$fqdn)(host=\\*)))

Cette option peut être spécifiée plusieurs fois et toutes les recherches spécifiées doivent retourner au moins une entrée pour que l'accès soit accordé.

pam_password_prohibit_message "MESSAGE"
Si cette option est définie, la modification du mot de passe via pam_ldap sera refusée et le message spécifié sera présenté à l'utilisateur à la place. Le message peut être utilisé pour diriger l'utilisateur vers un moyen alternatif de changer son mot de passe.
reconnect_invalidate DB,DB,...
Si cette option est définie, nslcd tentera de vider les caches externes spécifiés au démarrage et chaque fois qu'une connexion au serveur LDAP est rétablir après une erreur.

DB peut faire référence à l'une des cartes nsswitch, auquel cas nscd est contacté pour vider son cache pour la base de données spécifiée. Si DB est nfsidmap, nfsidmap est contacté pour vider son cache.

L'utilisation de cette option garantit que les caches externes sont vidés des informations incorrectes (typiquement l'absence d'utilisateurs) qui peuvent être présentes en raison de l'indisponibilité du serveur LDAP.

cache CACHE TIME [TIME]
Configure le temps pendant lequel les entrées sont conservées dans le cache interne spécifié.

La première valeur TIME spécifie le temps pendant lequel conserver les entrées trouvées dans le cache. La seconde valeur TIME spécifie le temps pendant lequel se souvenir qu'une entrée particulière n'a pas été trouvée. Si le second paramètre est absent, il est supposé être le même que le premier.

Les valeurs de temps sont spécifiées comme un nombre suivi d'un s pour secondes, m pour minutes, h pour heures ou d pour jours. Utilisez 0 ou off pour désactiver le cache.

Actuellement, seul le cache dn2uid est pris en charge, qui est utilisé pour se souvenir des recherches DN vers UID qui sont utilisées lorsque l'attribut member est utilisé. La valeur de temps par défaut pour ce cache est 15m.

EXPRESSIONS DE MAQUETAGE D'ATTRIBUTS

Pour certains attributs, une expression de maquettage peut être utilisée pour construire la valeur résultante. Ceci n'est actuellement possible que pour les attributs qui n'ont pas besoin d'être utilisés dans les filtres de recherche. Les expressions sont un sous-ensemble des expressions de chaîne entre guillemets doubles dans le shell Bourne (POSIX). Au lieu de la substitution de variables, des recherches d'attributs sont effectuées sur l'entrée actuelle et la valeur de l'attribut est substituée. Les expressions suivantes sont prises en charge :

${attr} (ou $attr en abrégé)
substituera la valeur de l'attribut
${attr:-mot}
(utiliser la valeur par défaut) substituera la valeur de l'attribut ou, si l'attribut n'est pas défini ou est vide, substituera le mot
${attr:+mot}
(utiliser la valeur alternative) substituera le mot si l'attribut est défini, sinon substituera la chaîne vide
${attr:offset:longueur}
substituera la longueur des caractères (en fait, des octets) à partir de la position offset (qui est comptée à partir de zéro) ; la chaîne substituée sera tronquée si elle est trop longue ; en particulier, elle peut être de longueur zéro (si la longueur est zéro ou si offset tombe en dehors de la chaîne d'origine)
${attr#mot}
supprimera la correspondance la plus courte possible de 'mot' depuis la gauche de la valeur de l'attribut
${attr##mot}
supprimera la correspondance la plus longue possible de 'mot' depuis la gauche de la valeur de l'attribut (seulement pynslcd)
${attr%mot}
supprimera la correspondance la plus courte possible de 'mot' depuis la droite de la valeur de l'attribut (seulement pynslcd)
${attr%%mot}
supprimera la correspondance la plus longue possible de 'mot' depuis la droite de la valeur de l'attribut (seulement pynslcd)

Seule l'expression de correspondance # est prise en charge dans nslcd et uniquement avec le symbole joker ?. L'implémentation pynslcd prend en charge la correspondance complète.

Les caractères guillemet ("), dollar ($) et antislash (\) doivent être échappés avec un antislash (\).

Les expressions sont inspectées pour récupérer automatiquement les attributs appropriés de LDAP. Voici quelques exemples pour démontrer comment ces expressions peuvent être utilisées dans le maquettage d'attributs :

"${shadowFlag:-0}"
utilise l'attribut shadowFlag, en utilisant la valeur 0 par défaut
"${homeDirectory:-/home/$uid}"
utilise l'attribut uid pour construire une valeur homeDirectory si cet attribut est manquant
"${isDisabled:+100}"
si l'attribut isDisabled est défini, renvoie 100, sinon laisse la valeur vide
"${userPassword#{crypt\}}"
supprime le préfixe {crypt} de l'attribut userPassword, renvoyant la valeur de hachage brute
