nsswitch.conf(5) Manual de Formatos de Archivo nsswitch.conf(5)

NOMBRE

nsswitch.conf - archivo de configuración del servicio de nombres

DESCRIPCIÓN

El archivo de configuración del Servicio de Nombres (NSS, por sus siglas en inglés), /etc/nsswitch.conf, es utilizado por la Biblioteca C de GNU y ciertas otras aplicaciones para determinar las fuentes de las cuales obtener información del servicio de nombres en un rango de categorías y en qué orden. Cada categoría de información se identifica por un nombre de base de datos.

El archivo es texto plano ASCII, con columnas separadas por espacios o tabulaciones. La primera columna especifica el nombre de la base de datos. Las columnas restantes describen el orden de las fuentes a consultar y un conjunto limitado de acciones que pueden realizarse según el resultado de la búsqueda.

Las siguientes bases de datos son entendidas por la Biblioteca C de GNU:

aliases
Alias de correo, usados por getaliasent(3) y funciones relacionadas.
ethers
Números de Ethernet.
group
Grupos de usuarios, usados por getgrent(3) y funciones relacionadas.
hosts
Nombres y números de host, usados por gethostbyname(3) y funciones relacionadas.
initgroups
Lista suplementaria de acceso a grupos, usada por la función getgrouplist(3).
netgroup
Lista de hosts y usuarios de red, usada para reglas de acceso. Las bibliotecas C anteriores a glibc 2.1 solo admitían netgroups sobre NIS.
networks
Nombres y números de red, usados por getnetent(3) y funciones relacionadas.
passwd
Contraseñas de usuario, usadas por getpwent(3) y funciones relacionadas.
protocols
Protocolos de red, usados por getprotoent(3) y funciones relacionadas.
publickey
Claves públicas y secretas para Secure_RPC usadas por NFS y NIS+.
rpc
Nombres y números de llamadas a procedimientos remotos, usados por getrpcbyname(3) y funciones relacionadas.
services
Servicios de red, usados por getservent(3) y funciones relacionadas.
shadow
Contraseñas de usuario encriptadas, usadas por getspnam(3) y funciones relacionadas.

La Biblioteca C de GNU ignora bases de datos con nombres desconocidos. Algunas aplicaciones usan esto para implementar un manejo especial para sus propias bases de datos. Por ejemplo, sudo(8) consulta la base de datos sudoers. La delegación de IDs de usuario/grupo subordinados se puede configurar usando la base de datos subid. Consulte subuid(5) y subgid(5) para más detalles.

Aquí hay un ejemplo de archivo /etc/nsswitch.conf:


passwd:         compat
group:          compat
shadow:         compat
hosts:          dns [!UNAVAIL=return] files
networks:       nis [NOTFOUND=return] files
ethers:         nis [NOTFOUND=return] files
protocols:      nis [NOTFOUND=return] files
rpc:            nis [NOTFOUND=return] files
services:       nis [NOTFOUND=return] files

La primera columna es el nombre de la base de datos. Las columnas restantes especifican:

•
Una o más especificaciones de servicio, por ejemplo, "files", "db" o "nis". El orden de los servicios en la línea determina el orden en que se consultarán esos servicios, uno tras otro, hasta que se encuentre un resultado.
•
Acciones opcionales a realizar si se obtiene un resultado particular del servicio anterior, por ejemplo, "[NOTFOUND=return]".

Las especificaciones de servicio soportadas en su sistema dependen de la presencia de bibliotecas compartidas y, por lo tanto, son extensibles. Las bibliotecas llamadas /lib/libnss_SERVICIO.so.X proporcionarán el SERVICIO nombrado. En una instalación estándar, puede usar "files", "db", "nis" y "nisplus". Para la base de datos hosts, puede especificar adicionalmente "dns". Para las bases de datos passwd, group y shadow, puede especificar adicionalmente "compat" (ver Modo de compatibilidad a continuación).

También se puede especificar una acción después de una especificación de servicio. La acción modifica el comportamiento tras un resultado obtenido de la fuente de datos anterior. Los elementos de acción tienen la forma general:

[ESTADO=ACCIÓN]
[!ESTADO=ACCIÓN]

donde

ESTADO => success | notfound | unavail | tryagain
ACCIÓN => return | continue | merge

El ! niega la prueba, coincidiendo con todos los resultados posibles excepto el especificado. La capitalización de las palabras clave no es significativa.

El valor de ESTADO se compara con el resultado de la función de búsqueda llamada por la especificación del servicio anterior, y puede ser uno de:

success
No ocurrió ningún error y se devuelve la entrada solicitada. La acción predeterminada para esta condición es "return".
notfound
La búsqueda tuvo éxito, pero la entrada solicitada no se encontró. La acción predeterminada para esta condición es "continue".
unavail
El servicio no está disponible permanentemente. Esto puede significar que el archivo requerido no se puede leer, o, para servicios de red, que el servidor no está disponible o no permite consultas. La acción predeterminada para esta condición es "continue".
tryagain
El servicio no está disponible temporalmente. Esto podría significar que un archivo está bloqueado o que un servidor actualmente no puede aceptar más conexiones. La acción predeterminada para esta condición es "continue".

El valor de ACCIÓN puede ser uno de:

return
Devolver un resultado ahora. No llamar a ninguna función de búsqueda adicional. Sin embargo, por razones de compatibilidad, si esta es la acción seleccionada para la base de datos group y el estado notfound, y el archivo de configuración no contiene la línea initgroups, la siguiente función de búsqueda siempre se llama, sin afectar el resultado de la búsqueda.
continue
Llamar a la siguiente función de búsqueda.
merge
[SUCCESS=merge] se usa entre dos entradas de base de datos. Cuando se localiza un grupo en la primera de las dos entradas de grupo, el procesamiento continuará hasta la siguiente. Si el grupo también se encuentra en la siguiente entrada (y el nombre del grupo y el GID coinciden exactamente), la lista de miembros de la segunda entrada se agregará al objeto de grupo a devolver. Disponible desde glibc 2.24. Tenga en cuenta que no se realizará la fusión para getgrent(3) ni se eliminarán los miembros duplicados cuando ocurran en ambas entradas que se están fusionando.

Modo de compatibilidad (compat)

El servicio "compat" de NSS es similar a "files" excepto que además permite entradas especiales en los archivos correspondientes para otorgar acceso al sistema a usuarios o miembros de netgroups. Las siguientes entradas son válidas

en este modo:

Para las bases de datos passwd y shadow:

+usuario
Incluir el usuario especificado del mapa NIS passwd/shadow.
+@netgroup
Incluir a todos los usuarios del netgroup dado.
-usuario
Excluir al usuario especificado del mapa NIS passwd/shadow.
-@netgroup
Excluir a todos los usuarios del netgroup dado.
+
Incluir a todos los usuarios, excepto a los previamente excluidos, del mapa NIS passwd/shadow.

Para la base de datos group:

+grupo
Incluir el grupo especificado del mapa de grupos NIS.
-grupo
Excluir el grupo especificado del mapa de grupos NIS.
+
Incluir todos los grupos, excepto los previamente excluidos, del mapa de grupos NIS.

Por defecto, la fuente es "nis", pero esto puede ser anulado especificando cualquier servicio NSS excepto "compat" en sí mismo como la fuente para las pseudo-bases de datos passwd_compat, group_compat y shadow_compat.

ARCHIVOS

Un servicio llamado SERVICIO se implementa mediante una biblioteca compartida llamada libnss_SERVICIO.so.X que reside en /lib.

/etc/nsswitch.conf
Archivo de configuración de NSS.
/lib/libnss_compat.so.X
implementa la fuente "compat".
/lib/libnss_db.so.X
implementa la fuente "db".
/lib/libnss_dns.so.X
implementa la fuente "dns".
/lib/libnss_files.so.X
implementa la fuente "files".
/lib/libnss_hesiod.so.X
implementa la fuente "hesiod".
/lib/libnss_nis.so.X
implementa la fuente "nis".
/lib/libnss_nisplus.so.X
implementa la fuente "nisplus".

Los siguientes archivos se leen cuando se especifica la fuente "files" para las bases de datos respectivas:

aliases
/etc/aliases
ethers
/etc/ethers
group
/etc/group
hosts
/etc/hosts
initgroups
/etc/group
netgroup
/etc/netgroup
networks
/etc/networks
passwd
/etc/passwd
protocols
/etc/protocols
publickey
/etc/publickey
rpc
/etc/rpc
services
/etc/services
shadow
/etc/shadow

NOTAS

A partir de glibc 2.33, nsswitch.conf se recarga automáticamente si el archivo se modifica. En versiones anteriores, todo el archivo se leía solo una vez dentro de cada proceso. Si el archivo se modificaba posteriormente, el proceso continuaba utilizando la configuración antigua.

Tradicionalmente, solo existía una única fuente de información de servicios, a menudo en forma de un único archivo de configuración (por ejemplo, /etc/passwd). Sin embargo, a medida que otros servicios de nombres, como Network Information Service (NIS) y Domain Name Service (DNS), se volvieron populares, se necesitó un método más flexible que los órdenes de búsqueda fijos codificados en la biblioteca C. El mecanismo Name Service Switch, basado en el mecanismo utilizado por Sun Microsystems en la biblioteca C de Solaris 2, introdujo una solución más limpia al problema.
