namespace(n)

Paquete: tcl

Licencias: TCL

namespace(n) Comandos integrados de Tcl namespace(n)

NOMBRE

namespace - crear y manipular contextos para comandos y variables

SINOPSIS

namespace subcomando ?arg ...?

DESCRIPCIÓN

El comando namespace permite crear, acceder y destruir contextos separados para comandos y variables. Consulte la sección ¿QUÉ ES UN NAMESPACE? a continuación para una breve descripción general de los namespaces. Los valores legales de subcomando se enumeran a continuación. Tenga en cuenta que puede abreviar los subcomandos.

namespace children ?namespace? ?pattern?
Devuelve una lista de todos los namespaces hijos que pertenecen al namespace namespace. Si no se especifica namespace, se devuelven los hijos del namespace actual. Este comando devuelve nombres completamente calificados, que comienzan con dos puntos (::). Si se proporciona el patrón opcional, este comando devuelve solo los nombres que coinciden con el patrón de estilo glob. El patrón real utilizado se determina de la siguiente manera: un patrón que comienza con dos puntos (::) se utiliza directamente, de lo contrario, se antepone el namespace namespace (o el nombre completamente calificado del namespace actual) al patrón.
namespace code script
Captura el contexto del namespace actual para la ejecución posterior del script script. Devuelve un nuevo script en el que script ha sido envuelto en un comando namespace inscope. El nuevo script tiene dos propiedades importantes. Primero, se puede evaluar en cualquier namespace y hará que script se evalúe en el namespace actual (aquel donde se invocó el comando namespace code). Segundo, se pueden agregar argumentos adicionales al script resultante y se pasarán a script como argumentos adicionales. Por ejemplo, supongamos que el comando set script [namespace code {foo bar}] se invoca en el namespace ::a::b. Entonces eval $script [list x y] se puede ejecutar en cualquier namespace (suponiendo que el valor de script se haya pasado correctamente) y tendrá el mismo efecto que el comando ::namespace eval ::a::b {foo bar x y}. Este comando es necesario porque extensiones como Tk normalmente ejecutan scripts de devolución de llamada en el namespace global. Un comando con ámbito captura un comando junto con su contexto de namespace de forma que pueda ejecutarse correctamente más tarde. Consulte la sección SCRIPTS CON ÁMBITO para ver algunos ejemplos de cómo se utiliza esto para crear scripts de devolución de llamada.
namespace current
Devuelve el nombre completamente calificado del namespace actual. El nombre real del namespace global es “” (es decir, una cadena vacía), pero este comando devuelve :: para el namespace global como una conveniencia para los programadores.
namespace delete ?namespace namespace ...?
Cada namespace namespace se elimina y se eliminan todas las variables, procedimientos y namespaces hijos contenidos en el namespace. Si un procedimiento se está ejecutando actualmente dentro del namespace, el namespace se mantendrá vivo hasta que el procedimiento regrese; sin embargo, el namespace se marca para evitar que otro código lo busque por nombre. Si un namespace no existe, este comando devuelve un error. Si no se proporcionan nombres de namespace, este comando no hace nada.
namespace ensemble subcomando ?arg ...?
Crea y manipula un comando que se forma a partir de un conjunto de subcomandos. Consulte la sección CONJUNTOS a continuación para obtener más detalles.
namespace eval namespace arg ?arg ...?
Activa un namespace llamado namespace y evalúa código en ese contexto. Si el namespace no existe todavía, se crea. Si se especifican más de un argumento arg, los argumentos se concatenan con un espacio entre cada uno de la misma manera que el comando eval, y el resultado se evalúa.

Si namespace tiene calificadores de namespace iniciales y cualquier namespace inicial no existe, se crean automáticamente.

namespace exists namespace
Devuelve 1 si namespace es un namespace válido en el contexto actual, devuelve 0 de lo contrario.
namespace export ?-clear? ?pattern pattern ...?
Especifica qué comandos se exportan desde un namespace. Los comandos exportados son aquellos que se pueden importar posteriormente a otro namespace utilizando un comando namespace import. Tanto los comandos definidos en un namespace como los comandos que el namespace ha importado previamente pueden ser exportados por un namespace. Los comandos no tienen que definirse en el momento en que se ejecuta el comando namespace export. Cada patrón puede contener caracteres especiales de estilo glob, pero no puede incluir calificadores de namespace. Es decir, el patrón solo puede especificar comandos en el namespace actual (el que exporta). Cada patrón se agrega a la lista de patrones de exportación del namespace. Si se proporciona la bandera -clear, la lista de patrones de exportación del namespace se restablece a vacía antes de que se agreguen los argumentos patrón. Si no se proporcionan patrones y no se proporciona la bandera -clear, este comando devuelve la lista de exportación actual del namespace.
namespace forget ?pattern pattern ...?
Elimina comandos importados previamente de un namespace. Cada patrón es un nombre simple o calificado como x, foo::x o a::b::p*. Los nombres calificados contienen dos puntos (::) y califican un nombre con el nombre de uno o más namespaces. Cada "patrón calificado" está calificado con el nombre de un namespace que exporta y puede tener caracteres especiales de estilo glob en el nombre del comando al final del nombre calificado. Los caracteres glob no pueden aparecer en un nombre de namespace. Para cada "patrón simple", este comando elimina los comandos coincidentes del namespace actual que se importaron de un namespace diferente. Para "patrones calificados", este comando primero encuentra los comandos exportados coincidentes. Luego verifica si alguno de esos comandos fue importado previamente por el namespace actual. Si es así, este comando elimina los comandos importados correspondientes. En efecto, esto deshace la acción de un comando namespace import.
namespace import ?-force? ?pattern pattern ...?
Importa comandos a un namespace, o consulta el conjunto de comandos importados en un namespace. Cuando no hay argumentos, namespace import devuelve la lista de comandos en el namespace actual que han sido importados de otros namespaces. Los comandos en la lista devuelta están en formato de nombres simples, sin calificadores de namespace en absoluto. Este formato es adecuado para la composición con namespace forget (ver EJEMPLOS a continuación).

Cuando se proporcionan argumentos patrón, cada patrón es un nombre calificado como foo::x o a::p*. Es decir, incluye el nombre de un namespace que exporta y puede tener caracteres especiales de estilo glob en el nombre del comando al final del nombre calificado. Los caracteres glob no pueden aparecer en un nombre de namespace. Cuando el nombre del namespace no está completamente calificado (es decir, no comienza con un separador de namespace), se resuelve como un nombre de namespace de la manera descrita en la sección RESOLUCIÓN DE NOMBRES; es un error si no se puede encontrar ningún namespace con ese nombre.

Todos los comandos que coinciden con una cadena patrón y que están actualmente exportados de su namespace se agregan al namespace actual. Esto se hace creando un nuevo comando en el namespace actual que apunta al comando exportado en su namespace original; cuando se llama al nuevo comando importado, invoca al comando exportado. Este comando normalmente devuelve un error si un comando importado entra en conflicto con un comando existente. Sin embargo, si se proporciona la opción -force, los comandos importados reemplazarán silenciosamente los comandos existentes. RESOLUCIÓN DE NOMBRES

En general, todos los comandos de Tcl que toman nombres de variables y comandos admiten nombres calificados. Esto significa que puede dar nombres calificados a comandos como set, proc, rename e interp alias. Si proporciona un nombre completamente calificado que comienza con ::, no hay duda sobre qué comando, variable o espacio de nombres se refiere. Sin embargo, si el nombre no comienza con :: (es decir, es *relativo*), Tcl sigue reglas básicas para buscarlo:

  • Los nombres de variables siempre se resuelven buscando primero en el espacio de nombres actual y luego en el espacio de nombres global.
  • Los nombres de comandos siempre se resuelven buscando primero en el espacio de nombres actual. Si no se encuentran allí, se buscan en todos los espacios de nombres en la ruta de comandos del espacio de nombres actual (que está vacía por defecto). Si no se encuentran allí, los nombres de comandos se buscan en el espacio de nombres global (o, en su defecto, son procesados por el manejador apropiado de namespace unknown).
  • Los nombres de espacios de nombres siempre se resuelven buscando solo en el espacio de nombres actual.

En el siguiente ejemplo,

set traceLevel 0
namespace eval Debug {
    printTrace $traceLevel
}

Tcl busca traceLevel en el espacio de nombres Debug y luego en el espacio de nombres global. Busca el comando printTrace de la misma manera. Si no se encuentra una variable o un nombre de comando en ninguno de los contextos, el nombre no está definido. Para que este punto quede absolutamente claro, considere el siguiente ejemplo:

set traceLevel 0
namespace eval Foo {
    variable traceLevel 3
    namespace eval Debug {
        printTrace $traceLevel
    }
}

Aquí Tcl busca traceLevel primero en el espacio de nombres Foo::Debug. Como no se encuentra allí, Tcl luego lo busca en el espacio de nombres global. La variable Foo::traceLevel se ignora por completo durante el proceso de resolución de nombres.

Puede usar el comando namespace which para aclarar cualquier duda sobre la resolución de nombres. Por ejemplo, el comando:

namespace eval Foo::Debug {namespace which -variable traceLevel}

devuelve ::traceLevel. Por otro lado, el comando,

namespace eval Foo {namespace which -variable traceLevel}

devuelve ::Foo::traceLevel.

Como se mencionó anteriormente, los nombres de los espacios de nombres se buscan de manera diferente a los nombres de las variables y los comandos. Los nombres de los espacios de nombres siempre se resuelven en el espacio de nombres actual. Esto significa, por ejemplo, que un comando namespace eval que crea un nuevo espacio de nombres siempre crea un hijo del espacio de nombres actual, a menos que el nombre del nuevo espacio de nombres comience con ::.

Tcl no tiene control de acceso para limitar qué variables, comandos o espacios de nombres puede referenciar. Si proporciona un nombre calificado que se resuelve en un elemento según la regla de resolución de nombres anterior, puede acceder al elemento.

Puede acceder a una variable de espacio de nombres desde un procedimiento en el mismo espacio de nombres utilizando el comando variable. De manera similar al comando global, esto crea un enlace local a la variable del espacio de nombres. Si es necesario, también crea la variable en el espacio de nombres actual y la inicializa. Tenga en cuenta que el comando global solo crea enlaces a variables en el espacio de nombres global. No es necesario utilizar un comando variable si siempre se refiere a la variable del espacio de nombres utilizando un nombre calificado apropiado.

IMPORTANDO COMANDOS

Los espacios de nombres se utilizan a menudo para representar bibliotecas. Algunos comandos de biblioteca se utilizan con tanta frecuencia que resulta molesto escribir sus nombres calificados. Por ejemplo, suponga que todos los comandos de un paquete como BLT están contenidos en un espacio de nombres llamado Blt. Entonces podría acceder a estos comandos de la siguiente manera:

Blt::graph .g -background red
Blt::table . .g 0,0

Si usa los comandos graph y table con frecuencia, es posible que desee acceder a ellos sin el prefijo Blt::. Puede hacerlo importando los comandos al espacio de nombres actual, de la siguiente manera:

namespace import Blt::*

Esto agrega todos los comandos exportados del espacio de nombres Blt al contexto del espacio de nombres actual, para que pueda escribir código como este:

graph .g -background red
table . .g 0,0

El comando namespace import solo importa comandos de un espacio de nombres que ese espacio de nombres exportó con un comando namespace export.

Importar *todos* los comandos de un espacio de nombres es generalmente una mala idea, ya que no se sabe lo que se obtendrá. Es mejor importar solo los comandos específicos que necesita. Por ejemplo, el comando

namespace import Blt::graph Blt::table

importa solo los comandos graph y table al contexto actual.

Si intenta importar un comando que ya existe, recibirá un error. Esto evita que importe el mismo comando de dos paquetes diferentes. Pero de vez en cuando (quizás al depurar), es posible que desee eludir esta restricción. Es posible que desee volver a emitir el comando namespace import para capturar nuevos comandos que han aparecido en un espacio de nombres. En ese caso, puede usar la opción -force, y los comandos existentes se sobrescribirán silenciosamente:

namespace import -force Blt::graph Blt::table

Si por alguna razón desea dejar de usar los comandos importados, puede eliminarlos con un comando namespace forget, de la siguiente manera:

namespace forget Blt::*

Esto busca en el espacio de nombres actual cualquier comando importado de Blt. Si encuentra alguno, lo elimina. De lo contrario, no hace nada. Después de esto, los comandos Blt deben accederse con el prefijo Blt::.

Cuando elimina un comando del espacio de nombres exportador de esta manera:

rename Blt::graph ""

el comando se elimina automáticamente de todos los espacios de nombres que lo importan.

EXPORTANDO COMANDOS

Puede exportar comandos de un espacio de nombres de la siguiente manera:

namespace eval Counter {
    namespace export bump reset
    variable Num 0
    variable Max 100
    proc bump {{by 1}} {
        variable Num
        incr Num $by
        Check
        return $Num
    }
    proc reset {} {
        variable Num
        set Num 0
    }
    proc Check {} {
        variable Num
        variable Max
        if {$Num > $Max} {
            error "too high!"
        }
    }
}

Los procedimientos bump y reset se exportan, por lo que se incluyen cuando importa del espacio de nombres Counter, de la siguiente manera:

namespace import Counter::*

Sin embargo, el procedimiento Check no se exporta, por lo que la operación de importación lo ignora.

El comando namespace import solo importa comandos que fueron declarados como exportados por su espacio de nombres. El comando namespace export especifica qué comandos pueden ser importados por otros espacios de nombres. Si un comando namespace import especifica un comando que no está exportado, el comando no se importa.

SCRIPTS CON ÁMBITO

El comando namespace code es el medio por el cual un script puede empaquetarse para su evaluación en un espacio de nombres distinto al en el que se creó. Se utiliza con mayor frecuencia para crear manejadores de eventos, enlaces Tk y rastreos para su evaluación en el contexto global. Por ejemplo, el siguiente código indica cómo dirigir una devolución de llamada de rastreo de variables al espacio de nombres actual:

namespace eval a {
    variable b
    proc theTraceCallback { n1 n2 op } {
        upvar 1 $n1 var
        puts "the value of $n1 has changed to $var"
        return
    }
    trace add variable b write [namespace code theTraceCallback]
}
set a::b c

Cuando se ejecuta, imprime el mensaje:

the value of a::b has changed to c

ENSEMBLES

El comando namespace ensemble se utiliza para crear y manipular comandos de conjunto (ensemble), que son comandos formados por la agrupación de subcomandos. Los comandos provienen típicamente del espacio de nombres actual cuando se creó el conjunto, aunque esto es configurable. Tenga en cuenta que puede haber cualquier número de conjuntos asociados con cualquier espacio de nombres (incluyendo ninguno, lo cual es cierto para todos los espacios de nombres por defecto), aunque todos los conjuntos asociados con un espacio de nombres se eliminan cuando se elimina ese espacio de nombres. El enlace entre un comando de conjunto y su espacio de nombres se mantiene, independientemente de cómo se renombre el conjunto.

Se definen tres subcomandos del comando namespace ensemble:

namespace ensemble create ?option value ...?
Crea un nuevo comando de conjunto enlazado al espacio de nombres actual, devolviendo el nombre completamente calificado del comando creado. Los argumentos de namespace ensemble create permiten la configuración del comando como con el comando namespace ensemble configure. Si no se anula con la opción -command, este comando crea un conjunto con exactamente el mismo nombre que el espacio de nombres enlazado. Consulte la sección OPCIONES DE CONJUNTO a continuación para obtener una lista completa de las opciones admitidas y sus efectos.
namespace ensemble configure command ?option? ?value ...?
Recupera el valor de una opción asociada con el comando de conjunto llamado command, o actualiza algunas opciones asociadas con ese comando de conjunto. Consulte la sección OPCIONES DE CONJUNTO a continuación para obtener una lista completa de las opciones admitidas y sus efectos.
namespace ensemble exists command
Devuelve un valor booleano que describe si el comando command existe y es un comando de conjunto. Este comando solo devuelve un error si el número de argumentos para el comando es incorrecto.

Cuando se llama, un comando de conjunto toma su primer argumento y lo busca (según las reglas descritas a continuación) para descubrir una lista de palabras con las que reemplazar el comando de conjunto y el subcomando. La lista resultante de palabras se evalúa (sin más s

substitutions) como si eso fuera lo que se escribió originalmente (es decir, pasando la lista de palabras a través de Tcl_EvalObjv) y devolviendo el resultado del comando. Tenga en cuenta que es legal hacer que el objetivo de una reescritura de un ensemble sea otro comando ensemble (o incluso el mismo). El comando ensemble no será visible a través del uso de los comandos uplevel o info level.

OPCIONES DE ENSEMBLE

Las siguientes opciones, compatibles con los comandos namespace ensemble create y namespace ensemble configure, controlan cómo se comporta un comando ensemble:

-map
Cuando no está vacío, esta opción proporciona un diccionario que ofrece un mapeo desde nombres de subcomandos a una lista de palabras prefijas para sustituir en lugar del comando ensemble y las palabras del subcomando (de manera similar a un alias creado con interp alias; las palabras no se vuelven a analizar después de la sustitución); si la primera palabra de cualquier objetivo no está completamente calificada cuando se establece, se asume que es relativa al *espacio de nombres actual* y se cambia para que sea exactamente eso (es decir, siempre está completamente calificada cuando se lee). Cuando esta opción está vacía, el mapeo será desde el nombre local del subcomando a su nombre completamente calificado. Tenga en cuenta que cuando esta opción no está vacía y la opción -subcommands está vacía, los nombres de los subcomandos del ensemble serán exactamente aquellas palabras que tengan mapeos en el diccionario.
-parameters
Esta opción proporciona una lista de argumentos con nombre (los nombres se utilizan durante la generación de mensajes de error) que son pasados por el llamador del ensemble entre el nombre del ensemble y el argumento del subcomando. Por defecto, es la lista vacía.
-prefixes
Esta opción (que está habilitada por defecto) controla si el comando ensemble reconoce prefijos no ambiguos de sus subcomandos. Cuando se desactiva, el comando ensemble requiere una coincidencia exacta de los nombres de los subcomandos.
-subcommands
Cuando no está vacío, esta opción lista exactamente qué subcomandos hay en el ensemble. El mapeo para cada uno de esos comandos será ya sea lo que esté definido en la opción -map, o al comando con el mismo nombre en el espacio de nombres enlazado al ensemble. Si esta opción está vacía, los subcomandos del espacio de nombres serán las claves del diccionario listado en la opción -map o los comandos exportados del espacio de nombres enlazado en el momento de la invocación del comando ensemble.
-unknown
Cuando no está vacío, esta opción proporciona un comando parcial (al cual se añaden todas las palabras que son argumentos del comando ensemble, incluido el nombre completamente calificado del ensemble) para manejar el caso en que un subcomando del ensemble no se reconoce y de lo contrario generaría un error. Cuando está vacío (por defecto), se genera un error (al estilo de Tcl_GetIndexFromObj) cada vez que el ensemble no puede determinar cómo implementar un subcomando en particular. Ver COMPORTAMIENTO DEL MANEJADOR DESCONOCIDO para más detalles.

La siguiente opción adicional es permitida por namespace ensemble create:

-command
Esta opción de solo escritura permite que el nombre del ensemble creado por namespace ensemble create sea cualquier cosa en cualquier espacio de nombres existente. El valor por defecto para esta opción es el nombre completamente calificado del espacio de nombres en el cual se invoca el comando namespace ensemble create.

La siguiente opción adicional es permitida por namespace ensemble configure:

-namespace
Esta opción de solo lectura permite la recuperación del nombre completamente calificado del espacio de nombres en el cual se creó el ensemble.

COMPORTAMIENTO DEL MANEJADOR DESCONOCIDO

Si se especifica un manejador desconocido para un ensemble, ese manejador se llama cuando el comando ensemble de lo contrario devolvería un error debido a que no puede decidir qué subcomando invocar. Las condiciones exactas bajo las cuales ocurre eso están controladas por las opciones -subcommands, -map y -prefixes, como se describe arriba.

Para ejecutar el manejador desconocido, el mecanismo de ensemble toma la opción -unknown especificada y añade cada argumento de la invocación de comando de ensemble intentada (incluido el propio comando ensemble, expresado como un nombre completamente calificado). Invoca el comando resultante en el ámbito de la llamada intentada. Si la ejecución del manejador desconocido termina normalmente, el motor de ensemble vuelve a analizar el subcomando (como se describe a continuación) e intenta despacharlo de nuevo, lo cual es ideal cuando la configuración del ensemble ha sido actualizada por el manejador de subcomando desconocido. Cualquier otro tipo de terminación del manejador desconocido se trata como un error.

Se espera que el resultado del manejador desconocido sea una lista (es un error si no lo es). Si la lista está vacía, el comando ensemble intenta buscar de nuevo el subcomando original y, si no se encuentra esta vez, se generará un error como si el manejador -unknown no estuviera allí (es decir, para cualquier invocación particular de un ensemble, su manejador desconocido se llamará como máximo una vez). Esto facilita que el manejador desconocido actualice el ensemble o su espacio de nombres de respaldo para proporcionar una implementación del subcomando deseado y volver a analizar.

Cuando el resultado es una lista no vacía, las palabras de esa lista se utilizan para reemplazar el comando ensemble y el subcomando, como si hubieran sido buscadas en el -map. Es responsabilidad del manejador desconocido proporcionar todos los calificadores de espacio de nombres si el subcomando implementador no está en el espacio de nombres del llamador del comando ensemble. Tenga en cuenta también que cuando los comandos ensemble están encadenados (por ejemplo, si convierte uno de los comandos que implementan un subcomando ensemble en un ensemble, de manera similar a los subcomandos de etiqueta y marca del widget text) la reescritura ocurre en el contexto del llamador del ensemble más externo. Es decir, los ensembles no colocan contextos de espacio de nombres en la pila de llamadas de Tcl por sí mismos.

Donde se proporciona un manejador -unknown vacío (el predeterminado), el comando ensemble generará un mensaje de error basado en la lista de comandos que el ensemble ha definido (formateado de manera similar al mensaje de error de Tcl_GetIndexFromObj). Este es el error que se lanzará cuando el subcomando aún no se reconozca durante el reanálisis. También es un error que un manejador -unknown elimine su espacio de nombres.

EJEMPLOS

Cree un espacio de nombres que contenga una variable y un comando exportado:

namespace eval foo {
    variable bar 0
    proc grill {} {
        variable bar
        puts "llamado [incr bar] veces"
    }
    namespace export grill
}

Llame al comando definido en el ejemplo anterior de varias maneras.

# Llamada directa
::foo::grill
# Utilice la ruta de resolución de comandos para encontrar el nombre
namespace eval boo {
    namespace path ::foo
    grill
}
# Importar al espacio de nombres actual, luego llamar a un alias local
namespace import foo::grill
grill
# Cree dos ensembles, uno con el nombre predeterminado y otro con un
# nombre especificado. Luego llámelos a través de los ensembles.
namespace eval foo {
    namespace ensemble create
    namespace ensemble create -command ::foobar
}
foo grill
foobar grill

Busque de dónde provino el comando importado en el ejemplo anterior:

puts "grill vino de [namespace origin grill]"

Elimine todos los comandos importados del espacio de nombres actual:

namespace forget {*}[namespace import]

Cree un ensemble para trabajar de forma simple con números, usando la opción -parameters para permitir que el operador se coloque entre el primer y el segundo argumento.

namespace eval do {
    namespace export *
    namespace ensemble create -parameters x
    proc plus  {x y} {expr { $x + $y }}
    proc minus {x y} {expr { $x - $y }}
}
# En uso, el ensemble funciona así:
puts [do 1 plus [do 9 minus 7]]
