NOMBRE

namespaces - resumen de los namespaces de Linux

DESCRIPCIÓN

Un namespace encapsula un recurso global del sistema en una abstracción que hace que parezca a los procesos dentro del namespace que tienen su propia instancia aislada del recurso global. Los cambios en el recurso global son visibles para otros procesos que son miembros del namespace, pero son invisibles para otros procesos. Un uso de los namespaces es la implementación de contenedores.

Esta página proporciona punteros a información sobre los diversos tipos de namespaces, describe los archivos asociados de /proc y resume las APIs para trabajar con namespaces.

Tipos de namespaces

La siguiente tabla muestra los tipos de namespaces disponibles en Linux. La segunda columna de la tabla muestra el valor de la bandera que se utiliza para especificar el tipo de namespace en varias APIs. La tercera columna identifica la página del manual que proporciona detalles sobre el tipo de namespace. La última columna es un resumen de los recursos que son aislados por el tipo de namespace.

Namespace Bandera Página Aísla
Cgroup CLONE_NEWCGROUP cgroup_namespaces(7) Directorio raíz de Cgroup
IPC CLONE_NEWIPC ipc_namespaces(7) IPC System V, colas de mensajes POSIX
Red CLONE_NEWNET network_namespaces(7) Dispositivos de red, pilas, puertos, etc.
Montaje CLONE_NEWNS mount_namespaces(7) Puntos de montaje
PID CLONE_NEWPID pid_namespaces(7) IDs de procesos
Tiempo CLONE_NEWTIME time_namespaces(7) Relojes de arranque y monotónicos
Usuario CLONE_NEWUSER user_namespaces(7) IDs de usuario y grupo
UTS CLONE_NEWUTS uts_namespaces(7) Nombre de host y nombre de dominio NIS

La API de namespaces

Además de varios archivos de /proc descritos a continuación, la API de namespaces incluye las siguientes llamadas al sistema:

clone(2)
La llamada al sistema clone(2) crea un nuevo proceso. Si el argumento flags de la llamada especifica una o más de las banderas CLONE_NEW* listadas anteriormente, entonces se crean nuevos namespaces para cada bandera, y el proceso hijo se convierte en miembro de esos namespaces. (Esta llamada al sistema también implementa un número de características no relacionadas con los namespaces).
setns(2)
La llamada al sistema setns(2) permite al proceso que llama unirse a un namespace existente. El namespace al que unirse se especifica a través de un descriptor de archivo que hace referencia a uno de los archivos de /proc/pid/ns descritos a continuación.
unshare(2)
La llamada al sistema unshare(2) mueve el proceso que llama a un nuevo namespace. Si el argumento flags de la llamada especifica una o más de las banderas CLONE_NEW* listadas anteriormente, entonces se crean nuevos namespaces para cada bandera, y el proceso que llama se convierte en miembro de esos namespaces. (Esta llamada al sistema también implementa un número de características no relacionadas con los namespaces).
ioctl(2)
Varias operaciones de ioctl(2) se pueden usar para descubrir información sobre los namespaces. Estas operaciones se describen en ioctl_nsfs(2).

La creación de nuevos namespaces usando clone(2) y unshare(2) en la mayoría de los casos requiere la capacidad CAP_SYS_ADMIN, ya que, en el nuevo namespace, el creador tendrá el poder de cambiar recursos globales que son visibles para otros procesos que son creados posteriormente en el namespace o se unen a él. Los namespaces de usuario son la excepción: desde Linux 3.8, no se requiere privilegios para crear un namespace de usuario.

El directorio /proc/pid/ns/

Cada proceso tiene un subdirectorio /proc/pid/ns/ que contiene una entrada para cada namespace que admite la manipulación por setns(2):


$ ls -l /proc/$$/ns | awk '{print $1, $9, $10, $11}'
total 0
lrwxrwxrwx. cgroup -> cgroup:[4026531835]
lrwxrwxrwx. ipc -> ipc:[4026531839]
lrwxrwxrwx. mnt -> mnt:[4026531840]
lrwxrwxrwx. net -> net:[4026531969]
lrwxrwxrwx. pid -> pid:[4026531836]
lrwxrwxrwx. pid_for_children -> pid:[4026531834]
lrwxrwxrwx. time -> time:[4026531834]
lrwxrwxrwx. time_for_children -> time:[4026531834]
lrwxrwxrwx. user -> user:[4026531837]
lrwxrwxrwx. uts -> uts:[4026531838]

Montar (véase mount(2)) uno de los archivos de este directorio en otro lugar del sistema de archivos mantiene vivo el namespace correspondiente del proceso especificado por pid, incluso si todos los procesos actualmente en el namespace terminan.

Abrir uno de los archivos de este directorio (o un archivo que esté montado en uno de estos archivos) devuelve un manejador de archivo para el namespace correspondiente del proceso especificado por pid. Mientras este descriptor de archivo permanezca abierto, el namespace seguirá vivo, incluso si todos los procesos en el namespace terminan. El descriptor de archivo puede pasarse a setns(2).

En Linux 3.7 y anteriores, estos archivos eran visibles como enlaces duros. Desde Linux 3.8, aparecen como enlaces simbólicos. Si dos procesos están en el mismo namespace, entonces los IDs de dispositivo y los números de inodo de sus enlaces simbólicos de /proc/pid/ns/xxx serán los mismos; una aplicación puede comprobar esto usando los campos stat.st_dev y stat.st_ino devueltos por stat(2). El contenido de este enlace simbólico es una cadena que contiene el tipo de namespace y el número de inodo, como en el siguiente ejemplo:


$ readlink /proc/$$/ns/uts
uts:[4026531838]

Los enlaces simbólicos en este subdirectorio son los siguientes:

/proc/pid/ns/cgroup (desde Linux 4.6)
Este archivo es un manejador para el namespace de cgroup del proceso.
/proc/pid/ns/ipc (desde Linux 3.0)
Este archivo es un manejador para el namespace IPC del proceso.
/proc/pid/ns/mnt (desde Linux 3.8)
Este archivo es un manejador para el namespace de montaje del proceso.
/proc/pid/ns/net (desde Linux 3.0)
Este archivo es un manejador para el namespace de red del proceso.
/proc/pid/ns/pid (desde Linux 3.8)
Este archivo es un manejador para el namespace PID del proceso. Este manejador es permanente durante la vida útil del proceso (es decir, la membresía del namespace PID de un proceso nunca cambia).
/proc/pid/ns/pid_for_children (desde Linux 4.12)
Este archivo es un manejador para el namespace PID de los procesos hijos creados por este proceso. Esto puede cambiar como consecuencia de llamadas a unshare(2) y setns(2) (véase pid_namespaces(7)), por lo que el archivo puede diferir de /proc/pid/ns/pid. El enlace simbólico obtiene un valor solo después de que el primer proceso hijo se crea en el namespace. (Previamente, readlink(2) del enlace simbólico devolverá un buffer vacío.)
/proc/pid/ns/time (desde Linux 5.6)
Este archivo es un manejador para el namespace de tiempo n

NAME

namespaces — Linux namespaces

DESCRIPTION

Namespaces are a feature of the Linux kernel that allows a system to be divided into multiple instances of certain resources, each instance having its own view of the global system. The kernel implements several types of namespaces. Each namespace type isolates a specific part of the system.

When a process is created using clone(2) or unshare(2) with appropriate flags, it can be placed into a new namespace or joined to an existing one. Processes within a namespace have a restricted view of the system, and actions performed by them may not be visible to processes outside the namespace, and vice versa.

The following namespace types are implemented:

Cgroup namespaces
Isolates the process's view of its cgroup hierarchy. The root cgroup in this namespace corresponds to some cgroup in the host's cgroup hierarchy. See cgroup_namespaces(7).
IPC namespaces
Isolate System V IPC objects and POSIX message queues. See ipc_namespaces(7).
Mount namespaces
Isolate the set of filesystem mount points. Creating a mount namespace results in a copy of the current mount namespace's mount table. Operations on mount points within the new namespace do not affect the parent namespace. See mount_namespaces(7).
Network namespaces
Isolate network resources. These include network devices, IP addresses, IP routing tables, firewall rules, port numbers, etc. See network_namespaces(7).
PID namespaces
Isolate the process ID number space. Processes in a new PID namespace have new PIDs, starting from 1. The parent PID namespace is seen as the parent of the root process in the new namespace. See pid_namespaces(7).
Time namespaces
Isolate the system's concept of time. This allows processes within the time namespace to have a different system time, boot time, and monotonic clock time than processes outside the namespace. See time_namespaces(7).
User namespaces
Isolate user and group identifiers. This allows a process to have a full set of privileges (e.g., root) within its user namespace, while having a non-privileged identity on the host system. See user_namespaces(7).
UTS namespaces
Isolate the hostname and NIS domain name. Processes in a UTS namespace can have their own hostname and domain name, different from those in other UTS namespaces. See uts_namespaces(7).

Process namespace links

The directory /proc/pid/ns/ contains symbolic links that allow inspection of the namespaces associated with a process pid. The links are as follows:

/proc/pid/ns/cgroup (since Linux 4.6)
This file is a handle for the cgroup namespace of the process.
/proc/pid/ns/init (since Linux 5.9)
This file is a handle for the init namespace of the process. This namespace is effectively the same as the PID namespace, but with a special root process (PID 1) that uses the init system provided by the namespace. When a new PID namespace is created, the initial process inside it becomes PID 1, and it is responsible for starting and managing other processes. This namespace is therefore tied to the PID namespace.
/proc/pid/ns/ipc (since Linux 3.8)
This file is a handle for the IPC namespace of the process.
/proc/pid/ns/mnt (since Linux 3.8)
This file is a handle for the mount namespace of the process.
/proc/pid/ns/net (since Linux 3.0)
This file is a handle for the network namespace of the process.
/proc/pid/ns/pid (since Linux 3.0)
This file is a handle for the PID namespace of the process.
/proc/pid/ns/pid_for_children (since Linux 5.9)
This file is a handle for the PID namespace of child processes created by this process. This can change as a consequence of calls to unshare(2) and setns(2).
/proc/pid/ns/time (since Linux 5.6)
This file is a handle for the time namespace of the process.
/proc/pid/ns/time_for_children (since Linux 5.6)
This file is a handle for the time namespace of child processes created by this process. This can change as a consequence of calls to unshare(2) and setns(2) (see time_namespaces(7)), so the file may differ from /proc/pid/ns/time.
/proc/pid/ns/user (since Linux 3.8)
This file is a handle for the user namespace of the process.
/proc/pid/ns/uts (since Linux 3.0)
This file is a handle for the UTS namespace of the process.

Permission to dereference or read (readlink(2)) these symbolic links is governed by a ptrace access mode PTRACE_MODE_READ_FSCREDS check; see ptrace(2).

The /proc/sys/user directory

The files in the /proc/sys/user directory (which is present since Linux 4.9) expose limits on the number of namespaces of various types that can be created. The files are as follows:

max_cgroup_namespaces
The value in this file defines a per-user limit on the number of cgroup namespaces that may be created in the user namespace.
max_ipc_namespaces
The value in this file defines a per-user limit on the number of ipc namespaces that may be created in the user namespace.
max_mnt_namespaces
The value in this file defines a per-user limit on the number of mount namespaces that may be created in the user namespace.
max_net_namespaces
The value in this file defines a per-user limit on the number of network namespaces that may be created in the user namespace.
max_pid_namespaces
The value in this file defines a per-user limit on the number of PID namespaces that may be created in the user namespace.
max_time_namespaces (since Linux 5.7)
The value in this file defines a per-user limit on the number of time namespaces that may be created in the user namespace.
max_user_namespaces
The value in this file defines a per-user limit on the number of user namespaces that may be created in the user namespace.
max_uts_namespaces
The value in this file defines a per-user limit on the number of uts namespaces that may be created in the user namespace.

Note the following details about these files:

•
The values in these files are modifiable by privileged processes.
•
The values exposed by these files are the limits for the user namespace in which the opening process resides.
•
The limits are per-user. Each user in the same user namespace can create namespaces up to the defined limit.
•
The limits apply to all users, including UID 0.
•
These limits apply in addition to any other per-namespace limits (such as those for PID and user namespaces) that may be enforced.
•
Upon encountering these limits, clone(2) and unshare(2) fail with the error ENOSPC.
•
For the initial user namespace, the default value in each of these files is half the limit on the number of threads that may be created (/proc/sys/kernel/threads-max). In all descendant user namespaces, the default value in each file is MAXINT.
•
When a namespace is created, the object is also accounted against ancestor namespaces. More precisely:
•
Each user namespace has a creator UID.
•
When a namespace is created, it is accounted against the creator UIDs in each of the ancestor user namespaces, and the kernel ensures that the corresponding namespace limit for the creator UID in the ancestor namespace is not exceeded.
•
The aforementioned point ensures that creating a new user namespace cannot be used as a means to escape the limits in force in the current user namespace.

Namespace lifetime

Absent any other factors, a namespace is automatically torn down when the last process in the namespace terminates or leaves the namespace. However, there are a number of other factors that may pin a namespace into existence even though it has no member processes. These factors include the following:

•
An open file descriptor or a bind mount exists for the corresponding /proc/pid/ns/* file.
•
The namespace is hierarchical (i.e., a PID or user namespace), and has a child namespace.
•
It is a user namespace that owns one or more nonuser namespaces.
•
It is a PID namespace, and there is a process that refers to the namespace via a /proc/pid/ns/pid_for_children symbolic link.
•
It is a time namespace, and there is a process that refers to the namespace via a /proc/pid/ns/time_for_children symbolic link.
•
It is an IPC namespace, and a corresponding mount of an mqueue filesystem (see mq_overview(7)) refers to this namespace.
•
It is a PID namespace, and a corresponding mount of a proc(5) filesystem refers to this namespace.
