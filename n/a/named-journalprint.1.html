NOMBRE

named-journalprint - imprimir el diario de zona en formato legible por humanos

SINOPSIS

named-journalprint [-c serial] [-dux] {journal}

DESCRIPCIÓN

named-journalprint escanea el contenido de un archivo de diario de zona, imprimiéndolo en un formato legible por humanos o, opcionalmente, convirtiéndolo a un formato de archivo de diario diferente.

Los archivos de diario son creados automáticamente por named <#std-iscman-named> cuando se realizan cambios en zonas dinámicas (por ejemplo, por nsupdate <#std-iscman-nsupdate>). Registran cada adición o eliminación de un registro de recursos, en formato binario, permitiendo que los cambios se reapliquen a la zona cuando el servidor se reinicia después de una detención o fallo. Por defecto, el nombre del archivo de diario se forma añadiendo la extensión .jnl al nombre del archivo de zona correspondiente.

named-journalprint convierte el contenido de un archivo de diario dado a un formato de texto legible por humanos. Cada línea comienza con add o del, para indicar si el registro se añadió o se eliminó, y continúa con el registro de recursos en formato de archivo maestro.

La opción -c (compacto) proporciona un mecanismo para reducir el tamaño de un diario eliminando (la mayoría/todos) las transacciones anteriores al número de serie especificado. Nota: esta opción *no debe* usarse mientras named <#std-iscman-named> se está ejecutando, y puede causar pérdida de datos si el archivo de zona no se ha actualizado para contener los datos que se están eliminando del diario. Úsela con extrema precaución.

La opción -x hace que se impriman datos adicionales sobre el archivo de diario al principio de la salida y antes de cada grupo de cambios.

Las opciones -u (actualizar) y -d (reducir) recrean el archivo de diario con una versión de formato modificada. El archivo de diario existente se reemplaza. -d escribe el diario en el formato utilizado por las versiones de BIND hasta 9.16.11; -u lo escribe en el formato utilizado por las versiones desde 9.16.13. (9.16.12 se omite debido a un error de formato de diario en esa versión). Tenga en cuenta que estas opciones *no deben* usarse mientras named <#std-iscman-named> se está ejecutando.

VER TAMBIÉN

named(8) <#std-iscman-named>, nsupdate(1) <#std-iscman-nsupdate>, Manual de Referencia del Administrador de BIND 9.
