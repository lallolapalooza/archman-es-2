NOMBRE

named-checkzone - herramienta de verificación de validez o conversión de archivos de zona

SINOPSIS

named-checkzone [-d] [-h] [-j] [-q] [-v] [-c clase] [-C modo] [-f formato] [-F formato] [-J nombrearchivo] [-i modo] [-k modo] [-m modo] [-M modo] [-n modo] [-l ttl] [-L número_serie] [-o nombrearchivo] [-r modo] [-s estilo] [-S modo] [-t directorio] [-T modo] [-w directorio] [-D] [-W modo] {nombre_zona} {nombrearchivo}

DESCRIPCIÓN

named-checkzone comprueba la sintaxis y la integridad de un archivo de zona. Realiza las mismas comprobaciones que named <#std-iscman-named> al cargar una zona. Esto hace que named-checkzone sea útil para comprobar archivos de zona antes de configurarlos en un servidor de nombres.

OPCIONES

-d
Esta opción activa la depuración.
-h
Esta opción imprime el resumen de uso y sale.
-q
Esta opción establece el modo silencioso, que solo establece un código de salida para indicar la finalización correcta o fallida.
-v
Esta opción imprime la versión del programa named-checkzone y sale.
-j
Al cargar un archivo de zona, esta opción le indica a named <#std-iscman-named> que lea el diario si existe. Se asume que el nombre del archivo del diario es el nombre del archivo de zona con la cadena .jnl añadida.
-J nombrearchivo
Al cargar el archivo de zona, esta opción le indica a named <#std-iscman-named> que lea el diario del archivo proporcionado, si existe. Esto implica -j.
-c clase
Esta opción especifica la clase de la zona. Si no se especifica, se asume IN.
-C modo
Esta opción controla el modo de comprobación en los archivos de zona al cargar. Los modos posibles son check-svcb:fail e check-svcb:ignore.

check-svcb:fail activa comprobaciones adicionales en los registros SVCB de _dns y check-svcb:ignore deshabilita estas comprobaciones. El valor predeterminado es check-svcb:fail.

-i modo
Esta opción realiza comprobaciones de integridad de la zona posteriores a la carga. Los modos posibles son full (predeterminado), full-sibling, local, local-sibling y none.

El modo full comprueba que los registros MX se refieran a registros A o AAAA (tanto nombres de host dentro como fuera de la zona). El modo local solo comprueba los registros MX que se refieren a nombres de host dentro de la zona.

El modo full comprueba que los registros SRV se refieran a registros A o AAAA (tanto nombres de host dentro como fuera de la zona). El modo local solo comprueba los registros SRV que se refieren a nombres de host dentro de la zona.

El modo full comprueba que los registros NS de delegación se refieran a registros A o AAAA (tanto nombres de host dentro como fuera de la zona). También comprueba que los registros de pegamento (glue) de direcciones en la zona coincidan con los anunciados por el hijo. El modo local solo comprueba los registros NS que se refieren a nombres de host dentro de la zona o verifica que existe algún pegamento necesario, es decir, cuando el servidor de nombres está en una zona hija.

Los modos full-sibling y local-sibling deshabilita las comprobaciones de pegamento de hermanos, pero por lo demás son iguales a full y local, respectivamente.

El modo none deshabilita las comprobaciones.

-f formato
Esta opción especifica el formato del archivo de zona. Los formatos posibles son text (predeterminado) y raw.
-F formato
Esta opción especifica el formato del archivo de salida proporcionado. Para named-checkzone, esto no tiene ningún efecto a menos que vuelque el contenido de la zona.

Los formatos posibles son text (predeterminado), que es la representación textual estándar de la zona, y raw y raw=N, que almacenan la zona en formato binario para una carga rápida por parte de named <#std-iscman-named>. raw=N especifica la versión del formato del archivo de zona sin procesar: si N es 0, el archivo sin procesar puede ser leído por cualquier versión de named <#std-iscman-named>; si N es 1, el archivo solo puede ser leído por la versión 9.9.0 o superior. El valor predeterminado es 1.

-k modo
Esta opción realiza comprobaciones check-names con el modo de fallo especificado. Los modos posibles son fail, warn (predeterminado) e ignore.
-l ttl
Esta opción establece un TTL máximo permisible para el archivo de entrada. Cualquier registro con un TTL superior a este valor hará que la zona sea rechazada. Esto es similar a usar la opción max-zone-ttl en named.conf <#std-iscman-named.conf>.
-L número_serie
Al compilar una zona al formato raw, esta opción establece el valor del "número de serie de origen" en la cabecera al número de serie especificado. Se espera que esto se utilice principalmente con fines de prueba.
-m modo
Esta opción especifica si se deben comprobar los registros MX para ver si son direcciones. Los modos posibles son fail, warn (predeterminado) e ignore.
-M modo
Esta opción comprueba si un registro MX se refiere a un CNAME. Los modos posibles son fail, warn (predeterminado) e ignore.
-n modo
Esta opción especifica si se deben comprobar los registros NS para ver si son direcciones. Los modos posibles son fail, warn (predeterminado) e ignore.
-o nombrearchivo
Esta opción escribe la salida de la zona en nombrearchivo. Si nombrearchivo es -, entonces la salida de la zona se escribe en la salida estándar.
-r modo
Esta opción comprueba si hay registros que se tratan de forma diferente por DNSSEC pero que son semánticamente iguales en DNS simple. Los modos posibles son fail, warn (predeterminado) e ignore.
-s estilo
Esta opción especifica el estilo del archivo de zona volcado. Los estilos posibles son full (predeterminado) y relative. El formato full es el más adecuado para ser procesado automáticamente por un script separado. El formato relative es más legible para humanos y, por lo tanto, adecuado para editarlo a mano. Esto no tiene ningún efecto a menos que se vuelque el contenido de la zona. Tampoco tiene ningún significado si el formato de salida no es texto.
-S modo
Esta opción comprueba si un registro SRV se refiere a un CNAME. Los modos posibles son fail, warn (predeterminado) e ignore.
-t directorio
Esta opción le indica a named <#std-iscman-named> que realice un chroot en directorio, de modo que
-T modo
Esta opción especifica el modo de comprobación de nombres para la delegación de la zona. Los modos posibles son fail, warn (predeterminado) e ignore.
-w directorio
Esta opción le indica a named <#std-iscman-named> que cambie el directorio de trabajo a directorio. Esto se utiliza para garantizar que los archivos de zona se carguen desde el directorio correcto en un entorno chrooted. El comportamiento predeterminado es no cambiar el directorio de trabajo.
-D
Esta opción comprueba los registros con un TTL cero.
-W modo
Esta opción especifica el modo de comprobación de nombres para las zonas del servidor principal. Los modos posibles son fail, warn (predeterminado) e ignore.
zonename
El nombre de la zona que se va a comprobar. Por ejemplo, example.com.
filename
El nombre del archivo de zona que se va a comprobar. Por ejemplo, db.example.com.

EJEMPLOS

Para comprobar el archivo de zona db.example.com para la zona example.com, utilice:

named-checkzone example.com db.example.com

Para comprobar el archivo de zona db.example.com para la zona example.com y volcarlo al archivo out.zone en formato de texto, utilice:

named-checkzone -o out.zone example.com db.example.com

Para comprobar el archivo de zona db.example.com para la zona example.com y volcarlo al archivo out.raw en formato binario, utilice:

named-checkzone -o out.raw -F raw=1 example.com db.example.com

named(8), named.conf(5).

named-checkzone(8) — Arch Linux

NAME

named-checkzone - check zone file syntax

SYNOPSIS

named-checkzone [-a] [-c view] [-d] [-e errorfile] [-f format] [-i charsets] [-k mode] [-l level] [-m mode] [-n name] [-q] [-r] [-t chrootdir] [-T mode] [-w directory] [-D] [-W mode] [zonename] [filename]

DESCRIPTION

The named-checkzone utility checks the syntax of a zone file. It reads the zone file specified by filename, parses it, and checks it for correctness against the specified zonename.

If the zone file is syntactically correct, named-checkzone prints the following message to standard output:

zone zonename/IN: loaded serial 123
OK

If errors are found, they are printed to standard error. The exit status is 1 if errors were detected, and 0 otherwise.

The named-checkzone utility can also be used to check the configuration files used by named(8) <#std-iscman-named>.

OPTIONS

-a
This option checks that all records in the zone file are correctly formed, and that no records are present that are not part of the zone.
-c view
This option checks the zone file for a specific view. If no view is specified, the default view is used.
-d
This option turns on debugging output.
-e errorfile
This option writes error messages to the specified errorfile instead of standard error.
-f format
This option specifies the input file format. Possible formats are relaxed (the default) and text.
-i charsets
This option specifies the character sets to be used for input and output. Possible modes are strict (the default) and relaxed.
-k mode
This option specifies whether to check for duplicate names. Possible modes are warn (the default) and ignore.
-l level
This option specifies the logging level. Possible levels are critical, error, warning, info, and debug.
-m mode
This option specifies whether to check for non-terminal wildcards. Possible modes are warn (the default) and ignore.
-n name
This option specifies the name of the zone to check. If not specified, the zone name is taken from the zone file.
-q
This option suppresses all output except for error messages.
-r
This option checks for reverse DNS records.
-t chrootdir
This option changes the root directory to chrootdir. This is useful when checking zone files that are located in a chrooted environment.
-T mode
This option checks whether Sender Policy Framework (SPF) records exist and issues a warning if an SPF-formatted TXT record is not also present. Possible modes are warn (the default) and ignore.
-w directory
This option instructs named <#std-iscman-named> to chdir to directory, so that relative filenames in master file $INCLUDE directives work. This is similar to the directory clause in named.conf <#std-iscman-named.conf>.
-D
This option dumps the zone file in canonical format.
-W mode
This option specifies whether to check for non-terminal wildcards. Non-terminal wildcards are almost always the result of a failure to understand the wildcard matching algorithm (RFC 4592 https://datatracker.ietf.org/doc/html/rfc4592.html). Possible modes are warn (the default) and ignore.
zonename
This indicates the domain name of the zone being checked.
filename
This is the name of the zone file.

RETURN VALUES

named-checkzone returns an exit status of 1 if errors were detected and 0 otherwise.
