NOMBRE

namespace.conf - el archivo de configuración de namespace

DESCRIPCIÓN

El módulo pam_namespace.so permite configurar espacios de nombres privados con directorios poli-instanciados. Los directorios pueden ser poli-instanciados basándose en el nombre de usuario o, en el caso de SELinux, en el nombre de usuario, el nivel de sensibilidad o el contexto de seguridad completo. Si existe un script ejecutable /etc/security/namespace.init, se utiliza para inicializar el espacio de nombres cada vez que se configura y monta un directorio de instancia. El script recibe la ruta del directorio poli-instanciado y la ruta del directorio de instancia como sus argumentos. El script se invoca con privilegios de root completos y el acceso al directorio de instancia en este contexto debe hacerse con precaución, ya que está controlado por el usuario no privilegiado para el que se ha creado.

El archivo /etc/security/namespace.conf especifica qué directorios son poli-instanciados, cómo se poli-instancian, cómo se nombrarían los directorios de instancia y para qué usuarios no se realizaría la poli-instanciación.

Cuando alguien inicia sesión, se escanea el archivo namespace.conf. Los comentarios se marcan con caracteres #. Cada línea que no es un comentario representa un directorio poli-instanciado. Los campos están separados por espacios pero pueden estar entrecomillados por caracteres " y también se reconocen secuencias de escape \b, \n y \t. Los campos son los siguientes:

directorio_poli prefijo_instancia método lista_de_uids

El primer campo, directorio_poli, es la ruta absoluta del directorio a poli-instanciar. La cadena especial $HOME se reemplaza con el directorio personal del usuario, y $USER con el nombre de usuario. Este campo no puede estar en blanco.

El segundo campo, prefijo_instancia, es la cadena de prefijo utilizada para construir la ruta del archivo para la instanciación de <directorio_poli>. La ruta debe terminar en una barra inclinada final, o en un prefijo de directorio utilizado para construir la ruta completa por instancia. Dependiendo del método de poli-instanciación, se le añadirá una "cadena de diferenciación de instancia" para generar la ruta final del directorio de instancia. Este directorio se crea si no existía previamente, y luego se monta como bind en el <directorio_poli> para proporcionar una instancia de <directorio_poli> basándose en la columna <método>. La cadena especial $HOME se reemplaza con el directorio personal del usuario, y $USER con el nombre de usuario. Este campo no puede estar en blanco.

El tercer campo, método, es el método utilizado para la poli-instanciación. Puede tomar los siguientes valores: "user" para poli-instanciación basada en el nombre de usuario, "level" para poli-instanciación basada en el nivel MLS del proceso y el nombre de usuario, "context" para poli-instanciación basada en el contexto de seguridad del proceso y el nombre de usuario, "tmpfs" para montar un sistema de archivos tmpfs como directorio de instancia, y "tmpdir" para crear un directorio temporal como directorio de instancia que se elimina cuando se cierra la sesión del usuario. Los métodos "context" y "level" solo están disponibles con SELinux. Este campo no puede estar en blanco.

El cuarto campo, lista_de_uids, es una lista separada por comas de nombres de usuario para los cuales no se realiza la poli-instanciación. Si se deja en blanco, la poli-instanciación se realizará para todos los usuarios. Si la lista va precedida de un solo carácter "~", la poli-instanciación se realiza solo para los usuarios de la lista.

El campo método también puede contener las siguientes banderas opcionales separadas por caracteres :.

create=modo,propietario,grupo - crea el directorio poli-instanciado. Los parámetros de modo, propietario y grupo son opcionales. El valor predeterminado para el modo se determina por umask, el propietario predeterminado es el usuario cuya sesión se abre, el grupo predeterminado es el grupo principal del usuario.

iscript=ruta - ruta al script init del directorio de instancia. El directorio base para rutas relativas es /etc/security/namespace.d.

noinit - no se ejecutará el script init del directorio de instancia.

shared - los directorios de instancia para los métodos "context" y "level" no contendrán el nombre de usuario y se compartirán entre todos los usuarios.

mntopts=valor - el valor de esta bandera se pasa a la llamada de montaje cuando se realiza el montaje de tmpfs. Permite, por ejemplo, especificar el tamaño máximo de la instancia tmpfs que se crea mediante la llamada de montaje. Además de las opciones especificadas en el manual de tmpfs(5), las banderas nosuid, noexec y nodev se pueden utilizar para deshabilitar respectivamente el efecto del bit setuid, deshabilitar la ejecución de ejecutables y deshabilitar la interpretación de dispositivos en el sistema de archivos tmpfs montado.

El directorio donde se crearán las instancias poli-instanciadas debe existir y, por defecto, debe tener el modo 0000. El requisito de que el padre de la instancia tenga el modo 0000 se puede anular con la opción de línea de comandos ignore_instance_parent_mode

En el caso de poli-instanciación por contexto o nivel, el contexto SELinux que se utiliza para la poli-instanciación es el contexto utilizado para ejecutar un nuevo proceso, tal como lo obtiene getexeccon. Este contexto debe ser establecido por la aplicación que llama o por el módulo pam_selinux.so. Si este contexto no está establecido, la poli-instanciación se basará únicamente en el nombre de usuario.

La "cadena de diferenciación de instancia" es <nombre de usuario> para el método "user" y <nombre de usuario>_<contexto de directorio raw> para los métodos "context" y "level". Si la cadena completa es demasiado larga, el final de la misma se reemplaza con su md5sum. También, cuando se utiliza la opción de línea de comandos gen_hash, la cadena completa se reemplaza con su md5sum.

EJEMPLOS

Estas son algunas líneas de ejemplo que podrían especificarse en /etc/security/namespace.conf.

      # Las siguientes tres líneas poli-instanciarán /tmp,
      # /var/tmp y los directorios personales de los usuarios. /tmp y /var/tmp
      # se poli-instanciarán basándose en el nivel de seguridad
      # así como en el nombre de usuario, mientras que el directorio personal se
      # poli-instanciará basándose en el contexto de seguridad completo y el nombre de usuario.
      # La poli-instanciación no se realizará para el usuario root
      # y adm para los directorios /tmp y /var/tmp, mientras que los directorios personales se
      # poli-instanciarán para todos los usuarios.
      #
      # Tenga en cuenta que los directorios de instancia no tienen que residir dentro
      # del directorio poli-instanciado. En los ejemplos siguientes,
      # las instancias de /tmp se crearán en el directorio /tmp-inst,
      # mientras que las instancias de /var/tmp y los directorios personales de los usuarios
      # residirán dentro de los directorios que se están
      # poli-instanciando.
      #
      /tmp     /tmp-inst/               level      root,adm
      /var/tmp /var/tmp/tmp-inst/   	level      root,adm
      $HOME    $HOME/$USER.inst/inst- context

Para los <servicio>s que requieren poli-instanciación (login, por ejemplo), coloque la siguiente línea en /etc/pam.d/<servicio> como la última línea del grupo de sesiones:

session required pam_namespace.so [argumentos]

Este módulo también depende de que pam_selinux.so establezca el contexto.
