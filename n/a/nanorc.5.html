NANORC(5) Manual de Formatos de Archivo NANORC(5)

NOMBRE

nanorc - Archivo de configuración de GNU nano

DESCRIPCIÓN

Los archivos nanorc contienen los ajustes predeterminados para nano, un editor de texto pequeño y amigable. Durante el inicio, si no se proporciona --rcfile, nano lee dos archivos: primero la configuración a nivel de sistema, desde /etc/nanorc (la ruta exacta puede ser diferente en tu sistema), y luego la configuración específica del usuario, ya sea desde ~/.nanorc o desde $XDG_CONFIG_HOME/nano/nanorc o desde ~/.config/nano/nanorc, el que se encuentre primero. Si se proporciona --rcfile, nano lee solo el archivo de configuración especificado.

AVISO

Desde la versión 8.0, para ser amigable con los recién llegados, ^F inicia una búsqueda hacia adelante, ^B inicia una búsqueda hacia atrás, M-F busca la siguiente ocurrencia hacia adelante y M-B busca la siguiente ocurrencia hacia atrás. Si deseas que esas combinaciones de teclas hagan lo que hacían antes de la versión 8.0, añade las siguientes líneas al final de tu archivo nanorc:

bind ^F forward main
bind ^B back main
bind M-F formatter main
bind M-B linter main

OPCIONES

El archivo de configuración acepta una serie de comandos set y unset, que se pueden usar para configurar nano al inicio sin usar opciones de línea de comandos. Además, hay algunos comandos para definir el resaltado de sintaxis y para reasignar teclas — consulta las dos secciones separadas sobre estos temas. nano lee un comando por línea. Todos los comandos y palabras clave deben escribirse en minúsculas.

Las opciones en los archivos nanorc tienen prioridad sobre los valores predeterminados de nano, y las opciones de línea de comandos anulan la configuración de nanorc. Además, las opciones que no toman un argumento están deshabilitadas por defecto. Por lo tanto, usar el comando unset solo es necesario cuando se quiere anular una configuración del archivo nanorc del sistema en tu propio nanorc. Las opciones que toman un argumento no se pueden deshabilitar.

Las comillas dentro de los parámetros characters que se muestran a continuación no deben escaparse. La última comilla doble en la línea se considerará la comilla de cierre.

Los comandos y argumentos admitidos son:

set afterends
Hace que Ctrl+Derecha y Ctrl+Suprimir se detengan en los finales de palabra en lugar de en los principios.
set allow_insecure_backup
Al hacer copias de seguridad de archivos, permite que la copia de seguridad se realice correctamente incluso si sus permisos no pueden ser (re)establecidos debido a consideraciones especiales del sistema operativo. NO debes habilitar esta opción a menos que estés seguro de que la necesitas.
set atblanks
Cuando el ajuste de línea suave está habilitado, hace que las líneas se ajusten en caracteres en blanco (tabulaciones y espacios) en lugar de siempre en el borde de la pantalla.
set autoindent
Indenta automáticamente una línea recién creada con el mismo número de tabulaciones y/o espacios que la línea anterior (o que la siguiente línea si la línea anterior es el principio de un párrafo).
set backup
Al guardar un archivo, crea un archivo de copia de seguridad añadiendo una tilde (~) al nombre del archivo.
set backupdir directorio
Crea y mantiene no solo un archivo de copia de seguridad, sino que crea y mantiene uno numerado de forma única cada vez que se guarda un archivo — cuando las copias de seguridad están habilitadas con set backup o --backup o -B. Los archivos numerados de forma única se almacenan en el directorio especificado.

Usa negrita en lugar de video inverso para la barra de título, barra de estado, barra de indicaciones, mini barra, combinaciones de teclas, números de línea y texto seleccionado. Esto puede ser anulado estableciendo las opciones titlecolor, statuscolor, promptcolor, minicolor, keycolor, numbercolor y/o selectedcolor.

set casesensitive
Realiza búsquedas que distinguen entre mayúsculas y minúsculas por defecto.
set colonparsing
Cuando un nombre de archivo proporcionado en la línea de comandos termina en dos puntos seguidos de dígitos y este nombre de archivo no existe, se elimina el dos puntos y los dígitos y se entienden los dígitos como un número de línea. Si el nombre de archivo recortado tampoco existe, repite el proceso y entiende los dos números obtenidos como número de línea y columna. Pero si el nombre de archivo doblemente recortado tampoco existe, olvida el recorte y acepta el nombre de archivo original tal cual. Para deshabilitar este análisis de dos puntos para algún archivo, usa +1 o similar antes del nombre de archivo relevante.
set constantshow
Informa constantemente la posición del cursor en la barra de estado. Esto anula la opción quickblank.
set cutfromcursor
Usa cortar-desde-cursor-hasta-el-final-de-línea por defecto, en lugar de cortar la línea completa.
set emptyline
No uses la línea debajo de la barra de título, dejándola completamente en blanco.
set errorcolor [bold,][italic,]fgcolor,bgcolor
Usa esta combinación de colores para la barra de estado cuando se muestra un mensaje de error. El valor predeterminado es bold,white,red. Ve a set titlecolor para nombres de colores válidos.
set fill número
Establece el ancho objetivo para justificar y el ajuste de línea automático a este número de columnas. Si el valor es 0 o menor, el ajuste ocurre al ancho de la pantalla menos número de columnas, permitiendo que el punto de ajuste varíe junto con el ancho de la pantalla si la pantalla se redimensiona. El valor predeterminado es -8.
set functioncolor [bold,][italic,]fgcolor,bgcolor
Usa esta combinación de colores para las descripciones concisas de funciones en las dos líneas de ayuda en la parte inferior de la pantalla. Ver set titlecolor para más detalles.
set guidestripe número
Dibuja una línea vertical en la columna dada, para ayudar a juzgar el ancho del texto. (El color de la línea se puede cambiar con set stripecolor.)
set historylog
Guarda los últimos cien cadenas de búsqueda y reemplazo y comandos ejecutados, para que puedan ser reutilizados fácilmente en sesiones posteriores.
set indicator
Muestra una "barra de desplazamiento" en el lado derecho de la ventana de edición. Muestra la posición de la vista en el búfer y cuánto del búfer cubre la vista.
set jumpyscrolling
Desplaza el contenido del búfer por medio pantalla en lugar de por línea.
set keycolor [bold,][italic,]fgcolor,bgcolor
Usa esta combinación de colores para las combinaciones de teclas de atajo en las dos líneas de ayuda en la parte inferior de la pantalla. Ver set titlecolor para más detalles.
set linenumbers

set locking
Habilita archivos de bloqueo al estilo vim para cuando se editan archivos.
set magic

Especifica los corchetes de apertura y cierre que pueden ser encontrados por las búsquedas de corchetes. Esto no puede incluir caracteres en blanco. El conjunto de apertura debe ir antes del conjunto de cierre, y los dos conjuntos deben estar en el mismo orden. El valor por defecto es "(<[{)>]}".

Suprime la barra de título y en su lugar muestra información sobre el búfer actual en la parte inferior de la pantalla, en el espacio para la barra de estado. A la derecha se muestran el número de línea y columna actuales, el código del carácter debajo del cursor (en formato Unicode: U+xxxx), las mismas banderas que se muestran con set stateflags, y un porcentaje que expresa cuánto está el cursor en el archivo (línea a línea). Cuando se carga o guarda un archivo, y también al cambiar entre búferes, el número de líneas en el búfer se muestra después del nombre del archivo. Este número se borra al presionar la siguiente tecla, o se reemplaza con un contador [i/n] cuando hay varios búferes abiertos. Los números de línea y columna y el código del carácter se muestran solo cuando se usa set constantshow, y se pueden activar y desactivar con M-C. Las banderas de estado se muestran solo cuando se usa set stateflags.

Utiliza esta combinación de colores para la minibarra. (Cuando esta opción no está especificada, se usan los colores de la barra de título.) Ver set titlecolor para más detalles.

Habilita el soporte del ratón, si está disponible para tu sistema. Cuando está habilitado, los clics del ratón se pueden usar para colocar el cursor, establecer la marca (con dos clics) y ejecutar atajos. Al leer un archivo con ^R, insértalo en un nuevo búfer por defecto.

set nohelp

set preserve

set promptcolor [negrita,][cursiva,]color_fg,color_bg

Hace que los mensajes de la barra de estado desaparezcan después de 1 pulsación de tecla en lugar de después de 20. Ten en cuenta que la opción constantshow anula esto. RESALTADO DE SINTAXIS

Colorear los diferentes elementos sintácticos de un archivo se hace mediante expresiones regulares (ver el comando color más abajo). Esto es intrínsecamente imperfecto, ya que las expresiones regulares no son lo suficientemente potentes como para analizar completamente un archivo. Sin embargo, las expresiones regulares pueden hacer mucho y son fáciles de crear, por lo que son adecuadas para un editor pequeño como nano.

Todas las expresiones regulares en nano son expresiones regulares extendidas POSIX. Esto significa que ., ?, *, +, ^, $ y varios otros caracteres son especiales. El punto . coincide con cualquier carácter individual, ? significa que el elemento anterior es opcional, * significa que el elemento anterior puede coincidir cero o más veces, + significa que el elemento anterior debe coincidir una o más veces, ^ coincide con el inicio de una línea, y $ el final, \< coincide con el inicio de una palabra, y \> el final, y \s coincide con un espacio en blanco. También significa que no son posibles las miradas hacia adelante y hacia atrás. Una explicación completa se puede encontrar en la página del manual de GNU grep: man grep.

Cada expresión regular en un archivo nanorc debe estar entrecomillada (""). Múltiples expresiones regulares pueden seguirse en una línea separándolas con espacios. Esto significa que una expresión regular no puede contener una comilla doble seguida de un espacio. Cuando necesite esta combinación dentro de una expresión regular, entonces la comilla doble o el espacio deben colocarse entre corchetes ([]).

Para cada tipo de archivo se puede definir una sintaxis separada mediante los siguientes comandos:

syntax nombre ["fileregex" ...]
Inicia la definición de una sintaxis con este nombre. Todos los comandos color y otros comandos similares subsiguientes se agregan a esta sintaxis, hasta que se encuentre un nuevo comando syntax.

Cuando se ejecuta nano, esta sintaxis se activa automáticamente (para el búfer correspondiente) si el nombre de archivo absoluto coincide con la expresión regular extendida fileregex. O la sintaxis se puede activar explícitamente (para todos los búferes) utilizando la opción de línea de comandos -Y o --syntax seguida del nombre.

La sintaxis default es especial: no toma fileregex y se aplica a los archivos que no coinciden con las expresiones regulares de ninguna sintaxis. La sintaxis none está reservada; especificarla en la línea de comandos es lo mismo que no tener ninguna sintaxis.

header "regex" ...
Si de todas las sintaxis definidas ninguna fileregex coincidió, entonces se compara esta regex (o regexes) contra la primera línea del archivo actual, para determinar si esta sintaxis debe usarse para él.
magic "regex" ...
Si ninguna fileregex coincidió y tampoco ninguna regex de header coincidió, entonces se compara esta regex (o regexes) contra el resultado de consultar la base de datos magic sobre el archivo actual, para determinar si esta sintaxis debe usarse para él. (Esta consulta solo se realiza cuando libmagic está realmente instalado en el sistema y se proporcionó --magic o set magic.)
formatter programa [argumento ...]
Ejecuta el programa dado sobre el contenido completo del búfer actual.
linter programa [argumento ...]
Utiliza el programa dado para ejecutar una verificación de sintaxis en el búfer actual.
comment "cadena"
Utiliza la cadena dada para comentar y descomentar líneas. Si la cadena contiene un carácter de barra vertical o pipe (|), esto designa comentarios de estilo de corchetes; por ejemplo, "/*|*/" para archivos CSS. Los caracteres antes del pipe se anteponen a la línea y los caracteres después del pipe se añaden al final de la línea. Si no hay un carácter de pipe, se antepone la cadena completa; por ejemplo, "#" para archivos Python. Si se especifican comillas dobles vacías, la función de comentar/descomentar se deshabilita; por ejemplo, "" para JSON. El valor predeterminado es "#".
tabgives "cadena"
Hace que la tecla <Tab> produzca la cadena dada. Útil para lenguajes como Python que desean ver solo espacios para la indentación. Esto anula la configuración de la opción tabstospaces.
color [bold,][italic,]color_de_fuente,color_de_fondo "regex" ...
Pinta todas las partes de texto que coinciden con la expresión regular extendida regex con los colores de fuente y fondo dados, de los cuales al menos uno debe especificarse. Los nombres de color válidos son: red, green, blue, magenta, yellow, cyan, white y black. Cada uno de estos ocho nombres puede ir precedido de la palabra light para obtener una versión más brillante de ese color. La palabra grey o gray se puede usar como sinónimo de lightblack. En una consola Linux, light no tiene ningún efecto en el color de fondo. En emuladores de terminal que pueden manejar al menos 256 colores, otros nombres de color válidos (pero no prefijables) son: pink, purple, mauve, lagoon, mint, lime, peach, orange, latte, rosy, beet, plum, sea, sky, slate, teal, sage, brown, ocher, sand, tawny, brick, crimson y normal — donde normal significa el color de fuente o fondo predeterminado. En dichos emuladores, el color también se puede especificar como un número hexadecimal de tres dígitos prefijado con #, donde los dígitos representan las cantidades de rojo, verde y azul, respectivamente. Esto le indica a nano que seleccione de la paleta disponible el color que se aproxima a los valores dados.

El par de colores puede ir precedido por bold y/o italic (separados por comas) para obtener una tipografía en negrita y/o inclinada, si su terminal puede hacerlo.

Todos los comandos de coloreado se aplican en el orden en que se especifican, lo que significa que los comandos posteriores pueden recambiar el color de cosas que fueron coloreadas antes.

icolor [bold,][italic,]color_de_fuente,color_de_fondo "regex" ...
Igual que lo anterior, excepto que la coincidencia no distingue entre mayúsculas y minúsculas.
color [bold,][italic,]color_de_fuente,color_de_fondo start="fromrx" end="torx"
Pinta todas las partes de texto cuyo inicio coincide con la expresión regular extendida fromrx y cuyo final coincide con la expresión regular extendida torx con los colores de fuente y fondo dados, de los cuales al menos uno debe especificarse. Esto significa que, después de una instancia inicial de fromrx, todo el texto hasta la primera instancia de torx se colorea. Esto permite que el resaltado de sintaxis abarque múltiples líneas.
icolor [bold,][italic,]color_de_fuente,color_de_fondo start="fromrx" end="torx"
Igual que el comando anterior, excepto que la coincidencia de fromrx y torx no distingue entre mayúsculas y minúsculas.

RESALTADO DE SINTAXIS

Los colores y las propiedades de resaltado de sintaxis se controlan mediante los comandos siguientes:

syntax name
Inicia la definición de una nueva sintaxis para el archivo name. A partir de este momento, todos los comandos que siguen (hasta el próximo comando syntax o hasta el final del archivo de configuración) se aplican a esta sintaxis.
keyword index "keyword"
Define una palabra clave de index. Los índices van de 0 a 31. El predeterminado es 0. Cuando se define una palabra clave, se le asigna un color. El índice 0 se usa para palabras clave de C. Por defecto, las palabras clave son sensibles a mayúsculas y minúsculas.
kwb index "keyword"
Igual que el anterior, pero la palabra clave solo se considerará si está rodeada de caracteres que no sean letras, números o guiones bajos.
comment index "commentstring"
Define una cadena de comentario de index. Los índices van de 0 a 3. El índice 0 se usa para comentarios de estilo C (/* ... */). El índice 1 se usa para comentarios de estilo C++ (// ...). El índice 2 se usa para comentarios de la primera línea de un script de shell. El índice 3 se usa para comentarios de la primera línea de un script de Python.
casing index "casingstyle"
Establece el estilo de mayúsculas/minúsculas para las palabras clave de index. Los valores válidos son lower, upper, y case (sensible a mayúsculas y minúsculas).
icolor index "keyword"
Define una palabra clave de index que debe ser ignorada en términos de mayúsculas y minúsculas. El índice 0 se usa para palabras clave de C. Por defecto, las palabras clave son sensibles a mayúsculas y minúsculas.
string index "stringbegin""stringend"
Define una cadena de index. Los índices van de 0 a 3. El índice 0 se usa para cadenas de estilo C ("..."). El índice 1 se usa para cadenas de estilo C++ ("..." o '...'). El índice 2 se usa para cadenas de estilo emacs (...) o '...'. El índice 3 se usa para cadenas de estilo shell ("..." o '...').
regex index "regex"
Define una expresión regular de index. Los índices van de 0 a 31. Estas expresiones regulares se usan para encontrar texto que no se ajusta a ninguno de los otros tipos de sintaxis.
magic "regex"
Busca la cadena regex en la primera línea del archivo. Si se encuentra, se activa la sintaxis actual. Útil para identificar el tipo de archivo (por ejemplo, #!/bin/sh).
header
Indica que las líneas que comienzan con una cadena de comentarios (definida por el comando comment) también deben coincidir con los comandos keyword y string.
linter command
Especifica el programa que se utilizará para comprobar la sintaxis del archivo. Si se especifica, el resultado de este programa se mostrará en la barra de estado. El formato de salida esperado es "filename:linenum:charnum: message".
formatter command
Especifica el programa que se utilizará para dar formato al archivo. Si se especifica, este programa se ejecutará en el archivo actual, y su salida reemplazará el contenido del archivo. El archivo se escribe primero en un archivo temporal, se ejecuta el programa sobre él y luego se vuelve a leer el archivo temporal.
color colorname start="fromrx" end="torx"
Define un color para el texto que coincide con el patrón de inicio y fin especificado. Los colores válidos son: default, black, red, green, yellow, blue, magenta, cyan, white, grey. También se puede usar bold, italic, underline, reverse. El patrón de inicio y fin son expresiones regulares. El patrón de fin es opcional. Si se omite, se aplica hasta el final de la línea.
bgcolor colorname start="fromrx" end="torx"
Igual que color, pero establece el color de fondo en lugar del color del texto.
casecolor colorname start="fromrx" end="torx"
Igual que color, excepto que la coincidencia no distingue entre mayúsculas y minúsculas.
casebgcolor colorname start="fromrx" end="torx"
Igual que bgcolor, excepto que la coincidencia no distingue entre mayúsculas y minúsculas.
include "syntaxfile"
Lee sintaxis de color autocontenidas de syntaxfile. Tenga en cuenta que syntaxfile solo puede contener los comandos anteriores, desde syntax hasta icolor.
extendsyntax name command argument...
Extiende la sintaxis previamente definida como name con otro command. Esto permite agregar un nuevo comando color, icolor, header, magic, formatter, linter, comment, o tabgives a una sintaxis ya definida, lo que es útil cuando desea mejorar ligeramente una sintaxis definida en uno de los archivos instalados por el sistema (que normalmente no son escribibles).

REASIGNACIÓN DE TECLAS

Las asignaciones de teclas se pueden cambiar mediante los tres comandos siguientes:

bind key function menu
Reasigna la key dada a la function dada en el menu dado (o en todos los menús donde exista la función cuando se usa all).
bind key "string" menu
Hace que la key dada produzca la string dada en el menu dado (o en todos los menús donde exista la clave cuando se usa all). Además de texto literal y/o códigos de control, la string puede contener nombres de funciones entre llaves. Estas funciones se invocan cuando se escribe la clave. Para incluir una llave literal de apertura, use {{}.
unbind key menu
Elimina la asignación de la key dada en el menu dado (o en todos los menús donde exista la clave cuando se usa all).

Tenga en cuenta que bind key "{function}" menu es equivalente a bind key function menu, excepto que para esta última forma nano verifica la disponibilidad de la function en el menu dado al inicio (e informa un error si no existe allí), mientras que para la primera forma nano verifica en el momento de la ejecución que la function existe pero no si tiene sentido en el menú actual. El usuario tiene que asegurarse de que un nombre de función entre llaves (o cualquier secuencia de ellos) sea apropiado. Comportamientos extraños o incluso un bloqueo pueden resultar cuando el nombre entre llaves no es adecuado.

El formato de key debe ser uno de:
^X
donde X es una letra latina, o uno de varios caracteres ASCII (@, ], \, ^, _), o la palabra "Space". Ejemplo: ^C.
M-X
donde X es cualquier carácter ASCII excepto [, o la palabra "Space". Ejemplo: M-8.
Sh-M-X
donde X es una letra latina. Ejemplo: Sh-M-U. Por defecto, cada pulsación de tecla Meta+letra hace lo mismo que la correspondiente Shift+Meta+letra. Pero cuando se realiza cualquier asignación Shift+Meta, eso ya no será así, para todas las letras.
FN
donde N es un valor numérico de 1 a 24. Ejemplo: F10. (A menudo, F13 a F24 se pueden escribir como F1 a F12 con Shift.)
Ins o Del.

Reasignar ^M (Enter) o ^I (Tab) probablemente no sea una buena idea. Reasignar ^[ (Esc) no es posible, ya que su código de tecla es el byte de inicio de las pulsaciones de tecla Meta y las secuencias de escape. Reasignar cualquiera de las teclas dedicadas de movimiento del cursor (las flechas, Inicio, Fin, AvPág y RePág) no es posible. En algunos terminales no es posible reasignar ^H (a menos que se use --raw) ya que su código de tecla es idéntico al de la tecla Retroceso.

Busca la siguiente ocurrencia en la dirección hacia adelante.

Reemplaza interactivamente texto dentro del búfer actual.

NAME

nanorc — nano editor configuration file

DESCRIPTION

The nano editor reads the configuration file ~/.nanorc (or $XDG_CONFIG_HOME/nano/nanorc, or ~/.config/nano/nanorc) to set up its default behavior. If the file is not found, the system-wide configuration file /etc/nanorc is used.

The configuration file consists of a list of option settings and key bindings.

NOTICE

This man page is not intended to be a tutorial. For a tutorial, see the nano cheatsheet.

OPTIONS

The following options can be set in the configuration file:

autoindent
When this option is set, newly entered lines will have the same amount of leading whitespace as the preceding line; or as the next line if the preceding line is the beginning of a paragraph.
cutfromcursor
Toggles whether cutting text cuts the whole line or just from the current cursor position to the end of the line.
breaklonglines
Toggles whether the overlong part of a line is hard-wrapped to the next line.
tabstospaces
Toggles whether typed tabs are converted to spaces.
mouse
Toggles mouse support.

Valid menu sections are:

main
The main editor window where text is entered and edited.
help
The help-viewer menu.
search
The search menu (AKA whereis).
replace
The 'search to replace' menu.
replacewith
The 'replace with' menu, which comes up after 'search to replace'.
yesno
The 'yesno' menu, where the Yes/No/All/Cancel question is asked.
gotoline
The 'goto line (and column)' menu.
writeout
The 'write file' menu.
insert
The 'insert file' menu.
browser
The 'file browser' menu, for selecting a file to be opened or inserted or written to.
whereisfile
The 'search for a file' menu in the file browser.
gotodir
The 'go to directory' menu in the file browser.
execute
The menu for inserting the output from an external command, or for filtering the buffer (or the marked region) through an external command, or for executing one of several tools.
spell
The menu of the integrated spell checker where the user can edit a misspelled word.
linter
The linter menu, which allows jumping through the linting messages.
all
A special name that encompasses all menus. For bind it means all menus where the specified function exists; for unbind it means all menus where the specified key exists.

EXAMPLES

To make Ctrl+Z suspend nano:

bind ^Z suspend main

To make Shift+Alt+C copy the marked region to the system's clipboard:

bind Sh-M-C "{execute}| xsel -ib {enter}{undo}" main
