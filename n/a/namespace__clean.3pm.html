namespace::clean(3) Documentación de Perl aportada por el usuario namespace::clean(3)

NOMBRE

namespace::clean - Mantén las importaciones y funciones fuera de tu espacio de nombres

SINOPSIS

package Foo;
use warnings;
use strict;
use Carp qw(croak);   # 'croak' será eliminado
sub bar { 23 }        # 'bar' será eliminado
# eliminar todas las funciones definidas previamente
use namespace::clean;
sub baz { bar() }     # 'baz' todavía definido, 'bar' todavía enlazado
# empezar a recolectar nombres de funciones de nuevo desde aquí
no namespace::clean;
sub quux { baz() }    # 'quux' será eliminado
# eliminar todas las funciones definidas después del unimport 'no'
use namespace::clean;
# Imprimirá: 'No', 'No', 'Sí' y 'No'
print +(__PACKAGE__->can('croak') ? 'Sí' : 'No'), "\n";
print +(__PACKAGE__->can('bar')   ? 'Sí' : 'No'), "\n";
print +(__PACKAGE__->can('baz')   ? 'Sí' : 'No'), "\n";
print +(__PACKAGE__->can('quux')  ? 'Sí' : 'No'), "\n";
1;

DESCRIPCIÓN

Manteniendo paquetes limpios

Cuando defines una función, o importas una, en un paquete de Perl, naturalmente también estará disponible como un método. Esto no causa problemas en sí mismo, pero puede complicar la subclasificación y, por ejemplo, las clases de plugins que se incluyen a través de herencia múltiple cargándolas como clases base.

El pragma "namespace::clean" eliminará todos los símbolos previamente declarados o importados al final del ciclo de compilación del paquete actual. Las funciones llamadas dentro del propio paquete seguirán enlazadas por su nombre, pero no aparecerán como métodos en tu clase o instancias.

Al desimportar mediante "no", puedes indicar a "namespace::clean" que empiece a recopilar funciones para la siguiente especificación de "use namespace::clean;".

Puedes usar el flag "-except" para indicar a "namespace::clean" que no deseas que elimine una función o método determinado. Un uso común sería un módulo que exporta un método "import" junto con algunas funciones:

use ModuleExportingImport;
use namespace::clean -except => [qw( import )];

Si solo quieres usar "-except" para una única subrutina, puedes pasarla directamente. Para más de un valor, tienes que usar una referencia de array.

Advertencia de enlace tardío

Ten en cuenta que la técnica utilizada por este módulo se basa en que perl resuelva todos los nombres a referencias de código reales durante la compilación de un ámbito. Si bien esto es casi siempre lo que hace el intérprete, existen algunas excepciones, en particular el estilo SUBNAME de "sort" en la invocación del comando incorporado "sort". El siguiente ejemplo no funcionará, porque "sort" no intenta resolver el nombre de la función a una referencia de código real hasta el tiempo de ejecución.

use MyApp::Utils 'my_sorter';
use namespace::clean;
my @sorted = sort my_sorter @list;

Necesitas sortear esto forzando una resolución en tiempo de compilación de la siguiente manera:

use MyApp::Utils 'my_sorter';
use namespace::clean;
my $my_sorter_cref = \&my_sorter;
my @sorted = sort $my_sorter_cref @list;

Eliminando explícitamente funciones cuando tu ámbito es compilado

También es posible indicar explícitamente a "namespace::clean" qué paquetes eliminar cuando el ámbito circundante termine de compilarse. Aquí tienes un ejemplo:

package Foo;
use strict;
# blessed NO disponible
sub my_class {
    use Scalar::Util qw( blessed );
    use namespace::clean qw( blessed );
    # blessed disponible
    return blessed shift;
}
# blessed NO disponible

Moose

Cuando uses "namespace::clean" junto con Moose, querrás mantener el método "meta" instalado. Así que tus clases deberían verse así:

package Foo;
use Moose;
use namespace::clean -except => 'meta';
...

Lo mismo ocurre con Moose::Role.

Limpiando otros paquetes

Puedes indicarle a "namespace::clean" que quieres limpiar otro paquete en lugar del que importa. Para hacer esto, tienes que pasar la opción "-cleanee" de la siguiente manera:

package My::MooseX::namespace::clean;
use strict;
use namespace::clean (); # sin limpieza, solo cargar
sub import {
    namespace::clean->import(
      -cleanee => scalar(caller),
      -except  => 'meta',
    );
}

Si no te importa la lógica de "namespace::clean" de descubrimiento y "-except", y solo quieres eliminar subrutinas, prueba "clean_subroutines".

MÉTODOS

clean_subroutines

Esto expone la lógica real de eliminación de subrutinas.

namespace::clean->clean_subroutines($cleanee, qw( subA subB ));

eliminará "subA" y "subB" de $cleanee. Ten en cuenta que esto eliminará las subrutinas **inmediatamente** y no esperará al final del ámbito. Si quieres que esto tenga efecto en un momento específico (por ejemplo, "namespace::clean" actúa al final de la compilación del ámbito), es tu responsabilidad asegurarte de que se ejecute en ese momento.

import

Crea una instantánea de las funciones definidas actualmente e instala un hook de B::Hooks::EndOfScope en el ámbito actual para invocar las limpiezas.

unimport

Este método será llamado cuando hagas

no namespace::clean;

Empezará una nueva sección de código que define funciones para limpiar.

get_class_store

Esto devuelve una referencia a un hash en un paquete pasado que contiene información sobre los nombres de funciones incluidos y excluidos de la eliminación.

get_functions

Toma una clase como argumento y devuelve todas las funciones definidas actualmente en ella como una referencia de hash con el nombre de la función como clave y una referencia a un tipo global del símbolo como valor.

DETALLES DE IMPLEMENTACIÓN

Este módulo funciona a través del efecto de que un

delete $SomePackage::{foo};

eliminará el símbolo "foo" de $SomePackage para búsquedas en tiempo de ejecución (por ejemplo, llamadas a métodos), pero dejará la entrada activa para ser llamada por nombres ya resueltos en el propio paquete. "namespace::clean" restaurará y, por lo tanto, en efecto, mantendrá todas las ranuras de globos que no sean "CODE".

Se ha añadido un archivo de prueba al núcleo de perl para asegurar que este comportamiento sea estable en futuras versiones.

Solo para completar, si quieres eliminar el símbolo completamente, usa "undef" en su lugar.

VER TAMBIÉN
