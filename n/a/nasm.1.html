NASM(1) Proyecto Netwide Assembler NASM(1)

NOMBRE

nasm - el Netwide Assembler, un ensamblador portable para 80x86

SINOPSIS

nasm [-@ archivo de respuesta] [-f formato] [-o archivo de salida] [-l archivo de listado] [opciones...] archivo

DESCRIPCIÓN

El comando nasm ensambla el archivo archivo y dirige la salida al archivo archivo de salida si se especifica. Si no se especifica archivo de salida, nasm derivará un nombre de archivo de salida predeterminado del nombre de su archivo de entrada, generalmente añadiendo ‘.o’ o ‘.obj’, o eliminando todas las extensiones para un archivo binario plano. Si no, el nombre del archivo de salida será ‘nasm.out’.

OPCIONES

-@ archivo

Hace que nasm procese las opciones del archivo como si estuvieran incluidas en la línea de comandos.

-a

Hace que nasm ensamble el archivo de entrada dado sin aplicar primero el preprocesador de macros.

-D|-d macro[=valor]

Predefine una macro de una sola línea.

-E|-e

Hace que nasm preprocese el archivo de entrada dado y escriba la salida en stdout (o el nombre de archivo de salida especificado), y no ensamble nada realmente.

-f formato

Especifica el formato del archivo de salida. Para ver una lista de formatos de salida válidos, utilice la opción -hf.

-F formato

Especifica el formato de la información de depuración. Para ver una lista de formatos de salida válidos, utilice la opción -y (por ejemplo -felf -y).

-g

Hace que nasm genere información de depuración.

-gformato

Equivalente a -g -F formato.

-h

Hace que nasm salga inmediatamente, después de dar un resumen de sus opciones de invocación.

-hf

Igual que -h, pero también lista todos los formatos de salida válidos.

-I|-i directorio

Añade un directorio a la ruta de búsqueda de archivos incluidos. La especificación del directorio debe incluir la barra inclinada final, ya que se antepondrá directamente al nombre del archivo incluido.

-l archivo de listado

Hace que un listado de ensamblaje se dirija al archivo dado, en el que se muestra el código fuente original en el lado derecho (más el código fuente de los archivos incluidos y las expansiones de macros multilínea) y el código generado se muestra en hexadecimal a la izquierda.

-M

Hace que nasm envíe dependencias estilo Makefile a stdout; la salida normal se suprime.

-MG archivo

Igual que -M pero asume que las dependencias de Makefile faltantes se generan y se añaden a la lista de dependencias sin un prefijo.

-MF archivo

Envía dependencias estilo Makefile al archivo especificado.

-MD archivo

Igual que una combinación de las opciones -M y -MF.

-MT archivo

Anula el nombre predeterminado del objetivo de dependencia. Este es normalmente el mismo que el nombre del archivo de salida, especificado por la opción -o.

-MQ archivo

Lo mismo que -MT excepto que intenta citar caracteres que tienen significado especial en la sintaxis de Makefile. Esto no es infalible, ya que no todos los caracteres con significado especial son citable en Make.

-MP

Emite un objetivo ficticio.

-O número

Optimiza las compensaciones de salto.
•-O0: Sin optimización
•-O1: Optimización mínima
•-Ox: Optimización multipaso (predeterminado)

-o archivo de salida

Especifica un nombre preciso para el archivo de salida, anulando el medio predeterminado de nasm para determinarlo.

-P|-p archivo

Especifica un archivo que se incluirá previamente, antes de que el archivo fuente principal comience a ser procesado.

-s

Hace que nasm envíe sus mensajes de error y/o texto de ayuda a stdout en lugar de stderr.

-t

Hace que nasm ensamble en modo compatible con SciTech TASM.

-U|-u macro

Anula una macro de una sola línea.

-v

Hace que nasm salga inmediatamente, después de mostrar su número de versión.

*-W[no-]foo'

Hace que nasm habilite o deshabilite ciertas clases de mensajes de advertencia, al estilo gcc, por ejemplo -Wlabel-orphan o -Wno-orphan-labels.

-w[+-]foo

Hace que nasm habilite o deshabilite ciertas clases de mensajes de advertencia, por ejemplo -w+label-orphan o -w-macro-params.

-X formato

Especifica el formato de reporte de errores (gnu o vc).

-y

Hace que nasm liste los formatos de depuración soportados.

-Z archivo

Hace que nasm redirija los mensajes de error a archivo. Esta opción existe para soportar sistemas operativos en los cuales stderr no se puede redirigir fácilmente.

--prefix, --postfix

Anteponen o añaden (respectivamente) el argumento dado a todas las variables globales o externas.

SINTAXIS

Esta página del manual no describe completamente la sintaxis del lenguaje ensamblador de nasm, pero sí resume las diferencias con otros ensambladores.

Los registros no tienen un signo ‘%’ delante, a diferencia de gas, y los registros de pila de punto flotante se denominan st0, st1, etc.

Las instrucciones de punto flotante pueden usar la forma de un solo operando o la doble. Se proporciona una palabra clave TO; por lo tanto, se podría escribir

fadd st0,st1
fadd st1,st0

o se podría usar las formas alternativas de un solo operando

fadd st1
fadd to st1

El almacenamiento no inicializado se reserva usando las pseudo-opciones RESB, RESW, RESD, RESQ, REST y RESO, cada una tomando un parámetro que da el número de bytes, palabras, doble palabras, cuádruples palabras o palabras de diez bytes a reservar.

La repetición de elementos de datos no se hace con la palabra clave DUP como se ve en los ensambladores de DOS, sino por el uso del prefijo TIMES, así:

mensaje: times 3 db 'abc'
         times 64-$+mensaje db 0

que define la cadena abcabcabc, seguida del número correcto de bytes cero para completar la longitud total hasta 64 bytes.

Las referencias a símbolos siempre se entienden como inmediatas (es decir, la dirección del símbolo), a menos que se usen corchetes, en cuyo caso se utilizan los contenidos de la ubicación de memoria. Así:

mov ax,variablepalabra

carga AX con la dirección de la variable variablepalabra, mientras que

mov ax,[variablepalabra]
mov ax,[variablepalabra+1]
mov ax,[es:variablepalabra+bx]

todas se refieren a los contenidos de las ubicaciones de memoria. Las sintaxis

mov ax,es:variablepalabra[bx]
es mov ax,variablepalabra[1]

no son legales en absoluto, aunque el uso de un nombre de registro de segmento como prefijo de instrucción es válido, y se puede usar con instrucciones como LODSB que no se pueden anular de ninguna otra manera.

Las constantes pueden expresarse numéricamente en la mayoría de los formatos: una H, Q o B al final denota hexadecimal, octal o binario respectivamente, y un ‘0x’ o ‘$’ inicial denotan hexadecimal también. Los ceros iniciales no se tratan de forma especial en absoluto. Las constantes de caracteres pueden estar encerradas entre comillas simples o dobles; no hay carácter de escape. El orden es little-endian (invertido), de modo que la constante de carácter 'abcd' denota 0x64636261 y no 0x61626364.

Las etiquetas locales comienzan con un punto, y su ‘localidad’ es otorgada por el ensamblador anteponiendo el nombre del símbolo no local anterior. Así, al declarar una etiqueta &#

nasm(1) — NASM manual

NAME

nasm — Netwide Assembler

SYNOPSIS

nasm [-f fmt] [-o outfile] [-l lstfile] [-M] [-m] [-X strconv] [infile] ...

DESCRIPTION

The Netwide Assembler, NASM, is an assembler for the Intel 80x86 microarchitecture. It is designed to be small, fast, and highly modular, with a number of output formats and a number of extensions to the x86 instruction set.

NASM can assemble programs for a wide variety of formats, including

  • flat binary files (no header)
  • Linux/i386, a.out, COFF, and ECOFF object files
  • Microsoft 16-bit OBJ object files
  • Omf object files
  • Java class files
  • FreeBSD/i386, Mach-O, and Mach-O 64-bit object files

NASM supports a number of extensions to the Intel syntax, including

  • conditional assembly
  • macro preprocessor
  • floating point instructions
  • Pentium instructions
  • MMX instructions
  • SSE, SSE2, SSE3, SSSE3, SSE4.1 and SSE4.2 instructions
  • AVX, AVX2, FMA, F16C, FMA4, XOP, TBM, AES, PCLMULQDQ, RDRAND, RDSEED, FSGSBASE, FMA4, FMA5, BMI, BMI2, LZCNT, MOVBE instructions
  • AVX-512 instructions
  • 64-bit mode instructions
  • 3DNow! instructions
  • TSX instructions

OPTIONS

The following options are available:

-f fmt
Specifies the output format. NASM supports a wide range of formats, which are described in the output formats section of the documentation.
-o outfile
Specifies the name of the output file. If this is not supplied, output will be written to a file named ‘outfile.o’ if the input file was ‘infile.asm’, or to standard output if no input file is specified.
-l lstfile
Specifies the name of the listing file. This file contains a copy of the source code, with line numbers and any generated machine code, and any error messages. If not supplied, the listing file is named ‘outfile.lst’.
-M
Prints NASM's internal version string to standard error and exits.
-m
Prints NASM's internal revision number to standard error and exits.
-X strconv
Controls the conversion of strings to character codes. The possible values for strconv are:
  • ‘none’: No conversion is performed.
  • ‘charcodes’: Strings are converted to character codes.
  • ‘numbers’: Strings are converted to numbers.

SYNTAX

NASM supports a syntax very similar to Intel's assembler syntax. The basic syntax is:

label: instruction [operands] [ ; comment ]

Labels are optional, as are comments. Instructions and operands follow standard x86 conventions. Operands can be:

  • immediate values
  • registers
  • memory addressing modes

Directives are commands to the assembler itself, and do not generate code. They usually start with a dot (.) or are keywords such as section, segment, etc. NASM supports a number of directives, some of which are described below.

Labels can be followed by a colon (:), or not. The colon is ignored if present. It is recommended to use the colon to distinguish labels from other symbols, and to avoid ambiguity with instruction mnemonics and directives.

The instruction times can be used to repeat an instruction or a sequence of instructions a number of times. For example, times 4 db 0 will generate four zero bytes.

Labels defined within loops are sometimes problematic. For example, if you have code like this:

loop:
    ...
    jmp loop

And you have a macro that expands to something like this:

macro movedi
    <<loop:
    mov edi, edi
>>

The macro expansion will create a label ‘loop’ that conflicts with the existing label. NASM has a mechanism to deal with this: if a label is defined inside a macro, and the macro is invoked inside a loop, the label will be automatically duplicated, creating a unique label for each invocation. This can be controlled with the ‘.loop’ suffix, which forces a label to be duplicated, or disabled entirely.

DIRECTIVES

SECTION name or SEGMENT name causes nasm to direct all following code to the named section. Section names vary with output file format, although most formats support the names .text, .data and .bss. (The exception is the obj format, in which all segments are user-definable.)

ABSOLUTE address causes nasm to position its notional assembly point at an absolute address: so no code or data may be generated, but you can use RESB, RESW and RESD to move the assembly point further on, and you can define labels. So this directive may be used to define data structures. When you have finished doing absolute assembly, you must issue another SECTION directive to return to normal assembly.

BITS 16, BITS 32 or BITS 64 switches the default processor mode for which nasm is generating code: it is equivalent to USE16 or USE32 in DOS assemblers.

EXTERN symbol and GLOBAL symbol import and export symbol definitions, respectively, from and to other modules. Note that the GLOBAL directive must appear before the definition of the symbol it refers to.

STRUC strucname and ENDSTRUC, when used to bracket a number of RESB, RESW or similar instructions, define a data structure. In addition to defining the offsets of the structure members, the construct also defines a symbol for the size of the structure, which is simply the structure name with size tacked on to the end.

FORMAT-SPECIFIC DIRECTIVES

ORG address is used by the bin flat-form binary output format, and specifies the address at which the output code will eventually be loaded.

GROUP grpname seg1 seg2... is used by the obj (Microsoft 16-bit) output format, and defines segment groups. This format also uses UPPERCASE, which directs that all segment, group and symbol names output to the object file should be in uppercase. Note that the actual assembly is still case sensitive.

LIBRARY libname is used by the rdf output format, and causes a dependency record to be written to the output file which indicates that the program requires a certain library in order to run.

MACRO PREPROCESSOR

Single-line macros are defined using the %define or %idefine commands, in a similar fashion to the C preprocessor. They can be overloaded with respect to number of parameters, although defining a macro with no parameters prevents the definition of any macro with the same name taking parameters, and vice versa. %define defines macros whose names match case-sensitively, whereas %idefine defines case-insensitive macros.

Multi-line macros are defined using %macro and %imacro (the distinction is the same as that between %define and %idefine), whose syntax is as follows

%macro name minprm[-maxprm][+][.nolist] [defaults]
<some lines of macro expansion text>
%endmacro

Again, these macros may be overloaded. The trailing plus sign indicates that any parameters after the last one get subsumed, with their separating commas, into the last parameter. The defaults part can be used to specify defaults for unspecified macro parameters after minparam. %endm is a valid synonym for %endmacro.

To refer to the macro parameters within a macro expansion, you use %1, %2 and so on. You can also enforce that a macro parameter should contain a condition code by using %+1, and you can invert the condition code by using %-1. You can also define a label specific to a macro invocation by prefixing it with a double ‘%’ sign.

Files can be included using the %include directive, which works like C.

The preprocessor has a ‘context stack’, which may be used by one macro to store information that a later one will retrieve. You can push a context on the stack using %push, remove one using %pop, and change the name of the top context (without disturbing any associated definitions) using %repl. Labels and %define macros specific to the top context may be defined by prefixing their names with %$, and things specific to the next context down with %$$, and so on.

Conditional assembly is done by means of %ifdef, %ifndef, %else and %endif as in C. (Except that %ifdef can accept several putative macro names, and will evaluate TRUE if any of them is defined.) In addition, the directives %ifctx and %ifnctx can be used to condition on the name of the top context on the context stack. The obvious set of ‘else-if’ directives, %elifdef, %elifndef, %elifctx and %elifnctx are also supported.
