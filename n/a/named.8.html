Paquete: bind

Licencias: MPL2

NAMED(8) BIND 9 NAMED(8)

NOMBRE

named - servidor de nombres de dominio de Internet

SINOPSIS

named [ [-4] | [-6] ] [-c archivo-config] [-C] [-d nivel-depuracion] [-D cadena] [-E nombre-motor] [-f] [-g] [-L archivo-log] [-M opcion] [-m bandera] [-n #cpus] [-p puerto] [-s] [-t directorio] [-u usuario] [-v] [-V] ]

DESCRIPCIÓN

named es un servidor del Sistema de Nombres de Dominio (DNS), parte de la distribución BIND 9 de ISC. Para más información sobre DNS, véase RFC 1033 https://datatracker.ietf.org/doc/html/rfc1033.html, RFC 1034 https://datatracker.ietf.org/doc/html/rfc1034.html, y RFC 1035 https://datatracker.ietf.org/doc/html/rfc1035.html.

Cuando se invoca sin argumentos, named lee el archivo de configuración predeterminado /etc/named.conf, lee cualquier dato inicial y espera consultas.

OPCIONES

-4
Esta opción indica a named que use solo IPv4, incluso si la máquina anfitriona es capaz de IPv6. -4 y -6 son mutuamente excluyentes.
-6
Esta opción indica a named que use solo IPv6, incluso si la máquina anfitriona es capaz de IPv4. -4 y -6 son mutuamente excluyentes.
-c archivo-config
Esta opción indica a named que use archivo-config como su archivo de configuración en lugar del predeterminado, /etc/named.conf. Para asegurar que el archivo de configuración pueda ser recargado después de que el servidor haya cambiado su directorio de trabajo debido a una posible opción directory en el archivo de configuración, archivo-config debe ser una ruta absoluta.
-C
Esta opción imprime la configuración predeterminada incorporada y sale.

NOTA: Esto es solo para fines de depuración y no es una representación precisa de la configuración real utilizada por named en tiempo de ejecución.

-d nivel-depuracion
Esta opción establece el nivel de depuración del demonio a nivel-depuracion. Los rastreos de depuración de named se vuelven más detallados a medida que aumenta el nivel de depuración.
-D cadena
Esta opción especifica una cadena que se utiliza para identificar una instancia de named en una lista de procesos. El contenido de cadena no se examina.
-E nombre-motor
Cuando sea aplicable, esta opción especifica el hardware a usar para operaciones criptográficas, como un almacén de claves seguro utilizado para firmar.

Cuando BIND 9 se compila con OpenSSL, este debe configurarse con el identificador de motor de OpenSSL que controla el acelerador criptográfico o el módulo de servicio de hardware (generalmente pkcs11).

-f
Esta opción ejecuta el servidor en primer plano (es decir, no se desvincula).
-F
Esta opción activa el modo FIPS (Estándares Federales de Procesamiento de Información de EE. UU.) si la biblioteca criptográfica subyacente admite la ejecución en modo FIPS.
-g
Esta opción ejecuta el servidor en primer plano y fuerza todo el registro a stderr.
-L archivo-log
Esta opción establece el registro en el archivo archivo-log por defecto, en lugar del registro del sistema.
-M opcion
Esta opción establece las opciones de contexto de memoria (separadas por comas) predeterminadas. Las banderas posibles son:
  • fill: rellena bloques de memoria con valores de etiqueta cuando se asignan o liberan, para ayudar a depurar problemas de memoria; este es el valor predeterminado implícito si named se ha compilado con --enable-developer.
  • nofill: deshabilita el comportamiento habilitado por fill; este es el valor predeterminado implícito a menos que named se haya compilado con --enable-developer.
-m bandera
Esta opción activa banderas de depuración de uso de memoria. Las banderas posibles son usage, trace y record. Estas corresponden a las banderas ISC_MEM_DEBUGXXXX descritas en <isc/mem.h>.
-n #cpus
Esta opción crea #cpus hilos de trabajo para aprovechar múltiples CPUs. Si no se especifica, named intenta determinar el número de CPUs presentes y crea un hilo por CPU. Si no puede determinar el número de CPUs, se crea un único hilo de trabajo.
-p valor
Esta opción especifica el puerto(s) en el que el servidor escuchará las consultas. Si valor tiene el formato <numeropuerto> o dns=<numeropuerto>, el servidor escuchará las consultas DNS en numeropuerto; si no se especifica, el valor predeterminado es el puerto 53. Si valor tiene el formato tls=<numeropuerto>, el servidor escuchará las consultas TLS en numeropuerto; el valor predeterminado es 853. Si valor tiene el formato https=<numeropuerto>, el servidor escuchará las consultas HTTPS en numeropuerto; el valor predeterminado es 443. Si valor tiene el formato http=<numeropuerto>, el servidor escuchará las consultas HTTP en numeropuerto; el valor predeterminado es 80.
-s
Esta opción escribe estadísticas de uso de memoria en stdout al salir.

Nota:

Esta opción es principalmente de interés para los desarrolladores de BIND 9 y puede ser eliminada o modificada en una versión futura.
-t directorio
Esta opción indica a named que haga chroot al directorio después de procesar los argumentos de la línea de comandos, pero antes de leer el archivo de configuración.

Advertencia:

Esta opción debe usarse junto con la opción -u, ya que hacer chroot a un proceso que se ejecuta como root no mejora la seguridad en la mayoría de los sistemas; la forma en que se define chroot permite que un proceso con privilegios de root escape de una prisión de chroot.
-U #oyentes
Esta opción ha sido eliminada. Los intentos de usarla ahora generan una advertencia.
-u usuario
Esta opción establece el setuid a usuario después de completar las operaciones privilegiadas, como la creación de sockets que escuchan en puertos privilegiados.

Nota:

En Linux, named utiliza el mecanismo de capacidades del kernel para eliminar todos los privilegios de root excepto la capacidad de enlazar a un puerto privilegiado y establecer límites de recursos del proceso. Desafortunadamente, esto significa que la opción -u solo funciona cuando named se ejecuta en el kernel 2.2.18 o posterior, o en el kernel 2.3.99-pre3 o posterior, ya que los kernels anteriores no permitían conservar los privilegios después de setuid.
-v
Esta opción informa el número de versión y sale.
-V
Esta opción informa el número de versión named(8) - Arch Linux Man Pages

NAME

named -porcion de BIND DNS Server

SYNOPSIS

named [-c configuration-file] [-d debug-level] [-e error-file] [-f] [-m] [-p port-number] [-q] [-r root-directory] [-s] [-t directory] [-v] [-x]

DESCRIPTION

named is the Dynamic DNS (DDNS) server. It is a high-performance, feature-rich, standards-compliant authoritative and caching name server.

The BIND 9 Administrator Reference Manual provides a complete description of the features and configuration of named.

OPTIONS

Options that are specified on the command line override the corresponding options in the configuration file.

-c configuration-file
Use configuration-file instead of the default /etc/named.conf.
-d debug-level
Set the debug level to debug-level. This must be a non-negative integer. Higher values result in more verbose logging.
-e error-file
Send logging output to error-file instead of the default stderr.
-f
Stay in the foreground. Normally, named forks and exits after initialization. If this option is specified, named does not fork and does not exit.
-m
Memory usage debugging. This option is only available if BIND was compiled with MEMORY debug support.
-p port-number
Listen on UDP port port-number instead of the default port 53. This option is intended for testing only.
-q
Graceful shutdown. This signal causes the server to dump the contents of its caches to the dump file, and then exit gracefully.
-r root-directory
Change root to directory. This option is used when running named from a chroot environment.
-s
Write the contents of the server's caches to the dump file and then exit. This is equivalent to sending SIGHUP to the server.
-t directory
Change the working directory to directory. This option is used when running named from a chroot environment.
-v
Print version information and exit.
-X lock-file
This option has been removed and using it will cause a fatal error.

SIGNALS

In routine operation, signals should not be used to control the nameserver; rndc <#std-iscman-rndc> should be used instead.

SIGHUP
This signal forces a reload of the server.
SIGINT, SIGTERM
These signals shut down the server.

The result of sending any other signals to the server is undefined.

CONFIGURATION

The named configuration file is too complex to describe in detail here. A complete description is provided in the BIND 9 Administrator Reference Manual.

named inherits the umask (file creation mode mask) from the parent process. If files created by named, such as journal files, need to have custom permissions, the umask should be set explicitly in the script used to start the named process.

FILES

/etc/named.conf
The default configuration file.
/var/run/named.pid
The default process-id file.
