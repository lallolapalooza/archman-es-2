NOMBRE

namespace.yaml - Archivo de configuración de Slurm para el plugin namespace/linux

DESCRIPCIÓN

namespace.yaml es un archivo de configuración con formato YAML que define los parámetros utilizados por el plugin namespace/linux de Slurm. Basándose en estos parámetros, el plugin creará los namespaces apropiados específicos para el trabajo. El plugin namespace/linux puede crear un namespace del sistema de archivos y construirá un namespace del sistema de archivos privado (u opcionalmente compartido) y montará una lista de directorios (por defecto /tmp y /dev/shm) dentro de él, dando al trabajo una vista privada de estos directorios. Estas rutas se montan dentro de la ubicación especificada por 'base_path' en el archivo namespace.yaml. También puede crear nuevos namespaces de Usuario y PID para el trabajo.

Cuando el trabajo finaliza, el namespace se desmonta y todos los archivos dentro de él se eliminan automáticamente.

Para hacer uso de estos plugins, 'PrologFlags=Contain' también debe estar presente en su archivo slurm.conf, como se muestra:

NamespaceType=namespace/linux
PrologFlags=Contain

El archivo siempre estará ubicado en el mismo directorio que slurm.conf.

El archivo debe estar ubicado en el mismo directorio que slurm.conf. Cualquier texto que siga a un "#" en este archivo se trata como un comentario hasta el final de esa línea. Los cambios en el archivo de configuración surten efecto tras reiniciar los demonios de Slurm.

PARÁMETROS

namespace.yaml contiene los siguientes atributos:

defaults
Configuración predeterminada del namespace. Si se especifica, contiene los campos descritos en las opciones.
node_confs
Lista de configuraciones de namespace para nodos. Los atributos de los elementos de la lista se describen a continuación.

definiciones de elementos de lista de conf_nodos

Cada elemento de node_confs contiene los siguientes atributos:

nodes
Lista de nombres de nodos a los que se aplicarán las opciones.
options
Opciones de configuración del namespace. Las opciones especificadas anularán las establecidas por defaults.

definiciones de opciones

options contiene los siguientes atributos:

auto_base_path
Esto determina si el plugin debe crear el directorio BasePath o no. Establézcalo en 'true' si el directorio no se pre-crea antes del inicio de Slurm. Si se establece en true, el directorio se crea con permisos 0755. El directorio no se elimina durante el apagado de Slurm. Si se establece en 'false' o no se especifica, el plugin esperaría que el directorio existiera. Esta opción se puede utilizar a nivel global o por línea. Este parámetro es opcional.
base_path
Especifique la RUTA que el plugin de namespace debe usar como base para montar los directorios privados. Esta ruta debe ser legible y escribible por el plugin. El plugin construye un directorio para cada trabajo dentro de esta ruta, que luego se utiliza para montar. La base_path se monta como 'privada' durante el inicio de slurmd y permanece montada hasta el apagado. El primer "%h" dentro del nombre se reemplaza con el nombre de host en el que se está ejecutando slurmd. El primer "%n" dentro del nombre se reemplaza con el nombre del nodo de Slurm en el que se está ejecutando slurmd. Establezca RUTA en 'none' para deshabilitar el plugin namespace/linux en subconjuntos de nodos cuando hay una configuración global en defaults.

NOTA: La base_path debe ser única para cada nodo. Si la base_path está en un sistema de archivos compartido, puede usar "%h" o "%n" para crear directorios únicos para cada nodo.

NOTA: El parámetro base_path no puede establecerse en ninguna de las rutas especificadas por dirs. El uso de estos directorios causará conflictos al intentar montar y desmontar los directorios privados para el trabajo.

clone_ns_script
Especifique la ruta completa de un script de inicialización opcional. Este script se ejecuta después de la construcción del namespace de un trabajo. Se proporcionará al script la variable de entorno SLURM_NS que contiene la ruta al namespace que puede ser utilizada por el comando nsenter. Esta variable permitirá que el script se una al namespace recién creado y realice trabajos de configuración adicionales. Este parámetro es opcional.
clone_ns_script_wait
El número de segundos a esperar a que el clone_ns_script se complete antes de considerar que el script ha fallado. El valor predeterminado es 10 segundos.
clone_ns_epilog
Especifique la ruta completa de un script de epílogo opcional. Este script se ejecuta justo antes de que se desmantele el namespace. Se proporcionará al script la variable de entorno SLURM_NS que contiene la ruta al namespace que puede ser utilizada por el comando nsenter. Esta variable permitirá que el script se una al namespace que pronto será eliminado y realice cualquier trabajo de limpieza. Este parámetro es opcional.
clone_ns_epilog_wait
El número de segundos a esperar a que el clone_ns_epilog se complete antes de considerar que el script ha fallado. El valor predeterminado es 10 segundos.
clone_ns_flags
Contiene una lista de valores de bandera de cadena. Este parámetro define qué namespaces adicionales deben crearse para el trabajo. Los valores válidos son "CLONE_NEWPID" y "CLONE_NEWUSER" para crear namespaces PID y USUARIO nuevos respectivamente. "CLONE_NEWNS" también será aceptado, pero siempre está activado. NOTA: Cuando se especifica CLONE_NEWUSER, también se requiere soporte para tokens bpf si se utiliza ConstrainDevices en cgroup.conf.
dirs
Una lista separada por comas de directorios para los que crear puntos de montaje privados. Este parámetro es opcional y si no se especifica, por defecto es ""/tmp,/dev/shm"".

NOTA: /dev/shm tiene un manejo especial y, en lugar de un montaje bind, es siempre un sistema de archivos tmpfs nuevo.

NOTA: Cuando se especifica CLONE_NEWPID, se montará automáticamente un sistema de archivos /proc único para el contenedor.

init_script
Especifique la ruta completa de un script de inicialización opcional. Este script se ejecuta antes de la construcción del namespace de un trabajo. Se puede utilizar para que el trabajo se una a namespaces adicionales antes de la construcción del namespace de /tmp o se puede utilizar para cualquier configuración específica del sitio. Este parámetro es opcional.
shared
Especificar Shared=true propagará nuevos montajes entre el namespace del sistema de archivos específico del trabajo y el namespace del sistema de archivos raíz, permitiendo el uso de autofs en el nodo. Este parámetro es opcional.
user_ns_script

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

>Especifica la ubicación de un script que realizará la configuración del espacio de nombres del usuario. Este script se ejecuta primero al configurar el espacio de nombres. La variable de entorno "SLURM_NS_PID" se proporciona para permitir la construcción de la ruta a los diversos archivos de mapeo a los que este script podría escribir. Si no se especifica, cada usuario y grupo se mapeará.

NOTAS

Si algún parámetro en namespace.yaml se cambia mientras slurm está en ejecución, entonces slurmd en los nodos respectivos deberá reiniciarse para que los cambios surtan efecto (scontrol reconfigure no es suficiente). Además, esto puede ser disruptivo para los trabajos que ya se están ejecutando en el nodo. Por lo tanto, se debe tener cuidado para asegurarse de que no se estén ejecutando trabajos si se implementan cambios en job_container.conf.

Reiniciar slurmd es seguro y no interrumpe los trabajos en ejecución, siempre que job_container.conf no se cambie entre reinicios, en cuyo caso se aplica el punto anterior.

EJEMPLO

---
predeterminados:
  auto_base_path: true
  base_path: "/var/nvme/storage_0"
  clone_ns_flags:
    - "CLONE_NEWPID"
    - "CLONE_NEWUSER"
    - "CLONE_NEWNS"
  clone_ns_epilog: "/ruta/al/script_epilog"
  clone_ns_epilog_wait: 10
  clone_ns_script: "/ruta/al/script_ns"
  init_script: "/ruta/al/script_init"
  shared: true
node_confs:
  - nodes:
    - "n1"
    - "n[2-4,6]"
    options:
      auto_base_path: true
      base_path: "/var/nvme/storage_1"
      clone_ns_script_wait: 20
      dirs: "/tmp"
      shared: false
      user_ns_script: "/ruta/al/script_usuario"
  - nodes:
    - "n[7-10]"
    options:
      auto_base_path: true
      base_path: "/var/nvme/storage_2"
      init_script: "/etc/slurm/init.sh"
