NOMBRE

nlopt_minimize - Minimizar una función no lineal multivariable

SINOPSIS

#include <nlopt.h>

nlopt_result nlopt_minimize(nlopt_algorithm algorithm,
                            int n,
                            nlopt_func f,
                            void* f_data,
                            const double* lb,
                            const double* ub,
                            double* x,
                            double* minf,
                            double minf_max,
                            double ftol_rel,
                            double ftol_abs,
                            double xtol_rel,
                            const double* xtol_abs,
                            int maxeval,
                            double maxtime);

Debería enlazar el programa resultante con las opciones del enlazador
-lnlopt -lm en Unix.

DESCRIPCIÓN

nlopt_minimize() intenta minimizar una función no lineal f de n variables de diseño utilizando el algorithm especificado. El valor mínimo de la función encontrado se devuelve en minf, con los valores correspondientes de las variables de diseño devueltos en el array x de longitud n. Los valores de entrada en x deben ser una suposición inicial para el óptimo. Las entradas lb y ub son arrays de longitud n que contienen los límites inferior y superior, respectivamente, en las variables de diseño x. Los otros parámetros especifican los criterios de parada (tolerancias, el número máximo de evaluaciones de la función, etc.) y otra información según se describe con más detalle a continuación. El valor de retorno es un código entero que indica éxito (positivo) o fracaso (negativo), según se describe a continuación.

Cambiando el parámetro algorithm entre varias constantes predefinidas descritas a continuación, se puede cambiar fácilmente entre una variedad de algoritmos de minimización. Algunos de estos algoritmos requieren que el gradiente (derivadas) de la función se proporcione a través de f, y otros algoritmos no requieren derivadas. Algunos de los algoritmos intentan encontrar un mínimo global dentro de los límites dados, y otros solo encuentran un mínimo local.

La función nlopt_minimize es un envoltorio alrededor de varios paquetes de minimización gratuitos/de código abierto, así como algunas implementaciones nuevas de algoritmos de optimización publicados. Por supuesto, podría compilar y llamar a estos paquetes por separado, y en algunos casos esto proporcionará una mayor flexibilidad que la disponible a través de la interfaz nlopt_minimize. Sin embargo, dependiendo de la función específica que se minimice, los diferentes algoritmos variarán en efectividad. La intención de nlopt_minimize es permitirle cambiar rápidamente entre algoritmos para experimentar con ellos para su problema, proporcionando una interfaz unificada simple a estas subrutinas.

FUNCIÓN OBJETIVO

nlopt_minimize() minimiza una función objetivo f de la forma:

double f(int n,
const double* x,
double* grad,
void* f_data);

El valor de retorno debe ser el valor de la función en el punto x, donde x apunta a un array de longitud n de las variables de diseño. La dimensión n es idéntica a la pasada a nlopt_minimize().

Además, si el argumento grad no es NULL, entonces grad apunta a un array de longitud n que debe establecerse (al retornar) en el gradiente de la función con respecto a las variables de diseño en x. Es decir, grad[i] debe contener al retornar la derivada parcial df/dx[i], para 0 <= i < n, si grad no es NULL. No todos los algoritmos de optimización (a continuación) utilizan la información del gradiente: para los algoritmos listados como "libres de derivadas", el argumento grad siempre será NULL y nunca necesitará ser calculado. (Sin embargo, para los algoritmos que sí utilizan información del gradiente, grad aún puede ser NULL para algunas llamadas).

El argumento f_data es el mismo que el pasado a nlopt_minimize(), y puede usarse para pasar cualquier dato adicional a la función. (Es decir, puede ser un puntero a alguna estructura/tipo de datos definido por el llamador que contenga la información que su función necesita, que usted convierta de void* mediante una conversión de tipo).

RESTRICCIONES

La mayoría de los algoritmos en NLopt están diseñados para la minimización de funciones con restricciones simples de límites en las entradas. Es decir, los vectores de entrada x[i] están restringidos a estar en un hiperrectángulo lb[i] <= x[i] <= ub[i] para 0 <= i < n, donde lb y ub son los dos arrays pasados a nlopt_minimize().

Sin embargo, algunos de los algoritmos admiten optimización parcial o totalmente sin restricciones, como se indica a continuación, donde una variable de diseño (parcial o totalmente) sin restricciones se indica con un límite inferior igual a -Inf y/o un límite superior igual a +Inf. Aquí, Inf es el infinito de punto flotante IEEE-754, que (en ANSI C99) se representa mediante la macro INFINITY en math.h. Alternativamente, para versiones más antiguas de C, también puede usar la macro HUGE_VAL (también en math.h).

Con algunos de los algoritmos, especialmente aquellos que no requieren información de derivadas, una forma simple (pero no especialmente eficiente) de implementar restricciones no lineales arbitrarias es retornar Inf (ver arriba) siempre que las restricciones sean violadas por una entrada dada x. Más en general, existen varias formas de implementar restricciones añadiendo "términos de penalización" a su función objetivo, que se describen en la literatura de optimización. Una forma mucho más eficiente de especificar restricciones no lineales se proporciona mediante la función nlopt_minimize_constrained() (descrita en su propia página de manual).

ALGORITMOS

El parámetro algorithm especifica el algoritmo de optimización (para más detalles sobre estos, consulte los archivos README en los subdirectorios del código fuente), y puede tomar cualquiera de los siguientes valores constantes. Las constantes con _G{N,D}_ en sus nombres se refieren a métodos de optimización global, mientras que _L{N,D}_ se refiere a métodos de optimización local (que intentan encontrar un mínimo local comenzando desde la suposición inicial x). Las constantes con _{G,L}N_ se refieren a algoritmos sin gradiente (libres de derivadas) que no requieren que la función objetivo proporcione un gradiente, mientras que _{G,L}D_ se refiere a algoritmos basados en derivadas que requieren que la función objetivo proporcione un gradiente. (Especialmente para optimización local, los algoritmos basados en derivadas son generalmente superiores a los libres de derivadas: el gradiente es útil si puede calcularlo económicamente, por ejemplo, mediante un método adjunto).

NLOPT_GN_DIRECT_L
Realiza una optimización global (G) libre de derivadas (N) utilizando el algoritmo de búsqueda DIRECT-L de Jones et al. modificado por Gablonsky et al. para estar más orientado a la búsqueda local. No admite optimización sin restricciones. También existen varias otras variantes del algoritmo DIRECT que son compatibles: NLOPT_GN_DIRECT, que es el algoritmo DIRECT original; NLOPT_GN_DIRECT_L_RAND, una versión ligeramente aleatorizada de DIRECT-L que puede ser mejor en espacios de búsqueda de alta dimensionalidad; NLOPT_GN_DIRECT_NOSCAL, NLOPT_GN_DIRECT_L_NOSCAL y NLOPT_GN_DIRECT_L_RAND_NOSCAL, que son versiones de DIRECT donde las dimensiones no se reescalan a un cubo unitario (lo que significa que las dimensiones con límites más grandes reciben más peso).
NLOPT_GN_ORIG_DIRECT_L
Una optimización global (G) libre de derivadas (N) utilizando el algoritmo DIRECT-L como se mencionó anteriormente, junto con NLOPT_GN_ORIG_DIRECT que es el algoritmo DIRECT original. A diferencia de NLOPT_GN_DIRECT_L anterior, estos dos algoritmos se basan en el código Fortran original de Gablonsky et al., que tiene algunas limitaciones codificadas para la cantidad de subdivisiones, etc., y no admite todos los criterios de parada de NLopt, pero por otro lado admite restricciones no lineales arbitrarias como se describe anteriormente.

NÚMEROS PSEUDOALEATORIOS

Para algoritmos de optimización estocástica, utilizamos números pseudoaleatorios generados por el algoritmo Mersenne Twister, basado en código de Makoto Matsumoto. Por defecto, la semilla para los números aleatorios se genera a partir de la hora del sistema, de modo que serán diferentes cada vez que ejecutes el programa. Si deseas utilizar números aleatorios deterministas, puedes establecer la semilla llamando a:

void nlopt_srand(unsigned long seed);

Algunos de los algoritmos también soportan el uso de secuencias de baja discrepancia (LDS), a veces conocidas como números cuasi-aleatorios. NLopt utiliza la LDS de Sobol, que está implementada para hasta 1111 dimensiones. maxeval.
