NLOPT(3) Manual de programación de NLopt NLOPT(3)

NOMBRE

nlopt - Biblioteca de optimización no lineal

SINOPSIS

#include <nlopt.h>

nlopt_opt opt = nlopt_create(algoritmo, n);
nlopt_set_min_objective(opt, f, f_data);
nlopt_set_ftol_rel(opt, tol);
...
nlopt_optimize(opt, x , &opt_f);
nlopt_destroy(opt);

El "..." indica cualquier número de llamadas a funciones de NLopt, a continuación, para
establecer parámetros de la optimización, restricciones y criterios de parada.
Aquí, nlopt_set_ftol_rel es meramente un ejemplo de un posible criterio de
parada. Debería enlazar el programa resultante con las banderas del enlazador
-lnlopt -lm en Unix.

DESCRIPCIÓN

NLopt es una biblioteca para la optimización no lineal. Intenta minimizar (o maximizar) una función objetivo no lineal dada f de n variables de diseño, utilizando el algoritmo especificado, posiblemente sujeto a restricciones lineales o no lineales. El valor óptimo de la función encontrado se devuelve en opt_f (tipo double) con los valores correspondientes de las variables de diseño devueltos en el array (double) x de longitud n. Los valores de entrada en x deben ser una conjetura inicial para el óptimo.

Los parámetros de la optimización se controlan a través del objeto opt de tipo nlopt_opt, que se crea mediante la función nlopt_create y se elimina mediante nlopt_destroy. Al llamar a varias funciones de la biblioteca NLopt, se pueden especificar criterios de parada (por ejemplo, una tolerancia relativa en el valor de la función objetivo se especifica mediante nlopt_set_ftol_rel), límites superior y/o inferior en los parámetros de diseño x, e incluso restricciones arbitrarias no lineales de desigualdad y igualdad.

Cambiando el parámetro algoritmo entre varias constantes predefinidas descritas a continuación, se puede cambiar fácilmente entre una variedad de algoritmos de minimización. Algunos de estos algoritmos requieren el gradiente (derivadas) de la función proporcionado a través de f, y otros algoritmos no requieren derivadas. Algunos de los algoritmos intentan encontrar un óptimo global dentro de los límites dados, y otros solo encuentran un óptimo local. La mayoría de los algoritmos solo manejan el caso en el que no hay restricciones no lineales. La biblioteca NLopt es un envoltorio alrededor de varios paquetes de minimización gratuitos/de código abierto, así como algunas implementaciones nuevas de algoritmos de optimización publicados. Por supuesto, podría compilar y llamar a estos paquetes por separado, y en algunos casos esto proporcionará una mayor flexibilidad que la disponible a través de NLopt. Sin embargo, dependiendo de la función específica que se optimice, los diferentes algoritmos variarán en efectividad. La intención de NLopt es permitirle cambiar rápidamente entre algoritmos para experimentar con ellos para su problema, proporcionando una interfaz unificada simple a estas subrutinas.

FUNCIÓN OBJETIVO

La función objetivo se especifica llamando a una de las siguientes:

nlopt_result nlopt_set_min_objective(nlopt_opt opt,
nlopt_func f,
void* f_data);
nlopt_result nlopt_set_max_objective(nlopt_opt opt,
nlopt_func f,
void* f_data);

dependiendo de si se desea minimizar o maximizar la función objetivo f, respectivamente. La función f debe tener la forma:

double f(unsigned n,
const double* x,
double* grad,
void* f_data);

El valor de retorno debe ser el valor de la función en el punto x, donde x apunta a un array de longitud n de las variables de diseño. La dimensión n es idéntica a la pasada a nlopt_create.

Además, si el argumento grad no es NULL, entonces grad apunta a un array de longitud n que debería (al regresar) establecerse en el gradiente de la función con respecto a las variables de diseño en x. Es decir, grad[i] debería contener la derivada parcial df/dx[i], para 0 <= i < n, si grad no es NULL. No todos los algoritmos de optimización (a continuación) utilizan la información del gradiente: para los algoritmos listados como "libres de derivadas", el argumento grad siempre será NULL y nunca necesitará ser calculado. (Para los algoritmos que sí utilizan información del gradiente, sin embargo, grad aún puede ser NULL para algunas llamadas).

El argumento f_data es el mismo que se pasó a nlopt_set_min_objective o nlopt_set_max_objective, y puede usarse para pasar cualquier dato adicional a la función. (Es decir, puede ser un puntero a alguna estructura/tipo de datos definido por el usuario que contenga la información que su función necesita, que usted convierte de void* mediante un typecast).

RESTRICCIONES DE LÍMITES

La mayoría de los algoritmos en NLopt están diseñados para la minimización de funciones con restricciones de límites simples en las entradas. Es decir, los vectores de entrada x[i] están restringidos a estar en un hiperrectángulo lb[i] <= x[i] <= ub[i] para 0 <= i < n. Estos límites se especifican pasando los arrays lb y ub de longitud n a una o ambas de las funciones:

nlopt_result nlopt_set_lower_bounds(nlopt_opt opt,
const double* lb);
nlopt_result nlopt_set_upper_bounds(nlopt_opt opt,
const double* ub);

Si no se establece un límite inferior/superior, el valor predeterminado es sin límite (no restringido, es decir, un límite de infinito); es posible tener límites inferiores pero no superiores o viceversa. Alternativamente, el usuario puede llamar a una de las funciones anteriores y pasar explícitamente un límite inferior de -HUGE_VAL y/o un límite superior de +HUGE_VAL para algunas variables de diseño para que no tengan límite inferior/superior, respectivamente. (HUGE_VAL es la constante estándar de C para un infinito de punto flotante, que se encuentra en el archivo de cabecera math.h).

Sin embargo, tenga en cuenta que algunos de los algoritmos en NLopt, en particular la mayoría de los algoritmos de optimización global, no admiten la optimización sin restricciones y devolverán un error si no proporciona límites inferiores y superiores finitos.

Para mayor comodidad, se proporcionan las siguientes dos funciones para establecer los límites inferior/superior para todas las variables de diseño a una única constante (para que no tenga que rellenar un array con un valor constante):

nlopt_result nlopt_set_lower_bounds1(nlopt_opt opt,
double lb);
nlopt_result nlopt_set_upper_bounds1(nlopt_opt opt,
double ub);

RESTRICCIONES NO LINEALES

Varios de los algoritmos en NLopt (MMA y ORIG_DIRECT) también admiten restricciones de desigualdad no lineales arbitrarias, y algunos también permiten restricciones de igualdad no lineales (COBYLA, SLSQP, ISRES y AUGLAG). Para estos algoritmos, puede especificar tantas restricciones no lineales como desee llamando a las siguientes funciones varias veces.

En particular, una restricción de desigualdad no lineal de la forma fc(x) <= 0, donde la función fc tiene la misma forma que la función objetivo descrita anteriormente, se puede especificar llamando a:

nlopt_result nlopt_add_inequality_constraint(nlopt_opt opt,
nlopt_func fc,
void* fc_data,
double tol);

Al igual que con la función objetivo, fc_data es un puntero a datos de usuario arbitrarios que se pasarán a la función fc cada vez que se llame. El parámetro tol es una tolerancia que se utiliza solo para criterios de parada: un punto x se considera factible para juzgar si se debe detener la optimización si fc(x) <= tol. Una tolerancia de cero significa que NLopt intentará no considerar ningún x como convergido a menos que fc sea estrictamente no positivo; en general, al menos una pequeña tolerancia positiva es aconsejable para reducir la sensibilidad a los errores de redondeo.

Una restricción de igualdad no lineal de la forma h(x) = 0, donde la función h tiene la misma forma que la función objetivo descrita anteriormente, se puede especificar llamando a:

nlopt_result nlopt_add_equality_constraint(nlopt_opt opt,
nlopt_func h,
void* h_data,
double tol);

CONSTRAINT FUNCTIONS

You can add inequality and/or equality constraints to the problem by calling the following functions:

nlopt_result nlopt_add_inequality_constraint(nlopt_opt opt,
nlopt_func f,
void* f_data,
double tol);
nlopt_result nlopt_add_equality_constraint(nlopt_opt opt,
nlopt_func h,
void* h_data,
double tol);

The f_data and h_data pointers are for arbitrary user data passed to the constraint functions f and h, respectively. The tol parameters are tolerances used for stopping criteria only: a point x is considered feasible for judging whether to stop the optimization if |f(x)| <= tol for inequality constraints and |h(x)| <= tol for equality constraints. A small positive tolerance is strongly advised for equality constraints in order to allow NLopt to converge even if the equality constraint is slightly nonzero.

Note that nlopt_add_inequality_constraint adds a constraint of the form f(x) >= 0, whereas nlopt_add_equality_constraint adds a constraint of the form h(x) = 0.

Some algorithms (see below) also support constraints where the gradient is provided. To add such constraints, use:

nlopt_result nlopt_add_inequality_constraint_grad(nlopt_opt opt,
nlopt_func f,
void* f_data,
nlopt_func grad,
void* grad_data,
double tol);
nlopt_result nlopt_add_equality_constraint_grad(nlopt_opt opt,
nlopt_func h,
void* h_data,
nlopt_func grad,
void* grad_data,
double tol);

Here, grad is a function that computes the gradient of the constraint function, and grad_data is user data for the gradient function. For algorithms that do not support gradients, the grad arguments will be ignored.

To remove all of the inequality and/or equality constraints from a given problem opt, you can call the following functions:

nlopt_result nlopt_remove_inequality_constraints(nlopt_opt opt);
nlopt_result nlopt_remove_equality_constraints(nlopt_opt opt);

ALGORITHMS

The algorithm parameter specifies the optimization algorithm (for more detail on these, see the README files in the source-code subdirectories), and can take on any of the following constant values.

Constants with _G{N,D}_ in their names refer to global optimization methods, whereas _L{N,D}_ refers to local optimization methods (that try to find a local optimum starting from the starting guess x). Constants with _{G,L}N_ refer to non-gradient (derivative-free) algorithms that do not require the objective function to supply a gradient, whereas _{G,L}D_ refers to derivative-based algorithms that require the objective function to supply a gradient. (Especially for local optimization, derivative-based algorithms are generally superior to derivative-free ones: the gradient is good to have if you can compute it cheaply, e.g. via an adjoint method.)

The algorithm specified for a given problem opt is returned by the function:

nlopt_algorithm nlopt_get_algorithm(nlopt_opt opt);

The available algorithms are:

NLOPT_GN_DIRECT_L
Perform a global (G) derivative-free (N) optimization using the DIRECT-L search algorithm by Jones et al. as modified by Gablonsky et al. to be more weighted towards local search. Does not support unconstrainted optimization. There are also several other variants of the DIRECT algorithm that are supported: NLOPT_GN_DIRECT, which is the original DIRECT algorithm; NLOPT_GN_DIRECT_L_RAND, a slightly randomized version of DIRECT-L that may be better in high-dimensional search spaces; NLOPT_GN_DIRECT_NOSCAL, NLOPT_GN_DIRECT_L_NOSCAL, and NLOPT_GN_DIRECT_L_RAND_NOSCAL, which are versions of DIRECT where the dimensions are not rescaled to a unit hypercube (which means that dimensions with larger bounds are given more weight).
NLOPT_GN_ORIG_DIRECT_L
A global (G) derivative-free optimization using the DIRECT-L algorithm as above, along with NLOPT_GN_ORIG_DIRECT which is the original DIRECT algorithm. Unlike NLOPT_GN_DIRECT_L above, these two algorithms refer to code based on the original Fortran code of Gablonsky et al., which has some hard-coded limitations on the number of subdivisions etc. and does not support all of the NLopt stopping criteria, but on the other hand it supports arbitrary nonlinear inequality constraints.
NLOPT_GD_STOGO
Global (G) optimization using the StoGO algorithm by Madsen et al. StoGO exploits gradient information (D) (which must be supplied by the objective) for its local searches, and performs the global search by a branch-and-bound technique. Only bound-constrained optimization is supported. There is also another variant of this algorithm, NLOPT_GD_STOGO_RAND, which is a randomized version of the StoGO search scheme. The StoGO algorithms are only available if NLopt is compiled with C++ code enabled, and should be linked via -lnlopt_cxx instead of -lnlopt (via a C++ compiler, in order to link the C++ standard libraries).
NLOPT_LN_NELDERMEAD
Perform a local (L) derivative-free (N) optimization, starting at x, using the Nelder-Mead simplex algorithm, modified to support bound constraints. Nelder-Mead, while popular, is known to occasionally fail to converge for some objective functions, so it should be used with caution. Anecdotal evidence, on the other hand, suggests that it works fairly well for some cases that are hard to handle otherwise, e.g. noisy/discontinuous objectives. See also NLOPT_LN_SBPLX below.
NLOPT_LN_SBPLX
Perform a local (L) derivative-free (N) optimization, starting at x, using an algorithm based on the Subplex algorithm of Rowan et al., which is an improved variant of Nelder-Mead (above). Our implementation does not use Rowan's original code, and has some minor modifications such as explicit support for bound constraints. (Like Nelder-Mead, Subplex often works well in practice, even for noisy/discontinuous objectives, but there is no rigorous guarantee that it will converge.)
NLOPT_LN_PRAXIS
Local (L) derivative-free (N) optimization using the principal-axis method, based on code by Richard Brent. Designed for unconstrained optimization, although bound constraints are supported too (via the inefficient method of returning +Inf when the constraints are violated).
NLOPT_LD_LBFGS
Local (L) gradient-based (D) optimization using the limited-memory BFGS (L-BFGS) algorithm. (The objective function must supply the gradient.) Unconstrained optimization is supported in addition to simple bound constraints (see above). Based on an implementation by Luksan et al.
NLOPT_LD_VAR2
Local (L) gradient-based (D) optimization using a shifted limited-memory variable-metric method based on code by Luksan et al., supporting both unconstrained and bound-constrained optimization. NLOPT_LD_VAR2 uses a rank-2 method, while .B NLOPT_LD_VAR1 is another variant using a rank-1 method.
NLOPT_LD_TNEWTON_PRECOND_RESTART
Local (L) gradient-based (D) optimization using an LBFGS-preconditioned truncated Newton method with steepest-descent restarting, based on code by Luksan et al., supporting both unconstrained and bound-constrained optimization. There are several other variants of this algorithm: NLOPT_LD_TNEWTON_PRECOND (same without restarting), NLOPT_LD_TNEWTON_RESTART (same without preconditioning), and NLOPT_LD_TNEWTON (same without restarting or preconditioning).
NLOPT_GN_CRS2_LM
Global (G) derivative-free (N) optimization using the controlled random search (CRS2) algorithm of Price, with the "local mutation" (LM) modification suggested by Kaelo and Ali.
NLOPT_GN_ISRES
Global (G) derivative-free (N) optimization using a genetic algorithm (mutation and differential evolution), using a stochastic ranking to handle nonlinear inequality and equality constraints as suggested by Runarsson and Yao.
NLOPT_G_MLSL_LDS, NLOPT_G_MLSL
Global (G) optimization using the multi-level single-linkage (MLSL) algorithm with a low-discrepancy sequence (LDS) or pseudorandom numbers, respectively. This algorithm executes a low-discrepancy or pseudorandom sequence of local searches, with a clustering heuristic to avoid multiple local searches for the same local optimum. The local search algorithm must be specified, along with termination criteria/tolerances for the local searches, by nlopt_set_local_optimizer. (This subsidiary algorithm can be with or without derivatives, and determines whether the objective function needs gradients.)
NLOPT_LD_MMA, NLOPT_LD_CCSAQ
Local (L) gradient-based (D) optimization using the method of moving asymptotes (MMA), or rather a refined version of the algorithm as published by Svanberg (2002). (NLopt uses an independent free-software/open-source implementation of Svanberg's algorithm.) CCSAQ is a related algorithm from Svanberg's paper which uses a local quadratic approximation rather than the more-complicated MMA model; the two usually have similar convergence rates. The NLOPT_LD_MMA algorithm supports both bound-constrained and unconstrained optimization, and also supports an arbitrary number (m) of nonlinear inequality (not equality) constraints as described above.
NLOPT_LD_SLSQP
Local (L) gradient-based (D) optimization using sequential quadratic programming and BFGS updates, supporting arbitrary nonlinear inequality and equality constraints, based on the code by Dieter Kraft (1988) adapted for use by the SciPy project. Note that this algorithm uses dense-matrix methods requiring O(n^2) storage and O(n^3) time, making it less practical for problems involving more than a few thousand parameters.
NLOPT_LN_COBYLA
Local (L) derivative-free (N) optimization using the COBYLA algorithm of Powell (Constrained Optimization BY Linear Approximations). The NLOPT_LN_COBYLA algorithm supports both bound-constrained and unconstrained optimization, and also supports an arbitrary number (m) of nonlinear inequality/equality constraints as described above.

INITIAL STEP SIZE

For some algorithms, it is necessary to specify an initial step size dx to be used in finding the first points. By default, this initial step size is chosen heuristically in some algorithm-specific way, but it can be changed by calling:

nlopt_result nlopt_set_initial_step(nlopt_opt opt,
double dx);

POBLACIÓN ESTOCÁSTICA

Varios de los algoritmos de búsqueda estocástica (por ejemplo, CRS, MLSL e ISRES) comienzan generando una "población" inicial de puntos aleatorios x. Por defecto, el tamaño de esta población inicial se elige heurísticamente de alguna manera específica del algoritmo, pero la población inicial se puede cambiar llamando a:

nlopt_result nlopt_set_population(nlopt_opt opt,
unsigned pop);

(Un pop de cero implica que se utilizará el valor predeterminado heurístico.)

NÚMEROS PSEUDOALEATORIOS

Para los algoritmos de optimización estocástica, utilizamos números pseudoaleatorios generados por el algoritmo Mersenne Twister, basado en código de Makoto Matsumoto. Por defecto, la semilla para los números aleatorios se genera a partir de la hora del sistema, de modo que serán diferentes cada vez que ejecute el programa. Si desea utilizar números aleatorios deterministas, puede establecer la semilla llamando a:

void nlopt_srand(unsigned long seed);

Algunos de los algoritmos también admiten el uso de secuencias de baja discrepancia (LDS), a veces conocidas como números cuasi-aleatorios. NLopt utiliza la LDS de Sobol, que está implementada para hasta 1111 dimensiones.
