rpmatch(3) Manual de funciones de biblioteca rpmatch(3)

NOMBRE

rpmatch - determina si la respuesta a una pregunta es afirmativa o negativa

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <stdlib.h>
int rpmatch(const char *response);
Requisitos de macro de prueba de características para glibc (ver feature_test_macros(7)):

rpmatch():

    Desde glibc 2.19:
        _DEFAULT_SOURCE
    glibc 2.19 y anteriores:
        _SVID_SOURCE

DESCRIPCIÓN

rpmatch() maneja la respuesta de un usuario a preguntas de sí o no, con soporte para internacionalización.

response debe ser una cadena terminada en nulo que contenga la respuesta proporcionada por el usuario, obtenida quizás con fgets(3) o getline(3).

La preferencia de idioma del usuario se tiene en cuenta según las variables de entorno LANG, LC_MESSAGES y LC_ALL, si el programa ha llamado a setlocale(3) para efectuar sus cambios.

Independientemente de la configuración regional, las respuestas que coincidan con ^[Yy] siempre se aceptan como afirmativas, y las que coincidan con ^[Nn] siempre se aceptan como negativas.

VALOR DE RETORNO

Después de examinar response, rpmatch() devuelve 0 para una respuesta negativa reconocida ("no"), 1 para una respuesta positiva reconocida ("sí"), y -1 cuando el valor de response no se reconoce.

ERRORES

Un valor de retorno de -1 puede indicar una entrada inválida o algún otro error. Es incorrecto solo comprobar si el valor de retorno es distinto de cero.

rpmatch() puede fallar por cualquiera de las razones por las que regcomp(3) o regexec(3) pueden fallar; el error no está disponible en errno ni en ningún otro lugar, pero indica un fallo del motor de expresiones regulares (pero este caso no es distinguible del de un valor no reconocido de response).

ATRIBUTOS

Para una explicación de los términos utilizados en esta sección, ver attributes(7).

Interfaz Atributo Valor
rpmatch () Seguridad de hilos MT-Safe locale

ESTÁNDARES

Ninguno.

HISTORIA

GNU, FreeBSD, AIX.

ERRORES CONOCIDOS

El YESEXPR y NOEXPR de algunas configuraciones regionales (incluida "C") solo inspeccionan el primer carácter de la response. Esto puede significar que "yno", etc., se resuelven a 1. Este es un desafortunado efecto secundario histórico que debería corregirse con el tiempo con una localización adecuada, y no debería disuadir de que rpmatch() sea la forma correcta de distinguir entre respuestas binarias.

EJEMPLOS

El siguiente programa muestra los resultados cuando rpmatch() se aplica a la cadena proporcionada en el argumento de línea de comandos del programa.

#define _DEFAULT_SOURCE
#include <locale.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
int
main(int argc, char *argv[])
{
    if (argc != 2 || strcmp(argv[1], "--help") == 0) {
        fprintf(stderr, "%s respuesta\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    setlocale(LC_ALL, "");
    printf("rpmatch() devuelve: %d\n", rpmatch(argv[1]));
    exit(EXIT_SUCCESS);
}
