NOMBRE

rpcbind — mapeador de direcciones universales a números de programa RPC

SINOPSIS

rpcbind [-adfhilsvw]

DESCRIPCIÓN

La utilidad rpcbind es un servidor que convierte números de programa RPC en direcciones universales. Debe estar en ejecución en el host para poder realizar llamadas RPC a un servidor en esa máquina.

Cuando se inicia un servicio RPC, este le informa a rpcbind la dirección en la que está escuchando y los números de programa RPC que está preparado para atender. Cuando un cliente desea realizar una llamada RPC a un número de programa determinado, primero se pone en contacto con rpcbind en la máquina del servidor para determinar la dirección a la que se deben enviar las solicitudes RPC.

La utilidad rpcbind debe iniciarse antes que cualquier otro servicio RPC. Normalmente, los servidores RPC estándar son iniciados por los monitores de puertos, por lo que rpcbind debe iniciarse antes de que se invoquen los monitores de puertos.

Cuando se inicia rpcbind, verifica que ciertas llamadas de traducción de nombres a direcciones funcionen correctamente. Si fallan, es posible que las bases de datos de configuración de red estén corruptas. Dado que los servicios RPC no pueden funcionar correctamente en esta situación, rpcbind informa la condición y termina.

La utilidad rpcbind solo puede ser iniciada por el superusuario.

OPCIONES

-a
Al depurar (-d), se aborta en caso de errores.
-d
Ejecutar en modo de depuración. En este modo, rpcbind registrará información adicional durante la operación y se abortará en ciertos errores si también se especifica -a. Con esta opción, las comprobaciones de consistencia de traducción de nombres a direcciones se muestran en detalle.
-f
No bifurcar y convertirse en un proceso en segundo plano.
-h
Especificar direcciones IP concretas para enlazar las solicitudes UDP. Esta opción se puede especificar varias veces y se puede usar para restringir las interfaces a las que responderá rpcbind. Al especificar direcciones IP con -h, rpcbind añadirá automáticamente 127.0.0.1 y, si IPv6 está habilitado, ::1 a la lista. Si no se especifica ninguna opción -h, rpcbind se enlazará a INADDR_ANY, lo que podría generar problemas en un host con múltiples interfaces, ya que rpcbind devolvería un paquete UDP desde una dirección IP diferente a la que se envió. Tenga en cuenta que cuando rpcbind se controla mediante la activación de socket de systemd, la opción -h se ignora. En este caso, debe editar las definiciones ListenStream y ListenDgram en /usr/lib/systemd/system/rpcbind.socket en su lugar.
-i
Modo "no seguro". Permite llamadas a SET y UNSET desde cualquier host. Normalmente, rpcbind acepta estas solicitudes solo desde la interfaz de bucle invertido por motivos de seguridad. Este cambio es necesario para programas que se compilaron con versiones anteriores de la biblioteca rpc y que no realizan esas solicitudes a través de la interfaz de bucle invertido.
-l
Activar el registro de conexiones de libwrap.
-s
Hace que rpcbind cambie al usuario daemon tan pronto como sea posible. Esto hace que rpcbind utilice puertos no privilegiados para conexiones salientes, evitando que clientes no privilegiados utilicen rpcbind para conectarse a servicios desde un puerto privilegiado.
-v
Imprime la versión de rpcbind y la configuración interna y sale.
-w
Hace que rpcbind realice un inicio "en caliente" leyendo un archivo de estado cuando rpcbind se inicia. El archivo de estado se crea cuando rpcbind termina.

ARCHIVOS

La utilidad rpcbind intenta cargar el archivo de configuración en el siguiente orden:

/etc/rpcbind.conf
/etc/default/rpcbind
/etc/sysconfig/rpcbind

NOTAS

Todos los servidores RPC deben reiniciarse si se reinicia rpcbind.
