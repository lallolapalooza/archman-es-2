Paquete: libtirpc

Licencias: SISSL, BSD-3-Clause

RPC_SVC_REG(3) Manual de funciones de biblioteca RPC_SVC_REG(3)

NOMBRE

rpc_svc_reg, rpc_reg, svc_reg, svc_unreg, svc_auth_reg, xprt_register, xprt_unregister — rutinas de biblioteca para registrar servidores

SINOPSIS

#include <rpc/rpc.h>

int
rpc_reg(rpcprog_t prognum, rpcvers_t versnum, rpcproc_t procnum, char *(*procname)(), xdrproc_t inproc, xdrproc_t outproc, char *nettype);

bool_t
svc_reg(SVCXPRT *xprt, const rpcprog_t prognum, const rpcvers_t versnum, void (*dispatch)(struct svc_req *, SVCXPRT *), const struct netconfig *netconf);

void
svc_unreg(const rpcprog_t prognum, const rpcvers_t versnum);

int
svc_auth_reg(int cred_flavor, enum auth_stat (*handler)(struct svc_req *, struct rpc_msg *));

void
xprt_register(SVCXPRT *xprt);

void
xprt_unregister(SVCXPRT *xprt);

DESCRIPCIÓN

Estas rutinas forman parte de la biblioteca RPC que permite a los servidores RPC registrarse con rpcbind (ver rpcbind(8)), y asociar el programa y número de versión dados con la función de despacho. Cuando el servidor RPC recibe una solicitud RPC, la biblioteca invoca la rutina de despacho con los argumentos apropiados.

Rutinas

Ver rpc(3) para la definición de la estructura de datos SVCXPRT.

rpc_reg()
Registra el programa prognum, el procedimiento procname, y la versión versnum con el paquete de servicio RPC. Si llega una solicitud para el programa prognum, la versión versnum y el procedimiento procnum, se llama a procname con un puntero a su(s) argumento(s); procname debe devolver un puntero a su(s) resultado(s) estático(s); inproc es la función XDR utilizada para decodificar los argumentos, mientras que outproc es la función XDR utilizada para codificar los resultados. Los procedimientos se registran en todos los transportes disponibles de la clase nettype. Ver rpc(3). Esta rutina devuelve 0 si el registro tuvo éxito, -1 en caso contrario.
svc_reg()
Asocia prognum y versnum con el procedimiento de despacho del servicio, dispatch. Si netconf es NULL, el servicio no se registra con el servicio rpcbind(8). Si netconf no es cero, entonces se establece una correspondencia del triple [prognum, versnum, netconf->nc_netid] con xprt->xp_ltaddr con el servicio rpcbind local.

La rutina svc_reg() devuelve 1 si tiene éxito y 0 en caso contrario.

svc_unreg()
Elimina del servicio rpcbind todas las correspondencias del triple [prognum, versnum, todos-los-transportes] con la dirección de red y todas las correspondencias dentro del paquete de servicio RPC del doble [prognum, versnum] con las rutinas de despacho.
svc_auth_reg()
Registra la rutina de autenticación del servicio handler con el mecanismo de despacho para que pueda ser invocada para autenticar solicitudes RPC recibidas con el tipo de autenticación cred_flavor. Esta interfaz permite a los desarrolladores agregar nuevos tipos de autenticación a sus aplicaciones RPC sin necesidad de modificar las bibliotecas. Los implementadores de servicios generalmente no necesitan esta rutina.

La aplicación de servicio típica llamaría a svc_auth_reg() después de registrar el servicio y antes de llamar a svc_run(). Cuando sea necesario procesar una credencial RPC de tipo cred_flavor, se llamará al procedimiento handler con dos argumentos, struct svc_req *rqst y struct rpc_msg *msg, y se espera que devuelva un valor válido de enum auth_stat. No hay disposición para cambiar o eliminar un manejador de autenticación una vez registrado.

La rutina svc_auth_reg() devuelve 0 si el registro es exitoso, 1 si cred_flavor ya tiene un manejador de autenticación registrado para él, y -1 en caso contrario.

xprt_register()
Después de que se crea el manejador de transporte del servicio RPC xprt, se registra con el paquete de servicio RPC. Esta rutina modifica la variable global svc_fdset (ver rpc_svc_calls(3)). Los implementadores de servicios generalmente no necesitan esta rutina.
xprt_unregister()
Antes de que se destruya un manejador de transporte del servicio RPC xprt, se desregistra del paquete de servicio RPC. Esta rutina modifica la variable global svc_fdset (ver rpc_svc_calls(3)). Los implementadores de servicios generalmente no necesitan esta rutina.
