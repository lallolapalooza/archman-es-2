DESCRIPCIÓN

Las rutinas de la biblioteca RPC permiten que los programas del lenguaje C realicen llamadas a procedimientos en otras máquinas a través de la red. Primero, el cliente llama a un procedimiento para enviar una solicitud al servidor. Al recibir la solicitud, el servidor llama a una rutina de despacho para realizar el servicio solicitado y luego envía una respuesta.

Las rutinas clnt_call(), rpc_call(), y rpc_broadcast() gestionan el lado del cliente de la llamada al procedimiento. Las rutinas restantes se ocupan del manejo de errores en caso de fallos.

Algunas de las rutinas toman un manejador CLIENT como uno de los argumentos. Un manejador CLIENT puede ser creado por una rutina de creación RPC como clnt_create() (ver rpc_clnt_create(3)).

Estas rutinas son seguras para usar en aplicaciones multihilo. Los manejadores CLIENT pueden ser compartidos entre hilos, sin embargo, en esta implementación, las solicitudes de diferentes hilos se serializan (es decir, la primera solicitud recibirá sus resultados antes de que se envíe la segunda solicitud).

Rutinas

Consulte rpc(3) para conocer la definición de la estructura de datos CLIENT.

clnt_call()
Una macro de función que llama al procedimiento remoto procnum asociado con el manejador del cliente, clnt, que se obtiene con una rutina de creación de cliente RPC como clnt_create() (ver rpc_clnt_create(3)). El argumento inproc es la función XDR utilizada para codificar los argumentos del procedimiento, y outproc es la función XDR utilizada para decodificar los resultados del procedimiento; in es la dirección del(los) argumento(s) del procedimiento, y out es la dirección donde colocar el(los) resultado(s). El argumento tout es el tiempo permitido para que se devuelvan los resultados, que es reemplazado por un tiempo de espera establecido explícitamente a través de clnt_control(), ver rpc_clnt_create(3). Si la llamada remota tiene éxito, el estado devuelto es RPC_SUCCESS, de lo contrario, se devuelve un estado apropiado.
clnt_freeres()
Una macro de función que libera cualquier dato asignado por el sistema RPC/XDR al decodificar los resultados de una llamada RPC. El argumento out es la dirección de los resultados, y outproc es la rutina XDR que describe los resultados. Esta rutina devuelve 1 si los resultados se liberaron correctamente y 0 en caso contrario.
clnt_geterr()
Una macro de función que copia la estructura de error del manejador del cliente a la estructura en la dirección errp.
clnt_perrno()
Imprime un mensaje en el error estándar correspondiente a la condición indicada por stat. Se agrega una nueva línea. Normalmente se usa después de que una llamada a procedimiento falla para una rutina para la que no se necesita un manejador de cliente, por ejemplo, rpc_call().
clnt_perror()
Imprime un mensaje en el error estándar indicando por qué falló una llamada RPC; clnt es el manejador utilizado para realizar la llamada. El mensaje se antepone con la cadena s y dos puntos. Se agrega una nueva línea. Normalmente se usa después de que una llamada a procedimiento remoto falla para una rutina que requiere un manejador de cliente, por ejemplo, clnt_call().
clnt_sperrno()

rpc_clnt_calls(3t)

NAME

clnt_sperrno, clnt_sperror, rpc_broadcast, rpc_broadcast_exp, rpc_call - client side of RPC

SYNOPSIS

clnt_sperrno(rpc_errnum)
clnt_sperror(rpch)
rpc_broadcast(prognum, versnum, procnum, xdr_args, argp, xdr_results, resultsp, nettype)
rpc_broadcast_exp(prognum, versnum, procnum, xdr_args, argp, xdr_results, resultsp, nettype, inittime, waittime)
rpc_call(host, prognum, versnum, procnum, xdr_args, argp, xdr_results, resultsp, nettype)

DESCRIPTION

These routines are part of the client-side support for remote procedure calls.

Routines

clnt_sperrno()
Used instead of clnt_perrno() when the program does not have a standard error output (e.g., a server process), or if the programmer does not want the message to be output using printf() (see printf(3)), or if a different message format than that supported by clnt_perrno() is to be used. Note: unlike clnt_sperror() and clnt_spcreateerror() (see rpc_clnt_create(3)), clnt_sperrno() does not return a pointer to static data, so the result will not be overwritten on each call.
clnt_sperror()
Like clnt_perror(), except that (like clnt_sperrno()) it returns a string instead of printing to standard error. However, clnt_sperror() does not append a newline character at the end of the message. Warning: returns a pointer to a buffer that is overwritten on each call.
rpc_broadcast()
Like rpc_call(), except that the call message is broadcast to all connectionless transports specified by nettype. If nettype is NULL, it defaults to "netpath". Each time a response is received, this routine calls eachresult(), which has the following form: bool_t eachresult(caddr_t out, const struct netbuf * addr, const struct netconfig * netconf) Here, out is the same as the out argument passed to rpc_broadcast(), except that the remote procedure's output is decoded there. addr points to the address of the machine that sent the results, and netconf is the netconfig structure of the transport on which the remote server responded. If eachresult() returns 0, rpc_broadcast() waits for more replies; otherwise, it returns with the appropriate status. Warning: broadcast file descriptors are limited in size to the maximum transfer size of that transport. For Ethernet, this value is 1500 bytes. The rpc_broadcast() function uses AUTH_SYS credentials by default (see rpc_clnt_auth(3)).
rpc_broadcast_exp()
Like rpc_broadcast(), except that the initial timeout, inittime, and the maximum timeout, waittime, are specified in milliseconds. The inittime argument is the initial time that rpc_broadcast_exp() waits before resending the request. After the first resend, the re-transmission interval increases exponentially until it exceeds waittime.
rpc_call()
Calls the remote procedure associated with prognum, versnum, and procnum on the machine host. The inproc argument is used to encode the procedure's arguments, and outproc is used to decode the procedure's results. in is the address of the procedure's argument(s), and out is the address where to place the result(s). The nettype argument can be any of the values listed in rpc(3). This routine returns RPC_SUCCESS if it succeeds, or an appropriate status is returned. Use the clnt_perrno() routine to translate failure status into error messages. Warning: rpc_call() uses the first available transport belonging to the class nettype on which it can create a connection. You do not have control over timeouts or authentication using this routine.

AVAILABILITY

These functions are part of libtirpc.
