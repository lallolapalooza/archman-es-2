RPCCLIENT(1) Comandos de usuario RPCCLIENT(1)

NOMBRE

rpcclient - herramienta para ejecutar funciones MS-RPC del lado del cliente

SINOPSIS

rpcclient [-c|--command=COMANDOS] [-I|--dest-ip=IP] [-p|--port=PUERTO] [-?|--help] [--usage] [-d|--debuglevel=NIVELDEBUG] [--debug-stdout] [--configfile=ARCHIVOCONFIG] [--option=nombre=valor] [-l|--log-basename=ARCHIVOBASELOG] [--leak-report] [--leak-report-full] [-R|--name-resolve=ORDENRESOLUCIONNOMBRES] [-O|--socket-options=OPCIONESOCKET] [-m|--max-protocol=MAXPROTOCOLO] [-n|--netbiosname=NOMBRENTBIOS] [--netbios-scope=SCOPE] [-W|--workgroup=GRUPOTRABAJO] [--realm=REALM] [-U|--user=[DOMINIO/]USUARIO[%CONTRASEÑA]] [-N|--no-pass] [--password=CADENA] [--pw-nt-hash] [-A|--authentication-file=ARCHIVO] [-P|--machine-pass] [--simple-bind-dn=DN] [--use-kerberos=deseado|requerido|apagado] [--use-krb5-ccache=CCACHE] [--use-winbind-ccache] [--client-protection=sign|encrypt|off] [-V|--version] {CADENAENLACE|HOST}

DESCRIPCIÓN

Esta herramienta forma parte del conjunto samba(7).

rpcclient es una utilidad desarrollada inicialmente para probar la funcionalidad MS-RPC en el propio Samba. Ha pasado por varias etapas de desarrollo y estabilidad. Muchos administradores de sistemas han escrito scripts a su alrededor para gestionar clientes Windows NT desde sus estaciones de trabajo UNIX.

OPCIONES

CADENAENLACE|HOST

Al conectarse a un servicio dcerpc, es necesario especificar una cadena de enlace.

El formato es:

TRANSPORTADOR:host[opciones]

donde TRANSPORTADOR es ncacn_np (tuberías con nombre) para SMB o ncacn_ip_tcp para DCERPC sobre TCP/IP.

"host" es una IP o nombre de host o nombre netbios. Si la cadena de enlace identifica el lado del servidor de un punto final, "host" puede ser una cadena vacía. Véase más abajo para más detalles.

"opciones" puede incluir un nombre de tubería SMB si se utiliza el transportador ncacn_np o un número de puerto TCP si se utiliza el transportador ncacn_ip_tcp, de lo contrario se determinarán automáticamente.

Ejemplos:

•ncacn_ip_tcp:samba.example.com[1024]
•ncacn_ip_tcp:samba.example.com[sign,seal,krb5]
•ncacn_ip_tcp:samba.example.com[sign,spnego]
•ncacn_np:samba.example.com
•ncacn_np:samba.example.com[samr]
•ncacn_np:samba.example.com[samr,sign,print]
•ncalrpc:/path/to/unix/socket
•//SAMBA
Los transportadores soportados son:
•ncacn_np - Conectar usando tuberías con nombre
•ncacn_ip_tcp - Conectar a través de TCP/IP
•ncalrpc - Conectar a través de RPC local (sockets unix)
Las opciones soportadas son:
•sign - Usar nivel de autenticación de integridad RPC
•seal - Habilitar nivel de autenticación de privacidad (cifrado) RPC
•connect - Usar nivel de conexión RPC (autenticación, pero sin sign o seal)
•packet - Usar nivel de autenticación de paquete RPC
•spnego - Usar SPNEGO en lugar de autenticación NTLMSS
•ntlm - Usar NTLM plano en lugar de SPNEGO o NTLMSS
•krb5 - Usar Kerberos en lugar de autenticación NTLMSS
•schannel - Crear una conexión schannel
•smb1 - Usar SMB1 para tuberías con nombre
•smb2 - Usar SMB2/3 para tuberías con nombre
•validate - Habilitar el validador NDR
•print - Habilitar la salida de depuración de paquetes
•padcheck - Comprobar si los datos de respuesta contienen bytes de relleno distintos de cero
•bigendian - Usar big endian para RPC
•ndr64 - Usar NDR64 para RPC

-c|--command=<cadena de comando>

Ejecutar comandos separados por punto y coma (listados abajo)

-I|--dest-ip IP-dirección

La dirección IP es la dirección del servidor al que conectarse. Debe especificarse en notación estándar "a.b.c.d".

Normalmente el cliente intentaría localizar un servidor SMB/CIFS con nombre buscando a través del mecanismo de resolución de nombres NetBIOS descrito anteriormente en el parámetro orden de resolución de nombres. El uso de este parámetro forzará al cliente a asumir que el servidor está en la máquina con la dirección IP especificada y se ignorará el componente de nombre NetBIOS del recurso al que se está conectando.

No hay un valor por defecto para este parámetro. Si no se proporciona, será determinado automáticamente por el cliente como se describe anteriormente.

-p|--port puerto

Este número es el número de puerto TCP que se utilizará al realizar conexiones al servidor. El número de puerto TCP estándar (bien conocido) para un servidor SMB/CIFS es 139, que es el valor por defecto.

-?|--help

Imprimir un resumen de las opciones de la línea de comandos.

--usage

Mostrar un mensaje de uso breve.

-d|--debuglevel=nivel

nivel es un entero de 0 a 10. El valor por defecto si no se especifica este parámetro es 1 para aplicaciones cliente.

Cuanto más alto sea este valor, más detalles se registrarán en los archivos de registro sobre las actividades del servidor. En el nivel 0, solo se registrarán errores críticos y advertencias serias. El nivel 1 es un nivel razonable para el uso diario: genera una pequeña cantidad de información sobre las operaciones realizadas.

Los niveles superiores a 1 generarán una cantidad considerable de datos de registro y solo deben usarse al investigar un problema. Los niveles superiores a 3 están diseñados para ser utilizados solo por desarrolladores y generan ENORMES cantidades de datos de registro, la mayoría de los cuales son extremadamente crípticos.

Tenga en cuenta que la especificación de este parámetro aquí anulará el parámetro log level en el archivo /etc/samba/smb.conf.

--debug-stdout

Redirigirá la salida de depuración a STDOUT. Por defecto, todos los clientes registran en STDERR.

--configfile=<archivo de configuración>

El archivo especificado contiene los detalles de configuración requeridos por el cliente. La información en este archivo puede ser general para el cliente y el servidor o solo proporcionar opciones específicas del cliente como client smb encrypt. Ver /etc/samba/smb.conf para más información. El nombre del archivo de configuración por defecto se determina en tiempo de compilación.

--option=<nombre>=<valor>

Establece la opción smb.conf(5) "<nombre>" al valor "<valor>" desde la línea de comandos. Esto anula los valores por defecto compilados y las opciones leídas del archivo de configuración. Si un nombre o un valor incluye un espacio, envuelva todo --option=nombre=valor entre comillas.

-l|--log-basename=directoriobase

Nombre base del directorio para los archivos de registro/depuración. Se añadirá la extensión ".nombreprog" (por ejemplo, log.smbclient, log.smbd, etc...). El archivo de registro nunca es eliminado por el cliente.

--leak-report

Habilita el reporte de fugas de talloc al salir.

--leak-report-full

Habilita el reporte completo de fugas de talloc al salir.

-V|--version

Imprime el número de versión del programa.

-R|--name-resolve=ORDENRESOLUCIONNOMBRES

Esta opción se utiliza para determinar qué servicios de nombres y en qué orden resolverán los nombres de host a direcciones IP. La opción toma una cadena separada por espacios de diferentes opciones de resolución de nombres. Lo mejor es envolver todo --name-resolve=ORDENRESOLUCIONNOMBRES entre comillas.

Las opciones son: "lmhosts", "host", "wins" y "bcast". Hacen que los nombres se resuelvan como sigue:

•lmhosts: Busca una dirección IP en el archivo lmhosts de Samba. Si la línea en lmhosts no tiene un tipo de nombre asociado al nombre NetBIOS (ver lmhosts(5) para más detalles) entonces cualquier tipo de nombre coincide para la búsqueda.
•host: Realiza una resolución estándar de nombre de host a dirección IP, utilizando las búsquedas de sistema /etc/hosts, NIS o DNS. Este método de resolución de nombres depende del sistema operativo, por ejemplo en IRIX o Solaris esto puede ser controlado por el archivo /etc/

OPTIONS

The following options are supported by smbclient, smbget, smbspool, testparm, smbpasswd, findsmb, nmblookup, smbcacls, smbcquotas, smbstatus, smbtar, mount.cifs and smbshare.

-?|-H|--help

Shows a brief summary of the options.

-d|--debuglevel=DEBUGLEVEL

Sets the level of debugging messages that are written to the log files. The debug level is a number between 0 and 10. The default is 0.

-l|--log-basename=LOGFILEBASE

Base name for log files. If this is set to “/var/log/samba/log.” then debug messages will be written to the files: /var/log/samba/log.smbclient, /var/log/samba/log.smbget, etc. If this parameter is not set then the default is to write to a file named after the program that is running.

--option=OPTION

Set Samba options from the command line.

This allows you to set Samba configuration parameters from the command line. This is useful when testing and debugging.

For example, you can set the name resolve order parameter by using --option=name resolve order=lmhosts,host.

-s|--configfile=FILENAME

Specifies the file name of the configuration file to use. The default is /etc/samba/smb.conf.

-M|--mask=MASK

Sets the NetBIOS name mask.

-R|--name-resolve=METHOD

Sets the order in which the Samba client tools will attempt to resolve NetBIOS names to IP addresses. The default order is lmhosts, host, wins, bcast. This can be overridden by a command line setting or the name resolve order parameter in the /etc/samba/smb.conf file.

The methods are:

•host: Query the DNS server first, then check the /etc/hosts file.
•lmhosts: Query the lmhosts file. This file is located in /etc/lmhosts. This file is generally ignored by most systems. Note that this method is only used if the NetBIOS name type being queried is the 0x20 (server) name type, otherwise it is ignored.
•wins: Query a name with the IP address listed in the wins server parameter. If no WINS server has been specified this method will be ignored.
•bcast: Do a broadcast on each of the known local interfaces listed in the interfaces parameter. This is the least reliable of the name resolution methods as it depends on the target host being on a locally connected subnet.

If this parameter is not set then the name resolve order defined in the /etc/samba/smb.conf file parameter (name resolve order) will be used.

The default order is lmhosts, host, wins, bcast. Without this parameter or any entry in the name resolve order parameter of the /etc/samba/smb.conf file, the name resolution methods will be attempted in this order.

-O|--socket-options=SOCKETOPTIONS

TCP socket options to set on the client socket. See the socket options parameter in the /etc/samba/smb.conf manual page for the list of valid options.

-m|--max-protocol=MAXPROTOCOL

The value of the parameter (a string) is the highest protocol level that will be supported by the client.

Note that specifying this parameter here will override the client max protocol parameter in the /etc/samba/smb.conf file.

-n|--netbiosname=NETBIOSNAME

This option allows you to override the NetBIOS name that Samba uses for itself. This is identical to setting the netbios name parameter in the /etc/samba/smb.conf file. However, a command line setting will take precedence over settings in /etc/samba/smb.conf.

--netbios-scope=SCOPE

This specifies a NetBIOS scope that nmblookup will use to communicate with when generating NetBIOS names. For details on the use of NetBIOS scopes, see rfc1001.txt and rfc1002.txt. NetBIOS scopes are very rarely used, only set this parameter if you are the system administrator in charge of all the NetBIOS systems you communicate with.

-W|--workgroup=WORKGROUP

Set the SMB domain of the username. This overrides the default domain which is the domain defined in smb.conf. If the domain specified is the same as the servers NetBIOS name, it causes the client to log on using the servers local SAM (as opposed to the Domain SAM).

Note that specifying this parameter here will override the workgroup parameter in the /etc/samba/smb.conf file.

-r|--realm=REALM

Set the realm for the domain.

Note that specifying this parameter here will override the realm parameter in the /etc/samba/smb.conf file.

-U|--user=[DOMAIN\]USERNAME[%PASSWORD]

Sets the SMB username or username and password.

If %PASSWORD is not specified, the user will be prompted. The client will first check the USER environment variable (which is also permitted to also contain the password separated by a %), then the LOGNAME variable (which is not permitted to contain a password) and if either exists, the value is used. If these environmental variables are not found, the username found in a Kerberos Credentials cache may be used.

A third option is to use a credentials file which contains the plaintext of the username and password. This option is mainly provided for scripts where the admin does not wish to pass the credentials on the command line or via environment variables. If this method is used, make certain that the permissions on the file restrict access from unwanted users. See the -A for more details.

Be cautious about including passwords in scripts or passing user-supplied values onto the command line. For security it is better to let the Samba client tool ask for the password if needed, or obtain the password once with kinit.

While Samba will attempt to scrub the password from the process title (as seen in ps), this is after startup and so is subject to a race.

-N|--no-pass

If specified, this parameter suppresses the normal password prompt from the client to the user. This is useful when accessing a service that does not require a password.

Unless a password is specified on the command line or this parameter is specified, the client will request a password.

If a password is specified on the command line and this option is also defined the password on the command line will be silently ignored and no password will be used.

--password

Specify the password on the commandline.

Be cautious about including passwords in scripts or passing user-supplied values onto the command line. For security it is better to let the Samba client tool ask for the password if needed, or obtain the password once with kinit.

If --password is not specified, the tool will check the PASSWD environment variable, followed by PASSWD_FD which is expected to contain an open file descriptor (FD) number.

Finally it will check PASSWD_FILE (containing a file path to be opened). The file should only contain the password. Make certain that the permissions on the file restrict access from unwanted users!

While Samba will attempt to scrub the password from the process title (as seen in ps), this is after startup and so is subject to a race.

--pw-nt-hash

The supplied password is the NT hash.

-A|--authentication-file=filename

This option allows you to specify a file from which to read the username and password used in the connection. The format of the file is: 
username = <value>
password = <value>
domain   = <value>

Make certain that the permissions on the file restrict access from unwanted users!

-P|--machine-pass

Use stored machine account password.

--simple-bind-dn=DN

DN to use for a simple bind.

--use-kerberos=desired|required|off

This parameter determines whether Samba client tools will try to authenticate using Kerberos. For Kerberos authentication you should use DNS names instead of IP addresses when connecting to a service. By default Samba client tools will try to use the default Kerberos credential cache (ccache). In case the ccache does not exist or -U|--user option was specified, clients will ask to enter a password and will obtain a Kerberos ticket (kinit) for you. If you want to use an alternative Kerberos credentical cache, use the --use-krb5-ccache option.

Note that specifying this parameter here will override the client use kerberos parameter in the /etc/samba/smb.conf file.

--use-krb5-ccache=CCACHE

Specifies the credential cache location for Kerberos authentication.

This will enforce --use-kerberos=required.

--use-winbind-ccache

Try to use the credential cache by winbind.

--client-protection=sign|encrypt|off

Sets the connection protection the client tool should use.

Note that specifying this parameter here will override the client protection parameter in the /etc/samba/smb.conf file.

In case you need more fine grained control you can use: --option=clientsmbencrypt=OPTION, --option=clientipcsigning=OPTION, --option=clientsigning=OPTION.

adddriver <arch> <config> [<version>]

Ejecuta una llamada RPC AddPrinterDriver() para instalar la información del controlador de impresora en el servidor. Tenga en cuenta que los archivos del controlador ya deben existir en el directorio devuelto por getdriverdir. Los valores posibles para arch son los mismos que para el comando getdriverdir. El parámetro config se define como sigue: 
Nombre Largo del Controlador:
Nombre del Archivo del Controlador:
Nombre del Archivo de Datos:
Nombre del Archivo de Configuración:
Nombre del Archivo de Ayuda:
Nombre del Monitor de Idioma:
Tipo de Dato Predeterminado:
Lista Separada por Comas de Archivos

Cualquier campo vacío debe introducirse como la cadena "NULL".

Samba no necesita soportar el concepto de Monitores de Impresión, ya que estos solo se aplican a impresoras locales cuyo controlador puede utilizar un enlace bidireccional para la comunicación. Este campo debe ser "NULL". En un servidor de impresión NT remoto, el Monitor de Impresión para un controlador debe estar instalado antes de añadir el controlador, o bien la llamada RPC fallará.

El parámetro version le permite especificar el número de versión del controlador de la impresora. Si se omite, se utilizará el número de versión predeterminado para la arquitectura especificada. Esta opción se puede utilizar para cargar controladores de impresora de Windows 2000 (versión 3).

addprinter <nombreimpresora> <nombresourcecompartido> <nombredriver> <puerto>

Añade una impresora en el servidor remoto. Esta impresora se compartirá automáticamente. Tenga en cuenta que el controlador de la impresora debe estar ya instalado en el servidor (ver adddriver) y el puerto debe ser un nombre de puerto válido (ver enumports.

deldriver <driver>

Elimina el controlador de impresora especificado para todas las arquitecturas. Esto no elimina los archivos reales del controlador del servidor, solo la entrada de la lista de controladores del servidor.

deldriverex <driver> [arquitectura] [version] [flags]

Elimina el controlador de impresora especificado y opcionalmente los archivos asociados con el controlador. Puede limitar esta acción a una arquitectura específica y una versión específica. Si no se proporciona arquitectura, se eliminarán todos los archivos del controlador de ese controlador. flags corresponden a los valores numéricos DPD_*, es decir, un valor de 3 solicita (DPD_DELETE_UNUSED_FILES | DPD_DELETE_SPECIFIC_VERSION).

rpcclient(1) - Arch manual pages

NAME

rpcclient – MSRPC client interface

SYNOPSIS

rpcclient [-U USERNAME] [-N] [-c COMMAND] [-d DOMAIN] [-g GROUP] [-k] [-m MACHINE] [-p PORT] [-s SERVER] [-S SHARE] [-t TIMEOUT] [-u USER] [-w WORKGROUP] [-W WINBINDD_INTERFACE] [-Y AUTH_TYPE] [-i] [-l] [-v] [HOST]

DESCRIPTION

The rpcclient program is a client for the MSRPC interface. It is intended to be used to investigate and test MSRPC services. MSRPC is a Microsoft RPC protocol that runs over SMB. It is used by many Windows services, including the User and Domain services, the Service Control Manager, the Registry service, and others.

MSRPC is a complex protocol, and the implementation in Samba is continually being developed. This means that not all MSRPC services are supported, and the supported services may not be fully implemented.

The rpcclient program provides an interactive interface for sending MSRPC requests to a server. You can also use the -c option to execute a single command.

The rpcclient program can be used to:

  • Enumerate and manipulate users and groups
  • Start, stop, and query services
  • Query and manipulate the registry
  • Perform other MSRPC operations

OPTIONS

The following options are available:

-U USERNAME
The username to use for authentication.
-N
Disable printing of the NTLM service password.
-c COMMAND
Execute the specified COMMAND and exit.
-d DOMAIN
The domain to use for authentication.
-g GROUP
The group to use for authentication.
-k
Use Kerberos authentication.
-m MACHINE
The machine name to use for authentication.
-p PORT
The port to use for the MSRPC connection.
-s SERVER
The server to connect to.
-S SHARE
The share to connect to.
-t TIMEOUT
The timeout in seconds for the MSRPC connection.
-u USER
The user to use for authentication.
-w WORKGROUP
The workgroup to use for authentication.
-W WINBINDD_INTERFACE
The interface to use for winbindd.
-Y AUTH_TYPE
The authentication type to use.
-i
Enable interactive mode.
-l
List available MSRPC services.
-v
Enable verbose output.

COMMANDS

The following commands are available in interactive mode:

  • lsadump PIDESC: Dump password hashes
  • lsdecomp PIDESC: Decompile password hashes
  • rpcinfo: List RPC services
  • samr: User and group management
  • srvsvc: Server service management
  • winreg: Registry service management

For more information on specific commands, use the help command within rpcclient.

BUGS

The Samba RPC code has been developed by examining network traces. No documentation is available from the original creators (Microsoft) on how MSRPC over SMB works, or how the individual MSRPC services work. Microsoft's implementation of these services has been demonstrated (and reported) to be... a bit flaky in places.

The development of Samba's implementation is also a bit rough, and as more of the services are understood, it can even result in versions of smbd(8) and rpcclient(1) that are incompatible for some commands or services. Additionally, the developers are sending reports to Microsoft, and problems found or reported to Microsoft are fixed in Service Packs, which may result in incompatibilities.
