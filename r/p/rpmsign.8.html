NOMBRE

rpmsign - Firma de paquetes RPM

SINOPSIS

FIRMA DE PAQUETES:

rpmsign --addsign|--resign [opciones-rpmsign] ARCHIVO_PAQUETE ...

rpmsign --delsign ARCHIVO_PAQUETE ...

rpmsign --delfilesign ARCHIVO_PAQUETE ...

opciones-rpmsign

[--rpmv3] [--fskpath CLAVE] [--signfiles]

DESCRIPCIÓN

Ambas opciones, --addsign y --resign, generan e insertan nuevas firmas para cada ARCHIVO_PAQUETE proporcionado, reemplazando cualquier firma existente. Existen dos opciones por razones históricas, actualmente no hay diferencia en el comportamiento.

Para crear una firma, rpmsign necesita verificar la suma de verificación del paquete. Como resultado, los paquetes con sumas de verificación MD5/SHA1 no se pueden firmar en modo FIPS.

rpmsign --delsign ARCHIVO_PAQUETE ...

Elimina todas las firmas de cada ARCHIVO_PAQUETE proporcionado.

rpmsign --delfilesign ARCHIVO_PAQUETE ...

Elimina todas las firmas de archivos IMA y fsverity de cada ARCHIVO_PAQUETE proporcionado.

OPCIONES DE FIRMA

--rpmv3
Fuerza la adición de firmas de cabecera+carga útil de RPM V3. Estas son cargas útiles costosas y redundantes en paquetes donde existe un resumen de carga útil separado (paquetes construidos con rpm >= 4.14). Rpmsign detectará automáticamente la necesidad de firmas V3, pero esta opción puede usarse para forzar su creación si los paquetes deben ser totalmente verificables con firmas con rpm < 4.14 u otras razones de interoperabilidad.
--fskpath CLAVE
Usado con --signfiles, usa la clave de firma de archivo CLAVE.
--certpath CERT
Usado con --signverity, usa el certificado de firma de archivo CERT.
--verityalgo ALG
Usado con --signverity, para especificar el algoritmo de firma. Se admiten sha256 y sha512, siendo sha256 el predeterminado si no se proporciona este argumento. Esto también se puede especificar con la macro %_verity_algorithm.
--signfiles
Firma los archivos del paquete. La macro %_binary_filedigest_algorithm debe estar configurada en un algoritmo admitido antes de construir el paquete. Los algoritmos admitidos son SHA1, SHA256, SHA384 y SHA512, que se representan como 2, 8, 9 y 10 respectivamente. La clave de firma de archivo (clave privada RSA) debe estar configurada antes de firmar el paquete; se puede configurar en la línea de comandos con --fskpath o la macro %_file_signing_key.
--signverity
Firma los archivos del paquete con firmas fsverity. La clave de firma de archivo (clave privada RSA) y el certificado de firma deben estar configurados antes de firmar el paquete. La clave se puede configurar en la línea de comandos con --fskpath o la macro %_file_signing_key, y el certificado se puede configurar en la línea de comandos con --certpath o la macro %_file_signing_cert.

CONFIGURACIÓN DE CLAVES DE FIRMA

Para poder firmar paquetes, necesita crear su propio par de claves pública y secreta (consulte el manual de GnuPG). Además, rpm(8) debe estar configurado para encontrar GnuPG y las claves apropiadas con las siguientes macros:

%_gpg_name
El nombre del "usuario" cuya clave desea usar para firmar sus paquetes. Típicamente, esta es la única configuración necesaria.
%_gpg_path
La ubicación de su llavero GnuPG si no es el predeterminado $GNUPGHOME.
%__gpg
La ruta del ejecutable GnuPG. Normalmente preconfigurado.

Por ejemplo, para poder usar GnuPG para firmar paquetes como el usuario "John Doe <jdoe@foo.com>" desde los llaveros ubicados en /etc/rpm/.gpg usando el ejecutable /opt/bin/gpg, incluiría

%_gpg_path /etc/rpm/.gpg
%_gpg_name John Doe <jdoe@foo.com>
%__gpg /opt/bin/gpg

en un archivo de configuración de macros, típicamente ~/.config/rpm/macros. Consulte la sección Configuración de Macros en rpm(8) para más detalles.
