RPC(3) Manual de funciones de biblioteca RPC(3)

NOMBRE

rpc — rutinas de biblioteca para llamadas a procedimientos remotos

SINOPSIS

#include <rpc/rpc.h>
#include <netconfig.h>

DESCRIPCIÓN

Estas rutinas permiten a los programas del lenguaje C realizar llamadas a procedimientos en otras máquinas a través de una red. Primero, el cliente envía una solicitud al servidor. Al recibir la solicitud, el servidor llama a una rutina de distribución para realizar el servicio solicitado y luego envía una respuesta.

Todas las rutinas RPC requieren el encabezado <rpc/rpc.h>. Las rutinas que toman una struct netconfig también requieren que se incluya <netconfig.h>.

Nettype

Algunas de las rutinas de la interfaz RPC de alto nivel toman una cadena nettype como uno de los argumentos (por ejemplo, clnt_create(), svc_create(), rpc_reg(), rpc_call()). Esta cadena define una clase de transportes que se pueden utilizar para una aplicación en particular.

El argumento nettype puede ser uno de los siguientes:

netpath
Elegir entre los transportes indicados por sus nombres de token en la variable de entorno NETPATH. Si NETPATH no está configurada o es NULL, se utiliza "visible" por defecto. "netpath" es el nettype por defecto.
visible
Elegir los transportes que tienen el indicador visible (v) establecido en el archivo /etc/netconfig.
circuit_v
Esto es lo mismo que "visible" excepto que elige solo los transportes orientados a conexión (semántica "tpi_cots" o "tpi_cots_ord") de las entradas en el archivo /etc/netconfig.
datagram_v
Esto es lo mismo que "visible" excepto que elige solo los transportes de datagramas sin conexión (semántica "tpi_clts") de las entradas en el archivo /etc/netconfig.
circuit_n
Esto es lo mismo que "netpath" excepto que elige solo los transportes de datagramas orientados a conexión (semántica "tpi_cots" o "tpi_cots_ord").
datagram_n
Esto es lo mismo que "netpath" excepto que elige solo los transportes de datagramas sin conexión (semántica "tpi_clts").
udp
Esto se refiere a UDP de Internet, tanto versión 4 como 6.
tcp
Esto se refiere a TCP de Internet, tanto versión 4 como 6.

Si nettype es NULL, se utiliza "netpath" por defecto. Los transportes se intentan en orden de izquierda a derecha en la variable NETPATH o en orden de arriba abajo en el archivo /etc/netconfig.

Estructuras de Datos

Algunas de las estructuras de datos utilizadas por el paquete RPC se muestran a continuación.

La Estructura AUTH

/*
 * Información de autenticación. Opaca para el cliente.
 */
struct opaque_auth {
    enum_t    oa_flavor;    /* sabor de la autenticación */
    caddr_t    oa_base;    /* dirección de más datos de autenticación */
    u_int    oa_length;    /* no exceder MAX_AUTH_BYTES */
};

/*
 * Manejador de autenticación, interfaz para los autenticadores del lado del cliente.
 */
typedef struct {
    struct    opaque_auth    ah_cred;
    struct    opaque_auth    ah_verf;
    struct auth_ops {
        void    (*ah_nextverf)();
        int    (*ah_marshal)();    /* siguiente verificación y serialización */
        int    (*ah_validate)();    /* validar verificador */
        int    (*ah_refresh)();    /* actualizar credenciales */
        void    (*ah_destroy)();    /* destruir esta estructura */
    } *ah_ops;
    caddr_t ah_private;
} AUTH;

La Estructura CLIENT

/*
 * Manejador rpc del cliente.
 * Creado por implementaciones individuales.
 * El cliente es responsable de inicializar auth.
 */

typedef struct {
    AUTH    *cl_auth;    /* autenticador */
    struct clnt_ops {
        enum clnt_stat    (*cl_call)();    /* llamar a procedimiento remoto */
        void    (*cl_abort)();        /* abortar una llamada */
        void    (*cl_geterr)();        /* obtener código de error específico */
        bool_t    (*cl_freeres)();    /* liberar resultados */
        void    (*cl_destroy)();    /* destruir esta estructura */
        bool_t    (*cl_control)();    /* el ioctl() de rpc */
    } *cl_ops;
    caddr_t    cl_private;    /* datos privados */
    char    *cl_netid;    /* identificador de red */
    char    *cl_tp;        /* nombre del dispositivo */
} CLIENT;

La estructura SVCXPRT

enum xprt_stat {
    XPRT_DIED,
    XPRT_MOREREQS,
    XPRT_IDLE
};

/*
 * Manejador de transporte del lado del servidor
 */
typedef struct {
    int    xp_fd;    /* descriptor de archivo para el manejador del servidor */
    u_short    xp_port;    /* obsoleto */
    const struct xp_ops {
        bool_t    (*xp_recv)();    /* recibir solicitudes entrantes */
        enum xprt_stat    (*xp_stat)();    /* obtener estado del transporte */
        bool_t    (*xp_getargs)();    /* obtener argumentos */
        bool_t    (*xp_reply)();      /* enviar respuesta */
        bool_t    (*xp_freeargs)(); /* liberar memoria asignada para argumentos */
        void    (*xp_destroy)();    /* destruir esta estructura */
    } *xp_ops;
    int    xp_addrlen;    /* longitud de la dirección remota. Obsoleto */
    struct sockaddr_in    xp_raddr; /* Obsoleto */
    const struct xp_ops2 {
        bool_t    (*xp_control)();    /* función catch-all */
    } *xp_ops2;
    char    *xp_tp;    /* nombre del dispositivo proveedor de transporte */
    char    *xp_netid;    /* identificador de red */
    struct netbuf    xp_ltaddr;    /* dirección de transporte local */
    struct netbuf    xp_rtaddr;    /* dirección de transporte remota */
    struct opaque_auth    xp_verf;    /* verificador de respuesta cruda */
    caddr_t    xp_p1;    /* privado: para uso de las operaciones svc */
    caddr_t    xp_p2;    /* privado: para uso de las operaciones svc */
    caddr_t    xp_p3;    /* privado: para uso de la biblioteca svc */
    int    xp_type    /* tipo de transporte */
} SVCXPRT;

La estructura svc_reg

struct svc_req {
    rpcprog_t    rq_prog;    /* número de programa del servicio */
    rpcvers_t    rq_vers;    /* versión del protocolo del servicio */
    rpcproc_t    rq_proc;    /* el procedimiento deseado */
    struct opaque_auth    rq_cred;    /* credenciales crudas de la red */
    caddr_t    rq_clntcred;    /* credenciales cocidas de solo lectura */
    SVCXPRT    *rq_xprt;    /* transporte asociado */
};

DESCRIPCIÓN

Estas funciones manejan el registro de servicios RPC y la recepción de llamadas de procedimiento remoto.

Nettype

El nettype es un nombre de tipo de red que se encuentra en el archivo /etc/netconfig. Los tipos de red comunes incluyen tcp y udp.

Derived Types

Estas funciones utilizan los siguientes tipos derivados:

struct svc_req
Representa una solicitud de servicio RPC entrante. Contiene información sobre el llamador, el programa RPC, la versión, el procedimiento y los argumentos de la llamada.

Data Structures

struct svc_req
Estructura utilizada para pasar información sobre una solicitud de servicio RPC entrante.
struct svcgetXPRT
Estructura opaca que representa un manejador de transporte RPC.

The AUTH Structure

La estructura AUTH se utiliza para la autenticación de RPC. No se utiliza directamente en estas funciones, pero es parte del marco general de RPC.

The CLIENT Structure

La estructura CLIENT representa un cliente RPC. No se utiliza directamente en estas funciones, pero está relacionada con el uso general de RPC.

The SVCXPRT structure

La estructura SVCXPRT es la estructura principal utilizada por los servicios RPC para interactuar con el transporte subyacente. Contiene punteros a funciones para operaciones de E/S y manejo de errores.

The svc_reg structure

Esta estructura se utiliza internamente para el registro de servicios RPC. No está expuesta directamente a los desarrolladores de aplicaciones.

The XDR structure

La estructura XDR se utiliza para la serialización y deserialización de datos. No se utiliza directamente en estas funciones de manejo de llamadas, pero es esencial para el procesamiento de argumentos y resultados de RPC.
