rpcgen(1) Manual de Comandos Generales rpcgen(1)

NOMBRE

rpcgen - compilador de protocolos RPC

SINOPSIS

rpcgen archivo_entrada
rpcgen [-Dnombre[=valor]] [-T] [-K segundos] archivo_entrada
rpcgen -c|-h|-l|-m|-M|-t [-o archivo_salida ] archivo_entrada
rpcgen -s tipo_red [-o archivo_salida] archivo_entrada
rpcgen -n id_red [-o archivo_salida] archivo_entrada

DESCRIPCIÓN

rpcgen es una herramienta que genera código C para implementar un protocolo RPC. La entrada para rpcgen es un lenguaje similar a C conocido como Lenguaje RPC (Lenguaje de Llamada a Procedimiento Remoto).

Normalmente, rpcgen se utiliza como en la primera sinopsis, donde toma un archivo de entrada y genera hasta cuatro archivos de salida. Si el archivo_entrada se llama proto.x, entonces rpcgen generará un archivo de cabecera en proto.h, rutinas XDR en proto_xdr.c, stubs del lado del servidor en proto_svc.c y stubs del lado del cliente en proto_clnt.c. Con la opción -T, también generará la tabla de envío RPC en proto_tbl.i. Con la opción -Sc, también generará código de ejemplo que ilustrará cómo usar los procedimientos remotos en el lado del cliente. Este código se creará en proto_client.c. Con la opción -Ss, también generará un código de servidor de ejemplo que ilustrará cómo escribir los procedimientos remotos. Este código se creará en proto_server.c.

El servidor creado puede ser iniciado tanto por los monitores de puerto (por ejemplo, inetd o listen) como por sí mismo. Cuando es iniciado por un monitor de puerto, crea servidores solo para el transporte para el cual se pasó el descriptor de archivo 0. El nombre del transporte debe especificarse configurando la variable de entorno PM_TRANSPORT. Cuando el servidor generado por rpcgen se ejecuta, crea manejadores de servidor para todos los transportes especificados en la variable de entorno NETPATH o, si no está configurada, crea manejadores de servidor para todos los transportes visibles desde el archivo /etc/netconfig. Nota: los transportes se eligen en tiempo de ejecución y no en tiempo de compilación.

Cuando se compila para un monitor de puerto (rpcgen -I) y el servidor se inicia automáticamente, se pone en segundo plano por defecto. Se puede usar un símbolo de definición especial RPC_SVC_FG para ejecutar el proceso del servidor en primer plano.

La segunda sinopsis proporciona características especiales que permiten la creación de servidores RPC más sofisticados. Estas características incluyen soporte para #defines proporcionados por el usuario y tablas de envío RPC. Las entradas en la tabla de envío RPC contienen:

•
punteros a la rutina de servicio correspondiente a ese procedimiento,
•
un puntero a los argumentos de entrada y salida
•
el tamaño de estas rutinas
Un servidor puede usar la tabla de envío para verificar la autorización y luego ejecutar la rutina de servicio; una biblioteca cliente puede usarla para manejar los detalles de la gestión de memoria y la conversión de datos XDR.

Las otras tres sinopsis mostradas arriba se utilizan cuando no se desean generar todos los archivos de salida, sino solo uno en particular. Algunos ejemplos de su uso se describen en la sección EJEMPLOS a continuación. Cuando rpcgen se ejecuta con la opción -s, crea servidores para esa clase particular de transportes. Cuando se ejecuta con la opción -n, crea un servidor para el transporte especificado por id_red. Si no se especifica archivo_entrada, rpcgen acepta la entrada estándar.

El preprocesador C, cc -E [ver cc(1)], se ejecuta en el archivo de entrada antes de que sea interpretado realmente por rpcgen. Para cada tipo de archivo de salida, rpcgen define un símbolo de preprocesador especial para uso por el programador de rpcgen:

RPC_HDR
definido al compilar en archivos de cabecera
RPC_XDR
definido al compilar en rutinas XDR
RPC_SVC
definido al compilar en stubs del lado del servidor
RPC_CLNT
definido al compilar en stubs del lado del cliente
RPC_TBL
definido al compilar en tablas de envío RPC

Cualquier línea que comience con `%' se pasa directamente al archivo de salida, sin ser interpretada por rpcgen.

Para cada tipo de dato al que se haga referencia en archivo_entrada, rpcgen asume que existe una rutina con la cadena xdr_ antepuesta al nombre del tipo de dato. Si esta rutina no existe en la biblioteca RPC/XDR, debe ser proporcionada. Proporcionar un tipo de dato indefinido permite la personalización de las rutinas XDR.

Las siguientes opciones están disponibles:

-a
Genera todos los archivos, incluido el código de ejemplo para el lado del cliente y del servidor.
-b
Genera código para el estilo rpc de SunOS4.1. Es para compatibilidad con versiones anteriores. Este es el valor predeterminado.
-5
Genera código para el estilo rpc de SysVr4. Lo utiliza RPC Independiente de Transporte que se encuentra en los sistemas Svr4. Por defecto, rpcgen genera código para el estilo rpc de SunOS4.1.
-c
Compila en rutinas XDR.
-C
Genera código en ANSI C. Esta opción también genera código que podría compilarse con el compilador C++. Este es el valor predeterminado.
-k
Genera código en K&R C. El valor predeterminado es ANSI C.
-Dnombre[=valor]
Define un símbolo nombre. Equivalente a la directiva #define en el código fuente. Si no se proporciona valor, valor se define como 1. Esta opción se puede especificar varias veces.
-h
Compila en definiciones de datos de C (un archivo de cabecera). La opción -T se puede usar en conjunto para producir un archivo de cabecera que admita tablas de envío RPC.
-I
Genera un servicio que puede ser iniciado desde inetd. El valor predeterminado es generar un servicio estático que maneja los transportes seleccionados con -s. Usar -I permite iniciar un servicio por cualquiera de los métodos.
-K segundos
Por defecto, los servicios creados usando rpcgen esperan 120 segundos después de atender una solicitud antes de salir. Ese intervalo se puede cambiar usando la bandera -K. Para crear un servidor que salga inmediatamente después de atender una solicitud, se puede usar -K 0. Para crear un servidor que nunca salga, el argumento apropiado es -K -1.
Al monitorear un servidor, algunos monitores de puerto, como listen(1M), siempre inician un nuevo proceso en respuesta a una solicitud de servicio. Si se sabe que un servidor se usará con dicho monitor, el servidor debe salir inmediatamente al completar. Para tales servidores, rpcgen debe usarse con -K -1.
-l
Compila en stubs del lado del cliente.
-m
Compila en stubs del lado del servidor, pero no genera una rutina de “main”. Esta opción es útil para rutinas de devolución de llamada y para usuarios que necesitan escribir su propia rutina de “main” para realizar la inicialización.
-M
Genera stubs seguros para multihilo para pasar argumentos y resultados entre el código generado por rpcgen y el código escrito por el usuario. Esta opción es útil para usuarios que desean usar hilos en su código.

rpcgen(1) - Arch manual pages

NAME

rpcgen — RPC protocol compiler

SYNOPSIS

rpcgen [options] infile

DESCRIPTION

The rpcgen utility is an RPC code generator. It takes an RPC API description file as input and produces C source files that are compiled to create RPC applications.

The input file is a description of the remote procedures. The file must contain a program definition.

-c
Generate C data representation (XDR) routines.
-C
Generate C++ data representation (XDR) routines.
-Dname
Passes the preprocessor macro name to the C compiler. This option is passed to the compiler that is invoked to compile the generated files.
-h
Generate header file. This file contains structure and enum definitions.
-Idir
Specify a directory to search for imported header files. Multiple directories can be specified.
-j
Generate client-side stubs for all transports.
-k
Generate server-side stubs for all transports.
-l
Generate client-side stubs.
-m
Generate server-side stubs without the remote procedure table. The default behaviour of generating the remote procedure table is disabled.
-n netid
Compile into server-side stubs for the transport specified by netid. There should be an entry for netid in the netconfig database. This option may be specified more than once, so as to compile a server that serves multiple transports.
-N
Use the newstyle of rpcgen. This allows procedures to have multiple arguments. It also uses the style of parameter passing that closely resembles C. So, when passing an argument to a remote procedure you do not have to pass a pointer to the argument but the argument itself. This behaviour is different from the oldstyle of rpcgen generated code. The newstyle is not the default case because of backward compatibility.
-o outfile
Specify the name of the output file. If none is specified, standard output is used (-c, -h, -l, -m, -n, -s, -Sc, -Sm, -Ss, and -t modes only).
-s nettype
Compile into server-side stubs for all the transports belonging to the class nettype. The supported classes are netpath, visible, circuit_n, circuit_v, datagram_n, datagram_v, tcp, and udp [see rpc(3N) for the meanings associated with these classes]. This option may be specified more than once. Note: the transports are chosen at run time and not at compile time.
-Sc
Generate sample code to show the use of remote procedure and how to bind to the server before calling the client side stubs generated by rpcgen.
-Sm
Generate a sample Makefile which can be used for compiling the application.
-Ss
Generate skeleton code for the remote procedures on the server side. You would need to fill in the actual code for the remote procedures.
-t
Compile into RPC dispatch table.
-T
Generate the code to support RPC dispatch tables.

The options -c, -h, -l, -m, -s and -t are used exclusively to generate a particular type of file, while the options -D and -T are global and can be used with the other options.

NOTES

The RPC Language does not support nesting of structures. As a work-around, structures can be declared at the top-level, and their name used inside other structures in order to achieve the same effect.

Name clashes can occur when using program definitions, since the apparent scoping does not really apply. Most of these can be avoided by giving unique names for programs, versions, procedures and types.

The server code generated with -n option refers to the transport indicated by netid and hence is very site specific.

EXAMPLE

The following example:

$ rpcgen -T prot.x

generates the five files: prot.h, prot_clnt.c, prot_svc.c, prot_xdr.c and prot_tbl.i.

The following example sends the C data-definitions (header file) to the standard output.

$ rpcgen -h prot.x

To send the test version of the -DTEST, server side stubs for all the transport belonging to the class datagram_n to standard output, use:

$ rpcgen -s datagram_n -DTEST prot.x

To create the server side stubs for the transport indicated by netid tcp, use:

$ rpcgen -n tcp -o prot_svc.c prot.x
