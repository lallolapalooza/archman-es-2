DESCRIPCIÓN

Estas rutinas forman parte de la biblioteca RPC, que permite a los programas en lenguaje C realizar llamadas a procedimientos en servidores a través de la red. Estas rutinas se ocupan de la creación de manejadores de servicio. Una vez creado el manejador, el servidor puede ser invocado llamando a svc_run().

Rutinas

Consulte rpc(3) para la definición de la estructura de datos SVCXPRT.

svc_control()
Una función para cambiar o recuperar diversa información sobre un objeto de servicio. El argumento req indica el tipo de operación y info es un puntero a la información. Los valores admitidos de req, sus tipos de argumento y lo que hacen son:
SVCGET_VERSQUIET
Si se recibe una solicitud para un número de programa servido por este servidor, pero el número de versión está fuera del rango registrado con el servidor, normalmente se devolverá un error RPC_PROGVERSMISMATCH. El argumento info debe ser un puntero a un entero. Tras la finalización correcta de la solicitud SVCGET_VERSQUIET, *info contiene un entero que describe el comportamiento actual del servidor: 0 indica el comportamiento normal del servidor (es decir, se devolverá un error RPC_PROGVERSMISMATCH); 1 indica que la solicitud fuera de rango se ignorará silenciosamente.
SVCSET_VERSQUIET
Si se recibe una solicitud para un número de programa servido por este servidor, pero el número de versión está fuera del rango registrado con el servidor, normalmente se devolverá un error RPC_PROGVERSMISMATCH. A veces es deseable cambiar este comportamiento. El argumento info debe ser un puntero a un entero que sea 0 (indicando el comportamiento normal del servidor — se devolverá un error RPC_PROGVERSMISMATCH) o 1 (indicando que la solicitud fuera de rango debe ignorarse silenciosamente).
svc_create()
La función svc_create() crea manejadores de servidor para todos los transportes pertenecientes a la clase nettype. El argumento nettype define una clase de transportes que se pueden utilizar para una aplicación determinada. Los transportes se prueban en orden de izquierda a derecha en la variable NETPATH o en orden de arriba abajo en la base de datos netconfig. Si nettype es NULL, se utiliza "netpath" por defecto.

La función svc_create() se registra con el servicio rpcbind (consulte rpcbind(8)). La función dispatch se llama cuando hay una llamada a procedimiento remoto para el prognum y versnum dados; esto requiere llamar a svc_run() (consulte svc_run() en rpc_svc_reg(3)). Si svc_create() tiene éxito, devuelve el número de manejadores de servidor que creó, de lo contrario, devuelve 0 y se registra un mensaje de error.

svc_destroy()
Una macro de función que destruye el manejador de servicio RPC xprt. La destrucción normalmente implica la desasignación de estructuras de datos privadas, incluido el propio xprt. El uso de xprt no está definido después de llamar a esta rutina.
svc_dg_create()
Esta rutina crea un manejador de servicio RPC sin conexión y devuelve un puntero a él. Esta rutina devuelve NULL si falla y se registra un mensaje de error. Los argumentos sendsz y recvsz se utilizan para especificar el tamaño de los búferes. Si son 0, se eligen valores predeterminados adecuados. El descriptor de archivo fildes debe estar abierto y enlazado. El servidor no está registrado con rpcbind(8).

NAME

rpc_svc_create - create an RPC service transport

SYNOPSIS

general server transport
svc_create(3)
svc_create(dispatch, prognum, versnum);
transport specific server transport
svc_reg(3)
svc_reg(transp, prognum, versnum, dispatch, now);
svc_vc_create(3)
svc_vc_create(fildes, sendsz, recvsz);
svc_dg_create(3)
svc_dg_create(fildes, sendsz, recvsz);
svc_tp_create(3)
svc_tp_create(netconf, prognum, versnum, dispatch);
svc_tli_create(3)
svc_tli_create(fildes, netconf, bindaddr, sendsz, recvsz);
svc_raw_create(3)
svc_raw_create(transp);

DESCRIPTION

These routines are used to create RPC service transports. The svc_create(), svc_reg(), svc_vc_create(), svc_dg_create(), svc_tp_create(), svc_tli_create(), and svc_raw_create() functions create RPC service transports, and return a handle that represents the transport. This handle is used by the other RPC routines to manipulate the RPC service.

Routines

svc_create()
This routine creates a generic RPC service transport, registers the specified program number (prognum) and version number (versnum) with the rpcbind(8) service, and associates the transport with the given dispatch function. The svc_create() function returns the service handle if it succeeds, otherwise a NULL is returned and an error message is logged. The svc_create() function should be called after the RPC service has been implemented.
svc_dg_create()
This routine creates a connectionless RPC service and returns a pointer to it. This routine returns NULL if it fails, and an error message is logged. The user may specify the size of the send and receive buffers with the arguments sendsz and recvsz; values of 0 choose suitable defaults. The file descriptor fildes should be open and bound. The server is not registered with the rpcbind(8) service.
svc_reg()
This routine registers the given program number (prognum) and version number (versnum) with the rpcbind(8) service on the transport specified by transp. The dispatch function is called when there is a remote procedure call for the given prognum and versnum; this requires calling svc_run(). The svc_reg() function returns 0 if it succeeds, otherwise it returns -1 and an error message is logged. If now is non-zero, the registration is performed immediately; otherwise, it is deferred until the next call to svc_run().
svc_raw_create()
This routine creates an RPC service handle and returns a pointer to it. The transport is really a buffer within the process's address space, so the corresponding RPC client should live in the same address space; (see clnt_raw_create() in rpc_clnt_create(3)). This routine allows simulation of RPC and acquisition of RPC overheads (such as round trip times), without any kernel and networking interference. This routine returns NULL if it fails, and an error message is logged.
svc_raw_create()
This routine creates an RPC server handle for the specified transport transp. The arguments sendsz and recvsz indicate sizes for the send and receive buffers. If they are 0, reasonable defaults are chosen. This routine returns NULL if it fails, and an error message is logged.
svc_tli_create()
This routine creates an RPC server handle, and returns a pointer to it. The fildes argument is the file descriptor on which the service is listening. If fildes is RPC_ANYFD, it opens a file descriptor on the transport specified by netconf. If the file descriptor is unbound and bindaddr is not NULL, fildes is bound to the address specified by bindaddr, otherwise fildes is bound to a default address chosen by the transport.

Note: the t_bind structure comes from the TLI/XTI SysV interface, which NetBSD does not use. The structure is defined in <rpc/types.h> for compatibility as:

struct t_bind {
    struct netbuf addr;	/* network address, see rpc(3) */
    unsigned int  qlen;	/* queue length (for listen(2)) */
};

In the case where the default address is chosen, the number of outstanding connect requests is set to 8 for connection-oriented transports. The user may specify the size of the send and receive buffers with the arguments sendsz and recvsz; values of 0 choose suitable defaults. This routine returns NULL if it fails, and an error message is logged. The server is not registered with the rpcbind(8) service.

svc_tp_create()
The svc_tp_create() function creates a server handle for the network specified by netconf, and registers itself with the rpcbind service. The dispatch function is called when there is a remote procedure call for the given prognum and versnum; this requires calling svc_run(). The svc_tp_create() function returns the service handle if it succeeds, otherwise a NULL is returned and an error message is logged.
svc_vc_create()
This routine creates a connection-oriented RPC service and returns a pointer to it. This routine returns NULL if it fails, and an error message is logged. The users may specify the size of the send and receive buffers with the arguments sendsz and recvsz; values of 0 choose suitable defaults. The file descriptor fildes should be open and bound. The server is not registered with the rpcbind(8) service.

AVAILABILITY

These functions are part of libtirpc.
