NOMBRE

rpc_secure — rutinas de biblioteca para llamadas a procedimientos remotos seguras

SINAPSIS

authdes_create(char *name, unsigned window, struct sockaddr *addr, des_block *ckey);

key_setsecret(const char *key);

int
user2netname(char *name, const uid_t uid, const char *domain);

DESCRIPCIÓN

Estas rutinas forman parte de la biblioteca RPC. Implementan la autenticación DES. Consulte rpc(3) para obtener más detalles sobre RPC.

La función authdes_create() es la primera de dos rutinas que interactúan con el sistema de autenticación segura de RPC, conocido como autenticación DES. La segunda es authdes_getucred(), que se describe a continuación.

Nota: el demonio del servidor de claves keyserv(8) debe estar en ejecución para que el sistema de autenticación DES funcione.

La función authdes_create(), utilizada en el lado del cliente, devuelve un manejador de autenticación que permitirá el uso del sistema de autenticación segura. El primer argumento, name, es el nombre de red, o netname, del propietario del proceso servidor. Este campo generalmente representa un hostname derivado de la rutina de utilidad host2netname(), pero también puede representar un nombre de usuario utilizando user2netname(). El segundo campo es la ventana de validez de la credencial del cliente, dada en segundos. Una ventana pequeña es más segura que una grande, pero elegir una ventana demasiado pequeña aumentará la frecuencia de resincronizaciones debido a la deriva del reloj. El tercer argumento, addr, es opcional. Si es NULL, el sistema de autenticación asumirá que el reloj local siempre está sincronizado con el reloj del servidor y no intentará resincronizaciones. Sin embargo, si se proporciona una dirección, el sistema utilizará la dirección para consultar el servicio de tiempo remoto cada vez que se requiera una resincronización. Este argumento suele ser la dirección del propio servidor RPC. El argumento final, ckey, también es opcional. Si es NULL, el sistema de autenticación generará una clave DES aleatoria para ser utilizada en el cifrado de credenciales. Sin embargo, si se proporciona, se utilizará en su lugar.

La función authdes_pk_create() es idéntica a authdes_create(), excepto que la clave pública debe proporcionarse en el momento de la llamada y esta función no la buscará por sí misma.

La función authdes_getucred(), la segunda de las dos rutinas de autenticación DES, se utiliza en el lado del servidor para convertir una credencial DES, que es independiente del sistema operativo, en una credencial de UNIX. Esta rutina difiere de la rutina de utilidad netname2user() en que authdes_getucred() extrae su información de una caché y no tiene que realizar una búsqueda de Yellow Pages cada vez que se llama para obtener su información.

La función getnetname() instala el nombre de red único e independiente del sistema operativo del llamante en el array de longitud fija name. Devuelve TRUE si tiene éxito y FALSE si falla.

La función host2netname() convierte un nombre de host específico del dominio a un nombre de red independiente del sistema operativo. Devuelve TRUE si tiene éxito y FALSE si falla. Es la inversa de netname2host().

La función key_decryptsession() es una interfaz para el demonio del servidor de claves, que está asociado con el sistema de autenticación segura de RPC (autenticación DES). Los programas de usuario rara vez necesitan llamarla, o sus rutinas asociadas key_encryptsession(), key_gendes() y key_setsecret(). Los comandos del sistema como login(1) y la biblioteca RPC son los principales clientes de estas cuatro rutinas.

La función key_decryptsession() toma un nombre de red de servidor y una clave DES, y descifra la clave utilizando la clave pública del servidor y la clave secreta asociada con la UID efectiva del proceso llamante. Es la inversa de key_encryptsession().

La función key_encryptsession() es una rutina de interfaz del servidor de claves. Toma un nombre de red de servidor y una clave DES, y la cifra utilizando la clave pública del servidor y la clave secreta asociada con la UID efectiva del proceso llamante. Es la inversa de key_decryptsession().

La función key_gendes() es una rutina de interfaz del servidor de claves. Se utiliza para solicitar al servidor de claves una clave de conversación segura. Elegir una "aleatoria" generalmente no es suficiente, porque las formas comunes de elegir números aleatorios, como usar la hora actual, son muy fáciles

rpc_secure(3t) — libtirpc documentation

NAME

rpc_secure, key_setsecret, netname2host, netname2user, user2netname ― functions to manage RPC security keys and convert RPC names.

SYNOPSIS

#include <rpc/rpc.h>

bool_t key_setsecret(keybuf *buf);
bool_t netname2host(netname nname, hostbuf *hname);
bool_t netname2user(netname nname, userbuf *ubuf);
bool_t user2netname(netname nname, userbuf *ubuf, char *netbuf);

DESCRIPTION

The functions described here are used to manage the security keys used by RPC and to convert between different representations of network names and user IDs.

The key_setsecret() function is a keyserver interface routine. It is used to set the key for the effective uid of the calling process.

The netname2host() function converts from an operating-system independent netname to a domain-specific hostname. Returns TRUE if it succeeds and FALSE if it fails. Inverse of host2netname().

The netname2user() function converts from an operating-system independent netname to a domain-specific user ID. Returns TRUE if it succeeds and FALSE if it fails. Inverse of user2netname().

The user2netname() function converts from a domain-specific username to an operating-system independent netname. Returns TRUE if it succeeds and FALSE if it fails. Inverse of netname2user().

AVAILABILITY

These functions are part of libtirpc.
