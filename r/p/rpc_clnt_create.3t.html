DESCRIPCIÓN

Las rutinas de la biblioteca RPC permiten que los programas del lenguaje C realicen llamadas a procedimientos en otras máquinas a través de la red. Primero se crea un manejador CLIENT y luego el cliente llama a un procedimiento para enviar una solicitud al servidor. Al recibir la solicitud, el servidor llama a una rutina de distribución para realizar el servicio solicitado y luego envía una respuesta.

Rutinas

clnt_control()
Una macro de función para cambiar o recuperar diversa información sobre un objeto cliente. El argumento req indica el tipo de operación, y info es un puntero a la información. Tanto para transportes sin conexión como orientados a conexión, los valores compatibles de req y sus tipos de argumento y lo que hacen son:
CLSET_TIMEOUT struct timeval * establecer tiempo de espera total
CLGET_TIMEOUT struct timeval * obtener tiempo de espera total

Nota: si establece el tiempo de espera usando clnt_control(), el argumento de tiempo de espera pasado por clnt_call() se ignora en todas las llamadas posteriores.

Nota: Si establece el valor de tiempo de espera a 0, clnt_control() devuelve inmediatamente un error (RPC_TIMEDOUT). Establezca el argumento de tiempo de espera a 0 para lotes de llamadas.

CLGET_SVC_ADDR struct netbuf * obtener la dirección del servidor
CLGET_FD int * obtener el fd del manejador
CLSET_FD_CLOSE void cerrar fd al destruir
CLSET_FD_NCLOSE void no cerrar fd al destruir
CLGET_VERS u_int32_t * obtener versión del programa RPC
CLSET_VERS u_int32_t * establecer versión del programa RPC
CLGET_XID u_int32_t * obtener XID de la llamada anterior
CLSET_XID u_int32_t * establecer XID de la próxima llamada

Las siguientes operaciones son válidas solo para transportes sin conexión:

CLSET_RETRY_TIMEOUT struct timeval * establecer el tiempo de espera de reintento
CLGET_RETRY_TIMEOUT struct timeval * obtener el tiempo de espera de reintento
CLSET_CONNECT int * usar connect(2)

El tiempo de espera de reintento es el tiempo que RPC espera la respuesta del servidor antes de retransmitir la solicitud. La función clnt_control() devuelve TRUE en caso de éxito y FALSE en caso de fallo.

clnt_create()
Rutina genérica de creación de cliente para el programa prognum y la versión versnum. El argumento host identifica el nombre del host remoto donde se encuentra el servidor. El argumento nettype indica la clase de protocolo de transporte a utilizar. Los transportes se intentan en orden de izquierda a derecha en la variable de entorno NETPATH o en orden de arriba a abajo en la base de datos netconfig. La función clnt_create() intenta todos los transportes de la clase nettype disponibles en la variable de entorno NETPATH y en la base de datos netconfig, y elige el primero que tiene éxito. Se establece un tiempo de espera por defecto que se puede modificar usando clnt_control(). Esta rutina devuelve NULL si falla. La rutina clnt_pcreateerror() puede usarse para imprimir la razón del fallo.

Nota: clnt_create() devuelve un identificador de cliente válido incluso si el número de versión particular suministrado a clnt_create() no está registrado con el servicio rpcbind(8). Esta discrepancia se descubrirá más tarde con una llamada a clnt_call() (ver rpc_clnt_calls(3)).

clnt_create_timed()
Rutina genérica de creación de cliente que es similar a clnt_create() pero que además tiene el argumento adicional timeout que especifica la cantidad máxima de tiempo permitida para cada clase de transporte intentada. En todos los demás aspectos, la llamada a clnt_create_timed() se comporta exactamente igual que la llamada a clnt_create().
clnt_create_vers()
Rutina genérica de creación de cliente que es similar a clnt_create() pero que además comprueba la disponibilidad de la versión. El argumento host identifica el nombre del host remoto donde se encuentra el servidor. El argumento nettype indica la clase de protocolos de transporte a utilizar. Si la rutina tiene éxito, devuelve un identificador de cliente creado para la versión más alta entre vers_low y vers_high que sea soportada por el servidor. El argumento vers_outp se establece a este valor. Es decir, después de un retorno exitoso vers_low <= *vers_outp <= vers_high. Si ninguna versión entre vers_low y vers_high es soportada por el servidor, la rutina falla y devuelve NULL. Se establece un tiempo de espera por defecto que puede modificarse usando clnt_control(). Esta rutina devuelve NULL si falla. La rutina clnt_pcreateerror() puede usarse para imprimir la razón del fallo. Nota: clnt_create() devuelve un identificador de cliente válido incluso si el número de versión particular suministrado a clnt_create() no está registrado con el servicio rpcbind(8). Esta discrepancia se descubrirá más tarde con una llamada a clnt_call() (ver rpc_clnt_calls(3)). Sin embargo, clnt_create_vers() hace esto por usted y devuelve un identificador válido solo si una versión dentro del rango suministrado es soportada por el servidor.
clnt_create_vers_timed()
Rutina genérica de creación de cliente que es similar a clnt_create_vers() pero que además tiene el argumento adicional timeout que especifica la cantidad máxima de tiempo permitida para cada clase de transporte intentada. En todos los demás aspectos, la llamada a clnt_create_vers_timed() se comporta exactamente igual que la llamada a clnt_create_vers().
clnt_destroy()
Una macro de función que destruye el identificador del cliente RPC. La destrucción generalmente implica la desasignación de estructuras de datos privadas, incluido el propio clnt. El uso de clnt no está definido después de llamar a clnt_destroy(). Si la biblioteca RPC abrió el descriptor de archivo asociado, o si CLSET_FD_CLOSE se estableció usando clnt_control(), se cerrará el descriptor de archivo. El llamador debe llamar a auth_destroy(clnt->cl_auth) (antes de llamar a clnt_destroy()) para destruir la estructura AUTH asociada (ver rpc_clnt_auth(3)).
clnt_dg_create()
Esta rutina crea un cliente RPC para el programa remoto prognum y la versión versnum; el cliente utiliza un transporte sin conexión. El programa remoto se encuentra en la dirección svcaddr. El argumento fildes es un descriptor de archivo abierto y enlazado. Esta rutina reenviará el mensaje de llamada a intervalos de 15 segundos hasta que se reciba una respuesta o hasta que la llamada expire. El tiempo total para que la llamada expire está especificado por clnt_call() (ver clnt_call() en rpc_clnt_calls(3)). Los períodos de tiempo de espera de reintento y de tiempo total se pueden cambiar usando clnt_control(). El usuario puede establecer el tamaño de los búferes de envío y recepción con los argumentos sendsz y recvsz; los valores 0 eligen valores predeterminados adecuados. Esta rutina devuelve NULL si falla.
clnt_pcreateerror()
Imprime un mensaje en la salida de error estándar indicando por qué no se pudo crear un identificador RPC de cliente. El mensaje se antepone con la cadena s y dos puntos, y se añade un salto de línea al final.
clnt_spcreateerror()
Similar a clnt_pcreateerror(), excepto que devuelve una cadena en lugar de imprimirla en la salida de error estándar. En este caso, no se añade un salto de línea al mensaje. Advertencia: devuelve un puntero a un búfer que se sobrescribe en cada llamada.
clnt_raw_create()
Esta rutina crea un identificador de cliente RPC para el programa remoto prognum y la versión versnum. El transporte utilizado para pasar mensajes al servicio es un búfer dentro del espacio de direcciones del proceso, por lo que el servidor RPC correspondiente debería vivir en el mismo espacio de direcciones; (ver svc_raw_create() en rpc_svc_create(3)). Esto permite simular RPC y medir sobrecargas RPC, como tiempos de ida y vuelta, sin ninguna interferencia del kernel o de la red. Esta rutina devuelve NULL si falla. La función clnt_raw_create() debe llamarse después de svc_raw_create().
clnt_tli_create()
Esta rutina crea un identificador de cliente RPC para el programa remoto prognum y la versión versnum. El programa remoto se encuentra en la dirección svcaddr. NAME

clnt_create, clnt_pcreateerror, clnt_tp_create, clnt_tp_create_timed, clnt_vc_create, rpc_createerr, rpc_createerr - generic RPC client creation

SYNOPSIS

#include <rpc/rpc.h>

CLIENT *clnt_create(const char *host, u_long prognum, u_long versnum, const char *nettype);
void clnt_pcreateerror(const char *str);
CLIENT *clnt_tp_create(const char *host, u_long prognum, u_long versnum, const char *netconf);
CLIENT *clnt_tp_create_timed(const char *host, u_long prognum, u_long versnum, const char *netconf, struct timeval *timeout);
CLIENT *clnt_vc_create(const char *host, u_long prognum, u_long versnum, const struct svc_call_back *svcaddr, u_int sendsz, u_int recvsz);
extern struct rpc_createerr rpc_createerr;

DESCRIPTION

These functions are used to create RPC client handles. An RPC client handle encapsulates the information necessary to make remote procedure calls to an RPC server process. The actual details of the transport (network protocols, etc.) are hidden from the user.

The routines differ in how they determine the network transport and address information for the remote service.

Routines

clnt_create()
The clnt_create() function creates an RPC client handle for the program prognum, version versnum, and for the transport specified by nettype on the remote host host. host is a presentation-layer name for the host machine. nettype is a string that specifies the desired transport mechanism, such as "udp" or "tcp". See rpc(7) for a list of supported transport types. The clnt_create() function consults the remote rpcbind service on the host host to determine the actual address of the remote service. Default options are set, which can be changed using clnt_control() calls. This routine returns NULL if it fails. The clnt_pcreateerror() routine can be used to print the reason for failure.
clnt_pcreateerror()
The clnt_pcreateerror() function prints a descriptive error message to the standard error output, preceded by the string str. The error message indicates the reason why an earlier RPC client creation routine failed. The global variable rpc_createerr is used to hold the error information.
clnt_tp_create()
Like clnt_create() except that clnt_tp_create() tries only one transport specified through netconf. The clnt_tp_create() function creates a client handle for the program prognum, the version versnum, and for the transport specified by netconf. Default options are set, which can be changed using clnt_control() calls. The remote rpcbind service on the host host is consulted for the address of the remote service. This routine returns NULL if it fails. The clnt_pcreateerror() routine can be used to print the reason for failure.
clnt_tp_create_timed()
Like clnt_tp_create() except clnt_tp_create_timed() has the extra argument timeout which specifies the maximum time allowed for the creation attempt to succeed. In all other respects, the clnt_tp_create_timed() call behaves exactly like the clnt_tp_create() call.
clnt_vc_create()
This routine creates an RPC client for the remote program prognum and version versnum; the client uses a connection-oriented transport. The remote program is located at address svcaddr. The fildes argument is an open and bound file descriptor. The user may specify the size of the send and receive buffers with the sendsz and recvsz arguments; values of 0 choose suitable defaults. This routine returns NULL if it fails. The address svcaddr should not be NULL and should point to the actual address of the remote program. The clnt_vc_create() function does not consult the remote rpcbind service for this information.
struct rpc_createerr rpc_createerr;
A global variable whose value is set by any RPC client handle creation routine that fails. It is used by the routine clnt_pcreateerror() to print the reason for the failure.

AVAILABILITY

These functions are part of libtirpc.
