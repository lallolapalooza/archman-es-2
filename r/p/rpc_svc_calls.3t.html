svc_getreq_poll(struct pollfd *pfdp, const int pollretval);

void
svc_getreqset(fd_set * rdfds);

struct netbuf *
svc_getrpccaller(const SVCXPRT *xprt);

void
svc_run(void);

bool_t
svc_sendreply(SVCXPRT *xprt, xdrproc_t outproc, char *out);

DESCRIPCIÓN

Estas rutinas forman parte de la biblioteca RPC que permite a los programas del lenguaje C realizar llamadas a procedimientos en otras máquinas a través de la red.

Estas rutinas están asociadas con el lado del servidor del mecanismo RPC. Algunas de ellas son llamadas por la función de despacho del lado del servidor, mientras que otras (como svc_run()) son llamadas cuando se inicia el servidor.

Rutinas

Ver rpc(3) para la definición de la estructura de datos SVCXPRT.

svc_dg_enablecache()
Esta función asigna una caché de solicitudes duplicadas para el punto final del servicio xprt, con un tamaño suficiente para contener cache_size entradas. Una vez habilitado, no hay forma de deshabilitar el caché. Esta rutina devuelve 0 si se asignó con éxito el espacio necesario para una caché del tamaño dado, y 1 en caso contrario.
svc_exit()
Esta función, cuando es llamada por cualquiera de los procedimientos del servidor RPC o de otra manera, hace que svc_run() retorne.

Tal como está implementado actualmente, svc_exit() pone a cero la variable global svc_fdset. Si se va a reanudar la actividad del servidor RPC, los servicios deben ser registrados nuevamente en la biblioteca RPC, ya sea a través de una de las funciones de rpc_svc_create(3), o utilizando xprt_register(). La función svc_exit() tiene alcance global y finaliza toda la actividad del servidor RPC.

fd_set svc_fdset
Una variable global que refleja la máscara de bits del descriptor de archivo de lectura del servidor RPC; es adecuada como argumento para la llamada al sistema select(2). Esto solo es de interés si los implementadores de servicios no llaman a svc_run(), sino que realizan su propio procesamiento asíncrono de eventos. Esta variable es de solo lectura (¡no pase su dirección a select(2)!), sin embargo, puede cambiar después de las llamadas a svc_getreqset() o a cualquiera de las rutinas de creación.
svc_freeargs()
Una macrofunción que libera cualquier dato asignado por el sistema RPC/XDR cuando decodificó los argumentos de un procedimiento de servicio usando svc_getargs(). Esta rutina devuelve TRUE si los resultados se liberaron con éxito, y FALSE en caso contrario.
svc_getargs()
Una macrofunción que decodifica los argumentos de una solicitud RPC asociada con el manejador de transporte del servicio RPC xprt. El argumento in es la dirección donde se colocarán los argumentos; inproc es la rutina XDR utilizada para decodificar los argumentos. Esta rutina devuelve TRUE si la decodificación tiene éxito, y FALSE en caso contrario.
svc_getreq_common()
Esta rutina se llama para manejar una solicitud en el descriptor de archivo dado.
svc_getreq_poll()
Esta rutina solo es de interés si un implementador de servicio no llama a svc_run(), sino que implementa un procesamiento asíncrono de eventos personalizado. Se llama cuando poll(2) ha determinado que ha llegado una solicitud RPC en algunos descriptores de archivo RPC; pollretval es el valor de retorno de poll(2) y pfdp es el array de estructuras pollfd en el cual se realizó el poll(2). Se asume que es un array lo suficientemente grande como para contener el número máximo de descriptores permitidos.
svc_getreqset()
Esta rutina solo es de interés si un implementador de servicio no llama a svc_run(), sino que implementa un procesamiento asíncrono de eventos personalizado. Se llama cuando poll(2) ha determinado que ha llegado una solicitud RPC en algunos descriptores de archivo RPC; rdfds es la máscara de bits resultante del descriptor de archivo de lectura. La rutina retorna cuando todos los descriptores de archivo asociados con el valor de rdfds han sido atendidos.
svc_getrpccaller()
La forma aprobada de obtener la dirección de red del llamador de un procedimiento asociado con el manejador de transporte del servicio RPC xprt.

NAME

rpc_svc_calls, svc_fdset, svc_pollset, svc_run, svc_sendreply - library routines for implementing RPC server side calls

SYNOPSIS

#include <sys/types.h>
#include <sys/time.h>
#include <rpc/rpc.h>
#include <sys/socket.h>

bool_t
svc_sendreply(SVCXPRT *xprt, xdrproc_t xdr_result, caddr_t result);
void
svc_run(void);

#include <poll.h>

extern fd_set svc_fdset;
extern struct pollfd svc_pollset[FD_SETSIZE];

DESCRIPTION

The routines described in this manual page are used by RPC services to handle incoming remote procedure call requests.

Routines

svc_fdset
This is a standard fd_set structure, which contains all the file descriptors that are currently registered with the RPC server dispatcher. It is used internally by the RPC library and is primarily used by the select system call within the svc_run routine. Service implementors may modify this set to include additional file descriptors that need to be monitored for RPC requests. When modifying this set, the programmer must also update the svc_pollset array accordingly.
svc_getcaller(transp)
This routine returns a pointer to a structure representing the address of the caller of the RPC service. The transp argument is the transport handle returned by svc_getreq() or svc_getreq_common(). For AF_LOCAL transport, it returns the sun_path field of the socket address structure, identifying the calling client. This only works if the client is calling the server over an AF_LOCAL socket.
struct pollfd svc_pollset[FD_SETSIZE];
svc_pollset is an array of pollfd structures derived from svc_fdset[]. It is suitable as an argument to the poll(2) system call. The derivation of svc_pollset from svc_fdset is made in the current implementation in svc_run(). Service implementors who do not call svc_run() and who wish to use this array must perform this derivation themselves.
svc_run()
This routine never returns. It waits for RPC requests to arrive, and calls the appropriate service procedure using svc_getreq_poll() when one arrives. This procedure is usually waiting for the poll(2) system call to return.
svc_sendreply()
Called by an RPC service's dispatch routine to send the results of a remote procedure call. The xprt argument is the request's associated transport handle; outproc is the XDR routine which is used to encode the results; and out is the address of the results. This routine returns TRUE if it succeeds, FALSE otherwise.

AVAILABILITY

These functions are part of libtirpc.
