regex(3) Manual de Funciones de Biblioteca regex(3)

NOMBRE

regcomp, regexec, regerror, regfree - Funciones POSIX regex

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <regex.h>
int regcomp(regex_t *restrict preg, const char *restrict regex,
            int cflags);
int regexec(const regex_t *restrict preg,
            const char *restrict string,
            size_t n, regmatch_t pmatch[_Nullable restrict n],
            int eflags);
size_t regerror(size_t errbuf_size;
            int errcode, const regex_t *_Nullable restrict preg,
            char errbuf[_Nullable restrict errbuf_size],
            size_t errbuf_size);
void regfree(regex_t *preg);
typedef struct {
    size_t    re_nsub;
} regex_t;
typedef struct {
    regoff_t  rm_so;
    regoff_t  rm_eo;
} regmatch_t;
typedef /* ... */  regoff_t;

DESCRIPCION

Compilación

regcomp() se utiliza para compilar una expresión regular en un formato adecuado para búsquedas posteriores con regexec().

En caso de éxito, el búfer de patrones en *preg se inicializa. regex es una cadena terminada en nulo. La configuración regional debe ser la misma al ejecutar regexec().

Después de que regcomp() tenga éxito, preg->re_nsub contiene el número de subexpresiones en regex. Por lo tanto, un valor de preg->re_nsub + 1 pasado como n a regexec() es suficiente para capturar todas las coincidencias.

cflags es el OR a nivel de bits de cero o más de las siguientes opciones:

REG_EXTENDED
Utiliza la sintaxis de Expresiones Regulares Extendidas POSIX al interpretar regex. Si no está configurada, se utiliza la sintaxis de Expresiones Regulares Básicas POSIX.
REG_ICASE
No diferencia entre mayúsculas y minúsculas. Las búsquedas posteriores con regexec() que utilicen este búfer de patrones no distinguirán entre mayúsculas y minúsculas.
REG_NOSUB
Solo informa del éxito general. regexec() utilizará solo pmatch para REG_STARTEND, ignorando n.
REG_NEWLINE
Los operadores de coincidencia de cualquier carácter no coinciden con una nueva línea.
Una lista de no coincidencia ([^...]) que no contenga una nueva línea no coincide con una nueva línea.
El operador de principio de línea (^) coincide con la cadena vacía inmediatamente después de una nueva línea, independientemente de si eflags, las banderas de ejecución de regexec(), contiene REG_NOTBOL.
El operador de fin de línea ($) coincide con la cadena vacía inmediatamente antes de una nueva línea, independientemente de si eflags contiene REG_NOTEOL.

Coincidencia

regexec() se utiliza para hacer coincidir una cadena terminada en nulo con el búfer de patrones compilado en *preg, que debe haber sido inicializado con regcomp(). eflags es el OR a nivel de bits de cero o más de las siguientes banderas:

REG_NOTBOL
El operador de principio de línea siempre falla al coincidir (pero véase la bandera de compilación REG_NEWLINE anterior). Esta bandera puede usarse cuando se pasan diferentes porciones de una cadena a regexec() y el principio de la cadena no debe interpretarse como el principio de la línea.
REG_NOTEOL
El operador de fin de línea siempre falla al coincidir (pero véase la bandera de compilación REG_NEWLINE anterior).
REG_STARTEND
Coincide [string + pmatch[0].rm_so, string + pmatch[0].rm_eo) en lugar de [string, string + strlen(string)). Esto permite hacer coincidir NUL bytes incrustados y evita un strlen(3) en cadenas de longitud conocida. Si se devuelven coincidencias (no se pasó REG_NOSUB a regcomp(), la coincidencia tuvo éxito y n > 0), estas sobrescriben pmatch como de costumbre, y los desplazamientos de coincidencia permanecen relativos a string (no a string + pmatch[0].rm_so). Esta bandera es una extensión BSD, no presente en POSIX.

Desplazamientos de coincidencia

A menos que se pasara REG_NOSUB a regcomp(), es posible obtener las ubicaciones de las coincidencias dentro de string: regexec() rellena n elementos de pmatch con resultados: pmatch[0] corresponde a la coincidencia completa, pmatch[1] al primer subexpresión, etc. Si hubo más coincidencias que n, se descartan; si hubo menos, los elementos no utilizados de pmatch se rellenan con -1.

Cada coincidencia válida (no -1) devuelta corresponde al rango [string + rm_so, string + rm_eo).

regoff_t es un tipo de entero con signo capaz de almacenar el valor más grande que puede almacenarse en un tipo ptrdiff_t o un tipo ssize_t.

Reporte de errores

regerror() se utiliza para convertir los códigos de error que pueden ser devueltos tanto por regcomp() como por regexec() en cadenas de mensajes de error.

Si preg no es un puntero nulo, errcode debe ser el último error devuelto por una operación sobre preg.

Si errbuf_size no es 0, se copian hasta errbuf_size bytes a errbuf; la cadena de error siempre se termina en nulo y se trunca para que quepa.

Liberación

regfree() desinicializa el búfer de patrones en *preg, liberando cualquier memoria asociada; *preg debe haber sido inicializado mediante regcomp().

VALOR DE RETORNO

regcomp() devuelve cero para una compilación exitosa o un código de error en caso de fallo.

regexec() devuelve cero para una coincidencia exitosa o REG_NOMATCH en caso de fallo.

regerror() devuelve el tamaño del búfer necesario para almacenar la cadena.

ERRORES

Los siguientes errores pueden ser devueltos por regcomp():

REG_BADBR
Uso inválido de un operador de referencia inversa.
REG_BADPAT
Uso inválido de operadores de patrones como grupos o listas.
REG_BADRPT
Uso inválido de operadores de repetición, como usar '*' como primer carácter.
REG_EBRACE
Operadores de intervalo de llaves no coincidentes.
REG_EBRACK
Operadores de lista de corchetes no coincidentes.
REG_ECOLLATE
Elemento de ordenación inválido.
REG_ECTYPE
Nombre de clase de caracteres desconocido.
REG_EEND
Error no específico. Esto no está definido por POSIX.
REG_EESCAPE
Barra invertida final.
REG_EPAREN
Operadores de grupo de paréntesis no coincidentes.
REG_ERANGE
Uso inválido del operador de rango; por ejemplo, el punto final del rango ocurre antes del punto de inicio.
REG_ESIZE
La expresión regular compilada requiere un búfer de patrón mayor que 64 kB. Esto no está definido por POSIX.
REG_ESPACE
Las rutinas de expresiones regulares se quedaron sin memoria.
REG_ESUBREG
Referencia posterior inválida a una subexpresión.

STANDARDS

POSIX.1-2008.

HISTORY

POSIX.1-2001.

Antes de POSIX.1-2008, se requería que regoff_t pudiera almacenar el valor más grande que se puede almacenar en un tipo off_t o un tipo ssize_t.

CAVEATS

Solo se requiere que re_nsub se inicialice si REG_NOSUB no se especificó, pero todas las implementaciones conocidas lo inicializan independientemente.

Tanto regex_t como regmatch_t pueden tener (y tienen) más miembros, en cualquier orden. Siempre refiérase a ellos por nombre.

EXAMPLES

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <regex.h>
#define NITEMS(arr)  (sizeof((arr)) / sizeof((arr)[0]))
static const char *const str =
        "1) John Driverhacker;\n2) John Doe;\n3) John Foo;\n";
static const char *const re = "John.*o";
int main(void)
{
    static const char *s = str;
    regex_t     regex;
    regmatch_t  pmatch[1];
    regoff_t    off, len;
    if (regcomp(&regex, re, REG_NEWLINE))
        exit(EXIT_FAILURE);
    printf("String = \"%s\"\n", str);
    printf("Matches:\n");
    for (unsigned int i = 0; ; i++) {
        if (regexec(&regex, s, NITEMS(pmatch), pmatch, 0))
            break;
        off = pmatch[0].rm_so + (s - str);
        len = pmatch[0].rm_eo - pmatch[0].rm_so;
        printf("#%u:\n", i);
        printf("offset = %jd; length = %jd\n", (intmax_t) off,
                (intmax_t) len);
        printf("substring = \"%.*s\"\n", len, s + pmatch[0].rm_so);
        s += pmatch[0].rm_eo;
    }
    exit(EXIT_SUCCESS);
}
