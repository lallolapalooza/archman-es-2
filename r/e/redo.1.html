REDO(1) General Commands Manual REDO(1)

NOMBRE

redo - reconstruye archivos objetivo cuando los archivos fuente han cambiado

SINOPSIS

redo [opción] [objetivo]...

DESCRIPCIÓN

redo es una herramienta para construir archivos y para reconstruirlos si alguna de sus dependencias ha cambiado. Las reglas de construcción están contenidas en archivos con la extensión .do que se denominan dofiles. Normalmente, los dofiles son scripts de shell ejecutados por sh(1).

redo utiliza un algoritmo simple para encontrar dofiles: Primero busca el nombre del archivo objetivo con el sufijo .do, luego busca nombres de archivo que consisten en default más la extensión del nombre de archivo objetivo más .do, eliminando recursivamente el último componente de la extensión del nombre de archivo objetivo.

Por ejemplo, si se le pide a redo que construya un archivo llamado example.x.y.z, buscará dofiles con los siguientes nombres de archivo para construir el archivo:

example.x.y.z.do

default.x.y.z.do

default.y.z.do

default.z.do

default.do

redo considera el primer archivo existente encontrado de esta manera como el dofile para el objetivo y lo ejecuta. Si a redo no se le da un objetivo, construye un objetivo llamado all. Si redo no puede encontrar un dofile para un objetivo, sale con un código de estado que indica fallo.

redo pasa tres argumentos a un dofile que se ejecuta:

$1
es el nombre del objetivo.
$2
es el nombre base del objetivo, es decir, el nombre del objetivo menos los componentes del directorio y las extensiones iniciales. Tenga en cuenta que la extensión se determina a partir del dofile: Un archivo example.a.b.c que se construye con un dofile default.b.c.do se considerará que tiene la extensión b.c, por lo que $2 se establecerá en example.a.
$3
es el nombre de un archivo temporal que reemplaza al objetivo atómicamente después de que el dofile haya salido con éxito. En lugar de escribir en $3, un dofile también puede escribir en la salida estándar.

Si el objetivo actual debe ser reconstruido si otros archivos cambian, esto se puede declarar con redo-ifchange(1): Cuando redo-ifchange(1) se ejecuta desde un dofile, redo construye los objetivos dados a redo-ifchange(1) y reconstruirá el objetivo actual en la próxima invocación de redo si alguno de los objetivos dados a redo-ifchange(1) ha cambiado desde la última construcción.

Si el objetivo actual debe ser reconstruido si un archivo que no existe en el momento de la construcción existe, esto se puede declarar con redo-ifcreate(1): Cuando redo-ifcreate(1) se ejecuta desde un dofile, redo reconstruirá el objetivo actual en la próxima invocación de redo si alguno de los objetivos dados a redo-ifcreate(1) existe.

Si el objetivo actual debe ser reconstruido si la salida de un comando cambia, esto se puede declarar con redo-stamp(1): Cuando redo-stamp(1) se ejecuta desde un dofile y se le dan datos en la entrada estándar, redo reconstruirá el objetivo actual en la próxima invocación de redo si la salida del comando que canalizó datos hacia él cambia.

Si el objetivo actual debe ser reconstruido siempre, esto se puede declarar con redo-always(1): Cuando redo-always(1) se ejecuta desde un dofile, redo reconstruirá el objetivo actual en la próxima invocación de redo.

OPCIONES

Si se da la opción -d o --debug, redo imprime información sobre todas las comprobaciones de dependencias.

Si se da la opción -h o --help, redo imprime un breve aviso sobre sus opciones de línea de comandos.

Si se da la opción -j o --jobs seguida de un entero, una invocación de redo(1) o redo-ifchange(1) con múltiples argumentos construye objetivos en paralelo. El argumento entero especifica el número máximo de objetivos que se pueden construir en paralelo. Los objetivos se bloquean, por lo que si los objetivos construidos en paralelo comparten una dependencia, redo(1) solo la construye una vez, a menos que el dofile de la dependencia use redo-always(1) para reconstruir cada vez, o la dependencia quede obsoleta durante una construcción de alguna otra manera.

Si se da la opción --version, redo imprime información de la versión y sale.

Si se da la opción -x o --xtrace, redo imprime los comandos dentro de los dofiles a medida que se ejecutan.

EJEMPLOS

redo
hace que redo busque un dofile llamado all.do, que ejecuta para construir el objetivo all. Normalmente, la ejecución de all.do no producirá ninguna salida en la salida estándar y redo no creará un archivo llamado all.
redo example.x.y.z
hace que redo busque dofiles llamados example.x.y.z.do, default.x.y.z.do, default.y.z.do, default.z.do, default.do. redo ejecuta el primer archivo que existe para construir example.x.y.z.
