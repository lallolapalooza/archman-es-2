Remote-Viewer(1) Soporte de virtualización Remote-Viewer(1)

NOMBRE

remote-viewer - un cliente simple de escritorio remoto

SINOPSIS

remote-viewer [OPCIONES] -- [URI]

DESCRIPCIÓN

remote-viewer es un cliente simple de pantalla remota. Los protocolos soportados son SPICE y VNC.

Iniciar remote-viewer sin URI abrirá un diálogo simple con una entrada y una lista de URIs accedidas previamente con éxito.

La URI también puede apuntar a un archivo de configuración de conexión, consulte la sección ARCHIVO DE CONEXIÓN para una descripción del formato.

Si la URI es '-', entonces remote-viewer leerá la entrada estándar como un archivo de configuración de conexión e intentará conectarse usándolo.

En algunas circunstancias, el visor puede necesitar capturar el puntero del ratón. La secuencia de teclas predeterminada para liberar la captura es "Ctrl_L"+"Alt_L", sin embargo, esto puede ser anulado usando el argumento "--hotkeys" documentado a continuación.

OPCIONES

Se aceptan las siguientes opciones al ejecutar "remote-viewer":

-h, --help
Muestra el resumen de ayuda de la línea de comandos
-V, --version
Muestra el número de versión del programa
-v, --verbose
Muestra información sobre la conexión
-z PCT, --zoom=PCT
Nivel de zoom de la ventana de visualización en porcentaje. Rango 10-400.
-f, --full-screen
Inicia con las ventanas maximizadas a pantalla completa.

Si es compatible, la pantalla remota se reconfigurará para que coincida con la configuración de los monitores del cliente físico, habilitando o deshabilitando monitores adicionales según sea necesario. Esto está implementado actualmente solo por el backend Spice y puede ser deshabilitado por el argumento "--auto-resize".

Para especificar qué monitores del cliente se utilizan en modo de pantalla completa, consulte la sección CONFIGURACIÓN a continuación.

--auto-resize <siempre|nunca>
Controla si está permitido intentar redimensionar el framebuffer remoto para que coincida con el tamaño de la ventana local. Actualmente está activado por defecto, pero tenga en cuenta que no todos los servidores soportarán esto.
-t TITULO, --title TITULO
Establece el título de la ventana a TITULO
-s, --shared
Permite una sesión compartida con múltiples clientes
--cursor auto|local
Controla cómo se renderiza el cursor del ratón. "auto" es el comportamiento predeterminado, que respetará el comportamiento solicitado por el servidor remoto. Esto puede implicar que el servidor renderice el cursor de forma remota en el framebuffer o envíe los detalles del cursor al cliente para que los renderice. "local" anula este predeterminado para solicitar que el cursor del escritorio local se renderice siempre, sin importar lo que solicite el servidor. Esto último rara vez es necesario, pero se puede usar si el servidor tiene una mala configuración que resulta en que su propio cursor se oculte.
--debug
Muestra información de depuración
-H HOTKEYS, --hotkeys HOTKEYS
Establece las combinaciones de teclas globales. De forma predeterminada, los atajos de teclado solo funcionan cuando el widget de visualización del invitado no tiene el foco. Cualquier acción especificada en HOTKEYS será efectiva incluso cuando el widget de visualización del invitado tenga el foco de entrada. El formato para HOTKEYS es <accion1>=<tecla1>[+<tecla2>][,<accion2>=<tecla3>[+<tecla4>]]. Los nombres de las teclas no distinguen entre mayúsculas y minúsculas. Las acciones válidas son: toggle-fullscreen, release-cursor, zoom-in, zoom-out, zoom-reset, secure-attention, usb-device-reset, smartcard-insert y smartcard-remove. La acción "secure-attention" envía una secuencia de atención segura (Ctrl+Alt+Del) al invitado. Ejemplos: 
--hotkeys=toggle-fullscreen=shift+f11,release-cursor=shift+f12
--hotkeys=release-cursor=ctrl+alt

Tenga en cuenta que las combinaciones de teclas para las que no se proporciona una asignación están deshabilitadas. Aunque el cliente gestiona las combinaciones de teclas especificadas aquí, todavía es posible enviarlas al invitado a través de una opción de menú.

-K, --keymap
Remapea y/o bloquea las pulsaciones de teclas proporcionadas al host. Todos los identificadores de teclas distinguen entre mayúsculas y minúsculas y siguen la convención de nombres definida en gdkkeysyms.h sin el prefijo GDK_KEY_.

Ejecutar la aplicación con --debug mostrará los símbolos de las pulsaciones de teclas de la siguiente manera:
"La tecla presionada fue keycode='0x63', gdk_keyname='c'"
"La tecla presionada fue keycode='0xffeb', gdk_keyname='Super_L'"

El formato para proporcionar un mapa de teclas es: <srcKeySym1>=[<destKeySym1>][+<destKeySym2][,<srckeySym2>=[<destKeySym1]

Para bloquear una pulsación de tecla, simplemente asigne un parámetro vacío a srcKeySym.

Ejemplo:
--keymap=Super_L=,Alt_L=,1=Shift_L+F1,2=Shift_L+F2

Esto bloqueará las pulsaciones de las teclas Super_L (típicamente Tecla de Windows) y Alt_L y remapeará la tecla 1 a Shift F1, y la 2 a Shift F2.

-k, --kiosk
Inicia en modo quiosco. En este modo, la aplicación se iniciará en pantalla completa con una interfaz mínima. Impedirá que el usuario salga o realice cualquier interacción fuera del uso de la sesión de escritorio remoto.

Tenga en cuenta que no puede ofrecer una solución segura completa por sí sola. Su sistema de quiosco debe tener configuraciones de seguridad y operativas adicionales para bloquear el sistema operativo. En particular, debe configurar o deshabilitar el administrador de ventanas, limitar las capacidades de la sesión, usar algún mecanismo de reinicio/vigilancia, deshabilitar el cambio de VT, etc.

--kiosk-quit <nunca|al-desconectar>
Por defecto, cuando el modo quiosco está habilitado, virt-viewer permanecerá abierto cuando se termine la conexión con el servidor remoto. Al establecer la opción kiosk-quit al valor "al-desconectar", virt-viewer se cerrará en su lugar.

TECLA DE ACCESO

Una combinación de asignación de teclas se describe mediante una serie de cadenas de teclas separadas por '+' que deben presionarse juntas para activar la acción asociada.

Debe componerse de modificadores (shift, ctrl o alt) y una tecla no modificadora. Por ejemplo, "shift+f11".

ARCHIVO DE CONEXIÓN

El archivo de conexión de remote-viewer tiene formato INI, con un grupo obligatorio [virt-viewer] y una clave "type".

Ejemplo

Abrir un archivo con el siguiente contenido iniciará remote-viewer en pantalla completa y se conectará al host "betsiboka" utilizando el protocolo SPICE:

[virt-viewer]
type=spice
host=betsiboka
port=5900
fullscreen=1

Lista de claves

"version" (cadena)
Si el número de versión de remote-viewer no es mayor o igual a la versión requerida, se genera un error con la versión esperada.

El formato de versión aceptado es una lista de enteros separados por '.'. Puede ir seguido de un guion '-' y un número de compilación adicional con el mismo formato.

La comparación de versiones se realiza comparando cada entero de la lista uno por uno. Si alguno de los componentes no es un número, la comparación de versiones fallará y se considerará que ambas versiones son iguales.

"versions" (lista osid:version)
Esta es una lista de parejas osid:version separadas por ';'. osid es una cadena arbitraria, version es un número de versión en el mismo formato que en el campo 'version'. Una pareja dada indica que las compilaciones de remote-viewer que coinciden con el 'osid' dado (fedora22, debian7, ...) deben ser al menos de la versión 'version'. Por coherencia, se recomienda utilizar los shortids de OS de libosinfo como osid.
