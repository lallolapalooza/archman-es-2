recvmmsg(2) Manual de llamadas al sistema recvmmsg(2)

NOMBRE

recvmmsg - recibir múltiples mensajes de un socket

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#define _GNU_SOURCE         /* Véase feature_test_macros(7) */
#include <sys/socket.h>
int recvmmsg(unsigned int n;
             int sockfd, struct mmsghdr msgvec[n], unsigned int n,
             int flags, struct timespec *timeout);

DESCRIPCIÓN

La llamada al sistema recvmmsg() es una extensión de recvmsg(2) que permite al llamante recibir múltiples mensajes de un socket mediante una única llamada al sistema. (Esto tiene beneficios de rendimiento para algunas aplicaciones). Una extensión adicional sobre recvmsg(2) es el soporte para un tiempo de espera en la operación de recepción.

El argumento sockfd es el descriptor de archivo del socket del que se van a recibir datos.

El argumento msgvec es un puntero a un array de estructuras mmsghdr. El tamaño de este array se especifica en n.

La estructura mmsghdr se define en <sys/socket.h> como:


struct mmsghdr {
    struct msghdr msg_hdr;  /* Cabecera del mensaje */
    unsigned int  msg_len;  /* Número de bytes recibidos para la cabecera */
};

El campo msg_hdr es una estructura msghdr, como se describe en recvmsg(2). El campo msg_len es el número de bytes devueltos para el mensaje en la entrada. Este campo tiene el mismo valor que el valor de retorno de una única recvmsg(2) en la cabecera.

El argumento flags contiene banderas OR-ed juntas. Las banderas son las mismas que se documentan para recvmsg(2), con la siguiente adición:

MSG_WAITFORONE (desde Linux 2.6.34)
Activa MSG_DONTWAIT después de que se haya recibido el primer mensaje.

El argumento timeout apunta a una struct timespec (ver clock_gettime(2)) que define un tiempo de espera (segundos más nanosegundos) para la operación de recepción (¡pero ver BUGS!). (Este intervalo se redondeará hacia arriba hasta la granularidad del reloj del sistema, y los retrasos de programación del núcleo significan que el intervalo de bloqueo puede excederse en una pequeña cantidad). Si timeout es NULL, la operación se bloquea indefinidamente.

Una llamada bloqueante a recvmmsg() se bloquea hasta que se hayan recibido n mensajes o hasta que expire el tiempo de espera. Una llamada no bloqueante lee tantos mensajes como estén disponibles (hasta el límite especificado por n) y vuelve inmediatamente.

Al regresar de recvmmsg(), los elementos sucesivos de msgvec se actualizan para contener información sobre cada mensaje recibido: msg_len contiene el tamaño del mensaje recibido; los subcampos de msg_hdr se actualizan como se describe en recvmsg(2). El valor de retorno de la llamada indica el número de elementos de msgvec que se han actualizado.

VALOR DE RETORNO

En caso de éxito, recvmmsg() devuelve el número de mensajes recibidos en msgvec; en caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

Los errores son los de recvmsg(2). Además, puede ocurrir el siguiente error:

EINVAL
timeout no es válido.

Ver también BUGS.

ESTÁNDARES

Linux.

HISTORIAL

Linux 2.6.33, glibc 2.12.

BUGS

El argumento timeout no funciona como se pretende. El tiempo de espera solo se comprueba después de la recepción de cada datagrama, de modo que si se reciben hasta n-1 datagramas antes de que expire el tiempo de espera, pero luego no se reciben más datagramas, la llamada se bloqueará para siempre.

Si ocurre un error después de que se haya recibido al menos un mensaje, la llamada tiene éxito y devuelve el número de mensajes recibidos. Se espera que el código de error se devuelva en una llamada posterior a recvmmsg(). Sin embargo, en la implementación actual, el código de error puede ser sobrescrito mientras tanto por un evento de red no relacionado en un socket, por ejemplo, un paquete ICMP entrante.

EJEMPLOS

El siguiente programa utiliza recvmmsg() para recibir múltiples mensajes en un socket y los almacena en múltiples búferes. La llamada regresa si todos los búferes están llenos o si ha expirado el tiempo de espera especificado.

El siguiente fragmento genera periódicamente datagramas UDP que contienen un número aleatorio:


$ while true; do echo $RANDOM > /dev/udp/127.0.0.1/1234;
      sleep 0.25; done

Estos datagramas son leídos por la aplicación de ejemplo, que puede producir la siguiente salida:


$ ./a.out
5 mensajes recibidos
1 11782
2 11345
3 304
4 13514
5 28421

Código fuente del programa

#define _GNU_SOURCE
#include <arpa/inet.h>
#include <netinet/in.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/socket.h>
#include <time.h>
int
main(void)
{
#define VLEN 10
#define BUFSIZE 200
#define TIMEOUT 1
    int                 sockfd, retval;
    char                bufs[VLEN][BUFSIZE+1];
    struct iovec        iovecs[VLEN];
    struct mmsghdr      msgs[VLEN];
    struct timespec     timeout;
    struct sockaddr_in  addr;
    sockfd = socket(AF_INET, SOCK_DGRAM, 0);
    if (sockfd == -1) {
        perror("socket()");
        exit(EXIT_FAILURE);
    }
    addr.sin_family = AF_INET;
    addr.sin_addr.s_addr = htonl(INADDR_LOOPBACK);
    addr.sin_port = htons(1234);
    if (bind(sockfd, (struct sockaddr *) &addr, sizeof(addr)) == -1) {
        perror("bind()");
        exit(EXIT_FAILURE);
    }
    memset(msgs, 0, sizeof(msgs));
    for (size_t i = 0; i < VLEN; i++) {
        iovecs[i].iov_base         = bufs[i];
        iovecs[i].iov_len          = BUFSIZE;
        msgs[i].msg_hdr.msg_iov    = &iovecs[i];
        msgs[i].msg_hdr.msg_iovlen = 1;
    }
    timeout.tv_sec = TIMEOUT;
    timeout.tv_nsec = 0;
    retval = recvmmsg(sockfd, msgs, VLEN, 0, &timeout);
    if (retval == -1) {
        perror("recvmmsg()");
        exit(EXIT_FAILURE);
    }
    printf("%d messages received\n", retval);
    for (size_t i = 0; i < retval; i++) {
        bufs[i][msgs[i].msg_len] = 0;
        printf("%zu %s", i+1, bufs[i]);
    }
    exit(EXIT_SUCCESS);
}
