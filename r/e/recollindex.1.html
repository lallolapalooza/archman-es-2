RECOLLINDEX(1) Manual de comandos generales RECOLLINDEX(1)

NOMBRE

recollindex - comando de indexación para el sistema de búsqueda de texto completo Recoll

SINOPSIS

recollindex -h
recollindex [ -z|-Z ] [ -k ] [ --nopurge ] [ -P ] [ --diagsfile <diagpath> ]
recollindex -m [ -w <secs>] [ -D ] [ -O ] [ -x ] [ -C ] [ -n|-k ]
recollindex -i [ -Z -k -f -P ] [<ruta [ruta ...]>]
recollindex -r [ -Z -K -e -f ] [ -p patrón ] <dirpath>
recollindex -e [<ruta [ruta ...]>]
recollindex -l|-S|-E
recollindex -s <idioma>
recollindex --webcache-compact
recollindex --webcache-burst <directorio_destino>
recollindex --notindexed [ruta [ruta ...]]

DESCRIPCIÓN

Crea o actualiza un índice de Recoll.

Hay varios modos de operación. Todos los modos admiten una opción opcional -c <cfgdir> para especificar el nombre del directorio de configuración, anulando el predeterminado o $RECOLL_CONFDIR (o $HOME/.recoll por defecto).

El modo normal indexará el conjunto de archivos descrito en la configuración. Esto actualizará incrementalmente el índice con los archivos que han cambiado desde la última ejecución. Si se proporciona la opción -z, el índice se borrará antes de comenzar. Si se proporciona la opción -Z, el índice no se restablecerá, pero todos los archivos se considerarán necesarios de volver a indexar (restablecimiento in situ).

recollindex no vuelve a procesar los archivos que fallaron previamente al indexarse (por ejemplo, debido a la falta de un programa auxiliar). Si se proporciona la opción -k, recollindex intentará nuevamente procesar todos los archivos fallidos. Tenga en cuenta que recollindex también puede decidir reintentar archivos fallidos si el script de verificación auxiliar definido por la variable de configuración "checkneedretryindexscript" indica que esto debería suceder.

La opción --nopurge deshabilitará el borrado normal de documentos eliminados del índice. Esto puede ser útil en casos especiales (cuando se sabe que parte del conjunto de documentos es temporalmente inaccesible).

La opción -P forzará el pase de purga. Esto es útil solo si el parámetro idxnoautopurge está configurado en el archivo de configuración.

Si se proporciona la opción --diagsfile, la ruta dada como parámetro se truncará y se escribirán diagnósticos de indexación en ella. Cada línea del archivo tendrá un tipo de diagnóstico (motivo por el cual el archivo no se indexa), la ruta del archivo y una posible información adicional, que puede ser el tipo MIME o la ruta interna del archivo según el problema. Los siguientes tipos de diagnóstico están definidos actualmente:

Skipped: la ruta coincide con un elemento de skippedPaths o skippedNames.
NoContentSuffix: la extensión del nombre del archivo se encuentra en la lista noContentSuffixes.
MissingHelper: falta un programa auxiliar.
Error: error general (ver el registro).
NoHandler: no hay ningún manejador definido para el tipo MIME.
ExcludedMime: el tipo MIME forma parte de la lista excludedmimetypes.
NotIncludedMime: la lista onlymimetypes no está vacía y el tipo MIME no está en ella.

La opción -R permite especificar un archivo temporal para escribir mensajes de error en caso de fallo de indexación. Los mismos mensajes se envían a stderr, y la opción es principalmente útil para la GUI, para mostrar una ventana emergente de error.

Si se proporciona la opción -m, recollindex se inicia para la monitorización en tiempo real, utilizando el paquete de monitorización del sistema de archivos para el que fue configurado (inotify en linux, gamin en xBSD, fsevents en MacOS y ReadDirectoryChanges en Windows). El programa se desconectará normalmente de la terminal de control y se convertirá en un demonio. Si se proporciona la opción -D, permanecerá en primer plano. La opción -w <segundos> se puede usar para especificar que el programa debe dormir durante el tiempo especificado antes de que comience la indexación. El valor predeterminado es 60. El demonio normalmente monitoriza la sesión X11 y sale cuando se reinicia. Esto se puede deshabilitar con la opción -x  . Puede usar la opción -n para omitir el pase incremental inicial que normalmente se realiza antes de que comience la monitorización. Una vez que la monitorización comienza, el demonio monitoriza la configuración y se reinicia desde cero si se realiza un cambio. Puede deshabilitar esto con la opción -C  . La opción -O también mantiene el proceso en primer plano y, además, hará que el proceso salga si su proceso padre desaparece.

recollindex -i indexará archivos individuales en el índice. Las bases de datos de expansión de sufijos y aspell no se actualizarán. Se utilizarán las variables de configuración skippedPaths y skippedNames, para que algunos archivos puedan ser omitidos. Puede indicarle a recollindex que ignore skippedPaths y skippedNames estableciendo la opción -f. Esto permite una selección de archivos completamente personalizada para un subárbol dado, para el cual agregaría el directorio superior a skippedPaths y usaría cualquier herramienta personalizada para generar la lista de archivos (es decir, una herramienta de un sistema de control de código fuente). Cuando se ejecuta de esta manera, el indexador normalmente no realiza el pase de purga de archivos eliminados, ya que no puede estar seguro de haber visto todos los archivos existentes. Puede forzar un pase de purga con -P.

recollindex -e borrará datos de archivos individuales del índice. Las bases de datos de expansión de sufijos no se actualizarán.

Las opciones -i y -e se pueden combinar. Esto primero realizará la purga y luego la indexación.

Con las opciones -i o -e, si no se proporcionan nombres de archivo en la línea de comandos, se leerán desde stdin, de modo que podría, por ejemplo, ejecutar:

find /path/to/dir -print | recollindex -e -i

para forzar la reindexación de un árbol de directorios (que debe existir dentro del área del sistema de archivos definida por topdirs en recoll.conf). Podría lograr en gran medida lo mismo con

find /path/to/dir -print | recollindex -Z -i

Este último realizará un trabajo menos exhaustivo de purga de subdocumentos obsoletos.

recollindex -r funciona principalmente como -i, pero el parámetro es un solo directorio, que se actualizará recursivamente. Esto principalmente no hace nada más que find topdir | recollindex -i pero puede ser más conveniente de usar cuando se inicia desde otro programa. Esto reintenta los archivos fallidos por defecto, use la opción -K para cambiar. Se pueden usar una o varias opciones -p para establecer patrones de selección de tipo shell (por ejemplo: *.pdf).

recollindex -l listará los nombres de los stemmers de idioma disponibles.

recollindex -s construirá la base de datos de expansión de sufijos para un idioma dado, que puede o no formar parte de la lista en el archivo de configuración. Si el idioma no forma parte de la configuración, la base de datos de expansión de sufijos se eliminará al final de la próxima ejecución normal de indexación. Puede obtener la lista de nombres de stemmers del comando recollindex -l. Tenga en cuenta que esto es principalmente para uso experimental, la forma normal de agregar un idioma de stemming es configurarlo en la configuración, ya sea editando "recoll.conf" o utilizando el diálogo de configuración de indexación de la GUI.
En el momento de escribir esto, los siguientes idiomas son reconocidos (de Xapian's stem.h):

  • danish
  • dutch
  • english Martin Porter's 2002 revision of his stemmer
  • english_lovins Lovin's stemmer
  • english_porter Porter's stemmer as described in his 1980 paper
  • finnish
  • french
  • german
  • italian
  • norwegian
  • portuguese
  • russian
  • spanish
  • swedish

recollindex -S reconstruirá el índice fonético/ortográfico. Esta característica utiliza el paquete aspell, que debe estar instalado en el sistema.

recollindex -E verificará la existencia del archivo de configuración para topdirs y otras rutas relevantes (para ayudar a atrapar errores tipográficos).

recollindex --webcache-compact recuperará el espacio desperdiciado por las instancias de páginas borradas dentro de la caché Web. Puede necesitar temporalmente usar el doble del espacio en disco utilizado por la caché Web.

recollindex --webcache-burst <directorio_destino> extraerá todas las entradas de la caché Web a archivos creados dentro de <directorio_destino>. Cada entrada de caché se extrae como dos archivos, para los datos y metadatos.

recollindex --notindexed [ruta [ruta ...]] verificará cada ruta e imprimirá aquellas que están ausentes en el índice (con un prefijo "ABSENT"), o causaron

recollindex(1)

NAME

recollindex

command-line indexer for Recoll

SYNOPSIS

recollindex [-c] [-e] [-i] [-l N] [-n] [-p] [-q] [-r] [-s name] [-t] [-v] [-x] [path... ]

DESCRIPTION

This command is used to update the Recoll index. It can be run manually, or automatically from cron. The index is stored in $HOME/.recoll. The program will automatically detect which files need to be indexed (modified or deleted since the last run) and will perform the necessary operations. Use recollindex -h to get a full list of options.

The default behaviour is to index all monitored directories. This can take a long time. To speed up the process, you can specify a list of files or directories to index. The program will then only index the specified items and their subdirectories.

If no paths are given on the command line, the command will read them, one per line, from stdin. The paths must be absolute and consistent with those in the index, there is no attempt to be clever about them.

Interrupting the command: as indexing can sometimes take a long time, the command can be interrupted by sending an interrupt (Ctrl-C, SIGINT) or terminate (SIGTERM) signal. Some time may elapse before the process exits, because it needs to properly flush and close the index. This can also be done from the recoll GUI (menu entry: File/Stop_Indexing). After such an interruption, the index will be somewhat inconsistent because some operations which are normally performed at the end of the indexing pass will have been skipped (for example, the stemming and spelling databases will be inexistent or out of date). You just need to restart indexing at a later time to restore consistency. The indexing will restart at the interruption point (the full file tree will be traversed, but files that were indexed up to the interruption and for which the index is still up to date will not need to be reindexed).
