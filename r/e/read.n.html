read(n) Comandos integrados de Tcl read(n)

NOMBRE

read - Leer desde un canal

SINOPSIS

read ?-nonewline? canalId

read canalId numChars

DESCRIPCIÓN

En la primera forma, el comando read lee todos los datos del canalId hasta el final del archivo. Si se especifica la opción -nonewline, se descarta el último carácter del archivo si es una nueva línea. En la segunda forma, el argumento adicional especifica cuántos caracteres leer. Se leerán y devolverán exactamente esa cantidad de caracteres, a menos que queden menos de numChars en el archivo; en este caso, se devolverán todos los caracteres restantes. Si el canal está configurado para utilizar una codificación multibyte, el número de caracteres leídos puede no ser el mismo que el número de bytes leídos.

CanalId debe ser un identificador de un canal abierto, como el canal de entrada estándar de Tcl (stdin), el valor de retorno de una invocación de open o socket, o el resultado de un comando de creación de canal proporcionado por una extensión de Tcl. El canal debe haber sido abierto para entrada.

Si canalId está en modo no bloqueante, el comando puede no leer tantos caracteres como se solicitó: una vez que se ha leído toda la entrada disponible, el comando devolverá los datos disponibles en lugar de bloquearse para obtener más entrada. Si el canal está configurado para utilizar una codificación multibyte, puede haber algunos bytes restantes en los búferes internos que no forman un carácter completo. Estos bytes no se devolverán hasta que un carácter completo esté disponible o se alcance el final del archivo. La opción -nonewline se ignora si el comando devuelve antes de llegar al final del archivo.

Read traduce las secuencias de fin de línea en la entrada a caracteres de nueva línea según la opción -translation para el canal. Consulte la entrada del manual de fconfigure para ver una discusión sobre las formas en que fconfigure alterará la entrada.

USO CON PUERTOS SERIE

Para la mayoría de las aplicaciones, un canal conectado a un puerto serie debe configurarse como no bloqueante: fconfigure canalId -blocking 0. Entonces read se comporta de manera similar a la descrita anteriormente. Se debe tener cuidado al usar read en puertos serie bloqueantes:

read canalId numChars
En esta forma, read se bloquea hasta que se reciben numChars desde el puerto serie.
read canalId
En esta forma, read se bloquea hasta la recepción del carácter de fin de archivo; consulte fconfigure -eofchar. Si no se ha configurado ningún carácter de fin de archivo para el canal, entonces read se bloqueará para siempre.

EJEMPLO

Este código de ejemplo lee un archivo de una vez y lo divide en una lista, con cada línea del archivo correspondiente a un elemento de la lista:

set fl [open /proc/meminfo]
set data [read $fl]
close $fl
set lines [split $data \n]
