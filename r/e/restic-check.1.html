NOMBRE

restic-check - Comprueba el repositorio en busca de errores

SINOPSIS

restic check [flags]

DESCRIPCIÓN

El comando "check" prueba el repositorio en busca de errores e informa de cualquier error que encuentre. También se puede utilizar para leer todos los datos y, por lo tanto, simular una restauración.

Por defecto, el comando "check" siempre cargará todos los datos directamente desde el repositorio y no utilizará una caché local.

ESTADO DE SALIDA

El estado de salida es 0 si el comando se ejecutó correctamente. El estado de salida es 1 si hubo algún error. El estado de salida es 10 si el repositorio no existe. El estado de salida es 11 si el repositorio ya está bloqueado. El estado de salida es 12 si la contraseña es incorrecta.

OPCIONES

-h, --help[=false] Ayuda para check

--read-data[=false] lee todos los blobs de datos

--read-data-subset="" lee un subconjunto de paquetes de datos, especificado como 'n/t' para una parte específica, o 'x%' o 'x.y%' o un tamaño en bytes con sufijos k/K, m/M, g/G, t/T para un subconjunto aleatorio

--with-cache[=false] usa la caché existente, solo lee datos no cacheados del repositorio

OPCIONES HEREDADAS DE COMANDOS PADRE

--cacert=[] archivo desde el que cargar certificados raíz (por defecto: usar certificados del sistema o $RESTIC_CACERT)

--cache-dir="" establece el directorio de la caché. (por defecto: usar el directorio de caché predeterminado del sistema)

--cleanup-cache[=false] elimina automáticamente los directorios de caché antiguos

--compression=auto modo de compresión (solo disponible para la versión 2 del formato de repositorio), uno de (auto|off|max) (por defecto: $RESTIC_COMPRESSION)

--http-user-agent="" establece un agente de usuario http para las solicitudes http salientes

--insecure-no-password[=false] usa una contraseña vacía para el repositorio, debe pasarse a cada comando de restic (inseguro)

--insecure-tls[=false] omite la verificación del certificado TLS al conectarse al repositorio (inseguro)

--json[=false] establece el modo de salida a JSON para los comandos que lo admiten

--key-hint="" ID de clave de la clave a intentar descifrar primero (por defecto: $RESTIC_KEY_HINT)

--limit-download=0 limita las descargas a una tasa máxima en KiB/s. (por defecto: ilimitado)

--limit-upload=0 limita las subidas a una tasa máxima en KiB/s. (por defecto: ilimitado)

--no-cache[=false] no usa una caché local

--no-extra-verify[=false] omite la verificación adicional de datos antes de la subida (ver documentación)

--no-lock[=false] no bloquea el repositorio, esto permite algunas operaciones en repositorios de solo lectura

-o, --option=[] establece una opción extendida (key=value, se puede especificar varias veces)

--pack-size=0 establece el tamaño de paquete objetivo en MiB, los archivos de paquete creados pueden ser más grandes (por defecto: $RESTIC_PACK_SIZE)

--password-command="" comando shell para obtener la contraseña del repositorio de (por defecto: $RESTIC_PASSWORD_COMMAND)

-p, --password-file="" archivo desde el que leer la contraseña del repositorio (por defecto: $RESTIC_PASSWORD_FILE)

-q, --quiet[=false] no muestra un informe de progreso exhaustivo

-r, --repo="" repositorio al que realizar copia de seguridad o desde el que restaurar (por defecto: $RESTIC_REPOSITORY)

--repository-file="" archivo desde el que leer la ubicación del repositorio (por defecto: $RESTIC_REPOSITORY_FILE)

--retry-lock=0s intenta de nuevo bloquear el repositorio si ya está bloqueado, toma un valor como 5m o 2h (por defecto: sin reintentos)

--stuck-request-timeout=5m0s duración después de la cual se reintentarán las solicitudes atascadas

--tls-client-cert="" ruta a un archivo que contiene el certificado de cliente TLS codificado en PEM y la clave privada (por defecto: $RESTIC_TLS_CLIENT_CERT)

-v, --verbose[=0] sea detallado (especificar varias veces o un nivel usando --verbose=n, nivel/veces máximo es 2)
