FBB::ReadLineStream(3bobcat) Edición de líneas de entrada FBB::ReadLineStream(3bobcat)

NOMBRE

FBB::ReadLineStream - std::istream que ofrece edición de línea e historial

SINOPSIS

#include <bobcat/readlinestream>
Opción de enlace: -lbobcat -lreadline

DESCRIPCIÓN

Un objeto FBB::ReadLineStream es un objeto std::istream que permite la manipulación de la edición de líneas y el historial.

La clase ReadLineStream utiliza la biblioteca readline de Gnu para permitir la edición de las líneas de entrada. El objeto ReadLineStream se puede utilizar para construir un std::istream que permita la edición en línea de las líneas leídas desde la terminal. Todas las líneas pueden ir precedidas por un prompt configurable.

Dado que la biblioteca readline de Gnu opera sobre datos globales, solo puede haber un objeto ReadLineStream (y el subyacente ReadLineBuf). ReadLineStream es una clase singleton: en cualquier programa solo puede haber un objeto ReadLineStream.

ReadLineStream ofrece capacidades de edición mientras el usuario está introduciendo líneas. Al igual que la función readline(3) de Gnu, los comandos de edición de línea son, por defecto, similares a los de emacs(1), pero pueden reconfigurarse fácilmente, por ejemplo, para ofrecer características similares a las de vi(1).

La manipulación del historial se proporciona como una opción. El historial recopilado puede ser accedido para lectura mediante un objeto FBB::ReadLineHistory.

Se proporciona información específica sobre las instalaciones ofrecidas por el software Gnu utilizado por ReadLineStream en la documentación de la Biblioteca GNU Readline (http://cnswww.cns.cwru.edu/php/chet/readline/rltop.html).

La función readline de Gnu lee su información desde el archivo de entrada estándar. Los programas que utilizan ReadLineStream normalmente no deberían extraer información de std::cin. Sin embargo, como el archivo de entrada estándar tiene un descriptor de archivo (0), la redirección debería ser posible (por ejemplo, utilizando FBB::Redirector).

Cuando se mantiene la línea de comandos, se ofrece la expansión del historial como una opción. La expansión del historial introduce palabras de la lista de historial en el flujo de entrada, facilitando la repetición de comandos, la inserción de elementos de una línea de entrada anterior en la línea de entrada actual o la corrección de errores en líneas de comandos anteriores.

La expansión del historial se realiza normalmente inmediatamente después de que se lee una línea completa.

La línea seleccionada del historial se llama *evento*, y las porciones de esa línea que se procesan se llaman *palabras*. Se dispone de varios modificadores para manipular las palabras seleccionadas. Esto es comparable a la forma en que un programa como bash(1) divide su línea de entrada en "palabras".

La expansión del historial se introduce mediante el uso del carácter de expansión de historial, por defecto igual al carácter !. Solo la barra invertida (\) y las comillas simples pueden cambiar el carácter de expansión de historial a un carácter normal.

El resto de esta sección se copia casi textualmente de la página del manual de history(3). Se remite al lector a esa página del manual o a la documentación de la Biblioteca Gnu History para obtener más detalles.

Los siguientes descriptores de evento son compatibles:

o
!: inicia una sustitución de historial, excepto cuando va seguida de un espacio en blanco, nueva línea, = u (.
o
!n: se refiere a la línea de comandos n.
o
!-n: se refiere a la línea de comandos actual menos n.
o
!! se refiere al comando anterior. Es un sinónimo de `!-1’.
o
!string se refiere al comando más reciente que comienza con string.
o
!?string[?] se refiere al comando más reciente que contiene string. La ? final puede omitirse si string va seguida inmediatamente de una nueva línea.
o
^string1^string2^ (sustitución rápida) repite el último comando, reemplazando string1 con string2. Equivalente a !!:s/string1/string2/.
o
!# toda la línea de comandos escrita hasta el momento.

Descriptores de palabra

Los descriptores de palabra se utilizan para seleccionar palabras deseadas del evento. Un : separa la especificación del evento del descriptor de palabra. Puede omitirse si el descriptor de palabra comienza con ^, $, *, - o %. Las palabras se numeran desde el principio de la línea, siendo la primera palabra denotada por 0 (cero). Las palabras se insertan en la línea actual separadas por espacios simples.

o
0 (cero) La palabra cero. Para el shell, esta es la palabra del comando.
o
n La palabra n.
o
^ El primer argumento. Es decir, la palabra 1.
o
$ El último argumento.
o
% La palabra que coincide con la búsqueda ?string? más reciente.
o
x-y Un rango de palabras; `-y’ abrevia `0-y’.
o
* Todas las palabras excepto la cero. Es un sinónimo de 1-$. No es un error usar * si solo hay una palabra en el evento; en ese caso se devuelve la cadena vacía.
o
x* Abreviatura de x-$.
o
x- Abreviatura de x-$ como x*, pero omite la última palabra. Si se proporciona un descriptor de palabra sin una especificación de evento, se utiliza el comando anterior como evento.

Modificadores

Después del descriptor de palabra opcional, puede aparecer una secuencia de uno o más de los siguientes modificadores, cada uno precedido por un :.

o
h elimina un componente de nombre de archivo final, dejando solo la ruta.
o
t elimina todos los componentes de nombre de archivo iniciales, dejando el nombre de archivo.
o
r elimina una sufijo final del tipo .xxx, dejando el nombre base.
o
e elimina todo excepto el sufijo final.
o
p imprime el nuevo comando pero no lo ejecuta.
o
q antepone comillas a las palabras sustituidas, escapando sustituciones posteriores.
o
x antepone comillas a las palabras sustituidas como con q, pero divide en palabras en los espacios en blanco y nuevas líneas.
o
s/viejo/nuevo/ sustituye nuevo por la primera ocurrencia de viejo en la línea del evento. Cualquier delimitador puede usarse en lugar de /. El delimitador final es opcional si es el último carácter de la línea del evento. El delimitador puede ser escapado en viejo y nuevo con una barra invertida simple. Si & aparece en nuevo, se reemplaza por viejo. Una barra invertida simple escapará el &. Si viejo es nulo, se establece en el último viejo sustituido, o, si no han ocurrido sustituciones de historial previas, la última cadena en una búsqueda !?string[?].
o
& repite la sustitución anterior.
o
g hace que los cambios se apliquen a toda la línea del evento. Esto se utiliza junto con :s (por ejemplo, :gs/viejo/nuevo/) o :&. Si se usa con :s, cualquier delimitador puede usarse en lugar de /, y el delimitador final es opcional si es el último carácter de la línea del evento. Una a puede usarse como sinónimo de g.
o
G aplica el siguiente modificador s una vez a cada palabra en la línea del evento.

ESPACIO DE NOMBRES

FBB
Todos los constructores, miembros, operadores y manipuladores mencionados en esta página de manual, están definidos en el espacio de nombres FBB.

HEREDA DE

FBB::ReadLineBuf (privadamente), std::istream (públicamente)

ENUMERACIONES

La enum Type define los siguientes valores:

o
DONT_EXPAND_HISTORY: no se solicita la expansión del historial;
o
EXPAND_HISTORY: se solicita la expansión del historial.

La enum Expansion proporciona valores de retorno significativos para el proceso de expansión del historial. Sus valores son:

o
DONT_EXEC: la expansión del historial tuvo éxito, pero la línea expandida no debe ejecutarse. Por ejemplo, después de ingresar la línea 
    ls *
la línea 
    !!:p
debería hacer que el programa que la usa muestre, en lugar de ejecutar ls *. Tenga en cuenta que la interpretación de este valor de retorno de expansión no es tarea del objeto ReadLineBuf, sino del programa que utiliza el objeto ReadLineBuf.
o
ERROR: la expansión del historial falló. Ver también el miembro expansionError a continuación;
o
EXPANDED: la expansión del historial tuvo éxito;
o
NO_EXPANSION: no se realizó ninguna expansión del historial.

CONSTRUCTORES

Preámbulo: dado que solo puede haber un objeto ReadLineBuf, cualquier intento de definir un segundo objeto ReadLineStream fallará, ya que solo puede haber un único objeto ReadLineBuf en cualquier programa. Un intento de definir un segundo objeto ReadLineBuf genera una excepción logic_error.

o
ReadLineStream(std::string const &prompt = "", Type type = NO_EXPANSION):
Este constructor inicializa el objeto ReadLineStream con un prompt inicial, utilizando un historial de como máximo std::numeric_limits<int>::max() líneas, y por defecto no utiliza expansión del historial.
o
ReadLineStream(std::string const &prompt, size_t historySize, Type type = NO_EXPANSION):
Este constructor inicializa el ReadLineStream con un prompt inicial, un historial inicial de un tamaño máximo predefinido, y por defecto no utiliza expansión del historial. Especificar un tamaño de historial de 0 resulta en que no se guarda historial; cualquier valor igual o superior a la constante predefinida std::numeric_limits<int>::max() resulta en un historial de como máximo std::numeric_limits<int>::max() líneas. Si no se solicita historial pero se especifica type como EXPAND_HISTORY, se lanza una excepción logic_error.

Los constructores de copia y movimiento (y los operadores de asignación) no están disponibles.

FUNCIONES MIEMBRO

Todos los miembros de std::streambuf están disponibles, ya que FBB::ReadLineStream hereda de esta clase.

o
ReadLineStream::Expansion expansion() const:
Se devuelve el estado de la expansión del historial después de recuperar una línea de la terminal. Su valor se determina después de cada línea recuperada de la terminal. Si no se solicita expansión del historial, devuelve Expansion::ERROR.
o
std::string const &expansionError() const:
Se devuelve una descripción textual corta de la naturaleza del error cuando expansion devuelve Expansion::ERROR. Si no se solicita expansión del historial, se devuelve una cadena vacía.
o
bool setExpansion(Type type):
La expansión del historial se puede activar o detener utilizando este miembro. Cuando se solicita expansión del historial pero el objeto ReadLineStream no mantiene ningún historial, la función devuelve false. De lo contrario, devuelve true.
o
void setPrompt(std::string const &prompt = ""):
El prompt que se muestra delante de la siguiente línea leída de la terminal puede ser modificado por este miembro. Cuando se llama sin argumentos, no se mostrará ningún prompt. setPrompt se puede llamar mientras se están recibiendo líneas de entrada. El nuevo prompt estará activo después de que la línea actual haya sido leída de la terminal.
o
bool useTimestamps(std::string (*timestamp)() = 0):
Cuando se inicializa con la dirección de una función que devuelve un std::string, a los comandos ingresados se les asignará una marca de tiempo igual al texto devuelto por la función apuntada por timestamp. Las marcas de tiempo se pueden recuperar utilizando el objeto ReadLineHistory(3). Por defecto o después de pasar un puntero 0 explícito a useTimestamps, no se almacenan marcas de tiempo. El valor false se devuelve cuando no se mantiene historial, de lo contrario, se devuelve true.

EJEMPLO

#include <iostream>
#include <istream>
#include <cstdio>
#include <sstream>
#include <iomanip>
#include <bobcat/readlinestream>
using namespace std;
using namespace FBB;
int main()
{
    ReadLineStream in("", 10, ReadLineBuf::EXPAND_HISTORY);
    size_t count = 0;
    string line;
    while (true)
    {
        ostringstream prompt;
        prompt << setw(2) << ++count << ": ";
        in.setPrompt(prompt.str());
        if (!getline(in, line))          // usa el prompt configurado más recientemente
            break;
        cout << "Recuperado: " << line << "\n"
                "Estado de expansión: ";
        switch (in.expansion())
        {
            case ReadLineBuf::ERROR:
                cout << "ERROR: " << in.expansionError() << ’\n’;
            break;
            case ReadLineBuf::NO_EXPANSION:
                cout << "no se realizó expansión\n";
            break;
            case ReadLineBuf::DONT_EXEC:
                cout << "no ejecutar la línea expandida\n";
            break;
            case ReadLineBuf::EXPANDED:
                cout << "expansión realizada con éxito\n";
            break;
        }
    }
}
