remap_file_pages(2) Manual de llamadas al sistema remap_file_pages(2)

NOMBRE

remap_file_pages - crear un mapeo de archivo no lineal

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#define _GNU_SOURCE         /* Ver feature_test_macros(7) */
#include <sys/mman.h>
[[deprecated]] int remap_file_pages(size_t size;
                                    void addr[size], size_t size,
                                    int prot, size_t pgoff, int flags);

DESCRIPCIÓN

Nota: esta llamada al sistema fue marcada como obsoleta a partir de Linux 3.16. En Linux 4.0, la implementación fue reemplazada por una emulación en el kernel más lenta. Aquellas pocas aplicaciones que usan esta llamada al sistema deberían considerar migrar a alternativas. Este cambio se hizo porque el código del kernel para esta llamada al sistema era complejo, y se cree que se usa poco o quizás incluso no se usa en absoluto. Si bien tuvo algunos casos de uso en aplicaciones de bases de datos en sistemas de 32 bits, esos casos de uso no existen en sistemas de 64 bits.

La llamada al sistema remap_file_pages() se utiliza para crear un mapeo no lineal, es decir, un mapeo en el que las páginas del archivo se mapean en un orden no secuencial en la memoria. La ventaja de usar remap_file_pages() sobre el uso de llamadas repetidas a mmap(2) es que el primer enfoque no requiere que el kernel cree estructuras de datos adicionales de VMA (Área de Memoria Virtual).

Para crear un mapeo no lineal, realizamos los siguientes pasos:

1.
Usar mmap(2) para crear un mapeo (que inicialmente es lineal). Este mapeo debe crearse con la bandera MAP_SHARED.
2.
Usar una o más llamadas a remap_file_pages() para reorganizar la correspondencia entre las páginas del mapeo y las páginas del archivo. Es posible mapear la misma página de un archivo en múltiples ubicaciones dentro de la región mapeada.

Los argumentos pgoff y size especifican la región del archivo que se va a reubicar dentro del mapeo: pgoff es un desplazamiento de archivo en unidades del tamaño de página del sistema; size es la longitud de la región en bytes.

El argumento addr tiene dos propósitos. Primero, identifica el mapeo cuyas páginas queremos reorganizar. Por lo tanto, addr debe ser una dirección que caiga dentro de una región mapeada previamente por una llamada a mmap(2). Segundo, addr especifica la dirección en la que se colocarán las páginas del archivo identificadas por pgoff y size.

Los valores especificados en addr y size deben ser múltiplos del tamaño de página del sistema. Si no lo son, el kernel redondea *ambos* valores *hacia abajo* al múltiplo más cercano del tamaño de página.

El argumento prot debe especificarse como 0.

El argumento flags tiene el mismo significado que para mmap(2), pero se ignoran todas las banderas excepto MAP_NONBLOCK.

VALOR DE RETORNO

En caso de éxito, remap_file_pages() devuelve 0. En caso de error, devuelve -1 y se establece errno para indicar el error.

ERRORES

EINVAL
addr no se refiere a un mapeo válido creado con la bandera MAP_SHARED.
EINVAL
addr, size, prot, o pgoff son inválidos.

ESTÁNDARES

Linux.

HISTORIA

Linux 2.5.46, glibc 2.3.3.

NOTAS

Desde Linux 2.6.23, remap_file_pages() crea mapeos no lineales solo en sistemas de archivos en memoria como tmpfs(5), hugetlbfs o ramfs. En sistemas de archivos con un respaldo de almacenamiento, remap_file_pages() no es mucho más eficiente que usar mmap(2) para ajustar qué partes del archivo se mapean a qué direcciones.
