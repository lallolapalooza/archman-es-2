PROLOG

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

readonly — establecer el atributo de solo lectura para variables

SINOPSIS

readonly nombre[=palabra]...
readonly -p

DESCRIPCIÓN

A las variables cuyos nombres se especifican se les dará el atributo de solo lectura. Los valores de las variables con el atributo de solo lectura no pueden ser modificados por asignaciones posteriores, ni esas variables pueden ser eliminadas con la utilidad unset. Si el nombre de una variable va seguido de =palabra, entonces el valor de esa variable se establecerá en palabra.

El built-in especial readonly soportará el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de Sintaxis de Utilidad.

Cuando se especifica -p, readonly escribe en la salida estándar los nombres y valores de todas las variables de solo lectura, en el siguiente formato:

"readonly %s=%s\n", <nombre>, <valor>

si nombre está establecido, y

"readonly %s\n", <nombre>

si nombre no está establecido.

El shell formateará la salida, incluyendo el uso adecuado de las comillas, de modo que sea adecuada para ser reintroducida en el shell como comandos que logren el mismo valor y los resultados de establecimiento del atributo readonly en un entorno de ejecución del shell en el que:

1.
Las variables con valores en el momento en que se emitieron no tienen el atributo readonly establecido.
2.
Las variables que no estaban establecidas en el momento en que se emitieron no tienen un valor en el momento en que la salida guardada se reintroduce en el shell.

Cuando no se proporcionan argumentos, los resultados no están especificados.

FUNDAMENTO

Algunos shells históricos conservan el atributo readonly entre invocaciones separadas. Este volumen de POSIX.1‐2017 permite este comportamiento, pero no lo exige.

La opción -p permite el acceso portable a los valores que se pueden guardar y luego restaurar usando, por ejemplo, un script de punto. Consulte también el FUNDAMENTO de export para una descripción de los casos de salida sin argumentos y con -p, y un ejemplo relacionado.

Se consideraron las funciones de solo lectura, pero se omitieron por no ser práctica histórica o particularmente útil. Además, las funciones no deben ser de solo lectura entre invocaciones para evitar la "suplantación" (suplantación es el término para la práctica de crear un programa que actúa como una utilidad conocida con la intención de subvertir la intención real del usuario) de scripts de shell administrativos o relevantes para la seguridad (o conscientes de la seguridad).

manual readonly(1p)

READONLY(1p)

NOMBRE

readonly - marca variables y funciones como de solo lectura

SINOPSIS

readonly [nombre...]

DESCRIPCIÓN

Cuando se invoca sin argumentos, readonly escribirá en la salida estándar una lista de los nombres de todas las variables y funciones definidas actualmente que son de solo lectura, cada uno seguido de un salto de línea. Cuando se proporcionan argumentos, readonly marcará cada nombre especificado como de solo lectura. Las variables marcadas como de solo lectura no pueden ser modificadas ni eliminadas por el shell.

Se permitirá la marca de una función como de solo lectura si las funciones de solo lectura son soportadas por la implementación del shell; de lo contrario, el shell escribirá un mensaje de error indicando que no soporta esta característica.

Si un nombre de argumento es el nombre de una variable o función de solo lectura existente, readonly no producirá ninguna salida y el estado de salida será cero. Si un argumento es el nombre de una variable o función que no se puede marcar como de solo lectura (por ejemplo, debido a una limitación del sistema), se escribirá un mensaje de diagnóstico en el error estándar y el estado de salida será distinto de cero.

OPCIONES

No hay opciones soportadas.

OPERANDOS

Los siguientes operandos están disponibles:

nombre

Un nombre de variable o función a marcar como de solo lectura.

STDIN

No utilizado.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectan la ejecución de readonly:

POSIXLY_CORRECT

Si se establece, el comportamiento de readonly se adhiere a las secciones relevantes de la Base de Definiciones de Utilidades de POSIX. De lo contrario, el comportamiento puede ser más permisivo.

EVENTOS ASÍNCRONOS

Por defecto, readonly deshabilita la captura de señales de cambio de tamaño de ventana.

STDOUT

Cuando se invoca sin argumentos, readonly escribe la lista de variables y funciones de solo lectura en STDOUT.

STDERR

Se utiliza para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

0 si todos los nombre se marcaron correctamente como de solo lectura, o si no se proporcionaron argumentos. De lo contrario, distinto de cero.

CONSECUENCIAS DE LOS ERRORES

Si un nombre no se puede marcar como de solo lectura, se escribirá un mensaje de diagnóstico en STDERR y el estado de salida será distinto de cero. Sin embargo, el procesamiento de otros argumentos continuará.

USO DE LA APLICACIÓN

Ninguna.

EJEMPLOS

1. Para ver todas las variables y funciones de solo lectura:

readonly

2. Para marcar la variable my_var como de solo lectura:

readonly my_var

3. Para marcar varias variables como de solo lectura:

readonly var1 var2 var3

FUNDAMENTO

La utilidad readonly permite a los usuarios proteger ciertas variables y funciones de modificaciones accidentales o malintencionadas por parte del shell. Esto es particularmente útil en scripts donde se desea mantener la integridad de ciertos valores durante la ejecución.
