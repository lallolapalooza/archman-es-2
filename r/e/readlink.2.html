readlink(2) System Calls Manual readlink(2)

NOMBRE

readlink, readlinkat - leer el valor de un enlace simbólico

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
ssize_t readlink(const char *restrict path, char buf[restrict bufsiz], size_t bufsiz);
#include <fcntl.h>            /* Definición de constantes AT_* */
#include <unistd.h>
ssize_t readlinkat(int dirfd, const char *restrict path,
                 char buf[restrict bufsiz], size_t bufsiz);
Requisitos de Macro de Prueba de Funcionalidad para glibc (ver feature_test_macros(7)):

readlink():

    _XOPEN_SOURCE >= 500 || _POSIX_C_SOURCE >= 200112L
        || /* glibc <= 2.19: */ _BSD_SOURCE

readlinkat():

    Desde glibc 2.10:
        _POSIX_C_SOURCE >= 200809L
    Antes de glibc 2.10:
        _ATFILE_SOURCE

DESCRIPCIÓN

readlink() coloca el contenido del enlace simbólico path en el búfer buf, que tiene un tamaño de bufsiz. readlink() no añade un byte nulo de terminación a buf. (Silenciosamente) truncará el contenido (a una longitud de bufsiz caracteres), en caso de que el búfer sea demasiado pequeño para contener todo el contenido.

readlinkat()

La llamada al sistema readlinkat() opera de forma exactamente igual que readlink(), excepto por las diferencias descritas aquí.

Si path es relativo, entonces se interpreta en relación con el directorio al que se refiere el descriptor de archivo dirfd (en lugar de en relación con el directorio de trabajo actual del proceso que llama, como hace readlink() para una ruta de acceso relativa).

Si path es relativo y dirfd es el valor especial AT_FDCWD, entonces path se interpreta en relación con el directorio de trabajo actual del proceso que llama (como readlink()).

Si path es absoluto, entonces se ignora dirfd.

Desde Linux 2.6.39, path puede ser una cadena vacía, en cuyo caso la llamada opera sobre el enlace simbólico al que se refiere dirfd (que debería haber sido obtenido usando open(2) con las banderas O_PATH y O_NOFOLLOW).

Ver openat(2) para una explicación de la necesidad de readlinkat().

VALOR DE RETORNO

En caso de éxito, estas llamadas devuelven el número de bytes colocados en buf. (Si el valor devuelto es igual a bufsiz, entonces puede haber ocurrido truncamiento). En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EACCES
Se deniega el permiso de búsqueda para un componente del prefijo de ruta. (Ver también path_resolution(7)).
EBADF
(readlinkat()) path es relativo pero dirfd no es AT_FDCWD ni un descriptor de archivo válido.
EFAULT
buf se extiende fuera del espacio de direcciones asignado del proceso.
EINVAL
bufsiz no es positivo.
EINVAL
El archivo nombrado (es decir, el componente final del nombre de archivo de path) no es un enlace simbólico.
EIO
Ocurrió un error de E/S al leer del sistema de archivos.
ELOOP
Se encontraron demasiados enlaces simbólicos al traducir el nombre de ruta.
ENAMETOOLONG
Un nombre de ruta, o un componente de un nombre de ruta, era demasiado largo.
ENOENT
El archivo nombrado no existe.
ENOMEM
No había suficiente memoria del kernel disponible.
ENOTDIR
Un componente del prefijo de ruta no es un directorio.
ENOTDIR
(readlinkat()) path es relativo y dirfd es un descriptor de archivo que se refiere a un archivo que no sea un directorio.

ESTÁNDARES

POSIX.1-2024.

HISTORIA

readlink()
4.4BSD (apareció por primera vez en 4.2BSD), POSIX.1-2001, POSIX.1-2008.
readlinkat()
POSIX.1-2008. Linux 2.6.16, glibc 2.4.

Hasta e incluyendo glibc 2.4, el tipo de retorno de readlink() se declaraba como int. Hoy en día, el tipo de retorno se declara como ssize_t, como (recientemente) se requiere en POSIX.1-2001.

glibc

En kernels más antiguos donde readlinkat() no está disponible, la función envoltorio de glibc recurre al uso de readlink(). Cuando path es relativo, glibc construye un nombre de ruta basado en el enlace simbólico en /proc/self/fd que corresponde al argumento dirfd.

NOTAS

Usar un búfer de tamaño estático podría no proporcionar suficiente espacio para el contenido del enlace simbólico. El tamaño requerido para el búfer se puede obtener del valor stat.st_size devuelto por una llamada a lstat(2) sobre el enlace. Sin embargo, el número de bytes escritos por readlink() y readlinkat() debe verificarse para asegurarse de que el tamaño del enlace simbólico no aumentó entre las llamadas. Asignar dinámicamente el búfer para readlink() y readlinkat() también aborda un problema común de portabilidad al usar PATH_MAX para el tamaño del búfer, ya que esta constante no está garantizada que esté definida por POSIX si el sistema no tiene tal límite.

EJEMPLOS

El siguiente programa asigna dinámicamente el búfer necesario para readlink() a partir de la información proporcionada por lstat(2), recurriendo a un búfer de tamaño PATH_MAX en casos donde lstat(2) informa un tamaño de cero.

#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    char         *buf;
    ssize_t      nbytes, bufsiz;
    struct stat  sb;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s <path>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    if (lstat(argv[1], &sb) == -1) {
        perror("lstat");
        exit(EXIT_FAILURE);
    }
    /* Añadir uno al tamaño del enlace, para que podamos determinar si
       el búfer devuelto por readlink() fue truncado.  */
    bufsiz = sb.st_size + 1;
    /* Algunos enlaces mágicos bajo (por ejemplo) /proc y /sys
       reportan 'st_size' como cero.  En ese caso, tomar PATH_MAX como
       una estimación "lo suficientemente buena".  */
    if (sb.st_size == 0)
        bufsiz = PATH_MAX;
    buf = malloc(bufsiz);
    if (buf == NULL) {
        perror("malloc");
        exit(EXIT_FAILURE);
    }
    nbytes = readlink(argv[1], buf, bufsiz);
    if (nbytes == -1) {
        perror("readlink");
        exit(EXIT_FAILURE);
    }
    /* Imprimir el contenido del enlace simbólico.  */
    if (nbytes == bufsiz) {
        /* El búfer fue truncado.  Esto puede indicar un problema
           con la estimación del tamaño.  */
        fprintf(stderr, "Warning: buffer was truncated\n");
    }
    /* El contenido del enlace simbólico no está terminado por nulo,
       así que debemos hacerlo nosotros mismos antes de imprimirlo.  */
    buf[nbytes] = '\0';
    printf("%s\n", buf);
    exit(EXIT_SUCCESS);
}
