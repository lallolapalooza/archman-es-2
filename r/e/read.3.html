Descripción Detallada

Advertencia

Esto es para usuarios avanzados y expertos. No lo necesitas a menos que sepas realmente lo que estás haciendo. La mayoría de las aplicaciones no lo necesitarán.

Históricamente, PhysicsFS proporcionaba acceso al sistema de archivos físico y a los archivos dentro de ese sistema de archivos. Sin embargo, a veces se necesita más potencia que esto. Quizás necesites proporcionar un archivo que esté completamente contenido en RAM, o necesites conectar alguna otra API de E/S de archivos a PhysicsFS, o necesites traducir los bits (quizás tengas un archivo .zip estándar que esté cifrado, y necesites descifrarlo sobre la marcha para el descompresor zip desprevenido).

Un PHYSFS_Io es la interfaz que utilizan los Archiveros para obtener datos de archivos. Históricamente, esto se mapeaba a E/S de archivos al sistema de archivos físico, pero a partir de PhysicsFS 2.1, las aplicaciones pueden proporcionar sus propias implementaciones de E/S en tiempo de ejecución.

Esta interfaz no es necesariamente un buen ajuste universal para E/S. Hay algunos requisitos a tener en cuenta:

  • Solo realizan E/S bloqueante (al menos, por ahora).
  • Necesitan poder duplicarse. Si tienes un manejador de archivo de fopen(), necesitas poder crear un clon único de él (para que tengamos dos manejadores del mismo archivo que puedan buscar/leer/etc. sin interferir entre sí).
  • Necesitan conocer el tamaño de todo su conjunto de datos.
  • Necesitan poder buscar y rebobinar a demanda.

...en resumen, probablemente no escribirás una implementación HTTP.

Seguridad de hilos: Las implementaciones de PHYSFS_Io no garantizan ser seguras para hilos por sí mismas. Bajo el capó, donde PhysicsFS las utiliza, la biblioteca proporciona sus propios bloqueos. Si planeas usarlas directamente desde hilos separados, deberías usar mutexes para protegerlas, o no usar el mismo PHYSFS_Io desde dos hilos al mismo tiempo.

Documentación de Campos

void(* PHYSFS_Io::destroy) (struct PHYSFS_Io *io)

Limpiar y desasignar la instancia de E/S. Liberar los recursos asociados, incluido (opaque) si procede.

Esta función siempre debe tener éxito: como tal, devuelve void. El sistema puede llamar a tu método flush() antes de esto. Puedes informar de un error allí si es necesario. Este método aún puede ser llamado si flush() falla, en cuyo caso tendrás que abandonar los datos no vaciados y otras condiciones de fallo y limpiar.

Una vez que este método se llama para una instancia dada, el sistema asumirá que es inseguro tocar esa instancia de nuevo y descartará cualquier referencia a ella.

Parámetros

s La instancia de E/S a destruir.

struct PHYSFS_Io *(* PHYSFS_Io::duplicate) (struct PHYSFS_Io *io)

Duplicar esta instancia de E/S. Esto debe resultar en una copia completa de este PHYSFS_Io, que pueda vivir de forma completamente independiente. La copia debe ser capaz de realizar todas sus operaciones sin alterar la original, incluido que cada objeto pueda ser destruido por separado (así, por ejemplo: no pueden compartir un manejador de archivo; cada uno necesita el suyo).

Si no puedes duplicar un manejador, es legal devolver NULL, pero casi con certeza necesitarás esta funcionalidad si quieres usar este PHYSFS_Io para respaldar un archivo.

Parámetros

io La instancia de E/S a duplicar.

Retorna

Un nuevo valor para el campo (opaque) de un stream, o NULL en caso de error.

int(* PHYSFS_Io::flush) (struct PHYSFS_Io *io)

Vaciar recursos en medios, o donde sea. Esta es la oportunidad de informar de errores para escrituras que habían afirmado éxito anteriormente, pero que aún tenían la posibilidad de fallar. Este método puede ser NULL si el vaciado no es necesario.

Esta función puede ser llamada antes de destroy(), ya que puede informar de errores y destroy() no puede. También puede ser llamada en otros momentos.

Parámetros

io La instancia de E/S a vaciar.

Retorna

Cero en caso de error, distinto de cero en caso de éxito.

PHYSFS_sint64(* PHYSFS_Io::length) (struct PHYSFS_Io *io)

Determinar el tamaño del conjunto de datos de la instancia de E/S. Devolver el número de bytes disponibles en el archivo, o -1 si no se puede determinar. Un fallo casi seguramente será fatal para el uso posterior de este stream, por lo que no puedes dejar esto sin implementar.

Parámetros

io La instancia de E/S a consultar.

Retorna

Tamaño total, en bytes, del conjunto de datos.

void* PHYSFS_Io::opaque

Datos de instancia para esta estructura. Cada instancia tiene un puntero asociado que se puede usar para almacenar lo que se desee. Este puntero es por instancia del stream, por lo que presumiblemente cambiará al llamar a duplicate(). Esto puede desasignarse durante el método destroy().

PHYSFS_sint64(* PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buf, PHYSFS_uint64 len)

Leer más datos. Leer (len) bytes de la interfaz, en la posición actual de E/S, y almacenarlos en (buffer). La posición actual de E/S debería avanzar por el número de bytes leídos con éxito.

No tienes que implementar esto; establécelo a NULL si no se implementa. Esto solo se usará si el archivo se abre para lectura. Si se establece a NULL, se usará una implementación predeterminada que informa inmediatamente de un error.

Parámetros

io La instancia de E/S de la que leer.
buf El buffer para almacenar los datos. Debe tener al menos (len) bytes de longitud y no puede ser NULL.
len El número de bytes a leer de la interfaz.

Retorna

número de bytes leídos del archivo, 0 en EOF, -1 si el fallo es completo.

PHYSFS_sint64(* PHYSFS_Io::tell) (struct PHYSFS_Io *io)

Informar la posición actual de E/S. Devolver el número de bytes desde el principio del archivo hasta la posición actual de E/S.

Este método no debe ser NULL. Cualquier stream debe poder informar su posición actual.

Parámetros

io La instancia de E/S a consultar.

Retorna

La posición actual de E/S, en bytes, desde el inicio.

PHYSFS_uint32 version

Información de compatibilidad binaria. La biblioteca establece esto en el número de la estructura de la versión actual (actualmente 1) antes de pasarla a tu aplicación. Tu código debe verificar esto y negarse a funcionar si la versión no es la esperada.

PHYSFS_sint64(* PHYSFS_Io::write) (struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len)

Escribir más datos. Escribir (len) bytes del (buffer) en la interfaz, en la posición actual de E/S. La posición actual de E/S debería moverse según el número de bytes escritos con éxito.

No tienes que implementar esto; establécelo a NULL si no se implementa. Esto solo se usará si el archivo se abre para escritura. Si se establece a NULL, se usará una implementación predeterminada que informa inmediatamente de un error.

Parámetros

io La instancia de E/S en la que escribir.
buffer El buffer que contiene los datos a escribir. No puede ser NULL.
len El número de bytes a escribir en la interfaz.

Retorna

número de bytes escritos, o -1 si el fallo es completo.

NAME

PHYSFS_Io - interface for a block of data

SYNOPSIS

struct PHYSFS_Io {
PHYSFS_Io();
virtual ~PHYSFS_Io();
PHYSFS_sint64 (*close)(struct PHYSFS_Io *io);
PHYSFS_sint64 (*eof)(struct PHYSFS_Io *io);
PHYSFS_sint64 (*read)(struct PHYSFS_Io *io, void *buffer, PHYSFS_uint64 len);
PHYSFS_sint64 (*seek)(struct PHYSFS_Io *io, PHYSFS_sint64 offset);
PHYSFS_sint64 (*tell)(struct PHYSFS_Io *io);
PHYSFS_uint32 version;
PHYSFS_sint64 (*write)(struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len);
};

Detailed Description

This is a C++ wrapper for a file handle. It is used by the API for all file i/o. If you are writing your own archive or other i/o module, you will need to implement this structure.

Do not allocate this struct directly. Use PHYSFS_openWrite(), PHYSFS_openRead(), or PHYSFS_openAppend() instead.

Field Documentation

PHYSFS_sint64(* PHYSfs_Io::close) (struct PHYSFS_Io *io)

Close the file handle. Returns non-zero on success, zero on failure.

Parameters

io The i/o instance to close.

Returns

non-zero on success, zero on error.

PHYSFS_sint64(* PHYSFS_Io::eof) (struct PHYSFS_Io *io)

Check if the end of the file has been reached. Returns non-zero if the end of the file has been reached, zero otherwise.

Parameters

io The i/o instance to query.

Returns

non-zero if end-of-file has been reached, zero otherwise.

PHYSFS_sint64(* PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buffer, PHYSFS_uint64 len)

Read data from the file. Reads (len) bytes from the current i/o position into (buffer). The current i/o position will be advanced by the number of bytes successfully read.

You may return fewer bytes than requested, but you may not return a value that is less than zero unless it is a complete failure. You may not return a value that is zero unless EOF is reached, or a fatal error occurs. A return value of -1 will be treated as an error condition.

Parameters

io The i/o instance to read from.
buffer The buffer to read data into. It must be at least (len) bytes long and can't be NULL.
len The number of bytes to read from the i/o instance.

Returns

number of bytes read, or -1 if a fatal error occurred.

PHYSFS_sint64(* PHYSFS_Io::seek) (struct PHYSFS_Io *io, PHYSFS_sint64 offset)

Move the current i/o position. Moves the current i/o position to the specified byte offset. Returns non-zero on success, zero on failure.

Parameters

io The i/o instance to seek.
offset The new byte offset for the i/o position.

Returns

non-zero on success, zero on error.

PHYSFS_sint64(* PHYSFS_Io::tell) (struct PHYSFS_Io *io)

Report current i/o position. Return bytes offset, or -1 if you aren't able to determine. A failure will almost certainly be fatal to further use of this stream, so you may not leave this unimplemented.

Parameters

io The i/o instance to query.

Returns

The current byte offset for the i/o position, -1 if unknown.

PHYSFS_uint32 PHYSFS_Io::version

Binary compatibility information. This must be set to zero at this time. Future versions of this struct will increment this field, so we know what a given implementation supports. We'll presumably keep supporting older versions as we offer new features, though.

PHYSFS_sint64(* PHYSFS_Io::write) (struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len)

Write more data. Write (len) bytes from (buffer) to the interface at the current i/o position. The current i/o position should move ahead by the number of bytes successfully written.

You don't have to implement this; set it to NULL if not implemented. This will only be used if the file is opened for writing. If set to NULL, a default implementation that immediately reports failure will be used.

You are allowed to buffer; a write can succeed here and then later fail when flushing. Note that PHYSFS_setBuffer() may be operating a level above your i/o, so you should usually not implement your own buffering routines.

Parameters

io The i/o instance to write to.
buffer The buffer to read data from. It must be at least (len) bytes long and can't be NULL.
len The number of bytes to read from (buffer).

Returns

number of bytes written to file, -1 if complete failure.
