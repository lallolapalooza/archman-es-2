readahead(2) Manual de llamadas al sistema readahead(2)

NOMBRE

readahead - iniciar prelectura de archivo en la caché de páginas

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#define _GNU_SOURCE             /* Ver feature_test_macros(7) */
#define _FILE_OFFSET_BITS 64
#include <fcntl.h>
ssize_t readahead(int fd, off_t offset, size_t count);

DESCRIPCIÓN

readahead() inicia la prelectura en un archivo para que las lecturas posteriores de ese archivo se satisfagan desde la caché y no se bloqueen en E/S de disco (suponiendo que la prelectura se inició lo suficientemente pronto y que otras actividades en el sistema no hayan vaciado las páginas de la caché mientras tanto).

El argumento fd es un descriptor de archivo que identifica el archivo que se va a leer. El argumento offset especifica el punto de inicio desde el cual se van a leer los datos y count especifica el número de bytes a leer. La E/S se realiza en páginas completas, por lo que offset se redondea efectivamente hacia abajo a un límite de página y se leen bytes hasta el siguiente límite de página mayor o igual a (offset+count). readahead() no lee más allá del final del archivo. El desplazamiento del archivo de la descripción de archivo a la que hace referencia el descriptor de archivo fd no se modifica.

VALOR DE RETORNO

En caso de éxito, readahead() devuelve 0; en caso de error, devuelve -1 y errno se establece para indicar el error.

ERRORES

EBADF
fd no es un descriptor de archivo válido o no está abierto para lectura.
EINVAL
fd no se refiere a un tipo de archivo al que se pueda aplicar readahead().

VERSIÓNES

En algunas arquitecturas de 32 bits, la firma de llamada para esta llamada al sistema difiere, por las razones descritas en syscall(2).

ESTÁNDARES

Linux.

HISTORIA

Linux 2.4.13, glibc 2.3.

NOTAS

_FILE_OFFSET_BITS debe definirse como 64 en el código que utiliza un puntero a readahead, si el código está destinado a ser portable a plataformas x86 y ARM tradicionales de 32 bits donde el ancho de off_t es de 32 bits por defecto.

ERRORES DE PROGRAMACIÓN

readahead() intenta programar las lecturas en segundo plano y devolver inmediatamente. Sin embargo, puede bloquearse mientras lee los metadatos del sistema de archivos necesarios para localizar los bloques solicitados. Esto ocurre con frecuencia con ext[234] en archivos grandes que utilizan bloques indirectos en lugar de extents, dando la apariencia de que la llamada se bloquea hasta que se leen los datos solicitados.

VER TAMBIÉN

lseek(2), madvise(2), mmap(2), posix_fadvise(2), read(2)
