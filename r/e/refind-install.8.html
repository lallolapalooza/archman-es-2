NOMBRE

refind-install - Instala rEFInd en la ESP y crea una entrada NVRAM

SINOPSIS

refind-install [--notesp | --usedefault archivo-dispositivo | --root punto-montaje | --ownhfs archivo-dispositivo ][--keepname] [--nodrivers | --alldrivers] [--shim nombre-archivo-shim] [--localkeys] [--encryptkeys] [--yes]

DESCRIPCIÓN

Para ser útil, el gestor de arranque rEFInd debe instalarse en la Partición del Sistema EFI (ESP) del ordenador o en otra ubicación accesible por EFI. En la mayoría de los casos, también se debe crear una entrada NVRAM que describa la ubicación de rEFInd. Estos pasos se pueden realizar manualmente; sin embargo, el comando refind-install proporciona una forma automatizada de realizar estas tareas tanto en Linux como en OS X. El comportamiento exacto y las opciones varían según el sistema operativo.

Algunos detalles que pueden afectar a cómo se ejecuta el script incluyen los siguientes:

*
Si ejecuta el script como un usuario normal, intenta obtener privilegios de root utilizando el comando sudo. Esto funciona en Mac OS X y en algunas instalaciones de Linux (como en Ubuntu o si se ha añadido a la lista de usuarios de sudo), pero en algunas instalaciones de Linux esto fallará. En tales sistemas, debe ejecutar refind-install como root.
*
En OS X, puede ejecutar el script con un ratón abriendo una sesión de Terminal y luego arrastrando y soltando el archivo refind-install en la ventana del Terminal. Necesitará presionar la tecla Retorno o Enter para ejecutar el script.
*
Si está utilizando la función de Cifrado de Disco Completo (WDE) de OS X 10.7, o la función de volúmenes lógicos en OS X 10.10, debe instalar rEFInd en la ESP o en una partición HFS+ separada. El valor predeterminado en rEFInd 0.8.4 y posteriores es instalar en la ESP. Si prefiere usar un volumen HFS+ separado, se requiere la opción --ownhfs archivo-dispositivo para refind-install.
*
Si no está utilizando WDE o volúmenes lógicos, puede instalar rEFInd en la partición raíz (/) de OS X utilizando la opción --notesp para refind-install. Se recomienda usar esta opción al actualizar desde una instalación de rEFInd que funcione en esta ubicación.
*
Si está reemplazando rEFIt con rEFInd en un Mac, existe la posibilidad de que refind-install le advierta sobre la presencia de un programa llamado /Library/StartupItems/rEFItBlesser y le pregunte si desea eliminarlo. Este programa está diseñado para mantener rEFIt como gestor de arranque bendiciéndolo automáticamente si el gestor de arranque predeterminado cambia. Esto es obviamente indeseable si instala rEFInd como su gestor de arranque principal, por lo que generalmente es mejor eliminar este programa. Si prefiere mantener sus opciones abiertas, puede responder N cuando refind-install pregunte si desea eliminar rEFItBlesser, y en su lugar copiarlo manualmente a otro lugar. Si posteriormente decide volver a usar rEFIt como su gestor de arranque principal, puede restaurar rEFItBlesser a su lugar.
*
Si tiene la intención de arrancar sistemas basados en BIOS en un PC basado en UEFI, debe editar la línea scanfor del archivo refind.conf para habilitar las búsquedas relevantes. Esto no es necesario en los Mac; debido a la popularidad de los arranques duales con Windows en los Mac, las búsquedas de BIOS/legado están habilitadas por defecto en los Mac.
*
En Linux, refind-install verifica el tipo de sistema de archivos del directorio /boot y, si hay un controlador de sistema de archivos coincidente disponible, lo instala. Tenga en cuenta que el "directorio /boot" puede estar en una partición separada o puede ser parte de su sistema de archivos raíz (/), en cuyo caso se instala el controlador para su sistema de archivos raíz. Es poco probable que esta característica funcione correctamente desde un sistema de emergencia, aunque podría funcionar si tiene una partición /boot separada y si monta esa partición en /boot en su sistema de emergencia, y la ESP en /boot/efi.
*
En OS X, refind-install verifica sus tablas de particiones en busca de signos de una instalación de Linux. Si se encuentra un signo de este tipo, el script instala el controlador de sistema de archivos EFI para el sistema de archivos ext4 de Linux. Esto permitirá a rEFInd leer su kernel de Linux si está en un sistema de archivos ext2, ext3 o ext4. Tenga en cuenta que algunas configuraciones requerirán un archivo /boot/refind_linux.conf, que solo se puede generar de manera confiable en Linux. (El script mkrlconf que viene con rEFInd realizará esta tarea una vez que haya arrancado Linux). Mientras tanto, puede lanzar GRUB desde rEFInd o presionar F2 o Insertar dos veces después de resaltar la opción de Linux en rEFInd. Esto le permitirá ingresar una especificación root=/dev/loquesea, donde /dev/loquesea es el identificador del dispositivo de su sistema de archivos raíz (/) de Linux.
*
Si ejecuta refind-install en Linux y si /boot/refind_linux.conf aún no existe, refind-install crea este archivo y lo rellena con algunas entradas de ejemplo. Si /boot está en una partición FAT (o HFS+ en un Mac), o si está en una partición ext2fs, ext3fs, ext4fs, ReiserFS, Btrfs o HFS+ y instala un controlador apropiado, el resultado es que rEFInd detectará su kernel y probablemente lo arrancará correctamente. Sin embargo, algunos sistemas requerirán ajustes manuales en refind_linux.conf, por ejemplo, para agregar dolvm a las opciones de arranque en sistemas Gentoo que usan LVM.
*
Si pasa la opción --shim al script (junto con un nombre de archivo para un binario Shim), el script se configura para una configuración de Arranque Seguro a través de Shim. Por defecto, esto hace que el binario rEFInd se renombre como grubx64.efi. Las versiones recientes de Shim admiten pasar el nombre del programa posterior a Shim a través de un parámetro. Si desea utilizar esta función, puede pasar la opción --keepname a refind-install.

Después de ejecutar refind-install, debe revisar la salida del script para asegurarse de que todo parezca correcto. refind-install muestra mensajes de error cuando encuentra errores, como si la ESP estuviera montada en modo de solo lectura o si se queda sin espacio en disco. Es posible que deba corregir dichos problemas manualmente y volver a ejecutar el script. En algunos casos, puede que necesite recurrir a la instalación manual, lo que le da un mejor control sobre detalles como qué partición usar para la instalación.

OPCIONES

--notesp
Esta opción, que solo es válida en OS X, indica a refind-install que instale rEFInd en la partición raíz de OS X en lugar de en la ESP. Este comportamiento era el predeterminado en rEFInd 0.8.3 y anteriores, por lo que puede desear usarlo al actualizar instalaciones de esa versión, a menos que haya usado --esp (que ahora es el comportamiento predeterminado, aunque la opción --esp ya no existe) o --ownhfs. También puede desear usar --notesp en nuevas instalaciones si está seguro de que no está utilizando cifrado de disco completo o volúmenes lógicos.
--usedefault archivo-dispositivo
Puede instalar rEFInd en un disco utilizando el nombre de archivo predeterminado/de reserva EFI/BOOT/bootx64.efi (así como EFI/BOOT/bootia32.efi y EFI/BOOT/bootaa64.efi, si las compilaciones IA-32 y ARM64 están disponibles) utilizando esta opción. El archivo-dispositivo debe ser una ESP sin montar, o al menos una partición FAT, como en --usedefault /dev/sdc1. Las entradas NVRAM de su ordenador no se modificarán al instalar de esta manera. La intención es que pueda crear una unidad flash USB de arranque o instalar rEFInd en un ordenador que tiende a "olvidar" su configuración NVRAM con esta opción. Esta opción es mutuamente excluyente con --notesp y --root.
--ownhfs archivo-dispositivo
Esta opción solo debe usarse en OS X. Se utiliza para instalar rEFInd en un volumen HFS+ distinto de un volumen de arranque Mac estándar. El resultado debería ser que rEFInd aparezca en el propio gestor de arranque de Mac. Más importante aún, las operaciones de suspensión a RAM pueden funcionar correctamente. Tenga en cuenta que esta opción requiere un volumen HFS+ que no sea actualmente un volumen de arranque de OS X. Puede ser un volumen de datos o una partición rEFInd dedicada. La ESP también podría funcionar, si se convierte para usar HFS+; sin embargo, HFS+ es un sistema de archivos no estándar para una ESP, por lo que no se recomienda.

refind-install(8)

NOMBRE

refind-install - Instalar el gestor de arranque rEFInd

SINOPSIS

refind-install [opciones]

DESCRIPCIÓN

El script refind-install es un script de shell que simplifica la instalación del gestor de arranque rEFInd. Se puede usar para instalar rEFInd en una partición ESP (EFI System Partition) o en una partición de datos separada, para instalarlo en una unidad externa o CD/DVD, o para facilitar la instalación en sistemas con arranque seguro (Secure Boot).

El script intenta detectar automáticamente la ubicación de la partición ESP (generalmente montada en /boot/efi en Linux y en el directorio EFI del disco de arranque en OS X). Si detecta la ESP, copia los archivos necesarios de rEFInd a la partición ESP y configura las variables NVRAM para arrancar rEFInd.

Si el script no puede detectar la ESP o si desea instalar rEFInd en una ubicación diferente, puede especificar manualmente el punto de montaje de la ESP o de la partición de datos utilizando la opción --mount-point.

El script también puede usarse para crear un CD/DVD de arranque de rEFInd o para instalar rEFInd en un dispositivo USB.

Opciones

--mount-point punto-montaje
Esta opción se utiliza para instalar rEFInd en una partición que no sea la ESP estándar, por ejemplo, una partición de datos separada o un CD/DVD de arranque. Se debe montar la instalación regular en /punto-montaje, incluyendo el directorio /boot (si está separado) en /punto-montaje/boot y (en Linux) la ESP en esa ubicación o en /punto-montaje/boot/efi. El script refind-install instala entonces rEFInd en la ubicación apropiada; en Linux, /punto-montaje/boot/EFI/refind o /punto-montaje/boot/efi/EFI/refind, dependiendo de dónde haya montado la ESP. En OS X, esta opción solo es útil junto con --notesp, en cuyo caso rEFInd se instalará en /punto-montaje/EFI/refind. El script también agrega una entrada en la NVRAM para rEFInd en esta ubicación. No se puede usar esta opción con --usedefault. Tenga en cuenta que esta opción no es necesaria al realizar una instalación de arranque dual Linux/OS X; simplemente instale normalmente en OS X.
--nodrivers
Normalmente, refind-install intenta instalar el controlador necesario para leer /boot en Linux. Este intento solo funciona si se está utilizando ext2fs, ext3fs, ext4fs, ReiserFS o Btrfs en la partición relevante. Si desea omitir la instalación de este controlador, pase la opción --nodrivers. Esta opción es implícita cuando se usa --usedefault.
--alldrivers
Al especificar esta opción, refind-install copia todos los archivos de controlador para su arquitectura. Es posible que desee eliminar los archivos de controlador no utilizados después de usar esta opción. Tenga en cuenta que algunos ordenadores se bloquean o no funcionan con ningún controlador si utiliza esta opción, así que úsela con precaución.
--shim nombre-archivo-shim o --preloader nombre-archivo-preloader
Si pasa esta opción a refind-install, el script copiará el archivo del programa shim especificado al directorio de destino, copiará el archivo MokManager.efi del directorio del archivo del programa shim al directorio de destino, copiará la versión de 64 bits de rEFInd como grubx64.efi y registrará shim con el firmware. (Si también especifica --usedefault, el registro de NVRAM se omite. Si también usa --keepname, el cambio de nombre a grubx64.efi se omite). Cuando el archivo de destino se identifica como PreLoader, ocurre algo muy similar, pero refind-install copia HashTool.efi en lugar de MokManager.efi y copia rEFInd como loader.efi en lugar de como grubx64.efi. La intención es simplificar la instalación de rEFInd en un ordenador que utiliza arranque seguro (Secure Boot); cuando se configura de esta manera, rEFInd arrancará en modo de arranque seguro, con una advertencia: la primera vez que arranque, se iniciará MokManager/HashTool, y deberá usarlo para localizar e instalar una clave pública o registrar rEFInd como una aplicación confiable. El archivo de clave pública de rEFInd se encontrará en el subdirectorio keys del directorio rEFInd con el nombre refind.cer.
--localkeys
Esta opción indica a refind-install que genere una nueva Clave de Propietario de Máquina (MOK), la almacene en /etc/refind.d/keys como refind_local.* y vuelva a firmar todos los binarios de rEFInd de 64 bits con esta clave antes de instalarlos. Esta es la forma preferible de instalar rEFInd en modo de arranque seguro, ya que significa que sus binarios se firmarán localmente en lugar de con mi clave, que se utiliza para firmar los binarios de muchos otros usuarios; sin embargo, este método requiere que los binarios openssl y sbsign estén instalados. El primero está fácilmente disponible en los repositorios de la mayoría de las distribuciones, pero el segundo no lo está, por lo que esta opción no es la predeterminada.
--encryptkeys
Normalmente, si utiliza la opción --localkeys, refind-install almacena los archivos de clave locales en su disco duro sin cifrar. Por lo tanto, si su ordenador se ve comprometido, el intruso podría usar su propia clave para firmar un cargador de arranque modificado, eliminando los beneficios del arranque seguro. Si utiliza esta opción, la clave privada se almacena en forma cifrada, protegida mediante una contraseña de cifrado. Debe introducir esta contraseña antes de que la clave pueda utilizarse para firmar cualquier binario, lo que reduce el riesgo de que un intruso pueda secuestrar su proceso de arranque. Obviamente, esta es una opción muy deseable, pero la desventaja es que debe recordar la contraseña e introducirla cada vez que actualice rEFInd o cualquier otro programa firmado con su clave privada. Esto también hace que una actualización completamente automatizada de rEFInd sea imposible.
--keepname
Esta opción solo es útil en conjunción con --shim. Le dice a refind-install que mantenga el nombre de archivo regular de rEFInd (típicamente refind_x64.efi) cuando se usa con shim, en lugar de renombrar el binario a grubx64.efi. Este cambio reduce la posibilidad de confusión debido a problemas con los nombres de archivo; sin embargo, esta función requiere que shim se inicie con un parámetro de línea de comandos que apunte al binario de rEFInd con su nombre real. Las versiones de shim anteriores a la 0.7 no admiten correctamente esta función. (La versión 0.4 la admite pero con una interpretación errónea de la especificación del cargador de seguimiento). Si sus variables NVRAM se corrompen o se olvidan, esta función puede hacer que rEFInd sea más difícil de iniciar. Esta opción es incompatible con --usedefault y no está disponible cuando se ejecuta en OS X o sin la opción --shim. Si el script detecta una instalación de rEFInd existente en EFI/BOOT o EFI/Microsoft/Boot y ninguna otra instalación de rEFInd cuando se utiliza esta opción, se abortará.
--yes
Esta opción hace que el script asuma una entrada de S (Sí) a cada indicación de sí/no que pueda generarse bajo ciertas condiciones, como si especifica --shim pero refind-install no detecta ninguna evidencia de una instalación de arranque seguro. Esta opción está destinada principalmente a ser utilizada por scripts, como los que podrían usarse como parte de una instalación a través de un paquete RPM o Debian.
