RENICE(1) Comandos de usuario RENICE(1)

NOMBRE

renice - alterar la prioridad de los procesos en ejecución

SINOPSIS

renice [--priority|--relative] prioridad [-g|-p|-u] identificador...

DESCRIPCIÓN

renice altera la prioridad de planificación de uno o más procesos en ejecución. El primer argumento es el valor de prioridad a utilizar. Los demás argumentos se interpretan como ID de proceso (por defecto), ID de grupo de procesos, ID de usuario o nombres de usuario. Hacer renice a un grupo de procesos hace que todos los procesos del grupo tengan alterada su prioridad de planificación. Hacer renice a un usuario hace que todos los procesos propiedad del usuario tengan alterada su prioridad de planificación.

Si no se utiliza la opción -n, --priority o --relative, la prioridad se establece como absoluta.

OPCIONES

-n prioridad

Especifica la prioridad de planificación absoluta o relativa (dependiendo de la variable de entorno POSIXLY_CORRECT) a utilizar para el proceso, grupo de procesos o usuario. El uso de la opción -n es opcional, pero cuando se usa, debe ser el primer argumento. Consulte NOTAS para más información.

--priority prioridad

Especifica una prioridad de planificación absoluta. La prioridad se establece al valor dado. Este es el valor por defecto, cuando no se especifica ninguna opción.

--relative prioridad

Especifica una prioridad de planificación relativa. Igual que la opción estándar POSIX -n. La prioridad se incrementa/decrementa según el valor dado.

-g, --pgrp

Interpreta los argumentos siguientes como ID de grupo de procesos.

-p, --pid

Interpreta los argumentos siguientes como ID de proceso (por defecto).

-u, --user

Interpreta los argumentos siguientes como nombres de usuario o UID.

-h, --help

Muestra el texto de ayuda y sale.

-V, --version

Muestra la versión y sale.

ARCHIVOS

/etc/passwd

para mapear nombres de usuario a IDs de usuario

NOTAS

Los usuarios distintos del superusuario solo pueden alterar la prioridad de los procesos que poseen. Además, un usuario no privilegiado solo puede aumentar el valor de "nice" (es decir, elegir una prioridad más baja) y tales cambios son irreversibles a menos que (desde Linux 2.6.12) el usuario tenga un límite de recursos de "nice" adecuado (consulte ulimit(1p) y getrlimit(2)).

El superusuario puede alterar la prioridad de cualquier proceso y establecer la prioridad a cualquier valor en el rango de -20 a 19. Prioridades útiles son: 19 (los procesos afectados solo se ejecutarán cuando nada más en el sistema quiera), 0 (la prioridad de planificación "base"), cualquier valor negativo (para hacer que las cosas vayan muy rápido).

Por razones históricas en esta implementación, la opción -n no seguía la especificación POSIX. Por lo tanto, en lugar de establecer una prioridad relativa, establece una prioridad absoluta por defecto. Dado que esto puede no ser deseable, este comportamiento se puede controlar estableciendo la variable de entorno POSIXLY_CORRECT para que sea totalmente compatible con POSIX. Consulte la opción -n para obtener detalles. Consulte --relative y --priority para opciones que no cambian el comportamiento dependiendo de las variables de entorno.

HISTORIA

El comando renice apareció en 4.0BSD.

EJEMPLOS

El siguiente comando cambiaría la prioridad de los procesos con PIDs 987 y 32, más todos los procesos propiedad de los usuarios daemon y root:

renice +1 987 -u daemon root -p 32
