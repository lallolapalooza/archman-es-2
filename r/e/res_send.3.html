DESCRIPCIÓN

Nota: Esta página está incompleta (varias funciones del resolver proporcionadas por glibc no se describen) y probablemente desactualizada.

Las funciones descritas a continuación realizan consultas a los servidores de nombres de dominio de Internet e interpretan sus respuestas.

La API consta de un conjunto de funciones más modernas y reentrantes, y un conjunto más antiguo de funciones no reentrantes que han sido sustituidas. Las interfaces tradicionales del resolver como res_init() y res_query() utilizan algún estado estático (global) almacenado en la estructura _res, lo que hace que estas funciones no sean seguras para hilos. BIND 8.2 introdujo un conjunto de nuevas interfaces res_ninit(), res_nquery(), y así sucesivamente, que toman un res_state como su primer argumento, permitiendo usar un estado del resolver por hilo.

Las funciones res_ninit() y res_init() leen los archivos de configuración (ver resolv.conf(5)) para obtener el nombre de dominio predeterminado y la(s) dirección(es) del servidor de nombres. Si no se proporciona ningún servidor, se intenta con el host local. Si no se proporciona ningún dominio, se utiliza el asociado al host local. Puede ser anulado por la variable de entorno LOCALDOMAIN. Normalmente, res_ninit() o res_init() se ejecutan con la primera llamada a una de las otras funciones. Cada llamada a res_ninit() requiere una llamada correspondiente a res_nclose() para liberar la memoria asignada por res_ninit() y las llamadas posteriores a res_nquery().

Las funciones res_nquery() y res_query() consultan al servidor de nombres para el nombre de dominio completamente calificado name del type y class especificados. La respuesta se deja en el búfer answer de longitud anslen proporcionado por el llamante.

Las funciones res_nsearch() y res_search() realizan una consulta y esperan la respuesta como res_nquery() y res_query(), pero además implementan las reglas predeterminadas y de búsqueda controladas por RES_DEFNAMES y RES_DNSRCH (ver la descripción de las opciones de _res más abajo).

Las funciones res_nquerydomain() y res_querydomain() realizan una consulta utilizando res_nquery()/res_query() sobre la concatenación de name y domain.

Las siguientes funciones son rutinas de bajo nivel utilizadas por res_nquery()/res_query().

Las funciones res_nmkquery() y res_mkquery() construyen un mensaje de consulta en buf de longitud buflen para el nombre de dominio dname. El tipo de consulta op es uno de los siguientes (típicamente QUERY):

QUERY
Consulta estándar.
IQUERY
Consulta inversa. Esta opción se eliminó en glibc 2.26, ya que no ha sido soportada por los servidores DNS durante mucho tiempo.
NS_NOTIFY_OP
Notificar al secundario del cambio de SOA (Start of Authority).

newrr no se utiliza actualmente.

La función res_nsend() y res_send() envían una consulta preformateada dada en msg de longitud msglen y devuelven la respuesta en answer, que tiene una longitud anslen. Llamarán a res_ninit()/res_init() si aún no se ha llamado.

La función dn_comp() comprime el nombre de dominio exp_dn y lo almacena en el búfer comp_dn de longitud length. La compresión utiliza un array de punteros dnptrs a nombres previamente comprimidos en el mensaje actual. El primer puntero apunta al principio del mensaje y la lista termina con NULL. El límite del array se especifica mediante lastdnptr. Si dnptr es NULL, los nombres de dominio no se comprimen. Si lastdnptr es NULL, la lista de etiquetas no se actualiza.

DESCRIPCIÓN

Las rutinas de resolución utilizan información de configuración y estado contenida en una estructura __res_state (ya sea pasada como argumento statep, o en la variable global _res, en el caso de las funciones no reentrantes más antiguas). El único campo de esta estructura que normalmente manipula el usuario es el campo options. Este campo puede contener el ""OR"" a nivel de bits de las siguientes opciones:

RES_INIT
Verdadero si se ha llamado a res_ninit() o res_init().
RES_DEBUG
Imprimir mensajes de depuración. Esta opción solo está disponible si glibc se compiló con la depuración habilitada, lo cual no es el valor predeterminado.
RES_AAONLY (no implementado; obsoleto en glibc 2.25)
Aceptar solo respuestas autorizadas. res_send() continúa hasta que encuentra una respuesta autorizada o devuelve un error. Esta opción estuvo presente pero no implementada hasta glibc 2.24; desde glibc 2.25, está obsoleta y su uso produce una advertencia.
RES_USEVC
Usar conexiones TCP para consultas en lugar de datagramas UDP.
RES_PRIMARY (no implementado; obsoleto en glibc 2.25)
Consultar solo el servidor de nombres de dominio principal. Esta opción estuvo presente pero no implementada hasta glibc 2.24; desde glibc 2.25, está obsoleta y su uso produce una advertencia.
RES_IGNTC
Ignorar errores de truncamiento. No volver a intentar con TCP.
RES_RECURSE
Establecer el bit de recursión deseada en las consultas. La recursión es llevada a cabo por el servidor de nombres de dominio, no por res_send(). [Habilitado por defecto].
RES_DEFNAMES
Si está establecido, res_search() agregará el nombre de dominio predeterminado a los nombres de un solo componente, es decir, aquellos que no contienen un punto. [Habilitado por defecto].
RES_STAYOPEN
Se usa con RES_USEVC para mantener la conexión TCP abierta entre consultas.
RES_DNSRCH
Si está establecido, res_search() buscará nombres de host en el dominio actual y en los dominios padre. Esta opción es utilizada por gethostbyname(3). [Habilitado por defecto].
RES_INSECURE1
Aceptar una respuesta de un servidor incorrecto. Esto puede usarse para detectar posibles riesgos de seguridad, pero necesitas compilar glibc con la depuración habilitada y usar la opción RES_DEBUG (solo con fines de depuración).
RES_INSECURE2
Aceptar una respuesta que contenga una consulta incorrecta. Esto puede usarse para detectar posibles riesgos de seguridad, pero necesitas compilar glibc con la depuración habilitada y usar la opción RES_DEBUG (solo con fines de depuración).
RES_NOALIASES
Deshabilitar el uso de la variable de entorno HOSTALIASES.
RES_USE_INET6
Intentar una consulta AAAA antes que una consulta A dentro de la función gethostbyname(3), y mapear respuestas IPv4 en forma de "túnel" IPv6 si no se encuentran registros AAAA pero existe un conjunto de registros A. Desde glibc 2.25, esta opción está obsoleta y su uso produce una advertencia; las aplicaciones deben usar getaddrinfo(3), en lugar de gethostbyname(3).
RES_ROTATE
Causa la selección de servidores de nombres en orden cíclico entre los listados. Esto tiene el efecto de distribuir la carga de consultas entre todos los servidores listados, en lugar de que todos los clientes intenten el primer servidor listado cada vez.
RES_NOCHECKNAME (no implementado; obsoleto en glibc 2.25)
Deshabilitar la verificación moderna de BIND de nombres de host y nombres de correo entrantes en busca de caracteres inválidos como guion bajo (_), no ASCII o caracteres de control. Esta opción estuvo presente hasta glibc 2.24; desde glibc 2.25, está obsoleta y su uso produce una advertencia.
RES_KEEPTSIG (no implementado; obsoleto en glibc 2.25)
No eliminar los registros TSIG. Esta opción estuvo presente pero no implementada hasta glibc 2.24; desde glibc 2.25, está obsoleta y su uso produce una advertencia.
RES_BLAST (no implementado; obsoleto en glibc 2.25)
Enviar cada consulta simultáneamente y recursivamente a todos los servidores. Esta opción estuvo presente pero no implementada hasta glibc 2.24; desde glibc 2.25, está obsoleta y su uso produce una advertencia.
RES_USEBSTRING (glibc 2.3.4 a glibc 2.24)
Realizar búsquedas inversas de IPv6 utilizando el formato de etiqueta de bits descrito en RFC 2673; si esta opción no está establecida (lo cual es el valor predeterminado), se utiliza el formato nibble. Esta opción se eliminó en glibc 2.25, ya que dependía de una extensión DNS incompatible con versiones anteriores que nunca se desplegó en Internet.
RES_NOIP6DOTINT (glibc 2.24 y anteriores)
Utilizar la zona ip6.arpa en la búsqueda inversa de IPv6 en lugar de ip6.int, que está obsoleta desde glibc 2.3.4. Esta opción está presente hasta e incluyendo glibc 2.24, donde está habilitada por defecto. En glibc 2.25, esta opción se eliminó.
RES_USE_EDNS0 (desde glibc 2.6)
Habilita el soporte para las extensiones DNS (EDNS0) descritas en RFC 2671.
RES_SNGLKUP (desde glibc 2.10)
Por defecto, glibc realiza búsquedas IPv4 e IPv6 en paralelo desde glibc 2.9. Algunos servidores DNS de electrodomésticos no pueden manejar estas consultas correctamente y hacen que las solicitudes expiren. Esta opción deshabilita el comportamiento y hace que glibc realice las solicitudes IPv6 e IPv4 secuencialmente (a costa de cierta ralentización del proceso de resolución).
RES_SNGLKUPREOP
Cuando la opción RES_SNGLKUP está habilitada, abre un nuevo socket para cada solicitud.
RES_USE_DNSSEC
Usar DNSSEC con el bit OK en el registro OPT. Esta opción implica RES_USE_EDNS0.
RES_NOTLDQUERY
No buscar el nombre no calificado como un dominio de nivel superior (TLD).
RES_DEFAULT
Opción predeterminada que implica: RES_RECURSE, RES_DEFNAMES, RES_DNSRCH y RES_NOIP6DOTINT.

VALOR DE RETORNO

Las funciones res_ninit() y res_init() devuelven 0 en caso de éxito, o -1 si ocurre un error.

Las funciones res_nquery(), res_query(), res_nsearch(), res_search(), res_nquerydomain(), res_querydomain(), res_nmkquery(), res_mkquery(), res_nsend() y res_send() devuelven la longitud de la respuesta, o -1 si ocurre un error.

Las funciones dn_comp() y dn_expand() devuelven la longitud del nombre comprimido, o -1 si ocurre un error.

En caso de un retorno de error de res_nquery(), res_query(), res_nsearch(), res_search(), res_nquerydomain() o res_querydomain(), la variable global h_errno (ver gethostbyname(3)) puede ser consultada para determinar el error.
