rebuilderd.conf(5) Manual de Formatos de Archivo rebuilderd.conf(5)

NOMBRE

rebuilderd.conf - Archivos de configuración de rebuilderd y rebuildctl

SINOPSIS

/etc/rebuilderd.conf

~/.config/rebuilderd.conf

DESCRIPCIÓN

Este archivo contiene la configuración tanto para rebuilderd como para rebuildctl.

OPCIONES

[http]

bind_addr=

La dirección a la que enlazar. Por defecto es 127.0.0.1:8484.

real_ip_header=

Si utilizas un proxy inverso, usa esta cabecera en lugar de la IP de conexión real. Asegúrate de que el proxy inverso tenga filtros implementados para evitar problemas de suplantación. No hay valor por defecto, pero se recomienda usar "X-Real-IP".

endpoint=

Establece un punto final (endpoint) por defecto para rebuildctl. Esto es especialmente útil para el temporizador de sincronización. Por defecto es http://127.0.0.1:8484.

[auth]

cookie=

Una cookie aleatoria para autenticar administradores. Si este valor no está establecido, rebuilderd generará una por sí mismo y la escribirá en /var/lib/rebuilderd/auth-cookie. Solo necesitas configurar esto si quieres administrar de forma remota.

https://rebuilder.example.com__">[endpoints."https://rebuilder.example.com"]

cookie=

Esta sección generalmente solo se configura en ~/.config/rebuilderd.conf. Permite establecer cookies para instancias de rebuilderd alternativas con -H. El valor pasado por -H debe coincidir exactamente con el encabezado de la sección, asegúrate de que no haya barras finales.

[worker]

authorized_workers=

Lista blanca de la clave pública de las instancias de rebuilderd-worker. Consulta la sección de autenticación en rebuilderd(1) para más detalles.

signup_secret=

Configura un secreto compartido que un rebuilderd-worker debe proporcionar para poder unirse. Consulta la sección de autenticación en rebuilderd(1) para más detalles.

[schedule]

retry_delay_base=

Configura el retardo para reintentar automáticamente las reconstrucciones fallidas en horas. Por defecto es 24h, esta base se multiplica por el número de reconstrucciones, por lo que el primer reintento ocurrirá después de 24h, el segundo reintento ocurrirá 48h después del primer reintento y el tercer reintento ocurrirá 72h después del segundo reintento. No hay un límite superior de reintentos. Si no puedes permitirte reintentos frecuentes, se recomienda establecer este valor a uno alto como 168 (1 semana) o superior. Las reconstrucciones exitosas no se reintentan.

EJEMPLO

## Configuración para el demonio http
#[http]
## La dirección a la que enlazar. Por defecto es 127.0.0.1:8484.
#bind_addr = "0.0.0.0:8484"
## Si utilizas un proxy inverso, usa esta cabecera en lugar de la IP de conexión real.
## Asegúrate de que el proxy inverso tenga filtros implementados para evitar problemas de suplantación.
#real_ip_header = "X-Real-IP"
## Establece un punto final por defecto para rebuildctl. Esto es especialmente útil para el temporizador de sincronización.
#endpoint = "http://127.0.0.1:8484"
## Una cookie aleatoria para la administración se genera al inicio y se escribe en /var/lib/rebuilderd/auth-cookie
## Puedes establecerla a un valor fijo aquí. Usa `pwgen -1s 32` para generar una.
## rebuildctl busca esta cookie en ~/.config/rebuilderd.conf, /etc/rebuilderd.conf y
## /var/lib/rebuilderd/auth-cookie en ese orden.
#[auth]
#cookie = "INSECURE"
## La cookie de autenticación anterior solo se usa para el punto final por defecto.
## Puedes usar diferentes puntos finales con `rebuildctl -H https://rebuilder.example.com status`,
## En ese caso, necesitas configurar una sección a continuación si quieres adjuntar una cookie.
#[endpoints."https://rebuilder.example.com"]
#cookie = "INSECURE"
## IMPORTANTE: en producción, asegúrate de que `authorized_workers` o `signup_secret` estén configurados.
#[worker]
## Si tenemos un conjunto fijo de trabajadores, podemos permitir la entrada de claves aquí.
#authorized_workers = ["key1", "key2"]
## Si queremos generar nuevos trabajadores dinámicamente, podemos configurar un secreto de registro a continuación.
## Usa `pwgen -1s 32` para generar uno.
#signup_secret = "INSECURE"
#[schedule]
## Configura el retardo para reintentar automáticamente las reconstrucciones fallidas en horas.
## El valor por defecto es 24h, esta base se multiplica por el número de reconstrucciones, por lo que el
## primer reintento ocurrirá después de 24h, el segundo reintento ocurrirá 48h después del
## primer reintento y el tercer reintento ocurrirá 72h después del segundo reintento. No hay
## límite superior de reintentos, si no puedes permitirte reintentos frecuentes, es
## recomendable establecer un valor alto como 168 (1 semana) o superior.
## Las reconstrucciones exitosas no se reintentan.
#retry_delay_base = 24
