reboot(2) Manual de Llamadas al Sistema reboot(2)

NOMBRE

reboot - reiniciar o habilitar/deshabilitar Ctrl-Alt-Del

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

/* Desde Linux 2.1.30 existen nombres simbólicos LINUX_REBOOT_*
   para las constantes y un cuarto argumento a la llamada: */
#include <linux/reboot.h>  /* Definición de las constantes LINUX_REBOOT_* */
#include <sys/syscall.h>   /* Definición de las constantes SYS_* */
#include <unistd.h>
int syscall(SYS_reboot, int magic, int magic2, int op, void *arg);
/* Bajo glibc y la mayoría de libc alternativas (incluyendo uclibc, dietlibc,
   musl y otras), algunas de las constantes involucradas han obtenido
   nombres simbólicos RB_*, y la llamada a la biblioteca es un envoltorio de 1 argumento
   para la llamada al sistema: */
#include <sys/reboot.h>    /* Definición de las constantes RB_* */
#include <unistd.h>
int reboot(int op);

DESCRIPCIÓN

La llamada reboot() reinicia el sistema, o habilita/deshabilita la combinación de teclas de reinicio (CAD, por sus siglas en inglés; la predeterminada es Ctrl-Alt-Delete; se puede cambiar usando loadkeys(1)).

Esta llamada al sistema falla (con el error EINVAL) a menos que magic sea igual a LINUX_REBOOT_MAGIC1 (es decir, 0xfee1dead) y magic2 sea igual a LINUX_REBOOT_MAGIC2 (es decir, 0x28121969). Sin embargo, desde Linux 2.1.17 también se permiten LINUX_REBOOT_MAGIC2A (es decir, 0x05121996) y desde Linux 2.1.97 también LINUX_REBOOT_MAGIC2B (es decir, 0x16041998) y desde Linux 2.5.71 también LINUX_REBOOT_MAGIC2C (es decir, 0x20112000) como valores para magic2. (Los valores hexadecimales de estas constantes tienen significado.)

El argumento op puede tener los siguientes valores:

LINUX_REBOOT_CMD_CAD_OFF
(RB_DISABLE_CAD, 0). CAD se deshabilita. Esto significa que la combinación de teclas CAD enviará una señal SIGINT a init (proceso 1), y este proceso podrá decidir la acción apropiada (quizás: matar todos los procesos, sincronizar, reiniciar).
LINUX_REBOOT_CMD_CAD_ON
(RB_ENABLE_CAD, 0x89abcdef). CAD se habilita. Esto significa que la combinación de teclas CAD realizará inmediatamente la acción asociada con LINUX_REBOOT_CMD_RESTART.
LINUX_REBOOT_CMD_HALT
(RB_HALT_SYSTEM, 0xcdef0123; desde Linux 1.1.76). Se imprime el mensaje "System halted." y el sistema se detiene. Se cede el control al monitor ROM, si lo hay. Si no va precedido de un sync(2), se perderán datos.
LINUX_REBOOT_CMD_KEXEC
(RB_KEXEC, 0x45584543, desde Linux 2.6.13). Ejecuta un kernel que ha sido cargado previamente con kexec_load(2). Esta opción está disponible solo si el kernel fue configurado con CONFIG_KEXEC.
LINUX_REBOOT_CMD_POWER_OFF
(RB_POWER_OFF, 0x4321fedc; desde Linux 2.1.30). Se imprime el mensaje "Power down.", el sistema se detiene y se corta toda la energía al sistema, si es posible. Si no va precedido de un sync(2), se perderán datos.
LINUX_REBOOT_CMD_RESTART
(RB_AUTOBOOT, 0x1234567). Se imprime el mensaje "Restarting system." y se realiza un reinicio predeterminado inmediatamente. Si no va precedido de un sync(2), se perderán datos.
LINUX_REBOOT_CMD_RESTART2
(0xa1b2c3d4; desde Linux 2.1.30). Se imprime el mensaje "Restarting system with command '%s'" y se realiza un reinicio (usando la cadena de comando dada en arg) inmediatamente. Si no va precedido de un sync(2), se perderán datos.
LINUX_REBOOT_CMD_SW_SUSPEND
(RB_SW_SUSPEND, 0xd000fce1; desde Linux 2.5.18). El sistema se suspende (hiberna) en disco. Esta opción está disponible solo si el kernel fue configurado con CONFIG_HIBERNATION.

Solo el superusuario puede llamar a reboot().

El efecto exacto de las acciones anteriores depende de la arquitectura. Para la arquitectura i386, el argumento adicional no hace nada actualmente (2.1.122), pero el tipo de reinicio puede determinarse mediante argumentos de línea de comandos del kernel ("reboot=...") para que sea cálido o frío, y ya sea duro o a través de la BIOS.

Comportamiento dentro de namespaces PID

Desde Linux 3.4, si se llama a reboot() desde un namespace PID diferente al namespace PID inicial con uno de los valores de op listados a continuación, realiza un "reinicio" de ese namespace: el proceso "init" del namespace PID se termina inmediatamente, con los efectos descritos en pid_namespaces(7).

Los valores que se pueden suministrar en op al llamar a reboot() en este caso son los siguientes:

LINUX_REBOOT_CMD_RESTART
LINUX_REBOOT_CMD_RESTART2
El proceso "init" se termina, y wait(2) en el proceso padre informa que el hijo fue eliminado con una señal SIGHUP.
LINUX_REBOOT_CMD_POWER_OFF
LINUX_REBOOT_CMD_HALT
El proceso "init" se termina, y wait(2) en el proceso padre informa que el hijo fue eliminado con una señal SIGINT.

Para los demás valores de op, reboot() devuelve -1 y errno se establece en EINVAL.

VALOR DE RETORNO

Para los valores de op que detienen o reinician el sistema, una llamada exitosa a reboot() no regresa. Para los demás valores de op, se devuelve cero si hay éxito. En todos los casos, se devuelve -1 si hay un fallo, y errno se establece para indicar el error.

ERRORES

EFAULT
Problema al obtener datos del espacio de usuario bajo LINUX_REBOOT_CMD_RESTART2.
EINVAL
Números mágicos o op incorrectos.
EPERM
El proceso llamante no tiene privilegios suficientes para llamar a reboot(); el llamante debe tener la CAP_SYS_BOOT dentro de su namespace de usuario.

ESTANDARES

Linux.
