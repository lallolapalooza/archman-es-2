REQUEST-KEY.CONF(5) Utilidades de gestión de claves de Linux REQUEST-KEY.CONF(5)

NOMBRE

request-key.conf - Archivo de configuración del manejador de instanciación

DESCRIPCIÓN

Estos archivos son utilizados por el programa /sbin/request-key para determinar qué programa debe ejecutar para instanciar una clave.

request-key busca la mejor coincidencia, leyendo todos los siguientes archivos:

/etc/request-key.d/*.conf
/etc/request-key.conf

Si no encuentra una coincidencia, devolverá un error y el kernel negará automáticamente la clave.

La mejor coincidencia se define como la línea con los saltos de comodín más cortos, clasificando las columnas en orden de izquierda a derecha. Si dos líneas tienen la misma longitud de saltos, se tomará la primera leída.

En los archivos, cualquier línea en blanco o línea que comience con un signo de almohadilla '#' se considera un comentario y se ignora.

Todas las demás líneas se asumen como líneas de comando con un número de campos separados por espacios en blanco:

<op> <tipo> <descripción> <info-llamada> <prog> <arg1> <arg2> ...

Los cuatro primeros campos se utilizan para hacer coincidir los parámetros pasados a request-key por el kernel. op es el tipo de operación; actualmente la única operación soportada es "create".

tipo, descripción e info-llamada coinciden con los tres parámetros pasados a keyctl request2 o a la llamada al sistema request_key(). Cada uno de estos puede contener un asterisco '*' como comodín en cualquier lugar dentro de la cadena.

Si se produce una coincidencia, el programa especificado por <prog> será ejecutado (exec'd). Este debe tener un nombre de ruta completamente calificado. argv[0] se establecerá a partir de la parte del nombre del programa que sigue al último carácter de barra '/'.

Si el nombre del programa va precedido de una barra vertical '|', el programa se bifurcará y ejecutará conectado a tres pipes. La información de llamada se enviará a través de stdin y los datos de carga útil previstos se obtendrán de stdout. Cualquier cosa enviada a stderr se publicará en syslog. Si el programa sale con 0, entonces /sbin/request-key intentará instanciar la clave con los datos leídos de stdout. Si falla de cualquier otra manera, request-key intentará ejecutar el comando de operación de 'negación' apropiado.

Los argumentos del programa pueden ser sustituidos por varias macros. Solo se admite la sustitución completa de argumentos; las sustituciones de macros no se pueden incrustar. Todas las macros comienzan con un signo de porcentaje '%'. A un argumento que comience con dos signos de porcentaje se le descartará uno de ellos.

Las siguientes macros son soportadas:

%o Tipo de operación
%k ID de clave
%t Tipo de clave
%d Descripción de la clave
%c Información de llamada
%u UID de clave
%g GID de clave
%T Keyring del hilo solicitante
%P Keyring del proceso solicitante
%S Keyring de sesión del solicitante

También existe otra sustitución de macros que permite la interpolación del contenido de una clave:

%{ <tipo>:<descripción> }

Esto realiza una búsqueda de una clave del tipo y descripción dados en los keyrings del solicitante, y si se encuentra, sustituye el contenido por la macro. Si no se encuentra, se registrará un error y la clave en construcción será negada.

EJEMPLO

Se instalará un archivo básico en /etc. Este contendrá dos líneas de depuración que se pueden utilizar para probar la instalación:

create user debug:* negate /bin/keyctl negate %k 30 %S
create user debug:loop:* * |/bin/cat
create user debug:* * /usr/share/keyutils/request-key-debug.sh %k %d %c %S
negate * * * /bin/keyctl negate %k 30 %S

Esto está configurado para que algo como:

keyctl request2 user debug:xxxx negate

creará una clave definida por el usuario negativa, algo como:

keyctl request2 user debug:yyyy spoon

creará una clave definida por el usuario instanciada con "Debug spoon" como carga útil, y algo como:

keyctl request2 user debug:loop:zzzz abcdefghijkl

creará una clave definida por el usuario instanciada con la información de llamada como carga útil.
