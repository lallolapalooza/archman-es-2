RENICE(1P) Manual del Programador POSIX RENICE(1P)

PROLOG

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

renice — establecer valores de nice de procesos en ejecución

SINOPSIS

renice [-g|-p|-u] -n incremento ID...

DESCRIPCIÓN

La utilidad renice solicitará que se cambien los valores de nice (consulte la definición de Valor de Nice en el volumen de Definiciones Base de POSIX.1‐2017, Sección 3.244) de uno o más procesos en ejecución. Por defecto, los procesos aplicables se especifican por sus IDs de proceso. Cuando se especifica un grupo de procesos (consulte -g), la solicitud se aplicará a todos los procesos del grupo.

El valor de nice estará limitado dentro de un rango definido por la implementación. Si el incremento solicitado eleva o reduce el valor de nice de la utilidad ejecutada más allá de los límites definidos por la implementación, se utilizará el límite cuyo valor se excedió.

Cuando un usuario es objeto de renice, la solicitud se aplica a todos los procesos cuyo ID de usuario guardado coincida con el ID de usuario correspondiente al usuario.

Independientemente de las opciones especificadas o de cualquier otro factor, renice no alterará los valores de nice de ningún proceso a menos que el usuario que solicita dicho cambio tenga los privilegios apropiados para hacerlo para el proceso especificado. Si el usuario carece de los privilegios apropiados para realizar la acción solicitada, la utilidad devolverá un estado de error.

Se comprobará el ID de usuario guardado del proceso del usuario en lugar de su ID de usuario efectivo cuando renice intente determinar el ID de usuario del proceso para determinar si el usuario tiene los privilegios apropiados.

OPCIONES

La utilidad renice cumplirá con las directrices de sintaxis de utilidad del volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, excepto por la Directriz 9.

Se admitirán las siguientes opciones:

-g
Interpreta los siguientes operandos como IDs de grupo de procesos enteros decimales sin signo.
-n incremento
Especifica cómo se debe ajustar el valor de nice del proceso o procesos especificados. El argumento de opción incremento es un entero decimal positivo o negativo que se utilizará para modificar el valor de nice del proceso o procesos especificados.

Los valores de incremento positivos harán que el valor de nice sea menor. Los valores de incremento negativos pueden requerir privilegios apropiados y harán que el valor de nice sea mayor.

-p
Interpreta los siguientes operandos como IDs de proceso enteros decimales sin signo. La opción -p es la predeterminada si no se especifican opciones.
-u
Interpreta los siguientes operandos como usuarios. Si existe un usuario con un nombre de usuario igual al operando, se utilizará el ID de usuario de ese usuario en el procesamiento posterior. De lo contrario, si el operando representa un entero decimal sin signo, se utilizará como el ID de usuario numérico del usuario.

OPERANDOS

Se admitirán los siguientes operandos:

ID
Un ID de proceso, ID de grupo de procesos o nombre/ID de usuario, según la opción seleccionada.

ENTRADA ESTÁNDAR

No se utiliza.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de renice:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de configuración regional).
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la configuración regional para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en los argumentos).
LC_MESSAGES

Determina la configuración regional que se debe utilizar para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida estándar de error.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Predeterminado.

SALIDA ESTÁNDAR

No se utiliza.

SALIDA DE ERROR ESTÁNDAR

La salida de error estándar se utilizará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
Finalización exitosa.
>0
Ocurrió un error.

CONSECUENCIAS DE ERRORES

Predeterminado.

Las siguientes secciones son informativas.

USO DE APLICACIÓN

Ninguno.

EJEMPLOS

1.
Ajustar el valor de nice para que los IDs de proceso 987 y 32 tengan un valor de nice menor:
renice -n 5 -p 987 32
2.
Ajustar el valor de nice para que los IDs de grupo 324 y 76 tengan un valor de nice mayor, si el usuario tiene los privilegios apropiados para hacerlo:
renice -n -4 -g 324 76
3.
Ajustar el valor de nice para que el ID de usuario numérico 8 y el usuario sas tengan un valor de nice menor:
renice -n 4 -u 8 sas

Los incrementos de valor de nice útiles en sistemas históricos incluyen 19 o 20 (los procesos afectados se ejecutan solo cuando nada más en el sistema intenta ejecutarse) y cualquier número negativo (para hacer que los procesos se ejecuten más rápido).

RAZONAMIENTO

Las especificaciones gid, pid y user no encajan ni en la definición de operando ni en la de argumento de opción. Sin embargo, para mayor claridad, se han incluido en la sección OPCIONES, en lugar de en la sección OPERANDOS.

La definición de valor de nice no pretende sugerir que todos los procesos de un sistema tengan prioridades comparables. Las extensiones de la política de planificación, como las prioridades en tiempo real en el volumen de Interfaces del Sistema de POSIX.1‐2017, hacen que la noción de una única prioridad subyacente para todas las políticas de planificación sea problemática. NAME

renice — alter priority of running processes

SYNOPSIS

renice [priority] [-p pid...] [-g gid...] [-u user...]

DESCRIPTION

The renice utility shall read a list of process IDs, process groups, or users and alter the system scheduling priority of the specified processes.

The priority argument shall be a decimal integer. By default, renice shall operate on the processes specified by the process IDs given on the command line. If the process IDs are omitted, renice shall operate on the process specified by the process ID specified with the -p option.

A lower priority number indicates a higher priority. The range of valid priorities is implementation-defined, but shall include at least the range [-20, 20].

A process can only increase its own priority (lower the nice value) up to the system's maximum priority level. A process can only decrease its own priority (increase the nice value) down to the system's minimum priority level. The system administrator can change the priority of any process.

If no explicit priority is given, the first argument is assumed to be the priority.

When renice is used to change the priority of a process, it is allowed to decrease its own priority (lower the nice value) to the system's maximum priority level. It is allowed to increase its own priority (higher the nice value) only to the system's minimum priority level. A process that is not a privileged user is allowed to decrease its own priority (lower the nice value) only to the system's maximum priority level. The system administrator is allowed to change the priority of any process.

A privileged user is a user with appropriate privileges to change the priority of any process. On systems that implement the getpriority() and setpriority() functions, this is typically the same as the privileged user defined for that system (for example, the user with the effective user ID of 0).

If the priority argument is omitted, the default value of 10 shall be used.

The behavior of renice can be affected by the following implementation-defined method:

The system scheduling priority of a process is adjusted by adding the difference between the new nice value and the old nice value.

OPTIONS

The renice utility shall conform to the Base Definitions volume of POSIX.1-2017, Section 12.2, Utility Syntax Guidelines.

The following options shall be supported:

-g
Specify that the following arguments represent process group IDs.
-p
Specify that the following arguments represent process IDs.
-u
Specify that the following arguments represent user names or user IDs.

If none of the -p, -g, or -u options are specified, the default behavior shall be to interpret the arguments as process IDs.

OPERANDS

The following operands shall be supported:

priority
A decimal integer representing the new scheduling priority for the processes.
pid
A process ID.
gid
A process group ID.
user
A user name or user ID.

STDIN

None.

INPUT FILES

None.

ENVIRONMENT VARIABLES

None.

ASYNCHRONOUS EVENTS

None.

STDOUT

When renice is successful, it shall write the following output for each process whose priority was successfully changed:

nice priority pid pid

where priority is the new nice value and pid is the process ID. The output shall be written in the POSIX locale, or in the locale's equivalent of the category LC_MESSAGES.

STDERR

The standard error shall be used for diagnostic messages.

OUTPUT FILES

None.

EXTENDED DESCRIPTION

None.

EXIT STATUS

The following exit values shall be returned:

0
Successful completion.
>0
An error occurred.

CONSEQUENCES OF ERRORS

If renice fails to change the priority of any specified process, it shall not terminate immediately. It shall continue processing the remaining arguments. If any process priority change fails, renice shall return a non-zero exit status.

APPLICATION USAGE

None.

EXAMPLES

None.

RATIONALE

The nice and renice utilities provide a mechanism for users to affect the system scheduling priority of their processes. The term "nice value" originated in the DEC TOPS-10 operating system and was later adopted by Berkeley UNIX. It refers to the fact that processes with higher nice values (lower priorities) are "nicer" to other processes, as they voluntarily yield the CPU more readily.

Implementations may implement the nice-related features to affect all processes on the system, others to affect just the general time-sharing activities implied by this volume of POSIX.1-2017, and others may have no effect at all. Because of the use of "implementation-defined" in nice and renice, a wide range of implementation strategies are possible.

Originally, this utility was written in the historical manner, using the term "nice value". This was always a point of concern with users because it was never intuitively obvious what this meant. With a newer version of renice, which used the term "system scheduling priority", it was hoped that novice users could better understand what this utility was meant to do. Also, it would be easier to document what the utility was meant to do. Unfortunately, the addition of the POSIX realtime scheduling capabilities introduced the concepts of process and thread scheduling priorities that were totally unaffected by the nice/renice utilities or the nice()/setpriority() functions. Continuing to use the term "system scheduling priority" would have incorrectly suggested that these utilities and functions were indeed affecting these realtime priorities. It was decided to revert to the historical term "nice value" to reference this unrelated process attribute.

Although this utility has use by system administrators (and in fact appears in the system administration portion of the BSD documentation), the standard developers considered that it was very useful for individual end users to control their own processes.

Earlier versions of this standard allowed the following forms in the SYNOPSIS:

renice nice_value[-p] pid...[-g gid...][-p pid...][-u user...]
renice nice_value -g gid...[-g gid...]-p pid...][-u user...]
renice nice_value -u user...[-g gid...]-p pid...][-u user...]

These forms are no longer specified by POSIX.1-2008 but may be present in some implementations.
