/etc/repod.conf.d/

DESCRIPCIÓN

Un archivo de configuración basado en TOML [1], que puede ser proporcionado en una ubicación de archivo de configuración predeterminada y/o en ubicaciones de archivos de configuración de anulación. Los archivos de configuración de anulación se leen y fusionan en orden alfabético y tienen mayor precedencia que la ubicación del archivo de configuración predeterminado.

Los archivos de configuración proporcionados en las ubicaciones del sistema (es decir, /etc/repod.conf y /etc/repod.conf.d/) solo se utilizan para el uso de repod en todo el sistema, mientras que las configuraciones proporcionadas en ubicaciones por usuario (es decir, $XDG_CONFIG_HOME/repod/repod.conf y $XDG_CONFIG_HOME/repod/repod.conf.d/) solo se utilizan para el uso de repod por usuario.

Si no se proporciona ningún archivo de configuración, se asumen los valores predeterminados (ver PREDETERMINADOS).

OPCIONES GLOBALES

Las opciones globales proporcionan los valores predeterminados para cualquier repositorio que no los defina. Para cualquier opción no definida, se asumen los valores predeterminados (ver OPCIONES PREDETERMINADAS).

architecture =

Una cadena de texto que establece la arquitectura de la CPU utilizada para cualquier repositorio que no la defina. Los valores entendidos son

"aarch64", "any", "arm", "armv6h", "armv7h", "i486", "i686", "pentium4", "riscv32", "riscv64", "x86_64", "x86_64_v2", "x86_64_v3", "x86_64_v4"

archiving =

Una tabla opcional o un valor booleano, que define las opciones de archivado utilizadas para cualquier repositorio que no las defina explícitamente. Cuando no se establece o se establece en true, se crean opciones de archivado predeterminadas. Si se establece en false, el archivado se deshabilita de forma predeterminada, pero aún se puede configurar por repositorio. Cuando se define como una tabla, la opción debe definir los siguientes pares clave-valor:

packages =
El nombre del directorio de archivo de paquetes (ver DIRECTORIOS PREDETERMINADOS para los valores predeterminados), debajo del cual se crean estructuras de directorios y archivos para el archivado de paquetes y archivos de firmas. Este directorio debe ser absoluto.
sources =
El nombre del directorio de archivo de fuentes (ver DIRECTORIOS PREDETERMINADOS para los valores predeterminados), debajo del cual se crean estructuras de directorios y archivos para el archivado de tarballs de fuentes. Este directorio debe ser absoluto.

build_requirements_exist =

Un valor booleano opcional, que define si los requisitos de compilación de los paquetes agregados deben existir en el archivo (si está configurado), en cualquiera de las capas de estabilidad del repositorio de destino o en el conjunto de paquetes que se están agregando. Cuando no se establece, el valor se establecerá en el valor predeterminado (ver OPCIONES PREDETERMINADAS). Cuando se establece en false, los requisitos de compilación de los paquetes agregados no se verifican, cuando se establece en true, se verifican. Esta configuración aún puede ser anulada por repositorio.

database_compression =

Una cadena de texto que establece la compresión de la base de datos utilizada para cualquier repositorio que no la defina. Los valores entendidos son

"","bz2", "gz", "xz", "zst"

management_repo

Una tabla que proporciona configuración para el repositorio de gestión para cualquier repositorio que no defina uno explícitamente. Como cada repositorio de paquetes binarios configurado se representa como una estructura de subdirectorios en el repositorio de gestión, varios repositorios pueden compartir el mismo management_repo.

directory =
El nombre del repositorio de gestión en el directorio base del repositorio de gestión (ver DIRECTORIOS PREDETERMINADOS), debajo del cual se crean directorios por repositorio de paquetes binarios. Si la cadena denota un directorio absoluto, se usa directamente y se ignora el directorio base predeterminado.
json_dumps =
Un entero, que define la opción para el método dumps() [2] de orjson. Predeterminado a:
1057

url =

Una cadena de URL opcional, para el repositorio upstream del repositorio de gestión (actualmente no utilizado)

package_pool =

Una cadena de texto que establece un directorio que sirve como pool de paquetes para cualquier repositorio que no lo defina.

package_verification =

Una cadena de texto opcional que establece la implementación de la verificación de firmas de paquetes para todos los repositorios. Si se selecciona una implementación de verificación de firmas, los paquetes que se agreguen al repositorio deben estar firmados. Los valores entendidos son

"pacman-key"

source_pool =

Una cadena de texto que establece un directorio que sirve como pool de tarballs de fuentes para cualquier repositorio que no lo defina.

AJUSTES DE LA BASE DE DATOS DE SINCRONIZACIÓN

Los ajustes de la base de datos de sincronización ofrecen control sobre la forma en que se exportan los datos para las bases de datos de sincronización de repositorios. Los pares clave-valor que se detallan a continuación se configuran dentro de una tabla global syncdb_settings. Para cualquier opción no definida, se asumen los valores predeterminados (ver OPCIONES PREDETERMINADAS).

desc_version =

Un entero que establece la versión desc utilizada al exportar el repositorio de gestión a una base de datos de sincronización de repositorios. Los valores entendidos son

2, 1

files_version =

Un entero que establece la versión files utilizada al exportar el repositorio de gestión a una base de datos de sincronización de repositorios. Los valores entendidos son

1

OPCIONES DE REPOSITORIO

Las opciones de repositorio se utilizan para configurar un repositorio específico. Si las opciones opcionales no están definidas, se asumen las opciones globales (ver OPCIONES GLOBALES) o los valores predeterminados (ver OPCIONES PREDETERMINADAS).

NOTA: Los directorios resueltos para los repositorios deben ser globalmente únicos. Las únicas excepciones a esta regla son package_pool, source_pool, archiving.packages y archiving.sources.

architecture =

Una cadena de texto opcional que establece la arquitectura de la CPU. Los valores entendidos son

"aarch64", "any", "arm", "armv6h", "armv7h", "i486", "i686", "pentium4", "riscv32", "riscv64", "x86_64", "x86_64_v2", "x86_64_v3", "x86_64_v4"

archiving =

Una tabla en línea opcional o un valor booleano, que define las opciones de archivado. Cuando no se establece o se establece en true, se utilizan las opciones de archivado globales. Si se establece en false, el archivado se deshabilita.

NOTA: Cuando se utilizan repositorios juntos, deben usar las mismas opciones de archivado.

Cuando se define como una tabla en línea, la opción debe definir los siguientes pares clave-valor:

Una configuración de cadena opcional que establece la compresión de la base de datos utilizada para el repositorio. Los valores entendidos son

"\"", "bz2", "gz", "xz", "zst"

group =

Un entero positivo opcional, que define el grupo al que pertenece un repositorio.

NOTA: Cuando los repositorios se agrupan, los nombres pkgbase y package deben ser únicos entre ellos (es decir, el mismo paquete no puede existir en dos repositorios al mismo tiempo; ¡esto es diferente de que el mismo paquete exista en diferentes capas de estabilidad del mismo repositorio!). Además, los repositorios deben usar el mismo repositorio de gestión (que reside debajo del directorio base del repositorio de gestión), el mismo directorio base del repositorio de paquetes, el mismo directorio base del pool de paquetes y el mismo directorio base del pool de fuentes.

management_repo =

Una tabla en línea opcional que proporciona configuración para el repositorio de gestión del repositorio. Si se proporciona, tiene precedencia sobre un management_repo definido globalmente. Como cada repositorio configurado se representa como una estructura de subdirectorios en el repositorio de gestión, varios repositorios pueden compartir el mismo management_repo.

directory =
El nombre del repositorio de gestión en el directorio base del repositorio de gestión (ver DIRECTORIOS PREDETERMINADOS), debajo del cual se crean directorios por repositorio de paquetes binarios. Si la cadena denota un directorio absoluto, se usa directamente y se ignora el directorio base predeterminado.
json_dumps =
Un entero, que define la opción para el método dumps() de orjson (ver https://github.com/ijl/orjson#option). El valor predeterminado es:
1057

url =

Una cadena de URL opcional, para el repositorio upstream del repositorio de gestión (actualmente no se usa)

package_url_validation =

Una tabla en línea opcional que proporciona configuración para la validación de URL de fuentes. Las URL de fuentes son enlaces, que pueden proporcionarse por pkgbase usando repod-file y sirven como referencia a los archivos de fuentes (por ejemplo, PKGBUILD) para cada paquete.

urls =
Una lista de cadenas de URL, contra las cuales deben validarse las URL de fuentes proporcionadas a repod-file.
tls_required =
Un valor booleano, que establece si las URL en la lista urls y cualquier URL de fuente proporcionada a repod-file deben usar TLS o no.

name =

Una cadena que establece el nombre del repositorio. Se utiliza para construir la ubicación debajo de la cual se almacenan los datos de paquetes estables del repositorio.

NOTA: La combinación de name y architecture debe ser única entre todos los repositorios.

Si la cadena denota un directorio relativo, se usa debajo del directorio base del repositorio de paquetes y del directorio base del repositorio de gestión predeterminados (ver DIRECTORIOS PREDETERMINADOS).

Si la cadena denota un directorio absoluto, se usa directamente y se ignoran los directorios base predeterminados.

debug =

Una cadena opcional que establece el nombre de depuración del repositorio. Se utiliza para construir la ubicación debajo de la cual se almacenan los datos de paquetes de depuración estables del repositorio.

NOTA: Al usar esta opción y también las opciones staging o testing, las opciones staging_debug y testing_debug (respectivamente) también deben establecerse.

Si la cadena denota un directorio relativo, se usa debajo del directorio base del repositorio de paquetes y del directorio base del repositorio de gestión predeterminados (ver DIRECTORIOS PREDETERMINADOS).

Si la cadena denota un directorio absoluto, se usa directamente y se ignoran los directorios base predeterminados.

package_pool =

Una cadena opcional que establece un directorio que sirve como pool de paquetes para el repositorio.

NOTA: Si los repositorios mueven paquetes entre sí, deben usar el mismo package_pool.

Si la cadena denota un directorio relativo, se usa debajo del directorio base del pool de paquetes predeterminado (ver DIRECTORIOS PREDETERMINADOS).

Si la cadena denota un directorio absoluto, se usa directamente y se ignoran los directorios base predeterminados.

source_pool =

Una cadena opcional que establece un directorio que sirve como pool de tarballs de fuentes para el repositorio.

NOTA: Si los repositorios mueven paquetes entre sí, deben usar el mismo source_pool.

Si la cadena denota un directorio relativo, se usa debajo del directorio base del pool de fuentes predeterminado (ver DIRECTORIOS PREDETERMINADOS).

Si la cadena denota un directorio absoluto, se usa directamente y se ignoran los directorios base predeterminados.

staging =

Una cadena opcional que establece el nombre de staging del repositorio. Se utiliza para construir la ubicación debajo de la cual se almacenan los datos de paquetes de staging del repositorio.

Si la cadena denota un directorio relativo, se usa debajo del directorio base del repositorio de paquetes y del directorio base del repositorio de gestión predeterminados (ver DIRECTORIOS PREDETERMINADOS).

Si la cadena denota un directorio absoluto, se usa directamente y se ignoran los directorios base predeterminados.

staging_debug =

Una cadena opcional que establece el nombre de depuración de staging del repositorio. Se utiliza para construir la ubicación debajo de la cual se almacenan los datos de paquetes de depuración de staging del repositorio.

NOTA: Las opciones staging y debug deben establecerse al usar esta opción. De manera similar, si debug y staging están configurados para un repositorio, esta opción también debe configurarse.

Si la cadena denota un directorio relativo, se usa debajo del directorio base del repositorio de paquetes y del directorio base del repositorio de gestión predeterminados (ver DIRECTORIOS PREDETERMINADOS).

Si la cadena denota un directorio absoluto, se usa directamente y se ignoran los directorios base predeterminados.

testing =

Una cadena opcional que establece el nombre de testing del repositorio. Se utiliza para construir la ubicación debajo de la cual se almacenan los datos de paquetes de testing del repositorio.

Si la cadena denota un directorio relativo, se usa debajo del directorio base del repositorio de paquetes y del directorio base del repositorio de gestión predeterminados (ver DIRECTORIOS PREDETERMINADOS).

Si la cadena denota un directorio absoluto, se usa directamente y se ignoran los directorios base predeterminados.

testing_debug =

Una cadena opcional que establece el nombre de depuración de testing del repositorio. Se utiliza para construir la ubicación debajo de la cual se almacenan los datos de paquetes de depuración de testing del repositorio.

NOTA: Las opciones testing y debug deben establecerse al usar esta opción. De manera similar, si debug y testing están configurados para un repositorio, esta opción también debe configurarse.

Si la cadena denota un directorio relativo, se usa debajo del directorio base del repositorio de paquetes y del directorio base del repositorio de gestión predeterminados (ver DIRECTORIOS PREDETERMINADOS).

Si la cadena denota un directorio absoluto, se usa directamente y se ignoran los directorios base predeterminados.
