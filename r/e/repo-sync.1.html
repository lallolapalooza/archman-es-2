DETALLES

El comando 'repo sync' sincroniza los directorios de proyectos locales con los repositorios remotos especificados en el manifiesto. Si un proyecto local aún no existe, clonará un nuevo directorio local desde el repositorio remoto y configurará las ramas de seguimiento como se especifica en el manifiesto. Si el proyecto local ya existe, 'repo sync' actualizará las ramas remotas y hará un rebase de los nuevos cambios locales sobre los nuevos cambios remotos.

'repo sync' sincronizará todos los proyectos listados en la línea de comandos. Los proyectos se pueden especificar por nombre o por una ruta relativa o absoluta al directorio local del proyecto. Si no se especifican proyectos, 'repo sync' sincronizará todos los proyectos listados en el manifiesto.

La opción -d/--detach se puede usar para volver a colocar los proyectos especificados en la revisión del manifiesto. Esta opción es especialmente útil si el proyecto está actualmente en una rama de tema, pero la revisión del manifiesto se necesita temporalmente.

La opción -s/--smart-sync se puede usar para sincronizar a una compilación buena conocida, según lo especificado por el elemento manifest-server en el manifiesto actual. La opción -t/--smart-tag es similar y permite especificar una etiqueta/etiqueta personalizada.

Las opciones -u/--manifest-server-username y -p/--manifest-server-password se pueden usar para especificar un nombre de usuario y una contraseña para autenticarse con el servidor de manifiestos al usar la opción -s o -t.

Si -u y -p no se especifican al usar la opción -s o -t, 'repo sync' intentará leer las credenciales de autenticación para el servidor de manifiestos del archivo .netrc del usuario.

DESCRIPTION

This command downloads the specified projects from the manifest. If no projects are specified, all projects in the manifest will be downloaded.

The download is performed using Git. If the project is not yet present, it will be cloned. If it is already present, it will be fetched.

All Git operations are performed using the Git configured in your environment. The Git binary is invoked directly. The 'repo' tool does not need to know Git internals. This means that all of Git's configuration values (e.g. user.name, user.email) are respected by 'repo sync'.

This command will also fetch Git submodules, if specified in the manifest or in the project's .gitmodules file. This is done by default for all projects.

The command will automatically check for Git submodules when performing fetches.

The Git configuration is used to determine where to fetch from. The server specified in the manifest file for each project is used to determine the default remote URL. If credentials are required by the Git server for a manifest, they should be included in the manifest server URL, or the user's Git configuration should be set up to provide them.

The command can also be used to sync specific projects. These projects can be specified by name, path or by using regular expressions. More complex expressions can be used by specifying them in the manifest file and referring to them by name.

The command also respects the Git configuration for credentials, e.g. if the server requires authentication, it will be prompted for, or used from the Git configuration.
