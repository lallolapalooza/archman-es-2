RETROARCH(6) Manual del Administrador del Sistema: retroarch RETROARCH(6)

NOMBRE

retroarch - El front-end de referencia para la API libretro.

SINOPSIS

retroarch [archivo(s) de ROM] [OPCIONES]...

DESCRIPCIÓN

retroarch es el front-end de referencia para la API libretro. libretro es una abstracción de un sistema de juegos y puede ser implementada por cualquier front-end. La API libretro está diseñada para juegos, emuladores y multimedia. retroarch se enfoca en exponer la funcionalidad necesaria para el sistema de juegos a través del uso de la línea de comandos y archivos de configuración. También incluye una interfaz de usuario simple integrada.

EJEMPLO DE LÍNEA DE COMANDOS

Cargar contenido, utilizando un núcleo libretro y un archivo de configuración específicos.
retroarch --config ~/.config/retroarch/retroarch.cfg --libretro /ruta/a/nucleo/libretro.so /ruta/a/rom.rom --verbose
Sin opciones de línea de comandos, se iniciará RetroArch en modo de menú.
retroarch
Iniciar RetroArch en modo de menú, con registro detallado.
retroarch --menu --verbose

Menú

Se refiere al sistema de interfaz gráfica de usuario integrado de RetroArch. Está diseñado para ser controlado solo con un gamepad.

CONTROLES PREDETERMINADOS

Por defecto, solo se acepta la entrada del teclado.

OPCIONES GENERALES

[archivo de ROM]
Si no se define la ruta del archivo de ROM en la línea de comandos, retroarch intentará cargar un núcleo sin ROM. Esto solo funcionará con algunos núcleos libretro. retroarch utiliza contenido sin comprimir, pero puede descomprimir contenido en formato .zip/deflate si se compila con soporte para ello. Los tipos de contenido admitidos dependen de la implementación libretro utilizada.
--help, -h
Muestra el texto de ayuda.
--menu
Se inicia directamente en el menú del juego si está habilitado. No requiere que se configure contenido o implementación libretro. Estos se pueden cargar posteriormente en el menú. Si no se pasan argumentos a retroarch, es equivalente a llamar a retroarch con este como único argumento.
--features
Muestra las características disponibles compiladas en RetroArch y luego sale.
-L RUTA, --libretro RUTA
Ruta a una implementación libretro que se utilizará. Esta opción anulará cualquier configuración en un archivo de configuración. Esta opción solo está disponible si RetroArch está compilado con carga libretro dinámica.
--save RUTA, -s RUTA
Anula la ruta utilizada para la RAM de guardado (*.srm) (obsoleto). Sin esta bandera, la ruta de la RAM de guardado se inferirá del nombre del archivo ROM, y se colocará en el mismo directorio que el archivo ROM con la extensión reemplazada por '.srm'. Si RUTA es un directorio, RetroArch lo tratará como el directorio de archivos de guardado, donde el nombre del archivo de guardado se inferirá del nombre de la ROM.
--savestate RUTA, -S RUTA
Anula la ruta utilizada para los estados de guardado (obsoleto). Sin esta bandera, la ruta del estado de guardado se inferirá del nombre del archivo ROM, y se colocará en el mismo directorio que el archivo ROM con la extensión reemplazada por '.state'. Si RUTA es un directorio, RetroArch lo tratará como el directorio de estados de guardado, donde el nombre del archivo de estado se inferirá del nombre de la ROM. Tenga en cuenta que los estados de guardado están vinculados a la implementación libretro que se esté utilizando. Usar una libretro diferente podría invalidar el archivo de estado de guardado.
--fullscreen, -f
Siempre inicia RetroArch en pantalla completa. Ignora la configuración del archivo de configuración.
--config RUTA, -c RUTA
Establece la ruta del archivo de configuración. retroarch usará esta ruta para cargar el archivo de configuración. Si no se define, retroarch buscará en rutas específicas de la plataforma para intentar encontrar el archivo de configuración. /etc/retroarch.cfg (cuando está instalado), o retroarch.cfg en el tarball fuente sirven como archivo de configuración esqueleto. /etc/retroarch.cfg solo debe servir como un esqueleto de configuración.
Los sistemas tipo Unix buscarán primero en $XDG_CONFIG_HOME/retroarch/retroarch.cfg. Si $XDG_CONFIG_HOME no está definido, se asume que es $HOME/.config según la especificación. Luego intentará en $HOME/.retroarch.cfg. Si ambas rutas fallan, RetroArch intentará crear un nuevo archivo de configuración predeterminado en $XDG_CONFIG_HOME/retroarch/retroarch.cfg (o el valor predeterminado de $HOME/.config para $XDG_CONFIG_HOME). Si todo falla, se asumirán los ajustes predeterminados. Si RetroArch crea un archivo de configuración predeterminado, intentará cargar el archivo de configuración esqueleto /etc/retroarch.cfg y lo usará como base. Esto permite a las distribuciones establecer rutas predeterminadas para los núcleos libretro y cosas similares. Un archivo de configuración no necesita definir cada opción posible, solo aquellas que deben ser anuladas.

Si se establece config_save_on_exit = true en el archivo de configuración, RetroArch sobrescribirá el archivo de configuración al salir. Los ajustes se pueden cambiar desde el menú. Si RetroArch sobrescribe un archivo de configuración, se perderán el formato, los comentarios, etc. Si RetroArch crea un archivo de configuración predeterminado, se establecerá automáticamente config_save_on_exit.

Windows buscará en retroarch.cfg en la misma carpeta donde reside retroarch.exe. También se creará un archivo de configuración predeterminado de la misma manera que en Unix.
--appendconfig RUTA
Añade un conjunto diferente de archivos de configuración al archivo de configuración cargado en -c (o el predeterminado). Se delimitan varios archivos de configuración por ','. Cada archivo de configuración se añadirá en orden, donde los pares clave-valor del siguiente archivo de configuración tendrán prioridad sobre los anteriores.
--subsystem SUBSISTEMA
Utiliza un subsistema del núcleo libretro cargado. Se cargan varios archivos de contenido como argumentos múltiples. Si se omite contenido, use un argumento de línea de comandos vacío (""). El contenido debe cargarse en un orden que dependa del subsistema particular utilizado. Consulte la salida del registro detallado para aprender cómo un subsistema particular desea que se cargue el contenido.
--nodevice PUERTO, -N PUERTO
Desconecta un dispositivo de entrada del puerto número PUERTO. Los valores posibles para PUERTO son de 1 a 8. Esto puede ser necesario para que algunos juegos inusuales se ejecuten correctamente. Si se establece explícitamente aquí, anula la configuración del archivo para ese puerto.
--dualanalog PUERTO, -A PUERTO
Conecta un controlador DualAnalog al puerto PUERTO. Los valores posibles son de 1 a 8. Si se establece explícitamente aquí, anula la configuración del archivo para ese puerto.
--device PUERTO:ID, -d PUERTO:ID
Conecta un dispositivo de entrada genérico ID al puerto PUERTO. Los valores posibles para el puerto son de 1 a 8. Si se establece explícitamente aquí, anula la configuración del archivo para ese puerto. ID es un número sin signo correspondiente al dispositivo para un núcleo libretro.
--record RUTA, -r RUTA
Activa la grabación de video del juego en RUTA. Se recomienda usar la extensión .mkv. Los códecs utilizados son (FFV1 o H264 RGB sin pérdidas (x264))/FLAC, adecuados para procesar el material posteriormente.
--recordconfig RUTA
Establece la ruta a un archivo de configuración para usar durante la grabación.
--size ANCHOxALTO
Permite especificar el ancho y alto exactos de salida de la grabación. Esta opción anulará cualquier configuración. La entrada de video se escala con filtrado por puntos antes de codificarse al tamaño correcto.
--play-replay RUTA, -P RUTA
Reproduce una grabac

NAME

retroarch - command line interface

SYNOPSIS

retroarch [-h | -v | -l | -k KEY | -s STATE_FILE | -S STATE_FILE | -m STATE_FILE | -M STATE_FILE | -r STATE_FILE | -R STATE_FILE | -t SAVE_FILE | -T SAVE_FILE | -f CONFIG_FILE | -c CONFIG_FILE | -p PID_FILE | -d CORE_DIR | -i INFO_DIR | -a ASSETS_DIR | -e EXEF_DIR | -P SAVE_DIR | -U UPS_PATCH | -B BPS_PATCH | -I IPS_PATCH | -X XDELTA_PATCH | -w WAIT_FOR_CONNECTION | -W WAIT_FOR_CONNECTION_PORT | -O OVERRIDE_RECEIVE_PORT | -L CORE_FILE | -U CORE_FILE | -M SRAM_MODE | -H | -C SERVER | -F FRAMES | --port PORT | --spectate | --command CMD | --nick NICK | --fullscreen | --disable-share | --game-specific-options GAME_SPECIFIC_OPTIONS | --no-patch | -D | CONTENT ... ]

DESCRIPTION

RetroArch is a frontend for libretro emulation cores. It is designed to be fast, lightweight, and have the ability to run on many different platforms, from PCs to game consoles to mobile phones.

This manual page covers the command-line options available for RetroArch.

EXAMPLE COMMANDLINE

Run a game with a specific core and configuration file:

retroarch -L /path/to/core.so -c /path/to/retroarch.conf /path/to/game.rom

Start a netplay session as host:

retroarch -H /path/to/game.rom

Start a netplay session as client:

retroarch -C SERVER_IP /path/to/game.rom

Menu

-h, --help
Show help message and exit.
-v, --verbose
Enable verbose logging.
-l, --list_cores
List available cores.
-k, --keybind KEY
Sends a hotkey command to a running RetroArch instance.
-s, --save_state PATH
Save state to PATH.
-S, --save_state_num NUMBER
Save state to STATE_FILE.NUMBER.
-m, --load_state PATH
Load state from PATH.
-M, --load_state_num NUMBER
Load state from STATE_FILE.NUMBER.
-r, --record_replay PATH
Start recording a .replay video to PATH immediately after startup.
-R, --record_replay_stop
Stop recording .replay video.
-t, --savestate_to_savefile
Saves state to the savefile.
-T, --loadstate_from_savefile
Loads state from the savefile.
-f, --config PATH
Use PATH as configuration file.
-c, --set_config SETTING=VALUE
Set configuration variable.
-p, --pidfile PATH
Write PID to PATH.
-d, --core_dir PATH
Use PATH as core directory.
-i, --info_dir PATH
Use PATH as info directory.
-a, --assets_dir PATH
Use PATH as assets directory.
-e, --exef_dir PATH
Use PATH as frontend executable directory.
-P, --save_dir PATH
Use PATH as save directory.
-U, --ups PATCH
Apply UPS patch.
-B, --bps PATCH
Apply BPS patch.
-I, --ips PATCH
Apply IPS patch.
-X, --xdelta PATCH
Apply Xdelta patch.
-w, --wait_for_connection
Wait for connection.
-W, --wait_for_connection_port PORT
Wait for connection on PORT.
-O, --override_receive_port PORT
Override receive port.
-L, --libretro CORE_FILE
Load CORE_FILE.
--fullscreen
Start in fullscreen mode.
--disable-share
Disable network sharing.
--game-specific-options GAME_SPECIFIC_OPTIONS
Enable game specific options.
--no-patch
Disable all kinds of content patching.
-D, --detach
Detach from the current console.

DEFAULT CONTROLS

The default controls can be found in the configuration file.

GENERAL OPTIONS

--record-replay-format FORMAT
Set the recording format for --record-replay. Valid formats are: replay, avi, mp4, gif.
--record-replay-base-path PATH
Set the base path for --record-replay.
--state-slot SLOT
Set the state slot to use for saving and loading states. Default is 0.
--save-file PATH
Set the save state file path. If not specified, it defaults to STATE_FILE.SLOT.
--save-file-set-file-content
Set save file content to save state.
--load-file-set-file-content
Set save file content to load state.
--save-replay
Record a .replay video to REPLAY_FILE. The cart ROM and movie file need to correspond. It also requires to play back with the same libretro backend that was used for recording.
--record-replay PATH, -R PATH
Start recording a .replay video to PATH immediately after startup.
--sram-mode MODE, -M MODE
MODE designates how to handle SRAM. The format of the second parameter is {no,}load-{no,}save. These two boolean values tell if SRAM loading and SRAM saving should take place. Note that noload-save implies that the SRAM will be overwritten with new data.
--verbose, -v
Activates verbose logging.
--host, -H
Be the host of netplay. Waits until a user connects. The host will always assume user 1.
--connect SERVER, -C SERVER
Connect to a host of netplay. Will always assume user 2.
--frames FRAMES, -F FRAMES
Sync frames to use when using netplay. More frames allow for more latency, but requires more CPU power. Set FRAMES to 0 to have perfect sync. 0 frames is only suitable for LAN. Defaults to 0.
--port PORT
Network port used for netplay. This defaults to 55435. This option affects both TCP and UDP.
--spectate
If netplay is used, it will go into a spectator mode. Spectator mode allows one host to live stream game playback to multiple clients. Essentially, clients receive a live streamed replay movie file. Clients can connect and disconnect at any time. Clients thus cannot interact as user 2. For spectating mode to work, both host and clients will need to use this flag.
--command CMD
Sends a command over UDP to an already running RetroArch application, and exit. The command is formatted as "COMMAND;HOST;PORT". HOST and PORT are both optional. "COMMAND;HOST" will set PORT to "network_cmd_port" default setting. If only "COMMAND" is used, HOST and PORT will be assumed to be "localhost" and "network_cmd_port" respectively.

The available commands are listed if "COMMAND" is invalid.

--nick NICK
Pick a nickname for use with netplay. This is purely cosmetic, and only serves to help users identify each other.
--ups PATCH, -U PATCH
Attempts to apply an UPS patch to the current content image. No files are altered. If this flag is not specified, RetroArch will look for a .ups file with same basename as content specified.
--bps PATCH
Attempts to apply a BPS patch to the current content image. No files are altered. If this flag is not specified, RetroArch will look for a .bps file with same basename as content specified.
--ips PATCH
Attempts to apply a IPS patch to the current content image. No files are altered. If this flag is not specified, RetroArch will look for a .ips file with same basename as content specified. Note that RetroArch cannot perform any error checking if patching was successful due to how IPS works.
--xdelta PATCH
Attempts to apply an Xdelta patch to the current content image. No files are altered. If this flag is not specified, RetroArch will look for a .xdelta file with same basename as content specified. Only available if RetroArch was built with Xdelta support.
--no-patch
Disables all kinds of content patching.
-D, --detach
Detach from the current console. This is currently only relevant for Microsoft Windows.

ENVIRONMENT

retroarch honors the following environment variables:

LIBRETRO_DIRECTORY
Specify the directory where RetroArch looks for core and info files, overriding the value of the "libretro_directory" configuration file option.
LIBRETRO_ASSETS_DIRECTORY
Specify the directory where RetroArch looks for assets, overriding the value of the "assets_directory" configuration file option.
LIBRETRO_AUTOCONFIG_DIRECTORY
Specify the directory where RetroArch looks for controller auto-configuration files, overriding the value of the "joypad_autoconfig_dir" configuration file option.
LIBRETRO_CHEATS_DIRECTORY
Specify the directory where RetroArch looks for cheat files, overriding the value of the "cheat_database_path" configuration file option.
LIBRETRO_DATABASE_DIRECTORY
Specify the directory where RetroArch looks for database files, overriding the value of the "content_database_path" configuration file option.
LIBRETRO_SYSTEM_DIRECTORY
Specify the directory where RetroArch looks for system files, overriding the value of the "system_directory" configuration file option.
LIBRETRO_VIDEO_FILTER_DIRECTORY
Specify the directory where RetroArch looks for video filters, overriding the value of the "video_filter_dir" configuration file option.
LIBRETRO_VIDEO_SHADER_DIRECTORY
Specify the directory where RetroArch looks for video shaders, overriding the value of the "video_shader_dir" configuration file option.
