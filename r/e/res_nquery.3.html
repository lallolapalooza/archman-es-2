DESCRIPCIÓN

Nota: Esta página está incompleta (varias funciones del resolucionador proporcionadas por glibc no se describen) y probablemente desactualizada.

Las funciones descritas a continuación realizan consultas y interpretan las respuestas de los servidores de nombres de dominio de Internet.

La API consta de un conjunto de funciones más modernas y reentrantes, y un conjunto más antiguo de funciones no reentrantes que han sido sustituidas. Las interfaces tradicionales del resolucionador como res_init() y res_query() utilizan algunos estados estáticos (globales) almacenados en la estructura _res, lo que hace que estas funciones no sean seguras para hilos. BIND 8.2 introdujo un conjunto de nuevas interfaces, res_ninit(), res_nquery(), etc., que toman un res_state como su primer argumento, por lo que puede utilizar un estado de resolucionador por hilo.

Las funciones res_ninit() y res_init() leen los archivos de configuración (véase resolv.conf(5)) para obtener el nombre de dominio predeterminado y la(s) dirección(es) del servidor de nombres. Si no se proporciona ningún servidor, se intenta con el host local. Si no se proporciona ningún dominio, se utiliza el asociado al host local. Puede ser anulado por la variable de entorno LOCALDOMAIN. res_ninit() o res_init() se ejecutan normalmente en la primera llamada a una de las otras funciones. Cada llamada a res_ninit() requiere una llamada correspondiente a res_nclose() para liberar la memoria asignada por res_ninit() y las llamadas posteriores a res_nquery().

Las funciones res_nquery() y res_query() consultan al servidor de nombres para el nombre de dominio completamente calificado name del type y class especificados. La respuesta se deja en el buffer answer de longitud anslen proporcionado por el llamador.

Las funciones res_nsearch() y res_search() realizan una consulta y esperan la respuesta como res_nquery() y res_query(), pero además implementan las reglas de dominio y búsqueda predeterminadas controladas por RES_DEFNAMES y RES_DNSRCH (véase la descripción de las opciones de _res a continuación).

Las funciones res_nquerydomain() y res_querydomain() realizan una consulta utilizando res_nquery()/res_query() en la concatenación de name y domain.

Las siguientes funciones son rutinas de nivel inferior utilizadas por res_nquery()/res_query().

Las funciones res_nmkquery() y res_mkquery() construyen un mensaje de consulta en buf de longitud buflen para el nombre de dominio dname. El tipo de consulta op es una de las siguientes (típicamente QUERY):

QUERY
Consulta estándar.
IQUERY
Consulta inversa. Esta opción fue eliminada en glibc 2.26, ya que no ha sido compatible con los servidores DNS durante mucho tiempo.
NS_NOTIFY_OP
Notificar a los secundarios del cambio de SOA (Start of Authority).

newrr no se utiliza actualmente.

La función res_nsend() y res_send() envían una consulta preformateada dada en msg de longitud msglen y devuelven la respuesta en answer que tiene una longitud anslen. Llamarán a res_ninit()/res_init() si aún no ha sido llamada.

La función dn_comp() comprime el nombre de dominio exp_dn y lo almacena en el buffer comp_dn de longitud length. La compresión utiliza una matriz de punteros dnptrs a nombres previamente comprimidos en el mensaje actual. El primer puntero apunta al principio del mensaje y la lista termina con NULL. El límite de la matriz se especifica mediante lastdnptr. Si dnptr es NULL, los nombres de dominio no se comprimen. Si lastdnptr es NULL, la lista de etiquetas no se actualiza.

NAME

res_init, res_ninit, res_query, res_search, res_querydomain, res_mkquery, res_send, res_nquery, res_nsearch, res_nquerydomain, res_nmkquery, res_nsend, dn_comp, dn_expand - resolver library routines

SYNOPSIS

All functions:

#include <resolv.h>

The resolver routines use configuration and state information contained in a __res_state structure (either passed as the statep argument, or in the global variable _res, in the case of the older nonreentrant functions). The only field of this structure that is normally manipulated by the user is the options field. This field can contain the bitwise "OR" of the following options:

RES_INIT
True if res_ninit() or res_init() has been called.
RES_DEBUG
Print debugging messages. This option is available only if glibc was built with debugging enabled, which is not the default.
RES_AAONLY (unimplemented; deprecated in glibc 2.25)
Accept authoritative answers only. res_send() continues until it finds an authoritative answer or returns an error. This option was present but unimplemented until glibc 2.24; since glibc 2.25, it is deprecated, and its usage produces a warning.
RES_USEVC
Use TCP connections for queries rather than UDP datagrams.
RES_PRIMARY (unimplemented; deprecated in glibc 2.25)
Query primary domain name server only. This option was present but unimplemented until glibc 2.24; since glibc 2.25, it is deprecated, and its usage produces a warning.
RES_IGNTC
Ignore truncation errors. Don't retry with TCP.
RES_RECURSE
Set the recursion desired bit in queries. Recursion is carried out by the domain name server, not by res_send(). [Enabled by default].
RES_DEFNAMES
If set, res_search() will append the default domain name to single component names—that is, those that do not contain a dot. [Enabled by default].
RES_STAYOPEN
Used with RES_USEVC to keep the TCP connection open between queries.
RES_DNSRCH
If set, res_search() will search for hostnames in the current domain and in parent domains. This option is used by gethostbyname(3). [Enabled by default].
RES_INSECURE1
Accept a response from a wrong server. This can be used to detect potential security hazards, but you need to compile glibc with debugging enabled and use RES_DEBUG option (for debug purpose only).
RES_INSECURE2
Accept a response which contains a wrong query. This can be used to detect potential security hazards, but you need to compile glibc with debugging enabled and use RES_DEBUG option (for debug purpose only).
RES_NOALIASES
Disable usage of HOSTALIASES environment variable.
RES_USE_INET6
Try an AAAA query before an A query inside the gethostbyname(3) function, and map IPv4 responses in IPv6 "tunneled form" if no AAAA records are found but an A record set exists. Since glibc 2.25, this option is deprecated, and its usage produces a warning; applications should use getaddrinfo(3), rather than gethostbyname(3).
RES_ROTATE
Causes round-robin selection of name servers from among those listed. This has the effect of spreading the query load among all listed servers, rather than having all clients try the first listed server first every time.
RES_NOCHECKNAME (unimplemented; deprecated in glibc 2.25)
Disable the modern BIND checking of incoming hostnames and mail names for invalid characters such as underscore (_), non-ASCII, or control characters. This option was present until glibc 2.24; since glibc 2.25, it is deprecated, and its usage produces a warning.
RES_KEEPTSIG (unimplemented; deprecated in glibc 2.25)
Do not strip TSIG records. This option was present but unimplemented until glibc 2.24; since glibc 2.25, it is deprecated, and its usage produces a warning.
RES_BLAST (unimplemented; deprecated in glibc 2.25)
Send each query simultaneously and recursively to all servers. This option was present but unimplemented until glibc 2.24; since glibc 2.25, it is deprecated, and its usage produces a warning.
RES_USEBSTRING (glibc 2.3.4 to glibc 2.24)
Make reverse IPv6 lookups using the bit-label format described in RFC 2673; if this option is not set (which is the default), then nibble format is used. This option was removed in glibc 2.25, since it relied on a backward-incompatible DNS extension that was never deployed on the Internet.
RES_NOIP6DOTINT (glibc 2.24 and earlier)
Use ip6.arpa zone in IPv6 reverse lookup instead of ip6.int, which is deprecated since glibc 2.3.4. This option is present up to and including glibc 2.24, where it is enabled by default. In glibc 2.25, this option was removed.
RES_USE_EDNS0 (since glibc 2.6)
Enables support for the DNS extensions (EDNS0) described in RFC 2671.
RES_SNGLKUP (since glibc 2.10)
By default, glibc performs IPv4 and IPv6 lookups in parallel since glibc 2.9. Some appliance DNS servers cannot handle these queries properly and make the requests time out. This option disables the behavior and makes glibc perform the IPv6 and IPv4 requests sequentially (at the cost of some slowdown of the resolving process).
RES_SNGLKUPREOP
When RES_SNGLKUP option is enabled, opens a new socket for the each request.
RES_USE_DNSSEC
Use DNSSEC with OK bit in OPT record. This option implies RES_USE_EDNS0.
RES_NOTLDQUERY
Do not look up unqualified name as a top-level domain (TLD).
RES_DEFAULT
Default option which implies: RES_RECURSE, RES_DEFNAMES, RES_DNSRCH, and RES_NOIP6DOTINT.

RETURN VALUE

The res_ninit() and res_init() functions return 0 on success, or -1 if an error occurs.

The res_nquery(), res_query(), res_nsearch(), res_search(), res_nquerydomain(), res_querydomain(), res_nmkquery(), res_mkquery(), res_nsend(), and res_send() functions return the length of the response, or -1 if an error occurs.

The dn_comp() and dn_expand() functions return the length of the compressed name, or -1 if an error occurs.

In the case of an error return from res_nquery(), res_query(), res_nsearch(), res_search(), res_nquerydomain(), or res_querydomain(), the global variable h_errno (see gethostbyname(3)) can be consulted to determine the error.

DESCRIPTION

Estas funciones son utilizadas para comunicarse con los servidores DNS (Domain Name System). El DNS es un sistema jerárquico y distribuido para nombrar computadoras, servicios o cualquier recurso conectado a Internet o a una red privada. La principal función del DNS es traducir nombres de dominio legibles por humanos (como www.archlinux.org) en direcciones IP numéricas (como 127.0.0.1) que las computadoras utilizan para conectarse entre sí.

Las funciones de nivel más bajo son res_init(), res_close(), res_mkquery(), res_send(), res_ninit(), res_nclose(), res_nmkquery() y res_nsend(). Estas funciones operan sobre una estructura res_state que contiene el estado de la consulta del resolver.

res_init() inicializa la estructura res_state. Lee la información de los archivos de configuración como /etc/resolv.conf para determinar los servidores DNS a consultar y las opciones de configuración. Los servidores DNS configurados serán consultados en orden hasta que se obtenga una respuesta o se agoten todos los servidores.

res_close() libera los recursos asociados con la estructura res_state.

res_mkquery() construye una consulta DNS. Toma varios parámetros como el nombre de dominio a consultar, la clase (generalmente C_IN para Internet), el tipo de registro DNS deseado (como T_A para direcciones IPv4, T_AAAA para direcciones IPv6, T_MX para servidores de correo, T_CNAME para alias de nombres, etc.) y construye un mensaje de consulta en el búfer proporcionado.

res_send() envía el mensaje de consulta construido por res_mkquery() a uno de los servidores DNS configurados y espera una respuesta. Si la respuesta no llega en un tiempo determinado o si se produce un error, puede reintentar la consulta con otro servidor.

Las versiones "n" de estas funciones (res_ninit(), res_nclose(), res_nmkquery(), res_nsend()) son versiones no globales de las funciones correspondientes. En lugar de usar variables globales para el estado del resolver, utilizan un puntero a una estructura res_state.

res_query() es una función de nivel superior que combina res_init(), res_mkquery() y res_send() para realizar una consulta DNS simple. Devuelve los datos de la respuesta DNS en el búfer proporcionado.

res_nquery() y res_nisquery() son versiones de res_query() que utilizan la estructura res_state.

dn_skipname(), dn_comp() y dn_expand() son funciones de utilidad para manipular nombres de dominio DNS codificados y expandidos. Los nombres de dominio en las consultas y respuestas DNS a menudo utilizan compresión de punteros para ahorrar espacio. dn_comp() comprime un nombre de dominio expandido y dn_expand() lo descomprime.

gethostbyname() y gethostbyaddr() son funciones de nivel superior más comunes que realizan consultas DNS y proporcionan información sobre hosts (nombres, alias, direcciones IP). gethostbyname() resuelve un nombre de host a una dirección IP, mientras que gethostbyaddr() hace lo contrario, resuelve una dirección IP a un nombre de host.

herror() e hstrerror() se utilizan para informar sobre errores del resolver. herror() imprime un mensaje de error formateado a stderr, mientras que hstrerror() devuelve una cadena de texto que describe un código de error específico.

RETURN VALUE

res_nquery(), res_nisquery(), res_query(), res_nsend() y res_send() devuelven la longitud del mensaje de respuesta DNS en el búfer de salida, o -1 en caso de error. El valor de error se puede encontrar en la variable global h_errno.

res_mkquery() y res_nmkquery() devuelven 0 en caso de éxito y -1 en caso de error.

res_init() y res_ninit() devuelven 0 en caso de éxito y -1 en caso de error. El estado del error se almacena en statp->res_state_error o en errno.

dn_skipname() devuelve un puntero al final del nombre de dominio comprimido.

dn_comp() devuelve la longitud del nombre de dominio comprimido o -1 en caso de error.

dn_expand() devuelve un puntero al final del nombre de dominio expandido en el mensaje original o NULL en caso de error.

gethostbyname() y gethostbyaddr() devuelven un puntero a una estructura hostent en caso de éxito, o un puntero NULL en caso de error. El error se almacena en h_errno.

hstrerror() devuelve una cadena de texto que describe el código de error.
