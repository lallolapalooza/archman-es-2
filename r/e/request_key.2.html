request_key(2) Manual de llamadas al sistema request_key(2)

NOMBRE

request_key - solicita una clave del sistema de gestión de claves del núcleo

BIBLIOTECA

Utilidades de gestión de claves de Linux (libkeyutils, -lkeyutils)

SINOPSIS

#include <keyutils.h>
key_serial_t request_key(const char *type, const char *description,
                         const char *_Nullable callout_info,
                         key_serial_t dest_keyring);

DESCRIPCIÓN

request_key() intenta encontrar una clave del tipo dado type con una descripción (nombre) que coincida con la proporcionada description. Si no se puede encontrar una clave así, entonces la clave se crea opcionalmente. Si la clave se encuentra o se crea, request_key() la adjunta al keyring especificado por el ID en dest_keyring y devuelve el número de serie de la clave.

request_key() primero busca recursivamente una clave coincidente en todos los keyrings adjuntos al proceso llamante. Los keyrings se buscan en el orden: keyring específico del hilo, keyring específico del proceso y keyring de sesión.

Si request_key() es llamado desde un programa invocado por request_key() en nombre de algún otro proceso para generar una clave, entonces los keyrings de ese otro proceso se buscarán a continuación, usando el ID de usuario, ID de grupo, IDs de grupo suplementarios y contexto de seguridad de ese otro proceso para determinar el acceso.

La búsqueda del árbol de keyrings es en anchura: las claves en cada keyring buscado se comprueban en busca de coincidencias antes de que se recurra a los keyrings hijos. Solo se pueden encontrar claves para las que el llamante tenga permiso de *búsqueda*, y solo se pueden buscar keyrings para los que el llamante tenga permiso de *búsqueda*.

Si la clave no se encuentra y callout es NULL, la llamada falla con el error ENOKEY.

Si la clave no se encuentra y callout no es NULL, el núcleo intenta invocar un programa en espacio de usuario para instanciar la clave. Los detalles se dan a continuación.

El número de serie dest_keyring puede ser el de un keyring válido para el cual el llamante tiene permiso de *escritura*, o puede ser uno de los siguientes IDs de keyring especiales:

KEY_SPEC_THREAD_KEYRING
Esto especifica el keyring específico del hilo del llamante (ver thread-keyring(7)).
KEY_SPEC_PROCESS_KEYRING
Esto especifica el keyring específico del proceso del llamante (ver process-keyring(7)).
KEY_SPEC_SESSION_KEYRING
Esto especifica el keyring específico de la sesión del llamante (ver session-keyring(7)).
KEY_SPEC_USER_KEYRING
Esto especifica el keyring específico del usuario del llamante (ver user-keyring(7)).
KEY_SPEC_USER_SESSION_KEYRING
Esto especifica el keyring de sesión del usuario del llamante (ver user-session-keyring(7)).

Cuando dest_keyring se especifica como 0 y no se ha realizado ninguna construcción de clave, no se realiza ningún enlace adicional.

De lo contrario, si dest_keyring es 0 y se construye una nueva clave, la nueva clave se enlazará al keyring "predeterminado". Más precisamente, cuando el núcleo intenta determinar a qué keyring se debe enlazar la clave recién construida, prueba los siguientes keyrings, comenzando con el keyring establecido mediante la operación KEYCTL_SET_REQKEY_KEYRING de keyctl(2) y continuando en el orden que se muestra a continuación hasta que encuentre el primer keyring que exista:

•
El keyring del solicitante (KEY_REQKEY_DEFL_REQUESTOR_KEYRING, desde Linux 2.6.29).
•
El keyring específico del hilo (KEY_REQKEY_DEFL_THREAD_KEYRING; ver thread-keyring(7)).
•
El keyring específico del proceso (KEY_REQKEY_DEFL_PROCESS_KEYRING; ver process-keyring(7)).
•
El keyring específico de la sesión (KEY_REQKEY_DEFL_SESSION_KEYRING; ver session-keyring(7)).
•
El keyring de sesión para el ID de usuario del proceso (KEY_REQKEY_DEFL_USER_SESSION_KEYRING; ver user-session-keyring(7)). Se espera que este keyring siempre exista.
•
El keyring específico del UID (KEY_REQKEY_DEFL_USER_KEYRING; ver user-keyring(7)). También se espera que este keyring siempre exista.

Si la operación KEYCTL_SET_REQKEY_KEYRING de keyctl(2) especifica KEY_REQKEY_DEFL_DEFAULT (o no se realiza ninguna operación KEYCTL_SET_REQKEY_KEYRING), entonces el núcleo busca un keyring comenzando desde el principio de la lista.

Solicitud de instanciación en espacio de usuario de una clave

Si el núcleo no puede encontrar una clave que coincida con type y description, y callout no es NULL, entonces el núcleo intenta invocar un programa en espacio de usuario para instanciar una clave con el type y description dados.

(1)
El núcleo crea una clave no instanciada, U, con el type y description solicitados.
(2)
El núcleo crea una clave de autorización, V, que hace referencia a la clave U y registra los hechos de que el llamante de request_key() es:
(2.1)
el contexto en el que se debe instanciar y asegurar la clave U, y
(2.2)
el contexto desde el cual se pueden satisfacer las solicitudes de claves asociadas.
La clave de autorización se construye de la siguiente manera:
•
El tipo de clave es ".request_key_auth".
•
El UID y GID de la clave son los mismos que los IDs de sistema de archivos correspondientes del proceso solicitante.
•
La clave otorga permisos de *vista*, *lectura* y *búsqueda* al poseedor de la clave, así como permiso de *vista* para el usuario de la clave.
•
La descripción (nombre) de la clave es la cadena hexadecimal que representa el ID de la clave que se va a instanciar en el programa solicitante.
•
La carga útil de la clave se toma de los datos especificados en callout_info.
•
Internamente, el núcleo también registra el PID del proceso que llamó a request_key().
(3)
El núcleo crea un proceso que ejecuta un servicio en espacio de usuario como request-key(8) con un keyring de sesión nuevo que contiene un enlace a la clave de autorización, V.
A este programa se le proporcionan los siguientes argumentos de línea de comandos:
[0]
La cadena "/sbin/request-key".
[1]
La cadena "create" (indicando que se va a crear una clave).
[2]
El ID de la clave que se va a instanciar.
[3]
El UID de sistema de archivos del llamante de request_key().
[4]
El GID de sistema de archivos del llamante de request_key().
[5]
El ID del keyring del hilo del llamante de request_key(). Puede ser cero si ese keyring no se ha creado.
[6]
El ID del keyring del proceso del llamante de request_key(). Puede ser cero si ese keyring no se ha creado.
[7]
El ID del keyring de sesión del llamante de request_key().
Nota: cada una de las comas

DESCRIPTION

The request_key() system call is used to locate or instantiate a key. The system call searches for a key matching the supplied type and description strings in the keyrings specified by the keyring argument. If a matching key is found, its serial number is returned.

If no matching key is found, then the kernel attempts to instantiate a new key.

The instantiation process is controlled by the configuration file /etc/request-key.conf. This file specifies which program (the "callout program") should be invoked for each key type. The callout program is responsible for creating the key payload.

The kernel invokes the callout program as follows:

(1)
The kernel looks up the appropriate callout program for the requested key type in /etc/request-key.conf. If no entry is found, the request fails with ENOKEY.
(2)
The kernel creates a special temporary key (an authorization key) of type request-key. This key's description is the serial number of the key being requested, and its payload contains the callout information (the callout_info string passed to request_key(), concatenated with the key description string passed to request_key()).
(3)
The kernel spawns the callout program specified in step (1). The command line for the callout program is constructed as follows:
callout_program key_type key_description key_id callout_info
  • callout_program is the program specified in /etc/request-key.conf.
  • key_type is the type of key requested.
  • key_description is the description of the key requested.
  • key_id is the ID of the authorization key created in step (2). This ID is passed as a command-line argument to the callout program. This argument is an integer, which is the key ID encoded in decimal (unlike the key IDs shown in /proc/keys, which are shown as hexadecimal values).
  • callout_info is the payload of the authorization key. This contains the actual callout data supplied to request_key() and the key description.
(4)
The program spawned in the previous step:
•
Assumes the authority to instantiate the key U using the keyctl(2) KEYCTL_ASSUME_AUTHORITY operation (typically via the keyctl_assume_authority(3) function).
•
Obtains the callout data from the payload of the authorization key V (using the keyctl(2) KEYCTL_READ operation (or, more commonly, the keyctl_read(3) function) with a key ID value of KEY_SPEC_REQKEY_AUTH_KEY).
•
Instantiates the key (or execs another program that performs that task), specifying the payload and destination keyring. (The destination keyring that the requestor specified when calling request_key() can be accessed using the special key ID KEY_SPEC_REQUESTOR_KEYRING.) Instantiation is performed using the keyctl(2) KEYCTL_INSTANTIATE operation (or, more commonly, the keyctl_instantiate(3) function). At this point, the request_key() call completes, and the requesting program can continue execution.

If these steps are unsuccessful, then an ENOKEY error will be returned to the caller of request_key() and a temporary, negatively instantiated key will be installed in the keyring specified by dest_keyring. This will expire after a few seconds, but will cause subsequent calls to request_key() to fail until it does. The purpose of this negatively instantiated key is to prevent (possibly different) processes making repeated requests (that require expensive request-key(8) upcalls) for a key that can't (at the moment) be positively instantiated.

Once the key has been instantiated, the authorization key (KEY_SPEC_REQKEY_AUTH_KEY) is revoked, and the destination keyring (KEY_SPEC_REQUESTOR_KEYRING) is no longer accessible from the request-key(8) program.

If a key is created, then—regardless of whether it is a valid key or a negatively instantiated key—it will displace any other key with the same type and description from the keyring specified in dest_keyring.
