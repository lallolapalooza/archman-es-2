RESOLVECTL(1) resolvectl RESOLVECTL(1)

NOMBRE

resolvectl, resolvconf - Resolver nombres de dominio, direcciones IPv4 e IPv6, registros de recursos DNS y servicios; introspeccionar y reconfigurar el resolvedor DNS

SINOPSIS

resolvectl [OPCIONES...] {COMANDO} [NOMBRE...]

DESCRIPCIÓN

resolvectl puede usarse para resolver nombres de dominio, direcciones IPv4 e IPv6, registros de recursos DNS y servicios con el servicio resolvedor de systemd-resolved.service(8). Por defecto, la lista especificada de parámetros se resolverá como nombres de host, recuperando sus direcciones IPv4 e IPv6. Si los parámetros especificados tienen el formato de direcciones IPv4 o IPv6, se realiza la operación inversa y se recupera un nombre de host para las direcciones especificadas.

La salida del programa contiene información sobre el protocolo utilizado para la búsqueda y en qué interfaz de red se descubrió la información. También contiene información sobre si la información pudo ser autenticada. Todos los datos para los que la validación local DNSSEC tiene éxito se consideran autenticados. Además, todos los datos originados de fuentes locales y confiables también se informan como autenticados, incluida la resolución del nombre de host local, el nombre de host "localhost" o todos los datos de /etc/hosts.

COMANDOS

query NOMBRE_HOST|DIRECCIÓN...

Resuelve nombres de dominio, así como direcciones IPv4 e IPv6. Cuando se usa junto con --type= o --class= (ver abajo), resuelve registros de recursos DNS de bajo nivel.

Si se especifica un nombre de dominio de un solo nivel, se busca de acuerdo con los dominios de búsqueda configurados, a menos que se especifique --search=no o --type=/--class=, que desactivan esta lógica.

Si se especifica un nombre de dominio internacional, se traduce automáticamente según las reglas de IDNA cuando se resuelve a través de DNS clásico, pero no para búsquedas a través de MulticastDNS o LLMNR. Si se usa --type=/--class=, la traducción IDNA se desactiva y los nombres de dominio se procesan según lo especificado.

Si se combina con --json= (solo compatible con --type=) se mostrarán los datos del registro de recursos en un objeto JSON.

Añadido en la versión 239.

service [[NOMBRE] TIPO] DOMINIO

Resuelve servicios RFC 6763 DNS-SD[1] y RFC 2782 SRV[2], dependiendo de la lista especificada de parámetros. Si se pasan tres parámetros, el primero se asume como el nombre del servicio DNS-SD, el segundo como el tipo de servicio SRV y el tercero como el dominio en el que buscar. En este caso, se ejecuta una búsqueda completa de estilo DNS-SD de SRV y TXT. Si solo se especifican dos parámetros, el primero se asume como el tipo de servicio SRV y el segundo como el dominio en el que buscar. En este caso, no se solicita un registro de recursos TXT. Finalmente, si solo se especifica un parámetro, se asume como un nombre de dominio, que ya está prefijado con un tipo SRV, y se realiza una búsqueda SRV (sin TXT).

Añadido en la versión 239.

openpgp EMAIL@DOMINIO...

Consulta claves PGP almacenadas como registros de recursos OPENPGPKEY, ver RFC 7929[3]. Las direcciones de correo electrónico especificadas se convierten al nombre de dominio DNS correspondiente y se imprimen todas las claves OPENPGPKEY.

Añadido en la versión 239.

tlsa [FAMILIA] DOMINIO[:PUERTO]...

Consulta claves públicas TLS almacenadas como registros de recursos TLSA, ver RFC 6698[4]. Se realizará una consulta para cada uno de los nombres especificados prefijados con el puerto y la familia ("_puerto._familia.dominio"). El número de puerto puede especificarse después de dos puntos (":"), de lo contrario, se utilizará 443 por defecto. La familia puede especificarse como el primer argumento, de lo contrario se utilizará tcp.

Añadido en la versión 239.

status [ENLACE...]

Muestra la configuración DNS global y por enlace que está actualmente en vigor. Si no se especifica ningún comando, este es el predeterminado implícito.

Añadido en la versión 239.

statistics

Muestra estadísticas generales del resolvedor, incluida información sobre si DNSSEC está habilitado y disponible, así como estadísticas de resolución y validación.

Añadido en la versión 239.

reset-statistics

Restablece los contadores de estadísticas que se muestran en statistics a cero. Esta operación requiere privilegios de root.

Añadido en la versión 239.

flush-caches

Vacía todas las cachés de registros de recursos DNS que mantiene el servicio localmente. Esto es en gran medida equivalente a enviar la señal SIGUSR2 al servicio systemd-resolved.

Añadido en la versión 239.

reset-server-features

Vacía toda la información del nivel de características que el resolvedor aprendió sobre servidores específicos, y asegura que la lógica de sondeo de características del servidor se reinicie desde el principio con la próxima solicitud de búsqueda. Esto es en gran medida equivalente a enviar la señal SIGRTMIN+1 al servicio systemd-resolved.

Añadido en la versión 239.

dns [ENLACE [SERVIDOR...]], domain [ENLACE [DOMINIO...]], default-route [ENLACE [BOOL...]], llmnr [ENLACE [MODO]], mdns [ENLACE [MODO]], dnssec [ENLACE [MODO]], dnsovertls [ENLACE [MODO]], nta [ENLACE [DOMINIO...]]

Obtener/establecer configuración DNS por interfaz. Estos comandos se pueden usar para configurar varias configuraciones DNS para interfaces de red. Estos comandos se pueden usar para informar a systemd-resolved o systemd-networkd sobre la configuración DNS por interfaz determinada a través de medios externos. El comando dns espera especificaciones de direcciones IPv4 o IPv6 de servidores DNS a utilizar. Cada dirección puede tomar opcionalmente un número de puerto separado por ":", un nombre o índice de interfaz de red separado por "%", y una Indicación de Nombre de Servidor (SNI) separada por "#". Cuando se especifica una dirección IPv6 con un número de puerto, la dirección debe estar entre corchetes. Es decir, los formatos completos aceptables son "111.222.333.444:9953%ifname#ejemplo.com" para IPv4 y "[1111:2222::3333]:9953%ifname#ejemplo.com" para IPv6. El comando domain espera dominios DNS válidos, posiblemente prefijados con "~", y configura un dominio de búsqueda o solo ruta por interfaz. El comando default-route espera un parámetro booleano y configura si el enlace puede usarse como ruta predeterminada para búsquedas DNS, es decir, si es adecuado para búsquedas de dominios para los que ningún otro enlace está configurado explícitamente. Los comandos llmnr, mdns, dnssec y dnsovertls se pueden usar para configurar los ajustes LLMNR, MulticastDNS, DNSSEC y DNSOverTLS por interfaz. Finalmente, el comando nta se puede usar para configurar dominios NTA DNSSEC adicionales por interfaz.

Los comandos dns, domain y nta pueden tomar una única cadena vacía como argumento para borrar sus respectivas listas de valores.

Para obtener detalles sobre estas configuraciones, sus valores posibles y su efecto, consulte las configuraciones correspondientes en systemd.network(5).

Añadido en la versión 239.

revert ENLACE

Revierte la configuración DNS por interfaz. Si la configuración DNS se revierte, todas las configuraciones DNS por interfaz se restablecen a sus valores predeterminados, deshaciendo todos los efectos de dns, domain, default-route, llmnr, mdns, dnssec, dnsovertls, nta. Tenga en cuenta que cuando desaparece una interfaz de red, toda la configuración se pierde automáticamente; en ese caso, no es necesario revertir explícitamente.

Añadido en la versión 239.

monitor

Muestra un flujo continuo de consultas de resolución de clientes locales y sus respuestas. Cada vez que se completa una consulta local, se muestra la clave de registro de recursos DNS de la consulta y los registros de recursos. Tenga en cuenta que esto muestra solo las consultas emitidas localmente y no se relaciona inmediatamente con las solicitudes DNS enviadas a los servidores DNS configurados o a las zonas LLMNR o MulticastDNS, ya que las búsquedas pueden responderse desde la caché local, o podrían resultar en múltiples transacciones DNS (por ejemplo, para validar información DNSSEC). Si se siguen cadenas de redireccionamiento CNAME/CNAME, se mostrará una consulta separada para cada elemento de la cadena. Use --json= para habilitar la salida JSON.

Añadido en la versión 252.

show-cache

Muestra

cómo el contenido actual de la caché, por ámbito. Usa --json= para habilitar la salida JSON.

Añadido en la versión 254.

show-server-state

Muestra información detallada del estado del servidor, por Servidor DNS. Usa --json= para habilitar la salida JSON.

Añadido en la versión 255.

log-level [LEVEL]

Si no se proporciona ningún argumento, imprime el nivel de registro actual del gestor. Si se proporciona un argumento opcional LEVEL, el comando cambia el nivel de registro actual del gestor a LEVEL (acepta los mismos valores que --log-level= descritos en systemd(1)).

Añadido en la versión 244.

OPCIONES

-4, -6

Por defecto, al resolver un nombre de host, se obtienen tanto direcciones IPv4 como IPv6. Especificando -4 solo se solicitan direcciones IPv4, especificando -6 solo se solicitan direcciones IPv6.

Añadido en la versión 239.

-i INTERFACE, --interface=INTERFACE

Especifica la interfaz de red en la que ejecutar la consulta. Esto puede especificarse como índice numérico de interfaz o como cadena de interfaz de red (p. ej. "en0"). Tenga en cuenta que esta opción no tiene efecto si se utiliza la configuración DNS a nivel de sistema (como se configura en /etc/resolv.conf o /etc/systemd/resolved.conf) en lugar de la configuración por enlace.

Añadido en la versión 239.

-p PROTOCOL, --protocol=PROTOCOL

Especifica el protocolo de red para la consulta. Puede ser uno de "dns" (es decir, DNS unicast clásico), "llmnr" (Resolución de nombres multicast de enlace local[5]), "llmnr-ipv4", "llmnr-ipv6" (LLMNR a través de los protocolos IP subyacentes indicados), "mdns" (DNS multicast[6]), "mdns-ipv4", "mdns-ipv6" (MDNS a través de los protocolos IP subyacentes indicados). Por defecto, la búsqueda se realiza a través de todos los protocolos adecuados para la búsqueda. Si se utiliza, limita el conjunto de protocolos que pueden usarse. Utilice esta opción varias veces para habilitar la resolución a través de múltiples protocolos al mismo tiempo. La configuración "llmnr" es idéntica a especificar este interruptor una vez con "llmnr-ipv4" y una vez a través de "llmnr-ipv6". Tenga en cuenta que esta opción no obliga al servicio a resolver la operación con el protocolo especificado, ya que eso podría requerir una interfaz de red y una configuración adecuadas. El valor especial "help" puede usarse para listar los valores conocidos.

Añadido en la versión 239.

-t TYPE, --type=TYPE, -c CLASS, --class=CLASS

Cuando se utiliza junto con el comando query, especifica el tipo de registro de recursos DNS (p. ej. A, AAAA, MX, ...) y la clase (p. ej. IN, ANY, ...) a buscar. Si se utilizan estas opciones, se solicita un conjunto de registros de recursos DNS que coincida con la clase y el tipo especificados. La clase se establece por defecto en IN si solo se especifica un tipo. El valor especial "help" puede usarse para listar los valores conocidos.

Sin estas opciones, resolvectl query proporciona resolución de nombres de dominio a direcciones y de direcciones a nombres de dominio de alto nivel. Con estas opciones, proporciona resolución de registros de recursos DNS de bajo nivel. La lógica del dominio de búsqueda se desactiva automáticamente cuando se utilizan estas opciones, es decir, los nombres de dominio especificados deben ser nombres de dominio completamente calificados. Además, la traducción interna de nombres de dominio IDNA también se desactiva, es decir, los nombres de dominio internacionales deben especificarse en notación "xn--...", a menos que se desee buscar en MulticastDNS/LLMNR, en cuyo caso se deben usar caracteres UTF-8.

Añadido en la versión 239.

--service-address=BOOL

Acepta un parámetro booleano. Si es verdadero (el valor por defecto), al realizar una búsqueda de servicio con --service, los nombres de host contenidos en los registros de recursos SRV también se resuelven.

Añadido en la versión 239.

--service-txt=BOOL

Acepta un parámetro booleano. Si es verdadero (el valor por defecto), al realizar una búsqueda de servicio DNS-SD con --service, el registro de metadatos de servicio TXT también se resuelve.

Añadido en la versión 239.

--cname=BOOL

Acepta un parámetro booleano. Si es verdadero (el valor por defecto), se siguen las redirecciones CNAME o DNAME de DNS. De lo contrario, si se encuentra un registro CNAME o DNAME durante la resolución, se devuelve un error.

Añadido en la versión 239.

--validate=BOOL

Acepta un parámetro booleano; se utiliza junto con query. Si es verdadero (el valor por defecto), la validación DNSSEC se aplica como de costumbre — bajo la condición de que esté habilitada para la red y para systemd-resolved.service en su conjunto. Si es falso, la validación DNSSEC se deshabilita para la consulta específica, independientemente de si está habilitada para la red o en el servicio. Tenga en cuenta que establecer esta opción en verdadero no fuerza la validación DNSSEC en sistemas/redes donde DNSSEC está desactivado. Esta opción solo es adecuada para desactivar dicha validación donde está habilitada, no para habilitar la validación donde está deshabilitada.

Añadido en la versión 248.

--synthesize=BOOL

Acepta un parámetro booleano; se utiliza junto con query. Si es verdadero (el valor por defecto), se resuelven dominios seleccionados en el sistema local, entre ellos "localhost", "_gateway", "_outbound", "_localdnsstub" y "_localdnsproxy" o entradas de /etc/hosts. Si es falso, estos dominios no se resuelven localmente, y o bien fallan (en el caso de "localhost", "_gateway" o "_outbound" y similares) o van a la red a través de búsquedas DNS/mDNS/LLMNR normales (en el caso de entradas de /etc/hosts).

Añadido en la versión 248.

--cache=BOOL

Acepta un parámetro booleano; se utiliza junto con query. Si es verdadero (el valor por defecto), las búsquedas utilizan la caché local de registros de recursos DNS. Si es falso, las búsquedas se enrutan a la red en su lugar, independientemente de si ya están disponibles en la caché local.

Añadido en la versión 248.

--zone=BOOL

Acepta un parámetro booleano; se utiliza junto con query. Si es verdadero (el valor por defecto), las búsquedas se responden a partir de registros de recursos LLMNR o mDNS registrados localmente, si están definidos. Si es falso, los registros LLMNR/mDNS registrados localmente no se consideran para la solicitud de búsqueda.

Añadido en la versión 248.

--trust-anchor=BOOL

Acepta un parámetro booleano; se utiliza junto con query. Si es verdadero (el valor por defecto), las búsquedas de DS y DNSKEY se responden a partir de los anclajes de confianza DNSSEC locales si es posible. Si es falso, el almacén de confianza local no se considera para la solicitud de búsqueda.

Añadido en la versión 248.

--network=BOOL

Acepta un parámetro booleano; se utiliza junto con query. Si es verdadero (el valor por defecto), las búsquedas se responden a través de solicitudes de red DNS, LLMNR o mDNS si no se pueden sintetizar localmente, o responder desde la caché local, zona o anclajes de confianza (ver arriba). Si es falso, la solicitud no se responde desde la red y, por lo tanto, fallará si ninguna de las fuentes indicadas puede responderlas.

Añadido en la versión 248.

--search=BOOL

Acepta un parámetro booleano. Si es verdadero (el valor por defecto), los nombres de host de etiqueta única especificados se buscarán en los dominios configurados en la lista de dominios de búsqueda, si no está vacía. De lo contrario, la lógica del dominio de búsqueda se deshabilita. Tenga en cuenta que esta opción no tiene efecto si se utiliza --type= (ver arriba), en cuyo caso la lógica del dominio de búsqueda se desactiva incondicionalmente.

Añadido en la versión 239.

--raw[=payload|packet]

Descarga los registros de respuesta como datos binarios. Si no hay argumento o si el argumento es "payload", se exporta la carga útil de los datos del registro de recursos, es decir, no toda la "RDATA", sino solo el contenido principal. Si el argumento es "packet", se descarga todo el registro de recursos en formato de cable, precedido por la longitud especificada como un entero de 64 bits little-endian. Este formato permite descargar y analizar varios registros de forma inequívoca.

Tenga en cuenta que "payload" solo es compatible con un pequeño subconjunto de tipos de registros de recursos: SSHFP, TLSA, OPENPGPKEY, donde se descargan solo los datos de la clave; y A, AAAA, donde se descargan los datos de la dirección.

Añadido en la versión 239.

--legend=BOOL

Acepta un parámetro booleano. Si es verdadero (el valor por defecto), se muestran las cabeceras de columna y la metainformación sobre la respuesta de la consulta. De lo contrario, esta salida se suprime.

Añadido en la versión 239.

--stale-data=BOOL

Acepta un parámetro booleano; se utiliza junto con query. Si es verdadero (el valor por defecto), las búsquedas se responden con datos obsoletos (registros de recursos caducados) si es posible. Si es falso, los datos obsoletos no se consideran para la solicitud de búsqueda.

Añadido en la versión 254.

--relax-single-label=BOOL

Acepta un parámetro booleano; se utiliza junto con query. Si es verdadero, las reglas relativas al enrutamiento de nombres de etiqueta única se relajan. Por defecto es falso. Por defecto, se supone que las búsquedas de nombres de etiqueta única se refieren a hosts locales que se resolverán mediante resolución local como LLMNR o mediante la calificación del dominio de búsqueda, y no se enrutan a servidores superiores tal como están. Si se habilita esta opción, estas reglas se deshabilitan y las consultas se enrutan de todos modos a servidores superiores. Consulte también la opción ResolveUnicastSingleLabel= en resolved.conf(5), que proporciona una opción a nivel de sistema que controla este comportamiento.

Añadido en la versión 256.

--no-ask-password

No consultar al usuario para autenticación en operaciones privilegiadas.

--json=MODE

Muestra la salida formateada como JSON. Espera uno de los siguientes valores: "short" (para la salida más corta posible sin espacios en blanco redundantes ni saltos de línea), "pretty" (para una versión formateada de la misma, con indentación y saltos de línea) o "off" (para desactivar la salida JSON, el valor por defecto).

-j

Equivalente a --json=pretty si se ejecuta en una terminal, y --json=short en caso contrario.

--no-pager

No canalizar la salida a un paginador.

-h, --help

Imprime un breve texto de ayuda y sale.

--version

Imprime una breve cadena de versión y sale.

resolvectl(1) - Arch Linux

NAME

resolvectl - Control parte de systemd-resolved.service

SYNOPSIS

/usr/bin/resolvectl -h | --help

/usr/bin/resolvectl --version

/usr/bin/resolvectl [-a | -d | -f | -x | -p] [-m] [-i] INTERFACE...

/usr/bin/resolvectl OPERATION

/usr/bin/resolvectl OPERATION ARGUMENT...

DESCRIPTION

resolvectl es una utilidad para interrogar y controlar el comportamiento del demonio de resolución de nombres de red de systemd, systemd-resolved.service(8). Se puede usar para mostrar la configuración de DNS actual, así como para realizar consultas de DNS.

También se puede usar para configurar perfiles de resolución de nombres para las interfaces de red individuales. El cliente de red de systemd se puede configurar para que informe a systemd-resolved.service(8) sobre la información de resolución de nombres de cada interfaz, y resolvectl se puede usar para invocar esta funcionalidad.

El archivo /etc/resolv.conf se puede vincular a /run/systemd/resolve/resolv.conf. Si es así, systemd-resolved.service(8) se encarga de mantener el archivo actualizado. Ver la discusión de /etc/resolv.conf en systemd-resolved.service(8).

Si no se proporciona ninguna opción de línea de comandos, resolvectl se ejecutará en modo interactivo y mostrará la información de la interfaz de red y los servidores DNS configurados.

COMMANDS

Las siguientes operaciones están disponibles:

query HOSTNAME...

Realiza una consulta de DNS para el HOSTNAME dado. Muestra los registros de recursos A, AAAA y PTR.

Se admiten varias opciones de consulta: MX, TXT, SRV, SPF, CNAME, NS, SOA, PTR, AAAA, A, CAA, DS, DNSKEY, NSEC, NSEC3, NSEC3PARAM, OPENPGPKEY, CERT, TLSA, SSHFP, SVCB, HTTPS, URI, NULL, WKS, RP, X25, ISDN, RTEX, NSAP, NSAP-NET, IPSECKEY, TKEY, TSIG, IXFR, AXFR, ANY. La mayoría de estas son alias para el tipo de registro de DNS genérico o específico. Por ejemplo, usar MX como operación es similar a usar query --type=MX.

Si se prefieren los resultados de DNSSEC, se puede usar la opción --dnssec.

domain [DOMAIN]...

Consulta el dominio de búsqueda o el nombre de dominio del dominio de búsqueda predeterminado, o establece uno nuevo si se proporcionan argumentos.

servers [--no-pager] [--legend=yes|no] [--type=yes|no] [-a|-4|-6] [--json]

Muestra los servidores DNS configurados para todas las interfaces de red, o para las interfaces especificadas. Se muestra la siguiente información:

El nombre de la interfaz, su dominio de búsqueda o nombre de dominio, los servidores DNS configurados, y el dominio de búsqueda de DNS global. Si el servidor DNS también se usa para la búsqueda de dominios locales, se indica también.

Si se especifica la opción --json, la salida se formatea como JSON.

status [--json]

Muestra el estado actual de systemd-resolved.service(8). Esto incluye la lista de interfaces de red con las que se ha configurado, los servidores DNS y los dominios de búsqueda utilizados, y el estado general del servicio.

Si se especifica la opción --json, la salida se formatea como JSON.

flush-caches [--all]

Vacía la caché de DNS de systemd-resolved.service(8). Si se especifica --all, también se vacían las cachés de todas las interfaces de red.

revert [INTERFACE]...

Elimina toda la información de resolución de nombres de la interfaz especificada. Si no se especifica ninguna interfaz, se revierten todas las interfaces configuradas.

default-route [--no-pager] [--legend=yes|no] [--json]

Muestra las interfaces que se utilizan como ruta de acceso predeterminada para el tráfico DNS. Solo puede haber una ruta predeterminada. Si se usa un servidor DNS que no está en la ruta predeterminada, se configurará automáticamente como ruta predeterminada. Si se usa un servidor DNS en la ruta predeterminada, se puede usar para la resolución de todos los dominios.

Si se especifica la opción --json, la salida se formatea como JSON.

network

Muestra la información de red de todas las interfaces de red actualmente conocidas por systemd-resolved.service(8).

log-level [LEVEL]

Establece el nivel de registro para systemd-resolved.service(8). Los niveles de registro válidos son emerg, alert, crit, err, warning, notice, info, debug.

log-color [yes|no]

Establece si los mensajes de registro deben colorearse.

service-type

Muestra el tipo de servicio de la implementación de la API de resolución de nombres.

OPTIONS

Se admiten las siguientes opciones de línea de comandos:

-h, --help
Muestra un breve resumen de uso y sale.
--version
Muestra la versión de la distribución y sale.
-a
Solo se usa con el modo de compatibilidad resolvconf(8). Registra datos de configuración DNS por interfaz con systemd-resolved.service(8). Lee datos de configuración DNS compatibles con resolv.conf(5) de la entrada estándar.
-d
Solo se usa con el modo de compatibilidad resolvconf(8). Anula el registro de datos de configuración DNS por interfaz con systemd-resolved.service(8).
-f
Solo se usa con el modo de compatibilidad resolvconf(8). Cuando se especifica -a y -d, no se quejarán de interfaces de red faltantes y ejecutarán silenciosamente ninguna operación en ese caso.
-x
Solo se usa con el modo de compatibilidad resolvconf(8). Este interruptor para operación "exclusiva" solo se admite parcialmente. Se mapea a un dominio de búsqueda configurado adicional de "~.".
-p
Solo se usa con el modo de compatibilidad resolvconf(8). Cuando se especifica, la interfaz no se usará como ruta predeterminada.
-m
Solo se usa con el modo de compatibilidad resolvconf(8). El interruptor no se admite y se ignora silenciosamente.
-i, --interface=INTERFACE
Solo se usa con el modo de compatibilidad resolvconf(8). Especifica la interfaz de red para la que se deben aplicar las configuraciones DNS. Si no se especifica, se utilizará la interfaz predeterminada.
-C, --type=TYPE
Especifica el tipo de registro de recursos DNS que se consultará. Si no se especifica, se asumirá A y AAAA. Véase RFC 1035 para la lista completa de tipos de registros de recursos.
-t, --timeout=SECONDS
Establece el tiempo de espera para las consultas DNS. Si no se especifica, se utiliza un valor predeterminado de 10 segundos.
-T, --dnssec
Habilita la resolución de DNSSEC. Si se especifica, las respuestas DNS se validarán usando DNSSEC. Si la validación falla, la respuesta se considerará no válida.
--legend=yes|no
Controla si se muestra la leyenda de la salida.
--json[=MODE]
Muestra la salida en formato JSON. El modo puede ser simple o pretty.

COMPATIBILITY WITH RESOLVCONF(8)

resolvectl es un binario multi-llamada. Cuando se invoca como "resolvconf" (generalmente logrado por medio de un enlace simbólico de este nombre al binario resolvectl) se ejecuta en un modo de compatibilidad limitado de resolvconf(8). Acepta la mayoría de los mismos argumentos y empuja todos los datos a systemd-resolved.service(8), similar a cómo funcionan los comandos dns y domain. Tenga en cuenta que systemd-resolved.service es el único backend compatible, lo que es diferente de otras implementaciones de este comando.

El archivo /etc/resolv.conf solo se actualizará con los servidores añadidos con este comando cuando /etc/resolv.conf sea un enlace simbólico a /run/systemd/resolve/resolv.conf, y no un archivo estático. Ver la discusión del manejo de /etc/resolv.conf en systemd-resolved.service(8).

No todas las operaciones admitidas por otras implementaciones son admitidas de forma nativa. Específicamente:

-a

Registra datos de configuración DNS por interfaz con systemd-resolved. Espera un nombre de interfaz de red como único argumento de línea de comandos. Lee datos de configuración DNS compatibles con resolv.conf(5) de su entrada estándar. Los campos relevantes son "nameserver" y "domain"/"search". Este comando es en su mayoría idéntico a invocar resolvectl con una combinación de comandos dns y domain.

Añadido en la versión 239.

-d

Anula el registro de datos de configuración DNS por interfaz con systemd-resolved. Este comando es en su mayoría idéntico a invocar resolvectl revert.

Añadido en la versión 239.

-f

Cuando se especifica -a y -d no se quejarán de interfaces de red faltantes y ejecutarán silenciosamente ninguna operación en ese caso.

Añadido en la versión 239.

-x

Este interruptor para operación "exclusiva" solo se admite parcialmente. Se mapea a un dominio de búsqueda configurado adicional de "~." — i.e. asegura que el tráfico DNS se enrute preferentemente a los servidores DNS en esta interfaz, a menos que haya otros dominios más específicos configurados en otras interfaces.

Añadido en la versión 239.

-p

Cuando se especifica, la interfaz no se usará como ruta predeterminada. Ver también systemd-resolved.service(8) sobre la ruta predeterminada.

Añadido en la versión 257.

-m

El interruptor no se admite y se ignora silenciosamente.

Añadido en la versión 239.

-u, -I, -i, -l, -R, -r, -v, -V, --enable-updates, --disable-updates, --are-updates-enabled

Estos interruptores no se admiten y el comando fallará si se usan.

Añadido en la versión 239.

Ver resolvconf(8) para detalles sobre esas opciones de línea de comandos.

Ejemplo 1. Recuperar las direcciones del dominio "www.0pointer.net" (registros de recursos A y AAAA)

$ resolvectl query www.0pointer.net
www.0pointer.net: 2a01:238:43ed:c300:10c3:bcf3:3266:da74
                  85.214.157.71
-- Información adquirida a través del protocolo DNS en 611.6ms.
-- Datos autenticados: no

Ejemplo 2. Recuperar el dominio de la dirección IP "85.214.157.71" (registro de recursos PTR)

$ resolvectl query 85.214.157.71
85.214.157.71: gardel.0pointer.net
-- Información adquirida a través del protocolo DNS en 1.2997s.
-- Datos autenticados: no

Ejemplo 3. Recuperar el registro MX del dominio "yahoo.com"

$ resolvectl --legend=no -t MX query yahoo.com
yahoo.com. IN MX    1 mta7.am0.yahoodns.net
yahoo.com. IN MX    1 mta6.am0.yahoodns.net
yahoo.com. IN MX    1 mta5.am0.yahoodns.net

Ejemplo 4. Resolver un servicio SRV

$ resolvectl service _xmpp-server._tcp gmail.com
_xmpp-server._tcp/gmail.com: alt1.xmpp-server.l.google.com:5269 [prioridad=20, peso=0]
                             173.194.210.125
                             alt4.xmpp-server.l.google.com:5269 [prioridad=20, peso=0]
                             173.194.65.125
                             ...

Ejemplo 5. Recuperar una clave PGP (registro de recursos OPENPGP)

$ resolvectl openpgp zbyszek@fedoraproject.org
d08ee310438ca124a6149ea5cc21b6313b390dce485576eff96f8722._openpgpkey.fedoraproject.org. IN OPENPGPKEY
        mQINBFBHPMsBEACeInGYJCb+7TurKfb6wGyTottCDtiSJB310i37/6ZYoeIay/5soJjlMyf
        MFQ9T2XNT/0LM6gTa0MpC1st9LnzYTMsT6tzRly1D1UbVI6xw0g0vE5y2Cjk3xUwAynCsSs
        ...

Ejemplo 6. Recuperar una clave TLS (registro de recursos TLSA)

$ resolvectl tlsa tcp fedoraproject.org:443
_443._tcp.fedoraproject.org IN TLSA 0 0 1 19400be5b7a31fb733917700789d2f0a2471c0c9d506c0e504c06c16d7cb17c0
        -- Uso del Certificado: Restricción de CA
        -- Selector: Certificado Completo
        -- Tipo de Coincidencia: SHA-256

"tcp" y ":443" son opcionales y podrían omitirse.
