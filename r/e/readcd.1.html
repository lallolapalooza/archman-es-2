READCD(1) COMANDOS DE USUARIO de Schily READCD(1)

NOMBRE

readcd - leer o escribir datos en Compact Disc u otros medios relacionados

SINOPSIS

readcd [ dev=dispositivo ][ opciones ]

DESCRIPCIÓN

Readcd se utiliza para leer o escribir Compact Disc.

Nomenclatura de dispositivos

La mayoría de los usuarios no necesitan preocuparse por la nomenclatura de dispositivos. Si no se especificó la opción dev=, readcd implementa el soporte de auto target y encuentra automáticamente la unidad si solo hay una unidad tipo CD-ROM disponible en el sistema. En caso de que existan más de una unidad tipo CD-ROM en el sistema, una lista de posibles nombres de dispositivos se puede obtener con readcd -scanbus o del ejemplo de destino de la salida de readcd dev=help, luego el parámetro dev= puede establecerse basándose en la lista de dispositivos.

El parámetro dispositivo de la opción dev= explicada a continuación se refiere a la notación estándar SCSI CAM de bus_scsi/target/lun del Grabador de CD/DVD/Blu-ray. Si existe un archivo /etc/default/cdrecord, el parámetro de la opción dev= también puede ser una etiqueta de nombre de unidad en dicho archivo (ver sección ARCHIVOS).

OPCIONES

Si no se han especificado opciones excepto la opción dev=, readcd entra en modo interactivo. Seleccione una función principal y siga las instrucciones.

Opciones informativas

-help
muestra información de la versión de readcd en la salida estándar.
-version
Imprime la información de la versión y sale.
-v
Incrementa el nivel de verbosidad general en uno. Esto se usa, por ejemplo, para mostrar el progreso del proceso.

Opciones funcionales de Readcd

-clone
Realiza una lectura de clonación. Lee el CD con todos los datos del subcanal y una TOC completa. Los datos completos de la TOC se guardarán en un archivo con un nombre similar al de la opción f= pero con el sufijo .toc añadido.

Tenga en cuenta que leer en modo clone resulta en la ausencia de corrección de errores a nivel de subcanal. Incluso en el canal de datos principal, hay menos corrección de errores que con otros modos de lectura. Esto resulta en una ligera degradación de la calidad. Evite copiar CDs de audio en modo clone por esta razón.

-c2scan
Escanea todo el CD o el rango especificado por sectores=rango en busca de errores C2. Los errores C2 son errores que son irremediables después de la segunda etapa del sistema de corrección Reed Solomon de 24/28 + 28/32 a nivel de audio (tamaño de sector de 2352 bytes). Si un CD de audio tiene errores C2, se necesita interpolación para ocultar los errores. Si un CD de datos tiene errores C2, estos errores son corregidos en la mayoría de los casos por el código ECC/EDC que crea 2352 bytes a partir de 2048 bytes de datos. El código ECC/EDC debería poder corregir alrededor de 100 bytes de error C2 por sector.

Si encuentra errores C2, es posible que desee reducir la velocidad utilizando la opción speed=, ya que los errores C2 pueden ser el resultado de un desequilibrio dinámico en el medio.

-cxscan
Escanea todo el CD o el rango especificado por sectores=rango en busca de errores C1/C2/CU. En modo no verboso, solo se imprime un resumen. Con -v, se imprime una línea por cada segundo no libre de errores. Con -vv, se imprime una línea por cada segundo. Este método de escaneo solo funciona para unas pocas unidades.
-edc-corr
En este modo, readcd lee sectores de datos de CD en modo de audio sin corregir y luego intenta corregir los datos utilizando la biblioteca del decodificador ECC/EDC de Heiko Eissfeldt. Como esta biblioteca implementa bucles sobre dos capas de corrección de errores, readcd puede ser capaz de corregir más datos que el firmware de la unidad de CD-ROM.

Esta opción es actualmente experimental y solo aplicable a medios de CD y actualmente solo admite sectores de CD-ROM de 2048 bytes planos.

f=archivo
Especifica el nombre del archivo donde se escribirán los datos de salida o de donde se tomarán los datos de entrada. Usar '-' como nombre de archivo hará que readcd use stdout o stdin respectivamente.
-factor
Muestra los valores de velocidad para meshpoints=# como un factor basado en la velocidad simple del medio actual. Esto solo funciona si readcd puede determinar el tipo de medio actual.
-fulltoc
Recupera una TOC completa del disco actual y la imprime en formato hexadecimal.
meshpoints=#
Imprime la velocidad de lectura en # ubicaciones. El propósito de esta opción es crear una lista de valores de velocidad de lectura adecuados para, por ejemplo, gnuplot. Los valores de velocidad se calculan asumiendo que 1000 bytes son un kilobyte, como se documenta en el estándar SCSI. Los datos de salida creados para este propósito se escriben en stdout.
-nocorr
Cambia la unidad a un modo donde ignora los errores de lectura en los sectores de datos que son resultado de errores ECC/EDC no corregibles antes de leer. Si readcd finaliza, el modo de recuperación de errores de la unidad se cambia de nuevo al modo antiguo recordado.
-noerror
No abortar si la comprobación de errores de alto nivel en readcd encontró un error no corregible en el flujo de datos.
-notrunc
No truncar el archivo de salida al abrirlo.
-overhead
Mide el tiempo de sobrecarga de los comandos SCSI. Esto se hace ejecutando varios comandos 1000 veces y mostrando el tiempo total utilizado. Si divide los tiempos mostrados por 1000, obtendrá el tiempo promedio de sobrecarga para un solo comando.
-pi8scan
Escanea todo el DVD o el rango especificado por sectores=rango en busca de errores pisum8. En modo no verboso, solo se imprime un resumen. Con -v, se imprime una línea por cada bloque no libre de errores de 8 * 32 kB. Con -vv, se imprime una línea por cada bloque de 8 * 32 kB. Este método de escaneo solo funciona para unas pocas unidades.
-pifscan
Escanea todo el DVD o el rango especificado por sectores=rango en busca de errores pif. En modo no verboso, solo se imprime un resumen. Con -v, se imprime una línea por cada bloque no libre de errores de 32 kB. Con -vv, se imprime una línea por cada bloque de 32 kB. Este método de escaneo solo funciona para unas pocas unidades.
-plot
Esta opción modifica el comportamiento de -cxscan, -pi8scan y -pifscan. La salida es más adecuada para gnuplot.
retries=#
Establece el número de reintentos para reintentos de alto nivel en readcd a #. El valor predeterminado es realizar 128 reintentos, lo que puede ser demasiado si desea leer un CD con muchos sectores ilegibles.
sectores=rango
Especifica un rango de sectores que debe leerse. El rango se especifica por el número del sector de inicio, un guion y el número del sector final. El sector final no está incluido en la lista, por lo que sectors=0-0 no leerá nada y puede usarse para verificar si hay un CD en la unidad.
speed=#
Establece el factor de velocidad del proceso de lectura o escritura a #. # es un entero, que representa un múltiplo de la velocidad de audio. Esto es aproximadamente 150 KB/s para CD-ROM y aproximadamente 172 KB/s para CD-Audio. Si no hay una opción de speed, readcd usará la velocidad máxima. Solo las unidades compatibles con MMC se beneficiarán de esta opción. La velocidad de las unidades no MMC no se modifica.

Usar una velocidad más baja puede aumentar la legibilidad de un CD o

OPTIONS

f=filename
File name of the image file that should be written to the media or from which the media should be read. If the filename is a dash (-), stdin or stdout is used.

Note that the default file name for reading is stdout and the default file name for writing is stdin.

-v
Increment the verbosity level by one. Verbose output may help to debug problems.
-V
Increment the verbosity level of the SCSI command transport layer by one. This option may be used to debug problems that occur in the CD-Recorder. Using -VV will show data buffer content in addition. Using -V or -VV slows down the process.
-Z
Perform a test write. Only the write command is executed, no data is written. This option may be used to test the CD-Recorder hardware and software. Note that this option is only supported for DVD-RAM media.
-c
Check if the CD-ROM drive is write-enabled. Return 0 if the drive is write-enabled, non-zero otherwise.
-d
Enable the debug mode. This option is obsolete, please use debug= instead.
debug=#
Set the misc debug value to #. This option may be used to debug problems while opening a driver for libscg, or with sector sizes and sector types. Using -debug slows down the process and may be the reason for a buffer underrun.
driver=drivername
Use the specified driver. The driver name is implemented specific. Use -prcap to get a list of supported drivers.
-eject
Eject the media after the operation is complete.
eject={yes|no}
Enable or disable ejecting the media after the operation is complete. Note that this option overrides the -eject option.
-G
Use the generic ATAPI driver. This option is obsolete, please use driver=native instead.
-h
Print a short usage message and exit.
-help
Print a detailed help message and exit.
I={yes|no}
Enable or disable the Isochronous mode. This option is used for reading from CD-ROMs and may help to avoid buffer underruns. The default is no.
kdebug=#, kd=#
Tell the scg-driver to modify the kernel debug value while SCSI commands are running.
m={mode|help}
Set the media type. If mode is help, a list of supported media types is printed. This option is only relevant for DVD-RAM media.
-overwrite
Overwrite the media. This option is only relevant for DVD-RAM media.
-prcap
Print the capabilities of the CD-ROM drive and exit.
-pq
Print the format capabilities of the CD-ROM drive and exit.
-quiet
Disable printing of status reports for failed SCSI commands.
-r
Switch to read mode. If this option is not present, readcd reads from the specified device.
-reset
Reset the CD-ROM drive before starting the operation.
s=#
Set the sector size to #. The default sector size is 2048 bytes. This option is only relevant for DVD-RAM media.
-silent, -s
Do not print out a status report for failed SCSI commands.
-test
Perform a test run. Only the commands that are necessary to perform the operation are executed, but no data is read or written. This option may be used to test the CD-ROM drive hardware and software.
timeout=#
Set the default SCSI command timeout value to # seconds. The default SCSI command timeout is the minimum timeout used for sending SCSI commands. If a SCSI command fails due to a timeout, you may try to raise the default SCSI command timeout above the timeout value of the failed command. If the command runs correctly with a raised command timeout, please report the better timeout value and the corresponding command to the author of the program. If no timeout option is present, a default timeout of 40 seconds is used.
ts=#
Set the maximum transfer size for a single SCSI command to #. The syntax for the ts= option is the same as for cdrecord fs=# or sdd bs=#.

If no ts= option has been specified, readcd defaults to a transfer size of 256 kB. If libscg gets lower values from the operating system, the value is reduced to the maximum value that is possible with the current operating system. Sometimes, it may help to further reduce the transfer size or to enhance it, but note that it may take a long time to find a better value by experimenting with the ts= option.

-w
Switch to write mode. Writing is only possible to DVD-RAM media. For other media, use cdrecord instead. Note that cdrecord also supports to write DVD-RAM media.

If this option is not present, readcd reads from the specified device.

SCSI options

dev=target
Set the SCSI target for the CD/DVD/BluRay-Recorder, see notes above. A typical target device specification is dev=1,6,0 . If a filename must be provided together with the numerical target specification, the filename is implementation specific. The correct filename in this case can be found in the system specific manuals of the target operating system. On a FreeBSD system without CAM support, you need to use the control device (e.g. /dev/rcd0.ctl). A correct device specification in this case may be dev=/dev/rcd0.ctl:@ .

General SCSI addressing
The target device to the dev= option refers to the SCSI CAM standard notation for scsibus/target/lun of the CD/DVD/BluRay-Recorder. Communication on SunOS is done with the SCSI general driver scg. Other operating systems are using a library simulation of this driver. Possible syntax is: dev= scsibus,target,lun or dev= target,lun. In the latter case, the CD/DVD/BluRay-Recorder has to be connected to the default SCSI bus of the machine. Scsibus, target and lun are integer numbers. Some operating systems or SCSI transport implementations may require to specify a filename in addition. In this case the correct syntax for the device is: dev= devicename:scsibus,target,lun or dev= devicename:target,lun. If the name of the device node that has been specified on such a system refers to exactly one SCSI device, a shorthand in the form dev= devicename:@ or dev= devicename:@,lun may be used instead of dev= devicename:scsibus,target,lun.

Remote SCSI addressing
To access remote SCSI devices, you need to prepend the SCSI device name by a remote device indicator. The remote device indicator is either REMOTE:user@host: or REMOTE:host: A valid remote SCSI device name may be: REMOTE:user@host: to allow remote SCSI bus scanning or REMOTE:user@host:1,0,0 to access the SCSI device at host connected to SCSI bus # 1,target 0, lun 0. In order to allow remote access to a specific host, the rscsi(1) program needs to be present and configured on the host.

Alternate SCSI transports
Cdrecord is completely based on SCSI commands but this is no problem as all CD/DVD/BluRay writers ever made use SCSI commands for the communication. Even ATAPI drives are just SCSI drives that inherently use the ATA packet interface as SCSI command transport layer build into the IDE (ATA) transport. You may need to specify an alternate transport layer on the command line if your OS does not implement a fully integrated kernel driver subsystem that allows to access any drive using SCSI commands via a single unique user interface.

To access SCSI devices via alternate transport layers, you need to prepend the SCSI device name by a transport layer indicator. The transport layer indicator may be something like USCSI: or ATAPI:. To get a list of supported transport layers for your platform, use dev= HELP:

Portability Background
To make readcd portable to all UNIX platforms, the syntax dev= devicename:scsibus,target,lun is preferred as it hides OS specific knowledge about device names from the user. A specific OS may not necessarily support a way to specify a real device file name nor a way to specify scsibus,target,lun.

Scsibus 0 is the default SCSI bus on the machine. Watch the boot messages for more information or look into /var/adm/messages for more information about the SCSI configuration of your machine. If you have problems to figure out what values for scsibus,target,lun should be used, try the -scanbus option of readcd described below.

Using logical names for devices
If no dev option is present, readcd will try to get the device from the CDR_DEVICE environment.

If a file /etc/default/cdrecord exists, and if the argument to the dev= option or the CDR_DEVICE environment does not contain the characters ',', '/', '@' or ':', it is interpreted as a device label name that was defined in the file /etc/default/cdrecord (see FILES section).

Autotarget Mode
If no dev= option and no CDR_DEVICE environment is present, or if it only contains a transport specifyer but no address notation, readcd tries to scan the SCSI address space for CD-ROM drives. If exactly one is found, this is used by default.

-V
Increment the verbose level with respect of SCSI command transport by one. This helps to debug problems during the process, that occur in the CD-Recorder. If you get incomprehensible error messages you should use this flag to get more detailed output. -VV will show data buffer content in addition. Using -V or -VV slows down the process.

EXAMPLES

For all examples below, it will be assumed that the drive is connected to the primary SCSI bus of the machine. The SCSI target id is set to 2.

To read the complete media from a CD-ROM writing the data to the file cdimage.raw:


readcd dev=2,0 f=cdimage.raw

To read sectors from range 150 ... 10000 from a CD-ROM writing the data to the file cdimage.raw:


readcd dev=2,0 sectors=150-10000 f=cdimage.raw

To write the data from the file cdimage.raw (e.g. a filesystem image from mkisofs) to a DVD-RAM, call:


readcd dev=2,0 -w f=cdimage.raw

ENVIRONMENT

RSH
If the RSH environment is present, the remote connection will not be created via rcmd(3) but by calling the program pointed to by RSH. Use e.g. RSH=/usr/bin/ssh to create a secure shell connection.

Note that this forces cdrecord to create a pipe to the rsh(1) program and disallows cdrecord to directly access the network socket to the remote server. This makes it impossible to set up performance parameters and slows down the connection compared to a root initiated rcmd(3) connection.

RSCSI
If the RSCSI environment is present, the remote SCSI server will not be the program /opt/schily/sbin/rscsi but the program pointed to by RSCSI. Note that the remote SCSI server program name will be ignored if you log in using an account that has been created with a remote SCSI server program as login shell.

CÓDIGOS DE SALIDA

Los siguientes códigos de salida se utilizan:

0
No apareció ningún error.
-1
Apareció un error específico. Puede ser un error de uso causado por una línea de comandos ilegal u otro error con un mensaje de error específico del problema de readcd.
-2
Apareció un error no especificado durante el proceso de comunicación con la unidad. Consulte el mensaje de error SCSI para más información. La sección DIAGNÓSTICOS a continuación contiene una explicación sobre cómo leer los mensajes de error SCSI.

Tenga en cuenta que los sistemas operativos y las shells más antiguos pueden no admitir el rango completo de 32 bits del código de salida y enmascarar el valor con 0xFF. Esto da como resultado códigos de salida acortados en el rango de 0..255, donde -1 se mapea a 255.

NOTAS

Si no desea permitir que los usuarios se conviertan en root en su sistema, readcd se puede instalar de forma segura como suid root. Esto permite que todos los usuarios o un grupo de usuarios sin privilegios de root utilicen readcd. En este caso, Readcd solo permitirá el acceso a las unidades de tipo CD-ROM. Para dar acceso a todos los usuarios para usar readcd, ingrese:

chown root /usr/local/bin/readcd
chmod 4711 /usr/local/bin/readcd

Para dar acceso a un grupo restringido de usuarios a readcd, ingrese:

chown root /usr/local/bin/readcd
chgrp cdburners /usr/local/bin/readcd
chmod 4710 /usr/local/bin/readcd

y agregue un grupo cdburners en su sistema.

Nunca otorgue permisos de escritura a usuarios que no sean root para los dispositivos /dev/scg? a menos que permita que cualquiera lea/escriba/formatee todos sus discos.

No debe conectar unidades antiguas que no admitan desconexión/reconexión al bus SCSI conectado a la grabadora de CD o al disco fuente.

Al usar readcd con el controlador genérico SCSI de Linux. Debe tener en cuenta que readcd utiliza una capa que intenta emular la funcionalidad del controlador scg sobre las unidades del sistema operativo local. Desafortunadamente, el controlador sg en Linux tiene varios defectos:

•
No puede saber si un comando SCSI no se pudo enviar en absoluto.
•
No puede obtener el byte de estado SCSI. Por esta razón, Readcd no puede informar comandos SCSI fallidos en algunas situaciones.
•
No puede obtener el recuento de DMA real de la transferencia. Readcd no puede informarle si hay un recuento residual de DMA.
•
No puede obtener el número de bytes válidos en los datos de solicitud de auto-sentido. Readcd no puede informarle si el dispositivo no transfiere ningún dato de sentido.
•
Recupera muy pocos datos en la solicitud de auto-sentido (CCS/SCSI-2/SCSI-3 requiere >= 18).

DIAGNÓSTICOS

Un mensaje de error típico para un comando SCSI se ve así:

readcd: I/O error. test unit ready: scsi sendcmd: no error
CDB:  00 20 00 00 00 00
status: 0x2 (CHECK CONDITION)
Sense Bytes: 70 00 05 00 00 00 00 0A 00 00 00 00 25 00 00 00 00 00
Sense Key: 0x5 Illegal Request, Segment 0
Sense Code: 0x25 Qual 0x00 (logical unit not supported) Fru 0x0
Sense flags: Blk 0 (not valid)
cmd finished after 0.002s timeout 40s
La primera línea proporciona información sobre el transporte del comando. El texto después de los dos puntos es el texto del error para la llamada del sistema desde la perspectiva del kernel. Normalmente es: I/O error a menos que ocurran otros problemas. Las siguientes palabras contienen una breve descripción del comando SCSI que falla. El resto de la línea indica si hubo algún problema con el transporte del comando a través del bus SCSI. fatal error significa que no fue posible transportar el comando (es decir, no hay ningún dispositivo presente en la dirección SCSI solicitada).

La segunda línea imprime el bloque de descriptores de comando SCSI para el comando fallido.

La tercera línea proporciona información sobre el código de estado SCSI devuelto por el comando, si el transporte del comando tiene éxito. Esta es información de error del dispositivo SCSI.

La cuarta línea es un volcado hexadecimal de la información de solicitud de auto-sentido para el comando.

La quinta línea es el texto del error para la clave de sentido si está disponible, seguido del número de segmento que solo es válido si el comando fue un comando de copia. Si el mensaje de error no está directamente relacionado con el comando actual, se agrega el texto deferred error.

La sexta línea es el texto del error para el código de sentido y el calificador de sentido si están disponibles. Si se conoce el tipo de dispositivo, los datos de sentido se decodifican de tablas en scsierrs.c. El texto va seguido del valor de error para una unidad reemplazable en campo.

La séptima línea imprime el número de bloque relacionado con el comando fallido y el texto de varios indicadores de error. El número de bloque puede no ser válido.

La octava línea informa el tiempo de espera configurado para este comando y el tiempo que realmente necesitó el comando para completarse.

ESTABILIDAD DE LA INTERFAZ

Las interfaces proporcionadas por readcd están diseñadas para una estabilidad a largo plazo. Dado que readcd depende de las interfaces proporcionadas por el sistema operativo subyacente, la estabilidad de las interfaces ofrecidas por readcd depende de la estabilidad de las interfaces del sistema operativo. Las interfaces modificadas en el sistema operativo pueden forzar interfaces modificadas en readcd.
