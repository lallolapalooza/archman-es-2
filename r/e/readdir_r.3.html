readdir_r(3) Manual de funciones de biblioteca readdir_r(3)

NOMBRE

readdir_r - leer un directorio

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <dirent.h>
[[deprecated]] int readdir_r(DIR *restrict dirp,
                             struct dirent *restrict entry,
                             struct dirent **restrict result);
Requisitos de la macro de prueba de características para glibc (ver feature_test_macros(7)):

readdir_r():

    _POSIX_C_SOURCE
        || /* glibc <= 2.19: */ _BSD_SOURCE || _SVID_SOURCE

DESCRIPCIÓN

Esta función está obsoleta; utilice readdir(3) en su lugar.

La función readdir_r() se inventó como una versión reentrante de readdir(3). Lee la siguiente entrada del directorio del flujo de directorio dirp y la devuelve en el búfer asignado por el llamador apuntado por entry. Para obtener detalles sobre la estructura dirent, consulte readdir(3).

Se coloca un puntero al búfer devuelto en *result; si se encontró el final del flujo de directorio, se devuelve NULL en *result.

Se recomienda que las aplicaciones utilicen readdir(3) en lugar de readdir_r(). Además, desde glibc 2.24, glibc desaprueba readdir_r(). Las razones son las siguientes:

•
En sistemas donde NAME_MAX no está definido, llamar a readdir_r() puede ser inseguro porque la interfaz no permite al llamador especificar la longitud del búfer utilizado para la entrada del directorio devuelta.
•
En algunos sistemas, readdir_r() no puede leer entradas de directorio con nombres muy largos. Cuando la implementación de glibc encuentra un nombre de este tipo, readdir_r() falla con el error ENAMETOOLONG después de que se haya leído la entrada final del directorio. En algunos otros sistemas, readdir_r() puede devolver un estado de éxito, pero el campo d_name devuelto puede no estar terminado en null o puede estar truncado.
•
En la especificación POSIX.1 actual (POSIX.1-2008), no se requiere que readdir(3) sea seguro para hilos. Sin embargo, en implementaciones modernas (incluida la implementación de glibc), las llamadas concurrentes a readdir(3) que especifican diferentes flujos de directorio son seguras para hilos. Por lo tanto, el uso de readdir_r() es generalmente innecesario en programas multihilo. En casos en los que varios hilos deben leer del mismo flujo de directorio, utilizar readdir(3) con sincronización externa sigue siendo preferible al uso de readdir_r(), por las razones expuestas en los puntos anteriores.
•
Se espera que una versión futura de POSIX.1 haga que readdir_r() sea obsoleto y requiera que readdir(3) sea seguro para hilos cuando se utiliza de forma concurrente en diferentes flujos de directorio.

VALOR DE RETORNO

La función readdir_r() devuelve 0 en caso de éxito. En caso de error, devuelve un número de error positivo (listado en ERRORES). Si se alcanza el final del flujo de directorio, readdir_r() devuelve 0 y devuelve NULL en *result.

ERRORES

EBADF
Descriptor de flujo de directorio dirp inválido.
ENAMETOOLONG
Se encontró una entrada de directorio cuyo nombre era demasiado largo para ser leído.
