regex(3) Manual de Funciones de Biblioteca regex(3)

NOMBRE

regcomp, regexec, regerror, regfree - Funciones POSIX de expresiones regulares

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <regex.h>
int regcomp(regex_t *restrict preg, const char *restrict regex,
            int cflags);
int regexec(const regex_t *restrict preg,
            const char *restrict string,
            size_t n, regmatch_t pmatch[_Nullable restrict n],
            int eflags);
size_t regerror(size_t errbuf_size;
            int errcode, const regex_t *_Nullable restrict preg,
            char errbuf[_Nullable restrict errbuf_size],
            size_t errbuf_size);
void regfree(regex_t *preg);
typedef struct {
    size_t    re_nsub;
} regex_t;
typedef struct {
    regoff_t  rm_so;
    regoff_t  rm_eo;
} regmatch_t;
typedef /* ... */  regoff_t;

DESCRIPCIÓN

Compilación

regcomp() se usa para compilar una expresión regular en un formato adecuado para búsquedas posteriores con regexec().

En caso de éxito, el búfer de patrón en *preg se inicializa. regex es una cadena terminada en nulo. La configuración regional debe ser la misma al ejecutar regexec().

Después de que regcomp() tenga éxito, preg->re_nsub contiene el número de subexpresiones en regex. Por lo tanto, un valor de preg->re_nsub + 1 pasado como n a regexec() es suficiente para capturar todas las coincidencias.

cflags es el OR a nivel de bits de cero o más de las siguientes opciones:

REG_EXTENDED
Usa la sintaxis de expresiones regulares extendidas POSIX al interpretar regex. Si no se establece, se usa la sintaxis de expresiones regulares básicas POSIX.
REG_ICASE
No diferenciar entre mayúsculas y minúsculas. Las búsquedas posteriores de regexec() que utilicen este búfer de patrón no distinguirán entre mayúsculas y minúsculas.
REG_NOSUB
Informar solo del éxito general. regexec() usará solo pmatch para REG_STARTEND, ignorando n.
REG_NEWLINE
Los operadores de "coincidir con cualquier carácter" no coinciden con un salto de línea.
Una lista de no coincidencia ([^...]) que no contiene un salto de línea no coincide con un salto de línea.
El operador de principio de línea (^) coincide con la cadena vacía inmediatamente después de un salto de línea, independientemente de si eflags, las banderas de ejecución de regexec(), contiene REG_NOTBOL.
El operador de fin de línea ($) coincide con la cadena vacía inmediatamente antes de un salto de línea, independientemente de si eflags contiene REG_NOTEOL.

Coincidencia

regexec() se usa para hacer coincidir una cadena terminada en nulo con el búfer de patrón compilado en *preg, que debe haber sido inicializado con regcomp(). eflags es el OR a nivel de bits de cero o más de las siguientes banderas:

REG_NOTBOL
El operador de principio de línea siempre falla al coincidir (pero vea la bandera de compilación REG_NEWLINE anterior). Esta bandera puede usarse cuando se pasan diferentes porciones de una cadena a regexec() y no se debe interpretar el principio de la cadena como el principio de la línea.
REG_NOTEOL
El operador de fin de línea siempre falla al coincidir (pero vea la bandera de compilación REG_NEWLINE anterior).
REG_STARTEND
Coincide [string + pmatch[0].rm_so, string + pmatch[0].rm_eo) en lugar de [string, string + strlen(string)). Esto permite hacer coincidir bytes NUL incrustados y evita un strlen(3) en cadenas de longitud conocida. Si se devuelven coincidencias (no se pasó REG_NOSUB a regcomp(), la coincidencia tuvo éxito y n > 0), sobrescriben pmatch como de costumbre, y las desplazaciones de coincidencia permanecen relativas a string (no a string + pmatch[0].rm_so). Esta bandera es una extensión de BSD, no está presente en POSIX.

Desplazamientos de coincidencia

A menos que se pasara REG_NOSUB a regcomp(), es posible obtener las ubicaciones de las coincidencias dentro de string: regexec() rellena n elementos de pmatch con resultados: pmatch[0] corresponde a la coincidencia completa, pmatch[1] a la primera subexpresión, etc. Si hubo más coincidencias que n, se descartan; si hubo menos, los elementos no utilizados de pmatch se rellenan con -1.

Cada coincidencia válida devuelta (no -1) corresponde al rango [string + rm_so, string + rm_eo).

regoff_t es un tipo de entero con signo capaz de almacenar el valor más grande que puede almacenarse en un tipo ptrdiff_t o un tipo ssize_t.

Reporte de errores

regerror() se usa para convertir los códigos de error que pueden ser devueltos tanto por regcomp() como por regexec() en cadenas de mensajes de error.

Si preg no es un puntero nulo, errcode debe ser el último error devuelto por una operación en preg.

Si errbuf_size no es 0, se copian hasta errbuf_size bytes a errbuf; la cadena de error siempre se termina en nulo y se trunca para que quepa.

Liberación

regfree() desinicializa el búfer de patrón en *preg, liberando cualquier memoria asociada; *preg debe haber sido inicializado a través de regcomp().

VALOR DE RETORNO

regcomp() devuelve cero para una compilación exitosa o un código de error en caso de fallo.

regexec() devuelve cero para una coincidencia exitosa o REG_NOMATCH en caso de fallo.

regerror() devuelve el tamaño del búfer necesario para almacenar la cadena.

ERRORES

Los siguientes errores pueden ser devueltos por regcomp():

REG_BADBR
Uso inválido del operador de referencia inversa.
REG_BADPAT
Uso inválido de operadores de patrón como grupo o lista.
REG_BADRPT
Uso inválido de operadores de repetición, como usar '*' como primer carácter.
REG_EBRACE
Operadores de intervalo de llaves no emparejados.
REG_EBRACK
Operadores de lista de corchetes no emparejados.
REG_ECOLLATE
Elemento de ordenación inválido.
REG_ECTYPE
Nombre de clase de caracteres desconocido.
REG_EEND
Error inespecífico. Esto no está definido por POSIX.
REG_EESCAPE
Barra invertida de cierre.
REG_EPAREN
Operadores de grupo de paréntesis no emparejados.
REG_ERANGE
Uso inválido del operador de rango; por ejemplo, el punto final del rango ocurre antes del punto de inicio.

DESCRIPTION

The POSIX.1 standard defines functions for POSIX regular expression matching. These functions are based on the capabilities of the original UNIX regular expression routines, but with extensions for internationalization and other enhancements.

The POSIX standard also defines a number of constants and data types that are used by these functions. The POSIX standard does not explicitly define the contents of the regex_t and regmatch_t structures, or the type regoff_t. Implementations are free to define these as they see fit, so long as they meet the requirements of the POSIX standard.

The following flags are used by regcomp(3):

REG_EXTENDED
Use extended regular expressions. If this flag is not specified, basic regular expressions are used. Extended regular expressions are generally easier to write and read than basic regular expressions, and they offer more features. They are also more powerful, as they allow for more complex patterns to be matched.

REG_NOSUB
Do not report subexpression matches. If this flag is specified, the regexec function will not store information about subexpression matches in the pmatch array. This can improve performance, as the function does not need to store as much information.

REG_ICASE
Ignore case distinctions in the pattern and the string. If this flag is specified, the regexec function will treat uppercase and lowercase letters as being the same. This can be useful for matching patterns that may appear in different cases, such as filenames or email addresses.

REG_NEWLINE
The character newline (‘\n’) shall match any character in the string, except that it shall not match the beginning of the string.

REG_PERL
Enable Perl-compatible regular expression extensions. This flag is not part of the POSIX standard, but it is supported by many implementations. Perl-compatible regular expressions offer a wide range of powerful features, including backreferences, lookarounds, and non-capturing groups.

The following flags are used by regexec(3):

REG_NOTBOL
The string being searched does not start with the beginning of a line. If this flag is specified, the regexec function will not treat the beginning of the string as the beginning of a line. This can be useful for matching patterns that may appear in the middle of a line, such as search queries.

REG_NOTEOL
The string being searched does not end with the end of a line. If this flag is specified, the regexec function will not treat the end of the string as the end of a line. This can be useful for matching patterns that may appear in the middle of a line, such as search queries.

REG_START
The offset in the string where the match should begin. This flag is used in conjunction with the pmatch array to specify the starting position of the match. This can be useful for searching for patterns that may appear multiple times in a string, as it allows you to specify where the search should begin.

REG_END
The offset in the string where the match should end. This flag is used in conjunction with the pmatch array to specify the ending position of the match. This can be useful for searching for patterns that may appear multiple times in a string, as it allows you to specify where the search should end.

REG_REFINE
Refine the search for a match. This flag is used in conjunction with the pmatch array to specify that the search should be refined to find a more specific match. This can be useful for searching for patterns that may have multiple possible matches, as it allows you to narrow down the search to find the most relevant match.

RETURN VALUE

On success, regcomp, regexec, regerror, regfree, and regdup return 0. On failure, they return a non-zero error code.

The regerror function returns the number of characters in the buffer on success, or 0 if the buffer is not large enough to hold the error message.

ERRORS

REG_ASSERT
An internal error occurred. This indicates a bug in the regex library.
REG_BADBR
Invalid use of a backreference (`\digit`).
REG_BADPAT
Invalid regular expression syntax.
REG_BADEAT
Invalid use of an escaped character.
REG_BADRPT
Invalid use of a repetition operator (e.g., `*`, `+`, `?`, `{n,m}`).
REG_ESIZE
Compiled regular expression requires a pattern buffer larger than 64 kB. This is not defined by POSIX.
REG_ESPACE
The regex routines ran out of memory.
REG_ESUBREG
Invalid back reference to a subexpression.

STANDARDS

POSIX.1-2008.

HISTORY

POSIX.1-2001.

Prior to POSIX.1-2008, regoff_t was required to be capable of storing the largest value that can be stored in either an off_t type or a ssize_t type.

CAVEATS

re_nsub is only required to be initialized if REG_NOSUB wasn't specified, but all known implementations initialize it regardless.

Both regex_t and regmatch_t may (and do) have more members, in any order. Always reference them by name.

EXAMPLES

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <regex.h>
#define NITEMS(arr)  (sizeof((arr)) / sizeof((arr)[0]))
static const char *const str =
        "1) John Driverhacker;\n2) John Doe;\n3) John Foo;\n";
static const char *const re = "John.*o";
int main(void)
{
    static const char *s = str;
    regex_t     regex;
    regmatch_t  pmatch[1];
    regoff_t    off, len;
    if (regcomp(&regex, re, REG_NEWLINE))
        exit(EXIT_FAILURE);
    printf("String = \"%s\"\n", str);
    printf("Matches:\n");
    for (unsigned int i = 0; ; i++) {
        if (regexec(&regex, s, NITEMS(pmatch), pmatch, 0))
            break;
        off = pmatch[0].rm_so + (s - str);
        len = pmatch[0].rm_eo - pmatch[0].rm_so;
        printf("#%u:\n", i);
        printf("offset = %jd; length = %jd\n", (intmax_t) off,
                (intmax_t) len);
        printf("substring = \"%.*s\"\n", len, s + pmatch[0].rm_so);
        s += pmatch[0].rm_eo;
    }
    exit(EXIT_SUCCESS);
}
