return(n)

Paquete: tcl

Licencias: TCL

return(n) Comandos integrados de Tcl return(n)

NOMBRE

return - Retornar desde un procedimiento, o establecer el código de retorno de un script

SINOPSIS

return ?resultado?

return ?-code código? ?resultado?

return ?opción valor ...? ?resultado?

DESCRIPCIÓN

En su uso más simple, el comando return se usa sin opciones en el cuerpo de un procedimiento para retornar inmediatamente el control al llamador del procedimiento. Si se proporciona un argumento resultado, su valor se convierte en el resultado del procedimiento devuelto al llamador. Si resultado no se especifica, se devolverá una cadena vacía al llamador como resultado del procedimiento.

El comando return cumple una función similar dentro de los archivos de script que son evaluados por el comando source. Cuando source evalúa el contenido de un archivo como un script, una invocación del comando return hará que la evaluación del script cese inmediatamente, y el valor resultado (o una cadena vacía) se devolverá como resultado del comando source.

CÓDIGOS DE RETORNO EXCEPCIONALES

Además del resultado de un procedimiento, el código de retorno de un procedimiento también puede ser establecido por return mediante el uso de la opción -code. En el caso habitual en que la opción -code no se especifica, el procedimiento retornará normalmente. Sin embargo, la opción -code puede usarse para generar un retorno excepcional del procedimiento. Código puede tener cualquiera de los siguientes valores:

ok (o 0)
Retorno normal: igual que si se omite la opción. El código de retorno del procedimiento es 0 (TCL_OK).
error (o 1)
Retorno de error: el código de retorno del procedimiento es 1 (TCL_ERROR). El comando del procedimiento se comporta en su contexto de llamada como si fuera el comando error resultado. Vea abajo para opciones adicionales.
return (o 2)
El código de retorno del procedimiento es 2 (TCL_RETURN). El comando del procedimiento se comporta en su contexto de llamada como si fuera el comando return (sin argumentos).
break (o 3)
El código de retorno del procedimiento es 3 (TCL_BREAK). El comando del procedimiento se comporta en su contexto de llamada como si fuera el comando break.
continue (o 4)
El código de retorno del procedimiento es 4 (TCL_CONTINUE). El comando del procedimiento se comporta en su contexto de llamada como si fuera el comando continue.
valor
Valor debe ser un entero; se devolverá como el código de retorno para el procedimiento actual.

Cuando un procedimiento quiere indicar que ha recibido argumentos inválidos de su llamador, puede usar return -code error con resultado establecido a un mensaje de error adecuado. De lo contrario, el uso de la opción return -code está mayormente limitado a procedimientos que implementan una nueva estructura de control.

El comando return -code actúa de manera similar dentro de los archivos de script que son evaluados por el comando source. Durante la evaluación del contenido de un archivo como script por source, una invocación del comando return -code código hará que el código de retorno de source sea código.

OPCIONES DE RETORNO

Además de un resultado y un código de retorno, la evaluación de un comando en Tcl también produce un diccionario de opciones de retorno. En el uso general, todos los pares opción valor dados como argumentos a return se convierten en entradas en el diccionario de opciones de retorno, y cualquier valor es aceptable excepto como se indica a continuación. El comando catch puede usarse para capturar toda esta información — el código de retorno, el resultado y el diccionario de opciones de retorno — que surge de la evaluación de un script.

Como se documentó anteriormente, la entrada -code en el diccionario de opciones de retorno recibe un tratamiento especial por parte de Tcl. Hay otras opciones de retorno también reconocidas y tratadas especialmente por Tcl. Son:

-errorcode lista
La opción -errorcode recibe un tratamiento especial solo cuando el valor de la opción -code es TCL_ERROR. Entonces, el valor de lista está destinado a ser información adicional sobre el error, presentado como una lista Tcl para un mayor procesamiento por parte de los programas. Si no se proporciona ninguna opción -errorcode a return cuando se proporciona la opción -code error, Tcl establecerá el valor de la entrada -errorcode en el diccionario de opciones de retorno al valor predeterminado de NONE. La opción de retorno -errorcode también se almacenará en la variable global errorCode.
-errorinfo info
La opción -errorinfo recibe un tratamiento especial solo cuando el valor de la opción -code es TCL_ERROR. Entonces info es el rastreo de pila inicial, destinado a proporcionar a un lector humano información adicional sobre el contexto en el que ocurrió el error. El rastreo de pila también se almacenará en la variable global errorInfo. Si no se proporciona ninguna opción -errorinfo a return cuando se proporciona la opción -code error, Tcl proporcionará su propio valor de rastreo de pila inicial en la entrada para -errorinfo. El rastreo de pila inicial de Tcl incluirá solo la llamada al procedimiento, y el desenrollado de la pila agregará información sobre los niveles de pila superiores, pero no habrá información sobre el contexto del error dentro del procedimiento. Típicamente, el valor de info se suministra desde el valor de -errorinfo en un diccionario de opciones de retorno capturado por el comando catch (o de la copia de esa información almacenada en la variable global errorInfo).
-errorstack lista
La opción -errorstack recibe un tratamiento especial solo cuando el valor de la opción -code es TCL_ERROR. Entonces lista es la pila de errores inicial, que registra los valores de argumento reales pasados a cada nivel de proc. La pila de errores también será accesible a través de info errorstack. Si no se proporciona ninguna opción -errorstack a return cuando se proporciona la opción -code error, Tcl proporcionará su propia pila de errores inicial en la entrada para -errorstack. La pila de errores inicial de Tcl incluirá solo la llamada al procedimiento, y el desenrollado de la pila agregará información sobre los niveles de pila superiores, pero no habrá información sobre el contexto del error dentro del procedimiento. Típicamente, el valor de lista se suministra desde el valor de -errorstack en un diccionario de opciones de retorno capturado por el comando catch (o de la copia de esa información de info errorstack).
-level nivel
Las opciones -level y -code trabajan juntas para establecer el código de retorno que será retornado por uno de los comandos que se están evaluando actualmente. El valor de nivel debe ser un entero no negativo que representa un número de niveles en la pila de llamadas. Define el número de niveles hacia arriba en la pila en el que el código de retorno de un comando que se está evaluando actualmente debe ser código. Si no se proporciona ninguna opción -level, el valor predeterminado de nivel es 1, de modo que return establece el código de retorno que el procedimiento actual devuelve a su llamador, 1 nivel arriba en la pila de llamadas. El mecanismo por el cual funcionan estas opciones se describe con más detalle abajo.
-options opciones
El valor opciones debe ser un diccionario válido. Las entradas de ese diccionario se tratan como pares opción valor adicionales para el comando return.

MECANISMOS DE MANEJO DEL CÓDIGO DE RETORNO

Los códigos de retorno se utilizan en Tcl para controlar el flujo del programa. Un script de Tcl es una secuencia de comandos de Tcl. Mientras cada evaluación de comando devuelva un código de retorno de TCL_OK, la evaluación continuará con el siguiente comando.

EXCEPTIONAL RETURN CODES

Any exceptional return code (non-TCL_OK) returned by the evaluation of a command interrupts the flow to the next command. Script evaluation ceases, and the exceptional return code from the command becomes the return code of the full script evaluation. This is the mechanism by which errors during script evaluation cause an interruption and unwinding of the call stack. It is also the mechanism by which commands like break, continue, and return cause script evaluation to terminate without evaluating all commands in sequence.

Some of Tcl's built-in commands evaluate scripts as part of their functioning. These commands can make use of exceptional return codes to enable special features. For example, the built-in Tcl commands that provide loops — such as while, for, and foreach — evaluate a script that is the body of the loop. If evaluation of the loop body returns the return code of TCL_BREAK or TCL_CONTINUE, the loop command can react in such a way as to give the break and continue commands their documented interpretation in loops.

Procedure invocation also involves evaluation of a script, the body of the procedure. Procedure invocation provides special treatment when evaluation of the procedure body returns the return code TCL_RETURN. In that circumstance, the -level entry in the return options dictionary is decremented. If after decrementing, the value of the -level entry is 0, then the value of the -code entry becomes the return code of the procedure. If after decrementing, the value of the -level entry is greater than zero, then the return code of the procedure is TCL_RETURN. If the procedure invocation occurred during the evaluation of the body of another procedure, the process will repeat itself up the call stack, decrementing the value of the -level entry at each level, so that the code will be the return code of the current command level levels up the call stack. The source command performs the same handling of the TCL_RETURN return code, which explains the similarity of return invocation during a source to return invocation within a procedure.

The return code of the return command itself triggers this special handling by procedure invocation. If return is provided the option -level 0, then the return code of the return command itself will be the value code of the -code option (or TCL_OK by default). Any other value for the -level option (including the default value of 1) will cause the return code of the return command itself to be TCL_RETURN, triggering a return from the enclosing procedure.

EXAMPLES

First, a simple example of using return to return from a procedure, interrupting the procedure body.

proc printOneLine {} {
    puts "line 1"    ;# This line will be printed.
    return
    puts "line 2"    ;# This line will not be printed.
}

Next, an example of using return to set the value returned by the procedure.

proc returnX {} {return X}
puts [returnX]    ;# prints "X"

Next, a more complete example, using return -code error to report invalid arguments.

proc factorial {n} {
    if {![string is integer $n] || ($n < 0)} {
        return -code error \
                "expected non-negative integer,\
                but got \"$n\""
    }
    if {$n < 2} {
        return 1
    }
    set m [expr {$n - 1}]
    set code [catch {factorial $m} factor]
    if {$code != 0} {
        return -code $code $factor
    }
    set product [expr {$n * $factor}]
    if {$product < 0} {
        return -code error \
                "overflow computing factorial of $n"
    }
    return $product
}

Next, a procedure replacement for break.

proc myBreak {} {
    return -code break
}

With the -level 0 option, return itself can serve as a replacement for break, with the help of interp alias.

interp alias {} Break {} return -level 0 -code break

An example of using catch and return -options to re-raise a caught error:

proc doSomething {} {
    set resource [allocate]
    catch {
        # Long script of operations
        # that might raise an error
    } result options
    deallocate $resource
    return -options $options $result
}

Finally an example of advanced use of the return options to create a procedure replacement for return itself:

proc myReturn {args} {
    set result ""
    if {[llength $args] % 2} {
        set result [lindex $args end]
        set args [lrange $args 0 end-1]
    }
    set options [dict merge {-level 1} $args]
    dict incr options -level
    return -options $options $result
}
