RENAME(3P) Manual de Programador POSIX RENAME(3P)

PROLOG

Esta página de manual forma parte del Manual de Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página de manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

rename, renameat — renombrar archivo

SINOPSIS

#include <stdio.h>
int rename(const char *old, const char *new);
#include <fcntl.h>
int renameat(int oldfd, const char *old, int newfd,
    const char *new);

DESCRIPCIÓN

Para rename(): La funcionalidad descrita en esta página de referencia está alineada con el estándar ISO C. Cualquier conflicto entre los requisitos descritos aquí y el estándar ISO C es inintencional. Este volumen de POSIX.1‐2017 remite al estándar ISO C.

La función rename() cambiará el nombre de un archivo. El argumento old apunta a la ruta del archivo que se va a renombrar. El argumento new apunta a la nueva ruta del archivo. Si el argumento new no se resuelve a una entrada de directorio existente para un archivo de tipo directorio y el argumento new contiene al menos un carácter que no sea <barra> y termina con uno o más caracteres de <barra> finales después de que todos los enlaces simbólicos hayan sido procesados, rename() fallará.

Si alguno de los argumentos old o new nombra un enlace simbólico, rename() operará sobre el enlace simbólico en sí mismo y no resolverá el último componente del argumento. Si el argumento old y el argumento new se resuelven a la misma entrada de directorio existente o a diferentes entradas de directorio para el mismo archivo existente, rename() devolverá éxito y no realizará ninguna otra acción.

Si el argumento old apunta a la ruta de un archivo que no es un directorio, el argumento new no debe apuntar a la ruta de un directorio. Si el enlace llamado por el argumento new existe, será eliminado y old se renombrará a new. En este caso, un enlace llamado new permanecerá visible para otros hilos durante toda la operación de renombrado y se referirá al archivo al que se refería new u old antes de que comenzara la operación. Se requiere permiso de acceso de escritura tanto para el directorio que contiene old como para el directorio que contiene new.

Si el argumento old apunta a la ruta de un directorio, el argumento new no debe apuntar a la ruta de un archivo que no sea un directorio. Si el directorio llamado por el argumento new existe, será eliminado y old se renombrará a new. En este caso, un enlace llamado new existirá durante toda la operación de renombrado y se referirá al directorio al que se refería new u old antes de que comenzara la operación. Si new nombra un directorio existente, debe ser un directorio vacío.

Si alguno de los argumentos pathname se refiere a una ruta cuya última componente es punto o punto-punto, rename() fallará.

Si el argumento old apunta a una ruta de un enlace simbólico, se renombrará el enlace simbólico. Si el argumento new apunta a una ruta de un enlace simbólico, se eliminará el enlace simbólico.

La ruta old no debe nombrar un directorio ancestro de la ruta new. Se requiere permiso de acceso de escritura para el directorio que contiene old y el directorio que contiene new. Si el argumento old apunta a la ruta de un directorio, se puede requerir permiso de acceso de escritura para el directorio nombrado por old y, si existe, el directorio nombrado por new.

Si el enlace llamado por el argumento new existe y el contador de enlaces del archivo se convierte en 0 cuando se elimina y ningún proceso tiene el archivo abierto, se liberará el espacio ocupado por el archivo y el archivo ya no será accesible. Si uno o más procesos tienen el archivo abierto cuando se elimina el último enlace, se eliminará el enlace antes de que rename() devuelva, pero la eliminación del contenido del archivo se pospondrá hasta que se cierren todas las referencias al archivo.

Tras la finalización exitosa, rename() marcará para actualización las marcas de tiempo de la última modificación de datos y del último cambio de estado del archivo del directorio padre de cada archivo.

Si la función rename() falla por cualquier motivo que no sea [EIO], cualquier archivo nombrado por new no se verá afectado.

La función renameat() será equivalente a la función rename() excepto en el caso en que old o new especifiquen una ruta relativa. Si old es una ruta relativa, el archivo que se va a renombrar se localizará en relación con el directorio asociado con el descriptor de archivo oldfd en lugar del directorio de trabajo actual. Si new es una ruta relativa, ocurrirá lo mismo solo en relación con el directorio asociado con newfd. Si el modo de acceso de la descripción de archivo abierta asociada con el descriptor de archivo no es O_SEARCH, la función verificará si las búsquedas de directorio están permitidas usando los permisos actuales del directorio subyacente al descriptor de archivo. Si el modo de acceso es O_SEARCH, la función no realizará la verificación.

Si se pasan los valores especiales AT_FDCWD en los parámetros oldfd o newfd a renameat(), se utilizará el directorio de trabajo actual en la determinación del archivo para el parámetro path respectivo.

VALOR DE RETORNO

Tras la finalización exitosa, la función rename() devolverá 0. De lo contrario, devolverá -1, se establecerá errno para indicar el error, y ni el archivo nombrado por old ni el archivo nombrado por new serán modificados o creados.

Tras la finalización exitosa, la función renameat() devolverá 0. De lo contrario, devolverá -1 y establecerá errno para indicar el error.

ERRORES

Las funciones rename() y renameat() fallarán si:

EACCES
Un componente de cualquier prefijo de ruta niega el permiso de búsqueda; o uno de los directorios que contienen old o new niega los permisos de escritura; o, se requiere permiso de escritura y se niega para un directorio al que apuntan los argumentos old o new.
EBUSY
El directorio nombrado por old o new está actualmente en uso por el sistema u otro proceso, y la implementación considera esto un error.
[EEXIST] o [ENOTEMPTY]

El enlace nombrado por new es un directorio que no es un directorio vacío.
EINVAL
La ruta old nombra un directorio ancestro de la ruta new, o cualquier argumento de ruta contiene una última componente que es punto o punto-punto.
EIO
Ha ocurrido un error físico de E/S.
EISDIR
El argumento new apunta a un directorio y el argumento old apunta a un archivo que no es un directorio.
ELOOP
Existe un bucle en los enlaces simbólicos encontrados durante la resolución del argumento path.
EMLINK
El archivo nombrado por old es un directorio, y el contador de enlaces del directorio padre de new excedería {LINK_MAX}.
ENAMETOOLONG

La longitud de una componente de una ruta es mayor que {NAME_MAX}.
ENOENT
El enlace nombrado por old no nombra un archivo existente, una componente del prefijo de ruta de new no existe, o old o new apunta a una cadena vacía.
ENOSPC
El directorio que contendría new no puede ser extendido.
