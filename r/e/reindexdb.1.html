reindexdb(1)

Paquete: postgresql-libs

Licencias: PostgreSQL

REINDEXDB(1) Documentación de PostgreSQL 18.1 REINDEXDB(1)

NOMBRE

reindexdb - reindexar una base de datos PostgreSQL

SINOPSIS

reindexdb [opción-conexión...] [opción...] [ -S | --schema esquema ]... [ -t | --table tabla ]... [ -i | --index índice ]... [ -s | --system ] [nombrebd | -a | --all]

DESCRIPCIÓN

reindexdb es una utilidad para reconstruir índices en una base de datos PostgreSQL.

reindexdb es un envoltorio alrededor del comando SQL REINDEX. No hay ninguna diferencia efectiva entre reindexar bases de datos a través de esta utilidad y a través de otros métodos para acceder al servidor.

OPCIONES

reindexdb acepta los siguientes argumentos de línea de comandos:

-a
--all

Reindexar todas las bases de datos.

--concurrently

Usar la opción CONCURRENTLY. Ver REINDEX(7), donde todas las advertencias de esta opción se explican en detalle.

[-d] nombrebd
[--dbname=]nombrebd

Especifica el nombre de la base de datos a reindexar, cuando -a/--all no se usa. Si no se especifica, el nombre de la base de datos se lee de la variable de entorno PGDATABASE. Si no está configurada, se usa el nombre de usuario especificado para la conexión. El nombrebd puede ser una cadena de conexión. Si es así, los parámetros de la cadena de conexión anularán cualquier opción de línea de comandos conflictiva.

-e
--echo

Mostrar los comandos que reindexdb genera y envía al servidor.

-i índice
--index=índice

Recrear solo el índice. Se pueden recrear múltiples índices escribiendo varios interruptores -i.

-j njobs
--jobs=njobs

Ejecutar los comandos de reindexación en paralelo ejecutando njobs comandos simultáneamente. Esta opción puede reducir el tiempo de procesamiento, pero también aumenta la carga en el servidor de base de datos.

reindexdb abrirá njobs conexiones a la base de datos, así que asegúrate de que tu configuración de max_connections sea lo suficientemente alta para acomodar todas las conexiones.

Ten en cuenta que esta opción es incompatible con la opción --system.

-q
--quiet

No mostrar mensajes de progreso.

-s
--system

Reindexar solo los catálogos del sistema de la base de datos.

-S esquema
--schema=esquema

Reindexar solo el esquema. Se pueden reindexar múltiples esquemas escribiendo varios interruptores -S.

-t tabla
--table=tabla

Reindexar solo la tabla. Se pueden reindexar múltiples tablas escribiendo varios interruptores -t.

--tablespace=tablespace

Especifica el tablespace donde se reconstruirán los índices. (Este nombre se procesa como un identificador entre comillas dobles).

-v
--verbose

Mostrar información detallada durante el procesamiento.

-V
--version

Mostrar la versión de reindexdb y salir.

-?
--help

Mostrar ayuda sobre los argumentos de línea de comandos de reindexdb y salir.

reindexdb también acepta los siguientes argumentos de línea de comandos para parámetros de conexión:

-h host
--host=host

Especifica el nombre del host de la máquina en la que se ejecuta el servidor. Si el valor comienza con una barra diagonal, se usa como el directorio para el socket de dominio Unix.

-p puerto
--port=puerto

Especifica el puerto TCP o la extensión del archivo de socket de dominio Unix local en el que el servidor está escuchando conexiones.

-U nombreusuario
--username=nombreusuario

Nombre de usuario para conectarse.

-w
--no-password

Nunca solicitar una contraseña. Si el servidor requiere autenticación de contraseña y no hay una contraseña disponible por otros medios, como un archivo .pgpass, el intento de conexión fallará. Esta opción puede ser útil en trabajos por lotes y scripts donde no hay ningún usuario presente para ingresar una contraseña.

-W
--password

Forzar a reindexdb a solicitar una contraseña antes de conectarse a una base de datos.

Esta opción nunca es esencial, ya que reindexdb solicitará automáticamente una contraseña si el servidor la demanda. Sin embargo, reindexdb desperdiciará un intento de conexión averiguando que el servidor quiere una contraseña. En algunos casos, vale la pena escribir -W para evitar el intento de conexión adicional.

--maintenance-db=nombrebd

Cuando se usa -a/--all, conectarse a esta base de datos para recopilar la lista de bases de datos a reindexar. Si no se especifica, se usará la base de datos postgres, o si esta no existe, se usará template1. Esto puede ser una cadena de conexión. Si es así, los parámetros de la cadena de conexión anularán cualquier opción de línea de comandos conflictiva. Además, los parámetros de la cadena de conexión (aparte del propio nombre de la base de datos) se reutilizarán al conectarse a otras bases de datos.

ENTORNO

PGDATABASE
PGHOST
PGPORT
PGUSER

Parámetros de conexión predeterminados

PG_COLOR

Especifica si se debe usar color en los mensajes de diagnóstico. Los valores posibles son always, auto y never.

Esta utilidad, como la mayoría de las otras utilidades de PostgreSQL, también utiliza las variables de entorno soportadas por libpq (ver Sección 32.15).

DIAGNÓSTICOS

En caso de dificultad, consulte REINDEX(7) y psql(1) para discusiones sobre problemas potenciales y mensajes de error. El servidor de base de datos debe estar en ejecución en el host objetivo. Además, se aplicarán todos los configuraciones de conexión predeterminadas y variables de entorno utilizadas por la biblioteca de front-end libpq.

EJEMPLOS

Para reindexar la base de datos test:

$ reindexdb test

Para reindexar la tabla foo y el índice bar en una base de datos llamada abcd:

$ reindexdb --table=foo --index=bar abcd
