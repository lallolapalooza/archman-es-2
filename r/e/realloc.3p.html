REALLOC(3P) Manual del Programador POSIX REALLOC(3P)

PROLOG

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual correspondiente de Linux para obtener detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

realloc — realocador de memoria

SINOPSIS

#include <stdlib.h>
void *realloc(void *ptr, size_t size);

DESCRIPCIÓN

La funcionalidad descrita en esta página de referencia está alineada con el estándar ISO C. Cualquier conflicto entre los requisitos descritos aquí y el estándar ISO C es no intencional. Este volumen de POSIX.1‐2017 remite al estándar ISO C.

La función realloc() desasignará el objeto antiguo apuntado por ptr y devolverá un puntero a un nuevo objeto que tenga el tamaño especificado por size. El contenido del nuevo objeto será el mismo que el del objeto antiguo antes de la desasignación, hasta el menor de los tamaños nuevo y antiguo. Los bytes en el nuevo objeto más allá del tamaño del objeto antiguo tendrán valores indeterminados. Si el tamaño del espacio solicitado es cero, el comportamiento será definido por la implementación: o bien se devuelve un puntero nulo, o el comportamiento será como si el tamaño fuera algún valor distinto de cero, excepto que el comportamiento no está definido si el puntero devuelto se utiliza para acceder a un objeto. Si el espacio no se puede asignar, el objeto permanecerá inalterado.

Si ptr es un puntero nulo, realloc() será equivalente a malloc() para el tamaño especificado.

Si ptr no coincide con un puntero devuelto anteriormente por calloc(), malloc() o realloc() o si el espacio se ha desasignado previamente mediante una llamada a free() o realloc(), el comportamiento no está definido.

El orden y la contigüidad del almacenamiento asignado por llamadas sucesivas a realloc() no están especificados. El puntero devuelto si la asignación tiene éxito estará debidamente alineado para que pueda asignarse a un puntero de cualquier tipo de objeto y luego usarse para acceder a dicho objeto en el espacio asignado (hasta que el espacio se libere explícitamente o se reasigne). Cada asignación de este tipo devolverá un puntero a un objeto distinto de cualquier otro objeto. El puntero devuelto apuntará al inicio (dirección de byte más baja) del espacio asignado. Si el espacio no se puede asignar, se devolverá un puntero nulo.

VALOR DE RETORNO

Al completarse con éxito, realloc() devolverá un puntero al espacio asignado (posiblemente movido). Si size es 0, o:

*
Se devolverá un puntero nulo y, si ptr no es un puntero nulo, errno se establecerá en un valor definido por la implementación.
*
Se devolverá un puntero al espacio asignado y se liberará el objeto de memoria apuntado por ptr. La aplicación deberá asegurarse de que el puntero no se use para acceder a un objeto.

Si no hay suficiente memoria disponible, realloc() devolverá un puntero nulo y establecerá errno en [ENOMEM]. Si realloc() devuelve un puntero nulo y errno se ha establecido en [ENOMEM], la memoria referenciada por ptr no se modificará.

ERRORES

La función realloc() fallará si:

ENOMEM
No hay suficiente memoria disponible.

Ninguno.

USO DE LA APLICACIÓN

La descripción de realloc() se ha modificado respecto a versiones anteriores de este estándar para alinearse con el estándar ISO/IEC 9899:1999. Las versiones anteriores permitían explícitamente que una llamada a realloc(p, 0) liberara el espacio apuntado por p y devolviera un puntero nulo. Aunque este comportamiento podría interpretarse como permitido por esta versión del estándar, el comité del lenguaje C ha indicado que esta interpretación es incorrecta. Las aplicaciones deben asumir que si realloc() devuelve un puntero nulo, el espacio apuntado por p no se ha liberado. Dado que esto podría dar lugar a liberaciones dobles, las implementaciones también deberían establecer errno si un puntero nulo indica realmente un fallo, y las aplicaciones solo deberían liberar el espacio si errno ha cambiado.

RACIOCINIO

Ninguno.

DIRECCIONES FUTURAS

Este estándar remite al estándar ISO C. Aunque ese estándar tiene actualmente un lenguaje que podría permitir que realloc(p, 0), donde p no es un puntero nulo, libere p y devuelva un puntero nulo, el comité responsable de ese estándar está considerando aclarar el lenguaje para prohibir explícitamente esa alternativa.
