readv(2) Manual de llamadas al sistema readv(2)

NOMBRE

readv, writev, preadv, pwritev, preadv2, pwritev2 - leer o escribir datos en múltiples búferes

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/uio.h>
ssize_t readv(int fd, const struct iovec *iov, int iovcnt);
ssize_t writev(int fd, const struct iovec *iov, int iovcnt);
ssize_t preadv(int fd, const struct iovec *iov, int iovcnt,
                off_t offset);
ssize_t pwritev(int fd, const struct iovec *iov, int iovcnt,
                off_t offset);
ssize_t preadv2(int fd, const struct iovec *iov, int iovcnt,
                off_t offset, int flags);
ssize_t pwritev2(int fd, const struct iovec *iov, int iovcnt,
                off_t offset, int flags);

preadv(), pwritev():

    Desde glibc 2.19:

    glibc 2.19 y anteriores:

DESCRIPCIÓN

La llamada al sistema readv() lee iovcnt búferes del archivo asociado con el descriptor de archivo fd en los búferes descritos por iov ("entrada dispersa").

La llamada al sistema writev() escribe iovcnt búferes de datos descritos por iov en el archivo asociado con el descriptor de archivo fd ("salida agrupada").

El puntero iov apunta a un array de estructuras iovec, descritas en iovec(3type).

La llamada al sistema readv() funciona igual que read(2) excepto que se llenan múltiples búferes.

La llamada al sistema writev() funciona igual que write(2) excepto que se escriben múltiples búferes.

Los búferes se procesan en orden de array. Esto significa que readv() llena completamente iov[0] antes de pasar a iov[1], y así sucesivamente. (Si hay datos insuficientes, es posible que no se llenen todos los búferes apuntados por iov). De manera similar, writev() escribe el contenido completo de iov[0] antes de pasar a iov[1], y así sucesivamente.

Las transferencias de datos realizadas por readv() y writev() son atómicas: los datos escritos por writev() se escriben como un bloque único que no se mezcla con la salida de escrituras en otros procesos; análogamente, se garantiza que readv() lee un bloque contiguo de datos del archivo, independientemente de las operaciones de lectura realizadas en otros hilos o procesos que tengan descriptores de archivo que se refieran a la misma descripción de archivo abierta (ver open(2)).

preadv() y pwritev()

La llamada al sistema preadv() combina la funcionalidad de readv() y pread(2). Realiza la misma tarea que readv(), pero añade un cuarto argumento, offset, que especifica el desplazamiento del archivo en el que se realizará la operación de entrada.

La llamada al sistema pwritev() combina la funcionalidad de writev() y pwrite(2). Realiza la misma tarea que writev(), pero añade un cuarto argumento, offset, que especifica el desplazamiento del archivo en el que se realizará la operación de salida.

El desplazamiento del archivo no se modifica por estas llamadas al sistema. El archivo al que se refiere fd debe ser capaz de buscar.

preadv2() y pwritev2()

Estas llamadas al sistema son similares a las llamadas preadv() y pwritev(), pero añaden un quinto argumento, flags, que modifica el comportamiento por llamada.

A diferencia de preadv() y pwritev(), si el argumento offset es -1, se utiliza y actualiza el desplazamiento actual del archivo.

El argumento flags contiene un OR a nivel de bits de cero o más de las siguientes banderas:

RWF_DSYNC (desde Linux 4.7)
Proporciona un equivalente por escritura del flag O_DSYNC de open(2). Este flag solo tiene significado para pwritev2(), y su efecto se aplica solo al rango de datos escrito por la llamada al sistema.
RWF_HIPRI (desde Linux 4.6)
Lectura/escritura de alta prioridad. Permite que los sistemas de archivos basados en bloques utilicen sondeos del dispositivo, lo que proporciona menor latencia, pero puede utilizar recursos adicionales. (Actualmente, esta funcionalidad solo es utilizable en un descriptor de archivo abierto con el flag O_DIRECT).
RWF_SYNC (desde Linux 4.7)
Proporciona un equivalente por escritura del flag O_SYNC de open(2). Este flag solo tiene significado para pwritev2(), y su efecto se aplica solo al rango de datos escrito por la llamada al sistema.
RWF_NOWAIT (desde Linux 4.14)
No esperar datos que no estén inmediatamente disponibles. Si se especifica este flag, la llamada al sistema preadv2() regresará instantáneamente si tuviera que leer datos del almacenamiento de respaldo o esperar un bloqueo. Si se leyeron algunos datos, devolverá el número de bytes leídos. Si no se leyeron bytes, devolverá -1 y establecerá errno a EAGAIN (pero ver BUGS). Actualmente, este flag solo tiene significado para preadv2().
RWF_APPEND (desde Linux 4.16)
Proporciona un equivalente por escritura del flag O_APPEND de open(2). Este flag solo tiene significado para pwritev2(), y su efecto se aplica solo al rango de datos escrito por la llamada al sistema. El argumento offset no afecta la operación de escritura; los datos siempre se añaden al final del archivo. Sin embargo, si el argumento offset es -1, se actualiza el desplazamiento actual del archivo.
RWF_NOAPPEND (desde Linux 6.9)
No honrar el flag O_APPEND de open(2). Este flag solo tiene significado para pwritev2(). Históricamente, Linux respetaba el flag O_APPEND si estaba establecido e ignoraba el argumento offset, lo cual es un error. Para pwritev2(), el argumento offset se honra como se espera si el flag RWF_NOAPPEND está establecido, lo mismo que si el flag O_APPEND no estuviera establecido.
RWF_ATOMIC (desde Linux 6.11)
Requiere que las escrituras en archivos regulares en sistemas de archivos basados en bloques se emitan con protección contra escrituras de desgarro (torn-write). La protección contra escrituras de desgarro significa que, en caso de fallo eléctrico o de cualquier otro hardware, se almacenarán todos los datos de la escritura o ninguno, pero nunca una mezcla de datos viejos y nuevos. Este flag solo tiene significado para pwritev2(), y su efecto se aplica solo al rango de datos escrito por la llamada al sistema. La longitud total de la escritura debe ser una potencia de 2 y debe tener un tamaño en el rango [stx_atomic_write_unit_min, stx_atomic_write_unit_max]. La escritura debe realizarse en un desplazamiento naturalmente alineado dentro del archivo con respecto a la longitud total de la escritura. Por ejemplo, se permite una escritura de longitud 32KiB en un desplazamiento de archivo de 32KiB, sin embargo, no se permite una escritura de longitud 32KiB en un desplazamiento de archivo de 48KiB. El límite superior de iovcnt para pwritev2() viene dado por el valor en stx_atomic_write_segments_max. La protección contra escrituras de desgarro solo funciona con el flag O_DIRECT, es decir, no se admiten escrituras en búfer. Para garantizar la consistencia de la escritura entre el estado en memoria de un archivo y el dispositivo de almacenamiento, se deben especificar O_SYNC o O_DSYNC para open(2). Las mismas garantías de E/S sincronizada descritas en open(2) se proporcionan cuando estos flags o sus flags y llamadas al sistema equivalentes

DESCRIPTION

Las llamadas al sistema readv() y writev() realizan múltiples operaciones de lectura y escritura, respectivamente, en un descriptor de archivo dado. Las operaciones se especifican mediante un vector de estructuras de tipo iovec, que se pasan en el argumento iov y se especifican en número en el argumento iovcnt.

Las funciones preadv() y pwritev() son idénticas a sus homólogas readv() y writev(), respectivamente, pero realizan la operación en un desplazamiento especificado por offset en lugar de usar la posición actual del archivo. Consulte pread(2) para obtener más detalles.

Las funciones preadv2() y pwritev2() son similares a preadv() y pwritev(), pero aceptan un argumento flags adicional que modifica el comportamiento de la llamada al sistema. Consulte la sección FLAGS para obtener más detalles.

IOV_IOMODE

Estas llamadas al sistema definen las siguientes banderas para el campo flags de la estructura ioctl (o, en el caso de preadv2/pwritev2, directamente en el argumento flags). Las banderas se aplican a operaciones de lectura/escritura en archivos regulares.

RWF_SYNC (desde Linux 5.13)
Las escrituras se realizan de forma síncrona. El subsistema de E/S espera hasta que se completen todas las escrituras en el disco antes de devolver el control. Para las lecturas, esta bandera se ignora.
RWF_NOWAIT (desde Linux 5.13)
Las lecturas/escrituras se realizan de forma asíncrona. La llamada al sistema devuelve el control inmediatamente después de iniciar la operación de E/S. La operación de E/S se ejecutará en segundo plano. El número de bytes leídos o escritos se devolverá más tarde a través de la llamada al sistema io_uring_enter(2). Si se usa en el contexto de las llamadas al sistema de interfaz de usuario (no io_uring), esto indica que la llamada subyacente debe hacerse asíncrona, y las funciones wrapper subyacentes (si las hay) deberían devolver el control tan pronto como sea posible, con las E/S completándose en segundo plano. Si hay algún error, el valor de retorno será EAGAIN o EINPROGRESS. Las llamadas read(2) y write(2) deben ser llamadas posteriormente para determinar el resultado final de la operación de E/S. Si RWF_NOWAIT se usa con lecturas o escrituras que ya están completas en el búfer de páginas, estas E/S se consideran completas y no se les asigna la gestión de las E/S de fondo. Si se usa en conjunto con RWF_SYNC, la llamada esperará a que las escrituras se completen en el disco, pero aún así devolverá el control inmediatamente.
RWF_HIPRI (desde Linux 5.13)
Las operaciones de E/S tienen alta prioridad. Esto permite que las E/S se desvíen de las E/S que se están ejecutando actualmente. Esto se aplica principalmente a las E/S de disco y puede ser útil para las E/S interactivas. No todas las pilas de E/S admiten esta bandera; si la pila de E/S no la admite, se ignora y no se produce ningún error. El comportamiento exacto depende de la implementación de la pila de E/S.
RWF_DSYNC (desde Linux 5.13)
Las escrituras se realizan de forma síncrona. Esto es similar a RWF_SYNC, pero las escrituras asíncronas que fueron iniciadas antes de esta llamada se completarán antes de que la llamada retorne. Las escrituras asíncronas iniciadas después de esta llamada se completarán después de que la llamada retorne. Para las lecturas, esta bandera se ignora.
RWF_APPEND (desde Linux 5.13)
Las escrituras se añaden al final del archivo. Esto es similar a abrir el archivo en modo de adición (O_APPEND). Esto solo tiene efecto en escrituras a través de un descriptor de archivo abierto sin la bandera O_APPEND. La bandera se ignora para las lecturas.
RWF_NOWRITE (desde Linux 5.13)
Esta operación es solo para lectura. Cualquier intento de escribir datos en el búfer de páginas fallará con EROFS si el archivo es de solo lectura. Esto se puede usar para evitar escrituras accidentales al usar RWF_SYNC o RWF_DSYNC con lecturas, asegurando que no se realicen escrituras en el disco.
RWF_ATOMIC (desde Linux 6.11)
Para las escrituras, esto indica que la operación debe ser atómica. Si la operación falla parcialmente, se revertirá. La atomicidad solo se garantiza si la operación cabe en un solo bloque de asignación de disco. Si el tamaño total de los búferes en el vector iov es mayor que el tamaño de un bloque de asignación de disco, esta bandera se ignora. La llamada a pwritev2(2) fallará con EINVAL si el desplazamiento y la longitud total de la operación violan las reglas de protección contra escrituras deshilachadas. Consulte statx(2) para obtener información sobre cómo determinar el tamaño máximo de segmento de escritura atómica.
RWF_DISCARD (desde Linux 6.13)
Para las escrituras, esto indica que los bloques de disco subyacentes deben ser descartados. Esto solo es aplicable a dispositivos de almacenamiento que admiten el comando TRIM/DISCARD. Si el dispositivo no admite el descarte, la operación se realizará como una escritura normal y no se producirá ningún error. Para las lecturas, esta bandera se ignora.
RWF_NOFLUSH (desde Linux 6.13)
Las escrituras no se vaciarán inmediatamente en el disco. Esto es útil cuando se combinan varias escrituras y se desea controlar el vaciado de forma explícita utilizando sync_file_range(2). Si se especifica RWF_SYNC, esta bandera se ignora. Para las lecturas, esta bandera se ignora.
RWF_FLUSH (desde Linux 6.13)
Las escrituras se vaciarán inmediatamente en el disco. Esto es similar a RWF_SYNC, pero no garantiza que las escrituras previas se hayan completado. Si se especifica RWF_SYNC, esta bandera se ignora. Para las lecturas, esta bandera se ignora.
RWF_RANGE (desde Linux 6.14)
Las operaciones de lectura/escritura se aplicarán a un rango específico del archivo. Esto es similar a usar un archivo mapeado en memoria con protección de solo lectura y luego realizar operaciones de escritura en ese rango. Si se utiliza con operaciones de escritura, los datos escritos se mantendrán en el búfer de páginas hasta que se vacíen explícitamente. Esta bandera solo está disponible para archivos regulares. Si se utiliza en un sistema de archivos o dispositivo de bloques que no lo admite, devolverá -1 y errno se establecerá en EOPNOTSUPP.
RWF_DONTCACHE (desde Linux 6.14)
Las lecturas o escrituras en un archivo regular eliminarán el contenido instanciado del búfer de páginas cuando la operación se complete. Esto es diferente de la E/S con búfer normal, donde los datos suelen permanecer en el búfer hasta que se recuperan debido a la presión de memoria. Si los rangos de la E/S de lectura o escritura ya estaban en el búfer antes de esta lectura o escritura, esos rangos no se eliminarán al finalizar la E/S.
Además, cualquier rango ensucianado por una operación de escritura con RWF_DONTCACHE establecido se eliminará para su escritura posterior. Esto es similar a llamar a sync_file_range(2) con SYNC_FILE_RANGE_WRITE para iniciar la escritura posterior en el rango dado. RWF_DONTCACHE es una sugerencia, o mejor esfuerzo, donde no se ofrecen garantías estrictas sobre el estado del búfer de páginas una vez que la operación se completa.
Si se utiliza en un sistema de archivos o dispositivo de bloques que no lo admite, devolverá -1 y errno se establecerá en EOPNOTSUPP.

RETURN VALUE

En caso de éxito, readv(), preadv(), y preadv2() devuelven el número de bytes leídos; writev(), pwritev(), y pwritev2() devuelven el número de bytes escritos.

Tenga en cuenta que no es un error que una llamada exitosa transfiera menos bytes de los solicitados (ver read(2) y write(2)).

En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORS

Los errores son los mismos que para read(2) y write(2). Además, preadv(), preadv2(), pwritev(), y pwritev2() también pueden fallar por las mismas razones que lseek(2). Adicionalmente, se definen los siguientes errores:

EINVAL
La suma de los valores iov_len desborda un valor ssize_t.
EINVAL
Si se especifica RWF_ATOMIC, la combinación de la suma de los valores iov_len y el valor offset no cumple con las reglas de protección contra escrituras deshilachadas de longitud y desplazamiento.
EINVAL
El número de vectores, iovcnt, es menor que cero o mayor que el máximo permitido. Si se especifica RWF_ATOMIC, este máximo viene dado por el valor stx_atomic_write_segments_max de statx.
EOPNOTSUPP
Se estableció RWF_DONTCACHE en flags y el archivo no lo admite.
EOPNOTSUPP
Se especifica una bandera desconocida en flags.

VERSIONS

C library/kernel differences

Las llamadas al sistema brutas preadv() y pwritev() tienen firmas de llamada que difieren ligeramente de las de las funciones wrapper correspondientes de la biblioteca C de GNU que se muestran en la SINOPSIS. El argumento final, offset, se desempaqueta por las funciones wrapper en dos argumentos en las llamadas al sistema:

unsigned long pos_l, unsigned long pos

Estos argumentos contienen, respectivamente, los 32 bits de orden bajo y de orden alto de offset.

Historical C library/kernel differences

Para hacer frente al hecho de que IOV_MAX era tan bajo en las primeras versiones de Linux, las funciones wrapper de glibc para readv() y writev() realizaron un trabajo adicional si detectaban que la llamada al sistema subyacente fallaba porque se excedía este límite. En el caso de readv(), la función wrapper asignó un búfer temporal lo suficientemente grande para todos los elementos especificados por iov, pasó ese búfer en una llamada a read(2), copió datos del búfer a las ubicaciones especificadas por los campos iov_base de los elementos de iov, y luego liberó el búfer. La función wrapper para writev() realizó la tarea análoga utilizando un búfer temporal y una llamada a write(2).

La necesidad de este esfuerzo adicional en las funciones wrapper de glibc desapareció con Linux 2.2 y posteriores. Sin embargo, glibc continuó proporcionando este comportamiento hasta glibc 2.10. A partir de glibc 2.9, las funciones wrapper solo proporcionan este comportamiento si la biblioteca detecta que el sistema está ejecutando un kernel de Linux anterior a Linux 2.6.18 (una versión de kernel seleccionada arbitrariamente). Y desde glibc 2.20 (que requiere un mínimo de Linux 2.6.32), las funciones wrapper de glibc siempre invocan directamente las llamadas al sistema.

NOTES

POSIX.1 permite a una implementación establecer un límite en el número de elementos que se pueden pasar en iov. Una implementación puede anunciar su límite definiendo IOV_MAX en <limits.h> o en tiempo de ejecución a través del valor de retorno de sysconf(_SC_IOV_MAX). En los sistemas Linux modernos, el límite es 1024. En los días de Linux 2.0, este límite era 16.

BUGS

Linux 5.9 y Linux 5.10 tienen un error donde preadv2() con la bandera RWF_NOWAIT puede devolver 0 incluso cuando no está al final del archivo.

EXAMPLES

El siguiente ejemplo de código demuestra el uso de writev():


char          *str0 = "hello ";
char          *str1 = "world\n";
ssize_t       nwritten;
struct iovec  iov[2];
iov[0].iov_base = str0;
iov[0].iov_len = strlen(str0);
iov[1].iov_base = str1;
iov[1].iov_len = strlen(str1);
nwritten = writev(STDOUT_FILENO, iov, 2);
