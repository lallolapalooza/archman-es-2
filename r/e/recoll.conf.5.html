RECOLL.CONF(5) Manual de Formatos de Archivo RECOLL.CONF(5)

NOMBRE

recoll.conf - archivo de configuración personal principal para Recoll

DESCRIPCIÓN

Este archivo define la configuración del índice para el sistema de búsqueda de texto completo Recoll.

El archivo de configuración a nivel de sistema se encuentra normalmente dentro de /usr/[local]/share/recoll/examples. Cualquier parámetro establecido en el archivo común puede ser anulado estableciéndolo en el archivo de configuración de índice específico, por defecto: $HOME/.recoll/recoll.conf

Todos los comandos de recoll aceptarán una opción -c o usarán la variable de entorno $RECOLL_CONFDIR para especificar un directorio de configuración de índice no predeterminado.

Un extracto corto del archivo podría verse así:

# Lista separada por espacios de directorios a indexar.
topdirs =  ~/docs /usr/share/doc
[~/somedirectory-with-utf8-txt-files]
defaultcharset = utf-8

Hay tres tipos de líneas:

  • Comentario o línea vacía.
  • Afectación de parámetro.
  • Definición de sección.

Las líneas vacías o las líneas que comienzan con # se ignoran.

Las líneas de afectación tienen la forma 'nombre = valor'. En la siguiente descripción, también tienen un tipo, que es principalmente indicativo. Los dos no obvios son 'fn': ruta de archivo, y 'dfn': ruta de directorio.

Las líneas de sección permiten redefinir un parámetro para un subárbol de directorio. Algunos de los parámetros utilizados para la indexación se buscan jerárquicamente, de lo más específico a lo menos específico. No todos los parámetros pueden redefinirse de manera significativa, esto se especifica para cada uno en la siguiente sección.

El carácter tilde (~) se expande en nombres de archivo al directorio de inicio del usuario.

Algunos valores de tipo 'string' son listas, lo que solo se indica por su descripción. En este caso, se usan espacios en blanco para la separación, y los elementos con espacios incrustados se pueden entrecomillar con comillas dobles.

OPCIONES

topdirs = string
Lista separada por espacios de archivos o directorios a indexar recursivamente. Puedes usar enlaces simbólicos en la lista, se seguirán, independientemente del valor de la variable followLinks. El valor por defecto es ~ : indexar recursivamente $HOME.
monitordirs = string
Lista separada por espacios de archivos o directorios a monitorear para actualizaciones. Al ejecutar el indexador en tiempo real, esto permite monitorear solo un subconjunto de toda el área indexada. Los elementos deben estar incluidos en el árbol definido por los miembros de 'topdirs'.
skippedNames = string
Nombres de archivos y directorios que deben ignorarse. Lista separada por espacios de patrones de comodines (simples, no rutas, no deben contener caracteres de ruta como '/').

Echa un vistazo a la configuración por defecto para el valor inicial, algunas entradas pueden no ser adecuadas para tu situación. La forma más fácil de verlo es a través del panel "parámetros locales" de configuración del índice de la GUI.

La lista en la configuración por defecto no excluye los directorios ocultos (nombres que comienzan con un punto), lo que significa que puede indexar bastantes cosas que no deseas. Por otro lado, los agentes de correo electrónico como Thunderbird suelen almacenar mensajes en directorios ocultos, y probablemente quieras que esto se indexe. Una solución posible es tener ".*" en "skippedNames", y añadir cosas como "~/.thunderbird" "~/.evolution" a "topdirs".

Ni siquiera los nombres de archivo se indexan para los patrones en esta lista, ver la variable "noContentSuffixes" para un enfoque alternativo que indexa los nombres de archivo. Puede ser redefinido para cualquier subdirectorio.

skippedNames- = string
Lista de patrones de nombres a eliminar de la lista predeterminada de skippedNames. Permite modificar la lista en la configuración local sin copiarla.
skippedNames+ = string
Lista de patrones de nombres a añadir a la lista predeterminada de skippedNames. Permite modificar la lista en la configuración local sin copiarla.
onlyNames = string
Patrones de filtro de nombres de archivo regulares. Normalmente está vacío. Si se establece, solo los nombres de archivo que no estén en skippedNames y coincidan con uno de los patrones se considerarán para indexar. Puede ser redefinido por subdirectorio. No se aplica a directorios.
noContentSuffixes = string
Lista de terminaciones de nombre (no necesariamente sufijos separados por puntos) para las cuales no intentamos identificar el tipo MIME, ni descomprimimos o indexamos el contenido. Solo se indexarán los nombres. Esto complementa la lista obsoleta recoll_noindex del archivo mimemap, que desaparecerá en una futura versión (el cambio de mimemap a recoll.conf permite editar la lista a través de la GUI). Esto es diferente de skippedNames porque son solo coincidencias de terminación de nombre (no patrones comodín), y el nombre del archivo en sí se indexa normalmente. Esto puede ser redefinido para subdirectorios.
noContentSuffixes- = string
Lista de terminaciones de nombre a eliminar de la lista predeterminada de noContentSuffixes.
noContentSuffixes+ = string
Lista de terminaciones de nombre a añadir a la lista predeterminada de noContentSuffixes.
skippedPaths = string
Rutas absolutas en las que no debemos entrar. Lista separada por espacios de expresiones de comodín para rutas absolutas del sistema de archivos (para archivos o directorios). La variable debe definirse en el nivel superior del archivo de configuración, no en una subsección.

Cualquier valor en la lista debe ser textual y consistentemente con los valores en topdirs, no se hacen intentos de resolver enlaces simbólicos. En la práctica, si, como es frecuente, /home es un enlace a /usr/home, tus topdirs predeterminados tendrán una única entrada "~" que se traducirá a "/home/tu_usuario". En este caso, cualquier entrada de skippedPaths debería comenzar con "/home/tu_usuario", *no* con "/usr/home/tu_usuario".

Los directorios de índice y configuración se añadirán automáticamente a la lista.

Las expresiones se comparan usando "fnmatch(3)" con la bandera FNM_PATHNAME activada por defecto. Esto significa que los caracteres "/" deben coincidir explícitamente. Puedes establecer "skippedPathsFnmPathname" a 0 para deshabilitar el uso de FNM_PATHNAME (lo que significa que "/*/dir3" coincidirá con "/dir1/dir2/dir3").

El valor predeterminado contiene el punto de montaje habitual para medios extraíbles para recordarte que en la mayoría de los casos es una mala idea que Recoll trabaje en ellos. Añadir explícitamente "/media/xxx" a la variable "topdirs" anulará esto.

skippedPathsFnmPathname = bool
Establecido a 0 para anular el uso de FNM_PATHNAME para comparar rutas saltadas.
nowalkfn = string
Nombre de archivo que provocará que su directorio padre sea saltado. Cualquier directorio que contenga un archivo con este nombre será saltado como si fuera parte de la lista skippedPaths. Ej: .recoll-noindex
daemSkippedPaths = string
Equivalente a skippedPaths específico para la indexación en tiempo real. Esto permite tener partes del árbol que se indexan inicialmente pero no se monitorean. Si daemSkippedPaths no está establecido, el demonio usa skippedPaths.
followLinks = bool
Seguir enlaces simbólicos durante la indexación. El valor predeterminado es ignorar los enlaces simbólicos para evitar la indexación múltiple de archivos enlazados. No se hace ningún esfuerzo para evitar la duplicación cuando esta opción se establece a true. Esta opción se puede establecer individualmente para cada uno de los miembros de "topdirs" usando secciones. No se puede cambiar por debajo del nivel de "topdirs". Los enlaces en la propia lista de "topdirs" siempre se siguen.

Los nombres de tipo MIME deben tomarse del archivo mimemap (los valores pueden ser diferentes de la salida de xdg-mime o file -i en algunos casos). Se puede redefinir para subárboles.
excludedmimetypes = string
Lista de tipos MIME excluidos. Te permite excluir algunos tipos de la indexación. Los nombres de tipo MIME deben tomarse del archivo mimemap (los valores pueden ser diferentes de la salida de xdg-mime o file -i en algunos casos) Se puede redefinir para subárboles.
nomd5types = string
Tipos MIME para los cuales no calculamos un hash md5. Las sumas de verificación md5 se utilizan solo para deduplicar resultados y pueden ser muy costosas de calcular en archivos multimedia u otros archivos grandes. Esta lista te permite desactivar el cálculo de md5 para tipos seleccionados. Es global (sin redefinición para subárboles). En este momento, solo tiene efecto para manejadores externos (exec y execm). Los tipos de archivo se pueden especificar enumerando tipos MIME (por ejemplo, audio/mpeg) o nombres de manejadores (por ejemplo, rclaudio.py).
compressedfilemaxkbs = int
Límite de tamaño para archivos comprimidos. Necesitamos descomprimirlos en un directorio temporal para su identificación, lo que puede ser ineficiente en algunos casos. Limita el desperdicio. Un valor negativo significa sin límite. 0 resulta en no procesar ningún archivo comprimido. Por defecto 100 MB.
textfilemaxmbs = int
Límite de tamaño para archivos de texto. Principalmente para omitir registros gigantes. También se utiliza para el tamaño máximo del cuerpo de los correos electrónicos. Por defecto 20 MB. Utiliza un valor de -1 para deshabilitar.
textfilepagekbs = int
Tamaño de página para archivos de texto. Si esto está configurado, los archivos text/plain se dividirán en documentos de aproximadamente este tamaño. Esto reducirá el uso de memoria en tiempo de indexación y ayudará a cargar datos en la ventana de vista previa en tiempo de consulta. Particularmente útil con archivos muy grandes, como registros de aplicaciones o del sistema. También ver textfilemaxmbs y compressedfilemaxkbs.
textunknownasplain = bool
Procesar archivos unknown text/xxx como text/plain Permite indexar archivos de texto varios identificados como text/whatever por "file" o "xdg-mime" sin tener que configurar explícitamente entradas de configuración para ellos. Esto funciona bien para la indexación (también provocará el procesamiento de muchos archivos inútiles), pero los documentos indexados de esta manera serán abiertos por el visor de escritorio, incluso si text/plain tiene un editor específico.
indexallfilenames = bool
Indexa los nombres de archivo de los archivos no procesados. Indexa los nombres de los archivos cuyo contenido no indexamos debido a un tipo MIME excluido o no compatible.
usesystemfilecommand = bool
Utiliza un mecanismo del sistema como último recurso para adivinar un tipo MIME. Dependiendo de la plataforma y la versión, una configuración en tiempo de compilación decidirá si realmente ejecuta un comando o utiliza libmagic. Esta identificación de último recurso (si la basada en sufijo falló) es generalmente útil, pero provocará la indexación de muchos archivos "text" falsos sin extensión. También ver "systemfilecommand".
systemfilecommand = string
Comando a utilizar para adivinar el tipo MIME si los métodos internos fallan. Esto se ignora en Windows o con Recoll 1.38+ si se compila con libmagic habilitado (por defecto). De lo contrario, esto debería ser un simulador de "file -i". La ruta del archivo se añadirá como último parámetro a la línea de comandos. "xdg-mime" funciona mejor que el comando tradicional "file", y ahora es el predeterminado configurado (con una opción de respaldo fija a "file").
processwebqueue = bool
Decide si procesamos la cola web. La cola es un directorio donde los plugins del navegador web de Recoll crean las copias de las páginas visitadas.
membermaxkbs = int
Límite de tamaño para los miembros del archivo. Esto se pasa a los manejadores MIME en el entorno como RECOLL_FILTER_MAXMEMBERKB.
indexStripChars = bool
Decide si almacenamos la capitalización de caracteres y los diacríticos en el índice. Si lo hacemos, se pueden realizar búsquedas sensibles a mayúsculas y minúsculas y diacríticos, pero el índice será más grande y a veces pueden ocurrir algunas rarezas marginales. El valor predeterminado es un índice "stripped" (sin distinción). Al usar múltiples índices para una búsqueda, este parámetro debe definirse de manera idéntica para todos. Cambiar el valor implica un reinicio del índice.
indexStoreDocText = bool
Decide si almacenamos el contenido de texto de los documentos en el índice. Almacenar el texto permite extraer fragmentos del mismo en tiempo de consulta, en lugar de construirlos a partir de datos de posición del índice.

Los formatos de índice Xapian más recientes han hecho que nuestro uso de la lista de posiciones sea inaceptablemente lento en algunos casos. El último formato de índice Xapian con buen rendimiento para el método antiguo es Chert, que es el predeterminado para 1.2, todavía soportado pero no predeterminado en 1.4 y se eliminará en 1.6.

El texto del documento almacenado se traduce de su formato original a texto plano UTF-8, pero no se le quitan mayúsculas, diacríticos ni signos de puntuación. Almacenarlo aumenta el tamaño del índice en un 10-20% típicamente, pero también permite obtener fragmentos más agradables, por lo que puede valer la pena habilitarlo incluso si no es estrictamente necesario para el rendimiento si puedes permitirte el espacio.

La variable solo tiene efecto al crear un índice, lo que significa que el directorio xapiandb no debe existir todavía. Su efecto exacto depende de la versión de Xapian.

Para Xapian 1.4, si la variable se establece en 0, solíamos usar el formato Chert y no almacenar el texto. Si la variable era 1, se usaba Glass y se almacenaba el texto. Ya no hacemos esto: almacenar el texto ha demostrado ser la opción mucho mejor, y eliminar esta posibilidad simplifica el código.

Por lo tanto, ahora, el formato del índice para un nuevo índice es siempre el predeterminado, pero la variable todavía controla si se almacena el texto o no, y el método de generación abstracta. Con Xapian 1.4 y posteriores, y la variable establecida en 0, la generación abstracta puede ser muy lenta, pero esta configuración aún puede ser útil para ahorrar espacio si no se utiliza la generación abstracta en absoluto, utilizando la configuración adecuada en la GUI y/o evitando la API de Python o las opciones de recollq que la activarían.

nonumbers = bool
Decide si se generarán términos para números. Por ejemplo "123", "1.5e6", 192.168.1.4, no se indexarían si nonumbers está configurado ("value123" todavía lo estaría). Los números a menudo son muy interesantes para buscar, y esto probablemente no debería configurarse, excepto en situaciones especiales, es decir, documentos científicos con enormes cantidades de números, donde configurar nonumbers reducirá el tamaño del índice. Esto solo se puede configurar para un índice completo, no para un subárbol.
notermpositions = bool
No almacenar posiciones de términos. Las posiciones de términos permiten búsquedas de frases y proximidad, pero hacen el índice mucho más grande. En algunas circunstancias especiales, puede que quieras prescindir de ellas.
dehyphenate = bool
Determina si indexamos "coworker" también cuando la entrada es "co-worker". Esto es nuevo en la versión 1.22 y está activado por defecto. Establecer la variable en "off" permite restaurar el comportamiento anterior.
indexedpunctuation = string
Cadena de caracteres de puntuación UTF-8 que se indexarán como palabras. Los términos resultantes serán buscables y, por ejemplo, al configurar el parámetro a "%€" (sin las comillas dobles), podrías buscar por separado "100%" o "100€". Ten en cuenta que "100%" o "100 %" se indexarían de la misma manera, los caracteres son sus propios separadores de palabras.
backslashasletter = bool
Procesar la barra invertida como una letra normal. Esto puede tener sentido para personas que quieren indexar comandos de TeX tal cual, pero no tiene mucho uso general.
underscoreasletter = bool
Procesar el guion bajo como una letra normal. Esto tiene sentido en tantos casos que uno se pregunta si no debería ser el predeterminado.
maxtermlength = int
Longitud máxima del término en caracteres Unicode. Las palabras más largas que esto serán descartadas. El valor predeterminado es 40 y solía estar codificado de forma fija, pero ahora se puede ajustar. Puede que necesites un reinicio del índice si cambias el valor.
maxdbdatarecordkbs = int
Tamaño binario máximo de un registro de datos de documento Xapian. El registro de datos almacena metadatos de documentos "almacenados". Un tamaño muy grande generalmente indica un error en el análisis del documento. Xapian tiene un límite estricto de alrededor de 100 MB para esto.
maxdbstoredtextmbs = int
Tamaño binario máximo del texto almacenado de un documento. Xapian tiene un límite estricto de alrededor de 100 MB para el valor comprimido, pero nuestro límite es anterior a la compresión, por lo que puede haber cierto margen.
nocjk = bool
Decide si se desactiva la división específica de caracteres/palabras de Asia Oriental (chino, coreano, japonés). Esto ahorrará una pequeña cantidad de CPU si no tienes documentos CJK. Si tu base de documentos incluye dicho texto pero no te interesa buscarlo, configurar nocjk puede ser un ahorro significativo de tiempo y espacio.
cjkngramlen = int
Esto te permite ajustar el tamaño de los n-gramas utilizados para indexar texto CJK. El valor predeterminado de 2 es probablemente apropiado en
En la mayoría de los casos. Un valor de 3 permitiría más precisión y eficiencia en palabras más largas, pero el índice será aproximadamente el doble de grande.
hangultagger = string
Tokenizador externo para coreano Hangul. Esto permite usar un procesador específico del idioma para extraer términos del texto coreano, en lugar del generador genérico de términos n-gramas. Ver https://www.recoll.org/pages/recoll-korean.html para instrucciones.
chinesetagger = string
Tokenizador externo para chino. Esto permite usar el tokenizador Jieba específico del idioma para extraer términos significativos del texto chino, en lugar del generador genérico de términos n-gramas. Ver https://www.recoll.org/pages/recoll-chinese.html para instrucciones.
indexstemminglanguages = string
Idiomas para los que se crearán datos de expansión de stemmer. Los nombres de los stemmers se pueden encontrar ejecutando "recollindex -l", o también se pueden establecer a partir de una lista en la GUI. Los valores son nombres completos de idiomas, por ejemplo, inglés, francés...
defaultcharset = string
Juego de caracteres predeterminado. Se utiliza para archivos que no contienen una definición de juego de caracteres (por ejemplo, text/plain). Los valores encontrados dentro de los archivos, por ejemplo, una etiqueta "charset" en documentos HTML, lo anularán. Si no se establece, el juego de caracteres predeterminado es el definido por el entorno NLS ($LC_ALL, $LC_CTYPE, $LANG), o en última instancia iso-8859-1 (de hecho cp-1252). Si por alguna razón desea un valor predeterminado general que no coincida con su LANG y no sea 8859-1, utilice esta variable. Esto se puede redefinir para cualquier subdirectorio.
unac_except_trans = string
Una lista de caracteres, codificados en UTF-8, que deben tratarse de forma especial al convertir texto a minúsculas sin acentos. Por ejemplo, en sueco, la letra 'a' con diéresis tiene plena ciudadanía en el alfabeto y no debe convertirse en 'a'. Cada elemento de la lista separada por espacios tiene el carácter especial como primer elemento y la traducción siguiente. El tratamiento de las versiones en minúsculas y mayúsculas de un carácter debe especificarse, ya que la pertenencia a la lista desactivará tanto el procesamiento estándar de acentos como de mayúsculas/minúsculas. El valor es global y afecta tanto a la indexación como a la consulta. También convertimos algunos caracteres Unicode confusos (comillas, guiones) a su equivalente ASCII para evitar fallos de búsqueda "invisibles".

maildefcharset = string
Anula el juego de caracteres predeterminado para los mensajes de correo electrónico que no especifican uno. Esto es útil principalmente para volcados de readpst (libpst), que son utf-8 pero no lo indican.
localfields = string
Establece campos en todos los archivos (normalmente de un área de sistema de archivos específica). La sintaxis es la habitual: nombre = valor ; attr1 = val1 ; [...] El valor está vacío, por lo que necesita un punto y coma inicial. Esto es útil, por ejemplo, para establecer el campo rclaptg para la selección de aplicaciones dentro de mimeview.
testmodifusemtime = bool
Utiliza mtime en lugar de ctime para comprobar si un archivo ha sido modificado. La hora se utiliza además del tamaño, que siempre se utiliza. Establecer esto puede reducir la reindexación en sistemas donde se utilizan atributos extendidos (por alguna otra aplicación), pero no se indexan, porque el cambio de atributos extendidos solo afecta a ctime. Notas: - Esto puede evitar la detección de cambios en algunos casos marginales de renombrado de archivos (el destino necesitaría tener el mismo tamaño y mtime). - Probablemente también debería establecer noxattrfields a 1 en este caso, excepto si todavía prefiere realizar la indexación de xattr, por ejemplo, si el patrón de actualización de archivos local lo hace valioso (como en general, existe el riesgo de que las actualizaciones de atributos extendidos puras sin modificación de archivo pasen desapercibidas). Realice un restablecimiento completo del índice después de cambiar esto.
noxattrfields = bool
Deshabilita la conversión de atributos extendidos a campos de metadatos. Esto probablemente necesita establecerse si testmodifusemtime está establecido.
metadatacmds = string
Define comandos para recopilar metadatos externos, por ejemplo, etiquetas tmsu. Puede haber varias entradas, separadas por punto y coma, cada una definiendo en qué nombre de campo van los datos y el comando a utilizar. No olvide el punto y coma inicial. Todos los nombres de campo deben ser diferentes. Puede utilizar alias en el archivo "field" si es necesario. Como un truco no muy elegante concedido por conveniencia, cualquier nombre de campo que comience con "rclmulti" se tomará como una indicación de que el comando devuelve varios valores de campo dentro de un blob de texto formateado como un archivo de configuración de recoll (líneas "fieldname = fieldvalue"). Se ignorará el nombre rclmultixx, y los nombres y valores de campo se analizarán a partir de los datos. Ejemplo: metadatacmds = ; tags = tmsu tags %f; rclmulti1 = cmdOutputsConf %f
cachedir = dfn
Directorio principal para los datos de Recoll. Los directorios de datos de Recoll normalmente se encuentran en relación con el directorio de configuración (por ejemplo, ~/.recoll/xapiandb, ~/.recoll/mboxcache). Si se establece "cachedir", los directorios se almacenan bajo el valor especificado en su lugar (por ejemplo, si cachedir es ~/.cache/recoll, el dbdir predeterminado sería ~/.cache/recoll/xapiandb). Esto afecta a dbdir, webcachedir, mboxcachedir, aspellDicDir, que aún pueden especificarse individualmente para anular cachedir. Tenga en cuenta que si tiene varias configuraciones, cada una debe tener un cachedir diferente, no hay un cálculo automático de una subruta dentro de cachedir.
maxfsoccuppc = int
Ocupación máxima del sistema de archivos por encima de la cual detenemos la indexación. El valor es un porcentaje, correspondiente a lo que muestra la columna "Capacity" de la salida df. El valor predeterminado es 0, lo que significa que no hay comprobación. Este parámetro solo se comprueba cuando el indexador se inicia, no cambiará el comportamiento de un proceso en ejecución.
dbdir = dfn
Ubicación del directorio de la base de datos Xapian. Se creará en la primera indexación. Si el valor no es una ruta absoluta, se interpretará como relativo a cachedir si está establecido, o al directorio de configuración (argumento -c o $RECOLL_CONFDIR). Si no se especifica nada, el valor predeterminado es ~/.recoll/xapiandb/
idxstatusfile = fn
Nombre del archivo temporal donde el proceso indexador actualiza su estado. Predeterminado: idxstatus.txt dentro del directorio de configuración.
mboxcachedir = dfn
Ubicación del directorio para almacenar los archivos de caché de offsets de mensajes mbox. Normalmente es "mboxcache" bajo cachedir si está establecido, o de lo contrario bajo el directorio de configuración, pero puede ser útil compartir un directorio entre diferentes configuraciones.
mboxcacheminmbs = int

El valor compilado del programa es 0. El valor por defecto configurado (de este archivo) es ahora de 50 MB, y debería estar bien en muchos casos. Profundidades de cola de tareas para cada etapa y control de configuración de hilos. Hay tres colas internas en las etapas del pipeline de indexación (extracción de datos de archivos, generación de términos, actualización de índice). Este parámetro define las profundidades de cola para cada etapa (tres valores enteros). En la práctica, las colas profundas no han demostrado aumentar el rendimiento. El primer valor también se usa para controlar la autoconfiguración de hilos o la deshabilitación de multihilo. Si la profundidad de la primera cola se establece en 0, Recoll establecerá las profundidades de cola y los recuentos de hilos basándose en el número de CPUs detectados. Los valores elegidos arbitrariamente son los siguientes (profundidad, nthread). 1 CPU -> sin hilos. Menos de 4 CPUs: (2, 2) (2, 2) (2, 1). Menos de 6: (2, 4), (2, 2), (2, 1). De lo contrario (2, 5), (2, 3), (2, 1). Si la profundidad de la primera cola se establece en -1, el multihilo se deshabilitará por completo. Los segundo y tercer valores se ignoran en ambos casos.

Número de hilos utilizados para cada etapa de indexación. Si la primera entrada en thrQSizes no es 0 o -1, estos tres valores definen el número de hilos utilizados para cada etapa (extracción de datos de archivos, generación de términos, actualización de índice). No tiene sentido usar un valor diferente de 1 para la última etapa porque la actualización del índice Xapian es necesariamente de un solo hilo (y protegida por un mutex).

Número de índices temporales utilizados durante la indexación incremental o completa. Si no se establece a cero, esto define cuántos índices temporales utilizamos durante la indexación. Estos índices temporales se fusionan con el principal al final de la operación. Usar múltiples índices y una fusión final puede mejorar significativamente el rendimiento de la indexación cuando las actualizaciones de índice Xapian de un solo hilo se convierten en un cuello de botella. Qué tan útil es esto depende del tipo de entrada y la CPU. Consulte el manual para más detalles.

recoll.conf(5) — Recoll

NAME

recoll.conf — Recoll configuration file

DESCRIPTION

The file recoll.conf contains configuration parameters for the Recoll search tool. Some parameters can be set globally and some are specific to a given directory (and its subdirectories). This enables fine-grained control over the indexing process.

Each parameter is set by a line starting with the parameter name, followed by an equals sign and the value.

A parameter value can be of type string, boolean (true/false), or a path.

Comments start with a # character and extend to the end of the line.

Parameters can be grouped in sections using square brackets, for example:

        [Where]
        basedir = /home/user/Documents

Parameters defined in a section override the global settings for the directory specified by the section name (if any).

The indexing daemon recollindexd reads this file. It is also used by the recoll command-line interface, for example to set the default configuration file to use.

The configuration file is searched for in the following locations, in order:

  • The directory specified by the RECOLL_CONFDIR environment variable.

  • The $HOME/.recoll directory.

  • The system-wide configuration directory, usually /etc/recoll.

OPTIONS

extractorsconf = dfn
Set the configuration file for the extractors. This file is parsed by the specific document parsers (e.g. for PDF, ODT, etc.). It is read once when the recollindexd daemon starts. The default is $RECOLL_CONFDIR/extractors.conf.
fieldsconf = dfn
Set the configuration file for the fields. This file is used to specify how to process extracted data. It can specify which fields to keep, how to translate them, and how to create new fields. It is read once when the recollindexd daemon starts. The default is $RECOLL_CONFDIR/fields.
pdfextrametafix = fn
Define the name of the XMP field editing script. This defines the name of a script to be loaded for editing XMP field values. The script should define a "MetaFixer" class with a metafix() method which will be called with the qualified tag name and value of each selected field, for editing or erasing. A new instance is created for each document, so that the object can keep state for, e.g. eliminating duplicate values.
zipUseSkippedNames = bool
Use skippedNames inside Zip archives. Fetched directly by the rclzip.py handler. Skip the patterns defined by skippedNames inside Zip archives. Can be redefined for subdirectories. See https://www.recoll.org/faqsandhowtos/FilteringOutZipArchiveMembers.html
zipSkippedNames = string
Space-separated list of wildcard expressions for names that should be ignored inside zip archives. This is used directly by the zip handler. If zipUseSkippedNames is not set, zipSkippedNames defines the patterns to be skipped inside archives. If zipUseSkippedNames is set, the two lists are concatenated and used. Can be redefined for subdirectories. See https://www.recoll.org/faqsandhowtos/FilteringOutZipArchiveMembers.html
zipMetaEncoding = string
File path encoding. Needs Python 3.11+. Set to "detect" for using chardet. This is useful for non-standard zip files where the metadata is neither UTF-8 (indicated by a file flag), nor CP437 (default). The parameter can be set for specific subtrees. You need to install the Python3 "chardet" package if the value is set to "detect".
orgmodesubdocs = bool
Index org-mode level 1 sections as separate sub-documents This is the default. If set to false, org-mode files will be indexed as plain text
mhmboxquirks = string
Enable thunderbird/mozilla-seamonkey mbox format quirks Set this for the directory(ies) where the email mbox files are stored.
imgocr = bool
Tell the non-default Python image handler to run OCR. See the PDF section for PDF OCR. The image OCR also needs mimeconf changes. See the manual. imgocr can be defined for subdirectories.
ocrprogs = string
OCR modules to try. The top OCR script will try to load the corresponding modules in order and use the first which reports being capable of performing OCR on the input file. Modules for tesseract (tesseract) and ABBYY FineReader (abbyy) are present in the standard distribution. For compatibility with the previous version, if this is not defined at all, the default value is "tesseract". Use an explicit empty value if needed. A value of "abbyy tesseract" will try everything.

tesseractlang = string
Language to assume for tesseract OCR. Important for improving the OCR accuracy. This can also be set through the contents of a file in the currently processed directory. See the rclocrtesseract.py script. Example values: eng, fra... See the tesseract documentation.
tesseractcmd = fn
Path for the tesseract command. Do not quote. This is mostly useful on Windows, or for specifying a non-default tesseract command. E.g. on Windows. tesseractcmd = C:/ProgramFiles(x86)/Tesseract-OCR/tesseract.exe
abbyylang = string
Language to assume for abbyy OCR. Important for improving the OCR accuracy. This can also be set through the contents of a file in the currently processed directory. See the rclocrabbyy.py script. Typical values: English, French... See the ABBYY documentation.
abbyyocrcmd = fn
Path for the abbyy command The ABBY directory is usually not in the path, so you should set this.
speechtotext = string
Activate speech to text conversion The only possible value at the moment is "whisper" for using the OpenAI whisper program.
sttmodel = string
Name of the whisper model
sttdevice = string
Name of the device to be used by for whisper
