readdir(3)

readdir(3) Manual de Funciones de Biblioteca readdir(3)

NOMBRE

readdir - leer un directorio

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <dirent.h>
struct dirent *readdir(DIR *dirp);

DESCRIPCIÓN

La función readdir() devuelve un puntero a una estructura dirent que representa la siguiente entrada de directorio en el flujo de directorio apuntado por dirp. Devuelve NULL al llegar al final del flujo de directorio o si ocurrió un error.

En la implementación de glibc, la estructura dirent se define de la siguiente manera:


struct dirent {
    ino_t          d_ino;       /* Número de inodo */
    off_t          d_off;       /* No es un desplazamiento; ver abajo */
    unsigned short d_reclen;    /* Longitud de este registro */
    unsigned char  d_type;      /* Tipo de archivo; no soportado
                                   por todos los tipos de sistema de archivos */
    char           d_name[256]; /* Nombre de archivo terminado en nulo */
};

Los únicos campos en la estructura dirent que son obligatorios según POSIX.1 son d_name y d_ino. Los otros campos no están estandarizados y no están presentes en todos los sistemas; ver VERSIONES.

Los campos de la estructura dirent son los siguientes:

d_ino
Este es el número de inodo del archivo.
d_off
El valor devuelto en d_off es el mismo que devolvería al llamar a telldir(3) en la posición actual del flujo de directorio. Tenga en cuenta que a pesar de su tipo y nombre, el campo d_off rara vez es algún tipo de desplazamiento de directorio en sistemas de archivos modernos. Las aplicaciones deben tratar este campo como un valor opaco, sin hacer suposiciones sobre su contenido; ver también telldir(3).
d_reclen
Este es el tamaño (en bytes) del registro devuelto. Esto puede no coincidir con el tamaño de la definición de la estructura que se muestra arriba; ver VERSIONES.
d_type
Este campo contiene un valor que indica el tipo de archivo, lo que permite evitar el gasto de llamar a lstat(2) si las acciones posteriores dependen del tipo de archivo.
Cuando se define una macro de prueba de características adecuada ( _DEFAULT_SOURCE desde glibc 2.19, o _BSD_SOURCE en glibc 2.19 y anteriores), glibc define las siguientes constantes de macro para el valor devuelto en d_type:
DT_BLK
Este es un dispositivo de bloques.
DT_CHR
Este es un dispositivo de caracteres.
DT_DIR
Este es un directorio.
DT_FIFO
Esta es una tubería con nombre (FIFO).
DT_LNK
Este es un enlace simbólico.
DT_REG
Este es un archivo regular.
DT_SOCK
Este es un socket de dominio UNIX.
DT_UNKNOWN
No se pudo determinar el tipo de archivo.
Actualmente, solo algunos sistemas de archivos (entre ellos: Btrfs, ext2, ext3 y ext4) tienen soporte completo para devolver el tipo de archivo en d_type. Todas las aplicaciones deben manejar correctamente un retorno de DT_UNKNOWN.
d_name
Este campo contiene el nombre de archivo terminado en nulo; ver VERSIONES.

Los datos devueltos por readdir() pueden ser sobrescritos por llamadas posteriores a readdir() para el mismo flujo de directorio.

VALOR DE RETORNO

En caso de éxito, readdir() devuelve un puntero a una estructura dirent. (Esta estructura puede estar asignada estáticamente; no intente free(3)la.)

Si se llega al final del flujo de directorio, se devuelve NULL y errno no se modifica. Si ocurre un error, se devuelve NULL y errno se establece para indicar el error. Para distinguir el final del flujo de un error, establezca errno a cero antes de llamar a readdir() y luego verifique el valor de errno si se devuelve NULL.

ERRORES

EBADF
Descriptor de flujo de directorio inválido dirp.

ATRIBUTOS

Para una explicación de los términos utilizados en esta sección, consulte attributes(7).

Interfaz Atributo Valor
readdir () Seguridad en hilos MT-Unsafe race:dirstream

En la especificación POSIX.1 actual (POSIX.1-2008), no se requiere que readdir() sea seguro para hilos. Sin embargo, en implementaciones modernas (incluida la implementación de glibc), las llamadas concurrentes a readdir() que especifican diferentes flujos de directorio son seguras para hilos. En casos donde múltiples hilos deben leer del mismo flujo de directorio, usar readdir() con sincronización externa sigue siendo preferible al uso de la función obsoleta readdir_r(3). Se espera que una versión futura de POSIX.1 requiera que readdir() sea seguro para hilos cuando se emplee concurrentemente en diferentes flujos de directorio.

VERSIONES

Solo los campos d_name y (como extensión XSI) d_ino están especificados en POSIX.1. Aparte de Linux, el campo d_type está disponible principalmente solo en sistemas BSD. Los campos restantes están disponibles en muchos, pero no en todos los sistemas. Bajo glibc, los programas pueden verificar la disponibilidad de los campos no definidos en POSIX.1 probando si las macros _DIRENT_HAVE_D_NAMLEN, _DIRENT_HAVE_D_RECLEN, _DIRENT_HAVE_D_OFF, o _DIRENT_HAVE_D_TYPE están definidas.

El campo d_name

La definición de la estructura dirent que se muestra arriba se toma de las cabeceras de glibc y muestra el campo d_name con un tamaño fijo.

Advertencia: las aplicaciones deben evitar cualquier dependencia del tamaño del campo d_name. POSIX lo define como char d_name[], un array de caracteres de tamaño no especificado, con como máximo NAME_MAX caracteres precediendo al byte nulo terminador ('\0').

POSIX.1 señala explícitamente que este campo no debe usarse como lvalue. El estándar también señala que el uso de sizeof(d_name) es incorrecto; use strlen(d_name) en su lugar. (En algunos sistemas, este campo se define como char d_name[1]!) Por implicación, el uso de sizeof(struct dirent) para capturar el tamaño del registro, incluyendo el tamaño de d_name, también es incorrecto.

Tenga en cuenta que mientras la llamada


fpathconf(fd, _PC_NAME_MAX)

devuelve el valor 255 para la mayoría de los sistemas de archivos, en algunos sistemas de archivos (por ejemplo, CIFS, servidores SMB de Windows), el nombre de archivo terminado en nulo que se devuelve (correctamente) en d_name puede exceder este tamaño. En tales casos, el campo d_reclen contendrá un valor que excede el tamaño de la estructura glibc dirent mostrada arriba.

ESTÁNDARES
