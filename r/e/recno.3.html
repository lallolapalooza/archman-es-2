recno(3) Manual de funciones de biblioteca recno(3)

NOMBRE

recno - método de acceso a base de datos por número de registro

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/types.h>
#include <db.h>

DESCRIPCIÓN

Tenga en cuenta: Esta página documenta las interfaces proporcionadas hasta glibc 2.1. Desde glibc 2.2, glibc ya no proporciona estas interfaces. Probablemente, esté buscando las API proporcionadas por la biblioteca libdb en su lugar.

La rutina dbopen(3) es la interfaz de biblioteca para archivos de base de datos. Uno de los formatos de archivo admitidos son los archivos de número de registro. La descripción general de los métodos de acceso a bases de datos se encuentra en dbopen(3), esta página del manual describe solo la información específica de recno.

La estructura de datos del método de acceso por número de registro son registros de longitud variable o fija almacenados en un formato de archivo plano, al que se accede mediante el número lógico de registro. La existencia del registro número cinco implica la existencia de los registros uno a cuatro, y la eliminación del registro número uno hace que el registro número cinco se renombre al registro número cuatro, así como que el cursor, si está posicionado después del registro número uno, se desplace un registro hacia abajo.

La estructura de datos específica del método de acceso recno proporcionada a dbopen(3) se define en el archivo de inclusión <db.h> de la siguiente manera:


typedef struct {
    unsigned long flags;
    unsigned int  cachesize;
    unsigned int  psize;
    int           lorder;
    size_t        reclen;
    unsigned char bval;
    char         *bfname;
} RECNOINFO;

Los elementos de esta estructura se definen de la siguiente manera:

flags
El valor del indicador se especifica combinando (OR) cualquiera de los siguientes valores:
R_FIXEDLEN
Los registros son de longitud fija, no delimitados por bytes. El elemento de la estructura reclen especifica la longitud del registro, y el elemento de la estructura bval se utiliza como carácter de relleno. Cualquier registro insertado en la base de datos que tenga menos de reclen bytes se rellena automáticamente.
R_NOKEY
En la interfaz especificada por dbopen(3), la recuperación secuencial de registros rellena las estructuras de clave y datos del llamador. Si se especifica el indicador R_NOKEY, las rutinas del cursor no están obligadas a rellenar la estructura de clave. Esto permite que las aplicaciones recuperen registros al final de los archivos sin leer todos los registros intermedios.
R_SNAPSHOT
Este indicador requiere que se tome una instantánea del archivo cuando se llama a dbopen(3), en lugar de permitir la lectura de registros no modificados del archivo original.
cachesize
Un tamaño máximo sugerido, en bytes, de la caché de memoria. Este valor es solo un consejo, y el método de acceso asignará más memoria en lugar de fallar. Si cachesize es 0 (no se especifica tamaño), se utiliza una caché predeterminada.
psize
El método de acceso recno almacena las copias en memoria de sus registros en un árbol b. Este valor es el tamaño (en bytes) de las páginas utilizadas para los nodos en ese árbol. Si psize es 0 (no se especifica tamaño de página), se elige un tamaño de página basándose en el tamaño de bloque de E/S del sistema de archivos subyacente. Consulte btree(3) para obtener más información.
lorder
El orden de bytes para los enteros en los metadatos de la base de datos almacenados. El número debe representar el orden como un entero; por ejemplo, el orden big-endian sería el número 4.321. Si lorder es 0 (no se especifica orden), se utiliza el orden del host actual.
reclen
La longitud de un registro de longitud fija.
bval
El byte delimitador que se utilizará para marcar el final de un registro para registros de longitud variable, y el carácter de relleno para registros de longitud fija. Si no se especifica ningún valor, se utilizan saltos de línea ("\n") para marcar el final de los registros de longitud variable y los registros de longitud fija se rellenan con espacios.
bfname
El método de acceso recno almacena las copias en memoria de sus registros en un árbol b. Si bfname no es NULL, especifica el nombre del archivo del árbol b, como si se especificara el nombre de archivo para un dbopen(3) de un archivo de árbol b.

La parte de datos del par clave/datos utilizado por el método de acceso recno es la misma que la de otros métodos de acceso. La clave es diferente. El campo data de la clave debe ser un puntero a una ubicación de memoria de tipo recno_t, tal como se define en el archivo de inclusión <db.h>. Este tipo es normalmente el tipo integral sin signo más grande disponible para la implementación. El campo size de la clave debe ser el tamaño de ese tipo.

Dado que no puede haber metadatos asociados con los archivos del método de acceso recno subyacente, cualquier cambio realizado en los valores predeterminados (por ejemplo, longitud de registro fija o valor separador de byte) debe especificarse explícitamente cada vez que se abre el archivo.

En la interfaz especificada por dbopen(3), el uso de la interfaz put para crear un nuevo registro provocará la creación de múltiples registros vacíos si el número de registro es más de uno mayor que el registro más grande actualmente en la base de datos.

ERRORES

Las rutinas del método de acceso recno pueden fallar y establecer errno para cualquiera de los errores especificados para la rutina de biblioteca dbopen(3) o los siguientes:

EINVAL
Se intentó añadir un registro a una base de datos de longitud fija que era demasiado grande para caber.

ERRORES DE PROGRAMACIÓN

Solo se admiten órdenes de bytes big-endian y little-endian.
