re(3perl) Guía de referencia para programadores de Perl re(3perl)

NOMBRE

re - Pragma de Perl para alterar el comportamiento de las expresiones regulares

SINOPSIS

use re 'taint';
($x) = ($^X =~ /^(.*)$/s);     # $x está contaminado aquí
$pat = '(?{ $foo = 1 })';
use re 'eval';
/foo${pat}bar/;                # no fallará (cuando no esté bajo el
                               # interruptor -T)
{
    no re 'taint';             # el predeterminado
    ($x) = ($^X =~ /^(.*)$/s); # $x no está contaminado aquí
    no re 'eval';              # el predeterminado
    /foo${pat}bar/;            # no permitido (con o sin el interruptor -T)
}
use re 'strict';               # Emitir advertencias para más condiciones
use re '/ix';
"FOO" =~ / foo /; # /ix implícito
no re '/x';
"FOO" =~ /foo/; # solo /i implícito
use re 'debug';                # mostrar información de depuración durante
/^(.*)$/s;                     # el tiempo de compilación y ejecución
use re 'debugcolor';           # lo mismo que 'debug', pero con salida
                               # coloreada
...
use re qw(Debug All);          # Lo mismo que "use re 'debug'", pero puedes
                               # usar "Debug" con cosas que no sean
                               # 'All'
use re qw(Debug More);         # 'All' más salida de detalles adicionales
no re qw(Debug ALL);           # Activar (casi) toda la depuración de re
                               # en este ámbito
use re qw(is_regexp regexp_pattern); # importar funciones utilitarias
my ($pat,$mods)=regexp_pattern(qr/foo/i);
if (is_regexp($obj)) {
    print "Obtuve expresión regular: ",
        scalar regexp_pattern($obj); # igual que perl lo convertiría
}                                    # a cadena pero sin problemas con re
                                     # bendecidos.

(Usamos $^X en estos ejemplos porque está contaminado por predeterminado.)

DESCRIPCIÓN

modo 'taint'

Cuando "use re 'taint'" está en vigor, y una cadena contaminada es el objetivo de una expresión regular, las memorias de la expresión regular (o los valores devueltos por el operador m// en contexto de lista) se contaminan. Esta característica es útil cuando las operaciones de expresión regular sobre datos contaminados no tienen como objetivo extraer subcadenas seguras, sino realizar otras transformaciones.

modo 'eval'

Cuando "use re 'eval'" está en vigor, se permite que una expresión regular contenga aserciones de ancho cero "(?{ ... })" y subexpresiones postergadas "(??{ ... })" que se derivan de la interpolación de variables, en lugar de aparecer literalmente dentro de la expresión regular. Eso normalmente no está permitido, ya que es un riesgo potencial de seguridad. Tenga en cuenta que este pragma se ignora cuando la expresión regular se obtiene de datos contaminados, es decir, la evaluación siempre está prohibida con expresiones regulares contaminadas. Consulte "(?{ code })" en perlre y "(??{ code })" en perlre.

A efectos de este pragma, la interpolación de expresiones regulares precompiladas (es decir, el resultado de "qr//") no se considera interpolación de variables. Por lo tanto:

/foo${pat}bar/

*está* permitido si $pat es una expresión regular precompilada, incluso si $pat contiene aserciones "(?{ ... })" o subexpresiones "(??{ ... })".

modo 'strict'

Tenga en cuenta que esta es una característica experimental que puede ser modificada o eliminada en una futura versión de Perl.

Cuando "use re 'strict'" está en vigor, se aplican comprobaciones más estrictas que de lo contrario al compilar patrones de expresiones regulares. Estas pueden causar que se emitan más advertencias que de lo contrario, y que más cosas sean fatales en lugar de solo advertencias. El propósito de esto es encontrar e informar en tiempo de compilación algunas cosas que, si bien pueden ser legales, tienen una posibilidad razonable de no ser la intención real del programador. Esto activa automáticamente la categoría de advertencia "regexp" (si no está ya activada) dentro de su ámbito.

Como ejemplo de algo que se detecta bajo 'strict', pero no de otra manera, es el patrón

qr/\xABC/

La construcción "\x" sin llaves debe ir seguida de exactamente dos dígitos hexadecimales; esta está seguida de tres. Actualmente se evalúa como equivalente a

qr/\x{AB}C/

es decir, el carácter cuyo valor de punto de código es 0xAB, seguido de la letra "C". Pero como "C" es un dígito hexadecimal, existe una posibilidad razonable de que la intención fuera

qr/\x{ABC}/

es decir, el único carácter en 0xABC. Bajo 'strict' es un error no seguir "\x" con exactamente dos dígitos hexadecimales. Cuando no está bajo 'strict' se emite una advertencia si solo hay un dígito hexadecimal, y no se emite ninguna advertencia si hay más de dos.

Se espera que lo que hace exactamente 'strict' evolucione con el tiempo a medida que ganemos experiencia con él. Esto significa que los programas que compilan bajo él en el Perl actual pueden no compilar, o pueden tener más o menos advertencias, en futuros Perls. No hay promesas de retrocompatibilidad con respecto a él. Además, ya existen propuestas para una sintaxis alternativa para activarlo. Por estas razones, su uso emitirá una advertencia de clase "experimental::re_strict", a menos que esa categoría esté desactivada.

Tenga en cuenta que si un patrón compilado dentro de 'strict' se recompila, por ejemplo, interpolándolo en otro patrón, fuera de 'strict', no se vuelve a comprobar su estrictez. Esto se debe a que si funciona bajo estrictez, debe funcionar bajo no estrictez.

modo '/flags'

Cuando se especifica "use re '/flags'a', 'aa', 'd', 'i', 'l', 'm', 'n', 'p', 's', 'u', 'x', y/o 'xx'.

"no re '/flags"use re '/flagsPor ejemplo, si desea que todas sus expresiones regulares tengan /msxx de forma predeterminada, simplemente ponga

use re '/msxx';

al principio de su código.

El conjunto de caracteres "/adul" los flags se cancelan mutuamente. Por lo tanto, en este ejemplo,

use re "/u";
"ss" =~ /\xdf/;
use re "/d";
"ss" =~ /\xdf/;

el segundo "use re" realiza un "no re '/u'" implícito.

De manera similar,

use re "/xx";   # Doble-x
...
use re "/x";    # X simple de aquí en adelante
...

Activar uno de los flags del conjunto de caracteres con "use re" tiene prioridad sobre el pragma "locale" y la característica "unicode_strings", para las expresiones regulares. Desactivar uno de estos flags cuando está activo revierte al comportamiento especificado por cualquier otro pragma que esté en el ámbito. Por ejemplo:

use feature "unicode_strings";
no re "/u"; # no hace nada
use re "/l";
no re "/l"; # revierte al comportamiento de unicode_strings

Los flags predeterminados se aplican a donde sea que se compile un patrón, con la excepción del flag "/x", que no se aplica a los patrones compilados a partir de argumentos de cadena para "split". Por lo tanto, `use re "/x";` no afecta el comportamiento de "split " "", pero *sí* afecta el comportamiento de "split / /".

modo 'debug'

Cuando "use re 'debug'" está en vigor, perl emite mensajes de depuración al compilar y usar expresiones regulares. La salida es la misma que la obtenida al ejecutar un ejecutable compilado con la opción "-DDEBUGGING".

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

intérprete de perl con el conmutador -Dr. Puede ser bastante voluminoso dependiendo de la complejidad de la coincidencia. Usar "debugcolor" en lugar de "debug" habilita una forma de salida que se puede utilizar para obtener una pantalla colorida en terminales que entienden las secuencias de color termcap. Establezca $ENV{PERL_RE_TC} a una lista separada por comas de propiedades de "termcap" para usar en el resaltado de cadenas encendido/apagado, parte pre-punto encendido/apagado. Consulte "Depuración de expresiones regulares" en perldebug para obtener información adicional.

NOTA que el formato exacto del modo "debug" NO se considera una API oficialmente compatible de Perl. Está destinado solo para depuración y puede cambiar según lo considere apropiado el equipo de desarrollo principal sin previo aviso o desaprobación en ninguna versión de Perl, mayor o menor. Cualquier documentación de la salida es puramente consultiva.

A partir de la versión 5.9.5, la directiva "use re 'debug'" y sus equivalentes están limitadas lexicalmente, al igual que las otras directivas. Sin embargo, tienen efectos tanto en tiempo de compilación como en tiempo de ejecución.

Consulte "Módulos Pragmáticos" en perlmodlib.

'Modo Debug'

De manera similar, "use re 'Debug'" produce una salida de depuración, la diferencia es que permite el ajuste fino de qué salida de depuración se emitirá. Las opciones se dividen en tres grupos: las relacionadas con la compilación, las relacionadas con la ejecución y las relacionadas con propósitos especiales.

NOTA que las opciones proporcionadas bajo el modo "Debug" y el formato exacto de la salida que crean NO se consideran una API oficialmente compatible de Perl. Está destinado solo para depuración y puede cambiar según lo considere apropiado el equipo de desarrollo principal sin previo aviso o desaprobación en ninguna versión de Perl, mayor o menor. Cualquier documentación del formato u opciones disponibles es solo consultiva y está sujeta a cambios sin previo aviso.

Las opciones son las siguientes:

Opciones relacionadas con la compilación
COMPILE
Activa todas las opciones de depuración no extra relacionadas con la compilación.
PARSE
Activa la salida de depuración relacionada con el proceso de análisis del patrón.
OPTIMISE
Habilita la salida relacionada con la fase de optimización de la compilación.
TRIEC
Información detallada sobre la compilación de trie.
DUMP
Volca el programa final después de que se compila y optimiza.
FLAGS
Volca las banderas asociadas con el programa
TEST
Imprime la salida destinada a probar los internos del proceso de compilación
Opciones relacionadas con la ejecución
EXECUTE
Activa todas las opciones de depuración no extra relacionadas con la ejecución.
MATCH
Activa la depuración del bucle principal de coincidencia.
TRIEE
Depuración adicional de cómo se ejecutan los tries.
INTUIT
Habilita la depuración de las optimizaciones del punto de inicio.
Opciones de depuración adicionales
EXTRA
Activa todas las opciones de depuración "adicionales".
BUFFERS
Habilita la depuración del almacenamiento de grupos de captura durante la coincidencia. Advertencia, esto puede producir una salida extremadamente grande.
TRIEM
Habilita la depuración mejorada de TRIE. Mejora tanto TRIEE como TRIEC.
STATE
Habilita la depuración de estados en el motor.
STACK
Habilita la depuración de la pila de recursión en el motor. Habilitar o deshabilitar esta opción hace automáticamente lo mismo para la depuración de estados. La salida de esto puede ser bastante grande.
GPOS
Habilita la depuración del modificador \G.
OPTIMISEM
Habilita la depuración optimizada mejorada y las optimizaciones del punto de inicio. Probablemente no sea útil excepto al depurar el propio motor regexp.
DUMP_PRE_OPTIMIZE
Habilita el volcado del patrón compilado antes de la fase de optimización.
WILDCARD
Cuando Perl encuentra un subpatrón comodín (ver "Comodines en valores de propiedad" en perlunicode), suspende la compilación del patrón principal, compila el subpatrón y luego lo compara con todas las posibilidades legales para determinar los puntos de código reales que coincide el subpatrón. Después de eso, los agrega al patrón principal y continúa su compilación.

Es muy probable que desees ver cómo se compila tu subpatrón, pero es probable que tenga menos utilidad para ti ver cómo Perl lo compara con todas las posibilidades legales, ya que eso está bajo el control de Perl, no tuyo. Por lo tanto, la información de depuración de la parte de compilación es la especificada por las otras opciones, pero la salida de depuración de la parte de coincidencia normalmente se suprime.

Puedes usar la opción WILDCARD para habilitar la salida de depuración de esta coincidencia de subpatrón. ¡Cuidado! Esto puede generar salidas voluminosas, y puede que no tenga mucho sentido para ti qué está haciendo Perl y por qué. Pero puede ser útil para ti ver por qué las cosas no salen como esperas.

Ten en cuenta que esta opción por sí sola no causa que se genere ninguna información de depuración. Lo que hace es detener la supresión normal de la información de depuración relacionada con la ejecución durante la parte de coincidencia de la compilación de comodines. También debes especificar qué información de depuración de ejecución deseas, por ejemplo, incluyendo también la opción EXECUTE.

Otros indicadores útiles
Estos son atajos útiles para ahorrar escritura.
ALL
Activa todas las opciones a la vez, excepto BUFFERS, WILDCARD y DUMP_PRE_OPTIMIZE. (Para obtener todas las opciones sin excepción, usa tanto ALL como EXTRA, o a partir de la versión 5.30 en un intérprete de perl habilitado para "-DDEBUGGING", usa los conmutadores de línea de comandos -Drv).
All
Activa DUMP y todas las opciones no extra de ejecución. Equivalente a: 
use re 'debug';
MORE
More
Activa las opciones habilitadas por "All", además de STATE, TRIEC y TRIEM.

A partir de la versión 5.9.5, la directiva "use re 'debug'" y sus equivalentes están limitadas lexicalmente, al igual que las otras directivas. Sin embargo, tienen efectos tanto en tiempo de compilación como en tiempo de ejecución.

Funciones Exportables

A partir de perl 5.9.5, el módulo "re" contiene una serie de funciones de utilidad que pueden exportarse opcionalmente al espacio de nombres del llamador. Se enumeran a continuación.

is_regexp($ref)
Devuelve verdadero si el argumento es una expresión regular compilada, tal como la devuelve "qr//", falso si no lo es.

Esta función no se confundirá por sobrecarga o bendición. En términos internos, extrae el puntero regexp de la estructura PERL_MAGIC_qr para que no pueda ser engañada.

regexp_pattern($ref)
Si el argumento es una expresión regular compilada tal como la devuelve "qr//", entonces esta función devuelve el patrón.

En contexto de lista, devuelve una lista de dos elementos, el primer elemento contiene el patrón y el segundo contiene los modificadores utilizados cuando se compiló el patrón.

my ($pat, $mods) = regexp_pattern($ref);

En contexto escalar, devuelve lo mismo que perl devolvería al convertir una referencia "qr//" cruda con el mismo patrón dentro a una cadena. Si el argumento no es una referencia compilada, entonces esta rutina devuelve falso pero definido en contexto escalar, y la lista vacía en contexto de lista. Por lo tanto, lo siguiente

if (regexp_pattern($ref) eq '(?^i:foo)')

no generará advertencias independientemente de lo que sea realmente $ref.

Al igual que "is_regexp", esta función no se confundirá por la sobrecarga o bendición del objeto.

regname($name,$all)
Devuelve el contenido de un búfer con nombre de la última coincidencia exitosa. Si $all es verdadero, devuelve una referencia de matriz que contiene una entrada por búfer, de lo contrario, devuelve el primer búfer definido.
regnames($all)
Devuelve una lista de todos los búferes con nombre definidos en la última coincidencia exitosa. Si $all es verdadero, devuelve todos los nombres definidos; si no, devuelve solo los nombres que estuvieron involucrados en la coincidencia.
regnames_count()
Devuelve el número de nombres distintos definidos en el patrón utilizado para la última coincidencia exitosa.

Nota: este resultado es siempre el número real de búferes con nombre distintos definidos; puede que no coincida con lo que devuelven las rutinas regnames() y relacionadas cuando esas rutinas no se han llamado con el $al

re.3perl man page

NAME

Regexp::Optimizer - Regular expression optimization routines

SYNOPSIS

use Regexp::Optimizer qw(regmust optimization);
my $qr = qr/foo\s+bar/;
my ($anchored, $floating) = regmust($qr);
my $opt_info = optimization($qr);

DESCRIPTION

This module provides access to the internal regular expression optimizer routines that Perl uses. These are used to speed up regular expression matching by determining what fixed strings or character classes must be present in any string that matches the pattern. The information is also used to determine if a pattern can be optimised into a simple string comparison.

The functions provided are:

regmust($ref)
Si el argumento es una expresión regular compilada como la devuelta por "qr//", esta función devuelve lo que el optimizador considera que es la cadena fija anclada más larga y la cadena fija flotante más larga en el patrón.

Una cadena fija se define como una subcadena que debe aparecer para que el patrón coincida. Una cadena fija anclada es una cadena fija que debe aparecer en un desplazamiento particular desde el principio de la coincidencia. Una cadena fija flotante se define como una cadena fija que puede aparecer en cualquier punto dentro de un rango de posiciones relativas al inicio de la coincidencia. Por ejemplo,

my $qr = qr/here .* there/x;
my ($anchored, $floating) = regmust($qr);
print "anchored:'$anchored'\nfloating:'$floating'\n";

resulta en

anchored:'here'
floating:'there'

Dado que "here" está antes de ".*" en el patrón, su posición se puede determinar exactamente. Sin embargo, eso no es cierto para "there"; podría aparecer en cualquier punto después de donde apareció la cadena anclada. Perl usa ambas para sus optimizaciones, prefiriendo la más larga o, si son iguales, la flotante.

NOTA: Esta puede que no sea necesariamente la cadena anclada y flotante definitiva más larga. Será lo que el optimizador del Perl que estés usando considere como el más largo. Si crees que el resultado es incorrecto, repórtalo a través de la utilidad perlbug.

optimization($ref)
Si el argumento es una expresión regular compilada como la devuelta por "qr//", esta función devuelve un hashref con la información de optimización descubierta en tiempo de compilación, para que podamos escribir pruebas sobre ella. Si se da cualquier otro argumento, devuelve "undef".

Se espera que el contenido del hash cambie de vez en cuando a medida que desarrollamos nuevas formas de optimizar; no se debe asumir estabilidad, ni siquiera entre versiones menores de perl.

Para la versión actual, el hash tendrá los siguientes contenidos:

minlen
Un entero, el número mínimo de caracteres en cualquier cadena que pueda coincidir.
minlenret
Un entero, el número mínimo de caracteres que puede haber en $& después de una coincidencia. (Considerar, por ejemplo, " /ns(?=\d)/ ".)
gofs
Un entero, el número de caracteres antes de pos() para iniciar la coincidencia.
noscan
Un booleano, "TRUE" para indicar que las subcadenas ancladas/flotantes encontradas no deben usarse. (CHECKME: aparentemente esto se establece para un patrón anclado sin subcadena flotante, pero nunca se usa.)
isall
Un booleano, "TRUE" para indicar que la información del optimizador es todo lo que contiene la expresión regular, y por lo tanto, no es necesario entrar en el motor de ejecución de expresiones regulares en absoluto.
anchor SBOL
Un booleano, "TRUE" si el patrón está anclado al inicio de la cadena.
anchor MBOL
Un booleano, "TRUE" si el patrón está anclado a cualquier inicio de línea dentro de la cadena.
anchor GPOS
Un booleano, "TRUE" si el patrón está anclado al final de la coincidencia anterior.
skip
Un booleano, "TRUE" si la clase de inicio puede coincidir solo con el primero de una secuencia.
implicit
Un booleano, "TRUE" si un "/.*/" se ha convertido implícitamente en un "/^.*/".
anchored/floating
Una cadena de bytes que representa una subcadena anclada o flotante respectivamente, que cualquier coincidencia debe contener, o undef si no se encontró tal subcadena, o si la subcadena requeriría utf8 para representarse.
anchored utf8/floating utf8
Una cadena utf8 que representa una subcadena anclada o flotante respectivamente, que cualquier coincidencia debe contener, o undef si no se encontró tal subcadena, o si la subcadena contiene solo caracteres ASCII de 7 bits.
anchored min offset/floating min offset
Un entero, el primer desplazamiento en caracteres desde una ubicación de coincidencia en la que se debe buscar la subcadena correspondiente.
anchored max offset/floating max offset
Un entero, el último desplazamiento en caracteres desde una ubicación de coincidencia en la que se debe buscar la subcadena correspondiente.

Ignorado para la cadena anclada, por lo que puede ser 0 o igual que min.
