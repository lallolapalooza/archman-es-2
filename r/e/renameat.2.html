rename(2) Manual de llamadas al sistema rename(2)

NOMBRE

rename, renameat, renameat2 - cambiar el nombre o la ubicación de un archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <stdio.h>
int rename(const char *oldpath, const char *newpath);
#include <fcntl.h>           /* Definición de las constantes AT_* */
#include <stdio.h>
int renameat(int olddirfd, const char *oldpath,
             int newdirfd, const char *newpath);
int renameat2(int olddirfd, const char *oldpath,
             int newdirfd, const char *newpath, unsigned int flags);

DESCRIPCIÓN

rename() renombra un archivo, moviéndolo entre directorios si es necesario. Otros enlaces duros al archivo (como los creados usando link(2)) no se ven afectados. Los descriptores de archivo abiertos para oldpath tampoco se ven afectados.

Varias restricciones determinan si la operación de renombrado tiene éxito o no: ver ERRORES más abajo.

Si newpath ya existe, será reemplazado atómicamente, de modo que no habrá ningún punto en el que otro proceso que intente acceder a newpath lo encuentre ausente. Sin embargo, probablemente habrá una ventana en la que tanto oldpath como newpath se refieran al archivo que se está renombrando.

Si oldpath y newpath son enlaces duros existentes que se refieren al mismo archivo, entonces rename() no hace nada y devuelve un estado de éxito.

Si newpath existe pero la operación falla por alguna razón, rename() garantiza dejar una instancia de newpath en su lugar.

oldpath puede especificar un directorio. En este caso, newpath debe o bien no existir, o bien especificar un directorio vacío.

Si oldpath se refiere a un enlace simbólico, el enlace se renombra; si newpath se refiere a un enlace simbólico, el enlace será sobrescrito.

renameat()

La llamada al sistema renameat() opera de manera exactamente igual que rename(), excepto por las diferencias descritas aquí.

Si la ruta de archivo dada en oldpath es relativa, entonces se interpreta en relación con el directorio al que se refiere el descriptor de archivo olddirfd (en lugar de en relación con el directorio de trabajo actual del proceso que llama, como se hace con rename() para una ruta relativa).

Si oldpath es relativo y olddirfd es el valor especial AT_FDCWD, entonces oldpath se interpreta en relación con el directorio de trabajo actual del proceso que llama (como rename()).

Si oldpath es absoluto, entonces olddirfd se ignora.

La interpretación de newpath es como la de oldpath, excepto que una ruta relativa se interpreta en relación con el directorio al que se refiere el descriptor de archivo newdirfd.

Ver openat(2) para una explicación de la necesidad de renameat().

renameat2()

renameat2() tiene un argumento adicional flags. Una llamada a renameat2() con un argumento flags cero es equivalente a renameat().

El argumento flags es una máscara de bits que consiste en cero o más de las siguientes banderas:

RENAME_EXCHANGE
Intercambia atómicamente oldpath y newpath. Ambas rutas deben existir pero pueden ser de tipos diferentes (por ejemplo, una podría ser un directorio no vacío y la otra un enlace simbólico).
RENAME_NOREPLACE
No sobrescribir newpath del renombrado. Devolver un error si newpath ya existe.
RENAME_NOREPLACE no se puede emplear junto con RENAME_EXCHANGE.
RENAME_NOREPLACE requiere soporte del sistema de archivos subyacente. El soporte para varios sistemas de archivos se añadió de la siguiente manera:
•
ext4 (Linux 3.15);
•
btrfs, tmpfs y cifs (Linux 3.17);
•
xfs (Linux 4.0);
•
Se añadió soporte para muchos otros sistemas de archivos en Linux 4.9, incluyendo ext2, minix, reiserfs, jfs, vfat y bpf.
RENAME_WHITEOUT (desde Linux 3.18)
Esta operación solo tiene sentido para implementaciones de sistemas de archivos overlay/union.
Especificar RENAME_WHITEOUT crea un objeto "whiteout" en la fuente del renombrado al mismo tiempo que se realiza el renombrado. Toda la operación es atómica, de modo que si el renombrado tiene éxito, el whiteout también se habrá creado.
Un "whiteout" es un objeto que tiene un significado especial en las construcciones de sistemas de archivos union/overlay. En estas construcciones, existen múltiples capas y solo la superior se modifica siempre. Un whiteout en una capa superior ocultará eficazmente un archivo coincidente en la capa inferior, haciendo que parezca que el archivo no existía.
Cuando se renombra un archivo que existe en la capa inferior, el archivo se copia primero (si no está ya en la capa superior) y luego se renombra en la capa superior de lectura/escritura. Al mismo tiempo, la fuente debe ser "whiteouted" (para que la versión del archivo fuente en la capa inferior se vuelva invisible). Toda la operación debe realizarse de forma atómica.
Cuando no forma parte de una union/overlay, el whiteout aparece como un dispositivo de caracteres con un número de dispositivo {0,0}. (Tenga en cuenta que otras implementaciones de union/overlay pueden emplear diferentes métodos para almacenar entradas de whiteout; específicamente, las monturas union de BSD emplean un tipo de inode separado, DT_WHT, que, aunque soportado por algunos sistemas de archivos disponibles en Linux, como CODA y XFS, es ignorado por el código de soporte de whiteout del kernel, a partir de Linux 4.19, al menos).
RENAME_WHITEOUT requiere los mismos privilegios que la creación de un nodo de dispositivo (es decir, la capacidad CAP_MKNOD).
RENAME_WHITEOUT no se puede emplear junto con RENAME_EXCHANGE.
RENAME_WHITEOUT requiere soporte del sistema de archivos subyacente. Entre los sistemas de archivos que lo soportan se incluyen tmpfs (desde Linux 3.18), ext4 (desde Linux 3.18), XFS (desde Linux 4.1), f2fs (desde Linux 4.2), btrfs (desde Linux 4.7) y ubifs (desde Linux 4.9).

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EACCES
Se deniega el permiso de escritura en el directorio que contiene oldpath o newpath, o se deniega el permiso de búsqueda en uno de los directorios en el prefijo de ruta de oldpath o newpath, o oldpath es un directorio y no permite el permiso de escritura (necesario para actualizar la entrada ..). (Ver también path_resolution(7)).
EBUSY
El renombrado falla porque oldpath o newpath es un directorio que está en uso por algún proceso (quizás como directorio actual, o como directorio raíz, o porque estaba abierto para lectura) o está en uso por el sistema (por ejemplo, como punto de montaje), mientras que el sistema considera esto un error. (Tenga en cuenta que no hay requisito de devolver EBUSY en tales casos — no hay nada de malo en hacer el renombrado de todos modos — pero está permitido devolver EBUSY si el sistema no puede manejar tales situaciones de otra manera).
EDQUOT
La cuota de disco para el usuario propietario del archivo ha expirado, o no hay espacio libre en el dispositivo para crear el nuevo nombre de archivo o para crear el directorio blanco (whiteout) (si se usa RENAME_WHITEOUT).
EEXIST
newpath existe y se especificó RENAME_NOREPLACE.
EFBIG
El tamaño del archivo excede el límite permitido para un archivo en el sistema de archivos de destino.
EINVAL
Se especificó un valor inválido en flags en una llamada a renameat2().
EINTR
La operación fue interrumpida por una señal.
EISDIR
oldpath es un directorio, pero newpath no lo es.
ELOOP
Se encontraron demasiados enlaces simbólicos en la traducción de una ruta.
EMLINK
Ya existe el número máximo de enlaces duros para el archivo de destino (en el caso de que newpath exista y sea un archivo o enlace simbólico, y oldpath también exista y sea un archivo o enlace simbólico, y ambos apunten al mismo inode). O el sistema de archivos de destino no puede crear enlaces duros. Ver también link(2).
EMULTIHOP
Se encontró un componente de ruta en oldpath o newpath que apunta a un directorio en una red de archivos de múltiples saltos, y la bandera follow_links no está activada.
ENAMETOOLONG
Un componente de la ruta es más largo que el permitido por el sistema operativo, o la longitud total de la ruta es más larga que el permitido. (Ver también path_resolution(7).)
ENOENT
Un componente de la ruta oldpath o newpath no existe, o oldpath es una ruta vacía.
ENOSPC
No hay espacio libre en el dispositivo de almacenamiento para completar la operación. (Esto incluye el caso de que newpath exista y sea un directorio, pero no se puede crear el enlace blanco (whiteout) si se especifica RENAME_WHITEOUT).
ENOTDIR
Un componente de la ruta oldpath o newpath no es un directorio, cuando se esperaba que lo fuera. O oldpath es un directorio, pero newpath ya existe y no es un directorio.
ENOTEMPTY
oldpath es un directorio que no está vacío, pero newpath ya existe y también es un directorio. Esto se aplica solo si se intentó renombrar un directorio existente a un nuevo nombre, y el nuevo nombre ya existía y también era un directorio.
EROFS
El archivo está en un sistema de archivos de solo lectura y se intentó modificarlo.
EXDEV
Se intentó renombrar un archivo a un directorio diferente en el mismo sistema de archivos, pero los dos directorios se encuentran en sistemas de archivos diferentes. (La operación de renombrado también falla con EXDEV si oldpath y newpath son enlaces duros y se refieren a inodes diferentes en diferentes sistemas de archivos).

También pueden producirse otros errores según el sistema de archivos subyacente.

ERRORES DE FLAGS DE RENAMEAT2

EINVAL
Se especificó un valor inválido en flags en una llamada a renameat2().
EPERM
Se especificó RENAME_WHITEOUT pero el proceso no tiene la capacidad CAP_MKNOD.
EXDEV
Se especificó RENAME_EXCHANGE, pero oldpath y newpath se encuentran en sistemas de archivos diferentes.

ERRORS

EACCES
Write access to the directory of either oldpath or newpath is not permitted; or, a component of either path is not a directory, or search permission is denied for a component of the path prefix of oldpath or newpath. Or, the directory containing oldpath has the sticky bit (S_ISVTX) set and the process's effective user ID is neither the user ID of the file to be deleted nor that of the directory containing it, and the process is not privileged (Linux: does not have the CAP_FOWNER capability); or newpath is an existing file and the directory containing it has the sticky bit set and the process's effective user ID is neither the user ID of the file to be replaced nor that of the directory containing it, and the process is not privileged (Linux: does not have the CAP_FOWNER capability).
EBADF
A file descriptor used for oldpath or newpath in `renameat` or `renameat2` is not valid, or is not a directory.
EBUSY
A component of an attempt to rename a directory was busy.
EDQUOT
The user's quota of disk blocks on the filesystem has been exhausted.
EFAULT
oldpath or newpath points outside your accessible address space.
EINVAL
The new pathname contained a path prefix of the old, or, more generally, an attempt was made to make a directory a subdirectory of itself.
EISDIR
newpath is an existing directory, but oldpath is not a directory.
ELOOP
Too many symbolic links were encountered in resolving oldpath or newpath.
EMLINK
oldpath already has the maximum number of links to it, or it was a directory and the directory containing newpath has the maximum number of links.
ENAMETOOLONG
oldpath or newpath was too long.
ENOENT
The link named by oldpath does not exist; or, a directory component in newpath does not exist; or, oldpath or newpath is an empty string.
ENOMEM
Insufficient kernel memory was available.
ENOSPC
The device containing the file has no room for the new directory entry.
ENOTDIR
A component used as a directory in oldpath or newpath is not, in fact, a directory. Or, oldpath is a directory, and newpath exists but is not a directory.
ENOTEMPTY or EEXIST
newpath is a nonempty directory, that is, contains entries other than "." and "..".
EPERM or EACCES
The directory containing oldpath has the sticky bit (S_ISVTX) set and the process's effective user ID is neither the user ID of the file to be deleted nor that of the directory containing it, and the process is not privileged (Linux: does not have the CAP_FOWNER capability); or newpath is an existing file and the directory containing it has the sticky bit set and the process's effective user ID is neither the user ID of the file to be replaced nor that of the directory containing it, and the process is not privileged (Linux: does not have the CAP_FOWNER capability); or the filesystem containing oldpath does not support renaming of the type requested.
EROFS
The file is on a read-only filesystem.
EXDEV
oldpath and newpath are not on the same mounted filesystem. (Linux permits a filesystem to be mounted at multiple points, but rename() does not work across different mount points, even if the same filesystem is mounted on both.)

The following additional errors can occur for renameat() and renameat2():

EBADF
oldpath (newpath) is relative but olddirfd (newdirfd) is not a valid file descriptor.
ENOTDIR
oldpath is relative and olddirfd is a file descriptor referring to a file other than a directory; or similar for newpath and newdirfd

The following additional errors can occur for renameat2():

EEXIST
flags contains RENAME_NOREPLACE and newpath already exists.
EINVAL
An invalid flag was specified in flags.
EINVAL
Both RENAME_NOREPLACE and RENAME_EXCHANGE were specified in flags.
EINVAL
Both RENAME_WHITEOUT and RENAME_EXCHANGE were specified in flags.
EINVAL
The filesystem does not support one of the flags in flags.
ENOENT
flags contains RENAME_EXCHANGE and newpath does not exist.
EPERM
RENAME_WHITEOUT was specified in flags, but the caller does not have the CAP_MKNOD capability.

glibc notes

On older kernels where renameat() is unavailable, the glibc wrapper function falls back to the use of rename(). When oldpath and newpath are relative pathnames, glibc constructs pathnames based on the symbolic links in /proc/self/fd that correspond to the olddirfd and newdirfd arguments.

BUGS

On NFS filesystems, you can not assume that if the operation failed, the file was not renamed. If the server does the rename operation and then crashes, the retransmitted RPC which will be processed when the server is up again causes a failure. The application is expected to deal with this. See link(2) for a similar problem.
