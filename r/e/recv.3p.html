RECV(3P) Manual del Programador POSIX RECV(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

recv — recibir un mensaje de un socket conectado

SINOPSIS

#include <sys/socket.h>
ssize_t recv(int socket, void *buffer, size_t length, int flags);

DESCRIPCIÓN

La función recv() recibe un mensaje de un socket de modo conectado o de modo sin conexión. Normalmente se utiliza con sockets conectados porque no permite a la aplicación recuperar la dirección de origen de los datos recibidos.

La función recv() toma los siguientes argumentos:

socket
Especifica el descriptor de archivo del socket.
buffer
Punta a un búfer donde se debe almacenar el mensaje.
length
Especifica la longitud en bytes del búfer al que apunta el argumento buffer.
flags
Especifica el tipo de recepción del mensaje. Los valores de este argumento se forman combinando lógicamente cero o más de los siguientes valores:
MSG_PEEK
Echa un vistazo a un mensaje entrante. Los datos se tratan como no leídos y la siguiente función recv() o similar seguirá devolviendo estos datos.
MSG_OOB
Solicita datos fuera de banda (out-of-band). La significación y semántica de los datos fuera de banda son específicas del protocolo.
MSG_WAITALL
En sockets SOCK_STREAM, esto solicita que la función se bloquee hasta que se pueda devolver la cantidad total de datos. La función puede devolver una cantidad menor de datos si el socket es un socket basado en mensajes, si se captura una señal, si la conexión se termina, si se especificó MSG_PEEK o si hay un error pendiente para el socket.

La función recv() devolverá la longitud del mensaje escrito en el búfer al que apunta el argumento buffer. Para sockets basados en mensajes, como SOCK_DGRAM y SOCK_SEQPACKET, el mensaje completo se leerá en una sola operación. Si un mensaje es demasiado largo para caber en el búfer suministrado y MSG_PEEK no está establecido en el argumento flags, los bytes en exceso se descartarán. Para sockets basados en streams, como SOCK_STREAM, los límites de los mensajes se ignorarán. En este caso, los datos se devolverán al usuario tan pronto como estén disponibles y no se descartarán datos.

Si el flag MSG_WAITALL no está establecido, los datos se devolverán solo hasta el final del primer mensaje.

Si no hay mensajes disponibles en el socket y O_NONBLOCK no está establecido en el descriptor de archivo del socket, recv() se bloqueará hasta que llegue un mensaje. Si no hay mensajes disponibles en el socket y O_NONBLOCK está establecido en el descriptor de archivo del socket, recv() fallará y establecerá errno en [EAGAIN] o [EWOULDBLOCK].

VALOR DE RETORNO

Tras completarse con éxito, recv() devolverá la longitud del mensaje en bytes. Si no hay mensajes disponibles para recibir y el par ha realizado un cierre ordenado, recv() devolverá 0. De lo contrario, se devolverá -1 y se establecerá errno para indicar el error.

ERRORES

La función recv() fallará si:

EAGAIN o EWOULDBLOCK

El descriptor de archivo del socket está marcado como O_NONBLOCK y no hay datos esperando ser recibidos; o MSG_OOB está establecido y no hay datos fuera de banda disponibles y o el descriptor de archivo del socket está marcado como O_NONBLOCK o el socket no admite el bloqueo para esperar datos fuera de banda.
EBADF
El argumento socket no es un descriptor de archivo válido.
ECONNRESET
Una conexión fue cerrada forzosamente por un par.
EINTR
La función recv() fue interrumpida por una señal que fue capturada, antes de que estuvieran disponibles los datos.
EINVAL
El flag MSG_OOB está establecido y no hay datos fuera de banda disponibles.
ENOTCONN
Se intenta una recepción en un socket de modo conectado que no está conectado.
ENOTSOCK
El argumento socket no se refiere a un socket.
EOPNOTSUPP
Los flags especificados no son compatibles con este tipo de socket o protocolo.
ETIMEDOUT
La conexión expiró durante el establecimiento de la conexión, o debido a un tiempo de espera de transmisión en una conexión activa.

La función recv() puede fallar si:

EIO
Ocurrió un error de E/S al leer o escribir en el sistema de archivos.
ENOBUFS
No había suficientes recursos disponibles en el sistema para realizar la operación.
ENOMEM
No había suficiente memoria disponible para satisfacer la solicitud.

USO DE APLICACIÓN

La función recv() es equivalente a recvfrom() con los argumentos address y address_len como punteros nulos, y a read() si el argumento socket se refiere a un socket y el argumento flags es 0.

Las funciones select() y poll() se pueden utilizar para determinar cuándo hay datos disponibles para ser recibidos.
