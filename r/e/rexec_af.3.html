rexec(3) Manual de funciones de biblioteca rexec(3)

NOMBRE

rexec, rexec_af - devolver un flujo a un comando remoto

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <netdb.h>
[[deprecated]]
int rexec(char **restrict ahost, int inport,
          const char *restrict user, const char *restrict passwd,
          const char *restrict cmd, int *restrict fd2p);
[[deprecated]]
int rexec_af(char **restrict ahost, int inport,
          const char *restrict user, const char *restrict passwd,
          const char *restrict cmd, int *restrict fd2p,
          sa_family_t af);

rexec(), rexec_af():

    Desde glibc 2.19:
        _DEFAULT_SOURCE
    En glibc hasta e incluyendo 2.19:
        _BSD_SOURCE

DESCRIPCIÓN

Esta interfaz está obsoleta por rcmd(3).

La función rexec() busca el host *ahost usando gethostbyname(3), devolviendo -1 si el host no existe. De lo contrario, *ahost se establece en el nombre estándar del host. Si se especifican tanto el nombre de usuario como la contraseña, se utilizan para autenticarse en el host remoto; de lo contrario, se busca en el entorno y luego en el archivo .netrc en el directorio principal del usuario información apropiada. Si todo esto falla, se le pide al usuario la información.

El puerto inport especifica qué puerto bien conocido de DARPA Internet se utilizará para la conexión; la llamada getservbyname("exec", "tcp") (ver getservent(3)) devolverá un puntero a una estructura que contiene el puerto necesario. El protocolo de conexión se describe en detalle en rexecd(8).

Si la conexión tiene éxito, se devuelve un socket en el dominio de Internet de tipo SOCK_STREAM al llamador, y se proporciona al comando remoto como stdin y stdout. Si fd2p no es cero, se establecerá un canal auxiliar a un proceso de control, y se colocará un descriptor de archivo para él en *fd2p. El proceso de control devolverá la salida de diagnóstico del comando (unidad 2) en este canal, y también aceptará bytes en este canal como números de señal UNIX, que se reenviarán al grupo de procesos del comando. La información de diagnóstico devuelta no incluye errores de autorización remota, ya que la conexión secundaria se establece después de que se haya verificado la autorización. Si fd2p es 0, entonces el stderr (unidad 2 del comando remoto) se hará igual que el stdout y no se harán disposiciones para enviar señales arbitrarias al proceso remoto, aunque puede que pueda llamar su atención utilizando datos fuera de banda.

rexec_af()

La función rexec() funciona sobre IPv4 (AF_INET). Por el contrario, la función rexec_af() proporciona un argumento adicional, af, que permite al llamador seleccionar el protocolo. Este argumento puede especificarse como AF_INET, AF_INET6 o AF_UNSPEC (para permitir que la implementación seleccione el protocolo).

ESTÁNDARES

HISTORIA

rexec()
4.2BSD, BSD, Solaris.
rexec_af()
glibc 2.2.

ERRORES

La función rexec() envía la contraseña sin cifrar a través de la red.

El servicio subyacente se considera un gran agujero de seguridad, y por lo tanto, no está habilitado en muchos sitios; ver rexecd(8) para explicaciones.

VER TAMBIÉN
