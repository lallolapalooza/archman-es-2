REMAKE(1) Comandos de usuario REMAKE(1)

NOMBRE

remake - utilidad GNU make para mantener grupos de programas

SINOPSIS

remake [OPCIÓN]... [OBJETIVO]...

DESCRIPCIÓN

remake determinará automáticamente qué piezas de un programa grande necesitan ser recompiladas, y emitirá los comandos para recompilarlas. El manual describe la implementación GNU de make de la cual se deriva remake, que fue escrita por Richard Stallman y Roland McGrath, y actualmente es mantenida por Paul Smith. Las extensiones de reporte de errores, depurador y perfilado fueron escritas por Rocky Bernstein. Nuestros ejemplos muestran programas en C, ya que son muy comunes, pero puedes usar remake con cualquier lenguaje de programación cuyo compilador pueda ser ejecutado con un comando de shell. De hecho, remake o make no se limitan a programas. Puedes usarlo para describir cualquier tarea donde algunos archivos deban actualizarse automáticamente a partir de otros siempre que los otros cambien.

Para prepararte para usar remake, debes escribir un archivo llamado makefile que describa las relaciones entre los archivos en tu programa, y los estados de los comandos para actualizar cada archivo. En un programa, típicamente el archivo ejecutable se actualiza a partir de archivos objeto, que a su vez se crean compilando archivos fuente.

Una vez que existe un makefile adecuado, cada vez que cambies algunos archivos fuente, este simple comando de shell:

remake

es suficiente para realizar todas las recompilaciones necesarias. El programa remake utiliza la descripción del makefile y los tiempos de última modificación de los archivos para decidir cuáles de los archivos necesitan ser actualizados. Para cada uno de esos archivos, emite los comandos registrados en el makefile.

remake ejecuta comandos en el makefile para actualizar uno o más nombres de objetivo, donde nombre es típicamente un programa. Si no está presente la opción -f, remake buscará los makefiles GNUmakefile, makefile y Makefile, en ese orden.

Normalmente deberías llamar a tu makefile makefile o Makefile. (Recomendamos Makefile porque aparece de forma prominente al principio de un listado de directorios, justo al lado de otros archivos importantes como README.) El primer nombre verificado, GNUmakefile, no se recomienda para la mayoría de los makefiles. Debes usar este nombre si tienes un makefile que es específico para GNU remake, y no será entendido por otras versiones de remake. Si makefile es '-', se leerá la entrada estándar.

remake actualiza un objetivo si depende de archivos prerrequisito que han sido modificados desde que el objetivo fue modificado por última vez, o si el objetivo no existe.

OPCIONES

A continuación, ofrecemos opciones específicas de remake. Para las demás opciones, por favor, consulta la documentación de GNU Make.

-c, --search-parent
si no se encuentra un Makefile o un objetivo en el directorio actual, remake buscará en el directorio padre un Makefile. Al encontrar un directorio padre, el más cercano con un Makefile, remake establecerá su directorio de trabajo actual al directorio donde se encontró el Makefile.

En este aspecto, la opción corta '-c' es como '-C' excepto que no se necesita especificar un directorio.

-!, --post-mortem
Entrar en el depurador ante un error. Esto es lo mismo que las opciones: --debugger --debugger-stop=error
-P, --profile [=TIPO]
Habilita la salida de perfilado de tiempos y dependencias utilizando el TIPO especificado para el formato. TIPO puede ser callgrind o json. Si se omite, por defecto será callgrind. Los archivos generados usando callgrind pueden ser analizados con kcachegrind, callgrind_annotate o gprof2dot. Los archivos generados con json tienen el formato especificado en el manual info.
--profile-directory=[RUTA]
Especifica la RUTA donde se escribirán los archivos de perfilado. Debe existir antes de ejecutar make. Se asume que es una ruta relativa al directorio inicial donde se llama a make, a menos que comience con ~ o /.
--targets
Imprime una lista de objetivos nombrados explícitamente encontrados en los makefiles leídos.
--tasks
Imprime una lista de objetivos nombrados explícitamente encontrados en los makefiles leídos que tienen comentarios de descripción. Un comentario de descripción se añade poniendo un solo comentario antes del objetivo que comienza con '#:'.
-x, --trace [=FLAGS]
Establece las banderas de rastreo. Si se omiten las FLAGS, entonces el comportamiento es el mismo que si se especificara --trace=normal. FLAGS puede ser read para rastrear los Makefiles leídos, noshell que es como normal pero el rastreo del shell está deshabilitado, o full para rastreo máximo.
-X, --debugger [=TIPO]
Entrar en el depurador con. Si se omiten los TYPE, entonces el comportamiento es el mismo que si se especificara --debugger=normal. TYPE puede ser goal para todos los rastreos de Makefiles leídos, preread que se detiene antes de que se lean los Makefiles, goal que se detiene después de que se construye el objetivo objetivo, normal que es lo mismo que no dar ninguna opción, preaction que es como normal pero el rastreo del shell está deshabilitado, full para rastreo máximo. Es lo mismo que dar todas las opciones excepto "normal". fatal para entrar en el depurador ante un error fatal, error para entrar en el depurador ante un error.

VER TAMBIÉN

La documentación completa de remake se mantiene como un manual Texinfo. Si los programas info y remake están correctamente instalados en tu sitio, el comando

info remake

debería darte acceso al manual de remake.

remake(1)

NOMBRE

remake - Un depurador de scripts de shell.

SINOPSIS

remake [opciones] [script [argumentos...]]

DESCRIPCIÓN

remake es un depurador para scripts de shell, diseñado para ser más interactivo y útil que las herramientas estándar comoset -x.

Permite establecer puntos de interrupción, inspeccionar variables, ejecutar comandos paso a paso y ver el flujo de ejecución del script.

OPCIONES

-q, --quiet
Suprime mensajes de inicio.
-v, --verbose
Activa la salida detallada.
-h, --help
Muestra el mensaje de ayuda y sale.
-V, --version
Muestra la información de versión y sale.

remake también acepta opciones para el propio script de shell, que se pasan directamente al intérprete de shell.

VER TAMBIÉN

bash(1), sh(1), set(1)
