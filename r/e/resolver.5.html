resolv.conf(5) Manual de Formatos de Archivo resolv.conf(5)

NOMBRE

resolv.conf - archivo de configuración del resolvedor

SINOPSIS

/etc/resolv.conf

DESCRIPCIÓN

El resolvedor es un conjunto de rutinas en la biblioteca C que proporcionan acceso al Sistema de Nombres de Dominio (DNS) de Internet. El archivo de configuración del resolvedor contiene información que es leída por las rutinas del resolvedor la primera vez que son invocadas por un proceso. El archivo está diseñado para ser legible por humanos y contiene una lista de palabras clave con valores que proporcionan varios tipos de información del resolvedor. El archivo de configuración se considera una fuente confiable de información DNS; consulte la opción trust-ad a continuación para obtener más detalles.

Si este archivo no existe, solo se consultará el servidor de nombres en la máquina local, y la lista de búsqueda contendrá el nombre de dominio local determinado a partir del nombre de host.

Las diferentes opciones de configuración son:

nameserver Dirección IP del servidor de nombres
Dirección de Internet de un servidor de nombres que el resolvedor debe consultar, ya sea una dirección IPv4 (en notación de puntos) o una dirección IPv6 en notación de dos puntos (y posiblemente puntos) según RFC 2373. Se pueden listar hasta MAXNS (actualmente 3, ver <resolv.h>) servidores de nombres, uno por palabra clave. Si hay múltiples servidores, la biblioteca del resolvedor los consulta en el orden listado. Si no hay entradas nameserver, el valor predeterminado es utilizar el servidor de nombres en la máquina local. (El algoritmo utilizado es probar un servidor de nombres y, si la consulta expira, probar el siguiente, hasta agotar los servidores de nombres, luego repetir intentando con todos los servidores de nombres hasta que se realice un número máximo de reintentos).
search Lista de búsqueda para la resolución de nombres de host.
Por defecto, la lista de búsqueda contiene una entrada, el nombre de dominio local. Se determina a partir del nombre de host local devuelto por gethostname(2); el nombre de dominio local se toma como todo lo que sigue al primer '.'. Finalmente, si el nombre de host no contiene un '.', se asume el dominio raíz como el nombre de dominio local.
Esto puede cambiarse listando la ruta de búsqueda de dominio deseada después de la palabra clave search, separando los nombres con espacios o tabulaciones. Las consultas del resolvedor que tengan menos de ndots puntos (el valor predeterminado es 1) se intentarán utilizando cada componente de la lista de búsqueda en orden hasta que se encuentre una coincidencia. Para entornos con múltiples subdominios, lea la opción options ndots:n a continuación para evitar ataques de man-in-the-middle y tráfico innecesario para los servidores DNS raíz. Tenga en cuenta que este proceso puede ser lento y generará mucho tráfico de red si los servidores de los dominios listados no son locales, y que las consultas expirarán si no hay un servidor disponible para uno de los dominios.
Si hay varias directivas search, solo se utiliza la lista de búsqueda de la última instancia.
En glibc 2.25 y anteriores, la lista de búsqueda se limita a seis dominios con un total de 256 caracteres. Desde glibc 2.26, la lista de búsqueda es ilimitada.
La directiva domain es un nombre obsoleto para la directiva search que maneja solo una entrada en la lista de búsqueda.
sortlist
Esta opción permite ordenar las direcciones devueltas por gethostbyname(3). Una lista de ordenación se especifica mediante pares de dirección IP-máscara de red. La máscara de red es opcional y, por defecto, es la máscara de red natural de la red. La dirección IP y los pares de red opcionales están separados por barras. Se pueden especificar hasta 10 pares. Aquí hay un ejemplo:

sortlist 130.155.160.0/255.255.240.0 130.155.0.0
options
Las opciones permiten modificar ciertas variables internas del resolvedor. La sintaxis es
options opción ...

donde opción es una de las siguientes:

debug
Establece RES_DEBUG en _res.options (efectivo solo si glibc fue compilado con soporte de depuración; ver resolver(3)).
ndots:n
Establece un umbral para el número de puntos que deben aparecer en un nombre dado a res_query(3) (ver resolver(3)) antes de que se realice una consulta absoluta inicial. El valor predeterminado para n es 1, lo que significa que si hay algún punto en un nombre, el nombre se intentará primero como un nombre absoluto antes de que se agreguen a él elementos de la lista de búsqueda. El valor de esta opción se limita silenciosamente a 15.
timeout:n
Establece el tiempo que el resolvedor esperará una respuesta de un servidor de nombres remoto antes de volver a intentar la consulta a través de un servidor de nombres diferente. Esto puede que no sea el tiempo total que tarda cualquier llamada a la API del resolvedor y no hay garantía de que una sola llamada a la API del resolvedor se corresponda con un solo tiempo de espera. Medido en segundos, el valor predeterminado es RES_TIMEOUT (actualmente 5, ver <resolv.h>). El valor de esta opción se limita silenciosamente a 30.
attempts:n
Establece el número de veces que el resolvedor enviará una consulta a sus servidores de nombres antes de rendirse y devolver un error a la aplicación que llama. El valor predeterminado es RES_DFLRETRY (actualmente 2, ver <resolv.h>). El valor de esta opción se limita silenciosamente a 5.
rotate
Establece RES_ROTATE en _res.options, lo que provoca una selección rotatoria de servidores de nombres entre los listados. Esto tiene el efecto de distribuir la carga de consultas entre todos los servidores listados, en lugar de que todos los clientes prueben primero el primer servidor listado cada vez.
no-aaaa (desde glibc 2.36)
Establece RES_NOAAAA en _res.options, lo que suprime las consultas AAAA realizadas por el resolvedor stub, incluidas las consultas AAAA activadas por interfaces basadas en NSS como getaddrinfo(3). Solo se ven afectadas las consultas DNS: los datos IPv6 en hosts(5) todavía se utilizan, getaddrinfo(3) con AI_PASSIVE seguirá produciendo direcciones IPv6, y los servidores de nombres IPv6 configurados todavía se utilizan. Para producir resultados correctos de Error de Nombre (NXDOMAIN), las consultas AAAA se traducen a consultas A. Esta opción está destinada principalmente a fines de diagnóstico, para descartar que las consultas DNS AAAA tengan un impacto adverso. Es incompatible con el uso de EDNS0 y la validación DNSSEC por parte de las aplicaciones.
no-check-names
Establece RES_NOCHECKNAME en _res.options, lo que deshabilita la comprobación moderna de BIND de nombres de host entrantes y nombres de correo para caracteres inválidos como guiones bajos (_), no ASCII o caracteres de control.
inet6
Establece RES_USE_INET6 en _res.options. Esto tiene el efecto de intentar una consulta AAAA antes que una consulta A dentro de la función gethostbyname(3), y de mapear respuestas IPv4 en forma "tunelizada" de IPv6 si no se encuentran registros AAAA pero existe un conjunto de registros A. Desde glibc 2.25, esta opción está obsoleta; las aplicaciones deben usar getaddrinfo(3), en lugar de gethostbyname(3).
ip6-bytestring (desde glibc 2.3.4 hasta glibc 2.24)
Establece RES_USEBSTRING en _res.options. Esto hace que las consultas inversas de IPv6 se realicen utilizando el formato de etiqueta de bits descrito en RFC 2673; si esta opción no está establecida (que es el valor predeterminado), se utiliza el formato de nibble. Esta opción se eliminó en glibc 2.25, ya que dependía de una extensión DNS incompatible con versiones anteriores que nunca se desplegó en Internet.
ip6-dotint/no-ip6-dotint (glibc 2.3.4 a glibc 2.24)

edns0 (desde glibc 2.6)
Establece RES_USE_EDNS0 en _res.options. Esto habilita el soporte para las extensiones DNS descritas en la RFC 2671.
single-request (desde glibc 2.10)
Establece RES_SNGLKUP en _res.options. Por defecto, glibc realiza las búsquedas de IPv4 e IPv6 en paralelo desde glibc 2.9. Algunos servidores DNS de dispositivos no pueden manejar estas consultas correctamente y hacen que las solicitudes caduquen. Esta opción deshabilita el comportamiento y hace que glibc realice las solicitudes IPv6 e IPv4 secuencialmente (a costa de cierta ralentización del proceso de resolución).
single-request-reopen (desde glibc 2.9)
Establece RES_SNGLKUPREOP en _res.options. El resolvedor utiliza el mismo socket para las solicitudes A y AAAA. Algunos hardwares envían erróneamente solo una respuesta. Cuando eso sucede, el sistema cliente se queda esperando la segunda respuesta. Activar esta opción cambia este comportamiento para que, si dos solicitudes del mismo puerto no se manejan correctamente, se cierre el socket y se abra uno nuevo antes de enviar la segunda solicitud.
no-tld-query (desde glibc 2.14)
Establece RES_NOTLDQUERY en _res.options. Esta opción hace que res_nsearch() no intente resolver un nombre no cualificado como si fuera un dominio de nivel superior (TLD). Esta opción puede causar problemas si el sitio tiene "localhost" como TLD en lugar de tener localhost en uno o más elementos de la lista de búsqueda. Esta opción no tiene efecto si ni RES_DEFNAMES ni RES_DNSRCH están configurados.
use-vc (desde glibc 2.14)
Establece RES_USEVC en _res.options. Esta opción fuerza el uso de TCP para las resoluciones DNS.
no-reload (desde glibc 2.26)
Establece RES_NORELOAD en _res.options. Esta opción deshabilita la recarga automática de un archivo de configuración modificado.
trust-ad (desde glibc 2.31)
Establece RES_TRUSTAD en _res.options. Esta opción controla el comportamiento del bit AD del resolvedor stub. Si un resolvedor validador establece el bit AD en una respuesta, indica que los datos de la respuesta fueron verificados según el protocolo DNSSEC. Para poder confiar en el bit AD, el sistema local debe confiar tanto en el resolvedor validador de DNSSEC como en la ruta de red hacia él, razón por la cual se requiere una opción explícita. Si la opción trust-ad está activa, el resolvedor stub establece el bit AD en las consultas DNS salientes (para habilitar el soporte del bit AD) y preserva el bit AD en las respuestas. Sin esta opción, el bit AD no se establece en las consultas y siempre se elimina de las respuestas antes de que se devuelvan a la aplicación. Esto significa que las aplicaciones pueden confiar en el bit AD en las respuestas si la opción trust-ad se ha configurado correctamente.
En glibc 2.30 y versiones anteriores, el bit AD no se establece automáticamente en las consultas y se transmite sin cambios a las aplicaciones en las respuestas.

La palabra clave search del archivo resolv.conf de un sistema puede ser anulada a nivel de proceso estableciendo la variable de entorno LOCALDOMAIN a una lista de dominios de búsqueda separados por espacios.

La palabra clave options del archivo resolv.conf de un sistema puede ser modificada a nivel de proceso estableciendo la variable de entorno RES_OPTIONS a una lista de opciones del resolvedor separadas por espacios, como se explica anteriormente en options.

La palabra clave y el valor deben aparecer en una sola línea, y la palabra clave (por ejemplo, nameserver) debe iniciar la línea. El valor sigue a la palabra clave, separado por espacios en blanco.

Las líneas que contienen un punto y coma (;) o un carácter de almohadilla (#) en la primera columna se tratan como comentarios.
