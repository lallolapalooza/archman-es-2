redirector(3bobcat) Redireccionamiento de archivos a nivel de sistema redirector(3bobcat)

NOMBRE

FBB::Redirector - Redirige un descriptor de archivo a otro descriptor

SINOPSIS

#include <bobcat/redirector>
Opción de enlace: -lbobcat

DESCRIPCION

Los objetos de la clase FBB::Redirector configuran un redireccionamiento de archivos a nivel de sistema, utilizando descriptores de archivo en lugar de flujos. Los objetos Redirector son efectivamente envoltorios alrededor de la llamada al sistema dup2(2). El redireccionamiento a nivel de sistema permite al programador enviar la salida, por ejemplo, al flujo de salida estándar, que en realidad aparece en otro flujo (por ejemplo, el de error estándar).

Los objetos Redirector se utilizan para redirigir la salida enviada a un flujo con descriptor de archivo x a otro flujo con descriptor de archivo y, de manera muy similar a como el operador > del shell redirige la salida estándar a un archivo.

Los objetos Redirector también se pueden utilizar para extraer información de un flujo con descriptor de archivo x en realidad de otro flujo con descriptor de archivo y, de manera muy similar a como se utiliza el operador < del shell para leer la información de un archivo desde la entrada estándar.

El redireccionamiento utilizando objetos Redirector representa una forma de redireccionamiento más fuerte que el ofrecido por el propio C++, que utiliza el redireccionamiento de std::streambuf y que, por lo tanto, está limitado al ámbito del programa. El redireccionamiento a nivel de sistema, por otro lado, se aplica a nivel de sistema, permitiendo al programador redirigir los flujos estándar al iniciar un programa. Por ejemplo, el error estándar se escribe comúnmente en la salida estándar mediante una invocación como programa 2>&1.

Al construir objetos Redirector se requiere un descriptor de archivo. El descriptor de archivo especificado en el constructor es el descriptor de archivo que utilizará el programa para leer o escribir información. Se requiere otro descriptor de archivo para configurar el redireccionamiento: el descriptor de archivo utilizado aquí es el descriptor de archivo del flujo que realmente contiene la información que se extrae del descriptor de archivo que se pasó al constructor de Redirector; o es el descriptor de archivo del flujo que recibe la información que se escribe en el flujo que tiene el descriptor de archivo que se pasó al constructor de Redirector.

Cuando un objeto Redirector sale de ámbito, sus descriptores de archivo se dejan como están. En particular, tenga en cuenta que no se realiza ninguna operación close(2) en los descriptores de archivo del Redirector. Después de configurar el redireccionamiento utilizando las funciones miembro del Redirector y pasar los descriptores de archivo del Redirector a código que utiliza los descriptores del Redirector, el objeto Redirector podría ser destruido de forma segura.

Formalmente, los descriptores de archivo no están definidos en C++, pero están disponibles en muchos tipos de sistemas operativos. En esos sistemas, cada `archivo' tiene un `descriptor de archivo' asociado. Un descriptor de archivo es un int, que es un índice en la tabla de asignación de archivos del programa, mantenida por el sistema. Otro tipo de entidades bien conocidas que son descriptores de archivo son los sockets.

Los descriptores de archivo bien conocidos (definidos, por ejemplo, en unistd.h) con valores fijos son 0 (STDIN_FILENO), que representa el flujo de entrada estándar (std::cin); 1, (STDOUT_FILENO), que representa el flujo de salida estándar (std::cout); 2, (STDERR_FILENO), que representa el flujo de error estándar (cerr); Notas:

o
Los redireccionamientos a nivel de sistema se mantienen durante las llamadas al sistema de la familia exec(3).
o
La destrucción de un objeto Redirector no deshace el redireccionamiento establecido por dicho objeto.

ENUMERACION

La enumeración StandardFileno contiene los siguientes valores:

o
STDIN (0)
o
STDOUT (1)
o
STDERR (2) Estos valores pueden usarse para configurar un redireccionamiento en lugar de los números simples.

CONSTRUCTORES

o
Redirector(int fd):
Este constructor espera el descriptor de archivo del archivo que será utilizado por el programa para acceder (leer, escribir) a otro archivo. El descriptor de archivo que se pasa al constructor es utilizado por el programa, y a menudo será STDIN, STDOUT, o STDERR, permitiendo al programa usar cin, cout, o cerr para extraer información de, o insertar información en otros flujos utilizando sus flujos de entrada y salida estándar.

Los constructores y operadores de asignación de copia y movimiento (y operadores de asignación) están disponibles.

FUNCIONES MIEMBRO

o
void swallow(int otherFd) const:
Esta función miembro espera un descriptor de archivo que se convertirá en un sinónimo del descriptor de archivo del constructor. El descriptor de archivo del constructor se redirige a otherFd.
Después de llamar exitosamente a swallow, la información escrita en otherFd se escribe en el descriptor de archivo del constructor. Por ejemplo, si el descriptor de archivo del constructor representa un archivo en disco y otherFd es STDOUT_FILENO, entonces toda la información enviada al flujo de salida estándar se envía en realidad al archivo en disco: 
    información enviada a otherFd -> se recibe en el Fd del constructor
    (ej. otherFd = STDOUT_FILENO)
Por el contrario, si el descriptor de archivo del constructor representa un archivo en disco y otherFd es STDIN_FILENO, entonces toda la información extraída de la entrada estándar se lee en realidad del archivo en disco. 
    información extraída de otherFd <- se lee desde el Fd del constructor
    (ej. otherFd = STDIN_FILENO)
Después de swallow, ambos descriptores de archivo están abiertos y apuntan al descriptor de archivo del constructor.
Antes de configurar el redireccionamiento, el otherFd original se cierra mediante close(2). Después de swallow, ambos descriptores de archivo pueden ser utilizados y apuntan al descriptor de archivo del constructor. Si después de llamar a swallow se llama a close(2) para uno de ellos, el otro permanece abierto.
Si el redireccionamiento falla, se lanza un objeto FBB::Exception, cuya función miembro which() muestra el valor errno del sistema establecido por la función fallida dup2(2).
o
void through(int otherFd) const:
Esta función miembro espera un descriptor de archivo que se convertirá en un sinónimo del descriptor de archivo del constructor. El descriptor de archivo del constructor se redirige a otherFd. El descriptor de archivo del constructor ya no se puede utilizar, ya que se cierra mediante close(2).
Después de llamar exitosamente a through, la información escrita en otherFd se escribe en el descriptor de archivo del constructor. Por ejemplo, si el descriptor de archivo del constructor representa un archivo en disco y otherFd es STDOUT_FILENO, entonces toda la información enviada al flujo de salida estándar se envía en realidad al archivo en disco: 
    información enviada a otherFd -> se recibe en el Fd del constructor
    (ej. otherFd = STDOUT_FILENO)
Por el contrario, si el descriptor de archivo del constructor representa un archivo en disco y otherFd es STDIN_FILENO, entonces toda la información extraída de la entrada estándar se lee en realidad del archivo en disco. 
    información extraída de otherFd <- se lee desde el Fd del constructor
    (ej. otherFd = STDIN_FILENO)
A diferencia de swallow, solo otherFd queda abierto después de through. El descriptor de archivo del constructor se cierra. Además, otherFd ya no es un sinónimo del descriptor de archivo del constructor, sino que se convierte en el descriptor de archivo del constructor. ¡En otras palabras, la información enviada al descriptor de archivo original (el del constructor) ahora va a otherFd y vice versa!
Si el redireccionamiento falla, se lanza un objeto FBB::Exception, cuya función miembro which() muestra el valor errno del sistema establecido por la función fallida dup2(2).

redirector(3bobcat) — Arch manual pages

NAME

redirector - Redirect standard streams

SYNOPSIS

    #include <bobcat/redirector>

    namespace FBB
    {
        class Redirector
        {
            public:
                enum StreamType { STDIN_FILENO = 0, STDOUT_FILENO = 1, STDERR_FILENO = 2 };

                Redirector(StreamType from = STDOUT_FILENO,
                           int otherFd = -1);
                ~Redirector();

                void swallow(StreamType type);
                void redirect(StreamType from, int otherFd);
                void close(StreamType type);
                int get(StreamType type) const;
                int fd(StreamType type) const;

            private:
                int redirect(int from, int to);
        };
    }

DESCRIPTION

The Redirector class provides a means to redirect standard I/O streams (standard input, standard output, standard error) to arbitrary file descriptors. When a Redirector object is created, its constructor may redirect the standard output stream (or standard error, or standard input) to a file descriptor specified as an argument to the constructor. By default, this is file descriptor 1 (stdout). If the constructor argument is -1 (the default value), then standard output is not redirected. If it is specified as STDIN_FILENO (0), STDOUT_FILENO (1), or STDERR_FILENO (2), then the constructor will redirect the stream corresponding to the argument from to the file descriptor specified by otherFd.

The swallow() member function can be used to redirect additional streams. For example, if the constructor is used to redirect standard output, swallow(STDERR_FILENO) can be used to redirect standard error to the same destination. The swallow() function will also close the original stream. The close() member function closes the specified stream, making it available again.

The get() and fd() member functions return the file descriptor associated with the specified stream. Note that this file descriptor may have been changed by the constructor or by swallow() or redirect().

The redirect() member function redirects stream from to file descriptor otherFd. The original stream from is closed before the redirection takes place. The otherFd parameter is then used for reads/writes from the stream.

If otherFd is STDIN_FILENO and from is STDIN_FILENO, then all information extracted from the standard input stream is actually read from the file on disk.

    information extracted from otherFd <- is read from the constructor’s Fd
    (e.g., otherFd = STDIN_FILENO)

Before setting up the redirection, the original otherFd is closed by close(2). Following through only otherFd can be used, and it refers to (i.e., reads or writes) the constructor’s file descriptor.

EXAMPLE

    #include <iostream>
    #include <bobcat/redirector>
    using namespace std;
    using namespace FBB;
    int main()
    {
        Redirector redirector(Redirector::STDOUT);
        redirector.swallow(Redirector::STDERR);
        cerr << "This appears at the standard output stream\n"
                "use `a.out > /dev/null’ to suppress this message" << endl;
    }
