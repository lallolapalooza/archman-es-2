restart_syscall(2) Manual de llamadas al sistema restart_syscall(2)

NOMBRE

restart_syscall - reiniciar una llamada al sistema después de una interrupción por una señal de detención

SINOPSIS

long restart_syscall(void);

Nota: No existe un envoltorio de glibc para esta llamada al sistema; véase NOTAS.

DESCRIPCIÓN

La llamada al sistema restart_syscall() se utiliza para reiniciar ciertas llamadas al sistema después de que un proceso que fue detenido por una señal (por ejemplo, SIGSTOP o SIGTSTP) se reanude más tarde tras recibir una señal SIGCONT. Esta llamada al sistema está diseñada solo para uso interno del kernel.

restart_syscall() se utiliza para reiniciar solo aquellas llamadas al sistema que, al reiniciarse, deben ajustar sus parámetros relacionados con el tiempo —a saber, poll(2) (desde Linux 2.6.24), nanosleep(2) (desde Linux 2.6), clock_nanosleep(2) (desde Linux 2.6) y futex(2), cuando se utiliza con las operaciones FUTEX_WAIT (desde Linux 2.6.22) y FUTEX_WAIT_BITSET (desde Linux 2.6.31). restart_syscall() reinicia la llamada al sistema interrumpida con un argumento de tiempo que se ajusta adecuadamente para tener en cuenta el tiempo que ya ha transcurrido (incluido el tiempo en que el proceso fue detenido por una señal). Sin el mecanismo restart_syscall(), el reinicio de estas llamadas al sistema no deduciría correctamente el tiempo ya transcurrido cuando el proceso continuara su ejecución.

VALOR DE RETORNO

El valor de retorno de restart_syscall() es el valor de retorno de la llamada al sistema que se esté reiniciando.

ERRORES

errno se establece según los errores de la llamada al sistema que esté siendo reiniciada por restart_syscall().

ESTANDARES

Linux.

HISTORIA

Linux 2.6.

NOTAS

No existe un envoltorio de glibc para esta llamada al sistema, ya que está destinada únicamente al uso del kernel y nunca debe ser llamada por aplicaciones.

El kernel utiliza restart_syscall() para garantizar que, cuando se reinicia una llamada al sistema después de que un proceso haya sido detenido por una señal y luego reanudado por SIGCONT, el tiempo que el proceso pasó en estado detenido se cuente contra el intervalo de tiempo de espera especificado en la llamada al sistema original. En el caso de llamadas al sistema que toman un argumento de tiempo de espera y se reinician automáticamente después de una señal de detención más SIGCONT, pero que no tienen el mecanismo restart_syscall() incorporado, después de que el proceso reanude la ejecución, el tiempo que el proceso pasó en estado de detención *no* se cuenta contra el valor de tiempo de espera. Ejemplos notables de llamadas al sistema que sufren este problema son ppoll(2), select(2) y pselect(2).

Desde el espacio de usuario, el funcionamiento de restart_syscall() es en gran medida invisible: para el proceso que realizó la llamada al sistema que se reinicia, parece que esa llamada al sistema se ejecutó y devolvió su valor de forma habitual.

VER TAMBIÉN

sigaction(2), sigreturn(2), signal(7)
