DESCRIPCIÓN

Nota: Esta página está incompleta (varias funciones del resolver proporcionadas por glibc no se describen) y es probable que esté desactualizada.

Las funciones descritas a continuación realizan consultas y interpretan las respuestas de los servidores de nombres de dominio de Internet.

La API consta de un conjunto de funciones más modernas y reentrantes y un conjunto más antiguo de funciones no reentrantes que han sido reemplazadas. Las interfaces tradicionales del resolver como res_init() y res_query() utilizan un estado estático (global) almacenado en la estructura _res, lo que hace que estas funciones no sean seguras para subprocesos. BIND 8.2 introdujo un conjunto de nuevas interfaces res_ninit(), res_nquery(), etc., que toman un res_state como primer argumento, por lo que puede utilizar un estado de resolver por hilo.

Las funciones res_ninit() y res_init() leen los archivos de configuración (ver resolv.conf(5)) para obtener el nombre de dominio predeterminado y la(s) dirección(es) del servidor de nombres. Si no se proporciona ningún servidor, se intenta con el host local. Si no se proporciona ningún dominio, se utiliza el asociado con el host local. Puede ser anulado por la variable de entorno LOCALDOMAIN. res_ninit() o res_init() se ejecuta normalmente en la primera llamada a una de las otras funciones. Cada llamada a res_ninit() requiere una llamada correspondiente a res_nclose() para liberar la memoria asignada por res_ninit() y las llamadas posteriores a res_nquery().

Las funciones res_nquery() y res_query() consultan al servidor de nombres para el nombre de dominio completamente calificado name del type y class especificados. La respuesta se deja en el búfer answer de longitud anslen proporcionado por el llamante.

Las funciones res_nsearch() y res_search() realizan una consulta y esperan la respuesta como res_nquery() y res_query(), pero además implementan las reglas de predeterminado y búsqueda controladas por RES_DEFNAMES y RES_DNSRCH (ver la descripción de las opciones de _res a continuación).

Las funciones res_nquerydomain() y res_querydomain() realizan una consulta utilizando res_nquery()/res_query() en la concatenación de name y domain.

Las siguientes funciones son rutinas de nivel inferior utilizadas por res_nquery()/res_query().

Las funciones res_nmkquery() y res_mkquery() construyen un mensaje de consulta en buf de longitud buflen para el nombre de dominio dname. El tipo de consulta op es uno de los siguientes (típicamente QUERY):

QUERY
Consulta estándar.
IQUERY
Consulta inversa. Esta opción se eliminó en glibc 2.26, ya que no ha sido compatible con los servidores DNS durante mucho tiempo.
NS_NOTIFY_OP
Notificar a la secundaria el cambio de SOA (Inicio de autoridad).

newrr no se utiliza actualmente.

La función res_nsend() y res_send() envían una consulta preformateada dada en msg de longitud msglen y devuelven la respuesta en answer que tiene una longitud anslen. Llamarán a res_ninit()/res_init() si aún no se ha llamado.

La función dn_comp() comprime el nombre de dominio exp_dn y lo almacena en el búfer comp_dn de longitud length. La compresión utiliza una matriz de punteros dnptrs a nombres previamente comprimidos en el mensaje actual. El primer puntero apunta al principio del mensaje y la lista termina con NULL. El límite de la matriz se especifica mediante lastdnptr. Si dnptr es NULL, los nombres de dominio no se comprimen. Si lastdnptr es NULL, la lista de etiquetas no se actualiza.

La función dn_expand() expande el nombre de dominio comprimido comp_dn a un nombre de dominio completo, que se coloca en el búfer exp_dn de tamaño length. El nombre comprimido está contenido en un mensaje de consulta o respuesta, y msg apunta al principio del m

OPTIONS

The resolver routines use configuration and state information contained in a __res_state structure (either passed as the statep argument, or in the global variable _res, in the case of the older nonreentrant functions). The only field of this structure that is normally manipulated by the user is the options field. This field can contain the bitwise "OR" of the following options:

RES_INIT
True if res_ninit() or res_init() has been called.
RES_DEBUG
Print debugging messages. This option is available only if glibc was built with debugging enabled, which is not the default.
RES_AAONLY (unimplemented; deprecated in glibc 2.25)
Accept authoritative answers only. res_send() continues until it finds an authoritative answer or returns an error. This option was present but unimplemented until glibc 2.24; since glibc 2.25, it is deprecated, and its usage produces a warning.
RES_USEVC
Use TCP connections for queries rather than UDP datagrams.
RES_PRIMARY (unimplemented; deprecated in glibc 2.25)
Query primary domain name server only. This option was present but unimplemented until glibc 2.24; since glibc 2.25, it is deprecated, and its usage produces a warning.
RES_IGNTC
Ignore truncation errors. Don't retry with TCP.
RES_RECURSE
Set the recursion desired bit in queries. Recursion is carried out by the domain name server, not by res_send(). [Enabled by default].
RES_DEFNAMES
If set, res_search() will append the default domain name to single component names—that is, those that do not contain a dot. [Enabled by default].
RES_STAYOPEN
Used with RES_USEVC to keep the TCP connection open between queries.
RES_DNSRCH
If set, res_search() will search for hostnames in the current domain and in parent domains. This option is used by gethostbyname(3). [Enabled by default].
RES_INSECURE1
Accept a response from a wrong server. This can be used to detect potential security hazards, but you need to compile glibc with debugging enabled and use RES_DEBUG option (for debug purpose only).
RES_INSECURE2
Accept a response which contains a wrong query. This can be used to detect potential security hazards, but you need to compile glibc with debugging enabled and use RES_DEBUG option (for debug purpose only).
RES_NOALIASES
Disable usage of HOSTALIASES environment variable.
RES_USE_INET6
Try an AAAA query before an A query inside the gethostbyname(3) function, and map IPv4 responses in IPv6 "tunneled form" if no AAAA records are found but an A record set exists. Since glibc 2.25, this option is deprecated, and its usage produces a warning; applications should use getaddrinfo(3), rather than gethostbyname(3).
RES_ROTATE
Causes round-robin selection of name servers from among those listed. This has the effect of spreading the query load among all listed servers, rather than having all clients try the first listed server first every time.
RES_NOCHECKNAME (unimplemented; deprecated in glibc 2.25)
Disable the modern BIND checking of incoming hostnames and mail names for invalid characters such as underscore (_), non-ASCII, or control characters. This option was present until glibc 2.24; since glibc 2.25, it is deprecated, and its usage produces a warning.
RES_KEEPTSIG (unimplemented; deprecated in glibc 2.25)
Do not strip TSIG records. This option was present but unimplemented until glibc 2.24; since glibc 2.25, it is deprecated, and its usage produces a warning.
RES_BLAST (unimplemented; deprecated in glibc 2.25)
Send each query simultaneously and recursively to all servers. This option was present but unimplemented until glibc 2.24; since glibc 2.25, it is deprecated, and its usage produces a warning.
RES_USEBSTRING (glibc 2.3.4 to glibc 2.24)
Make reverse IPv6 lookups using the bit-label format described in RFC 2673; if this option is not set (which is the default), then nibble format is used. This option was removed in glibc 2.25, since it relied on a backward-incompatible DNS extension that was never deployed on the Internet.
RES_NOIP6DOTINT (glibc 2.24 and earlier)
Use ip6.arpa zone in IPv6 reverse lookup instead of ip6.int, which is deprecated since glibc 2.3.4. This option is present up to and including glibc 2.24, where it is enabled by default. In glibc 2.25, this option was removed.
RES_USE_EDNS0 (since glibc 2.6)
Enables support for the DNS extensions (EDNS0) described in RFC 2671.
RES_SNGLKUP (since glibc 2.10)
By default, glibc performs IPv4 and IPv6 lookups in parallel since glibc 2.9. Some appliance DNS servers cannot handle these queries properly and make the requests time out. This option disables the behavior and makes glibc perform the IPv6 and IPv4 requests sequentially (at the cost of some slowdown of the resolving process).
RES_SNGLKUPREOP
When RES_SNGLKUP option is enabled, opens a new socket for the each request.
RES_USE_DNSSEC
Use DNSSEC with OK bit in OPT record. This option implies RES_USE_EDNS0.
RES_NOTLDQUERY
Do not look up unqualified name as a top-level domain (TLD).
RES_DEFAULT
Default option which implies: RES_RECURSE, RES_DEFNAMES, RES_DNSRCH, and RES_NOIP6DOTINT.

RETURN VALUE

The res_ninit() and res_init() functions return 0 on success, or -1 if an error occurs.

The res_nquery(), res_query(), res_nsearch(), res_search(), res_nquerydomain(), res_querydomain(), res_nmkquery(), res_mkquery(), res_nsend(), and res_send() functions return the length of the response, or -1 if an error occurs.

The dn_comp() and dn_expand() functions return the length of the compressed name, or -1 if an error occurs.

In the case of an error return from res_nquery(), res_query(), res_nsearch(), res_search(), res_nquerydomain(), or res_querydomain(), the global variable h_errno (see gethostbyname(3)) can be consulted to determine the error.

NAME

res_init, res_mkquery, res_send, dn_expand, dnptrs, _res - resolver library initialization

LIBRARY

GNU C Library (glibc), as part of the BIND resolver library

SYNOPSIS

#include <resolv.h>

int res_init(void);
int res_mkquery(const char *dname, const char *type, const char *class, char *buf, int buflen, const char *domain, char *(*alloc)(size_t), int apiflag);
int res_send(const char *buf, int buflen, char *answer, int anslen);
int dn_expand(const unsigned char *msg, const unsigned char *eom, const unsigned char *compressed, char *expanded, int length);
extern struct __res_state *_res;


DESCRIPTION


The functions res_init(), res_mkquery(), res_send(), and dn_expand() are part of the resolver library that handles Domain Name System (DNS) queries. The resolver library provides an interface for applications to query DNS servers. The global structure _res (defined in <resolv.h>) holds the resolver state.


res_init() initializes the resolver state, reading the system configuration file (e.g., /etc/resolv.conf) to set up the nameservers, search domains, and other options. This function should be called before any other resolver functions.


res_mkquery() constructs a DNS query message. It takes the domain name, query type, and query class as input and formats them into a buffer. The parameters `domain`, `alloc`, and `apiflag` are used for constructing the query in certain scenarios, particularly with older versions of the resolver library or for specific query types.


res_send() sends a DNS query message (previously constructed by res_mkquery() or other means) to the configured nameservers and waits for a reply. It returns the reply in the `answer` buffer.


dn_expand() expands a compressed domain name from a DNS message into a human-readable string. This is often used to interpret the response from a DNS query.


The global variable `_res` is a pointer to a structure of type `__res_state` (or `res_state` in older versions) which contains the resolver's internal state, including the addresses of the nameservers, the search domain list, and various options.


RETURN VALUE


res_init() returns 0 on success, and -1 on error.


res_mkquery() returns the total size of the query message if successful, or -1 on error.


res_send() returns the number of bytes in the reply message if successful, or -1 on error. A return value of 0 might indicate a truncated reply that needs to be retried with the `RES_MORE` option set.


dn_expand() returns the number of characters consumed from the compressed name if successful, or -1 on error.

STANDARDS


These functions are part of the BIND resolver library, which has been a de facto standard for DNS resolution on Unix-like systems for many years. They are generally compatible with standards defined by the Internet Engineering Task Force (IETF), such as RFC 1034 and RFC 1035.


HISTORY


These functions first appeared in early versions of the Berkeley Internet Name Domain (BIND) DNS resolver.
