DESCRIPCIÓN

Las funciones que tratan con módulos MIB se dividen en cuatro grupos: las que tratan con la inicialización y el apagado, con la lectura y análisis de archivos MIB, con la búsqueda en el árbol MIB y rutinas de salida.

Inicialización y Apagado

add_mibdir se utiliza para añadir el directorio especificado a la ruta de ubicaciones que se buscan para encontrar archivos que contienen módulos MIB. Nótese que esto no carga realmente los módulos MIB ubicados en ese directorio, sino que es simplemente un paso de inicialización para hacerlos disponibles para netsnmp_read_module. Esta función devuelve un recuento de archivos encontrados en el directorio, o -1 si hay un error. Debe llamarse *antes* de invocar netsnmp_init_mib.

netsnmp_init_mib configura la ruta de búsqueda de directorios MIB (usando add_mibdir), configura el marco MIB interno y luego carga los módulos MIB apropiados (usando netsnmp_read_module y read_mib). Vea la sección VARIABLES DE ENTORNO para más detalles.
Debe llamarse antes que cualquier otra rutina que manipule o acceda al árbol MIB (pero después de cualquier llamada adicional a add_mibdir).

shutdown_mib borrará la información que fue recopilada por netsnmp_read_module, add_mibdir y add_module_replacement. Se recomienda encarecidamente no invocar shutdown_mib mientras haya sesiones SNMP gestionándose activamente.

Lectura y Análisis de MIBs

netsnmp_read_module toma el nombre de un módulo MIB (que no necesariamente tiene que ser el mismo que el nombre del archivo que contiene el módulo), lo localiza dentro de la lista configurada de directorios MIB y carga las definiciones del módulo en el árbol MIB activo. También carga cualquier módulo MIB listado en la cláusula IMPORTS de este módulo.

read_mib es similar, pero toma el nombre del archivo que contiene el módulo MIB. Nótese que este archivo no necesita estar ubicado dentro de la lista de búsqueda de directorios MIB (aunque sí los módulos listados en la cláusula IMPORTS).

read_all_mibs leerá todos los módulos MIB encontrados en la lista de búsqueda de directorios MIB.

En general, el analizador es silencioso sobre las rarezas que ve en los archivos MIB. Para obtener advertencias, llame a snmp_set_mib_warnings con un level de 1 (o 2 para aún más advertencias).

add_module_replacement se puede usar para permitir que los nuevos módulos MIB obsoleten los más antiguos, sin necesidad de modificar las cláusulas IMPORTS de otros módulos. Toma los nombres de los módulos viejo y nuevo, junto con una indicación de qué porciones del módulo viejo se ven afectadas.

tag len carga el nuevo módulo cuando:
NULL 0 siempre (el módulo viejo es un subconjunto estricto de
el nuevo)
nombre 0 solo para el tag dado
nombre no 0 para cualquier identificador con este prefijo
También se puede usar para manejar errores en los identificadores de módulo utilizados en las cláusulas IMPORTS de MIB (como referirse a RFC1213 en lugar de RFC1213-MIB).

Búsqueda en el Árbol MIB

read_objid toma una cadena que contiene una versión textual de un identificador de objeto (en forma numérica o descriptiva), y lo transforma en la lista correspondiente de sub-identificadores. Esto se devuelve en el parámetro output, con el número de sub-identificadores devuelto a través de out_len. Cuando se llama, out_len debe contener la longitud máxima de la matriz output. Si se están procesando múltiples identificadores de objeto, esta longitud debe restablecerse antes de cada llamada. Esta función devuelve un valor de 1 si tiene éxito al analizar la cadena y 0 en caso contrario.

snmp_parse_oid es similar, pero devuelve un puntero al búfer OID analizado (o NULL).

get_module_node toma un descriptor y el nombre de un módulo, y devuelve la lista OID correspondiente, de la misma manera que read_objid arriba.
Si el nombre del módulo se especifica como "ANY", entonces esta rutina asumirá que el descriptor dado es único dentro del árbol, y devolverá la entrada coincidente. Si esta suposición es inválida, el comportamiento de qué variable se devuelve depende de la implementación.

Salida

print_mib imprimirá una representación del árbol MIB activamente actualmente en el puntero FILE especificado.

print_objid tomará un identificador de objeto (tal como es devuelto por read_objid, snmp_parse_oid o get_module_node), e imprimirá la forma textual de este OID en la salida estándar.

fprint_objid hace lo mismo, pero imprime en el puntero FILE especificado por el parámetro inicial.

snprint_objid imprime la misma información en el búfer apuntado por buf, que tiene una longitud de len. Devuelve el número de caracteres impresos, o -1 si el búfer no era lo suficientemente grande. En este último caso, buf típicamente contendrá una versión truncada de la información (pero este comportamiento no está garantizado).

print_description, fprint_description y snprint_description toman un identificador de objeto similar e imprimen una versión de la definición MIB para ese objeto, junto con el OID completo. El argumento width controla cómo se presenta el OID.

NAME

read_all_mibs, read_mib, init_mib, netsnmp_read_module, snmp_set_save_descriptions – cargar MIBs

SYNOPSIS

#include <net-snmp/library/mib.h>

void init_mib(void);

int read_all_mibs(void);

int read_mib(const char *mibstring);

int netsnmp_read_module(const char *modulename);

void snmp_set_save_descriptions(int);

DESCRIPTION

Estas funciones se utilizan para cargar y analizar módulos MIB. Permiten a la aplicación Net-SNMP traducir nombres simbólicos de objetos (como ifDescr) a sus OID numéricos correspondientes (como .1.3.6.1.2.1.2.2.1.2) y viceversa. También proporcionan información textual sobre los objetos MIB.

Se deben llamar a init_mib o read_all_mibs antes de que se puedan utilizar las funciones de traducción de nombres dependientes de MIB (como snmp_parse_oid). init_mib inicializa el subsistema MIB, cargando un conjunto predeterminado de módulos MIB y los MIBs especificados por las variables de entorno MIBS y MIBDIRS.

read_all_mibs carga todos los módulos MIB disponibles en los directorios especificados por MIBDIRS. Esto puede ser un proceso que consume mucho tiempo y memoria, y generalmente solo es necesario si necesita acceder a un gran número de MIBs o si no sabe qué MIBs necesitará de antemano.

read_mib carga un MIB específico. El argumento mibstring puede ser el nombre de un archivo MIB, un nombre de módulo MIB (por ejemplo, IF-MIB) o un OID (en cuyo caso se carga el MIB que contiene ese OID).

netsnmp_read_module carga un módulo MIB específico por su nombre.

snmp_set_save_descriptions controla si la información de descripción de los objetos MIB se almacena en caché después de que se analizan. Si se establece en 1 (el valor predeterminado), las descripciones se almacenan en caché, lo que puede acelerar las búsquedas posteriores de descripciones. Si se establece en 0, las descripciones no se almacenan en caché, lo que ahorra memoria pero puede hacer que las búsquedas de descripciones sean más lentas.

Se recomienda encarecidamente llamar a snmp_set_save_descriptions(1) *antes* de llamar a init_mib (o similar).

ENVIRONMENT VARIABLES

El uso principal de las variables de entorno con respecto a estas llamadas API es configurar qué módulos MIB se deben cargar y dónde se encuentran.

MIBDIRS
Una lista separada por dos puntos de directorios para buscar módulos MIB.
Predeterminado: /usr/share/snmp/mibs
Utilizado por init_mib, netsnmp_read_module, read_all_mibs y (implícitamente) por read_mib.
MIBS
Una lista separada por dos puntos de módulos MIB para cargar.
La lista predeterminada de módulos dependerá de cómo se compiló originalmente el software Net-SNMP, pero típicamente es:
IP-MIB:IF-MIB:TCP-MIB:UDP-MIB:SNMPv2-MIB:RFC1213-MIB:UCD-SNMP-MIB:HOST-RESOURCES-MIB
Si el valor de la variable de entorno MIBS comienza con un carácter '+', entonces estos módulos MIB se agregarán a la lista predeterminada. De lo contrario, estos módulos (más cualquiera de los que importan) se cargarán *en lugar* de la lista predeterminada.
Si la variable de entorno MIBS tiene el valor ALL, entonces se llamará a read_all_mibs para cargar la colección completa de todos los módulos MIB disponibles.
Utilizado solo por init_mib.
MIBFILES
Una lista separada por dos puntos de archivos para cargar.
Predeterminado: (ninguno)
Utilizado solo por init_mib.
