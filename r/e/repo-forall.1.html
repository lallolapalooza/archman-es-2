repo-forall(1)

Paquete: repo

Licencias: Apache-2.0

REPO(1) Manual de Repo REPO(1)

NOMBRE

repo - repo forall - página del manual de repo forall

SINOPSIS

repo forall [<proyecto>...] -c <comando> [<arg>...]

DESCRIPCIÓN

Resumen

Ejecutar un comando de shell en cada proyecto

repo forall -r str1 [str2] ... -c <comando> [<arg>...]

OPCIONES

-h, --help
mostrar esta ayuda y salir
-j TRABAJOS, --jobs=TRABAJOS
número de trabajos a ejecutar en paralelo (predeterminado: basado en el número de núcleos de CPU)
-r, --regex
ejecutar el comando solo en proyectos que coincidan con la expresión regular o comodín
-i, --inverse-regex
ejecutar el comando solo en proyectos que NO coincidan con la expresión regular o comodín
-g GRUPOS, --groups=GRUPOS
ejecutar el comando solo en proyectos que coincidan con los grupos especificados
-c, --command
comando (y sus argumentos) a ejecutar
-e, --abort-on-errors
abortar si un comando finaliza de forma no exitosa
--ignore-missing
omitir silenciosamente y no salir con valor distinto de cero debido a la falta de checkouts
--interactive
forzar uso interactivo

Opciones de registro:

-v, --verbose
mostrar toda la salida
-q, --quiet
mostrar solo errores
-p
mostrar encabezados de proyecto antes de la salida

Opciones multi-manifiesto:

--outer-manifest
operar comenzando desde el manifiesto más externo
--no-outer-manifest
no operar en manifiestos externos
--this-manifest-only
operar solo en este manifiesto (sub)
--no-this-manifest-only, --all-manifests
operar en este manifiesto y sus submanifiestos

Ejecuta `repo help forall` para ver el manual detallado.

DETALLES

Ejecuta el mismo comando de shell en cada proyecto.

La opción -r permite ejecutar el comando solo en proyectos que coincidan con una expresión regular o comodín.

Por defecto, los proyectos se procesan de forma no interactiva en paralelo. Si deseas ejecutar comandos interactivos, asegúrate de pasar --interactive para forzar --jobs 1. Si bien el orden de procesamiento de los proyectos no está garantizado, el orden de la salida del proyecto es estable.

Formato de Salida

La opción -p hace que 'repo forall' enlace tuberías a los flujos de entrada, salida y error estándar del comando, y canaliza toda la salida a una sesión de paginador continua. Los encabezados de proyecto se insertan antes de que se muestre la salida de cada comando. Si el comando no produce salida en un proyecto, no se muestra ningún encabezado.

La convención de formato utilizada por -p es muy adecuada para algunos tipos de búsqueda, por ejemplo, `repo forall -p -c git log -SFoo` imprimirá todas las confirmaciones que añaden o eliminan referencias a Foo.

La opción -v hace que 'repo forall' muestre mensajes de error si un comando produce salida solo en stderr. Normalmente, la opción -p hace que la salida del comando se suprima hasta que el comando produzca al menos un byte de salida en stdout.

Entorno

pwd es el directorio de trabajo del proyecto. Si el cliente actual es un cliente espejo, entonces pwd es el repositorio Git.

REPO_PROJECT se establece en el nombre único del proyecto.

REPO_PATH es la ruta relativa a la raíz del cliente.

REPO_OUTERPATH es la ruta de la raíz del submanifiesto relativa a la raíz del cliente.

REPO_INNERPATH es la ruta relativa a la raíz del submanifiesto.

REPO_REMOTE es el nombre del sistema remoto del manifiesto.

REPO_LREV es el nombre de la revisión del manifiesto, traducido a una rama de seguimiento local. Si necesitas pasar la revisión del manifiesto a un comando git ejecutado localmente, usa REPO_LREV.

REPO_RREV es el nombre de la revisión del manifiesto, exactamente como está escrito en el manifiesto.

REPO_COUNT es el número total de proyectos que se están iterando.

REPO_I es el contador de iteración actual (basado en 1). Se puede usar junto con REPO_COUNT para añadir un indicador de progreso simple a tu comando.

REPO__* son cualquier variable de entorno adicional, especificada por el elemento "anotación" bajo cualquier elemento de proyecto. Esto puede ser útil para diferenciar árboles basados en criterios específicos del usuario, o simplemente para anotar detalles del árbol.

los argumentos posicionales del shell ($1, $2, .., $#) se establecen con cualquier argumento que siga a <comando>.

Ejemplo: para listar proyectos:

repo forall -c 'echo $REPO_PROJECT'

Observa que $REPO_PROJECT se cita para asegurar que se expanda en el contexto de la ejecución de <comando> en lugar de en el shell que llama.

A menos que se use -p, stdin, stdout, stderr se heredan del terminal y no se redirigen.

Si se usa -e, cuando un comando finaliza de forma no exitosa, 'repo forall' abortará sin iterar a través de los proyectos restantes.
