resolv.conf(5) Manual de formatos de archivo resolv.conf(5)

NOMBRE

resolv.conf - archivo de configuración del resolvedor

SINOPSIS

/etc/resolv.conf

DESCRIPCIÓN

El resolvedor es un conjunto de rutinas en la biblioteca C que proporcionan acceso al Sistema de Nombres de Dominio (DNS) de Internet. El archivo de configuración del resolvedor contiene información que es leída por las rutinas del resolvedor la primera vez que son invocadas por un proceso. El archivo está diseñado para ser legible por humanos y contiene una lista de palabras clave con valores que proporcionan varios tipos de información del resolvedor. El archivo de configuración se considera una fuente confiable de información DNS; consulte la opción trust-ad a continuación para obtener detalles.

Si este archivo no existe, solo se consultará el servidor de nombres en la máquina local y la lista de búsqueda contendrá el nombre de dominio local determinado a partir del nombre de host.

Las diferentes opciones de configuración son:

nameserver Dirección IP del servidor de nombres
Dirección de Internet de un servidor de nombres que el resolvedor debe consultar, ya sea una dirección IPv4 (en notación de puntos) o una dirección IPv6 en notación de dos puntos (y posiblemente puntos) según RFC 2373. Se pueden listar hasta MAXNS (actualmente 3, ver <resolv.h>) servidores de nombres, uno por palabra clave. Si hay varios servidores, la biblioteca del resolvedor los consulta en el orden en que se listan. Si no hay entradas nameserver, el valor predeterminado es usar el servidor de nombres en la máquina local. (El algoritmo utilizado es probar un servidor de nombres y, si la consulta caduca, probar el siguiente, hasta agotar los servidores de nombres, y luego repetir intentando con todos los servidores de nombres hasta que se realice un número máximo de reintentos).
search Lista de búsqueda para la consulta del nombre de host.
Por defecto, la lista de búsqueda contiene una entrada, el nombre de dominio local. Se determina a partir del nombre de host local devuelto por gethostname(2); el nombre de dominio local se considera todo lo que sigue al primer '.'. Finalmente, si el nombre de host no contiene un '.', se asume el dominio raíz como el nombre de dominio local.
Esto se puede cambiar listando la ruta de búsqueda de dominio deseada después de la palabra clave search, separando los nombres con espacios o tabulaciones. Las consultas del resolvedor que tengan menos de ndots puntos (el valor predeterminado es 1) se intentarán usando cada componente de la ruta de búsqueda sucesivamente hasta que se encuentre una coincidencia. Para entornos con múltiples subdominios, lea la opción options ndots:n a continuación para evitar ataques de "man-in-the-middle" y tráfico innecesario para los servidores DNS raíz. Tenga en cuenta que este proceso puede ser lento y generará mucho tráfico de red si los servidores de los dominios listados no son locales, y que las consultas caducarán si no hay un servidor disponible para uno de los dominios.
Si hay múltiples directivas search, solo se utilizará la lista de búsqueda de la última instancia.
En glibc 2.25 y anteriores, la lista de búsqueda se limita a seis dominios con un total de 256 caracteres. Desde glibc 2.26, la lista de búsqueda es ilimitada.
La directiva domain es un nombre obsoleto para la directiva search que maneja solo una entrada de la lista de búsqueda.
sortlist
Esta opción permite ordenar las direcciones devueltas por gethostbyname(3). Una lista de ordenación se especifica mediante pares de dirección IP-máscara de red. La máscara de red es opcional y, por defecto, es la máscara de red natural de la red. La dirección IP y los pares de red opcionales se separan por barras. Se pueden especificar hasta 10 pares. Aquí hay un ejemplo:

sortlist 130.155.160.0/255.255.240.0 130.155.0.0
options
Las opciones permiten modificar ciertas variables internas del resolvedor. La sintaxis es
options opción ...

donde opción es una de las siguientes:

debug
Establece RES_DEBUG en _res.options (efectivo solo si glibc se compiló con soporte de depuración; ver resolver(3)).
ndots:n
Establece un umbral para el número de puntos que deben aparecer en un nombre dado a res_query(3) (ver resolver(3)) antes de que se realice una consulta absoluta inicial. El valor predeterminado para n es 1, lo que significa que si hay algún punto en un nombre, se probará primero el nombre como un nombre absoluto antes de que se le añadan elementos de la lista de búsqueda. El valor de esta opción se limita silenciosamente a 15.
timeout:n
Establece el tiempo que el resolvedor esperará una respuesta de un servidor de nombres remoto antes de reintentar la consulta a través de un servidor de nombres diferente. Esto no puede ser el tiempo total tomado por ninguna llamada a la API del resolvedor y no hay garantía de que una única llamada a la API del resolvedor se corresponda con un único tiempo de espera. Medido en segundos, el valor predeterminado es RES_TIMEOUT (actualmente 5, ver <resolv.h>). El valor de esta opción se limita silenciosamente a 30.
attempts:n
Establece el número de veces que el resolvedor enviará una consulta a sus servidores de nombres antes de rendirse y devolver un error a la aplicación que llama. El valor predeterminado es RES_DFLRETRY (actualmente 2, ver <resolv.h>). El valor de esta opción se limita silenciosamente a 5.
rotate
Establece RES_ROTATE en _res.options, lo que provoca una selección de servidores de nombres en orden circular entre los listados. Esto tiene el efecto de distribuir la carga de consultas entre todos los servidores listados, en lugar de que todos los clientes prueben primero el primer servidor listado cada vez.
no-aaaa (desde glibc 2.36)
Establece RES_NOAAAA en _res.options, lo que suprime las consultas AAAA realizadas por el resolvedor stub, incluidas las consultas AAAA activadas por interfaces basadas en NSS como getaddrinfo(3). Solo se ven afectadas las consultas DNS: los datos IPv6 en hosts(5) todavía se utilizan, getaddrinfo(3) con AI_PASSIVE todavía producirá direcciones IPv6, y los servidores de nombres IPv6 configurados todavía se utilizan. Para producir resultados correctos de Error de Nombre (NXDOMAIN), las consultas AAAA se traducen a consultas A. Esta opción está destinada principalmente a fines de diagnóstico, para descartar que las consultas DNS AAAA tengan un impacto adverso. Es incompatible con el uso de EDNS0 y la validación de DNSSEC por parte de las aplicaciones.
no-check-names
Establece RES_NOCHECKNAME en _res.options, lo que deshabilita la comprobación moderna de BIND de los nombres de host y nombres de correo entrantes en busca de caracteres inválidos como el guion bajo (_), caracteres no ASCII o caracteres de control.
inet6
Establece RES_USE_INET6 en _res.options. Esto tiene el efecto de probar una consulta AAAA antes que una consulta A dentro de la función gethostbyname(3), y de mapear respuestas IPv4 en la forma "tuneled" de IPv6 si no se encuentran registros AAAA pero existe un conjunto de registros A. Desde glibc 2.25, esta opción está obsoleta; las aplicaciones deben usar getaddrinfo(3), en lugar de gethostbyname(3).
ip6-bytestring (desde glibc 2.3.4 hasta glibc 2.24)
Establece RES_USEBSTRING en _res.options. Esto hace que las consultas inversas de IPv6 se realicen utilizando el formato de etiqueta de bits descrito en RFC 2673; si esta opción no está establecida (que es el valor predeterminado), entonces se utiliza el formato de nibble. Esta opción se eliminó en glibc 2.25, ya que dependía de una extensión DNS incompatible hacia atrás que nunca se desplegó en Internet.
ip6-dotint/no-ip6-dotint
Establece RES_USE_DOTTINT o ~RES_USE_DOTTINT en _res.options. Esto controla el formato de las consultas inversas de IPv6. El formato predeterminado es el formato de nibble (inverso), donde cada dígito de la dirección IP se convierte en una etiqueta DNS separada. Si se establece ip6-dotint, se utilizará el formato de dominio de Internet (dot-int) descrito en RFC 1886.
no-tld-query (desde glibc 2.25)
Establece RES_NOTLDQUERY en _res.options. Esto deshabilita las consultas de TLD (Top-Level Domain) que se generan si la consulta de un nombre de host sin puntos no se puede resolver. Sin esta opción, el resolvedor intentará resolver el nombre como un TLD, lo que puede generar tráfico innecesario hacia los servidores raíz.
trust-ad (desde glibc 2.17)
Establece RES_TRUSTAD en _res.options. El bit AD (Authenticated Data) se devolverá en las respuestas DNS para indicar que los datos han sido autenticados por el servidor DNS. Esto se utiliza a menudo con DNSSEC. Si el servidor DNS no admite la autenticación de datos o no puede autenticar los datos, el bit AD se establecerá de forma predeterminada. Esta opción intenta instruir al resolvedor para que considere los datos de DNS como confiables solo si el bit AD está configurado.

CONJUGACIÓN

Cada línea del archivo /etc/resolv.conf consta de un campo de palabra clave seguido de campos de argumento. Las líneas que comienzan con un carácter de almohadilla (#) o un punto y coma (;) son comentarios. Las líneas vacías también se ignoran.

Las palabras clave son sensibles a mayúsculas y minúsculas. Las siguientes palabras clave se reconocen:

nameserver
El argumento es una dirección IP. La palabra clave puede repetirse.
search
El argumento es el nombre de un dominio. La palabra clave puede repetirse.
domain
El argumento es el nombre de un dominio. La palabra clave puede repetirse.
options
El argumento es una opción de palabras clave o un nombre de dominio.
sortlist
El argumento es una dirección IP con una máscara de red opcional.

La palabra clave domain se utiliza para especificar el dominio local. Si no se especifica un dominio, el sistema intenta determinarlo a partir del nombre de host. La palabra clave search se utiliza para especificar una lista de dominios en los que buscar nombres de host.

La palabra clave options se utiliza para especificar varias opciones del resolvedor. Las opciones disponibles son:

debug
Habilita el modo de depuración.
ndots:n
Establece el número de puntos que deben estar presentes en un nombre antes de que se intente una consulta absoluta.
timeout:n
Establece el tiempo de espera para las respuestas de los servidores de nombres.
attempts:n
Establece el número de intentos de consulta antes de abandonar.
rotate
Permite la rotación de servidores de nombres.
no-aaaa
Suprime las consultas AAAA.
no-check-names
Deshabilita la verificación de nombres no válidos.
inet6
Intenta consultas AAAA antes que A.
ip6-bytestring
Utiliza el formato de etiqueta de bytes para consultas inversas de IPv6.
ip6-dotint
Utiliza el formato dot-int para consultas inversas de IPv6.
no-ip6-dotint
No utiliza el formato dot-int para consultas inversas de IPv6.
no-tld-query
Deshabilita las consultas de TLD.
trust-ad
Confía en los datos autenticados por DNSSEC.

VÉASE TAMBIÉN

gethostbyname(3), getaddrinfo(3), resolver(3), hosts(5), hostname(7), systemd-resolved.service(8)

OPTIONS

The following options are recognized in the options keyword of /etc/resolv.conf file.

ip6-dotint (glibc 2.3.4 a glibc 2.24)
Borra/establece RES_NOIP6DOTINT en _res.options. Cuando esta opción está desactivada (ip6-dotint), las búsquedas inversas de IPv6 se realizan en la zona (obsoleta) ip6.int; cuando esta opción está activada (no-ip6-dotint), las búsquedas inversas de IPv6 se realizan en la zona ip6.arpa por defecto. Estas opciones están disponibles hasta glibc 2.24, donde no-ip6-dotint es el valor por defecto. Dado que el soporte de ip6-dotint dejó de estar disponible en Internet hace mucho tiempo, estas opciones se eliminaron en glibc 2.25.
edns0 (desde glibc 2.6)
Establece RES_USE_EDNS0 en _res.options. Esto habilita el soporte para las extensiones de DNS descritas en la RFC 2671.
single-request (desde glibc 2.10)
Establece RES_SNGLKUP en _res.options. Por defecto, glibc realiza búsquedas de IPv4 e IPv6 en paralelo desde glibc 2.9. Algunos servidores DNS de aparatos no pueden manejar estas consultas correctamente y hacen que las solicitudes caduquen. Esta opción deshabilita el comportamiento y hace que glibc realice las solicitudes IPv6 e IPv4 secuencialmente (a costa de una ralentización del proceso de resolución).
single-request-reopen (desde glibc 2.9)
Establece RES_SNGLKUPREOP en _res.options. El resolvedor utiliza el mismo socket para las solicitudes A y AAAA. Algunos hardwares envían erróneamente solo una respuesta. Cuando eso sucede, el sistema cliente se queda esperando la segunda respuesta. Activar esta opción cambia este comportamiento de modo que si dos solicitudes desde el mismo puerto no se manejan correctamente, se cerrará el socket y se abrirá uno nuevo antes de enviar la segunda solicitud.
no-tld-query (desde glibc 2.14)
Establece RES_NOTLDQUERY en _res.options. Esta opción hace que res_nsearch() no intente resolver un nombre no cualificado como si fuera un dominio de nivel superior (TLD). Esta opción puede causar problemas si el sitio tiene "localhost" como TLD en lugar de tener localhost en uno o más elementos de la lista de búsqueda. Esta opción no tiene efecto si ni RES_DEFNAMES ni RES_DNSRCH están establecidos.
use-vc (desde glibc 2.14)
Establece RES_USEVC en _res.options. Esta opción fuerza el uso de TCP para las resoluciones DNS.
no-reload (desde glibc 2.26)
Establece RES_NORELOAD en _res.options. Esta opción deshabilita la recarga automática de un archivo de configuración modificado.
trust-ad (desde glibc 2.31)
Establece RES_TRUSTAD en _res.options. Esta opción controla el comportamiento del bit AD del resolvedor stub. Si un resolvedor que valida establece el bit AD en una respuesta, indica que los datos de la respuesta fueron verificados de acuerdo con el protocolo DNSSEC. Para confiar en el bit AD, el sistema local debe confiar tanto en el resolvedor que valida DNSSEC como en la ruta de red hacia él, razón por la cual se requiere una activación explícita. Si la opción trust-ad está activa, el resolvedor stub establece el bit AD en las consultas salientes (para habilitar el soporte del bit AD), y preserva el bit AD en las respuestas. Sin esta opción, el bit AD no se establece en las consultas, y siempre se elimina de las respuestas antes de que se devuelvan a la aplicación. Esto significa que las aplicaciones pueden confiar en el bit AD en las respuestas si la opción trust-ad se ha establecido correctamente.
En glibc 2.30 y anteriores, el AD no se establece automáticamente en las consultas y se pasa sin cambios a las aplicaciones en las respuestas.

La palabra clave search del archivo resolv.conf de un sistema puede ser anulada a nivel de proceso estableciendo la variable de entorno LOCALDOMAIN a una lista de dominios de búsqueda separados por espacios.

La palabra clave options del archivo resolv.conf de un sistema puede ser modificada a nivel de proceso estableciendo la variable de entorno RES_OPTIONS a una lista de opciones del resolvedor separadas por espacios, como se explica anteriormente en options.

La palabra clave y el valor deben aparecer en una sola línea, y la palabra clave (por ejemplo, nameserver) debe comenzar la línea. El valor sigue a la palabra clave, separado por espacios en blanco.

Las líneas que contienen un punto y coma (;) o un carácter de almohadilla (#) en la primera columna se tratan como comentarios.
