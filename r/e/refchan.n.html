NAME

refchan - command handler API of reflected channels

SYNOPSIS

cmdPrefix option ?arg arg ...?

DESCRIPTION

El manejador a nivel de Tcl para un canal reflejado debe ser un comando con subcomandos (denominado un conjunto, ya que es un comando tal como el creado por namespace ensemble create, aunque la implementación de manejadores para canales reflejados no está ligada a namespace ensemble de ninguna manera; véase EJEMPLO más abajo para saber cómo construir una oo::class que soporte la API). Tenga en cuenta que cmdPrefix es lo que se especificó en la llamada a chan create, y puede constar de varios argumentos; esto se expandirá a varias palabras en lugar del prefijo.

De todos los subcomandos posibles, el manejador debe soportar initialize, finalize y watch. El soporte para los otros subcomandos es opcional.

SUBCOMANDOS OBLIGATORIOS

cmdPrefix initialize channelId modo
Una invocación de este subcomando será la primera llamada que el cmdPrefix recibirá para el nuevo channelId especificado. Es responsabilidad de este subcomando configurar las estructuras de datos internas necesarias para rastrear el canal y su estado.

El valor de retorno del método tiene que ser una lista que contenga los nombres de todos los subcomandos soportados por el cmdPrefix. Esto también le dice al núcleo de Tcl qué versión de la API para canales reflejados está utilizando este manejador de comandos.

Cualquier error lanzado por el método abortará la creación del canal y no se creará ningún canal. El error lanzado aparecerá como un error lanzado por chan create. Cualquier excepción que no sea un error (por ejemplo, break, etc.) se trata como (y se convierte en) un error.

Nota: Si la creación del canal se abortó debido a fallos aquí, entonces el subcomando finalize no se llamará.

El argumento modo le indica al manejador si el canal se abrió para lectura, escritura o ambos. Es una lista que contiene cualquiera de las cadenas read o write. La lista puede estar vacía, pero generalmente contendrá al menos un elemento.

El subcomando debe lanzar un error si el modo elegido no es soportado por el cmdPrefix.

cmdPrefix finalize channelId
Una invocación de este subcomando será la última llamada que el cmdPrefix recibirá para el channelId especificado. Se generará justo antes de la destrucción de las estructuras de datos del canal mantenidas por el núcleo de Tcl. El manejador de comandos no debe acceder al channelId de ninguna manera. Al ser invocado este subcomando, se deben limpiar todos los recursos internos asignados a este canal.

El valor de retorno de este subcomando se ignora.

Si el subcomando lanza un error, el comando que causó su invocación (generalmente chan close) parecerá haber lanzado este error. Cualquier excepción que no sea un error (por ejemplo, break, etc.) se trata como (y se convierte en) un error.

Este subcomando no se invoca si la creación del canal se abortó durante initialize (Véase arriba).

cmdPrefix watch channelId eventspec
Este subcomando notifica al cmdPrefix que el channelId especificado está interesado en los eventos listados en el eventspec. Este argumento es una lista que contiene read y/o write. La lista puede estar vacía, lo que indica que el canal no desea ser notificado de ningún evento. En esa situación, el manejador debería deshabilitar la generación de eventos completamente.

Advertencia: Se ignora cualquier valor de retorno del subcomando. Esto incluye todos los errores lanzados por el subcomando, break, continue y códigos de retorno personalizados.

Este subcomando interactúa con chan postevent. Intentar publicar un evento que no estaba listado en la última llamada a watch hará que chan postevent lance un error.

SUBCOMANDOS OPCIONALES

cmdPrefix read channelId count
Este subcomando opcional se llama cuando el usuario solicita datos del canal channelId. count especifica cuántos bytes se han solicitado. Si el subcomando no es soportado, entonces no es posible leer del canal manejado por el comando.

El valor de retorno de este subcomando se toma como los datos bytes solicitados. Si los datos devueltos contienen más bytes de los solicitados, se señalará un error y será lanzado posteriormente por el comando que realizó la lectura (generalmente gets o read). Sin embargo, devolver menos bytes de los solicitados es aceptable.

Tenga en cuenta que devolver nada (0 bytes) es una señal a las capas superiores de que se ha alcanzado el EOF en el canal. Para indicar que el canal no tiene datos en este momento, pero aún no ha alcanzado el EOF, es necesario lanzar el error "EAGAIN", es decir, o bien

return -code error EAGAIN
o 
error EAGAIN

Para extensibilidad, cualquier error cuyo valor sea un número entero negativo hará que las capas superiores establezcan la variable de nivel C "errno" al valor absoluto de este número, señalando un error del sistema. Sin embargo, tenga en cuenta que la correspondencia exacta entre estos números de error y sus significados depende del sistema operativo.

Por ejemplo, mientras que en Linux tanto

return -code error -11
y 
error -11

son equivalentes a los ejemplos anteriores, usando la cadena más legible "EAGAIN", esto no es cierto para BSD, donde el número equivalente es -35.

Sin embargo, la cadena simbólica es la misma en todos los sistemas y se traduce internamente al número correcto. Ningún otro valor de error tiene tal correspondencia con una cadena simbólica.

Si el subcomando lanza cualquier otro error, el comando que causó su invocación (generalmente gets o read) parecerá haber lanzado este error. Cualquier excepción que no sea un error (por ejemplo, break, etc.) se trata y se convierte en un error.

cmdPrefix write channelId data
Este subcomando opcional se llama cuando el usuario escribe datos en el canal channelId. El argumento data contiene bytes, no caracteres. Cualquier tipo de transformación (EOL, codificación) configurada para el canal ya se ha aplicado en este punto. Si este subcomando no es soportado, entonces no es posible escribir en el canal manejado por el comando.

El valor de retorno del subcomando se toma como el número de bytes escritos por el canal. Cualquier cosa no numérica causará que se señale un error y será lanzado posteriormente por el comando que realizó la escritura. Un valor negativo implica que la escritura falló. Devolver un valor mayor que el número de bytes dados al manejador, o cero, está prohibido y hará que el núcleo de Tcl lance un error.

Para indicar que el canal no puede aceptar datos para escritura en este momento, es necesario lanzar el error "EAGAIN", es decir, o bien

return -code error EAGAIN
o 
error EAGAIN

Para extensibilidad, cualquier error cuyo valor sea un número entero negativo hará que las capas superiores establezcan la variable de nivel C "errno" al valor absoluto de este número, señalando un error del sistema. Sin embargo, tenga en cuenta que la correspondencia exacta entre estos números de error y sus significados depende del sistema operativo.

Por ejemplo, mientras que en Linux tanto

return -code error -11
y 
error -11

son equivalentes a los ejemplos anteriores, usando la cadena más legible "EAGAIN", esto no es cierto para BS

NAME

refchan – build Tcl channels from Tcl code

SYNOPSIS

package require Tcl
namespace import ::tcl::chan::*
chan prefix ?cmdPrefix?
chan create ?options? ?commandPrefix? ?channelId?

DESCRIPTION

The refchan package provides a facility to create Tcl channels from Tcl code. This is useful for implementing channel drivers in Tcl itself, e.g. for custom protocols or virtual file systems.

The core of the facility is the chan create command. It takes a channel command prefix, and optionally a list of methods to implement, and returns a channel id. The methods are invoked by the Tcl channel core when operations are performed on the channel.

The command prefix specified via chan prefix is used as the command name for the Tcl commands which are created to handle the channel operations. The default prefix is ::tcl::channel::.

cmdPrefix
The chan prefix command sets or returns the command prefix used for channel access commands. If cmdPrefix is given, it is set as the new prefix. The default prefix is ::tcl::channel::.

The command chan create is the main entry point for creating channels. It takes a list of channel operations to be implemented, and the command prefix for the commands that implement them. The commandPrefix is the base name for the commands that implement the operations. For instance, if the prefix is ::tcl::channel:: and the command is chan create read [::tcl::channel myproto], then the read operation is implemented by the command ::tcl::channel::myproto\ read.

cmdPrefix create ?options? commandPrefix ?channelId?
Creates a new channel implementing the operations specified by the commandPrefix. The commandPrefix is the name of a Tcl command which is expected to implement the methods required for the channel operations. The methods are invoked as <commandPrefix> <operation> .... Currently supported operations are:
initialize channelId mode
Called when the channel is created. The channelId is the channel identifier of the new channel. The mode is a string indicating the mode the channel is opened in (e.g. "read", "write", "read write"). The method should return a string of space-separated keywords, indicating which operations are supported by the channel. See the documentation of the methods below for the exact list of keywords.
finalize channelId
Called when the channel is closed or destroyed. It is the place to clean up any resources associated with the channel.
watch channelId events
Called when the channel is being registered with the Tcl event loop. The events argument is a string of space separated keywords indicating the events the channel is interested in (e.g. "read", "write"). The method should setup the necessary event handlers and return a string of space separated keywords, indicating the events it will actually signal. This method is optional, and if not provided, the channel is assumed not to support events.
read channelId count
Called when data is requested from the channel. The channelId is the channel identifier. The count argument is the maximum number of bytes to read. The method should return the data read, or an empty string if the channel has reached end-of-file. If the method throws an error, the command that caused its invocation (usually read) will appear to have thrown this error. Any exception beyond error (e.g., break, etc.) is treated as and converted to an error.
write channelId data
Called when data is to be written to the channel. The channelId is the channel identifier. The data argument is the data to be written. The method should return the number of bytes actually written. If the method throws an error, the command that caused its invocation (usually puts or write) will appear to have thrown this error. Any exception beyond error (e.g., break, etc.) is treated as and converted to an error.
seek channelId offset base
This optional subcommand is responsible for the handling of chan seek and chan tell requests on the channel channelId. If it is not supported then seeking will not be possible for the channel.
The base argument is the same as the equivalent argument of the builtin chan seek, namely:
start
Seeking is relative to the beginning of the channel.
current
Seeking is relative to the current seek position.
end
Seeking is relative to the end of the channel.
The offset is an integer number specifying the amount of bytes to seek forward or backward. A positive number should seek forward, and a negative number should seek backward. A channel may provide only limited seeking. For example sockets can seek forward, but not backward. The return value of the subcommand is taken as the (new) location of the channel, counted from the start. This has to be an integer number greater than or equal to zero. If the subcommand throws an error the command which caused its invocation (usually chan seek, or chan tell) will appear to have thrown this error. Any exception beyond error (e.g., break, etc.) is treated as and converted to an error. The offset/base combination of 0/current signals a chan tell request, i.e., seek nothing relative to the current location, making the new location identical to the current one, which is then returned.
cmdPrefix configure channelId option value
This optional subcommand is for setting the type-specific options of channel channelId. The option argument indicates the option to be written, and the value argument indicates the value to set the option to.
This subcommand will never try to update more than one option at a time; that is behavior implemented in the Tcl channel core. The return value of the subcommand is ignored. If the subcommand throws an error the command which performed the (re)configuration or query (usually fconfigure or chan configure) will appear to have thrown this error. Any exception beyond error (e.g., break, etc.) is treated as and converted to an error.
cmdPrefix cget channelId option
This optional subcommand is used when reading a single type-specific option of channel channelId. If this subcommand is supported then the subcommand cgetall must be supported as well.
The subcommand should return the value of the specified option. If the subcommand throws an error, the command which performed the (re)configuration or query (usually fconfigure or chan configure) will appear to have thrown this error. Any exception beyond error (e.g., break, etc.) is treated as and converted to an error.
cmdPrefix cgetall channelId
This optional subcommand is used for reading all type-specific options of channel channelId. If this subcommand is supported then the subcommand cget has to be supported as well.
The subcommand should return a list of all options and their values. This list must have an even number of elements. If the subcommand throws an error the command which performed the (re)configuration or query (usually fconfigure or chan configure) will appear to have thrown this error. Any exception beyond error (e.g., break, etc.) is treated as and converted to an error.
cmdPrefix blocking channelId mode
This optional subcommand handles changes to the blocking mode of the channel channelId. The mode is a boolean flag. A true value means that the channel has to be set to blocking, and a false value means that the channel should be non-blocking.
The return value of the subcommand is ignored. If the subcommand throws an error the command which caused its invocation (usually fconfigure or chan configure) will appear to have thrown this error. Any exception beyond error (e.g., break, etc.) is treated as and converted to an error.

If the subcommand throws any other error the command which caused its invocation (usually puts) will appear to have thrown this error. Any exception beyond error (e.g., break, etc.) is treated as and converted to an error.

NOTES

Some of the functions supported in channels defined in Tcl's C interface are not available to channels reflected to the Tcl level.

The function Tcl_DriverGetHandleProc is not supported; i.e., reflected channels do not have OS specific handles.

The function Tcl_DriverHandlerProc is not supported. This driver function is relevant only for stacked channels, i.e., transformations. Reflected channels are always base channels, not transformations.

The function Tcl_DriverFlushProc is not supported. This is because the current generic I/O layer of Tcl does not use this function anywhere at all. Therefore support at the Tcl level makes no sense either. This may be altered in the future (through extending the API defined here and changing its version number) should the function be used at some time in the future.

EXAMPLE

This demonstrates how to make a channel that reads from a string.

oo::class create stringchan {
    variable data pos
    constructor {string {encoding {}}} {
        if {$encoding eq ""} {set encoding [encoding system]}
        set data [encoding convertto $encoding $string]
        set pos 0
    }
    method initialize {ch mode} {
        return "initialize finalize watch read seek"
    }
    method finalize {ch} {
        my destroy
    }
    method watch {ch events} {
        # Must be present but we ignore it because we do not
        # post any events
    }
    # Must be present on a readable channel
    method read {ch count} {
        set d [string range $data $pos [expr {$pos+$count-1}]]
        incr pos [string length $d]
        return $d
    }
    # This method is optional, but useful for the example below
    method seek {ch offset base} {
        switch $base {
            start {
                set pos $offset
            }
            current {
                incr pos $offset
            }
            end {
                set pos [string length $data]
                incr pos $offset
            }
        }
        if {$pos < 0} {
            set pos 0
        } elseif {$pos > [string length $data]} {
            set pos [string length $data]
        }
        return $pos
    }
}
# Now we create an instance...
set string "The quick brown fox jumps over the lazy dog.\n"
set ch [chan create read [stringchan new $string]]
puts [gets $ch];   # Prints the whole string
seek $ch -5 end;
puts [read $ch];   # Prints just the last word
