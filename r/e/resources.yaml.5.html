NOMBRE

resources.yaml - Archivo de configuración de Slurm para Recursos Jerárquicos (HRES).

DESCRIPCIÓN

resources.yaml es un archivo de configuración con formato YAML que define los Recursos Jerárquicos (HRES). El archivo debe estar ubicado en el mismo directorio que slurm.conf. Cualquier texto que siga a un carácter "#" en este archivo se trata como un comentario hasta el final de esa línea.

Hay más detalles disponibles en la página de Planificación de Recursos Jerárquicos (HRES): https://slurm.schedmd.com/hres.html

PARÁMETROS

Cada definición de Recursos Jerárquicos es un objeto YAML que contiene los siguientes atributos:

recurso
El nombre único para el recurso. Este nombre será utilizado para identificarlo por slurmctld. Este debe ser el primer atributo del objeto.
modo
El modo de planificación para el recurso. Debe ser uno de los siguientes:
MODO_1
Se requieren recursos suficientes en solo una capa que se solape con los nodos asignados del trabajo.
MODO_2
Los recursos suficientes deben estar disponibles en todas las capas que se solapen con los nodos asignados del trabajo.
MODO_3
Los recursos se asignan por nodo. El planificador calcula el consumo total de la capa más granular y lo suma a las capas sucesivamente superiores, asegurando que el conteo no se exceda en ninguna capa. Este modo está diseñado para recursos consumibles como la energía y puede mapearse a una topología de bloques utilizando el parámetro topología.
topología
(Opcional) Especifica el nombre de una definición de topology/block para mapear a este recurso. Este parámetro solo es válido para recursos MODE_3. Las capas HRes deben tener el mismo diseño que la topología de bloques especificada. Esto permite al planificador optimizar simultáneamente las asignaciones de HRes y de topología de bloques.
variables
(Opcional) Una lista de pares nombre/valor que mapean cadenas de texto arbitrarias a recuentos de recursos definidos administrativamente. Los usuarios pueden entonces usar estas cadenas en envíos de trabajos (por ejemplo, --resources=power:full_node) en lugar de un valor numérico. Cada entrada en la lista contiene:
nombre
El alias de cadena para el valor (por ejemplo, "full_node").
valor
El recuento numérico del recurso (por ejemplo, 1000).
capas
Una lista de capas que definen la jerarquía de recursos. Cada capa es un objeto YAML que contiene:
nodos
Una lista de nombres de nodo o expresiones de lista de hosts que forman parte de esta capa.
conteo
El número total de recursos disponibles en esta capa específica.
base
(Opcional) Una lista de pares nombre/valor que describen el consumo de recursos no relacionado con el trabajo (estático) en esta capa. Esto es particularmente relevante para MODE_3. Cada entrada contiene:
nombre
El nombre del consumidor de recursos estático (por ejemplo, "storage", "network1").
valor
El recuento numérico de recursos que utiliza este consumidor.

EJEMPLO

---
- recurso: plano
  modo: MODO_2
  capas:
    - nodos:			# nivel más alto
        - "nodo[01-32]"
      conteo: 24
    - nodos:			# niveles medios
        - "nodo[01-16]"
      conteo: 16
    - nodos:
        - "nodo[17-32]"
      conteo: 16
    - nodos:			# niveles más bajos
        - "nodo[01-08]"
      conteo: 12
    - nodos:
        - "nodo[09-16]"
      conteo: 12
    - nodos:
        - "nodo[17-24]"
      conteo: 12
    - nodos:
        - "nodo[25-32]"
      conteo: 12
- recurso: natural
  modo: MODO_1
  capas:
    - nodos:			# nivel más alto
        - "nodo[01-32]"
      conteo: 50
    - nodos:			# niveles más bajos
        - "nodo[01-16]"
      conteo: 100
    - nodos:
        - "nodo[17-32]"
      conteo: 100
- recurso: energia
  modo: MODO_3
  topologia: blok1
  variables:
    - nombre: nodo_completo
      valor: 1000
    - nombre: nodo_gpu_completo
      valor: 2000
  capas:
    - nodos:
        - "nodo[01-32]"
      conteo: 130000
      base:
        - nombre: unidad_ac1
          valor: 10000
        - nombre: unidad_ac2
          valor: 8000
    - nodos:
        - "nodo[01-16]"
      conteo: 60000
      base:
        - nombre: red1
          valor: 3000
    - nodos:
        - "nodo[17-32]"
      conteo: 80000
      base:
        - nombre: red2
          valor: 2000
    - nodos:
        - "nodo[01-08]"
      conteo: 40000
      base:
        - nombre: almacenamiento
          valor: 5000
    - nodos:
        - "nodo[09-16]"
      conteo: 40000
    - nodos:
        - "nodo[17-24]"
      conteo: 40000
    - nodos:
        - "nodo[25-32]"
      conteo: 40000
