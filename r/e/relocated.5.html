RELOCATED(5) Manual de formatos de archivo RELOCATED(5)

NOMBRE

relocated - formato de tabla relocated de Postfix

SINOPSIS

postmap /etc/postfix/relocated

DESCRIPCIÓN


La tabla opcional relocated(5) proporciona la información que se utiliza en los mensajes de rebote de "el usuario se ha mudado a nueva_ubicación".

Normalmente, la tabla relocated(5) se especifica como un archivo de texto que sirve como entrada para el comando postmap(1). El resultado, un archivo indexado en formato dbm o db, se utiliza para búsquedas rápidas por el sistema de correo. Ejecute el comando "postmap /etc/postfix/relocated" para reconstruir un archivo indexado después de cambiar la tabla relocated correspondiente.

Cuando la tabla se proporciona a través de otros medios como NIS, LDAP o SQL, las mismas búsquedas se realizan que para los archivos indexados ordinarios.

Alternativamente, la tabla puede proporcionarse como un mapa de expresiones regulares donde los patrones se dan como expresiones regulares, o las búsquedas pueden dirigirse a un servidor basado en TCP. En esos casos, las búsquedas se realizan de una manera ligeramente diferente como se describe a continuación en "TABLAS DE EXPRESIONES REGULARES" o "TABLAS BASADAS EN TCP".

Las búsquedas en la tabla no distinguen entre mayúsculas y minúsculas.

CONVERSIÓN A MINÚSCULAS

La cadena de búsqueda se convierte a minúsculas antes de la búsqueda en la base de datos. A partir de Postfix 2.3, la cadena de búsqueda no se convierte a minúsculas con tipos de base de datos como regexp: o pcre: cuyos campos de búsqueda pueden coincidir tanto con mayúsculas como con minúsculas.

FORMATO DE TABLA

El formato de entrada para el comando postmap(1) es el siguiente:

  • Una entrada tiene una de las siguientes formas: 
         patrón      nueva_ubicación

    Donde nueva_ubicación especifica información de contacto como una dirección de correo electrónico, o quizás una dirección postal o un número de teléfono.

  • Se ignoran las líneas vacías y las líneas que solo contienen espacios en blanco, al igual que las líneas cuyo primer carácter que no es un espacio en blanco es un `#'.
  • Una línea lógica comienza con texto que no es espacio en blanco. Una línea que comienza con espacio en blanco continúa una línea lógica.

ORDEN DE BÚSQUEDA EN LA TABLA

Con búsquedas de archivos indexados como DB o DBM, o de tablas en red como NIS, LDAP o SQL, los patrones se prueban en el orden que se indica a continuación:

usuario@dominio
Coincide con usuario@dominio. Esta forma tiene precedencia sobre todas las demás formas.
usuario
Coincide con usuario@sitio cuando sitio es $myorigin, cuando sitio está listado en $mydestination, o cuando sitio está listado en $inet_interfaces o $proxy_interfaces.
@dominio
Coincide con otras direcciones en dominio. Esta forma tiene la menor precedencia.

EXTENSIÓN DE DIRECCIÓN

Cuando la parte local de una dirección de correo contiene el delimitador de destinatario opcional (por ejemplo, usuario+foo@dominio), el orden de búsqueda es: usuario+foo@dominio, usuario@dominio, usuario+foo, usuario, y @dominio.

TABLAS DE EXPRESIONES REGULARES

Esta sección describe cómo cambian las búsquedas en la tabla cuando la tabla se proporciona en forma de expresiones regulares o cuando las búsquedas se dirigen a un servidor basado en TCP. Para una descripción de la sintaxis de la tabla de búsqueda de expresiones regulares, consulte regexp_table(5) o pcre_table(5). Para una descripción del protocolo de búsqueda de cliente/servidor TCP, consulte tcp_table(5). Esta característica está disponible en Postfix 2.5 y posteriores.

Cada patrón es una expresión regular que se aplica a la dirección completa que se está buscando. Por lo tanto, las direcciones de correo usuario@dominio no se dividen en sus partes constituyentes usuario y @dominio, ni se divide usuario+foo en usuario y foo.

Los patrones se aplican en el orden especificado en la tabla, hasta que se encuentra un patrón que coincide con la cadena de búsqueda.

Los resultados son los mismos que con las búsquedas en archivos indexados, con la característica adicional de que las subcadenas entre paréntesis del patrón pueden interpolarse como $1, $2 y así sucesivamente.

TABLAS BASADAS EN TCP

Esta sección describe cómo cambian las búsquedas en la tabla cuando las búsquedas se dirigen a un servidor basado en TCP. Para una descripción del protocolo de búsqueda de cliente/servidor TCP, consulte tcp_table(5). Esta característica está disponible en Postfix 2.5 y posteriores.

Cada operación de búsqueda utiliza la dirección completa una vez. Por lo tanto, las direcciones de correo usuario@dominio no se dividen en sus partes constituyentes usuario y @dominio, ni se divide usuario+foo en usuario y foo.

Los resultados son los mismos que con las búsquedas en archivos indexados.

ERRORES


El formato de la tabla no entiende las convenciones de comillas.

PARÁMETROS DE CONFIGURACIÓN

Los siguientes parámetros de main.cf son especialmente relevantes. El texto a continuación proporciona solo un resumen de los parámetros. Consulte postconf(5) para más detalles, incluidos ejemplos.

relocated_maps (vacío)
Tablas de búsqueda opcionales con nueva información de contacto para usuarios o dominios que ya no existen.

Otros parámetros de interés:

inet_interfaces (all)
Las direcciones de interfaz de red local en las que este sistema de correo recibe correo.
mydestination ($myhostname, localhost.$mydomain, localhost)
La lista de dominios a los que se entrega el correo a través del transporte de entrega de correo $local_transport.
myorigin ($myhostname)
El nombre de dominio del que parece proceder el correo enviado localmente, y al que se entrega el correo enviado localmente.
proxy_interfaces (vacío)
Las direcciones de interfaz de red remota en las que este sistema de correo recibe correo a través de una unidad de proxy o traducción de direcciones de red.
