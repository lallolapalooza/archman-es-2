Nombre

refer - procesa referencias bibliográficas para groff

Sintaxis

refer [-bCenPRS] [-a n] [-B campo.macro] [-c campos] [-f n] [-i campos] [-k campo] [-l expresion-rango] [-p archivo-base-de-datos] [-s campos] [-t n] [archivo ...]
refer --help
refer -v
refer --version

Descripción

La implementación GNU de refer forma parte del sistema de formateo de documentos groff(1). refer es un preprocesador de troff(1) que prepara citas bibliográficas buscando palabras clave especificadas en un documento de entrada roff(7), evitando la necesidad de escribir dichas anotaciones y permitiendo que el estilo de cita en la salida formateada se altere de forma independiente y sistemática. Copia el contenido de cada archivo al flujo de salida estándar, excepto que interpreta las líneas entre .[ y .] como citas a traducir a entrada de groff, y las líneas entre .R1 y .R2 como instrucciones sobre cómo se deben procesar las citas. Normalmente, refer no es ejecutado directamente por el usuario, sino invocado especificando la opción -R a groff(1). Si no se proporcionan operandos archivo en la línea de comandos, o si archivo es “-”, se lee el flujo de entrada estándar.

Cada cita especifica una referencia. La cita puede especificar una referencia contenida en una base de datos bibliográfica proporcionando un conjunto de palabras clave que solo esa referencia contiene. Alternativamente, puede especificar una referencia proporcionando un registro de base de datos en la cita. También es posible una combinación de estas alternativas.

Para cada cita, refer puede producir una marca en el texto. Esta marca consiste en una etiqueta que puede separarse del texto y de otras etiquetas de diversas maneras. Para cada referencia, también emite comandos del lenguaje groff(7) que pueden ser utilizados por un paquete de macros para producir una referencia formateada para cada cita. Por lo tanto, la salida de refer debe ser procesada utilizando un paquete de macros adecuado, como me, mm, mom o ms. Los comandos para formatear la referencia de una cita pueden emitirse inmediatamente después de la cita, o las referencias pueden acumularse y los comandos emitirse en un momento posterior. Si las referencias se acumulan, entonces múltiples citas de la misma referencia producirán una única referencia formateada.

La interpretación de las líneas entre .R1 y .R2 como comandos del preprocesador es una característica del refer de GNU. Los documentos que utilizan esta característica aún pueden ser procesados por el refer de AT&T simplemente agregando las líneas

.de R1
.ig R2
..
al principio del documento. Esto hará que troff(1) ignore todo lo que esté entre .R1 y .R2. El efecto de algunos comandos también se puede lograr mediante opciones. Estas opciones se soportan principalmente para compatibilidad con el refer de AT&T. Generalmente es más conveniente usar comandos.

refer genera solicitudes .lf para que los nombres de archivo y los números de línea en los mensajes producidos por los comandos que leen la salida de refer sean correctos; también interpreta líneas que comienzan con .lf para que los nombres de archivo y los números de línea en los mensajes y las líneas .lf que produce sean precisos, incluso si la entrada ha sido preprocesada por un comando como soelim(1).

Bases de datos bibliográficas

La base de datos bibliográfica es un archivo de texto que consta de registros separados por una o más líneas en blanco. Dentro de cada registro, los campos comienzan con un % al principio de una línea. Cada campo tiene un nombre de un solo carácter que sigue inmediatamente al %. Es mejor usar solo letras mayúsculas y minúsculas para los nombres de los campos. El nombre del campo debe ir seguido de exactamente un espacio, y luego por el contenido del campo. Los campos vacíos se ignoran. El significado convencional de cada campo es el siguiente:

%A
El nombre de un autor. Si el nombre contiene un sufijo como “Jr.”, debe separarse del apellido por una coma. Puede haber múltiples ocurrencias del campo %A. El orden es significativo. Es una buena idea suministrar siempre un campo %A o un campo %Q.
%B
Para un artículo que forma parte de un libro, el título del libro.
%C
El lugar (ciudad) de publicación.
%D
La fecha de publicación. El año debe especificarse completo. Si se especifica el mes, se debe usar el nombre en lugar del número del mes, pero solo se requieren las primeras tres letras. Es una buena idea suministrar siempre un campo %D; si la fecha es desconocida, se puede usar un valor como en prensa o desconocido.
%E
Para un artículo que forma parte de un libro, el nombre de un editor del libro. Donde la obra tiene editores y ningún autor, los nombres de los editores deben darse como campos %A y “, (ed.)” o “, (eds.)” debe añadirse al último autor.
%G
Número de orden del gobierno de EE. UU.
%I
El editor (emisor).
%J
Para un artículo en una revista, el nombre de la revista.
%K
Palabras clave a utilizar para la búsqueda.
%L
Etiqueta.
%N
Número de edición de la revista.
%O
Otra información. Esto se imprime normalmente al final de la referencia.
%P
Número de página. Un rango de páginas se puede especificar como m-n.
%Q
El nombre del autor, si el autor no es una persona. Esto solo se usará si no hay campos %A. Solo puede haber un campo %Q.
%R
Número de informe técnico.
%S
Nombre de la serie.
%T
Título. Para un artículo en un libro o revista, este debe ser el título del artículo.
%V
Número de volumen de la revista o libro.
%X
Anotación.

Para todos los campos excepto %A y %E, si hay más de una ocurrencia de un campo particular en un registro, solo se usará el último campo de este tipo.

Si se utilizan cadenas de acentos, deben seguir al carácter a acentuar. Esto significa que un documento ms debe llamar a la macro .AM cuando se inicializa. Las cadenas de acentos no deben ir entre comillas: use un \ en lugar de dos. Las cadenas de acentos son una característica obsoleta de los paquetes de macros me y ms; los documentos modernos deben usar secuencias de escape de caracteres especiales de groff en su lugar; ver groff_char(7).

Citas

Las citas tienen un formato característico.

.[texto-apertura
banderas palabras-clave
campos
.]texto-cierre

Los componentes texto-apertura, texto-cierre y banderas son opcionales. Solo uno de los componentes de palabras-clave y campos debe especificarse.

El componente palabras-clave indica buscar en las bases de datos bibliográficas una referencia que contenga todas las palabras de palabras-clave. Es un error si se encuentra más de una referencia.

El componente campos especifica campos adicionales para reemplazar o complementar los especificados en la referencia. Cuando las referencias se están acumulando y el componente palabras-clave no está vacío, entonces los campos adicionales solo deben especificarse en la primera ocasión en que se cita una referencia particular, y se aplicarán a todas las citas de esa referencia.

El componente flags es una lista de caracteres no alfanuméricos, cada uno de los cuales modifica el tratamiento de esta cita en particular. AT&T refer tratará estas banderas como parte de las palabras clave y, por lo tanto, las ignorará ya que son no alfanuméricas. Las siguientes banderas se reconocen actualmente.

#
Utiliza la etiqueta especificada por el comando short-label, en lugar de la especificada por el comando label. Si no se ha especificado ninguna etiqueta corta, se utilizará la etiqueta normal. Típicamente, la etiqueta corta se usa con etiquetas de autor-fecha y consiste solo en la fecha y posiblemente una letra para desambiguar; el “#” debe ser sugerente de un tipo de etiqueta numérico.
[
Antepone opening-text con la primera cadena especificada en el comando bracket-label.
]
Sigue closing-text con la segunda cadena especificada en el comando bracket-label.

Una ventaja de usar las banderas [ y ] en lugar de incluir los corchetes en opening-text y closing-text es que puedes cambiar el estilo de corchete utilizado en el documento simplemente cambiando el comando bracket-label. Otra ventaja es que la ordenación y fusión de citas no se inhibirá necesariamente si se utilizan las banderas.

Si se va a insertar una etiqueta en el texto, se adjuntará a la línea anterior a la línea .[. Si no hay tal línea, se insertará una línea adicional antes de la línea .[ y se dará una advertencia.

No hay una notación especial para hacer una cita de múltiples referencias. Simplemente usa una secuencia de citas, una para cada referencia. No pongas nada entre las citas. Las etiquetas de todas las citas se adjuntarán a la línea anterior a la primera cita. Las etiquetas también pueden ordenarse o fusionarse. Consulte la descripción de la expresión de etiqueta <> y de los comandos sort-adjacent-labels y abbreviate-label-ranges. Una etiqueta no se fusionará si su cita tiene un opening-text o closing-text no vacío. Sin embargo, las etiquetas de una cita que utiliza la bandera ] y sin ningún closing-text, seguida inmediatamente por una cita que utiliza la bandera [ y sin ningún opening-text, pueden ordenarse y fusionarse aunque el opening-text de la primera cita o el closing-text de la segunda cita no esté vacío. (Si desea evitar esto, use la secuencia de escape de carácter ficticio \& como closing-text de la primera cita).

Comandos

Los comandos están contenidos entre líneas que comienzan con .R1 y .R2. El reconocimiento de estas líneas se puede prevenir con la opción -R. Cuando se reconoce una línea .R1, todas las referencias acumuladas se eliminan. Ni las líneas .R1 ni .R2, ni nada entre ellas, se imprimen.

Los comandos se separan por saltos de línea o punto y coma. Un signo de número (#) introduce un comentario que se extiende hasta el final de la línea, pero no oculta el salto de línea. Cada comando se divide en palabras. Las palabras se separan por espacios o tabulaciones. Una palabra que comienza con una comilla doble (neutra) (") se extiende hasta la siguiente comilla doble que no va seguida de otra comilla doble. Si no hay tal comilla doble, la palabra se extiende hasta el final de la línea. Los pares de comillas dobles en una palabra que comienza con comillas dobles se colapsan en una sola comilla doble. Ni el signo de número ni el punto y coma se reconocen dentro de las comillas dobles. Una línea puede continuarse terminándola con una barra invertida “\”; esto funciona en todas partes excepto después de un signo de número.

Cada nombre de comando name que está marcado con * tiene un comando negativo asociado no-name que deshace el efecto de name. Por ejemplo, el comando no-sort especifica que las referencias no deben ordenarse. Los comandos negativos no toman argumentos.

En la siguiente descripción, cada argumento debe ser una sola palabra; field se usa para una sola letra mayúscula o minúscula que nombra un campo; fields se usa para una secuencia de tales letras; m y n se usan para números no negativos; string se usa para una cadena arbitraria; file se usa para el nombre de un archivo.

abbreviate* fields string1 string2 string3 string4
Abreviar los nombres iniciales de los fields. Una letra inicial se separará de otra letra inicial por string1, del último nombre por string2, y de cualquier otra cosa (como “von” o “de”) por string3. Estos tienen como valor predeterminado un punto seguido de un espacio. En un nombre inicial con guion, la inicial de la primera parte del nombre se separará del guion por string4; esto tiene como valor predeterminado un punto. No se hace ningún intento para manejar las ambigüedades que puedan resultar de la abreviación. Los nombres se abrevian antes de ordenarlos y antes de construir las etiquetas.
abbreviate-label-ranges* string
Tres o más etiquetas adyacentes que se refieren a referencias consecutivas se abreviarán a una etiqueta que consiste en la primera etiqueta, seguida de string, seguida de la última etiqueta. Esto es principalmente útil con etiquetas numéricas. Si se omite string, el valor predeterminado es “-”.
accumulate*
Acumular referencias en lugar de escribir cada referencia a medida que se encuentra. Las referencias acumuladas se escribirán cada vez que se encuentre una referencia del tipo
.[
$LIST$
.]
se encuentre, después de que se hayan procesado todos los archivos de entrada, y cada vez que se reconozca una línea .R1.
annotate* field string
field es una anotación; imprímela al final de la referencia como un párrafo precedido por la línea
.string

Si se omite string, el valor predeterminado será AP; si también se omite field, el valor predeterminado será X. Solo un campo puede ser una anotación.

articles string ...
Cada string es un artículo definido o indefinido, y debe ignorarse al principio de los campos T al ordenar. Inicialmente, se reconocen como artículos “a”, “an” y “the”.
bibliography file ...
Escribe todas las referencias contenidas en cada base de datos bibliográfica file. Este comando debe ir al final de un bloque .R1/.R2.
bracket-label string1 string2 string3
En el texto, encierra cada etiqueta entre string1 y string2. Una ocurrencia de string2 seguida inmediatamente por string1 se convertirá en string3. El comportamiento predeterminado es el siguiente.
bracket-label \*([. \*(.] ", "
capitalize fields
Convierte fields a mayúsculas y versalitas.
compatible*
Reconoce .R1 y .R2 incluso cuando van seguidos de un carácter distinto de espacio o salto de línea.
database file ...
Busca en cada base de datos bibliográfica file. Para cada file, si existe un archivo de índice .i creado por indxbib(1), se buscará en él; cada índice puede cubrir múltiples bases de datos.
date-as-label* string
string es una expresión de etiqueta que especifica una cadena con la que reemplazar el campo D después de construir la etiqueta. Consulte la subsección “Expresiones de etiqueta” a continuación para obtener una descripción de las expresiones de etiqueta. Este comando es útil si no desea etiquetas explícitas en la lista de referencias, sino que desea manejar cualquier desambiguación necesaria calificando la fecha de alguna manera. La etiqueta utilizada en el texto sería típicamente alguna combinación del autor y la fecha. En la mayoría de los casos, también debería usar el comando no-label-in-reference. Por ejemplo,
date-as-label D.+yD.y%a*D.-y
adjuntaría una letra desambiguadora a la parte del año del campo D en la referencia.
default-database*
Se debe buscar en la base de datos predeterminada. Este es el comportamiento predeterminado, por lo que la versión negativa de este comando es más útil. refer determina si la base de datos predeterminada debe buscarse la primera vez que necesita hacer una búsqueda. Por lo tanto, se debe dar un comando no-default-database antes de eso, para que sea efectivo.
discard* fields
Cuando se lea la referencia, se deben descartar los fields; no se imprimirán definiciones de cadenas para los fields. Inicialmente, los fields son XYZ.
et-al* string m n
Controla el uso de et al. en la evaluación de expresiones @ en expresiones de etiqueta. Si el número de autores necesario para hacer que la secuencia de autores sea inequívoca es u y el número total de autores es t, entonces los últimos t-u autores serán reemplazados por string siempre que t-u no sea menor que m y t no sea menor que n. El comportamiento predeterminado es el siguiente.
et-al " et al" 2 3
Observe la ausencia de un punto al final de la abreviatura, lo cual es discutiblemente incorrecto. (Et al[.] es la abreviatura de et alli, al igual que etc. es la abreviatura de et cetera.)
include file
Incluir file e interpretar

Sintaxis de comandos

Todos los comandos comienzan con un guión seguido de un nombre de comando. Por ejemplo, command. Los argumentos que siguen al nombre del comando pueden ser obligatorios u opcionales. Los argumentos opcionales se denotan con corchetes. Las cadenas de texto que contienen espacios se pueden delimitar con comillas dobles. Los comandos se pueden agrupar en un archivo de configuración de la siguiente manera:

unir-autores cadena1 cadena2 cadena3
Une a varios autores con cadenas. Cuando hay exactamente dos autores, se unirán con cadena1. Cuando hay más de dos autores, todos menos los dos últimos se unirán con cadena2, y los dos últimos autores se unirán con cadena3. Si se omite cadena3, se usará por defecto cadena1; si también se omite cadena2, también se usará por defecto cadena1. Por ejemplo,
unir-autores " y " ", " ", y "
restaurará el método predeterminado para unir autores.
etiqueta-en-referencia*
Al generar la referencia, define la cadena [F como la etiqueta de la referencia. Este es el comportamiento predeterminado, por lo que la versión negativa de este comando es más útil.
etiqueta-en-texto*
Para cada referencia, genera una etiqueta en el texto. La etiqueta se separará del texto circundante como se describe en el comando etiqueta-entre-corchetes. Este es el comportamiento predeterminado, por lo que la versión negativa de este comando es más útil.
etiqueta cadena
cadena es una expresión de etiqueta que describe cómo etiquetar cada referencia.
separar-partes-segundas-de-etiqueta cadena
Al fusionar etiquetas de dos partes, separa la segunda parte de la segunda etiqueta de la primera etiqueta con cadena. Consulte la descripción de la expresión de etiqueta <>.
mover-puntuacion*
En el texto, mueve la puntuación al final de la línea más allá de la etiqueta. Generalmente es una buena idea usar este comando a menos que estés usando números en superíndice como etiquetas.
invertir* cadena
Invierte los campos cuyos nombres están en cadena. Cada nombre de campo puede ir seguido de un número que indica cuántos de esos campos se deben invertir. Si no se da ningún número para un campo, se invertirán todos los campos.
ignorar-busqueda* campos
Al buscar claves en bases de datos para las que no existe índice, ignora el contenido de campos. Inicialmente, se ignoran los campos XYZ.
truncar-busqueda* n
Solo requiere que se proporcionen los primeros n caracteres. En efecto, al buscar una palabra clave dada en la base de datos, las palabras se truncan al máximo de n y la longitud de la clave. Inicialmente, n es 6.
etiqueta-corta* cadena
cadena es una expresión de etiqueta que especifica un estilo de etiqueta alternativo (generalmente más corto). Se utiliza cuando se da el indicador # en la cita. Al usar etiquetas de estilo autor-fecha, la identidad del autor o autores a veces está clara por el contexto, por lo que puede ser deseable omitir el autor o autores de la etiqueta. El comando etiqueta-corta se usará típicamente para especificar una etiqueta que contenga solo una fecha y posiblemente una letra desambiguadora.
ordenar* cadena
Ordena las referencias de acuerdo con cadena. Las referencias se acumularán automáticamente. cadena debe ser una lista de nombres de campos, cada uno seguido de un número, que indica cuántos campos con ese nombre se deben usar para ordenar. “+” se puede usar para indicar que se deben usar todos los campos con ese nombre. También se puede usar . para indicar que las referencias se deben ordenar usando la etiqueta (tentativa). (La subsección “Expresiones de etiqueta” a continuación describe el concepto de etiqueta tentativa).
ordenar-etiquetas-adyacentes*
Ordena las etiquetas que son adyacentes en el texto de acuerdo con su posición en la lista de referencias. Este comando generalmente debería usarse si se ha dado el comando abreviar-etiquetas-rangos, o si la expresión de etiqueta contiene una expresión <>. Esto no tendrá ningún efecto a menos que se estén acumulando referencias.

Expresiones de etiqueta

Las expresiones de etiqueta se pueden evaluar tanto de forma normal como tentativa. El resultado de la evaluación normal se utiliza para la generación. El resultado de la evaluación tentativa, llamado la etiqueta tentativa, se utiliza para recopilar la información que la evaluación normal necesita para desambiguar la etiqueta. Las expresiones de etiqueta especificadas por los comandos fecha-como-etiqueta y etiqueta-corta no se evalúan tentativamente. La evaluación normal y la tentativa son las mismas para todos los tipos de expresión excepto para las expresiones @, * y %. La descripción a continuación se aplica a la evaluación normal, excepto donde se especifique lo contrario.

campo
campo n
La n-ésima parte de campo. Si se omite n, se usa por defecto 1.
'cadena'
Los caracteres de cadena literalmente.
@
Todos los autores unidos como se especifica en el comando unir-autores. Se utilizará la totalidad del nombre de cada autor. Sin embargo, si las referencias se ordenan por autor (es decir, la especificación de ordenación comienza con “A+”), entonces se utilizarán los apellidos en lugar de los nombres completos, siempre que esto no introduzca ambigüedad, y también se puede usar una sub-secuencia inicial de los autores en lugar de todos los autores, nuevamente siempre que esto no introduzca ambigüedad. El uso del solo apellido para el i-ésimo autor de alguna referencia se considera ambiguo si existe otra referencia tal que los primeros i-1 autores de las referencias sean los mismos, los i-ésimos autores no sean los mismos, pero los apellidos de los i-ésimos autores sean los mismos. Una sub-secuencia inicial propia de la secuencia de autores para alguna referencia se considera ambigua si existe una referencia con alguna otra secuencia de autores que también tenga esa sub-secuencia como una sub-secuencia inicial propia. Cuando se usa una sub-secuencia inicial de autores, los autores restantes son reemplazados por la cadena especificada en el comando etc; este comando también puede especificar requisitos adicionales que deben cumplirse antes de que se pueda utilizar una sub-secuencia inicial. @ se evalúa tentativamente como una representación canónica de los autores, de modo que los autores que se comparan por igual para fines de ordenación tendrán la misma representación.
%n
%a
%A
%i
%I
El número de serie de la referencia formateado de acuerdo con el carácter que sigue al %. El número de serie de una referencia es 1 más el número de referencias anteriores con la misma etiqueta tentativa que esta referencia. Estas expresiones se evalúan tentativamente como una cadena vacía.
expr*
Si existe otra referencia con la misma etiqueta tentativa que esta referencia, entonces expr, de lo contrario una cadena vacía. Se evalúa tentativamente como una cadena vacía.
expr+n
expr-n
Las primeras (+) o últimas (-) n letras mayúsculas o minúsculas o dígitos de expr. Los caracteres especiales de roff (como \('a) cuentan como una sola letra. Las cadenas de acentos se conservan pero no cuentan para el total.
expr.l
expr convertido a minúsculas.
expr.u
expr convertido a mayúsculas.
expr.c
expr convertido a mayúsculas y versalitas.
expr.r
expr invertido para que el apellido vaya primero.
expr.a
expr con nombres propios abreviados. Los campos especificados en el comando abreviar se abrevian antes de evaluar cualquier etiqueta. Por lo tanto, .a solo es útil cuando se desea abreviar un campo en una etiqueta pero no en una referencia.
expr.y
La parte del año de expr.
expr.+y
La parte de expr antes del año, o la totalidad de expr si no contiene un año.
expr.-y
La parte de expr después del año, o una cadena vacía si expr no contiene un año.
expr.n
La parte del apellido de expr.
expr1~expr2
expr1 excepto que si el último carácter de expr1 es - entonces será reemplazado por expr2.
expr1 expr2
La concatenación de expr1 y expr2.
expr1|expr2
Si expr1 no está vacío, entonces expr1, de lo contrario expr2.
expr1&expr2
Si expr1 no está vacío, entonces expr2, de lo contrario una cadena vacía.
expr1?expr2:expr3
Si expr1 no está vacío, entonces expr2, de lo contrario expr3.
<expr>
La etiqueta tiene dos partes, que se separan por expr. Dos etiquetas adyacentes de dos partes que tienen la misma primera parte se fusionarán al adjuntar la segunda parte de la segunda etiqueta a la primera etiqueta separada por la cadena especificada en el comando separar-partes-segundas-de-etiqueta (inicialmente, una coma seguida de un espacio); la etiqueta resultante también será una etiqueta de dos partes con la misma primera parte que antes de la fusión, y así se pueden fusionar etiquetas adicionales. Se permite que la primera parte esté vacía; esto puede ser deseable para expr

refer - manual citation processor

Synopsis

refer [-a n] [-b] [-B] [-c fields] [-C] [-e] [-f n] [-i fields] [-k] [-k field] [-l] [-l m] [-l ,n] [-l m,n] [-n] [-p db-file] [-P] [-R] [-s spec] [-S] [-t n] [-v] [-V] [file…]

Description

The refer program is a preprocessor for groff(7) documents. It finds and formats citations to bibliographic databases. It operates on the input file arguments, or on standard input if no files are given.

Input to refer consists of text interleaved with citation requests. A citation request is a line starting with the string “.[” followed by a list of keywords, and ending with “.]”. refer searches one or more bibliographic databases for entries matching the keywords. For each matching entry, it generates a label and potentially a formatted citation. The label is inserted into the text, and the bibliographic data is stored for later use by the groff formatter.

A citation request looks like this:

.[
keyword1 keyword2 ...
.]

The keywords are used to search the databases. The first database entry found that matches any of the keywords is used. The search is case insensitive.

By default, refer looks for entries in the file /usr/dict/papers/Ind. The -p option can be used to specify an alternative database file.

A citation request line is replaced by a label. The label is formed by concatenating strings, specified by the -l or -k options. The default label format is “A.n”, where “A” denotes an article and “n” is a number unique to the article. The numbers are generated sequentially as matching entries are found.

Additional formatting of the generated citation can be controlled using groff macros. The refer macro package /usr/share/groff/1.23.0/tmac/refer.tmac defines strings and macros that facilitate this.

The search mechanism for keywords can be influenced by the -i option, which specifies fields to be ignored during the search. The -t option truncates the search string length.

The short-label command specifies the format of the citation label. It takes a list of fields and their corresponding format strings. For example, short-label A.nD.y means the label will be the author's initial, followed by the publication date, and then the year.

short-label
Specifies the format for the generated citation labels.
(expr)
Same as expr. Used for grouping.

The expressions are listed in order of precedence (highest first); & and | have the same precedence.

Macro interface

Each reference starts with a call to the macro ]-. The string [F will be defined to be the label for this reference, unless the no-label-in-reference command has been given. There then follows a series of string definitions, one for each field: string [X corresponds to field X. The register [P is set to 1 if the P field contains a range of pages. The [T, [A and [O registers are set to 1 according as the T, A and O fields end with any of .?! (an end-of-sentence character). The [E register will be set to 1 if the [E string contains more than one name. The reference is followed by a call to the ][ macro. The first argument to this macro gives a number representing the type of the reference. If a reference contains a J field, it will be classified as type 1, otherwise if it contains a B field, it will be type 3, otherwise if it contains a G or R field it will be type 4, otherwise if it contains an I field it will be type 2, otherwise it will be type 0. The second argument is a symbolic name for the type: other, journal-article, book, article-in-book, or tech-report. Groups of references that have been accumulated or are produced by the bibliography command are preceded by a call to the ]< macro and followed by a call to the ]> macro.

refer uses temporary files. See the groff(1) man page for details of where such files are created.

Bugs

In label expressions, <> expressions are ignored inside .char expressions.

Examples

We can illustrate the operation of refer with a sample bibliographic database containing one entry and a simple roff document to cite that entry.

$ 
cat > my-db-file
%A Daniel P.\& Friedman
%A Matthias Felleisen
%C Cambridge, Massachusetts
%D 1996
%I The MIT Press
%T The Little Schemer, Fourth Edition
$ 
refer -p my-db-file
Read the book
.[
friedman
.]
on your summer vacation.
<Control+D>
.lf 1 -
Read the book\*([.1\*(.]
.ds [F 1
.]-
.ds [A Daniel P. Friedman and Matthias Felleisen
.ds [C Cambridge, Massachusetts
.ds [D 1996
.ds [I The MIT Press
.ds [T The Little Schemer, Fourth Edition
.nr [T 0
.nr [A 0
.][ 2 book
.lf 5 -
on your summer vacation.

The foregoing shows us that refer (a) produces a label “1”; (b) brackets that label with interpolations of the “[.” and “.]” strings; (c) calls a macro “]-”; (d) defines strings and registers containing the label and bibliographic data for the reference; (e) calls a macro “][”; and (f) uses the lf request to restore the line numbers of the original input. As discussed in subsection “Macro interface” above, it is up to the document or a macro package to employ and format this information usefully. Let us see how we might turn groff_ms(7) to this task.

$ 
REFER=my-db-file groff -R -ms
.LP
Read the book
.[
friedman
.]
on your summer vacation.
Commentary is available.\*{*\*}
.FS \*{*\*}
Space reserved for penetrating insight.
.FE

ms's automatic footnote numbering mechanism is not aware of refer's label numbering, so we have manually specified a (superscripted) symbolic footnote for our non-bibliographic aside.
