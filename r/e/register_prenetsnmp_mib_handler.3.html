DESCRIPCIÓN

Las funciones constituyen un sistema bastante extensible para analizar varios archivos de configuración en tiempo de ejecución de una aplicación. El flujo del archivo de configuración se divide en las siguientes fases:

1.
Registro de manejadores.
2.
Lectura de los archivos de configuración para requisitos de análisis previo a MIB.
3.
Lectura y análisis de los archivos MIB textuales.
4.
Lectura de los archivos de configuración para directivas de configuración.
5.
Opcionalmente, relectura de los archivos de configuración en una fecha posterior.

La idea es que la aplicación que llama pueda registrar *manejadores* para *tokens* específicos definidos en archivos de configuración nombrados específicos. La función read_configs() puede entonces ser llamada para buscar todos los archivos de configuración relevantes, hacer coincidir la primera palabra de cada línea con la lista de tokens registrados y pasar el resto de la línea al manejador registrado apropiado.

REGISTRO DE UN MANEJADOR

register_config_handler()
Registra una rutina de manejo de configuración, que debe ser llamada para procesar directivas de configuración que comiencen con el token especificado. Por ejemplo:
register_config_handler("snmp", "exampleToken", example_handler, NULL, "ARG1 [ARG2]");
registraría la función example_handler() para que sea llamada cada vez que la primera palabra de una línea en el archivo(s) de configuración snmp.conf coincida con "exampleToken".
Llamar a los manejadores apropiados para procesar las directivas del archivo de configuración es responsabilidad de read_configs() (ver abajo).
register_const_config_handler()
Similar a la función register_config_handler(), pero la rutina analizadora está explícitamente restringida a no modificar la cadena que se está analizando.
register_prenetsnmp_mib_handler()
Similar a la función register_config_handler(), pero la rutina manejadora registrada será llamada *antes* de que se lean los MIBs textuales. Esto se usa típicamente para tokens que afectarán la configuración del analizador MIB y normalmente solo se usará dentro de la propia biblioteca SNMP.
register_mib_handlers()
Rutina de inicialización para registrar los manejadores de configuración internos de la biblioteca SNMP.
unregister_config_handler()
Elimina el manejador de configuración registrado para el filePrefix y token especificados.
unregister_all_config_handlers()
Elimina todos los manejadores de configuración registrados.

Manejadores de Tokens

Las funciones manejadoras deben tener la siguiente firma:

void handler(const char *token, char *line);
o
void handler(const char *token, const char *line); br (si se registró usando register_const_config_handler)

La función será llamada con dos argumentos, el primero siendo el token que activó la llamada a esta función (es decir, el token usado al registrar el manejador), y el segundo siendo el resto de la línea del archivo de configuración (es decir, todo lo que sigue al espacio en blanco después del token coincidente).

Manejadores de Liberación

Si la función manejadora de tokens asigna dinámicamente recursos al procesar una entrada de configuración, es posible que deban liberarse antes de volver a leer los archivos de configuración. Si el cuarto parámetro ( releaser ) pasado a register_config_handler no es NULL, entonces especifica una función que debe ser llamada antes de volver a leer los archivos de configuración. Esta función debe liberar cualquier recurso asignado por la función manejadora de tokens y restablecer su noción de configuración a su valor predeterminado. La función manejadora de tokens puede entonces ser llamada nuevamente de manera segura. No se pasan argumentos a la función de liberación de recursos.
Tenga en cuenta que esta función no se llama cuando el manejador se desregistra individualmente (pero se llama como parte de unregister_all_config_handlers() ).
