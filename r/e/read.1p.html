READ(1P) Manual del Programador POSIX READ(1P)

PROLOG

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

read — leer desde la entrada estándar en variables de shell

SINOPSIS

read [-r] var...

DESCRIPCIÓN

La utilidad read leerá una única línea lógica desde la entrada estándar en una o más variables de shell.

Por defecto, a menos que se especifique la opción -r, <barra invertida> actuará como carácter de escape. Una <barra invertida> sin escapar conservará el valor literal del carácter siguiente, con la excepción de un <salto de línea>. Si un <salto de línea> sigue a la <barra invertida>, la utilidad read interpretará esto como una continuación de línea. La <barra invertida> y el <salto de línea> se eliminarán antes de dividir la entrada en campos. Todas las demás <barras invertidas> sin escapar se eliminarán después de dividir la entrada en campos.

Si la entrada estándar es un dispositivo de terminal y el shell invocador es interactivo, read solicitará una línea de continuación cuando lea una línea de entrada que termina con una <barra invertida><salto de línea>, a menos que se especifique la opción -r.

El <salto de línea> de terminación (si lo hay) se eliminará de la entrada y los resultados se dividirán en campos como en el shell para los resultados de la expansión de parámetros (consulte la Sección 2.6.5, División de Campos); el primer campo se asignará a la primera variable var, el segundo campo a la segunda variable var, y así sucesivamente. Si hay menos campos que operandos var, las variables var restantes se establecerán a cadenas vacías. Si hay menos variables var que campos, la última variable var se establecerá a un valor que comprenda los siguientes elementos:

*
El campo que corresponde a la última variable var en la secuencia de asignación normal descrita anteriormente
*
El(los) delimitador(es) que sigue(n) al campo que corresponde a la última variable var
*
Los campos restantes y sus delimitadores, ignorando los espacios en blanco de IFS al final

La configuración de las variables especificadas por los operandos var afectará al entorno de ejecución del shell actual; consulte la Sección 2.12, Entorno de Ejecución del Shell. Si se llama en un subshell o en un entorno de ejecución de utilidad separado, como uno de los siguientes:

(read foo)
nohup read ...
find . -exec read ... \;

no afectará a las variables del shell en el entorno del llamador.

OPCIONES

La utilidad read cumplirá con el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Pautas de Sintaxis de Utilidad.

Se admite la siguiente opción:

-r
No trate el carácter <barra invertida> de forma especial. Considere cada <barra invertida> como parte de la línea de entrada.

OPERANDOS

Se admite el siguiente operando:

var
El nombre de una variable de shell existente o no existente.

STDIN

La entrada estándar será un archivo de texto.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de read:

IFS
Determina los separadores de campos internos utilizados para delimitar los campos; consulte la Sección 2.5.3, Variables de Shell.
LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de configuración regional).
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la configuración regional para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en los argumentos).
LC_MESSAGES

Determina la configuración regional que debe utilizarse para afectar al formato y al contenido de los mensajes de diagnóstico escritos en la salida estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.
PS2
Proporciona la cadena de aviso que un shell interactivo escribirá en la salida estándar cuando se lea una línea que termina con una <barra invertida><salto de línea> y no se especificó la opción -r.

EVENTOS ASÍNCRONOS

Predeterminado.

STDOUT

No se utiliza.

STDERR

La salida estándar se utilizará para mensajes de diagnóstico y avisos para entrada continuada.

ARCHIVOS DE SALIDA

Ninguno.

Ninguno.

Se devolverán los siguientes valores de salida:

 0
Finalización exitosa.
>0
Se detectó el fin de archivo o ocurrió un error.

USO PARA LA APLICACIÓN

La opción -r se incluye para permitir que read absorba el propósito de la utilidad line, que no está incluida en POSIX.1‐2008.

EJEMPLOS

El siguiente comando:

while read -r xx yy
do
    printf "%s %s\n$yy$xx"
done < archivo_entrada

imprime un archivo con el primer campo de cada línea movido al final de la línea.

FUNDAMENTO

La utilidad read históricamente ha sido una función integrada del shell. Se separó en su propia utilidad para aprovechar la descripción más rica de la funcionalidad introducida por este volumen de POSIX.1‐2017.

Dado que read afecta al entorno de ejecución del shell actual, generalmente se proporciona como una función regular integrada del shell. Si se llama en un subshell o en un entorno de ejecución de utilidad separado, como uno de los siguientes:

(read foo)
nohup read ...
find . -exec read ... \;

no afecta a las variables del shell en el entorno del llamador.

RATIONALE

El procesamiento de las líneas de continuación cuando no se usa la opción -r puede dar lugar a que la entrada no termine con una <new-line>. Esto ocurre si la última línea del archivo de entrada termina con una barra invertida <backslash> seguida de una <new-line>. Por esta razón, se utiliza "si existe" en "La <new-line> de terminación (si existe) se eliminará de la entrada" en la descripción. No es una relajación del requisito de que la entrada estándar sea un archivo de texto.
