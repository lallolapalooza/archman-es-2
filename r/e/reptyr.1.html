NOMBRE

reptyr - Reparentar un programa en ejecución a una nueva terminal

SINOPSIS

reptyr PID

reptyr -l|-L [COMANDO [ARGUMENTOS]]

DESCRIPCIÓN

reptyr es una utilidad para tomar un programa existente en ejecución y adjuntarlo a una nueva terminal. ¿Iniciaste un proceso de larga duración a través de ssh, pero tienes que irte y no quieres interrumpirlo? Simplemente inicia una pantalla (screen), usa reptyr para tomarlo, y luego mata la sesión ssh y vete a casa.

reptyr funciona adjuntándose al programa objetivo usando ptrace(2), redirigiendo descriptores de archivo relevantes y cambiando la terminal de control del programa (Ver tty(4)). Es este último detalle el que hace que reptyr funcione mucho mejor que alternativas como retty(1).

Después de adjuntar un programa, este aparecerá como en segundo plano o suspendido en el shell desde el que se lanzó (dependiendo del shell). Para máxima seguridad, puedes ejecutar

bg; disown

en el shell antiguo para eliminar la asociación con el programa, pero reptyr intentará asegurar que el programa objetivo siga ejecutándose incluso si cierras el shell sin hacerlo.

OPCIONES

-T

Usa un modo alternativo de adjuntar, "TTY-stealing" (robo de TTY). En este modo, reptyr no usará ptrace(2) al proceso objetivo, sino que intentará descubrir el emulador de terminal del pty de ese proceso y robar el extremo maestro del pty. Este modo es más fiable y flexible en muchas circunstancias (por ejemplo, puede adjuntar todos los procesos de un tty, en lugar de solo un proceso). Sin embargo, como desventaja, los hijos de sshd(8) no pueden ser adjuntados a través de -T a menos que reptyr se ejecute como root. Ver para más información sobre tty-stealing.

-l, -L [COMANDO [ARGUMENTOS]]

En lugar de adjuntar un nuevo proceso, crea un nuevo par de pty, proxy el extremo maestro a la terminal actual, y luego imprime el nombre del pty esclavo. Esto se puede pasar, por ejemplo, a la opción set inferior-tty de gdb.

Si se pasan un COMANDO y ARGUMENTOS opcionales junto con -l, ese comando se ejecutará como un hijo de reptyr con la variable de entorno REPTYR_PTY establecida al nombre del pty esclavo. Si se usa -L en lugar de -l, entonces los fds 0-2 del hijo también se redirigirán para apuntar al esclavo, y el hijo se ejecutará en una sesión nueva con el esclavo como su terminal de control.

-s

Por defecto, reptyr moverá cualquier descriptor de archivo en el objetivo que estuviera conectado a la terminal de control del objetivo para que apunte a la nueva terminal. La opción -s hará que reptyr adjunte incondicionalmente los descriptores de archivo 0, 1 y 2 en el objetivo, incluso si el objetivo no tiene terminal de control o si no están conectados a una terminal.

-v

Imprime la versión de reptyr y sale.

-h

Imprime un mensaje de uso y sale.

-V

Imprime salida de depuración detallada mientras se ejecuta.

NOTAS

reptyr depende de la llamada al sistema ptrace(2) para adjuntarse al programa remoto. En Ubuntu Maverick y versiones posteriores, esta capacidad está deshabilitada por defecto por razones de seguridad. Puedes habilitarla temporalmente haciendo


# echo 0 > /proc/sys/kernel/yama/ptrace_scope

como root, o permanentemente editando el archivo /etc/sysctl.d/10-ptrace.conf, que también contiene más información sobre esta configuración.

ERRORES

Al adjuntar algunos programas de curses, no redibujarán la pantalla inmediatamente, y se necesitará un ^L o similar para forzar un redibujado.

Del mismo modo, después de adjuntar ciertos programas, la terminal antigua puede quedar en un estado extraño, y puede ser necesario un clear o incluso un reset antes de que la terminal antigua sea utilizable de nuevo.

Adjuntar a rtorrent (y probablemente a algunas otras aplicaciones) no funciona bien (rtorrent deja de aceptar entrada) (El problema es que rtorrent está usando epoll para sondear stdin, y no actualizamos la referencia interna que el fd de epoll tiene al tty antiguo).

Adjuntar a un proceso con hijos no funciona bien. Esto debería ser posible de arreglar: solo necesito hacer ptrace de cada hijo individualmente y hacer lo mismo con él.

Adjuntar un proceso less(1) no funciona si tienes un archivo .lessfilter, ya que less deja un hijo zombie en este caso. Esto podría tener una solución alternativa.

Los errores deben ser reportados al autor (ver abajo) o a través del rastreador de problemas en GitHub.
