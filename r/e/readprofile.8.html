READPROFILE(8) Administración del Sistema READPROFILE(8)

NOMBRE

readprofile - leer información de perfil del kernel

SINOPSIS

readprofile [opciones]

VERSIÓN

Esta página del manual documenta la versión 2.0 del programa.

DESCRIPCIÓN

El comando readprofile utiliza la información de /proc/profile para imprimir datos en formato ASCII en la salida estándar. La salida se organiza en tres columnas: la primera es el número de ticks del reloj, la segunda es el nombre de la función C en el kernel donde ocurrieron esos ticks, y la tercera es la carga normalizada del procedimiento, calculada como la relación entre el número de ticks y la longitud del procedimiento. La salida se rellena con espacios para facilitar la lectura.

OPCIONES

-a, --all

Imprime todos los símbolos en el archivo de mapa. Por defecto, no se imprimen los procedimientos con ticks reportados.

-b, --histbin

Imprime los recuentos individuales de los bins del histograma.

-i, --info

Información. Esto hace que readprofile imprima solo el paso de perfilado utilizado por el kernel. El paso de perfilado es la resolución del búfer de perfilado y se elige durante la configuración del kernel (a través de make config) o en la línea de comandos del kernel. Si el modificador -t (conciso) se usa junto con -i, solo se imprimirá el número decimal.

-m, --mapfile archivo_mapa

Especifica un archivo de mapa, que por defecto es /usr/src/linux/System.map. Deberías especificar el archivo de mapa en la línea de comandos si tu kernel actual no es el último que compilaste, o si mantienes System.map en otro lugar. Si el nombre del archivo de mapa termina en .gz, se descomprime sobre la marcha.

-M, --multiplier multiplicador

En algunas arquitecturas es posible alterar la frecuencia con la que el kernel entrega interrupciones de perfilado a cada CPU. Esta opción permite establecer la frecuencia, como un multiplicador de la frecuencia del reloj del sistema, HZ. Linux 2.6.16 eliminó el soporte de multiplicador para la mayoría de los sistemas. Esta opción también restablece el búfer de perfilado y requiere privilegios de superusuario.

-p, --profile archivo_perfil

Especifica un búfer de perfilado diferente, que por defecto es /proc/profile. Usar un archivo de perfil diferente es útil si quieres "congelar" el perfilado del kernel en algún momento y leerlo más tarde. El archivo /proc/profile se puede copiar usando cat(1) o cp(1). Ya no hay soporte para búferes de perfil comprimidos, como en readprofile-1.1, porque el programa necesita conocer el tamaño del búfer con anticipación.

-r, --reset

Restablece el búfer de perfilado. Esto solo puede ser invocado por root, porque /proc/profile es legible por todos pero solo escribible por el superusuario. Sin embargo, puedes hacer que readprofile tenga el ID de usuario establecido en 0, para restablecer el búfer sin obtener privilegios.

-s, --counters

Imprime los contadores individuales dentro de las funciones.

-v, --verbose

Detallado. La salida se organiza en cuatro columnas y se rellena con espacios. La primera columna es la dirección de RAM de una función del kernel, la segunda es el nombre de la función, la tercera es el número de ticks del reloj y la última es la carga normalizada.

-h, --help

Muestra el texto de ayuda y sale.

-V, --version

Muestra la versión y sale.

ARCHIVOS

/proc/profile

Una instantánea binaria del búfer de perfilado.

/usr/src/linux/System.map

La tabla de símbolos para el kernel.

/usr/src/linux/*

El programa que se está perfilando :-)

ERRORES

readprofile solo funciona con un kernel 1.3.x o posterior, porque /proc/profile cambió entre la versión 1.2 y la 1.3.

Este programa solo funciona con kernels ELF. El cambio para kernels a.out es trivial y se deja como ejercicio para el usuario de a.out.

Para habilitar el perfilado, el kernel debe reiniciarse, ya que no hay un módulo de perfilado disponible y no sería fácil de construir. Para habilitar el perfilado, puedes especificar profile=2 (o otro número) en la línea de comandos del kernel. El número que especifiques es el exponente 2 utilizado como paso de perfilado.

El perfilado se deshabilita cuando se inhiben las interrupciones. Esto significa que muchos ticks de perfilado ocurren cuando las interrupciones se vuelven a habilitar. Ten cuidado con la información engañosa.

EJEMPLO

Navegar por el búfer de perfilado ordenado por ticks del reloj:

   readprofile | sort -nr | less

Imprimir los 20 procedimientos más cargados:

   readprofile | sort -nr +2 | head -20

Imprimir solo el perfil del sistema de archivos:

   readprofile | grep _ext2

Ver toda la información del kernel, con direcciones de RAM:

   readprofile -av | less

Navegar por un búfer de perfil "congelado" para un kernel no actual:

   readprofile -p ~/profile.freeze -m /zImage.map.gz

Solicitar perfilado a 2kHz por CPU y restablecer el búfer de perfilado:

   sudo readprofile -M 20
