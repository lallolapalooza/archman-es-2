DESCRIPCIÓN

Las funciones son un sistema bastante extensible para analizar varios archivos de configuración en tiempo de ejecución de una aplicación. El flujo del archivo de configuración se divide en las siguientes fases:

1.
Registro de manejadores.
2.
Lectura de los archivos de configuración para requisitos de análisis previos a MIB.
3.
Lectura y análisis de los archivos MIB textuales.
4.
Lectura de los archivos de configuración para directivas de configuración.
5.
Opcionalmente, volver a leer los archivos de configuración en una fecha futura.

La idea es que la aplicación que llama pueda registrar manejadores para ciertos tokens especificados en ciertos archivos de configuración nombrados. La función read_configs() puede luego ser llamada para buscar todos los archivos de configuración relevantes, comparar la primera palabra de cada línea con la lista de tokens registrados y pasar el resto de la línea al manejador registrado apropiado.

REGISTRO DE UN MANEJADOR

register_config_handler()
Registra una rutina de manejo de configuración, que debe ser llamada para procesar directivas de configuración que comienzan con el token especificado. Por ejemplo:
register_config_handler("snmp", "exampleToken", example_handler, NULL, "ARG1 [ARG2]");
registraría la función example_handler() para que sea llamada cada vez que la primera palabra de una línea en los archivos de configuración snmp.conf coincida con "exampleToken".
Llamar a los manejadores apropiados para procesar las directivas del archivo de configuración es responsabilidad de read_configs() (ver abajo).
register_const_config_handler()
Similar a la función register_config_handler(), pero la rutina analizadora está explícitamente limitada a no modificar la cadena que se está analizando.
register_prenetsnmp_mib_handler()
Similar a la función register_config_handler(), pero la rutina manejadora registrada se llamará antes de que se lean los MIB textuales. Esto se usa típicamente para tokens que afectarán la configuración del analizador de MIB, y normalmente solo se usará dentro de la propia biblioteca SNMP.
register_mib_handlers()
Rutina de inicialización para registrar los manejadores de configuración internos de la biblioteca SNMP.
unregister_config_handler()
Elimina el manejador de configuración registrado para el filePrefix y token especificados.
unregister_all_config_handlers()
Elimina todos los manejadores de configuración registrados.

Manejadores de Tokens

Las funciones manejadoras deben tener la siguiente firma:

void handler(const char *token, char *line);
o
void handler(const char *token, const char *line); br (si se registró usando register_const_config_handler)

La función se llamará con dos argumentos, el primero es el token que activó la llamada a esta función (es decir, el token utilizado al registrar el manejador), y el segundo es el resto de la línea del archivo de configuración (es decir, todo lo que sigue al espacio en blanco después del token coincidente).

Manejadores de Liberación

Si la función manejadora de tokens asigna dinámicamente recursos al procesar una entrada de configuración, es posible que deban liberarse antes de volver a leer los archivos de configuración. Si el cuarto parámetro ( releaser ) pasado a register_config_handler no es NULL, entonces especifica una función que se llamará antes de volver a leer los archivos de configuración. Esta función debe liberar cualquier recurso asignado por la función manejadora de tokens y restablecer su noción de la configuración a su valor predeterminado. La función manejadora de tokens puede entonces llamarse de nuevo de forma segura. No se pasan argumentos a la función manejadora de liberación de recursos.
Tenga en cuenta que esta función no se llama cuando el manejador se anula el registro individualmente (pero sí se llama como parte de unregister_all_config_handlers() ).

Manejadores de Aplicaciones

register_app_config_handler()
register_app_prenetsnmp_mib_handler()
unregister_app_config_handler()

Estas son variantes de los manejadores de configuración anteriores, pero se aplican a las directivas de configuración específicas de la aplicación en lugar de a los archivos de configuración específicos del subsistema (como snmp.conf). El parámetro filePrefix se omite ya que estas directivas se buscan en todos los archivos de configuración de la aplicación.

register_app_config_handler() registra un manejador que se llamará durante la fase de lectura normal de los archivos de configuración.
register_app_prenetsnmp_mib_handler() registra un manejador que se llamará durante la fase de lectura previa a MIB.

LECTURA DE CONFIGURACIÓN

read_premib_configs()
Esta función lee todos los archivos de configuración estándar de la aplicación y llama a todos los manejadores registrados que se marcaron para ser llamados antes de la lectura de MIBs (es decir, usando register_prenetsnmp_mib_handler() o register_app_prenetsnmp_mib_handler()).
read_configs()
Esta función lee todos los archivos de configuración estándar de la aplicación. Lee los archivos de MIB textuales (si aún no se han leído) y luego llama a todos los manejadores registrados (excepto los que ya se llamaron antes de MIB).

Normalmente, una aplicación llamaría a read_premib_configs() al principio de su inicialización, luego llamaría a snmp_add_mibfile() para cargar los MIBs y luego llamaría a read_configs() para procesar las directivas de configuración restantes.

AYUDA Y ERRORES

read_config_print_usage()
Imprime una línea de uso para el análisis de configuración. Si se pasa un argumento no NULL, se imprime al principio de cada línea de uso. Por ejemplo:
read_config_print_usage("myapp ");

Imprimiría:

myapp usage: ...
config_pwarn()
Similar a perror(), imprime la cadena dada precedida por "Error: " seguida de un mensaje de error del sistema, si corresponde.
config_perror()
Similar a perror(), imprime la cadena dada precedida por "Error: " seguida de un mensaje de error del sistema, si corresponde.

EJEMPLO

A continuación se muestra un ejemplo simplificado de cómo registrar un manejador de configuración:

static void
my_log_handler(const char *token, char *c_log_line)
{
    /* Process the log line */
    syslog(LOG_INFO, "%s: %s", token, c_log_line);
}

static void
my_log_releaser(void)
{
    /* Free any resources allocated by my_log_handler */
}

void init_my_app() {
    /* ... other initializations ... */

    /* Register a handler for the "log" token in the snmp.conf file */
    register_config_handler(
        "snmp",          /* File prefix (e.g. snmp.conf) */
        "log",           /* Token */
        my_log_handler,  /* Handler function */
        my_log_releaser, /* Releaser function */
        "log "  /* Usage string */
    );

    /* ... */
}

int main(int argc, char **argv) {
    /* ... */

    init_my_app();

    /* Read configuration files */
    read_premib_configs();  /* Read handlers for pre-MIB config */
    /* Potentially load MIBs here using snmp_add_mibfile() */
    read_configs();         /* Read remaining configuration */

    /* ... */
    return 0;
}

    Estas funciones son análogas a register_config_handler(), register_prenetsnmp_mib_handler() y unregister_config_handler() pero no requieren el argumento del tipo de archivo (que es completado por la aplicación). La intención es que los módulos MIB escritos para el agente utilicen estas funciones para permitir al agente tener más control sobre qué archivos de configuración se leen (típicamente los archivos snmpd.conf).

    LECTURA DE ARCHIVOS DE CONFIGURACIÓN

    read_premib_configs()
    read_configs()
    Estas rutinas procesan los archivos de configuración encontrados en la ruta de búsqueda de configuración (ver más abajo). Para cada entrada, se llama al manejador registrado para ese token de configuración.

    read_premib_configs() se ejecuta antes de que se lean los archivos MIB y procesa los tokens de configuración registrados usando register_prenetsnmp_mib_handler() (o register_app_prenetsnmp_mib_handler()). Todas las demás entradas se ignoran.

    read_configs() se ejecuta después de que se han leído los archivos MIB y procesa los tokens de configuración registrados usando register_config_handler() (o register_app_config_handler()). Si encuentra un token de configuración para el cual no se ha registrado ningún manejador (ni pre- ni post-mib), mostrará un mensaje de advertencia y continuará procesando con la siguiente línea del archivo de configuración.

    Ruta de búsqueda de configuración

    Los archivos de configuración que se leerán se encuentran buscando en una lista de directorios de configuración archivos con nombres apropiados. En cada uno de esos directorios, la biblioteca buscará archivos llamados snmp.conf, snmp.local.conf, app.conf, app.local.conf,
    (donde app es el prefijo de archivo específico de la aplicación utilizado para registrar los manejadores de configuración). No es necesario que alguno o todos estos archivos estén presentes en cada directorio. Los archivos que faltan se omitirán silenciosamente.
    La idea detrás de los dos sufijos diferentes es que el primer archivo puede ser compartido (a través de rdist o un montaje NFS) en un gran número de máquinas y el segundo archivo puede usarse para configurar ajustes locales para una máquina en particular.

    La lista predeterminada de directorios a buscar es /etc/snmp, seguido de /usr/share/snmp, seguido de /usr/lib/snmp, seguido de $HOME/.snmp. Esta lista puede cambiarse estableciendo la variable de entorno SNMPCONFPATH a una lista de directorios (separados por dos puntos) para buscar.

    init_snmp()

    El modo normal de operación sería registrar los manejadores de configuración específicos de la aplicación e invocar init_snmp(). Esto llamaría a las rutinas enumeradas anteriormente para registrar los manejadores de configuración internos de la biblioteca, procesar cualquier token de configuración registrado con register_prenetsnmp_mib_handler(), leer los archivos MIB textuales usando init_mib(), y finalmente analizar los tokens del archivo de configuración registrados con register_config_handler().

    Si se utiliza la función init_snmp(), ninguna de estas funciones necesita ser llamada explícitamente por la aplicación.

    CADENAS DE AYUDA Y ERRORES

    El parámetro usageLine pasado a register_config_handler() y llamadas similares, se utiliza para mostrar información de ayuda cuando se llama a la función read_config_print_usage(). Esta función es utilizada por todas las aplicaciones cuando se pasa el flag -H en la línea de comandos. Imprime un resumen de todas las líneas del archivo de configuración y los archivos asociados que el sistema de configuración entiende. El parámetro usageLine debe ser una lista de argumentos esperados después del token, y no una descripción larga (que debería ir en una página de manual en su lugar). El prefijo lead se antepondrá a cada línea que la función imprima en stderr, donde muestra su salida.

    La función init_snmp() debe llamarse antes que la función read_config_print_usage(), para que la biblioteca pueda registrar sus directivas de archivo de configuración también para que la función read_config_print_usage() las muestre.

    Funciones de manejo de errores

    Las dos funciones config_pwarn() y config_perror() toman una cadena de error como argumento y la imprimen en stderr junto con el archivo y el número de línea que causaron el error. Una llamada a la segunda función también forzará a read_configs() a devolver eventualmente un código de error que indique a su función llamante que debe abortar la operación de la aplicación.

    VARIABLES DE ENTORNO

    SNMPCONFPATH
    Una lista separada por dos puntos de directorios para buscar archivos de configuración. Predeterminado:
    /etc/snmp:/usr/share/snmp:/usr/lib/snmp:$HOME/.snmp
