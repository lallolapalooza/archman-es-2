READLINK(3P) Manual del programador de POSIX READLINK(3P)

PRÓLOGO

Esta página del manual es parte del Manual del programador de POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

readlink, readlinkat — leer el contenido de un enlace simbólico

SINOPSIS

#include <unistd.h>
ssize_t readlink(const char *restrict path, char *restrict buf,
    size_t bufsize);
#include <fcntl.h>
ssize_t readlinkat(int fd, const char *restrict path,
    char *restrict buf, size_t bufsize);

DESCRIPCIÓN

La función readlink() colocará el contenido del enlace simbólico referenciado por path en el búfer buf, que tiene un tamaño de bufsize. Si el número de bytes en el enlace simbólico es menor que bufsize, el contenido del resto de buf no se especifica. Si el argumento buf no es lo suficientemente grande para contener el contenido del enlace, los primeros bufsize bytes se colocarán en buf.

Si el valor de bufsize es mayor que {SSIZE_MAX}, el resultado depende de la implementación.

Tras una finalización exitosa, readlink() marcará para actualización la última marca de tiempo de acceso a datos del enlace simbólico.

La función readlinkat() será equivalente a la función readlink() excepto en el caso en que path especifique una ruta relativa. En este caso, el enlace simbólico cuyo contenido se lee es relativo al directorio asociado con el descriptor de archivo fd en lugar del directorio de trabajo actual. Si el modo de acceso de la descripción del archivo abierto asociado con el descriptor de archivo no es O_SEARCH, la función verificará si se permiten búsquedas de directorios utilizando los permisos actuales del directorio subyacente al descriptor de archivo. Si el modo de acceso es O_SEARCH, la función no realizará la verificación.

Si readlinkat() recibe el valor especial AT_FDCWD en el parámetro fd, se utilizará el directorio de trabajo actual y el comportamiento será idéntico al de una llamada a readlink().

VALOR DE RETORNO

Tras una finalización exitosa, estas funciones devolverán el recuento de bytes colocados en el búfer. De lo contrario, estas funciones devolverán un valor de -1, dejarán el búfer sin cambios y establecerán errno para indicar el error.

ERRORES

Estas funciones fallarán si:

EACCES
Se niega el permiso de búsqueda para un componente del prefijo de ruta de path.
EINVAL
El argumento path nombra un archivo que no es un enlace simbólico.
EIO
Ocurrió un error de E/S al leer del sistema de archivos.
ELOOP
Existe un bucle en los enlaces simbólicos encontrados durante la resolución del argumento path.
ENAMETOOLONG

La longitud de un componente de un nombre de ruta es mayor que {NAME_MAX}.
ENOENT
Un componente de path no nombra un archivo existente o path es una cadena vacía.
ENOTDIR
Un componente del prefijo de ruta nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio, o el argumento path contiene al menos un carácter que no es <barra> y termina con uno o más caracteres de <barra> finales y el último componente del nombre de ruta nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio.

La función readlinkat() fallará si:

EACCES
El modo de acceso de la descripción del archivo abierto asociado con fd no es O_SEARCH y los permisos del directorio subyacente a fd no permiten búsquedas de directorios.
EBADF
El argumento path no especifica una ruta absoluta y el argumento fd no es ni AT_FDCWD ni un descriptor de archivo válido abierto para lectura o búsqueda.
ENOTDIR
El argumento path no es una ruta absoluta y fd es un descriptor de archivo asociado con un archivo que no es un directorio.

Estas funciones pueden fallar si:

ELOOP
Se encontraron más de {SYMLOOP_MAX} enlaces simbólicos durante la resolución del argumento path.
ENAMETOOLONG

La longitud de un nombre de ruta excede {PATH_MAX}, o la resolución del nombre de ruta de un enlace simbólico produjo un resultado intermedio con una longitud que excede {PATH_MAX}.

Las siguientes secciones son informativas.

EJEMPLOS

Leer el Nombre de un Enlace Simbólico

El siguiente ejemplo muestra cómo leer el nombre de un enlace simbólico llamado /modules/pass1.

#include <unistd.h>
char buf[1024];
ssize_t len;
...
if ((len = readlink("/modules/pass1", buf, sizeof(buf)-1)) != -1)
    buf[len] = '\0';

USO POR PARTE DE LA APLICACIÓN

Las aplicaciones que cumplen no deben asumir que el contenido devuelto del enlace simbólico está terminado en nulo.

JUSTIFICACIÓN

El tipo asociado con bufsiz es un size_t para ser consistente tanto con el estándar ISO C como con la definición de read(). El comportamiento especificado para readlink() cuando bufsiz es cero representa la práctica histórica. Para este caso, los desarrolladores del estándar consideraron un cambio por el cual readlink() devolvería el número de bytes no nulos contenidos en el enlace simbólico con el búfer buf sin cambios; sin embargo, dado que el valor del miembro st_size de la estructura stat se puede usar para determinar el tamaño del búfer necesario para contener el contenido del enlace simbólico tal como lo devuelve readlink(), esta propuesta fue rechazada y se mantuvo la práctica histórica.

El propósito de la función readlinkat() es leer el contenido de enlaces simbólicos en directorios distintos del directorio de trabajo actual sin exposición a condiciones de carrera. Cualquier parte de la ruta de un archivo podría modificarse en paralelo a una llamada a readlink(), lo que resultaría en un comportamiento no especificado. Al abrir un descriptor de archivo para el directorio de destino y usar la función readlinkat() se puede garantizar que el enlace simbólico leído se encuentra relativo al directorio deseado.
