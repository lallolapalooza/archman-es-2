NOMBRE

regexp_table - formato de las tablas de expresiones regulares de Postfix

SINOPSIS

postmap -q "cadena" regexp:/etc/postfix/nombrearchivo
postmap -q - regexp:/etc/postfix/nombrearchivo <archivoentrada

DESCRIPCIÓN


El sistema de correo Postfix utiliza tablas opcionales para la reescritura de direcciones, el enrutamiento de correo o el control de acceso. Estas tablas suelen estar en formato dbm o db.

Alternativamente, las tablas de búsqueda pueden especificarse en forma de expresiones regulares POSIX. En este caso, cada entrada se compara con una lista de patrones. Cuando se encuentra una coincidencia, se devuelve el resultado correspondiente y la búsqueda se termina.

Para saber qué tipos de tablas de búsqueda soporta su sistema Postfix, utilice el comando "postconf -m".

Para probar tablas de búsqueda, utilice el comando "postmap -q" como se describe en la SINOPSIS anterior. Utilice "postmap -hmq - <archivo" para patrones de header_checks(5), y "postmap -bmq - <archivo" para body_checks(5) (Postfix 2.6 y posteriores).

COMPATIBILIDAD

Con Postfix versión 2.2 y anteriores, especifique "postmap -fq" para consultar una tabla que contenga patrones sensibles a mayúsculas y minúsculas. Los patrones no distinguen entre mayúsculas y minúsculas por defecto.

FORMATO DE TABLA

La forma general de una tabla de expresiones regulares de Postfix es:

/patrón/flags resultado
Cuando patrón coincide con la cadena de entrada, utilice el valor de resultado correspondiente.
!/patrón/flags resultado
Cuando patrón no coincide con la cadena de entrada, utilice el valor de resultado correspondiente.
si /patrón/flags
finsi
Si la cadena de entrada coincide con /patrón/, entonces haga coincidir esa cadena de entrada con los patrones entre si y finsi. El bloque si..finsi puede anidarse.

Nota: no anteponga espacios en blanco a los patrones dentro de si..finsi.

Esta característica está disponible en Postfix 2.1 y posteriores.

si !/patrón/flags
finsi
Si la cadena de entrada no coincide con /patrón/, entonces haga coincidir esa cadena de entrada con los patrones entre si y finsi. El bloque si..finsi puede anidarse.

Nota: no anteponga espacios en blanco a los patrones dentro de si..finsi.

Esta característica está disponible en Postfix 2.1 y posteriores.

líneas en blanco y comentarios
Se ignoran las líneas vacías y las líneas que solo contienen espacios en blanco, al igual que las líneas cuyo primer carácter que no es un espacio en blanco es un `#'.
texto multilínea
Una línea lógica comienza con texto que no son espacios en blanco. Una línea que comienza con un espacio en blanco continúa una línea lógica.

Cada patrón es una expresión regular POSIX delimitada por un par de delimitadores. La sintaxis de la expresión regular se documenta en re_format(7) con 4.4BSD, en regex(5) con Solaris, y en regex(7) con Linux. Otros sistemas pueden utilizar otros nombres de documento.

El delimitador de expresión puede ser cualquier carácter no alfanumérico, excepto espacios en blanco o caracteres que tengan un significado especial (tradicionalmente se usa la barra inclinada).

Por defecto, la coincidencia no distingue entre mayúsculas y minúsculas, y los saltos de línea no se tratan como caracteres especiales. El comportamiento se controla mediante banderas, que se activan/desactivan añadiendo uno o más de los siguientes caracteres después del patrón:

i (por defecto: activado)
Activa/desactiva la bandera de sensibilidad a mayúsculas y minúsculas. Por defecto, la coincidencia no distingue entre mayúsculas y minúsculas.
m (por defecto: desactivado)
Activa/desactiva la bandera del modo multilínea. Cuando esta bandera está activada, los metacaracteres ^ y $ coinciden inmediatamente después y justo antes de un carácter de nueva línea, respectivamente, además de coincidir al principio y al final de la cadena de entrada.
x (por defecto: activado)
Activa/desactiva la bandera de sintaxis de expresión extendida. Por defecto, se habilita el soporte para la sintaxis de expresión extendida.

ORDEN DE BÚSQUEDA DE LA TABLA

Los patrones se aplican en el orden especificado en la tabla, hasta que se encuentre un patrón que coincida con la cadena de entrada.

Cada patrón se aplica a toda la cadena de entrada. Dependiendo de la aplicación, esa cadena es un nombre de host de cliente completo, una dirección IP de cliente completa o una dirección de correo completa. Por lo tanto, no se realiza ninguna búsqueda de dominio padre o red padre, y las direcciones de correo usuario@dominio no se dividen en sus partes constituyentes usuario y dominio, ni usuario+foo se divide en usuario y foo.

SUSTITUCIÓN DE TEXTO

La sustitución de subcadenas (texto que coincide con patrones dentro de "()") de la expresión coincidente en la cadena de resultado se solicita con $1, $2, etc.; especifique $$ para producir un carácter $ como salida. Las macros en la cadena de resultado pueden necesitar escribirse como ${n} o $(n) si no están seguidas por espacios en blanco.

Nota: dado que los patrones negados (los precedidos por !) devuelven un resultado cuando la expresión no coincide, las sustituciones no están disponibles para patrones negados.

ESPECIFICACIÓN EN LÍNEA

El contenido de una tabla puede especificarse en el nombre de la tabla (Postfix 3.7 y posteriores). La sintaxis básica es:

main.cf:
    parametro = .. regexp:{ { regla-1 }, { regla-2 } .. } ..
master.cf:
    .. -o { parametro = .. regexp:{ { regla-1 }, { regla-2 } .. } .. } ..

Postfix expande recursivamente cualquier instancia de $nombre_parametro en el valor del parámetro anterior, ignora los espacios en blanco después de '{' y antes de '}', y escribe cada regla como una línea de texto en un archivo en memoria:

archivo en memoria:
    regla-1
    regla-2
    ..

Postfix analiza el resultado como si fuera un archivo en /etc/postfix.

ADVERTENCIAS SOBRE LA ESPECIFICACIÓN EN LÍNEA

  • Evite usar $nombre_parametro dentro de un patrón regexp: en línea. El patrón tendría coincidencias inesperadas si hay metacaracteres como '.' en la expansión de $nombre_parametro. Para evitar coincidencias inesperadas, utilice una tabla pcre: y especifique \Q$nombre_parametro\E.
  • Cuando una regla en línea deba contener $, especifique $$ para evitar que Postfix intente hacer la expansión de $nombre mientras evalúa un valor de parámetro. Para verificar una configuración en línea, utilice la opción "postconf -x" como se muestra a continuación:
  • Cuando una configuración "nombre_parametro = valor" de main.cf contenga una tabla regexp: en línea, utilice el comando "postconf -x nombre_parametro". Verifique que no haya advertencias de "parámetro indefinido", y que la salida tenga la sintaxis que se usaría en un archivo regexp: de Postfix no en línea.
  • Cuando una anulación master.cf "-o { nombre_parametro = valor }" contenga una tabla regexp: en línea, utilice el comando "postconf -Px '*/*/nombre_parametro' ". Verifique que no haya advertencias de "parámetro indefinido", y que la salida tenga la sintaxis que se usaría en un archivo regexp: de Postfix no en línea.

EJEMPLO DE MAPA DE ACCESO SMTPD

# Deshabilitar el enrutamiento especificado por el remitente. Esto es obligatorio si reenvía correo
# para otros dominios.
/[%!@].*[%!@]/       55

# Primero saltar el texto codificado en base 64 para ahorrar ciclos de CPU.
~^[[:alnum:]+/]{60,}$~          OK
