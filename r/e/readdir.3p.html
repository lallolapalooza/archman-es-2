READDIR(3P) Manual del programador de POSIX READDIR(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del programador de POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

readdir, readdir_r — leer un directorio

SINOPSIS

#include <dirent.h>
struct dirent *readdir(DIR *dirp);
int readdir_r(DIR *restrict dirp, struct dirent *restrict entry,
    struct dirent **restrict result);

DESCRIPCIÓN

El tipo DIR, que se define en la cabecera <dirent.h>, representa un flujo de directorio, que es una secuencia ordenada de todas las entradas del directorio en un directorio particular. Las entradas del directorio representan archivos; los archivos pueden ser eliminados de un directorio o agregados a un directorio de forma asíncrona a la operación de readdir().

La función readdir() devolverá un puntero a una estructura que representa la entrada del directorio en la posición actual del flujo de directorio especificado por el argumento dirp, y posicionará el flujo de directorio en la siguiente entrada. Devolverá un puntero nulo al llegar al final del flujo de directorio. La estructura dirent definida en la cabecera <dirent.h> describe una entrada de directorio. El valor del miembro d_ino de la estructura se establecerá en el número de serie del archivo del archivo llamado por el miembro d_name. Si el miembro d_name nombra un enlace simbólico, el valor del miembro d_ino se establecerá en el número de serie del archivo del propio enlace simbólico.

La función readdir() no devolverá entradas de directorio que contengan nombres vacíos. Si existen entradas para punto ('.') o doble punto ('..'), se devolverá una entrada para punto y una entrada para doble punto; de lo contrario, no se devolverán.

La aplicación no debe modificar la estructura a la que apunta el valor de retorno de readdir(), ni las áreas de almacenamiento a las que apuntan los punteros dentro de la estructura. El puntero devuelto, y los punteros dentro de la estructura, pueden ser invalidados o la estructura o las áreas de almacenamiento pueden ser sobrescritas por una llamada posterior a readdir() en el mismo flujo de directorio. No se verán afectados por una llamada a readdir() en un flujo de directorio diferente. El puntero devuelto, y los punteros dentro de la estructura, también pueden ser invalidados si el hilo de llamada termina.

Si un archivo se elimina o se agrega al directorio después de la llamada más reciente a opendir() o rewinddir(), es indeterminado si una llamada posterior a readdir() devolverá una entrada para ese archivo.

La función readdir() puede almacenar en búfer varias entradas de directorio por operación de lectura real; readdir() marcará para actualización la última marca de tiempo de acceso a los datos del directorio cada vez que el directorio se lea realmente.

Después de una llamada a fork(), el padre o el hijo (pero no ambos) pueden continuar procesando el flujo de directorio usando readdir(), rewinddir(), o seekdir(). Si los procesos padre e hijo utilizan estas funciones, el resultado es indefinido.

La función readdir() no necesita ser segura para hilos.

Las aplicaciones que deseen verificar situaciones de error deben establecer errno a 0 antes de llamar a readdir(). Si errno se establece a un valor distinto de cero en el retorno, se produjo un error.

La función readdir_r() inicializará la estructura dirent referenciada por entry para representar la entrada del directorio en la posición actual del flujo de directorio al que se refiere dirp, almacenará un puntero a esta estructura en la ubicación referenciada por result, y posicionará el flujo de directorio en la siguiente entrada.

El almacenamiento apuntado por entry debe ser lo suficientemente grande para un dirent con una matriz de miembros char d_name que contenga al menos {NAME_MAX}+1 elementos.

Tras una finalización exitosa, el puntero devuelto en *result tendrá el mismo valor que el argumento entry. Al llegar al final del flujo de directorio, este puntero tendrá el valor NULL.

La función readdir_r() no devolverá entradas de directorio que contengan nombres vacíos.

Si un archivo se elimina o se agrega al directorio después de la llamada más reciente a opendir() o rewinddir(), es indeterminado si una llamada posterior a readdir_r() devolverá una entrada para ese archivo.

La función readdir_r() puede almacenar en búfer varias entradas de directorio por operación de lectura real; readdir_r() marcará para actualización la última marca de tiempo de acceso a los datos del directorio cada vez que el directorio se lea realmente.

VALOR DE RETORNO

Tras una finalización exitosa, readdir() devolverá un puntero a un objeto de tipo struct dirent. Cuando se encuentra un error, se devolverá un puntero nulo y se establecerá errno para indicar el error. Cuando se encuentra el final del directorio, se devolverá un puntero nulo y errno no se modificará.

Si tiene éxito, la función readdir_r() devolverá cero; de lo contrario, se devolverá un número de error para indicar el error.

ERRORES

Estas funciones fallarán si:

EOVERFLOW
Uno de los valores de la estructura a devolver no se puede representar correctamente.

Estas funciones pueden fallar si:

EBADF
El argumento dirp no se refiere a un flujo de directorio abierto.
ENOENT
La posición actual del flujo de directorio es inválida.

EJEMPLOS

El siguiente programa de ejemplo busca en el directorio actual cada uno de los argumentos proporcionados en la línea de comandos.

#include <dirent.h>
#include <errno.h>
#include <stdio.h>
#include <string.h>
static void lookup(const char *arg)
{
    DIR *dirp;
    struct dirent *dp;
    if ((dirp = opendir(".")) == NULL) {
        perror("no se pudo abrir '.'");
        return;
    }
    do {
        errno = 0;
        if ((dp = readdir(dirp)) != NULL) {
            if (strcmp(dp->d_name, arg) != 0)
                continue;
            (void) printf("encontrado %s\n", arg);
            (void) closedir(dirp);
                return;
        }
    } while (dp != NULL);
    if (errno != 0)
        perror("error al leer el directorio");
    else
        (void) printf("no se pudo encontrar %s\n", arg);
    (void) closedir(dirp);
    return;
}
int main(int argc, char *argv[])
{
    int i;
    for (i = 1; i < argc; i++)
        lookup(argv[i]);
    return (0);
}

USO DE LA APLICACIÓN

La función readdir() debe usarse junto con opendir(), closedir() y rewinddir() para examinar el contenido del directorio.

La función readdir_r() es segura para hilos y devolverá valores en un búfer proporcionado por el usuario en lugar de posiblemente usar un área de datos estática que pueda ser sobrescrita en cada llamada.

FUNDAMENTO

El valor devuelto por readdir() simplemente representa una entrada de directorio. No se debe inferir ninguna equivalencia.

Las implementaciones históricas de readdir() obtienen múltiples entradas de directorio en una sola operación de lectura, lo que permite que las operaciones posteriores de readdir() operen a partir de la información almacenada en búfer. Cualquier redacción que requiriera que cada operación exitosa de readdir() marcara la última marca de tiempo de acceso a los datos del directorio para su actualización permitiría tales implementaciones históricas orientadas al rendimiento.

Al devolver una entrada de directorio para la raíz de un sistema de archivos montado, algunas implementaciones históricas de readdir() devolvían el número de serie del archivo del punto de montaje subyacente, en lugar de la raíz del sistema de archivos montado. RATIONALE

El número de serie no tiene ninguna significación para las aplicaciones.

Dado que readdir() devuelve NULL cuando detecta un error y cuando se llega al final del directorio, una aplicación que necesite diferenciar debe establecer errno a cero antes de la llamada y comprobarlo si se devuelve NULL. Dado que la función no debe cambiar errno en el segundo caso y debe establecerlo a un valor distinto de cero en el primer caso, un errno cero después de una llamada que devuelve NULL indica el fin del directorio; de lo contrario, un error.

Se propusieron rutinas para tratar este problema de forma más directa:

int derror (dirp)
DIR *dirp;
void clearderr (dirp)
DIR *dirp;

La primera indicaría si ha ocurrido un error y la segunda borraría la indicación de error. En su lugar, se adoptó el método más sencillo que implica errno, exigiendo que readdir() no cambie errno cuando se encuentra el fin del directorio.

Se consideró, pero se rechazó, una señal o error que indicara que un directorio ha cambiado mientras estaba abierto.

La versión segura para hilos de la función de lectura de directorios devuelve valores en un búfer proporcionado por el usuario en lugar de utilizar posiblemente un área de datos estática que podría ser sobrescrita en cada llamada. Se puede utilizar la constante en tiempo de compilación {NAME_MAX} o la opción correspondiente de pathconf() para determinar los tamaños máximos de los nombres de ruta devueltos.
