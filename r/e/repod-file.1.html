repod-file(1)

Paquete: repod

Licencias: GPL-3.0-or-later

repod-file(1) repod repod-file(1)

Acciones de archivo para paquetes, repositorio de gestión y bases de datos de sincronización.

usage: repod-file [-h] [-c CONFIG] [-d] [-s] [-v] {package,repo,schema} ...

ARGUMENTOS POSICIONALES

subcommand
Posibles opciones: package, repo, schema

ARGUMENTOS NOMBRADOS

-c, --config
archivo de configuración
-d, --debug
salida de depuración

Por defecto: False

-s, --system
modo sistema

Por defecto: False

-v, --verbose
salida detallada

Por defecto: False

SUB-COMANDOS

package

interactuar con archivos de paquetes

repod-file package [-h] {inspect} ...

Argumentos Posicionales

package
Posibles opciones: inspect

Sub-comandos

inspect

inspeccionar archivos de paquetes

repod-file package inspect [-h] [-B | -M | -P] [-p] [-s] file [file ...]

Argumentos Posicionales

file
archivos de paquete

Argumentos Nombrados

-B, --buildinfo
solo inspeccionar .BUILDINFO

Por defecto: False

-M, --mtree
solo inspeccionar .MTREE

Por defecto: False

-P, --pkginfo
solo inspeccionar .PKGINFO

Por defecto: False

-p, --pretty
imprimir salida de forma bonita

Por defecto: False

-s, --with-signature
localizar y usar un archivo de firma para cada archivo de paquete proporcionado

Por defecto: False

repo

interactuar con repositorios

repod-file repo [-h] {importdb,importpkg,writedb} ...

Argumentos Posicionales

repo
Posibles opciones: importdb, importpkg, writedb

Sub-comandos

importdb

importar estado desde una base de datos de sincronización de repositorio

repod-file repo importdb [-h] [-a ARCHITECTURE] [-D | -S | -T] file name

Argumentos Posicionales

file
base de datos de sincronización de repositorio
name
nombre del repositorio a importar

Argumentos Nombrados

-a, --architecture
apuntar a un repositorio con una arquitectura específica (si existen múltiples con el mismo nombre pero diferente arquitectura)
-D, --debug
importar al repositorio de depuración

Por defecto: False

-S, --staging
importar al repositorio provisional (staging)

Por defecto: False

-T, --testing
importar al repositorio de pruebas (testing)

Por defecto: False

importpkg

importar paquetes a un repositorio

repod-file repo importpkg [-h] [-a ARCHITECTURE] [-d] [-p] [-s]
                          [-u SOURCE_URL [SOURCE_URL ...]] [-D | -S | -T]
                          file [file ...] name

Argumentos Posicionales

file
archivos de paquete
name
nombre del repositorio al que importar

Argumentos Nombrados

-a, --architecture
apuntar a un repositorio con una arquitectura específica (si existen múltiples con el mismo nombre pero diferente arquitectura)
-d, --dry-run
solo mostrar la salida, pero no escribirla en el archivo

Por defecto: False

-p, --pretty
imprimir salida de forma bonita (solo aplica en modo de simulación)

Por defecto: False

-s, --with-signature
localizar y usar un archivo de firma para cada archivo de paquete proporcionado

Por defecto: False

-u, --source-url
lista de URLs de origen para pkgbases añadidas (proporcionadas como una o más cadenas pkgbase=url)

Por defecto: []

-D, --debug
importar al repositorio de depuración

Por defecto: False

-S, --staging
importar al repositorio provisional (staging)

Por defecto: False

-T, --testing
importar al repositorio de pruebas (testing)

Por defecto: False

writedb

exportar estado a una base de datos de sincronización de repositorio

repod-file repo writedb [-h] [-a ARCHITECTURE] [-D | -S | -T] name

Argumentos Posicionales

name
nombre del repositorio al que escribir

Argumentos Nombrados

-a, --architecture
apuntar a un repositorio con una arquitectura específica (si existen múltiples con el mismo nombre pero diferente arquitectura)
-D, --debug
exportar desde el repositorio de depuración

Por defecto: False

-S, --staging
exportar desde el repositorio provisional (staging)

Por defecto: False

-T, --testing
exportar desde el repositorio de pruebas (testing)

Por defecto: False

comandos de esquema JSON

repod-file schem

EJEMPLOS

TRANSFORMAR BASE DE DATOS SYNC DEL REPOSITORIO A REPOSITORIO DE GESTIÓN

Los archivos de la Base de Datos Sync pueden ser transformados a representaciones utilizadas en el contexto de un Repositorio de Gestión.

NOTA:

Se requieren archivos de la Base de Datos de Archivos para crear archivos del Repositorio de Gestión, ¡que contienen información sobre los archivos incluidos en sus respectivos paquetes! Estos datos no están contenidos en los archivos de la Base de Datos Predeterminada.

Para fines de prueba, se pueden usar las bases de datos sync del sistema en /var/lib/pacman/sync/ (esto asume un sistema que utiliza pacman como gestor de paquetes).

Para importar archivos de la Base de Datos Predeterminada y emitirlos al directorio del repositorio de gestión de un repositorio configurado, use:

repod-file repo importdb /var/lib/pacman/sync/core.db default

Para poder usar los archivos de la Base de Datos de Archivos, asegúrese de actualizarlos primero.

pacman -Fy

Después, es posible importar esos archivos de forma análoga a como se hace con los archivos de la Base de Datos Predeterminada:

repod-file repo importdb /var/lib/pacman/sync/core.files default

Lo anterior asume que el repositorio llamado default está presente (por ejemplo, cuando no hay un archivo de configuración para repod).

TRANSFORMAR REPOSITORIO DE GESTIÓN A BASE DE DATOS SYNC DEL REPOSITORIO

Los archivos JSON contenidos en un Repositorio de Gestión pueden ser transformados en una Base de Datos Sync (se crean archivos de Base de Datos Predeterminada y Base de Datos de Archivos).

Después de seguir los ejemplos en TRANSFORMAR BASE DE DATOS SYNC DEL REPOSITORIO A REPOSITORIO DE GESTIÓN, es posible usar los archivos creados y convertirlos de nuevo en archivos de Base de Datos Sync.

repod-file repo writedb default

Lo anterior crea default.db así como default.files en la ubicación binaria del repositorio del repositorio llamado default.
