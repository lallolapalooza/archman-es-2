FBB::ReadLineBuf(3bobcat) Edición de líneas de entrada FBB::ReadLineBuf(3bobcat)

NOMBRE

FBB::ReadLineBuf - std::streambuf que ofrece edición de línea e historial

SINOPSIS

#include <bobcat/readlinebuf>
Opción de enlace: -lbobcat -lreadline

DESCRIPCIÓN

El objeto FBB::ReadLineBuf puede usarse como un std::streambuf de objetos std::istream, permitiendo la edición de líneas y la manipulación del historial.

ReadLineBuf utiliza la biblioteca readline de Gnu para permitir la edición de líneas de entrada. El objeto ReadLineBuf puede ser usado para construir un std::istream que permita la edición en línea de las líneas leídas de la terminal. Todas las líneas pueden ir precedidas por un prompt configurable.

Dado que la biblioteca readline de Gnu opera sobre datos globales, solo puede haber un objeto ReadLineBuf. Por lo tanto, ReadLineBuf es una clase singleton: en cualquier programa solo puede existir un objeto ReadLineBuf (la biblioteca readline de Gnu, sin embargo, ofrece funciones que permiten a los programas usar múltiples historiales. Por lo tanto, sería en principio posible diseñar una clase ReadLineBuf no singleton. Dado que los programas normalmente solo interactúan con una única terminal, probablemente haya poco uso para una clase ReadLineBuf no singleton).

ReadLineBuf ofrece capacidades de edición mientras el usuario está introduciendo líneas. Al igual que la función readline(3) de Gnu, los comandos de edición de línea son, por defecto, similares a los de emacs(1), pero pueden reconfigurarse fácilmente, por ejemplo, para ofrecer características similares a las de vi(1).

La manipulación del historial se proporciona como una opción. El historial recopilado puede ser accedido para lectura utilizando un objeto FBB::ReadLineHistory.

La información específica sobre las facilidades ofrecidas por el software Gnu utilizado por ReadLineBuf se proporciona en la documentación de la Biblioteca GNU Readline (http://cnswww.cns.cwru.edu/php/chet/readline/rltop.html).

La función readline de Gnu lee su información del archivo de entrada estándar. Los programas que usan ReadLineBuf normalmente no deberían extraer información de std::cin. Sin embargo, dado que el archivo de entrada estándar tiene un descriptor de archivo (0), la redirección debería ser posible (por ejemplo, usando FBB::Redirector).

Cuando se mantiene la línea de comandos, se ofrece la expansión del historial como una opción. La expansión del historial introduce palabras de la lista de historial en el flujo de entrada, facilitando la repetición de comandos, la inserción de elementos de una línea de entrada anterior en la línea de entrada actual, o la corrección de errores en líneas de comandos anteriores.

La expansión del historial generalmente se realiza inmediatamente después de leer una línea completa.

La línea seleccionada del historial se llama el evento, y las porciones de esa línea que se procesan se llaman palabras. Varios modificadores están disponibles para manipular las palabras seleccionadas. Esto es comparable a la forma en que un programa como bash(1) divide su línea de entrada en "palabras".

La expansión del historial se introduce mediante el uso del carácter de expansión del historial, por defecto igual al carácter !. Solo la barra invertida (\) y las comillas simples pueden cambiar el carácter de expansión del historial en un carácter normal.

El resto de esta sección se copia casi textualmente de la página del manual history(3). Se remite al lector a esa página del manual o a la documentación de la Biblioteca Gnu History para obtener más detalles.

Los siguientes designadores de eventos son compatibles:

o
!: inicia una sustitución de historial, excepto cuando va seguido de un espacio, salto de línea, = o (.
o
!n: se refiere a la línea de comandos n.
o
!-n: se refiere a la línea de comandos actual menos n.
o
!! se refiere al comando anterior. Esto es un sinónimo de `!-1’.
o
!string se refiere al comando más reciente que comienza con string.
o
!?string[?] se refiere al comando más reciente que contiene string. El signo de interrogación (?) final puede omitirse si string va seguido inmediatamente de un salto de línea.
o
^string1^string2^ (sustitución rápida) repite el último comando, reemplazando string1 con string2. Equivalente a !!:s/string1/string2/.
o
!# toda la línea de comandos escrita hasta ahora.

Designadores de palabras

Los designadores de palabras se utilizan para seleccionar palabras deseadas del evento. Un : separa la especificación del evento del designador de palabras. Puede omitirse si el designador de palabras comienza con ^, $, *, -, o %. Las palabras se numeran desde el principio de la línea, siendo la primera palabra denotada por 0 (cero). Las palabras se insertan en la línea actual separadas por espacios simples.

o
0 (cero) La palabra cero. Para el shell, esta es la palabra del comando.
o
n La palabra n.
o
^ El primer argumento. Es decir, la palabra 1.
o
$ El último argumento.
o
% La palabra que coincide con la búsqueda más reciente ?string?.
o
x-y Un rango de palabras; `-y’ abrevia `0-y’.
o
* Todas las palabras excepto la cero. Esto es un sinónimo de 1-$. No es un error usar * si solo hay una palabra en el evento; en ese caso se devuelve la cadena vacía.
o
x* Abreviatura de x-$.
o
x- Abreviatura de x-$ como x*, pero omite la última palabra. Si se proporciona un designador de palabras sin especificación de evento, se utiliza el comando anterior como evento.

Modificadores

Después del designador de palabras opcional, puede aparecer una secuencia de uno o más de los siguientes modificadores, cada uno precedido por un :.

o
h elimina un componente de nombre de archivo final, dejando solo la cabeza.
o
t elimina todos los componentes de nombre de archivo iniciales, dejando la cola.
o
r elimina un sufijo final de la forma .xxx, dejando el nombre base.
o
e elimina todo excepto el sufijo final.
o
p imprime el nuevo comando pero no lo ejecuta.
o
q pone entre comillas las palabras sustituidas, escapando futuras sustituciones.
o
x pone entre comillas las palabras sustituidas como con q, pero las divide en palabras según los espacios y saltos de línea.
o
s/viejo/nuevo/ sustituye nuevo por la primera ocurrencia de viejo en la línea del evento. Se puede usar cualquier delimitador en lugar de /. El delimitador final es opcional si es el último carácter de la línea del evento. El delimitador puede ser escapado en viejo y nuevo con una barra invertida simple. Si & aparece en nuevo, se reemplaza por viejo. Una barra invertida simple escapará el &. Si viejo es nulo, se establece en el último viejo sustituido, o, si no han ocurrido sustituciones de historial previas, la última cadena en una búsqueda !?string[?].
o
& repite la sustitución anterior.
o
g hace que los cambios se apliquen a toda la línea del evento. Esto se usa en conjunción con :s (por ejemplo, :gs/viejo/nuevo/) o :&. Si se usa con :s, se puede usar cualquier delimitador en lugar de /, y el delimitador final es opcional si es el último carácter de la línea del evento. Una

HEREDA DE

std::streambuf

ENUMERACIONES

El enum Type define los siguientes valores:

o
DONT_EXPAND_HISTORY: no se solicita la expansión del historial;
o
EXPAND_HISTORY: se solicita la expansión del historial.

El enum Expansion proporciona valores de retorno significativos para el proceso de expansión del historial. Sus valores son:

o
DONT_EXEC: la expansión del historial tuvo éxito, pero la línea expandida no debe ser ejecutada. Por ejemplo, después de introducir la línea 
    ls *
la línea 
    !!:p
debería hacer que el programa que lo utiliza muestre, en lugar de ejecutar ls *. Tenga en cuenta que la interpretación de este valor de retorno de expansión no es tarea del objeto ReadLineBuf, sino del programa que utiliza el objeto ReadLineBuf.
o
ERROR: la expansión del historial falló. Véase también el miembro expansionError más abajo;
o
EXPANDED: la expansión del historial tuvo éxito;
o
NO_EXPANSION: no se realizó ninguna expansión del historial.

MIEMBROS ESTÁTICOS

o
ReadLineBuf &initialize(std::string const &prompt = "", Type type = NO_EXPANSION):
Este miembro estático devuelve el ReadLineBuf utilizando un prompt inicial, un historial de como máximo std::numeric_limits<int>::max() líneas, y por defecto no utilizando la expansión del historial. Si el objeto ya ha sido inicializado se lanzará una excepción logic_error.
o
ReadLineBuf &initialize(std::string const &prompt, size_t historySize, Type type = NO_EXPANSION):
Este miembro estático inicializa el ReadLineBuf utilizando un prompt inicial, un historial inicial de un tamaño máximo predefinido, y por defecto no utilizando la expansión del historial. Especificar un tamaño de historial 0 resulta en que no se guarde historial, cualquier valor igual o superior a la constante predefinida std::numeric_limits<int>::max() resulta en un historial de como máximo std::numeric_limits<int>::max() líneas. Si no se solicita historial pero se especifica type como EXPAND_HISTORY se lanzará una excepción logic_error. También se lanzará una logic_error si el objeto ya ha sido inicializado.
o
ReadLineBuf &instance():
Este miembro estático devuelve el objeto ReadLineBuf ya inicializado. Si el objeto aún no ha sido inicializado se lanzará una excepción logic_error.

CONSTRUCTORES

Como la clase ReadLineBuf es una clase singleton, no ofrece constructores públicos, ni tampoco están disponibles operadores de asignación sobrecargados.

FUNCIONES MIEMBRO

Todos los miembros de std::streambuf están disponibles, ya que FBB::ReadLineBuf hereda de esta clase.

o
ReadLineBuf::Expansion expansion() const:
Se devuelve el estado de la expansión del historial después de recuperar una línea de la terminal. Su valor se determina después de cada línea recuperada de la terminal. Si no se solicita expansión del historial, devuelve Expansion::ERROR.
o
std::string const &expansionError() const:
Se devuelve una descripción textual corta de la naturaleza del error cuando expansion devuelve Expansion::ERROR. Si no se solicita expansión del historial, se devuelve una cadena vacía.
o
bool setExpansion(Type type):
La expansión del historial se puede activar o detener utilizando este miembro. Cuando se solicita la expansión del historial pero el objeto ReadLineBuf no mantiene ningún historial, la función devuelve false. De lo contrario, devuelve true.
o
void setPrompt(std::string const &prompt = ""):
El prompt que se muestra delante de la siguiente línea leída de la terminal puede ser modificado por este miembro. Cuando se llama sin argumentos, no se mostrará ningún prompt. setPrompt se puede llamar mientras se están recibiendo líneas de entrada. El nuevo prompt estará activo después de que la línea actual haya sido leída de la terminal.
o
bool useTimestamps(std::string (*timestamp)() = 0):
Cuando se inicializa con la dirección de una función que devuelve un std::string, a los comandos introducidos se les asignará una marca de tiempo igual al texto devuelto por la función apuntada por timestamp. Las marcas de tiempo se pueden recuperar utilizando el objeto ReadLineHistory(3). Por defecto o después de pasar un puntero 0 explícito a useTimestamps, no se almacenan marcas de tiempo. El valor false se devuelve cuando no se mantiene historial, de lo contrario, se devuelve true.

EJEMPLO

#include <iostream>
#include <istream>
#include <cstdio>
#include <sstream>
#include <iomanip>
#include <bobcat/readlinebuf>
//#include "../readlinebuf"
using namespace std;
using namespace FBB;
int main()
{
    ReadLineBuf &readlineBuf =
            ReadLineBuf::initialize("", 10, ReadLineBuf::EXPAND_HISTORY);
    istream in(&readlineBuf);
    size_t count = 0;
    string line;
    while (true)
    {
        ostringstream prompt;
        prompt << setw(2) << ++count << ": ";
        readlineBuf.setPrompt(prompt.str());
        if (!getline(in, line))          // usa el último prompt establecido
            break;
        cout << "Recuperado: " << line << "\n"
                "Estado de la expansión: ";
        switch (readlineBuf.expansion())
        {
            case ReadLineBuf::ERROR:
                cout << "ERROR: " << readlineBuf.expansionError() << ’\n’;
            break;
            case ReadLineBuf::NO_EXPANSION:
                cout << "no se realizó expansión\n";
            break;
            case ReadLineBuf::DONT_EXEC:
                cout << "no ejecutar la línea expandida\n";
            break;
            case ReadLineBuf::EXPANDED:
                cout << "expansión realizada con éxito\n";
            break;
        }
    }
}
