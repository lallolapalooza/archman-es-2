RECOVER(6) Manual de Juegos RECOVER(6)

NOMBRE

recover - recuperar una partida de NetHack interrumpida por un desastre

SINOPSIS

recover [ -d directorio ] base1 base2 ...

DESCRIPCIÓN

Ocasionalmente, una partida de NetHack se interrumpe por un desastre cuando el juego o el sistema se cuelga. Antes de NetHack v3.1, estas partidas se perdían porque diversa información como el inventario del jugador se mantenía solo en memoria. Ahora, toda la información pertinente se puede escribir en disco, por lo que tales partidas se pueden recuperar en el punto del último cambio de nivel.

Las opciones base le indican a recover qué archivos procesar. Cada opción base especifica la recuperación de una partida separada.

La opción -d, que debe ser el primer argumento si aparece, proporciona un directorio que es el área de juego de NetHack. Anula el valor de NETHACKDIR, HACKDIR, o el directorio especificado por el administrador del juego durante la compilación (generalmente /usr/games/lib/nethackdir).

Para que la recuperación sea posible, nethack debe haber sido compilado con la opción INSURANCE (esa configuración fue), y la opción en tiempo de ejecución checkpoint también debe haber estado activada. NetHack normalmente escribe archivos para los niveles a medida que el jugador los abandona, para que estén listos para visitas posteriores. Al usar checkpointing, NetHack también escribe el nivel entrado y el estado actual del juego en cada cambio de nivel. Esto naturalmente ralentiza un poco los cambios de nivel.

Los nombres de los archivos de nivel tienen el formato base.nn, donde nn es un número interno de contabilidad para el nivel. El archivo base.0 se utiliza para la identidad del juego, el bloqueo y, cuando se usa checkpointing, para el estado del juego. Varios sistemas operativos utilizan diferentes estrategias para construir el nombre base. Los microordenadores usan el nombre del personaje, posiblemente truncado y modificado para ser un nombre de archivo legal en ese sistema. Los sistemas multiusuario utilizan el nombre del personaje (modificado) precedido por un número de usuario para evitar conflictos, o "xlock" si se limita el número de jugadores concurrentes. Puede ser necesario buscar en el área de juego para encontrar el nombre base correcto de la partida interrumpida. recover transformará estos archivos de nivel en un archivo de guardado del mismo nombre que usaría nethack.

Dado que recover debe poder leer y eliminar archivos del área de juego y crear archivos en el directorio de guardado, tiene interacciones interesantes con la seguridad del juego. Dar acceso a usuarios ordinarios a recover a través de setuid o setgid equivale a dejar el área de juego escribible por todo el mundo, con respecto a hacer trampas y estropear partidas de otros jugadores. Para un sistema monousuario, esto por supuesto no cambia nada, por lo que algunos de los puertos para microordenadores instalan recover por defecto.

Para un sistema multiusuario, el administrador del juego puede querer organizar que todos los archivos .0 en el área de juego se alimenten a recover al arrancar la máquina anfitriona, y manejar las caídas del juego individualmente. Si la población de usuarios es lo suficientemente confiable, recover puede instalarse con los mismos permisos que tiene el ejecutable nethack. En cualquier caso, recover se compila fácilmente desde el directorio de utilidades de la distribución.

NOTAS

Al igual que el propio nethack, recover sobrescribirá los archivos de guardado existentes del mismo nombre. Los archivos de guardado creados por recover no están comprimidos; pueden comprimirse posteriormente si se desea, pero incluso un nethack que use compresión los encontrará en formato sin comprimir.

VER TAMBIÉN

nethack(6)

ERRORES

recover no intenta averiguar si un nombre base especifica una partida en progreso. Si múltiples máquinas comparten un área de juego, esto sería imposible de determinar.

recover debería enseñarse a usar el mecanismo de bloqueo del área de juego de nethack para evitar conflictos.
