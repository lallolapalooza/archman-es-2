NOMBRE

repart.d - Archivos de Definición de Partición para Reparticionamiento Automático al Inicio

SINOPSIS

/etc/repart.d/*.conf
/run/repart.d/*.conf
/usr/local/lib/repart.d/*.conf
/usr/lib/repart.d/*.conf

DESCRIPCIÓN

Los archivos repart.d/*.conf describen las propiedades básicas de las particiones de los dispositivos de bloque del sistema local. Pueden ser utilizados para declarar tipos, nombres y tamaños de particiones que deberían existir. El servicio systemd-repart(8) lee estos archivos e intenta añadir particiones nuevas que faltan y expandir las particiones existentes de acuerdo con estas definiciones. La operación es generalmente incremental, es decir, cuando se aplican, lo que ya existe se deja intacto, y las particiones nunca se reducen, mueven o eliminan.

Estos archivos de definición son útiles para implementar imágenes de sistemas operativos que se preparan y distribuyen con imágenes de tamaño mínimo (por ejemplo, carentes de particiones de estado o de intercambio), y que al primer arranque toman posesión automáticamente de cualquier espacio restante en el disco siguiendo unas pocas reglas básicas.

Actualmente, el soporte para archivos de definición de partición solo está implementado para tablas de partición GPT.

Los archivos de partición generalmente se comparan con las particiones que ya existen en el disco en un algoritmo simple: los archivos de partición se ordenan por su nombre de archivo (ignorando el prefijo del directorio) y luego se comparan en orden contra las particiones existentes que coinciden con el mismo UUID de tipo de partición. Específicamente, la primera partición existente con un UUID de tipo de partición específico se asigna al primer archivo de definición con el mismo UUID de tipo de partición, y la segunda partición existente con un tipo de UUID a la segunda partición del archivo con el mismo tipo de UUID, y así sucesivamente. Cualquier archivo de partición sobrante que no tenga una partición existente coincidente se asume que define una nueva partición que debe crearse. Dichas particiones se añaden al final de la tabla de particiones, en el orden definido por sus nombres utilizando el primer espacio de partición mayor que el número de espacio más alto actualmente en uso. Cualquier partición existente que no tenga un archivo de partición coincidente se deja como está.

Tenga en cuenta que estas definiciones solo pueden usarse para crear e inicializar particiones nuevas o para expandir las existentes. En este último caso, sin embargo, no expandirá los sistemas de archivos contenidos; se pueden utilizar mecanismos separados, como systemd-growfs(8), para expandir los sistemas de archivos dentro de estas particiones. Las particiones también pueden marcarse para expansión automática mediante la opción GrowFileSystem=, en cuyo caso el sistema de archivos se expande en el primer montaje por herramientas que respetan esta bandera. Ver más abajo para más detalles.

Añadido en la versión 245.

Peso=

Un peso numérico a asignar a esta partición en el rango 0...1000000. El espacio de disco disponible se asigna a las particiones definidas según sus pesos relativos (sujeto a las restricciones de tamaño configuradas con TamañoMínimoPorBytes=, TamañoMáximoPorBytes=), de modo que una partición con peso 2000 recibe el doble de espacio que una con peso 1000, y una partición con peso 333 un tercio de eso. Por defecto es 1000.

La configuración Peso= se utiliza para distribuir el espacio de disco disponible de forma "elástica", basándose en el tamaño del disco y las particiones existentes. Si una partición debe tener un tamaño fijo, utilice tanto TamañoMínimoPorBytes= como TamañoMáximoPorBytes= con el mismo valor para fijar el tamaño a un valor, en cuyo caso el peso no tiene ningún efecto.

Añadido en la versión 245.

PesoRelleno=

Similar a Peso=, pero establece un peso para el espacio libre después de la partición (el "relleno"). Al distribuir el espacio disponible, se suman los pesos de todas las particiones y todo el relleno definido, y luego cada partición y relleno recibe la fracción definida por su peso. Por defecto es 0, es decir, por defecto no se aplica relleno.

El relleno es útil si se debe dejar espacio vacío para adiciones posteriores o un margen de seguridad al final del dispositivo o entre particiones.

Añadido en la versión 245.

TamañoMínimoPorBytes=, TamañoMáximoPorBytes=

Especifica restricciones de tamaño mínimo y máximo en bytes. Acepta los sufijos habituales K, M, G, T, ... (en base 1024). Si se especifica TamañoMínimoPorBytes=, la partición se crea o se amplía a al menos el tamaño especificado. Si se especifica TamañoMáximoPorBytes=, la partición se crea o se amplía a como máximo el tamaño especificado. El tamaño exacto se determina a través del valor de peso configurado con Peso=, véase más arriba. Cuando TamañoMínimoPorBytes= se establece igual a TamañoMáximoPorBytes=, el peso configurado no tiene efecto, ya que la partición se dimensiona explícitamente al valor fijo especificado. Tenga en cuenta que las particiones nunca se crean más pequeñas que 4096 bytes, y dado que las particiones nunca se reducen, el tamaño anterior de la partición (en caso de que la partición ya exista) también se aplica como límite inferior para el nuevo tamaño. Los valores deben especificarse como múltiplos de 4096 bytes y se redondean hacia arriba (en caso de TamañoMínimoPorBytes=) o hacia abajo (en caso de TamañoMáximoPorBytes=) en caso contrario. Si el dispositivo de respaldo no proporciona suficiente espacio para cumplir las restricciones, la colocación de la partición fallará. Para las particiones que deban crearse, dependiendo de la configuración de Prioridad= (véase más arriba), la partición podría ser descartada y el algoritmo de colocación reiniciado. Por defecto, se establece una restricción de tamaño mínimo de 10M y ninguna restricción de tamaño máximo.

Si se establece Formato=, el tamaño mínimo se incrementa automáticamente al tamaño mínimo del sistema de archivos para el tipo de sistema de archivos seleccionado, si se conoce. Además, para las particiones ESP/XBOOTLDR, el mínimo se incrementa a 100M (para imágenes de sector de 512b) o 260M (para imágenes de sector de 4K) automáticamente, si se especifica un valor menor.

Añadido en la versión 245.

RellenoMínimoPorBytes=, RellenoMáximoPorBytes=

Especifica restricciones de tamaño mínimo y máximo en bytes para el espacio libre después de la partición (el "relleno"). La semántica es similar a TamañoMínimoPorBytes= y TamañoMáximoPorBytes=, excepto que, a diferencia de los tamaños de partición, el espacio libre se puede reducir y puede ser tan pequeño como cero. Por defecto, no se establecen restricciones de tamaño para el relleno, por lo que solo PesoRelleno= determina el tamaño del relleno aplicado.

Añadido en la versión 245.

CopiarBloques=

Toma una ruta a un archivo regular, un nodo de dispositivo de bloque, un nodo de dispositivo de carácter o un directorio, o el valor especial "auto". Si se especifica y la partición se crea de nuevo, los datos de la ruta especificada se escriben en la partición recién creada, a nivel de bloque. Si se especifica un directorio, se determina el dispositivo de bloque de respaldo del sistema de archivos en el que se encuentra el directorio, y los datos se leen directamente de él. Esta opción es útil para replicar eficientemente sistemas de archivos existentes en nuevas particiones a nivel de bloque, por ejemplo, para construir un instalador de sistema operativo simple o un generador de imágenes de sistema operativo. Especifique /dev/urandom como valor para inicializar una partición con datos aleatorios.

Si se especifica el valor especial "auto", la fuente para copiar se selecciona automáticamente del sistema en ejecución (o de la imagen especificada con --image=, si se utiliza). Se determina una partición que coincide tanto con el tipo de partición configurado (tal como se declara con Tipo= descrito anteriormente), como con el directorio montado actualmente apropiado para ese tipo de partición. Por ejemplo, si el tipo de partición se establece en "root", la partición que respalda el directorio raíz (/) se utiliza como fuente para copiar, si su tipo de partición también se establece en "root". Si el tipo declarado es "usr", la partición que respalda /usr/ se utiliza como fuente para copiar bloques, si su tipo de partición también se establece en "usr". La lógica es capaz de rastrear automáticamente las particiones de respaldo para volúmenes cifrados y habilitados para Verity. "CopiarBloques=auto" es útil para implementar sistemas "auto-replicantes", es decir, sistemas que son su propio instalador.

El archivo especificado aquí debe tener un tamaño que sea múltiplo del tamaño de bloque básico de 512 y no estar vacío. Si se utiliza esta opción, el algoritmo de asignación de tamaño se modifica ligeramente: la partición se crea al menos tan grande como sea necesario para albergar los datos, es decir, el tamaño de los datos es un valor de tamaño mínimo adicional que se tiene en cuenta para el algoritmo de asignación, similar y adicional al valor TamañoMínimo= configurado anteriormente.

Esta opción no tiene ningún efecto si la partición ya existe, es decir, los datos existentes nunca se sobrescriben. Tenga en cuenta que los datos se copian antes de que se actualice la tabla de particiones, es decir, antes de que la partición se cree realmente de forma persistente. Esto proporciona robustez: se garantiza que la partición no existe o existe completamente poblada; no es posible que la partición exista pero no esté poblada o solo parcialmente poblada.

Esta opción no se puede combinar con Formato= o CopiarArchivos=.

Añadido en la versión 246.

Formato=

Toma un nombre de sistema de archivos, como "ext4", "btrfs", "xfs", "vfat", "erofs", "squashfs" o el valor especial "swap". Si se especifica y la partición se crea de nuevo, se formatea con el sistema de archivos especificado (o como dispositivo swap). El UUID y la etiqueta del sistema de archivos se derivan automáticamente del UUID y la etiqueta de la partición. Si se utiliza esta opción, el algoritmo de asignación de tamaño se modifica ligeramente: la partición se crea al menos tan grande como sea necesario para el sistema de archivos mínimo del tipo especificado (o 4KiB si el tamaño mínimo no se conoce).

Esto también toma un valor meta especial "vacío". Si se especifica, es equivalente a especificar "Etiqueta=_vacío" y "NoAuto=1".

Esta opción no tiene ningún efecto si la partición ya existe.

De manera similar al comportamiento de CopiarBloques=, el sistema de archivos se formatea antes de que se cree la partición, asegurando que la partición solo exista con un sistema de archivos completamente inicializado.

Esta opción no se puede combinar con CopiarBloques=.

Añadido en la versión 247.

CopiarArchivos=

Toma un triplete separado por dos puntos en la forma "fuente[:destino[:opciones]]". fuente es una ruta absoluta que se refiere a un archivo o directorio de origen en el host. destino es una ruta absoluta en el sistema de archivos de la partición recién creada y el sistema de archivos formateado. opciones es una lista separada por comas de opciones donde cada opción tiene el formato "clave[=valor]".

Esta configuración se puede utilizar para copiar archivos o directorios del host al sistema de archivos que se crea debido a la opción Formato=. Si se utiliza CopiarArchivos= sin Formato= especificado explícitamente, se implica "Formato=" con un valor predeterminado adecuado (actualmente "vfat" para particiones "ESP" y "XBOOTLDR", y "ext4" en caso contrario, pero esto puede cambiar en el futuro). Esta opción se puede utilizar varias veces para copiar varios archivos o directorios del host al sistema de archivos recién formateado.

La ruta de destino puede omitirse, en cuyo caso la ruta de fuente también se utiliza como ruta de destino (relativa a la raíz del sistema de archivos recién creado). Si la ruta de origen se refiere a un directorio, se copia recursivamente.

Las opciones pueden contener los siguientes valores:

fsverity=

Se puede establecer en el valor "off" (el valor predeterminado si la opción no está presente) o "copy". Si se establece en "off", ningún archivo copiado en el sistema de archivos desde esta fuente tendrá fs-verity habilitado. Si se establece en "copy", la información de fs-verity para cada archivo se copiará del archivo de origen correspondiente.

Añadido en la versión 258.

Esta opción no tiene ningún efecto si la partición ya existe: no se puede utilizar para copiar archivos adicionales en una partición existente, solo se puede utilizar para poblar un sistema de archivos creado de nuevo.

La operación de copia se ejecuta antes de que el sistema de archivos se registre en la tabla de particiones, lo que garantiza que un sistema de archivos poblado de esta manera solo exista completamente inicializado.

Tenga en cuenta que CopiarArchivos= omitirá la copia de archivos que no son compatibles con el sistema de archivos de destino (por ejemplo, enlaces simbólicos, fifos, sockets y dispositivos en vfat). Cuando se encuentra un tipo de archivo no compatible, systemd-repart omitirá la copia de este archivo y escribirá un mensaje de registro al respecto.

Tenga en cuenta que systemd-repart no cambia los UID/GID de los archivos y directorios copiados. Al ejecutar systemd-repart como un usuario no privilegiado para crear una imagen de archivos y directorios propiedad del mismo usuario, puede ejecutar systemd-repart en un espacio de nombres de usuario con el usuario actual mapeado al usuario root.para asegurar que los archivos y directorios en la imagen sean propiedad del usuario root.

Tenga en cuenta que al poblar sistemas de archivos XFS con systemd-repart y cuando los dispositivos de bucle no están disponibles, poblar sistemas de archivos XFS con archivos que contienen espacios, tabulaciones o saltos de línea puede fallar en versiones antiguas de mkfs.xfs(8) debido a limitaciones de su formato de archivo proto.

Tenga en cuenta que al poblar sistemas de archivos XFS con systemd-repart y cuando los dispositivos de bucle no están disponibles, los atributos extendidos no se copiarán en los sistemas de archivos XFS generados debido a las limitaciones del formato de archivo proto de mkfs.xfs(8).

Esta opción no se puede combinar con CopyBlocks=.

Cuando systemd-repart(8) se invoca con el interruptor de línea de comandos --copy-source=, las rutas de los archivos se toman relativas al directorio especificado. Si no se utiliza --copy-source=, pero se utilizan los interruptores --image= o --root=, las rutas de origen se toman relativas al directorio raíz especificado o a la raíz de la imagen de disco.

ExcludeFiles=, ExcludeFilesTarget=

Toma una o más rutas absolutas, separadas por espacios en blanco, cada una refiriéndose a un archivo o directorio de origen en el host. Esta configuración puede usarse para excluir archivos o directorios del host de ser copiados en el sistema de archivos cuando se usa CopyFiles=. Esta opción puede usarse varias veces para excluir múltiples archivos o directorios del host de ser copiados en el sistema de archivos recién formateado.

Si la ruta es un directorio y termina en "/", solo se excluyen los contenidos del directorio pero no el directorio en sí. Si la ruta es un directorio y no termina en "/", tanto el directorio como sus contenidos se excluyen.

ExcludeFilesTarget= es como ExcludeFiles=, excepto que en lugar de excluir la ruta en el host de ser copiada en la partición, excluye cualquier archivo y directorio de ser copiado en la ruta dada en la partición.

Cuando systemd-repart(8) se invoca con los interruptores de línea de comandos --image= o --root=, las rutas especificadas se toman relativas al directorio raíz especificado o a la raíz de la imagen de disco.

Añadido en la versión 254.

MakeDirectories=

Toma uno o más rutas absolutas, separadas por espacios en blanco, cada una declarando un directorio a crear dentro del nuevo sistema de archivos. El comportamiento es similar a CopyFiles=, pero en lugar de copiar un conjunto de archivos, solo crea los directorios especificados con el modo predeterminado de 0755 propiedad del usuario y grupo root, más todos sus directorios padre (con la misma propiedad y modo de acceso). Para configurar directorios con diferente propiedad o modo de acceso, use CopyFiles= y especifique un árbol de origen a copiar que contenga directorios apropiadamente propiedad/configurados. Esta opción puede usarse más de una vez para crear múltiples directorios. Cuando CopyFiles= y MakeDirectories= se usan juntos, el primero se aplica primero. Si un directorio listado ya existe, no se realiza ninguna operación (en particular, la propiedad/modo de acceso de los directorios se deja como está).

El caso de uso principal para esta opción es crear un conjunto mínimo de directorios que puedan ser montados por encima por otras particiones contenidas en la misma imagen de disco. Por ejemplo, una imagen de disco donde el sistema de archivos raíz se formatea al arrancar por primera vez podría querer precrear automáticamente /usr/ en ella de esta manera, para que la partición "usr" pueda sobremontarla.

Considere usar systemd-tmpfiles(8) con su opción --image= para precrear otras jerarquías de directorios más complejas (así como otros inodos) con un control detallado de la propiedad, modos de acceso y otros atributos de archivo.

Añadido en la versión 249.

MakeSymlinks=

Toma uno o más argumentos, separados por espacios en blanco, cada uno declarando un enlace simbólico a crear dentro del nuevo sistema de archivos. Cada argumento es un par de rutas de origen y destino del enlace simbólico, separadas por dos puntos. Esta opción puede usarse más de una vez para crear múltiples enlaces simbólicos. Cuando CopyFiles= y MakeSymlinks= se usan juntos, el primero se aplica primero.

El caso de uso principal para esta opción es crear enlaces simbólicos que necesiten existir antes de que se ejecute systemd-tmpfiles(8). Por ejemplo, al usar systemd-confext(8), esta configuración puede usarse para crear enlaces simbólicos en /var/lib/extensions.mutable para redirigir escrituras a confexts mutables a una ubicación personalizada.

Considere usar systemd-tmpfiles(8) con su opción --image= para precrear otros enlaces simbólicos (así como otros inodos) con un control detallado de la propiedad, modos de acceso y otros atributos de archivo.

DefaultSubvolume=

Toma una ruta absoluta que especifica el subvolumen predeterminado dentro del nuevo sistema de archivos. Tenga en cuenta que esta configuración no crea el subvolumen en sí, que se puede configurar con Subvolumes=.

Tenga en cuenta que esta opción solo tiene efecto si el sistema de archivos de destino soporta subvolúmenes, como btrfs(8).

Tenga en cuenta que esta opción solo se admite en combinación con --offline=yes desde btrfs-progs 6.12 o más reciente.

Añadido en la versión 256.

Encrypt=

Toma uno de "off", "key-file", "tpm2" y "key-file+tpm2" (alternativamente, también acepta un valor booleano, que se mapea a "off" cuando es falso, y a "key-file" cuando es verdadero). Predeterminado a "off". Si no es "off", la partición se formateará con una superbloque LUKS2, antes de que se copien los bloques configurados con CopyBlocks= o se cree el sistema de archivos configurado con Format=.

La UUID de LUKS2 se deriva automáticamente de la UUID de la partición de forma estable. Si se usa "key-file" o "key-file+tpm2", se añade una clave a la superbloque LUKS2, configurable con la opción --key-file= de systemd-repart. Si se usa "tpm2" o "key-file+tpm2", se añade una clave a la superbloque LUKS2 que se registra en el chip TPM2 local, según lo configurado con las opciones --tpm2-device= y --tpm2-pcrs= de systemd-repart.

Cuando se usa, esto altera ligeramente la lógica de asignación de tamaño, ya que los límites de tamaño implícitos y mínimos de Format= y CopyBlocks= se incrementan por el espacio necesario para la superbloque LUKS2 (ver arriba).

Esta opción no tiene efecto si la partición ya existe.

Añadido en la versión 247.

Verity=

Toma uno de "off", "data", "hash" o "signature". Predeterminado a "off". Si se establece a "off" o "data", la partición se puebla con contenido según lo especificado por CopyBlocks= o CopyFiles=. Si se establece a "hash", la partición se poblará con hashes de veracidad de la partición de datos de veracidad coincidente. Si se establece a "signature", la partición se poblará con un objeto JSON que contiene una firma del hash raíz de veracidad de la partición de hash de veracidad coincidente.

Una partición de veracidad coincidente es una partición con la misma clave de coincidencia de veracidad (según lo configurado con VerityMatchKey=).

Si no se configura explícitamente, la UUID de la partición de datos se establecerá en los primeros 128 bits del hash raíz de veracidad. De manera similar, si no se configura, la UUID de la partición de hash se establecerá en los últimos 128 bits del hash raíz de veracidad. El hash raíz de veracidad en sí se incluirá en la salida de systemd-repart.

Esta opción no tiene efecto si la partición ya existe.

El uso de esta opción en combinación con Encrypt= no es compatible.

Para cada valor único de VerityMatchKey=, se debe definir una única partición de datos de veracidad ("Verity=data") y una única partición de hash de veracidad ("Verity=hash").

Añadido en la versión 252.

VerityMatchKey=

Toma una cadena identificadora corta elegida por el usuario. Esta configuración se usa para encontrar particiones de veracidad hermanas para la partición de veracidad actual. Ver la descripción de Verity=.

Añadido en la versión 252.

VerityDataBlockSizeBytes=

Configura el tamaño del bloque de datos de la partición de hash de veracidad generada. Debe estar entre 512 y 4096 bytes y debe ser una potencia de 2. Predeterminado al tamaño del sector si se configura explícitamente, o al tamaño del sector del dispositivo de bloque subyacente, o 4K si systemd-repart no está operando en un dispositivo de bloque.

Añadido en la versión 255.

VerityHashBlockSizeBytes=

Configura el tamaño del bloque de hash de la partición de hash de veracidad generada. Debe estar entre 512 y 4096 bytes y debe ser una potencia de 2. Predeterminado al tamaño del sector si se configura explícitamente, o al tamaño del sector del dispositivo de bloque subyacente, o 4K si systemd-repart no está operando en un dispositivo de bloque.

Añadido en la versión 255.

FactoryReset=

Toma un argumento booleano. Si se especifica, la partición se marca para su eliminación durante una operación de restablecimiento de fábrica. Esta funcionalidad es útil para implementar esquemas donde las imágenes se pueden restablecer a su estado original eliminando particiones y creándolas de nuevo. Predeterminado a apagado.

Añadido en la versión 245.

Flags=

Configura el campo de 64 bits de indicadores de partición GPT para establecer para la partición al crearla. Esta opción no tiene efecto si la partición ya existe. Si no se especifica, el valor de los indicadores se establece en todos ceros, excepto para los tres bits que también se pueden configurar a través de NoAuto=, ReadOnly= y GrowFileSystem=; véase más abajo para detalles sobre los valores predeterminados de estas tres banderas. Especifique el valor de las banderas en hexadecimal (prefijándolo con "0x"), binario (prefijo "0b") o decimal (sin prefijo).

Añadido en la versión 249.

NoAuto=, ReadOnly=, GrowFileSystem=

Configura las banderas de partición No-Auto, Read-Only y Grow-File-System (bit 63, 60 y 59) de la entrada de la tabla de particiones, según se define en la **Especificación de Particiones Descubribles**[1]. Solo disponible para tipos de partición compatibles con la especificación. Esta opción es una forma amigable de establecer los bits 63, 60 y 59 del valor de las banderas de partición sin establecer ningún otro bit, y también puede configurarse mediante Flags=, véase más arriba.

Si Flags= se utiliza junto con una o más de las opciones NoAuto=/ReadOnly=/GrowFileSystem=, estas últimas controlan el valor de las banderas relevantes, es decir, las configuraciones de alto nivel NoAuto=/ReadOnly=/GrowFileSystem= anulan los bits relevantes de la configuración de bajo nivel Flags=.

Tenga en cuenta que las tres banderas afectan solo al montaje automático de particiones, tal como lo implementa systemd-gpt-auto-generator(8) o la opción --image= de varios comandos (como systemd-nspawn(1)). No tiene ningún efecto en los montajes explícitos, como los realizados mediante mount(8) o fstab(5).

Si se establecen tanto el bit 60 como el 59 para una partición (es decir, la partición está marcada como de solo lectura y marcada para el crecimiento del sistema de archivos), la última opción generalmente no tiene efecto: la bandera de solo lectura tiene prioridad en la mayoría de las herramientas que leen estas banderas, y dado que el crecimiento del sistema de archivos implica escribir en la partición, se ignora en consecuencia.

NoAuto= está desactivado por defecto. ReadOnly= está activado por defecto para los tipos de partición Verity, y desactivado para todos los demás. GrowFileSystem= está activado por defecto para todos los tipos de partición que lo admiten, excepto si la partición está marcada como de solo lectura (y, por lo tanto, por defecto está desactivado para las particiones Verity).

Añadido en la versión 249.

SplitName=

Configura el sufijo a añadir a los artefactos divididos cuando se utiliza la opción --split de systemd-repart(8). Se admite la expansión de especificadores simples, véase más abajo. El valor predeterminado es "%t". Para deshabilitar la generación de artefactos divididos para una partición, establezca SplitName= en "-".

Añadido en la versión 252.

Minimize=

Acepta uno de los valores "off", "best" y "guess" (alternativamente, también acepta un valor booleano, que se mapea a "off" cuando es falso y a "best" cuando es verdadero). El valor predeterminado es "off". Si se establece en "best", la partición tendrá el tamaño mínimo necesario para almacenar las fuentes configuradas con CopyFiles=. "best" actualmente solo es compatible con sistemas de archivos de solo lectura. Si se establece en "guess", la partición se crea al menos tan grande como sea necesario para almacenar las fuentes configuradas con CopyFiles=. Tenga en cuenta que a menos que el sistema de archivos sea de solo lectura, systemd-repart tendrá que poblar el sistema de archivos dos veces para adivinar el tamaño mínimo requerido, por lo que habilitar esta opción puede ralentizar la reparepartición al poblar particiones grandes.

Añadido en la versión 253.

MountPoint=

Especifica dónde y cómo debe montarse la partición. Acepta al menos un campo y como máximo dos campos separados por dos puntos (":"). El primer campo especifica dónde debe montarse la partición. El segundo campo especifica opciones de montaje adicionales que se añadirán a las opciones de montaje predeterminadas. Estos campos corresponden a la segunda y cuarta columna del formato fstab(5). Dado que se utilizan dos puntos para separar campos, cada campo debe entrecomillarse si contiene dos puntos. Por ejemplo: 
MountPoint="/path/with:colon":"zstd:1,noatime,lazytime"

Esta configuración puede especificarse varias veces para montar la partición varias veces. Esto se puede utilizar para añadir montajes para diferentes subvolúmenes de btrfs(8) ubicados en la misma partición btrfs.

SupplementFor=

Acepta un nombre de definición de partición, como "10-esp". Si se especifica, systemd-repart evitará crear esta partición y en su lugar preferirá fusionar parcialmente las dos definiciones. Sin embargo, dependiendo de la disposición existente de las particiones en el disco, systemd-repart puede verse obligado a volver a las definiciones sin fusionar y utilizarlas tal como están escritas originalmente, creando potencialmente esta partición. Específicamente, systemd-repart retrocederá si esta partición ya existe en el disco, o si la partición de destino ya existe en el disco pero es demasiado pequeña, o si no puede asignar espacio para la partición fusionada por alguna otra razón.

Los siguientes campos se fusionan en la definición de destino de las siguientes maneras: Weight= y PaddingWeight= simplemente se sobrescriben; SizeMinBytes= y PaddingMinBytes= utilizan el mayor de los dos valores; SizeMaxBytes= y PaddingMaxBytes= utilizan el valor más pequeño; y CopyFiles=, ExcludeFiles=, ExcludeFilesTarget=, MakeDirectories= y Subvolumes= se concatenan.

El uso de esta opción en combinación con CopyBlocks=, Encrypt= o Verity= no es compatible. La definición de destino tampoco puede establecer estas configuraciones. Una definición no puede ser simultáneamente un suplemento y actuar como destino para alguna otra definición de suplemento. Un destino no puede tener más de una partición suplementaria asociada.

Por ejemplo, las distribuciones pueden usar esto para implementar $BOOT según se define en la **Especificación del Cargador de Arranque**[2]. Las distribuciones pueden preferir usar la ESP como $BOOT siempre que sea posible, pero para cumplir con la especificación, a veces se debe usar XBOOTLDR. Por lo tanto, deben crear dos definiciones: la primera que define una ESP lo suficientemente grande como para contener solo el cargador de arranque, y la segunda para XBOOTLDR que sea lo suficientemente grande como para contener los kernels y configurada como un suplemento para la ESP. Siempre que sea posible, systemd-repart(8) intentará fusionar las dos definiciones para crear una ESP grande, pero si eso no es admisible debido a las condiciones existentes en el disco, se crearán una ESP pequeña y una XBOOTLDR grande.

Como otro ejemplo, las distribuciones también pueden usar esto para compartir sin problemas una única partición /home en un escenario de arranque múltiple, mientras prefieren mantener /home en la partición raíz por defecto. Tener una partición /home separada de la partición raíz implica cierta complejidad adicional: alguien tiene que decidir cómo dividir el espacio entre las dos particiones. Por otro lado, permite a un usuario compartir su área de inicio entre varios sistemas operativos instalados (es decir, a través de systemd-homed.service(8)). Las distribuciones deben crear dos definiciones: la primera para una partición raíz que ocupe un porcentaje relativamente pequeño del disco, y la segunda como suplemento de la primera para crear una partición /home que ocupe todo el espacio libre restante. En el primer arranque, si systemd-repart encuentra una partición /home existente en el disco, descomprimirá las definiciones y creará solo una partición raíz pequeña. De lo contrario, las definiciones se fusionarán y se creará una única partición raíz grande.

Añadido en la versión 257.

AddValidateFS=

Acepta un argumento booleano. Si está habilitado, establecerá los atributos extendidos user.validatefs.gpt_label, user.validatefs.gpt_type_uuid y user.validatefs.mount_point en el inodo raíz del sistema de archivos formateado con las etiquetas de partición, los UUID de tipo de partición y el punto de montaje previsto para el sistema de archivos. Por defecto está habilitado si se utiliza Format= y el argumento especificado no es "swap" ni "vfat".

Estos atributos extendidos son leídos por systemd-validatefs@.service(8) y pueden codificar restricciones en los fi montadosle systems that must be fulfilled for the system to successfully boot. This is particular important in systemd-gpt-auto-generator(8) scenarios, which puts together the mount hierarchy from untrusted data from the GPT partition table. As these extended attributes are stored inside the file system, they are typically authenticated as part of the file system (assuming it is contained in protected volume; i.e. LUKS or dm-verity), and hence may be used to securely validate the matching partition table fields.

Added in version 258.

FileSystemSectorSize=

Controls the sector size for any file system, LUKS volume or Verity volume formatted on this partition. Expects a power of 2 as value, and must be equal or larger than 512. Typically it's recommended to set the file system sector size to 4096, even on 512 sector disks (and in particular for images that are only ever intended to be stored as file on disks), in order to optimize performance. However, for compatibility with foreign operating systems or firmware it might be advisable to use the native sector size of the backing disk.

If unspecified and operating on a block device, defaults to the native sector size of the device. If unspecified and operating on a disk image file defaults to 4096.

Regardless of what is configured here, or which default is picked, the file system sector size is always increased to be equal or larger than the disk sector size.

Added in version 258.

EJEMPLOS

Ejemplo 1. Redimensionar la partición raíz al tamaño completo del disco en el primer arranque

Con el siguiente archivo, la partición raíz se redimensiona automáticamente al tamaño completo del disco si es posible durante el arranque.

# /usr/lib/repart.d/50-root.conf
[Partition]
Type=root

Ejemplo 2. Crear particiones de intercambio y de inicio automáticamente al arrancar, si faltan

La partición de inicio ocupa todo el espacio disponible en el disco, mientras que la partición de intercambio ocupa como máximo 1G y como mínimo 64M. Establecemos una prioridad > 0 en la partición de intercambio para asegurar que no se utilice si no hay suficiente espacio disponible. Por cada tres bytes asignados a la partición de inicio, la partición de intercambio recibe uno.

# /usr/lib/repart.d/60-home.conf
[Partition]
Type=home
# /usr/lib/repart.d/70-swap.conf
[Partition]
Type=swap
SizeMinBytes=64M
SizeMaxBytes=1G
Priority=1
Weight=333

Ejemplo 3. Crear particiones B en una configuración Verity A/B, si faltan

Supongamos que el proveedor tiene la intención de actualizar imágenes del sistema operativo en una configuración A/B, es decir, con dos particiones raíz (y dos particiones Verity coincidentes) que se utilizarán alternativamente durante las actualizaciones. Para minimizar el tamaño de las imágenes, la imagen original se envía solo con una partición raíz y una partición Verity (el conjunto "A"), y la segunda partición raíz y Verity (el conjunto "B") se crearán en el primer arranque en el espacio libre del medio.

# /usr/lib/repart.d/50-root.conf
[Partition]
Type=root
SizeMinBytes=512M
SizeMaxBytes=512M
# /usr/lib/repart.d/60-root-verity.conf
[Partition]
Type=root-verity
SizeMinBytes=64M
SizeMaxBytes=64M

Las definiciones anteriores cubren el conjunto "A" de partición raíz (de un tamaño fijo de 512M) y partición Verity para la partición raíz (de un tamaño fijo de 64M). Usemos enlaces simbólicos para crear el conjunto "B" de particiones, ya que después de todo tendrán las mismas propiedades y tamaños que el conjunto "A".

# ln -s 50-root.conf /usr/lib/repart.d/70-root-b.conf
# ln -s 60-root-verity.conf /usr/lib/repart.d/80-root-verity-b.conf

Ejemplo 4. Crear una partición de datos y particiones Verity correspondientes a partir de un árbol de SO

Suponiendo que tenemos un árbol de SO en /var/tmp/os-tree que queremos empaquetar en una partición raíz junto con particiones Verity coincidentes, podemos hacerlo de la siguiente manera:

# 50-root.conf
[Partition]
Type=root
CopyFiles=/var/tmp/os-tree
Verity=data
VerityMatchKey=root
Minimize=guess
# 60-root-verity.conf
[Partition]
Type=root-verity
Verity=hash
VerityMatchKey=root
# Establecer explícitamente el tamaño del bloque de hash y datos a 4K
VerityDataBlockSizeBytes=4096
VerityHashBlockSizeBytes=4096
Minimize=best
# 70-root-verity-sig.conf
[Partition]
Type=root-verity-sig
Verity=signature
VerityMatchKey=root

NAME

repart.d - Archivos de configuración de partición de reasignación de discos

SYNOPSIS

El archivo de configuración de una partición individual para el comando systemd-repart.service (8) se almacena en /etc/systemd/repart.d/, /usr/lib/systemd/repart.d/ o /run/systemd/repart.d/. Los archivos deben tener la extensión .conf.

DESCRIPTION

El sistema utiliza archivos de configuración para definir las particiones que deben crearse en un disco. Cada archivo se centra en una única partición que se creará en el disco de destino.

Estos archivos definen los atributos de una partición, como su tamaño, sistema de archivos y puntos de montaje.

Los archivos se dividen en varias secciones.

[PARTITION] SECTION OPTIONS

La sección principal se llama [PARTITION]. Los siguientes parámetros se pueden especificar en ella:

ID=
Identificador único para esta partición. Debe ser un nombre alfanumérico o una cadena que contenga guiones. Este ID se utilizará en los nombres de las particiones creadas en el disco. Si no se especifica, se derivará del nombre del archivo de configuración. Por ejemplo, si el archivo se llama 00-root.conf, el ID será root.
TYPE=
El tipo de partición. Los valores válidos son data, root, swap, efi, usr, var, home, tmp, srv, srv, srv o state. El tipo de partición determina el propósito y la configuración predeterminada de la partición.
SIZE=
El tamaño de la partición. Se puede especificar en bytes o utilizando sufijos comunes como K, M, G, T (potencias de 1024). Se puede utilizar % para especificar un porcentaje del espacio libre restante en el disco. Por ejemplo, SIZE=50% para la mitad del espacio restante.
FORMAT=
El sistema de archivos con el que formatear la partición. Los valores válidos incluyen auto, ext2, ext3, ext4, btrfs, xfs, f2fs, vfat, swap. Si se establece en auto, se elegirá un sistema de archivos predeterminado basado en el TYPE. Para los tipos swap, efi y state, este campo está implícitamente establecido y no debe especificarse.
MOUNTPOINT=
El punto de montaje de la partición. Solo tiene sentido para las particiones de tipo data, root, usr, var, home, tmp, srv y state. Para los tipos swap y efi, este campo está implícitamente establecido y no debe especificarse.
PARTLABEL=
Una cadena que se utilizará como etiqueta de la partición. Si no se especifica, se derivará del ID. Esta etiqueta se puede ver usando lsblk --fs.
PARTUUID=
Una cadena que se utilizará como UUID de la partición. Si no se especifica, se generará automáticamente. Este UUID es específico de la tabla de particiones GPT y no debe confundirse con el UUID del sistema de archivos.
FSTYPE=
El tipo de sistema de archivos de la partición. Equivalente a FORMAT, pero se refiere al sistema de archivos existente en una partición que no se formatea. Para las particiones de tipo swap y efi, se configura automáticamente.
OPTIONS=
Una cadena de opciones de montaje, separadas por comas. Esto solo se aplica a las particiones de tipo data, root, usr, var, home, tmp, srv y state.

SPECIFIERS

Los siguientes especificadores se pueden usar en los valores de los campos:

%N
El número de disco que se está particionando (por ejemplo, 0 para /dev/sda).
%n
El número de partición (por ejemplo, 1 para /dev/sda1).
%C
El número de disco y partición en formato /dev/sdXn.
%I
El ID de la partición.
%T
El tipo de partición.
%F
El formato del sistema de archivos.
%M
El punto de montaje de la partición.
%L
La etiqueta de la partición.
%U
El UUID de la partición.

ENVIRONMENT

La configuración de partición también se puede influenciar por las siguientes variables de entorno:

SYSTEMD_REPART_DISK=
Especifica el disco de destino para la creación de particiones. Si no se establece, se utilizará el primer disco disponible.

[PARTITION]
ID=root

SIZE=50%
FORMAT=btrfs
MOUNTPOINT=/
PARTLABEL=MyRootPartition

Y para una partición de arranque EFI:

[PARTITION]
ID=efi
TYPE=efi
SIZE=512M
FORMAT=vfat
PARTLABEL=EFI System Partition
