NOMBRE

reuse-annotate - Añadir información REUSE a los archivos

SINOPSIS

reuse annotate [opciones] [archivo ...]

DESCRIPCIÓN

reuse-annotate añade información REUSE en las cabeceras de los archivos. Esto es útil especialmente en escenarios donde deseas añadir un titular de derechos de autor o una licencia a muchos archivos sin tener que editar manualmente la cabecera de cada archivo.

Advertencia:

Ten cuidado al usar annotate en procesos automatizados. Aunque nada te impide usarlo en tu script de lanzamiento, deberías asegurarte de que la información que añade sea realmente un reflejo de la realidad. Esto se verifica mejor manualmente.

La cabecera REUSE se coloca en la parte superior del archivo, exceptuando ciertas cabeceras existentes como shebangs (#!) o declaraciones XML (<?xml version="1.0"?>). Si ya existe una cabecera diferente que contiene información de derechos de autor o licencias en el archivo —en la parte superior o en otro lugar—, esa cabecera se reemplaza in situ con la información REUSE adicionalmente proporcionada.

La herramienta intenta detectar automáticamente el estilo de comentario a utilizar a partir de la extensión del archivo y usa ese estilo de comentario.

Normalmente, la herramienta utiliza un estilo de comentario de una sola línea cuando está disponible (por ejemplo, se usa // en lugar de /* ... */ para estilos de comentarios C++). Si no hay un estilo de comentario de una sola línea disponible, se utiliza un estilo multilínea.

OPCIONES OBLIGATORIAS

Se requiere al menos *una* de las siguientes opciones. Contienen la información que la herramienta añadirá a los archivos. Puedes repetir estas opciones.

-c, --copyright COPYRIGHT
Un titular de derechos de autor. Esto no contiene el año ni el prefijo de derechos de autor. Consulta --year y --copyright-prefix para el año y el prefijo.
-l, --license LICENCIA
Un identificador de licencia SPDX.
--contributor CONTRIBUTOR
Un nombre de un contribuidor. El contribuidor se añadirá a través de la etiqueta SPDX-FileContributor:.

OTRAS OPCIONES

-y, --year AÑO
Define el año del aviso de derechos de autor. Si no se define, el año por defecto es el año actual. El valor puede ser un rango (complejo), como '2017-2019', o '2017, 2019-2022, 2024-Presente'.
-s, --style ESTILO
Anula el mecanismo de detección del estilo de comentarios para forzar un estilo de comentarios en los archivos. Esto es útil cuando no se reconoce una extensión de archivo, o cuando una extensión de archivo está asociada con un estilo de comentarios con el que no estás de acuerdo.
--copyright-prefix PREFIJO
El prefijo a usar en el aviso de derechos de autor. Si no se define, se usa spdx como prefijo. Los prefijos de derechos de autor disponibles son:
spdx:               SPDX-FileCopyrightText: <año> <autor>
spdx-c:             SPDX-FileCopyrightText: (C) <año> <autor>
spdx-symbol:        SPDX-FileCopyrightText: © <año> <autor>
spdx-string:        SPDX-FileCopyrightText: Copyright <año> <autor>
spdx-string-c:      SPDX-FileCopyrightText: Copyright (C) <año> <autor>
spdx-string-symbol: SPDX-FileCopyrightText: Copyright © <año> <autor>
string:             Copyright <año> <autor>
string-c:           Copyright (C) <año> <autor>
string-symbol:      Copyright © <año> <autor>
symbol:             © <año> <autor>
-t, --template PLANTILLA
La plantilla a usar para la cabecera de comentarios. El nombre de la plantilla coincide con el nombre de la plantilla en .reuse/templates/, sin el sufijo .jinja2 o .commented.jinja2.
--exclude-year
No incluir el año en el aviso de derechos de autor.
--merge-copyrights
Si dos (o más) avisos de derechos de autor son idénticos excepto por sus años, impímalos en una sola línea con los años combinados.
--single-line
Forzar a la herramienta a usar un estilo de comentario de una sola línea. Para C, sería //.
--multi-line
Forzar a la herramienta a usar un estilo de comentario multilínea. Para C, sería /* ... */.
-r, --recursive
Añadir anotaciones a todos los archivos recursivamente bajo la ruta especificada.
--no-replace
En lugar de reemplazar la primera cabecera en el archivo que contiene información de derechos de autor y licencias, mantenerla y crear una nueva cabecera en la parte superior.
--force-dot-license
Escribir siempre un archivo .license en lugar de intentar escribir en el propio archivo.
--fallback-dot-license
En lugar de abortar cuando una extensión de archivo no tiene un estilo de comentario asociado, crear un archivo .license para esos archivos.
--skip-unrecognised
En lugar de abortar cuando una extensión de archivo no tiene un estilo de comentario asociado, omitir esos archivos.
--help
Mostrar la ayuda y salir.

PLANTILLAS

Cuando la herramienta añade una cabecera a un archivo, normalmente primero lista todos los avisos de derechos de autor alfabéticamente, subsequentemente todos los contribuidores, luego añade una sola línea en blanco y finalmente lista todas las Expresiones de Licencia SPDX alfabéticamente. Es posible cambiar este comportamiento y usar un tipo de cabecera personalizada que contenga texto adicional. Esto se hace a través de plantillas Jinja2.

La plantilla por defecto es:

{% for copyright_line in copyright_lines %}
{{ copyright_line }}
{% endfor %}
{% for contributor_line in contributor_lines %}
SPDX-FileContributor: {{ contributor_line }}
{% endfor %}
{% for expression in spdx_expressions %}
SPDX-License-Identifier: {{ expression }}
{% endfor %}

Las plantillas se comentan automáticamente por la herramienta, dependiendo del estilo de comentario detectado o especificado.

Puedes crear tus propias plantillas Jinja2 y colocarlas en .reuse/templates/. Debes añadir el sufijo .jinja2 a tu plantilla.

Dentro de la plantilla, tienes acceso a las siguientes variables:

  • copyright_lines --- una lista de avisos de derechos de autor (cadena).
  • contributor_lines --- una lista de contribuidores (cadena).
  • spdx_expressions --- una lista de Expresiones de Licencia SPDX (cadena).

En el futuro, se pueden añadir más variables.

En algunos casos, es posible que desees hacer un formato de comentario personalizado. En esos casos, puedes pre-formatear tu cabecera como un comentario. Al hacerlo, añade el sufijo .commented.jinja2 a tu plantilla.

NAME

reuse-annotate

annotate files with license information

SYNOPSIS

reuse annotate [OPTIONS] [FILE]...

DESCRIPTION

This command adds SPDX license and copyright information to files.

The command will create a new header or append to an existing header.

By default, the command will look for a license in the REUSE configuration file (~/.config/reuse/config.toml or /etc/reuse/config.toml) and use it if found. In addition, the current year is added as copyright year.

If the file already contains a license or copyright header, the command will update it. By default, it adds the license and copyright information at the beginning of the file.

MANDATORY OPTIONS

None.

OTHER OPTIONS

--copyright=TEXT
Specify the copyright holder name. If not specified, reuse will try to find the copyright holder in the git log.
--license=TEXT
Specify the license identifier. If not specified, reuse will try to find the license in the REUSE configuration file.
--email=TEXT
Specify the email address of the copyright holder. If not specified, reuse will try to find the email address in the git log.
--year=TEXT
Specify the copyright year. If not specified, reuse will use the current year.
--skip-checks
Skip checks for existing license or copyright headers. This will always add the specified information, even if it already exists.
--verbose
Enable verbose output.
-h, --help
Show help message and exit.
-v, --version
Show version and exit.

TEMPLATES

The following template is used to generate the license header:

/*
{% for copyright_line in copyright_lines %}
 * {{ copyright_line }}
{% endfor %}
{% if copyright_lines and spdx_expressions %}
 *
{% endif %}
{% for expression in spdx_expressions %}
 * SPDX-License-Identifier: {{ expression }}
{% endfor %}
{% if "GPL-3.0-or-later" in spdx_expressions %}
 *
 * This program is free software: you can redistribute it and/or modify it under
 * the terms of the GNU General Public License as published by the Free Software
 * Foundation, either version 3 of the License, or (at your option) any later

 *
 * You should have received a copy of the GNU General Public License along with
 * this program. If not, see <https://www.gnu.org/licenses/>.
{% endif %}
 */

EXAMPLES

The basic usage is reuse annotate --copyright="Jane Doe" --license=MIT my_file.py. This will add the following header to the file (assuming that the current year is 2019):
