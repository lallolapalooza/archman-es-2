rename(2) System Calls Manual rename(2)

NOMBRE

rename, renameat, renameat2 - cambiar el nombre o la ubicación de un archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <stdio.h>
int rename(const char *oldpath, const char *newpath);
#include <fcntl.h>           /* Definición de constantes AT_* */
#include <stdio.h>
int renameat(int olddirfd, const char *oldpath,
             int newdirfd, const char *newpath);
int renameat2(int olddirfd, const char *oldpath,
             int newdirfd, const char *newpath, unsigned int flags);

DESCRIPCIÓN

rename() renombra un archivo, moviéndolo entre directorios si es necesario. Cualquier otro enlace duro al archivo (como los creados usando link(2)) no se ven afectados. Los descriptores de archivo abiertos para oldpath tampoco se ven afectados.

Varias restricciones determinan si la operación de renombrar tiene éxito o no: ver ERRORES abajo.

Si newpath ya existe, será reemplazado atómicamente, de modo que no habrá ningún momento en el que otro proceso que intente acceder a newpath lo encuentre ausente. Sin embargo, probablemente habrá una ventana en la que tanto oldpath como newpath se refieran al archivo que se está renombrando.

Si oldpath y newpath son enlaces duros existentes que se refieren al mismo archivo, entonces rename() no hace nada y devuelve un estado de éxito.

Si newpath existe pero la operación falla por alguna razón, rename() garantiza dejar una instancia de newpath en su lugar.

oldpath puede especificar un directorio. En este caso, newpath debe o bien no existir, o bien especificar un directorio vacío.

Si oldpath se refiere a un enlace simbólico, el enlace se renombra; si newpath se refiere a un enlace simbólico, el enlace se sobrescribirá.

renameat()

La llamada al sistema renameat() opera exactamente de la misma manera que rename(), excepto por las diferencias descritas aquí.

Si la ruta de archivo dada en oldpath es relativa, entonces se interpreta en relación con el directorio referido por el descriptor de archivo olddirfd (en lugar de en relación con el directorio de trabajo actual del proceso que llama, como se hace con rename() para una ruta de archivo relativa).

Si oldpath es relativa y olddirfd es el valor especial AT_FDCWD, entonces oldpath se interpreta en relación con el directorio de trabajo actual del proceso que llama (como rename()).

Si oldpath es absoluta, entonces olddirfd se ignora.

La interpretación de newpath es la misma que para oldpath, excepto que una ruta de archivo relativa se interpreta en relación con el directorio referido por el descriptor de archivo newdirfd.

Ver openat(2) para una explicación de la necesidad de renameat().

renameat2()

renameat2() tiene un argumento adicional flags. Una llamada renameat2() con un argumento flags cero es equivalente a renameat().

El argumento flags es una máscara de bits que consta de cero o más de las siguientes banderas:

RENAME_EXCHANGE
Intercambia atómicamente oldpath y newpath. Ambas rutas de archivo deben existir, pero pueden ser de tipos diferentes (por ejemplo, una podría ser un directorio no vacío y la otra un enlace simbólico).
RENAME_NOREPLACE
No sobrescribir newpath del renombre. Devolver un error si newpath ya existe.
RENAME_NOREPLACE no se puede emplear junto con RENAME_EXCHANGE.
RENAME_NOREPLACE requiere soporte del sistema de archivos subyacente. El soporte para varios sistemas de archivos se añadió de la siguiente manera:
•
ext4 (Linux 3.15);
•
btrfs, tmpfs y cifs (Linux 3.17);
•
xfs (Linux 4.0);
•
Se añadió soporte para muchos otros sistemas de archivos en Linux 4.9, incluyendo ext2, minix, reiserfs, jfs, vfat y bpf.
RENAME_WHITEOUT (desde Linux 3.18)
Esta operación solo tiene sentido para implementaciones de sistemas de archivos overlay/union.
Especificar RENAME_WHITEOUT crea un objeto "whiteout" en la fuente del renombre al mismo tiempo que se realiza el renombre. Toda la operación es atómica, de modo que si el renombre tiene éxito, también se habrá creado el whiteout.
Un "whiteout" es un objeto que tiene un significado especial en construcciones de sistemas de archivos union/overlay. En estas construcciones, existen múltiples capas y solo la superior se modifica alguna vez. Un whiteout en una capa superior ocultará efectivamente un archivo coincidente en la capa inferior, haciendo parecer que el archivo no existía.
Cuando se renombra un archivo que existe en la capa inferior, el archivo se copia primero (si aún no está en la capa superior) y luego se renombra en la capa superior de lectura/escritura. Al mismo tiempo, la fuente debe ser "whiteouted" (para que la versión del archivo fuente en la capa inferior se vuelva invisible). Toda la operación debe realizarse de forma atómica.
Cuando no forma parte de una union/overlay, el whiteout aparece como un dispositivo de caracteres con un número de dispositivo {0,0}. (Tenga en cuenta que otras implementaciones de union/overlay pueden emplear métodos diferentes para almacenar entradas de whiteout; específicamente, la union mount de BSD emplea un tipo de inodo separado, DT_WHT, que, aunque soportado por algunos sistemas de archivos disponibles en Linux, como CODA y XFS, es ignorado por el código de soporte de whiteout del kernel, a partir de Linux 4.19, al menos).
RENAME_WHITEOUT requiere los mismos privilegios que crear un nodo de dispositivo (es decir, la capacidad CAP_MKNOD).
RENAME_WHITEOUT no se puede emplear junto con RENAME_EXCHANGE.
RENAME_WHITEOUT requiere soporte del sistema de archivos subyacente. Entre los sistemas de archivos que lo soportan se incluyen tmpfs (desde Linux 3.18), ext4 (desde Linux 3.18), XFS (desde Linux 4.1), f2fs (desde Linux 4.2), btrfs (desde Linux 4.7) y ubifs (desde Linux 4.9).

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

EACCES
Se deniega el permiso de escritura en el directorio que contiene oldpath o newpath, o se deniega el permiso de búsqueda en uno de los directorios en el prefijo de ruta de oldpath o newpath, o oldpath es un directorio y no permite permiso de escritura (necesario para actualizar la entrada ..). (Ver también path_resolution(7)).
EBUSY
El renombre falla porque oldpath o newpath es un directorio que está en uso por algún proceso (quizás como directorio actual, o como directorio raíz, o porque estaba abierto para lectura) o está en uso por el sistema (por ejemplo, como punto de montaje), mientras que el sistema considera esto un error. (Tenga en cuenta que no hay requisito de devolver EBUSY en tales casos—no hay nada de malo en hacer el renombre de todas formas—pero se permite devolver EBUSY si el sistema no puede manejar de otra manera tales situaciones).
EDQUOT
El usuario ha superado su cuota de disco en el sistema de archivos de destino.
EEXIST
newpath existe y no se utilizó RENAME_NOREPLACE ni RENAME_EXCHANGE.
EFBIG
El tamaño del archivo original excede el máximo permitido por el sistema de archivos de destino.
EINVAL
oldpath y newpath apuntan al mismo archivo. O, el sistema de archivos no soporta operaciones de renombrado atómico (por ejemplo, si oldpath es un directorio y newpath no lo es, o viceversa) o si se especificó RENAME_EXCHANGE y uno de los operandos no es un archivo regular, un directorio, un enlace simbólico o un dispositivo. También, se deniega el permiso de escritura en el directorio que contiene oldpath o newpath, o se deniega el permiso de búsqueda en uno de los directorios en el prefijo de ruta de oldpath o newpath.

renameat2(): se especificaron flags inválidos.

EISDIR
newpath es un directorio, pero oldpath no lo es.
LIO
La operación de renombre no se pudo completar debido a una condición de carrera (por ejemplo, el sistema de archivos está siendo accedido desde múltiples nodos en un clúster).
EMLINK
El número de enlaces duros al archivo incluido en newpath excede el máximo permitido por el sistema de archivos.
OMOUNT
oldpath es un punto de montaje o un directorio dentro de un sistema de archivos montado.
NFILE
El número máximo de archivos abiertos en el sistema ha sido alcanzado.
NOLINK
El número máximo de enlaces permitidos en el directorio de destino ha sido alcanzado.
ENOSPC
No hay espacio en el dispositivo (es decir, el sistema de archivos de destino está lleno).
ENOTDIR
Un componente de la ruta de acceso oldpath o newpath no es un directorio, o oldpath es un directorio y no se permite escribir en él (ver también EACCES).
ENOTEMPTY
newpath es un directorio, pero no está vacío. O, oldpath es un directorio que se está intentando mover a un directorio que no está vacío.
ENOTSUP
El sistema de archivos no soporta operaciones de renombrado atómico. O, se especificó RENAME_EXCHANGE y uno de los operandos es un archivo que no es regular, directorio, enlace simbólico o dispositivo.
EROFS
El archivo está en un sistema de archivos de solo lectura.
EXDEV
Intentar renombrar un archivo entre directorios en diferentes sistemas de archivos.
ETXTBSY
El archivo que se está renombrando es un archivo ejecutable abierto para ejecución.
