RIGCTLSYNC(1) Utilidades de Hamlib RIGCTLSYNC(1)

NOMBRE

rigctlsync - sincronizar un equipo de radio con SDR# (u otro equipo de radio)

SINOPSIS

rigctlsync [-hlLuV] [-m id] [-r dispositivo] [-R dispositivo] [-s velocidad] [-S velocidad] [-c id] [-C parámetro=valor] [-B] [-v[-Z]]

DESCRIPCIÓN

Permite sincronizar la frecuencia de un equipo de radio con SDR#. Funciona mejor cuando se usa con rigctld, FlRig o una radio multiport.

Por favor, informe de errores y proporcione comentarios en la dirección de correo electrónico indicada en la sección ERRORES más abajo. Los parches y las mejoras de código enviados a la misma dirección son bienvenidos.

OPCIONES

Este programa sigue la sintaxis habitual de línea de comandos de GNU. Las opciones cortas que toman un argumento pueden tener el valor inmediatamente después o separado por un espacio. Las opciones largas que comienzan con dos guiones (‘-’) requieren un ‘=’ entre la opción y cualquier argumento.

Aquí hay un resumen de las opciones admitidas:

-m, --model=id
Selecciona el número de modelo del equipo de radio.
Ver lista de modelos (usar “rigctlsync -l”).
Nota: rigctlsync (o software de terceros que utiliza la API de C) utilizará el modelo de radio 2 para NET rigctl (comunicándose con rigctld).
-r, --rig-file=dispositivo
Utiliza dispositivo como el nombre del archivo del puerto conectado al equipo de radio.
A menudo es un puerto serie, pero podría ser un adaptador USB a serie. Normalmente /dev/ttyS0, /dev/ttyS1, /dev/ttyUSB0, etc. en Linux, COM1, COM2, etc. en MS Windows. Los derivados de BSD y Mac OS/X tienen sus propias designaciones. Consulte la documentación de su sistema.
La cadena especial “uh-rig” puede ser dada para habilitar soporte para dispositivos micro-ham.
-R, --rig-file2=dispositivo
Utiliza dispositivo como el nombre de uno de los puertos COM virtuales -- su programa se conectará al otro puerto COM del par virtual.
-s, --serial-speed=velocidad
Establece la velocidad serie a velocidad baudios.
Utiliza la velocidad serie máxima de las capacidades del backend del radio (establecida por -m arriba) como predeterminada.
-S, --serial-speed2=velocidad
Establece la velocidad serie a velocidad baudios para el puerto COM virtual (ver -R).
Utiliza la velocidad serie máxima de las capacidades del backend del radio (establecida por -m arriba) como predeterminada.
-c, --civaddr=id
Utiliza id como la dirección CI-V para comunicarse con el equipo de radio.
Solo útil para equipos Icom y algunos Ten-Tec.
Nota: El id está en notación decimal, a menos que esté precedido por 0x, en cuyo caso es hexadecimal.
-L, --show-conf
Lista todos los parámetros de configuración para el equipo de radio definido con -m arriba.
-C, --set-conf=parámetro=valor[,parámetro=valor]
Establece uno o más parámetros de configuración del equipo de radio, p.ej. stop_bits=2.
Utilice la opción -L anterior para obtener una lista de los parámetros de configuración para un número de modelo determinado.
-u, --dump-caps
Muestra las capacidades del equipo de radio definido con -m arriba y sale.
-l, --list
Lista todos los números de modelo definidos en Hamlib y sale.
La lista está ordenada por número de modelo.
Nota: En Linux, la lista se puede desplazar hacia atrás usando Shift-PageUp/Shift-PageDown, o usando las barras de desplazamiento de un terminal virtual en X o la ventana de comandos en Windows. La salida se puede redirigir a more(1) o less(1), p.ej. “rigctl -l | more”.
-n, --no-restore-ai
rigctl restaura el estado de información automática (AI) en el equipo de radio controlado.
Si esto no se desea, por ejemplo si está utilizando rigctl para activar o desactivar el modo AI, pase esta opción.
-B, --mapa2b
Mapea set_freq en VFOA a VFOB en su lugar. Esto permite usar un skimmer CW con el equipo de radio en modo dividido y hacer clic en una frecuencia en el skimmer CW establecerá VFOB a la frecuencia de transmisión.
-v, --verbose
Establece el modo detallado, acumulativo (ver DIAGNÓSTICOS abajo).
-Z, --debug-time-stamps
Habilita marcas de tiempo para los mensajes de depuración.
Úselo solo en combinación con la opción -v ya que no genera salida por sí solo.
-h, --help
Muestra un resumen de estas opciones y sale.
-V, --version
Muestra la versión de rigctl y sale.

Nota: Algunas opciones pueden no estar implementadas por un backend determinado y devolverán un error. Esto es más probable que ocurra con las opciones --set-conf y --show-conf.

DIAGNÓSTICOS

La opción -v, --verbose permite diferentes niveles de diagnósticos a la salida estándar de error (stderr) y corresponden a -v para BUG, -vv para ERR, -vvv para WARN, -vvvv para VERBOSE, o -vvvvv para TRACE.

Un nivel de detalle dado es útil para proporcionar la información de depuración necesaria a la dirección de correo electrónico más abajo. Por ejemplo, la salida TRACE muestra todos los valores enviados y recibidos del equipo de radio, lo cual es muy útil para el desarrollo de la biblioteca de backend de radio y puede ser solicitado por los desarrolladores.

ESTADO DE SALIDA

rigctlsync sale con:

0
si todas las operaciones se completaron normalmente;
1
si hubo una opción o argumento de línea de comandos inválido;
2
si Hamlib devolvió un error.

EJEMPLO

Inicia rigctlsync con FLRig como modelo de Hamlib


$ rigctlsync -m 4 -M 9 -R 192.168.1.1:4532

El siguiente diagrama muestra el flujo de comunicaciones que permite que N1MM Logger+ se comunique con un equipo de radio conectado a Flrig:


Flrig -><- rigctlcom -> COM9 <- virt_port_pipe -> COM10 <- N1MM
