NOMBRE

rigctlcom - puerto COM passthru como emulador TS-2000 a tu equipo

SINOPSIS

rigctlcom [-hlLuV] [-m id] [-r dispositivo] [-R dispositivo] [-p dispositivo] [-d dispositivo] [-P tipo] [-D tipo] [-s baud] [-S baud] [-c id] [-C parm=val] [-B] [-v[-Z]]

DESCRIPCIÓN

Permite que programas que pueden conectarse al TS-2000 a través del puerto COM utilicen equipos Hamlib o FLRig. Múltiples programas pueden conectarse al equipo a través de FLRig o rigctld.

Los puertos serie/COM virtuales deben configurarse primero utilizando socat(1) o similar en sistemas POSIX (BSD, Linux, OS/X). En Microsoft Windows, las utilidades disponibles son com0com, Free Virtual Serial Ports, o VPSD.

Por favor, informa de errores y proporciona comentarios en la dirección de correo electrónico indicada en la sección ERRORES más abajo. Se aceptan parches y mejoras de código enviados a la misma dirección.

OPCIONES

Este programa sigue la sintaxis habitual de línea de comandos de GNU. Las opciones cortas que toman un argumento pueden tener el valor inmediatamente después o separado por un espacio. Las opciones largas que empiezan por dos guiones (‘-’) requieren un ‘=’ entre la opción y cualquier argumento.

A continuación, se muestra un resumen de las opciones admitidas:

-m, --modelo=id
Selecciona el número de modelo del equipo.
Ver lista de modelos (usa “rigctlcom -l”).
Nota: rigctlcom (o software de terceros que utiliza la API C) utilizará el modelo de equipo 2 para NET rigctl (comunicación con rigctld).
-r, --archivo-equipo=dispositivo
Utiliza dispositivo como el nombre del archivo del puerto conectado al equipo.
A menudo un puerto serie, pero podría ser un adaptador USB a serie. Típicamente /dev/ttyS0, /dev/ttyS1, /dev/ttyUSB0, etc. en Linux, COM1, COM2, etc. en MS Windows. Los sabores BSD y Mac OS/X tienen sus propias designaciones. Consulta la documentación de tu sistema.
La cadena especial “uh-rig” puede ser dada para habilitar el soporte de dispositivos micro-ham.
-R, --archivo-equipo2=dispositivo
Utiliza dispositivo como el nombre de archivo de uno de los puertos COM virtuales -- tu programa se conectará al otro puerto COM del par virtual.
Los puertos serie virtuales en sistemas POSIX se pueden crear con socat(1):

$ socat -d -d pty,raw,echo=0 pty,raw,echo=0

Consulta esta respuesta de Stackoverflow para usar socat.
En Microsoft Windows, las utilidades disponibles son com0com, Free Virtual Serial Ports o VPSD (ver DESCRIPCIÓN arriba para enlaces WWW).
-p, --archivo-ptt=dispositivo
Utiliza dispositivo como el nombre del archivo del dispositivo Push-To-Talk usando un archivo de dispositivo como se describe arriba.
-d, --archivo-dcd=dispositivo
Utiliza dispositivo como el nombre del archivo del dispositivo Data Carrier Detect usando un archivo de dispositivo como se describe arriba.
-P, --tipo-ptt=tipo
Utiliza tipo de dispositivo Push-To-Talk.
Los tipos admitidos son ‘RIG’ (comando CAT), ‘DTR’, ‘RTS’, ‘PARALLEL’, ‘NONE’, anulando el tipo PTT definido en el backend del equipo.
Algunos efectos secundarios de este comando son que cuando el tipo se establece en DTR, el estado PTT de lectura proviene del frontend de Hamlib, no se lee del equipo. Cuando se establece en NONE, el estado PTT no se puede leer ni establecer, incluso si el backend del equipo admite la lectura/establecimiento del estado PTT desde el equipo.
-D, --tipo-dcd=tipo
Utiliza tipo de dispositivo Data Carrier Detect.
Los tipos admitidos son ‘RIG’ (comando CAT), ‘DSR’, ‘CTS’, ‘CD’, ‘PARALLEL’, ‘NONE’.
-s, --velocidad-serie=baud
Establece la velocidad serie a baud rate.
Utiliza la velocidad serie máxima de las capacidades del backend del equipo (establecida con -m arriba) como predeterminada.
-S, --velocidad-serie2=baud
Establece la velocidad serie a baud rate para el puerto COM virtual (ver -R).
Utiliza la velocidad serie máxima de las capacidades del backend del equipo (establecida con -m arriba) como predeterminada.
-c, --direccion-civ=id
Utiliza id como la dirección CI-V para comunicarse con el equipo.
Solo útil para equipos Icom y algunos Ten-Tec.
Nota: El id está en notación decimal, a menos que vaya precedido por 0x, en cuyo caso es hexadecimal.
-L, --mostrar-conf
Lista todos los parámetros de configuración para el equipo definido con -m arriba.
-C, --establecer-conf=parm=val[,parm=val]
Establece uno o más parámetros de configuración del equipo, por ejemplo stop_bits=2.
Utiliza la opción -L anterior para obtener una lista de parámetros de configuración para un número de modelo dado.
-u, --volcar-capacidades
Vuelca las capacidades del equipo definido con -m arriba y sale.
-l, --listar
Lista todos los números de modelo definidos en Hamlib y sale.
La lista está ordenada por número de modelo.
Nota: En Linux, la lista se puede desplazar hacia atrás usando Shift-PageUp/Shift-PageDown, o usando las barras de desplazamiento de un terminal virtual en X o la ventana de comandos en Windows. La salida se puede enviar a more(1) o less(1), por ejemplo “rigctl -l | more”.
-n, --no-restaurar-ai
rigctl restaura el estado de la información automática (AI) en el equipo controlado.
Si esto no es deseado, por ejemplo, si estás usando rigctl para activar o desactivar el modo AI, pasa esta opción.
-B, --mapa2b
Mapea set_freq en VFOA a VFOB en su lugar. Esto permite usar un skimmer CW con el equipo en modo split y hacer clic en una frecuencia en el skimmer CW establecerá VFOB a la frecuencia de transmisión.
-v, --verboso
Establece el modo verboso, acumulativo (ver DIAGNÓSTICOS más abajo).
-Z, --marcas-tiempo-debug
Habilita marcas de tiempo para los mensajes de depuración.
Usar solo en combinación con la opción -v, ya que no genera salida por sí sola.
-h, --ayuda
Muestra un mensaje de ayuda y sale.
-V, --version
Muestra la información de la versión de Hamlib y sale.

DIAGNÓSTICOS

Los mensajes de depuración se imprimen en la salida de error estándar. La salida de depuración se incrementa con la opción -v. El nivel más alto de detalle de la depuración es -vvv.

       1: Errores fatales
       2: Errores
       3: Advertencias
       4: Estado de alto nivel
       5: Estado de nivel medio
       6: Estado de bajo nivel
       7: Estado de todos los comandos/respuestas
       8: Estado de todos los comandos/respuestas (más detalles)

La opción -vvv genera una salida exhaustiva que a menudo es innecesaria.

ERRORES

Informar de errores o hacer preguntas sobre este programa a la lista de correo de Hamlib <hamlib@lists.sourceforge.net>.

rigctlcom(1) - Hamlib documentation

NAME

rigctlcom - rig control daemon for Hamlib

SYNOPSIS

rigctlcom [-c] [-d] [-h] [-m model] [-r device] [-s speed] [-t trace] [-v] [-V]

rigctlcom [-h] [-V]

DESCRIPTION

This manual page documents the rigctlcom command.

rigctlcom is a component of Hamlib used for interacting with radio transceivers. It acts as a bridge, allowing other applications to communicate with a radio through the Hamlib library.

This particular version of the rig control daemon is designed to be controlled via a virtual serial port pair, allowing applications such as N1MM Logger+ to communicate with a radio connected to Hamlib. The communications flow is typically:


Hamlib Radio Backend <-> rigctld <-> rigctlcom <-> Virtual Serial Port Pair <-> Application

Where the virtual serial port pair is typically created using a utility such as socat(1).

OPTIONS

-c
Causes rigctlcom to send a CAT command to the rig to check if the rig is present. If the rig is not present, it will exit with an error.
-d
Dump the configuration parameters for the selected rig model and exit.
-h, --help
Show a summary of these options and exit.
-m model
Set the rig model to use. Use -l to list all supported models.
-r device
Set the serial port device to use for communication with the rig. If not specified, rigctlcom will try to open the default device.
-s speed
Set the serial port speed (baud rate). If not specified, rigctlcom will try to detect the speed or use a default value.
-t trace
Set the trace level for debugging. Higher values provide more detailed tracing information.
-v
Verbose mode. Output diagnostic information to stderr.
-V, --version
Show version of rigctl and exit.

Note: Some options may not be implemented by a given backend and will return an error. This is most likely to occur with the --set-conf and --show-conf options.

DIAGNOSTICS

The -v, --verbose option allows different levels of diagnostics to be output to stderr and correspond to -v for BUG, -vv for ERR, -vvv for WARN, -vvvv for VERBOSE, or -vvvvv for TRACE.

A given verbose level is useful for providing needed debugging information to the email address below. For example, TRACE output shows all of the values sent to and received from the radio which is very useful for radio backend library development and may be requested by the developers.

EXIT STATUS

rigctlcom exits with:

0
if all operations completed normally;
1
if there was an invalid command line option or argument;
2
if an error was returned by Hamlib.

EXAMPLE

Start rigctlcom with FLRig as the Hamlib model and virtual com port pair COM9/COM10, e.g. N1MM Logger+ attaching to COM10 and using the TS-2000 emulator attached to COM9 (assumes virtual serial/COM ports pipe has been created with the proper utility as described above):


$ rigctlcom -m 4 -R COM9 -S 115200

The following diagram shows the communications flow that allows N1MM Logger+ to communicate with a radio connected to Flrig:


Flrig -><- rigctlcom -> COM9 <- virt_port_pipe -> COM10 <- N1MM
