GDBSERVER(1) Herramientas de Desarrollo de GNU GDBSERVER(1)

NOMBRE

gdbserver - Servidor Remoto para el Depurador GNU

SINOPSIS

gdbserver comm prog [args...]

gdbserver --attach comm pid

gdbserver --multi comm

DESCRIPCIÓN

gdbserver es un programa que permite ejecutar GDB en una máquina diferente a la que está ejecutando el programa que se está depurando.

Uso (lado del servidor (objetivo)):

Primero, necesitas tener una copia del programa que quieres depurar en el sistema objetivo. El programa puede ser despojado (stripped) para ahorrar espacio si es necesario, ya que a gdbserver no le importan los símbolos. Todo el manejo de símbolos lo realiza el GDB que se ejecuta en el sistema host.

Para usar el servidor, te conectas al sistema objetivo y ejecutas el programa gdbserver. Debes indicarle (a) cómo comunicarse con GDB, (b) el nombre de tu programa y (c) sus argumentos. La sintaxis general es:

objetivo> gdbserver <comm> <programa> [<args> ...]

Por ejemplo, usando un puerto serie, podrías decir:

objetivo> gdbserver /dev/com1 emacs foo.txt

Esto le indica a gdbserver que depure emacs con el argumento foo.txt y que se comunique con GDB a través de /dev/com1. gdbserver ahora espera pacientemente a que el GDB host se comunique con él.

Para usar una conexión TCP, podrías decir:

objetivo> gdbserver host:2345 emacs foo.txt

Esto dice prácticamente lo mismo que el último ejemplo, excepto que nos comunicaremos con el GDB de "host" vía TCP. El argumento "host:2345" significa que esperamos ver una conexión TCP desde "host" al puerto TCP local 2345. (Actualmente, la parte "host" se ignora). Puedes elegir cualquier número para el puerto siempre que no entre en conflicto con otros servicios TCP existentes en el sistema objetivo. Este mismo número de puerto debe usarse en el comando "target remote" del GDB host, que se describirá en breve. Ten en cuenta que si eliges un número de puerto que entra en conflicto con otro servicio, gdbserver imprimirá un mensaje de error y saldrá.

gdbserver también puede adjuntarse a programas en ejecución. Esto se logra a través del argumento --attach. La sintaxis es:

objetivo> gdbserver --attach <comm> <pid>

pid es el ID del proceso de un proceso actualmente en ejecución. No es necesario apuntar gdbserver a un binario para el proceso en ejecución.

Para iniciar "gdbserver" sin suministrar un comando inicial para ejecutar o un ID de proceso al que adjuntarse, usa la opción de línea de comandos --multi. En tal caso, deberías conectarte usando "target extended-remote" para iniciar el programa que deseas depurar.

objetivo> gdbserver --multi <comm>

Uso (lado host):

Necesitas una copia sin despojar del programa objetivo en tu sistema host, ya que GDB necesita examinar sus tablas de símbolos y demás. Inicia GDB como lo harías normalmente, con el programa objetivo como primer argumento. (Puede que necesites usar la opción --baud si la línea serie no funciona a 9600 baudios). Es decir, "gdb PROGRAMA-OBJETIVO", o "gdb --baud BAUD PROGRAMA-OBJETIVO". Después de eso, el único comando nuevo que necesitas conocer es "target remote" (o "target extended-remote"). Su argumento es ya sea un nombre de dispositivo (generalmente un dispositivo serie, como /dev/ttyb), o un descriptor de "HOST:PUERTO". Por ejemplo:

(gdb) target remote /dev/ttyb

se comunica con el servidor a través de la línea serie /dev/ttyb, y:

(gdb) target remote el-objetivo:2345

se comunica a través de una conexión TCP al puerto 2345 en el host `el-objetivo', donde previamente iniciaste gdbserver con el mismo número de puerto. Ten en cuenta que para las conexiones TCP, debes iniciar gdbserver antes de usar el comando `target remote', de lo contrario, podrías obtener un error como `Connection refused'.

gdbserver también puede depurar múltiples inferiores a la vez, descrito en el manual de GDB en el nodo "Inferiors Connections and Programs" -- comando shell "info -f gdb -n 'Inferiors Connections and Programs'". En tal caso usa la variante del comando GDB "extended-remote":

(gdb) target extended-remote el-objetivo:2345

La opción de gdbserver --multi puede o no usarse en tal caso.

OPCIONES

Hay tres modos diferentes para invocar gdbserver:

  • Depurar un programa específico especificado por su nombre: 
    gdbserver <comm> <prog> [<args>...]

    El parámetro comm especifica cómo debe comunicarse el servidor con GDB; es el nombre de un dispositivo (para usar una línea serie), un número de puerto TCP (":1234"), o "-" o "stdio" para usar la entrada/salida estándar de "gdbserver". Especifica el nombre del programa a depurar en prog. Cualquier argumento restante se pasará al programa tal cual. Cuando el programa termine, GDB cerrará la conexión y "gdbserver" saldrá.

  • Depurar un programa específico especificando el ID de proceso de un programa en ejecución: 
    gdbserver --attach <comm> <pid>

    El parámetro comm es como se describe arriba. Suministra el ID de proceso de un programa en ejecución en pid; GDB hará todo lo demás. Al igual que con el modo anterior, cuando el proceso pid termine, GDB cerrará la conexión y "gdbserver" saldrá.

  • Modo multiproceso: depurar más de un programa/proceso: 
    gdbserver --multi <comm>

    En este modo, GDB puede instruir a gdbserver qué comando(s) ejecutar. A diferencia de los otros 2 modos, GDB no cerrará la conexión cuando un proceso que se está depurando termine, por lo que puedes depurar varios procesos en la misma sesión.

En cada uno de los modos puedes especificar estas opciones:

--help
Lista todas las opciones, con explicaciones breves.
--version
Esta opción hace que gdbserver imprima su número de versión y salga.
--attach
gdbserver se adjuntará a un programa en ejecución. La sintaxis es: 
objetivo> gdbserver --attach <comm> <pid>

pid es el ID del proceso de un proceso actualmente en ejecución. No es necesario apuntar gdbserver a un binario para el proceso en ejecución.

--multi
Para iniciar "gdbserver" sin suministrar un comando inicial para ejecutar o un ID de proceso al que adjuntarse, usa esta opción de línea de comandos. Luego puedes conectarte usando "target extended-remote" e iniciar el programa que deseas depurar. La sintaxis es: 
objetivo> gdbserver --multi <comm>
--debug[=opcion1,opcion2,...]
Instruye a "gdbserver" para que muestre información adicional de estado sobre el proceso de depuración. Esta opción está destinada al desarrollo de "gdbserver" y para informes de errores a los desarrolladores.

Cada opcion es el nombre de un componente para el cual se debe habilitar la depuración. La lista de opciones posibles es all, threads, event-loop, remote. La opción especial all habilita todos los componentes. La lista de opciones se procesa de izquierda a derecha, y una opción puede ir precedida del carácter "-" para deshabilitar la salida para ese componente, por lo que podrías escribir:

objetivo> gdbserver --debug=all,-event-loop

para activar la salida de depuración para todos los componentes excepto event-loop. Si no se pasan opciones a --debug, se trata como equivalente a --debu

OPCIONES

--multi-g
Esto podría cambiar en futuras versiones de "gdbserver".
--debug-file=nombre_archivo
Instruye a "gdbserver" para que envíe cualquier salida de depuración al nombre_archivo dado. Esta opción está destinada al desarrollo de "gdbserver" y para informes de errores a los desarrolladores.
--debug-format=opcion1[,opcion2,...]
Instruye a "gdbserver" para que incluya información adicional en cada línea de salida de depuración.
--wrapper
Especifica un wrapper para lanzar programas para depuración. La opción debe ir seguida del nombre del wrapper, luego cualquier argumento de línea de comandos para pasar al wrapper, luego " -- " indicando el final de los argumentos del wrapper.
--once
Por defecto, gdbserver mantiene abierto el puerto TCP de escucha, de modo que son posibles conexiones adicionales. Sin embargo, si inicia "gdbserver" con la opción --once, dejará de escuchar cualquier intento de conexión posterior después de conectarse a la primera sesión de GDB.

info gdb

debería darle acceso al manual completo.
