NOMBRE

windres - manipula recursos de Windows

SINOPSIS

windres [opciones] [archivo-entrada] [archivo-salida]

DESCRIPCIÓN

windres lee recursos de un archivo de entrada y los copia a un archivo de salida. Cualquiera de los archivos puede estar en uno de tres formatos:

"rc"
Un formato de texto leído por el Compilador de Recursos.
"res"
Un formato binario generado por el Compilador de Recursos.
"coff"
Un objeto o ejecutable COFF.

La descripción exacta de estos diferentes formatos está disponible en la documentación de Microsoft.

Cuando windres convierte del formato "rc" al formato "res", actúa como el Compilador de Recursos de Windows. Cuando windres convierte del formato "res" al formato "coff", actúa como el programa "CVTRES" de Windows.

Cuando windres genera un archivo "rc", la salida es similar pero no idéntica al formato esperado para la entrada. Cuando un archivo "rc" de entrada se refiere a un nombre de archivo externo, un archivo "rc" de salida incluirá el contenido del archivo en su lugar.

Si el formato de entrada o salida no se especifica, windres lo adivinará basándose en el nombre del archivo o, para el archivo de entrada, en el contenido del archivo. Un archivo con extensión .rc se tratará como un archivo "rc", un archivo con extensión .res se tratará como un archivo "res", y un archivo con extensión .o o .exe se tratará como un archivo "coff".

Si no se especifica un archivo de salida, windres imprimirá los recursos en formato "rc" a la salida estándar.

El uso normal es que usted escriba un archivo "rc", utilice windres para convertirlo a un archivo objeto COFF, y luego enlace el archivo COFF en su aplicación. Esto hará que los recursos descritos en el archivo "rc" estén disponibles para Windows.

OPCIONES

-i nombre-archivo
--input nombre-archivo
El nombre del archivo de entrada. Si esta opción no se usa, windres usará el primer argumento que no sea una opción como nombre del archivo de entrada. Si no hay argumentos que no sean opciones, windres leerá de la entrada estándar. windres no puede leer un archivo COFF de la entrada estándar.
-o nombre-archivo
--output nombre-archivo
El nombre del archivo de salida. Si esta opción no se usa, windres usará el primer argumento que no sea una opción, después de cualquiera utilizado para el nombre del archivo de entrada, como nombre del archivo de salida. Si no hay un argumento que no sea una opción, windres escribirá a la salida estándar. windres no puede escribir un archivo COFF a la salida estándar. Tenga en cuenta que, para compatibilidad con rc, la opción -fo también se acepta, pero no se recomienda su uso.
-J formato
--input-format formato
El formato de entrada a leer. formato puede ser res, rc o coff. Si no se especifica un formato de entrada, windres lo adivinará, como se describe anteriormente.
-O formato
--output-format formato
El formato de salida a generar. formato puede ser res, rc o coff. Si no se especifica un formato de salida, windres lo adivinará, como se describe anteriormente.
-F objetivo
--target objetivo
Especifica el formato BFD a usar para un archivo COFF como entrada o salida. Este es un nombre de objetivo BFD; puede usar la opción --help para ver una lista de objetivos admitidos. Normalmente windres usará el formato predeterminado, que es el primero listado por la opción --help.
--preprocessor programa
Cuando windres lee un archivo "rc", lo pasa primero por el preprocesador de C. Esta opción puede usarse para especificar el preprocesador a usar. El preprocesador predeterminado es "gcc".
--preprocessor-arg opción
Cuando windres lee un archivo "rc", lo pasa primero por el preprocesador de C. Esta opción puede usarse para especificar texto adicional que se pasará al preprocesador en su línea de comandos. Esta opción puede usarse múltiples veces para agregar múltiples opciones a la línea de comandos del preprocesador. Si la opción --preprocessor no se ha especificado, se usará un conjunto predeterminado de argumentos del preprocesador, con cualquier opción --preprocessor-arg colocada después de ellos en la línea de comandos. Estos argumentos predeterminados son "-E", "-xc-header" y "-DRC_INVOKED".
-I directorio
--include-dir directorio
Especifica un directorio de inclusión a usar al leer un archivo "rc". windres se lo pasará al preprocesador como una opción -I. windres también buscará en este directorio al buscar archivos nombrados en el archivo "rc". Si el argumento pasado a este comando coincide con alguno de los formatos admitidos (como se describe en la opción -J), emitirá una advertencia de deprecación y se comportará igual que la opción -J. Los programas nuevos no deben usar este comportamiento. Si un directorio coincide con un formato, simplemente prefíjelo con ./ para deshabilitar la compatibilidad con versiones anteriores.
-D objetivo
--define sim[=val]
Especifica una opción -D para pasar al preprocesador al leer un archivo "rc".
-U objetivo
--undefine sim
Especifica una opción -U para pasar al preprocesador al leer un archivo "rc".
-r
Ignorado por compatibilidad con rc.
-v
Habilita el modo detallado. Esto le indica cuál es el preprocesador si no especificó uno.
-c val
--codepage val
Especifica la página de códigos predeterminada a usar al leer un archivo "rc". val debe ser un código de página de códigos decimal o hexadecimal prefijado con 0x. El rango válido es de cero hasta 0xffff, pero la validez de la página de códigos depende del host y la configuración.
-l val
--language val
Especifica el idioma predeterminado a usar al leer un archivo "rc". val debe ser un código de idioma hexadecimal. Los ocho bits bajos son el idioma y los ocho bits altos son el subidioma.
--use-temp-file
Usa un archivo temporal en lugar de usar popen para leer la salida del preprocesador. Usa esta opción si la implementación de popen tiene errores en el host (por ejemplo, ciertas versiones de Windows 95 y Windows 98 en idiomas que no sean inglés.

NAME

windres - Windows resource compiler

SYNOPSIS

windres [-i input file] [-o output file] [-I target] [-J endianness] [-K type] [-v] [--] [input files...]

DESCRIPTION

The windres program is a resource compiler for Windows. It takes a text file describing resources and compiles it into a binary resource file that can be linked into a Windows executable.

The input file format is a subset of the Microsoft Visual C++ resource compiler format. It supports definitions for icons, bitmaps, cursors, dialogs, menus, strings, and version information.

OPTIONS

-i input file
Specifies the input file containing the resource definitions. If not specified, windres will read from standard input.
-o output file
Specifies the output file to which the compiled resources will be written. If not specified, windres will write to standard output.
-I target
Specifies the target architecture for the resources. Valid values are "pe" (Portable Executable) and "pe-i386", "pe-x86-64", "pe-arm-eabi", "pe-aarch64", etc. This option is often not needed as windres can usually determine the target from the compiler's internal configuration.
-J endianness
Specifies the endianness of the target architecture. Valid values are "little" and "big". This option is also often not needed.
-K type
Specifies the resource type to compile. This is generally not needed, as windres can usually determine the resource type from the input file.
-v
Prints the version number for windres.
--use-temp-file
Use a temporary file to read the output of the preprocessor. This is necessary on some systems that have a buggy popen where the output will instead go to the console).
--no-use-temp-file
Use popen, not a temporary file, to read the output of the preprocessor. This is the default behaviour.
-h
--help
Prints a usage summary.
-V
--version
Prints the version number for windres.
--yydebug
If windres is compiled with "YYDEBUG" defined as 1, this will turn on parser debugging.
@file
Read command-line options from file. The options read are inserted in place of the original @file option. If file does not exist, or cannot be read, then the option will be treated literally, and not removed.

Options in file are separated by whitespace. A whitespace character may be included in an option by surrounding the entire option in either single or double quotes. Any character (including a backslash) may be included by prefixing the character to be included with a backslash. The file may itself contain additional @file options; any such options will be processed recursively.
