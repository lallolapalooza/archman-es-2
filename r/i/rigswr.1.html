RIGSWR(1) Hamlib Utilities RIGSWR(1)

NOMBRE

rigswr - mide la ROE (Relación de Onda Estacionaria) en función de la frecuencia.

SINOPSIS

rigswr [-hvV] [-m id] [-r dispositivo] [-s baud] [-c id] [-C parm=val] [-p dispositivo] [-P tipo] freq_inicio freq_fin [paso_freq]

DESCRIPCIÓN

rigswr utiliza Hamlib para controlar una radio y medir la ROE (Relación de Onda Estacionaria) en un rango de frecuencias.

Escanea frecuencias desde freq_inicio hasta freq_fin con un incremento opcional de paso_freq (el paso por defecto es 100 kHz). Todos los valores deben ingresarse como un entero en Hertz (ciclos por segundo).

Nota: rigswr asume que freq_inicio es menor o igual a freq_fin. Si es mayor, rigswr saldrá sin hacer nada.

Para cada frecuencia, transmite al 25% de la POTENCIA total durante 0.5 segundos en modo CW y lee la ROE.

La frecuencia y la ROE correspondiente se imprimen en stdout.

Para funcionar correctamente, rigswr necesita una radio que pueda medir la ROE y un backend de Hamlib que soporte la lectura de ROE desde la radio.

Tenga en cuenta que Hamlib es software de nivel BETA. Si bien muchas bibliotecas de backend carecen de soporte completo para radios, las funciones básicas suelen estar bien soportadas.

Por favor, informe de errores y proporcione comentarios en la dirección de correo electrónico que se indica en la sección BUGS a continuación. Se agradecen los parches y las mejoras de código enviados a la misma dirección.

OPCIONES

Este programa sigue la sintaxis habitual de línea de comandos de GNU. Las opciones cortas que toman un argumento pueden tener el valor inmediatamente después o separado por un espacio. Las opciones largas que comienzan con dos guiones (-) requieren un = entre la opción y cualquier argumento.

Aquí hay un resumen de las opciones admitidas:

-m, --model=id
Selecciona el número de modelo de la radio.
Ver lista de modelos (use rigctl -l).
-r, --rig-file=dispositivo
Utiliza dispositivo como el nombre del archivo del puerto conectado a la radio.
A menudo un puerto serie, pero podría ser un adaptador USB a serie. Típicamente /dev/ttyS0, /dev/ttyS1, /dev/ttyUSB0, etc. en Linux, COM1, COM2, etc. en MS Windows. Las variantes BSD y Mac OS/X tienen sus propias designaciones. Consulte la documentación de su sistema.
-s, --serial-speed=baud
Establece la velocidad serie de la radio a baud.
Utiliza la velocidad serie máxima de las capacidades del backend de la radio como predeterminada.
-c, --civaddr=id
Utiliza id como la dirección CI-V para comunicarse con la radio.
Solo útil para radios Icom y algunas Ten-Tec.
Nota: El id está en notación decimal, a menos que esté prefijado por 0x, en cuyo caso es hexadecimal.
-C, --set-conf=parm=val[,parm=val]
Establece parámetros de configuración de la radio, por ejemplo, stop_bits=2.
Utilice la opción -L de rigctl para obtener una lista de parámetros de configuración para un número de modelo determinado.
-p, --ptt-file=dispositivo
Utiliza dispositivo como el nombre del archivo del puerto Push-To-Talk (PTT) utilizando un archivo de dispositivo como con la opción -r anterior.
Esto solo es necesario si la radio no tiene control PTT CAT y requiere un puerto de dispositivo separado para activar el transmisor.
-P, --ptt-type=tipo
Utiliza el tipo de dispositivo Push-To-Talk.
Los tipos soportados son RIG (CAT), DTR, RTS, PARALLEL, NONE.
-v, --verbose
Establece el modo verboso, acumulativo (ver DIAGNOSTICS abajo).
-h, --help
Muestra un resumen de estas opciones y sale.
-V, --version
Muestra la versión de rigswr y sale.

Nota: Algunas opciones pueden no ser implementadas por un backend dado y devolverán un error. Esto es más probable que ocurra con la opción --set-conf.

DIAGNÓSTICOS

La opción -v, --verbose permite diferentes niveles de diagnóstico para ser enviados a stderr y corresponden a -v para BUG, -vv para ERR, -vvv para WARN, -vvvv para VERBOSE, o -vvvvv para TRACE.

Un nivel verboso dado es útil para proporcionar la información de depuración necesaria a la dirección de correo electrónico a continuación. Por ejemplo, la salida TRACE muestra todos los valores enviados y recibidos de la radio, lo cual es muy útil para el desarrollo de bibliotecas backend de radio y puede ser solicitado por los desarrolladores.

ESTADO DE SALIDA

rigswr sale con:

0
si todas las operaciones se completaron normalmente;
1
si hubo una opción de línea de comandos o argumento inválido;
2
si un error fue devuelto por Hamlib;
3
si la radio no tiene las capacidades requeridas.

EJEMPLO

Escanea frecuencias entre 14.000 MHz y 14.200 MHz con un paso de 50 kHz en un TS-850 y registra las mediciones de ROE en el archivo cswr (el texto escrito se muestra en negrita):


$ rigswr -m 2009 -r /dev/ttyS1 14000000 14200000 50000 > cswr

Después de la finalización, cswr contiene las siguientes líneas:


14000000 1.50
14050000 1.31
14100000 1.22
14150000 1.07
14200000 1.07

El resultado se puede graficar con gnuplot(1):


$ gnuplot
set data style linespoints
set grid
plot cswr

BUGS

Dependiendo de la configuración del manipulador/QSK, las transmisiones en modo CW pueden no estar moduladas, lo que podría dar un resultado incorrecto. Por favor, informe de esta situación si ocurre.
