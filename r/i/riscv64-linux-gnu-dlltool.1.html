DLLTOOL(1) Herramientas de desarrollo de GNU DLLTOOL(1)

NOMBRE

dlltool - crea archivos necesarios para construir y usar DLLs

SINOPSIS

dlltool [-d|--input-def nombre-archivo-def]
[-b|--base-file nombre-archivo-base]
[-e|--output-exp nombre-archivo-exp]
[-z|--output-def nombre-archivo-def]
[-l|--output-lib nombre-archivo-libreria]
[-y|--output-delaylib nombre-archivo-libreria-retrasada]
[--export-all-symbols] [--no-export-all-symbols]
[--exclude-symbols lista]
[--no-default-excludes]
[-S|--as ruta-al-ensamblador] [-f|--as-flags opciones]
[-D|--dllname nombre] [-m|--machine maquina]
[-a|--add-indirect]
[-U|--add-underscore] [--add-stdcall-underscore]
[-k|--kill-at] [-A|--add-stdcall-alias]
[-p|--ext-prefix-alias prefijo]
[-x|--no-idata4] [-c|--no-idata5]
[--use-nul-prefixed-import-tables]
[-I|--identify nombre-archivo-libreria] [--identify-strict]
[-i|--interwork]
[-n|--nodelete] [-t|--temp-prefix prefijo]
[-v|--verbose]
[-h|--help] [-V|--version]
[--no-leading-underscore] [--leading-underscore]
[--deterministic-libraries] [--non-deterministic-libraries]
[archivo-objeto ...]

DESCRIPCIÓN

dlltool lee sus entradas, que pueden provenir de las opciones -d y -b, así como de los archivos objeto especificados en la línea de comandos. Luego procesa estas entradas y, si se ha especificado la opción -e, crea un archivo de exportaciones. Si se ha especificado la opción -l, crea un archivo de librería y si se ha especificado la opción -z, crea un archivo def. Cualquiera o todas las opciones -e, -l y -z pueden estar presentes en una sola invocación de dlltool.

Al crear una DLL, junto con el código fuente de la DLL, es necesario tener otros tres archivos. dlltool puede ayudar con la creación de estos archivos.

El primer archivo es un archivo .def que especifica qué funciones se exportan desde la DLL, qué funciones importa la DLL, etc. Este es un archivo de texto y puede crearse manualmente, o se puede usar dlltool para crearlo utilizando la opción -z. En este caso, dlltool escaneará los archivos objeto especificados en su línea de comandos buscando aquellas funciones que hayan sido marcadas especialmente como exportadas y las incluirá en el archivo .def que crea.

Para marcar una función como exportada desde una DLL, necesita tener una entrada -export:<nombre_de_la_funcion> en la sección .drectve del archivo objeto. Esto se puede hacer en C usando el operador asm():

asm (".section .drectve");
asm (".ascii \"-export:mi_func\"");

int mi_func (void) { ... }

El segundo archivo necesario para la creación de DLL es un archivo de exportaciones. Este archivo se vincula con los archivos objeto que componen el cuerpo de la DLL y maneja la interfaz entre la DLL y el mundo exterior. Este es un archivo binario y puede crearse proporcionando la opción -e a dlltool al crear o leer un archivo .def.

El tercer archivo necesario para la creación de DLL es el archivo de librería con el que los programas se vincularán para acceder a las funciones de la DLL (una `librería de importación'). Este archivo puede crearse proporcionando la opción -l a dlltool al crear o leer un archivo .def.

Si se especifica la opción -y, dlltool genera una librería de importación retrasada que puede usarse en lugar de la librería de importación normal para permitir que un programa se vincule a la dll solo en el momento en que se llama a una función importada por primera vez. El ejecutable resultante necesitará vincularse a la librería estática delayimp que contiene __delayLoadHelper2(), la cual a su vez importará LoadLibraryA y GetProcAddress de kernel32.

dlltool construye el archivo de librería manualmente, pero construye el archivo de exportaciones creando archivos temporales que contienen sentencias de ensamblador y luego ensamblando estos. La opción de línea de comandos -S se puede usar para especificar la ruta al ensamblador que usará dlltool, y la opción -f se puede usar para pasar opciones específicas a ese ensamblador. La opción -n se puede usar para evitar que dlltool elimine estos archivos temporales de ensamblador cuando termine, y si se especifica -n dos veces, esto evitará que dlltool elimine los archivos objeto temporales que utilizó para construir la librería.

Aquí hay un ejemplo de cómo crear una DLL a partir de un archivo fuente dll.c y también cómo crear un programa (a partir de un archivo objeto llamado program.o) que usa esa DLL:

gcc -c dll.c
dlltool -e exports.o -l dll.lib dll.o
gcc dll.o exports.o -o dll.dll
gcc program.o dll.lib -o program

dlltool también puede usarse para consultar una librería de importación existente para determinar el nombre de la DLL a la que está asociada. Consulte la descripción de la opción -I o --identify.

OPCIONES

Las opciones de línea de comandos tienen los siguientes significados:

-d nombre-archivo
--input-def nombre-archivo
Especifica el nombre de un archivo .def para ser leído y procesado.
-b nombre-archivo
--base-file nombre-archivo
Especifica el nombre de un archivo base para ser leído y procesado. El contenido de este archivo se añadirá a la sección de reubicación en el archivo de exportaciones generado por dlltool.
-e nombre-archivo
--output-exp nombre-archivo
Especifica el nombre del archivo de exportaciones a ser creado por dlltool.
-z nombre-archivo
--output-def nombre-archivo
Especifica el nombre del archivo .def a ser creado por dlltool.
-l nombre-archivo
--output-lib nombre-archivo
Especifica el nombre del archivo de librería a ser creado por dlltool.
-y nombre-archivo
--output-delaylib nombre-archivo
Especifica el nombre del archivo de librería de importación retrasada a ser creado por dlltool.
--deterministic-libraries
--non-deterministic-libraries
Al crear librerías de salida en respuesta a las opciones --output-lib o --output-delaylib, usa el valor cero para cualquier marca de tiempo, ID de usuario e ID de grupo creados (--deterministic-libraries) o las marcas de tiempo, ID de usuario e ID de grupo reales (--non-deterministic-libraries).
--export-all-symbols
Trata todos los símbolos definidos global y débilmente encontrados en los archivos objeto de entrada como símbolos a exportar. Hay una pequeña lista de símbolos que no se exportan por defecto; consulte la opción --no-default-excludes. Puede añadir a la lista de símbolos a no exportar usando la opción --exclude-symbols.
--no-export-all-symbols
Exporta solo los símbolos listados explícitamente en un archivo .def de entrada o en secciones .drectve en los archivos objeto de entrada. Este es el comportamiento por defecto. Las secciones .drectve son creadas por atributos dllexport en el código fuente.
--exclude-symbols lista
No exporta los símbolos en lista. Esta es una lista de nombres de símbolos separados por caracteres de coma o dos puntos. Los nombres de los símbolos no deben contener un guion bajo inicial. Esto solo es significativo cuando se usa --export-all-symbols.
--no-default-excludes
Por defecto, dlltool no exporta ciertos símbolos comunes (por ejemplo, `__main', `_main', `_pei_module', `_pei_interface'). Use esta opción para deshabilitar esta exclusión por defecto de modo que todos los símbolos globales y débiles sean exportados (cuando se usa --export-all-symbols).
-S ruta-al-ensamblador
--as ruta-al-ensamblador
Especifica la ruta al ensamblador que se utilizará para ensamblar los archivos de exportación temporales.
-f opciones
--as-flags opciones
Pasa las opciones dadas al ensamblador.
-D nombre
--dllname nombre
Especifica el nombre de la DLL a la que se hace referencia en la librería de importación que se está creando. Si no se especifica, el nombre de la DLL se infiere del nombre del archivo de librería de importación.
-m maquina
--machine maquina
Especifica la arquitectura de máquina para la que se está creando la librería. Las arquitecturas reconocidas son `pe32' (para la plataforma Win32) y `pe64' (para la plataforma Win64). El valor predeterminado es `pe32'.
-a
--add-indirect
Esto se usa para construir un archivo de exportación que se pueda usar para la importación indirecta. El archivo de exportación creado solo contendrá símbolos de importación, no símbolos de exportación.
-U
--add-underscore
Prefija un guion bajo a todos los nombres de símbolos que se exportan. Esto es necesario para la compatibilidad con algunas versiones anteriores de los compiladores de C.
--add-stdcall-underscore
Prefija un guion bajo a todos los nombres de símbolos que usan la convención de llamada stdcall. Esto es necesario para la compatibilidad con algunos compiladores de C.
-k
--kill-at
Elimina el sufijo `@num` de los símbolos que usan la convención de llamada stdcall. Por ejemplo, `_myfunc@12' se convierte en `_myfunc'.
-A
--add-stdcall-alias
Para cada símbolo que usa la convención de llamada stdcall, crea una entrada de alias adicional en el archivo .def. Por ejemplo, si se exporta `_myfunc', y se está usando la opción, la entrada en el archivo .def será `my_func = _myfunc'. Esto es para la compatibilidad con `ptypes.h' en el compilador de Free Pascal.
-p prefijo
--ext-prefix-alias prefijo
Crea un alias para cada símbolo exportado usando el prefijo dado. Por ejemplo, si el prefijo es `a', entonces un símbolo exportado `_myfunc' será exportado también como `a_myfunc'.
-x
--no-idata4
No incluya la tabla de importación idata version 4.
-c
--no-idata5
No incluya la tabla de importación idata version 5.
--use-nul-prefixed-import-tables
Las tablas de importación que empiezan con un nombre de módulo de cero bytes son generadas de forma predeterminada. Esta opción hace que un nombre de módulo de un byte (`\0') sea usado en su lugar.
-I nombre-archivo-libreria
--identify nombre-archivo-libreria
Identifica el archivo de librería de importación especificado. Esto implica que dlltool intentará determinar el nombre de la DLL a la que hace referencia el archivo de librería de importación y lo imprimirá en la salida estándar.
--identify-strict
Igual que --identify, pero genera un error si el archivo de librería de importación no es válido o si no se puede identificar.
-i
--interwork
Genera una librería de importación para la arquitectura ARM. Esto es principalmente para la compatibilidad con el código existente.
-n
--nodelete
No elimine los archivos temporales de ensamblador creados por dlltool. Especificar esta opción dos veces (-nn) evitará que se eliminen los archivos objeto temporales utilizados para crear la librería de importación.
-t prefijo
--temp-prefix prefijo
Utiliza el prefijo dado para los nombres de los archivos temporales creados por dlltool. El valor predeterminado es `tmp-'.
-v
--verbose
Activa la salida detallada, que informa sobre las acciones realizadas por dlltool.
-h
--help
Muestra un resumen de las opciones de uso de dlltool y termina.
-V
--version
Muestra la información de versión de dlltool y termina.
--no-leading-underscore
Desactiva la adición de un guion bajo inicial a los símbolos exportados en la librería de importación. Por defecto, el guion bajo se añade.
--leading-underscore
Activa la adición de un guion bajo inicial a los símbolos exportados en la librería de importación. Esta es la opción predeterminada.

">--no-default-excludes
Cuando se utiliza --export-all-symbols, por defecto evitará exportar ciertos símbolos especiales. La lista actual de símbolos a evitar exportar es DllMain@12, DllEntryPoint@0, impure_ptr. Puedes usar la opción --no-default-excludes para proceder y exportar estos símbolos especiales. Esto solo tiene sentido cuando se utiliza --export-all-symbols.
-S ruta
--as ruta
Especifica la ruta, incluido el nombre del archivo, del ensamblador que se utilizará para crear el archivo de exportaciones.
-f opciones
--as-flags opciones
Especifica cualquier opción de línea de comandos específica que se pasará al ensamblador al construir el archivo de exportaciones. Esta opción funcionará incluso si la opción -S no se utiliza. Esta opción solo toma un argumento, y si aparece más de una vez en la línea de comandos, las apariciones posteriores anularán las anteriores. Por lo tanto, si es necesario pasar múltiples opciones al ensamblador, estas deben ir entre comillas dobles.
-D nombre
--dll-name nombre
Especifica el nombre que se almacenará en el archivo .def como el nombre de la DLL cuando se utilice la opción -e. Si esta opción no está presente, entonces el nombre de archivo dado a la opción -e se utilizará como el nombre de la DLL.
-m máquina
-machine máquina
Especifica el tipo de máquina para la cual se debe construir el archivo de biblioteca. dlltool tiene un tipo predeterminado incorporado, dependiendo de cómo se creó, pero esta opción se puede usar para anularlo. Esto normalmente solo es útil al crear DLLs para un procesador ARM, cuando el contenido de la DLL está codificado usando instrucciones Thumb.
-a
--add-indirect
Especifica que cuando dlltool esté creando el archivo de exportaciones, debe agregar una sección que permita que las funciones exportadas se referencien sin usar la biblioteca de importación. ¡Lo que sea que eso signifique!
-U
--add-underscore
Especifica que cuando dlltool esté creando el archivo de exportaciones, debe agregar un guion bajo al principio de los nombres de todos los símbolos exportados.
--no-leading-underscore
--leading-underscore
Especifica si los símbolos estándar deben prefijarse o no.
--add-stdcall-underscore
Especifica que cuando dlltool esté creando el archivo de exportaciones, debe agregar un guion bajo al principio de los nombres de las funciones stdcall exportadas. Los nombres de variables y las funciones no stdcall no se modifican. Esta opción es útil al crear bibliotecas de importación compatibles con GNU para DLLs de terceros que fueron compiladas con herramientas de MS-Windows.
-k
--kill-at
Especifica que los sufijos @<número> deben omitirse de los nombres de las funciones stdcall que se importarán de la DLL. Esto es útil al crear una biblioteca de importación para una DLL que exporta funciones stdcall pero sin el sufijo de nombre de símbolo @<número> habitual.

Esto no cambia el nombre de los símbolos proporcionados por la biblioteca de importación a los programas enlazados contra ella, sino solo las entradas en la tabla de importación (es decir, la sección .idata).

-A
--add-stdcall-alias
Especifica que cuando dlltool esté creando el archivo de exportaciones, debe agregar alias para símbolos stdcall sin @ <número> además de los símbolos con @ <número>.
-p
--ext-prefix-alias prefijo
Hace que dlltool cree alias externos para todas las importaciones de DLL con el prefijo especificado. Los alias se crean tanto para símbolos externos como de importación sin guion bajo al principio.
-x
--no-idata4
Especifica que cuando dlltool esté creando los archivos de exportación y biblioteca debe omitir la sección ".idata4". Esto es para compatibilidad con ciertos sistemas operativos.
--use-nul-prefixed-import-tables
Especifica que cuando dlltool esté creando los archivos de exportación y biblioteca debe prefijar las tablas ".idata4" y ".idata5" con un elemento cero. Esto emula la generación antigua de bibliotecas de importación de "dlltool" de gnu. Por defecto, esta opción está desactivada.
-c
--no-idata5
Especifica que cuando dlltool esté creando los archivos de exportación y biblioteca debe omitir la sección ".idata5". Esto es para compatibilidad con ciertos sistemas operativos.
-I nombre_archivo
--identify nombre_archivo
Especifica que dlltool debe inspeccionar la biblioteca de importación indicada por nombre_archivo e informar, en "stdout", el(los) nombre(s) de las DLL(s) asociadas. Esto se puede realizar además de cualquier otra operación indicada por las otras opciones y argumentos. dlltool falla si la biblioteca de importación no existe o no es realmente una biblioteca de importación. Ver también --identify-strict.
--identify-strict
Modifica el comportamiento de la opción --identify, de modo que se informa un error si nombre_archivo está asociado con más de una DLL.
-i
--interwork
Especifica que dlltool debe marcar los objetos en el archivo de biblioteca y el archivo de exportaciones que produce como que soportan la interconexión entre código ARM y Thumb.
-n
--nodelete
Hace que dlltool conserve los archivos temporales del ensamblador que utilizó para crear el archivo de exportaciones. Si esta opción se repite, dlltool también conservará los archivos objeto temporales que utiliza para crear el archivo de biblioteca.
-t prefijo
--temp-prefix prefijo
Hace que dlltool utilice prefijo al construir los nombres de los archivos temporales del ensamblador y objeto. Por defecto, el prefijo del archivo temporal se genera a partir del pid.
-v
--verbose
Hace que dlltool describa lo que está haciendo.
-h
--help
Muestra una lista de opciones de línea de comandos y luego sale.
-V
--version
Muestra el número de versión de dlltool y luego sale.
@archivo
Lee las opciones de la línea de comandos desde archivo. Las opciones leídas se insertan en lugar de la opción original @archivo. Si archivo no existe, o no se puede leer, la opción se tratará literalmente y no se eliminará.

Las opciones en archivo están separadas por espacios en blanco. Un carácter de espacio en blanco puede incluirse en una opción rodeando la opción completa con comillas simples o dobles. Cualquier carácter (incluido una barra invertida) puede incluirse prefijando el carácter a incluir con una barra invertida. El archivo puede contener él mismo opciones adicionales @archivo; cualquiera de estas opciones se procesará recursivamente.
