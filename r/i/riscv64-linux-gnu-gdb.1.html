GDB(1) Herramientas de desarrollo de GNU GDB(1)

NOMBRE

gdb - El depurador de GNU

SINOPSIS

gdb [OPCIONES] [programa|programa ID_proceso|programa core]

DESCRIPCIÓN

El propósito de un depurador como GDB es permitirte ver qué está sucediendo "dentro" de otro programa mientras se ejecuta, o qué estaba haciendo otro programa en el momento en que falló.

GDB puede hacer cuatro tipos de cosas principales (más otras cosas en apoyo de estas) para ayudarte a detectar errores en el acto:

  • Iniciar tu programa, especificando cualquier cosa que pueda afectar su comportamiento.
  • Hacer que tu programa se detenga bajo condiciones especificadas.
  • Examinar qué ha sucedido, cuando tu programa se ha detenido.
  • Cambiar cosas en tu programa, para que puedas experimentar corrigiendo los efectos de un error y seguir aprendiendo sobre otro.

Puedes usar GDB para depurar programas escritos en C, C++, Fortran y Modula-2.

GDB se invoca con el comando de shell "gdb". Una vez iniciado, lee comandos del terminal hasta que le digas que salga con el comando GDB "quit" o "exit". Puedes obtener ayuda en línea del propio GDB usando el comando "help".

Puedes ejecutar "gdb" sin argumentos u opciones; pero la forma más habitual de iniciar GDB es con uno o dos argumentos, especificando un archivo ejecutable como argumento:

gdb programa

También puedes iniciarlo especificando tanto un archivo ejecutable como un archivo core:

gdb programa core

Alternativamente, puedes especificar un ID de proceso como segundo argumento o usar la opción "-p", si quieres depurar un proceso en ejecución:

gdb programa 1234
gdb -p 1234

lo que adjuntaría GDB al proceso 1234. Con la opción -p puedes omitir el nombre de archivo del programa.

Estos son algunos de los comandos de GDB más solicitados:

break [archivo:][función|línea]
Establece un punto de interrupción en función o línea (en archivo).
run [lista_args]
Inicia tu programa (con lista_args, si se especifica).
bt
Backtrace: muestra la pila del programa.
print expresión
Muestra el valor de una expresión.
c
Continúa ejecutando tu programa (después de detenerse, por ejemplo, en un punto de interrupción).
next
Ejecuta la siguiente línea del programa (después de detenerse); avanza *sobre* cualquier llamada a función en la línea.
edit [archivo:]función
Muestra la línea del programa donde está actualmente detenido.
list [archivo:]función
Escribe el texto del programa en las inmediaciones de donde está actualmente detenido.
step
Ejecuta la siguiente línea del programa (después de detenerse); entra *dentro* de cualquier llamada a función en la línea.
help [nombre]
Muestra información sobre el comando GDB nombre, o información general sobre el uso de GDB.
quit
exit
Sale de GDB.

Para obtener detalles completos sobre GDB, consulta Using GDB: A Guide to the GNU Source-Level Debugger, de Richard M. Stallman y Roland H. Pesch. El mismo texto está disponible en línea como la entrada "gdb" en el programa "info".

OPCIONES

Cualquier argumento que no sean opciones especifica un archivo ejecutable y un archivo core (o ID de proceso); es decir, el primer argumento encontrado sin un indicador de opción asociado es equivalente a una opción --se, y el segundo, si existe, es equivalente a una opción -c si es el nombre de un archivo. Muchas opciones tienen formas largas y abreviadas; ambas se muestran aquí. Las formas largas también se reconocen si las trunca, siempre que sea suficiente parte de la opción para que sea inequívoca.

Las formas abreviadas se muestran aquí con - y las formas largas con -- para reflejar cómo se muestran en --help. Sin embargo, GDB reconoce todas las siguientes convenciones para la mayoría de las opciones:

"--option=valor"
"--option valor"
"-option=valor"
"-option valor"
"--o=valor"
"--o valor"
"-o=valor"
"-o valor"

Todos los argumentos de línea de comandos y opciones que proporciones se procesan en orden secuencial. El orden marca la diferencia cuando se utiliza la opción -x.

--help
-h
Lista todas las opciones, con explicaciones breves.
--symbols=archivo
-s archivo
Lee la tabla de símbolos del archivo.
--write
Permite escribir en archivos ejecutables y core.
--exec=archivo
-e archivo
Usa archivo como el archivo ejecutable a ejecutar cuando sea apropiado, y para examinar datos puros en conjunto con un volcado de memoria.
--se=archivo
Lee la tabla de símbolos del archivo y úsala como el archivo ejecutable.
--core=archivo
-c archivo
Usa archivo como un volcado de memoria (core dump) para examinar.
--command=archivo
-x archivo
Ejecuta comandos de GDB desde archivo.
--eval-command=comando
-ex comando
Ejecuta el comando de GDB dado.
--init-eval-command=comando
-iex
Ejecuta el comando de GDB antes de cargar el inferior.
--directory=directorio
-d directorio
Añade directorio a la ruta para buscar archivos fuente.
--nh
No ejecuta comandos desde ~/.config/gdb/gdbinit, ~/.gdbinit, ~/.config/gdb/gdbearlyinit, o ~/.gdbearlyinit
--nx
-n
No ejecuta comandos desde ningún archivo de inicialización .gdbinit o .gdbearlyinit.
--quiet
--silent
-q
«Silencioso». No imprime los mensajes introductorios y de derechos de autor. Estos mensajes también se suprimen en modo batch.
--batch
Ejecuta en modo batch. Sale con estado 0 después de procesar todos los archivos de comandos especificados con -x (y .gdbinit, si no está inhibido). Sale con un estado distinto de cero si ocurre un error al ejecutar los comandos de GDB en los archivos de comandos.

El modo batch puede ser útil para ejecutar GDB como un filtro

gdb(1) — Arch manual pages

NAME

gdb — The GNU Debugger

SYNOPSIS

gdb [option...] [program [arglist...]]
gdb [-nx] [-irrelevant] [--interpreter=interp]

gdb [-n] [-batch] [-ex command]... [-x commandfile]... [-tui] [program [arglist...]]

gdb [-n] [-batch] [-ex command]... [-x commandfile]... [-tui] [--pid=pid]

gdb [-n] [-batch] [-ex command]... [-x commandfile]... [-tui] [--pid=pid] [program [arglist...]]

DESCRIPTION

The GNU Debugger, gdb, allows you to see what is going on inside another program while it executes or what another program was doing at the time it crashed. You can set breakpoints where you will, step the program, and change variables of your programs for experiments.

gdb can be used on executable files, and also on core dumps.

When gdb is invoked, it may be telling you that you have a core dump file to analyze. You can also ask gdb to analyze a core dump file by typing gdb followed by the program name and the core dump file name.

If you start gdb without any arguments, it will start up and tell you the name of the program it is symbolicating, and the source file it is reading.

OPTIONS

--batch
Run in batch mode. This is useful for producing automated test output. In batch mode, gdb will terminate execution of the program at the first error, for example to download and run a program on another computer; in order to make this more useful, the message 
Program exited normally.
(which is ordinarily issued whenever a program running under GDB control terminates) is not issued when running in batch mode.
--batch-silent
Run in batch mode, just like --batch, but totally silent. All GDB output is suppressed (stderr is unaffected). This is much quieter than --silent and would be useless for an interactive session.

This is particularly useful when using targets that give Loading section messages, for example.

Note that targets that give their output via GDB, as opposed to writing directly to "stdout", will also be made silent.

--args prog [arglist]
Change interpretation of command line so that arguments following this option are passed as arguments to the inferior. As an example, take the following command: 
gdb ./a.out -q
It would start GDB with -q, not printing the introductory message. On the other hand, using: 
gdb --args ./a.out -q
starts GDB with the introductory message, and passes the option to the inferior.
--pid=pid
Attach GDB to an already running program, with the PID pid.
--tui
Open the terminal user interface.
--readnow
Read all symbols from the given symfile on the first access.
--readnever
Do not read symbol files.
--return-child-result
GDB's exit code will be the same as the child's exit code.
--configuration
Print details about GDB configuration and then exit.
--version
Print version information and then exit.
--cd=directory
Run GDB using directory as its working directory, instead of the current directory.
--data-directory=directory
-D
Run GDB using directory as its data directory. The data directory is where GDB searches for its auxiliary files.
--fullname
-f
Emacs sets this option when it runs GDB as a subprocess. It tells GDB to output the full file name and line number in a standard, recognizable fashion each time a stack frame is displayed (which includes each time the program stops). This recognizable format looks like two \032 characters, followed by the file name, line number and character position separated by colons, and a newline. The Emacs-to-GDB interface program uses the two \032 characters as a signal to display the source code for the frame.
-b baudrate
Set the line speed (baud rate or bits per second) of any serial interface used by GDB for remote debugging.
-l timeout
Set timeout, in seconds, for remote debugging.
--tty=device
Run using device for your program's standard input and output.

SEE ALSO

The full documentation for GDB is maintained as a Texinfo manual. If the "info" and "gdb" programs and GDB's Texinfo documentation are properly installed at your site, the command

info gdb

should give you access to the complete manual.
