NOMBRE

gdb - El depurador GNU

SINOPSIS

gdb [OPCIONES] [programa|programa ID_proceso|programa core]

DESCRIPCIÓN

El propósito de un depurador como GDB es permitirte ver qué está sucediendo "dentro" de otro programa mientras se ejecuta, o qué estaba haciendo otro programa en el momento en que falló.

GDB puede hacer cuatro tipos principales de cosas (además de otras cosas en apoyo a estas) para ayudarte a detectar errores en el acto:

  • Iniciar tu programa, especificando cualquier cosa que pueda afectar su comportamiento.
  • Hacer que tu programa se detenga bajo condiciones especificadas.
  • Examinar lo que ha sucedido, cuando tu programa se ha detenido.
  • Cambiar cosas en tu programa, para que puedas experimentar corrigiendo los efectos de un error y continuar aprendiendo sobre otro.

Puedes usar GDB para depurar programas escritos en C, C++, Fortran y Modula-2.

GDB se invoca con el comando de shell "gdb". Una vez iniciado, lee comandos desde el terminal hasta que le indicas que salga con el comando GDB "quit" o "exit". Puedes obtener ayuda en línea desde el propio GDB usando el comando "help".

Puedes ejecutar "gdb" sin argumentos ni opciones; pero la forma más habitual de iniciar GDB es con un argumento o dos, especificando un archivo ejecutable como argumento:

gdb programa

También puedes iniciar con un archivo ejecutable y un archivo core especificados:

gdb programa core

Puedes, en cambio, especificar un ID de proceso como segundo argumento o usar la opción "-p", si quieres depurar un proceso en ejecución:

gdb programa 1234
gdb -p 1234

adjuntaría GDB al proceso 1234. Con la opción -p puedes omitir el nombre de archivo de programa.

Aquí están algunos de los comandos GDB más frecuentemente necesarios:

break [archivo:][función|línea]
Establece un punto de interrupción en función o línea (en archivo).
run [lista_args]
Inicia tu programa (con lista_args, si se especifica).
bt
Backtrace (rastreo inverso): muestra la pila del programa.
print expresión
Muestra el valor de una expresión.
c
Continúa ejecutando tu programa (después de detenerse, por ejemplo, en un punto de interrupción).
next
Ejecuta la siguiente línea de programa (después de detenerse); pasa por encima de cualquier llamada a función en la línea.
edit [archivo:]función
examina la línea del programa donde se detuvo actualmente.
list [archivo:]función
escribe el texto del programa en las inmediaciones de donde se detuvo actualmente.
step
Ejecuta la siguiente línea de programa (después de detenerse); entra en cualquier llamada a función en la línea.
help [nombre]
Muestra información sobre el comando GDB nombre, o información general sobre el uso de GDB.
quit
exit
Sale de GDB.

Para obtener detalles completos sobre GDB, consulta Using GDB: A Guide to the GNU Source-Level Debugger, de Richard M. Stallman y Roland H. Pesch. El mismo texto está disponible en línea como la entrada "gdb" en el programa "info".

OPCIONES

Cualquier argumento que no sean opciones especifica un archivo ejecutable y un archivo core (o ID de proceso); es decir, el primer argumento encontrado sin un indicador de opción asociado es equivalente a una opción --se, y el segundo, si existe, es equivalente a una opción -c si es el nombre de un archivo. Muchas opciones tienen formas largas y abreviadas; ambas se muestran aquí. Las formas largas también se reconocen si las truncas, siempre que la opción esté lo suficientemente completa como para ser inequívoca.

Las formas abreviadas se muestran aquí con - y las formas largas se muestran con -- para reflejar cómo se muestran en --help. Sin embargo, GDB reconoce todas las siguientes convenciones para la mayoría de las opciones:

"--opción=valor"
"--opción valor"
"-opción=valor"
"-opción valor"
"--o=valor"
"--o valor"
"-o=valor"
"-o valor"

Todas las opciones y argumentos de línea de comandos que proporciones se procesan en orden secuencial. El orden marca la diferencia cuando se usa la opción -x.

--symbols=archivo
-s archivo

--write

--exec=archivo
-e archivo
Usa archivo como archivo ejecutable para ejecutar cuando sea apropiado, y para examinar datos puros en conjunción con un volcado de memoria (core dump).

OPTIONS

--batch
Run in batch mode. This is useful for running GDB within a script. When running in batch mode, GDB will exit after processing all commands from the command file specified by the -x option, or after executing all commands specified in the command line. GDB will not prompt for input. This option is also useful when running GDB on another computer.

In batch mode, the normal GDB startup message and the (gdb) prompt are suppressed. Also, the message 

Program exited normally.
(que normalmente se emite cada vez que un programa que se ejecuta bajo el control de GDB termina) no se emite cuando se ejecuta en modo batch.

--batch-silent
Ejecutar en modo batch, igual que --batch, pero totalmente silencioso. Toda la salida de GDB se suprime (stderr no se ve afectado). Esto es mucho más silencioso que --silent y sería inútil para una sesión interactiva.

Esto es particularmente útil cuando se utilizan targets que generan mensajes de Loading section, por ejemplo.

Tenga en cuenta que los targets que emiten su salida a través de GDB, en lugar de escribir directamente en la "stdout", también se silenciarán.

--args prog [arglist]
Cambiar la interpretación de la línea de comandos para que los argumentos que siguen a esta opción se pasen como argumentos al inferior. Como ejemplo, tome el siguiente comando: 
gdb ./a.out -q

Iniciaría GDB con -q, sin imprimir el mensaje introductorio. Por otro lado, usando:

gdb --args ./a.out -q

inicia GDB con el mensaje introductorio y pasa la opción al inferior.

--pid=pid
Adjuntar GDB a un programa ya en ejecución, con el PID pid.
--tui
Abrir la interfaz de usuario de terminal.
--readnow
Leer todos los símbolos del archivo de símbolos dado en el primer acceso.
--readnever
No leer archivos de símbolos.
--return-child-result
El código de salida de GDB será el mismo que el código de salida del hijo.
--configuration
Imprimir detalles sobre la configuración de GDB y luego salir.
--version
Imprimir información de la versión y luego salir.
--cd=directory
Ejecutar GDB usando directory como su directorio de trabajo, en lugar del directorio actual.
--data-directory=directory
-D
Ejecutar GDB usando directory como su directorio de datos. El directorio de datos es donde GDB busca sus archivos auxiliares.
--fullname
-f
Emacs establece esta opción cuando ejecuta GDB como un subproceso. Le dice a GDB que emita el nombre de archivo completo y el número de línea de una manera estándar y reconocible cada vez que se muestra un marco de pila (lo que incluye cada vez que el programa se detiene). Este formato reconocible se ve como dos caracteres \032, seguidos del nombre del archivo, el número de línea y la posición del carácter separados por dos puntos, y una nueva línea. El programa de interfaz Emacs-a-GDB utiliza los dos caracteres \032 como una señal para mostrar el código fuente del marco.
-b baudrate
Establecer la velocidad de línea (velocidad en baudios o bits por segundo) de cualquier interfaz serie utilizada por GDB para depuración remota.
-l timeout
Establecer el tiempo de espera, en segundos, para la depuración remota.
--tty=device
Ejecutar usando device para la entrada y salida estándar de su programa.
