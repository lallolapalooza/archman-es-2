NOMBRE

rink-defs - formato de `definition.units` de Rink

DESCRIPCIÓN

La base de datos de unidades es un documento textual que contiene las definiciones de unidades, prefijos, unidades base, cantidades y sustancias.

Los comentarios comienzan con # y continúan hasta el final de la línea. Las líneas en blanco se ignoran. Los comentarios se pueden colocar en la misma línea que las unidades, al final.

 # Esta línea es un comentario
 # Y esta también

Unidades

Las unidades se definen con su nombre y su definición separadas por espacios. Una definición se puede dividir en varias líneas usando \ si se desea.

pie                    12 pulgada

Los comentarios de documentación son líneas que comienzan con ??. Se aplican a la siguiente definición que les sigue. Rink se los muestra a los usuarios finales al consultar una definición.

?? Yarda y libra internacional, desde el 1 de julio de 1959.
?? Los comentarios de documentación se pueden dividir en
?? varias líneas.
pie                    12 pulgada

Sustancias

Las sustancias pueden representar un objeto específico (como la Tierra o el Sol), un material como agua o hormigón, una molécula química, un elemento de la tabla periódica o una partícula elemental.

Una sustancia tiene un nombre, un símbolo opcional (utilizado para fórmulas químicas) y contiene una lista de propiedades dentro de un bloque {}.

Las propiedades pueden ser "const", que se utiliza principalmente para objetos contables como una partícula, o pueden ser una relación, como la densidad de un material.

neutrón {
    masa                const neutron_mass          1.00866491588 u
    longitud_onda       const neutron_wavelength    constante_planck / masa c
    momento_magnético   const neutron_moment        -0.96623650e-26 J/T
}

Las dos variantes de sintaxis para las propiedades son:

 [nombre] const [nombre_salida] [expresión]
 [nombre] [nombre_entrada] [expresión_entrada] / [nombre_salida] [expresión_salida]

Categorías

Las unidades dentro de la misma categoría se agruparán en la interfaz de usuario al realizar búsquedas y otras operaciones. Una categoría se inicia usando el pragmático !category que toma un identificador (lower_snake_case) y un nombre para mostrar como un literal de cadena.

!category us_survey "Medidas de topografía de EE. UU."

Unidades base

Las unidades base son imposibles de definir en términos de otra unidad sin crear un ciclo. Representan cantidades físicas fundamentales como tiempo, longitud, temperatura, etc.

El nombre es una forma abreviada que se utiliza al mostrar la dimensionalidad (por ejemplo, la dimensionalidad de aceleración es m / s^2), mientras que la forma larga se utiliza para fines de visualización.

Solo se deben agregar nuevas unidades base cuando haya un valor claro para hacerlo. Los ejemplos incluyen radianes y bits.

?? Igual a la masa del prototipo internacional del
?? kilogramo. 3er CGPM (1901, CR, 70).
kg        !kilogramo

Cantidades

Las cantidades se muestran entre paréntesis cada vez que rink muestra una unidad. Son muy útiles para el análisis dimensional, ya que puede ser difícil recordar que kg m^2 / s^2 significa la cantidad física de energía.

Las cantidades se definen de manera similar a las unidades, pero la definición comienza con un carácter ?. Las cantidades están en un espacio de nombres separado de las unidades, por lo que los únicos nombres válidos que se pueden usar son las unidades base, así como otras cantidades.

A diferencia de las unidades, las cantidades no tienen valor numérico (ni siquiera un valor de 1 como las unidades derivadas del SI).

longitud                  ? metro
area                    ? longitud^2

Prefijos

Los prefijos permiten la entrada de unidades como gigabytes, megametros, kilosegundos sin necesidad de definir explícitamente cada una en la base de datos de unidades. Los prefijos son siempre adimensionales.

Estos no deben agregarse con frecuencia, solo cuando sea relevante para algún sistema de conteo. Los ejemplos incluyen prefijos de bytes de potencia de dos (MiB, GiB, etc.) y prefijos Duodecimales.

Los prefijos se dividen en dos tipos, prefijos "largos" y prefijos "cortos". Los prefijos cortos generalmente solo deben tener 1 letra. Típicamente, los prefijos cortos son alias de su prefijo largo correspondiente.

Los prefijos se definen de manera similar a otras unidades, pero el nombre termina con un sufijo de - (prefijos largos) o -- (prefijos cortos).

Los prefijos usan su propio espacio de nombres. Sus definiciones solo pueden hacer referencia a otros prefijos, y no a unidades.

kilo-                   1e3
k--                     kilo

GUÍA

Estas directrices se aplican principalmente al contribuir al definitions.units original.

La base de datos de unidades generalmente debe ajustarse para caber dentro de 80 columnas, para facilitar la lectura. Del mismo modo, las definiciones de unidades generalmente deben alinearse verticalmente usando espacios.

Las unidades no triviales generalmente deben tener un comentario de documentación. Este comentario puede explicar qué significa la unidad y proporcionar una cita de su valor.

Si hay múltiples formas de interpretar cómo se debe definir una unidad, entonces mencione qué interpretación se está utilizando. A menos que esté implícito por el nombre (por ejemplo, añossideral). Los ejemplos donde las unidades tienen múltiples interpretaciones incluyen:

•Las unidades personalizadas pueden variar según el país, e incluso pueden variar según el año en ese país. Como las definiciones estadounidenses, británicas, australianas e internacionales del pie.
•Unidades que son inherentemente difusas o representan múltiples fuentes. Esto puede incluir días (calendario, sideral), años (calendario, sideral, tropical) y otros.

Los comentarios de documentación deben estar escritos en inglés estadounidense. Deben tener capitalización de oración y puntos, como se escribe esta guía. Evite las oraciones largas.

Los enlaces externos deben incluir la parte del protocolo (https://, http://). Deben estar rodeados por corchetes angulares, como https://example.com.

Las fechas deben escribirse en formato largo, como 5 de julio de 1982. No utilice formatos ambiguos como 2/3/99. A menudo es suficiente indicar solo el año.

Los comentarios en el archivo de definiciones están escritos para el beneficio de otros mantenedores. Pueden incluir explicaciones de por qué las unidades se definen de cierta manera. También pueden indicar que ciertas unidades forman parte de un grupo o conjunto.

Todas las unidades deben estar dentro de un bloque !category / !endcategory. Los bloques de categoría también deben incluir comentarios relacionados con esa categoría, y el pragmático !category debe seguir inmediatamente al !endcategory de la última categoría. Esto es para permitir que el archivo se navegue fácilmente usando los pliegues de Vim. El nombre para mostrar de una categoría debe estar en mayúsculas de frase y alineado a la columna 70.

NOMBRADO

Los nombres en inglés deben ser en minúsculas sin separadores. Las palabras pueden separarse por guiones bajos cuando añaden claridad. Los ejemplos incluyen pie, brazocubitoolimpico, gallonestadounidense.

Si hay una abreviatura disponible, debe agregarse como un alias del nombre más largo. Los ejemplos incluyen ft para pie, B para byte, y Ω para ohmio.

ft                      pie

NAME

rink-defs — Rink units definitions

DESCRIPTION

This document describes the format of the units definition files used by Rink, a command-line calculator.

SYNTAX

Definitions files consist of zero or more unit definitions. Blank lines and lines starting with a hash symbol (#) are ignored.

A unit definition has the following format:

VERBATIM / DEFINITION

Where VERBATIM is the string that will be used to refer to the unit, and DEFINITION is either a number or another unit definition. If VERBATIM contains spaces or special characters, it must be enclosed in double quotes ("). The definition may be preceded by a full definition string in parentheses. This string will be displayed when the definition is printed.

Definitions may be chained. For example:

"light year" "365 day" "a light year"

In this example, light year is defined as 365 day. The string a light year is the verbatim string that will be used when displaying the definition.

Aliases can be created using a comma.

"foot", "ft", "12 inch"

This defines foot and ft as aliases for each other.

A unit can also be defined as a constant.

pi "3.14159265358979323846" "Pi"

The verbatim string pi is defined as the rational number represented by the string 3.14159265358979323846. The string Pi is the verbatim string shown when displaying the definition.

Units can be grouped into categories for organizational purposes.

!category length
"meter", "m"
!category time
"second", "s"
!endcategory

The !category and !endcategory directives must be on lines by themselves. Categories are optional.

Documentation comments can be added using ??. These comments are not parsed by Rink but can be used by other tools.

?? This is a comment.
"meter", "m"

GUIDELINES

Here are some general guidelines for writing unit definitions:

Canonical names should be the most common representation of the unit. Aliases should be used for other common representations.

Units that are most commonly written in a non-Latin script. Use the non-Latin name as the canonical name, and add an ASCII-based one as an alias. Examples include золотник, 分地.

Some units are typically written with a symbol. Treat these similar to the non-Latin script names. Examples include π (Pi), τ (Tau).

Legacy Unicode symbols should only be used as aliases of more standard names. This includes uncommon symbols such as ㎒ (Unicode symbol for Megahertz).

If there are multiple names for a unit, then the one that’s most typical should be the "canonical name". The canonical version should have the full definition, and the other names should be added as aliases pointing to the canonical version. Avoid duplicating the definition.

DEFINITIONS

Units should be defined in terms of other related units when possible. The expression you use to define the unit will be visible to the end user. For example, a foot is defined as 12 inch rather than as 304.8 mm. This is because there is already a separate entry for inch defined as 2.54 mm. When displaying a unit’s definition, Rink shows both the original definition as well as the absolute value. So for foot it shows that it’s defined as 12 inch which equals 304.8 millimeter.

Rink can represent arbitrary precision rational numbers. The only limitation is how much memory is available. As a result, irrational numbers like Pi or Euler’s constant should be defined to at least 20 digits.

Universal constants that are measured experimentally should have as many significant figures as are currently known. For example, if a number is known to ±0.000003, then it should be listed to 6 digits after the decimal point.

FILES

Rink searches for the definitions file in these locations:

•./rink/definitions.units
•$XDG_CONFIG_DIR/rink/definitions.units
•/usr/share/rink/definitions.units

When live currency fetching is enabled, Rink also looks for a currency file in these locations:

•./rink/currency.units
•$XDG_CONFIG_DIR/rink/currency.units
•/usr/share/rink/currency.units

HISTORY

Rink’s units database was originally based on GNU Units and inherits much of its syntax from there.

Notable differences include:

•Removal of !locale, !set, !utf8, and other pragmas not used by Rink.
•Addition of !category and !endcategory.
•Addition of documentation comments starting with ??.
•Addition of substances.
