RIVERCTL(1) Manual de Comandos Generales RIVERCTL(1)

NOMBRE

riverctl - interfaz de línea de comandos para controlar river

SINOPSIS

riverctl [opciones] comando [argumentos específicos del comando]

DESCRIPCIÓN

riverctl es una utilidad de línea de comandos utilizada para controlar y configurar river a través del protocolo Wayland.

OPCIONES

-h

Muestra un mensaje de ayuda y sale.

-version

Muestra el número de versión y sale.

TERMINOLOGÍA

Este manual utiliza términos que algunos pueden encontrar confusos, procedentes principalmente de su uso en otros proyectos de Wayland.

El compositor, servidor de pantalla, servidor Wayland, etc., son formas de referirse a river en sí mismo.

Una vista (o toplevel) es lo que la mayoría llama una ventana.

Una salida es un sinónimo de una pantalla o monitor.

Las etiquetas (tags) son la forma que tiene river de dividir las vistas de una salida en grupos (no necesariamente disjuntos), una analogía con los espacios de trabajo.

COMANDOS

ACCIONES

close

Cierra la vista enfocada.

exit

Sale del compositor, terminando la sesión Wayland.

focus-output next|previous|up|right|down|left|nombre

Enfoca la siguiente o anterior salida, la salida más cercana en cualquier dirección o una salida por nombre.

focus-view [-skip-floating] next|previous|up|down|left|right

Enfoca la siguiente o anterior vista en la pila o la vista más cercana en cualquier dirección.
•
-skip-floating: Omite las vistas flotantes, enfocando solo las teseladas.

Mueve la vista enfocada en la dirección especificada por delta píxeles lógicos. La vista se establecerá como flotante.

resize horizontal|vertical delta

Redimensiona la vista enfocada a lo largo del eje dado por delta píxeles lógicos. La vista se establecerá como flotante.

Ajusta la vista enfocada al borde de la pantalla especificado. La vista se establecerá como flotante.

send-to-output [-current-tags] next|previous|up|right|down|left|nombre

•

Ejecuta comando_shell usando `/bin/sh -c comando_shell`. Ten en cuenta que spawn solo toma un argumento. Para ejecutar un comando que toma múltiples argumentos, se recomienda envolver el comando entre comillas.

swap next|previous|up|down|left|right

Intercambia la vista enfocada con la siguiente o anterior vista no flotante en la pila o la vista no flotante más cercana en cualquier dirección.

toggle-float

Alterna el estado flotante de la vista enfocada.

toggle-fullscreen

Alterna el estado de pantalla completa de la vista enfocada.

Sube la vista enfocada a la parte superior de la pila de diseño. Si la vista superior en la pila ya está enfocada, sube la segunda vista.

Establece el espacio de nombres de diseño que se utilizará por defecto para todas las salidas.

Envía comando al generador de diseño en la salida actualmente enfocada con el espacio_de_nombres dado, si lo hubiere. Los comandos que un generador de diseño entiende dependen del generador de diseño. Para rivertile, consulta la documentación en la página del manual rivertile(1).

GESTIÓN DE ETIQUETAS

Las etiquetas son similares a los espacios de trabajo pero más flexibles. Puedes asignar múltiples etiquetas a las vistas y enfocar múltiples etiquetas simultáneamente. Se utilizan campos de bits para describir conjuntos de etiquetas al interactuar con river. Como tales, los siguientes comandos toman un número normal de base 10 como argumento, pero la semántica se entiende mejor en binario. El número binario 000000001 representa un conjunto que contiene solo la etiqueta 1, mientras que 100001101 representa un conjunto que contiene las etiquetas 1, 3, 4 y 9.

Cuando una vista se inicia, se le asignan las etiquetas actualmente enfocadas de la salida.

Siempre debe enfocarse al menos una etiqueta y cada vista debe asignarse al menos una etiqueta. Las operaciones que violarían alguno de estos requisitos son ignoradas por river.

set-focused-tags etiquetas

Muestra vistas con etiquetas correspondientes a los bits establecidos de etiquetas en la salida actualmente enfocada.

set-view-tags etiquetas

Asigna a la vista actualmente enfocada las etiquetas correspondientes a los bits establecidos de etiquetas.

toggle-focused-tags etiquetas

Alterna la visibilidad de las vistas con etiquetas correspondientes a los bits establecidos de etiquetas en la salida actualmente enfocada.

toggle-view-tags etiquetas

Alterna las etiquetas de la vista actualmente enfocada correspondientes a los bits establecidos de etiquetas.

spawn-tagmask máscara_etiquetas

Establece una máscara_etiquetas para filtrar las etiquetas asignadas a las vistas recién iniciadas. Esta máscara se aplicará a las etiquetas de las nuevas vistas con un AND bit a bit. Si, por ejemplo, las etiquetas 000011111 están enfocadas y la máscara_etiquetas de inicio es 111110001, una nueva vista se asignará las etiquetas 000010001. Si no quedaran etiquetas después del filtrado, la máscara_etiquetas se ignora.

focus-previous-tags

Establece las etiquetas a su valor anterior en la salida actualmente enfocada, permitiendo saltar entre 2 configuraciones de etiquetas.

send-to-previous-tags

Asigna a la vista actualmente enfocada las etiquetas anteriores de la salida actualmente enfocada.

MAPAS

Los mapas son modales en river. Cada mapa está asociado con un modo y solo está activo mientras se está en ese modo. Hay dos modos especiales: "normal" y "bloqueado". El modo normal es el modo inicial al arrancar. El modo bloqueado se entra automáticamente mientras la sesión está bloqueada (por ejemplo, debido a un bloqueador de pantalla). No se puede entrar ni salir de él manualmente.

Los siguientes modificadores están disponibles para su uso en los mapas:

  • Shift
  • Control
  • Mod1 (Alt)
  • Mod3
  • Mod4 (Super)
  • Mod5
  • None

Alt y Super son alias de Mod1 y Mod4 respectivamente. None permite crear un mapa sin modificadores.

Las teclas se especifican por su nombre XKB keysym. Consulta /usr/include/xkbcommon/xkbcommon-keysyms.h para la lista completa.

Los botones del ratón se especifican por sus nombres de código de evento de entrada de Linux. Los valores más comúnmente utilizados son:

  • BTN_LEFT - botón izquierdo del ratón
  • BTN_RIGHT - botón derecho del ratón
  • BTN_MIDDLE - botón central del ratón

Una lista completa se puede encontrar en /usr/include/linux/input-event-codes.h

declare-mode nombre

Crea un nuevo modo llamado nombre.

enter-mode nombre

Cambia al modo dado si existe.

map [-release|-repeat|-layout índice] modo modificadores tecla comando

Ejecuta comando cuando se presiona tecla con los modificadores especificados mientras se está en el modo dado.
•
-release: Ejecuta el comando al soltar la tecla en lugar de presionarla.
†

†

map-button [-release|-repeat|-layout index] mode modifiers button command

Ejecuta el comando cuando se presiona el botón del ratón especificado con los modificadores dados mientras se está en el modo dado.

unmap mode modifiers key

Elimina el mapa para la combinación de modo, modificadores y tecla dada.

unmap-button mode modifiers button

Elimina el mapa de botón para la combinación de modo, modificadores y botón dada.

clear-mappings [mode]

Elimina todos los mapas para el modo dado. Si no se especifica un modo, elimina todos los mapas de todos los modos.

clear-tags [mode]

Elimina todas las asignaciones de etiquetas para el modo dado. Si no se especifica un modo, elimina todas las asignaciones de etiquetas de todos los modos.

clear-view-tags mode tags

Elimina las etiquetas dadas de todas las vistas en el modo dado. Si no se especifica un modo, elimina las etiquetas de todas las vistas en todos los modos.

set-view-title title

Establece el título de la vista enfocada.

set-view-class class

Establece la clase de la vista enfocada.

set-view-app-id app_id

Establece el ID de aplicación de la vista enfocada.

set-output-geometry x y width height

Establece la geometría de la salida enfocada. Los valores se escalan a la resolución de la pantalla.

CONFIGURACIÓN

riverctl lee los comandos de configuración del archivo ~/.config/river/init o /etc/river/init. Si ninguno de los dos existe, se intentará ejecutar el comando dado con riverctl.

Por ejemplo, para configurar un atajo de teclado para iniciar termite:

map normal Mod4+Return spawn termite

EJEMPLOS

Para cerrar la ventana enfocada:

riverctl close

Para mover la ventana enfocada a la siguiente etiqueta:

riverctl toggle-focused-tags $(($(echo $((1 << (<(expr $(cat ~/.config/river/tags) + 1)))))

Para cerrar la ventana enfocada y luego salir de river:

riverctl close ; riverctl exit

Para iniciar dmenu y luego abrir el archivo seleccionado:

riverctl spawn dmenu_run < ~/.cache/dmenu_run

REGLAS

Las reglas comparan el app-id y el título de las vistas con un patrón de glob. Un glob es una cadena que opcionalmente puede tener un * al principio y/o al final. Un * en un glob coincide con cero o más caracteres arbitrarios en el app-id o título.

Por ejemplo, abc coincide con a*, *a*, *b*, *c, abc, y * pero no coincide con *a, b*, *b, c*, o ab. Tenga en cuenta que * coincide con todo mientras que ** y la cadena vacía no son válidos.

rule-add [-app-id glob|-title glob] acción [argumentos]

Agrega una regla que aplica una acción a las vistas cuyo app-id y título coincidan con el glob respectivo. Omitir -app-id o -title es equivalente a pasar -app-id * o -title *. Algunas acciones requieren uno o más argumentos.

Los tipos de acción compatibles son:

  • float: Hace que la vista sea flotante. Se aplica solo a vistas nuevas.
  • no-float: No hace que la vista sea flotante. Se aplica solo a vistas nuevas.
  • ssd: Utiliza decoraciones del lado del servidor para la vista. Se aplica a vistas nuevas y existentes.
  • csd: Utiliza decoraciones del lado del cliente para la vista. Se aplica a vistas nuevas y existentes.
  • tags: Establece las etiquetas iniciales de la vista. Requiere las etiquetas como argumento. Se aplica solo a vistas nuevas.
  • output: Establece la salida inicial de la vista. Requiere la salida como argumento. Se aplica solo a vistas nuevas. La salida se puede especificar ya sea por nombre de conector (como HDMI-A-1 o DP-2), o por identificador en forma de FABRICANTE MODELO SERIE, por ejemplo para una salida con fabricante: HP Inc., modelo: HP 22w, y serie: CNC93720WF, el identificador sería: HP Inc. HP 22w CNC93720WF. Si el fabricante, modelo o serie es desconocido, se utiliza la palabra "Unknown".
  • position: Establece la posición inicial de la vista, limitándola a los límites de la salida. Requiere las coordenadas x e y de la vista como argumentos, ambas deben ser no negativas. Se aplica solo a vistas nuevas.
  • dimensions: Establece las dimensiones iniciales de la vista, limitándolas a las restricciones de la vista. Requiere el ancho y la altura de la vista como argumentos, ambos deben ser no negativos. Se aplica solo a vistas nuevas.
  • fullscreen: Hace que la vista sea a pantalla completa. Se aplica solo a vistas nuevas.
  • no-fullscreen: No hace que la vista sea a pantalla completa. Se aplica solo a vistas nuevas.
  • tearing: Permite que la vista se "rompa" cuando está a pantalla completa, independientemente de la preferencia de la vista. Se aplica a vistas nuevas y existentes.
  • no-tearing: Deshabilita el "tearing" para la vista independientemente de la preferencia de la vista. Se aplica a vistas nuevas y existentes.

Tanto las reglas float como no-float se agregan a la misma lista, lo que significa que agregar una regla no-float con los mismos argumentos que una regla float la sobrescribirá. Lo mismo ocurre con las reglas ssd y csd, fullscreen y no-fullscreen, tearing y no-tearing.

Si múltiples reglas en una lista coinciden con una vista dada, se aplicará la regla más específica. Por ejemplo, con las siguientes reglas:

app-id  title  action
foo     bar    ssd
foo     *      csd
*       bar    csd
*       baz    ssd
una vista con app-id 'foo' y título 'bar' obtendrá ssd a pesar de coincidir con dos reglas csd, ya que la primera regla es la más específica. Además, una vista con app-id 'foo' y título 'baz' obtendrá csd a pesar de coincidir con la última regla de la lista, ya que la especificidad del app-id tiene prioridad sobre la especificidad del título.

Si una vista no coincide con ninguna regla, river respetará los deseos csd/ssd del cliente y puede iniciar la vista flotante basándose en heurísticas simples destinadas a capturar vistas tipo popup.

Si una vista se inicia a pantalla completa o no es flotante, las reglas position y dimensions no tendrán efecto. Una vista debe coincidir con una regla float para que estas tengan efecto.

rule-del [-app-id glob|-title glob] acción

Elimina una regla creada usando rule-add con los argumentos dados.

list-rules float|ssd|tags|position|dimensions|fullscreen

Imprime la lista de reglas especificada. La salida está ordenada de más específica a menos específica, el mismo orden en que se verifican las vistas para buscar una coincidencia. Solo la primera regla coincidente en la lista tiene efecto en una vista dada.

NAME

riverctl - control the river compositor

SYNOPSIS

riverctl [-h] -c command [argument...]

DESCRIPTION

The riverctl utility sends commands to the river compositor.

River supports two configuration files. The first is ~/.config/river/init for river specific configuration. The second is ~/.config/river/input for input device configuration.

The commands that riverctl supports are listed below. Commands for input device configuration are listed under INPUT CONFIGURATION.

OPTIONS

-h
Show help message and exit.
-c, command
The command to send to river. For more information, see the COMMANDS section.

TERMINOLOGY

The riverctl utility uses the following terminology:

  • Output: A physical display connected to your system.
  • View: A view is a container for a single application window.
  • Container: A container is a node in the layout tree. Views are containers, and other containers can be split and arranged to create complex layouts.
  • Focus: The currently selected view or container.
  • Mode: A set of keybindings. The default mode is called normal.
  • Seat: A seat is a collection of input devices. River typically only uses one seat.

COMMANDS

get-focused-view

Prints the unique identifier of the focused view to stdout.

get-views

Prints a list of all views to stdout.

get-outputs

Prints a list of all outputs to stdout.

get-workspaces

Prints a list of all workspaces to stdout.

get-focused-workspace

Prints the name of the focused workspace to stdout.

get-layout

Prints the layout of the focused container to stdout.

map mode key command [argument...]

Binds a key combination to a command in a given mode. mode can be any of the modes defined in your configuration file. For a list of valid key names, see KEYBINDINGS. command is one of the commands listed below.

unmap mode key

Unbinds a key combination from a command in a given mode.

set-mode mode

Sets the current mode to the given mode.

get-mode

Prints the current mode to stdout.

spawn command [argument...]

Spawns a new process.

close

Closes the focused view.

focus direction

Moves the focus in the specified direction. Valid directions are:
  • up
  • down
  • left
  • right
  • next: focus the next view in reading order
  • prev: focus the previous view in reading order
  • parent: focus the parent container
  • first: focus the first view in the focused container

swap direction

Swaps the focused view with the view in the specified direction. Valid directions are:
  • up
  • down
  • left
  • right
  • next: swap with the next view in reading order
  • prev: swap with the previous view in reading order

move-to-output output

Moves the focused view to the specified output.

move-to-workspace workspace [output]

Moves the focused view to the specified workspace. If output is specified, the view will be moved to that output.

merge-with-output output

Merges the focused workspace with the specified output. This command will move all views from the focused workspace to the specified output.

split-ratio ratio

Splits the focused container with the given ratio. ratio must be a float between 0.0 and 1.0.

split-toggle

Toggles the split direction of the focused container. Horizontal and vertical splits are alternated.

fullscreen [state]

Toggles fullscreen for the focused view, or sets it to state, which can be toggle, on, or off.

set-dead-key-moments disabled|on-focus-change|on-output-change

Configure how dead key moments are handled.
  • disabled: Dead key moments are disabled. This is the default.
  • on-focus-change: A dead key moment is triggered whenever focus changes. This means that when you press a dead key, then switch focus to another window, the dead key is processed.
  • on-output-change: A dead key moment is triggered whenever focus changes output. This means that when you press a dead key, then switch focus to another output, the dead key is processed.

If the view to be focused is on an output that does not have focus, focus is switched to that output.

set-cursor-movement-mode disabled|normal|always

Configure how cursor movement affects focus.
  • disabled: Cursor movement does not affect focus. This is the default.
  • normal: Moving the cursor over a view will focus that view. Moving the cursor within a view will not re-focus that view if focus has moved elsewhere.
  • always: Moving the cursor will always focus whatever view is under the cursor.

If the view to be focused is on an output that does not have focus, focus is switched to that output.

hide-cursor timeout timeout

Hide the cursor if it wasn't moved in the last timeout milliseconds until it is moved again. The default value is 0, which disables automatically hiding the cursor. Show the cursor again on any movement.

hide-cursor when-typing enabled|disabled

Hide the cursor when pressing any non-modifier key. Show the cursor again on any movement.

set-cursor-warp disabled|on-output-change|on-focus-change

Set the cursor warp mode. There are two available modes:
  • disabled: Cursor will not be warped. This is the default.
  • on-output-change: When a different output is focused, the cursor will be warped to its center.
  • on-focus-change: When a different view/output is focused, the cursor will be warped to its center.

set-repeat rate delay

Set the keyboard repeat rate to rate key repeats per second and repeat delay to delay milliseconds. The default is a rate of 25 repeats per second and a delay of 600ms.

xcursor-theme theme_name [size]

Set the xcursor theme to theme_name and optionally set the size. The theme of the default seat determines the default for Xwayland and is made available through the XCURSOR_THEME and XCURSOR_SIZE environment variables.

INPUT CONFIGURATION

list-inputs

List all input devices.

list-input-configs

List all input configurations.

keyboard-layout [-rules rules] [-model model] [-variant variant] [-options options] layout

Set the XKB layout for all keyboards. Defaults from libxkbcommon are used for everything left unspecified. Note that layout may be a comma separated list of layouts (e.g. "us,de") which may be switched between using various key combinations configured through the options argument (e.g. -options "grp:ctrl_space_toggle"). See xkeyboard-config(7) for possible values and more information.

keyboard-layout-file path

Set the XKB layout for all keyboards from an XKB keymap file at the provided path. Documentation for the XKB keymap file format can be found at the following URL: https://xkbcommon.org/doc/current/keymap-text-format-v1.html

The input command can be used to create a configuration rule for an input device identified by its name. The name of an input device consists of its type, its decimal vendor id, its decimal product id and finally its self-advertised name, separated by -. Simple globbing patterns are supported, see the rules section for further information on globs.

A list of all device properties that can be configured may be found below. However note that not every input device supports every property.

input name events enabled|disabled|disabled-on-external-mouse

Configure whether the input devices events will be used by river.

input name accel-profile none|flat|adaptive

Set the pointer acceleration profile of the input device.

input name pointer-accel factor

Set the pointer acceleration factor of the input device. Needs a float between -1.0 and 1.0.

input name click-method none|button-areas|clickfinger

Set the click method of the input device.

input name drag enabled|disabled

Enable or disable the tap-and-drag functionality of the input device.

input name drag-lock enabled|disabled

Enable or disable the drag lock functionality of the input device.

input name disable-while-typing enabled|disabled

Enable or disable the disable-while-typing functionality of the input device.

input name disable-while-trackpointing enabled|disabled

Enable or disable the disable-while-trackpointing functionality of the input device.

input name middle-emulation enabled|disabled

Enable or disable the middle click emulation functionality of the input device.

input name natural-scroll enabled|disabled

Enable or disable the natural scroll functionality of the input device. If active, the scroll direction is inverted.

input name scroll-factor factor

Set the scroll factor of the input device. Accepts a postive value greater than 0. For example, a factor of 0.5 will make scrolling twice as slow while a factor of 3 will make scrolling 3 times as fast.

input name left-handed enabled|disabled

Enable or disable the left handed mode of the input device.

input name tap enabled|disabled

Enable or disable the tap functionality of the input device.

input name tap-button-map left-right-middle|left-middle-right

Configure the button mapping for tapping.
  • left-right-middle: 1 finger tap equals left click, 2 finger tap equals right click, 3 finger tap equals middle click.
  • left-middle-right: 1 finger tap equals left click, 2 finger tap equals middle click, 3 finger tap equals right click.

input name scroll-method none|two-finger|edge|button

Set the scroll method of the input device.
  • none: No scrolling
  • two-finger: Scroll by swiping with two fingers simultaneously
  • edge: Scroll by swiping along the edge
  • button: Scroll with pointer movement while holding down a button

input name scroll-button button

Set the scroll button of an input device. button is the name of a Linux input event code.

input name scroll-button-lock enabled|disabled

Enable or disable the scroll button lock functionality of the input device. If active, the button does not need to be held down. One press makes the button considered to be held down, and a second press releases the button.

input name map-to-output output|disabled

Maps the input to a given output. This is valid even if the output isn't currently active and will lead to the device being mapped once it is connected.

EXAMPLES

Bind Super+Return in normal mode to spawn a foot(1) terminal:

riverctl map normal Mod4 Return spawn 'foot --app-id=foobar'

Bind Super+Shift+J to swap the focused view with the next visible view:

riverctl map normal Mod4+Shift J swap next
