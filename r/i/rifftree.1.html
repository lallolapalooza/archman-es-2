NOMBRE

rifftree - Imprime la estructura de árbol RIFF de un archivo RIFF arbitrario.

SINOPSIS

rifftree [OPCIONES] ARCHIVO

DESCRIPCIÓN

El Formato de Archivo de Intercambio de Recursos (RIFF) es un formato de archivo binario simple destinado a estructuras de datos similares a árboles. Muchos formatos de archivo propietarios se construyen sobre el formato RIFF (por ejemplo, formatos de archivo multimedia como WAV, AVI, DLS, GIG). Los datos en un archivo RIFF están encapsulados en los llamados "chunks" (trozos). Hay chunks de lista (contenedores) que pueden verse como nodos en el árbol de datos y, por lo tanto, pueden tener hijos (es decir, pueden tener subchunks) y hay chunks de datos normales que pueden verse como hojas en el árbol de datos y, por lo tanto, no pueden tener hijos. Los chunks regulares (hojas del árbol) contienen los datos reales a almacenar. Los chunks de lista en sí (nodos / contenedores) no contienen datos por sí mismos.

Cada chunk de lista y chunk normal tiene un ID de 32 bits (no único), que suele ser un texto ASCII legible de cuatro caracteres, que refleja el propósito de la lista o chunk respectivo. Esta aplicación imprimirá este ID para cada chunk encontrado. La ventaja de los IDs de lista/chunk legibles por humanos es que los archivos basados en esta práctica pueden analizarse fácilmente de forma manual con un editor hexadecimal.

Un archivo RIFF normal siempre comienza con un chunk de lista (ya sea con el ID de chunk "RIFF" o "RIFX"), que contiene todos los demás chunks. No hay otros chunks fuera de los límites de ese primer chunk en un archivo RIFF normal. Sin embargo, puede anular esta expectativa con los argumentos descritos a continuación (ver el argumento '--flat'), para poder abrir otros archivos similares a RIFF.

OPCIONES

 ARCHIVO
Nombre del archivo basado en RIFF.
 -v
Imprime la versión y sale.
 -s
Imprime el tamaño de cada chunk RIFF.
 --flat
El primer chunk del archivo no es un chunk de lista (contenedor). Es posible que desee utilizar esto si el archivo no es un archivo RIFF "real". Un archivo RIFF "real" siempre tiene un chunk de lista (contenedor) RIFF como primer chunk del archivo, y espera que todos los chunks estén contenidos en ese primer chunk (lista/contenedor) del archivo. Por lo tanto, en un archivo RIFF "real", tampoco habría otros chunks fuera del ámbito (es decir, después del final) del primer chunk del archivo. Sin embargo, muchos formatos de archivo primitivos son una secuencia plana de chunks de datos ordinarios (no chunks de lista/contenedor). Si está utilizando esta opción, también debe usar --first-chunk-id.
 --first-chunk-id CKID
Actualmente solo se usa en combinación con --flat. CKID será el ID de chunk de 32 bits del primer chunk del archivo. Si el primer chunk del archivo no tiene el ID de chunk dado, esta aplicación se abortará. Esto asegura que el archivo sea realmente el formato que esperaba. El argumento esperado aquí debe ser un texto ASCII legible por humanos de cuatro caracteres, ya que los IDs de chunk RIFF suelen ser cadenas ASCII legibles por humanos.
 --big-endian
El archivo está en formato big endian. Actualmente solo se usa en combinación con --flat. Sin --flat, el tipo de endianness se detectará automáticamente. Si está utilizando --flat y no proporciona --big-endian ni --little-endian, entonces se utilizará el tipo de endianness nativo de su máquina por defecto.
 --little-endian
El archivo está en formato little endian. Actualmente solo se usa en combinación con --flat. Sin --flat, el tipo de endianness se detectará automáticamente. Si está utilizando --flat y no proporciona --big-endian ni --little-endian, entonces se utilizará el tipo de endianness nativo de su máquina por defecto.

EJEMPLOS

Mostrar la estructura del archivo de un archivo RIFF estándar (en el siguiente ejemplo, un archivo Gigasampler/GigaStudio) y mostrar los tamaños exactos de cada chunk en el archivo:

rifftree -s piano.gig

Haga lo mismo para un archivo de sonido Korg Trinity/Triton/OASYS/Kronos (que no es un archivo RIFF estándar, sino un archivo similar a RIFF):

rifftree -s --flat --first-chunk-id MSP1 --big-endian PIANO_000.KMP
