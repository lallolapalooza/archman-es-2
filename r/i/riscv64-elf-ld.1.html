LD(1) Herramientas de desarrollo GNU LD(1)

NOMBRE

ld - El enlazador GNU

SINOPSIS

ld [opciones] archivo_objeto ...

DESCRIPCIÓN

ld combina un número de archivos objeto y de archivo, relocaliza sus datos y resuelve referencias de símbolos. Generalmente, el último paso en la compilación de un programa es ejecutar ld.

ld acepta archivos de lenguaje de comandos de enlazado escritos en un superconjunto de la sintaxis del Lenguaje de Comandos del Editor de Enlace de AT&T, para proporcionar control explícito y total sobre el proceso de enlazado.

Esta página del manual no describe el lenguaje de comandos; consulte la entrada ld en "info" para obtener detalles completos sobre el lenguaje de comandos y sobre otros aspectos del enlazador GNU.

Esta versión de ld utiliza las bibliotecas BFD de propósito general para operar sobre archivos objeto. Esto permite a ld leer, combinar y escribir archivos objeto en muchos formatos diferentes, por ejemplo, COFF o "a.out". Diferentes formatos pueden ser enlazados juntos para producir cualquier tipo de archivo objeto disponible.

Además de su flexibilidad, el enlazador GNU es más útil que otros enlazadores al proporcionar información diagnóstica. Muchos enlazadores abandonan la ejecución inmediatamente al encontrar un error; siempre que sea posible, ld continúa ejecutándose, permitiéndole identificar otros errores (o, en algunos casos, obtener un archivo de salida a pesar del error).

El enlazador GNU ld está diseñado para cubrir una amplia gama de situaciones y ser lo más compatible posible con otros enlazadores. Como resultado, tiene muchas opciones para controlar su comportamiento.

OPCIONES

El enlazador soporta una gran cantidad de opciones de línea de comandos, pero en la práctica, pocas de ellas se utilizan en un contexto particular. Por ejemplo, un uso frecuente de ld es enlazar archivos objeto Unix estándar en un sistema Unix estándar y compatible. En dicho sistema, para enlazar un archivo "hello.o":

ld -o <salida> /lib/crt0.o hello.o -lc

Esto le indica a ld que produzca un archivo llamado salida como resultado de enlazar el archivo "/lib/crt0.o" con "hello.o" y la biblioteca "libc.a", que provendrá de los directorios de búsqueda estándar. (Consulte la discusión de la opción -l a continuación).

Algunas de las opciones de línea de comandos para ld pueden especificarse en cualquier punto de la línea de comandos. Sin embargo, las opciones que se refieren a archivos, como -l o -T, hacen que el archivo se lea en el punto en que la opción aparece en la línea de comandos, en relación con los archivos objeto y otras opciones de archivo. Repetir opciones no relacionadas con archivos con un argumento diferente no tendrá un efecto adicional, o anulará las ocurrencias previas (las que están más a la izquierda en la línea de comandos) de esa opción. Las opciones que se pueden especificar significativamente más de una vez se anotan en las descripciones a continuación.

Los argumentos que no son opciones son archivos objeto o archivos que se van a enlazar juntos. Pueden seguir, preceder o mezclarse con las opciones de línea de comandos, excepto que un argumento de archivo objeto no puede colocarse entre una opción y su argumento.

Normalmente, el enlazador se invoca con al menos un archivo objeto, pero puede especificar otras formas de archivos de entrada binaria usando -l, -R y el lenguaje de comandos del script. Si *no* se especifican archivos de entrada binaria, el enlazador no produce ninguna salida y emite el mensaje No input files (Sin archivos de entrada).

Si el enlazador no puede reconocer el formato de un archivo objeto, asumirá que es un script de enlazador. Un script especificado de esta manera aumenta el script de enlazador principal utilizado para el enlace (ya sea el script de enlazador predeterminado o el especificado usando -T). Esta característica permite al enlazador enlazar contra un archivo que parece ser un objeto o un archivo, pero que en realidad solo define algunos valores de símbolo, o utiliza "INPUT" o "GROUP" para cargar otros objetos. Especificar un script de esta manera simplemente aumenta el script de enlazador principal, con los comandos adicionales colocados después del script principal; use la opción -T para reemplazar completamente el script de enlazador predeterminado, pero tenga en cuenta el efecto del comando "INSERT".

Para opciones cuyos nombres son una sola letra, los argumentos de opción deben seguir la letra de opción sin espacios en blanco intermedios, o darse como argumentos separados inmediatamente después de la opción que los requiere.

Para opciones cuyos nombres son de varias letras, uno o dos guiones pueden preceder al nombre de la opción; por ejemplo, -trace-symbol y --trace-symbol son equivalentes. Nota: hay una excepción a esta regla. Las opciones de varias letras que comienzan con una 'o' minúscula solo pueden ir precedidas por dos guiones. Esto es para reducir la confusión con la opción -o. Así, por ejemplo, -omagic establece el nombre del archivo de salida a magic, mientras que --omagic establece el indicador NMAGIC en la salida.

Los argumentos para las opciones de varias letras deben estar separados del nombre de la opción por un signo igual, o darse como argumentos separados inmediatamente después de la opción que los requiere. Por ejemplo, --trace-symbol foo y --trace-symbol=foo son equivalentes. Se aceptan abreviaturas únicas de los nombres de las opciones de varias letras.

Nota: si el enlazador se invoca indirectamente, a través de un controlador de compilador (por ejemplo, gcc), entonces todas las opciones de línea de comandos del enlazador deben ir precedidas por -Wl, (o lo que sea apropiado para el controlador de compilador particular), de esta manera:

gcc -Wl,--start-group foo.o bar.o -Wl,--end-group

Esto es importante, porque de lo contrario, el programa controlador del compilador puede omitir silenciosamente las opciones del enlazador, lo que resulta en un enlace incorrecto. La confusión también puede surgir al pasar opciones que requieren valores a través de un controlador, ya que el uso de un espacio entre la opción y el argumento actúa como un separador, y hace que el controlador pase solo la opción al enlazador y el argumento al compilador. En este caso, lo más sencillo es usar las formas unidas tanto de las opciones de una sola letra como de varias letras, como:

gcc foo.o bar.o -Wl,-eENTRY -Wl,-Map=a.map

Aquí hay una tabla de los modificadores genéricos de línea de comandos aceptados por el enlazador GNU:

@archivo
Leer opciones de línea de comandos desde archivo. Las opciones leídas se insertan en lugar de la opción @archivo original. Si archivo no existe o no se puede leer, entonces la opción se tratará literalmente y no se eliminará.

Las opciones en archivo están separadas por espacios en blanco. Un carácter de espacio en blanco puede incluirse en una opción rodeando la opción completa con comillas simples o dobles. Cualquier carácter (incluido una barra invertida) puede incluirse prefijando el carácter a incluir con una barra invertida. El archivo puede contener él mismo opciones adicionales @archivo; cualquiera de esas opciones se procesará recursivamente.

-a palabra_clave
Esta opción es compatible con HP/UX. El argumento palabra_clave debe ser una de las cadenas archive, shared o default. -aarchive es funcionalmente equivalente a -Bstatic, y las otras dos palabras clave son funcionalmente equivalentes a -Bdynamic. Esta opción puede usarse cualquier número de veces.
--audit AUDITLIB
Añade AUDITLIB a la entrada "DT_AUDIT" de la sección dinámica. AUDITLIB no se verifica su existencia, ni utilizará el DT_SONAME especificado en la biblioteca. Si se especifica varias veces, "DT_AUDIT" contendrá una lista separada por dos puntos de interfaces de auditoría a utilizar. Si el enlazador encuentra un objeto con una entrada de auditoría mientras busca bibliotecas compartidas, añadirá una entrada "DT_DEPAUDIT" correspondiente en el archivo de salida. Esta opción solo es significativa en plataformas ELF que soportan la interfaz rtld-audit.
-b formato_entrada
--format=formato_entrada
ld puede estar configurado para soportar más de un tipo de archivo objeto. Si su ld está configurado de esta manera, puede usar la opción -b para especificar el formato binario para los archivos objeto que siguen a esta opción en la línea de comandos. Incluso cuando ld está configurado para soportar formatos de objeto alternativos, generalmente no necesita especificar esto, ya que ld debe estar configurado para esperar como
un formato de entrada predeterminado, el formato más común en cada máquina. input-format es una cadena de texto, el nombre de un formato particular soportado por las bibliotecas BFD. (Puede listar los formatos binarios disponibles con objdump -i.)

Puede que desee utilizar esta opción si está enlazando archivos con un formato binario inusual. También puede usar -b para cambiar de formato explícitamente (al enlazar archivos objeto de diferentes formatos), incluyendo -b input-format antes de cada grupo de archivos objeto en un formato particular.

El formato predeterminado se toma de la variable de entorno "GNUTARGET".

También puede definir el formato de entrada desde un script, usando el comando "TARGET";

-c archivo-comandos-MRI
--mri-script=archivo-comandos-MRI
Para compatibilidad con enlazadores producidos por MRI, ld acepta archivos de script escritos en un lenguaje de comandos alternativo y restringido, descrito en la sección "Archivos de Script Compatibles con MRI" de la documentación de GNU ld. Introduzca los archivos de script MRI con la opción -c; use la opción -T para ejecutar scripts de enlazador escritos en el lenguaje de scripting de propósito general de ld. Si archivo-comandos-MRI no existe, ld lo busca en los directorios especificados por cualquier opción -L.
-d
-dc
-dp
Estas tres opciones son equivalentes; se admiten múltiples formas por compatibilidad con otros enlazadores. Asignan espacio a símbolos comunes incluso si se especifica un archivo de salida relocable (con -r). El comando de script "FORCE_COMMON_ALLOCATION" tiene el mismo efecto.
--depaudit BIBLIOTECA-AUDITORIA
-P BIBLIOTECA-AUDITORIA
Añade BIBLIOTECA-AUDITORIA a la entrada "DT_DEPAUDIT" de la sección dinámica. No se comprueba la existencia de BIBLIOTECA-AUDITORIA, ni utilizará el DT_SONAME especificado en la biblioteca. Si se especifica varias veces, "DT_DEPAUDIT" contendrá una lista de interfaces de auditoría separadas por dos puntos a utilizar. Esta opción solo es significativa en plataformas ELF que soporten la interfaz rtld-audit. La opción -P se proporciona para compatibilidad con Solaris.
--enable-linker-version
Habilita la directiva del script del enlazador "LINKER_VERSION", descrita en **Datos de Sección de Salida**. Si se utiliza esta directiva en un script del enlazador y se ha habilitado esta opción, se insertará una cadena que contiene la versión del enlazador en el punto actual.

Nota: la ubicación de esta opción en la línea de comandos del enlazador es significativa. Solo afectará a los scripts del enlazador que vengan después en la línea de comandos, o que estén integrados en el enlazador.

--disable-linker-version
Deshabilita la directiva del script del enlazador "LINKER_VERSION", de modo que no inserte una cadena de versión. Este es el comportamiento predeterminado.
--enable-non-contiguous-regions
Esta opción evita generar un error si una sección de entrada no encaja en una sección de salida coincidente. El enlazador intenta asignar la sección de entrada a secciones de salida coincidentes posteriores, y solo genera un error si ninguna sección de salida es lo suficientemente grande. Esto es útil cuando hay varias regiones de memoria no contiguas disponibles y la sección de entrada no requiere una en particular. El orden en que se evalúan las secciones de entrada no cambia, por ejemplo: 
MEMORY {
  MEM1 (rwx) : ORIGIN = 0x1000, LENGTH = 0x14
  MEM2 (rwx) : ORIGIN = 0x1000, LENGTH = 0x40
  MEM3 (rwx) : ORIGIN = 0x2000, LENGTH = 0x40
}
SECTIONS {
  mem1 : { *(.data.*); } > MEM1
  mem2 : { *(.data.*); } > MEM2
  mem3 : { *(.data.*); } > MEM3
}

con secciones de entrada:
.data.1: tamaño 8
.data.2: tamaño 0x10
.data.3: tamaño 4

resulta en que .data.1 se asigna a mem1, y .data.2 y .data.3
se asignan a mem2, aunque .data.3 cabría en mem3.

Esta opción es incompatible con las instrucciones INSERT porque cambia la forma en que las secciones de entrada se mapean a las secciones de salida.

--enable-non-contiguous-regions-warnings
Esta opción habilita advertencias cuando "--enable-non-contiguous-regions" permite coincidencias potencialmente inesperadas en el mapeo de secciones, lo que podría llevar a descartar silenciosamente una sección en lugar de fallar porque no encaja en ninguna región de salida.
-e punto-entrada
--entry=punto-entrada
Utilice punto-entrada como el símbolo explícito para comenzar la ejecución de su programa, en lugar del punto de entrada predeterminado. Si no existe un símbolo llamado punto-entrada, el enlazador intentará interpretar punto-entrada como un número, y lo usará como la dirección de entrada (el número se interpretará en base 10; puede usar un prefijo 0x para base 16, o un prefijo 0 para base 8).
--exclude-libs bib,bib,...
Especifica una lista de bibliotecas de archivo de las cuales los símbolos no deben exportarse automáticamente. Los nombres de las bibliotecas pueden estar delimitados por comas o dos puntos. Especificar "--exclude-libs ALL" excluye los símbolos de todas las bibliotecas de archivo de la exportación automática. Esta opción solo está disponible para el puerto de destino i386 PE del enlazador y para puertos de destino ELF. Para i386 PE, los símbolos listados explícitamente en un archivo .def todavía se exportan, independientemente de esta opción. Para puertos de destino ELF, los símbolos afectados por esta opción se tratarán como ocultos.
--exclude-modules-for-implib modulo,modulo,...
Especifica una lista de archivos objeto o miembros de archivo, de los cuales los símbolos no deben exportarse automáticamente, pero que deben copiarse completamente en la biblioteca de importación que se está generando durante el enlace. Los nombres de los módulos pueden estar delimitados por comas o dos puntos, y deben coincidir exactamente con los nombres de archivo que ld utiliza para abrir los archivos; para miembros de archivo, este es simplemente el nombre del miembro, pero para archivos objeto, el nombre listado debe incluir y coincidir precisamente con cualquier ruta utilizada para especificar el archivo de entrada en la línea de comandos del enlazador. Esta opción solo está disponible para el puerto de destino i386 PE del enlazador. Los símbolos listados explícitamente en un archivo .def todavía se exportan, independientemente de esta opción.
-E
--export-dynamic
--no-export-dynamic
Al crear un ejecutable enlazado dinámicamente, el uso de la opción -E o la opción --export-dynamic hace que el enlazador agregue todos los símbolos a la tabla de símbolos dinámicos. La tabla de símbolos dinámicos es el conjunto de símbolos que son visibles desde objetos dinámicos en tiempo de ejecución.

Si no usa ninguna de estas opciones (o usa la opción --no-export-dynamic para restaurar el comportamiento predeterminado), la tabla de símbolos dinámicos normalmente contendrá solo aquellos símbolos que son referenciados por algún objeto dinámico mencionado en el enlace.

Si usa "dlopen" para cargar un objeto dinámico que necesita referirse a los símbolos definidos por el programa, en lugar de a algún otro objeto dinámico, entonces probablemente necesitará usar esta opción al enlazar el programa mismo.

También puede usar la lista dinámica para controlar qué símbolos se deben agregar a la tabla de símbolos dinámicos si el formato de salida lo soporta. Vea la descripción de --dynamic-list.

Tenga en cuenta que esta opción es específica para puertos de destino ELF. Los destinos PE soportan una función similar para exportar todos los símbolos de una DLL o EXE; vea la descripción de --export-all-symbols a continuación.

--export-dynamic-symbol=patron
Al crear un ejecutable enlazado dinámicamente, los símbolos que coinciden con patron se agregarán a la tabla de símbolos dinámicos. Al crear una biblioteca compartida, las referencias a símbolos que coinciden con patron no se vincularán a las definiciones dentro de la biblioteca compartida. Esta opción no tiene efecto al crear una biblioteca compartida y no se especifican -Bsymbolic o --dynamic-list. Esta opción solo es significativa en plataformas ELF que soportan bibliotecas compartidas.
--export-dynamic-symbol-list=archivo
Especifique un --export-dynamic-symbol por cada patrón en el archivo. El formato del archivo es el mismo que el nodo de versión sin ámbito y nombre de nodo. Vea **VERSION** para más información.
-EB
Enlaza objetos big-endian. Esto afecta al formato de salida predeterminado.
-EL
Enlaza objetos little-endian. Esto afecta al formato de salida predeterminado.
-f nombre
--auxiliary=nombre
Al crear un objeto compartido ELF, establece el campo interno DT_AUXILIARY al nombre especificado. Esto le dice al enlazador dinámico que la tabla de símbolos del objeto compartido debe usarse como un filtro auxiliar en la tabla de símbolos del objeto compartido nombre.

Si posteriormente enlaza un programa contra este objeto filtro, entonces, cuando ejecute el programa, el enlazador dinámico verá el campo DT_AUXILIARY. Si el enlazador dinámico resuelve algún símbolo del objeto filtro, primero comprobará si existe una definición en el objeto compartido nombre. Si existe una, se utilizará en lugar de la definición en el objeto filtro. El objeto compartido nombre no necesita existir. Por lo tanto, el objeto compartido nombre puede utilizarse para proporcionar una implementación alternativa de ciertas funciones, quizás para depuración o para rendimiento específico de la máquina.

Esta opción puede especificarse más de una vez. Las entradas DT_AUXILIARY se crearán en el orden en que aparezcan en la línea de comandos.

-F nombre
--filter=nombre
Al crear un objeto compartido ELF, establece el campo interno DT_FILTER al nombre especificado. Esto le indica al enlazador dinámico que la tabla de símbolos del objeto compartido que se está creando se utilizará como un filtro para la tabla de símbolos del objeto compartido nombre.

Si posteriormente enlaza un programa contra este objeto filtro, al ejecutar el programa, el enlazador dinámico verá el campo DT_FILTER. El enlazador dinámico resolverá los símbolos de acuerdo con la tabla de símbolos del objeto filtro como de costumbre, pero en realidad se enlazará a las definiciones encontradas en el objeto compartido nombre. Por lo tanto, el objeto filtro se puede usar para seleccionar un subconjunto de los símbolos proporcionados por el objeto nombre.

Algunos enlazadores más antiguos utilizaban la opción -F en toda una cadena de herramientas de compilación para especificar el formato del archivo objeto tanto para los archivos de entrada como de salida. El enlazador GNU utiliza otros mecanismos para este propósito: las opciones -b, --format, --oformat, el comando "TARGET" en los scripts del enlazador y la variable de entorno "GNUTARGET". El enlazador GNU ignorará la opción -F cuando no esté creando un objeto compartido ELF.

-fini=nombre
Al crear un ejecutable o un objeto compartido ELF, llama a NOMBRE cuando el ejecutable o el objeto compartido se descarga, estableciendo DT_FINI a la dirección de la función. Por defecto, el enlazador utiliza "_fini" como la función a llamar.
-g
Ignorado. Proporcionado para compatibilidad con otras herramientas.
-G valor
--gpsize=valor
Establece el tamaño máximo de los objetos a optimizar utilizando el registro GP a tamaño. Esto solo es significativo para formatos de archivo objeto como MIPS ELF que admiten la colocación de objetos grandes y pequeños en secciones diferentes. Se ignora para otros formatos de archivo objeto.
-h nombre
-soname=nombre
Al crear un objeto compartido ELF, establece el campo interno DT_SONAME al nombre especificado. Cuando un ejecutable se enlaza con un objeto compartido que tiene un campo DT_SONAME, al ejecutar el programa el enlazador dinámico intentará cargar el objeto compartido especificado por el campo DT_SONAME en lugar de utilizar el nombre de archivo proporcionado al enlazador.
-i
Realiza un enlace incremental (igual que la opción -r).
-init=nombre
Al crear un ejecutable o un objeto compartido ELF, llama a NOMBRE cuando el ejecutable o el objeto compartido se carga, estableciendo DT_INIT a la dirección de la función. Por defecto, el enlazador utiliza "_init" como la función a llamar.
-l espec_nombre
--library=espec_nombre
Añade el archivo de biblioteca o objeto especificado por espec_nombre a la lista de archivos a enlazar. Esta opción se puede utilizar cualquier número de veces. Si espec_nombre tiene la forma :nombre_archivo, ld buscará en la ruta de bibliotecas un archivo llamado nombre_archivo, de lo contrario buscará en la ruta de bibliotecas un archivo llamado libespec_nombre.a.

En sistemas que soportan bibliotecas compartidas, ld también puede buscar archivos distintos de libespec_nombre.a. Específicamente, en sistemas ELF y SunOS, ld buscará en un directorio una biblioteca llamada libespec_nombre.so antes de buscar una llamada libespec_nombre.a. (Por convención, la extensión ".so" indica una biblioteca compartida.) Tenga en cuenta que este comportamiento no se aplica a :nombre_archivo, que siempre especifica un archivo llamado nombre_archivo.

El enlazador buscará en un archivo de biblioteca solo una vez, en la ubicación en que se especifica en la línea de comandos. Si el archivo de biblioteca define un símbolo que estaba indefinido en algún objeto que apareció antes del archivo de biblioteca en la línea de comandos, el enlazador incluirá los archivos apropiados del archivo de biblioteca. Sin embargo, un símbolo indefinido en un objeto que aparece más tarde en la línea de comandos no provocará que el enlazador busque de nuevo el archivo de biblioteca.

Consulte la opción -( para conocer una forma de forzar al enlazador a buscar archivos de biblioteca varias veces.

Puede listar el mismo archivo de biblioteca varias veces en la línea de comandos.

Este tipo de búsqueda de archivos de biblioteca es estándar para los enlazadores Unix. Sin embargo, si está utilizando ld en AIX, tenga en cuenta que es diferente del comportamiento del enlazador de AIX.

-L dir_busqueda
--library-path=dir_busqueda
Añade la ruta dir_busqueda a la lista de rutas que ld buscará para las bibliotecas de archivos y los scripts de control de ld. Puede usar esta opción cualquier número de veces. Los directorios se buscan en el orden en que se especifican en la línea de comandos. Los directorios especificados en la línea de comandos se buscan antes que los directorios predeterminados. Todas las opciones -L se aplican a todas las opciones -l, independientemente del orden en que aparezcan las opciones. Las opciones -L no afectan a cómo ld busca un script de enlazador a menos que se especifique la opción -T.

Si dir_busqueda comienza con "=" o $SYSROOT, este prefijo será reemplazado por el prefijo sysroot, controlado por la opción --sysroot, o especificado cuando se configura el enlazador.

El conjunto predeterminado de rutas buscadas (sin ser especificadas con -L) depende de qué modo de emulación esté utilizando ld, y en algunos casos también de cómo se configuró.

Las rutas también se pueden especificar en un script de enlace con el comando "SEARCH_DIR". Los directorios especificados de esta manera se buscan en el punto en que aparece el script de enlazador en la línea de comandos.

-m emulacion
Emula el enlazador de emulacion. Puede listar las emulaciones disponibles con las opciones --verbose o -V.

Si no se utiliza la opción -m, la emulación se toma de la variable de entorno "LDEMULATION", si esta está definida.

De lo contrario, la emulación predeterminada depende de cómo se configuró el enlazador.

--remap-inputs=patron=nombre_archivo
--remap-inputs-file=archivo
Estas opciones permiten cambiar los nombres de los archivos de entrada antes de que el enlazador intente abrirlos. La opción --remap-inputs=foo.o=bar.o hará que cualquier intento de cargar un archivo llamado foo.o intente cargar en su lugar un archivo llamado bar.o. Se permiten patrones comodín en el primer nombre de archivo, por lo que --remap-inputs=foo*.o=bar.o renombrará cualquier archivo de entrada que coincida con foo*.o a bar.o.

Una forma alternativa de la opción --remap-inputs-file=nombre_archivo permite leer las reasignaciones desde un archivo. Cada línea del archivo puede contener una única reasignación. Las líneas en blanco se ignoran. Todo desde un carácter de almohadilla (#) hasta el final de una línea se considera un comentario y también se ignora. El patrón de mapeo se puede separar del nombre de archivo por espacios en blanco o por un carácter de igual (=).

Las opciones se pueden especificar varias veces. Sus contenidos se acumulan. Las reasignaciones se procesarán en el orden en que aparecen en la línea de comandos y, si provienen de un archivo, en el orden en que aparecen en el archivo. Si se produce una coincidencia, no se realizará ninguna comprobación adicional para ese nombre de archivo.

Si el nombre de archivo de reemplazo es /dev/null o simplemente NUL, la reasignación hará que el archivo de entrada sea ignorado. Esta puede ser una forma conveniente de experimentar con la eliminación de archivos de entrada de un entorno de compilación complicado.

Tenga en cuenta que esta opción depende de la posición y solo afecta a los nombres de archivo que vienen después en la línea de comandos. Por lo tanto:

ld foo.o --remap-inputs=foo.o=bar.o

No tendrá ningún efecto, mientras que:

ld --remap-inputs=foo.o=bar.o foo.o

Renombrará el archivo de entrada foo.o a bar.o.

Nota: estas opciones también afectan a los archivos referenciados por las declaraciones INPUT en los scripts del enlazador. Pero como los scripts del enlazador se procesan después de que se lee toda la línea de comandos, la posición de las opciones de reasignación en la línea de comandos no es significativa.

Si la opción verbose está habilitada, se informarán todas las reasignaciones que coincidan, aunque de nuevo la opción verbose debe estar habilitada en la línea de comandos antes de que aparezcan los nombres de archivo reasignados.

Si las opciones -Map o --print-map están habilitadas, la lista de reasignaciones se incluirá en la salida del mapa.

-M
--print-map
Imprime un mapa de enlace en la salida estándar. Un mapa de enlace proporciona información sobre el enlace, incluyendo lo siguiente:
  • Dónde se mapean los archivos objeto en la memoria.
  • Cómo se asignan los símbolos comunes.
  • Todos los miembros del archivo de biblioteca incluidos en el enlace, con una mención del símbolo que provocó la inclusión del miembro del archivo de biblioteca.
  • Los valores asignados a los símbolos.

    Nota: los símbolos cuyos valores se calculan mediante una expresión que implica una referencia a un valor anterior del mismo símbolo pueden no tener el resultado correcto mostrado en el mapa de enlace. Esto se debe a que el enlazador descarta los resultados intermedios y solo conserva el valor final de una expresión. En tales circunstancias, el enlazador mostrará el valor final entre corchetes. Por ejemplo, un script de enlazador que contiene:

    foo = 1
foo = foo * 4
foo = foo + 8

    producirá la siguiente salida en el mapa de enlace si se utiliza la opción -M:

    0x00000001                foo = 0x1
[0x0000000c]                foo = (foo * 0x4)
[0x0000000c]                foo = (foo + 0x8)

    Consulte Expressions para

más información sobre expresiones en scripts del enlazador.

  • Cómo se fusionan las propiedades de GNU.

    Se actualizó la propiedad 0xc0010001 (0x1) para fusionar foo.o (0x1) y bar.o (0x1)

    Esto indica que el valor de la propiedad 0xc0010001 se actualiza a 0x1 en la salida al fusionar propiedades en foo.o, cuya propiedad 0xc0010001 tiene el valor 0x1, y bar.o, cuya propiedad 0xc0010001 tiene el valor 0x1.

    --warn-execstack
    --warn-execstack-objects
    --no-warn-execstack
    En plataformas ELF, el enlazador puede generar mensajes de advertencia si se le solicita crear un archivo de salida que contenga una pila ejecutable. Hay tres estados posibles:
    1.
    No generar ninguna advertencia.
    2.
    Generar siempre advertencias, incluso si se solicita una pila ejecutable a través de la opción de línea de comandos -z execstack.
    3.
    Solo generar una advertencia si un archivo de objeto solicita una pila ejecutable, pero no si se utiliza la opción -z execstack.

    El estado predeterminado depende de cómo se configuró el enlazador cuando se compiló. La opción --no-warn-execstack pone siempre al enlazador en el estado de no advertencias. La opción --warn-execstack pone al enlazador en el estado de advertencia siempre. La opción --warn-execstack-objects pone al enlazador en el estado de advertencia solo para archivos de objeto.

    Nota: Los archivos de entrada en formato ELF pueden especificar que necesitan una pila ejecutable al tener una sección .note.GNU-stack con el bit ejecutable activado en sus flags de sección. Pueden especificar que no necesitan una pila ejecutable al tener la misma sección, pero sin el bit de flag ejecutable activado. Si un archivo de entrada no tiene una sección .note.GNU-stack, el comportamiento predeterminado es específico del objetivo. Para algunos objetivos, la ausencia de dicha sección implica que se requiere una pila ejecutable. Esto a menudo es un problema para archivos ensambladores creados manualmente.

    --warn-multiple-gp
    Advierte si se requieren múltiples valores de puntero global en el archivo de salida. Esto solo es significativo para ciertos procesadores, como Alpha. Específicamente, algunos procesadores colocan constantes de gran valor en una sección especial. Un registro especial (el puntero global) apunta a la mitad de esta sección, de modo que las constantes puedan cargarse eficientemente a través de un modo de direccionamiento relativo al registro base. Dado que el desplazamiento en el modo relativo al registro base es fijo y relativamente pequeño (por ejemplo, 16 bits), esto limita el tamaño máximo del pool de constantes. Por lo tanto, en programas grandes, a menudo es necesario utilizar múltiples valores de puntero global para poder direccionar todas las constantes posibles. Esta opción provoca una advertencia cuando ocurre este caso.

    --wrap=símbolo

  return __real_malloc (c);

    Establece el tamaño por defecto de las tablas hash del enlazador a un número primo cercano a _número_. De manera similar, reducir este valor puede reducir los requisitos de memoria a costa de la velocidad.

    --compress-debug-sections=none
    --compress-debug-sections=zlib
    --compress-debug-sections=zlib-gnu
    --compress-debug-sections=zlib-gabi
    --compress-debug-sections=zstd
    En plataformas ELF, estas opciones controlan cómo se comprimen las secciones de depuración DWARF utilizando zlib.

    --compress-debug-sections=none no comprime las secciones de depuración DWARF. --compress-debug-sections=zlib-gnu comprime las secciones de depuración DWARF y las renombra para que comiencen con .zdebug en lugar de .debug. --compress-debug-sections=zlib-gabi también comprime las secciones de depuración DWARF, pero en lugar de renombrarlas, establece la bandera SHF_COMPRESSED en las cabeceras de las secciones.

    La opción --compress-debug-sections=zlib es un alias de --compress-debug-sections=zlib-gabi.

    --compress-debug-sections=zstd comprime las secciones de depuración DWARF utilizando zstd.

    Tenga en cuenta que esta opción anula cualquier compresión en las secciones de depuración de entrada, por lo que si un binario se enlaza con --compress-debug-sections=none, por ejemplo, cualquier sección de depuración comprimida en los archivos de entrada se descomprimirá antes de copiarse en el binario de salida.

    El comportamiento de compresión por defecto varía según el destino involucrado y las opciones de configuración utilizadas para compilar la cadena de herramientas. El valor por defecto se puede determinar examinando la salida de la opción --help del enlazador.

    --reduce-memory-overheads
    Esta opción reduce los requisitos de memoria en tiempo de ejecución de ld, a costa de la velocidad de enlazado. Esto se introdujo para seleccionar el algoritmo O(n^2) antiguo para la generación de archivos de mapa de enlace, en lugar del nuevo algoritmo O(n) que utiliza aproximadamente un 40% más de memoria para el almacenamiento de símbolos.

    Otro efecto del interruptor es establecer el tamaño por defecto de la tabla hash en 1021, lo que nuevamente ahorra memoria a costa de aumentar el tiempo de ejecución del enlazador. Sin embargo, esto no se hace si se ha utilizado el interruptor --hash-size.

    El interruptor --reduce-memory-overheads también puede utilizarse para habilitar otras compensaciones en futuras versiones del enlazador.

    --max-cache-size=tamaño
    ld normalmente almacena en caché la información de reubicación y las tablas de símbolos de los archivos de entrada en memoria con tamaño ilimitado. Esta opción establece el tamaño máximo de caché en _tamaño_.
    --build-id
    --build-id=estilo
    Solicita la creación de una sección de nota ELF ".note.gnu.build-id" o una sección COFF ".buildid". El contenido de la nota son bits únicos que identifican este archivo enlazado. _estilo_ puede ser "uuid" para usar 128 bits aleatorios, "sha1" para usar un hash SHA1 de 160 bits sobre las partes normativas del contenido de salida, "md5" para usar un hash MD5 de 128 bits sobre las partes normativas del contenido de salida, o "0xcadenahex" para usar una cadena de bits elegida especificada como un número par de dígitos hexadecimales (los caracteres "-" y ":" entre pares de dígitos se ignoran). Si _estilo_ se omite, se usa "sha1".

    Los estilos "md5" y "sha1" producen un identificador que es siempre el mismo en un archivo de salida idéntico, pero será único entre todos los archivos de salida no idénticos. No está destinado a ser comparado como una suma de verificación del contenido del archivo. Un archivo enlazado puede ser modificado posteriormente por otras herramientas, pero la cadena de bits de ID de compilación que identifica el archivo enlazado original no cambia.

    Pasar "none" para _estilo_ deshabilita la configuración de cualquier opción "--build-id" anterior en la línea de comandos.

    Nota: El uso de la extensión 'auto-import' hará que la sección de texto del archivo de imagen se vuelva escribible. Esto no se ajusta a la especificación del formato PE-COFF publicada por Microsoft.

    Nota: El uso de la extensión 'auto-import' también hará que los datos de solo lectura que normalmente se colocarían en la sección .rdata se coloquen en la sección .data en su lugar. Esto es para solucionar un problema con las constantes que se describe aquí: http://www.cygwin.com/ml/cygwin/2004-09/msg01101.html

    El uso de 'auto-import' generalmente 'funcionará' — pero a veces puede ver este mensaje:

    "variable '' no se puede autoimportar. Lea la documentación de ld sobre `"--enable-auto-import"` para obtener detalles."

    Este mensaje ocurre cuando alguna (sub)expresión accede a una dirección dada por la suma de dos constantes (las tablas de importación Win32 solo permiten una). Los casos en los que esto puede ocurrir incluyen accesos a campos de miembros de variables de estructura importadas de una DLL, así como el uso de un índice constante en una variable de matriz importada de una DLL. Cualquier variable de múltiples palabras (matrices, estructuras, long long, etc.) puede desencadenar esta condición de error. Sin embargo, independientemente del tipo de datos exacto de la variable exportada que causa el problema, ld siempre la detectará, emitirá la advertencia y saldrá.

    Existen varias formas de abordar esta dificultad, independientemente del tipo de datos de la variable exportada:

    Una forma es usar el interruptor --enable-runtime-pseudo-reloc. Esto deja la tarea de ajustar las referencias en su código cliente para el entorno de ejecución, por lo que este método solo funciona cuando el entorno de ejecución admite esta característica.

    Una segunda solución es forzar que una de las 'constantes' sea una variable — es decir, desconocida e iroptimizable en tiempo de compilación. Para matrices, hay dos posibilidades: a) hacer que el índice (la dirección de la matriz) sea una variable, o b) hacer que el índice 'constante' sea una variable. Así:

    extern type extern_array[];
extern_array[1] -->
   { volatile type *t=extern_array; t[1] }

    o

    extern type extern_array[];
extern_array[1] -->
   { volatile int t=1; extern_array[t] }

    Para estructuras (y la mayoría de los demás tipos de datos de múltiples palabras) la única opción es hacer que la estructura en sí (o el long long, o el...) sea una variable:

    extern struct s extern_struct;
extern_struct.field -->
   { volatile struct s *t=&extern_struct; t->field }

    o

    extern long long extern_ll;
extern_ll -->
  { volatile long long * local_ll=&extern_ll; *local_ll }

    Un tercer método para tratar con esta dificultad es abandonar 'auto-import' para el símbolo en cuestión y marcarlo con `"__declspec(dllimport)"`. Sin embargo, en la práctica, esto requiere usar #defines en tiempo de compilación para indicar si está compilando una DLL, compilando código cliente que se enlazará a la DLL, o simplemente compilando/enlazando una biblioteca estática. Al elegir entre los diversos métodos para resolver el problema del 'dirección directa con desplazamiento constante', debe considerar el uso típico en el mundo real:

    Original:

    --foo.h
extern int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  printf("%d\n",arr[1]);
}

    Solución 1:

    --foo.h
extern int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  /* Esta solución alternativa es para win32 y cygwin; no "optimizar" */
  volatile int *parr = arr;
  printf("%d\n",parr[1]);
}

    Solución 2:

    --foo.h

#if (defined(_WIN32) || defined(__CYGWIN__)) && \
  !(defined(FOO_BUILD_DLL) || defined(FOO_STATIC))
#define FOO_IMPORT __declspec(dllimport)
#else
#define FOO_IMPORT
#endif
extern FOO_IMPORT int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  printf("%d\n",arr[1]);
}

    OPTIONS

    The GNU linker supports a number of options to control the format of the output file. These are:

    --aout-ctype
    --no-aout-ctype
    These options control the output of the header flags for the different a.out output formats. The "ctype"s are defined in the file <b.out.h>. The default behaviour is to output the flags as required by the NUXI standard.
    --be8
    Output little-endian 80386 code. This is the default for the i386 target. This option is ignored if the target is not the i386.
    --le32
    Output little-endian 32-bit code. This is the default for the i386 target. This option is ignored if the target is not the i386.
    --bigendian
    Output big-endian code. This is the default for the m68k and ns32k targets. This option is ignored if the target is not the m68k or ns32k.
    --little-endian
    Output little-endian code. This is the default for the i386, ns32k, and m88k targets. This option is ignored if the target is not the i386, ns32k, or m88k.
    --interleave
    --no-interleave
    These options control whether the text and data sections are interleaved in the output file. The default is to interleave them.
    --linkerset-name
    This option selects a linker set name. See the section on linker sets below.
    --max-page-size=number
    Set the maximum page size.
    --magic=number
    Set the magic number in the output file header to number. This option is only supported for the pdp11-aout target.
    --major=number
    Set the major version number in the output file header.
    --minor=number
    Set the minor version number in the output file header.
    --no-sort-sections
    Do not sort the sections in the output file. By default, the sections are sorted according to the section type and name.
    --pic-kind
    --no-pic-kind
    These options control the generation of position independent code. The possible values of "kind" are "code" and "data". This option is only supported for the m68k and i386 targets.
    --reloc-type
    --no-reloc-type
    These options control the output of relocation bits. The possible values of "type" are "absolute", "high", "low", "pcrel", "relative" and "special". The default behaviour is to output all relocation bits.
    --strex
    --no-strex
    These options control the generation of string extension relocations. This option is only supported for the i386 target.
    --tsaware
    --disable-tsaware
    The image is Terminal Server aware. This option is disabled by default.
    --insert-timestamp
    --no-insert-timestamp
    Insert a real timestamp into the image. This is the default behaviour as it matches legacy code and it means that the image will work with other, proprietary tools. The problem with this default is that it will result in slightly different images being produced each time the same sources are linked. The option --no-insert-timestamp can be used to insert a zero value for the timestamp, this ensuring that binaries produced from identical sources will compare identically.

    If --insert-timestamp is active then the time inserted is either the time that the linking takes place or, if the "SOURCE_DATE_EPOCH" environment variable is defined, the number of seconds since Unix epoch as specified by that variable.

    --enable-reloc-section
    --disable-reloc-section
    Create the base relocation table, which is necessary if the image is loaded at a different image base than specified in the PE header. This option is enabled by default.

    The C6X uClinux target uses a binary format called DSBT to support shared libraries. Each shared library in the system needs to have a unique index; all executables use an index of 0.

    --dsbt-size size
    This option sets the number of entries in the DSBT of the current executable or shared library to size. The default is to create a table with 64 entries.
    --dsbt-index index
    This option sets the DSBT index of the current executable or shared library to index. The default is 0, which is appropriate for generating executables. If a shared library is generated with a DSBT index of 0, the "R_C6000_DSBT_INDEX" relocs are copied into the output file.

    The --no-merge-exidx-entries switch disables the merging of adjacent exidx entries in frame unwind info.

    --branch-stub
    This option enables linker branch relaxation by inserting branch stub sections when needed to extend the range of branches. This option is usually not required since C-SKY supports branch and call instructions that can access the full memory range and branch relaxation is normally handled by the compiler or assembler.
    --stub-group-size=N
    This option allows finer control of linker branch stub creation. It sets the maximum size of a group of input sections that can be handled by one stub section. A negative value of N locates stub sections after their branches, while a positive value allows stub sections to appear either before or after the branches. Values of 1 or -1 indicate that the linker should choose suitable defaults.

    The 68HC11 and 68HC12 linkers support specific options to control the memory bank switching mapping and trampoline code generation.

    --no-trampoline
    This option disables the generation of trampoline. By default a trampoline is generated for each far function which is called using a "jsr" instruction (this happens when a pointer to a far function is taken).
    --bank-window name
    This option indicates to the linker the name of the memory region in the MEMORY specification that describes the memory bank window. The definition of such region is then used by the linker to compute paging and addresses within the memory window.

    --got=type
    This option tells the linker which GOT generation scheme to use. type should be one of single, negative, multigot or target. For more information refer to the Info entry for ld.

    The following options are supported to control microMIPS instruction generation and branch relocation checks for ISA mode transitions when linking for MIPS targets.

    --insn32
    --no-insn32
    These options control the choice of microMIPS instructions used in code generated by the linker, such as that in the PLT or lazy binding stubs, or in relaxation. If --insn32 is used, then the linker only uses 32-bit instruction encodings. By default or if --no-insn32 is used, all instruction encodings are used, including 16-bit ones where possible.
    --ignore-branch-isa
    --no-ignore-branch-isa
    These options control branch relocation checks for invalid ISA mode transitions. If --ignore-branch-isa is used, then the linker accepts any branch relocations and any ISA mode transition required is lost in relocation calculation, except for some cases of "BAL" instructions which meet relaxation conditions and are converted to equivalent "JALX" instructions as the associated relocation is calculated. By default or if --no-ignore-branch-isa is used a check is made causing the loss of an ISA mode transition to produce an error.
    --compact-branches
    --no-compact-branches
    These options control the generation of compact instructions by the linker in the PLT entries for MIPS R6.

    For the pdp11-aout target, three variants of the output format can be produced as selected by the following options. The default variant for pdp11-aout is the --omagic option, whereas for other targets --nmagic is the default. The --imagic option is defined only for the pdp11-aout target, while the others are described here as they apply to the pdp11-aout target.

    -N
    --omagic
    Mark the output as "OMAGIC" (0407) in the a.out header to indicate that the text segment is not to be write-protected and shared. Since the text and data sections are both readable and writable, the data section is allocated immediately contiguous after the text segment. This is the oldest format for PDP11 executable programs and is the default for ld on PDP11 Unix systems from the beginning through 2.11BSD.
    -n
    --nmagic
    Mark the output as "NMAGIC" (0410) in the a.out header to indicate that when the output file is executed, the text portion will be read-only and shareable among all processes executing the same file. This involves moving the data areas up to the first possible 8K byte page boundary following the end of the text. This option creates a pure executable format.
    -z
    --imagic
    Mark the output as "IMAGIC" (0411) in the a.out header to indicate that when the output file is executed, the program text and data areas will be loaded into separate address spaces using the split instruction and data space feature of the memory management unit in larger models of the PDP11. This doubles the address space available to the program. The text segment is again pure, write-protected, and shareable. The only difference in the output format between this option and the others, besides the magic number, is that both the text and data sections start at location 0. The -z option selected this format in 2.11BSD. This option creates a separate executable format.
    --no-omagic
    Equivalent to --nmagic for pdp11-aout.

    ENVIRONMENT

    You can change the behaviour of ld with the environment variables "GNUTARGET", "LDEMULATION" and "COLLECT_NO_DEMANGLE".

If there is no "GNUTARGET" in the environment, ld uses the natural format of the target. If "GNUTARGET" is set to "default" then BFD attempts to discover the input format by examining binary input files; this method often succeeds, but there are potential ambiguities, since there is no method of ensuring that the magic number used to specify object-file formats is unique. However, the configuration procedure for BFD on each system places the conventional format for that system first in the search-list, so ambiguities are resolved in favor of convention.

    "LDEMULATION" determines the default emulation if you don't use the -m option. The emulation can affect various aspects of linker behaviour, particularly the default linker script. You can list the available emulations with the --verbose or -V options.     NOMBRE

    ld - el enlazador de GNU

    SINOPSIS

    ld [opciones] objfile ...

    DESCRIPCIÓN

    ld enlaza juntos una serie de archivos objeto objfile en uno solo, el cual es otro archivo objeto que puede ser usado ya sea para enlazamiento posterior o para ser ejecutado. Cada uno de los objfile debe ser un archivo objeto de entrada. ld usa la biblioteca de enlazamiento en tiempo de ejecución de libld para realizar la mayor parte del trabajo de enlazamiento.

    En la mayoría de los sistemas, ld es invocado por gcc. Cuando gcc invoca a ld, invoca a ld con opciones que enlazan el compilador con las bibliotecas C estándar.

    Si ld es invocado sin ninguna opción, entonces procesará la línea de comandos como si hubiera sido invocado con la opción --help.

    El enlazador tiene dos modos de operación: enlazar archivos objeto y crear un archivo de biblioteca de la cual se puede enlazar. (Este último modo se usa con el comando ar).

    Para enlazar archivos objeto, ld toma una lista de archivos objeto de entrada y produce un archivo objeto de salida.

    Para crear una biblioteca, se usan los archivos objeto de entrada. ld puede crear una biblioteca estática, que es un archivo índice de archivos objeto. No se usa directamente para esto, sino que se invoca al comando ar.
