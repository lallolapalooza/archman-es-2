NOMBRE

gdb - El Depurador de GNU

SINOPSIS

gdb [OPCIONES] [programa|programa ID_proceso|programa core]

DESCRIPCIÓN

El propósito de un depurador como GDB es permitirle ver qué está sucediendo "dentro" de otro programa mientras se ejecuta, o qué estaba haciendo otro programa en el momento en que falló.

GDB puede hacer cuatro tipos principales de cosas (más otras cosas en apoyo de estas) para ayudarle a detectar errores en el acto:

  • Iniciar su programa, especificando cualquier cosa que pueda afectar su comportamiento.
  • Hacer que su programa se detenga bajo condiciones especificadas.
  • Examinar qué ha sucedido, cuando su programa se ha detenido.
  • Cambiar cosas en su programa, para que pueda experimentar corrigiendo los efectos de un error y continuar aprendiendo sobre otro.

Puede usar GDB para depurar programas escritos en C, C++, Fortran y Modula-2.

GDB se invoca con el comando de shell "gdb". Una vez iniciado, lee comandos del terminal hasta que le indica que salga con el comando GDB "quit" o "exit". Puede obtener ayuda en línea del propio GDB usando el comando "help".

Puede ejecutar "gdb" sin argumentos u opciones; pero la forma más común de iniciar GDB es con un argumento o dos, especificando un programa ejecutable como argumento:

gdb programa

También puede iniciar con un programa ejecutable y un archivo core especificados:

gdb programa core

Alternativamente, puede especificar un ID de proceso como segundo argumento o usar la opción "-p", si desea depurar un proceso en ejecución:

gdb programa 1234
gdb -p 1234

adjuntaría GDB al proceso 1234. Con la opción -p puede omitir el nombre de archivo del programa.

Aquí están algunos de los comandos GDB más frecuentemente necesarios:

break [archivo:][función|línea]
Establecer un punto de interrupción en función o línea (en archivo).
run [lista_args]
Iniciar su programa (con lista_args, si se especifica).
bt
Backtrace: mostrar la pila del programa.
print expresión
Mostrar el valor de una expresión.
c
Continuar ejecutando su programa (después de detenerse, por ejemplo, en un punto de interrupción).
next
Ejecutar la siguiente línea del programa (después de detenerse); pasar por encima de cualquier llamada a función en la línea.
edit [archivo:]función
Ver la línea del programa donde se detiene actualmente.
list [archivo:]función
Escribir el texto del programa en las proximidades de donde se detiene actualmente.
step
Ejecutar la siguiente línea del programa (después de detenerse); entrar en cualquier llamada a función en la línea.
help [nombre]
Mostrar información sobre el comando GDB nombre, o información general sobre cómo usar GDB.
quit
exit
Salir de GDB.

Para obtener detalles completos sobre GDB, consulte Using GDB: A Guide to the GNU Source-Level Debugger, por Richard M. Stallman y Roland H. Pesch. El mismo texto está disponible en línea como la entrada "gdb" en el programa "info".

OPCIONES

Cualquier argumento que no sean opciones especifica un archivo ejecutable y un archivo core (o ID de proceso); es decir, el primer argumento encontrado sin un indicador de opción asociado es equivalente a una opción --se, y el segundo, si lo hay, es equivalente a una opción -c si es el nombre de un archivo. Muchas opciones tienen formas largas y abreviadas; ambas se muestran aquí. Las formas largas también se reconocen si las trunca, siempre que haya suficiente parte de la opción para que no sea ambigua.

Las formas abreviadas se muestran aquí con - y las formas largas con -- para reflejar cómo se muestran en --help. Sin embargo, GDB reconoce todas las siguientes convenciones para la mayoría de las opciones:

"--opcion=valor"
"--opcion valor"
"-opcion=valor"
"-opcion valor"
"--o=valor"
"--o valor"
"-o=valor"
"-o valor"

Todas las opciones y argumentos de línea de comandos que proporcione se procesan en orden secuencial. El orden marca la diferencia cuando se utiliza la opción -x.

--help
-h
Listar todas las opciones, con explicaciones breves.
--symbols=archivo
-s archivo
Leer la tabla de símbolos del archivo.
--write
Permitir escribir en archivos ejecutables y core.
--exec=archivo
-e archivo
Usar archivo como el archivo ejecutable para ejecutar cuando sea apropiado, y para examinar datos puros junto con un volcado de memoria (core dump).
--se=archivo
Leer la tabla de símbolos del archivo y usarla como el archivo ejecutable.
--core=archivo
-c archivo
Usar archivo como un volcado de memoria (core dump) para examinar.
--command=archivo
-x archivo
Ejecutar comandos GDB desde archivo.
--eval-command=comando
-ex comando
Ejecutar el comando GDB dado.
--init-eval-command=comando
-iex
Ejecutar el comando GDB antes de cargar el inferior.
--directory=directorio
-d directorio
Agregar directorio a la ruta para buscar archivos fuente.
--nh
No ejecutar comandos de ~/.config/gdb/gdbinit, ~/.gdbinit, ~/.config/gdb/gdbearlyinit, o ~/.gdbearlyinit
--nx
-n
No ejecutar comandos de ningún archivo de inicialización .gdbinit o .gdbearlyinit.
--quiet
--silent
-q
Modo "silencioso". No imprimir los mensajes introductorios y de copyright. Estos mensajes también se suprimen en modo batch.
--batch
Ejecutar en modo batch. Salir con estado 0 después de procesar todos los archivos de comando especificados con -x (y .gdbinit, si no está inhibido). Salir con estado distinto de cero si ocurre un error al ejecutar los comandos GDB en los archivos de comando.

NOMBRE

gdb - el depurador de GNU

SINOPSIS

gdb [opción...] [programa [argumentos de programa...]]
gdb [opción...] --pid=pid
gdb [opción...] --attach=pid
gdb [opción...] --command=archivo
gdb [opción...] --batch
gdb [opción...] --tui
gdb [opción...] --return-child-result
gdb [opción...] --configuration
gdb [opción...] --version

DESCRIPCIÓN

GDB, el depurador de GNU, permite ver qué está haciendo un programa mientras se ejecuta o qué hizo antes de que se bloqueara. Puede modificar partes de un programa y así continuar ejecutándolo para probar la corrección de correcciones.

GDB permite hacer las siguientes cosas:

  • Iniciar su programa, con cualquier entrada que tome, y especificar cómo debe ser optimizado por el sistema operativo.
  • Hacer que su programa termine o se detenga en un punto especificado.
  • Cuando su programa se detiene, examinar las variables que se le pasaron; es decir, ver las partes de la memoria que estaba usando.
  • Cambiar cualquier variable en su programa para que pueda experimentar el efecto de corregir un error sin tener que recompilar todo el programa e intentar encontrar el error de nuevo.

Tenga en cuenta que GDB solo puede depurar programas compilados con información de depuración. Si el archivo ejecutable no contiene información de depuración, puede agregarla con el comando GDB de GNU add-symbol-file.

OPCIONES

--batch
Ejecutar en modo por lotes, es decir, sin interacción. GDB saldrá después de procesar todos los comandos de entrada (ya sea desde archivos de comandos o desde la entrada estándar). Si el programa se detiene o falla, GDB imprimirá un mensaje y saldrá. El mensaje "Program exited normally." (que normalmente se emite cada vez que un programa que se ejecuta bajo el control de GDB termina) no se emite cuando se ejecuta en modo por lotes. Esto es útil para scripts, y para ejecutar un programa en otro ordenador; para hacer esto más útil, el mensaje.
--batch-silent
Ejecutar en modo por lotes, igual que --batch, pero totalmente en silencio. Toda la salida de GDB se suprime (stderr no se ve afectado). Esto es mucho más silencioso que --silent y sería inútil para una sesión interactiva.

Esto es particularmente útil cuando se utilizan objetivos que proporcionan mensajes de Loading section, por ejemplo.

Tenga en cuenta que los objetivos que emiten su salida a través de GDB, en lugar de escribir directamente en "stdout", también se silenciarán.

--args prog [arglist]
Cambiar la interpretación de la línea de comandos para que los argumentos que siguen a esta opción se pasen como argumentos al inferior. Como ejemplo, tome el siguiente comando: 
gdb ./a.out -q

Iniciaría GDB con -q, sin imprimir el mensaje introductorio. Por otro lado, usando:

gdb --args ./a.out -q

inicia GDB con el mensaje introductorio y pasa la opción al inferior.

--pid=pid
Adjuntar GDB a un programa ya en ejecución, con el PID pid.
--tui
Abrir la interfaz de usuario de terminal.
--readnow
Leer todos los símbolos del archivo de símbolos dado en el primer acceso.
--readnever
No leer archivos de símbolos.
--return-child-result
El código de salida de GDB será el mismo que el código de salida del hijo.
--configuration
Imprimir detalles sobre la configuración de GDB y luego salir.
--version
Imprimir información de la versión y luego salir.
--cd=directory
Ejecutar GDB usando directory como su directorio de trabajo, en lugar del directorio actual.
--data-directory=directory
-D
Ejecutar GDB usando directory como su directorio de datos. El directorio de datos es donde GDB busca sus archivos auxiliares.
--fullname
-f
Emacs establece esta opción cuando ejecuta GDB como un subproceso. Le dice a GDB que emita el nombre de archivo completo y el número de línea en un formato estándar y reconocible cada vez que se muestra un marco de pila (lo que incluye cada vez que el programa se detiene). Este formato reconocible parece dos caracteres \032, seguidos del nombre del archivo, el número de línea y la posición del carácter separados por dos puntos, y un salto de línea. El programa de interfaz Emacs a GDB utiliza los dos caracteres \032 como señal para mostrar el código fuente del marco.
-b baudrate
Establecer la velocidad de línea (baud rate o bits por segundo) de cualquier interfaz serie utilizada por GDB para la depuración remota.
-l timeout
Establecer el tiempo de espera, en segundos, para la depuración remota.
--tty=device
Ejecutar usando device para la entrada y salida estándar de su programa.

VER TAMBIÉN

La documentación completa de GDB se mantiene en un manual de Texinfo. Si los programas "info" y "gdb" y la documentación de Texinfo de GDB están instalados correctamente en su sitio, el comando

info gdb

debería darle acceso al manual completo.
