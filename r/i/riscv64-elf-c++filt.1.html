Paquete: riscv64-elf-binutils

Licencias: GPL

C++FILT(1) Herramientas de desarrollo GNU C++FILT(1)

NOMBRE

c++filt - decodifica símbolos de C++ y Java

SINOPSIS

c++filt [-_|--strip-underscore]
[-n|--no-strip-underscore]
[-p|--no-params]
[-t|--types]
[-i|--no-verbose]
[-r|--no-recurse-limit]
[-R|--recurse-limit]
[-s formato|--format=formato]
[--help] [--version] [símbolo...]

DESCRIPCIÓN

Los lenguajes C++ y Java proporcionan sobrecarga de funciones, lo que significa que puedes escribir muchas funciones con el mismo nombre, siempre que cada función acepte parámetros de tipos diferentes. Para poder distinguir estas funciones de nombres similares, C++ y Java las codifican en un nombre de ensamblador de bajo nivel que identifica de forma única cada versión diferente. Este proceso se conoce como mangling (apelotonamiento). El programa c++filt [1] realiza el mapeo inverso: decodifica (demangles) nombres de bajo nivel a nombres de nivel de usuario para que puedan ser leídos.

Cada palabra alfanumérica (compuesta por letras, dígitos, guiones bajos, signos de dólar o puntos) vista en la entrada es un nombre potencialmente apelotonado. Si el nombre se decodifica en un nombre de C++, el nombre de C++ reemplaza al nombre de bajo nivel en la salida; de lo contrario, se emite la palabra original. De esta manera, puedes pasar un archivo fuente de ensamblador completo, que contenga nombres apelotonados, a través de c++filt y ver el mismo archivo fuente con nombres decodificados.

También puedes usar c++filt para descifrar símbolos individuales pasándolos en la línea de comandos:

c++filt <simbolo>

Si no se proporcionan argumentos de símbolo, c++filt lee nombres de símbolos de la entrada estándar en su lugar. Todos los resultados se imprimen en la salida estándar. La diferencia entre leer nombres de la línea de comandos versus leer nombres de la entrada estándar es que los argumentos de la línea de comandos se esperan que sean solo nombres apelotonados y no se realiza ninguna comprobación para separarlos del texto circundante. Por lo tanto, por ejemplo:

c++filt -n _Z1fv

funcionará y decodificará el nombre a "f()" mientras que:

c++filt -n _Z1fv,

no funcionará. (Nota la coma adicional al final del nombre apelotonado que lo hace inválido). Sin embargo, este comando funcionará:

echo _Z1fv, | c++filt -n

y mostrará "f()", es decir, el nombre decodificado seguido de una coma final. Este comportamiento se debe a que cuando los nombres se leen de la entrada estándar, se espera que puedan formar parte de un archivo fuente de ensamblador donde podría haber caracteres adicionales o extraños después de un nombre apelotonado. Por ejemplo:

.type   _Z1fv, @function

OPCIONES

-_
--strip-underscore
En algunos sistemas, tanto los compiladores C como C++ ponen un guión bajo delante de cada nombre. Por ejemplo, el nombre C "foo" obtiene el nombre de bajo nivel "_foo". Esta opción elimina el guión bajo inicial. Si c++filt elimina el guión bajo por defecto es dependiente del objetivo.
-n
--no-strip-underscore
No eliminar el guión bajo inicial.
-p
--no-params
Al decodificar el nombre de una función, no mostrar los tipos de los parámetros de la función.
-t
--types
Intentar decodificar también tipos además de nombres de funciones. Esto está desactivado por defecto ya que los tipos apelotonados normalmente solo se usan internamente en el compilador y pueden confundirse con nombres no apelotonados. Por ejemplo, una función llamada "a" tratada como un nombre de tipo apelotonado se decodificaría como "signed char".
-i
--no-verbose
No incluir detalles de implementación (si los hay) en la salida decodificada.
-r
-R
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Habilita o deshabilita un límite en la cantidad de recursión realizada al decodificar cadenas. Dado que los formatos de apelotonamiento de nombres permiten un nivel infinito de recursión, es posible crear cadenas cuya decodificación agote el espacio de pila disponible en la máquina anfitriona, desencadenando un fallo de memoria. El límite intenta evitar que esto suceda restringiendo la recursión a 2048 niveles de anidamiento.

Por defecto, este límite está habilitado, pero deshabilitarlo puede ser necesario para decodificar nombres verdaderamente complicados. Tenga en cuenta, sin embargo, que si el límite de recursión está deshabilitado, es posible agotar la pila y cualquier informe de error sobre tal evento será rechazado.

La opción -r es un sinónimo de la opción --no-recurse-limit. La opción -R es un sinónimo de la opción --recurse-limit.

-s formato
--format=formato
c++filt puede decodificar varios métodos de apelotonamiento, utilizados por diferentes compiladores. El argumento de esta opción selecciona qué método utiliza:
"auto"
Selección automática basada en el ejecutable (el método por defecto)
"gnu"
el utilizado por el compilador GNU C++ (g++)
"lucid"
el utilizado por el compilador Lucid (lcc)
"arm"
el especificado por el C++ Annotated Reference Manual
"hp"
el utilizado por el compilador HP (aCC)
"edg"
el utilizado por el compilador EDG
"gnu-v3"
el utilizado por el compilador GNU C++ (g++) con la ABI V3.
"java"
el utilizado por el compilador GNU Java (gcj)
"gnat"
el utilizado por el compilador GNU Ada (GNAT).
--help
Imprime un resumen de las opciones de c++filt y sale.
--version
Imprime el número de versión de c++filt y sale.
@archivo
Lee las opciones de la línea de comandos desde archivo. Las opciones leídas se insertan en lugar de la opción @archivo original. Si archivo no existe o no se puede leer, la opción se tratará literalmente y no se eliminará.

Las opciones en archivo están separadas por espacios en blanco. Se puede incluir un carácter de espacio en blanco en una opción rodeando la opción completa con comillas simples o dobles. Se puede incluir cualquier carácter (incluido una barra invertida) prefijando el carácter a incluir con una barra invertida. El archivo puede contener a su vez opciones adicionales @archivo; tales opciones se procesarán recursivamente.

NOTAS AL PIE

1.
MS-DOS no permite caracteres "+" en nombres de archivo, por lo que en MS-DOS este programa se llama CXXFILT.

NAME

c++filt - Desmolda nombres C++.

SYNOPSIS

c++filt [-options] [demangled_name]

DESCRIPTION

El programa c++filt desmoldea nombres de C++ que han sido codificados por el compilador.

Los compiladores C++ codifican los nombres de las funciones y otros identificadores para soportar la sobrecarga de funciones y la sobrecarga de operadores. Este proceso se llama "mangling". El programa c++filt invierte este proceso, tomando un nombre codificado y produciendo el nombre C++ original. Esto es útil para leer las salidas de depuradores y otros programas que muestran nombres codificados.

Si se proporciona un demangled_name en la línea de comandos, c++filt lo desmoldea y escribe la salida estándar.

Si no se proporciona ningún demangled_name en la línea de comandos, c++filt lee de la entrada estándar, desmoldea cada línea y escribe la salida estándar.

OPTIONS

-n, --no-params
No desmoldea los parámetros de la función. En su lugar, desmoldea solo el nombre de la función.
-p, --strip-underscores
Elimina los guiones bajos iniciales de los nombres de símbolos.
-h, --help
Muestra un mensaje de ayuda y sale.
-V, --version
Muestra información de la versión y sale.
