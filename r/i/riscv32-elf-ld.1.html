LD(1) Herramientas de Desarrollo GNU LD(1)

NOMBRE

ld - El enlazador GNU

SINOPSIS

ld [opciones] archivo-objeto ...

DESCRIPCIÓN

ld combina un número de archivos objeto y de archivo, relocaliza sus datos y resuelve referencias de símbolos. Usualmente el último paso en la compilación de un programa es ejecutar ld.

ld acepta archivos de lenguaje de comandos de enlazador escritos en un superconjunto de la sintaxis del Lenguaje de Comandos del Editor de Enlace de AT&T, para proporcionar control explícito y total sobre el proceso de enlazado.

Esta página del manual no describe el lenguaje de comandos; véase la entrada ld en "info" para detalles completos sobre el lenguaje de comandos y sobre otros aspectos del enlazador GNU.

Esta versión de ld utiliza las bibliotecas BFD de propósito general para operar sobre archivos objeto. Esto permite a ld leer, combinar y escribir archivos objeto en muchos formatos diferentes — por ejemplo, COFF o "a.out". Diferentes formatos pueden ser enlazados juntos para producir cualquier tipo de archivo objeto disponible.

Aparte de su flexibilidad, el enlazador GNU es más útil que otros enlazadores al proporcionar información diagnóstica. Muchos enlazadores abandonan la ejecución inmediatamente al encontrar un error; siempre que sea posible, ld continúa ejecutándose, permitiéndole identificar otros errores (o, en algunos casos, obtener un archivo de salida a pesar del error).

El enlazador GNU ld está diseñado para cubrir una amplia gama de situaciones y para ser lo más compatible posible con otros enlazadores. Como resultado, usted tiene muchas opciones para controlar su comportamiento.

OPCIONES

El enlazador soporta una gran cantidad de opciones de línea de comandos, pero en la práctica pocas de ellas se usan en un contexto particular. Por ejemplo, un uso frecuente de ld es enlazar archivos objeto estándar de Unix en un sistema Unix estándar y compatible. En tal sistema, para enlazar un archivo "hello.o":

ld -o <salida> /lib/crt0.o hello.o -lc

Esto le dice a ld que produzca un archivo llamado salida como resultado de enlazar el archivo "/lib/crt0.o" con "hello.o" y la biblioteca "libc.a", que provendrá de los directorios de búsqueda estándar. (Véase la discusión de la opción -l más adelante.)

Algunas de las opciones de línea de comandos de ld pueden ser especificadas en cualquier punto de la línea de comandos. Sin embargo, las opciones que se refieren a archivos, como -l o -T, hacen que el archivo sea leído en el punto en que la opción aparece en la línea de comandos, en relación con los archivos objeto y otras opciones de archivo. Repetir opciones no relacionadas con archivos con un argumento diferente tendrá ningún efecto adicional, o anulará las ocurrencias previas (las que están más a la izquierda en la línea de comandos) de esa opción. Las opciones que pueden especificarse significativamente más de una vez se indican en las descripciones a continuación.

Los argumentos que no son opciones son archivos objeto o archivos que se enlazarán juntos. Pueden seguir, preceder o mezclarse con las opciones de línea de comandos, excepto que un argumento de archivo objeto no puede colocarse entre una opción y su argumento.

Usualmente el enlazador se invoca con al menos un archivo objeto, pero puede especificar otras formas de archivos de entrada binarios usando -l, -R, y el lenguaje de comandos de script. Si no se especifican archivos de entrada binarios en absoluto, el enlazador no produce ninguna salida y emite el mensaje No input files (Sin archivos de entrada).

Si el enlazador no puede reconocer el formato de un archivo objeto, asumirá que es un script de enlazador. Un script especificado de esta manera aumenta el script de enlazador principal utilizado para el enlace (ya sea el script de enlazador predeterminado o el especificado usando -T). Esta característica permite al enlazador enlazar contra un archivo que parece ser un objeto o un archivo, pero que en realidad solo define algunos valores de símbolo, o utiliza "INPUT" o "GROUP" para cargar otros objetos. Especificar un script de esta manera simplemente aumenta el script de enlazador principal, con los comandos adicionales colocados después del script principal; use la opción -T para reemplazar completamente el script de enlazador predeterminado, pero tenga en cuenta el efecto del comando "INSERT".

Para opciones cuyos nombres son una sola letra, los argumentos de la opción deben seguir a la letra de la opción sin espacios intermedios, o ser dados como argumentos separados inmediatamente después de la opción que los requiere.

Para opciones cuyos nombres son múltiples letras, uno o dos guiones pueden preceder al nombre de la opción; por ejemplo, -trace-symbol y --trace-symbol son equivalentes. Nota: hay una excepción a esta regla. Las opciones de múltiples letras que comienzan con una 'o' minúscula solo pueden ir precedidas por dos guiones. Esto es para reducir la confusión con la opción -o. Así, por ejemplo, -omagic establece el nombre del archivo de salida a magic mientras que --omagic establece la bandera NMAGIC en la salida.

Los argumentos para las opciones de múltiples letras deben estar separados del nombre de la opción por un signo igual, o ser dados como argumentos separados inmediatamente después de la opción que los requiere. Por ejemplo, --trace-symbol foo y --trace-symbol=foo son equivalentes. Se aceptan abreviaturas únicas de los nombres de las opciones de múltiples letras.

Nota: si el enlazador se invoca indirectamente, a través de un controlador de compilación (por ejemplo, gcc) entonces todas las opciones de línea de comandos del enlazador deben ir precedidas por -Wl, (o lo que sea apropiado para el controlador de compilación particular) de esta manera:

gcc -Wl,--start-group foo.o bar.o -Wl,--end-group

Esto es importante, ya que de lo contrario el programa controlador de compilación puede descartar silenciosamente las opciones del enlazador, resultando en un enlace incorrecto. También puede surgir confusión al pasar opciones que requieren valores a través de un controlador, ya que el uso de un espacio entre la opción y el argumento actúa como un separador, y hace que el controlador pase solo la opción al enlazador y el argumento al compilador. En este caso, lo más sencillo es usar las formas unidas de las opciones de una y varias letras, como:

gcc foo.o bar.o -Wl,-eENTRY -Wl,-Map=a.map

@archivo
Lee las opciones de línea de comandos del archivo. Las opciones leídas se insertan en lugar de la opción original @archivo. Si archivo no existe, o no se puede leer, entonces la opción se tratará literalmente y no se eliminará.

Las opciones en archivo están separadas por espacios en blanco. Un carácter de espacio en blanco puede incluirse en una opción rodeando la opción completa con comillas simples o dobles. Cualquier carácter (incluido una barra invertida) puede incluirse prefijando el carácter a incluir con una barra invertida. El archivo puede contener él mismo opciones adicionales @archivo; cualquier opción de este tipo se procesará recursivamente.

-a palabra_clave
Esta opción es compatible con HP/UX. El argumento palabra_clave debe ser una de las cadenas archive, shared, o default. -aarchive es funcionalmente equivalente a -Bstatic, y las otras dos palabras clave son funcionalmente equivalentes a -Bdynamic. Esta opción puede usarse cualquier número de veces.

Si el enlazador encuentra un objeto con una entrada de auditoría mientras busca bibliotecas compartidas, añadirá una entrada "DT_DEPAUDIT" correspondiente en el archivo de salida. Esta opción solo es significativa en plataformas ELF que soportan la interfaz rtld-audit.

-d
-dc
-dp
Estas tres opciones son equivalentes; se soportan múltiples formas para compatibilidad con otros enlazadores. Asignan espacio a símbolos comunes incluso si se especifica un archivo de salida relocable (con -r). El comando de script "FORCE_COMMON_ALLOCATION" tiene el mismo efecto.
--depaudit BIBLIOTECA-AUDITORIA
-P BIBLIOTECA-AUDITORIA
Añade BIBLIOTECA-AUDITORIA a la entrada "DT_DEPAUDIT" de la sección dinámica. No se verifica la existencia de BIBLIOTECA-AUDITORIA, ni utilizará la DT_SONAME especificada en la biblioteca. Esta opción solo tiene sentido en plataformas ELF que soportan la interfaz rtld-audit. La opción -P se proporciona por compatibilidad con Solaris.
--enable-linker-version
Habilita la directiva de script de enlazador "LINKER_VERSION", descrita en Datos de la Sección de Salida. Si esta directiva se utiliza en un script de enlazador y esta opción se ha habilitado, se insertará una cadena que contiene la versión del enlazador en el punto actual.

Nota: la ubicación de esta opción en la línea de comandos del enlazador es significativa. Solo afectará a los scripts de enlazador que vengan después de ella en la línea de comandos, o que estén integrados en el enlazador.

--disable-linker-version
Deshabilita la directiva de script de enlazador "LINKER_VERSION", de modo que no inserte una cadena de versión. Este es el comportamiento predeterminado.
--enable-non-contiguous-regions
Esta opción evita generar un error si una sección de entrada no encaja en una sección de salida coincidente. El enlazador intenta asignar la sección de entrada a secciones de salida coincidentes subsiguientes, y solo genera un error si ninguna sección de salida es lo suficientemente grande. Esto es útil cuando hay varias regiones de memoria no contiguas disponibles y la sección de entrada no requiere una en particular. El orden en que se evalúan las secciones de entrada no cambia, por ejemplo: 
MEMORY {
  MEM1 (rwx) : ORIGIN = 0x1000, LENGTH = 0x14
  MEM2 (rwx) : ORIGIN = 0x1000, LENGTH = 0x40
  MEM3 (rwx) : ORIGIN = 0x2000, LENGTH = 0x40
}
SECTIONS {
  mem1 : { *(.data.*); } > MEM1
  mem2 : { *(.data.*); } > MEM2
  mem3 : { *(.data.*); } > MEM3
}

con secciones de entrada:
.data.1: tamaño 8
.data.2: tamaño 0x10
.data.3: tamaño 4

resulta en .data.1 asignado a mem1, y .data.2 y .data.3
asignados a mem2, aunque .data.3 cabría en mem3.

Esta opción es incompatible con las sentencias INSERT porque cambia la forma en que las secciones de entrada se mapean a las secciones de salida.

--enable-non-contiguous-regions-warnings
Esta opción habilita advertencias cuando "--enable-non-contiguous-regions" permite coincidencias potencialmente inesperadas en el mapeo de secciones, lo que podría llevar a descartar silenciosamente una sección en lugar de fallar porque no encaja en ninguna región de salida.
-e entrada
--entry=entrada
Utiliza entrada como el símbolo explícito para el inicio de la ejecución de tu programa, en lugar del punto de entrada predeterminado. Si no hay un símbolo llamado entrada, el enlazador intentará interpretar entrada como un número, y lo utilizará como la dirección de entrada (el número se interpretará en base 10; puedes usar un prefijo 0x para base 16, o un prefijo 0 para base 8).
--exclude-libs lib,lib,...
Especifica una lista de bibliotecas de archivo de las cuales no se deben exportar símbolos automáticamente. Los nombres de las bibliotecas pueden estar delimitados por comas o dos puntos. Especificar "--exclude-libs ALL" excluye la exportación automática de símbolos de todas las bibliotecas de archivo. Esta opción solo está disponible para el puerto i386 PE del enlazador y para puertos dirigidos a ELF. Para i386 PE, los símbolos listados explícitamente en un archivo .def todavía se exportan, independientemente de esta opción. Para puertos dirigidos a ELF, los símbolos afectados por esta opción se tratarán como ocultos.
--exclude-modules-for-implib modulo,modulo,...
Especifica una lista de archivos objeto o miembros de archivo, de los cuales no se deben exportar símbolos automáticamente, pero que deben copiarse íntegramente a la biblioteca de importación que se está generando durante el enlace. Los nombres de los módulos pueden estar delimitados por comas o dos puntos, y deben coincidir exactamente con los nombres de archivo utilizados por ld para abrir los archivos; para miembros de archivo, este es simplemente el nombre del miembro, pero para archivos objeto, el nombre listado debe incluir y coincidir exactamente con cualquier ruta utilizada para especificar el archivo de entrada en la línea de comandos del enlazador. Esta opción solo está disponible para el puerto i386 PE del enlazador. Los símbolos listados explícitamente en un archivo .def todavía se exportan, independientemente de esta opción.
-E
--export-dynamic
--no-export-dynamic
Al crear un ejecutable enlazado dinámicamente, el uso de la opción -E o la opción --export-dynamic hace que el enlazador agregue todos los símbolos a la tabla de símbolos dinámicos. La tabla de símbolos dinámicos es el conjunto de símbolos que son visibles desde objetos dinámicos en tiempo de ejecución.

Si no utiliza ninguna de estas opciones (o utiliza la opción --no-export-dynamic para restaurar el comportamiento predeterminado), la tabla de símbolos dinámicos normalmente contendrá solo aquellos símbolos que son referenciados por algún objeto dinámico mencionado en el enlace.

Si utiliza "dlopen" para cargar un objeto dinámico que necesita referirse a los símbolos definidos por el programa, en lugar de algún otro objeto dinámico, entonces probablemente necesitará usar esta opción al enlazar el programa en sí.

También puede utilizar la lista dinámica para controlar qué símbolos se deben agregar a la tabla de símbolos dinámicos si el formato de salida lo admite. Consulte la descripción de --dynamic-list.

Tenga en cuenta que esta opción es específica para puertos dirigidos a ELF. Los destinos PE admiten una función similar para exportar todos los símbolos de una DLL o EXE; consulte la descripción de --export-all-symbols a continuación.

--export-dynamic-symbol=glob
Al crear un ejecutable enlazado dinámicamente, los símbolos que coincidan con glob se agregarán a la tabla de símbolos dinámicos. Al crear una biblioteca compartida, las referencias a símbolos que coincidan con glob no se vincularán a las definiciones dentro de la biblioteca compartida. Esta opción no tiene efecto al crear una biblioteca compartida y no se especifican -Bsymbolic o --dynamic-list. Esta opción solo tiene sentido en plataformas ELF que admiten bibliotecas compartidas.
--export-dynamic-symbol-list=archivo
Especifique un --export-dynamic-symbol para cada patrón en el archivo. El formato del archivo es el mismo que el nodo de versión sin el ámbito ni el nombre del nodo. Consulte VERSION para obtener más información.
-EB
Enlaza objetos big-endian. Esto afecta al formato de salida predeterminado.
-EL
Enlaza objetos little-endian. Esto afecta al formato de salida predeterminado.
-f nombre
--auxiliary=nombre
Al crear un objeto compartido ELF, establece el campo interno DT_AUXILIARY al nombre especificado. Esto le dice al enlazador dinámico que la tabla de símbolos del objeto compartido debe usarse como un filtro auxiliar en la tabla de símbolos del objeto compartido nombre.

Si más tarde enlaza un programa contra este objeto de filtro, entonces, cuando ejecute el programa, el enlazador dinámico verá el campo DT_AUXILIARY. Si el enlazador dinámico resuelve algún símbolo del objeto de filtro, primero verificará si hay una definición en el objeto compartido nombre. Si la hay, se utilizará en lugar de la definición en el objeto de filtro. El objeto compartido nombre no necesita existir. Por lo tanto, el objeto compartido nombre puede usarse para proporcionar una implementación alternativa de ciertas funciones, quizás para depuración o para optimizar el rendimiento específico de la máquina.

Esta opción se puede especificar más de una vez. Las entradas DT_AUXILIARY se crearán en el orden en que aparezcan en la línea de comandos.

-F nombre
--filter=nombre
Al crear un objeto compartido ELF, establece el campo interno DT_FILTER al nombre especificado. Esto indica al enlazador dinámico que la tabla de símbolos del objeto compartido que se está creando debe usarse como un filtro en la tabla de símbolos del objeto compartido nombre.

Si posteriormente enlazas un programa contra este objeto filtro, entonces, cuando ejecutes el programa, el enlazador dinámico verá el campo DT_FILTER. El enlazador dinámico resolverá los símbolos según la tabla de símbolos del objeto filtro como de costumbre, pero en realidad se enlazará a las definiciones encontradas en el objeto compartido nombre. Por lo tanto, el objeto filtro se puede utilizar para seleccionar un subconjunto de los símbolos proporcionados por el objeto nombre.

Algunos enlazadores antiguos utilizaron la opción -F en toda una cadena de herramientas de compilación para especificar el formato del archivo objeto tanto para los archivos objeto de entrada como de salida. El enlazador de GNU utiliza otros mecanismos para este propósito: las opciones -b, --format, --oformat, el comando "TARGET" en los scripts del enlazador y la variable de entorno "GNUTARGET". El enlazador de GNU ignorará la opción -F cuando no esté creando un objeto compartido ELF.

-fini=nombre
Al crear un ejecutable o un objeto compartido ELF, llama a NOMBRE cuando el ejecutable o el objeto compartido se descargan, estableciendo DT_FINI a la dirección de la función. Por defecto, el enlazador utiliza "_fini" como la función a la que llamar.
-g
Ignorado. Proporcionado para compatibilidad con otras herramientas.
-G valor
--gpsize=valor
Establece el tamaño máximo de los objetos que se optimizarán utilizando el registro GP a tamaño. Esto solo es significativo para formatos de archivo objeto como MIPS ELF que admiten la colocación de objetos grandes y pequeños en secciones diferentes. Esto se ignora para otros formatos de archivo objeto.
-h nombre
-soname=nombre
Al crear un objeto compartido ELF, establece el campo interno DT_SONAME al nombre especificado. Cuando un ejecutable se enlaza con un objeto compartido que tiene un campo DT_SONAME, entonces cuando se ejecute el ejecutable, el enlazador dinámico intentará cargar el objeto compartido especificado por el campo DT_SONAME en lugar de utilizar el nombre de archivo dado al enlazador.
-i
Realiza un enlace incremental (igual que la opción -r).
-init=nombre
Al crear un ejecutable o un objeto compartido ELF, llama a NOMBRE cuando el ejecutable o el objeto compartido se cargan, estableciendo DT_INIT a la dirección de la función. Por defecto, el enlazador utiliza "_init" como la función a la que llamar.
-l especnombredearchivo
--library=especnombredearchivo
Agrega el archivo de biblioteca o el archivo objeto especificado por especnombredearchivo a la lista de archivos a enlazar. Esta opción se puede usar cualquier número de veces. Si especnombredearchivo tiene la forma :nombrearchivo, ld buscará en la ruta de bibliotecas un archivo llamado nombrearchivo, de lo contrario buscará en la ruta de bibliotecas un archivo llamado libespecnombredearchivo.a.

En sistemas que admiten bibliotecas compartidas, ld también puede buscar archivos distintos de libespecnombredearchivo.a. Específicamente, en sistemas ELF y SunOS, ld buscará en un directorio una biblioteca llamada libespecnombredearchivo.so antes de buscar una llamada libespecnombredearchivo.a. (Por convención, una extensión ".so" indica una biblioteca compartida). Tenga en cuenta que este comportamiento no se aplica a :nombrearchivo, que siempre especifica un archivo llamado nombrearchivo.

El enlazador buscará en un archivo de biblioteca solo una vez, en la ubicación donde se especifica en la línea de comandos. Si el archivo de biblioteca define un símbolo que no estaba definido en algún objeto que apareció antes del archivo de biblioteca en la línea de comandos, el enlazador incluirá los archivos apropiados del archivo de biblioteca. Sin embargo, un símbolo no definido en un objeto que aparece más tarde en la línea de comandos no hará que el enlazador busque nuevamente en el archivo de biblioteca.

Consulte la opción -( para ver una forma de forzar al enlazador a buscar archivos de biblioteca múltiples veces.

Puede listar el mismo archivo de biblioteca varias veces en la línea de comandos.

Este tipo de búsqueda de archivos de biblioteca es estándar para los enlazadores de Unix. Sin embargo, si está utilizando ld en AIX, tenga en cuenta que es diferente del comportamiento del enlazador de AIX.

-L directoriodebúsqueda
--library-path=directoriodebúsqueda
Agrega la ruta directoriodebúsqueda a la lista de rutas que ld buscará para bibliotecas de archivos y scripts de control de ld. Puede usar esta opción cualquier número de veces. Los directorios se buscan en el orden en que se especifican en la línea de comandos. Los directorios especificados en la línea de comandos se buscan antes que los directorios predeterminados. Todas las opciones -L se aplican a todas las opciones -l, independientemente del orden en que aparezcan las opciones. Las opciones -L no afectan cómo ld busca un script de enlazador a menos que se especifique la opción -T.

Si directoriodebúsqueda comienza con "=" o $SYSROOT, entonces este prefijo será reemplazado por el prefijo sysroot, controlado por la opción --sysroot, o especificado cuando se configuró el enlazador.

El conjunto predeterminado de rutas buscadas (sin ser especificado con -L) depende de qué modo de emulación esté utilizando ld y, en algunos casos, también de cómo se configuró.

Las rutas también se pueden especificar en un script de enlace con el comando "SEARCH_DIR". Los directorios especificados de esta manera se buscan en el punto en que aparece el script de enlace en la línea de comandos.

-m emulación
Emula el enlazador emulación. Puede enumerar las emulaciones disponibles con las opciones --verbose o -V.

Si no se utiliza la opción -m, la emulación se toma de la variable de entorno "LDEMULATION", si está definida.

De lo contrario, la emulación predeterminada depende de cómo se configuró el enlazador.

--remap-inputs=patrón=nombrearchivo
--remap-inputs-file=archivo
Estas opciones permiten cambiar los nombres de los archivos de entrada antes de que el enlazador intente abrirlos. La opción --remap-inputs=foo.o=bar.o hará que cualquier intento de cargar un archivo llamado foo.o intente cargar en su lugar un archivo llamado bar.o. Se permiten patrones comodín en el primer nombre de archivo, por lo que --remap-inputs=foo*.o=bar.o renombrará cualquier archivo de entrada que coincida con foo*.o a bar.o.

Una forma alternativa de la opción --remap-inputs-file=nombrearchivo permite leer las reasignaciones de un archivo. Cada línea en el archivo puede contener una sola reasignación. Las líneas en blanco se ignoran. Cualquier cosa desde un carácter de almohadilla (#) hasta el final de una línea se considera un comentario y también se ignora. El patrón de mapeo se puede separar del nombre de archivo por espacios en blanco o un carácter de igual (=).

Las opciones se pueden especificar varias veces. Sus contenidos se acumulan. Las reasignaciones se procesarán en el orden en que aparezcan en la línea de comandos y, si provienen de un archivo, en el orden en que aparezcan en el archivo. Si se produce una coincidencia, no se realizará ninguna comprobación adicional para ese nombre de archivo.

Si el nombre de archivo de reemplazo es /dev/null o simplemente NUL, la reasignación hará que el archivo de entrada se ignore. Esta puede ser una forma conveniente de experimentar eliminando archivos de entrada de un entorno de compilación complicado.

Tenga en cuenta que esta opción depende de la posición y solo afecta a los nombres de archivo que aparecen después de ella en la línea de comandos. Por lo tanto:

ld foo.o --remap-inputs=foo.o=bar.o

No tendrá ningún efecto, mientras que:

ld --remap-inputs=foo.o=bar.o foo.o

Renombrará el archivo de entrada foo.o a bar.o.

Nota: estas opciones también afectan a los archivos referenciados por declaraciones INPUT en los scripts del enlazador. Pero dado que los scripts del enlazador se procesan después de leer toda la línea de comandos, la posición de las opciones de reasignación en la línea de comandos no es significativa.

Si la opción verbose está habilitada, se informarán las coincidencias que coincidan, aunque nuevamente la opción verbose debe estar habilitada en la línea de comandos antes de que aparezcan los nombres de archivo reasignados.

  • Cómo se asignan los símbolos comunes.

    0x00000001                foo = 0x1
[0x0000000c]                foo = (foo * 0x4)

    Consulte Expresiones para

    Esto indica que el valor de la propiedad 0xc0010001 se actualiza a 0x1 en la salida al fusionar propiedades en foo.o, cuya propiedad 0xc0010001 tiene el valor 0x1, y bar.o, cuya propiedad 0xc0010001 tiene el valor 0x1.

-( archives -)

The archives should be a list of archive files. They may be either explicit file names, or -l options.

The specified archives are searched repeatedly until no new undefined references are created. Normally, an archive is searched only once in the order that it is specified on the command line. If a symbol in that archive is needed to resolve an undefined symbol referred to by an object in an archive that appears later on the command line, the linker would not be able to resolve that reference. Using this option has a significant performance cost. It is best to use it only when there are unavoidable circular references between two or more archives.

En plataformas ELF, el enlazador puede generar mensajes de advertencia si se le pide que cree un archivo de salida que contenga una pila ejecutable. Hay tres estados posibles:
1.
No generar ninguna advertencia.
2.
Generar advertencias siempre, incluso si se solicita una pila ejecutable a través de la opción de línea de comandos -z execstack.
3.
Generar una advertencia solo si un archivo objeto solicita una pila ejecutable, pero no si se utiliza la opción -z execstack.

--warn-multiple-gp
Advierte si se requieren múltiples valores de puntero global en el archivo de salida. Esto solo tiene sentido para ciertos procesadores, como Alpha. Específicamente, algunos procesadores colocan constantes de valor grande en una sección especial. Un registro especial (el puntero global) apunta a la mitad de esta sección, de modo que las constantes se puedan cargar de manera eficiente mediante un modo de direccionamiento relativo al registro base. Dado que el desplazamiento en el modo relativo al registro base es fijo y relativamente pequeño (por ejemplo, 16 bits), esto limita el tamaño máximo del grupo de constantes. Por lo tanto, en programas grandes, a menudo es necesario utilizar múltiples valores de puntero global para poder direccionar todas las constantes posibles. --wrap=symbol
This option specifies that the linker should resolve all references to the symbol symbol to the symbol "__wrap_symbol". This procedure is useful for adding functionality to library routines. One might want to count the number of calls to a library routine, or to add checking before calling the routine.

You would create a routine called "__wrap_symbol" which does your custom processing, and then calls the original routine via a call to "__real_symbol". The linker will resolve calls to "__real_symbol" to the real library function.

You may wish to provide a "__real_malloc" function as well, so that links without the --wrap option will succeed. Esta opción reduce los requisitos de memoria en tiempo de ejecución de ld, a costa de la velocidad de enlazado. Otro efecto del cambio es establecer el tamaño por defecto de la tabla hash en 1021, lo que a su vez ahorra memoria a costa de aumentar el tiempo de ejecución del enlazador. Sin embargo, esto no se hace si se ha utilizado el modificador --hash-size.

Como una extensión de GNU, es posible permitir su uso en imágenes ejecutables también, o (probablemente inútilmente!) deshabilitarlo en archivos objeto, utilizando estas dos opciones. Las imágenes ejecutables generadas con estos nombres de sección largos son ligeramente no estándar, ya que llevan una tabla de cadenas, y pueden generar una salida confusa cuando se examinan con herramientas no GNU que reconocen PE, como visores y volcadores de archivos. Sin embargo, GDB depende del uso de nombres de sección largos de PE para encontrar las secciones de información de depuración Dwarf-2 en una imagen ejecutable en tiempo de ejecución, y por lo tanto, si no se especifica ninguna de las opciones en la línea de comandos, ld habilitará los nombres de sección largos, anulando el comportamiento predeterminado y técnicamente correcto, cuando detecta la presencia de información de depuración al enlazar una imagen ejecutable y no eliminar los símbolos. Las siguientes observaciones pertenecen a la implementación original de la característica y hoy en día son obsoletas para los destinos Cygwin y MinGW.

Nota: El uso de la extensión 'auto-import' hará que la sección de texto del archivo de imagen se vuelva escribible. Esto no se ajusta a la especificación del formato PE-COFF publicada por Microsoft.

Nota - el uso de la extensión 'auto-import' también provocará que los datos de solo lectura, que normalmente se colocarían en la sección .rdata, se coloquen en la sección .data en su lugar. Esto es para solucionar un problema con las constantes que se describe aquí: http://www.cygwin.com/ml/cygwin/2004-09/msg01101.html

Usar 'auto-import' generalmente 'funcionará' -- pero a veces podrías ver este mensaje:

"la variable '<var>' no se puede autoimportar. Por favor, lee la documentación de ld "--enable-auto-import" para más detalles."

Este mensaje ocurre cuando alguna (sub)expresión accede a una dirección dada en última instancia por la suma de dos constantes (las tablas de importación de Win32 solo permiten una). Instancias donde esto puede ocurrir incluyen el acceso a campos miembro de variables de estructura importadas de una DLL, así como el uso de un índice constante en una variable de arreglo importada de una DLL. Cualquier variable de múltiples palabras (arreglos, estructuras, long long, etc.) puede desencadenar esta condición de error. Sin embargo, independientemente del tipo de datos exacto de la variable exportada que cause el problema, ld siempre la detectará, emitirá la advertencia y saldrá.

Hay varias formas de abordar esta dificultad, independientemente del tipo de datos de la variable exportada:

Una forma es usar el modificador --enable-runtime-pseudo-reloc. Esto deja la tarea de ajustar las referencias en su código cliente para el entorno de ejecución, por lo que este método solo funciona cuando el entorno de ejecución soporta esta característica.

Una segunda solución es forzar que una de las 'constantes' sea una variable -- es decir, desconocida y no optimizable en tiempo de compilación. Para los arreglos, hay dos posibilidades: a) hacer que el indexado (la dirección del arreglo) sea una variable, o b) hacer que el índice 'constante' sea una variable. Así:

extern type extern_array[];
extern_array[1] -->
   { volatile type *t=extern_array; t[1] }

o

extern type extern_array[];
extern_array[1] -->
   { volatile int t=1; extern_array[t] }

Para estructuras (y la mayoría de los demás tipos de datos de múltiples palabras) la única opción es hacer que la estructura misma (o el long long, o el ...) sea una variable:

extern struct s extern_struct;
extern_struct.field -->
   { volatile struct s *t=&extern_struct; t->field }

o

extern long long extern_ll;
extern_ll -->
  { volatile long long * local_ll=&extern_ll; *local_ll }

Un tercer método para lidiar con esta dificultad es abandonar 'auto-import' para el símbolo problemático y marcarlo con "__declspec(dllimport)". Sin embargo, en la práctica, esto requiere usar #defines en tiempo de compilación para indicar si estás creando una DLL, creando código cliente que se enlazará a la DLL, o simplemente creando/enlazando a una biblioteca estática. Al elegir entre los diversos métodos para resolver el problema de 'dirección directa con desplazamiento constante', debes considerar el uso típico en el mundo real:

Original:

--foo.h
extern int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  printf("%d\n",arr[1]);
}

Solución 1:

--foo.h
extern int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  /* Este workaround es para win32 y cygwin; no "optimizar" */
  volatile int *parr = arr;
  printf("%d\n",parr[1]);
}

Solución 2:

--foo.h
/* Nota: Se asume auto-exportación (sin __declspec(dllexport)) */
#if (defined(_WIN32) || defined(__CYGWIN__)) && \
  !(defined(FOO_BUILD_DLL) || defined(FOO_STATIC))
#define FOO_IMPORT __declspec(dllimport)
#else
#define FOO_IMPORT
#endif
extern FOO_IMPORT int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  printf("%d\n",arr[1]);
}

Una cuarta forma de evitar este problema es refactorizar tu biblioteca para usar una interfaz funcional en lugar de una interfaz de datos para las variables problemáticas (por ejemplo, funciones accesoras set_foo() y get_foo()).

Puedes cambiar el comportamiento de ld con las variables de entorno "GNUTARGET", "LDEMULATION" y "COLLECT_NO_DEMANGLE".

"GNUTARGET" determina el formato del objeto del archivo de entrada si no usas -b (o su sinónimo --format). Su valor debe ser uno de los nombres BFD para un formato de entrada. Si no hay "GNUTARGET" en el entorno, ld usa el formato natural del objetivo. Si "GNUTARGET" se establece en "default", entonces BFD intenta descubrir el formato de entrada examinando los archivos binarios de entrada; este método a menudo tiene éxito, pero existen ambigüedades potenciales, ya que no hay un método para garantizar que el número mágico utilizado para especificar los formatos de archivo objeto sea único. Sin embargo, el procedimiento de configuración para BFD en cada sistema coloca el formato convencional para ese sistema primero en la lista de búsqueda, por lo que las ambigüedades se resuelven a favor de la convención.

"LDEMULATION" determina la emulación predeterminada si no usas la opción -m. La emulación puede afectar varios aspectos del comportamiento del enlazador, particularmente el script de enlazador predeterminado. Puedes listar las emulaciones disponibles con las opciones --verbose o -V. Si la opción -m no se usa y la variable de entorno "LDEMULATION" no está definida, la emulación predeterminada depende de cómo se configuró el enlazador.
