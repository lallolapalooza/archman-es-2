LD(1) Herramientas de desarrollo GNU LD(1)

NOMBRE

ld - El enlazador GNU

SINOPSIS

ld [opciones] archivo-objeto ...

DESCRIPCIÓN

ld combina un número de archivos objeto y de archivo, los relocaliza y resuelve referencias de símbolos. Generalmente, el último paso en la compilación de un programa es ejecutar ld.

ld acepta archivos de lenguaje de comandos de enlazador escritos en un superconjunto de la sintaxis del lenguaje de comandos del enlazador de AT&T, para proporcionar control explícito y total sobre el proceso de enlazado.

Esta página del manual no describe el lenguaje de comandos; consulte la entrada ld en "info" para obtener detalles completos sobre el lenguaje de comandos y otros aspectos del enlazador GNU.

Esta versión de ld utiliza las bibliotecas BFD de propósito general para operar con archivos objeto. Esto permite a ld leer, combinar y escribir archivos objeto en muchos formatos diferentes, por ejemplo, COFF o "a.out". Diferentes formatos pueden ser enlazados juntos para producir cualquier tipo de archivo objeto disponible.

Además de su flexibilidad, el enlazador GNU proporciona información diagnóstica más útil que otros enlazadores. Muchos enlazadores abandonan la ejecución inmediatamente al encontrar un error; siempre que sea posible, ld continúa la ejecución, permitiéndole identificar otros errores (o, en algunos casos, obtener un archivo de salida a pesar del error).

El enlazador GNU ld está diseñado para cubrir una amplia gama de situaciones y ser lo más compatible posible con otros enlazadores. Como resultado, tiene muchas opciones para controlar su comportamiento.

OPCIONES

El enlazador soporta una gran cantidad de opciones de línea de comandos, pero en la práctica pocas se utilizan en un contexto particular. Por ejemplo, un uso frecuente de ld es enlazar archivos objeto estándar de Unix en un sistema Unix estándar y soportado. En tal sistema, para enlazar un archivo "hola.o":

ld -o <salida> /lib/crt0.o hola.o -lc

Esto le dice a ld que produzca un archivo llamado salida como resultado de enlazar el archivo "/lib/crt0.o" con "hola.o" y la biblioteca "libc.a", que provendrá de los directorios de búsqueda estándar. (Vea la discusión de la opción -l más abajo).

Algunas de las opciones de línea de comandos para ld pueden especificarse en cualquier punto de la línea de comandos. Sin embargo, las opciones que se refieren a archivos, como -l o -T, hacen que el archivo se lea en el punto en que aparece la opción en la línea de comandos, en relación con los archivos objeto y otras opciones de archivo. Repetir opciones no relacionadas con archivos con un argumento diferente o no tendrá efecto adicional, o anulará las ocurrencias previas (las que están más a la izquierda en la línea de comandos) de esa opción. Las opciones que pueden especificarse significativamente más de una vez se anotan en las descripciones a continuación.

Los argumentos que no son opciones son archivos objeto o archivos que van a ser enlazados juntos. Pueden seguir, preceder o mezclarse con las opciones de línea de comandos, excepto que un argumento de archivo objeto no puede colocarse entre una opción y su argumento.

Normalmente el enlazador se invoca con al menos un archivo objeto, pero puede especificar otras formas de archivos de entrada binaria usando -l, -R y el lenguaje de comandos de script. Si no se especifican archivos de entrada binaria en absoluto, el enlazador no produce ninguna salida y emite el mensaje No input files.

Si el enlazador no puede reconocer el formato de un archivo objeto, asumirá que es un script de enlazador. Un script especificado de esta manera aumenta el script de enlazador principal utilizado para el enlace (ya sea el script de enlazador predeterminado o el especificado usando -T). Esta característica permite al enlazador enlazar contra un archivo que parece ser un objeto o un archivo, pero que en realidad solo define algunos valores de símbolos, o utiliza "INPUT" o "GROUP" para cargar otros objetos. Especificar un script de esta manera simplemente aumenta el script de enlazador principal, con los comandos adicionales colocados después del script principal; use la opción -T para reemplazar completamente el script de enlazador predeterminado, pero tenga en cuenta el efecto del comando "INSERT".

Para opciones cuyos nombres son una sola letra, los argumentos de opción deben seguir la letra de opción sin espacios intermedios, o darse como argumentos separados inmediatamente después de la opción que los requiere.

Para opciones cuyos nombres son múltiples letras, uno o dos guiones pueden preceder el nombre de la opción; por ejemplo, -trace-symbol y --trace-symbol son equivalentes. Nota: hay una excepción a esta regla. Las opciones de múltiples letras que comienzan con una 'o' minúscula solo pueden ir precedidas por dos guiones. Esto es para reducir la confusión con la opción -o. Así, por ejemplo, -omagic establece el nombre del archivo de salida a magic, mientras que --omagic establece la bandera NMAGIC en la salida.

Los argumentos para opciones de múltiples letras deben separarse del nombre de la opción con un signo igual, o darse como argumentos separados inmediatamente después de la opción que los requiere. Por ejemplo, --trace-symbol foo y --trace-symbol=foo son equivalentes. Se aceptan abreviaturas únicas de los nombres de las opciones de múltiples letras.

Nota: si el enlazador se invoca indirectamente, a través de un controlador de compilación (por ejemplo, gcc), entonces todas las opciones de línea de comandos del enlazador deben ir precedidas por -Wl, (o lo que sea apropiado para el controlador de compilación particular), así:

gcc -Wl,--start-group foo.o bar.o -Wl,--end-group

Esto es importante, ya que de lo contrario el programa controlador de compilación puede omitir silenciosamente las opciones del enlazador, resultando en un enlace incorrecto. La confusión también puede surgir al pasar opciones que requieren valores a través de un controlador, ya que el uso de un espacio entre la opción y el argumento actúa como un separador, y hace que el controlador pase solo la opción al enlazador y el argumento al compilador. En este caso, es más sencillo usar las formas unidas tanto de opciones de una sola letra como de múltiples letras, como:

gcc foo.o bar.o -Wl,-eENTRY -Wl,-Map=a.map

@archivo
Lee las opciones de línea de comandos desde archivo. Las opciones leídas se insertan en lugar de la opción original @archivo. Si archivo no existe, o no se puede leer, entonces la opción se tratará literalmente y no se eliminará.

Las opciones en archivo están separadas por espacios en blanco. Un carácter de espacio en blanco puede incluirse en una opción rodeando la opción completa entre comillas simples o dobles. Cualquier carácter (incluida una barra invertida) puede incluirse anteponiendo el carácter que se va a incluir con una barra invertida. El archivo puede contener opciones adicionales @archivo; cualquier opción de este tipo se procesará recursivamente.

-a palabra_clave
Esta opción se soporta por compatibilidad con HP/UX. El argumento palabra_clave debe ser una de las cadenas archive, shared, o default. -aarchive es funcionalmente equivalente a -Bstatic, y las otras dos palabras clave son funcionalmente equivalentes a -Bdynamic. Esta opción puede usarse cualquier número de veces.

Algunos enlazadores antiguos utilizaban la opción -F en toda una cadena de herramientas de compilación para especificar el formato del archivo objeto tanto para los archivos objeto de entrada como de salida. El enlazador GNU utiliza otros mecanismos para este propósito: las opciones -b, --format, --oformat, el comando "TARGET" en los scripts del enlazador y la variable de entorno "GNUTARGET". El enlazador GNU ignorará la opción -F cuando no esté creando un objeto compartido ELF.

Establece el tamaño máximo de los objetos a optimizar utilizando el registro GP a size. Esto solo es significativo para formatos de archivo objeto como MIPS ELF que admiten la colocación de objetos grandes y pequeños en secciones diferentes. Esto se ignora para otros formatos de archivo objeto.

-l namespec
--library=namespec
Añade el archivo de archivo o objeto especificado por namespec a la lista de archivos a enlazar. Esta opción se puede usar cualquier número de veces. Si namespec tiene la forma :filename, ld buscará en la ruta de bibliotecas un archivo llamado filename, de lo contrario, buscará en la ruta de bibliotecas un archivo llamado libnamespec.a.

Específicamente, en sistemas ELF y SunOS, ld buscará en un directorio una biblioteca llamada libnamespec.so antes de buscar una llamada libnamespec.a. (Por convención, una extensión ".so" indica una biblioteca compartida.) Tenga en cuenta que este comportamiento no se aplica a :filename, que siempre especifica un archivo llamado filename.

El enlazador buscará un archivo solo una vez, en la ubicación en que se especifica en la línea de comandos. Si el archivo define un símbolo que no estaba definido en algún objeto que apareció antes que el archivo en la línea de comandos, el enlazador incluirá los archivos apropiados del archivo. Sin embargo, un símbolo indefinido en un objeto que aparece más tarde en la línea de comandos no provocará que el enlazador vuelva a buscar en el archivo.

Vea la opción -( para saber cómo forzar al enlazador a buscar archivos varias veces.

Puede listar el mismo archivo varias veces en la línea de comandos.

Este tipo de búsqueda de archivos es estándar para los enlazadores Unix. Sin embargo, si está utilizando ld en AIX, tenga en cuenta que es diferente del comportamiento del enlazador AIX.

-L searchdir
--library-path=searchdir
Añade la ruta searchdir a la lista de rutas que ld buscará para bibliotecas de archivos y scripts de control de ld. Puede usar esta opción cualquier número de veces. Los directorios se buscan en el orden en que se especifican en la línea de comandos. Los directorios especificados en la línea de comandos se buscan antes que los directorios predeterminados. Todas las opciones -L se aplican a todas las opciones -l, independientemente del orden en que aparezcan las opciones. Las opciones -L no afectan a cómo ld busca un script del enlazador a menos que se especifique la opción -T.

Si searchdir comienza con "=" o $SYSROOT, entonces este prefijo será reemplazado por el prefijo sysroot, controlado por la opción --sysroot, o especificado cuando se configura el enlazador.

El conjunto predeterminado de rutas buscadas (sin ser especificado con -L) depende de qué modo de emulación esté usando ld, y en algunos casos también de cómo fue configurado.

Las rutas también se pueden especificar en un script de enlace con el comando "SEARCH_DIR". Los directorios especificados de esta manera se buscan en el punto en que el script del enlazador aparece en la línea de comandos.

-m emulation
Emula el enlazador emulation. Puede listar las emulaciones disponibles con las opciones --verbose o -V.

Si la opción -m no se usa, la emulación se toma de la variable de entorno "LDEMULATION", si esta está definida.

De lo contrario, la emulación predeterminada depende de cómo se configuró el enlazador.

--remap-inputs=pattern=filename
--remap-inputs-file=file
Estas opciones permiten cambiar los nombres de los archivos de entrada antes de que el enlazador intente abrirlos. La opción --remap-inputs=foo.o=bar.o hará que cualquier intento de cargar un archivo llamado foo.o intente cargar en su lugar un archivo llamado bar.o. Se permiten patrones comodín en el primer nombre de archivo, por lo que --remap-inputs=foo*.o=bar.o renombrará cualquier archivo de entrada que coincida con foo*.o a bar.o.

Una forma alternativa de la opción --remap-inputs-file=filename permite leer las reasignaciones de un archivo. Cada línea en el archivo puede contener una sola reasignación. Las líneas en blanco se ignoran. Cualquier cosa desde un carácter de almohadilla (#) hasta el final de una línea se considera un comentario y también se ignora. El patrón de mapeo puede separarse del nombre de archivo por espacio en blanco o un carácter de igual (=).

Las opciones se pueden especificar varias veces. Sus contenidos se acumulan. Las reasignaciones se procesarán en el orden en que ocurren en la línea de comandos, y si provienen de un archivo, en el orden en que ocurren en el archivo. Si se produce una coincidencia, no se realizará más comprobación para ese nombre de archivo.

Si el nombre de archivo de reemplazo es /dev/null o simplemente NUL, entonces la reasignación realmente hará que el archivo de entrada se ignore. Esta puede ser una forma conveniente de experimentar eliminando archivos de entrada de un entorno de compilación complicado.

Tenga en cuenta que esta opción depende de la posición y solo afecta a los nombres de archivo que vienen después de ella en la línea de comandos. Por lo tanto:

ld foo.o --remap-inputs=foo.o=bar.o

No tendrá ningún efecto, mientras que:

ld --remap-inputs=foo.o=bar.o foo.o

Renombrará el archivo de entrada foo.o a bar.o.

Nota: estas opciones también afectan a los archivos referenciados por las sentencias INPUT en los scripts del enlazador. Pero dado que los scripts del enlazador se procesan después de leer toda la línea de comandos, la posición de las opciones de reasignación en la línea de comandos no es significativa.

Si la opción verbose está habilitada, se informarán las reasignaciones que coincidan, aunque de nuevo la opción verbose debe estar habilitada en la línea de comandos antes de que aparezcan los nombres de archivo reasignados.

Si las opciones -Map o --print-map están habilitadas, la lista de reasignaciones se incluirá en la salida del mapa.

-M
--print-map
Imprime un mapa de enlace en la salida estándar. Un mapa de enlace proporciona información sobre el enlace, incluyendo lo siguiente:
  • Dónde se mapean los archivos objeto en memoria.
  • Cómo se asignan los símbolos comunes.
  • Todos los miembros del archivo incluidos en el enlace, con una mención del símbolo que provocó la inclusión del miembro del archivo.
  • Los valores asignados a los símbolos.

    Nota: Es posible que los símbolos cuyos valores se calculan mediante una expresión que involucra una referencia a un valor anterior del mismo símbolo no muestren el resultado correcto en el mapa de enlace. Esto se debe a que el enlazador descarta los resultados intermedios y solo conserva el valor final de una expresión. En tales circunstancias, el enlazador mostrará el valor final encerrado entre corchetes. Así, por ejemplo, un script del enlazador que contenga:

    foo = 1
foo = foo * 4
foo = foo + 8

    Producirá la siguiente salida en el mapa de enlace si se usa la opción -M:

    0x00000001                foo = 0x1
[0x0000000c]                foo = (foo * 0x4)
[0x0000000c]                foo = (foo + 0x8)

    How GNU properties are merged.

    When the linker merges input .note.gnu.property sections into one output .note.gnu.property section, some properties are removed or updated. These actions are reported in the link map. For example:

    Removed property 0xc0000002 to merge foo.o (0x1) and bar.o (not found)

    This indicates that property 0xc0000002 is removed from output when merging properties in foo.o, whose property 0xc0000002 value is 0x1, and bar.o, which doesn't have property 0xc0000002.

    Updated property 0xc0010001 (0x1) to merge foo.o (0x1) and bar.o (0x1)

    This indicates that property 0xc0010001 value is updated to 0x1 in output when merging properties in foo.o, whose 0xc0010001 property value is 0x1, and bar.o, whose 0xc0010001 property value is 0x1.

    On some ELF targets, a list of fixups inserted by <b>--relax</b> 
    foo.o: Adjusting branch at 0x00000008 towards "far" in section .text

    This indicates that the branch at 0x00000008 in foo.o, targeting the symbol "far" in section .text, has been replaced by a trampoline.

    --print-map-discarded
    --no-print-map-discarded
    Print (or do not print) the list of discarded and garbage collected sections in the link map. Enabled by default.
    --print-map-locals
    --no-print-map-locals
    Print (or do not print) local symbols in the link map. Local symbols will have the text (local) printed before their name, and will be listed after all of the global symbols in a given section. Temporary local symbols (typically those that start with .L) will not be included in the output. Disabled by default.
    -n
    --nmagic
    Turn off page alignment of sections, and disable linking against shared libraries. If the output format supports Unix style magic numbers, mark the output as "NMAGIC".
    -N
    --omagic
    Set the text and data sections to be readable and writable. Also, do not page-align the data segment, and disable linking against shared libraries. If the output format supports Unix style magic numbers, mark the output as "OMAGIC". Note: Although a writable text section is allowed for PE-COFF targets, it does not conform to the format specification published by Microsoft.
    --no-omagic
    This option negates most of the effects of the -N option. It sets the text section to be read-only, and forces the data segment to be page-aligned. Note - this option does not enable linking against shared libraries. Use -Bdynamic for this.
    -o output
    --output=output
    Use output as the name for the program produced by ld; if this option is not specified, the name a.out is used by default. The script command "OUTPUT" can also specify the output file name.

    Note - the linker will delete the output file before it starts to write to it. It will do this even if it turns out that the link cannot be completed due to errors.

    Note - the linker will check to make sure that the output file name does not match the name of any of the input files, but that is all. In particular it will not complain if the output file might overwrite a source file or some other important file. Therefore in build systems it is recommended to use the -o option as the last option on the linker command line. For example consider:

    ld -o $(EXE) $(OBJS)
ld $(OBJS) -o $(EXE)

    If the EXE variable is not defined for some reason, the first version of the linker command could end up deleting one of the object files (the first one in the OBJS list) whereas the second version of the linker command will generate an error message and not delete anything.

    --dependency-file=depfile
    Write a dependency file to depfile. This file contains a rule suitable for "make" describing the output file and all the input files that were read to produce it. The output is similar to the compiler's output with -M -MP. Note that there is no option like the compiler's -MM, to exclude "system files" (which is not a well-specified concept in the linker, unlike "system headers" in the compiler). So the output from --dependency-file is always specific to the exact state of the installation where it was produced, and should not be copied into distributed makefiles without careful editing.
    -O level
    If level is a numeric values greater than zero ld optimizes the output. This might take significantly longer and therefore probably should only be enabled for the final binary. At the moment this option only affects ELF shared library generation. Future releases of the linker may make more use of this option. Also currently there is no difference in the linker's behaviour for different non-zero values of this option. Again this may change with future releases.
    -plugin name
    Involve a plugin in the linking process. The name parameter is the absolute filename of the plugin. Usually this parameter is automatically added by the complier, when using link time optimization, but users can also add their own plugins if they so wish.

    Note that the location of the compiler originated plugins is different from the place where the ar, nm and ranlib programs search for their plugins. In order for those commands to make use of a compiler based plugin it must first be copied into the ${libdir}/bfd-plugins directory. All gcc based linker plugins are backward compatible, so it is sufficient to just copy in the newest one.

    --push-state
    The --push-state allows one to preserve the current state of the flags which govern the input file handling so that they can all be restored with one corresponding --pop-state option.

    The option which are covered are: -Bdynamic, -Bstatic, -dn, -dy, -call_shared, -non_shared, -static, -N, -n, --whole-archive, --no-whole-archive, -r, -Ur, --copy-dt-needed-entries, --no-copy-dt-needed-entries, --as-needed, --no-as-needed, and -a.

    One target for this option are specifications for pkg-config. When used with the --libs option all possibly needed libraries are listed and then possibly linked with all the time. It is better to return something as follows:

    -Wl,--push-state,--as-needed -libone -libtwo -Wl,--pop-state
    --pop-state
    Undoes the effect of --push-state, restores the previous values of the flags governing input file handling.
    -q
    --emit-relocs
    Leave relocation sections and contents in fully linked executables. Post link analysis and optimization tools may need this information in order to perform correct modifications of executables. This results in larger executables.

    This option is currently only supported on ELF platforms.

    --force-dynamic
    Force the output file to have dynamic sections. This option is specific to VxWorks targets.
    -r
    --relocatable
    Generate relocatable output---i.e., generate an output file that can in turn serve as input to ld. This is often called partial linking. As a side effect, in environments that support standard Unix magic numbers, this option also sets the output file's magic number to "OMAGIC". If this option is not specified, an absolute file is produced. When linking C++ programs, this option will not resolve references to constructors; to do that, use -Ur.

    When an input file does not have the same format as the output file, partial linking is only supported if that input file does not contain any relocations. Different output formats can have further restrictions; for example some "a.out"-based formats do not support partial linking with input files in other formats at all.

    When the relocatable output contains both contents which require link-time optimization (LTO) and contents which don't require LTO, a .gnu_object_only section will be created to contain a relocatable object file, as if -r is applied to all relocatable inputs which don't require LTO. When processing a relocatable input with a .gnu_object_only section, the linker will extract the .gnu_object_only section as a separate input.

    Note that since -r groups some sections from different input files together, there may be negative impacts on code size and locality in final executable or shared library.

    This option does the same thing as -i.

    -u symbol
    --undefined=symbol

    Requiere que symbol esté definido en el archivo de salida.     -Ur
    Para programas que no usan constructores o destructores, o para sistemas basados en ELF, esta opción es equivalente a -r: genera una salida relocable, es decir, un archivo de salida que a su vez puede servir como entrada para ld. Para otros binarios, sin embargo, la opción -Ur es similar a -r pero también resuelve referencias a constructores y destructores.

    Para aquellos sistemas donde -r y -Ur se comportan de manera diferente, no funciona usar -Ur en archivos que fueron enlazados con -Ur; una vez que la tabla de constructores ha sido construida, no se puede agregar a ella. Usa -Ur solo para el último enlace parcial, y -r para los otros.

    --orphan-handling=MODE

    "place"

    "discard"
    Todas las secciones huérfanas se descartan, colocándolas en la sección /DISCARD/.
    "warn"
    El enlazador colocará la sección huérfana como para "place" y también emitirá una advertencia.
    "error"
    El enlazador saldrá con un error si se encuentra alguna sección huérfana.

-( archivos -)
--start-group archivos --end-group
Los archivos deben ser una lista de archivos de archivo. Pueden ser nombres de archivo explícitos o opciones -l.

Los archivos de archivo especificados se buscan repetidamente hasta que no se creen nuevas referencias no definidas. Normalmente, un archivo de archivo se busca solo una vez en el orden en que se especifica en la línea de comandos. Si un símbolo en ese archivo de archivo es necesario para resolver un símbolo no definido al que se hace referencia en un objeto en un archivo de archivo que aparece más tarde en la línea de comandos, el enlazador no podría resolver esa referencia. Al agrupar los archivos de archivo, todos ellos se buscarán repetidamente hasta que se resuelvan todas las referencias posibles.

El uso de esta opción tiene un costo de rendimiento significativo. Es mejor usarla solo cuando hay referencias circulares inevitables entre dos o más archivos de archivo.

Esta opción afecta a las etiquetas DT_NEEDED ELF para bibliotecas dinámicas mencionadas en la línea de comandos después de la opción --as-needed. -rpath=dir
Añade un directorio a la ruta de búsqueda de bibliotecas en tiempo de ejecución. Esto se utiliza al enlazar un ejecutable ELF con objetos compartidos. La búsqueda de -rpath de esta manera solo es compatible con enlazadores nativos y enlazadores cruzados que hayan sido configurados con la opción --with-sysroot.

las opciones -L. Si se utiliza una opción -rpath, la ruta de búsqueda en tiempo de ejecución se formará exclusivamente utilizando las opciones -rpath, ignorando las opciones -L. -rpath-link=dir
Al utilizar ELF o SunOS, una biblioteca compartida puede requerir otra. Esto ocurre cuando un enlace "ld -shared" incluye una biblioteca compartida como uno de los archivos de entrada.

Cuando el enlazador encuentra dicha dependencia al realizar un enlace no compartido y no relocable, intentará automáticamente localizar la biblioteca compartida requerida e incluirla en el enlace, si no está incluida explícitamente. En tal caso, se buscan varios directorios como se describe a continuación. La opción -rpath-link especifica el primer conjunto de directorios a buscar. Esta opción puede especificar una secuencia de nombres de directorios, ya sea proporcionando una lista de nombres separados por dos puntos, o apareciendo varias veces.

La forma alternativa de estos tokens, ${ORIGIN} y ${LIB}, también se puede utilizar. El token $PLATFORM no es compatible.

La opción --rpath-link debe usarse con precaución, ya que anula la ruta de búsqueda que puede haber sido compilada en una biblioteca compartida. En tal caso, es posible utilizar involuntariamente una ruta de búsqueda diferente a la que el enlazador en tiempo de ejecución habría utilizado.

Cualquier directorio especificado por las opciones -rpath-link.

Cualquier directorio especificado por las opciones -rpath. La búsqueda de -rpath de esta manera solo es compatible con enlazadores nativos y enlazadores cruzados que se han configurado con la opción --with-sysroot.

Para un enlazador nativo en un sistema FreeBSD, cualquier directorio especificado por la macro "_PATH_ELF_HINTS" definida en el archivo de cabecera elf-hints.h.

Cualquier directorio especificado por un comando "SEARCH_DIR" en un script de enlazador proporcionado en la línea de comandos, incluidos los scripts especificados por -T (pero no -dT).

--section-ordering-file=script
Esta opción se utiliza para aumentar el script de enlazador actual con un mapeo adicional de secciones de entrada a secciones de salida. Este archivo debe utilizar la misma sintaxis para "SECTIONS" que se utiliza en los scripts de enlazador normales, pero no debe hacer nada más que colocar las secciones de entrada en secciones de salida. @pxref{SECTIONS}

Una segunda restricción en el script de ordenación de secciones es que solo puede hacer referencia a secciones de salida que ya estén definidas por el script de enlazador que se esté utilizando actualmente. (Es decir, el script de enlazador predeterminado o un script especificado en la línea de comandos). Sin embargo, el beneficio del script de ordenación de secciones es que las secciones de entrada se mapean al inicio de las secciones de salida, de modo que puedan garantizar el orden de las secciones en la sección de salida. Por ejemplo, imagine que el script de enlazador predeterminado se ve así:

SECTIONS {
  .text : { *(.text.hot) ; *(.text .text.*) }
  .data : { *(.data.big) ; *(.data .data.*) }
  }

Luego, si se utiliza un archivo de ordenación de secciones como este:

.text : { *(.text.first) ; *(.text.z*) }
.data : { foo.o(.data.first) ; *(.data.small) }

Esto sería equivalente a un script de enlazador como este:

SECTIONS {
  .text : { *(.text.first) ; *(.text.z*) ; *(.text.hot) ; *(.text .text.*) }
  .data : { foo.o(.data.first) ; *(.data.small) ; *(.data.big) ; *(.data .data.*) }
  }

La ventaja del archivo de ordenación de secciones es que se puede utilizar para ordenar aquellas secciones que son importantes para el usuario sin tener que preocuparse por ninguna otra sección, regiones de memoria o cualquier otra cosa.

Tenga en cuenta que esto no funcionará con formatos de archivo de objeto que no admitan secciones arbitrarias. Por ejemplo, en SunOS, ld combina entradas duplicadas en la tabla de cadenas de símbolos. --warn-multiple-gp
Advertir si se requieren múltiples valores de puntero global en el archivo de salida. Esto solo es significativo para ciertos procesadores, como Alpha. Dado que el desplazamiento en el modo relativo a un registro base es fijo y relativamente pequeño (por ejemplo, 16 bits), esto limita el tamaño máximo del pool de constantes. Esto se puede usar para proporcionar una envoltura para una función del sistema. La función envolvente debe llamarse "__wrap_simbolo". Si desea llamar a la función del sistema, debe llamar a "__real_simbolo".

Aquí hay un ejemplo trivial:

void *
__wrap_malloc (size_t c)
{
  printf ("malloc llamado con %zu\n", c);
  return __real_malloc (c);
}

Si enlazas otro código con este archivo usando --wrap malloc, entonces todas las llamadas a "malloc" llamarán a la función "__wrap_malloc" en su lugar. La llamada a "__real_malloc" en "__wrap_malloc" llamará a la función real "malloc".

Puede que desees proporcionar una función "__real_malloc" también, de modo que los enlaces sin la opción --wrap tengan éxito. Si haces esto, no debes poner la definición de "__real_malloc" en el mismo archivo que "__wrap_malloc"; si lo haces, el ensamblador puede resolver la llamada antes de que el enlazador tenga la oportunidad de envolverla a "malloc".

Solo las referencias no definidas son reemplazadas por el enlazador. Por lo tanto, las referencias internas de la unidad de traducción a simbolo no se resuelven como "__wrap_simbolo". En el siguiente ejemplo, la llamada a "f" en "g" no se resuelve como "__wrap_f".

int
f (void)
{
  return 123;
}

int
g (void)
{
  return f();
}

DESCRIPCIÓN

El objetivo de ld es combinar una serie de archivos objeto y bibliotecas en un único archivo ejecutable, un archivo objeto, una biblioteca compartida o una biblioteca estática.

Las opciones que no se refieren a un objetivo específico se aplican a ld, ld.bfd y gold. Las opciones que solo se aplican a uno de los vinculadores están documentadas al final de la sección.

OPCIONES COMUNES

--compress-debug-sections=[none|zlib-gnu|zlib-gabi|zstd]

--compress-debug-sections=zlib

--compress-debug-sections=zlib-gnu

--compress-debug-sections=zstd

--compress-debug-sections=zlib-gnu
--compress-debug-sections=zstd
En plataformas ELF, estas opciones controlan cómo se comprimen las secciones de depuración DWARF usando zlib.

--compress-debug-sections=none no comprime las secciones de depuración DWARF. --compress-debug-sections=zlib-gnu comprime las secciones de depuración DWARF y las renombra para que comiencen con .zdebug en lugar de .debug. --compress-debug-sections=zlib-gabi también comprime las secciones de depuración DWARF, pero en lugar de renombrarlas, establece la bandera SHF_COMPRESSED en los encabezados de las secciones.

La opción --compress-debug-sections=zlib es un alias para --compress-debug-sections=zlib-gabi.

--compress-debug-sections=zstd comprime las secciones de depuración DWARF usando zstd.

Tenga en cuenta que esta opción anula cualquier compresión en las secciones de depuración de entrada, por lo que si un binario se enlaza con --compress-debug-sections=none, por ejemplo, las secciones de depuración comprimidas en los archivos de entrada se descomprimirán antes de copiarse en el binario de salida.

El comportamiento predeterminado de compresión varía según el destino involucrado y las opciones de configuración utilizadas para compilar la cadena de herramientas. El valor predeterminado se puede determinar examinando la salida de la opción --help del vinculador.

--reduce-memory-overheads
Esta opción reduce los requisitos de memoria en tiempo de ejecución de ld, a expensas de la velocidad de enlazado. Se introdujo para seleccionar el antiguo algoritmo O(n^2) para la generación del archivo de mapa de enlace, en lugar del nuevo algoritmo O(n) que utiliza aproximadamente un 40% más de memoria para el almacenamiento de símbolos.

Otro efecto del cambio es establecer el tamaño de la tabla hash predeterminada en 1021, lo que nuevamente ahorra memoria a costa de alargar el tiempo de ejecución del vinculador. Sin embargo, esto no se hace si se ha utilizado el cambio --hash-size.

El cambio --reduce-memory-overheads también puede utilizarse para habilitar otras compensaciones en versiones futuras del vinculador.

--max-cache-size=tamaño
ld normalmente almacena en caché la información de reubicación y las tablas de símbolos de los archivos de entrada en memoria con tamaño ilimitado. Esta opción establece el tamaño máximo de la caché en tamaño.
--build-id
--build-id=estilo
Solicita la creación de una sección de nota ELF .note.gnu.build-id o una sección COFF .buildid. El contenido de la nota son bits únicos que identifican este archivo enlazado. estilo puede ser uuid para usar 128 bits aleatorios; sha1 para usar un hash SHA1 de 160 bits, md5 para usar un hash MD5 de 128 bits, o xx para usar un XXHASH de 128 bits en las partes normativas del contenido de salida; o 0xcadenahex para usar una cadena de bits elegida especificada como un número par de dígitos hexadecimales (los caracteres - y : entre pares de dígitos se ignoran). Si se omite estilo, se usa sha1.

Los estilos md5, sha1 y xx producen un identificador que siempre es el mismo en un archivo de salida idéntico, pero que es casi seguro que es único entre todos los archivos de salida no idénticos. No está pensado para ser comparado como una suma de verificación del contenido del archivo. Un archivo enlazado puede ser modificado posteriormente por otras herramientas, pero la cadena de bits del ID de construcción que identifica el archivo enlazado original no cambia.

Pasar none como estilo deshabilita la configuración de cualquier opción --build-id anterior en la línea de comandos.

--package-metadata=JSON
Solicita la creación de una sección de nota ELF .note.package. El contenido de la nota está en formato JSON, según la especificación de metadatos del paquete. Para más información, consulte: https://systemd.io/ELF_PACKAGE_METADATA/ El argumento JSON admite la codificación por porcentaje y la codificación siguiente de %[cadena] (donde cadena se refiere al nombre en las Referencias de Caracteres Nombrados de HTML): %[coma] para ,, %[lbrace] para {, %[quot] para ", %[rbrace] para }, y %[space] para el carácter de espacio. Si falta el argumento JSON/ está vacío, esto deshabilitará la creación de la nota de metadatos, si se había habilitado mediante una ocurrencia anterior de la opción --package-metadata. Si el vinculador se compiló con libjansson, la cadena JSON se validará.

El vinculador i386 PE soporta la opción -shared, que hace que la salida sea una biblioteca enlazada dinámicamente (DLL) en lugar de un ejecutable normal. Debe nombrar la salida *.dll cuando utilice esta opción. Además, el vinculador soporta completamente los archivos *.def estándar, que se pueden especificar en la línea de comandos del vinculador como un archivo objeto (de hecho, debe preceder a los archivos que exporta símbolos, para asegurar que se enlacen, al igual que un archivo objeto normal).

Además de las opciones comunes a todos los destinos, el vinculador i386 PE soporta opciones de línea de comandos adicionales que son específicas del destino i386 PE. Las opciones que toman valores pueden separarse de sus valores por un espacio o un signo igual.

--add-stdcall-alias

Utilice archivo como nombre de un archivo en el que guardar las direcciones base de todas las reubicaciones necesarias para generar DLLs con dlltool. [Esta es una opción específica de i386 PE]
--dll
Crea una DLL en lugar de un ejecutable normal. También puede usar -shared o especificar una LIBRARY en un archivo .def dado. [Esta opción es específica del puerto del vinculador dirigido a i386 PE]
--enable-long-section-names

--no-direct-access
Do not use direct access to variables. The default behavior is to use direct access. If you are using a modern version of Windows or Cygwin, this option may solve problems you encounter with DLLs. Specifically, it addresses the problem of "direct address with constant offset" for DATA imports from DLLs.

When choosing between the various methods for resolving the 'direct address with constant offset' problem, you should consider typical real-world usage:

Original:

--foo.h
extern int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  printf("%d\n",arr[1]);
}

Solution 1:

--foo.h
extern int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  /* This workaround is for win32 and cygwin; do not "optimize" */
  volatile int *parr = arr;
  printf("%d\n",parr[1]);
}

Solution 2:

--foo.h
/* Note: auto-export is assumed (no __declspec(dllexport)) */
#if (defined(_WIN32) || defined(__CYGWIN__)) && \
  !(defined(FOO_BUILD_DLL) || defined(FOO_STATIC))
#define FOO_IMPORT __declspec(dllimport)
#else
#define FOO_IMPORT
#endif
extern FOO_IMPORT int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  printf("%d\n",arr[1]);
}
