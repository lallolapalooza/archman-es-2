NOMBRE

gprof - muestra datos de perfil de llamada de gráfico

SINOPSIS

gprof [ -[abcDhilLrsTvwxyz] ] [ -[ABCeEfFJnNOpPqQRStZ][nombre] ]
[ -I directorios ] [ -d[num] ] [ -k desde/hacia ]
[ -m conteo-minimo ] [ -R archivo-mapa ] [ -t longitud-tabla ]
[ --[no-]fuente-anotada[=nombre] ]
[ --[no-]conteos-ejecucion[=nombre] ]
[ --[no-]perfil-plano[=nombre] ] [ --[no-]grafico[=nombre] ]
[ --[no-]tiempo=nombre] [ --todas-lineas ] [ --breve ]
[ --debug[=nivel] ] [ --ordenacion-funciones ]
[ --ordenacion-archivos archivo-mapa ] [ --directorio-ruta=directorios ]
[ --mostrar-funciones-no-usadas ] [ --formato-archivo=nombre ]
[ --info-archivo ] [ --ayuda ] [ --linea ] [ --nombres-archivos-inline ]
[ --conteo-minimo=n ] [ --no-estatico ] [ --imprimir-ruta ]
[ --archivos-separados ] [ --grafico-llamadas-estatico ] [ --suma ]
[ --longitud-tabla=longitud ] [ --tradicional ] [ --version ]
[ --ancho=n ] [ --ignorar-no-funciones ]
[ --demangle[=ESTILO] ] [ --no-demangle ]
[--tabla-simbolos-externa=nombre]
[ archivo-imagen ] [ archivo-perfil ... ]

DESCRIPCIÓN

"gprof" produce un perfil de ejecución de programas C, Pascal o Fortran77. El efecto de las rutinas llamadas se incorpora en el perfil de cada llamador. Los datos del perfil se toman del archivo de perfil de gráfico de llamadas (gmon.out por defecto), que se crea con programas compilados con la opción -pg de "cc", "pc", y "f77". La opción -pg también enlaza versiones de las rutinas de la biblioteca compiladas para perfilado. "Gprof" lee el archivo objeto dado (el valor predeterminado es "a.out") y establece la relación entre su tabla de símbolos y el perfil de gráfico de llamadas de gmon.out. Si se especifica más de un archivo de perfil, la salida de "gprof" muestra la suma de la información del perfil en los archivos de perfil dados.

"Gprof" calcula la cantidad de tiempo gastado en cada rutina. Luego, estos tiempos se propagan a lo largo de los bordes del gráfico de llamadas. Se descubren ciclos y las llamadas a un ciclo se hacen para compartir el tiempo del ciclo.

Hay varias formas de salida disponibles del análisis.

El perfil plano muestra cuánto tiempo pasó tu programa en cada función y cuántas veces se llamó a esa función. Si simplemente quieres saber qué funciones consumen la mayor parte del tiempo de CPU, se indica concisamente aquí.

El gráfico de llamadas muestra, para cada función, qué funciones la llamaron, qué otras funciones llamó y cuántas veces. También hay una estimación de cuánto tiempo se gastó en las subrutinas de cada función. Esto puede sugerir lugares donde podrías intentar eliminar llamadas a funciones que consumen mucho tiempo.

La lista de código fuente anotado es una copia del código fuente del programa, etiquetada con el número de veces que se ejecutó cada línea del programa.

OPCIONES

Estas opciones especifican cuál de varios formatos de salida "gprof" debe producir.

Muchas de estas opciones toman un symspec opcional para especificar funciones a incluir o excluir. Estas opciones se pueden especificar múltiples veces, con diferentes symspecs, para incluir o excluir conjuntos de símbolos.

La especificación de cualquiera de estas opciones anula el valor predeterminado (-p -q), que imprime un perfil plano y un análisis de gráfico de llamadas para todas las funciones.

"-A[symspec]"
"--fuente-anotada[=symspec]"
La opción -A hace que "gprof" imprima código fuente anotado. Si se especifica symspec, imprime la salida solo para los símbolos coincidentes.
"-b"
"--breve"
Si se proporciona la opción -b, "gprof" no imprime los textos explicativos detallados que intentan explicar el significado de todos los campos en las tablas. Esto es útil si tienes la intención de imprimir la salida, o estás cansado de ver los textos explicativos.
"-B"
La opción -B hace que "gprof" imprima el análisis del gráfico de llamadas.
"-C[symspec]"
"--conteos-ejecucion[=symspec]"
La opción -C hace que "gprof" imprima un recuento de funciones y el número de veces que se llamó a cada una. Si se especifica symspec, imprime el recuento solo para los símbolos coincidentes.

Si el archivo de datos de perfil contiene registros de conteo de bloques básicos, la especificación de la opción -l, junto con -C, hará que los conteos de ejecución de bloques básicos se recuenten y se muestren.

"-i"
"--info-archivo"
La opción -i hace que "gprof" muestre información de resumen sobre el archivo(s) de datos de perfil y luego salga. Se muestra el número de registros de histograma, gráfico de llamadas y conteo de bloques básicos.
"-I directorios"
"--directorio-ruta=directorios"
La opción -I especifica una lista de directorios de búsqueda en los que encontrar archivos fuente. La variable de entorno GPROF_PATH también se puede usar para transmitir esta información. Se utiliza principalmente para la salida de código fuente anotado.
"-J[symspec]"
"--no-fuente-anotada[=symspec]"
La opción -J hace que "gprof" no imprima código fuente anotado. Si se especifica symspec, "gprof" imprime código fuente anotado, pero excluye los símbolos coincidentes.
"-L"
"--imprimir-ruta"
Normalmente, los nombres de archivo de origen se imprimen suprimiendo el componente de ruta. La opción -L hace que "gprof" imprima la ruta completa de los nombres de archivo de origen, que se determina a partir de la información de depuración simbólica en el archivo imagen y es relativa al directorio en el que se invocó el compilador.
"-p[symspec]"
"--perfil-plano[=symspec]"
La opción -p hace que "gprof" imprima un perfil plano. Si se especifica symspec, imprime el perfil plano solo para los símbolos coincidentes.
"-P[symspec]"
"--no-perfil-plano[=symspec]"
La opción -P hace que "gprof" suprima la impresión de un perfil plano. Si se especifica symspec, "gprof" imprime un perfil plano, pero excluye los símbolos coincidentes.
"-q[symspec]"
"--grafico[=symspec]"
La opción -q hace que "gprof" imprima el análisis del gráfico de llamadas. Si se especifica symspec, imprime el gráfico de llamadas solo para los símbolos coincidentes y sus hijos.
"-Q[symspec]"
"--no-grafico[=symspec]"
La opción -Q hace que "gprof" suprima la impresión del gráfico de llamadas. Si se especifica symspec, "gprof" imprime un gráfico de llamadas, pero excluye los símbolos coincidentes.
"-t"
"--longitud-tabla=num"
La opción -t hace que se listen las num líneas de código fuente más activas en cada archivo de código fuente cuando la anotación del código fuente está habilitada. El valor predeterminado es 10.
"-y"
"--archivos-separados"
Esta opción solo afecta la salida de código fuente anotado. Normalmente, "gprof" imprime archivos de código fuente anotado en la salida estándar. Si se especifica esta opción, el código fuente anotado para un archivo llamado ruta/nombrearchivo se genera en el archivo nombrearchivo-ann. NAME

gprof - display profiling information

SYNOPSIS

gprof [-b] [-c] [-d[num]] [-e function_name] [-E function_name] [-f function_name] [-F function_name] [-l] [-L] [-m num] [-o outfile] [-q] [-r] [-R map_file] [-s] [-S filename] [-T] [-v] [-w width] [-x] [-z] [-Z] [--demangle[=style]] [--no-demangle] [--file-ordering=map_file] [--function-ordering] [--help] [--inline-file-names] [--min-count=num] [--no-static] [--time=symspec] [--no-time=symspec] [--external-symbol-table=filename] [--version] [--width=width] [--all-lines] [--debug[=num]] [--static-call-graph] [--ignore-non-functions] [--display-unused-functions] [--sum] [--file-format=name] [gmon.parse ...]

DESCRIPTION

The gprof utility analyzes program execution time and the call graph of a program run. It uses information gathered by the runtime profiling library, typically compiled into the program using the -pg flag with cc or gcc.

The profiling data is typically written to a file named gmon.out in the current directory when the program terminates normally. gprof reads one or more of these files (specified as arguments on the command line) and produces a report.

The report consists of three sections:

  • A flat profile, listing each function, the number of times it was called, and the total amount of time spent in it.
  • A detailed call graph, showing how functions call each other, and how much time is spent in each function and its descendants.
  • A function-by-function index.

The profiling data file gmon.out contains a profile counter sample, a call graph arc sample, and a program counter sample. gprof uses the profile counter sample to generate the flat profile, and the call graph sample to generate the call graph. The program counter sample is used to compute the flat profile.

The following options are available:

Profile Output Control

"-b"
"--no-graph"
Suppresses the printing of the call graph.
"-e symspec"
"--exclude=symspec"
Do not print information about functions matching symspec. This option affects both the flat profile and the call graph. This option can be specified more than once.
"-f symspec"
"--flat-exclude=symspec"
Do not print information about functions matching symspec in the flat profile. This option can be specified more than once.
"-F symspec"
"--graph-exclude=symspec"
Do not print information about functions matching symspec in the call graph. This option can be specified more than once.
"-L"
"--show-load-libraries"
Print the load library names along with the function names. This is only useful if the program was linked with the -pg flag and the program calls routines in a shared library.
"-o outfile"
"--outfile=outfile"
Use the specified outfile instead of gmon.out.
"-q"
"--brief"
Do not print a tally of functions and the number of times each was called. If symspec is specified, print tally, but exclude matching symbols.
"-r"
"--function-ordering"
The --function-ordering option causes gprof to print a suggested function ordering for the program based on profiling data. This option suggests an ordering which may improve paging, tlb and cache behavior for the program on systems which support arbitrary ordering of functions in an executable.

The exact details of how to force the linker to place functions in a particular order is system dependent and out of the scope of this manual.

"-R map_file"
"--file-ordering map_file"
The --file-ordering option causes gprof to print a suggested .o link line ordering for the program based on profiling data. This option suggests an ordering which may improve paging, tlb and cache behavior for the program on systems which do not support arbitrary ordering of functions in an executable.

Use of the -a argument is highly recommended with this option.

The map_file argument is a pathname to a file which provides function name to object file mappings. The format of the file is similar to the output of the program nm.

c-parse.o:00000000 T yyparse
c-parse.o:00000004 C yyerrflag
c-lang.o:00000000 T maybe_objc_method_name
c-lang.o:00000000 T print_lang_statistics
c-lang.o:00000000 T recognize_objc_keyword
c-decl.o:00000000 T print_lang_identifier
c-decl.o:00000000 T print_lang_type
...

To create a map_file with GNU nm, type a command like nm --extern-only --defined-only -v --print-file-name program-name.

"-T"
"--traditional"
The -T option causes gprof to print its output in "traditional" BSD style.
"-w width"
"--width=width"
Sets width of output lines to width. Currently only used when printing the function index at the bottom of the call graph.
"-x"
"--all-lines"
This option affects annotated source output only. By default, only the lines at the beginning of a basic-block are annotated. If this option is specified, every line in a basic-block is annotated by repeating the annotation for the first line. This behavior is similar to tcov's -a.
"--demangle[=style]"
"--no-demangle"
These options control whether C++ symbol names should be demangled when printing output. The default is to demangle symbols. The --no-demangle option may be used to turn off demangling. Different compilers have different mangling styles. The optional demangling style argument can be used to choose an appropriate demangling style for your compiler.

Analysis Options

"-a"
"--no-static"
The -a option causes gprof to suppress the printing of statically declared (private) functions. (These are functions whose names are not listed as global, and which are not visible outside the file/function/block where they were defined.) Time spent in these functions, calls to/from them, etc., will all be attributed to the function that was loaded directly before it in the executable file. This option affects both the flat profile and the call graph.
"-c"
"--static-call-graph"
The -c option causes the call graph of the program to be augmented by a heuristic which examines the text space of the object file and identifies function calls in the binary machine code. Since normal call graph records are only generated when functions are entered, this option identifies children that could have been called, but never were. Calls to functions that were not compiled with profiling enabled are also identified, but only if symbol table entries are present for them. Calls to dynamic library routines are typically not found by this option. Parents or children identified via this heuristic are indicated in the call graph with call counts of 0.
"-D"
"--ignore-non-functions"
The -D option causes gprof to ignore symbols which are not known to be functions. This option will give more accurate profile data on systems where it is supported (Solaris and HPUX for example).
"-k from/to"
The -k option allows you to delete from the call graph any arcs from symbols matching symspec from to those matching symspec to.
"-l"
"--line"
The -l option enables line-by-line profiling, which causes histogram hits to be charged to individual source code lines, instead of functions. This feature only works with programs compiled by older versions of the gcc compiler. Newer versions of gcc are designed to work with the gcov tool instead.

If the program was compiled with basic-block counting enabled, this option will also identify how many times each line of code was executed. While line-by-line profiling can help isolate where in a large function a program is spending its time, it also significantly increases the running time of gprof, and magnifies statistical inaccuracies.

"--inline-file-names"
This option causes gprof to print the source file after each symbol in both the flat profile and the call graph. The full path to the file is printed if used with the -L option.
"-m num"
"--min-count=num"
This option affects execution count output only. Symbols that are executed less than num times are suppressed.
"-nsymspec"
"--time=symspec"
The -n option causes gprof, in its call graph analysis, to only propagate times for symbols matching symspec.
"-Nsymspec"
"--no-time=symspec"
The -n option causes gprof, in its call graph analysis, not to propagate times for symbols matching symspec.
"-Sfilename"
"--external-symbol-table=filename"
The -S option causes gprof to read an external symbol table file, such as /proc/kallsyms, rather than read the symbol table from the given object file (the default is a.out). This is useful for profiling kernel modules.
"-z"
"--display-unused-functions"
If you give the -z option, gprof will mention all functions in the flat profile, even those that were never called, and that had no time spent in them. This is useful in conjunction with the -c option for discovering which routines were never called.

Miscellaneous Options

"-d[num]"
"--debug[=num]"
The -d num option specifies debugging options. If num is not specified, enable all debugging.
"-h"
"--help"
The -h option prints command line usage.
"-Oname"
"--file-format=name"
Selects the format of the profile data files. Recognized formats are auto (the default), bsd, 4.4bsd, magic, and prof (not yet supported).
"-s"
"--sum"
The -s option causes gprof to summarize the information in the profile data files it read in, and write out a profile data file called gmon.sum, which contains all the information from the profile data files that gprof read in. The file gmon.sum may be one of the specified input files; the effect of this is to merge the data in the other input files into gmon.sum.

Eventually you can run gprof again without -s to analyze the cumulative data in the file gmon.sum.

"-v"
"--version"
The -v flag causes gprof to print the current version number, and then exit.

Deprecated Options

These options have been replaced with newer versions that use symspecs.

"-e function_name"
The -e function option tells gprof to not print information about the function function_name (and its children...) in the call graph. The function will still be listed as a child of any functions that call it, but its index number will be shown as [not printed]. More than one -e option may be given; only one function_name may be indicated with each -e option.
"-E function_name"
The "-efunction" option works like the "-e" option, but time spent in the function (and children who were not called from anywhere else), will not be used to compute the percentages-of-time for the call graph. More than one -E option may be given; only one function_name may be indicated with each -E option.
"-f function_name"
The -f function option causes gprof
"Li">"gprof" para limitar el grafo de llamadas a la función nombre_funcion y sus descendientes (y los descendientes de sus descendientes...). Se pueden dar varias opciones -f; solo se puede indicar un nombre_funcion con cada opción -f.
"-F nombre_funcion"
La opción -F funcion funciona como la opción "-f", pero solo el tiempo empleado en la función y sus descendientes (y los descendientes de sus descendientes...) se utilizará para determinar el tiempo total y los porcentajes de tiempo del grafo de llamadas. Se pueden dar varias opciones -F; solo se puede indicar un nombre_funcion con cada opción -F. La opción -F anula la opción -E.

ERRORES

Se muestra la granularidad del muestreo, pero sigue siendo, en el mejor de los casos, estadística. Suponemos que el tiempo de cada ejecución de una función puede expresarse como el tiempo total de la función dividido por el número de veces que se llama a la función. Por lo tanto, el tiempo propagado a lo largo de los arcos del grafo de llamadas hacia los padres de la función es directamente proporcional al número de veces que se recorre ese arco.

Los padres que no estén perfilados por sí mismos tendrán el tiempo de sus hijos perfilados propagado a ellos, pero aparecerán como invocados espontáneamente en el listado del grafo de llamadas y no propagarán su tiempo más allá. De manera similar, los captadores de señales, aunque estén perfilados, aparecerán como espontáneos (aunque por razones más oscuras). Los hijos perfilados de los captadores de señales deberían tener sus tiempos propagados correctamente, a menos que el captador de señales fuera invocado durante la ejecución de la rutina de perfilado, en cuyo caso todo está perdido.

El programa perfilado debe llamar a "exit"(2) o retornar normalmente para que la información de perfilado se guarde en el archivo gmon.out.
