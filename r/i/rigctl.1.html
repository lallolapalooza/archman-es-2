RIGCTL(1) Utilidades de Hamlib RIGCTL(1)

NOMBRE

rigctl - controla transceptores y receptores de radio

SINOPSIS

rigctl [-hiIlLnouV] [-m id] [-r dispositivo] [-p dispositivo] [-d dispositivo] [-P tipo] [-D tipo] [-s velocidad] [-c id] [-t caracter] [-C parm=val] -Y [-v[-Z]] [comando|-]

DESCRIPCIÓN

Controla transceptores y receptores de radio. rigctl acepta comandos de la línea de comandos, así como en modo interactivo si no se proporcionan en la línea de comandos.

Ten en cuenta que Hamlib es software de nivel BETA. Aunque muchas bibliotecas de backend carecen de soporte completo para radios, las funciones básicas suelen estar bien soportadas.

Por favor, reporta errores y proporciona comentarios en la dirección de correo electrónico indicada en la sección ERRORES más abajo. Se aceptan parches y mejoras de código enviados a la misma dirección.

OPCIONES

Este programa sigue la sintaxis habitual de línea de comandos de GNU. Las opciones cortas que toman un argumento pueden tener el valor inmediatamente después o separado por un espacio. Las opciones largas que empiezan con dos guiones (‘-’) requieren un ‘=’ entre la opción y cualquier argumento.

Aquí tienes un resumen de las opciones soportadas:

-m, --modelo=id
Selecciona el número de modelo de radio. El valor por defecto es una radio dummy.
Ver lista de modelos (usa “rigctl -l”).
Nota: rigctl (o software de terceros que usa la API C) utilizará el modelo de radio 2 para NET rigctl (comunicándose con rigctld).
-r, --archivo-radio=dispositivo
Usa dispositivo como el nombre del archivo del puerto conectado a la radio.
Típicamente /dev/ttyS0, /dev/ttyS1, /dev/ttyUSB0, etc. en Linux, COM1, COM2, etc. en MS Windows. Las variantes BSD y Mac OS/X tienen sus propias designaciones. Consulta la documentación de tu sistema.
Puede ser una dirección de red:puerto, p. ej., 127.0.0.1:12345
La cadena especial “uh-rig” puede ser dada para habilitar el soporte de dispositivos micro-ham.
-p, --archivo-ptt=dispositivo
Usa dispositivo como el nombre del archivo del dispositivo Push-To-Talk utilizando un archivo de dispositivo como se describe arriba.
-d, --archivo-dcd=dispositivo
Usa dispositivo como el nombre del archivo del dispositivo Data Carrier Detect utilizando un archivo de dispositivo como se describe arriba.
-P, --tipo-ptt=tipo
Usa el tipo de dispositivo Push-To-Talk.
Los tipos soportados son ‘RIG’ (comando CAT), ‘DTR’, ‘RTS’, ‘PARALLEL’, ‘CM108’, ‘GPIO’, ‘GPION’, ‘NONE’, reemplazando el tipo PTT definido en el backend de la radio.
Algunos efectos secundarios de este comando son que cuando el tipo se establece a DTR, el estado PTT leído proviene del frontend de Hamlib, no se lee de la radio. Cuando se establece a NONE, el estado PTT no puede ser leído o establecido, incluso si el backend de la radio soporta leer/establecer el estado PTT de la radio.
-D, --tipo-dcd=tipo
Usa el tipo de dispositivo Data Carrier Detect.
Los tipos soportados son ‘RIG’ (comando CAT), ‘DSR’, ‘CTS’, ‘CD’, ‘PARALLEL’, ‘CM108’, ‘GPIO’, ‘GPION’, ‘NONE’.
-s, --velocidad-serial=velocidad
Establece la velocidad serial a velocidad baudios.
Usa la velocidad serial máxima de las capacidades del backend de la radio (establecida por -m arriba) como valor por defecto.
-c, --direccion-civ=id
Usa id como la dirección CI-V para comunicarse con la radio.
Solo útil para radios Icom y algunas Ten-Tec.
Nota: El id está en notación decimal, a menos que esté precedido por 0x, en cuyo caso es hexadecimal.
-t, --terminador-comando-envio=caracter
Cambia el caracter de terminación para el protocolo de texto al usar el comando enviar_comando.
El valor por defecto es ASCII CR (‘0x0D’). Los caracteres no imprimibles ASCII pueden darse como el número ASCII en formato hexadecimal precedido por “0x”. Puedes pasar una cadena vacía para no tener caracter de terminación. La cadena “-1” indica a rigctl que cambie a protocolo binario. Ver el comando enviar_comando para más explicación.
Por ejemplo, para especificar un terminador de comando para comandos de texto estilo Kenwood, pasa “-t ';'” a rigctl. Ver EJEMPLO abajo.
-L, --mostrar-config
Lista todos los parámetros de configuración para la radio definida con -m arriba. Saldrá si no se proporciona -r. Nota que la radio dummy no tiene parámetros seriales.
-C, --establecer-config=parm=val[,parm=val]
Establece parámetro(s) de configuración. Algunos comunes son: 
async:True habilita la transferencia de datos asíncrona para backends que la soportan. Esto permite el uso de datos de transcepción y espectro.
auto_power_on:True habilita que las radios compatibles se enciendan al abrir
auto_power_off:True habilita que las radios compatibles se apaguen al cerrar
auto_disable_screensaver:True habilita que las radios compatibles tengan su salvapantallas deshabilitado al abrir
dcd_type:Sobrescribe el tipo de interfaz Data Carrier Detect (o squelch)
dcd_pathname:Nombre de la ruta al archivo del dispositivo Data Carrier Detect (o squelch)
disable_yaesu_bandselect:True deshabilita la selección automática de banda al cambiar de banda para radios Yaesu
dtr_state:ON enciende DTR, OFF lo apaga, Unset lo deshabilita
lo_freq:Frecuencia a sumar a la frecuencia del VFO para usar con un transvertor
post_write_delay:Retraso en ms entre cada comando enviado
ptt_share:True habilita que el puerto ptt sea compartido con otras aplicaciones
ptt_type:Sobrescribe el tipo de interfaz Push-To-Talk
ptt_pathname:Nombre de la ruta al archivo del dispositivo Push-To-Talk
ptt_bitnum:Número de bit GPIO de Push-To-Talk
retry:Número máximo de reintentos
rts_state:ON enciende RTS, OFF lo apaga, Unset lo deshabilita
twiddle_timeout:Para operaciones de satélite cuando VFOB se modifica, pausará los comandos de VFOB hasta el tiempo de espera
twiddle_rit:Suprime get_freq en VFOB para satélites con ajuste RIT
timeout:Tiempo de espera en ms
write_delay:Retraso en ms entre cada byte enviado
tuner_control_pathname:Nombre de la ruta a un script/programa para controlar un sintonizador con 1 argumento de 0/1 para Apagado/Encendido del Sintonizador

Usa la opción -L arriba para una lista de parámetros de configuración para un número de modelo dado.
-u, --volcar-capacidades
Vuelca las capacidades para la radio definida con -m arriba y sale.
-l, --listar
Lista todos los números de modelo definidos en Hamlib y sale.
La lista está ordenada por número de modelo.
Nota: En Linux, la lista puede ser desplazada hacia atrás usando Shift-PageUp/Shift-PageDown, o usando las barras de desplazamiento de un terminal virtual en X o la ventana de cmd en Windows. La salida puede ser redirigida a more(1) o less(1), p. ej., “rigctl -l | more”.
-o, --vfo
Habilitar el modo VFO.
Se requerirá un argumento VFO adicional antes de cada comando apropiado (excepto set_vfo). De lo contrario, se usa 'currVFO' cuando esta opción no está configurada y no se usa un argumento VFO adicional.
-n, --no-restore-ai
Al salir, rigctl restaura el estado de la información automática (AI) en el equipo controlado.
Si esto no se desea, por ejemplo, si está usando rigctl para activar o desactivar el modo AI, pase esta opción.
-i, --read-history
Leer el historial de comandos y argumentos guardado previamente de un archivo (predeterminado $HOME/.rigctl_history) para la sesión actual.
Disponible cuando rigctl está compilado con soporte Readline (ver READLINE abajo).
Nota: Para leer un archivo de historial almacenado en otro directorio, configure la variable de entorno RIGCTL_HIST_DIR, por ejemplo, 'RIGCTL_HIST_DIR=~/tmp rigctl -i'. Cuando RIGCTL_HIST_DIR no está configurado, se usa el valor de HOME.
-I, --save-history
Escribir el historial de comandos y argumentos de la sesión actual (y sesiones anteriores, si se proporciona la opción -i) en un archivo (predeterminado $HOME/.rigctl_history) al final de la sesión actual.
Los comandos completos con argumentos se guardan como una sola línea para ser recordados y utilizados o editados. Disponible cuando rigctl está compilado con soporte Readline (ver READLINE abajo).
Nota: Para escribir un archivo de historial en otro directorio, configure la variable de entorno RIGCTL_HIST_DIR, por ejemplo, 'RIGCTL_HIST_DIR=~/tmp rigctl -IRq. Cuando RIGCTL_HIST_DIR no está configurado, se usa el valor de HOME.
-v, --verbose
Establecer modo detallado, acumulativo (ver DIAGNOSTICS abajo).
-Y,--ignore-err
Ignora los errores al abrir el equipo.
-Z, --debug-time-stamps
Habilita las marcas de tiempo para los mensajes de depuración.
Usar solo en combinación con la opción -v, ya que no genera salida por sí sola.
-h, --help
Muestra un resumen de estas opciones y sale.
-V, --version
Muestra la versión de rigctl y sale.
-!, --cookie
Establece la cookie que se utilizará para la seguridad de acceso remoto.
-#, --skip_init
Omite la mayor parte de la inicialización de inicio.
-
Detiene el procesamiento de opciones y lee comandos de la entrada estándar.
Ver Standard Input abajo.

Nota: Algunas opciones pueden no ser implementadas por un backend determinado y devolverán un error. Esto es más probable que ocurra con las opciones --set-conf y --show-conf.

Tenga en cuenta que el backend para la radio a controlar, o la radio misma, puede no admitir algunos comandos. En ese caso, la operación fallará con un código de error de Hamlib.

COMANDOS

Los comandos se pueden ingresar como un solo carácter o como un nombre de comando largo. Los comandos no van precedidos de un guión como las opciones. Pueden escribirse en modo interactivo o proporcionarse como argumento(s) en modo de interfaz de línea de comandos. En modo interactivo, los comandos y sus argumentos se pueden ingresar en una sola línea:


M LSB 2400

Dado que la mayoría de las operaciones de Hamlib tienen un método set (establecer) y un método get (obtener), se utilizará una sola letra mayúscula para los métodos set, mientras que la letra minúscula correspondiente se referirá al método get. Cada operación también tiene un nombre largo; en modo interactivo, anteponga una barra invertida, '\', para ingresar un nombre de comando largo en minúsculas.

Ejemplo: Use '\dump_caps' para ver qué capacidades admiten esta radio y backend.

Nota: El backend para la radio a controlar, o la radio misma, puede no admitir algunos comandos. En ese caso, la operación fallará con un mensaje de error de Hamlib.

Entrada Estándar

Como alternativa a la entrada de comandos interactivos READLINE o a un solo comando por ejecución, rigctl presenta una opción especial donde se puede usar un solo guión ('-') para leer comandos de la entrada estándar (stdin). Los comandos deben estar separados por espacios en blanco, de manera similar a los comandos proporcionados en la línea de comandos. Se pueden agregar comentarios usando el carácter '#', todo el texto hasta el final de la línea actual, incluido el carácter '#', se ignora.

Un ejemplo simple (el texto escrito está en negrita):


$ cat <<.EOF. >cmds.txt
> # File of commands
> v f m	# query rig
> V VFOB F 14200000 M CW 500	# set rig
> v f m	# query rig
> .EOF.
$ rigctl -m1 - <cmds.txt
v VFOA
f 145000000
m FM
15000
V VFOB
F 14200000
M CW 500
v VFOB
f 14200000
m CW
500
$

Comandos de rigctl

A continuación se incluye un resumen de los comandos (En el caso de los comandos set, la cadena entre comillas y en cursiva se reemplaza por el valor en la descripción. En el caso de los comandos get, la cadena entre comillas y en cursiva es el nombre clave del valor devuelto):

Q|q, salir de rigctl
Sale de rigctl en modo interactivo.
Cuando rigctl está controlando el equipo directamente, cerrará el backend del equipo y el puerto. Cuando rigctl está conectado a rigctld (modelo de radio 2), la conexión TCP/IP a rigctld se cierra y rigctld permanece en ejecución, disponible para otra conexión de red TCP/IP.
F, set_freq 'Frequency'
Establece la 'Frequency', en Hz.
La frecuencia puede ser un valor de punto flotante o entero.
f, get_freq
Obtiene la 'Frequency', en Hz.
Devuelve un valor entero y el VFO que hamlib considera activo. Tenga en cuenta que algunos equipos (por ejemplo, todos los Icom) no pueden rastrear el VFO actual, por lo que hamlib puede desincronizarse con el equipo si el usuario presiona botones del equipo como el VFO.
M, set_mode 'Mode' 'Passband'
Establece el 'Mode' y el 'Passband'.
El modo es un token: 'USB', 'LSB', 'CW', 'CWR', 'RTTY', 'RTTYR', 'AM', 'FM', 'WFM', 'AMS', 'PKTLSB', 'PKTUSB', 'PKTFM', 'ECSSUSB', 'ECSSLSB', 'FA', 'SAM', 'SAL', 'SAH', 'DSB'.
El ancho de banda está en Hz como un entero, -1 para no cambiar, o '0' para el valor predeterminado del backend de la radio. IC7300 puede usar 1,2,3 para seleccionar qué filtro usar.
Nota: Pasar un '?' (consulta) como primer argumento en lugar de un token de Modo devolverá una lista separada por espacios de los Modos soportados por el backend de la radio. Úselo para determinar los Modos soportados de un backend de radio determinado.
m, get_mode
Obtiene el 'Mode' y el 'Passband'.
Devuelve el Modo como un token y el Ancho de banda en Hz como en set_mode arriba.
V, set_vfo 'VFO'
Establece el 'VFO'.
El VFO es un token: 'VFOA', 'VFOB', 'VFOC', 'currVFO', 'VFO', 'MEM', 'Main', 'Sub', 'TX', 'RX', 'MainA', 'MainB', 'MainC', 'SubA', 'SubB', 'SubC'.
En modo VFO (ver opción --vfo arriba) solo se requiere un solo parámetro VFO:

$ rigctl -m 2029 -r /dev/rig -o
Rig command: V
VFO: VFOB
Rig command:

v, get_vfo
Obtiene el 'VFO' actual.
Devuelve el VFO como un token como en set_vfo arriba.
J, set_rit 'RIT'
Establece el 'RIT'.
El RIT está en Hz y puede ser + o -. Un valor de '0' restablece el RIT (Receiver Incremental Tuning) para que coincida con la frecuencia del VFO.
Nota: El RIT debe activarse o desactivarse explícitamente con el comando set_func. Esto permite establecer el desplazamiento del RIT independientemente de su activación y permite que el RIT permanezca activo mientras se establece el desplazamiento en '0'.
j, get_rit
Obtiene el 'RIT' en Hz.
El valor devuelto es un entero.
Z, set_xit 'XIT'
Establece el 'XIT'.
El XIT está en Hz y puede ser + o -. Un valor de '0' restablece el XIT (Transmitter Incremental Tuning) para que coincida con la frecuencia del VFO.
Nota: El XIT debe activarse o desactivarse explícitamente con el comando set_func. Esto permite establecer el desplazamiento del XIT independientemente de su activación y permite que el XIT permanezca activo
z, get_xit
Obtener 'XIT' en Hz.
El valor devuelto es un entero.
T, set_ptt 'PTT'
Establecer 'PTT'.
PTT es un valor: ‘0’ (RX), ‘1’ (TX), ‘2’ (TX mic), o ‘3’ (TX data).
t, get_ptt
Obtener el estado 'PTT'.
Devuelve PTT como un valor en set_ptt arriba.
S, set_split_vfo 'Split' 'TX VFO'
Establecer el modo 'Split'.
Split es ‘0’ = Normal o ‘1’ = Split.
Establecer 'TX VFO'.
TX VFO es un token: ‘VFOA’, ‘VFOB’, ‘VFOC’, ‘currVFO’, ‘VFO’, ‘MEM’, ‘Main’, ‘Sub’, ‘TX’, ‘RX’.
s, get_split_vfo
Obtener el modo 'Split'.
Split es ‘0’ = Normal o ‘1’ = Split.
Obtener 'TX VFO'.
TX VFO es un token como en set_split_vfo arriba.
I, set_split_freq 'Tx Frequency'
Establecer 'TX Frequency', en Hz.
La frecuencia puede ser un valor de punto flotante o entero.
i, get_split_freq
Obtener 'TX Frequency', en Hz.
Devuelve un valor entero.
X, set_split_mode 'TX Mode' 'TX Passband'
Establecer 'TX Mode' y 'TX Passband'.
TX Mode es un token: ‘USB’, ‘LSB’, ‘CW’, ‘CWR’, ‘RTTY’, ‘RTTYR’, ‘AM’, ‘FM’, ‘WFM’, ‘AMS’, ‘PKTLSB’, ‘PKTUSB’, ‘PKTFM’, ‘ECSSUSB’, ‘ECSSLSB’, ‘FA’, ‘SAM’, ‘SAL’, ‘SAH’, ‘DSB’.
TX Passband está en Hz como un entero, o ‘0’ para el valor predeterminado del backend de radio.
Nota: Pasar un ‘?’ (consulta) como primer argumento en lugar de un token de TX Mode devolverá una lista separada por espacios de los TX Modes admitidos por el backend de radio. Usa esto para determinar los TX Modes admitidos de un backend de radio dado.
x, get_split_mode
Obtener 'TX Mode' y 'TX Passband'.
Devuelve TX Mode como un token y TX Passband en Hz como en set_split_mode arriba.
Y, set_ant 'Antenna' 'Option'
Establecer 'Antenna' y 'Option'.
El número es el número de antena basado en 1 (‘1’, ‘2’, ‘3’, ...).
La opción depende del equipo. Para Icom, probablemente establecerá las antenas de Tx y Rx como en el IC-7851. Consulta tu manual para ver los valores de opción específicos del equipo. La mayoría de los equipos no se preocupan por la opción.
Para el IC-7851, FTDX3000 (y quizás otros) significa esto:

1 = TX/RX = ANT1  FTDX3000=ANT1/ANT3
2 = TX/RX = ANT2  FTDX3000=ANT2/ANT3
3 = TX/RX = ANT3  FTDX3000=ANT3
4 = TX/RX = ANT1/ANT4
5 = TX/RX = ANT2/ANT4
6 = TX/RX = ANT3/ANT4

y, get_ant 'Antenna'
Obtener 'Antenna'.
Un valor de 0 para Antenna devolverá la antena de TX actual.
> 0 es el número de antena basado en 1 (‘1’, ‘2’, ‘3’, ...).
La opción devuelta depende del equipo. Para Icom, es probable que sea la bandera de solo RX.
b, send_morse 'Morse'
Enviar símbolos 'Morse'. Para equipos Yaesu, usa el número de memoria (1-5 para la mayoría de los equipos) o un mensaje de hasta 50 caracteres (que usará la memoria #1).

Ejemplo desde la línea de comandos:

rigctl -m 3073 -r /dev/ttyUSB0 b "CQ CQ DE ME"
Ejemplo Yaesu para enviar el mensaje #1: 
rigctl -m 1035 -r /dev/ttyUSB0 b 1
0xbb, stop_morse
Detener el envío del código morse actual.
0xbc, wait_morse
Esperar a que termine el morse; solo funciona con interrupción completa.
0x94, send_voice_mem 'Msgnum'
Hacer que el equipo transmita el mensaje interno 'Msgnum'.
0x8b, get_dcd
Obtener el estado 'DCD' (squelch): ‘0’ (Cerrado) o ‘1’ (Abierto).
R, set_rptr_shift 'Rptr Shift'
Establecer 'Rptr Shift'.
Rptr Shift es uno de: ‘+’, ‘-’, o algo más para ‘None’.
r, get_rptr_shift
Obtener 'Rptr Shift'.
Devuelve ‘+’, ‘-’, o ‘None’.
O, set_rptr_offs 'Rptr Offset'
Establecer 'Rptr Offset', en Hz.
o, get_rptr_offs
Obtener 'Rptr Offset', en Hz.
C, set_ctcss_tone 'CTCSS Tone'
Establecer 'CTCSS Tone', en décimas de Hz.
c, get_ctcss_tone
Obtener 'CTCSS Tone', en décimas de Hz.
D, set_dcs_code 'DCS Code'
Establecer 'DCS Code'.
d, get_dcs_code
Obtener 'DCS Code'.
0x90, set_ctcss_sql 'CTCSS Sql'
Establecer el tono 'CTCSSSql', en décimas de Hz.
0x91, get_ctcss_sql
Obtener el tono 'CTCSSSql', en décimas de Hz.
0x92, set_dcs_sql 'DCSSql'
Establecer el código 'DCS Sql'.
0x93, get_dcs_sql
Obtener el código 'DCS Sql'.
N, set_ts 'Tuning Step'
Establecer 'Tuning Step', en Hz.
n, get_ts
Obtener 'Tuning Step', en Hz.
U, set_func 'Func' 'Func Status'
Establecer 'Func' y 'Func Status'.
Func es un token: ‘ABM’, ‘AFC’, ‘AFLT’, ‘AIP’, ‘ANF’, ‘ANL’, ‘APF’, ‘ARO’, ‘BC2’, ‘BC’, ‘COMP’, ‘CSQL’, ‘DIVERSITY’, ‘DSQL’, ‘DUAL_WATCH’, ‘FAGC’, ‘FBKIN’, ‘LOCK’, ‘MBC’, ‘MN’, ‘MON’, ‘MUTE’, ‘NB2’, ‘NB’, ‘NR’, ‘OVF_STATUS’, ‘RESUME’, ‘REV’, ‘RF’, ‘RIT’, ‘SATMODE’, ‘SBKIN’, ‘SCEN’, ‘SCOPE’, ‘SEND_MORSE’, ‘SEND_VOICE_MEM’, ‘SPECTRUM’, ‘SPECTRUM_HOLD’, ‘SQL’, ‘SYNC’, ‘TBURST’, ‘TONE’, ‘TRANSCEIVE’, ‘TSQL’, ‘TUNER’, ‘VOX’, ‘VSC’, ‘XIT’.

Establecer 'DateTime'
Establece el reloj del equipo -- tenga en cuenta que algunos equipos no manejan segundos o milisegundos. Si intenta configurar segundos/milisegundos y el equipo no lo soporta, recibirá un mensaje de advertencia de depuración. El formato es ISO8601. Los formatos aceptados permiten una zona horaria de 2 o 4 dígitos 
YYYY-MM-DDTHH:MM:SS.SSS+ZZ (donde +ZZ es un desplazamiento UTC de -/+ HH)
YYYY-MM-DDTHH:MM:SS.SSS+ZZZZ (donde +ZZZZ es un desplazamiento UTC de -/+ HHMM)
YYYY-MM-DDTHH:MM:SS+ZZ
YYYY-MM-DDTHH:MM:SS+ZZZZ
YYYY-MM-DDTHH:MM+ZZ
YYYY-MM-DDTHH:MM+ZZZZ
YYYY-MM-DD (establece solo la fecha)
local (establece ambos relojes a la hora local)
utc (establece ambos relojes a la hora UTC)
Nota: Los equipos Icom esperan que configure la hora local y las horas de diferencia con UTC. Entonces...un ejemplo de las 4 PM EST sería 2021-12-01T16:00:00-0500 Pero...si desea mostrar GMT, debe configurar el reloj para GMT con desplazamiento UTC cero. ¡Esperamos que Icom permita mostrar ambos relojes en el futuro!

Nota: Los equipos Kenwood solo permiten configurar el reloj local, y solo si no se establece automáticamente por NTP. Intentar configurar el reloj cuando NTP está en uso establecerá el desplazamiento, pero no la hora, y no se devolverá ningún estado de error. La hora mostrada en el reloj auxiliar está determinada únicamente por la UTC y el desplazamiento auxiliar.
