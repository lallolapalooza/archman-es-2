NOMBRE

cpp - El preprocesador de C

SINOPSIS

cpp [-Dmacro[=defn]...] [-Umacro]
[-Idir...] [-iquotedir...]
[-M|-MM] [-MG] [-MF archivo]
[-MP] [-MQ objetivo...]
[-MT objetivo...]
archivo_entrada [[-o] archivo_salida]

Solo se incluyen las opciones más útiles; consulte más abajo para obtener una lista más completa de opciones específicas del preprocesador. Además, cpp acepta la mayoría de las opciones del controlador gcc, que no se enumeran aquí. Consulte la documentación de GCC para obtener detalles.

DESCRIPCIÓN

El preprocesador de C, a menudo conocido como cpp, es un *procesador de macros* que es utilizado automáticamente por el compilador de C para transformar su programa antes de la compilación. Se llama procesador de macros porque le permite definir *macros*, que son abreviaturas breves para construcciones más largas.

El preprocesador de C está destinado a ser utilizado solo con código fuente de C, C++ y Objective-C. En el pasado, se ha abusado de él como un procesador de texto general. Fallará con entradas que no obedezcan las reglas léxicas de C. Por ejemplo, los apóstrofos se interpretarán como el comienzo de constantes de caracteres y causarán errores. Además, no puede depender de que preserve las características de la entrada que no son significativas para los lenguajes de la familia C. Si se preprocesa un Makefile, se eliminarán todas las tabulaciones y el Makefile no funcionará.

Dicho esto, a menudo puede salirse con la suya usando cpp en cosas que no son C. Otros lenguajes de programación tipo Algol suelen ser seguros (Ada, etc.). También lo es el ensamblador, con precaución. El modo -traditional-cpp preserva más espacios en blanco y, por lo demás, es más permisivo. Muchos de los problemas se pueden evitar escribiendo comentarios estilo C o C++ en lugar de comentarios del lenguaje nativo, y manteniendo las macros simples.

Siempre que sea posible, debe utilizar un preprocesador diseñado para el lenguaje en el que está escribiendo. Las versiones modernas del ensamblador GNU tienen capacidades de macro. La mayoría de los lenguajes de programación de alto nivel tienen su propio mecanismo de inclusión e inclusión condicional. Si todo lo demás falla, pruebe un verdadero procesador de texto general, como GNU M4.

Los preprocesadores de C varían en algunos detalles. Este manual describe el preprocesador GNU C, que proporciona un pequeño superconjunto de las características del estándar C de ISO. En su modo predeterminado, el preprocesador GNU C no hace algunas cosas requeridas por el estándar. Estas son características que rara vez, o nunca, se usan y pueden causar cambios sorprendentes en el significado de un programa que no las espera. Para obtener C estándar estricto, debe usar las opciones -std=c90, -std=c99, -std=c11 o -std=c17, dependiendo de la versión del estándar que desee. Para obtener todos los diagnósticos obligatorios, también debe usar -pedantic.

Este manual describe el comportamiento del preprocesador ISO. Para minimizar diferencias gratuitas, donde el comportamiento del preprocesador ISO no entra en conflicto con la semántica tradicional, el preprocesador tradicional debería comportarse de la misma manera. Las diversas diferencias que existen se detallan en la sección *MODO TRADICIONAL*.

Para mayor claridad, a menos que se indique lo contrario, las referencias a CPP en este manual se refieren a GNU CPP.

OPCIONES

El comando cpp espera dos nombres de archivo como argumentos, archivo_entrada y archivo_salida. El preprocesador lee archivo_entrada junto con cualquier otro archivo que especifique con #include. Toda la salida generada por los archivos de entrada combinados se escribe en archivo_salida.

Ya sea archivo_entrada o archivo_salida puede ser -, que como archivo_entrada significa leer de la entrada estándar y como archivo_salida significa escribir en la salida estándar. Si se omite alguno de los archivos, significa lo mismo que si se hubiera especificado - para ese archivo. También puede usar la opción -o archivo_salida para especificar el archivo de salida.

A menos que se indique lo contrario, o la opción termine en =, todas las opciones que toman un argumento pueden tener ese argumento apareciendo inmediatamente después de la opción, o con un espacio entre la opción y el argumento: -Ifoo y -I foo tienen el mismo efecto.

Muchas opciones tienen nombres de varias letras; por lo tanto, múltiples opciones de una sola letra *no* pueden agruparse: -dM es muy diferente de -d -M.

-D nombre
Predefine nombre como una macro, con definición 1.
-D nombre=definición
El contenido de definición se tokeniza y se procesa como si apareciera durante la fase tres de traducción en una directiva #define. En particular, la definición se trunca con caracteres de nueva línea incrustados.

Si está invocando el preprocesador desde un shell o un programa similar a un shell, puede que necesite usar la sintaxis de comillas del shell para proteger caracteres como espacios que tienen un significado en la sintaxis del shell.

Si desea definir una macro similar a una función en la línea de comandos, escriba su lista de argumentos con paréntesis alrededor antes del signo igual (si lo hay). Los paréntesis son significativos para la mayoría de los shells, por lo que debe comillar la opción. Con sh y csh, -D'nombre(args...)=definición' funciona.

Las opciones -D y -U se procesan en el orden en que se proporcionan en la línea de comandos. Todas las opciones -imacros archivo y -include archivo se procesan después de todas las opciones -D y -U.

-U nombre
Cancela cualquier definición previa de nombre, ya sea integrada o proporcionada con una opción -D.
-include archivo
Procesa archivo como si "#include "archivo"" apareciera como la primera línea del archivo fuente principal. Sin embargo, el primer directorio buscado para archivo es el directorio de trabajo del preprocesador *en lugar* del directorio que contiene el archivo fuente principal. Si no se encuentra allí, se busca en el resto de la cadena de búsqueda de "#include "..."" como es normal.

Si se proporcionan varias opciones -include, los archivos se incluyen en el orden en que aparecen en la línea de comandos.

-imacros archivo
Exactamente igual que -include, excepto que cualquier salida producida al escanear archivo se descarta. Las macros que define permanecen definidas. Esto le permite obtener todas las macros de una cabecera sin procesar también sus declaraciones.

Todos los archivos especificados por -imacros se procesan antes que todos los archivos especificados por -include.

-undef
No predefina ninguna macro específica del sistema o específica de GCC. Las macros predefinidas estándar permanecen definidas.
-pthread
Define macros adicionales necesarias para usar la biblioteca de hilos POSIX. Debe usar esta opción de manera consistente tanto para la compilación como para el enlace. Esta opción es compatible con destinos GNU/Linux, la mayoría de los otros derivados de Unix, y también con destinos Cygwin y MinGW x86.
-M
En lugar de producir el resultado del preprocesamiento, produce una regla adecuada para make que describe las dependencias del archivo fuente principal. El preprocesador produce una regla de make que contiene el nombre del archivo objeto para ese archivo fuente, dos puntos, y los nombres de todos los archivos incluidos, incluidos los que provienen de las opciones de línea de comandos -include o -imacros.

A menos que se especifique explícitamente (con -MT o -MQ), el nombre del archivo objeto consiste en el nombre del archivo fuente con cualquier sufijo reemplazado por el sufijo del archivo objeto y con cualquier parte del directorio inicial eliminada. Si hay muchos archivos incluidos, la regla se divide en varias líneas usando \-nueva línea. La regla no tiene comandos.

Esta opción no suprime la salida de depuración del preprocesador, como -dM. Para evitar mezclar dicha salida de depuración con las reglas de dependencia, debe especificar explícitamente el archivo de salida de dependencia con -MF, o usar una variable de entorno como DEPENDENCIES_OUTPUT. La salida de depuración todavía se envía a la salida regular.

de la corriente como es normal.

Pasar -M al compilador implica -E y suprime advertencias con un -w implícito.

-MM
Similar a -M pero no menciona archivos de cabecera que se encuentran en directorios de cabeceras del sistema, ni archivos de cabecera que se incluyan, directa o indirectamente, desde una cabecera de este tipo.

Esto implica que la elección de corchetes angulares o comillas dobles en una directiva #include no determina por sí misma si esa cabecera aparece en la salida de dependencias de -MM.

-MF archivo
Cuando se usa con -M o -MM, especifica un archivo donde escribir las dependencias. Si no se proporciona la opción -MF, el preprocesador envía las reglas al mismo lugar donde enviaría la salida preprocesada.

Cuando se usa con las opciones del compilador -MD o -MMD, -MF anula el archivo de salida de dependencias por defecto.

Si archivo es -, entonces las dependencias se escriben en stdout.

-MG
En conjunción con una opción como -M que solicita la generación de dependencias, -MG asume que los archivos de cabecera que faltan son archivos generados y los añade a la lista de dependencias sin generar un error. El nombre del archivo de dependencia se toma directamente de la directiva "#include" sin añadirle ningún directorio. -MG también suprime la salida preprocesada, ya que un archivo de cabecera faltante hace que esto sea inútil.

Esta característica se utiliza en la actualización automática de makefiles.

-Mno-modules
Deshabilita la generación de dependencias para interfaces de módulos compilados.
-MP
Esta opción instruye a CPP para añadir un objetivo ficticio (phony target) para cada dependencia distinta del archivo principal, haciendo que cada una dependa de nada. Estas reglas ficticias evitan errores que make emite si eliminas archivos de cabecera sin actualizar el Makefile para que coincida.

Esta es una salida típica:

test.o: test.c test.h

test.h:
-MT objetivo
Cambia el objetivo de la regla emitida por la generación de dependencias. Por defecto, CPP toma el nombre del archivo de entrada principal, elimina cualquier componente de directorio y cualquier sufijo de archivo como .c, y añade el sufijo de objeto habitual de la plataforma. El resultado es el objetivo.

Una opción -MT establece el objetivo como exactamente la cadena que especifiques. Si quieres múltiples objetivos, puedes especificarlos como un solo argumento a -MT, o usar múltiples opciones -MT.

Por ejemplo, -MT '$(objpfx)foo.o' podría dar

$(objpfx)foo.o: foo.c
-MQ objetivo
Igual que -MT, pero entrecomilla cualquier carácter que sea especial para Make. -MQ '$(objpfx)foo.o' da 
$$(objpfx)foo.o: foo.c

El objetivo por defecto se entrecomilla automáticamente, como si se hubiera proporcionado con -MQ.

-MD
-MD es equivalente a -M -MF archivo, excepto que -E no se implica. El compilador determina archivo basándose en si se proporciona una opción -o. Si es así, el compilador usa su argumento pero con un sufijo de .d, de lo contrario toma el nombre del archivo de entrada, elimina cualquier componente de directorio y sufijo, y aplica un sufijo de .d.

Si se usa -MD en conjunción con -E, cualquier opción -o se entiende que especifica el archivo de salida de dependencias, pero si se usa sin -E, cada -o se entiende que especifica un archivo objeto de destino.

Dado que -E no se implica, -MD puede usarse para generar un archivo de salida de dependencias como un efecto secundario del proceso de compilación.

-MMD
Similar a -MD excepto que solo menciona cabeceras de usuario, no cabeceras del sistema.
-fpreprocessed
Indica al preprocesador que el archivo de entrada ya ha sido preprocesado. Esto suprime cosas como la expansión de macros, la conversión de trigrafos, el empalme de saltos de línea escapados y el procesamiento de la mayoría de las directivas. El preprocesador todavía reconoce y elimina comentarios, para que puedas pasar un archivo preprocesado con -C al compilador sin problemas. En este modo, el preprocesador integrado es poco más que un tokenizador para los front-ends.

-fpreprocessed se implica si el archivo de entrada tiene una de las extensiones .i, .ii o .mi. Estas son las extensiones que GCC utiliza para archivos preprocesados creados con -save-temps.

-fdirectives-only
Al preprocesar, maneja las directivas, pero no expande macros.

El comportamiento de la opción depende de las opciones -E y -fpreprocessed.

Con -E, el preprocesamiento se limita al manejo de directivas como "#define", "#ifdef" y "#error". Otras operaciones del preprocesador, como la expansión de macros y la conversión de trigrafos, no se realizan. Además, la opción -dD se habilita implícitamente.

Con -fpreprocessed, la predefinición de macros de la línea de comandos y la mayoría de las macros incorporadas se deshabilita. Las macros como "__LINE__", que son contextualmente dependientes, se manejan normalmente. Esto permite la compilación de archivos preprocesados previamente con "-E -fdirectives-only".

Con ambas opciones -E y -fpreprocessed, las reglas para -fpreprocessed tienen precedencia. Esto permite el preprocesamiento completo de archivos preprocesados previamente con "-E -fdirectives-only".

-fdollars-in-identifiers
Acepta $ en identificadores.
-fextended-identifiers
Acepta nombres de caracteres universales y caracteres extendidos en identificadores. Esta opción está habilitada por defecto para C99 (y versiones posteriores del estándar C) y C++.
-fno-canonical-system-headers
Al preprocesar, no acorta las rutas de cabeceras del sistema con canonización.
-fmax-include-depth=profundidad
Establece la profundidad máxima de los #include anidados. El valor por defecto es 200.
-ftabstop=ancho
Establece la distancia entre las tabulaciones. Esto ayuda al preprocesador a informar de columnas correctas en advertencias o errores, incluso si hay tabulaciones en la línea. Si el valor es menor que 1 o mayor que 100, la opción se ignora. El valor por defecto es 8.
-ftrack-macro-expansion[=nivel]
Rastrea las ubicaciones de los tokens a través de las expansiones de macros. Esto permite al compilador emitir diagnósticos sobre la pila de expansión de macros actual cuando ocurre un error de compilación en una expansión de macro. Usar esta opción hace que el preprocesador y el compilador consuman más memoria. El parámetro nivel se puede usar para elegir el nivel de precisión del rastreo de la ubicación de los tokens, disminuyendo así el consumo de memoria si es necesario. El valor 0 de nivel desactiva esta opción. El valor 1 rastrea las ubicaciones de los tokens en un modo degradado en aras de una sobrecarga mínima de memoria. En este modo, todos los tokens resultantes de la expansión de un argumento de una macro tipo función tienen la misma ubicación. El valor 2 rastrea las ubicaciones de los tokens completamente. Este valor es el que más memoria consume. Cuando esta opción se proporciona sin argumento, el valor del parámetro por defecto es 2.

Nota que "-ftrack-macro-expansion=2" está activado por defecto.

-fmacro-prefix-map=viejo=nuevo
Al preprocesar archivos que residen en el directorio viejo, expande las macros "__FILE__" y "__BASE_FILE__" como si los archivos residiran en el directorio nuevo en su lugar. Esto se puede usar para cambiar una ruta absoluta a una ruta relativa usando . para nuevo, lo que puede resultar en compilaciones más reproducibles e independientes de la ubicación. Esta opción también afecta a "__builtin_FILE()" durante la compilación. Ver también -ffile-prefix-map y -fcanon-prefix-map.
-fexec-charset=charset
Establece el conjunto de caracteres de ejecución, utilizado para constantes de cadena y carácter. El valor por defecto es UTF-8. charset puede ser cualquier codificación soportada por la rutina de la biblioteca "iconv" del sistema.
-fwide-exec-charset=charset
Establece el conjunto de caracteres de ejecución anchos, utilizado para constantes de cadena y carácter anchos. El valor por defecto es uno de UTF-32BE, UTF-32LE, UTF-16BE o UTF-16LE, el que corresponda al ancho de "wchar_t" y al orden de bytes big-endian o little-endian que se esté utilizando para la generación de código. Al igual que con -fexec-charset, charset puede ser cualquier codificación soportada por la rutina de la biblioteca "iconv" del sistema; sin embargo, tendrás problemas con codificaciones que no encajen exactamente en "wchar_t".
-finput-charset=charset
Establece el conjunto de caracteres de entrada, utilizado para la traducción del conjunto de caracteres del archivo de entrada al conjunto de caracteres fuente utilizado por GCC. Si la configuración regional no lo especifica, o GCC no puede obtener esta información de la configuración regional, el valor por defecto es UTF-8. Esto puede ser anulado por la configuración regional o por esta opción de línea de comandos. Actualmente, la opción de línea de comandos tiene prioridad si hay un conflicto. charset puede ser cualquier codificación soportada por la rutina de la biblioteca "iconv" del sistema.
-fworking-directory
Habilita la generación de marcadores de línea (linemarkers) en la salida del preprocesador que informan al compilador sobre el directorio de trabajo actual en el momento del preprocesamiento. Cuando esta opción está habilitada, el preprocesador emite, después del marcador de línea inicial, un segundo marcador de línea.
marcador con el directorio de trabajo actual seguido de dos barras. GCC usa este directorio, cuando está presente en la entrada preprocesada, como el directorio emitido como directorio de trabajo actual en algunos formatos de información de depuración. Esta opción está habilitada implícitamente si la información de depuración está habilitada, pero esto puede ser inhibido con la forma negada -fno-working-directory. Si el flag -P está presente en la línea de comandos, esta opción no tiene efecto, ya que no se emiten directivas "#line".
-A predicate=answer
Realiza una aserción con el predicado predicate y la respuesta answer. Esta forma es preferible a la forma antigua -A predicate(answer), que todavía se soporta, porque no utiliza caracteres especiales del shell.
-A -predicate=answer
Cancela una aserción con el predicado predicate y la respuesta answer.
-C
No descarta comentarios. Todos los comentarios se pasan al archivo de salida, excepto los comentarios en directivas procesadas, que se eliminan junto con la directiva.

Debes estar preparado para efectos secundarios al usar -C; causa que el preprocesador trate los comentarios como tokens por derecho propio. Por ejemplo, los comentarios que aparecen al principio de lo que sería una línea de directiva tienen el efecto de convertir esa línea en una línea de código fuente ordinaria, ya que el primer token en la línea ya no es un #.

-CC
No descarta comentarios, incluso durante la expansión de macros. Esto es similar a -C, excepto que los comentarios contenidos dentro de macros también se pasan al archivo de salida donde se expande la macro.

Además de los efectos secundarios de la opción -C, la opción -CC hace que todos los comentarios estilo C++ dentro de una macro se conviertan en comentarios estilo C. Esto es para evitar que el uso posterior de esa macro comente inadvertidamente el resto de la línea de código fuente.

La opción -CC se usa generalmente para soportar comentarios de lint.

-P
Inhibe la generación de marcadores de línea en la salida del preprocesador. Esto podría ser útil al ejecutar el preprocesador en algo que no sea código C, y se enviará a un programa que podría confundirse con los marcadores de línea.
-traditional
-traditional-cpp
Intenta imitar el comportamiento de los preprocesadores C pre-estándar, en oposición a los preprocesadores C ISO.

Tenga en cuenta que GCC no intenta emular de otra manera un compilador C pre-estándar, y estas opciones solo se soportan con el switch -E, o al invocar CPP explícitamente.

-trigraphs
Soporta trigrafos C ISO. Estas son secuencias de tres caracteres, todas comenzando con ??, que están definidas por C ISO para representar caracteres individuales. Por ejemplo, ??/ representa \, por lo que '??/n' es una constante de carácter para una nueva línea.

Por defecto, GCC ignora los trigrafos, pero en modos que cumplen con los estándares los convierte. Ver las opciones -std y -ansi.

-remap
Habilita código especial para solucionar problemas con sistemas de archivos que solo permiten nombres de archivo muy cortos, como MS-DOS.
-H
Imprime el nombre de cada archivo de cabecera utilizado, además de otras actividades normales. Cada nombre se indenta para mostrar cuán profundo en la pila de #include está. Los archivos de cabecera precompilados también se imprimen, incluso si resultan ser inválidos; un archivo de cabecera precompilado inválido se imprime con ...x y uno válido con ...! .
-dletras
Indica que se generen volcados de depuración durante la compilación según lo especificado por las letras. Las banderas documentadas aquí son las relevantes para el preprocesador. Otras letras son interpretadas por el compilador propiamente dicho, o reservadas para futuras versiones de GCC, y por lo tanto se ignoran silenciosamente. Si especifica letras cuyo comportamiento entra en conflicto, el resultado no está definido.
-dM
En lugar de la salida normal, genera una lista de directivas #define para todas las macros definidas durante la ejecución del preprocesador, incluidas las macros predefinidas. Esto le da una manera de averiguar qué está predefinido en su versión del preprocesador. Suponiendo que no tiene el archivo foo.h, el comando 
touch foo.h; cpp -dM foo.h

muestra todas las macros predefinidas.

-dD
Similar a -dM excepto que emite *ambas* directivas #define y el resultado del preprocesamiento. Ambos tipos de salida van al archivo de salida estándar.
-dN
Similar a -dD, pero emite solo los nombres de las macros, no sus expansiones.
-dI
Emite directivas #include además del resultado del preprocesamiento.
-dU
Similar a -dD excepto que solo se emiten las macros que se expanden, o cuya definibilidad se prueba en directivas del preprocesador; la salida se retrasa hasta el uso o la prueba de la macro; y también se emiten directivas #undef para las macros probadas pero indefinidas en el momento.
-fdebug-cpp
Esta opción solo es útil para depurar GCC. Cuando se usa desde CPP o con -E, vuelca información de depuración sobre mapas de ubicación. Cada token en la salida va precedido por el volcado del mapa al que pertenece su ubicación.

Cuando se usa desde GCC sin -E, esta opción no tiene efecto.

-I dir
-iquote dir
-isystem dir
-idirafter dir
Agrega el directorio dir a la lista de directorios a buscar para archivos de cabecera durante el preprocesamiento.

Si dir comienza con = o $SYSROOT, entonces el = o $SYSROOT se reemplaza por el prefijo del sysroot; ver --sysroot y -isysroot.

Los directorios especificados con -iquote se aplican solo a la forma de comillas de la directiva, "#include "file"". Los directorios especificados con -I, -isystem, o -idirafter se aplican a la búsqueda de ambas directivas "#include "file"" y "#include <file>".

Puede especificar cualquier número o combinación de estas opciones en la línea de comandos para buscar archivos de cabecera en varios directorios. El orden de búsqueda es el siguiente:

1.
Para la forma de comillas de la directiva de inclusión, se busca primero el directorio del archivo actual.
2.
Para la forma de comillas de la directiva de inclusión, se buscan los directorios especificados con opciones -iquote en orden de izquierda a derecha, según aparecen en la línea de comandos.
3.
Los directorios especificados con opciones -I se escanean en orden de izquierda a derecha.
4.
Los directorios especificados con opciones -isystem se escanean en orden de izquierda a derecha.
5.
Se escanean los directorios del sistema estándar.
6.
Los directorios especificados con opciones -idirafter se escanean en orden de izquierda a derecha.

Puede usar -I para reemplazar un archivo de cabecera del sistema, sustituyendo su propia versión, ya que estos directorios se buscan antes que los directorios de archivos de cabecera del sistema estándar. Sin embargo, no debe usar esta opción para agregar directorios que contengan archivos de cabecera del sistema suministrados por el proveedor; use -isystem para eso.

Las opciones -isystem y -idirafter también marcan el directorio como un directorio del sistema, de modo que recibe el mismo tratamiento especial que se aplica a los directorios del sistema estándar.

Si un directorio de inclusión del sistema estándar, o un directorio especificado con -isystem, también se especifica con -I, se ignora la opción -I. El directorio aún se busca, pero como un directorio del sistema en su posición normal en la cadena de inclusión del sistema. Esto es para asegurar que el procedimiento de GCC para corregir archivos de cabecera defectuosos y el orden para la directiva "#include_next" no se cambien inadvertidamente. Si realmente necesita cambiar el orden de búsqueda de los directorios del sistema, use las opciones -nostdinc y/o -isystem.

-I-
Divide la ruta de inclusión. Esta opción ha sido deprecada. Por favor, use -iquote en su lugar para los directorios -I antes de -I- y elimine la opción -I-.

Cualquier directorio especificado con opciones -I antes de -I- se busca solo para cabeceras solicitadas con "#include "file""; no se buscan para "#include <file>". Si se especifican directorios adicionales con opciones -I después de -I-, esos directorios se buscan para todas las directivas #include.

Además, -I- inhibe el uso del directorio del archivo actual como primer directorio de búsqueda para "#include "file"". No hay forma de anular este efecto de -I-.

NAME

cpp - C Preprocessor

SYNOPSIS

cpp [options] [input file] [output file]

cpp [-o] output file -traditional-cpp [-nostdinc] [-isystem dir] ... [input file]

DESCRIPTION

This manual page describes the GNU C Preprocessor, cpp. cpp is a preprocessor for the C, C++, Objective-C and Objective-C++ programming languages. It is typically used as the first stage of the compilation process. Its tasks are to process “directives”— lines beginning with #— and to expand macros.

Directives

The directives understood by cpp are:

#define macro [(parms)] [value]
#elif condition
#else
#endif
#error text
#if condition
#ifdef macro
#ifndef macro
#include ["file" or <file>]
#line number [filename]
#pragma text
#undef macro

Invocation

Normally, cpp is invoked by the compiler driver (gcc). You can also invoke it directly, but you may need to specify options to approximate the compiler's behavior.

When invoked directly, cpp reads the specified input files (standard input if none are given) and writes the result to the specified output file (standard output if none are given). The -o option is ignored if only one input file is specified and it is standard input. The -traditional-cpp option is only valid when cpp is invoked directly.

Options

The following options are available:

-Idir
-iquotedir
-isystemdir
-idirafterdir
Append dir to the list of directories in which to search for header files. cpp searches for header files in directories specified with -I and -iquote in the order they appear on the command line. Directories specified with -isystem and -idirafter are searched after all directories specified with -I and -iquote. Directories specified with -isystem are treated as system directories, and warnings are suppressed for those directories. Directories specified with -idirafter are searched after the directories specified with -isystem.
-iprefix prefix
Specify prefix as the prefix for subsequent -iwithprefix options. If the prefix represents a directory, you should include the final /.
-iwithprefix dir
-iwithprefixbefore dir
Append dir to the prefix specified previously with -iprefix, and add the resulting directory to the include search path. -iwithprefixbefore puts it in the same place -I would; -iwithprefix puts it where -idirafter would.
-isysroot dir
This option is like the --sysroot option, but applies only to header files (except for Darwin targets, where it applies to both header files and libraries). See the --sysroot option for more information.
-imultilib dir
Use dir as a subdirectory of the directory containing target-specific C++ headers.
-nostdinc
Do not search the standard system directories for header files. Only the directories explicitly specified with -I, -iquote, -isystem, and/or -idirafter options (and the directory of the current file, if appropriate) are searched.
-nostdinc++
Do not search for header files in the C++-specific standard directories, but do still search the other standard directories. (This option is used when building the C++ library.)
-Wcomment
-Wcomments
Warn whenever a comment-start sequence /* appears in a /* comment, or whenever a backslash-newline appears in a // comment. This warning is enabled by -Wall.
-Wtrigraphs
Warn if any trigraphs are encountered that might change the meaning of the program. Trigraphs within comments are not warned about, except those that would form escaped newlines.

This option is implied by -Wall. If -Wall is not given, this option is still enabled unless trigraphs are enabled. To get trigraph conversion without warnings, but get the other -Wall warnings, use -trigraphs -Wall -Wno-trigraphs.

-Wundef
Warn if an undefined identifier is evaluated in an "#if" directive. Such identifiers are replaced with zero.
-Wexpansion-to-defined
Warn whenever defined is encountered in the expansion of a macro (including the case where the macro is expanded by an #if directive). Such usage is not portable. This warning is also enabled by -Wpedantic and -Wextra.
-Wunused-macros
Warn about macros defined in the main file that are unused. A macro is used if it is expanded or tested for existence at least once. The preprocessor also warns if the macro has not been used at the time it is redefined or undefined.

Built-in macros, macros defined on the command line, and macros defined in include files are not warned about.

Note: If a macro is actually used, but only used in skipped conditional blocks, then the preprocessor reports it as unused. To avoid the warning in such a case, you might improve the scope of the macro's definition by, for example, moving it into the first skipped block. Alternatively, you could provide a dummy use with something like:

#if defined the_macro_causing_the_warning
#endif
-Wno-endif-labels
Do not warn whenever an "#else" or an "#endif" are followed by text. This sometimes happens in older programs with code of the form 
#if FOO
...
#else FOO
...
#endif FOO

The second and third "FOO" should be in comments. This warning is on by default.

ENVIRONMENT

This section describes the environment variables that affect how CPP operates. You can use them to specify directories or prefixes to use when searching for include files, or to control dependency output.

Note that you can also specify places to search using options such as -I, and control dependency output with options like -M. These take precedence over environment variables, which in turn take precedence over the configuration of GCC.

CPATH
C_INCLUDE_PATH
CPLUS_INCLUDE_PATH
OBJC_INCLUDE_PATH
Each variable's value is a list of directories separated by a special character, much like PATH, in which to look for header files. The special character, "PATH_SEPARATOR", is target-dependent and determined at GCC build time. For Microsoft Windows-based targets it is a semicolon, and for almost all other targets it is a colon.

CPATH specifies a list of directories to be searched as if specified with -I, but after any paths given with -I options on the command line. This environment variable is used regardless of which language is being preprocessed.

The remaining environment variables apply only when preprocessing the particular language indicated. Each specifies a list of directories to be searched as if specified with -isystem, but after any paths given with -isystem options on the command line.

In all these variables, an empty element instructs the compiler to search its current working directory. Empty elements can appear at the beginning or end of a path. For instance, if the value of CPATH is ":/special/include", that has the same effect as -I. -I/special/include.

DEPENDENCIES_OUTPUT
If this variable is set, its value specifies how to output dependencies for Make based on the non-system header files processed by the compiler. System header files are ignored in the dependency output.

The value of DEPENDENCIES_OUTPUT can be just a file name, in which case the Make rules are written to that file, guessing the target name from the source file name. Or the value can have the form file target, in which case the rules are written to file file using target as the target name.

In other words, this environment variable is equivalent to combining the options -MM and -MF, with an optional -MT switch too.

SUNPRO_DEPENDENCIES
This variable is the same as DEPENDENCIES_OUTPUT (see above), except that system header files are not ignored, so it implies -M rather than -MM. However, the dependence on the main input file is omitted.
SOURCE_DATE_EPOCH
If this variable is set, its value specifies a UNIX timestamp to be used in replacement of the current date and time in the "__DATE__" and "__TIME__" macros, so that the embedded timestamps become reproducible.

The value of SOURCE_DATE_EPOCH must be a UNIX timestamp, defined as the number of seconds (excluding leap seconds) since 01 Jan 1970 00:00:00 represented in ASCII; identical to the output of "date +%s" on GNU/Linux and other systems that support the %s extension in the "date" command.

The value should be a known timestamp such as the last modification time of the source or package and it should be set by the build process.

NAME

cpp - C preprocessor

SYNOPSIS

cpp [OPTION]... [INPUT [OUTPUT]]

DESCRIPTION

GCC includes a preprocessor, named cpp, that runs before the principal compilation phase. The C preprocessor communicates with the C compiler to simplify the task of writing and maintaining programs. It supports several features:

  • Inclusion of header files: #include directives tell cpp to fetch the named file and insert its contents into the source code. This is used to share common definitions between different source files.

  • Macro expansions: #define directives allow you to define macros, which are symbolic names for chunks of code. cpp replaces these names with their corresponding definitions. Macros can be defined to accept arguments, like functions.

  • Conditional compilation: Directives like #if, #ifdef, #ifndef, #else, #elif and #endif allow you to include or exclude sections of code from the compilation based on whether certain conditions are true. This is useful for writing code that works on different platforms or for debugging purposes.

  • Line control: The #line directive allows you to specify the name of the current input file and the current line number. This is mainly used by compilers that generate C code.

cpp is usually invoked automatically by the compiler driver (e.g. gcc or g++). You can also invoke cpp directly, but this is rarely necessary.

OPTIONS

The full set of command-line options for cpp is very extensive. Here are some of the most common ones:

  • -DMACRO[=VALUE]

    : Define MACRO with VALUE. If VALUE is not given, it defaults to 1. This is equivalent to a #define directive in the source code.

  • -UMACRO

    : Undefine MACRO. This removes any previous definition of MACRO.

  • -IDIR

    : Add directory DIR to the list of directories searched for header files. The compiler searches these directories in the order you specify them.

  • -isystem DIR

    : Similar to -I, but the directory is treated as a system header directory. This means that warnings and errors related to files in this directory are suppressed.

  • -include FILE

    : Process FILE as if it appeared as the first #include directive in the source code. This is useful for including configuration headers.

  • -imacros FILE

    : Process FILE for macro definitions, and then discard the resulting tokens, before processing the main source file. This is useful for defining macros that will be available to the main source file.

  • -P

    : Do not generate #line directives. This is useful when you want to process the preprocessed output manually.

  • -C

    : Do not discard comments. By default, comments are discarded by cpp.

  • -cplusplus

    : This option is implicit when cpp is invoked by g++. It tells cpp to treat the input as C++ code, enabling C++-specific preprocessor features like trigraphs and the // comment syntax.

  • -traditional

    : Emulate traditional C preprocessor behavior. This option is generally discouraged.

  • -W...

    : Enable various compiler warnings. For example, -Wall enables most common warnings.

  • -o FILE

    : Write output to FILE instead of standard output. If omitted, and the input is a regular file, the output is sent to standard output. If the input is standard input, the output goes to standard output.

  • -v

    : Verbose mode. Print the commands as they are executed. This can be useful for debugging.

  • --help

    : Print a summary of the options and exit.

  • --version

    : Print version information and exit.

ENVIRONMENT

The behavior of cpp can be influenced by several environment variables:

  • CPATH, C_INCLUDE_PATH, CPLUS_INCLUDE_PATH

    : These variables specify directories to be searched for header files. CPATH is a general-purpose variable, while C_INCLUDE_PATH is specifically for C headers and CPLUS_INCLUDE_PATH is for C++ headers. They are searched in the order they appear in the variable, and after directories specified with the -I option.

  • TMPDIR

    : Specifies a directory where cpp can create temporary files. If not set, it defaults to /tmp.
