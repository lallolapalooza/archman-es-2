RIGSMTR(1) Utilidades Hamlib RIGSMTR(1)

NOMBRE

rigsmtr - mide el medidor S frente al acimut usando Hamlib

SINOPSIS

rigsmtr [-hvV] [-m id] [-r dispositivo] [-s velocidad] [-c id] [-C parámetro=valor] [-M id] [-R dispositivo] [-S velocidad] [-N parámetro=valor] [paso_tiempo]

DESCRIPCIÓN

rigsmtr usa Hamlib para controlar una radio y medir el valor del medidor S frente al acimut de la antena.

Rota la antena desde el acimut mínimo hasta el acimut máximo. Cada segundo, o paso_tiempo si se especifica en segundos, recupera la intensidad de la señal. El acimut en grados y el nivel correspondiente del medidor S en dB relativos a S9 se imprimen en stdout.

Para funcionar correctamente, rigsmtr necesita una radio que pueda medir el medidor S y un backend de Hamlib que sea capaz de recuperarlo, conectado a un rotador compatible con Hamlib.

Tenga en cuenta que Hamlib es software de nivel BETA. Aunque muchas bibliotecas de backend carecen de soporte completo para radios, las funciones básicas suelen estar bien soportadas.

Por favor, informe de errores y proporcione comentarios en la dirección de correo electrónico indicada en la sección ERRORES más abajo. Se aceptan parches y mejoras de código enviados a la misma dirección.

OPCIONES

Este programa sigue la sintaxis habitual de línea de comandos de GNU. Las opciones cortas que toman un argumento pueden tener el valor inmediatamente después o separado por un espacio. Las opciones largas que comienzan con dos guiones (‘-’) requieren un ‘=’ entre la opción y cualquier argumento.

Aquí hay un resumen de las opciones soportadas.

-m, --modelo=id
Selecciona el número del modelo de radio.
Ver lista de modelos (usa “rigctl -l”).
-r, --archivo-radio=dispositivo
Usa dispositivo como el nombre del archivo del puerto conectado a la radio.
A menudo un puerto serie, pero podría ser un adaptador USB a serie. Típicamente /dev/ttyS0, /dev/ttyS1, /dev/ttyUSB0, etc. en Linux, COM1, COM2, etc. en MS Windows. Los sabores BSD y Mac OS/X tienen sus propias designaciones. Consulte la documentación de su sistema.
-s, --velocidad-serie=velocidad
Establece la velocidad serie de la radio a velocidad baudios.
Utiliza la velocidad serie máxima de las capacidades del backend de la radio como valor predeterminado.
-c, --civaddr=id
Usa id como la dirección CI-V para comunicarse con la radio.
Solo útil para radios Icom y algunas Ten-Tec.
Nota: El id está en notación decimal, a menos que vaya precedido por 0x, en cuyo caso es hexadecimal.
-C, --set-conf=parámetro=valor[,parámetro=valor]
Establece uno o más parámetros de configuración de la radio, p. ej., stop_bits=2.
Utilice la opción -L de rigctl para obtener una lista de parámetros de configuración para un número de modelo dado.
-M, --modelo-rotador=id
Selecciona el número del modelo del rotador.
Ver lista de modelos (usa “rotctl -l”).
-R, --archivo-rotador=dispositivo
Usa dispositivo como el nombre del archivo del puerto conectado al rotador.
A menudo un puerto serie, pero podría ser un adaptador USB a serie. Típicamente /dev/ttyS0, /dev/ttyS1, /dev/ttyUSB0, etc. en Linux, COM1, COM2, etc. en MS Windows. Los sabores BSD y Mac OS/X tienen sus propias designaciones. Consulte la documentación de su sistema.
-S, --velocidad-serie-rotador=velocidad
Establece la velocidad serie del rotador a velocidad baudios.
Utiliza la velocidad serie máxima de las capacidades del backend del rotador como valor predeterminado.
-N, --rot-set-conf=parámetro=valor[,parámetro=valor]
Establece uno o más parámetros de configuración del rotador, p. ej., stop_bits=2.
Utilice la opción -L de rotctl para obtener una lista de parámetros de configuración para un número de modelo dado.
-v, --verbose
Establece el modo verboso, acumulativo (ver DIAGNÓSTICOS más abajo).
-h, --ayuda
Muestra un resumen de estas opciones y sale.
-V, --version
Muestra la versión de rigsmtr y sale.

Nota: Es posible que algunas opciones no estén implementadas por un backend determinado y devuelvan un error. Esto es más probable que ocurra con las opciones --set-conf y --rot-set-conf.

DIAGNÓSTICOS

La opción -v, --verbose permite diferentes niveles de diagnósticos que se envían a stderr y corresponden a -v para BUG, -vv para ERR, -vvv para WARN, -vvvv para VERBOSE, o -vvvvv para TRACE.

Un nivel de verbosidad determinado es útil para proporcionar la información de depuración necesaria a la dirección de correo electrónico abajo. Por ejemplo, la salida TRACE muestra todos los valores enviados y recibidos de la radio, lo cual es muy útil para el desarrollo de bibliotecas de backend de radio y puede ser solicitado por los desarrolladores.

ESTADO DE SALIDA

rigsmtr sale con:

0
si todas las operaciones se completaron normalmente;
1
si hubo una opción o argumento de línea de comandos inválido;
2
si Hamlib devolvió un error;
3
si la radio no tiene las capacidades requeridas.

EJEMPLO

Recopila lecturas del medidor S en un TS-850 mientras un rotador EasycommII realiza una rotación completa de 360° y guarda las mediciones en el archivo csmtr (el texto escrito se muestra en negrita):


$ rigsmtr -m 2009 -r /dev/ttyS1 -M 202 > csmtr

Después de la finalización, el archivo csmtr contiene líneas como:


0 -47
30 -40
60 -22
90 -3
120 10
150 1
180 -11
210 -24
240 -35
270 -42
300 -48
330 -51
360 -49

Los resultados se pueden graficar con gnuplot(1):


$ gnuplot
set angles degrees
set polar
set grid polar 15.
unset border
unset param
set style data line
set rrange [-60:60]
set xrange [-60:60]
set yrange [-60:60]
plot csmtr
