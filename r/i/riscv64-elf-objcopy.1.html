DESCRIPCION

La utilidad GNU objcopy copia el contenido de un archivo objeto a otro. objcopy utiliza la Biblioteca GNU BFD para leer y escribir archivos objeto. Puede escribir el archivo objeto de destino en un formato diferente al del archivo objeto de origen. El comportamiento exacto de objcopy se controla mediante opciones de línea de comandos. Tenga en cuenta que objcopy debería ser capaz de copiar un archivo completamente enlazado entre dos formatos cualesquiera. Sin embargo, copiar un archivo objeto relocable entre dos formatos cualesquiera puede no funcionar como se espera.

objcopy crea archivos temporales para realizar sus traducciones y los elimina después. objcopy utiliza BFD para realizar todo su trabajo de traducción; tiene acceso a todos los formatos descritos en BFD y, por lo tanto, es capaz de reconocer la mayoría de los formatos sin que se le indique explícitamente.

objcopy se puede utilizar para generar registros S (S-records) utilizando un formato de salida srec (por ejemplo, use -O srec).

objcopy se puede utilizar para generar un archivo binario crudo (raw binary) utilizando un formato de salida binary (por ejemplo, use -O binary). Cuando objcopy genera un archivo binario crudo, esencialmente producirá un volcado de memoria del contenido del archivo objeto de entrada. Se descartará toda la información de símbolos y relocaciones. El volcado de memoria comenzará en la dirección de carga de la sección más baja copiada en el archivo de salida.

Al generar un archivo S-record o binario crudo, puede ser útil usar -S para eliminar secciones que contengan información de depuración. En algunos casos, -R será útil para eliminar secciones que contengan información que no sea necesaria para el archivo binario.

Nota---objcopy no es capaz de cambiar la endianidad de sus archivos de entrada. Si el formato de entrada tiene una endianidad (algunos formatos no la tienen), objcopy solo puede copiar las entradas a formatos de archivo que tengan la misma endianidad o que no tengan ninguna endianidad (por ejemplo, srec). (Sin embargo, consulte la opción --reverse-bytes).

OPCIONES

archivo_entrada
archivo_salida
Los archivos de entrada y salida, respectivamente. Si no especifica archivo_salida, objcopy crea un archivo temporal y renombra destructivamente el resultado con el nombre de archivo_entrada.
-I nombrebfd
--input-target=nombrebfd
Considere que el formato objeto del archivo de origen es nombrebfd, en lugar de intentar deducirlo.
-O nombrebfd
--output-target=nombrebfd
Escriba el archivo de salida utilizando el formato objeto nombrebfd.
-F nombrebfd
--target=nombrebfd
Use nombrebfd como formato objeto tanto para el archivo de entrada como para el de salida; es decir, simplemente transfiera datos de origen a destino sin traducción.
-B arquitectura_bfd
--binary-architecture=arquitectura_bfd
Útil al transformar un archivo de entrada sin arquitectura a un archivo objeto. En este caso, la arquitectura de salida se puede establecer en arquitectura_bfd. Esta opción se ignorará si el archivo de entrada tiene una arquitectura_bfd conocida. Puede acceder a estos datos binarios dentro de un programa haciendo referencia a los símbolos especiales que se crean durante el proceso de conversión. --long-section-names {enable,disable,keep}
Controla el manejo de nombres de sección largos al procesar los formatos de objeto "COFF" y "PE-COFF". El comportamiento predeterminado, keep, es preservar los nombres de sección largos si hay alguno presente en el archivo de entrada. Las opciones enable y disable habilitan o deshabilitan forzosamente el uso de nombres de sección largos en el objeto de salida; cuando disable está activo, los nombres de sección largos en el objeto de entrada se truncarán. La opción enable solo emitirá nombres de sección largos si hay algunos presentes en las entradas; esto es en gran medida lo mismo que keep, pero se deja sin definir si la opción enable podría forzar la creación de una tabla de cadenas vacía en el archivo de salida.
--change-leading-char
Algunos formatos de archivo objeto utilizan caracteres especiales al inicio de los símbolos. El carácter más común es el guion bajo, que los compiladores a menudo añaden antes de cada símbolo. Esta opción le indica a objcopy que cambie el carácter inicial de cada símbolo al convertir entre formatos de archivo objeto. Si los formatos de archivo objeto utilizan el mismo carácter inicial, esta opción no tiene ningún efecto. De lo contrario, añadirá un carácter, eliminará un carácter o cambiará un carácter, según corresponda.
--remove-leading-char
Si el primer carácter de un símbolo global es un carácter inicial de símbolo especial utilizado por el formato del archivo objeto, elimina el carácter. El carácter inicial de símbolo más común es el guion bajo. Esta opción eliminará un guion bajo inicial de todos los símbolos globales. Esto puede ser útil si desea enlazar objetos de diferentes formatos de archivo con diferentes convenciones para nombres de símbolos. Esto es diferente de --change-leading-char porque siempre cambia el nombre del símbolo cuando es apropiado, independientemente del formato del archivo objeto de salida.
--reverse-bytes=num
Invierte los bytes en una sección con contenidos de salida. La longitud de una sección debe ser divisible exactamente por el valor dado para que el intercambio pueda realizarse. La inversión se realiza antes de que se realice el intercalado.

Esta opción se utiliza típicamente en la generación de imágenes ROM para sistemas de destino problemáticos. Por ejemplo, en algunas placas de destino, las palabras de 32 bits obtenidas de las ROM de 8 bits se vuelven a ensamblar en orden de bytes little-endian, independientemente del orden de bytes de la CPU. Dependiendo del modelo de programación, es posible que sea necesario modificar la endianidad de la ROM.

Considere un archivo simple con una sección que contiene los siguientes ocho bytes: 12345678.

Usando --reverse-bytes=2 para el ejemplo anterior, los bytes en el archivo de salida tendrían el orden 21436587.

Usando --reverse-bytes=4 para el ejemplo anterior, los bytes en el archivo de salida tendrían el orden 43218765.

Usando --reverse-bytes=2 para el ejemplo anterior, seguido de --reverse-bytes=4 en el archivo de salida, los bytes en el segundo archivo de salida tendrían el orden 34127856.

--alt-machine-code=index
Si la arquitectura de salida tiene códigos de máquina alternativos, utiliza el index-ésimo código en lugar del predeterminado. Esto es útil en caso de que una máquina reciba un código oficial y la cadena de herramientas adopte el nuevo código, pero otras aplicaciones sigan dependiendo del uso del código original. Para arquitecturas basadas en ELF, si la alternativa index no existe, el valor se trata como un número absoluto que se almacenará en el campo e_machine de la cabecera ELF.
--writable-text
Marca el texto de salida como escribible. Esta opción no es significativa para todos los formatos de archivo objeto.
--readonly-text
Hace que el texto de salida esté protegido contra escritura. Esta opción no es significativa para todos los formatos de archivo objeto.
--pure
Marca el archivo de salida como paginado bajo demanda. Esta opción no es significativa para todos los formatos de archivo objeto.
--impure
Marca el archivo de salida como impuro. Esta opción no es significativa para todos los formatos de archivo objeto.
--prefix-symbols=string
Antepone string a todos los símbolos del archivo de salida.
--prefix-sections=string
Antepone string a todos los nombres de sección del archivo de salida.
--prefix-alloc-sections=string
Antepone string a los nombres de todas las secciones asignadas en el archivo de salida.
--add-gnu-debuglink=path-to-file
Crea una sección .gnu_debuglink que contiene una referencia a path-to-file y la añade al archivo de salida. Nota: el archivo en path-to-file debe existir. Parte del proceso de añadir la sección .gnu_debuglink implica incrustar una suma de verificación del contenido del archivo de depuración en la sección.

Si el archivo de información de depuración se compila en una ubicación pero se instalará más tarde en una ubicación diferente, no utilice la ruta a la ubicación de instalación. La opción --add-gnu-debuglink fallará porque el archivo instalado aún no existe. En su lugar, coloque el archivo de información de depuración en el directorio actual y utilice la opción --add-gnu-debuglink sin componentes de directorio, de la siguiente manera:

objcopy --add-gnu-debuglink=foo.debug

En tiempo de depuración, el depurador intentará buscar el archivo de información de depuración separado en un conjunto de ubicaciones conocidas. El conjunto exacto de estas ubicaciones varía según la distribución utilizada, pero generalmente incluye:

"* El mismo directorio que el ejecutable."
"* Un subdirectorio del directorio que contiene el ejecutable"
llamado .debug
"* Un directorio global de depuración como /usr/lib/debug."

Siempre que el archivo de información de depuración se instale en una de estas ubicaciones antes de que se ejecute el depurador, todo debería funcionar correctamente.

--keep-section-symbils
--keep-section-symbols
Al depurar un archivo, quizás con --strip-debug o --strip-unneeded, conserva cualquier símbolo que especifique nombres de sección, que de otro modo se depurarían.
--keep-file-symbols
Al depurar un archivo, quizás con --strip-debug o --strip-unneeded, conserva cualquier símbolo que especifique nombres de archivos fuente, que de otro modo se depurarían.
--only-keep-debug
Depura un archivo, eliminando el contenido de cualquier sección que no sería depurada por --strip-debug y dejando intactas las secciones de depuración. En archivos ELF, esto preserva todas las secciones de notas en la salida.

Nota: las cabeceras de sección de las secciones depuradas se conservan, incluidos sus tamaños, pero el contenido de la sección se descarta. Las cabeceras de sección se conservan para que otras herramientas puedan vincular el archivo de información de depuración con el ejecutable real, incluso si ese ejecutable se ha reubicado en un espacio de direcciones diferente.

La intención es que esta opción se utilice junto con --add-gnu-debuglink para crear un ejecutable de dos partes. Una, un binario depurado que ocupará menos espacio en RAM y en una distribución, y la segunda, un archivo de información de depuración que solo se necesita si se requieren capacidades de depuración. El procedimiento sugerido para crear estos archivos es el siguiente:

1.<Enlaza el ejecutable como de costumbre. Suponiendo que se llama>
"foo" entonces...
1.<Ejecuta "objcopy --only-keep-debug foo foo.dbg" para>
crear un archivo que contenga la información de depuración.
1.<Ejecuta "objcopy --strip-debug foo" para crear un>
ejecutable depurado.
1.<Ejecuta "objcopy --add-gnu-debuglink=foo.dbg foo">
para agregar un enlace a la información de depuración en el ejecutable depurado.

Nota: la elección de ".dbg" como extensión para el archivo de información de depuración es arbitraria. También el paso "--only-keep-debug" es opcional. Puedes hacer esto en su lugar:

1.<Enlaza el ejecutable como de costumbre.>
1.<Copia "foo" a "foo.full">
1.<Ejecuta "objcopy --strip-debug foo">
1.<Ejecuta "objcopy --add-gnu-debuglink=foo.full foo">

es decir, el archivo al que apunta --add-gnu-debuglink puede ser el ejecutable completo. No tiene que ser un archivo creado por el conmutador --only-keep-debug.

Nota: este conmutador solo está destinado a usarse en archivos completamente enlazados. No tiene sentido usarlo en archivos objeto donde la información de depuración puede estar incompleta. Además, la característica gnu_debuglink actualmente solo admite la presencia de un nombre de archivo que contenga información de depuración, no múltiples nombres de archivo en una base de un archivo por objeto.

--strip-dwo
Elimina el contenido de todas las secciones DWARF .dwo, dejando intactas las secciones de depuración restantes y todos los símbolos. Esta opción está destinada a ser utilizada por el compilador como parte de la opción -gsplit-dwarf, que divide la información de depuración entre el archivo .o y un archivo .dwo separado. El compilador genera toda la información de depuración en el mismo archivo, luego utiliza la opción --extract-dwo para copiar las secciones .dwo al archivo .dwo, y luego la opción --strip-dwo para eliminar esas secciones del archivo .o original.
--extract-dwo
Extrae el contenido de todas las secciones DWARF .dwo. Consulte la opción --strip-dwo para obtener más información.
--file-alignment num
Especifica la alineación de archivo. Las secciones en el archivo siempre comenzarán en offsets de archivo que son múltiplos de este número. El valor predeterminado es 512. [Esta opción es específica para destinos PE.]
--heap reserve
--heap reserve,commit
Especifica el número de bytes de memoria a reservar (y opcionalmente confirmar) para ser utilizados como heap para este programa. [Esta opción es específica para destinos PE.]
--image-base value
Utiliza value como la dirección base de tu programa o dll. Esta es la ubicación de memoria más baja que se utilizará cuando tu programa o dll se cargue. Para reducir la necesidad de reubicar y mejorar el rendimiento de tus dlls, cada una debe tener una dirección base única y no superponerse con ninguna otra dll. El valor predeterminado es 0x400000 para ejecutables y 0x10000000 para dlls. [Esta opción es específica para destinos PE.]
--section-alignment num
Establece el campo de alineación de sección en la cabecera PE. Las secciones en memoria siempre comenzarán en direcciones que sean múltiplos de este número. El valor predeterminado es 0x1000. [Esta opción es específica para destinos PE.]
--stack reserve
--stack reserve,commit
Especifica el número de bytes de memoria a reservar (y opcionalmente confirmar) para ser utilizados como stack para este programa. [Esta opción es específica para destinos PE.]
--subsystem which
--subsystem which:major
--subsystem which:major.minor
Especifica el subsistema bajo el cual se ejecutará tu programa. Los valores legales para which son "native", "windows", "console", "posix", "efi-app", "efi-bsd", "efi-rtd", "sal-rtd", y "xbox". Opcionalmente, también puedes establecer la versión del subsistema. También se aceptan valores numéricos para which. [Esta opción es específica para destinos PE.]
--extract-symbol
Mantiene las marcas de sección y los símbolos del archivo, pero elimina todos los datos de las secciones. Específicamente, la opción:
*<elimina el contenido de todas las secciones;>
*<establece el tamaño de cada sección a cero; y>
*<establece la dirección de inicio del archivo a cero.>

Esta opción se utiliza para construir un archivo .sym para un kernel VxWorks. También puede ser una forma útil de reducir el tamaño de un archivo de entrada del enlazador --just-symbols.

--compress-debug-sections
Comprime las secciones de depuración DWARF utilizando zlib con SHF_COMPRESSED de la ABI ELF. Nota: si la compresión realmente hiciera que una sección sea más grande, entonces no se comprime.
--compress-debug-sections=none
--compress-debug-sections=zlib
--compress-debug-sections=zlib-gnu
--compress-debug-sections=zlib-gabi
--compress-debug-sections=zstd
Para archivos ELF, estas opciones controlan cómo se comprimen las secciones de depuración DWARF. --compress-debug-sections=none es equivalente a --decompress-debug-sections. --compress-debug-sections=zlib y --compress-debug-sections=zlib-gabi son equivalentes a --compress-debug-sections. --compress-debug-sections=zlib-gnu comprime las secciones de depuración DWARF utilizando el formato obsoleto zlib-gnu. Las secciones de depuración se renombran para que comiencen con .zdebug. --compress-debug-sections=zstd comprime las secciones de depuración DWARF utilizando zstd. Nota: si la compresión realmente hiciera que una sección sea más grande, entonces no se comprime ni se renombra.
--decompress-debug-sections
Descomprime las secciones de depuración DWARF. Para una sección .zdebug, se restaura el nombre original.
--elf-stt-common=yes
--elf-stt-common=no
Para archivos ELF, estas opciones controlan si los símbolos comunes deben convertirse al tipo "STT_COMMON" o "STT_OBJECT". --elf-stt-common=yes convierte el tipo de símbolo común a "STT_COMMON". --elf-stt-common=no convierte el tipo de símbolo común a "STT_OBJECT".
--merge-notes
--no-merge-notes
Para archivos ELF, intenta (o no intenta) reducir el tamaño de cualquier sección de tipo SHT_NOTE eliminando notas duplicadas.
-V
--version
Muestra el número de versión de objcopy.
--verilog-data-width=bytes
Para la salida Verilog, esta opción controla el número de bytes convertidos para cada elemento de datos de salida. El destino de entrada controla la endianidad de la conversión.
-v
--verbose
Salida detallada: lista todos los archivos objeto modificados. En el caso de los archivos, objcopy -V lista todos los miembros del archivo.
--help
Muestra un resumen de las opciones de objcopy.
--info
Muestra una lista que indica todas las arquitecturas y formatos de objeto disponibles.
@file
Lee comandos de

OPCIONES

...
Las opciones de línea se leen de archivo. Las opciones leídas se insertan en lugar de la opción original @archivo. Si archivo no existe, o no se puede leer, entonces la opción se tratará literalmente y no se eliminará.

Las opciones en archivo están separadas por espacios en blanco. Un carácter de espacio en blanco puede incluirse en una opción rodeando la opción completa con comillas simples o dobles. Cualquier carácter (incluyendo una barra invertida) puede incluirse anteponiendo una barra invertida al carácter que se va a incluir. El archivo puede contener opciones @archivo adicionales; dichas opciones se procesarán recursivamente.
