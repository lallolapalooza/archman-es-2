RGBASM(5) Manual de Formatos de Archivo RGBASM(5)

NOMBRE

rgbasm — documentación del lenguaje de ensamblado

DESCRIPCIÓN

Esta es la descripción completa del lenguaje de ensamblado utilizado por rgbasm(1). Para la descripción completa de las instrucciones en el lenguaje máquina soportado por la CPU de Game Boy, ver gbz80(7).

Es recomendable tener cierta familiaridad con el hardware de Game Boy antes de leer este documento. RGBDS está específicamente dirigido a Game Boy, y por lo tanto muchas de sus características se vinculan directamente con sus conceptos. Este documento no pretende ser una referencia del hardware de Game Boy.

Generalmente, "el enlazador" se referirá a rgblink(1), pero cualquier programa que procese archivos objeto de RGBDS (descritos en rgbds(5)) puede usarse en su lugar.

SINTAXIS

La sintaxis es basada en líneas, como en cualquier otro ensamblador. Cada línea puede tener componentes en este orden:

[directiva] [; comentario]
[etiqueta:] [instrucción [:: instrucción ...]] [; comentario]

Las directivas son comandos para el propio ensamblador, como PRINTLN, SECTION o OPT.

Las etiquetas asocian un nombre a una ubicación específica dentro de una sección (ver Etiquetas abajo).

Las instrucciones se ensamblan en opcodes de Game Boy. Múltiples instrucciones en una línea pueden separarse por dos puntos ‘::’.

Las instrucciones disponibles están documentadas en gbz80(7).

Tenga en cuenta que donde una instrucción requiere un registro de 8 bits r8, rgbasm puede interpretar HIGH(r16) como el registro de 8 bits superior del r16 dado, por ejemplo, HIGH(HL) para H; y LOW(r16) como el inferior, por ejemplo, LOW(HL) para L (excepto para LOW(AF), ya que F no es un registro válido).

Tenga en cuenta también que donde una instrucción requiere un código de condición cc, rgbasm puede interpretar !cc como el código de condición opuesto; por ejemplo, !nz para z.

Todas las palabras clave reservadas (directivas, nombres de registro, etc.) no distinguen entre mayúsculas y minúsculas; todos los identificadores (etiquetas y otros nombres de símbolos) distinguen entre mayúsculas y minúsculas.

Los comentarios se utilizan para proporcionar información a los humanos sobre el código, como explicaciones. El ensamblador siempre ignora los comentarios y su contenido.

Hay dos tipos de comentarios, en línea y de bloque. Los comentarios en línea son todo lo que sigue a un punto y coma ‘;’ que no esté dentro de una cadena, hasta el final de la línea. Los comentarios de bloque, que comienzan con ‘/*’ y terminan con ‘*/’, pueden dividirse en varias líneas, o aparecer en medio de una expresión.

Un ejemplo que demuestra estas características de sintaxis:

SECTION "Mi Código", ROM0  ; una directiva
MiFunción:              ; una etiqueta
    push hl              ; una instrucción
    /* ...y múltiples instrucciones,
       con mayúsculas y minúsculas mezcladas */
    ld a, [hli] :: LD H, [HL] :: Ld l, a
    pop /*espera un momento*/ hl
    ret

A veces las líneas pueden ser demasiado largas y puede ser necesario dividirlas. Para hacerlo, coloque una barra invertida al final de la línea:

    DB 1, 2, 3, \
       4, 5, 6, \ ; Ponlo antes de cualquier comentario
       7, 8, 9
    DB "Hola, \  ; Se incluye el espacio antes de la \
mundo!"           ; Se incluyen los espacios iniciales

Interpolación de símbolos

Una característica peculiar es escribir un símbolo entre ‘{llaves}’, llamada "interpolación de símbolos". Esto pegará el contenido del símbolo como si fueran parte del archivo fuente. Si es un símbolo de cadena, sus caracteres se insertan tal cual. Si es un símbolo numérico, su valor se convierte a notación hexadecimal con un signo de dólar ‘$’ delante.

Las interpolaciones de símbolos también se pueden anidar.

DEF tema EQUS "la vida, el universo y \"todo\""
DEF significado EQUS "respuesta"
; Define respuesta = 42
DEF {significado} = 42
; Imprime "La respuesta a la vida, el universo y "todo" es $2A"
PRINTLN "La {significado} a {tema} es {{significado}}"
PURGE tema, significado, {significado}

Los símbolos pueden ser interpolados incluso en contextos que deshabilitan la expansión automática de constantes de cadena: ‘nombre’ se expandirá en todos los casos de ‘DEF({nombre})’, ‘DEF {nombre} EQU/=/EQUS/etc ...’, ‘PURGE {nombre}’ y ‘MACRO {nombre}’, pero, por ejemplo, no en ‘DEF(nombre)’.

Es posible cambiar la forma en que se imprimen los símbolos especificando un formato de impresión de la siguiente manera: ‘{fmt:símbolo}’. El especificador ‘fmt’ consta de las siguientes partes: ‘<signo><exacto><alineación><relleno><ancho><fracción><precisión><tipo>’. Estas partes son:

Parte Significado
‘<signo>’ Puede ser ‘+’ o ‘ ’. Si se especifica, imprime este carácter delante de números no negativos.
‘<exacto>’ Puede ser ‘#’. Si se especifica, imprime el valor en un formato "exacto": con un prefijo de base para tipos enteros no decimales (‘$’, ‘&’ o ‘%’); con un sufijo de precisión ‘q’ para números de punto fijo; o con caracteres de escape ‘\’ para cadenas.
‘<alineación>’ Puede ser ‘-’. Si se especifica, alinea a la izquierda en lugar de a la derecha.
‘<relleno>’ Puede ser ‘0’. Si se especifica, rellena los números alineados a la derecha con ceros en lugar de espacios.
‘<ancho>’ Puede ser uno o más ‘0’ – ‘9’. Si se especifica, rellena el valor hasta este ancho, alineado a la derecha con espacios por defecto.
‘<fracción>’ Puede ser ‘.’ seguido de uno o más ‘0’ – ‘9’. Si se especifica, imprime esta cantidad de dígitos fraccionales de un número de punto fijo. El valor predeterminado es 5 dígitos, máximo 255 dígitos.
‘<precisión>’ Puede ser ‘q’ seguido de uno o más ‘0’ – ‘9’. Si se especifica, imprime esta cantidad de dígitos de un número entero, por ejemplo, ‘q8’. El valor predeterminado es 0 dígitos, máximo 255 dígitos.
‘<tipo>’ Puede ser ‘d’, ‘x’, ‘X’, ‘o’, ‘b’, ‘c’, ‘s’, ‘p’ o ‘e’. Imprime el número como decimal, hexadecimal con minúsculas, hexadecimal con mayúsculas, octal, binario, como un carácter, como una cadena, como un puntero (como hexadecimal) o en notación científica (base 10), respectivamente. Si se omite, se utiliza ‘d’ para los números enteros y ‘s’ para las cadenas.

Por ejemplo, para imprimir la variable v con un ancho de 4, rellenada con ceros a la izquierda y en hexadecimal, escribiría {04x:v}.

Si se desea imprimir un literal de coma flotante, se puede usar el especificador de tipo ‘f’. Para los literales de punto fijo, use ‘q’.

Este es un ejemplo de algunos de los formatos:

DEF valor_hex EQUS "$AABB"
DEF valor_dec EQUS "42"
PRINTLN "Hex: {valor_hex}, Decimal: {valor_dec}"
PRINTLN "Hex: {04X:valor_hex}, Decimal: {04d:valor_dec}"

018;0’ – ‘9’. Si se especifica, imprime un número de punto fijo con esta precisión. Por defecto, utiliza la opción -Q actual. ‘<type>’ Especifica el tipo de valor.

Todas las partes del especificador de formato son opcionales, excepto el ‘<type>’. Los tipos de impresión válidos son:

Tipo Formato Ejemplo
‘d’ Decimal con signo -42
‘u’ Decimal sin signo 42
‘x’ Hexadecimal en minúsculas 2a
‘X’ Hexadecimal en mayúsculas 2A
‘b’ Binario 101010
‘o’ Octal 52
‘f’ Punto fijo 1234.56789
‘s’ Cadena contenido de la cadena

Ejemplos:

SECTION "Prueba", ROM0[2]
X:                 ; Esto funciona con etiquetas **cuya dirección es conocida**
DEF Y = 3          ; Esto también funciona con variables
DEF SUMA EQU X + Y  ; Y lo mismo con constantes numéricas
; Imprime "%0010 + $3 == 5"
PRINTLN "{#05b:X} + {#x:Y} == {d:SUMA}"

rsset 32
DEF PORCENTAJE rb 1   ; Lo mismo con constantes de desplazamiento
DEF VALOR = 20
DEF RESULTADO = MUL(20.0, 0.32)
; Imprime "32% de 20 = 6.40"
PRINTLN "{d:PORCENTAJE}% de {d:VALOR} = {f:RESULTADO}"

DEF QUIEN EQUS STRLWR("MUNDO")
; Imprime "Hola mundo!"
PRINTLN "Hola {s:QUIEN}!"

Aunque, para estos ejemplos, STRFMT sería más apropiado; ver Expresiones de cadena más abajo.

EXPRESIONES

Una expresión puede estar compuesta de muchas cosas. Las expresiones numéricas siempre se evalúan utilizando aritmética de 32 bits con signo. El cero se considera el único número "falso", todos los números distintos de cero (incluidos los negativos) son "verdaderos".

Se dice que una expresión es "constante" si rgbasm conoce su valor. Este es generalmente siempre el caso, a menos que intervenga una etiqueta, como se explica en la sección de SÍMBOLOS. Sin embargo, algunos operadores pueden ser constantes incluso con operandos no constantes, como se explica en Operadores más abajo.

Las instrucciones del lenguaje de macros generalmente requieren expresiones constantes.

Formatos numéricos

Hay una serie de formatos numéricos.

Tipo de formato Prefijos posibles Caracteres aceptados

Hexadecimal $, 0x, 0X 0123456789ABCDEF
Octal &, 0o, 0O 01234567
Binario %, 0b, 0B 01
Punto fijo ninguno 01234.56789

Los guiones bajos también se aceptan en números, excepto al principio. Esto puede ser útil para agrupar dígitos, como ‘123_456’ o ‘%1100_1001’.

La forma de "constante de carácter" produce el valor al que se mapea el carácter en el mapa de caracteres actual. Por ejemplo, por defecto (consulte ascii(7)), ‘'A'’ produce 65. Una constante de carácter debe representar un único valor, por lo que no puede incluir varios caracteres o caracteres que se mapeen a varios valores. Consulte Mapas de caracteres para obtener información sobre los mapas de caracteres y Expresiones de cadena para obtener información sobre los caracteres de escape permitidos en las constantes de carácter.

El último, gráficos de Game Boy, es bastante interesante y útil. Después del acento grave, se esperan 8 dígitos entre 0 y 3, correspondientes a los valores de píxel. El valor resultante son los dos bytes de datos de tile que producirían esa fila de píxeles. Por ejemplo, ‘`01012323’ es equivalente a ‘$0F55’.

También puede utilizar símbolos, que se reemplazan implícitamente por su valor.

Operadores

Puede utilizar estos operadores en expresiones numéricas (listados de mayor a menor precedencia):

Operador Significado
( ) Agrupación
FUNC() Llamada a función incorporada
** Exponenciación
+ - ~ ! Signo más unario, menos (negación), complemento (negación bit a bit) y negación booleana
* / % Multiplicación, división y módulo (resto)
<< >> >>> Desplazamientos de bits (izquierda, derecha con extensión de signo, derecha con extensión de cero)
& | ^ AND/OR/XOR bit a bit
+ - Suma y resta
== != < > <= >= Comparaciones
&& AND booleano
|| OR booleano

‘**’ eleva un número a una potencia no negativa. Es el único operador asociativo por la derecha, lo que significa que ‘p ** q ** r’ es igual a ‘p ** (q ** r)’, no a ‘(p ** q) ** r’. Todos los demás operadores binarios son asociativos por la izquierda.

‘~’ complementa un valor invirtiendo sus 32 bits.

‘%’ se utiliza para obtener el resto de la división correspondiente, de modo que ‘x / y * y + x % y == x’ sea siempre cierto. El resultado tiene el mismo signo que el divisor. Esto hace que ‘x % y’ sea igual a ‘(x + y) % y’ o ‘(x - y) % y’.

Los desplazamientos funcionan desplazando todos los bits del operando izquierdo hacia la izquierda (‘<<’) o hacia la derecha (‘>>’) según la cantidad del operando derecho. Al desplazar hacia la izquierda, todos los bits recién insertados se reinician; al desplazar hacia la derecha, son copias del bit más significativo original en su lugar. Esto hace que ‘a << b’ y ‘a >> b’ sean equivalentes a multiplicar y dividir por 2 elevado a la potencia de b, respectivamente.

Los operadores de comparación devuelven 0 si la comparación es falsa y 1 en caso contrario.

A diferencia de muchos otros lenguajes, y por razones técnicas, rgbasm todavía evalúa ambos operandos de ‘&&’ y ‘||’.

Los operadores ‘&&’ y ‘&’ con una constante cero como uno de los operandos serán constantes 0, y ‘||’ con una constante distinta de cero como uno de los operandos será constante 1, incluso si el otro operando no es constante.

‘!’ devuelve 1 si el operando era 0 y 0 en caso contrario. Incluso un operando no constante con bits distintos de cero devolverá 0.

Expresiones de punto fijo

Los números de punto fijo son técnicamente solo enteros, pero conceptualmente tienen un punto decimal en una ubicación fija (de ahí el nombre). Esto les da una mayor precisión, a costa de un rango más pequeño, y sigue siendo mucho más económico de manipular que los números de punto flotante (que rgbasm no soporta).

La precisión predeterminada de todos los números de punto fijo es de 16 bits, lo que significa que los 16 bits inferiores se utilizan para la parte fraccionaria; por lo tanto, cuentan en 65536avos de 1.0. Esta precisión puede cambiarse con la opción de línea de comandos -Q, y/o con OPT Q (ver Cambiar opciones mientras se ensambla). Un literal individual de punto fijo puede especificar su propia precisión, anulando la predeterminada actual, añadiendo una “q” seguida del número de bits fraccionarios: por ejemplo, ‘1234.5q8’ es igual a $0004d2_80 ( =1234.5*28 ).

Dado que los valores de punto fijo siguen siendo solo enteros, puede utilizarlos en expresiones enteras normales. Puede truncar fácilmente un número de punto fijo a un entero desplazándolo a la derecha por el número de bits fraccionarios. Se deduce que puede convertir un entero a un número de punto fijo desplazándolo a la izquierda esa misma cantidad.

Tenga en cuenta que el número actual de bits fraccionarios se puede calcular como TZCOUNT(1.0).

POW(x, y) xy

No hay funciones para suma y resta de punto fijo, porque los operadores ‘+’ y ‘-’ pueden sumar y restar pares de operandos de punto fijo.

Tenga en cuenta que algunos operadores o funciones tienen sentido al combinar enteros y valores de punto fijo. Por ejemplo, ‘2.0 * 3’ es equivalente a ‘MUL(2.0, 3.0)’, y ‘6.0 / 2’ es equivalente a ‘DIV(6.0, 2.0)’. Tenga cuidado y piense en el significado de las operaciones al hacer este tipo de cosas.

Todas estas funciones de punto fijo pueden tomar un argumento final opcional, que es la precisión a usar para esa operación individual. Por ejemplo, ‘MUL(6.0q8, 7.0q8, 8)’ se evaluará como ‘42.0q8’ sin importar el valor establecido como la opción actual Q. rgbasm no verifica la consistencia de las precisiones, por lo que una entrada sin sentido como ‘MUL(4.2q8, 6.9q12, 16)’ producirá un resultado sin sentido (pero técnicamente correcto): “basura entra, basura sale”.

La función FMOD se utiliza para obtener el resto de la división de punto fijo correspondiente, de modo que ‘MUL(DIV(x, y), y) + FMOD(x, y) == x’ siempre sea verdadera. El resultado tiene el mismo signo que el dividendo; ¡esto es lo opuesto a cómo funciona el operador módulo entero ‘%’!

Las funciones trigonométricas (SIN, COS, TAN, etc) se definen en términos de un círculo dividido en 1.0 “giros” (igual a 2π radianes, o 360 grados).

Estas funciones son útiles para la generación automática de varias tablas. Por ejemplo:

; Generar una tabla de 128 valores de seno
; de sin(0.0) a sin(0.5) excluido,
; con amplitud escalada de [-1.0, 1.0] a [0.0, 128.0].
FOR angle, 0.0, 0.5, 0.5 / 128
    db MUL(SIN(angle) + 1.0, 128.0 / 2) >> 16
ENDR

Expresiones de cadena

La expresión de cadena más básica es cualquier número de caracteres contenido entre comillas dobles (‘"por ejemplo"’). El carácter de barra invertida ‘\’ es especial, ya que hace que el carácter que le sigue sea “escapado”, lo que significa que se trata de manera diferente de lo normal. Hay una serie de secuencias de escape que puede usar dentro de una cadena:

Secuencia Significado
‘\\’ Barra invertida (escapa el carácter de escape en sí)
‘\"’ Comilla doble (no termina una cadena)
‘\'’ Comilla simple (no termina un literal de carácter)
‘\{’ Llave de apertura (no inicia la interpolación)
‘\}’ Llave de cierre (no finaliza la interpolación)
‘\n’ Nueva línea (ASCII $0A)
‘\r’ Retorno de carro (ASCII $0D)
‘\t’ Tabulación (ASCII $09)
‘\0’ Nulo (ASCII $00)

Las cadenas multilínea están contenidas entre triple comillas (‘"""por ejemplo"""’). Las secuencias de escape funcionan de la misma manera en las cadenas multilínea; sin embargo, los caracteres de nueva línea literales se incluirán tal cual, sin necesidad

dida para escaparles con ‘\r’ o ‘\n’.

Las cadenas raw se prefijan con un hash ‘#’. Dentro de ellas, las barras invertidas y las llaves se tratan como caracteres normales, por lo que no se expandirán como argumentos de macro, símbolos interpolados o secuencias de escape. Por ejemplo, la cadena raw ‘#"\t\1{s}\"’ es equivalente a la cadena normal ‘"\\t\\1\{s}\\"’. (Nótese que esto evita que las cadenas raw incluyan el carácter de comillas dobles). Las cadenas raw también pueden estar contenidas en comillas triples para que sean multilínea, de modo que puedan incluir caracteres de nueva línea o comillas literales (aunque todavía no tres comillas seguidas).

Puedes usar el operador ‘++’ para concatenar dos cadenas. ‘"str" ++ "ing"’ es equivalente a ‘"string"’, o a ‘STRCAT("str", "ing")’.

Mapas de caracteres

Al escribir cadenas de texto que se mostrarán en la Game Boy, la codificación de caracteres en la ROM puede ser diferente de la codificación del archivo de origen. Por ejemplo, las fichas utilizadas para las letras mayúsculas pueden colocarse comenzando en el índice de ficha 128, lo que difiere del ASCII que comienza en 65.

Los mapas de caracteres permiten mapear cadenas a secuencias arbitrarias de números:

CHARMAP "A", 42
CHARMAP ":)", 39
CHARMAP "<br>", 13, 10
CHARMAP "&euro;", $20ac

Esto resultaría en que 'db "Amen :)<br>"' sea equivalente a 'db 42, 109, 101, 110, 32, 39, 13, 10', y 'dw "25&euro;"' sea equivalente a 'dw 50, 53, $20ac'.

Esto se puede utilizar para codificar información de depuración en ASCII y usar una codificación diferente para otros propósitos, por ejemplo. Inicialmente, hay un mapa de caracteres llamado 'main' y se selecciona automáticamente como el mapa de caracteres actual desde el principio. También hay una pila de mapas de caracteres que se puede usar para guardar y restaurar qué mapa de caracteres está activo actualmente.

Otras funciones

Hay algunas otras funciones que realizan acciones más allá de las operaciones numéricas o de cadenas:

SECCIONES

Antes de poder empezar a escribir código, debes definir una sección. Esto le dice al ensamblador qué tipo de información sigue y, si es código, dónde colocarlo.

SECTION nombre, tipo
SECTION nombre, tipo, opciones
SECTION nombre, tipo[dir]
SECTION nombre, tipo[dir], opciones

nombre es una cadena entre comillas dobles, y puede ser un nombre nuevo o el nombre de una sección existente. Si el tipo no coincide, se produce un error. Todas las demás secciones deben tener un nombre único, incluso en diferentes archivos de origen, o el enlazador lo tratará como un error.

Los posibles tipos de sección son los siguientes:

ROM0
Una sección de ROM. dir puede oscilar entre $0000 y $3FFF, o $0000 y $7FFF si el modo ROM pequeño está habilitado en el enlazador.
ROMX
Una sección de ROM con bancos. dir puede oscilar entre $4000 y $7FFF. El banco puede oscilar entre 1 y 511. Se convierte en un alias de ROM0 si el modo ROM pequeño está habilitado en el enlazador.
VRAM
Una sección de RAM de video con bancos. dir puede oscilar entre $8000 y $9FFF. El banco puede ser 0 o 1, pero el banco 1 no está disponible si el modo DMG está habilitado en el enlazador.
SRAM
Una sección de RAM externa (de guardado) con bancos. dir puede oscilar entre $A000 y $BFFF. El banco puede oscilar entre 0 y 15.
WRAM0
Una sección de RAM de propósito general. dir puede oscilar entre $C000 y $CFFF, o $C000 y $DFFF si el modo WRAM0 está habilitado en el enlazador.
WRAMX
Una sección de RAM de propósito general con bancos. dir puede oscilar entre $D000 y $DFFF. El banco puede oscilar entre 1 y 7. Se convierte en un alias de WRAM0 si el modo WRAM0 está habilitado en el enlazador.
OAM
Una sección de RAM de atributos de objeto. dir puede oscilar entre $FE00 y $FE9F.
HRAM
Una sección de RAM alta. dir puede oscilar entre $FF80 y $FFFE.

Dado que RGBDS produce ROMs, el código y los datos solo se pueden colocar en secciones ROM0 y ROMX. Para colocar algo en RAM, haz que se almacene en ROM y cópialo a RAM.

opciones son separadas por comas y pueden incluir:

BANK[banco]
Especifica en qué banco colocar la sección el enlazador. Consulta arriba los valores posibles para banco, dependiendo del tipo.
ALIGN[alineación, desplazamiento]
Coloca la sección en una dirección cuyos alineación bits menos significativos sean iguales
a offset. Tenga en cuenta que ALIGN[align] es una abreviatura de ALIGN[align, 0]. Esta opción se puede usar con [addr], siempre que no se contradigan. También es posible solicitar alineación en medio de una sección; ver Solicitar alineación abajo.

Si no se especifica [addr], la sección se considera “flotante”; el enlazador calculará automáticamente una dirección apropiada para la sección. De manera similar, si BANK[bank] no se especifica, el enlazador encontrará automáticamente un banco con suficiente espacio.

Las secciones también se pueden colocar utilizando un archivo de script del enlazador. El formato se describe en rgblink(5). Permiten al usuario colocar secciones flotantes en el banco deseado en el orden especificado en el script. Esto es útil si las secciones no se pueden colocar en una dirección manualmente porque el tamaño puede cambiar, pero deben estar juntas.

Ejemplos de secciones:

  • SECTION "Cool Stuff", ROMX

    Esto cambia a la sección llamada “CoolStuff”, creándola si aún no existe. Puede terminar en cualquier banco de ROM. El código y los datos pueden seguir.

  • Si es necesario, se puede especificar la dirección base de la sección: 
    SECTION "Cool Stuff", ROMX[$4567]
  • Un ejemplo con un banco fijo: 
    SECTION "Cool Stuff", ROMX[$4567], BANK[3]
  • Y si solo desea forzar el banco de la sección, y no su posición dentro del banco, eso también es posible: 
    SECTION "Cool Stuff", ROMX, BANK[7]
  • Ejemplos de alineación: El primero podría ser útil para definir un buffer de OAM para ser transferido por DMA, ya que debe estar alineado a 256 bytes. El segundo también podría ser apropiado para GBC HDMA, o para un código de copia optimizado que requiere alineación. 
    SECTION "OAM Data", WRAM0, ALIGN[8] ; alinea a 256 bytes
SECTION "VRAM Data", ROMX, BANK[2], ALIGN[4] ; alinea a 16 bytes

La sección actual se puede terminar sin iniciar una nueva sección usando ENDSECTION. Esta directiva borrará el contexto de la sección, por lo que ya no podrá escribir código hasta que inicie otra sección. Puede ser útil para evitar definir accidentalmente código o datos en la sección incorrecta.

Pila de secciones

POPS y PUSHS proporcionan la interfaz a la pila de secciones. El número de entradas en la pila está limitado únicamente por la cantidad de memoria en su máquina.

PUSHS insertará el contexto de la sección actual en la pila de secciones. POPS luego se puede usar más tarde para restaurarlo. Útil para definir secciones en archivos incluidos cuando no desea anular el contexto de la sección en el punto en que se incluyó el archivo.

PUSHS también puede tomar los mismos argumentos que SECTION, para insertar el contexto de la sección actual y definir una nueva sección al mismo tiempo:

SECTION "Code", ROM0
Function:
    ld a, 42
    PUSHS "Variables", WRAM0
        wAnswer: db
    POPS
    ld [wAnswer], a

Código en RAM

A veces quieres tener algo de código en RAM. Pero entonces no puedes simplemente ponerlo en una sección de RAM, tienes que almacenarlo en ROM y copiarlo a RAM en algún momento.

Esto significa que el código (o los datos) no se almacenará en el lugar donde se ejecute. Afortunadamente, los bloques LOAD son la solución perfecta para eso. Aquí tienes un ejemplo de cómo usarlos:

SECTION "LOAD example", ROMX
CopyCode:
    ld de, RAMCode
    ld hl, RAMLocation
    ld c, RAMCode.end - RAMCode
.loop
    ld a, [de]
    inc de
    ld [hli], a
    dec c
    jr nz, .loop
    ret

RAMCode:
  LOAD "RAM code", WRAM0
RAMLocation:
    ld hl, .string
    ld de, $9864
.copy
    ld a, [hli]
    ld [de], a
    inc de
    and a
    jr nz, .copy
    ret

.string
    db "Hello World!\0"
  ENDL
.end

Un bloque LOAD se siente similar a una declaración SECTION porque crea una nueva. Todos los datos y el código generados dentro de dicho bloque se colocan en la sección actual como de costumbre, pero todas las etiquetas se crean como si estuvieran ubicadas en esta nueva sección.

En el ejemplo anterior, todo el código y los datos terminarán en la sección “LOAD example”. Notarás las etiquetas ‘RAMCode’ y ‘RAMLocation’. La primera está situada en ROM, donde se almacena el código, la segunda en RAM, donde se cargará el código.

No puedes anidar bloques LOAD, ni puedes cambiar o detener la sección actual dentro de ellos.

El bloque LOAD actual se puede terminar usando ENDL. Esta directiva solo es necesaria si desea reanudar la escritura de código en su sección ROM contenedora. Cualquiera de LOAD, SECTION, ENDSECTION o POPS finalizará el bloque LOAD actual antes de realizar su propia función.

LOAD bloques pueden usar los modificadores UNION o FRAGMENT como se describe en Secciones unionizadas abajo.

Secciones unionizadas

Cuando tienes poca RAM, es posible que desees definir asignaciones de memoria estática superpuestas, como se explica en la sección Asignación de espacios superpuestos en RAM. Sin embargo, una UNION solo funciona dentro de un solo archivo, por lo que no se puede usar, por ejemplo, para definir variables temporales en varios archivos, todos los cuales utilizan la misma memoria asignada estáticamente. Las secciones unionizadas resuelven este problema. Para declarar una sección unionizada, agregue una palabra clave UNION después de la de SECTION; la declaración no es diferente de lo contrario. Las secciones unionizadas siguen algunas reglas diferentes a las secciones normales:

  • La misma sección unionizada (es decir, que tiene el mismo nombre) se puede declarar varias veces por invocación de rgbasm, y en varias invocaciones. Las diferentes declaraciones se tratan y fusionan de manera idéntica, ya sea dentro de la misma invocación o en diferentes.
  • Si una sección ha sido declarada como unionizada, todas las secciones con el mismo nombre también deben ser declaradas como unionizadas.
  • Todas las declaraciones deben tener el mismo tipo. Por ejemplo, incluso si se utiliza la opción -w de rgblink(1), los tipos WRAM0 y WRAMX todavía se consideran diferentes.
  • Se pueden especificar diferentes restricciones (alineación, banco, etc.) para cada declaración de sección unionizada, pero todas deben ser compatibles. Por ejemplo, la alineación debe ser compatible con cualquier dirección fija, todos los bancos especificados deben ser los mismos, etc.
  • Las secciones unionizadas no pueden tener el tipo ROM0 o ROMX.

Las diferentes declaraciones de la misma sección unionizada no se añaden, sino que se superponen unas sobre otras, al igual que en Asignación de espacios superpuestos en RAM. De manera similar, el tamaño de una sección unionizada es el mayor de todas sus declaraciones.

Fragmentos de sección

Los fragmentos de sección son secciones con un pequeño giro: cuando se encuentran varias del mismo nombre, se concatenan en lugar de producir un error. Esto funciona dentro del mismo archivo (paralelizando el comportamiento que las secciones "planas" tienen en versiones anteriores), pero también entre archivos objeto. Para declarar un fragmento de sección, agregue una palabra clave FRAGMENT después de la de SECTION; la declaración no es diferente de lo contrario. Sin embargo, de manera similar a Secciones unionizadas, se deben seguir algunas reglas:

  • Si una sección ha sido declarada como fragmento, todas las secciones con el mismo nombre también deben ser declaradas como fragmentos.
  • Todas las declaraciones deben tener el mismo tipo. Por ejemplo, incluso si se utiliza la opción -w de rgblink(1), los tipos WRAM0 y WRAMX todavía se consideran diferentes.
  • Se pueden especificar diferentes restricciones (alineación, banco, etc.) para cada declaración de fragmento de sección, pero todas deben ser compatibles. Por ejemplo, la alineación debe ser compatible con cualquier dirección fija, todos los bancos especificados deben ser los mismos, etc.
  • Un fragmento de sección no puede ser unionizado; después de todo, eso no tendría mucho sentido.

Cuando RGBASM fusiona dos fragmentos, el que se encuentra más tarde se añade al que se encontró antes.

Cuando RGBLINK fusiona dos fragmentos, el archivo cuyo archivo se especificó último se añade al archivo cuyo archivo se especificó primero. Por ejemplo, asumiendo que ‘bar.o’, ‘baz.o’ y ‘foo.o’ contienen un fragmento con el mismo nombre, el comando

rgblink -o rom.gb baz.o foo.o bar.o
produciría el fragmento de ‘baz.o’ primero, seguido por el de ‘foo.o’, y el de ‘bar.o’ al último.

Literales de fragmento

Los literales de fragmento son útiles para bloques cortos de código o datos que solo se referencian una vez. Son fragmentos de sección creados al rodear instrucciones o directivas con corchetes dobles ‘[[’ ‘]]’, sin una directiva

Fragment literals

Fragment literals are a way to define sections on the fly. They are denoted by square brackets [[ and ]], and can contain any valid rgbasm code, including other fragment literals or macros.

A fragment literal becomes a SECTION FRAGMENT, sharing the same name and bank as its parent ROM section, but without any other constraints. The parent section also becomes a FRAGMENT if it was not one already, so that it can be merged with its fragment literals. RGBLINK merges the fragments in no particular order.

A fragment literal can take the place of any 16-bit integer constant ‘n16’ from the gbz80(7) documentation, as well as a DW item. The fragment literal then evaluates to its starting address. For example, you can CALL or JP to a fragment literal.

This code using named labels:

DataTable:
    dw First
    dw Second
    dw Third
First:  db 1
Second: db 4
Third:  db 9
Routine:
    push hl
    ld hl, Left
    jr z, .got_it
    ld hl, Right
.got_it
    call .print
    pop hl
    ret
.print:
    ld de, $1003
    ld bc, STARTOF(VRAM)
    jp Print
Left:  db "left\0"
Right: db "right\0"

is equivalent to this code using fragment literals:

DataTable:
    dw [[ db 1 ]]
    dw [[ db 4 ]]
    dw [[ db 9 ]]
Routine:
    push hl
    ld hl, [[ db "left\0" ]]
    jr z, .got_it
    ld hl, [[ db "right\0" ]]
.got_it
    call [[
        ld de, $1003
        ld bc, STARTOF(VRAM)
        jp Print
    ]]
    pop hl
    ret

The difference is that the example using fragment literals does not declare a particular order for its pieces.

Fragment literals can be arbitrarily nested, so extreme use cases are technically possible. This code using named labels:

dw FortyTwo
FortyTwo:
    call Sub1
    jr Sub2
Sub1:
    ld a, [Twenty]
    ret
Twenty: db 20
Sub2:
    jp Sub3
Sub3:
    call Sub1
    inc a
    add a
    ret

is equivalent to this code using fragment literals:

dw [[
    call [[
        Sub1: ld a, [ [[db 20]] ] :: ret
    ]]
    jr [[
        jp [[ call Sub1 :: inc a :: add a :: ret ]]
    ]]
]]

SYMBOLS

RGBDS supports several types of symbols:

Label
Numeric symbol designating a memory location. May or may not have a value known at assembly time.
Constant
Numeric symbol whose value has to be known at assembly time.
Macro
A block of rgbasm code that can be invoked later.
String
A text string that can be expanded later, similarly to a macro.

Symbol names can contain ASCII letters, numbers, underscores ‘_’, hashes ‘#’, dollar signs ‘$’, and at signs ‘@’. However, they must begin with either a letter or an underscore. Additionally, label names can contain up to a single dot ‘.’, which may not be the first character.

A symbol cannot have the same name as a reserved keyword, unless its name is a “raw identifier” prefixed by a hash ‘#’. For example, ‘#load’ denotes a symbol named ‘load’, and ‘#LOAD’ denotes a different symbol named ‘LOAD’; in both cases the ‘#’ prevents them from being treated as the keyword LOAD.

Labels

One of the assembler's main tasks is to keep track of addresses for you, so you can work with meaningful names instead of “magic” numbers. Labels enable just that: a label ties a name to a specific location within a section. A label resolves to a bank and address, determined at the same time as its parent section's (see further in this section).

A label is defined by writing its name at the beginning of a line, followed by one or two colons, without any whitespace between the label name and the colon(s). Declaring a label (global or local) with two colons ‘::’ will define and EXPORT it at the same time. (See Exporting and importing symbols below). When defining a local label, the colon can be omitted, and rgbasm will act as if there was only one.

A label is said to be local if its name contains a dot ‘.’; otherwise, it is said to be global (not to be mistaken with “exported”, explained in Exporting and importing symbols below). More than one dot in label names is not allowed.

For convenience, local labels can use a shorthand syntax: when a symbol name starting with a dot is found (for example, inside an expression, or when declaring a label), then the current “label scope” is implicitly prepended.

Defining a global label sets it as the current “label scope”, until the next global label definition, or the end of the current section.

Here are some examples of label definitions:

GlobalLabel:
AnotherGlobal:
.locallabel ; This defines "AnotherGlobal.locallabel"
.another_local:
AnotherGlobal.with_another_local:
ThisWillBeExported:: ; Note the two colons
ThisWillBeExported.too::

In a numeric expression, a label evaluates to its address in memory. (To obtain its bank, use the ‘BANK()’ function described in Other functions). For example, given the following, ‘ld de, vPlayerTiles’ would be equivalent to ‘ld de, $80C0’ assuming the section ends up at $80C0:

SECTION "Player tiles", VRAM
vPlayerTiles:
    ds 6 * 16
.end

A label's location (and thus value) is usually not determined until the linking stage, so labels usually cannot be used as constants. However, if the section in which the label is defined has a fixed base address, its value is known at assembly time.

Also, while rgbasm obviously can compute the difference between two labels if both are constant, it is also able to compute the difference between two non-constant labels if they both belong to the same section, such as ‘PlayerTiles’ and ‘PlayerTiles.end’ above.

Anonymous labels

Anonymous labels are useful for short blocks of code. They are defined like normal labels, but without a name before the colon. Anonymous labels are independent of label scoping, so defining one does not change the scoped label, and referencing one is not affected by the current scoped label.

Anonymous labels are referenced using a colon ‘:’ followed by pluses ‘+’ or minuses ‘-’. Thus :+ references the next one after the expression, :++ the one after that; :- references the one before the expression; and so on.

    ld hl, :++
:   ld a, [hli] ; referenced by "jr nz"
    ldh [c], a
    dec c
    jr nz, :-
    ret

:   ; referenced by "ld hl"
    dw $7FFF, $1061, $03E0, $58A5

Variables

An equal sign ‘=’ is used to define mutable numeric symbols. Unlike the other symbols described below, variables can be redefined. This is useful for internal symbols in macros, for counters, etc.

DEF ARRAY_SIZE EQU 4
DEF COUNT = 2
DEF COUNT = 3
DEF COUNT = ARRAY_SIZE + COUNT
DEF COUNT *= 2
; COUNT now has the value 14

Note that colons ‘:’ following the name are not allowed.

Variables can be conveniently redefined by compound assignment operators like in C:

Operator Meaning
+= -= Compound plus/minus
*= /= %= Compound multiply/divide/modulo
<<= >>= Compound shift left/right
&= |= ^= Compound and/or/xor

Examples:

DEF x = 10
DEF x += 1    ; x == 11
DEF y = x - 1 ; y == 10
DEF y *= 2    ; y == 20
DEF y >>= 1   ; y == 10
DEF x ^= y    ; x == 1

Declaring a variable with EXPORT DEF or EXPORT REDEF will define and EXPORT it at the same time. (See Exporting and importing symbols below).

DEFINIR DATOS

Definir datos constantes en ROM

DB define una lista de bytes que se almacenarán en la imagen final. Ideal para tablas y texto.

DB 1,2,3,4,"Esta es una cadena"

Alternativamente, puede usar DW para almacenar una lista de palabras (16 bits) o DL para almacenar una lista de doble palabras/longs (32 bits). Ambas escriben sus datos en orden de bytes little-endian; por ejemplo, 'dw $CAFE' es equivalente a 'db $FE, $CA' y no a 'db $CA, $FE'.

Las cadenas se manejan de forma un poco especial: primero pasan por la conversión del mapa de caracteres (ver Mapas de caracteres), luego cada carácter resultante se emite individualmente. Por ejemplo, bajo el mapa de caracteres predeterminado, las dos siguientes líneas son idénticas:

DW "Hola!"
DW "H", "o", "l", "a", "!", ""

Si no desea este manejo especial, encierre la cadena entre paréntesis.

DS también se puede usar para rellenar una región de memoria con algunos valores repetidos. Por ejemplo:

; genera 3 bytes: $AA, $AA, $AA
DS 3, $AA
; genera 7 bytes: $BB, $CC, $BB, $CC, $BB, $CC, $BB
DS 7, $BB, $CC

También puede usar DB, DW y DL sin argumentos. Esto funciona exactamente como DS 1, DS 2 y DS 4 respectivamente. En consecuencia, DB, DW y DL sin argumentos se pueden usar en una sección WRAM0 / WRAMX / HRAM / VRAM / SRAM.

Incluir archivos de datos binarios

Probablemente tenga algunos gráficos, datos de nivel, etc., que le gustaría incluir. Use INCBIN para incluir un archivo binario sin procesar tal como está. Si el archivo no se encuentra en el directorio actual, se buscará en la lista de rutas de inclusión pasada a la opción -I de rgbasm(1) en la línea de comandos.

INCBIN "titulo.bin"
INCBIN "sprites/heroe.bin"

También puede incluir solo una parte de un archivo con INCBIN. El siguiente ejemplo incluye 256 bytes del archivo data.bin, comenzando desde el byte 78.

INCBIN "data.bin", 78, 256

El argumento de longitud es opcional. Si solo se especifica la posición de inicio, se incluirán los bytes desde la posición de inicio hasta el final del archivo.

Asignar espacio estáticamente en RAM

DS asigna estáticamente un número de bytes vacíos. Este es el método preferido para asignar espacio en una sección de RAM. También puede usar DB, DW y DL sin argumentos (ver Definir datos constantes en ROM más abajo).

DS 42 ; Asigna 42 bytes

El espacio vacío en las secciones de RAM no se inicializará. En las secciones de ROM, se rellenará con el valor pasado a la opción de línea de comandos -p, excepto cuando se usan superposiciones con -O.

En lugar de un número exacto de bytes, puede especificar ALIGN[alineación, desplazamiento] para asignar tantos bytes como sean necesarios para alinear los datos subsiguientes. Por lo tanto, 'DS ALIGN'[alineación, desplazamiento], ... es equivalente a 'DS' n, ... seguido de ALIGN[alineación, desplazamiento], donde n es el valor mínimo necesario para satisfacer la restricción de ALIGN (ver Solicitar alineación más abajo). Tenga en cuenta que ALIGN[alineación] es un atajo para ALIGN[alineación, 0].

Asignar espacios superpuestos en RAM

Las uniones permiten que múltiples asignaciones de memoria estática se superpongan, como las uniones en C. Esto no aumenta la cantidad de memoria disponible, pero permite reutilizar la misma región de memoria para diferentes propósitos.

Una unión comienza con la palabra clave UNION y termina en la palabra clave ENDU correspondiente. NEXTU separa cada bloque de asignaciones, y puede usarlo tantas veces como sea necesario dentro de una unión.

; Supongamos que PC == $C0DE aquí
UNION
    ; Aquí, PC == $C0DE
    wNombre:: ds 10
    ; No

Directives for data arrangement

Unions

Like C structures, unions are also supported by the assembler. They are declared using the UNION directive, and unlike structures, they do not occupy space sequentially but rather overlap. This means that all members of a union share the same memory address.

The size of a union is the size of its largest member.

UNION PlayerStats
    wName:: ds 10
    wNickname:: ds 10
ENDU

Here, wName and wNickname share the same starting address. The size of the union is 10 bytes.

UNION Player
    wName:: ds 10
    ; PC == $C0E8
    wHealth:: dw
    ; PC == $C0E8
    wLives:: db
    ; PC == $C0E9
    ds 7
    ; PC == $C0F0
    wBonus:: db
    ; PC == $C0F1
    wPC:: dw
    ; PC == $C0F3
NEXTU
    wNickname:: ds 10
    ; PC == $C0F2
NEXTU
    ; PC is back to $C0DE
    wHealth:: dw
    ; PC == $C0E0
    wLives:: db
    ; PC == $C0E1
    ds 7
    ; PC == $C0E8
    wBonus:: db
    ; PC == $C0E9
NEXTU
    ; PC is back to $C0DE again
    wVideoBuffer: ds 16
    ; PC == $C0EE
ENDU
; Afterward, PC == $C0F2

In the example above, 'wName, wHealth', and 'wVideoBuffer' all have the same value; so do 'wNickname' and 'wBonus'. Thus, keep in mind that 'ld [wHealth], a' assembles to the exact same thing as 'ld [wName], a'.

This whole union's total size is 20 bytes, the size of the largest block (the first one, containing 'wName' and 'wNickname').

Unions may be nested, with each inner union's size being determined as above, and affecting its outer union like any other allocation.

Unions may be used in any section, but they may only contain space-allocating directives like DS (see Statically allocating space in RAM).

Requesting alignment

While ALIGN as presented in SECTIONS is often useful as-is, sometimes you instead want a particular piece of data (or code) in the middle of the section to be aligned. This is made easier through the use of mid-section ALIGN align, offset. It will retroactively alter the section's attributes to ensure that the location the ALIGN directive is at, has its align lower bits equal to offset.

If the constraint cannot be met (for example because the section is fixed at an incompatible address), an error is produced. Note that ALIGN align is a shorthand for ALIGN align, 0.

There may be times when you don't just want to specify an alignment constraint at the current location, but also skip ahead until the constraint can be satisfied. In that case, you can use DS ALIGN[align, offset] to allocate however many bytes are required to align the subsequent data.

If the constraint cannot be met by skipping any amount of space, an error is produced. Note that ALIGN[align] is a shorthand for ALIGN[align, 0].

THE MACRO LANGUAGE

Invoking macros

A macro is invoked by using its name at the beginning of a line, like a directive, followed by any comma-separated arguments.

add a, b
ld sp, hl
my_macro      ; This will be expanded
sub a, 87
my_macro 42   ; So will this
ret c
my_macro 1, 2 ; And this

After rgbasm has read the macro invocation line, it will expand the body of the macro (the lines between MACRO and ENDM) in its place.

Important note: When a macro body is expanded, its expansion may contain another macro invocation, which will be expanded as well, and may be recursive. If this creates an infinite loop, rgbasm will error out once a certain depth is reached (see the -r command-line option in rgbasm(1)). The same problem can occur if the expansion of a macro then expands a string constant, which itself expands.

It's possible to pass arguments to macros as well!

MACRO lb
    ld \1, (\2) << 8 | (\3)
ENDM
    lb hl, 20, 18        ; Expands to "ld hl, ((20) << 8) | (18)"
    lb de, 3 + 1, NUM**2 ; Expands to "ld de, ((3 + 1) << 8) | (NUM**2)"

You expand the arguments inside the macro body by using the escape sequences \1 through \9, \1 being the first argument, \2 being the second, and so on. Since there are only nine digits, you can only use the first nine macro arguments that way. To use the rest, you put the argument number in angle brackets, like \<10>.

This bracketed syntax supports decimal numbers and numeric symbols, where negative values count from the last argument. For example, '‘\<_NARG>’' or '‘\<-1>’' will get the last argument.

Other macro arguments and symbol interpolations will also be expanded inside the angle brackets. For example, if '‘\1’' is '‘13’', then '‘\<\1>’' inside the macro body will expand to '‘\<13>’'. Or if '‘DEF v10 = 42’' and '‘DEF x = 10’', then '‘\<v{d:x}>’' will expand to '‘\<42>’'.

Macro arguments are passed as string constants, although there's no need to enclose them in quotes. Thus, arguments are not evaluated as expressions, but instead are expanded directly inside the macro body. This means that they support all the escape sequences of strings (see String expressions above), as well as some of their own:

Sequence Meaning
'‘\,’' Comma (does not terminate the argument)
'‘\(’' Open parenthesis (does not start enclosing argument contents)
'‘\)’' Close parenthesis (does not end enclosing argument contents)

Line continuations work as usual inside macros or lists of macro arguments. However, some characters need to be escaped, as in the following example:

MACRO PrintMacro1
    PRINTLN STRCAT(\1)
ENDM
    PrintMacro1 "Hello "\, \
                "world"
MACRO PrintMacro2
    PRINT \1
ENDM
    PrintMacro2 STRCAT("Hello ", \
                       "world\n")

The comma in '‘PrintMacro1’' needs to be escaped to prevent it from starting another macro argument. The comma in '‘PrintMacro2’' does not need escaping because it is inside parentheses, similar to macro arguments in the C programming language. The backslash in '‘\n’' also does not need escaping because quoted string literals work as usual inside macro arguments.

Since macro arguments are expanded directly, it's often a good idea to put parentheses around them if they're meant as part of a numeric expression. For instance, consider the following:

MACRO print_double
    PRINTLN \1 * 3
ENDM
    print_double 1 + 2

The body will expand to '‘PRINTLN 1 + 2 * 3’', which will print 7 and not 9 as you might have expected.

The SHIFT directive is only available inside macro bodies. It shifts the argument numbers by one to the left, so what was \2 is now \1, what was \3 is now \2, and so forth. (What was \1 is no longer accessible, so _NARG is decreased by 1.)

SHIFT can also take an integer parameter to shift that many times instead of once. A negative parameter will shift the arguments to the right, which can regain access to previously shifted ones.

SHIFT is especially useful in REPT loops to iterate over different arguments, evaluating the same loop body each time.

There are some escape sequences which are only valid inside the body of a macro:

Sequence Meaning
'‘\1’' – '‘\9’' The 1st–9th macro argument
'‘\<...>’' Further macro arguments
'‘\#’' All _NARG macro arguments, separated by commas
'‘\@’' Unique symbol name affix (see below)

The \@ escape sequence is often useful in macros which define symbols. Suppose your macro expands to a loop of assembly code:

MACRO loop_c_times
    xor a, a
.loop
    ld [hl+], a
    dec c
    jr nz, .loop
ENDM

If you use this macro more than once in the same label scope, it will define '.loop' twice, which is an error. To work around this problem, you can use \@ as a label suffix:

MACRO loop_c_times_fixed
    xor a, a
.loop\@
    ld [hl+], a
    dec c
    jr nz, .loop\@
ENDM

This will expand to a different value in each invocation, similar to gensym in the Lisp programming language.

\@ also works in REPT blocks, expanding to a different value in each iteration.

Automatically repeating blocks of code

Suppose you want to unroll a time-consuming loop without copy-pasting it. REPT

Directives for controlling assembly

Repeating code blocks

REPT está aquí para ese propósito. Todo lo que esté entre REPT y el correspondiente ENDR se repetirá un número de veces, como si hubieras hecho una operación de copiar y pegar tú mismo. El siguiente ejemplo ensamblará 'add a, c' cuatro veces:

REPT 4
    add a, c
ENDR

También puedes usar REPT para generar tablas sobre la marcha:

; Genera una tabla de valores al cuadrado de 0**2 = 0 a 100**2 = 10000
DEF x = 0
REPT 101
    dw x * x
    DEF x += 1
ENDR

Al igual que en las macros, también puedes usar la secuencia de escape \@. Los bloques REPT pueden anidarse.

Un patrón común es repetir un bloque para cada valor en algún rango. FOR es más simple que REPT para ese propósito. Todo lo que esté entre FOR y el correspondiente ENDR se repetirá para cada valor de un símbolo dado. Las constantes de cadena no se expanden dentro del nombre del símbolo. Por ejemplo, este código producirá una tabla de valores al cuadrado de 0 a 255:

FOR N, 256
    dw N * N
ENDR

Actúa como si hubieras hecho:

DEF N = 0
    dw N * N
DEF N = 1
    dw N * N
DEF N = 2
    dw N * N
; ...
DEF N = 255
    dw N * N
DEF N = 256

Puedes personalizar el rango de valores de FOR, de manera similar a la función 'range' en el lenguaje de programación Python:

Código Rango
FOR V, stop V se incrementa de 0 a stop
FOR V, start, stop V se incrementa de start a stop
FOR V, start, stop, step V va de start a stop en pasos de step

El valor de FOR se actualizará por step hasta que alcance o exceda stop, es decir, cubre el rango semiabierto de start (inclusive) a stop (exclusivo). La variable V recibirá este valor al inicio de cada nueva iteración; cualquier cambio realizado en ella dentro del cuerpo del bucle FOR se sobrescribirá. Por lo tanto, el símbolo V no necesita estar definido antes de ninguna iteración del bucle FOR, pero debe ser una variable (Variables) si lo está. Por ejemplo:

FOR V, 4, 25, 5
    PRINT "{d:V} "
    DEF V *= 2
ENDR
    PRINTLN "done {d:V}"

Esto imprimirá:

4 9 14 19 24 done 29

Al igual que con los bloques REPT, puedes usar la secuencia de escape \@ dentro de los bloques FOR, y estos pueden anidarse.

Puedes detener un bloque de repetición con el comando BREAK. Un BREAK dentro de un bloque REPT o FOR interrumpirá la iteración actual y no repetirá más. Continuará ejecutando el código después del ENDR del bloque. Por ejemplo:

FOR V, 1, 100
    PRINT "{d:V}"
    IF V == 5
        PRINT " stop! "
        BREAK
    ENDC
    PRINT ", "
ENDR
    PRINTLN "done {d:V}"

Esto imprimirá:

1, 2, 3, 4, 5 stop! done 5

Ensamblando bloques de código condicionalmente

Los cuatro comandos IF, ELIF, ELSE y ENDC permiten que rgbasm omita partes de tu código según una condición. Esta es una característica potente comúnmente utilizada en macros.

IF NUM < 0
  PRINTLN "NUM < 0"
ELIF NUM == 0
  PRINTLN "NUM == 0"
ELSE
  PRINTLN "NUM > 0"
ENDC

Los bloques ELIF (que significa "else if") y ELSE son opcionales. Los bloques IF / ELIF / ELSE / ENDC pueden anidarse.

Ten en cuenta que si se encuentra un bloque ELSE antes de un bloque ELIF, el bloque ELIF será ignorado. Todos los bloques ELIF deben ir antes del bloque ELSE. Además, si hay más de un bloque ELSE, todos excepto el primero serán ignorados.

Incluyendo otros archivos fuente

Usa INCLUDE para procesar otro archivo ensamblador y luego regresar al archivo actual cuando termine. Si el archivo no se encuentra en el directorio actual, se buscará en la lista de rutas de inclusión pasada a la opción -I de rgbasm(1) en la línea de comandos. Puedes anidar llamadas INCLUDE infinitamente (o hasta que te quedes sin memoria, lo que ocurra primero).

INCLUDE "irq.inc"

También puedes incluir implícitamente un archivo antes del archivo fuente con la opción -P de rgbasm(1).

Imprimiendo cosas durante el ensamblado

Los comandos PRINT y PRINTLN imprimen texto y valores en la salida estándar. Útil para depurar macros, o donde sea que sientas la necesidad de darte a ti mismo información importante.

PRINT "Hello world!\n"
PRINTLN "Hello world!"
PRINT _NARG, " arguments\n"
PRINTLN "sum: ", 2+3, " product: ", 2*3
PRINTLN STRFMT("E = %f", 2.718)
PRINT
imprime cada uno de sus argumentos separados por comas. Los números se imprimen como hexadecimales sin signo en mayúsculas con un prefijo '$'. Para diferentes formatos, usa STRFMT.
PRINTLN
imprime cada uno de sus argumentos separados por comas, si los hay, seguido de una nueva línea ('\n').

Abortando el proceso de ensamblado

FAIL y WARN se pueden usar para imprimir errores y advertencias respectivamente durante el proceso de ensamblado. Esto es especialmente útil para macros que reciben un argumento inválido. FAIL y WARN toman una cadena como único argumento e imprimirán esta cadena como un error normal con un número de línea.

FAIL detiene el ensamblado inmediatamente, mientras que WARN muestra el mensaje pero continúa después.

Si necesitas asegurarte de que alguna suposición sea correcta al compilar, puedes usar ASSERT y STATIC_ASSERT. Los ejemplos de sintaxis se dan a continuación:

Function:
    xor a
ASSERT LOW(MyByte) == 0
    ld h, HIGH(MyByte)
    ld l, a
    ld a, [hli]
; ¡También puedes indentar esto!
    ASSERT BANK(OtherFunction) == BANK(Function)
    call OtherFunction
; Las minúsculas también funcionan
    ld hl, FirstByte
    ld a, [hli]
assert FirstByte + 1 == SecondByte
    ld b, [hl]
    ret
.end
    ; Si especificas uno, se imprimirá un mensaje
    STATIC_ASSERT .end - Function < 256, "Function is too large!"

Primero, la diferencia entre ASSERT y STATIC_ASSERT es que la primera es evaluada por RGBASM si puede, de lo contrario por RGBLINK; pero la segunda solo es evaluada por RGBASM. Si RGBASM no puede calcular el valor del argumento de STATIC_ASSERT, producirá un error.

Segundo, como se muestra arriba, se puede agregar opcionalmente una cadena al final, para dar una idea de lo que está comprobando la aserción.

Finalmente, puedes agregar una de WARN, FAIL o FATAL como el primer argumento opcional a ASSERT o STATIC_ASSERT. Si la aserción falla, WARN generará una advertencia simple (controlada por la bandera -Wassert de rgbasm(1)); FAIL (el predeterminado) causará un error no fatal; y FATAL abortará inmediatamente.

MISCELÁNEO

Cambiando opciones durante el ensamblado

OPT se puede usar para cambiar algunas de las opciones durante el ensamblado desde dentro del código fuente, en lugar de definirlas en la línea de comandos. (Ver rgbasm(1)).

OPT toma una lista de opciones separadas por comas como argumento:

PUSHO
    OPT g.oOX, Wdiv       ; actúa como las opciones de línea de comandos -g.oOX -Wdiv
    DW `..ooOOXX          ; usa los caracteres constantes gráficos de OPT g
    PRINTLN $80000000/-1  ; imprime una advertencia sobre la división
POPO
    DW `00112233          ; usa los caracteres constantes gráficos por defecto
    PRINTLN $80000000/-1  ; sin advertencia por defecto

OPT puede modificar las opciones b, g, p, Q, r y W.

POPO y PUSHO proporcionan la interfaz a la pila de opciones. PUSHO apilará el conjunto actual de opciones en la pila de opciones. POPO podrá entonces ser usado más tarde para restaurarlas. Útil si deseas cambiar algunas opciones en un archivo incluido y no quieres destruir las opciones establecidas por el programa que incluyó tu archivo. El número de entradas de la pila está limitado solo por la cantidad de memoria de tu máquina.

PUSHO también puede tomar una lista separada por comas de opciones, para apilar el conjunto actual y aplicar el conjunto de argumentos al mismo tiempo:

PUSHO b.X, g.oOX
    DB %..XXXX..
    DW `..ooOOXX
POPO
