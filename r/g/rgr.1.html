NOMBRE

rgr - Un reemplazador interactivo para ripgrep que facilita la búsqueda y el reemplazo en archivos desde la línea de comandos.

DESCRIPCIÓN

Para usar esta herramienta, primero debes haber instalado rg (también conocido como: ripgrep). Ver: https://github.com/BurntSushi/ripgrep/#installation.

USO

Uso normal

Al iniciar, todos los argumentos de la línea de comandos se pasan a rg (añadiendo --json y --no-config). La salida JSON se analiza y se te presenta una interfaz de terminal (descrita a continuación).

Ten en cuenta que, dado que usamos la opción --json, un número de opciones de rg no están disponibles. Consulta rgr --help para ver una lista de las opciones admitidas que se pasarán a ripgrep.

Grupos de captura

Puedes usar grupos de captura al usar rgr, por ejemplo rgr "foo (\w+)". Al usarlos, las coincidencias se pueden utilizar al reemplazar refiriéndose a ellas por su nombre $name o índice $1. Esta sintaxis se hereda del crate `regex`, ver: https://docs.rs/regex/1.8.4/regex/struct.Captures.html#method.expand

Solo se puede pasar un patrón a la vez cuando se utilizan grupos de captura (es decir, no se permiten varios indicadores -e <pat>).

Lectura de resultados desde un archivo

Esta herramienta también admite la lectura de resultados desde un archivo JSON, teniendo en cuenta el siguiente caso de uso:

•El usuario ejecuta "rg --json <args> > rg-results.json"
•Ahora, esta herramienta se puede ejecutar con esos resultados a través de "RGR_JSON_FILE=./rg-results.json rgr"

INTERFAZ

Para ver una lista de atajos de teclado, presiona ? mientras estás en el modo SELECT. Hay varios modos:

SELECT

•Este modo es el primer modo que se presenta después de iniciar rgr.
•En este modo se presenta una lista de coincidencias y se pueden activar o desactivar.
•Desactivar una coincidencia significa que la coincidencia en sí no se reemplazará.

REPLACE

•En este modo, el usuario escribe el texto de reemplazo deseado y las coincidencias se actualizan en tiempo real.
•Ten en cuenta que esto es solo una demostración, no se realizan cambios en el disco.
•Los bytes que no son UTF-8 en las coincidencias se muestran con el carácter de reemplazo UTF-8 en este modo.
•Presionar control+s provocará que todas las coincidencias seleccionadas se reemplacen con el texto introducido.

CONFIRM

•Se le pide al usuario que confirme antes de escribir los reemplazos en el disco.
•Los reemplazos se escriben en el disco y se hacen todos los intentos de usar la codificación de archivo correcta. (ver CODIFICACIÓN DE ARCHIVO).
•Ten en cuenta que rgr no reemplazará una porción de bytes diferente a la que rg informó en su salida. (ver CODIFICACIÓN DE ARCHIVO).

HELP

•Este modo proporciona información sobre rgr y sus atajos de teclado.

CARACTERES DE CONTROL

El usuario puede cambiar cómo se representan los caracteres de control en la interfaz presionando control+v. Los diferentes modos son:

•C: mostrar caracteres de control comunes
•c: mostrar caracteres de control comunes (una línea)
•A: mostrar todos los caracteres de control
•a: mostrar todos los caracteres de control (una línea)
•H: mostrar caracteres de control comunes como espacios y ocultar los demás (ocultos)

CODIFICACIÓN DE ARCHIVO

El manejo de la codificación de archivos ocurre en dos lugares: el modo SELECT y cuando los reemplazos se escriben en el disco.

En el modo SELECT, los bytes que no son UTF-8 se muestran con el carácter de reemplazo UTF-8. Esto ocurre porque los archivos en sí aún no se han leído (la información proviene directamente de ripgrep) y, por lo tanto, la codificación del archivo es desconocida.

Durante el reemplazo, la codificación se maneja de la siguiente manera:

•Si se encuentra un BOM (Byte Order Mark), se usa esa codificación, de lo contrario
•Si se pasó una codificación a ripgrep, se usa esa codificación, de lo contrario
•Se utiliza la biblioteca chardet ( https://github.com/thuleqaid/rust-chardet) para detectar la codificación
•Si eso falla, se asume UTF8

Ten en cuenta que rgr nunca reemplazará una coincidencia que no espera. Si al reemplazar una coincidencia, los bytes a reemplazar no coinciden con los que ripgrep encontró, la herramienta fallará y el archivo no se escribirá. (Los errores se informarán en STDERR).
