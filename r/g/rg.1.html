NOMBRE

rg - búsqueda recursiva en el directorio actual de líneas que coinciden con un patrón

SINOPSIS

rg [OPCIONES] PATRÓN [RUTA...]

rg [OPCIONES] -e PATRÓN... [RUTA...]

rg [OPCIONES] -f ARCHIVOPATRON... [RUTA...]

rg [OPCIONES] --files [RUTA...]

rg [OPCIONES] --type-list

comando | rg [OPCIONES] PATRÓN

rg [OPCIONES] --help

rg [OPCIONES] --version

DESCRIPCIÓN

ripgrep (rg) busca recursivamente en el directorio actual un patrón de expresiones regulares. Por defecto, ripgrep respetará tu .gitignore y omitirá automáticamente los archivos/directorios ocultos y los archivos binarios.

El motor de expresiones regulares por defecto de ripgrep utiliza autómatas finitos y garantiza búsquedas en tiempo lineal. Debido a esto, características como las referencias inversas y el lookaround arbitrario no son compatibles. Sin embargo, si ripgrep se compila con PCRE2, entonces se puede usar la bandera -P/--pcre2 para habilitar referencias inversas y lookaround.

ripgrep admite archivos de configuración. Establece RIPGREP_CONFIG_PATH a un archivo de configuración. El archivo puede especificar un argumento de shell por línea. Las líneas que comienzan con # se ignoran. Para más detalles, consulta ARCHIVOS DE CONFIGURACIÓN abajo.

ripgrep detectará automáticamente si stdin es un archivo legible y buscará en stdin un patrón de expresión regular, por ejemplo, ls | rg foo. En algunos entornos, stdin puede existir cuando no debería. Para desactivar la detección de stdin, se puede especificar explícitamente el directorio a buscar, por ejemplo, rg foo ./.

Al igual que otras herramientas como ls, ripgrep alterará su salida dependiendo de si stdout está conectado a una tty. Por defecto, al imprimir una tty, ripgrep habilitará colores, números de línea y un formato de encabezado que lista cada ruta de archivo coincidente una vez en lugar de una vez por línea coincidente.

Consejo: para desactivar todo filtrado inteligente y hacer que ripgrep se comporte un poco más como grep clásico, usa rg -uuu.

SINTAXIS DE EXPRESIONES REGULARES

ripgrep utiliza el motor de expresiones regulares de Rust por defecto, que documenta su sintaxis: https://docs.rs/regex/1.*/regex/#syntax

ripgrep utiliza expresiones regulares orientadas a bytes, lo que tiene documentación adicional: https://docs.rs/regex/1.*/regex/bytes/index.html#syntax

A primera aproximación, ripgrep utiliza expresiones regulares tipo Perl sin lookaround ni referencias inversas. Esto las hace muy similares a las expresiones regulares "extendidas" (ERE) compatibles con *egrep*, pero con algunas características adicionales como clases de caracteres Unicode.

Si estás usando ripgrep con la bandera -P/--pcre2, consulta https://www.pcre.org o las páginas man de PCRE2 para obtener documentación sobre la sintaxis compatible.

ARGUMENTOS POSICIONALES

PATRÓN
Una expresión regular utilizada para la búsqueda. Para hacer coincidir un patrón que comienza con un guion, usa la opción -e/--regexp.
RUTA
Un archivo o directorio para buscar. Los directorios se buscan recursivamente. Las rutas de archivo especificadas explícitamente en la línea de comandos anulan las reglas de glob y de ignorar.

OPCIONES

Esta sección documenta todos los flags que acepta ripgrep. Los flags están agrupados en categorías a continuación según su función.

Ten en cuenta que muchas opciones se pueden activar y desactivar. En algunos casos, esos flags no se enumeran explícitamente a continuación. Por ejemplo, el flag --column (listado a continuación) habilita los números de columna en la salida de ripgrep, pero el flag --no-column (no listado a continuación) los deshabilita. Lo inverso también puede existir. Por ejemplo, el flag --no-ignore (listado a continuación) deshabilita la lógica gitignore de ripgrep, pero el flag --ignore (no listado a continuación) la habilita. Estos flags son útiles para anular un archivo de configuración de ripgrep (o un alias) en la línea de comandos. La documentación de cada flag indica si existe un flag invertido. En todos los casos, el último flag especificado tiene precedencia.

OPCIONES DE ENTRADA

-e PATRÓN, --regexp=PATRÓN

Un patrón para buscar. Esta opción se puede proporcionar varias veces, donde todos los patrones dados se buscan, además de cualquier patrón proporcionado por -f/--file. Se imprimen las líneas que coinciden con al menos uno de los patrones proporcionados. Este flag también se puede usar al buscar patrones que comienzan con un guion.

Por ejemplo, para buscar el literal -foo:

    rg -e -foo

También puedes usar el delimitador especial -- para indicar que no se proporcionarán más flags. Es decir, lo siguiente es equivalente a lo anterior:

    rg -- -foo

Cuando se usa -f/--file o -e/--regexp, entonces ripgrep trata todos los argumentos posicionales como archivos o directorios para buscar.

-f ARCHIVOPATRON, --file=ARCHIVOPATRON

Busca patrones del archivo dado, con un patrón por línea. Cuando se usa este flag varias veces o en combinación con el flag -e/--regexp, entonces se buscan todos los patrones proporcionados. Las líneas de patrón vacías coincidirán con todas las líneas de entrada, y el salto de línea no se cuenta como parte del patrón.

Una línea se imprime si y solo si coincide con al menos uno de los patrones.

Cuando ARCHIVOPATRON es -, entonces se leerá stdin para los patrones.

Cuando se usa -f/--file o -e/--regexp, entonces ripgrep trata todos los argumentos posicionales como archivos o directorios para buscar.

--pre=COMANDO

Para cada RUTA de entrada, este flag hace que ripgrep busque la salida estándar de COMANDO RUTA en lugar del contenido de RUTA. Esta opción espera que el programa COMANDO sea una ruta o que esté disponible en tu PATH. Una cadena vacía COMANDO o el flag --no-pre desactivarán este comportamiento.
ADVERTENCIA
Cuando se establece este flag, ripgrep generará incondicionalmente un proceso para cada archivo que se busca. Por lo tanto, esto puede incurrir en una penalización de rendimiento innecesariamente grande si no necesitas la flexibilidad que ofrece este flag. Una posible mitigación es usar el flag --pre-glob para limitar con qué archivos se ejecuta un preprocesador.

Un preprocesador no se ejecuta cuando ripgrep busca stdin.

Al buscar en conjuntos de archivos que pueden requerir uno de varios preprocesadores, COMANDO debe ser un programa envoltura que primero clasifique RUTA basándose en números mágicos/contenido o basándose en el nombre de la RUTA y luego se distribuya a un preprocesador apropiado. Cada COMANDO también tiene su entrada estándar conectada a RUTA para mayor conveniencia.

Por ejemplo, un script de shell para COMANDO podría parecer:

    case "$1" in
    *.pdf)
        exec pdftotext "$1" -
        ;;
    *)
        case $(file "$1") in
        *Zstandard*)
            exec pzstd -cdq
            ;;
        *)
            exec cat
            ;;
        esac
        ;;
    esac

El script anterior utiliza pdftotext para convertir un archivo PDF a texto plano. Para todos los demás archivos, el script utiliza la utilidad file para detectar el tipo de archivo basándose en su contenido. Si es un archivo comprimido en formato Zstandard, se utiliza pzstd para descomprimir el contenido a stdout.

Esto anula el flag -z/--search-zip.

--pre-glob=GLOB

Este flag funciona junto con el flag --pre. Es decir, cuando se dan uno o más flags --pre-glob, entonces solo los archivos que coincidan con el conjunto dado de globs se pasarán al comando especificado por el flag --pre. Los archivos que no coincidan se buscarán sin usar el comando preprocesador.

Este flag es útil al buscar muchos archivos con el flag --pre. Es decir, proporciona la capacidad de evitar la sobrecarga del proceso para archivos que no necesitan preprocesamiento.

c. Ejemplo, dado el siguiente script de shell, pre-pdftotext:

    #!/bin/sh
    pdftotext "$1" -

entonces es posible usar --pre pre-pdftotext --pre-glob '*.pdf' para que ripgrep solo ejecute el comando pre-pdftotext en archivos con la extensión .pdf.

Se pueden usar múltiples banderas --pre-glob. Las reglas de globbing coinciden con los globbing de gitignore. Anteponer un glob con ! para excluirlo.

Esta bandera no tiene efecto si no se usa la bandera --pre.

-z, --search-zip

Esta bandera indica a ripgrep que busque en archivos comprimidos. Actualmente, se admiten archivos gzip, bzip2, xz, LZ4, LZMA, Brotli y Zstd. Esta opción espera que los binarios de descompresión (como gzip) estén disponibles en su PATH. Si no se encuentran los binarios requeridos, ripgrep no emitirá mensajes de error por defecto. Utilice la bandera --debug para ver más información.

Tenga en cuenta que esta bandera no hace que ripgrep busque en formatos de archivo como árboles de directorios. Solo hace que ripgrep detecte archivos comprimidos y luego los descomprima antes de buscar su contenido, como lo haría con cualquier otro archivo.

Esto anula la bandera --pre.

Esta bandera se puede deshabilitar con --no-search-zip.

OPCIONES DE BÚSQUEDA

-s, --case-sensitive

Ejecuta la búsqueda de forma sensible a mayúsculas y minúsculas. Este es el modo por defecto.

Esta es una opción global que se aplica a todos los patrones proporcionados a ripgrep. Los patrones individuales aún se pueden hacer coincidir de forma insensible a mayúsculas y minúsculas utilizando indicadores de expresiones regulares en línea. Por ejemplo, (?i)abc coincidirá con abc de forma insensible a mayúsculas y minúsculas incluso cuando se usa esta bandera.

Esta bandera anula las banderas -i/--ignore-case y -S/--smart-case.

--crlf

Cuando está habilitado, ripgrep tratará CRLF (\r\n) como un terminador de línea en lugar de solo \n.

Principalmente, esto permite que las aserciones de ancla de línea ^ y $ en los patrones de expresiones regulares traten CRLF, CR o LF como terminadores de línea en lugar de solo LF. Tenga en cuenta que nunca coincidirán entre un CR y un LF. CRLF se trata como un único terminador de línea.

Cuando se utiliza el motor de expresiones regulares por defecto, el soporte CRLF también se puede habilitar dentro del patrón con el indicador R. Por ejemplo, (?R:$) coincidirá justo antes de CR o LF, pero nunca entre CR y LF.

Esta bandera anula --null-data.

Esta bandera se puede deshabilitar con --no-crlf.

--dfa-size-limit=NUM+SUFIJO?

El límite superior de tamaño del DFA de la expresión regular. El límite por defecto es algo generoso para cualquier patrón individual o para muchos patrones pequeños. Esto solo debe cambiarse en entradas de expresiones regulares muy grandes donde el motor de expresiones regulares (más lento) de reserva podría usarse de lo contrario si se alcanza el límite.

El formato de entrada acepta sufijos de K, M o G que corresponden a kilobytes, megabytes y gigabytes, respectivamente. Si no se proporciona ningún sufijo, la entrada se trata como bytes.

-E CODIFICACION, --encoding=CODIFICACION

Especifica la codificación de texto que ripgrep usará en todos los archivos buscados. El valor por defecto es auto, lo que hará que ripgrep intente detectar automáticamente la codificación de forma individual para cada archivo. La detección automática en este caso solo se aplica a los archivos que comienzan con una marca de orden de bytes (BOM) UTF-8 o UTF-16. No se realiza ninguna otra detección automática. También se puede especificar none, que deshabilitará completamente la detección de BOM y siempre resultará en la búsqueda de los bytes sin procesar, incluida una BOM si está presente, independientemente de su codificación.

Otros valores admitidos se pueden encontrar en la lista de etiquetas aquí: https://encoding.spec.whatwg.org/#concept-encoding-get.

Para obtener más detalles sobre la codificación y cómo ripgrep la maneja, consulte GUIDE.md.

La detección de codificación que utiliza ripgrep se puede revertir a su modo automático mediante la bandera --no-encoding.

--engine=MOTOR

Especifica qué motor de expresiones regulares usar. Cuando elige un motor de expresiones regulares, aplica esa elección a cada expresión regular proporcionada a ripgrep (por ejemplo, a través de múltiples banderas -e/--regexp o -f/--file).

Los valores aceptados son default, pcre2 o auto.

El valor por defecto es default, que suele ser el más rápido y debería ser bueno para la mayoría de los casos de uso. El motor pcre2 es útil generalmente cuando desea utilizar características como look-around o backreferences. auto elegirá dinámicamente entre los motores de expresiones regulares admitidos dependiendo de las características utilizadas en un patrón, basándose en el mejor esfuerzo.

Tenga en cuenta que el motor pcre2 es una característica opcional de ripgrep. Si PCRE2 no se incluyó en su compilación de ripgrep, usar esta bandera hará que ripgrep imprima un mensaje de error y salga.

Esto anula los usos anteriores de las banderas -P/--pcre2 y --auto-hybrid-regex.

-F, --fixed-strings

Trata todos los patrones como literales en lugar de como expresiones regulares. Cuando se utiliza esta bandera, no es necesario escapar los caracteres especiales meta de las expresiones regulares como .(){}*+.

Esta bandera se puede deshabilitar con --no-fixed-strings.

-i, --ignore-case

Cuando se proporciona esta bandera, todos los patrones se buscarán de forma insensible a mayúsculas y minúsculas. Las reglas de insensibilidad a mayúsculas y minúsculas utilizadas por el motor de expresiones regulares por defecto de ripgrep se ajustan a las reglas de "plegado simple" de mayúsculas y minúsculas de Unicode.

Esta es una opción global que se aplica a todos los patrones proporcionados a ripgrep. Los patrones individuales aún se pueden hacer coincidir de forma sensible a mayúsculas y minúsculas utilizando indicadores de expresiones regulares en línea. Por ejemplo, (?-i)abc coincidirá con abc de forma sensible a mayúsculas y minúsculas incluso cuando se usa esta bandera.

Esta bandera anula -s/--case-sensitive y -S/--smart-case.

-v, --invert-match

Esta bandera invierte la coincidencia. Es decir, en lugar de imprimir líneas que coinciden, ripgrep imprimirá líneas que no coinciden.

Tenga en cuenta que esto solo invierte la coincidencia línea por línea. Por ejemplo, combinar esta bandera con -l/--files-with-matches emitirá archivos que contienen líneas que no coinciden con los patrones dados. Eso no es lo mismo que, por ejemplo, --files-without-match, que emitirá archivos que no contienen ninguna línea coincidente.

Esta bandera se puede deshabilitar con --no-invert-match.

-x, --line-regexp

Cuando está habilitado, ripgrep solo mostrará coincidencias rodeadas por límites de línea. Esto es equivalente a rodear cada patrón con ^ y $. En otras palabras, esto solo imprime líneas donde la línea completa participa en una coincidencia.

Esto anula la bandera -w/--word-regexp.

-m NUM, --max-count=NUM

Limita el número de líneas coincidentes por archivo buscado a NUM.

Cuando se usa -U/--multiline, una sola coincidencia que abarca varias líneas solo se cuenta una vez para los fines de este límite. Múltiples coincidencias en una sola línea se cuentan solo una vez, como lo harían en el modo no multilínea.

Cuando se combina con -A/--after-context o -C/--context, es posible que se impriman más coincidencias que el máximo si las líneas contextuales contienen una coincidencia.

Tenga en cuenta que 0 es un valor legal pero probablemente no sea útil. Cuando se usa, ripgrep no buscará nada.

--mmap

Cuando está habilitado, ripgrep buscará utilizando mapas de memoria cuando sea posible. Esto está habilitado por defecto cuando ripgrep cree que será más rápido.

La búsqueda con mapas de memoria no se puede utilizar en todas las circunstancias. Por ejemplo, al buscar archivos virtuales o transmisiones como stdin. En tales casos, los mapas de memoria no se utilizarán incluso cuando esta bandera esté habilitada.

Tenga en cuenta que ripgrep puede abortar inesperadamente cuando se utilizan mapas de memoria si busca un archivo que se trunca simultáneamente. Los usuarios pueden optar por no participar en esta posibilidad deshabilitando los mapas de memoria.

Esta bandera se puede deshabilitar con --no-mmap.

-U, --multiline

Esta bandera habilita la búsqueda a través de múltiples líneas.

Cuando el modo multilínea está habilitado, ripgrep levantará la restricción de que una coincidencia no puede incluir un terminador de línea. Por ejemplo, cuando el modo multilínea no está habilitado (el valor por defecto), entonces la expresión regular \p{any} coincidirá con cualquier punto de código Unicode excepto \n. De manera similar, la expresión regular \n está explícitamente prohibida, y si intenta usarla, ripgrep devolverá un error. Sin embargo, cuando el modo multilínea está habilitado, \p{any} coincidirá con cualquier punto de código Unicode, incluido \n, y las expresiones regulares como \n están permitidas.

Una advertencia importante es que el modo multilínea no cambia la semántica de coincidencia de .. Es decir, en la mayoría de los analizadores de expresiones regulares, un . por defecto coincidirá con cualquier carácter excepto \n, y esto es cierto también en ripgrep. Para que . coincida con \n, debe habilitar el indicador "dot all" dentro de la expresión regular. Por ejemplo, tanto (?s). como (?s:.) tienen la misma semántica, donde . coincidirá con cualquier carácter, incluido \n. Alternativamente, se puede pasar la bandera --multiline-dotall para hacer que el comportamiento "dot all" sea el predeterminado. Esta bandera solo se aplica cuando la búsqueda multilínea está habilitada.

No hay límite en el número de líneas que puede abarcar una sola coincidencia.

ADVERTENCIA: Debido a cómo funciona el motor de expresiones regulares subyacente, las búsquedas multilínea pueden ser más lentas que las búsquedas normales orientadas a líneas, y también pueden consumir más memoria. En particular, cuando el modo multilínea está habilitado, ripgrep requiere que cada archivo que busca esté organizado de forma contigua en memoria (ya sea leyéndolo en la pila o mapeándolo en memoria). Las cosas que no se pueden mapear en memoria (como stdin) se consumirán hasta EOF antes de que pueda comenzar la búsqueda. En general, ripgrep solo hará estas cosas cuando sea necesario. Específicamente, si se proporciona la bandera -U/--multiline pero la expresión regular no contiene patrones que coincidan con caracteres \n, entonces ripgrep evitará automáticamente leer cada archivo en memoria antes de buscarlo. Sin embargo, si solo le interesan las coincidencias que abarcan como máximo una línea, siempre es mejor deshabilitar el modo multilínea.

Esto anula la bandera --stop-on-nonmatch.

Esta bandera se puede deshabilitar con --no-multiline.

--multiline-dotall

Esta bandera habilita el modo "dot all" en todos los patrones de expresiones regulares. Esto hace que . coincida con los terminadores de línea cuando la búsqueda multilínea está habilitada. Esto flag no tiene ningún efecto si la búsqueda multilínea no está habilitada con el flag -U/--multiline.

Normalmente, un . coincidirá con cualquier carácter excepto los terminadores de línea. Si bien este comportamiento normalmente no es relevante para la coincidencia orientada a líneas (ya que las coincidencias pueden abarcar como máximo una línea), esto puede ser útil al buscar con el flag -U/--multiline. Por defecto, el modo multilínea se ejecuta sin el modo "punto todo" habilitado.

Este flag generalmente está destinado a ser utilizado en un alias o en tu archivo de configuración de ripgrep si prefieres la semántica de "punto todo" por defecto. Ten en cuenta que independientemente de si se utiliza este flag o no, la semántica de "punto todo" aún se puede controlar mediante flags en línea en el propio patrón de regex, por ejemplo, (?s:.) siempre habilita "punto todo" mientras que (?-s:.) siempre deshabilita "punto todo". Además, puedes usar clases de caracteres como \p{any} para que coincidan con cualquier punto de código Unicode independientemente de si el modo "punto todo" está habilitado o no.

Este flag se puede deshabilitar con --no-multiline-dotall.

--no-unicode

Este flag deshabilita el modo Unicode para todos los patrones proporcionados a ripgrep.

Por defecto, ripgrep habilitará el "modo Unicode" en todas sus regex. Esto tiene una serie de consecuencias:

  • . solo coincidirá con valores escalares Unicode codificados en UTF-8 válidos.
  • Clases como \w, \s, \d son conscientes de Unicode y mucho más grandes que sus versiones solo ASCII.
  • La coincidencia insensible a mayúsculas/minúsculas utilizará el plegado de mayúsculas/minúsculas de Unicode.
  • Una gran variedad de clases como \p{Emoji} están disponibles. (Aunque el conjunto específico de clases disponibles varía según el motor de regex. En general, el motor de regex predeterminado tiene más clases disponibles).
  • Los límites de palabra (\b y \B) utilizan la definición de Unicode de un carácter de palabra.

En algunos casos, puede ser deseable desactivar estas cosas. Este flag hará exactamente eso. Por ejemplo, el modo Unicode a veces puede tener un impacto negativo en el rendimiento, especialmente cuando cosas como \w se usan con frecuencia (incluso a través de repeticiones acotadas como \w{100}) cuando solo se necesita su interpretación ASCII.

Este flag se puede deshabilitar con --unicode.

--null-data

Habilitar este flag hace que ripgrep utilice NUL como terminador de línea en lugar del valor predeterminado de \n.

Esto es útil al buscar archivos binarios grandes que de otro modo tendrían líneas muy largas si se usara \n como terminador de línea. En particular, ripgrep requiere que, como mínimo, cada línea quepa en memoria. Usar NUL en su lugar puede ser una solución útil para mantener bajos los requisitos de memoria y evitar condiciones de falta de memoria (OOM).

Esto también es útil para procesar datos delimitados por NUL, como los emitidos al usar el flag -0/--null de ripgrep o el flag --print0 de find.

El uso de este flag implica -a/--text. También anula --crlf.

-P, --pcre2

Cuando este flag está presente, ripgrep utilizará el motor de regex PCRE2 en lugar de su motor de regex predeterminado.

Esto es generalmente útil cuando deseas usar características como look-around o backreferences.

Usar este flag es lo mismo que pasar --engine=pcre2. Los usuarios pueden optar por usar --engine=auto para pedirle a ripgrep que seleccione automáticamente el motor de regex correcto según los patrones dados. Este flag y el flag --engine se anulan mutuamente.

Ten en cuenta que PCRE2 es una característica opcional de ripgrep. Si PCRE2 no se incluyó en tu compilación de ripgrep, usar este flag hará que ripgrep imprima un mensaje de error y salga. PCRE2 también puede tener una peor experiencia de usuario en algunos casos, ya que tiene menos APIs de introspección que el motor de regex predeterminado de ripgrep. Por ejemplo, si usas un \n en una regex PCRE2 sin el flag -U/--multiline, ripgrep fallará silenciosamente al no encontrar ninguna coincidencia en lugar de informar un error de inmediato (como lo hace con el motor de regex predeterminado).

Este flag se puede deshabilitar con --no-pcre2.

--regex-size-limit=NUM+SUFIJO?

El límite de tamaño de la regex compilada, donde la regex compilada generalmente corresponde a un único objeto en memoria que puede coincidir con todos los patrones proporcionados a ripgrep. El límite predeterminado es lo suficientemente generoso como para que la mayoría de los patrones razonables (o incluso un pequeño número de ellos) encajen.

Esto es útil para cambiar cuando deseas explícitamente que ripgrep dedique potencialmente mucho más tiempo y/o memoria a construir un compilador de regex.

El formato de entrada acepta sufijos de K, M o G que corresponden a kilobytes, megabytes y gigabytes, respectivamente. Si no se proporciona sufijo, la entrada se trata como bytes.

-S, --smart-case

Este flag indica a ripgrep que busque de forma insensible a mayúsculas/minúsculas si el patrón está completamente en minúsculas. De lo contrario, ripgrep buscará de forma sensible a mayúsculas/minúsculas.

Un patrón se considera completamente en minúsculas si se cumplen ambas reglas:

  • Primero, el patrón contiene al menos un carácter literal. Por ejemplo, a\w contiene un literal (a) pero solo \w no.
  • Segundo, de los literales en el patrón, ninguno de ellos se considera mayúscula según Unicode. Por ejemplo, foo\pL no tiene literales en mayúscula pero Foo\pL sí.

Esto anula los flags -s/--case-sensitive y -i/--ignore-case.

--stop-on-nonmatch

Habilitar esta opción hará que ripgrep deje de leer un archivo una vez que encuentre una línea que no coincide después de haber encontrado una línea que sí coincide. Esto es útil si se espera que todas las coincidencias en un archivo dado estén en líneas secuenciales, por ejemplo, debido a que las líneas están ordenadas.

Esto anula el flag -U/--multiline.

-a, --text

Este flag indica a ripgrep que busque archivos binarios como si fueran texto. Cuando este flag está presente, la detección de archivos binarios de ripgrep se deshabilita. Esto significa que cuando se busca un archivo binario, su contenido puede imprimirse si hay una coincidencia. Esto puede causar la impresión de códigos de escape que alteran el comportamiento de tu terminal.

Cuando la detección de archivos binarios está habilitada, es imperfecta. En general, utiliza una heurística simple. Si se ve un byte NUL durante la búsqueda, el archivo se considera binario y la búsqueda se detiene (a menos que este flag esté presente). Alternativamente, si se utiliza el flag --binary, ripgrep solo saldrá cuando vea un byte NUL después de haber encontrado una coincidencia (o haya buscado todo el archivo).

Este flag anula el flag --binary.

Este flag se puede deshabilitar con --no-text.

-j NUM, --threads=NUM

Este flag establece el número aproximado de hilos a utilizar. Un valor de 0 (que es el valor predeterminado) hace que ripgrep elija el recuento de hilos utilizando heurísticas.

-w, --word-regexp

Cuando está habilitado, ripgrep solo mostrará coincidencias rodeadas por límites de palabras. Esto equivale a rodear cada patrón con \b{medio-inicio} y \b{medio-fin}.

Esto anula el flag -x/--line-regexp.

--auto-hybrid-regex

OBSOLETO. Usa --engine en su lugar.

Cuando se utiliza este flag, ripgrep elegirá dinámicamente entre los motores de regex compatibles según las características utilizadas en un patrón. Cuando ripgrep elige un motor de regex, aplica esa elección para cada regex proporcionada a ripgrep (por ejemplo, a través de múltiples flags -e/--regexp o -f/--file).

Como ejemplo de cómo podría comportarse este flag, ripgrep intentará usar su motor de regex predeterminado basado en autómatas finitos siempre que el patrón se pueda compilar correctamente con ese motor de regex. Si PCRE2 está habilitado y si el patrón dado no se pudo compilar con el motor de regex predeterminado, entonces PCRE2 se utilizará automáticamente para la búsqueda. Si PCRE2 no está disponible, entonces este flag no tiene ningún efecto porque solo hay un motor de regex para elegir.

En el futuro, ripgrep puede ajustar sus heurísticas sobre cómo decide qué motor de regex usar. En general, las heurísticas se limitarán a un análisis estático de los patrones, y no a ningún comportamiento específico en tiempo de ejecución observado al buscar archivos.

La principal desventaja de usar este flag es que puede que no siempre sea obvio qué motor de regex utiliza ripgrep y, por lo tanto, la semántica de coincidencia o el perfil de rendimiento de ripgrep pueden cambiar sutil y inesperadamente. Sin embargo, en muchos casos, todos los motores de regex estarán de acuerdo en lo que constituye una coincidencia y puede ser bueno admitir de forma transparente características de regex más avanzadas como look-around y backreferences sin necesidad de habilitarlas explícitamente.

Este flag se puede deshabilitar con --no-auto-hybrid-regex.

--no-pcre2-unicode

OBSOLETO. Usa --no-unicode en su lugar.

Ten en cuenta que el modo Unicode está habilitado por defecto.

Este flag se puede deshabilitar con --pcre2-unicode.

OPCIONES DE FILTRO

--binary

Habilitar este flag hará que ripgrep busque archivos binarios. Por defecto, ripgrep intenta omitir automáticamente los archivos binarios para mejorar la relevancia de los resultados y hacer la búsqueda más rápida.

Los archivos binarios se detectan heurísticamente basándose en si contienen un byte NUL o no. Por defecto (sin este flag activado), una vez que se ve un byte NUL, ripgrep dejará de buscar en el archivo. Generalmente, los bytes NUL ocurren al principio de la mayoría de los archivos binarios. Si un byte NUL ocurre después de una coincidencia, ripgrep no imprimirá la coincidencia, dejará de buscar en ese archivo y emitirá una advertencia de que algunas coincidencias se están suprimiendo.

En contraste, cuando se proporciona este flag, ripgrep continuará buscando en un archivo incluso si se encuentra un byte NUL. En particular, si se encuentra un byte NUL, ripgrep continuará buscando hasta que se encuentre una coincidencia o se alcance el final del archivo, lo que ocurra primero. Si se encuentra una coincidencia, ripgrep se detendrá e imprimirá una advertencia de que la búsqueda se detuvo prematuramente.

Si deseas que ripgrep busque un archivo sin ningún manejo especial de bytes NUL (y potencialmente imprima datos binarios en la salida estándar), deberías usar el flag -a/--text.

El flag --binary es un flag para controlar el mecanismo de filtrado automático de ripgrep. Como tal, no necesita usarse al buscar un archivo explícitamente o al buscar en la entrada estándar. Es decir, solo es aplicable cuando se busca recursivamente en un directorio.

Cuando el flag -u/--unrestricted

se proporciona por tercera vez, entonces esta bandera se habilita automáticamente.

Esta bandera anula la bandera -a/--text.

Esta bandera se puede deshabilitar con --no-binary.

-L, --follow

Esta bandera instruye a ripgrep para que siga enlaces simbólicos al recorrer directorios. Este comportamiento está deshabilitado por defecto. Tenga en cuenta que ripgrep comprobará bucles de enlaces simbólicos e informará de errores si encuentra uno. ripgrep también informará de errores para enlaces rotos. Para suprimir mensajes de error, use la bandera --no-messages.

Esta bandera se puede deshabilitar con --no-follow.

-g GLOB, --glob=GLOB

Incluye o excluye archivos y directorios para la búsqueda que coincidan con el glob dado. Esto siempre anula cualquier otra lógica de ignorar. Se pueden usar múltiples banderas glob. Las reglas de glob coinciden con las reglas de .gitignore. Anteceda un glob con ! para excluirlo. Si varios globs coinciden con un archivo o directorio, el glob dado más tarde en la línea de comandos tiene precedencia.

Como extensión, los globs admiten la especificación de alternativas: -g 'ab{c,d}*' es equivalente a -g abc -g abd. Las alternativas vacías como -g 'ab{,c}' no son compatibles actualmente. Tenga en cuenta que esta extensión de sintaxis también está actualmente habilitada en los archivos gitignore, aunque esta sintaxis no es compatible con git en sí. ripgrep puede deshabilitar esta extensión de sintaxis en los archivos gitignore, pero siempre estará disponible a través de la bandera -g/--glob.

Cuando esta bandera está activada, cada archivo y directorio se aplica a ella para probar una coincidencia. Por ejemplo, si solo desea buscar en un directorio en particular foo, entonces -g foo es incorrecto porque foo/bar no coincide con el glob foo. En su lugar, debe usar -g 'foo/**'.

--glob-case-insensitive

Procesa todos los patrones glob proporcionados con la bandera -g/--glob sin distinguir entre mayúsculas y minúsculas. Esto efectivamente trata -g/--glob como --iglob.

Esta bandera se puede deshabilitar con --no-glob-case-insensitive.

-., --hidden

Busca archivos y directorios ocultos. Por defecto, se omiten los archivos y directorios ocultos. Tenga en cuenta que si un archivo o directorio oculto está en la lista blanca de un archivo de ignorar, entonces se buscará incluso si esta bandera no se proporciona. De manera similar, si un archivo o directorio oculto se proporciona explícitamente como argumento a ripgrep.

Un archivo o directorio se considera oculto si su nombre base comienza con un punto (.). En sistemas operativos que admiten un atributo de archivo "oculto", como Windows, los archivos con este atributo también se consideran ocultos.

Tenga en cuenta que -./--hidden incluirá archivos y carpetas como .git independientemente de --no-ignore-vcs. Para excluir dichas rutas al usar -./--hidden, debe ignorarlas explícitamente utilizando otra bandera o archivo de ignorar.

Esta bandera se puede deshabilitar con --no-hidden.

--iglob=GLOB

Incluye o excluye archivos y directorios para la búsqueda que coincidan con el glob dado. Esto siempre anula cualquier otra lógica de ignorar. Se pueden usar múltiples banderas glob. Las reglas de glob coinciden con las reglas de .gitignore. Anteceda un glob con ! para excluirlo. Si varios globs coinciden con un archivo o directorio, el glob dado más tarde en la línea de comandos tiene precedencia. Los globs utilizados a través de esta bandera se comparan sin distinguir entre mayúsculas y minúsculas.

--ignore-file=PATH

Especifica una ruta a uno o más archivos de reglas con formato gitignore. Estos patrones se aplican después de los patrones encontrados en .gitignore, .rgignore y .ignore y se comparan en relación con el directorio de trabajo actual. Es decir, los archivos especificados a través de esta bandera tienen menor precedencia que los archivos encontrados automáticamente en el árbol de directorios. Se pueden especificar varios archivos de ignorar adicionales utilizando esta bandera repetidamente. Al especificar varios archivos de ignorar, los archivos anteriores tienen menor precedencia que los archivos posteriores.

Si está buscando una forma de incluir o excluir archivos y directorios directamente en la línea de comandos, use -g/--glob en su lugar.

--ignore-file-case-insensitive

Procesa los archivos de ignorar (.gitignore, .ignore, etc.) sin distinguir entre mayúsculas y minúsculas. Tenga en cuenta que esto conlleva una penalización de rendimiento y es más útil en sistemas de archivos que no distinguen entre mayúsculas y minúsculas (como Windows).

Esta bandera se puede deshabilitar con --no-ignore-file-case-insensitive.

-d NUM, --max-depth=NUM

Esta bandera limita la profundidad del recorrido del directorio a NUM niveles más allá de las rutas dadas. Un valor de 0 solo busca las rutas dadas explícitamente.

Por ejemplo, rg --max-depth 0 dir/ no hace nada porque no se descenderá en dir/. rg --max-depth 1 dir/ solo buscará en los hijos directos de dir.

Una forma alternativa para esta bandera es --maxdepth.

--max-filesize=NUM+SUFIJO?

Ignora archivos de más de NUM de tamaño. Esto no se aplica a los directorios.

El formato de entrada acepta sufijos de K, M o G que corresponden a kilobytes, megabytes y gigabytes, respectivamente. Si no se proporciona sufijo, la entrada se trata como bytes.

Ejemplos: --max-filesize 50K o --max-filesize 80M.

--no-ignore

Cuando está activado, los archivos de ignorar como .gitignore, .ignore y .rgignore no se respetarán. Esto implica --no-ignore-dot, --no-ignore-exclude, --no-ignore-global, --no-ignore-parent y --no-ignore-vcs.

Esto no implica --no-ignore-files, ya que --ignore-file se especifica explícitamente como un argumento de línea de comandos.

Cuando se proporciona solo una vez, la bandera -u/--unrestricted es idéntica en comportamiento a esta bandera y puede considerarse un alias. Sin embargo, las banderas posteriores -u/--unrestricted tienen efectos adicionales.

Esta bandera se puede deshabilitar con --ignore.

--no-ignore-dot

No respeta las reglas de filtro de los archivos .ignore o .rgignore.

Esto no afecta si ripgrep ignorará archivos y directorios cuyos nombres comienzan con un punto (.). Para eso, consulte la bandera -./--hidden. Esta bandera tampoco afecta si se respetan las reglas de filtro de los archivos .gitignore.

Esta bandera se puede deshabilitar con --ignore-dot.

--no-ignore-exclude

No respeta las reglas de filtro de archivos configurados manualmente para el repositorio. Por ejemplo, esto incluye el archivo .git/info/exclude de git.

Esta bandera se puede deshabilitar con --ignore-exclude.

--no-ignore-files

Cuando está activado, se ignoran todas las banderas --ignore-file, incluso las que aparecen después de esta bandera.

Esta bandera se puede deshabilitar con --ignore-files.

--no-ignore-global

No respeta las reglas de filtro de los archivos de ignorar que provienen de fuentes "globales", como la opción de configuración core.excludesFile de git (que por defecto es $HOME/.config/git/ignore).

Esta bandera se puede deshabilitar con --ignore-global.

--no-ignore-parent

Cuando esta bandera está activada, las reglas de filtro de los archivos de ignorar encontrados en directorios padre no se respetan. Por defecto, ripgrep ascenderá por los directorios padre del directorio de trabajo actual para buscar cualquier archivo de ignorar aplicable que deba aplicarse. En algunos casos, esto puede no ser deseable.

Esta bandera se puede deshabilitar con --ignore-parent.

--no-ignore-vcs

Cuando se proporciona, las reglas de filtro de los archivos de ignorar del control de origen (por ejemplo, .gitignore) no se respetan. Por defecto, ripgrep respeta las reglas de ignorar de git para el filtrado automático. En algunos casos, puede no ser deseable respetar las reglas de ignorar del control de origen y, en su lugar, solo respetar las reglas en .ignore o .rgignore.

Tenga en cuenta que esta bandera no afecta directamente al filtrado de archivos o carpetas de control de origen que comienzan con un punto (.), como .git. Estos se ven afectados por -./--hidden y sus banderas relacionadas en su lugar.

Esta bandera implica --no-ignore-parent para los archivos de ignorar de control de origen también.

Esta bandera se puede deshabilitar con --ignore-vcs.

--no-require-git

Cuando se proporciona esta bandera, los archivos de ignorar del control de origen, como .gitignore, se respetan incluso si no hay ningún repositorio de git presente.

Por defecto, ripgrep solo respetará las reglas de filtro de los archivos de ignorar del control de origen cuando ripgrep detecte que la búsqueda se está ejecutando dentro de un repositorio de control de origen. Por ejemplo, cuando se observa un directorio .git.

Esta bandera relaja la restricción predeterminada. Por ejemplo, podría ser útil cuando el contenido de un repositorio de git se almacena o copia en algún lugar, pero donde el estado del repositorio está ausente.

Esta bandera se puede deshabilitar con --require-git.

--one-file-system

Cuando está habilitado, ripgrep no cruzará los límites del sistema de archivos en relación con el punto de inicio de la búsqueda.

Tenga en cuenta que esto se aplica a cada argumento de ruta dado a ripgrep. Por ejemplo, en el comando

    rg --one-file-system /foo/bar /quux/baz

ripgrep buscará tanto en /foo/bar como en /quux/baz incluso si están en sistemas de archivos diferentes, pero no cruzará un límite de sistema de archivos al recorrer el árbol de directorios de cada ruta.

Esto es similar a la bandera -xdev o -mount de find.

Esta bandera se puede deshabilitar con --no-one-file-system.

-t TYPE, --type=TYPE

Esta bandera limita ripgrep a buscar archivos que coincidan con TYPE. Se pueden proporcionar varias banderas -t/--type.

Esta bandera admite el valor especial all, que se comportará como si se hubiera proporcionado -t/--type para cada tipo de archivo compatible con ripgrep (incluidos los tipos de archivo personalizados). El resultado final es que --type=all hace que ripgrep busque en modo "lista blanca", donde solo buscará archivos que reconoce a través de sus definiciones de tipo.

Tenga en cuenta que esta bandera tiene menor precedencia que tanto la bandera -g/--glob como las reglas encontradas en los archivos de ignorar.

Para ver la lista de tipos de archivo disponibles, use la bandera --type-list.

-T TYPE, --type-not=TYPE

No busques archivos que coincidan con TYPE. Se pueden proporcionar varias banderas -T/--type-not. Use el comando --ty
Aquí tienes la traducción del contenido al español, manteniendo la estructura del archivo: pe-list para listar todos los tipos disponibles.

Esta bandera soporta el valor especial all, que se comportará como si se hubiera proporcionado -T/--type-not para cada tipo de archivo soportado por ripgrep (incluyendo cualquier tipo de archivo personalizado). El resultado final es que --type-not=all hace que ripgrep busque en modo de "lista negra", donde solo buscará archivos que no sean reconocidos por sus definiciones de tipo.

Para ver la lista de tipos de archivo disponibles, usa la bandera --type-list.

--type-add=TYPESPEC

Esta bandera añade un nuevo glob para un tipo de archivo particular. Solo se puede añadir un glob a la vez. Se pueden proporcionar múltiples banderas --type-add. A menos que se use --type-clear, los globs se añaden a cualquier glob existente definido dentro de ripgrep.

Ten en cuenta que esto debe pasarse a cada invocación de ripgrep. Las configuraciones de tipo no se persisten. Ver ARCHIVOS DE CONFIGURACIÓN para una solución alternativa.

Ejemplo:

    rg --type-add 'foo:*.foo' -tfoo PATRÓN

Esta bandera también puede usarse para incluir reglas de otros tipos con la directiva especial de inclusión. La directiva de inclusión permite especificar uno o más nombres de tipo (separados por coma) que han sido definidos y sus reglas se importarán automáticamente en el tipo especificado. Por ejemplo, para crear un tipo llamado src que coincida con archivos C++, Python y Markdown, se puede usar:

    --type-add 'src:include:cpp,py,md'

Reglas de glob adicionales aún se pueden añadir al tipo src usando esta bandera nuevamente:

    --type-add 'src:include:cpp,py,md' --type-add 'src:*.foo'

Ten en cuenta que los nombres de tipo deben consistir únicamente en letras o números Unicode. Los caracteres de puntuación no están permitidos.

--type-clear=TIPO

Borra los globs de tipos de archivo definidos previamente para TIPO. Esto borra cualquier glob previamente definido para el TIPO, pero los globs se pueden añadir después de esta bandera.

Ten en cuenta que esto debe pasarse a cada invocación de ripgrep. Las configuraciones de tipo no se persisten. Ver ARCHIVOS DE CONFIGURACIÓN para una solución alternativa.

-u, --unrestricted

Esta bandera reduce el nivel de filtrado "inteligente". Usos repetidos (hasta 3) reducen aún más el filtrado. Cuando se repite tres veces, ripgrep buscará en cada archivo de un árbol de directorios.

Una sola bandera -u/--unrestricted es equivalente a --no-ignore. Dos banderas -u/--unrestricted son equivalentes a --no-ignore -./--hidden. Tres banderas -u/--unrestricted son equivalentes a --no-ignore -./--hidden --binary.

El único filtrado que aún realiza ripgrep cuando se da -uuu es omitir enlaces simbólicos y evitar imprimir coincidencias de archivos binarios. Los enlaces simbólicos pueden seguirse mediante la bandera -L/--follow, y los archivos binarios pueden tratarse como archivos de texto mediante la bandera -a/--text.

OPCIONES DE SALIDA

-A NUM, --after-context=NUM

Muestra NUM líneas después de cada coincidencia.

Esto anula la bandera --passthru y anula parcialmente la bandera -C/--context.

-B NUM, --before-context=NUM

Muestra NUM líneas antes de cada coincidencia.

Esto anula la bandera --passthru y anula parcialmente la bandera -C/--context.

--block-buffered

Cuando está habilitado, ripgrep usará buffering de bloque. Es decir, cada vez que se encuentre una línea coincidente, se escribirá en un buffer en memoria y no se escribirá en la salida estándar hasta que el buffer alcance un cierto tamaño. Este es el comportamiento predeterminado cuando la salida estándar de ripgrep se redirige a una tubería o a un archivo. Cuando la salida estándar de ripgrep está conectada a un tty, se usará buffering de línea por defecto. Forzar el buffering de bloque puede ser útil al volcar una gran cantidad de contenido a un tty.

Esto anula la bandera --line-buffered.

Esta bandera se puede deshabilitar con --no-block-buffered.

-b, --byte-offset

Imprime el desplazamiento de bytes (basado en 0) dentro del archivo de entrada antes de cada línea de salida. Si se especifica -o/--only-matching, imprime el desplazamiento del texto coincidente en sí.

Si ripgrep realiza transcodificación, el desplazamiento de bytes es en términos del resultado de la transcodificación y no de los datos originales. Esto se aplica de manera similar a otras transformaciones en los datos, como la descompresión o un filtro --pre.

Esta bandera se puede deshabilitar con --no-byte-offset.

--color=CUÁNDO

Esta bandera controla cuándo usar colores. La configuración predeterminada es auto, lo que significa que ripgrep intentará adivinar cuándo usar colores. Por ejemplo, si ripgrep está imprimiendo a un tty, usará colores, pero si se redirige a un archivo o una tubería, suprimirá la salida de color.

ripgrep suprimirá la salida de color por defecto en otras circunstancias también. Estas incluyen, pero no se limitan a:

  • Cuando la variable de entorno TERM no está establecida o está establecida a dumb.
  • Cuando la variable de entorno NO_COLOR está establecida (independientemente de su valor).
  • Cuando se proporcionan banderas que implican que no se necesitan colores. Por ejemplo, --vimgrep y --json.

Los valores posibles para esta bandera son:

nunca
Los colores nunca se usarán.
auto
El valor predeterminado. ripgrep intenta ser inteligente.
siempre
Los colores siempre se usarán independientemente de dónde se envíe la salida.
ansi
Al igual que 'siempre', pero emite escapes ANSI (incluso en una consola de Windows).

Esta bandera también controla si se emiten hipervínculos. Por ejemplo, cuando se especifica un formato de hipervínculo, los hipervínculos no se usarán cuando el color esté suprimido. Si se desean emitir hipervínculos pero no colores, se debe usar la bandera --colors para establecer manualmente todos los estilos de color a none:

    --colors 'path:none' \
    --colors 'line:none' \
    --colors 'column:none' \
    --colors 'match:none' \
    --colors 'highlight:none'

--colors=ESPECIFICACION_COLOR

Esta bandera especifica la configuración de color para usar en la salida. Esta bandera puede proporcionarse varias veces. Las configuraciones se aplican iterativamente. Las etiquetas de color preexistentes se limitan a una de ocho opciones: red, blue, green, cyan, magenta, yellow, white y black. Los estilos se limitan a nobold, bold, nointense, intense, nounderline, underline, noitalic o italic.

El formato de la bandera es {tipo}:{atributo}:{valor}. tipo debe ser uno de path, line, column, highlight o match. atributo puede ser fg, bg o style. valor es un color (para fg y bg) o un estilo de texto. Un formato especial, {tipo}:none, borrará todas las configuraciones de color para tipo.

Por ejemplo, el siguiente comando cambiará el color de coincidencia a magenta y el color de fondo de los números de línea a amarillo:

    rg --colors 'match:fg:magenta' --colors 'line:bg:yellow'

Otro ejemplo, el siguiente comando "resaltará" el texto no coincidente en las líneas coincidentes:

    rg --colors 'highlight:bg:yellow' --colors 'highlight:fg:black'

El tipo de color "highlight" es particularmente útil para contrastar líneas coincidentes con el contexto circundante impreso por las banderas -B/--before-context, -A/--after-context, -C/--context o --passthru.

Los colores extendidos se pueden usar para valor cuando el tty soporta secuencias de color ANSI. Estos se especifican como x (color 256) o x,x,x (color verdadero 24 bits) donde x es un número entre 0 y 255 inclusive. x puede ser dado como un número decimal normal o un número hexadecimal, que va precedido por 0x.

Por ejemplo, el siguiente comando cambiará el color de fondo de la coincidencia al representado por el valor rgb (0,128,255):

    rg --colors 'match:bg:0,128,255'

o, equivalentemente,

    rg --colors 'match:bg:0x0,0x80,0xFF'

Ten en cuenta que los estilos intense y nointense no tendrán efecto cuando se usen junto con estos códigos de color extendidos.

--column

Muestra los números de columna (basados en 1). Esto solo muestra los números de columna para la primera coincidencia en cada línea. Esto no intenta tener en cuenta Unicode. Un byte es igual a una columna. Esto implica -n/--line-number.

Cuando se usa -o/--only-matching, los números de columna escritos corresponden al inicio de cada coincidencia.

Esta bandera se puede deshabilitar con --no-column.

-C NUM, --context=NUM

Muestra NUM líneas antes y después de cada coincidencia. Esto es equivalente a proporcionar las banderas -B/--before-context y -A/--after-context con el mismo valor.

Esto anula la bandera --passthru. Las banderas -A/--after-context y -B/--before-context ambas anulan parcialmente esta bandera, independientemente del orden. Por ejemplo, -A2 -C1 es equivalente a -A2 -B1.

--context-separator=SEPARADOR

La cadena utilizada para separar líneas de contexto no contiguas en la salida. Esto solo se usa cuando se utiliza una de las banderas de contexto (es decir, -A/--after-context, -B/--before-context o -C/--context). Se pueden usar secuencias de escape como \x7F o \t. El valor predeterminado es --.

Cuando el separador de contexto se establece en una cadena vacía, todavía se inserta un salto de línea. Para deshabilitar completamente los separadores de contexto, use la bandera --no-context-separator.

--field-context-separator=SEPARADOR

Establece el separador de contexto de campo. Este separador solo se utiliza al imprimir líneas de contexto. Se utiliza para delimitar rutas de archivo, números de línea, columnas y la propia línea de contexto. El separador puede ser cualquier número de bytes, incluido cero. Se pueden usar secuencias de escape como \x7F o \t.

El carácter - es el valor predeterminado.

--field-match-separator=SEPARADOR

Establece el separador de coincidencia de campo. Este separador solo se utiliza al imprimir líneas coincidentes. Se utiliza para delimitar rutas de archivo, números de línea, col
Columnas y la línea coincidente en sí. El separador puede ser cualquier número de bytes, incluido cero. Se pueden usar secuencias de escape como \x7F o \t.

El carácter : es el valor predeterminado.

--heading

Este indicador imprime la ruta del archivo encima de los grupos de coincidencias de cada archivo en lugar de imprimir la ruta del archivo como prefijo para cada línea coincidente.

Este es el modo predeterminado al imprimir en una tty.

Cuando stdout no es una tty, entonces ripgrep usará por defecto el formato estándar similar a grep. Se puede forzar este formato en entornos similares a Unix redirigiendo la salida de ripgrep a cat. Por ejemplo, rg foo | cat.

Este indicador se puede deshabilitar con --no-heading.

-h, --help

Este indicador imprime la salida de ayuda para ripgrep.

A diferencia de la mayoría de los otros indicadores, el comportamiento del indicador corto, -h, y el indicador largo, --help, es diferente. El indicador corto mostrará una salida de ayuda condensada, mientras que el indicador largo mostrará una salida de ayuda detallada. La salida de ayuda detallada tiene documentación completa, mientras que la salida de ayuda condensada mostrará solo una línea para cada indicador.

--hostname-bin=COMANDO

Este indicador controla cómo ripgrep determina el nombre de host de este sistema. El valor del indicador debe corresponder a un ejecutable (ya sea una ruta o algo que se pueda encontrar a través de la variable de entorno PATH de su sistema). Cuando se establece, ripgrep ejecutará este ejecutable, sin argumentos, y tratará su salida (con los espacios en blanco iniciales y finales eliminados) como el nombre de host de su sistema.

Cuando no se establece (el valor predeterminado, o la cadena vacía), ripgrep intentará detectar automáticamente el nombre de host de su sistema. En Unix, esto corresponde a llamar a gethostname. En Windows, esto corresponde a llamar a GetComputerNameExW para obtener el "nombre de host DNS físico" del sistema.

ripgrep utiliza el nombre de host de su sistema para producir hipervínculos.

--hyperlink-format=FORMATO

Establece el formato de los hipervínculos a utilizar al imprimir resultados. Los hipervínculos hacen que ciertos elementos de la salida de ripgrep, como las rutas de archivo, sean clickeables. Esto generalmente solo funciona en emuladores de terminal que admiten hipervínculos OSC-8. Por ejemplo, el formato file://{host}{path} emitirá un hipervínculo RFC 8089. Para ver el formato que está utilizando ripgrep, pase el indicador --debug.

Alternativamente, una cadena de formato puede corresponder a uno de los siguientes alias: default, none, cursor, file, grep+, kitty, macvim, textmate, vscode, vscode-insiders, vscodium. El alias será reemplazado por una cadena de formato que está destinada a funcionar para la aplicación correspondiente.

Las siguientes variables están disponibles en la cadena de formato:

{path}
Requerido. Esto se reemplaza con una ruta a un archivo coincidente. Se garantiza que la ruta es absoluta y está codificada en porcentaje para que sea válida para ponerla en una URI. Tenga en cuenta que se garantiza que una ruta comienza con un /.
{host}
Opcional. Esto se reemplaza con el nombre de host de su sistema. En Unix, esto corresponde a llamar a gethostname. En Windows, esto corresponde a llamar a GetComputerNameExW para obtener el "nombre de host DNS físico" del sistema. Alternativamente, si se proporcionó --hostname-bin, entonces se devolverá el nombre de host devuelto por la salida de ese programa. Si no se pudo encontrar ningún nombre de host, esta variable se reemplaza con la cadena vacía.
{line}
Opcional. Si es apropiado, esto se reemplaza con el número de línea de una coincidencia. Si no hay un número de línea disponible (por ejemplo, si se dio --no-line-number), entonces se reemplaza automáticamente con el valor 1.
{column}
Opcional, pero requiere la presencia de {line}. Si es apropiado, esto se reemplaza con el número de columna de una coincidencia. Si no hay un número de columna disponible (por ejemplo, si se dio --no-column), entonces se reemplaza automáticamente con el valor 1.
{wslprefix}
Opcional. Este es un valor especial que se establece en wsl$/WSL_DISTRO_NAME, donde WSL_DISTRO_NAME corresponde al valor de la variable de entorno equivalente. Si el sistema no es Unix o si la variable de entorno WSL_DISTRO_NAME no está establecida, entonces se reemplaza con la cadena vacía.

Una cadena de formato puede estar vacía. Una cadena de formato vacía es equivalente al alias none. En este caso, los hipervínculos se deshabilitarán.

Hasta ahora, ripgrep no habilita los hipervínculos por defecto. Los usuarios deben optar por ellos. Si no está seguro de qué formato usar, pruebe default.

Al igual que los colores, cuando ripgrep detecta que stdout no está conectado a una tty, los hipervínculos se deshabilitan automáticamente, independientemente del valor de este indicador. Los usuarios pueden pasar --color=always para emitir forzadamente hipervínculos.

Tenga en cuenta que los hipervínculos solo se escriben cuando una ruta también está en la salida y los colores están habilitados. Para escribir hipervínculos sin colores, necesitará configurar ripgrep para que no coloree nada sin deshabilitar completamente todos los códigos de escape ANSI: 

    --colors 'path:none' \
    --colors 'line:none' \
    --colors 'column:none' \
    --colors 'match:none'

ripgrep funciona de esta manera porque trata el indicador --color como un proxy de si se deben usar códigos de escape ANSI o no. Esto significa que las variables de entorno como NO_COLOR=1 y TERM=dumb no solo deshabilitan los colores, sino también los hipervínculos. De manera similar, los colores y los hipervínculos se deshabilitan cuando ripgrep no escribe en una tty. (A menos que uno fuerce la situación estableciendo --color=always).

Si está buscando directamente en un archivo, por ejemplo: 

    rg foo path/to/file

entonces no se emitirán hipervínculos ya que la ruta dada no aparece en la salida. Para que la ruta aparezca, y por lo tanto también un hipervínculo, use el indicador -H/--with-filename.

Para obtener más información sobre hipervínculos en emuladores de terminal, consulte: https://gist.github.com/egmontkob/eb114294efbcd5adb1944c9f3cb5feda

--include-zero

Cuando se usa con -c/--count o --count-matches, esto hace que ripgrep imprima el número de coincidencias para cada archivo, incluso si hubo cero coincidencias. Esto está deshabilitado por defecto, pero se puede habilitar para que ripgrep se comporte más como grep.

Este indicador se puede deshabilitar con --no-include-zero.

--line-buffered

Cuando está habilitado, ripgrep siempre usará buffer de línea. Es decir, cada vez que se encuentre una línea coincidente, se enviará a stdout inmediatamente. Este es el valor predeterminado cuando el stdout de ripgrep está conectado a una tty, pero de lo contrario, ripgrep usará buffer de bloques, que es típicamente más rápido. Este indicador fuerza a ripgrep a usar buffer de línea, incluso si de lo contrario usaría buffer de bloques. Esto es típicamente útil en pipelines de shell, por ejemplo: 
    tail -f something.log | rg foo --line-buffered | rg bar

Esto anula el indicador --block-buffered.

Este indicador se puede deshabilitar con --no-line-buffered.

-n, --line-number

Mostrar números de línea (basados en 1).

Esto está habilitado por defecto cuando stdout está conectado a una tty.

Este indicador se puede deshabilitar con -N/--no-line-number.

-N, --no-line-number

Suprimir números de línea.

Los números de línea están deshabilitados por defecto cuando stdout no está conectado a una tty.

Los números de línea se pueden activar forzadamente con -n/--line-number.

-M NUM, --max-columns=NUM

Cuando se proporciona, ripgrep omitirá las líneas más largas que este límite en bytes. En lugar de imprimir líneas largas, solo se imprime el número de coincidencias en esa línea.

Cuando este indicador se omite o se establece en 0, entonces no tiene ningún efecto.

--max-columns-preview

Imprime una vista previa de las líneas que exceden el límite de columnas configurado.

Cuando se usa el indicador -M/--max-columns, ripgrep reemplazará por defecto completamente cualquier línea que sea demasiado larga con un mensaje indicando que se eliminó una línea coincidente. Cuando este indicador se combina con -M/--max-columns, en su lugar se muestra una vista previa de la línea (correspondiente al tamaño del límite), donde la parte de la línea que excede el límite no se muestra.

Si el indicador -M/--max-columns no está establecido, entonces esto no tiene ningún efecto.

Este indicador se puede deshabilitar con --no-max-columns-preview.

-0, --null

Siempre que se imprime la ruta de un archivo, síguela con un byte NUL. Esto incluye imprimir rutas de archivo antes de las coincidencias, y al imprimir una lista de archivos coincidentes como con -c/--count, -l/--files-with-matches y --files. Esta opción es útil para usar con xargs.

-o, --only-matching

Imprime solo las partes coincidentes (no vacías) de una línea coincidente, con cada parte de este tipo en una línea de salida separada.

--path-separator=SEPARADOR

Establece el separador de ruta a utilizar al imprimir rutas de archivo. Esto por defecto es el separador de ruta de su plataforma, que es / en Unix y \ en Windows. Este indicador está destinado a anular el valor predeterminado cuando el entorno lo exige (por ejemplo, cygwin). Un separador de ruta se limita a un solo byte.

Establecer este indicador en una cadena vacía lo revierte a su comportamiento predeterminado. Es decir, el separador de ruta se elige automáticamente según el entorno.

--passthru

Imprime tanto las líneas coincidentes como las no coincidentes.

Otra forma de lograr un efecto similar es modificando su patrón para que coincida con la cadena vacía. Por ejemplo, si está buscando usando rg foo, entonces usando rg '^|foo' en su lugar emitirá cada línea en cada archivo buscado, pero solo las ocurrencias de foo se resaltarán. Este indicador habilita el mismo comportamiento sin necesidad de modificar el patrón.

Una ortografía alternativa para este indicador es --passthrough.

Esto anula los indicadores -C/--context, -A/--after-context y -B/--before-context.

-p, --pretty

Este es un alias de conveniencia para --color=always --heading --line-number. Este indicador es útil cuando todavía desea una salida atractiva incluso si está redirigiendo ripgrep a otro programa o archivo. Por ejemplo: rg -p foo | less -R.

-q, --quiet

No imprima nada en stdout. Si se encuentra una coincidencia en un archivo, entonces ripgrep dejará de buscar. Esto es útil
cuando se usa ripgrep solo por su código de salida (que será un código de error si no se encuentran coincidencias).

Cuando se usa --files, ripgrep dejará de buscar archivos después de encontrar el primer archivo que no coincida con ninguna regla de ignorar.

-r REEMPLAZO, --replace=REEMPLAZO

Reemplaza cada coincidencia con el texto proporcionado al imprimir los resultados. Ni esta bandera ni ninguna otra bandera de ripgrep modificarán tus archivos.

Los índices de grupos de captura (por ejemplo, $5) y nombres (por ejemplo, $foo) son compatibles en la cadena de reemplazo. Los índices de grupos de captura se numeran según la posición del paréntesis de apertura del grupo, donde el grupo más a la izquierda es $1. El grupo especial $0 corresponde a la coincidencia completa.

El nombre de un grupo se forma tomando la cadena más larga de letras, números y guiones bajos (es decir, [_0-9A-Za-z]) después del $. Por ejemplo, $1a se reemplazará con el grupo llamado 1a, no con el grupo en el índice 1. Si el nombre del grupo contiene caracteres que no son letras, números o guiones bajos, o si deseas seguir inmediatamente el grupo con otro texto, el nombre debe colocarse entre llaves. Por ejemplo, ${1}a tomará el contenido del grupo en el índice 1 y le añadirá a al final.

Si un índice o nombre no se refiere a un grupo de captura válido, se reemplazará con una cadena vacía.

En shells como Bash y zsh, debes encerrar el patrón entre comillas simples en lugar de comillas dobles. De lo contrario, los índices de grupos de captura serán reemplazados por variables de shell expandidas que muy probablemente estarán vacías.

Para escribir un $ literal, usa $$.

Ten en cuenta que el reemplazo, por defecto, reemplaza cada coincidencia, y no la línea completa. Para reemplazar la línea completa, debes hacer coincidir la línea completa.

Esta bandera se puede usar con la bandera -o/--only-matching.

--sort=ORDENARPOR

Esta bandera habilita la ordenación de resultados en orden ascendente. Los valores posibles para esta bandera son:
none
(Por defecto) No ordenar resultados. El más rápido. Puede ser multihilo.
path
Ordenar por ruta de archivo. Siempre de un solo hilo. El orden se determina ordenando los archivos en cada entrada de directorio durante el recorrido. Esto significa que dados los archivos a/b y a+, el segundo se ordenará después del primero aunque + normalmente se ordenaría antes que /.
modified
Ordenar por la última hora de modificación de un archivo. Siempre de un solo hilo.
accessed
Ordenar por la última hora de acceso a un archivo. Siempre de un solo hilo.
created
Ordenar por la hora de creación de un archivo. Siempre de un solo hilo.

Si el criterio de ordenación elegido (manual o por defecto) no está disponible en tu sistema (por ejemplo, la hora de creación no está disponible en sistemas de archivos ext4), ripgrep intentará detectarlo, mostrará un error y saldrá sin buscar.

Para ordenar los resultados en orden inverso o descendente, usa la bandera --sortr. Además, esta bandera anula --sortr.

Ten en cuenta que ordenar resultados actualmente obliga a ripgrep a abandonar el paralelismo y ejecutarse en un solo hilo.

--sortr=ORDENARPOR

Esta bandera habilita la ordenación de resultados en orden descendente. Los valores posibles para esta bandera son:
none
(Por defecto) No ordenar resultados. El más rápido. Puede ser multihilo.
path
Ordenar por ruta de archivo. Siempre de un solo hilo. El orden se determina ordenando los archivos en cada entrada de directorio durante el recorrido. Esto significa que dados los archivos a/b y a+, el segundo se ordenará antes que el primero aunque + normalmente se ordenaría después que / al hacer una ordenación lexicográfica inversa.
modified
Ordenar por la última hora de modificación de un archivo. Siempre de un solo hilo.
accessed
Ordenar por la última hora de acceso a un archivo. Siempre de un solo hilo.
created
Ordenar por la hora de creación de un archivo. Siempre de un solo hilo.

Si el criterio de ordenación elegido (manual o por defecto) no está disponible en tu sistema (por ejemplo, la hora de creación no está disponible en sistemas de archivos ext4), ripgrep intentará detectarlo, mostrará un error y saldrá sin buscar.

Para ordenar los resultados en orden ascendente, usa la bandera --sort. Además, esta bandera anula --sort.

Ten en cuenta que ordenar resultados actualmente obliga a ripgrep a abandonar el paralelismo y ejecutarse en un solo hilo.

--trim

Cuando se activa, se eliminará todo el espacio en blanco ASCII al principio de cada línea impresa.

Esta bandera se puede desactivar con --no-trim.

--vimgrep

Esta bandera instruye a ripgrep a imprimir los resultados con cada coincidencia en su propia línea, incluyendo números de línea y números de columna.

Con esta opción, una línea con más de una coincidencia se imprimirá en su totalidad más de una vez. Por esa razón, la cantidad total de salida como resultado de esta bandera puede ser cuadrática en el tamaño de la entrada. Por ejemplo, si el patrón coincide con cada byte en un archivo de entrada, cada línea se repetirá por cada byte coincidente. Por esta razón, los usuarios solo deben usar esta bandera cuando no haya otra opción. Las integraciones de editor deben preferir alguna otra forma de leer resultados de ripgrep, como a través de la bandera --json. Una alternativa para evitar un uso de memoria exorbitante es forzar a ripgrep al modo de un solo hilo con la bandera -j/--threads. Sin embargo, ten en cuenta que esto no afectará el tamaño total de la salida, solo la memoria heap que usará ripgrep.

-H, --with-filename

Esta bandera instruye a ripgrep a imprimir la ruta del archivo para cada línea coincidente. Este es el comportamiento por defecto cuando se buscan más de un archivo. Si --heading está habilitado (el comportamiento por defecto al imprimir a una tty), la ruta del archivo se mostrará encima de los grupos de coincidencias de cada archivo; de lo contrario, el nombre del archivo se mostrará como prefijo para cada línea coincidente.

Esta bandera anula -I/--no-filename.

-I, --no-filename

Esta bandera instruye a ripgrep a no imprimir nunca la ruta del archivo con cada línea coincidente. Este es el comportamiento por defecto cuando se le indica explícitamente a ripgrep que busque un solo archivo o stdin.

Esta bandera anula -H/--with-filename.

--sort-files

OBSOLETO. Usa --sort=path en su lugar.

Esta bandera instruye a ripgrep a ordenar los resultados de búsqueda por ruta de archivo lexicográficamente en orden ascendente. Ten en cuenta que esto actualmente deshabilita todo paralelismo y ejecuta la búsqueda en un solo hilo.

Esta bandera anula --sort y --sortr.

Esta bandera se puede desactivar con --no-sort-files.

MODOS DE SALIDA

-c, --count

Esta bandera suprime la salida normal y muestra el número de líneas que coinciden con los patrones dados para cada archivo buscado. Cada archivo que contenga una coincidencia tendrá su ruta y recuento impresos en cada línea. Ten en cuenta que a menos que se habilite -U/--multiline y los patrones dados puedan coincidir en varias líneas, esto informa el número de líneas que coinciden y no el número total de coincidencias. Cuando el modo multilínea está habilitado y los patrones dados pueden coincidir en varias líneas, -c/--count es equivalente a --count-matches.

Si solo se proporciona un archivo a ripgrep, entonces solo se imprimirá el recuento si hay una coincidencia. La bandera -H/--with-filename se puede usar para forzar la impresión de la ruta del archivo en este caso. Si necesitas que se imprima un recuento independientemente de si hay una coincidencia, usa --include-zero.

Ten en cuenta que es posible que esta bandera tenga resultados inconsistentes con la salida de -l/--files-with-matches. Notablemente, por defecto, ripgrep intenta evitar buscar archivos con datos binarios. Con esta bandera, ripgrep necesita buscar todo el contenido de los archivos, lo que puede incluir datos binarios. Pero con -l/--files-with-matches, ripgrep puede detenerse tan pronto como se observe una coincidencia, lo que puede ocurrir mucho antes de cualquier dato binario. Para evitar esta inconsistencia sin deshabilitar la detección de binarios, usa la bandera --binary.

Esto anula la bandera --count-matches. Ten en cuenta que cuando -c/--count se combina con -o/--only-matching, ripgrep se comporta como si se hubiera dado --count-matches.

--count-matches

Esta bandera suprime la salida normal y muestra el número de coincidencias individuales de los patrones dados para cada archivo buscado. Cada archivo que contenga coincidencias tendrá su ruta y recuento de coincidencias impresos en cada línea. Ten en cuenta que esto informa el número total de coincidencias individuales y no el número de líneas que coinciden.

Si solo se proporciona un archivo a ripgrep, entonces solo se imprimirá el recuento si hay una coincidencia. La bandera -H/--with-filename se puede usar para forzar la impresión de la ruta del archivo en este caso.

Esto anula la bandera -c/--count. Ten en cuenta que cuando -c/--count se combina con -o/--only-matching, ripgrep se comporta como si se hubiera dado --count-matches.

-l, --files-with-matches

Imprime solo las rutas con al menos una coincidencia y suprime el contenido de las coincidencias.

Ten en cuenta que es posible que esta bandera tenga resultados inconsistentes con la salida de -c/--count. Notablemente, por defecto, ripgrep intenta evitar buscar archivos con datos binarios. Con esta bandera, ripgrep puede dejar de buscar antes de que se observen datos binarios. Pero con -c/--count, ripgrep tiene que buscar todo el contenido para determinar el recuento de coincidencias, lo que significa que podría ver datos binarios que provoquen que omita la búsqueda de ese archivo. Para evitar esta inconsistencia sin deshabilitar la detección de binarios, usa la bandera --binary.

Esto anula --files-without-match.

--files-without-match

Imprime las rutas que contienen cero coincidencias y suprime el contenido de las coincidencias.

Esto anula -l/--files-with-matches.

DESCRIPTION

ripgrep is a line-oriented search tool that recursively searches the current directory for a regex that matches each input line. ripgrep has been optimized to retry faster than other tools. For example, ripgrep implements a cache for the directory structure of the current directory, and uses a bloom filter to avoid file contents scanning when possible.

By default, ripgrep respects the following ignore rules:

  • It will ignore files and directories specified in .gitignore, .ignore, and .ripgreprc files.
  • It will ignore files and directories specified in the ignore file specified by the RIPGREP_CONFIG_PATH environment variable.
  • It will ignore files and directories specified in the ignore file specified by the --ignore-file option.
  • It will ignore files specified by the .git/info/exclude file.
  • It will skip hidden files and directories by default.
  • It will skip binary files by default.

The full list of ignore files ripgrep consults is:

  • .gitignore
  • .git/info/exclude
  • .ignore
  • .ripgreprc

The order listed above is the order in which they are read. If a file is missing or empty, then the next file is read. If a file is present, then the rest of the files are skipped. This behavior is configurable with the --no-ignore flag.

If ripgrep finds a file that should be ignored, it will not be searched. If ripgrep finds a directory that should be ignored, then the entire directory will be skipped.

ripgrep supports the following regex syntaxes:

  • The default syntax is Perl-compatible regular expressions (PCRE) with Unicode support.
  • The -s/--multiline flag can be enabled to change the default behavior of PCRE to match across multiple lines.

If no file path is specified, ripgrep searches the current directory.

If a file path is specified, ripgrep searches that file.

If multiple file paths are specified, ripgrep searches all of them.

ripgrep prints each matching line to standard output, prefixed by the file name and line number. If a file has multiple matches, then the file name is only printed for the first match. If the -H flag is given, then the file name is printed for every match.

If the -v flag is given, then ripgrep prints lines that do not match the regex.

ripgrep uses the Rust regex crate, which implements a variant of Perl syntax.

The following is a quick reference:

*

+
Matches the preceding element one or more times.
?
Matches the preceding element zero or one times.
^
Matches the start of the string.
$

|

The exit status is zero if zero or more matches were found, and non-zero otherwise.

AUTOMATIC FILTERING

ripgrep supports several types of automatic filtering to reduce the set of files that are searched. These include ignoring files specified in .gitignore files, hidden files, binary files, and symlinks.

Each of the types of filtering can be configured via command line flags:

  • There are several flags starting with --no-ignore that toggle which, if any, ignore rules are respected. --no-ignore by itself will disable all of them.
  • -./--hidden will force ripgrep to search hidden files and directories.
  • --binary will force ripgrep to search binary files.
  • -L/--follow will force ripgrep to follow symlinks.

As a special short hand, the -u flag can be specified up to three times. Each additional time incrementally decreases filtering:

  • -u is equivalent to --no-ignore.
  • -uu is equivalent to --no-ignore --hidden.
  • -uuu is equivalent to --no-ignore --hidden --binary.

In particular, rg -uuu should search the same exact content as grep -r.

CONFIGURATION FILES

ripgrep supports reading configuration files that change ripgrep's default behavior. The format of the configuration file is an "rc" style and is very simple. It is defined by two rules:

1.
Every line is a shell argument, after trimming whitespace.
2.
Lines starting with # (optionally preceded by any amount of whitespace) are ignored.

ripgrep will look for a single configuration file if and only if the RIPGREP_CONFIG_PATH environment variable is set and is non-empty. ripgrep will parse arguments from this file on startup and will behave as if the arguments in this file were prepended to any explicit arguments given to ripgrep on the command line. Note though that the rg command you run must still be valid. That is, it must always contain at least one pattern at the command line, even if the configuration file uses the -e/--regexp flag.

For example, if your ripgreprc file contained a single line:

    --smart-case

then the following command

    RIPGREP_CONFIG_PATH=wherever/.ripgreprc rg foo

would behave identically to the following command:

    rg --smart-case foo

Another example is adding types, like so:

    --type-add
    web:*.{html,css,js}*

The above would behave identically to the following command:

    rg --type-add 'web:*.{html,css,js}*' foo

The same applies to using globs. This:

    --glob=!.git

or this:

    --glob
    !.git

would behave identically to the following command:

    rg --glob '!.git' foo

The bottom line is that every shell argument needs to be on its own line. So for example, a config file containing

    -j 4

is probably not doing what you intend. Instead, you want

    -j
    4

or

    -j4

ripgrep also provides a flag, --no-config, that when present will suppress any and all support for configuration. This includes any future support for auto-loading configuration files from pre-determined paths.

Conflicts between configuration files and explicit arguments are handled exactly like conflicts in the same command line invocation. That is, assuming your config file contains only --smart-case, then this command:

    RIPGREP_CONFIG_PATH=wherever/.ripgreprc rg foo --case-sensitive

is exactly equivalent to

    rg --smart-case foo --case-sensitive

in which case, the --case-sensitive flag would override the --smart-case flag.

SHELL COMPLETION

Shell completion files are included in the release tarball for Bash, Fish, Zsh and PowerShell.

For bash, move rg.bash to $XDG_CONFIG_HOME/bash_completion or /etc/bash_completion.d/.

For fish, move rg.fish to $HOME/.config/fish/completions.

For zsh, move _rg to one of your $fpath directories.

CAVEATS

ripgrep may abort unexpectedly when using default settings if it searches a file that is simultaneously truncated. This behavior can be avoided by passing the --no-mmap flag which will forcefully disable the use of memory maps in all cases.

ripgrep may use a large amount of memory depending on a few factors. Firstly, if ripgrep uses parallelism for search (the default), then the entire output for each individual file is buffered into memory in order to prevent interleaving matches in the output. To avoid this, you can disable parallelism with the -j1 flag. Secondly, ripgrep always needs to have at least a single line in memory in order to execute a search. A file with a very long line can thus cause ripgrep to use a lot of memory. Generally, this only occurs when searching binary data with the -a/--text flag enabled. (When the -a/--text flag isn't enabled, ripgrep will replace all NUL bytes with line terminators, which typically prevents exorbitant memory usage.) Thirdly, when ripgrep searches a large file using a memory map, the process will likely report its resident memory usage as the size of the file. However, this does not mean ripgrep actually needed to use that much heap memory; the operating system will generally handle this for you.
