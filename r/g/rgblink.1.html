RGBLINK(1) Manual de comandos generales RGBLINK(1)

NOMBRE

rgblink — Enlazador de Game Boy

SINOPSIS

rgblink [-dhMtVvwx] [-l script_enlazador] [-m archivo_mapa] [-n archivo_simbolos] [-O archivo_superposicion] [-o archivo_salida] [-p valor_relleno] [-S especificacion] [-W advertencia] archivo ...

DESCRIPCIÓN

El programa rgblink enlaza archivos objeto de RGB, típicamente creados por rgbasm(1), en un único archivo ROM de Game Boy. El formato del archivo objeto se documenta en rgbds(5).

Las secciones ROM0 se colocan en los primeros 16 KiB de la ROM de salida, y las secciones ROMX se colocan en cualquier “banco” de 16 KiB excepto el primero. Si tu ROM solo tendrá 32 KiB, puedes usar la opción -t para cambiar esto.

De manera similar, las secciones WRAM0 se colocan en los primeros 4 KiB de WRAM (“banco 0”), y las secciones WRAMX se colocan en cualquier banco de los últimos 4 KiB. Si tu ROM no utiliza WRAM con bancos, puedes usar la opción -w para cambiar esto.

Además, si tu ROM está diseñada para una Game Boy monocromática, puedes asegurarte de no usar ninguna sección incompatible usando la opción -d, que habilita implícitamente -w pero también prohíbe el uso de VRAM con bancos.

El archivo de entrada archivo_asm puede ser una ruta a un archivo, o - para leer desde la entrada estándar.

Ten en cuenta que las opciones pueden abreviarse siempre que la abreviatura sea inequívoca: --verb es --verbose, pero --ver no es válido porque también podría ser --version. Los argumentos son los siguientes:

-d, --dmg
Habilita el modo DMG. Prohíbe el uso de secciones que no existen en un DMG, como el banco VRAM 1. Esta opción habilita automáticamente -w.
-h, --help
Imprime el texto de ayuda del programa y sale.
-l script_enlazador, --linkerscript script_enlazador
Especifica un archivo de script enlazador que indica al enlazador cómo deben colocarse las secciones en la ROM. Los atributos asignados en el script enlazador deben ser consistentes con los asignados en el código. Consulta rgblink(5) para más información sobre el formato del script enlazador.
-M, --no-sym-in-map
Si se especifica, el archivo mapa no listará símbolos, solo secciones.
-m archivo_mapa, --map archivo_mapa
Escribe un archivo mapa en el nombre de archivo dado, listando cómo se asignaron las secciones y los símbolos.
-n archivo_simbolos, --sym archivo_simbolos
Escribe un archivo de símbolos en el nombre de archivo dado, listando todas las etiquetas visibles y las constantes numéricas exportadas. Las etiquetas muestran su banco y dirección, las constantes numéricas muestran su valor, siguiendo esta especificación. Varios programas externos pueden usar esta información, por ejemplo, para ayudar a depurar ROMs.
-O archivo_superposicion, --overlay archivo_superposicion
Si se especifica, las secciones se superpondrán “encima” de la imagen ROM archivo_superposicion: el espacio vacío entre secciones se llenará con los bytes correspondientes de archivo_superposicion. Esto es útil para parchear una ROM existente. ¡Ten en cuenta que todas las secciones deben ser fijas (banco forzado y dirección)!
-o archivo_salida, --output archivo_salida
Escribe la imagen ROM en el archivo dado.
-p valor_relleno, --pad valor_relleno
Al insertar relleno entre secciones, rellena con este valor. El valor por defecto es 0.
-S especificacion, --scramble especificacion
Habilita un algoritmo de “aleatorización” diferente para colocar secciones. Consulta Algoritmo de aleatorización a continuación para una explicación y una descripción de especificacion.
-t, --tiny
Expande el tamaño de la sección ROM0 de 16 KiB a los 32 KiB completos asignados a ROM. Las secciones ROMX que están fijadas a un banco que no sea el 1 se convierten en errores, otras secciones ROMX se tratan como ROM0. Útil para ROMs que caben en 32 KiB.
-V, --version
Imprime la versión del programa y sale.
-v, --verbose
Detallado: habilita la impresión de más información en la salida de error estándar.
-W advertencia, --warning advertencia
Establece la bandera de advertencia advertencia. Se imprimirá un mensaje de advertencia si advertencia es una bandera de advertencia desconocida. Consulta la sección DIAGNÓSTICO para ver una lista de advertencias.
-w, --wramx
Expande el tamaño de la sección WRAM0 de 4 KiB a los 8 KiB completos asignados a WRAM. Las secciones WRAMX que están fijadas a un banco que no sea el 1 se convierten en errores, otras secciones WRAMX se tratan como WRAM0.
-x, --nopad
Deshabilita el relleno al final del archivo final. Esta opción habilita automáticamente -t. Puedes usarla para crear archivos binarios que no sean una ROM. Al crear una ROM, ten en cuenta que no usar esta opción no reemplaza la opción -p de rgbfix(1).

Algoritmo de aleatorización

El algoritmo de colocación de secciones por defecto intenta minimizar el número de bancos utilizados; la “aleatorización” en su lugar coloca secciones en un conjunto dado de bancos, intentando minimizar el número de secciones que comparten un banco dado. Esto es útil para detectar suposiciones de banco rotas, como esperar que dos secciones diferentes terminen en el mismo banco (eso no está garantizado a menos que ambas se les asigne manualmente el mismo número de banco).

Una especificación de aleatorización es una lista separada por comas de especificaciones de región. Se permite una coma final, así como espacios en blanco entre todas las especificaciones y sus componentes. Cada especificación de región tiene el siguiente formato:

región[=tamaño]
región debe ser una de las siguientes (sin distinción de mayúsculas y minúsculas), mientras que tamaño debe ser un entero decimal positivo entre 1 y el máximo correspondiente. Ciertas regiones permiten omitir el tamaño, en cuyo caso se usa su valor máximo por defecto.
Nombre de región Tamaño máximo Tamaño opcional
romx 65535 No
sram 65535 No
wramx 65535 No
vram 65535 No
rom 1 Sí
wram 1 Sí

DIAGNÓSTICO

Los errores y advertencias se imprimen en la salida de error estándar. Las advertencias pueden ser habilitadas o deshabilitadas con la opción -W. Las siguientes advertencias están disponibles:

invalid-cpu-int-type
Advertir sobre tipos de enteros de CPU no válidos.
unknown-section
Advertir sobre secciones desconocidas.
unknown-warning
Advertir sobre banderas de advertencia desconocidas.
unused-bank
Advertir sobre bancos que no se utilizan.

EJEMPLOS

Enlaza el archivo objeto main.o y crea una ROM llamada rom.gb:

rgblink -o rom.gb main.o

Crea un archivo mapa y un archivo de símbolos además de la ROM:

rgblink -m main.map -n main.sym -o rom.gb main.o

Utiliza un script enlazador para colocar secciones específicas en bancos específicos:

rgblink -l gblink.link -o rom.gb main.o

rgblink(8) — rgbds documentation

NAME

rgblink — Game Boy ROM linker

SYNOPSIS

rgblink [-h] [-f] [-d] [-n] [-p pad] [-m mapfile] [-o outfile] [-w] [-t] [-V] [-v] [infile ...]

DESCRIPTION

The rgblink command links together one or more rgbasm-generated object files (.o) into a single Game Boy ROM image, or library file. It handles the Game Boy's memory map, including setting up sections, managing bank switching, and calculating checksums.

The following options are available:

-h
Print a help message and exit.
-f
Do not pad the output file to the next bank boundary (16 MiB). This is mostly useful for debugging or for creating files that will be combined later.
-d
Include debugging information in the output file. This is typically used for making Game Boy cartridges that can be debugged with an emulator that supports it.
-n
Do not include a symbol table in the output file. This is mostly useful for creating Game Boy cartridges that need to be as small as possible.
-p pad
Set the value used to pad unused sections of the output file. The default value is 0x00.
-m mapfile
Write a map file to mapfile. This file contains a detailed breakdown of the sections in the output file.
-o outfile
Write the output to outfile. If this option is not specified, the output will be written to standard output.
-w
Enable warnings. Warnings are diagnostic messages that indicate possibly erroneous behavior that does not necessarily compromise the linking process. This is equivalent to -Wall.
-t
Print the output file's section table to standard output.
-V
Print version information and exit.
-v
Increase verbosity. This option can be specified multiple times to increase the verbosity level.

The rgblink command can also take a list of object files as arguments. These files will be linked together in the order they are specified. The output file will contain the combined code and data from all of the input files.

Scrambling

By default, rgblink will scramble sections across banks to make it harder to reverse-engineer the ROM. This can be controlled with the following options:

romx=size

wramx=size

sram=size

Each of these options takes a size argument, which specifies the number of banks to scramble the corresponding sections across. A size of 0 disables scrambling for that region.

For example, ‘romx=64,wramx=4’ will scramble ROMX sections among ROM banks 1 to 64, WRAMX sections among RAM banks 1 to 4, and will not scramble SRAM sections.

Later region specs override earlier ones; for example, ‘romx=42, Romx=0’ disables scrambling for romx.

wramx scrambling is silently ignored if -w is passed (including if implied by -d), as WRAMX sections will be treated as WRAM0.

Scrambling Table
Section Max Size Scrambling
romx 255 Yes
sram 255 No
wramx 7 Yes

A size of 0 disables scrambling for that region.

For example, ‘romx=64,wramx=4’ will scramble ROMX sections among ROM banks 1 to 64, WRAMX sections among RAM banks 1 to 4, and will not scramble SRAM sections.

Later region specs override earlier ones; for example, ‘romx=42, Romx=0’ disables scrambling for romx.

wramx scrambling is silently ignored if -w is passed (including if implied by -d), as WRAMX sections will be treated as WRAM0.

DIAGNOSTICS

Warnings are diagnostic messages that indicate possibly erroneous behavior that does not necessarily compromise the linking process. The following options alter the way warnings are processed.

-Werror
Make all warnings into errors. This can be negated as -Wno-error to prevent turning all warnings into errors.
-Werror=
Make the specified warning or meta warning into an error. A warning's name is appended (example: -Werror=assert), and this warning is implicitly enabled and turned into an error. This can be negated as -Wno-error= to prevent turning a specified warning into an error, even if -Werror is in effect.

The following warnings are “meta” warnings, that enable a collection of other warnings. If a specific warning is toggled via a meta flag and a specific one, the more specific one takes priority. The position on the command-line acts as a tie breaker, the last one taking effect.

-Wall
This enables warnings that are likely to indicate an error or undesired behavior, and that can easily be fixed.
-Weverything
Enables literally every warning.

The following warnings are actual warning flags; with each description, the corresponding warning flag is included. Note that each of these flag also has a negation (for example, -Wobsolete enables the warning that -Wno-obsolete disables; and -Wall enables every warning that -Wno-all disables). Only the non-default flag is listed here. Ignoring the “no-” prefix, entries are listed alphabetically.

-Wno-assert
Warn when WARN-type assertions fail. (See “Aborting the assembly process” in rgbasm(5) for ASSERT).
-Wdiv
Warn when dividing the smallest negative integer (-2**31) by -1, which yields itself due to integer overflow. This warning is enabled by -Wall.
-Wno-obsolete
Warn when obsolete features are encountered, which have been deprecated and may later be removed.
-Wshift
Warn when shifting right a negative value. Use a division by 2**N instead. This warning is enabled by -Wall.
-Wshift-amount
Warn when a shift's operand is negative or greater than 32. This warning is enabled by -Wall.
-Wno-truncation
Warn when an implicit truncation (for example, db to an 8-bit value) loses some bits. This occurs when an N-bit value is 2**N or greater, or less than -2**N.

EXAMPLES

All you need for a basic ROM is an object file, which can be made into a ROM image like so:

$ rgblink -o bar.gb foo.o

The resulting bar.gb will not have correct checksums (unless you put them in the assembly source). You should use rgbfix(1) to fix these so that the program will actually run in a Game Boy:

$ rgbfix -v bar.gb

Here is a more complete example:

$ rgblink -o bin/game.gb -n bin/game.sym -p 0xFF obj/title.o obj/engine.o
