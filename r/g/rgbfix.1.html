rgbfix(1)

RGBFIX(1) Manual de Comandos Generales RGBFIX(1)

NOMBRE

rgbfix — Utilidad de cabecera y corrector de suma de verificación para Game Boy

SINOPSIS

rgbfix [-hjOsVvw] [-C | -c] [-f espec_correccion] [-i id_juego] [-k cadena_licenciatario] [-L archivo_logo] [-l id_licenciatario] [-m tipo_mbc] [-n version_rom] [-o archivo_salida] [-p valor_relleno] [-r tam_ram] [-t cadena_titulo] [-W advertencia] [archivo ...]

DESCRIPCIÓN

rgbfix es un programa que modifica las cabeceras de las imágenes ROM de Game Boy, típicamente generadas por rgblink(1), aunque funcionará con cualquier ROM de Game Boy. También realiza otras operaciones de corrección, como el relleno. rgbfix solo modifica los campos para los que tiene valores especificados. Se recomienda a los desarrolladores que llenen esos campos con bytes 0x00 en su código fuente antes de ejecutar rgbfix, y que ya hayan poblado aquellos campos que no especifican con rgbfix.

El archivo_asm de entrada puede ser una ruta a un archivo o - para leer desde la entrada estándar.

Tenga en cuenta que las opciones pueden abreviarse siempre que la abreviatura no sea ambigua: --color-o es --color-only, pero --color es inválido porque también podría ser --color-compatible. Las opciones posteriores en la línea de comandos anulan las establecidas anteriormente. Las opciones aceptadas son las siguientes:

-C, --color-only
Establece el indicador de solo Game Boy Color (0x143) a 0xC0. Esto anula -c si se estableció previamente.
-c, --color-compatible
Establece el indicador de compatibilidad con Game Boy Color: (0x143) a 0x80. Esto anula -c si se estableció previamente.
-f espec_correccion, --fix-spec espec_correccion
Corrige ciertos valores de cabecera que Game Boy comprueba para su corrección. Alternativamente, destruye intencionadamente estos valores escribiendo su inverso binario. espec_correccion es una cadena que contiene cualquier combinación de los siguientes caracteres:
l
Corrige el logo de Nintendo (0x104–0x133).
L
Destruye el logo de Nintendo.
h
Corrige la suma de verificación de la cabecera (0x14D).
H
Destruye la suma de verificación de la cabecera.
g
Corrige la suma de verificación global (0x14E–0x14F).
G
Destruye la suma de verificación global.
-h, --help
Imprime el texto de ayuda del programa y sale.
-i id_juego, --game-id id_juego
Establece la cadena del ID del juego (0x13F–0x142) a una cadena dada. Si es más larga que 4 caracteres, será truncada.
-j, --non-japanese
Establece el indicador de región no japonesa (0x14A) a 0x01.
-k cadena_licenciatario, --new-licensee cadena_licenciatario
Establece la cadena del nuevo licenciatario (0x144–0x145) a una cadena dada. Si es más larga que 2 caracteres, será truncada.
-L archivo_logo, --logo archivo_logo
Especifica un archivo de logo a utilizar en lugar del logo oficial de Nintendo. El archivo debe ser de 48 bytes de datos de tile 1bpp; la imagen fuente debe tener 48 píxeles de ancho y 8 píxeles de alto.
-l id_licenciatario, --old-licensee id_licenciatario
Establece el código del antiguo licenciatario (0x14B) a un valor dado de 0 a 0xFF. Este valor está obsoleto y debe establecerse a 0x33 en todo software nuevo.
-m tipo_mbc, --mbc-type tipo_mbc
Establece el tipo de MBC (0x147) a un valor dado de 0 a 0xFF.

Este valor también puede ser un nombre de MBC. La lista de nombres aceptados se puede obtener pasando 'help' o 'list' como argumento. Se permite cualquier cantidad de espacios en blanco (espacios y tabulaciones) alrededor de los signos más, y el orden de los "componentes" es libre, siempre que el nombre del MBC sea el primero. Existen consideraciones especiales para el mapeador TPP1; consulte la sección TPP1 más abajo.

-n version_rom, --rom-version version_rom
Establece la versión de la ROM (0x14C) a un valor dado de 0 a 0xFF.
-O, --overwrite
Alias de -Wno-overwrite.
-o archivo_salida, --output archivo_salida
Escribe la imagen ROM modificada en el archivo dado, o '-' para escribir en la salida estándar. Si no se especifica, los archivos de entrada se modifican in situ, o se escriben en la salida estándar si se leen desde la entrada estándar.
-p valor_relleno, --pad-value valor_relleno
Rellena la imagen ROM a un tamaño válido con un valor de relleno dado de 0 a 255 (0xFF). rgbfix elegirá automáticamente un tamaño de 32 KiB, 64 KiB, 128 KiB, ..., 8192 KiB. El byte del tamaño del cartucho (0x148) se modificará para reflejar este nuevo tamaño. El valor de relleno recomendado es 0xFF, para acelerar la escritura de la ROM en chips flash y para evitar "deslizamientos de nop" en la VRAM.
-r tam_ram, --ram-size tam_ram
Establece el tamaño de la RAM (0x149) a un valor dado de 0 a 0xFF.
-s, --sgb-compatible
Establece el indicador SGB (0x146) a 0x03. Este indicador será ignorado por el SGB a menos que el código del antiguo licenciatario (--l) sea 0x33.
-t titulo, --title titulo
Establece el título del juego (0x137–0x13A) a una cadena dada. Si es más largo que 16 caracteres, será truncado.
-V, --version
Imprime la información de la versión y sale.
-v, --verbose
Activa la salida detallada.
-W advertencia, --warning advertencia
Emite una advertencia especificada. Las advertencias válidas son:
no-overwrite
Suprime la advertencia de que se está sobrescribiendo un archivo de entrada.

EJEMPLOS

Para corregir la suma de verificación de la cabecera y el logo de Nintendo en el archivo `myrom.gb` y guardar el resultado en `myrom_fixed.gb`:

    $ rgbfix -f h myrom.gb -o myrom_fixed.gb

Para establecer el título a "HELLO WORLD", el ID de juego a "GB01", y la versión de ROM a 1, y luego rellenar con 0xFF:

    $ rgbfix -t "HELLO WORLD" -i GB01 -n 1 -p 0xFF myrom.gb

Para establecer la compatibilidad con Game Boy Color y la región no japonesa:

    $ rgbfix -c -j myrom.gb

TPP1

El mapeador TPP1 (o Agobj) es un mapeador de cartuchos de terceros que se puede identificar con el código 0x34.

El mapeador TPP1 utiliza el campo de licenciatario antiguo (0x14B) para almacenar un byte de control de mapeador. El bit 6 (0x40) se utiliza para controlar la memoria protegida de escritura, mientras que el bit 7 (0x80) se utiliza para indicar que el mapeador está en modo de 128 MB. Dado que la mayoría de las utilidades esperan que el campo de licenciatario antiguo sea 0x33, a menudo es necesario establecer explícitamente el código de licenciatario antiguo a 0x33 y especificar el comportamiento deseado del mapeador TPP1 a través de otros campos, o de lo contrario, se puede perder el acceso a la memoria. El código de mapeador 0x34 por sí solo no siempre es suficiente.

Normalmente, se utiliza el siguiente campo de cabecera para indicar el tamaño de la ROM en el mapeador TPP1:

• 0x148: Tamaño de la ROM

El formato de este campo es el siguiente:

Bit 7:
Control de protección contra escritura (0 = Desactivado, 1 = Activado).
Bits 0-6:
Tamaño de la ROM en MB (por ejemplo, 0x01 para 1 MB, 0x02 para 2 MB, etc.).

Por ejemplo, una ROM de 4 MB con protección contra escritura activada se representaría como 0x44 (0x40 | 0x04).

Para más detalles, consulta la documentación del mapeador TPP1.

NAME

rgbfix ― fix Game Boy ROM headers

SYNOPSIS

rgbfix [-vjdcC] [-p value] [-t title] [-l value] [-k value] [-m value] [-r value] [-s value] [-f flags] [-W warning]… file

DESCRIPTION

rgbfix is used to fix the header of a Game Boy ROM file. The Game Boy cartridge header is located at offset 0x0100-0x014f in the ROM. This header contains information about the ROM, such as its title, checksums, and configuration flags. Some information in the header is required for the ROM to run correctly on original hardware (e.g. the header checksum). Other information is optional and may be used by emulators or ROM managers.

rgbfix can perform the following actions:

  • Calculate and fill in the header checksum (0x0100–0x014e). The checksum is calculated as a two's complement sum of all bytes in the range, and stored at 0x014d.
  • Calculate and fill in the Nintendo logo checksum (0x0104–0x0133). This checksum must be 0x00 to pass hardware checks.
  • Fix the global checksum (0x014e). This checksum is used by the Game Boy to verify the integrity of the ROM. It is calculated as a one's complement sum of all bytes in the ROM. The Game Boy stores the value it calculates at 0x014e, and compares it to the value found there.
  • Set the title string (0x134–0x143) to a given string. If the title is longer than the maximum length, it will be truncated. The max length is 11 characters if the game ID (-i) is specified, 15 characters if the CGB flag (-c or -C) is specified but the game ID is not, and 16 characters otherwise.
  • Set the GamePak GB flag (0x143) and the GamePak CGB flag (0x146). These flags indicate whether the ROM is compatible with the Game Boy Color.
  • Set the SGB flag (0x146). This flag indicates whether the ROM is intended for use with the Super Game Boy.
  • Set the ROM type (0x147). This specifies the Memory Bank Controller (MBC) used by the ROM.
  • Set the ROM size (0x148). This indicates the total size of the ROM.
  • Set the RAM size (0x149). This indicates the amount of RAM available on the cartridge.
  • Pad the ROM to a specified size.

The following options are available:

-c, -C, --cartridge-mode
Set the GamePak GB flag to the value of value. If -c is used without a value, it defaults to 0x01. If -C is used, it defaults to 0x80.
-f, --flags flags
Set the ROM type (0x147), ROM size (0x148), and RAM size (0x149) to the values specified by flags. The format of flags is: MBC[+RAM][,SIZE] where MBC is one of n (none), r (MBC1), u (MBC2), m (MBC5), b (HuC3), t (TPP1), l (assumes SGB flag). RAM is the RAM size in KiB (e.g., 8, 64), and SIZE is the ROM size in KiB (e.g., 1024, 2048). If RAM or SIZE are not specified, they default to the minimum values that can hold the ROM. If MBC is l, the SGB flag (0x146) is enabled, and the ROM type is set to MBC1. Any combination of the below flags can be supplied.
-i, --game-id value
Set the Game ID to the specified value. The Game ID is a 4-byte value stored at 0x13f. This option is mainly used by emulators and other tools.
-j, --jump-table
Set the value at 0x14a to 0x00. This is often used to indicate that the ROM is a Japanese region ROM.
-k, --nintendo-checksum value
Set the Nintendo logo checksum to the specified value. If not specified, this defaults to 0x00, which is required for hardware compatibility. Setting this option to a non-zero value will cause the Nintendo logo checksum to fail on original hardware.
-l, --licensee-code value
Set the licensee code to the specified value. The default value is 0x00 (Lib. Code).
-m, --manufacturer-code value
Set the manufacturer code to the specified value. The default value is 0x00. This option is deprecated and should not be used.
-p, --padding value
Pad the ROM to the specified size, in bytes. The padding byte is specified by value. The default padding byte is 0x00. If the specified size is smaller than the current ROM size, the ROM will not be truncated.
-r, --rom-size value
Set the ROM size to the specified value. The value is specified as a number of 32 Kibibyte banks. The default ROM size is the smallest power of 2 banks that fits the ROM.
-s, --sgb
Enable the Super Game Boy flag. This sets the SGB flag at 0x146 to 0x03 and the ROM type at 0x147 to 0x01 (MBC1).
-t, title
Set the title string (0x134–0x143) to a given string. If the title is longer than the maximum length, it will be truncated. The max length is 11 characters if the game ID (-i) is specified, 15 characters if the CGB flag (-c or -C) is specified but the game ID is not, and 16 characters otherwise.
-V, --version
Print the version of the program and exit.
-v, --validate
Equivalent to -f lhg.
-W warning, --warning warning
Set warning flag warning. A warning message will be printed if warning is an unknown warning flag. See the DIAGNOSTICS section for a list of warnings.
-w
Disable all warning output, even when turned into errors.

DIAGNOSTICS

Warnings are diagnostic messages that indicate possibly erroneous behavior that does not necessarily compromise the header-fixing process. The following options alter the way warnings are processed.

-Werror
Make all warnings into errors. This can be negated as -Wno-error to prevent turning all warnings into errors.
-Werror=
Make the specified warning or meta warning into an error. A warning's name is appended (example: -Werror=overwrite), and this warning is implicitly enabled and turned into an error. This can be negated as -Wno-error= to prevent turning a specified warning into an error, even if -Werror is in effect.

The following warnings are “meta” warnings, that enable a collection of other warnings. If a specific warning is toggled via a meta flag and a specific one, the more specific one takes priority. The position on the command-line acts as a tie breaker, the last one taking effect.

-Wall
This enables warnings that are likely to indicate an error or undesired behavior, and that can easily be fixed.
-Weverything
Enables literally every warning.

The following warnings are actual warning flags; with each description, the corresponding warning flag is included. Note that each of these flag also has a negation (for example, -Wtruncation enables the warning that -Wno-truncation disables; and -Wall enables every warning that -Wno-all disables). Only the non-default flag is listed here. Ignoring the “no-” prefix, entries are listed alphabetically.

-Wno-mbc
Warn when there are inconsistencies with or caveats about the specified MBC type.
-Wno-overwrite
Warn when overwriting different non-zero bytes in the header.
-Wno-sgb
Warn when the SGB flag (-s) conflicts with the old licensee code (-l).
-Wno-truncation
Warn when truncating values to fit the available space.

EXAMPLES

Most values in the ROM header do not matter to the actual console, and most are seldom useful anyway. The bare minimum requirements for a workable program are the header checksum, the Nintendo logo, and (if needed) the CGB/SGB flags. It is a good idea to pad the image to a valid size as well (“valid” meaning a power of 2, times 32 KiB).

The following will make a plain, non-color Game Boy game without checking for a valid size:

$ rgbfix -v foo.gb

The following will make a SGB-enabled, color-enabled game with a title of “foobar”, and pad it to a valid size. (The Game Boy itself does not use the title, but some emulators or ROM managers do.)

$ rgbfix -vcs -l 0x33 -p 255 -t foobar baz.gb

The following will duplicate the header of the game “Survival Kids”, sans global checksum:

$ rgbfix -cjsv -k A4 -l 0x33 -m 0x1B -p 0xFF -r 3 -t SURVIVALKIDAVKE SurvivalKids.gbc

TPP1

TPP1 is a homebrew mapper designed as a functional superset of the common traditional MBCs, allowing larger ROM and RAM sizes combined with other hardware features. Its specification, as well as more resources, can be found online at https://github.com/aaaaaa123456789/tpp1.

MBC name

The MBC name for TPP1 is more complex than standard mappers. It must be followed with the revision number, of the form ‘major.minor’, where both ‘major’ and ‘minor’ are decimal, 8-bit integers. There may be any amount of spaces or underscores between ‘TPP1’ and the revision number. rgbfix only supports 1.x revisions, and will reject everything else.

Like other mappers, the name may be followed with a list of optional, ‘+’-separated features; however, ‘RAM’ should not be specified, as the TPP1 mapper implicitly requests RAM if a non-zero RAM size is specified. Therefore, rgbfix will ignore the ‘RAM’ feature on a TPP1 mapper.

Special considerations

TPP1 overwrites the byte at 0x14A, usually indicating the region destination (see -j), with one of its three identification bytes. Therefore, rgbfix will warn about and ignore -j if used in combination with TPP1.
