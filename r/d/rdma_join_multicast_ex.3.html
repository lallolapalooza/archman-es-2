RDMA_JOIN_MULTICAST_EX(3) Manual del programador de Librdmacm RDMA_JOIN_MULTICAST_EX(3)

NOMBRE

rdma_join_multicast_ex - Se une a un grupo multicast con opciones extendidas.

SINOPSIS

#include <rdma/rdma_cma.h>

int rdma_join_multicast_ex (struct rdma_cm_id *id, struct rdma_cm_join_mc_attr_ex *mc_join_attr, void *context);

ARGUMENTOS

id
Identificador de comunicación asociado a la solicitud.
mc_join_attr
Es una estructura rdma_cm_join_mc_attr_ex, tal como se define en <rdma/rdma_cma.h>.
context
Contexto definido por el usuario asociado a la solicitud de unión.

DESCRIPCIÓN

Se une a un grupo multicast (MCG) con opciones extendidas. Actualmente soporta la unión MC con una bandera de unión especificada.

struct rdma_cm_join_mc_attr_ex {
uint32_t                comp_mask;      /* OR a nivel de bits entre el enum "rdma_cm_join_mc_attr_mask" */
uint32_t                join_flags;     /* Usa una única bandera del enum "rdma_cm_mc_join_flags" */
struct sockaddr         *addr;          /* Dirección multicast que identifica el grupo al que unirse */
};

Las banderas de unión admitidas son:

RDMA_MC_JOIN_FLAG_FULLMEMBER - Crea un grupo multicast, envía mensajes multicast al MCG, recibe mensajes multicast del MCG.

RDMA_MC_JOIN_FLAG_SENDONLY_FULLMEMBER - Crea un grupo multicast, envía mensajes multicast al MCG, no recibe mensajes multicast del MCG (solo envío).

Iniciar una unión MC como "Miembro Completo Solo Envío" en InfiniBand requiere soporte de SM, de lo contrario, la unión fallará.

Iniciar una unión MC como "Miembro Completo Solo Envío" en RoCEv2/ETH no enviará ningún mensaje IGMP a diferencia de una unión MC de Miembro Completo. Cuando se utiliza "Miembro Completo Solo Envío", el QP no se adjuntará al MCG.

VALOR DE RETORNO

Devuelve 0 en caso de éxito, o -1 en caso de error. Si ocurre un error, errno se establecerá para indicar el motivo de la falla.

NOTAS

Antes de unirse a un grupo multicast, el `rdma_cm_id` debe estar enlazado a un dispositivo RDMA llamando a `rdma_bind_addr` o `rdma_resolve_addr`. El uso de `rdma_resolve_addr` requiere que las tablas de enrutamiento locales resuelvan la dirección multicast a un dispositivo RDMA, a menos que se proporcione una dirección de origen específica. El usuario debe llamar a `rdma_leave_multicast` para abandonar el grupo multicast y liberar cualquier recurso multicast. Después de que la operación de unión se complete, si un QP está asociado con el `rdma_cm_id`, se adjunta automáticamente al grupo multicast cuando el evento multicast es recuperado por el usuario. De lo contrario, el usuario es responsable de llamar a `ibv_attach_mcast` para enlazar el QP al grupo multicast. El contexto de unión se devuelve al usuario a través del campo `private_data` en el evento `rdma_cm_event`.
