RDMA_CREATE_QP(3) Manual del programador de Librdmacm RDMA_CREATE_QP(3)

NOMBRE

rdma_create_qp - Asigna una QP.

SINOPSIS

#include <rdma/rdma_cma.h>

int rdma_create_qp (struct rdma_cm_id *id, struct ibv_pd *pd, struct ibv_qp_init_attr *qp_init_attr);

ARGUMENTOS

id
Identificador RDMA.
pd
Dominio de protección opcional para la QP.
qp_init_attr
Atributos de inicialización de la QP.

DESCRIPCIÓN

Asigna una QP asociada con el rdma_cm_id especificado y la transiciona para enviar y recibir.

VALOR DE RETORNO

Devuelve 0 si tiene éxito, o -1 si ocurre un error. Si ocurre un error, errno se establecerá para indicar el motivo del fallo.

NOTAS

El rdma_cm_id debe estar enlazado a un dispositivo RDMA local antes de llamar a esta función, y el dominio de protección debe ser para el mismo dispositivo. Las QPs asignadas a un rdma_cm_id son transicionadas automáticamente por librdmacm a través de sus estados. Después de ser asignada, la QP estará lista para manejar la publicación de recepciones. Si la QP no está conectada, estará lista para publicar envíos.

Si no se proporciona un dominio de protección - el parámetro pd es NULL - entonces el rdma_cm_id se creará utilizando un dominio de protección predeterminado. Se asigna un dominio de protección predeterminado por dispositivo RDMA.

Los atributos iniciales de la QP se especifican mediante el parámetro qp_init_attr. Los campos send_cq y recv_cq en ibv_qp_init_attr son opcionales. Si no se especifica una cola de finalización de envío o recepción, entonces librdmacm asignará una CQ para la QP, junto con canales de finalización correspondientes. Los canales de finalización y los datos de CQ creados por librdmacm se exponen al usuario a través de la estructura rdma_cm_id.

Las capacidades y propiedades reales de la QP creada se devolverán al usuario a través del parámetro qp_init_attr. Un rdma_cm_id solo puede estar asociado con una única QP.
