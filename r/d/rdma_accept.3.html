RDMA_ACCEPT(3) Manual del Programador de Librdmacm RDMA_ACCEPT(3)

NOMBRE

rdma_accept - Se llama para aceptar una solicitud de conexión.

SINOPSIS

#include <rdma/rdma_cma.h>

int rdma_accept (struct rdma_cm_id *id, struct rdma_conn_param *conn_param);

ARGUMENTOS

id
Identificador de conexión asociado con la solicitud.
conn_param
Información necesaria para establecer la conexión. Consulte PROPIEDADES DE LA CONEXIÓN a continuación para obtener detalles.

DESCRIPCIÓN

Se llama desde el lado de escucha para aceptar una solicitud de conexión o de búsqueda de servicio de datagramas.

VALOR DE RETORNO

Devuelve 0 si tiene éxito, o -1 si ocurre un error. Si ocurre un error, errno se establecerá para indicar el motivo de la falla.

NOTAS

A diferencia de la rutina de aceptación de sockets, rdma_accept no se llama en un rdma_cm_id de escucha. En su lugar, después de llamar a rdma_listen, el usuario espera a que ocurra un evento RDMA_CM_EVENT_CONNECT_REQUEST. Los eventos de solicitud de conexión proporcionan al usuario un rdma_cm_id recién creado, similar a un nuevo socket, pero el rdma_cm_id está enlazado a un dispositivo RDMA específico. rdma_accept se llama en el nuevo rdma_cm_id.

PROPIEDADES DE LA CONEXIÓN

Las siguientes propiedades se utilizan para configurar la comunicación y se especifican mediante el parámetro conn_param al aceptar una solicitud de conexión o datagrama. Los usuarios deben utilizar los valores de rdma_conn_param reportados en el evento de solicitud de conexión para determinar los valores apropiados para estos campos al aceptar. Los usuarios pueden referenciar los valores de la estructura rdma_conn_param en el evento de conexión directamente, o pueden referenciar su propia estructura. Si se referencia la estructura rdma_conn_param de un evento, el evento no debe confirmarse hasta después de que esta llamada regrese.

Si el parámetro conn_param es NULL, se utilizan los valores reportados en el evento de solicitud de conexión, ajustados a la baja según las restricciones del hardware local.

datos_privados
Hace referencia a un búfer de datos controlado por el usuario. El contenido del búfer se copia y se pasa de forma transparente al lado remoto como parte de la solicitud de comunicación. Puede ser NULL si no se requieren datos_privados.
longitud_datos_privados
Especifica el tamaño del búfer de datos controlado por el usuario. Tenga en cuenta que la cantidad real de datos transferidos al lado remoto depende del transporte y puede ser mayor que la solicitada.
recursos_del_receptor
El número máximo de operaciones RDMA de lectura y atómicas pendientes que el lado local aceptará del lado remoto. Se aplica solo a RDMA_PS_TCP. Este valor debe ser menor o igual que el atributo max_qp_rd_atom del dispositivo RDMA local, pero preferiblemente mayor o igual que el valor de recursos_del_receptor reportado en el evento de solicitud de conexión.
profundidad_del_iniciador
El número máximo de operaciones RDMA de lectura y atómicas pendientes que el lado local tendrá hacia el lado remoto. Se aplica solo a RDMA_PS_TCP. Este valor debe ser menor o igual que el atributo max_qp_init_rd_atom del dispositivo RDMA local y el valor de profundidad_del_iniciador reportado en el evento de solicitud de conexión.
control_de_flujo
Especifica si el control de flujo por hardware está disponible. Este valor se intercambia con el par remoto y no se utiliza para configurar el QP. Se aplica solo a RDMA_PS_TCP.
contador_de_reintentos
Este valor se ignora.
contador_reintentos_rnr
El número máximo de veces que se debe reintentar una operación de envío desde el par remoto en una conexión después de recibir un error de receptor no listo (RNR). Los errores RNR se generan cuando llega una solicitud de envío antes de que se haya publicado un búfer para recibir los datos entrantes. Se aplica solo a RDMA_PS_TCP.
srq
Especifica si el QP asociado con la conexión está utilizando una cola de recepción compartida. La biblioteca ignora este campo si se ha creado un QP en el rdma_cm_id. Se aplica solo a RDMA_PS_TCP.
numero_qp
Especifica el número de QP asociado con la conexión. La biblioteca ignora este campo si se ha creado un QP en el rdma_cm_id.

ESPECÍFICO DE INFINIBAND

Además de las propiedades de conexión definidas anteriormente, los QP de InfiniBand se configuran con un temporizador mínimo de NAK RNR y valores de tiempo de espera de ACK local. El valor mínimo del temporizador NAK RNR se establece en 0, para un retraso de 655 ms. El tiempo de espera de ACK local se calcula en función de la vida útil del paquete y el retraso de ACK local de la HCA. La vida útil del paquete está determinada por el Administrador de Subred InfiniBand y es parte de la información de la ruta (registro de ruta) obtenida por el lado activo de la conexión. El retraso de ACK de la HCA es una propiedad de la HCA utilizada localmente.

El contador de reintentos RNR es un valor de 3 bits.

La longitud de los datos privados proporcionados por el usuario se limita a 196 bytes para RDMA_PS_TCP, o 136 bytes para RDMA_PS_UDP.
