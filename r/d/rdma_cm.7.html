RDMA_CM(7) Manual del programador de Librdmacm RDMA_CM(7)

NOMBRE

rdma_cm - Gestor de comunicaciones RDMA.

SINOPSIS

#include <rdma/rdma_cma.h>

DESCRIPCIÓN

Se utiliza para establecer la comunicación a través de transportes RDMA.

NOTAS

El RDMA CM es un gestor de comunicaciones utilizado para configurar transferencias de datos fiables, conectadas y de datagramas no fiables. Proporciona una interfaz neutral al transporte RDMA para establecer conexiones. Los conceptos de la API se basan en sockets, pero adaptados a la semántica basada en pares de colas (QP): la comunicación debe realizarse a través de un dispositivo RDMA específico y las transferencias de datos se basan en mensajes.

El RDMA CM puede controlar tanto el QP como la gestión de la comunicación (establecimiento/cierre de conexión) de una API RDMA, o solo la parte de gestión de la comunicación. Funciona en conjunto con la API de verbos definida por la biblioteca libibverbs. La biblioteca libibverbs proporciona las interfaces subyacentes necesarias para enviar y recibir datos.

El RDMA CM puede operar de forma asíncrona o síncrona. El modo de operación lo controla el usuario mediante el uso del parámetro de canal de eventos rdma_cm en llamadas específicas. Si se proporciona un canal de eventos, un identificador rdma_cm informará los datos de su evento (resultados de la conexión, por ejemplo) en ese canal. Si no se proporciona un canal, todas las operaciones de rdma_cm para el identificador rdma_cm seleccionado se bloquearán hasta que se completen.

El RDMA CM ofrece una opción a diferentes proveedores de libibverbs para anunciar y utilizar diversas opciones de configuración de QP específicas del proveedor. Esta funcionalidad se llama ECE (establecimiento de conexión mejorado).

VERBOS RDMA

El rdma_cm admite toda la gama de verbos disponibles a través de la biblioteca e interfaces de libibverbs. Sin embargo, también proporciona funciones de envoltura para algunas de las funcionalidades de verbos más utilizadas. El conjunto completo de llamadas de verbos abstraídos son:

rdma_reg_msgs - registra una matriz de búferes para enviar y recibir

rdma_reg_read - registra un búfer para operaciones de lectura RDMA

rdma_reg_write - registra un búfer para operaciones de escritura RDMA

rdma_dereg_mr - anula el registro de una región de memoria

rdma_post_recv - publica un búfer para recibir un mensaje

rdma_post_send - publica un búfer para enviar un mensaje

rdma_post_read - publica una operación RDMA para leer datos en un búfer

rdma_post_write - publica una operación RDMA para escribir datos desde un búfer

rdma_post_recvv - publica un vector de búferes para recibir un mensaje

rdma_post_sendv - publica un vector de búferes para enviar un mensaje

rdma_post_readv - publica un vector de búferes para recibir una lectura RDMA

rdma_post_writev - publica un vector de búferes para enviar una escritura RDMA

rdma_post_ud_send - publica un búfer para enviar un mensaje en un QP UD

rdma_get_send_comp - obtiene el estado de finalización para una operación de envío o RDMA

rdma_get_recv_comp - obtiene información sobre una recepción completada

Se utiliza un proceso casi idéntico para configurar la comunicación de datagramas no fiables (UD) entre nodos. Sin embargo, no se forma una conexión real entre QPs, por lo que no es necesaria la desconexión.

NOTAS

La biblioteca librdmacm puede ser usada para gestionar conexiones RDMA de manera simplificada. Maneja la configuración de la dirección de destino y la resolución de rutas, la conexión y desconexión de las colas de pares (QP) y la comunicación de eventos.

Para usar librdmacm, el usuario debe primero crear un canal de eventos (rdma_create_event_channel) y luego un identificador (rdma_create_id).

El proceso de conexión típico para un cliente:

  1. Crear un canal de eventos: rdma_create_event_channel.
  2. Crear un rdma_cm_id: rdma_create_id. Este ID representa el punto de conexión del cliente.
  3. Resolver la dirección de destino: rdma_resolve_addr. Esto se hace para encontrar la dirección de destino RDMA.
  4. Resolver la ruta: rdma_resolve_route. Esto se hace para encontrar la ruta RDMA hacia el destino.
  5. Conectar: rdma_connect. Esto envía una solicitud de conexión al servidor.
  6. Esperar el evento RDMA_CM_EVENT_ADDR_RESOLVED.
  7. Esperar el evento RDMA_CM_EVENT_ROUTE_RESOLVED.
  8. Esperar el evento RDMA_CM_EVENT_CONNECT_REQUEST (en el servidor) o RDMA_CM_EVENT_ESTABLISHED (en el cliente).
  9. (Opcional) Establecer las opciones de ECE: rdma_set_local_ece.
  10. (Opcional) Obtener las opciones de ECE del remoto: rdma_get_remote_ece.
  11. Si la conexión es establecida, usar el QP asociado con el rdma_cm_id para transferir datos.
  12. Desconectar: rdma_disconnect.
  13. Destruir el QP: rdma_destroy_qp.
  14. Destruir el ID: rdma_destroy_id.
  15. Destruir el canal de eventos: rdma_destroy_event_channel.

El proceso de conexión típico para un servidor:

  1. Crear un canal de eventos: rdma_create_event_channel.
  2. Crear un rdma_cm_id: rdma_create_id. Este ID representa el punto de escucha del servidor.
  3. Asociar el ID con una dirección local: rdma_bind_addr.
  4. Poner el ID en modo de escucha: rdma_listen.
  5. Esperar el evento RDMA_CM_EVENT_CONNECT_REQUEST. Este evento se recibe cuando un cliente intenta conectarse.
  6. Para aceptar la conexión, crear un nuevo rdma_cm_id para el lado del servidor usando rdma_create_id y asociarlo con el rdma_cm_id de escucha usando rdma_migrate_id.
  7. Aceptar la conexión: rdma_accept.
  8. (Opcional) Establecer las opciones de ECE: rdma_set_local_ece.
  9. (Opcional) Obtener las opciones de ECE del remoto: rdma_get_remote_ece.
  10. Si la conexión es establecida, usar el QP asociado con el nuevo rdma_cm_id para transferir datos.
  11. Desconectar: rdma_disconnect.
  12. Destruir el QP: rdma_destroy_qp.
  13. Destruir el ID: rdma_destroy_id.
  14. Destruir el canal de eventos: rdma_destroy_event_channel.

Nota: Para el cliente, se puede llamar a rdma_connect en lugar de rdma_create_id, rdma_resolve_addr, rdma_resolve_route y rdma_connect. rdma_connect asume que el ID ya ha sido creado. Cuando se usa el método de conexión simplificado, el ID se crea internamente.

Las siguientes funciones son útiles para gestionar las transferencias sobre la conexión:

rdma_get_cm_event
espera el evento RDMA_CM_EVENT_DISCONNECTED
rdma_ack_cm_event
confirma el evento
rdma_disconnect
cierra la conexión
rdma_destroy_qp
destruye el QP
rdma_destroy_id
libera el rdma_cm_id conectado
rdma_destroy_id
libera el rdma_cm_id de escucha
rdma_destroy_event_channel
libera el canal de eventos
rdma_get_remote_ece
obtiene las opciones ECe enviadas por el cliente
rdma_set_local_ece
establece las opciones ECe deseadas

CODIGOS DE RETORNO

= 0
éxito
= -1
error - ver errno para más detalles

La mayoría de las funciones de librdmacm devuelven 0 para indicar éxito, y un valor de retorno de -1 para indicar fallo. Si una función opera de forma asíncrona, un valor de retorno de 0 significa que la operación se inició correctamente. La operación aún podría completarse con error; los usuarios deben verificar el estado del evento relacionado. Si el valor de retorno es -1, entonces errno contendrá información adicional sobre la razón del fallo.

Versiones anteriores de la biblioteca devolvían -errno y no establecían errno para algunos casos relacionados con los códigos ENOMEM, ENODEV, ENODATA, EINVAL y EADDRNOTAVAIL. Las aplicaciones que desean verificar estos códigos y tener compatibilidad con versiones anteriores de la biblioteca deben establecer manualmente errno al negativo del código de retorno si es < -1.
