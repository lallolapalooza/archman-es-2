NOMBRE

rdesktop - Cliente de Escritorio Remoto

SINOPSIS

rdesktop [opciones] servidor[:puerto]

DESCRIPCIÓN

rdesktop es un cliente para el Protocolo de Escritorio Remoto (RDP), utilizado en una serie de productos de Microsoft. Se sabe que funciona con versiones de servidor de Microsoft Windows que van desde el servidor terminal NT 4 hasta Windows Server 2012 R2.

OPCIONES

-u <nombredeusuario>
Nombre de usuario para la autenticación en el servidor.
-d <dominio>
Dominio para la autenticación.
-s <shell>
Shell de inicio para el usuario - inicia una aplicación específica en lugar de Explorar. Si SeamlessRDP está habilitado, esta es la aplicación que se inicia en modo sin interrupciones.
-c <directorio>
El directorio de trabajo inicial para el usuario. A menudo se utiliza en combinación con -s para configurar un entorno de inicio de sesión fijo.
-p <contraseña>
La contraseña para autenticarse. Tenga en cuenta que esto puede no tener efecto si "Solicitar siempre contraseña" está habilitado en el servidor. ADVERTENCIA: si especifica una contraseña en la línea de comandos, puede ser visible para otros usuarios cuando utilicen herramientas como ps. Use -p - para que rdesktop solicite una contraseña al inicio (desde la entrada estándar).
-n <nombredehost>
Nombre de host del cliente. Normalmente, rdesktop obtiene automáticamente el nombre de host del cliente.
-k <mapateclado>
Disposición del teclado a emular. Esto requiere que se instale un archivo de mapa de teclas correspondiente. Los mapas de teclas estándar proporcionados con rdesktop siguen el esquema de nomenclatura RFC1766: un código de idioma seguido de un código de país si es necesario, por ejemplo, en-us, en-gb, de, fr, sv, etc.

El mapa de teclado predeterminado depende de la configuración regional actual (variables de entorno LC_* y LANG). Si la configuración regional actual es desconocida, el mapa de teclado predeterminado es en-us (un teclado inglés de EE. UU.).

Los mapas de teclado son nombres de archivo, lo que significa que distinguen entre mayúsculas y minúsculas. Todos los mapas de teclado estándar están en minúsculas.

Los mapas de teclado se buscan en relación con los directorios $HOME/.rdesktop/keymaps, KEYMAP_PATH (especificado en tiempo de compilación) y $CWD/keymaps, en este orden. El argumento keyboard-map también puede ser un nombre de archivo absoluto.

El valor especial `none' se puede utilizar en lugar de un mapa de teclado. En este caso, rdesktop adivinará los códigos de escaneo a partir de los códigos de teclas de eventos X11 utilizando un método de mapeo interno. Este método solo admite las teclas alfanuméricas básicas y puede no funcionar correctamente en todas las plataformas, por lo que se desaconseja su uso.

-g <geometría>
Geometría del escritorio (AxA[@DPI][+X[+Y]]). Si la geometría es la palabra especial "workarea", la geometría se obtendrá de la propiedad extendida de sugerencias del administrador de ventanas _NET_WORKAREA, desde la ventana raíz. La geometría también se puede especificar como un porcentaje de la pantalla completa, por ejemplo, "-g 80%", "-g 80%x70%".

Si la geometría especificada depende del tamaño de la pantalla y el tamaño de la pantalla cambia, rdesktop se reconectará automáticamente utilizando el nuevo tamaño de pantalla. Esto requiere que rdesktop se haya compilado con soporte RandR.

El parámetro opcional DPI debe especificarse si la pantalla en la que se muestra rdesktop está demasiado lejos de 96 DPI para que las ventanas sin escalar sean legibles. Windows actualmente acepta valores de 96 a 480.

La colocación de desplazamiento de la ventana es opcional. El punto de inicio es la esquina superior izquierda de la pantalla. El administrador de ventanas puede empujar dentro del área visible si un panel estaría cubierto. El esquema es "-g <valor>+<xoff>+<yoff>, por ejemplo, "-g 30%+200+600".

-i
Usar la contraseña como PIN de tarjeta inteligente. Si se detecta un certificado de usuario válido en el lector de tarjetas inteligentes, la contraseña pasada con el argumento p se utiliza como PIN para la tarjeta inteligente. Esta función también requiere que se utilice la redirección de tarjeta inteligente mediante el argumento r scard.
-f
Habilitar el modo de pantalla completa. Esto anula el administrador de ventanas y hace que la ventana de rdesktop cubra completamente la pantalla actual. El modo de pantalla completa se puede alternar en cualquier momento usando Ctrl-Alt-Enter.
-b
Forzar al servidor a enviar actualizaciones de pantalla como mapas de bits en lugar de utilizar operaciones de dibujo de nivel superior.
-t
Deshabilitar el uso de control remoto. Esto deshabilitará funciones como el intercambio de conexiones sin interrupciones.
-A <seamlessrdpshell>
Habilitar SeamlessRDP especificando la ruta al shell de rdp sin interrupciones. En este modo, rdesktop crea una ventana X11 para cada ventana en el lado del servidor. Este modo requiere el componente del lado del servidor SeamlessRDP, que está disponible en http://www.cendio.com/seamlessrdp/.

Al usar esta opción, normalmente debería especificar un shell de inicio que lance la aplicación deseada a través de SeamlessRDP.

Ejemplo: rdesktop -A 'c:\seamlessrdp\seamlessrdpshell.exe' -s 'notepad' mywts.domain.com

Cualquier llamada subsiguiente a la línea de comandos de ejemplo anterior utilizará la función de intercambio de conexiones sin interrupciones, que inicia otro notepad en la conexión actual al servidor especificado y luego sale.

-V <versióntls>
Establecer la versión de Seguridad a Nivel de Transporte (también conocida como SSL) utilizada. Debe ser uno de los siguientes valores: 1.0, 1.1, 1.2. Por defecto se admiten todas las versiones.
-B
Utilizar el almacenamiento intermedio (BackingStore) del servidor X en lugar del integrado en rdesktop.
-e
Deshabilitar cifrado. Esta opción solo es necesaria (y solo funcionará) si tiene una versión francesa de NT TSE.
-E
Deshabilitar cifrado del cliente al servidor. Esto envía un paquete de inicio de sesión cifrado, pero todo lo posterior está sin cifrar (incluidos los inicios de sesión interactivos).
-m
No enviar eventos de movimiento del ratón. Esto ahorra ancho de banda, aunque algunas aplicaciones de Windows pueden depender de recibir el movimiento del ratón.
-M
Utilizar el cursor X local heredado del administrador de ventanas en lugar del cursor del servidor. Esto es útil principalmente con -m, pero también es útil si el servidor envía cursores de ratón incorrectos.
-C
Usar mapa de color privado. Esto mejorará la precisión del color en una pantalla de 8 bits, pero rdesktop aparecerá en color falso cuando no tenga el foco.
-D
Ocultar las decoraciones del administrador de ventanas, utilizando las sugerencias MWM.
-K
No anular los enlaces de teclado del administrador de ventanas. Por defecto, rdesktop intenta capturar toda la entrada del teclado cuando tiene el foco.
-S <tamañobotón>
Habilitar el modo de aplicación única. Esta opción se puede usar al ejecutar una aplicación única y maximizada (a través de -s). Cuando se presiona el botón de minimizar de la aplicación de Windows, la ventana de rdesktop se minimiza en lugar de la aplicación remota. El botón de maximizar/restaurar está deshabilitado. Para que esto funcione, debe especificar el tamaño de botón correcto, en píxeles. La palabra especial "standard" significa 18 píxeles.
-T <título>
Establece el título de la ventana. El título debe especificarse usando una cadena UTF-8.
-N
Habilitar la sincronización de numlock entre el servidor X y la sesión RDP remota. Esto es útil con aplicaciones que observan el estado de numlock, pero puede causar problemas con algunos servidores X como Xvnc.
-X <idventana>
Incrustar la ventana de rdesktop en otra ventana. Se espera que el id de ventana sea decimal o hexadecimal (precedido por 0x).

NAME

rdesktop - RDP client for Windows NT/2000/XP/2003

SYNOPSIS

rdesktop [options] [-u username][-d domain][-p password][-n hostname] server[:port]

DESCRIPTION

rdesktop is a client for the Remote Desktop Protocol (RDP) which is used by Microsoft Windows NT, Windows 2000, Windows XP, Windows Server 2003, and Windows Vista.

The program allows a user to remotely control another computer running Windows. The user interface of the remote computer is displayed on the local computer. Keyboard and mouse input from the local computer are sent to the remote computer.

OPTIONS

-a bpp
Sets the colour depth for the connection (8, 15, 16, 24 or 32). More than 8 bpp are only supported when connecting to Windows XP (up to 16 bpp) or newer. Note that the colour depth may also be limited by the server configuration. The default value is the depth of the root window.
-z
Enable compression of the RDP datastream.
-x <experience>
Changes default bandwidth performance behaviour for RDP5. By default only theming is enabled, and all other options are disabled (corresponding to modem (56 Kbps)). Setting experience to b[roadband] enables menu animations and full window dragging. Setting experience to l[an] will also enable the desktop wallpaper. Setting experience to m[odem] disables all (including themes). Experience can also be a hexadecimal number containing the flags.
-P
Enable caching of bitmaps to disk (persistent bitmap caching). This generally improves performance (especially on low bandwidth connections) and reduces network traffic at the cost of slightly longer startup and some disk space. (10MB for 8-bit colour, 20MB for 15/16-bit colour, 30MB for 24-bit colour and 40MB for 32-bit colour sessions)
-r <device>
Enable redirection of the specified device on the client, such that it appears on the server. Note that the allowed redirections may be restricted by the server configuration.

Following devices are currently supported:

-r comport:<comport>=<device>,...
Redirects serial devices on your client to the server. Note that if you need to change any settings on the serial device(s), do so with an appropriate tool before starting rdesktop. In most OSes you would use stty. Bidirectional/Read support requires Windows XP or newer. In Windows 2000 it will create a port, but it's not seamless, most shell programs will not work with it.
-r disk:<sharename>=<path>,...
Redirects a path to the share \\tsclient\<sharename> on the server (requires Windows XP or newer). The share name is limited to 8 characters.
-r lptport:<lptport>=<device>,...
Redirects parallel devices on your client to the server. Bidirectional/Read support requires Windows XP or newer. In Windows 2000 it will create a port, but it's not seamless, most shell programs will not work with it.
-r printer:<printername>[=<driver>],...
Redirects a printer queue on the client to the server. The <printername> is the name of the queue in your local system. <driver> defaults to a simple PS-driver unless you specify one. Keep in mind that you need a 100% match in the server environment, or the driver will fail. The first printer on the command line will be set as your default printer.
-r sound:[local|off|remote]
Redirects sound generated on the server to the client. "remote" only has any effect when you connect to the console with the -0 option. (Requires Windows XP or newer).
-r lspci
Activates the lspci channel, which allows the server to enumerate the clients PCI devices. See the file lspci-channel.txt in the documentation for more information.
-r scard[:<Scard Name>=<Alias Name>[;<Vendor Name>][,...]]
Enables redirection of one or more smart-cards. You can provide static name binding between GNU/Linux and Windows. To do this you can use optional parameters as described: <Scard Name> - device name in GNU/Linux and UNIX environment, <Alias Name> - device name shown in Windows environment <Vendor Name> - optional device vendor name. For list of examples run rdesktop without parameters.
-r clipboard:[off|PRIMARYCLIPBOARD|CLIPBOARD]
Enable clipboard redirection. 'PRIMARYCLIPBOARD' looks at both PRIMARY and CLIPBOARD when sending data to server. 'CLIPBOARD' looks at only 'CLIPBOARD'.
-0
Attach to the console of the server (requires Windows Server 2003 or newer).
-4
Use RDP version 4.
-5
Use RDP version 5 (default).
-v
Enable verbose output

CredSSP Smartcard options

--sc-csp-name <name>
Specify the CSP (Crypto Service Provider) to use on the windows side for the smartcard authentication. CSP is the driver for your smartcard and it seems like this is required to be specified for CredSSP authentication. For Swedish NetID the following CSP name is used; "Net iD - CSP".
--sc-container-name <name>
Specify the container name, usually this is the username for default container and it seems like this is required to be specified for CredSSP authentication.
--sc-reader-name <name>
Specify the reader name to be used to prevent the pin code being sent to wrong card if there are several readers.
--sc-card-name <name>
Specify the card name for example; "Telia EID IP5a".
