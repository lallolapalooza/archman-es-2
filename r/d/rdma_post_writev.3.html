NOMBRE

rdma_post_writev - publicar una solicitud de trabajo de escritura RDMA.

SINOPSIS

#include <rdma/rdma_verbs.h>

int rdma_post_writev (struct rdma_cm_id *id, void *context, struct ibv_sge *sgl, int nsge, int flags, uint64_t remote_addr, uint32_t rkey);

ARGUMENTOS

id
Una referencia a un identificador de comunicación donde se publicará la solicitud.
context
Contexto definido por el usuario asociado con la solicitud.
sgl
Una lista de dispersión-agregación de los búferes de origen de la escritura.
nsge
El número de entradas de la matriz de dispersión-agregación.
flags
Marcas opcionales utilizadas para controlar la operación de escritura.
remote_addr
La dirección de la memoria registrada remota a la que escribir.
rkey
La clave de memoria registrada asociada con la dirección remota.

DESCRIPCIÓN

Publica una solicitud de trabajo en la cola de envío del par de colas asociado con el rdma_cm_id. El contenido de los búferes de datos locales se escribirá en la región de memoria remota.

VALOR DE RETORNO

Devuelve 0 si tiene éxito, o -1 si ocurre un error. Si ocurre un error, errno se establecerá para indicar el motivo de la falla.

NOTAS

Para obtener una lista de las marcas admitidas, consulte ibv_post_send. A menos que se especifique datos en línea, los búferes de datos locales deben haber sido registrados antes de emitir la escritura, y los búferes deben permanecer registrados hasta que la escritura se complete. Los búferes remotos siempre deben estar registrados.

Las operaciones de escritura no se pueden publicar en un rdma_cm_id o en el par de colas correspondiente hasta que se haya conectado.

El contexto definido por el usuario asociado con la solicitud de escritura se devolverá al usuario a través del campo wr_id (identificador de solicitud de trabajo) de la finalización del trabajo.

VER TAMBIÉN
