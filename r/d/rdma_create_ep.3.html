RDMA_CREATE_EP(3) Manual del programador de Librdmacm RDMA_CREATE_EP(3)

NOMBRE

rdma_create_ep - Asigna un identificador de comunicación y, opcionalmente, una QP.

SINOPSIS

#include <rdma/rdma_cma.h>

int rdma_create_ep (struct rdma_cm_id **id, struct rdma_addrinfo *res, struct ibv_pd *pd, struct ibv_qp_init_attr *qp_init_attr);

ARGUMENTOS

id
Una referencia donde se devolverá el identificador de comunicación asignado.
res
Información de dirección asociada con el rdma_cm_id devuelto por rdma_getaddrinfo.
pd
Dominio de protección opcional si se asocia una QP con el rdma_cm_id.
qp_init_attr
Atributos iniciales opcionales de la QP.

DESCRIPCIÓN

Crea un identificador que se utiliza para rastrear la información de comunicación.

VALOR DE RETORNO

Devuelve 0 si tiene éxito, o -1 si ocurre un error. Si ocurre un error, errno se establecerá para indicar la razón de la falla.

NOTAS

Después de resolver la información de la dirección utilizando rdma_getaddrinfo, un usuario puede usar esta llamada para asignar un rdma_cm_id basándose en los resultados.

Si el rdma_cm_id se utilizará en el lado activo de una conexión, lo que significa que res->ai_flag no tiene RAI_PASSIVE establecido, rdma_create_ep creará automáticamente una QP en el rdma_cm_id si qp_init_attr no es NULL. La QP se asociará con el dominio de protección especificado, si se proporciona, o con un dominio de protección predeterminado si no. Los usuarios deberían ver rdma_create_qp para obtener detalles sobre el uso de los parámetros pd y qp_init_attr. Después de llamar a rdma_create_ep, el rdma_cm_id devuelto puede conectarse llamando a rdma_connect. Las llamadas del lado activo rdma_resolve_addr y rdma_resolve_route no son necesarias.

Si el rdma_cm_id se utilizará en el lado pasivo de una conexión, indicado por tener res->ai_flag establecido en RAI_PASSIVE, esta llamada guardará los parámetros pd y qp_init_attr proporcionados. Cuando se recupera una nueva solicitud de conexión llamando a rdma_get_request, el rdma_cm_id asociado con la nueva conexión se asociará automáticamente con una QP usando los parámetros pd y qp_init_attr. Después de llamar a rdma_create_ep, el rdma_cm_id devuelto puede ponerse en estado de escucha llamando inmediatamente a rdma_listen. La llamada del lado pasivo rdma_bind_addr no es necesaria. Las solicitudes de conexión pueden recuperarse llamando a rdma_get_request.

El rdma_cm_id recién creado se establecerá para usar operaciones síncronas. Los usuarios que deseen operaciones asíncronas deben migrar el rdma_cm_id a un canal de eventos creado por el usuario utilizando rdma_migrate_id.

Los usuarios deben liberar el rdma_cm_id creado llamando a rdma_destroy_ep.

VER TAMBIÉN
