RDMA_GETADDRINFO(3) Manual del Programador de Librdmacm RDMA_GETADDRINFO(3)

NOMBRE

rdma_getaddrinfo - Proporciona traducción de direcciones independiente del transporte.

SINOPSIS

#include <rdma/rdma_cma.h>

int rdma_getaddrinfo (const char *node, const char *service, const struct rdma_addrinfo *hints, struct rdma_addrinfo **res);

ARGUMENTOS

nodo
Opcional, nombre, IPv4 de punto decimal o dirección hexadecimal IPv6 a resolver.
servicio
Nombre del servicio o número de puerto de la dirección.
sugerencias
Referencia a una estructura rdma_addrinfo que contiene sugerencias sobre el tipo de servicio que soporta el llamador.
res
Un puntero a una lista enlazada de estructuras rdma_addrinfo que contienen información de respuesta.

DESCRIPCIÓN

Resuelve la dirección del nodo de destino y del servicio y devuelve la información necesaria para establecer la comunicación. Proporciona el equivalente funcional RDMA de getaddrinfo.

VALOR DEVUELTO

Devuelve 0 si hay éxito, o -1 si hay un error (errno se establecerá para indicar el motivo de la falla), o uno de los siguientes códigos de error distintos de cero:

EAI_ADDRFAMILY
El host de red especificado no tiene ninguna dirección de red en la familia de direcciones solicitada.
EAI_AGAIN
El servidor de nombres devolvió una indicación de fallo temporal. Inténtelo de nuevo más tarde.
EAI_BADFLAGS
hints.ai_flags contiene indicadores inválidos.
EAI_FAIL
El servidor de nombres devolvió una indicación de fallo permanente.
EAI_FAMILY
La familia de direcciones solicitada no es compatible.
EAI_MEMORY
Sin memoria.
EAI_NODATA
El host de red especificado existe, pero no tiene direcciones de red definidas.
EAI_NONAME
El nodo o servicio no se conoce; o tanto nodo como servicio son NULL.
EAI_SERVICE
El servicio solicitado no está disponible para el tipo de QP solicitado. Puede estar disponible a través de otro tipo de QP.
EAI_QPTYPE
El tipo de socket solicitado no es compatible. Esto podría ocurrir, por ejemplo, si hints.ai_qptype y hints.ai_port_space son inconsistentes (por ejemplo, IBV_QPT_UD y RDMA_PS_TCP, respectivamente).
EAI_SYSTEM
Otro error del sistema, compruebe errno para obtener detalles. La función gai_strerror() traduce estos códigos de error a una cadena legible por humanos, adecuada para la notificación de errores.

NOTAS

Deben proporcionarse nodo, servicio o hints. Si se proporcionan hints, la operación estará controlada por hints.ai_flags. Si se especifica RAI_PASSIVE, la llamada resolverá información de dirección para usarla en el lado pasivo de una conexión. Si se proporciona nodo, rdma_getaddrinfo intentará resolver la dirección RDMA, la ruta y los datos de conexión al nodo dado. El parámetro hints, si se proporciona, puede usarse para controlar la salida resultante según se indica a continuación. Si no se proporciona nodo, rdma_getaddrinfo intentará resolver la información de direccionamiento RDMA basándose en hints.ai_src_addr, hints.ai_dst_addr o hints.ai_route.

rdma_addrinfo

ai_flags
Indicadores de sugerencia que controlan la operación. Los indicadores soportados son:
RAI_PASSIVE
Indica que los resultados se utilizarán en el lado pasivo/de escucha de una conexión.
RAI_NUMERICHOST
Si se especifica, el parámetro nodo, si se proporciona, debe ser una dirección de red numérica. Este indicador suprime cualquier resolución de dirección prolongada.
RAI_NOROUTE
Si se establece, este indicador suprime cualquier resolución de ruta prolongada.
RAI_FAMILY
Si se establece, la configuración de ai_family debe usarse como una sugerencia de entrada para interpretar el parámetro nodo.
RAI_DNS
Indica que la resolución de direcciones debe usar DNS para mapear los nombres de nodo y servicio a direcciones. El indicador es mutuamente excluyente con RAI_SA. La resolución DNS es la opción predeterminada.
RAI_SA
Indica que la resolución de direcciones debe consultar la SA de Infiniband para mapear los nombres de nodo y servicio a direcciones. El indicador es mutuamente excluyente con RAI_DNS. La resolución SA solo se aplica a los puertos Infiniband. Los puertos no Infiniband se omitirán.
ai_family
Familia de direcciones para la dirección de origen y destino. Las familias soportadas son: AF_INET, AF_INET6 y AF_IB.
ai_qp_type
Indica el tipo de QP RDMA utilizado para la comunicación. Los tipos soportados son: IBV_QPT_UD (datagrama no fiable) e IBV_QPT_RC (conectado fiable).
ai_port_space
Espacio de puertos RDMA en uso. Los valores soportados son: RDMA_PS_UDP, RDMA_PS_TCP y RDMA_PS_IB.
ai_src_len
La longitud de la dirección de origen referenciada por ai_src_addr. Será 0 si no se pudo descubrir una dirección de origen adecuada para un destino dado.
ai_dst_len
La longitud de la dirección de destino referenciada por ai_dst_addr. Será 0 si se especificó el indicador RAI_PASSIVE como parte de las sugerencias.
ai_src_addr
Si se proporciona, la dirección para el dispositivo RDMA local.
ai_dst_addr
Si se proporciona, la dirección para el dispositivo RDMA de destino.
ai_src_canonname
El nombre canónico del origen.
ai_dst_canonname
El nombre canónico del destino.
ai_route_len
Tamaño del búfer de información de enrutamiento referenciado por ai_route. Será 0 si el transporte subyacente no requiere datos de enrutamiento, o si no se pudo resolver ninguno.
ai_route
Información de enrutamiento para transportes RDMA que requieren datos de enrutamiento como parte del establecimiento de la conexión. El formato de los datos de enrutamiento depende del transporte subyacente. Si se utilizan transportes Infiniband, ai_route hará referencia a una matriz de struct ibv_path_data en la salida, si los datos de enrutamiento están disponibles. Las rutas de enrutamiento pueden restringirse estableciendo los campos de datos de enrutamiento deseados en la entrada de rdma_getaddrinfo. Para Infiniband, hints.ai_route puede hacer referencia a una matriz de struct ibv_path_record o struct ibv_path_data en la entrada.
ai_connect_len
Tamaño de la información de conexión referenciada por ai_connect. Será 0 si el transporte subyacente no requiere información de conexión adicional.
ai_connect
Datos intercambiados como parte del proceso de establecimiento de la conexión. Si se proporcionan, los datos de ai_connect deben transferirse como datos privados, con cualquier dato privado suministrado por el usuario siguiéndolos.
ai_next

rdma_getaddrinfo(3) — librdmacm — Arch Linux

NAME

rdma_getaddrinfo

get destination address information

SYNOPSIS

#include <rdma/rdma_verbs.h>
int rdma_getaddrinfo(const char *nodename, const char *servname,
    const struct rdma_addrinfo *hints, struct rdma_addrinfo **res);

ARGUMENTS

nodename

An optional pointer to a null-terminated string that specifies a node name or a numeric host address.

servname

An optional pointer to a null-terminated string that specifies a protocol-specific service name or a numeric port number.

hints

An optional pointer to an rdma_addrinfo structure that specifies criteria for selecting the return address. If hints is not NULL, then the fields that are not relevant to the query should be set to zero or NULL. The ai_flags field may be used to request specific behavior.

res

An output parameter. If the call is successful, then res is set to point to a linked list of rdma_addrinfo structures, each of which represents an address that is valid for the specified node name and service name. The caller must free the memory for this list by calling rdma_freeaddrinfo(3).

DESCRIPTION

The rdma_getaddrinfo() function is the extensible interface for network address resolution. This function takes node and service names, translates them into a set of canonical protocol-independent address structures, and returns them to the caller.

The hints argument specifies criteria that the caller uses to filter the results. For example, a caller can request that only stream sockets be returned, or that only IPv4 addresses be returned.

The nodename and servname arguments are interpreted as follows:

If nodename is not NULL, it is interpreted as a host name or an IP address.
If servname is not NULL, it is interpreted as a service name or a port number.
If both are not NULL, then rdma_getaddrinfo() is expected to return address information that matches both.
If both are NULL, then rdma_getaddrinfo() is expected to return a list of available local addresses.

The hints structure is used to specify requirements for the return values. The following flags can be specified in ai_flags:

AI_PASSIVE

If the AI_PASSIVE flag is set, and nodename is NULL, then the returned address information will be suitable for use with bind(2) system call. This is typically used for server applications that want to listen on a specific port for incoming connections.

AI_NUMERICHOST

If the AI_NUMERICHOST flag is set, then nodename is treated as a numeric host address. If the name is not a valid numeric address, then an error is returned.

AI_NUMERICSERV

If the AI_NUMERICSERV flag is set, then servname is treated as a numeric port number. If the name is not a valid numeric port number, then an error is returned.

AI_ALL

If the AI_ALL flag is set, then the returned address information includes all addresses for the specified node name and service name, regardless of whether they are IPv4 or IPv6.

AI_LOCALONLY

If the AI_LOCALONLY flag is set, then the returned address information includes only local addresses.

The rdma_addrinfo structure is defined as follows:

struct rdma_addrinfo {
    int     ai_flags;
    int     ai_port_space;
    struct sockaddr     *ai_src_addr;
    struct sockaddr     *ai_dst_addr;
    struct rdma_conn_param *ai_conn_param;
    void    *ai_user_data;
};

The ai_port_space field can be set to RDMA_PS_TCP or RDMA_PS_UDP to specify the desired port space.

The ai_conn_param field is a pointer to a rdma_conn_param structure, which is used to specify connection parameters such as retry counts and timeouts.

The ai_user_data field can be used by the caller to store arbitrary user data associated with the address information.

RETURN VALUE

On success, rdma_getaddrinfo() returns 0 and sets res to point to a linked list of rdma_addrinfo structures. On failure, it returns a negative error code and sets res to NULL.

NOTES

The rdma_getaddrinfo function is a thread-safe function.

The memory allocated for the result list pointed to by res must be freed by the caller using rdma_freeaddrinfo(3).

The rdma_conn_param structure pointed to by ai_conn_param is optional. If it is not provided, default connection parameters will be used.

rdma_addrinfo

The rdma_addrinfo structure is used to exchange address information between the caller and the rdma_getaddrinfo() function. It contains the following fields:

ai_flags

Flags that specify the type of address information requested. See the DESCRIPTION section for a list of possible flags.

ai_port_space

Specifies the port space for the address. Can be RDMA_PS_TCP or RDMA_PS_UDP.

ai_src_addr

Pointer to a sockaddr structure that specifies the source address. This is typically used for binding to a specific local address.

ai_dst_addr

Pointer to a sockaddr structure that specifies the destination address. This is used for connecting to a remote address.

ai_conn_param

Pointer to a rdma_conn_param structure that specifies connection parameters such as retry count, RNR (Receiver Not Ready) timeout, and retry error recovery settings.

ai_user_data

A pointer to user-defined data that can be associated with this address information entry. This is useful for passing application-specific context along with the address.

Note that ai_src_addr and ai_dst_addr will point to dynamically allocated memory that is part of the returned rdma_addrinfo structure. The caller does not need to allocate or free this memory separately, but it should be considered freed when rdma_freeaddrinfo(3) is called.

There are no more structures.
