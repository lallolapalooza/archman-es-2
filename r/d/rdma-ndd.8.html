RDMA-NDD(8) Diagnósticos OpenIB RDMA-NDD(8)

NOMBRE

RDMA-NDD - Demonio de actualización de Descripción de Nodo de dispositivo RDMA

SINOPSIS

rdma-ndd <opciones>

DESCRIPCIÓN

rdma-ndd es un demonio del sistema que vigila los cambios en los dispositivos rdma y/o los cambios en el nombre de host y actualiza la Descripción del Nodo de los dispositivos rdma basándose en esos cambios.

DETALLES

El funcionamiento completo de este demonio requiere kernels que soporten el sondeo del archivo hostname de procfs, así como libudev.

Si su sistema no soporta ninguna de estas características, el demonio establecerá las Descripciones del Nodo al arrancar y luego dormirá para siempre.

Configuración de Descripción del Nodo

El demonio utiliza la variable de entorno RDMA_NDD_ND_FORMAT para establecer la descripción del nodo. Los siguientes comodines se pueden especificar para un control más dinámico.

%h -- reemplazar con el nombre de host actual (sin incluir el dominio)

%d -- reemplazar con el nombre del dispositivo (por ejemplo, mlx4_0, qib0, etc.)

Si no se especifica, el valor predeterminado es "%h %d".

NOTA: Al arrancar, y al detectar un nuevo dispositivo, la Descripción del Nodo siempre se escribe para asegurar que el SM y rdma-ndd estén sincronizados. Los eventos posteriores solo escribirán la Descripción del Nodo en un dispositivo si ha cambiado.

Usando systemd

Establecer la variable de entorno para el demonio se hace normalmente a través de una unidad de inserción de systemd. Por ejemplo, lo siguiente podría añadirse a un archivo llamado /etc/systemd/system/rdma-ndd.service.d/nd-format.conf para usar solo el nombre de host como descripción de su nodo.

[Service] Environment="RDMA_NDD_ND_FORMAT=%%h"

NOTA: Systemd requiere un '%' adicional.

OPCIONES

-f, --foreground Ejecutar en primer plano en lugar de como un demonio

-d, --debug Registrar información de depuración adicional en syslog

--systemd Habilitar la integración con systemd.
