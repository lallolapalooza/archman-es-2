NOMBRE

rdfind - encuentra archivos duplicados

SINOPSIS

rdfind [ opciones ] directorio1 | archivo1 [ directorio2 | archivo2 ] ...

DESCRIPCIÓN

rdfind encuentra archivos duplicados entre y/o dentro de varios directorios. Calcula la suma de verificación solo si es necesario. rdfind se ejecuta en tiempo O(Nlog(N)) donde N es el número de archivos.

Si se encuentran dos (o más) archivos iguales, el programa decide cuál de ellos es el original y los restantes se consideran duplicados. Esto se hace clasificando los archivos entre sí y decidiendo cuál tiene el rango más alto. Ver la sección RANKING para más detalles.

Por defecto, no se toma ninguna acción además de crear un archivo con los archivos detectados y mostrar la cantidad de espacio que se podría ahorrar.

Si necesita un mejor control sobre la clasificación del que se ofrece, puede usar algún preprocesador que ordene los nombres de archivo en el orden deseado y luego ejecute el programa usando xargs. Ver los ejemplos a continuación para saber cómo usar find y xargs junto con rdfind.

Para incluir archivos o directorios cuyos nombres comiencen con -, use rdfind ./- para no confundirlos con opciones.

CLASIFICACIÓN

Dados dos o más archivos iguales, el que tenga el rango más alto se selecciona como original y los restantes son duplicados. Las reglas de clasificación se dan a continuación, donde las reglas se ejecutan desde el principio hasta que se ha encontrado un original. Dados dos archivos A y B que tienen tamaño y contenido iguales, la clasificación es la siguiente:

Si A fue encontrado mientras se escaneaba un argumento de entrada antes que B, A tiene un rango más alto.

Si A fue encontrado en una profundidad de directorio menor que B, A tiene un rango más alto (A está más cerca de la raíz).

si A y B se encuentran durante el escaneo del mismo argumento de entrada y comparten la misma profundidad de directorio, cuál de ellos tiene el rango más alto depende de si la operación determinista está habilitada. Esto está activado por defecto, ver la opción -deterministic). Si está habilitado, cuál tiene el rango más alto no se especifica pero es determinista. Si está deshabilitado, el que fue reportado primero por el sistema de archivos tiene el rango más alto.

OPCIONES

Opciones de búsqueda, etc.:

-ignoreempty verdadero|falso
Ignora archivos vacíos. Establecer esto a verdadero (el valor por defecto) es equivalente a -minsize 1, falso es equivalente a -minsize 0.
-minsize N
Ignora archivos con menos de N bytes. El valor por defecto es 1, lo que significa que se ignoran los archivos vacíos.
-maxsize N
Ignora archivos con N bytes o más. El valor por defecto es 0, lo que significa que esta comprobación está deshabilitada.
-followsymlinks verdadero|falso
Sigue los enlaces simbólicos. El valor por defecto es falso.
-removeidentinode verdadero|falso
Elimina elementos encontrados que tienen inodo y ID de dispositivo idénticos. El valor por defecto es verdadero.
-checksum md5|sha1|sha256|sha512|xxh128
Qué tipo de suma de verificación usar: md5, sha1, sha256, sha512 o xxh128. El valor por defecto es sha1 desde la versión 1.4.0. xxh128 es una suma de verificación muy rápida, pero no de calidad criptográfica. El soporte xxh es opcional y requiere que rdfind se haya configurado con --with-xxhash. En caso de que se use xxh pero no haya soporte, se devuelve un error.
-buffersize N
Tamaño del bloque en bytes al calcular la suma de verificación para los archivos, un tamaño menor o mayor puede mejorar el rendimiento dependiendo del sistema de archivos y el algoritmo de suma de verificación. El valor por defecto es 1 MiB, el máximo permitido es 128MiB (inclusive).
-deterministic verdadero|falso
Si está activado (el valor por defecto), ordena los archivos de rango igual en un orden no especificado pero determinista. Esto hace que el comportamiento sea independiente del orden en que se listan los archivos al consultar el sistema de archivos.

Opciones de acción:

-makesymlinks verdadero|falso
Reemplaza los archivos duplicados con enlaces simbólicos. El valor por defecto es falso.
-makehardlinks verdadero|falso
Reemplaza los archivos duplicados con enlaces duros. El valor por defecto es falso.
-makeresultsfile verdadero|falso
Crea un archivo de resultados en el directorio actual. El valor por defecto es verdadero. Si el archivo existe, se sobrescribe. Esto no afecta a si se eliminan elementos. Ver -dryrun para cómo deshabilitar las eliminaciones.
-outputname nombre
Nombra el archivo de resultados como "nombre" en lugar del default results.txt.
-deleteduplicates verdadero|falso
Elimina (desenlaza) archivos. El valor por defecto es falso.

Opciones generales:

-sleep Xms
Duerme X milisegundos entre la lectura de cada archivo, para reducir la carga. El valor por defecto es 0 (sin pausa). Tenga en cuenta que solo unos pocos valores son compatibles en la actualidad: 0, 1-5, 10, 25, 50, 100 milisegundos.
-n, -dryrun verdadero|falso
Muestra lo que debería haberse hecho, no elimina ni enlaza nada en realidad. El valor por defecto es falso.
-h, -help, --help
Muestra un breve mensaje de ayuda.
-v, -version, --version
Muestra el número de versión.

EJEMPLOS

Buscar archivos duplicados en el directorio de inicio y un directorio de copia de seguridad:
rdfind ~ /mnt/backup
Eliminar duplicados en un directorio de copia de seguridad:
rdfind -deleteduplicates true /mnt/backup
Buscar archivos duplicados en directorios llamados foo:
find . -type d -name foo -print0 |xargs -0 rdfind

ARCHIVOS

results.txt (el nombre por defecto es results.txt y puede cambiarse con la opción outputname, ver arriba) El archivo de resultados results.txt contendrá una fila por cada archivo duplicado encontrado, junto con una fila de encabezado explicando las columnas. Un texto describe por qué el archivo se considera un duplicado:

DUPTYPE_UNKNOWN algún error interno

DUPTYPE_FIRST_OCCURRENCE el archivo que se considera el original.

DUPTYPE_WITHIN_SAME_TREE archivos en el mismo árbol (encontrados al procesar el directorio en el mismo argumento de entrada que el original)

DUPTYPE_OUTSIDE_TREE el archivo se encuentra al procesar un argumento de entrada diferente al del original.

ERRORES/CARACTERÍSTICAS

Al especificar el mismo directorio dos veces, se mantiene el primero encontrado como el más importante (original), y los restantes como duplicados. Esto puede no ser lo que deseas.

El enlace simbólico crea enlaces absolutos. Esto puede no ser lo que deseas. Para crear enlaces relativos en su lugar, puedes usar el comando symlink (2), que es capaz de convertir enlaces absolutos a enlaces relativos.

Versiones anteriores lamentablemente contenían un error ortográfico en la palabra occurrence. Esto ahora es correcto

BUGS/FEATURES

See the issue tracker at https://github.com/pauldreik/rdfind/issues. Please report bugs and request features there.

The default hash value is MD5. If you are working on a system where the MD5 hash value is not considered safe enough, you may want to use the -h sha1 option. It is slower, though. Note that for very large file collections, the hash value is never safe enough; therefore, the comparison of the files themselves is default.

If you are working with files that have identical names, sizes and timestamps, you should disable the comparison of the files themselves by using the -I option. This might be useful for example, if you want to remove duplicate files from your backup medium, and you do not want to risk data loss by comparing files which are not identical.

This might be useful for example, if you want to remove duplicate files from your backup medium, and you do not want to risk data loss by comparing files which are not identical.

The output file --outputfile is always written in the same format. If you are using this file as input for user scripts, you should be aware of the fact that the format has been changed slightly in version 1.3. Earlier versions used comma-separated fields, while version 1.3 onwards uses space separated fields, and also includes the filename, and the hash value, which has been added in version 1.3, which might affect user scripts parsing the output file written by rdfind.

SECURITY CONSIDERATIONS

Avoid manipulating the directories while rdfind is reading. rdfind is quite brittle in that case. Especially, when deleting or making links, rdfind can be subject to a symlink attack. Use with care!
