rtcOccluded4/8/16(3) Kernels de trazado de rayos Embree 3 rtcOccluded4/8/16(3)

NOMBRE

rtcOccluded4/8/16 - encuentra cualquier impacto para un paquete de rayos

SINOPSIS

#include <embree3/rtcore.h>
void rtcOccluded4(
  const int* valid,
  RTCScene scene,
  struct RTCIntersectContext* context,
  struct RTCRay4* ray
);
void rtcOccluded8(
  const int* valid,
  RTCScene scene,
  struct RTCIntersectContext* context,
  struct RTCRay8* ray
);
void rtcOccluded16(
  const int* valid,
  RTCScene scene,
  struct RTCIntersectContext* context,
  struct RTCRay16* ray
);

DESCRIPCIÓN

Las funciones rtcOccluded4/8/16 verifican si cada rayo activo del paquete de rayos de tamaño 4, 8 o 16 (argumento ray) tiene algún impacto con la escena (argumento scene). Ver la Sección [rtcOccluded1] para una descripción de cómo configurar y rastrear rayos de oclusión.

Se debe proporcionar una máscara de validez de rayos (argumento valid) que almacena un entero de 32 bits (-1 significa válido y 0 inválido) por rayo en el paquete. Solo se procesan los rayos activos y los datos de impacto de los rayos inactivos no se modifican.

Se garantiza que la implementación de estas funciones invocará las funciones de devolución de llamada siempre con el mismo tamaño de paquete de rayos y orden de rayos que se especificaron inicialmente.

Para rtcOccluded4, el paquete de rayos debe estar alineado a 16 bytes, para rtcOccluded8 la alineación debe ser de 32 bytes y para rtcOccluded16 la alineación debe ser de 64 bytes.

Las funciones rtcOccluded4, rtcOccluded8 y rtcOccluded16 pueden cambiar el tamaño del paquete de rayos y el orden de los rayos al llamar a funciones de filtro de intersección o devoluciones de llamada de geometría del usuario. Bajo ciertas condiciones, la aplicación puede asumir que los paquetes permanecerán intactos, lo que se puede determinar consultando las propiedades RTC_DEVICE_PROPERTY_NATIVE_RAY4_SUPPORTED, RTC_DEVICE_PROPERTY_NATIVE_RAY8_SUPPORTED, RTC_DEVICE_PROPERTY_NATIVE_RAY16_SUPPORTED a través de la función rtcGetDeviceProperty. Ver [rtcGetDeviceProperty] para más información.

ESTADO DE SALIDA

Por razones de rendimiento, esta función no realiza ninguna verificación de errores, por lo tanto, no establecerá ningún indicador de error en caso de fallo.
