sigprocmask(2) System Calls Manual sigprocmask(2)

NOMBRE

sigprocmask, rt_sigprocmask - examinar y cambiar señales bloqueadas

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <signal.h>

/* Prototipo de la función wrapper de glibc */
int sigprocmask(int how, const sigset_t *_Nullable restrict set,
                           sigset_t *_Nullable restrict oldset);
#include <signal.h>           /* Definición de constantes SIG_* */
#include <sys/syscall.h>      /* Definición de constantes SYS_* */
#include <unistd.h>
/* Prototipo de la llamada al sistema subyacente */
int syscall(SYS_rt_sigprocmask, int how,
                           const kernel_sigset_t *_Nullable set,
                           kernel_sigset_t *_Nullable oldset,
                           size_t sigsetsize);
/* Prototipo de la llamada al sistema heredada */
[[deprecated]] int syscall(SYS_sigprocmask, int how,
                           const old_kernel_sigset_t *_Nullable set,
                           old_kernel_sigset_t *_Nullable oldset);
Requisitos de Macro de Prueba de Funciones para glibc (ver feature_test_macros(7)):

sigprocmask():

    _POSIX_C_SOURCE

DESCRIPCIÓN

sigprocmask() se utiliza para obtener y/o cambiar la máscara de señales del hilo llamante. La máscara de señales es el conjunto de señales cuya entrega está actualmente bloqueada para el llamante (ver también signal(7) para más detalles).

El comportamiento de la llamada depende del valor de how, como sigue.

SIG_BLOCK
El conjunto de señales bloqueadas es la unión del conjunto actual y el argumento set.
SIG_UNBLOCK
Las señales en set se eliminan del conjunto actual de señales bloqueadas. Es permisible intentar desbloquear una señal que no está bloqueada.
SIG_SETMASK
El conjunto de señales bloqueadas se establece en el argumento set.

Si oldset no es NULL, el valor anterior de la máscara de señales se almacena en oldset.

Si set es NULL, entonces la máscara de señales no cambia (es decir, how se ignora), pero el valor actual de la máscara de señales se devuelve de todos modos en oldset (si no es NULL).

Se describe un conjunto de funciones para modificar e inspeccionar variables de tipo sigset_t ("conjuntos de señales") en sigsetops(3).

El uso de sigprocmask() no está especificado en un proceso multihilo; ver pthread_sigmask(3).

VALOR DE RETORNO

sigprocmask() devuelve 0 en caso de éxito. En caso de fallo, se devuelve -1 y se establece errno para indicar el error.

ERRORES

EFAULT
El argumento set o oldset apunta fuera del espacio de direcciones asignado del proceso.
EINVAL
O bien el valor especificado en how no era válido o el kernel no soporta el tamaño pasado en sigsetsize.

VERSIONES

Diferencias biblioteca C/kernel

La definición de sigset_t del kernel difiere en tamaño de la utilizada por la biblioteca C. En esta página de manual, la primera se denomina kernel_sigset_t (sin embargo, se denomina sigset_t en las fuentes del kernel).

La función wrapper de glibc para sigprocmask() ignora silenciosamente los intentos de bloquear las dos señales de tiempo real que se utilizan internamente por la implementación de hilos NPTL. Ver nptl(7) para detalles.

La llamada al sistema original de Linux se denominaba sigprocmask(). Sin embargo, con la adición de señales de tiempo real en Linux 2.2, el tipo sigset_t de tamaño fijo y 32 bits (denominado old_kernel_sigset_t en esta página de manual) soportado por esa llamada al sistema ya no era adecuado. En consecuencia, se añadió una nueva llamada al sistema, rt_sigprocmask(), para soportar un tipo sigset_t ampliado (denominado kernel_sigset_t en esta página de manual). La nueva llamada al sistema toma un cuarto argumento, size_t sigsetsize, que especifica el tamaño en bytes de los conjuntos de señales en set y oldset. Actualmente se requiere que este argumento tenga un valor fijo específico de la arquitectura (igual a sizeof(kernel_sigset_t)).

La función wrapper sigprocmask() de glibc oculta estos detalles, llamando transparentemente a rt_sigprocmask() cuando el kernel las proporciona.

ESTÁNDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2001.

NOTAS

No es posible bloquear SIGKILL o SIGSTOP. Los intentos de hacerlo se ignoran silenciosamente.

Cada uno de los hilos en un proceso tiene su propia máscara de señales.

Un hijo creado a través de fork(2) hereda una copia de la máscara de señales de su padre; la máscara de señales se conserva a través de execve(2).

Si SIGBUS, SIGFPE, SIGILL, o SIGSEGV se generan mientras están bloqueadas, el resultado no está definido, a menos que la señal haya sido generada por kill(2), sigqueue(3), o raise(3).

Ver sigsetops(3) para detalles sobre la manipulación de conjuntos de señales.

Tenga en cuenta que es permisible (aunque no muy útil) especificar tanto set como oldset como NULL.
