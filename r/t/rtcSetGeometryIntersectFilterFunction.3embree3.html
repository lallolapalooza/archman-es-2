rtcSetGeometryIntersectFilterFunction(3) Núcleos de Ray Tracing Embree 3 rtcSetGeometryIntersectFilterFunction(3)

NOMBRE

rtcSetGeometryIntersectFilterFunction - establece el filtro de intersección
  para la geometría

SINOPSIS

#include <embree3/rtcore.h>
struct RTCFilterFunctionNArguments
{
  int* valid;
  void* geometryUserPtr;
  const struct RTCIntersectContext* context;
  struct RTCRayN* ray;
  struct RTCHitN* hit;
  unsigned int N;
};
typedef void (*RTCFilterFunctionN)(
  const struct RTCFilterFunctionNArguments* args
);
void rtcSetGeometryIntersectFilterFunction(
  RTCGeometry geometry,
  RTCFilterFunctionN filter
);

DESCRIPCIÓN

La función rtcSetGeometryIntersectFilterFunction registra una función de llamada de filtro de intersección (argumento filter) para la geometría especificada (argumento geometry).

Solo se puede registrar una función de llamada por geometría, y las invocaciones posteriores sobrescriben la función de llamada previamente establecida. Pasar NULL como puntero de función deshabilita la función de llamada registrada.

La función de filtro de intersección registrada se invoca para cada impacto encontrado durante las consultas de rayos de tipo rtcIntersect y puede aceptar o rechazar ese impacto. La característica se puede utilizar para definir una silueta para una primitiva y rechazar impactos que estén fuera de la silueta. Por ejemplo, una hoja de árbol podría modelarse con una textura alfa que decida si los puntos de impacto están dentro o fuera de la hoja.

Si se establece el modo RTC_BUILD_QUALITY_HIGH, las funciones de filtro pueden llamarse varias veces para el mismo impacto de primitiva. Además, los rayos que golpean exactamente el borde también pueden informar dos impactos para la misma superficie. Para ciertos casos de uso, la aplicación puede tener que solucionar esta limitación recopilando pares de (geomID/primID) de impactos ya reportados e ignorando duplicados.

La función de devolución de llamada del filtro de tipo RTCFilterFunctionN recibe una serie de argumentos a través de la estructura RTCFilterFunctionNArguments. El parámetro valid de esa estructura apunta a una máscara de entero válida (0 significa inválido y -1 significa válido). El miembro geometryUserPtr es un puntero de usuario establecido opcionalmente por geometría a través de la función rtcSetGeometryUserData. El miembro context apunta al contexto de intersección pasado a la función de consulta de rayos. El parámetro ray apunta a N rayos en diseño SOA. El parámetro hit apunta a N impactos en diseño SOA a probar. El parámetro N es el número de rayos e impactos en ray e hit. La distancia de impacto se proporciona como el valor tfar del rayo. Si la geometría de impacto está instanciada, el miembro instID del rayo es válido, y el rayo y el impacto potencial están en el espacio del objeto.

La función de devolución de llamada del filtro tiene la tarea de comprobar para cada rayo válido si desea aceptar o rechazar el impacto correspondiente. Para rechazar un impacto, la función de devolución de llamada del filtro solo tiene que escribir 0 en la máscara de entero válida del rayo correspondiente. Para aceptar el impacto, solo tiene que dejar la máscara válida en -1. La función de filtro también puede modificar el impacto y disminuir el valor tfar del rayo, pero no debe modificar otros datos del rayo ni ningún componente inactivo del rayo o impacto.

La implementación de la función de filtro puede optar por implementar un único camino de código que utiliza las funciones auxiliares de acceso a rayos RTCRay_XXX y las funciones auxiliares de acceso a impactos RTCHit_XXX para acceder a los datos de rayos e impactos. Alternativamente, el código puede ramificarse a implementaciones optimizadas para tamaños específicos de N y lanzar las entradas de rayo e impacto a los tipos de paquete adecuados.

ESTADO DE SALIDA

En caso de error, se establece un código de error que se puede consultar mediante rtcGetDeviceError.
