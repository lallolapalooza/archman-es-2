NOMBRE

rtl_433 - Receptor genérico de datos RF para dispositivos de banda ISM utilizando RTL-SDR y SoapySDR.

DESCRIPCIÓN

Esta página del manual documenta brevemente el comando rtl_433.

rtl_433 es un receptor de datos genérico, principalmente para las bandas ISM de 433.92 MHz, 868 MHz (SRD), 315 MHz y 915 MHz. Funciona con RTL-SDR y/o SoapySDR. Los dispositivos probados y soportados activamente son dongles DVB basados en RTL2832 (usando RTL-SDR) y muestras de ingeniería de LimeSDR (LimeSDR USB y LimeSDR mini, amablemente proporcionadas por MyriadRf), PlutoSDR, HackRF One (usando controladores SoapySDR), así como SoapyRemote.

SINOPSIS

rtl_433 [OPCIÓN]... ARCHIVO...

OPCIONES

A continuación se incluye un resumen de las opciones. La información detallada sobre algunas opciones sigue más adelante.


Se busca un archivo "rtl_433.conf" en "./", XDG_CONFIG_HOME, por ejemplo, "$HOME/.config/rtl_433/",
SYSCONFDIR, por ejemplo, "/usr/local/etc/rtl_433/", luego los argumentos de línea de comandos se analizarán en orden.

Opciones generales

[ -V ]
Muestra la cadena de versión y sale
[ -v ]
Aumenta la verbosidad (se puede usar varias veces).
-v : aviso detallado, -vv : información detallada, -vvv : depuración, -vvvv : traza.
[ -c <ruta> ]
Lee las opciones de configuración de un archivo

Opciones del sintonizador

[ -d <índice del dispositivo USB RTL-SDR> | :<serial del dispositivo USB RTL-SDR> | <consulta de dispositivo SoapySDR> | rtl_tcp | ayuda ]
[-g <ganancia> | ayuda] (por defecto: automático)
[ -t <configuración> ]
aplica una lista de configuraciones clave=valor al dispositivo SDR
ej. para SoapySDR -t "antena=A,ancho_banda=4.5M,rfnotch_ctrl=false"
para RTL-SDR usa "direct_samp[=1]", "offset_tune[=1]", "digital_agc[=1]", "biastee[=1]"
[ -f <frecuencia> ]
Frecuencia(s) de recepción (por defecto: 433920000 Hz)
[ -H <segundos> ]
Intervalo de salto para sondeo de múltiples frecuencias (por defecto: 600 segundos)
[ -p <error_ppm> ]
Corrige el error de frecuencia del sintonizador rtl-sdr (por defecto: 0)
[ -s <tasa de muestreo> ]
Establece la tasa de muestreo (por defecto: 250000 Hz)
[ -D reiniciar | pausar | salir | manual ]
Opciones de modo de ejecución del dispositivo de entrada.

Opciones del demodulador

[ -R <dispositivo> | ayuda ]
Habilita solo el protocolo de decodificación del dispositivo especificado (se puede usar varias veces)
Especifica un número negativo para deshabilitar un protocolo de decodificación de dispositivo (se puede usar varias veces)
[ -X <espec> | ayuda ]
Agrega un decodificador de propósito general (precede con -R 0 para deshabilitar todos los decodificadores)
[ -Y auto | clásico | minmax ]
Modo de detector de pulsos FSK.
[ -Y nivel=<nivel dB> ]
Nivel de detección manual utilizado para determinar pulsos (-1.0 a -30.0) (0=automático).
[ -Y minlevel=<nivel dB> ]
Nivel de detección mínimo manual utilizado para determinar pulsos (-1.0 a -99.0).
[ -Y minsnr=<nivel dB> ]
SNR mínimo para determinar pulsos (1.0 a 99.0).
[ -Y autolevel ]
Establece minlevel automáticamente en base al ruido promedio estimado.
[ -Y squelch ]
Omite tramas por debajo del nivel de ruido estimado para reducir la carga de CPU.
[ -Y ampest | magest ]
Elige el estimador de nivel de amplitud o magnitud.

Opciones de análisis/depuración

[ -A ]
Analizador de Pulsos. Habilita el análisis de pulsos y el intento de decodificación.
Deshabilita todos los decodificadores con -R 0 si solo deseas la salida del analizador.
[ -y <código> ]
Verifica la decodificación de datos de prueba demodulados (ej. "{25}fb2dd58") con los dispositivos habilitados

Opciones de E/S de archivos

[ -S ninguno | todos | desconocido | conocido ]
Guardado automático de señal. Crea un archivo por señal.
Nota: Guarda muestras crudas de I/Q (pcm uint8, 2 canales). Modo preferido para generar archivos de prueba.
[ -r <nombre de archivo> | ayuda ]
Lee datos del archivo de entrada en lugar de un receptor
[ -w <nombre de archivo> | ayuda ]
Guarda el flujo de datos en un archivo de salida (un '-' vuelca las muestras a stdout)
[ -W <nombre de archivo> | ayuda ]
Guarda el flujo de datos en un archivo de salida, sobrescribe el archivo existente

Opciones de salida de datos

[ -F log | kv | json | csv | mqtt | influx | syslog | trigger | null | ayuda ]
Produce salida decodificada en el formato dado.
Agrega la salida a un archivo con :<nombre de archivo> (ej. -F csv:log.csv), por defecto es stdout.
Especifica host/puerto para syslog con ej. -F syslog:127.0.0.1:1514
[ -M tiempo[:<opciones>] | protocolo | nivel | ruido[:<secs>] | estadísticas | bits | ayuda ]
Agrega varios metadatos a cada salida.
[ -K ARCHIVO | RUTA | <etiqueta> | <clave>=<etiqueta> ]
Agrega un token expandido o una etiqueta fija a cada línea de salida.
[ -C nativo | si | costumbres ]
Convierte unidades en la salida decodificada.
[ -n <valor> ]
Especifica el número de muestras a tomar (cada muestra es un par I/Q)
[ -T <segundos> ]
Especifica el número de segundos de ejecución, también 12:34 o 1h23m45s
[ -E salto | salir ]
Salta/Sale después de emitir eventos exitosos
[ -h ]
Muestra esta ayuda de uso y sale
Usa -d, -g, -R, -X, -F, -M, -r, -w, o -W sin argumento para más ayuda

Selección del dispositivo de entrada

El controlador de dispositivo RTL-SDR está disponible.
[ -d <índice del dispositivo USB RTL-SDR> ]
(por defecto: 0)
[ -d :<serial del dispositivo USB RTL-SDR (se puede configurar con rtl_eeprom -s)> ]
Para establecer la ganancia para RTL-SDR, usa -g <ganancia> para establecer una ganancia general en dB.
El controlador de dispositivo SoapySDR está disponible.
[ -d "" ]
Abre el dispositivo SoapySDR por defecto
[ -d driver=rtlsdr ]
Abre, por ejemplo, un dispositivo SoapySDR específico
Para establecer la ganancia para SoapySDR, usa -g ELEMT=valor,ELEMT=valor,... ej. -g LNA=20,TIA=8,PGA=2 (para LimeSDR).
[ -d rtl_tcp[:[//]host[:puerto] ]
(por defecto: localhost:1234)
Especifica el host/puerto al que conectarse con ej. -d rtl_tcp:127.0.0.1:1234

Opción de ganancia

[ -g <ganancia> ]
(por defecto: auto)
Para RTL-SDR: ganancia en dB ("0" es automático).
Para SoapySDR: ganancia en dB para distribución automática ("" es automático), o cadena de elementos de ganancia.
Ej. "LNA=20,TIA=8,PGA=2" para LimeSDR.

Especificación de decodificador flexible

Usa -X <espec> para agregar un decodificador flexible de propósito general.

<espec> es "clave=valor[,clave=valor...]" Las claves comunes son:

nombre=<nombre> (o: n=<nombre>)
modulación=

NAME

rtl_433 - list of supported devices and decoder options

SYNOPSIS

rtl_433 [-h|-l] [-a|-A] [-d device] [-g gain] [-f frequency] [-s samplerate] [-p ppm] [-t] [-Y opmod] [-X option] [-F format] [-M meta] [-r file] [-w file] [-W file] [decoder ...]

DESCRIPTION

rtl_433 is a tool to decode Radio Transmission from various Digital Devices Such as Weather stations, Remote controls, Sensors, etc. The list of supported devices is very long, and it is constantly being expanded.

This document lists the supported devices and explains the various command line options.

Device selection

At the end of the command line, you can specify one or more device names to decode. If no device name is supplied, all supported devices are tried.

E.g. to only decode the National Weather Channel devices:

rtl_433 -F kv NWS

To decode multiple devices:

rtl_433 -F kv Acurite Temp/Humid OregonScientific THGN132DP BTS207

The names are case-insensitive. You can use parts of the name, and it will match multiple devices. To get a full list of device names use `rtl_433 -V`.

Command line options

[ -h | -l ]
Print a list of supported devices and exit.
[ -a | -A ]
Enable automatic detection of supported devices.
[ -d device ]
Use specified RTL-SDR device.
[ -g gain ]
Set tuner gain. Use -g ? to list available gains for the device.
[ -f frequency ]
Set center frequency.
[ -s samplerate ]
Set sample rate.
[ -p ppm ]
Set tuner frequency correction (PPM).
[ -t ]
Test mode, print message counts.
[ -Y opmod ]
Select digital demodulation mode. Supported options are:
amplitude
AM demodulation (default)
askem
Amplitude shift keying demodulation
fsk
Frequency shift keying demodulation
ook
On-off keying demodulation

Decoder option

[ -X option ... ]
Specify decoder specific options. The first option may be a short name for the decoder, or a general name like `modulation`. When multiple options are specified, they are ORed.
Each option can be specified by its full name or a short name.
General options:
modulation=<modulation>
(or: m=<modulation>)
short=<short>
(or: s=<short>)
long=<long>
(or: l=<long>)
sync=<sync>
(or: y=<sync>)
reset=<reset>
(or: r=<reset>)
gap=<gap>
(or: g=<gap>)
tolerance=<tolerance>
(or: t=<tolerance>)
priority=<n> : run decoder only as fallback
where: <name> can be any descriptive name tag you need in the output
<modulation> is one of:
OOK_MC_ZEROBIT : Manchester Code with fixed leading zero
bit
OOK_PCM : Non Return to Zero coding (Pulse Code)
OOK_RZ : Return to Zero coding (Pulse Code)
OOK_PPM : Pulse Position Modulation
OOK_PWM : Pulse Width Modulation
OOK_DMC : Differential Manchester Code
OOK_PIWM_RAW : Raw Pulse Interval and Width
Modulation
OOK_PIWM_DC : Differential Pulse Interval and Width
Modulation
OOK_MC_OSV1 : Manchester Code for OSv1 devices
FSK_PCM : FSK Pulse Code Modulation
FSK_PWM : FSK Pulse Width Modulation
FSK_MC_ZEROBIT : Manchester Code with fixed leading zero
bit
<short>, <long>, <sync> are nominal modulation timings in us,
<reset>, <gap>, <tolerance> are maximum modulation timings
in us: PCM/RZ short: Nominal width of pulse [us]

long: Nominal width of bit period [us] PPM short: Nominal width of '0' gap [us]

long: Nominal width of '1' gap [us] PWM short: Nominal width of '1' pulse [us]

long: Nominal width of '0' pulse [us]

sync: Nominal width of sync pulse [us] (optional) common gap: Maximum gap size
before new row of bits [us]

reset: Maximum gap size before End Of Message [us]

tolerance: Maximum pulse deviation [us] (optional). Available options are:
bits=<n> : only match if at least one row has
<n> bits
rows=<n> : only match if there are <n> rows
repeats=<n> : only match if some row is repeated
<n> times
use opt>=n to match at least <n> and opt<=n to match at most <n>
invert : invert all bits
reflect : reflect each byte (MSB first to MSB last)
decode_uart : UART 8n1 (10-to-8) decode
decode_dm : Differential Manchester decode
match=<bits> : only match if the <bits> are
found
preamble=<bits> : match and align at the
<bits> preamble
<bits> is a row spec of {<bit
count>}<bits as hex number>
unique : suppress duplicate row output
countonly : suppress detailed row output

E.g. -X "n=doorbell,m=OOK_PWM,s=400,l=800,r=7000,g=1000,match={24}0xa9878c,repeats>=3"

Output format option

[ -F log|kv|json|csv|mqtt|influx|syslog|trigger|null ]
Produce decoded output in given format.
Without this option the default is LOG and KV output. Use "-F null" to remove the default.
Append output to file with :<filename> (e.g. -F csv:log.csv), defaults to stdout.
Specify MQTT server with e.g. -F mqtt://localhost:1883
Default user and password are read from MQTT_USERNAME and MQTT_PASSWORD env vars.
Add MQTT options with e.g. -F "mqtt://host:1883,opt=arg"
MQTT options are: user=foo, pass=bar, retain[=0|1], <format>[=topic]
Supported MQTT formats: (default is all)

events: posts JSON event data, default "<base>/events"

states: posts JSON state data, default "<base>/states"

devices: posts device and sensor info in nested topics,

default "<base>/devices[/type][/model][/subtype][/channel][/id]"
A base topic can be set with base=<topic>, default is "<rtl_433>/HOSTNAME".
Any topic string overrides the base topic and will expand keys like [/model]
E.g. -F "mqtt://localhost:1883,user=USERNAME,pass=PASSWORD,retain=0,devices=rtl_433[/id]"
With MQTT each rtl_433 instance needs a distinct driver selection. The MQTT Client-ID is computed from the driver string.
If you use multiple RTL-SDR, perhaps set a serial and select by that (helps not to get the wrong antenna).
Specify InfluxDB 2.0 server with e.g. -F "influx://localhost:9999/api/v2/write?org=<org>&bucket=<bucket>,token=<authtoken>"
Specify InfluxDB 1.x server with e.g. -F "influx://localhost:8086/write?db=<db>&p=<password>&u=<user>"

Additional parameter -M time:unix:usec:utc for correct timestamps in InfluxDB recommended
Specify host/port for syslog with e.g. -F syslog:127.0.0.1:1514

Meta information option

[ -M time[:<options>]|protocol|level|noise[:<secs>]|stats|bits ]
Add various metadata to every output line.
Use "time" to add current date and time meta data (preset for live inputs).
Use "time:rel" to add sample position meta data (preset for read-file and stdin).
Use "time:unix" to show the seconds since unix epoch as time meta data. This is always UTC.
Use "time:iso" to show the time with ISO-8601 format (YYYY-MM-DD"T"hh:mm:ss).
Use "time:off" to remove time meta data.
Use "time:usec" to add microseconds to date time meta data.
Use "time:tz" to output time with timezone offset.
Use "time:utc" to output time in UTC.
(this may also be accomplished by invocation with TZ environment variable set).
"usec" and "utc" can be combined with other options, eg. "time:iso:utc" or "time:unix:usec".
Use "replay[:N]" to replay file inputs at (N-times) realtime.
Use "protocol" / "noprotocol" to output the decoder protocol number meta data.
Use "level" to add Modulation, Frequency, RSSI, SNR, and Noise meta data.
Use "noise[:<secs>]" to report estimated noise level at intervals (default: 10 seconds).
Use "stats[:[<level>][:<interval>]]" to report statistics (default: 600 seconds).

level 0: no report, 1: report successful devices, 2: report active devices, 3: report all
Use "bits" to add bit representation to code outputs (for debug).

Read file option

[ -r <filename> ]
Read data from input file instead of a receiver
Parameters are detected from the full path, file name, and extension.
A center frequency is detected as (fractional) number suffixed with 'M',

'Hz', 'kHz', 'MHz', or 'GHz'.
A sample rate is detected as (fractional) number suffixed with 'k',

'sps', 'ksps', 'Msps', or 'Gsps'.
File content and format are detected as parameters, possible options are:

'cu8', 'cs16', 'cf32' ('IQ' implied), and 'am.s16'.
Parameters must be separated by non-alphanumeric chars and are case-insensitive.
Overrides can be prefixed, separated by colon (':')
E.g. default detection by extension: path/filename.am.s16
forced overrides: am:s16:path/filename.ext
Reading from pipes also support format options.
E.g reading complex 32-bit float: CU32:-

Write file option

[ -w <filename> ]
Save data stream to output file (a '-' dumps samples to stdout)
[ -W <filename> ]
Save data stream to output file, overwrite existing file
Parameters are detected from the full path, file name, and extension.
File content and format are detected as parameters, possible options are:

'cu8', 'cs8', 'cs16', 'cf32' ('IQ' implied),

'am.s16', 'am.f32', 'fm.s16', 'fm.f32',

'i.f32', 'q.f32', 'logic.u8', 'ook', and 'vcd'.
Parameters must be separated by non-alphanumeric chars and are case-insensitive.
Overrides can be prefixed, separated by colon (':')
E.g. default detection by extension: path/filename.am.s16
forced overrides: am:s16:path/filename.ext
