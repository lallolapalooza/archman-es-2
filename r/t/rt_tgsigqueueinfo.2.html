rt_sigqueueinfo(2) Manual de llamadas al sistema rt_sigqueueinfo(2)

NOMBRE

rt_sigqueueinfo, rt_tgsigqueueinfo - encolar una señal y datos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/signal.h>     /* Definición de las constantes SI_* */
#include <sys/syscall.h>      /* Definición de las constantes SYS_* */
#include <unistd.h>
int syscall(SYS_rt_sigqueueinfo, pid_t tgid,
            int sig, siginfo_t *info);
int syscall(SYS_rt_tgsigqueueinfo, pid_t tgid, pid_t tid,
            int sig, siginfo_t *info);

Nota: No hay envoltorios de glibc para estas llamadas al sistema; consulte NOTAS.

DESCRIPCIÓN

Las llamadas al sistema rt_sigqueueinfo() y rt_tgsigqueueinfo() son las interfaces de bajo nivel utilizadas para enviar una señal más datos a un proceso o hilo. El receptor de la señal puede obtener los datos adjuntos estableciendo un manejador de señales con la bandera SA_SIGINFO de sigaction(2).

Estas llamadas al sistema no están destinadas a un uso directo por parte de las aplicaciones; se proporcionan para permitir la implementación de sigqueue(3) y pthread_sigqueue(3).

La llamada al sistema rt_sigqueueinfo() envía la señal sig al grupo de hilos con el ID tgid. (El término "grupo de hilos" es sinónimo de "proceso", y tgid corresponde al ID de proceso tradicional de UNIX.) La señal se entregará a un miembro arbitrario del grupo de hilos (es decir, uno de los hilos que no esté bloqueando actualmente la señal).

El argumento info especifica los datos que acompañan a la señal. Este argumento es un puntero a una estructura de tipo siginfo_t, descrita en sigaction(2) (y definida al incluir <sigaction.h>). El llamante debe establecer los siguientes campos en esta estructura:

si_codigo
Debe ser uno de los códigos SI_* en el archivo fuente del kernel de Linux include/asm-generic/siginfo.h. Si la señal se está enviando a un proceso distinto del propio llamante, se aplican las siguientes restricciones:
•
El código no puede ser un valor mayor o igual a cero. En particular, no puede ser SI_USER, que es utilizado por el kernel para indicar una señal enviada por kill(2), ni tampoco puede ser SI_KERNEL, que se utiliza para indicar una señal generada por el kernel.
•
El código no puede (desde Linux 2.6.39) ser SI_TKILL, que se utiliza por el kernel para indicar una señal enviada utilizando tgkill(2).
si_pid
Debe establecerse en un ID de proceso, típicamente el ID de proceso del remitente.
si_uid
Debe establecerse en un ID de usuario, típicamente el ID de usuario real del remitente.
si_valor
Este campo contiene los datos del usuario que acompañan a la señal. Para más información, consulte la descripción del último argumento (union sigval) de sigqueue(3).

Internamente, el kernel establece el campo si_signo en el valor especificado en sig, de modo que el receptor de la señal también pueda obtener el número de señal a través de ese campo.

La llamada al sistema rt_tgsigqueueinfo() es similar a rt_sigqueueinfo(), pero envía la señal y los datos al único hilo especificado por la combinación de tgid, un ID de grupo de hilos, y tid, un hilo en ese grupo de hilos.

VALOR DE RETORNO

En caso de éxito, estas llamadas al sistema devuelven 0. En caso de error, devuelven -1 y se establece errno para indicar el error.

ERRORES

EAGAIN
Se ha alcanzado el límite de señales que pueden encolarse. (Consulte signal(7) para más información.)
EINVAL
sig, tgid o tid no eran válidos.
EPERM
El llamante no tiene permiso para enviar la señal al destino. Para los permisos requeridos, consulte kill(2).
EPERM
tgid especifica un proceso distinto del llamante y info->si_codigo es inválido.
ESRCH
rt_sigqueueinfo(): No se encontró ningún grupo de hilos que coincidiera con tgid.

rt_tgsigqueinfo(): No se encontró ningún hilo que coincidiera con tgid y tid.

ESTANDARES

Linux.

HISTORIA

rt_sigqueueinfo()
Linux 2.2.
rt_tgsigqueueinfo()
Linux 2.6.31.

NOTAS

Dado que estas llamadas al sistema no están destinadas al uso por parte de las aplicaciones, no existen funciones envoltorio en glibc; utilice syscall(2) en el improbable caso de que desee llamarlas directamente.

Al igual que con kill(2), se puede utilizar la señal nula (0) para comprobar si el proceso o hilo especificado existe.

VER TAMBIÉN
