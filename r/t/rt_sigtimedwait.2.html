sigwaitinfo(2) Manual de Llamadas al Sistema sigwaitinfo(2)

NOMBRE

sigwaitinfo, sigtimedwait, rt_sigtimedwait - esperar síncronamente señales en cola

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <signal.h>
int sigwaitinfo(const sigset_t *restrict set,
                siginfo_t *_Nullable restrict info);
int sigtimedwait(const sigset_t *restrict set,
                siginfo_t *_Nullable restrict info,
                const struct timespec *restrict timeout);
Requisitos de Macro de Prueba de Funcionalidad para glibc (ver feature_test_macros(7)):

sigwaitinfo(), sigtimedwait():

    _POSIX_C_SOURCE >= 199309L

DESCRIPCIÓN

sigwaitinfo() suspende la ejecución del hilo actual hasta que una de las señales en set esté pendiente (Si una de las señales en set ya está pendiente para el hilo actual, sigwaitinfo() retornará inmediatamente.)

sigwaitinfo() elimina la señal del conjunto de señales pendientes y devuelve el número de señal como resultado de la función. Si el argumento info no es NULL, entonces el buffer al que apunta se utiliza para devolver una estructura de tipo siginfo_t (ver sigaction(2)) que contiene información sobre la señal.

Si varias señales en set están pendientes para el llamador, la señal que se recupera mediante sigwaitinfo() se determina según las reglas de ordenación habituales; ver signal(7) para más detalles.

sigtimedwait() funciona exactamente igual que sigwaitinfo() excepto que tiene un argumento adicional, timeout, que especifica el intervalo durante el cual el hilo se suspende esperando una señal. (Este intervalo se redondeará al alza a la granularidad del reloj del sistema, y los retrasos de planificación del núcleo pueden hacer que el intervalo se exceda en una pequeña cantidad.) Este argumento es una estructura timespec(3).

Si ambos campos de esta estructura se especifican como 0, se realiza una sondeo: sigtimedwait() retorna inmediatamente, ya sea con información sobre una señal que estaba pendiente para el llamador, o con un error si ninguna de las señales en set estaba pendiente.

VALOR DE RETORNO

En caso de éxito, tanto sigwaitinfo() como sigtimedwait() devuelven un número de señal (es decir, un valor mayor que cero). En caso de error, ambas llamadas devuelven -1, con errno establecido para indicar el error.

ERRORES

EAGAIN
Ninguna señal en set se volvió pendiente dentro del período timeout especificado para sigtimedwait().
EINTR
La espera fue interrumpida por un manejador de señales; ver signal(7). (Este manejador era para una señal distinta de las de set.)
EINVAL
timeout no era válido.

VERSIONES

Diferencias biblioteca C/núcleo

En Linux, sigwaitinfo() es una función de biblioteca implementada sobre sigtimedwait().

Las funciones de envoltura de glibc para sigwaitinfo() y sigtimedwait() ignoran silenciosamente los intentos de esperar las dos señales de tiempo real que se usan internamente en la implementación de hilos de NPTL. Ver nptl(7) para detalles.

La llamada al sistema original de Linux se llamaba sigtimedwait(). Sin embargo, con la adición de señales de tiempo real en Linux 2.2, el tipo sigset_t de tamaño fijo y 32 bits soportado por esa llamada al sistema ya no era adecuado. En consecuencia, se añadió una nueva llamada al sistema, rt_sigtimedwait(), para soportar un tipo sigset_t ampliado. La nueva llamada al sistema toma un cuarto argumento, size_t sigsetsize, que especifica el tamaño en bytes del conjunto de señales en set. Actualmente se requiere que este argumento tenga el valor sizeof(sigset_t) (o se produce el error EINVAL). La función de envoltura sigtimedwait() de glibc oculta estos detalles, llamando transparentemente a rt_sigtimedwait() cuando el núcleo la proporciona.

ESTÁNDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2001.

NOTAS

En uso normal, el programa que llama bloquea las señales en set mediante una llamada previa a sigprocmask(2) (para que la disposición predeterminada para estas señales no ocurra si se vuelven pendientes entre llamadas sucesivas a sigwaitinfo() o sigtimedwait()) y no establece manejadores para estas señales. En un programa multihilo, la señal debe bloquearse en todos los hilos, para evitar que la señal se trate según su disposición predeterminada en un hilo distinto al que llama a sigwaitinfo() o sigtimedwait().

El conjunto de señales que está pendiente para un hilo dado es la unión del conjunto de señales que está pendiente específicamente para ese hilo y el conjunto de señales que está pendiente para el proceso en su conjunto (ver signal(7)).

Los intentos de esperar SIGKILL y SIGSTOP se ignoran silenciosamente.

Si varios hilos de un proceso están bloqueados esperando la(s) misma(s) señal(es) en sigwaitinfo() o sigtimedwait(), entonces exactamente uno de los hilos recibirá la señal si se vuelve pendiente para el proceso en su conjunto; cuál de los hilos recibe la señal es indeterminado.

sigwaitinfo() o sigtimedwait(), no se pueden usar para recibir señales que se generan de forma síncrona, como la señal SIGSEGV que resulta de acceder a una dirección de memoria inválida o la señal SIGFPE que resulta de un error aritmético. Dichas señales solo pueden ser capturadas mediante un manejador de señales.

POSIX deja sin especificar el significado de un valor NULL para el argumento timeout de sigtimedwait(), permitiendo la posibilidad de que esto tenga el mismo significado que una llamada a sigwaitinfo(), y de hecho esto es lo que se hace en Linux.
