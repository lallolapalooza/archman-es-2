NOMBRE

rtmpgw - pasarela de transmisión de medios RTMP

SINOPSIS

rtmpgw [-r url] [-n nombrehost] [-c puerto] [-l protocolo] [-S host:puerto] [-a app] [-t tcUrl] [-p pageUrl] [-s swfUrl] [-f flashVer] [-u auth] [-C conndata] [-y playpath] [-v] [-d suscripcion] [-e] [-k saltar] [-A inicio] [-B fin] [-b buffer] [-m timeout] [-T clave] [-j JSON] [-w swfHash] [-x swfSize] [-W swfUrl] [-X swfAge] [-D direccion] [-g puerto] [-q] [-V] [-z]
rtmpgw -h

DESCRIPCIÓN

rtmpgw es un servidor para transmitir contenido multimedia de RTMP a HTTP.

rtmpgw escucha las solicitudes HTTP que especifican parámetros de transmisión RTMP y luego devuelve los datos RTMP en la respuesta HTTP. La única solicitud HTTP válida es "GET /" pero se pueden proporcionar opciones adicionales en formato codificado en URL. Las opciones especificadas en la línea de comandos se usarán como valores predeterminados, que pueden ser sobrescritas por opciones en la solicitud HTTP.

OPCIONES

Parámetros de Red

Estas opciones definen cómo conectarse al servidor de medios.

--rtmp -r url
URL del servidor y del contenido multimedia.
--host -n nombrehost
Sobrescribe el nombre de host en la URL RTMP.
--port -c puerto
Sobrescribe el número de puerto en la URL RTMP.
--protocol -l número
Sobrescribe el protocolo en la URL RTMP. 
  0 = rtmp
  1 = rtmpt
  2 = rtmpe
  3 = rtmpte
  4 = rtmps
  5 = rtmpts
--socks -S host:puerto
Utiliza el proxy SOCKS4 especificado.

Parámetros de Conexión

Estas opciones definen el contenido del paquete RTMP Connect request. Si no se proporcionan los valores correctos, el servidor de medios rechazará el intento de conexión.

--app -a app
Nombre de la aplicación a la que conectarse en el servidor RTMP. Sobrescribe la aplicación en la URL RTMP. A veces, el analizador de URL de rtmpdump no puede determinar el nombre de la aplicación automáticamente, por lo que debe proporcionarse explícitamente usando esta opción.
--tcUrl -t url
URL de la transmisión de destino. Por defecto es rtmp[e]://host[:puerto]/app/playpath.
--pageUrl -p url
URL de la página web en la que se incrustaron los medios. Por defecto no se enviará ningún valor.
--swfUrl -s url
URL del reproductor SWF para los medios. Por defecto no se enviará ningún valor.
--flashVer -f versión
Versión del plugin Flash utilizada para ejecutar el reproductor SWF. El valor predeterminado es "LNX 10,0,32,18".
--auth -u cadena
Una cadena de autenticación que se añadirá al mensaje Connect. Usar esta opción añadirá un booleano TRUE y luego la cadena especificada. Esta opción solo la usan algunos servidores particulares y está obsoleta. Debería usarse la opción --conn más general en su lugar.
--conn -C tipo:datos
Añade datos AMF arbitrarios al mensaje Connect. El tipo debe ser B para Booleano, N para número, S para cadena, O para objeto, o Z para nulo. Para Booleanos, los datos deben ser 0 o 1 para FALSO o VERDADERO, respectivamente. Igualmente, para Objetos, los datos deben ser 0 o 1 para finalizar o iniciar un objeto, respectivamente. Los elementos de datos en subobjetos pueden tener nombre, prefijando el tipo con 'N' y especificando el nombre antes del valor, por ejemplo, NB:miBandera:1. Esta opción se puede usar varias veces para construir secuencias AMF arbitrarias. Por ejemplo: 
  -C B:1 -C S:authMe -C O:1 -C NN:code:1.23 -C NS:flag:ok -C O:0

Parámetros de Sesión

Estas opciones surten efecto después de que la solicitud Connect se haya realizado con éxito.

--playpath -y ruta
Sobrescribe el playpath analizado de la URL RTMP. A veces, el analizador de URL de rtmpdump no puede determinar el playpath correcto automáticamente, por lo que debe proporcionarse explícitamente usando esta opción.
--live -v
Especifica que los medios son una transmisión en vivo. No es posible reanudar ni buscar en transmisiones en vivo.
--subscribe -d transmisión
Nombre de la transmisión en vivo a la que suscribirse. Por defecto es playpath.
--start -A num
Comenzar en el segundo num de la transmisión. No es válido para transmisiones en vivo.
--stop -B num
Detener en el segundo num de la transmisión.
--buffer -b num
Establece el tiempo de búfer en num milisegundos. El valor predeterminado es 20000.
--timeout -m num
Tiempo de espera de la sesión después de num segundos sin recibir datos del servidor. El valor predeterminado es 120.

Parámetros de Seguridad

Estas opciones manejan solicitudes de autenticación adicionales del servidor.

--token -T clave
Clave para la respuesta SecureToken, utilizada si el servidor requiere autenticación SecureToken.
--jtv -j JSON
Token JSON utilizado por los servidores legacy de Justin.tv. Invoca NetStream.Authenticate.UsherToken
--swfhash -w cadenahex
Hash SHA256 del archivo SWF descomprimido. Esta opción puede ser necesaria si el servidor utiliza Verificación SWF, pero consulte la opción --swfVfy a continuación. El hash es de 32 bytes y debe proporcionarse en hexadecimal. La opción --swfsize siempre debe usarse con esta opción.
--swfsize -x num
Tamaño del archivo SWF descomprimido. Esta opción puede ser necesaria si el servidor utiliza Verificación SWF, pero consulte la opción --swfVfy a continuación. La opción --swfhash siempre debe usarse con esta opción.
--swfVfy -W url
URL del reproductor SWF para estos medios. Esta opción reemplaza las tres opciones --swfUrl, --swfhash y --swfsize. Cuando se usa esta opción, el reproductor SWF se recupera de la URL especificada y el hash y el tamaño se calculan automáticamente. La información también se almacena en caché en un archivo .swfinfo en el directorio de inicio del usuario, por lo que no necesita ser recuperada y recalculada cada vez que se ejecuta rtmpdump. El archivo .swfinfo registra la URL, la hora de obtención, la marca de tiempo de modificación del archivo SWF, su tamaño y su hash. Por defecto, la información en caché se utilizará durante 30 días antes de volver a verificar.
--swfAge -X días
Especifica cuántos días usar la información SWF en caché antes de volver a verificar. Use 0 para siempre

NAME

rtmpproxy, rtmpgw

RTMP proxy

SYNOPSIS

rtmpproxy

[-h] [-a address] [-p port] [-l host] [-t port] [-d] [-v] [-z]

rtmpgwd

[-h] [-a address] [-p port] [-l host] [-t port] [-d] [-v] [-z]

DESCRIPTION

rtmpproxy is an RTMP proxy. It listens for RTMP connections on a given address and port, and forwards them to another RTMP server. This can be useful for various purposes, such as caching, filtering, or modifying RTMP streams.

rtmpgwd is a daemonized version of rtmpproxy. It runs in the background and handles RTMP connections.

The proxy can be configured to either forward the connection to a specific server and port, or to use the information provided by the client to determine the server and port.

The proxy can also be configured to cache SWF verification information to speed up subsequent connections to the same server. This cached information is stored in the $HOME/.swfinfo file.

The proxy supports both RTMP and RTMPE protocols.

OPTIONS

-h
Print a summary of command options.
-a address
The IP address to listen on. Defaults to 0.0.0.0 (any address).
-p port
The port to listen on. Defaults to 1935.
-l host
The hostname or IP address of the target RTMP server. If not specified, the proxy will try to determine the target server from the client's request.
-t port
The port of the target RTMP server. Defaults to 1935.
-d
Run as a daemon. This option is only available for rtmpgwd.
-v
Enable verbose output. This will print more detailed information about the proxy's activity.
-z
Enable debug output. This will print extremely verbose output, including hex dumps of all packet data.

EXAMPLES

To run rtmpproxy on all interfaces, listening on port 1935, and forwarding connections to rtmp://example.com:1935:

rtmpproxy -a 0.0.0.0 -p 1935 -l example.com -t 1935

To run rtmpproxy as a daemon, listening on port 8080, and forwarding connections to rtmp://localhost:1935:

rtmpgwd -p 8080 -l localhost -t 1935

FILES

$HOME/.swfinfo
Cache of SWF verification information.
