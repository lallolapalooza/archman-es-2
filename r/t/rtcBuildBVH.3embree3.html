rtcBuildBVH(3) Núcleos de trazado de rayos Embree 3 rtcBuildBVH(3)

NOMBRE

rtcBuildBVH - construye un BVH

SINOPSIS

#include <embree3/rtcore.h>
struct RTC_ALIGN(32) RTCBuildPrimitive
{
  float lower_x, lower_y, lower_z; 
  unsigned int geomID;
  float upper_x, upper_y, upper_z;
  unsigned int primID;
};
typedef void* (*RTCCreateNodeFunction) (
  RTCThreadLocalAllocator allocator,
  unsigned int childCount,
  void* userPtr
);
typedef void (*RTCSetNodeChildrenFunction) (
  void* nodePtr,
  void** children,
  unsigned int childCount,
  void* userPtr
);
typedef void (*RTCSetNodeBoundsFunction) (
  void* nodePtr,
  const struct RTCBounds** bounds,
  unsigned int childCount,
  void* userPtr
);
typedef void* (*RTCCreateLeafFunction) (
  RTCThreadLocalAllocator allocator,
  const struct RTCBuildPrimitive* primitives,
  size_t primitiveCount,
  void* userPtr
);
typedef void (*RTCSplitPrimitiveFunction) (
  const struct RTCBuildPrimitive* primitive,
  unsigned int dimension,
  float position,
  struct RTCBounds* leftBounds,
  struct RTCBounds* rightBounds,
  void* userPtr
);
typedef bool (*RTCProgressMonitorFunction)(
  void* userPtr, double n
);
enum RTCBuildFlags
{
  RTC_BUILD_FLAG_NONE,
  RTC_BUILD_FLAG_DYNAMIC
};
struct RTCBuildArguments
{
  size_t byteSize;
  enum RTCBuildQuality buildQuality;
  enum RTCBuildFlags buildFlags;
  unsigned int maxBranchingFactor;
  unsigned int maxDepth;
  unsigned int sahBlockSize;
  unsigned int minLeafSize;
  unsigned int maxLeafSize;
  float traversalCost;
  float intersectionCost;
  RTCBVH bvh;
  struct RTCBuildPrimitive* primitives;
  size_t primitiveCount;
  size_t primitiveArrayCapacity;
  RTCCreateNodeFunction createNode;
  RTCSetNodeChildrenFunction setNodeChildren;
  RTCSetNodeBoundsFunction setNodeBounds;
  RTCCreateLeafFunction createLeaf;
  RTCSplitPrimitiveFunction splitPrimitive;
  RTCProgressMonitorFunction buildProgress;
  void* userPtr;
};
struct RTCBuildArguments rtcDefaultBuildArguments();
void* rtcBuildBVH(
  const struct RTCBuildArguments* args
);

DESCRIPCIÓN

La función rtcBuildBVH se puede utilizar para construir un BVH en un formato definido por el usuario sobre primitivas arbitrarias. Todos los argumentos de la función se proporcionan a través de la estructura RTCBuildArguments. El primer miembro de esa estructura debe establecerse en el tamaño de la estructura en bytes (miembro byteSize) lo que permite extensiones futuras de la estructura. Se recomienda inicializar la estructura de argumentos de compilación utilizando la función rtcDefaultBuildArguments.

La función rtcBuildBVH recibe el BVH a construir (miembro bvh), el array de primitivas (miembro primitives), la capacidad de ese array (miembro primitiveArrayCapacity), el número de primitivas almacenadas dentro del array (miembro primitiveCount), punteros de función de devolución de llamada y un puntero definido por el usuario (miembro userPtr) que se pasa a todas las funciones de devolución de llamada cuando se invocan. La aplicación puede liberar el array de primitivas después de que se haya construido el BVH. Todas las funciones de devolución de llamada se llaman típicamente desde múltiples hilos, por lo que su implementación debe ser segura para subprocesos.

Se deben registrar cuatro funciones de devolución de llamada, que se invocan durante la compilación para crear nodos BVH (miembro createNode), para establecer los punteros a todos los hijos (miembro setNodeChildren), para establecer los cuadros delimitadores de todos los hijos (miembro setNodeBounds), y para crear un nodo hoja (miembro createLeaf).

El puntero de función a la función de división de primitivas (miembro splitPrimitive) puede ser NULL, sin embargo, entonces no es posible realizar divisiones espaciales en modo de alta calidad. El puntero de función utilizado para informar el progreso de la compilación (miembro buildProgress) es opcional y también puede ser NULL.

Además, se pasan algunas configuraciones de compilación para configurar la compilación del BVH. Utilizando las configuraciones de calidad de compilación (miembro buildQuality), se puede elegir entre una compilación rápida de baja calidad que es buena para escenas dinámicas y una compilación de calidad estándar para escenas estáticas. También se puede especificar el factor de ramificación máximo deseado del BVH (miembro maxBranchingFactor), la profundidad máxima que debe tener el BVH (miembro maxDepth), el tamaño del bloque para la heurística SAH (miembro sahBlockSize), el tamaño mínimo y máximo de la hoja (miembros minLeafSize y maxLeafSize), y los costos estimados de un paso de recorrido y una intersección de primitiva (miembros traversalCost y intersectionCost). Al habilitar las banderas de compilación RTC_BUILD_FLAG_DYNAMIC (miembro buildFlags), el rendimiento de la recompilación para escenas dinámicas mejora a costa de mayores requisitos de memoria.

Para dividir espacialmente las primitivas en modo de alta calidad, el constructor necesita espacio adicional al final del array de primitivas de compilación para almacenar las primitivas divididas. La capacidad total del array de primitivas de compilación se pasa utilizando el miembro primitiveArrayCapacity, y debe ser aproximadamente el doble del número de primitivas cuando se utilizan divisiones espaciales.

Las devoluciones de llamada RTCCreateNodeFunc y RTCCreateLeafFunc reciben un objeto asignador local de hilo que debe usarse para la asignación rápida de nodos utilizando la función rtcThreadLocalAlloc. Recomendamos encarecidamente el uso de este mecanismo de asignación, ya que enfoques alternativos como malloc estándar pueden ser más de 10 veces más lentos. El objeto asignador pasado a las devoluciones de llamada de creación solo puede usarse dentro del hilo actual. La memoria asignada usando rtcThreadLocalAlloc se libera automáticamente cuando se elimina el objeto RTCBVH. Si utiliza su propio esquema de asignación de memoria, debe liberar la memoria usted mismo cuando el objeto RTCBVH ya no se utilice.

La devolución de llamada RTCCreateNodeFunc recibe adicionalmente el número de hijos para este nodo en el rango de 2 a maxBranchingFactor (argumento childCount).

La función de devolución de llamada RTCSetNodeChildFunc recibe un puntero al nodo como entrada (argumento nodePtr), un array de punteros a los hijos (argumento childPtrs), y el tamaño de este array (argumento childCount).

La función de devolución de llamada RTCSetNodeBoundsFunc recibe un puntero al nodo como entrada (argumento nodePtr), un array de punteros a los cuadros delimitadores de los hijos (argumento bounds), y el tamaño de este array (argumento childCount).

La devolución de llamada RTCCreateLeafFunc recibe adicionalmente un array de primitivas como entrada (argumento primitives), y el tamaño de este array (argumento primitiveCount). La devolución de llamada debe leer los miembros geomID y primID de las primitivas pasadas para construir la hoja.

La devolución de llamada RTCSplitPrimitiveFunc se invoca en modo de alta calidad para dividir una primitiva (argumento primitive) en la posición especificada (argumento position) y dimensión (argumento dimension). La devolución de llamada debe devolver los límites de las partes izquierda y derecha recortadas de la primitiva (argumentos leftBounds y rightBounds).

La función de devolución de llamada RTCProgressMonitorFunction se llama con la tasa de finalización estimada n en el rango [0, 1]. Devolver verdadero de la devolución de llamada permite que la compilación continúe; devolver falso cancela la compilación.

ESTADO DE SALIDA

En caso de fallo, se establece un código de error que se puede consultar utilizando rtcGetDeviceError.
