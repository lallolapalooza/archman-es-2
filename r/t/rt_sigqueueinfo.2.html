rt_sigqueueinfo(2) Manual de Llamadas al Sistema rt_sigqueueinfo(2)

NOMBRE

rt_sigqueueinfo, rt_tgsigqueueinfo - encolar una señal y datos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/signal.h>     /* Definición de constantes SI_* */
#include <sys/syscall.h>      /* Definición de constantes SYS_* */
#include <unistd.h>
int syscall(SYS_rt_sigqueueinfo, pid_t tgid,
            int sig, siginfo_t *info);
int syscall(SYS_rt_tgsigqueueinfo, pid_t tgid, pid_t tid,
            int sig, siginfo_t *info);

Nota: No hay envolturas de glibc para estas llamadas al sistema; ver NOTAS.

DESCRIPCIÓN

Las llamadas al sistema rt_sigqueueinfo() y rt_tgsigqueueinfo() son las interfaces de bajo nivel utilizadas para enviar una señal más datos a un proceso o hilo. El receptor de la señal puede obtener los datos adjuntos estableciendo un manejador de señales con la bandera SA_SIGINFO de sigaction(2).

Estas llamadas al sistema no están destinadas a un uso directo de las aplicaciones; se proporcionan para permitir la implementación de sigqueue(3) y pthread_sigqueue(3).

La llamada al sistema rt_sigqueueinfo() envía la señal sig al grupo de hilos con el ID tgid. (El término "grupo de hilos" es sinónimo de "proceso", y tgid corresponde al ID de proceso UNIX tradicional.) La señal se entregará a un miembro arbitrario del grupo de hilos (es decir, a uno de los hilos que no esté bloqueando actualmente la señal).

El argumento info especifica los datos que acompañan a la señal. Este argumento es un puntero a una estructura de tipo siginfo_t, descrita en sigaction(2) (y definida incluyendo <sigaction.h>). El llamante debe establecer los siguientes campos en esta estructura:

si_code
Debe ser uno de los códigos SI_* en el archivo fuente del kernel de Linux include/asm-generic/siginfo.h. Si la señal se está enviando a cualquier proceso que no sea el llamante, se aplican las siguientes restricciones:
•
El código no puede ser un valor mayor o igual a cero. En particular, no puede ser SI_USER, que es utilizado por el kernel para indicar una señal enviada por kill(2), ni puede ser SI_KERNEL, que se utiliza para indicar una señal generada por el kernel.
•
El código no puede (desde Linux 2.6.39) ser SI_TKILL, que es utilizado por el kernel para indicar una señal enviada usando tgkill(2).
si_pid
Debe establecerse en un ID de proceso, típicamente el ID de proceso del remitente.
si_uid
Debe establecerse en un ID de usuario, típicamente el ID de usuario real del remitente.
si_value
Este campo contiene los datos del usuario que acompañan a la señal. Para más información, vea la descripción del último argumento (union sigval) de sigqueue(3).

Internamente, el kernel establece el campo si_signo al valor especificado en sig, para que el receptor de la señal también pueda obtener el número de señal a través de ese campo.

La llamada al sistema rt_tgsigqueueinfo() es similar a rt_sigqueueinfo(), pero envía la señal y los datos al único hilo especificado por la combinación de tgid, un ID de grupo de hilos, y tid, un hilo en ese grupo de hilos.

VALOR DE RETORNO

En caso de éxito, estas llamadas al sistema devuelven 0. En caso de error, devuelven -1 y errno se establece para indicar el error.

ERRORES

EAGAIN
Se ha alcanzado el límite de señales que se pueden encolar. (Ver signal(7) para más información.)
EINVAL
sig, tgid, o tid no eran válidos.
EPERM
El llamante no tiene permiso para enviar la señal al destino. Para los permisos requeridos, ver kill(2).
EPERM
tgid especifica un proceso distinto del llamante y info->si_code no es válido.
ESRCH
rt_sigqueueinfo(): No se encontró ningún grupo de hilos que coincida con tgid.

rt_tgsigqueinfo(): No se encontró ningún hilo que coincida con tgid y tid.

ESTANDARES

Linux.

HISTORIA

rt_sigqueueinfo()
Linux 2.2.
rt_tgsigqueueinfo()
Linux 2.6.31.

NOTAS

Dado que estas llamadas al sistema no están destinadas al uso de aplicaciones, no hay funciones de envoltura de glibc; use syscall(2) en el improbable caso de que desee llamarlas directamente.

Al igual que con kill(2), la señal nula (0) se puede utilizar para verificar si el proceso o hilo especificado existe.

VER TAMBIÉN

kill(2), pidfd_send_signal(2), sigaction(2), sigprocmask(2), tgkill(2), pthread_sigqueue(3), sigqueue(3), signal(7)

rt_sigqueueinfo(2)

recibir una señal con información extendida

NAME

rt_sigqueueinfo - enviar una señal a un proceso o grupo de procesos con información extendida

SYNOPSIS


#include <signal.h>

int rt_sigqueueinfo(pid_t pid, int sig, siginfo_t *info);

DESCRIPTION

La llamada al sistema rt_sigqueueinfo envía la señal sig al proceso cuyo ID es pid. La señal se acompaña de la información extendida proporcionada por la estructura siginfo_t apuntada por info.

Si pid es 0, la señal se envía a todos los procesos del grupo de procesos del llamante.

Si pid es -1, la señal se envía a todos los procesos para los que el llamante tiene permiso de enviar señales (excepto al propio llamante).

Si pid es un valor negativo distinto de -1, la señal se envía al grupo de procesos cuyo ID es -pid.

RETURN VALUE

En caso de éxito, rt_sigqueueinfo devuelve 0. En caso de error, devuelve -1 y establece errno para indicar el error.

ERRORS

EINVAL
Se proporcionó un número de señal no válido.
ESRCH
El proceso especificado por pid no existe.
EPERM
El proceso que realiza la llamada no tiene permiso para enviar la señal al proceso de destino.

STANDARDS

rt_sigqueueinfo es parte de la interfaz de señales en tiempo real de POSIX, pero no está disponible en todas las plataformas.

HISTORY

La llamada al sistema rt_sigqueueinfo fue introducida en Linux 2.6.

NOTES

La estructura siginfo_t contiene información detallada sobre la señal, como el remitente, la causa de la señal y cualquier dato adicional asociado con ella. Para obtener más detalles sobre la estructura siginfo_t, consulte la página del manual sigaction(2).
