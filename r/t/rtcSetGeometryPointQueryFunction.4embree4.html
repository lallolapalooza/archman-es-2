NOMBRE

rtcSetGeometryPointQueryFunction - establece la función de callback de consulta de puntos para una geometría

SINOPSIS

#include <embree4/rtcore.h>
struct RTCPointQueryFunctionArguments
{
  // el objeto de consulta (en espacio de mundo) que se pasó como argumento de rtcPointQuery.
  struct RTCPointQuery* query;
  // se utiliza para datos de entrada/salida del usuario. No será leído ni modificado internamente.
  void* userPtr;
  // ID de primitiva y ID de geometría de la primitiva
  unsigned int  primID;        
  unsigned int  geomID;    
  // el contexto con la pila de transformaciones e IDs de instancia
  struct RTCPointQueryContext* context;
  // factor de escala que indica si la transformación de instancia actual
  // es una transformación de similitud.
  float similarityScale;
};
typedef bool (*RTCPointQueryFunction)(
  struct RTCPointQueryFunctionArguments* args
);
void rtcSetGeometryPointQueryFunction(
  RTCGeometry geometry,
  RTCPointQueryFunction queryFunc
);

DESCRIPCIÓN

La función rtcSetGeometryPointQueryFunction registra una función de callback de consulta de puntos (argumento queryFunc) para la geometría especificada (argumento geometry).

Solo se puede registrar una función de callback por geometría y las invocaciones posteriores sobrescriben la función de callback establecida previamente. Pasar NULL como puntero de función deshabilita la función de callback registrada.

La función de callback registrada es invocada por [rtcPointQuery] para cada primitiva de la geometría que intersecta el dominio de consulta de puntos correspondiente. La función de callback de tipo RTCPointQueryFunction recibe una serie de argumentos a través de la estructura RTCPointQueryFunctionArguments. El objeto de consulta es el objeto de consulta de puntos original pasado a [rtcPointQuery], usrPtr es un puntero arbitrario para pasar datos de entrada y almacenar resultados de la función de callback. Los primID, geomID y context (ver [rtcInitPointQueryContext] para más detalles) se pueden usar para identificar los datos de geometría de la primitiva.

Una RTCPointQueryFunction también se puede pasar directamente como argumento a [rtcPointQuery]. En este caso, la callback se invoca para todas las primitivas de la escena que intersectan el dominio de consulta. Si se pasa una función de callback como argumento a [rtcPointQuery] y se establece una función de callback (potencialmente diferente) para una geometría con [rtcSetGeometryPointQueryFunction], ambas funciones de callback se invocan y la función de callback pasada a [rtcPointQuery] se llamará antes que la función de callback específica de la geometría.

Si se utiliza instanciación, el parámetro simliarityScale indica si la transformación de instancia actual (elemento superior de la pila en context) es una transformación de similitud o no. Las transformaciones de similitud se componen de traslación, rotación y escalado uniforme y si una matriz M define una transformación de similitud, existe un factor de escala D tal que para todo x,y: dist(Mx, My) = D * dist(x, y). En este caso, el parámetro scalingFactor es este factor de escala D y de lo contrario es 0. Una escala de similitud válida (similarityScale > 0) permite calcular información de distancia en espacio de instancia y escalar las distancias al espacio de mundo (por ejemplo, para actualizar el radio de consulta, ver abajo) dividiendo la distancia en espacio de instancia por la escala de similitud. Si la transformación de instancia actual no es una transformación de similitud (similarityScale es 0), el cálculo de la distancia debe realizarse en espacio de mundo para garantizar la corrección. En este caso, se deben usar las transformaciones de instancia a mundo dadas con el contexto para transformar los datos de la primitiva al espacio de mundo. De lo contrario, la ubicación de la consulta se puede transformar al espacio de instancia, lo que puede ser más eficiente. Si no hay transformación de instancia, la escala de similitud es 1.

La función de callback se llamará potencialmente para primitivas fuera del dominio de consulta por dos razones: Primero, la callback se invoca para todas las primitivas dentro de un nodo hoja de BVH ya que no se determinan internamente los datos de geometría de las primitivas y, por lo tanto, las primitivas individuales no se descartan (solo sus cajas delimitadoras (agregadas)). Segundo, en caso de que se utilicen transformaciones no de similitud, el dominio de consulta elipsoidal resultante (en espacio de instancia) se aproxima internamente por su caja delimitadora alineada con los ejes y, por lo tanto, los nodos internos que no intersectan el dominio original pueden intersectar la caja delimitadora aproximada, lo que resulta en callbacks innecesarias. En cualquier caso, las callbacks son conservadoras, es decir, si una primitiva está dentro del dominio de consulta se invocará una callback, pero no es necesariamente cierto lo contrario.

Para mayor eficiencia, el radio de la consulta puede disminuirse (en espacio de mundo) dentro de la función de callback para mejorar el descarte de geometría durante la traversa del BVH. Si el radio de la consulta se actualizó, la función de callback debe devolver true para emitir una actualización de la información de traversa interna. Aumentar el radio o modificar el tiempo o la posición de la consulta resulta en un comportamiento indefinido.

Dentro de la función de callback, es seguro llamar a [rtcPointQuery] nuevamente, por ejemplo, al implementar instanciación manualmente. En este caso, la transformación de instancia debe insertarse en la pila en context. Embree calculará internamente la información de consulta de puntos en espacio de instancia utilizando el elemento superior de la pila en context cuando se llame a [rtcPointQuery].

Para una implementación de referencia de una traversa de puntos más cercanos de mallas triangulares utilizando instanciación e instanciación definida por el usuario, consulte el tutorial [ClosestPoint].
