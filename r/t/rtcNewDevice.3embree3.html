rtcNewDevice(3) Kernels de trazado de rayos Embree 3 rtcNewDevice(3)

NOMBRE

rtcNewDevice - crea un nuevo dispositivo

SINOPSIS

#include <embree3/rtcore.h>
RTCDevice rtcNewDevice(const char* config);

DESCRIPCIÓN

Esta función crea un nuevo dispositivo y devuelve un manejador para este dispositivo. El objeto del dispositivo tiene un recuento de referencias con un recuento de referencias inicial de 1. El manejador puede liberarse usando la llamada a la API rtcReleaseDevice.

El objeto del dispositivo actúa como una fábrica de clases para todos los demás tipos de objetos. Todos los objetos creados a partir del dispositivo (como escenas, geometrías, etc.) mantienen una referencia al dispositivo, por lo tanto, el dispositivo no se destruirá a menos que estos objetos se destruyan primero.

Los objetos solo son compatibles si pertenecen al mismo dispositivo, por ejemplo, no se permite crear una geometría en un dispositivo y adjuntarla a una escena creada con un dispositivo diferente.

Se puede pasar una cadena de configuración (argumento config) a la construcción del dispositivo. Esta cadena de configuración puede ser NULL para usar la configuración predeterminada.

Se soporta la siguiente configuración:

•
threads=[int]: Especifica un número de hilos de compilación a utilizar. Un valor de 0 habilita todos los hilos de hardware detectados. Por defecto se usan todos los hilos de hardware.
•
user_threads=[int]: Establece el número de hilos de usuario que se pueden utilizar para unirse y participar en la confirmación de una escena usando rtcJoinCommitScene. El sistema de tareas solo usará threads-user_threads hilos de trabajo, por lo tanto, si la aplicación desea usar únicamente sus hilos para confirmar escenas, simplemente establezca threads igual a user_threads. Esta opción solo tiene efecto con el sistema de tareas Intel(R) Threading Building Blocks (TBB).
•
set_affinity=[0/1]: Cuando está habilitado, los hilos de compilación se afinan a los hilos de hardware. Esta opción está deshabilitada por defecto en CPUs estándar, y habilitada por defecto en procesadores Xeon Phi.
•
start_threads=[0/1]: Cuando está habilitado, los hilos de compilación se inician de antemano. Esto puede ser útil para la evaluación comparativa para excluir el tiempo de creación de hilos. Esta opción está deshabilitada por defecto.
•
isa=[sse2,sse4.2,avx,avx2,avx512]: Usa la ISA especificada. Por defecto la ISA se selecciona automáticamente.
•
max_isa=[sse2,sse4.2,avx,avx2,avx512]: Configura la selección automática de ISA para usar como máximo la ISA especificada.
•
hugepages=[0/1]: Habilita o deshabilita el uso de páginas grandes. En Linux se usan páginas grandes por defecto, pero en Windows y macOS están deshabilitadas por defecto.
•
enable_selockmemoryprivilege=[0/1]: Cuando se establece en 1, habilita el privilegio SeLockMemoryPrivilege que se requiere para usar páginas grandes en Windows. Esta opción solo tiene efecto en Windows y se ignora en otras plataformas. Ver la Sección [Soporte de Páginas Grandes] para más detalles.
•
verbose=[0,1,2,3]: Establece la verbosidad de la salida. Cuando se establece en 0, no se imprime ninguna salida por Embree, cuando se establece a un nivel más alto se imprime más salida. Por defecto Embree no imprime nada en la consola.
•
frequency_level=[simd128,simd256,simd512]: Especifica el nivel de frecuencia en el que la aplicación quiere ejecutarse, que puede ser:
a)
simd128 para ejecutarse a la máxima frecuencia
b)
simd256 para ejecutarse a nivel de frecuencia intensivo en AVX2
c)
simd512 para ejecutarse a nivel de frecuencia intensivo en AVX512. Cuando se especifica algún nivel de frecuencia, Embree evitará hacer optimizaciones que puedan reducir el nivel de frecuencia por debajo del nivel especificado. Por ejemplo, si su aplicación no usa instrucciones AVX, establecer “frequency_level=simd128” hará que algunas CPUs se ejecuten a la máxima frecuencia, lo que puede resultar en un mayor rendimiento de la aplicación si realiza mucha sombreado. Si su aplicación usa intensivamente código AVX, lo mejor es establecer el nivel de frecuencia en simd256. Por defecto, Embree intenta evitar reducir la frecuencia de la CPU estableciendo el nivel simd256 solo cuando la CPU no tiene una reducción significativa de reloj.

Diferentes opciones de configuración deben separarse por comas, por ejemplo:

rtcNewDevice("threads=1,isa=avx");

ESTADO DE SALIDA

En caso de éxito, devuelve un manejador del dispositivo creado. En caso de fallo, devuelve NULL como dispositivo y establece un código de error por hilo que se puede consultar usando rtcGetDeviceError(NULL).

VER TAMBIÉN

[rtcRetainDevice], [rtcReleaseDevice]
