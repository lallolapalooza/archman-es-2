rtcInitOccludedArguments(3) Embree Ray Tracing Kernels 4 rtcInitOccludedArguments(3)

NOMBRE

rtcInitOccludedArguments - inicializa la estructura de argumentos ocluidos

SINOPSIS

#include <embree4/rtcore.h>
enum RTCRayQueryFlags
{
  RTC_RAY_QUERY_FLAG_NONE,
  RTC_RAY_QUERY_FLAG_INCOHERENT,
  RTC_RAY_QUERY_FLAG_COHERENT,
  RTC_RAY_QUERY_FLAG_INVOKE_ARGUMENT_FILTER
};
struct RTCOccludedArguments
{
  enum RTCRayQueryFlags flags;
  enum RTCFeatureFlags feature_mask;
  struct RTCRayQueryContext* context;
  RTCFilterFunctionN filter;
  RTCOccludedFunctionN intersect;
#if RTC_MIN_WIDTH
  float minWidthDistanceFactor;
#endif
};
void rtcInitOccludedArguments(
  struct RTCOccludedArguments* args
);

DESCRIPCIÓN

La función rtcInitOccludedArguments inicializa la estructura de argumentos opcional que se puede pasar a las funciones rtcOccluded1/4/8/16 con valores predeterminados. La estructura de argumentos debe utilizarse para funciones Embree más avanzadas, como se describe aquí.

El miembro flags se puede utilizar para habilitar un modo de recorrido especial. El uso de la bandera RTC_RAY_QUERY_FLAG_INCOHERENT utiliza un algoritmo de recorrido optimizado para rayos incoherentes (predeterminado), mientras que RTC_RAY_QUERY_FLAG_COHERENT utiliza un algoritmo de recorrido optimizado para rayos coherentes (por ejemplo, rayos de cámara primarios).

El miembro feature_mask debe usarse en SYCL para habilitar solo las características de trazado de rayos requeridas para renderizar una escena dada. Consulte la sección [RTCFeatureFlags] para obtener una descripción más detallada.

El miembro context se puede utilizar para pasar un contexto de intersección opcional. Se garantiza que el puntero al contexto pasado a una consulta de rayos se pasa directamente a todas las funciones de devolución de llamada. De esta manera, es posible adjuntar datos arbitrarios al final del contexto, como una carga útil por rayo. Tenga en cuenta que no se garantiza que el puntero del rayo se pase a las funciones de devolución de llamada, por lo que no es posible leer datos adicionales del puntero del rayo pasado a las devoluciones de llamada. Consulte la sección [rtcInitRayQueryContext] para obtener más detalles.

El miembro filter especifica una función de filtro que se invocará para cada impacto encontrado. La compatibilidad con la función de filtro de argumentos debe habilitarse para una escena utilizando la bandera de escena RTC_SCENE_FLAG_FILTER_FUNCTION_IN_ARGUMENTS. En caso de instanciación, esta característica también debe habilitarse para cada escena instanciada.

La función de filtro de argumentos se invoca para cada geometría para la que se habilitó explícitamente utilizando la función rtcSetGeometryEnableFilterFunctionFromArguments. La invocación de la función de filtro de argumentos también se puede forzar para cada geometría utilizando la bandera de consulta de rayos RTC_RAY_QUERY_FLAG_INVOKE_ARGUMENT_FILTER. Esta función de filtro de argumentos se invoca como una segunda etapa de filtrado después de que se invoca la función de filtro por geometría. Solo los rayos que pasaron la primera etapa de filtrado son válidos en esta segunda etapa de filtrado. Tener una función de filtro por consulta de rayos de este tipo puede ser útil para implementar modificaciones del comportamiento de la consulta, como recopilar todos los impactos o acumular transparencias.

El miembro intersect especifica la devolución de llamada de geometría de usuario que se invocará para cada geometría de usuario encontrada durante el recorrido. La devolución de llamada de geometría de usuario especificada de esta manera tiene preferencia sobre la especificada dentro de la geometría.

El valor minWidthDistanceFactor controla el tamaño objetivo de los radios de las curvas cuando la característica de ancho mínimo está habilitada. Consulte la función [rtcSetGeometryMaxRadiusScale] para obtener más detalles sobre la característica de ancho mínimo.

ESTADO DE SALIDA

Ningún código de error es establecido por esta función.
