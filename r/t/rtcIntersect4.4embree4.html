rtcIntersect4/8/16(3) Kernels de trazado de rayos Embree 4 rtcIntersect4/8/16(3)

NOMBRE

rtcIntersect4/8/16 - encuentra los impactos más cercanos para un paquete de rayos

SINOPSIS

#include <embree4/rtcore.h>
void rtcIntersect4(
  const int* valid,
  RTCScene scene,
  struct RTCRayHit4* rayhit,
  struct RTCIntersectArguments* args = NULL
);
void rtcIntersect8(
  const int* valid,
  RTCScene scene,
  struct RTCRayHit8* rayhit,
  struct RTCIntersectArguments* args = NULL
);
void rtcIntersect16(
  const int* valid,
  RTCScene scene,
  struct RTCRayHit16* rayhit,
  struct RTCIntersectArguments* args = NULL
);

DESCRIPCIÓN

Las funciones rtcIntersect4/8/16 encuentran los impactos más cercanos para un paquete de rayos de tamaño 4, 8 o 16 (argumento rayhit) con la escena (argumento scene). La entrada de rayo/impacto contiene un paquete de rayos y un paquete de impactos. El struct de argumentos opcionales pasado (argumento args) se utiliza para pasar argumentos adicionales para funciones avanzadas. Consulte la Sección [rtcIntersect1] para obtener más detalles y una descripción de cómo configurar y rastrear rayos.

Se debe proporcionar una máscara de validez de rayos (argumento valid) que almacena un entero de 32 bits (-1 significa válido y 0 inválido) por rayo en el paquete. Solo se procesan los rayos activos, y los datos de impacto de los rayos inactivos no se modifican.

Para rtcIntersect4, el paquete de rayos debe estar alineado a 16 bytes; para rtcIntersect8, la alineación debe ser de 32 bytes; y para rtcIntersect16, la alineación debe ser de 64 bytes.

Las funciones rtcIntersect4, rtcIntersect8 y rtcIntersect16 pueden cambiar el tamaño del paquete de rayos y el orden de los rayos al llamar a funciones de filtro o a callbacks de geometría de usuario. Bajo ciertas condiciones, la aplicación puede asumir que los paquetes permanecerán intactos, lo cual se puede determinar consultando las propiedades RTC_DEVICE_PROPERTY_NATIVE_RAY4_SUPPORTED, RTC_DEVICE_PROPERTY_NATIVE_RAY8_SUPPORTED, RTC_DEVICE_PROPERTY_NATIVE_RAY16_SUPPORTED a través de la función rtcGetDeviceProperty. Consulte [rtcGetDeviceProperty] para obtener más información.

ESTADO DE SALIDA

Por razones de rendimiento, esta función no realiza ninguna comprobación de errores y, por lo tanto, no establecerá ningún indicador de error en caso de fallo.
