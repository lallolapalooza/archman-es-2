RTLD-AUDIT(7) Manual de Información Miscelánea RTLD-AUDIT(7)

NOMBRE

rtld-audit - API de auditoría para el enlazador dinámico

SINOPSIS

#define _GNU_SOURCE             /* Ver feature_test_macros(7) */
#include <link.h>

DESCRIPCIÓN

El enlazador dinámico de GNU (enlazador en tiempo de ejecución) proporciona una API de auditoría que permite a una aplicación ser notificada cuando ocurren varios eventos de enlace dinámico. Esta API es muy similar a la interfaz de auditoría proporcionada por el enlazador en tiempo de ejecución de Solaris. Las constantes y prototipos necesarios se definen incluyendo <link.h>.

Para usar esta interfaz, el programador crea una biblioteca compartida que implementa un conjunto estándar de nombres de función. No todas las funciones necesitan ser implementadas: en la mayoría de los casos, si el programador no está interesado en una clase particular de evento de auditoría, entonces no se necesita proporcionar ninguna implementación para la función de auditoría correspondiente.

Para emplear la interfaz de auditoría, la variable de entorno LD_AUDIT debe definirse para contener una lista de bibliotecas compartidas separadas por dos puntos, cada una de las cuales puede implementar (partes de) la API de auditoría. Cuando ocurre un evento auditable, se invoca la función correspondiente en cada biblioteca, en el orden en que se enumeran las bibliotecas.

la_version()

unsigned int la_version(unsigned int version);

Esta es la única función que debe ser definida por una biblioteca de auditoría: realiza el apretón de manos inicial entre el enlazador dinámico y la biblioteca de auditoría. Al invocar esta función, el enlazador dinámico pasa, en version, la versión más alta de la interfaz de auditoría que el enlazador soporta.

Una implementación típica de esta función simplemente devuelve la constante LAV_CURRENT, que indica la versión de <link.h> que se utilizó para compilar el módulo de auditoría. Si el enlazador dinámico no soporta esta versión de la interfaz de auditoría, se negará a activar este módulo de auditoría. Si la función devuelve cero, el enlazador dinámico tampoco activa este módulo de auditoría.

Para habilitar la compatibilidad con versiones anteriores de enlazadores dinámicos, un módulo de auditoría puede examinar el argumento version y devolver una versión anterior a LAV_CURRENT, asumiendo que el módulo puede ajustar su implementación para que coincida con los requisitos de la versión anterior de la interfaz de auditoría. La función la_version no debe devolver el valor de version sin comprobaciones adicionales porque podría corresponder a una interfaz que no coincide con las definiciones de <link.h> utilizadas para compilar el módulo de auditoría.

la_objsearch()

char *la_objsearch(const char *name, uintptr_t *cookie,
                   unsigned int flag);

El enlazador dinámico invoca esta función para informar a la biblioteca de auditoría que está a punto de buscar un objeto compartido. El argumento name es el nombre de archivo o ruta que se va a buscar. cookie identifica el objeto compartido que inició la búsqueda. flag se establece en uno de los siguientes valores:

LA_SER_ORIG
Este es el nombre original que se está buscando. Típicamente, este nombre proviene de una entrada DT_NEEDED de ELF, o es el argumento filename dado a dlopen(3).
LA_SER_LIBPATH
name se creó utilizando un directorio especificado en LD_LIBRARY_PATH.
LA_SER_RUNPATH
name se creó utilizando un directorio especificado en una lista DT_RPATH o DT_RUNPATH de ELF.
LA_SER_CONFIG
name se encontró a través de la caché de ldconfig(8) (/etc/ld.so.cache).
LA_SER_DEFAULT
name se encontró mediante una búsqueda en uno de los directorios predeterminados.
LA_SER_SECURE
name es específico para un objeto seguro (no utilizado en Linux).

Como resultado de la función, la_objsearch() devuelve la ruta del archivo que el enlazador dinámico debe usar para su procesamiento posterior. Si se devuelve NULL, entonces esta ruta de archivo se ignora para el procesamiento posterior. Si esta biblioteca de auditoría simplemente tiene la intención de monitorear las rutas de búsqueda, entonces se debe devolver name.

la_activity()

void la_activity( uintptr_t *cookie, unsigned int flag);

El enlazador dinámico llama a esta función para informar a la biblioteca de auditoría que está ocurriendo actividad en el mapa de enlaces. cookie identifica el objeto en la cabeza del mapa de enlaces. Cuando el enlazador dinámico invoca esta función, flag se establece en uno de los siguientes valores:

LA_ACT_ADD
Se están agregando nuevos objetos al mapa de enlaces.
LA_ACT_DELETE
Se están eliminando objetos del mapa de enlaces.
LA_ACT_CONSISTENT
La actividad del mapa de enlaces se ha completado: el mapa es nuevamente consistente.

la_objopen()

unsigned int la_objopen(struct link_map *map, Lmid_t lmid,
                        uintptr_t *cookie);

El enlazador dinámico llama a esta función cuando se carga un nuevo objeto compartido. El argumento map es un puntero a una estructura de mapa de enlaces que describe el objeto. El campo lmid tiene uno de los siguientes valores

LM_ID_BASE
El mapa de enlaces es parte del espacio de nombres inicial.
LM_ID_NEWLM
El mapa de enlaces es parte de un nuevo espacio de nombres solicitado a través de dlmopen(3).

cookie es un puntero a un identificador para este objeto. El identificador se proporciona a llamadas posteriores a funciones en la biblioteca de auditoría para identificar este objeto. Este identificador se inicializa para apuntar al mapa de enlaces del objeto, pero la biblioteca de auditoría puede cambiar el identificador a otro valor que prefiera usar para identificar el objeto.

Como valor de retorno, la_objopen() devuelve una máscara de bits creada OR-ando cero o más de las siguientes constantes, que permiten a la biblioteca de auditoría seleccionar los objetos que serán monitoreados por la_symbind*():

LA_FLG_BINDTO
Auditar enlaces de símbolos a este objeto.
LA_FLG_BINDFROM
Auditar enlaces de símbolos desde este objeto.

Un valor de retorno de 0 de la_objopen() indica que no se deben auditar los enlaces de símbolos para este objeto.

la_objclose()

unsigned int la_objclose(uintptr_t *cookie);

El enlazador dinámico invoca esta función después de que se haya ejecutado cualquier código de finalización para el objeto, antes de que el objeto sea descargado. El argumento cookie es el identificador obtenido de una invocación anterior de la_objopen().

En la implementación actual, se ignora el valor devuelto por la_objclose().

la_preinit()

void la_preinit(uintptr_t *cookie);

El enlazador dinámico invoca esta función después de que se hayan cargado todos los objetos compartidos, antes de que se pase el control a la aplicación (es decir, antes de llamar a main()). Tenga en cuenta que main() aún puede cargar dinámicamente objetos más tarde usando dlopen(3).

la_symbind*()

uintptr_t la_symbind32(Elf32_Sym *sym, unsigned int ndx,
                       uintptr_t *refcook, uintptr_t *defcook,
                       unsigned int *flags, const char *symname);
uintptr_t la_symbind64(Elf64_Sym *sym, unsigned int ndx,
                       uintptr_t *refcook, uintptr_t *defcook,
                       unsigned int *flags, const char *symname);

El enlazador dinámico invoca una de estas funciones cuando se produce un enlace de símbolos entre dos objetos compartidos que han sido marcados para notificación de auditoría por la_objopen(). La función la_symbind32() se emplea en plataformas de 32 bits; la función la_symbind64() se emplea en plataformas de 64 bits.

El argumento sym es un puntero a una estructura que proporciona información sobre el símbolo que se está enlazando. La definición de la estructura se muestra en <elf.h>. Entre los campos de esta estructura, st_value indica la dirección a la que se enlaza el símbolo.

El argumento ndx proporciona el índice del símbolo en la tabla de símbolos del objeto compartido enlazado.

El argumento refcook identifica el objeto compartido que está realizando la referencia al símbolo; este es el mismo identificador que se proporciona a la función la_objopen() que devolvió LA_FLG_BINDFROM. El argumento defcook identifica el objeto compartido que define el símbolo referenciado; este es el mismo identificador que se proporciona a la función la_objopen() que devolvió LA_FLG_BINDTO.

El argumento symname apunta a una cadena que contiene el nombre del símbolo.

El argumento flags es una máscara de bits que proporciona información sobre el símbolo y puede utilizarse para modificar la auditoría posterior de esta entrada de la PLT (Tabla de Enlace de Procedimientos). El enlazador dinámico puede proporcionar los siguientes valores de bits en este argumento:

LA_SYMB_DLSYM
El enlace resultó de una llamada a dlsym(3).
LA_SYMB_ALTVALUE
Una llamada anterior a la_symbind*() devolvió un valor alternativo para este símbolo.

Por defecto, si la biblioteca de auditoría implementa las funciones la_pltenter() y la_pltexit() (ver más abajo), entonces estas funciones se invocan, después de la_symbind(), para las entradas de la PLT, cada vez que se hace referencia al símbolo. Las siguientes banderas pueden ser ORadas en *flags para cambiar este comportamiento por defecto:

LA_SYMB_NOPLTENTER
No llamar a la_pltenter() para este símbolo.
LA_SYMB_NOPLTEXIT
No llamar a la_pltexit() para este símbolo.

El valor de retorno de la_symbind32() y la_symbind64() es la dirección a la que se debe pasar el control después de que la función regrese. Si la biblioteca de auditoría solo está monitorizando los enlaces de símbolos, debería devolver sym->st_value. Se puede devolver un valor diferente si la biblioteca desea dirigir el control a una ubicación alternativa.

la_pltenter()

El nombre exacto y los tipos de argumento para esta función dependen de la plataforma de hardware. (La definición apropiada la proporciona <link.h>.) Aquí está la definición para x86-32:

Elf32_Addr la_i86_gnu_pltenter(Elf32_Sym *sym, unsigned int ndx,
                 uintptr_t *refcook, uintptr_t *defcook,
                 La_i86_regs *regs, unsigned int *flags,
                 const char *symname, long *framesizep);

Esta función se invoca justo antes de que se llame a una entrada de la PLT, entre dos objetos compartidos que han sido marcados para notificación de enlace.

Los argumentos sym, ndx, refcook, defcook y symname son los mismos que para la_symbind*().

El argumento regs apunta a una estructura (definida en <link.h>) que contiene los valores de los registros que se usarán para la llamada a esta entrada de la PLT.

El argumento flags apunta a una máscara de bits que transmite información sobre, y puede usarse para modificar la auditoría posterior de, esta entrada de la PLT, al igual que para la_symbind*().

El argumento framesizep apunta a un búfer de tipo long int que se puede usar para establecer explícitamente el tamaño del marco utilizado para la llamada a esta entrada de la PLT. Si invocaciones diferentes de la_pltenter() para este símbolo devuelven valores diferentes, se utiliza el valor máximo devuelto. La función la_pltexit() solo se llama si este búfer se establece explícitamente en un valor adecuado.

El valor de retorno de la_pltenter() es el mismo que para la_symbind*().

la_pltexit()

El nombre exacto y los tipos de argumento para esta función dependen de la plataforma de hardware. (La definición apropiada la proporciona <link.h>.) Aquí está la definición para x86-32:

unsigned int la_i86_gnu_pltexit(Elf32_Sym *sym, unsigned int ndx,
                 uintptr_t *refcook, uintptr_t *defcook,
                 const La_i86_regs *inregs, La_i86_retval *outregs,
                 const char *symname);

Esta función se llama cuando una entrada de la PLT, creada entre dos objetos compartidos que han sido marcados para notificación de enlace, regresa. La función se llama justo antes de que el control regrese al llamador de la entrada de la PLT.

Los argumentos sym, ndx, refcook, defcook y symname son los mismos que para la_symbind*().

El argumento inregs apunta a una estructura (definida en <link.h>) que contiene los valores de los registros utilizados para la llamada a esta entrada de la PLT. El argumento outregs apunta a una estructura (definida en <link.h>) que contiene los valores de retorno de la llamada a esta entrada de la PLT. Estos valores pueden ser modificados por el llamador, y los cambios serán visibles para el llamador de la entrada de la PLT.

En la implementación actual de GNU, el valor de retorno de la_pltexit() se ignora.

VERSIONS

Esta API es muy similar a la API de Solaris descrita en la *Guía de Enlazador y Librerías* de Solaris, en el capítulo *Interfaz de Auditoría del Enlazador en Tiempo de Ejecución*.

STANDARDS

Ninguno.

NOTES

Observe las siguientes diferencias con la API de auditoría del enlazador dinámico de Solaris:

•
La interfaz la_objfilter() de Solaris no es compatible con la implementación de GNU.
•
Las funciones la_symbind32() y la_pltexit() de Solaris no proporcionan un argumento symname.
•
La función la_pltexit() de Solaris no proporciona los argumentos inregs y outregs (pero sí proporciona un argumento retval con el valor de retorno de la función).

BUGS

En las versiones de glibc hasta la 2.9 inclusive, especificar más de una biblioteca de auditoría en LD_AUDIT resulta en un fallo en tiempo de ejecución. Según se informa, esto está corregido en glibc 2.10.

EXAMPLES

#include <link.h>
#include <stdio.h>
unsigned int
la_version(unsigned int version)
{
    printf("la_version(): version = %u; LAV_CURRENT = %u\n",
            version, LAV_CURRENT);
    return LAV_CURRENT;
}
char *
la_objsearch(const char *name, uintptr_t *cookie, unsigned int flag)
{
    printf("la_objsearch(): name = %s; cookie = %p", name, cookie);
    printf("; flag = %s\n",
            (flag == LA_SER_ORIG) ?    "LA_SER_ORIG" :
            (flag == LA_SER_LIBPATH) ? "LA_SER_LIBPATH" :
            (flag == LA_SER_RUNPATH) ? "LA_SER_RUNPATH" :
            (flag == LA_SER_DEFAULT) ? "LA_SER_DEFAULT" :
            (flag == LA_SER_CONFIG) ?  "LA_SER_CONFIG" :
            (flag == LA_SER_SECURE) ?  "LA_SER_SECURE" :
            "???");
    return name;
}
void
la_activity (uintptr_t *cookie, unsigned int flag)
{
    printf("la_activity(): cookie = %p; flag = %s\n", cookie,
            (flag == LA_ACT_CONSISTENT) ? "LA_ACT_CONSISTENT" :
            (flag == LA_ACT_ADD) ?        "LA_ACT_ADD" :
            (flag == LA_ACT_DELETE) ?     "LA_ACT_DELETE" :
            "???");
}
unsigned int
la_objopen(struct link_map *map, Lmid_t lmid, uintptr_t *cookie)
{
    printf("la_objopen(): loading \"%s\"; lmid = %s; cookie=%p\n",
            map->l_name,
            (lmid == LM_ID_BASE) ?  "LM_ID_BASE" :
            (lmid == LM_ID_NEWLM) ? "LM_ID_NEWLM" :
            "???",
            cookie);
    return LA_FLG_BINDTO | LA_FLG_BINDFROM;
}
unsigned int
la_objclose (uintptr_t *cookie)
{
    printf("la_objclose(): %p\n", cookie);
    return 0;
}
void
la_preinit(uintptr_t *cookie)
{
    printf("la_preinit(): %p\n", cookie);
}
uintptr_t
la_symbind32(Elf32_Sym *sym, unsigned int ndx, uintptr_t *refcook,
        uintptr_t *defcook, unsigned int *flags, const char *symname)
{
    printf("la_symbind32(): symname = %s; sym->st_value = %p\n",
            symname, sym->st_value);
    printf("        ndx = %u; flags = %#x", ndx, *flags);
    printf("; refcook = %p; defcook = %p\n", refcook, defcook);
    return sym->st_value;
}
uintptr_t
la_symbind64(Elf64_Sym *sym, unsigned int ndx, uintptr_t *refcook,
        uintptr_t *defcook, unsigned int *flags, const char *symname)
{
    printf("la_symbind64(): symname = %s; sym->st_value = %p\n",
            symname, sym->st_value);
    printf("        ndx = %u; flags = %#x", ndx, *flags);
    printf("; refcook = %p; defcook = %p\n", refcook, defcook);
    return sym->st_value;
}
Elf32_Addr
la_i86_gnu_pltenter(Elf32_Sym *sym, unsigned int ndx,
        uintptr_t *refcook, uintptr_t *defcook, La_i86_regs *regs,
        unsigned int *flags, const char *symname, long *framesizep)
{
    printf("la_i86_gnu_pltenter(): %s (%p)\n", symname, sym->st_value);
    return sym->st_value;
}
