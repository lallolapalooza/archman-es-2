rtcInitIntersectArguments(3) Núcleos de trazado de rayos Embree 4 rtcInitIntersectArguments(3)

NOMBRE

rtcInitIntersectArguments - inicializa la estructura de argumentos de intersección

SINOPSIS

#include <embree4/rtcore.h>
enum RTCRayQueryFlags
{
  RTC_RAY_QUERY_FLAG_NONE,
  RTC_RAY_QUERY_FLAG_INCOHERENT,
  RTC_RAY_QUERY_FLAG_COHERENT,
  RTC_RAY_QUERY_FLAG_INVOKE_ARGUMENT_FILTER
};
struct RTCIntersectArguments
{
  enum RTCRayQueryFlags flags;
  enum RTCFeatureFlags feature_mask;
  struct RTCQueryContext* context;
  RTCFilterFunctionN filter;
  RTCIntersectFunctionN intersect;
#if RTC_MIN_WIDTH
  float minWidthDistanceFactor;
#endif
};
void rtcInitIntersectArguments(
  struct RTCIntersectArguments* args
);

DESCRIPCIÓN

La función rtcInitIntersectArguments inicializa la estructura de argumentos opcionales que se puede pasar a las funciones rtcIntersect1/4/8/16 a valores predeterminados. La estructura de argumentos necesita ser utilizada para características más avanzadas de Embree, como se describe aquí.

El miembro flags se puede utilizar para habilitar modos de traversal especiales. Usar el flag RTC_RAY_QUERY_FLAG_INCOHERENT utiliza un algoritmo de traversal optimizado para rayos incoherentes (predeterminado), mientras que RTC_RAY_QUERY_FLAG_COHERENT utiliza un algoritmo de traversal optimizado para rayos coherentes (por ejemplo, rayos de cámara primarios).

El miembro feature_mask debe usarse en SYCL para habilitar solo las características de trazado de rayos requeridas para renderizar una escena dada. Consulte la sección [RTCFeatureFlags] para obtener una descripción más detallada.

El miembro context se puede usar para pasar un contexto de intersección opcional. Se garantiza que el puntero al contexto pasado a una consulta de rayos se pasa directamente a todas las funciones de llamada. De esta manera, es posible adjuntar datos arbitrarios al final del contexto, como una carga útil por rayo. Tenga en cuenta que no se garantiza que el puntero del rayo se pase a las funciones de llamada, por lo tanto, no es posible leer datos adicionales del puntero del rayo pasado a las llamadas. Consulte la sección [rtcInitRayQueryContext] para obtener más detalles.

El miembro filter especifica una función de filtro para invocar para cada intersección encontrada. La compatibilidad con la función de filtro de argumentos debe habilitarse para una escena utilizando el flag de escena RTC_SCENE_FLAG_FILTER_FUNCTION_IN_ARGUMENTS. En caso de instanciación, esta característica también debe habilitarse para cada escena instanciada.

La función de filtro de argumentos se invoca para cada geometría para la cual se habilitó explícitamente utilizando la función rtcSetGeometryEnableFilterFunctionFromArguments. La invocación de la función de filtro de argumentos también se puede forzar para cada geometría utilizando el flag de consulta de rayos RTC_RAY_QUERY_FLAG_INVOKE_ARGUMENT_FILTER. Esta función de filtro de argumentos se invoca como una segunda etapa de filtro después de que se invoca la función de filtro por geometría. Solo los rayos que pasaron la primera etapa de filtro son válidos en esta segunda etapa de filtro. Tener una función de filtro de este tipo por consulta de rayos puede ser útil para implementar modificaciones del comportamiento de la consulta, como recopilar todas las intersecciones o acumular transparencias.

El miembro intersect especifica la llamada de geometría de usuario que se invocará para cada geometría de usuario encontrada durante el traversal. La llamada de geometría de usuario especificada de esta manera tiene preferencia sobre la especificada dentro de la geometría.

El valor minWidthDistanceFactor controla el tamaño objetivo de los radios de las curvas cuando la característica de anchura mínima está habilitada. Consulte la función [rtcSetGeometryMaxRadiusScale] para obtener más detalles sobre la característica de anchura mínima.

ESTADO DE SALIDA

No se establece ningún código de error por esta función.
