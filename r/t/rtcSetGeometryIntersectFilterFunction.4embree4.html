NOMBRE

rtcSetGeometryIntersectFilterFunction - establece la función de filtro de intersección
  para la geometría

SINOPSIS

#include <embree4/rtcore.h>
struct RTCFilterFunctionNArguments
{
  int* valid;
  void* geometryUserPtr;
  const struct RTCRayQueryContext* context;
  struct RTCRayN* ray;
  struct RTCHitN* hit;
  unsigned int N;
};
typedef void (*RTCFilterFunctionN)(
  const struct RTCFilterFunctionNArguments* args
);
void rtcSetGeometryIntersectFilterFunction(
  RTCGeometry geometry,
  RTCFilterFunctionN filter
);

DESCRIPCIÓN

La función rtcSetGeometryIntersectFilterFunction registra una función de devolución de llamada de filtro de intersección (argumento filter) para la geometría especificada (argumento geometry).

Solo se puede registrar una función de devolución de llamada por geometría, y las invocaciones posteriores sobrescriben la función de devolución de llamada previamente establecida. Pasar NULL como puntero de función deshabilita la función de devolución de llamada registrada.

La función de filtro de intersección registrada se invoca para cada hit encontrado durante las consultas de rayos de tipo rtcIntersect y puede aceptar o rechazar ese hit. La característica se puede utilizar para definir una silueta para una primitiva y rechazar hits que se encuentran fuera de la silueta. Por ejemplo, la hoja de un árbol podría modelarse con una textura alfa que decida si los puntos de impacto se encuentran dentro o fuera de la hoja.

Si se establece el modo RTC_BUILD_QUALITY_HIGH, las funciones de filtro pueden llamarse varias veces para el mismo hit de primitiva. Además, los rayos que golpean exactamente el borde también pueden informar dos hits para la misma superficie. Para ciertos casos de uso, la aplicación puede tener que solucionar esta limitación recopilando pares (geomID/primID) de hits ya informados e ignorando duplicados.

La función de devolución de llamada de filtro de tipo RTCFilterFunctionN recibe una serie de argumentos a través de la estructura RTCFilterFunctionNArguments. El parámetro valid de esa estructura apunta a una máscara de enteros válida (0 significa inválido y -1 significa válido). El miembro geometryUserPtr es un puntero de usuario establecido opcionalmente por geometría a través de la función rtcSetGeometryUserData. El miembro context apunta al contexto de consulta de rayos pasado a la función de consulta de rayos. El parámetro ray apunta a N rayos en diseño SOA. El parámetro hit apunta a N hits en diseño SOA para probar. El parámetro N es el número de rayos y hits en ray y hit. La distancia del hit se proporciona como el valor tfar del rayo. Si la geometría del hit está instanciada, el miembro instID del rayo es válido, y el rayo y el hit potencial están en el espacio del objeto.

La función de devolución de llamada de filtro tiene la tarea de verificar para cada rayo válido si desea aceptar o rechazar el hit correspondiente. Para rechazar un hit, la función de devolución de llamada de filtro solo tiene que escribir 0 en la máscara de enteros válida del rayo correspondiente. Para aceptar el hit, solo tiene que dejar la máscara válida establecida en -1. Al aceptar un hit, la función de filtro tiene además permitido cambiar el hit y disminuir el valor tfar del rayo, pero no debe modificar otros datos del rayo ni ningún componente inactivo del rayo o hit.

La implementación de la función de filtro puede optar por implementar un único camino de código que utiliza las funciones auxiliares de acceso a rayos RTCRay_XXX y las funciones auxiliares de acceso a hits RTCHit_XXX para acceder a los datos de rayos y hits. Alternativamente, el código puede ramificarse a implementaciones optimizadas para tamaños específicos de N y convertir las entradas de rayos y hits a los tipos de paquete adecuados.

ESTADO DE SALIDA

En caso de fallo, se establece un código de error que se puede consultar mediante rtcGetDeviceError.
