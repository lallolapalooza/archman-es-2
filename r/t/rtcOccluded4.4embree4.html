rtcOccluded4/8/16(3) Embree Ray Tracing Kernels 4 rtcOccluded4/8/16(3)

NOMBRE

rtcOccluded4/8/16 - encuentra cualquier impacto para un paquete de rayos

SINOPSIS

#include <embree4/rtcore.h>
void rtcOccluded4(
  const int* valid,
  RTCScene scene,
  struct RTCRay4* ray,
  struct RTCOccludedArguments* args = NULL
);
void rtcOccluded8(
  const int* valid,
  RTCScene scene,
  struct RTCRay8* ray,
  struct RTCOccludedArguments* args = NULL
);
void rtcOccluded16(
  const int* valid,
  RTCScene scene,
  struct RTCRay16* ray,
  struct RTCOccludedArguments* args = NULL
);

DESCRIPCIÓN

Las funciones rtcOccluded4/8/16 comprueban para cada rayo activo del paquete de rayos de tamaño 4, 8 o 16 (argumento de rayo) si existe algún impacto con la escena (argumento de escena). La estructura de argumentos opcionales pasada (argumento args) se puede usar para casos de uso avanzados, véase la sección [rtcInitOccludedArguments] para más detalles. Véase la Sección [rtcOccluded1] para más detalles y una descripción de cómo configurar y trazar rayos de oclusión.

Se debe proporcionar una máscara de validez de rayos (argumento valid) que almacena un entero de 32 bits (-1 significa válido y 0 inválido) por rayo en el paquete. Solo se procesan los rayos activos y los datos de impacto de los rayos inactivos no se modifican.

Para rtcOccluded4, el paquete de rayos debe estar alineado a 16 bytes, para rtcOccluded8 la alineación debe ser de 32 bytes, y para rtcOccluded16 la alineación debe ser de 64 bytes.

Las funciones rtcOccluded4, rtcOccluded8 y rtcOccluded16 pueden cambiar el tamaño del paquete de rayos y el orden de los rayos al llamar a funciones de filtro de intersección o a callbacks de geometría definidos por el usuario. Bajo ciertas condiciones, la aplicación puede asumir que los paquetes permanecerán intactos, lo cual se puede determinar consultando las propiedades RTC_DEVICE_PROPERTY_NATIVE_RAY4_SUPPORTED, RTC_DEVICE_PROPERTY_NATIVE_RAY8_SUPPORTED, RTC_DEVICE_PROPERTY_NATIVE_RAY16_SUPPORTED a través de la función rtcGetDeviceProperty. Véase [rtcGetDeviceProperty] para más información.

ESTADO DE SALIDA

Por razones de rendimiento, esta función no realiza ninguna comprobación de errores, por lo que no establecerá ninguna bandera de error en caso de fallo.
