rtcInitIntersectContext(3) Kernels de Trazado de Rayos Embree 3 rtcInitIntersectContext(3)

NOMBRE

rtcInitIntersectContext - inicializa el contexto de intersección

SINOPSIS

#include <embree3/rtcore.h>
enum RTCIntersectContextFlags
{
  RTC_INTERSECT_CONTEXT_FLAG_NONE,
  RTC_INTERSECT_CONTEXT_FLAG_INCOHERENT,
  RTC_INTERSECT_CONTEXT_FLAG_COHERENT,
};
struct RTCIntersectContext
{
  enum RTCIntersectContextFlags flags;
  RTCFilterFunctionN filter;
  #if RTC_MAX_INSTANCE_LEVEL_COUNT > 1
    unsigned int instStackSize;
  #endif
  unsigned int instID[RTC_MAX_INSTANCE_LEVEL_COUNT];
  #if RTC_MIN_WIDTH
    float minWidthDistanceFactor;
  #endif
};
void rtcInitIntersectContext(
  struct RTCIntersectContext* context
);

DESCRIPCIÓN

Se soporta un contexto de intersección por consulta de rayo (tipo RTCIntersectContext) que puede ser utilizado para configurar flags de intersección (miembro flags), especificar una función de callback de filtro (miembro filter), especificar la cadena de IDs de la instancia actual (miembros instID e instStackSize), y para adjuntar datos arbitrarios a la consulta (por ejemplo, datos por rayo).

La función rtcInitIntersectContext inicializa el contexto con valores por defecto y debe ser llamada para inicializar cada contexto de intersección. Esta función se inserta en línea, lo que minimiza la sobrecarga y permite optimizaciones del compilador.

El flag del contexto de intersección puede ser utilizado para ajustar el comportamiento del algoritmo de traversa. Usando el flag RTC_INTERSECT_CONTEXT_FLAG_INCOHERENT se utiliza un algoritmo de traversa optimizado para rayos incoherentes (por defecto), mientras que RTC_INTERSECT_CONTEXT_FLAG_COHERENT utiliza un algoritmo de traversa optimizado para rayos coherentes (por ejemplo, rayos de cámara primarios).

El mejor rendimiento para rayos primarios se puede obtener utilizando la API de stream de rayos y estableciendo el flag del contexto de intersección a RTC_INTERSECT_CONTEXT_FLAG_COHERENT. Para rayos secundarios, normalmente es mejor usar el flag RTC_INTERSECT_CONTEXT_FLAG_INCOHERENT, a menos que los rayos también sean conocidos por ser muy coherentes (por ejemplo, para rayos de transparencia primarios).

Se puede especificar una función de filtro dentro del contexto. Esta función de filtro se invoca como una segunda etapa de filtrado después de que la función de filtro de intersección o oclusión por geometría es invocada. Solo los rayos que pasaron la primera etapa de filtrado son válidos en esta segunda etapa de filtrado. Tener una función de filtro por consulta de rayo puede ser útil para implementar modificaciones del comportamiento de la consulta, como la recolección de todos los impactos o la acumulación de transparencias. El soporte para la función de filtro de contexto debe ser habilitado para una escena usando el flag de escena RTC_SCENE_FLAG_CONTEXT_FILTER_FUNCTION. En caso de instanciación, esta característica también debe ser habilitada para cada escena instanciada.

El valor minWidthDistanceFactor controla el tamaño objetivo de los radios de las curvas cuando la característica de ancho mínimo está habilitada. Por favor, consulte la función [rtcSetGeometryMaxRadiusScale] para más detalles sobre la característica de ancho mínimo.

Se garantiza que el puntero al contexto de intersección pasado a una consulta de rayo se pasa directamente a las funciones de callback registradas. De esta manera es posible adjuntar datos arbitrarios al final del contexto de intersección, como una carga útil por rayo.

Tenga en cuenta que no se garantiza que el puntero del rayo se pase a las funciones de callback, por lo que no es posible leer datos adicionales del puntero del rayo pasado a los callbacks.

VALOR DE RETORNO

Esta función no establece ningún código de error.

VER TAMBIÉN

[rtcIntersect1], [rtcOccluded1]
