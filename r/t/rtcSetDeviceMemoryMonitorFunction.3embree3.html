rtcSetDeviceMemoryMonitorFunction(3) Núcleos de Ray Tracing Embree 3 rtcSetDeviceMemoryMonitorFunction(3)

NOMBRE

rtcSetDeviceMemoryMonitorFunction - registra una función de devolución de llamada
  para rastrear el consumo de memoria

SINOPSIS

#include <embree3/rtcore.h>
typedef bool (*RTCMemoryMonitorFunction)(
  void* userPtr,
  ssize_t bytes,
  bool post
);
void rtcSetDeviceMemoryMonitorFunction(
  RTCDevice device,
  RTCMemoryMonitorFunction memoryMonitor,
  void* userPtr
);

DESCRIPCIÓN

Utilizando la llamada rtcSetDeviceMemoryMonitorFunction, es posible registrar una función de devolución de llamada (argumento memoryMonitor) con carga útil (argumento userPtr) para un dispositivo (argumento device), que se llama cada vez que se asigna o libera memoria interna por objetos de ese dispositivo. Usando este mecanismo de devolución de llamada del monitor de memoria, la aplicación puede rastrear el consumo de memoria de un dispositivo Embree y, opcionalmente, terminar las llamadas a la API que consumen demasiada memoria.

Solo se puede registrar una función de devolución de llamada por dispositivo, y las invocaciones posteriores sobrescriben la función de devolución de llamada previamente establecida. Pasar NULL como puntero de función deshabilita la función de devolución de llamada registrada.

Una vez registrada, el dispositivo Embree invocará la función de devolución de llamada del monitor de memoria antes o después de asignar o liberar bloques de memoria importantes. La función de devolución de llamada recibe la carga útil especificada en el momento del registro (argumento userPtr), el número de bytes asignados o liberados (argumento bytes) y si la devolución de llamada se invoca después de que tuvo lugar la asignación o liberación (argumento post). La función de devolución de llamada puede ser llamada desde múltiples hilos concurrentemente.

La aplicación puede rastrear el uso actual de memoria del dispositivo Embree acumulando atómicamente el parámetro de entrada bytes proporcionado a la función de devolución de llamada. Este parámetro será >0 para las asignaciones y <0 para las liberaciones.

Embree continuará su operación normalmente al retornar true desde la función de devolución de llamada. Si se retorna false, Embree cancelará la operación actual con el código de error RTC_ERROR_OUT_OF_MEMORY. Se permiten realizar múltiples solicitudes de cancelación desde diferentes hilos. La cancelación solo ocurrirá cuando la devolución de llamada se realizó para asignaciones (bytes > 0), de lo contrario, se ignorará la solicitud de cancelación.

Si se invocó una devolución de llamada para cancelar antes de que ocurriera la asignación (post == false), entonces los bytes del parámetro no deben acumularse, ya que la asignación nunca ocurrirá. Si la devolución de llamada para cancelar se invocó después de que ocurrió la asignación (post == true), entonces los bytes del parámetro deben acumularse, ya que la asignación ocurrió correctamente y una liberación posterior liberará ese bloque de datos.

ESTADO DE SALIDA

En caso de error, se establece un código de error que se puede consultar usando rtcGetDeviceError.

VER TAMBIÉN

[rtcNewDevice]
