NOMBRE

rkhunter - Rastreador de Rootkits

SINOPSIS

rkhunter {--check | --unlock | --update | --versioncheck |
--propupd [{nombre de archivo | directorio | nombre de paquete},...] |
--list [tests | {lang | idiomas} | rootkits | perl |
propfiles] |
--config-check | --version | --help} [opciones]

DESCRIPCIÓN

rkhunter es un script de shell que lleva a cabo varias comprobaciones en el sistema local para intentar detectar rootkits y malware conocidos. También realiza comprobaciones para ver si los comandos han sido modificados, si los archivos de inicio del sistema han sido modificados y varias comprobaciones en las interfaces de red, incluidas las comprobaciones de aplicaciones en escucha.

rkhunter ha sido escrito para ser lo más genérico posible, por lo que debería ejecutarse en la mayoría de los sistemas Linux y UNIX. Se proporciona con algunos scripts de soporte en caso de que falten ciertos comandos en el sistema, y algunos de estos son scripts de perl. rkhunter requiere ciertos comandos presentes para poder ejecutarse. Adicionalmente, algunas pruebas requieren comandos específicos, pero si estos no están presentes, la prueba se omitirá. rkhunter necesita ser ejecutado bajo un shell tipo Bourne, típicamente bash o ksh. rkhunter puede ser ejecutado como un trabajo cron o desde la línea de comandos.

OPCIONES DE COMANDO

Si no se proporciona ninguna opción de comando, se asume --help. rkhunter devolverá un código de salida distinto de cero si ocurre algún error o advertencia.

-c, --check
Esta opción de comando le dice a rkhunter que realice varias comprobaciones en el sistema local. El resultado de cada prueba se mostrará en stdout. Si se encuentra algo sospechoso, se mostrará una advertencia. Se generará automáticamente un archivo de registro de las pruebas y los resultados.

Se sugiere que esta opción de comando se ejecute regularmente para garantizar que el sistema no haya sido comprometido.

--unlock
Esta opción de comando simplemente desbloquea (elimina) el archivo de bloqueo. Si esta opción se usa sola, no se crea ningún archivo de registro.
--update
Esta opción de comando hace que rkhunter compruebe si hay una versión posterior de alguno de sus archivos de datos de texto. Debe haber un navegador web de línea de comandos, por ejemplo wget o lynx, presente en el sistema al usar esta opción.

Se sugiere que esta opción de comando se ejecute regularmente para garantizar que los archivos de datos se mantengan actualizados.

Si esta opción se usa a través de cron, se recomienda que también se use la opción --nocolors.

Un código de salida de cero para esta opción de comando significa que no había actualizaciones disponibles. Un código de salida de uno significa que ocurrió un error de descarga, y un código de dos significa que no ocurrió ningún error pero había actualizaciones disponibles y se han instalado.

--propupd [{nombre de archivo | directorio | nombre de paquete},...]
Una de las comprobaciones que realiza rkhunter es comparar las propiedades actuales de varios archivos de comandos, con las que ha almacenado previamente. Esta opción de comando hace que rkhunter actualice su archivo de datos de valores almacenados con los valores actuales.

Si se usa la opción nombre de archivo, debe ser una ruta de acceso completa o un nombre de archivo simple (por ejemplo, 'awk'). Cuando se usa, solo se actualizará la entrada en la base de datos de propiedades de archivos para ese archivo. Si se usa la opción directorio, solo se actualizarán los archivos listados en la base de datos que se encuentren en el directorio dado. De manera similar, si se usa la opción nombre de paquete, solo se actualizarán los archivos en la base de datos que formen parte del paquete especificado. El nombre del paquete debe ser la parte base del nombre, no se deben incluir números de versión; por ejemplo, 'coreutils'. Los nombres de paquetes, por supuesto, solo se almacenarán en la base de datos de propiedades de archivos si se está utilizando un gestor de paquetes. Si un nombre de paquete es el mismo que un nombre de archivo - por ejemplo, 'file' podría referirse al comando 'file' o al paquete RPM 'file' (que contiene el comando 'file') - se usará el nombre del paquete. Si no se proporciona ninguna opción específica, se actualiza toda la base de datos.

ADVERTENCIA: Es responsabilidad del usuario asegurarse de que los archivos del sistema sean genuinos y provengan de una fuente confiable. rkhunter solo puede informar si un archivo ha cambiado, pero no sobre qué ha causado el cambio. Por lo tanto, si un archivo ha cambiado y se usa la opción de comando --propupd, rkhunter asumirá que el archivo es genuino.

--versioncheck
Esta opción de comando hace que rkhunter compruebe si hay una versión posterior del programa. Debe haber un navegador web de línea de comandos presente en el sistema al usar esta opción.

Si esta opción se usa a través de cron, se recomienda que también se use la opción --nocolors.

Un código de salida de cero para esta opción de comando significa que no había ninguna versión nueva disponible. Un código de salida de uno significa que ocurrió un error al descargar el número de versión más reciente, y un código de dos significa que no ocurrió ningún error pero hay una nueva versión disponible.

--list [tests | {lang | idiomas} | rootkits | perl | propfiles]
Esta opción de comando listará algunas de las capacidades soportadas del programa y luego saldrá. La opción tests lista los nombres de las pruebas disponibles actualmente (ver el archivo README para más detalles sobre los nombres de las pruebas). La opción languages lista los idiomas actualmente disponibles, y la opción rootkits lista los rootkits que son buscados por rkhunter. La opción perl lista el estado de instalación del comando perl y los módulos perl que pueden ser utilizados por algunas de las pruebas. Tenga en cuenta que no es necesario instalar estos módulos. Sin embargo, si rkhunter se ve obligado a usar perl para ejecutar una prueba, el módulo debe estar presente. La opción propfiles listará los nombres de los archivos que se utilizan para generar la base de datos de propiedades de archivos. Si no se proporciona ninguna opción específica, se muestran todas las listas, excepto la base de datos de propiedades de archivos.
-C, --config-check
Esta opción de comando hace que rkhunter compruebe sus archivos de configuración y luego salga. El programa realizará sus comprobaciones normales de configuración según lo especificado por las opciones de habilitar y deshabilitar en la línea de comandos y en los archivos de configuración. Es decir, solo se comprobarán las opciones de configuración de las pruebas que normalmente se ejecutarían. Para comprobar todas las opciones configuradas, utilice las opciones --enable all --disable none en la línea de comandos. Adicionalmente, el programa comprobará si hay alguna opción de configuración no reconocida. Si se encuentran problemas de configuración, se mostrarán y el código de retorno se establecerá en 1.

Se sugiere que esta opción se utilice siempre que se hayan modificado los archivos de configuración.

-V, --version
Esta opción de comando hace que rkhunter muestre su número de versión y luego salga.
-h, --help

Esta opción de comando muestra el menú de pantalla de ayuda y luego sale.

OPCIONES

rkhunter utiliza un archivo de configuración, llamado rkhunter.conf, para muchas de sus opciones de configuración. También puede utilizar un archivo de configuración local, llamado rkhunter.conf.local, y un directorio llamado rkhunter.d si está presente. Tanto el archivo de configuración local como el directorio local deben estar en el mismo directorio que el archivo de configuración principal. El instalador no crea el archivo o directorio local, pero uno, o ambos, pueden ser creados por el usuario si es necesario. Algunas opciones también se pueden especificar en la línea de comandos, y estas anularán las opciones equivalentes del archivo de configuración. Las opciones del archivo de configuración están bien documentadas dentro del propio archivo de configuración principal. Las siguientes son las opciones de la línea de comandos. Los valores predeterminados mencionados aquí son los valores predeterminados del programa, a menos que se indique explícitamente como el valor predeterminado del archivo de configuración.

--appendlog
Por defecto, se creará un nuevo archivo de registro cuando se ejecute rkhunter y el archivo de registro anterior se renombrará añadiéndole .old. Esta opción indica a rkhunter que añada al archivo de registro existente. Si el archivo de registro no existe, se creará.
--bindir <directorio>...
Esta opción modifica los directorios en los que rkhunter busca para encontrar los diversos comandos que requiere (es decir, su PATH). El valor predeterminado es el PATH raíz y una lista interna de algunos directorios de comandos comunes. Por defecto, un directorio especificado se añadirá a la lista predeterminada. Sin embargo, si el nombre del directorio comienza con el carácter '+', se antepondrá a la lista (es decir, se colocará al principio de la lista).
--cs2, --color-set2
Por defecto, rkhunter mostrará los resultados de sus pruebas en color. Los colores utilizados son verde para las pruebas exitosas, rojo para las pruebas fallidas (advertencias) y amarillo para las pruebas omitidas. Estos colores son visibles cuando se usa un fondo negro, pero son difíciles de ver sobre un fondo blanco. Esta opción indica a rkhunter que utilice un conjunto de colores diferente que se adapte mejor a un fondo blanco.
--configfile <archivo>
El proceso de instalación indicará automáticamente a rkhunter dónde se encuentra su archivo de configuración. Sin embargo, si es necesario, esta opción se puede utilizar para especificar una ruta diferente.

Si se va a utilizar un archivo de configuración local o un directorio, este debe residir en el mismo directorio que el archivo de configuración especificado por esta opción.

--cronjob
Esto es similar a la opción de comando --check, pero deshabilita varias de las opciones interactivas. Cuando se utiliza esta opción, se asumen --check, --nocolors y --skip-keypress. Por defecto, no se envía ninguna salida a stdout, por lo que la opción --report-warnings-only puede ser útil con esta opción.
--dbdir <directorio>
El proceso de instalación configurará automáticamente dónde se almacenan los archivos de datos para rkhunter. Sin embargo, si es necesario, esta opción se puede utilizar para especificar un directorio diferente. El directorio puede ser de solo lectura, después de la instalación, siempre que no se especifiquen las opciones --update o --propupd, y que la opción --versioncheck no se especifique si ROTATE_MIRRORS se establece en 1 en el archivo de configuración.
--debug
Esta es una opción especial principalmente para los desarrolladores. No produce ninguna salida en stdout. El registro regular continuará según el valor predeterminado o según lo especificado por la opción --logfile, y la salida de depuración estará en un nombre de archivo generado aleatoriamente que comienza con /tmp/rkhunter-debug.
--disable <prueba>[,<prueba>...]
Esta opción indica a rkhunter que no ejecute las pruebas especificadas. Lea el archivo README para obtener más información sobre los nombres de las pruebas. Por defecto, no se deshabilita ninguna prueba.
--display-logfile
Esta opción hará que el archivo de registro se muestre en la pantalla una vez que rkhunter haya terminado.
--enable <prueba>[,<prueba>...]
Esta opción indica a rkhunter que ejecute solo las pruebas especificadas. Si solo se da un nombre de prueba, distinto de all, se asume la opción --skip-keypress. Lea el archivo README para obtener más información sobre los nombres de las pruebas. Por defecto, todas las pruebas están habilitadas. Todos los nombres de las pruebas se enumeran a continuación en PRUEBAS.
--hash {MD5 | SHA1 | SHA224 | SHA256 | SHA384 | SHA512 |
NONE | <comando>}
Tanto la comprobación de propiedades de archivos como la opción de comando --propupd utilizarán una función hash para determinar el valor hash actual de un archivo. Esta opción indica a rkhunter qué función hash utilizar. Las opciones MD5 y SHA buscarán el comando relevante y, si no se encuentra, se utilizará un script de soporte de perl para ver si se ha instalado un módulo de perl que admita la función. Alternativamente, se puede especificar un comando específico. Se puede usar un valor de NONE para indicar que los valores hash no se deben obtener ni utilizar como parte de la comprobación de propiedades de archivos. El valor predeterminado es SHA256.

Los sistemas que utilizan prelinking deben usar MD5, SHA1 o NONE.

--lang, --language <idioma>
Esta opción especifica qué idioma utilizar para las pruebas y los resultados mostrados. Los idiomas actualmente admitidos se pueden ver con la opción de comando --list. El valor predeterminado es en (inglés). Si un mensaje que se va a mostrar no se encuentra en el archivo de idioma, se utilizará la versión en inglés. Por lo tanto, el archivo de idioma inglés debe estar siempre presente. La opción de comando --update actualizará los archivos de idioma cuando haya nuevas versiones disponibles.
-l, --logfile [archivo]
Por defecto, rkhunter escribirá un archivo de registro. La ubicación predeterminada del archivo es /var/log/rkhunter.log. Sin embargo, esta ubicación se puede cambiar utilizando esta opción. Si se especifica /dev/null como archivo de registro, no se escribirá ningún archivo de registro. Si no se proporciona un archivo específico, se utilizará el valor predeterminado. Por defecto, rkhunter creará un nuevo archivo de registro cada vez que se ejecute. Cualquier archivo de registro existente se aparta y se le añade .old.
--noappend-log
Esta opción devuelve rkhunter a su comportamiento predeterminado de crear un nuevo archivo de registro en lugar de añadirle información.
--nocf

Esta opción solo es válida cuando se utiliza la opción de línea de comandos --disable. Cuando se utiliza la opción --disable, por defecto, la opción del archivo de configuración para deshabilitar pruebas también se utiliza para determinar qué pruebas ejecutar. Si solo se va a utilizar la opción --disable para determinar qué pruebas ejecutar, se debe proporcionar --nocf.
--nocolors
Esta opción hace que el resultado de cada prueba no se muestre en un color específico. Se utilizará el color predeterminado, generalmente el inverso del color de fondo (típicamente es solo blanco y negro).
--nolog
Esta opción indica a rkhunter que no escriba nada en un archivo de registro.
--nomow, --no-mail-on-warning
El archivo de configuración tiene una opción que provocará que se envíe un mensaje de correo electrónico simple a un usuario si rkhunter detecta alguna advertencia durante las comprobaciones del sistema. Esta opción de línea de comandos anula la opción del archivo de configuración y evita que se envíe un mensaje de correo electrónico. El valor predeterminado del archivo de configuración es no enviar un mensaje por correo electrónico.
--ns, --nosummary
Cuando se utiliza la opción de comando --check, por defecto se muestra un breve resumen de los resultados al final. Esta opción evita que se muestre el resumen.
--novl, --no-verbose-logging
Durante algunas pruebas, rkhunter registrará mucha información. El uso de esta opción reduce la cantidad de registro y, por lo tanto, puede mejorar el rendimiento de rkhunter. Sin embargo, el archivo de registro contendrá menos información si ocurren advertencias. Por defecto, el registro detallado está habilitado.
--pkgmgr {RPM | DPKG | BSD | BSDng | SOLARIS | NONE}
Esta opción se utiliza durante la comprobación de propiedades de archivos o cuando se proporciona la opción de comando --propupd. Indica a rkhunter que los valores de propiedad de archivos actuales deben obtenerse del gestor de paquetes correspondiente. Consulte el archivo README para obtener más detalles sobre esta opción. El valor predeterminado es NONE, lo que significa no utilizar un gestor de paquetes.
-q, --quiet
Esta opción indica a rkhunter que no muestre ninguna salida. Puede ser útil cuando solo se va a comprobar el código de salida. Se pueden utilizar otras opciones con esta para forzar la visualización solo de elementos específicos.
--rwo, --report-warnings-only
Esta opción hace que solo se muestren los mensajes de advertencia. Esto puede ser útil cuando rkhunter se ejecuta a través de cron. Se pueden utilizar otras opciones para forzar la visualización de otros elementos de información.
--sk, --skip-keypress
Cuando se utiliza la opción de comando --check, después de ciertas secciones de pruebas, se le pedirá al usuario que presione la tecla intro para continuar. Esta opción deshabilita esa función y rkhunter se ejecutará hasta que todas las pruebas hayan finalizado.

Si no se ha proporcionado esta opción, y se le pide al usuario que presione la tecla intro, se puede introducir una sola letra 's', en mayúscula o minúscula, seguida de la tecla intro. rkhunter continuará las pruebas sin pedir más confirmación al usuario (como si se hubiera proporcionado esta opción).

--summary
Esta opción hará que se muestre el resumen de los resultados de las pruebas. Este es el valor predeterminado.
--syslog [facility.priority]
Cuando se utiliza la opción de comando --check, esta opción hará que las horas de inicio y finalización se registren en syslog. El valor predeterminado es no registrar nada en syslog, pero si se utiliza la opción, el nivel predeterminado es authpriv.notice.

NAME

rkhunter

Rootkit scanner

SYNOPSIS

rkhunter [ option | test ] ...

DESCRIPTION

rkhunter (RootKit Hunter) is an utility that scans for rootkits, backdoors and local exploits. It performs several checks on the local system to find signs of infection.

These checks include:

  • Checking for the presence of known rootkits.
  • Checking for suspicious file permissions.
  • Checking for suspicious file attributes.
  • Checking for suspicious kernel modules.
  • Checking for suspicious running processes.
  • Checking for suspicious network listening ports.
  • Checking for suspicious hidden files.
  • Checking for suspicious configuration files.
  • Checking for suspicious startup files.
  • Checking for suspicious shared libraries.
  • Checking for suspicious application settings.
  • Checking for suspicious cron jobs.
  • Checking for suspicious application modules.

If rkhunter finds any suspicious files or settings, it will warn the user. The user can then decide whether to take action or not.

COMMAND OPTIONS

The following options are available:

--append-log
Append the results of the current scan to the log file. The default is to overwrite the log file.
--booleans
--color COLORED
Use the specified colours in the output. The default is to use the colour set determined by the "Colour" option in the configuration file. See the "Colour" option documentation.
--color-set2
Use the second colour set. This is intended for use when rkhunter is run on a terminal where the X Window system is in use. See the "Colour" option documentation.
--configfile FILE
Use the specified configuration file instead of the default /etc/rkhunter.conf.
--dbdir DIRECTORY
Use the specified directory for the rkhunter database files. The default is /var/lib/rkhunter.local.
--debug
Show debug messages.
--disable TEST[,TEST::]
Disable the specified test(s). Use the test names as shown by the "--list-tests" option. The default is to run all tests.
--display-config
Display the configuration file options.
--disable-event EVENT[,EVENT::]
Disable the specified event(s). The default is to log all events.
--enable TEST[,TEST::]
Enable the specified test(s). Use the test names as shown by the "--list-tests" option. The default is to run all tests.
--file-permissions
Check file permissions.
--graphics
Use graphics in the output. The default is to use text.
--group
Check group accounts.
-h, --help
Show help message.
--immutable
Check for immutable files.
--introvert
This option is ignored. It is included for compatibility with older versions.
--lang LANG
Use the specified language for the output. The default is English.
--list-all-tests
List all available tests.
--list-enabled-tests
List all enabled tests.
--list-tests
List all available tests.
--log FILE
Use the specified file for logging. The default is /var/log/rkhunter.log.
--lowercase
Use lowercase for all text in the output. The default is to use the case specified in the configuration file.
--prop
Check file properties.
--rootkits
Check for known rootkits.
--ruler
Draw a ruler in the output.
--skip-keypress
Do not wait for a keypress before starting the scan.
--skip-modules
Do not scan for kernel modules.
--skip-routines
Do not scan for rootkit routines.
--suspscan
Perform a suspicious scan.
--update
Update the rkhunter data files.
--update-check
Check for updates to the rkhunter data files.
--version
Show version information.
-V, --verbose
Show verbose output.
--vl, --verbose-logging
This option tells rkhunter that when it runs some tests, it should log as much information as possible. This can be useful when trying to diagnose why a warning has occurred, but it obviously also takes more time. The default is to use verbose logging.
-x, --autox
When this option is used, rkhunter will try and detect if the X Window system is in use. If it is in use, then the second color set will automatically be used (see the --color-set2 option). This allows rkhunter to be run on, for example, a server console (where X is not present, so the default color set should be used), and on a users terminal (where X is in use, so the second color set should be used). In both cases rkhunter will use the correct color set. The configuration file default is to try and detect X.
-X, --no-autox
This option prevents rkhunter from automatically detecting if the X Window system is being used. See the --autox option.
