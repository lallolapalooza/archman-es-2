R2E(1) Manual de Comandos Generales R2E(1)

NOMBRE

r2e - recibir feeds RSS por correo electrónico

SINOPSIS

r2e [opciones] <comando> [argumentos]

DESCRIPCIÓN

r2e es un programa simple que puedes ejecutar en tu crontab(5). Supervisa los feeds RSS y te envía un mensaje de correo electrónico bien formateado para cada elemento nuevo.

Para empezar rápidamente con r2e, prueba estos pasos:

r2e new tu@tudominio.com
r2e add nombrefeed http://feed.url/somewhere.rss
r2e run

El último comando debería incluirse eventualmente en tu crontab si quieres que las cosas se te envíen automáticamente.

OPCIONES

-h, --help
Imprime la ayuda de rss2email y sale.
-v, --version
Imprime la versión de rss2email y sale.
--full-version
Imprime las versiones de Python, el compilador utilizado para compilar Python y los paquetes utilizados por rss2email.
-c, --config <ruta>
La configuración del programa se lee desde $XDG_CONFIG_HOME/rss2email.cfg por defecto (ver también ARCHIVOS y VARIABLES DE ENTORNO a continuación). Usa esta opción para establecer un archivo de configuración diferente.
-d, --data <ruta>
Los datos dinámicos del programa se leen desde $XDG_DATA_HOME/rss2email.json por defecto (ver también ARCHIVOS y VARIABLES DE ENTORNO a continuación). Usa esta opción para establecer un archivo de datos diferente.
-V, --verbose
Incrementa la verbosidad del registro.

COMANDOS

new [<email>]
Crea una nueva base de datos de feeds. Si se proporciona el argumento <email>, establece la dirección de correo electrónico predeterminada a la que se envían los correos.
email [<email>]
Actualiza la dirección de correo electrónico de destino predeterminada a <email>.
add [--only-new] <nombre> <url> [<email>]
Suscríbete a un feed. El argumento <nombre> le da un nombre al feed para manipulación futura. <url> es la URL del feed. El argumento opcional <email> es la dirección de correo electrónico a la que se enviarán los elementos nuevos, anulando la dirección predeterminada para este feed en particular. Repite para cada feed al que quieras suscribirte.
La opción --only-new recupera el feed al momento de la adición sin enviar las entradas, haciendo que la ejecución posterior de run las considere como ya enviadas. Debe usarse cuando uno solo está interesado en entradas que aún no están en el feed en el momento de ejecutar add.
run [--no-send] [--clean] [<indice> [<indice> ...]]
Escanea los feeds y envía correos electrónicos para elementos nuevos. Esto se puede ejecutar en un trabajo cron.
La opción --no-send detiene que r2e envíe cualquier correo electrónico. Esto puede ser útil la primera vez que lo ejecutes, ya que de lo contrario enviaría un correo electrónico por cada entrada de feed disponible.

La opción --clean reduce el tamaño de la base de datos eliminando entradas antiguas. Fuerza la descarga de feeds seleccionados o de todos los feeds, y solo debe usarse semanal o mensualmente.

Si se especifica un <indice>, r2e solo descargará ese feed. <indice> puede ser el nombre del feed (como lo establece add) o el índice del feed (como lo muestra list).

list
Lista todos los feeds en la base de datos.
pause [<indice> [<indice> ...]]
Pausa feeds (deshabilita la recuperación). La opción <indice> selecciona los feeds a pausar (ver run para valores posibles). Si no se proporciona <indice>, se pausan todos los feeds.
unpause [<indice> [<indice> ...]]
Reanuda feeds (habilita la recuperación).
delete <indice> [<indice> [<indice> ...]]
Elimina un feed (o feeds) de la base de datos. La opción <indice> selecciona los feeds a eliminar (ver run para valores posibles).
reset [<indice> [<indice> ...]]
Olvida los datos dinámicos del feed (por ejemplo, para reenviar entradas antiguas). La opción <indice> selecciona los feeds a restablecer (ver run para valores posibles). Si no se proporciona <indice>, se restablecen todos los feeds.
opmlimport [<ruta>]
Importa nuevos feeds desde OPML. <ruta> es el archivo del cual se leerán los datos OPML. Si no se proporciona <ruta>, r2e lee los datos desde la entrada estándar.
opmlexport [<ruta>]
Exporta todos los feeds a OPML. <ruta> es el archivo al cual se escribirán los datos OPML. Si no se proporciona <ruta>, r2e escribe los datos en la salida estándar.

CONFIGURACIÓN

El comportamiento del programa puede controlarse a través de $XDG_CONFIG_HOME/rss2email.cfg (ver también ARCHIVOS y VARIABLES DE ENTORNO a continuación). El formato del archivo es similar a un archivo INI de Microsoft Windows. Es analizado por la clase ConfigParser de Python, así que consulta la documentación de Python en http://docs.python.org/3/library/configparser.html para detalles del formato.

El archivo de configuración almacena la configuración general (aplicada a todos los feeds) en la sección [DEFAULT]. El comando new creará un archivo de configuración por ti, que puedes editar como mejor te parezca. El comando add agregará secciones específicas para cada feed. Para anular cualquier configuración para todos los feeds, cambia el valor en la sección [DEFAULT]. Para anular una configuración para un feed en particular, agrega esa configuración a la sección específica del feed. Aquí hay un ejemplo que anula use-publisher-email y name-format para el feed nombrefeed.

[DEFAULT]
from = user@rss2email.invalid
force-from = False
use-publisher-email = False
name-format = {feed-title}: {author}
  ...
verbose = warning
[feed.nombrefeed]
url = http://feed.url/somewhere.rss
use-publisher-email = True
name-format = {author} ({feed.title})

Puedes configurar los siguientes elementos:

Direccionamiento

from
La dirección de correo electrónico desde la que provienen los mensajes por defecto
use-8bit
Transfer-Encoding. Para el correo local, es seguro y conveniente usar 8bit.
force-from
True: Usa solo la dirección 'from'. False: Usa la dirección de correo electrónico especificada por el feed, cuando sea posible.
use-publisher-email
True: Usa el correo electrónico del editor si no puedes encontrar el del autor. False: Simplemente usa la dirección de correo electrónico 'from' en su lugar.
name-format
Si está vacío, usa solo la dirección de correo electrónico del feed en lugar del nombre de visualización más la dirección de correo electrónico. Los atributos disponibles pueden incluir 'feed', 'feed-name', 'feed-url', 'feed-title', 'author' y 'publisher', pero solo 'feed', 'feed-name' y 'feed-url' están garantizados.
to
Establece esto a las direcciones de correo electrónico de To predeterminadas.

Recuperación

proxy
Establece un proxy HTTP (por ejemplo, 'http://tu.proxy.aqui:8080/')
feed-timeout<

NAME

rss2email - convert RSS feeds to email

SYNOPSIS

r2e [-h] [-V] [-c file] [-d file] [-l feed] [-r feed] [-R] [-a] [-t]

DESCRIPTION

rss2email is a tool that retrieves RSS feeds, processes them, and emails the contents to you. It is configurable via a configuration file, defaults to $HOME/.config/rss2email.cfg.

The configuration file is a Python file. Settings are global, but can be overridden on a per-feed basis. To override a global setting, you can append a new line for the feed in question to the configuration file that looks like:

feed-name = value

where feed-name is the name of the feed, and value is the overridden setting.

All settings are optional. If a setting is not specified, a default value is used.

The configuration file is parsed by ConfigParser. See the section below for a list of configuration variables.

By default, rss2email creates a database of entries it has already sent. This prevents duplicate emails. The database is stored in $HOME/.local/share/rss2email.json.

Command Line Options

-h
Print a help message and exit.
-V
Print program version and exit.
-c
Use configuration file file instead of the default. Multiple configuration files may be specified.
-d
Use database file file instead of the default. This option is only effective if file does not already exist.
-l
List feeds that are currently subscribed to.
-r
Remove feed feed from the database.
-R
Remove all feeds from the database.
-a
Add feed feed to the database. This option is only effective if the feed is not already in the database.
-t
Test configuration by sending a test email. This option implies 'active = True'.

CONFIGURATION

Configuration settings are specified in a Python configuration file. The following settings are available:

General

feeds
A list of dictionaries, each representing a feed to subscribe to. Each dictionary should have a 'url' key. Other optional keys include 'name', 'email', and 'interval'. If 'name' is not specified, it defaults to the feed's title. If 'email' is not specified, it defaults to the user's email address. If 'interval' is not specified, it defaults to 24 hours.
timeout
Set the timeout (in seconds) for feed server response

Processing

active
True: Fetch, process, and email feeds. False: Don't fetch, process, or email feeds
digest
True: Send a single, multi-entry email per feed per rss2email run. False: Send a single email per entry.
digest-type
Message content-type for digests. Valid values are 'multipart/digest' and 'multipart/mixed'. The former is the default, but many mail user agents do not support it.
date-header
True: Generate Date header based on item's date, when possible. False: Generate Date header based on time sent.
date-header-order
A comma-delimited list of some combination of ('issued', 'created', 'modified', 'expired') expressing ordered list of preference in dates to use for the Date header of the email.
bonus-header
Set this to add bonus headers to all emails Example: bonus-header = 'Approved: joe@bob.org'
trust-guid
True: Receive one email per post. False: Receive an email every time a post changes.
trust-link
True: Receive one email per unique link url. False: Defer to trust-guid preference. Toggling this for existing feeds may result in duplicates, because the old entries will not be recorded under their new link-based ids.
encodings
To most correctly encode emails with international characters, we iterate through the list below and use the first character set that works.
post-process
User processing hooks. Note the space after the module name. Example: post-process = 'rss2email.post_process.downcase downcase_message'
digest-post-process
User processing hooks for digest messages. If 'digest' is enabled, the usual 'post-process' hook gets to message the per-entry messages, but this hook is called with the full digest message before it is mailed. Example: digest-post-process = 'rss2email.post_process.downcase downcase_message'
subject-format
The format for the Subject line. Available attributes are 'feed', 'feed-name', 'feed-url', 'feed-title'.

HTML conversion

html-mail
True: Send text/html messages when possible. False: Convert HTML to plain text.
use-css
Use CSS
css
Optional CSS styling

html2text options

unicode-snob
Use Unicode characters instead of their ascii psuedo-replacements
links-after-each-paragraph
Put the links after each paragraph instead of at the end.
inline-links
Use inline, rather than reference, formatting for images and links.
wrap-links
Wrap links according to body width.
body-width
Wrap long lines at position. Any negative value for no wrapping, 0 for 78 width (compatibility), or any positive width.

Mailing

email-protocol
Select protocol from: sendmail, smtp, imap, maildir
sendmail
Path to sendmail (or compatible)

SMTP configuration

smtp-auth
Set to True to use SMTP AUTH
smtp-username
username for SMTP AUTH
smtp-password
password for SMTP AUTH
smtp-server
SMTP server
smtp-ssl
Connect to the SMTP server using SSL

IMAP configuration

imap-auth
set to True to use IMAP auth.
imap-username
username for IMAP authentication
imap-password
password for IMAP authentication
imap-server
IMAP server
imap-port
IMAP port
imap-ssl
connect to the IMAP server using SSL
imap-mailbox
where we should store new messages

Maildir configuration

maildir-path
Path of maildir to write messages into
maildir-mailbox
Mailbox within maildir-path to write messages into

Miscellaneous

user-agent
String to use as HTTP User-Agent in web requests and as the User-Agent header in outgoing emails. If present, __VERSION__ and __URL__ are replaced with rss2email version number and webpage.
verbose
Verbosity (one of 'error', 'warning', 'info', or 'debug').

FILES

$XDG_CONFIG_HOME/rss2email.cfg
If this file exists, it is read to configure the program.
$XDG_DATA_HOME/rss2email.json
The database of feeds. Use r2e to add, remove, or modify feeds, do not edit it directly.

ENVIRONMENT VARIABLES

The environment variables used by r2e are all defined in the XDG Base Directory Specification, which aims to standardize locations for user-specific configuration and data files.

XDG_CONFIG_HOME
The preferred directory for configuration files. Defaults to $HOME/.config.
XDG_DATA_HOME
The preferred directory for data files. Defaults to $HOME/.local/share.
XDG_RUNTIME_DIR
The preferred directory for lockfiles. Defaults to /tmp/rss2email-UID
XDG_CONFIG_DIRS
A colon ':' separated, preference ordered list of base directories for configuration files in addition to $XDG_CONFIG_HOME. Defaults to /etc/xdg. If multiple configuration files are found in this path, they will all be read by the ConfigParser class (see also CONFIGURATION above).
XDG_DATA_DIRS
A colon ':' separated, preference ordered list of base directories for data files. Defaults to /usr/local/share/:/usr/share/. Only the first matching file is used.
