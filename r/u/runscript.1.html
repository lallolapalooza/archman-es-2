RUNSCRIPT(1) Manual de Comandos Generales RUNSCRIPT(1)

NOMBRE

runscript - intérprete de scripts para minicom

SINOPSIS

runscript nombre_script [archivo_log [directorio_home]]

DESCRIPCIÓN

runscript es un intérprete de scripts simple que puede ser llamado desde dentro del programa de comunicaciones minicom para automatizar tareas como iniciar sesión en un sistema Unix o tu BBS favorito.

INVOACIÓN

El programa espera un nombre de script y opcionalmente un nombre de archivo y el directorio personal del usuario como argumentos, y espera que su entrada y salida estén conectadas al "extremo remoto", el sistema al que te estás conectando. Todos los mensajes de runscript destinados a la pantalla local se dirigen a la salida stderr. Todo esto se maneja automáticamente si lo ejecutas desde minicom. Los parámetros de archivo_log y directorio_home solo se utilizan para indicar al comando log el nombre del archivo de registro y dónde escribirlo. Si se omite el directorio_home, runscript utiliza el directorio que se encuentra en la variable de entorno $HOME. Si también se omite el nombre del archivo de registro, los comandos log se ignoran.

PALABRAS CLAVE

Runscript reconoce los siguientes comandos:

expect   send     goto     gosub    return   !<   !
exit     print    set      inc      dec      if   timeout
verbose  sleep    break    call     log

RESUMEN DE PALABRAS CLAVE

send <cadena>
Se envía <cadena> al módem. Le sigue un '\r'. <cadena> puede ser:
- texto normal, p.ej. 'send hola'
- texto entre comillas, p.ej. 'send "hola mundo"'

Dentro de <cadena> se reconocen las siguientes secuencias:

\n - nueva línea
\r - retorno de carro
\a - campana
\b - retroceso
\c - no enviar el '\r' por defecto.
\f - avance de página
\^ - el carácter ^
\o - enviar el carácter o (o es un número octal)

Los caracteres de control se pueden usar en la cadena con el prefijo ^ (^A a ^Z, ^[, ^ ^], ^^ y ^_). Si necesita enviar el carácter ^, debe prefijarlo con el carácter de escape \.
Los caracteres octales son de cuatro dígitos o delimitados por un carácter no numérico, p.ej., el carácter nulo se puede enviar con \0000 y 'send 1234' es equivalente a 'send \0061234'.
También se puede usar $(variable_entorno), por ejemplo $(TERM). Minicom pasa tres variables de entorno especiales: $(LOGIN), que es el nombre de usuario, $(PASS), que es la contraseña, como se define en la entrada correspondiente del directorio de marcación, y $(TERMLIN) que es el número de líneas de terminal reales en su pantalla (es decir, excluyendo la línea de estado).

print <cadena>
Imprime <cadena> en la pantalla local. Por defecto seguido de '\r\n'. Ver la descripción de 'send' arriba.
etiqueta:
Declara una etiqueta (con el nombre 'etiqueta') para usar con goto o gosub.
goto <etiqueta>
Salta a otro lugar en el programa.
gosub <etiqueta>
Salta a otro lugar en el programa. Cuando se encuentra la sentencia 'return', el control vuelve a la sentencia después del gosub. Los Gosub se pueden anidar.
return
Regresa de un gosub.
! <comando>
Ejecuta un shell para ti en el que se ejecuta 'comando'. Al regresar, la variable '$?' se establece al estado de salida de este comando, por lo que posteriormente puedes probarlo usando 'if'.
!< <comando>
Ejecuta un shell para ti en el que se ejecuta 'comando'. La salida stdout de la ejecución del comando se enviará al módem. Al regresar, la variable '$?' se establece al estado de salida de este comando, por lo que posteriormente puedes probarlo usando 'if'.
exit [valor]
Sale de "runscript" con un estado de salida opcional. (por defecto 1)
set <variable> <valor>
Establece el valor de <variable> (que es una sola letra a-z) al <valor>. Si <variable> no existe, se creará. <valor> puede ser un valor entero u otra variable.
inc <variable>
Incrementa el valor de <variable> en uno.
dec <variable>
Decrementa el valor de <variable> en uno.
if <valor> <operador> <valor> <sentencia>
Ejecución condicional de <sentencia>. <operador> puede ser <, >, != o =. Por ejemplo, 'if a > 3 goto exitlabel'.
timeout <valor>
Establece el tiempo de espera global. Por defecto, 'runscript' saldrá después de 120 segundos. Esto se puede cambiar con este comando. Advertencia: este comando actúa de manera diferente dentro de una sentencia 'expect', pero más sobre eso después.
verbose <on|off>
Por defecto, esto está 'on'. Eso significa que cualquier cosa que se esté leyendo del módem por 'runscript' se refleja en la pantalla. Esto es para que puedas ver lo que está haciendo 'runscript'.
sleep <valor>
Suspende la ejecución durante <valor> segundos.
expect
  expect {
    patrón  [sentencia]
    patrón  [sentencia]
    [timeout <valor> [sentencia] ]
    ....
  }
El comando más importante de todos. Expect sigue leyendo de la entrada hasta que lee un patrón que coincide con uno de los especificados. Si expect encuentra una sentencia opcional después de ese patrón, la ejecutará. De lo contrario, la acción por defecto es simplemente salir del expect. 'patrón' es una cadena, igual que en 'send' (ver arriba). Normalmente, expect agotará el tiempo de espera en 60 segundos y simplemente saldrá, pero esto se puede cambiar con el comando timeout.
break
Sale de una sentencia 'expect'. Esto normalmente solo es útil como argumento para 'timeout' dentro de un expect, ya que la acción por defecto de timeout es salir inmediatamente.
call <nombre_script>
Transfiere el control a otro archivo de script. Cuando ese archivo de script finaliza sin errores, el script original continuará.
log <texto>
Escribe texto en el archivo de registro.

NOTAS

Si quieres que tu script salga de minicom (por ejemplo, cuando usas minicom para marcar a tu ISP, y luego inicias una sesión PPP o SLIP desde un script), prueba el comando "! killall -9 minicom" como último comando del script. La opción -9 debería evitar que minicom cuelgue la línea y restablezca el módem antes de salir.
Bueno, no creo que esta sea suficiente información para convertirte en un 'programador' experimentado en 'runscript', pero junto con los ejemplos no debería ser demasiado difícil escribir algunos archivos de script útiles. Las cosas serán más fáciles si tienes experiencia con BASIC. El código fuente de minicom viene junto con dos scripts de ejemplo, scriptdemo y unixlogin. Especialmente el último es una buena base para construir tus propios scripts.

ERRORES

minicom(1) - Manual page

NAME

minicom - user friendly serial communication program

SYNOPSIS

minicom [ -c | -C file ] [ -d devicename ] [ -s ] [ -k ] [ -o ] [ -p protocol ] [ -g hostfile ] [ -w ] [ -l ] [ -f ] [ -r ] [ -R ] [ -t termtype ] [ -h ] [ -V ] [ -P pathname ] [ -S script ] [ -a ] [ -e ] [ -v ] [ -x ] [ -? ]

DESCRIPTION

minicom is a serial communication program for the Unix-like operating systems. It is designed to be user-friendly and easy to use. It supports all the common functions of a serial communication program, such as dialing, logging of sessions, file transfer, etc. It also supports script files for automating tasks.

INVOCATION

The minicom command can be invoked with several options. The most common ones are:

  • -c, -C file: Specifies the configuration file to be used.
  • -d devicename: Specifies the serial port to be used (e.g., /dev/ttyS0).
  • -s: Starts minicom in setup mode.
  • -k: Do not send K TERM variables.
  • -o: Offline mode.
  • -p protocol: Specifies the file transfer protocol to be used.
  • -g hostfile: Specifies the host file to be used.
  • -w: Wrap long lines.
  • -l: Line wrap.
  • -f: Full screen mode.
  • -r: Receive files.
  • -R: Receive files using Kermit.
  • -t termtype: Specifies the terminal type.
  • -h: Show help.
  • -V: Show version.
  • -P pathname: Specifies the pathname for scripts.
  • -S script: Specifies the script to be executed.
  • -a: Auto send.
  • -e: Echo input.
  • -v: Version.
  • -x: Extended help.
  • -?: Show help.

KEYWORDS

serial communication, modem, terminal, console

OVERVIEW OF KEYWORDS

minicom provides a set of keywords that can be used to configure its behavior. These keywords are typically defined in a configuration file (e.g., ~/.minirc).

Some common keywords include:

  • set port ...
  • set baudrate ...
  • set parity ...
  • set flowcontrol ...
  • set screen ...
  • set term ...
  • set cmd_send ...
  • set cmd_receive ...
  • set script ...

Refer to the minicom manual for a complete list of keywords and their options.

NOTES

minicom is a powerful tool for serial communication. It can be used to access remote systems, configure network devices, and perform other tasks that require serial communication. The configuration file allows for extensive customization of minicom's behavior.

SEE ALSO

screen(1), picocom(1), seyon(1)
