RUBBER(1) Manual de Comandos Generales RUBBER(1)

NOMBRE

rubber - un sistema de compilación para documentos LaTeX

SINOPSIS

rubber [opciones] fuentes ...
rubber-pipe [opciones]

DESCRIPCIÓN

Rubber es un envoltorio para LaTeX y programas complementarios. Su propósito es, dado un origen LaTeX a procesar, compilarlo las veces suficientes para resolver todas las referencias, ejecutando posiblemente programas satélite como BibTeX, makeindex, Metapost, etc. para producir archivos de datos apropiados.

El comando rubber compila completamente los documentos especificados. Los archivos fuente pueden ser tanto fuentes LaTeX (en cuyo caso el sufijo .tex puede omitirse) como documentos en un formato que Rubber sabe cómo traducir a LaTeX. Si una compilación falla, todo el proceso se detiene, incluyendo la compilación de los siguientes documentos en la línea de comandos, y rubber devuelve un código de salida distinto de cero.

El comando rubber-pipe hace lo mismo para un documento pero lee el fuente LaTeX desde la entrada estándar y vuelca el documento compilado a la salida estándar.

Alguna información no se puede extraer de las fuentes LaTeX. Este es el caso, por ejemplo, de las rutas de búsqueda (que se pueden especificar en variables de entorno como TEXINPUTS), o del estilo a usar con Makeindex. Para abordar este problema, se puede añadir información para Rubber en los comentarios de las fuentes LaTeX, ver la sección DIRECTIVAS.

OPCIONES

Las opciones se utilizan para elegir la acción a realizar o para configurar el proceso de compilación. Son prácticamente las mismas en rubber y rubber-pipe. Las opciones se analizan utilizando las convenciones de Getopt de GNU.

-b, --bzip2
Comprime el documento final (en formato bzip2). Esto es equivalente a decir -o bzip2 después de todas las demás opciones.
--clean
Elimina todos los archivos producidos por la compilación, en lugar de compilar el documento. Esta opción solo está presente en rubber. Se aplica a la compilación tal como se haría con las demás opciones de la línea de comandos, es decir, decir "rubber --clean foo" no eliminará foo.ps, mientras que decir "rubber --ps --clean foo" sí lo hará.
-c, --comando <comando>
Ejecuta el comando (o directiva) especificado antes de analizar los archivos de entrada. Ver la sección DIRECTIVAS para más detalles.
-e, --epilogo <comando>
Ejecuta el comando (o directiva) especificado después de analizar los archivos de entrada. Ver la sección DIRECTIVAS para más detalles.
-f, --forzar
Fuerza al menos una compilación de la fuente. Esto puede ser útil, por ejemplo, si alguna dependencia inusual fue modificada (p.ej., un paquete en un directorio del sistema). Esta opción es irrelevante en rubber-pipe.
-z, --gzip
Comprime el documento final (en formato gzip). Esto es equivalente a decir -o gz después de todas las demás opciones.
-h, --ayuda
Muestra la lista de todas las opciones disponibles y sale amablemente.
--inplace
Ve al directorio de los archivos fuente antes de compilar, de modo que los resultados de la compilación estén en el mismo lugar que sus fuentes.
--into <directorio>
Ve al directorio especificado antes de compilar, de modo que todos los archivos se produzcan allí y no en el directorio actual.
--jobname <nombre>
Especifica un nombre de trabajo diferente del nombre base del archivo. Esto cambia el nombre de los archivos de salida y solo se aplica al primer objetivo.
-k, --mantener
Esta opción solo se usa en rubber-pipe. Con esta opción, los archivos temporales no se eliminarán después de compilar el documento y volcar los resultados a la salida estándar. El documento temporal se llama rubtmpX.tex, donde X es un número tal que ningún archivo con ese nombre exista inicialmente.
-n, --maxerr <num>
Establece el número máximo de errores mostrados. Por defecto, se informan hasta 10 errores; decir -n -1 muestra todos los errores.
-m, --módulo <módulo>[:<args>]
Usa el módulo especificado además de los paquetes del documento. Se pueden pasar argumentos al paquete añadiéndolos después de dos puntos, corresponden a las opciones del paquete en LaTeX. El módulo se carga antes de analizar las fuentes del documento.
--only <fuentes>
Compila el documento parcialmente, incluyendo solo las fuentes especificadas. Esto funciona insertando una llamada a \includeonly en la línea de comandos. El argumento es una lista de nombres de archivo separados por comas.
-o, --post <módulo>[:<args>]
Usa el módulo especificado como post-procesador. Esto es similar a las opciones -m excepto que el módulo se carga después de analizar el documento.
-d, --pdf
Produce salida PDF. Cuando esta opción viene después de --ps (por ejemplo, en la forma -pd) es un sinónimo de -o ps2pdf, de lo contrario actúa como -m pdftex, para usar pdfLaTeX en lugar de LaTeX.
-p, --ps
Procesa el DVI producido por el proceso a través de dvips(1) para producir un documento PostScript. Esta opción es un sinónimo de -o dvips, no puede venir después de --pdf.
-q, --quieto
Disminuye el nivel de verbosidad. Es lo opuesto a -v.
-r, --leer <archivo>
Lee directivas adicionales del archivo especificado (ver también la directiva "read").
-S, --src-specials
Habilita la generación de especiales de origen si el compilador lo soporta. Esto es equivalente a establecer la variable src-specials a yes.
-s, --corto
Muestra los mensajes de error de LaTeX en formato compacto (un error por línea).
-I, --texpath <directorio>
Añade el directorio especificado a la ruta de búsqueda de TeX.
--synctex
Habilita el soporte SyncTeX en la ejecución de LaTeX.
--unsafe
Permite que el documento invoque programas externos arbitrarios. Esto es potencialmente peligroso, solo use esta opción para documentos que provengan de una fuente confiable.
-v, --verbose
Aumenta el nivel de verbosidad. Existen niveles entre 0 y 4; el nivel por defecto es 1 para rubber y 0 para rubber-pipe. Cuidado, decir -vvv hace que Rubber hable mucho.
--version
Imprime el número de versión y sale amablemente.
-W, --warn <tipo>
Informa información del tipo dado si no hubo errores durante la compilación. Los tipos disponibles son: boxes (cajas demasiado grandes y demasiado pequeñas), refs (referencias indefinidas o múltiplemente definidas), misc (otras advertencias) y all para informar todas las advertencias.

MÓDULOS

La acción de Rubber está influenciada por los módulos. Los módulos se encargan de las características particulares de los paquetes y programas externos.

Paquetes

dedicados a los proporcionados por defecto para incluir nuevas características (este es el propósito del sistema de módulos). Los módulos estándar son los siguientes:

asymptote
Procesa los archivos .asy generados por el paquete LaTeX, luego activa una recompilación.
beamer
Este módulo maneja los archivos adicionales de Beamer de la misma manera que otras tablas de contenidos.
bibtex, biblatex
Se encarga de procesar la bibliografía del documento con BibTeX cuando sea necesario. Este módulo se carga automáticamente si el documento contiene la macro \bibliography (ver también en DIRECTIVAS para opciones).
combine
El paquete combine se utiliza para recopilar varios documentos LaTeX en uno solo, y este módulo maneja las dependencias en este caso.
epsfig
Este módulo maneja la inclusión de gráficos para los documentos que utilizan la macro \psfig de estilo antiguo. En realidad, es una interfaz para el módulo graphics, consulte este último para obtener detalles.
glossaries
Ejecuta makeglossaries y recompila cuando cambia el archivo .glo.
graphics, graphicx
Estos módulos identifican los gráficos incluidos en el documento y los consideran dependencias para la compilación. También utilizan reglas estándar para construir estos archivos con programas externos. Consulte la documentación de info para obtener detalles.
hyperref
Maneja los archivos adicionales que produce este paquete en algunos casos.
index, makeidx, nomencl
Procesa los índices y nomenclaturas del documento con makeindex(1) cuando sea necesario (ver sección DIRECTIVAS para opciones).
ltxtable
Agrega dependencias para archivos insertados a través del paquete LaTeX ltxtable.
minitoc, minitoc-hyper
Al limpiar, elimina archivos adicionales producidos para crear tablas de contenidos parciales.
moreverb, verbatim
Agrega los archivos incluidos con \verbatiminput y macros similares a la lista de dependencias.
multibib
Maneja las bibliografías adicionales que crea este paquete y elimina los archivos adicionales al limpiar.
xr
Agrega archivos .aux adicionales utilizados para referencias externas a la lista de dependencias, para que la recompilación sea automática cuando los documentos referenciados cambian.

Pre-procesamiento

Los siguientes módulos se proporcionan para usar programas que generan código fuente LaTeX a partir de un formato de archivo diferente:

cweb
El propósito de este módulo es ejecutar cweave(1) si es necesario antes del proceso de compilación para producir el código fuente LaTeX. Este módulo se carga automáticamente si el archivo especificado en la línea de comandos tiene .w como sufijo.
lhs2TeX
Este módulo utiliza el preprocesador lhs2TeX para generar el código fuente LaTeX a partir de un programa Literate Haskell. Se activa automáticamente si el nombre del archivo de entrada termina en .lhs.

Post-procesamiento

Los siguientes módulos se proporcionan para admitir diferentes tipos de post-procesamientos. Tenga en cuenta que el orden importa al usar estos módulos: si desea utilizar una cadena de procesamiento como

foo.tex -> foo.dvi -> foo.ps -> foo.pdf -> foo.pdf.gz
debe cargar los módulos dvips, ps2pdf y gz en ese orden, por ejemplo, usando la línea de comandos
rubber -p -o ps2pdf -z foo.tex
bzip2
Produce una versión del archivo final comprimida con bzip2(1).
dvipdfm
Ejecuta dvipdfm(1) al final de la compilación para producir un documento PDF.
dvips
Ejecuta dvips(1) al final de la compilación para producir un documento PostScript. Este módulo también se carga con la opción de línea de comandos --ps.
expand
Produce un código fuente LaTeX expandido reemplazando las macros \input por los archivos incluidos, las macros de bibliografía por la bibliografía producida por bibtex(1), y las clases y paquetes locales por su código fuente. Si el archivo principal es foo.tex, el archivo expandido se llamará foo-final.tex. Consulte la documentación de info para obtener detalles.
gz
Produce una versión del archivo final comprimida con gzip(1).
ps2pdf
Suponiendo que la compilación produce un documento PostScript (por ejemplo, usando el módulo dvips), convierte este documento a PDF usando ps2pdf(1).

Elección del compilador

Los siguientes módulos se utilizan para cambiar el compilador de LaTeX:

aleph
Utiliza el compilador Aleph en lugar de TeX, es decir, compila el documento usando lamed(1) en lugar de latex.
omega
Utiliza el compilador Omega en lugar de TeX, es decir, compila el documento usando lambda(1) en lugar de latex. Si el módulo dvips se usa también, utilizará odvips(1) para traducir el archivo DVI. Tenga en cuenta que este módulo se activa automáticamente cuando el documento utiliza el paquete omega.
pdftex
Indica a Rubber que use pdflatex(1) en lugar de latex(1) para compilar el documento. Por defecto, esto produce un archivo PDF en lugar de un DVI, pero al cargar el módulo con la opción dvi (por ejemplo, diciendo -m pdftex:dvi) el documento se compila a DVI usando pdflatex. Este módulo también se carga con la opción de línea de comandos --pdf.
vtex
Indica a Rubber que use el compilador VTeX. Por defecto, utiliza vlatex como compilador para producir salida PDF. Con la opción ps (por ejemplo, al decir "rubber -m vtex:ps foo.tex") el compilador utilizado es vlatexp y el resultado es un archivo PostScript.
xelatex
Indica a Rubber que use xelatex(1) en lugar de latex.

DIRECTIVAS

El comportamiento automático de Rubber se basa en la búsqueda de macros en los códigos fuente de LaTeX. Cuando esto no es suficiente, se pueden agregar directivas en los comentarios de los códigos fuente. Una directiva es una línea como

% rubber: cmd args
La línea debe comenzar con un "%", luego cualquier secuencia de signos "%" y espacios, luego el texto "rubber:" seguido de espacios y un nombre de comando, posiblemente seguido de espacios y argumentos.

Directivas Generales

alias <name1> <name2>
Pretender que la macro LaTeX name1 es equivalente a name2. Esto puede ser útil al definir envoltorios alrededor de macros compatibles.
clean <file>
Indica que el archivo especificado debe eliminarse al limpiar usando --clean.
depend <file>
Considerar el archivo especificado como una dependencia, de modo que su tiempo de modificación sea verificado.
make <file> [<options>]
Declarar que el archivo especificado debe ser generado. Las opciones pueden especificar la forma en que debe producirse, las opciones disponibles son from <file> para especificar la fuente y with <rule> para especificar la regla de conversión. Por ejemplo, decir "make foo.pdf from foo.eps" indica que foo.pdf debe producirse a partir de foo.eps, con cualquier regla de conversión que pueda hacerlo. Consulte la documentación de info para obtener detalles sobre la conversión de archivos.
module <module> [<options>]
Carga el módulo especificado, posiblemente con opciones. Esto es equivalente a la opción de línea de comandos --module.
onchange <file> <command>
Ejecuta el comando de shell especificado después de compilar si el contenido del archivo especificado ha cambiado. El nombre del archivo termina en el primer espacio.
path <directory>
Agrega el directorio especificado a la ruta de búsqueda de TeX (y Rubber). El nombre del directorio es todo lo que sigue a los espacios después de "path".
produce <file>
Declara que la ejecución de LaTeX creará o actualizará el(los) archivo(s) especificado(s).
read <file>
Lee el archivo de directivas especificado. El archivo debe contener una directiva por línea. Las líneas vacías y las líneas que comienzan con "%" se ignoran.
rules <file>

DIRECTIVAS

Las directivas son opciones que se pueden poner en el archivo de configuración (normalmente rubber.conf) para modificar el comportamiento de Rubber.

Las directivas son de la forma key = value. Las líneas que empiezan por # son comentarios. Las líneas vacías son ignoradas.

Existen dos tipos de directivas: generales y específicas de módulo.

Directivas generales

include <file>
Lee reglas de conversión adicionales del archivo especificado. El formato de este archivo es el mismo que el de rules.ini, véase la documentación de info para más detalles.
set <nombre> <valor>
Establece el valor de una variable como una cadena de texto. Para más detalles sobre las variables existentes y su significado, véase la documentación de info.
setlist <nombre> <valores>
Establece el valor de una variable como una lista de cadenas de texto (separadas por espacios). Para más detalles sobre las variables existentes y su significado, véase la documentación de info.
shell_escape
Marca el documento como que requiere programas externos (shell-escape o write18). Rubber no habilita esto realmente a menos que se llame con la opción --unsafe.
synctex
Habilita el soporte de SyncTeX en la ejecución de LaTeX.
watch <archivo>
Vigila el archivo especificado en busca de cambios. Si el contenido de este archivo ha cambiado después de una compilación, se dispara otra compilación. Esto es útil en el caso de tablas de contenido, por ejemplo.

Directivas específicas de módulo

Si un comando tiene la forma foo.bar, se considera un comando bar para el módulo foo. Si este módulo no está registrado cuando se encuentra la directiva, el comando se ignora silenciosamente. Para los módulos estándar, las directivas son las siguientes:

biblatex.path <directorio>
Añade el directorio especificado a la ruta de búsqueda de bases de datos BibTeX (.bib).
bibtex.crossrefs <número>
Establece el número mínimo de crossref requeridos para la inclusión automática de la entrada referenciada en la lista de citas. Esto establece la opción -min-crossrefs al llamar a bibtex(1).
bibtex.path <directorio>
Añade el directorio especificado a la ruta de búsqueda de bases de datos BibTeX (.bib).
bibtex.stylepath <directorio>
Añade el directorio especificado a la ruta de búsqueda de estilos BibTeX (.bst).
bibtex.tool <comando>
Utiliza una herramienta de bibliografía diferente en lugar de BibTeX.
dvipdfm.options <opciones>
Pasa los interruptores de línea de comandos especificados a dvipdfm.
dvips.options <opciones>
Pasa los interruptores de línea de comandos especificados a dvips.
index.tool (index) <nombre>
Especifica qué herramienta se utilizará para procesar el índice. Las herramientas actualmente soportadas son makeindex(1) (la opción predeterminada) y xindy(1). El argumento index es opcional, puede usarse para especificar la lista de índices a los que se aplica el comando. Cuando está presente, debe estar entre paréntesis; la lista está separada por comas. Cuando el argumento no está presente, el comando se aplica a todos los índices.
index.language (index) <idioma>
Selecciona el idioma utilizado para ordenar el índice. Esto solo se aplica al usar xindy(1) como herramienta de indexación. El argumento opcional tiene la misma semántica que arriba.
index.modules (index) <módulo>...
Especifica qué módulos usar al procesar un índice con xindy(1). El argumento opcional tiene la misma semántica que arriba.
index.order (index) <opciones>
Modifica las opciones de ordenación para los índices. Los argumentos son palabras (separadas por espacios) entre standard, german y letter. Esto solo se aplica al usar makeindex(1). El argumento opcional tiene la misma semántica que arriba.
index.path (index) <directorio>
Añade el directorio especificado a la ruta de búsqueda de estilos de índice (.ist). El argumento opcional tiene la misma semántica que arriba.
index.style (index) <estilo>
Especifica el estilo de índice a utilizar. El argumento opcional tiene la misma semántica que arriba.
makeidx.language, .modules, .order, .path, .style, .tool
Estas directivas son las mismas que para el módulo index, excepto que no aceptan el argumento opcional.
multibib.crossrefs, .path, .stylepath, .tool
Estas directivas son las mismas que para el módulo bibtex pero se aplican a bibliografías gestionadas por el paquete multibib. Toman un primer argumento opcional, con la misma convención que para las directivas del módulo index, que puede usarse para especificar la lista de bibliografías a las que se aplica el comando.
