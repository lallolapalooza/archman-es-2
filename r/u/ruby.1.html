NOMBRE

ruby — Lenguaje de scripting orientado a objetos interpretado

SINOPSIS

ruby [--copyright] [--version] [-SUacdlnpswvy] [-0[octal]] [-C directorio] [-E externo[:interno]] [-F[patrón]] [-I directorio] [-K[c]] [-T[nivel]] [-W[nivel]] [-e comando] [-i[extensión]] [-r librería] [-x[directorio]] [--{habilitar|deshabilitar}-CARACTERÍSTICA] [--dump=objetivo] [--verbose] [--crash-report=plantilla] [--] [archivo_programa] [argumento ...]

DESCRIPCIÓN

Ruby es un lenguaje de scripting interpretado para la programación orientada a objetos rápida y sencilla. Tiene muchas características para procesar archivos de texto y para realizar tareas de administración del sistema (como en Perl). Es simple, directo y extensible.

Si desea un lenguaje para una programación orientada a objetos fácil, o no le gusta la fealdad de Perl, o le gusta el concepto de LISP, pero no le gustan demasiados paréntesis, Ruby podría ser su lenguaje de elección.

CARACTERÍSTICAS

Las características de Ruby son las siguientes:

Interpretado
Ruby es un lenguaje interpretado, por lo que no necesita recompilar los programas escritos en Ruby para ejecutarlos.
Las variables no tienen tipo (tipado dinámico)
Las variables en Ruby pueden contener datos de cualquier tipo. No tiene que preocuparse por el tipado de las variables. En consecuencia, tiene una comprobación en tiempo de compilación más débil.
No se necesita declaración
Puede usar variables en sus programas Ruby sin ninguna declaración. Los nombres de las variables denotan su alcance: global, de clase, de instancia o local.
Sintaxis simple
Ruby tiene una sintaxis simple influenciada ligeramente por Eiffel.
Sin gestión de memoria a nivel de usuario
Ruby tiene gestión automática de memoria. Los objetos que ya no son referenciados desde ningún lugar son recolectados automáticamente por el recolector de basura incorporado en el intérprete.
Todo es un objeto
Ruby es un lenguaje puramente orientado a objetos, y lo ha sido desde su creación. Incluso los datos básicos como los enteros se ven como objetos.
Clase, herencia y métodos
Al ser un lenguaje orientado a objetos, Ruby naturalmente tiene características básicas como clases, herencia y métodos.
Métodos singleton
Ruby tiene la capacidad de definir métodos para ciertos objetos. Por ejemplo, puede definir una acción de presionar un botón para un widget específico definiendo un método singleton para el botón. O puede crear su propio sistema de objetos basado en prototipos si lo desea.
Mix-in por módulos
Ruby intencionalmente no tiene herencia múltiple ya que es una fuente de confusión. En su lugar, Ruby tiene la capacidad de compartir implementaciones a través del árbol de herencia. Esto a menudo se llama un ‘Mix-in’.
Iteradores
Ruby tiene iteradores para la abstracción de bucles.
Cierres
En Ruby, puedes objetivar el procedimiento.
Procesamiento de texto y expresiones regulares
Ruby tiene un conjunto de características de procesamiento de texto como en Perl.
M17N, independiente del conjunto de caracteres
Ruby admite programación multilingüe. Fácil de procesar textos escritos en muchos idiomas naturales diferentes y codificados en muchas codificaciones de caracteres diferentes, sin depender de Unicode.
Bignums
Con bignums integrados, puede, por ejemplo, calcular factorial(400).
Reflexión y lenguajes específicos del dominio
La clase también es una instancia de la clase Class. La definición de clases y métodos es una expresión al igual que lo es 1+1. Por lo tanto, sus programas pueden incluso escribir y modificar programas. Así, puede escribir su aplicación en su propio lenguaje de programación sobre Ruby.
Manejo de excepciones
Como en Java(tm).
Acceso directo al sistema operativo
Ruby puede usar la mayoría de las llamadas del sistema UNIX, utilizadas a menudo en la programación de sistemas.
Carga dinámica
En la mayoría de los sistemas UNIX, puede cargar archivos objeto en el intérprete Ruby sobre la marcha.
Bibliotecas ricas
Además de las “bibliotecas incorporadas” y las “bibliotecas estándar” que se incluyen con Ruby, una gran cantidad de bibliotecas de terceros (“gems”) están disponibles a través del sistema de gestión de paquetes llamado ‘RubyGems’, a saber, el comando gem(1). Visite RubyGems.org (https://rubygems.org/) para encontrar las gems que necesita, y explore GitHub (https://github.com/) para ver cómo se desarrollan y utilizan.

ENTORNO GC

El recolector de basura (GC) de Ruby rastrea objetos en ranuras de tamaño fijo, pero cada objeto puede tener asignaciones de memoria auxiliares manejadas por las llamadas de la familia malloc de la biblioteca estándar de C ( malloc(3), calloc(3) y realloc(3)). En esta documentación, el "montón" (heap) se refiere al montón de objetos de Ruby de ranuras de tamaño fijo, mientras que "malloc" se refiere a asignaciones auxiliares comúnmente denominadas el "montón del proceso". Por lo tanto, hay al menos dos formas posibles de activar el GC:

1
Alcanzar el límite de objetos.
2
Alcanzar el límite de malloc.

En Ruby 2.1, se introdujo el GC generacional y los límites se dividen en generaciones jóvenes y viejas, lo que proporciona dos formas adicionales de activar un GC:

3
Alcanzar el límite de objetos viejos.
4
Alcanzar el límite de malloc viejo.

Actualmente hay 4 áreas posibles donde el GC puede ajustarse mediante las siguientes variables de entorno:

RUBY_GC_HEAP_n_INIT_SLOTS
Asignación inicial de ranuras en un montón específico. Los montones disponibles se pueden encontrar en las claves de GC.stat_heap. n es un número decimal entre 0 y 4. Introducido en Ruby 3.3.
RUBY_GC_HEAP_FREE_SLOTS
Prepara al menos esta cantidad de ranuras después del GC. Asigna esta cantidad de ranuras si no hay suficientes. Introducido en Ruby 2.1, por defecto: 4096
RUBY_GC_HEAP_GROWTH_FACTOR
Aumenta la tasa de asignación de ranuras del montón por este factor. Introducido en Ruby 2.1, por defecto: 1.8, mínimo: 1.0 (sin crecimiento)
RUBY_GC_HEAP_GROWTH_MAX_SLOTS
La tasa de asignación se limita a este número de ranuras, lo que evita asignaciones excesivas debido a RUBY_GC_HEAP_GROWTH_FACTOR. Introducido en Ruby 2.1, por defecto: 0 (sin límite)
RUBY_GC_HEAP_OLDOBJECT_LIMIT_FACTOR
Realiza un GC completo cuando el número de objetos viejos es más que R * N, donde R es este factor y N es el número de objetos viejos después del último GC completo. Introducido en Ruby 2.1.1, por defecto: 2.0
RUBY_GC_HEAP_REMEMBERED_WB_UNPROTECTED_OBJECTS_LIMIT_RATIO
Se utiliza para calcular el remembered_wb_unprotected_objects_limit utilizando una relación con old_objects. Introducido en Ruby 3.3, por defecto: 0.1, mínimo: 0.0
RUBY_GC_MALLOC_LIMIT
El límite inicial de asignación de la generación joven del grupo de funciones malloc. El GC comenzará cuando se alcance este límite. Por defecto: 16 MB
RUBY_GC_MALLOC_LIMIT_MAX
El límite máximo de asignación de la generación joven de malloc antes de que el GC comience.

Ruby interpreter behavior can be modified by setting the following environment variables:

RUBYOPT
A string of options that are prepended to the command line arguments. Options in RUBYOPT are processed after the options on the command line.
RUBYLIB
A string of directories, separated by colons (:), that are added to the default load path. RUBYLIB is processed after the options specified by -I.
RUBY_VERSION
A string that is available as $RUBY_VERSION in Ruby.
RUBY_PLATFORM
A string that is available as $RUBY_PLATFORM in Ruby. It describes the operating system and architecture.
RUBY_ENGINE
A string that is available as $RUBY_ENGINE in Ruby. It describes the Ruby implementation (e.g., `ruby`, `truffle`, `jruby`).
RUBY_DESCRIPTION
A string that is available as $RUBY_DESCRIPTION in Ruby. It describes the Ruby implementation, version, and platform.
RUBY_PATCHLEVEL
A string that is available as $RUBY_PATCHLEVEL in Ruby. It describes the patch level of the Ruby interpreter.
RUBY_RELEASE_DATE
A string that is available as $RUBY_RELEASE_DATE in Ruby. It describes the release date of the Ruby interpreter.
RUBYOPT_FOR_SPECIFIC_ENGINE
See also RUBYOPT. If the engine is truffle, then TRUFFLEOPTS is used. If the engine is jruby, then JRUBY_OPTS is used. The options are appended.

GC ENVIRONMENT

RUBY_GC_HEAP_INIT_SLOTS
The initial number of heap slots to allocate. Introduced in Ruby 2.4, default: 1000.
RUBY_GC_HEAP_FREE_SLOTS
The number of free slots to target for heap allocation. Introduced in Ruby 2.4, default: 0 (meaning it is calculated from RUBY_GC_HEAP_GROWTH_FACTOR).
RUBY_GC_HEAP_GROWTH_FACTOR
The growth factor for the heap. When the number of free slots is less than total_slots * growth_factor, more slots are allocated. Introduced in Ruby 2.4, default: 1.3.
RUBY_GC_HEAP_GROWTH_MAX_SIZE
The maximum number of heap slots to allocate. Introduced in Ruby 2.4, default: 0 (meaning no limit).
RUBY_GC_HEAP_SIZE_MAX
The maximum size of the heap in bytes. Introduced in Ruby 2.1, default: 0 (meaning no limit).
RUBY_GC_HEAP_SORT_ALLOCATED_POINTERS
Sorts allocated pointers by address, which helps to reduce fragmentation. Introduced in Ruby 2.4, default: 0 (disabled).
RUBY_GC_MALLOC_LIMIT
The initial limit of young generation allocation from malloc, a GC will start when this limit is reached. Introduced in Ruby 2.1, default: 32MB.
RUBY_GC_MALLOC_LIMIT_MAX
The maximum limit of young generation allocation from malloc before a GC starts. Prevents excessive malloc growth due to RUBY_GC_MALLOC_LIMIT_GROWTH_FACTOR. Introduced in Ruby 2.1, default: 32MB.
RUBY_GC_MALLOC_LIMIT_GROWTH_FACTOR
Increases the limit of young generation malloc calls, reducing GC frequency but increasing malloc growth until RUBY_GC_MALLOC_LIMIT_MAX is reached. Introduced in Ruby 2.1, default: 1.4, minimum: 1.0 (no growth)
RUBY_GC_HEAP_FREE_SLOTS_MIN_RATIO
Allocate additional pages when the number of free slots is lower than the value (total_slots * (this ratio)). Introduced in Ruby 2.4, default: 0.2, minimum: 0.0, maximum: 1.0
RUBY_GC_HEAP_FREE_SLOTS_MAX_RATIO
Allow to free pages when the number of free slots is greater than the value (total_slots * (this ratio)). Introduced in Ruby 2.4, default: 0.4, minimum: RUBY_GC_HEAP_FREE_SLOTS_MIN_RATIO, maximum: 1.0
RUBY_GC_HEAP_FREE_SLOTS_GOAL_RATIO
Allocate slots to satisfy this formula: free_slots = total_slots * goal_ratio In other words, prepare (total_slots * goal_ratio) free slots. if this value is 0.0, then use RUBY_GC_HEAP_GROWTH_FACTOR directly. Introduced in Ruby 2.4, default: 0.65, minimum: RUBY_GC_HEAP_FREE_SLOTS_MIN_RATIO, maximum: RUBY_GC_HEAP_FREE_SLOTS_MAX_RATIO
RUBY_GC_OLDMALLOC_LIMIT
The initial limit of old generation allocation from malloc, a full GC will start when this limit is reached. Introduced in Ruby 2.1, default: 16MB
RUBY_GC_OLDMALLOC_LIMIT_MAX
The maximum limit of old generation allocation from malloc before a full GC starts. Prevents excessive malloc growth due to RUBY_GC_OLDMALLOC_LIMIT_GROWTH_FACTOR. Introduced in Ruby 2.1, default: 128MB
RUBY_GC_OLDMALLOC_LIMIT_GROWTH_FACTOR
Increases the limit of old generation malloc allocation, reducing full GC frequency but increasing malloc growth until RUBY_GC_OLDMALLOC_LIMIT_MAX is reached. Introduced in Ruby 2.1, default: 1.2, minimum: 1.0 (no growth)
RUBY_SHARED_FIBER_POOL_FREE_STACKS
Frees stacks of pooled fibers, if set to 1. Do not free the stacks if set to 0. Introduced in Ruby 2.7, default: 1 (no growth)

STACK SIZE ENVIRONMENT

Stack size environment variables are implementation-dependent and subject to change with different versions of Ruby. The VM stack is used for pure-Ruby code and managed by the virtual machine. Machine stack is used by the operating system and its usage is dependent on C extensions as well as C compiler options. Using lower values for these may allow applications to keep more Fibers or Threads running; but increases the chance of SystemStackError exceptions and segmentation faults (SIGSEGV). These environment variables are available since Ruby 2.0.0. All values are specified in bytes.

RUBY_THREAD_VM_STACK_SIZE
VM stack size used at thread creation. default: 524288 (32-bit CPU) or 1048575 (64-bit)
RUBY_THREAD_MACHINE_STACK_SIZE
Machine stack size used at thread creation. default: 524288 or 1048575
RUBY_FIBER_VM_STACK_SIZE
VM stack size used at fiber creation. default: 65536 or 131072
RUBY_FIBER_MACHINE_STACK_SIZE
Machine stack size used at fiber creation. default: 262144 or 524288

CRASH REPORT ENVIRONMENT

RUBY_CRASH_REPORT
The template of path name to save crash report. default: none

Naming crash report files

The template can contain % specifiers which are substituted by the following values when a crash report file is created:

%%
A single % character.
%e
Basename of executable.
%E
Pathname of executable, with slashes (/) replaced by exclamation marks (!).
%f
Basename of the program name, $0.
%F
Pathname of the program name, $0, with slashes (/) replaced by exclamation marks (!).
%p
PID of dumped process.
%t
Time of dump, expressed as seconds since the Epoch, 1970-01-01 00:00:00 +0000 (UTC).
%NNN
A character code in octal.

A single % at the end of the template is dropped from the core filename, as is the combination of a % followed by any character other than those listed above. All other characters in the template become a literal part of the core filename. The template may include '/' characters, which are interpreted as delimiters for directory names.

Piping crash reports to a program

If the first character of this file is a pipe symbol (|), then the remainder of the line is interpreted as the command-line for a program (or script) that is to be executed.

The pipe template is split on spaces into an argument list before the template parameters are expanded.

NAME

ruby - Una calculadora de lenguaje interpretado y orientada a objetos.

SYNOPSIS

ruby [-cswv] [-e "código" ...] [-I dir ...] [-r library ...] [--] [file ...] [argument ...]

DESCRIPTION

ruby es un lenguaje de scripting dinámico y de código abierto que se centra en la simplicidad y la productividad. Es un lenguaje de scripting interpretado, de alto nivel, que es completamente orientado a objetos. Ruby tiene un lenguaje de sintaxis limpia que es fácil de leer y escribir.

OPTIONS

-c
Analiza el código fuente de cada archivo de entrada para detectar errores de sintaxis, pero no lo ejecuta. Imprime "Syntax OK" si no hay errores.
-s
Permite el uso de guiones bajos en las opciones de línea de comandos.
-w
Permite avisos de advertencia.
-v
Imprime la versión de Ruby y sale.
-e "código"
Especifica un comando para ser ejecutado.
-I dir
Añade el directorio `dir` a la ruta de búsqueda de librerías.
-r library
Requiere la librería especificada antes de ejecutar el código.
--
Indica el final de las opciones. Cualquier argumento posterior se trata como un nombre de archivo o argumento de programa.

ENVIRONMENT

RUBYLIB
Una lista separada por dos puntos de directorios que se añadirán a la ruta de búsqueda de librerías.
RUBYOPT
Opciones que se pasarán al intérprete de Ruby.
RUBYVERS
Especifica la versión de Ruby a usar.

MISC ENVIRONMENT

RUBYSHELLVARVALUE: si se define, Ruby utilizará este valor en lugar de obtener el valor de una variable de shell.
