NOMBRE

run0 - Elevar privilegios

SINOPSIS

run0 [OPCIONES...] [COMANDO...]

DESCRIPCIÓN

run0 puede ser utilizado para adquirir temporal e interactivamente privilegios elevados o diferentes. Sirve un propósito similar a sudo(8), pero opera de manera diferente en un par de áreas clave:

•No se heredan credenciales de ejecución ni de contexto de seguridad del llamador en los comandos invocados, ya que se invocan desde un servicio nuevo y aislado derivado por el gestor de servicios.
•La autenticación se realiza a través de polkit[1], aislando así la solicitud de autenticación de la terminal (si es posible).
•Se asigna una pseudo-tty independiente para el comando invocado, desacoplando su ciclo de vida y aislándolo por seguridad.
•No se utiliza funcionalidad de bit de acceso SetUID/SetGID para la implementación.

En conjunto, esto debería proporcionar una alternativa más segura y robusta al mecanismo sudo, en particular en entornos de SO donde no hay soporte SetUID/SetGID disponible (por ejemplo, estableciendo la variable NoNewPrivileges= en systemd-system.conf(5)).

Cualquier sesión invocada a través de run0 se ejecutará a través de la pila PAM "systemd-run0".

Tenga en cuenta que run0 se implementa como una invocación alternativa multi-llamada de systemd-run(1). Es decir, run0 es un enlace simbólico al archivo ejecutable systemd-run, y se comporta como run0 si se invoca a través del enlace simbólico, de lo contrario se comporta como systemd-run.

OPCIONES

Se entienden las siguientes opciones:

--unit=

Utilice este nombre de unidad en lugar de uno generado automáticamente.

Añadido en la versión 256.

--property=

Establece una propiedad de la unidad de servicio que se crea. Esta opción toma una asignación en el mismo formato que el comando set-property de systemctl(1).

Añadido en la versión 256.

--description=

Proporcione una descripción para la unidad de servicio que se invoca. Si no se especifica, el propio comando se utilizará como descripción. Consulte Description= en systemd.unit(5).

Añadido en la versión 256.

--slice=

Haga que la nueva unidad .service sea parte de la slice especificada, en lugar de user.slice.

Añadido en la versión 256.

--slice-inherit

Haga que la nueva unidad .service sea parte de la slice en la que se invocó run0. Esta opción puede combinarse con --slice=, en cuyo caso la slice especificada a través de --slice= se colocará dentro de la slice en la que se invoca el comando run0.

Ejemplo: considere que run0 se invoca en la slice foo.slice, y el argumento --slice= es bar. La unidad se colocará entonces en foo-bar.slice.

Añadido en la versión 256.

--user=, -u, --group=, -g

Cambia al usuario/grupo especificado. Si no se especifica, por defecto es "root", a menos que se utilice --area= (ver abajo), en cuyo caso por defecto es el usuario invocador.

Añadido en la versión 256.

--nice=

Ejecuta la sesión invocada con el nivel de nice especificado.

Añadido en la versión 256.

--chdir=, -D

Ejecuta la sesión invocada con el directorio de trabajo especificado. Si no se especifica, por defecto es el directorio de trabajo actual del cliente si se cambia al usuario root, o el directorio de inicio del usuario de destino en caso contrario.

Añadido en la versión 256.

--via-shell

Invoca el shell de inicio de sesión del usuario de destino y ejecuta el comando especificado (si lo hay) a través de él.

Añadido en la versión 258.

-i

Atajo para --via-shell --chdir='~'.

Añadido en la versión 258.

--setenv=NOMBRE[=VALOR]

Ejecuta la sesión invocada con la variable de entorno especificada establecida. Este parámetro puede utilizarse varias veces para establecer varias variables. Cuando se omiten "=" y VALOR, se utilizará el valor de la variable con el mismo nombre en el entorno invocador.

Añadido en la versión 256.

--background=COLOR

Cambia el color de fondo de la terminal al color ANSI especificado mientras dure la sesión. Si no se especifica, el fondo se teñirá con un tono rojizo cuando se opere como root, y con un tono amarillento cuando se opere bajo otra UID, como recordatorio de los privilegios cambiados. El color especificado debe ser un color de fondo SGR de código de escape ANSI X3.64, es decir, cadenas como "40", "41", ..., "47", "48;2;...", "48;5;...". Consulte ANSI Escape Code (Wikipedia)[2] para más detalles. Establézcalo a una cadena vacía para deshabilitar.

Ejemplo: "--background=44" para un fondo azul.

Añadido en la versión 256.

--pty, --pty-late, --pipe

Solicita la asignación de una TTY pseudo para la sesión de run0 (en caso de --pty o --pty-late), o solicita pasar los descriptores de archivo STDIN, STDOUT, STDERR del llamador directamente (en caso de --pipe). --pty-late es muy similar a --pty pero comienza el procesamiento de la TTY solo una vez que se completa el inicio de la unidad, dejando la entrada para contraseñas/agentes de polkit hasta ese momento. Si no se especifica ninguno de estos interruptores, o si se especifican tanto --pipe como uno de --pty/--pty-late, el modo se elegirá automáticamente: si la entrada estándar, la salida estándar y la salida de error estándar están todas conectadas a una TTY, entonces se asignará una TTY pseudo (en modo --pty-late a menos que se especifique --no-ask-password, en cuyo caso se seleccionará --pty), de lo contrario, los descriptores de archivo relevantes se pasarán directamente.

--pty y --pipe se añadieron en v257.

--pty-late se añadió en v258.

--shell-prompt-prefix=CADENA

Establece una cadena de prefijo para el prompt del shell. Esto controla en última instancia la variable de entorno $SHELL_PROMPT_PREFIX para el programa invocado, que normalmente se importa en el prompt del shell. Por defecto, si los emojis son compatibles, se muestra un emoji de superhéroe (🦸). Este valor predeterminado también puede cambiarse (o desactivarse) pasando la variable de entorno $SYSTEMD_RUN_SHELL_PROMPT_PREFIX a run0, véase más abajo. Establezca a una cadena vacía para deshabilitar el prefijo del prompt del shell.

Añadido en la versión 257.

--lightweight=BOOLEANO

Controla si se activa el gestor de servicios por usuario para el usuario de destino. Por defecto, si el usuario de destino es "root" o un usuario del sistema, el gestor de servicios por usuario no se activa como efecto de la invocación de run0, de lo contrario sí.

Esto controla en última instancia la variable de entorno $XDG_SESSION_CLASS que pam_systemd(8) respeta.

Añadido en la versión 258.

--area=ÁREA

Controla el "área" de la cuenta de destino para iniciar sesión. Las áreas son directorios de inicio secundarios dentro del directorio de inicio principal del usuario de destino, es decir, iniciar sesión en el área "foobar" de una cuenta se traduce en que $HOME se establezca como ~/Areas/foobar al iniciar sesión.

Si se utiliza esta opción, el usuario predeterminado al que transicionar cambia de root al usuario que llama (pero --user= tiene prioridad, ver arriba). O en otras palabras, solo especificar un área sin un usuario es un mecanismo para crear una nueva sesión del usuario que llama, solo con un área diferente.

Esto controla en última instancia la variable de entorno $XDG_AREA que pam_systemd(8) respeta.

Para más detalles sobre el concepto de área, consulte pam_systemd_home(8).

Añadido en la versión 258.

--machine=

Ejecuta la operación en un contenedor local. Especifique el nombre de un contenedor al que conectarse.

Añadido en la versión 256.

--no-ask-password

No preguntar la

run0(8)

NAME

run0 - run a command as root or another user, securely

SYNOPSIS

run0 [OPTIONS...] [--] [COMMAND [ARG]... | --shell]

DESCRIPTION

Runs a command or an interactive shell as the user root (by default) or another specified user. This is intended as a safer alternative to sudo or su when used in conjunction with systemd service units or other automated processes that manage security policies via Polkit.

Unlike sudo, run0 does not use PAM to determine authorization. Instead, it relies on Polkit, which is configured via separate policy files. This means that authorization is granted or denied based on the Polkit action io.systemd.run, and not based on the originating user's password.

The command line arguments after the first non-option argument become part of the command line of the launched process. If no command line is specified, an interactive shell is invoked.

If run0 is invoked without any command, it may be used to start a login shell for the target user, allowing interactive shell sessions. This is often used in combination with systemd.unit(5)'s ExecStart= directive to start shell sessions within service units.

If the user initiating the run0 call is not root, the command will be executed as the user specified by --user (which defaults to root), unless configured otherwise via Polkit.

run0 uses sd_bus_call(3) to invoke the io.systemd.run Polkit action. This action receives the originating user's UID and GID, the target user and group, and the command line to execute. The Polkit action implementation then uses setuid(2) and execve(2) to execute the command as the target user.

OPTIONS

The following options are understood:

-h, --help
Print a short help text and exit.
--version
Print a short version string and exit.
--user=USER
Run as the specified USER. If not specified, defaults to root. This option can be used multiple times to specify multiple users. The last one specified will be used as the target user.
--group=GROUP
Run as the specified GROUP. If not specified, defaults to the primary group of the target user. This option can be used multiple times to specify multiple groups. The last one specified will be used as the target group.
--setenv=NAME=VALUE
Set environment variable NAME to VALUE in the executed command's environment. This option can be used multiple times to set multiple environment variables.
--unsetenv=NAME
Unset environment variable NAME in the executed command's environment. This option can be used multiple times to unset multiple environment variables.
--machine=MACHINE
Execute the command on a systemd-nspawn container named MACHINE. See machinectl(1) for details.
--via-shell
If no command is specified, invoke the target user's login shell instead of defaulting to /bin/sh when operating with --machine=. This is ignored if a command is specified.
--uid=UID
Run as the user with the specified numeric UID. This option is mutually exclusive with --user=.
--gid=GID
Run as the group with the specified numeric GID. This option is mutually exclusive with --group=.
--shell-prompt-prefix=PREFIX
Set the prefix for the shell prompt. By default, a superhero emoji is used if supported. This option can be used to override the default prefix, or to disable it by setting it to an empty string. See ENVIRONMENT VARIABLES for more details.

All command line arguments after the first non-option argument become part of the command line of the launched process. If no command line is specified an interactive shell is invoked. The shell to invoke may be controlled through --via-shell - when specified the target user's shell is used - or --setenv=SHELL=.... By default, the originating user's shell is executed if operating locally, or /bin/sh when operating with --machine=.

Note that unlike sudo, run0 always spawns shells with login shell semantics, regardless of -i.

EXIT STATUS

On success, 0 is returned. If run0 failed to start the session or the specified command fails, a non-zero return value will be returned.

ENVIRONMENT VARIABLES

As with systemd-run, the session will inherit the system environment from the service manager. In addition, the following environment variables will be set:

$TERM

Copied from the $TERM of the caller. Can be overridden with --setenv=

Added in version 256.

$SUDO_USER

Set to the username of the originating user.

Added in version 256.

$SUDO_UID

Set to the numeric UNIX user id of the originating user.

Added in version 256.

$SUDO_GID

Set to the primary numeric UNIX group id of the originating session.

Added in version 256.

$SHELL_PROMPT_PREFIX

By default, set to the superhero emoji (if supported), but may be overridden with the $SYSTEMD_RUN_SHELL_PROMPT_PREFIX environment variable (see below), or the --shell-prompt-prefix= switch (see above).

Added in version 257.

The following variables may be passed to run0:

$SYSTEMD_RUN_SHELL_PROMPT_PREFIX

If set, overrides the default shell prompt prefix that run0 sets for the invoked shell (the superhero emoji). Set to an empty string to disable shell prompt prefixing.

Added in version 257.
