RUNUSER(1) Comandos de Usuario RUNUSER(1)

NOMBRE

runuser - ejecutar un comando con un usuario y grupo sustitutos

SINOPSIS

runuser [opciones] -u usuario [[--] comando [argumento...]]

runuser [opciones] [-] [usuario [argumento...]]

DESCRIPCIÓN

runuser se puede utilizar para ejecutar comandos con un usuario y grupo sustitutos. Si no se proporciona la opción -u, runuser recurre a la semántica compatible con su y se ejecuta un shell. La diferencia entre los comandos runuser y su es que runuser no pide contraseña (ya que solo puede ser ejecutado por el usuario root) y utiliza una configuración PAM diferente. El comando runuser no tiene que estar instalado con permisos de set-user-ID.

Si la sesión PAM no es necesaria, la solución recomendada es usar el comando setpriv(1).

Cuando se llama sin argumentos, runuser por defecto ejecuta un shell interactivo como root.

Por compatibilidad hacia atrás, runuser por defecto no cambia el directorio actual y solo establece las variables de entorno HOME y SHELL (más USER y LOGNAME si el usuario de destino no es root). Esta versión de runuser usa PAM para la gestión de sesiones.

Tenga en cuenta que runuser en todos los casos usa PAM (pam_getenvlist()) para realizar la modificación final del entorno. Las opciones de línea de comandos como --login y --preserve-environment afectan al entorno antes de que sea modificado por PAM.

Desde la versión 2.38, runuser restablece los límites de recursos del proceso RLIMIT_NICE, RLIMIT_RTPRIO, RLIMIT_FSIZE, RLIMIT_AS y RLIMIT_NOFILE.

OPCIONES

-c, --command=comando

Pasa comando al shell con la opción -c.

-f, --fast

Pasa -f al shell, lo que puede ser útil o no, dependiendo del shell.

-g, --group=grupo

El grupo primario a utilizar. Esta opción solo está permitida para el usuario root.

-G, --supp-group=grupo

Especifica un grupo suplementario. Esta opción solo está disponible para el usuario root. El primer grupo suplementario especificado también se utiliza como grupo primario si no se especifica la opción --group.

-, -l, --login

Inicia el shell como un shell de inicio de sesión con un entorno similar al de un inicio de sesión real:
•borra todas las variables de entorno excepto TERM y las variables especificadas por --whitelist-environment
•inicializa las variables de entorno HOME, SHELL, USER, LOGNAME y PATH
•cambia al directorio de inicio del usuario de destino
•establece argv[0] del shell a '-' para hacer del shell un shell de inicio de sesión

-m, -p, --preserve-environment

Conserva todo el entorno, es decir, no establece HOME, SHELL, USER o LOGNAME. La opción se ignora si se especifica la opción --login.

-P, --pty

Crea un pseudo-terminal para la sesión. El terminal independiente proporciona mejor seguridad ya que el usuario no comparte un terminal con la sesión original. Esto puede usarse para evitar la inyección de comandos ioctl TIOCSTI y otros ataques de seguridad contra descriptores de archivo de terminal. Toda la sesión también puede moverse al fondo (por ejemplo, runuser --pty -u usuario -- comando &). Si el pseudo-terminal está habilitado, entonces runuser actúa como un proxy entre las sesiones (sincroniza stdin y stdout).

Esta característica está diseñada principalmente para sesiones interactivas. Si la entrada estándar no es un terminal, sino por ejemplo una tubería (por ejemplo, echo "date" | runuser --pty -u usuario), entonces la bandera ECHO para el pseudo-terminal se deshabilita para evitar salidas confusas.

-s, --shell=shell

Ejecuta el shell especificado en lugar del predeterminado. El shell a ejecutar se selecciona según las siguientes reglas, en orden:
•el shell especificado con --shell
•el shell especificado en la variable de entorno SHELL si se utiliza la opción --preserve-environment
•el shell listado en la entrada passwd del usuario de destino
•/bin/sh

Si el usuario de destino tiene un shell restringido (es decir, no listado en /etc/shells), entonces se ignoran las opciones --shell y las variables de entorno SHELL, a menos que el usuario que llama sea root.

--session-command=comando

Igual que -c, pero no crea una nueva sesión. (Desaconsejado.)

-T, --no-pty

No crea un pseudo-terminal, lo opuesto a --pty y -P. Tenga en cuenta que ejecutar sin un pseudo-terminal presenta el riesgo de seguridad de escalada de privilegios a través de la inyección de comandos ioctl TIOCSTI/TIOCLINUX.

-u, --user=usuario

Ejecuta comando con el ID de usuario efectivo y el ID de grupo del nombre de usuario usuario.

-w, --whitelist-environment=lista

No restablece las variables de entorno especificadas en la lista separada por comas al borrar el entorno para --login. La lista blanca se ignora para las variables de entorno HOME, SHELL, USER, LOGNAME y PATH.

-h, --help

Muestra el texto de ayuda y sale.

-V, --version

Muestra la versión y sale.

ARCHIVOS DE CONFIGURACIÓN

runuser lee los archivos de configuración /etc/default/runuser y /etc/login.defs. Los siguientes elementos de configuración son relevantes para runuser:

ENV_PATH (string)

Define la variable de entorno PATH para un usuario normal. El valor predeterminado es /usr/local/bin:/bin:/usr/bin.

ENV_ROOTPATH (string), ENV_SUPATH (string)

Define la variable de entorno PATH para root. ENV_SUPATH tiene prioridad. El valor predeterminado es /usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin.

ALWAYS_SET_PATH (boolean)

Si se establece en yes y no se especificaron --login y --preserve-environment, runuser inicializa PATH.

La variable de entorno PATH puede ser diferente en sistemas donde /bin y /sbin se fusionan en /usr; esta variable también se ve afectada por la opción de línea de comandos --login y la configuración del sistema PAM (por ejemplo, pam_env(8)).

ESTADO DE SALIDA

runuser normalmente devuelve el estado de salida del comando que ejecutó. Si el comando fue terminado por una señal, runuser devuelve el número de la señal más 128.

Estados de salida generados por runuser:

1

Error genérico antes de ejecutar el comando solicitado

126

El comando solicitado no se pudo ejecutar

127

El comando solicitado no se encontró
