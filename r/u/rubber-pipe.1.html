RUBBER(1) Manual de Comandos Generales RUBBER(1)

NOMBRE

rubber - un sistema de construcción para documentos LaTeX

SINOPSIS

rubber [opciones] fuentes ...
rubber-pipe [opciones]

DESCRIPCIÓN

Rubber es un envoltorio para LaTeX y programas compañeros. Su propósito es, dado un LaTeX fuente a procesar, compilarlo suficientes veces para resolver todas las referencias, ejecutando posiblemente programas satélite como BibTeX, makeindex, Metapost, etc. para producir archivos de datos apropiados.

El comando rubber construye completamente los documentos especificados. Los archivos fuente pueden ser tanto fuentes LaTeX (en cuyo caso se puede omitir la extensión .tex) como documentos en un formato que Rubber sepa cómo traducir a LaTeX. Si una compilación falla, todo el proceso se detiene, incluida la compilación de los siguientes documentos en la línea de comandos, y rubber devuelve un código de salida distinto de cero.

El comando rubber-pipe hace lo mismo para un documento, pero lee la fuente LaTeX desde la entrada estándar y vuelca el documento compilado en la salida estándar.

Alguna información no puede ser extraída de las fuentes LaTeX. Este es el caso, por ejemplo, de las rutas de búsqueda (que se pueden especificar en variables de entorno como TEXINPUTS), o el estilo a usar con Makeindex. Para abordar este problema, se puede añadir información para Rubber en los comentarios de las fuentes LaTeX, ver la sección DIRECTIVAS.

OPCIONES

Las opciones se usan para elegir la acción a realizar o para configurar el proceso de construcción. Son en su mayoría las mismas en rubber y rubber-pipe. Las opciones se analizan utilizando las convenciones de Getopt de GNU.

-b, --bzip2
Comprime el documento final (en formato bzip2). Esto equivale a decir -o bzip2 después de todas las demás opciones.
--clean
Elimina todos los archivos producidos por la compilación, en lugar de construir el documento. Esta opción solo está presente en rubber. Se aplica a la compilación tal como se haría con las otras opciones de la línea de comandos, es decir, decir "rubber --clean foo" no eliminará foo.ps, mientras que decir "rubber --ps --clean foo" sí lo hará.
-c, --command <comando>
Ejecuta el comando (o directiva) especificado antes de analizar los archivos de entrada. Ver la sección DIRECTIVAS para más detalles.
-e, --epilogue <comando>
Ejecuta el comando (o directiva) especificado después de analizar los archivos de entrada. Ver la sección DIRECTIVAS para más detalles.
-f, --force
Fuerza al menos una compilación de la fuente. Esto puede ser útil, por ejemplo, si alguna dependencia inusual fue modificada (p.ej. un paquete en un directorio del sistema). Esta opción es irrelevante en rubber-pipe.
-z, --gzip
Comprime el documento final (en formato gzip). Esto equivale a decir -o gz después de todas las demás opciones.
-h, --help
Muestra la lista de todas las opciones disponibles y sale amablemente.
--inplace
Ve al directorio de los archivos fuente antes de compilar, para que los resultados de la compilación estén en el mismo lugar que sus fuentes.
--into <directorio>
Ve al directorio especificado antes de compilar, para que todos los archivos se produzcan allí y no en el directorio actual.
--jobname <nombre>
Especifica un nombre de trabajo diferente al nombre base del archivo. Esto cambia el nombre de los archivos de salida y solo se aplica al primer objetivo.
-k, --keep
Esta opción solo se usa en rubber-pipe. Con esta opción, los archivos temporales no se eliminarán después de compilar el documento y volcar los resultados en la salida estándar. El documento temporal se llama rubtmpX.tex, donde X es un número tal que ningún archivo de ese nombre exista inicialmente.
-n, --maxerr <num>
Establece el número máximo de errores mostrados. Por defecto, se informan hasta 10 errores; decir -n -1 muestra todos los errores.
-m, --module <módulo>[:<args>]
Usa el módulo especificado además de los paquetes del documento. Se pueden pasar argumentos al paquete añadiéndolos después de dos puntos, corresponden a las opciones del paquete en LaTeX. El módulo se carga antes de analizar las fuentes del documento.
--only <fuentes>
Compila el documento parcialmente, incluyendo solo las fuentes especificadas. Esto funciona insertando una llamada a \includeonly en la línea de comandos. El argumento es una lista de nombres de archivo separados por comas.
-o, --post <módulo>[:<args>]
Usa el módulo especificado como post-procesador. Esto es similar a las opciones -m excepto que el módulo se carga después de analizar el documento.
-d, --pdf
Produce salida PDF. Cuando esta opción viene después de --ps (por ejemplo, en la forma -pd) es un sinónimo de -o ps2pdf, de lo contrario actúa como -m pdftex, para usar pdfLaTeX en lugar de LaTeX.
-p, --ps
Procesa el DVI producido por el proceso a través de dvips(1) para producir un documento PostScript. Esta opción es un sinónimo de -o dvips, no puede venir después de --pdf.
-q, --quiet
Disminuye el nivel de verbosidad. Es lo opuesto a -v.
-r, --read <archivo>
Lee directivas adicionales del archivo especificado (ver también la directiva "read").
-S, --src-specials
Habilita la generación de especiales de fuente si el compilador lo soporta. Esto equivale a establecer la variable src-specials a yes.
-s, --short
Muestra los mensajes de error de LaTeX en forma compacta (un error por línea).
-I, --texpath <directorio>
Añade el directorio especificado a la ruta de búsqueda de TeX.
--synctex
Habilita el soporte SyncTeX en la ejecución de LaTeX.
--unsafe
Permite que el documento invoque programas externos arbitrarios. Esto es potencialmente peligroso, solo usa esta opción para documentos de fuentes confiables.
-v, --verbose
Aumenta el nivel de verbosidad. Existen niveles entre 0 y 4, el nivel por defecto es 1 para rubber y 0 para rubber-pipe. Cuidado, decir -vvv hace que Rubber hable mucho.
--version
Imprime el número de versión y sale amablemente.
-W, --warn <tipo>
Informa información del tipo dado si no hubo errores durante la compilación. Los tipos disponibles son: boxes (cajas sobrerrllenadas o subllenadas), refs (referencias indefinidas o múltiplemente definidas), misc (otras advertencias) y all para informar todas las advertencias.

MÓDULOS

La acción de Rubber está influenciada por módulos. Los módulos se encargan de las características particulares de los paquetes y programas externos.

Paquetes

Por cada paquete que un documento usa, Rubber busca un módulo del mismo nombre para realizar las tareas que este paquete pueda requerir aparte de la compilación por LaTeX. Módulos

se pueden agregar a los proporcionados por defecto para incluir nuevas funcionalidades (este es el propósito del sistema de módulos). Los módulos estándar son los siguientes:

asymptote
Procesa los archivos .asy generados por el paquete LaTeX, luego activa una recompilación.
beamer
Este módulo maneja los archivos adicionales de Beamer de la misma manera que otras tablas de contenidos.
bibtex, biblatex
Se encarga de procesar la bibliografía del documento con BibTeX cuando sea necesario. Este módulo se carga automáticamente si el documento contiene la macro \bibliography (ver también en DIRECTIVAS para opciones).
combine
El paquete combine se utiliza para reunir varios documentos LaTeX en uno solo, y este módulo maneja las dependencias en este caso.
epsfig
Este módulo maneja la inclusión de gráficos para los documentos que usan la macro \psfig de estilo antiguo. Es en realidad una interfaz para el módulo graphics, ver este último para más detalles.
glossaries
Ejecuta makeglossaries y recompila cuando el archivo .glo cambia.
graphics, graphicx
Estos módulos identifican los gráficos incluidos en el documento y los consideran dependencias para la compilación. También utilizan reglas estándar para construir estos archivos con programas externos. Ver la documentación info para más detalles.
hyperref
Maneja los archivos adicionales que este paquete produce en algunos casos.
index, makeidx, nomencl
Procesa los índices y nomenclaturas del documento con makeindex(1) cuando sea necesario (ver sección DIRECTIVAS para opciones).
ltxtable
Agrega dependencias para archivos insertados a través del paquete LaTeX ltxtable.
minitoc, minitoc-hyper
Al limpiar, elimina archivos adicionales que se produjeron para crear tablas de contenidos parciales.
moreverb, verbatim
Agrega los archivos incluidos con \verbatiminput y macros similares a la lista de dependencias.
multibib
Maneja las bibliografías adicionales que crea este paquete y elimina los archivos adicionales al limpiar.
xr
Agrega archivos .aux adicionales utilizados para referencias externas a la lista de dependencias, de modo que la recompilación sea automática cuando los documentos referenciados se cambien.

Pre-procesamiento

Los siguientes módulos se proporcionan para usar programas que generan código fuente LaTeX a partir de un formato de archivo diferente:

cweb
El propósito de este módulo es ejecutar cweave(1) si es necesario antes del proceso de compilación para producir el código fuente LaTeX. Este módulo se carga automáticamente si el archivo especificado en la línea de comandos tiene .w como sufijo.
lhs2TeX
Este módulo utiliza el preprocesador lhs2TeX para generar el código fuente LaTeX a partir de un programa Literate Haskell. Se activa automáticamente si el nombre del archivo de entrada termina en .lhs.

Post-procesamiento

Los siguientes módulos se proporcionan para soportar diferentes tipos de post-procesamientos. Tenga en cuenta que el orden importa al usar estos módulos: si desea usar una cadena de procesamiento como

foo.tex -> foo.dvi -> foo.ps -> foo.pdf -> foo.pdf.gz
tiene que cargar los módulos dvips, ps2pdf y gz en ese orden, por ejemplo, usando la línea de comandos
rubber -p -o ps2pdf -z foo.tex
bzip2
Produce una versión del archivo final comprimida con bzip2(1).
dvipdfm
Ejecuta dvipdfm(1) al final de la compilación para producir un documento PDF.
dvips
Ejecuta dvips(1) al final de la compilación para producir un documento PostScript. Este módulo también se carga con la opción de línea de comandos --ps.
expand
Produce un código fuente LaTeX expandido reemplazando las macros \input por los archivos incluidos, las macros de bibliografía por la bibliografía producida por bibtex(1), y las clases y paquetes locales por su código fuente. Si el archivo principal es foo.tex entonces el archivo expandido se llamará foo-final.tex. Ver la documentación info para más detalles.
gz
Produce una versión del archivo final comprimida con gzip(1).
ps2pdf
Suponiendo que la compilación produce un documento PostScript (por ejemplo, usando el módulo dvips), convierte este documento a PDF usando ps2pdf(1).

Elección del compilador

Los siguientes módulos se utilizan para cambiar el compilador de LaTeX:

aleph
Utiliza el compilador Aleph en lugar de TeX, es decir, compila el documento usando lamed(1) en lugar de latex.
omega
Utiliza el compilador Omega en lugar de TeX, es decir, compila el documento usando lambda(1) en lugar de latex. Si el módulo dvips se usa también, utilizará odvips(1) para traducir el archivo DVI. Tenga en cuenta que este módulo se activa automáticamente cuando el documento utiliza el paquete omega.
pdftex
Indica a Rubber que utilice pdflatex(1) en lugar de latex(1) para compilar el documento. Por defecto, esto produce un archivo PDF en lugar de un DVI, pero al cargar el módulo con la opción dvi (por ejemplo, diciendo -m pdftex:dvi) el documento se compila a DVI usando pdflatex. Este módulo también se carga con la opción de línea de comandos --pdf.
vtex
Indica a Rubber que utilice el compilador VTeX. Por defecto utiliza vlatex como compilador para producir salida PDF. Con la opción ps (por ejemplo, al decir "rubber -m vtex:ps foo.tex") el compilador utilizado es vlatexp y el resultado es un archivo PostScript.
xelatex
Indica a Rubber que utilice xelatex(1) en lugar de latex.

DIRECTIVAS

El comportamiento automático de Rubber se basa en la búsqueda de macros en los códigos fuente de LaTeX. Cuando esto no es suficiente, se pueden agregar directivas en los comentarios de los códigos fuente. Una directiva es una línea como

% rubber: cmd args
La línea debe comenzar con un "%", luego cualquier secuencia de signos "%" y espacios, luego el texto "rubber:" seguido de espacios y un nombre de comando, posiblemente seguido de espacios y argumentos.

Directivas generales

alias <name1> <name2>
Pretender que la macro LaTeX name1 es equivalente a name2. Esto puede ser útil al definir envoltorios alrededor de macros compatibles.
clean <archivo>
Indica que el archivo especificado debe eliminarse al limpiar usando --clean.
depend <archivo>
Considerar el archivo especificado como una dependencia, de modo que su hora de modificación será verificada.
make <archivo> [<opciones>]
Declarar que el archivo especificado debe generarse. Las opciones pueden especificar la forma en que debe producirse, las opciones disponibles son from <archivo> para especificar la fuente y with <regla> para especificar la regla de conversión. Por ejemplo, decir "make foo.pdf from foo.eps" indica que foo.pdf debe producirse a partir de foo.eps, con cualquier regla de conversión que pueda hacerlo. Ver la documentación info para más detalles sobre conversión de archivos.
module <módulo> [<opciones>]
Carga el módulo especificado, posiblemente con opciones. Esto es equivalente a la opción de línea de comandos --module.
onchange <archivo> <comando>
Ejecuta el comando de shell especificado después de compilar si el contenido del archivo especificado ha cambiado. El nombre del archivo termina en el primer espacio.
path <directorio>
Agrega el directorio especificado a la ruta de búsqueda para TeX (y Rubber). El nombre del directorio es todo lo que sigue a los espacios después de "path".
produce <archivo>
Declara que la ejecución de LaTeX creará o actualizará el archivo especificado(s).
read <archivo>
Lee el archivo de directivas especificado. El archivo debe contener una directiva por línea. Las líneas vacías y las líneas que comienzan con "%" se ignoran.

NAME

rubber-pipe - invoke latex processing from within latex

SYNOPSIS

rubber-pipe [options] [file]

DESCRIPTION

Rubber is a script which can be invoked from within a LaTeX document. It is intended to automate some of the tedious tasks that are part of the preparation of a LaTeX document, such as running bibtex, makeindex, etc. multiple times until all references are resolved. Rubber itself is configured using directives within the LaTeX source.

The directives are plain LaTeX commands that are ignored by `latex` itself, but are detected by Rubber. They start with a dot, for instance, `.import`. They can be placed anywhere in the document.

Rubber can be used in two ways:

  • As a standalone program:
    rubber-pipe [options] [file]
    In this case, Rubber processes the given file (or the file `main.tex` if none is given) and runs the necessary tools (like latex, bibtex, etc.) as configured by the directives embedded in the source file.
  • As a filter:
    latex ... | rubber-pipe ...
    In this case, Rubber reads LaTeX code from standard input and writes the processed code to standard output. This is typically used to process input files that contain directives that need to be expanded before the main LaTeX run.

OPTIONS

The following options are supported by Rubber:

-d, --debug
Turn on debug messages. This option can be specified multiple times to increase the debugging level.
-f, --force
Force processing of the document, even if the timestamp suggests that it is not necessary. This is useful if the document has been modified in a way that is not reflected in the timestamps.
-h, --help
Show a short usage message and exit.
-o, --output-directory dir
Write all output files to the specified directory. By default, output files are written in the same directory as the input file.
-q, --quiet
Suppress informational messages. Only warnings and errors will be shown.
-s, --unsafe
Allow potentially unsafe operations, such as shell escapes. By default, these operations are disallowed.
-v, --version
Show program version and exit.
-w, --watch
Watch the document for changes and recompile automatically if needed.

MODULES

Rubber supports several modules that can be enabled or disabled using directives. The following modules are supported:

bibtex
Enable BibTeX support.
chapter
Enable chapter support. This directive is used to specify the base name of the main LaTeX file.
docstrip
Enable docstrip support. This directive is used to extract documentation from LaTeX source files.
index
Enable index support.
kpse
Enable kpse (Kernel PSE) support. This directive is used to add directories to the TeX search path.
multibbl
Enable multibbl support. This directive is used to manage multiple bibliographies.
natbib
Enable natbib support.
programs
Enable support for running arbitrary programs.
shell_escape
Enable shell escape support.
synctex
Enable SyncTeX support.

DIRECTIVES

The following directives are supported by Rubber:

.import <file>
Import directives from the specified file. The format of this file is the same as that of rules.ini, see the info documentation for details.
.set <name> <value>
Set the value of a variable as a string. For details on the existing variables and their meaning, see the info documentation.
.setlist <name> <values>
Set the value of a variable as a (space-separated) list of strings. For details on the existing variables and their meaning, see the info documentation.
.shell_escape
Mark the document as requiring external programs (shell-escape or write18). Rubber does not actually enable this unless called with the option --unsafe.
.synctex
Enable SyncTeX support in the LaTeX run.
.watch <file>
Watch the specified file for changes. If the contents of this file has changed after a compilation, then another compilation is triggered. This is useful in the case of tables of contents, for instance.

Module-specific directives

If a command has the form foo.bar, it is considered a command bar for the module foo. If this module is not registered when the directive is found, then the command is silently ignored. For the standard modules, the directives are the following:

.biblatex.path <directory>
Adds the specified directory to the search path for BibTeX databases (.bib files).
.bibtex.crossrefs <number>
Set the minimum number of crossref required for automatic inclusion of the referenced entry in the citation list. This sets the option -min-crossrefs when calling bibtex(1).
.bibtex.path <directory>
Adds the specified directory to the search path for BibTeX databases (.bib files).
.bibtex.stylepath <directory>
Adds the specified directory to the search path for BibTeX styles (.bst files).
.bibtex.tool <command>
Use a different bibliography tool instead of BibTeX.
.dvipdfm.options <options>
Pass the specified command-line switches to dvipdfm.
.dvips.options <options>
Pass the specified command-line switches to dvips.
.index.tool (index) <name>
Specifies which tool is to be used to process the index. The currently supported tools are makeindex(1) (the default choice) and xindy(1). The argument index is optional, it may be used to specify the list of indexes the command applies to. When present, it must be enclosed in parentheses; the list is comma-separated. When the argument is not present, the command applies to all indices.
.index.language (index) <language>
Selects the language used for sorting the index. This only applies when using xindy(1) as the indexing tool. The optional argument has the same semantics as above.
.index.modules (index) <module>...
Specify which modules to use when processing an index with xindy(1). The optional argument has the same semantics as above.
.index.order (index) <options>
Modifies the sorting options for the indexes. The arguments are words (separated by spaces) among standard, german and letter. This only applies when using makeindex(1). The optional argument has the same semantics as above.
.index.path (index) <directory>
Adds the specified directory to the search path for index styles (.ist files). The optional argument has the same semantics as above.
.index.style (index) <style>
Specifies the index style to be used. The optional argument has the same semantics as above.
.makeidx.language, .modules, .order, .path, .style, .tool
These directives are the same as for the index module, except that they don't accept the optional argument.
.multibib.crossrefs, .path, .stylepath, .tool
These directives are the same as for the bibtex module but they apply to bibliographies managed by the multibib package. They take an optional first argument, with the same convention as for the directives of the index module, which may be used to specify the list of bibliographies the command applies to.
