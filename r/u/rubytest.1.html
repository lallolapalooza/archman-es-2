Paquete: ruby-rubytest-cli

Licencias: BSD

RUBYTEST(1) RUBYTEST(1)

NOMBRE

rubytest - pruebas de ruby a través de la API de rubytest

DESCRIPCIÓN

El comando rubytest es una interfaz de línea de comandos para ejecutar pruebas para frameworks de prueba basados en RubyTest.

VISIÓN GENERAL

La herramienta de línea de comandos rubytest sigue muchas de las convenciones habituales, por lo que su uso es bastante sencillo. La opción -h/--help está disponible para detallar todas sus opciones. Aquí hay un ejemplo básico de uso.

$ rubytest -Ilib test/*_test.rb

Esto añadiría lib a la ruta de carga de Ruby ($LOAD_PATH) y luego cargaría todos los archivos de prueba que coincidan con el patrón glob test/*_test.rb.

Al ejecutar pruebas, debes asegurarte de cargar tu framework de pruebas o el adaptador Ruby Test de tu framework. Esto generalmente se hace a través de un script de ayuda en los archivos de prueba, pero también se puede hacer a través de opciones de línea de comandos, por ejemplo:

$ rubytest -r lemon -r ae test/test_*.rb

Por supuesto, puede ser tedioso tener que escribir un comando tan largo una y otra vez. Esto se puede solucionar con un archivo de configuración. Para utilizarlo, agregue un archivo etc/test.rb a un proyecto y añada entradas de Test.run (un alias para Test.configure) en él.

Test.run do |r|
  r.loadpath ´lib´
  r.test_files << ´test/*_test.rb´
end
Test.run ´coverage´ do |r|
  r.loadpath ´lib´
  r.test_files << ´test/*_test.rb´
  r.before do
    require ´simplecov´
    Simplecov.setup do |s|
      s.filter ´test/´
      s.command_name File.basename($0)
      s.coverage_dir ´log/coverage´
    end
    # para asegurar una cobertura adecuada
    require ´myapp´
  end
end

Ahora, cuando se use rubytest, se aplicará la primera configuración. Para usar la configuración de 'cobertura', utilice la opción -p/--profile.

$ rubytest -p coverage

De esta manera, un proyecto puede tener cualquier número de configuraciones de prueba diferentes, y es fácil seleccionar entre ellas.

Tenga en cuenta que el ejemplo anterior podría haber usado Test.configure en lugar de Test.run. Hacen lo mismo. Pero no use Test.run! porque eso provocará que las pruebas se ejecuten inmediatamente.

El archivo de configuración puede estar en el directorio config en lugar de etc, lo cual es bueno para proyectos Rails. Pero si prefiere un archivo en la raíz del proyecto, entonces Testfile o .test también se pueden usar en su lugar. Todas estas ubicaciones son compatibles simplemente porque ninguna convención de configuración ha tomado un sólido control en la comunidad de Ruby. Sin embargo, recomendamos encarecidamente usar etc/test.rb. Al final, esa parece ser la mejor convención general.

USO

rubytest [opciones] [archivos ...]

OPCIONES

  • -p --profile <NOMBRE> Usar perfil de configuración.
  • -f --format <NOMBRE> Formato del informe.
  • y --tapy Acceso directo para -f tapy.
  • -j --tapj Acceso directo para -f tapj.
  • -t --tag <TAG> Seleccionar pruebas por etiqueta.
  • -u --unit <TAG> Seleccionar pruebas por unidad de software.
  • -m --match <TEXTO> Seleccionar pruebas por descripción.
  • -A --autopath Añadir automáticamente rutas a $LOAD_PATH.
  • -I --loadpath <RUTA> Añadir la ruta dada a $LOAD_PATH.
  • -C --chdir <DIR> Cambiar de directorio antes de ejecutar las pruebas.
  • -R --chroot Cambiar al directorio raíz del proyecto antes de ejecutar las pruebas.
  • -r --require <ARCHIVO> Requerir archivo.
  • -c --config <ARCHIVO> Usar archivo de configuración alternativo.
  • -V --verbose Proporcionar detalles adicionales en los informes.
  • --[no-]ansi Activar/desactivar colores ANSI.
  • --debug Activar modo de depuración.
  • --about Mostrar información sobre rubytest.
  • --version Mostrar versión de rubytest.
  • -h --help Mostrar este mensaje de ayuda.
