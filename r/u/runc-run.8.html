NOMBRE

runc-run - crear e iniciar un contenedor

SINOPSIS

runc run [opción ...] id-de-contenedor

DESCRIPCIÓN

El comando run crea una instancia de un contenedor a partir de un paquete (bundle), y lo inicia. Puedes pensar en run como un atajo para create seguido de start.

OPCIONES

--bundle|-b ruta
Ruta a la raíz del directorio del paquete. Por defecto es el directorio actual.
--console-socket ruta
Ruta a un socket AF_UNIX que recibirá un descriptor de archivo que referencia el extremo maestro de la pseudoterminal de la consola. Ver docs/terminals ⟨https://github.com/opencontainers/runc/blob/master/docs/terminals.md⟩.
--detach|-d
Desasociarse del proceso del contenedor.
--pid-file ruta
Especificar el archivo donde se escribirá el PID del proceso inicial del contenedor.
--no-subreaper
Desactivar el uso del subreaper utilizado para recolectar procesos reparentados.
--no-pivot
No usar pivot root para encarcelar el proceso dentro de rootfs. Esto no debe utilizarse excepto en circunstancias excepcionales y puede ser inseguro desde el punto de vista de la seguridad.
--no-new-keyring
No crear un nuevo keyring de sesión para el contenedor. Esto hará que el contenedor herede la clave de sesión de los procesos que lo llaman.
--preserve-fds N
Pasar N descriptores de archivo adicionales al contenedor (stdio + $LISTEN_FDS + N en total). El valor por defecto es 0.
--keep
Conservar el directorio de estado y el cgroup del contenedor. Esto puede ser útil si un usuario quiere comprobar el estado (por ejemplo, de los controladores de cgroup) después de que el contenedor haya salido. Si se utiliza esta opción, se necesitará un runc delete manual después para limpiar los artefactos de un contenedor que ha salido.
