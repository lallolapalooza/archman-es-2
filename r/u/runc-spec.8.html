NOMBRE

runc-spec - crear un nuevo archivo de especificación

SINOPSIS

runc spec [opción ...]

DESCRIPCIÓN

El comando spec crea el nuevo archivo de especificación llamado config.json para el bundle.

La especificación generada es solo un archivo de inicio. Se requiere editar la especificación para lograr los resultados deseados. Por ejemplo, la especificación generada recientemente incluye un parámetro args que inicialmente se establece para llamar al comando sh cuando se inicia el contenedor. Llamar a sh puede funcionar para un contenedor de ubuntu o busybox, pero no funcionará para contenedores que no incluyan el binario sh.

OPCIONES

--bundle|-b ruta
Establece ruta a la raíz del directorio del bundle.
--rootless
Genera una configuración para un contenedor sin root. Ten en cuenta que esta opción es completamente diferente de la opción global --rootless.

EJEMPLOS

Para ejecutar un simple contenedor "hello-world", se necesita establecer el parámetro args en la especificación para llamar a hello. Esto se puede hacer usando sed(1), jq(1), o un editor de texto.

Los siguientes comandos:


- crearán un bundle para hello-world;
- cambiarán el comando a ejecutar en un contenedor a /hello usando jq(1);
- ejecutarán el comando hello en un nuevo contenedor hello-world llamado container1.

mkdir hello
cd hello
docker pull hello-world
docker export $(docker create hello-world) > hello-world.tar
mkdir rootfs
tar -C rootfs -xf hello-world.tar
runc spec
jq '.process.args |= ["/hello"]' < config.json > new.json
mv -f new.json config.json
runc run container1

En el comando run anterior, container1 es el nombre para la instancia del contenedor que estás iniciando. El nombre que proporciones para la instancia del contenedor debe ser único en tu host.

Una alternativa para generar una configuración de especificación personalizada es usar oci-runtime-tool; su subcomando oci-runtime-tool generate tiene muchas opciones que se pueden usar para realizar cualquier personalización que desees. Consulta runtime-tools ⟨https://github.com/opencontainers/runtime-tools⟩ para obtener más información.

Al iniciar un contenedor a través de runc, este último generalmente necesita privilegios de root. Si aún no se está ejecutando como root, puedes usar sudo(8), por ejemplo:

sudo runc start container1

Alternativamente, puedes iniciar un contenedor sin root, que tiene la capacidad de ejecutarse sin privilegios de root. Para que esto funcione, el archivo de especificación debe ajustarse en consecuencia. Puedes pasar la opción --rootless a este comando para generar un archivo de especificación sin root adecuado.

VER TAMBIÉN
