random(4) Manual de Controladores de Dispositivo random(4)

NOMBRE

random, urandom — dispositivos de fuente de números aleatorios del kernel

SINOPSIS

#include <linux/random.h>
int ioctl(fd, RNDrequest, param);

DESCRIPCIÓN

Los archivos especiales de caracteres /dev/random y /dev/urandom (presentes desde Linux 1.3.30) proporcionan una interfaz al generador de números aleatorios del kernel. El archivo /dev/random tiene el número de dispositivo principal 1 y el número de dispositivo menor 8. El archivo /dev/urandom tiene el número de dispositivo principal 1 y el número de dispositivo menor 9.

El generador de números aleatorios recopila ruido ambiental de los controladores de dispositivos y otras fuentes en un pool de entropía. El generador también mantiene una estimación de la cantidad de bits de ruido en el pool de entropía. A partir de este pool de entropía, se crean números aleatorios.

Linux 3.17 y posteriores proporcionan la interfaz getrandom(2), más simple y segura, que no requiere archivos especiales; consulte la página del manual de getrandom(2) para obtener detalles.

Al leer, el dispositivo /dev/urandom devuelve bytes aleatorios utilizando un generador de números pseudoaleatorios sembrado a partir del pool de entropía. Las lecturas de este dispositivo no se bloquean (es decir, no se cede la CPU), pero pueden incurrir en un retraso considerable al solicitar grandes cantidades de datos.

Cuando se lee durante el arranque temprano, /dev/urandom puede devolver datos antes de que se inicialice el pool de entropía. Si esto es una preocupación en su aplicación, utilice getrandom(2) o /dev/random en su lugar.

El dispositivo /dev/random es una interfaz heredada que se remonta a una época en la que los primitivos criptográficos utilizados en la implementación de /dev/urandom no eran ampliamente confiables. Devolverá bytes aleatorios solo dentro del número estimado de bits de ruido fresco en el pool de entropía, bloqueándose si es necesario. /dev/random es adecuado para aplicaciones que necesitan aleatoriedad de alta calidad y pueden permitirse retrasos indeterminados.

Cuando el pool de entropía está vacío, las lecturas de /dev/random se bloquearán hasta que se recopile ruido ambiental adicional. Desde Linux 5.6, la bandera O_NONBLOCK se ignora ya que /dev/random ya no se bloqueará excepto durante el proceso de arranque temprano. En versiones anteriores, si se llama a open(2) para /dev/random con la bandera O_NONBLOCK, una posterior llamada a read(2) no se bloqueará si no está disponible el número de bytes solicitado. En su lugar, se devuelven los bytes disponibles. Si no hay ningún byte disponible, read(2) devolverá -1 y errno se establecerá en EAGAIN.

La bandera O_NONBLOCK no tiene efecto al abrir /dev/urandom. Al llamar a read(2) para el dispositivo /dev/urandom, las lecturas de hasta 256 bytes devolverán tantos bytes como se soliciten y no serán interrumpidas por un manejador de señal. Las lecturas con un búfer por encima de este límite pueden devolver menos bytes que los solicitados o fallar con el error EINTR, si son interrumpidas por un manejador de señal.

Desde Linux 3.16, una llamada a read(2) desde /dev/urandom devolverá como máximo 32 MB. Una llamada a read(2) desde /dev/random devolverá como máximo 512 bytes (340 bytes antes de Linux 2.6.12).

Escribir en /dev/random o /dev/urandom actualizará el pool de entropía con los datos escritos, pero esto no resultará en un mayor contador de entropía. Esto significa que afectará el contenido leído de ambos archivos, pero no hará que las lecturas de /dev/random sean más rápidas.

Uso

La interfaz /dev/random se considera una interfaz heredada, y /dev/urandom se prefiere y es suficiente en todos los casos de uso, con la excepción de las aplicaciones que requieren aleatoriedad durante el arranque temprano; para estas aplicaciones, se debe utilizar getrandom(2) en su lugar, ya que se bloqueará hasta que se inicialice el pool de entropía.

Si se guarda un archivo de semilla a través de reinicios como se recomienda a continuación, la salida es criptográficamente segura contra atacantes sin acceso root local tan pronto como se recarga en la secuencia de arranque, y perfectamente adecuada para claves de sesión de cifrado de red. (Todas las distribuciones principales de Linux han guardado el archivo de semilla a través de reinicios desde el año 2000 al menos.) Dado que las lecturas de /dev/random pueden bloquearse, los usuarios normalmente querrán abrirlo en modo no bloqueante (o realizar una lectura con tiempo de espera), y proporcionar alguna notificación al usuario si la entropía deseada no está disponible inmediatamente.

Configuración

Si su sistema no tiene /dev/random y /dev/urandom creados ya, se pueden crear con los siguientes comandos:


mknod -m 666 /dev/random c 1 8
mknod -m 666 /dev/urandom c 1 9
chown root:root /dev/random /dev/urandom

Cuando un sistema Linux se inicia sin mucha interacción del operador, el pool de entropía puede estar en un estado bastante predecible. Esto reduce la cantidad real de ruido en el pool de entropía por debajo de la estimación. Para contrarrestar este efecto, ayuda llevar la información del pool de entropía a través de cierres y arranques. Para hacer esto, agregue las líneas a un script apropiado que se ejecute durante la secuencia de arranque del sistema Linux:


echo "Inicializando generador de números aleatorios..."
random_seed=/var/run/random-seed
# Lleva una semilla aleatoria de arranque a arranque
# Carga y luego guarda todo el pool de entropía
if [ -f $random_seed ]; then
    cat $random_seed >/dev/urandom
else
    touch $random_seed
fi
chmod 600 $random_seed
poolfile=/proc/sys/kernel/random/poolsize
[ -r $poolfile ] && bits=$(cat $poolfile) || bits=4096
bytes=$(expr $bits / 8)
dd if=/dev/urandom of=$random_seed count=1 bs=$bytes

Además, agregue las siguientes líneas a un script apropiado que se ejecute durante el apagado del sistema Linux:


# Lleva una semilla aleatoria de apagado a arranque
# Guarda todo el pool de entropía
echo "Guardando semilla aleatoria..."
random_seed=/var/run/random-seed
touch $random_seed
chmod 600 $random_seed
poolfile=/proc/sys/kernel/random/poolsize
[ -r $poolfile ] && bits=$(cat $poolfile) || bits=4096
bytes=$(expr $bits / 8)
dd if=/dev/urandom of=$random_seed count=1 bs=$bytes

En los ejemplos anteriores, asumimos Linux 2.6.0 o posterior, donde /proc/sys/kernel/random/poolsize devuelve el tamaño del pool de entropía en bits (ver más abajo).

Interfaces de /proc

Los archivos en el directorio /proc/sys/kernel/random (presentes desde Linux 2.3.16) proporcionan información adicional sobre el dispositivo /dev/random:

entropy_avail
Este archivo de solo lectura da la entropía disponible, en bits. Este será un número en el rango de 0 a 4096.
poolsize
Este archivo da el tamaño del pool de entropía. La semántica de este archivo varía entre versiones del kernel:
Linux 2.4:
Este archivo da el tamaño del pool de entropía en bytes. Normalmente, este archivo tendrá el valor 512, pero es escribible y puede cambiarse a cualquier valor para el cual exista un algoritmo disponible. Las opciones son 32, 64, 128, 256, 512, 1024 o 2048.
Linux 2.6 y posteriores:
Este archivo es de solo lectura y da el tamaño del pool de entropía en bits. Contiene el valor 4096.
read_wakeup_threshold
Este archivo contiene el número de bits de entropía requeridos para despertar a los procesos que duermen esperando entropía de /dev/random. El valor predeterminado es 64.
write_wakeup_threshold

Interfaz ioctl(2)

Las siguientes solicitudes de ioctl(2) están definidas en descriptores de archivo conectados a /dev/random o /dev/urandom. Todas las solicitudes realizadas interactuarán con el pool de entropía de entrada, afectando tanto a /dev/random como a /dev/urandom. La capacidad CAP_SYS_ADMIN se requiere para todas las solicitudes excepto RNDGETENTCNT.

RNDGETENTCNT
Recupera el recuento de entropía del pool de entrada; el contenido será el mismo que el archivo entropy_avail en proc. El resultado se almacenará en el entero apuntado por el argumento.
RNDADDTOENTCNT
Incrementa o decrementa el recuento de entropía del pool de entrada en el valor apuntado por el argumento.
RNDGETPOOL
Eliminado en Linux 2.6.9.
RNDADDENTROPY
Añade entropía adicional al pool de entrada, incrementando el recuento de entropía. Esto difiere de escribir en /dev/random o /dev/urandom, que solo añaden algunos datos pero no incrementan el recuento de entropía. Se utiliza la siguiente estructura:

struct rand_pool_info {
    int    entropy_count;
    int    buf_size;
    __u32  buf[0];
};

Aquí entropy_count es el valor que se suma (o resta) al recuento de entropía, y buf es el buffer de tamaño buf_size que se añade al pool de entropía.
RNDZAPENTCNT
RNDCLEARPOOL
Pone a cero el recuento de entropía de todos los pools y añade algunos datos del sistema (como el reloj de pared) a los pools.

NOTAS

ERRORES
