NOMBRE

"razor-report" - Agente de Informes de Razor

SINOPSIS

razor-report [opciones]  archivo_con_correo_en_formato_rfc822
$ cat correo | razor-report
$ razor-report ./correo 
$ razor-report -d ./correo

DESCRIPCIÓN

"razor-report" es el Agente de Informes de Razor que se utiliza para informar de mensajes de spam a un Servidor de Nominación de Razor. "razor-report" debería ser invocado generalmente desde un MUA (Agente de Usuario de Correo), aunque no hay restricciones para invocarlo desde la línea de comandos. "razor-report" es un filtro, lo que significa que los mensajes de spam deben ser canalizados a través de él. Por defecto, "razor-report" se pone en segundo plano y se desconecta de la terminal de control al iniciarse.

Si a "razor-report" se le pasa más de un correo, informará de cada uno contra la base de datos. Por favor, utilice esto con precaución, no queremos que la base de datos se llene con correos identificados incorrectamente como spam. "razor-report" soporta archivos con formato mbox con 1 o más correos en ellos, así como archivos que contienen un único correo RFC 822 (no-mbox). Puede haber más de un archivo en la línea de comandos, que puede ser tanto no-mbox como mbox en cualquier orden.

Sin embargo, no se pueden leer más de un correo no-mbox desde la entrada estándar. Tanto "razor-report" como razor-revoke(1) requieren autenticación del usuario para funcionar, vea razor-admin(1). Esto permite al Servidor de Nominación de Razor llevar un registro de cuántos mensajes informa y revoca un usuario. Cuantos más mensajes informe y/o revoque correctamente un usuario, más confianza ganará el usuario. Del mismo modo, cuando los mensajes se informan o revocan incorrectamente, la confianza de ese usuario disminuye. Los usuarios altamente confiables tendrán el mayor impacto en el Catálogo de Razor.

USO

"razor-report" acepta los siguientes argumentos:

"-h"
Imprime un mensaje de uso y sale.
"-v"
Imprime el número de versión y sale.
"-d | --verbose"
Imprime información de depuración en la salida estándar.
"-debuglevel=n | -dl=n"
Establece el nivel de depuración a 'n'. El valor por defecto es 3 sin la opción "-d", y 9 con ella.
"-whitelist=archivo"
Especifica el archivo a usar para la lista blanca. Anula la opción 'whitelist' en "razor-agent.conf".
"-s"
Simula una comprobación. Hace todo excepto hablar con el servidor.
"-conf=nombre_archivo"
Especifica un archivo de configuración alternativo. Si no se especifica, se calcula, vea la página del manual de razor-agents(1) para más detalles. Vea la página del manual de razor-agent.conf(5) para varias opciones de configuración. El valor por defecto es "<razorhome>/razor-agent.conf".
"-home=dir"
Especifica el directorio de razorhome. Aquí es donde residen el archivo de configuración, los archivos de registro, las identidades y los archivos del servidor. Si no se especifica, se calcula, vea la página del manual de razor-agents(1) para más detalles.
"-logfile=archivo"
Especifica el archivo a donde registrar en lugar de lo que hay en el archivo de configuración. El valor por defecto es "<razorhome>/razor-agent.log".
"-ident=nombre_archivo"
Especifica un archivo de identidad a usar para autenticarse con los Servidores Razor. Si no se especifica, se usa "<razorhome>/identity-<usuario>".
"-rs=razor.server.com"
Utiliza este Servidor de Nominación de Razor en lugar de leer "servers.nomination.lst".
"-H"
Calcula e imprime la firma del contenido del correo y sale. Si no se especifica "-e=entero", se usarán todos los motores soportados.
"-S=cadena"
Acepta una lista de firmas precalculadas (con "-H") en la línea de comandos, en lugar de calcular una a partir del contenido del correo. Las firmas se pueden enviar en hexadecimal o base64, pero se prefiere base64. Requiere "-e=entero". Uso:

razor-report -e 1 -S a8a3d545adb73f9733675571ffeaf10cba87745b

"-e=entero"
Especifica el motor utilizado para crear firmas. Debe ser 1, 2, 3 o 4 en esta versión. El motor 1, o "-e=1", se usa para las firmas de Razor 1.x. Se usa solo con "-S=cadena" o "-H".
"-ep4=cadena"
Cadena utilizada por el motor 4 al calcular firmas. Publicada por los Servidores de Nominación de Razor y actualizada muy frecuentemente. Se usa solo cuando "-e=4".
"-i=nombre_archivo"
Usa la identidad del archivo en lugar de leer <razorhome>/identity. Los Servidores Razor calculan la confianza para cada identidad única. Los Agentes Razor determinan la identidad mediante un proceso de 2 pasos. Primero, comprueban si la identidad se especifica a través de la línea de comandos (-i=archivo). Si no está ahí, buscan en <razorhome> el archivo de identidad. Si <razorhome> no tiene un archivo de identidad, la autenticación fallará - no puedes informar ni revocar. Vea razor-agents.conf(5) para más sobre <razorhome>. ---fixme----
"-a"
Solo autenticar. Si se autentica, sale con 0; si no, sale con 1.
"-f"
Permanece en primer plano, no se desconecta y se ejecuta en segundo plano.

INTEGRACIÓN CON MUTT

Añada la siguiente línea a "mutt.conf"

macro index S "|/usr/bin/razor-report"

Luego presione S sobre el mensaje de spam en "mutt" para informarlo con "razor-report". Dado que "razor-report" se bifurca, el control regresará inmediatamente.
