radrelay.conf(5) Archivo de configuración de FreeRADIUS radrelay.conf(5)

NOMBRE

radrelay.conf - archivo de configuración para la personalidad "radrelay" del servidor FreeRADIUS

DESCRIPCIÓN

El archivo radrelay.conf reside en el directorio de la base de datos de radius, por defecto /etc/raddb. Define la configuración global para el servidor FreeRADIUS, cuando el servidor opera como "radrelay".

FORMATO DEL ARCHIVO

Para una descripción detallada del formato del archivo, consulte "man radiusd.conf". Las entradas de configuración son muy similares para radrelay.conf, con algunas diferencias como se indica aquí.

REPLICACIÓN PARA COPIAS DE SEGURIDAD

Muchos sitios ejecutan múltiples servidores de radius; al menos un servidor principal y uno de respaldo. Cuando el principal falla, la mayoría de los NAS lo detectan y cambian al servidor de respaldo.

Esto provocará que sus paquetes de contabilidad vayan al servidor de respaldo, y algunos NAS ni siquiera vuelven al servidor principal cuando este vuelve a estar en línea.

El resultado es que se pierden registros de contabilidad, y/o el administrador debe hacer malabares para combinar los diferentes archivos de detalle de múltiples servidores. También significa que la base de datos de sesiones ("radutmp", utilizada para radwho y detección de uso simultáneo) se desincroniza.

radrelay resuelve este problema "retransmitiendo" paquetes de un servidor a otro, de modo que ambos tengan el mismo conjunto de datos de contabilidad.

ALMACENAMIENTO TEMPORAL PARA SERVIDORES DE ALTO TRÁFICO

Si el servidor RADIUS recibe repentinamente muchos paquetes de contabilidad, puede que no haya suficiente potencia de CPU para procesarlos todos a tiempo. Este problema es especialmente notable cuando los paquetes de contabilidad van a una base de datos de backend.

Del mismo modo, puede tener una base de datos que rastrea las sesiones "en vivo" y otra que rastrea los datos históricos de contabilidad. En ese caso, el acceso a la primera base de datos es rápido, ya que es pequeña. El acceso a la segunda base de datos puede ser más lento, ya que puede contener varios gigabytes de datos. Además, escribir en la primera base de datos a tiempo es importante, mientras que los datos pueden escribirse en la segunda base de datos con unos minutos de retraso, sin que ocurra ningún daño.

RETRANSMISIÓN DE PAQUETES DE CONTABILIDAD

El archivo radrelay.conf controla la personalidad "radrelay" del servidor, que puede realizar ambas funciones anteriores al mismo tiempo.

USO

Primero, debe configurar el servidor radius principal para registrar en un archivo de detalle adicional y único. Esto se puede hacer agregando una instancia adicional del módulo de detalle a radiusd.conf:

Por ejemplo:

	detalles radrelay-detalle {
		nombre_archivo = ${radacctdir}/radrelay/detalle
		permisos = 0600
		permisos_directorio = 0755
		bloqueo = sí
	}
	...
	contabilidad {
		...
		radrelay-detalle
		...
	}

Esta configuración hará que los paquetes de contabilidad se registren en el archivo ${radacctdir}/radrelay/detalle. Este archivo no debe ser rotado por los scripts de rotación de registros estándar, ya que el programa radrelay lo leerá y rotará.

EJEMPLO DE RADRELAY.CONF

Consulte el archivo radrelay.conf para obtener instrucciones detalladas sobre las entradas de configuración, su significado y cómo utilizarlas.

Para que la porción "radrelay" del servidor lea el archivo de detalle anterior, configure radrelay.conf con la siguiente sección:

	escuchar {
		tipo = detalle
		nombre_archivo = ${radacctdir}/radrelay/detalle
		max_pendientes = 100
		identidad = radrelay
	}

El servidor leerá los paquetes de contabilidad del archivo de detalle y los procesará como si los hubiera recibido del NAS. Por lo tanto, debe configurar la sección "contabilidad" de radrelay.conf para escribir los registros de contabilidad en un módulo "sql", o para enviarlos a otro servidor RADIUS.

Luego, inicie el servidor con el siguiente comando:

$ radiusd -n radrelay

El servidor debería iniciarse, leer el archivo de detalle y procesar los paquetes de contabilidad del mismo.

NOTAS

El archivo radiusd.conf no se lee en absoluto cuando el servidor se está ejecutando como radrelay. Por favor, edite radrelay.conf.
