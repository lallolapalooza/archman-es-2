RABBITMQ-SERVICE.BAT(8) Manual del Administrador del Sistema RABBITMQ-SERVICE.BAT(8)

NOMBRE

rabbitmq-service.bat — herramienta para gestionar el servicio de RabbitMQ en Windows

SINOPSIS

rabbitmq-service.bat [comando]

DESCRIPCIÓN

RabbitMQ es un bróker de mensajería de código abierto multiplataforma.

Ejecutar rabbitmq-service.bat permite que el bróker RabbitMQ se ejecute como un servicio en entornos Windows®. El servicio del bróker RabbitMQ puede iniciarse y detenerse utilizando el panel de servicios de Windows®.

Por defecto, el servicio se ejecutará en el contexto de autenticación de la cuenta del sistema local. Por lo tanto, es necesario sincronizar las cookies de Erlang entre la cuenta del sistema local (típicamente C:\Windows\.erlang.cookie) y la cuenta que se utilizará para ejecutar rabbitmqctl(8).

COMANDOS

help
Muestra información de uso.
install
Instala el servicio. El servicio no se iniciará. Las invocaciones subsiguientes actualizarán los parámetros del servicio si las variables de entorno relevantes fueron modificadas.
remove
Elimina el servicio. Si el servicio está en ejecución, se detendrá automáticamente antes de ser eliminado. Como consecuencia, no se eliminarán archivos y rabbitmq-server(8) seguirá siendo operable.
start
Inicia el servicio. El servicio debe haber sido instalado correctamente de antemano.
stop
Detiene el servicio. El servicio debe estar en ejecución para que este comando tenga algún efecto.
disable
Deshabilita el servicio. Esto es el equivalente a establecer el tipo de inicio en Deshabilitado utilizando el panel de control de servicios.
enable
Habilita el servicio. Esto es el equivalente a establecer el tipo de inicio en Automático utilizando el panel de control de servicios.

AMBIENTE

RABBITMQ_SERVICENAME
Por defecto es RabbitMQ.
RABBITMQ_BASE
Nota: solo para Windows. Por defecto es el directorio de datos de aplicación del usuario actual. Esta es la ubicación de los directorios de logs y bases de datos.
RABBITMQ_NODENAME
Por defecto es "rabbit@". seguido del nombre de host calculado. Puede usarse para ejecutar múltiples nodos en el mismo host. Cada nodo en un clúster debe tener un RABBITMQ_NODENAME único. Para saber más, consulta la guía de clústeres de RabbitMQ
RABBITMQ_NODE_IP_ADDRESS
Por defecto, RabbitMQ se vinculará a todas las interfaces IPv6 e IPv4 disponibles. Esta variable limita el nodo a una interfaz de red o familia de direcciones. Para saber más, consulta la guía de redes de RabbitMQ
RABBITMQ_NODE_PORT
Puerto AMQP 0-9-1 y AMQP 1.0. Por defecto es 5672. Para saber más, consulta la guía de redes de RabbitMQ
ERLANG_SERVICE_MANAGER_PATH
Por defecto es C:\Archivos de Programa\erl{version}\erts-{version}\bin (o C:\Archivos de Programa (x86)\erl{version}\erts-{version}\bin para entornos de 64 bits). Esta es la ubicación de instalación del gestor de servicios de Erlang.
RABBITMQ_CONSOLE_LOG
Establece esta variable en new o reuse para que la salida de la consola del servidor se redirija a un archivo llamado NOMBRE_DEL_SERVICIO.debug en el directorio de datos de aplicación del usuario que instaló el servicio. En Vista será C:\Usuarios\AppData\nombreusuario\NOMBRE_DEL_SERVICIO. En versiones anteriores de Windows será C:\Documentos y Configuración\nombreusuario\Datos de Aplicación\NOMBRE_DEL_SERVICIO. Si RABBITMQ_CONSOLE_LOG se establece en new, se creará un nuevo archivo cada vez que se inicie el servicio. Si RABBITMQ_CONSOLE_LOG se establece en reuse, el archivo se sobrescribirá cada vez que se inicie el servicio. El comportamiento por defecto cuando RABBITMQ_CONSOLE_LOG no está establecido o está establecido en un valor distinto de new o reuse es descartar la salida del servidor.
