NOMBRE

rabbitmq-queues — Herramientas de gestión de colas de RabbitMQ

SINOPSIS

rabbitmq-queues [-q] [-s] [-l] [-n nodo] [-t tiempo_espera] comando [opciones_comando]

DESCRIPCIÓN

rabbitmq-queues es una herramienta de línea de comandos que proporciona comandos utilizados para gestionar colas, por ejemplo, para aumentar, reducir o reequilibrar réplicas de tipos de colas replicadas. Consulte la guía de colas quorum de RabbitMQ y la guía general de colas de RabbitMQ para obtener más información sobre los tipos de colas en RabbitMQ.

OPCIONES

-n nodo
El nodo predeterminado es "rabbit@nombre_host_destino", donde nombre_host_destino es el host local. En un host llamado "myserver.example.com", el nombre del nodo suele ser "rabbit@myserver" (a menos que se haya modificado RABBITMQ_NODENAME). La salida de "hostname -s" suele ser el sufijo correcto para usar después del signo "@". Consulte rabbitmq-server(8) para obtener detalles sobre la configuración de un nodo RabbitMQ.
-q, --quiet
Se selecciona el modo de salida silencioso. Los mensajes informativos se reducen cuando el modo silencioso está activo.
-s, --silent
Se selecciona el modo de salida mudo. Los mensajes informativos se reducen y las cabeceras de tabla se suprimen cuando el modo mudo está activo.
-t tiempo_espera, --timeout tiempo_espera
Tiempo de espera de la operación en segundos. No todos los comandos admiten tiempos de espera. El valor predeterminado es infinito.
-l, --longnames
Debe especificarse cuando el clúster está configurado para usar nombres de nodo largos (FQDN). Para obtener más información, consulte la guía de clústeres de RabbitMQ.
--erlang-cookie cookie
Secreto compartido para autenticarse en el nodo de destino. Es preferible utilizar un archivo local o la variable de entorno RABBITMQ_ERLANG_COOKIE en lugar de especificar esta opción en la línea de comandos. Para obtener más información, consulte la guía de herramientas CLI de RabbitMQ.

COMANDOS

help

Muestra la ayuda general y los comandos compatibles con rabbitmq-queues.

Cluster

grow nodo selector --vhost-pattern patrón --queue-pattern patrón --errors-only

Añade una nueva réplica en el nodo dado para todas o la mitad de las colas quorum coincidentes.

Los valores de selector admitidos son:

all
Selecciona todas las colas quorum
even
Selecciona colas quorum con un número par de réplicas

Ejemplo:

rabbitmq-queues grow "rabbit@nuevohost" "all" --vhost-pattern "un-vhost" --queue-pattern ".*"
rebalance tipo --vhost-pattern patrón --queue-pattern patrón

Reequilibra las réplicas líderes de cola entre los nodos del clúster.

Los valores de tipo admitidos son:

all
Todos los tipos de colas
quorum
Solo colas quorum
classic
Solo colas clásicas
stream
Solo streams

Ejemplo:

rabbitmq-queues rebalance "all" --vhost-pattern "un-vhost" --queue-pattern ".*"
shrink nodo

Reduce los clústeres de colas quorum eliminando cualquier miembro (réplica) en el nodo dado.

Ejemplo:

rabbitmq-queues shrink "rabbit@nodo-descomisionado"

Replicación

add_member cola nodo --vhost host-virtual

Añade un miembro (réplica) de cola quorum en el nodo dado.

Ejemplo:

rabbitmq-queues add_member --vhost "un-vhost" "una-cola" "rabbit@nuevo-nodo"
delete_member cola nodo --vhost host-virtual

Elimina un miembro (réplica) de cola quorum en el nodo dado.

Ejemplo:

rabbitmq-queues delete_member --vhost "un-vhost" "una-cola" "rabbit@nodo-descomisionado"

Colas

quorum_status cola --vhost host-virtual

Muestra el estado quorum de una cola quorum.

Ejemplo:

rabbitmq-queues quorum_status --vhost "un-vhost" "una-cola"
peek cola posicion --vhost host-virtual --timeout

Muestra los detalles de un mensaje en la posición dada de la cola. Este comando actualmente solo es compatible con colas quorum.

Ejemplo:

rabbitmq-queues peek --vhost "un-vhost" "una-cola" "1"
check_if_cluster_has_classic_queue_mirroring_policy

Comprobación de estado que sale con un código distinto de cero si hay políticas en el clúster que habilitan

COMMANDS

check_if_cluster_has_classic_queue_mirroring_policy

Health check that exits with a non-zero code if the cluster has any classic queue mirroring policies.

Classic queue mirroring has been deprecated since 2021 and was completely removed in the RabbitMQ 4.0 development cycle.

Example:

rabbitmq-queues check_if_cluster_has_classic_queue_mirroring_policy
check_if_node_is_quorum_critical

Health check that exits with a non-zero code if there are queues with minimum online quorum (queues that would lose their quorum if the target node is shut down).

Example:

rabbitmq-queues check_if_node_is_quorum_critical
