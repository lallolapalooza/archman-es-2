rage(1) Manual de comandos generales rage(1)

NOMBRE

rage - Una herramienta de cifrado simple, segura y moderna

SINOPSIS

rage [-h|--help] [-V|--version] [--max-work-factor] [-o|--output] [-e|--encrypt] [-r|--recipient] [-R|--recipients-file] [-p|--passphrase] [-a|--armor] [-d|--decrypt] [-i|--identity] [-j ] [ENTRADA]

DESCRIPCIÓN

rage cifra o descifra ENTRADA a SALIDA. El argumento ENTRADA es opcional y por defecto es la entrada estándar. Solo se puede especificar un archivo ENTRADA. Si no se especifica -o/--output, SALIDA por defecto es la salida estándar.

Si se especifica -p/--passphrase, el archivo se cifra con una contraseña solicitada interactivamente. De lo contrario, se cifra para uno o más DESTINATARIOS especificados con -r/--recipient o -R/--recipients-file. Cada destinatario puede descifrar el archivo.

En modo -d/--decrypt, los archivos cifrados con contraseña se detectan automáticamente y se solicita la contraseña de forma interactiva. De lo contrario, se utilizan uno o más IDENTIDADES especificados con -i/--identity para descifrar el archivo.

Los archivos cifrados con age son binarios y no maleables, con aproximadamente 200 bytes de sobrecarga por destinatario, más 16 bytes cada 64KiB de texto plano.

OPCIONES

-h, --help
Imprime este mensaje de ayuda y sale.
-V, --version
Imprime la información de la versión y sale.
--max-work-factor=WF
Factor de trabajo máximo permitido para el descifrado con contraseña.
-o, --output=SALIDA
Escribe el archivo cifrado o descifrado en SALIDA en lugar de la salida estándar. Si SALIDA ya existe, será sobrescrito.

Si se cifra sin -a/--armor, rage se negará a producir salida binaria en una TTY. Esto se puede forzar especificando "-" como SALIDA.

-e, --encrypt
Cifra ENTRADA a SALIDA. Esta es la opción por defecto.
-r, --recipient=DESTINATARIO
Cifra al DESTINATARIO especificado explícitamente. Consulte la sección DESTINATARIOS E IDENTIDADES para conocer los posibles formatos de destinatario.

Esta opción se puede repetir y combinar con otras banderas de destinatario, y el archivo puede ser descifrado por todos los destinatarios proporcionados de forma independiente.

-R, --recipients-file=RUTA
Cifra a los DESTINATARIOS listados en el archivo en RUTA, uno por línea. Las líneas vacías y las líneas que comienzan con "#" se ignoran como comentarios.

Si RUTA es "-", los destinatarios se leen de la entrada estándar. En este caso, el argumento ENTRADA debe ser especificado.

Esta opción se puede repetir y combinar con otras banderas de destinatario, y el archivo puede ser descifrado por todos los destinatarios proporcionados de forma independiente.

-p, --passphrase
Cifra con una contraseña, solicitada interactivamente desde la terminal. rage ofrecerá generar automáticamente una contraseña segura.

Esta opción no se puede usar con otras banderas de destinatario.

-a, --armor
Cifra en una codificación "blindada" solo ASCII.

El blindaje de age es una versión estricta de PEM con el tipo "AGE ENCRYPTED FILE", Base64 canónico "strict", sin cabeceras y sin soporte para datos adicionales al principio y al final.

El descifrado detecta y decodifica transparentemente el blindaje ASCII.

-d, --decrypt
Descifra ENTRADA a SALIDA.

Si ENTRADA está cifrada con contraseña, se detectará automáticamente y se solicitará la contraseña de forma interactiva. De lo contrario, se utilizarán las IDENTIDADES especificadas con -i/--identity.

El blindaje ASCII se detecta y decodifica transparentemente.

-i, --identity=IDENTIDAD
Descifra usando las IDENTIDADES en IDENTIDAD.

IDENTIDAD puede ser uno de los siguientes:

a. Un archivo que lista IDENTIDADES una por línea. Las líneas vacías y las líneas que comienzan con "#" se ignoran como comentarios.

b. Un archivo age cifrado con contraseña, que contiene IDENTIDADES una por línea como las anteriores. La contraseña se solicita interactivamente. Tenga en cuenta que los archivos de identidad protegidos con contraseña no son necesarios para la mayoría de los casos de uso, ya que el acceso al archivo de identidad cifrado implica el acceso a todo el sistema.

c. Un archivo de clave privada SSH, en formato PKCS#1, PKCS#8 o OpenSSH. Si la clave privada está protegida con contraseña, la contraseña se solicita interactivamente solo si la identidad SSH coincide con el archivo. Consulte la sección de claves SSH para obtener más información, incluidos los tipos de clave admitidos.

d. "-", lo que hace que una de las opciones anteriores se lea de la entrada estándar. En este caso, el argumento ENTRADA debe ser especificado.

Esta opción se puede repetir. Las identidades se prueban en el orden en que se proporcionan, y se utiliza la primera que coincida con uno de los destinatarios del archivo. Las identidades no utilizadas se ignoran, pero es un error si el archivo de ENTRADA está cifrado con contraseña y se especifica -i/--identity.

-j=NOMBRE-PLUGIN
Descifra usando el plugin sin datos NOMBRE-PLUGIN.

Esto es equivalente a usar -i/--identity con un archivo que contiene una única IDENTIDAD de plugin que no codifica datos específicos del plugin.

[ENTRADA]
Ruta a un archivo del cual leer.

DESTINATARIOS E IDENTIDADES

Los DESTINATARIOS son valores públicos, como una clave pública, a los que se puede cifrar un archivo. Las IDENTIDADES son valores privados, como una clave privada, que permiten descifrar un archivo cifrado al DESTINATARIO correspondiente.

Claves nativas X25519

Los pares de claves nativas de age se generan con rage-keygen(1), y proporcionan codificaciones pequeñas y cifrado seguro basado en X25519. Son el tipo de destinatario recomendado para la mayoría de las aplicaciones.

Una codificación de DESTINATARIO comienza con "age1" y se ve así:


age1gde3ncmahlqd9gg50tanl99r960llztrhfapnmx853s4tjum03uqfssgdh

Una codificación de IDENTIDAD comienza con "AGE-SECRET-KEY-1" y se ve así:


AGE-SECRET-KEY-1KTYK6RVLN5TAPE7VF6FQQSKZ9HWWCDSKUGXXNUQDWZ7XXT5YK5LSF3UTKQ

Un archivo cifrado no puede vincularse al destinatario nativo al que se cifra sin acceso a la identidad correspondiente.

Claves SSH

Como característica de conveniencia, rage también admite el cifrado a claves ssh(1) RSA o Ed25519. Las claves RSA deben tener al menos 2048 bits. Esta característica emplea criptografía más compleja y solo debe utilizarse cuando no hay una clave nativa disponible para el destinatario. Tenga en cuenta que es posible que las claves SSH no estén protegidas a largo plazo por el destinatario, ya que son revocables cuando se utilizan solo para autenticación.

Una codificación de DESTINATARIO es una clave pública SSH en el formato de "authorized_keys" (consulte la sección "FORMATO DEL ARCHIVO AUTHORIZED_KEYS" de sshd(8)), que comienza con "ssh-rsa" o "ssh-ed25519", como la siguiente:


ssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAABgQDULTit0KUehbi[...]GU4BtElAbzh8=
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIH9pO5pz22JZEas[...]l1uZc31FGYMXa

El comentario al final de la línea, si está presente, se ignora.

rage(1) — Arch manual pages

NAME

rage - a simple, modern, and secure file encryption tool

SYNOPSIS

rage [-e|-d] [-i identity]... [-r recipient]... [-R recipients-file]... [-p [passphrase]] [-P passphrase-file] [-m max-passphrase-bytes] [-o output-file] [-E] [-v] [-h] [input-file]...

DESCRIPTION

rage is a file encryption tool inspired by PGP, but without the complexity. It uses the X25519 public-key algorithm for encryption and decryption, with AES-GCM for symmetric encryption of the file contents. It also supports passphrases and plugins for extensibility.

OPTIONS

-e, --encrypt
Encrypt the given input files. This is the default mode if neither -e nor -d is specified.
-d, --decrypt
Decrypt the given input files.
-i identity, --identity identity
An identity to use for decryption. This can be a file path to a private key, or a passphrase. Can be specified multiple times. For more information, see the RECIPIENTS AND IDENTITIES section.
-r recipient, --recipient recipient
A recipient to encrypt the file for. This can be a public key, a passphrase, or a plugin identifier. Can be specified multiple times.
-R recipients-file, --recipients-file recipients-file
Read recipients from the specified file. Each line in the file is treated as a separate recipient. Can be specified multiple times.
-p [passphrase], --passphrase [passphrase]
Encrypt the file using a passphrase. If no passphrase is provided on the command line, rage will prompt for one. This option can be used in conjunction with -r to encrypt a file with both a passphrase and for specific recipients.
-P passphrase-file, --passphrase-file passphrase-file
Read the passphrase from the specified file. Can be used in conjunction with -p or -d.
-m max-passphrase-bytes, --max-passphrase-bytes max-passphrase-bytes
The maximum number of bytes to read from a passphrase file. Defaults to 1 MiB.
-o output-file, --output output-file
Write the output to the specified file. If not specified, output is written to stdout.
-E, --encrypt-to-stdout
When encrypting multiple files, write each encrypted file to stdout instead of inferring the filename from the input filename. This is useful when piping multiple files to rage.
-v, --verbose
Print verbose output to stderr.
-h, --help
Print help information and exit.

RECIPIENTS AND IDENTITIES

When encrypting, rage uses RECIPIENTS to determine who can decrypt the file. When decrypting, rage uses IDENTITIES to determine which private keys or passphrases to use.

A RECIPIENT is typically an age public key. It is a string starting with "age1". rage will encrypt the file so that only holders of the corresponding private key can decrypt it.

An IDENTITY is typically an age private key. It is a file passed individually to -i/--identity. Note that keys held on hardware tokens such as YubiKeys or accessed via ssh-agent(1) are not supported.

An encrypted file can be linked to the SSH public key it was encrypted to. This is so that rage can identify the correct SSH private key before requesting its password, if any.

Plugins

rage can be extended through plugins. A plugin is only loaded if a corresponding RECIPIENT or IDENTITY is specified. (Simply decrypting a file encrypted with a plugin will not cause it to load, for security reasons among others.)

A RECIPIENT for a plugin named "example" starts with "age1example1", while an IDENTITY starts with "AGE-PLUGIN-EXAMPLE-1". They both encode arbitrary plugin-specific data, and are generated by the plugin.

When either is specified, rage searches for age-plugin-example in the PATH and executes it to perform the file header encryption or decryption. The plugin may request input from the user through rage to complete the operation.

Plugins can be freely mixed with other plugins or natively supported keys.

A plugin is not bound to only encrypt or decrypt files meant for or generated by the plugin. For example, a plugin can be used to decrypt files encrypted to a native X25519 RECIPIENT or even with a passphrase. Similarly, a plugin can encrypt a file such that it can be decrypted without the use of any plugin.

Plugins for which the IDENTITY/RECIPIENT distinction doesn't make sense (such as a symmetric encryption plugin) may generate only an IDENTITY and instruct the user to perform encryption with the -e/--encrypt and -i/--identity flags. Plugins for which the concept of separate identities doesn't make sense (such as a password-encryption plugin) may instruct the user to use the -j flag.

EXAMPLES

Generate a new identity, encrypt data, and decrypt:

$ rage-keygen -o key.txt
Public key: age1ql3z7hjy54pw3hyww5ayyfg7zqgvc7w3j2elw8zmrj2kg5sfn9aqmcac8p

$ tar cvz ~/data | rage -r age1ql3z7hjy54pw3hyww5ayyfg7zqgvc7w3j2elw8zmrj2kg5sfn9aqmcac8p > data.tar.gz.age

$ rage -d -o data.tar.gz -i key.txt data.tar.gz.age

Encrypt example.jpg to multiple recipients and output to example.jpg.age:

$ rage -o example.jpg.age -r age1ql3z7hjy54pw3hyww5ayyfg7zqgvc7w3j2elw8zmrj2kg5sfn9aqmcac8p \
-r age1lggyhqrw2nlhcxprm67z43rta597azn8gknawjehu9d9dl0jq3yqqvfafg example.jpg
Encrypt to a list of recipients:

$ cat > recipients.txt
# Alice
age1ql3z7hjy54pw3hyww5ayyfg7zqgvc7w3j2elw8zmrj2kg5sfn9aqmcac8p
# Bob
age1lggyhqrw2nlhcxprm67z43rta597azn8gknawjehu9d9dl0jq3yqqvfafg

$ rage -R recipients.txt example.jpg > example.jpg.age

Encrypt and decrypt a file using a passphrase:

$ rage -p secrets.txt > secrets.txt.age
Using an autogenerated passphrase:
release-response-step-brand-wrap-ankle-pair-unusual-sword-train

$ rage -d secrets.txt.age > secrets.txt
Type passphrase:

Encrypt and decrypt with a passphrase-protected identity file:

$ rage -p <(rage-keygen) > key.age
Public key: age1yhm4gctwfmrpz87tdslm550wrx6m79y9f2hdzt0lndjnehwj0ukqrjpyx5
Using an autogenerated passphrase:
hip-roast-boring-snake-mention-east-wasp-honey-input-actress

$ rage -r age1yhm4gctwfmrpz87tdslm550wrx6m79y9f2hdzt0lndjnehwj0ukqrjpyx5 secrets.txt > secrets.txt.age

$ rage -d -i key.age secrets.txt.age > secrets.txt
Type passphrase:

Encrypt and decrypt with an SSH public key:

$ rage -R ~/.ssh/id_ed25519.pub example.jpg > example.jpg.age

$ rage -d -i ~/.ssh/id_ed25519 example.jpg.age > example.jpg

Encrypt and decrypt with age-plugin-yubikey:

$ age-plugin-yubikey
# Run interactive setup, generate identity file and obtain recipient.

$ rage -r age1yubikey1qwt50d05nh5vutpdzmlg5wn80xq5negm4uj9ghv0snvdd3yysf5yw3rhl3t secrets.txt > secrets.txt.age

$ rage -d -i age-yubikey-identity-388178f3.txt secrets.txt.age

Encrypt to the SSH keys of a GitHub user:

$ curl https://github.com/benjojo.keys | rage -R - example.jpg > example.jpg.age
