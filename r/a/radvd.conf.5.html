NOMBRE

radvd.conf - archivo de configuración del demonio de anuncio de router radvd

DESCRIPCIÓN

Este archivo describe la información que se incluye en el anuncio de router (RA) de una interfaz específica.

El archivo contiene una o más definiciones de interfaz de la forma:

interface nombre {
	lista de opciones específicas de interfaz
	lista de definiciones de prefijos
	lista de clientes (direcciones IPv6) a anunciar
	lista de definiciones de rutas
	lista de definiciones de RDNSS
	lista de definiciones de DNSSL
	lista de definiciones de ABRO
	lista de prefijos pref64 de NAT64
	lista de prefijos a ignorar automáticamente
	lista de direcciones de origen de RA aceptables
};

Todas las opciones posibles específicas de interfaz se detallan a continuación. Cada opción debe terminar con un punto y coma. Las opciones no distinguen entre mayúsculas y minúsculas.

Las definiciones de prefijos son de la forma:

prefix prefijo/longitud {
	lista de opciones específicas de prefijo
};

El prefijo puede ser un prefijo de red o la dirección de la interfaz. La dirección de la interfaz debe usarse al utilizar extensiones de IPv6 móvil.

El prefijo especial "::/64" también es compatible en sistemas que implementan getifaddrs() (en otros sistemas, la activación de la configuración falla y radvd se cierra). Cuando se configura, radvd elige todos los prefijos no de enlace local asignados a la interfaz y comienza a anunciarlos (a menos que se ignoren con autoignoreprefixes). Esto puede ser aplicable en escenarios distintos a 6to4 donde el prefijo ascendente puede cambiar. Esta opción es incompatible con la opción Base6to4Interface. La opción AdvRouterAddr siempre está habilitada cuando se utiliza esta configuración.

Todas las opciones posibles específicas de prefijo se describen a continuación. Cada opción debe terminar con un punto y coma.

Los valores decimales solo se permiten para MinDelayBetweenRAs, MaxRtrAdvInterval y MinRtrAdvInterval. Los valores decimales solo deben usarse cuando se utilizan extensiones de IPv6 móvil.

Las definiciones de ruta son de la forma:

route prefijo/longitud {
	lista de opciones específicas de ruta
};

El prefijo de una definición de ruta debe ser un prefijo de red; puede usarse para anunciar rutas más específicas a los hosts.

Las definiciones de RDNSS (servidor DNS recursivo) son de la forma:

RDNSS ip [ip] [ip] {
	lista de opciones específicas de rdnss
};

Cada bloque de definición de RDNSS tiene una longitud máxima de 2040 bytes, incluido el encabezado, lo que permite hasta 127 direcciones.

Si se excede la longitud, radvd registrará un error no fatal en lugar de enviar la opción.

Las definiciones de DNSSL (Lista de búsqueda DNS) son de la forma:

DNSSL sufijo [sufijo] [sufijo] [...] {
	lista de opciones específicas de dnssl
};

Cada bloque de definición de DNSSL tiene una longitud máxima de 2040 bytes, incluido el encabezado, aplicado después de que los sufijos se codifiquen según RFC1035, sección 3.1.

Si se excede la longitud, radvd registrará un error no fatal en lugar de enviar la opción.

Por defecto, radvd enviará anuncios de router multicast para que cada nodo en el enlace pueda utilizarlos. La lista de clientes (dirección IPv6) a los que anunciar y de los que aceptar solicitudes de router se puede configurar. Si se hace, radvd no envía mensajes a las direcciones multicast sino solo a las direcciones unicast configuradas. Las solicitudes de otras direcciones se rechazan a menos que UnrestrictedUnicast esté habilitado. Esto es similar a UnicastOnly pero incluye mensajes periódicos y configuración de acceso de clientes entrantes. Vea la sección de ejemplos para un caso de uso de esto.

Las definiciones son de la forma:

clients {
        lista de direcciones IPv6
};

Los clientes pueden prefijarse con "!" para ignorarlos completamente y nunca enviarles anuncios.

Por defecto, radvd utilizará la primera dirección de enlace local para la interfaz como dirección de origen para los anuncios de router. Esto se puede sobrescribir estableciendo manualmente la lista de direcciones de origen aceptables. Si se hace, radvd utilizará la primera dirección de la interfaz que esté presente en las direcciones de origen configuradas. Esta funcionalidad NO falsificará la dirección de origen, pero puede ser útil en combinación con VRRP u otra funcionalidad que realice una MAC virtual/de conmutación por error.

AdvRASrcAddress {
        lista de direcciones IPv6
};

Las definiciones de ABRO (Opción de Router Perimetral Autorizado) son de la forma:

abro dirección-ipv6 {
        lista de opciones específicas de abro
};

prefijo pref64 de NAT64 (el prefijo NAT64 incluido en los anuncios de router):

nat64prefix prefijo/longitud {
	lista de opciones específicas de prefijo NAT64
};

El valor de longitud solo puede ser /32, /40, /48, /56, /64 o /96.

Al usar el prefijo especial "::/64", esta opción forma una lista de exclusión para prefijos que no deben generarse y anunciarse automáticamente. No tiene ningún efecto en ninguna otra definición de prefijo.

Las definiciones son de la forma:

autoignoreprefixes {
        lista de prefijos IPv6
};

OPCIONES ESPECÍFICAS DE INTERFAZ

IgnoreIfMissing on|off

Un indicador de si la interfaz se ignora o no si no existe al arrancar.

Esto es útil para interfaces dinámicas que no están activas cuando radvd se inicia o que se deshabilitan y vuelven a habilitar dinámicamente durante el tiempo que radvd se ejecuta.

Las versiones actuales de radvd intentan automáticamente reactivar las interfaces.

Habilitar IgnoreIfMissing también suprime ciertas advertencias en los mensajes de registro relacionados con interfaces faltantes.

Por defecto: on

AdvSendAdvert on|off

Un indicador de si el router envía anuncios de router periódicos y responde a las solicitudes de router.

Esta opción ya no tiene que especificarse primero, pero debe estar on para habilitar el anuncio en esta interfaz.

Por defecto: off

UnicastOnly on|off

Indica que el tipo de enlace de la interfaz solo admite unicast. Esto evitará que se envíen anuncios no solicitados y hará que los anuncios solicitados se envíen unicast al nodo que los solicita. Esta opción es necesaria para enlaces no broadcast de acceso múltiple, como ISATAP.

Por defecto: off

UnrestrictedUnicast on|off

Un indicador de si se responderá o no a las solicitudes de router cuando haya una lista de clientes configurada.

Esto permite que se envíen anuncios no solicitados regulares a algunos clientes sin ignorar las solicitudes de router de clientes desconocidos.

Por defecto: off

AdvRASolicitedUnicast on|off

Indica que las solicitudes de router se responderán con anuncios de router unicast, como se recomienda en RFC7772. Las redes grandes con una alta concentración de dispositivos móviles pueden experimentar, por ejemplo, agotamiento de la batería, cuando los mensajes de anuncio de router solicitados son multicast.

Esto corresponde a la opción de Cisco IOS ipv6 nd ra solicited unicast

Por defecto: on

MaxRtrAdvInterval segundos

El tiempo máximo permitido entre el envío de anuncios de router multicast no solicitados desde la interfaz, en segundos.

Debe ser no inferior a 4 segundos y no superior a 1800 segundos.

Mínimo al usar extensiones de IPv6 móvil: 0.07.

Para valores inferiores a 0.2 segundos, se agregan 0.02 segundos para tener en cuenta las granularidades de programación según se especifica en RFC3775.

Por defecto: 600 segundos

MinRtrAdvInterval segundos

El tiempo mínimo permitido entre el envío de anuncios de router multicast no solicitados desde la interfaz, en segundos.

Debe ser no inferior a 3 segundos y no superior a 0.75 * MaxRtrAdvInterval.

Por defecto: 200 segundos

AdvDefaultLifetime segundos

El tiempo de vida predeterminado de la información de ruta por defecto, en segundos.

Debe ser no inferior a 2 segundos y no superior a 65535 segundos.

Default: 1800 segundos

AdvOtherConfigFlag on|off

Un indicador de si los hosts deben usar la información de configuración de direcciones (es decir, la lista de servidores DNS) que se anuncia en los anuncios de router.

Default: off

AdvLinkMTU bytes

El valor del campo MTU (Unidad de Transmisión Máxima) del enlace.

Si se establece en 0, el valor se obtendrá del host.

Default: 0

AdvReachableTime milisegundos

El tiempo que un nodo cree que un destino permanece alcanzable después de recibir un anuncio de confirmación de recepción. Se utiliza en el algoritmo de detección de duplicados de direcciones (DAD) y en el mantenimiento de la caché de vecino.

Debe ser no inferior a 0 milisegundos y no superior a 3600000 milisegundos.

Default: 0 milisegundos (este valor se obtiene del host)

AdvRetransTimer milisegundos

El tiempo de retransmisión del temporizador utilizado para las retransmisiones de mensajes de Neighbor Discovery.

Debe ser no inferior a 0 milisegundos y no superior a 3600000 milisegundos.

Default: 0 milisegundos (este valor se obtiene del host)

AdvCurHopLimit limit

El valor del campo Límite de Saltos Actual utilizado en los paquetes IP salientes.

Default: 64

AdvRouterLifetime segundos

El tiempo que la entrada de este router en la caché de vecinos de un host se considera válida. Debe ser un valor en segundos.

Puede ser un valor de 0 para indicar que este router no debe ser usado como router por defecto.

Si se establece en 0, este router no debe ser usado como router por defecto.

Debe ser no inferior a 0 segundos y no superior a 9000 segundos.

Default: 1800 segundos

AdvManagedFlag on|off

Un indicador de si los hosts deben usar la configuración gestionada de direcciones (es decir, SLAAC).

Default: off

AdvHomeAgentFlag on|off

Un indicador de si este router es un agente de inicio de Mobile IPv6.

Default: off

AdvHomeAgentInfo on|off

Un indicador de si se debe incluir información adicional sobre el agente de inicio.

Default: off

AdvNat64Prefix on|off

Un indicador de si se debe anunciar un prefijo NAT64.

Default: off

AdvPreference value

La preferencia del router, utilizada por los hosts para elegir un router por defecto.

El valor puede ser high, medium o low. El valor predeterminado es medium.

AdvDefaultPreference value

La preferencia del router, utilizada por los hosts para elegir un router por defecto.

El valor puede ser high, medium o low. El valor predeterminado es medium.

AdvRouterAddr on|off

Un indicador de si la dirección del router se debe incluir en los anuncios de router.

Default: on

MinDelayBetweenRAs milisegundos

El tiempo mínimo entre dos anuncios de router consecutivos que se envían en respuesta a una solicitud de router.

Default: 0 milisegundos

Base6to4Interface interface

Especifica la interfaz que se utilizará para el encapsulamiento 6to4. No se puede usar con el prefijo especial "::/64".

Adv6to4RelayFlag on|off

Un indicador de si se debe anunciar la dirección del relé 6to4.

Default: off

Adv6to4RelayTimeout segundos

El tiempo de espera para el relé 6to4.

Default: 1800 segundos

Adv6to4RelayAddress ipv6addr

La dirección del relé 6to4.

RegisteredIPv6ONLinkFlag on|off

Un indicador de si el prefijo IPv6 está en el enlace.

Default: on

RegisteredIPv6AutonomusFlag on|off

Un indicador de si el prefijo IPv6 es autónomo.

Default: on

RegisteredIPv6AddressFlag on|off

Un indicador de si la dirección IPv6 se utiliza como prefijo registrado.

Default: off

RegisteredIPv6RouterFlag on|off

Un indicador de si la dirección IPv6 se utiliza como prefijo de router.

Default: off

RegisteredIPv6HomeAgentFlag on|off

Un indicador de si la dirección IPv6 se utiliza como agente de inicio.

Default: off

RegisteredIPv6Preference value

La preferencia del prefijo IPv6 registrado.

El valor puede ser high, medium o low. El valor predeterminado es medium.

RegisteredIPv6Lifetime segundos

El tiempo de vida del prefijo IPv6 registrado.

Default: 1800 segundos

ROUTER ADVERTISEMENT OPTIONS

MaxRtrAdvInterval seconds

The maximum time allowed between sending multicast router advertisements from the interface, in seconds. This is defined as the protocol constant MAX_RTR_ADV_INTERVAL in RFC4861.

The value must be between 4 and 1800 seconds. Minimum when using Mobile IPv6 extensions: 0.03.

Default: 600

MinRtrAdvInterval seconds

The minimum time allowed between sending multicast router advertisements from the interface, in seconds. This is defined as the protocol constant MIN_RTR_ADV_INTERVAL in RFC4861. MIPv6 redefines this parameter to have a minimum of 0.03 seconds.

Minimum when using Mobile IPv6 extensions: 0.03.

Default: 0.33 * MaxRtrAdvInterval

MinDelayBetweenRAs seconds

The minimum time allowed between sending multicast router advertisements from the interface, in seconds.

This applies to solicited multicast RAs. This is defined as the protocol constant MIN_DELAY_BETWEEN_RAS in RFC4861. MIPv6 redefines this parameter to have a minimum of 0.03 seconds.

Minimum when using Mobile IPv6 extensions: 0.03.

Default: 3

AdvManagedFlag on|off

When set, hosts use the administered (stateful) protocol for address autoconfiguration in addition to any addresses autoconfigured using stateless address autoconfiguration. The use of this flag is described in RFC 4862.

Default: off

AdvOtherConfigFlag on|off

When set, hosts use the administered (stateful) protocol for autoconfiguration of other (non-address) information. The use of this flag is described in RFC 4862.

Default: off

AdvLinkMTU integer

The MTU option is used in router advertisement messages to ensure that all nodes on a link use the same MTU value in those cases where the link MTU is not well known.

If specified, i.e. not 0, must not be smaller than 1280 and not greater than the maximum MTU allowed for this link (e.g. ethernet has a maximum MTU of 1500. See RFC 4864).

Default: 0

AdvReachableTime milliseconds

The time, in milliseconds, that a node assumes a neighbor is reachable after having received a reachability confirmation. Used by the Neighbor Unreachability Detection algorithm (see Section 7.3 of RFC 4861). A value of zero means unspecified (by this router).

Must be no greater than 3,600,000 milliseconds (1 hour).

Default: 0

AdvRetransTimer milliseconds

The time, in milliseconds, between retransmitted Neighbor Solicitation messages. Used by address resolution and the Neighbor Unreachability Detection algorithm (see Sections 7.2 and 7.3 of RFC 4861). A value of zero means unspecified (by this router).

Default: 0

AdvCurHopLimit integer

The default value that should be placed in the Hop Count field of the IP header for outgoing (unicast) IP packets. The value should be set to the current diameter of the Internet. The value zero means unspecified (by this router).

Default: 64

AdvDefaultLifetime seconds

The lifetime associated with the default router in units of seconds. The maximum value corresponds to 18.2 hours. A lifetime of 0 indicates that the router is not a default router and should not appear on the default router list. The router lifetime applies only to the router's usefulness as a default router; it does not apply to information contained in other message fields or options. Options that need time limits for their information include their own lifetime fields.

Must be either zero or between MaxRtrAdvInterval and 9000 seconds.

Default: 3 * MaxRtrAdvInterval (Minimum 1 second).

AdvDefaultPreference low|medium|high

The preference associated with the default router, as either "low", "medium", or "high".

Default: medium

AdvSourceLLAddress on|off

When set, the link-layer address of the outgoing interface is included in the RA.

Default: on

RemoveAdvOnExit on|off

Upon shutdown, send a final advertisement with zero Router Lifetime. This should cause the router and routes to be immediately removed from the receiving end-nodes' route table. This may need to be disabled ("off") in an vrrp or carp setup.

Default: on

AdvHomeAgentFlag on|off

When set, indicates that sending router is able to serve as Mobile IPv6 Home Agent. When set, minimum limits specified by Mobile IPv6 are used for MinRtrAdvInterval and MaxRtrAdvInterval.

Default: off

AdvHomeAgentInfo on|off

When set, Home Agent Information Option (specified by Mobile IPv6) is included in Router Advertisements. AdvHomeAgentFlag must also be set when using this option.

Default: off

HomeAgentLifetime seconds

The length of time in seconds (relative to the time the packet is sent) that the router is offering Mobile IPv6 Home Agent services. A value 0 must not be used. The maximum lifetime is 65520 seconds (18.2 hours). This option is ignored, if AdvHomeAgentInfo is not set.

If both HomeAgentLifetime and HomeAgentPreference are set to their default values, Home Agent Information Option will not be sent.

Default: AdvDefaultLifetime

HomeAgentPreference integer

The preference for the Home Agent sending this Router Advertisement. Values greater than 0 indicate more preferable Home Agent, values less than 0 indicate less preferable Home Agent. This option is ignored, if AdvHomeAgentInfo is not set.

If both HomeAgentLifetime and HomeAgentPreference are set to their default values, Home Agent Information Option will not be sent.

Default: 0

AdvMobRtrSupportFlag on|off

When set, the Home Agent signals it supports Mobile Router registrations (specified by NEMO Basic). AdvHomeAgentInfo must also be set when using this option.

Default: off

AdvIntervalOpt on|off

When set, Advertisement Interval Option (specified by Mobile IPv6) is included in Router Advertisements. When set, minimum limits specified by Mobile IPv6 are used for MinRtrAdvInterval and MaxRtrAdvInterval.

The advertisement interval is based on the configured MaxRtrAdvInterval parameter except where this is less than 200ms. In this case, the advertised interval is ( MaxRtrAdvInterval + 20ms ).

Default: off

AdvCaptivePortalAPI "URL"

When set, advertise RFC8908 Captive-Portal API URL.

See RFC8952 Captive Portal Architecture, RFC8910 Captive-Portal Identification in DHCP and Router Advertisements (RAs) and RFC8908 Captive Portal API for more information.

Most likely you do not need this.

Default: not included

DeprecatePrefix on|off

Al apagar, esta opción hará que radvd deprecie el prefijo anunciándolo en el RA de apagado de radvd con un tiempo de vida preferido de cero y un tiempo de vida válido ligeramente superior a 2 horas. Esto animará a los nodos finales que utilizan este prefijo a depreciar inmediatamente cualquier dirección asociada. Tenga en cuenta que esta opción solo debe usarse cuando solo un router anuncia el prefijo en el enlace, de lo contrario, los nodos finales depreciarán las direcciones asociadas a pesar de que el prefijo aún sea válido para uso preferido.

Ver RFC4862, sección 5.5.3., "Procesamiento de anuncios de router", parte (e).

Default: off

DecrementLifetimes on|off

Esta opción hace que radvd disminuya los valores de los tiempos de vida preferidos y válidos para el prefijo con el tiempo. Los tiempos de vida se decrementan por el número de segundos desde el último RA. Si radvd recibe una señal SIGUSR1, restablecerá los valores de los tiempos de vida preferidos y válidos a los valores iniciales utilizados por radvd cuando comenzó. Si radvd nunca recibe una señal SIGUSR1, continuará disminuyendo los tiempos de vida hasta que el tiempo de vida preferido llegue a cero. Después de un RA final con un valor de tiempo de vida preferido de cero, radvd dejará de anunciar el prefijo. Si una señal SIGUSR1 hace que los tiempos de vida se restablezcan, el prefijo volverá a aparecer en los RAs.

Esta opción está destinada a ser utilizada junto con un cliente DHCPv6 que esté utilizando la opción Identity Association for Prefix Delegation (IA_PD) para adquirir un prefijo de un Router Delegante para uso por un Router Solicitante. En este escenario, los prefijos dentro del prefijo delegado que son anunciados por radvd envejecerían en paralelo y a la misma velocidad que el prefijo delegado, y expirarían aproximadamente al mismo tiempo, si la vida del prefijo delegado no se extiende.

Ver RFC3633, "Opciones de prefijo IPv6 para el protocolo de configuración dinámica de host (DHCP) versión 6".

Default: off

Base6Interface name

Si se especifica esta opción, este prefijo se combinará con la dirección IPv6 de la interfaz especificada por name. La longitud resultante del prefijo será 64.

Base6to4Interface name

Si se especifica esta opción, este prefijo se combinará con la dirección IPv4 de la interfaz name para producir un prefijo 6to4 válido. Los primeros 16 bits de este prefijo se reemplazarán por 2002 y los siguientes 32 bits de este prefijo se reemplazarán por la dirección IPv4 asignada a la interfaz name en el momento de la configuración. Los 80 bits restantes del prefijo (incluida la ID de SLA) se anunciarán según lo especificado en el archivo de configuración. Ver la siguiente sección para un ejemplo.

Si la interfaz name no está disponible en el momento de la configuración, se escribirá una advertencia en el registro y este prefijo se deshabilitará hasta que radvd se reconfigure.

Esta opción permite a los sistemas con direcciones IPv4 dinámicas actualizar sus prefijos 6to4 anunciados simplemente reiniciando radvd o enviando una señal SIGHUP para que radvd se reconfigure.

Tenga en cuenta que los prefijos 6to4 derivados de direcciones IPv4 asignadas dinámicamente deben anunciarse con un tiempo de vida significativamente más corto (ver las opciones AdvValidLifetime y AdvPreferredLifetime).

Para más información sobre 6to4, ver RFC 3056.

Default: 6to4 no se utiliza

OPCIONES ESPECÍFICAS DE RUTA

AdvRouteLifetime segundos|infinity

El tiempo de vida asociado con la ruta en unidades de segundos. El valor simbólico infinity representa el infinito (es decir, un valor de todos unos (0xffffffff)).

Default: 3 * MaxRtrAdvInterval

AdvRoutePreference low|medium|high

La preferencia asociada con el router predeterminado, como "low" (baja), "medium" (media) o "high" (alta).

Default: medium

RemoveRoute on|off

Al apagar, anunciar esta ruta con un tiempo de vida de cero segundos. Esto debería hacer que la ruta se elimine inmediatamente de la tabla de rutas de los nodos finales receptores.

Default: on

OPCIONES ESPECÍFICAS DE RDNSS

AdvRDNSSLifetime segundos|infinity
La duración máxima durante la cual se utilizarán las entradas RDNSS para la resolución de nombres. Un valor de 0 significa que el servidor de nombres ya no debe usarse. Como se describe en RFC8106, el uso del valor predeterminado o un valor más grande garantiza la fiabilidad de una entrada incluso bajo la pérdida de RAs en enlaces con una tasa relativamente alta de pérdida de paquetes.

Default: 3*MaxRtrAdvInterval

FlushRDNSS on|off

Al apagar, anunciar las entradas RDNSS con un tiempo de vida de cero segundos. Esto debería hacer que las direcciones RDNSS se eliminen inmediatamente de la lista de Servidores DNS Recursivos de los nodos finales.

Default: on

OPCIONES ESPECÍFICAS DE DNSSL

AdvDNSSLLifetime segundos|infinity;
La duración máxima durante la cual se utilizarán las entradas DNSSL para la resolución de nombres. Un valor de 0 significa que el sufijo ya no debe utilizarse. Como se describe en RFC8106, el uso del valor predeterminado o un valor más grande garantiza la fiabilidad de una entrada incluso bajo la pérdida de RAs en enlaces con una tasa relativamente alta de pérdida de paquetes.

Default: 3*MaxRtrAdvInterval

FlushDNSSL on|off

Al apagar, anunciar las entradas DNSSL con un tiempo de vida de cero segundos. Esto debería hacer que las entradas DNSSL se eliminen inmediatamente de la lista de búsqueda DNS de los nodos finales.

Default: on

OPCIONES ESPECÍFICAS DE ABRO

AdvValidLifetime segundos
El tiempo en unidades de que el conjunto de información del router de borde es válido. Un valor de todos los bits cero asume un valor predeterminado de 10.000 (~ una semana).
AdvVersionLow, AdvVersionHigh unsignedinteger
Ambas formas son un número de versión de 32 bits sin signo que corresponde al conjunto de información contenido en el mensaje RA.

OPCIONES ESPECÍFICAS DE NAT64 PREF64

AdvValidLifetime segundos

La duración en segundos (en relación con el momento en que se envía el paquete) durante la cual el prefijo es válido para el propósito de determinación de la existencia de NAT64. En caso de que el valor no sea un múltiplo de 8, la validez se redondea al múltiplo de 8 más cercano. El máximo es 65528 segundos.

Default: el menor valor entre 3 * MaxRtrAdvInterval y 65528

EJEMPLOS

interface eth0
{
        AdvSendAdvert on;
        prefix 2001:db8:0:1::/64
        {
                AdvOnLink on;
                AdvAutonomous on;
        };
};

Indica que el demonio de anuncios de router debe anunciar (AdvSendAdvert on;) el prefijo 2001:db8:0:1:: que tiene una longitud de 64 en la interfaz eth0. Además, el prefijo se marcará como autónomo (AdvAutonomous on;) y como en el enlace (AdvOnLink on;). Todas las demás opciones se dejan con sus valores predeterminados.

Para admitir la detección de movimiento de Nodos Móviles IPv6, la dirección de la interfaz debe usarse en lugar del prefijo de red:

interface eth0
{
        AdvSendAdvert on;
        prefix 2001:db8:0:1::4/64
        {
                AdvOnLink on;
                AdvAutonomous on;
                AdvRouterAddr on;
        };
};

Para el soporte 6to4, incluya la opción Base6to4Interface en cada sección de prefijo. Al usar una dirección IPv4 dinámica, establezca tiempos de vida de prefijo cortos para evitar que los hosts retengan prefijos inaccesibles después de que se haya asignado una nueva dirección IPv4. Al anunciar en una interfaz dinámica (por ejemplo, Bluetooth), omita la interfaz si aún no está activa.

interface bnep0
{
        IgnoreIfMissing on;
        AdvSendAdvert on;
        # Anunciar al menos cada 30 segundos
        MaxRtrAdvInterval 30;
        prefix 0:0:0:5678::/64
        {
                AdvOnLink on;
                AdvAutonomous on;
                Base6to4Interface ppp0;
                # Tiempos de vida muy cortos para direcciones dinámicas
                AdvValidLifetime 300;
                AdvPreferredLifetime 120;
        };
};

Dado que 6to4 está habilitado, el prefijo se anunciará como 2002:WWXX:YYZZ:5678::/64, donde WW.XX.YY.ZZ es la dirección IPv4 de ppp0 en el momento de la configuración. (Las direcciones IPv6 se escriben en hexadecimal mientras que las direcciones IPv4 se escriben en decimal, por lo que la dirección IPv4 WW.XX.YY.ZZ en el prefijo 6to4 se representará en hexadecimal).

En este caso específico, los scripts de configuración pueden enviar la señal HUP a radvd al activar bnep0.

EXAMPLES

The example below shows a configuration with unicast only Announce.

interface eth0
{
        AdvSendAdvert on;
        AdvManagedFlag off;
        AdvOtherConfigFlag off;
        unicast-clients
        {
                2001:db8:0:1::2;
        };
};

The example below shows a configuration for a router that should only announce a prefix to clients on a link.

interface eth0
{
        AdvSendAdvert on;
        prefix 2001:db8:0:1::/64
        {
                AdvOnLink on;
                AdvAutonomous on;
        };
        clients
        {
                2001:db8:0:1::2;
                fe80::21f:16ff:fe06:3aab;
        };
};

In the above configuration, the router sends router advertisements to the specified clients only. It will not send router advertisements to all clients on the link.

The example below shows a configuration with multiple unicast addresses.

interface eth0
{
        AdvSendAdvert on;
        prefix 2001:db8:0:1::/64
        {
                AdvOnLink on;
                AdvAutonomous on;
        };
        clients
        {
                2001:db8:0:1::2;
                2001:db8:0:1::3;
                fe80::21f:16ff:fe06:3aab;
                fe80::21d:72ff:fe96:aaff;
        };
};

The example below shows a configuration that uses only the clients listed in the configuration file.

interface eth0
{
        AdvSendAdvert on;
        prefix 2001:db8:0:1::/64
        {
                AdvOnLink on;
                AdvAutonomous on;
        };
        clients
        {
                fe80::21f:16ff:fe06:3aab;
                fe80::21d:72ff:fe96:aaff;
        };
};

This configuration would only announce the prefix to fe80::21f:16ff:fe06:3aab and fe80::21d:72ff:fe96:aaff. Furthermore, all RA requests of other clients are denied.

This may come in handy if you want to roll out IPv6 only partially because some clients are broken or untested.

interface lowpan0

		AdvRouterAddr on;
	};
	abro fe80::a200:0:0:1/64 {
		AdvVersionLow 10;
		AdvVersionHigh 2;
		AdvValidLifetime 2;
	};
