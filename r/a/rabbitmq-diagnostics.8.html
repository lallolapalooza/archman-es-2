NAME

rabbitmq-diagnostics — Herramientas de diagnóstico, monitorización y comprobación de estado de RabbitMQ

SYNOPSIS

rabbitmq-diagnostics [-q] [-s] [-l] [-n nodo] [-t tiempo_espera] comando [opciones_comando]

DESCRIPTION

rabbitmq-diagnostics es una herramienta de línea de comandos que proporciona comandos utilizados para el diagnóstico, monitorización y comprobación del estado de los nodos de RabbitMQ. Consulte las guías de documentación de RabbitMQ para obtener más información sobre el diagnóstico, la monitorización y las comprobaciones de estado de RabbitMQ.

rabbitmq-diagnostics permite al operador inspeccionar el estado del nodo y del clúster. Hay disponibles una serie de comprobaciones de estado para ser utilizadas de forma interactiva y por herramientas de monitorización.

Por defecto, si no es posible conectarse y autenticarse con el nodo de destino (por ejemplo, si está detenido), la operación fallará. Para saber más, consulte la guía de Monitorización de RabbitMQ

OPTIONS

-n nodo
El nodo por defecto es "rabbit@nombre_host_destino", donde nombre_host_destino es el host local. En un host llamado "myserver.example.com", el nombre del nodo será normalmente "rabbit@myserver" (a menos que RABBITMQ_NODENAME se haya anulado). La salida de "hostname -s" suele ser el sufijo correcto a usar después del signo "@". Consulte rabbitmq-server(8) para obtener detalles sobre la configuración de un nodo RabbitMQ.
-q, --quiet
Se selecciona el modo de salida silencioso. Los mensajes informativos se reducen cuando el modo silencioso está activo.
-s, --silent
Se selecciona el modo de salida mudo. Los mensajes informativos se reducen y las cabeceras de tabla se suprimen cuando el modo mudo está activo.
-t tiempo_espera, --timeout tiempo_espera
Tiempo de espera de la operación en segundos. No todos los comandos admiten tiempos de espera. El valor por defecto es infinito.
-l, --longnames
Debe especificarse cuando el clúster está configurado para usar nombres de nodo largos (FQDN). Para saber más, consulte la guía de Clústeres de RabbitMQ
--erlang-cookie cookie
Secreto compartido para usar en la autenticación con el nodo de destino. Prefiera usar un archivo local o la variable de entorno RABBITMQ_ERLANG_COOKIE en lugar de especificar esta opción en la línea de comandos. Para saber más, consulte la guía de Herramientas CLI de RabbitMQ

COMMANDS

La mayoría de los comandos proporcionados por rabbitmq-diagnostics inspeccionan el estado del nodo y del clúster o realizan comprobaciones de estado.

Los comandos que listan entidades de topología (por ejemplo, colas) utilizan la tabulación como delimitador de columnas. Estos comandos y sus argumentos se delegan a rabbitmqctl(8).

Algunos comandos ( list_queues, list_exchanges, list_bindings y list_consumers) aceptan un parámetro opcional vhost.

Los comandos list_queues, list_exchanges y list_bindings aceptan un parámetro de host virtual opcional para el cual mostrar los resultados. El valor por defecto es "/".

Monitorización, observabilidad y comprobaciones de estado

alarms

Lista las alarmas de recursos, si las hay, en el clúster.

Consulte la guía de Alarmas de Recursos de RabbitMQ para obtener más información.

Ejemplo:

alarms

Lists all alarms on the cluster nodes. Can also list alarms on a specific node using the -n option. (See rabbitmqctl(8)).

Example:

rabbitmq-diagnostics alarms
certificates

Displays the node certificates for every listener on target node that is configured to use TLS.

Example:

rabbitmq-diagnostics certificates
check_alarms

Health check that fails (returns with a non-zero code) if there are alarms in effect on any of the cluster nodes.

See RabbitMQ Resource Alarms guide to learn more.

Example:

rabbitmq-diagnostics check_alarms
check_certificate_expiration [--unit time_unit] [--within seconds]

Checks the expiration date on the certificates for every listener on target node that is configured to use TLS. Supported time units are:

  • days
  • weeks
  • months
  • years

Example:

rabbitmq-diagnostics check_certificate_expiration --unit weeks --within 6
check_local_alarms

Health check that fails (returns with a non-zero code) if there are alarms in effect on the target node.

See RabbitMQ Resource Alarms guide to learn more.

Example:

rabbitmq-diagnostics check_local_alarms
check_port_connectivity

Health check that fails (returns with a non-zero code) if any listener ports on the target node cannot accept a new TCP connection opened by rabbitmq-diagnostics

The check only validates if a new TCP connection is accepted. It does not perform messaging protocol handshake or authenticate.

See RabbitMQ Networking guide to learn more.

Example:

rabbitmq-diagnostics check_port_connectivity
check_port_listener port

Health check that fails (returns with a non-zero code) if the target node is not listening on the specified port (there is no listener that uses that port).

See RabbitMQ Networking guide to learn more.

Example:

rabbitmq-diagnostics check_port_listener 5672
check_protocol_listener protocol

Health check that fails (returns with a non-zero code) if the target node does not have a listener for the specified protocol.

See RabbitMQ Networking guide to learn more.

Example:

rabbitmq-diagnostics check_protocol_listener mqtt
check_running

Health check that fails (returns with a non-zero code) if the RabbitMQ application is not running on the target node.

If rabbitmqctl(8) was used to stop the application, this check will fail.

Example:

rabbitmq-diagnostics check_running
check_virtual_hosts

Health check that checks if all vhosts are running in the target node

Example:

rabbitmq-diagnostics check_virtual_hosts --timeout 60
cipher_suites

Lists cipher suites enabled by default. To list all available cipher suites, add the --all argument.

Example:

rabbitmq-diagnostics cipher_suites --format openssl --all
command_line_arguments

Displays target node's command-line arguments and flags as reported by the runtime.

Example:

rabbitmq-diagnostics command_line_arguments -n rabbit@hostname
consume_event_stream [--duration seconds | -d seconds] [--pattern pattern] [--timeout milliseconds]

Streams internal events from a running node. Output is jq-compatible.

Example:

rabbitmq-diagnostics consume_event_stream -n rabbit@hostname --duration 20 --pattern queue_.*
discover_peers

Runs a peer discovery on the target node and prints the discovered nodes, if any.

See RabbitMQ Cluster Formation guide to learn more.

Example:

rabbitmq-diagnostics discover_peers --timeout 60
environment
See environment in rabbitmqctl(8)
erlang_cookie_hash

Outputs a hashed value of the shared secret used by the target node to authenticate CLI tools and peers. The value can be compared with the hash found in error messages of CLI tools.

See RabbitMQ Clustering guide to learn more.

Example:

rabbitmq-diagnostics erlang_cookie_hash -q
erlang_version

Reports target node's Erlang/OTP version.

Example:

rabbitmq-diagnostics erlang_version -q
is_booting

Reports if RabbitMQ application is currently booting (not booted/running or stopped) on the target node.

Example:

rabbitmq-diagnostics is_booting
is_running

Reports if RabbitMQ application is fully booted and running (that is, not stopped) on the target node.

Example:

rabbitmq-diagnostics is_running
list_bindings [-p vhost] [bindinginfoitem ...]

See list_bindings in rabbitmqctl(8)

list_channels [channelinfoitem ...]

See list_channels in rabbitmqctl(8)

list_ciphers

See list_ciphers in rabbitmqctl(8)

list_connections [connectioninfoitem ...]

See list_connections in rabbitmqctl(8)

list_consumers [-p vhost]

See list_consumers in rabbitmqctl(8)

list_exchanges [-p vhost] [exchangeinfoitem ...]

See list_exchanges in rabbitmqctl(8)

list_hashes

See list_hashes in rabbitmqctl(8)

list_queues [-p vhost] [--offline | --online | --silent] [queueinfoitem ...]

See list_queues in rabbitmqctl(8)

log_file_names

Lists names of all log files that RabbitMQ might be writing to.

Example:

rabbitmq-diagnostics log_file_names -n rabbit@hostname
memory_breakdown

Prints a breakdown of memory usage by component on the target node.

Example:

rabbitmq-diagnostics memory_breakdown -n rabbit@hostname
memory_use

Prints total memory usage for the target node.

Example:

rabbitmq-diagnostics memory_use -n rabbit@hostname
node_version

Reports target node's RabbitMQ version.

Example:

rabbitmq-diagnostics node_version -q
open_file_descriptors

Prints number of open file descriptors for the target node's RabbitMQ process.

Example:

rabbitmq-diagnostics open_file_descriptors -n rabbit@hostname
os_info

Prints operating system information for the target node.

Example:

rabbitmq-diagnostics os_info -n rabbit@hostname
partitions

Reports network partitions detected by the target node.

See RabbitMQ Network Partitions guide to learn more.

Example:

rabbitmq-diagnostics partitions
pid

Reports the process ID (PID) of the target node's RabbitMQ application.

Example:

rabbitmq-diagnostics pid
policies [-p vhost]

Lists all policies in the specified virtual host (or all virtual hosts if -p is omitted).

Example:

rabbitmq-diagnostics policies -p /
read_log_file path

Prints the contents of the specified log file.

Example:

rabbitmq-diagnostics read_log_file /var/log/rabbitmq/rabbit@hostname.log
report

Runs a set of checks and outputs a diagnostic report. The report includes information about node status, cluster status, alarms, resource usage, etc.

Example:

rabbitmq-diagnostics report
set_policy name pattern definition [-p vhost] [--priority priority]

Sets a policy with the given name, pattern, and definition for the specified virtual host.

Example:

rabbitmq-diagnostics set_policy ha-all --pattern ".*" --definition '{"ha-mode": "all"}' -p /
status

Prints a summary of the target node's status, including information about the cluster, running applications, and listeners.

Example:

rabbitmq-diagnostics status
stop_app

Stops the RabbitMQ application on the target node. This is equivalent to running rabbitmqctl stop_app.

Example:

rabbitmq-diagnostics stop_app
stop_disk_high_watermark

Returns the configured value for the disk high watermark for the target node.

Example:

rabbitmq-diagnostics stop_disk_high_watermark
stop_memory_high_watermark

Returns the configured value for the memory high watermark for the target node.

Example:

rabbitmq-diagnostics stop_memory_high_watermark
sync_state

Reports the sync state of the target node's data structures. This is useful for diagnosing cluster synchronization issues.

Example:

rabbitmq-diagnostics sync_state
tcp_connections

Lists all active TCP connections to the target node.

Example:

rabbitmq-diagnostics tcp_connections
trace_on

Enables protocol tracing on the target node. All network traffic will be logged.

Use with caution, as this can generate a large amount of data.

Example:

rabbitmq-diagnostics trace_on
trace_off

Disables protocol tracing on the target node.

Example:

rabbitmq-diagnostics trace_off
update_cluster_settings file

Updates cluster settings from the specified file.

Example:

rabbitmq-diagnostics update_cluster_settings /path/to/settings.conf
upgrade_nodes

Performs an in-place upgrade of the RabbitMQ application on the target node.

See the RabbitMQ Upgrade guide for details.

Example:

rabbitmq-diagnostics upgrade_nodes
upgrade_minor_nodes

Performs an in-place upgrade of the RabbitMQ application on minor nodes in the cluster. Minor nodes are those that are not the first node in the cluster.

Example:

rabbitmq-diagnostics upgrade_minor_nodes
version

Prints the version of the rabbitmq-diagnostics tool.

Example:

rabbitmq-diagnostics version
vm_memory_breakdown

Prints a breakdown of Erlang VM memory usage for the target node.

Example:

rabbitmq-diagnostics vm_memory_breakdown -n rabbit@hostname
vm_memory_total

Prints total Erlang VM memory usage for the target node.

Example:

rabbitmq-diagnostics vm_memory_total -n rabbit@hostname
whoami

Prints the identity of the target node.

Example:

rabbitmq-diagnostics whoami
write_part_of_log start_line end_line

Writes a specified range of lines from the target node's log file to standard output.

Example:

rabbitmq-diagnostics write_part_of_log 100 200

COMMANDS

list_queues [--local] [queueinfoitem ...]

Ver list_queues en rabbitmqctl(8)

list_unresponsive_queues [--local] [--queue-timeout milisegundos] [columna ...] [--no-table-headers]

Ver list_unresponsive_queues en rabbitmqctl(8)

listeners

Lista los listeners (sockets enlazados) en este nodo. Úsalo para inspeccionar en qué protocolos y puertos el nodo está escuchando conexiones de clientes, herramientas CLI y peers.

Ver la guía de redes de RabbitMQ para aprender más.

Ejemplo:

rabbitmq-diagnostics listeners
log_tail [--number número | -N número] [--timeout milisegundos]

Imprime las últimas N líneas del log en el nodo

Ejemplo:

rabbitmq-diagnostics log_tail --number 100
log_tail_stream [--duration segundos | -d segundos] [--timeout milisegundos]

Transmite logs desde un nodo en ejecución durante un período de tiempo

Ejemplo:

rabbitmq-diagnostics log_tail_stream --duration 60
maybe_stuck

Muestrea periódicamente los rastreos de pila de todos los procesos Erlang ("hilos ligeros") en el nodo. Informa los procesos para los cuales las muestras de rastreo de pila son idénticas.

Muestras idénticas pueden indicar que el proceso no está avanzando, pero no son necesariamente una indicación de un problema.

Ejemplo:

rabbitmq-diagnostics maybe_stuck -q
memory_breakdown [--unit unidad_memoria]

Muestra el uso de memoria del nodo por categoría. Las unidades de memoria admitidas son:

  • bytes
  • megabytes
  • gigabytes
  • terabytes

Ver la guía de uso de memoria de RabbitMQ para aprender más.

Ejemplo:

rabbitmq-diagnostics memory_breakdown --unit gigabytes
observer [--interval segundos]

Inicia una interfaz de observer CLI en el nodo destino

Ejemplo:

rabbitmq-diagnostics observer --interval 10
ping

Chequeo de salud más básico. Tiene éxito si el nodo destino (runtime) está en ejecución y rabbitmq-diagnostics puede autenticarse con él correctamente.

report

Ver report en rabbitmqctl(8)

runtime_thread_stats [--sample-interval intervalo]

Realiza muestreo de la actividad de los hilos de runtime (kernel) durante intervalo segundos y lo informa.

Para que este comando funcione, Erlang/OTP en el nodo destino debe ser compilado con soporte de contabilidad de microestados y tener el paquete runtime_tools disponible.

Ejemplo:

rabbitmq-diagnostics runtime_thread_stats --sample-interval 15
schema_info [--no_table_headers] [columna ...] [--timeout milisegundos]

Ver schema_info en rabbitmqctl(8)

server_version

Informa la versión del nodo destino.

Ejemplo:

rabbitmq-diagnostics server_version -q
status

Ver status en rabbitmqctl(8)

tls_versions

Lista todas las versiones TLS admitidas por el runtime en el nodo destino. Ten en cuenta que RabbitMQ puede configurarse para aceptar solo un subconjunto de esas versiones; por ejemplo, SSLv3 está desactivado por defecto.

Ver la guía TLS de RabbitMQ para aprender más.

Ejemplo:

rabbitmq-diagnostics tls_versions -q
