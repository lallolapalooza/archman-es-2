RADIUSD(8) Servidor FreeRADIUS RADIUSD(8)

NOMBRE

radiusd - Servidor de Autenticación, Autorización y Contabilidad

SINOPSIS

radiusd [-C] [-d directorio_config] [-D directorio_diccionarios] [-f] [-h] [-i direccion_ip] [-l archivo_log] [-m] [-n nombre] [-p puerto] [-P] [-s] [-t] [-v] [-x] [-X]

DESCRIPCIÓN

FreeRADIUS es un servidor RADIUS de alto rendimiento y altamente configurable. Soporta muchos back-ends de bases de datos como archivos de texto plano, SQL, LDAP, Perl, Python, etc. También soporta muchos protocolos de autenticación como PAP, CHAP, MS-CHAP(v2), HTTP Digest y EAP (EAP-MD5, EAP-TLS, PEAP, EAP-TTLS, EAP-SIM, etc.).

También tiene soporte completo para el protocolo de consulta VLAN (VMPS) de Cisco y DHCP.

Por favor, lea la sección DEBUGGING a continuación. Contiene instrucciones para configurar rápidamente el servidor para su sistema local.

OPCIONES

Las siguientes opciones de línea de comandos son aceptadas por el servidor:

-C
Comprueba la configuración y sale inmediatamente. Si hay un problema al leer la configuración, el servidor saldrá con un código de estado distinto de cero. Si la configuración parece aceptable, el servidor saldrá con un código de estado cero.

Tenga en cuenta que esta comprobación tiene limitaciones. Debido a las complejidades que implica el inicio de un servidor RADIUS casi completado, estas comprobaciones son necesariamente incompletas. El servidor puede devolver un código de estado cero al ejecutarse con -C, pero aún puede salir con un error cuando se ejecuta normalmente.

Consulte la salida de radiusd -XC para obtener una lista informativa de qué módulos se comprueban para una configuración correcta y cuáles se omiten, y por lo tanto no se comprueban.

-d directorio_config
Por defecto es /etc/raddb. Radiusd busca aquí sus archivos de configuración, como el archivo dictionary y el archivo users.
-D directorio_diccionarios
Establece el directorio principal de diccionarios. Por defecto es /usr/share/freeradius.
-f
No se bifurca, permanece ejecutándose como un proceso en primer plano.
-h
Imprime información de ayuda sobre el uso.
-i direccion_ip
Define qué dirección IP utiliza el servidor para enviar y recibir paquetes.

Si se proporciona esta opción de línea de comandos, se ignoran la "bind_address" y todas las entradas "listen{}" en radiusd.conf.

Esta opción DEBE usarse junto con "-p".

-l archivo_log
Por defecto es ${logdir}/radius.log. Radiusd escribe su información de registro en este archivo. Si archivo_log es la cadena "stdout", el registro se escribirá en stdout.
-m
Al recibir SIGINT o SIGQUIT, sale limpiamente en lugar de inmediatamente. Esto es especialmente útil cuando se ejecuta el servidor con "valgrind".
-n nombre
Lee raddb/nombre.conf en lugar de raddb/radiusd.conf.
-p puerto
Define qué puerto se utiliza para recibir paquetes de autenticación. Los paquetes de contabilidad se reciben en "puerto + 1".

Cuando se proporciona esta opción de línea de comandos, se ignoran todas las secciones "listen" en radiusd.conf.

Esta opción DEBE usarse junto con "-i".

-P
Escribe siempre el PID, incluso con -f.
-s
Ejecuta en modo de "servidor único". El servidor normalmente se ejecuta con múltiples hilos y/o procesos, lo que puede reducir su tiempo de respuesta a las solicitudes. Sin embargo, algunos sistemas tienen problemas con la concurrencia, por lo que ejecutar en modo de "servidor único" puede ayudar a abordar esos problemas. En modo de servidor único, el servidor tampoco se "daemonizará" (se ejecutará en segundo plano automáticamente).
-t
No genera hilos.
-v
Imprime la información de la versión del servidor y sale.
-X
Modo de depuración. Equivalente a "-sfxx -l stdout". Al intentar comprender cómo funciona el servidor, SIEMPRE ejecútelo con "radiusd -X". Para servidores de producción, use "raddebug"
-x
Modo de depuración de granularidad fina. En este modo, el servidor imprimirá detalles de cada solicitud en su salida de stdout. Puede especificar esta opción varias veces (-x -x o -xx) para obtener una salida más detallada.

DEPURACIÓN

La configuración predeterminada está configurada para funcionar en las circunstancias más amplias posibles. Requiere cambios mínimos para su sistema.

Sin embargo, sus necesidades pueden ser complejas y requerir cambios significativos en la configuración del servidor. Realizar cambios aleatorios es un método garantizado de fallo. En su lugar, RECOMENDAMOS ENCARECIDAMENTE proceder a través de los siguientes pasos:

1) Ejecute siempre el servidor en modo de depuración ( radiusd -X ) después de realizar un cambio de configuración. No podemos enfatizar esto lo suficiente. Si no está ejecutando el servidor en modo de depuración, no podrá ver lo que está haciendo y no podrá corregir ningún problema.

Si hace preguntas en la lista de correo, la primera respuesta será decirles "ejecute el servidor en modo de depuración". Por favor, siga estas instrucciones.

2) Cambie lo menos posible en los archivos de configuración predeterminados. El servidor contiene una década de experiencia con protocolos, bases de datos y diferentes sistemas. Su configuración predeterminada está diseñada para funcionar en casi todas partes y para hacer casi todo lo que necesita.

3) Cuando realice un pequeño cambio, pruébelo antes de cambiar nada más. Si el cambio funciona, guarde una copia de la configuración y realice otro cambio. Si el cambio no funciona, depúrelo y trate de entender por qué no funciona.

Si comienza realizando cambios importantes en la configuración del servidor, nunca funcionará y nunca podrá depurar el problema.

4) Si necesita agregar una conexión a una base de datos FOO (por ejemplo, LDAP o SQL), entonces:


a) Edite raddb/modules/foo
Este archivo contiene la configuración predeterminada para el módulo. Contiene comentarios que describen lo que se puede configurar y qué significan esas entradas de configuración.
b) Edite raddb/sites-available/default
Este archivo contiene la política predeterminada para el servidor. Por ejemplo, "habilitar la autenticación CHAP, MS-CHAP y EAP". Busque en este archivo todas las referencias a su módulo "foo". Lea los comentarios y elimine el hash ('#') inicial de las líneas que hacen referencia al módulo. Esto habilita el módulo.
c) Edite raddb/sites-available/inner-tunnel
Este archivo contiene la política predeterminada para la porción "tunelizada" de ciertos métodos EAP. Realice el mismo tipo de edición que arriba, para el archivo "default". Si no está utilizando EAP (802.1X), entonces este paso se puede omitir.
d) Inicie el servidor en modo de depuración ( radiusd -X ) y comience a probar.

5) Haga preguntas en la lista de correo (freeradius-users@lists.freeradius.org). Al hacer preguntas, incluya la salida del modo de depuración ( radiusd -X ). Esta información permitirá a las personas ayudarle. Si no la incluye, la primera respuesta a su mensaje será "publique la salida del modo de depuración".

Haga preguntas antes, no después. Si no puede resolver un problema en un día, haga una pregunta en la lista de correo. La mayoría de las preguntas ya se han visto y se pueden responder rápidamente.

CONFIGURACIÓN

Radiusd utiliza varios archivos de configuración. Cada archivo tiene su propia página man que describe el formato del archivo. Estos archivos son:

radiusd.conf
El archivo de configuración principal, que establece los elementos controlados por el administrador.
dictionary
Este archivo suele ser estático. Define todos los atributos RADIUS posibles utilizados en los otros archivos de configuración. No necesita modificarlo. Incluye otros archivos de diccionario en el mismo directorio.
hints
Define ciertas pistas para el servidor radius basándose en el nombre de inicio de sesión del usuario u otros atributos enviados por el servidor de acceso. También permite mapear nombres de usuario (como Pusername -> username). Esto proporciona la funcionalidad que el servidor de Livingston 2.0 tiene como soporte de "Prefijo" y "Sufijo" en el archivo users, pero es más general. Por supuesto, la forma de hacer las cosas de Livingston también está soportada, e incluso puede utilizar ambas al mismo tiempo (dentro de ciertos límites).
huntgroups
Define los grupos de búsqueda (huntgroups) que tiene, y hace posible restringir el acceso a ciertos grupos de búsqueda a ciertos (grupos de) usuarios.
users
Aquí se definen los usuarios. En una configuración típica, este archivo contiene principalmente entradas DEFAULT para procesar los diferentes tipos de inicios de sesión, basándose en las pistas del archivo hints. La autenticación se basa entonces en el contenido del archivo /etc/passwd de UNIX. Sin embargo, también es posible definir todos los usuarios, y sus contraseñas, en este archivo.
