raw(7) Manual de Información Miscelánea raw(7)

NOMBRE

raw - Sockets raw de IPv4 en Linux

SINOPSIS

#include <sys/socket.h>
#include <netinet/in.h>
raw_socket = socket(AF_INET, SOCK_RAW, int protocol);

DESCRIPCIÓN

Los sockets raw permiten implementar nuevos protocolos IPv4 en el espacio de usuario. Un socket raw recibe o envía el datagrama raw sin incluir las cabeceras de nivel de enlace.

La capa IPv4 genera una cabecera IP al enviar un paquete a menos que la opción de socket IP_HDRINCL esté habilitada en el socket. Cuando está habilitada, el paquete debe contener una cabecera IP. Para la recepción, la cabecera IP siempre se incluye en el paquete.

Para crear un socket raw, un proceso debe tener la capacidad CAP_NET_RAW en el espacio de nombres de usuario que rige su espacio de nombres de red.

Todos los paquetes o errores que coincidan con el número de protocolo especificado para el socket raw se pasan a este socket. Para una lista de los protocolos permitidos, consulte la lista IANA de números de protocolo asignados en http://www.iana.org/assignments/protocol-numbers/ y getprotobyname(3).

Un protocolo de IPPROTO_RAW implica que IP_HDRINCL está habilitado y es capaz de enviar cualquier protocolo IP que se especifique en la cabecera pasada. La recepción de todos los protocolos IP a través de IPPROTO_RAW no es posible usando sockets raw.

Campos de la cabecera IP modificados al enviar con IP_HDRINCL
Suma de comprobación IP Siempre completada
Dirección de origen Completada cuando es cero
ID del paquete Completado cuando es cero
Longitud total Siempre completada

Si se especifica IP_HDRINCL y la cabecera IP tiene una dirección de destino distinta de cero, entonces la dirección de destino del socket se utiliza para enrutar el paquete. Cuando se especifica MSG_DONTROUTE, la dirección de destino debe referirse a una interfaz local, de lo contrario, de todas formas se realiza una búsqueda en la tabla de enrutamiento, pero se ignoran las rutas de gateway.

Si IP_HDRINCL no está configurado, entonces las opciones de cabecera IP se pueden establecer en sockets raw con setsockopt(2); consulte ip(7) para más información.

A partir de Linux 2.2, todos los campos y opciones de la cabecera IP se pueden establecer utilizando opciones de socket IP. Esto significa que los sockets raw generalmente solo son necesarios para protocolos nuevos o protocolos sin interfaz de usuario (como ICMP).

Cuando se recibe un paquete, se pasa a cualquier socket raw que se haya enlazado a su protocolo antes de pasarlo a otros manejadores de protocolo (por ejemplo, módulos de protocolo del kernel).

Formato de dirección

Para enviar y recibir datagramas (sendto(2), recvfrom(2) y similares), los sockets raw utilizan la estructura de dirección sockaddr_in estándar definida en ip(7). El campo sin_port podría usarse para especificar el número de protocolo IP, pero se ignora para el envío en Linux 2.2 y posteriores, y siempre debe establecerse en 0 (ver BUGS). Para paquetes entrantes, sin_port se establece en cero.

Opciones de socket

Las opciones de socket raw se pueden establecer con setsockopt(2) y leer con getsockopt(2) pasando el indicador de familia IPPROTO_RAW.

ICMP_FILTER
Habilita un filtro especial para sockets raw enlazados al protocolo IPPROTO_ICMP. El valor tiene un bit establecido por cada tipo de mensaje ICMP que debe ser filtrado. El valor predeterminado es no filtrar ningún mensaje ICMP.

Además, se admiten todas las opciones de socket ip(7) IPPROTO_IP válidas para sockets de datagramas.

Manejo de errores

Los errores originados en la red solo se pasan al usuario cuando el socket está conectado o la bandera IP_RECVERR está habilitada. Para sockets conectados, solo se pasan EMSGSIZE y EPROTO por compatibilidad. Con IP_RECVERR, todos los errores de red se guardan en la cola de errores.

ERRORES

EACCES
El usuario intentó enviar a una dirección de broadcast sin tener la bandera de broadcast activada en el socket.
EFAULT
Se proporcionó una dirección de memoria inválida.
EINVAL
Argumento inválido.
EMSGSIZE
Paquete demasiado grande. Ya sea que el descubrimiento de MTU de ruta esté habilitado (la bandera de socket IP_MTU_DISCOVER) o que el tamaño del paquete exceda el tamaño máximo permitido de paquetes IPv4 de 64 kilo­bytes.
EOPNOTSUPP
Se pasó una bandera inválida a una llamada de socket (como MSG_OOB).
EPERM
El usuario no tiene permiso para abrir sockets raw. Solo los procesos con un ID de usuario efectivo de 0 o el atributo CAP_NET_RAW pueden hacerlo.
EPROTO
Ha llegado un error ICMP informando de un problema de parámetros.

VERSIONES

IP_RECVERR e ICMP_FILTER son nuevos en Linux 2.2. Son extensiones de Linux y no deben usarse en programas portátiles.

Linux 2.0 habilitó cierta compatibilidad de errores a errores con BSD en el código del socket raw cuando se configuraba la opción de socket SO_BSDCOMPAT; desde Linux 2.2, esta opción ya no tiene ese efecto.

NOTAS

Por defecto, los sockets raw realizan el descubrimiento de MTU (Unidad de Transmisión Máxima) de ruta. Esto significa que el kernel realizará un seguimiento de la MTU hacia una dirección IP de destino específica y devolverá EMSGSIZE cuando un paquete raw exceda dicho límite. Cuando esto sucede, la aplicación debe disminuir el tamaño del paquete. El descubrimiento de MTU de ruta también se puede desactivar usando la opción de socket IP_MTU_DISCOVER o el archivo /proc/sys/net/ipv4/ip_no_pmtu_disc, consulte ip(7) para más detalles. Cuando se desactiva, los sockets raw fragmentarán los paquetes salientes que excedan la MTU de la interfaz. Sin embargo, no se recomienda desactivarlo por razones de rendimiento y fiabilidad.

Un socket raw puede enlazarse a una dirección local específica usando la llamada bind(2). Si no está enlazado, se reciben todos los paquetes con el protocolo IP especificado. Además, un socket raw se puede enlazar a un dispositivo de red específico usando SO_BINDTODEVICE; consulte socket(7).

Un socket IPPROTO_RAW es solo para envío. Si realmente desea recibir todos los paquetes IP, use un socket packet(7) con el protocolo ETH_P_IP. Tenga en cuenta que los sockets de paquete no reasemblan fragmentos IP, a diferencia de los sockets raw.

Si desea recibir todos los paquetes ICMP para un socket de datagramas, a menudo es mejor usar IP_RECVERR en ese socket particular; consulte ip(7).

Los sockets raw pueden interceptar todos los protocolos IP en Linux, incluso protocolos como ICMP o TCP que tienen un módulo de protocolo en el kernel. En este caso, los paquetes se pasan tanto al módulo del kernel como a los socket(s) raw. Esto no debe confiarse en programas portátiles, muchas otras implementaciones de socket BSD tienen limitaciones aquí.

NOMBRE

raw - formato de socket de bajo nivel para protocolos IP

SINOPSIS

#include <sys/types.h>
#include <sys/socket.h>
#include <netinet/in.h>

int socket(AF_INET, SOCK_RAW, int protocol);

DESCRIPCIÓN

Los sockets crudos son un tipo especial de socket que se puede utilizar para enviar y recibir paquetes IP sin procesar. Solo los usuarios con privilegios de superusuario (o la capacidad CAP_NET_RAW) pueden crear sockets crudos.

El parámetro protocol en la llamada socket(2) especifica el protocolo de nivel superior que se va a manejar. Solo se pueden especificar protocolos que no sean IP. Los valores válidos son 0 (lo que significa que se requiere una cabecera IP para cada paquete enviado) o uno de los valores definidos en la cabecera protocols(7) (por ejemplo, IPPROTO_TCP, IPPROTO_UDP, IPPROTO_ICMP).

Cuando se crea un socket SOCK_RAW, el sistema operativo no adjunta ni elimina automáticamente la cabecera IP. En su lugar, se espera que el programa la proporcione.

El campo sin_port en la estructura sockaddr_in se puede utilizar para especificar el protocolo de nivel superior para los paquetes enviados en lugar de pasar un argumento protocol a socket(2). Si sin_port es distinto de cero, debe especificar el protocolo de nivel superior.

El uso de IP_HDRINCL como el campo sin_port o como argumento protocol a socket(2) hace que el kernel envíe el paquete tal como está (incluida la cabecera IP). Esto difiere de muchas otras implementaciones de sockets crudos.

Los sockets crudos son generalmente poco portables y deben evitarse en programas destinados a ser portables.

El envío en sockets crudos debe tomar el protocolo IP de sin_port; esta capacidad se perdió en Linux 2.2. La solución es usar IP_HDRINCL.

ERRORES

Las extensiones de proxy transparentes no se describen.

Cuando la opción IP_HDRINCL está establecida, los datagramas no se fragmentarán y están limitados a la MTU de la interfaz.

Establecer el protocolo IP para enviar en sin_port se perdió en Linux 2.2. Siempre se utiliza el protocolo al que estaba enlazado el socket o que se especificó en la llamada inicial a socket(2).

VERSIONES

El comportamiento de establecer el protocolo IP en sin_port se perdió en Linux 2.2.

NOTAS

Para la configuración de sockets crudos, el campo sin_family debe establecerse en AF_INET.

Si se especifica un protocolo de nivel superior válido a socket(2), los paquetes salientes que no tengan una cabecera IP válida serán descartados.

Los sockets crudos se utilizan típicamente para la implementación de protocolos de red o para fines de depuración de red.

El uso de sockets crudos requiere una comprensión profunda del funcionamiento de la pila de red.

BUGS

Las extensiones de proxy transparentes no se describen.

Cuando la opción IP_HDRINCL está establecida, los datagramas no se fragmentarán y están limitados a la MTU de la interfaz.

Establecer el protocolo IP para enviar en sin_port se perdió en Linux 2.2. Siempre se utiliza el protocolo al que estaba enlazado el socket o que se especificó en la llamada inicial a socket(2).
