RADARE2(1) Manual de Comandos Generales RADARE2(1)

NOMBRE

radare2 — Editor hexadecimal avanzado de línea de comandos, desensamblador y depurador

SINOPSIS

radare2 [-a arch] [-b bits] [-B baddr] [-c cmd] [-e k=v] [-i archivo] [-I prearchivo] [-k kernel] [-m addr] [-p proyecto] [-P parche] [-r rarun2] [-R reglar2] [-s addr] [-012AdDjwntLquvVxX] -|--|=|archivo

DESCRIPCIÓN

radare2 es un editor hexadecimal de línea de comandos.

"r2" es el nombre del programa alias para radare2.

Esta página del manual aún no está actualizada. Siéntase libre de contribuir.

Las opciones son:

--
Abrir radare2 en un archivo vacío
-
Equivalente de 'r2 malloc://512'
-0
Imprimir \x00 después de la inicialización y después de cada comando ejecutado
-1
Redirigir stderr a stdout
-2
Cerrar stderr antes de iniciar RCore
-a arch
Forzar asm.arch (x86, ppc, arm, mips, bf, java, ...)
-A
Ejecutar el comando 'aaa' antes del prompt o parche para analizar todo el código referenciado. Usar -AA para ejecutar aaaa
-b bits
Forzar asm.bits (16, 32, 64)
-B baddr
Especificar la dirección base a usar al cargar un nuevo binario. Ver 'e?bin.baddr'
-c cmd
Ejecutar el comando dado antes de mostrar el prompt
-d
Iniciar en modo depurador
-D dbg.backend
Habilitar modo depuración. Establecer cfg.debug=true
-e k=v
Establecer la variable de configuración de evaluación clave=valor. Por ejemplo -e scr.color=false. Cuando se pasa -e después de -j, establecerá la fuente del script a ejecutar en lugar de establecer variables de evaluación.
-f
Tamaño de bloque = tamaño del archivo
-j
Ejecutar script QJS si se pasa un argumento o entrar en el shell qjs si no se especifica archivo. Puede evaluar expresiones al pasar la opción -e después de -j.
-i archivo
Ejecutar archivo de script. Después de cargar el archivo
-I archivo
Ejecutar archivo de script. Antes de cargar el archivo
-k kernel
Seleccionar kernel (asm.os) para la resolución de syscalls
-l plugfile
Cargar archivo de plugin dado
-L
Listar plugins de IO cargados.
-LL
Listar plugins de core cargados.
-m addr
Mapear archivo en la dirección dada
-M
Deshabilitar demangling
-n
No realizar ningún análisis (r_bin). Solo cargar el archivo sin procesar
-nn
Solo cargar las estructuras rbin (elf, mach0, ...)
-N
No cargar la configuración del usuario/proyectos de ~/.radare2rc, ~/.config/radare2/radare2rc y los scripts dentro del directorio .../radare2rc.d/.
-NN
Igual que -N pero también deshabilita la carga automática de plugins en tiempo de inicio
-q
Modo silencioso (sin prompt) y salir después de ejecutar los comandos especificados con -i o -c
-qq
Salir antes de mostrar el prompt. Justo después de que todos los argumentos -e -c e -i se evalúen.
-Q
Igual que q, pero saliendo sin liberar RCore, esto produce fugas al salir, pero ahorra unos preciosos milisegundos para ejecutar la suite de pruebas en modo rápido.
-p prj
Establecer archivo de proyecto
-P archivo
Aplicar archivo rapatch y salir (ver doc/rapatch.md para más detalles)
-r rarun2
Especificar el perfil rarun2 de dbg.profile a usar al iniciar un programa para depuración
-R directiva-rarun2
Especificar directivas rarun2 personalizadas sin tener que crear un perfil rarun2
-s addr
Comenzar a buscar en esta dirección
-S
Habilitar modo sandbox (igual que -e cfg.sandbox=true)
-t
Obtener información del binario y analizar el binario en un hilo de fondo
-T
Evitar calcular los hashes del archivo
-u
Establecer bin.filter=false para cargar información rbin sin filtrar nombres
-v
Mostrar información de la versión y salir (Usar -qv para obtener solo el número de versión)
-V
Mostrar versiones de la biblioteca de radare2 (imprime formato JSON si se usa -j)
-w
Abrir en modo escritura
-h
Mostrar mensaje de ayuda
-H
Mostrar ayuda sobre archivos y entorno
-x
Abrir el mapa de archivo sin permisos de ejecución
-X
Igual que -e bin.usextr=false, no usar plugins extractores, útil para dyldcache

SHELL

Escriba '?' para obtener ayuda

VISUAL

Para entrar en modo visual, use el comando 'V'. Luego presione '?' para obtener ayuda.

DEBUGGER

En r2, los comandos del depurador se implementan bajo el comando 'd'. Escriba 'd?' para obtener ayuda.

radare2(1) — Arch manual pages

NAME

radare2

a portable reverse engineering framework

SYNOPSIS

radare2 [-Aanv] [-c CMD] [-d DEBUG_OPTS] [-e VAR=VAL] [-f] [-F FORMAT] [-k KEY] [-m MMAP] [-n] [-p PORT] [-q] [-s SCRIPT] [-u UNPACK] [-w] [-X] [-6 ARCH] [-o OUTDIR] [-j] [FILE [...]]

DESCRIPTION

radare2 is a complete framework for reverse engineering and analyzing any kind of file (ELF, PE, Mach-O, hex, disassembly, ...). It can be used for debugging, vulnerability research, code audit, malware analysis, and more.

It offers many features, including:

disassembly
Multiple instruction set architectures supported.
debugging
Attach to running processes or debug specific binaries.
analysis
Automatic analysis of code, data, strings, functions, etc.
patching
Modify code and data on the fly.
command line interface
A powerful command line interface for interactive use.
scripting
Scripting capabilities with multiple languages (JavaScript, Python, etc.).
graphical interface
Multiple GUI options available (e.g., via the r2gui plugin or third-party tools like radare2-ghidra).
plugins
Extensible plugin system for adding new features and analyses.
I/O
Support for various I/O methods (file, network, PTY, pipes, etc.).

SHELL

When no file is specified, radare2 starts in its own shell. You can enter commands directly, or use the ? command to get help.

Example of common commands:

o file
Open a file.
i
Show file information.
aaa
Analyze all.
s ADDRESS
Seek to an address.
p SIZE
Print data.
VV
Show the control flow graph.
q
Quit.

VISUAL

radare2 also supports a visual mode. Enter visual mode by typing V in the command line shell. Visual mode provides an interactive interface with multiple panels for code, hex dump, registers, etc. Use ? for help in visual mode.

DEBUGGER

radare2 can act as a debugger. You can attach to running processes using d command or debug specific binaries.

Common debugger commands:

d
Debugger commands.
dc
Continue execution.
ds
Step execution.
dr
Show/modify registers.
db ADDRESS
Set breakpoint.

ENVIRONMENT

radare2 recognizes the following environment variables:

R2_ARGS
Run radare2 with defined arguments in environment and ignore cli ones.
R2_IGNVER
Load plugins ignoring the specified version. (be careful)
R2_DEBUG
If defined, show error messages and crash signal.
R2_DEBUG_ASSERT=1
Set a breakpoint when hitting an assert.
R2_MAGICPATH
/Users/pancake/.local/share/radare2/share/radare2/4.5.0-git/magic
R2_NOPLUGINS
Do not load r2 shared plugins.
R2_RCFILE
~/.radare2rc (user preferences, batch script).
R2_RDATAHOME
/usr/local
FILE
Path to the current working file.
