random(7) Manual de Información Miscelánea random(7)

NOMBRE

random - descripción general de las interfaces para obtener aleatoriedad

DESCRIPCIÓN

El generador de números aleatorios del kernel se basa en la entropía recopilada de los controladores de dispositivos y otras fuentes de ruido ambiental para sembrar un generador de números pseudoaleatorios criptográficamente seguro (CSPRNG). Está diseñado para la seguridad, en lugar de la velocidad.

Las siguientes interfaces proporcionan acceso a la salida del CSPRNG del kernel:

•
Los dispositivos /dev/urandom y /dev/random, ambos descritos en random(4). Estos dispositivos han estado presentes en Linux desde tiempos tempranos, y también están disponibles en muchos otros sistemas.
•
La llamada al sistema específica de Linux getrandom(2), disponible desde Linux 3.17. Esta llamada al sistema proporciona acceso ya sea a la misma fuente que /dev/urandom (llamada la fuente urandom en esta página) o a la misma fuente que /dev/random (llamada la fuente random en esta página). Por defecto, es la fuente urandom; la fuente random se selecciona especificando la bandera GRND_RANDOM a la llamada al sistema. (La función getentropy(3) proporciona una interfaz ligeramente más portátil sobre getrandom(2).)

Inicialización del pool de entropía

El kernel recopila bits de entropía del entorno. Cuando se ha recopilado un número suficiente de bits aleatorios, el pool de entropía se considera inicializado.

Elección de la fuente aleatoria

A menos que esté generando claves a largo plazo (y lo más probable es que ni siquiera entonces), probablemente no debería leer del dispositivo /dev/random ni emplear getrandom(2) con la bandera GRND_RANDOM. En su lugar, lea del dispositivo /dev/urandom o emplee getrandom(2) sin la bandera GRND_RANDOM. Los algoritmos criptográficos utilizados para la fuente urandom son bastante conservadores, y por lo tanto deberían ser suficientes para todos los propósitos.

La desventaja de GRND_RANDOM y las lecturas de /dev/random es que la operación puede bloquearse durante un período de tiempo indefinido. Además, lidiar con las solicitudes parcialmente cumplidas que pueden ocurrir al usar GRND_RANDOM o al leer de /dev/random aumenta la complejidad del código.

Simulaciones de Monte Carlo y otras aplicaciones de muestreo probabilístico

Usar estas interfaces para proporcionar grandes cantidades de datos para simulaciones de Monte Carlo u otros programas/algoritmos que realizan muestreo probabilístico será lento. Además, es innecesario, ya que tales aplicaciones no necesitan números aleatorios criptográficamente seguros. En su lugar, utilice las interfaces descritas en esta página para obtener una pequeña cantidad de datos para sembrar un generador de números pseudoaleatorios en espacio de usuario para su uso por dichas aplicaciones.

Comparación entre getrandom, /dev/urandom, y /dev/random

La siguiente tabla resume el comportamiento de las diversas interfaces que se pueden utilizar para obtener aleatoriedad. GRND_NONBLOCK es una bandera que se puede usar para controlar el comportamiento de bloqueo de getrandom(2). La columna final de la tabla considera el caso que puede ocurrir al principio del arranque cuando el pool de entropía aún no está inicializado.

Interfaz Pool Comportamiento de bloqueo Comportamiento cuando el pool aún no está listo
/dev/random Pool de bloqueo Si la entropía es demasiado baja, se bloquea hasta que haya suficiente entropía nuevamente Se bloquea hasta que se recopila suficiente entropía
/dev/urandom Salida CSPRNG Nunca se bloquea Devuelve salida de CSPRNG no inicializado (puede tener baja entropía y no ser adecuado para criptografía)
getrandom () Igual que /dev/urandom No se bloquea una vez que el pool está listo Se bloquea hasta que el pool esté listo
getrandom () GRND_RANDOM Igual que /dev/random Si la entropía es demasiado baja, se bloquea hasta que haya suficiente entropía nuevamente Se bloquea hasta que el pool esté listo
getrandom () GRND_NONBLOCK Igual que /dev/urandom No se bloquea una vez que el pool está listo EAGAIN
getrandom () GRND_RANDOM + GRND_NONBLOCK Igual que /dev/random EAGAIN si no hay suficiente entropía disponible EAGAIN

Generación de claves criptográficas

La cantidad de material de semilla requerido para generar una clave criptográfica es igual al tamaño efectivo de la clave. Por ejemplo, una clave privada RSA o Diffie-Hellman de 3072 bits tiene un tamaño efectivo de 128 bits (requiere alrededor de 2^128 operaciones para romperse), por lo que un generador de claves solo necesita 128 bits (16 bytes) de material de semilla de /dev/random.

Si bien un margen de seguridad por encima de ese mínimo es razonable, como protección contra fallos en el algoritmo CSPRNG, ningún primitivo criptográfico disponible hoy en día puede prometer más de 256 bits de seguridad, por lo que si algún programa lee más de 256 bits (32 bytes) del pool aleatorio del kernel por invocación, o por intervalo de resemebrazo razonable (no menos de un minuto), eso debería tomarse como una señal de que su criptografía *no* está implementada hábilmente.

    RANDOM(7) Secciones varias de Linux RANDOM(7)

    NOMBRE

    random, urandom - pseudorrandomidad y números aleatorios criptográficamente seguros

    DESCRIPCIÓN

    Los archivos del dispositivo/dev/random y/dev/urandom (nodos de dispositivo caracteriales, mayor 1, menor 8 para ambos en la mayoría de los sistemas) proporcionan una interfaz para la generación de números aleatorios del sistema operativo.

    /dev/random y/dev/urandom se utilizan para generar números pseudoaleatorios. La diferencia entre ellos es la forma en que manejan la entropía.

    /dev/random se considera un generador de números pseudoaleatorios (PRNG) con una entropía de alta calidad. Solo devuelve números aleatorios cuando tiene suficiente entropía recopilada. Esto significa que si el sistema no ha recopilado suficientes datos aleatorios (por ejemplo, debido a una falta de actividad del usuario o de eventos del sistema), la lectura de/dev/random puede bloquearse hasta que se recolecte suficiente entropía.

    /dev/urandom es un PRNG que no bloquea. Utiliza el mismo algoritmo que/dev/random pero tiene una cola de entropía más pequeña y no espera a que se recopile nueva entropía. Esto significa que/dev/urandom casi siempre devolverá datos inmediatamente, pero los datos generados podrían ser menos aleatorios si el sistema no tiene suficiente entropía.

    Entropía

    El sistema recopila entropía de varias fuentes, como la actividad del teclado, los movimientos del ratón, las interrupciones del disco y la actividad de la red. Esta entropía se utiliza para "sembrar" el PRNG.

    Si necesita números aleatorios criptográficamente seguros, se recomienda utilizar/dev/urandom en lugar de/dev/random, ya que/dev/urandom está diseñado para proporcionar números pseudoaleatorios de alta calidad para la mayoría de los fines criptográficos./dev/random solo debe usarse en situaciones en las que se requiera una garantía absoluta de que los números aleatorios no se generarán hasta que haya suficiente entropía disponible, como en la generación de claves de cifrado muy sensibles donde el tiempo de bloqueo no es un problema.

    Uso

    Puede leer de/dev/random o/dev/urandom como si fueran archivos normales. Por ejemplo, para leer 16 bytes de datos aleatorios de/dev/urandom, puede usar el siguiente comando:

    head -c 16 /dev/urandom

    Las aplicaciones que requieren números aleatorios de alta calidad pueden usar bibliotecas comoopenssl olibsodium para acceder a estas fuentes de entropía de una manera más segura y conveniente.
