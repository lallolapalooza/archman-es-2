ros-dump - crea una imagen volcada de un script de roswell

Sinopsis

ros [OPCIONES1...] dump [OPCIONES2...] MODO argumentos...

Las OPCIONES1 especifican las opciones estándar de roswell como -L o -m LISP. Las OPCIONES2 especifican las opciones de reducción de imagen que describimos más adelante. MODO es output o executable.

Descripción

ros-dump crea una imagen lisp volcada del estado después de procesar todas las opciones OPCIONES1.

Tiene dos modos: output y executable. En ambos modos, el entorno global (por ejemplo, la vinculación global a variables especiales como *package*) del estado justo después del reinicio es el entorno que estaba efectivo cuando se volcó el script.

La imagen volcada generalmente no es compatible entre las diferentes implementaciones, y tampoco entre las versiones.

Modos de volcado

output [-f] [-o SALIDA] NOMBRE

Carga el script de roswell NOMBRE y guarda el estado actual de lisp en una imagen.

El archivo de imagen se escribe por defecto en un directorio interno de roswell de manera organizada, es decir, en algún lugar debajo de $ROSWELL_INSTALL_DIR deducido por la implementación actual, su versión y el NOMBRE dado.

Cuando el archivo de salida ya existe, el comando falla con un código de error.

La imagen puede ser cargada por ros -m IMAGEN. Al reiniciar desde la imagen, los subcomandos estándar de roswell y los argumentos adicionales al script también están disponibles, por ejemplo, ros run para reanudar con un repl, o --restart FUNC para llamar a una función específica, dejando cierta flexibilidad.

-o SALIDA
La imagen se escribe en SALIDA en lugar de la ubicación predeterminada.
-f
Forzar salida cuando la salida ya existe.

executable NOMBRE [-o SALIDA]

Cuando un script se vuelca con executable, la imagen volcada se convierte en un binario ejecutable autocontenido que implica --restart main.

Si se proporciona SALIDA, el binario resultante se escribe en este archivo. De lo contrario, el nombre del archivo de salida se deduce de NOMBRE y se escribe en el mismo directorio. En Windows y si SCRIPT tiene la extensión .ros, el nombre del archivo será SCRIPT.exe. En los otros sistemas, el resultado será SCRIPT (sin extensión).

Esta característica es compatible con SBCL, CCL, CMUCL, CLISP, ECL.

Opciones de reducción de imagen

Estas opciones desvinculan algunas referencias a los objetos en tiempo de ejecución y permiten a los recolectores de basura reclamar algo de memoria, lo que eventualmente reduce el tamaño de la imagen volcada.

Se debe tener cuidado para asegurar que el programa resultante funcione como se espera, ya que algunas de estas operaciones pueden destruir las suposiciones comunes de los programas conformes. Por ejemplo, las opciones de reducción relacionadas con paquetes pueden inhibir las llamadas en tiempo de ejecución a READ después del reinicio.

Las opciones de reducción se procesan de izquierda a derecha.

–disable-compression, –enable-compression, -c
Estas opciones deshabilitan/habilitan la característica de compresión de núcleo en SBCL. Por lo tanto, esta opción solo tiene sentido en SBCL. La compresión está habilitada por defecto.
–remove-docstrings
Esta opción elimina todas las cadenas de documentación de todos los símbolos en toda la imagen lisp.
–delete-package PKG
Esta opción se puede especificar varias veces. Desinterna los símbolos en el PAQUETE, llama a makeunbound y fmakeunbound en cada símbolo y elimina el paquete. Los nombres de los paquetes se convierten automáticamente a mayúsculas.
–delete-all-packages
Esta opción aplica –delete-package PKG en todos los paquetes, excepto algunos paquetes en lista negra (keyword, roswell, ROS.SCRIPT.DUMP, y el paquete del símbolo de la función principal).
–delete-packages-except PACKAGE
Esta opción se puede especificar varias veces. Es idéntica a –delete-all-packages excepto que agrega PACKAGE a la lista negra. Los nombres de los paquetes se convierten automáticamente a mayúsculas.
–destroy-packages-sbcl
Esta es una opción específica de sbcl que es aún más agresiva que los métodos anteriores (reducción de >10MB). Destruye el sistema de paquetes modificando las tablas internas para los paquetes, limpiando las cachés para la lista de uso de paquetes, etc. La lista negra se comparte entre –delete-all-packages y –destroy-packages-sbcl. Sin embargo, este método no llama a fmakunbound/makunbound, por lo que combinar ambos métodos puede resultar en una reducción más agresiva del tamaño de la imagen. Debido a la naturaleza de esta opción, es deseable especificarla como el último método (es decir, el más a la derecha).
–purify, –no-purify
Esto es común a CCL, SBCL, CMUCL. Mueve todos los objetos al espacio estático donde el GC no escanea, para el rendimiento posterior del GC. La purificación está habilitada por defecto.
–impurify, –no-impurify
Esta es una opción específica de CCL (habilitada por defecto). Mueve todos los objetos al espacio dinámico antes de guardar la imagen. Esto permite que los objetos del espacio estático sean recolectados por el GC. Cuando la purificación está habilitada, impurifica todos los objetos antes de ejecutar el GC purificador.
–delete-debug-info
Esto elimina la información de depuración de las funciones (usada para mostrar el marco de pila, etc.), así como las ubicaciones de origen y la información de deprecación de varios símbolos. Solo SBCL. Esta opción tiene un gran efecto (reducción de +10MB).
–delete-macro-definitions, –delete-compiler-macro-definitions
Esto elimina todas las definiciones de macros y macros compiladoras, asumiendo que no se realizará ninguna compilación/interpretación de código en tiempo de ejecución. Esta opción debería ser portable entre implementaciones. Tiene una reducción de ~2MB en SBCL.
–delete-compiler-information-sbcl
Esta es una opción específica de SBCL que es más agresiva que los métodos anteriores (reducción de ~4MB). Además de las definiciones de macros y macros compiladoras, destruye los sistemas internos del compilador de SBCL al eliminar también la información de inlining, el transformador IR1 y el IR2 (VOP).
