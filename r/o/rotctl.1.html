ROTCTL(1) Utilidades Hamlib ROTCTL(1)

NOMBRE

rotctl - controla los rotadores de antena

SINOPSIS

rotctl [-hiIlLuV] [-m id] [-r dispositivo] [-R dispositivo2] [-s baud] [-t caracter] [-C parm=val] [-o azoffset] [-O eloffset] [-v[-Z]] [comando|-]

DESCRIPCIÓN

Controla los rotadores de antena.

rotctl acepta comandos de la línea de comandos, así como en modo interactivo si no se proporcionan en la línea de comandos.

Tenga en cuenta que Hamlib es software de nivel BETA. Aunque a muchas bibliotecas de backend les falta soporte completo para rotadores, las funciones básicas suelen estar bien soportadas.

Por favor, informe de errores y proporcione comentarios en la dirección de correo electrónico indicada en la sección ERRORES a continuación. Los parches y las mejoras de código enviados a la misma dirección son bienvenidos.

OPCIONES

Este programa sigue la sintaxis habitual de línea de comandos de GNU. Las opciones cortas que toman un argumento pueden tener el valor inmediatamente después o separado por un espacio. Las opciones largas que comienzan con dos guiones (‘-’) requieren un ‘=’ entre la opción y cualquier argumento.

Aquí hay un resumen de las opciones soportadas:

-m, --modelo=id
Selecciona el número de modelo del rotador.
Ver lista de modelos (use “rotctl -l”).
Nota: rotctl (o software de terceros que utilice la API C) utilizará el modelo de rotador 2 para NET rotctl (comunicándose con rotctld).
-r, --archivo-rotador=dispositivo
Usa dispositivo como nombre de archivo del puerto conectado al rotador.
A menudo un puerto serie, pero puede ser un adaptador USB a serie. Típicamente /dev/ttyS0, /dev/ttyS1, /dev/ttyUSB0, etc. en Linux, COM1, COM2, etc. en MS Windows. Las variantes BSD y Mac OS/X tienen sus propias designaciones. Consulte la documentación de su sistema.
-R, --archivo-rotador2=dispositivo
Usa dispositivo como nombre de archivo del puerto conectado al segundo rotador. por ejemplo, segundo rotador utilizado para la elevación.
A menudo un puerto serie, pero puede ser un adaptador USB a serie. Típicamente /dev/ttyS0, /dev/ttyS1, /dev/ttyUSB0, etc. en Linux, COM1, COM2, etc. en MS Windows. Las variantes BSD y Mac OS/X tienen sus propias designaciones. Consulte la documentación de su sistema.
-s, --velocidad-serie=baud
Establece la velocidad serie a baud.
Utiliza la velocidad serie máxima de las capacidades del backend del rotador como predeterminada.
-t, --terminador-comando-envio=caracter
Cambia el caracter de terminación para el protocolo de texto al usar el comando enviar_comando.
El valor predeterminado es CR ASCII (‘0x0D’). Los caracteres no imprimibles ASCII se pueden dar como el número ASCII en formato hexadecimal precedido por “0x”. Puede pasar una cadena vacía para no tener carácter de terminación. La cadena “-1” le dice a rotctl que cambie al protocolo binario. Consulte el comando enviar_comando para obtener más explicaciones.
Nota: El punto y coma (‘;’) es un terminador común para los rotadores que aceptan cadenas de caracteres ASCII.
-o, --establecer-azoffset
Corrección de acimut flotante -- durante el establecimiento el valor se suma, durante la obtención el valor se resta.
-O, --establecer-eloffset
Corrección de elevación flotante -- durante el establecimiento el valor se suma, durante la obtención el valor se resta.
-L, --mostrar-config
Lista todos los parámetros de configuración para el rotador definido con -m arriba.
-C, --establecer-config=parm=val[,parm=val]
Establece el(los) parámetro(s) de configuración del rotador, por ejemplo, stop_bits=2.
Use la opción -L arriba para obtener una lista de parámetros de configuración para un número de modelo dado.
-u, --volcar-capacidades
Volca las capacidades para el rotador definido con -m arriba y sale.
-l, --listar
Lista todos los números de modelo de rotador definidos en Hamlib y sale.
La lista está ordenada por número de modelo.
Nota: En Linux, la lista se puede desplazar hacia atrás usando Shift-PageUp/Shift-PageDown, o usando las barras de desplazamiento de un terminal virtual en X o la ventana de comandos en Windows. La salida se puede canalizar a more(1) o less(1), por ejemplo “rotctl -l | more”.
-i, --leer-historial
Lee el historial de comandos y argumentos guardado previamente de un archivo (predeterminado $HOME/.rotctl_history) para la sesión actual.
Disponible cuando rotctl está compilado con soporte Readline (ver READLINE abajo).
Nota: Para leer un archivo de historial almacenado en otro directorio, establezca la variable de entorno ROTCTL_HIST_DIR, por ejemplo “ROTCTL_HIST_DIR=$HOME/tmp rotctl -i”. Cuando ROTCTL_HIST_DIR no está establecido, se utiliza el valor de HOME.
-I, --guardar-historial
Escribe el historial de comandos y argumentos de la sesión actual (y cualquier sesión anterior, si también se proporciona la opción -i) a un archivo (predeterminado $HOME/.rotctl_history) al final de la sesión actual.
Los comandos completos con argumentos se guardan como una sola línea para ser recuperados y utilizados o editados. Disponible cuando rotctl está compilado con soporte Readline (ver READLINE abajo).
Nota: Para escribir un archivo de historial en otro directorio, establezca la variable de entorno ROTCTL_HIST_DIR, por ejemplo “ROTCTL_HIST_DIR=$HOME/tmp rotctl -I”. Cuando ROTCTL_HIST_DIR no está establecido, se utiliza el valor de HOME.
-v, --verboso
Establece el modo verboso, acumulativo (ver DIAGNÓSTICOS abajo).
-Z, --marcas-tiempo-depuracion
Habilita marcas de tiempo para los mensajes de depuración.
Úselo solo en combinación con la opción -v, ya que no genera salida por sí mismo.
-h, --ayuda
Muestra un resumen de estas opciones y sale.
-V, --versión
Muestra la versión de rotctl y sale.
-
Detiene el procesamiento de opciones y lee comandos de la entrada estándar.
Ver Entrada Estándar abajo.

Nota: Es posible que algunas opciones no estén implementadas por un backend determinado y devolverán un error. Esto es más probable que ocurra con las opciones --establecer-config y --mostrar-config.

Tenga en cuenta que el backend para el rotador a controlar, o el propio rotador, pueden no soportar algunos comandos. En ese caso, la operación fallará con un código de error de Hamlib.

P 123 45

Dado que la mayoría de las operaciones de Hamlib tienen un método set (establecer) y un método get (obtener), a menudo se usará una letra mayúscula para un método set, mientras que la letra minúscula correspondiente se referirá al método get. Entrada Estándar

Como alternativa a la entrada de comandos interactiva READLINE o a un solo comando por ejecución, rotctl presenta una opción especial donde se puede usar un solo guion (‘-’) para leer comandos de la entrada estándar (stdin). Los comandos deben separarse por espacios en blanco, de manera similar a los comandos dados en la línea de comandos. Se pueden agregar comentarios usando el carácter ‘#’, todo el texto hasta el final de la línea actual, incluido el carácter ‘#’, se ignora.

Un ejemplo simple:


$ cat <<.EOF. >cmds.txt
> # Archivo de comandos
> set_pos 180.0 10.0	# rotar
> pause 30  # esperar a que la acción se complete
> get_pos   # consultar el rotador
>.EOF.
$ rotctl -m 1 - <cmds.txt
set_pos 180.0 10.0
pause 30
get_pos 180.000000
10.000000
$

Comandos del Rotador

A continuación se incluye un resumen de los comandos (En el caso de los comandos set, la cadena cursiva entre comillas se reemplaza por el valor en la descripción. En el caso de los comandos get, la cadena cursiva entre comillas es el nombre de la clave del valor devuelto):

Q|q, salir de rotctl
Salir de rotctl en modo interactivo.
Cuando rotctl controla el rotador directamente, cerrará el backend y el puerto del rotador. Cuando rotctl está conectado a rotctld (modelo de rotador 2), se cerrará la conexión TCP/IP a rotctld y rotctld permanecerá en ejecución, disponible para otra conexión de red TCP/IP.
P, set_pos 'Azimut' 'Elevación'
Establecer posición.
'Azimut' y 'Elevación' son valores de punto flotante.
El azimut puede variar de -180 a 540, dependiendo del rotador, para permitir rotadores orientados al sur y las capacidades del rotador.
La elevación puede variar de -20 a 210, dependiendo del rotador.
Por ejemplo:

P 163.0 41.0

Nota: Si el rotador no admite el ajuste de elevación (la mayoría no lo hace), proporcione “0.0” para 'Elevación'.
p, get_pos
Obtener posición.
'Azimut' y 'Elevación' se devuelven como valores de punto flotante de doble precisión.
M, move 'Dirección' 'Velocidad'
Mover el rotador en una dirección específica a la velocidad dada.
'Dirección' es un entero o palabra clave definida como ‘2’ = ARRIBA, ‘4’ = ABAJO, ‘8’ = IZQUIERDA o CCW (sentido antihorario), ‘16’ = DERECHA o CW (sentido horario), ‘32’ = ARRIBA_IZQUIERDA o ARRIBA_CCW, ‘R64’ = ARRIBA_DERECHA o ARRIBA_CW, ‘128’ = ABAJO_IZQUIERDA o ABAJO_CCW, ‘256’ = ABAJO_DERECHA o ABAJO_CW
'Velocidad' es un entero entre 1 y 100. Use -1 para no cambiar la velocidad actual.
Nota: No todos los backends que implementan el comando move utilizan el valor de Velocidad.
S, stop
Detener el rotador.
K, park
Estacionar el rotador.
C, set_conf 'Token' 'Valor'
Establecer un parámetro de configuración.
'Token' es una cadena; consulte la opción -C y la salida de -L.
'Valor' es una cadena de hasta 20 caracteres.
R, reset 'Reset'
Reiniciar el rotador.
'Reset' acepta un valor entero de ‘1’ para “Reset All” (Reiniciar todo).
_, get_info
Obtener información miscelánea sobre el rotador.
Devuelve 'Info' "Nombre del Modelo" en este momento.
dump_state
Devolver cierta información de estado sobre el backend del rotador.
1, dump_caps
No es un comando remoto real de rot, solo muestra las capacidades, es decir, lo que el backend sabe sobre este modelo y lo que puede hacer.
w, send_cmd 'Cmd'
Enviar una cadena de comando cruda al rotador.
Se agrega automáticamente un CR (retorno de carro) ASCII (o el valor de --send-cmd-term, ver opción -t) al final del comando para protocolos de texto. Para protocolos binarios, ingrese valores hexadecimales como “\0xAA\0xBB”.

Comandos de Localizador

Estos comandos ofrecen conversiones de Grados Minutos Segundos a otros formatos, conversiones de localizador Maidenhead y conversiones de distancia y azimut.

L, lonlat2loc 'Longitud' 'Latitud' 'Len Loc'
Devuelve el 'Localizador' Maidenhead para la 'Longitud' y 'Latitud' dadas.
Se proporcionan valores de punto flotante. La precisión del cuadrado devuelto se controla mediante 'Len Loc', que debe ser un número entero par entre 2 y 12.
Por ejemplo:

L -170.0 -85.0 12

devuelve:

Localizador: AA55AA00AA00

l, loc2lonlat 'Localizador'
Devuelve 'Longitud' y 'Latitud' en grados decimales en el centro aproximado del cuadrado de cuadrícula Maidenhead solicitado.
'Localizador' puede tener una longitud de 2 a 12 caracteres.
La longitud oeste se expresa como un valor negativo.
La latitud sur se expresa como un valor negativo.
Por ejemplo:

l AA55AA00AA00

devuelve:

Longitud: -169.999983 Latitud: -84.999991

Nota: A pesar del uso de variables de doble precisión internamente, se produce algún error de redondeo.
D, dms2dec 'Grados' 'Minutos' 'Segundos' 'S/O'
Devuelve 'Grados Dec', un valor de punto flotante con signo.
'Grados' y 'Minutos' son valores enteros.
'Segundos' es un valor de punto flotante.
'S/O' es una bandera, donde ‘1’ indica latitud Sur o longitud Oeste, y ‘0’ indica Norte o Este (la bandera es necesaria ya que las computadoras no reconocen un cero con signo, aunque solo el valor de 'Grados' suele tener signo en la notación DMS).
d, dec2dms 'Grados Dec'
Devuelve 'Grados' 'Minutos' 'Segundos' 'S/O'.
Los valores son como en dms2dec arriba.
E, dmmm2dec 'Grados' 'Minutos Dec' 'S/O'
Devuelve 'Grados Dec', un valor de punto flotante con signo.
'Grados' es un valor entero.
'Minutos Dec' es un valor de punto flotante.
'S/O' es una bandera como en dms2dec arriba.
e, dec2dmmm 'Grados Dec'
Devuelve 'Grados' 'Minutos' 'S/O'.
Los valores son como en dmmm2dec arriba.
B, qrb 'Lon 1' 'Lat 1' 'Lon 2' 'Lat 2'
Devuelve 'Distancia' y 'Azimut'.
'Distancia' está en km.
'Azimut' está en grados.
Los valores de Lon/Lat proporcionados son números de punto flotante con signo.
A, a_sp2a_lp 'Deg Trayecto Corto'
Devuelve 'Deg Trayecto Largo'.
Tanto el argumento proporcionado como el valor devuelto son valores de punto flotante dentro del rango de 0.00 a 360.00.
Nota: Proporcionar un valor negativo devolverá un mensaje de error.
a, d_sp2d_lp 'km Trayecto Corto'
Devuelve 'km Trayecto Largo'.
Ambos, el argumento proporcionado y el valor devuelto, son valores de punto flotante.
pause 'Segundos'
Pausa durante el número entero de 'Segundos' especificado antes de enviar el siguiente comando al rotador.

READLINE

Si los archivos de desarrollo de la biblioteca Readline se encuentran en el momento de la configuración, rotctl se compilará condicionalmente con soporte Readline para la entrada de comandos y argumentos. Los enlaces de teclas de comandos de Readline se encuentran en sus valores predeterminados, como se describe en el manual de Readline. rotctl establece el nombre “rotctl” que puede usarse en Constructos de Inicialización Condicional en el Archivo de Inicialización de Readline ($HOME/.inputrc por defecto) para enlaces de teclas personalizados exclusivos de rotctl.

El historial de comandos está disponible con soporte Readline, como se describe en el manual de historial de Readline. Los comandos y las cadenas de argumentos se almacenan como líneas únicas, incluso cuando se solicitan argumentos individualmente. Los comandos y argumentos no se validan y se almacenan tal como se escribieron, con los valores separados por un solo espacio.

Normalmente, el historial de la sesión no se guarda; sin embargo, el uso de cualquiera de las opciones -i/--read-history o -I/--save-history al iniciar rotctl provocará que se lea cualquier historial guardado previamente y/o que se escriba el historial de la sesión actual y cualquier sesión anterior (suponiendo que las opciones -i y -I se proporcionen juntas) al cerrar rotctl. Cada opción es mutuamente excluyente, es decir, cualquiera puede darse por separado o en combinación. Esto es útil para guardar un conjunto de comandos y luego leerlos más tarde, pero sin escribir el historial modificado para un conjunto coherente de comandos de prueba en modo interactivo, por ejemplo.

El historial se almacena en $HOME/.rotctl_history por defecto, aunque el directorio de destino puede cambiarse estableciendo la variable de entorno ROTCTL_HIST_DIR. Cuando ROTCTL_HIST_DIR no está establecida, se utiliza el valor de la variable de entorno HOME en su lugar. Solo el directorio de destino puede cambiarse en este momento.

Si el soporte de Readline no se encuentra en el momento de la configuración, se utiliza el controlador de comandos interno original. Readline no se utiliza para los comandos de rotctl introducidos en la línea de comandos, independientemente de si el soporte de Readline está integrado o no.

Nota: El soporte de Readline no se incluye en las compilaciones binarias de MS Windows de 32 o 64 bits proporcionadas por el Proyecto Hamlib. Ejecutar rotctl en la plataforma MS Windows en la shell de 'cmd' sí proporciona historial de comandos de línea de sesión, sin embargo, no se guarda en disco entre sesiones.

DIAGNÓSTICOS

La opción -v, --verbose permite diferentes niveles de diagnósticos que se enviarán a stderr y corresponden a -v para BUG, -vv para ERR, -vvv para WARN, -vvvv para VERBOSE, o -vvvvv para TRACE.

Un nivel de verbosidad dado es útil para proporcionar la información de depuración necesaria a la dirección de correo electrónico a continuación. Por ejemplo, la salida TRACE muestra todos los valores enviados y recibidos de la radio, lo cual es muy útil para el desarrollo de bibliotecas backend de radio y puede ser solicitado por los desarrolladores.

ESTADO DE SALIDA

rotctl sale con:

0
si todas las operaciones se completaron normalmente;
1
si hubo una opción o argumento de línea de comandos inválido;
2
si Hamlib devolvió un error.

EJEMPLOS

Iniciar rotctl para RotorEZ usando el primer puerto serie en Linux:


$ rotctl -m 401 -r /dev/ttyS0

Iniciar rotctl para RotorEZ usando COM2 en MS Windows:


> rotctl -m 401 -r COM2

Conectarse a un rotctld en ejecución con el modelo de rotador 2 (“NET rotctl”) en el host local y especificando el puerto TCP, y consultando la posición:


$ rotctl -m 2 -r localhost:4533 t_pos
