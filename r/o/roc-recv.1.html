NOMBRE

roc-recv - recibir audio en tiempo real

SINOPSIS

roc-recv OPCIONES

DESCRIPCIÓN

Recibe flujos de audio de remitentes remotos y los escribe en un dispositivo de audio o archivo.

URI de Punto Final

Las opciones --source, --repair y --control definen los puntos finales de red en los que recibir el tráfico.

URI_PUNTO_FINAL debe tener el siguiente formato:

protocolo://host[:puerto][/ruta][?consulta]

Ejemplos:

  • rtsp://localhost:123/ruta?consulta
  • rtp+rs8m://localhost:123
  • rtp://0.0.0.0:123
  • rtp://[::1]:123
  • rtcp://0.0.0.0:123

La lista de protocolos soportados se puede obtener usando la opción --list-supported.

El campo host debe ser un FQDN (nombre de dominio), una dirección IPv4 o una dirección IPv6 entre corchetes. Puede ser 0.0.0.0 (para IPv4) o [::] (para IPv6) para enlazar el punto final a todas las interfaces de red.

El campo puerto puede omitirse si el protocolo define un puerto estándar. De lo contrario, es obligatorio. Puede establecerse a cero para enlazar el punto final a un puerto efímero elegido aleatoriamente.

Los campos ruta y consulta solo están permitidos para protocolos que los soporten, p.ej. para RTSP.

Si el FEC está habilitado en el remitente, se debe proporcionar un par de puntos finales de origen y reparación. Los dos puntos finales deben usar protocolos compatibles, p.ej. rtp+rs8m:// para el punto final de origen, y rs8m:// para el punto final de reparación. Si el FEC está deshabilitado, se debe proporcionar un único punto final de origen.

Protocolos de origen y reparación soportados:

  • origen rtp://, reparación none (RTP simple sin FEC)
  • origen rtp+rs8m://, reparación rs8m:// (RTP con FEC Reed-Solomon)
  • origen rtp+ldpc://, reparación ldpc:// (RTP con FEC LDPC-Staircase)

Además, se recomienda proporcionar un punto final de control. Se utiliza para intercambiar información no multimedia utilizada para identificar sesiones, transportar comentarios, etc. Si no se proporciona ningún punto final de control, la sesión opera en un modo de recuperación reducido, que puede ser menos robusto y no soportar todas las características.

Protocolos de control soportados:

•
rtcp://

URI de E/S

Las opciones --output y --backup requieren un URI de dispositivo o archivo en una de las siguientes formas:

  • TIPO_DISPOSITIVO://NOMBRE_DISPOSITIVO -- dispositivo de audio
  • TIPO_DISPOSITIVO://default -- dispositivo de audio predeterminado para el tipo de dispositivo dado
  • file:///RUTA/ABSOLUTA -- ruta de archivo absoluta
  • file://localhost/RUTA/ABSOLUTA -- ruta de archivo absoluta (forma alternativa; solo se soporta el host "localhost")
  • file:/RUTA/ABSOLUTA -- ruta de archivo absoluta (forma alternativa)
  • file:RUTA/RELATIVA -- ruta de archivo relativa
  • file://- -- stdout
  • file:- -- stdout (forma alternativa)

Ejemplos:

  • pulse://default
  • pulse://alsa_output.pci-0000_00_1f.3.analog-stereo
  • alsa://hw:1,0
  • file:///home/usuario/test.wav
  • file://localhost/home/usuario/test.wav
  • file:/home/usuario/test.wav
  • file:./test.wav
  • file:-

La lista de esquemas y formatos de archivo soportados se puede obtener usando la opción --list-supported.

Si se omite --output, se selecciona el controlador y el dispositivo predeterminados

OPTIONS

The following options are available:

--backup AUDIO
Use AUDIO as a backup audio source. If the option is omitted, no backup source is used.
--backup-format FORMAT
Force backup audio file format to FORMAT. If the option is omitted, the file format is auto-detected. The option is always required when the backup is stdin.
--choppy-play-timeout TIME
Set choppy playback timeout to TIME. If audio playback is choppy for this duration, it's considered stalled. Default is 1s.
--color
Force terminal coloring. Use it when output is redirected to a file or another command.
-c, --control URI
Set control endpoint to URI. If not set, the control endpoint is auto-detected based on the source endpoint.
--config FILE
Load configuration from FILE. The file must be a JSON.
--cpu-profile FILE
Dump CPU profile to FILE in JSON format when process exits.
--error-timeout TIME
Set error timeout to TIME. If audio playback errors for this duration, it's considered stalled. Default is 1s.
--fec SCHEME
Set FEC scheme to SCHEME. Supported schemes are: rs8m, ldpc.
--frame-len TIME
Set frame length to TIME. Default is 20ms.
-h, --help
Print help message and exit.
--io-latency TIME
Set I/O latency to TIME. Default is 20ms.
-l, --list DEVICE
List available devices of specified type and exit. Supported types are: alsa, pulse.
--latency-backend BACKEND
Set latency tuning backend to BACKEND. Supported backends are: niq.
--latency-profile PROFILE
Set latency tuning profile to PROFILE. Supported profiles are: gradual.
-m, --max-latency TIME
Set maximum latency to TIME. Default is 5s.
-M, --miface MIFACE
Set multicast interface to MIFACE. It should be an IP address of the network interface on which to join the multicast group.
-n, --min-latency TIME
Set minimum latency to TIME. Default is 20ms.
--no-color
Disable terminal coloring.
--no-play-timeout TIME
Set no playback timeout to TIME. If audio playback is stalled for this duration, it's considered stalled. Default is 1s.
-o, --output URI
Set output device to URI. If not specified, output is sent to the default audio device.
--output-format FORMAT
Force output file format to FORMAT. If the option is omitted, the file format is auto-detected. The option is always required when the output is stdout.
-p, --port PORT
Set port to PORT. This option is deprecated and ignored.
--rate RATE
Force a specific sample rate to RATE. If not specified, sample rate is auto-detected.
-r, --repair URI
Set repair endpoint to URI. If not set, the repair endpoint is auto-detected based on the source endpoint.
--resampler-backend BACKEND
Set resampler backend to BACKEND. Supported backends are: speex, ffmpeg.
--resampler-profile PROFILE
Set resampler profile to PROFILE. Supported profiles are: very-low, low, normal, high, very-high.
--reuseaddr
Enable SO_REUSEADDR socket option.
-s, --source URI
Set source endpoint to URI. This option is required.
-t, --target-latency TIME
Set target latency to TIME. Default is 100ms.
--threads NUMBER
Set number of threads to NUMBER. Default is auto-detected.
-V, --version
Print version and exit.
-v, --verbose
Enable verbose mode. Use multiple times for more output.

The --output-format and --backup-format options can be used to force the output or backup file format. If the option is omitted, the file format is auto-detected. The option is always required when the output or backup is stdout or stdin.

The path component of the provided URI is percent-decoded. For convenience, unencoded characters are allowed as well, except that % should be always encoded as %25.

For example, the file named /foo/bar%/[baz] may be specified using either of the following URIs: file:///foo%2Fbar%25%2F%5Bbaz%5D and file:///foo/bar%25/[baz].

Multicast interface

If --miface option is present, it defines an IP address of the network interface on which to join the multicast group. If not present, no multicast group should be joined.

It's not possible to receive multicast traffic without joining a multicast group. The user should either provide multicast interface, or join the group manually using foreign tools.

MIFACE should be an IP address of the network interface on which to join the multicast group. It may be 0.0.0.0 (for IPv4) or :: (for IPv6) to join the multicast group on all available interfaces.

Multiple slots

Multiple sets of endpoints can be specified to retrieve media from multiple addresses.

Such endpoint sets are called slots. All slots should have the same set of endpoint types (source, repair, etc) and should use the same protocols for them. All slots should also have their own multicast interface option, if it's used.

SO_REUSEADDR

If --reuseaddr option is provided, SO_REUSEADDR socket option will be enabled for all sockets (by default it's enabled only for multicast sockets).

For TCP, it allows immediately reusing recently closed socket in TIME_WAIT state, which may be useful you want to be able to restart server quickly.

For UDP, it allows multiple processes to bind to the same address, which may be useful if you're using systemd socket activation.

Regardless of the option, SO_REUSEADDR is always disabled when binding to ephemeral port.

Backup audio

If --backup option is given, it defines input audio device or file which will be played when there are no connected sessions. If it's not given, silence is played instead.

Backup file is restarted from the beginning each time when the last session disconnect. The playback of of the backup file is automatically looped.

Time units

TIME should have one of the following forms:
123ns; 1.23us; 1.23ms; 1.23s; 1.23m; 1.23h;

Size units

SIZE should have one of the following forms:
123; 1.23K; 1.23M; 1.23G;

EXAMPLES

Endpoint examples

Bind one bare RTP endpoint on all IPv4 interfaces:

$ roc-recv -vv -s rtp://0.0.0.0:10001

Bind source, repair, and control endpoints to all IPv4 interfaces (but not IPv6):

$ roc-recv -vv -s rtp+rs8m://0.0.0.0:10001 -r rs8m://0.0.0.0:10002 \
    -c rtcp://0.0.0.0:10003

Bind source, repair, and control endpoints to all IPv6 interfaces (but not IPv4):

$ roc-recv -vv -s rtp+rs8m://[::]:10001 -r rs8m://[::]:10002 -c rtcp://[::]:10003

Bind source, repair, and control endpoints to a particular network interface:

$ roc-recv -vv -s rtp+rs8m://192.168.0.3:10001 -r rs8m://192.168.0.3:10002 \
    -c rtcp://192.168.0.3:10003

Bind endpoints to a particular multicast address and join to a multicast group on a particular network interface:

$ roc-recv -vv -s rtp+rs8m://225.1.2.3:10001 -r rs8m://225.1.2.3:10002 \
    -c rtcp://225.1.2.3:10003 \
    --miface 192.168.0.3

Bind two sets of source, repair, and control endpoints (six endpoints in total):

$ roc-recv -vv \
    -s rtp+rs8m://192.168.0.3:10001 -r rs8m://192.168.0.3:10002 \
        -c rtcp://192.168.0.3:10003 \
    -s rtp+rs8m://198.214.0.7:10001 -r rs8m://198.214.0.7:10002 \
        -c rtcp://198.214.0.7:10003

I/O examples

Output to the default device (omit -o):

$ roc-recv -vv -s rtp://0.0.0.0:10001

Output to the default ALSA device:

$ roc-recv -vv -s rtp://0.0.0.0:10001 -o alsa://default

Output to a specific PulseAudio device:

$ roc-recv -vv -s rtp://0.0.0.0:10001 -o pulse://alsa_input.pci-0000_00_1f.3.analog-stereo

Output to a file in WAV format (guess format by extension):

$ roc-recv -vv -s rtp://0.0.0.0:10001 -o file:./output.wav

Output to a file in WAV format (specify format manually):

$ roc-recv -vv -s rtp://0.0.0.0:10001 -o file:./output.file --output-format wav

Output to stdout in WAV format:

$ roc-recv -vv -s rtp://0.0.0.0:10001 -o file:- --output-format wav >./output.wav

Output to a file in WAV format (absolute path):

$ roc-recv -vv -s rtp://0.0.0.0:10001 -o file:///home/user/output.wav

Specify backup file:

$ roc-recv -vv -s rtp://0.0.0.0:10001 --backup file:./backup.wav

Tuning examples

Force a specific rate on the output device:

$ roc-recv -vv -s rtp://0.0.0.0:10001 --rate=44100

Select the LDPC-Staircase FEC scheme:

$ roc-recv -vv -s rtp+ldpc://0.0.0.0:10001 -r ldpc://0.0.0.0:10002 \
    -c rtcp://0.0.0.0:10003

Select lower session latency:

$ roc-recv -vv -s rtp://0.0.0.0:10001 --target-latency=50ms

Select lower I/O latency and frame length:

$ roc-recv -vv -s rtp://0.0.0.0:10001 \
    --io-latency=20ms --frame-len 4ms

Manually specify thresholds and timeouts:

$ roc-recv -vv -s rtp://0.0.0.0:10001 \
    --target-latency=50ms --min-latency=40ms --max-latency 60ms \
    --no-play-timeout=200ms --choppy-play-timeout=500ms

Manually specify resampling parameters:

$ roc-recv -vv -s rtp://0.0.0.0:10001 \
    --resampler-backend=speex --resampler-profile=high

Manually specify latency tuning parameters:

$ roc-recv -vv -s rtp://0.0.0.0:10001 \
    --latency-backend=niq --latency-profile=gradual

ENVIRONMENT VARIABLES

The following environment variables are supported:

NO_COLOR
By default, terminal coloring is automatically detected. This environment variable can be set to a non-empty string to disable terminal coloring. It has lower precedence than --color option.
FORCE_COLOR
By default, terminal coloring is automatically detected. This environment variable can be set to a positive integer to enable/force terminal coloring. It has lower precedence than NO_COLOR variable and --color option.
