RUTA(8) Manual de Administrador del Sistema de Linux RUTA(8)

NOMBRE

route - mostrar / manipular la tabla de enrutamiento IP

SINOPSIS

route [-CFvnNee] [-A familia |-4|-6]

route
[-v] [-A familia |-4|-6] add [-net|-host] objetivo [netmask Nm] [gw Gw] [metric N] [mss M] [window W] [irtt I] [reject] [mod] [dyn] [reinstate] [[dev] If]
route
[-v] [-A familia |-4|-6] del [-net|-host] objetivo [gw Gw] [netmask Nm] [metric M] [[dev] If]
route
[-V] [--version] [-h] [--help]

DESCRIPCIÓN

Route manipula las tablas de enrutamiento IP del kernel. Su uso principal es configurar rutas estáticas a hosts o redes específicas a través de una interfaz después de que haya sido configurada con el programa ifconfig(8).

Cuando se utilizan las opciones add o del, route modifica las tablas de enrutamiento. Sin estas opciones, route muestra el contenido actual de las tablas de enrutamiento.

OPCIONES

-A familia
usa la familia de direcciones especificada (ej. `inet'). Usa route --help para una lista completa. Puedes usar -6 como alias para --inet6 y -4 como alias para -A inet.
-F
opera sobre la tabla de enrutamiento FIB (Base de Información de Encaminamiento) del kernel. Esta es la opción por defecto.
-C
opera sobre la caché de enrutamiento del kernel.
-v
selecciona operación detallada.
-n
muestra direcciones numéricas en lugar de intentar determinar nombres simbólicos de host. Esto es útil si estás intentando determinar por qué ha desaparecido la ruta a tu servidor de nombres.
-e
usa el formato de netstat(8) para mostrar la tabla de enrutamiento. -ee generará una línea muy larga con todos los parámetros de la tabla de enrutamiento.
del
elimina una ruta.
add
añade una nueva ruta.
objetivo
la red o host de destino. Puedes proporcionar una dirección o un nombre simbólico de red o host. Opcionalmente, puedes usar la notación /longitud_prefijo en lugar de usar la opción netmask.
-net
el objetivo es una red.
-host
el objetivo es un host.
netmask NM
al añadir una ruta de red, la máscara de red a utilizar.
gw GW
reenvía paquetes a través de una puerta de enlace.
NOTA: La puerta de enlace especificada debe ser alcanzable primero. Esto generalmente significa que debes configurar una ruta estática a la puerta de enlace de antemano. Si especificas la dirección de una de tus interfaces locales, se usará para decidir a qué interfaz se deben reenviar los paquetes. Este es un truco de compatibilidad BSD.
metric M
establece el campo métrico en la tabla de enrutamiento (usado por los demonios de enrutamiento) a M. Si no se especifica esta opción, la métrica para la familia de direcciones inet6 (IPv6) por defecto es '1', para inet (IPv4) por defecto es '0'. Siempre debes especificar un valor métrico explícito para no depender de esos valores predeterminados: también difieren de iproute2.
mss M
establece la MTU (Unidad Máxima de Transmisión) de la ruta a M bytes. Ten en cuenta que la implementación actual del comando route no permite la opción para establecer el MSS (Tamaño Máximo de Segmento).
window W
establece la ventana TCP para conexiones a través de esta ruta a W bytes. Esto generalmente solo se usa en redes AX.25 y con controladores incapaces de manejar tramas consecutivas.
irtt I
establece el tiempo de ida y vuelta inicial (irtt) para conexiones TCP a través de esta ruta a I milisegundos (1-12000). Esto generalmente solo se usa en redes AX.25. Si se omite, se usa el valor predeterminado de 300 ms de RFC 1122.
reject
instala una ruta de bloqueo, que forzará un fallo en la búsqueda de ruta. Esto se usa, por ejemplo, para enmascarar redes antes de usar la ruta predeterminada. ¡Esto NO es para cortafuegos!
mod, dyn, reinstate
instala una ruta dinámica o modificada. Estas banderas son para fines de diagnóstico, y generalmente solo son establecidas por demonios de enrutamiento.
dev If
fuerza que la ruta se asocie con el dispositivo especificado, ya que de lo contrario el kernel intentará determinar el dispositivo por sí mismo (comprobando rutas y especificaciones de dispositivo ya existentes, y dónde se añade la ruta). En la mayoría de las redes normales no necesitarás esto.

Si dev If es la última opción en la línea de comandos, la palabra dev puede omitirse, ya que es la opción predeterminada. De lo contrario, el orden de los modificadores de ruta (metric netmask gw dev) no importa.

EJEMPLOS

route add -net 127.0.0.0 netmask 255.0.0.0 metric 1024 dev lo
añade la entrada normal de loopback, usando la máscara de red 255.0.0.0 y asociada con el dispositivo "lo" (asumiendo que este dispositivo fue configurado previamente correctamente con ifconfig(8)).
route add -net 192.56.76.0 netmask 255.255.255.0 metric 1024 dev eth0
añade una ruta a la red local 192.56.76.x a través de "eth0". La palabra "dev" puede omitirse aquí.
route del default
elimina la ruta predeterminada actual, que se etiqueta como "default" o 0.0.0.0 en el campo de destino de la tabla de enrutamiento actual.
route del -net 192.56.76.0 netmask 255.255.255.0
elimina la ruta. Dado que el kernel de enrutamiento de Linux utiliza direccionamiento sin clases, casi siempre tendrás que especificar la máscara de red que sea la misma que se ve en la lista 'route -n'.
route add default gw mango
añade una ruta predeterminada (que se usará si ninguna otra ruta coincide). Todos los paquetes que usen esta ruta serán enrutados a través de la dirección de un nodo llamado "mango". El dispositivo que se usará realmente para esa ruta depende de cómo podamos alcanzar "mango"; "mango" debe estar en una ruta directamente alcanzable.
route add mango sl0
Añade la ruta al host llamado "mango" a través de la interfaz SLIP (asumiendo que "mango" es el host SLIP).
route add -net 192.57.66.0 netmask 255.255.255.0 gw mango
Este comando añade la red "192.57.66.x" para ser enrutada a través de la ruta anterior a la interfaz SLIP.
route add -net 224.0.0.0 netmask 240.0.0.0 dev eth0
Este es un comando oscuro documentado para que la gente sepa cómo hacerlo. Configura todas las rutas IP de clase D (multidifusión) para que vayan a través de "eth0". Esta es la línea de configuración normal correcta con un kernel de multidifusión.
route add -net 10.0.0.0 netmask 255.0.0.0 metric 1024 reject
Esto instala una ruta de rechazo

EJEMPLOS

Aquí hay algunos ejemplos de cómo usar route:

route add default gw 192.168.1.1
Esto agrega una ruta por defecto que envía todo el tráfico a través de la puerta de enlace 192.168.1.1.
route add -net 192.168.2.0 netmask 255.255.255.0 gw 10.0.0.1
Esto agrega una ruta para la red 192.168.2.0/24 que envía todo el tráfico destinado a esa red a través de la puerta de enlace 10.0.0.1.
route del -net 10.0.0.0/8
Esto elimina todas las rutas para la red 10.0.0.0/8.
route add -host 192.168.3.5 gw 192.168.1.2
Esto agrega una ruta para el host específico 192.168.3.5 que envía todo el tráfico destinado a ese host a través de la puerta de enlace 192.168.1.2.
route add -net 10.0.0.0 netmask 255.0.0.0 reject
Esto agrega una ruta para la red 10.0.0.0/8 que rechaza activamente todo el tráfico destinado a esa red.
route add -net 10.0.0.0/8 dev eth0
Esto agrega una ruta para la red 10.0.0.0/8 que envía todo el tráfico directamente a través de la interfaz eth0.
route -6 add 2001:0002::/48 metric 1 dev eth0
Esto agrega una ruta IPv6 con la métrica especificada que es directamente alcanzable a través de eth0.

SALIDA

La salida de la tabla de enrutamiento del kernel está organizada en las siguientes columnas:

Destino
La red de destino o el host de destino.
Puerta_de_enlace
La dirección de la puerta de enlace o '*' si no hay ninguna configurada.
Genmask
La máscara de red para la red de destino; '255.255.255.255' para un destino de host y '0.0.0.0' para la ruta predeterminada.
Banderas
Las banderas posibles incluyen:
U (la ruta está activa)
H (el destino es un host)
G (usar puerta_de_enlace)
R (restaurar ruta para enrutamiento dinámico)
D (instalada dinámicamente por un demonio o redirección)
M (modificada por un demonio de enrutamiento o redirección)
A (instalada por addrconf)
C (entrada de caché)
! (ruta de rechazo)
Métrica
La 'distancia' al destino (generalmente contada en saltos).
Ref
Número de referencias a esta ruta. (No se usa en el kernel de Linux).
Uso
Conteo de búsquedas para la ruta. Dependiendo del uso de -F y -C, serán fallos de caché de ruta (-F) o aciertos (-C).
Interfaz
Interfaz a la que se enviarán los paquetes para esta ruta.
MSS
Tamaño máximo de segmento predeterminado para conexiones TCP a través de esta ruta.
Ventana
Tamaño de ventana predeterminado para conexiones TCP a través de esta ruta.
irtt
RTT (Round Trip Time - Tiempo de ida y vuelta) inicial. El kernel lo usa para estimar los mejores parámetros del protocolo TCP sin esperar respuestas (posiblemente lentas).
HH (solo en caché)
El número de entradas ARP y rutas cacheadas que se refieren a la caché de cabecera de hardware para la ruta cacheada. Será -1 si no se necesita una dirección de hardware para la interfaz de la ruta cacheada (por ejemplo, lo).
Arp (solo en caché)
Si la dirección de hardware para la ruta cacheada está actualizada o no.
