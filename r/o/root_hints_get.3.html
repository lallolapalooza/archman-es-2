NOMBRE

val_create_context() val_free_context() - administrar el contexto del validador

val_context_setqflags() - administrar las banderas del contexto del validador

val_resolve_and_check(), val_free_result_chain() - consultar y validar respuestas de un servidor de nombres DNS

val_istrusted() - verificar si el valor de estado corresponde al de una respuesta confiable

val_isvalidated() - verificar si el valor de estado representa una respuesta que se encadena criptográficamente desde un ancla de confianza configurada

val_does_not_exist() - verificar si el valor de estado representa uno de los tipos de no existencia

p_val_status(), p_ac_status(), p_val_error() - mostrar el estado de validación, el estado de la cadena de autenticación y la información de error

val_log_add_optarg - controlar la verbosidad de los mensajes de registro y la ubicación de salida

DESCRIPCIÓN

La función val_resolve_and_check() consulta a un conjunto de servidores de nombres para la tupla <nombre_dominio, tipo, clase> y verifica y valida la respuesta. La verificación implica comprobar los RRSIG, y la validación es la verificación de una cadena de autenticación desde un ancla de confianza configurada.

El parámetro flags se puede utilizar para controlar los resultados de la validación. Los siguientes valores, que pueden combinarse con OR, están actualmente definidos para este campo:

VAL_QUERY_DONT_VALIDATE
Esta bandera hace que el validador deshabilite la validación para esta consulta.
VAL_QUERY_IGNORE_SKEW
Esta bandera hace que el validador deshabilite la comprobación de los tiempos de inicio y expiración de las firmas en los RRSIG.
VAL_QUERY_AC_DETAIL
Esta bandera hace que el validador copie los detalles de la cadena de autenticación en el miembro val_rc_answer dentro de la estructura val_result_chain devuelta.
VAL_QUERY_ASYNC
Esta bandera habilita la resolución de consultas asíncrona para esa búsqueda.
VAL_QUERY_NO_DLV
Esta bandera hace que el validador deshabilite el procesamiento DLV para esta consulta. Esto solo está disponible si la biblioteca libval(3) ha sido compilada con soporte DLV.
VAL_QUERY_NO_EDNS0_FALLBACK
Al consultar varios servidores de nombres, libsres(3) también intentará varios tamaños de EDNS0, terminando con una consulta que tiene EDNS0 deshabilitado (es decir, sin el bit CD establecido). Esta bandera hace que libval deshabilite el fallback de EDNS0 para la consulta.
VAL_QUERY_ITERATE
Esta bandera fuerza a libval a buscar iterativamente el nombre consultando varios servidores de nombres en la jerarquía de delegación, en lugar de solicitar esta información a cualquier servidor de nombres en caché que pueda estar configurado en dnsval.conf.
VAL_QUERY_SKIP_RESOLVER
Esta bandera fuerza a libval a mirar solo su caché mientras intenta resolver un nombre.
VAL_QUERY_SKIP_CACHE
Hay dos niveles de caché que ocurren dentro de libval: a nivel de aserción y a nivel de respuesta. Esta bandera fuerza a libval a ignorar los datos en ambas cachés mientras intenta resolver un nombre.
VAL_QUERY_SKIP_ANS_CACHE
Hay dos niveles de caché que ocurren dentro de libval: a nivel de aserción y a nivel de respuesta. Esta bandera fuerza a libval a ignorar los datos en la caché de respuestas mientras intenta resolver un nombre. Si ya existe una aserción para el nombre, clase y tipo dados, esa aserción se reutiliza hasta que expira. Una vez que expira, el nombre se busca a través de una consulta, incluso si un registro más reciente (obtenido por otra aserción en el mismo o diferente contexto) está disponible en su caché de respuestas.

El primer parámetro de val_resolve_and_check() es el contexto del validador. Las aplicaciones pueden crear un nuevo contexto de validador utilizando la función val_create_context(). Esta función analiza los archivos de configuración del resolvedor y del validador y crea el manejador newcontext para esta información analizada. La información almacenada como parte del contexto del validador incluye la política de validación y la política del resolvedor.

Las políticas del validador y del resolvedor se leen de los archivos /etc/dnsval.conf y /etc/resolv.conf por defecto. /etc/root.hints proporciona información de arranque para el validador cuando funciona como un resolvedor completo (ver dnsval.conf(3)). Estos valores predeterminados pueden ser diferentes si se especificó algún otro valor en el momento de la configuración de la biblioteca. Si no se encuentra el archivo de configuración del resolvedor predeterminado en la ubicación especificada, libval también intentará recurrir a /etc/resolv.conf como último recurso.

Las aplicaciones también pueden crear un contexto de validador con una política personalizada utilizando la función val_create_context_ex().

El argumento opt en val_create_context_ex() apunta a la siguiente estructura:

typedef struct val_context_opt {
    unsigned int vc_qflags;
    unsigned int vc_polflags;
    char *vc_valpol;
    char *vc_nslist;
    char *vc_val_conf;
    char *vc_res_conf;
    char *vc_root_conf;
    val_global_opt_t *gopt, 
} val_context_opt_t;

vc_qflags especifica las banderas de consulta predeterminadas para las consultas asociadas con el contexto. Este campo es idéntico al argumento flags en la función val_resolve_and_check().

Los campos vc_val_conf, vc_res_conf y vc_root_conf se pueden usar para especificar archivos de configuración alternativos en lugar de los archivos predeterminados utilizados para la información de configuración del validador, el resolvedor y las pistas raíz.

El campo vc_valpol se puede usar para proporcionar un "fragmento" de configuración de validador personalizado al validador. El validador analiza esta información y la aplica a la configuración predeterminada del validador, ya sea como una extensión o como una anulación, según lo especificado por el campo vc_polflags. De manera similar, el campo vc_nslist se puede usar para proporcionar una lista personalizada de servidores de nombres recursivos a los que enviar consultas, además (o en lugar) de la lista de servidores de nombres especificada en el archivo resolv.conf. La lista de servidores de nombres en vc_res_conf debe especificarse como una lista separada por espacios en blanco de direcciones IP o IPv6.

Se puede crear un mapeo personalizado entre una zona y un servidor de nombres utilizando la función val_context_store_ns_for_zone().

vc_polflags puede configurarse con los siguientes valores:

CTX_DYN_POL_VAL_OVR
Cuando esta bandera está activada, solo la configuración del validador especificada en el campo vc_valpol se utiliza para la configuración del validador. Las opciones especificadas en el archivo dnsval.conf se ignoran.
CTX_DYN_POL_RES_OVR
Cuando esta bandera está activada, solo la lista de servidores de nombres proporcionada en el campo vc_nslist se utiliza para la resolución de nombres. Las opciones especificadas en el archivo resolv.conf se ignoran.

La función val_context_setqflags() establece las banderas para todas las futuras consultas asociadas con context. La bandera action se puede establecer en 0 para establecer las banderas o en 1 para borrar las banderas especificadas por flags.

La función val_create_context() devuelve un puntero a un validador de contexto nuevo y válido en newcontext. El parámetro label se usa para identificar el contexto en los mensajes de registro.

La función val_free_context() libera el contexto creado previamente por val_create_context() o val_create_context_ex().

La función val_free_result_chain() libera la estructura val_result_chain devuelta por val_resolve_and_check().

La función val_istrusted() devuelve 1 si el valor de val_status indica que la respuesta es confiable, de lo contrario, devuelve 0.

La función val_isvalidated() devuelve 1 si el valor de val_status indica que la respuesta ha sido validada, de lo contrario, devuelve 0.

La función val_does_not_exist() devuelve 1 si el valor de val_status indica que el nombre de dominio consultado no existe, de lo contrario, devuelve 0.

Las funciones p_val_status(), p_ac_status() y p_val_error() devuelven una cadena de caracteres que describe el valor de estado dado.

La función val_log_add_optarg() configura la salida de registro para libval. El parámetro args es un conjunto de opciones separadas por comas para controlar el nivel de detalle del registro. Si use_stderr se establece en 1, los mensajes de registro se enviarán a stderr, de lo contrario, se enviarán a syslog.

EJEMPLO

El siguiente código de ejemplo ilustra cómo consultar y validar una dirección A para un dominio específico:

#include <stdio.h>
#include <stdlib.h>
#include <validator.h>

int
main(int argc, char **argv)
{
    val_context_t *context;
    struct val_result_chain *results;
    int ret;

    if (argc != 2) {
        fprintf(stderr, "Uso: %s <dominio>\n", argv[0]);
        exit(1);
    }

    /* Crear un contexto de validador */
    ret = val_create_context("mi_app", &context);
    if (ret != VAL_SUCCESS) {
        fprintf(stderr, "Error al crear el contexto del validador: %s\n",
                p_val_error(ret));
        exit(1);
    }

    /* Consultar y validar la dirección A para el dominio */
    ret = val_resolve_and_check(context, argv[1], QUERY_IN,
                                RR_A, VAL_QUERY_DONT_VALIDATE, &results);
    if (ret != VAL_SUCCESS) {
        fprintf(stderr, "Error al resolver y comprobar %s: %s\n",
                argv[1], p_val_error(ret));
        val_free_context(context);
        exit(1);
    }

    /* Imprimir los resultados */
    if (results && results->val_rc_answer) {
        struct val_answer *ans;
        for (ans = results->val_rc_answer; ans; ans = ans->val_ans_next) {
            if (ans->val_ans_type == RR_A) {
                char ip_str[INET_ADDRSTRLEN];
                inet_ntop(AF_INET, &ans->val_ans_rdata->val_rdata_ipv4,
                          ip_str, INET_ADDRSTRLEN);
                printf("Dirección A para %s: %s\n", argv[1], ip_str);
            }
        }
    } else {
        printf("No se encontraron registros A para %s\n", argv[1]);
    }

    /* Liberar recursos */
    val_free_result_chain(results);
    val_free_context(context);

    return 0;
}

FALLOS

El comportamiento de validación puede ser complejo y propenso a errores. Es posible que las políticas de validación no estén configuradas correctamente, o que los anclajes de confianza no estén disponibles.

DESCRIPTION

The val_context_init() function initializes a validation context. A validation context is used to hold configuration options for the DNSSEC validator.

The flags parameter can be set to one or more of the following values:

CTX_DYN_POL_RES_OVR
When this flag is set only the name servers specified in the vc_nslist field is used for the resolver configuration. Options specified in the resolv.conf file are ignored.
CTX_DYN_POL_GLO_OVR
When this flag is set only the global options set in gopt field are used. Global options specified in the dnsval.conf file are ignored.
CTX_DYN_POL_RES_NRD
When this flag is set outgoing queries have the Recursion Desired (RD) bit set to 0. This is useful if queries need to be sent to an authoritative-only name server.

The gopt field points to the following structure:

typedef struct val_global_opt {
    int local_is_trusted;
    long edns0_size;
    int env_policy;
    int app_policy;
    char *log_target;
    int closest_ta_only;
    int rec_fallback;
    long max_refresh;
    int proto;
} val_global_opt_t;

Setting a value of 1 for local_is_trusted is equivalent to specifying the trust-oob-answers option in the dnsval.conf file to yes. Similarly, setting the closest_ta_only and rec_fallback members to 1 is equivalent to setting the closest-ta-only and rec-fallback options to yes in the dnsval.conf file. A value of 0 is equivalent to the no setting for these option.

Setting the edns0_size member to a particular value has the same effect setting the edns0-size option in the dnsval.conf file.

Setting the max_refresh member to a particular value has the same effect setting the max-refresh option in the dnsval.conf file.

Setting the proto member to a particular value has the same effect setting the proto option in the dnsval.conf file.

env_policy and app_policy can be set to one of VAL_POL_GOPT_DISABLE, VAL_POL_GOPT_ENABLE, or VAL_POL_GOPT_OVERRIDE. These values correspond directly to the disable, enable and override options for the env-policy and app-policy settings in the dnsval.conf file.

Values of -1 for the above fields are treated as "ignore" conditions in that the validator will not include dynamically supplied global options with a value of -1 when creating its context. This allows an application to overriding a subset of global options while using the global options supplied in the dnsval.conf file by default.

The log_target field enables the application to supply log targets in addition to the ones configured in the configuration file.

See dnsval.conf(3) for more details on specifying validator policy.

Default query flags can be set and unset for a given context using val_context_setqflags(). This allows an application to alter the DNSSEC validator processing, while still having most of the more granular default configuration specified in its configuration file. The action parameter can be set to one of the following.

VAL_CTX_FLAG_SET
This option causes the validator to set the given flag as one of the default query flags.
VAL_CTX_FLAG_RESET
This option causes the validator to reset the given flag if it was set as one of the default query flags for the context.

Answers returned by val_resolve_and_check() are made available in the *results linked list. Each answer corresponds to a distinct RRset; multiple RRs within the RRset are part of the same answer. Multiple answers are possible when type is ns_t_any or ns_t_rrsig.

Individual elements in *results point to val_authentication_chain linked lists. The authentication chain elements in val_authentication_chain contain the actual RRsets returned by the name server in response to the query.

Validation result values returned in val_result_chain can be can be converted into ASCII format using the p_val_status(). Authentication chain status values returned in each element of the val_authentication_chain linked list can be can be converted into ASCII format using the p_ac_status() functions.

While some applications such as DNSSEC troubleshooting utilities and packet inspection tools may look at individual authentication chain elements to identify the actual reasons for validation error, most applications will only be interested in a single error code for determining the authenticity of data.

val_isvalidated() identifies if a given validation result status value corresponds to an answer that was cryptographically verified and validated using a locally configured trust anchor.

val_istrusted() identifies if a given validator status value is trusted. An answer may be locally trusted without being validated.

val_does_not_exist() identifies if a given validator status value corresponds to one of the non-existence types.

The libval library internally allocates memory for *results and this must be freed by the invoking application using the free_result_chain() interface.

DATA STRUCTURES

struct val_result_chain
struct val_result_chain
{
    val_status_t                     val_rc_status;
    char                            *val_rc_alias;
    struct val_rrset_rec            *val_rc_rrset;
    struct val_authentication_chain *val_rc_answer;
    int                              val_rc_proof_count;
    struct val_authentication_chain *val_rc_proofs[MAX_PROOFS];
    struct val_result_chain         *val_rc_next;
};
val_rc_answer
Cadena de autenticación para un RRset dado.
val_rc_next
Puntero al siguiente RRset en el conjunto de respuestas devueltas para una consulta.
val_rc_proofs
Puntero a las cadenas de autenticación para cualquier prueba de no existencia que se haya devuelto para la consulta.
val_rc_proof_count
Número de elementos de prueba almacenados en val_rc_proofs. El número no puede exceder MAX_PROOFS.
val_rc_alias
Para un elemento val_result_chain que apunta a un alias de nombre, este campo contiene el valor de destino.
val_rc_rrset
Para un elemento val_result_chain que contiene un campo val_rc_answer válido (no NULL), el campo val_rc_rrset apunta al elemento val_rrset_rec de nivel superior en la cadena de autenticación val_rc_answer.
val_rc_status
Estado de validación para un RRset dado. Puede ser uno de los siguientes:
VAL_SUCCESS
Respuesta recibida y validada con éxito.
VAL_NONEXISTENT_NAME
No existía el nombre y se devolvió una prueba válida de no existencia que confirmaba el nombre faltante (ámbito NSEC o NSEC3). Los componentes de la prueba también se validaron individualmente.
VAL_NONEXISTENT_TYPE
No existía el tipo para el nombre y se devolvió una prueba válida de no existencia que confirmaba el nombre faltante. Los componentes de la prueba también se validaron individualmente.
VAL_NONEXISTENT_NAME_NOCHAIN
No existía el nombre y se devolvió una prueba válida de no existencia que confirmaba el nombre faltante. Los componentes de la prueba también se identificaron como confiables, pero no se validaron individualmente.
VAL_NONEXISTENT_TYPE_NOCHAIN
No existía el tipo para el nombre y se devolvió una prueba válida de no existencia que confirmaba el nombre faltante (ámbito NSEC o NSEC3). Los componentes de la prueba también se identificaron como confiables, pero no se validaron individualmente.
VAL_PINSECURE
Se sabía que el registro o algún ancestro del registro en la cadena de autenticación hacia el ancla de confianza era demostrablemente inseguro.
VAL_PINSECURE_UNTRUSTED
Se sabía que el registro o algún ancestro del registro en la cadena de autenticación hacia el ancla de confianza era demostrablemente inseguro. Pero la condición demostrablemente insegura se configuró como no confiable.
VAL_BARE_RRSIG
No es posible la validación DNSSEC, la consulta era para un RRSIG.
VAL_IGNORE_VALIDATION
La política local se configuró para ignorar la validación de la zona de la cual se recibieron estos datos.
VAL_UNTRUSTED_ZONE
La política local se configuró para rechazar cualquier dato recibido de la zona dada.
VAL_OOB_ANSWER
La respuesta se obtuvo utilizando algún método Out Of Band, como un archivo de configuración local.
VAL_BOGUS
La respuesta no pudo ser validada debido a fallos en la verificación de firmas o a la imposibilidad de verificar las pruebas en la cadena de autenticación.
VAL_DNS_ERROR
Se encontró algún error durante el procesamiento de DNS.
VAL_INDETERMINATE
La respuesta no pudo ser validada debido a metadatos DNSSEC faltantes.
VAL_NOTRUST
Todos los componentes disponibles en la cadena de autenticación se verificaron correctamente, pero no había ningún ancla de confianza disponible.

Los valores de estado en val_status_t devueltos por el validador se pueden mostrar en formato ASCII utilizando p_val_status().

val_ac_status
Estado de validación del elemento de la cadena de autenticación. Este campo contendrá el código de estado para el componente dado en la cadena de autenticación. Este campo puede contener uno de los siguientes valores:
VAL_AC_UNSET
No se pudo determinar el estado.
VAL_AC_IGNORE_VALIDATION
Se ignoró la validación del registro de recursos dado, ya sea debido a alguna directiva de política local o debido a algún comportamiento específico del protocolo.
VAL_AC_UNTRUSTED_ZONE
La política local definió una zona dada como no confiable, sin que se considerara necesaria ninguna validación adicional.
VAL_AC_PINSECURE
No se pudo construir la cadena de autenticación desde un ancla de confianza hasta una zona dada debido a la ausencia demostrable de un registro DS para esta zona en el padre.
VAL_AC_BARE_RRSIG
La respuesta fue para una consulta de tipo RRSIG. Los RRSIG contienen las firmas criptográficas para otros datos DNS y no pueden validarse por sí mismos.
VAL_AC_NO_LINK
No se configuró ningún ancla de confianza para una cadena de autenticación dada o la cadena no se enlazó.
VAL_AC_TRUST
Al menos una de las firmas que cubren el conjunto de registros DNSKEY dado se verificó directamente utilizando una clave configurada como ancla de confianza DNSSEC.
VAL_AC_RRSIG_MISSING
No se pudieron recuperar los datos RRSIG para un registro de recursos.
VAL_AC_DNSKEY_MISSING
No se pudo recuperar el DNSKEY de un RRSIG que cubre un registro de recursos.
VAL_AC_DS_MISSING
No estuvo disponible el registro DS que cubre un registro DNSKEY.
VAL_AC_DATA_MISSING
No se devolvieron datos para una consulta y el DNS no indicó un error.
VAL_AC_DNS_ERROR
Se encontró algún error durante el procesamiento de DNS.
VAL_AC_NOT_VERIFIED
No se pudieron verificar todos los RRSIG que cubrían el conjunto de registros.
VAL_AC_VERIFIED
Al menos un RRSIG que cubría un registro de recursos tenía un estado de VAL_AC_RRSIG_VERIFIED.
val_ac_rrset
Puntero a un conjunto de registros de tipo struct val_rrset_rec obtenido de la respuesta DNS.
val_ac_trust
Puntero a un elemento de cadena de autenticación que contiene un conjunto de registros DNSKEY que se puede utilizar para verificar RRSIG sobre el registro actual, o contiene un conjunto de registros DS que se puede utilizar para construir la cadena de confianza hacia un ancla de confianza.

VAL_AC_RRSIG_VERIFIED

VAL_AC_WCARD_VERIFIED

VAL_AC_RRSIG_VERIFIED_SKEW

VAL_AC_WCARD_VERIFIED_SKEW

VAL_AC_WRONG_LABEL_COUNT
    El número de etiquetas en la firma fue mayor

VAL_AC_INVALID_RRSIG
    No se pudo analizar la RRSIG.
VAL_AC_RRSIG_NOTYETACTIVE
    El tiempo de inicio de la RRSIG está en el futuro.
VAL_AC_RRSIG_EXPIRED
    La RRSIG había expirado.
VAL_AC_ALGORITHM_NOT_SUPPORTED
    El algoritmo RRSIG no fue compatible.
VAL_AC_RRSIG_VERIFY_FAILED
    Una RRSIG dada que cubre un conjunto de registros era
      falsa.
VAL_AC_RRSIG_ALGORITHM_MISMATCH
    El keytag al que se hace referencia en la RRSIG coincidía con un
    DNSKEY pero los algoritmos eran diferentes.
VAL_AC_DNSKEY_NOMATCH
    Una RRSIG fue creada por un DNSKEY que no
    existía en el conjunto de claves del apex.

Para cada miembro val_rr_rec de tipo DNSKEY (o DS, donde sea relevante) dentro del conjunto de registros de autenticación val_ac_rrset, el estado de validación se almacena en la variable rr_status y puede devolver uno de los siguientes valores:

VAL_AC_TRUST_POINT
    El DNSKEY o el registro DS dado se configuró 
    como un ancla de confianza DNSSEC.
VAL_AC_SIGNING_KEY
    Este DNSKEY se utilizó para crear una RRSIG para
    el conjunto de registros de recursos.
VAL_AC_VERIFIED_LINK
    Este DNSKEY proporcionó el enlace en la cadena de autenticación
    desde el ancla de confianza hasta el registro firmado.
VAL_AC_UNKNOWN_ALGORITHM_LINK
    Este DNSKEY proporcionó el enlace en la cadena de autenticación
    desde el ancla de confianza hasta el registro firmado,
    pero el algoritmo DNSKEY era desconocido.
VAL_AC_UNKNOWN_DNSKEY_PROTOCOL
    El número de protocolo DNSKEY no fue reconocido.
VAL_AC_ALGORITHM_NOT_SUPPORTED
    El algoritmo DNSKEY o DS no fue compatible.

VAL_AC_DS_NOMATCH
    Una RRSIG se creó con una clave que no
    existía en el conjunto de registros DS padre.
VAL_AC_INVALID_KEY
    La clave utilizada para verificar la RRSIG no era un DNSKEY válido.
VAL_AC_INVALID_DS
    El DS utilizado para validar el DNSKEY no se pudo analizar.
rr_next
Punta al siguiente registro de recursos en el conjunto de registros.

REGISTRO (LOGGING)

libval proporciona la función val_log_add_optarg() para controlar la verbosidad y la ubicación de la salida de los mensajes de registro.

La función val_log_add_optarg() toma dos argumentos: el primer argumento args es un valor de cadena de caracteres que especifica la ubicación y la verbosidad. El segundo argumento, use_stderr, si se establece en un valor mayor que 0, permite que libval envíe mensajes de registro a stderr.

La cadena de caracteres que especifica la ubicación y la verbosidad del destino del registro tiene un formato específico:

<nivel-debug>:<tipo-destino>[:<opciones-destino>]

donde
<nivel-debug> es 1-7, para niveles crecientes de verbosidad
<tipo-destino> es uno de file, net, syslog, stderr, stdout
<opciones-destino> depende de <tipo-destino>
file:<nombre-archivo> (abierto en modo de adición)
net[:<nombre-host>:<puerto-host>] (127.0.0.1:1053)
syslog[:facility] (0-23 (predeterminado 1 USER))

Los niveles de registro se pueden traducir aproximadamente a diferentes tipos de mensajes de registro de la siguiente manera (los mensajes devueltos para cada nivel en esta lista incluyen los mensajes devueltos para el nivel anterior):

3 : Error   : error encontrado
4 : Warning : recuperación de un error
5 : Notice  : proporciona resultados finales de validación para una consulta 
              y detalles sobre archivos de políticas y etiquetas utilizadas 
6 : Info    :
da detalles sobre cadenas de autenticación 7 : Debug : proporciona información de nivel de depuración
