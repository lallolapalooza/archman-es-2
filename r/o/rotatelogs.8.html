ROTATELOGS(8) rotatelogs ROTATELOGS(8)

NOMBRE

rotatelogs - Programa de registro por tubería para rotar los registros de Apache

SINOPSIS

rotatelogs [ -l ] [ -L nombre-enlace ] [ -p programa ] [ -f ] [ -D ] [ -t ] [ -v ] [ -e ] [ -c ] [ -n número-de-archivos ] archivo-log tiempo-rotación|tamaño-archivo(B|K|M|G) [ desfase ]

RESUMEN

rotatelogs es un programa simple para usar junto con la función de archivo de registro por tubería de Apache. Soporta la rotación basada en un intervalo de tiempo o en el tamaño máximo del registro.

OPCIONES

-l
Causa el uso de la hora local en lugar de GMT como base para el intervalo o para el formato strftime(3) con rotación basada en tamaño.
-L nombre-enlace
Crea un enlace simbólico que apunta al archivo de registro actual. El nombre del enlace se pasa como primer argumento al programa ejecutado por la opción -p. La longitud del nombre-enlace no debe superar los 255 caracteres. La opción -L debe usarse junto con la opción -p.
-p programa
Si se especifica, rotatelogs ejecutará el programa especificado cada vez que se abra un nuevo archivo de registro. El nombre del archivo recién abierto se pasa como primer argumento al programa. Si se ejecuta después de una rotación, el archivo de registro antiguo se pasa como segundo argumento. rotatelogs no espera a que el programa especificado termine antes de continuar operando, y no registrará ningún código de error devuelto en la terminación. El programa invocado utiliza la misma entrada estándar, salida estándar y error estándar que rotatelogs, y también hereda el entorno.
-f
Causa que el archivo de registro se abra inmediatamente, tan pronto como rotatelogs comience, en lugar de esperar a que se lea la primera entrada del archivo de registro (para sitios no muy ocupados, puede haber un retraso considerable entre el inicio del servidor y el manejo de la primera solicitud, lo que significa que el archivo de registro asociado no "existe" hasta entonces, lo que causa problemas a algunas herramientas de registro automatizadas)
-D
Crea los directorios padre de la ruta donde se colocará el archivo de registro si aún no existen. Esto permite que se utilicen las sustituciones de formato strftime(3) en la ruta y no solo en el nombre del archivo.
-t
Causa que el archivo de registro se trunque en lugar de rotarse. Esto es útil cuando un registro es procesado en tiempo real por un comando como tail, y no hay necesidad de datos archivados. No se agregará ningún sufijo al nombre del archivo, sin embargo, se respetarán las cadenas de formato que contengan caracteres '%'.
-T
Causa que todos los archivos de registro, excepto el inicial, se trunquen al abrirse. Esto es útil cuando la cadena de formato contiene algo que circulará, como el día del mes. Disponible en 2.4.56 y posteriores.
-v
Produce salida detallada en STDERR. La salida contiene el resultado del análisis de configuración y todas las acciones de apertura y cierre de archivos.
-e
Reenvía los registros a la salida estándar. Útil cuando los registros deben ser procesados adicionalmente en tiempo real por otra herramienta en la cadena.
-c
Crea un archivo de registro para cada intervalo, incluso si está vacío.
-n número-de-archivos
Utiliza una lista circular de nombres de archivo sin marcas de tiempo. Esta opción sobrescribe los archivos de registro al inicio y durante la rotación. Con -n 3, la serie de archivos de registro abiertos sería "archivo-log", "archivo-log.1", "archivo-log.2", y luego sobrescribiendo "archivo-log". Cuando este programa abre por primera vez "archivo-log", el archivo solo se truncará si también se proporciona -t. Cada rotación posterior siempre comenzará con el truncamiento del archivo de destino. Para la rotación basada en tamaño sin -t y con archivos de registro existentes, esta opción puede resultar en un comportamiento poco intuitivo, como que las entradas de registro iniciales se envíen a "archivo-log.1", y las entradas en "archivo-log.1" no se conserven incluso si más tarde no se han utilizado todavía "archivo-log.n". Disponible en 2.4.5 y posteriores.
archivo-log
El nombre del archivo de registro a rotar. Los sufijos se añaden usando la función strftime(3). Si se utiliza la opción -n, entonces los sufijos son simplemente .1, .2, etc.
tiempo-rotación
El tiempo entre rotaciones del archivo de registro en segundos. La rotación ocurre al principio de este intervalo. Por ejemplo, si el tiempo de rotación es 3600, el archivo de registro se rotará al principio de cada hora; si el tiempo de rotación es 86400, el archivo de registro se rotará todas las noches a medianoche. (Si no se registra ningún dato durante un intervalo, no se creará ningún archivo.)
tamaño-archivo(B|K|M|G)
El tamaño máximo del archivo en seguido de exactamente una de las letras B (Bytes), K (KBytes), M (MBytes) o G (GBytes). PP Cuando se especifican tiempo y tamaño, el tamaño debe darse después del tiempo. La rotación ocurrirá cada vez que se alcancen los límites de tiempo o tamaño.
desfase
El número de minutos de desfase respecto a UTC. Si se omite, se asume cero y se utiliza UTC. Por ejemplo, para usar la hora local en la zona UTC -5 horas, especifique un valor de -300 para este argumento. En la mayoría de los casos, se debe usar -l en lugar de especificar un desfase.

EJEMPLOS

     CustomLog "|bin/rotatelogs /var/log/logfile 86400" common

Esto crea los archivos /var/log/logfile.nnnn donde nnnn es la hora del sistema en la que nominalmente comienza el registro (esta hora siempre será un múltiplo del tiempo de rotación, por lo que puede sincronizar scripts cron con ella). Al final de cada tiempo de rotación (aquí después de 24 horas) se inicia un nuevo registro.

     CustomLog "|bin/rotatelogs -l /var/log/logfile.%Y.%m.%d 86400" common

Esto crea los archivos /var/log/logfile.aaaa.mm.dd donde aaaa es el año, mm es el mes y dd es el día del mes. El registro cambiará a un nuevo archivo cada día a medianoche, hora local.

     CustomLog "|bin/rotatelogs /var/log/logfile 5M" common

Esta configuración rotará el archivo de registro cada vez que alcance un tamaño de 5 megabytes.

     ErrorLog "|bin/rotatelogs /var/log/errorlog.%Y-%m-%d-%H_%M_%S 5M"

Esta configuración rotará el archivo de registro de errores cada vez que alcance un tamaño de 5 megabytes, y el sufijo del nombre del archivo de registro se creará con el formato errorlog.AAAA-mm-dd-HH_MM_SS.

     CustomLog "|bin/rotatelogs -t /var/log/logfile 86400" common

Esto crea el archivo /var/log/logfile, truncando el archivo al inicio y luego truncando el archivo una vez al día. Se espera en este escenario que un proceso separado (como tail) procese el archivo en tiempo real.

     CustomLog "|bin/rotatelogs -T /var/log/logfile.%d 86400" common

Si el servidor se inicia (o se reinicia) el primer día del mes, esto añade a /var/log/logfile.01. Cuando se escribe una entrada de registro el segundo día del mes, /var/log/logfile.02 se trunca y se añadirán nuevas entradas al principio. Este ejemplo conserva aproximadamente 1 mes de registros sin mantenimiento externo.

PORTABILIDAD

Las siguientes sustituciones de cadena de formato de archivo de registro deberían ser compatibles con todas las implementaciones de strftime(3), consulte la página del manual de strftime(3) para ver las extensiones específicas de la biblioteca.

• %A - nombre completo del día de la semana (localizado)
• %a - nombre abreviado del día de la semana (localizado)
• %B - nombre completo del mes (localizado)
• %b - nombre abreviado del mes (localizado)
• %c - fecha y hora (localizado)
• %d - día del mes en 2 dígitos
• %H - hora en 2 dígitos (reloj de 24 horas)
• %I - hora en 2 dígitos (reloj de 12 horas)
• %j - día del año en 3 dígitos
• %M - minuto en 2 dígitos
• %m - mes en 2 dígitos
• %p - am/pm del reloj de 12 horas (localizado)
• %S - segundo en 2 dígitos
• %U - semana del año (domingo como primer día de la semana) en 2 dígitos
• %W - semana del año (lunes como primer día de la semana) en 2 dígitos
• %w - día de la semana (0=domingo, 6=sábado)
• %X - fecha (localizada)
• %x - fecha (localizada)
• %Y - año con 4 dígitos
• %y - año sin siglo en 2 dígitos
• %Z - nombre de la zona horaria (si está disponible)
• %% - un solo carácter '%'

Si está usando un sistema que no permite la rotación de archivos basada en el tiempo, o si está usando un sistema que no tiene un reloj de tiempo real, o si está usando un sistema que no tiene un nombre de host, entonces rotatelogs no funcionará correctamente.

Cuando se utiliza la rotación basada en tiempo, las marcas de tiempo se basan en la hora universal coordinada (UTC). Los registros se rotarán al comienzo de cada intervalo de tiempo especificado. Si el sistema no registra ningún dato durante un intervalo, no se creará ningún archivo.

Cuando se utiliza la rotación basada en tamaño, el tamaño se especifica seguido de una de las letras B (Bytes), K (KiloBytes), M (MegaBytes) o G (GigaBytes).

Si se especifican tanto el tiempo como el tamaño, la rotación ocurrirá cuando se alcance cualquiera de los dos límites.

El programa puede ser invocado mediante la directiva CustomLog o ErrorLog en el archivo de configuración de Apache. Por ejemplo:

     CustomLog "|/usr/sbin/rotatelogs /var/log/access.log 86400" common

Esto rotará el archivo de registro /var/log/access.log cada 24 horas (86400 segundos). El nombre del archivo rotado incluirá una marca de tiempo basada en la hora de inicio del registro.

     ErrorLog "|/usr/sbin/rotatelogs -l /var/log/error.log.%Y%m%d 3600"

Esto rotará el archivo de registro de errores cada hora (3600 segundos) y creará archivos con un sufijo que indica la fecha en formato AAAAmmdd, utilizando la hora local.

La opción -p permite ejecutar un programa externo cada vez que se rota un archivo. Por ejemplo, se podría usar para comprimir el archivo rotado:

     CustomLog "|bin/rotatelogs -p /usr/bin/gzip /var/log/access.log 86400" common

Esto rotará el archivo de registro cada 24 horas y luego ejecutará gzip en el archivo rotado.
