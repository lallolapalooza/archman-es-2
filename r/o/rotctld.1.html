ROTCTLD(1) Utilidades Hamlib ROTCTLD(1)

NOMBRE

rotctld - demonio de control de rotador TCP

SINOPSIS

rotctld [-hlLuV] [-m id] [-r dispositivo] [-s velocidad] [-T IPADDR] [-t número] [-C parámetro=valor] [-v[-Z]]

DESCRIPCIÓN

El programa rotctld es un demonio de control de rotador que maneja las solicitudes de los clientes a través de sockets TCP. Esto permite que múltiples programas de usuario compartan un rotador (esto necesita más desarrollo). Se pueden controlar múltiples rotadores en diferentes puertos TCP mediante el uso de múltiples procesos rotctld. La sintaxis de los comandos es la misma que la de rotctl(1). Se espera que rotctld sea especialmente útil para autores de clientes que utilicen lenguajes como Perl, Python, PHP y otros.

rotctld se comunica con un cliente a través de un socket TCP utilizando comandos de texto compartidos con rotctl. El protocolo es simple, los comandos se envían a rotctld en una línea y rotctld responde a los comandos de "obtener" con los valores solicitados, uno por línea, cuando tiene éxito; de lo contrario, responde con una línea "RPRT x", donde "x" es un número negativo que indica el código de error. Los comandos que no devuelven valores responden con la línea "RPRT x", donde "x" es "0" cuando tiene éxito, de lo contrario es un número negativo que indica el código de error. Cada línea está terminada con un carácter de nueva línea '\n'. Este protocolo es principalmente para uso por el backend de NET rotctl (modelo de rotador 2).

Un separado Protocolo de Respuesta Extendida extiende el comportamiento anterior al repetir la cadena del comando recibido como encabezado, cualquier valor devuelto como un par clave: valor, y la cadena "RPRT x" como marcador de fin de respuesta que incluye el valor de éxito o fallo de Hamlib. Consulte la sección PROTOCOLO para obtener detalles. Considere usar este protocolo para clientes que interactuarán directamente con rotctld a través de un socket TCP.

Tenga en cuenta que Hamlib es software de nivel BETA. Si bien muchas bibliotecas backend carecen de soporte completo para rotadores, las funciones básicas suelen estar bien soportadas.

Por favor, informe de errores y proporcione comentarios en la dirección de correo electrónico indicada en la sección ERRORES más adelante. Los parches y mejoras de código enviados a la misma dirección son bienvenidos.

OPCIONES

Este programa sigue la sintaxis habitual de línea de comandos de GNU. Las opciones cortas que toman un argumento pueden tener el valor inmediatamente después o separado por un espacio. Las opciones largas que comienzan con dos guiones (‘-’) requieren un ‘=’ entre la opción y cualquier argumento.

Aquí hay un resumen de las opciones compatibles:

-m, --modelo=id
Seleccionar el número de modelo del rotador.
Ver lista de modelos (usar “rotctld -l”).
Nota: rotctl (o software de terceros que utiliza la API C) utilizará el modelo de rotador 2 para NET rotctl (este número de modelo no se utiliza para rotctld aunque aparezca en la lista de modelos).
-r, --archivo-rotador=dispositivo
Usar dispositivo como el nombre de archivo del puerto conectado al rotador.
A menudo un puerto serie, pero podría ser un adaptador USB a serie. Típicamente /dev/ttyS0, /dev/ttyS1, /dev/ttyUSB0, etc. en Linux, COM1, COM2, etc. en MS Windows. Los sabores BSD y Mac OS/X tienen sus propias designaciones. Consulte la documentación de su sistema.
-s, --velocidad-serie=velocidad
Establecer la velocidad serie a velocidad baudios.
Utiliza la velocidad serie máxima de las capacidades del backend del rotador como valor predeterminado.
-T, --direccion-escucha=IPADDR
Usar IPADDR como la dirección IP de escucha.
El valor predeterminado es CUALQUIERA.
rotctld se puede ejecutar y conectar de la siguiente manera:
rotctld (se enlaza a todas las interfaces)
rotctl -m 2
rotctl -m 2 -r 127.0.0.1
rotctl -m 2 -r localhost
rotctl -m 2 -r 192.168.1.1 (dirección IP local)
rotctl -m 2 -r ::1 (en Linux rotctld no escucha en IPV6 por defecto)

rotctld -T 127.0.0.1 (enlazar solo a 127.0.0.1)
rotctl -m 2 (se enlaza a todas las interfaces)
rotctl -m 2 -r 127.0.0.1 (enlazar solo a 127.0.0.1)
-t, --puerto=número
Usar número como el puerto de escucha TCP.
El valor predeterminado es 4533.
Nota: Dado que el puerto predeterminado de rotctld es 4533, es aconsejable usar puertos impares para rotctld, por ejemplo, 4533, 4535, 4537, etc.
-L, --mostrar-conf
Mostrar todos los parámetros de configuración para el rotador definido con -m arriba.
-C, --establecer-conf=parámetro=valor[,parámetro=valor]
Establecer uno o más parámetros de configuración del rotador, por ejemplo, stop_bits=2.
Utilice la opción -L anterior para obtener una lista de parámetros de configuración para un número de modelo determinado.
-u, --volcar-estado
Volcar el estado del rotador definido con -m arriba y salir.
-u, --volcar-capacidades
Volcar las capacidades del rotador definido con -m arriba y salir.
-l, --listar
Listar todos los números de modelo de rotador definidos en Hamlib y salir.
La lista está ordenada por número de modelo.
Nota: En Linux, la lista se puede desplazar hacia atrás usando Shift-PageUp/Shift-PageDown, o usando las barras de desplazamiento de un terminal virtual en X o la ventana de comandos en Windows. La salida se puede canalizar a more(1) o less(1), por ejemplo, “rotctl -l | more”.
-v, --detallado
Establecer modo detallado, acumulativo (ver DIAGNÓSTICOS abajo).
-Z, --marcas-tiempo-depuracion
Habilitar marcas de tiempo para los mensajes de depuración.
Usar solo en combinación con la opción -v ya que no genera salida por sí sola.
-h, --ayuda
Mostrar un resumen de estas opciones y salir.
-V, --version
Mostrar la versión de rotctld y salir.

Nota: Es posible que algunas opciones no estén implementadas por un backend determinado y devuelvan un error. Esto es más probable que ocurra con las opciones --set-conf y --show-conf.

Tenga en cuenta que el backend para el rotador a controlar, o el rotador en sí mismo, puede no soportar algunos comandos. En ese caso, la operación fallará con un código de error de Hamlib.

PROTOCOL

\n

There are two protocols in use by rotctld, the Default\n Protocol and the Extended Response Protocol.

\n

The Default Protocol is intended primarily for the\n communication between Hamlib library functions and rotctld\n (\"NET rotctl\", available using rotator model '2').

\n

The Extended Response Protocol is intended to be used with\n scripts or other programs interacting directly with rotctld as\n consistent feedback is provided.

\n
\n

Default Protocol

\n

The Default Protocol is intentionally simple. Commands are\n entered on a single line with any needed values. In practice, reliable\n results are obtained by terminating each command string with a newline\n character, '\\n'.

\n

Example set position (Perl code):

\n

\n
\n

\n
print $socket \"P 135 10\\n\";
\n

or:

\n

\n
\n

\n
print $socket \"\\set_pos 135 10\\n\";   # escape leading '\\'\n
\n

A one line response will be sent as a reply to set\n commands, \"RPRT x\\n\" where x is the Hamlib error\n code with '0' indicating success of the command.

\n

Responses from rotctld get commands are text values\n and match the same tokens used in the set commands. Each value is\n returned on its own line. On error the string \"RPRT\n x\\n\" is returned where x is the Hamlib error code.

\n

Example get position (Perl code):

\n

\n
\n

\n
print $socket \"p\\n\";\n\"135\"\n\"10\"
\n

Este protocolo es utilizado principalmente por el backend "NET rotctl" (rotctl modelo 2) que permite a las aplicaciones ya escritas para la API C de Hamlib aprovechar rotctld sin necesidad de reescribir el código de la aplicación. El usuario de una aplicación puede seleccionar el modelo de rotador 2 ("NET rotctl") y luego establecer rot_pathname a "localhost:4533" u otro *host*:*puerto* de red (establecido por las opciones -T/-t, respectivamente, arriba).

Protocolo de Respuesta Extendida

El protocolo de Respuesta Extendida agrega varias reglas a las cadenas devueltas por rotctld y agrega una regla para la sintaxis del comando.

1. El comando recibido por rotctld se repite con su nombre de comando largo seguido de el/los valor(es) (si los hay) recibido(s) del cliente terminado por el separador de respuesta especificado como el primer registro de la respuesta.

2. El último registro de cada bloque es la cadena "RPRT x\n" donde x es el valor de retorno numérico de la función de backend de Hamlib que fue llamada por el comando.

3. Cualquier registro que consista en valores de datos devueltos por el backend del rotador se antepone con una cadena seguida inmediatamente por dos puntos, luego un espacio y luego el valor terminado por el separador de respuesta, por ejemplo, "Azimuth: 90.000000\n" cuando el comando fue antepuesto con '+'.

4. Todos los comandos recibidos serán confirmados por rotctld con registros de las reglas 1 y 2. Los registros de la regla 3 solo se devuelven cuando se deben devolver valores de datos al cliente.

Un ejemplo de respuesta a un comando P enviado desde el prompt de la shell (nota el '+' antepuesto):


$ echo "+P 90 45" | nc -w 1 localhost 4533
set_pos: 90 45
RPRT 0

En este caso, el nombre de comando largo y los valores se devuelven en la primera línea y la segunda línea contiene el marcador de fin de bloque y el valor numérico del backend del rotador que indica éxito.

Un ejemplo de respuesta a una consulta get_pos:


$ echo "+get_pos" | nc -w 1 localhost 4533
get_pos:
Azimuth: 90.000000
Elevation: 45.000000
RPRT 0
Nota: La '\' todavía es necesaria para el nombre de comando largo incluso con el carácter ERP.

En este caso, como no se pasa ningún valor a rotctld, la primera línea consiste solo en el nombre de comando largo. La última línea muestra que el comando fue procesado exitosamente por el backend del rotador.

Invocar el Protocolo de Respuesta Extendida requiere anteponer un comando con un carácter de puntuación. Como se muestra en los ejemplos anteriores, anteponer un '+' al comando da como resultado que las respuestas se separen por un carácter de nueva línea ('\n'). Cualquier otro carácter de puntuación reconocido por la función C ispunct() excepto '\', '?' o '_' hará que ese carácter se convierta en el separador de respuesta y la respuesta completa estará en una sola línea.

Resumen de caracteres separadores:

'+'
Cada registro de la respuesta se antepone con una nueva línea ('\n').
';', '|' o ','
Cada registro de la respuesta se antepone con el carácter dado, resultando en una respuesta completa en una sola línea.
Estos son separadores de registros comunes para representaciones de texto de datos de hojas de cálculo, etc.
'?'
Reservado para ayuda en rotctl.
'_'
Reservado para el comando corto get_info
'#'
Reservado para comentarios al leer un script de archivo de comandos.
Nota: ¡Otros caracteres de puntuación no han sido probados! Úselos bajo su propio riesgo.

Por ejemplo, invocar una consulta get_pos con un ';' precedente devuelve:


get_pos:;Azimuth: 90.000000;Elevation: 45.000000;RPRT 0

O, usando el carácter de barra vertical '|', devuelve:


get_pos:|Azimuth: 90.000000|Elevation: 45.000000|RPRT 0

Y un comando set_pos antepuesto con un '|' devuelve:


set_pos: 135 22.5|RPRT 0

Dicho formato permitirá leer una respuesta como un solo evento utilizando un separador de respuesta preferido. ¡Otros caracteres de puntuación no han sido probados!

Todos los comandos, con la excepción de set_conf, han sido probados con el protocolo de Respuesta Extendida y el script Perl testrotctld.pl incluido.

DIAGNÓSTICOS

La opción -v, --verbose permite diferentes niveles de diagnósticos para ser enviados a stderr y corresponden a -v para BUG, -vv para ERR, -vvv para WARN, -vvvv para VERBOSE, o -vvvvv para TRACE.

Un nivel de verbosidad dado es útil para proporcionar la información de depuración necesaria a la dirección de correo electrónico abajo. Por ejemplo, la salida TRACE muestra todos los valores enviados y recibidos de la radio, lo cual es muy útil para el desarrollo de bibliotecas de backend de radio y puede ser solicitado por los desarrolladores.

EJEMPLOS

Iniciar rotctld para un rotor Hy-Gain Ham IV con la placa RotorEZ de Idiom Press instalada utilizando un adaptador USB a serie y ejecutándose en segundo plano:


$ rotctld -m 401 -r /dev/ttyUSB1 &

Iniciar rotctld para RotorEZ usando COM2 en Win32:


> rotctl -m 401 -r COM2

Conectarse al rotctld ya en ejecución, y establecer la posición a 135.0 grados de acimut y 30.0 grados de elevación con un tiempo de espera de lectura de 1 segundo desde el prompt de la shell:


$ echo "\set_pos 135.0 30.0" | nc -w 1 localhost 4533

Conectarse a un rotctld en ejecución con rotctl en el host local:


$ rotctl -m 2

SEGURIDAD

Sin autenticación alguna; NO deje este puerto TCP abierto a Internet. Por favor, pregunte si se necesita una seguridad más fuerte o considere usar un túnel Secure Shell (ssh(1)).

Dado que rotctld no necesita permisos mayores que rotctl, es aconsejable no iniciar rotctld como "root" u otra cuenta de usuario del sistema para limitar cualquier vulnerabilidad.

ERRORES

El demonio no se está desvinculando ni ejecutando en segundo plano.

No hay método para salir del demonio, por lo que se debe usar el comando kill(1) para terminarlo.

Múltiples clientes que usan el demonio pueden experimentar contención con el rotador conectado.
