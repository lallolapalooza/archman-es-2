ros-template - Editar plantilla para ros-init

sinopsis

•
ros template comando argumentos...

Subcomandos

init nombre-plantilla
Crear nueva plantilla en el directorio local-proyecto.
deinit nombre-plantilla
Eliminar una plantilla del directorio local-proyecto.
list
Mostrar lista de archivos y estados de los archivos tipo permisos reescritura en las plantillas.
checkout [nombre-plantilla]
Cuando se invoca sin nombre-plantilla, este comando muestra candidatos para las plantillas actuales para operar. Si se proporciona nombre-plantilla, este comando elige el nombre como plantilla actual.
add [nombre-plantilla] [archivos ...]
Añadir archivos a la plantilla actual. El primer parámetro puede tomarse como un nombre-plantilla cuando la plantilla actual es default.
cat [nombre-plantilla] [archivos ...]
Mostrar el contenido de la plantilla actual.
edit [nombre-plantilla] [archivos ...]
Editar el contenido de los archivos en la plantilla usando /usr/bin/editor.
path [nombre-plantilla] [archivos ...]
Mostrar la ruta nativa de los archivos en la plantilla.
rm [nombre-plantilla] [archivos ...]
Eliminar archivo de la plantilla actual.
type [nombre-plantilla] [tipo] [archivos ...]
Cambiar el tipo de archivo. Las opciones actuales para los tipos son djula o copy {{nombre}} {{autor}} {{email}} {{universal_time}} son variables disponibles en el archivo de plantilla. Sin archivos, cambia el tipo predeterminado.
chmod [nombre-plantilla] [modo] [archivos ...]
Cambiar los bits de modo del archivo a generar. Especificar el modo en formato octal.
rewrite [nombre-plantilla] archivo regla-reescritura
Cambiar el nombre del archivo usando plantilla Djula. Las variables {{nombre}} {{autor}} {{email}} {{universal_time}} están disponibles para la regla-reescritura.
export [nombre-plantilla] [directorio]
Exportar archivos de la plantilla actual al directorio actual.
import [directorio]
Importar plantilla del directorio actual
help
Mostrar la ayuda del subcomando.

Descripción

El comando ros-template(1) administra plantillas de proyectos.

Crear plantilla

Primero, el subcomando init crea una plantilla vacía.

$ ros template init sample-template

Muchos de los subcomandos toman un nombre de plantilla como primer argumento. Pero puedes omitirlo con los subcomandos checkout. Después de lo siguiente, dichos subcomandos se aplicarán a sample-template.

$ ros template checkout sample-template

Luego, el subcomando add añade archivo(s) local(es) a la plantilla. Después, el subcomando list muestra información de los archivos en la plantilla.

$ echo "Hola {{ autor }}!!" > sample.txt
$ ros template add sample.txt
$ ros template list
      copy  sample.txt

La palabra copy significa una estrategia al aplicar la plantilla. Hay las siguientes 2 estrategias.

•
copy simplemente copia el archivo tal cual.
•
djula procesa el contenido del archivo mediante el motor de plantillas, Djula (http://mmontone.github.io/djula/).
•
Las variables disponibles se explican más adelante.

El subcomando type lo cambia. Además, la estrategia predeterminada (copy) se puede cambiar para cada plantilla con el subcomando type sin nombres de archivo (Ej. ros template type djula).

$ ros template type djula sample.txt
$ ros template list
      djula sample.txt

sample.txt se mostrará simplemente como sample.txt por defecto. Pero puedes cambiarlo con el subcomando rewrite. En el siguiente ejemplo, se mostrará como sample_<nombre del proyecto>.txt.

$ ros template rewrite sample.txt "sample-{{ name }}.txt"
$ ros template list
      djula sample.txt -> "sample-{{ name }}.txt"

Nota: Las reglas de reescritura siempre se procesan mediante Djula independientemente de la estrategia del archivo.

Aplicar plantilla

ros-init(1) puede especificar una plantilla.

$ mkdir temp ; cd temp
$ ros init sample-template some-project
$ ls
sample-some-project.txt
$ cat sample-some-project.txt # Asumiendo que "autor" es "alien"
Hola alien!!

El nombre del archivo y su contenido se procesan mediante Djula como se explicó anteriormente. Las siguientes variables se pueden usar por defecto.

•
{{name}}: Nombre del proyecto especificado en ros-init(1)
•
{{author}}: Nombre del autor extraído de la configuración de Git o whoami
•
{{email}}: Dirección de correo electrónico extraída de la configuración de Git o creada usando whoami y hostname
•
{{universal_time}}: Hora universal creada por la función get-universal-time

Además, puedes usar variables originales como las siguientes.

$ echo "Hola {{ area }}!!" > sample.txt
$ ros template add sample.txt # Nota: Sobrescribe el existente
$ mkdir temp ; cd temp
$ ros init sample-template roswell --area 51
$ cat sample-roswell.txt
Hola 51!!

Exportar e importar plantilla

Básicamente, ros-template(1) está diseñado para administrar internamente los archivos añadidos.

Sin embargo, si deseas, por ejemplo, administrarlo usando Git en un directorio local o instalar plantillas distribuidas, puedes usar los subcomandos export e import.

Primero, el subcomando export exporta los archivos añadidos y un archivo de configuración roswell.init.<nombre-plantilla>.asd que se crea y edita internamente.

$ ros template export dir
$ ls dir
roswell.init.sample-template.asd  sample.txt
$ cat dir/sample.txt
Hola {{ area }}!!

Segundo, el subcomando import los importa.

# Supongamos que esto está en otra máquina...
$ ros template list sample-template # no se muestra nada 
$ ls downloaded
roswell.init.sample-template.asd  sample.txt
$ ros template import downloaded
$ ros template list sample-template
      djula sample.txt -> "sample-{{ name }}.txt"

Nota: Si existe una plantilla con el mismo nombre, será sobrescrita.
