NOMBRE

rollinit - Crea nuevos registros rollrec para un archivo rollrec de DNSSEC-Tools.

SINOPSIS

rollinit [opciones] <nombrezona1> ... <nombrezonaN>

DESCRIPCIÓN

rollinit crea nuevas entradas rollrec para un archivo rollrec. Este archivo rollrec será utilizado por rollerd para gestionar el cambio de claves para las zonas nombradas.

Las entradas rollrec recién generadas se escriben en la salida estándar, a menos que se especifique la opción -out.

Una entrada rollrec tiene este formato:

roll "ejemplo.com"
    zonename        "ejemplo.com"
    zonefile        "ejemplo.com.signed"
    keyrec          "ejemplo.com.krf"
    zonegroup       "zonas-ejemplo"
    kskphase        "0"
    zskphase        "0"
    administrator   "bob@bobhost.ejemplo.com"
    directory       "/var/dns/zones/ejemplo.com"
    loglevel        "phase"
    ksk_rolldate    " "
    ksk_rollsecs    "0"
    zsk_rolldate    " "
    zsk_rollsecs    "0"
    maxttl          "604800"
    display         "1"
    phasestart      "Lun Ene 9 16:00:00 2006"
    # registros opcionales para el cambio RFC5011:
    istrustanchor   "no"
    holddowntime    "60D"

Las palabras clave roll y skip indican si rollerd debe procesar o ignorar una entrada rollrec particular. Los registros roll se crean por defecto; las entradas skip se crean si se especifica la opción -skip.

La línea roll tiene un nombre que se utiliza para distinguirla de todas las demás entradas rollrec en el archivo. El campo zonename se establece en el nombre de la zona. Estos dos datos a menudo son los mismos, pero esto no es obligatorio. rollinit los establecerá con el mismo valor, a menos que se utilice la opción -rollrec.

Los campos zonefile y keyrec se establecen según las opciones y argumentos de la línea de comandos. La forma de generar los valores reales de rollrec es un poco compleja y se describe en la sección CAMPOS ZONEFILE Y KEYREC más abajo.

El campo zonegroup se utiliza para asociar un conjunto de rollrecs, de modo que puedan ser controlados por un único comando rollctl -group. Se pueden especificar varios zonegroups en una lista separada por comas. Se eliminarán los espacios en blanco iniciales y finales, pero se permiten los espacios en blanco internos. Este campo es opcional y rollinit solo lo establece si se especifica la opción -zonegroup. (Aunque esto utiliza el término "zona", en realidad se refiere al nombre de las entradas rollrec).

El campo administrator se establece en la dirección de correo electrónico de la persona (o personas, si la dirección es en realidad una lista de distribución) considerada como la persona responsable de la zona.

El campo directory se establece en el directorio que contiene los archivos de la zona. Estos archivos incluyen el archivo de zona, el archivo de zona firmado y el archivo keyrec.

El campo loglevel se establece en el nivel de mensajes de registro que rollerd debe producir para esta zona. El nivel de registro incluye aquellos mensajes con una prioridad mayor que el nivel especificado, por lo que un nivel de "phase" también incluirá mensajes "err" y "fatal".

Los campos kskphase y zskphase indican la fase de cambio para las claves KSK y ZSK de la zona. El valor 0 indica que la zona está en operación normal (sin cambio) para ese tipo de clave. Una fase distinta de cero (1-7 para KSKs; 1-4 para ZSKs) indica que la zona está en proceso de cambio de claves. Solo uno de estos campos debe ser distinto de cero en un momento dado. Si ambos son cero, no se están realizando operaciones de cambio.

Los campos ksk_rolldate y ksk_rollsecs indican cuándo comenzó el cambio de KSK. Si los valores son espacios en blanco y cero, respectivamente, entonces la zona no está en cambio de KSK.

Los campos zsk_rolldate y zsk_rollsecs indican cuándo comenzó el cambio de ZSK. Si los valores son espacios en blanco y cero, respectivamente, entonces la zona no está en cambio de ZSK.

El campo booleano display indica si blinkenlights debe mostrar información sobre esta zona.

El campo maxttl contiene el valor TTL máximo del archivo de zona.

Los campos phasestart contienen la fecha en que se entró en la fase de cambio actual.

Los archivos rollrec también tienen el campo zsargs que contiene opciones especificadas por el usuario para zonesigner. Este campo se establece durante la ejecución de rollerd cuando el administrador determina que algunos campos de la zona deben modificarse. No es un campo inicial de rollrec y, en consecuencia, no puede ser especificado por rollinit.

El campo istrustanchor especifica si se deben cambiar las claves KSK de manera compatible con cualquier resolvedor de validación remoto que utilice la KSK como ancla de confianza. Si se establece en "yes", entonces 60 días será el tiempo de espera mínimo durante la fase 3 del cambio de KSK para asegurar que los resolvedores remotos puedan seguir correctamente los pasos necesarios según lo especificado por RFC5011. El valor predeterminado de 60 días se puede cambiar a través del campo holddowntime.

INFO ROLLRECS

A partir de la versión 1.15 de DNSSEC-Tools, cada archivo rollrec debe tener un info rollrec. Esta entrada rollrec especial contiene información sobre el propio archivo rollrec y no contiene información de zona. Su contenido no debe ser modificado por nada que no sean las utilidades de DNSSEC-Tools.

CAMPOS ZONEFILE y KEYREC

Los campos zonefile y keyrec pueden ser proporcionados utilizando las opciones -zonefile y -keyrec, o se pueden usar valores predeterminados.

Los valores predeterminados utilizan el nombre de zona del rollrec, tomado de la línea de comandos, como base. Se añade .signed al nombre de zona para el archivo de zona; se añade .krf al nombre de zona para el archivo keyrec.

Si se especifican -zonefile o -keyrec, los valores de las opciones se utilizan de una de las dos maneras:

1. Se proporciona un único nombre de zona en la línea de comandos.
Los valores de las opciones para -zonefile y/o -keyrec se utilizan para los campos reales de rollrec.
2. Se proporcionan varios nombres de zona en la línea de comandos.
Los valores de las opciones para -zonefile y/o -keyrec se utilizan como plantillas para los campos reales de rollrec. Los valores de las opciones deben contener la cadena =. Esta cadena se reemplaza por la zona para la que se está creando el rollrec.

Consulte la sección EJEMPLOS para ver ejemplos de cómo rollinit utiliza las opciones.

OPCIONES

A rollinit se le pueden dar las siguientes opciones:

-rollrec nombre-rollrec
Esto especifica el nombre del registro rollrec. Este valor puede contener espacios. Si esta opción no se especifica, se establecerá con el mismo valor que el campo zonename. Consulte las secciones CAMPOS ZONEFILE Y KEYREC y EJEMPLOS para más detalles.
-zonefile archivo-zona
Esto especifica el valor del campo zonefile. Consulte las secciones CAMPOS ZONEFILE Y KEYREC y EJEMPLOS para más detalles.
-keyrec archivo-keyrec
Esto especifica el valor del campo keyrec. Consulte las secciones CAMPOS ZONEFILE Y KEYREC y EJEMPLOS para más detalles.
-zg zonegroup
-zonegroup zonegroup
Esto especifica el valor del campo zonegroup. Este campo es opcional.
-admin
Esto especifica el valor del campo administrator. Si no se proporciona, no se incluirá un campo administrator para el registro.
-directory
Esto especifica el valor del campo directory. Si no se proporciona, no se incluirá un campo directory para el registro.
-loglevel
Esto especifica el valor del campo loglevel.

NAME

rollinit

initialize roll record database

SYNOPSIS

rollinit [-D] [-h] [-V] [-d dir] [-f file] [-g group] [-z zone …]

DESCRIPTION

The rollinit command creates and initializes a roll record database that may be used by rollerd(8) for zone keying. The roll record database is a set of files named keyrec and rollrec in a specified directory.

If neither the -z nor the -g option is specified, rollinit creates an empty database in the current directory.

Otherwise, rollinit creates roll records for each zone and zonegroup specified.

Zone names are specified using the -z option. Zonegroups are specified using the -g option.

The zone group may be specified as a comma-separated list of zone group names. If a zone is associated with multiple zone groups, the zone group string will be stored as a comma-separated list.

The zonefile and keyrec names are derived from the zone name. They are assumed to be zone.signed and zone.krf respectively.

If the -f option is specified, the database will be created in the file specified.

If the -d option is specified, the database will be created in the directory specified.

If the -D option is specified, the database will be created in the directory /var/db/dnssec-tools.

If the -h option is specified, a help message is printed.

If the -V option is specified, version information is printed.

INFO ROLLRECS

The records are stored in a file named rollrec in the specified directory. The format of the rollrec file is described in file-rollrec.pm(5). The format of the keyrec file is described in file-keyrec.pm(5).

ZONEFILE and KEYREC FIELDS

The zonefile and keyrec fields are optional. If they are not specified, they default to zonename.signed and zonename.krf respectively.

OPTIONS

-D Use default database directory /var/db/dnssec-tools.
-d dir Use the specified directory dir for the database.
-f file Use the specified file file for the database.
-g group Associate the specified zone group group with the specified zones.
-h Print a help message and exit.
-V Print version information and exit.
-z zone Create a roll record for the specified zone zone.

EXAMPLES

Example 14. Two zones, One zonegroup

This example shows the rollrec generated by giving rollinit a set of two zones and a single zonegroup.

$ rollinit -zg "example zones" example1.com example2.com

        zonename        "example1.com"
        zonefile        "example1.com.signed"
        keyrec          "example1.com.krf"
        zonegroup       "example zones"
    roll    "example2.com"
        zonename        "example2.com"
        zonefile        "example2.com.signed"
        keyrec          "example2.com.krf"
        zonegroup       "example zones"

This example shows the rollrec generated by giving rollinit a set of two zonegroups for a single zone.
