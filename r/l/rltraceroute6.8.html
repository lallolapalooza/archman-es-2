TRACEROUTE6(8) Manual del Administrador del Sistema TRACEROUTE6(8)

NOMBRE

rltraceroute6 - herramienta traceroute para IPv6

tcptraceroute6 - herramienta traceroute TCP/IPv6

SINOPSIS

traceroute6 [-AdEILlnrSU] [-f min_hop] [-g hop] [ -i iface] [-m max_hop] [-p port] [-q intentos] [ -s origen] [-t tclass] [-w espera] [-z delay_ms] < nombrehost/dirección> [longitud paquete]

tcptraceroute6 [-AdEnrS] [-f min_hop] [-g hop] [ -i iface] [-l tamaño_paquete] [-m max_hop] [-p puerto] [ -q intentos] [-s origen] [-t tclass] [-w espera] [ -z delay_ms] < nombrehost/dirección> [puerto]

DESCRIPCIÓN

rltraceroute6 es una implementación de traceroute para IPv6.

Muestra la lista de saltos a lo largo de la ruta de red entre el sistema local y el destino especificado, enviando paquetes mientras se incrementa su límite de saltos, hasta que se alcanza el destino final.

Por defecto, rltraceroute6 envía paquetes de sondeo UDP hacia el destino (ese es el valor predeterminado histórico). Sin embargo, también puede enviar paquetes TCP, de manera muy similar a como lo hace tcptraceroute de Michael C. Toren en redes IPv4; tcptraceroute6 envía paquetes TCP por defecto (y imita la sintaxis de línea de comandos de tcptraceroute). Finalmente, también puede enviar paquetes ICMPv6 Echo Request, como algunas otras implementaciones de traceroute (como la del sistema Microsoft Windows); tracert6 lo hace por defecto.

Debe especificar el nombre o la dirección del host hacia el cual se debe determinar la ruta de red. Un parámetro adicional opcional especifica ya sea la longitud de los paquetes de sondeo (para paquetes UDP e ICMP), o el número de puerto/nombre de servicio de destino (para paquetes TCP).

Tenga en cuenta que el puerto de destino TCP cero es realmente el puerto TCP número 0 (que no se puede usar a través de la interfaz de programación TCP/IP de nivel superior estándar).

OPCIONES

-A
Envía paquetes de sondeo TCP/ACK. Esto es muy eficiente contra firewalls sin estado (por ejemplo, las versiones oficiales del kernel de Linux hasta la 2.4.31 y 2.6.14 inclusive), y completamente inútil contra los que tienen estado. Tenga en cuenta que el sondeo TCP/ACK no puede determinar si el puerto TCP de destino está abierto o no.
-d
Habilita la opción de depuración de sockets (SO_DEBUG). A menos que esté depurando el kernel, esto probablemente no tendrá ningún efecto real.
-E
Envía paquetes de sondeo TCP/SYN de *ECN-setup* (según RFC 3168) en lugar de paquetes de sondeo TCP/SYN sin ECN-setup. Esto no tiene efecto a menos que también se especifique la opción de línea de comandos -S.
-F
Esta opción se ignora por compatibilidad hacia atrás. Los paquetes IPv6 nunca se fragmentan en tránsito.
-f
Anula el límite de saltos inicial de los paquetes IPv6 (predeterminado: 1).
-g
Agrega un segmento de ruta IPv6 dentro de una Cabecera de Enrutamiento IPv6. Esto permite el enrutamiento de origen flexible. Actualmente, solo se soporta la cabecera de enrutamiento de "Tipo 0".
-h
Muestra ayuda y sale.
-I (solo rltraceroute6)
Envía paquetes de sondeo ICMPv6 Echo (como ping6). Esa es la opción predeterminada para tracert6.
-i
Envía paquetes solo a través de la interfaz especificada. Ver también BUGS.
-I (solo rltraceroute6)
Envía paquetes UDP-Lite (protocolo 136) (con cobertura completa de suma de verificación) como paquetes de sondeo en lugar de UDP normal (protocolo 17).
-l (solo rltraceroute6)
Imprime el límite de saltos de los paquetes recibidos. Esto se usa principalmente para detectar enrutamiento asimétrico.
-l (solo tcptraceroute6)
Especifica el tamaño (en bytes) de los paquetes enviados.
-m
Anula el límite de saltos máximo (número máximo de saltos). El valor predeterminado es 30 saltos, lo que debería ser suficiente en Internet IPv6 durante algún tiempo.
-N
Intenta resolver la dirección IPv6 de cada salto a un nombre de host. Esta es la opción predeterminada. Esta opción está pensada para compatibilidad hacia atrás con tcptraceroute(8).
-n
No intente resolver la dirección IPv6 de cada salto a un nombre de host. Esto puede acelerar significativamente el traceroute.
-p
Para rltraceroute6, especifica el número de puerto de destino base (predeterminado: 33434). rltraceroute6 asume que los paquetes hacia este puerto hasta este puerto más el límite de saltos máximo no están en uso por ningún programa en el destino final y que no están bloqueados por ningún firewall. El hecho de que esta suposición no siempre fuera correcta, llevó finalmente al desarrollo del tcptraceroute original para IPv4 por Michael Toren.

Para tcptraceroute6, especifica el número de puerto de origen (predeterminado: automático). Tenga en cuenta que el número de puerto de origen cero realmente significa el número cero, en lugar de algún número de puerto que se asignaría automáticamente, como es el caso de los programas habituales.

-q
Anula el número de sondeos enviados a cada salto (predeterminado: 3).
-r
No enrutar paquetes, es decir, no enviar paquetes a través de una puerta de enlace que se especificaría en la tabla de enrutamiento. Ver también BUGS.
-S
Utiliza paquetes de sondeo TCP/SYN. Esa es la opción predeterminada para tcptraceroute6.
-s
Especifica explícitamente la dirección de origen a utilizar para los paquetes de sondeo.
-S
Utiliza paquetes de sondeo UDP. Esa es la opción predeterminada para rltraceroute6.
-t
Especifica la clase de tráfico (DSCP) para los paquetes de sondeo. Ver también BUGS.
-U (solo rltraceroute6)
Envía paquetes de sondeo UDP. Esa es la opción predeterminada.
-V
Muestra la versión del programa y la licencia y sale.
-w
Anula el retardo (en segundos) a esperar por una respuesta una vez enviado un paquete de sondeo dado (predeterminado: 5 segundos).
-x
Esta opción se ignora para una migración sin problemas desde traceroute IPv4. La cabecera IPv6 no tiene campo de suma de verificación.
-z
Especifica un retardo en milisegundos a esperar entre cada sondeo con un límite de saltos idéntico. Esto puede ser útil para evitar la limitación de velocidad de ICMPv6 en algunos hosts.

DIAGNÓSTICOS

Si se recibe una respuesta, se imprime el tiempo de ida y vuelta. Además, símbolos específicos denotan ciertos errores:

* Sin respuesta
No se recibió ninguna respuesta válida antes del retardo de tiempo de espera (ver opción -w).
!N No hay ruta al destino
No hay entrada para la red de destino en la tabla de enrutamiento.
!A Comunicación con el destino prohibida administrativamente
Un firewall rechazó explícitamente el tráfico.
!S Fuera del alcance de la dirección de origen
El alcance de la dirección de origen es demasiado pequeño para alcanzar la dirección de destino. En el momento de escribir esto, esto solo puede ocurrir cuando se usa una dirección de origen de enlace local para alcanzar un destino de alcance global. (Nota: algunas implementaciones de traceroute para IPv4 usan !S para error de ruta de origen, lo cual es completamente diferente)
!H Dirección inalcanzable
La dirección del host no es alcanzable por otras razones, particularmente un fallo en la capa de enlace (por ejemplo, fallo en el descubrimiento de vecinos).
!P Se encontró un tipo de Cabecera Siguiente no reconocido
El destino no implementa el protocolo de capa 4 utilizado. Deberías intentarlo de nuevo con Solicitudes de Eco ICMPv6 (-I coma

OPTIONS

-g gateway
Specify a gateway. This option can be given multiple times. Gateway addresses are added to the IPv6 Routing Header. This option requires the traceroute6(8) to run with the capability to create Routing Headers. On Linux, this requires the kernel to be compiled with the CONFIG_IP6_NF_TARGET_MASQUERADE option enabled and the use of the traceroute6(8) program to be setuid root or the user running the program must have the CAP_NET_RAW capability. The default IPv6 Routing Header is type 0, which MUST be supported by any IPv6 node.

SEGURIDAD

rltraceroute6 debe configurarse como setuid root para permitir su uso por usuarios no privilegiados. Perderá sus privilegios de root antes de cualquier intento de enviar o recibir datos de la red, con el fin de reducir el posible impacto de una vulnerabilidad de seguridad.

ERRORES

Aunque puedan ser útiles, las opciones -i y -r son ignoradas por el kernel oficial de Linux en el momento de escribir esta página man, y por lo tanto no funcionan como se documenta.

El soporte para la opción -t estuvo roto hasta la versión 2.6.18 del kernel de Linux.

El uso de la Cabecera de Enrutamiento, con la opción -g, desencadena un OOPS en las versiones del kernel de Linux anteriores a la 2.6.17.12.

La recepción de paquetes TCP/SYN-ACK no funciona en absoluto en FreeBSD. Esto limita severamente la utilidad de tcptraceroute6 en FreeBSD.

La longitud del paquete tiene en cuenta la cabecera IPv6 y, si está presente, las cabeceras de extensión. Las versiones de rltraceroute6 anteriores a la 0.7.4 la usaban en su lugar como longitud de la carga útil IPv6, es decir, no incluían las cabeceras de capa 3 en el cálculo. El traceroute6 de iputils de Linux ni siquiera incluye la cabecera UDP. En general, la semántica de la longitud del paquete es muy inconsistente entre las implementaciones de traceroute IPv6.
