NOMBRE

rndc - utilidad de control del servidor de nombres

SINOPSIS

rndc [-b dirección-origen] [-c archivo-config] [-k archivo-clave] [-s servidor] [-p puerto] [-q] [-r] [-V] [-y clave-servidor] [[-4] | [-6]] {comando}

DESCRIPCIÓN

rndc controla el funcionamiento de un servidor de nombres. Si rndc se invoca sin opciones o argumentos de línea de comandos, imprime un resumen corto de los comandos soportados y las opciones disponibles y sus argumentos.

rndc se comunica con el servidor de nombres a través de una conexión TCP, enviando comandos autenticados con firmas digitales. En las versiones actuales de rndc y named <#std-iscman-named>, los únicos algoritmos de autenticación soportados son HMAC-MD5 (para compatibilidad), HMAC-SHA1, HMAC-SHA224, HMAC-SHA256 (predeterminado), HMAC-SHA384 y HMAC-SHA512. Utilizan un secreto compartido en cada extremo de la conexión, que proporciona autenticación estilo TSIG para la solicitud de comando y la respuesta del servidor de nombres. Todos los comandos enviados a través del canal deben ser firmados por una clave-servidor conocida por el servidor.

rndc lee un archivo de configuración para determinar cómo contactar al servidor de nombres y decidir qué algoritmo y clave debe usar.

OPCIONES

-4
Esta opción indica usar solo IPv4.
-6
Esta opción indica usar solo IPv6.
-b dirección-origen
Esta opción indica dirección-origen como la dirección de origen para la conexión al servidor. Se permiten múltiples instancias, para permitir la configuración de las direcciones de origen IPv4 e IPv6.
-c archivo-config
Esta opción indica archivo-config como el archivo de configuración en lugar del predeterminado, /etc/rndc.conf.
-k archivo-clave
Esta opción indica archivo-clave como el archivo de clave en lugar del predeterminado, /etc/rndc.key. La clave en /etc/rndc.key se usa para autenticar los comandos enviados al servidor si el archivo-config no existe.
-s servidor
servidor es el nombre o la dirección del servidor que coincide con una declaración de servidor en el archivo de configuración para rndc. Si no se proporciona ningún servidor en la línea de comandos, se utiliza el host nombrado por la cláusula default-server en la declaración options del archivo de configuración de rndc.
-p puerto
Esta opción indica a BIND 9 que envíe comandos al puerto TCP puerto en lugar de su puerto de canal de control predeterminado, 953.
-q
Esta opción establece el modo silencioso, donde el texto del mensaje devuelto por el servidor no se imprime a menos que haya un error.
-r
Esta opción instruye a rndc a imprimir el código de resultado devuelto por named <#std-iscman-named> después de ejecutar el comando solicitado (por ejemplo, ISC_R_SUCCESS, ISC_R_FAILURE, etc.).
-t tiempo de espera
Esta opción establece el período de tiempo de espera inactivo para rndc a tiempo de espera segundos. El valor predeterminado es 60 segundos, y el valor máximo configurable es 86400 segundos (1 día). Si se establece en 0, no hay tiempo de espera.
-V
Esta opción habilita el registro detallado.
-y clave-servidor
Esta opción indica el uso de la clave clave-servidor del archivo de configuración. Para que la validación del mensaje de control tenga éxito, clave-servidor debe ser conocida por named <#std-iscman-named> con el mismo algoritmo y cadena secreta. Si no se especifica ninguna clave-servidor, rndc primero busca una cláusula de clave en la declaración del servidor del servidor que se está utilizando, o si no hay una declaración de servidor presente para ese host, entonces en la cláusula clave-predeterminada de la declaración options. Tenga en cuenta que el archivo de configuración contiene secretos compartidos que se utilizan para enviar comandos de control autenticados a los servidores de nombres, y por lo tanto, no deben tener acceso general de lectura o escritura.

COMANDOS

Se puede ver una lista de los comandos soportados por rndc ejecutando rndc sin argumentos.

Los comandos actualmente soportados son:

addzone zona [clase [vista]] configuración
Este comando agrega una zona mientras el servidor se está ejecutando. Este comando requiere que la opción allow-new-zones esté configurada en yes. La cadena de configuración especificada en la línea de comandos es el texto de configuración de zona que normalmente se colocaría en named.conf <#std-iscman-named.conf>.

La configuración se guarda en un archivo llamado nombrevista.nzf (o, si named <#std-iscman-named> se compila con liblmdb, un archivo de base de datos LMDB llamado nombrevista.nzd). nombrevista es el nombre de la vista, a menos que el nombre de la vista contenga caracteres incompatibles con su uso como nombre de archivo, en cuyo caso se usa un hash criptográfico del nombre de la vista en su lugar. Cuando named <#std-iscman-named> se reinicia, el archivo se carga en la configuración de la vista para que las zonas que fueron agregadas puedan persistir después de un reinicio.

Este comando de ejemplo addzone agrega la zona example.com a la vista predeterminada:

rndc addzone example.com '{ type primary; file "example.com.db"; };'

(¡Observe los corchetes alrededor y el punto y coma después del texto de configuración de la zona!)

Ver también rndc delzone y rndc modzone.

delzone [-clean] zona [clase [vista]]
Este comando elimina una zona mientras el servidor se está ejecutando.

Si se especifica el argumento -clean, el archivo maestro de la zona (y el archivo de diario, si lo hay) se eliminan junto con la zona. Sin la opción -clean, los archivos de zona deben eliminarse manualmente. (Si la zona es de tipo secondary o stub, los archivos que necesitan ser eliminados se informan en la salida del comando rndc delzone.)

Si la zona se agregó originalmente a través de rndc addzone, entonces se elimina permanentemente. Sin embargo, si se configuró originalmente en named.conf <#std-iscman-named.conf>, esa configuración original permanece en su lugar; cuando el servidor se reinicia o se reconfigura, la zona se vuelve a crear. Para eliminarla permanentemente, también debe ser eliminada de named.conf <#std-iscman-named.conf>.

Ver también rndc addzone y rndc modzone.

dnssec (-status | -step | -rollover -key id [-alg algoritmo] [-when tiempo] | -checkds [-key id [-alg algoritmo]] [-when tiempo] publicado | retirado)) zona [clase [vista]]
Este comando permite interactuar con la "dnssec-policy" de una zona dada.

rndc dnssec -status muestra el estado de firma DNSSEC para la zona especificada.

rndc dnssec -step envía una señal a una instancia de named <#std-iscman-named> para una zona configurada con dnssec-policy en modo manual, indicándole que continúe con las operaciones que previamente habían sido bloqueadas pero registradas. Esto da al operador humano la oportunidad de revisar los mensajes de registro, comprender lo que sucederá a continuación y luego, usando rndc dnssec -step, informar a named <#std-iscman-named> que proceda a la siguiente etapa.

rndc dnssec -roll

addzone zone [class [view]] configuration
This command adds a new zone to the server. It requires that the allow-new-zones option be set to yes. The zone configuration string is the text that would normally be placed in named.conf for the zone.

The zone is added to the running server, and the change is recorded in the configuration journal. The zone is added to the configuration file when the server is next reconfigured or restarted.

See also rndc delzone and rndc modzone.

delzone zone [class [view]]
This command removes a zone from the server. It requires that the allow-new-zones option be set to yes. The zone is removed from the running server, and the change is recorded in the configuration journal. The zone is removed from the configuration file when the server is next reconfigured or restarted.

See also rndc addzone and rndc modzone.

dumpdb [-all | -cache | -zones | -adb | -bad | -expired | -fail] [view ...]
This command dumps the server's caches (default) and/or zones to the dump file for the specified views. If no view is specified, all views are dumped. (See the dump-file option in the BIND 9 Administrator Reference Manual.)
loadkeys [zone [class [view]]]
This command fetches all DNSSEC keys for the given zone from the key directory. If they are within their publication period, they are merged into the zone's DNSKEY RRset. Unlike rndc sign, however, the zone is not immediately re-signed by the new keys, but is allowed to incrementally re-sign over time.

This command requires that the zone be configured with a dnssec-policy, and also requires the zone to be configured to allow dynamic DNS. (See "Dynamic Update Policies" in the Administrator Reference Manual for more details.)

managed-keys (status | refresh | sync | destroy) [class [view]]
This command inspects and controls the "managed-keys" database which handles RFC 5011 https://datatracker.ietf.org/doc/html/rfc5011 DNSSEC trust anchor maintenance. If a view is specified, these commands are applied to that view; otherwise, they are applied to all views.
  • When run with the status keyword, this prints the current status of the managed-keys database.
  • When run with the refresh keyword, this forces an immediate refresh query to be sent for all the managed keys, updating the managed-keys database if any new keys are found, without waiting the normal refresh interval.
  • When run with the sync keyword, this forces an immediate dump of the managed-keys database to disk (in the file managed-keys.bind or (viewname.mkeys). This synchronizes the database with its journal file, so that the database's current contents can be inspected visually.
  • When run with the destroy keyword, the managed-keys database is shut down and deleted, and all key maintenance is terminated. This command should be used only with extreme caution.

    Existing keys that are already trusted are not deleted from memory; DNSSEC validation can continue after this command is used. However, key maintenance operations cease until named <#std-iscman-named> is restarted or reconfigured, and all existing key maintenance states are deleted.

    Running rndc reconfig or restarting named <#std-iscman-named> immediately after this command causes key maintenance to be reinitialized from scratch, just as if the server were being started for the first time. This is primarily intended for testing, but it may also be used, for example, to jumpstart the acquisition of new keys in the event of a trust anchor rollover, or as a brute-force repair for key maintenance problems.

modzone zone [class [view]] configuration
This command modifies the configuration of a zone while the server is running. This command requires the allow-new-zones option to be set to yes. As with addzone, the configuration string specified on the command line is the zone configuration text that would ordinarily be placed in named.conf <#std-iscman-named.conf>.

If the zone was originally added via rndc addzone, the configuration changes are recorded permanently and are still in effect after the server is restarted or reconfigured. However, if it was originally configured in named.conf <#std-iscman-named.conf>, then that original configuration remains in place; when the server is restarted or reconfigured, the zone reverts to its original configuration. To make the changes permanent, it must also be modified in named.conf <#std-iscman-named.conf>.

See also rndc addzone and rndc delzone.

notify zone [class [view]]
This command resends NOTIFY messages for the zone.
over [zone [class [view]]] key-id
This command allows you to schedule key rollover for a specific key (overriding the original key lifetime).
reconfig [-v]
This command causes the server to reload its configuration file. If the configuration file has changed, then all zones are re-added to the server. If -v is specified, then the zone configuration is also re-read. This is useful if the zone configuration has changed, but the zone itself has not.
refresh zone [class [view]]
This command causes the server to re-read the zone file for the specified zone. The zone is reloaded from the zone file, and any changes made to the zone file since it was last loaded are incorporated into the server's database.

This command is only useful for zones that are loaded from files. For dynamically updated zones, use rndc reload.

reload [zone [class [view]]]
This command causes the server to reload the specified zone. If no zone is specified, then all zones are reloaded. This command is primarily intended for dynamically updated zones, as it causes the server to re-read the zone from its journal file if it has been updated.
reopen
This command causes the server to close and re-open all of its output files, including the log files and the core dump file. This is useful for allowing log files to be renamed or rotated externally.
sign zone [class [view]]
This command causes the specified zone to be signed. If no zone is specified, then all zones are signed.

This command requires that the zone be configured with a dnssec-policy, and also requires the zone to be configured to allow dynamic DNS. (See "Dynamic Update Policies" in the Administrator Reference Manual for more details.)

sigchase domain [class [view]]
This command traces the chain of DNSSEC signatures from the specified domain up to a trust anchor. It prints the names of the keys and the zones that are involved in the chain. This is useful for diagnosing DNSSEC validation failures.
stop [-p]
This command causes the server to shut down gracefully. Recent changes made through dynamic update or IXFR are saved to the master files before the server exits. If -p is specified, named <#std-iscman-named>'s process ID is returned. This allows an external process to determine when named <#std-iscman-named> has completed shutting down.

See also rndc halt.

thaw [zone [class [view]]]
This command resumes updates to a dynamic zone that was previously frozen with rndc freeze. If no zone is specified, then all zones are thawed.

See also rndc freeze.

trace
This command sets the server's debugging level to 1. This causes the server to print debugging information to the log file for all queries that it processes.

See also rndc notrace.

validation (on | off) [class [view]]
This command enables or disables DNSSEC validation for the specified view. If no view is specified, then validation is enabled or disabled for all views.
waitsec [view]
This command returns the number of seconds that the server will wait before sending a second query to a server that previously failed to respond. This is controlled by the max-stale-median-ttl and max-recursion-depth options in named.conf.
checkds
This command informs named <#std-iscman-named> that the DS for a specified zone's key-signing key has been confirmed to be published in, or withdrawn from, the parent zone. This is required in order to complete a KSK rollover. The -key id and -alg algorithm arguments can be used to specify a particular KSK, if necessary; if there is only one key acting as a KSK for the zone, these arguments can be omitted. The time of publication or withdrawal for the DS is set to the current time by default, but can be overridden to a specific time with the argument -when time, where time is expressed in YYYYMMDDHHMMSS notation.
dnstap (-reopen | -roll [number])
This command closes and re-opens DNSTAP output files.

rndc dnstap -reopen allows the output file to be renamed externally, so that named <#std-iscman-named> can truncate and re-open it.

rndc dnstap -roll causes the output file to be rolled automatically, similar to log files. The most recent output file has ".0" appended to its name; the previous most recent output file is moved to ".1", and so on. If number is specified, then the number of backup log files is limited to that number.

fetchlimit [view]
This command dumps a list of servers that are currently being rate-limited as a result of fetches-per-server settings, and a list of domain names that are currently being rate-limited as a result of fetches-per-zone settings.
flush
This command flushes the server's cache.
flushname name [view]
This command flushes the given name from the view's DNS cache and, if applicable, from the view's nameserver address database, bad server cache, and SERVFAIL cache.
flushtree name [view]
This command flushes the given name, and all of its subdomains, from the view's DNS cache, address database, bad server cache, and SERVFAIL cache.
freeze [zone [class [view]]]
This command suspends updates to a dynamic zone. If no zone is specified, then all zones are suspended. This allows manual edits to be made to a zone normally updated by dynamic update, and causes changes in the journal file to be synced into the master file. All dynamic update attempts are refused while the zone is frozen.

See also rndc thaw.

halt [-p]
This command stops the server immediately. Recent changes made through dynamic update or IXFR are not saved to the master files, but are rolled forward from the journal files when the server is restarted. If -p is specified, named <#std-iscman-named>'s process ID is returned. This allows an external process to determine when named <#std-iscman-named> has completed halting.

See also rndc stop.

skr -import file zone [class [view]]
This command allows you to import a SKR file for the specified zone, to support offline KSK signing.
memprof [(on | off | dump)]
This command controls memory profiling. To have any effect, named <#std-iscman-named> must be built with jemalloc, the library have profiling support enabled and run with the prof:true allocator configuration. (either via MALLOC_CONF or /etc/malloc.conf)

The prof_active:false option is recommended to ensure the profiling overhead does not affect named <#std-iscman-named> when not needed.

The on and off options will start and stop the jemalloc memory profiling respectively. When run with the dump option, named <#std-iscman-named> will dump the profile to the working directory. The name will be chosen automatically by jemalloc.

nta [(-class class | -dump | -force | -remove | -lifetime duration)] domain [view]
This command sets a DNSSEC negative trust anchor (NTA) for domain, with a lifetime of duration. The default lifetime is configured in named.conf <#std-iscman-named.conf> via the nta-lifetime option, and defaults to one hour. The lifetime cannot exceed one week.

A negative trust anchor selectively disables DNSSEC validation for zones that are known to be failing because of misconfiguration rather than an attack. When data to be validated is at or below an active NTA (and above any other configured trust anchors), named <#std-iscman-named> aborts the DNSSEC validation process and treats the data as insecure rather than bogus. This continues until the NTA's lifetime has elapsed.

rndc signing -nsec3param establece los parámetros NSEC3 para una zona. Este es el único mecanismo soportado para usar NSEC3 con zonas de firma en línea. Los parámetros se especifican en el mismo formato que un registro de recursos NSEC3PARAM: algoritmo hash, flags, iteraciones y salt, en ese orden.

Actualmente, el único valor definido para algoritmo hash es 1, que representa SHA-1. Los flags pueden establecerse en 0 o 1, dependiendo de si el bit de exclusión (opt-out) en la cadena NSEC3 debe estar establecido. iteraciones define el número de veces adicionales que se aplicará el algoritmo al generar un hash NSEC3. La salt es una cadena de datos expresada en hexadecimal, un guión (-) si no se va a usar ninguna salt, o la palabra clave auto, que hace que named <#std-iscman-named> genere una salt aleatoria de 64 bits.

La única configuración recomendada es rndc signing -nsec3param 1 0 0 - zona, es decir, sin salt, sin iteraciones adicionales, sin exclusión (opt-out).

Advertencia:

No utilice iteraciones, salt o exclusión adicionales a menos que todas sus implicaciones se comprendan completamente. Un mayor número de iteraciones causa problemas de interoperabilidad y expone a los servidores a ataques de denegación de servicio (DoS) que agotan la CPU.

rndc signing -nsec3param none elimina una cadena NSEC3 existente y la reemplaza por NSEC.

rndc signing -serial valor establece el número de serie de la zona a valor. Si el valor causara que el número de serie retrocediera, se rechaza. El uso principal de este parámetro es establecer el número de serie en zonas con firma en línea.

stats
Este comando escribe estadísticas del servidor en el archivo de estadísticas. (Consulte la opción statistics-file en el Manual de Administración de BIND 9.)
status
Este comando muestra el estado del servidor. Tenga en cuenta que el número de zonas incluye la zona interna bind/CH y la zona de sugerencias predeterminada ./IN, si no hay una zona raíz configurada explícitamente.
stop -p
Este comando detiene el servidor, asegurándose de que los cambios recientes realizados a través de actualizaciones dinámicas o IXFR se guarden primero en los archivos maestros de las zonas actualizadas. Si se especifica -p, se devuelve el ID de proceso de named <#std-iscman-named>. Esto permite que un proceso externo determine cuándo named <#std-iscman-named> ha completado la detención.

Vea también rndc halt.

sync -clean [zona [clase [vista]]]
Este comando sincroniza los cambios en el archivo de registro (journal) de una zona dinámica con el archivo maestro. Si se especifica la opción "-clean", también se elimina el archivo de registro. Si no se especifica ninguna zona, se sincronizan todas las zonas.
tcp-timeouts [inicial inactivo keepalive anunciado]
Cuando se llama sin argumentos, este comando muestra los valores actuales de las opciones tcp-initial-timeout, tcp-idle-timeout, tcp-keepalive-timeout y tcp-advertised-timeout. Cuando se llama con argumentos, estos valores se actualizan. Esto permite a un administrador realizar ajustes rápidos bajo un ataque de denegación de servicio (DoS). Consulte las descripciones de estas opciones en el Manual de Administración de BIND 9 para obtener detalles sobre su uso.
thaw [zona [clase [vista]]]
Este comando habilita las actualizaciones en una zona dinámica congelada. Si no se especifica ninguna zona, se habilitan todas las zonas congeladas. Esto hace que el servidor recargue la zona desde el disco y vuelva a habilitar las actualizaciones dinámicas después de que la carga se haya completado. Después de descongelar una zona, las actualizaciones dinámicas ya no se rechazan. Si la zona ha cambiado y se está utilizando la opción ixfr-from-differences, el archivo de registro se actualiza para reflejar los cambios en la zona. De lo contrario, si la zona ha cambiado, se elimina cualquier archivo de registro existente. Si no se especifica ninguna zona, la recarga se realiza de forma asíncrona.

Vea también rndc freeze.

trace [nivel]
Si no se especifica ningún nivel, este comando incrementa el nivel de depuración del servidor en uno.
nivel
Si se especifica, este comando establece el nivel de depuración del servidor al valor proporcionado.

Vea también rndc notrace.

validation (on | off | status) [vista ...]
Este comando habilita, deshabilita o comprueba el estado actual de la validación DNSSEC. Por defecto, la validación está habilitada.

La caché se vacía cuando la validación se activa o desactiva para evitar el uso de datos que puedan diferir entre los estados.

zonestatus zona [clase [vista]]
Este comando muestra el estado actual de la zona dada, incluyendo el nombre del archivo maestro y cualquier archivo de inclusión del que se cargó, cuándo se cargó por última vez, el número de serie actual, el número de nodos, si la zona soporta actualizaciones dinámicas, si la zona está firmada con DNSSEC, si utiliza gestión automática de claves DNSSEC o firma en línea, y los tiempos programados de actualización o caducidad para la zona.

Vea también rndc showzone.

Los comandos rndc que especifican nombres de zona, como reload, retransfer o zonestatus, pueden ser ambiguos cuando se aplican a zonas de tipo redirect. Las zonas de redirección siempre se denominan . y pueden confundirse con zonas de tipo hint o con copias secundarias de la zona raíz. Para especificar una zona de redirección, utilice el nombre especial de zona -redirect, sin un punto final. (Con un punto final, esto especificaría una zona llamada "-redirect".)

LIMITACIONES

Actualmente no hay forma de proporcionar la clave secreta compartida para una server_key sin usar el archivo de configuración.

Varios mensajes de error podrían ser más claros.
