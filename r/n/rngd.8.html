NOMBRE

rngd - Comprueba y proporciona datos aleatorios del dispositivo de hardware al dispositivo aleatorio del kernel

SINOPSIS

rngd [-b, --background] [-f, --foreground] [-d, --debug] [-l, --list] [-x, --exclude] [-n, --include] [-O, --option] [-i, --ignorefail] [-o, --random-device=archivo] [-p, --pid-file=archivo] [-r, --rng-device=archivo] [-s, --random-step=nnn] [-t, --test] [-W, --fill-watermark=nnn] [-R, --force-reseed=nnn] [-u, --use-slow-sources] [-D, --drop-privileges=usuario:grupo] [-q, --quiet] [-?, --help] [-v, --version]

DESCRIPCIÓN

Este demonio proporciona datos de un generador de números aleatorios al pool de entropía del kernel, después de verificar primero que los datos sean realmente aleatorios.

Las opciones -f o --foreground se pueden usar para indicar a rngd que evite la bifurcación al iniciar. Esto se usa típicamente para depuración. Las opciones -b o --background, que realizan la bifurcación y ponen a rngd en segundo plano automáticamente, son las predeterminadas.

Las opciones -r o --rng-device se pueden usar para seleccionar una fuente de entrada alternativa, además de la predeterminada /dev/hwrng. Las opciones -o o --random-device se pueden usar para seleccionar un dispositivo de salida de entropía alternativo, además de la predeterminada /dev/random. Tenga en cuenta que este dispositivo debe soportar la API de ioctl de /dev/random del kernel de Linux.

OPCIONES

-b, --background
Convertirse en un demonio (predeterminado)
-f, --foreground
No bifurcar y convertirse en un demonio
-d, --debug
Habilitar mensajes de depuración
-l, --list
Listar los índices y nombres de las fuentes de entropía disponibles. El código de salida al listar fuentes es 0 si se encontró e inicializó al menos 1 fuente de entropía, 1 en caso contrario.
-x, --exclude
Deshabilitar fuentes de entropía basadas en el índice o (nombre corto) informado por la opción --list
-n, --include
Habilitar fuentes de entropía basadas en el índice o (nombre corto) informado por la opción --list
-O, --option
Proporcionar opciones de configuración específicas para fuentes de entropía individuales, en el formato --option [índice|nombre corto]:clave:valor. Consulte la sección Fuentes de Entropía a continuación para ver los índices y las opciones específicas de la fuente. Tenga en cuenta que al especificar -O [<índice>|<nombre corto>] se imprimirán las opciones disponibles para ese índice en la consola.
-p archivo, --pid-file=archivo
Archivo utilizado para registrar el PID del demonio y exclusiones múltiples (predeterminado: /var/run/rngd.pid)
-i, --ignorefail
Ignorar fallos repetidos de fips
-o archivo, --random-device=archivo
Dispositivo del kernel utilizado para la salida de números aleatorios (predeterminado: /dev/random)
-r archivo, --rng-device=archivo
Dispositivo del kernel utilizado para la entrada de números aleatorios (predeterminado: /dev/hwrng)
-s nnn, --random-step=nnn
Número de bytes escritos en random-device a la vez (predeterminado: 64)
-t, --test
Entrar en modo de prueba. En este modo (que implica -f), toda la entropía generada se descarta y rngd informa la cantidad de entropía generada cada segundo.
-e nnn, --entropy-count=nnn
Número de bits a considerar aleatorios al agregar entropía. 1<=e<=8 (predeterminado: 8)
-W n, --fill-watermark=nnn
Una vez que comenzamos a hacerlo, proporcionamos entropía a random-device hasta que haya al menos fill-watermark bits de entropía disponibles en su pool de entropía. Por defecto, este valor se establece en el 75% del tamaño del pool de entropía o 2048 bits si no se pudo determinar el tamaño del pool de entropía. Establecer esto demasiado alto hará que rngd domine el contenido del pool de entropía. Valores bajos perjudicarán el rendimiento del sistema durante las escaseces de entropía. No establezca fill-watermark por encima del tamaño del pool de entropía (normalmente 256 bits). Un valor de 0 en esta opción no establecerá ninguna marca de agua.
-R n, --force-reseed=nnn
Para kernels más nuevos que soportan pools de entropía no bloqueantes, sigue siendo beneficioso agregar periódicamente entropía fresca como un evento de resemillado. --force-reseed define el número de segundos entre los cuales se agrega entropía fresca al pool de entropía del kernel. El valor predeterminado es de 5 minutos.
-u, --use-slow-sources
Las fuentes de entropía nist, jitter y pkcs11 se consideran lentas para proporcionar entropía. Por defecto, sus datos solo se utilizan después de que todas las demás fuentes hayan fallado en proporcionar entropía válida 100 veces. Con esta opción, rngd siempre intenta obtener entropía de estas fuentes también.
-D, --drop-privileges=usuario:grupo
Reducir privilegios a un usuario y grupo especificados después de la inicialización. Se puede especificar un usuario y un grupo como nombre o como ID numérico y deben estar separados por dos puntos. Debe existir un usuario y un grupo. Por defecto, no se reducen los privilegios.
-q, --quiet
Suprimir todos los mensajes
-?, --help
Proporcionar un resumen corto de todas las opciones del programa
-v, --version
Mostrar la versión del programa

FUENTES DE ENTROPÍA

Rngd se compone de múltiples fuentes de entropía, cuyos datos se agregan y se proporcionan al pool de entropía del kernel. Tenga en cuenta que no todas las fuentes de entropía están disponibles en todos los sistemas, y si una fuente de entropía se habilita para un sistema en el que no es apropiado (o posible) usarla, puede fallar al inicializarse. No es fatal para rngd que una sola fuente de entropía falle durante el inicio. Solo se necesita una fuente de entropía para que rngd funcione. Las siguientes fuentes de entropía están actualmente definidas en rngd

RNG de Hardware (hwrng)
El RNG de Hardware es una fuente de entropía genérica que extrae entropía de un rng de hardware conectado por defecto a /dev/hwrng
TPM (tpm)
Entropía extraída del dispositivo TPM integrado. Tenga en cuenta que esta fuente de entropía está obsoleta y se eliminará pronto, ya que los dispositivos tpm más nuevos exportan entropía a través de /dev/hwrng, que es recolectada por la fuente hwrng anterior
RDRAND/RDSEED (rdrand)
Entropía extraída de las instrucciones RDRAND y RDSEED (solo x86)

use_aes - selecciona si rdrand se utiliza para sembrar un cprng y producir entropía, o si toda la entropía se extrae directamente de la instrucción rdrand (predeterminado 0)

  • NAME

    rngd

    random number generator daemon

    SYNOPSIS

    rngd

    rngd [-f] [-q] [-o file] [-i file] [-p pidfile] [-b] [-s delay] [-T timeout]
     [-x name] [-X name] [-d device] [-r file] [-l file] [-c file] [-u file]
     [-P path] [-O path] [-t file] [-e file]

    DESCRIPTION

    rngd is a daemon that feeds random data from a random data source to the kernel's random number generator. It can also be used to add entropy to userspace by writing the data to a file.

    rngd relies on a random number generator that is accessible via /dev/random or /dev/urandom. It also supports various other entropy sources, detailed below.

    rngd is intended to be run as a service, typically started at boot time.

    OPTIONS

    The options available to rngd are as follows:

    -f
    Foreground mode. Don't fork into the background.
    -q
    Quiet mode. Don't log messages to stderr or stdout.
    -o file
    Output file. Write random data to the specified file. If this is not specified, rngd will write to the kernel's random number generator (/dev/random).
    -i file
    Input file. Read random data from the specified file. If this is not specified, rngd will attempt to use available entropy sources.
    -p pidfile
    Pid file. Write the process ID to the specified file. Defaults to /run/rngd.pid.
    -b
    Background mode. Fork into the background. This is the default unless -f is specified.
    -s delay
    Startup delay. Wait for the specified number of seconds before attempting to open entropy sources. Defaults to 0.
    -T timeout
    Timeout. Sets the timeout for read operations on entropy sources. Defaults to 5 seconds.
    -x name
    Disable entropy source. Prevents the specified entropy source from being used.
    -X name
    Enable entropy source. Forces the specified entropy source to be used. By default, all available entropy sources are used unless disabled with -x.
    -d device
    Device. Use the specified device as the entropy source. This option can be used multiple times to specify multiple devices.
    -r file
    Read file. Use the specified file as an entropy source. This option can be used multiple times to specify multiple files.
    -l file
    Log file. Log entropy quality information to the specified file.
    -c file
    Configuration file. Read entropy source configuration from the specified file.
    -u file
    Unblock file. If rngd is blocked waiting for entropy, writing to this file will unblock it. This is useful for testing.
    -P path
    Path to entropy sources. Look for entropy sources in the specified directory.
    -O path
    Output path. Write entropy data to files in the specified directory.
    -t file
    Test file. Write test data to the specified file.
    -e file
    Error file. Write error messages to the specified file.

    ENTROPY SOURCES

    rngd supports the following entropy sources:

    Hardware RNG (hw_rng)
    Entropy gathered from a hardware random number generator. This is typically an interface to a CPU instruction that returns a random value, or a dedicated hardware RNG device.
    Options
    device - Specify the device node for the hardware RNG.

    check_interval - Specify the interval in seconds at which to check the health of the hardware RNG. Defaults to 60.

    min_len - Specify the minimum length of random data to request from the hardware RNG. Defaults to 16.

    max_len - Specify the maximum length of random data to request from the hardware RNG. Defaults to 1024.

    tries - Specify the number of times to try reading from the hardware RNG before giving up. Defaults to 1.

    reseed_interval - Specify the interval in seconds at which to reseed the kernel's random number generator. Defaults to 300.

    Certrix Entropy Beacon (certrix)
    Entropy gathered from the Certrix entropy beacon. This is a commercial entropy source that requires a subscription.
    NIST Entropy Beacon (nist)
    Entropy gathered from the NIST network entropy beacon. Note that this entropy source is disabled by default as it should never be used for cryptographic purposes, or any use case in which random data should be known only by a single entity.
    Qrypt Entropy Beacon (qrypt)
    Entropy gathered from the qrypt entropy beacon. Note this beacon provides entropy to remote clients over a TLS connection. As such this source should not be used for cryptographic operations unless the security of the network can be guaranteed against man in the middle and other network based attacks.
    Options
    tokenfile - Specify the file containing the access token to the Qrypt beacon

    delay - Specify the maximum delay (in seconds) that the source will wait when there are temporary conditions preventing entropy retrieval before trying to fetch entropy again. The default maximum delay is eight hours, exponentially counting up from one second upwards, in powers of two.

    JITTER (jitter)
    Entropy gathered by measuring timing variance of operations on the local cpu
    Options
    thread_count - Set the number of threads that the jitter entropy source will spawn

    buffer_size - Set the size of the buffer cache that each thread maintains

    refill_thresh - Set the low watermark for the cache that triggers its corresponding thread to start refill operations

    retry_count - If all entropy buffers are empty, retry this many times before giving up. Note that jitterentropy can take several seconds to refill a buffer, and so retries after a delay may be preferable to repeatedly spining on an empty buffer (default 1)

    retry_delay - between each retry for retry_count above, sleep for this many seconds. May also be the special value -1, representing adaptive sleep, where each retry delay will be half the recorded execution time of the last entropy gathering round (default -1)

    force_soft_timer - on platforms with a hardware timer that is too coarse to sample jitter, we can instead use a software based timer loop. Detection and use of this mechanism is automatic, but this can be useful for testing purposes

    PKCS11 (pkcs11)
    Entropy gathered via the opensc openssl engine, which can extract entropy from various smart card readers. Install a package for your distribution containing pkcs11 endpoint library to gather smartcard entropy. This is opensc for Fedora, opensc-pkcs11 for Debian/Ubuntu or another package containing opensc-pkcs11.so.
    Options
    engine_path - Set the patch for the pkcs11 engine DSO to load

    chunk_size - Some pkcs11 engines have restrictions on how much data can be requested at a time, this option allows for the request to be subdivided into smaller chunks to be satisfied

    RTLSDR (rtlsdr)
    Entropy gathered via the rtl software defined radio library, which can gather entropy using various usb software defined radios listening to random radio static
    Options
    devid - When multiple devices are available the integer index of the device to use

    freq_min - The minimum frequence range to scan in

    freq_max - The maximum frequency range to scan in

    sample_min - The minimum sample rate of the radio

    sample_max - The maximum sample rate of the radio

    Named pipe (namedpipe)
    Reads entropy from a named pipe (aka FIFO). Another program, for example a driver reading and preparing data from an external hardware RNG, is expected to feed entropy into this named pipe. Should the named pipe be closed, rngd will try to reopen it.
    Options
    path - Path of the named pipe. Required.

    timeout - Maximum time in seconds rngd waits until a full FIPS test buffer of entropy can be read. Defaults to 5.
