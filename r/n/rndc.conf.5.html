Paquete: bind

RNDC.CONF(5) BIND 9 RNDC.CONF(5)

NOMBRE

rndc.conf - archivo de configuración de rndc

SINOPSIS

rndc.conf

DESCRIPCIÓN

rndc.conf es el archivo de configuración para rndc <#std-iscman-rndc>, la utilidad de control del servidor de nombres BIND 9. Este archivo tiene una estructura y sintaxis similares a named.conf <#std-iscman-named.conf>. Las sentencias se encierran entre llaves y terminan con punto y coma. Las cláusulas dentro de las sentencias también terminan con punto y coma. Los estilos de comentario habituales están soportados:

Estilo C: /* */

Estilo C++: // hasta el final de la línea

Estilo Unix: # hasta el final de la línea

rndc.conf es mucho más simple que named.conf <#std-iscman-named.conf>. El archivo utiliza tres sentencias: una sentencia options, una sentencia server y una sentencia key.

La sentencia options contiene cinco cláusulas. La cláusula default-server va seguida del nombre o dirección de un servidor de nombres. Este host se utiliza cuando no se proporciona ningún servidor de nombres como argumento a rndc <#std-iscman-rndc>. La cláusula default-key va seguida del nombre de una clave, que se identifica mediante una sentencia key. Si no se proporciona ningún keyid en la línea de comandos de rndc, y no se encuentra ninguna cláusula key en una sentencia server coincidente, esta clave predeterminada se utiliza para autenticar los comandos y respuestas del servidor. La cláusula default-port va seguida del puerto al que conectarse en el servidor de nombres remoto. Si no se proporciona ninguna opción port en la línea de comandos de rndc, y no se encuentra ninguna cláusula port en una sentencia server coincidente, este puerto predeterminado se utiliza para conectarse. Las cláusulas default-source-address y default-source-address-v6 se pueden utilizar para establecer las direcciones de origen IPv4 e IPv6 respectivamente.

Después de la palabra clave server, la sentencia server incluye una cadena que es el nombre de host o la dirección de un servidor de nombres. La sentencia tiene tres cláusulas posibles: key, port y addresses. El nombre de la clave debe coincidir con el nombre de una sentencia de clave en el archivo. El número de puerto especifica el puerto al que conectarse. Si se proporciona una cláusula addresses, estas direcciones se utilizan en lugar del nombre del servidor. Cada dirección puede tener un puerto opcional. Si se proporciona una source-address o source-address-v6, se utiliza para especificar la dirección de origen IPv4 e IPv6, respectivamente.

La sentencia key comienza con una cadena identificativa, el nombre de la clave. La sentencia tiene dos cláusulas. algorithm identifica el algoritmo de autenticación que rndc <#std-iscman-rndc> debe utilizar; actualmente solo se soportan HMAC-MD5 (para compatibilidad), HMAC-SHA1, HMAC-SHA224, HMAC-SHA256 (predeterminado), HMAC-SHA384 y HMAC-SHA512. A continuación, se encuentra una cláusula secret que contiene la codificación en base64 de la clave de autenticación del algoritmo. La cadena base64 se encierra entre comillas dobles.

Hay dos formas comunes de generar la cadena base64 para el secreto. El programa BIND 9 rndc-confgen <#std-iscman-rndc-confgen> puede utilizarse para generar una clave aleatoria, o el programa mmencode, también conocido como mimencode, puede utilizarse para generar una cadena base64 a partir de una entrada conocida. mmencode no viene con BIND 9 pero está disponible en muchos sistemas. Consulte la sección Ejemplo para ver ejemplos de líneas de comando para cada uno.

EJEMPLO

options {
  default-server  localhost;
  default-key     samplekey;
};
server localhost {
  key             samplekey;
};
server testserver {
  key     testkey;
  addresses   { localhost port 5353; };
};
key samplekey {
  algorithm       hmac-sha256;
  secret          "6FMfj43Osz4lyb24OIe2iGEz9lf1llJO+lz";
};
key testkey {
  algorithm   hmac-sha256;
  secret      "R3HI8P6BKw9ZwXwN3VZKuQ==";
};

En el ejemplo anterior, rndc <#std-iscman-rndc> por defecto utiliza el servidor en localhost (127.0.0.1) y la clave llamada "samplekey". Los comandos al servidor localhost utilizan la clave "samplekey", que también debe estar definida en el archivo de configuración del servidor con el mismo nombre y secreto. La sentencia de clave indica que "samplekey" utiliza el algoritmo HMAC-SHA256 y su cláusula de secreto contiene la codificación base64 del secreto HMAC-SHA256 entrecomillada.

Si se utiliza rndc -s testserver <#cmdoption-rndc-s>, entonces rndc <#std-iscman-rndc> se conecta al servidor en localhost puerto 5353 usando la clave "testkey".

Para generar un secreto aleatorio con rndc-confgen <#std-iscman-rndc-confgen>:

rndc-confgen <#std-iscman-rndc-confgen>

Se escribe un archivo rndc.conf completo, incluyendo la clave generada aleatoriamente, a la salida estándar. También se imprimen sentencias comentadas de key y controls para named.conf <#std-iscman-named.conf>.

Para generar un secreto base64 con mmencode:

echo "texto plano conocido para un secreto" | mmencode

CONFIGURACIÓN DEL SERVIDOR DE NOMBRES

El servidor de nombres debe estar configurado para aceptar conexiones rndc y para reconocer la clave especificada en el archivo rndc.conf, utilizando la sentencia controls en named.conf <#std-iscman-named.conf>. Consulte las secciones sobre la sentencia controls en el Manual de Administración de BIND 9 para obtener más detalles.
