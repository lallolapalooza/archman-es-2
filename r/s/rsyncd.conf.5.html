NOMBRE

rsyncd.conf - archivo de configuración para rsync en modo demonio

SINOPSIS

rsyncd.conf

La versión en línea de esta página del manual (que incluye enlaces entre temas) está disponible en https://download.samba.org/pub/rsync/rsyncd.conf.5.

DESCRIPCIÓN

El archivo rsyncd.conf es el archivo de configuración en tiempo de ejecución para rsync cuando se ejecuta como un demonio rsync.

El archivo rsyncd.conf controla la autenticación, el acceso, el registro y los módulos disponibles.

FORMATO DEL ARCHIVO

El archivo consta de módulos y parámetros. Un módulo comienza con el nombre del módulo entre corchetes y continúa hasta que comienza el siguiente módulo. Los módulos contienen parámetros del tipo nombre = valor.

El archivo está basado en líneas: cada línea terminada en nueva línea representa un comentario, un nombre de módulo o un parámetro.

Solo el primer signo de igual en un parámetro es significativo. Los espacios en blanco antes o después del primer signo de igual se desechan. Los espacios en blanco al principio, al final y los espacios en blanco internos en los nombres de módulos y parámetros son irrelevantes. Los espacios en blanco al principio y al final en un valor de parámetro se desechan. Los espacios en blanco internos dentro de un valor de parámetro se conservan literalmente.

Cualquier línea que comience con una almohadilla (#) se ignora, al igual que las líneas que solo contienen espacios en blanco. (Si una almohadilla ocurre después de algo que no sea un espacio en blanco inicial, se considera parte del contenido de la línea).

Cualquier línea que termine en un \ se "continúa" en la siguiente línea al estilo habitual de UNIX.

Los valores que siguen al signo de igual en los parámetros son todos una cadena de texto (no se necesitan comillas) o un booleano, que puede ser sí/no, 0/1 o verdadero/falso. La mayúscula/minúscula no es significativa en los valores booleanos, pero se conserva en los valores de cadena de texto.

LANZAMIENTO DEL DEMONIO RSYNC

El demonio rsync se lanza especificando la opción --daemon a rsync.

El demonio debe ejecutarse con privilegios de root si desea usar chroot, enlazar a un puerto numerado por debajo de 1024 (como es el puerto predeterminado 873), o establecer la propiedad de los archivos. De lo contrario, solo debe tener permiso para leer y escribir los archivos de datos, registro y bloqueo apropiados.

Puede lanzarlo a través de inetd, como un demonio independiente, o desde un cliente rsync a través de un shell remoto. Si se ejecuta como un demonio independiente, simplemente ejecute el comando "rsync --daemon" desde un script de inicio adecuado.

Cuando se ejecuta a través de inetd, debe agregar una línea como esta a /etc/services:

rsync           873/tcp

y una sola línea como esta a /etc/inetd.conf:

rsync   stream  tcp     nowait  root   /usr/bin/rsync rsyncd --daemon

Reemplace "/usr/bin/rsync" con la ruta donde tiene rsync instalado en su sistema. Luego, deberá enviar una señal HUP a inetd para que vuelva a leer su archivo de configuración.

Tenga en cuenta que no debe enviar una señal HUP al demonio rsync para forzarlo a volver a leer el archivo rsyncd.conf. El archivo se vuelve a leer en cada conexión del cliente.

PARÁMETROS GLOBALES

Los primeros parámetros en el archivo (antes de un encabezado [módulo]) son los parámetros globales:

archivo motd
Este parámetro le permite especificar un "mensaje del día" (MOTD) para mostrar a los clientes en cada conexión. Esto generalmente contiene información del sitio y avisos legales. El valor predeterminado es no tener archivo MOTD. Esto puede ser anulado por la opción de línea de comandos --dparam=motdfile=ARCHIVO al iniciar el demonio.
archivo pid
Este parámetro indica al demonio rsync que escriba su ID de proceso en ese archivo. rsync mantiene el archivo bloqueado para que pueda saber cuándo es seguro sobrescribir un archivo existente.
El nombre del archivo puede ser anulado por la opción de línea de comandos --dparam=pidfile=ARCHIVO al iniciar el demonio.
puerto
Puede anular el puerto predeterminado en el que escuchará el demonio especificando este valor (predeterminado 873). Esto se ignora si el demonio está siendo ejecutado por inetd, y es reemplazado por la opción de línea de comandos --port.
dirección
Puede anular la dirección IP predeterminada en la que escuchará el demonio especificando este valor. Esto se ignora si el demonio está siendo ejecutado por inetd, y es reemplazado por la opción de línea de comandos --address.
opciones de socket
Este parámetro puede proporcionar diversión infinita para las personas a las que les gusta ajustar sus sistemas al máximo. Puede configurar todo tipo de opciones de socket que pueden hacer las transferencias más rápidas (o más lentas). Lea la página del manual de la llamada al sistema setsockopt() para obtener detalles sobre algunas de las opciones que puede configurar. Por defecto, no se establecen opciones de socket especiales. Estas configuraciones también se pueden especificar a través de la opción de línea de comandos --sockopts.
backlog de escucha
Puede anular el valor predeterminado de backlog cuando el demonio escucha conexiones. Por defecto es 5.

También puede incluir cualquier PARÁMETRO DE MÓDULO en la parte global del archivo de configuración, en cuyo caso el valor proporcionado anulará el valor predeterminado para ese parámetro.

Puede usar referencias a variables de entorno en los valores de los parámetros. Los parámetros de cadena de texto tendrán referencias %VAR% expandidas lo más tarde posible (cuando la cadena se use por primera vez en el programa), lo que permite el uso de variables que rsync establece en el momento de la conexión, como RSYNC_USER_NAME. Los parámetros que no son de cadena de texto (como las configuraciones verdadero/falso) se expanden al leerse del archivo de configuración. Si una variable no existe en el entorno, o si una secuencia de caracteres no es una referencia válida (como un signo de porcentaje sin pareja), se pasan los caracteres crudos sin cambios. Esto ayuda a la compatibilidad y seguridad retroactivas (por ejemplo, expandir un %VAR% inexistente a una cadena vacía en una ruta podría resultar en una ruta muy insegura). La forma más segura de insertar un % literal en un valor es usar %%.

PARÁMETROS DE MÓDULO

Después de los parámetros globales, debe definir una serie de módulos, cada módulo exporta un árbol de directorios como un nombre simbólico. Los módulos se exportan especificando un nombre de módulo entre corchetes [módulo] seguido de los parámetros para ese módulo. El nombre del módulo no puede contener una barra o un corchete de cierre. Si el nombre contiene espacios en blanco, cada secuencia interna de espacios en blanco se cambiará por un solo espacio, mientras que los espacios en blanco iniciales o finales se desecharán.

También existe un nombre de módulo especial de "[global]" que no define un módulo sino que cambia de nuevo al contexto de configuración global donde se pueden especificar parámetros predeterminados. Dado que cada módulo definido recibe su conjunto completo de parámetros como una combinación de los valores predeterminados que se establecen en esa posición en el archivo de configuración más su propia lista de parámetros, el uso de una sección "[global]" puede ayudar a mantener valores de configuración compartidos para múltiples módulos.

Al igual que con los PARÁMETROS GLOBALES, puede usar referencias a variables de entorno en los valores de los parámetros. Consulte esa sección para obtener detalles.

comentario
Este parámetro especifica una cadena de descripción que se muestra junto al nombre del módulo cuando los clientes obtienen una lista de módulos disponibles. El valor predeterminado es no tener comentario.
ruta
Este parámetro especifica el directorio en el sistema de archivos del demonio que se pondrá a disposición en este módulo. Debe especificar este parámetro para cada módulo en rsyncd.conf.

ignore dirs

  
Cuando se establece en "sí", este parámetro le dice al demonio rsync que
      ignore todas las entradas de directorio que no contienen ningún archivo
      que coincida con el patrón de archivo de la transferencia. Esto se puede
      usar para evitar que los clientes se sincronicen en módulos que solo
      contienen directorios vacíos. Los directorios que contienen entradas
      excluidas de otra manera (por ejemplo, por el parámetro "filter") aún
      serán transferidos. El valor predeterminado es "no".
      A tener en cuenta: en la mayoría de los sistemas, la verificación del
      contenido de un directorio solo se puede realizar después de que se ha
      comenzado a transferir el contenido del directorio. Esto significa que
      el demonio aún podría enumerar el directorio afectado, pero se omitirá
      antes de que se transfiera cualquier dato. El efecto de esto es el mismo
      que si el directorio nunca hubiera existido, y es una forma de ocultar
      la jerarquía del módulo. Hay formas complicadas de evitar esto, sin
      embargo, así que será mejor que confíe en sus usuarios si elige esta
      combinación de parámetros.

  
charset

  
Esto especifica el nombre del conjunto de caracteres en el que se almacenan
      los nombres de archivo del módulo. Si el cliente utiliza una opción
      --iconv, el demonio utilizará el valor del parámetro
      "charset" independientemente del conjunto de caracteres que el cliente
      haya pasado realmente. Esto permite que el demonio admita la conversión
      de conjuntos de caracteres en un módulo chroot sin archivos adicionales
      en el área chroot, y también garantiza que la traducción de nombres se
      realice de manera consistente. Si el parámetro "charset" no está
      establecido, se rechaza la opción --iconv, al igual que si
      "iconv" se hubiera especificado a través de "refuse options".

  

  
Si desea forzar a los usuarios a usar siempre --iconv para un módulo
      particular, agregue "no-iconv" al parámetro "refuse options". Tenga en
      cuenta que esto restringirá el acceso a su módulo a clientes rsync muy
      recientes.

  
max connections

  
Este parámetro le permite especificar el número máximo de conexiones
      simultáneas que permitirá. Cualquier cliente que se conecte cuando se
      haya alcanzado el máximo recibirá un mensaje indicándoles que intenten
      más tarde. El valor predeterminado es 0, lo que significa que no hay
      límite. Un valor negativo deshabilita el módulo. Ver también el parámetro
      "lock file".

  
log file

  
Cuando el parámetro "log file" se establece en una cadena no vacía, el
      demonio rsync registrará mensajes en el archivo indicado en lugar de usar
      syslog. Esto es particularmente útil en sistemas (como AIX) donde
      syslog() no funciona para programas chrooted. El archivo se abre
      antes de llamar a chroot(), lo que permite colocarlo fuera de la
      transferencia. Si este valor se establece por módulo en lugar de globalmente,
      el registro global aún contendrá cualquier fallo de autorización o
      mensajes de error del archivo de configuración.

  

  
Si el demonio no puede abrir el archivo especificado, recurrirá a usar
      syslog y mostrará un error sobre el fallo. (Tenga en cuenta que el fallo
      al abrir el archivo de registro especificado solía ser un error fatal).

  

  
Esta configuración se puede anular utilizando las opciones de línea de
      comandos --log-file=FILE o --dparam=logfile=FILE. La
      primera anula todos los parámetros de archivo de registro del demonio y
      todas las configuraciones de módulo. La segunda establece el archivo de
      registro del demonio y el valor predeterminado para todos los módulos,
      lo que aún permite que los módulos anulen la configuración predeterminada.

  
syslog facility

  
Este parámetro le permite especificar el nombre de la instalación de
      syslog que se utilizará al registrar mensajes del demonio rsync. Puede
      utilizar cualquier nombre de instalación de syslog estándar que esté
      definido en su sistema. Los nombres comunes son auth, authpriv, cron,
      daemon, ftp, kern, lpr, mail, news, security, syslog, user, uucp, local0,
      local1, local2, local3, local4, local5, local6 y local7. El valor
      predeterminado es daemon. Esta configuración no tiene ningún efecto si la
      configuración "log file" es una cadena no vacía (establecida en la
      configuración por módulo o heredada de la configuración global).

  
syslog tag

  
Este parámetro le permite especificar la etiqueta de syslog que se
      utilizará al registrar mensajes del demonio rsync. El valor predeterminado
      es "rsyncd". Esta configuración no tiene ningún efecto si la configuración
      "log file" es una cadena no vacía (establecida en la configuración por
      módulo o heredada de la configuración global).

  

  
Por ejemplo, si quisiera que el nombre de cada usuario autenticado se
      incluyera en la etiqueta de syslog, podría hacer algo como esto:







  

  


syslog tag = rsyncd.%RSYNC_USER_NAME%

  







  
max verbosity

  
Este parámetro le permite controlar la cantidad máxima de información
      detallada que permitirá que genere el demonio (ya que la información va
      al archivo de registro). El valor predeterminado es 1, lo que permite al
      cliente solicitar un nivel de verbosidad.

  

  
Esto también afecta la capacidad del usuario para solicitar niveles más
      altos de registro --info y --debug. Si el valor máximo es
      2, entonces ningún valor de info y/o debug que sea más alto que el que
      establecería -vv será respetado por el demonio en su registro.
      Para ver hasta qué nivel de verbosidad necesita aceptar para un nivel de
      info/debug particular, consulte
      rsync --info=help y
      rsync --debug=help. Por ejemplo, se necesita max-verbosity
      4 para poder emitir debug TIME2 y FLIST3.

  
lock file

  
Este parámetro especifica el archivo que se utilizará para admitir el
      parámetro "max connections". El demonio rsync utiliza el bloqueo de
      registros en este archivo para garantizar que no se supere el límite de
      conexiones máximas para los módulos que comparten el archivo de bloqueo.
      El valor predeterminado es
      /var/run/rsyncd.lock.

  
read only

  
Este parámetro determina si los clientes podrán cargar archivos o no. Si
      "read only" es verdadero, cualquier intento de carga fallará. Si "read
      only" es falso, las cargas serán posibles si los permisos de archivo en el
      lado del demonio los permiten. El valor predeterminado es que todos los
      módulos sean de solo lectura.

  

  
Tenga en cuenta que "auth users" puede anular esta configuración por
      usuario.

  
write only

  
Este parámetro determina si los clientes podrán descargar archivos o no.
      Si "write only" es verdadero, cualquier intento de descarga fallará. Si
      "write only" es falso, las descargas serán posibles si los permisos de
      archivo en el lado del demonio los permiten. El valor predeterminado es
      que este parámetro esté deshabilitado.

  

  
Pista útil: probablemente querrá especificar "refuse options =
      delete" para un módulo de solo escritura.

  
open noatime

  
Cuando se establece en True, este parámetro le indica al demonio rsync que
      abra archivos con la bandera O_NOATIME (en sistemas que lo admiten) para
      evitar cambiar la hora de acceso de los archivos que se están
      transfiriendo. Si su sistema operativo no admite la bandera O_NOATIME,
      rsync ignorará silenciosamente esta opción. Tenga en cuenta también que
      algunos sistemas de archivos se montan para evitar actualizar el atime en
      el acceso de lectura incluso sin establecer la bandera O_NOATIME.

  

  
Cuando se establece en False, este parámetro garantiza que los archivos
      en el servidor no se abran con O_NOATIME.

  

  
Cuando se establece en Unset (el valor predeterminado), el usuario controla
      la configuración a través de
      --open-noatime.

  
list

  
Este parámetro determina si este módulo se lista cuando el cliente solicita
      un listado de módulos disponibles. Además, si esto es falso, el demonio
      fingirá que el módulo no existe cuando un cliente denegado por
      "hosts allow" o "hosts deny" intente acceder a él. Tenga en cuenta que si
      "reverse lookup" está deshabilitado globalmente pero habilitado para el
      módulo, la búsqueda inversa resultante a un servidor DNS potencialmente
      controlado por el cliente aún puede revelar al cliente que ha alcanzado
      un módulo existente. El valor predeterminado es que los módulos sean
      listables.

  
uid

  
Este parámetro especifica el nombre de usuario o ID de usuario con el que se
      deben realizar las transferencias de archivos hacia y desde ese módulo
      cuando el demonio se ejecutaba como root. En combinación con el parámetro
      "gid", esto determina qué permisos de archivo están disponibles. El valor
      predeterminado cuando lo ejecuta un superusuario es cambiar al usuario
      "nobody" del sistema. El valor predeterminado para un no superusuario es
      no intentar cambiar el usuario. Ver también el parámetro "gid".

  

  
La variable de entorno RSYNC_USER_NAME puede usarse para solicitar que rsync
      se ejecute como el usuario autorizador. Por ejemplo, si desea que un rsync
      se ejecute como el mismo usuario que se recibió para la autenticación rsync,
      esta configuración es útil:







  

  


uid = %RSYNC_USER_NAME%
gid = *

  







  
gid

  
Este parámetro especifica uno o más nombres/IDs de grupo que se utilizarán
      al acceder al módulo. El primero será el grupo predeterminado, y los
      adicionales se establecerán como grupos suplementarios. También puede
      especificar un "*" como el primer gid de la lista, que será
      reemplazado por todos los grupos normales para el usuario de la
      transferencia (ver "uid"). El valor predeterminado cuando lo ejecuta un
      superusuario es cambiar al grupo "nobody" (o quizás "nogroup") de su
      sistema operativo sin otros grupos suplementarios. El valor predeterminado
      para un no superusuario es no cambiar ningún atributo de grupo (y de
      hecho, su sistema operativo puede no permitir que un no superusuario intente
      cambiar la configuración de su grupo).

  

  
La lista especificada normalmente se divide en tokens basándose en espacios
      y comas. Sin embargo, si la lista comienza con una coma, la lista solo se
      divide por comas, lo que permite que un nombre de grupo contenga un espacio.
      En cualquier caso, se elimina cualquier espacio en blanco inicial y/o final
      de los tokens y se ignoran los tokens vacíos.

  
daemon uid

  
Este parámetro especifica un uid bajo el cual se ejecutará el demonio. El
      demonio generalmente se ejecuta como usuario root, y cuando esto se deja
      sin establecer, el usuario no se modifica. Ver también el parámetro
      "uid".

  
daemon gid

  
Este parámetro especifica un gid bajo el cual se ejecutará el demonio. El
      demonio generalmente se ejecuta como grupo root, y cuando esto se deja
      sin establecer, el grupo no se modifica. Ver también el parámetro "gid".

  
fake super

  
Establecer "fake super = yes" para un módulo hace que el lado del demonio
      se comporte como si se hubiera especificado la opción de línea de comandos
      --fake-super. Esto permite almacenar los atributos completos de un
      archivo sin necesidad de que el demonio se ejecute realmente como root.

  
filter

  
El demonio tiene su propia cadena de filtros que determina qué archivos
      deja acceder al cliente. Esta cadena no se envía al cliente y es
      independiente de cualquier filtro que el cliente pueda haber especificado.
      Los archivos excluidos por la cadena de filtros del demonio (archivos
      daemon-excluded) se tratan como inexistentes si el cliente intenta
      extraerlos, se omiten con un mensaje de error si el cliente intenta
      enviarlos (desencadenando el código de salida 23), y nunca se eliminan
      del módulo. Puede





  

  
Use los filtros de demonio para evitar que los clientes
      descarguen o manipulen archivos administrativos privados, como archivos
      que pueda agregar para admitir traducciones de nombres uid/gid.

  

  
La cadena de filtros de demonio se construye a partir de los parámetros "filter",
      "include from", "include", "exclude from" y
      "exclude", en ese orden de prioridad. Los patrones anclados se anclan en la raíz del módulo. Para evitar el acceso a un subárbol completo, por ejemplo, "/secret", debe
      excluir todo en el subárbol; la forma más fácil de hacerlo es con un patrón de triple estrella como "/secret/***".

  

  
El parámetro "filter" toma una lista de reglas de filtro de demonio separadas por espacios, aunque es lo suficientemente inteligente como para saber que no debe dividir un token en un espacio interno en una regla (por ejemplo,
      "- /foo  - /bar" se analiza como
      dos reglas). Puede especificar una o más reglas de archivo de fusión usando la sintaxis normal. Solo un parámetro "filter" puede aplicarse a un módulo dado en el archivo de configuración, así que ponga todas las reglas que desee en un solo parámetro.
      Tenga en cuenta que las reglas de archivo de fusión por directorio no proporcionan tanta protección como las reglas globales, pero se pueden usar para que --delete funcione mejor
      durante una operación de descarga del cliente si los archivos de fusión por directorio se incluyen
      en la transferencia y el cliente solicita que se utilicen.

  
exclude

  
Este parámetro toma una lista de patrones de exclusión de demonio separados por espacios. Al igual que con la opción --exclude del cliente, los patrones se pueden calificar con "- " o "+ " para indicar explícitamente exclusión/inclusión. Solo un parámetro "exclude" puede aplicarse a un módulo dado. Consulte el parámetro "filter" para obtener una descripción de cómo los archivos excluidos afectan al demonio.

  
include

  
Utilice una "include" para anular los efectos del
      parámetro "exclude". Solo un parámetro "include" puede aplicarse a un módulo dado. Consulte el parámetro "filter" para obtener una
      descripción de cómo los archivos excluidos afectan al demonio.

  
exclude from

  
Este parámetro especifica el nombre de un archivo en el demonio que contiene
      patrones de exclusión de demonio, uno por línea. Solo un parámetro "exclude from" puede aplicarse a un módulo dado; si tiene varios archivos de exclusión, puede especificarlos como un archivo de fusión en el parámetro "filter". Consulte el parámetro "filter" para obtener una descripción de cómo
      los archivos excluidos afectan al demonio.

  
include from

  
Análogo de "exclude from" para un archivo de patrones de inclusión de demonio. Solo un parámetro "include from" puede aplicarse a un módulo dado. Consulte el parámetro "filter" para obtener una descripción de cómo
      los archivos excluidos afectan al demonio.

  
incoming chmod

  
Este parámetro le permite especificar un conjunto de cadenas chmod separadas por comas que afectarán a los permisos de todos los archivos entrantes (archivos que está recibiendo el demonio). Estos cambios ocurren después de todos los demás cálculos de permisos, e incluso anularán los permisos predeterminados del destino y/o los permisos existentes cuando el cliente no especifique
      --perms. Consulte la descripción de la opción rsync --chmod y la página del manual de chmod(1) para obtener información sobre el formato de esta
    cadena.

  
outgoing chmod

  
Este parámetro le permite especificar un conjunto de cadenas chmod separadas por comas que afectarán a los permisos de todos los archivos salientes (archivos que se están enviando desde el demonio). Estos cambios ocurren primero, haciendo que los permisos enviados parezcan ser diferentes de los almacenados en el sistema de archivos. Por ejemplo, podría deshabilitar los permisos de escritura de grupo en el servidor mientras hace que parezca que están activados para los clientes. Consulte la
      descripción de la opción rsync --chmod y la página del manual de chmod(1)
      para obtener información sobre el formato de esta cadena.

  
auth users

  
Este parámetro especifica una lista de reglas de autorización separadas por comas y/o espacios. En su forma más simple, enumera los nombres de usuario que podrán conectarse a este módulo. Los nombres de usuario no necesitan existir en el sistema local. Las reglas pueden contener caracteres comodín de shell que se compararán con el nombre de usuario proporcionado por el cliente para la autenticación. Si se establece "auth users", se le pedirá al cliente que proporcione un nombre de usuario y una contraseña para conectarse al módulo. Se utiliza un protocolo de autenticación de respuesta a desafío para este intercambio. Los nombres de usuario y las contraseñas en texto plano se almacenan en el archivo especificado por el parámetro "secrets file". El valor predeterminado es que todos los usuarios puedan conectarse sin contraseña (esto se llama "rsync anónimo").

  

  
Además de la coincidencia de nombres de usuario, puede especificar la coincidencia de nombres de grupo mediante un prefijo '@'. Al usar la coincidencia de nombres de grupo, el nombre de usuario autenticador debe ser un usuario real en el sistema, o se asumirá que no pertenece a ningún grupo. Por ejemplo, especificar "@rsync" coincidirá con el usuario autenticador si el usuario nombrado es miembro del grupo rsync.

  

  
Finalmente, las opciones se pueden especificar después de dos puntos (:). Las opciones le permiten "denegar" a un usuario o grupo, establecer el acceso a "ro" (solo lectura) o establecer el acceso a "rw" (lectura/escritura). Establecer una configuración ro/rw específica de la regla de autenticación anula la configuración "solo lectura" del módulo.

  

  
Asegúrese de poner las reglas en el orden en que desea que se comparen, porque
      la verificación se detiene en el primer usuario o grupo coincidente, y esa es la única autenticación que se verifica. Por ejemplo:







  

  

    
auth users = joe:deny @guest:deny admin:rw @rsync:ro susan joe sam

  







  

  
En la regla anterior, al usuario joe se le negará el acceso sin importar qué. A cualquier usuario que pertenezca al grupo "guest" también se le niega el acceso. El usuario "admin" obtiene acceso en modo de lectura/escritura, pero solo si el usuario admin no pertenece al grupo "guest" (porque la regla de coincidencia de usuario admin nunca se alcanzaría si el usuario pertenece al grupo "guest").
      Cualquier otro usuario que pertenezca al grupo "rsync" obtendrá acceso de solo lectura. Finalmente, los usuarios susan, joe y sam obtienen la configuración ro/rw del módulo, pero solo si el usuario no coincidió con una regla de coincidencia de grupo anterior.

  

  
Si necesita especificar un nombre de usuario o grupo con un espacio, comience su lista con una coma para indicar que la lista solo debe dividirse por comas (aunque también se eliminarán los espacios en blanco iniciales y finales, y las entradas vacías simplemente se ignorarán). Por ejemplo:







  

  

    
auth users = , joe:deny, @Some Group:deny, admin:rw, @RO Group:ro

  







  

  
Consulte la descripción del archivo secrets para ver cómo puede tener contraseñas por usuario
      así como contraseñas por grupo. También explica cómo un usuario puede autenticarse usando su contraseña de usuario o (cuando sea aplicable) una contraseña de grupo, dependiendo de la regla que se esté autenticando.

  

  
Consulte también la sección titulada "USO DE FUNCIONES DE RSYNC-DAEMON A TRAVÉS DE UNA CONEXIÓN DE SHELL REMOTA" en rsync(1) para obtener información sobre cómo
      manejar un nombre de usuario a nivel de rsyncd.conf que difiere del nombre de usuario a nivel de
      shell remoto cuando se utiliza un shell remoto para conectarse a un demonio rsync.

  
secrets file

  
Este parámetro especifica el nombre de un archivo que contiene los pares
      username:password y/o @groupname:password utilizados para autenticar este módulo. Este archivo solo se consulta si se especifica el parámetro "auth users". El archivo está basado en líneas y contiene un par
      name:password por línea. Cualquier línea que tenga un hash (#) como primer carácter de la línea se considera un comentario y se omite. Las
      contraseñas pueden contener cualquier carácter, pero tenga en cuenta que muchos sistemas operativos limitan la longitud de las contraseñas que se pueden escribir en el lado del cliente, por lo que es posible que las contraseñas de más de 8 caracteres no funcionen.

  

  
El uso de líneas específicas de grupo solo es relevante cuando el módulo se autoriza utilizando una regla coincidente "@groupname". Cuando eso sucede, el usuario puede ser autorizado a través de su línea
      "username:password" o la línea "@groupname:password" para el grupo que activó la autenticación.

  

  
Depende de usted qué tipo de entradas de contraseña desea incluir, ya sean usuarios, grupos o ambos. El uso de reglas de grupo en "auth users" no requiere que especifique una contraseña de grupo si no desea utilizar contraseñas compartidas.

  

  
No hay un valor predeterminado para el parámetro "secrets file", debe elegir un nombre (como /etc/rsyncd.secrets). El archivo normalmente no debe ser legible por "otros"; consulte "strict modes". Si el
      archivo no se encuentra o se rechaza, no será posible iniciar sesión para un módulo "auth users".

  
strict modes

  
Este parámetro determina si se comprobarán o no los permisos del archivo secrets. Si "strict modes" es true, entonces el
      archivo secrets no debe ser legible por ningún ID de usuario que no sea el que
      está ejecutando el demonio rsync. Si "strict modes" es false,
      la comprobación no se realiza. El valor predeterminado es true. Este parámetro se agregó para acomodar rsync ejecutándose en el sistema operativo Windows.

  
hosts allow

  
Este parámetro le permite especificar una lista de patrones separados por comas y/o espacios que se comparan con el nombre de host y la dirección IP de un cliente que se conecta. Si ninguno de los patrones coincide, la conexión se rechaza.

  

  
Cada patrón puede tener una de las seis formas:







  
o

  
una dirección IPv4 decimal con puntos de la forma a.b.c.d, o una dirección IPv6 de la forma a:b:c::d:e:f. En este caso, la dirección IP de la máquina entrante debe coincidir exactamente.

  
o

  
una dirección/máscara en el formato ipaddr/n donde ipaddr es la dirección IP y n
      es el número de bits en uno en la máscara de red. Se permitirán todas las direcciones IP que coincidan con la dirección IP enmascarada.

  
o

  
una dirección/máscara en el formato ipaddr/n donde ipaddr es la dirección IP y n
      es el número de bits en uno en la máscara de red. Se permitirán todas las direcciones IP que coincidan con la dirección IP enmascarada.







  

  
una dirección/máscara en el formato ipaddr/n donde ipaddr es la dirección IP y n
      es el número de bits en uno en la máscara de red. Se permitirán todas las direcciones IP que coincidan con la dirección IP enmascarada.



      el formato ipaddr/maskaddr donde ipaddr es la dirección IP
      y maskaddr es la máscara de red en notación decimal con puntos para IPv4, o
      similar para IPv6, por ejemplo ffff:ffff:ffff:ffff:: en lugar de /64. Todas las direcciones IP
      que coincidan con la dirección IP enmascarada serán permitidas.
  
o

  
un patrón de nombre de host utilizando comodines. Si el nombre de host de la IP de conexión
      (según lo determinado por una búsqueda inversa) coincide con el nombre comodinado (utilizando las
      mismas reglas que la coincidencia de nombres de archivo de Unix normales), se permite el acceso al cliente.
      Esto solo funciona si la "búsqueda inversa" está habilitada (la
    predeterminada).

  
o

  
un nombre de host. Un nombre de host simple se compara con el DNS inverso de la IP de conexión
      (si la "búsqueda inversa" está habilitada), y/o la IP del
      nombre de host dado se compara con la IP de conexión
      (si la "búsqueda directa" está habilitada, como lo está de forma predeterminada). Cualquier coincidencia permitirá
      el acceso.

  
o

  
un '@' seguido de un nombre de netgroup, que coincidirá si el DNS inverso de
      la IP de conexión está en el netgroup especificado.
Nota: Las direcciones de enlace local IPv6 pueden tener un ámbito en la especificación de la dirección: 
fe80::1%link1
fe80::%link1/64
fe80::%link1/ffff:ffff:ffff:ffff::
También puede combinar "hosts allow" con "hosts deny" como una forma de agregar excepciones a su lista de denegación. Cuando se especifican ambos parámetros, el parámetro "hosts allow" se verifica primero y una coincidencia resulta en que el cliente pueda conectarse. Un host no permitido se compara luego con la lista "hosts deny" para ver si debe ser rechazado. Un host que no coincide con ninguna de las listas puede conectarse.
El valor predeterminado es que no haya ningún parámetro "hosts allow", lo que significa que todos los hosts pueden conectarse.
hosts deny
Este parámetro le permite especificar una lista de patrones separados por comas y/o espacios en blanco que se comparan con el nombre de host y la dirección IP de un cliente que se conecta. Si el patrón coincide, la conexión se rechaza. Consulte el parámetro "hosts allow" para obtener más información.
El valor predeterminado es que no haya ningún parámetro "hosts deny", lo que significa que todos los hosts pueden conectarse.
reverse lookup
Controla si el demonio realiza una búsqueda inversa de la dirección IP del cliente para determinar su nombre de host, que se utiliza para las comprobaciones de "hosts allow" y "hosts deny" y la expansión de registro "%h". Esto está habilitado de forma predeterminada, pero es posible que desee deshabilitarlo para ahorrar tiempo si sabe que la búsqueda no devolverá un resultado útil, en cuyo caso el demonio utilizará el nombre "UNDETERMINED" en su lugar.
Si este parámetro está habilitado globalmente (incluso de forma predeterminada), rsync realiza la búsqueda tan pronto como un cliente se conecta, por lo que deshabilitarlo para un módulo no evitará la búsqueda. Por lo tanto, probablemente querrá deshabilitarlo globalmente y luego habilitarlo para los módulos que necesiten la información.
forward lookup
Controla si el demonio realiza una búsqueda directa de cualquier nombre de host especificado en una configuración de hosts allow/deny. De forma predeterminada, esto está habilitado, lo que permite el uso de un nombre de host explícito que no sería devuelto por el DNS inverso de la IP de conexión.
ignore errors
Este parámetro indica a rsyncd que ignore los errores de E/S en el demonio al decidir si ejecutar la fase de eliminación de la transferencia. Normalmente, rsync omite el paso --delete si se han producido errores de E/S para evitar eliminaciones desastrosas debido a escasez temporal de recursos u otros errores de E/S. En algunos casos, esta prueba es contraproducente, por lo que puede utilizar este parámetro para desactivar este comportamiento.
ignore nonreadable
Esto indica al demonio rsync que ignore por completo los archivos que no son legibles por el usuario. Esto es útil para archivos públicos que pueden tener algunos archivos no legibles entre los directorios, y el administrador del sistema no quiere que esos archivos se vean en absoluto.
transfer logging
Este parámetro habilita el registro por archivo de las descargas y subidas en un formato algo similar al utilizado por los demonios ftp. El demonio siempre registra la transferencia al final, por lo que si una transferencia se interrumpe, no se hará ninguna mención en el archivo de registro.
Si desea personalizar las líneas de registro, consulte el parámetro "log format".
log format
Este parámetro le permite especificar el formato utilizado para registrar las transferencias de archivos cuando el registro de transferencias está habilitado. El formato es una cadena de texto que contiene secuencias de escape de un solo carácter incrustadas, precedidas por un carácter de porcentaje (%). También se puede especificar un ancho de campo numérico opcional entre el signo de porcentaje y la letra de escape (por ejemplo, "%-50n %8l %07p"). Además, se pueden especificar una o más apóstrofes antes de una escape numérica para indicar que el valor numérico debe ser más legible para humanos. Los 3 niveles admitidos son los mismos que para la opción de línea de comandos --human-readable, aunque el valor predeterminado es que la legibilidad humana esté desactivada. Cada apóstrofe añadida aumenta el nivel (por ejemplo, "%''l %'b %f").
El formato de registro predeterminado es "%o %h [%a] %m (%u) %f %l", y siempre se antepone "%t [%p] " al utilizar el parámetro "log file". (Un script de Perl que resumirá este formato de registro predeterminado se incluye en la distribución del código fuente de rsync en el subdirectorio "support": rsyncstats.)
Las escapes de un solo carácter que se entienden son las siguientes:
o
%a la dirección IP remota (solo disponible para un demonio)
o
%b el número de bytes realmente transferidos
o
%B los bits de permisos del archivo (por ejemplo, rwxrwxrwt)
o
%c el tamaño total de las sumas de verificación de bloques recibidas para el archivo base (solo al enviar)
o
%C la suma de verificación completa del archivo si se conoce para el archivo. Para protocolos/versiones de rsync más antiguas, la suma de verificación se salaba y, por lo tanto, no es un valor útil (y no se muestra cuando es el caso). Para que se genere la suma de verificación de un archivo, debe estar en vigor la opción --checksum o el archivo debe haberse transferido sin utilizar una suma de verificación salada. Consulte la opción --checksum-choice para ver una forma de elegir el algoritmo.
o
%f el nombre del archivo (forma larga en el emisor; sin "/" al final)
o
%G el gid del archivo (decimal) o "DEFAULT"
o
%h el nombre del host remoto (solo disponible para un demonio)
o
%i una lista detallada de lo que se está actualizando
o
%l la longitud del archivo en bytes
o
%L la cadena " -> SYMLINK", " => HARDLINK", o "" (donde SYMLINK o HARDLINK es un nombre de archivo)
o
%m el nombre del módulo
o
%M la hora de la última modificación del archivo
o
%n el nombre del archivo (forma corta; "/" al final en el directorio)
o
%o la operación, que es "send", "recv", o "del." (el último incluye el punto final)
o
%p el ID de proceso de esta sesión de rsync
o
%P la ruta del módulo
o
%t la fecha y hora actuales
o
%u el nombre de usuario autenticado o una cadena vacía
o
%U el uid del archivo (decimal)
Para obtener una lista de lo que significan los caracteres que produce "%i", consulte la opción --itemize-changes en la página del manual de rsync.
Tenga en cuenta que algunos de los resultados del registro cambian al comunicarse con versiones anteriores de rsync. Por ejemplo, los archivos eliminados solo se mostraban como mensajes detallados antes de rsync 2.6.4.
timeout
Este parámetro le permite anular la elección del cliente para el tiempo de espera de E/S para este módulo. Al utilizar este parámetro, puede asegurarse de que rsync no esperará indefinidamente a un cliente inactivo. El tiempo de espera se especifica en segundos. Un valor de cero significa que no hay tiempo de espera y es el valor predeterminado. Una buena opción para demonios rsync anónimos puede ser 600 (lo que da un tiempo de espera de 10 minutos).
refuse options
Este parámetro le permite especificar una lista de opciones de línea de comandos de rsync separadas por espacios que serán rechazadas por su demonio rsync. Puede especificar el nombre completo de la opción, su abreviatura de una letra, o una cadena comodín que coincida con varias opciones. A partir de la versión 3.2.0, también puede negar una coincidencia comenzándola con un "!".
Cuando se rechaza una opción, el demonio imprime un mensaje de error y sale.
Por ejemplo, esto rechazaría --checksum (-c) y todas las diversas opciones de eliminación: 
refuse options = c delete
La razón por la que lo anterior rechaza todas las opciones de eliminación es que las opciones implican --delete, y las opciones implícitas se rechazan igual que las opciones explícitas.
El uso de una coincidencia negada le permite ajustar sus rechazos después de un comodín, como esto: 
refuse options = delete-* !delete-during
La coincidencia negada también puede convertir tu lista de opciones rechazadas en una lista de opciones aceptadas. Para hacer esto, comienza la lista con un "*" (para rechazar todas las opciones) y luego especifica una o más coincidencias negadas para aceptar. Por ejemplo:
refuse options = * !a !v !compress*
No te preocupes de que el "*" rechace ciertas opciones vitales como --dry-run, --server, --no-iconv, --seclude-args, etc. Estas opciones importantes no se emparejan con comodines, por lo que deben ser anuladas por su nombre exacto. Por ejemplo, si estás forzando transferencias iconv, podrías usar algo como esto:
refuse options = * no-iconv !a !v
Como ayuda adicional (a partir de la versión 3.2.0), rechazar (o "!refusing") la opción "a" o "archive" también afecta a todas las opciones que implica la opción --archive (-rdlptgoD), pero solo si la opción se empareja explícitamente (sin usar un comodín). Si quieres hacer algo complicado, puedes usar "archive*" para evitar este efecto secundario, pero ten en cuenta que ningún cliente rsync normal envía jamás la opción de archivo real al servidor.
Como característica de seguridad adicional, el rechazo de "delete" también rechaza remove-source-files cuando el demonio es el remitente; si deseas esto último sin lo primero, en su lugar rechaza "delete-*", ya que esto rechaza todos los modos de eliminación sin afectar a --remove-source-files. (Ten en cuenta que la opción --delete del cliente normalmente resulta en --delete-during.)
Al volver a permitir las opciones de eliminación, deberías especificar "!delete*" (para aceptar todas las opciones de eliminación) o especificar un conjunto limitado que incluya "delete", como:
refuse options = * !a !delete !delete-during
... mientras que esto acepta cualquier opción de eliminación excepto --delete-after:
refuse options = * !a !delete* delete-after
Una nota sobre el rechazo de "compress": puede ser mejor configurar el parámetro del demonio "dont compress" a "*" y asegurarse de que RSYNC_COMPRESS_LIST=zlib esté configurado en el entorno del demonio para deshabilitar la compresión silenciosamente en lugar de devolver un error que obligue al cliente a eliminar la opción -z.
Si estás volviendo a permitir la opción de compresión, es posible que desees emparejar "!compress*" si también deseas permitir la opción --compress-level.
Ten en cuenta que las opciones "copy-devices" y "write-devices" se rechazan por defecto, pero se pueden aceptar explícitamente con "!copy-devices" y/o "!write-devices". Las opciones "log-file" y "log-file-format" se rechazan forzosamente y no se pueden aceptar.
Aquí están todas las opciones que no se emparejan con comodines:
o
--server: Requerido para que rsync funcione.
o
--rsh, -e: Requerido para transmitir indicadores de compatibilidad al servidor.
o
--out-format: Requerido para transmitir el comportamiento de salida a un receptor remoto. Aunque rsync pasa el alias más antiguo --log-format por razones de compatibilidad, estas opciones no deben confundirse con --log-file-format.
o
--sender: Usa el parámetro "write only" en lugar de rechazar esto.
o
--dry-run, -n: ¿Quién querría deshabilitar esto?
o
--seclude-args, -s: Es el método más antiguo de protección de argumentos.
o
--from0, -0: Facilita la aceptación/rechazo de --files-from sin afectar a este modificador útil.
o
--iconv: Esto se deshabilita automáticamente basándose en el parámetro "charset".
o
--no-iconv: La mayoría de las transferencias usan esta opción.
o
--checksum-seed: Es una opción segura y bastante rara.
o
--write-devices: No es un comodín pero también se deshabilita automáticamente.
dont compress
NOTA: Este parámetro actualmente no tiene ningún efecto excepto en un caso: si se establece en "*", entonces minimiza o deshabilita la compresión para todos los archivos (para aquellos que no quieren rechazar completamente la opción --compress).
Este parámetro te permite seleccionar nombres de archivo basados en patrones de comodín que no deben comprimirse al obtener archivos del demonio (no existe un parámetro análogo para gobernar el envío de archivos a un demonio). La compresión puede ser costosa en términos de uso de CPU, por lo que generalmente es bueno no intentar comprimir archivos que no se comprimirán bien, como archivos ya comprimidos.
El parámetro "dont compress" toma una lista separada por espacios de patrones de comodín sin distinción de mayúsculas y minúsculas. Cualquier nombre de archivo de origen que coincida con uno de los patrones se comprimirá lo menos posible durante la transferencia. Si el algoritmo de compresión tiene un nivel de "apagado", entonces no ocurre ninguna compresión para esos archivos. Si un algoritmo tiene la capacidad de cambiar el nivel a mitad de la transmisión, se minimizará para reducir el uso de CPU tanto como sea posible.
Consulta el parámetro --skip-compress en la página del manual de rsync(1) para ver la lista de sufijos de archivo que se omiten por defecto si este parámetro no está configurado.
early exec, pre-xfer exec, post-xfer exec
Puedes especificar un comando que se ejecutará en las primeras etapas de la conexión, o justo antes y/o después de la transferencia. Si el comando early exec o pre-xfer exec devuelve un código de error, la transferencia se aborta antes de que comience. Cualquier salida del comando pre-xfer exec en stdout (hasta varios KB) se mostrará al usuario al abortar, pero *no* se mostrará si el script devuelve éxito. Los otros programas no pueden enviar ningún texto al usuario. Toda la salida, excepto el stdout del pre-xfer exec, va a stdout/stderr del demonio correspondiente, que generalmente se descarta. Consulta la opción --no-detach para ver una forma de ver la salida del demonio, lo que puede ayudar en la depuración.
Ten en cuenta que el comando early exec se ejecuta antes de que se conozca alguna parte de la solicitud de transferencia, excepto el nombre del módulo. Este script auxiliar se puede usar para configurar un montaje de disco o descifrar datos en un directorio de módulo, pero es posible que necesites usar lock file y max connections para evitar problemas de concurrencia. Si el cliente rsync especificó la opción --early-input=FILE, puede enviar hasta aproximadamente 5 KB de datos a la entrada estándar del script temprano. La entrada estándar estará vacía de lo contrario.
Ten en cuenta que el comando post-xfer exec todavía se ejecuta incluso si uno de los otros scripts devuelve un código de error. Sin embargo, el comando pre-xfer exec *no* se ejecutará si el comando early exec falla.
Las siguientes variables de entorno se establecerán, aunque algunas son específicas del entorno pre-xfer o post-xfer:
o
RSYNC_MODULE_NAME: El nombre del módulo al que se accede.
o
RSYNC_MODULE_PATH: La ruta configurada para el módulo.
o
RSYNC_HOST_ADDR: La dirección IP del host de acceso.
o
RSYNC_HOST_NAME: El nombre del host de acceso.
o
RSYNC_USER_NAME: El nombre del usuario de acceso (vacío si no hay usuario).
o
RSYNC_PID: Un número único para esta transferencia.
o
RSYNC_REQUEST: (solo pre-xfer) La información del módulo/ruta especificada por el usuario. Ten en cuenta que el usuario puede especificar varios archivos de origen, por lo que la solicitud puede ser algo como "mod/path1 mod/path2", etc.
o
RSYNC_ARG#: (solo pre-xfer) Los argumentos pre-solicitud se establecen en estos valores numerados. RSYNC_ARG0 es siempre "rsyncd", seguido de las opciones que se usaron en RSYNC_ARG1, y así sucesivamente. Habrá un valor de "." que indica que las opciones han terminado y que los argumentos de ruta están comenzando -- estos contienen información similar a RSYNC_REQUEST, pero con valores separados y el nombre del módulo eliminado.
o
RSYNC_EXIT_STATUS: (solo post-xfer) el valor de salida del lado del servidor. Será 0 para una ejecución exitosa, un valor positivo para un error generado por el servidor, o -1 si rsync no se cerró correctamente. Ten en cuenta que un error que ocurre en el lado del cliente actualmente no se envía al lado del servidor, por lo que este no es el estado de salida final para toda la transferencia.
o
RSYNC_RAW_STATUS: (solo post-xfer) el valor de salida sin procesar de waitpid().
Aunque los comandos pueden asociarse con un módulo en particular, se ejecutan utilizando los permisos del usuario que inició el demonio (no la configuración uid/gid del módulo) sin ninguna restricción de chroot.
Estas configuraciones respetan 2 variables de entorno: usa RSYNC_SHELL para establecer un shell a usar al ejecutar el comando (que de lo contrario usa el shell predeterminado de tu llamada system()), y usa RSYNC_NO_XFER_EXEC para deshabilitar ambas opciones por completo.

DIRECTIVAS DE CONFIGURACIÓN

Actualmente hay dos directivas de configuración disponibles que permiten que un archivo de configuración incorpore el contenido de otros archivos: &include y &merge. Ambas permiten una referencia a un archivo o a un directorio. Difieren en cuán segregado se considera el contenido del archivo.

La directiva &include trata cada archivo como más distinto, cada uno heredando los valores predeterminados del archivo padre, comenzando el análisis de parámetros como globales/predeterminados y dejando los valores predeterminados sin cambios para el análisis del resto del archivo padre.

La directiva &merge, por otro lado, trata el contenido del archivo como si se insertara en el lugar de la directiva, y por lo tanto puede establecer parámetros en un módulo iniciado en otro archivo, puede afectar los valores predeterminados para otros archivos, etc.

Cuando una directiva &include o &merge hace referencia a un directorio, leerá todos los archivos *.conf o *.inc (respectivamente) que se encuentren dentro de ese directorio (sin escaneo recursivo), con los archivos ordenados alfabéticamente. Por lo tanto, si tiene un directorio llamado "rsyncd.d" con los archivos "foo.conf", "bar.conf" y "baz.conf" dentro de él, esta directiva:

&include /path/rsyncd.d

sería lo mismo que este conjunto de directivas:

&include /path/rsyncd.d/bar.conf
&include /path/rsyncd.d/baz.conf
&include /path/rsyncd.d/foo.conf

excepto que se ajusta a medida que se agregan y eliminan archivos del directorio.

La ventaja de la directiva &include es que puede definir uno o más módulos en un archivo separado sin preocuparse por efectos secundarios no deseados entre los archivos de módulo autocontenidos.

La ventaja de la directiva &merge es que puede cargar fragmentos de configuración que se pueden incluir en múltiples definiciones de módulos, y también puede establecer valores globales que afectarán a las conexiones (como motd file), o globales que afectarán a otros archivos de inclusión.

Por ejemplo, este es un archivo /etc/rsyncd.conf útil:

port = 873
log file = /var/log/rsync.log
pid file = /var/lock/rsync.pid
&merge /etc/rsyncd.d
&include /etc/rsyncd.d

Esto fusionaría cualquier archivo /etc/rsyncd.d/*.inc (para valores globales que deben permanecer en vigor), y luego incluiría cualquier archivo /etc/rsyncd.d/*.conf (definiendo módulos sin ninguna interferencia de valor global).

FUERZA DE AUTENTICACIÓN

El protocolo de autenticación utilizado en rsync es un sistema de respuesta a desafíos basado en MD4 de 128 bits. Sin embargo, esto es una protección bastante débil (con al menos un algoritmo de búsqueda de hash por fuerza bruta disponible públicamente), por lo que si desea una seguridad de alta calidad, le recomiendo que ejecute rsync sobre ssh. (Sí, una versión futura de rsync cambiará a un método de hash más fuerte).

Tenga en cuenta también que el protocolo del demonio rsync actualmente no proporciona ninguna encriptación de los datos que se transfieren a través de la conexión. Solo se proporciona autenticación. Utilice ssh como transporte si desea encriptación.

También puede hacer uso de la encriptación SSL/TLS si coloca rsync detrás de un proxy SSL.

CONFIGURACIÓN DEL DEMONIO SSL/TLS

Al configurar un demonio rsync para acceder a través de SSL/TLS, necesitará configurar un proxy TCP (como haproxy o nginx) como front-end que maneje la encriptación.

o
Debería limitar el acceso al puerto del demonio rsync backend para permitir solo la conexión del proxy. Si está en el mismo host que el proxy, configurarlo para que solo escuche en localhost es una buena idea.
o
Debería considerar activar el parámetro del demonio rsync proxy protocol si su proxy admite el envío de esa información. Los ejemplos a continuación asumen que está habilitado.

Un ejemplo de configuración de haproxy es el siguiente:

frontend fe_rsync-ssl
   bind :::874 ssl crt /etc/letsencrypt/example.com/combined.pem
   mode tcp
   use_backend be_rsync
backend be_rsync
   mode tcp
   server local-rsync 127.0.0.1:873 check send-proxy

Un ejemplo de configuración de proxy nginx es el siguiente:

stream {
   server {
       listen 874 ssl;
       listen [::]:874 ssl;
       ssl_certificate /etc/letsencrypt/example.com/fullchain.pem;
       ssl_certificate_key /etc/letsencrypt/example.com/privkey.pem;
       proxy_pass localhost:873;
       proxy_protocol on; # Requiere rsyncd.conf "proxy protocol = true"
       proxy_timeout 1m;
       proxy_connect_timeout 5s;
   }
}

Si el demonio rsync debe ser accesible encriptado y sin encriptar al mismo tiempo, haga que el proxy escuche también en el puerto 873 y déjelo manejar ambos flujos.

EJEMPLOS DE CONFIGURACIÓN DEL DEMONIO

Un archivo rsyncd.conf simple que permite rsync anónimo a un área ftp en /home/ftp sería:

[ftp]
        path = /home/ftp
        comment = área de exportación ftp

Un ejemplo más sofisticado sería:

uid = nobody
gid = nobody
use chroot = yes
max connections = 4
syslog facility = local5
pid file = /var/run/rsyncd.pid
[ftp]
        path = /var/ftp/./pub
        comment = toda el área ftp (aproximadamente 6,1 GB)
[sambaftp]
        path = /var/ftp/./pub/samba
        comment = área ftp de Samba (aproximadamente 300 MB)
[rsyncftp]
        path = /var/ftp/./pub/rsync
        comment = área ftp de rsync (aproximadamente 6 MB)
[sambawww]
        path = /public_html/samba
        comment = páginas WWW de Samba (aproximadamente 240 MB)
[cvs]
        path = /data/cvs
        comment = repositorio CVS (requiere autenticación)
        auth users = tridge, susan
        secrets file = /etc/rsyncd.secrets

El archivo /etc/rsyncd.secrets se vería algo así:

tridge:mypass
susan:herpass
