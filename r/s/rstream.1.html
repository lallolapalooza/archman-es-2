NOMBRE

rstream - prueba de ping-pong de streaming sobre RDMA.

SINOPSIS

rstream [-s dirección_servidor] [-b dirección_enlace] [-f formato_dirección]
			[-B tamaño_buffer] [-I iteraciones] [-C conteo_transferencia]
			[-S tamaño_transferencia] [-p puerto_servidor] [-T opción_prueba]

DESCRIPCIÓN

Utiliza el protocolo de streaming sobre RDMA (rsocket) para conectar e intercambiar datos entre una aplicación cliente y servidor.

OPCIONES

-s dirección_servidor
El nombre de red o la dirección IP del sistema servidor que escucha las conexiones. El nombre o dirección utilizado debe enrutar a través de un dispositivo RDMA. Esta opción debe ser especificada por el cliente.
-b dirección_enlace
La dirección de red local a la que enlazar.
-f formato_dirección
Los formatos de dirección soportados son ip, ipv6, gid o name.
-B tamaño_buffer
Indica el tamaño de los búferes de red de envío y recepción.
-I iteraciones
El número de veces que se intercambiará el número especificado de mensajes entre el cliente y el servidor. (por defecto 1000)
-C conteo_transferencia
El número de mensajes a transferir desde el cliente al servidor y de vuelta en cada iteración. (por defecto 1000)
-S tamaño_transferencia
El tamaño de cada transferencia de envío, en bytes. (por defecto 1000) Si se especifica 'all', rstream ejecutará una serie de pruebas de varios tamaños.
-p puerto_servidor
El número de puerto del servidor.
-T opción_prueba
Especifica los parámetros de la prueba. Las opciones disponibles son:

s | socket - utiliza llamadas de socket estándar para transferir datos

a | async - utiliza operaciones asíncronas (por ejemplo, select / poll)

b | blocking - utiliza llamadas bloqueantes

f | fork - servidor fork para el procesamiento (fuerza la opción -T s)

n | nonblocking - utiliza llamadas no bloqueantes

r | resolve - utiliza rdma cm para resolver la dirección

v | verify - verifica las transferencias de datos

NOTAS

El uso básico es iniciar rstream en un sistema servidor, luego ejecutar rstream -s nombre_servidor en un sistema cliente. Por defecto, rstream ejecutará una serie de pruebas de rendimiento de latencia y ancho de banda. Especificar un número diferente de iteraciones, conteo_transferencia o tamaño_transferencia ejecutará una prueba personalizada por el usuario usando valores por defecto donde no se hayan especificado.

Dado que esta prueba mapea recursos RDMA al espacio de usuario, los usuarios deben asegurarse de que tienen los recursos del sistema y los permisos disponibles. Consulte el archivo README de libibverbs para obtener más detalles.
