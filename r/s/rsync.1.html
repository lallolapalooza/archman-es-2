rsync(1) Comandos de usuario rsync(1)

NOMBRE

rsync - una herramienta rápida y versátil para copiar archivos (remotos y locales)

SINOPSIS

Local:
    rsync [OPCIÓN...] SRC... [DEST]
Acceso a través de shell remoto:
    Obtener:
        rsync [OPCIÓN...] [USUARIO@]HOST:SRC... [DEST]
    Enviar:
        rsync [OPCIÓN...] SRC... [USUARIO@]HOST:DEST
Acceso a través de daemon rsync:
    Obtener:
        rsync [OPCIÓN...] [USUARIO@]HOST::SRC... [DEST]
        rsync [OPCIÓN...] rsync://[USUARIO@]HOST[:PUERTO]/SRC... [DEST]
    Enviar:
        rsync [OPCIÓN...] SRC... [USUARIO@]HOST::DEST
        rsync [OPCIÓN...] SRC... rsync://[USUARIO@]HOST[:PUERTO]/DEST)

Los usos con un solo argumento SRC y sin argumento DEST listarán los archivos fuente en lugar de copiarlos.

La versión en línea de esta página del manual (que incluye enlaces cruzados entre temas) está disponible en https://download.samba.org/pub/rsync/rsync.1.

DESCRIPCIÓN

Rsync es una herramienta de copia de archivos rápida y extraordinariamente versátil. Puede copiar localmente, hacia/desde otra máquina a través de cualquier shell remoto, o hacia/desde un daemon rsync remoto. Ofrece un gran número de opciones que controlan cada aspecto de su comportamiento y permiten una especificación muy flexible del conjunto de archivos a copiar. Es famoso por su algoritmo de transferencia delta, que reduce la cantidad de datos enviados por la red enviando solo las diferencias entre los archivos de origen y los archivos existentes en el destino. Rsync se utiliza ampliamente para copias de seguridad y replicación, y como un comando de copia mejorado para el uso diario.

Rsync encuentra los archivos que necesitan ser transferidos utilizando un algoritmo de "comprobación rápida" (por defecto) que busca archivos que han cambiado en tamaño o en la hora de última modificación. Cualquier cambio en los otros atributos conservados (según lo solicitado por las opciones) se realiza directamente en el archivo de destino cuando la comprobación rápida indica que los datos del archivo no necesitan ser actualizados.

Algunas de las características adicionales de rsync son:

o
soporte para copiar enlaces, dispositivos, propietarios, grupos y permisos
o
opciones de exclusión y exclusión-desde similares a GNU tar
o
un modo de exclusión CVS para ignorar los mismos archivos que CVS ignoraría
o
puede usar cualquier shell remoto transparente, incluyendo ssh o rsh
o
no requiere privilegios de superusuario
o
pipelining de transferencias de archivos para minimizar los costos de latencia
o
soporte para daemons rsync anónimos o autenticados (ideal para replicación)

GENERAL

Rsync copia archivos ya sea hacia o desde una máquina remota, o localmente en la máquina actual (no soporta copiar archivos entre dos máquinas remotas).

Hay dos maneras diferentes para que rsync contacte a un sistema remoto: usando un programa de shell remoto como transporte (como ssh o rsh) o contactando directamente a un daemon rsync a través de TCP. El transporte de shell remoto se usa siempre que la ruta de origen o destino contenga un único separador de dos puntos (:) después de una especificación de host. Contactar directamente a un daemon rsync ocurre cuando la ruta de origen o destino contiene un separador de dos puntos dobles (::) después de una especificación de host, O cuando se especifica una URL rsync:// (ver también la sección UTILIZANDO FUNCIONALIDADES DE DAEMON RSYNC A TRAVÉS DE UNA CONEXIÓN DE SHELL REMOTO para una excepción a esta última regla).

Como caso especial, si se especifica un único argumento de origen sin destino, los archivos se listan en un formato de salida similar a "ls -l".

Como es de esperar, si ni la ruta de origen ni la de destino especifican una máquina remota, la copia se realiza localmente (ver también la opción --list-only).

Rsync se refiere al lado local como cliente y al lado remoto como servidor. No confundas servidor con un daemon rsync. Un daemon es siempre un servidor, pero un servidor puede ser tanto un daemon como un proceso iniciado por un shell remoto.

CONFIGURACIÓN

Consulta el archivo README.md para obtener instrucciones de instalación.

Una vez instalado, puedes usar rsync en cualquier máquina a la que puedas acceder a través de un shell remoto (así como algunas a las que puedas acceder usando el protocolo de modo daemon de rsync). Para transferencias remotas, un rsync moderno utiliza ssh para sus comunicaciones, pero puede haber sido configurado para usar un shell remoto diferente por defecto, como rsh o remsh.

También puedes especificar cualquier shell remoto que desees, ya sea usando la opción de línea de comandos -e, o configurando la variable de entorno RSYNC_RSH.

Ten en cuenta que rsync debe estar instalado tanto en la máquina de origen como en la de destino.

USO

Usas rsync de la misma manera que usas rcp. Debes especificar un origen y un destino, uno de los cuales puede ser remoto.

Quizás la mejor manera de explicar la sintaxis sea con algunos ejemplos:

rsync -t *.c foo:src/

Esto transferiría todos los archivos que coincidan con el patrón *.c desde el directorio actual al directorio src en la máquina foo. Si alguno de los archivos ya existe en el sistema remoto, se utiliza el protocolo de actualización remota de rsync para actualizar el archivo enviando solo las diferencias en los datos. Ten en cuenta que la expansión de comodines en la línea de comandos (*.c) a una lista de archivos es manejada por el shell antes de ejecutar rsync y no por rsync mismo (exactamente igual que todos los demás programas de estilo Posix).

rsync -avz foo:src/bar /data/tmp

Esto transferiría recursivamente todos los archivos del directorio src/bar en la máquina foo al directorio /data/tmp/bar en la máquina local. Los archivos se transfieren en modo archivo, lo que garantiza que los enlaces simbólicos, dispositivos, atributos, permisos, propietarios, etc. se conserven en la transferencia. Además, se utilizará compresión para reducir el tamaño de las partes de datos de la transferencia.

rsync -avz foo:src/bar/ /data/tmp

Una barra inclinada al final de la fuente cambia este comportamiento para evitar la creación de un nivel de directorio adicional en el destino. Puedes pensar en una barra inclinada final en una fuente como "copiar el contenido de este directorio" en lugar de "copiar el directorio por nombre", pero en ambos casos, los atributos del directorio contenedor se transfieren al directorio contenedor en el destino. En otras palabras, cada uno de los siguientes comandos copia los archivos de la misma manera, incluyendo la configuración de los atributos de /dest/foo:

rsync -av /src/foo /dest
rsync -av /src/foo/ /dest/foo

Ten en cuenta también que las referencias a hosts y módulos no requieren una barra inclinada final para copiar el contenido del directorio predeterminado. Por ejemplo, ambos de estos copian el contenido del directorio remoto en "/dest":

rsync -av host: /dest
rsync -av host::module /dest

También puedes usar rsync en modo solo local, donde tanto el origen como el destino no tienen un ':' en el nombre. En este caso, se comporta como un comando de copia mejorado.

Finalmente, puedes listar todos los módulos (que se pueden listar) disponibles desde un daemon rsync particular omitiendo el nombre del módulo:

rsync somehost.mydomain.com::

COPIANDO UN ÚNICO ELEMENTO

Rsync tiene una regla de sintaxis para copiar archivos únicos que puede ser difícil de recordar. La regla es:

rsync [OPCIÓN]... ORIGEN DESTINO

Cuando el ORIGEN es un único archivo, el DESTINO se trata como un archivo.

Cuando el ORIGEN es un directorio, el DESTINO se trata como un directorio.

Esto significa que si el ORIGEN es un único archivo, el comportamiento de rsync es el mismo que si se usa -r (o -a) y el DESTINO es un archivo, pero si el ORIGEN es un directorio, entonces rsync crea el directorio DESTINO si no existe y copia el contenido del directorio ORIGEN dentro del directorio DESTINO.

Esta regla se aplica cuando el ORIGEN es un único elemento especificado explícitamente en la línea de comandos o cuando un patrón coincide con un solo archivo.

La única forma de obligar a rsync a tratar un ORIGEN de directorio como un directorio es terminar la ruta del ORIGEN con una barra inclinada (/). Por el contrario, la única forma de obligar a rsync a tratar un ORIGEN de archivo como un archivo es no terminar la ruta del ORIGEN con una barra inclinada.

Para que no haya confusión, use la siguiente regla:

  • Si el ORIGEN es un archivo, ¡nunca use una barra inclinada al final!

  • Si el ORIGEN es un directorio, ¡siempre use una barra inclinada al final!

Si copia un único archivo, no puede terminar la ruta de origen con una barra inclinada, por lo que debe usar la sintaxis de barra inclinada final que se muestra arriba solo cuando copie un directorio.

El siguiente ejemplo copia el archivo foo.c como bar.c en el directorio save (asumiendo que bar.c no es un directorio):

rsync -ai src/foo.c save/bar.c

La regla de copia de un solo elemento podría afectarle inadvertidamente si copia un solo elemento sin darse cuenta y especifica un directorio de destino que no existe (sin usar una barra inclinada al final). Por ejemplo, si src/*.c coincide con un archivo y save/dir no existe, esto lo confundirá al nombrar el archivo de destino save/dir:

rsync -ai src/*.c save/dir

Para prevenir tal accidente, asegúrese de que el directorio de destino exista o especifique la ruta de destino con una barra inclinada final:

rsync -ai src/*.c save/dir/

ORDEN DE TRANSFERENCIA ORDENADO

Rsync siempre ordena los nombres de archivo especificados en su lista de transferencia interna. Esto maneja la fusión del contenido de directorios con nombres idénticos y facilita la eliminación de nombres de archivo duplicados. Sin embargo, puede confundir a alguien cuando los archivos se transfieren en un orden diferente al que se dio en la línea de comandos.

Si necesita que un archivo en particular se transfiera antes que otro, sepárelos en diferentes llamadas de rsync o considere usar --delay-updates (que no afecta el orden de transferencia ordenado, pero hace que la fase final de actualización de archivos sea mucho más rápida).

SEGURIDAD MULTIHOSPEDADOR

Rsync toma medidas para garantizar que las solicitudes de archivo que se comparten en una transferencia estén protegidas contra diversos problemas de seguridad. La mayoría de los problemas potenciales surgen en el lado receptor, donde rsync toma medidas para garantizar que la lista de archivos que se transfieren permanezca dentro de los límites de lo que se solicitó.

Con este fin, rsync 3.1.2 y posteriores han abortado cuando una lista de archivos contiene una ruta absoluta o relativa que intenta escapar de la parte superior de la transferencia. Además, a partir de la versión 3.2.5, rsync realiza dos comprobaciones de seguridad más de la lista de archivos para (1) garantizar que no se agregaron argumentos de origen adicionales a la transferencia distintos de los que solicitó el cliente y (2) garantizar que la lista de archivos cumpla con las reglas de exclusión que se enviaron al remitente.

Para aquellos que aún no tienen un cliente rsync 3.2.5 (o aquellos que quieren ser extra cautelosos), lo más seguro es hacer una copia en un directorio de destino dedicado para los archivos remotos cuando no confía en el host remoto. Por ejemplo, en lugar de hacer una copia de rsync en su directorio de inicio:

rsync -aiv host1:dir1 ~

Dedique un directorio "host1-files" al contenido remoto:

rsync -aiv host1:dir1 ~/host1-files

Consulte la opción --trust-sender para obtener detalles adicionales.

PRECAUCIÓN: no es particularmente seguro usar rsync para copiar archivos de un sistema de archivos que conserva las mayúsculas/minúsculas a uno que las ignora. Si debe realizar dicha copia, debería deshabilitar los enlaces simbólicos con --no-links o habilitar la manipulación de enlaces simbólicos con --munge-links (y asegurarse de usar la opción local o remota correcta). Esto evitará que rsync haga cosas potencialmente peligrosas si el nombre de un enlace simbólico se superpone con un archivo o directorio. Sin embargo, no garantiza que obtenga una copia completa de todos los archivos (ya que puede que no sea posible cuando los nombres se superponen). Una solución potencialmente mejor es listar todos los archivos de origen y crear una lista segura de nombres de archivo que pase a la opción --files-from. Los archivos que entren en conflicto de nombre deberán copiarse a directorios de destino diferentes utilizando más de una copia.

Si bien una copia de un sistema de archivos que ignora las mayúsculas/minúsculas a uno que las ignora puede funcionar bastante bien, si no está activa ninguna opción de --delete-during o --delete-before, rsync puede potencialmente actualizar un archivo existente en el lado receptor sin notar que las mayúsculas/minúsculas del nombre de archivo deberían cambiarse para que coincidan con el remitente.

USO AVANZADO

La sintaxis para solicitar varios archivos de un host remoto se realiza especificando argumentos de host remoto adicionales con el mismo estilo que el primero, u omitiendo el nombre del host. Por ejemplo, todos estos funcionan:

rsync -aiv host:file1 :file2 host:file{3,4} /dest/
rsync -aiv host::modname/file{1,2} host::modname/extra /dest/
rsync -aiv host::modname/first ::extra-file{1,2} /dest/

Tenga en cuenta que una conexión de demonio solo admite el acceso a un módulo por comando de copia, por lo que si el inicio de una ruta de seguimiento no comienza con el nombre del módulo de la primera ruta, se asume que es una ruta dentro del módulo (como los extra-file1 y extra-file2 que se obtienen arriba).

Las versiones muy antiguas de rsync (2.6.9 y anteriores) solo permitían especificar un argumento de origen remoto, por lo que algunas personas han confiado en la división de espacios realizada por el shell remoto para dividir un argumento en varias rutas. Tal comportamiento poco intuitivo ya no es compatible de forma predeterminada (aunque puede solicitarlo, como se describe a continuación).

A partir de la versión 3.2.4, los nombres de archivo se pasan a un shell remoto de manera que se preservan los caracteres que usted le da. Por lo tanto, si solicita un archivo con espacios en el nombre, eso es lo que buscará el rsync remoto:

rsync -aiv host:'a simple file.pdf' /dest/

Si utiliza scripts que han sido escritos para aplicar manualmente un cifrado adicional a los argumentos de rsync remotos (o para requerir la división de argumentos remotos), puede solicitar a rsync que permita que su script maneje el cifrado adicional. Esto se hace agregando la opción --old-args a las ejecuciones de rsync en el script (lo que requiere un rsync nuevo) o exportando RSYNC_OLD_ARGS=1 y RSYNC_PROTECT_ARGS=0 (que funciona con versiones antiguas o nuevas de rsync).

CONECTANDO A UN DAEMON RSYNC

También es posible usar rsync sin un shell remoto como transporte. En este caso, se conectará directamente a un daemon rsync remoto, típicamente usando el puerto TCP 873. (Esto obviamente requiere que el daemon se esté ejecutando en el sistema remoto, así que consulte la sección INICIO DE UN DAEMON RSYNC PARA ACEPTAR CONEXIONES a continuación para obtener información sobre eso).

Usar rsync de esta manera es lo mismo que usarlo con un shell remoto, excepto que:

o
Use la sintaxis de doble dos puntos o la sintaxis de URL rsync:// en lugar de la sintaxis de dos puntos (shell remoto).
o
El primer elemento de la "ruta" es en realidad un nombre de módulo.
o
Los argumentos de origen remotos adicionales pueden usar una sintaxis abreviada que omite el nombre del host y/o el nombre del módulo, como se discute en USO AVANZADO.
o
El daemon remoto puede imprimir un "mensaje del día" cuando se conecte.
o
Si especifica solo el host (sin módulo ni ruta), se mostrará una lista de los módulos accesibles en el daemon.
o
Si especifica una ruta de origen remota pero ningún destino, se mostrará una lista de los archivos coincidentes en el daemon remoto.
o
La opción --rsh (-e) debe omitirse para evitar cambiar el estilo de conexión de usar una conexión de socket a USAR FUNCIONES DE DAEMON RSYNC A TRAVÉS DE UNA CONEXIÓN DE SHELL REMOTO.

Un ejemplo que copia todos los archivos en un módulo remoto llamado "src":

rsync -av host::src /dest

Algunos módulos en el daemon remoto pueden requerir autenticación. Si es así, recibirá una solicitud de contraseña cuando se conecte. Puede evitar la solicitud de contraseña estableciendo la variable de entorno RSYNC_PASSWORD a la contraseña que desea usar o utilizando la opción --password-file. Esto puede ser útil al crear scripts de rsync.

ADVERTENCIA: En algunos sistemas, las variables de entorno son visibles para todos los usuarios. En esos sistemas, se recomienda usar --password-file.

Puede establecer la conexión a través de un proxy web estableciendo la variable de entorno RSYNC_PROXY a un par nombre de host:puerto que apunte a su proxy web. Tenga en cuenta que la configuración de su proxy web debe admitir conexiones proxy al puerto 873.

También puede establecer una conexión de daemon usando un programa como proxy estableciendo la variable de entorno RSYNC_CONNECT_PROG a los comandos que desea ejecutar en lugar de realizar una conexión de socket directa. La cadena puede contener el escape "%H" para representar el nombre del host especificado en el comando rsync (así que use "%%" si necesita un solo "%" en su cadena). Por ejemplo:

export RSYNC_CONNECT_PROG='ssh proxyhost nc %H 873'
rsync -av targethost1::module/src/ /dest/
rsync -av rsync://targethost2/module/src/ /dest/

El comando especificado anteriormente usa ssh para ejecutar nc (netcat) en un proxyhost, que reenvía todos los datos al puerto 873 (el daemon rsync) en el targethost (%H).

Tenga en cuenta también que si la variable de entorno RSYNC_SHELL está configurada, ese programa se utilizará para ejecutar el comando RSYNC_CONNECT_PROG en lugar de usar el shell predeterminado de la llamada system().

A veces es útil utilizar varias funciones de un daemon rsync (como módulos con nombre) sin permitir nuevas conexiones de socket a un sistema (más allá de lo que ya se requiere para permitir el acceso de shell remoto). Rsync admite la conexión a un host usando un shell remoto y luego iniciando un servidor "daemon" de uso único que espera leer su archivo de configuración en el directorio de inicio del usuario remoto. Esto puede ser útil si desea cifrar los datos de una transferencia tipo daemon, pero dado que el daemon es iniciado por el usuario remoto, es posible que no pueda usar funciones como chroot o cambiar la UID utilizada por el daemon. OPCIONES

Rsync acepta tanto opciones largas (guión doble + palabra) como cortas (guión simple + letra). La lista completa de opciones disponibles se describe a continuación. Si una opción se puede especificar de más de una manera, las opciones están separadas por comas. Algunas opciones solo tienen una variante larga, no corta.

Si la opción toma un parámetro, el parámetro solo se lista después de la variante larga, aunque también debe especificarse para la corta. Al especificar un parámetro, puede usar el formato --opción=parámetro, --opción parámetro, -o=parámetro, -o parámetro, o -oparámetro (las últimas opciones asumen que su opción tiene una variante corta).

Es posible que el parámetro deba ser citado de alguna manera para que sobreviva al análisis de la línea de comandos del shell. También tenga en cuenta que un guión inicial (~) en una ruta es sustituido por su shell, así que asegúrese de separar el nombre de la opción del nombre del archivo usando un espacio si desea que el shell local lo expanda.

--help
Imprime una página de ayuda corta que describe las opciones disponibles en rsync y sale. También puede usar -h para --help cuando se usa sin ninguna otra opción (ya que normalmente significa --human-readable).
--version, -V
Imprime la versión de rsync más otra información y sale. Cuando se repite, la información se genera en formato JSON que sigue siendo bastante legible (solo del lado del cliente).
La salida incluye una lista de capacidades compiladas, una lista de optimizaciones, la lista predeterminada de algoritmos de suma de verificación, la lista predeterminada de algoritmos de compresión, la lista predeterminada de resúmenes de autenticación de demonios, un enlace al sitio web de rsync y algunos elementos más.
--verbose, -v
Esta opción aumenta la cantidad de información que se le proporciona durante la transferencia. Por defecto, rsync funciona en silencio. Una sola -v le proporcionará información sobre qué archivos se están transfiriendo y un resumen breve al final. Dos opciones -v le darán información sobre qué archivos se están omitiendo y un poco más de información al final. Más de dos opciones -v solo deben usarse si está depurando rsync.
El resumen al final de la ejecución le indica el número de bytes enviados al rsync remoto (que es el lado receptor en una copia local), el número de bytes recibidos del host remoto y el promedio de bytes por segundo de los datos transferidos calculado durante toda la ejecución de rsync. La segunda línea muestra el tamaño total (en bytes), que es la suma de todos los tamaños de archivo que rsync consideró transferir. También muestra un valor de "aceleración", que es una relación del tamaño total del archivo dividido por la suma de los bytes enviados y recibidos (que es realmente solo un número más grande es mejor para sentirse bien). Tenga en cuenta que estos valores de bytes se pueden hacer más (o menos) legibles para humanos usando las opciones --human-readable (o --no-human-readable).
En un rsync moderno, la opción -v es equivalente a la configuración de grupos de opciones --info y --debug. Puede optar por usar estas opciones más nuevas además de, o en lugar de usar --verbose, ya que cualquier configuración detallada anula las configuraciones implícitas de -v. Tanto --info como --debug tienen una forma de solicitar ayuda que le dice exactamente qué indicadores se establecen para cada aumento de verbosidad.
Sin embargo, tenga en cuenta que la configuración de "max verbosity" de un demonio limitará qué tan alto se puede establecer el nivel de los indicadores individuales en el lado del demonio. Por ejemplo, si el máximo es 2, entonces cualquier indicador de información y/o depuración que se establezca en un valor más alto que el que se establecería con -vv se degradará al nivel -vv en el registro del demonio.
--info=FLAGS
Esta opción le permite tener un control detallado sobre la información de salida que desea ver. A un nombre de indicador individual se le puede seguir un número de nivel, donde 0 significa silenciar esa salida, 1 es el nivel de salida predeterminado y números más altos aumentan la salida de ese indicador (para aquellos que admiten niveles más altos). Use --info=help para ver todos los nombres de indicadores disponibles, lo que generan y qué nombres de indicadores se agregan para cada aumento en el nivel de verbosidad. Algunos ejemplos:
rsync -a --info=progress2 src/ dest/
rsync -avv --info=stats2,misc1,flist0 src/ dest/
Tenga en cuenta que la salida de --info=name se ve afectada por las opciones --out-format y --itemize-changes (-i). Consulte esas opciones para obtener más información sobre qué se genera y cuándo.
Esta opción se agregó en 3.1.0, por lo que un rsync más antiguo en el lado del servidor podría rechazar sus intentos de control detallado (si uno o más indicadores debían enviarse al servidor y el servidor era demasiado antiguo para entenderlos). Consulte también la advertencia sobre "max verbosity" anterior cuando trate con un demonio.
--debug=FLAGS
Esta opción le permite tener un control detallado sobre la salida de depuración que desea ver. A un nombre de indicador individual se le puede seguir un número de nivel, donde 0 significa silenciar esa salida, 1 es el nivel de salida predeterminado y números más altos aumentan la salida de ese indicador (para aquellos que admiten niveles más altos). Use --debug=help para ver todos los nombres de indicadores disponibles, lo que generan y qué nombres de indicadores se agregan para cada aumento en el nivel de verbosidad. Algunos ejemplos:
rsync -avvv --debug=none src/ dest/
rsync -avA --del --debug=del2,acl src/ dest/
Tenga en cuenta que algunos mensajes de depuración solo se generarán cuando se especifique la opción --stderr=all, especialmente aquellos relacionados con la depuración de E/S y búferes.
A partir de la versión 3.2.0, esta opción ya no se reenvía automáticamente al lado del servidor para permitirle especificar diferentes valores de depuración para cada lado de la transferencia, así como para especificar una nueva opción de depuración que solo está presente en una de las versiones de rsync. Si desea duplicar la misma opción en ambos lados, usar la expansión de llaves es una forma fácil de ahorrarle escritura. Esto funciona en zsh y bash:
rsync -aiv {-M,}--debug=del2 src/ dest/
--stderr=errors|all|client
Esta opción controla qué procesos envían a stderr y si los mensajes de información también se cambian a stderr. Las cadenas de modo se pueden abreviar, así que siéntase libre de usar un valor de una sola letra. Las 3 opciones posibles son:
o
errors - (el predeterminado) hace que todos los procesos de rsync envíen un error directamente a stderr, incluso si el proceso está en el lado remoto de la transferencia. Los mensajes de información se envían al lado del cliente a través del flujo del protocolo. Si stderr no está disponible (es decir, al conectarse directamente con un demonio a través de un socket), los errores vuelven a enviarse a través del flujo del protocolo.
o
all - hace que todos los mensajes de rsync (información y error) se escriban directamente en stderr desde todos los procesos (posibles). Esto hace que stderr se almacene en búfer por línea (en lugar de crudo) y elimina la capacidad de dividir los mensajes de información y error por identificador de archivo. Para aquellos que depuran o usan varios niveles de verbosidad, esta opción puede ayudar a evitar atascar el flujo de transferencia (lo que debería evitar cualquier posibilidad de que un error de bloqueo cuelgue las cosas). También permite que --debug habilite algunos mensajes adicionales relacionados con E/S.
o
client - hace que todos los mensajes de rsync se envíen al lado del cliente a través del flujo del protocolo. Un proceso cliente genera todos los mensajes, con errores en stderr e información en stdout. Este era el predeterminado en versiones anteriores de rsync, pero puede causar retrasos en los errores cuando hay muchos datos de transferencia antes de los mensajes. Si está enviando archivos a un rsync más antiguo, es posible que desee usar --stderr=all, ya que ese modismo ha existido durante varias versiones.
Esta opción se agregó en rsync 3.2.3. Esta versión también comenzó el reenvío de una configuración no predeterminada al lado remoto, aunque rsync usa las opciones compatibles con versiones anteriores --msgs2stderr y --no-msgs2stderr para representar los ajustes all y client, respectivamente. Un rsync más nuevo continuará aceptando estos nombres de opción más antiguos para mantener la compatibilidad.
--quiet, -q
Esta opción disminuye la cantidad de información que se le proporciona durante la transferencia, suprimiendo notablemente los mensajes informativos del servidor remoto. Esta opción es útil cuando se invoca rsync desde cron.
--no-motd
Esta opción afecta la información que genera el cliente al inicio de una transferencia de demonio. Suprime el texto del mensaje del día (MOTD), pero también afecta la lista de módulos que el demonio envía en respuesta a la solicitud "rsync host::" (debido a una limitación en el protocolo rsync), así que omita esta opción si desea solicitar la lista de módulos del demonio.
--ignore-times, -I
Normalmente rsync omitirá todos los archivos que ya tengan el mismo tamaño y hayan la misma marca de tiempo de modificación. Esta opción desactiva este comportamiento de "verificación rápida", haciendo que todos los archivos se actualicen.
Esta opción puede ser confusa en comparación con --ignore-existing y --ignore-non-existing, ya que estas causan que rsync transfiera menos archivos, mientras que esta opción causa que rsync transfiera más archivos.
--size-only
Esto modifica el algoritmo de "verificación rápida" de rsync para encontrar archivos que necesitan ser transferidos, cambiándolo de la transferencia predeterminada de archivos con tamaño o tiempo de última modificación modificado, a solo buscar archivos que han cambiado de tamaño. Esto es útil al empezar a usar rsync después de usar otro sistema de duplicación que puede no preservar las marcas de tiempo exactamente.
--modify-window=NUM, -@
Al comparar dos marcas de tiempo, rsync considera que las marcas de tiempo son iguales si no difieren en más que el valor de la ventana de modificación. El valor predeterminado es 0, que solo coincide con segundos enteros. Si especifica un valor negativo (y el receptor es al menos la versión 3.1.3), también se tendrán en cuenta los nanosegundos. Especificar 1 es útil para copias hacia/desde sistemas de archivos FAT de MS Windows, ya que FAT representa tiempos con una resolución de 2 segundos (permitiendo que los tiempos difieran del original hasta 1 segundo).
Si desea que todas sus transferencias utilicen por defecto la comparación de nanosegundos, puede crear un archivo ~/.popt y poner estas líneas en él:
rsync alias -a -a@-1
rsync alias -t -t@-1
Con eso como valor predeterminado, necesitaría especificar --modify-window=0 (también conocido como -@0) para anularlo e ignorar los nanosegundos, por ejemplo, si está copiando entre ext3 y ext4, o si el rsync receptor es anterior a 3.1.3.
--checksum, -c
Esto cambia la forma en que rsync verifica si los archivos han sido modificados y necesitan ser transferidos. Sin esta opción, rsync utiliza una "verificación rápida" que (por defecto) comprueba si el tamaño y la hora de la última modificación de cada archivo coinciden entre el remitente y el receptor. Esta opción cambia esto para comparar una suma de verificación de 128 bits para cada archivo que tiene un tamaño coincidente. Generar las sumas de verificación significa que ambos lados consumirán mucha E/S de disco leyendo todos los datos de los archivos en la transferencia, por lo que esto puede ralentizar significativamente (y esto es antes de cualquier lectura que se realizará para transferir archivos modificados).
El lado que envía genera sus sumas de verificación mientras realiza el escaneo del sistema de archivos que crea la lista de archivos disponibles. El receptor genera sus sumas de verificación al escanear archivos modificados, y verificará cualquier archivo que tenga el mismo tamaño que el archivo correspondiente del remitente: los archivos con tamaño modificado o suma de verificación modificada se seleccionan para la transferencia.
Tenga en cuenta que rsync siempre verifica que cada archivo *transferido* se reconstruyó correctamente en el lado receptor mediante la comprobación de una suma de verificación de archivo completo que se genera mientras se transfiere el archivo, pero esa verificación automática después de la transferencia no tiene nada que ver con la comprobación de "¿Es necesario actualizar este archivo?" anterior a la transferencia de esta opción.
La suma de verificación utilizada se negocia automáticamente entre el cliente y el servidor, pero se puede anular utilizando la opción --checksum-choice (--cc) o una variable de entorno que se discute en la sección de esa opción.
--archive, -a
Esto es equivalente a -rlptgoD. Es una forma rápida de decir que desea recursión y desea preservar casi todo. Tenga en cuenta que no incluye la preservación de ACLs (-A), xattrs (-X), atimes (-U), crtimes (-N), ni la búsqueda y preservación de enlaces duros (-H).
La única excepción a la equivalencia anterior es cuando se especifica --files-from, en cuyo caso no se implica -r.
--no-OPTION
Puede desactivar una o más opciones implícitas prefijando el nombre de la opción con "no-". No todas las opciones positivas tienen un opuesto negado, pero muchas lo tienen, incluidas aquellas que se pueden usar para deshabilitar una opción implícita (por ejemplo, --no-D, --no-perms) o que tienen diferentes valores predeterminados en diversas circunstancias (por ejemplo, --no-whole-file, --no-blocking-io, --no-dirs). Cada opción negada válida acepta tanto el nombre de la opción corto como el largo después del prefijo "no-" (por ejemplo, --no-R es lo mismo que --no-relative).
Como ejemplo, si desea usar --archive (-a) pero no desea --owner (-o), en lugar de convertir -a en -rlptgD, puede especificar -a --no-o (también conocido como --archive --no-owner).
El orden de las opciones es importante: si especifica --no-r -a, la opción -r terminará activándose, lo opuesto a -a --no-r. Tenga en cuenta también que los efectos secundarios de la opción --files-from NO son posicionales, ya que afecta al estado predeterminado de varias opciones y cambia ligeramente el significado de -a (consulte la opción --files-from para obtener más detalles).
--recursive, -r
Esto le dice a rsync que copie directorios recursivamente. Vea también --dirs (-d) para una opción que permite el escaneo de un solo directorio.
Consulte la opción --inc-recursive para una discusión sobre la recursión incremental para crear la lista de archivos a transferir.
--inc-recursive, --i-r
Esta opción habilita explícitamente la recursión incremental al buscar archivos, lo cual está habilitado por defecto cuando se utiliza la opción --recursive y ambos lados de la transferencia están ejecutando rsync 3.0.0 o posterior.
La recursión incremental utiliza mucha menos memoria que la no incremental, al mismo tiempo que comienza la transferencia más rápidamente (ya que no necesita escanear toda la jerarquía de transferencia antes de comenzar a transferir archivos). Si no hay recursión habilitada en los archivos de origen, esta opción no tiene efecto.
Algunas opciones requieren que rsync conozca la lista completa de archivos, por lo que estas opciones deshabilitan el modo de recursión incremental. Estas incluyen:
o
--delete-before (el antiguo valor predeterminado de --delete)
o
--delete-after
o
--prune-empty-dirs
o
--delay-updates
Para hacer que --delete sea compatible con la recursión incremental, rsync 3.0.0 estableció --delete-during como el modo de eliminación predeterminado (que se agregó por primera vez en 2.6.4).
Un efecto secundario de la recursión incremental es que cualquier subdirectorio faltante dentro de un directorio escaneado recursivamente se crea (por defecto) antes de recursar en los subdirectorios. Este punto de creación temprano (en comparación con una recursión no incremental) permite a rsync establecer la hora de modificación del directorio completado de inmediato (sin tener que retrasar eso hasta que una gran cantidad de copias recursivas hayan finalizado). Sin embargo, estos directorios tempranos aún no tienen su modo, mtime o propiedad completados; tienen derechos más restrictivos hasta que comience la copia del subdirectorio. Este modismo de creación temprana se puede evitar utilizando la opción --omit-dir-times.
La recursión incremental se puede deshabilitar usando la opción --no-inc-recursive (--no-i-r).
--no-inc-recursive, --no-i-r
Deshabilita el nuevo algoritmo de recursión incremental de la opción --recursive. Esto hace que rsync escanee la lista completa de archivos antes de comenzar a transferir archivos. Vea --inc-recursive para más información.
--relative, -R
Usa rutas relativas. Esto significa que los nombres de ruta completos especificados en la línea de comandos se envían al servidor en lugar de solo las partes finales de los nombres de archivo. Esto es particularmente útil cuando desea enviar varios directorios diferentes al mismo tiempo. Por ejemplo, si usara este comando:
rsync -av /foo/bar/baz.c remote:/tmp/
crearía un archivo llamado baz.c en /tmp/ en la máquina remota. Si en cambio usara
rsync -avR /foo/bar/baz.c remote:/tmp/
entonces se crearía un archivo llamado /tmp/foo/bar/baz.c en la máquina remota, conservando su ruta completa. Estos elementos de ruta adicionales se denominan "directorios implícitos" (es decir, los directorios "foo" y "foo/bar" en el ejemplo anterior).
A partir de rsync 3.0.0, rsync siempre envía estos directorios implícitos como directorios reales en la lista de archivos, incluso si un elemento de ruta es realmente un enlace simbólico en el lado de envío. Esto evita algunos comportamientos realmente inesperados al copiar la ruta completa de un archivo que no sabías que tenía un enlace simbólico en su ruta. Si desea duplicar un enlace simbólico del lado del servidor, incluya tanto el enlace simbólico a través de su ruta como el directorio referente a través de su ruta real. Si está tratando con un rsync más antiguo en el lado de envío, es posible que deba usar la opción --no-implied-dirs.
También es posible limitar la cantidad de información de ruta que se envía como directorios implícitos para cada ruta que especifique. Con un rsync moderno en el lado de envío (a partir de 2.6.7), puede insertar un punto y una barra en la ruta de origen, de esta manera:
rsync -avR /foo/./bar/baz.c remote:/tmp/
Eso crearía /tmp/bar/baz.c en la máquina remota. (Tenga en cuenta que el punto debe ir seguido de una barra, por lo que "/foo/." no se abreviaría). Para versiones anteriores de rsync, necesitaría usar un chdir para limitar la ruta de origen. Por ejemplo, al enviar archivos:
(cd /foo; rsync -avR bar/baz.c remote:/tmp/)
(Tenga en cuenta que los paréntesis ponen los dos comandos en un sub-shell, de modo que el comando "cd" no permanece en vigor para comandos futuros). Si está extrayendo archivos de un rsync más antiguo, use este modismo (pero solo para una transferencia que no sea de demonio):
rsync -avR --rsync-path="cd /foo; rsync" \
     remoto:bar/baz.c /tmp/
--no-implied-dirs
Esta opción afecta el comportamiento predeterminado de la opción --relative. Cuando se especifica, los atributos de los directorios implícitos de los nombres de origen no se incluyen en la transferencia. Esto significa que los elementos de ruta correspondientes en el sistema de destino se dejan sin cambios si existen, y cualquier directorio implícito faltante se crea con atributos predeterminados. Esto permite que estos elementos de ruta implícitos tengan grandes diferencias, como ser un enlace simbólico a un directorio en el lado receptor.
Por ejemplo, si un argumento de línea de comandos o una entrada de archivos-desde le indicó a rsync que transfiriera el archivo "ruta/foo/archivo", los directorios "ruta" y "ruta/foo" se implican cuando se usa --relative. Si "ruta/foo" es un enlace simbólico a "bar" en el sistema de destino, el rsync receptor normalmente eliminaría "ruta/foo", lo recrearía como un directorio y recibiría el archivo en el nuevo directorio. Con --no-implied-dirs, el rsync receptor actualiza "ruta/foo/archivo" utilizando los elementos de ruta existentes, lo que significa que el archivo se crea en "ruta/bar". Otra forma de lograr esta preservación de enlaces es usar la opción --keep-dirlinks (que también afectará a los enlaces simbólicos a directorios en el resto de la transferencia).
Al extraer archivos de un rsync anterior a la versión 3.0.0, puede que necesite usar esta opción si el lado emisor tiene un enlace simbólico en la ruta que solicita y desea que los directorios implícitos se transfieran como directorios normales.
--backup, -b
Con esta opción, los archivos de destino preexistentes se renombran cada vez que se transfiere o elimina un archivo. Puede controlar dónde va el archivo de copia de seguridad y qué sufijo (si alguno) se añade utilizando las opciones --backup-dir y --suffix.
Si no especifica --backup-dir:
1.
la opción --omit-dir-times se forzará a activarse
2.
el uso de --delete (sin --delete-excluded), hace que rsync añada una regla de filtro de "protección" para el sufijo de copia de seguridad al final de todos sus filtros existentes que se ve así: -f "P *~". Esta regla evita que se eliminen los archivos respaldados previamente.
Tenga en cuenta que si está proporcionando sus propias reglas de filtro, es posible que necesite insertar manualmente su propia regla de exclusión/protección en algún lugar más arriba en la lista para que tenga prioridad suficiente para ser efectiva (por ejemplo, si sus reglas especifican una inclusión/exclusión final de *, la regla añadida automáticamente nunca se alcanzaría).
--backup-dir=DIR
Esto implica la opción --backup y le dice a rsync que almacene todas las copias de seguridad en el directorio especificado en el lado receptor. Esto se puede usar para copias de seguridad incrementales. Adicionalmente, puede especificar un sufijo de copia de seguridad usando la opción --suffix (de lo contrario, los archivos respaldados en el directorio especificado conservarán sus nombres de archivo originales).
Tenga en cuenta que si especifica una ruta relativa, el directorio de copias de seguridad será relativo al directorio de destino, por lo que probablemente querrá especificar una ruta absoluta o una ruta que comience con "../". Si un demonio de rsync es el receptor, el directorio de copias de seguridad no puede salir de la jerarquía de rutas del módulo, así que tenga especial cuidado de no eliminarlo ni copiar en él.
--suffix=SUFFIX
Esta opción le permite anular el sufijo de copia de seguridad predeterminado utilizado con la opción --backup (-b). El sufijo predeterminado es un ~ si no se especificó --backup-dir, de lo contrario es una cadena vacía.
--update, -u
Esto fuerza a rsync a omitir cualquier archivo que exista en el destino y tenga una fecha de modificación más reciente que el archivo de origen. (Si un archivo de destino existente tiene una fecha de modificación igual a la del archivo de origen, se actualizará si los tamaños son diferentes).
Tenga en cuenta que esto no afecta la copia de directorios, enlaces simbólicos u otros archivos especiales. Además, una diferencia en el formato del archivo entre el emisor y el receptor siempre se considera lo suficientemente importante como para una actualización, sin importar la fecha de los objetos. En otras palabras, si el origen tiene un directorio donde el destino tiene un archivo, la transferencia ocurrirá independientemente de las marcas de tiempo.
Esta opción es una REGLA DE TRANSFERENCIA, así que no espere ningún efecto secundario de exclusión.
Una advertencia para aquellos que eligen combinar --inplace con --update: una transferencia interrumpida dejará un archivo parcial en el lado receptor con una fecha de modificación muy reciente, por lo que volver a ejecutar la transferencia probablemente no continuará con el archivo interrumpido. Como tal, generalmente es mejor evitar combinar esto con --inplace a menos que haya implementado pasos manuales para manejar cualquier archivo en curso interrumpido.
--inplace
Esta opción cambia cómo rsync transfiere un archivo cuando sus datos necesitan ser actualizados: en lugar del método predeterminado de crear una nueva copia del archivo y moverla a su lugar cuando está completa, rsync escribe los datos actualizados directamente en el archivo de destino.
Esto tiene varios efectos:
o
Los enlaces duros no se rompen. Esto significa que los nuevos datos serán visibles a través de otros enlaces duros al archivo de destino. Además, los intentos de copiar archivos de origen diferentes en un archivo de destino múltiples enlazados darán como resultado una "lucha" con los datos de destino que cambian de un lado a otro.
o
Los binarios en uso no se pueden actualizar (el sistema operativo evitará que esto suceda, o los binarios que intentan cargar sus datos en memoria se comportarán mal o fallarán).
o
Los datos del archivo estarán en un estado inconsistente durante la transferencia y permanecerán así si la transferencia se interrumpe o si una actualización falla.
o
Un archivo en el que rsync no puede escribir no se puede actualizar. Si bien un superusuario puede actualizar cualquier archivo, un usuario normal debe tener permiso de escritura para que la apertura del archivo para escritura sea exitosa.
o
La eficiencia del algoritmo de transferencia diferencial de rsync puede verse reducida si algunos datos en el archivo de destino se sobrescriben antes de que puedan copiarse a una posición posterior en el archivo. Esto no se aplica si usa --backup, ya que rsync es lo suficientemente inteligente como para usar el archivo de copia de seguridad como archivo base para la transferencia.
ADVERTENCIA: no debe usar esta opción para actualizar archivos que están siendo accedidos por otros, así que tenga cuidado al elegir usarla para una copia.
Esta opción es útil para transferir archivos grandes con cambios basados en bloques o datos añadidos, y también en sistemas que están limitados por disco, no por red. También puede ayudar a evitar que una instantánea de sistema de archivos de copia en escritura diverja todo el contenido de un archivo que solo tiene cambios menores.
La opción implica --partial (ya que una transferencia interrumpida no elimina el archivo), pero entra en conflicto con --partial-dir y --delay-updates. Antes de rsync 2.6.4, --inplace también era incompatible con --compare-dest y --link-dest.
--append
Este modo de copia especial solo funciona para actualizar eficientemente archivos que se sabe que están creciendo, donde el contenido existente en el lado receptor también se sabe que es el mismo que el contenido en el emisor. El uso de --append puede ser peligroso si no está 100% seguro de que todos los archivos en la transferencia son archivos compartidos y en crecimiento. Por lo tanto, debe usar reglas de filtro para asegurarse de eliminar cualquier archivo que no cumpla con estos criterios.
Rsync actualiza estos archivos en crecimiento en su lugar sin verificar ningún contenido existente en el archivo (solo verifica el contenido que está añadiendo). Rsync omite cualquier archivo que exista en el lado receptor que no sea más corto que el archivo asociado en el lado emisor (lo que significa que los archivos nuevos se transfieren). También omite cualquier archivo cuyo tamaño en el lado emisor se acorte durante las negociaciones de envío (rsync advierte sobre un archivo "disminuido" cuando esto sucede).
Esto no interfiere con la actualización de los atributos no de contenido de un archivo (por ejemplo, permisos, propiedad, etc.) cuando el archivo no necesita ser transferido, ni afecta la actualización de ningún directorio o archivo no regular.
--append-verify
Este modo de copia especial funciona como --append excepto que todos los datos del archivo se incluyen en la verificación de la suma de verificación (lo que lo hace menos eficiente pero también potencialmente más seguro). Esta opción puede ser peligrosa si no está 100% seguro de que todos los archivos en la transferencia son archivos compartidos y en crecimiento. Consulte la opción --append para obtener más detalles.
Nota: antes de rsync 3.0.0, la opción --append funcionaba como --append-verify, por lo que si interactúa con un rsync más antiguo (o la transferencia usa un protocolo anterior a 30), especificar cualquiera de las opciones de append iniciará una transferencia --append-verify.
--dirs, -d
Indica al lado emisor que incluya los directorios que se encuentren. A diferencia de --recursive, el contenido de un directorio no se copia a menos que el nombre del directorio especificado sea "." o termine con una barra inclinada (por ejemplo, ".", "dir/.", "dir/", etc.). Sin esta opción o la opción --recursive, rsync omitirá todos los directorios que encuentre (y emitirá un mensaje a tal efecto para cada uno). Si especifica tanto --dirs como --recursive, --recursive tiene prioridad.
La opción --dirs está implícita por la opción --fil

Este es un alias para --no-motd. Se puede usar para evitar la impresión de mensajes de bienvenida o de cierre del daemon en el cliente. Cuando se utiliza con una transferencia de directorios, esta opción también asegura que la opción implícita --list-only se aplique a los directorios si no se especificó --recursive (para que los directorios se vean en la lista). Especifique --no-dirs (o --no-d) si desea desactivar esto.

También existe una opción de ayuda para compatibilidad con versiones anteriores, --old-dirs (--old-d) que le dice a rsync que use un truco de -r --exclude='/*/*' para que una versión anterior de rsync liste un solo directorio sin recursar.

--hard-links, -H
Esto le dice a rsync que busque archivos enlazados físicamente en el origen y que enlace los archivos correspondientes en el destino. Sin esta opción, los archivos enlazados físicamente en el origen se tratan como si fueran archivos separados.
Esta opción NO garantiza necesariamente que el patrón de enlaces físicos en el destino coincida exactamente con el del origen. Los casos en los que el destino puede terminar con enlaces físicos adicionales incluyen los siguientes:
o
Si el destino contiene enlaces físicos superfluos (más enlaces de los presentes en la lista de archivos de origen), el algoritmo de copia no los romperá explícitamente. Sin embargo, si una o más de las rutas tienen diferencias de contenido, el proceso normal de actualización de archivos romperá esos enlaces adicionales (a menos que esté utilizando la opción --inplace).
o
Si especifica un directorio --link-dest que contiene enlaces físicos, el enlace de los archivos de destino contra los archivos de --link-dest puede hacer que algunas rutas en el destino se enlacen debido a las asociaciones de --link-dest.
Tenga en cuenta que rsync solo puede detectar enlaces físicos entre archivos que se encuentran dentro del conjunto de transferencia. Si rsync actualiza un archivo que tiene conexiones de enlace físico adicionales con archivos fuera de la transferencia, ese enlace se romperá. Si se siente tentado a usar la opción --inplace para evitar esta ruptura, tenga mucho cuidado de saber cómo se están actualizando sus archivos para estar seguro de que no ocurran cambios no deseados debido a enlaces físicos pendientes (y consulte la opción --inplace para ver más advertencias).
Si la recursión incremental está activa (ver --inc-recursive), rsync puede transferir un archivo enlazado físicamente que falta antes de encontrar que otro enlace para ese contenido existe en otro lugar de la jerarquía. Esto no afecta la precisión de la transferencia (es decir, qué archivos están enlazados físicamente entre sí), solo su eficiencia (es decir, la copia de datos para una copia nueva y temprana de un archivo enlazado físicamente que podría haberse encontrado más tarde en la transferencia en otro miembro del conjunto de archivos enlazados físicamente). Una forma de evitar esta ineficiencia es deshabilitar la recursión incremental usando la opción --no-inc-recursive.
--perms, -p
Esta opción hace que el rsync receptor establezca los permisos del destino para que sean los mismos que los permisos del origen. (Ver también la opción --chmod para una forma de modificar lo que rsync considera los permisos de origen).
Cuando esta opción está *desactivada*, los permisos se establecen de la siguiente manera:
o
Los archivos existentes (incluidos los archivos actualizados) conservan sus permisos existentes, aunque la opción --executability podría cambiar solo el permiso de ejecución del archivo.
o
Los archivos nuevos obtienen sus bits de permiso "normales" establecidos en los permisos del archivo de origen enmascarados con los permisos predeterminados del directorio receptor (ya sea la umask del proceso receptor o los permisos especificados a través de la ACL predeterminada del directorio receptor), y sus bits de permiso especiales deshabilitados, excepto en el caso en que un nuevo directorio herede un bit setgid de su directorio padre.
Por lo tanto, cuando --perms y --executability están ambos deshabilitados, el comportamiento de rsync es el mismo que el de otras utilidades de copia de archivos, como cp(1) y tar(1).
En resumen: para dar a los archivos de destino (tanto antiguos como nuevos) los permisos de origen, use --perms. Para dar a los archivos nuevos los permisos predeterminados del destino (dejando intactos los archivos existentes), asegúrese de que la opción --perms esté desactivada y use --chmod=ugo=rwX (que asegura que todos los bits no enmascarados se habiliten). Si desea hacer que este último comportamiento sea más fácil de escribir, podría definir un alias de popt para él, como poner esta línea en el archivo ~/.popt (lo siguiente define la opción -Z e incluye --no-g para usar el grupo predeterminado del directorio de destino):
rsync alias -Z --no-p --no-g --chmod=ugo=rwX
Luego podría usar esta nueva opción en un comando como este:
rsync -avZ src/ dest/
(Advertencia: asegúrese de que -a no siga a -Z, o re-habilitará las dos opciones --no-* mencionadas anteriormente).
La preservación del bit setgid del destino en directorios recién creados cuando --perms está desactivado se agregó en rsync 2.6.7. Las versiones anteriores de rsync preservaban erróneamente los tres bits de permiso especiales para los archivos recién creados cuando --perms estaba desactivado, mientras que anulaban la configuración del bit setgid del destino en un directorio recién creado. La observancia de ACL predeterminadas se agregó al parche de ACL para rsync 2.6.7, por lo que las versiones anteriores de rsync (o las que no habilitan ACL) usan la umask incluso si hay ACL predeterminadas presentes. (Tenga en cuenta que es la versión del rsync receptor la que afecta estos comportamientos).
--executability, -E
Esta opción hace que rsync preserve la ejecutabilidad (o no ejecutabilidad) de los archivos regulares cuando --perms no está habilitado. Un archivo regular se considera ejecutable si al menos una 'x' está activada en sus permisos. Cuando la ejecutabilidad de un archivo de destino existente difiere de la del archivo de origen correspondiente, rsync modifica los permisos del archivo de destino de la siguiente manera:
o
Para hacer que un archivo no sea ejecutable, rsync desactiva todos sus permisos 'x'.
o
Para hacer que un archivo sea ejecutable, rsync activa cada permiso 'x' que tenga un permiso 'r' correspondiente habilitado.
Si --perms está habilitado, esta opción se ignora.
--acls, -A
Esta opción hace que rsync actualice las ACL del destino para que sean las mismas que las ACL del origen. La opción también implica --perms.
Los sistemas de origen y destino deben tener entradas ACL compatibles para que esta opción funcione correctamente. Consulte la opción --fake-super para obtener una forma de respaldar y restaurar ACL que no son compatibles.
--xattrs, -X
Esta opción hace que rsync actualice los atributos extendidos del destino para que sean los mismos que los del origen.
Para sistemas que admiten espacios de nombres de atributos extendidos, una copia realizada por un superusuario copia todos los espacios de nombres excepto system.*. Un usuario normal solo copia el espacio de nombres user.*. Para poder respaldar y restaurar espacios de nombres que no son de usuario como un usuario normal, consulte la opción --fake-super.
El filtrado de nombres anterior se puede anular utilizando una o más opciones de filtro con el modificador x. Cuando especifica una regla de filtro que afecta a los atributos extendidos, rsync requiere que realice su propio filtrado de sistema/usuario, así como cualquier filtrado adicional para qué nombres de atributos extendidos se copian y qué nombres se permiten eliminar. Por ejemplo, para omitir el espacio de nombres del sistema, podría especificar:
--filter='-x system.*'
Para omitir todos los espacios de nombres excepto el espacio de nombres del usuario, podría especificar una coincidencia de usuario negada:
--filter='-x! user.*'
Para evitar que se eliminen atributos, podría especificar una regla solo para el receptor que excluya todos los nombres:
--filter='-xr *'
Tenga en cuenta que la opción -X no copia valores especiales de atributos extendidos de rsync (por ejemplo, los utilizados por --fake-super) a menos que repita la opción (por ejemplo, -XX). Este modo de "copiar todos los atributos extendidos" no se puede usar con --fake-super.
--chmod=CHMOD
Esta opción le dice a rsync que aplique uno o más modos de "chmod" separados por comas a los permisos de los archivos en la transferencia. El valor resultante se trata como si fueran los permisos que el lado del envío proporcionó para el archivo, lo que significa que esta opción puede parecer no tener ningún efecto en los archivos existentes si --perms no está habilitado.
Además de las reglas de análisis normales especificadas en la página del manual de chmod(1), puede especificar un elemento que solo se aplique a un directorio prefijándolo con una 'D', o especificar un elemento que solo se aplique a un archivo prefijándolo con una 'F'. Por ejemplo, lo siguiente asegurará que todos los directorios obtengan el bit set-gid, que ningún archivo sea escribible por otros, que ambos sean escribibles por el usuario y el grupo, y que ambos tengan una ejecutabilidad consistente en todos los bits:
--chmod=Dg+s,ug+w,Fo-w,+X
También se permite usar números de modo octal:
--chmod=D2775,F664
También es legal especificar múltiples opciones --chmod, ya que cada opción adicional simplemente se agrega a la lista de cambios a realizar.
Consulte las opciones --perms y --executability para ver cómo se puede aplicar el valor de permiso resultante a los archivos en la transferencia.
--owner, -o
Esta opción hace que rsync establezca el propietario del archivo de destino para que sea el mismo que el archivo de origen, pero solo si el rsync receptor se está ejecutando como superusuario (ver también las opciones --super y --fake-super). Sin esta opción, el propietario de los archivos nuevos y/o transferidos se establece en el usuario que invoca en el lado receptor.
La preservación de la propiedad asociará nombres coincidentes por defecto, pero puede recurrir al uso del ID nu
mber en algunas circunstancias (ver también la opción --numeric-ids para una discusión completa).
--group, -g
Esta opción hace que rsync establezca el grupo del archivo de destino para que sea el mismo que el del archivo de origen. Si el programa receptor no se está ejecutando como el superusuario (o si se especificó --no-super), solo se conservarán los grupos de los que el usuario invocador en el lado receptor es miembro. Sin esta opción, el grupo se establece en el grupo predeterminado del usuario invocador en el lado receptor.
La preservación de la información del grupo asociará nombres coincidentes por defecto, pero puede recurrir al uso del número de ID en algunas circunstancias (ver también la opción --numeric-ids para una discusión completa).
--devices
Esta opción hace que rsync transfiera archivos de dispositivos de caracteres y bloques al sistema remoto para recrear estos dispositivos. Si el rsync receptor no se está ejecutando como superusuario, rsync omite silenciosamente la creación de los archivos de dispositivos (ver también las opciones --super y --fake-super).
Por defecto, rsync genera una advertencia de "archivo no regular" para cada archivo de dispositivo encontrado cuando esta opción no está establecida. Puede silenciar la advertencia especificando --info=nonreg0.
--specials
Esta opción hace que rsync transfiera archivos especiales, como sockets con nombre y FIFOs. Si el rsync receptor no se está ejecutando como superusuario, rsync omite silenciosamente la creación de los archivos especiales (ver también las opciones --super y --fake-super).
Por defecto, rsync genera una advertencia de "archivo no regular" para cada archivo especial encontrado cuando esta opción no está establecida. Puede silenciar la advertencia especificando --info=nonreg0.
-D
La opción -D es equivalente a "--devices --specials".
--copy-devices
Esto indica a rsync que trate un dispositivo en el lado de envío como un archivo regular, lo que permite copiarlo a un archivo de destino normal (o a otro dispositivo si también se especificó --write-devices).
Esta opción es rechazada por defecto por un demonio rsync.
--write-devices
Esto indica a rsync que trate un dispositivo en el lado receptor como un archivo regular, lo que permite escribir datos de archivos en un dispositivo.
Esta opción implica la opción --inplace.
Tenga cuidado al usar esto, ya que debe saber qué dispositivos están presentes en el lado receptor de la transferencia, especialmente al ejecutar rsync como root.
Esta opción es rechazada por defecto por un demonio rsync.
--times, -t
Esto indica a rsync que transfiera las horas de modificación junto con los archivos y las actualice en el sistema remoto. Tenga en cuenta que si esta opción no se utiliza, la optimización que excluye los archivos que no se han modificado no puede ser efectiva; en otras palabras, la ausencia de -t (o -a) hará que la próxima transferencia se comporte como si usara --ignore-times (-I), lo que provocará que todos los archivos se actualicen (aunque el algoritmo de transferencia delta de rsync hará que la actualización sea bastante eficiente si los archivos no han cambiado realmente, es mucho mejor usar -t).
Un rsync moderno que utiliza el protocolo de transferencia 30 o 31 transmite una hora de modificación utilizando hasta 8 bytes. Si rsync se ve obligado a utilizar un protocolo más antiguo (quizás debido a que el rsync remoto sea anterior a 3.0.0) se transmite una hora de modificación utilizando 4 bytes. Antes de la versión 3.2.7, estos valores de 4 bytes podían transmitir un rango de fechas del 13 de diciembre de 1901 al 19 de enero de 2038. A partir de la versión 3.2.7, estos valores de 4 bytes ahora transmiten un rango de fechas del 1 de enero de 1970 al 7 de febrero de 2106. Si tiene archivos con fechas anteriores a 1970, asegúrese de que sus ejecutables de rsync estén actualizados para que se pueda transmitir el rango completo de fechas.
--atimes, -U
Esto indica a rsync que establezca las horas de acceso (uso) de los archivos de destino en el mismo valor que los archivos de origen.
Si se repite, también establece la opción --open-noatime, que puede ayudar a que los sistemas de envío y recepción tengan las mismas horas de acceso en los archivos transferidos sin necesidad de ejecutar rsync una vez más después de que se transfiera un archivo.
Tenga en cuenta que algunas versiones antiguas de rsync (anteriores a la 3.2.0) pueden haber sido compiladas con un parche de --atimes pre-lanzamiento que no implica --open-noatime cuando esta opción se repite.
--open-noatime
Esto indica a rsync que abra los archivos con la bandera O_NOATIME (en sistemas que la soporten) para evitar cambiar la hora de acceso de los archivos que se están transfiriendo. Si su SO no soporta la bandera O_NOATIME, entonces rsync ignorará silenciosamente esta opción. Tenga en cuenta también que algunos sistemas de archivos se montan para evitar actualizar el atime en el acceso de lectura incluso sin que la bandera O_NOATIME esté establecida.
--crtimes, -N,
Esto indica a rsync que establezca las horas de creación (novedad) de los archivos de destino en el mismo valor que los archivos de origen. Su SO y sistema de archivos deben soportar el establecimiento de horas de creación (nacimiento) arbitrarias para que esta opción sea soportada.
--omit-dir-times, -O
Esto indica a rsync que omita los directorios cuando preserve las horas de modificación, acceso y creación. Si NFS está compartiendo los directorios en el lado receptor, es una buena idea usar -O. Esta opción se infiere si usa --backup sin --backup-dir.
Esta opción también tiene el efecto secundario de evitar la creación temprana de subdirectorios faltantes cuando la recursión incremental está habilitada, como se discute en la sección --inc-recursive.
--omit-link-times, -J
Esto indica a rsync que omita los enlaces simbólicos al preservar las horas de modificación, acceso y creación.
--super
Esto indica al lado receptor que intente realizar actividades de superusuario incluso si el rsync receptor no fue ejecutado por el superusuario. Estas actividades incluyen: preservar usuarios a través de la opción --owner, preservar todos los grupos (no solo los grupos del usuario actual) a través de la opción --group, y copiar dispositivos a través de la opción --devices. Esto es útil para sistemas que permiten tales actividades sin ser el superusuario, y también para asegurar que obtendrá errores si el lado receptor no se está ejecutando como superusuario. Para desactivar las actividades de superusuario, el superusuario puede usar --no-super.
--fake-super
Cuando esta opción está habilitada, rsync simula actividades de superusuario guardando/restaurando los atributos privilegiados a través de atributos extendidos especiales que se adjuntan a cada archivo (según sea necesario). Esto incluye el propietario y el grupo del archivo (si no es el predeterminado), la información del dispositivo del archivo (los dispositivos y archivos especiales se crean como archivos de texto vacíos), y cualquier bit de permiso que no permitiremos que se establezca en el archivo real (por ejemplo, el archivo real obtiene u-s,g-s,o-t por seguridad) o que limitaría el acceso del propietario (ya que el superusuario real siempre puede acceder/cambiar un archivo, los archivos que creamos pueden ser siempre accedidos/cambiados por el usuario que los crea). Esta opción también maneja ACLs (si se especificó --acls) y atributos extendidos no de usuario (si se especificó --xattrs).
Esta es una buena manera de hacer copias de seguridad de datos sin usar un superusuario, y para almacenar ACLs de sistemas incompatibles.
La opción --fake-super solo afecta al lado donde se utiliza la opción. Para afectar al lado remoto de una conexión de shell remoto, use la opción --remote-option (-M):
rsync -av -M--fake-super /src/ host:/dest/
Para una copia local, esta opción afecta tanto al origen como al destino. Si desea que una copia local habilite esta opción solo para los archivos de destino, especifique -M--fake-super. Si desea que una copia local habilite esta opción solo para los archivos de origen, combine --fake-super con -M--super.
Esta opción es anulada por ambas, --super y --no-super.
Ver también la configuración fake super en el archivo rsyncd.conf del demonio.
--sparse, -S
Intenta manejar archivos dispersos de manera eficiente para que ocupen menos espacio en el destino. Si se combina con --inplace, el archivo creado podría no terminar con bloques dispersos con algunas combinaciones de versión del kernel y/o tipo de sistema de archivos. Si --whole-file está en efecto (por ejemplo, para una copia local), entonces siempre funcionará porque rsync trunca el archivo antes de escribir la versión actualizada.
Tenga en cuenta que las versiones de rsync anteriores a la 3.1.3 rechazarán la combinación de --sparse y --inplace.
--preallocate
Esto indica al receptor que asigne cada archivo de destino a su tamaño final antes de escribir datos en el archivo. Rsync solo utilizará el soporte de preasignación a nivel de sistema de archivos real proporcionado por la llamada al sistema fallocate(2) de Linux o posix_fallocate(3) de Cygwin, no la lenta implementación de glibc que escribe un byte nulo en cada bloque.
Sin esta opción, los archivos más grandes pueden no ser completamente contiguos en el sistema de archivos, pero con esta opción rsync probablemente copiará más lentamente. Si el destino no es un sistema de archivos que admita extensiones (como ext4, xfs, NTFS, etc.), esta opción puede no tener ningún efecto positivo.
Si se combina con --sparse, el archivo solo tendrá bloques dispersos (en lugar de secuencias de bytes nulos asignados) si la versión del kernel y el tipo de sistema de archivos admiten la creación de agujeros en los datos asignados.
--dry-run, -n
Esto hace que rsync realice una ejecución de prueba que no realiza ningún cambio (y produce una salida en su mayor parte similar a una ejecución real). Se usa más comúnmente en combinación con las opciones --verbose (-v) y/o --itemize-changes (-i) para ver qué va a hacer un comando rsync antes de ejecutarlo realmente.

--dry-run, -n
This performs a trial run with no changes made. Rsync will tell you what it would do, but not actually transfer any files, delete any files, or run any commands. The output of a dry run should be exactly the same on a dry run and a subsequent real run (barring intentional trickery and system call failures); if it isn't, that's a bug. Other output should be mostly unchanged, but may differ in some areas. Notably, a dry run does not send the actual data for file transfers, so --progress has no effect, the "bytes sent", "bytes received", "literal data", and "matched data" statistics are too small, and the "speedup" value is equivalent to a run where no file transfers were needed.
--whole-file, -W
This option disables rsync's delta-transfer algorithm, which causes all transferred files to be sent whole. The transfer may be faster if this option is used when the bandwidth between the source and destination machines is higher than the bandwidth to disk (especially when the "disk" is actually a networked filesystem). This is the default when both the source and destination are specified as local paths, but only if no batch-writing option is in effect.
--no-whole-file, --no-W
Disable whole-file updating when it is enabled by default for a local transfer. This usually slows rsync down, but it can be useful if you are trying to minimize the writes to the destination file (if combined with --inplace) or for testing the checksum-based update algorithm.
See also the --whole-file option.

If two comma-separated names are supplied, the first name affects the transfer checksums, and the second name affects the pre-transfer checksums (-c).

If "none" is specified for the first (or only) name, the --whole-file option is forced on and no checksum verification is performed on the transferred data. If "none" is specified for the second (or only) name, the --checksum option cannot be used.
The "auto" option is the default, where rsync bases its algorithm choice on a negotiation between the client and the server as follows:
When both sides of the transfer are at least 3.2.0, rsync chooses the first algorithm in the client's list of choices that is also in the server's list of choices. If no common checksum choice is found, rsync exits with an error. If the remote rsync is too old to support checksum negotiation, a value is chosen based on the protocol version (which chooses between MD5 and various flavors of MD4 based on protocol age).
The default order can be customized by setting the environment variable RSYNC_CHECKSUM_LIST to a space-separated list of acceptable checksum names. --one-file-system, -x
This tells rsync to avoid crossing a filesystem boundary when recursing. This does not limit the user's ability to specify items to copy from multiple filesystems, just rsync's recursion through the hierarchy of each directory that the user specified, and also the analogous recursion on the receiving side during deletion. Also keep in mind that rsync treats a "bind" mount to the same device as being on the same filesystem.
If this option is repeated, rsync omits all mount-point directories from the copy. Otherwise, it includes an empty directory at each mount-point it encounters (using the attributes of the mounted directory because those of the underlying mount-point directory are inaccessible).
If rsync has been told to collapse symlinks (via --copy-links or --copy-unsafe-links), a symlink to a directory on another device is treated like a mount-point. Symlinks to non-directories are unaffected by this option.
--ignore-non-existing, --existing
This tells rsync to skip creating files (including directories) that do not exist yet on the destination. If this option is combined with the --ignore-existing option, no files will be updated (which can be useful if all you want to do is delete extraneous files).
This option is a TRANSFER RULE, so don't expect any exclude side effects.
--ignore-existing
This tells rsync to skip updating files that already exist on the destination (this does not ignore existing directories, or nothing would get done). See also --ignore-non-existing.
This option is a TRANSFER RULE, so don't expect any exclude side effects.
This option can be useful for those doing backups using the --link-dest option when they need to continue a backup run that got interrupted. Since a --link-dest run is copied into a new directory hierarchy (when it is used properly), using [--ignore-existing will ensure that the already-handled files don't get tweaked (which avoids a change in permissions on the hard-linked files). This does mean that this option is only looking at the existing files in the destination hierarchy itself.
When --info=skip2 is used rsync will output "FILENAME exists (INFO)" messages where the INFO indicates one of "type change", "sum change" (requires -c), "file change" (based on the quick check), "attr change", or "uptodate". Using --info=skip1 (which is also implied by 2 -v options) outputs the exists message without the INFO suffix.
--remove-source-files
This tells rsync to remove from the sending side the files (meaning non-directories) that are a part of the transfer and have been successfully duplicated on the receiving side.
Note that you should only use this option on source files that are quiescent. If you are using this to move files that show up in a particular directory over to another host, make sure that the finished files get renamed into the source directory, not directly written into it, so that rsync can't possibly transfer a file that is not yet fully written. If you can't first write the files into a different directory, you should use a naming idiom that lets rsync avoid transferring files that are not yet finished (e.g. name the file "foo.new" when it is written, rename it to "foo" when it is done, and then use the option --exclude='*.new' for the rsync transfer).
Starting with 3.1.0, rsync will skip the sender-side removal (and output an error) if the file's size or modify time has not stayed unchanged.
Starting with 3.2.6, a local rsync copy will ensure that the sender does not remove a file the receiver just verified, such as when the user accidentally makes the source and destination directory the same path.
--delete
This tells rsync to delete extraneous files from the receiving side (ones that aren't on the sending side), but only for the directories that are being synchronized. You must have asked rsync to send the whole directory (e.g. "dir" or "dir/") without using a wildcard for the directory's contents (e.g. "dir/*") since the wildcard is expanded by the shell and rsync thus gets a request to transfer individual files, not the files' parent directory. Files that are excluded from the transfer are also excluded from being deleted unless you use the --delete-excluded option or mark the rules as only matching on the sending side (see the include/exclude modifiers in the FILTER RULES section).
Prior to rsync 2.6.7, this option would have no effect unless --recursive was enabled. Beginning with 2.6.7, deletions will also occur when --dirs (-d) is enabled, but only for directories whose contents are being copied.
This option can be dangerous if used incorrectly! It is a very good idea to first try a run using the --dry-run (-n) option to see what files are going to be deleted.
If the sending side detects any I/O errors, then the deletion of any files at the destination will be automatically disabled. This is to prevent temporary filesystem failures (such as NFS errors) on the sending side from causing a massive deletion of files on the destination. You can override this with the --ignore-errors option.
The --delete option may be combined with one of the --delete-WHEN options without conflict, as well as --delete-excluded. However, if none of the --delete-WHEN options are specified, rsync will choose the --delete-during algorithm when talking to rsync 3.0.0 or newer, or the --delete-before algorithm when
talking to an older rsync. Véase también --delete-delay y --delete-after.
--delete-before
Solicita que las eliminaciones de archivos en el lado receptor se realicen antes de que comience la transferencia. Véase --delete (que está implícito) para más detalles sobre la eliminación de archivos.
Eliminar antes de la transferencia es útil si el sistema de archivos tiene poco espacio y eliminar archivos innecesarios ayudaría a posibilitar la transferencia. Sin embargo, introduce un retraso antes del inicio de la transferencia, y este retraso podría hacer que la transferencia expire (si se especificó --timeout). También obliga a rsync a usar el algoritmo de recursión antiguo y no incremental que requiere que rsync escanee todos los archivos de la transferencia en memoria a la vez (véase --recursive).
--delete-during, --del
Solicita que las eliminaciones de archivos en el lado receptor se realicen incrementalmente a medida que ocurre la transferencia. El escaneo de eliminación por directorio se realiza justo antes de que se verifiquen las actualizaciones en cada directorio, por lo que se comporta como un --delete-before más eficiente, incluyendo la realización de las eliminaciones antes de que se actualicen los archivos de filtro por directorio. Esta opción se agregó por primera vez en la versión 2.6.4 de rsync. Véase --delete (que está implícito) para más detalles sobre la eliminación de archivos.
--delete-delay
Solicita que las eliminaciones de archivos en el lado receptor se calculen durante la transferencia (como --delete-during), y luego se eliminen después de que la transferencia se complete. Esto es útil cuando se combina con --delay-updates y/o --fuzzy, y es más eficiente que usar --delete-after (pero puede comportarse de manera diferente, ya que --delete-after calcula las eliminaciones en un pase separado después de que se completan todas las actualizaciones). Si el número de archivos eliminados excede un búfer interno, se creará un archivo temporal en el lado receptor para almacenar los nombres (se elimina mientras está abierto, por lo que no debería verlo durante la transferencia). Si la creación del archivo temporal falla, rsync intentará recurrir a usar --delete-after (lo que no puede hacer si --recursive está realizando un escaneo incremental). Véase --delete (que está implícito) para más detalles sobre la eliminación de archivos.
--delete-after
Solicita que las eliminaciones de archivos en el lado receptor se realicen después de que la transferencia se haya completado. Esto es útil si está enviando nuevos archivos de fusión por directorio como parte de la transferencia y desea que sus exclusiones tengan efecto para la fase de eliminación de la transferencia actual. También obliga a rsync a usar el algoritmo de recursión antiguo y no incremental que requiere que rsync escanee todos los archivos de la transferencia en memoria a la vez (véase --recursive). Véase --delete (que está implícito) para más detalles sobre la eliminación de archivos.
Véase también la opción --delete-delay que podría ser una opción más rápida para aquellos que solo quieren que las eliminaciones ocurran al final de la transferencia.
--delete-excluded
Esta opción convierte cualquier regla de exclusión/inclusión no calificada en reglas del lado del servidor que no afecten las eliminaciones del receptor.
Por defecto, una exclusión o inclusión tiene tanto un efecto en el lado del servidor (para "ocultar" y "mostrar" archivos al construir la lista de archivos del servidor) como un efecto en el lado del receptor (para "proteger" y "arriesgar" archivos cuando ocurren eliminaciones). Cualquier regla que no tenga un modificador para especificar en qué lados se ejecuta se tratará en su lugar como si fuera solo una regla del lado del servidor, evitando cualquier efecto de "protección" de las reglas.
Una regla aún puede aplicarse a ambos lados, incluso con esta opción especificada, si la regla recibe las letras modificadoras de remitente y receptor (por ejemplo, -f'-sr foo'). Las reglas de protección/riesgo del lado del receptor también se pueden especificar explícitamente para limitar las eliminaciones. Esto le ahorra tener que editar un montón de reglas -f'- foo' en -f'-s foo' (también conocido como -f'H foo') (sin mencionar las inclusiones correspondientes).
Véase la sección REGLAS DE FILTRO para más información. Véase --delete (que está implícito) para más detalles sobre la eliminación.
--ignore-missing-args
Cuando rsync está procesando inicialmente los archivos de origen solicitados explícitamente (por ejemplo, argumentos de línea de comandos o entradas de --files-from), normalmente es un error si el archivo no se encuentra. Esta opción suprime ese error y no intenta transferir el archivo. Esto no afecta a los errores posteriores de archivos desaparecidos si un archivo se encontró inicialmente presente y más tarde ya no está.
--delete-missing-args
Esta opción lleva el comportamiento de la opción (implícita) --ignore-missing-args un paso más allá: cada argumento faltante se convertirá en una solicitud de eliminación del archivo de destino correspondiente en el lado receptor (si existe). Si el archivo de destino es un directorio no vacío, solo se eliminará con éxito si --force o --delete están en vigor. Aparte de eso, esta opción es independiente de cualquier otro tipo de procesamiento de eliminación.
Los archivos de origen faltantes se representan mediante entradas especiales de lista de archivos que se muestran como una entrada "*missing" en la salida de --list-only.
--ignore-errors
Indica a --delete que continúe y elimine archivos incluso cuando haya errores de E/S.
--force
Esta opción indica a rsync que elimine un directorio no vacío cuando este deba ser reemplazado por un no directorio. Esto solo es relevante si las eliminaciones no están activas (véase --delete para más detalles).
Nota para versiones anteriores de rsync: --force solía ser necesario incluso cuando se usaba --delete-after, y solía ser no funcional a menos que la opción --recursive también estuviera habilitada.
--max-delete=NUM
Esto indica a rsync que no elimine más de NUM archivos o directorios. Si ese límite se excede, todas las eliminaciones posteriores se omiten hasta el final de la transferencia. Al final, rsync muestra una advertencia (incluyendo un recuento de las eliminaciones omitidas) y sale con un código de error 25 (a menos que ocurra alguna condición de error más importante).
A partir de la versión 3.0.0, puede especificar --max-delete=0 para que se le advierta sobre cualquier archivo externo en el destino sin eliminar ninguno de ellos. Los clientes más antiguos interpretaban esto como "ilimitado", por lo que si no sabe qué versión tiene el cliente, puede usar el menos obvio --max-delete=-1 como una forma compatible con versiones anteriores para especificar que no se permitan eliminaciones (aunque las versiones muy antiguas no advertían cuando se superaba el límite).
--max-size=SIZE
Esto indica a rsync que evite transferir cualquier archivo que sea más grande que el SIZE especificado. Un valor numérico puede ir seguido de una cadena para indicar las unidades numéricas o dejarse sin calificar para especificar bytes. Siéntase libre de usar un valor fraccional junto con las unidades, como --max-size=1.5m.
Esta opción es una REGLA DE TRANSFERENCIA, así que no espere ningún efecto secundario de exclusión.
La primera letra de una cadena de unidades puede ser B (bytes), K (kilo), M (mega), G (giga), T (tera) o P (peta). Si la cadena es un solo carácter o tiene "ib" añadido (por ejemplo, "G" o "GiB"), las unidades son múltiplos de 1024. Si usa un sufijo de dos letras que termina en "B" (por ejemplo, "kb"), obtendrá unidades que son múltiplos de 1000. Las letras de la cadena pueden ser cualquier combinación de mayúsculas y minúsculas que desee utilizar.
Finalmente, si la cadena termina en "+1" o "-1", se desplaza en un byte en la dirección indicada. El valor más grande posible suele ser 8192P-1.
Ejemplos: --max-size=1.5mb-1 son 1499999 bytes, y --max-size=2g+1 son 2147483649 bytes.
Tenga en cuenta que las versiones de rsync anteriores a 3.1.0 no permitían --max-size=0.
--min-size=SIZE
Esto indica a rsync que evite transferir cualquier archivo que sea más pequeño que el SIZE especificado, lo que puede ayudar a no transferir archivos pequeños y basura. Véase la opción --max-size para una descripción de SIZE y otra información.
Tenga en cuenta que las versiones de rsync anteriores a 3.1.0 no permitían --min-size=0.
--max-alloc=SIZE
Por defecto, rsync limita cada asignación individual de malloc/realloc a aproximadamente 1 GB de tamaño. Para la mayoría de las personas, este límite funciona perfectamente y evita que un error de protocolo haga que rsync solicite una gran cantidad de memoria. Sin embargo, si tiene muchos millones de archivos en una transferencia, una gran cantidad de memoria del servidor y no desea dividir su transferencia en varias partes, puede aumentar el límite por asignación a algo más grande y rsync consumirá más memoria.
Tenga en cuenta que este no es un límite en el tamaño total de la memoria asignada. Es un valor de verificación de cordura para cada asignación individual.
Véase la opción --max-size para una descripción de cómo se puede especificar SIZE. El sufijo predeterminado si no se proporciona ninguno son bytes.
A partir de la versión 3.2.7, un valor de 0 es una forma fácil de especificar SIZE_MAX (el límite más grande posible).
Puede establecer un valor predeterminado utilizando la variable de entorno RSYNC_MAX_ALLOC utilizando los mismos valores de SIZE que soporta esta opción. Si el rsync remoto no entiende la opción --max-alloc, puede anular un valor ambiental especificando --max-alloc=1g, lo que hará que rsync evite enviar la opción al lado remoto (porque "1G" es el valor predeterminado).
--block-size=SIZE, -B
Esto fuerza que el tamaño del bloque utilizado en el algoritmo de transferencia delta de rsync sea un valor fijo. Normalmente se selecciona en función del tamaño de cada archivo que se está actualizando. Véase el informe técnico para más detalles.
A partir de la versión 3.2.3, el SIZE se puede especificar con un sufijo como se detalla en la opción --max-size. Las versiones anteriores solo aceptaban un recuento de bytes.

--rsync-path=PROGRAMA
Úselo para especificar qué programa se ejecutará en la máquina remota para iniciar rsync. A menudo se usa cuando rsync no está en la ruta del shell remoto por defecto (por ejemplo, --rsync-path=/usr/local/bin/rsync). Tenga en cuenta que PROGRAMA se ejecuta con la ayuda de un shell, por lo que puede ser cualquier programa, script o secuencia de comandos que desee ejecutar, siempre que no corrompa la entrada estándar y la salida estándar que rsync está utilizando para comunicarse.
Un ejemplo complicado es establecer un directorio por defecto diferente en la máquina remota para usarlo con la opción --relative. Por ejemplo:
rsync -avR --rsync-path="cd /a/b && rsync" host:c/d /e/
--remote-option=OPCIÓN, -M
Esta opción se utiliza para situaciones más avanzadas en las que desea que ciertos efectos se limiten a un solo lado de la transferencia. Por ejemplo, si desea pasar --log-file=ARCHIVO y --fake-super al sistema remoto, especifíquelo de la siguiente manera:
rsync -av -M --log-file=foo -M--fake-super src/ dest/
Si desea que una opción afecte solo al lado local de una transferencia cuando normalmente afecta a ambos lados, envíe su negación al lado remoto. Así:
rsync -av -x -M--no-x src/ dest/
Tenga cuidado al usar esto, ya que es posible activar una opción que haga que rsync tenga una idea diferente sobre qué datos esperar a continuación en el socket, y eso hará que falle de forma críptica.
Tenga en cuenta que debe usar una opción -M separada para cada opción remota que desee pasar. En versiones anteriores de rsync, la presencia de espacios en el argumento de opción remota podría hacer que se dividiera en argumentos remotos separados, pero esto requiere el uso de --old-args en un rsync moderno.
Al realizar una transferencia local, el lado "local" es el emisor y el lado "remoto" es el receptor.
Tenga en cuenta que algunas versiones de la biblioteca de análisis de opciones popt tienen un error que le impide usar un argumento adyacente con un igual junto a una letra de opción corta (por ejemplo, -M--log-file=/tmp/foo). Si este error afecta a su versión de popt, puede usar la versión de popt que se incluye con rsync.
--cvs-exclude, -C
Este es un atajo útil para excluir una amplia gama de archivos que a menudo no desea transferir entre sistemas. Utiliza un algoritmo similar a CVS para determinar si un archivo debe ser ignorado.
La lista de exclusión se inicializa para excluir los siguientes elementos (estos elementos iniciales están marcados como perecederos -- ver la sección REGLAS DE FILTRO):

luego, se agregan los archivos listados en $HOME/.cvsignore a la lista y cualquier archivo listado en la variable de entorno CVSIGNORE (todos los nombres de cvsignore están delimitados por espacios en blanco).
Finalmente, se ignora cualquier archivo si está en el mismo directorio que un archivo .cvsignore y coincide con uno de los patrones listados allí. A diferencia de los archivos de filtro/exclusión de rsync, estos patrones se dividen en espacios en blanco. Ver el manual de cvs(1) para más información.
Si está combinando -C con sus propias reglas --filter, debe tener en cuenta que estas exclusiones de CVS se agregan al final de sus propias reglas, independientemente de dónde se colocó -C en la línea de comandos. Esto las hace de menor prioridad que cualquier regla que haya especificado explícitamente. Si desea controlar dónde se insertan estas exclusiones de CVS en sus reglas de filtro, debe omitir -C como opción de línea de comandos y usar una combinación de --filter=:C y --filter=-C (ya sea en su línea de comandos o colocando las reglas "":C"" y ""-C"" en un archivo de filtro con sus otras reglas). La primera opción activa el escaneo por directorio del archivo .cvsignore. La segunda opción realiza una importación única de las exclusiones de CVS mencionadas anteriormente.
--filter=REGLA, -f
Esta opción le permite agregar reglas para excluir selectivamente ciertos archivos de la lista de archivos a transferir. Esto es más útil en combinación con una transferencia recursiva.
Puede usar tantas opciones --filter en la línea de comandos como desee para construir la lista de archivos a excluir. Si el filtro contiene espacios en blanco, asegúrese de ponerlo entre comillas para que el shell le dé la regla a rsync como un solo argumento. El texto a continuación también menciona que puede usar un guion bajo para reemplazar el espacio que separa una regla de su argumento.
Ver la sección REGLAS DE FILTRO para obtener información detallada sobre esta opción.
-F
La opción -F es un atajo para agregar dos reglas --filter a su comando. La primera vez que se usa es un atajo para esta regla:
--filter='dir-merge /.rsync-filter'
Esto le dice a rsync que busque archivos .rsync-filter por directorio que se han esparcido por la jerarquía y use sus reglas para filtrar los archivos en la transferencia. Si -F se repite, es un atajo para esta regla:
--filter='exclude .rsync-filter'
Esto filtra los propios archivos .rsync-filter de la transferencia.
Ver la sección REGLAS DE FILTRO para obtener información detallada sobre cómo funcionan estas opciones.
--exclude=PATRÓN
Esta opción es una forma simplificada de la opción --filter que especifica una regla de exclusión y no permite la sintaxis completa de análisis de reglas de las reglas de filtro normales. Esto es equivalente a especificar -f'- PATRÓN'.
Ver la sección REGLAS DE FILTRO para obtener información detallada sobre esta opción.
--exclude-from=ARCHIVO
Esta opción está relacionada con la opción --exclude, pero especifica un ARCHIVO que contiene patrones de exclusión (uno por línea). Las líneas en blanco en el archivo se ignoran, al igual que los comentarios de línea completa que comienzan con ';' o '#' (las reglas de nombres de archivo que contienen esos caracteres no se ven afectadas).
Si una línea comienza con "- " (guion, espacio) o "+ " (más, espacio), entonces el tipo de regla se especifica explícitamente como exclusión o inclusión (respectivamente). Cualquier regla sin dicho prefijo se considera una exclusión.
Si una línea consiste únicamente en "!", entonces las reglas de filtro actuales se borran antes de agregar cualquier regla adicional.
Si ARCHIVO es '-', la lista se leerá de la entrada estándar.
--include=PATRÓN

Ver la sección REGLAS DE FILTRO para obtener información detallada sobre esta opción.
--include-from=ARCHIVO

Si una línea comienza con "- " (guion, espacio) o "+ " (más, espacio), entonces el tipo de regla se especifica explícitamente como una exclusión o una inclusión (respectivamente). Cualquier regla sin tal prefijo se considera una inclusión.

--files-from=FILE
Usar esta opción te permite especificar la lista exacta de archivos a transferir (leída del FILE especificado o '-' para entrada estándar). También ajusta el comportamiento predeterminado de rsync para facilitar la transferencia solo de los archivos y directorios especificados:
o
Se implica la opción --relative (-R), que conserva la información de ruta especificada para cada elemento en el archivo (usa --no-relative o --no-R si deseas desactivarla).
o
Se implica la opción --dirs (-d), que creará directorios especificados en la lista en el destino en lugar de omitirlos ruidosamente (usa --no-dirs o --no-d si deseas desactivarla).
o
El comportamiento de la opción --archive (-a) no implica --recursive (-r), así que especifícala explícitamente si la deseas.
o
Estos efectos secundarios cambian el estado predeterminado de rsync, por lo que la posición de la opción --files-from en la línea de comandos no tiene influencia en cómo se analizan otras opciones (por ejemplo, -a funciona igual antes o después de --files-from, al igual que --no-R y todas las demás opciones).
Los nombres de archivo que se leen del archivo FILE son todos relativos al directorio fuente ; se eliminan las barras iniciales y no se permiten referencias ".." para subir más allá del directorio fuente. Por ejemplo, toma este comando:
rsync -a --files-from=/tmp/foo /usr remote:/backup
Si /tmp/foo contiene la cadena "bin" (o incluso "/bin"), el directorio /usr/bin se creará como /backup/bin en el host remoto. Si contiene "bin/" (nota la barra inclinada final), el contenido inmediato del directorio también se enviará (sin necesidad de ser mencionado explícitamente en el archivo; esto comenzó en la versión 2.6.4). En ambos casos, si la opción -r estuviera habilitada, la jerarquía completa de ese directorio también se transferiría (ten en cuenta que -r necesita ser especificada explícitamente con --files-from, ya que no está implícita por -a. Ten en cuenta también que el efecto de la opción (habilitada por defecto) -r es duplicar solo la información de ruta leída del archivo; no fuerza la duplicación de la ruta de especificación de origen (en este caso, /usr).
Además, el archivo --files-from se puede leer desde el host remoto en lugar del host local si especificas un "host:" delante del archivo (el host debe coincidir con un extremo de la transferencia). Como atajo, puedes especificar solo un prefijo de ":" para indicar "usar el extremo remoto de la transferencia". Por ejemplo:
rsync -a --files-from=:/path/file-list src:/ /tmp/copy
Esto copiaría todos los archivos especificados en el archivo /path/file-list que estuviera ubicado en el host remoto "src".
Si las opciones --iconv y --secluded-args se especifican y los nombres de archivo de --files-from se envían de un host a otro, los nombres de archivo se traducirán del juego de caracteres del host de envío al juego de caracteres del host de recepción.
NOTA: ordenar la lista de archivos en la entrada de --files-from ayuda a rsync a ser más eficiente, ya que evitará volver a visitar los elementos de ruta compartidos entre entradas adyacentes. Si la entrada no está ordenada, algunos elementos de ruta (directorios implícitos) pueden ser escaneados varias veces, y rsync eventualmente los desduplicará después de que se conviertan en elementos de lista de archivos.
--from0, -0
Esto le indica a rsync que las reglas/nombres de archivo que lee de un archivo están terminados por un carácter nulo ('\0'), no por un NL, CR o CR+LF. Esto afecta a --exclude-from, --include-from, --files-from, y cualquier archivo fusionado especificado en una regla de --filter. No afecta a --cvs-exclude (ya que todos los nombres leídos de un archivo .cvsignore se dividen por espacios en blanco).
--old-args
Esta opción le indica a rsync que deje de intentar proteger los valores de argumento en el lado remoto de la división involuntaria de palabras u otra mala interpretación. También permite al cliente tratar un argumento vacío como "." en lugar de generar un error.
El valor predeterminado en un rsync moderno es que los caracteres "shell-active" (incluidos los espacios) se escapan con una barra invertida en los argumentos que se envían al shell remoto. Los caracteres comodín *, ?, [, y ] no se escapan en los argumentos de nombre de archivo (permitiendo que se expandan en múltiples nombres de archivo) mientras se protegen en los argumentos de opción, como --usermap.
Si tienes un script que quiere usar la división de argumentos de estilo antiguo en sus nombres de archivo, especifica esta opción una vez. Si el shell remoto tiene problemas con alguna barra invertida de escape, especifica esta opción dos veces.
También puedes controlar esta configuración a través de la variable de entorno RSYNC_OLD_ARGS. Si tiene el valor "1", rsync usará por defecto una configuración de opción única. Si tiene el valor "2" (o más), rsync usará por defecto una configuración de opción repetida. Si es "0", obtendrás el comportamiento de escape predeterminado. El entorno siempre se anula mediante opciones positivas o negativas especificadas manualmente (la negativa es --no-old-args).
Ten en cuenta que esta opción también deshabilita la verificación de seguridad adicional agregada en 3.2.5 que asegura que un remitente remoto no está incluyendo elementos de nivel superior adicionales en la lista de archivos que no solicitaste. Este efecto secundario es necesario porque no podemos saber con certeza qué nombres esperar cuando el shell remoto está interpretando los argumentos.
Esta opción entra en conflicto con la opción --secluded-args.
--secluded-args, -s
Esta opción envía todos los nombres de archivo y la mayoría de las opciones a rsync remoto a través del protocolo (no a la línea de comandos del shell remoto), lo que evita que el shell remoto los modifique. Los comodines se expanden en el host remoto por rsync en lugar de por un shell.
Esto es similar al escape de argumentos predeterminado con barra invertida que se agregó en 3.2.4 (ver --old-args) ya que previene la división de espacios y efectos secundarios de caracteres especiales no deseados. Sin embargo, tiene el inconveniente de ser incompatible con versiones anteriores de rsync (anteriores a 3.0.0) y de ser rechazado por shells restringidos que quieren poder inspeccionar todos los valores de opción por seguridad.
Esta opción es útil para aquellas ocasiones en las que necesitas que el juego de caracteres del argumento se convierta para el host remoto, si el shell remoto es incompatible con el método de escape de barra invertida predeterminado, o si hay alguna otra razón por la que deseas que la mayoría de las opciones y argumentos eviten la línea de comandos del shell remoto.
Si combinas esta opción con --iconv, los argumentos relacionados con el lado remoto se traducirán del juego de caracteres local al remoto. La traducción ocurre antes de que se expandan los comodines. Ver también la opción --files-from.
También puedes controlar esta configuración a través de la variable de entorno RSYNC_PROTECT_ARGS. Si tiene un valor distinto de cero, esta configuración se habilitará por defecto, de lo contrario se deshabilitará por defecto. Cualquiera de los estados se anula con una versión positiva o negativa especificada manualmente de esta opción (ten en cuenta que --no-s y --no-secluded-args son las versiones negativas). Esta variable de entorno también se ve anulada por una exportación no nula de RSYNC_OLD_ARGS.
Esta opción entra en conflicto con la opción --old-args.
Esta opción solía llamarse --protect-args (antes de 3.2.6) y ese nombre antiguo todavía se puede usar (aunque especificarla como -s es siempre la opción más fácil y compatible).
--trust-sender
Esta opción deshabilita dos verificaciones de validación adicionales que un cliente local realiza sobre la lista de archivos generada por un remitente remoto. Esta opción solo debe usarse si confías en que el remitente no incluirá algo malicioso en la lista de archivos (algo que posiblemente podría hacerse a través de un rsync modificado, un shell modificado o alguna manipulación similar).
Normalmente, el cliente rsync (a partir de la versión 3.2.5) ejecuta dos verificaciones de validación adicionales al obtener archivos de un rsync remoto:
o
Verifica que no se hayan agregado elementos de argumento adicionales en la parte superior de la transferencia.
o
Verifica que ninguno de los elementos de la lista de archivos sean nombres que deberían haber sido excluidos (si se especificaron reglas de filtro).
Ten en cuenta que varias opciones pueden desactivar una o ambas de estas verificaciones si la opción interfiere con la validación. Por ejemplo:
o
Usar un archivo de filtro por directorio lee reglas de filtro que solo el servidor conoce, por lo que la verificación de filtro se deshabilita.
o
Usar la opción --old-args permite al remitente manipular los argumentos solicitados, por lo que la verificación de argumentos se deshabilita.
o
Leer la lista de archivos desde el lado del servidor significa que el cliente no conoce la lista de argumentos, por lo que la verificación de argumentos se deshabilita.
o
Usar --read-batch deshabilita ambas verificaciones ya que el archivo de lote's los contenidos habrán sido verificados cuando se crearon.
Esta opción puede ayudar a un cliente servidor de poca potencia si el análisis de patrones adicional está ralentizando una transferencia enorme. También se puede utilizar para solucionar un error desconocido actualmente en la lógica de verificación de una transferencia de un remitente de confianza.
Al usar esta opción, es una buena idea especificar un directorio de destino dedicado, como se discute en la sección de SEGURIDAD MULTIMÁQUINA.
--copy-as=USUARIO[:GRUPO]
Esta opción indica a rsync que use el USUARIO y (si se especifica después de dos puntos) el GRUPO para las operaciones de copia. Esto solo funciona si el usuario que ejecuta rsync tiene la capacidad de cambiar de usuario. Si no se especifica el grupo, se utilizan los grupos predeterminados del usuario.
Esta opción puede ayudar a reducir el riesgo de que un rsync se ejecute como root hacia o desde un directorio que pueda tener cambios activos y desee asegurarse de que no sean posibles las acciones de lectura o escritura a nivel de root de archivos del sistema. Si bien alternativamente podría ejecutar todo rsync como el usuario especificado, a veces necesita las credenciales de acceso a la máquina a nivel de root, por lo que esto permite que rsync descienda de root para la parte de copia de la operación después de que se establezca la conexión remota o del demonio.
La opción solo afecta a un lado de la transferencia a menos que la transferencia sea local, en cuyo caso afecta a ambos lados. Utilice --remote-option para afectar al lado remoto, como -M--copy-as=joe. Para una transferencia local, el archivo de soporte lsh (o lsh.sh) proporciona un script auxiliar de shell local que se puede usar para permitir que se especifique un host de tipo "localhost:" o "lh:" sin necesidad de configurar ningún shell remoto, lo que le permite especificar opciones remotas que afectan al lado de la transferencia que utiliza la especificación de host (y usar el nombre de host "lh" evita la anulación del directorio remoto al directorio principal del usuario).
Por ejemplo, el siguiente rsync escribe los archivos locales como el usuario "joe":
sudo rsync -aiv --copy-as=joe host1:backups/joe/ /home/joe/
Esto hace que todos los archivos sean propiedad del usuario "joe", limita los grupos a los que están disponibles para ese usuario y hace imposible que el usuario joe realice una explotación temporal de la ruta para inducir un cambio en un archivo que el usuario joe no tiene permisos para cambiar.
El siguiente comando realiza una copia local en el directorio "dest/" como el usuario "joe" (suponiendo que haya instalado support/lsh en un directorio de su $PATH):
sudo rsync -aive lsh -M--copy-as=joe src/ lh:dest/
--temp-dir=DIR, -T
Esta opción indica a rsync que utilice DIR como directorio temporal al crear copias temporales de los archivos transferidos en el lado receptor. El comportamiento predeterminado es crear cada archivo temporal en el mismo directorio que el archivo de destino asociado. A partir de rsync 3.1.1, los nombres de archivos temporales dentro del DIR especificado no tendrán un punto adicional como prefijo (aunque todavía tendrán un sufijo aleatorio añadido).
Esta opción se utiliza con más frecuencia cuando la partición de disco receptora no tiene suficiente espacio libre para contener una copia del archivo más grande de la transferencia. En este caso (es decir, cuando el directorio temporal está en una partición de disco diferente), rsync no podrá renombrar cada archivo temporal recibido para reemplazar el archivo de destino asociado, sino que deberá copiarlo en su lugar. Rsync hace esto copiando el archivo encima del archivo de destino, lo que significa que el archivo de destino contendrá datos truncados durante esta copia. Si no se hiciera de esta manera (incluso si el archivo de destino se eliminara primero, los datos se copiaran localmente a un archivo temporal en el directorio de destino y luego se renombraran en su lugar) sería posible que el archivo antiguo continuara ocupando espacio en disco (si alguien lo tuviera abierto), y por lo tanto, podría no haber suficiente espacio para que la nueva versión cupiera en el disco al mismo tiempo.
Si está utilizando esta opción por motivos distintos a la escasez de espacio en disco, puede que desee combinarla con la opción --delay-updates, que garantizará que todos los archivos copiados se coloquen en subdirectorios dentro de la jerarquía de destino, esperando el final de la transferencia. Si no tiene suficiente espacio para duplicar todos los archivos que llegan en la partición de destino, otra forma de indicarle a rsync que no está demasiado preocupado por el espacio en disco es usar la opción --partial-dir con una ruta relativa; debido a que esto le dice a rsync que está bien almacenar una copia de un solo archivo en un subdirectorio dentro de la jerarquía de destino, rsync usará el directorio parcial como área de preparación para transferir el archivo copiado y luego lo renombrará en su lugar desde allí. (Especificar un --partial-dir con una ruta absoluta no tiene este efecto secundario).
--fuzzy, -y
Esta opción le dice a rsync que busque un archivo base para cualquier archivo de destino que falte. El algoritmo actual busca en el mismo directorio que el archivo de destino un archivo con un tamaño y tiempo de modificación idénticos, o un archivo con un nombre similar. Si se encuentra, rsync utiliza el archivo base difuso para intentar acelerar la transferencia.
Si la opción se repite, el análisis difuso también se realizará en cualquier directorio de destino alternativo coincidente que se especifique mediante --compare-dest, --copy-dest o --link-dest.
Tenga en cuenta que el uso de la opción --delete podría eliminar archivos potenciales de coincidencia difusa, así que use --delete-after o especifique algunas exclusiones de nombres de archivo si necesita evitar esto.
--compare-dest=DIR
Esta opción indica a rsync que use DIR en la máquina de destino como una jerarquía adicional para comparar los archivos de destino al hacer transferencias (si los archivos faltan en el directorio de destino). Si se encuentra un archivo en DIR que es idéntico al archivo del remitente, el archivo NO se transferirá al directorio de destino. Esto es útil para crear una copia de seguridad dispersa solo de los archivos que han cambiado desde una copia de seguridad anterior. Esta opción se usa típicamente para copiar en un directorio vacío (o recién creado).
A partir de la versión 2.6.4, se pueden proporcionar varios directorios --compare-dest, lo que hará que rsync busque en la lista en el orden especificado una coincidencia exacta. Si se encuentra una coincidencia que solo difiere en atributos, se realiza una copia local y se actualizan los atributos. Si no se encuentra ninguna coincidencia, se seleccionará un archivo base de uno de los DIRs para intentar acelerar la transferencia.
Si DIR es una ruta relativa, es relativa al directorio de destino. Ver también --copy-dest y --link-dest.
NOTA: a partir de la versión 3.1.0, rsync eliminará un archivo de una jerarquía de destino no vacía si se encuentra una coincidencia exacta en una de las jerarquías de compare-dest (haciendo que el resultado final se parezca más a una copia nueva).
--copy-dest=DIR
Esta opción se comporta como --compare-dest, pero rsync también copiará los archivos no modificados que se encuentren en DIR al directorio de destino utilizando una copia local. Esto es útil para realizar transferencias a un nuevo destino mientras se dejan intactos los archivos existentes, y luego realizar un cambio rápido cuando todos los archivos se hayan transferido correctamente.
Se pueden proporcionar varios directorios --copy-dest, lo que hará que rsync busque en la lista en el orden especificado un archivo no modificado. Si no se encuentra ninguna coincidencia, se seleccionará un archivo base de uno de los DIRs para intentar acelerar la transferencia.
Si DIR es una ruta relativa, es relativa al directorio de destino. Ver también --compare-dest y --link-dest.
--link-dest=DIR
Esta opción se comporta como --copy-dest, pero los archivos no modificados se enlazan desde DIR al directorio de destino. Los archivos deben ser idénticos en todos los atributos conservados (por ejemplo, permisos, posible propiedad) para que los archivos se enlacen entre sí. Un ejemplo:
rsync -av --link-dest=$PWD/prior_dir host:src_dir/ new_dir/
Si los archivos no se enlazan, verifique sus atributos. Verifique también si algunos atributos se están forzando fuera del control de rsync, como una opción de montaje que reduce root a un solo usuario, o monta una unidad extraíble con propiedad genérica (como la opción "Ignorar propiedad en este volumen" de OS X).
A partir de la versión 2.6.4, se pueden proporcionar varios directorios --link-dest, lo que hará que rsync busque en la lista en el orden especificado una coincidencia exacta (hay un límite de 20 de estos directorios). Si se encuentra una coincidencia que solo difiere en atributos, se realiza una copia local y se actualizan los atributos. Si no se encuentra ninguna coincidencia, se seleccionará un archivo base de uno de los DIRs para intentar acelerar la transferencia.
Esta opción funciona mejor al copiar en una jerarquía de destino vacía, ya que los archivos existentes pueden tener sus atributos modificados, y eso puede afectar a los archivos de destino alternativos a través de enlaces duros. Además, la enumeración de cambios puede volverse un poco confusa. Tenga en cuenta que antes de la versión 3.1.0, una coincidencia exacta en un directorio alternativo nunca se encontraba (ni se enlazaba al destino) cuando ya existía un archivo de destino.
Tenga en cuenta que si combina esta opción con --ignore-times, rsync no enlazará ningún archivo porque solo enlaza archivos idénticos entre sí como sustituto de la transferencia del archivo, nunca como una verificación adicional después de que el archivo se actualiza.
Si DIR es una ruta relativa, es relativa al directorio de destino. Ver también --compare-dest y --copy-dest.
Tenga en cuenta que las versiones de rsync anteriores a 2.6.1 tenían un error que podía impedir que --link-dest funcionara correctamente para un usuario no superusuario cuando se especificaba (o implicaba) --owner (-o). Puede solucionar este error evitando la opción -o (o usando --no-o) al enviar a un rsync antiguo.
--compress, -z
Con esta opción, rsync comprime los datos del archivo a medida que se envían a la máquina de destino
lo cual reduce la cantidad de datos que se transmiten, algo útil en una conexión lenta.
Rsync admite múltiples métodos de compresión y elegirá uno por ti a menos que fuerces la elección utilizando la opción --compress-choice (--zc).
Ejecuta rsync --version para ver la lista de compresión predeterminada compilada en tu versión.
Cuando ambos lados de la transferencia tienen al menos la versión 3.2.0, rsync elige el primer algoritmo de la lista de opciones del cliente que también está en la lista de opciones del servidor. Si no se encuentra ninguna opción de compresión común, rsync sale con un error. Si el rsync remoto es demasiado antiguo para admitir la negociación de checksum, se asume que su lista es "zlib".
El orden predeterminado se puede personalizar estableciendo la variable de entorno RSYNC_COMPRESS_LIST a una lista de nombres de compresión aceptables separados por espacios. Si la cadena contiene un carácter "&", se divide en "cadena del cliente & cadena del servidor", de lo contrario, la misma cadena se aplica a ambos. Si la cadena (o parte de la cadena) no contiene caracteres que no sean de espacio en blanco, se utiliza la lista de compresión predeterminada. Los nombres de compresión desconocidos se descartan de la lista, pero una lista con solo nombres inválidos resulta en una negociación fallida.
Hay algunas versiones antiguas de rsync que se configuraron para rechazar una opción -z y requerir el uso de -zz porque su biblioteca de compresión no era compatible con el método de compresión zlib predeterminado. Generalmente puedes ignorar esta rareza a menos que el servidor rsync se queje y te diga que especifiques -zz.
--compress-choice=STR, --zc=STR
Esta opción se puede usar para anular la negociación automática del algoritmo de compresión que ocurre cuando se usa --compress. La opción implica --compress a menos que se especifique "none", que en su lugar implica --no-compress.
Las opciones de compresión que puedes usar son:
o
zstd
o
lz4
o
zlibx
o
zlib
o
none
Ejecuta rsync --version para ver la lista de compresión predeterminada compilada en tu versión (que puede diferir de la lista anterior).
Ten en cuenta que si ves un error sobre una opción llamada --old-compress o --new-compress, esto es rsync intentando enviar la opción --compress-choice=zlib o --compress-choice=zlibx de manera compatible con versiones anteriores que la mayoría de las versiones de rsync entienden. Este error indica que la versión más antigua de rsync en el servidor no te permitirá forzar el tipo de compresión.
Ten en cuenta que el algoritmo de compresión "zlibx" es solo el algoritmo "zlib" con datos coincidentes excluidos del flujo de compresión (para intentar hacerlo más compatible con una implementación externa de zlib).
--compress-level=NUM, --zl=NUM
Establece explícitamente el nivel de compresión a usar (ver --compress, -z) en lugar de dejarlo predeterminado. La opción --compress se implica siempre que el nivel elegido no sea un nivel de "no comprimir" para el algoritmo de compresión que está en efecto (por ejemplo, la compresión zlib trata el nivel 0 como "apagado").
Los valores de nivel varían según el checksum en efecto. Debido a que rsync negociará una opción de checksum por defecto (cuando el rsync remoto sea lo suficientemente nuevo), puede ser bueno combinar esta opción con una opción --compress-choice (--zc) a menos que estés seguro de la opción en efecto. Por ejemplo:
rsync -aiv --zc=zstd --zl=22 host:src/ dest/
Para la compresión zlib y zlibx, los valores válidos son de 1 a 9, siendo 6 el predeterminado. Especificar --zl=0 desactiva la compresión, y especificar --zl=-1 elige el nivel predeterminado de 6.
Para la compresión zstd, los valores válidos son de -131072 a 22, siendo 3 el predeterminado. Especificar 0 elige el predeterminado de 3.
Para la compresión lz4 no hay niveles, por lo que el valor es siempre 0.
Si especificas un valor demasiado grande o demasiado pequeño, el número se limita silenciosamente a un valor válido. Esto te permite especificar algo como --zl=999999999 y asegurarte de que obtendrás el nivel de compresión máximo sin importar qué algoritmo se eligió.
Si deseas conocer el nivel de compresión que está en efecto, especifica --debug=nstr para ver los resultados de la "cadena negociada". Esto informará algo como "Client compress: zstd (level 3)" (junto con la opción de checksum en efecto).
--skip-compress=LIST
NOTA: ningún método de compresión admite actualmente cambios de compresión por archivo, por lo que esta opción no tiene ningún efecto.
Anula la lista de extensiones de archivo que se comprimirán lo menos posible. Rsync establece el nivel de compresión por archivo basándose en la extensión del archivo. Si el algoritmo de compresión tiene un nivel de "apagado", entonces no se produce ninguna compresión para esos archivos. Otros algoritmos que admiten el cambio del nivel de streaming sobre la marcha tendrán el nivel minimizado para reducir el uso de CPU tanto como sea posible para un archivo coincidente.
La LISTA debe ser una o más extensiones de archivo (sin el punto) separadas por barras (/). Puedes especificar una cadena vacía para indicar que no se deben omitir archivos.
Se admite la coincidencia simple de clases de caracteres: cada una debe consistir en una lista de letras dentro de corchetes (por ejemplo, no se admiten clases especiales como "[:alpha:]", y '-' no tiene un significado especial).
Los caracteres asterisco (*) y signo de interrogación (?) no tienen un significado especial.
Aquí tienes un ejemplo que especifica 6 extensiones de archivo para omitir (ya que 1 de las 5 reglas coincide con 2 extensiones):
--skip-compress=gz/jpg/mp[34]/7z/bz2

--numeric-ids
Con esta opción, rsync transferirá IDs numéricos de grupo y usuario en lugar de usar nombres de usuario y grupo y mapearlos en ambos extremos.
Por defecto, rsync usará el nombre de usuario y el nombre de grupo para determinar la propiedad de los archivos. El UID especial 0 y el grupo especial 0 nunca se mapean a través de nombres de usuario/grupo, incluso si la opción --numeric-ids no se especifica.
Si un usuario o grupo no tiene nombre en el sistema de origen o no tiene coincidencia en el sistema de destino, se utilizará en su lugar el ID numérico del sistema de origen. Consulta también la configuración use chroot en la página man de rsyncd.conf para algunos comentarios sobre cómo la configuración de chroot afecta la capacidad de rsync para buscar los nombres de los usuarios y grupos y qué puedes hacer al respecto.
--usermap=STRING, --groupmap=STRING
Estas opciones te permiten especificar usuarios y grupos que deben ser mapeados a otros valores por el lado receptor. La CADENA es uno o más pares de valores DE:A separados por comas. Cualquier valor DE coincidente del remitente se reemplaza con un valor A del receptor. Puedes especificar nombres de usuario o IDs de usuario para los valores DE y A, y el valor DE también puede ser una cadena comodín, que se comparará con los nombres del remitente (los comodines NO coinciden con los números de ID, aunque consulta más abajo por qué un '*' coincide con todo). En su lugar, puedes especificar un rango de números de ID a través de un rango inclusivo: BAJO-ALTO. Por ejemplo:
--usermap=0-99:nobody,wayne:admin,*:normal --groupmap=usr:1,1:usr
La primera coincidencia en la lista es la que se utiliza. Debes especificar todos tus mapeos de usuario utilizando una sola opción --usermap, y/o todos tus mapeos de grupo utilizando una sola opción --groupmap.
Ten en cuenta que el nombre del remitente para el usuario y grupo 0 no se transmite al receptor, por lo que debes hacer coincidir estos valores usando un 0, o usar los nombres en efecto en el lado receptor (típicamente "root"). Todos los demás nombres DE coinciden con los que están en uso en el lado de envío. Todos los nombres A coinciden con los que están en uso en el lado de recepción.
Cualquier ID que no tenga un nombre en el lado de envío se trata como si tuviera un nombre vacío a efectos de coincidencia. Esto les permite ser coincididos a través de un "*" o usando un nombre vacío. Por ejemplo:
--usermap=:nobody --groupmap=*:nobody
Cuando se utiliza la opción --numeric-ids, el remitente no envía ningún nombre, por lo que todos los IDs se tratan como si tuvieran un nombre vacío. Esto significa que deberás especificar valores DE numéricos si deseas mapear estos IDs sin nombre a valores diferentes.
Para que la opción --usermap funcione, el receptor deberá estar ejecutándose como superusuario (ver también las opciones --super y --fake-super). Para que la opción --groupmap funcione, el receptor deberá tener permiso
s para configurar ese grupo.
A partir de rsync 3.2.4, la opción --usermap implica la opción --owner (-o) mientras que la opción --groupmap implica la opción --group (-g) (ya que rsync necesita tener esas opciones habilitadas para que las opciones de mapeo funcionen).
Un cliente rsync más antiguo puede necesitar usar -s para evitar una queja sobre caracteres comodín, pero un rsync moderno maneja esto automáticamente.
--chown=USUARIO:GRUPO
Esta opción fuerza que todos los archivos pertenezcan a USUARIO con grupo GRUPO. Esta es una interfaz más simple que usar --usermap y --groupmap directamente, pero se implementa usando esas opciones internamente, por lo que no se pueden mezclar. Si USUARIO o GRUPO están vacíos, no se producirá ningún mapeo para el usuario/grupo omitido. Si GRUPO está vacío, se puede omitir el dos puntos final, pero si USUARIO está vacío, se debe proporcionar un dos puntos inicial.
Si especifica ""--chown=foo:bar"", esto es exactamente lo mismo que especificar ""--usermap=*:foo --groupmap=*:bar"", solo que más fácil (y con las mismas opciones --owner y/o --group implícitas).
Un cliente rsync más antiguo puede necesitar usar -s para evitar una queja sobre caracteres comodín, pero un rsync moderno maneja esto automáticamente.
--timeout=SEGUNDOS
Esta opción permite establecer un tiempo de espera máximo de E/S en segundos. Si no se transfiere ningún dato durante el tiempo especificado, rsync saldrá. El valor predeterminado es 0, que significa sin tiempo de espera.
--contimeout=SEGUNDOS
Esta opción permite establecer el tiempo que rsync esperará a que su conexión a un demonio rsync tenga éxito. Si se alcanza el tiempo de espera, rsync saldrá con un error.
--address=DIRECCION
Por defecto, rsync se enlazará a la dirección comodín al conectarse a un demonio rsync. La opción --address permite especificar una dirección IP específica (o nombre de host) a la que enlazarse.
Ver también la versión de demonio de la opción --address.
--port=PUERTO
Esto especifica un número de puerto TCP alternativo a usar en lugar del predeterminado de 873. Esto solo es necesario si está utilizando la sintaxis de doble dos puntos (::) para conectarse con un demonio rsync (ya que la sintaxis de URL tiene una forma de especificar el puerto como parte de la URL).
Ver también la versión de demonio de la opción --port.
--sockopts=OPCIONES
Esta opción puede proporcionar diversión sin fin para las personas a las que les gusta ajustar sus sistemas al máximo. Puede establecer todo tipo de opciones de socket que pueden hacer que las transferencias sean más rápidas (¡o más lentas!). Lea la página del manual de la llamada al sistema setsockopt() para obtener detalles sobre algunas de las opciones que puede configurar. Por defecto, no se establecen opciones de socket especiales. Esto solo afecta a las conexiones de socket directas a un demonio rsync remoto.
Ver también la versión de demonio de la opción --sockopts.
--blocking-io
Esto indica a rsync que utilice E/S de bloqueo al iniciar un transporte de shell remoto. Si el shell remoto es rsh o remsh, rsync utiliza por defecto E/S de bloqueo; de lo contrario, utiliza E/S sin bloqueo. (Tenga en cuenta que ssh prefiere E/S sin bloqueo).
--outbuf=MODO
Esto establece el modo de almacenamiento en búfer de salida. El modo puede ser Ninguno (también conocido como Sin búfer), Línea o Bloque (también conocido como Completo). Puede especificar tan poco como una sola letra para el modo, y usar mayúsculas o minúsculas.
El uso principal de esta opción es cambiar el almacenamiento en búfer completo a almacenamiento en búfer por línea cuando la salida de rsync va a un archivo o tubería.
--itemize-changes, -i
Solicita una lista simple de los cambios que se están realizando en cada archivo, incluidos los cambios de atributos. Esto es exactamente lo mismo que especificar --out-format='%i %n%L'. Si repite la opción, los archivos sin cambios también se mostrarán, pero solo si el rsync receptor tiene al menos la versión 2.6.7 (puede usar -vv con versiones anteriores de rsync, pero eso también activa la salida de otros mensajes detallados).
El escape "%i" tiene una salida críptica que tiene 11 letras de longitud. El formato general es como la cadena YXcstpoguax, donde Y se reemplaza por el tipo de actualización que se está realizando, X se reemplaza por el tipo de archivo, y las otras letras representan atributos que pueden mostrarse si se están modificando.
Los tipos de actualización que reemplazan a la Y son los siguientes:
o
Un < significa que un archivo se está transfiriendo al host remoto (enviado).
o
Un > significa que un archivo se está transfiriendo al host local (recibido).
o
Una c significa que se está produciendo un cambio/creación local para el elemento (como la creación de un directorio o el cambio de un enlace simbólico, etc.).
o
Una h significa que el elemento es un enlace duro a otro elemento (requiere --hard-links).
o
Un . significa que el elemento no se está actualizando (aunque pueda tener atributos que se estén modificando).
o
Un * significa que el resto del área de salida detallada contiene un mensaje (por ejemplo, "eliminando").
Los tipos de archivo que reemplazan a la X son: f para un archivo, d para un directorio, L para un enlace simbólico, D para un dispositivo y S para un archivo especial (por ejemplo, sockets con nombre y fifos).
Las otras letras de la cadena indican si algunos atributos del archivo han cambiado, como sigue:
o
"." - el atributo no ha cambiado.
o
"+" - el archivo se crea nuevo.
o
" " - todos los atributos no han cambiado (todos los puntos se convierten en espacios).
o
"?" - el cambio es desconocido (cuando el rsync remoto es antiguo).
o
Una letra indica que se está actualizando un atributo.
El atributo asociado con cada letra es el siguiente:
o
Una c significa que un archivo regular tiene una suma de verificación diferente (requiere --checksum) o que un enlace simbólico, dispositivo o archivo especial tiene un valor cambiado. Tenga en cuenta que si está enviando archivos a un rsync anterior a 3.0.1, este indicador de cambio solo estará presente para archivos regulares con sumas de verificación diferentes.
o
Una s significa que el tamaño de un archivo regular es diferente y será actualizado por la transferencia de archivos.
o
Una t significa que la hora de modificación es diferente y se está actualizando al valor del remitente (requiere --times). Un valor alternativo de T significa que la hora de modificación se establecerá en la hora de transferencia, lo que ocurre cuando se actualiza un archivo/enlace simbólico/dispositivo sin --times y cuando se cambia un enlace simbólico y el receptor no puede establecer su hora. (Nota: al usar un cliente rsync 3.0.0, puede ver la bandera s combinada con t en lugar de la bandera T correcta para este error de establecimiento de hora).
o
Una p significa que los permisos son diferentes y se están actualizando al valor del remitente (requiere --perms).
o
Una o significa que el propietario es diferente y se está actualizando al valor del remitente (requiere --owner y privilegios de superusuario).
o
Una g significa que el grupo es diferente y se está actualizando al valor del remitente (requiere --group y la autoridad para establecer el grupo).
o
o
Una u|n|b indica la siguiente información:

u significa que la hora de acceso (uso) es diferente y se está actualizando al valor del remitente (requiere --atimes)

o
n significa que la hora de creación (novedad) es diferente y se está actualizando al valor del remitente (requiere --crtimes)
o
b significa que tanto la hora de acceso como la de creación se están actualizando.
o
La a significa que la información de ACL está siendo cambiada.
o
La x significa que la información de atributos extendidos está siendo cambiada.
Otra salida posible es: al eliminar archivos, "%i" mostrará la cadena "*eliminando" para cada elemento que se esté eliminando (asumiendo que te estás comunicando con un rsync lo suficientemente reciente como para que registre las eliminaciones en lugar de mostrarlas como un mensaje detallado).
--out-format=FORMATO
Esto te permite especificar exactamente lo que el cliente rsync muestra al usuario por cada actualización. El formato es una cadena de texto que contiene secuencias de escape de un solo carácter incrustadas prefijadas con un carácter de porcentaje (%). Se asume un formato predeterminado de ""%n%L"" si se especifica --info=name o -v (esto solo te indica el nombre del archivo y, si el elemento es un enlace, a dónde apunta). Para obtener una lista completa de los caracteres de escape posibles, consulta la configuración de log format en la página del manual de rsyncd.conf.
Especificar la opción --out-format implica --info=name.
option, que mencionará cada archivo, directorio, etc. que se actualiza de manera significativa (un archivo transferido, un enlace simbólico/dispositivo recreado o un directorio tocado). Además, si el escape itemize-changes (%i) está incluido en la cadena (por ejemplo, si se usó la opción --itemize-changes), el registro de nombres aumenta para mencionar cualquier elemento que se modifique de cualquier manera (siempre que el lado receptor tenga al menos la versión 2.6.4). --log-file=FILE
Esta opción hace que rsync registre lo que está haciendo en un archivo. Esto es similar al registro que hace un demonio, pero puede solicitarse para el lado del cliente y/o el lado del servidor de una transferencia que no sea de demonio. Si se especifica como una opción del cliente, se habilitará el registro de transferencia con un formato predeterminado de "%i %n%L". Consulte la opción --log-file-format si desea anular esto.
Aquí hay un ejemplo de comando que solicita al lado remoto que registre lo que está sucediendo:

Esto es muy útil si necesita depurar por qué una conexión se cierra inesperadamente.
Consulte también la versión de demonio de la opción --log-file.

Esto le permite especificar exactamente qué registro por actualización se incluye en el archivo especificado por la opción --log-file (que también debe especificarse para que esta opción tenga algún efecto). Para obtener una lista de los caracteres de escape posibles, consulte la configuración de log format en la página del manual de rsyncd.conf.

--stats
Esto le indica a rsync que imprima un conjunto detallado de estadísticas sobre la transferencia de archivos, lo que le permite saber cuán efectivo es el algoritmo de transferencia de delta de rsync para sus datos. Esta opción es equivalente a --info=stats2 si se combina con 0 o 1 opción(es) de -v, o --info=stats3 si se combina con 2 o más opción(es) de -v.
Las estadísticas actuales son las siguientes:
o
Número de archivos es el recuento de todos los "archivos" (en el sentido genérico), que incluye directorios, enlaces simbólicos, etc. El recuento total irá seguido de una lista de recuentos por tipo de archivo (si el total no es cero). Por ejemplo: "(reg: 5, dir: 3, link: 2, dev: 1, special: 1)" enumera los totales de archivos regulares, directorios, enlaces simbólicos, dispositivos y archivos especiales. Si algún valor es 0, se omite completamente de la lista.
o
Número de archivos creados es el recuento de cuántos "archivos" (sentido genérico) se crearon (en lugar de actualizarse). El recuento total irá seguido de una lista de recuentos por tipo de archivo (si el total no es cero).
o
Número de archivos eliminados es el recuento de cuántos "archivos" (sentido genérico) se eliminaron. El recuento total irá seguido de una lista de recuentos por tipo de archivo (si el total no es cero). Tenga en cuenta que esta línea solo se muestra si las eliminaciones están en efecto, y solo si se está utilizando el protocolo 31 (el predeterminado para rsync 3.1.x).
o
Número de archivos regulares transferidos es el recuento de archivos normales que se actualizaron a través del algoritmo de transferencia de delta de rsync, que no incluye directorios, enlaces simbólicos, etc. Tenga en cuenta que rsync 3.1.0 agregó la palabra "regular" a este encabezado.
o
Tamaño total de archivos es la suma total de todos los tamaños de archivos en la transferencia. Esto no cuenta ningún tamaño para directorios o archivos especiales, pero sí incluye el tamaño de los enlaces simbólicos.
o
Tamaño total de archivos transferidos es la suma total de todos los tamaños de archivos solo para los archivos transferidos.
o
Datos literales es la cantidad de datos de actualización de archivos no coincidentes que tuvimos que enviar al receptor para que recreara los archivos actualizados.
o
Datos coincidentes es la cantidad de datos que el receptor obtuvo localmente al recrear los archivos actualizados.
o
Tamaño de la lista de archivos es el tamaño que tenían los datos de la lista de archivos cuando el emisor los envió al receptor. Esto es menor que el tamaño en memoria de la lista de archivos debido a cierta compresión de datos duplicados cuando rsync envía la lista.
o
Tiempo de generación de la lista de archivos es el número de segundos que el emisor dedicó a crear la lista de archivos. Esto requiere una versión moderna de rsync en el lado emisor para que esté presente.
o
Tiempo de transferencia de la lista de archivos es el número de segundos que el emisor dedicó a enviar la lista de archivos al receptor.
o
Total de bytes enviados es el recuento de todos los bytes que rsync envió desde el lado del cliente al lado del servidor.
o
Total de bytes recibidos es el recuento de todos los bytes que no son de mensaje que rsync recibió el lado del cliente del lado del servidor. "Bytes que no son de mensaje" significa que no contamos los bytes de un mensaje detallado que el servidor nos envió, lo que hace que las estadísticas sean más consistentes.
--8-bit-output, -8
Esto le indica a rsync que deje todos los caracteres de alto bit sin escapar en la salida en lugar de intentar probarlos para ver si son válidos en la configuración regional actual y escapar los inválidos. Todos los caracteres de control (pero nunca las tabulaciones) siempre se escapan, independientemente de la configuración de esta opción.
El modismo de escape que comenzó en la versión 2.6.7 es mostrar una barra invertida literal (\) y un signo de almohadilla (#), seguidos de exactamente 3 dígitos octales. Por ejemplo, un salto de línea se mostraría como "#012". Una barra invertida literal que está en un nombre de archivo no se escapa a menos que esté seguida por un signo de almohadilla y 3 dígitos (0-9).
--human-readable, -h
Muestra los números en un formato más legible para humanos. Hay 3 niveles posibles:
1.
muestra los números con un separador entre cada conjunto de 3 dígitos (ya sea una coma o un punto, dependiendo de si el punto decimal se representa con un punto o una coma).
2.
muestra los números en unidades de 1000 (con un sufijo de carácter para unidades mayores; vea abajo).
3.
muestra los números en unidades de 1024.
El valor predeterminado es el nivel 1 legible para humanos. Cada opción -h aumenta el nivel en uno. Puede reducir el nivel a 0 (para mostrar los números como dígitos puros) especificando la opción --no-human-readable (--no-h).
Las letras de unidad que se anexan en los niveles 2 y 3 son: K (kilo), M (mega), G (giga), T (tera) o P (peta). Por ejemplo, un archivo de 1234567 bytes se mostraría como 1.23M en el nivel 2 (suponiendo que un punto es el punto decimal de su sistema).
Nota de compatibilidad retroactiva: las versiones de rsync anteriores a 3.1.0 no admiten el nivel 1 legible para humanos y, por defecto, usan el nivel 0. Por lo tanto, especificar una o dos opciones -h se comportará de manera comparable en versiones antiguas y nuevas, siempre que no haya especificado una opción --no-h antes de una o más opciones -h. Consulte la opción --list-only para ver una diferencia.
--partial
Por defecto, rsync eliminará cualquier archivo transferido parcialmente si la transferencia se interrumpe. En algunas circunstancias, es más deseable conservar los archivos transferidos parcialmente. Usar la opción --partial le indica a rsync que conserve el archivo parcial, lo que debería hacer que una transferencia posterior del resto del archivo sea mucho más rápida.
--partial-dir=DIR
Esta opción modifica el comportamiento de la opción --partial y también implica que esta esté habilitada. Este método mejorado de archivo parcial coloca cualquier archivo transferido parcialmente en el DIR especificado en lugar de escribir el archivo parcial en el archivo de destino. En la siguiente transferencia, rsync utilizará un archivo encontrado en este directorio como datos para acelerar la reanudación de la transferencia y luego lo eliminará después de que haya cumplido su propósito.
Tenga en cuenta que si se especifica --whole-file (o se implica), cualquier archivo parcial encontrado para un archivo que se está actualizando simplemente se eliminará (ya que rsync está enviando archivos sin usar el algoritmo de transferencia de delta de rsync).
Rsync creará el DIR si falta, pero solo el último directorio; no toda la ruta. Esto facilita el uso de una ruta relativa (como "--partial-dir=.rsync-partial") para que rsync cree el directorio parcial en el directorio del archivo de destino cuando sea necesario, y luego lo elimine nuevamente cuando se elimine el archivo parcial. Tenga en cuenta que esta eliminación de directorio solo se realiza para un nombre de ruta relativo, ya que se espera que una ruta absoluta sea un directorio reservado para el trabajo de directorio parcial.
Si el valor de partial-dir no es una ruta absoluta, rsync agregará una regla de exclusión al final de todas sus exclusiones existentes. Esto evitará el envío de cualquier archivo de directorio parcial que pueda existir en el lado emisor, y también evitará la eliminación inoportuna de elementos de directorio parcial en el lado receptor. --early-input=ARCHIVO
Esta opción permite a rsync enviar hasta 5K de datos al script "early exec" en su stdin. Un uso posible de estos datos es dar al script un secreto que se pueda usar para montar un sistema de archivos cifrado (que deberías desmontar en el script "post-xfer exec").
El demonio debe ser al menos de la versión 3.2.1.
--list-only
Esta opción hará que los archivos de origen se listen en lugar de transferirse. Esta opción se infiere si hay un solo argumento de origen y no se especifica destino, por lo que sus usos principales son:
1.
para convertir un comando de copia que incluye un argumento de destino en un comando de listado de archivos, o
2.
para poder especificar más de un argumento de origen. Nota: asegúrate de incluir el destino.
PRECAUCIÓN: ten en cuenta que un argumento de origen con un comodín es expandido por el shell en múltiples argumentos, por lo que nunca es seguro intentar especificar un único argumento con comodín para intentar inferir esta opción. Un ejemplo seguro es:
rsync -av --list-only foo* destino/
Esta opción siempre utiliza un formato de salida que se parece a esto:
drwxrwxr-x          4,096 2022/09/30 12:53:11 support
-rw-rw-r--             80 2005/01/11 10:37:37 support/Makefile
La única opción que afecta a este estilo de salida es (a partir de 3.1.0) la opción --human-readable (-h). El valor predeterminado es mostrar los tamaños como recuentos de bytes con separadores de dígitos (en una columna de 14 caracteres de ancho). Especificar al menos una opción -h hace que los tamaños se muestren con sufijos de unidad. Si deseas tamaños de bytes al estilo antiguo sin separadores de dígitos (y una columna de 11 caracteres de ancho) usa --no-h.
Nota de compatibilidad: al solicitar un listado remoto de archivos de un rsync de la versión 2.6.3 o anterior, puedes encontrar un error si solicitas un listado no recursivo. Esto se debe a que un listado de archivos implica la opción --dirs sin --recursive, y los rsync más antiguos no tienen esa opción. Para evitar este problema, especifica la opción --no-dirs (si no necesitas expandir el contenido de un directorio) o activa la recursión y excluye el contenido de los subdirectorios: -r --exclude='/*/*'.
--bwlimit=TASA
Esta opción te permite especificar la tasa máxima de transferencia de los datos enviados a través del socket, especificada en unidades por segundo. El valor de TASA puede ir acompañado de un sufijo para indicar un multiplicador de tamaño, y puede ser un valor fraccionario (por ejemplo, --bwlimit=1.5m). Si no se especifica sufijo, se asumirá que el valor está en unidades de 1024 bytes (como si se hubiera añadido "K" o "KiB"). Consulta la opción --max-size para obtener una descripción de todos los sufijos disponibles. Un valor de 0 especifica que no hay límite.
Por razones de compatibilidad hacia atrás, el límite de tasa se redondeará a la unidad KiB más cercana, por lo que no es posible una tasa inferior a 1024 bytes por segundo.
Rsync escribe datos sobre el socket en bloques, y esta opción limita el tamaño de los bloques que rsync escribe, e intenta mantener la tasa de transferencia promedio en el límite solicitado. Se puede observar cierta ráfaga cuando rsync escribe un bloque de datos y luego duerme para cumplir con la tasa promedio.
Debido al búfer interno de datos, la opción --progress puede no reflejar con precisión la velocidad a la que se envían los datos. Esto se debe a que algunos archivos pueden mostrarse como enviados rápidamente cuando los datos se almacenan en búfer rápidamente, mientras que otros pueden mostrarse como muy lentos cuando se produce la descarga del búfer de salida. Esto puede solucionarse en una versión futura.
Consulta también la versión de demonio de la opción --bwlimit.
--stop-after=MIN, (--time-limit=MIN)
Esta opción indica a rsync que deje de copiar cuando haya transcurrido el número especificado de minutos.
Para una máxima flexibilidad, rsync no comunica esta opción al rsync remoto, ya que generalmente es suficiente que un lado de la conexión se detenga según lo especificado. Esto permite el uso de la opción incluso cuando solo un lado de la conexión la admite. Puedes informar al lado remoto sobre el límite de tiempo utilizando --remote-option (-M), si surge la necesidad.
La versión --time-limit de esta opción está obsoleta.
--stop-at=a-m-dTh:m
Esta opción indica a rsync que deje de copiar cuando se haya alcanzado el punto en el tiempo especificado. La fecha y hora se pueden especificar completamente en un formato numérico de año-mes-díaThora:minuto (por ejemplo, 2000-12-31T23:59) en la zona horaria local. Puedes optar por separar los números de fecha con barras en lugar de guiones.
El valor también se puede abreviar de diversas maneras, como especificar un año de 2 dígitos y/o omitir varios valores. En todos los casos, se tomará el valor como el próximo punto posible en el tiempo donde la información proporcionada coincida. Si el valor especifica la hora actual o una hora pasada, rsync saldrá con un error.
Por ejemplo, "1-30" especifica el próximo 30 de enero (a medianoche, hora local), "14:00" especifica las próximas 2 p.m., "1" especifica el próximo día 1 del mes a medianoche, "31" especifica el próximo mes en el que se pueda detener el día 31, y ":59" especifica el próximo minuto 59 después de la hora.
Para una máxima flexibilidad, rsync no comunica esta opción al rsync remoto, ya que generalmente es suficiente que un lado de la conexión se detenga según lo especificado. Esto permite el uso de la opción incluso cuando solo un lado de la conexión la admite. Puedes informar al lado remoto sobre el límite de tiempo utilizando --remote-option (-M), si surge la necesidad. Ten en cuenta que el host remoto puede tener una zona horaria predeterminada diferente a la de tu host local.
--fsync
Causa que el lado receptor haga fsync de cada archivo terminado. Esto puede ralentizar la transferencia, pero puede ayudar a dar tranquilidad al actualizar archivos críticos.
--write-batch=ARCHIVO
Registra un archivo que posteriormente se puede aplicar a otro destino idéntico con --read-batch. Consulta la sección "MODO DE LOTE" para obtener detalles, y también la opción --only-write-batch.
Esta opción anula las listas negociadas de suma de verificación y compresión y siempre negocia una elección basada en las opciones antiguas de md5/md4/zlib. Si deseas una elección más moderna, utiliza las opciones --checksum-choice (--cc) y/o --compress-choice (--zc).
--only-write-batch=ARCHIVO
Funciona como --write-batch, excepto que no se realizan actualizaciones en el sistema de destino al crear el lote. Esto te permite transportar los cambios al sistema de destino a través de algún otro medio y luego aplicar los cambios mediante --read-batch.
Ten en cuenta que puedes sentirte libre de escribir el lote directamente en algún medio extraíble: si este medio se llena antes del final de la transferencia, puedes aplicar esa transferencia parcial al destino y repetir todo el proceso para obtener el resto de los cambios (siempre que no te importe un sistema de destino parcialmente actualizado mientras ocurre el ciclo de actualización múltiple).
También ten en cuenta que solo ahorras ancho de banda al enviar cambios a un sistema remoto, ya que esto permite que los datos en lotes se desvíen del remitente al archivo de lote sin tener que fluir por el cable hacia el receptor (al recibir, el remitente es remoto y, por lo tanto, no puede escribir el lote).
--read-batch=ARCHIVO
Aplica todos los cambios almacenados en ARCHIVO, un archivo generado previamente por --write-batch. Si *ARCHIVO* es -, los datos del lote se leerán de la entrada estándar. Consulta la sección "MODO DE LOTE" para obtener detalles.
--protocol=NUM
Fuerza el uso de una versión de protocolo anterior. Esto es útil para crear un archivo de lote que sea compatible con una versión anterior de rsync. Por ejemplo, si se está utilizando rsync 2.6.4 con la opción --write-batch, pero se utilizará rsync 2.6.3 para ejecutar la opción --read-batch, deberías usar "--protocol=28" al crear el archivo de lote para forzar el uso de la versión de protocolo anterior en el archivo de lote (suponiendo que no puedas actualizar el rsync en el sistema de lectura).
--iconv=ESPECIFICACION_CONVERSION
Rsync puede convertir nombres de archivos entre conjuntos de caracteres utilizando esta opción. Usar una ESPECIFICACION_CONVERSION de "." le indica a rsync que busque el conjunto de caracteres predeterminado a través de la configuración regional. Alternativamente, puedes especificar completamente qué conversión realizar dando un conjunto de caracteres local y remoto separados por una coma en el orden --iconv=LOCAL,REMOTO, por ejemplo, --iconv=utf8,iso88591. Este orden asegura que la opción permanecerá igual ya sea que estés enviando o recibiendo archivos. Finalmente, puedes especificar --no-iconv o una ESPECIFICACION_CONVERSION de "-" para desactivar cualquier conversión. La configuración predeterminada de esta opción es específica del sitio y también puede verse afectada por la variable de entorno RSYNC_ICONV.
Para obtener una lista de los nombres de conjuntos de caracteres que admite tu biblioteca iconv local, puedes ejecutar "iconv --list".

Tenga en cuenta que rsync no realiza ninguna conversión de nombres en archivos de filtro (incluidos los archivos de inclusión/exclusión). Depende de usted asegurarse de que está especificando reglas coincidentes que puedan coincidir en ambos lados de la transferencia. Por ejemplo, puede especificar reglas de inclusión/exclusión adicionales si existen diferencias en los nombres de archivo en los dos lados que deban tenerse en cuenta.
Cuando pasa una opción --iconv a un demonio rsync que lo permite, el demonio utiliza la codificación de caracteres especificada en su parámetro de configuración "charset", independientemente de la codificación de caracteres remota que pase realmente. Por lo tanto, puede sentirse libre de especificar solo la codificación de caracteres local para una transferencia de demonio (por ejemplo, --iconv=utf8).
--ipv4, -4 o --ipv6, -6
Indica a rsync que prefiera IPv4/IPv6 al crear sockets o al ejecutar ssh. Esto afecta a los sockets que rsync controla directamente, como el socket de salida al contactar directamente a un demonio rsync, así como al reenvío de la opción -4 o -6 a ssh cuando rsync puede deducir que ssh se está utilizando como shell remoto. Para otros shells remotos, deberá especificar la opción "--rsh SHELL -4" directamente (o cualquier otra pista IPv4/IPv6 que utilice).
Ver también la versión de demonio de estas opciones.
Si rsync se compiló sin soporte para IPv6, la opción --ipv6 no tendrá efecto. La salida de rsync --version contendrá "no IPv6" si es el caso.
--checksum-seed=NUM
Establece la semilla de suma de verificación al entero NUM. Esta semilla de suma de verificación de 4 bytes se incluye en el cálculo de la suma de verificación de cada bloque y archivo MD4 (los checksums de archivo MD5 más modernos no usan semilla). Por defecto, la semilla de suma de verificación es generada por el servidor y por defecto es la hora actual (time()). Esta opción se utiliza para establecer una semilla de suma de verificación específica, lo que es útil para aplicaciones que desean sumas de verificación de bloques repetibles, o en el caso de que el usuario desee una semilla de suma de verificación más aleatoria. Establecer NUM a 0 hace que rsync utilice el valor predeterminado de time() para la semilla de suma de verificación.

OPCIONES DE DEMONIO

Las opciones permitidas al iniciar un demonio rsync son las siguientes:

--daemon
Esto indica a rsync que debe ejecutarse como un demonio. El demonio que inicie puede ser accedido usando un cliente rsync con la sintaxis host::module o rsync://host/module/.
Si la entrada estándar es un socket, rsync asumirá que se está ejecutando a través de inetd, de lo contrario, se desconectará del terminal actual y se convertirá en un demonio en segundo plano. El demonio leerá el archivo de configuración (rsyncd.conf) en cada conexión realizada por un cliente y responderá a las solicitudes en consecuencia.
Ver la página del manual de rsyncd.conf(5) para más detalles.
--address=ADDRESS
Por defecto, rsync se enlazará a la dirección comodín cuando se ejecute como un demonio con la opción --daemon. La opción --address le permite especificar una dirección IP (o nombre de host) específica a la que enlazar. Esto hace posible el alojamiento virtual en conjunción con la opción --config.
Ver también la opción global de dirección en la página del manual de rsyncd.conf y la versión de cliente de la opción --address.
--bwlimit=RATE
Esta opción le permite especificar la tasa de transferencia máxima para los datos que el demonio envía a través del socket. El cliente aún puede especificar un valor --bwlimit menor, pero no se permitirá un valor mayor.
Ver la versión de cliente de la opción --bwlimit para obtener algunos detalles adicionales.
--config=FILE
Esto especifica un archivo de configuración alternativo al predeterminado. Esto solo es relevante cuando se especifica --daemon. El valor predeterminado es /etc/rsyncd.conf a menos que el demonio se ejecute a través de un programa de shell remoto y el usuario remoto no sea el superusuario; en ese caso, el valor predeterminado es rsyncd.conf en el directorio actual (típicamente $HOME).
--dparam=OVERRIDE, -M
Esta opción se puede utilizar para establecer un parámetro de configuración del demonio al iniciar rsync en modo demonio. Es equivalente a agregar el parámetro al final de la configuración global antes de la definición del primer módulo. Los nombres de los parámetros se pueden especificar sin espacios, si lo desea. Por ejemplo:
rsync --daemon -M pidfile=/path/rsync.pid
--no-detach
Cuando se ejecuta como demonio, esta opción le indica a rsync que no se desvincule y se convierta en un proceso en segundo plano. Esta opción es requerida cuando se ejecuta como un servicio en Cygwin, y también puede ser útil cuando rsync es supervisado por un programa como daemontools o el System Resource Controller de AIX. --no-detach también se recomienda cuando rsync se ejecuta bajo un depurador. Esta opción no tiene efecto si rsync se ejecuta desde inetd o sshd.
--port=PORT
Esto especifica un número de puerto TCP alternativo para que el demonio escuche en lugar del predeterminado 873.
Ver también la versión de cliente de la opción --port y la configuración global de puerto en la página del manual de rsyncd.conf.
--log-file=FILE
Esta opción le indica al demonio rsync que use el nombre de archivo de registro dado en lugar de usar la configuración "log file" en el archivo de configuración.
Ver también la versión de cliente de la opción --log-file.
--log-file-format=FORMAT
Esta opción le indica al demonio rsync que use la cadena FORMAT dada en lugar de usar la configuración "log format" en el archivo de configuración. También habilita "transfer logging" a menos que la cadena esté vacía, en cuyo caso el registro de transferencias se desactiva.
Ver también la versión de cliente de la opción --log-file-format.
--sockopts
Esto anula la configuración de socket options en el archivo rsyncd.conf y tiene la misma sintaxis.
Ver también la versión de cliente de la opción --sockopts.
--verbose, -v
Esta opción aumenta la cantidad de información que el demonio registra durante su fase de inicio. Después de que el cliente se conecta, el nivel de verbosidad del demonio será controlado por las opciones que utilizó el cliente y la configuración "max verbosity" en la sección del módulo de configuración.
Ver también la versión de cliente de la opción --verbose.
--ipv4, -4 o --ipv6, -6
Indica a rsync que prefiera IPv4/IPv6 al crear los sockets entrantes que utilizará el demonio rsync para escuchar las conexiones. Una de estas opciones puede ser requerida en versiones anteriores de Linux para solucionar un error de IPv6 en el kernel (si ve un error de "dirección ya en uso" cuando nada más está usando el puerto, intente especificar --ipv6 o --ipv4 al iniciar el demonio).
Ver también la versión de cliente de estas opciones.
Si rsync se compiló sin soporte para IPv6, la opción --ipv6 no tendrá efecto. La salida de rsync --version contendrá "no IPv6" si es el caso.
--help, -h
Cuando se especifica después de --daemon, imprime una página de ayuda corta que describe las opciones disponibles para iniciar un demonio rsync.

REGLAS DE FILTRO

Las reglas de filtro permiten un control personalizado de varios aspectos de cómo se manejan los archivos:

o
Controlar qué archivos envía el lado del remitente a la lista de archivos que describe la jerarquía de transferencia
o
Controlar qué archivos protege el lado del receptor de la eliminación cuando el archivo no está en la lista de archivos del remitente
o
Controlar qué nombres de atributos extendidos se omiten al copiar xattrs

Las reglas se especifican directamente a través de argumentos de opción o se pueden leer desde uno o más archivos. Los archivos de reglas de filtro pueden ser incluso parte de la jerarquía de archivos que se copian, afectando diferentes partes del árbol de diferentes maneras.

REGLAS SIMPLES DE INCLUSIÓN/EXCLUSIÓN

Primero cubriremos los conceptos básicos de cómo las reglas de inclusión y exclusión afectan qué archivos se transfieren, ignorando cualquier efecto de eliminación. Las reglas de filtro afectan principalmente el contenido de los directorios en los que rsync está "recursando", pero también pueden afectar un elemento de nivel superior en la transferencia que se especificó como argumento.

El valor predeterminado para cualquier archivo/directorio no coincidente es incluirlo en la transferencia, lo que coloca el archivo/directorio en la lista de archivos del remitente. El uso de una regla de exclusión hace que uno o más archivos/directorios coincidentes se dejen fuera de la lista de archivos del remitente. Una regla de inclusión se puede utilizar para limitar el efecto de una regla de exclusión que coincide con demasiados archivos.

El orden de las reglas es importante porque la primera regla que coincide es la que surte efecto. Por lo tanto, si una regla anterior excluye un archivo, ninguna regla de inclusión posterior puede tener ningún efecto. Esto significa que debe colocar cualquier anulación de inclusión en algún lugar antes de la exclusión que pretende limitar.

Cuando se excluye un directorio, todo su contenido y subcontenidos también se excluyen. El remitente no escanea nada de él, lo que puede ahorrar mucho tiempo al omitir subárboles grandes innecesarios.

También es importante comprender que las reglas de inclusión/exclusión se aplican a cada archivo y directorio en los que el remitente está recursando.

FILTER RULES

Rsync has a powerful filtering mechanism that allows you to specify which files and directories should be included or excluded from a transfer. This filtering is done using rules that can be specified directly on the command line or read from files.

It is important to understand how rsync's filtering works. When rsync encounters a file or directory, it checks it against the ordered list of filter rules. The first rule that matches determines whether the file or directory is included or excluded. If no rule matches, the default behavior applies.

The rules are processed in the order they appear. This means that a later rule can override an earlier one. For example, if you exclude a directory and then include a specific file within that directory, the file will still be excluded unless the include rule comes after the exclude rule and explicitly includes the file.

When rsync descends into a directory, it applies the filtering rules to each directory it visits on the way down. This means that if a directory is excluded, any files or subdirectories within it will also be excluded, even if they are explicitly included in a later rule. Therefore, if you want a particular deep file to be included, you have to make sure that none of the directories that must be traversed on the way down to that file are excluded or else the file will never be discovered to be included. As an example, if the directory "a/path" was given as a transfer argument and you want to ensure that the file "a/path/down/deep/wanted.txt" is a part of the transfer, then the sender must not exclude the directories "a/path", "a/path/down", or "a/path/down/deep" as it makes it way scanning through the file tree.

When you are working on the rules, it can be helpful to ask rsync to tell you what is being excluded/included and why. Specifying --debug=FILTER or (when pulling files) -M--debug=FILTER turns on level 1 of the FILTER debug information that will output a message any time that a file or directory is included or excluded and which rule it matched. Beginning in 3.2.4 it will also warn if a filter rule has trailing whitespace, since an exclude of "foo " (with a trailing space) will not exclude a file named "foo".

Exclude and include rules can specify wildcard PATTERN MATCHING RULES (similar to shell wildcards) that allow you to match things like a file suffix or a portion of a filename.

A rule can be limited to only affecting a directory by putting a trailing slash onto the filename.

SIMPLE INCLUDE/EXCLUDE EXAMPLE

With the following file tree created on the sending side:

mkdir x/
touch x/file.txt
mkdir x/y/
touch x/y/file.txt
touch x/y/zzz.txt
mkdir x/z/
touch x/z/file.txt

Then the following rsync command will transfer the file "x/y/file.txt" and the directories needed to hold it, resulting in the path "/tmp/x/y/file.txt" existing on the remote host:

rsync -ai -f'+ x/' -f'+ x/y/' -f'+ x/y/file.txt' -f'- *' x host:/tmp/

Aside: this copy could also have been accomplished using the -R option (though the 2 commands behave differently if deletions are enabled):

rsync -aiR x/y/file.txt host:/tmp/

The following command does not need an include of the "x" directory because it is not a part of the transfer (note the trailing slash). Running this command would copy just "/tmp/x/file.txt" because the "y" and "z" dirs get excluded:

rsync -ai -f'+ file.txt' -f'- *' x/ host:/tmp/x/

This command would omit the zzz.txt file while copying "x" and everything else it contains:

rsync -ai -f'- zzz.txt' x host:/tmp/

FILTER RULES WHEN DELETING

By default the include & exclude filter rules affect both the sender (as it creates its file list) and the receiver (as it creates its file lists for calculating deletions). If no delete option is in effect, the receiver skips creating the delete-related file lists. This two-sided default can be manually overridden so that you are only specifying sender rules or receiver rules, as described in the FILTER RULES IN DEPTH section.

When deleting, an exclude protects a file from being removed on the receiving side while an include overrides that protection (putting the file at risk of deletion). The default is for a file to be at risk -- its safety depends on it matching a corresponding file from the sender.

An example of the two-sided exclude effect can be illustrated by the copying of a C development directory between 2 systems. When doing a touch-up copy, you might want to skip copying the built executable and the .o files (sender hide) so that the receiving side can build their own and not lose any object files that are already correct (receiver protect). For instance:

rsync -ai --del -f'- *.o' -f'- cmd' src host:/dest/

Note that using -f'-p *.o' is even better than -f'- *.o' if there is a chance that the directory structure may have changed. The "p" modifier is discussed in FILTER RULE MODIFIERS.

One final note, if your shell doesn't mind unexpanded wildcards, you could simplify the typing of the filter options by using an underscore in place of the space and leaving off the quotes. For instance, -f -_*.o -f -_cmd (and similar) could be used instead of the filter options above.

FILTER RULES IN DEPTH

Rsync supports old-style include/exclude rules and new-style filter rules. The older rules are specified using --include and --exclude as well as the --include-from and --exclude-from. These are limited in behavior but they don't require a "-" or "+" prefix. An old-style exclude rule is turned into a "- name" filter rule (with no modifiers) and an old-style include rule is turned into a "+ name" filter rule (with no modifiers).

Rsync builds an ordered list of filter rules as specified on the command-line and/or read-in from files. New style filter rules have the following syntax:

RULE [PATTERN_OR_FILENAME]
RULE,MODIFIERS [PATTERN_OR_FILENAME]

You have your choice of using either short or long RULE names, as described below. If you use a short-named rule, the ',' separating the RULE from the MODIFIERS is optional. The PATTERN or FILENAME that follows (when present) must come after either a single space or an underscore (_). Any additional spaces and/or underscores are considered to be a part of the pattern name. Here are the available rule prefixes:

exclude, '-'
specifies an exclude pattern that (by default) is both a hide and a protect.
include, '+'
specifies an include pattern that (by default) is both a show and a risk.
merge, '.'
specifies a merge-file on the client side to read for more rules.
dir-merge, ':'
specifies a per-directory merge-file. Using this kind of filter rule requires that you trust the sending side's filter checking, so it has the side-effect mentioned under the --trust-sender option.
hide, 'H'
specifies a pattern for hiding files from the transfer. Equivalent to a sender-only exclude, so -f'H foo' could also be specified as -f'-s foo'.
show, 'S'
files that match the pattern are not hidden. Equivalent to a sender-only include, so -f'S foo' could also be specified as -f'+s foo'.
protect, 'P'
specifies a pattern for protecting files from deletion. Equivalent to a receiver-only exclude, so -f'P foo' could also be specified as -f'-r foo'.
risk, 'R'
files that match the pattern are not protected. Equivalent to a receiver-only include, so -f'R foo' could also be specified as -f'+r foo'.
clear, '!'
clears the current include/exclude list (takes no arg)

When rules are being read from a file (using merge or dir-merge), empty lines are ignored, as are whole-line comments that start with a '#' (filename rules that contain a hash character are unaffected).

Note also that the --filter, --include, and --exclude options take one rule/pattern each. To add multiple ones, you can repeat the options on the command-line, use the merge-file syntax of the --filter option, or the --include-from / --exclude-from options.

PATTERN MATCHING RULES

Most of the rules mentioned above take an argument that specifies what the rule should match. If rsync is recursing through a directory hierarchy, keep in mind that each pattern is matched against the name of every directory in the descent path as rsync finds the filenames to send.

The matching rules for the pattern argument take several forms:

o
If a pattern contains a / (not counting a trailing slash) or a "**" (which can match a slash), then the pattern is matched against the full pathname, including any leading directories within the transfer. If the pattern doesn't contain a (non-trailing) / or a "**", then it is matched only against the final component of the filename or pathname. For example, foo means that the final path component must be "foo" while foo/bar would match the last 2 elements of the path (as long as both elements are within the transfer).
o
A pattern that ends with a / only matches a directory, not a regular file, symlink, or device.
o
A pattern that starts with a / is anchored to the start of the transfer path instead of the end. For example, /foo/** or /foo/bar/** match only leading elements in the path. If the rule is read from a per-directory filter file, the transfer path being matched will begin at the level of the filter file instead of the top of the transfer. See the section on ANCHORING INCLUDE/EXCLUDE PATTERNS for a full discussion of how to specify a pattern that matches at the root of the transfer.

Rsync chooses between doing a simple string match and wildcard matching by checking if the pattern contains one of these three wildcard characters: '*', '?', and '[' :

o
a '?' matches any single character except a slash (/).
o
a '*' matches any sequence of characters, but it does not match a slash (/). If you want to match a slash, you must use a wildcard that can match a slash, such as a '**' wildcard (if the pattern contains a '/').
o
a '[...]' matches any single character in the brackets. If the first character after the opening bracket is a caret ('^'), it matches any character not in the brackets. A range of characters can be specified, e.g., '[a-z]'.

Note that the above wildcard matching is similar to, but not identical to, shell globbing. For example, there is no special handling for periods at the beginning of a filename.

REGLAS DE FILTRO

Las reglas de filtro se utilizan para incluir o excluir archivos de la transferencia. Las reglas pueden incluir comodines y modificadores especiales.

o
un '*' coincide con cero o más caracteres que no sean barras inclinadas.
o
un '**' coincide con cero o más caracteres, incluidas las barras inclinadas.
o
un '[' introduce una clase de caracteres, como [a-z] o [[:alpha:]], que debe coincidir con un carácter.
o
un '***' final en el patrón es una abreviatura que permite coincidir con un directorio y todo su contenido utilizando una única regla. Por ejemplo, especificar "dir_name/***" coincidirá tanto con el directorio "dir_name" (como si se hubiera especificado "dir_name/") como con todo lo que hay en el directorio (como si se hubiera especificado "dir_name/**").
o
una barra invertida se puede utilizar para escapar de un carácter comodín, pero solo se interpreta como un carácter de escape si hay al menos un carácter comodín presente en el patrón de coincidencia. Por ejemplo, el patrón "foo\bar" coincide con esa barra invertida única literalmente, mientras que el patrón "foo\bar*" tendría que cambiarse a "foo\\bar*" para evitar que "\b" se convierta solo en "b".

Aquí tienes algunos ejemplos de coincidencia de exclusión/inclusión:

o
La opción -f'- *.o' excluiría todos los nombres de archivo que terminan en .o
o
La opción -f'- /foo' excluiría un archivo (o directorio) llamado foo en el directorio raíz de la transferencia
o
La opción -f'- foo/' excluiría cualquier directorio llamado foo
o
La opción -f'- foo/*/bar' excluiría cualquier archivo/dir llamado bar que estuviera a dos niveles por debajo de un directorio llamado foo (si foo está en la transferencia)
o
Las opciones -f'- /foo/**/bar' excluirían cualquier archivo/dir llamado bar que estuviera a dos o más niveles por debajo de un directorio de nivel superior llamado foo (ten en cuenta que /foo/bar no se excluye con esto)
o
Las opciones -f'+ */' -f'+ *.c' -f'- *' incluirían todos los directorios y archivos fuente .c pero nada más
o
Las opciones -f'+ foo/' -f'+ foo/bar.c' -f'- *' incluirían solo el directorio foo y foo/bar.c (el directorio foo debe incluirse explícitamente o sería excluido por "- *")

MODIFICADORES DE REGLAS DE FILTRO

Los siguientes modificadores se aceptan después de una regla de inclusión (+) o exclusión (-):

o
una / especifica que la regla de inclusión/exclusión debe coincidir con la ruta absoluta del elemento actual. Por ejemplo, -f'-/ /etc/passwd' excluiría el archivo passwd cada vez que la transferencia estuviera enviando archivos desde el directorio "/etc", y "-/ subdir/foo" excluiría siempre "foo" cuando estuviera en un dir llamado "subdir", incluso si "foo" estuviera en la raíz de la transferencia actual.
o
una ! especifica que la inclusión/exclusión tendrá efecto si el patrón no coincide. Por ejemplo, -f'-! */' excluiría todos los no directorios.
o
una C se utiliza para indicar que todas las reglas globales de exclusión de CVS se insertarán como exclusiones en lugar de "-C". No debe seguir ningún argumento.
o
una s se utiliza para indicar que la regla se aplica al lado del remitente. Cuando una regla afecta al lado del remitente, afecta a qué archivos se incluyen en la lista de archivos del remitente. Por defecto, una regla afecta a ambos lados a menos que se especifique --delete-excluded, en cuyo caso las reglas por defecto solo afectan al lado del remitente. Consulte también las reglas hide (H) y show (S), que son una forma alternativa de especificar inclusiones/exclusiones del lado del remitente.
o
una r se utiliza para indicar que la regla se aplica al lado del receptor. Cuando una regla afecta al lado del receptor, evita que se eliminen archivos. Consulte el modificador s para más información. Consulte también las reglas protect (P) y risk (R), que son una forma alternativa de especificar inclusiones/exclusiones del lado del receptor.
o
una p indica que una regla es perecedera, lo que significa que se ignora en los directorios que se están eliminando. Por ejemplo, las reglas por defecto de la opción --cvs-exclude (-C) que excluyen cosas como "CVS" y "*.o" están marcadas como perecederas y no impedirán que un directorio eliminado en el origen se elimine en el destino.
o
una x indica que una regla afecta a los nombres xattr en las operaciones de copia/eliminación de xattr (y, por lo tanto, se ignora al coincidir nombres de archivo/directorio). Si no se especifican reglas de coincidencia de xattr, se utiliza una regla de filtrado de xattr por defecto (consulte la opción --xattrs).

REGLAS DE FILTRO DE ARCHIVOS DE MEZCLA

Puedes mezclar archivos completos en tus reglas de filtro especificando una regla de filtro de mezcla (.) o dir-merge (:), como se introdujo en la sección REGLAS DE FILTRO.

Hay dos tipos de archivos de mezcla: de instancia única (.) y por directorio (:). Un archivo de mezcla de instancia única se lee una vez y sus reglas se incorporan a la lista de filtros en lugar de la regla ".".

Para los archivos de mezcla por directorio, rsync escaneará cada directorio que atraviese en busca del archivo con nombre, fusionando su contenido cuando exista el archivo en la lista actual de reglas heredadas. Estos archivos de reglas por directorio deben crearse en el lado del remitente, ya que es el lado del remitente el que se escanea para ver los archivos disponibles para transferir. Estos archivos de reglas también pueden necesitar ser transferidos al lado del receptor si deseas que afecten a qué archivos no se eliminan (ver REGLAS POR DIRECTORIO Y ELIMINAR más abajo).

Algunos ejemplos:

merge /etc/rsync/default.rules
. /etc/rsync/default.rules
dir-merge .per-dir-filter
dir-merge,n- .non-inherited-per-dir-excludes
:n- .non-inherited-per-dir-excludes

Los siguientes modificadores se aceptan después de una regla de mezcla o dir-merge:

o
un - especifica que el archivo debe consistir solo en patrones de exclusión, sin ningún otro análisis de reglas excepto comentarios dentro del archivo.
o
un + especifica que el archivo debe consistir solo en patrones de inclusión, sin ningún otro análisis de reglas excepto comentarios dentro del archivo.
o
una C es una forma de especificar que el archivo se leerá de manera compatible con CVS. Esto activa 'n', 'w' y '-', pero también permite especificar el token de borrado de lista (!). Si no se proporciona nombre de archivo, se asume ".cvsignore".
o
una e excluirá el nombre del archivo de mezcla de la transferencia; por ejemplo, "dir-merge,e .rules" es como "dir-merge .rules" y "- .rules".
o
una n especifica que las reglas no son heredadas por los subdirectorios.
o
una w especifica que las reglas se dividen por palabras según el espacio en blanco en lugar de la división normal por líneas. Esto también desactiva los comentarios. Nota: el espacio que separa el prefijo de la regla se trata especialmente, por lo que "- foo + bar" se analiza como dos reglas (suponiendo que el análisis de prefijos tampoco estuviera deshabilitado).
o
También puedes especificar cualquiera de los modificadores para las reglas "+" o "-" (arriba) para que las reglas que se leen del archivo tengan por defecto ese modificador establecido (excepto el modificador '!', que no sería útil). Por ejemplo, "merge,-/ .excl" trataría el contenido de .excl como exclusiones de ruta absoluta, mientras que "dir-merge,s .filt" y ":sC" harían que todas sus reglas por directorio se aplicaran solo en el lado del remitente. Si la regla de mezcla especifica los lados a afectar (a través del modificador 's' o 'r' o ambos), entonces las reglas en el archivo no deben especificar lados (a través de un modificador o un prefijo de regla como hide).

Las reglas por directorio se heredan en todos los subdirectorios del directorio donde se encontró el archivo de mezcla, a menos que se usara el modificador 'n'. Las reglas de cada subdirectorio se anteponen a las reglas por directorio heredadas de sus padres, lo que da a las reglas más recientes mayor prioridad que a las reglas heredadas.

Todo el conjunto de reglas de dir-merge se agrupa en el lugar donde se especificó el archivo de mezcla, por lo que es posible anular las reglas de dir-merge a través de una regla que se especificó anteriormente en la lista de reglas globales. Cuando la regla de borrado de lista ("!") se lee de un archivo por directorio, solo borra las reglas heredadas para el archivo de mezcla actual.

Otra forma de evitar que una regla única de un archivo de mezcla por directorio sea heredada es anclarla con una barra inclinada inicial. Las reglas ancladas en un archivo de mezcla por directorio son relativas al directorio del archivo de mezcla, por lo que un patrón "/foo" solo coincidiría con el archivo "foo" en el directorio donde se encontró el archivo de filtro de mezcla por directorio.

Aquí tienes un archivo de filtro de ejemplo que especificarías a través de --filter=". file":

merge /home/user/.global-filter
- *.gz
dir-merge .rules
+ *.[ch]
- *.o
- foo*

Esto mezclará el contenido del archivo /home/user/.global-filter al principio de la lista y también convertirá el nombre de archivo ".rules" en un archivo de filtro por directorio. Todas las reglas leídas antes del inicio del escaneo del directorio siguen las reglas de anclaje globales (es decir, una barra inclinada inicial coincide en la raíz de la transferencia).

Si se especifica un archivo de mezcla por directorio con una ruta que es un directorio padre del primer directorio de transferencia, rsync escaneará todos los directorios padres desde ese punto de partida hasta el directorio de transferencia en busca del indicador por directorio

FILTER RULES

Por ejemplo, aquí tienes un filtro común (ver -F):

--filter=': /.rsync-filter'

Esa regla le dice a rsync que busque el archivo .rsync-filter en todos los directorios desde la raíz hasta el directorio padre de la transferencia, antes de que comience el escaneo normal de directorios del archivo en los directorios que se envían como parte de la transferencia. (Nota: para un demonio rsync, la raíz es siempre la misma que la "ruta" del módulo).

Algunos ejemplos de este pre-escaneo para archivos por directorio:

rsync -avF /src/path/ /dest/dir
rsync -av --filter=': ../../.rsync-filter' /src/path/ /dest/dir
rsync -av --filter=': .rsync-filter' /src/path/ /dest/dir

Los dos primeros comandos anteriores buscarán ".rsync-filter" en "/" y "/src" antes de que el escaneo normal comience a buscar el archivo en "/src/path" y sus subdirectorios. El último comando evita el escaneo del directorio padre y solo busca los archivos ".rsync-filter" en cada directorio que forma parte de la transferencia.

Si desea incluir el contenido de un ".cvsignore" en sus patrones, debe usar la regla ":C", que crea una fusión de directorio del archivo .cvsignore, pero analizada de manera compatible con CVS. Puede usar esto para afectar dónde se coloca la inclusión del archivo .cvsignore por directorio de la opción --cvs-exclude (-C) en sus reglas, colocando ":C" donde desee en sus reglas de filtro. Sin esto, rsync agregaría la regla de fusión de directorio para el archivo .cvsignore al final de todas sus otras reglas (dándole una prioridad menor que sus reglas de línea de comandos). Por ejemplo:

cat <<EOT | rsync -avC --filter='. -' a/ b
+ foo.o
:C
- *.old
EOT
rsync -avC --include=foo.o -f :C --exclude='*.old' a/ b

Ambos comandos rsync anteriores son idénticos. Cada uno fusionará todas las reglas de .cvsignore por directorio en medio de la lista en lugar de al final. Esto permite que sus reglas específicas del directorio reemplacen las reglas que siguen a :C en lugar de estar subordinadas a todas sus reglas. Para afectar las otras reglas de exclusión de CVS (es decir, la lista de exclusiones predeterminada, el contenido de $HOME/.cvsignore y el valor de $CVSIGNORE), debe omitir la opción de línea de comandos -C e insertar en su lugar una regla "-C" en sus reglas de filtro; por ejemplo, "--filter=-C".

REGLA DE FILTRO PARA BORRAR LISTA

Puede borrar la lista actual de inclusión/exclusión utilizando la regla de filtro "!" (como se introdujo en la sección REGLAS DE FILTRO). La lista "actual" es la lista global de reglas (si la regla se encuentra al analizar las opciones de filtro) o un conjunto de reglas por directorio (que se heredan en su propia sublista, por lo que un subdirectorio puede usar esto para borrar las reglas del padre).

PATRONES DE INCLUSIÓN/EXCLUSIÓN CON ANCLA

Como se mencionó anteriormente, los patrones globales de inclusión/exclusión se anclan en la "raíz de la transferencia" (a diferencia de los patrones por directorio, que se anclan en el directorio del archivo de fusión). Si piensa en la transferencia como un subárbol de nombres que se envían del remitente al receptor, la raíz de la transferencia es donde el árbol comienza a duplicarse en el directorio de destino. Esta raíz rige dónde coinciden los patrones que comienzan con /.

Dado que la coincidencia es relativa a la raíz de la transferencia, cambiar la barra inclinada final en una ruta de origen o cambiar el uso de la opción --relative afecta la ruta que necesita usar en su coincidencia (además de cambiar cuánto del árbol de archivos se duplica en el host de destino). Los siguientes ejemplos demuestran esto.

Supongamos que queremos hacer coincidir dos archivos de origen, uno con una ruta absoluta de "/home/me/foo/bar" y otro con una ruta de "/home/you/bar/baz". Así es como difieren las diversas opciones de comando para una transferencia de 2 orígenes:

Archivo de destino: /dest/me/foo/bar
Archivo de destino: /dest/you/bar/baz
Comando de ejemplo: rsync -a /home/me/ /home/you/ /dest
Patrón +/-: /foo/bar (nota la falta de "me")
Patrón +/-: /bar/baz (nota la falta de "you")
Archivo de destino: /dest/foo/bar
Archivo de destino: /dest/bar/baz

Patrón +/-: /home/you/bar/baz (ídem)
Archivo de destino: /dest/home/me/foo/bar
Archivo de destino: /dest/home/you/bar/baz

REGLAS POR DIRECTORIO Y BORRADO

Sin una opción de borrado, las reglas por directorio solo son relevantes en el lado del remitente, por lo que puede excluir libremente los archivos de fusión sin afectar la transferencia. Para facilitar esto, el modificador 'e' agrega esta exclusión por usted, como se ve en estos dos comandos equivalentes:

rsync -av --filter=': .excl' --exclude=.excl host:src/dir /dest
rsync -av --filter=':e .excl' host:src/dir /dest

Sin embargo, si desea realizar un borrado en el lado del receptor Y desea que algunos archivos se excluyan de ser borrados, deberá asegurarse de que el lado del receptor conozca los archivos que se deben excluir. La forma más fácil es incluir los archivos de fusión por directorio en la transferencia y usar --delete-after, ya que esto asegura que el lado del receptor obtenga todas las mismas reglas de exclusión que el lado del remitente antes de que intente borrar algo:

rsync -avF --delete-after host:src/dir /dest

Sin embargo, si los archivos de fusión no forman parte de la transferencia, deberá especificar algunas reglas de exclusión globales (es decir, especificadas en la línea de comandos), o deberá mantener sus propios archivos de fusión por directorio en el lado del receptor. Un ejemplo de lo primero es este (suponga que los archivos .rules remotos se excluyen a sí mismos):

rsync -av --filter=': .rules' --filter='. /my/extra.rules'
   --delete host:src/dir /dest

En el ejemplo anterior, el archivo extra.rules puede afectar a ambos lados de la transferencia, pero (en el lado del remitente) las reglas están subordinadas a las reglas fusionadas de los archivos .rules porque se especificaron después de la regla de fusión por directorio. En un último ejemplo, el lado remoto está excluyendo los archivos .rsync-filter de la transferencia, pero queremos usar nuestros propios archivos .rsync-filter para controlar qué se borra en el lado del receptor. Para hacer esto, debemos excluir específicamente los archivos de fusión por directorio (para que no se borren) y luego colocar reglas en los archivos locales para controlar qué más no se debe borrar. Como uno de estos comandos:

rsync -av --filter=':e /.rsync-filter' --delete \
    host:src/dir /dest
rsync -avFF --delete host:src/dir /dest

REGLAS DE TRANSFERENCIA

Además de las REGLAS DE FILTRO que afectan los escaneos recursivos de archivos que generan la lista de archivos en el lado del remitente y (al borrar) en el lado del receptor, existen reglas de transferencia. Estas reglas afectan qué archivos decide el generador que necesitan ser transferidos sin los efectos secundarios de una regla de filtro de exclusión. Las reglas de transferencia afectan solo a los archivos y nunca a los directorios.

Debido a que una regla de transferencia no afecta lo que entra en la lista de archivos del remitente (y del receptor), no puede tener ningún efecto en qué archivos se borran en el lado del receptor. Por ejemplo, si el archivo "foo" está presente en la lista del remitente pero su tamaño es tal que se omite debido a una regla de transferencia, el lado del receptor no solicita el archivo. Sin embargo, su presencia en la lista de archivos significa que una pasada de borrado no eliminará un archivo coincidente llamado "foo" en el lado del receptor. Por otro lado, una exclusión en el lado del servidor (ocultar) del archivo "foo" deja el archivo fuera de la lista de archivos del servidor, y en ausencia de una exclusión en el lado del receptor (proteger), el receptor eliminará un archivo coincidente llamado "foo" si se solicitan borrados.

Dado que los archivos todavía están en la lista de archivos del remitente, la opción --prune-empty-dirs no juzgará un directorio como vacío, incluso si contiene solo archivos que las reglas de transferencia omitieron.

De manera similar, una regla de transferencia no tiene ningún efecto adicional en qué archivos se borran en el lado del receptor, por lo que establecer un tamaño máximo de archivo para la transferencia no evita que se borren archivos grandes.

Ejemplos de reglas de transferencia incluyen el algoritmo predeterminado de "verificación rápida" (que compara tamaño y tiempo de modificación), la opción --update, la opción --max-size, la opción --ignore-non-existing y algunas otras.

MODO LOTE

El modo lote se puede utilizar para aplicar el mismo conjunto de actualizaciones a muchos sistemas idénticos. Supongamos que se tiene un árbol que se replica en varios hosts. Ahora supongamos que se han realizado algunos cambios en este árbol de origen y esos cambios deben propagarse a los otros hosts. Para hacer esto usando el modo lote, rsync se ejecuta con la opción write-batch para aplicar los cambios realizados en el árbol de origen a uno de los árboles de destino. La opción write-batch hace que el cliente rsync almacene en un "archivo lote" toda la información necesaria para repetir esta operación en otros árboles de destino idénticos.

Generar el archivo lote una vez ahorra tener que realizar la generación de estado del archivo, suma de verificación y bloques de datos más de una vez al actualizar varios árboles de destino. Se pueden usar protocolos de transporte multidifusión para transferir los archivos de actualización por lotes a muchos hosts a la vez, en lugar de enviar los mismos datos a cada host individualmente.

Para aplicar los cambios registrados a otro árbol de destino, ejecute rsync con la opción read-batch, especificando el nombre del mismo archivo lote y el árbol de destino. Rsync actualiza el árbol de destino utilizando la información almacenada en el archivo lote.

ARCHIVOS_DE_BATCH

When rsync is used to update a destination tree, it can optionally write out the information needed to repeat the operation to a batch file. This is done using the --write-batch option. The batch file is named BATCH_FILE where BATCH_FILE is specified on the command line.

When the batch file is created, a second file, BATCH_FILE.sh, is also created. This second file is a simple shell script that can be used to repeat the batch update on another host, or on the same host in a different destination tree. The script is named BATCH_FILE.sh.

If the rsync command line used to create the batch file included a remote source or destination, the script will contain the appropriate rsync command line for that syntax. However, the script is written to be flexible. It takes an optional argument which is the pathname of the destination directory. This allows you to run the script on a host where the destination directory has a different pathname than the one used when creating the batch file. For example, if you created the batch file on host1 using a destination path of /a/b/c, you could later use the script on host2 with a destination path of /x/y/z by running the script like this:

./BATCH_FILE.sh /x/y/z

If no argument is given to the script, it uses the destination pathname that was recorded when the batch file was created. This path is embedded in the script file.

Note that the shell script will append the batch data via standard input, so you may need to redirect standard input when running the script, e.g.:

./BATCH_FILE.sh /path/to/destination < BATCH_FILE

The --read-batch option is used to read batch files. It can be specified on the rsync command line, or it can be implied by running the BATCH_FILE.sh script. If rsync is reading a batch file (either explicitly using --read-batch or implicitly via the BATCH_FILE.sh script), then the options used when the batch file was created are read from the batch file itself. This makes it easy to update a destination tree using a previously saved set of options.

However, some options specified when creating the batch file might not be appropriate when reading the batch file. For example, the source directory might be different. To handle this, the BATCH_FILE.sh script takes an optional argument that specifies the destination directory. If you provide this argument, it will be used by the rsync command inside the script. If you don't provide it, the script will use the destination directory that was specified when the batch file was created.

There is also a BATCH_FILE.sh file generated, which is a command-line suitable for updating a destination tree using the associated batch file. It can be executed using a Bourne (or Bourne-like) shell, optionally passing in an alternate destination tree pathname which is then used instead of the original destination path. This is useful when the destination tree path on the current host differs from the one used to create the batch file.

Examples:

$ rsync --write-batch=foo -a host:/source/dir/ /adest/dir/
$ scp foo* remote:
$ ssh remote ./foo.sh /bdest/dir/
$ rsync --write-batch=foo -a /source/dir/ /adest/dir/
$ ssh remote rsync --read-batch=- -a /bdest/dir/ <foo

In these examples, rsync is used to update /adest/dir/ from /source/dir/ and the information to repeat this operation is stored in "foo" and "foo.sh". The host "remote" is then updated with the batched data going into the directory /bdest/dir. The differences between the two examples reveals some of the flexibility you have in how you deal with batches:

o
The first example shows that the initial copy doesn't have to be local -- you can push or pull data to/from a remote host using either the remote-shell syntax or rsync daemon syntax, as desired.
o
The first example uses the created "foo.sh" file to get the right rsync options when running the read-batch command on the remote host.
o
The second example reads the batch data via standard input so that the batch file doesn't need to be copied to the remote machine first. This example avoids the foo.sh script because it needed to use a modified --read-batch option, but you could edit the script file if you wished to make use of it (just be sure that no other option is trying to use standard input, such as the --exclude-from=- option).

Caveats:

The read-batch option expects the destination tree that it is updating to be identical to the destination tree that was used to create the batch update fileset. When a difference between the destination trees is encountered the update might be discarded with a warning (if the file appears to be up-to-date already) or the file-update may be attempted and then, if the file fails to verify, the update discarded with an error. This means that it should be safe to re-run a read-batch operation if the command got interrupted. If you wish to force the batched-update to always be attempted regardless of the file's size and date, use the -I option (when reading the batch). If an error occurs, the destination tree will probably be in a partially updated state. In that case, rsync can be used in its regular (non-batch) mode of operation to fix up the destination tree.

The rsync version used on all destinations must be at least as new as the one used to generate the batch file. Rsync will die with an error if the protocol version in the batch file is too new for the batch-reading rsync to handle. See also the --protocol option for a way to have the creating rsync generate a batch file that an older rsync can understand. (Note that batch files changed format in version 2.6.3, so mixing versions older than that with newer versions will not work.)

When reading a batch file, rsync will force the value of certain options to match the data in the batch file if you didn't set them to the same as the batch-writing command. Other options can (and should) be changed. For instance --write-batch changes to --read-batch, --files-from is dropped, and the --filter / --include / --exclude options are not needed unless one of the --delete options is specified.

The code that creates the BATCH.sh file transforms any filter/include/exclude options into a single list that is appended as a "here" document to the shell script file. An advanced user can use this to modify the exclude list if a change in what gets deleted by --delete is desired. A normal user can ignore this detail and just use the shell script as an easy way to run the appropriate --read-batch command for the batched data.

The original batch mode in rsync was based on "rsync+", but the latest version uses a new implementation.

ENLACES_SIMBOLICOS

Three basic behaviors are possible when rsync encounters a symbolic link in the source directory.

By default, symbolic links are not transferred at all. A message "skipping non-regular" file is emitted for any symlinks that exist.

If --links is specified, then symlinks are added to the transfer (instead of being noisily ignored), and the default handling is to recreate them with the same target on the destination. Note that --archive implies --links.

If --copy-links is specified, then symlinks are "collapsed" by copying their referent, rather than the symlink.

Rsync can also distinguish "safe" and "unsafe" symbolic links. An example where this might be used is a web site mirror that wishes to ensure that the rsync module that is copied does not include symbolic links to /etc/passwd in the public section of the site. Using --copy-unsafe-links will cause any links to be copied as the file they point to on the destination. Using --safe-links will cause unsafe links to be omitted by the receiver. (Note that you must specify or imply --links for --safe-links to have any effect.)

Symbolic links are considered unsafe if they are absolute symlinks (start with /), empty, or if they contain enough ".." components to ascend from the top of the transfer.

Here's a summary of how the symlink options are interpreted. The list is in order of precedence, so if your combination of options isn't mentioned, use the first line that is a complete subset of your options:

--copy-links
Turn all symlinks into normal files and directories (leaving no symlinks in the transfer for any other options to affect).
--copy-dirlinks
Turn just symlinks to directories into real directories, leaving all other symlinks to be handled as described below.
--links --copy-unsafe-links
Turn all unsafe symlinks into files and create all safe symlinks.
--copy-unsafe-links
Turn all unsafe symlinks into files, noisily skip all safe symlinks.
--links --safe-links
The receiver skips creating unsafe symlinks found in the transfer and creates the safe ones.
--links
Create all symlinks.

For the effect of --munge-links, see the discussion in that option's section.

Note that the --keep-dirlinks option does not effect symlinks in the transfer but instead affects how rsync treats a symlink to a directory that already exists on the receiving side. See that option's section for a warning.

DIAGNÓSTICOS

Rsync occasionally produces error messages that may seem a little cryptic. The one that seems to cause the most confusion is "protocol version mismatch -- is your shell clean?".

This message is usually caused by your startup scripts or remote shell facility producing unwanted garbage on the stream that rsync is using for its transport. The way to diagnose this problem is to run your remote shell like this:

ssh remotehost /bin/true > out.dat

then look at out.dat. If everything is working correctly then out.dat should be a zero length file. If you are getting the above error from rsync then you will probably find that out.dat contains some text or data. Look at the contents and try to work out what is producing it. The most common cause is incorrectly configured shell startup scripts (such as .cshrc or .profile) that contain output statements for non-interactive logins.

If you are having trouble debugging filter patterns, then try specifying the -vv option. At this level of verbosity rsync will show why each individual file is included or excluded.

The USER or LOGNAME environment variables are used to determine the default username sent to an rsync daemon. If neither is set, the username defaults to "nobody". If both are set, USER takes precedence.
RSYNC_PARTIAL_DIR
This environment variable specifies the directory to use for a --partial transfer without implying that partial transfers be enabled. See the --partial-dir option for full details.
RSYNC_COMPRESS_LIST
This environment variable allows you to customize the negotiation of the compression algorithm by specifying an alternate order or a reduced list of names. Use the command rsync --version to see the available compression names. See the --compress option for full details.
RSYNC_CHECKSUM_LIST
This environment variable allows you to customize the negotiation of the checksum algorithm by specifying an alternate order or a reduced list of names. Use the command rsync --version to see the available checksum names. See the --checksum-choice option for full details.
RSYNC_MAX_ALLOC
This environment variable sets an allocation maximum as if you had used the --max-alloc option.
RSYNC_PORT
This environment variable is not read by rsync, but is instead set in its sub-environment when rsync is running the remote shell in combination with a daemon connection. This allows a script such as rsync-ssl to be able to know the port number that the user specified on the command line.
HOME
This environment variable is used to find the user's default .cvsignore file.
RSYNC_CONNECT_PROG
This environment variable is mainly used in debug setups to set the program to use when making a daemon connection. See CONNECTING TO AN RSYNC DAEMON for full details.
RSYNC_SHELL
This environment variable is mainly used in debug setups to set the program to use to run the program specified by RSYNC_CONNECT_PROG. See CONNECTING TO AN RSYNC DAEMON for full details.

rsync - Programa de sincronización y transferencia de archivos remotos

SINOPSIS

rsync [OPTION]... SRC [SRC]... DEST

rsync [OPTION]... SRC [SRC]... [USER@]HOST:DEST

rsync [OPTION]... [USER@]HOST::MODULE [DEST]

rsync [OPTION]... rsync://[USER@]HOST[:PORT]/[MODULE] [DEST]

DESCRIPCIÓN

rsync es una utilidad de software muy popular que implementa un algoritmo de transferencia de archivos remotos y locales que minimiza el tráfico al enviar solo las diferencias entre los archivos de origen y destino.

rsync se usa para muchas cosas, incluyendo copias de seguridad y replicación de espejos de directorios a través de redes de computadoras lentas o veloces.

rsync es extremadamente flexible y tiene una amplia gama de opciones para controlar su comportamiento.

OPCIONES

La mayoría de las opciones comunes de rsync se resumen en la sección RESUMEN DE OPCIONES más abajo. Cada opción se describe en detalle en la sección OPCIONES más adelante.

ESPECIFICACIÓN DE MÓDULOS

Cuando se conecta a un demonio rsync, el argumento de destino puede ser una especificación de módulo. El demonio rsync en el host remoto busca la línea de módulo especificada en su archivo de configuración (rsyncd.conf). El demonio luego exportará los archivos y directorios que se especifiquen en esa entrada de módulo.

El formato de la especificación del módulo es:

[USER@]HOST::MODULE[/SUBSUBCONTROL][?FILTER...]

El módulo puede tener parámetros adicionales, separados por un signo de interrogación (?) al final del nombre del módulo. Estos son filtros de inclusión/exclusión de archivos que se aplican al módulo de destino. Por ejemplo, para copiar todos los archivos de un módulo excepto los archivos *.tmp:

rsync -av host::module?*.tmp - /ruta/a/destino

DELETIONS LOCALES

rsync intenta ser inteligente acerca de las eliminaciones locales. Si la eliminación está habilitada y se le pide que elimine un directorio, rsync intentará eliminar el directorio localmente en el destino.

LISTA DE ARCHIVOS TRANSFERIDOS

Si se especifica la opción --itemize-changes (-i), rsync generará una lista de los archivos que se han cambiado, junto con un código de estado que describe el tipo de cambio.

ESPECIFICACIÓN DE SOBRESCRITURA

rsync permite la sobrescritura condicional de archivos. Si un archivo está presente en el destino y en el origen, y el archivo de origen es más nuevo (o tiene la misma fecha de modificación), entonces el archivo de destino se sobrescribe.

PROGRAMA REMOTE-SHELL

rsync se puede usar con un programa de shell remoto para conectarse a la máquina remota. Por defecto, este es ssh. Puedes especificar otro programa usando la opción -e ssh --rsh=/ruta/a/otro/programa.

RELACIÓN DEMONIO RSYNC

rsync puede funcionar en modo cliente/servidor. El demonio rsync se ejecuta en el host remoto y espera conexiones. Cuando un cliente rsync se conecta al demonio, puede solicitar la transferencia de archivos o directorios específicos. El demonio rsync está configurado a través de un archivo de configuración (rsyncd.conf).

SOLICITUDES DE CLIENTE

Cuando rsync se ejecuta en modo cliente, envía una solicitud al demonio rsync remoto. El demonio rsync procesa la solicitud y envía una lista de archivos que necesitan ser transferidos. Luego, el cliente rsync envía los archivos modificados al demonio.

COINCIDENCIA AVANZADA

rsync tiene capacidades de coincidencia avanzadas. Puede especificar patrones de inclusión y exclusión para controlar qué archivos se incluyen o excluyen de la transferencia. Estos patrones se especifican en la línea de comandos o en un archivo de configuración.

TUNELIZACIÓN

rsync puede usar la tunelización para conectarse a hosts remotos. Esto se hace típicamente usando ssh. La opción -L permite la tunelización de enlaces simbólicos, y la opción -K permite la tunelización de conexiones.

REDUNDANCIA REDUCIDA

rsync puede reducir la redundancia al transferir solo los bloques de datos que han cambiado. Esto se logra dividiendo los archivos en bloques y comparando los bloques entre el origen y el destino. Luego, solo se transfieren los bloques que han cambiado.

DETALLES GENERALES DEL PROTOCOLO

rsync usa un protocolo de comunicación para transferir archivos. El protocolo se basa en el algoritmo de diferencia de rsync. El cliente y el servidor intercambian información sobre los archivos y directorios, y luego solo se transfieren los datos modificados.

DEMONIO DE RED

El demonio rsync es un programa de servidor que escucha las conexiones entrantes de los clientes rsync. El demonio rsync se configura a través de un archivo de configuración (rsyncd.conf). Este archivo especifica qué directorios están disponibles para la transferencia y qué opciones de seguridad se aplican.

INTERNET SOBRE RSYNC

rsync se puede usar para transferir archivos a través de Internet. Cuando se usa sobre Internet, rsync generalmente usa ssh como programa de shell remoto para proporcionar cifrado y autenticación.

USO

rsync [OPCIONES]... FUENTE [FUENTE]... DESTINO

rsync [OPCIONES]... [USUARIO@]HOST:DESTINO

rsync [OPCIONES]... [USUARIO@]HOST::MÓDULO [DESTINO]

rsync [OPCIONES]... rsync://[USUARIO@]HOST[:PUERTO]/[MÓDULO] [DESTINO]

COPIAR A UN NOMBRE DIFERENTE

Para copiar un archivo o directorio a un nombre diferente, simplemente especifique el nombre de destino deseado.

rsync -a mi_archivo.txt mi_archivo_copia.txt

rsync -a mi_directorio/ mi_directorio_copia/

ORDEN DE TRANSFERENCIA ORDENADO

rsync puede transferir archivos en un orden ordenado. Esto se logra usando la opción --sort-transfer.

SEGURIDAD MULTI-HOST

rsync se puede usar para transferir archivos de manera segura a través de múltiples hosts. Esto se logra típicamente usando ssh como programa de shell remoto y configurando claves SSH para la autenticación sin contraseña.

USO AVANZADO

rsync tiene muchas opciones avanzadas para controlar el comportamiento de transferencia. Estas incluyen filtros de exclusión/inclusión, compresión, cifrado y más.

CONEXIÓN A UN DEMONIO RSYNC

Para conectarse a un demonio rsync, use el siguiente formato:

rsync [OPCIONES]... [USUARIO@]HOST::MÓDULO [DESTINO]

O:

rsync [OPCIONES]... rsync://[USUARIO@]HOST[:PUERTO]/[MÓDULO] [DESTINO]

USO DE FUNCIONES DEL DEMONIO RSYNC A TRAVÉS DE UNA CONEXIÓN REMOTE-SHELL

Puedes usar las características del demonio rsync a través de una conexión remota-shell normal (como ssh) especificando el nombre del módulo con un rsync:// prefijo.

INICIO DE UN DEMONIO RSYNC PARA ACEPTAR CONEXIONES

Para iniciar un demonio rsync que acepte conexiones, use el siguiente comando:

rsync --daemon [OPCIONES]

El demonio rsync se configura a través del archivo /etc/rsyncd.conf.

EJEMPLOS

Copiar un directorio localmente, preservando permisos, propiedad y tiempos de modificación:

rsync -a /ruta/a/origen/ /ruta/a/destino/

Copiar un directorio a un host remoto usando ssh:

rsync -avz -e ssh /ruta/a/origen/ usuario@remoto:/ruta/a/destino/

Sincronizar un directorio con un demonio rsync:

rsync -av --progress /ruta/a/origen/ usuario@remoto::modulo_destino

OPCIONES

Las opciones se describen en detalle en las páginas del manual de rsync.

OPCIONES DE DEMONIO

Las opciones para el demonio rsync se configuran en /etc/rsyncd.conf.

REGLAS DE FILTRO

rsync soporta reglas de filtro para incluir y excluir archivos y directorios específicos. Estas reglas se pueden especificar en la línea de comandos o en un archivo.

REGLAS DE TRANSFERENCIA

Las reglas de transferencia se utilizan para controlar cómo se transfieren los archivos. Por ejemplo, puede especificar que los archivos más grandes se transfieran primero.

MODO LOTE

El modo lote (--batch) se utiliza para realizar operaciones de rsync en un conjunto de archivos que se especifican en un archivo. Esto es útil para automatizar copias de seguridad.

ENLACES SIMBÓLICOS

rsync tiene varias opciones para controlar cómo se manejan los enlaces simbólicos. Por defecto, rsync copia los enlaces simbólicos como enlaces simbólicos. Puede usar la opción -l para copiar enlaces simbólicos como enlaces simbólicos, o la opción -L para copiar el contenido del archivo al que apunta el enlace simbólico.

DIAGNÓSTICOS

rsync proporciona mensajes de diagnóstico detallados para ayudar a depurar problemas. Puede aumentar la verbosidad usando la opción -v.

VALORES DE SALIDA

rsync devuelve un valor de salida de 0 si la transferencia fue exitosa. Un valor distinto de cero indica un error. Los códigos de error específicos se detallan en las páginas del manual de rsync.

RSYNC_OPTIONS
