NOMBRE

rscsi - servidor de protocolo de transporte SCSI genérico remoto

SINOPSIS

/opt/schily/sbin/rscsi

DESCRIPCIÓN

El comando rscsi es un programa servidor de transporte SCSI genérico remoto. rscsi es un programa que se ejecuta localmente en la máquina con dispositivos SCSI, es utilizado por programas remotos como cdrecord(1), cdda2wav(1), readcd(1) y sformat(1) que acceden a dispositivos SCSI a través de una conexión de comunicación interprocesos mediante libscg. rscsi normalmente se inicia con una llamada a rexec(3) o rcmd(3), pero también puede ser conectado a través de una tubería interna a una sesión de ssh(1) que fue configurada por el usuario remoto.

El programa rscsi acepta solicitudes de scg_open, scg_close, scg_cmd y similares, todas relacionadas con la interfaz de libscg. rscsi ejecuta los comandos y luego responde con una indicación de estado.

El programa rscsi está preparado para ser instalado como un shell de usuario en el archivo passwd para crear inicios de sesión y verificaciones de seguridad específicos para SCSI remotos.

Todas las solicitudes se envían al programa rscsi en ASCII y, por lo tanto, son independientes del orden de bytes y de la máquina.

Todas las respuestas se envían de vuelta en ASCII y en una de las siguientes dos formas.

Todos los comandos exitosos (excepto el comando "S" que envía comandos SCSI) tienen respuestas de

Anúmero\n

donde número es la representación en ASCII de un número decimal que usualmente es el código de retorno de la llamada del sistema o función correspondiente.

Todos los comandos fallidos se responden con

Enúmero-de-error\nmensaje-de-error\nlongitud-xerror\ntexto-xerror

donde número-de-error es uno de los posibles números de error descritos en intro(2), y mensaje-de-error es la cadena de error correspondiente obtenida por strerror(3), longitud-xerror es la longitud del texto de error adicional texto-xerror y puede ser 0. En caso de que longitud-xerror sea 0, no se envía texto-xerror. Tenga en cuenta que un comando SCSI fallido que devolvió datos de sentido SCSI se considera un comando exitoso y no utiliza el formato de error predeterminado.

El protocolo rscsi implementa los siguientes comandos:


Vqué\n
Devuelve la versión para varias instancias del software en el servidor rscsi. El parámetro qué puede tener los siguientes valores:
0
Devuelve SCG_VERSION de libscg en el servidor rscsi. Esto devuelve la cadena de versión para la capa de adaptación de transporte SCSI de bajo nivel.
1
Devuelve SCG_AUTHOR de libscg en el servidor rscsi. Esto devuelve el nombre del autor de la capa de adaptación de transporte SCSI de bajo nivel.
2
Devuelve SCG_SCCS_ID de libscg en el servidor rscsi. Esto devuelve la cadena de versión SCCS para la capa de adaptación de transporte SCSI de bajo nivel.
20
Devuelve SCG_KVERSION de libscg en el servidor rscsi. Esto devuelve la versión de la instancia del kernel del controlador que está debajo de la capa de adaptación de transporte SCSI de bajo nivel.

Esta llamada puede no ser compatible con todos los sistemas operativos.

Este comando corresponde a la función scg_version(3) de libscg.

Odispositivo\n
Abre el dispositivo SCSI especificado.

Consulte la descripción de la opción dev= en cdrecord(1) para obtener más información sobre los posibles valores del parámetro dispositivo.

Si un dispositivo ya está abierto, se cierra antes de realizar una nueva apertura.

Este comando corresponde a la función scg_open(3) de libscg.

El valor de retorno en caso de éxito es 0.

Cdispositivo\n
Cierra el dispositivo o archivo abierto actualmente. El argumento dispositivo se ignora.

Este comando corresponde a la función scg_close(3) de libscg.

El valor de retorno es el valor de retorno de la función scg_close(3).

Dtamaño\n
Configura el tamaño máximo de DMA para el dispositivo SCSI abierto actualmente. El parámetro tamaño es el tamaño de DMA deseado en bytes.

Este comando corresponde a la función scg_bufsize(3) de libscg.

El valor devuelto es el tamaño de DMA real que se pudo configurar. Este valor puede ser menor que el parámetro tamaño.

Mtamaño\n
Asigna un búfer adecuado para transferencias DMA SCSI.

Este comando corresponde a la función scg_getbuf(3) de libscg.

El valor devuelto es el tamaño de DMA real que se pudo configurar. Este valor puede ser menor que el parámetro tamaño.

F\n
Libera un búfer previamente asignado.

Este comando corresponde a la función scg_freebuf(3) de libscg.

El valor de retorno en caso de éxito es 0.

N\n
Recupera el valor máximo permitido para el número de bus SCSI.

Este comando corresponde a la función scg_numbus(3) de libscg.

El valor de retorno es el valor de retorno de la función scg_numbus(3).

Bnrobus\ncanal\n
Comprueba si existe un bus SCSI con un número de bus igual a nrobus. El parámetro canal se ignora actualmente.

Este comando corresponde a la función scg_havebus(3) de libscg.

El valor de retorno es el valor de retorno de la función scg_havebus(3).

Tnrobus\ncanal\ntarget\nlun\n
Establece la dirección del objetivo SCSI a nrobus, target, lun. El parámetro canal se ignora actualmente.

Este comando corresponde a la función scg_settarget(3) de libscg.

El valor de retorno es el valor de retorno de la función scg_havebus(3).

I\n
Recupera el ID del iniciador SCSI para el bus SCSI actual.

Este comando corresponde a la función scg_initiator_id(3) de libscg.

El valor de retorno es el valor de retorno de la función scg_initiator_id(3).

A\n
Comprueba si el objetivo actual es o puede ser un dispositivo ATAPI.

Este comando corresponde a la función scg_isatapi(3) de libscg.

El valor de retorno es el valor de retorno de la función scg_isatapi(3).

Rqué\n
Realiza un reinicio SCSI. El parámetro qué puede tener los siguientes valores:
0
Prueba si se admite un reinicio SCSI como con la llamada a la función scg_reset(3) con SCG_RESET_NOP.

Este comando corresponde a la llamada a la función scg_reset(3) con el parámetro SCG_RESET_NOP.

1
Realiza un reinicio SCSI global como con la llamada a la función scg_reset(3) con SCG_RESET_ALL.

Este comando corresponde a la llamada a la función scg_reset(3) con el parámetro SCG_RESET_ALL.

2
Realiza un reinicio SCSI por bus como con la llamada a la función scg_reset(3) con SCG_RESET_BUS.

Este comando corresponde a la llamada a la función scg_reset(3) con el parámetro SCG_RESET_BUS.

3
Realiza un reinicio SCSI para el objetivo actual como con la llamada a la función scg_reset(3) con SCG_RESET_TARGET.

Este comando corresponde a la llamada a la función scg_reset(3) con el parámetro SCG_RESET_TARGET.

Sbuffer\n
Envía un comando SCSI dado por buffer. El comando SCSI debe estar en formato de texto ASCII y debe contener todos los campos del paquete de comando SCSI que están definidos en la estructura scg_cmd en scg.h. El búfer del comando SCSI debe estar terminado con un carácter de nueva línea.

Este comando corresponde a la llamada a la función scg_cmd(3) de libscg.

Las respuestas de este comando son específicas para el comando SCSI ejecutado y no siguen el formato de respuesta normal. Si el comando SCSI se ejecutó sin errores, se devuelve una cadena de texto que contiene los datos de respuesta del comando SCSI. Si el comando SCSI falló y devolvió datos de sentido SCSI, se envía un código de error, seguido de los datos de sentido SCSI.

Xbuffer\n
Envía un comando SCSI dado por buffer y espera una respuesta DMA. El comando SCSI debe estar en formato de texto ASCII y debe contener todos los campos del paquete de comando SCSI que están definidos en la estructura scg_cmd en scg.h. El búfer del comando SCSI debe estar terminado con un carácter de nueva línea.

Este comando corresponde a la llamada a la función scg_dma_cmd(3) de libscg.

Las respuestas de este comando son específicas para el comando SCSI ejecutado y no siguen el formato de respuesta normal. Si el comando SCSI se ejecutó sin errores, se devuelve una cadena de texto que contiene los datos de respuesta del comando SCSI. Si el comando SCSI falló y devolvió datos de sentido SCSI, se envía un código de error, seguido de los datos de sentido SCSI.

Lbuffer\n
Envía un comando SCSI dado por buffer y espera una respuesta de bloque. El comando SCSI debe estar en formato de texto ASCII y debe contener todos los campos del paquete de comando SCSI que están definidos en la estructura scg_cmd en scg.h. El búfer del comando SCSI debe estar terminado con un carácter de nueva línea.

Este comando corresponde a la llamada a la función scg_block_cmd(3) de libscg.

Las respuestas de este comando son específicas para el comando SCSI ejecutado y no siguen el formato de respuesta normal. Si el comando SCSI se ejecutó sin errores, se devuelve una cadena de texto que contiene los datos de respuesta del comando SCSI. Si el comando SCSI falló y devolvió datos de sentido SCSI, se envía un código de error, seguido de los datos de sentido SCSI.

Hbuffer\n
Envía un comando SCSI dado por buffer y espera una respuesta de lectura. El comando SCSI debe estar en formato de texto ASCII y debe contener todos los campos del paquete de comando SCSI que están definidos en la estructura scg_cmd en scg.h. El búfer del comando SCSI debe estar terminado con un carácter de nueva línea.

Este comando corresponde a la llamada a la función scg_read_cmd(3) de libscg.

Las respuestas de este comando son específicas para el comando SCSI ejecutado y no siguen el formato de respuesta normal. Si el comando SCSI se ejecutó sin errores, se devuelve una cadena de texto que contiene los datos de respuesta del comando SCSI. Si el comando SCSI falló y devolvió datos de sentido SCSI, se envía un código de error, seguido de los datos de sentido SCSI.

Wbuffer\n
Envía un comando SCSI dado por buffer y espera una respuesta de escritura. El comando SCSI debe estar en formato de texto ASCII y debe contener todos los campos del paquete de comando SCSI que están definidos en la estructura scg_cmd en scg.h. El búfer del comando SCSI debe estar terminado con un carácter de nueva línea.

Este comando corresponde a la llamada a la función scg_write_cmd(3) de libscg.

Las respuestas de este comando son específicas para el comando SCSI ejecutado y no siguen el formato de respuesta normal. Si el comando SCSI se ejecutó sin errores, se devuelve una cadena de texto que contiene los datos de respuesta del comando SCSI. Si el comando SCSI falló y devolvió datos de sentido SCSI, se envía un código de error, seguido de los datos de sentido SCSI.

Qbuffer\n
Envía un comando SCSI dado por buffer y espera una respuesta de cero bytes. El comando SCSI debe estar en formato de texto ASCII y debe contener todos los campos del paquete de comando SCSI que están definidos en la estructura scg_cmd en scg.h. El búfer del comando SCSI debe estar terminado con un carácter de nueva línea.

Este comando corresponde a la llamada a la función scg_zero_cmd(3) de libscg.

Las respuestas de este comando son específicas para el comando SCSI ejecutado y no siguen el formato de respuesta normal. Si el comando SCSI se ejecutó sin errores, se devuelve una cadena de texto que contiene los datos de respuesta del comando SCSI. EJEMPLOS

Para usar rscsi remotamente con cdrecord(1), primero debe configurar la entrada remota apropiada en su archivo ~/.rhosts o /etc/hosts.equiv.

ssh -l root server_with_scsi_devices /opt/schily/sbin/rscsi

o si desea usar un usuario con privilegios limitados para acceder a un dispositivo específico:

ssh -l scsi_user server_with_scsi_devices /opt/schily/sbin/rscsi

Ahora, en el cliente, puede ejecutar:

cdrecord dev=server_with_scsi_devices: dev_file=/dev/cdrom speed=4

o para un dispositivo específico en el servidor:

cdrecord dev=server_with_scsi_devices:/dev/sg0 speed=4

DIAGNÓSTICOS

Si el programa servidor rscsi no se inicia, verifique si el dispositivo está ocupado o si el programa está configurado como shell de usuario en el archivo passwd y si el usuario que lo llama está autorizado para acceder al dispositivo SCSI.

CONSULTE TAMBIÉN

NAME

rscsi — remote SCSI-1 commands

SYNOPSIS

rscsi [-d] [-f file] [-l] [-v] [-s host] [-t host] [-u user] [--help] [--version]

DESCRIPTION

The rscsi command is used to access SCSI devices from remote hosts. It is typically used by services like cdrecord(1), cdda2wav(1), readcd(1), and sformat(1) to access devices on hosts that do not support the direct SCSI-1 interface.

The rscsi server listens on a network socket for incoming commands and forwards them to the local SCSI subsystem.

The following commands are supported by the rscsi server:

H
Get host information. This command does not need any parameters. The reply is:
Hhost_id\nhost_version\n
where host_id is a string describing the host and host_version is a string describing the version of the rscsi server.
Ohost_id\nhost_version\n
Open a connection to the specified SCSI device. This command needs the following parameters:
host_id
A string identifying the host. This is typically the hostname or IP address of the remote host.
host_version
A string identifying the version of the remote host. This is usually the same as the version of the rscsi server.

The reply for a successful open is:

Ohandle\n

handle
A unique identifier for the opened connection.

If an error occurs, the reply is:

Eerror string\n

error string
A string describing the error.

This command corresponds to the scg_open(3) function from libscg.

The return value is the return value from the scg_open(3) function.

Chandle\n
Close the connection associated with the given handle. This command does not need any further parameters. The reply is:
C
Indicates that the connection has been closed successfully.

If an error occurs, the reply is:

Eerror string\n

This command corresponds to the scg_close(3) function from libscg.

The return value is the return value from the scg_close(3) function.

Rhandle\ncount\nflags\n
Reset the SCSI bus or target. This command takes the following parameters:
handle
The handle of the connection to reset.
count
This parameter is ignored for reset operations.
flags
The type of reset to perform:
0
Do nothing. This value corresponds to the value SCG_RESET_NONE.
1
Perform a SCSI target reset as with the SCG_RESET_TGT parameter.
2
Perform a SCSI bus reset as with the SCG_RESET_BUS parameter.

This command corresponds to the scg_reset(3) function from libscg.

The return value is the return value from the scg_reset(3) function.

Scount\nflags\ncdb_len\nsense_len\ntimeout\n
Send a SCSI command to the currently selected target. This command takes the following parameters:
count
The DMA count for this command. If the command is a command that transfers data to the target, the related data is send directly after the SCSI command descriptor block. that is described above.
flags
The flags that apply to this SCSI command:
1
Tell the kernel that the SCSI command will transfer data from the target to the host. This corresponds to the flag value SCG_RECV_DATA.
2
Tell the kernel to send the SCSI command with disconnect/reconnect enabled. This corresponds to the flag value SCG_DISRE_ENA. This flag is not supported on all platforms.
4
Make the kernel silent on SCSI errors. This corresponds to the flag value SCG_SILENT. This flag is not supported on all platforms.
8
Tell the kernel to retry the SCSI command in case of a retryable SCSI transport error. This corresponds to the flag value SCG_CMD_RETRY. This flag is not supported on all platforms.
16
Tell the kernel to send the SCSI command with parity disabled. This corresponds to the flag value SCG_NOPARITY. This flag is not supported on all platforms.
cdb_len
The SCSI command descriptor length for this command. The SCSI command descriptor has to be send with the correct length directly after the new line past the timeout value.
sense_len
The amount of sense data that is expected in return of a failed SCSI command that produces SCSI sense data.
timeout
The timeout for the SCSI command in seconds. Fractions of a second may be specified by sending a floating point number.

The reply for a SCSI command that could be send to the target is:

Acount\nerror\nerrno\nscb\nsense_count\n

count
The DMA count of any data returned from the target. If this count is nonzero, the data is send back directly after the reply block mentioned above.
error
A SCSI error classification from one of the following values:
0
No error occurred. This value corresponds to the value SCG_NO_ERROR .
1
A retryable error occurred while trying to transport the SCSI command to the target. This value corresponds to the value SCG_RETRYABLE .
2
A fatal error occurred while trying to transport the SCSI command to the target. This value corresponds to the value SCG_FATAL .
3
A SCSI timeout occurred. This value corresponds to the value SCG_TIMEOUT .
errno
Any possible UNIX errno value for the SCSI command.
scb
The SCSI status byte
sense_count
The sense count returned for the SCSI command. The SCSI sense data is send back directly after any possible SCSI DMA data received from the target.

This command corresponds to the scg_cmd(3) function from libscg.

The return value is the return value from the scg_cmd(3) function.

Any other command causes rscsi to exit.

FILES

/etc/default/rscsi
Default values can be set for the following options in /etc/default/rscsi. For example:

DEBUG=/tmp/rscsi.debug
USER=rscsi
ACCESS=rscsi myhost.mydomain.org 1 -1 3 0

All keywords must be on the beginning of a line.

DEBUG
If you like to get debug information, set this to a file name where rscsi should put debug information.
USER
The name of a user (local to the RSCSI server) that may use the services of the rscsi server. More than one USER=name line is possible. A line USER=* grants access to all users.
ACCESS
This keyword is followed by six parameters separated by a TAB. The name of a user (local to the RSCSI server host) that may use the services of the rscsi server followed by the name of a host from where operation is granted followed by a SCSI device specification that is made of bus-number channel (ignored for now) target-id and lun that specify a SCSI device that may be accessed if this ACCESS line matches. If one or more entries of the bus-number channel target-id lun specification is set to -1, this matches any possible value for the related part of the SCSI device specification. More than one ACCESS=name host SCSI-device line is possible.

If standard input of rscsi is not a socket from a remote host, rscsi will compare the host entry from /etc/default/rscsi with the following strings:

PIPE
If stdin is a UNIX pipe.

If you like to allow remote connections that use the ssh protocol, you need to use the word PIPE instead of the real hostname in the matching ACCESS= line.

ILLEGAL_SOCKET
If getpeername() does not work for stdin.
NOT_IP
If getpeername() works for stdin but is not connected to an internet socket.

DIAGNOSTICS

NOTES

The possibility to create a debug file by calling rscsi file has been disabled for security reasons. If you like to debug rscsi edit /etc/default/rscsi and insert a DEBUG entry.

INTERFACE STABILITY

The interfaces provided by rscsi are designed for long term stability. As rscsi depends on interfaces provided by the underlying operating system, the stability of the interfaces offered by rscsi depends on the interface stability of the OS interfaces. Modified interfaces in the OS may enforce modified interfaces in rscsi.
