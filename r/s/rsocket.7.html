RSOCKET(7) Manual del programador de Librdmacm RSOCKET(7)

NOMBRE

rsocket - API de sockets RDMA

SINOPSIS

#include <rdma/rsocket.h>

DESCRIPCIÓN

API y protocolo de sockets RDMA

NOTAS

Rsockets es un protocolo sobre RDMA que soporta una API a nivel de socket para aplicaciones. Las APIs de Rsocket pretenden coincidir con el comportamiento de las llamadas a socket correspondientes, excepto donde se indique lo contrario. Las funciones de Rsocket coinciden con el nombre y la firma de función de las llamadas a socket, con la excepción de que todas las llamadas a función van precedidas de una 'r'.

Las siguientes funciones están definidas:

rsocket

rbind, rlisten, raccept, rconnect

rshutdown, rclose

rrecv, rrecvfrom, rrecvmsg, rread, rreadv

rsend, rsendto, rsendmsg, rwrite, rwritev

rpoll, rselect

rgetpeername, rgetsockname

rsetsockopt, rgetsockopt, rfcntl

Las funciones toman los mismos parámetros que los utilizados para los sockets. Las siguientes capacidades y flags son compatibles en este momento:

PF_INET, PF_INET6, SOCK_STREAM, SOCK_DGRAM

SOL_SOCKET - SO_ERROR, SO_KEEPALIVE (flag soportado, pero ignorado), SO_LINGER, SO_OOBINLINE, SO_RCVBUF, SO_REUSEADDR, SO_SNDBUF

IPPROTO_TCP - TCP_NODELAY, TCP_MAXSEG

IPPROTO_IPV6 - IPV6_V6ONLY

MSG_DONTWAIT, MSG_PEEK, O_NONBLOCK

Rsockets proporciona extensiones más allá de las rutinas de socket normales que permiten la colocación directa de datos en el búfer de una aplicación. Esto también se conoce como soporte de copia cero, ya que los datos se envían y reciben directamente, evitando copias en búferes controlados por la red. Las siguientes llamadas y opciones soportan la colocación directa de datos.

riomap, riounmap, riowrite

off_t riomap(int socket, void *buf, size_t len, int prot, int flags, off_t offset)
Riomap registra un búfer de aplicación con el hardware RDMA
asociado a un rsocket. El búfer se registra para acceso local únicamente (PROT_NONE) o para acceso de escritura remota (PROT_WRITE). Cuando se registra para acceso remoto, el búfer se mapea a un desplazamiento determinado. El desplazamiento lo proporciona el usuario, o si el usuario selecciona -1 para el desplazamiento, rsockets selecciona uno. El par remoto puede acceder a un búfer mapeado por E/S especificando el desplazamiento correcto. No se garantiza que el mapeo esté disponible hasta después de que el par remoto reciba una transferencia de datos iniciada después de que riomap se haya completado.

Para habilitar el uso de llamadas de mapeo de E/S remotas en un rsocket, una aplicación debe establecer el número de mapeos de E/S que están disponibles para el par remoto. Esto se puede hacer utilizando la opción rsetsockopt RDMA_IOMAPSIZE. Por defecto, un rsocket no soporta mapeos de E/S remotos. riounmap

int riounmap(int socket, void *buf, size_t len)
Riounmap elimina el mapeo entre un búfer y un rsocket.

riowrite

size_t riowrite(int socket, const void *buf, size_t count, off_t offset, int flags)
Riowrite permite a una aplicación transferir datos a través de un rsocket
directamente a un búfer mapeado por E/S remotamente. El búfer remoto se especifica a través de un parámetro de desplazamiento, que corresponde a un búfer mapeado por E/S remoto. Desde la perspectiva del remitente, riowrite se comporta de manera similar a rwrite. Desde la vista del receptor, las transferencias de riowrite se redirigen silenciosamente a un búfer de datos predeterminado. Los datos se reciben automáticamente y no se informa al receptor de la transferencia. Sin embargo, los datos de iowrite siguen siendo parte del flujo de datos, de modo que los datos de iowrite se escribirán antes de recibir una transferencia posterior. Un mensaje enviado inmediatamente después de iniciar un iowrite puede usarse para notificar al receptor del iowrite.

Además de las opciones de socket estándar, rsockets soporta opciones específicas para dispositivos y protocolos RDMA. Estas opciones son accesibles a través de rsetsockopt utilizando el nivel de opción SOL_RDMA.

RDMA_SQSIZE - Tamaño entero de la cola de envío subyacente.
RDMA_RQSIZE - Tamaño entero de la cola de recepción subyacente.
RDMA_INLINE - Tamaño entero de los datos en línea.
RDMA_IOMAPSIZE - Número entero de mapeos de E/S remotos soportados
RDMA_ROUTE - struct ibv_path_data del registro de ruta para la conexión.

Tenga en cuenta que los fd de rsockets no se pueden pasar a llamadas que no sean de rsockets. Para aplicaciones que deben mezclar fd de rsocket con fd de socket normales o archivos abiertos, rpoll y rselect soportan la sonda tanto de rsockets como de fd normales.

Las aplicaciones existentes pueden utilizar rsockets mediante una biblioteca de precarga. Dado que rsockets implementa un protocolo de extremo a extremo, ambos lados de una conexión deben usar rsockets. La biblioteca rdma_cm proporciona dicha biblioteca de precarga, librspreload. Para reducir la probabilidad de que la biblioteca de precarga intercepte llamadas sin el conocimiento explícito del usuario, la biblioteca librspreload se instala en el subdirectorio %libdir%/rsocket.

La biblioteca de precarga se puede usar estableciendo LD_PRELOAD al ejecutar. Tenga en cuenta que no todas las aplicaciones funcionarán con rsockets. El soporte está limitado en función de las opciones de socket utilizadas por la aplicación. El soporte para fork() es limitado, pero está disponible. Para usar rsockets con la biblioteca de precarga para aplicaciones que llaman a fork, los usuarios deben establecer la variable de entorno RDMAV_FORK_SAFE=1 tanto en el lado del cliente como en el del servidor de la conexión. En general, fork es soportable para aplicaciones de servidor que aceptan una conexión y luego bifurcan un proceso para manejar la nueva conexión.

rsockets utiliza archivos de configuración que otorgan al administrador control sobre la configuración predeterminada utilizada por rsockets. Utilice archivos bajo /etc/rdma/rsocket como se muestra:

mem_default - tamaño predeterminado del(los) búfer(es) de recepción

wmem_default - tamaño predeterminado del(los) búfer(es) de envío

sqsize_default - tamaño predeterminado de la cola de envío

rqsize_default - tamaño predeterminado de la cola de recepción

inline_default - tamaño predeterminado de los datos en línea

iomap_size - tamaño predeterminado de la tabla de mapeo de E/S remotas

polling_time - número predeterminado de microsegundos para sondear datos antes de esperar

wake_up_interval - número máximo de milisegundos para bloquear en poll. Este valor se utiliza para protegerse contra posibles bloqueos de la aplicación en rpoll().

Todos los archivos de configuración deben contener un único valor entero. Los valores pueden establecerse emitiendo un comando similar al siguiente ejemplo.

echo 1000000 > /etc/rdma/rsocket/mem_default

Si no hay archivos de configuración disponibles, rsockets utiliza valores predeterminados internos. Las aplicaciones pueden anular los valores predeterminados mediante programación a través de la rutina rsetsockopt.

NOMBRE

rdma-core - Bibliotecas y utilidades de espacio de usuario RDMA

SINOPSIS

libibverbs, librdmacm, rdma-pm, rdma-bind-port, rdma-udaddy

DESCRIPCIÓN

El paquete rdma-core proporciona las bibliotecas de espacio de usuario y las utilidades necesarias para utilizar los adaptadores de acceso directo a memoria remota (RDMA) en Linux. RDMA es una tecnología de red que permite a un ordenador acceder directamente a la memoria de otro ordenador sin involucrar al sistema operativo, lo que resulta en una latencia muy baja y un alto rendimiento.

Los componentes clave de rdma-core incluyen:

  • libibverbs: La biblioteca principal para la interacción con dispositivos RDMA. Proporciona una API de bajo nivel para operaciones como la creación de colas de completado (CQ), colas de envío (SQ) y colas de recepción (RQ), así como para la gestión de memorias registradas y la transferencia de datos.
  • librdmacm: Una biblioteca para la gestión de conexiones RDMA. Facilita el establecimiento de conexiones de confianza entre nodos RDMA, manejando la señalización y la autenticación.
  • rdma-pm: Un demonio para la gestión de energía de dispositivos RDMA.
  • rdma-bind-port: Una utilidad para enlazar puertos de servicios a la red RDMA.
  • rdma-udaddy: Una utilidad para la gestión de direcciones de UDP en RDMA.

Estas bibliotecas y utilidades son esenciales para el desarrollo de aplicaciones que utilizan RDMA, como sistemas de almacenamiento de alto rendimiento, computación de alto rendimiento (HPC) y redes de baja latencia.

NOTAS

La configuración y el uso de dispositivos RDMA pueden variar según el hardware y el sistema operativo. Consulte la documentación específica de su proveedor de hardware y el kernel de Linux para obtener instrucciones detalladas.
