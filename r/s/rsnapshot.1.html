NOMBRE

rsnapshot - utilidad para instantáneas de sistemas de archivos remotos

SINOPSIS

rsnapshot [-vtxqVD] [-c archivo_cfg] [comando] [argumentos]

DESCRIPCIÓN

rsnapshot es una utilidad para instantáneas de sistemas de archivos. Puede tomar instantáneas incrementales de sistemas de archivos locales y remotos para cualquier número de máquinas.

Las instantáneas de sistemas de archivos locales se manejan con rsync(1). Las conexiones remotas seguras se manejan con rsync sobre ssh(1), mientras que las conexiones rsync anónimas simplemente usan un servidor rsync. Tanto las transferencias remotas como las locales dependen de rsync.

rsnapshot ahorra mucho más espacio en disco de lo que podría imaginar. La cantidad de espacio requerido es aproximadamente el tamaño de una copia de seguridad completa, más una copia de cada archivo adicional que se cambia. rsnapshot hace un uso extensivo de enlaces duros, por lo que si el archivo no cambia, la siguiente instantánea es simplemente un enlace duro al mismo archivo exacto.

rsnapshot normalmente será invocado como root por un trabajo cron, o una serie de trabajos cron. Es posible, sin embargo, ejecutar como cualquier usuario arbitrario con un archivo de configuración alternativo.

Todas las opciones importantes se especifican en un archivo de configuración, que se encuentra por defecto en /etc/rsnapshot.conf. Se puede especificar un archivo alternativo en la línea de comandos. También hay opciones adicionales que se pueden pasar en la línea de comandos.

Las opciones de la línea de comandos son las siguientes:

-v verboso, muestra los comandos de shell que se están ejecutando

-t prueba, muestra los comandos de shell que se ejecutarían

-c ruta a un archivo de configuración alternativo

-x un sistema de archivos, no cruzar particiones dentro de cada punto de respaldo

-q silencioso, suprimir advertencias no fatales

-V igual que -v, pero con más detalle

-D una manguera de fuego de información de diagnóstico

CONFIGURACIÓN

/etc/rsnapshot.conf es el archivo de configuración por defecto. Todos los parámetros de este archivo deben estar separados por tabulaciones. /etc/rsnapshot.conf.default puede usarse como referencia.

Se recomienda copiar /etc/rsnapshot.conf.default a /etc/rsnapshot.conf, y luego modificar /etc/rsnapshot.conf para que se ajuste a sus necesidades.

Las líneas largas pueden dividirse en varias líneas. Las líneas de "continuación" **deben** comenzar con un espacio o un carácter de tabulación. Las líneas de continuación tendrán todos los espacios en blanco iniciales y finales eliminados, y luego se les añadirá un carácter de tabulación intercalado a la línea anterior cuando se analice el archivo de configuración.

Aquí hay una lista de parámetros permitidos:

config_version Versión del archivo de configuración (requerido). Por defecto es 1.2

snapshot_root Ruta del sistema de archivos local para guardar todas las instantáneas

include_conf Incluir otro archivo en la configuración en este punto.

Esto es recursivo, pero es posible que necesite tener cuidado con las rutas al especificar qué archivo incluir. Comprobamos si el archivo que ha especificado es legible, y mostraremos un error si no lo es. Recomendamos usar una ruta completa. Como caso especial, el valor de include_conf puede estar entre `comillas invertidas`, en cuyo caso se ejecutará y lo que envíe a STDOUT se incluirá en la configuración. Tenga en cuenta que los metacaracteres de shell pueden ser interpretados.

no_create_root Si se establece en 1, rsnapshot no creará el directorio snapshot_root

cmd_rsync Ruta completa a "rsync" (requerido)

cmd_ssh Ruta completa a "ssh" (opcional)

cmd_cp Ruta completa a "cp" (opcional, pero debe ser la versión de GNU)

Si está utilizando Linux, debería descomentar cmd_cp. Si está utilizando una plataforma que no tiene GNU cp, debería dejar cmd_cp comentado.

Con GNU cp, rsnapshot puede encargarse tanto de archivos normales como de archivos especiales (como FIFOs, sockets y dispositivos de bloque/carácter) en una sola pasada.

Si cmd_cp está deshabilitado, rsnapshot usará su propia función incorporada, native_cp_al(), para hacer copias de seguridad de archivos y directorios regulares. Luego, esto será seguido por una llamada separada a rsync, para transferir los archivos especiales (asumiendo que hay algunos).

cmd_rm Ruta completa a "rm" (opcional)

cmd_logger Ruta completa a "logger" (opcional, para soporte de syslog)

cmd_du Ruta completa a "du" (opcional, para informes de uso de disco)

cmd_rsnapshot_diff Ruta completa a "rsnapshot-diff" (opcional)

cmd_preexec

Ruta completa (más cualquier argumento) al script preexec (opcional). Este script se ejecutará inmediatamente antes de cada operación de respaldo (pero no de las rotaciones). Si la ejecución falla, rsnapshot se detendrá inmediatamente.

cmd_postexec

Ruta completa (más cualquier argumento) al script postexec (opcional). Este script se ejecutará inmediatamente después de cada operación de respaldo (pero no de las rotaciones). Si la ejecución falla, rsnapshot se detendrá inmediatamente.

linux_lvm_cmd_lvcreate

linux_lvm_cmd_lvremove

linux_lvm_cmd_mount

linux_lvm_cmd_umount

Rutas a los comandos lvcreate, lvremove, mount y umount, para usar con LVMs de Linux. También puede incluir opciones para los comandos. Los comandos lvcreate, lvremove, mount y umount son necesarios para gestionar instantáneas de volúmenes LVM y son opcionales en caso contrario.

retain [nombre] [número]

"nombre" se refiere al nombre de este nivel de respaldo (por ejemplo, alpha, beta, también llamado 'intervalo'). "número" es el número de instantáneas para este tipo de intervalo que se retendrán. El valor de "nombre" será el comando pasado a rsnapshot para realizar este tipo de respaldo.

Un alias obsoleto para 'retain' es 'interval'.

Ejemplo: retain alpha 6

[root@localhost]# rsnapshot alpha

Para este ejemplo, cada vez que se ejecute, ocurrirá lo siguiente:

Se eliminará <snapshot_root>/alpha.5/, si existe.

Se rotarán +1 todas las <snapshot_root>/alpha.{1,2,3,4}/, si existen.

Se copiará <snapshot_root>/alpha.0/ a <snapshot_root>/alpha.1/ usando enlaces duros.

Cada punto de respaldo (explicado a continuación) se sincronizará con los directorios correspondientes en <snapshot_root>/alpha.0/

Los niveles de respaldo deben especificarse en el archivo de configuración en orden, de más frecuente a menos frecuente. La primera entrada es la que se sincronizará con los puntos de respaldo. Los niveles de respaldo subsiguientes (por ejemplo, beta, gamma, etc.) simplemente rotan, con cada nivel de respaldo superior tomando de la de abajo para su directorio .0.

Ejemplo:

retain alpha 6

retain beta 7

retain gamma 4

beta.0/ se moverá desde alpha.5/, y gamma.0/ se moverá desde beta.6/

alpha.0/ se sincronizará directamente desde el sistema de archivos.

link_dest 1

Si su versión de rsync soporta --link-dest (2.5.7 o más reciente), puede habilitar esto para que rsync maneje algunas cosas que GNU cp o las subrutinas incorporadas harían de otra manera. Habilitar esto hace que rsnapshot tome una rama de código ligeramente más complicada, pero es la mejor manera de soportar archivos especiales en sistemas que no son Linux.

sync_first 1

sync_first cambia el comportamiento de rsnapshot. Cuando está habilitado, todas las llamadas a rsnapshot con varios niveles de respaldo simplemente rotan archivos. Todas las copias de seguridad se manejan llamando a rsnapshot con el argumento "sync". Los archivos sincronizados se almacenan en un directorio ".sync" dentro del snapshot_root.

Esto permite una mejor recuperación en caso de que rsnapshot se interrumpa en medio de una operación de sincronización, ya que los pasos de sincronización y rotación están separados. Esto también significa que puede ejecutar fácilmente "rsnapshot sync" en la línea de comandos sin temor a forzar la rotación de todos los demás directorios. Este beneficio viene al costo de una

más espacio en disco por instantánea. El valor predeterminado es 0 (apagado).

verbose 2

La cantidad de información que se imprimirá cuando se ejecute el programa. Los valores permitidos son del 1 al 5. El valor predeterminado es 2. 
1        Silencioso       Mostrar solo errores fatales
2        Predeterminado    Mostrar advertencias y errores
3        Detallado         Mostrar los comandos de shell equivalentes que se ejecutan
4        Muy Detallado     Igual que detallado, pero con más detalles
5        Depuración        Todo tipo de información

loglevel 3

Este número significa lo mismo que verbose arriba, pero determina cuántos datos se escriben en el archivo de registro, si es que se está escribiendo uno.

logfile /var/log/rsnapshot

Ruta completa del sistema de archivos al archivo de registro de rsnapshot. Si esto está definido, se escribirá un archivo de registro, cuya cantidad de datos se controla con loglevel. Si esto está comentado, no se escribirá ningún archivo de registro.

include [patrón-de-nombre-de-archivo]

Esto se pasa directamente a rsync usando la directiva --include. Este parámetro se puede especificar tantas veces como sea necesario, con un patrón definido por línea. Consulte la página del manual de rsync(1) para conocer la sintaxis.

exclude [patrón-de-nombre-de-archivo]

Esto se pasa directamente a rsync usando la directiva --exclude. Este parámetro se puede especificar tantas veces como sea necesario, con un patrón definido por línea. Consulte la página del manual de rsync(1) para conocer la sintaxis.

include_file /ruta/a/archivo/de/inclusión

Esto se pasa directamente a rsync usando la directiva --include-from. Consulte la página del manual de rsync(1) para conocer la sintaxis.

exclude_file /ruta/a/archivo/de/exclusión

Esto se pasa directamente a rsync usando la directiva --exclude-from. Consulte la página del manual de rsync(1) para conocer la sintaxis.

rsync_short_args -a

Lista de argumentos cortos para pasar a rsync. Si no se especifica, el valor predeterminado es "-a". Tenga en cuenta que todos deben estar juntos. Por ejemplo, "-az" es válido, mientras que "-a -z" no lo es.

"-a" es el "modo archivo" de rsync, que le indica que copie la mayor parte de los metadatos del sistema de archivos que pueda para cada archivo. Esto específicamente *no* incluye información sobre enlaces duros, ya que aumentaría en gran medida el uso de memoria de rsync y lo ralentizaría. Si necesita conservar enlaces duros en sus copias de seguridad, agregue "H" a esto.

rsync_long_args --delete --numeric-ids --relative --delete-excluded

Lista de argumentos largos para pasar a rsync. Los valores predeterminados son
--delete --numeric-ids --relative --delete-excluded Esto significa que la estructura de directorios en cada destino de punto de copia de seguridad coincidirá con la del origen del punto de copia de seguridad.

Se permiten comillas en rsync_long_args, por ejemplo "--rsync-path='sudo /usr/bin/rsync'". Puede usar comillas simples (') o dobles ("), pero las comillas anidadas (incluidas las comillas anidadas mixtas) no están permitidas. Unas comillas similares también están permitidas en rsync_long_args por punto de copia de seguridad.

rsync_numtries 0

Número de intentos adicionales para ejecutar rsync para cada origen de copia de seguridad dado. Cada vez que la operación rsync para una fuente finaliza con un código de salida distinto de cero, rsnapshot repetirá esta operación hasta que se alcance el número configurado de "rsync_numtries" o rsync finalice con éxito. Por defecto, no se realizan intentos repetidos ("rsync_numtries 0").

rsync_wait_between_tries 0

Espera entre intentos en segundos. Especifique la duración en segundos para esperar entre reintentos de la operación rsync. El número de reintentos debe definirse en rsync_numtries. El tiempo de espera predeterminado es de 0 segundos.

ssh_args -p 22

Argumentos que se pasarán a ssh. Si no se especifica, el predeterminado es ninguno.

du_args -csh

Argumentos que se pasarán a du. Si no se especifica, el predeterminado es -csh. GNU du admite -csh, BSD du admite -csk, Solaris du no admite -c en absoluto. Se recomienda la versión de GNU, ya que ofrece la mayoría de las funciones.

lockfile /var/run/rsnapshot.pid

stop_on_stale_lockfile 0

Archivo de bloqueo a utilizar cuando se ejecuta rsnapshot. Esto evita que una segunda invocación sobrescriba la primera. Si no se especifica, no se utiliza ningún archivo de bloqueo. Asegúrese de utilizar un directorio que no sea escribible por todos por motivos de seguridad. Se recomienda encarecidamente el uso de un archivo de bloqueo.

Si existe un archivo de bloqueo cuando rsnapshot se inicia, intentará leer el archivo y se detendrá con un error si no puede. Si *puede* leer el archivo, comprueba si existe un proceso con el PID anotado en el archivo. Si existe, rsnapshot se detiene con un mensaje de error. Si no hay ningún proceso con ese PID, asumimos que el archivo de bloqueo está obsoleto y lo ignoramos *a menos que* stop_on_stale_lockfile esté configurado en 1, en cuyo caso nos detenemos.

stop_on_stale_lockfile tiene un valor predeterminado de 0.

one_fs 1

Evita que rsync cruce particiones del sistema de archivos. Establecer esto a un valor de 1 habilita esta función. 0 lo desactiva. Este parámetro es opcional. El valor predeterminado es 0 (apagado).

use_lazy_deletes 1

Cambia el comportamiento predeterminado de rsnapshot y no elimina inicialmente la instantánea más antigua. En su lugar, mueve ese directorio a _delete.[id_proceso] y continúa como de costumbre. Una vez que la copia de seguridad se haya completado, el archivo de bloqueo se eliminará antes de que rsnapshot comience a eliminar el directorio.

Habilitar esto significa que las instantáneas se toman antes (ya que la eliminación no viene primero), y se permite que otros procesos de rsnapshot comiencen mientras se está realizando la eliminación final. Este beneficio tiene el costo de usar más espacio en disco. El valor predeterminado es 0 (apagado).

Los detalles de cómo funciona esto han cambiado en la versión 1.3.1 de rsnapshot. Originalmente, solo podía haber un directorio .delete por nivel de copia de seguridad. Ahora puede haber muchos, por lo que si su próxima copia de seguridad (por ejemplo) alfa se inicia mientras la anterior todavía está realizando una eliminación perezosa, puede tener temporalmente directorios _delete adicionales.

linux_lvm_snapshotsize 2G

Tamaño de la instantánea (o instantáneas) LVM (opción lvcreate --size).

linux_lvm_snapshotname rsnapshot

Nombre que se utilizará al crear la instantánea (o instantáneas) del volumen lógico LVM (opción lvcreate --name).

linux_lvm_vgpath /dev

Ruta a los Grupos de Volúmenes LVM.

linux_lvm_mountpath /mnt/lvm-snapshot

Punto de montaje que se utilizará para montar temporalmente la (s) instantánea (s).

backup /etc/ localhost/

backup root@example.com:/etc/ example.com/

backup rsync://example.com/path2/ example.com/

backup /var/ localhost/ one_fs=1

backup lvm://vg0/home/path2/ lvm-vg0/

backup_script /usr/local/bin/backup_pgsql.sh pgsql_backup/

Ejemplos:

backup /etc/ localhost/

Copia de seguridad de /etc/ a <snapshot_root>/<retain>.0/localhost/etc/ usando rsync en el sistema de archivos local

backup /usr/local/ localhost/

Copia de seguridad de /usr/local/ a <snapshot_root>/<retain>.0/localhost/usr/local/ usando rsync en el sistema de archivos local

backup root@example.com:/etc/ example.com/

Copia de seguridad de root@example.com:/etc/ a <snapshot_root>/<retain>.0/example.com/etc/ usando rsync sobre ssh

backup example.com:/etc/ example.com/

Lo mismo, pero dejando que ssh elija el nombre de usuario remoto (según lo especificado en ~/.ssh/config, de lo contrario, igual que el nombre de usuario local)

backup root@example.com:/usr/local/ example.com/

Copia de seguridad de root@example.com:/usr/local/ a <snapshot_root>/<retain>.0/example.com/usr/local/ usando rsync sobre ssh

backup rsync://example.com/pub/ example.com/pub/

Copia de seguridad de rsync://example.com/pub/ a <snapshot_root>/<retain>.0/example.com/pub/ usando un servidor rsync anónimo. Tenga en cuenta que, a diferencia de las copias de seguridad de rutas locales y el uso de rsync sobre ssh, los servidores rsync tienen "módulos", que son directorios de nivel superior que se exportan. Por lo tanto, el módulo también debe especificarse en la ruta de destino, como se muestra en el ejemplo anterior (el directorio pub/ al final).

backup /var/ localhost/ one_fs=1

Esto es lo mismo que los otros ejemplos, pero observe la cuarta columna. Aquí es donde se especifican las opciones por punto de copia de seguridad para anular la configuración global. Este parámetro adicional puede tomar varias opciones, separadas por comas.

Es más útil cuando se especifican exclusiones de rsync por copia de seguridad de la siguiente manera:

backup root@somehost:/ somehost +rsync_long_args=--exclude=/var/spool/

Observe el signo +. Eso le indica a rsync_long_args que *agregue* a la lista de argumentos para pasar a rsync en lugar de reemplazar la lista. El signo + solo se admite para rsync_long_args y rsync_short_args de rsnapshot.

backup lvm://vg0/home/path2/ lvm-vg0/

Realiza una copia de seguridad del volumen lógico LVM llamado home, del grupo de volúmenes vg0, en <snapshot_root>/<retain>.0/lvm-vg0/. Creará, montará, hará copia de seguridad, desmontará y eliminará una instantánea LVM por cada entrada lvm://.

backup_script /usr/local/bin/backup_database.sh db_backup/

En este ejemplo, especificamos un script o programa para ejecutar. Este script simplemente debe crear archivos y/o directorios en su directorio de trabajo actual. rsnapshot tomará esa salida y la moverá al directorio especificado en la tercera columna.

NOTAS

Asegúrate de que tu archivo /etc/rsnapshot.conf tenga todos los elementos separados por tabulaciones. Consulta /etc/rsnapshot.conf.default para ver un ejemplo de archivo funcional.

Asegúrate de añadir una barra inclinada al final de todas las referencias a directorios. Si no lo haces, es posible que se creen directorios adicionales en tus instantáneas. Para más información sobre cómo se maneja la barra inclinada final, consulta la página del manual de rsync(1).

Asegúrate de que el directorio de instantáneas tenga permisos chmod 700 y sea propiedad de root (asumiendo que las copias de seguridad las realiza el usuario root). Si el directorio de instantáneas es legible por otros usuarios, podrán modificar las instantáneas que contienen sus archivos, destruyendo así la integridad de las instantáneas.

Si deseas que los usuarios normales puedan restaurar sus propias copias de seguridad, hay varias maneras de conseguirlo. Un escenario sería:

Establece snapshot_root a /.private/.snapshots en /etc/rsnapshot.conf

Establece los permisos de archivo en estos directorios de la siguiente manera:

drwx------    /.private
drwxr-xr-x    /.private/.snapshots

Exporta el directorio /.private/.snapshots a través de NFS de solo lectura, un recurso compartido de Samba de solo lectura, etc.

Consulta el HOWTO de rsnapshot para más información sobre cómo hacer accesibles las copias de seguridad a usuarios no privilegiados.

Para que ssh funcione sin supervisión a través de cron, probablemente querrás usar inicios de sesión con clave pública. Crea una clave ssh sin frase de contraseña para root e instala la clave pública en cada máquina que quieras respaldar. Si estás respaldando archivos del sistema de máquinas remotas, esto probablemente significa inicios de sesión de root sin supervisión. Otra posibilidad es crear un segundo usuario en la máquina solo para copias de seguridad. Dale al usuario un nombre diferente, como "rsnapshot", pero mantén el UID y GID establecidos en 0, para darle privilegios de root. Sin embargo, haz los inicios de sesión más restrictivos, ya sea a través de la configuración de ssh o usando un shell alternativo.

¡TEN CUIDADO! Si un atacante obtiene la clave privada, tendrá acceso libre a todos los sistemas involucrados. Si no estás seguro de cómo hacer esto, consulta ssh(1), sshd(1) y ssh-keygen(1).

Los scripts de copia de seguridad se ejecutan como el mismo usuario que rsnapshot. Típicamente, este es root. Asegúrate de que todos tus scripts de copia de seguridad solo sean escribibles por root y que no llamen a ningún otro programa que no sea propiedad de root. Si no lo haces, cualquiera que pueda escribir en el script de copia de seguridad o en cualquier programa que llame podrá tomar el control total de la máquina. Por supuesto, esta no es una situación exclusiva de rsnapshot.

Por defecto, las transferencias de rsync se realizan utilizando la opción --numeric-ids. Esto significa que los nombres de usuario y los nombres de grupo se ignoran durante las transferencias, pero la información UID/GID se mantiene intacta. La suposición es que las copias de seguridad se restaurarán en el mismo entorno del que provinieron. Sin esta opción, restaurar copias de seguridad de múltiples servidores heterogéneos sería inmanejable. Si estás archivando instantáneas con GNU tar, es posible que quieras usar el parámetro --numeric-owner. Además, ten a mano una copia de los archivos /etc/passwd y /etc/group del sistema archivado para el mapeo de UID/GID a nombres.

Si eliminas puntos de copia de seguridad en el archivo de configuración, los archivos previamente archivados bajo esos puntos permanecerán permanentemente en el directorio de instantáneas a menos que los elimines tú mismo. Si deseas conservar espacio en disco, deberás ir al directorio <snapshot_root> y eliminar manualmente los archivos del directorio ".0" del nivel de copia de seguridad más pequeño.

Por ejemplo, si anteriormente estabas respaldando /home/ con un destino de localhost/, y alpha es tu nivel de copia de seguridad más pequeño, deberías hacer lo siguiente para recuperar ese espacio en disco:

rm -rf <snapshot_root>/alpha.0/localhost/home/

Ten en cuenta que las otras instantáneas tomadas previamente de /home/ seguirán utilizando ese espacio en disco, pero como los archivos se eliminan de alpha.0/, ya no se copiarán a los directorios subsiguientes y, por lo tanto, se eliminarán a su debido tiempo a medida que ocurran las rotaciones.

rsnapshot(1) - rsnapshot-tools
NAME

rsnapshot - a utility for making efficient, incremental backups of local filesystems

SYNOPSIS

rsnapshot [-r | -t | -l] [-c configfile] [-f file] [-p pidfile] [-v] [target...] rsnapshot -V

DESCRIPTION

rsnapshot is a filesystem snapshot utility. It uses asetminus(8) hard links to implement incremental backups of local filesystems. This means that you get the benefits of incremental backups (saving disk space) while the backup appears to the user like a full backup. For each backup cycle, rsnapshot creates a new directory containing files that are hard-linked from the previous backup. If a file has changed since the last backup, a new copy of the file is made. Otherwise, the new backup directory simply points to the old file via a hard link.

rsnapshot can back up to local directories or remote directories accessible via ssh. It supports features such as.

rsnapshot is designed to be run from cron. It reads its configuration from a configuration file, usually /etc/rsnapshot.conf.

CONFIGURATION

The configuration file is divided into sections. Each section is preceded by a line containing the section name in square brackets, e.g. [DEFAULT].

The following options can be set in the configuration file:

snapshot_root
This is the root directory where all snapshots will be stored. For example, if snapshot_root is set to /home/user/backups, then a backup of /home might be stored in /home/user/backups/home.
config_version
This option specifies the version of the configuration file format. It must be set to 1.2.
ssh_args
Arguments to pass to ssh. For example, to disable X11 forwarding, you could use ssh_args="-x".
ssh_identity_file
The identity file to use for ssh authentication. This is useful if you need to use a specific private key to connect to a remote host.
rsync_args
Arguments to pass to rsync. For example, to enable compression, you could use rsync_args="-z".
rsync_path
The path to the rsync executable. This is useful if rsync is not in the default PATH.
link_dest
If this option is set to 1, rsnapshot will use rsync's --link-dest option to hard link unchanged files from the previous backup. This is the default behavior.
template_directory
The directory to use for storing templates. Templates are used to create new snapshot directories.
logfile
The path to the log file. If this option is not set, rsnapshot will log to stdout.
verbose
If this option is set to 1, rsnapshot will be more verbose. This is the default behavior.
quiet
If this option is set to 1, rsnapshot will be less verbose. This overrides the verbose option.
interval
The interval for backups. For example, interval hourly means that rsnapshot will create hourly backups.
path
The path to the directory to back up. This option can be specified multiple times.
USAGE

The following commands are available:

rsnapshot [-r | -t | -l] [-c configfile] [-f file] [-p pidfile] [-v] [target...]
This command performs a backup. The target argument specifies the directory to back up. If no target is specified, all directories specified in the configuration file will be backed up.
rsnapshot -V
This command prints the version of rsnapshot and exits.

The following options are available:

-r
Perform a backup.
-t
Test mode. Perform a backup, but do not create any files or directories.
-l
List mode. List the files that would be backed up.
-c configfile
Use the specified configuration file instead of the default /etc/rsnapshot.conf.
-f file
Specify a file containing a list of directories to back up. This option overrides the path option in the configuration file.
-p pidfile
Write the process ID to the specified pidfile. This is useful for preventing multiple instances of rsnapshot from running at the same time.
-v
Verbose mode. Print more detailed output.
-V
Print the version of rsnapshot and exit.
EXIT VALUES

0 on success, non-zero on failure.

FILES

/etc/rsnapshot.conf: default configuration file

SEE ALSO

rsync(1), setminus(8)

DIAGNOSTICS

rsnapshot logs its actions to stdout and/or a log file specified by the logfile option in the configuration file. Error messages are printed to stderr.

BUGS

Please report bugs to the rsnapshot mailing list or bug tracker.

NOTES

rsnapshot is a powerful tool for creating efficient, incremental backups. It is highly recommended that you read the rsnapshot documentation carefully before using it.
