rsync-ssl(1) Comandos de usuario rsync-ssl(1)

NOMBRE

rsync-ssl - un script auxiliar para conectarse a un demonio rsync ssl

SINOPSIS

rsync-ssl [--tipo=TIPO_SSL] ARGUMENTOS_RSYNC

La versión en línea de esta página de manual (que incluye enlaces cruzados de temas) está disponible en https://download.samba.org/pub/rsync/rsync-ssl.1.

DESCRIPCIÓN

El script rsync-ssl te ayuda a realizar una copia rsync hacia/desde un demonio rsync que requiere conexiones ssl.

El script requiere que especifiques un argumento de demonio rsync con el formato hostname:: (con 2 puntos) o rsync://hostname/. El puerto predeterminado utilizado para la conexión es 874 (uno más que el 873 normal) a menos que se anule en el entorno. Puedes especificar un puerto de anulación mediante --port o incluyéndolo en el lugar normal del formato de URL, aunque ambas opciones requieren que tu versión de rsync sea al menos 3.2.0.

OPCIONES

Si el primer argumento es una opción --tipo=TIPO_SSL, el script solo utilizará ese programa en particular para abrir una conexión ssl en lugar de intentar encontrar un ejecutable openssl o stunnel mediante una heurística simple (suponiendo que la variable de entorno RSYNC_SSL_TYPE tampoco esté configurada -- ver más abajo). Esta opción debe especificar uno de openssl o stunnel. El signo igual es obligatorio para esta opción en particular.

Todas las demás opciones se pasan al comando rsync, así que consulta la página del manual de rsync(1) para obtener más información sobre cómo funciona.

VARIABLES DE ENTORNO

Los scripts auxiliares ssl se ven afectados por las siguientes variables de entorno:

RSYNC_SSL_TYPE
Especifica el tipo de programa que se debe usar para abrir la conexión ssl. Debe ser uno de openssl o stunnel. La opción --tipo=TIPO_SSL la anula, cuando se especifica.
RSYNC_SSL_PORT
Si se especifica, el valor es el número de puerto que se utiliza como predeterminado cuando el usuario no especifica un puerto en su comando rsync. Cuando no se especifica, el número de puerto predeterminado es 874. (Tenga en cuenta que las versiones anteriores de rsync (anteriores a 3.2.0) no comunicaban un valor de número de puerto de anulación al script auxiliar).
RSYNC_SSL_CERT
Si se especifica, el valor es un nombre de archivo que contiene un certificado para usar en la conexión.
RSYNC_SSL_KEY
Si se especifica, el valor es un nombre de archivo que contiene una clave para el certificado proporcionado para usar en la conexión.
RSYNC_SSL_CA_CERT
Si se especifica, el valor es un nombre de archivo que contiene un certificado de autoridad de certificación que se utiliza para validar la conexión.
RSYNC_SSL_OPENSSL
Especifica el ejecutable openssl a ejecutar cuando el tipo de conexión está configurado como openssl. Si no se especifica, se busca "openssl" en el $PATH.
RSYNC_SSL_GNUTLS
Especifica el ejecutable gnutls-cli a ejecutar cuando el tipo de conexión está configurado como gnutls. Si no se especifica, se busca "gnutls-cli" en el $PATH.
RSYNC_SSL_STUNNEL
Especifica el ejecutable stunnel a ejecutar cuando el tipo de conexión está configurado como stunnel. Si no se especifica, se busca primero "stunnel4" y luego "stunnel" en el $PATH.

EJEMPLOS

rsync-ssl -aiv example.com::mod/ destino
rsync-ssl --tipo=openssl -aiv example.com::mod/ destino
rsync-ssl -aiv --port 9874 example.com::mod/ destino
rsync-ssl -aiv rsync://example.com:9874/mod/ destino

EL LADO DEL SERVIDOR

Para obtener ayuda sobre cómo configurar un rsync compatible con SSL/TLS, consulte las instrucciones en rsyncd.conf.

VER TAMBIÉN

rsync(1), rsyncd.conf(5)

ADVERTENCIAS

Tenga en cuenta que el uso de una conexión stunnel requiere al menos la versión 4 de stunnel, lo que debería ser el caso en sistemas modernos. Además, no verifica una conexión contra la colección de certificados CA, por lo que solo cifra la conexión sin ninguna validación de certificado a menos que haya especificado las opciones de certificado del entorno.

Este script también admite una opción --tipo=gnutls, pero en el momento de esta versión, el comando gnutls-cli estaba descartando la salida, lo que lo hacía inutilizable. Si ese error se ha corregido en su versión, no dude en exportar gnutls en una variable de entorno RSYNC_SSL_TYPE para que su uso sea el predeterminado.
