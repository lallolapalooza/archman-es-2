NOMBRE

rcmd, rresvport, iruserok, ruserok, rcmd_af, rresvport_af, iruserok_af, ruserok_af - rutinas para devolver un flujo a un comando remoto

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <netdb.h>    /* O <unistd.h> en algunos sistemas */
int rcmd(char **restrict ahost, unsigned short inport,
            const char *restrict locuser,
            const char *restrict remuser,
            const char *restrict cmd, int *restrict fd2p);
int rresvport(int *port);
int iruserok(uint32_t raddr, int superuser,
            const char *ruser, const char *luser);
int ruserok(const char *rhost, int superuser,
            const char *ruser, const char *luser);
int rcmd_af(char **restrict ahost, unsigned short inport,
            const char *restrict locuser,
            const char *restrict remuser,
            const char *restrict cmd, int *restrict fd2p,
            sa_family_t af);

int iruserok_af(const void *restrict raddr, int superuser,
            const char *restrict ruser, const char *restrict luser,
            sa_family_t af);
int ruserok_af(const char *rhost, int superuser,
            const char *ruser, const char *luser,
            sa_family_t af);

DESCRIPCIÓN

La función rcmd() es utilizada por el superusuario para ejecutar un comando en una máquina remota utilizando un esquema de autenticación basado en números de puerto privilegiados. La función rresvport() devuelve un descriptor de archivo a un socket con una dirección en el espacio de puertos privilegiados. Las funciones iruserok() y ruserok() son utilizadas por los servidores para autenticar clientes que solicitan servicio con rcmd(). Las cuatro funciones son utilizadas por el servidor rshd(8) (entre otros).

rcmd()

La función rcmd() busca el host *ahost usando gethostbyname(3), devolviendo -1 si el host no existe. De lo contrario, *ahost se establece en el nombre estándar del host y se establece una conexión a un servidor que reside en el puerto de Internet bien conocido inport.

Si la conexión tiene éxito, se devuelve un socket en el dominio de Internet de tipo SOCK_STREAM al llamante, y se le da al comando remoto como stdin y stdout. Si fd2p no es cero, entonces se configurará un canal auxiliar a un proceso de control, y se colocará un descriptor de archivo para él en *fd2p. El proceso de control devolverá salida de diagnóstico del comando (unidad 2) en este canal, y también aceptará bytes en este canal como números de señal UNIX, para ser reenviados al grupo de procesos del comando. Si fd2p es 0, entonces el stderr (unidad 2 del comando remoto) se hará igual que el stdout y no se harán provisiones para enviar señales arbitrarias al proceso remoto, aunque es posible que pueda llamar su atención usando datos fuera de banda.

El protocolo se describe en detalle en rshd(8).

rresvport()

La función rresvport() se utiliza para obtener un socket con un puerto privilegiado enlazado a él. Este socket es adecuado para su uso por rcmd() y varias otras funciones. Los puertos privilegiados son los del rango 0 a 1023. Solo un proceso privilegiado (en Linux, un proceso que tiene la capacidad CAP_NET_BIND_SERVICE en el espacio de nombres de usuario que gobierna su espacio de nombres de red) tiene permitido enlazarse a un puerto privilegiado. En la implementación de glibc, esta función restringe su búsqueda a los puertos de 512 a 1023. El argumento port es valor-resultado: el valor que proporciona a la llamada se utiliza como punto de partida para una búsqueda circular del rango de puertos; al retornar (exitosamente), contiene el número de puerto que se enlazó.

iruserok() y ruserok()

Las funciones iruserok() y ruserok() toman la dirección IP o el nombre del host remoto, respectivamente, dos nombres de usuario y una bandera que indica si el nombre del usuario local es el del superusuario. Luego, si el usuario *no* es el superusuario, verifica el archivo /etc/hosts.equiv. Si esa búsqueda no se realiza o no tiene éxito, se verifica el .rhosts en el directorio de inicio del usuario local para ver si se permite la solicitud de servicio.

Si este archivo no existe, no es un archivo regular, pertenece a cualquiera que no sea el usuario o el superusuario, es escribible por cualquiera que no sea el propietario, o está enlazado en cualquier lugar, la verificación falla automáticamente. Se devuelve cero si el nombre de la máquina está listado en el archivo hosts.equiv, o si el host y el nombre de usuario remoto se encuentran en el archivo .rhosts; de lo contrario, iruserok() y ruserok() devuelven -1. Si el dominio local (obtenido de gethostname(2)) es el mismo que el dominio remoto, solo es necesario especificar el nombre de la máquina.

Si se conoce la dirección IP del host remoto, se debe usar iruserok() en lugar de ruserok(), ya que no requiere confiar en el servidor DNS para el dominio del host remoto.

variantes *_af()

Todas las funciones descritas anteriormente funcionan con sockets IPv4 (AF_INET). Las variantes "_af" toman un argumento adicional que permite especificar la familia de direcciones del socket. Para estas funciones, el argumento af puede especificarse como AF_INET o AF_INET6. Además, rcmd_af() admite el uso de AF_UNSPEC.

VALOR DE RETORNO

La función rcmd() devuelve un descriptor de socket válido en caso de éxito. Devuelve -1 en caso de error e imprime un mensaje diagnóstico en el error estándar.

La función rresvport() devuelve un descriptor de socket válido y enlazado en caso de éxito. En caso de fallo, devuelve -1 y establece errno para indicar el error. El código de error EAGAIN se sobrecarga para significar: "Todos los puertos de red en uso".

Para obtener información sobre el retorno de ruserok() y iruserok(), consulte arriba.

NAME

iruserok, iruserok_af - verificar si un usuario remoto está autorizado a llamar a un servicio de red

LIBRARY

Name service switch library (libnss) (libc, -lnsl)

SYNOPSIS

int iruserok(struct in_addr raddr, int superuser, const char * username, const char * remotename);
int iruserok_af(const void * raddr, int superuser, const char * username, const char * remotename);

DESCRIPTION

Estas funciones se utilizan para verificar si un usuario remoto está autorizado a llamar a un servicio de red. Se utilizan comúnmente en los demonios de servicios de red como rshd(8), rexecd(8) y rlogind(8).

El objetivo es verificar si el usuario remoto remotename tiene permiso para iniciar sesión en el sistema local como username. Esto se hace consultando el archivo /etc/hosts.equiv y el archivo $HOME/.rhosts en el directorio personal del usuario local.

Si superuser es distinto de cero, solo se realiza una comprobación estricta de los archivos /etc/hosts.equiv y $HOME/.rhosts. Si superuser es cero, también se permite que el usuario root se conecte desde cualquier host.

La dirección del host remoto se pasa en raddr. Para iruserok, este es un struct in_addr que contiene la dirección IP del host remoto. Para iruserok_af, raddr es un puntero void * que apunta a una estructura de dirección de familia de direcciones (AF_INET o AF_INET6).

El parámetro username es el nombre del usuario local en el que el usuario remoto desea iniciar sesión. El parámetro remotename es el nombre del usuario en el host remoto.

Una llamada exitosa devuelve 1. Una llamada fallida devuelve 0.

RETURN VALUE

Las funciones devuelven 1 si se concede el permiso, 0 en caso contrario.
