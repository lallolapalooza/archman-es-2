NOMBRE

rrdcached - Demonio de caché de datos para rrdtool

SINOPSIS

rrdcached [-a tamaño_alloc] [-b dir_base [-B]] [-F] [-f tiempo_espera] [-G grupo]] [-g] [-j dir_journal] [-L] [-l direccion] [-m modo] [-O] [-o archivo_log] [-P permisos] [-p archivo_pid] [-R] [-s grupo] [-t hilos_escritura] [-U usuario]] [-V nivel_log] [-w tiempo_espera] [-z retraso]

DESCRIPCIÓN

rrdcached es un demonio que recibe actualizaciones de archivos RRD existentes, las acumula y, si se han recibido suficientes o ha pasado un tiempo definido, escribe las actualizaciones en el archivo RRD. Se puede usar un comando de *flush* para forzar la escritura de valores en el disco, de modo que las instalaciones de gráficos y similares puedan trabajar con datos actualizados.

El demonio fue escrito pensando en configuraciones grandes. Estas configuraciones suelen tener problemas relacionados con la E/S tarde o temprano por razones que escapan al alcance de este documento. Consulte la wiki en la página principal de RRDtool para obtener detalles. ¡Consulte también "CONSIDERACIONES DE SEGURIDAD" a continuación antes de usar este demonio! Una descripción detallada de cómo funciona el demonio se puede encontrar en la sección "CÓMO FUNCIONA" a continuación.

OPCIONES

-l direccion
Indica al demonio que se enlace a direccion y acepte conexiones TCP entrantes en ese socket. Si direccion comienza con "unix:", todo lo que siga a ese prefijo se interpreta como la ruta a un socket de dominio UNIX. De lo contrario, la dirección o el nombre del nodo se resuelven usando "getaddrinfo()".

Para sockets de red, se puede especificar un puerto usando el formato "[direccion]:puerto". Si la dirección es una dirección IPv4 o un nombre de dominio completo (es decir, la dirección contiene al menos un punto (".")), los corchetes se pueden omitir, lo que resulta en el patrón (más simple) "direccion:puerto". El puerto por defecto es 42217. Si especifica un socket de red, es obligatorio leer la sección "CONSIDERACIONES DE SEGURIDAD".

Se aceptan los siguientes formatos. Tenga en cuenta que la dirección del socket UNIX debe comenzar con una barra en el segundo caso!

unix:</ruta/al/socket.unix>
/<ruta/al/socket.unix>
<nombre-host-o-ip>
[<nombre-host-o-ip>]:<puerto>
<nombre-host-o-ipv4>:<puerto>

Dada una puerto sin host (por ejemplo, "-l :42217") el demonio escuchará en ese puerto en todas las interfaces de red. Use "-L" para evitar tener que proporcionar explícitamente el puerto si se desea el puerto por defecto.

Si no se especifica ninguna opción -l, se utilizará la dirección por defecto, "unix:/tmp/rrdcached.sock". Se pueden proporcionar múltiples opciones -l.

-L
Indica al demonio que se enlace al puerto TCP por defecto en todas las interfaces disponibles. Es equivalente a "-l ''" sin la confusión de un parámetro de cadena vacía.
-s nombre_grupo|gid
Establece los permisos de grupo de un socket de dominio UNIX. La opción acepta un ID de grupo numérico o un nombre de grupo. Ese grupo tendrá entonces permisos de lectura y escritura (el socket tendrá permisos de archivo 0760) para el socket y, por lo tanto, podrá enviar comandos al demonio. Esto puede ser útil en casos donde no se pueden ejecutar fácilmente todos los procesos RRD con los mismos privilegios de usuario (por ejemplo, scripts CGI que generan gráficos y que normalmente se ejecutan en el contexto de permisos del servidor web).

Esta opción afecta a las siguientes direcciones de socket UNIX (las opciones -l siguientes) o al socket por defecto (si no se han especificado opciones -l), es decir, puede especificar diferentes configuraciones para diferentes sockets.

Por defecto, no se cambia la propiedad ni los permisos del socket y, por lo tanto, se utiliza la configuración predeterminada del sistema.

-m modo
Establece los permisos de archivo de un socket de dominio UNIX. La opción acepta un número octal que representa el patrón de bits para el modo (consulte chmod(1) para más detalles).

Tenga en cuenta que no todos los sistemas respetan esta configuración. En Linux, se requieren permisos de lectura/escritura para conectarse a un socket UNIX. Sin embargo, muchos sistemas derivados de BSD ignoran los permisos para los sockets UNIX. Consulte unix(7) para más detalles.

Esta opción afecta a las siguientes direcciones de socket UNIX (las opciones -l siguientes) o al socket por defecto (si no se han especificado opciones -l), es decir, puede especificar diferentes configuraciones para diferentes sockets.

Por defecto, no se cambia la propiedad ni los permisos del socket y, por lo tanto, se utiliza la configuración predeterminada del sistema.

-P comando[,comando[,...]]
Especifica los comandos aceptados a través de un socket de red y un socket UNIX. Esto permite a los administradores de RRDCacheD controlar las acciones aceptadas desde varias fuentes.

Los argumentos proporcionados a la opción -P son una lista de comandos separados por comas. Por ejemplo, para permitir los comandos "FLUSH" y "PENDING" se podría especificar:

rrdcached -P FLUSH,PENDING $MAS_ARGUMENTOS

La opción -P afecta a las siguientes direcciones de socket (las opciones -l siguientes) o al socket por defecto (si no se han especificado opciones -l). En el siguiente ejemplo, solo el socket de red IPv4 (dirección 10.0.0.1) estará restringido a los comandos "FLUSH" y "PENDING":

rrdcached -l unix:/ruta/algun/camino -P FLUSH,PENDING -l 10.0.0.1

Una lista completa de comandos disponibles se puede encontrar en la sección "Comandos Válidos" a continuación. Hay dos excepciones menores:

  • Los comandos "HELP" y "QUIT" siempre están permitidos.
  • Si el comando "BATCH" está aceptado, el comando . también se aceptará automáticamente.

Por favor, lea también "CONSIDERACIONES DE SEGURIDAD" a continuación.

-V nivel_log
rrdcached bajo carga puede inundar severamente los logs. Esta opción de línea de comandos especifica el nivel de log máximo a utilizar, lo que significa que un mensaje con una verbosidad mayor que el nivel de log se silencia (LOG_EMERG siendo el más bajo y LOG_DEBUG el más alto).

Valores aceptados para "nivel_log" (de menor a mayor verbosidad): LOG_EMERG, LOG_ALERT, LOG_CRIT, LOG_ERR, LOG_WARNING, LOG_NOTICE, LOG_INFO, LOG_DEBUG

Nivel de log por defecto cuando esta bandera NO está presente: LOG_ERR

Ver también: syslog.h

-o archivo_log
Registra en el archivo dado en lugar de syslog.
-w tiempo_espera
Los datos se escriben en disco cada tiempo_espera segundos. Se puede usar un sufijo opcional (por ejemplo, "5m" en lugar de 300 segundos). Si esta opción no se especifica, se utilizará el intervalo predeterminado de 300 segundos.

CÓMO FUNCIONA

Cuando recibe una actualización de datos, rrdcached busca el archivo RRD correspondiente en el disco. Si se encuentra, almacena la actualización en una caché en memoria. Cuando se alcanza una de las condiciones de vaciado (ver más abajo), el demonio escribe todas las actualizaciones pendientes para ese archivo en el disco y luego elimina las actualizaciones de la memoria caché.

Las condiciones de vaciado son:

Un tiempo máximo de espera:
Los datos se escriben en el disco cada 300 segundos (5 minutos) por defecto. Esto se puede cambiar con la opción -w.
Un número máximo de actualizaciones pendientes:
Si el número de actualizaciones pendientes para un archivo RRD excede un cierto umbral, se escribe en el disco. El umbral es de 10 actualizaciones por defecto y se puede cambiar con la opción -c.

Estas condiciones garantizan que los datos se escriban en el disco con una frecuencia razonable, pero también reducen la carga de E/S al agrupar múltiples escrituras.

El demonio se puede controlar enviándole comandos a través del socket especificado con la opción -l. Los comandos disponibles son:

FLUSH
Escribe todas las actualizaciones pendientes en el disco. Este comando puede recibir un nombre de archivo RRD como argumento. Si se proporciona, solo se vaciarán las actualizaciones pendientes para ese archivo específico. Si no se proporciona ningún nombre de archivo, se vaciarán todos los archivos RRD.
RECONNECT
Indica al demonio que intente reconectarse a cualquier archivo RRD al que no pueda acceder actualmente. Esto puede ser útil si los archivos están temporalmente no disponibles (por ejemplo, debido a problemas de montaje NFS).
SET CACHE LIMIT
Establece el número máximo de actualizaciones pendientes permitidas por archivo RRD. El argumento es el nuevo límite.
SET WRITE DELAY
Establece el número de segundos que deben transcurrir antes de que las actualizaciones de un archivo RRD se escriban en el disco. El argumento es el nuevo retraso en segundos.
SET THREAD COUNT
Establece el número de hilos de escritura que utiliza rrdcached. El argumento es el nuevo número de hilos.
GET CACHE LIMIT
Devuelve el número máximo de actualizaciones pendientes permitidas por archivo RRD.
GET WRITE DELAY
Devuelve el número de segundos que deben transcurrir antes de que las actualizaciones de un archivo RRD se escriban en el disco.
GET THREAD COUNT
Devuelve el número de hilos de escritura que utiliza rrdcached.
STATS
Devuelve estadísticas sobre el funcionamiento de rrdcached, incluyendo el número de actualizaciones recibidas, escritas y perdidas.
UNKNOWN COMMAND
Imprime un mensaje de ayuda con todos los comandos disponibles.
QUIT
Hace que el demonio salga limpiamente.

CONSIDERACIONES DE SEGURIDAD

rrdcached se puede controlar de forma remota enviándole comandos a través de un socket de red. Esto puede ser un riesgo de seguridad si no se toman las precauciones adecuadas. Las siguientes consideraciones deben tenerse en cuenta:

  • No exponga el socket de red a Internet. Debería ser accesible solo desde hosts de confianza. Use un firewall para restringir el acceso si es necesario.
  • Utilice la opción -P para restringir los comandos aceptados. Especifique solo los comandos que realmente necesita que estén disponibles. Por ejemplo, si solo necesita vaciar la caché, use "-P FLUSH".
  • Considere el uso de un socket de dominio UNIX en lugar de un socket de red. Los sockets de dominio UNIX están limitados al acceso del sistema de archivos local y, por lo tanto, son intrínsecamente más seguros que los sockets de red.
  • Configure los permisos de usuario y grupo correctamente. Asegúrese de que solo los usuarios autorizados puedan conectarse al socket.

Incumplir estas directrices puede permitir que actores malintencionados obtengan acceso no autorizado a su sistema RRD, lo que podría provocar la corrupción de datos o la denegación de servicio.

EJEMPLOS

Para iniciar rrdcached con la configuración predeterminada (socket UNIX en "/tmp/rrdcached.sock", tiempo de espera de 300 segundos):

rrdcached

Para iniciar rrdcached escuchando en la interfaz de red "192.168.1.100" en el puerto 42217, con un tiempo de espera de 60 segundos y escribiendo en un archivo de registro:

rrdcached -l 192.168.1.100:42217 -w 60 -o /var/log/rrdcached.log

Para iniciar rrdcached utilizando un socket UNIX, configurando los permisos del grupo para que solo el grupo "rrdusers" pueda acceder a él:

rrdcached -l unix:/var/run/rrdcached.sock -s rrdusers

ARCHIVOS

"/var/run/rrdcached.pid"
El archivo PID por defecto si no se especifica la opción -p.

CONSIDERACIONES DE SEGURIDAD

Autenticación

Si tu instalación de rrdtool se compiló sin libwrap, ¡no hay ninguna forma de autenticación para los clientes que se conectan al demonio rrdcache!

Si tu instalación de rrdtool se compiló con libwrap, entonces puedes usar hosts_access para restringir el acceso de los clientes al demonio rrdcache (rrdcached). Para más información sobre cómo usar hosts_access para restringir el acceso al demonio rrdcache, deberías leer las páginas man de hosts_access(5).

Todavía se recomienda encarecidamente instalar un filtro de paquetes o un mecanismo similar para evitar conexiones no autorizadas. A menos que tengas una VLAN o VPN dedicada para esto, ¡usar sockets de red es probablemente una mala idea!

Autorización

Hay una autorización mínima por socket.

La autorización se realiza actualmente por socket. Esto significa que cada socket tiene una lista de comandos que aceptará y aceptará. Solo aceptará aquellos comandos explícitamente listados, pero (actualmente) los aceptará de cualquiera que llegue al socket.

Si se van a utilizar los sockets de red, es necesario restringir los comandos aceptados a los que necesitan los clientes externos. Si, por ejemplo, los clientes externos quieren dibujar gráficos de los datos cacheados, solo se les debería permitir usar el comando "FLUSH".

La autorización no funciona cuando rrdcached se activa por socket a través de systemd.

Cifrado

No hay cifrado.

De nuevo, esto puede añadirse en el futuro, pero por ahora es tu trabajo mantener privados tus datos privados. ¡Instala una VPN o un túnel cifrado si tus estadísticas son confidenciales!

Verificación de integridad

No hay verificación de integridad.

El demonio escribirá ciegamente en cualquier archivo que se le indique, así que realmente deberías crear un usuario separado solo para este demonio. Además, no realiza ninguna comprobación de integridad, por lo que si se le indica que escriba valores para una fecha muy futura, ¡tus archivos se estropearán mucho!

Conclusión

  • La seguridad es trabajo del administrador.
  • Recomendamos permitir el acceso de escritura solo a través de sockets de dominio UNIX.
  • Has sido advertido.

PROTOCOLO

El demonio se comunica con los clientes utilizando un protocolo ASCII basado en líneas, fácil de leer y fácil de escribir. Esto facilita que los scripts implementen el protocolo y que los usuarios puedan usar telnet para conectarse al demonio y probar cosas "a mano".

El protocolo está basado en líneas, esto significa que cada registro consiste en una o más líneas. Una línea se termina con el carácter de salto de línea 0x0A, comúnmente escrito como "\n". En los ejemplos a continuación, este carácter se escribirá como "<LF>" ("line feed").

Después de establecerse la conexión, se espera que el cliente envíe un "comando". Un comando consiste en la palabra clave del comando, posiblemente algunos argumentos y un carácter de nueva línea de terminación. Para una lista de comandos, ver "Comandos Válidos" a continuación.

Ejemplo:

FLUSH /tmp/foo.rrd<LF>

El demonio responde con una línea que consiste en un código de estado y un mensaje de estado corto, separados por uno o más espacios. Un código de estado negativo señala un error, un código de estado positivo o cero señala éxito. Si el código de estado es mayor que cero, indica el número de líneas que siguen a la línea de estado.

Ejemplos:

0 Success<LF>
2 Two lines follow<LF>
This is the first line<LF>
And this is the second line<LF>

Comandos Válidos

Los siguientes comandos son entendidos por el demonio:

FLUSH nombre_archivo
Hace que el demonio ponga nombre_archivo en la cabeza de la cola de actualización (posiblemente moviéndolo allí si el nodo ya está encolado). La respuesta se enviará después de que el nodo haya sido desencolado.
FLUSHALL
Hace que el demonio comience a vaciar TODOS los valores pendientes en disco. Esto retorna inmediatamente, aunque las escrituras puedan llevar mucho tiempo.
PENDING nombre_archivo
Muestra las actualizaciones "pendientes" para un archivo, en orden. Las actualizaciones mostradas aún no se han escrito en el archivo RRD subyacente.
FETCH nombre_archivo CF [inicio [fin] [ds ...]]
Llama a "rrd_fetch" con los argumentos especificados y devuelve el resultado en formato de texto. Si es necesario, el archivo se vacía a disco primero. La función del lado del cliente "rrdc_fetch" (declarada en "rrd_client.h") analiza la salida y se comporta igual que "rrd_fetch_r" para una fácil integración de consultas remotas. ds define las columnas a volcar - si no se dan ninguna, se devuelven todas.
FETCHBIN nombre_archivo CF [inicio [fin] [ds ...]]
Llama a "rrd_fetch" con los argumentos especificados y devuelve el resultado en formato de texto/binario para evitar sobrecarga innecesaria de serialización/deserialización. Si es necesario, el archivo se vacía a disco primero. La función del lado del cliente "rrdc_fetch" (declarada en "rrd_client.h") analiza la salida y se comporta igual que "rrd_fetch_r" para una fácil integración de consultas remotas. ds define las columnas a volcar - si no se dan ninguna, se devuelven todas.
FORGET nombre_archivo
Elimina nombre_archivo de la caché. ¡Las actualizaciones pendientes SE PERDERÁN!
QUEUE
Muestra los archivos que están en la cola de salida. Devuelve cero o más líneas en el siguiente formato, donde <num_vals> es el número de valores a escribir para el <archivo>: 
<num_vals> <archivo>
HELP [comando]
Devuelve un breve mensaje de uso. Si no se da ningún comando, o si comando es HELP, se devuelve una lista de comandos admitidos por el demonio. De lo contrario, se devuelve una breve descripción, que puede contener un puntero a una página de manual. Obviamente, esto está pensado para uso interactivo y el formato en el que se devuelven los comandos y los resúmenes de uso no está bien definido.
STATS
Devuelve una lista de métricas que se pueden utilizar para medir el rendimiento del demonio y comprobar su estado. Para una descripción de los valores devueltos, ver "Valores de Rendimiento" a continuación.

El formato en el que se devuelven los valores es similar a muchos otros protocolos basados en líneas: Cada valor se imprime en una línea separada, cada una consistente en el nombre del valor, dos puntos, uno o más espacios y el valor real.

Ejemplo:

9 Statistics follow
QueueLength: 0
UpdatesReceived: 30
FlushesReceived: 2
UpdatesWritten: 13
DataSetsWritten: 390
TreeNodesNumber: 13
TreeDepth: 4
JournalBytes: 190
JournalRotate: 0
PING
PING-PONG, esto es muy útil cuando se utiliza un grupo de conexiones entre el cliente de usuario y RRDCACHED.

Ejemplo:

0 PONG
UPDATE nombre_archivo valores [valores ...]
Añade más datos a un nombre de archivo. Esta es la operación para la que fue diseñado el demonio, por lo que describir el mecanismo de nuevo es innecesario. Lee "CÓMO FUNCIONA" arriba para una explicación detallada.

Ten en cuenta que rrdcached solo acepta marcas de tiempo absolutas en los valores de actualización. Las cadenas de actualización como "N:1:2:3" se convierten automáticamente a tiempo absoluto por la biblioteca cliente RRD antes de enviarlas a rrdcached.

WROTE nombre_archivo
Este comando se escribe en el journal después de que un archivo se escribe correctamente en disco. Se utiliza durante la reproducción del journal para determinar qué actualizaciones ya se han aplicado. Es solo válido en el journal; no se acepta desde otros canales de comando.
FIRST nombre_archivo [rranum]
Devuelve la marca de tiempo para el primer CDP en la RRA especificada. Por defecto, se utiliza la RRA cero si no se especifica ninguna.
LAST nombre_archivo
Devuelve la marca de tiempo de la última actualización del RRD especificado. Ten en cuenta que la caché no se vacía antes de comprobar, ya que se espera que el cliente lo solicite por separado si es necesario.
INFO nombre_archivo
Devuelve la información de configuración del RRD especificado. Ten en cuenta que la caché no se vacía antes de comprobar, ya que se espera que el cliente lo solicite por separado si es necesario.

La información se devuelve, un elemento por línea, con el formato:

I<nombre_clave> I<tipo> I<valor>

PROTOCOL

The rrdcached daemon accepts commands over a TCP connection. The protocol is text-based. Client commands are sent to the daemon, and the daemon responds with status information, usually "OK" for success or "ERROR" followed by a descriptive message for failure.

CREATE filename [-s stepsize] [-b begintime] [-r sourcefile ...] [-t templatefile] [-O] DSdefinitions ... RRAdefinitions ...
Esto creará el archivo RRD de acuerdo con los parámetros suministrados, siempre que los parámetros sean válidos, y (si se proporciona la opción -O o si rrdcached se inició con la bandera -O) el nombre de archivo especificado no exista ya.
BATCH
Este comando inicia la carga masiva de múltiples comandos. Está diseñado para instalaciones con tasas de actualización extremadamente altas, ya que permite emitir más de un comando por read() y write().

Todos los comandos se ejecutan como si se dieran individualmente, excepto la salida para el usuario. Los mensajes que indican éxito se suprimen y los mensajes de error se retrasan hasta que el cliente termina.

El procesamiento de comandos finaliza cuando el cliente envía un punto (".") en su propia línea. Después de que el cliente haya terminado, el servidor responde con un recuento de errores y la lista de mensajes de error (si los hay). Cada mensaje de error indica el número del comando al que corresponde y el mensaje de error en sí. El primer comando de usuario después de BATCH es el comando número uno.

cliente:  BATCH
servidor:  0 Adelante. Termina con un punto '.' en su propia línea.
cliente:  UPDATE x.rrd 1223661439:1:2:3            <--- comando #1
cliente:  UPDATE y.rrd 1223661440:3:4:5            <--- comando #2
cliente:  y así sucesivamente...
cliente:  .
servidor:  2 Errores
servidor:  1 mensaje para el comando 1
servidor:  12 mensaje para el comando 12
LIST [RECURSIVE] I/<ruta>
Este comando permite listar directorios y bases de datos rrd según lo ve el demonio. El "directorio" raíz es el base_dir (ver '-b dir'). Cuando se invoca con 'LIST RECURSIVE /<ruta>' se comportará de manera similar a 'ls -R' pero limitado a archivos rrd (listando todas las bases rrd en el subárbol de <ruta>, omitiendo directorios vacíos).
SUSPEND nombre de archivo
Suspende la escritura en un archivo RRD. Mientras un archivo está suspendido, todas las métricas para él se almacenan en caché en memoria hasta que se llama a RESUME para ese archivo o se llama a RESUMEALL.
RESUME nombre de archivo
Reanuda la escritura en un archivo RRD previamente suspendido por SUSPEND o SUSPENDALL.
SUSPENDALL
Suspende la escritura en todos los archivos RRD. Mientras un archivo está suspendido, todas las métricas para él se almacenan en caché en memoria hasta que se llama a RESUME para ese archivo o se llama a RESUMEALL.
RESUMEALL
Reanuda la escritura en todos los archivos RRD previamente suspendidos por SUSPEND o SUSPENDALL.
QUIT
Desconecta de rrdcached.

Valores de Rendimiento

Los siguientes contadores son devueltos por el comando STATS:

QueueLength (entero sin signo de 64 bits)
Número de nodos actualmente en cola en la cola de actualización.
UpdatesReceived (entero sin signo de 64 bits)
Número de comandos UPDATE recibidos.
FlushesReceived (entero sin signo de 64 bits)
Número de comandos FLUSH recibidos.
UpdatesWritten (entero sin signo de 64 bits)
Número total de actualizaciones, es decir, llamadas a "rrd_update_r", desde que se inició el demonio.
DataSetsWritten (entero sin signo de 64 bits)
Número total de "conjuntos de datos" escritos en disco desde que se inició el demonio. Un conjunto de datos son uno o más valores pasados al comando UPDATE. Por ejemplo: "1223661439:123:456" es un conjunto de datos con dos valores. El término "conjunto de datos" se utiliza para evitar confusiones sobre si se cuentan valores individuales o grupos de valores.
TreeNodesNumber (entero sin signo de 64 bits)
Número de nodos en la caché.
TreeDepth (entero sin signo de 64 bits)
Profundidad del árbol utilizado para la búsqueda rápida de claves.
JournalBytes (entero sin signo de 64 bits)
Número total de bytes escritos en el journal desde el inicio.
JournalRotate (entero sin signo de 64 bits)
Número de veces que el journal ha sido rotado desde el inicio.

SEÑALES

SIGINT y SIGTERM
El demonio se cierra normalmente al recibir cualquiera de estas señales. Las actualizaciones pendientes se manejan de acuerdo con las opciones -j y -F.
SIGUSR1
El demonio se cierra DESPUÉS de volcar todas las actualizaciones al disco. Esto puede llevar un tiempo.
SIGUSR2
El demonio se cierra inmediatamente, sin volcar las actualizaciones al disco. Las actualizaciones pendientes se reproducirán desde el journal cuando el demonio se inicie de nuevo. ADVERTENCIA: si el journaling (-j) NO está habilitado, cualquier actualización pendiente SE PERDERÁ.
