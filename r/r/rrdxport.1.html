RRDXPORT(1) rrdtool RRDXPORT(1)

NOMBRE

rrdxport - Exporta datos en formato XML basados en datos de uno o varios RRD

SINOPSIS

rrdtool xport [-s|--start segundos] [-e|--end segundos] [-m|--maxrows filas] [--step valor] [--json] [-t|--showtime] [--enumds] [--daemon|-d direccion] [DEF:vname=rrd:nombre-ds:CF] [CDEF:vname=expresion-rpn] [XPORT:vname[:leyenda]]

DESCRIPCIÓN

El propósito principal de la función xport es escribir una representación en formato XML de los datos almacenados en uno o varios RRDs. También puede extraer informes numéricos.

Si no se encuentran declaraciones XPORT, no habrá salida.

-s|--start segundos (por defecto fin-1día)
La hora en que debe comenzar el rango exportado. Se requieren segundos desde la época (1970-01-01). Los números negativos son relativos al tiempo actual. Por defecto, se imprimirá un día de datos. Ver también "ESPECIFICACIÓN DE TIEMPO ESTILO AT-" en rrdfetch para una explicación detallada de cómo especificar el tiempo.

Ver "FORMATO DE SALIDA" a continuación para obtener detalles sobre cómo esto afecta la salida.

-e|--end segundos (por defecto ahora)
La hora en que debe terminar el rango exportado. Tiempo en segundos desde la época. Ver también "ESPECIFICACIÓN DE TIEMPO ESTILO AT-" en rrdfetch para una explicación detallada de cómo especificar el tiempo.

Ver "FORMATO DE SALIDA" a continuación para obtener detalles sobre cómo esto afecta la salida.

-m|--maxrows filas (por defecto 400 filas)
Esto funciona como el parámetro -w|--width de rrdgraph. De hecho, es exactamente lo mismo, pero el parámetro se renombró para describir su propósito en este módulo. Ver la documentación de rrdgraph para detalles.
--step valor (por defecto automático)
Ver documentación de rrdgraph.
--daemon|-d direccion
Dirección del demonio rrdcached. Si se especifica, se envía un comando "flush" al servidor antes de leer los archivos RRD. Esto permite que rrdtool devuelva datos frescos incluso si el demonio está configurado para almacenar en caché valores durante mucho tiempo. Para obtener una lista de formatos aceptados, consulta la opción -l en el manual de rrdcached. 
rrdtool xport --daemon unix:/var/run/rrdcached.sock ...
-t|--showtime
Incluir la hora en cada fila de datos.
--json
Producir salida en formato json (en lugar de xml)
--enumds
El xml generado debe contener los valores de datos en etiquetas enumeradas. 
<v0>valor</v0><v1>valor</v1>
DEF:vname=rrd:nombre-ds:CF
Ver documentación de rrdgraph.
CDEF:vname=expresion-rpn
Ver documentación de rrdgraph.
XPORT:vname[:leyenda]
Debe haber al menos una declaración XPORT. Se imprimen los valores referenciados por vname. Opcionalmente, se puede añadir una leyenda.

FORMATO DE SALIDA

La salida está encerrada en un elemento xport y contiene dos bloques. El primer bloque está encerrado en un elemento meta y contiene algunos metadatos. El segundo bloque está encerrado en un elemento data y contiene las filas de datos.

Supongamos que el comando xport se ve así:

rrdtool xport \
        --start now-1h --end now \
        DEF:xx=host-inout.lo.rrd:output:AVERAGE \
        DEF:yy=host-inout.lo.rrd:input:AVERAGE \
        CDEF:aa=xx,yy,+,8,* \
        XPORT:xx:"bytes de salida" \
        XPORT:aa:"bits de entrada y salida"

La sección de metadatos resultante es (los valores dependerán de las características del RRD):

<meta>
  <start>1020611700</start>
  <step>300</step>
  <end>1020615600</end>
  <rows>14</rows>
  <columns>2</columns>
  <legend>
    <entry>bytes de salida</entry>
    <entry>bits de entrada y salida</entry>
  </legend>
</meta>

La sección de datos resultante es:

<data>
  <row><t>1020611700</t><v>3.4000000000e+00</v><v>5.4400000000e+01</v></row>
  <row><t>1020612000</t><v>3.4000000000e+00</v><v>5.4400000000e+01</v></row>
  <row><t>1020612300</t><v>3.4000000000e+00</v><v>5.4400000000e+01</v></row>
  <row><t>1020612600</t><v>3.4113333333e+00</v><v>5.4581333333e+01</v></row>
  <row><t>1020612900</t><v>3.4000000000e+00</v><v>5.4400000000e+01</v></row>
  <row><t>1020613200</t><v>3.4000000000e+00</v><v>5.4400000000e+01</v></row>
  <row><t>1020613500</t><v>3.4000000000e+00</v><v>5.4400000000e+01</v></row>
  <row><t>1020613800</t><v>3.4000000000e+00</v><v>5.4400000000e+01</v></row>
  <row><t>1020614100</t><v>3.4000000000e+00</v><v>5.4400000000e+01</v></row>
  <row><t>1020614400</t><v>3.4000000000e+00</v><v>5.4400000000e+01</v></row>
  <row><t>1020614700</t><v>3.7333333333e+00</v><v>5.9733333333e+01</v></row>
  <row><t>1020615000</t><v>3.4000000000e+00</v><v>5.4400000000e+01</v></row>
  <row><t>1020615300</t><v>3.4000000000e+00</v><v>5.4400000000e+01</v></row>
  <row><t>1020615600</t><v>NaN</v><v>NaN</v></row>
</data>

Todas las estadísticas en la salida usarán el mismo paso. La primera muestra será la primera muestra que comience inmediatamente después de --start. La última muestra será la que termine en o inmediatamente después de --end.

Cada muestra tiene una marca de tiempo y uno o más valores. Las marcas de tiempo asociadas con un valor en RRDtool SIEMPRE representan la hora en que se tomó la muestra. Dado que cualquier valor que muestree representará algún tipo de estado pasado recopilado por su aparato de muestreo, la marca de tiempo siempre estará al final del período de muestreo.

RRDtool no almacena las muestras reales, sino que realiza un remuestreo interno de los valores que se le presentan. Sin embargo, cuando se presenta un valor de dato con una sola marca de tiempo, la marca de tiempo está al final del período que el valor representa. Tenga en cuenta que la marca de tiempo en sí misma está fuera del período para el que la muestra es válida. Para obtener más detalles sobre esto, consulte la explicación del cálculo de PDP.

Entonces, el rango de tiempo para una muestra con marca de tiempo es en realidad desde "marca de tiempo - paso" inclusivo hasta "marca de tiempo" exclusivo.

La primera línea de la salida de la muestra:

<row><t>1020611700</t><v>3.4000000000e+00</v><v>5.4400000000e+01</v></row>

por lo tanto, significa que los valores para el intervalo 1020611400 a 1020611699 fueron 3.4 y 54.4 para "bytes de salida" y "bits de entrada y salida" respectivamente, porque el valor se tomó a las 1020611700.

EJEMPLO 1

rrdtool xport \
        DEF:out=if1-inouts.rrd:outoctets:AVERAGE \
        XPORT:out:"bytes de salida"

EJEMPLO 2

rrdtool xport \
        DEF:out1=if1-inouts.rrd:outoctets:AVERAGE \
        DEF:out2=if2-inouts.rrd:outoctets:AVERAGE \
        CDEF:sum=out1,out2,+ \
        XPORT:out1:"bytes de salida if1" \
        XPORT:out2:"bytes de salida if2" \
        XPORT:sum:"suma de salida"

VARIABLES DE ENTORNO

Las siguientes variables de entorno pueden ser usadas para cambiar el comportamiento de "rrdtool xport":

RRDCACHED_ADDRESS
Si esta variable de entorno está configurada, tendrá el mismo efecto que especificar la opción "--daemon" en la línea de comandos. Si ambas están presentes, el argumento de la línea de comandos tiene precedencia.
