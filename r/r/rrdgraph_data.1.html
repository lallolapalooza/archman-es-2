RRDGRAPH_DATA(1) rrdtool RRDGRAPH_DATA(1)

NOMBRE

rrdgraph_data - preparación de datos para gráficos en rrdtool graph

SINOPSIS

DEF:<nombre_v>=<archivo_rrd>:<nombre_ds>:<CF>[:step=<paso>][:start=<tiempo>][:end=<tiempo>][:reduce=<CF>][:daemon=<direccion>]

VDEF:nombre_v=expresión RPN

CDEF:nombre_v=expresión RPN

DESCRIPCIÓN

Estas tres instrucciones extraen valores de datos de los archivos RRD, alterándolos opcionalmente (piense, por ejemplo, en una conversión de bytes a bits). Si lo desea, también puede definir variables que contengan información útil como máximo, mínimo, etc. Dos de las instrucciones utilizan un lenguaje llamado RPN que se describe en su propia página del manual.

Los nombres de variables (nombre_v) deben estar compuestos por cadenas de los siguientes caracteres "A-Z, a-z, 0-9, _, -" y tener una longitud máxima de 255 caracteres.

Al elegir nombres de variables, asegúrese de no elegir un nombre que ya esté en uso por un operador RPN. Una apuesta segura es usar nombres en minúsculas o con mayúsculas y minúsculas para las variables, ya que los operadores siempre estarán en mayúsculas.

DEF

DEF:<nombre_v>=<archivo_rrd>:<nombre_ds>:<CF>[:step=<paso>][:start=<tiempo>][:end=<tiempo>][:reduce=<CF>][:daemon=<direccion>]

Este comando recupera datos de un archivo RRD. El nombre virtual nombre_v puede luego usarse en el resto del script. Por defecto, se elegirá un RRA que contenga los datos consolidados correctos con una resolución apropiada. La resolución puede ser anulada con la opción --step. La resolución puede ser anulada nuevamente especificando el tamaño del paso. El período de tiempo de estos datos es el mismo que el del gráfico por defecto, puede anular esto especificando inicio y fin. ¡Recuerde escapar los dos puntos en la especificación de tiempo!

Si la resolución de los datos es mayor que la resolución del gráfico, los datos se consolidarán aún más. Esto puede dar como resultado un gráfico que abarca un tiempo ligeramente mayor del solicitado. Idealmente, cada punto en el gráfico debería corresponder con un CDP de un RRA. Por ejemplo, si su RRD tiene un RRA con una resolución de 1800 segundos por CDP, debería crear una imagen con un ancho de 400 y un período de tiempo de 400*1800 segundos (use tiempos de inicio y fin apropiados, como "--start end-8days8hours").

Si es necesario realizar consolidación, el CF del RRA especificado en el propio DEF se utilizará para reducir la densidad de datos. Este comportamiento se puede cambiar usando ":reduce=<CF>". Este parámetro opcional especifica el CF a usar durante la fase de reducción de datos.

Es posible solicitar fuentes de datos individuales de un RRDCacheD específico, ver rrdcached, usando el parámetro ":daemon=<direccion>". El valor dado a este parámetro sigue la misma sintaxis que otros medios para especificar la dirección del demonio de caché. Se describe en detalle en rrdcached. Tenga en cuenta, sin embargo, que los dos puntos (en direcciones IPv6 y como separador de puertos, por ejemplo) deben escaparse con una barra invertida.

Ejemplo:

DEF:ds0=router.rrd:ds0:AVERAGE
DEF:ds0weekly=router.rrd:ds0:AVERAGE:step=7200
DEF:ds0weekly=router.rrd:ds0:AVERAGE:start=end-1h
DEF:ds0weekly=router.rrd:ds0:AVERAGE:start=11\:00:end=start+1h
DEF:ds0weekly=router.rrd:ds0:AVERAGE:daemon=collect1.example.com

VDEF

VDEF:nombre_v=expresión RPN

Este comando devuelve un valor y/o un tiempo de acuerdo con las declaraciones RPN utilizadas. El nombre_v resultante, dependiendo de las funciones utilizadas, tendrá un valor y un componente de tiempo. Cuando utiliza este nombre_v en otra expresión RPN, está insertando efectivamente su valor como si hubiera puesto un número en ese lugar. La variable también puede usarse en los diversos elementos de gráfico e impresión.

Ejemplo: "VDEF:avg=mydata,AVERAGE"

Tenga en cuenta que actualmente solo las funciones de agregación funcionan en expresiones RPN VDEF. Los parches para cambiar esto son bienvenidos.

CDEF

CDEF:nombre_v=expresión RPN

Este comando crea un nuevo conjunto de puntos de datos (solo en memoria, no en el archivo RRD) a partir de una o más series de datos diferentes. Las instrucciones RPN se utilizan para evaluar una función matemática en cada punto de datos. El nombre_v resultante puede usarse posteriormente en el script, como si hubiera sido generado por una instrucción DEF.

Ejemplo: "CDEF:mydatabits=mydata,8,*"

Acerca de CDEF versus VDEF

En algún punto del procesamiento, RRDtool ha recopilado una matriz de tasas listas para mostrar.

CDEF trabaja sobre una matriz así. Por ejemplo, CDEF:new=ds0,8,* multiplicaría cada uno de los miembros de la matriz por ocho (probablemente transformando bytes en bits). El resultado es una matriz que contiene los nuevos valores.

VDEF también trabaja sobre una matriz así pero de una manera diferente. Por ejemplo, VDEF:max=ds0,MAXIMUM escanearía cada uno de los miembros de la matriz y almacenaría el valor máximo.

¿Cuándo usas VDEF versus CDEF?

Usa CDEF para transformar tus datos antes de graficarlos. En el ejemplo anterior, usaríamos un CDEF para transformar bytes a bits antes de graficar los bits.

Usas un VDEF si quieres que max(1,5,3,2,4) devuelva cinco, que se mostraría en la leyenda del gráfico (para responder, ¿cuál fue el valor máximo durante el período del gráfico?).

Si quieres aplicar operaciones 'complejas' al resultado de un VDEF, tienes que usar de nuevo un CDEF, ya que los VDEFs solo parecen expresiones RPN, pero en realidad no lo son.

VER TAMBIÉN

rrdgraph proporciona una visión general de cómo funciona rrdtool graph. rrdgraph_data describe DEF, CDEF y VDEF en detalle. rrdgraph_rpn describe el lenguaje RPN utilizado en las declaraciones de ?DEF. La página rrdgraph_graph describe todas las funciones de gráfico e impresión.

Asegúrate de leer rrdgraph_examples para obtener consejos y trucos.

DESCRIPTION

La orden rrdtool graph se utiliza para generar gráficos a partir de datos almacenados en archivos RRD. Permite una gran flexibilidad en la personalización de los gráficos, desde la definición de los datos a mostrar hasta la apariencia visual.

DATOS

Los datos para los gráficos se definen mediante la palabra clave DEF o VDEF, seguida del nombre del archivo RRD, el nombre del Data Source (DS) y un nombre para la serie de datos. También se pueden aplicar operaciones de consolidación y transformación a los datos.

DEF

DEF:nombre=archivo.rrd:fuente[:XFF][:{AVERAGE|LAST|MAX|MIN}]

Define una fuente de datos.

  • nombre: Nombre que se usará para referirse a esta fuente de datos en el gráfico.
  • archivo.rrd: El archivo RRD que contiene los datos.
  • fuente: El nombre del Data Source (DS) dentro del archivo RRD.
  • XFF: (Opcional) Factor de corrección para valores ausentes (NULL). Por defecto es 0.5.
  • {AVERAGE|LAST|MAX|MIN}: (Opcional) Especifica cómo consolidar los datos. Por defecto es AVERAGE.

VDEF

VDEF:nombre=archivo.rrd:fuente:CF[:argumento]

Define un valor derivado.

  • nombre: Nombre que se usará para referirse a este valor derivado.
  • archivo.rrd: El archivo RRD que contiene los datos.
  • fuente: El nombre del Data Source (DS) dentro del archivo RRD.
  • CF: El tipo de cálculo a realizar (AVERAGE, LAST, MAX, MIN, TOTAL, STEP, PERCENT, VPERCENT, SORT, FLOOR, CEIL, AVERAGE_SEC, LAST_SEC, MAX_SEC, MIN_SEC).
  • argumento: (Opcional) Un argumento para el cálculo, dependiendo de la CF. Por ejemplo, para PERCENT, se especifica el porcentaje (ej. 95).

CDEF

CDEF:nombre=expresión

Define una nueva fuente de datos calculada mediante una expresión. La expresión puede incluir operaciones aritméticas, funciones y referencias a otras fuentes de datos (DEF o VDEF).

Ejemplo: CDEF:promedio_cpu=cpu_user,cpu_system,+,2, / (suma de cpu_user y cpu_system, dividido por 2)

About CDEF versus VDEF

DEF se utiliza para seleccionar datos brutos de un archivo RRD. VDEF se utiliza para calcular un único valor derivado de un conjunto de datos (como el promedio, máximo, mínimo, etc. durante el período de tiempo seleccionado). CDEF se utiliza para definir una nueva serie de datos calculada a partir de una o más fuentes de datos existentes (DEF o VDEF) utilizando una expresión matemática.
