NOMBRE

rrdupdate - Almacena un nuevo conjunto de valores en el RRD

SINOPSIS

rrdtool {update | updatev} archivo [--template|-t nombre-ds[:nombre-ds]...] [--skip-past-updates|-s] [--daemon|-d direccion] [--] N:valor[:valor]... timestamp:valor[:valor]... timestamp-atrasado@valor[:valor]...

DESCRIPCIÓN

La función update introduce nuevos valores de datos en un RRD. Los datos se alinean temporalmente (se interpolan) según las propiedades del RRD al que se escriben los datos.

updatev
Esta versión alternativa de update toma los mismos argumentos y realiza la misma función. La v significa verbose (detallado), que describe la salida devuelta. updatev devuelve una lista de todos los puntos de datos consolidados (CDP) escritos en disco como resultado de la invocación de update. Los valores están indexados por marca de tiempo (timestamp) (time_t), RRA (función de consolidación y PDP por CDP) y fuente de datos (nombre). Tenga en cuenta que, dependiendo de los argumentos de la llamada actual y anterior a update, la lista puede no tener entradas o tener un gran número de entradas.

Dado que updatev requiere acceso directo al disco, la opción --daemon no se puede usar con este comando.

archivo
El nombre del RRD que desea actualizar.
--locking|-L try|block|none
Bloquea el archivo RRD en el modo especificado: try falla si el archivo está bloqueado por otro proceso, block espera hasta que se libere el bloqueo y none omite el bloqueo por completo. El valor predeterminado se lee de la variable de entorno $RRD_LOCKING y recurre a try si dicha variable no existe.
--template|-t nombre-ds[:nombre-ds]...
Por defecto, la función update espera sus datos de entrada en el orden en que se definen las fuentes de datos en el RRD, excluyendo cualquier fuente de datos COMPUTE (es decir, si la tercera fuente de datos DST es COMPUTE, el tercer valor de entrada se mapeará a la cuarta fuente de datos en el RRD y así sucesivamente). Esto no es muy resistente a errores, ya que podría estar enviando datos incorrectos a un RRD.

El modificador template permite especificar qué fuentes de datos va a actualizar y en qué orden. Si las fuentes de datos especificadas en la plantilla no están disponibles en el archivo RRD, el proceso de actualización abortará con un mensaje de error.

Si bien parece posible con el modificador template actualizar fuentes de datos de forma asíncrona, RRDtool asigna implícitamente el valor *UNKNOWN* a las fuentes de datos no COMPUTE que faltan en la plantilla.

No especifique un valor para un DST COMPUTE en la función update. Si esto se hace accidentalmente (y esto solo se puede hacer usando el modificador template), RRDtool ignorará el valor especificado para el DST COMPUTE.

El demonio de caché rrdcached no se puede usar junto con plantillas todavía.

--skip-past-updates|-s
Al actualizar un archivo rrd con datos anteriores a la última actualización ya aplicada, rrdtool emitirá un mensaje de error y abortará. Esta opción indica a rrdtool que omita silenciosamente dichos datos. Puede ser útil al reproducir datos antiguos en un archivo rrd y no está seguro de cuántas actualizaciones ya se han aplicado.
--daemon|-d direccion
Si se proporciona, RRDtool intentará conectarse al demonio de caché rrdcached en direccion. Si la conexión se establece correctamente, los valores se enviarán al demonio en lugar de acceder a los archivos directamente. Si la conexión no se puede establecer, recurrirá al acceso directo a archivos. Si bien esto es conveniente, puede crear problemas silenciosamente, así que lea la advertencia en los ejemplos.

Para obtener una lista de formatos aceptados, consulte la opción -l en el manual de rrdcached.

{N | timestamp}:valor[:valor]...
Los datos utilizados para actualizar el RRD se adquirieron en un momento determinado. Este tiempo se puede definir en segundos desde 1970-01-01 o usando la letra 'N', en cuyo caso la hora de actualización se establecerá como la hora actual. Los valores de tiempo negativos se restan de la hora actual. También se puede usar una ESPECIFICACIÓN DE TIEMPO ESTILO AT (consulte la documentación de rrdfetch) delimitando el final de la especificación de tiempo con el carácter '@' en lugar de ':'. Obtener el momento exacto es especialmente importante cuando se trabaja con fuentes de datos de tipo COUNTER, DERIVE, DCOUNTER, DDERIVE o ABSOLUTE.

Al usar valores de tiempo negativos, las opciones y los datos deben separarse con dos guiones (--), de lo contrario, el valor de tiempo se interpretará como una opción. Vea abajo un ejemplo.

Los elementos restantes del argumento son actualizaciones de DS. El orden de esta lista es el mismo que el orden en que se definieron las fuentes de datos en el RRA. Si no hay datos para una determinada fuente de datos, se puede especificar la letra U (por ejemplo, N:0.1:U:1).

El formato del valor adquirido de la fuente de datos depende del tipo de fuente de datos elegido. Normalmente será numérico, pero los módulos de adquisición de datos pueden imponer su propia interpretación de este parámetro siempre que el dos puntos (:) siga siendo el separador de valores de la fuente de datos.

VARIABLES DE ENTORNO

Las siguientes variables de entorno se pueden usar para cambiar el comportamiento de "rrdtool update":

RRDCACHED_ADDRESS
Si esta variable de entorno está configurada, tendrá el mismo efecto que especificar la opción "--daemon" en la línea de comandos. Si ambos están presentes, el argumento de la línea de comandos tiene prioridad.
RRDCACHED_STRIPPATH
Si esta variable de entorno está configurada, eliminará la cadena inicial del nombre del archivo antes de enviarlo a rrdcached. Esto está pensado principalmente para permitir que rrdcached funcione con herramientas xymon y cacti sin tener que modificar dichas herramientas.
RRD_LOCKING
Si esta variable de entorno está configurada, el archivo RRD se bloqueará en el modo especificado: try falla si el archivo está bloqueado por otro proceso, block espera hasta que se libere el bloqueo y none omite el bloqueo por completo.

Esta variable puede ser anulada por la opción de línea de comandos --locking.

EJEMPLOS

  • "rrdtool update demo1.rrd N:3.44:3.15:U:23"

    Actualiza el archivo de base de datos demo1.rrd con 3 valores conocidos y uno *UNKNOWN*. Utiliza la hora actual como hora de actualización.

  • "rrdtool update demo2.rrd 887457267:U 887457521:22 887457903:2.7"

    Actualiza el archivo de base de datos demo2.rrd, que espera datos de una sola fuente de datos, tres veces. Primero con un valor *UNKNOWN* y luego con dos lecturas regulares. El intervalo de actualización parece ser de alrededor de 300 segundos.

  • "rrdtool update demo3.rrd -- -5:21 N:42"

    Actualiza el archivo de base de datos demo3.rrd dos veces, utilizando cinco segundos en el pasado y la hora actual como horas de actualización.

  • "rrdtool update --daemon unix:/tmp/rrdd.sock demo4.rrd N:23"

    Utiliza el socket de dominio UNIX "/tmp/rrdd.sock" para contactar al demonio de caché. Si el demonio de caché no está disponible, actualiza el archivo "demo4.rrd" directamente. ADVERTENCIA: Dado que se especifica una ruta relativa, el siguiente efecto perturbador puede

EXAMPLES

The rrdupdate utility can be used to update several RRD files at once.

 rrdupdate data/cpu.rrd data/load.rrd data/memory.rrd \
           -s time -t "CPU usage" -t "Load average" -t "Memory usage"

This will update data/cpu.rrd with the value for "CPU usage", data/load.rrd with the value for "Load average", and data/memory.rrd with the value for "Memory usage".

The update command can take arguments for the corresponding data source. It is possible to specify arguments for each data source and update it individually.

 rrdupdate myhost.rrd \
           -s time -t "CPU usage" U \
           -s time -t "Load average" 1.5 \
           -s time -t "Memory usage" U

This will update myhost.rrd three times. Once for the data source "CPU usage", once for "Load average" with the value 1.5 and once for "Memory usage".

Here is an example using a configuration file:

 rrdupdate myhost.rrd -d /etc/rrdupdate.conf

In this example, the configuration file /etc/rrdupdate.conf would contain lines like:

 update myhost.rrd \
          -s time -t "CPU usage" U \
          -s time -t "Load average" 1.5 \
          -s time -t "Memory usage" U

The following example uses a socket file to communicate with the rrdcached daemon.

 rrdupdate -j /var/run/rrdcached.sock myhost.rrd

It is also possible to specify the socket file on a per-update basis.

 rrdupdate -j /var/run/rrdcached.sock \
           -s time -t "CPU usage" U \
           -j /var/tmp/another.sock -s time -t "Disk usage" 75

The -j option overrides the default socket specified with -j.

Note that all file paths are relative to the working directory of the process invoking rrdupdate unless rrdcached is used.

If rrdcached is used, the file paths are relative to the working directory of the rrdcached daemon. For example, if the daemon is started with the option: 

 rrdcached -f /var/run/rrdcached.sock -b /var/rrd

and you run:

 rrdupdate -j /var/run/rrdcached.sock myhost.rrd

then rrdupdate will ask rrdcached to update the file /var/rrd/myhost.rrd.

If rrdcached is not available or the connection to the daemon fails, rrdupdate will try to update the file directly. If the file path is relative, it will be interpreted relative to the working directory of the invoking process.

Example of relative paths:

Assume the working directory is /home/user/rrd. The file is data/cpu.rrd.

  • If rrdcached is available, the file relative to the working directory of the daemon is used. If the daemon is not available, the file relative to the current working directory of the invoking process is used. This may update two different files depending on whether the daemon could be reached or not. Don't do relative paths, kids!
