NOMBRE

rrdtune - Modificar algunas propiedades básicas de una Base de Datos Redonda (Round Robin Database)

SINOPSIS

rrdtool tune nombre-archivo [--heartbeat|-h nombre-ds:heartbeat] [--minimum|-i nombre-ds:min] [--maximum|-a nombre-ds:max] [--data-source-type|-d nombre-ds:DST] [--data-source-rename|-r nombre-antiguo:nombre-nuevo] [--deltapos|-p valor-escala] [--deltaneg|-n valor-escala] [--failure-threshold|-f umbral-fallo] [--window-length|-w longitud-ventana] [--alpha|-x parametro-adaptacion] [--beta|-y parametro-adaptacion] [--gamma|-z parametro-adaptacion] [--gamma-deviation|-v parametro-adaptacion] [--smoothing-window|-s fraccion-temporada] [--smoothing-window-deviation|-S fraccion-temporada] [--aberrant-reset|-b nombre-ds] [--step|-t nuevopaso] [--daemon|-D direccion] [DEL:nombre-ds] [DS:espec-ds] [DELRRA:indice] [RRA:espec-rra] [RRA#indice:[+-=]<numero>

DESCRIPCIÓN

La opción tune permite alterar algunos de los valores básicos de configuración almacenados en el área de encabezado de una Base de Datos Redonda (RRD).

Una aplicación de la función tune es relajar las reglas de validación en una RRD. Esto permite rellenar una nueva RRD con datos disponibles en intervalos más grandes de lo que normalmente se permitiría. Tenga mucho cuidado con las operaciones de tune para fuentes de datos COMPUTE. Establecer el min, max y heartbeat para una fuente de datos COMPUTE sin cambiar el tipo de fuente de datos a un DST no COMPUTE CORROMPERÁ el encabezado de la fuente de datos en la RRD.

Una segunda aplicación de la función tune es establecer o alterar parámetros utilizados por las funciones especializadas de las RRA para la detección de comportamiento aberrante.

Aún otra aplicación es añadir o eliminar fuentes de datos (DS) o añadir/eliminar o alterar algunos aspectos de los archivos redondos (RRA). Estas operaciones no se realizan realmente in situ, sino que generan un nuevo archivo RRD internamente y lo mueven sobre el archivo original. Los datos se mantienen intactos durante estas operaciones. Para modificaciones aún más profundas, puede revisar las opciones --source y --template de la función create, que le permiten combinar múltiples archivos RRD en uno nuevo y que es aún más inteligente en cuanto a los datos que puede mantener o "regenerar".

nombre-archivo
El nombre de la RRD que desea ajustar.
--heartbeat|-h nombre-ds:heartbeat
Modificar el heartbeat de una fuente de datos. Al establecerlo en un valor alto, la RRD aceptará cosas como un valor por día.
--minimum|-i nombre-ds:min
Alterar el valor mínimo aceptable como entrada de la fuente de datos. Establecer min en 'U' deshabilitará este límite.
--maximum|-a nombre-ds:max
Alterar el valor máximo aceptable como entrada de la fuente de datos. Establecer max en 'U' deshabilitará este límite.
--data-source-type|-d nombre-ds:DST
Alterar el tipo DST de una fuente de datos.
--data-source-rename|-r nombre-antiguo:nombre-nuevo
Renombrar una fuente de datos.
--deltapos|-p valor-escala
Alterar el factor de escala de desviación para el límite superior de la banda de confianza utilizada internamente para calcular violaciones para la RRA FAILURES. El valor predeterminado es 2. Tenga en cuenta que este parámetro no está relacionado con los límites de confianza de los gráficos, que deben especificarse como un argumento CDEF para generar un gráfico con límites de confianza. El factor de escala del gráfico no necesita coincidir con el valor utilizado internamente por la RRA FAILURES.
--deltaneg|-n valor-escala
Alterar el factor de escala de desviación para el límite inferior de la banda de confianza utilizada internamente para calcular violaciones para la RRA FAILURES. El valor predeterminado es 2. Al igual que con --deltapos, este argumento no está relacionado con el factor de escala elegido al graficar los límites de confianza.
--failure-threshold|-f umbral-fallo
Alterar el número de violaciones del límite de confianza que constituyen un fallo a efectos de la RRA FAILURES. Debe ser un entero menor o igual a la longitud de la ventana de la RRA FAILURES. Esta restricción no es verificada por la opción tune, por lo que se puede restablecer simultáneamente el umbral de fallos y la longitud de la ventana. El establecimiento de esta opción restablecerá el recuento de violaciones a 0.
--window-length|-w longitud-ventana
Alterar el número de puntos de tiempo en la ventana temporal para determinar fallos. Debe ser un entero mayor o igual a la longitud de la ventana de la RRA FAILURES y menor o igual a 28. El establecimiento de esta opción restablecerá el recuento de violaciones a 0.
--alpha|-x parametro-adaptacion
Alterar el parámetro de adaptación de la intersección para el algoritmo de predicción de Holt-Winters. Este parámetro debe estar entre 0 y 1.
--beta|-y parametro-adaptacion
Alterar el parámetro de adaptación de la pendiente para el algoritmo de predicción de Holt-Winters. Este parámetro debe estar entre 0 y 1.
--gamma|-z parametro-adaptacion
Alterar el parámetro de adaptación del coeficiente estacional para la RRA SEASONAL. Este parámetro debe estar entre 0 y 1.
--gamma-deviation|-v parametro-adaptacion
Alterar el parámetro de adaptación de la desviación estacional para la RRA DEVSEASONAL. Este parámetro debe estar entre 0 y 1.
--smoothing-window|-s fraccion-temporada
Alterar el tamaño de la ventana de suavizado para la RRA SEASONAL. Debe estar entre 0 y 1.
--smoothing-window-deviation|-S fraccion-temporada
Alterar el tamaño de la ventana de suavizado para la RRA DEVSEASONAL. Debe estar entre 0 y 1.
--aberrant-reset|-b nombre-ds
Esta opción provoca que el algoritmo de detección de comportamiento aberrante se reinicie para la fuente de datos especificada; es decir, olvida todo lo que ha aprendido hasta ahora. Específicamente, para la RRA HWPREDICT o MHWPREDICT, establece los coeficientes de intersección y pendiente como desconocidos. Para la RRA SEASONAL, establece todos los coeficientes estacionales como desconocidos. Para la RRA DEVSEASONAL, establece todos los coeficientes de desviación estacional como desconocidos. Para la RRA FAILURES, borra el historial de violaciones. Tenga en cuenta que el reinicio no borra predicciones pasadas (los valores de la RRA HWPREDICT o MHWPREDICT), desviaciones predichas (los valores de la RRA DEVPREDICT), o historial de fallos (los valores de la RRA FAILURES). Esta opción funcionará incluso si no todas las RRAs listadas están presentes.

Debido a la implementación de esta opción, hay un impacto indirecto en otras fuentes de datos en la RRD. Un algoritmo de suavizado se aplica a los valores SEASONAL y DEVSEASONAL de forma periódica. Durante la inicialización de arranque, este suavizado se pospone. Para mayor eficiencia, la implementación del suavizado no es específica de la fuente de datos. Esto significa que el uso de reset para una fuente de datos retrasará la ejecución del algoritmo de suavizado para todas las fuentes de datos en el archivo. Es poco probable que esto tenga consecuencias graves, a menos que los datos que se recopilan para las fuentes de datos no reiniciadas sean inusualmente volátiles du

el período de reinicialización de la fuente de datos de reinicio.

Se aconseja el uso de esta opción de ajuste cuando el comportamiento de la serie temporal de la fuente de datos cambia de manera drástica y permanente.

--step|-t newstep
Cambia el tamaño del paso de la RRD a newstep.

--daemon|-D address
NOTA: Dado que la opción -d (letra 'd' minúscula) ya estaba ocupada, esta función (a diferencia de la mayoría de las otras) utiliza la letra 'D' mayúscula para la opción de una sola letra para nombrar al demonio de caché.

Si se proporciona, RRDtool intentará conectarse al demonio de caché rrdcached en address y fallará si no se puede establecer la conexión. Si la conexión se establece con éxito, los datos del filename se vaciarán antes de realizar la operación de copia/modificación. Posteriormente, el demonio de caché olvidará el filename, de modo que el próximo acceso a través del demonio de caché leerá la estructura correcta.

Esta secuencia de operaciones está diseñada para lograr un resultado general consistente con respecto a la consistencia interna de los archivos RRD cuando se utiliza una de las operaciones de cambio de DS o RRA (es decir, el archivo resultante siempre debe ser un archivo RRD válido, independientemente de las actualizaciones concurrentes a través del demonio de caché). Con respecto a la consistencia de los datos, no se realizan tales garantías: sin sincronización externa, las actualizaciones concurrentes pueden perderse.

Para obtener una lista de formatos aceptados, consulte la opción -l en el manual de rrdcached.

DEL:ds-name
Cada fuente de datos nombrada con una especificación DEL será eliminada. El RRD resultante carecerá tanto de la definición como de los datos de esa fuente de datos. Se permiten múltiples especificaciones DEL.
DS:ds-spec
Por cada definición de fuente de datos de este tipo (para la sintaxis exacta, consulte el comando create), se agregará una nueva fuente de datos al RRD. Se permiten múltiples especificaciones DS.
DELRRA:index
Elimina el RRA con el índice index. El índice está basado en cero, es decir, el primer RRA tiene el índice 0.
RRA:rra-spec
Por cada definición de archivo de este tipo (para la sintaxis exacta, consulte el comando create), se agregará un nuevo RRA al RRD de salida. Se permiten múltiples especificaciones RRA.
RRA#index:[+-=]<número>
Añade/elimina o establece el número dado de filas para el RRA con el índice <index>. El índice está basado en cero, es decir, el primer RRA tiene el índice 0.

EJEMPLO 1

"rrdtool tune data.rrd -h in:100000 -h out:100000 -h through:100000"

Establece el heartbeat mínimo requerido para las fuentes de datos 'in', 'out' y 'through' a 100.000 segundos, lo que equivale a poco más de un día de datos en data.rrd. Esto permitiría alimentar datos antiguos de MRTG-2.0 directamente a RRDtool sin generar entradas *UNKNOWN*.

EJEMPLO 2

"rrdtool tune monitor.rrd --window-length 5 --failure-threshold 3"

Si el RRA FAILURES se crea implícitamente, la longitud de ventana por defecto es 9 y el umbral de fallo por defecto es 7. Este comando define ahora un fallo como 3 o más violaciones en una ventana temporal de 5 puntos de datos.

EJEMPLO 3

"rrdtool tune some.rrd DEL:a RRA#0:+10"

Elimina la fuente de datos llamada a y extiende el primer archivo en 10 filas. Esto, de hecho, reemplazará el RRD de entrada con un nuevo RRD manteniendo todos los datos existentes. Para la mayoría de los casos de uso prácticos, esto es idéntico a una modificación real in situ.
