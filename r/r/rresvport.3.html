rcmd(3) Manual de Funciones de Biblioteca rcmd(3)

NOMBRE

rcmd, rresvport, iruserok, ruserok, rcmd_af, rresvport_af, iruserok_af, ruserok_af - rutinas para devolver un stream a un comando remoto

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <netdb.h>    /* O <unistd.h> en algunos sistemas */
int rcmd(char **restrict ahost, unsigned short inport,
            const char *restrict locuser,
            const char *restrict remuser,
            const char *restrict cmd, int *restrict fd2p);
int rresvport(int *port);
int iruserok(uint32_t raddr, int superuser,
            const char *ruser, const char *luser);
int ruserok(const char *rhost, int superuser,
            const char *ruser, const char *luser);
int rcmd_af(char **restrict ahost, unsigned short inport,
            const char *restrict locuser,
            const char *restrict remuser,
            const char *restrict cmd, int *restrict fd2p,
            sa_family_t af);
int rresvport_af(int *port, sa_family_t af);
int iruserok_af(const void *restrict raddr, int superuser,
            const char *restrict ruser, const char *restrict luser,
            sa_family_t af);
int ruserok_af(const char *rhost, int superuser,
            const char *ruser, const char *luser,
            sa_family_t af);

DESCRIPCIÓN

La función rcmd() es utilizada por el superusuario para ejecutar un comando en una máquina remota usando un esquema de autenticación basado en números de puerto privilegiados. La función rresvport() devuelve un descriptor de archivo a un socket con una dirección en el espacio de puertos privilegiados. Las funciones iruserok() y ruserok() son utilizadas por los servidores para autenticar clientes que solicitan servicio con rcmd(). Las cuatro funciones son utilizadas por el servidor rshd(8) (entre otros).

rcmd()

La función rcmd() busca el host *ahost usando gethostbyname(3), devolviendo -1 si el host no existe. De lo contrario, *ahost se establece en el nombre estándar del host y se establece una conexión a un servidor que reside en el puerto de Internet bien conocido inport.

Si la conexión tiene éxito, se devuelve un socket en el dominio de Internet de tipo SOCK_STREAM al llamante, y se proporciona al comando remoto como stdin y stdout. Si fd2p no es cero, entonces se establecerá un canal auxiliar a un proceso de control, y se colocará un descriptor de archivo para él en *fd2p. El proceso de control devolverá salida diagnóstica del comando (unidad 2) en este canal, y también aceptará bytes en este canal como números de señal UNIX, para ser reenviados al grupo de procesos del comando. Si fd2p es 0, entonces el stderr (unidad 2 del comando remoto) se hará igual que el stdout y no se harán provisiones para enviar señales arbitrarias al proceso remoto, aunque es posible que puedas llamar su atención usando datos fuera de banda.

El protocolo se describe en detalle en rshd(8).

rresvport()

La función rresvport() se utiliza para obtener un socket con un puerto privilegiado enlazado a él. Este socket es adecuado para su uso por rcmd() y varias otras funciones. Los puertos privilegiados son aquellos en el rango de 0 a 1023. Solo un proceso privilegiado (en Linux, un proceso que tiene la capacidad CAP_NET_BIND_SERVICE en el espacio de nombres de usuario que gobierna su espacio de nombres de red) tiene permitido enlazarse a un puerto privilegiado. En la implementación de glibc, esta función restringe su búsqueda a los puertos del 512 al 1023. El argumento port es de valor-resultado: el valor que proporciona a la llamada se utiliza como punto de partida para una búsqueda circular del rango de puertos; al regresar (con éxito), contendrá el número de puerto que se enlazó.

iruserok() y ruserok()

Las funciones iruserok() y ruserok() toman la dirección IP o el nombre del host remoto, respectivamente, dos nombres de usuario y una bandera que indica si el nombre de usuario local es el del superusuario. Luego, si el usuario *no* es el superusuario, verifica el archivo /etc/hosts.equiv. Si esa búsqueda no se realiza, o no tiene éxito, se verifica el archivo .rhosts en el directorio principal del usuario local para ver si la solicitud de servicio está permitida.

Si este archivo no existe, no es un archivo regular, es propiedad de cualquier persona que no sea el usuario o el superusuario, es escribible por cualquier persona que no sea el propietario, o está enlazado de forma rígida en cualquier lugar, la verificación falla automáticamente. Se devuelve cero si el nombre de la máquina está listado en el archivo hosts.equiv, o si el host y el nombre de usuario remoto se encuentran en el archivo .rhosts; de lo contrario, iruserok() y ruserok() devuelven -1. Si el dominio local (obtenido de gethostname(2)) es el mismo que el dominio remoto, solo es necesario especificar el nombre de la máquina.

Si se conoce la dirección IP del host remoto, se debe usar iruserok() en lugar de ruserok(), ya que no requiere confiar en el servidor DNS para el dominio del host remoto.

Variantes *_af()

Todas las funciones descritas anteriormente funcionan con sockets IPv4 (AF_INET). Las variantes con sufijo "_af" toman un argumento adicional que permite especificar la familia de direcciones del socket. Para estas funciones, el argumento af puede especificarse como AF_INET o AF_INET6. Además, rcmd_af() admite el uso de AF_UNSPEC.

VALOR DE RETORNO

La función rcmd() devuelve un descriptor de socket válido en caso de éxito. Devuelve -1 en caso de error e imprime un mensaje diagnóstico en el error estándar.

La función rresvport() devuelve un descriptor de socket válido y enlazado en caso de éxito. En caso de fallo, devuelve -1 y establece errno para indicar el error. El código de error EAGAIN se sobrecarga para significar: "Todos los puertos de red en uso".

Para obtener información sobre el retorno de ruserok() e iruserok(), consulte lo anterior.

ATRIBUTOS

Para una explicación de los términos utilizados en esta sección, consulte attributes(7).

ESTÁNDARES

BSD.

HISTORIA

rresvport.3.en

NAME

rresvport, rresvport_af — find a privileged port

LIBRARY

Basic Networking Library (libbsd, -lbsd)

SYNOPSIS

#include <sys/types.h>
#include <sys/socket.h>

int
rresvport(int *amaster);

int
rresvport_af(int *amaster, int af);

DESCRIPTION

The rresvport() and rresvport_af() functions return an open, connected, non-blocking socket of an Internet domain, suitable for use as a client's source port in a connection to a server expecting connections from privileged ports.

The socket is connected to the address host 0 where host is the address of the local machine. The socket is bound to a privileged port. The highest possible privileged port is used first, and the function searches downwards until it finds a port that is not in use.

The rresvport_af() function is the same as rresvport() except that it allows the caller to specify the address family, af. Valid values for af are AF_INET and AF_INET6.

If amaster is not NULL, it is set to the file descriptor of the socket. Otherwise, the return value is the file descriptor.

RETURN VALUE

On success, rresvport() and rresvport_af() return the socket file descriptor. On error, they return -1 and set $errno to indicate the error.

ATTRIBUTES

For explanations on the terms used in this section, see attributes(7).

Multi-threading safe
No.

STANDARDS

rresvport() and rresvport_af() are extensions to the POSIX standard, originating from BSD.

HISTORY

rresvport(3) first appeared in 4.3BSD. The _af version was added later.

The rresvport_af function was added in glibc 2.2. The rresvport function is available since glibc 2.1.

ruserok(3) and ruserok_af(3) are related functions for authentication.

ruserok()
glibc 2.1.
ruserok_af()
glibc 2.2.

Solaris, 4.2BSD. The "_af" variants are more recent additions, and are not present on as wide a range of systems.

BUGS

iruserok() and iruserok_af() are declared in glibc headers only since glibc 2.12.

SEE ALSO

rlogin(1), rsh(1), rexec(3), rexecd(8), rlogind(8), rshd(8)

NOMBRE

rresvport, rresvport_af — encontrar un puerto privilegiado

BIBLIOTECA

Biblioteca de Red Básica (libbsd, -lbsd)

SINOPSIS

#include <sys/types.h>
#include <sys/socket.h>

int
rresvport(int *amaster);

int
rresvport_af(int *amaster, int af);

DESCRIPCIÓN

Las funciones rresvport() y rresvport_af() devuelven un socket abierto, conectado y no bloqueante de un dominio de Internet, adecuado para ser utilizado como puerto de origen de un cliente en una conexión a un servidor que espera conexiones desde puertos privilegiados.

El socket se conecta a la dirección host 0 donde host es la dirección de la máquina local. El socket se enlaza a un puerto privilegiado. Se utiliza primero el puerto privilegiado más alto posible, y la función busca hacia abajo hasta que encuentra un puerto que no esté en uso.

La función rresvport_af() es la misma que rresvport() excepto que permite al llamador especificar la familia de direcciones, af. Los valores válidos para af son AF_INET y AF_INET6.

Si amaster no es NULL, se establece al descriptor de archivo del socket. De lo contrario, el valor de retorno es el descriptor de archivo.

VALOR DE RETORNO

En caso de éxito, rresvport() y rresvport_af() devuelven el descriptor de archivo del socket. En caso de error, devuelven -1 y establecen $errno para indicar el error.

ATRIBUTOS

Para obtener explicaciones sobre los términos utilizados en esta sección, consulte attributes(7).

Seguro para múltiples hilos
No.

ESTÁNDARES

rresvport() y rresvport_af() son extensiones del estándar POSIX, originarias de BSD.

HISTORIA

rresvport(3) apareció por primera vez en 4.3BSD. La versión _af se añadió más tarde.

La función rresvport_af se añadió en glibc 2.2. La función rresvport está disponible desde glibc 2.1.
