NOMBRE

rrdcgi - Crear páginas web que contienen gráficos RRD basados en plantillas

SINOPSIS

"#!/ruta/a/"rrdcgi [--filter|-f]

DESCRIPCIÓN

rrdcgi es una especie de intérprete de scripts muy limitado. Su propósito es ejecutarse como un programa cgi y analizar una plantilla de página web que contiene etiquetas especiales <RRD::. rrdcgi interpretará y actuará de acuerdo con estas etiquetas. Al final, imprimirá una página web incluyendo las cabeceras CGI necesarias.

rrdcgi analiza el contenido de la plantilla en 3 pasos. En cada paso, solo busca un subconjunto de etiquetas. Esto permite anidar etiquetas.

El analizador de argumentos utiliza la misma semántica que estás acostumbrado de tu C-shell.

--filter|-f
Asume que rrdcgi se ejecuta como un filtro y no como un cgi.

Palabras Clave

RRD::CV nombre
Inserta la variable CGI del nombre dado.
RRD::CV::QUOTE nombre
Inserta la variable CGI del nombre dado pero la entrecomilla, lista para ser utilizada como argumento en otra etiqueta RRD::. Así, incluso cuando hay espacios en el valor de la variable CGI, seguirá siendo considerada un solo argumento.
RRD::CV::PATH nombre
Inserta la variable CGI del nombre dado, la entrecomilla y se asegura de que no comience con '/' ni contenga '..'. Esto es para asegurar que no se introduzcan nombres de ruta problemáticos a través de la interfaz CGI.
RRD::GETENV variable
Obtiene el valor de una variable de entorno. 
<RRD::GETENV REMOTE_USER>

podría darte el nombre del usuario remoto dado que estás utilizando algún tipo de control de acceso en el directorio.

RRD::GOODFOR segundos
Especifica el número de segundos que esta página debe permanecer válida. Esto instruirá a rrdcgi para que imprima una cabecera Last-Modified, una Expire y, si el número de segundos es negativo, una cabecera Refresh.
RRD::INCLUDE nombre_archivo
Incluye el contenido del archivo especificado en la página devuelta desde el cgi.
RRD::SETENV variable valor
Si deseas presentar tus gráficos en una zona horaria diferente a la tuya, podrías usar 
<RRD::SETENV TZ UTC>

para asegurar que todo se presente en Hora Universal. Ten en cuenta que los valores permitidos para TZ dependen de tu sistema operativo.

RRD::SETVAR variable valor
Análogo a SETENV pero para variables locales.
RRD::GETVAR variable
Análogo a GETENV pero para variables locales.
RRD::TIME::LAST archivo_rrd formato_strftime
Esto se reemplaza por la hora de última modificación del RRD seleccionado. La hora se formatea con strftime utilizando la cadena especificada en el segundo argumento.
RRD::TIME::NOW formato_strftime
Esto se reemplaza por la hora actual del día. La hora se formatea con strftime utilizando la cadena especificada en el argumento.

Ten en cuenta que si devuelves : (dos puntos) de tu formato strftime, es posible que tengas que escaparlos usando \ si la hora se va a utilizar como argumento para un comando GRAPH.

RRD::TIME::STRFTIME INICIO|FIN espec_inicio espec_fin formato_strftime
Esto se reemplaza por una hora formateada con strftime usando el formato formato_strftime en espec_inicio o espec_fin, dependiendo de si se especifica INICIO o FIN. Tanto espec_inicio como espec_fin deben ser proporcionados, ya que ambos podrían ser relativos el uno al otro. Esto está pensado para permitir títulos bonitos en los gráficos con horas que son más fáciles de entender para personas no expertas en RRDtool que "-2semanas".

Ten en cuenta que, de nuevo, si devuelves : (dos puntos) de tu formato strftime, es posible que tengas que escaparlos usando \ si la hora se va a utilizar como argumento para un comando GRAPH.

RRD::GRAPH argumentos_rrdgraph
Esta etiqueta crea el gráfico RRD definido por su argumento y luego se reemplaza por una etiqueta <IMG ... > apropiada que hace referencia al gráfico. La opción --lazy en RRD graph puede ser utilizada para asegurar que los gráficos solo se regeneren cuando estén desactualizados. Los argumentos de la etiqueta RRD::GRAPH funcionan como se describe en la página del manual de rrdgraph.

Utiliza la opción --lazy en tus etiquetas RRD::GRAPH, para reducir la carga en tu servidor. Esta opción asegura que los gráficos solo se regeneren cuando los antiguos estén desactualizados.

Si no especificas tu propio formato --imginfo, se utilizará el siguiente:

<IMG SRC="%s" WIDTH="%lu" HEIGHT="%lu">

Ten en cuenta que %s representa la parte del nombre de archivo del gráfico generado; todos los directorios dados en el argumento del archivo PNG se eliminarán.

RRD::PRINT número
Si la etiqueta RRD::GRAPH anterior contenía algún argumento PRINT, entonces puedes acceder a su salida con esta etiqueta. El argumento número se refiere al número del argumento PRINT. El primer PRINT tiene el número 0.
RRD::INTERNAL <var>
Esta etiqueta se reemplaza por una variable interna. Actualmente, las siguientes variables son conocidas: VERSION, COMPILETIME. Estas variables representan los valores compilados.

EJEMPLO 1

El siguiente ejemplo crea una página web con un único gráfico RRD.

#!/usr/local/bin/rrdcgi
<HTML>
<HEAD><TITLE>Demostración de RRDCGI</TITLE></HEAD>
<BODY>
<H1>Página de ejemplo de RRDCGI</H1>
<P>
<RRD::GRAPH demo.png --lazy --title="Temperaturas"
         DEF:cel=demo.rrd:exhaust:AVERAGE
         LINE2:cel#00a000:"D. Celsius">
</P>
</BODY>
</HTML>

EJEMPLO 2

Este script es un poco más elaborado, te permite ejecutarlo desde un formulario que establece RRD_NAME. RRD_NAME se utiliza luego para seleccionar qué RRD quieres usar como fuente para tu gráfico.

#!/usr/local/bin/rrdcgi
<HTML>
<HEAD><TITLE>Demostración de RRDCGI</TITLE></HEAD>
<BODY>
<H1>Página de ejemplo de RRDCGI para <RRD::CV RRD_NAME></H1>
<H2>Selección</H2>
<FORM><INPUT NAME=RRD_NAME TYPE=RADIO VALUE=roomA> Habitación A,
      <INPUT NAME=RRD_NAME TYPE=RADIO VALUE=roomB> Habitación B.
      <INPUT TYPE=SUBMIT></FORM>
<H2>Gráfico</H2>
<P>
<RRD::GRAPH <RRD::CV::PATH RRD_NAME>.png --lazy
         --title "Temperaturas para "<RRD::CV::QUOTE RRD_NAME>
         DEF:cel=<RRD::CV::PATH RRD_NAME>.rrd:exhaust:AVERAGE
         LINE2:cel#00a000:"D. Celsius">
</P>
</BODY>
</HTML>

EJEMPLO 3

Este ejemplo muestra cómo manejar el caso donde los RRD, gráficos y binarios cgi están en directorios separados

#!/.../bin/rrdcgi
<HTML>
<HEAD><TITLE>Demostración de RRDCGI</TITLE></HEAD>
<BODY>
<H1>Página de prueba de RRDCGI</H1>
<RRD::GRAPH
 /.../web/pngs/testhvt.png
 --imginfo '<IMG SRC=/.../pngs/%s WIDTH=%lu HEIGHT=%lu >'
 --lazy --start -1d --end now
 DEF:http_src=/.../rrds/test.rrd:http_src:AVERAGE
 AREA:http_src#00ff00:http_src
>
</BODY>
</HTML>

Nota 1: Reemplaza /.../ con los directorios relevantes

Nota 2: El SRC=/.../pngs deben ser rutas desde la perspectiva del servidor web/navegador
