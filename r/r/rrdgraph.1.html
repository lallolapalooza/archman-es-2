NOMBRE

rrdgraph - Funciones de graficación de Round Robin Database tool

SINOPSIS

rrdtool graph|graphv nombre_archivo [opción ...] [definición de datos ...] [cálculo de datos ...] [definición de variable ...] [elemento gráfico ...] [elemento de impresión ...]

DESCRIPCIÓN

La función graph de RRDtool se utiliza para presentar los datos de una RRD a un espectador humano. Su propósito principal es crear una representación gráfica agradable, pero también puede generar un informe numérico.

VISIÓN GENERAL

rrdtool graph necesita datos para trabajar, por lo que debe utilizar una o más sentencias de definición de datos para recopilar estos datos. No está limitado a una base de datos, es perfectamente legal recopilar datos de dos o más bases de datos (una por sentencia, aunque).

Si desea mostrar promedios, máximos, percentiles, etc., es mejor recopilarlos ahora usando la sentencia de definición de variable. Actualmente, esto no marca la diferencia, pero en una versión futura de RRDtool puede que desee recopilar estos valores antes de la consolidación.

Los datos obtenidos de la RRA se consolidan para que haya exactamente un punto de datos por píxel en el gráfico. Si no tiene cuidado, RRDtool expandirá el rango ligeramente si es necesario. Tenga en cuenta que, en ese caso, el primer y/o último píxel bien podrían volverse desconocidos.

A veces, los datos no están exactamente en el formato en el que le gustaría mostrarlos. Por ejemplo, puede estar recopilando bytes por segundo, pero quiere mostrar bits por segundo. Para eso está diseñado el comando de cálculo de datos. Después de consolidar los datos, se hace una copia y esta copia se modifica utilizando un conjunto de comandos RPN bastante potente.

Cuando haya terminado de obtener y procesar los datos, es hora de graficarlos (o imprimirlos). Esto finaliza la secuencia de rrdtool graph.

Use graphv en lugar de graph para obtener información detallada sobre la geometría del gráfico y los datos una vez que se dibuja. Consulte la parte inferior del documento para obtener más información.

OPCIONES

nombre_archivo

El nombre y la ruta del gráfico a generar. Se recomienda que termine en ".png", ".svg" o ".eps", pero RRDtool no lo impone.

nombre_archivo puede ser '"-"' para enviar la imagen a "stdout". En este caso, no se genera ninguna otra salida.

Rango de tiempo

[-s|--start tiempo] [-e|--end tiempo] [-S|--step segundos]

El inicio y el final de la serie temporal que desea mostrar, y de qué RRA provienen los datos. Los valores predeterminados son: hace 1 día hasta ahora, con la mejor resolución posible. Inicio y fin se pueden especificar en varios formatos, consulte "ESPECIFICACIÓN DE TIEMPO ESTILO AT" en rrdfetch y rrdgraph_examples. Por defecto, rrdtool graph calcula el ancho de un píxel en el dominio del tiempo e intenta obtener datos de una RRA con esa resolución. Con la opción step puede alterar este comportamiento. Si desea que rrdtool graph obtenga datos con una resolución de una hora de la RRD, establezca step en 3600. Nota: un paso menor a un píxel será ignorado silenciosamente.

Para --imgformats que no son de imagen, consulte "FORMATO DE SALIDA" en rrdxport para obtener detalles sobre cómo esto afecta la salida.

Etiquetas

[-t|--title cadena]

Una cadena horizontal colocada en la parte superior del gráfico que puede separarse en varias líneas usando <br/> o \n

[-v|--vertical-label cadena]

Una cadena vertical colocada en el lado izquierdo del gráfico.

Tamaño

[-w|--width píxeles] [-h|--height píxeles] [-j|--only-graph] [-D|--full-size-mode]

Por defecto, el ancho y la altura del lienzo (la parte con los datos reales y tal). Esto por defecto es 400 píxeles por 100 píxeles.

Si especifica la opción --full-size-mode, el ancho y la altura especifican las dimensiones finales de la imagen de salida y el lienzo se redimensiona automáticamente para ajustarse.

Si especifica la opción --only-graph y establece la altura < 32 píxeles, obtendrá una imagen de gráfico diminuta (miniatura) para usar como ícono en una vista general, por ejemplo. Se eliminarán todas las etiquetas del gráfico.

Límites

[-u|--upper-limit valor] [-l|--lower-limit valor] [-r|--rigid] [--allow-shrink]

Por defecto, el gráfico se escalará automáticamente para ajustar el eje y al rango de los datos. Puede cambiar este comportamiento estableciendo explícitamente los límites. El eje y mostrado irá al menos desde lower-limit hasta upper-limit. El escalado automático aún permitirá que esos límites se estiren a menos que se establezca la opción rigid. allow-shrink altera el comportamiento de rigid al permitir el escalado automático hacia abajo; el gráfico no excederá los límites especificados por el usuario.

[-A|--alt-autoscale]

A veces, el algoritmo predeterminado para seleccionar la escala del eje y no es satisfactorio. Normalmente, la escala se selecciona de un conjunto predefinido de rangos y esto falla miserablemente cuando necesita graficar algo como "260 + 0.001 * sin(x)". Esta opción calcula el mínimo y máximo del eje y a partir de los valores de datos mínimos y máximos reales. Nuestro ejemplo mostraría ligeramente menos de "260-0.001" a ligeramente más de "260+0.001" (esta característica fue aportada por Sasha Mikheev).

[-J|--alt-autoscale-min]

Donde "--alt-autoscale" modificará tanto los valores máximos como mínimos absolutos, esta opción solo afectará al valor mínimo. El valor máximo, si no se define en la línea de comandos, será 0. Esta opción puede ser útil al graficar tráfico de routers cuando la línea WAN utiliza compresión, y por lo tanto, el rendimiento puede ser superior a la velocidad de la línea WAN.

[-M|--alt-autoscale-max]

Donde "--alt-autoscale" modificará tanto los valores máximos como mínimos absolutos, esta opción solo afectará al valor máximo. El valor mínimo, si no se define en la línea de comandos, será 0. Esta opción puede ser útil al graficar tráfico de routers cuando la línea WAN utiliza compresión, y por lo tanto, el rendimiento puede ser superior a la velocidad de la línea WAN.

[-N|--no-gridfit]

Para evitar efectos de desenfoque de anti-aliasing, RRDtool ajusta los puntos a los píxeles de resolución del dispositivo, lo que da como resultado una apariencia más nítida. Si esto no es de su agrado, puede usar este interruptor para desactivar este comportamiento.

El ajuste de cuadrícula está desactivado para la salida PDF, EPS, SVG por defecto.

Eje X

[-x|--x-grid GTM:GST:MTM:MST:LTM:LST:LPR:LFM]

[-x|--x-grid none]

La etiqueta del eje x es bastante compleja de configurar. Si no tiene necesidades muy especiales, probablemente sea mejor confiar en la configuración automática para que esto salga bien. Puede especificar la cadena "none" para suprimir la cuadrícula y las etiquetas por completo.

La cuadrícula se define especificando una cierta cantidad de tiempo en las posiciones de los ?TM. Puede elegir entre "SECOND", "MINUTE", "HOUR", "DAY", "WEEK", "MONTH" o "YEAR". Luego define cuántos de estos deben pasar entre cada línea o etiqueta. Esto

Eje X

El par (?TM:?ST) debe especificarse para la cuadrícula base (G??), la cuadrícula principal (M??) y las etiquetas (L??). Para las etiquetas, también debe definir una precisión en LPR y una cadena de formato strftime en LFM. LPR define dónde se colocará cada etiqueta. Si es cero, la etiqueta se colocará justo debajo de la línea correspondiente (útil para horas, fechas, etc.). Si especifica un número de segundos aquí, la etiqueta se centrará en este intervalo (útil para lunes, enero, etc.).

--x-grid MINUTE:10:HOUR:1:HOUR:4:0:%X

Esto coloca líneas de cuadrícula cada 10 minutos, líneas de cuadrícula principales cada hora y etiquetas cada 4 horas. Las etiquetas se colocan debajo de las líneas de cuadrícula principales ya que especifican exactamente esa hora.

--x-grid HOUR:8:DAY:1:DAY:1:86400:%A

Esto coloca líneas de cuadrícula cada 8 horas, líneas de cuadrícula principales y etiquetas cada día. Las etiquetas se colocan exactamente entre dos líneas de cuadrícula principales, ya que especifican el día completo y no solo la medianoche.

[--week-fmt cadena de formato strftime]

Por defecto, rrdtool utiliza "Week %V" para representar el número de semana. Con esta opción, puede definir su propio formato, sin anular completamente el formato del eje x.

Eje Y

[-y|--y-grid paso de cuadrícula:factor de etiqueta]

[-y|--y-grid none]

Las líneas de cuadrícula del eje Y aparecen en cada intervalo de paso de cuadrícula. Las etiquetas se colocan cada factor de etiqueta líneas. Puede especificar "-y none" para suprimir la cuadrícula y las etiquetas por completo. El valor predeterminado para esta opción es seleccionar automáticamente valores sensatos.

Si ha configurado --y-grid en 'none', no solo se suprimen las etiquetas, sino que también se elimina el espacio reservado para ellas. Todavía puede agregar espacio manualmente si utiliza el comando --units-length para reservar explícitamente espacio.

[--left-axis-formatter nombre del formateador]

Especifique qué formateador usar para representar los valores del eje.

numeric
El valor predeterminado, los valores se expresan como cantidades numéricas.
timestamp
Los valores se interpretan como marcas de tiempo de Unix (número de segundos desde 1970-01-01 00:00:00 UTC) y se expresan utilizando el formato strftime (el valor predeterminado es '%Y-%m-%d %H:%M:%S'). Consulte también --units-length y --left-axis-format.
duration
Los valores se interpretan como duraciones en milisegundos. El formato sigue las reglas de valstrfduration calificadas por PRINT/GPRINT. Consulte rrdgraph_graph.

[--left-axis-format cadena de formato]

Por defecto, el formato de las etiquetas del eje se determina automáticamente. Si desea hacerlo usted mismo, utilice esta opción con los mismos argumentos %lf que conoce de los comandos PRINT y GPRINT, u otros si utiliza un formateador diferente.

[-Y|--alt-y-grid]

Coloca la cuadrícula Y dinámicamente según el rango Y del gráfico. El algoritmo asegura que siempre haya una cuadrícula, que haya suficientes pero no demasiadas líneas de cuadrícula, y que la cuadrícula sea métrica. Es decir, las líneas de cuadrícula se colocan cada 1, 2, 5 o 10 unidades. Este parámetro también asegurará que se muestren suficientes decimales, incluso si su gráfico va de 69.998 a 70.001. (aportado por Sasha Mikheev).

[-o|--logarithmic]

Escalado logarítmico del eje Y.

[-X|--units-exponent valor]

Esto establece el escalado 10**exponente de los valores del eje Y. Normalmente, los valores se escalarán a las unidades apropiadas (k, M, etc.). Sin embargo, puede que desee mostrar las unidades siempre en k (Kilo, 10e3) incluso si los datos están en el rango M (Mega, 10e6), por ejemplo. El valor debe ser un entero múltiplo de 3 entre -18 y 18 inclusive. Es el exponente de las unidades que desea utilizar. Por ejemplo, use 3 para mostrar los valores del eje Y en k (Kilo, 10e3, miles), use -6 para mostrar los valores del eje Y en u (Micro, 10e-6, millonésimas). Use un valor de 0 para evitar cualquier escalado de los valores del eje Y.

Esta opción es muy eficaz para confundir a la función de escalado automático y al pintor de cuadrículas predeterminados de RRDtool. Si RRDtool detecta que no tiene éxito al etiquetar el gráfico en las circunstancias dadas, cambiará al modo más robusto --alt-y-grid.

[-L|--units-length valor]

¿A cuántos dígitos debe suponer RRDtool que son las etiquetas del eje Y? Es posible que deba usar esta opción para reservar suficiente espacio una vez que comience a manipular el etiquetado del eje Y.

[--units=si]

Con esta opción, los valores del eje Y en gráficos logarítmicos se escalarán a las unidades apropiadas (k, M, etc.) en lugar de usar notación exponencial. Tenga en cuenta que para los gráficos lineales, la notación SI se utiliza por defecto.

Eje Y Derecho

[--right-axis escala:desplazamiento] [--right-axis-label etiqueta]

Se dibujará un segundo eje a la derecha del gráfico. Está vinculado al eje izquierdo a través de los parámetros de escala y desplazamiento. También puede definir una etiqueta para el eje derecho.

[--right-axis-formatter nombre del formateador]

Especifique qué formateador usar para representar los valores del eje.

numeric
El valor predeterminado, los valores se expresan como cantidades numéricas.
timestamp
Los valores se interpretan como marcas de tiempo de Unix (número de segundos desde 1970-01-01 00:00:00 UTC) y se expresan utilizando el formato strftime (el valor predeterminado es '%Y-%m-%d %H:%M:%S'). Consulte también --units-length y --right-axis-format.
duration
Los valores se interpretan como duraciones en milisegundos. El formato sigue las reglas de valstrfduration calificadas por PRINT/GPRINT. Consulte rrdgraph_graph.

[--right-axis-format cadena de formato]

Por defecto, el formato de las etiquetas del eje se determina automáticamente. Si desea hacerlo usted mismo, utilice esta opción con los mismos argumentos %lf que conoce de los comandos PRINT y GPRINT, u otros si utiliza un formateador diferente.

Leyenda

[-g|--no-legend]

Suprimir la generación de la leyenda; solo renderizar el gráfico.

[-F|--force-rules-legend]

Forzar la generación de leyendas HRULE y VRULE, incluso si esas HRULE o VRULE no se dibujarán porque están fuera de los límites del gráfico (imita el comportamiento de las versiones anteriores a 1.0.42).

[--legend-position=(north|south|west|east)]

Coloca la leyenda en el lado dado del gráfico. El valor predeterminado es south. En las posiciones west o east, es necesario agregar saltos de línea manualmente.

[--legend-direction=(topdown|bottomup|bottomup2)]

Coloca los elementos de la leyenda en el orden vertical dado. El valor predeterminado es topdown. Usando bottomup, los elementos de la leyenda aparecen en el mismo orden vertical que una pila de líneas o áreas. Usando bottomup2, se mantendrán en orden las líneas COMMENT iniciales y finales, esto podría ser útil para generadores que las usan como encabezados de tabla y similares.

Miscelánea

[-z|--lazy]

Generar el gráfico solo si el gráfico actual está desactualizado o no existe. Tenga en cuenta que todos los cálculos se realizarán independientemente para que la salida de PRINT y graphv sea completa. Tenga en cuenta que el comportamiento de lazy a este respecto ha experimentado varios cambios a lo largo del tiempo. Lo único de lo que realmente puede depender antes de RRDtool 1.3.7 es que lazy no generará el gráfico cuando ya esté allí y esté actualizado, y también que generará el tamaño del gráfico.

[-d|--daemon dirección]

Dirección del demonio rrdcached. Si se especifica, se envía un comando "flush" al servidor antes de leer los archivos RRD. Esto permite que el gráfico contenga datos frescos, incluso si el demonio está configurado para almacenar en caché valores durante mucho tiempo. Para obtener una lista de formatos aceptados, consulte la opción -l en el manual de rrdcached.

rrdtool graph [...] --daemon unix:/var/run/rrdcached.sock [...]

[-f|--imginfo printfstr]

Después de crear la imagen, la función graph utiliza printf junto con esta cadena de formato para crear una salida similar a la función PRINT, solo que la función printf recibe los parámetros filename, xsize y ysize. Para generar una etiqueta IMG adecuada para incluir el gráfico en una página web, la línea de comandos sería:

--imginfo '<IMG SRC="/img/%s" WIDTH="%lu" HEIGHT="%lu" ALT="Demo">'

[-c|--color COLORTAG#rrggbb[aa]]

Anula los colores predeterminados para los elementos estándar del gráfico. El COLORTAG es uno de "BACK" para el fondo, "CANVAS" para el fondo del gráfico real, "SHADEA" para el borde izquierdo y superior, "SHADEB" para el borde derecho e inferior, "GRID", "MGRID" para la cuadrícula principal, "FONT" para el color de la fuente, "AXIS" para el eje del gráfico, "FRAME" para la línea alrededor de las manchas de color y, finalmente, "ARROW" para la punta de flecha que apunta hacia arriba y hacia adelante. Cada color se compone de tres números hexadecimales que especifican su componente de color rgb (00 está apagado, FF es máximo) de rojo, verde y azul. Opcionalmente, puede agregar otro número hexadecimal que especifique la transparencia (FF es sólido). Puede configurar esta opción varias veces para alterar varios valores predeterminados.

Una flecha verde se crea con: "--color ARROW#00FF00"

[--grid-dash on:off]

por defecto, la cuadrícula se dibuja en un patrón de 1 encendido, 1 apagado. Con esta opción puedes configurarlo tú mismo

--grid-dash 1:3 para una cuadrícula de puntos
--grid-dash 1:0 para líneas de cuadrícula ininterrumpidas

[--border ancho]

Ancho en píxeles para el borde 3D dibujado alrededor de la imagen

This is useful to calculate daily average ranging from midnight to midnight rather than say the last 24 hours. .SS Data and variables .TP .BI "DEF:" vname "=" rrdfile ":" ds-name ":" CF [:step=step][:start=time][:end=time] .TP .BI "CDEF:" vname "=" RPN expression .TP .BI "VDEF:" vname "=" RPN expression .PP You need at least one DEF and one LINE, AREA, GPRINT, PRINT statement to generate anything useful. .PP See rrdgraph_data and rrdgraph_rpn for the exact format. .PP NOTE: Graph and print elements .PP You need at least one graph element to generate an image and/or at least one print statement to generate a report. See rrdgraph_graph for the exact format. .SS graphv Calling RRDtool with the graphv option will return information in the RRDtool info format. On the command line this means that all output will be in key=value format. When used from the Perl and Ruby bindings a hash pointer will be returned from the call. .PP When the filename '-' is given, the contents of the graph itself will also be returned through this interface (hash key 'image'). On the command line the output will look like this: .PP .DS B print[0] = "0.020833" print[1] = "0.0440833" graph_left = 51 graph_top = 22 graph_width = 400 graph_height = 100 graph_start = 1232908800 graph_end = 1232914200 image_width = 481 image_height = 154 value_min = 0.0000000000e+00 value_max = 4.0000000000e-02 image = BLOB_SIZE:8196 [... 8196 bytes of image data ...] .DE .PP There is more information returned than in the standard interface. Especially the 'graph_*' keys are new. They help applications that want to know what is where on the graph. .SH ENVIRONMENT VARIABLES The following environment variables may be used to change the behavior of .B rrdtool graph: .TP .BI "RRDCACHED_ADDRESS " If this environment variable is set it will have the same effect as specifying the "--daemon" option on the command line. If both are present, the command line argument takes precedence. .TP .BI "RRD_DEFAULT_FONT " RRDtool comes with a preset default font. You can set the environment variable RRD_DEFAULT_FONT if you want to change this. .SH SEE ALSO rrdgraph gives an overview of how .B rrdtool graph works. rrdgraph_data describes .B DEF, CDEF and .B VDEF in detail. rrdgraph_rpn describes the .B RPN language used in the ?DEF statements. rrdgraph_graph page describes all of the graph and print functions. .PP Make sure to read rrdgraph_examples for tips&tricks. .SH AUTHOR Program by Tobias Oetiker .PP This manual page by Alex van den Bogaerdt with corrections and/or additions by several people .DT 2024-07-29 1.9.0 rrdtool(1) - Arch Linux
