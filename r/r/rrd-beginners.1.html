NOMBRE

rrd-beginners - Guía para principiantes de RRDtool

SINOPSIS

Ayudando a los nuevos usuarios de RRDtool a comprender los conceptos básicos de RRDtool

DESCRIPCIÓN

Este manual es un intento de ayudar a los principiantes a comprender los conceptos de RRDtool. Pone de relieve las diferencias entre RRDtool y otras bases de datos. Con la ayuda de un ejemplo, explica la estructura de la base de datos de RRDtool. A esto le sigue una visión general de la característica de "gráficos" de RRDtool. Al final, tiene scripts de muestra que ilustran el uso/envoltorio de RRDtool dentro de scripts de Shell o Perl.

¿Qué hace a RRDtool tan especial?

RRDtool es software bajo licencia GNU desarrollado por Tobias Oetiker, un administrador de sistemas en el Instituto Federal Suizo de Tecnología. Aunque es una base de datos, existen diferencias claras entre las bases de datos RRDtool y otras bases de datos, como se enumera a continuación:

  • RRDtool almacena datos; eso lo convierte en una herramienta de backend. El conjunto de comandos de RRDtool permite crear gráficos; eso también lo convierte en una herramienta de frontend. Otras bases de datos solo almacenan datos y no pueden crear gráficos.
  • En el caso de las bases de datos lineales, los nuevos datos se añaden al final de la tabla de la base de datos. Por lo tanto, su tamaño sigue aumentando, mientras que el tamaño de una base de datos RRDtool se determina en el momento de su creación. Imagine una base de datos RRDtool como el perímetro de un círculo. Los datos se añaden a lo largo del perímetro. Cuando los nuevos datos llegan al punto de partida, sobrescriben los datos existentes. De esta manera, el tamaño de una base de datos RRDtool siempre se mantiene constante. El nombre "Round Robin" proviene de este comportamiento.
  • Otras bases de datos almacenan los valores tal como se proporcionan. RRDtool se puede configurar para calcular la tasa de cambio del valor anterior al valor actual y almacenar esta información en su lugar.
  • Otras bases de datos se actualizan cuando se proporcionan valores. La base de datos RRDtool está estructurada de tal manera que necesita datos en intervalos de tiempo predefinidos. Si no recibe un nuevo valor durante el intervalo, almacena un valor DESCONOCIDO para ese intervalo. Por lo tanto, al utilizar la base de datos RRDtool, es imperativo utilizar scripts que se ejecuten a intervalos regulares para garantizar un flujo de datos constante para actualizar la base de datos RRDtool.

RRDtool está diseñado para almacenar series temporales de datos. Con cada actualización de datos, se almacena una marca de tiempo asociada. El tiempo siempre se expresa en segundos transcurridos desde la época (01-01-1970). RRDtool se puede instalar tanto en Unix como en Windows. Viene con un conjunto de comandos para realizar diversas operaciones en bases de datos RRD. A este conjunto de comandos se puede acceder desde la línea de comandos, así como desde scripts de Shell o Perl. Los scripts actúan como envoltorios para acceder a los datos almacenados en las bases de datos RRDtool.

Comprensión mediante un ejemplo

La estructura de una base de datos RRD es diferente de otras bases de datos lineales. Otras bases de datos definen tablas con columnas y muchos otros parámetros. Estas definiciones a veces son muy complejas, especialmente en bases de datos grandes. Las bases de datos RRDtool se utilizan principalmente para fines de monitoreo y, por lo tanto, son muy simples en su estructura. Los parámetros que deben definirse son variables que almacenan valores y archivos de esos valores. Al ser sensibles al tiempo, también se definen un par de parámetros relacionados con el tiempo. Debido a su estructura, la definición de una base de datos RRDtool también incluye una disposición para especificar acciones específicas a tomar en ausencia de valores de actualización. Data Source (DS), heartbeat, Date Source Type (DST), Round Robin Archive (RRA) y Consolidation Function (CF) son algunas de las terminologías relacionadas con las bases de datos RRDtool.

La estructura de una base de datos y la terminología asociada a ella se pueden explicar mejor con un ejemplo.

rrdtool create target.rrd \
        --start 1023654125 \
        --step 300 \
        DS:mem:GAUGE:600:0:671744 \
        RRA:AVERAGE:0.5:12:24 \
        RRA:AVERAGE:0.5:288:31

Este ejemplo crea una base de datos llamada target.rrd. La hora de inicio (1'023'654'125) se especifica en el número total de segundos desde la época (tiempo en segundos desde 01-01-1970). Al actualizar la base de datos, también se especifica la hora de actualización. Esta hora de actualización DEBE ser mayor (posterior) que la hora de inicio y DEBE estar en segundos desde la época.

El paso de 300 segundos indica que la base de datos espera nuevos valores cada 300 segundos. El script envoltorio debe programarse para que se ejecute cada step segundos para que actualice la base de datos cada step segundos.

DS (Data Source) es la variable real que se relaciona con el parámetro del dispositivo que se está monitoreando. Su sintaxis es

DS:nombre_variable:DST:heartbeat:min:max

DS es una palabra clave. "nombre_variable" es un nombre bajo el cual el parámetro se guarda en la base de datos. Puede haber tantos DS en una base de datos como sea necesario. Después de cada intervalo de paso, se proporciona un nuevo valor de DS para actualizar la base de datos. Este valor también se llama Punto de Datos Primario (PDP). En nuestro ejemplo anterior, se genera un nuevo PDP cada 300 segundos.

Tenga en cuenta que si NO proporciona puntos de datos nuevos exactamente cada 300 segundos, no es un problema, RRDtool interpolará los datos en consecuencia.

DST (Data Source Type) define el tipo del DS. Puede ser COUNTER, DERIVE, ABSOLUTE, GAUGE. Un DS declarado como COUNTER guardará la tasa de cambio del valor durante un período de paso. Esto asume que el valor siempre está aumentando (la diferencia entre el valor actual y el anterior es mayor que 0). Los contadores de tráfico en un enrutador son un candidato ideal para usar COUNTER como DST. DERIVE es lo mismo que COUNTER, pero permite valores negativos también. Si desea ver la tasa de *cambio* en el espacio libre en disco de su servidor, es posible que desee utilizar el tipo de datos DERIVE. ABSOLUTE también guarda la tasa de cambio, pero asume que el valor anterior se establece en 0. La diferencia entre el valor actual y el anterior es siempre igual al valor actual. Por lo tanto, simplemente almacena el valor actual dividido por el intervalo de paso (300 segundos en nuestro ejemplo). GAUGE no guarda la tasa de cambio. Guarda el valor real en sí. No hay divisiones ni cálculos. El consumo de memoria en un servidor es un ejemplo típico de gauge. La diferencia entre los diferentes tipos de DSTs se puede explicar mejor con el siguiente ejemplo:

Valores       = 300, 600, 900, 1200
Paso         = 300 segundos
DS COUNTER   =    1,  1,   1,    1
DS DERIVE    =    1,  1,   1,    1
DS ABSOLUTE  =    1,  2,   3,    4
DS GAUGE     = 300, 600, 900, 1200

El siguiente parámetro es heartbeat. En nuestro ejemplo, el heartbeat es de 600 segundos. Si la base de datos no recibe un nuevo PDP dentro de los 300 segundos, esperará otros 300 segundos (600 segundos en total). Si no recibe ningún PDP dentro de los 600 segundos, guardará un valor DESCONOCIDO en la base de datos. Este valor DESCONOCIDO es una característica especial de RRDtool: es mucho mejor que asumir que un valor faltante era 0 (cero) o cualquier otro número que también podría ser un valor de datos válido. Por ejemplo, el contador de flujo de tráfico en un enrutador sigue aumentando. Digamos que se pierde un valor para un intervalo y se almacena 0 en lugar de DESCONOCIDO. Ahora, cuando el siguiente valor esté disponible, calculará la diferencia entre el valor actual y el valor anterior (0), lo cual no es correcto. Por lo tanto, insertar el valor DESCONOCIDO tiene mucho más sentido aquí.

Los dos parámetros siguientes son el valor mínimo y máximo, respectivamente. Si la variable a almacenar tiene valores máximos y mínimos predecibles, esto debe especificarse aquí. Cualquier valor de actualización que caiga fuera de este rango se almacenará como DESCONOCIDO.

La siguiente línea declara un archivo round robin (RRA). La sintaxis para declarar un RRA es

RRA:CF:xff:paso:filas

RRA es la palabra clave para declarar RRAs. La función de consolidación (CF) puede ser AVERAGE, MINIMUM, MAXIMUM y LAST. El concepto de punto de datos consolidado (CDP) entra en juego aquí. Un CDP se forma a partir de paso número de PDPs mediante CF (promedio, valor máximo/mínimo o último valor). Este RRA contendrá filas de estos CDPs.

Echemos un vistazo al ejemplo anterior. Para el primer RRA, se calcula el PROMEDIO (CF) de 12 (pasos) PDPs (variables DS) para formar un CDP. Se archivan 24 (filas) de estos CDPs. Cada PDP ocurre cada 300 segundos. 12 PDPs representan 12 veces 300 segundos, que es 1 hora. Esto significa que 1 CDP (que es igual a 12 PDPs) representa datos de 1 hora. 24 de estos CDPs representan 1 día (1 hora por 24 CDPs). Esto significa que este RRA es un archivo de un día. Después de 24 CDPs, el CDP número 25 reemplazará al primer CDP. El segundo RRA almacena 31 CDPs; cada CDP representa un valor PROMEDIO para un día (288 PDPs, cada uno cubriendo 300 segundos = 24 horas).

). Por lo tanto, este RRA es un archivo de un mes. Una única base de datos puede tener muchos RRAs. Si hay múltiples DS, cada RRA individual guardará datos de todos los DS de la base de datos. Por ejemplo, si una base de datos tiene 3 DS y se declaran RRAs diarios, semanales, mensuales y anuales, entonces cada RRA contendrá datos de las 3 fuentes de datos.

Magia Gráfica

Otra característica importante de RRDtool es su capacidad para crear gráficos. El comando "graph" utiliza el comando "fetch" internamente para recuperar valores de la base de datos. Con los valores recuperados dibuja gráficos según lo definido por los parámetros suministrados en la línea de comandos. Un solo gráfico puede mostrar diferentes DS (Fuentes de Datos) de una base de datos. También es posible mostrar los valores de más de una base de datos en un solo gráfico. A menudo, es necesario realizar algunas operaciones matemáticas sobre los valores recuperados de la base de datos antes de graficarlos. Por ejemplo, en las respuestas SNMP, el consumo de memoria los valores se especifican generalmente en KBytes y el flujo de tráfico en las interfaces se especifica en Bytes. Los gráficos para estos valores serán más significativos si los valores se representan en MBytes y mbps. El comando de gráfico RRDtool permite definir tales conversiones. Además de los cálculos matemáticos, también es posible realizar operaciones lógicas como mayor que, menor que, y si/entonces/sino. Si una base de datos contiene más de un archivo RRA, entonces puede surgir una pregunta: ¿cómo decide RRDtool qué archivo RRA utilizar para recuperar los valores? RRDtool examina varias cosas al tomar su decisión. Primero, se asegura de que el RRA cubra la mayor parte del marco de tiempo del gráfico posible. Segundo, examina la resolución del RRA en comparación con la resolución del gráfico. Intenta encontrar uno que tenga la misma o mejor resolución. Con la opción "-r", puede forzar a RRDtool a asumir una resolución diferente a la calculada a partir del ancho en píxeles del gráfico.

Los valores de diferentes variables se pueden presentar en 5 formas diferentes en un gráfico: AREA, LINE1, LINE2, LINE3 y STACK. AREA se representa mediante un área de color sólido con los valores como límite de esta área. LINE1/2/3 (ancho creciente) son simplemente líneas planas que representan los valores. STACK es también un área, pero se apila sobre un AREA o LINE1/2/3. Otra cosa importante a tener en cuenta es que las variables se grafican en el orden en que se definen en el comando de gráfico. Por lo tanto, se debe tener cuidado de definir STACK solo después de definir AREA/LINE. También es posible incluir comentarios formateados dentro del gráfico. Las instrucciones detalladas se pueden encontrar en el manual de gráficos.

Envolver RRDtool dentro de scripts Shell/Perl

Después de entender RRDtool, es hora de usarlo realmente en scripts. Las tareas involucradas en la gestión de redes son la recopilación de datos, el almacenamiento de datos y la recuperación de datos. En el siguiente ejemplo, se utiliza la base de datos target.rrd creada anteriormente. La recopilación y el almacenamiento de datos se realizan mediante scripts de Shell. La recuperación de datos y la generación de informes se realizan mediante scripts de Perl. Estos scripts se muestran a continuación:

Script de Shell (recopila datos, actualiza la base de datos)

#!/bin/sh
a=0
while [ "$a" == 0 ]; do
snmpwalk -c public 192.168.1.250 hrSWRunPerfMem > snmp_reply
    total_mem=`awk 'BEGIN {tot_mem=0}
                          { if ($NF == "KBytes")
                            {tot_mem=tot_mem+$(NF-1)}
                          }
                    END {print tot_mem}' snmp_reply`
    # Puedo usar N como reemplazo del tiempo actual
    rrdtool update target.rrd N:$total_mem
    # dormir hasta que se cumplan los próximos 300 segundos
    perl -e 'sleep 300 - time % 300'
done # fin del bucle while

Script de Perl (recupera datos de la base de datos y genera gráficos y estadísticas)

#!/usr/bin/perl -w
# Este script extrae datos de target.rrd, crea un gráfico del consumo
# de memoria en el objetivo (Procesador Dual P3 1 GHz, 656 MB de RAM)
# llama al módulo perl de RRD
use lib qw( /usr/local/rrdtool-1.0.41/lib/perl ../lib/perl );
use RRDs;
my $cur_time = time();                # establece la hora actual
my $end_time = $cur_time - 86400;     # establece la hora de finalización 24 horas atrás
my $start_time = $end_time - 2592000; # establece el inicio 30 días en el pasado
# extrae los valores promedio de la base de datos RRD entre la hora de inicio y finalización
my ($start,$step,$ds_names,$data) =
    RRDs::fetch("target.rrd", "AVERAGE",
                "-r", "600", "-s", "$start_time", "-e", "$end_time");
# guarda los valores extraídos en un array bidimensional
my $rows = 0;
my $columns = 0;
my $time_variable = $start;
foreach $line (@$data) {
  $vals[$rows][$columns] = $time_variable;
  $time_variable = $time_variable + $step;
  foreach $val (@$line) {
          $vals[$rows][++$columns] = $val;}
  $rows++;
  $columns = 0;
}
my $tot_time = 0;
my $count = 0;
# guarda los valores del bidimensional en un array unidimensional
for $i ( 0 .. $#vals ) {
    $tot_mem[$count] = $vals[$i][1];
    $count++;
}
my $tot_mem_sum = 0;
# calcula la suma de todos los valores
for $i ( 0 .. ($count-1) ) {
    $tot_mem_sum = $tot_mem_sum + $tot_mem[$i];
}
# calcula el promedio del array
my $tot_mem_ave = $tot_mem_sum/($count);
# crea el gráfico
RRDs::graph ("/images/mem_$count.png",
            "--title= Uso de Memoria",
            "--vertical-label=Consumo de Memoria (MB)",
            "--start=$start_time",
            "--end=$end_time",
            "--color=BACK#CCCCCC",
            "--color=CANVAS#CCFFFF",
            "--color=SHADEB#9999CC",
            "--height=125",
            "--upper-limit=656",
            "--lower-limit=0",
            "--rigid",
            "--base=1024",
            "DEF:tot_mem=target.rrd:mem:AVERAGE",
            "CDEF:tot_mem_cor=tot_mem,0,671744,LIMIT,UN,0,tot_mem,IF,1024,/",
            "CDEF:machine_mem=tot_mem,656,+,tot_mem,-",
            "COMMENT:Consumo de Memoria entre $start_time",
            "COMMENT:    y $end_time                     ",
            "HRULE:656#000000:Memoria Máxima Disponible - 656 MB",
            "AREA:machine_mem#CCFFFF:Memoria No Utilizada",
            "AREA:tot_mem_cor#6699CC:Consumo total de memoria en MB");
my $err=RRDs::error;
if ($err) {print "problema al generar el gráfico: $err\n";}
# imprime la salida
print "Consumo promedio de memoria es ";
printf "%5.2f",$tot_mem_ave/1024;
print " MB. La representación gráfica se puede encontrar en /images/mem_$count.png.";
