NOMBRE

rrdthreads - Disposiciones para enlazar la biblioteca RRD para usar en programas multihilo

SINOPSIS

Usar librrd en programas multihilo requiere algunas precauciones adicionales, ya que la biblioteca RRD en su forma original no era para nada segura en cuanto a hilos. Este documento describe los requisitos y las trampas para usar la versión multihilo de librrd en sus propios programas. También ofrece pistas para el futuro desarrollo de RRD para mantener la biblioteca segura en cuanto a hilos.

Actualmente, solo algunas operaciones de RRD están implementadas de forma segura en cuanto a hilos. Todas terminan con el sufijo habitual ""_r"".

DESCRIPCIÓN

Para usar librrd en programas multihilo, debe:

  • Enlazar con librrd_th en lugar de librrd (use "-lrrd_th" al enlazar)
  • Usar las funciones ""_r"" en lugar de las funciones normales de la API
  • No usar ninguna especificación de tiempo de tipo "at". El análisis de dichas especificaciones de tiempo no es nada seguro en cuanto a hilos.
  • Nunca usar funciones que no sean *"_r" a menos que se documente explícitamente que la función es segura en cuanto a hilos.
  • Cada hilo DEBE llamar a "rrd_get_context()" antes de su primera llamada a cualquier función de "librrd_th" para configurar datos específicos del hilo. Esto no es estrictamente necesario, pero es la única forma de verificar si la asignación de memoria puede ser realizada por esta función. De lo contrario, el programa puede morir con una SIGSEGV en una situación de baja memoria.
  • Siempre llame a "rrd_error_clear()" antes de cualquier llamada a la biblioteca. De lo contrario, la llamada puede fallar debido a algún error anterior.

NOTAS PARA LOS CONTRIBUIDORES DE RRD

Se deben seguir algunas precauciones al desarrollar RRD a partir de ahora:

•
Solo usar funciones seguras en cuanto a hilos en el código de la biblioteca. Muchas funciones de libc de uso común no son seguras en cuanto a hilos. Tenga cuidado en las siguientes situaciones o al usar las siguientes funciones de la biblioteca:
  • Se deben evitar las llamadas directas a "strerror()": use "rrd_strerror()" en su lugar, que proporciona un mensaje de error por hilo.
  • Las familias de funciones "getpw*", "getgr*", "gethost*" (y algunas otras funciones "get*") no son seguras en cuanto a hilos: use las variantes *"_r".
  • Funciones de tiempo: "asctime", "ctime", "gmtime", "localtime": use las variantes *"_r".
  • "strtok": use "strtok_r".
  • "tmpnam": use "tmpnam_r".
  • Muchas otras (consulte la documentación).
  • Se proporciona un archivo de cabecera llamado rrd_is_thread_safe.h que funciona con el preprocesador C de GNU para "envenenar" algunas de las funciones más comunes no seguras en cuanto a hilos utilizando la directiva "#pragma GCC poison". Simplemente incluya este archivo de cabecera en los archivos fuente que desee mantener seguros en cuanto a hilos.
  • ¡No introduzca variables globales!

    Si realmente, realmente tiene que usar una variable global, puede agregar un nuevo campo a la estructura "rrd_context" y modificar rrd_error.c, rrd_thread_safe.c y rrd_non_thread_safe.c

  • No use "getopt" ni "getopt_long" en *"_r" (ni directa ni indirectamente).

    "getopt" usa variables globales y se comporta mal en una aplicación multihilo cuando se llama de forma concurrente. En su lugar, proporcione una función *_r que tome todas las opciones como parámetros de función. Puede proporcionar argumentos argc y **argv para listas de argumentos de longitud variable. Vea "rrd_update_r" como ejemplo.

  • ¡No use la función "rrd_parsetime"!

    Utiliza muchas variables globales. Puede usarla en funciones no diseñadas para ser seguras en cuanto a hilos, como en funciones que envuelven la versión "_r" de alguna operación (por ejemplo, "rrd_create", pero no en "rrd_create_r").

FUNCIONES SEGURAS EN CUANTO A HILOS IMPLEMENTADAS ACTUALMENTE

Actualmente existen variantes seguras en cuanto a hilos para "rrd_update", "rrd_create", "rrd_dump", "rrd_info", "rrd_last" y "rrd_fetch".
