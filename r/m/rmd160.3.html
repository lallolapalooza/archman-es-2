RMD160(3) Manual de Funciones de Biblioteca RMD160(3)

NOMBRE

RMD160Init, RMD160Update, RMD160Pad, RMD160Final, RMD160Transform, RMD160End, RMD160File, RMD160FileChunk, RMD160Data — calcular el resumen del mensaje ``RIPEMD-160''

BIBLIOTECA

Biblioteca de Soporte de Resumen de Mensajes (MD4, MD5, etc.) (libmd, -lmd)

SINOPSIS

#include <sys/types.h>
#include <rmd160.h>

void
RMD160Init(RMD160_CTX *contexto);

void
RMD160Update(RMD160_CTX *contexto, const uint8_t *datos, uint32_t nbytes);

void
RMD160Pad(RMD160_CTX *contexto);

void
RMD160Final(uint8_t resumen[RMD160_DIGEST_LENGTH], RMD160_CTX *contexto);

void
RMD160Transform(uint32_t estado[5], const uint8_t bloque[RMD160_BLOCK_LENGTH]);

char *
RMD160End(RMD160_CTX *contexto, char *buf);

char *
RMD160File(const char *nombre_archivo, char *buf);

char *
RMD160FileChunk(const char *nombre_archivo, char *buf, off_t offset, off_t longitud);

char *
RMD160Data(const uint8_t *datos, size_t len, char *buf);

DESCRIPCIÓN

Las funciones RMD160 implementan el algoritmo de hash de resumen de mensaje RIPE de 160 bits (RMD-160). RMD-160 se utiliza para generar una representación condensada de un mensaje llamada resumen del mensaje. El algoritmo toma un mensaje de menos de 2^64 bits como entrada y produce un resumen de 160 bits adecuado para su uso como firma digital.

Las funciones RMD160 se consideran más seguras que las funciones md4(3), md5(3) y sha1(3). Todas comparten una interfaz similar.

La función RMD160Init() inicializa una RMD160_CTX contexto para su uso con RMD160Update() y RMD160Final(). La función RMD160Update() añade datos de longitud nbytes al RMD160_CTX especificado por contexto. RMD160Final() se llama cuando todos los datos han sido añadidos a través de RMD160Update() y almacena un resumen del mensaje en el parámetro resumen.

La función RMD160Pad() puede usarse para aplicar relleno al resumen del mensaje como en RMD160Final(), pero el contexto actual aún puede usarse con RMD160Update().

La función RMD160Transform() es utilizada por RMD160Update() para hashear bloques de 512 bits y forma el núcleo del algoritmo. La mayoría de los programas deberían usar la interfaz proporcionada por RMD160Init(), RMD160Update() y RMD160Final() en lugar de llamar RMD160Transform() directamente.

La función RMD160End() es un front-end para RMD160Final() que convierte el resumen en una representación ASCII del resumen de 160 bits en hexadecimal.

La función RMD160File() calcula el resumen de un archivo y devuelve el resultado a través de RMD160End(). Si RMD160File() no puede abrir el archivo, se devuelve un puntero NULL.

RMD160FileChunk() se comporta como RMD160File() pero calcula el resumen solo para esa porción del archivo que comienza en offset y continúa durante longitud bytes o hasta el final del archivo, lo que ocurra primero. Se puede especificar una longitud cero para leer hasta el final del archivo. Se ignorará una longitud o offset negativa.

La función RMD160Data() calcula el resumen de una cadena arbitraria y devuelve el resultado a través de RMD160End().

Para cada una de las funciones RMD160End(), RMD160File() y RMD160Data() el parámetro buf debe ser una cadena de al menos 41 caracteres de tamaño o un puntero NULL. En este último caso, se asignará espacio dinámicamente a través de malloc(3) y deberá liberarse usando free(3) cuando ya no sea necesario.

EJEMPLOS

El siguiente fragmento de código calculará el resumen de la cadena "abc" que es ``0x8eb208f7e05d987a9b044a8e98c6b087f15a0bfc''.

RMD160_CTX rmd;
uint8_t resultados[RMD160_DIGEST_LENGTH];
char *buf;
int n;

buf = "abc";
n = strlen(buf);
RMD160Init(&rmd);
RMD160Update(&rmd, (uint8_t *)buf, n);
RMD160Final(resultados, &rmd);

/* Imprimir el resumen como un único valor hexadecimal largo */
printf("0x");
for (n = 0; n < RMD160_DIGEST_LENGTH; n++)
	printf("%02x", resultados[n]);
putchar('\n');

Alternativamente, las funciones auxiliares podrían usarse de la siguiente manera:

RMD160_CTX rmd;
uint8_t salida[RMD160_DIGEST_STRING_LENGTH];
char *buf = "abc";

printf("0x%s\n", RMD160Data(buf, strlen(buf), salida));

HISTORIA

Las funciones RMD-160 aparecieron en OpenBSD 2.1.

AUTORES

Esta implementación de RMD-160 fue escrita por Markus Friedl.

Las funciones RMD160End(), RMD160File(), RMD160FileChunk() y RMD160Data() son derivadas de código escrito por Poul-Henning Kamp.

ADVERTENCIAS

Si un resumen de mensaje se va a copiar a un tipo de datos multibyte (es decir, un arreglo de cinco enteros de 32 bits) será necesario realizar un intercambio de bytes en máquinas de orden de bytes little-endian como i386, alpha y vax.
