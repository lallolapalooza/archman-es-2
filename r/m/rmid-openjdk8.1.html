rmid(1) Herramientas de Invocación de Métodos Remotos (RMI) rmid(1)

NOMBRE

rmid - Inicia el demonio del sistema de activación que permite registrar y activar objetos en una Máquina Virtual Java (JVM).

SINOPSIS

rmid [opciones]
opciones
Las opciones de línea de comandos. Ver Opciones.

DESCRIPCIÓN

El comando rmid inicia el demonio del sistema de activación. El sistema de activación debe iniciarse antes de que los objetos activables puedan ser registrados en el sistema de activación o activados en una JVM. Para obtener detalles sobre cómo escribir programas que utilizan objetos activables, consulte el tutorial Uso de la Activación en http://docs.oracle.com/javase/8/docs/technotes/guides/rmi/activation/overview.html

Inicie el demonio ejecutando el comando rmid y especificando un archivo de política de seguridad, de la siguiente manera:

rmid -J-Djava.security.policy=rmid.policy

Cuando ejecute la implementación de Oracle del comando rmid, por defecto deberá especificar un archivo de política de seguridad para que el comando rmid pueda verificar si la información en cada ActivationGroupDesc puede ser utilizada para iniciar una JVM para un grupo de activación. Específicamente, el comando y las opciones especificadas por CommandEnvironment y cualquier propiedad pasada a un constructor de ActivationGroupDesc ahora deben permitirse explícitamente en el archivo de política de seguridad para el comando rmid. El valor de la propiedad sun.rmi.activation.execPolicy dicta la política que el comando rmid utiliza para determinar si la información en un ActivationGroupDesc puede ser utilizada para iniciar una JVM para un grupo de activación. Para más información, consulte la descripción de la opción -J-Dsun.rmi.activation.execPolicy=policy.

Ejecutar el comando rmid inicia el Activador y un registro interno en el puerto predeterminado 1098 y enlaza un ActivationSystem al nombre java.rmi.activation.ActivationSystem en este registro interno.

Para especificar un puerto alternativo para el registro, debe especificar la opción -port al ejecutar el comando rmid. Por ejemplo, el siguiente comando inicia el demonio del sistema de activación y un registro en el puerto predeterminado del registro, 1099.

rmid -J-Djava.security.policy=rmid.policy -port 1099

INICIAR RMID A PETICIÓN

Una alternativa a iniciar rmid desde la línea de comandos es configurar inetd (Oracle Solaris) o xinetd (Linux) para iniciar rmid a petición.

Cuando RMID se inicia, intenta obtener un canal heredado (heredado de inetd/xinetd) llamando al método System.inheritedChannel. Si el canal heredado es nulo o no es una instancia de java.nio.channels.ServerSocketChannel, entonces RMID asume que no fue iniciado por inetd/xinetd y se inicia como se describió anteriormente.

Si el canal heredado es una instancia de ServerSocketChannel, entonces RMID utiliza el java.net.ServerSocket obtenido del ServerSocketChannel como el socket del servidor que acepta solicitudes de los objetos remotos que exporta: el registro en el que se enlaza java.rmi.activation.ActivationSystem y el objeto remoto java.rmi.activation.Activator. En este modo, RMID se comporta igual que cuando se inicia desde la línea de comandos, excepto en los siguientes casos:

•
La salida impresa en System.err se redirige a un archivo. Este archivo se encuentra en el directorio especificado por la propiedad del sistema java.io.tmpdir (típicamente /var/tmp o /tmp) con el prefijo rmid-err y el sufijo tmp.
•
La opción -port no está permitida. Si se especifica esta opción, entonces RMID sale con un mensaje de error.
•
La opción -log es obligatoria. Si esta opción no se especifica, entonces RMID sale con un mensaje de error.

Consulte las páginas del manual de inetd (Oracle Solaris) o xinetd (Linux) para obtener detalles sobre cómo configurar servicios para que se inicien a petición.

OPCIONES

-Copción

Especifica una opción que se pasa como argumento de línea de comandos a cada proceso hijo (grupo de activación) del comando rmid cuando se crea ese proceso. Por ejemplo, podría pasar una propiedad a cada máquina virtual generada por el demonio del sistema de activación: 
rmid -C-Dsome.property=value

Esta capacidad de pasar argumentos de línea de comandos a los procesos hijos puede ser útil para la depuración. Por ejemplo, el siguiente comando habilita el registro de llamadas en todas las JVM hijas.

rmid -C-Djava.rmi.server.logCalls=true
-Jopción

Especifica una opción que se pasa al intérprete de Java que ejecuta RMID. Por ejemplo, para especificar que el comando rmid utilice un archivo de política llamado rmid.policy, la opción -J puede usarse para definir la propiedad java.security.policy en la línea de comandos de rmid, por ejemplo: 
rmid -J-Djava.security.policy-rmid.policy
-J-Dsun.rmi.activation.execPolicy=política

Especifica la política que RMID emplea para verificar comandos y opciones de línea de comandos utilizados para iniciar la JVM en la que se ejecuta un grupo de activación. Tenga en cuenta que esta opción solo existe en la implementación de Oracle del demonio de activación RMI de Java. Si esta propiedad no se especifica en la línea de comandos, el resultado es el mismo que si se especificara -J-Dsun.rmi.activation.execPolicy=default. Los valores posibles de política pueden ser default, policyClassName o none.
•
default

El valor predeterminado o no especificado execPolicy permite que el comando rmid ejecute comandos con opciones de línea de comandos específicas solo cuando el comando rmid ha recibido permiso para ejecutar esos comandos y opciones en el archivo de política de seguridad que utiliza el comando rmid. Solo la implementación predeterminada del grupo de activación puede ser utilizada con la política de ejecución predeterminada.

El comando rmid inicia una JVM para un grupo de activación con la información del descriptor del grupo de activación registrado del grupo, un ActivationGroupDesc. El descriptor del grupo especifica un ActivationGroupDesc.CommandEnvironment opcional que incluye el comando a ejecutar para iniciar el grupo de activación y cualquier opción de línea de comandos a agregar a la línea de comandos. Por defecto, el comando rmid utiliza el comando java que se encuentra en java.home. El descriptor del grupo también contiene sobrescrituras de propiedades que se agregan a la línea de comandos como opciones definidas como: -D<propiedad>=<valor>. El permiso com.sun.rmi.rmid.ExecPermission otorga al comando rmid permiso para ejecutar un comando especificado en el CommandEnvironment del descriptor del grupo para iniciar un grupo de activación. El permiso com.sun.rmi.rmid.ExecOptionPermission permite que el comando rmid utilice opciones de línea de comandos, especificadas como sobrescrituras de propiedades en el descriptor del grupo o como opciones en el CommandEnvironment al iniciar el grupo de activación. Al otorgar al comando rmid permiso para ejecutar varios comandos y opciones, los permisos ExecPermission y ExecOptionPermission deben otorgarse a todas las fuentes de código.

ExecPermission

La clase ExecPermission representa el permiso para que el comando rmid ejecute un comando específico para iniciar un grupo de activación.

Sintaxis: El nombre de un ExecPermission es la ruta de un comando para el cual se otorga permiso al comando rmid para ejecutar. Una ruta que termina en una barra (/) y un asterisco (*) indica que todos los archivos contenidos en ese directorio

rmid(8) - Arch Linux

NAME

rmid - Java Remote Method Invocation activation system daemon

SYNOPSIS

rmid [options]

DESCRIPTION

The rmid command starts the RMI activation system daemon. The activation system allows you to register and activate remote objects that are implemented by classes that are not running continuously.

The rmid command provides a way to start activation groups that can be created to support activation of remote objects.

The activation system daemon, rmid, must be running for objects to be activated.

The rmid command can be started with a security policy file that controls which commands and options rmid can execute when it starts activation groups.

If rmid is started with no options, it runs with the default policy, which is to not allow any commands or options to be executed.

The rmid daemon can be started from the command line, or it can be started automatically by the system when the system boots.

If the sun.rmi.activation.execPolicy system property is set to a value other than none, then the rmid command will execute the specified policy.

START RMID ON DEMAND

Normally, the rmid command is started by an administrator before any activation occurs. However, rmid can also be started on demand by the activation system itself.

If the sun.rmi.activation.startjava.useSystemProperties system property is set to true, then the activation system will attempt to start rmid on demand if it is not already running. The activation system will attempt to start rmid by running the command specified by the sun.rmi.activation.rmid system property.

If the sun.rmi.activation.rmid system property is not set, then the activation system will attempt to start rmid by running the rmid command with no arguments.

OPTIONS

-Joption

Passes the argument option to the Java Virtual Machine (JVM) running the rmid command. For example, `-J-Xms512m` sets the initial heap size to 512 megabytes.
-policy policy

Specifies the security policy file to be used by the rmid command. If this option is not specified, then the rmid command will use the default security policy, which is to not allow any commands or options to be executed. The policy file is a text file that contains a list of permissions granted to code sources. The format of the policy file is described in the java.policy(5) man page.
-k

If the rmid command is already running, then this option causes the current invocation of rmid to stop the running rmid command and start a new one. This option is useful for updating the security policy of the rmid command.
•
execPolicy

The execPolicy argument specifies the policy to be used for executing commands by the rmid command. The policy can be one of the following values:

•
exec

The exec policy allows the rmid command to execute commands specified by ExecPermission and ExecOptionPermission entries in the policy file. The ExecPermission and ExecOptionPermission classes are used to grant permission to execute specific commands and command-line options.

ExecPermission

The ExecPermission class represents permission for the rmid command to execute a specific program. The name of an ExecPermission is the absolute path name of the program to be executed.

Syntax: Path names can include wildcards. A path name that ends in a slash (/) indicates all files and subdirectories contained in that directory. A path name that consists of the special token <<ALL FILES>> matches any file.

A path name that consists of an asterisk (*) indicates all files in the current directory. A path name that consists of a minus sign (-) indicates all files in the current directory and (recursively) all files and subdirectories contained in the current directory.

ExecOptionPermission

The ExecOptionPermission class represents permission for the rmid command to use a specific command-line option when starting an activation group. The name of an ExecOptionPermission is the value of a command-line option.

Syntax: Options support a limited wildcard scheme. An asterisk signifies a wildcard match, and it can appear as the option name itself (matches any option), or an asterisk (*) can appear at the end of the option name only when the asterisk (*) follows a dot (.) or an equals sign (=).

For example: * or -Dmydir.* or -Da.b.c=* is valid, but *mydir or -Da*b or ab* is not.

Policy file for rmid

When you grant the rmid command permission to execute various commands and options, the permissions ExecPermission and ExecOptionPermission must be granted to all code sources (universally). It is safe to grant these permissions universally because only the rmid command checks these permissions.

An example policy file that grants various execute permissions to the rmid command is:

grant {
    permission com.sun.rmi.rmid.ExecPermission
        "/files/apps/java/jdk1.7.0/solaris/bin/java";
    permission com.sun.rmi.rmid.ExecPermission
        "/files/apps/rmidcmds/*";
    permission com.sun.rmi.rmid.ExecOptionPermission
        "-Djava.security.policy=/files/policies/group.policy";
    permission com.sun.rmi.rmid.ExecOptionPermission
        "-Djava.security.debug=*";
    permission com.sun.rmi.rmid.ExecOptionPermission
        "-Dsun.rmi.*";
};

The first permission granted allows the rmid command to execute the 1.7.0 release of the java command, specified by its explicit path name. By default, the version of the java command found in java.home is used (the same one that the rmid command uses), and does not need to be specified in the policy file. The second permission allows the rmid command to execute any command in the directory /files/apps/rmidcmds.

The third permission granted, an ExecOptionPermission, allows the rmid command to start an activation group that defines the security policy file to be /files/policies/group.policy. The next permission allows the java.security.debug property to be used by an activation group. The last permission allows any property in the sun.rmi property name hierarchy to be used by activation groups.

To start the rmid command with a policy file, the java.security.policy property needs to be specified on the rmid command line, for example:

rmid -J-Djava.security.policy=rmid.policy.

•
<policyClassName>

If the default behavior is not flexible enough, then an administrator can provide, when starting the rmid command, the name of a class whose checkExecCommand method is executed to check commands to be executed by the rmid command.

The policyClassName specifies a public class with a public, no-argument constructor and an implementation of the following checkExecCommand method:

 public void checkExecCommand(ActivationGroupDesc desc, String[] command)
        throws SecurityException;

Before starting an activation group, the rmid command calls the policy's checkExecCommand method and passes to it the activation group descriptor and an array that contains the complete command to start the activation group. If the checkExecCommand throws a SecurityException, then the rmid command does not start the activation group and an ActivationException is thrown to the caller attempting to activate the object.

•
none

If the sun.rmi.activation.execPolicy property value is none, then the rmid command does not perform any validation of commands to start activation groups.

-log dir

Specifies the name of the directory the activation system daemon uses to write its database and associated information. The log directory defaults to creating a log, in the directory in which the rmid command was executed.
-port port

Specifies the port the registry uses. The activation system daemon binds the ActivationSystem, with the name java.rmi.activation.ActivationSystem, in this registry. The ActivationSystem on the local machine can be obtained using the following Naming.lookup method call: 
import java.rmi.*; 
    import java.rmi.activation.*;
    ActivationSystem system; system = (ActivationSystem)
    Naming.lookup("//:port/java.rmi.activation.ActivationSystem");
-stop

Stops the current invocation of the rmid command for a port specified by the -port option. If no port is specified, then this option stops the rmid invocation running on port 1098.

ENVIRONMENT VARIABLES

CLASSPATH

Used to provide the system a path to user-defined classes. Directories are separated by colons, for example: .:/usr/local/java/classes.
