RMDIR(1P) Manual del programador POSIX RMDIR(1P)

PRÓLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

rmdir — eliminar directorios

SINOPSIS

rmdir [-p] dir...

DESCRIPCIÓN

La utilidad rmdir eliminará la entrada de directorio especificada por cada operando dir.

Para cada operando dir, la utilidad rmdir realizará acciones equivalentes a la función rmdir() llamada con el operando dir como su único argumento.

Los directorios se procesarán en el orden especificado. Si se especifica un directorio y un subdirectorio de ese directorio en una sola invocación de la utilidad rmdir, la aplicación especificará el subdirectorio antes del directorio padre para que el directorio padre esté vacío cuando la utilidad rmdir intente eliminarlo.

OPCIONES

La utilidad rmdir se ajustará a las Definiciones Base del volumen de POSIX.1‐2017, Sección 12.2, Directrices de sintaxis de utilidad.

La siguiente opción deberá ser compatible:

-p
Eliminar todos los directorios en una ruta. Para cada operando dir:
1.
Se eliminará la entrada de directorio que nombra.
2.
Si el operando dir incluye más de un componente de ruta, ocurrirán efectos equivalentes al siguiente comando:
rmdir -p $(dirname dir)

OPERANDOS

El siguiente operando deberá ser compatible:

dir
Una ruta de un directorio vacío a eliminar.

STDIN

No se usa.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de rmdir:

LANG
Proporcionar un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determinar la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en lugar de caracteres multibyte en los argumentos).
LC_MESSAGES

Determinar la localización que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en el error estándar.
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Predeterminado.

STDOUT

No se usa.

STDERR

El error estándar se utilizará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
Cada entrada de directorio especificada por un operando dir se eliminó correctamente.
>0
Ocurrió un error.

CONSECUENCIAS DE ERRORES

Predeterminado.

Las siguientes secciones son informativas.

USO DE LA APLICACIÓN

La definición de un directorio vacío es uno que contiene, como máximo, entradas de directorio para punto (.) y punto-punto (..).

EJEMPLOS

Si un directorio a en el directorio actual está vacío excepto que contiene un directorio b y a/b está vacío excepto que contiene un directorio c:

rmdir -p a/b/c

elimina los tres directorios.

JUSTIFICACIÓN

En los sistemas System V históricos, la opción -p también causaba que se escribiera un mensaje en la salida estándar. El mensaje indicaba si se eliminó toda la ruta o si parte de la ruta permanecía por alguna razón. La sección STDERR requiere este diagnóstico cuando no se elimina toda la ruta especificada por un operando dir, pero no permite que el mensaje de estado que informa el éxito se escriba como un diagnóstico.

La utilidad rmdir en System V también incluía una opción -s que suprimía el mensaje informativo generado por la opción -p. Esta opción se ha omitido porque el mensaje informativo no está especificado por este volumen de POSIX.1‐2017.
