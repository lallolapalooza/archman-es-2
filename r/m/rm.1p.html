RM(1P) Manual del programador POSIX RM(1P)

PROLOGO

Esta página del manual es parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

rm — eliminar entradas de directorio

SINOPSIS

rm [-iRr] archivo...
rm -f [-iRr] [archivo...]

DESCRIPCION

La utilidad rm eliminará la entrada de directorio especificada por cada argumento archivo.

Si se especifican los archivos punto o punto-punto como la porción del nombre base de un operando (es decir, el componente final de la ruta) o si un operando se resuelve en el directorio raíz, rm escribirá un mensaje diagnóstico en la salida de error estándar y no hará nada más con dichos operandos.

Para cada archivo se tomarán los siguientes pasos:

1.
Si el archivo no existe:
a.
Si la opción -f no está especificada, rm escribirá un mensaje diagnóstico en la salida de error estándar.
b.
Continuar con los archivos restantes.
2.
Si el archivo es de tipo directorio, se tomarán los siguientes pasos:
a.
Si no se especifica ni la opción -R ni la opción -r, rm escribirá un mensaje diagnóstico en la salida de error estándar, no hará nada más con el archivo y continuará con los archivos restantes.
b.
Si el archivo es un directorio vacío, rm puede saltar al paso 2d. Si la opción -f no está especificada, y ya sea los permisos del archivo no permiten escribir y la entrada estándar es un terminal o la opción -i está especificada, rm escribirá un aviso en la salida de error estándar y leerá una línea de la entrada estándar. Si la respuesta no es afirmativa, rm no hará nada más con el archivo actual y continuará con los archivos restantes.
c.
Para cada entrada contenida en el archivo, distinta de punto o punto-punto, se tomarán los cuatro pasos enumerados aquí (1 a 4) con la entrada como si fuera un operando de archivo. La utilidad rm no recorrerá directorios siguiendo enlaces simbólicos a otras partes de la jerarquía, sino que eliminará los enlaces mismos.
d.
Si se especifica la opción -i, rm escribirá un aviso en la salida de error estándar y leerá una línea de la entrada estándar. Si la respuesta no es afirmativa, rm no hará nada más con el archivo actual y continuará con los archivos restantes.
3.
Si el archivo no es de tipo directorio, la opción -f no está especificada, y ya sea los permisos del archivo no permiten escribir y la entrada estándar es un terminal o la opción -i está especificada, rm escribirá un aviso en la salida de error estándar y leerá una línea de la entrada estándar. Si la respuesta no es afirmativa, rm no hará nada más con el archivo actual y continuará con los archivos restantes.
4.
Si el archivo actual es un directorio, rm realizará acciones equivalentes a la función rmdir() definida en el volumen de Interfaces del Sistema de POSIX.1-2017 llamada con una ruta del archivo actual utilizada como argumento path. Si el archivo actual no es un directorio, rm realizará acciones equivalentes a la función unlink() definida en el volumen de Interfaces del Sistema de POSIX.1-2017 llamada con una ruta del archivo actual utilizada como argumento path.

Si esto falla por alguna razón, rm escribirá un mensaje diagnóstico en la salida de error estándar, no hará nada más con el archivo actual y continuará con los archivos restantes.

La utilidad rm deberá ser capaz de descender a profundidades arbitrarias en una jerarquía de archivos, y no fallará debido a limitaciones de longitud de ruta (a menos que un operando especificado por el usuario exceda las limitaciones del sistema).

OPCIONES

La utilidad rm se ajustará a las Directrices de Sintaxis de Utilidades del volumen de Definiciones Base de POSIX.1-2017, *Sección 12.2*.

Las siguientes opciones se soportarán:

-f
No solicitar confirmación. No escribir mensajes diagnósticos ni modificar el estado de salida en caso de que no haya operandos de archivo, o en caso de operandos que no existan. Cualquier ocurrencia previa de la opción -i será ignorada.
-i
Solicitar confirmación como se describió anteriormente. Cualquier ocurrencia previa de la opción -f será ignorada.
-R
Eliminar jerarquías de archivos. Consulte la DESCRIPCIÓN.
-r
Equivalente a -R.

OPERANDOS

El siguiente operando se soportará:

archivo
Una ruta de una entrada de directorio a eliminar.

ENTRADA ESTÁNDAR

La entrada estándar se utilizará para leer una línea de entrada en respuesta a cada aviso especificado en la sección STDOUT. De lo contrario, la entrada estándar no se utilizará.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de rm:

LANG
Proporcionar un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1-2017, *Sección 8.2*, *Variables de Internacionalización* para la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de configuración regional).
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_COLLATE

Determinar la configuración regional para el comportamiento de rangos, clases de equivalencia y elementos de ordenación multicarácter utilizados en la expresión regular extendida definida para la palabra clave yesexpr en la categoría LC_MESSAGES.
LC_CTYPE
Determinar la configuración regional para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en argumentos) y el comportamiento de las clases de caracteres dentro de las expresiones regulares utilizadas en la expresión regular extendida definida para la palabra clave yesexpr en la categoría LC_MESSAGES.
LC_MESSAGES

Determinar la configuración regional utilizada para procesar respuestas afirmativas, y la configuración regional utilizada para afectar el formato y el contenido de los mensajes diagnósticos y los avisos escritos a la salida de error estándar.
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

USO DE APLICACIONES

La utilidad rm tiene prohibido eliminar los nombres punto y punto-punto para evitar las consecuencias de hacer inadvertidamente algo como:

rm -r .*

Algunas implementaciones no permiten la eliminación del último enlace a un archivo binario ejecutable que se está ejecutando; consulte el error [EBUSY] en la función unlink() definida en el volumen de Interfaces del Sistema de POSIX.1‐2017. Por lo tanto, la utilidad rm puede no poder eliminar dichos archivos.

La opción -i hace que rm solicite y lea la entrada estándar incluso si la entrada estándar no es un terminal, pero en ausencia de -i la solicitud de modo no se realiza cuando la entrada estándar no es un terminal.

EJEMPLOS

1.
El siguiente comando:
rm a.out core

elimina las entradas de directorio: a.out y core.

2.
El siguiente comando:
rm -Rf junk

elimina el directorio junk y todo su contenido, sin preguntar.

FUNDAMENTACIÓN

Para una claridad absoluta, los párrafos (2b) y (3) en la DESCRIPCIÓN de rm que describen el comportamiento al solicitar confirmación, deben interpretarse de la siguiente manera:

if ((NOT f_option) AND
    ((not_writable AND input_is_terminal) OR i_option))

El formato exacto de las solicitudes interactivas no está especificado. Solo se especifica la naturaleza general del contenido de las solicitudes porque las implementaciones pueden desear solicitudes más descriptivas que las utilizadas en implementaciones históricas. Por lo tanto, una aplicación que no utiliza la opción -f, o que utiliza la opción -i, se basa en el sistema para proporcionar el diálogo más adecuado directamente con el usuario, basándose en el comportamiento especificado.

La opción -r es una práctica histórica en todos los sistemas conocidos. La opción sinónima -R se proporciona para la coherencia con las otras utilidades de este volumen de POSIX.1‐2017 que proporcionan opciones que solicitan el descenso recursivo a través de la jerarquía de archivos.

El comportamiento de la opción -f en las versiones históricas de rm es inconsistente. En general, además de "forzar" el desvinculado sin solicitar permiso, siempre hace que los mensajes de diagnóstico se supriman y el estado de salida no se modifique para operandos inexistentes y archivos que no se pueden desvincular. En algunas versiones, sin embargo, la opción -f también suprime los mensajes de uso y los errores del sistema. La supresión de tales mensajes no es un servicio para scripts de shell ni para usuarios.

Es menos claro que los mensajes de error sobre archivos que no se pueden desvincular (eliminar) deban suprimirse. Aunque esta es una práctica histórica, este volumen de POSIX.1‐2017 no permite que la opción -f suprima dichos mensajes.

Al recibir las opciones -r y -i, las versiones históricas de rm solicitan al usuario dos veces para cada directorio, una vez antes de eliminar su contenido y una vez antes de intentar eliminar la entrada del directorio que lo nombra. Esto permite al usuario "podar" el recorrido de la jerarquía de archivos. Las versiones históricas de rm eran inconsistentes en que algunas no realizaban la primera solicitud para directorios nombrados en la línea de comandos y otras tenían un comportamiento de solicitud oscuro cuando se especificaba la opción -i y los permisos del archivo no permitían la escritura. El rm de POSIX Shell y Utilidades difiere poco de la práctica histórica, pero requiere que las solicitudes sean consistentes. Las versiones históricas de rm también eran inconsistentes en que las solicitudes se hacían tanto a la salida estándar como al error estándar. Este volumen de POSIX.1‐2017 requiere que las solicitudes se hagan al error estándar, para la coherencia con cp y mv, y para permitir extensiones históricas de rm que proporcionan una opción para listar los archivos eliminados en la salida estándar.

Se requiere que la utilidad rm descienda a profundidades arbitrarias para que se pueda eliminar cualquier jerarquía de archivos. Esto significa, por ejemplo, que la utilidad rm no puede quedarse sin descriptores de archivo durante su descenso (es decir, si el número de descriptores de archivo es limitado, rm no se puede implementar de la manera histórica en la que se utiliza un descriptor de archivo por nivel de directorio). Además, no se permite que rm falle debido a restricciones de longitud de ruta, a menos que un operando especificado por el usuario sea más largo que {PATH_MAX}.

La utilidad rm elimina los enlaces simbólicos en sí mismos, no los archivos a los que apuntan, como consecuencia de la dependencia de la funcionalidad unlink(), según la DESCRIPCIÓN. Al eliminar jerarquías con -r o -R, la prohibición de seguir enlaces simbólicos debe hacerse explícita.
