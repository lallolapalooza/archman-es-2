RMT(8) Manual de GNU TAR RMT(8)

NOMBRE

rmt - servidor de cintas magnéticas remotas

SINOPSIS

rmt

DESCRIPCIÓN

Rmt proporciona acceso remoto a archivos y dispositivos para tar(1), cpio(1) y utilidades de copia de seguridad similares. Normalmente se llama ejecutando rsh(1) o ssh(1) en la máquina remota, opcionalmente usando un nombre de usuario diferente si se proporciona uno.

El programa que llama se comunica con rmt enviando solicitudes a su entrada estándar y leyendo respuestas de la salida estándar. Una solicitud consiste en una letra de solicitud seguida de un argumento (si es necesario) y un carácter de nueva línea. Los datos adicionales, si los hay, se envían después de la nueva línea. En caso de éxito, rmt devuelve


Anúmero\n

donde número es una representación ASCII de un código de retorno decimal. Los datos adicionales se devuelven después de esta línea. En caso de error, se devuelve la siguiente respuesta:


Eerrno\nmensaje-error\n

donde errno es uno de los códigos de error del sistema, como se describe en errno(3), y mensaje-error es una descripción humana de una línea del error, como la impresa por perror(3).

Los comandos disponibles y las posibles respuestas se discuten en detalle en la siguiente sección.

COMANDOS

Odispositivo\nflags\n
Abre el dispositivo con los flags dados. Si ya se había abierto un dispositivo, se cierra antes de abrir el nuevo.

Argumentos

dispositivo
El nombre del dispositivo a abrir.
flags
Flags para open(2): un número decimal, o cualquier constante O_* válida de fcntl.h (se puede omitir el O_ inicial), o un OR a nivel de bits (usando |) de cualquiera de estos, por ejemplo: 
576
64|512
CREAT|TRUNC
Además, también se permite una forma combinada, es decir, un modo decimal seguido de su representación simbólica. En este caso, se da preferencia a la representación simbólica.

Respuesta

A0\n en caso de éxito.

Extensiones

La versión BSD solo permite un número decimal como flags.
C[dispositivo]\n
Cierra el dispositivo abierto actualmente.
Argumentos

Se ignoran silenciosamente todos los argumentos.
Respuesta

A0\n en caso de éxito.
Lwhence\noffset\n
Realiza un lseek(2) en el dispositivo abierto actualmente con los parámetros especificados.
Argumentos
whence
Desde dónde medir el desplazamiento. Los valores válidos son: 
0, SET, SEEK_SET	buscar desde el principio del archivo
1, CUR, SEEK_CUR	buscar desde la ubicación actual
2, END, SEEK_END	buscar desde el final del archivo
Respuesta

Aoffset\n en caso de éxito. El offset es el nuevo desplazamiento en el archivo.
Extensiones
La versión BSD solo permite 0,1,2 como whence.
Rcount\n

Lee count bytes de datos del dispositivo actual.
Argumentos
count
número de bytes a leer.
Respuesta

En caso de éxito:


Ardcount\n

seguido de rdcount bytes de datos leídos del dispositivo.

Wcount\n
Escribe datos en el dispositivo actual. El comando va seguido de count bytes de datos de entrada.
Argumentos
count
Número de bytes a escribir.
Respuesta

En caso de éxito: Awrcount\n, donde wrcount es el número de bytes realmente escritos.
Iopcode\ncount\n
Realiza un comando ioctl(2) MTIOCOP con los parámetros especificados.
Argumentos
opcode
Código de operación MTIOCOP.
count
mt_count.
Respuesta

En caso de éxito: A0\n.
S\n
Devuelve el estado del dispositivo abierto actualmente, tal como se obtuvo de una llamada a ioctl(2) MTIOCGET.
Argumentos

Ninguno
Respuesta

En caso de éxito: Acount\n seguido de count bytes de datos.

VER TAMBIÉN

tar(1).

ERRORES CONOCIDOS

No se recomienda usar esta utilidad como una herramienta de acceso a archivos remotos de propósito general.

REPORTE DE ERRORES

Reporte errores a <bug-tar@gnu.org>.

HISTORIA

El comando rmt apareció en 4.2BSD. El rmt de GNU está escrito desde cero, utilizando la especificación de BSD.
