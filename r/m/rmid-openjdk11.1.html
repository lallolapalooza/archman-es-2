rmid(1) Herramientas de Invocación de Métodos Remotos (RMI) rmid(1)

NOMBRE

rmid - Inicia el demonio del sistema de activación que permite registrar y activar objetos en una Máquina Virtual Java (JVM).

SINOPSIS

rmid [opciones]
opciones
Las opciones de línea de comandos. Ver Opciones.

DESCRIPCIÓN

El comando rmid inicia el demonio del sistema de activación. El sistema de activación debe iniciarse antes de que los objetos activables puedan ser registrados con el sistema de activación o activados en una JVM. Para obtener detalles sobre cómo escribir programas que utilicen objetos activables, consulte el tutorial Uso de la Activación en http://docs.oracle.com/javase/8/docs/technotes/guides/rmi/activation/overview.html

Inicie el demonio ejecutando el comando rmid y especificando un archivo de política de seguridad, como sigue:

rmid -J-Djava.security.policy=rmid.policy

Cuando ejecute la implementación de Oracle del comando rmid, por defecto deberá especificar un archivo de política de seguridad para que el comando rmid pueda verificar si la información en cada ActivationGroupDesc tiene permitido ser utilizada para iniciar una JVM para un grupo de activación. Específicamente, el comando y las opciones especificadas por CommandEnvironment y cualquier propiedad pasada a un constructor ActivationGroupDesc ahora deben permitirse explícitamente en el archivo de política de seguridad para el comando rmid. El valor de la propiedad sun.rmi.activation.execPolicy dicta la política que el comando rmid utiliza para determinar si la información en un ActivationGroupDesc puede ser utilizada para iniciar una JVM para un grupo de activación. Para más información, consulte la descripción de la opción -J-Dsun.rmi.activation.execPolicy=policy.

Ejecutar el comando rmid inicia el Activator y un registro interno en el puerto predeterminado 1098 y enlaza un ActivationSystem al nombre java.rmi.activation.ActivationSystem en este registro interno.

Para especificar un puerto alternativo para el registro, debe especificar la opción -port al ejecutar el comando rmid. Por ejemplo, el siguiente comando inicia el demonio del sistema de activación y un registro en el puerto predeterminado del registro, 1099.

rmid -J-Djava.security.policy=rmid.policy -port 1099

INICIAR RMID BAJO DEMANDA

Una alternativa a iniciar rmid desde la línea de comandos es configurar inetd (Oracle Solaris) o xinetd (Linux) para iniciar rmid bajo demanda.

Cuando RMID se inicia, intenta obtener un canal heredado (heredado de inetd/xinetd) llamando al método System.inheritedChannel. Si el canal heredado es nulo o no es una instancia de java.nio.channels.ServerSocketChannel, entonces RMID asume que no fue iniciado por inetd/xinetd y se inicia como se describió anteriormente.

Si el canal heredado es una instancia de ServerSocketChannel, entonces RMID utiliza el java.net.ServerSocket obtenido del ServerSocketChannel como el socket del servidor que acepta las solicitudes para los objetos remotos que exporta: el registro en el que se enlaza java.rmi.activation.ActivationSystem y el objeto remoto java.rmi.activation.Activator. En este modo, RMID se comporta igual que cuando se inició desde la línea de comandos, excepto en los siguientes casos:

•
La salida impresa a System.err se redirige a un archivo. Este archivo se encuentra en el directorio especificado por la propiedad del sistema java.io.tmpdir (típicamente /var/tmp o /tmp) con el prefijo rmid-err y el sufijo tmp.
•
La opción -port no está permitida. Si se especifica esta opción, entonces RMID sale con un mensaje de error.
•
La opción -log es requerida. Si esta opción no se especifica, entonces RMID sale con un mensaje de error.

Consulte las páginas del manual de inetd (Oracle Solaris) o xinetd (Linux) para obtener detalles sobre cómo configurar servicios para ser iniciados bajo demanda.

OPCIONES

-Copción

Especifica una opción que se pasa como argumento de línea de comandos a cada proceso hijo (grupo de activación) del comando rmid cuando se crea ese proceso. Por ejemplo, podría pasar una propiedad a cada máquina virtual generada por el demonio del sistema de activación: 
rmid -C-Dsome.property=value

Esta capacidad de pasar argumentos de línea de comandos a los procesos hijos puede ser útil para depurar. Por ejemplo, el siguiente comando habilita el registro de llamadas del servidor en todas las JVMs hijas.

rmid -C-Djava.rmi.server.logCalls=true
-Jopción

Especifica una opción que se pasa al intérprete de Java que ejecuta RMID. Por ejemplo, para especificar que el comando rmid utilice un archivo de política llamado rmid.policy, la opción -J se puede usar para definir la propiedad java.security.policy en la línea de comandos del comando rmid, por ejemplo: 
rmid -J-Djava.security.policy-rmid.policy
-J-Dsun.rmi.activation.execPolicy=política

Especifica la política que RMID emplea para verificar comandos y opciones de línea de comandos utilizadas para iniciar la JVM en la que se ejecuta un grupo de activación. Tenga en cuenta que esta opción solo existe en la implementación de Oracle del demonio de activación RMI de Java. Si esta propiedad no se especifica en la línea de comandos, el resultado es el mismo que si se especificara -J-Dsun.rmi.activation.execPolicy=default. Los valores posibles de política pueden ser default, policyClassName o none.
•
default

El valor predeterminado o no especificado execPolicy permite que el comando rmid ejecute comandos con opciones de línea de comandos específicas solo cuando al comando rmid se le ha concedido permiso para ejecutar esos comandos y opciones en el archivo de política de seguridad que utiliza el comando rmid. Solo la implementación predeterminada del grupo de activación se puede usar con la política de ejecución predeterminada.

El comando rmid inicia una JVM para un grupo de activación con la información en el descriptor del grupo de activación registrado del grupo, un ActivationGroupDesc. El descriptor del grupo especifica un ActivationGroupDesc.CommandEnvironment opcional que incluye el comando a ejecutar para iniciar el grupo de activación y cualquier opción de línea de comandos a agregar a la línea de comandos. Por defecto, el comando rmid utiliza el comando java que se encuentra en java.home. El descriptor del grupo también contiene reemplazos de propiedades que se agregan a la línea de comandos como opciones definidas como: -D<propiedad>=<valor>. El permiso com.sun.rmi.rmid.ExecPermission otorga al comando rmid permiso para ejecutar un comando especificado en el CommandEnvironment del descriptor del grupo para iniciar un grupo de activación. El permiso com.sun.rmi.rmid.ExecOptionPermission habilita al comando rmid a usar opciones de línea de comandos, especificadas como reemplazos de propiedades en el descriptor del grupo o como opciones en el CommandEnvironment al iniciar el grupo de activación. Al otorgar al comando rmid permiso para ejecutar varios comandos y opciones, los permisos ExecPermission y ExecOptionPermission deben otorgarse a todas las fuentes de código.

ExecPermission

La clase ExecPermission representa el permiso para que el comando rmid ejecute un comando específico para iniciar un grupo de activación.

Sintaxis: El nombre de un ExecPermission es la ruta de un comando para el cual se otorga al comando rmid permiso para ejecutar. Una ruta que termina en una barra (/) y un asterisco (*) indica que todos los archivos contenidos en ese directorio, donde la barra es el separador de archivos, File.separatorChar.

NOMBRE

rmid - gestor de grupos de activación de RMI

SINOPSIS

rmid [ -Joption ] [ -log dir ] [ -port port ] [ -stop ] [ policyClassName ]

DESCRIPCIÓN

El demonio del sistema de activación, rmid, es un programa que ejecuta el gestor de grupos de activación de RMI. El sistema de activación permite que las aplicaciones distribuidas creen y localicen objetos que se ejecutan en procesos de larga duración llamados grupos de activación. Los grupos de activación se utilizan para alojar objetos remotos. Los objetos remotos se activan (es decir, se cargan y se ponen en marcha) bajo demanda cuando el servicio de nombres de RMI recibe una solicitud para un objeto remoto activado.

El demonio rmid se ejecuta normalmente en la máquina donde se alojan los objetos remotos. Los clientes remotos y los objetos de agente de reenvío pueden conectarse al demonio rmid para solicitar la activación de objetos remotos. El demonio rmid crea un grupo de activación (un proceso Java que se ejecuta en segundo plano) para alojar el objeto remoto.

El demonio rmid es un componente del sistema de activación de RMI. El sistema de activación de RMI proporciona los mecanismos para la activación de objetos remotos, que es la capacidad de un objeto remoto para ser iniciado automáticamente cuando se accede a él. La activación es un mecanismo que permite a los objetos remotos ser creados y cargados bajo demanda.

El demonio rmid es necesario para iniciar el sistema de activación de RMI. El sistema de activación de RMI consta de dos partes: el demonio rmid y la interfaz ActivationSystem. La interfaz ActivationSystem es utilizada por los clientes remotos y los agentes de reenvío para solicitar la activación de objetos remotos. El demonio rmid implementa la interfaz ActivationSystem.

El demonio rmid se inicia normalmente en el momento del arranque del sistema. El demonio rmid escucha las solicitudes de activación en un puerto especificado. El puerto por defecto es 1098.

El demonio rmid mantiene una base de datos de información de activación, que se almacena en un directorio especificado por la opción -log. La base de datos contiene información sobre los grupos de activación y los objetos remotos que se han activado. La base de datos se utiliza para restaurar el estado del sistema de activación en caso de reinicio del demonio rmid.

El demonio rmid utiliza un archivo de políticas para determinar qué comandos y opciones se pueden ejecutar. El archivo de políticas se especifica en la línea de comandos utilizando la opción -J-Djava.security.policy=policyFile.

El demonio rmid utiliza las siguientes clases de permisos para controlar qué comandos y opciones se pueden ejecutar:

•
ExecPermission

La clase ExecPermission representa el permiso para que el comando rmid ejecute un comando específico. El nombre de una ExecPermission es la ruta completa del comando que se va a ejecutar.

Un nombre de ruta que termina en una barra inclinada (/) y un signo menos (-) indica todos los archivos y subdirectorios contenidos en ese directorio (recursivamente). Un nombre de ruta que consiste en el token especial <<ALL FILES>> coincide con cualquier archivo.

Un nombre de ruta que consiste en un asterisco (*) indica todos los archivos en el directorio actual. Un nombre de ruta que consiste en un signo menos (-) indica todos los archivos en el directorio actual y (de forma recursiva) todos los archivos y subdirectorios contenidos en el directorio actual.

•
ExecOptionPermission

La clase ExecOptionPermission representa el permiso para que el comando rmid utilice una opción de línea de comandos específica al iniciar un grupo de activación. El nombre de una ExecOptionPermission es el valor de una opción de línea de comandos.

Sintaxis: Las opciones admiten un esquema de comodines limitado. Un asterisco significa una coincidencia de comodín, y puede aparecer como el nombre de la opción en sí (coincide con cualquier opción), o un asterisco (*) puede aparecer al final del nombre de la opción solo cuando el asterisco (*) sigue a un punto (.) o a un signo igual (=).

Por ejemplo: * o -Dmydir.* o -Da.b.c=* es válido, pero *mydir o -Da*b o ab* no lo es.

Archivo de políticas para rmid

Cuando se concede permiso al comando rmid para ejecutar varios comandos y opciones, los permisos ExecPermission y ExecOptionPermission deben concederse a todas las fuentes de código (universalmente). Es seguro conceder estos permisos universalmente porque solo el comando rmid comprueba estos permisos.

Un archivo de políticas de ejemplo que concede varios permisos de ejecución al comando rmid es:

grant {
    permission com.sun.rmi.rmid.ExecPermission
        "/files/apps/java/jdk1.7.0/solaris/bin/java";
    permission com.sun.rmi.rmid.ExecPermission
        "/files/apps/rmidcmds/*";
    permission com.sun.rmi.rmid.ExecOptionPermission
        "-Djava.security.policy=/files/policies/group.policy";
    permission com.sun.rmi.rmid.ExecOptionPermission
        "-Djava.security.debug=*";
    permission com.sun.rmi.rmid.ExecOptionPermission
        "-Dsun.rmi.*";
};

El primer permiso concedido permite al comando rmid ejecutar la versión 1.7.0 del comando java, especificado por su ruta explícita. Por defecto, se utiliza la versión del comando java que se encuentra en java.home (la misma que utiliza el comando rmid), y no necesita especificarse en el archivo de políticas. El segundo permiso permite al comando rmid ejecutar cualquier comando en el directorio /files/apps/rmidcmds.

El tercer permiso concedido, un ExecOptionPermission, permite al comando rmid iniciar un grupo de activación que define el archivo de políticas de seguridad como /files/policies/group.policy. El siguiente permiso permite que la propiedad java.security.debug sea utilizada por un grupo de activación. El último permiso permite que cualquier propiedad en la jerarquía de nombres de propiedad sun.rmi sea utilizada por los grupos de activación.

Para iniciar el comando rmid con un archivo de políticas, la propiedad java.security.policy debe especificarse en la línea de comandos de rmid, por ejemplo:

rmid -J-Djava.security.policy=rmid.policy.

ARRANCAR RMID BAJO DEMANDA

•
<policyClassName>

Si el comportamiento por defecto no es lo suficientemente flexible, un administrador puede proporcionar, al iniciar el comando rmid, el nombre de una clase cuyo método checkExecCommand se ejecuta para comprobar los comandos que va a ejecutar el comando rmid.

El policyClassName especifica una clase pública con un constructor público sin argumentos y una implementación del siguiente método checkExecCommand:

 public void checkExecCommand(ActivationGroupDesc desc, String[] command)
        throws SecurityException;

Antes de iniciar un grupo de activación, el comando rmid llama al método checkExecCommand de la política y le pasa el descriptor del grupo de activación y una matriz que contiene el comando completo para iniciar el grupo de activación. Si checkExecCommand lanza una SecurityException, entonces el comando rmid no inicia el grupo de activación y se lanza una ActivationException al llamador que intenta activar el objeto.

•
none

Si el valor de la propiedad sun.rmi.activation.execPolicy es none, entonces el comando rmid no realiza ninguna validación de comandos para iniciar grupos de activación.

OPCIONES

-log dir

Especifica el nombre del directorio que el demonio del sistema de activación utiliza para escribir su base de datos y la información asociada. El directorio de registro por defecto es la creación de un registro, en el directorio en el que se ejecutó el comando rmid.
-port port

Especifica el puerto que utiliza el registro. El demonio del sistema de activación enlaza el ActivationSystem, con el nombre java.rmi.activation.ActivationSystem, en este registro. El ActivationSystem en la máquina local se puede obtener utilizando la siguiente llamada al método Naming.lookup: 
import java.rmi.*; 
    import java.rmi.activation.*;
    ActivationSystem system; system = (ActivationSystem)
    Naming.lookup("//:port/java.rmi.activation.ActivationSystem");
-stop

Detiene la invocación actual del comando rmid para un puerto especificado por la opción -port. Si no se especifica ningún puerto, esta opción detiene la invocación de rmid que se está ejecutando en el puerto 1098.

VARIABLES DE ENTORNO

CLASSPATH
Se utiliza para proporcionar al sistema una ruta a las clases definidas por el usuario. Los directorios están separados por dos puntos, por ejemplo: .:/usr/local/java/classes.
