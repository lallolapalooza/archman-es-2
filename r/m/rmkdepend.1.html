RMKDEPEND(1) Manual de comandos generales RMKDEPEND(1)

NOMBRE

rmkdepend - crea dependencias en makefiles (Versión ROOT)

SINOPSIS

rmkdepend [ -Dnombre=def ] [ -Dnombre ] [ -Idirincl ] [ -Ydirincl ] [ -a ] [ -fmakefile ] [ -osufijoobj ] [ -pprefijobj ] [ -scadena ] [ -wancho ] [ -v ] [ -m ] [ -- otrasopciones -- ] archivocódigo [ -tnombrearchivoobjetivo ] ...

DESCRIPCIÓN

El programa rmkdepend lee cada archivocódigo en secuencia y lo analiza como un preprocesador de C, procesando todas las directivas #include, #define, #undef, #ifdef, #ifndef, #endif, #if, #elif y #else para poder determinar correctamente qué directivas #include se usarían en una compilación. Cualquier directiva #include puede referenciar archivos que tengan otras directivas #include , y el análisis ocurrirá también en estos archivos.

Cada archivo que un archivocódigo incluye, directa o indirectamente, es lo que rmkdepend llama una dependencia. Estas dependencias se escriben luego en un makefile de tal manera que make(1) sepa qué archivos objeto deben recompilarse cuando una dependencia ha cambiado.

Por defecto, rmkdepend coloca su salida en el archivo llamado makefile si existe, de lo contrario en Makefile. Se puede especificar un makefile alternativo con la opción -f. Primero busca en el makefile la línea


# DO NOT DELETE THIS LINE -- make depend depends on it.

o una proporcionada con la opción -s, como delimitador para la salida de dependencias. Si la encuentra, eliminará todo lo que siga a esta línea hasta el final del makefile y colocará la salida después de esta línea. Si no la encuentra, el programa añadirá la cadena al final del makefile y colocará la salida después de ella. Para cada archivocódigo que aparece en la línea de comandos, rmkdepend pone líneas en el makefile de la forma


archivocódigo.o: archivorep ...

Donde archivocódigo.o es el nombre de la línea de comandos con su sufijo reemplazado por ``.o'', y archivorep es una dependencia descubierta en una directiva #include al analizar archivocódigo o uno de los archivos que incluyó.

NOTA

La aplicación rmkdepend se basa en makedepend(1) del Consorcio X, pero modificada ligeramente para adaptarse a las necesidades del sistema ROOT. Esta página de man(1) es más o menos idéntica a la página de manual de makedepend(1), excepto por este aviso y las secciones VER TAMBIÉN y AUTORES.

EJEMPLO

Normalmente, rmkdepend se usaría en un objetivo de makefile para que escribir ``make depend'' actualice las dependencias del makefile. Por ejemplo,

    SRCS = archivo1.c archivo2.c ...
    CFLAGS = -O -DHACK -I../foobar -xyz
    depend:
            rmkdepend -- $(CFLAGS) -- $(SRCS)

OPCIONES

El programa ignorará cualquier opción que no entienda para que puedas usar los mismos argumentos que usarías para cc(1).

-Dnombre=def o -Dnombre
Definir. Esto coloca una definición para nombre en la tabla de símbolos de rmkdepend. Sin =def el símbolo se define como ``1''.
-Idirincl
Directorio de inclusión. Esta opción le dice a rmkdepend que añada dirincl al principio de su lista de directorios a buscar cuando encuentre una directiva #include . Por defecto, rmkdepend solo busca en los directorios de inclusión estándar (normalmente /usr/include y posiblemente un directorio dependiente del compilador).
-Ydirincl
Reemplaza todos los directorios de inclusión estándar con el único directorio de inclusión especificado; puedes omitir dirincl para simplemente evitar buscar en los directorios de inclusión estándar.
-a
Añade las dependencias al final del archivo en lugar de reemplazarlas.
-fmakefile
Nombre de archivo. Esto te permite especificar un makefile alternativo en el cual rmkdepend puede colocar su salida. Especificar ``-'' como nombre de archivo (es decir, -f-) envía la salida a la salida estándar en lugar de modificar un archivo existente.
-osufijoobj
Sufijo de archivo objeto. Algunos sistemas pueden tener archivos objeto con un sufijo diferente de ``.o''. Esta opción te permite especificar otro sufijo, como ``.b'' con -o.b o ``:obj'' con -o:obj y así sucesivamente.
-pprefijobj
Prefijo de archivo objeto. El prefijo se antepone al nombre del archivo objeto. Esto se usa generalmente para designar un directorio diferente para el archivo objeto. El valor predeterminado es la cadena vacía.
-scadena
Cadena delimitadora de inicio. Esta opción te permite especificar una cadena diferente para que rmkdepend la busque en el makefile.
-wancho
Ancho de línea. Normalmente, rmkdepend se asegurará de que cada línea de salida que escriba no supere los 78 caracteres de ancho por motivos de legibilidad. Esta opción te permite cambiar este ancho.
-v
Operación detallada. Esta opción hace que rmkdepend emita la lista de archivos incluidos por cada archivo de entrada en la salida estándar.
-m
Advertir sobre inclusiones múltiples. Esta opción hace que rmkdepend produzca una advertencia si algún archivo de entrada incluye otro archivo más de una vez. En versiones anteriores de rmkdepend este era el comportamiento predeterminado; el predeterminado ha sido cambiado para que coincida mejor con el comportamiento del compilador C, que no considera la inclusión múltiple como un error. Esta opción se proporciona por compatibilidad retroactiva y para ayudar a depurar problemas relacionados con la inclusión múltiple.
-- opciones --
Si rmkdepend encuentra un doble guion (--) en la lista de argumentos, entonces cualquier argumento no reconocido que siga a este será ignorado silenciosamente; un segundo doble guion termina este tratamiento especial. De esta manera, rmkdepend puede ser configurado para ignorar de forma segura argumentos esotéricos del compilador que normalmente se encontrarían en una macro make CFLAGS (ver la sección EJEMPLO arriba). Todas las opciones que rmkdepend reconoce y que aparecen entre el par de dobles guiones se procesan normalmente.
-tnombrearchivoobjetivo
Nombre de archivo. Esto te permite especificar un nombre de archivo objetivo alternativo que se usará para el archivo anterior. Por ejemplo, si llamas


rmkdepend -sobj -pbuild archivo.cxx -tbiblioteca.so

en lugar de insertar la línea


build/archivo.obj: ...

rmkdepend insertará:


biblioteca.so: ...

ALGORITMO

El enfoque utilizado en este programa le permite ejecutarse una orden de magnitud más rápido que cualquier otro "generador de dependencias" que haya visto. Fundamental para este rendimiento son dos suposiciones: que todos los archivos compilados por un solo makefile se compilarán con opciones -I y -D aproximadamente iguales; y que la mayoría de los archivos en un solo directorio incluirán archivos en gran medida iguales.

Dadas estas suposiciones, rmkdepend espera ser llamado una vez por makefile, con todos los archivos fuente que son mantenidos por el makefile apareciendo en la línea de comandos. Analiza cada archivo fuente y de inclusión exactamente una vez, manteniendo una tabla de símbolos interna para cada uno. Por lo tanto, el primer archivo en la línea de comandos tomará una cantidad de tiempo proporcional a la cantidad de tiempo que toma un preprocesador C normal. Pero

rmkdepend(1) — Arch manual pages

NAME

rmkdepend

generates dependency files for C/C++ source files

SYNOPSIS

rmkdepend [-a] [-c] [-D path] [-f file] [-I path] [-k] [-o] [-p] [-P] [-R] [-s string] [-u] [-v] [-w width] [--] [files …]

DESCRIPTION

rmkdepend is a utility that examines C and C++ source files and generates dependency files that can be used by make.

The dependency files generated contain rules for compiling the source files into object files. For example, if you have a file named file.c, the dependency file generated will look something like:


file.o: file.c header1.h header2.h ...

This means that if file.c or any of the header files change, then file.o will need to be recompiled.

NOTE

This utility is part of the ROOT C++ framework.

EXAMPLE

To generate dependency files for all the C++ files in the current directory, you can use the following command:


rmkdepend *.cxx

This will create dependency files named like file.o for each file.cxx in the current directory. These dependency files can be included in your make file.

OPTIONS

-a
Append dependencies to existing dependency files instead of overwriting them.
-c
Create C style dependency files (e.g., file.o: file.c) instead of C++ style (e.g., file.o: file.cxx).
-D path
Add path to the list of directories where header files are searched.
-f file
Write the generated dependencies to file instead of standard output.
-I path
Same as -D path.
-k
Continue processing files even if an error occurs.
-o
Generate dependencies for object files (e.g., file.o) instead of source files (e.g., file.cxx).
-p
Print the names of the header files that are parsed.
-P
Do not parse system header files (e.g., those in /usr/include).
-R
Remove duplicates from the list of dependencies.
-s string
Prepend string to the generated dependency rules.
-u
Do not include the source file itself in the list of dependencies.
-v
Enable verbose output.
-w width
Set the maximum width of the generated dependency lines to width.
--
Process the remaining arguments as filenames, even if they start with a hyphen.

ALGORITHM

rmkdepend parses each C/C++ source file specified on the command line. For each file, it scans the source code for #include directives. When it encounters an #include directive, it recursively parses the included header file. To avoid redundant parsing and to optimize the process, rmkdepend maintains a cache of parsed header files. If it encounters an include file that it has already parsed, it does not parse it again.

For example, imagine you are compiling two files, file1.c and file2.c, they each include the header file header.h, and the file header.h in turn includes the files def1.h and def2.h. When you run the command


rmkdepend file1.c file2.c

rmkdepend will parse file1.c and consequently, header.h and then def1.h and def2.h. It then decides that the dependencies for this file are


file1.o: header.h def1.h def2.h

But when the program parses file2.c and discovers that it, too, includes header.h, it does not parse the file, but simply adds header.h, def1.h and def2.h to the list of dependencies for file2.o.

SEE ALSO

cc(1), make(1), root(1), root-cint(1)

See also the ROOT webpages: http://root.cern

BUGS

rmkdepend parses, but does not currently evaluate, the SVR4 #predicate(token-list) preprocessor expression; such expressions are simply assumed to be true. This may cause the wrong #include directives to be evaluated.

Imagine you are parsing two files, say file1.c and file2.c, each includes the file def.h. The list of files that def.h includes might truly be different when def.h is included by file1.c than when it is included by file2.c. But once rmkdepend arrives at a list of dependencies for a file, it is cast in concrete.
