rfcomm(7) Linux System Administration rfcomm(7)

Name

rfcomm - Protocolo RFCOMM

SYNOPSIS

#include <sys/socket.h>
#include <bluetooth/bluetooth.h>
#include <bluetooth/rfcomm.h>
rfcomm_socket = socket(PF_BLUETOOTH, SOCK_STREAM, BTPROTO_RFCOMM);

DESCRIPTION

El protocolo RFCOMM proporciona emulación de puertos serie sobre el protocolo L2CAP(7). El protocolo se basa en el estándar ETSI TS 07.10.

RFCOMM es un protocolo de transporte simple, con disposiciones adicionales para emular los 9 circuitos de los puertos serie RS-232 (EIATIA-232-E).

DIRECCIÓN DEL SOCKET

struct sockaddr_rc {
    sa_family_t rc_family;
    unsigned short rc_bdaddr;
    unsigned char rc_channel;
};

Ejemplo:

struct sockaddr_rc addr;
memset(&addr, 0, sizeof(addr));
addr.rc_family = AF_BLUETOOTH;
bacpy(&addr.rc_bdaddr, bdaddr);
addr.rc_channel = channel;

OPCIONES DEL SOCKET

Las siguientes opciones del socket se pueden establecer usando setsockopt(2) y leer con getsockopt(2) con el nivel de socket establecido en SOL_BLUETOOTH.

BT_SECURITY (desde Linux 2.6.30)

Nivel de seguridad del canal, valores posibles:

Valor Nivel de Seguridad Tipo de Clave de Enlace Cifrado
BT_SECURITY_SDP 0 (Solo SDP) Ninguno No requerido
BT_SECURITY_LOW 1 (Bajo) No autenticado No requerido
BT_SECURITY_MEDIUM 2 (Medio - predeterminado) No autenticado Deseado
BT_SECURITY_HIGH 3 (Alto) Autenticado Requerido
BT_SECURITY_FIPS (desde Linux 3.15) 4 (Solo Seguro) Autenticado (Emparejamiento Simple Seguro basado en P-256 y Autenticación Segura) Requerido

Ejemplo:

int level = BT_SECURITY_HIGH;
int err = setsockopt(rfcomm_socket, SOL_BLUETOOTH, BT_SECURITY, &level,
                     sizeof(level));
if (err == -1) {
    perror("setsockopt");
    return 1;
}

BT_DEFER_SETUP (desde Linux 2.6.30)

Configuración de conexión diferida del canal, esto controla si el procedimiento de conexión necesita ser autorizado por el espacio de usuario antes de responder, lo que permite la autorización a nivel de perfil, valores posibles:

Valor Descripción Autorización
0 Desactivar (predeterminado) No requerido
1 Activar Requerido

Ejemplo:

int defer_setup = 1;
int err = setsockopt(rfcomm_socket, SOL_BLUETOOTH, BT_DEFER_SETUP,
                     &defer_setup, sizeof(defer_setup));
if (err == -1) {
    perror("setsockopt");
    return err;
}
err = listen(rfcomm_socket, 5);
if (err) {
    perror("listen");
    return err;
}
struct sockaddr_rc remote_addr = {0};
socklen_t addr_len = sizeof(remote_addr);
int new_socket = accept(rfcomm_socket, (struct sockaddr*)&remote_addr,
                        &addr_len);
if (new_socket < 0) {
    perror("accept");
    return new_socket;
}
/* Para completar la configuración de la conexión de new_socket, lee 1 byte */
char c;
struct pollfd pfd;
memset(&pfd, 0, sizeof(pfd));
pfd.fd = new_socket;
pfd.events = POLLOUT;
err = poll(&pfd, 1, 0);
if (err) {
    perror("poll");
    return err;
}
if (!(pfd.revents & POLLOUT)) {
    err = read(sk, &c, 1);
    if (err < 0) {
        perror("read");
        return err;
    }
}

BT_FLUSHABLE (desde Linux 2.6.39)

Bandera de canal desechable, esto controla si los datos del canal pueden ser desechados o no, valores posibles:

Definición Valor Descripción
BT_FLUSHABLE_OFF 0x00 (predeterminado) No desechar datos
BT_FLUSHABLE_ON 0x01 Desechar datos

BT_CHANNEL_POLICY (desde Linux 3.10)

Política de canal de alta velocidad (AMP), valores posibles:

Definición Valor Descripción
BT_CHANNEL_POLICY_BREDR_ONLY 0 (predeterminado) Solo BR/EDR
BT_CHANNEL_POLICY_BREDR_PREFERRED 1 BR/EDR Preferido
BT_CHANNEL_POLICY_BREDR_PREFERRED 2 AMP Preferido

BT_PHY (desde Linux 5.10)

PHY(s) admitidos en el canal, valores posibles:

Definición Valor Descripción
BT_PHY_BR_1M_1SLOT BIT 0 BR 1Mbps 1SLOT
BT_PHY_BR_1M_3SLOT BIT 1 BR 1Mbps 3SLOT
BT_PHY_BR_1M_5SLOT BIT 2 BR 1Mbps 5SLOT
BT_PHY_BR_2M_1SLOT BIT 3 EDR 2Mbps 1SLOT
BT_PHY_BR_2M_3SLOT BIT 4 EDR 2Mbps 3S

SOCKET OPTIONS

The Bluetooth sockets support the following socket options.

Option Level Description
BT_OPTIONS SOL_BLUETOOTH For enabling or disabling socket specific options.
BT_SECURITY SOL_BLUETOOTH Set the security level for outgoing connections.
BT_BINDADDR SOL_BLUETOOTH Used to bind to a specific local Bluetooth device address.
BT_COMM_MODE SOL_BLUETOOTH Set the communication mode for RFCOMM sockets.
BT_AMP_HCIDEV SOL_BLUETOOTH Set the HCI device for AMP sockets.
BT_AMP_RADIO SOL_BLUETOOTH Set the radio type for AMP sockets.
BT_POWER SOL_BLUETOOTH Set the transmit power for L2CAP sockets.

The BT_SECURITY socket option takes an integer value representing the security level. The possible values are:

0
No security requirements.
1
Authentication required.
2
Encryption required.
3
Authentication and encryption required.

The BT_BINDADDR socket option takes a struct sockaddr_rc structure with the local Bluetooth device address to bind to.

The BT_COMM_MODE socket option takes an integer value representing the communication mode. The possible values are:

0
Serial port emulation.
1
Direct data transfer.

The BT_AMP_HCIDEV socket option takes an integer value representing the HCI device to use for AMP sockets.

The BT_AMP_RADIO socket option takes an integer value representing the radio type for AMP sockets. The possible values are:

0
Dual-mode radio.
1
AMP-only radio.

The BT_POWER socket option takes an integer value representing the transmit power for L2CAP sockets.

NOTES

The Bluetooth socket API is only available when the kernel has been compiled with the Bluetooth subsystem enabled.

The Bluetooth socket API is a relatively new addition to the Linux kernel, and as such, it may be subject to change in future versions.

The BT_OPTIONS socket option is used to control various aspects of the Bluetooth socket behavior. The available options are bitmasks and can be combined.

The BT_SECURITY socket option is used to control the security level of Bluetooth connections. Higher security levels require more authentication and encryption, which may impact performance.

The BT_BINDADDR socket option is used to bind a socket to a specific local Bluetooth device address. This is useful when a machine has multiple Bluetooth adapters.

The BT_COMM_MODE socket option is used to set the communication mode for RFCOMM sockets. The default mode is serial port emulation.

The BT_AMP_HCIDEV and BT_AMP_RADIO socket options are used to configure AMP sockets.

The BT_POWER socket option is used to set the transmit power for L2CAP sockets.

EXAMPLES

The following example shows how to create a Bluetooth socket and bind it to a specific address:

#include <sys/socket.h>
#include <bluetooth/bluetooth.h>
#include <bluetooth/rfcomm.h>

int main() {
    struct sockaddr_rc addr = { 0 };
    int s, status;
    int opt = BT_SECURITY;
    int val = 3;

    // allocate socket
    s = socket(AF_BLUETOOTH, SOCK_STREAM, BTPROTO_RFCOMM);

    // bind socket to port 1 on the first available
    // local bluetooth adapter
    addr.rc_family = AF_BLUETOOTH;
    addr.rc_channel = (uint8_t) 1;
    str2ba( "00:00:00:00:00:00", &addr.rc_bdaddr );

    status = bind(s, (struct sockaddr *)&addr, sizeof(addr));

    // Set security level to authentication and encryption
    setsockopt(s, SOL_BLUETOOTH, opt, &val, sizeof(val));

    // ... rest of the code
    return 0;
}

The following example shows how to set the PHY for a Bluetooth socket:

#include <sys/socket.h>
#include <bluetooth/bluetooth.h>

int main() {
    int s, status;
    int opt = BT_OPTIONS;
    int val = BT_PHY_LE_2M | BT_PHY_LE_CODED;

    // allocate socket
    s = socket(AF_BLUETOOTH, SOCK_RAW, 0);

    // Set PHY to 2Mbps and Coded PHY for LE connections
    status = setsockopt(s, SOL_BLUETOOTH, opt, &val, sizeof(val));

    // ... rest of the code
    return 0;
}

DIAGNOSTICS

The socket functions return the standard UNIX error codes.

HISTORY

The Bluetooth socket API was first introduced in Linux kernel version 2.4.x.

The BT_OPTIONS, BT_SECURITY, BT_BINDADDR, BT_COMM_MODE, BT_AMP_HCIDEV, BT_AMP_RADIO and BT_POWER socket options were added in later versions.

The BT_PHY_ options were added in Linux kernel 5.4.

The BT_LINK_POLICY_ and BT_LINK_MODE_ options were added in Linux kernel 5.5.

The BT_RFCOMM_OPTIONS_ options were added in Linux kernel 5.6.

AVAILABILITY

These socket options are available on Linux systems with the BlueZ stack installed.
