DESCRIPCIÓN

La función rcmd() es utilizada por el superusuario para ejecutar un comando en una máquina remota utilizando un esquema de autenticación basado en números de puerto privilegiados. La función rresvport() devuelve un descriptor de archivo a un socket con una dirección en el espacio de puertos privilegiados. Las funciones iruserok() y ruserok() son utilizadas por los servidores para autenticar clientes que solicitan servicio con rcmd(). Las cuatro funciones son utilizadas por el servidor rshd(8) (entre otros).

rcmd()

La función rcmd() busca el host *ahost usando gethostbyname(3), devolviendo -1 si el host no existe. De lo contrario, *ahost se establece en el nombre estándar del host y se establece una conexión a un servidor ubicado en el puerto de Internet de conocido nombre inport.

Si la conexión tiene éxito, se devuelve un socket en el dominio de Internet de tipo SOCK_STREAM al llamador, y se proporciona al comando remoto como stdin y stdout. Si fd2p no es cero, entonces se configurará un canal auxiliar a un proceso de control, y se colocará un descriptor de archivo para él en *fd2p. El proceso de control devolverá la salida de diagnóstico del comando (unidad 2) en este canal, y también aceptará bytes en este canal como números de señal de UNIX, que se reenviarán al grupo de procesos del comando. Si fd2p es 0, entonces el stderr (unidad 2 del comando remoto) se hará igual que el stdout y no se harán provisiones para enviar señales arbitrarias al proceso remoto, aunque puede ser capaz de llamar su atención utilizando datos fuera de banda.

El protocolo se describe en detalle en rshd(8).

rresvport()

La función rresvport() se utiliza para obtener un socket con un puerto privilegiado asociado. Este socket es adecuado para su uso por rcmd() y varias otras funciones. Los puertos privilegiados son aquellos en el rango de 0 a 1023. Solo un proceso privilegiado (en Linux, un proceso que tiene la capacidad CAP_NET_BIND_SERVICE en el espacio de nombres del usuario que rige su espacio de nombres de red) puede vincularse a un puerto privilegiado. En la implementación de glibc, esta función restringe su búsqueda a los puertos de 512 a 1023. El argumento port es valor-resultado: el valor que proporciona a la llamada se utiliza como punto de partida para una búsqueda circular del rango de puertos; en la devolución (exitosa), contiene el número de puerto al que se vinculó.

iruserok() y ruserok()

Las funciones iruserok() y ruserok() toman la dirección IP o el nombre, respectivamente, de un host remoto, dos nombres de usuario y una bandera que indica si el nombre del usuario local es el del superusuario. Luego, si el usuario no es el superusuario, verifica el archivo /etc/hosts.equiv. Si esa búsqueda no se realiza o no tiene éxito, se verifica el .rhosts en el directorio principal del usuario local para ver si se permite la solicitud de servicio.

Si este archivo no existe, no es un archivo regular, pertenece a alguien que no sea el usuario o el superusuario, es escribible por alguien que no sea el propietario, o está enlazado rígidamente en algún lugar, la verificación falla automáticamente. Se devuelve cero si el nombre de la máquina está listado en el archivo hosts.equiv, o si el host y el nombre de usuario remoto se encuentran en el archivo .rhosts; de lo contrario, iruserok() y ruserok() devuelven -1. Si el dominio local (tal como se obtiene de gethostname(2)) es el mismo que el dominio remoto, solo es necesario especificar el nombre de la máquina.

Si se conoce la dirección IP del host remoto, se debe usar iruserok() en lugar de ruserok(), ya que no requiere confiar en el servidor DNS para el dominio del host remoto.

Variantes *_af()

Todas las funciones descritas anteriormente funcionan con sockets IPv4 (AF_INET). Las variantes "_af" toman un argumento adicional que permite especificar la familia de direcciones del socket. Para estas funciones, el argumento af se puede especificar como AF_INET o AF_INET6. Además, rcmd_af() admite el uso de AF_UNSPEC.

VALOR DE RETORNO

La función rcmd() devuelve un descriptor de socket válido en caso de éxito. Devuelve -1 en caso de error e imprime un mensaje diagnóstico en el error estándar.

La función rresvport() devuelve un descriptor de socket válido y enlazado en caso de éxito. En caso de fallo, devuelve -1 y establece errno para indicar el error. El código de error EAGAIN se usa indebidamente para significar: "Todos los puertos de red en uso".

Para obtener información sobre el retorno de ruserok() e iruserok(), consulte arriba.

SYNOPSIS

#include <sys/socket.h>

int ruserok_af(const char *rhost, int superuser, const char *un, int af);

DESCRIPTION

These functions are used to check if a remote user is authorized to log in. They are part of the traditional rlogin protocol and are rarely used directly by applications today.

The ruserok() function checks if the user named by the string un on the remote host rhost is allowed to log in. The superuser parameter should be non-zero if the login is being made by the superuser. This allows the superuser to log in from any host.

The ruserok_af() function is similar to ruserok() but takes an additional address family parameter af. This allows specifying the address family (e.g., AF_INET or AF_INET6) for the remote host.

These functions consult the .rhosts file (or equivalent) on the remote host to determine authorization.

RETURN VALUE

These functions return 1 on success and 0 on failure.

STANDARDS

These functions are specific to BSD-derived systems and are not part of any standard. Their use is discouraged in favor of more secure authentication mechanisms.
