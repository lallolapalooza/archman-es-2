rcmd(3) Manual de Funciones de Biblioteca rcmd(3)

NOMBRE

rcmd, rresvport, iruserok, ruserok, rcmd_af, rresvport_af, iruserok_af, ruserok_af - rutinas para devolver un flujo a un comando remoto

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <netdb.h>    /* O <unistd.h> en algunos sistemas */
int rcmd(char **restrict ahost, unsigned short inport,
            const char *restrict locuser,
            const char *restrict remuser,
            const char *restrict cmd, int *restrict fd2p);
int rresvport(int *port);
int iruserok(uint32_t raddr, int superuser,
            const char *ruser, const char *luser);
int ruserok(const char *rhost, int superuser,
            const char *ruser, const char *luser);
int rcmd_af(char **restrict ahost, unsigned short inport,
            const char *restrict locuser,
            const char *restrict remuser,
            const char *restrict cmd, int *restrict fd2p,
            sa_family_t af);
int rresvport_af(int *port, sa_family_t af);
int iruserok_af(const void *restrict raddr, int superuser,
            const char *restrict ruser, const char *restrict luser,
            sa_family_t af);
int ruserok_af(const char *rhost, int superuser,
            const char *ruser, const char *luser,
            sa_family_t af);

DESCRIPCIÓN

La función rcmd() es utilizada por el superusuario para ejecutar un comando en una máquina remota usando un esquema de autenticación basado en números de puerto privilegiados. La función rresvport() devuelve un descriptor de archivo a un socket con una dirección en el espacio de puertos privilegiados. Las funciones iruserok() y ruserok() son utilizadas por los servidores para autenticar clientes que solicitan servicio con rcmd(). Las cuatro funciones son utilizadas por el servidor rshd(8) (entre otros).

rcmd()

La función rcmd() busca el host *ahost usando gethostbyname(3), devolviendo -1 si el host no existe. De lo contrario, *ahost se establece en el nombre estándar del host y se establece una conexión a un servidor que reside en el puerto de Internet bien conocido inport.

Si la conexión tiene éxito, se devuelve un socket en el dominio de Internet de tipo SOCK_STREAM al llamador, y se proporciona al comando remoto como stdin y stdout. Si fd2p no es cero, entonces se establecerá un canal auxiliar a un proceso de control, y se colocará un descriptor de archivo para él en *fd2p. El proceso de control devolverá la salida de diagnóstico del comando (unidad 2) en este canal, y también aceptará bytes en este canal como números de señal de UNIX, que se enviarán al grupo de procesos del comando. Si fd2p es 0, entonces el stderr (unidad 2 del comando remoto) se hará igual que el stdout y no se harán provisiones para enviar señales arbitrarias al proceso remoto, aunque es posible que pueda llamar su atención utilizando datos fuera de banda.

El protocolo se describe en detalle en rshd(8).

rresvport()

La función rresvport() se utiliza para obtener un socket con un puerto privilegiado enlazado a él. Este socket es adecuado para su uso por rcmd() y varias otras funciones. Los puertos privilegiados son los del rango 0 a 1023. Solo un proceso privilegiado (en Linux, un proceso que tiene la capacidad CAP_NET_BIND_SERVICE en el espacio de nombres de usuario que gobierna su espacio de nombres de red) tiene permitido enlazarse a un puerto privilegiado. En la implementación de glibc, esta función restringe su búsqueda a los puertos del 512 al 1023. El argumento port es valor-resultado: el valor que proporciona a la llamada se utiliza como punto de partida para una búsqueda circular en el rango de puertos; en la devolución (exitosa), contendrá el número de puerto que se enlazó.

iruserok() y ruserok()

Las funciones iruserok() y ruserok() toman la dirección IP o el nombre del host remoto, respectivamente, dos nombres de usuario y una bandera que indica si el nombre del usuario local es el del superusuario. Luego, si el usuario *no* es el superusuario, comprueba el archivo /etc/hosts.equiv. Si esa búsqueda no se realiza, o no tiene éxito, se comprueba el archivo .rhosts en el directorio principal del usuario local para ver si se permite la solicitud de servicio.

Si este archivo no existe, no es un archivo regular, es propiedad de alguien que no sea el usuario o el superusuario, es escribible por cualquier persona que no sea el propietario, o tiene enlaces duros en cualquier lugar, la comprobación falla automáticamente. Se devuelve cero si el nombre de la máquina está listado en el archivo hosts.equiv, o si el host y el nombre de usuario remoto se encuentran en el archivo .rhosts; de lo contrario, iruserok() y ruserok() devuelven -1. Si el dominio local (obtenido de gethostname(2)) es el mismo que el dominio remoto, solo es necesario especificar el nombre de la máquina.

Si se conoce la dirección IP del host remoto, se debe preferir iruserok() sobre ruserok(), ya que no requiere confiar en el servidor DNS para el dominio del host remoto.

Variantes *_af()

Todas las funciones descritas anteriormente funcionan con sockets IPv4 (AF_INET). Las variantes "_af" toman un argumento adicional que permite especificar la familia de direcciones del socket. Para estas funciones, el argumento af se puede especificar como AF_INET o AF_INET6. Además, rcmd_af() admite el uso de AF_UNSPEC.

VALOR DE RETORNO

La función rcmd() devuelve un descriptor de socket válido en caso de éxito. Devuelve -1 en caso de error e imprime un mensaje diagnóstico en la salida de error estándar.

La función rresvport() devuelve un descriptor de socket válido y enlazado en caso de éxito. En caso de fallo, devuelve -1 y establece errno para indicar el error. El código de error EAGAIN se sobrecarga para significar: "Todos los puertos de red en uso".

Para obtener información sobre el retorno de ruserok() e iruserok(), consulte arriba.
