NOMBRE

rcs - cambiar atributos de archivos RCS

SINOPSIS

rcs opciones archivo...

DESCRIPCIÓN

rcs crea nuevos archivos RCS o cambia los atributos de los existentes. Un archivo RCS contiene múltiples revisiones de texto, una lista de acceso, un registro de cambios, texto descriptivo y algunos atributos de control. Para que rcs funcione, el nombre de inicio de sesión del llamante debe estar en la lista de acceso, excepto si la lista de acceso está vacía, el llamante es el propietario del archivo o el superusuario, o está presente la opción -i.

Los nombres de archivo que coinciden con un sufijo RCS denotan archivos RCS; todos los demás denotan archivos de trabajo. Los nombres se emparejan como se explica en ci(1). Los números de revisión utilizan la sintaxis descrita en ci(1).

OPCIONES

-i
Crea e inicializa un nuevo archivo RCS, pero no deposita ninguna revisión. Si el nombre del archivo RCS no tiene componente de directorio, intente colocarlo primero en el subdirectorio ./RCS y luego en el directorio actual. Si el archivo RCS ya existe, imprime un mensaje de error.
-anombresdeinicio
Añade los nombres de inicio de sesión que aparecen en la lista separada por comas nombresdeinicio a la lista de acceso del archivo RCS.
-Aarchivoantiguo
Añade la lista de acceso de archivoantiguo a la lista de acceso del archivo RCS.
-e[nombresdeinicio]
Borra los nombres de inicio de sesión que aparecen en la lista separada por comas nombresdeinicio de la lista de acceso del archivo RCS. Si se omite nombresdeinicio, borra toda la lista de acceso.
-b[rev]
Establece la rama predeterminada a rev. Si se omite rev, la rama predeterminada se restablece a la rama (dinámicamente) más alta en el tronco.
-ccadena
Establece el líder de comentario a cadena. Un ci inicial, o un rcs -i sin -c, adivina el líder de comentario a partir del sufijo del nombre del archivo de trabajo.

Esta opción es obsoleta, ya que RCS normalmente utiliza el prefijo de la línea $Log$ anterior al insertar líneas de registro durante la extracción (ver co(1)). Sin embargo, las versiones anteriores de RCS utilizan el líder de comentario en lugar del prefijo de la línea $Log$, por lo que si planea acceder a un archivo con versiones antiguas y nuevas de RCS, asegúrese de que su líder de comentario coincida con su prefijo de línea $Log$.

-ksust
Establece la sustitución de palabras clave predeterminada a sust. El efecto de la sustitución de palabras clave se describe en co(1). Proporcionar una opción explícita -k a co, rcsdiff y rcsmerge anula este valor predeterminado. Tenga cuidado con rcs -kv, ya que -kv es incompatible con co -l. Utilice rcs -kkv para restaurar la sustitución de palabras clave predeterminada normal.
-l[rev]
Bloquea la revisión con el número rev. Si se proporciona una rama, bloquea la última revisión en esa rama. Si se omite rev, bloquea la última revisión en la rama predeterminada. El bloqueo evita cambios superpuestos. Si otra persona ya tiene el bloqueo, el bloqueo se rompe como con rcs -u (ver más abajo).
-u[rev]
Desbloquea la revisión con el número rev. Si se proporciona una rama, desbloquea la última revisión en esa rama. Si se omite rev, elimina el último bloqueo en posesión del llamante. Normalmente, solo el bloqueador de una revisión puede desbloquearla. El desbloqueo por parte de otra persona rompe el bloqueo. Si RCS se configuró con --with-mailer, se enviará un mensaje de correo electrónico al bloqueador original. El mensaje contiene un comentario solicitado al rompedor. El comentario se termina con fin de archivo o con una línea que contiene . por sí sola.
-L
Establece el bloqueo a estricto. El bloqueo estricto significa que el propietario de un archivo RCS no está exento de bloqueo para la entrega. Esta opción debe usarse para archivos que se comparten.
-U
Establece el bloqueo a no estricto. El bloqueo no estricto significa que el propietario de un archivo no necesita bloquear una revisión para la entrega. Esta opción no debe usarse para archivos que se comparten. Si el bloqueo predeterminado es estricto o no lo es, lo determina su administrador del sistema, pero normalmente es estricto.
-mrev:[msg]
Reemplaza el mensaje de registro de la revisión rev con msg. Si se omite msg, se usa por defecto "*** mensaje de registro vacío ***".
-M
No envíe correo al romper el bloqueo de otra persona. Esta opción no está pensada para uso casual; está pensada para programas que advierten a los usuarios por otros medios e invocan rcs -u solo como una operación de bajo nivel para romper bloqueos.
-nnombre[:[rev]]
Asocia el nombre simbólico nombre con la rama o revisión rev. Elimina el nombre simbólico si tanto : como rev se omiten; de lo contrario, imprime un mensaje de error si nombre ya está asociado con otro número. Si rev es simbólico, se expande antes de la asociación. Una rev que consiste en un número de rama seguido de un punto . representa la revisión más reciente actual en la rama. Un : con una rev vacía representa la revisión más reciente actual en la rama predeterminada, normalmente el tronco. Por ejemplo, rcs -nnombre: RCS/* asocia nombre con la revisión más reciente actual de todos los archivos RCS nombrados; esto contrasta con rcs -nnombre:$ RCS/* que asocia nombre con los números de revisión extraídos de las cadenas de palabras clave en los archivos de trabajo correspondientes.
-Nnombre[:[rev]]
Actúa como -n, excepto que anula cualquier asignación previa de nombre.
-orango
elimina (“descarta”) las revisiones dadas por rango. Un rango que consiste en un solo número de revisión se refiere a esa revisión. Un rango que consiste en un número de rama se refiere a la revisión más reciente en esa rama. Un rango de la forma rev1:rev2 se refiere a las revisiones rev1 a rev2 en la misma rama, :rev se refiere desde el principio de la rama que contiene rev hasta incluir rev, y rev: se refiere desde la revisión rev hasta el final de la rama que contiene rev. Ninguna de las revisiones descartadas puede tener ramas o bloqueos.
-q
Ejecutar silenciosamente; no imprimir diagnósticos.
-I
Ejecutar interactivamente, incluso si la entrada estándar no es una terminal.
-sestado[:rev]
Establece el atributo de estado de la revisión rev a estado. Si rev es un número de rama, asume la revisión más reciente en esa rama. Si se omite rev, asume la revisión más reciente en la rama predeterminada. Cualquier identificador es aceptable para estado. Un conjunto útil de estados es Exp (para experimental), Stab (para estable) y Rel (para liberado). Por defecto, ci(1) establece el estado de una revisión a Exp.
-t[archivo]
Escribe texto descriptivo del contenido del archivo nombrado en el archivo RCS, eliminando el texto existente. El nombre del archivo no puede comenzar con -. Si se omite archivo, obtén el texto de la entrada estándar, terminado por fin de archivo o por una línea que contenga . por sí sola. Solicita el texto si es posible la interacción; ver -I. Con -i, se obtiene texto descriptivo incluso si no se proporciona -t.
-t-cadena
Escribe texto descriptivo de la cadena en el archivo RCS, eliminando el texto existente.

NAME

rcs — maintain a version control system

SYNOPSIS

rcs [-i] [-h] [-tfile] [-e] [-u] [-a] [-M] [-q] [-V[n]] [-xsuffixes] [-zzone] file ...

DESCRIPTION

The rcs command maintains the consistency of a collection of source code files.

The default behavior of rcs is to transform the given files into revision control files by inserting tags and other RCS meta-information. If the -i option is used, rcs will install a new revision control file for each of the given files, initialized with the contents of the corresponding file. Then, the corresponding file is renamed with the extension `,v'.

The revision control files contain the difference between the original version and the current version. The difference is stored in the delta-compressed format.

Normally, rcs locks the file it is working on to prevent concurrent edits. You may override this behavior with the -u option. If a file is already locked, rcs will not process it.

If a file is not locked, rcs will lock it with the effective user as the owner. This lock is advisory and may be broken by any user.

The user is prompted for a description of the changes, and for each revision, a new revision control file is created. The old revision control file is kept for history and future reference.

The RCS file will be created in the same directory as the working file.

OPTIONS

-a
Insert the revision control file's corresponding working file into the revision control file. This option is intended for use with the -i option, and may be used only with the -i option.
-e
Enable the use of symbolic names. This option is ignored unless the revision control file already exists.
-h
Generate a check-in compatible with the make utility. This option is ignored unless the revision control file already exists.
-i
Install a new revision control file for each of the given files, initialized with the contents of the corresponding file. Then, the corresponding file is renamed with the extension `,v'.
-M
Use the make mode for checking out files. This option is ignored unless the revision control file already exists.
-q
Quiet mode. Suppress the diagnostic messages.
-tfile
Use file as the descriptive text for the revision control file. If file is omitted, the descriptive text is taken from the standard input.
-u
Unlock the file. This option is intended for use with the -i option, and may be used only with the -i option.
-ksubst
Determine the keyword substitution mode. The default is -kk. See ci(1) for details.
-V
Print RCS's version number.
-Vn
Emulate RCS version n. See co(1) for details.
-xsuffixes
Use suffixes to characterize RCS files. See ci(1) for details.
-zzone
Use zone as the default time zone. This option has no effect; it is present for compatibility with other RCS commands.

The -k option is used to specify the keyword expansion mode. The default is -kkv. Use this option with care; it can suppress recompilation even when it is needed, i.e. when a change to the RCS file would mean a change to keyword strings in the working file. The default behavior is to follow the dependency of some copy of the working file on the RCS file. Use this option with care; it can suppress recompilation even when it is needed, i.e. when a change to the RCS file would mean a change to keyword strings in the working file.

At least one explicit option must be given, to ensure compatibility with future planned extensions to the rcs command.

COMPATIBILITY

The -brev option generates an RCS file that cannot be parsed by RCS version 3 or earlier.

The -ksubst options (except -kkv) generate an RCS file that cannot be parsed by RCS version 4 or earlier.

Use rcs -Vn to make an RCS file acceptable to RCS version n by discarding information that would confuse version n.

RCS version 5.5 and earlier does not support the -x option, and requires a ,v suffix on an RCS file name.

FILES

rcs accesses files much as ci(1) does, except that it uses the effective user for all accesses, it does not write the working file or its directory, and it does not even read the working file unless a revision number of $ is specified.

ENVIRONMENT

RCSINIT
Options prepended to the argument list, separated by spaces. A backslash escapes spaces within an option. The RCSINIT options are prepended to the argument lists of most RCS commands. Useful RCSINIT options include -q, -V, -x, and -z.
RCS_MEM_LIMIT
Normally, for speed, commands either memory map or copy into memory the RCS file if its size is less than the memory-limit, currently defaulting to ``unlimited''. Otherwise (or if the initially-tried speedy ways fail), the commands fall back to using standard i/o routines. You can adjust the memory limit by setting RCS_MEM_LIMIT to a numeric value lim (measured in kilobytes). An empty value is silently ignored. As a side effect, specifying RCS_MEM_LIMIT inhibits fall-back to slower routines.
TMPDIR
Name of the temporary directory. If not set, the environment variables TMP and TEMP are inspected instead and the first value found is taken; if none of them are set, a host-dependent default is used, typically /tmp.

DIAGNOSTICS

The RCS file name and the revisions outdated are written to the diagnostic output. The exit status is zero if and only if all operations were successful.

BUGS

A catastrophe (e.g. a system crash) can cause RCS to leave behind a semaphore file that causes later invocations of RCS to claim that the RCS file is in use. To fix this, remove the semaphore file. A semaphore file's name typically begins with , or ends with _.

The separator for revision ranges in the -o option used to be - instead of :, but this leads to confusion when symbolic names contain -. For backwards compatibility rcs -o still supports the old - separator, but it warns about this obsolete use.

Symbolic names need not refer to existing revisions or branches. For example, the -o option does not remove symbolic names for the outdated revisions; you must use -n to remove the names.
