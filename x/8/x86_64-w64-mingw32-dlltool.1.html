DLLTOOL(1) Herramientas de Desarrollo GNU DLLTOOL(1)

NOMBRE

dlltool - crear archivos necesarios para construir y usar DLLs

SINOPSIS

dlltool [-d|--input-def nombre-archivo-def]
[-b|--base-file nombre-archivo-base]
[-e|--output-exp nombre-archivo-exportaciones]
[-z|--output-def nombre-archivo-def]
[-l|--output-lib nombre-archivo-libreria]
[-y|--output-delaylib nombre-archivo-libreria-retardo]
[--export-all-symbols] [--no-export-all-symbols]
[--exclude-symbols lista]
[--no-default-excludes]
[-S|--as ruta-al-ensamblador] [-f|--as-flags opciones]
[-D|--dllname nombre] [-m|--machine maquina]
[-a|--add-indirect]
[-U|--add-underscore] [--add-stdcall-underscore]
[-k|--kill-at] [-A|--add-stdcall-alias]
[-p|--ext-prefix-alias prefijo]
[-x|--no-idata4] [-c|--no-idata5]
[--use-nul-prefixed-import-tables]
[-I|--identify nombre-archivo-libreria] [--identify-strict]
[-i|--interwork]
[-n|--nodelete] [-t|--temp-prefix prefijo]
[-v|--verbose]
[-h|--help] [-V|--version]
[--no-leading-underscore] [--leading-underscore]
[--deterministic-libraries] [--non-deterministic-libraries]
[archivos-objeto ...]

DESCRIPCIÓN

dlltool lee sus entradas, que pueden provenir de las opciones -d y -b, así como de archivos objeto especificados en la línea de comandos. Luego procesa estas entradas y, si se ha especificado la opción -e, crea un archivo de exportaciones. Si se ha especificado la opción -l, crea un archivo de librería y si se ha especificado la opción -z, crea un archivo def. Cualquiera o todas las opciones -e, -l y -z pueden estar presentes en una invocación de dlltool.

Al crear una DLL, junto con el código fuente de la DLL, es necesario tener tres archivos adicionales. dlltool puede ayudar en la creación de estos archivos.

El primer archivo es un archivo .def que especifica qué funciones se exportan desde la DLL, qué funciones importa la DLL, etc. Este es un archivo de texto y puede crearse manualmente, o se puede usar dlltool para crearlo usando la opción -z. En este caso, dlltool escaneará los archivos objeto especificados en su línea de comandos en busca de aquellas funciones que hayan sido marcadas especialmente como exportadas y pondrá entradas para ellas en el archivo .def que crea.

Para marcar una función como exportada desde una DLL, necesita tener una entrada -export:<nombre_de_la_funcion> en la sección .drectve del archivo objeto. Esto se puede hacer en C usando el operador asm():

asm (".section .drectve");
asm (".ascii \"-export:my_func\"");

int my_func (void) { ... }

El segundo archivo necesario para la creación de DLL es un archivo de exportaciones. Este archivo se enlaza con los archivos objeto que componen el cuerpo de la DLL y maneja la interfaz entre la DLL y el mundo exterior. Este es un archivo binario y puede crearse proporcionando la opción -e a dlltool al crear o leer un archivo .def.

El tercer archivo necesario para la creación de DLL es el archivo de librería con el que los programas se enlazarán para acceder a las funciones de la DLL (una `librería de importación'). Este archivo puede crearse proporcionando la opción -l a dlltool al crear o leer un archivo .def.

Si se especifica la opción -y, dlltool genera una librería de importación retardada que se puede utilizar en lugar de la librería de importación normal para permitir que un programa se enlace con la dll solo tan pronto como se llame a una función importada por primera vez. El ejecutable resultante necesitará enlazarse con la librería estática delayimp que contiene __delayLoadHelper2(), la cual a su vez importará LoadLibraryA y GetProcAddress de kernel32.

dlltool construye el archivo de librería manualmente, pero construye el archivo de exportaciones creando archivos temporales que contienen instrucciones de ensamblador y luego ensamblándolos. La opción de línea de comandos -S se puede usar para especificar la ruta al ensamblador que usará dlltool, y la opción -f se puede usar para pasar opciones específicas a ese ensamblador. La opción -n se puede usar para evitar que dlltool elimine estos archivos temporales de ensamblador cuando haya terminado, y si se especifica -n dos veces, esto evitará que dlltool elimine los archivos objeto temporales que usó para construir la librería.

Aquí hay un ejemplo de creación de una DLL desde un archivo fuente dll.c y también de creación de un programa (desde un archivo objeto llamado program.o) que utiliza esa DLL:

gcc -c dll.c
dlltool -e exports.o -l dll.lib dll.o
gcc dll.o exports.o -o dll.dll
gcc program.o dll.lib -o program

dlltool también puede usarse para consultar una librería de importación existente para determinar el nombre de la DLL a la que está asociada. Vea la descripción de la opción -I o --identify.

OPCIONES

Las opciones de la línea de comandos tienen los siguientes significados:

-d nombre-archivo
--input-def nombre-archivo
Especifica el nombre de un archivo .def a ser leído y procesado.
-b nombre-archivo
--base-file nombre-archivo
Especifica el nombre de un archivo base a ser leído y procesado. El contenido de este archivo se agregará a la sección de reubicación en el archivo de exportaciones generado por dlltool.
-e nombre-archivo
--output-exp nombre-archivo
Especifica el nombre del archivo de exportaciones a ser creado por dlltool.
-z nombre-archivo
--output-def nombre-archivo
Especifica el nombre del archivo .def a ser creado por dlltool.
-l nombre-archivo
--output-lib nombre-archivo
Especifica el nombre del archivo de librería a ser creado por dlltool.
-y nombre-archivo
--output-delaylib nombre-archivo
Especifica el nombre del archivo de librería de importación retardada a ser creado por dlltool.
--deterministic-libraries
--non-deterministic-libraries
Al crear librerías de salida en respuesta a las opciones --output-lib o --output-delaylib, ya sea usa el valor cero para cualquier marca de tiempo, ID de usuario y ID de grupo creados (--deterministic-libraries) o las marcas de tiempo, ID de usuario e ID de grupo reales (--non-deterministic-libraries).
--export-all-symbols
Trata todos los símbolos globales y débiles definidos encontrados en los archivos objeto de entrada como símbolos a ser exportados. Hay una pequeña lista de símbolos que no se exportan por defecto; véase la opción --no-default-excludes. Puede agregar a la lista de símbolos a no exportar usando la opción --exclude-symbols.
--no-export-all-symbols
Exporta solo los símbolos listados explícitamente en un archivo .def de entrada o en las secciones .drectve en los archivos objeto de entrada. Este es el comportamiento por defecto. Las secciones .drectve son creadas por los atributos dllexport en el código fuente.
--exclude-symbols lista
No exporte los símbolos en lista. Esta es una lista de nombres de símbolos separados por comas o dos puntos. Los nombres de símbolos no deberían contener un guion bajo inicial. Esto solo es significativo cuando se usa --export-all-symbols.
--no-default-excludes
Por defecto, ciertos símbolos (como `__main', `_pei386_runtime_relocator', etc.) no se exportan. Usar esta opción desactiva esa lista de exclusiones por defecto, por lo que estos símbolos también se exportarán si se usa --export-all-symbols.
-S ruta-al-ensamblador
--as ruta-al-ensamblador
Especifica la ruta completa al ensamblador que será utilizado por dlltool.
-f opciones
--as-flags opciones
Especifica las opciones que se pasarán al ensamblador.
-D nombre
--dllname nombre
Especifica el nombre de la DLL. Esto se usa cuando se está creando un archivo de exportación y la DLL aún no existe. El nombre de la DLL se incluirá en el archivo de exportación.
-m maquina
--machine maquina
Especifica el tipo de máquina para la que se está creando la DLL. Las máquinas válidas son `i386', `i486', `i586', `i686', `amd64', `ia64', `sparc', etc. El valor por defecto es `i386'.
-a
--add-indirect
Agrega una entrada de importación indirecta para cada función exportada. Esto asegura que si la DLL se llama a sí misma, estas llamadas usen la tabla de importación.
-U
--add-underscore
Agrega un guion bajo al principio de los nombres de símbolos. Esto es necesario para la compatibilidad con la convención de nombres de C de muchas compilaciones de C.
--add-stdcall-underscore
Agrega un guion bajo al principio de los nombres de símbolos que usan la convención de llamada stdcall. Esto es necesario para la compatibilidad con las DLLs de Windows que exportan funciones con nombres como `_FunctionName@N'.
-k
--kill-at
Elimina los sufijos de tamaño de pila (`@N') de los nombres de símbolos stdcall. Esto es útil cuando se está creando una librería de importación para una DLL que exporta funciones stdcall y el compilador espera que el nombre no tenga el sufijo `@N'.
-A
--add-stdcall-alias
Agrega un alias de alias stdcall para cada función exportada. Esto es necesario para la compatibilidad con las DLLs de Windows que exportan funciones con nombres como `FunctionName@N' y también como `_FunctionName@N'.
-p prefijo
--ext-prefix-alias prefijo
Agrega un prefijo al nombre de cada símbolo exportado. Esto es útil cuando se está creando una librería de importación para una DLL que tiene símbolos exportados con un prefijo específico, como `_'.
-x
--no-idata4
No incluya la tabla de importación de `idata4'. Esto puede ser necesario para la compatibilidad con versiones antiguas de Windows.
-c
--no-idata5
No incluya la tabla de importación de `idata5'. Esto puede ser necesario para la compatibilidad con versiones antiguas de Windows.
--use-nul-prefixed-import-tables
Utiliza tablas de importación prefijadas con NUL para las importaciones. Esto puede ser necesario para la compatibilidad con algunas DLLs antiguas de Windows.
-I nombre-archivo-libreria
--identify nombre-archivo-libreria
Identifica el nombre de la DLL a la que está asociada la librería de importación dada. Imprime el nombre de la DLL a la salida estándar y sale.
--identify-strict
Igual que --identify, pero falla si la librería de importación no contiene información de identificación.
-i
--interwork
Habilita el modo interworking para ARM. Esto es necesario cuando se está creando una librería de importación para una DLL que se ejecutará en un entorno ARM que mezcla código de 16 y 32 bits.
-n
--nodelete
No elimine los archivos temporales creados por dlltool durante su ejecución. Esto puede ser útil para depurar.
-t prefijo
--temp-prefix prefijo
Especifica un prefijo para los nombres de los archivos temporales creados por dlltool. El prefijo por defecto es `dlltool-'.
-v
--verbose
Imprime información detallada sobre las acciones de dlltool. Esto puede ser útil para depurar.
-h
--help
Muestra un mensaje de ayuda y sale.
-V
--version
Muestra información de la versión y sale.
--no-leading-underscore
No agregue un guion bajo al principio de los nombres de símbolos. Este es el comportamiento por defecto para la mayoría de las arquitecturas.
--leading-underscore
Agregue un guion bajo al principio de los nombres de símbolos. Esto es necesario para la compatibilidad con la convención de nombres de C de muchas compilaciones de C.

VER TAMBIÉN

ld(1), gcc(1)

OPTIONS

--no-default-excludes
Cuando se usa --export-all-symbols, por defecto evitará exportar ciertos símbolos especiales. La lista actual de símbolos a evitar exportar es DllMain@12, DllEntryPoint@0, impure_ptr. Puede usar la opción --no-default-excludes para exportar estos símbolos especiales. Esto solo tiene sentido cuando se usa --export-all-symbols.
-S ruta
--as ruta
Especifica la ruta, incluido el nombre del archivo, del ensamblador a utilizar para crear el archivo de exportaciones.
-f opciones
--as-flags opciones
Especifica cualquier opción de línea de comandos que se pasará al ensamblador al compilar el archivo de exportaciones. Esta opción funcionará incluso si la opción -S no se utiliza. Esta opción solo toma un argumento, y si aparece más de una vez en la línea de comandos, las ocurrencias posteriores anularán a las anteriores. Por lo tanto, si es necesario pasar múltiples opciones al ensamblador, deben encerrarse entre comillas dobles.
-D nombre
--dll-name nombre
Especifica el nombre que se almacenará en el archivo .def como el nombre de la DLL cuando se utilice la opción -e. Si esta opción no está presente, el nombre del archivo proporcionado a la opción -e se utilizará como el nombre de la DLL.
-m máquina
-machine máquina
Especifica el tipo de máquina para la que se debe compilar el archivo de biblioteca. dlltool tiene un tipo predeterminado incorporado, dependiendo de cómo se creó, pero esta opción puede usarse para anularlo. Esto normalmente solo es útil al crear DLL para un procesador ARM, cuando el contenido de la DLL está codificado utilizando instrucciones Thumb.
-a
--add-indirect
Especifica que cuando dlltool esté creando el archivo de exportaciones, debe agregar una sección que permita que las funciones exportadas se referencien sin usar la biblioteca de importación. ¡Lo que sea que eso signifique!
-U
--add-underscore
Especifica que cuando dlltool esté creando el archivo de exportaciones, debe anteponer un guion bajo a los nombres de todos los símbolos exportados.
--no-leading-underscore
--leading-underscore
Especifica si los símbolos estándar deben prefijarse o no.
--add-stdcall-underscore
Especifica que cuando dlltool esté creando el archivo de exportaciones, debe anteponer un guion bajo a los nombres de las funciones stdcall exportadas. Los nombres de variables y las funciones que no sean stdcall no se modifican. Esta opción es útil al crear bibliotecas de importación compatibles con GNU para DLL de terceros que se compilaron con herramientas de MS-Windows.
-k
--kill-at
Especifica que los sufijos @<número> se omitan de los nombres de las funciones stdcall que se importarán de la DLL. Esto es útil al crear una biblioteca de importación para una DLL que exporta funciones stdcall pero sin el sufijo de nombre de símbolo @<número> habitual.

Esto no cambia el nombre de los símbolos proporcionados por la biblioteca de importación a los programas enlazados contra ella, sino solo las entradas en la tabla de importación (es decir, la sección .idata).

-A
--add-stdcall-alias
Especifica que cuando dlltool esté creando el archivo de exportaciones, debe agregar alias para símbolos stdcall sin @ <número> además de los símbolos con @ <número>.
-p
--ext-prefix-alias prefijo
Hace que dlltool cree alias externos para todas las importaciones de DLL con el prefijo especificado. Los alias se crean tanto para símbolos externos como de importación sin guion bajo inicial.
-x
--no-idata4
Especifica que cuando dlltool esté creando los archivos de exportación y biblioteca, debe omitir la sección ".idata4". Esto es para compatibilidad con ciertos sistemas operativos.
--use-nul-prefixed-import-tables
Especifica que cuando dlltool esté creando los archivos de exportación y biblioteca, debe prefijar la sección ".idata4" y ".idata5" con un elemento cero. Esto emula la generación antigua de bibliotecas de importación de GNU de "dlltool". Por defecto, esta opción está desactivada.
-c
--no-idata5
Especifica que cuando dlltool esté creando los archivos de exportación y biblioteca, debe omitir la sección ".idata5". Esto es para compatibilidad con ciertos sistemas operativos.
-I nombrearchivo
--identify nombrearchivo
Especifica que dlltool debe inspeccionar la biblioteca de importación indicada por nombrearchivo y reportar, en "stdout", el nombre o nombres de las DLL asociadas. Esto se puede realizar además de cualquier otra operación indicada por las otras opciones y argumentos. dlltool falla si la biblioteca de importación no existe o no es realmente una biblioteca de importación. Ver también --identify-strict.
--identify-strict
Modifica el comportamiento de la opción --identify, de modo que se reporte un error si nombrearchivo está asociado con más de una DLL.
-i
--interwork
Especifica que dlltool debe marcar los objetos en el archivo de biblioteca y el archivo de exportaciones que produce como compatibles con la interconexión entre código ARM y Thumb.
-n
--nodelete
Hace que dlltool preserve los archivos ensambladores temporales que utilizó para crear el archivo de exportaciones. Si esta opción se repite, dlltool también conservará los archivos objeto temporales que utiliza para crear el archivo de biblioteca.
-t prefijo
--temp-prefix prefijo
Hace que dlltool utilice prefijo al construir los nombres de los archivos ensamblador y objeto temporales. Por defecto, el prefijo del archivo temporal se genera a partir del PID.
-v
--verbose
Hace que dlltool describa lo que está haciendo.
-h
--help
Muestra una lista de opciones de línea de comandos y luego sale.
-V
--version
Muestra el número de versión de dlltool y luego sale.
@archivo
Lee las opciones de la línea de comandos desde archivo. Las opciones leídas se insertan en lugar de la opción original @archivo. Si archivo no existe o no se puede leer, la opción se tratará literalmente y no se eliminará.

Las opciones en archivo están separadas por espacios en blanco. Se puede incluir un carácter de espacio en blanco en una opción encerrando la opción completa entre comillas simples o dobles. Se puede incluir cualquier carácter (incluido una barra invertida) anteponiendo el carácter a incluir con una barra invertida. El archivo puede contener opciones adicionales @archivo; dichas opciones se procesarán recursivamente.
