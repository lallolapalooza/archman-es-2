LD(1) Herramientas de desarrollo de GNU LD(1)

NOMBRE

ld - El enlazador de GNU

SINOPSIS

ld [opciones] archivo_objeto ...

DESCRIPCIÓN

ld combina una serie de archivos objeto y de biblioteca, relocaliza sus datos y resuelve las referencias de símbolos. Normalmente, el último paso en la compilación de un programa es ejecutar ld.

ld acepta archivos de lenguaje de comandos de enlazador escritos en un superconjunto de la sintaxis del Lenguaje de Comandos del Editor de Enlace de AT&T, para proporcionar control explícito y total sobre el proceso de enlazado.

Esta página del manual no describe el lenguaje de comandos; consulte la entrada ld en "info" para obtener detalles completos sobre el lenguaje de comandos y sobre otros aspectos del enlazador de GNU.

Esta versión de ld utiliza las bibliotecas BFD de propósito general para operar con archivos objeto. Esto permite a ld leer, combinar y escribir archivos objeto en muchos formatos diferentes; por ejemplo, COFF o "a.out". Diferentes formatos pueden ser enlazados juntos para producir cualquier tipo de archivo objeto disponible.

Aparte de su flexibilidad, el enlazador de GNU es más útil que otros enlazadores al proporcionar información diagnóstica. Muchos enlazadores abandonan la ejecución inmediatamente al encontrar un error; siempre que sea posible, ld continúa la ejecución, permitiéndole identificar otros errores (o, en algunos casos, obtener un archivo de salida a pesar del error).

El enlazador de GNU ld está destinado a cubrir una amplia gama de situaciones y a ser lo más compatible posible con otros enlazadores. Como resultado, tiene muchas opciones para controlar su comportamiento.

OPCIONES

El enlazador soporta una gran cantidad de opciones de línea de comandos, pero en la práctica pocas se utilizan en un contexto particular. Por ejemplo, un uso frecuente de ld es enlazar archivos objeto estándar de Unix en un sistema Unix estándar y compatible. En un sistema así, para enlazar un archivo "hello.o":

ld -o <salida> /lib/crt0.o hello.o -lc

Esto le indica a ld que produzca un archivo llamado salida como resultado del enlazado del archivo "/lib/crt0.o" con "hello.o" y la biblioteca "libc.a", que provendrá de los directorios de búsqueda estándar. (Vea la discusión de la opción -l a continuación.)

Algunas de las opciones de línea de comandos para ld pueden ser especificadas en cualquier punto de la línea de comandos. Sin embargo, las opciones que se refieren a archivos, como -l o -T, hacen que el archivo sea leído en el punto en que la opción aparece en la línea de comandos, en relación con los archivos objeto y otras opciones de archivo. Repetir opciones no relacionadas con archivos con un argumento diferente no tendrá ningún efecto adicional, o anulará ocurrencias previas (las más a la izquierda en la línea de comandos) de esa opción. Las opciones que pueden ser significativamente especificadas más de una vez se anotan en las descripciones a continuación.

Los argumentos que no son opciones son archivos objeto o bibliotecas que se van a enlazar juntos. Pueden seguir, preceder o mezclarse con las opciones de línea de comandos, excepto que un argumento de archivo objeto no puede colocarse entre una opción y su argumento.

Normalmente, el enlazador se invoca con al menos un archivo objeto, pero puede especificar otras formas de archivos de entrada binarios usando -l, -R y el lenguaje de comandos de script. Si no se especifican archivos de entrada binarios en absoluto, el enlazador no produce ninguna salida y emite el mensaje No hay archivos de entrada.

Si el enlazador no puede reconocer el formato de un archivo objeto, asumirá que es un script de enlazador. Un script especificado de esta manera complementa el script de enlazador principal utilizado para el enlace (ya sea el script de enlazador predeterminado o el especificado usando -T). Esta característica permite al enlazador enlazar contra un archivo que parece ser un objeto o una biblioteca, pero que en realidad simplemente define algunos valores de símbolos, o utiliza "INPUT" o "GROUP" para cargar otros objetos. Especificar un script de esta manera simplemente complementa el script de enlazador principal, con los comandos adicionales colocados después del script principal; use la opción -T para reemplazar completamente el script de enlazador predeterminado, pero tenga en cuenta el efecto del comando "INSERT".

Para opciones cuyos nombres son una sola letra, los argumentos de la opción deben seguir la letra de la opción sin espacios intermedios, o ser dados como argumentos separados inmediatamente después de la opción que los requiere.

Para opciones cuyos nombres son múltiples letras, un guion o dos pueden preceder al nombre de la opción; por ejemplo, -trace-symbol y --trace-symbol son equivalentes. Nota: hay una excepción a esta regla. Las opciones de múltiples letras que comienzan con una 'o' minúscula solo pueden ir precedidas por dos guiones. Esto es para reducir la confusión con la opción -o. Así, por ejemplo, -omagic establece el nombre del archivo de salida a magic, mientras que --omagic establece la bandera NMAGIC en la salida.

Los argumentos para opciones de múltiples letras deben estar separados del nombre de la opción por un signo igual, o ser dados como argumentos separados inmediatamente después de la opción que los requiere. Por ejemplo, --trace-symbol foo y --trace-symbol=foo son equivalentes. Se aceptan abreviaturas únicas de los nombres de las opciones de múltiples letras.

Nota: si el enlazador se invoca indirectamente, a través de un controlador de compilador (por ejemplo, gcc), entonces todas las opciones de línea de comandos del enlazador deben ir precedidas por -Wl, (o lo que sea apropiado para el controlador de compilador en particular) de esta manera:

gcc -Wl,--start-group foo.o bar.o -Wl,--end-group

Esto es importante, porque de lo contrario el programa controlador de compilador puede omitir silenciosamente las opciones del enlazador, resultando en un enlace incorrecto. También puede surgir confusión al pasar opciones que requieren valores a través de un controlador, ya que el uso de un espacio entre la opción y el argumento actúa como un separador, y hace que el controlador pase solo la opción al enlazador y el argumento al compilador. En este caso, es más sencillo usar las formas unidas de opciones de una sola letra y de múltiples letras, como:

gcc foo.o bar.o -Wl,-eENTRY -Wl,-Map=a.map

Aquí hay una tabla de los interruptores genéricos de línea de comandos aceptados por el enlazador de GNU:

@archivo
Lee las opciones de línea de comandos desde archivo. Las opciones leídas se insertan en lugar de la opción @archivo original. Si archivo no existe, o no se puede leer, entonces la opción se tratará literalmente, y no se eliminará.

Las opciones en archivo están separadas por espacios en blanco. Se puede incluir un carácter de espacio en blanco en una opción rodeando toda la opción entre comillas simples o dobles. Se puede incluir cualquier carácter (incluido una barra invertida) anteponiendo el carácter a incluir con una barra invertida. El archivo puede contener opciones adicionales @archivo; dichas opciones se procesarán recursivamente.

-a palabra_clave
Esta opción es compatible con HP/UX. El argumento palabra_clave debe ser una de las cadenas archive, shared o default. -aarchive es funcionalmente equivalente a -Bstatic, y las otras dos palabras clave son funcionalmente equivalentes a -Bdynamic. Esta opción se puede usar cualquier número de veces.
--audit AUDITLIB
Añade AUDITLIB a la entrada "DT_AUDIT" de la sección dinámica. AUDITLIB no se comprueba si existe, ni usará el DT_SONAME especificado en la biblioteca. Si se especifica varias veces, "DT_AUDIT" contendrá una lista separada por dos puntos de interfaces de auditoría a usar. Si el enlazador encuentra un objeto con una entrada de auditoría mientras busca bibliotecas compartidas, añadirá una entrada "DT_DEPAUDIT" correspondiente en el archivo de salida. Esta opción solo es significativa en plataformas ELF que soporten la interfaz rtld-audit.
-b formato_entrada
--format=formato_entrada
ld puede configurarse para soportar más de un tipo de archivo objeto. Si su ld está configurado de esta manera, puede usar la opción -b para especificar el formato binario para los archivos objeto que siguen a esta opción en la línea de comandos. Incluso cuando ld está configurado para soportar formatos de objeto alternativos, normalmente no necesita especificarlo, ya que ld debería estar configurado para ex
tado como formato de entrada predeterminado el formato más común en cada máquina. input-format es una cadena de texto, el nombre de un formato particular compatible con las bibliotecas BFD. (Puedes listar los formatos binarios disponibles con objdump -i).

Puede que desees usar esta opción si estás enlazando archivos con un formato binario inusual. También puedes usar -b para cambiar de formato explícitamente (al enlazar archivos objeto de diferentes formatos), incluyendo -b input-format antes de cada grupo de archivos objeto en un formato particular.

El formato predeterminado se toma de la variable de entorno "GNUTARGET".

También puedes definir el formato de entrada desde un script, usando el comando "TARGET";

-c archivo-de-comandos-mri
--mri-script=archivo-de-comandos-mri
Para compatibilidad con enlazadores producidos por MRI, ld acepta archivos de script escritos en un lenguaje de comandos alternativo y restringido, descrito en la sección "Archivos de Script Compatibles con MRI" de la documentación de GNU ld. Introduce los archivos de script MRI con la opción -c; usa la opción -T para ejecutar scripts de enlazador escritos en el lenguaje de scripting de propósito general de ld. Si archivo-de-comandos-mri no existe, ld lo busca en los directorios especificados por cualquier opción -L.
-d
-dc
-dp
Estas tres opciones son equivalentes; se admiten múltiples formas para compatibilidad con otros enlazadores. Asignan espacio a los símbolos comunes incluso si se especifica un archivo de salida relocalizable (con -r). El comando de script "FORCE_COMMON_ALLOCATION" tiene el mismo efecto.
--depaudit AUDITLIB
-P AUDITLIB
Añade AUDITLIB a la entrada "DT_DEPAUDIT" de la sección dinámica. AUDITLIB no se verifica su existencia, ni utilizará el DT_SONAME especificado en la biblioteca. Si se especifica varias veces, "DT_DEPAUDIT" contendrá una lista separada por dos puntos de interfaces de auditoría a utilizar. Esta opción solo es significativa en plataformas ELF que admiten la interfaz rtld-audit. La opción -P se proporciona para compatibilidad con Solaris.
--enable-linker-version
Habilita la directiva de script del enlazador "LINKER_VERSION", descrita en Datos de Sección de Salida. Si se usa esta directiva en un script de enlazador y se ha habilitado esta opción, se insertará una cadena que contiene la versión del enlazador en el punto actual.

Nota: la ubicación de esta opción en la línea de comandos del enlazador es significativa. Solo afectará a los scripts de enlazador que vienen después de ella en la línea de comandos, o que están integrados en el enlazador.

--disable-linker-version
Inhabilita la directiva de script del enlazador "LINKER_VERSION", de modo que no inserte una cadena de versión. Este es el comportamiento predeterminado.
--enable-non-contiguous-regions
Esta opción evita generar un error si una sección de entrada no encaja en una sección de salida coincidente. El enlazador intenta asignar la sección de entrada a secciones de salida coincidentes posteriores, y solo genera un error si ninguna sección de salida es lo suficientemente grande. Esto es útil cuando hay varias regiones de memoria no contiguas disponibles y la sección de entrada no requiere una en particular. El orden en que se evalúan las secciones de entrada no cambia, por ejemplo: 
MEMORY {
  MEM1 (rwx) : ORIGIN = 0x1000, LENGTH = 0x14
  MEM2 (rwx) : ORIGIN = 0x1000, LENGTH = 0x40
  MEM3 (rwx) : ORIGIN = 0x2000, LENGTH = 0x40
}
SECTIONS {
  mem1 : { *(.data.*); } > MEM1
  mem2 : { *(.data.*); } > MEM2
  mem3 : { *(.data.*); } > MEM3
}

con secciones de entrada:
.data.1: tamaño 8
.data.2: tamaño 0x10
.data.3: tamaño 4

resulta en .data.1 asignado a mem1, y .data.2 y .data.3
asignados a mem2, aunque .data.3 cabría en mem3.

Esta opción es incompatible con las sentencias INSERT porque cambia la forma en que las secciones de entrada se mapean a las secciones de salida.

--enable-non-contiguous-regions-warnings
Esta opción habilita advertencias cuando "--enable-non-contiguous-regions" permite coincidencias posiblemente inesperadas en el mapeo de secciones, lo que podría llevar a descartar silenciosamente una sección en lugar de fallar porque no encaja en ninguna región de salida.
-e entrada
--entry=entrada
Usa entrada como el símbolo explícito para comenzar la ejecución de tu programa, en lugar del punto de entrada predeterminado. Si no hay un símbolo llamado entrada, el enlazador intentará analizar entrada como un número, y lo usará como la dirección de entrada (el número se interpretará en base 10; puedes usar un prefijo 0x para base 16, o un prefijo 0 para base 8). Para i386 PE, entrada puede ser también el nombre original de la función (sin el guion bajo inicial y/o el sufijo stdcall @número cuando sea aplicable).
--exclude-libs lib,lib,...
Especifica una lista de bibliotecas de archivo de las cuales los símbolos no deben exportarse automáticamente. Los nombres de biblioteca pueden estar delimitados por comas o dos puntos. Especificar "--exclude-libs ALL" excluye los símbolos de todas las bibliotecas de archivo de la exportación automática. Esta opción solo está disponible para el puerto i386 PE del enlazador y para puertos dirigidos a ELF. Para i386 PE, los símbolos listados explícitamente en un archivo .def todavía se exportan, independientemente de esta opción. Para puertos dirigidos a ELF, los símbolos afectados por esta opción se tratarán como ocultos.
--exclude-modules-for-implib modulo,modulo,...
Especifica una lista de archivos objeto o miembros de archivo, de los cuales los símbolos no deben exportarse automáticamente, pero que deben copiarse enteros a la biblioteca de importación que se está generando durante el enlace. Los nombres de módulo pueden estar delimitados por comas o dos puntos, y deben coincidir exactamente con los nombres de archivo utilizados por ld para abrir los archivos; para miembros de archivo, este es simplemente el nombre del miembro, pero para archivos objeto, el nombre listado debe incluir y coincidir exactamente con cualquier ruta utilizada para especificar el archivo de entrada en la línea de comandos del enlazador. Esta opción solo está disponible para el puerto i386 PE del enlazador. Los símbolos listados explícitamente en un archivo .def todavía se exportan, independientemente de esta opción.
-E
--export-dynamic
--no-export-dynamic
Al crear un ejecutable enlazado dinámicamente, usar la opción -E o la opción --export-dynamic hace que el enlazador añada todos los símbolos a la tabla de símbolos dinámicos. La tabla de símbolos dinámicos es el conjunto de símbolos que son visibles desde objetos dinámicos en tiempo de ejecución.

Si no usas ninguna de estas opciones (o usas la opción --no-export-dynamic para restaurar el comportamiento predeterminado), la tabla de símbolos dinámicos normalmente contendrá solo aquellos símbolos que son referenciados por algún objeto dinámico mencionado en el enlace.

Si usas "dlopen" para cargar un objeto dinámico que necesita referirse a los símbolos definidos por el programa, en lugar de algún otro objeto dinámico, entonces probablemente necesitarás usar esta opción al enlazar el programa mismo.

También puedes usar la lista dinámica para controlar qué símbolos deben añadirse a la tabla de símbolos dinámicos si el formato de salida lo soporta. Ver la descripción de --dynamic-list.

Ten en cuenta que esta opción es específica para puertos dirigidos a ELF. Los destinos PE admiten una función similar para exportar todos los símbolos de una DLL o EXE; ver la descripción de --export-all-symbols a continuación.

--export-dynamic-symbol=glob
Al crear un ejecutable enlazado dinámicamente, los símbolos que coincidan con glob se añadirán a la tabla de símbolos dinámicos. Al crear una biblioteca compartida, las referencias a símbolos que coincidan con glob no se enlazarán con las definiciones dentro de la biblioteca compartida. Esta opción no tiene efecto al crear una biblioteca compartida y no se especifican -Bsymbolic o --dynamic-list. Esta opción solo es significativa en plataformas ELF que soportan bibliotecas compartidas.
--export-dynamic-symbol-list=archivo
Especifica un --export-dynamic-symbol por cada patrón en el archivo. El formato del archivo es el mismo que el nodo de versión sin ámbito ni nombre de nodo. Ver VERSION para más información.
-EB
Enlaza objetos big-endian. Esto afecta al formato de salida predeterminado.
-EL
Enlaza objetos little-endian. Esto afecta al formato de salida predeterminado.
-f nombre
--auxiliary=nombre
Al crear un objeto compartido ELF, establece el campo interno DT_AUXILIARY al nombre especificado. Esto le dice al enlazador dinámico que la tabla de símbolos del objeto compartido debe usarse como un filtro auxiliar en la tabla de símbolos del objeto compartido nombre.

Si posteriormente enlazas un programa contra este objeto filtro, entonces, cuando ejecutes el programa, el enlazador dinámico verá el campo DT_AUXILIARY. Si el enlazador dinámico resuelve algún símbolo del objeto filtro, primero verificará si hay una definición en el objeto compartido nombre. Si la hay, se usará en lugar de la definición en el objeto filtro. El objeto compartido nombre no necesita existir. Así, el objeto compartido nombre puede usarse para proporcionar una implementación alternativa de ciertas funciones, quizás para depuración o para optimización específica de la máquina.

-i
Realiza un enlace incremental (igual que la opción -r).
-init=nombre
Al crear un ejecutable o un objeto compartido ELF, llama a NOMBRE cuando el ejecutable o el objeto compartido se carga, estableciendo DT_INIT a la dirección de la función. Por defecto, el enlazador utiliza "_init" como función a llamar.
-l espec_nombre
--library=espec_nombre
Añade el archivo de biblioteca o objeto especificado por espec_nombre a la lista de archivos a enlazar. Esta opción se puede utilizar un número ilimitado de veces. Si espec_nombre tiene la forma :nombre_archivo, ld buscará en la ruta de bibliotecas un archivo llamado nombre_archivo, de lo contrario buscará en la ruta de bibliotecas un archivo llamado libespec_nombre.a.

En sistemas que admiten bibliotecas compartidas, ld también puede buscar archivos distintos de libespec_nombre.a. Específicamente, en sistemas ELF y SunOS, ld buscará en un directorio una biblioteca llamada libespec_nombre.so antes de buscar una llamada libespec_nombre.a. (Por convención, una extensión ".so" indica una biblioteca compartida). Tenga en cuenta que este comportamiento no se aplica a :nombre_archivo, que siempre especifica un archivo llamado nombre_archivo.

El enlazador buscará en un archivo solo una vez, en la ubicación en que se especifica en la línea de comandos. Si el archivo define un símbolo que no estaba definido en algún objeto que apareció antes que el archivo en la línea de comandos, el enlazador incluirá los archivos apropiados del archivo. Sin embargo, un símbolo indefinido en un objeto que aparece más tarde en la línea de comandos no hará que el enlazador busque de nuevo en el archivo.

Vea la opción -( para conocer una forma de forzar al enlazador a buscar archivos varias veces.

Puede listar el mismo archivo varias veces en la línea de comandos.

Este tipo de búsqueda de archivos es estándar para los enlazadores Unix. Sin embargo, si está utilizando ld en AIX, tenga en cuenta que es diferente del comportamiento del enlazador de AIX.

-L dir_busqueda
--library-path=dir_busqueda
Añade la ruta dir_busqueda a la lista de rutas que ld buscará para las bibliotecas de archivos y los scripts de control de ld. Puede utilizar esta opción un número ilimitado de veces. Los directorios se buscan en el orden en que se especifican en la línea de comandos. Los directorios especificados en la línea de comandos se buscan antes que los directorios por defecto. Todas las opciones -L se aplican a todas las opciones -l, independientemente del orden en que aparezcan las opciones. Las opciones -L no afectan a cómo ld busca un script de enlazador a menos que se especifique la opción -T.

Si dir_busqueda comienza con "=" o $SYSROOT, entonces este prefijo será reemplazado por el prefijo sysroot, controlado por la opción --sysroot, o especificado cuando se configura el enlazador.

El conjunto por defecto de rutas buscadas (sin ser especificadas con -L) depende de qué modo de emulación esté utilizando ld, y en algunos casos también de cómo fue configurado.

Las rutas también se pueden especificar en un script de enlace con el comando "SEARCH_DIR". Los directorios especificados de esta manera se buscan en el punto en que aparece el script de enlace en la línea de comandos.

-m emulacion
Emula el enlazador de emulacion. Puede listar las emulaciones disponibles con las opciones --verbose o -V.

Si no se utiliza la opción -m, la emulación se toma de la variable de entorno "LDEMULATION", si esta está definida.

De lo contrario, la emulación por defecto depende de cómo se configuró el enlazador.

--remap-inputs=patron=nombre_archivo
--remap-inputs-file=archivo
Estas opciones permiten cambiar los nombres de los archivos de entrada antes de que el enlazador intente abrirlos. La opción --remap-inputs=foo.o=bar.o hará que cualquier intento de cargar un archivo llamado foo.o intente cargar en su lugar un archivo llamado bar.o. Se permiten patrones comodín en el primer nombre de archivo, por lo que --remap-inputs=foo*.o=bar.o renombrará cualquier archivo de entrada que coincida con foo*.o a bar.o.

Una forma alternativa de la opción --remap-inputs-file=nombre_archivo permite leer las reasignaciones de un archivo. Cada línea en el archivo puede contener una única reasignación. Las líneas en blanco se ignoran. Cualquier cosa desde un carácter de almohadilla (#) hasta el final de una línea se considera un comentario y también se ignora. El patrón de mapeo puede separarse del nombre de archivo por espacios en blanco o un carácter de igual (=).

Las opciones se pueden especificar varias veces. Sus contenidos se acumulan. Las reasignaciones se procesarán en el orden en que ocurran en la línea de comandos, y si provienen de un archivo, en el orden en que ocurran en el archivo. Si se produce una coincidencia, no se realizará ninguna comprobación adicional para ese nombre de archivo.

Si el nombre de archivo de reemplazo es /dev/null o simplemente NUL, entonces la reasignación hará que el archivo de entrada se ignore. Esta puede ser una forma conveniente de experimentar quitando archivos de entrada de un entorno de compilación complicado.

Tenga en cuenta que esta opción depende de la posición y solo afecta a los nombres de archivo que vienen después de ella en la línea de comandos. Por lo tanto:

ld foo.o --remap-inputs=foo.o=bar.o

No tendrá ningún efecto, mientras que:

ld --remap-inputs=foo.o=bar.o foo.o

Renombrará el archivo de entrada foo.o a bar.o.

Nota: estas opciones también afectan a los archivos referenciados por las sentencias INPUT en los scripts de enlazador. Pero como los scripts de enlazador se procesan después de que se lee toda la línea de comandos, la posición de las opciones de reasignación en la línea de comandos no es significativa.

Si la opción verbose está habilitada, se informarán las reasignaciones que coincidan, aunque nuevamente la opción verbose necesita estar habilitada en la línea de comandos antes de que aparezcan los nombres de archivo reasignados.

Si las opciones -Map o --print-map están habilitadas, la lista de reasignaciones se incluirá en la salida del mapa.

-M
--print-map
Imprime un mapa de enlace en la salida estándar. Un mapa de enlace proporciona información sobre el enlace, incluyendo lo siguiente:
  • Dónde se mapean los archivos objeto en memoria.
  • Cómo se asignan los símbolos comunes.
  • Todos los miembros de archivo incluidos en el enlace, con una mención del símbolo que provocó que se incluyera el miembro del archivo.
  • Los valores asignados a los símbolos.

    Nota: es posible que los símbolos cuyos valores se calculan mediante una expresión que implica una referencia a un valor anterior del mismo símbolo no muestren el resultado correcto en el mapa de enlace. Esto se debe a que el enlazador descarta los resultados intermedios y solo retiene el valor final de una expresión. En tales circunstancias, el enlazador mostrará el valor final encerrado entre corchetes. Por ejemplo, un script de enlazador que contenga:

    foo = 1
foo = foo * 4
foo = foo + 8

    Producirá la siguiente salida en el mapa de enlace si la opción -M

se utiliza:

0x00000001                foo = 0x1
[0x0000000c]                foo = (foo * 0x4)
[0x0000000c]                foo = (foo + 0x8)

Consulte la sección Expressions para obtener más información sobre las expresiones en los scripts del enlazador.

  • Cómo se fusionan las propiedades de GNU.

    Cuando el enlazador fusiona las secciones .note.gnu.property de entrada en una única sección .note.gnu.property de salida, algunas propiedades se eliminan o se actualizan. Estas acciones se notifican en el mapa de enlace. Por ejemplo:

    Removed property 0xc0000002 to merge foo.o (0x1) and bar.o (not found)

    Esto indica que la propiedad 0xc0000002 se elimina de la salida al fusionar propiedades en foo.o, cuyo valor de propiedad 0xc0000002 es 0x1, y bar.o, que no tiene la propiedad 0xc0000002.

    Updated property 0xc0010001 (0x1) to merge foo.o (0x1) and bar.o (0x1)

    Esto indica que el valor de la propiedad 0xc0010001 se actualiza a 0x1 en la salida al fusionar propiedades en foo.o, cuya propiedad 0xc0010001 tiene el valor 0x1, y bar.o, cuya propiedad 0xc0010001 tiene el valor 0x1.

  • En algunos destinos ELF, una lista de correcciones insertadas por --relax 
    foo.o: Adjusting branch at 0x00000008 towards "far" in section .text

    Esto indica que el salto en 0x00000008 en foo.o, dirigido al símbolo "far" en la sección .text, ha sido reemplazado por una trampolina.

    -n
    --nmagic
    Desactiva la alineación de páginas de las secciones y deshabilita el enlace contra bibliotecas compartidas. Si el formato de salida admite números mágicos de estilo Unix, marca la salida como "NMAGIC".
    -N
    --omagic
    Establece las secciones de texto y datos para que sean legibles y modificables. Además, no alinea por página el segmento de datos y deshabilita el enlace contra bibliotecas compartidas. Si el formato de salida admite números mágicos de estilo Unix, marca la salida como "OMAGIC". Nota: Aunque se permite una sección de texto modificable para destinos PE-COFF, no cumple con la especificación del formato publicada por Microsoft.

    Esta opción niega la mayoría de los efectos de la opción -N. Establece la sección de texto como de solo lectura y fuerza la alineación por página del segmento de datos. Nota: esta opción no habilita el enlace contra bibliotecas compartidas. Utilice -Bdynamic para ello.
    -o salida
    --output=salida
    Utiliza salida como nombre para el programa producido por ld; si esta opción no se especifica, se utiliza por defecto el nombre a.out. El comando de script "OUTPUT" también puede especificar el nombre del archivo de salida.

    Nota: el enlazador eliminará el archivo de salida antes de comenzar a escribir en él. Lo hará incluso si el enlace no se puede completar debido a errores.

    Nota: el enlazador verificará que el nombre del archivo de salida no coincida con el nombre de ninguno de los archivos de entrada, pero eso es todo. En particular, no se quejará si el archivo de salida puede sobrescribir un archivo fuente o algún otro archivo importante. Por lo tanto, en los sistemas de compilación, se recomienda usar la opción -o como la última opción en la línea de comandos del enlazador. Por ejemplo, considere:

    ld -o $(EXE) $(OBJS)
ld $(OBJS) -o $(EXE)

    Si la variable EXE no está definida por alguna razón, la primera versión del comando del enlazador podría terminar eliminando uno de los archivos objeto (el primero de la lista OBJS), mientras que la segunda versión del comando del enlazador generará un mensaje de error y no eliminará nada.

    --dependency-file=archivo-dependencias
    Escribe un archivo de dependencias en archivo-dependencias. Este archivo contiene una regla adecuada para "make" que describe el archivo de salida y todos los archivos de entrada que se leyeron para producirlo. La salida es similar a la salida del compilador con -M -MP. Tenga en cuenta que no hay una opción como -MM del compilador, para excluir "archivos del sistema" (lo que no es un concepto bien especificado en el enlazador, a diferencia de los "archivos de cabecera del sistema" en el compilador). Por lo tanto, la salida de --dependency-file es siempre específica del estado exacto de la instalación donde se produjo, y no debe copiarse en makefiles distribuidos sin una edición cuidadosa.
    -O nivel
    Si nivel es un valor numérico mayor que cero, ld optimiza la salida. Esto puede llevar significativamente más tiempo y, por lo tanto, probablemente solo debería habilitarse para el binario final. Por el momento, esta opción solo afecta la generación de bibliotecas compartidas ELF. Las versiones futuras del enlazador pueden hacer un mayor uso de esta opción. Tampoco hay actualmente ninguna diferencia en el comportamiento del enlazador para diferentes valores distintos de cero de esta opción. De nuevo, esto puede cambiar con futuras versiones.
    -plugin nombre
    Involucra un plugin en el proceso de enlace. El parámetro nombre es el nombre de archivo absoluto del plugin. Normalmente, este parámetro se añade automáticamente por el compilador, cuando se utiliza la optimización en tiempo de enlace, pero los usuarios también pueden añadir sus propios plugins si lo desean.

    Tenga en cuenta que la ubicación de los plugins originados por el compilador es diferente del lugar donde los programas ar, nm y ranlib buscan sus plugins. Para que esos comandos puedan utilizar un plugin basado en el compilador, primero debe copiarse en el directorio ${libdir}/bfd-plugins. Todos los plugins del enlazador basados en gcc son compatibles con versiones anteriores, por lo que es suficiente copiar el más reciente.

    --push-state
    --push-state permite preservar el estado actual de las banderas que rigen el manejo de archivos de entrada para que todas puedan restaurarse con una opción correspondiente --pop-state.

    Las opciones cubiertas son: -Bdynamic, -Bstatic, -dn, -dy, -call_shared, -non_shared, -static, -N, -n, --whole-archive, --no-whole-archive, -r, -Ur, --copy-dt-needed-entries, --no-copy-dt-needed-entries, --as-needed, --no-as-needed y -a.

    Un objetivo para esta opción son las especificaciones para pkg-config. Cuando se usa con la opción --libs, se listan todas las bibliotecas posiblemente necesarias y luego se enlazan con ellas todo el tiempo. Es mejor devolver algo como lo siguiente:

    -Wl,--push-state,--as-needed -libone -libtwo -Wl,--pop-state
    --pop-state
    Anula el efecto de --push-state, restaura los valores anteriores de las banderas que rigen el manejo de archivos de entrada.
    -q
    --emit-relocs
    Deja las secciones y contenidos de reubicación en ejecutables completamente enlazados. Las herramientas de análisis y optimización posteriores al enlace pueden necesitar esta información para realizar modificaciones correctas de los ejecutables. Esto resulta en ejecutables más grandes.

    Esta opción solo es compatible actualmente en plataformas ELF.

    --force-dynamic
    Fuerza que el archivo de salida tenga secciones dinámicas. Esta opción es específica para destinos VxWorks.
    -r
    --relocatable
    Genera salida reubicable; es decir, genera un archivo de salida que a su vez puede servir como entrada para ld. Esto a menudo se llama enlace parcial. Como efecto secundario, en entornos que admiten números mágicos estándar de Unix, esta opción también establece el número mágico del archivo de salida en "OMAGIC". Si esta opción no se especifica, se produce un archivo absoluto. Al enlazar programas C++, esta opción no resolverá referencias a constructores; para ello, use -Ur.

    Cuando un archivo de entrada no tiene el mismo formato que el archivo de salida, el enlace parcial solo se admite si ese archivo de entrada no contiene reubicaciones. Los diferentes formatos de salida pueden tener restricciones adicionales; por ejemplo, algunos formatos basados en "a.out" no admiten el enlace parcial con archivos de entrada en otros formatos en absoluto.

    Cuando la salida reubicable contiene tanto contenido que requiere optimización en tiempo de enlace (LTO) como contenido que no la requiere, se creará una sección .gnu_object_only para contener un archivo objeto reubicable, como si se aplicara -r a todas las entradas reubicables que no requieren LTO. Al procesar una entrada reubicable con una sección .gnu_object_only, el enlazador extraerá la sección .gnu_object_only como una entrada separada.

    Tenga en cuenta que, dado que -r agrupa algunas secciones de diferentes archivos de entrada, puede haber impactos negativos en el tamaño del código y la localidad en el ejecutable final o la biblioteca compartida.

    Esta opción hace lo mismo que -i.

    -R nombre-archivo
    --just-symbols=nombre-archivo
    Lee los nombres de símbolos y sus direcciones del archivo nombre-archivo, pero no lo reubica ni lo incluye en la salida. Esto permite que su archivo de salida se refiera simbólicamente a ubicaciones de memoria absolutas definidas en otros
    programas. Puedes usar esta opción más de una vez.

    Por compatibilidad con otros enlazadores ELF, si la opción -R va seguida de un nombre de directorio, en lugar de un nombre de archivo, se trata como la opción -rpath.

    --rosegment
    --no-rosegment
    Intenta asegurar que solo se cree un único segmento de solo lectura y no de código. Solo es útil cuando se usa junto con la opción -z separate-code. Los binarios resultantes deberían ser más pequeños que si se usa -z separate-code por sí sola. Sin esta opción, o si se especifica --no-rosegment, la opción -z separate-code creará dos segmentos de solo lectura, uno antes del segmento de código y otro después.

    Los nombres de las opciones son engañosos, pero han sido elegidos para que el enlazador sea compatible con los enlazadores LLD y GOLD.

    Estas opciones solo están soportadas por destinos ELF.

    Omite toda la información de símbolos del archivo de salida.

    --strip-debug
    Omite la información de símbolos del depurador (pero no todos los símbolos) del archivo de salida.

La salida de -t es útil para generar una lista de todos los archivos objeto y scripts involucrados en el enlazado, por ejemplo, al empaquetar archivos para un informe de error del enlazador.
    -T scriptfile
    --script=scriptfile
    Usa scriptfile como script de enlazador. Este script reemplaza el script de enlazador predeterminado de ld (en lugar de añadirle), a menos que el script contenga "INSERT", por lo que commandfile debe especificar todo lo necesario para describir el archivo de salida.

    -dT scriptfile
    --default-script=scriptfile
    Usa scriptfile como script de enlazador predeterminado.

    Esta opción es similar a la opción --script excepto en que el procesamiento del script se retrasa hasta después de que se hayan procesado el resto de la línea de comandos. Esto permite que las opciones colocadas después de la opción --default-script en la línea de comandos afecten al comportamiento del script de enlazador, lo que puede ser importante cuando la línea de comandos del enlazador no puede ser controlada directamente por el usuario. (por ejemplo, porque la línea de comandos está siendo construida por otra herramienta, como gcc).

    -u symbol
    --undefined=symbol
    Fuerza que symbol se ingrese en el archivo de salida como un símbolo indefinido. Hacer esto puede, por ejemplo, activar el enlazado de módulos adicionales de las bibliotecas estándar. -u puede repetirse con diferentes argumentos de opción para ingresar símbolos indefinidos adicionales. Esta opción es equivalente al comando de script de enlazador "EXTERN".

    Si esta opción se está utilizando para forzar la inclusión de módulos adicionales en el enlace, y si es un error que el símbolo permanezca indefinido, entonces se debe usar la opción --require-defined en su lugar.

    --require-defined=symbol
    Requiere que symbol esté definido en el archivo de salida. Esta opción es igual a la opción --undefined excepto que si symbol no está definido en el archivo de salida, el enlazador emitirá un error y saldrá. El mismo efecto se puede lograr en un script de enlazador usando "EXTERN", "ASSERT" y "DEFINED" juntos. Esta opción se puede usar varias veces para requerir símbolos adicionales.
    -Ur
    Para programas que no usan constructores o destructores, o para sistemas basados en ELF, esta opción es equivalente a -r: genera salida reubicable, es decir, un archivo de salida que a su vez puede servir como entrada para ld. Para otros binarios, sin embargo, la opción -Ur es similar a -r pero también resuelve referencias a constructores y destructores.

    Para aquellos sistemas donde -r y -Ur se comportan de manera diferente, no funciona usar -Ur en archivos que fueron enlazados con -Ur; una vez que la tabla de constructores se ha construido, no se le puede añadir nada. Use -Ur solo para el último enlace parcial, y -r para los otros.

    --orphan-handling=MODE
    Controla cómo se manejan las secciones huérfanas. Una sección huérfana es una que no se menciona específicamente en un script de enlazador.

    MODE puede tener cualquiera de los siguientes valores:

    "place"
    Las secciones huérfanas se colocan en una sección de salida adecuada siguiendo la estrategia descrita en Secciones Huérfanas. La opción --unique también afecta a cómo se colocan las secciones.
    "discard"
    Todas las secciones huérfanas se descartan, colocándolas en la sección /DISCARD/.
    "warn"
    El enlazador colocará la sección huérfana como en "place" y también emitirá una advertencia.
    "error"
    El enlazador saldrá con un error si se encuentra alguna sección huérfana.

    El valor predeterminado si no se proporciona --orphan-handling es "place".

    --unique[=SECTION]
    Crea una sección de salida separada para cada sección de entrada que coincida con SECTION, o si el argumento comodín opcional SECTION falta, para cada sección de entrada huérfana. Una sección huérfana es aquella que no se menciona específicamente en un script de enlazador. Puede usar esta opción varias veces en la línea de comandos; evita la fusión normal de secciones de entrada con el mismo nombre, anulando las asignaciones de secciones de salida en un script de enlazador.
    -v
    --version
    -V
    Muestra el número de versión de ld. La opción -V también enumera las emulaciones soportadas. Consulte también la descripción de --enable-linker-version en Opciones, Opciones de línea de comandos que se puede usar para insertar la cadena de versión del enlazador en un binario.

    --discard-all
    Elimina todos los símbolos locales.
    -X
    --discard-locals
    Elimina todos los símbolos locales temporales. (Estos símbolos comienzan con prefijos de etiqueta local específicos del sistema, típicamente .L para sistemas ELF o L para sistemas tradicionales a.out).)

    --trace-symbol=symbol
    Imprime el nombre de cada archivo enlazado en el que aparece symbol. Esta opción se puede dar cualquier número de veces. En muchos sistemas es necesario anteponer un guion bajo.

    -z keyword
    Las palabras clave reconocidas son:
    call-nop=prefix-addr
    call-nop=suffix-nop
    call-nop=prefix-byte
    call-nop=suffix-byte
    Especifica el relleno de "NOP" de 1 byte al transformar una llamada indirecta a una función definida localmente, foo, a través de su slot GOT. call-nop=prefix-addr genera "0x67 call foo". call-nop=suffix-nop genera "call foo 0x90". call-nop=prefix-byte genera "byte call foo". call-nop=suffix-byte genera "call foo byte".     cet-report=none

    --no-keep-memory
    ld normalmente optimiza la velocidad en lugar del uso de memoria almacenando en caché las tablas de símbolos de los archivos de entrada en memoria. Esta opción le indica a ld que, en cambio, optimice el uso de memoria, volviendo a leer las tablas de símbolos según sea necesario. Esto puede ser necesario si ld se queda sin espacio de memoria al enlazar un ejecutable grande.

    -z defs
    Informa sobre referencias de símbolos no resueltas de archivos de objeto regulares. Esto se hace incluso si el enlazador está creando una biblioteca compartida no simbólica.     --allow-multiple-definition

    --allow-shlib-undefined
    --no-allow-shlib-undefined
    Permite o prohíbe símbolos no definidos en bibliotecas compartidas. Este interruptor es similar a --no-undefined, excepto que determina el comportamiento cuando los símbolos no definidos están en una biblioteca compartida en lugar de un archivo de objeto regular. No afecta a cómo se manejan los símbolos no definidos en archivos de objeto regulares.

    El comportamiento predeterminado es informar errores para cualquier símbolo no definido referenciado en bibliotecas compartidas si el enlazador se utiliza para crear un ejecutable, pero permitirlos si el enlazador se utiliza para crear una biblioteca compartida.

    Las razones para permitir referencias de símbolos no definidos en bibliotecas compartidas especificadas en el enlace son que:

    • Una biblioteca compartida especificada en el enlace puede no ser la misma que la disponible en tiempo de carga, por lo que el símbolo podría ser resoluble en tiempo de carga.
    • Existen algunos sistemas operativos, por ejemplo BeOS y HPPA, donde los símbolos no definidos en bibliotecas compartidas son normales.

      El kernel de BeOS, por ejemplo, aplica parches a las bibliotecas compartidas en tiempo de carga para seleccionar la función que sea más apropiada para la arquitectura actual. Esto se usa, por ejemplo, para seleccionar dinámicamente una función memset apropiada.

    Si se proporciona esta opción, el enlazador invocará a nombre_script cada vez que se encuentre un error. La búsqueda de -rpath de esta manera solo es compatible con los enlazadores nativos y los enlazadores cruzados que se han configurado con la opción --with-sysroot.

Si se utiliza una opción -rpath, la ruta de búsqueda en tiempo de ejecución se formará exclusivamente utilizando las opciones -rpath, ignorando las opciones -L. Esto puede ser útil cuando se usa gcc, que añade muchas opciones -L que pueden estar en sistemas de archivos montados por NFS.

    -rpath-link=dir

    Cuando el enlazador encuentra una dependencia de este tipo al realizar un enlace no compartido, no relocable, intentará automáticamente localizar la biblioteca compartida requerida e incluirla en el enlace, si no está incluida explícitamente. Esta opción puede especificar una secuencia de nombres de directorios proporcionando una lista de nombres separados por dos puntos, o apareciendo varias veces.

Se reemplazarán por la ruta completa al directorio que contiene el programa o el objeto compartido en el caso de $ORIGIN y ya sea lib - para binarios de 32 bits - o lib64 - para binarios de 64 bits - en el caso de $LIB.

Tenga en cuenta, sin embargo, que esto solo se aplica a las bibliotecas adicionales necesarias para satisfacer las bibliotecas compartidas ya incluidas. No se aplica a las bibliotecas que se incluyen a través de la opción de línea de comandos -l. Las búsquedas de bibliotecas -l solo se realizan en los directorios especificados por la opción -L.

La diferencia entre -rpath y -rpath-link es que los directorios especificados por las opciones -rpath se incluyen en el ejecutable y se utilizan en tiempo de ejecución, mientras que la opción -rpath-link solo es efectiva en tiempo de enlace. La búsqueda de -rpath de esta manera solo es compatible con enlazadores nativos y enlazadores cruzados que se hayan configurado con la opción --with-sysroot.
    3.

    4.

    5.

    8.

    9.

    --section-ordering-file=script
    Esta opción se utiliza para aumentar el script de enlazador actual con un mapeo adicional de secciones de entrada a secciones de salida. Este archivo debe utilizar la misma sintaxis para "SECTIONS" que se utiliza en los scripts de enlazador normales, pero no debe hacer nada más que colocar las secciones de entrada en las secciones de salida. @pxref{SECTIONS}

    Una segunda restricción en el script de ordenación de secciones es que solo puede hacer referencia a secciones de salida que ya están definidas por el script de enlazador que se está utilizando. (Es decir, el script de enlazador predeterminado o un script especificado en la línea de comandos). Sin embargo, la ventaja del script de ordenación de secciones es que las secciones de entrada se mapean al inicio de las secciones de salida, de modo que pueden garantizar el orden de las secciones en la sección de salida. Por ejemplo, imagine que el script de enlazador predeterminado se ve así:

    SECTIONS {
  .text : { *(.text.hot) ; .text .text.*) }
  .data : { *(.data.big) ; .data .data.*) }
  }

    Luego, si se utiliza un archivo de ordenación de secciones como este:

    .text : { *(.text.first) ; *(.text.z*) }
.data : { foo.o(.data.first) ; *(.data.small) }

    Esto sería equivalente a un script de enlazador como este:

    SECTIONS {
  .text : { *(.text.first) ; *(.text.z*) ; *(.text.hot) ; .text .text.*) }
  .data : { foo.o(.data.first) ; *(.data.small) ; *(.data.big) ; .data .data.*) }
  }

    La ventaja del archivo de ordenación de secciones es que se puede utilizar para ordenar aquellas secciones que son importantes para el usuario sin tener que preocuparse por ninguna otra sección, ni regiones de memoria, ni nada más.

    --warn-execstack-objects

    En plataformas ELF, el enlazador puede generar mensajes de advertencia si se le pide que cree un archivo de salida que contenga una pila ejecutable. Hay tres estados posibles:
    1.
    No generar ninguna advertencia.
    2.
    Generar siempre advertencias, incluso si se solicita una pila ejecutable a través de la opción de línea de comandos -z execstack.

    --warn-multiple-gp
    Advierte si se requieren múltiples valores de puntero global en el archivo de salida. Esto solo es significativo para ciertos procesadores, como Alpha. Específicamente, algunos procesadores colocan constantes de gran valor en una sección especial. Un registro especial (el puntero global) apunta al medio de esta sección, de modo que las constantes puedan cargarse eficientemente a través de un modo de direccionamiento relativo al registro base. Dado que el desplazamiento en el modo relativo al registro base es fijo y relativamente pequeño (por ejemplo, 16 bits), esto limita el tamaño máximo del grupo de constantes. Por lo tanto, en programas grandes, a menudo es necesario usar múltiples valores de puntero global para poder dirigir todas las constantes posibles. Esta opción provoca una advertencia cada vez que ocurre este caso.

    Las siguientes observaciones se refieren a la implementación original de la característica y están obsoletas hoy en día para los objetivos de Cygwin y MinGW.

    Nota: El uso de la extensión 'auto-import' hará que la sección de texto del archivo de imagen se vuelva escribible. Esto no cumple con la especificación del formato PE-COFF publicada por Microsoft.

    Nota: el uso de la extensión 'auto-import' también hará que los datos de solo lectura que normalmente se colocarían en la sección .rdata se coloquen en la sección .data en su lugar. Esto es para solucionar un problema con las constantes que se describe aquí: http://www.cygwin.com/ml/cygwin/2004-09/msg01101.html

    Usar 'auto-import' generalmente funcionará, pero a veces puede ver este mensaje:

    "no se puede autoimportar la variable '<var>'. Lea la documentación para "--enable-auto-import" de ld para obtener detalles."

    Este mensaje ocurre cuando alguna (sub)expresión accede a una dirección dada en última instancia por la suma de dos constantes (las tablas de importación de Win32 solo permiten una). Los casos en los que esto puede ocurrir incluyen el acceso a campos miembro de variables de estructura importadas de una DLL, así como el uso de un índice constante en una variable de matriz importada de una DLL. Cualquier variable de varias palabras (matrices, estructuras, long long, etc.) puede activar esta condición de error. Sin embargo, independientemente del tipo de dato exacto de la variable exportada que cause el problema, ld siempre la detectará, emitirá la advertencia y saldrá.

    Hay varias formas de abordar esta dificultad, independientemente del tipo de dato de la variable exportada:

    Una forma es usar el modificador --enable-runtime-pseudo-reloc. Esto deja la tarea de ajustar las referencias en su código cliente para el entorno de ejecución, por lo que este método solo funciona cuando el entorno de ejecución admite esta característica.

    Una segunda solución es forzar que una de las 'constantes' sea una variable, es decir, desconocida y no optimizable en tiempo de compilación. Para las matrices, hay dos posibilidades: a) hacer que el elemento indexado (la dirección de la matriz) sea una variable, o b) hacer que el índice 'constante' sea una variable. Por lo tanto:

    extern type extern_array[];
extern_array[1] -->
   { volatile type *t=extern_array; t[1] }

    o

    extern type extern_array[];
extern_array[1] -->
   { volatile int t=1; extern_array[t] }

    Para estructuras (y la mayoría de los demás tipos de datos de varias palabras), la única opción es hacer que la estructura en sí misma (o el long long, o el ...) sea una variable:

    extern struct s extern_struct;
extern_struct.field -->
   { volatile struct s *t=&extern_struct; t->field }

    o

    extern long long extern_ll;
extern_ll -->
  { volatile long long * local_ll=&extern_ll; *local_ll }

    Un tercer método para tratar con esta dificultad es abandonar 'auto-import' para el símbolo en cuestión y marcarlo con "__declspec(dllimport)". Sin embargo, en la práctica, esto requiere el uso de #defines en tiempo de compilación para indicar si está compilando una DLL, compilando código cliente que se enlaza a la DLL, o simplemente compilando/enlazando a una biblioteca estática. Al elegir entre los diversos métodos para resolver el problema de la 'dirección directa con desplazamiento constante', debe considerar el uso típico en el mundo real:

    Original:

    --foo.h
extern int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  printf("%d\n",arr[1]);
}

    Solución 1:

    --foo.h
extern int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  /* Este es un solución alternativa para win32 y cygwin; no "optimizar" */
  volatile int *parr = arr;
  printf("%d\n",parr[1]);
}

    Solución 2:

    --foo.h
/* Nota: se asume auto-export (sin __declspec(dllexport)) */
#if (defined(_WIN32) || defined(__CYGWIN__)) && \
  !(defined(FOO_BUILD_DLL) || defined(FOO_STATIC))
#define FOO_IMPORT __declspec(dllimport)
#else
#define FOO_IMPORT
#endif
extern FOO_IMPORT int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  printf("%d\n",arr[1]);
}

    Una cuarta forma de evitar este problema es recodificar su biblioteca para usar una interfaz funcional en lugar de una interfaz de datos para las variables que causan el problema (por ejemplo, funciones accedentes set_foo() y get_foo()).

    ENTORNO

    Puede cambiar el comportamiento de ld con las variables de entorno "GNUTARGET", "LDEMULATION" y "COLLECT_NO_DEMANGLE".

    "GNUTARGET" determina el formato del objeto del archivo de entrada si no usa -b (o su sinónimo --format). Su valor debe ser uno de los nombres BFD para un formato de entrada. Si no hay "GNUTARGET" en el entorno, ld utiliza el formato natural del destino. Si "GNUTARGET" se establece en "default", BFD intenta descubrir el formato de entrada examinando los archivos binarios de entrada; este método a menudo tiene éxito, pero existen ambigüedades potenciales, ya que no hay un método para garantizar que el número mágico utilizado para especificar los formatos de archivo objeto sea único. Sin embargo, el procedimiento de configuración para BFD en cada sistema coloca el formato convencional para ese sistema primero en la lista de búsqueda, por lo que las ambigüedades se resuelven a favor de la convención.

    "LDEMULATION" determina la emulación predeterminada si no usa la opción -m. La emulación puede afectar varios aspectos del comportamiento del enlazador, particularmente el script de enlazador predeterminado. Puede listar las emulaciones disponibles con las opciones --verbose o -V. Si no se usa la opción -m y la variable de entorno "LDEMULATION" no está definida, la emulación predeterminada depende de cómo se configuró el enlazador.

    DESCRIPTION

    The GNU linker, ld, combines various types of object files (containing code and data) and searches necessary standard libraries and archives to make an executable file, a shared library, or an object file. By default it creates an executable file.

    The linker performs a two-pass process. First it determines the memory addresses of input sections. Then it assigns the symbols to those addresses.

    The linker automatically determines the type of object files, and how to process them. Some operations may be specified by command-line options.

    The linker can be instructed to emulate different linkers. For example, on an `i386-linux' system, it can emulate `GNU ld', `sol2', `osf`, and `lynxos'. The default emulation is determined by the linker's configuration. This default can be overridden by the -memulation option.

    ld can also be invoked as collect2. This is done by the gcc linker wrapper program. The default may be overridden by the --demangle and --no-demangle options.

    OPTIONS

    The linker has a large number of options. Below are some of the most common ones.

    -a
    Perform a linking which is valid for a shared object.
    --as-needed
    Only link against libraries hereafter in the command line if they are needed to resolve symbols referenced in the preceding object files and libraries. When you are writing an executable that links against shared libraries, this option means that you do not link against the shared libraries that are not needed. This is the default behavior for shared libraries.
    -barch
    Specify the target architecture. See the --help option for a list of supported architectures.
    -cSECTIONS
    Specify the layout of sections in the output file. This option is typically used for embedded systems.
    --cref
    Output cross-reference table.
    --defsym sym=val
    Create a new global symbol `sym' and set its value to `val'.
    --demangle
    Decode symbol names into user-level function and variable names. This is the default behavior.
    -e ENTRY
    Set the entry point symbol to ENTRY.
    --eh-frame-hdr
    Construct a separate section containing DWARF exception header information.
    --emit-relocs[=type]
    Emit relocation entries in the output file. The optional type can be `coff`, `elf32-littleriscv`, etc. This is usually used for creating position-independent code.
    --enable-new-dtags
    Use new dynamic table tags. This is the default behavior.
    -fFLAG
    Set specific flags. See the --help option for a list of supported flags.
    --gc-sections
    Discard unused sections.
    --hash-style=[sysv|gnu|both]
    Set the style of the symbol hash table used in shared libraries. `gnu` is the default.
    --help
    Print a summary of the linker options on the standard output and exit.
    -i
    Perform incremental linking.
    -larchive
    Link against the archive or shared library `archive'.
    -Ldir
    Add directory `dir' to the library search path.
    --lint-brandbrand
    The linker will ensure that objects using the specified brand are linked together. This is used for specific ABI compatibility.
    -mEMULATION
    Set the linker emulation. See the --help option for a list of supported emulations.
    --no-as-needed
    Libraries are always linked, even if they are not needed.
    --no-demangle
    Do not decode symbol names.
    --no-global-optimization
    Disable global optimization.
    --no-insert-timestamp
    Do not insert a timestamp into the output file.
    --no-libtool
    Disable libtool emulation.
    --no-merge-exidx
    Do not merge exception index sections.
    --no-plt
    Do not create a procedure linkage table.
    --no-relax
    Disable relocation relaxation.
    --no-undefined-sections
    Do not create sections for undefined symbols.
    --no-whole-archive
    Disable the effect of --whole-archive for subsequent libraries.
    --nxcompat
    Make the executable non-executable stack compatible (NXCOMPAT).
    -o output
    Place the output into file `output'.
    --omagic
    Set the OMAGIC flag in the PE header.
    --optimize-for-shared-lib
    Optimize for shared libraries.
    --pie
    Create a Position Independent Executable (PIE).
    --print-archive-庫

    --print-search-dirs
    Print the library search paths.
    --profile
    Print linking information.
    --push-state
    Push the current linker state.
    --pop-state
    Pop the last saved linker state.
    --relax
    Enable relocation relaxation. This allows the linker to optimize relocations.
    -r
    Produce an intermediate object file containing relocated but unlinked object files.
    -R dir
    Add directory `dir' to the runtime library search path.
    --sort-section-names
    Sort section names alphabetically.
    --sort-entriesentry
    Sort entries according to the specified criteria.
    --split-by-reloc
    Split output sections by relocation.
    --split-by-section
    Split output sections by section.
    --stats
    Print linker resource use information.
    --strip-debug
    Strip debug information from the output file.
    -s
    Strip symbol tables and debugging information from the output file.
    -t
    Print the linker script.
    --toplevel-sort

    --trace
    Trace linker operations.
    --trace-symbol=sym

    --traditional-linking
    Use traditional linking order.

    ENVIRONMENT

    The linker automatically determines the type of object files, and how to process them. Some operations may be specified by command-line options.

    The linker can be instructed to emulate different linkers. For example, on an `i386-linux' system, it can emulate `GNU ld', `sol2`, `osf`, and `lynxos'. The default emulation is determined by the linker's configuration. This default can be overridden by the -memulation option.

    ld can also be invoked as collect2. This is done a similar fashion by the "gcc" linker wrapper program. The default may be overridden by the --demangle and --no-demangle options.

    If the PE/COFF specific --insert-timestamp is active and the SOURCE_DATE_EPOCH environment variable is defined, then the timestamp value in this variable will be inserted into the COFF header instead of the current time.

    If the "LD_STATS" environment variable is defined then linker resource use information will be recorded, just as if the --stats option had been used. If the "LD_STATS" variable has a string value then this will used as the name of a file into which the information should be stored. Otherwise the information will be sent to the standard output stream.
