NOMBRE

xfs_db - depurar un sistema de archivos XFS

SINOPSIS

xfs_db [ -c comando ] ... [ -i|r|x|F ] [ -f ] [ -l dispositivo_log ] [ -R dispositivo_rt ] [ -p nombre_programa ] dispositivo
xfs_db -V

DESCRIPCIÓN

xfs_db se utiliza para examinar un sistema de archivos XFS. En circunstancias raras, también se puede utilizar para modificar un sistema de archivos XFS, pero esa tarea normalmente se deja a xfs_repair(8) o a scripts como xfs_admin(8) que ejecutan xfs_db.

OPCIONES

-c comando
Los comandos de xfs_db se pueden ejecutar interactivamente (por defecto) o como argumentos en la línea de comandos. Se pueden proporcionar múltiples argumentos -c. Los comandos se ejecutan en la secuencia indicada y luego el programa sale.
-f
Especifica que la imagen del sistema de archivos a procesar está almacenada en un archivo regular en dispositivo (ver la opción -d de archivo de mkfs.xfs(8)). Esto puede ocurrir si se ha hecho una copia de imagen de un sistema de archivos en un archivo ordinario con xfs_copy(8).
-F
Especifica que queremos continuar aunque la magia de la superbloque no sea correcta. Para su uso en xfs_metadump.
-i
Permite la ejecución en un sistema de archivos montado, siempre que esté montado en modo de solo lectura. Útil para scripts de shell que solo deben operar en sistemas de archivos en un estado garantizado y consistente (desmontado o montado en modo de solo lectura). Estas semánticas son ligeramente diferentes a las de la opción -r.
-l dispositivo_log
Especifica el dispositivo donde reside el registro externo de los sistemas de archivos. Solo para aquellos sistemas de archivos que utilizan un registro externo. Ver la opción -l de mkfs.xfs(8), y consultar xfs(5) para una descripción detallada del registro XFS.
-p nombre_programa
Establece el nombre del programa a nombre_programa para los indicadores de línea de comandos y algunos mensajes de error; el valor predeterminado es xfs_db.
-R
dispositivo_rt Especifica el dispositivo donde residen los datos en tiempo real. Esto solo es relevante para sistemas de archivos que tienen una sección en tiempo real. Ver la opción -r de mkfs.xfs(8), y consultar xfs(5) para una descripción detallada de la sección en tiempo real de XFS.
-r
Abre dispositivo o nombre_archivo en modo de solo lectura. Esta opción es requerida si el sistema de archivos está montado. Solo es necesario omitir esta bandera si se va a usar un comando que cambie datos (write, blocktrash, crc).
-x
Especifica el modo experto. Esto habilita los comandos (write, blocktrash, crc invalidate/revalidate).
-V
Imprime el número de versión y sale.

CONCEPTOS

Los comandos de xfs_db se pueden dividir en dos clases. La mayoría de los comandos son para la navegación y visualización de estructuras de datos en el sistema de archivos. Otros comandos son para escanear el sistema de archivos de alguna manera.

Los comandos que se utilizan para navegar por la estructura del sistema de archivos toman argumentos que reflejan los nombres de los campos de la estructura del sistema de archivos. Puede haber múltiples nombres de campo separados por puntos cuando las estructuras subyacentes están anidadas, como en C. Los nombres de campo se pueden indexar (como un índice de matriz) si el campo subyacente es una matriz. Los índices de matriz se pueden especificar como un rango, dos números separados por un guion.

xfs_db mantiene una dirección actual en el sistema de archivos. La granularidad de la dirección es una estructura del sistema de archivos. Esta puede ser un bloque del sistema de archivos, un inodo o una cuota (más pequeño que un bloque del sistema de archivos), o un bloque de directorio (podría ser más grande que un bloque del sistema de archivos). Hay una variedad de comandos para establecer la dirección actual. Asociado a la dirección actual está el tipo de datos actual, que es el tipo estructural de estos datos. Los comandos que siguen la estructura del sistema de archivos siempre establecen el tipo así como la dirección. Los comandos que examinan piezas de un archivo individual (inodo) necesitan que se establezca el inodo actual, esto se hace con el comando inode.

La información de dirección/tipo actual se mantiene en una pila que se puede manipular explícitamente con los comandos push, pop y stack. Esto permite la fácil examinación de una estructura de sistema de archivos anidada. Además, las últimas varias ubicaciones visitadas se almacenan en un búfer circular que se puede manipular con los comandos forward, back y ring.

Los sistemas de archivos XFS se dividen en un pequeño número de grupos de asignación. xfs_db mantiene una noción del grupo de asignación actual que es manipulado por algunos comandos. El grupo de asignación inicial es 0.

blocktrash [-z] [-o offset] [-n count] [-x min] [-y max] [-s seed] [-0|1|2|3] [-t type] ...
Trash randomly selected filesystem metadata blocks. Trashing occurs to randomly selected bits in the chosen blocks. This command is available only in debugging versions of xfs_db. It is useful for testing xfs_repair(8).
-0 | -1 | -2 | -3
These are used to set the operating mode for blocktrash. Only one can be used: -0 changed bits are cleared; -1 changed bits are set; -2 changed bits are inverted; -3 changed bits are randomized.
-n

-o
supplies the bit offset at which to start trashing the block. If the value is preceded by a '+', the trashing will start at a randomly chosen offset that is larger than the value supplied. The default is to randomly choose an offset anywhere in the block.

-t

-x

-y
sets the maximum size of bit range to be trashed. The default value is 1024.
-z
trashes the block at the top of the stack. It is not necessary to run blockget if this option is supplied.

fsmap [ inicio ] [ fin ]
Imprime el mapeo de bloques de disco utilizados por un sistema de archivos XFS. El mapa enumera cada extensión utilizada por archivos, metadatos del grupo de asignación, registros de diario y metadatos estáticos del sistema de archivos, así como cualquier región que no esté en uso. Todos los bloques, desplazamientos y longitudes se especifican en unidades de bloques de 512 bytes, independientemente del tamaño del bloque del sistema de archivos. Los argumentos opcionales inicio y fin se pueden utilizar para restringir la salida a un rango particular de bloques de disco.
fuzz [-c] [-d] campo acción
Escribe datos basura en un campo de estructura específico en el disco. El modo experto debe estar habilitado para usar este comando. La operación se realiza de inmediato; no hay almacenamiento en búfer.
El comando fuzz puede realizar las siguientes acciones sobre un campo:
zeroes
Borra todos los bits en el campo.
ones
Establece todos los bits en el campo.
firstbit
Invierte el primer bit en el campo. Para un valor escalar, este es el bit más alto.
middlebit
Invierte el bit del medio en el campo.
lastbit
Invierte el último bit en el campo. Para un valor escalar, este es el bit más bajo.
add
Suma un valor pequeño a un campo escalar.
sub
Resta un valor pequeño de un campo escalar.
random
Aleatoriza el contenido del campo.
Los siguientes modificadores afectan el comportamiento de escritura:
-c
Omite los verificadores de escritura y el recálculo de CRC; permite que se escriban datos no válidos en el disco.
-d
Omite los verificadores de escritura pero realiza el recálculo de CRC; permite que se escriban datos no válidos en el disco para probar la detección de datos no válidos.
hash[-d|-p ino_padre]"cadenas
Imprime el valor hash de la cadena utilizando la función hash de la implementación de directorios y atributos de XFS.

Si se especifica la opción -d, se utiliza la función hash específica del directorio. Esto solo marca la diferencia en sistemas de archivos con búsquedas que no distinguen entre mayúsculas y minúsculas en ASCII habilitadas.

Si se especifica la opción -p, se utiliza la función hash específica del puntero padre. El número de inodo del directorio padre debe especificarse como argumento. Esto solo marca la diferencia en sistemas de archivos con búsquedas que no distinguen entre mayúsculas y minúsculas en ASCII habilitadas.

Una bifurcación de atributos se organiza como un B-árbol con los datos reales incrustados en los bloques de hoja. La raíz del B-árbol se encuentra en el bloque 0 de la bifurcación. data

DESCRIPTION

The xfs_db utility is a debugger for XFS filesystems. It allows you to examine the internal structure of an XFS filesystem. It is primarily intended for use by filesystem developers, but it can be useful for system administrators trying to diagnose filesystem problems.

xfs_db can be used to examine the filesystem structure in detail, print out filesystem metadata, and perform a variety of checks on the filesystem's integrity. It can also be used to modify filesystem metadata, but this should only be done with extreme caution, as incorrect modifications can easily corrupt the filesystem.

xfs_db requires the filesystem to be unmounted. If the filesystem is mounted, xfs_db will print an error message and exit.

OPTIONS

xfs_db recognizes the following options:

-c command
Execute the given command and then exit.
-d
Run xfs_db in debug mode. This enables some extra sanity checks and messages.
-r
Open the filesystem read-only. This is the default behavior.
-v
Verbosity. This option can be specified multiple times to increase the level of verbosity.

CONCEPTS

This section describes some of the concepts and terminology used by xfs_db.

filesystem block
The basic unit of allocation on an XFS filesystem. The block size is determined when the filesystem is created. Typical block sizes are 4K, 8K, 16K, 32K, 64K, 128K, 256K, 512K, or 1024K.
inode
An inode is a data structure that describes a file or directory. It contains metadata about the file, such as its size, ownership, and permissions, as well as pointers to the data blocks that make up the file.
allocation group
An XFS filesystem is divided into one or more allocation groups. Each allocation group is a contiguous range of filesystem blocks that is managed independently. Allocation groups help to improve performance by allowing multiple threads to allocate and deallocate blocks concurrently.
superblock
The superblock is a data structure that contains information about the entire filesystem, such as its size, block size, and the location of the allocation groups. There are typically two copies of the superblock, one at the beginning of the filesystem and one at the end.
realtime subsystem
An optional feature of XFS filesystems that allows for the allocation of special realtime data. This is typically used for large files or files that require high performance.

DIAGNOSTICS

Many messages can come from the blockget command. If the filesystem is completely corrupt, a core dump might be produced instead of the message

device is not a valid filesystem

If the filesystem is very large (has many files) then blockget might run out of memory. In this case the message

out of memory
is printed.

The following is a description of the most likely problems and the associated messages. Most of the diagnostics produced are only meaningful with an understanding of the structure of the filesystem.

agf_freeblks n, counted m in ag a
The freeblocks count in the allocation group header for allocation group a doesn't match the number of blocks counted free.
agf_longest n, counted m in ag a
The longest free extent in the allocation group header for allocation group a doesn't match the longest free extent found in the allocation group.
agi_count n, counted m in ag a
The allocated inode count in the allocation group header for allocation group a doesn't match the number of inodes counted in the allocation group.
agi_freecount n, counted m in ag a
The free inode count in the allocation group header for allocation group a doesn't match the number of inodes counted free in the allocation group.
block a/b expected inum 0 got i
The block number is specified as a pair (allocation group number, block in the allocation group). The block is used multiple times (shared), between multiple inodes. This message usually follows a message of the next type.
block a/b expected type unknown got y
The block is used multiple times (shared).
block a/b type unknown not expected
