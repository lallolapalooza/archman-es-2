NOMBRE

xfs_quota - administra el uso de cuotas en sistemas de archivos XFS

SINOPSIS

xfs_quota [ -x ] [ -f ] [ -p programa ] [ -c comando ] ... [ -d proyecto ] ... [ -D archivo_proyectos ] [ -P archivo_idproyecto ] [ ruta ... ]
xfs_quota -V

DESCRIPCIÓN

xfs_quota es una utilidad para reportar y editar varios aspectos de la cuota del sistema de archivos.

Las opciones de xfs_quota son:

-c comando
Los comandos de xfs_quota se pueden ejecutar interactivamente (por defecto) o como argumentos en la línea de comandos. Se pueden proporcionar múltiples argumentos -c. Los comandos se ejecutan en la secuencia dada y luego el programa sale.
-p programa
Establece el nombre del programa para los avisos y algunos mensajes de error, el valor por defecto es xfs_quota.
-x
Habilita el modo experto. Todos los comandos administrativos (ver la sección COMANDOS DE ADMINISTRADOR a continuación) que permiten modificaciones en el sistema de cuotas están disponibles solo en modo experto.
-f
Habilita el modo de sistema de archivos extranjero. Un número limitado de comandos de usuario y administrativos están disponibles para usarlos en algunos sistemas de archivos extranjeros (no XFS).
-d proyecto
Se pueden especificar nombres de proyecto o identificadores numéricos con esta opción, lo que restringe la salida de los comandos individuales de xfs_quota al conjunto de proyectos especificados. Se pueden proporcionar múltiples argumentos -d.
-D archivo_proyectos
Especifica un archivo que contiene la correspondencia de identificadores numéricos de proyecto a árboles de directorios. /etc/projects como valor por defecto, si esta opción no se proporciona.
-P archivo_idproyecto
Especifica un archivo que contiene la correspondencia de identificadores numéricos de proyecto a nombres de proyecto. /etc/projid como valor por defecto, si esta opción no se proporciona.
-V
Imprime el número de versión y sale.

Los argumentos opcionales ruta se pueden usar para especificar puntos de montaje o archivos de dispositivo que identifiquen sistemas de archivos XFS. La salida de los comandos individuales de xfs_quota se restringirá entonces al conjunto de sistemas de archivos especificados.

Esta página del manual se divide en dos secciones: en primer lugar, información para los usuarios de sistemas de archivos con cuotas habilitadas y los comandos de xfs_quota de interés para dichos usuarios; y en segundo lugar, información que es útil solo para administradores de sistemas de archivos XFS que usan cuotas y los comandos de cuota que permiten modificaciones en el sistema de cuotas.

Tenga en cuenta que comunes a casi todos los comandos individuales descritos a continuación son las opciones para especificar qué tipos de cuota son de interés: cuota de usuario (-u), cuota de grupo (-g) y/o cuota de proyecto (-p). Además, varios comandos proporcionan opciones para operar sobre "bloques usados" (-b), "inodos usados" (-i), y/o "bloques en tiempo real usados" (-r).

Muchos comandos también tienen ayuda en línea exhaustiva. Utilice el comando help para obtener más detalles sobre cualquier comando.

RESUMEN DE CUOTAS

En la mayoría de los entornos informáticos, el espacio en disco no es infinito. El subsistema de cuotas proporciona un mecanismo para controlar el uso del espacio en disco. Las cuotas se pueden establecer para cada usuario individual en cualquiera/todos los sistemas de archivos locales. El subsistema de cuotas advierte a los usuarios cuando exceden su límite asignado, pero permite un espacio adicional para el trabajo actual (límite estricto/límite blando). Además, los sistemas de archivos XFS con la aplicación de límites deshabilitada se pueden utilizar como un sistema eficaz de contabilidad del uso del disco.

Vista de los usuarios de las cuotas de disco

Para la mayoría de los usuarios, las cuotas de disco son de poca importancia o un hecho de la vida que no se puede evitar. Hay dos cuotas posibles que se pueden imponer: se puede establecer un límite en la cantidad de espacio que un usuario puede ocupar, y puede haber un límite en el número de archivos (inodos) que pueden poseer.

El comando quota proporciona información sobre las cuotas que han sido establecidas por los administradores del sistema y el uso actual.

Hay cuatro números para cada límite: uso actual, límite blando (cuota), límite estricto y límite de tiempo. El límite blando es el número de bloques de 1K (o archivos) que se espera que el usuario mantenga por debajo. El límite estricto no se puede exceder. Si el uso de un usuario alcanza el límite estricto, las solicitudes posteriores de espacio (o intentos de crear un archivo) fallan con el error "Cuota excedida" (EDQUOT).

Cuando un usuario excede el límite blando, el temporizador se activa. Cada vez que la cuota cae por debajo de los límites blandos, el temporizador se desactiva. Si el temporizador se agota, el límite particular que se ha excedido se trata como si se hubiera alcanzado el límite estricto, y no se asignan más recursos al usuario. La única forma de restablecer esta condición, aparte de desactivar la aplicación de límites o aumentar el límite, es reducir el uso por debajo de la cuota. Solo el superusuario (es decir, un proceso suficientemente capaz) puede establecer los límites de tiempo y esto se hace por sistema de archivos.

Sobrevivir cuando se alcanza el límite de cuota

En la mayoría de los casos, la única forma para que un usuario se recupere de las condiciones de sobrecuota es abortar cualquier actividad que esté en curso en el sistema de archivos que haya alcanzado su límite, eliminar suficientes archivos para que el límite vuelva a estar por debajo de la cuota, y reintentar el programa fallido.
Sin embargo, si un usuario está en el editor y una escritura falla debido a una situación de sobrecuota, esa no es una acción adecuada. Lo más probable es que el intento inicial de escribir el archivo haya truncado su contenido anterior, por lo que si el editor se aborta sin escribir correctamente el archivo, no solo se pierden los cambios recientes, sino posiblemente gran parte, o incluso todo, del contenido que existía anteriormente.
Hay varias salidas seguras posibles para un usuario atrapado en esta situación. Pueden usar el comando de escape del editor a la shell para examinar su espacio de archivos y eliminar archivos excedentes. Alternativamente, usando sh(1), pueden suspender el editor, eliminar algunos archivos y luego reanudarlo. Una tercera posibilidad es escribir el archivo en algún otro sistema de archivos (quizás en un archivo en /tmp) donde la cuota del usuario no haya sido excedida. Luego, después de rectificar la situación de cuota, el archivo se puede mover de nuevo al sistema de archivos al que pertenece.

Cuotas por defecto

El subsistema de cuotas XFS permite aplicar una cuota por defecto para cualquier usuario, grupo o proyecto que no tenga un límite de cuota explícitamente establecido. Estos límites se almacenan y se muestran como los límites del ID 0, aunque en realidad no limitan al ID 0.

NAME

xfs_quota — XFS filesystem quota utility

SYNOPSIS

xfs_quota [ -v ] [ -x ] [ -c command ] [ -o option ] ... filesystem ...

DESCRIPTION

The xfs_quota utility is used to display and administer XFS filesystem quotas.

Quotas can be enforced on a per-user, per-group, or per-project basis. Project quotas are a newer feature that allows files to be associated with a project identifier, distinct from the owning user or group. See projects(5) for more detail.

The xfs_quota utility supports both user/group and project quotas. Project quotas are only available on kernels which have been configured with the CONFIG_XFS_QUOTA option, and require the filesystem to be mounted with the prjquota option.

User and group quotas are enabled by mounting the filesystem with the usrquota or grpquota mount options respectively.

To provide these quotas, XFS uses a quota file on the filesystem. For user quotas, this file is aquota.user. For group quotas, it is aquota.group. For project quotas, it is aquota.project. These files must be created on the filesystem, and the filesystem must be mounted with the appropriate quota options.

The following is a list of the options supported by xfs_quota:

-c command
Execute the specified command. Multiple commands can be specified by using this option multiple times. The commands are executed sequentially. See the QUOTA ADMINISTRATION and DIRECTORY TREE QUOTA sections below for a list of available commands.
-v
Verbosely report actions. This option is useful when executing commands that modify quota files, such as limit or project.
-x
Enable the extended administration interface. This allows access to commands that modify quota files and settings. Without this option, only reporting commands are available.
-o option
Specify an extended option. Currently, the only supported option is prid= which can be used to specify a project ID when using the limit command.

QUOTA OVERVIEW

Quotas are a mechanism for limiting the disk space and number of files that can be used by users and groups on a filesystem. XFS supports user, group, and project quotas.

User quotas limit the amount of disk space and number of files that each individual user can consume.

Group quotas limit the amount of disk space and number of files that each group can consume.

Project quotas limit the amount of disk space and number of files that can be consumed by files belonging to a specific project. Project information is stored in the inode for each file, and is managed via the project command. Project quotas require the filesystem to be mounted with the prjquota option.

USER COMMANDS

The following commands are available when -x is not specified:

report [ -a ] [ -l ] [ -p ] [ -u ] [ -g ] [ -d ] [ -F format ] [ name/id ... ]
Report current disk usage and limits. Without any arguments, it reports usage and limits for all users, groups, and projects (if enabled).

Options:

-a
Report for all filesystems with quotas enabled.
-l
Report limits in addition to usage.
-p
Report project quotas.
-u
Report user quotas.
-g
Report group quotas.
-d
Report default limits (used for new files/directories).
-F format
Specify the output format. Supported formats include: normal, usermsg, grouptotals, projectmsg, projecttotals, defaultusermsg, defaultgrouptotals, defaultprojectmsg, defaultprojecttotals.
If name/id arguments are provided, only the specified users, groups, or projects are reported.
limit [ -u ] [ -g ] [ -p ] [ -d ] name/id quotas
Set limits for a user, group, or project. quotas is a comma-separated list of limits. See quota(1) for details on the format of quotas.
enable [ -a ] [ -u ] [ -g ] [ -p ]
Enable quotas on the specified filesystem(s). Without any arguments, enables all quota types on all filesystems.
disable [ -a ] [ -u ] [ -g ] [ -p ]
Disable quotas on the specified filesystem(s).

QUOTA ADMINISTRATION

The following commands are available when -x is specified:

off [ -a ] [ -u ] [ -g ] [ -p ]
Turn off disk quota enforcement for the specified filesystem(s). Equivalent to disable.
on [ -a ] [ -u ] [ -g ] [ -p ]
Turn on disk quota enforcement for the specified filesystem(s). Equivalent to enable.
remove [ -a ] [ -u ] [ -g ] [ -p ]
Remove the quota files from the specified filesystem(s). This effectively resets all quota information.
resize [ -u ] [ -g ] [ -p ]
Resize quota files to accommodate current usage. This is useful after enabling quotas on a filesystem with existing data.
settransid
Set transaction ID for quota files. This is only used internally by XFS.
quotaon
Enable quotas on the specified filesystem(s). Equivalent to on.
quotaoff
Disable quotas on the specified filesystem(s). Equivalent to off.
quotacheck [ -a ] [ -u ] [ -g ] [ -p ]
Verify filesystem quotas and reconstruct quota files if necessary. This command should be run periodically, or after filesystem corruption.
limit [ -u ] [ -g ] [ -p ] [ -d ] name/id quotas
Set limits for a user, group, or project. quotas is a comma-separated list of limits. See quota(1) for details on the format of quotas.
writeall
Write current limits to quota files. This is done automatically by the limit command, but can be useful for applying changes made directly to quota files.
print_fs
Print filesystem name and quota file path.
set_fs
Set filesystem name and quota file path.
print_user
Print user quota information.
set_user
Set user quota information.
print_group
Print group quota information.
set_group
Set group quota information.
print_proj
Print project quota information.
set_proj
Set project quota information.
print_dqinfo
Print quota file information.
set_dqinfo
Set quota file information.

DIRECTORY TREE QUOTA

Project quotas are managed using the project command. This command allows you to associate directory trees with project identifiers. Files created within these directory trees will inherit the project identifier of the tree.

The project command takes the following options:

-s
Setup a directory tree for project quota accounting. This option must be used when initially enabling project quotas on a directory tree. It recursively descends the specified directory tree, setting the project identifier on all files within the tree. This ensures that existing files are accounted to the project. A new file created within the tree will automatically be assigned the project ID of the directory it is created in.
-C
Clear a directory tree from project quota accounting. This option recursively descends the specified directory tree, clearing the project identifier from all files within the tree. This is useful when you no longer want to enforce project quotas on a particular directory tree.
-c
Check a directory tree for project quota accounting consistency. This option recursively descends the specified directory tree and reports any inodes that do not have the correct project identifier set, or if the project flag is not set. If the tree is consistent, nothing is reported.
-d level
Limit the recursion depth. -1 means infinite recursion (default). 0 means only the top-level directory is processed. 1 means the top-level directory and its immediate children are processed, and so on.
-p
Specify project paths directly on the command line, without needing to edit /etc/projects. If /etc/projects exists, it will still be used in addition to the paths specified on the command line.

A managed tree must be setup initially using the -s option to the project command. The specified project name or identifier is matched to one or more trees defined in /etc/projects, and these trees are then recursively descended to mark the affected inodes as being part of that tree. This process sets an inode flag and the project identifier on every file in the affected tree. Once this has been done, new files created in the tree will automatically be accounted to the tree based on their project identifier. An attempt to create a hard link to a file in the tree will only succeed if the project identifier matches the project identifier for the tree. The xfs_io utility can be used to set the project ID for an arbitrary file, but this can only be done by a privileged user.

A previously setup tree can be cleared from project quota control through use of the project -C option, which will recursively descend the tree, clearing the affected inodes from project quota control.

Finally, the project -c option can be used to check whether a tree is setup, it reports nothing if the tree is correct, otherwise it reports the paths of inodes which do not have the project ID of the rest of the tree, or if the inode flag is not set.

Option -d can be used to limit recursion level (-1 is infinite, 0 is top level only, 1 is first level ... ). Option -p adds possibility to specify project paths in command line without a need for /etc/projects to exist. Note that if projects file exists then it is also used.

EXAMPLES

Enabling quota enforcement on an XFS filesystem (restrict a user to a set amount of space).

# mount -o uquota /dev/xvm/home /home
# xfs_quota -x -c 'limit bsoft=500m bhard=550m tanya' /home
# xfs_quota -x -c report /home

Enabling project quota on an XFS filesystem (restrict files in log file directories to only using 1 gigabyte of space).

# mount -o prjquota /dev/xvm/var /var
# echo 42:/var/log >> /etc/projects
# echo logfiles:42 >> /etc/projid
# xfs_quota -x -c 'project -s logfiles' /var
# xfs_quota -x -c 'limit -p bhard=1g logfiles' /var

Same as above without a need for configuration files.

# rm -f /etc/projects /etc/projid
# mount -o prjquota /dev/xvm/var /var
# xfs_quota -x -c 'project -s -p /var/log 42' /var
# xfs_quota -x -c 'limit -p bhard=1g 42' /var

CAVEATS

The XFS allocation mechanism will always reserve the maximum amount of space required before proceeding with an allocation. If insufficient space for this reservation is available, due to the block quota limit being reached for example, this may result in the allocation failing even though there is sufficient space. Quota enforcement can thus sometimes happen in situations where the user is under quota and the end result of some operation would still have left the user under quota had the operation been allowed to run its course. This additional overhead is typically in the range of tens of blocks.

Both of these properties are unavoidable side effects of the way XFS operates, so should be kept in mind when assigning block limits.

BUGS

Quota support for filesystems with realtime subvolumes is not yet implemented, nor is the quota warning mechanism (the Linux warnquota(8) tool can be used to provide similar functionality on that platform).
