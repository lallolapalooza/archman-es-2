NOMBRE

xfsdump - Utilidad de volcado incremental del sistema de archivos XFS

SINOPSIS

xfsdump -h
xfsdump [ opciones ] -f destino [ -f destino ... ] sistema_de_archivos
xfsdump [ opciones ] - sistema_de_archivos
xfsdump -I [ subopt=valor ... ]

DESCRIPCIÓN

xfsdump realiza copias de seguridad de archivos y sus atributos en un sistema de archivos. Los archivos se vuelcan a medios de almacenamiento, un archivo regular o la salida estándar. Las opciones permiten al operador volcar todos los archivos, solo los archivos que han cambiado desde un volcado anterior, o solo los archivos contenidos en una lista de nombres de ruta.

La utilidad xfsrestore(8) repopulate un sistema de archivos con el contenido del volcado.

Cada invocación de xfsdump vuelca solo un sistema de archivos. Esa invocación se denomina sesión de volcado. La sesión de volcado divide el sistema de archivos en uno o más flujos de volcado, uno por destino. La división se realiza en orden de número de inodo del sistema de archivos (ino), en límites seleccionados para igualar el tamaño de cada flujo. Además, los puntos de ruptura entre flujos pueden estar en medio de archivos muy grandes (en límites de extensión) si es necesario para lograr una ecualización de tamaño de flujo razonable. Cada flujo de volcado puede abarcar varios objetos de medios, y un único objeto de medios puede contener varios flujos de volcado. El objeto de medios típico es un cartucho de cinta. El registro de objetos de medios el flujo de volcado como uno o más archivos de medios. Un archivo de medios es un volcado parcial autocontenido, destinado a minimizar el impacto de las caídas de medios en todo el flujo de volcado a expensas de aumentar el tiempo necesario para completar el volcado. De forma predeterminada, solo se escribe un archivo de medios, a menos que se especifique un tamaño de archivo de medios usando la opción -d. Otras técnicas, como hacer una segunda copia de la imagen de volcado, brindan más protección contra fallas de medios que múltiples archivos de medios.

xfsdump mantiene un inventario de volcado en línea en /var/lib/xfsdump/inventory. La opción -I muestra el contenido del inventario jerárquicamente. Los niveles de la jerarquía son: sistema de archivos, sesión de volcado, flujo y archivo de medios.

Las opciones de xfsdump son:

-a
Especifica que los archivos para los cuales el Sistema de Migración de Datos (DMF) tiene copias completas fuera de línea (archivos de doble estado) se traten como si estuvieran fuera de línea (OFL). Esto significa que los datos del archivo no serán volcados por xfsdump, lo que resultará en un archivo de volcado más pequeño. Si el archivo se restaura posteriormente, los datos del archivo seguirán siendo accesibles a través de DMF. Si se especifican tanto la 'opción -a' como la 'opción -z', la 'opción -a' tendrá prioridad (ver la opción '-z' a continuación).
-b tamaño_bloque
Especifica el tamaño del bloque, en bytes, que se utilizará para el volcado. Se debe especificar el mismo tamaño de bloque para restaurar la cinta. Si no se usa la opción -m, entonces -b no necesita ser especificado. En su lugar, se utilizará un tamaño de bloque predeterminado de 1Mb.
-c nombre_programa
Utiliza el programa especificado para alertar al operador cuando se requiera un cambio de medio. El programa de alerta es típicamente un script para enviar un correo electrónico o mostrar una ventana para llamar la atención del operador.
-d tamaño_archivo
Especifica el tamaño, en megabytes, de los archivos de medios de volcado. Si no se especifica, xfsdump volcará datos a cinta utilizando un único archivo de medios por objeto de medios. Es posible que sea necesario ajustar el tamaño del archivo de medios especificado si, por ejemplo, xfsdump no puede encajar un archivo de medios en una sola cinta.
-e
Permite excluir archivos del volcado. Esto hará que xfsdump omita los archivos que tienen el atributo de archivo "no volcar" establecido. Vea la sección "Exclusión de archivos individuales" a continuación para obtener detalles sobre cómo establecer este atributo de archivo.
-f destino [ -f destino ... ]
Especifica un destino de volcado. Un destino de volcado puede ser la ruta de un dispositivo (como una unidad de cinta), un archivo regular o una unidad de cinta remota (ver rmt(8)). Esta opción debe omitirse si se especifica la opción de salida estándar (un solo - precediendo la especificación del sistema de archivos de origen).
-l nivel
Especifica un nivel de volcado de 0 a 9. El nivel de volcado determina el volcado base al que es relativo este volcado. El volcado base es el volcado más reciente en un nivel inferior. Un volcado de nivel 0 es absoluto: se vuelcan todos los archivos. Un nivel de volcado donde 1 <= nivel <= 9 se denomina volcado incremental. Solo se vuelcan los archivos que han sido cambiados desde el volcado base. Los volcados de subárboles (ver la opción -s a continuación) no se pueden usar como base para volcados incrementales.
-m
Utiliza el protocolo de cinta mínimo para destinos de cinta no scsi o destinos de cinta remotos que no son unidades de cinta Linux scsi ni unidades de cinta IRIX. Esta opción no se puede usar sin especificar un tamaño de bloque a utilizar (ver la opción -b anterior).
-o
Sobrescribe la cinta. Con esta opción, xfsdump no lee la cinta primero para comprobar el contenido. Esta opción puede usarse si xfsdump no puede determinar el tamaño del bloque de una cinta.
-p intervalo
Hace que se impriman informes de progreso en el intervalo especificado. intervalo se da en segundos. El informe de progreso indica cuántos archivos se han volcado, el número total de archivos a volcar, el porcentaje de datos volcados y el tiempo transcurrido.
-q
La unidad de cinta de destino es una cinta QIC. Las cintas QIC solo usan un tamaño de bloque de 512 bytes, para lo cual xfsdump debe hacer concesiones especiales.
-s nombre_ruta [ -s nombre_ruta ... ]
Restringe el volcado a los archivos contenidos en los nombres de ruta especificados (subárboles). Un nombre_ruta debe ser relativo al punto de montaje del sistema de archivos. Por ejemplo, si un sistema de archivos está montado en /d2, el argumento nombre_ruta para el directorio /d2/users es ``users''. Un nombre_ruta puede ser un archivo o un directorio; si es un directorio, se vuelca toda la jerarquía de archivos y subdirectorios anclada en ese directorio. Los volcados de subárboles no se pueden usar como base para volcados incrementales (ver la opción -l anterior).
-t archivo
Establece la hora del volcado a la hora de modificación de archivo en lugar de usar la hora actual. xfsdump utiliza la hora del volcado para determinar qué archivos deben respaldarse durante un volcado incremental. Esta opción debe usarse al volcar instantáneas para que la hora del volcado coincida con la hora en que se tomó la instantánea. De lo contrario, los archivos modificados después de tomar una instantánea pueden omitirse en el siguiente volcado incremental.
-v nivel_verbosidad
-v subsistema=nivel_verbosidad[,subsistema=nivel_verbosidad,...]
Especifica el nivel de detalle utilizado para los mensajes que se muestran durante el curso del volcado. El argumento nivel_verbosidad puede pasarse como una cadena o un entero. Si se pasa como una cadena, los siguientes valores pueden usarse: silent, verbose, trace, debug o nitty. Si se pasa como un entero, se pueden usar valores de 0-5. Los valores 0-4 corresponden a las cadenas ya mencionadas. El valor 5 se puede usar para producir una depuración aún más detallada.

La primera forma de esta opción activa el registro de mensajes en todos los subsistemas de volcado. La segunda forma permite controlar el nivel de registro de mensajes por subsistema. Las dos formas se pueden combinar (ver el ejemplo a continuación). El argumento subsistema puede tomar uno de los siguientes valores: general, proc, drive, media, inventory, inomap y excluded_files.

Por ejemplo, para volcar el sistema de archivos raíz con el seguimiento activado para todos los subsistemas: 

# xfsdump -v trace -f /dev/tape /


Para habilitar el seguimiento a nivel de depuración para operaciones de unidad y medios: 

# xfsdump -v drive=debug,media=debug -f /dev/tape /


Para habilitar el seguimiento de todos los subsistemas y el seguimiento a nivel de depuración solo para las operaciones de unidad: 

# xfsdump -v trace,drive=debug -f /dev/tape /

-z tamaño
Especifica el tamaño máximo, en kilobytes, de los archivos que se incluirán en el volcado. Los archivos de mayor tamaño se excluirán del volcado, excepto los archivos de doble estado de DMF cuando se especifica la 'opción -a' (ver 'opción -a' arriba). Cuando se especifica, la 'opción -a' tiene prioridad sobre la 'opción -z'. El tamaño es una estimación basada en el número de bloques de disco realmente utilizados por el archivo, por lo que no incluye los huecos. En otras palabras, el tamaño se refiere a la cantidad de espacio que ocuparía el archivo en el volcado resultante. En una restauración interactiva, el archivo omitido es visible con 'ls' de xfsrestore y, aunque puede utilizar los comandos 'add' y 'extract', no se restaurará nada.
-A
No volcar atributos extendidos de archivos. Al volcar un sistema de archivos gestionado dentro de un entorno DMF, esta opción no debe utilizarse. DMF almacena el estado de migración de archivos dentro de atributos extendidos asociados a cada archivo. Si estos atributos no se preservan al restaurar el sistema de archivos, los archivos que estaban en estado migrado no podrán ser recuperados por DMF. Tenga en cuenta que los volcados que contienen atributos extendidos de archivos no se pueden restaurar con versiones anteriores de xfsrestore(8).
-B id_sesion
Especifica el ID de la sesión de volcado en la que se basará esta sesión de volcado. Si se especifica esta opción, las opciones -l (nivel) y -R (reanudar) no están permitidas. En su lugar, xfsdump determina si la sesión de volcado actual debe ser incremental y/o reanudarla, consultando el nivel y los atributos interrumpidos de la sesión base. Si la sesión base fue interrumpida, la sesión de volcado actual es una reanudación de esa base en el mismo nivel. De lo contrario, la sesión de volcado actual es un volcado incremental con un nivel uno mayor que el de la sesión base. Esta opción permite que los volcados incrementales y reanudados se basen en cualquier volcado anterior, en lugar de solo el más reciente.
-D
Controla qué directorios se respaldan durante un volcado incremental. Por defecto, los directorios no modificados se vuelcan si los archivos o directorios debajo de ellos han cambiado. Esto da como resultado un volcado autosuficiente: si se pierde un volcado base, o usted sabe que el archivo (s) que desea restaurar está en un volcado incremental, puede restaurar solo ese volcado sin cargar primero el (los) volcado (s) base. Sin embargo, este método requiere una travesía potencialmente costosa a través del sistema de archivos.

Cuando se especifica -D, los directorios no modificados no se vuelcan. Esto resulta en un volcado más rápido, pero los archivos terminarán en el directorio de huérfanos de xfsrestore(8), a menos que primero se cargue el (los) volcado (s) base.

-E
Pre-borrar medio. Si se especifica esta opción, el medio se borra antes de su uso. Se le pedirá confirmación al operador, a menos que también se especifique la opción -F.
-F
No preguntar al operador. Cuando xfsdump encuentra un objeto de medio que contiene datos que no son de xfsdump, xfsdump normalmente pide permiso al operador para sobrescribir. Con esta opción, la sobrescritura se realiza sin hacer preguntas. Cuando xfsdump encuentra el fin del medio durante un volcado, xfsdump normalmente pregunta al operador si se proporcionará otro objeto de medio. Con esta opción, el volcado se interrumpe en su lugar.
-I
Muestra el inventario de xfsdump (no se realiza ningún volcado). xfsdump registra cada sesión de volcado en un inventario en línea en /var/lib/xfsdump/inventory. xfsdump utiliza este inventario para determinar la base de los volcados incrementales. También es útil para identificar manualmente una sesión de volcado que se va a restaurar. Las subopciones para filtrar la visualización del inventario se describen más adelante.
-J
Inhibe la actualización normal del inventario. Esto es útil cuando el medio al que se está volcando se descartará o sobrescribirá.
-K
Genera un volcado de formato 2 en lugar del formato actual. Esto es útil si el volcado se restaurará en un sistema con un xfsrestore más antiguo que no entiende el formato de volcado actual. No se recomienda el uso de esta opción de lo contrario.
-L etiqueta_sesion
Especifica una etiqueta para la sesión de volcado. Puede ser cualquier cadena arbitraria de hasta 255 caracteres de longitud.
-M etiqueta [ -M etiqueta ... ]
Especifica una etiqueta para el primer objeto de medio (por ejemplo, cartucho de cinta) escrito en el destino correspondiente durante la sesión. Puede ser cualquier cadena arbitraria de hasta 255 caracteres de longitud. Se pueden especificar múltiples etiquetas de objetos de medio, una para cada destino.
-O archivo_opciones
Inserta las opciones contenidas en archivo_opciones al principio de la línea de comandos. Las opciones se especifican tal como aparecerían si se escribieran en la línea de comandos. Además, se pueden usar caracteres de nueva línea (\n) como espacio en blanco. Las opciones se colocan antes de todas las opciones dadas en la línea de comandos, justo después del nombre del comando. Solo se puede usar una opción -O. El uso recursivo se ignora. El sistema de archivos de origen no se puede especificar en archivo_opciones.
-R
Reanuda una sesión de volcado previamente interrumpida. Si el volcado más reciente en este nivel de volcado (opción -l) fue interrumpido, este volcado contiene solo los archivos que no estaban en el volcado interrumpido y son consistentes con el nivel incremental. Sin embargo, los archivos contenidos en el volcado interrumpido que han sido modificados posteriormente se vuelven a volcar.
-T
Inhibe los tiempos de espera de diálogo interactivo. Cuando la opción -F no se especifica, xfsdump solicita al operador etiquetas y cambios de medio. Cada diálogo normalmente expira si no se proporciona ninguna respuesta. Esta opción evita el tiempo de espera.
-Y longitud
Especifica la longitud del anillo de búfer de E/S. xfsdump utiliza un anillo de búferes de salida para lograr el máximo rendimiento al volcar a unidades de cinta. La longitud del anillo predeterminada es 3. Sin embargo, esto aún no está habilitado en Linux, lo que hace que esta opción sea benigna.
-
Un único - hace que la secuencia de volcado se envíe a la salida estándar, donde puede ser canalizada a otra utilidad como xfsrestore(8) o redirigida a un archivo. Esta opción no se puede usar con la opción -f. El - debe seguir a todas las demás opciones y preceder a la especificación del sistema de archivos.

El sistema de archivos, sistema_archivos, se puede especificar ya sea como un punto de montaje o como un archivo de dispositivo especial (por ejemplo, /dev/dsk/dks0d1s0). El sistema de archivos debe estar montado para ser volcado.

NOTAS

Interrupción del volcado

Un volcado se puede interrumpir en cualquier momento y reanudar más tarde. Para interrumpir, escriba control-C (o el carácter de interrupción actual del terminal). Se le pedirá al operador que seleccione una de varias operaciones, incluida la interrupción del volcado. Después de que el operador seleccione la interrupción del volcado, el volcado continúa hasta que se encuentra un punto de ruptura conveniente (típicamente el final del archivo actual). Los archivos muy grandes se dividen en subarchivos más pequeños, por lo que la espera del final del archivo actual es breve.

Reanudación del volcado

Un volcado previamente interrumpido se puede reanudar especificando la opción -R. Si el volcado más reciente en el nivel especificado fue interrumpido, el nuevo volcado no incluye archivos ya volcados, a menos que hayan cambiado desde el volcado interrumpido.

Gestión de medios

Un solo objeto de medio puede contener muchas secuencias de volcado. Por el contrario, una sola secuencia de volcado puede abarcar múltiples objetos de medio. Si una secuencia de volcado se envía a un objeto de medio que ya contiene uno o más volcados, xfsdump agrega la nueva secuencia de volcado después de la última secuencia de volcado. Los archivos de medio nunca se sobrescriben. Si se encuentra el fin del medio durante el curso de un volcado, se le pide al operador que inserte un nuevo objeto de medio en la unidad. La continuación de la secuencia de volcado se agrega después del último archivo de medio en el nuevo objeto de medio.

Inventario

Cada sesión de volcado actualiza una base de datos de inventario en /var/lib/xfsdump/inventory. xfsdump utiliza el inventario para determinar la base de los volcados incrementales y reanudados.

Esta base de datos se puede mostrar invocando xfsdump con la opción -I. La visualización utiliza sangría con tabulaciones para presentar el inventario jerárquicamente. El primer nivel es el sistema de archivos. El segundo nivel es la sesión. El tercer nivel es la secuencia de medio (actualmente solo se admite una secuencia). El cuarto nivel enumera secuencialmente los archivos de medio que componen la secuencia.

Las siguientes subopciones están disponibles para filtrar la visualización.

-I profundidad=n
(donde n es 1, 2 o 3) limita la profundidad jerárquica de la visualización. Cuando n es 1, solo se muestra la información del sistema de archivos del inventario. Cuando n es 2, solo se muestra información del sistema de archivos y de la sesión. Cuando n es 3, solo se muestra información del sistema de archivos, de la sesión y de la secuencia.
-I nivel=n
(donde n es el nivel de volcado) limita la visualización a los volcados de ese nivel de volcado en particular.

La visualización puede restringirse a los archivos de medio contenidos en un objeto de medio específico.

-I mobjid=valor
(donde valor es un ID de medio) especifica el objeto de medio por su ID de medio.
-I mobjlabel=valor
(donde valor es una etiqueta de medio) especifica el objeto de medio por su etiqueta de medio.

De manera similar, la visualización se puede restringir a un sistema de archivos específico.

-I mnt=punto_montaje
(es decir, [nombre_host:]ruta_acceso), identifica el sistema de archivos por su punto de montaje. Especificar el nombre de host es opcional, pero puede ser útil en un entorno de clúster donde más de un host puede ser responsable de

NAME

xfsdump - backup an XFS filesystem

SYNOPSIS

xfsdump [ -AgGiy ] [ -c compressor ] [ -d daemon ] [ -f dfile ] [ -l level ] [ -m ] [ -o options ] [ -P prog ] [ -r ] [ -s subdirs ] [ -t time ] [ -v verbose ] [ -z bytes ] [ - ] [ pathname ]

DESCRIPTION

xfsdump is a utility for backing up XFS filesystems. It produces files or data streams containing all the information required to restore a filesystem from a particular point in time.

The backup is performed by traversing the specified filesystem (or subtree) and writing the contents of the files, along with their associated metadata, to a specified destination. The destination may be a regular file, a tape device, or standard output. Dumps can be created as either a single contiguous stream, or as a set of multiple, independent streams.

The destination is specified using the -f option. This option may be specified multiple times to specify multiple destinations for a multi-stream dump. A single stream dump is the default if only one -f option is specified.

The dump is fully described by a set of inventory files, which are stored in the directory /var/lib/xfsdump. The inventory is used by xfsrestore to determine which dumps to restore and from where.

The dump level determines the type of dump. A level 0 dump is a full dump. A dump at level N, where N is greater than 0, is an incremental dump. An incremental dump contains only the files that have changed since the last dump at a level less than N.

The contents of the inventory files are not dumped, even if the directory containing the inventory is part of the filesystem being dumped. This is to prevent the possibility of restoring an old version of the inventory, overwriting the current version, and causing data loss.

See the DIAGNOSTICS section for a description of the dump status messages.

Options

-A
Only process files with the A time attribute set. The A time attribute is described in xfsattr(5). Setting this attribute is a way of marking files for special backup treatment.
-c compressor
Use the specified compressor to compress the dump stream. The available compressors are listed in the xfsdump(8) man page. This option is only available if xfsdump has been compiled with compression support.
-d daemon
Use the specified daemon to handle the dump stream. The default daemon is rmtd. This option is used when dumping to a remote tape device.
-f dfile
Specifies the destination for the dump file. This can be a regular file, a tape device, or standard output (indicated by a hyphen). This option may be specified multiple times for a multi-stream dump. If only one -f option is specified, the dump is a single-stream dump. If multiple -f options are specified, the dump is a multi-stream dump, with each stream written to a separate destination.
-G
When dumping to a tape device, request that the device be rewound after the dump is complete. This is the default behavior for tape devices.
-g
When dumping to a tape device, do not rewind the tape after the dump is complete. This is the default behavior for non-tape devices.
-I [filter,...]
Show the inventory, rather than performing a dump. The optional filters limit the display to inventory entries matching the filters. See the Inventory Filters section below for details.
-i
Interactive mode. When this option is specified, xfsdump prompts the user for confirmation before dumping each file. This is useful for creating small, customized dumps.
-l level
Specifies the dump level. level must be an integer between 0 and 9. Level 0 is a full dump. Levels 1-9 are incremental dumps. The default level is 0.
-m
Minimal rmt protocol. Use this option when dumping to a remote tape device that does not support the full rmt protocol.
-o options
Specify dump options. The following options are supported:
append
Append to an existing dump file. This is only supported for regular files.
build
Build the dump inventory file. This is the default behavior.
bytesex=order
Set the byte sex of the dump file to order. Supported values are little and big.
noresume
Do not allow the dump to be resumed. If the dump is interrupted, it must be restarted from the beginning.
oldtmp
Use the old temporary file format. This is for compatibility with older versions of xfsrestore.
overwrite
Overwrite an existing dump file. This is the default behavior for tape devices.
quit
Quit if a media error occurs. This is the default behavior.
uncompress
Do not compress the dump stream. This is the default behavior.
-P prog
Specifies the program to be used for alerting the operator when a media change is required. The default program is builtin(5).
-r
Rebuild the dump inventory file from the specified dump file. This is used to restore the inventory if it has been lost or corrupted.
-s subdirs
Limit the dump to the specified subdirectories. subdirs is a comma-separated list of subdirectory paths. If this option is specified, only the specified subdirectories (and their contents) will be dumped.
-t time
Only dump files that have changed since the specified time. The time must be in the format YYYYMMDDhhmmSS.
-v verbose
Set the verbosity level. verbose is an integer between 0 and 9. Higher values provide more detailed output.
-y
Do not prompt for confirmation before starting the dump. This option can only be used if the dump level is 0.
-z bytes
Do not dump files larger than the specified number of bytes. This option is useful for excluding large files such as temporary files or core dumps.
-
Dump to standard output. This is equivalent to using -f -.

Inventory Filters

The -I option can be used to filter the dump inventory. The following filters are supported:

depth=depth
Limit the display to dumps at the specified depth in the filesystem hierarchy. A depth of 0 means only the root filesystem is displayed. A depth of 1 means the root filesystem and its direct subdirectories are displayed, and so on.
level=level
Limit the display to dumps at the specified dump level.
mnt=mount_point
Limit the display to dumps of the filesystem that was mounted at the specified mount_point at the time of the dump.
mobjlabel=label
Limit the display to dumps that were written to the media object with the specified label.
mobjid=id
Limit the display to dumps that were written to the media object with the specified id.
sessionlabel=label
Limit the display to dumps belonging to the session with the specified label.
sessionid=id
Limit the display to dumps belonging to the session with the specified id.
fsid=filesystem_id
identifies the filesystem by filesystem ID.
dev=device_pathname
(that is, [hostname:]device_pathname) identifies the filesystem by device. As with the mnt filter, specifying the hostname is optional.

More than one of these suboptions, separated by commas, may be specified at the same time to limit the display of the inventory to those dumps of interest. However, at most four suboptions can be specified at once: one to constrain the display hierarchy depth, one to constrain the dump level, one to constrain the media object, and one to constrain the filesystem.

For example, -I depth=1,mobjlabel="tape 1",mnt=host1:/test_mnt would display only the filesystem information (depth=1) for those filesystems that were mounted on host1:/test_mnt at the time of the dump, and only those filesystems dumped to the media object labeled "tape 1".

Dump records may be removed (pruned) from the inventory using the xfsinvutil program.

An additional media file is placed at the end of each dump stream. This media file contains the inventory information for the current dump session. Its contents may be merged back into the online inventory database at a later time using xfsrestore(1M).

The inventory files stored in /var/lib/xfsdump are not included in the dump, even if that directory is contained within the filesystem being dumped. Including the inventory in the dump may lead to loss or corruption of data, should an older version be restored overwriting the current version. To backup the xfsdump inventory, the contents of /var/lib/xfsdump should be copied to another location which may then be safely dumped. Upon restoration, those files may be copied back into /var/lib/xfsdump, overwriting whatever files may be there, or xfsinvutil(1M) may be used to selectively merge parts of the restored inventory back into the current inventory. Prior to version 1.1.8, xfsdump would include the /var/lib/xfsdump directory in the dump. Care should be taken not to overwrite the /var/lib/xfsdump directory when restoring an old dump, by either restoring the filesystem to another location or by copying the current contents of /var/lib/xfsdump to a safe place prior to running xfsrestore(1M).

Labels

The operator can specify a label to identify the dump session and a label to identify a media object. The session label is placed in every media file produced in the course of the dump, and is recorded in the inventory.

The media label is used to identify media objects, and is independent of the session label. Each media file on the media object contains a copy of the media label. An error is returned if the operator specifies a media label that does not match the media label on a media object containing valid media files. Media labels are recorded in the inventory.

UUIDs

UUIDs (Universally Unique Identifiers) are used in three places: to identify the filesystem being dumped (using the filesystem UUID, see xfs(5) for more details), to identify the dump session, and to identify each media object. The inventory display (-I) includes all of these.

Dump Level Usage

The dump level mechanism provides a structured form of incremental dumps. A dump of level level includes only files that have changed since the most recent dump at a level less than level. For example, the operator can establish a dump schedule that involves a full dump every Friday and a daily incremental dump containing only files that have changed since the previous dump. In this case Friday's dump would be at level 0, Saturday's at level 1, Sunday's at level 2, and so on, up to the Thursday dump at level 6.

The above schedule results in a very tedious restore procedure to fully reconstruct the Thursday version of the filesystem; xfsrestore would need to be fed all 7 dumps in sequence. A compromise schedule is to use level 1 on Saturday, Monday, and Wednesday, and level 2 on Sunday, Tuesday, and Thursday. The Monday and Wednesday dumps would take longer, but the worst case restore requires the accumulation of just three dumps, one each at level 0, level 1, and level 2.

Quotas

If the filesystem being dumped contains user quotas, xfsdump will use xfs_quota(8) to store the quotas in a file called xfsdump_quotas in the root of the filesystem to be dumped. This file will then be included in the dump. Upon restoration, xfs_quota (8) can be used to reactivate the quotas for the filesystem. Note, however, that the xfsdump_quotas file will probably require modification to change the filesystem or UIDs if the filesystem has been restored to a different partition or system. Group and project quotas will be handled in a similar fashion and saved in files called xfsdump_quotas_group and xfsdump_quotas_proj , respectively.

Excluding individual files

It may be desirable to exclude particular files or directories from the dump. The -s option can be used to limit the dump to a specified directory, and the -z option can be used to exclude files over a particular size. Additionally, when xfsdump is run with the -e option, files that are tagged with the "no dump" file attribute will not be included in the dump. The chattr(1) command can be used to set this attribute on individual files or entire subtrees.

To tag an individual file for exclusion from the dump: 

$ chattr +d file


To tag all files in a subtree for exclusion from the dump: 

$ chattr -R +d directory


Note that any new files or directories created in a directory which has the "no dump" attribute set will automatically inherit this attribute. Also note that xfsdump does not check directories for the "no dump" attribute.

Care should be taken to note which files have been tagged. Under normal operation, xfsdump will only report the number of files it will skip. The -v excluded_files=debug option, however, will cause xfsdump to list the inode numbers of the individual files affected.

EXAMPLES

To perform a level 0, single stream dump of the root filesystem to a locally mounted tape drive, prompting for session and media labels when required: 

# xfsdump -f /dev/tape /


To specify session and media labels explicitly: 

# xfsdump -L session_1 -M tape_0 -f /dev/tape /


To perform a dump to a remote tape using the minimal rmt protocol and a set blocksize of 64k: 

# xfsdump -m -b 65536 -f otherhost:/dev/tape /


To perform a level 0, multi-stream dump to two locally mounted tape drives: 

# xfsdump -L session_2 -f /dev/rmt/tps4d6v -M tape_1 \
          -f /dev/rmt/tps5d6v -M tape_2 /


To perform a level 1 dump relative to the last level 0 dump recorded in the inventory: 

# xfsdump -l 1 -f /dev/tape /


To copy the contents of a filesystem to another directory (see xfsrestore(8)): 

# xfsdump -J - / | xfsrestore -J - /new

DIAGNOSTICS

The exit code is 0 on normal completion, non-zero if an error occurs or the dump is terminated by the operator.

For all verbosity levels greater than 0 (silent) the final line of the output shows the exit status of the dump. It is of the form: 

xfsdump: Dump Status: code


Where code takes one of the following values: SUCCESS (normal completion), INTERRUPT (interrupted), QUIT (media no longer usable), INCOMPLETE (dump incomplete), FAULT (software error), and ERROR (resource error). Every attempt will be made to keep both the syntax and the semantics of this log message unchanged in future versions of xfsdump. However, it may be necessary to refine or expand the set of exit codes, or their interpretation at some point in the future.

The message ``xfsdump: WARNING: unable to open directory: ino N: Invalid argument'' can occur with filesystems which are actively being modified while xfsdump is running. This can happen to either directory or regular file inodes - affected files will not end up in the dump, files below affected directories will be placed in the orphanage directory by xfsrestore.

BUGS

xfsdump does not dump unmounted filesystems.

The dump frequency field of /etc/fstab is not supported.

xfsdump uses the alert program only when a media change is required.

xfsdump requires root privilege (except for inventory display).

xfsdump can only dump XFS filesystems.

The media format used by xfsdump can only be understood by xfsrestore.

xfsdump does not know how to manage CD-ROM or other removable disk drives.

xfsdump can become confused when doing incremental or resumed dumps if on the same machine you dump two XFS filesystems and both filesystems have the same filesystem identifier (UUID). Since xfsdump uses the filesystem identifier to identify filesystems, xfsdump maintains one combined set of dump inventories for both filesystems instead of two sets of dump inventories. NAME

xfsdump — XFS filesystem dump utility

SYNOPSIS

xfsdump [-c file] [-C] [-d device] [-f file] [-l level] [-m] [-r] [-s path] [-u] [-v] [-z] [-B] [-h hostname] [-i] [-t file] [-a] [-k command] [-p program] [-e program] [-o] [-?] [device]

DESCRIPTION

xfsdump is a utility for backing up the contents of an XFS filesystem. It can perform full or incremental backups. Backups can be written to regular files or raw devices.

The backup is a stream of file data and metadata. xfsdump can also dump the entire filesystem in a single operation, in which case it would be a full dump.

xfsdump can also be used to dump a single file or directory within the filesystem.

Incremental dumps are supported. The level of an incremental dump is specified with the -l option. A level 0 dump is a full dump. A level 1 dump contains all files changed since the last level 0 dump. A level 2 dump contains all files changed since the last level 1 dump, and so on.

The dump can be written to a regular file or a raw device. The output file can be compressed using the -z option.

xfsdump can also be used to create a copy of the filesystem using the -r option. This option is useful for creating a clone of the filesystem.

NOTES

xfsdump is intended to be used on unmounted filesystems. If the filesystem is mounted, xfsdump will attempt to dump it, but the results may not be consistent.

If you are backing up a mounted filesystem, it is recommended that you use the -r option to create a consistent snapshot of the filesystem.

xfsdump can be used to dump a single file or directory within the filesystem. This is useful for backing up specific files or directories.

The backup can be written to a regular file or a raw device. The output file can be compressed using the -z option.

EXAMPLES

To perform a full dump of the filesystem on /dev/sda1 to the file /backup/dump.xfs:

xfsdump -f /backup/dump.xfs /dev/sda1

To perform an incremental dump of level 1:

xfsdump -l 1 -f /backup/dump.xfs.1 /dev/sda1

To dump a single directory /home/user/data:

xfsdump -s /home/user/data -f /backup/dump.xfs.home /dev/sda1

FILES

/etc/xfsdump.conf: configuration file for xfsdump.

SEE ALSO

xfsrestore(8), xfs(5)

DIAGNOSTICS

xfsdump will print error messages to standard error if any errors occur.

BUGS

This utility may not work correctly if the filesystem was not created with XFS. For example, if a block-by-block copy program like dd or some other block-by-block copy program was used to make a copy of an XFS filesystem. See xfs_copy(8) and xfs(5) for more details.
