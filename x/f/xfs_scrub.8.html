NOMBRE

xfs_scrub - comprobar y reparar el contenido de un sistema de archivos XFS montado

SINOPSIS

xfs_scrub [ -abCeMmnpTvx ] punto-de-montaje
xfs_scrub -V

DESCRIPCIÓN

xfs_scrub intenta comprobar y reparar todos los metadatos en un sistema de archivos XFS montado.

xfs_scrub solicita al kernel que limpie todos los objetos de metadatos en el sistema de archivos. Los registros de metadatos se escanean en busca de valores obviamente incorrectos y luego se comparan con otros metadatos. El objetivo es establecer una confianza razonable sobre la consistencia del sistema de archivos general examinando la consistencia de los registros de metadatos individuales con los otros metadatos del sistema de archivos. Los metadatos dañados pueden reconstruirse a partir de otras estructuras de datos de metadatos si existen estructuras de datos redundantes que estén intactas.

La corrupción del sistema de archivos y las oportunidades de optimización se registrarán en el flujo de error estándar. Habilitar el modo detallado aumentará la cantidad de información de estado enviada a la salida.

Si la limpieza del kernel informa que los metadatos necesitan reparaciones u optimizaciones y el usuario no pasa -n en la línea de comandos, este programa le pedirá al kernel que realice las reparaciones y realice las optimizaciones. Consulte las secciones sobre optimizaciones y reparaciones para ver una lista de las optimizaciones y reparaciones conocidas por este programa. Es posible que el kernel no admita la reparación u optimización del sistema de archivos. Si este es el caso, el sistema de archivos debe desmontarse y ejecutar xfs_repair(8) en el sistema de archivos para solucionar los problemas.

OPCIONES

-a errores
Abortar si se encuentran más de esta cantidad de errores en el sistema de archivos.
-b
Ejecutar en modo de fondo. Si la opción se especifica una vez, solo se ejecutará un hilo de limpieza a la vez. Si se proporciona más de una vez, se agregará un retraso artificial de 100 us a cada llamada de limpieza para reducir aún más la sobrecarga de la CPU.
-C fd
Esta opción hace que xfs_scrub escriba información de progreso en la descripción del archivo especificada para que se pueda monitorear el progreso de la verificación del sistema de archivos. Si la descripción del archivo es una tty, se renderizará una barra de progreso elegante. De lo contrario, se generará una simple volcada de estado numérico compatible con el formato fsck -C.
-e
Especifica qué sucede cuando se detectan errores. Si se proporciona shutdown, el sistema de archivos se desconectará si se encuentran errores. Si se proporciona continue, no se tomará ninguna acción si se encuentran errores; este es el comportamiento predeterminado.
-k
No llamar a TRIM en el espacio libre.
-M punto-de-montaje-real
Abrir esta ruta para emitir llamadas de sistema de limpieza al kernel. El parámetro posicional punto-de-montaje se utilizará para mostrar mensajes informativos y para el registro. Este parámetro existe para habilitar el sandboxing de procesos para el modo de servicio.
-m archivo
Buscar en este archivo los sistemas de archivos montados en lugar de /etc/mtab.
-n
Solo comprobar los metadatos del sistema de archivos. No reparar ni optimizar nada.

-o subopt[=valor] Anular lo que el programa pueda concluir sobre el sistema de archivos si se deja por su cuenta.

Las subopciones admitidas son:
autofsck
Decidir el modo de operación a partir del valor de la propiedad del sistema de archivos autofsck. Consulte la sección propiedades del sistema de archivos para obtener más detalles.
fstrim_pct=porcentaje
Para limitar el tiempo dedicado a las actividades de fstrim durante la fase 8, este programa intenta equilibrar el tiempo de ejecución estimado con la completitud del recorte. En resumen, el programa evita solicitudes de recorte pequeñas para ahorrar tiempo.

Durante la fase 7, se construye un histograma de escala logarítmica de los extentos de espacio libre. Al comienzo de la fase 8, se calcula un CDF en orden decreciente de longitud de extento de los cubos del histograma. Se elige un punto que corresponde al objetivo de porcentaje de fstrim del CDF y se mapea de nuevo a un cubo del histograma. Se recortan los extentos de espacio libre que son al menos tan largos como el tamaño del cubo. Los extentos más pequeños se ignoran.

Por defecto, el umbral de porcentaje es 99%.

iwarn
Tratar los mensajes informativos como advertencias. Esto resultará en un código de retorno distinto de cero y un nivel de registro más alto.
-p
Solo optimizar los metadatos del sistema de archivos. Si se requieren reparaciones, informarlas y salir.
-T
Imprimir información de tiempo y uso de memoria para cada fase.
-v
Habilitar el modo detallado, que imprime actualizaciones de estado periódicas.
-V
Imprime el número de versión y sale.
-x
Leer todos los extentos de datos de archivos para buscar errores de disco. xfs_scrub emitirá lecturas O_DIRECT directamente al dispositivo de bloques. Si el dispositivo de bloques es un disco SCSI, emitirá comandos READ VERIFY directamente al disco. Si se encuentran errores de medios, el informe de error incluirá el desplazamiento del disco, en bytes. Si los errores de medios afectan a un archivo, el informe también incluirá el número de inodo y el desplazamiento del archivo, en bytes. Estas acciones confirmarán que todos los bloques de datos de archivos se pueden leer del almacenamiento.

OPTIMIZACIONES

Las optimizaciones admitidas por este programa incluyen, entre otras:

•
Instruir al almacenamiento subyacente para que elimine los extentos no utilizados a través del ioctl TRIM.
•
Actualizar los superbloques secundarios para que coincidan con el superbloque primario.
•
Desactivar las comprobaciones de escritura de bloques compartidos para archivos que ya no comparten bloques.

REPARACIONES

Las reparaciones se realizan llamando al kernel. Esto limita el alcance de las actividades de reparación a la reconstrucción de estructuras de datos primarias a partir de estructuras de datos secundarias, o estructuras secundarias a partir de estructuras primarias. La existencia de estructuras de datos secundarias puede requerir características que solo se pueden activar desde mkfs.xfs(8). Si los errores no pueden ser reparados, el sistema de archivos debe desmontarse y ejecutar xfs_repair(8). Las reparaciones admitidas por el kernel incluyen, entre otras:

•
Reconstrucción de datos de asignación de extentos.
•
Reconstrucción de información de espacio libre.
•
Reconstrucción de índices de inodos.
•
Corrección de corrupciones menores de registros de inodos.
•
Recalculo de información de recuento de referencias.
•
Reconstrucción de datos de mapeo inverso a partir de datos de asignación de extentos primarios.
•
Programación de un quotacheck para el próximo montaje.

Si los metadatos corruptos se reparan con éxito, este programa registrará que una reparación ha tenido éxito en lugar de un informe de corrupción.

PROPIEDADES DEL SISTEMA DE ARCHIVOS

Los administradores del sistema pueden transmitir sus preferencias para la limpieza de un sistema de archivos en particular estableciendo la propiedad del sistema de archivos autofsck a través del comando xfs_property(8) en el sistema de archivos. Estas preferencias se respetarán si se especifica la opción -o autofsck.

Los valores reconocidos para la propiedad autofsck son:

none
No escanear el sistema de archivos en absoluto.
check
Escanear e informar la corrupción y las oportunidades de optimización, pero no cambiar nada.
optimize
Escanear e informar la corrupción y las oportunidades de optimización, y realizar las optimizaciones, pero no reparar nada.
repair
Escanear e informar la corrupción y las oportunidades de optimización, y realizar las reparaciones y optimizaciones.

NAME

xfs_scrub - Check XFS filesystem for errors

SYNOPSIS

xfs_scrub [‑nrvsV]

xfs_scrub [‑nrvsV] [‑P property]

  specialfile...

DESCRIPTION

xfs_scrub performs filesystem checks on one or more XFS filesystems. It is intended as a safety net for detecting filesystem corruptions that may not be found by other mechanisms. It can also perform some optimizations.

The utility is designed to be run on an unmounted filesystem. Running it on a mounted filesystem is not supported and may lead to incorrect results or filesystem corruption.

The SCRUB_METADATA ioctl is used to perform the scrubbing operation. This ioctl is new and may not be supported by older kernels.

When xfs_scrub is run, it will iterate through all the metadata structures of the filesystem and verify their integrity. If corruptions are found, they will be reported. Depending on the options given, it may also attempt to repair them.

The filesystem is specified by the block special device file that corresponds to the mounted filesystem.

OPTIONS

The options are explained in the following sections.

OPTIMIZATIONS

When the filesystem is checked, xfs_scrub can also perform certain optimizations. These include relocating B-trees to reduce fragmentation and rebalancing them to improve performance.

REPAIRS

If the filesystem is found to be corrupt, xfs_scrub can attempt to repair the corruption. This may involve rewriting parts of the filesystem metadata.

FILESYSTEM PROPERTIES

xfs_scrub can be influenced by filesystem properties, which are set using the -P option. The following properties are supported:

check
Scan the filesystem and report corruptions, but do not fix them.
optimize
Scan the filesystem and optimize where possible. Report corruptions, but do not fix them.
repair
Scan the filesystem, fix corruptions, and optimize where possible.

If the property is not set, the default is check if the filesystem has either reverse mapping btrees or parent pointers enabled, or none otherwise.

EXIT CODE

The exit code returned by xfs_scrub is the sum of the following conditions:
0 - No errors
1 - File system errors left uncorrected
2 - File system optimizations possible
4 - Operational error
8 - Usage or syntax error

CAVEATS

xfs_scrub is an immature utility! Do not run this program unless you have backups of your data! This program takes advantage of in-kernel scrubbing to verify a given data structure with locks held and can keep the filesystem busy for a long time. The kernel must be new enough to support the SCRUB_METADATA ioctl.

If errors are found and cannot be repaired, the filesystem must be unmounted and repaired.
