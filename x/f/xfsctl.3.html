XFSCTL(3) Manual de Funciones de Librería XFSCTL(3)

NOMBRE

xfsctl - controlar sistemas de archivos XFS y archivos individuales

C SINOPSIS

#include <xfs/xfs.h>

int xfsctl(const char *path, int fd, int cmd, void *ptr);

int platform_test_xfs_fd(int fd);
int platform_test_xfs_path(const char *path);

DESCRIPCIÓN

Parte de la funcionalidad específica del sistema de archivos XFS es accesible a las aplicaciones a través de interfaces de llamadas al sistema específicas de la plataforma. Estas operaciones se pueden dividir en dos secciones: operaciones que actúan sobre archivos individuales y operaciones que actúan sobre el sistema de archivos en sí. Se debe tener cuidado al emitir llamadas xfsctl() para asegurar que la ruta y el descriptor de archivo de destino (ambos deben proporcionarse) realmente representen un archivo de un sistema de archivos XFS. Las llamadas al sistema statfs(2) y fstatfs(2) se pueden usar para determinar si una ruta arbitraria o un descriptor de archivo pertenecen o no a un sistema de archivos XFS. Sin embargo, estos no son portátiles, por lo que las rutinas platform_test_xfs_fd() y platform_test_xfs_path() proporcionan un mecanismo independiente de la plataforma.

Operaciones de Archivo

Para realizar una operación sobre un archivo individual, la ruta y los argumentos del descriptor pasados a xfsctl identifican el archivo sobre el que se opera. El argumento final descrito a continuación se refiere al argumento final de xfsctl. Todas las estructuras de datos y macros mencionadas a continuación se definen en el archivo de cabecera <xfs/xfs_fs.h>.

XFS_IOC_ALLOCSP
XFS_IOC_ALLOCSP64
XFS_IOC_FREESP

XFS_IOC_FREESP64
Alterar el espacio de almacenamiento asociado con una sección del archivo ordinario especificado. La sección se especifica mediante una variable de tipo xfs_flock64_t, apuntada por el argumento final. El tipo de dato xfs_flock64_t contiene los siguientes miembros: l_whence es 0, 1 o 2 para indicar que el desplazamiento relativo l_start se medirá desde el inicio del archivo, la posición actual o el final del archivo, respectivamente (es decir, l_start es el desplazamiento desde la posición especificada en l_whence). Si el desplazamiento especificado está antes del final actual del archivo, cualquier dato escrito previamente en esta sección ya no es accesible. Si el desplazamiento especificado está más allá del final actual del archivo, el archivo se amplía y se rellena con ceros. El campo l_len se ignora actualmente y debe establecerse en cero.

Las operaciones XFS_IOC_ALLOCSP, XFS_IOC_ALLOCSP64, XFS_IOC_FREESP y XFS_IOC_FREESP64 son todas idénticas.

Estos ioctls ya no son compatibles a partir de Linux 5.17.

XFS_IOC_FSSETDM
Establecer los campos di_dmevmask y di_dmstate en un inodo XFS en disco. Los únicos valores legítimos para estos campos son los devueltos previamente en los campos bs_dmevmask y bs_dmstate de la estructura bulkstat. Los datos a los que se refiere el argumento final son una struct fsdmidata. Los miembros de esta estructura son fsd_dmevmask y fsd_dmstate. El campo di_dmevmask se establece al valor en fsd_dmevmask. El campo di_dmstate se establece al valor en fsd_dmstate. Este comando está restringido a root o a procesos con capacidades de gestión de dispositivos. Su único propósito es permitir que los programas de copia de seguridad y restauración restauren los campos críticos del inodo en disco mencionados anteriormente. Este ioctl no es compatible a partir de Linux 5.5.
XFS_IOC_DIOINFO
Obtener la información necesaria para realizar E/S directa en el descriptor de archivo especificado. La E/S directa se realiza directamente hacia y desde el búfer de datos de un usuario. Dado que la caché de búfer del kernel ya no está entre los dos, el búfer de datos del usuario debe cumplir con el mismo tipo de restricciones que se requieren para acceder a una partición de disco sin procesar. El argumento final apunta a una variable de tipo struct dioattr, que contiene los siguientes miembros: d_mem es el requisito de alineación de memoria del búfer de datos del usuario. d_miniosz especifica el tamaño del bloque, el tamaño mínimo de la solicitud de E/S y la alineación de E/S. El tamaño de todas las solicitudes de E/S debe ser un múltiplo de esta cantidad y el valor del puntero de búsqueda en el momento de la solicitud de E/S también debe ser un múltiplo entero de esta cantidad. d_maxiosz es el tamaño máximo de la solicitud de E/S que se puede realizar en el descriptor de archivo. Si una solicitud de E/S no cumple estas restricciones, la llamada read(2) o write(2) fallará con EINVAL. Todas las solicitudes de E/S se mantienen consistentes con cualquier dato traído a la caché con un acceso a través de un descriptor de archivo no directo.

XFS_IOC_RESVSP

XFS_IOC_RESVSP64
Este comando se utiliza para asignar espacio a un archivo. Se especifica un rango de bytes mediante un puntero a una variable de tipo xfs_flock64_t en el argumento final. Los bloques se asignan, pero no se rellenan con ceros, y el tamaño del archivo no cambia. Si el sistema de archivos XFS está configurado para marcar extensiones de archivo no escritas, el rendimiento se verá afectado negativamente al escribir en espacio preasignado, ya que se requieren transacciones adicionales del sistema de archivos para convertir las marcas de extensión en el rango del archivo escrito. Si xfs_info(8) informa unwritten=1, entonces el sistema de archivos se hizo para marcar extensiones no escritas.

XFS_IOC_UNRESVSP

XFS_IOC_UNRESVSP64
Este comando se utiliza para liberar espacio de un archivo. Se especifica un rango de bytes mediante un puntero a una variable de tipo xfs_flock64_t en el argumento final. Los bloques parciales del sistema de archivos se ponen a cero, y los bloques completos del sistema de archivos se eliminan del archivo. El tamaño del archivo no cambia.
XFS_IOC_ZERO_RANGE
Este comando se utiliza para convertir un rango de un archivo a ceros sin emitir E/S de datos. Se especifica un rango de bytes mediante un puntero a una variable de tipo xfs_flock64_t en el argumento final. Los bloques se preasignan para las regiones que abarcan agujeros en el archivo, y todo el rango se convierte en extensiones no escritas. Esta operación es un método rápido para sobrescribir cualquier parte del rango especificado con ceros sin eliminar ningún bloque ni tener que escribir ceros en el disco. Cualquier lectura posterior en el rango dado devolverá ceros hasta que se escriban nuevos datos. Esta funcionalidad requiere que los sistemas de archivos admitan extensiones no escritas. Si xfs_info(8) informa unwritten=1, entonces el sistema de archivos se hizo para marcar extensiones no escritas. 
XFS_IOC_PATH_TO_HANDLE
XFS_IOC_PATH_TO_FSHANDLE
XFS_IOC_FD_TO_HANDLE
XFS_IOC_OPEN_BY_HANDLE
XFS_IOC_READLINK_BY_HANDLE
XFS_IOC_ATTR_LIST_BY_HANDLE
XFS_IOC_ATTR_MULTI_BY_HANDLE
XFS_IOC_FSSETDM_BY_HANDLE
Estas son todas interfaces que se utilizan para implementar varias funciones de libhandle (ver open_by_handle(3)). Todas están sujetas a cambios y no deben ser llamadas directamente por las aplicaciones. XFS_IOC_FSSETDM_BY_HANDLE no es compatible a partir de Linux 5.5.
