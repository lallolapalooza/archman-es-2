xfs_fsr(8) Manual del Administrador del Sistema xfs_fsr(8)

NOMBRE

xfs_fsr - reorganizador de sistemas de archivos para XFS

SINOPSIS

xfs_fsr [-vdg] 
[-t segundos] [-p pasadas] [-f leftoff] [-m mtab]
xfs_fsr [-vdg] 
[xfsdev | archivo] ...
xfs_fsr -V

DESCRIPCIÓN

xfs_fsr solo es aplicable a sistemas de archivos XFS.

xfs_fsr mejora la organización de sistemas de archivos montados. El algoritmo de reorganización opera sobre un archivo a la vez, compactando o mejorando de otro modo la disposición de los extents del archivo (bloques contiguos de datos de archivo).

Las siguientes opciones son aceptadas por xfs_fsr. Las opciones -m, -t y -f no tienen significado si se especifican sistemas de archivos o archivos en la línea de comandos.

-m mtab
Usa este archivo para la lista de sistemas de archivos a reorganizar. El valor predeterminado es usar /etc/mtab.
-t segundos
Cuánto tiempo reorganizar. El valor predeterminado es 7200 segundos (2 horas).
-p pasadas
Número de pasadas antes de terminar la reorganización global. El valor predeterminado es 10 pasadas.
-f leftoff
Usa este archivo en lugar de /var/tmp/.fsrlast para leer el estado de dónde empezar y como archivo para almacenar el estado de dónde se detuvo la reorganización.
-v
Detallado. Imprime información críptica sobre cada archivo que se está reorganizando.
-d
Depuración. Imprime información aún más críptica.
-g
Imprime a syslog (predeterminado si stdout no es una tty).
-V
Imprime el número de versión y sale.

Cuando se invoca sin argumentos, xfs_fsr reorganiza todos los archivos regulares en todos los sistemas de archivos montados. xfs_fsr realiza muchos ciclos sobre /etc/mtab, realizando una pasada sobre cada sistema de archivos XFS en cada ocasión. Cada pasada recorre y selecciona los archivos con el mayor número de extents. Intenta desfragmentar el 10% superior de estos archivos en cada pasada.

Se ejecuta hasta por dos horas, después de lo cual registra el sistema de archivos donde se detuvo, para poder comenzar allí la próxima vez. Esta información se almacena en el archivo /var/tmp/.fsrlast_xfs. Si la información encontrada aquí es de alguna manera inconsistente o desactualizada, se ignora y la reorganización comienza desde el principio del primer sistema de archivos encontrado en /etc/mtab.

xfs_fsr puede ser llamado con uno o más argumentos que nombran sistemas de archivos (nombre del dispositivo de bloque) y archivos a reorganizar. En este modo, xfs_fsr no lee ni escribe /var/tmp/.fsrlast_xfs, ni se ejecuta por un intervalo de tiempo fijo. Realiza una pasada por cada archivo regular especificado y todos los archivos regulares en cada sistema de archivos especificado. Un nombre en la línea de comandos que se refiere a un enlace simbólico (excepto a un dispositivo de sistema de archivos), FIFO o socket de dominio UNIX genera un mensaje de advertencia, pero de lo contrario se ignora. Mientras se recorre el sistema de archivos, estos tipos de archivos se omiten silenciosamente.

ARCHIVOS

/etc/mtab
contiene la lista predeterminada de sistemas de archivos a reorganizar.
/var/tmp/.fsrlast_xfs
registra el estado donde se detuvo la reorganización.

VER TAMBIÉN

xfs_fsr(8), mkfs.xfs(8), xfs_ncheck(8), xfs(5).

NOTAS

xfs_fsr mejora la disposición de los extents para cada archivo copiando el archivo completo a una ubicación temporal y luego intercambiando los extents de datos de los archivos de destino y temporales de manera atómica. Este método requiere que haya suficiente espacio libre en disco disponible para copiar cualquier archivo dado y que el espacio esté menos fragmentado que el archivo original. También requiere que el propietario del archivo tenga suficiente cuota de espacio de archivos restante para realizar la copia en sistemas que ejecutan cuotas. xfs_fsr genera un mensaje de advertencia si el espacio no es suficiente para mejorar el archivo de destino.

Un archivo temporal utilizado para mejorar un archivo dado en la línea de comandos se crea en el mismo directorio padre del archivo de destino y se antepone la cadena '.fsr'. Los archivos temporales utilizados para mejorar un dispositivo XFS completo se almacenan en un directorio en la raíz del dispositivo de destino y utilizan el mismo esquema de nomenclatura. Los archivos temporales se eliminan al crearse para que los datos no sean legibles por ningún otro proceso.

xfs_fsr no opera en archivos que están actualmente mapeados en memoria. Se puede ver un error de 'archivo ocupado' para estos archivos si se establece la opción detallada (-v).

Los archivos marcados como no-defrag serán omitidos. El comando xfs_io(8) chattr con el atributo f se puede usar para establecer o borrar esta bandera. Los archivos y directorios creados en un directorio con la bandera no-defrag heredarán el atributo.

Una entrada en /etc/mtab o el archivo especificado usando la opción -m debe tener la opción rw especificada para acceso de lectura y escritura. Si esta opción no está presente, entonces xfs_fsr omite el sistema de archivos descrito por esa línea. Consulte la página de referencia de fstab(5) para más detalles.

En general, no prevemos la necesidad de ejecutar xfs_fsr en particiones del sistema como /, /boot y /usr, ya que en general no sufrirán fragmentación. También existen problemas con la desfragmentación de archivos que lilo(8) usa para arrancar su sistema. Se recomienda que estos archivos se marquen como no-defrag con el comando xfs_io(8) chattr. Si estos archivos son movidos por xfs_fsr, entonces debe ejecutar lilo nuevamente antes de reiniciar o podría tener un sistema no arrancable.
