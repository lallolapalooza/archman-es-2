NOMBRE

xfsrestore - Utilidad de restauración incremental de sistemas de archivos XFS

SINOPSIS

xfsrestore -h
xfsrestore [ opciones ] -f fuente [ -f fuente ... ] destino
xfsrestore [ opciones ] - destino
xfsrestore -I [ subopt=valor ... ]

DESCRIPCIÓN

xfsrestore restaura sistemas de archivos a partir de copias de seguridad producidas por xfsdump(8). Hay dos modos de operación disponibles: simple y acumulativo.

El modo simple es el predeterminado. xfsrestore rellena el directorio de destino especificado, destino, con los archivos contenidos en los medios de copia de seguridad.

La opción -r especifica el modo acumulativo. Se utilizan invocaciones sucesivas de xfsrestore para aplicar una secuencia cronológicamente ordenada de copias de seguridad delta a una copia de seguridad base (nivel 0). Se reproduce el contenido del sistema de archivos en el momento en que se produjo cada copia de seguridad. Esto puede implicar añadir, eliminar, renombrar, enlazar y desenlazar archivos y directorios.

Una copia de seguridad delta se define como una copia de seguridad incremental (opción -l de xfsdump con nivel > 0) o una copia de seguridad reanudada (opción -R de xfsdump). Las deltas deben aplicarse en el orden en que se produjeron. Cada delta aplicado debe haberse producido con el delta aplicado anteriormente como base.

xfsrestore mantiene información de estado en el directorio xfsrestorehousekeepingdir, para informar a invocaciones posteriores cuando se utiliza en modo acumulativo o en caso de que una restauración se interrumpa. Para garantizar que la información de estado pueda ser procesada, se debe utilizar una versión compatible de xfsrestore para cada invocación sucesiva. Además, cada invocación debe ejecutarse en un sistema con la misma endianidad y tamaño de página.

Las opciones de xfsrestore son:

-a administración
Cada invocación de xfsrestore crea un directorio llamado xfsrestorehousekeepingdir. Este directorio se crea normalmente directamente debajo del directorio destino. La opción -a permite al operador especificar un directorio alternativo, administración, en el que xfsrestore crea el directorio xfsrestorehousekeepingdir. Al realizar una restauración acumulativa (opción -r) o al reanudar (opción -R) una restauración, cada invocación sucesiva debe especificar el mismo directorio alternativo.
-b tamaño_bloque
Especifica el tamaño de bloque, en bytes, que se utilizará para la restauración. Para otras unidades, como DAT o 8 mm , se debe especificar el mismo tamaño de bloque utilizado para la operación de xfsdump para restaurar la cinta. El tamaño de bloque predeterminado es 1 MB.
-c nombre_programa
Utiliza el programa especificado para alertar al operador cuando se requiere un cambio de medio. El programa de alerta suele ser un script para enviar un correo o mostrar una ventana para llamar la atención del operador.
-e
Evita que xfsrestore sobrescriba archivos existentes en el directorio destino.
-f fuente [ -f fuente ... ]
Especifica una fuente de la copia de seguridad que se va a restaurar. Puede ser la ruta de acceso de un dispositivo (como una unidad de cinta), un archivo regular o una unidad de cinta remota (consulte rmt(8)). Esta opción debe omitirse si se especifica la opción de entrada estándar (un solo - antes de la especificación de destino).
-i
Selecciona la operación interactiva. Una vez leída la jerarquía de directorios en el medio, se inicia un diálogo interactivo. El operador utiliza un pequeño conjunto de comandos para examinar la jerarquía de directorios, seleccionando archivos y subárboles para su extracción. Los comandos disponibles se dan a continuación. Inicialmente no se selecciona nada, excepto aquellos subárboles especificados con las opciones de línea de comandos -s.
ls [arg]
Lista las entradas en el directorio actual o en el directorio especificado, o la entrada de archivo no directorios especificada. Se muestran tanto el número de inodo original como el nombre de la entrada. Las entradas que son directorios se añaden con una `/'. Las entradas que han sido seleccionadas para extracción se anteponen con un `*'.
cd [arg]
Cambia el directorio de trabajo actual al argumento especificado, o al directorio raíz del sistema de archivos si no se especifica ningún argumento.
pwd
Imprime la ruta de acceso del directorio actual, relativa a la raíz del sistema de archivos.
add [arg]
El directorio actual o el archivo o directorio especificado dentro del directorio actual se selecciona para su extracción. Si se especifica un directorio, se seleccionan este y todos sus descendientes. Las entradas seleccionadas para extracción se anteponen con un `*' cuando se listan con ls.
delete [arg]
El directorio actual o el archivo o directorio especificado dentro del directorio actual se deselecciona para su extracción. Si se especifica un directorio, se deseleccionan este y todos sus descendientes. La forma más rápida de extraer la mayoría de los archivos de un directorio es seleccionar el directorio y luego deseleccionar los archivos que no se necesitan.
extract
Finaliza el diálogo interactivo y provoca que se restauren todos los subárboles seleccionados.
quit
xfsrestore finaliza el diálogo interactivo y sale inmediatamente, incluso si hay archivos o subárboles seleccionados para extracción.
help
Lista un resumen de los comandos disponibles.
-m
Utiliza el protocolo de cinta mínimo. Esta opción no se puede utilizar sin especificar un tamaño de bloque a utilizar (consulte la opción -b anterior).
-n archivo
Permite a xfsrestore restaurar solo archivos más nuevos que archivo. La hora de modificación de archivo (es decir, como se muestra con el comando ls -l) se compara con la hora de modificación del inodo de cada archivo en los medios de origen (es decir, como se muestra con el comando ls -lc). Un archivo se restaura desde los medios solo si su hora de modificación de inodo es mayor o igual a la hora de modificación de archivo.
-o
Restaura el propietario/grupo de archivos y directorios incluso si no es root. Cuando se ejecuta con un ID de usuario efectivo de root, xfsrestore restaura el propietario y el grupo de cada archivo y directorio. Cuando se ejecuta con cualquier otro ID de usuario efectivo, no lo hace, a menos que se especifique esta opción.
-p intervalo
Provoca que se impriman informes de progreso a intervalos de intervalo segundos. El valor del intervalo es aproximado, xfsrestore retrasará los informes de progreso para evitar una sobrecarga de procesamiento indebida.
-q
La unidad de cinta de origen es una cinta QIC. Las cintas QIC solo utilizan un tamaño de bloque de 512 bytes, para lo cual xfsrestore debe hacer concesiones especiales.
-r
Selecciona el modo de operación acumulativo. Las opciones -a y destino deben ser las mismas para cada invocación.
-s subárbol
Especifica un subárbol para restaurar. Se permiten cualquier número de opciones -s. La restauración se limita a la unión de todos los subárboles especificados. Cada subárbol se especifica como una ruta de acceso relativa al destino de restauración. Si se especifica un directorio, se restauran el directorio y todos los archivos debajo de ese directorio.
-t
Muestra el contenido de la copia de seguridad, pero no crea ni modifica ningún archivo o directorio. Puede ser conveniente establecer el nivel de verbosidad en silencioso al usar esta opción.
-x
Esta opción puede ser útil para solucionar un problema por el cual los archivos se restauran en un directorio huérfano debido a un problema de xfsdump (v3.1.7 - v3.1.9). No se puede restaurar una copia de seguridad normal con esta opción. Esta opción solo funciona para una copia de seguridad corrupta. Si una copia de seguridad se crea con un xfsdump problemático (v3.1.7 - v3.1.9), debería ver el contenido de la copia de seguridad con la opción -t b
antes de restaurar. Luego, si un archivo se coloca en el directorio de orfanato, deberá utilizar esta opción -x para restaurar la copia de seguridad. De lo contrario, podrá restaurar la copia de seguridad sin esta opción.

En el modo acumulativo, esta opción solo es necesaria para una copia de seguridad base (nivel 0). Ya no necesitará esta opción para copias de seguridad de nivel 1+ .

-v verbosidad
-v subsys=verbosidad[,subsys=verbosidad,...]
Especifica el nivel de detalle utilizado para los mensajes que se muestran durante el curso de la restauración. El argumento verbosidad puede pasarse como cadena o como entero. Si se pasa como cadena, se pueden utilizar los siguientes valores: silent, verbose, trace, debug, o nitty. Si se pasa como entero, se pueden utilizar valores de 0 a 5. Los valores 0-4 corresponden a las cadenas ya mencionadas. El valor 5 se puede utilizar para producir una salida de depuración aún más detallada.

La primera forma de esta opción activa el registro de mensajes en todos los subsistemas de restauración. La segunda forma permite controlar el nivel de registro de mensajes por subsistema. Las dos formas se pueden combinar (ver el ejemplo a continuación). El argumento subsys puede tomar uno de los siguientes valores: general, proc, drive, media, inventory, y tree.

Por ejemplo, para restaurar el sistema de archivos raíz con el rastreo activado para todos los subsistemas: 

# xfsrestore -v trace -f /dev/tape /


Para habilitar el rastreo a nivel de depuración para operaciones de unidad y medios: 

# xfsrestore -v drive=debug,media=debug -f /dev/tape /


Para habilitar el rastreo para todos los subsistemas y el rastreo a nivel de depuración solo para operaciones de unidad: 

# xfsrestore -v trace,drive=debug -f /dev/tape /


-A
No restaurar atributos extendidos de archivos. Al restaurar un sistema de archivos gestionado dentro de un entorno DMF, esta opción no debe usarse. DMF almacena el estado de migración de archivos dentro de atributos extendidos asociados con cada archivo. Si estos atributos no se conservan al restaurar el sistema de archivos, los archivos que estaban en estado migrado no podrán ser recuperados por DMF. Tenga en cuenta que la creación de copias de seguridad de atributos extendidos de archivos también es opcional.
-B
Cambiar la propiedad y los permisos del directorio de destino para que coincidan con los del directorio raíz de la copia de seguridad.
-D
Restaurar la configuración de eventos de DMAPI (Interfaz de Programación de Aplicaciones de Gestión de Datos). Si el sistema de archivos restaurado se gestionará dentro del mismo entorno DMF que la copia de seguridad original, es esencial que se utilice la opción -D. De lo contrario, normalmente no es deseable restaurar esta configuración.
-E
Evita que xfsrestore sobrescriba versiones más nuevas de los archivos. La hora de modificación del inodo del archivo en el medio se compara con la hora de modificación del inodo del archivo correspondiente en el directorio dest. El archivo solo se restaura si la versión en el medio es más reciente que la versión en el directorio dest. La hora de modificación del inodo de un archivo se puede mostrar con el comando ls -lc.
-F
Inhibir las indicaciones interactivas del operador. Esta opción inhibe xfsrestore de solicitar al operador la verificación de la copia de seguridad seleccionada como destino de restauración y de solicitar cualquier cambio de medio.
-I
Hace que se muestre el inventario de xfsdump (no se realiza ninguna restauración). Cada vez que se utiliza xfsdump, se actualiza un inventario en línea en /var/lib/xfsdump/inventory. Esto se utiliza para determinar la base para las copias de seguridad incrementales. También es útil para identificar manualmente una sesión de copia de seguridad que se va a restaurar (consulte las opciones -L y -S). Las subopciones para filtrar la visualización del inventario se describen más adelante.
-J
Inhibe la actualización del inventario al encontrar un inventario de sesión en el medio durante la restauración. xfsrestore actualiza de forma oportunista el inventario en línea cuando encuentra un inventario de sesión en el medio, pero solo si se ejecuta con un ID de usuario efectivo de root y solo si esta opción no se proporciona.
-K
Obliga a xfsrestore a usar números de generación del formato de copia de seguridad 2. Normalmente, la necesidad de esto se determina automáticamente, pero esta opción es necesaria en la primera invocación de xfsrestore en el caso poco frecuente de que una restauración acumulativa comience con una copia de seguridad de formato 3 (o posterior) y vaya seguida de una copia de seguridad de formato 2.
-L etiqueta_sesion
Especifica la etiqueta de la sesión de copia de seguridad que se va a restaurar. Se busca esta etiqueta en el medio de origen. Es una cadena arbitraria de hasta 255 caracteres de longitud. La etiqueta de la sesión de copia de seguridad deseada se puede copiar de la visualización del inventario producida por la opción -I.
-O archivo_opciones
Inserta las opciones contenidas en archivo_opciones al principio de la línea de comandos. Las opciones se especifican tal como aparecerían si se escribieran en la línea de comandos. Además, los caracteres de nueva línea (\n) se pueden usar como espacios en blanco. Las opciones se colocan antes de todas las opciones dadas realmente en la línea de comandos, justo después del nombre del comando. Solo se puede usar una opción -O. Se ignora el uso recursivo. El directorio de destino no se puede especificar en archivo_opciones.
-Q
Forzar la finalización de una sesión de restauración interrumpida. Esta opción es necesaria para solucionar un escenario patológico específico. Al restaurar una sesión de copia de seguridad que se interrumpió debido a una condición de fin de medio (EOM) y no hay inventario de sesión en línea disponible, xfsrestore no puede saber cuándo se completa la restauración de esa sesión de copia de seguridad. El operador se ve obligado a interrumpir la sesión de restauración. En ese caso, si el operador intenta aplicar posteriormente una copia de seguridad reanudada (usando la opción -r), xfsrestore se niega a hacerlo. El operador debe indicarle a xfsrestore que considere completa la restauración base utilizando esta opción al aplicar la copia de seguridad reanudada.
-R
Reanudar una restauración previamente interrumpida. xfsrestore puede ser interrumpido en cualquier momento al presionar el carácter de interrupción del terminal (ver stty(1)). Utilice esta opción para reanudar la restauración. Las opciones -a y destino deben ser las mismas.
-S id_sesion
Especifica el UUID de la sesión de la copia de seguridad que se va a restaurar. Se busca este UUID en el medio de origen. El UUID de la sesión de copia de seguridad deseada se puede copiar de la visualización del inventario producida por la opción -I.
-T
Inhibir los tiempos de espera del diálogo interactivo. xfsrestore solicita al operador los cambios de medio. Este diálogo normalmente expira si no se proporciona ninguna respuesta. Esta opción evita el tiempo de espera.
-X subarbol
Especifica un subárbol a excluir. Esto es lo opuesto a la opción -s. Se permiten cualquier número de opciones -X. Cada subárbol se especifica como una ruta de acceso relativa al destino de restauración. Si se especifica un directorio, se excluyen el directorio y todos los archivos debajo de ese directorio.
-Y longitud_anillo_io
Especificar la longitud del anillo de búfer de E/S. xfsrestore utiliza un anillo de búferes de entrada para lograr el máximo rendimiento al restaurar desde unidades de cinta. La longitud predeterminada del anillo es 3. Sin embargo, esto no está habilitado actualmente en Linux todavía, lo que hace que esta opción sea benigna.
-
Un solo - hace que la entrada estándar se lea como la fuente de la copia de seguridad que se va a restaurar. La entrada estándar puede ser una tubería de otra utilidad (como xfsdump(8)) o un archivo redirigido. Esta opción no se puede utilizar con la opción -f. El - debe seguir a todas las demás opciones y preceder a la especificación del destino.

El sistema de archivos volcado se restaura en el directorio dest. No hay un valor predeterminado; se debe especificar el dest.

NOTAS

Restauración Acumulativa

Se puede restaurar una copia de seguridad base (nivel 0) y un conjunto ordenado de copias de seguridad delta secuencialmente, cada una encima de la anterior, para reproducir el contenido del sistema de archivos original en el momento en que se produjo la última delta. El operador invoca xfsrestore una vez por cada copia de seguridad. La opción -r debe especificarse. El directorio dest debe ser el mismo para todas las invocaciones. Cada invocación deja un directorio llamado xfsrestorehousekeeping en el directorio dest (sin embargo, consulte la opción -a anterior). Este directorio contiene la información de estado que debe comunicarse entre invocaciones. El operador debe eliminar este directorio después de que se haya aplicado la última delta.

xfsrestore también genera un directorio llamado orphanage en el directorio dest. xfsrestore elimina este directorio después de completar una restauración simple. Sin embargo, si orphanage no está vacío, no se elimina. Esto puede suceder si los archivos presentes en el medio de copia de seguridad no están referenciados por ninguno de los directorios restaurados. El orphanage tiene una entrada para cada archivo de este tipo. El nombre de la entrada es el número de inodo original del archivo, un ".", y el recuento de generación del archivo módulo 4096 (solo se utilizan los 12 bits inferiores del recuento de generación).

xfsrestore no elimina el orphanage después de restauraciones acumulativas. Al igual que el directorio xfsrestorehousekeeping, el operador debe eliminarlo después de aplicar todas las copias de seguridad delta.

Gestión de Medios

Una copia de seguridad consta de uno o más archivos de medios contenidos en uno o más objetos de medios. Un archivo de medio contiene todo o una parte de la copia de seguridad del sistema de archivos. Los sistemas de archivos grandes se dividen en varios archivos de medios para minimizar el impacto de las caídas de medios y para acomodar los límites de los objetos de medios (fin de medios).

NAME

xfsrestore - restore an XFS filesystem backup

SYNOPSIS

xfsrestore [options] sourcedest

xfsrestore -h

DESCRIPTION

The xfsrestore command restores files from an XFS filesystem backup created by xfsdump(8). The backup can be on a local or remote tape device, or in a regular file.

Restoring a filesystem always requires the target filesystem to be mounted. A non-empty directory is required as the restore destination. If the destination exists, the dump is restored into it.

The restore destination can be the root of a filesystem, or any subdirectory within a filesystem. If the destination is a subdirectory, then the dumped directory structure is restored relative to that subdirectory. If the destination is the root of the filesystem, the dump is restored directly into the filesystem root. If the destination is an empty directory, the dump is restored into that directory.

By default, xfsrestore attempts to restore the entire filesystem. If the dump spans multiple media objects (e.g. multiple tape cartridges), the operator is prompted to load the next media object when needed. (Note: Removable media drives other than tape cartridges are not supported).

Tape cartridges can contain multiple media files, which are typically separated by (in tape parlance) file marks. If a dump spans multiple media objects, the restore must begin with the media object containing the first media file dumped. The operator is prompted when the next media object is needed.

Media objects can contain more than one dump. The operator can select the desired dump by specifying the dump label (-L option), or by specifying the dump UUID (-S option). If neither is specified, xfsrestore scans the entire media object, prompting the operator as each dump session is encountered.

The inventory display (-I option) is useful for identifying the media objects required. It is also useful for identifying a dump session. The session UUID can be copied from the inventory display to the -S option argument to unambiguously identify a dump session to be restored.

Dumps placed in regular files or the standard output do not span multiple media objects, nor do they contain multiple dumps.

Inventory

Each dump session updates an inventory database in /var/lib/xfsdump/inventory. This database can be displayed by invoking xfsrestore with the -I option. The display uses tabbed indentation to present the inventory hierarchically. The first level is filesystem. The second level is session. The third level is media stream (currently only one stream is supported). The fourth level lists the media files sequentially composing the stream.

The following suboptions are available to filter the display.

-I depth=n
(where n is 1, 2, or 3) limits the hierarchical depth of the display. When n is 1, only the filesystem information from the inventory is displayed. When n is 2, only filesystem and session information are displayed. When n is 3, only filesystem, session and stream information are displayed.
-I level=n
(where n is the dump level) limits the display to dumps of that particular dump level.

The display may be restricted to media files contained in a specific media object.

-I mobjid=value
(where value is a media ID) specifies the media object by its media ID.
-I mobjlabel=value
(where value is a media label) specifies the media object by its media label.

Similarly, the display can be restricted to a specific filesystem.

-I mnt=mount_point
(that is, [hostname:]pathname), identifies the filesystem by mountpoint. Specifying the hostname is optional, but may be useful in a clustered environment where more than one host can be responsible for dumping a filesystem.
-I fsid=filesystem_id
identifies the filesystem by filesystem ID.
-I dev=device_pathname
(that is, [hostname:]device_pathname) identifies the filesystem by device. As with the mnt filter, specifying the hostname is optional.

More than one of these suboptions, separated by commas, may be specified at the same time to limit the display of the inventory to those dumps of interest. However, at most four suboptions can be specified at once: one to constrain the display hierarchy depth, one to constrain the dump level, one to constrain the media object, and one to constrain the filesystem.

For example, -I depth=1,mobjlabel="tape 1",mnt=host1:/test_mnt would display only the filesystem information (depth=1) for those filesystems that were mounted on host1:/test_mnt at the time of the dump, and only those filesystems dumped to the media object labeled "tape 1".

Dump records may be removed (pruned) from the inventory using the xfsinvutil program.

An additional media file is placed at the end of each dump stream. This media file contains the inventory information for the current dump session. If the online inventory files in /var/lib/xfsdump/inventory are missing information for the current dump session, then the inventory information in the media file is automatically added to the files in /var/lib/xfsdump/inventory. If you wish to incorporate the inventory information from the media file without restoring any data, you may do so using the -t option: 

# xfsrestore -t -f /dev/tape


This is useful to rebuild the inventory database if it is ever lost or corrupted. The only caveat is that xfsrestore needs to read through the entire dump in order to reach the inventory media file. This could become time consuming for dump sessions with large media files.

Media Errors

xfsdump is tolerant of media errors, but cannot do error correction. If a media error occurs in the body of a media file, the filesystem file represented at that point is lost. The bad portion of the media is skipped, and the restoration resumes at the next filesystem file after the bad portion of the media.

If a media error occurs in the beginning of the media file, the entire media file is lost. For this reason, large dumps are broken into a number of reasonably sized media files. The restore resumes with the next media file.

Quotas

When xfsdump dumps a filesystem with user quotas, it creates a file in the root of the dump called xfsdump_quotas. xfsrestore can restore this file like any other file included in the dump. This file can be processed by the restore command of xfs_quota(8) to reactivate the quotas. However, the xfsdump_quotas file contains information which may first require modification; specifically the filesystem name and the user ids. If you are restoring the quotas for the same users on the same filesystem from which the dump was taken, then no modification will be necessary. However, if you are restoring the dump to a different filesystem, you will need to:

- ensure the new filesystem is mounted with the quota option

- modify the xfsdump_quotas file to contain the new filesystem name

- ensure the uids in the xfsdump_quotas file are correct

Once the quota information has been verified, the restore command of xfs_quota (8) can be used to apply the quota limits to the filesystem.

Group and project quotas are handled in a similar fashion and will be restored in files called xfsdump_quotas_group and xfsdump_quotas_proj, respectively.

EXAMPLES

To restore the root filesystem from a locally mounted tape: 

# xfsrestore -f /dev/tape /


To restore from a remote tape, specifying the dump session id: 

# xfsrestore -L session_1 -f otherhost:/dev/tape /new


To restore the contents a of a dump to another subdirectory: 

# xfsrestore -f /dev/tape /newdir


To copy the contents of a filesystem to another directory (see xfsdump(8)): 

# xfsdump -J - / | xfsrestore -J - /new

DIAGNOSTICS

The exit code is 0 on normal completion, and non-zero if an error occurred or the restore was terminated by the operator.

For all verbosity levels greater than 0 (silent) the final line of the output shows the exit status of the restore. It is of the form: 

xfsdump: Restore Status: code


Where code takes one of the following values: SUCCESS (normal completion), INTERRUPT (interrupted), QUIT (media no longer usable), INCOMPLETE (restore incomplete), FAULT (software error), and ERROR (resource error). Every attempt will be made to keep both the syntax and the semantics of this log message unchanged in future versions of xfsrestore. However, it may be necessary to refine or expand the set of exit codes, or their interpretation at some point in the future.

BUGS

Pathnames of restored non-directory files (relative to the dest directory) must be 1023 characters (MAXPATHLEN) or less. Longer pathnames are discarded and a warning message displayed.

There is no verify option to xfsrestore. This would allow the operator to compare a filesystem dump to an existing filesystem, without actually doing a restore.

The interactive commands (-i option) do not understand regular expressions.

When the minimal rmt option is specified, xfsrestore applies it to all remote tape sources. The same blocksize (specified by the -b option) is used for all these remote drives.

xfsrestore uses the alert program only when a media change is required.

Cumulative mode (-r option) requires that the operator invoke xfsrestore for the base and for each delta to be applied in sequence to the base. It would be better to allow the operator to identify the last delta in the sequence of interest, and let xfsrestore work backwards from that delta to identify and apply the preceding deltas and base dump, all in one invocation.
