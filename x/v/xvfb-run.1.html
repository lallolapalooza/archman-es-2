xvfb-run(1) Manual de Comandos Generales xvfb-run(1)

NOMBRE

xvfb-run - ejecuta un cliente X especificado o un comando en un entorno de servidor X virtual

SINOPSIS

xvfb-run [ opciones ] comando

DESCRIPCIÓN

xvfb-run es un envoltorio para el comando Xvfb(1x) que simplifica la tarea de ejecutar comandos (típicamente un cliente X, o un script que contiene una lista de clientes a ejecutar) dentro de un entorno de servidor X virtual.

xvfb-run configura un archivo de autenticación X (o utiliza uno existente especificado por el usuario), escribe una cookie en él (ver xauth(1x)) y luego inicia el servidor X Xvfb como un proceso en segundo plano. El ID del proceso de Xvfb se almacena para su uso posterior. El comando especificado se ejecuta utilizando la pantalla X correspondiente al servidor Xvfb recién iniciado y el archivo de autenticación X creado anteriormente.

Cuando el comando termina, se guarda su estado, se mata el servidor Xvfb (usando el ID del proceso almacenado anteriormente), se elimina la cookie de autenticación X y se elimina el archivo de autenticación (si el usuario no especificó uno para usar). xvfb-run luego sale con el estado de salida del comando.

xvfb-run requiere el comando xauth para funcionar.

OPCIONES

-a, --auto-servernum
Intenta obtener un número de servidor libre, comenzando en 99, o el argumento de --server-num.
-e archivo, --error-file=archivo
Almacena la salida de xauth y Xvfb en archivo. El valor predeterminado es /dev/null.
-f archivo, --auth-file=archivo
Almacena los datos de autenticación X en archivo. Por defecto, se crea un directorio temporal llamado xvfb-run.PID (donde PID es el ID del proceso de xvfb-run) en el directorio especificado por la variable de entorno TMPDIR (o /tmp si esa variable está vacía o no está definida), y se utiliza el comando tempfile(1) para crear un archivo en ese directorio temporal llamado Xauthority.
-h, --help
Muestra un mensaje de uso y sale.
-n numeroservidor, --server-num=numeroservidor
Utiliza numeroservidor como el número de servidor (pero ver la opción -a, --auto-servernum anterior). El valor predeterminado es 99.
-l, --listen-tcp
Habilita la escucha del puerto TCP en el servidor X. Por razones de seguridad (para evitar ataques de denegación de servicio o exploits), la escucha del puerto TCP está deshabilitada por defecto.
-p nombredelprotocolo, --xauth-protocol=nombredelprotocolo
Utiliza nombredelprotocolo como el protocolo de autenticación X a utilizar. El valor predeterminado es '.', que xauth interpreta como su propio protocolo predeterminado, que es MIT-MAGIC-COOKIE-1.
-s argumentos, --server-args=argumentos
Pasa argumentos al servidor Xvfb. Tenga cuidado de citar cualquier carácter de espacio en blanco que pueda ocurrir dentro de argumentos para evitar que se consideren separadores para los argumentos propios de xvfb-run. Además, tenga en cuenta que la especificación de '-nolisten tcp' en argumentos puede anular la función de la opción -l, --listen-tcp propia de xvfb-run, y que la especificación del número de servidor (por ejemplo, ':1') puede ignorarse debido a la forma en que el servidor X analiza su lista de argumentos. Utilice la opción xvfb-run -n numeroservidor, --server-num=numeroservidor para lograr esta última función. El valor predeterminado es '-screen 0 640x480x8'.
-w retraso, --wait=retraso
Espera retraso segundos después de lanzar Xvfb antes de intentar iniciar el comando especificado. El valor predeterminado es 3.

AMBIENTE

COLUMNAS
indica el ancho del dispositivo de terminal en celdas de caracteres. Este valor se utiliza para formatear mensajes de diagnóstico. Si no se establece, se consulta la terminal usando stty(1) para determinar su ancho. Si falla, se asume un valor de '80'.
TMPDIR
especifica el directorio en el que colocar el directorio temporal de xvfb-run para el almacenamiento del archivo de autenticación X; solo se utiliza si las opciones -f o --auth-file no se especifican.

ARCHIVOS DE SALIDA

A menos que se especifiquen las opciones -f o --auth-file, se crea (y se elimina) un directorio y archivo temporal dentro de él para almacenar las cookies de autenticación X utilizadas por el servidor Xvfb y el(los) cliente(s) ejecutado(s) bajo él. Ver tempfile(1). Si se utilizan -f o --auth-file, entonces el archivo de autenticación X especificado solo se escribe, no se crea ni se elimina (aunque xauth crea un archivo de autenticación por sí mismo si se le indica que use uno que no exista).

También se crea un archivo de error con un nombre especificado por el usuario si se especifican las opciones -e o --error-file; ver arriba.

ESTADO DE SALIDA

xvfb-run utiliza su estado de salida, así como la salida al error estándar, para comunicar diagnósticos. El estado de salida '1' no se utiliza y debe interpretarse como un fallo del comando especificado.

0
xvfb-run solo utiliza este estado de salida si se proporciona la opción -h, --help. En todas las demás situaciones, esto puede interpretarse como éxito del comando especificado.
2
No se especificó ningún comando para ejecutar.
3
El comando xauth no está disponible.
4
El directorio temporal que se iba a utilizar ya existe; dado que xvfb-run produce un directorio con un nombre único, esto puede indicar un intento por parte de otro proceso en el sistema de explotar una condición de carrera de archivos temporales.
5
Se encontró un problema al limpiar el directorio temporal.
6
Se encontró un problema al usar getopt(1) para analizar los argumentos de la línea de comandos.

EJEMPLOS

xvfb-run --auto-servernum --server-num=1 xlogo
ejecuta el cliente de demostración xlogo(1x) dentro del servidor X Xvfb en el primer número de servidor disponible mayor o igual a 1.
xvfb-run --server-args="-screen 0 1024x768x24" ico -faces
ejecuta el cliente de demostración ico(1x) (y le pasa el argumento -faces) dentro del servidor X Xvfb, configurado con una ventana raíz de 1024 por 768 píxeles y una profundidad de color de 24 bits.

Tenga en cuenta que los clientes X de demostración utilizados en los ejemplos anteriores no saldrán por sí solos, por lo que deberán ser terminados antes de que xvfb-run pueda salir.

ERRORES

Ver el Sistema de Seguimiento de Errores de Debian ⟨URL: http://bugs.debian.org/xvfb ⟩. Si desea informar de un error en xvfb-run, utilice el comando reportbug(1).

xvfb(1x)

NAME

xvfb - Virtual framebuffer

SYNOPSIS

xvfb [-help] [-display display] [-screen scrnum/widthxheightxdepth] [-ac] [-nolisten type] [-keybd driver] [-fbdir directory] [-shm] [-extension extension] [-config file] [-logfile logfile] [-fp fontpath] [-coefs file] [-gnomefd fd] [-- args...]

DESCRIPTION

Xvfb is a server that can operate effectively as a screen in the X Window System. It implements the X Window System protocol, but has no display connected to it. It is a virtual framebuffer. This server is useful for testing X clients, automated screen captures, and other tasks where a full X server but no physical screen is required. Xvfb is a monochrome server. For colour servers, use Xvfb.

The Xvfb server supports screens of arbitrary size and colour depth. It can be run with multiple screens, and it supports all standard X Window System extensions. In addition, it supports the XFree86-Misc and XFree86-BigRequests extensions.

The Xvfb server can be run with a pseudo-driver, which simulates a graphics adapter. This is useful for testing X clients that require a graphics adapter to be present. The pseudo-driver is configured by specifying the -screen option. The -screen option takes the form scrnum/widthxheightxdepth, where scrnum is the screen number, width is the screen width in pixels, height is the screen height in pixels, and depth is the colour depth in bits per pixel.

OPTIONS

  • -help: Prints a usage message and exits.
  • -display display: Specifies the display name to be used for the server. The default is :1.
  • -screen scrnum/widthxheightxdepth: Specifies the screen number, width, height, and colour depth for the server. The default is 0/640x480x8.
  • -ac: Disables access control.
  • -nolisten type: Disables listening for connections on the specified transport type (e.g., tcp, inet, unix).
  • -keybd driver: Specifies the keyboard driver to be used.
  • -fbdir directory: Specifies the directory in which to create the frame buffer device.
  • -shm: Enables shared memory transport.
  • -extension extension: Enables the specified extension.
  • -config file: Specifies a configuration file.
  • -logfile logfile: Specifies a log file.
  • -fp fontpath: Specifies the font path.
  • -coefs file: Specifies a coefficients file.
  • --: Indicates the end of the Xvfb options. Any subsequent arguments are passed to the X client.

ENVIRONMENT

None.

OUTPUT FILES

None.

EXIT STATUS

0 on success, non-zero on failure.

EXAMPLES

Start an Xvfb server with a 1024x768 24-bit screen on display :99:

xvfb :99 -screen 0/1024x768x24

Run a command under Xvfb:

xvfb-run your_command

BUGS

None known.

AUTHOR

Xvfb was originally developed by the XFree86 Project, Inc. and is now maintained by the freedesktop.org Xorg developers.
