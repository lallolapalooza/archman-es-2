NOMBRE

xorrisofs - Emulación del programa mkisofs de ISO 9660 por el programa xorriso

SINOPSIS

xorrisofs [ opciones ] [-o nombre_archivo ] ruta [rutas ...]

DESCRIPCIÓN

xorrisofs produce sistemas de archivos ISO 9660 mejorados con Rock Ridge y sesiones adicionales a dichos sistemas de archivos. Opcionalmente también puede producir árboles de directorios Joliet.

xorrisofs entiende las opciones del programa mkisofs de cdrtools por Joerg Schilling. Su implementación es parte del programa xorriso, el cual no comparte código fuente con cdrtools.

ISO 9660, Rock Ridge, Joliet, HFS+:

ISO 9660 (también conocido como ECMA-119) es un sistema de archivos de solo lectura que se utiliza principalmente para medios ópticos (CD, DVD, BD), pero que también puede residir en otros dispositivos de almacenamiento como archivos de disco, unidades USB o particiones de disco. Es ampliamente legible por muchos sistemas operativos y por las instalaciones de arranque de las computadoras personales.

ISO 9660 describe directorios y archivos de datos con nombres de archivo muy restringidos, sin distinción entre mayúsculas y minúsculas. Sus metadatos no cumplen con las especificaciones fundamentales de POSIX.

Rock Ridge es el nombre de un conjunto de información adicional que mejora un sistema de archivos ISO 9660 para que pueda representar un sistema de archivos compatible con POSIX con propiedad, permisos de acceso, enlaces simbólicos y otros atributos. Rock Ridge permite nombres de archivo de hasta 255 bytes y rutas de hasta 1024 bytes.

xorrisofs produce información de Rock Ridge por defecto. Se desaconseja firmemente deshabilitar esta característica.

Joliet es el nombre de un árbol de directorios adicional que proporciona nombres de archivo de hasta 64 caracteres codificados en UTF-16. Un árbol Joliet es principalmente interesante para leer la imagen ISO por sistemas operativos de Microsoft Corporation. La producción de este árbol de directorios se puede habilitar con la opción -J.

ISO 9660:1999 es el nombre de un árbol de directorios adicional que proporciona nombres de archivo más largos. Permite que los nombres de archivo individuales tengan hasta 207 caracteres. Podría ser útil con algunas instalaciones de arranque de sistemas informáticos más antiguos que no leen ni Rock Ridge ni Joliet, pero que aún así necesitan nombres de archivo más largos. La producción de este árbol de directorios se puede habilitar con la opción -iso-level 4.

HFS+ es el nombre de un sistema de archivos que normalmente se utiliza para escribir y leer en discos duros y dispositivos similares. Es posible incrustar una partición HFS+ en la imagen ISO 9660 emergente y marcarla con entradas de Mapa de Particiones de Apple. Esto interfiere con las opciones que copian datos en los primeros 32 KiB de la imagen ISO, como -G o -isohybrid-mbr. Consulte la opción -hfsplus.

El propósito principal de tener una partición HFS+ incrustada es el arranque de ciertos modelos de computadoras Apple.

Insertar archivos en la imagen ISO:

xorrisofs maneja dos tipos de direcciones de archivo:
ruta_disco es una ruta a un objeto en el árbol de directorios del sistema de archivos local.
iso_rr_ruta es la dirección Rock Ridge de un objeto de archivo en la imagen ISO. Si no se va a almacenar información de Rock Ridge en una imagen emergente, los nombres se mapearán a nombres ISO 9660 de longitud y conjunto de caracteres limitados.

Un argumento del programa se maneja como especificación_de_ruta, si no se reconoce como una opción original de mkisofs o una opción adicional de xorrisofs. Una especificación de ruta representa un objeto de archivo de entrada mediante una ruta_disco. Si la opción -graft-points no está presente, el comportamiento depende del tipo de archivo de ruta_disco. Los directorios se fusionan con el directorio / de la imagen ISO. Los archivos de otros tipos se copian en el directorio /.

Si está presente -graft-points, cada especificación_de_ruta se divide en la primera aparición del carácter =. La parte anterior al = se toma como destino, es decir, la iso_rr_ruta para el objeto de archivo en la imagen ISO. La parte posterior al primer = se toma como origen, es decir, la ruta_disco del objeto de entrada.

Es posible incluir caracteres = en la iso_rr_ruta anteponiéndoles un carácter \. Lo mismo debe hacerse para los caracteres \ que deban formar parte de la iso_rr_ruta.

Si la parte de origen de la especificación_de_ruta conduce a un directorio, todos los archivos debajo de ese directorio también se insertarán en la imagen. Es posible excluir archivos específicos de la inserción con la ayuda de la opción -m.

En caso de que el destino ya exista, se aplican las siguientes reglas: Los directorios y otros archivos pueden sobrescribir no directorios existentes. Los directorios se fusionan con los directorios existentes. Los no directorios no pueden sobrescribir directorios existentes.

Relación con el programa xorriso:

xorrisofs es en realidad un modo de comando del programa xorriso, al que se accede ya sea mediante el comando xorriso "-as mkisofs" o iniciando el programa con uno de los nombres "xorrisofs", "mkisofs", "genisoimage", o "genisofs".

Este modo de comando se puede abandonar mediante el argumento "--", que lleva al modo de comando genérico de xorriso. Consulte man xorriso para su descripción.

xorriso realiza la lectura y escritura de imágenes con la ayuda de libburn, que está destinada principalmente a unidades ópticas, pero también opera en todos los tipos de archivos POSIX, excepto directorios.

Los mensajes del programa llaman a cualquier archivo de imagen "unidad". Los tipos de archivo que no son compatibles con la lectura se informan como "en blanco". El espacio libre de medios informado puede ser bastante ficticio.

Sin embargo, xorrisofs no opera directamente en unidades ópticas, sino que fuerza a libburn a considerarlas como archivos de dispositivo generales. Por lo tanto, para escribir medios ópticos secuenciales (CD, DVD-R, DVD+R, BD-R), deberá usar un programa de grabación. Por ejemplo, la emulación de cdrecord de xorriso. Consulte EJEMPLOS.

OPCIONES

Carga de imagen:

Las siguientes opciones controlan la carga de una imagen ISO existente con el propósito de preparar una sesión adicional adecuada. Si faltan, se compondrá una nueva imagen desde cero.

-M ruta_disco
Establece la ruta desde la cual cargar el árbol de directorios de la imagen ISO existente en la que basar el próximo árbol de directorios como sesión adicional. La ruta debe conducir a un objeto de archivo legible de acceso aleatorio. En GNU/Linux: archivos de datos regulares o archivos de dispositivo de bloque.
Un tipo especial de ruta_disco pseudo tiene la forma "/dev/fd/"número. Representa el descriptor de archivo abierto con el número dado, independientemente de si el sistema operativo soporta esta característica mediante nodos de archivo en /dev/fd o no. Por ejemplo, /dev/fd/3 es el descriptor de archivo 3 que fue abierto por el programa que luego inició xorriso.
-prev-session ruta_disco
Alias de -M.
-dev ruta_disco
Alias de -M.
-C inicio_última_sesión,dirección_grabable_siguiente
Establece la dirección de bloque de 2 KiB inicio_última_sesión desde la cual leer la imagen ISO del archivo dado por la opción -M.
Separado por una coma, establece la dirección_grabable_siguiente a la que se escribirá finalmente la sesión adicional. Lo decisivo es en realidad la dirección de bloque que los lectores previstos deberán usar como dirección de superbloque en el medio previsto.
Ambos valores pueden ser consultados de medios ópticos con la ayuda de programas de grabación y la opción -msinfo de cdrecord. xorriso mismo puede obtenerlos en su emulación de cdrecord.
    valores=$(xorriso -as cdrecord dev=/dev/... -msinfo)
    echo $valores
La opción -C se puede usar sin la opción -M para crear una imagen ISO desde cero y prepararla para ser finalmente escrita en una dirección de bloque distinta de 0. El parámetro inicio_última_sesión debe establecerse entonces a 0.
-cdrecord-params inicio_última_sesión,dirección_grabable_siguiente
Alias de -C.

-root ruta_iso_rr
Inserta todos los archivos bajo la ruta_iso_rr dada. Si se proporciona la opción -graft-points, entonces ruta_iso_rr se antepone a cada parte de destino de un especificador de ruta.
El valor predeterminado para -root es "/".
-old-root ruta_iso_rr
Habilita la inserción incremental de archivos en la imagen cargada. Las direcciones efectivas de destino y origen de los especificadores de ruta dados se comparan para ver si el destino ya existe en la imagen ISO y sigue siendo idéntico al origen en el disco. Los metadatos en la imagen ISO se ajustarán si difieren de los del disco. Los archivos nuevos y los archivos con contenido modificado se agregarán nuevamente. Los archivos de destino que no existen en ninguna de las fuentes de especificadores de ruta correspondientes se eliminarán del árbol de directorios de la ISO.
Si la configuración efectiva de -root difiere de la ruta_iso_rr dada con -old-root, entonces los archivos debajo del directorio -old-root se clonarán debajo del directorio -root. La clonación ocurre antes de la comparación de archivos.
--old-root-no-ino
Deshabilita el registro y uso de números de inodo del disco. Si no se registran números de inodo del disco, entonces la opción -old-root tendrá que leer el contenido del archivo del disco y compararlo con la suma de verificación MD5 que se registra en la imagen ISO.
Con números de inodo del disco registrados y con ctime y mtime creíbles, es posible detectar cambios potenciales en el contenido sin leerlo realmente. Queda una laguna si varios sistemas de archivos diferentes pueden montarse en el mismo directorio, como es habitual con /mnt. En este caso, se debe usar la opción --old-root-devno o deshabilitar el acceso directo al número de inodo con --old-root-no-ino.
--old-root-devno
Habilita la comparación de números de dispositivo registrados junto con números de inodo registrados. Esto solo funciona con números de dispositivo estables antiguos que lamentablemente están pasados de moda. Si el disco duro tiene un número de dispositivo diferente después de cada reinicio, entonces esta comparación verá todos los archivos como cambiados y, por lo tanto, evitará cualquier ahorro de tamaño incremental.
--old-root-no-md5
Deshabilita el registro y uso de sumas de verificación MD5 para el contenido de archivos de datos. Si no se registran sumas de verificación ni números de inodo del disco, entonces la opción -old-root tendrá que leer el contenido del archivo de la imagen ISO al compararlo con el contenido del archivo del disco.
Ajustes para la producción de la imagen:
-o ruta_disco
Establece la dirección del archivo de salida para la imagen ISO emergente. Si la dirección existe como un archivo regular, se truncará a longitud 0 cuando comience la producción de la imagen. No puede existir ya como un directorio. Si aún no existe, entonces su directorio padre debe existir y se creará un archivo regular.
Un tipo especial de pseudo ruta_disco tiene la forma "/dev/fd/" número. Representa el descriptor de archivo abierto con el número dado, independientemente de si el sistema operativo admite esta característica mediante nodos de archivo en /dev/fd o no. Por ejemplo, /dev/fd/4 es el descriptor de archivo 4 que fue abierto por el programa que luego inició xorriso.
El valor predeterminado es la salida estándar (/dev/fd/1), que también puede establecerse mediante la ruta_disco "-".
-output ruta_disco
Alias de -o.
--stdio_sync "on"|"off"|"end"|número
Establece el número de bytes después de los cuales forzar la salida al disco para evitar que la memoria se sature con muchos datos pendientes para dispositivos lentos. "on" es lo mismo que "16m". La salida forzada se puede deshabilitar con "off", o retrasar con "end" hasta que se produzcan todos los datos. Si se elige un número, debe ser al menos 64k.
El valor predeterminado con la emulación mkisofs de xorriso es --stdio_sync "off".
xorriso utiliza un búfer FIFO interno con un tamaño predeterminado de 4 MiB. Por lo tanto, forzar la caché de E/S del sistema operativo al disco no bloquea necesariamente la producción simultánea de más contenido de imagen.
--emul-toc
Escribe un segundo superbloque con la primera sesión en archivos de acceso aleatorio. Si se añaden más sesiones y se actualiza el primer superbloque, entonces el segundo superbloque no se sobrescribirá. Por lo tanto, todavía es posible montar la primera sesión y encontrar los bloques de inicio de las sesiones posteriores.
El precio es de 64 KiB de consumo de espacio adicional. Si -partition_offset es distinto de cero, entonces son 128 KiB más el doble de la configuración de la partición.
--no-emul-toc
No escribe un segundo superbloque con la primera sesión en archivos de acceso aleatorio.
Este es el valor predeterminado.
--sort-weight número_peso ruta_iso_rr
Asigna un número de peso LBA a los archivos regulares. Si ruta_iso_rr apunta a un directorio, entonces todos los archivos regulares debajo de él recibirán el número_peso.
El número_peso puede variar de -2147483648 a 2147483647. Cuanto mayor sea, menor será la dirección de bloque de los datos del archivo en la imagen ISO emergente. Actualmente, el catálogo de arranque El Torito tiene un peso fijo de 1000 millones. Normalmente, debería ocupar el bloque con la dirección más baja posible. Los archivos de datos se agregan o cargan con un peso inicial de 0. Los archivos de imagen de arranque tienen un peso predeterminado de 2.
--sort-weight-list ruta_disco
Lee pares de número de peso y ruta_iso_rr de un archivo del sistema de archivos local. Aplica cada par como con --sort-weight.
Solo el último --sort-weight-list o --sort-weight-patterns de una ejecución de xorrisofs tendrá efecto.
El número de peso se lee desde el inicio de la línea. La parte de ruta_iso_rr de una línea de entrada comienza inmediatamente después del primer espacio en blanco o carácter de tabulación de la línea.
Notas para el caso de que esta función se utilice dentro de una secuencia de comandos genéricos de xorriso (no es un problema con una ejecución pura de emulación de mkisofs):
Los archivos direccionados deben estar ya en el modelo de imagen ISO cuando ejecute
-as mkisofs --sort-weight-list ruta_disco --
Se pueden utilizar varios comandos de este tipo para aplicar más de un archivo de peso.
Los archivos de datos que se cargan mediante -indev o -dev obtienen un peso entre 1 y 2 exp 28 = 268,435,456, dependiendo de su dirección de bloque. Esto debería mantenerlos aproximadamente en el mismo orden si se aplica el método de escritura de modificación.
--sort-weight-patterns ruta_disco
Igual que --sort-weight-list, pero expandiendo las rutas_iso_rr como patrones de analizador de shell y aplicando --sort-weight a cada archivo coincidente.
-uid número|nombre
Utiliza el número dado o el nombre de usuario existente localmente como ID de propietario de todos los archivos y directorios en el sistema de archivos emergente. Un nombre vacío o el nombre "-" revoca esta función.
-gid número|nombre
-gid gid
Utiliza el número dado o el nombre de grupo existente localmente como el ID de grupo de todos los archivos y directorios en el sistema de archivos emergente. Un nombre vacío o el nombre "-" revoca esta característica.
-dir-mode modo
Establece los permisos de acceso para todos los directorios en la imagen al modo dado, que es un número octal que comienza con "0" o una lista separada por comas de declaraciones del tipo [ugoa]*[+-=][rwxst]* . Por ejemplo, ug=rx,a-rwx
-file-mode modo
Igual que -dir-mode pero para todos los archivos de datos regulares en la imagen.
-pad

Añade 300 KiB al final de la imagen ISO producida. Esto evita posibles errores de lectura de imágenes ISO que se han escrito en medios CD en modo TAO. Los bytes adicionales se reclaman como parte de la imagen ISO si no se proporciona --emul-toc.
La opción -pad es la predeterminada.
-no-pad
Deshabilita el relleno de 300 KiB al final de la imagen ISO producida. Esto es seguro si la imagen no está destinada a ser grabada en CD o si se graba en CD como única pista en modo de escritura SAO.
--old-empty
Utiliza la forma antigua de dar direcciones de bloque en el rango [0,31] a archivos sin contenido de datos propio. La nueva forma es tener un bloque dedicado al que apuntarán todos esos archivos.
Configuración para el cumplimiento de estándares:
-iso-level número
Especifica la versión ISO 9660 que define las limitaciones de nombres de archivo y tamaño de archivo de datos. Las restricciones de nomenclatura no se aplican a los nombres Rock Ridge, sino solo a los nombres de bajo nivel ISO 9660. Hay tres niveles de conformidad:
El Nivel 1 permite nombres ISO de la forma 8.3 y un tamaño de archivo de hasta 4 GiB - 1.
El Nivel 2 permite nombres ISO con hasta 32 caracteres y un tamaño de archivo de hasta 4 GiB - 1.
El Nivel 3 permite nombres ISO con hasta 32 caracteres y un tamaño de archivo de hasta 400 GiB - 200 KiB. (Esta limitación de tamaño la establece la implementación de xorriso y no la ISO 9660, que permitiría casi 8 TiB.)
El pseudonivel 4 habilita la producción de un árbol de directorios ISO 9660:1999 adicional.
-disallow_dir_id_ext
No seguir el mal hábito de mkisofs que permite puntos en los nombres ISO de los directorios. Por otro lado, algunas imágenes GNU/Linux arrancables dependen de este mal hábito.
-U

Esta opción permite nombres de archivo ISO sin puntos y de hasta 37 caracteres, rutas de archivo ISO más largas que 255 caracteres y todos los caracteres ASCII en los nombres de archivo. Además, omite el punto y coma y los números de versión al final de los nombres ISO.
Todo esto viola las especificaciones ISO 9660.
-untranslated-filenames
Alias de -U.
-untranslated_name_len número
Permite nombres de archivo ISO de hasta el número de caracteres dado sin ninguna conversión de caracteres. El número máximo es 96. Si un nombre de archivo tiene más caracteres, la producción de la imagen fallará deliberadamente.
Esto viola las especificaciones ISO 9660.
-allow-lowercase
Permite caracteres en minúsculas en los nombres de archivo ISO.
Esto viola las especificaciones ISO 9660.
-relaxed-filenames
Permite casi todos los caracteres de 7 bits en los nombres de archivo ISO. No están permitidos 0x0 y '/'. Si no se da la opción -allow-lowercase, las letras minúsculas se convertirán a mayúsculas.
Esto viola las especificaciones ISO 9660.

-R

Con mkisofs, esta opción habilita las extensiones Rock Ridge. xorrisofs las produce por defecto. Se desaconseja encarecidamente deshabilitarlas con la opción --norock.
-rock

Alias de -R.
-r

Habilita Rock Ridge y establece el ID de usuario y grupo de todos los archivos en la imagen ISO a 0. Otorga permisos r- a todos. Deniega todos los permisos w-. Si se establece algún permiso x, otorga permiso x a todos. Elimina los bits s y t.
Estos cambios de atributos permanecen retrasados hasta que finaliza la emulación de mkisofs. Dentro del mismo comando de emulación -as mkisofs, pueden ser revocados por una opción posterior --norock. Por razones de compatibilidad, la opción -R no revoca los cambios ordenados por -r.
-rational-rock
Alias de -r.
--norock

Esta opción deshabilita la producción de extensiones Rock Ridge para los objetos de archivo ISO 9660. Las capacidades multisesión de xorrisofs dependen en gran medida de la fidelidad de nomenclatura de Rock Ridge. Por lo tanto, se desaconseja encarecidamente deshabilitarla con esta opción, excepto para el caso de uso especial de revocar el efecto de -r con:
--norock -R
--set_all_file_dates cadena_de_tiempo
Establece mtime, atime y ctime de todos los archivos y directorios al tiempo dado.
Los formatos válidos de cadena_de_tiempo son: 'Nov 8 14:51:13 CET 2007', 110814512007.13, 2007110814511300. Véase también --modification-date= y man xorriso, Ejemplos de cadenas_de_tiempo de entrada.
Si la cadena_de_tiempo es "set_to_mtime", entonces atime y ctime de cada archivo y directorio se establecerán al valor encontrado en su mtime.
Estas acciones permanecen retrasadas hasta que comienza la producción real de ISO. Hasta entonces, pueden ser revocadas por --set_all_file_dates con una cadena_de_tiempo vacía o la cadena_de_tiempo "default".
Las marcas de tiempo del archivo de catálogo de arranque El Torito se actualizarán cuando se produzca la ISO. Pueden ser influenciadas por --modification-date=.
-file_name_limit número
Establece la longitud máxima permitida para los nombres de archivo en el rango de 64 a 255. Los componentes de ruta que sean más largos que el número dado se truncarán y sus últimos 33 bytes se sobrescribirán con dos puntos ':' y la representación hexadecimal del MD5 de los primeros 4095 bytes del nombre completo que excede la longitud. Los caracteres UTF-8 potencialmente incompletos tendrán sus bytes iniciales reemplazados por '_'.
Los kernels de Linux hasta al menos 4.1 representan incorrectamente nombres de longitud 254 y 255. Si esperas tales nombres dentro o debajo de disk_paths y planeas montar la ISO con kernels de Linux como esos, considera establecer -file_name_limit 253.
-D
El estándar ECMA-119 exige que ninguna ruta en la imagen tenga más de 8 componentes de nombre o 255 caracteres. Por lo tanto, sería necesario mover árboles de directorios más profundos a un directorio superior. Rock Ridge ofrece la oportunidad de hacer que estos directorios reubicados aparezcan en su posición profunda original, pero esta característica podría no estar implementada correctamente por los sistemas operativos que montan la imagen.
La opción -D deshabilita esta reubicación de directorios profundos, y por lo tanto viola las especificaciones ISO 9660.
xorrisofs tiene -D establecido por defecto. Si se especifica explícitamente, anula las opciones -rr_reloc_dir y -hide-rr-moved.
-disable-deep-relocation
Alias de -D.
-rr_reloc_dir nombre

Los directorios que conducen a tales rutas de archivo se moverán a un directorio en el directorio raíz de la imagen. Su nombre se establecerá con esta opción. Es permisible usar el directorio raíz mismo.
El árbol de directorios general aparecerá originalmente profundo cuando se interprete como un árbol Rock Ridge. Aparecerá reorganizado si solo se consideran las información ECMA-119.
Si el directorio de reubicación de destino dado no existe cuando comienza la producción de la imagen, se creará y se marcará para Rock Ridge como un artefacto de reubicación. Al menos en GNU/Linux no se mostrará en las imágenes Rock Ridge montadas.
El nombre no debe contener un carácter '/' después de su primer carácter y no debe tener más de 255 bytes de longitud.
Esta opción no tiene efecto si está presente la opción -D.

-hfsplus
Habilita la producción de un sistema de archivos HFS+ adicional dentro de la imagen ISO 9660 y lo marca con entradas del Mapa de Partición de Apple (APM) en el Área del Sistema, los primeros 32 KiB de la imagen.
Esto puede entrar en conflicto con opciones como -G o -isohybrid-mbr que envían datos del usuario para su inclusión en el mismo rango de direcciones. Los primeros 8 bytes del Área del Sistema se sobrescriben con { 0x45, 0x52, 0x08 0x00, 0xeb, 0x02, 0xff, 0xff } que pueden ejecutarse como código de máquina x86 sin efectos negativos. Por lo tanto, si un MBR se combina con esta característica, sus primeros 8 bytes no deben contener comandos esenciales.
Los siguientes bloques de 2 KiB en el Área del Sistema serán ocupados por entradas APM. La primera cubre la parte de la imagen ISO anterior a los metadatos del sistema de archivos HFS+. La segunda marca el rango desde los metadatos de HFS+ hasta el final de los datos de contenido del archivo. Si siguen más datos de la imagen ISO, se producirá una tercera entrada de partición. Otras características de xorriso podrían causar la necesidad de más entradas APM.
Tenga en cuenta que HFS+ no distingue entre mayúsculas y minúsculas, aunque puede grabar nombres de archivo con letras mayúsculas y minúsculas. Por lo tanto, los nombres de archivo del árbol de nombres iso_rr pueden colisionar en el árbol de nombres HFS+. En este caso, se modifican agregando caracteres de subrayado y números de conteo. En caso de nombres muy largos, podría ser necesario mapearlos a "MANGLED_...".
ADVERTENCIA:
La implementación HFS+ en libisofs tiene un límite de 125.829.120 bytes para el tamaño del árbol de directorios general. Esto es suficiente para aproximadamente 300.000 archivos de longitud de nombre normal. Si se excede el límite, se emitirá un evento de FALLO y la producción de la ISO no ocurrirá.

Establece una cadena de 16 dígitos "0" a "9" y letras "a" a "f", que se utilizará como número de serie único de un sistema de archivos HFS+ emergente.

Establece el tamaño de bloque de asignación que se utilizará al producir sistemas de archivos HFS+. Se permiten 512, 2048 o 0. Este último deja que el programa decida.

Establece los atributos de creador y tipo HFS+ de un archivo en la imagen emergente. Estos son dos códigos de 4 caracteres cada uno.
-hfs-bless-by blessing iso_rr_path
Emite una bendición HFS+. Estos son roles que se pueden atribuir a hasta cuatro directorios y un archivo de datos:
"ppc_bootdir", "intel_bootfile", "show_folder", "os9_folder", "osx_folder".
Se pueden abreviar como "p", "i", "s", "9", y "x".
Cada rol puede atribuirse a un máximo de un objeto de archivo. "intel_bootfile" es el que se aplicaría a un archivo de datos. Todos los demás se aplican a directorios. Ningún objeto de archivo puede tener más de una bendición.

Esto solo funciona si hay al menos un archivo de datos debajo del directorio. disk_path puede volverse ambiguo si archivos de diferentes subárboles del sistema de archivos local se colocan en el mismo subárbol de la imagen ISO. Imágenes ISO de arranque El Torito:

La precondición para una imagen ISO de arranque es tener en la imagen ISO los archivos de un cargador de arranque. Las instalaciones de arranque de las computadoras se dirigen a dichos archivos, que normalmente ejecutan archivos de programas adicionales desde la imagen ISO. xorrisofs puede producir varios tipos de bloques de arranque o registros de arranque, que se convierten en parte de la imagen ISO y son interpretados por la instalación de arranque correspondiente.

Un registro de arranque El Torito apunta la instalación de arranque a un catálogo de arranque con una o más imágenes de arranque, que son archivos de programas binarios almacenados en la imagen ISO. El contenido de los archivos de imagen de arranque no está dentro del alcance de El Torito.
xorriso compone el catálogo de arranque de acuerdo con los archivos de imagen de arranque dados y estructurados por las opciones -b, -e, -eltorito-alt-boot y --efi-boot. A menudo contiene solo una entrada.
Normalmente, las imágenes de arranque son archivos de datos dentro del sistema de archivos ISO. Mediante la ruta especial "--interval:appended_partition_NNN:all::" es posible referirse a una partición adjunta. El número NNN indica el número de partición tal como se utiliza con la opción correspondiente -append_partition. Ejemplo:
-append_partition 2 0xef /tmp/efi.img
-e --interval:appended_partition_2:all::
El Torito es interpretado por las instalaciones de arranque PC-BIOS y EFI. La mayoría de los CDs GNU/Linux de arranque están equipados con imágenes de arranque ISOLINUX o GRUB para PC-BIOS.
xorrisofs soporta las opciones de ejemplo de la wiki de ISOLINUX, las opciones utilizadas en el script GRUB grub-mkrescue y el ejemplo en la wiki de FreeBSD AvgLiveCD.

Para el arranque de CD a través de instalaciones de arranque que no sean PC-BIOS y EFI, y para el arranque desde unidades USB o discos duros, consulte la siguiente sección sobre el Área del Sistema.

Con imágenes de arranque de ISOLINUX y GRUB, esta opción debe ir acompañada de las opciones -c, -no-emul-boot, -boot-load-size 4, -boot-info-table.

Área del Sistema, MBR, GPT, APM, otros bloques de arranque:

Los primeros 16 bloques de una imagen ISO son el Área del Sistema. Está reservado para software de arranque dependiente del sistema. Esto puede ser las instalaciones de arranque y las tablas de partición de

diversas arquitecturas de hardware.
Un MBR (Master Boot Record) contiene código de arranque y una tabla de particiones. Es leído por PC-BIOS al arrancar desde un pendrive o disco duro, y por PowerPC CHRP o PReP al arrancar. Una partición MBR con tipo 0xee indica la presencia de GPT.
Una GPT (GUID Partition Table) marca las particiones de una manera más moderna. Es leída por EFI al arrancar desde un pendrive o disco duro, y puede ser utilizada para encontrar y montar una partición HFS+ dentro de la imagen ISO.
Un APM (Apple Partition Map) marca la partición HFS+. Es leído por Macs para arrancar y montar.
MBR, GPT y APM son combinables. APM ocupa los primeros 8 bytes del código de arranque MBR. Los tres no obstaculizan el arranque El Torito desde CDROM.
xorrisofs soporta further boot facilities: MIPS Big Endian (SGI), MIPS Little Endian (DEC), SUN SPARC, HP-PA, DEC Alpha. Estas no son combinables entre sí ni tampoco con MBR, GPT, o APM.

Varias de las siguientes opciones esperan rutas de disco como entrada, pero también aceptan cadenas de descripción para el lector de intervalos libisofs, el cual es capaz de extraer datos de archivos de disco o de -indev y de poner a cero partes del contenido: -G, -generic-boot, --embedded-boot, --grub2-mbr, -isohybrid-mbr, -efi-boot-part, -prep-boot-part, -B, -sparc-boot, -append_partition.
La cadena de descripción consta de los siguientes componentes, separados por dos puntos ':'.
"--interval:"Flags":"Interval":"Zeroizers":"Source
El componente "--interval" indica que no se trata de una ruta de disco simple, sino de una cadena de descripción del lector de intervalos.
El componente Flags modifica la interpretación posterior:
"local_fs" exige leer de un archivo representado por la ruta en Source.
"imported_iso" exige leer desde -indev. Esto solo funciona si -outdev no es lo mismo que -indev. El componente Source se ignora.
"appended_partition_NNN" con un número decimal NNN solo funciona para opciones que anuncian rutas de imagen de arranque El Torito: -b, -e, --efi-boot. El número indica el número de partición tal como se usa con la opción correspondiente -append_partition.
El componente Interval consta de dos números de dirección de bytes separados por un carácter de guion '-'. Por ejemplo, "0-429" significa leer los bytes del 0 al 429.
El componente Zeroizers consta de cero o más cadenas separadas por comas. Definen qué parte de los datos leídos se pondrá a cero. El byte número 0 significa el byte leído desde la dirección de inicio del Intervalo. Cada cadena puede ser una de las siguientes:
"zero_mbrpt" exige poner a cero la tabla de particiones MBR si los bytes 510 y 511 contienen la firma MBR 0x55 0xaa.
"zero_gpt" exige verificar la presencia de una cabecera GPT en los bytes 512 a 1023, ponerla a cero junto con sus bloques de tabla de particiones.
"zero_apm" exige verificar el bloque 0 de APM y poner a cero sus bloques de tabla de particiones.
Start_byte"-"End_byte exige poner a cero los bytes leídos comenzando con el número Start_byte y terminando después de End_byte.
El componente Source es la ruta del archivo con la bandera "local_fs", y se ignora con la bandera "imported_iso".
Los números de byte pueden ser escalados por un sufijo de {k,m,g,t,s,d} que significa multiplicación por {1024, 1024k, 1024m, 1024g, 2048, 512}. Un número final escalado representa el último byte del rango escalado.
Por ejemplo, "0d-0d" es "0-511".
Ejemplos:
"local_fs:0-32767:zero_mbrpt,zero_gpt,440-443:/tmp/template.iso"
"imported_iso:45056d-47103d::"

-G disk_path
Copia como máximo 32768 bytes del archivo de disco dado al principio de la imagen ISO.
A diferencia de una imagen de arranque El Torito, el archivo disk_path no necesita ser añadido a la imagen ISO. No aparecerá como archivo en los árboles de directorios.
En situaciones de múltiples sesiones, la ruta de disco especial "." evita la lectura de un archivo de disco pero, sin embargo, provoca los ajustes en el MBR existente, que fueron ordenados por otras opciones.

Alias de -G.
--embedded-boot disk_path
Alias de -G.
--grub2-mbr disk_path
Instala disk_path en el Área del Sistema y lo trata como un MBR GRUB2 moderno. La dirección de inicio del contenido de la primera imagen de arranque se convierte en un recuento de bloques de 512 bytes, y se añade un desplazamiento de 4. El resultado se escribe como un número de 64 bits little-endian en la dirección de byte 0x1b0.
-isohybrid-mbr disk_path
Instala disk_path como MBR ISOLINUX isohybrid, lo que hace que la imagen de arranque dada por la opción -b sea arrancable desde pendrives y discos duros a través de PC-BIOS. Esta preparación normalmente la realiza el programa isohybrid de ISOLINUX sobre la imagen ISO ya producida.
La ruta del disco debe conducir a uno de los archivos de Syslinux isohdp[fp]x*.bin. El MBR se parchea según las necesidades de isohybrid. La primera partición describe el rango de la imagen ISO. Su inicio está en el bloque 0 por defecto, pero puede establecerse en 64 bloques de disco con la opción -partition_offset 16.
Para el significado de la ruta de disco especial "." véase la opción -G.
-isohybrid-gpt-basdat
Marca la imagen de arranque El Torito actual (ver opciones -b y -e) en una GPT inválida como partición de tipo Basic Data. Esto solo funciona con -isohybrid-mbr y tiene el mismo impacto en el área del sistema que -efi-boot-part. No se puede combinar con -efi-boot-part o -hfsplus.
Las primeras tres imágenes de arranque marcadas por GPT también aparecerán como entradas de partición en MBR. La partición MBR de tipo 0xEF es la que utiliza realmente el firmware EFI para arrancar desde un pendrive. La partición MBR para PC-BIOS obtiene el tipo 0x00 en lugar de 0x17 en este caso. A menudo, las entradas MBR posteriores son las que realmente utiliza EFI.
-isohybrid-gpt-hfsplus
Marca la imagen de arranque El Torito actual (ver opciones -b y -e) en GPT como partición de tipo HFS+. El impacto y las restricciones son como con -isohybrid-gpt-basdat.
-isohybrid-apm-hfsplus
Marca la imagen de arranque El Torito actual (ver opciones -b y -e) en Apple Partition Map como partición de tipo HFS+. Esto solo funciona con -isohybrid-mbr y tiene un impacto similar en el área del sistema que -hfsplus. No se puede combinar con -efi-boot-part o -hfsplus.
El archivo MBR isohybrid ISOLINUX debe comenzar con un patrón conocido de 32 bytes de código máquina x86 que esencialmente no hace nada. Será sobrescrito por 32 bytes de una simulación de cabecera APM.
-part_like_isohybrid
Controla si -isohybrid-gpt-basdat, -isohybrid-gpt-hfsplus y -isohybrid-apm-hfsplus se aplican incluso si -isohybrid-mbr no está presente. No emerge ninguna partición MBR de tipo 0xee, incluso si se produce GPT. Los huecos entre las particiones GPT y APM no se rellenarán con más particiones. Las particiones añadidas se mencionarán en APM si emergen otras particiones APM.
-iso_mbr_part_type "default"|number|type_guid
Establece el tipo de partición del MBR o GPT que representa la ISO o al menos la protege.
El número puede ser de 0x00 a 0xff. El texto "default" restablece los tipos por defecto de las diversas ocasiones para crear una partición ISO MBR. Esto no tiene efecto si no emerge ninguna partición por otras configuraciones o si el tipo de partición se prescribe obligatoriamente, como 0xee para MBR protector GPT o 0x96 para CHRP.
Si en su lugar se proporciona un type_guid como una cadena hexadecimal de 32 dígitos como a2a0d0ebe5b9334487c068b6b72699c7 o como un texto estructurado como EBD0A0A2-B9E5-4433-87C0-68B6B72699C7, se utilizará como tipo de partición si el sistema de archivos ISO aparece como partición en GPT. En MBR, C12A7328-F81F-11D2-BA4B-00A0C93EC93B se mapeará a 0xef. Cualquier otro GUID se mapeará a 0x83.
--protective-msdos-label
Parchea el Área del Sistema con una tabla de particiones PC-DOS simple donde la partición 1 reclama el rango de la imagen ISO pero deja el primer bloque sin reclamar. Esto es mutuamente excluyente con la opción -isohybrid-mbr.
--mbr-force-bootable
Fuerza una partición MBR con la bandera "bootable/active" si se dan opciones como --protective-msdos-label o --grub2-mbr. Estas opciones normalmente hacen que la bandera se establezca si hay una partición MBR de tipo distinto de 0xee o 0xef. Si no existe tal partición, entonces no se establece ninguna bandera de arranque, a menos que --mbr-force-bootable fuerce la creación de una partición ficticia de tipo 0x00 que cubra solo el primer bloque de la imagen ISO.
Si ninguna otra opción indica un MBR arrancable y se crea una partición con -append_partition, entonces --mbr-force-bootable causa una bandera de arranque como lo haría con, por ejemplo, --protective-msdos-label.
--gpt-iso-bootable
Establece el bit 2 de las banderas de partición GPT para la partición ISO 9660 si emerge dicha partición GPT. Este bit se especifica como "Legacy BIOS bootable" pero su verdadero significado no está claro. Algunos BIOS compatibles con GPT podrían querer verlo en alguna partición.
--gpt-iso-not-ro
No establece el bit 60 de las banderas de partición GPT para la partición ISO 9660 si emerge dicha partición GPT. Este bit se especifica como "Read-only" y por lo tanto es apropiado. Pero es inusual en particiones de disco GPT.
-partition_offset 2kb_block_adr
Causa la creación de una tabla de particiones con una sola partición que comienza en la dirección de bloque dada. Esto se cuenta en bloques de 2048 bytes, no en bloques de 512 bytes. Si la dirección de bloque no es cero, debe ser al menos 16. Valores mayores que 16 son difícilmente útiles. Un desplazamiento de partición no cero causa la generación de dos superbloques y dos conjuntos de árboles de directorios. La imagen será entonces montable desde su inicio absoluto, así como desde el inicio de la partición.
El valor de desplazamiento de una imagen ISO se conserva cuando se añade una nueva sesión a una imagen cargada. Por lo tanto, el valor definido aquí solo está en vigor si se escribe una nueva imagen ISO.
-partition_hd_cyl number
Establece el número de cabezales por cilindro para la tabla de particiones MBR. 0 elige un
-partition_sec_hd número
Establece el número de sectores por cabeza para la tabla de particiones MBR. 0 elige un valor predeterminado. El máximo es 63.
El producto partition_sec_hd * partition_hd_cyl * 512 es el tamaño del cilindro. Debe ser divisible por 2048 para permitir una alineación exacta. Con particiones añadidas y -appended_part_as_gpt no hay límite para el número de cilindros. De lo contrario, puede haber como máximo 1024 de ellos. Si el tamaño del cilindro es demasiado pequeño para mantenerse por debajo del límite, entonces se eligen valores apropiados de partition_hd_cyl con partition_sec_hd 32 o 63. Si la imagen es mayor que 8.422.686.720 bytes, entonces las restricciones de tamaño del cilindro no se pueden cumplir para MBR. De todos modos, no parecen ser muy importantes. Las direcciones de bloque planas en las tablas de particiones son buenas para 1 TiB.
-partition_cyl_align modo
Controla la alineación del tamaño de la imagen a un número entero de cilindros. Está prescrito por las especificaciones isohybrid y parece complacer al programa fdisk. El tamaño del cilindro debe ser divisible por 2048. Las imágenes mayores que 8.323.596.288 bytes no pueden alinearse en la tabla de particiones MBR.
El modo "auto" es el predeterminado. La alineación mediante relleno solo ocurre si se proporciona la opción -isohybrid-mbr.
El modo "on" provoca la alineación mediante relleno con la opción --protective-msdos-label también. El modo "all" es como "on" pero también rellena las particiones de -append_partition a un tamaño alineado.
El modo "off" deshabilita la alineación incondicionalmente.
-append_partition número_partición código_tipo ruta_disco
Hace que una imagen de sistema de archivos preparada se añada a la imagen ISO y se describa mediante una entrada de tabla de particiones en un bloque de arranque al inicio de la imagen ISO emergente. La entrada de partición tendrá el tamaño del archivo enviado redondeado al siguiente múltiplo de 2048 bytes o al siguiente múltiplo del tamaño del cilindro.
Tenga cuidado con las ejecuciones multisesión posteriores. La partición añadida se sobrescribirá.
número_partición puede ser de 1 a 4. El número 1 colocará toda la imagen ISO en el espacio no reclamado antes de la partición 1. Así, junto con la mayoría de las características MBR o GPT de xorriso, el número 2 sería la opción más natural.
código_tipo puede ser "FAT12", "FAT16", "Linux", o un número hexadecimal entre 0x00 y 0xff. No todos esos números darán resultados útiles. Para obtener una lista de códigos, busque en Internet "Partition Types" o ejecute el comando fdisk "L". Si la partición aparece en GPT, el código_tipo 0xef se mapea al GUID de tipo de Partición del Sistema EFI. Todos los demás se mapean a GUID de Tipo de Datos Básico.
código_tipo también puede ser un GUID de tipo como una cadena hexadecimal simple como a2a0d0ebe5b9334487c068b6b72699c7 o como texto estructurado como EBD0A0A2-B9E5-4433-87C0-68B6B72699C7. Se utilizará si la partición se menciona en GPT. En MBR, C12A7328-F81F-11D2-BA4B-00A0C93EC93B se mapeará a 0xef. Cualquier otro GUID se mapeará a 0x83. En APM, 48465300-0000-11AA-AA11-00306543ECAC se mapeará al tipo de partición "Apple_HFS", cualquier otro a "Data".
Si algún otro comando provoca la producción de GPT, las particiones añadidas también se mencionarán allí, incluso si no se proporciona -appended_part_as_gpt.
-appended_part_as_gpt
Marca las particiones de -append_partition en GPT en lugar de en MBR. En este caso, el MBR muestra una única partición de tipo 0xee que cubre todos los datos de salida.
Por defecto, las particiones añadidas se marcan solo en GPT si se produce GPT debido a otras opciones.
-appended_part_as_apm
Marca las particiones de -append_partition en Apple Partition Map también.
Por defecto, las particiones añadidas se marcan solo en APM si se produce APM debido a otras opciones y se habilita -part_like_isohybrid.

Extracción de Plantillas Jigdo:

De man genisoimage: "Jigdo es una herramienta para ayudar en la distribución de archivos grandes como imágenes de CD y DVD; ver http://atterer.net/jigdo/ para más detalles. Las imágenes ISO de Debian CDs y DVDs se publican en la web en formato jigdo para permitir a los usuarios finales descargarlas de manera más eficiente."
Si se habilitó el uso de libjte en tiempo de compilación de xorriso, entonces xorrisofs puede producir un archivo .jigdo y un archivo .template junto con una imagen ISO de sesión única. Si no, las opciones de Jigdo causarán un evento de FALLO, que normalmente lleva a la interrupción del programa.
Se puede determinar la capacidad para Jigdo con:
$ xorrisofs -version 2>&1 | grep '^libjte' && echo YES

El archivo .jigdo contiene sumas de verificación y direcciones simbólicas de archivos. El archivo .template contiene la imagen ISO comprimida con etiquetas de referencia en lugar de los bytes de contenido de los archivos listados.
La entrada para este proceso son los argumentos normales para una sesión de xorrisofs sin imagen cargada, y un archivo de suma de verificación que lista aquellos archivos de datos que pueden ser listados en el archivo .jigdo y referenciados externamente en el archivo .template. Cada archivo designado se representa en el archivo de suma de verificación por una única línea de texto:
Suma de verificación en dígitos hexadecimales, 2 espacios, tamaño en dígitos decimales de 12 dígitos o espacios, 2 espacios, dirección simbólica del archivo
El tipo de suma de verificación se elige mediante -jigdo "checksum_algorithm" con los valores "md5" (32 dígitos hexadecimales) o "sha256" (64 dígitos hexadecimales). También se usará para las líneas de direcciones de archivos en el archivo .jigdo.
El valor predeterminado es "md5".
La dirección del archivo en una línea del archivo de suma de verificación debe tener el mismo nombre base que la ruta del disco del archivo que debe coincidir. La ruta del directorio de la dirección del archivo es decisiva para el mapeo To=From, no para el reconocimiento del archivo. Después del mapeo To=From, la dirección del archivo se escribe en el archivo .jigdo. Las herramientas de restauración de Jigdo convertirán estas direcciones en direcciones de origen de datos realmente accesibles desde las cuales pueden leer.
Si la lista de parámetros de jigdo no está vacía, el relleno se contará como parte de la imagen ISO.

Elige los algoritmos para las sumas de verificación "# Template Hex" en el archivo .jigdo. Las reglas para list_of_names son las mismas que con -checksum_algorithm_iso.

Una ejecución simple de producción de imagen

Un árbol de archivos preparado en el directorio ./for_iso se copia en el directorio raíz de la imagen ISO. Los permisos de archivo se establecen como solo lectura para todos. Se agregan atributos Joliet para sistemas Microsoft. La imagen resultante se escribe como archivo de datos ./image.iso en el disco.
$ xorrisofs -r -J -o ./image.iso ./for_iso

Establecer rutas de imagen ISO mediante -graft-points

Sin la opción -graft-points, cada archivo de disco dado se copia en el directorio raíz de la imagen ISO, manteniendo su nombre. Si se da un directorio, sus archivos y subdirectorios se copian en el directorio raíz, manteniendo sus nombres.
$ xorrisofs ... /home/me/datafile /tmp/directory
produce en el directorio raíz de la imagen ISO:
/datafile
/file_1_from_directory
...
/file_N_from_directory

Con la opción -graft-points es posible colocar archivos y directorios en rutas arbitrarias de la imagen ISO.
$ xorrisofs ... -graft-points /home/me/datafile /dir=/tmp/directory
produce en el directorio raíz de la imagen ISO

y:
/datafile
/dir
Los directorios padres necesarios en la imagen serán creados automáticamente:
/datafiles/file1=/home/me/datafile
produce en la imagen ISO:
/datafiles/file1
Los atributos del directorio /datafiles se copian de /home/me en disco.

Normalmente, uno debería evitar los caracteres = y \ en la parte ISO de un pathspec. Pero si es necesario, se pueden escapar:
/with_\=_and_\\/file=/tmp/directory/file
produce en la imagen ISO:
/with_=_and_\/file

Realizar ejecuciones multisesión

Este ejemplo funciona solo para medios multisesión: CD-R[W], DVD-R[W], DVD+R, BD-R. Añadir la opción de cdrskin --grow_overwriteable_iso a todas las ejecuciones -as cdrecord para habilitar la emulación multisesión en medios regrabables.
La primera sesión se escribe de la siguiente manera:
$ xorrisofs -graft-points \
/tree1=prepared_for_iso/tree1 \
| xorriso -as cdrecord -v dev=/dev/sr0 blank=fast -multi -eject -
Las sesiones posteriores se escriben de la siguiente manera (la ejecución de dd es solo para dar a los demonios la oportunidad de estropearlo):
$ m=$(xorriso -as cdrecord dev=/dev/sr0 -msinfo)
$ dd if=/dev/sr0 count=1 >/dev/null 2>&1
$ xorrisofs -M /dev/sr0 -C $m -graft-points \
/tree2=prepared_for_iso/tree2 \
| xorriso -as cdrecord -v dev=/dev/sr0 -waiti -multi -eject -
Expulse siempre la bandeja de la unidad entre sesiones.
La ejecución de xorriso -as mkisofs leerá sesiones antiguas a través del controlador de CD-ROM de /dev/sr0. Es posible que este controlador no sea consciente del contenido modificado mientras el medio no se cargue de nuevo. En este caso, xorriso no evaluaría correctamente la sesión anterior y la nueva sesión solo contendría los archivos recién añadidos.
Algunos sistemas no tienen suficiente paciencia con la carga automática de bandejas y algunos demonios pueden interferir con el primer intento de lectura del controlador de CD-ROM desde un medio recién cargado.
Al cargar la bandeja manualmente, espere 10 segundos después de que la unidad haya dejado de parpadear.
Una forma automática segura parece ser una ejecución separada de xorriso para cargar la bandeja con la espera adecuada, y una ejecución posterior de dd que se ofrecerá a sí misma para cualquier problema causado por demonios que evalúen el estado modificado de la unidad. Si esto no ayuda, inserte una ejecución de "sleep 10" entre xorriso y dd.

Dejar que xorrisofs trabaje bajo growisofs

growisofs espera un programa formateador ISO que entienda las opciones -C y -M. Se define una variable para anular el nombre predeterminado codificado.
$ export MKISOFS="xorrisofs"
$ growisofs -Z /dev/dvd /some/files
$ growisofs -M /dev/dvd /more/files
Si no hay "xorrisofs" disponible en su sistema, entonces tendrá que crear un enlace que apunte al binario xorriso e indicarle a growisofs que lo use. Por ejemplo, mediante:
$ ln -s $(which xorriso) "$HOME/xorrisofs"
$ export MKISOFS="$HOME/xorrisofs"
Se puede salir de la emulación de mkisofs con el argumento "--" y utilizar todos los comandos de xorriso. growisofs no soporta opciones que comienzan con "-o", pero -outdev debe establecerse en "-". Así que use "outdev" en su lugar:
$ growisofs -Z /dev/dvd --for_backup -- \
outdev - -update_r /my/files /files
$ growisofs -M /dev/dvd --for_backup -- \
outdev - -update_r /my/files /files
Tenga en cuenta que --for_backup se da en la emulación de mkisofs. Para preservar los datos extra grabados, debe estar en vigor cuando la emulación cargue la imagen.

Copia de seguridad incremental de unos pocos árboles de directorios

Esto cambia los árboles de directorios /open_source_project y /personal_mail en la imagen ISO para que se conviertan en copias exactas de sus contrapartes en disco. Se crearán objetos de archivo ISO, se eliminarán o se ajustarán sus atributos en consecuencia.
Se registrarán ACL, xattr, enlaces duros y sumas de verificación MD5. Se espera que los números de inodo en el sistema de archivos de disco sean persistentes a través de ciclos de montaje y arranque. Los archivos con nombres que coincidan con *.o o *.swp se excluyen explícitamente.

Para ser utilizado varias veces en el mismo medio, cada vez que se desee una actualización de los dos árboles de disco al medio. Comience con un medio en blanco y actualícelo hasta que la ejecución falle sin problemas debido a la falta de espacio restante en el antiguo.
Expulse siempre la bandeja de la unidad entre sesiones. Una ejecución de dd debería dar a los demonios la oportunidad de estropear la primera lectura en medios recién cargados.
$ msinfo=$(xorriso -as cdrecord dev=/dev/sr0 -msinfo)
$ dd if=/dev/sr0 count=1 >/dev/null 2>&1
$ load_opts=
$ test -n "$msinfo" && load_opts="-M /dev/sr0 -C $msinfo"
$ xorrisofs $load_opts -o - --for_backup -m '*.o' -m '*.swp' \
-V PROJ_MAIL_"$(date '+%Y_%m_%d_%H%M%S')" -graft-points \
-old-root / \
/projects=/home/thomas/projects \
/personal_mail=/home/thomas/personal_mail \
| xorriso -as cdrecord dev=/dev/sr0 -v -multi -waiti -eject -

Esto tiene sentido si la copia de seguridad completa deja una capacidad restante sustancial en los medios y si los cambios esperados son mucho menores que la copia de seguridad completa.

Mejor no usar su copia de seguridad más reciente para -old-root. Tenga al menos dos medios que use alternativamente. De modo que solo las copias de seguridad más antiguas se vean amenazadas por la nueva operación de escritura, mientras que la copia de seguridad más reciente se almacena de forma segura en un medio diferente.
Siempre tenga un medio en blanco listo para realizar una copia de seguridad completa en caso de que el intento de actualización falle debido a una capacidad restante insuficiente. Por supuesto, esta falla no estropeará el medio antiguo.

Si los números de inodo en disco no son persistentes, utilice la opción --old-root-no-ino. En este caso, una ejecución de actualización comparará las sumas MD5 grabadas con el contenido actual del archivo en el disco duro.

Con la opción de montaje **-o "sbsector="** en GNU/Linux o **-s** en FreeBSD o NetBSD, es posible acceder a los árboles de sesiones que representan las versiones de copia de seguridad anteriores. Con medios CD, GNU/Linux mount acepta números de sesión directamente con su opción "session=".
Los medios multisesión y la mayoría de los medios regrabables grabados por xorriso pueden indicar los sbsectores de sus sesiones con la opción -toc de xorriso:
$ xorriso -dev /dev/sr0 -toc
xorriso puede imprimir el comando de montaje coincidente para un número de sesión:
$ xorriso -mount_cmd /dev/sr0 session 12 /mnt
o para un ID de volumen que coincida con una expresión de búsqueda:
$ xorriso -mount_cmd /dev/sr0 volid '*2008_12_05*' /mnt
Ambos producen en la salida estándar algo como:
mount -t iso9660 -o nodev,noexec,nosuid,ro,sbsector=1460256 '/dev/sr0' '/mnt'
El superusuario puede dejar que xorriso ejecute el comando de montaje directamente:
# osirrox -mount /dev/sr0 "volid" '*2008_12_05*' /mnt

Copia de seguridad incremental con árboles acumulados

Solaris no ofrece la opción de montar sesiones anteriores. Para mantenerlas accesibles, se pueden mapear todos los archivos a un árbol de archivos bajo un directorio de sesión y acumular esos directorios de sesión en sesión. El árbol -root se clona del árbol -old-root antes de ser comparado con los árboles apropiados en disco.
Esto exige conocer el nombre del directorio de sesión utilizado previamente.
Con la primera sesión:
$ xorrisofs -root /session1 \
-o - --for_backup -m '*.o' -m '*.swp' \
-V PROJ_MAIL_"$(date '+%Y_%m_%d_%H%M%S')" -graft-points \
/projects=/home/thomas/projects \
/personal_mail=/home/thomas/personal_mail \
| xorriso -as cdrecord dev=/dev/sr0 -v blank=as_needed \
-multi -waiti -eject -

Con la segunda sesión, la opción -old-root se refiere a /session1 y el nuevo -root es /session2.
Expulse siempre la bandeja de la unidad entre sesiones. Una ejecución de dd debería dar a los demonios la oportunidad de estropear la primera lectura en medios recién cargados.
$ msinfo=$(xorriso -as cdrecord dev=/dev/sr0 -msinfo)
$ dd if=/dev/sr0 count=1 >/dev/null 2>&1
$ load_opts=
$ test -n "$msinfo" && load_opts="-M /dev/sr0 -C $msinfo"
$ xorrisofs $load_opts -root /session2 -old-root /session1 \
-o - --for_backup -m '*.o' -m '*.swp' \
-V PROJ_MAIL_"$(date '+%Y_%m_%d_%H%M%S')" -graft-points \
/projects=/home/thomas/projects \
/personal_mail=/home/thomas/personal_mail \
| xorriso -as cdrecord dev=/dev/sr0 -v -multi -waiti -eject -
Con la tercera sesión, la opción -old-root se refiere a /session2. El nuevo -root es /session3. Y así sucesivamente.

Crear imágenes arrancables para PC-BIOS y EFI

El conjunto de cargadores de arranque SYSLINUX/ISOLINUX es popular para arrancar PC-BIOS. La wiki de ISOLINUX prescribe crear en disco un directorio ./CD_root y copiar todos los archivos deseados debajo de ese directorio. Especialmente el archivo isolinux.bin se copiará a ./CD_root/isolinux/isolinux.bin. Este es el archivo de imagen de arranque.
Las opciones mkisofs prescritas se pueden usar sin cambios con **xorrisofs**:
$ xorrisofs -o output.iso \
-b isolinux/isolinux.bin -c isolinux/boot.cat \
-no-emul-boot -boot-load-size 4 -boot-info-table \
./CD_root
Grábelo en un CD con un programa de grabación. Por ejemplo:
$ xorriso -as cdrecord -v dev=/dev/sr0 blank=as_needed output.iso

La imagen del ejemplo anterior arrancará desde CD, DVD o BD, pero no desde una memoria USB u otros dispositivos similares a discos duros. Esto se puede hacer con la ayuda de un MBR isohíbrido. Syslinux proporciona archivos de plantilla coincidentes como isohdp[fp]x*.bin. Por ejemplo, /usr/lib/syslinux/isohdpfx.bin.
Si unos pocos cientos de KB de tamaño no importan, la opción -partition_offset se puede usar para crear una tabla de particiones donde la partición 1 comienza no en el bloque 0. Esto facilita las manipulaciones posteriores de la memoria USB con herramientas de partición y formateo.
La imagen del siguiente ejemplo estará preparada para arrancar vía MBR y su primera partición comenzará en el bloque 64 del disco duro.
También arrancará desde medios ópticos.
$ xorrisofs -o output.iso \
-b isolinux/isolinux.bin -c isolinux/boot.cat \
-no-emul-boot -boot-load-size 4 -boot-info-table \
-isohybrid-mbr /usr/lib/syslinux/isohdpfx.bin

NOMBRE

xorrisofs - construir imágenes de CD-ROM de datos

SINOPSIS

xorrisofs [ OPCIONES... ] [ -graft-points ] RUTA...

DESCRIPCIÓN

xorrisofs genera imágenes de CD-ROM de datos. Está destinado a ser un reemplazo compatible con la mayoría de las aplicaciones para mkisofs, que a su vez está basado en el trabajo de cdrecord. xorrisofs está soportado por el proyecto libburnia-project.org y tiene como objetivo ser compatible con el estándar ECMA-119 (ISO 9660), con extensiones como Rock Ridge, Joliet, HFS+, El Torito, ISO/IEC 13346 (Reino Unido), CD/DVD Hybrid y UDF.

El programa está diseñado para ser lo más compatible posible con mkisofs. Para las extensiones no contempladas por ISO 9660, se basa en la implementación de libisofs.

La ejecución interactiva de xorrisofs puede ser iniciada por el usuario escribiendo ejemplos. Los no iniciados por el usuario son posibles, pero no recomendados.

El programa maneja la mayoría de los archivos y directorios de entrada que no son de solo-lectura. Si el origen es un archivo de imagen de disco, se pueden leer archivos de ahí o se puede leer el disco entero. Los archivos y directorios de entrada se pueden nombrar explícitamente o pueden ser leídos de un archivo de lista de archivos o de la tabla de particiones de una imagen de disco.

Para EFI:

El archivo de imagen de arranque debe ser una imagen de una partición del sistema EFI, es decir, un sistema de archivos FAT con el directorio /EFI/BOOT y los archivos de arranque con los nombres prescritos por EFI: BOOTIA32.EFI para x86 de 32 bits, BOOTx64.EFI para AMD/x86 de 64 bits (en UEFI-2.4 hay de hecho una "x" en minúsculas), BOOTAA64.EFI para ARM de 64 bits. El software en el sistema de archivos FAT debería ser capaz de encontrar e inspeccionar el sistema de archivos ISO en busca de la configuración del cargador de arranque y el inicio del sistema operativo. El programa GRUB2 grub-mkimage puede producir un sistema de archivos FAT tal con contenido adecuado, que luego utiliza más software GRUB2 del sistema de archivos ISO.

Los equipos de arranque EFI se pueden combinar con la imagen isohybrid de arriba para PC-BIOS de una manera no realmente compatible con UEFI-2.4, lo que obviamente funciona bien. Produce tablas de particiones MBR y GPT, ambas con particiones anidadas. Suponiendo que la imagen de la partición del sistema EFI está lista como ./CD_root/boot/grub/efi.img, agregue las siguientes opciones antes de la dirección del directorio ./CD_root:

   -eltorito-alt-boot -e 'boot/grub/efi.img' -no-emul-boot \
   -isohybrid-gpt-basdat \

Más compatible con UEFI-2.4 es decidir por MBR o GPT y adjuntar una copia de la partición del sistema EFI para evitar la superposición de la partición ISO y la partición EFI. Aquí para MBR:

   -eltorito-alt-boot -e 'boot/grub/efi.img' -no-emul-boot \
   -append_partition 2 0xef ./CD_root/boot/grub/efi.img \

Se supone que las ISO resultantes arrancan desde medios ópticos y unidades USB. Se puede omitir la opción -eltorito-alt-boot si no se usa la opción -b para hacer que la ISO arranque a través de PC-BIOS.

Para ISOs con equipo de arranque GRUB2 puro, considere usar la herramienta GRUB2 grub-mkrescue como frontend para xorrisofs.

Si tiene un sistema de archivos ISO de arranque y desea conocer su equipamiento más una propuesta sobre cómo reproducirlo, intente:

   $ xorriso -hfsplus on -indev IMAGE.iso \
   -report_el_torito plain -report_system_area plain \
   -print "" -print "======= Propuesta para opciones de xorrisofs:" \
   -report_el_torito as_mkisofs

Los archivos se leen en la secuencia dada aquí, pero ninguno de ellos es requerido. Las líneas no se interpretan como opciones de xorrisofs sino como comandos genéricos de xorriso. Consulte man xorriso.

Después de los archivos de inicio de xorriso, el programa intenta uno por uno abrir para lectura:

    ./.mkisofsrc
    $MKISOFSRC
    $HOME/.mkisofsrc
    $(dirname $0)/.mkisofsrc

En caso de éxito, interpreta el contenido del archivo y no intenta con más archivos. La última dirección solo se usa si el argumento de inicio 0 tiene un dirname no trivial.

El lector actualmente interpreta los siguientes pares NOMBRE=VALOR:

    APPI predeterminado para -A
    PUBL predeterminado para -publisher
    SYSI predeterminado para -sysid
    VOLI predeterminado para -V
    VOLS predeterminado para -volset

Cualquier otra línea será ignorada silenciosamente.

ENTORNO

Las siguientes variables de entorno influyen en el comportamiento del programa:

HOME se usa para encontrar los archivos de inicio de xorriso y mkisofs.

MKISOFSRC puede usarse para señalar al programa a un archivo de inicio de mkisofs.

SOURCE_DATE_EPOCH pertenece a las especificaciones de reproducible-builds.org. Se supone que está indefinido o que contiene un número decimal que indica los segundos desde el 1 de enero de 1970. Si contiene un número, se usa como valor de tiempo para establecer el predeterminado de --modification-date=. --gpt_disk_guid toma por predeterminado "modification-date". El predeterminado de --set_all_file_dates es entonces "set_to_mtime". Además, el tiempo "now" para los nodos ISO sin fuente de disco se establece en el valor de SOURCE_DATE_EPOCH.

Los archivos de inicio y las opciones del programa pueden anular el efecto de SOURCE_DATE_EPOCH.
