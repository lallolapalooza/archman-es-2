NOMBRE

xorg.conf, xorg.conf.d - archivos de configuración para el servidor X Xorg

INTRODUCCIÓN

Xorg soporta varios mecanismos para proporcionar/obtener parámetros de configuración y de tiempo de ejecución: opciones de línea de comandos, variables de entorno, los archivos de configuración xorg.conf y xorg.conf.d, auto-detección y valores predeterminados de respaldo. Cuando se proporciona la misma información de más de una manera, se utiliza el mecanismo de mayor precedencia. La lista de mecanismos está ordenada de mayor a menor precedencia. Tenga en cuenta que no todos los parámetros se pueden proporcionar a través de todos los métodos. Las opciones de línea de comandos y las variables de entorno disponibles (y algunos valores predeterminados) se describen en las páginas del manual Xserver(1) y Xorg(1). La mayoría de los parámetros del archivo de configuración, con sus valores predeterminados, se describen a continuación. Los parámetros de configuración específicos del controlador y del módulo se describen en la página del manual del controlador o módulo relevante.

DESCRIPCIÓN

Xorg utiliza un archivo de configuración llamado xorg.conf y archivos que terminan con el sufijo .conf del directorio xorg.conf.d para su configuración inicial. El archivo de configuración xorg.conf se busca en los siguientes lugares cuando el servidor se inicia como un usuario normal:

/etc/X11/<cmdline>
/usr/etc/X11/<cmdline>
/etc/X11/$XORGCONFIG
/usr/etc/X11/$XORGCONFIG
/etc/X11/xorg.conf
/etc/xorg.conf
/usr/etc/X11/xorg.conf.<hostname>
/usr/etc/X11/xorg.conf
/usr/lib/X11/xorg.conf.<hostname>
/usr/lib/X11/xorg.conf

donde <cmdline> es una ruta relativa (sin componentes “..”) especificada con la opción de línea de comandos -config, $XORGCONFIG es la ruta relativa (sin componentes “..”) especificada por esa variable de entorno, y <hostname> es el nombre de host de la máquina según lo informado por gethostname(3).

Cuando el servidor Xorg es iniciado por el usuario “root”, las ubicaciones de búsqueda del archivo de configuración son las siguientes:

<cmdline>
/etc/X11/<cmdline>
/usr/etc/X11/<cmdline>
$XORGCONFIG
/etc/X11/$XORGCONFIG
/usr/etc/X11/$XORGCONFIG
/etc/X11/xorg.conf
/etc/xorg.conf
/usr/etc/X11/xorg.conf.<hostname>
/usr/etc/X11/xorg.conf
/usr/lib/X11/xorg.conf.<hostname>
/usr/lib/X11/xorg.conf

donde <cmdline> es la ruta especificada con la opción de línea de comandos -config (que puede ser absoluta o relativa), $XORGCONFIG es la ruta especificada por esa variable de entorno (absoluta o relativa), $HOME es la ruta especificada por esa variable de entorno (generalmente el directorio de inicio) y <hostname> es el nombre de host de la máquina según lo informado por gethostname(3).

Se buscan archivos de configuración adicionales en los siguientes directorios cuando el servidor se inicia como un usuario normal:

/etc/X11/<cmdline>
/etc/X11/<cmdline>
/etc/X11/xorg.conf.d
/etc/X11/xorg.conf.d

donde <cmdline> es una ruta relativa (sin componentes “..”) especificada con la opción de línea de comandos -configdir.

Cuando el servidor Xorg es iniciado por el usuario “root”, las ubicaciones de búsqueda del directorio de configuración son las siguientes:

<cmdline>
/etc/X11/<cmdline>
/etc/X11/<cmdline>
/etc/X11/xorg.conf.d
/etc/X11/xorg.conf.d

donde <cmdline> es la ruta especificada con la opción de línea de comandos -configdir (que puede ser absoluta o relativa).

Finalmente, también se buscarán archivos de configuración en un directorio reservado para uso del sistema. Esto es para separar los archivos de configuración de los paquetes del proveedor o de terceros de los de administración local. Estos archivos se encuentran en el siguiente directorio:

/usr/share/X11/xorg.conf.d

Los archivos xorg.conf y xorg.conf.d se componen de un número de secciones que pueden estar presentes en cualquier orden, u omitirse para usar los valores de configuración predeterminados. Cada sección tiene el formato:

Section  "NombreSección"
    EntradaSección
    ...
EndSection

Los nombres de sección son:

Files          Nombres de ruta de archivo
ServerFlags    Marcas del servidor
Module         Carga dinámica de módulos
Extensions     Habilitación de extensiones
InputDevice    Descripción del dispositivo de entrada
InputClass     Descripción de la clase de entrada
OutputClass    Descripción de la clase de salida
Device         Descripción del dispositivo gráfico
VideoAdaptor   Descripción del adaptador de video Xv
Monitor        Descripción del monitor
Modes          Descripciones de modos de video
Screen         Configuración de pantalla
ServerLayout   Diseño general
DRI            Configuración específica de DRI
Vendor         Configuración específica del proveedor

Los siguientes nombres de sección obsoletos todavía se reconocen por motivos de compatibilidad. En los nuevos archivos de configuración, se debe usar la sección InputDevice en su lugar.

Keyboard       Configuración del teclado
Pointer        Configuración del puntero/ratón

La sección antigua XInput ya no se reconoce.

Las secciones ServerLayout están en el nivel más alto. Vinculan los dispositivos de entrada y salida que se utilizarán en una sesión. Los dispositivos de entrada se describen en las secciones InputDevice. Los dispositivos de salida suelen constar de varios componentes independientes (por ejemplo, una tarjeta gráfica y un monitor). Estos componentes múltiples se vinculan en las secciones Screen, y son estas las que se referencian en la sección ServerLayout. Cada sección Screen vincula una tarjeta gráfica y un monitor. Las tarjetas gráficas se describen en las secciones Device y los monitores en las secciones Monitor.

Las palabras clave de los archivos de configuración no distinguen entre mayúsculas y minúsculas, y los caracteres “_” se ignoran. La mayoría de las cadenas (incluidos los nombres de Option) tampoco distinguen entre mayúsculas y minúsculas, y son insensibles al espacio en blanco y a los caracteres “_”.

Cada entrada del archivo de configuración suele ocupar una sola línea en el archivo. Consisten en una palabra clave, que posiblemente va seguida de uno o más argumentos, y el número y los tipos de los argumentos dependen de la palabra clave. Los tipos de argumento son:

Integer     un número entero en decimal, hexadecimal u octal
Real        un número de punto flotante
String      una cadena entre comillas dobles (")

Nota: los valores enteros hexadecimales deben ir precedidos de “0x”, y los valores octales de “0”.

Se puede utilizar una palabra clave especial llamada Option para proporcionar datos de formato libre a varios componentes del servidor. La palabra clave Option toma uno o dos argumentos de cadena. El primero es el nombre de la opción y el segundo argumento opcional es el valor de la opción. Algunos tipos de valores de opción utilizados comúnmente incluyen:

Integer     un número entero en decimal, hexadecimal u octal
Real        un número de punto flotante
String      una secuencia de caracteres
Boolean     un valor booleano (ver abajo)
Frequency   un valor de frecuencia (ver abajo)

Tenga en cuenta que *todos* los valores de Option, no solo las cadenas, deben ir entre comillas.

Las opciones booleanas pueden tener opcionalmente un valor especificado. Cuando no se especifica ningún valor, el valor de la opción es TRUE. Los siguientes valores de opción booleana se reconocen como TRUE:

1, on, true, yes

y los siguientes valores de opción booleana se reconocen como FALSE:

0, off, false, no

Si un nombre de opción va precedido de "No", entonces el valor de la opción se niega.

Ejemplo: las siguientes entradas de opción son equivalentes:

Option "Accel"   "Off"
Option "NoAccel"
Option "NoAccel" "On"
Option "Accel"   "false"
Option "Accel"   "no"

Los valores de opción de frecuencia consisten en un número real que opcionalmente va seguido de una de las siguientes unidades de frecuencia:

Hz, k, kHz, M, MHz

SECCIÓN FILES

La sección Files se utiliza para especificar algunos nombres de ruta requeridos por el servidor. Algunas de estas rutas también se pueden configurar desde la línea de comandos (ver Xserver(1) y Xorg(1)). La configuración de la línea de comandos anula los valores especificados en el archivo de configuración. La sección Files es opcional, al igual que todas las entradas que puedan aparecer en ella.

Las entradas que pueden aparecer en esta sección son:

FontPath "ruta"
establece la ruta de búsqueda de fuentes. Esta ruta es una lista de elementos de ruta de fuentes separados por comas que el servidor Xorg busca para las bases de datos de fuentes. Se pueden especificar múltiples entradas FontPath, y se concatenarán para construir la ruta de fuentes utilizada por el servidor. Los elementos de ruta de fuentes pueden ser rutas de directorios absolutas, directorios de catálogo o un identificador de servidor de fuentes. Los formatos de los dos últimos se explican a continuación:
Directorios de catálogo:
Los directorios de catálogo se pueden especificar usando el prefijo catalogue: antes del nombre del directorio. El directorio se puede poblar con enlaces simbólicos que apunten a los directorios de fuentes reales, utilizando la siguiente sintaxis en el nombre del enlace simbólico:
<identificador>:[atributo]:pri=<prioridad>

donde <identificador> es un identificador alfanumérico, [atributo] es un atributo que se pasará al FPE subyacente y <prioridad> es un número utilizado para ordenar los FPE de archivos de fuentes. Ejemplos:

75dpi:unscaled:pri=20 -> /usr/share/X11/fonts/75dpi
gscript:pri=60 -> /usr/share/fonts/default/ghostscript
misc:unscaled:pri=10 -> /usr/share/X11/fonts/misc
Identificadores de servidor de fuentes:
Los identificadores de servidor de fuentes tienen el formato:

<trans>/<nombrehost>:<numeropuerto>

donde <trans> es el tipo de transporte a usar para conectarse al servidor de fuentes (por ejemplo, unix para sockets de dominio UNIX o tcp para una conexión TCP/IP), <nombrehost> es el nombre del host de la máquina que ejecuta el servidor de fuentes, y <numeropuerto> es el número de puerto en el que está escuchando el servidor de fuentes (generalmente 7100).

Cuando esta entrada no se especifica en el archivo de configuración, el servidor recurre a la ruta de fuentes predeterminada compilada, que contiene los siguientes elementos de ruta de fuentes (que se pueden configurar dentro de un directorio de catálogo):

/usr/share/fonts/X11/misc/
/usr/share/fonts/X11/TTF/
/usr/share/fonts/X11/OTF/
/usr/share/fonts/X11/Type1/
/usr/share/fonts/X11/100dpi/
/usr/share/fonts/X11/75dpi/

Los elementos de ruta de fuentes que resultan ser inválidos se eliminan de la ruta de fuentes al iniciar el servidor.

ModulePath "ruta"
establece la ruta de búsqueda de módulos cargables del servidor Xorg. Esta ruta es una lista de directorios separados por comas que el servidor Xorg busca para cargar módulos, en el orden especificado. Se pueden especificar múltiples entradas ModulePath, y se concatenarán para construir la ruta de búsqueda de módulos utilizada por el servidor. La ruta de módulos predeterminada es
lib/xorg/modules
XkbDir "ruta"
establece el directorio base para los archivos de diseño de teclado. La opción de línea de comandos -xkbdir se puede usar para anular esto. El directorio predeterminado es
/usr/share/X11/xkb

SECCIÓN SERVERFLAGS

Además de las opciones específicas de esta sección (descritas a continuación), la sección ServerFlags se utiliza para especificar algunas opciones globales del servidor Xorg. Todas las entradas de esta sección son Options, aunque por motivos de compatibilidad todavía se reconocen algunas entradas de estilo antiguo. Esas entradas antiguas no se documentan aquí, y su uso no se recomienda. La sección ServerFlags es opcional, al igual que las entradas que se pueden especificar en ella.

Las Options especificadas en esta sección (con la excepción de la Option "DefaultServerLayout") pueden ser anuladas por las Options especificadas en la sección ServerLayout activa. Las opciones con equivalentes en la línea de comandos se anulan cuando se utiliza su equivalente en la línea de comandos. Las opciones reconocidas por esta sección son:

Option "Debug" "cadena"
Esta lista separada por comas proporciona una forma de controlar varios interruptores de depuración desde el archivo de configuración. Por el momento, el único valor definido es dmabuf_capable, que instruye a glamor para habilitar código de gestión de búfer inestable.
Option "DefaultServerLayout" "id-layout"
Esto especifica la sección ServerLayout predeterminada a usar en ausencia de la opción de línea de comandos -layout.
Option "DontVTSwitch" "booleano"
Esto prohíbe el uso de la secuencia Ctrl+Alt+Fn (donde Fn se refiere a una de las teclas de función numeradas). Esa secuencia normalmente se utiliza para cambiar a otra "terminal virtual" en sistemas operativos que tienen esta característica. Cuando esta opción está habilitada, esa secuencia de teclas no tiene un significado especial y se pasa a los clientes. Predeterminado: desactivado.
Option "DontZap" "booleano"
Esto prohíbe el uso de la acción XKB Terminate_Server (generalmente en Ctrl+Alt+Retroceso, dependiendo de las opciones de XKB). Esta acción normalmente se utiliza para terminar el servidor Xorg. Cuando esta opción está habilitada, la acción no tiene efecto. Predeterminado: desactivado.
Option "DontZoom" "booleano"
Esto prohíbe el uso de las secuencias Ctrl+Alt+Keypad-Plus y Ctrl+Alt+Keypad-Minus. Estas secuencias permiten cambiar entre modos de video. Cuando esta opción está habilitada, esas secuencias de teclas no tienen un significado especial y se pasan a los clientes. Predeterminado: desactivado.
Option "DisableVidModeExtension" "booleano"
Esto deshabilita las partes de la extensión VidMode utilizadas por el cliente xvidtune que se pueden usar para cambiar los modos de video. Predeterminado: la extensión VidMode está habilitada.
Option "AllowNonLocalXvidtune" "booleano"
Esto permite que el cliente xvidtune (y otros clientes que usan la extensión VidMode) se conecten desde otro host. Predeterminado: desactivado.
Option "AllowMouseOpenFail" "booleano"
Esto indica a los controladores mousedrv(4) y vmmouse(4) que no informen de un error si el dispositivo del ratón no se puede abrir/inicializar. No tiene efecto en los controladores evdev(4) u otros. Predeterminado: falso.
Option "BlankTime" "tiempo"
establece el tiempo de espera de inactividad para la fase blank del protector de pantalla. tiempo está en minutos. Esto es equivalente a la opción -s del servidor Xorg, y el valor se puede cambiar en tiempo de ejecución con xset(1). Predeterminado: 10 minutos.
Option "StandbyTime" "tiempo"
establece el tiempo de espera de inactividad para la fase standby del modo DPMS. tiempo está en minutos, y el valor se puede cambiar en tiempo de ejecución con xset(1). Predeterminado: 10 minutos. Esto solo es adecuado para monitores compatibles con VESA DPMS, y puede que no sea compatible con todos los controladores de video. Solo se habilita para pantallas que tengan configurada la opción "DPMS" (ver la sección MONITOR a continuación).
Option "SuspendTime" "tiempo"
establece el tiempo de espera de inactividad para la fase suspend del modo DPMS. tiempo está en minutos, y el valor se puede cambiar en tiempo de ejecución con xset(1). Predeterminado: 10 minutos. Esto solo es adecuado para monitores compatibles con VESA DPMS, y puede que no sea compatible con todos los controladores de video. Solo se habilita para pantallas que tengan configurada la opción "DPMS" (ver la sección MONITOR a continuación).
Option "OffTime" "tiempo"
establece el tiempo de espera de inactividad para la fase off del modo DPMS. tiempo está en minutos, y el valor se puede cambiar en tiempo de ejecución con xset(1). Predeterminado: 10 minutos. Esto solo es adecuado para monitores compatibles con VESA DPMS, y puede que no sea compatible con todos los controladores de video. Solo se habilita para pantallas que tengan configurada la opción "DPMS" (ver la sección MONITOR a continuación).
Option "MaxClients" "entero"
Establece el número máximo de clientes permitidos para conectarse al servidor X. Los valores aceptables son 64, 128, 256 o 512.
Option "NoPM" "booleano"
Deshabilita algo relacionado con los eventos de administración de energía. Predeterminado: PM habilitado en plataformas que lo admiten.
Option "Xinerama" "booleano"
habilita o deshabilita la extensión XINERAMA. Predeterminado: deshabilitado.
Option "IndirectGLX" "booleano"
habilita o deshabilita contextos GLX indirectos. Los contextos GLX indirectos están deshabilitados por defecto.
Option "DRI2" "booleano"
habilita o deshabilita DRI2. DRI2 está deshabilitado por defecto.

GLX SECTION

El servidor Xorg puede ser configurado para cargar módulos GLX específicos. Esta sección es opcional, al igual que todas las entradas que pueden especificarse en ella.

Las entradas en esta sección son pares de nombre-valor, donde el nombre es el nombre de la opción y el valor es el argumento de la opción. El nombre de la opción es sensible a mayúsculas y minúsculas.

Option "GlxVisuals" "string"
Esta opción controla cuántos visuales GLX configura el módulo GLX. El valor por defecto es typical, que configurará un subconjunto típico de los GLXFBConfigs proporcionados por el driver como visuales GLX. Otras opciones son minimal, que configurará el conjunto mínimo permitido por la especificación GLX, y all, que configurará visuales GLX para todos los GLXFBConfigs.
Option "UseDefaultFontPath" "boolean"
Incluye la ruta de fuentes por defecto incluso si otras rutas se especifican en xorg.conf. Si está habilitado, también se incluyen otras rutas de fuentes. Habilitado por defecto.
Option "IgnoreABI" "boolean"
Permite la carga de módulos compilados para una versión diferente y potencialmente incompatible del servidor X. Deshabilitado por defecto.
Option "AutoAddDevices" "boolean"
Si esta opción está deshabilitada, no se agregarán dispositivos desde los backends HAL o udev. Habilitado por defecto.
Option "AutoEnableDevices" "boolean"
Si esta opción está deshabilitada, los dispositivos se agregarán (y se enviará el evento DevicePresenceNotify), pero no se habilitarán, dejando la política a cargo del cliente. Habilitado por defecto.
Option "AutoAddGPU" "boolean"
Si esta opción está deshabilitada, no se agregarán dispositivos GPU desde el backend udev. Habilitado por defecto. (Puede ser necesario deshabilitarla para configurar Xinerama).
Option "AutoBindGPU" "boolean"
Si está habilitado, las GPUs secundarias se configurarán automáticamente como salidas de video y fuentes de descarga. Esto hace que, por ejemplo, las salidas de los portátiles conectadas solo a la GPU secundaria estén directamente disponibles para su uso sin necesidad de ejecutar "xrandr --setprovideroutputsource". Habilitado por defecto.
Option "Log" "string"
Esta opción controla si el log se vacía y/o se sincroniza al disco después de cada mensaje. Los valores posibles son flush o sync. No establecido por defecto.
Option "AllowByteSwappedClients" "boolean"
Permite clientes con un orden de bytes diferente al del servidor. Habilitado por defecto.

SECCIÓN MODULE

La sección Module se utiliza para especificar qué módulos del servidor Xorg deben cargarse. Esta sección se ignora cuando el servidor Xorg se compila en forma estática. El tipo de módulos que normalmente se cargan en esta sección son módulos de extensión del servidor Xorg. La mayoría de los otros tipos de módulos se cargan automáticamente cuando son necesarios a través de otros mecanismos. La sección Module es opcional, al igual que todas las entradas que pueden especificarse en ella.

Las entradas en esta sección pueden tener dos formas. La primera y más comúnmente utilizada es una entrada que utiliza la palabra clave Load, como se describe aquí:

Load "nombremodulo"
Esto instruye al servidor para que cargue el módulo llamado nombremodulo. El nombre del módulo dado debe ser el nombre estándar del módulo, no el nombre del archivo del módulo. El nombre estándar distingue entre mayúsculas y minúsculas, y no incluye los prefijos “lib” o “cyg”, ni los sufijos “.so” o “.dll”.
Ejemplo: el módulo de extensión DRI se puede cargar con la siguiente entrada:
Load "dri"
Disable "nombremodulo"
Esto instruye al servidor para que no cargue el módulo llamado nombremodulo. Algunos módulos se cargan por defecto en el servidor, y esto anula ese valor predeterminado. Si se da una instrucción Load para el mismo módulo, anula la instrucción Disable y el módulo se carga. El nombre del módulo dado debe ser el nombre estándar del módulo, no el nombre del archivo del módulo. Al igual que con la instrucción Load, el nombre estándar distingue entre mayúsculas y minúsculas, y no incluye el prefijo "lib", ni los sufijos ".a", ".o", o ".so".

La segunda forma de entrada es una SubSection, con el nombre de la subsección siendo el nombre del módulo, y el contenido de la SubSection siendo Options que se pasan al módulo cuando se carga.

Ejemplo: el módulo extmod (que contiene un grupo misceláneo de extensiones del servidor) se puede cargar, con la extensión XFree86-DGA deshabilitada usando la siguiente entrada:

SubSection "extmod"
   Option  "omit XFree86-DGA"
EndSubSection

Los módulos se buscan en cada directorio especificado en la ruta de búsqueda ModulePath, y en los subdirectorios drivers, extensions, input, internal y multimedia de cada uno de esos directorios. Además de esto, se buscan primero los subdirectorios específicos del sistema operativo de todo lo anterior si existen.

Para ver qué módulos de extensión están disponibles, consulte el subdirectorio extensions bajo:

lib/xorg/modules

Los módulos de extensión “extmod”, “dbe”, “dri”, “dri2”, “glx” y “record” se cargan automáticamente, si están presentes, a menos que se deshabiliten con entradas "Disable". Se recomienda cargar al menos el módulo de extensión “extmod”. Si no es así, algunas extensiones del servidor comúnmente utilizadas (como la extensión SHAPE) no estarán disponibles.

SECCIÓN EXTENSIONS

La sección Extensions se utiliza para especificar qué extensiones del protocolo X11 deben habilitarse o deshabilitarse. La sección Extensions es opcional, al igual que todas las entradas que pueden especificarse en ella.

Las entradas en esta sección se enumeran como sentencias Option con el nombre de la extensión como primer argumento y un valor booleano como segundo. El nombre de la extensión distingue entre mayúsculas y minúsculas, y coincide con la forma que se muestra en la salida de "Xorg -extension ?".

Ejemplo: la extensión MIT-SHM se puede deshabilitar con la siguiente entrada: 
Section "Extensions"
    Option "MIT-SHM" "Disable"
EndSection

SECCIÓN INPUTDEVICE

El archivo de configuración puede tener múltiples secciones InputDevice. Los servidores X recientes emplean backends HAL o udev para la enumeración de dispositivos de entrada y el hotplugging de entrada. Normalmente no es necesario proporcionar secciones InputDevice en xorg.conf si se utiliza el hotplugging (es decir, si AutoAddDevices está habilitado). Si el hotplugging está habilitado, se ignorarán las secciones InputDevice que utilicen el driver mouse, kbd y vmmouse.

Si el hotplugging está deshabilitado, normalmente habrá al menos dos: una para el teclado (primario) principal y otra para el puntero principal. Si falta alguna de estas dos, se utilizará una configuración por defecto para las que falten. En ausencia de un dispositivo de entrada principal especificado explícitamente, se utiliza el primer InputDevice marcado como CorePointer (o CoreKeyboard). Si no hay coincidencia allí, se utiliza el primer InputDevice que utiliza el driver “mouse” (o “kbd”). El último recurso es utilizar configuraciones por defecto integradas. Actualmente, la configuración por defecto puede no funcionar como se espera en todas las plataformas.

Las secciones InputDevice tienen el siguiente formato:

Section "InputDevice"
    Identifier "nombre"
    Driver     "driverentrada"
    options
    ...
EndSection

This is typically used to override the default auto-detection and should only be done when the driver-specific documentation recommends it.

This optional entry specifies the type of graphics chip. This is typically used to override the auto-detection and should only be done when the driver-specific documentation recommends it.

This optional entry specifies the default color depth (bits per pixel) to be used. This is typically used to override the auto-detection and should only be done when the driver-specific documentation recommends it.
RamSize ramsize
This optional entry specifies the amount of memory on the graphics board, in megabytes. This is typically used to override the auto-detection and should only be done when the driver-specific documentation recommends it.
Screen screen-number
This optional entry specifies the screen number to which this graphics board is attached. This is typically used to override the auto-detection and should only be done when the driver-specific documentation recommends it.

This optional entry specifies the memory base address of the graphics board's RAMDAC. This entry is not used by many drivers, and it should only be specified if the driver-specific documentation recommends it.

This optional entry specifies the IO base address. This entry is not used by many drivers, and it should only be specified if the driver-specific documentation recommends it.

SECCIÓN MODES

El archivo de configuración puede tener múltiples secciones Modes, o ninguna. Estas secciones proporcionan una forma de definir conjuntos de modos de video independientemente de las secciones Monitor. Las secciones Monitor pueden incluir las definiciones proporcionadas en estas secciones usando la palabra clave UseModes. En la mayoría de los casos, las secciones Modes no son necesarias porque el conjunto integrado de modos estándar VESA será suficiente.

Las secciones Modes tienen el siguiente formato:

Section "Modes"
    Identifier "nombre"
    entradas
    ...
EndSection

La entrada Identifier especifica el nombre único para este conjunto de descripciones de modos. Las otras entradas permitidas en las secciones Modes son las entradas Mode y ModeLine que se describen anteriormente en la sección Monitor.

SECCIÓN SCREEN

El archivo de configuración puede tener múltiples secciones Screen. Debe haber al menos una, para la pantalla que se está utilizando. Una "pantalla" representa la vinculación de un dispositivo gráfico (sección Device) y un monitor (sección Monitor). Una sección Screen se considera "activa" si es referenciada por una sección ServerLayout activa o por la opción de línea de comandos -screen. Si ninguna de esas está presente, la primera sección Screen que se encuentre en el archivo de configuración se considera la activa.

Las secciones Screen tienen el siguiente formato:

Section "Screen"
    Identifier "nombre"
    Device     "devid"
    GPUDevice  "devid"
    Monitor    "monid"
    entradas
    ...
    SubSection "Display"
       entradas
       ...
    EndSubSection
    ...
EndSection

La entrada Identifier es obligatoria. Todas las demás son opcionales.

La entrada Identifier especifica el nombre único para esta pantalla. La sección Screen proporciona información específica para toda la pantalla, incluidas las Options específicas de la pantalla. En configuraciones multi-head, habrá múltiples secciones Screen activas, una por cada cabeza.

Device "id-dispositivo"
Esta entrada especifica la sección Device que se utilizará para esta pantalla. Cuando hay múltiples tarjetas gráficas presentes, esto es lo que vincula una tarjeta específica a una pantalla. El id-dispositivo debe coincidir con el Identifier de una sección Device en el archivo de configuración.
GPUDevice "id-dispositivo"
Esta entrada especifica la sección Device que se utilizará como dispositivo GPU secundario para esta pantalla. Cuando hay múltiples tarjetas gráficas presentes, esto es lo que vincula una tarjeta secundaria específica a una pantalla. El id-dispositivo debe coincidir con el Identifier de una sección Device en el archivo de configuración. Esto se puede especificar hasta 4 veces para una sola pantalla.
Monitor "id-monitor"
especifica qué descripción de monitor se utilizará para esta pantalla. Si no se especifica un nombre de Monitor, se utiliza una configuración predeterminada. Currently the default configuration may not function as expected on all platforms.
VideoAdaptor "xv-id"
especifica una descripción opcional del adaptador de video Xv a usar con esta pantalla.
DefaultDepth profundidad
especifica la profundidad de color que el servidor debe usar por defecto. La opción de línea de comandos -depth puede usarse para anular esto. Si ninguna se especifica, la profundidad por defecto depende del controlador, pero en la mayoría de los casos es 8.
DefaultFbBpp bpp
especifica qué diseño de framebuffer usar por defecto. La opción de línea de comandos -fbbpp puede usarse para anular esto. En la mayoría de los casos, el controlador elegirá el mejor valor por defecto para esto. El único caso en el que existe una elección en este valor es para la profundidad 24, donde algunos hardware soportan tanto un diseño de framebuffer empaquetado de 24 bits como un diseño de framebuffer disperso de 32 bits.

Solo aplica esta sección Screen si el servidor X se inició con la opción -seat id-asiento.

Habilita la aceleración por hardware 2D. Esta opción está habilitada por defecto, pero puede ser necesario desactivarla si hay errores en el controlador. Hay muchas opciones para deshabilitar operaciones aceleradas específicas, listadas a continuación. Esta opción especifica una lista separada por espacios de bibliotecas de proveedor OpenGL a utilizar para la pantalla. Esto puede usarse para seleccionar una implementación alternativa para desarrollo, depuración o conjuntos de características alternativos. Por defecto: mesa.

Esta opción especifica una API de renderizado para usar junto con el método de aceleración Glamor. Cuando no hay una que coincida con los valores de profundidad y/o fbbpp que se están utilizando, todos los parámetros que se pueden especificar aquí vuelven a sus valores por defecto.

        entradas

Esta entrada especifica para qué profundidad de color se utilizará la subsección Display. Esta entrada generalmente se especifica, pero se puede omitir para crear una subsección Display que coincida con todo o cuando se desea coincidir solo con el parámetro FbBpp. El rango de valores de profundidad permitidos depende del controlador. La mayoría de los controladores soportan 8, 15, 16 y 24. Algunos también soportan 1 y/o 4, y otros pueden soportar otros valores (como 30).
