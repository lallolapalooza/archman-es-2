xorg.conf(5) Manual de formatos de archivo xorg.conf(5)

NOMBRE

xorg.conf, xorg.conf.d — archivos de configuración para el servidor X Xorg

INTRODUCCIÓN

Xorg soporta varios mecanismos para suministrar/obtener parámetros de configuración y de tiempo de ejecución: opciones de línea de comandos, variables de entorno, los archivos de configuración xorg.conf y xorg.conf.d, auto-detección y valores por defecto de respaldo. Cuando la misma información se suministra de más de una forma, se utiliza el mecanismo de mayor precedencia. La lista de mecanismos está ordenada de mayor a menor precedencia. Tenga en cuenta que no todos los parámetros se pueden suministrar a través de todos los métodos. Las opciones de línea de comandos y variables de entorno disponibles (y algunos valores por defecto) se describen en las páginas del manual de Xserver(1) y Xorg(1). La mayoría de los parámetros de archivos de configuración, con sus valores por defecto, se describen a continuación. Los parámetros de configuración específicos de controladores y módulos se describen en la página del manual del controlador o módulo correspondiente.

DESCRIPCIÓN

Xorg utiliza un archivo de configuración llamado xorg.conf y archivos que terminan con el sufijo .conf del directorio xorg.conf.d para su configuración inicial. El archivo de configuración xorg.conf se busca en los siguientes lugares cuando el servidor se inicia como usuario normal:

/etc/X11/<cmdline>
/usr/etc/X11/<cmdline>
/etc/X11/$XORGCONFIG
/usr/etc/X11/$XORGCONFIG
/etc/X11/xorg.conf
/etc/xorg.conf
/usr/etc/X11/xorg.conf.<hostname>
/usr/etc/X11/xorg.conf
/usr/lib/X11/xorg.conf.<hostname>
/usr/lib/X11/xorg.conf

donde <cmdline> es una ruta relativa (sin componentes “..”) especificada con la opción de línea de comandos -config, $XORGCONFIG es la ruta relativa (sin componentes “..”) especificada por esa variable de entorno, y <hostname> es el nombre del host de la máquina según lo informado por gethostname(3).

Cuando el servidor Xorg es iniciado por el usuario “root”, las ubicaciones de búsqueda del archivo de configuración son las siguientes:

<cmdline>
/etc/X11/<cmdline>
/usr/etc/X11/<cmdline>
$XORGCONFIG
/etc/X11/$XORGCONFIG
/usr/etc/X11/$XORGCONFIG
/etc/X11/xorg.conf
/etc/xorg.conf
/usr/etc/X11/xorg.conf.<hostname>
/usr/etc/X11/xorg.conf
/usr/lib/X11/xorg.conf.<hostname>
/usr/lib/X11/xorg.conf

donde <cmdline> es la ruta especificada con la opción de línea de comandos -config (que puede ser absoluta o relativa), $XORGCONFIG es la ruta especificada por esa variable de entorno (absoluta o relativa), $HOME es la ruta especificada por esa variable de entorno (generalmente el directorio personal), y <hostname> es el nombre del host de la máquina según lo informado por gethostname(3).

Se buscan archivos de configuración adicionales en los siguientes directorios cuando el servidor se inicia como usuario normal:

/etc/X11/<cmdline>
/etc/X11/<cmdline>
/etc/X11/xorg.conf.d
/etc/X11/xorg.conf.d

donde <cmdline> es una ruta relativa (sin componentes “..”) especificada con la opción de línea de comandos -configdir.

Cuando el servidor Xorg es iniciado por el usuario “root”, las ubicaciones de búsqueda del directorio de configuración son las siguientes:

<cmdline>
/etc/X11/<cmdline>
/etc/X11/<cmdline>
/etc/X11/xorg.conf.d
/etc/X11/xorg.conf.d

donde <cmdline> es la ruta especificada con la opción de línea de comandos -configdir (que puede ser absoluta o relativa).

Finalmente, también se buscarán archivos de configuración en un directorio reservado para uso del sistema. Esto es para separar los archivos de configuración de los paquetes de proveedores o de terceros de los de la administración local. Estos archivos se encuentran en el siguiente directorio:

/usr/share/X11/xorg.conf.d

Los archivos xorg.conf y xorg.conf.d se componen de una serie de secciones que pueden estar presentes en cualquier orden, u omitirse para usar los valores de configuración por defecto. Cada sección tiene el formato:

Section  "NombreDeSección"
    EntradaDeSección
    ...
EndSection

Los nombres de las secciones son:

Files          Rutas de archivos
ServerFlags    Indicadores del servidor
Module         Carga dinámica de módulos
Extensions     Habilitación de extensiones
InputDevice    Descripción del dispositivo de entrada
InputClass     Descripción de la clase de entrada
OutputClass    Descripción de la clase de salida
Device         Descripción del dispositivo gráfico
VideoAdaptor   Descripción del adaptador de video Xv
Monitor        Descripción del monitor
Modes          Descripciones de modos de video
Screen         Configuración de pantalla
ServerLayout   Diseño general
DRI            Configuración específica de DRI
Vendor         Configuración específica del proveedor

Los siguientes nombres de sección obsoletos aún se reconocen por motivos de compatibilidad. En los nuevos archivos de configuración, se debe utilizar la sección InputDevice en su lugar.

Keyboard       Configuración del teclado
Pointer        Configuración del puntero/ratón

La antigua sección XInput ya no se reconoce.

Las secciones ServerLayout están en el nivel más alto. Vinculan los dispositivos de entrada y salida que se utilizarán en una sesión. Los dispositivos de entrada se describen en las secciones InputDevice. Los dispositivos de salida suelen constar de varios componentes independientes (por ejemplo, una tarjeta gráfica y un monitor). Estos múltiples componentes se vinculan en las secciones Screen, y son estas las que se referencian en la sección ServerLayout. Cada sección Screen vincula una tarjeta gráfica y un monitor. Las tarjetas gráficas se describen en las secciones Device, y los monitores se describen en las secciones Monitor.

Las palabras clave de los archivos de configuración no distinguen entre mayúsculas y minúsculas, y los caracteres “_” se ignoran. La mayoría de las cadenas (incluidos los nombres de Option) tampoco distinguen entre mayúsculas y minúsculas, y son insensibles al espacio en blanco y a los caracteres “_”.

Cada entrada del archivo de configuración suele ocupar una sola línea en el archivo. Consisten en una palabra clave, que posiblemente va seguida de uno o más argumentos, cuyo número y tipos dependen de la palabra clave. Los tipos de argumento son:

Integer     un número entero en decimal, hexadecimal o
              octal
Real        un número de punto flotante
String      una cadena encerrada entre comillas dobles
              (")

Nota: los valores enteros hexadecimales deben ir precedidos de “0x”, y los valores octales de “0”.

Se puede utilizar una palabra clave especial llamada Option para proporcionar datos de formato libre a varios componentes del servidor. La palabra clave Option toma uno o dos argumentos de cadena. El primero es el nombre de la opción y el segundo argumento opcional es el valor de la opción. Algunos tipos de valores de opción comúnmente utilizados incluyen:

Integer     un número entero en decimal, hexadecimal o
              octal
Real        un número de punto flotante
String      una secuencia de caracteres
Boolean     un valor booleano (ver más abajo)
Frequency   un valor de frecuencia (ver más abajo)

Tenga en cuenta que *todos* los valores de Option, no solo las cadenas, deben ir entre comillas.

Las opciones booleanas pueden tener opcionalmente un valor especificado. Cuando no se especifica ningún valor, el valor de la opción es TRUE. Los siguientes valores de opción booleana se reconocen como TRUE:

1, on, true, yes

y los siguientes valores de opción booleana se reconocen como FALSE:

0, off, false, no

Si un nombre de opción va precedido de “No”, entonces el valor de la opción se niega.

Ejemplo: las siguientes entradas de opción son equivalentes:

Option "Accel"   "Off"
Option "NoAccel"
Option "NoAccel" "On"
Option "Accel"   "false"
Option "Accel"   "no"

Los valores de opción de frecuencia consisten en un número real que opcionalmente va seguido de una de las siguientes unidades de frecuencia:

Hz, k, kHz, M, MHz

Cuando se omite el nombre de la unidad, las unidades correctas se determinarán a partir de t

el valor y las expectativas del rango apropiado del valor. Se recomienda que las unidades se especifiquen siempre al usar valores de la opción de frecuencia para evitar cualquier error al determinar el valor.

SECCIÓN DE ARCHIVOS

La sección Archivos se utiliza para especificar algunos nombres de ruta requeridos por el servidor. Algunas de estas rutas también se pueden establecer desde la línea de comandos (ver Xserver(1) y Xorg(1)). La configuración de la línea de comandos anula los valores especificados en el archivo de configuración. La sección Archivos es opcional, al igual que todas las entradas que pueden aparecer en ella.

Las entradas que pueden aparecer en esta sección son:

FontPath "ruta"
establece la ruta de búsqueda de fuentes. Esta ruta es una lista separada por comas de elementos de ruta de fuentes que el servidor Xorg busca para bases de datos de fuentes. Se pueden especificar varias entradas FontPath, y se concatenarán para construir la ruta de fuentes utilizada por el servidor. Los elementos de la ruta de fuentes pueden ser rutas de directorios absolutas, directorios de catálogo o un identificador de servidor de fuentes. Los formatos de los dos últimos se explican a continuación:
Directorios de catálogo:
Los directorios de catálogo se pueden especificar usando el prefijo catalogue: antes del nombre del directorio. El directorio puede entonces poblarse con enlaces simbólicos que apunten a los directorios de fuentes reales, utilizando la siguiente sintaxis en el nombre del enlace simbólico:
<identificador>:[atributo]:pri=<prioridad>

donde <identificador> es un identificador alfanumérico, [atributo] es un atributo que se pasará al FPE subyacente y <prioridad> es un número utilizado para ordenar los FPE de archivos de fuentes. Ejemplos:

75dpi:unscaled:pri=20 -> /usr/share/X11/fonts/75dpi
gscript:pri=60 -> /usr/share/fonts/default/ghostscript
misc:unscaled:pri=10 -> /usr/share/X11/fonts/misc
Identificadores de servidor de fuentes:
Los identificadores de servidor de fuentes tienen el formato:

<trans>/<nombrehost>:<numeropuerto>

donde <trans> es el tipo de transporte que se utilizará para conectarse al servidor de fuentes (por ejemplo, unix para sockets de dominio UNIX o tcp para una conexión TCP/IP), <nombrehost> es el nombre del host de la máquina que ejecuta el servidor de fuentes y <numeropuerto> es el número de puerto en el que está escuchando el servidor de fuentes (generalmente 7100).

Cuando esta entrada no se especifica en el archivo de configuración, el servidor recurre a la ruta de fuentes predeterminada compilada, que contiene los siguientes elementos de ruta de fuentes (que se pueden establecer dentro de un directorio de catálogo):

/usr/share/fonts/X11/misc/
/usr/share/fonts/X11/TTF/
/usr/share/fonts/X11/OTF/
/usr/share/fonts/X11/Type1/
/usr/share/fonts/X11/100dpi/
/usr/share/fonts/X11/75dpi/

Los elementos de la ruta de fuentes que resultan ser inválidos se eliminan de la ruta de fuentes cuando el servidor se inicia.

ModulePath "ruta"
establece la ruta de búsqueda de módulos de servidor Xorg cargables. Esta ruta es una lista separada por comas de directorios que el servidor Xorg busca para cargar módulos en el orden especificado. Se pueden especificar varias entradas ModulePath, y se concatenarán para construir la ruta de búsqueda de módulos utilizada por el servidor. La ruta de módulos predeterminada es
lib/xorg/modules
XkbDir "ruta"
establece el directorio base para los archivos de diseño de teclado. La opción de línea de comandos -xkbdir se puede utilizar para anular esto. El directorio predeterminado es
/usr/share/X11/xkb

SECCIÓN SERVERFLAGS

Además de las opciones específicas para esta sección (descritas a continuación), la sección ServerFlags se utiliza para especificar algunas opciones globales del servidor Xorg. Todas las entradas de esta sección son Opciones, aunque por motivos de compatibilidad todavía se reconocen algunas entradas de estilo antiguo. Esas entradas de estilo antiguo no se documentan aquí y su uso no se recomienda. La sección ServerFlags es opcional, al igual que las entradas que se pueden especificar en ella.

Las Opciones especificadas en esta sección (con la excepción de la Opción "DefaultServerLayout") pueden ser anuladas por las Opciones especificadas en la sección activa ServerLayout. Las opciones con equivalentes en la línea de comandos se anulan cuando se utiliza su equivalente en la línea de comandos. Las opciones reconocidas por esta sección son:

Option "Debug" "cadena"
Esta lista separada por comas proporciona una forma de controlar varios interruptores de depuración desde el archivo de configuración. En este momento, el único valor definido es dmabuf_capable, que instruye a glamor para que habilite código de gestión de búfer inestable.
Option "DefaultServerLayout" "id-layout"
Esto especifica la sección ServerLayout predeterminada a utilizar en ausencia de la opción de línea de comandos -layout.
Option "DontVTSwitch" "booleano"
Esto prohíbe el uso de la secuencia Ctrl+Alt+Fn (donde Fn se refiere a una de las teclas de función numeradas). Esa secuencia se usa normalmente para cambiar a otra "terminal virtual" en sistemas operativos que tienen esta función. Cuando esta opción está habilitada, esa secuencia de teclas no tiene un significado especial y se pasa a los clientes. Predeterminado: desactivado.
Option "DontZap" "booleano"
Esto prohíbe el uso de la acción XKB Terminate_Server (generalmente en Ctrl+Alt+Retroceso, dependiendo de las opciones de XKB). Esta acción se usa normalmente para terminar el servidor Xorg. Cuando esta opción está habilitada, la acción no tiene ningún efecto. Predeterminado: desactivado.
Option "DontZoom" "booleano"
Esto prohíbe el uso de las secuencias Ctrl+Alt+Keypad-Plus y Ctrl+Alt+Keypad-Minus. Estas secuencias permiten cambiar entre modos de video. Cuando esta opción está habilitada, esas secuencias de teclas no tienen un significado especial y se pasan a los clientes. Predeterminado: desactivado.
Option "DisableVidModeExtension" "booleano"
Esto deshabilita las partes de la extensión VidMode utilizadas por el cliente xvidtune que se pueden usar para cambiar los modos de video. Predeterminado: la extensión VidMode está habilitada.
Option "AllowNonLocalXvidtune" "booleano"
Esto permite que el cliente xvidtune (y otros clientes que utilizan la extensión VidMode) se conecten desde otro host. Predeterminado: desactivado.
Option "AllowMouseOpenFail" "booleano"
Esto indica a los controladores mousedrv(4) y vmmouse(4) que no informen de fallo si el dispositivo del ratón no se puede abrir/inicializar. No tiene efecto en los controladores evdev(4) u otros. Predeterminado: falso.
Option "BlankTime" "tiempo"
establece el tiempo de inactividad para la fase blank del salvapantallas. El tiempo está en minutos. Esto es equivalente a la bandera -s del servidor Xorg, y el valor se puede cambiar en tiempo de ejecución con xset(1). Predeterminado: 10 minutos.
Option "StandbyTime" "tiempo"
establece el tiempo de inactividad para la fase standby del modo DPMS. El tiempo está en minutos, y el valor se puede cambiar en tiempo de ejecución con xset(1). Predeterminado: 10 minutos. Esto solo es adecuado para monitores compatibles con VESA DPMS y puede que no sea compatible con todos los controladores de video. Solo se habilita para pantallas que tengan la opción "DPMS" establecida (ver la sección MONITOR a continuación).
Option "SuspendTime" "tiempo"
establece el tiempo de inactividad para la fase suspend del modo DPMS. El tiempo está en minutos, y el valor se puede cambiar en tiempo de ejecución con xset(1). Predeterminado: 10 minutos. Esto solo es adecuado para monitores compatibles con VESA DPMS y puede que no sea compatible con todos los controladores de video. Solo se habilita para pantallas que tengan la opción "DPMS" establecida (ver la sección MONITOR a continuación).
Option "OffTime" "tiempo"
establece el tiempo de inactividad para la fase off del modo DPMS. El tiempo está en minutos, y el valor se puede cambiar en tiempo de ejecución con xset(1). Predeterminado: 10 minutos. Esto solo es adecuado para monitores compatibles con VESA DPMS y puede que no sea compatible con todos los controladores de video. Solo se habilita para pantallas que tengan la opción "DPMS" establecida (ver la sección MONITOR a continuación).
Option "MaxClients" "entero"
Establece el número máximo de clientes permitidos para conectarse al servidor X. Los valores aceptables son 64, 128, 256 o 512.
Option "NoPM" "booleano"
Deshabilita algo relacionado con los eventos de gestión de energía. Predeterminado: PM habilitado en plataformas que lo soportan.
Option "Xinerama" "booleano"
habilita o deshabilita la extensión XINERAMA. Predeterminado: deshabilitado.
Option "IndirectGLX" "booleano"
habilita o deshabilita los contextos GLX indirectos. Los contextos GLX indirectos están deshabilitados por defecto.
Option "DRI2" "booleano"
habilita o deshabilita DRI2. DRI2 está deshabilitado por defecto.

No tiene ningún dispositivo maestro ni controla un cursor. El dispositivo solo está disponible para clientes que utilizan la API de la Extensión de Entrada X. Esta opción está deshabilitada por defecto. Las opciones CorePointer, CoreKeyboard, AlwaysCore y SendCoreEvents son la inversa de la opción Floating (es decir, SendCoreEvents "on" es equivalente a Floating "off").

Esta opción solo controla el comportamiento de inicio; un dispositivo puede volver a adjuntarse o configurarse como flotante en tiempo de ejecución.

Option "TransformationMatrix" "a b c d e f g h i"
Especifica la matriz de transformación de 3x3 para dispositivos de entrada absolutos. El dispositivo de entrada se vinculará al área dada en la matriz. En la mayoría de las configuraciones, "a" y "e" especifican el ancho y la altura del área a la que está vinculado el dispositivo, y "c" y "f" especifican el desplazamiento x e y del área. El rango de valores es de 0 a 1, donde 1 representa el ancho o la altura de todas las ventanas raíz juntas, 0.5 representa la mitad del área, etc. Los valores representan una matriz de 3x3, con el primer, segundo y tercer grupo de tres valores representando la primera, segunda y tercera fila de la matriz, respectivamente. La matriz identidad es "1 0 0 0 1 0 0 0 1".

ACELERACIÓN DEL PUNTERO

Para los dispositivos de puntero, las siguientes opciones controlan cómo se acelera o desacelera el puntero con respecto al movimiento físico del dispositivo. La mayoría de estas se pueden ajustar en tiempo de ejecución; consulte la página del manual xinput(1) para obtener más detalles. Aquí solo se discuten las opciones de aceleración más importantes.

Option "AccelerationProfile" "integer"
Selecciona el perfil. En términos sencillos, el perfil constituye la "sensación" de la aceleración. Más formalmente, define cómo se construye la función de transferencia (aceleración real como función de la velocidad actual del dispositivo y los controles de aceleración). Esto es principalmente una cuestión de preferencia personal.
 0      clásico (mayormente compatible)
-1      ninguno (solo se aplica desaceleración constante)
 1      dependiente del dispositivo
 2      polinomial (función polinomial)
 3      lineal suave (curva suave, luego lineal)
 4      simple (normal cuando es lento, de lo contrario acelerado)
 5      potencia (función de potencia)
 6      lineal (más velocidad, más aceleración)
 7      limitado (como lineal, pero alcanza el máximo en el umbral)
Option "ConstantDeceleration" "real"
Hace que el puntero sea deceleración veces más lento de lo normal. Muy útil para dispositivos de alta resolución. Un valor entre 0 y 1 acelerará el puntero.
Option "AdaptiveDeceleration" "real"
Permite desacelerar realmente el puntero cuando se mueve lentamente. Como máximo, será deceleración adaptativa veces más lento. Permite una colocación precisa del puntero sin sacrificar la velocidad.
Option "AccelerationScheme" "string"
Selecciona el esquema, que es el algoritmo subyacente.
predictable   algoritmo predeterminado (comportamiento más predecible)
lightweight   código de aceleración antiguo (según lo especificado en la especificación del protocolo X)
none          sin aceleración ni desaceleración
Option "AccelerationNumerator" "integer"
Option "AccelerationDenominator" "integer"
Establece el numerador y el denominador del factor de aceleración. El factor de aceleración es una fracción que, junto con el umbral, se puede utilizar para ajustar los perfiles a las necesidades del usuario. Los perfiles simple y limited lo utilizan directamente (es decir, aceleran por el factor); para otros perfiles, un factor de aceleración más alto debería resultar en un puntero más rápido. Típicamente, 1 no está acelerado y los valores hasta 5 son sensatos.
Option "AccelerationThreshold" "integer"
Establece el umbral, que es aproximadamente la velocidad (generalmente unidades del dispositivo por cada 10 ms) requerida para que la aceleración sea efectiva. Sin embargo, el efecto preciso varía según el perfil.

SECCIÓN INPUTCLASS

El archivo de configuración puede tener múltiples secciones InputClass. Estas secciones son opcionales y se utilizan para proporcionar configuración para una clase de dispositivos de entrada a medida que se agregan automáticamente. Un dispositivo de entrada puede coincidir con más de una sección InputClass. Cada clase puede anular la configuración de una clase anterior, por lo que es mejor organizar las secciones con las coincidencias más genéricas primero.

Las secciones InputClass tienen el siguiente formato:

Section "InputClass"
    Identifier  "nombre"
    entradas
    ...
    opciones
    ...
EndSection

La entrada Identifier es obligatoria en todas las secciones InputClass. Todas las demás entradas son opcionales.

La entrada Identifier especifica el nombre único para esta clase de entrada. La entrada Driver especifica el nombre del controlador a utilizar para este dispositivo de entrada. Después de examinar todas las clases, el módulo "inputdriver" de la primera entrada Driver se habilitará al usar el servidor cargable.

Cuando se agrega automáticamente un dispositivo de entrada, sus características se comparan con todas las secciones InputClass. Cada sección puede contener entradas opcionales para limitar la coincidencia de la clase. Si no aparecen ninguna de las entradas opcionales, la sección InputClass es genérica y coincidirá con cualquier dispositivo de entrada. Si aparecen más de una de estas entradas, todas deben coincidir para que se aplique la configuración.

Hay dos tipos de entradas de coincidencia utilizadas en las secciones InputClass. La primera permite que varios tokens se comparen con los atributos del dispositivo. Se puede construir una entrada para que coincida con atributos de diferentes dispositivos separando los argumentos con un carácter '|'. Se pueden proporcionar múltiples entradas del mismo tipo para agregar múltiples condiciones de coincidencia en el mismo atributo. Por ejemplo:

Section "InputClass"
    Identifier   "Mi Clase"
    # la cadena de producto debe contener ejemplo y
    # o gizmo o gadget
    MatchProduct "ejemplo"
    MatchProduct "gizmo|gadget"
    NoMatchDriver "nombrecontrolador"
    ...
EndSection
MatchProduct "matchproduct"
Esta entrada se puede usar para verificar si la subcadena "matchproduct" aparece en el nombre del producto del dispositivo.
MatchVendor "matchvendor"
Esta entrada se puede usar para verificar si la subcadena "matchvendor" aparece en el nombre del proveedor del dispositivo.
MatchDevicePath "matchdevice"
Esta entrada se puede usar para verificar si el archivo del dispositivo coincide con el patrón de ruta de "matchdevice".
MatchOS "matchos"
Esta entrada se puede usar para verificar si el sistema operativo coincide con la cadena "matchos" sin distinción de mayúsculas y minúsculas. Esta entrada solo se admite en plataformas que proporcionan la llamada al sistema uname(2).
MatchPnPID "matchpnp"
El ID Plug and Play (PnP) del dispositivo se puede comparar con el patrón de comodín de shell "matchpnp".
MatchUSBID "matchusb"
El ID USB del dispositivo se puede comparar con el patrón de comodín de shell "matchusb". El ID se construye como números hexadecimales en minúsculas separados por dos puntos (:). Este es el mismo formato que el programa lsusb(8).
MatchDriver "matchdriver"
Compara la cadena "matchdriver" con distinción de mayúsculas y minúsculas con el controlador configurado actualmente del dispositivo. El orden de las secciones que utilizan esta entrada es importante, ya que no coincidirá a menos que el controlador haya sido establecido por el backend de configuración o una sección InputClass anterior.
MatchTag "matchtag"

SECCIÓN OUTPUTCLASS

El archivo de configuración puede tener múltiples secciones OutputClass. Estas secciones son opcionales y se utilizan para proporcionar configuración para una clase de dispositivos de salida a medida que se añaden automáticamente. Un dispositivo de salida puede coincidir con más de una sección OutputClass. Cada clase puede invalidar los ajustes de una clase anterior, por lo que es mejor organizar las secciones con las coincidencias más genéricas primero.

Las secciones OutputClass tienen el siguiente formato:

Section "OutputClass"
    Identifier  "nombre"
    entradas
    ...
EndSection

La entrada Identifier es obligatoria en todas las secciones OutputClass. Todas las demás entradas son opcionales.

La entrada Identifier especifica el nombre único para esta clase de salida. La entrada Driver especifica el nombre del controlador a utilizar para este dispositivo de salida. Después de examinar todas las clases, el módulo "outputdriver" de la primera entrada Driver se habilitará al utilizar el servidor cargable.

Cuando se añade automáticamente un dispositivo de salida, sus características se comprueban con todas las secciones OutputClass. Cada sección puede contener entradas opcionales para acotar la coincidencia de la clase. Si no aparece ninguna de las entradas opcionales, la sección OutputClass es genérica y coincidirá con cualquier dispositivo de salida. Si aparecen más de una de estas entradas, todas deben coincidir para que se aplique la configuración.

La siguiente lista de tokens puede coincidir con atributos del dispositivo. Se puede construir una entrada para que coincida con atributos de diferentes dispositivos separando los argumentos con el carácter '|'.

Por ejemplo:

Section "OutputClass"
    Identifier   "Mi Clase"
    # el controlador del kernel debe ser foo o bar
    MatchDriver "foo|bar"
    ...
EndSection
MatchDriver "matchdriver"
Comprueba la cadena sensible a mayúsculas y minúsculas "matchdriver" con el controlador del kernel del dispositivo.

Cuando un dispositivo de salida ha coincidido con la sección OutputClass, cualquier entrada Option se aplica al dispositivo. Se reconoce una Option específica de OutputClass. Consulte la sección Device a continuación para obtener una descripción de las entradas Option restantes.

Option "PrimaryGPU" "booleano"
Esta opción especifica que el dispositivo coincidente debe tratarse como la GPU principal, reemplazando la selección de la GPU utilizada como salida por el firmware. Si varios dispositivos de salida coinciden con una sección OutputClass con la opción PrimaryGPU establecida, el primero que se enumere se convierte en la GPU principal.

Una Sección OutputClass puede contener entradas ModulePath. Cuando un dispositivo de salida coincide con una sección OutputClass, cualquier entrada ModulePath en esa OutputClass se antepone a la ruta de búsqueda de módulos cargables del servidor Xorg. Consulte ModulePath en la sección Files para obtener más información.

DEVICE SECTION

The config file may have multiple Device sections. There should normally be at least one, for the graphics card being used, but a default configuration will be created when one isn't specified.

Device sections have the following format:

Section "Device"
    Identifier "name"
    entries
    ...
EndSection

The Identifier entry specifies the unique name for this device section. This is used to refer to this section from other parts of the config file, such as the Screen section.

The other entries in the Device section are optional, and are used to specify information about the graphics card and its associated driver.

The entries that may be used in Device section are described below.

BusID busid
This optional entry specifies the PCI bus, device, and function number of the graphics card. This is typically used to override automatic detection when multiple graphics devices are present. The format is typically PCI:vendor:device:function. This entry is not used by many drivers, and it should only be specified if the driver-specific documentation recommends it.
Chipset "chipset"
This optional entry specifies the name of the graphics chipset. This can be used to override the auto-detection, but that should only be done when the driver-specific documentation recommends it.
Ramdac "ramdac"
This optional entry specifies the name of the RAMDAC. This can be used to override the auto-detection, but that should only be done when the driver-specific documentation recommends it.
Driver "driver"
This optional entry specifies the name of the driver to be used for this device. If not specified, the X server will attempt to auto-select an appropriate driver.
Capabilities caps
This optional entry specifies a set of driver capabilities. This is used internally by the X server and should not normally be set by the user.
Screen screen-number
This optional entry specifies which screen this device should be associated with. The default is screen 0.
Device baseaddress
This optional entry specifies the memory base address of a graphics board's linear frame buffer. This entry is not used by many drivers, and it should only be specified if the driver-specific documentation recommends it.
IOBase baseaddress
This optional entry specifies the IO base address. This entry is not used by many drivers, and it should only be specified if the driver-specific documentation recommends it.
ChipID id
This optional entry specifies a numerical ID representing the chip type. For PCI cards, it is usually the device ID. This can be used to override the auto-detection, but that should only be done when the driver-specific documentation recommends it.
ChipRev rev
This optional entry specifies the chip revision number. This can be used to override the auto-detection, but that should only be done when the driver-specific documentation recommends it.
MatchSeat seat-id
Only apply this Device section if X server was started with -seat seat-id option.
Option "ModeDebug" "boolean"
Enable printing of additional debugging information about modesetting to the server log.
Option "NoOutputInitialSize" "width height"
Normally, the X server infers the initial screen size based on any connected outputs. However, if no outputs are connected, the X server picks a default screen size of 1024 x 768. This option overrides the default screen size to use when no outputs are connected. In contrast to the "Virtual" Display SubSection entry, which applies unconditionally, "NoOutputInitialSize" is only used if no outputs are detected when the X server starts.
Option "PreferCloneMode" "boolean"
If enabled, bring up monitors of a screen in clone mode instead of horizontal extended layout by default. (Defaults to off; the video driver can change the default value, but this option can always override it)
Options
Option flags may be specified in the Device sections. These include driver-specific options and driver-independent options. The former are described in the driver-specific documentation. Some of the latter are described below in the section about the Screen section, and they may also be included here.

SCREEN SECTION

Each Screen section specifies the configuration for a single screen. Multiple Screen sections may be present in a config file, and these are used for multi-head configurations.

Screen sections have the following format:

Section "Screen"
    ...
EndSection
Identifier ident
This entry is used to identify the screen section. It is used by the ServerLayout section to refer to this screen. ident must be a unique string.
Device ident
This entry must be present in the Screen section. It binds the screen to a Device section, which specifies the graphics hardware and driver to be used. ident refers to the identifier of the Device section.
Monitor ident
This entry must be present in the Screen section. It binds the screen to a Monitor section, which describes the physical monitor(s) attached. ident refers to the identifier of the Monitor section.
Display ident
This entry is used to specify details for a particular display configuration. It is explained in more detail in the DISPLAY SUBSECTION section below.
VideoAdaptor "xv-id"
specifies an optional Xv video adaptor description to be used with this screen.
DefaultDepth depth
specifies which color depth the server should use by default. The -depth command line option can be used to override this. If neither is specified, the default depth is driver-specific, but in most cases is 8.
DefaultFbBpp bpp
specifies which framebuffer layout to use by default. The -fbbpp command line option can be used to override this. In most cases the driver will chose the best default value for this. The only case where there is even a choice in this value is for depth 24, where some hardware supports both a packed 24 bit framebuffer layout and a sparse 32 bit framebuffer layout.
MatchSeat seat-id
Only apply this Screen section if X server was started with -seat seat-id option.
Options
Various Option flags may be specified in the Screen section. Some are driver-specific and are described in the driver documentation. Others are driver-independent, and will eventually be described here.
Option "Accel"
Enables 2D hardware acceleration. This option is on by default, but it may be necessary to turn it off if there are bugs in the driver. There are many options to disable specific accelerated operations, listed below. Note that disabling an operation will have no effect if the operation is not accelerated (whether due to lack of support in the hardware or in the driver).
Option "GlxVendorLibrary" "string"
This option specifies a space-separated list of OpenGL vendor libraries to use for the screen. This may be used to select an alternate implementation for development, debugging, or alternate feature sets. Default: mesa.
Option "RenderingAPI" "string"
This option specifies an rendering API for use in conjunction with Glamor accel method. You can specify OpenGL with a value "gl" and OpenGL ES with a value "es", and the default is both, when Glamor fallbacks to GLES if GL 2.1 is not available. This may be useful for embedded and old cards, where GL ES feature set works faster than GL feature set. Default: gl.
Option "InitPrimary" "boolean"
Use the Int10 module to initialize the primary graphics card. Normally, only secondary cards are soft-booted using the Int10 module, as the primary card has already been initialized by the BIOS at boot time. Default: false.
Option "NoInt10" "boolean"
Disables the Int10 module, a module that uses the int10 call to the BIOS of the graphics card to initialize it. Default: false.

Each Screen section may optionally contain one or more Display subsections. Those subsections provide depth/fbbpp specific configuration information, and the one chosen depends on the depth and/or fbbpp that is being used for the screen. The Display subsection format is described in the section below.

DISPLAY SUBSECTION

Each Screen section may have multiple Display subsections. The “active” Display subsection is the first that matches the depth and/or fbbpp values being used, or failing that, the first that has neither a depth or fbbpp value specified. The Display subsections are optional. When there isn't one that matches the depth and/or fbbpp values being used, all the parameters that can be specified here fall back to their defaults.

Display subsections have the following format:

    SubSection "Display"
        Depth depth
        entries
        ...
    EndSubSection
Depth depth
This entry specifies what colour depth the Display subsection is to be used for. This entry is usually specified, but it may be omitted to create a match-all Display subsection or when wishing to match only against the FbBpp parameter. The range of depth values that are allowed depends on the driver. Most drivers support 8, 15, 16 and 24. Some also support 1 and/or 4, and some may support other values (like 30). Note: depth means the number of bits in a pixel that are actually used to determine the pixel colour. 32 is not a valid depth value. Most hardware that uses 32 bits per pixel only uses 24 of them to hold the colour information, which means that the colour depth is 24, not 32.
FbBpp bpp
This entry specifies the framebuffer format this Display subsection is to be used for. This entry is only needed when providing depth 24 configurations that allow a choice between a 24 bpp packed framebuffer format and a 32bpp sparse framebuffer format. In most cases this entry should not be used.
Weight red-weight green-weight blue-weight
This optional entry specifies the relative RGB weighting to be used for a screen is being used at depth 16 for drivers that allow multiple formats. This may also be specified from the command line with the -weight option (see Xorg(1)).
Virtual xdim ydim
This optional entry specifies the virtual screen resolution to be used. xdim must be a multiple of either 8 or 16 for most drivers, and a multiple of 32 when running in monochrome mode. The given value will be rounded down if this is not the case. Video modes which are too large for the specified virtual size will be rejected. If this entry is not present, the virtual screen resolution will be set to accommodate all the valid video modes given in the Modes entry. Some drivers/hardware combinations do not support virtual screens. Refer to the appropriate driver-specific documentation for details.
ViewPort x0 y0
This optional entry sets the upper left corner of the initial display. This is only relevant when the virtual screen resolution is different from the resolution of the initial video mode. If this entry is not given, then the initial display will be centered in the virtual display area.
Modes "mode-name" ...
This optional entry specifies the list of video modes to use. Each mode-name specified must be in double quotes. They must correspond to those specified or referenced in the appropriate Monitor section (including implicitly referenced built-in VESA standard modes). The server will delete modes from this list which don't satisfy various requirements. The first valid mode in this list will be the default display mode for startup. The list of valid modes is converted internally into a circular list. It is possible to switch to the next mode with Ctrl+Alt+Keypad-Plus and to the previous mode with Ctrl+Alt+Keypad-Minus. When this entry is omitted, the valid modes referenced by the appropriate Monitor section will be used. If the Monitor section contains no modes, then the selection will be taken from the built-in VESA standard modes.
Visual "visual-name"
This optional entry sets the default root visual type. This may also be specified from the command line (see the Xserver(1) man page). The visual types available for depth 8 are (default is PseudoColor):
StaticGray
GrayScale
StaticColor
PseudoColor
TrueColor
DirectColor
The visual type available for the depths 15, 16 and 24 are (default is TrueColor): 
TrueColor
DirectColor

Not all drivers support DirectColor at these depths.

The visual types available for the depth 4 are (default is StaticColor):

StaticGray
GrayScale
StaticColor
PseudoColor

The visual type available for the depth 1 (monochrome) is StaticGray.

Black red green blue
This optional entry allows the “black” colour to be specified. This is only supported at depth 1. The default is black.
White red green blue
This optional entry allows the “white” colour to be specified. This is only supported at depth 1. The default is white.
Options
Option flags may be specified in the Display subsections. These may include driver-specific options and driver-independent options. The former are described in the driver-specific documentation. Some of the latter are described above in the section about the Screen section, and they may also be included here.

SERVERLAYOUT SECTION

The config file may have multiple ServerLayout sections. A “server layout” represents the binding of one or more screens (Screen sections) and one or more input devices (InputDevice sections) to form a complete configuration. In multi-head configurations, it also specifies the relative layout of the heads. A ServerLayout section is considered “active” if it is referenced by the -layout command line option or by an Option "DefaultServerLayout" entry in the ServerFlag

Sección SERVERLAYOUT

Si no se especifican las opciones de línea de comandos -layout y -screen, se busca la primera sección ServerLayout y se utiliza su contenido para el resto del archivo de configuración. Si se encuentran múltiples secciones ServerLayout, se utiliza la especificada por la opción -layout, seguida de la especificada por la opción -screen (la primera tiene precedencia sobre la segunda). Si no se utilizan estas opciones, se considera que la primera sección ServerLayout encontrada en el archivo de configuración es la activa. Si no hay secciones ServerLayout, se seleccionan la pantalla activa única y dos dispositivos de entrada activos (principales), como se describe en las secciones correspondientes anteriores.

Las secciones ServerLayout tienen el siguiente formato:

Section "ServerLayout"
    Identifier   "nombre"
    Screen       "id-pantalla"
    ...
    InputDevice  "id-dispositivo-entrada"
    ...
    options
    ...
EndSection

Cada sección ServerLayout debe tener una entrada Identifier y al menos una entrada Screen.

La entrada Identifier especifica el nombre único para esta disposición del servidor. La sección ServerLayout proporciona información específica para toda la sesión, incluidas las Options específicas de la sesión. Las opciones ServerFlags (descritas anteriormente) se pueden especificar aquí, y las que se dan aquí anulan a las dadas en la sección ServerFlags.

Las entradas que se pueden utilizar en esta sección se describen aquí.

Screen num-pantalla "id-pantalla" información-posición
Se debe proporcionar una de estas entradas por cada pantalla que se utilice en una sesión. El campo id-pantalla es obligatorio y especifica la sección Screen a la que se hace referencia. El campo num-pantalla es opcional y se puede utilizar para especificar el número de pantalla en configuraciones de múltiples cabezales. Cuando se omite este campo, las pantallas se numerarán en el orden en que se listan. La numeración comienza desde 0 y debe ser consecutiva. El campo información-posición describe la forma en que se posicionan múltiples pantallas. Hay varias formas en que se puede proporcionar esta información:
x y
Absolute x y
Ambas especifican que las coordenadas de la esquina superior izquierda son (x,y). La palabra clave Absolute es opcional. Algunas versiones anteriores de XFree86 (4.2 y anteriores) no reconocen la palabra clave Absolute, por lo que es más seguro especificar solo las coordenadas sin ella.
RightOf "id-pantalla"
LeftOf "id-pantalla"
Above "id-pantalla"
Below "id-pantalla"
Relative "id-pantalla" x y
Estas ubican la pantalla en relación con otra pantalla. Las cuatro primeras ubican la pantalla inmediatamente a la derecha, izquierda, arriba o abajo de la otra pantalla. Al posicionar a la derecha o izquierda, los bordes superiores se alinean. Al posicionar arriba o abajo, los bordes izquierdos se alinean. La forma Relative especifica el desplazamiento del origen de la pantalla (esquina superior izquierda) con respecto al origen de otra pantalla.
InputDevice "id-dispositivo-entrada" "opción" ...
Se debe proporcionar una de estas entradas por cada dispositivo de entrada que se utilice en una sesión. Normalmente se requieren al menos dos, una para el puntero principal y otra para el teclado principal. Si falta alguno de estos, se buscan entradas InputDevice adecuadas utilizando el método descrito anteriormente en la sección INPUTDEVICE. El campo id-dispositivo-entrada es obligatorio y especifica el nombre de la sección InputDevice a la que se hace referencia. Se pueden especificar múltiples campos opción, cada uno entre comillas dobles. Las opciones permitidas aquí son cualquiera que también se pueda dar en las secciones InputDevice. Normalmente, solo se utilizarían aquí las opciones de dispositivo de entrada específicas de la sesión. Las opciones más comunes son:
"CorePointer"
"CoreKeyboard"
"SendCoreEvents"
y las dos primeras deben usarse normalmente para indicar los dispositivos de puntero principal y teclado principal, respectivamente.
MatchSeat id-asiento
Aplicar esta sección ServerLayout solo si el servidor X se inició con la opción -seat id-asiento.
Options
Además de lo siguiente, cualquier opción permitida en la sección ServerFlags también se puede especificar aquí. Cuando la misma opción aparece en ambos lugares, el valor dado aquí anula al dado en la sección ServerFlags.
Option "IsolateDevice" "id-bus"
Restringe los reinicios del dispositivo al id-bus especificado. Consulte la opción BusID (descrita en la sección DEVICE SECTION, anterior) para conocer el formato del parámetro id-bus. Similar a IsolateDevice, excepto que se utiliza el id-bus del primer dispositivo en la disposición.

NAME

xorg.conf - Xorg configuration file

INTRODUCTION

The Xorg server (Xorg) is a server program that implements the X Window System protocol. The Xorg server reads configuration files to determine how to set up the X server environment. The main configuration file is typically named xorg.conf. This file is used to configure the server's behavior, including input devices, output displays, screen resolutions, and more.

The configuration file is divided into sections, each of which controls a specific aspect of the Xorg server. These sections are typically identified by a keyword enclosed in uppercase letters and surrounded by square brackets, e.g., [MODULE].

DESCRIPTION

The xorg.conf file contains configuration directives that are used by the Xorg server to initialize and configure the X Window System environment. The file is organized into sections, each of which corresponds to a specific component or aspect of the X server. The most common sections are:

  • MODULE: Configures Xorg server modules.
  • FILES: Specifies directories for font files and other resources.
  • INPUTDEVICE: Configures input devices such as keyboards and mice.
  • DEVICE: Configures graphics hardware.
  • SCREEN: Configures screen settings, including resolution and color depth.
  • MONITOR: Configures monitor settings.
  • SERVERLAYOUT: Defines the overall server layout, including which screens and input devices are used.

Each section contains a set of directives, which are typically key-value pairs. These directives are used to specify configuration options for the component associated with the section.

For example, a DEVICE section might include directives like:

Section "Device"
    Identifier  "My Graphics Card"
    Driver      "intel"
    BusID       "PCI:0:2:0"
EndSection

This section defines a graphics card with a specific identifier, driver, and PCI bus ID.

FILES SECTION

The FILES section specifies directories where Xorg should look for font files and other resources. It typically contains directives like:

  • FontPath: Specifies a directory containing font files.
Section "Files"
    FontPath    "/usr/share/fonts/misc"
    FontPath    "/usr/share/fonts/TTF"
EndSection

SERVERFLAGS SECTION

The SERVERFLAGS section specifies general options for the Xorg server. This section is optional. Some common options include:

  • Option "dpms": Enables or disables DPMS (Display Power Management Signaling).
  • Option "Xinerama": Enables or disables Xinerama multi-head support.
Section "ServerFlags"
    Option "dpms" "true"
EndSection

MODULE SECTION

The MODULE section is used to load Xorg server modules. Modules extend the functionality of the Xorg server. Common modules include input device drivers, graphics drivers, and extensions.

Section "Module"
    Load    "GLcore"
    Load    "dri"
EndSection

EXTENSIONS SECTION

The EXTENSIONS section allows enabling or disabling specific Xorg extensions. Extensions provide additional features and capabilities to the X server.

Section "Extensions"
    Option "Composite" "Enable"
EndSection

INPUTDEVICE SECTION

The INPUTDEVICE section configures input devices such as keyboards, mice, touchpads, and joysticks. Each INPUTDEVICE section typically has an Identifier and a Driver directive. It can also include specific Option directives to customize the device's behavior.

Section "InputDevice"
    Identifier  "My Keyboard"
    Driver      "kbd"
    Option      "XkbLayout" "us"
EndSection

INPUTCLASS SECTION

The INPUTCLASS section provides a way to apply configuration options to input devices based on their properties (e.g., driver, type, identifier). This allows for more flexible configuration of input devices, especially when dealing with multiple similar devices.

Section "InputClass"
    Identifier "My Touchpad"
    MatchIsTouchpad "on"
    Driver "libinput"
    Option "Tapping" "on"
EndSection

OUTPUTCLASS SECTION

The OUTPUTCLASS section allows applying configuration options to output devices (monitors) based on their properties. This is particularly useful for configuring multi-monitor setups.

Section "OutputClass"
    Identifier "My Monitor Setup"
    MatchName "Dell U2711"
    Option "RightOf" "Built-in Display"
EndSection

DEVICE SECTION

The DEVICE section configures graphics hardware. Each DEVICE section typically specifies an Identifier, the graphics Driver to use (e.g., "nvidia", "intel", "amdgpu"), and can include options for performance tuning or specific features.

Section "Device"
    Identifier  "Nvidia Card"
    Driver      "nvidia"
    VendorName  "NVIDIA Corporation"
    BoardName   "GeForce GTX 1080"
EndSection

VIDEOADAPTOR SECTION

The VIDEOADAPTOR section is an older way to configure graphics hardware. It is generally superseded by the DEVICE section and is less commonly used in modern Xorg configurations.

MONITOR SECTION

The MONITOR section describes a physical monitor. It typically includes an Identifier, and can specify settings like VendorName, ModelName, and supported HorizSync and VertRefresh ranges.

Section "Monitor"
    Identifier  "My Monitor"
    VendorName  "Generic"
    ModelName   "Generic 1920x1080"
    HorizSync   30.0 - 70.0
    VertRefresh 50.0 - 75.0
EndSection

MODES SECTION

The MODES section is used to define specific video modes (resolutions and refresh rates) that can be used by the X server. This section is less common now, as modes are often handled by the driver or generated dynamically.

Section "Modes"
    Identifier "1920x1080"
    DotClock       173.00
    HTimings       1920 2048 2256 2592
    VTimings       1080 1083 1088 1125
EndSection

SCREEN SECTION

The SCREEN section ties together a graphics DEVICE, a MONITOR, and potentially specific modes and options to define a usable screen. It specifies the graphics device, the monitor connected to it, and the default display settings.

Section "Screen"
    Identifier  "Default Screen"
    Device      "My Graphics Card"
    Monitor     "My Monitor"
    DefaultDepth 24
    SubSection "Display"
        Depth       24
        Modes       "1920x1080" "1280x1024"
    EndSubSection
EndSection

DISPLAY SUBSECTION

The DISPLAY subsection within a SCREEN section defines the available color depths and the video modes to use at each depth. The Depth directive specifies the color depth (e.g., 8, 16, 24, 32 bits per pixel), and the Modes directive lists the resolutions and refresh rates supported at that depth.

SERVERLAYOUT SECTION

The SERVERLAYOUT section specifies the overall arrangement of screens and input devices for the X server. It defines which SCREEN sections are active and how they are positioned relative to each other (e.g., using LeftOf, RightOf, Above, Below directives). It also associates INPUTDEVICE sections with specific screens.

Section "ServerLayout"
    Identifier  "Default Layout"
    Screen      0  "Default Screen" 0 0
    InputDevice "My Keyboard" "CoreKeyboard"
    InputDevice "My Mouse"    "CorePointer"
EndSection

DRI SECTION

The DRI section is used to configure Direct Rendering Infrastructure (DRI) settings, which allow applications to perform 3D rendering operations directly on the graphics hardware for improved performance. This section is typically used with drivers that support DRI.

Section "DRI"
    Mode    0
EndSection

Mode 0 typically means DRI is enabled.

VENDOR SECTION

The VENDOR section is used to specify vendor-specific information or options. This section is less commonly used and is often specific to certain hardware or drivers.
