NOMBRE

xorriso-dd-target - Evaluador de dispositivos y copiador de imágenes de disco para GNU/Linux

SINOPSIS

xorriso-dd-target [ opciones ] [ nombres_de_dispositivo ]

DESCRIPCIÓN

xorriso-dd-target evalúa dispositivos de bloque del kernel de Linux si son objetivos adecuados para un archivo de imagen de disco y, opcionalmente, copia el archivo de imagen a uno de ellos.
Está especializado en los nombres de dispositivo del kernel de Linux y utiliza las capacidades del programa util-linux lsblk. Por lo tanto, se niega a ejecutarse en kernels que no sean de Linux.

El propósito principal de xorriso-dd-target es inspeccionar los archivos de dispositivo de medios de almacenamiento similares a discos y juzgar si parecen dispositivos extraíbles con contenido desechable.
Si se detecta un único candidato plausible, el programa está dispuesto a copiar un archivo de imagen de disco en él. Esto sobrescribirá o hará inaccesible la tabla de particiones anterior y todo el contenido de datos anterior del dispositivo de destino.
A menudo se necesita poder de superusuario para la identificación del tipo de sistema de archivos, para un posible desmontaje y para una posible escritura de imagen. La opción -with_sudo ofrece una forma de obtener este poder solo para esas tareas y ejecutar el programa de lo contrario con el poder de un usuario normal.
Si se pretende que un archivo de imagen de disco particular sea la fuente de copia, entonces su ruta debe proporcionarse con la opción -image_file, para que su tamaño pueda usarse como criterio de decisión.

A continuación se describen casos de uso con ejemplos:
- Listar nombres de dispositivos sin formato
- Listar todos los dispositivos con razonamiento
- Evaluar dispositivos específicos dados
- Detectar el dispositivo deseado al enchufarlo
- Escribir imagen en un dispositivo recomendado
- Mostrar comandos para escribir en un dispositivo no recomendado

Listar nombres de dispositivos sin formato:

El caso de uso más simple y aburrido es la ejecución del programa sin nombres de dispositivo y sin las opciones -list_all, -plug_test, -DO_WRITE, -dummy_force. Imprime en la salida estándar (stdout) solo los nombres de los dispositivos recomendables sin el prefijo "/dev/". Un nombre por línea y sin ningún texto de razonamiento.
La posible solicitud de contraseña de sudo, el mensaje sobre sudo y la línea vacía después de él no van a stdout.
Ejemplo:
$ xorriso-dd-target -with_sudo
Probando sudo para obtener posiblemente la solicitud de contraseña ahora:
[sudo] contraseña para thomas:
sudo /bin/lsblk parece estar bien.

sde

Listar todos los dispositivos con razonamiento:

Para el usuario más curioso, existe la opción -list_all que imprime la evaluación de cada dispositivo similar a un disco que lista el programa lsblk. Sin embargo, se excluyen las unidades ópticas, las disqueteras, los dispositivos de bloque de RAM y los dispositivos loop.
Cada dispositivo se muestra en una línea de la forma
nombre : recomendación : razonamiento : información
nombre es el nombre del dispositivo sin el prefijo "/dev/".
recomendación es "SÍ" o "NO". "SÍ" indica que el dispositivo parece ser un disco extraíble, no se utiliza como disco del sistema o almacenamiento de datos sincero, y, si se prueba, de tamaño suficiente o plausible.
razonamiento es una lista de palabras separadas por espacios con el sufijo '+' para una propiedad del dispositivo que invita o '-' para una propiedad prohibitiva. Normalmente, una única razón '-' descalifica el dispositivo como recomendable. Solo si se proporciona la opción -look_for_iso, una razón "has_XYZ-" puede ser anulada por la presencia de un sistema de archivos ISO 9660 en el dispositivo.
La opción -list_long provoca que con cada línea se incluya una lista adicional de la información proporcionada por lsblk que condujo a las razones mostradas.
Ejemplo:
$ xorriso-dd-target -with_sudo -list_all
...
sda : NO : not_usb- has_vfat+ has_ext4- : ATA Samsung SSD 850
sdb : NO : not_usb- has_swap- has_ext4- : ATA WDC WD20EFRX-68A
sdc : SÍ : usb+ has_iso9660+ has_vfat+ : Intenso Ultra Line
sdd : NO : usb+ has_iso9660+ has_vfat+ has_ext2- : SanDisk Cruzer

Evaluar dispositivos específicos dados:

Si se proporcionan nombres de dispositivo en lugar de la opción -list_all, solo se inspeccionan esos dispositivos. Su resultado se lista sin la parte ": información", a menos que se proporcione la opción -with_vendor_model.
Los nombres de dispositivo no deben comenzar con '-' y deben ser palabras únicas compuestas por los caracteres [A-za-z0-9_/-]. No deben contener '/'. Por ejemplo, 'sdc' es válido, '/dev/sdc' no es válido.
Si un nombre de dispositivo dado no es recomendado, el valor de salida es 1.
Tiene poco sentido proporcionar nombres de dispositivo que no estén listados por -list_all.
Ejemplos:
$ xorriso-dd-target -with_sudo sdc
...
sdc : SÍ : usb+ has_iso9660+ has_vfat+
$ xorriso-dd-target -with_sudo -with_vendor_model sdc
...
sdc : SÍ : usb+ has_iso9660+ has_vfat+ : Intenso Ultra Line
$ xorriso-dd-target sdc
sdc : NO : usb+ no_fs_while_not_su-

Detectar el dispositivo deseado al enchufarlo:

La opción -plug_test activa un método interactivo para determinar inequívocamente el candidato de dispositivo de destino deseado. Consta de 2 o 3 pasos.
El Paso 1 es tener el dispositivo de almacenamiento deseado desconectado y confirmarlo presionando la tecla Enter en el aviso del programa. El programa evaluará la lista de dispositivos no deseados.
El Paso 2 es conectar el dispositivo de almacenamiento deseado y confirmarlo presionando la tecla Enter por segunda vez. El programa esperará hasta 10 segundos para que aparezca un dispositivo de almacenamiento similar a un disco que no esté en la lista de dispositivos no deseados. El usuario puede esperar presionando la tecla hasta que el parpadeo del dispositivo parezca que está listo.
Solo si se encuentra un único dispositivo nuevo, el programa continuará como si se hubiera proporcionado un único nombre de dispositivo. La opción -list_all y cualquier nombre de dispositivo proporcionado como argumento se ignorarán.
El Paso 3 ocurre solo si se proporcionan las opciones -DO_WRITE o -dummy_force. El programa solicita una entrada final de la palabra 'yes' antes de que comience la escritura real o simulada.
Ejemplo:
$ xorriso-dd-target -with_sudo -plug_test
...

Escribir imagen en un dispositivo recomendado:

Solo si se proporciona la opción -DO_WRITE y no se proporciona -list_all, y si se lista exactamente un dispositivo recomendable, se sobrescribirá realmente con el contenido del archivo del -image_file proporcionado. En este caso, el valor de salida es cero si la escritura tuvo éxito, y distinto de cero en caso contrario.
La opción -dummy evita este tipo de acción real y en su lugar muestra los comandos de umount y dd planificados en stdout.
Ejemplo:
$ xorriso-dd-target -with_sudo -plug_test -DO_WRITE \
-image_file debian-live-10.0.0-amd64-xfce.iso

NAME

xorriso-dd-target - Assist to find a drive for dd, help to write an iso9660 filesystem image.

SYNOPSIS

xorriso-dd-target [OPTION]... [DEVICE]...

DESCRIPTION

xorriso-dd-target is a shell script helper program to find a target storage device for the common unix command dd. It aims at helping users who need to write an ISO 9660 filesystem image onto a removable medium like USB sticks or SD cards.

The program analyzes the available block devices and reports on which ones are suitable candidates for writing an image file. It applies a set of rules to avoid accidental data loss on wrong devices.

If the program is called with -DO_WRITE and exactly one device is found to be suitable, it will perform the writing of the image file by calling dd. Before writing, it will offer to unmount partitions of the target device and will display the `dd` command it is about to execute.

If more than one device is suitable, or none, it will list them but not perform any write operation.

CAUTION: This program is designed to perform potentially destructive operations like overwriting storage devices. Always double-check the device names and the program's advice before proceeding with any write operation. The author is not responsible for any data loss.

Risks and Countermeasures

The program tries to avoid advising devices that should not be used for image writing. Reasons for disqualification are explained with the option -list_long. Normally, a single prohibitive reason (marked with a trailing '-') is enough to disqualify a device.

However, there are arguments that can be misused for that.
The outmost complicity to potentially unwise actions is offered by option -dummy_force. If given together with a single device name or with option -plug_test it will act like -dummy -DO_WRITE with this device, even if it looks not advisable. I.e. it will show the shell commands which the program does not dare to perform.
Example:
$ xorriso-dd-target -with_sudo -list_long -dummy_force sdd \
-image_file debian-live-10.0.0-amd64-xfce.iso
...

Alphabetical List of positive and negative reasons:

As stated with use case "List all devices", reasons are words with either suffix '+' for an inviting device property or '-' for a prohibitive property.
Normally a single '-' reason disqualifies the device from being advisable.

has_XYZ-
A filesystem of type XYZ is detected on base device or partition and is spoiling the impression of a device with disposable content.
has_iso9660+
An ISO 9660 filesystem is detected.
has_vfat+
A FAT (MS-DOS-like) filesystem is detected.
look_for_iso++
Option -look_for_iso is given and an ISO 9660 filesystem is detected. This reason overrides any "has_XYZ-" reason.
looks_like_cd_drive-
A given device name looks like the name of an optical drive: sr[0-9]*. Use program xorrecord for this kind of devices.
looks_like_disk_partition-
A given device name looks like the name of a partition. Expected are names of base devices, like "sde", not of their partitions, like "sde1".
looks_like_floppy-
A given device name looks like the name of a floppy disk drive: fd[0-9]*.
looks_like_loopdev-
A given device name looks like the name of a loop device: loop[0-9]*.
looks_like_ramdev-
A given device name looks like the name of a RAM block device: zram[0-9]*.
lsblk_no_size-
A size test is given by -max_size, -min_size, or -image_file but the size of the device cannot be inquired by lsblk. This is supposed to happen only with given inappropriate device names.
mmcblk+
The device name looks like a directly connected memory card.
name_with_slash-
A given device name contains '/' characters.
no_bus_info-
The device is not a memory card and lsblk reports nothing about the way how it is connected to the computer.
no_fs_while_not_su-
No filesystem is reported by lsblk and the program does not believe to have run it with superuser powers. There is the risk that lsblk silently failed to detect existing filesystems.
no_iso9660-
Option -look_for_iso is given but no ISO 9660 filesystem is detected.
not_usb-
The device is not a memory card and lsblk reports that it is connected by something other than USB.
size_too_large-
Option -max_size is given with a size smaller than the size of the device.
size_too_small-
Option -min_size or -image_file is given with size or file size larger than the size of the device.
usb+
The device is reported by lsblk to be connected via USB.

OPTIONS

-plug_test
Find the target device by asking the user to press the Enter key when the desired target is _not_ plugged in, to then plug it in, and to press Enter again.
This overrides device names and option -list_all. The found device is then shown with advice, vendor, and model.
Option -DO_WRITE is obeyed if given. In this case, the word 'yes' has to be entered to let unmounting and writing begin.
-list_all
Print list of all found devices with advice, vendor and model. One per line. Ignore any device names. Ignore -DO_WRITE.
-list_long
After each result line, which shows reasons, add an additional listing of the information provided by lsblk which led to the reasons and add an empty line.
-with_vendor_model
Print vendor and model with each submitted device name.
-max_size n[M|G|T]
Set the upper byte size limit for advisable devices. Plain numbers get rounded down to full millions. As suffix are recognized: M = million, G = billion, T = trillion.
Be generous to avoid problems with GB < GiB.
-min_size n[M|G|T]
Set the lower byte size limit for advisable devices. After processing like with -max_size, one million gets added to the size limit.
-look_for_iso
Demand presence of an ISO 9660 filesystem. If so, then any further filesystem type is acceptable on that device.
If this option is missing, only ISO 9660 and VFAT filesystems are accepted.
-with_sudo
Run 'lsblk -o FSTYPE' by sudo. If no filesystems are detected on a device while the program has no superuser power, then the device is not advised. Option -with_sudo avoids this refusal without the need to run the whole program as superuser.
If -DO_WRITE -with_sudo is given, then the programs umount and dd will be run by sudo, too.
-trust_lsblk_udev
Suppress the reason no_fs_while_not_su- if lsblk is linked with libudev.so. In this case it is likely that lsblk can retrieve FSTYPE even if run by a non-priviledged user.
This option is intended for use by frontend programs which are certain that they do not encounter a udev-using version of lsblk which nevertheless fails to detect existing filesystems. Human users should better acquire superuser powers if reason no_fs_while_not_su- is reported.
-image_file PATH
Set the path of the image file which shall be written to a device. Its size will be set as -min_size.
-DO_WRITE
Write the given -image_file to the one advisable device that is found. If more than one such device is found, then they get listed but no writing happens.
In this case, to get a real write run, consider unplugging unneeded devices, or using option -plug_test, or a re-run with one of the advised device names as additional argument.
-no_pacifier
Do not use dd options to print progress messages and to perform synchronized output. These options are used by default if program dd offers progress messages.
-dummy
Report the -DO_WRITE actions but do not perform them.
-dummy_force
If a single device name is given, do a run of -dummy -DO_WRITE even against the advice of this program. This probably shows you ways to shoot your own foot.
-version
Print the program name, version text, and timestamp to stdout and then end the program.
-help
Print the help text to stdout and then end the program.
