xdp-filter(8) Un filtro de paquetes simple impulsado por XDP xdp-filter(8)

NOMBRE

xdp-filter - un filtro de paquetes simple impulsado por XDP

SINOPSIS

Xdp-filter es una utilidad de filtrado de paquetes impulsada por XDP. Es deliberadamente simple y, por lo tanto, no tiene las mismas capacidades de coincidencia que, por ejemplo, netfilter. En cambio, gracias a XDP, puede lograr tasas de descarte muy altas: decenas de millones de paquetes por segundo en un solo núcleo de CPU.

Ejecutar xdp-filter

La sintaxis para ejecutar xdp-filter es:

xdp-filter COMANDO [opciones]
Donde COMANDO puede ser uno de:
       load        - cargar xdp-filter en una interfaz
       unload      - descargar xdp-filter de una interfaz
       port        - añadir un puerto a la lista de filtros
       ip          - añadir una dirección IP a la lista de filtros
       ether       - añadir una dirección MAC Ethernet a la lista de filtros
       status      - mostrar el estado actual de xdp-filter
       poll        - solicitar salida de estadísticas
       help        - mostrar la lista de comandos disponibles

Cada comando y sus opciones se explican a continuación. O use xdp-filter COMANDO --help para ver las opciones de cada comando.

El comando LOAD

Para usar xdp-filter, primero debe cargarse en una interfaz. Esto se logra con el comando load, que toma el nombre de la interfaz como parámetro y, opcionalmente, permite especificar las características que se deben incluir. Por defecto, se cargan todas las características, pero la deselección de algunas características puede acelerar la coincidencia de paquetes y aumentar el rendimiento considerablemente.

La sintaxis del comando load es:

xdp-filter load [opciones] <ifname>

Donde <ifname> es el nombre de la interfaz en la que cargar xdp-filter y debe especificarse. Las opciones admitidas son:

-m, --mode <modo>

Especifica en qué modo se cargará el programa XDP. Los valores válidos son 'native', que es el modo XDP nativo en el controlador por defecto, 'skb', que provoca el uso del llamado *modo skb* (también conocido como XDP genérico), o 'hw' que provoca que el programa se descargue al hardware.

-p, --policy <política>

Esto establece la política que xdp-filter aplica a los paquetes que **no** coinciden con ninguna de las reglas de filtrado. El valor por defecto es allow (permitir), en cuyo caso los paquetes que no coinciden con ninguna regla pueden pasar. La otra opción es deny (denegar), en cuyo caso **todos** los paquetes se descartan **excepto** aquellos que coinciden con las opciones de filtro.

Xdp-filter no puede cargarse simultáneamente en modos de política deny y allow en el sistema. Tenga en cuenta que cargar xdp-filter en modo deny descartará todo el tráfico en la interfaz hasta que se instalen las reglas de permiso adecuadas, por lo que se necesita cierta precaución para evitar quedar bloqueado fuera de un sistema remoto.

-f, --features <características>

Use esta opción para seleccionar qué características incluir al cargar xdp-filter. Por defecto, se cargan todas las características disponibles. Así que para seleccionar características individuales especifique una o más de las siguientes:

  • tcp: Soporte para filtrar por número de puerto TCP
  • udp: Soporte para filtrar por número de puerto UDP
  • ipv6: Soporte para filtrar por direcciones IPv6
  • ipv4: Soporte para filtrar por direcciones IPv4
  • ethernet: Soporte para filtrar por direcciones MAC Ethernet

Especifique varias características separándolas con una coma. Por ejemplo: tcp,udp,ipv6.

-v, --verbose

Habilita el registro de depuración. Especifique dos veces para una mayor verbosidad.

-h, --help

Muestra un resumen de las opciones disponibles

El comando UNLOAD

El comando unload descarga xdp-filter de una (o todas las) interfaces y limpia el estado del programa.

La sintaxis del comando load es:

xdp-filter unload [opciones] <ifname>

Donde <ifname> es el nombre de la interfaz de la que descargar xdp-filter y debe especificarse a menos que se utilice la opción --all. Las opciones admitidas son:

-a, --all

Especifique esta opción para eliminar xdp-filter de todas las interfaces en las que se cargó. Si se especifica esta opción, no se necesita ningún <ifname>.

Esta opción también se puede utilizar para limpiar todo el estado de xdp-filter si los programas XDP se descargaron por otros medios.

-k, --keep-maps

Especifique esta opción para evitar que xdp-filter borre el estado de sus mapas. Por defecto, se eliminan todos los mapas BPF que ya no son necesarios para ningún programa cargado. Sin embargo, esto también eliminará el contenido de los mapas (las reglas de filtrado), por lo que esta opción se puede utilizar para mantener los mapas para que las reglas persistan hasta que se vuelva a cargar xdp-filter.

-v, --verbose

Habilita el registro de depuración. Especifique dos veces para una mayor verbosidad.

-h, --help

Muestra un resumen de las opciones disponibles

El comando PORT

Use el comando port para agregar un puerto TCP o UDP a la lista de coincidencias de xdp-filter. Para que esto funcione, xdp-filter debe cargarse con la característica udp o tcp (o ambas) en al menos una interfaz.

La sintaxis del comando port es:

xdp-filter port [opciones] <puerto>

Donde <puerto> es el número de puerto a agregar (o eliminar si se especifica --remove). Las opciones admitidas son:

-r, --remove

Elimina el puerto en lugar de agregarlo.

-m, --mode <modo>

Selecciona el modo de filtrado. Las opciones válidas son src y dst, ambas pueden especificarse como src,dst. Si se especifica src, el número de puerto se agregará como una coincidencia de *puerto de origen*, mientras que si se especifica dst, el número de puerto se agregará como una coincidencia de *puerto de destino*. Si se especifican ambos, se coincidirá con un paquete si **cualquiera** de sus puertos de origen o destino es el número de puerto especificado.

-p, --proto <proto>

Especifique uno (o ambos) de udp y/o tcp para coincidir con puertos UDP o TCP, respectivamente.

-s, --status

Si se especifica esta opción, se imprimirá la lista actual de puertos coincidentes después de insertar el número de puerto. De lo contrario, no se imprimirá nada.

-v, --verbose

Habilita el registro de depuración. Especifique dos veces para una mayor verbosidad.

-h, --help

Muestra un resumen de las opciones disponibles

El comando STATUS

El comando status imprime el estado actual de xdp-filter: en qué interfaces está cargado, la lista actual de reglas y algunas estadísticas sobre cuántos paquetes se han procesado en total y cuántas veces se ha activado cada regla.

La sintaxis para el comando status es:

xdp-filter status [opciones]

Donde las opciones admitidas son:

-v, --verbose

Habilitar registro de depuración. Especifique dos veces para una verbosidad aún mayor.

-h, --help

Mostrar un resumen de las opciones disponibles.

El comando POLL

El comando poll sondea periódicamente el mapa de estadísticas de xdp-filter e imprime el número total de paquetes y bytes procesados por xdp-filter, así como el número en el último intervalo de sondeo, convertido a paquetes (y bytes) por segundo. Esto se puede usar para inspeccionar el rendimiento de xdp-filter y para comparar el rendimiento de los diferentes conjuntos de características seleccionables por el parámetro load.

La sintaxis para el comando poll es:

xdp-filter poll [opciones]

Donde las opciones admitidas son:

-i, --interval <intervalo>

El intervalo de sondeo, en milisegundos. El valor predeterminado es 1000 (1 segundo).

-v, --verbose

Habilitar registro de depuración. Especifique dos veces para una verbosidad aún mayor.

-h, --help

Mostrar un resumen de las opciones disponibles.

Ejemplos

Para filtrar todos los paquetes que llegan por el puerto 80 en eth0, emita los siguientes comandos:

# xdp-filter load eth0 -f tcp,udp
# xdp-filter port 80

Para filtrar todos los paquetes excepto los de la dirección IP fc00:dead:cafe::1, emita los siguientes comandos (¡cuidado, esto puede bloquearlo de acceso remoto!):

# xdp-filter load eth0 -f ipv6 -p deny
# xdp-filter ip fc00:dead:cafe::1 -m src

Para permitir paquetes de cualquiera de las IPs fc00:dead:cafe::1 o que lleguen por el puerto 22, emita lo siguiente (¡cuidado, esto puede bloquearlo de acceso remoto!):

# xdp-filter load eth0 -f ipv6,tcp -p deny
# xdp-filter port 22
# xdp-filter ip fc00:dead:cafe::1 -m src
