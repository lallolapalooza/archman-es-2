DESCRIPCIÓN

Xdvi es un programa para previsualizar archivos dvi, producidos por ejemplo por el programa tex(1), bajo el sistema de ventanas X.

Xdvi puede mostrar el archivo reducido por varios factores enteros, y tiene una ``lupa'' para ver partes de la página ampliadas (ver la sección MAGNIFIER abajo). Esta versión de xdvi también se conoce como xdvik ya que utiliza la biblioteca kpathsea para localizar y generar archivos de fuentes. Además de eso, soporta las siguientes características:

-
enlaces de hipertexto en archivos DVI (sección HYPERLINKS),
-
renderización directa de fuentes PostScript<tm> Tipo 1 (sección TYPE 1 FONTS),
-
especiales de origen en el archivo DVI (sección SOURCE SPECIALS),
-
búsqueda de cadenas en archivos DVI (sección STRING SEARCH),
-
guardar o imprimir (partes de) el archivo DVI (secciones PRINT DIALOG y SAVE DIALOG).

Xdvi puede ser compilado con el toolkit Motif o el toolkit Xaw (Athena) (y sus variantes), y la versión Motif tiene una GUI ligeramente diferente; estas diferencias se anotan a continuación.

Antes de mostrar una página de un archivo DVI, xdvi comprobará si el archivo ha cambiado desde la última vez que se mostró. Si es así, recargará el archivo. Esta característica le permite previsualizar muchas versiones del mismo archivo ejecutando xdvi solo una vez. Dado que no puede leer archivos DVI parciales, las versiones de xdvik a partir de la 22.74.3 crearán una copia temporal del archivo DVI que se está viendo, para asegurar que el archivo pueda ser visto sin interrupciones. (Se puede usar -notempfile para desactivar esta característica).

Xdvi puede mostrar especiales PostScript<tm> mediante cualquiera de tres métodos. Intentará primero usar Display PostScript<tm>, luego NeWS, luego intentará usar Ghostscript para renderizar las imágenes. Todas estas opciones dependen de software adicional para funcionar correctamente; además, algunas de ellas pueden no estar compiladas en esta copia de xdvi.

Por razones de rendimiento, xdvi no renderiza especiales PostScript en la lupa.

Si no se ha especificado ningún nombre de archivo en la línea de comandos, xdvi intentará abrir el archivo abierto más recientemente; si el historial de archivos (accesible a través del menú Archivo > Abrir Reciente) está vacío, o si ninguno de los archivos del historial son archivos DVI válidos, mostrará un selector de archivos para elegir un nombre de archivo. (En versiones anteriores, que no tenían historial de archivos, siempre se usaba el selector de archivos; puede establecer el recurso X noFileArgUseHistory a false para recuperar el comportamiento anterior.)

OPCIONES

Además de especificar el archivo dvi (con o sin la extensión .dvi), xdvi soporta las siguientes opciones de línea de comandos. Si la opción comienza con un `+' en lugar de un `-', la opción se restaura a su valor predeterminado. Por defecto, estas opciones se pueden establecer a través de los nombres de recursos dados entre paréntesis en la descripción de cada opción.

+página
Especifica la primera página a mostrar. Si se proporciona + sin un número, se asume la última página; la primera página es la predeterminada.
-allowshell
(.allowShell) Esta opción habilita la ejecución de comandos externos en especiales PostScript. (Por razones de seguridad, las ejecuciones de comandos están deshabilitadas por defecto.) Esta opción debería usarse raramente; en particular, no debería usarse solo para descomprimir archivos: esa función se realiza automáticamente si el nombre del archivo termina en .Z, .gz o .bz2. Las ejecuciones de comandos siempre se desactivan si se usa la opción -safer.
-altfont fuente
(.altFont) Declara una fuente predeterminada a usar cuando la fuente en el archivo dvi no se encuentra. Esto es útil, por ejemplo, con fuentes PostScript <tm>.
-anchorposition ancla
Salta al ancla después de abrir el archivo DVI. Esto solo es útil al invocar xdvi desde otras aplicaciones.
-background color
(.background) Determina el color del fondo. Igual que -bg.
-bg color
(.background) Determina el color del fondo.
-browser navegador
(.wwwBrowser) Define el navegador web utilizado para manejar URLs externas. El valor de esta opción o recurso tiene la misma sintaxis que la variable de entorno BROWSER; consulte la explicación de esa variable en la sección `ENVIRONMENT' a continuación para una descripción detallada. Si ni la opción ni el recurso X wwwBrowser se especifican, se utilizan las variables de entorno BROWSER y WWWBROWSER (en ese orden) para determinar el comando del navegador. Si tampoco están configuradas, se utiliza el siguiente valor predeterminado: xdg-open %s:htmlview %s:firefox -remote -remote "openURL(%s,new-window)":mozilla -remote "openURL(%s,new-window)":netscape -raise -remote "openURL(%s,new-window)":xterm -e w3m %s:xterm -e lynx %s:xterm -e wget %s
-copy
(.copy) Usa siempre la operación de copia al escribir caracteres en la pantalla. Esta opción puede ser necesaria para el funcionamiento correcto en una pantalla a color, pero los caracteres sobrescritos serán incorrectos. Si se está utilizando anti-aliasing en escala de grises, la operación -copy deshabilitará el uso de planos de color y hará que las sobrescrituras salgan incorrectamente. Ver también -thorough.
-cr color
(.cursorColor) Determina el color del cursor del ratón. El predeterminado es el mismo que el color de primer plano.
-debug máscara de bits|cadena[,cadena ...]
(.debugLevel) Si es distinto de cero, imprime información adicional en la salida estándar. El argumento puede ser una máscara de bits especificada como número decimal, o una lista de cadenas separadas por comas.
Para la representación de máscara de bits, múltiples va
se pueden especificar añadiendo los números que representan los bits individuales; por ejemplo, para depurar todos los comandos de búsqueda y apertura de archivos, utilice 4032 (= 2048 + 1024 + 512 + 256 + 128 + 64). Utilice -1 para activar la depuración de todo (esto producirá una salida enorme).
Para la representación en cadena, utilice las cadenas que se enumeran en la siguiente tabla, separadas por comas; por ejemplo, para depurar todos los comandos de búsqueda y apertura de archivos, utilice search,expand,paths,hash,stat,open. (La opción `kpathsea' se proporciona como abreviatura para estas.) Tenga en cuenta que es posible que sea necesario entrecomillar dicha lista para evitar que el shell interprete las comas o los espacios de la lista.
Los números y cadenas individuales tienen los siguientes significados: 
1	bitmap	Creación de mapas de bits
2	dvi	Traducción de DVI
4	pk	Fuentes PK
8	batch	Modo por lotes: Salir después
		de leer el archivo DVI
16	event	Manejo de eventos
32	ps	Llamadas al intérprete PostScript
64	stat	Llamadas stat(2) de Kpathsea
128	hash	Búsquedas en tablas hash de Kpathsea
256	open	Apertura de archivos de Kpathsea
512	paths	Definiciones de rutas de Kpathsea
1024	expand	Expansión de rutas de Kpathsea
2048	search	Búsqueda de Kpathsea
4032	kpathsea	Todas las opciones de Kpathsea
4096	htex	Especiales Hypertex
8192	src	Especiales de origen
16384	client	Modo cliente/servidor (ver opciones -unique
		y -sourceposition)
32768	ft	Mensajes de la biblioteca FreeType (fuentes Type 1)
65536	ft_verbose	Mensajes detallados de la biblioteca FreeType (actualmente no utilizados)
131072	gui	Elementos de la GUI
262144	find	Búsqueda de cadenas en el archivo DVI
524288	files	Historial de archivos y apertura de archivos DVI
Algunas de las opciones de depuración de Kpathsea son proporcionadas en realidad por Kpathsea; consulte la sección de Depuración del manual de Kpathsea para obtener más información sobre estas.
-density densidad
(.densityPercent) Determina la densidad utilizada al reducir los mapas de bits para las fuentes. Un valor más alto produce una fuente más clara. El valor predeterminado es 40. Si se está utilizando la escala de grises, este argumento no se aplica; utilice -gamma en su lugar. Consulte también la pulsación de tecla `S'. Igual que -S.
-display host:pantalla
Especifica el host y la pantalla que se utilizarán para mostrar el archivo dvi. Por defecto, esto se obtiene de la variable de entorno DISPLAY.
-dvipspath ruta
(.dvipsPath) Utilice ruta como programa dvips a usar al imprimir. El valor predeterminado para esto es dvips. El programa o script debe leer el archivo DVI de la entrada estándar y escribir el archivo PostScript en la salida estándar.
-editor editor
(.editor) Especifica el editor que se invocará cuando se active la acción source-special() para iniciar una búsqueda inversa (por defecto mediante Ctrl-Mouse 1). El argumento de esta opción es una cadena de formato en la que las ocurrencias de ``%f'' se reemplazan por el nombre del archivo, las ocurrencias de ``%l'' se reemplazan por el número de línea dentro del archivo y las ocurrencias opcionales de ``%c'' se reemplazan por el número de columna dentro de la línea.

Si no se especifica ni la opción ni el recurso X .editor, se comprueban las siguientes variables de entorno para determinar el comando del editor: XEDITOR, VISUAL y EDITOR (en esta secuencia). Si la cadena se encuentra como valor de las variables de entorno VISUAL o EDITOR, se antepone ``xterm -e '' a la cadena; si el editor se especifica por otros medios, debe tener la forma de un comando de shell para abrir una ventana X con un editor. Si ninguna de estas variables está configurada, se muestra un mensaje de advertencia y se utiliza el comando ``xterm -e vi +%l %f''.

Si no ocurre ningún ``%f'' o ``%l'' en la cadena, las cadenas de formato que falten se añadirán automáticamente. (Esto es para compatibilidad con otros programas al usar una de las variables de entorno).

Se inicia una nueva instancia del editor cada vez que se utiliza este comando; por lo tanto, es preferible utilizar un editor que se pueda invocar en modo `cliente' para cargar nuevos archivos en la misma instancia. Los ajustes de ejemplo son:

emacsclient --no-wait
(Emacs antiguos)
gnuclient -q
(XEmacs y Emacs más recientes)
gvim --servername xdvi --remote
(VIM v6.0+; la opción `--servername xdvi' hará que gvim ejecute una instancia dedicada para los archivos abiertos por xdvi.)
nc
(nedit)

Tenga en cuenta que estas cadenas deben entrecomillarse al usarlas en la línea de comandos para protegerlas del shell; al usarlas como argumento para el recurso .editor en un archivo de recursos X, no deben usarse comillas.

NOTA SOBRE SEGURIDAD: El argumento de esta opción no se ejecuta como un comando de shell, sino a través de exec() para evitar trucos maliciosos con el contenido de los especiales de origen.

-expert
Esta opción solo se admite por motivos de compatibilidad con versiones anteriores; es equivalente a -expertmode 0, que debería preferirse.
-expertmode bandera
(.expertMode) Con un argumento de 0, esta opción desactiva la visualización de los botones, las barras de desplazamiento, la barra de herramientas (solo Motif), la línea de estado y la lista de páginas. Estos elementos de la GUI también se pueden activar/desactivar por separado, combinando los valores apropiados en el argumento bandera. Esto funciona de manera similar a la opción -debug: el entero bandera se trata como un mapa de bits donde cada bit representa un elemento. Si el bit tiene el valor 1, el elemento está activado, si tiene el valor 0, el elemento está desactivado. El significado de los bits es el siguiente: 
1	statusline
2	scrollbars
4	Motif: pagelist, Xaw: buttons and pagelist
8	toolbar (Motif only)
16	menubar (Motif only)
Por ejemplo, para activar solo la línea de estado y las barras de desplazamiento, utilice 3 (= 1 + 2). Consulte también la pulsación de tecla `x', donde los bits se abordan por sus posiciones, de 1 a 3 (Xaw) o 5 (Motif), respectivamente.

Si la línea de estado no está activa, todos los mensajes que normalmente se imprimirían en la línea de estado se imprimirán en stdout, a menos que se utilice la opción -hushstdout.

-fg color
(.foreground) Determina el color del texto (primer plano).
-findstring cadena
Esta opción activa la búsqueda de cadena en el archivo DVI mencionado en la línea de comandos, similar a la búsqueda directa (consulte la descripción de la opción sourceposition): Si ya hay otra instancia de xdvi ejecutándose en la pantalla de ese archivo DVI, hará que esa instancia realice la búsqueda en su lugar. La búsqueda comienza en la parte superior de la página actual del archivo DVI.
-font fuente
(*font) Establece la fuente utilizada en menús, botones, etc., como se describe en la página man X(7x). La fuente para las ventanas secundarias se puede establecer por separado, por ejemplo:
xdvi*statusline*font: \
   -*-helvetica-medium-r-*-*-12-*-*-*-*-*-*-*
-foreground color
Igual que -fg.
-fullscreen
Cuando se utiliza esta opción, xdvi se ejecutará (intentará) en modo de pantalla completa, sin decoraciones de ventana. No se garantiza que esta opción funcione con todos los gestores de ventanas/escritorios; si experimenta problemas con ella, utilice la opción -geometry en su lugar y una configuración adecuada del gestor de ventanas para eliminar las decoraciones de la ventana. Al usar esta opción para presentaciones, es posible que desee eliminar también todos los widgets de control, utilizando la opción -expertmode. Esta opción también se puede activar/desactivar en tiempo de ejecución utilizando la acción fullscreen (por defecto asignada a Ctrl-l).
-gamma gamma
(.gamma) Controla la interpolación de colores en la paleta de colores de anti-aliasing en escala de grises. El valor predeterminado es 1.0. Para 0 < gamma < 1, las fuentes serán más claras (más parecidas al fondo), y para gamma > 1, las fuentes serán más oscuras (más parecidas al primer plano). Los valores negativos se comportan de la misma manera, pero utilizan un algoritmo ligeramente diferente. Para pantallas en color y escala de grises; para monocromas, consulte -density. Consulte también la pulsación de tecla `S'.
-geometry geometría
(.geometry) Especifica la geometría inicial de la ventana principal, como se describe en la página man X(7x). La geometría de las ventanas secundarias se puede establecer por separado, por ejemplo:
xdvi*helpwindow.geometry: 600x800
-gsalpha
(.gsAlpha) Hace que Ghostscript se llame con el controlador x11alpha en lugar del controlador x11. El controlador x11alpha habilita el anti-aliasing en los especiales de PostScript, para una apariencia más agradable. Está disponible en versiones más recientes de Ghostscript. Esta opción también se puede activar/desactivar con la pulsación de tecla `V'.
-gspalette paleta
(.palette) Especifica la paleta que se utilizará al usar Ghostscript para renderizar especiales de PostScript. Los valores posibles son Color, Greyscale y Monochrome. El valor predeterminado es Color.
-h, -help, --help
Imprime un breve texto de ayuda con un resumen de las opciones de la línea de comandos en la salida estándar.
-hl color
(.highlight) Determina el color del borde de la página, de la regla en `modo regla', y de los marcadores de resaltado en la búsqueda directa y la búsqueda de cadenas. El valor predeterminado es el color del primer plano.
-hush
(.Hush) Hace que xdvi suprima todas las advertencias suprimibles.
-hushbell
(.hushBell) No emite el tono X cuando ocurre un error.
-hushchars
(.hushLostChars) Hace que xdvi suprima las advertencias sobre refe
-hushchecksums
(.hushChecksums) Hace que xdvi suprima las advertencias sobre incompatibilidades de checksum entre el archivo dvi y el archivo de fuente.
-hushstdout
(.hushStdout) Suprime la impresión de mensajes de estado a stdout. Tenga en cuenta que los errores o advertencias seguirán imprimiéndose en stderr incluso si se utiliza esta opción.
-icongeometry geometría
(.iconGeometry) Especifica la posición inicial para el icono.
-iconic
(.iconic) Hace que la ventana xdvi comience en estado icónico. El valor predeterminado es comenzar con la ventana abierta.
-install
(.install) Si xdvi se ejecuta bajo una visualización PseudoColor, entonces (por defecto) buscará visualizaciones TrueColor con más bits por píxel, y cambiará a una visualización de ese tipo si existe. Si no existe tal visualización, utilizará la visualización y el mapa de colores actual. Si se selecciona -install, sin embargo, aún utilizará una visualización TrueColor con una profundidad mayor, si está disponible; de lo contrario, instalará su propio mapa de colores en la visualización actual. Si la visualización actual no es PseudoColor, entonces xdvi no cambiará la visualización ni el mapa de colores, independientemente de sus opciones. El valor predeterminado del recurso install es el valor especial, maybe. No hay opción +install. Ver también -noinstall y la sección ESCALADO EN GRISES Y MAPAS DE COLORES.
-interpreter archivo
(.interpreter) Usa archivo como el intérprete de Ghostscript. Por defecto usa gs.
-keep
(.keepPosition) Establece una bandera para indicar que xdvi no debe moverse a la posición de inicio al pasar a una nueva página. Ver también la pulsación de tecla `k'. Esta bandera es respetada por todas las acciones de cambio de página y por up-or-previous() / down-or-next(), aunque estos últimos solo respetan la posición horizontal, no la vertical. Esto permite un desplazamiento "continuo" hacia adelante y hacia atrás en un documento con una ventana de visualización más estrecha que el ancho de la página.
-l
(.listFonts) Enumera los nombres de todas las fuentes utilizadas.
-license
Imprime información de licencia.
-linkcolor
(.linkColor) Color utilizado para hipervínculos no visitados (`Blue2' por defecto). Los hipervínculos no se visitan antes de hacer clic en ellos, o después de que el archivo DVI se haya recargado. El valor debe ser un nombre de color X válido (como DarkGoldenrod4) o una cadena de color hexadecimal (como #8b6508). Ver también -visitedlinkcolor y -linkstyle.
-linkstyle
(.LinkStyle) Determina el estilo en el que se muestran los hipervínculos. Los valores posibles y sus significados son: 
0	No resaltar enlaces
1	Subrayar enlaces con el color del enlace
2	Sin subrayado, colorear texto con el color del enlace
3	Subrayar y mostrar texto coloreado con el
	color del enlace
Los valores para color del enlace se especifican mediante las opciones/recursos -linkcolor y -visitedlinkcolor (ver).
-margins dimensión
(.Margin) Especifica el tamaño del margen superior y del margen lateral. Esto determina la posición "de inicio" de la página dentro de la ventana de la siguiente manera. Si toda la página cabe en la ventana, entonces se ignoran los ajustes de margen. Si, incluso después de eliminar los márgenes de la izquierda, derecha, arriba y abajo, la página aún no cabe en la ventana, entonces la página se coloca en la ventana de manera que se ocultan los márgenes superior e izquierdo, y presumiblemente la esquina superior izquierda del texto de la página estará en la esquina superior izquierda de la ventana. De lo contrario, el texto se centra en la ventana. La dimensión debe ser un número decimal opcionalmente seguido de cualquiera de las abreviaturas de dos letras para unidades aceptadas por TeX (pt, pc, in, bp, cm, mm, dd, cc o sp). Por defecto, la unidad será cm (centímetros). Ver también -sidemargin, -topmargin y la pulsación de tecla `M'.
-mfmode def-modo
(.mfMode) Especifica una cadena def-modo, que puede usarse para buscar fuentes (ver ENTORNO, abajo). Generalmente, al cambiar el def-modo, también es necesario cambiar el tamaño de la fuente al valor apropiado para ese modo. Esto se hace añadiendo dos puntos y el valor en puntos por pulgada; por ejemplo, -mfmode ljfour:600. Este método anula cualquier valor dado por el recurso pixelsPerInch o el argumento de línea de comandos -p. El modo Metafont también se pasa a metafont durante la creación automática de fuentes. Por defecto, es no especificado.
-mgs tamaño
Igual que -mgs1.
-mgs[n] tamaño
(.magnifierSize[n]) Especifica el tamaño de la ventana a utilizar para la "lupa" para el Botón n. El tamaño puede darse como un entero (indicando que la lupa será cuadrada), o puede darse en el formato anchoxalto. Ver la sección ACCIONES DEL RATÓN. Los valores predeterminados son 200x150, 400x250, 700x500, 1000x800 y 1200x1200.
-mousemode [0|1|2]
(.mouseMode) Especifica el modo predeterminado de xdvi al inicio: Lupa (0), Modo de Selección de Texto (1) o Modo Regla (2). Ver la sección MODOS, abajo, para más información.
-nocolor
(.color) Desactiva el uso de especiales de color. Esta opción se puede alternar con la pulsación de tecla `C'. (Nota: -nocolor corresponde a color:off; +nocolor a color:on.)
-nofork
(.fork) Con las opciones -sourceposition y -unique, el comportamiento predeterminado es que xdvi se ponga en segundo plano (como un demonio) si no hay una instancia apropiada de xdvi ya en ejecución. Este argumento hace que se ejecute en primer plano en su lugar. Esto es útil para depurar, o si su aplicación cliente no puede manejar bien que un programa se ponga en segundo plano de esta manera; por ejemplo, se sabe que las funciones IPC de emacs tienen problemas con esto. Si no se proporciona el argumento -sourceposition o -unique, entonces esta opción no tiene efecto. (Nota: -nofork corresponde a fork:off; +nofork a fork:on.)
-noghostscript
(.ghostscript) Inhibe el uso de Ghostscript para mostrar especiales PostScript<tm>. (Nota: -noghostscript corresponde a ghostscript:off; +noghostscript a ghostscript:on.)
-nogrey
(.grey) Desactiva el uso de anti-aliasing en escala de grises al imprimir mapas de bits reducidos. (Nota: -nogrey corresponde a grey:off; +nogrey a grey:on.) Ver también la pulsación de tecla `G'.
-nogssafer
(.gsSafer) Normalmente, si Ghostscript se utiliza para renderizar especiales PostScript, el intérprete Ghostscript se ejecuta con la opción -dSAFER. La opción -nogssafer ejecuta Ghostscript sin -dSAFER. La opción -dSAFER en Ghostscript deshabilita operadores PostScript como deletefile, para evitar que programas PostScript posiblemente maliciosos tengan algún efecto. Si se especifica la opción -safer, entonces esta opción no tiene efecto; en ese caso Ghostscript se ejecuta siempre con -dSAFER. (Nota: -nogssafer corresponde a gsSafer:off; +nogssafer a gsSafer:on.)
-noinstall
(.install) Inhibe el comportamiento predeterminado de cambiar a una visualización TrueColor si hay una disponible con más bits por píxel que la visualización actual. (Nota: -noinstall corresponde a install:off; no hay opción +noinstall.) Ver también -install y la sección ESCALADO EN GRISES Y MAPAS DE COLORES.
-nomakepk
(.makePk) Desactiva la generación automática de archivos de fuentes que no se encuentran por otros medios. (Nota: -nomakepk corresponde a makePk:off; +nomakepk a makePK:on.)
-nomatchinverted
(.matchInverted) No resalte las coincidencias de búsqueda de cadenas en color invertido; en su lugar, dibuje un rectángulo en color resaltado (ver la opción -hl) alrededor de la coincidencia. Esta opción se activa automáticamente si la pantalla no se está ejecutando en TrueColor. (Nota: -nomatchinverted corresponde a matchInverted:off; +nomatchinverted a matchInverted:on.)
-noomega
(.omega) Esto deshabilitará el uso de extensiones Omega al interpretar archivos DVI. Por defecto, los opcodes adicionales 129 y 134 son reconocidos por xdvi como extensiones Omega e interpretados como solicitudes para establecer caracteres de 2 bytes. La única desventaja es que la matriz de fuentes virtuales requerirá 65536 posiciones en lugar de las 256 predeterminadas, es decir, los requisitos de memoria de xdvi serán ligeramente mayores. Si considera esto inaceptable o encuentra otro problema con las extensiones Omega, puede desactivar esta extensión usando -noomega (pero por favor envíe un informe de error si encuentra tales problemas; ver la dirección de errores en la sección AUTORES más abajo).
(Nota: -noomega corresponde a omega: off; +noomega a omega: on.)
-noscan
(.prescan) Por defecto, xdvi realiza un escaneo preliminar del archivo dvi para procesar cualquier especial papersize; esto es especialmente importante al inicio, ya que el tamaño del papel puede ser necesario para
determine la ventana. Si se usa PostScript<tm>, entonces el preanálisis también es necesario para procesar correctamente los archivos de encabezado. Además, el preanálisis es necesario para determinar correctamente el color de fondo de una página. Esta opción desactiva dicho preanálisis. (El preanálisis se activará automáticamente si xdvi detecta alguno de los especiales mencionados anteriormente). (Nota: -noscan corresponde a prescan:off; +noscan a prescan:on.)
-notempfile
(.tempFile) Como se mencionó en la sección DESCRIPCIÓN anterior, xdvi creará una copia temporal del archivo DVI para que pueda ser accedido sin interrupciones, incluso mientras el archivo está siendo reescrito por TeX. Dado que esto introduce la sobrecarga de copiar el archivo cada vez que cambia, la opción -notempfile permite desactivar este comportamiento. En este caso, exponer partes de la ventana mientras TeX está escribiendo el archivo DVI borrará el contenido actual de la ventana hasta que el archivo DVI pueda ser completamente releído.
(Nota: -notempfile corresponde a tempFile:off; +notempfile a tempFile:on.)
-notype1fonts
(.type1) Esto deshabilitará el uso de la biblioteca FreeType para mostrar fuentes PostScript<tm> Type 1. Utilice esta opción como solución alternativa cuando encuentre problemas con la visualización de fuentes Type 1 (pero no olvide enviar un informe de error en este caso, a la URL mencionada en la sección AUTORES a continuación).
(Nota: -notype1fonts corresponde a type1:off; +notype1fonts a type1:on.)
-offsets dimensión
(.Offset) Especifica el tamaño de ambos desfases, horizontal y vertical, de la salida en la página. Por decreto del Stanford TeX Project, el origen de página predeterminado de TeX siempre está 1 pulgada hacia la derecha y hacia abajo desde la esquina superior izquierda de la página, incluso cuando se utilizan tamaños de papel no americanos. Por lo tanto, los desfases predeterminados son 1.0 pulgada. El argumento dimensión debe ser un número decimal seguido opcionalmente por alguna de las abreviaturas de dos letras para unidades aceptadas por TeX (pt, pc, in, bp, cm, mm, dd, cc o sp). Por defecto, la unidad será cm (centímetros). Consulte también -xoffset y -yoffset.
-p píxeles
(.pixelsPerInch) Define el tamaño de las fuentes a utilizar, en píxeles por pulgada. El valor predeterminado es 600. Esta opción se proporciona solo para compatibilidad con versiones anteriores; la forma preferida es establecer tanto la resolución como el modo Metafont a través de la opción -mfmode (que se ve más abajo).
-paper tipo_papel
(.paper) Especifica el tamaño de la página impresa. Tenga en cuenta que en la mayoría de los casos es mejor especificar el tamaño del papel en el archivo de entrada TeX a través de la línea

\usepackage[dvips]{geometry}

que será reconocida tanto por dvips como por xdvi; en ese caso el uso de una opción `-paper' debería ser innecesario.
El tamaño del papel puede especificarse en la forma anchoxalto seguido opcionalmente por una unidad, donde ancho y alto son números decimales que dan el ancho y la altura del papel, respectivamente, y la unidad es cualquiera de las abreviaturas de dos letras para unidades aceptadas por TeX (pt, pc, in, bp, cm, mm, dd, cc o sp). Por defecto, la unidad es cm (centímetros).
También hay sinónimos que se pueden usar: us (8.5x11in), legal (8.5x14in), foolscap (13.5x17in), así como los tamaños ISO a1-a7, b1-b7, c1-c7. Cada uno de estos también tiene una variante horizontal o "rotada": usr (11x8.5in), a1r-a7r, etc. Para compatibilidad con dvips, también se admiten los formatos letter (8.5x11in), ledger (17x11in) y tabloid (11x17in) (estos no tienen variantes rotadas).
Cualquiera de los tamaños anteriores puede ir precedido por un signo más (`+'); esto hace que el tamaño del papel especificado aquí anule cualquier tamaño de papel especificado en el archivo dvi. El tamaño de papel predeterminado es 21 x 29.7 cm (tamaño A4).

-sourceposition línea[:col][ ]nombre_archivo
Esta opción hace que xdvi busque en el archivo dvi el lugar correspondiente a la línea (y, opcionalmente, columna) indicada en el archivo fuente .tex, y resalte el lugar encontrado dibujando un rectángulo en el color resaltado (ver la opción -hl) alrededor del texto correspondiente. Además, cuando se ejecuta con este argumento (y la opción -nofork no se da, que se ve más abajo), xdvi siempre devolverá inmediatamente: si encuentra otra instancia de xdvi mostrando ya el dvi_file, entonces hará que esa instancia eleve su ventana y se mueva al lugar dado en el archivo dvi; de lo contrario, iniciará su propia instancia en segundo plano. Si varias instancias de xdvi están mostrando el respectivo archivo dvi, se utilizará la instancia que fue elevada por última vez al primer plano.

El espacio antes de nombre_archivo solo es necesario si el nombre de archivo comienza con un dígito. Cuando se usa el espacio, el argumento debe incluirse entre comillas para evitar que el shell malinterprete el espacio como un separador de argumentos.

Esta opción requiere que dvi_file esté preparado con información de fuentes especiales. Ver la sección sobre FUENTES ESPECIALES para obtener detalles sobre cómo hacerlo.

Aquí hay una descripción más detallada de cómo el nombre de archivo en el argumento -sourceposition se compara con el nombre de archivo en las fuentes especiales:

1.
Si ninguno de los nombres de archivo contiene un componente de ruta, los nombres de archivo se comparan ignorando las extensiones `.tex' en ambos nombres de archivo.
2.
De lo contrario, si uno de los nombres de archivo contiene un componente de ruta (por ejemplo: ./test.tex, ../test.tex, /my/homedir/tex/test.tex o cualquier combinación de estos), ambos nombres de archivo se expanden a una ruta completa, con cualquier ocurrencia de ../ y ./ expandida, y se eliminan los slashes múltiples.
El nombre de ruta en -sourceposition se expande en relación con el directorio de trabajo actual de la invocación xdvi -sourceposition, y los nombres de ruta en las fuentes especiales se expanden en relación con la ruta del archivo DVI actual que se está viendo.
Los nombres de ruta se comparan luego ignorando las extensiones `.tex' en ambos nombres de ruta.

(.textEncoding) Usa encoding como la codificación de texto de la cadena en la ventana "Buscar". Normalmente, esto no debería ser necesario ya que la codificación se determina a partir de la configuración regional.
-thorough
(.thorough) Xdvi normalmente intentará asegurar que los caracteres de sobreescritura (por ejemplo, \notin) se impriman correctamente. En pantallas monocromáticas, esto siempre es posible con una operación lógica, ya sea and u or. Sin embargo, en pantallas en color, esto puede requerir dos operaciones, una para establecer los bits apropiados y otra para borrar otros bits. Si este es el caso, entonces por defecto xdvi utilizará en su lugar la operación copy, que no maneja la sobreescritura correctamente. La opción -thorough elige la opción más lenta pero más correcta. Ver también -copy.

(.topMargin) Especifica los márgenes superior e inferior (ver -margins).
-unique
(.unique) Esta opción hará que otra instancia de xdvi ejecutándose en la misma pantalla actúe como un `servidor'. Por ejemplo, la invocación

xdvi -unique +5 file.dvi

hará que esta otra instancia cargue file.dvi en la página 5 en lugar del archivo que está mostrando actualmente. Si ya existe otra instancia de xdvi mostrando el archivo file.dvi, simplemente saltará a la página 5. Si la otra instancia de xdvi está mostrando un archivo diferente, cargará file.dvi en su lugar. De lo contrario, si no hay otra instancia de xdvi ejecutándose actualmente en la pantalla, esta opción iniciará una nueva instancia de xdvi en segundo plano (a menos que se especifique la opción -nofork, que ver) mostrando la página 5 de file.dvi.
El nombre del archivo y la opción +n para el número de página son las únicas opciones disponibles para controlar una instancia remota de xdvi de esta manera; todas las demás opciones se ignoran actualmente.

TECLAS

Xdvi reconoce las siguientes pulsaciones de teclas cuando se escriben en su ventana. Cada una puede ir opcionalmente precedida por un número (positivo o negativo), un `argumento de prefijo', cuya interpretación dependerá de la pulsación de tecla particular. Este argumento de prefijo puede ser descartado presionando la tecla ``Escape''. Si están presentes, las teclas ``Help'', ``Prior'' y ``Next'' son sinónimos de las teclas `?', `b' y `f', respectivamente.

Las combinaciones de teclas enumeradas aquí son las que xdvi asigna por defecto. Los nombres que aparecen entre corchetes al principio de las descripciones son los nombres de las acciones asociadas a las teclas; estos pueden usarse para personalizar las combinaciones de teclas, como se explica con más detalle en la sección PERSONALIZACIÓN a continuación. Si solo se enumera una combinación en minúsculas, tanto las teclas mayúsculas como las minúsculas funcionarán para esa combinación.

ACCIONES DEL RATÓN EN LA VENTANA PRINCIPAL

Las acciones del ratón se pueden personalizar configurando el recurso X mouseTranslations. Dado que hay tres modos de ratón diferentes (ver la sección MODES abajo), hay una acción especial mouse-modes que lista las acciones para cada uno de los tres modos: mouse-modes("ACCIONES-PARA-MODO1", "ACCIONES-PARA-MODO2", "ACCIONES-PARA-MODO3"). Si se especifica solo un argumento, esta acción se usa para todos los modos. Las combinaciones predeterminadas son las siguientes:

xdvi.mouseTranslations: \
Shift<Btn1Down>:mouse-modes("drag(+)")\n\
Shift<Btn2Down>:mouse-modes("drag(|)")\n\
Shift<Btn3Down>:mouse-modes("drag(-)")\n\
Ctrl<Btn1Down>:mouse-modes("source-special()")\n\
<Btn1Down>: mouse-modes("do-href()magnifier(*2)", "text-selection()", "ruler()")\n\
<Btn2Down>: mouse-modes("do-href-newwindow()magnifier(*2)", "text-selection()", "ruler()")\n\
<Btn3Down>: mouse-modes("magnifier(*3)")\n\
<Btn4Down>: mouse-modes("wheel(-0.2)")\n\
<Btn5Down>: mouse-modes("wheel(0.2)")\n\
<Btn6Down>: mouse-modes("hwheel(-0.2)")\n\
<Btn7Down>: mouse-modes("hwheel(0.2)")\n\
Todas estas acciones se describen con más detalle a continuación. Note el uso de comillas alrededor de las cadenas de acción, que son necesarias para agruparlas en un solo argumento. Los botones 4, 5, 6 y 7 se refieren a movimientos de rueda (rueda arriba/abajo/izquierda/derecha) en ratones con rueda. No todos los ratones soportan el desplazamiento horizontal.

Las rutinas del Toolkit X que implementan las traducciones no soportan tipos de eventos de Btn6Down o Btn7Down. Debido a esto, xdvi implementa su propio analizador para las traducciones dadas en mouseTranslations. Este analizador es más limitado que el analizador integrado en el Toolkit X. La cadena dada en mouseTranslations no debe comenzar con ``#replace'', ``#augment'', o ``#override''. Los modificadores de la forma @keysym no son soportados, y el tipo de evento debe ser de la forma BtnDown o BtnnDown, donde n es un entero positivo sin ceros iniciales. Además, algunas limitaciones se aplican al campo de acción.

do-href()
do-href-newwindow()
Por lo general, si una combinación especifica más de una acción, todas las acciones se ejecutan en secuencia. Las combinaciones de hipervínculos do-href() y do-href-newwindow() son especiales en el sentido de que se usan como una *alternativa* a otras acciones que podrían seguirlas *si* el ratón está actualmente sobre un hipervínculo. En este caso, ninguna de las otras acciones se ejecutará; de lo contrario, solo se ejecutarán las otras acciones.
La acción do-href() salta al destino del enlace en la ventana actual de xdvi (cambiando eventualmente a otra página), y do-href-newwindow() abre una nueva instancia de xdvi para el destino del enlace. En ambos casos, la ubicación del destino se indica con una pequeña flecha dibujada en el mismo color que un enlace visitado en la esquina izquierda de la ventana.
magnifier(n x m)
magnifier(*n)
Esta acción mostrará una "lupa" que muestra la imagen sin reducir de la región alrededor del puntero del ratón. La lupa desaparece cuando se suelta el botón del ratón. Mover el cursor del ratón mientras se mantiene presionado el botón moverá la lupa.
Diferentes botones del ratón producen ventanas de diferentes tamaños, como lo indica el argumento de la acción magnifier(). Su argumento es una cadena de la forma anchoxalto, como en la opción de línea de comandos -mgsn, o una de las cadenas *1 a *5, refiriéndose al valor especificado por la opción correspondiente -mgsn.
drag(+)
drag(|)
drag(-)
Arrastra la página con el ratón. Esta acción debe tener un parámetro, el carácter ``|'', ``-'', o ``+'', indicando solo arrastre vertical, solo arrastre horizontal, o arrastre en todas las direcciones.
source-special()
Esta acción inicia una "búsqueda inversa", abriendo el editor en la ubicación en el archivo TeX correspondiente a la ubicación del puntero en el archivo DVI. Ver la sección sobre ESPECIALES DE ORIGEN, abajo, para más información sobre esto.
wheel()
Esta acción se puede usar para desplazarse por la imagen con un ratón con rueda, donde normalmente está asociada al botón del ratón 4 (rueda arriba) o 5 (rueda abajo). La acción toma un parámetro, que indica la distancia para desplazar la imagen. Si el parámetro contiene un punto decimal, la distancia se da en unidades de rueda; de lo contrario, en píxeles. Un valor negativo desplaza hacia arriba, un valor positivo hacia abajo.
hwheel()
Esta acción se puede usar para desplazar la imagen horizontalmente con un ratón con rueda, donde normalmente está asociada al botón del ratón 6 (rueda izquierda) o 7 (rueda derecha). La acción toma un parámetro, que indica la distancia para desplazar la imagen. Si el parámetro contiene un punto decimal, la distancia se da en unidades de rueda; de lo contrario, en píxeles. Un valor negativo desplaza hacia la izquierda, un valor positivo hacia la derecha. No todos los ratones soportan el desplazamiento horizontal; esto es principalmente para touchpads, trackpads, etc.
text-selection()
Esta acción permite marcar una región rectangular de texto en el archivo DVI. El texto se coloca en el búfer de selección X y se puede pegar en otras aplicaciones (por ejemplo, editores de texto). Esto funciona de forma similar a la opción Texto plano en el diálogo de Guardar; ver la discusión allí para más información sobre problemas de codificación.
ruler()
Esta acción crea una regla en forma de cruz. Mover el ratón y mantener presionado el botón arrastra la regla y permite medir distancias en la página. Ver la sección Modo Regla para más información sobre esto.

ACCIONES NO ASOCIADAS

Las siguientes acciones no están asociadas a una tecla por defecto, pero están disponibles para personalización.

quit-confirm()
Muestra una ventana de confirmación para salir de xdvi. Para asociarla a la tecla `q' en lugar de la acción predeterminada `quit()', coloque lo siguiente en su archivo ~/.Xdefaults:

down-or-next()
Similar a unpause-or-next(): Se mueve dos tercios de pantalla hacia abajo, o a la página siguiente si ya se está en la parte inferior de la página.
shrink-to-dpi()
Esta acción toma un argumento (obligatorio). Establece el factor de reducción a un entero para aproximar el uso de fuentes con el número correspondiente de puntos por pulgada. Si xdvi está usando fuentes escaladas para p puntos por pulgada, y el argumento de shrink-to-dpi es n, entonces el factor de reducción correspondiente es la relación p/n, redondeada al entero más cercano.
user-exec()
Esta acción toma un argumento (obligatorio). Ejecuta un programa externo especificado por el argumento, que se tokeniza por espacios en blanco. La variable de entorno XDVI_FILE se establece con la ruta absoluta del archivo DVI, para que el programa pueda encontrar el DVI. Como ejemplo, para establecer la tecla `m' como una combinación de teclas que regenera el archivo DVI con `make', coloque lo siguiente en su archivo ~/.Xdefaults:

xdvi.mainTranslations: #override\
<Key>m: user-exec(xdvi-remake)\n

donde `xdvi-remake' nombra un programa en su PATH análogo a `cd $(dirname $XDVI_FILE) && make $(basename $XDVI_FILE)'. (Ver también la sección SIGNALS para una forma de hacer que xdvi recargue el archivo DVI una vez que ha sido regenerado.)

Los caracteres ideográficos de las fuentes CJKV se tratan de manera especial: todo el espacio en blanco (espacios y saltos de línea) antes y después de dichos caracteres se ignora en la cadena de búsqueda y en el archivo DVI.

Para que coincida con un carácter de nueva línea, use \n en la cadena de búsqueda; para que coincida con la cadena \n, use \\n.

Si la casilla de verificación Expresión Regular está activada, la cadena se trata como una expresión regular en sintaxis extendida POSIX, con las siguientes propiedades:

-
a? coincide con a cero o una vez.
-
a* coincide con a cero o más veces.
-
a+ coincide con a una o más veces. Tenga en cuenta que * y + son codiciosos, es decir, coinciden con la subcadena más larga posible.
-
El patrón . coincide con cualquier carácter excepto el salto de línea. Para que también coincida con un salto de línea, use `(.|\n)'.
-
a{n} coincide con a exactamente n veces.
-
a{n,m} coincide con a al menos n y no más de m veces.
-
a|b coincide con a o b. Se pueden usar corchetes para agrupar, por ejemplo: (a|b)|c.
-
La cadena que coincide con el enésimo grupo se puede referenciar mediante \n, por ejemplo, \1 se refiere a la primera coincidencia.
-
Los caracteres ^ y $ coinciden con el principio y el final de una línea, respectivamente.
-
[abc] coincide con cualquiera de las letras a, b, c, y [a-z] coincide con todos los caracteres de la a a la z.
-
Cada elemento en una expresión regular también puede ser una de las siguientes clases de caracteres POSIX: 
[[:alnum:]] [[:alpha:]] [[:blank:]] [[:cntrl:]] [[:digit:]]
[[:graph:]] [[:lower:]] [[:print:]] [[:space:]] [[:upper:]]

Estas se pueden negar insertando un símbolo ^ después del primer corchete: [^[:alpha:]]

Para más detalles sobre expresiones regulares POSIX, vea, por ejemplo, la definición del estándar IEEE Std 1003.1 disponible en línea en:

http://www.opengroup.org/onlinepubs/007904975/basedefs/xbd_chap09.html
-
Como una extensión no estándar, se pueden usar las siguientes abreviaturas similares a Perl en lugar de las clases POSIX: 
Símbolo	Significado	Clase POSIX
    \w	un carácter alfanumérico	[[:alnum:]]
    \W	un carácter no alfanumérico	[^[:alnum:]]
    \d	un carácter dígito	[[:digit:]]
    \D	un carácter no dígito	[^[:digit:]]
    \s	un carácter de espacio en blanco	[[:space:]]
    \S	un carácter no de espacio en blanco	[^[:space:]]
-
Los siguientes caracteres son símbolos especiales; deben escaparse con \ para poder hacer coincidir con ellos literalmente: ( ) [ ] . * ? + ^ $ \.
-
Las coincidencias de longitud cero se omiten silenciosamente.

-

-
distinguir mayúsculas y minúsculas (por defecto se ignoran las mayúsculas y minúsculas, es decir, una cadena de búsqueda Test coincidirá tanto con las cadenas test como con TEST en el archivo DVI);
-

Por lo tanto, las palabras con guiones aparecerán como una sola palabra para la búsqueda, y una búsqueda de dos palabras con un espacio intermedio también coincidirá con las palabras si están separadas por un salto de línea.
Tenga en cuenta que la eliminación de guiones puede causar efectos secundarios no deseados para palabras compuestas que contienen guiones y que se dividen después del guion, y que el reemplazo de los saltos de línea afecta la interpretación de las expresiones regulares de la siguiente manera: El patrón . también coincidirá con los saltos de línea, y ^ y $ ya no coincidirán con el principio y el final de las líneas. DIÁLOGO DE IMPRESIÓN

La ventana del diálogo de impresión le permite imprimir todas las páginas, páginas marcadas (haga clic o arrastre el Ratón-2 en la lista de páginas para marcarlas), o un rango de páginas. Tenga en cuenta que los números de página siempre se refieren a páginas físicas, por lo que si está utilizando la opción `usar páginas TeX', es posible que desee desactivarla para que sea más fácil determinar los números de página correctos (o evitar este problema por completo marcando las páginas a imprimir).

El valor del campo de texto Impresora se pasa a dvips a través del mecanismo -o!, como un único argumento después del `!'. Cualquier argumento listado en el campo Opciones de dvips se segmenta por espacios en blanco y se pasa como argumentos separados a dvips. Si, por ejemplo, desea imprimir el archivo 2-up, debería ingresar la siguiente cadena en el campo Impresora:

    psnup -2 -q | lpr -Plp

Hay varios recursos para personalizar el comportamiento y las entradas predeterminadas del diálogo de impresión:

dvipsPrinterString
dvipsOptionsString
Estos se pueden usar para proporcionar entradas predeterminadas para los campos de texto Impresora y Opciones de dvips, respectivamente. Si no se especifica ningún tamaño de papel en el archivo DVI (a través de, por ejemplo, \usepackage[dvips]{geometry} - este es el método preferido), el campo de entrada se inicializa con el valor actual de la opción de línea de comandos/recurso X paper. Por ejemplo, la opción -paper a4r se traduce en las opciones de dvips -t a4 -t landscape. Tenga en cuenta que no se realiza ninguna comprobación para saber si dvips realmente entiende estas opciones (las ignorará si no puede); actualmente no todas las opciones utilizadas por xdvi están cubiertas por dvips.
dvipsHangTime
dvipsFailHangTime
Estos especifican el tiempo (en milisegundos) que la ventana de progreso de impresión permanecerá abierta después de que el proceso de dvips haya terminado. El valor de dvipsHangTime se usa si el proceso termina con éxito; dvipsFailHangTime se usa si termina con un error. Los valores predeterminados son 1.5 y 5 segundos, respectivamente. Si ambos valores son negativos, la ventana permanecerá abierta hasta que sea cerrada por el usuario.

MODOS

La combinación de teclas Ctrl-m [switch-mode()] cambia entre tres enlaces de ratón diferentes, que también se pueden activar a través del menú Modos (en Motif, es un submenú del menú Opciones llamado Modo del Ratón). El modo predeterminado al arrancar se puede personalizar a través del recurso X mouseMode o la opción de línea de comandos -mousemode. El modo de arranque predeterminado es el Modo Amplificador.

Nota: Los modos se implementan cambiando la acción magnifier(). Cambiar el modo no funcionará si Ratón-1 se ha personalizado a una secuencia de acciones que no contiene la acción magnifier().

Modo Amplificador
En este modo, los botones del ratón 1 a 5 abren un "cristal de aumento" que muestra una imagen sin reducir de la página (es decir, una imagen a la resolución determinada por la opción/recurso X pixels o mfmode) en varios tamaños. Cuando se mueve el amplificador, se muestran pequeñas marcas similares a una regla en los bordes del amplificador (a menos que el recurso X delayRulers esté establecido en falso, en cuyo caso las marcas siempre se muestran). La unidad de las marcas está determinada por el recurso X tickUnits (mm por defecto). Esta unidad se puede cambiar en tiempo de ejecución a través de la acción switch-magnifier-units(), por defecto enlazada a la combinación de teclas `t' (vea la descripción de esa tecla, y de switch-magnifier-units() para más detalles sobre las unidades disponibles).
La longitud de las marcas se puede cambiar a través del recurso X tickLength (4 por defecto). Un valor cero o negativo suprime las marcas.

Si nl_langinfo() no está disponible, pero iconv sí, puedes especificar la codificación de entrada para iconv a través del recurso X textEncoding (ver la salida de **iconv -l** para una lista de codificaciones válidas). Si el soporte iconv no está disponible, solo se admiten las codificaciones ISO-8859-1 y UTF-8 (estos nombres no distinguen entre mayúsculas y minúsculas).
Ten en cuenta que UTF-8 es la única codificación que puede representar todos los caracteres (por ejemplo, símbolos matemáticos) de un archivo DVI. Si ISO-8859-1 está activo, los caracteres que no se pueden mostrar se reemplazan por `\' seguido del código hexadecimal del carácter. Para otras codificaciones, tales caracteres pueden desencadenar mensajes de error de iconv. Si un carácter no se reconoce en absoluto, se reemplaza por `?'.
Para extraer porciones más grandes de texto, alternativamente puedes guardar páginas seleccionadas o el archivo completo en formato de texto a través del menú **Archivo > Guardar como ...**.
Modo Regla
Este modo proporciona una forma sencilla de medir distancias en la página.
Cuando este modo se activa, el cursor del ratón cambia a una cruz fina, y una regla más grande en forma de cruz se dibuja en el color de resaltado en la ubicación del ratón. La regla no tiene unidades adjuntas; en su lugar, la distancia actual entre la regla y el cursor del ratón se imprime continuamente en la línea de estado.
Al activar el Modo Regla, la regla está inicialmente unida al ratón y se puede mover. Luego se puede posicionar en un lugar fijo haciendo clic en el **Mouse-1**. Después de eso, el cursor del ratón se puede mover para medir la distancia horizontal (dx), vertical (dy) y directa (más corta) (dr) entre el centro de la regla y el ratón.
Hacer clic en **Mouse-1** nuevamente moverá la regla a la posición actual del ratón, y mantener presionado **Mouse-1** arrastrará la regla.
En el Modo Regla, las siguientes combinaciones de teclas especiales extienden o reemplazan las combinaciones predeterminadas:
o
[ruler-snap-origin()] Ajusta la regla de nuevo al origen de coordenadas (0,0).
t

P
[anula declare-page-number()] Imprime las distancias que se muestran en la línea de estado en la salida estándar.

ESCALA DE GRISES Y MAPAS DE COLOR

La función de anti-aliasing en escala de grises de **xdvi** no funcionará de manera óptima si la pantalla no tiene suficientes colores disponibles. Esto puede ocurrir si otras aplicaciones están utilizando la mayor parte del mapa de colores (incluso si están minimizadas). Si esto sucede, **xdvi** imprimirá un mensaje de error y activará la opción **-copy**. Esto resultará en caracteres superpuestos que aparecerán incorrectamente; también puede resultar en una calidad de visualización deficiente si el número de colores disponibles es muy pequeño.

Típicamente, este problema ocurre en pantallas que asignan ocho bits de memoria de video por píxel. Para ver cuántos bits por píxel utiliza tu pantalla, escribe **xwininfo** en una ventana de **xterm**, y luego haz clic con el ratón en la ventana raíz cuando se te solicite. La entrada "Depth:" te dirá cuántos bits se asignan por píxel.

Las pantallas que utilizan al menos 15 bits por píxel son típicamente visuales **TrueColor**, que no tienen este problema, ya que su mapa de colores se asigna permanentemente y está disponible para todas las aplicaciones. (La clase visual también la muestra **xwininfo**.) Para más información sobre las clases visuales, consulta la documentación del Sistema de Ventanas X.

Para aliviar este problema, por lo tanto, se puede (a) ejecutar con más bits por píxel (esto puede requerir añadir más memoria de video o reemplazar la tarjeta de video), (b) cerrar otras aplicaciones que puedan estar utilizando gran parte del mapa de colores y luego reiniciar **xdvi**, o (c) ejecutar **xdvi** con la opción **-install**.

Una aplicación que a menudo es la causa de este problema es **Netscape**. En este caso, hay dos alternativas más para remediar la situación. Se puede ejecutar "netscape -install" para que **Netscape** instale un mapa de colores privado. Esto puede hacer que los colores cambien de forma extraña cuando el ratón se mueve a una ventana diferente. O, se puede ejecutar "netscape -ncols 220" para limitar **Netscape** a un número menor de colores. Un número menor asegurará que otras aplicaciones tengan más colores disponibles, pero degradará la calidad de color en la ventana de **Netscape**.

MANEJO DE FIGURAS POSTSCRIPT

**Xdvi** puede mostrar archivos de PostScript Encapsulado (EPS) incluidos en el archivo dvi. Dichos archivos se buscan primero en el directorio donde se encuentra el archivo dvi, y luego usando las reglas normales de **Kpathsea**. Sin embargo, hay una excepción: si el nombre del archivo comienza con una comilla invertida (`), los caracteres restantes en el nombre del archivo dan un comando de shell (a menudo **zcat**) que se ejecuta; su salida estándar se envía para ser interpretada como PostScript. Dado que la ejecución de comandos de shell arbitrarios con los permisos del usuario es un gran riesgo de seguridad, la evaluación de estos comandos entre comillas invertidas está deshabilitada por defecto. Debe activarse mediante la opción de línea de comandos **-allowshell**. **NOTA:** Nunca debes usar esta opción cuando veas documentos que no compilaste tú mismo. Los especiales de comillas invertidas no son necesarios para descomprimir archivos PostScript comprimidos con gzip, ya que **xdvi** puede hacerlo sobre la marcha si el nombre del archivo termina en .eps.gz o .eps.Z (y si los primeros bytes del archivo indican que el archivo está realmente comprimido). Esto es más seguro y flexible que el enfoque de comillas invertidas, ya que las reglas de búsqueda de archivos predeterminadas se aplicarán también a dichos nombres de archivo.

FUENTES TYPE 1

Usando FreeType (versión 2), xdvi puede renderizar fuentes PostScript<tm> Type 1 directamente, sin pasar por fuentes de píxeles (pk) de TeX. La ventaja de esto es que solo se necesita almacenar una tamaño de cada fuente en el disco. A menos que se use la opción -notype1fonts, xdvi intentará renderizar cada fuente usando FreeType. Solo como solución alternativa invocará un programa externo (como mktexpk, que a su vez puede invocar utilidades como ps2pk o gsftopk) para generar una fuente de píxeles a partir de la fuente Type 1. La renderización directa de las fuentes Computer Modern debería funcionar directamente, mientras que otras fuentes Type 1 como las 35 fuentes PostScript<tm> `estándar' residentes en impresoras pueden necesitar ser accesibles para su uso con xdvi, a menos que su administrador del sistema o distribución de TeX ya lo hayan hecho (lo cual es el caso, por ejemplo, para sistemas TeX Live actuales). Para las 35 fuentes residentes PostScript<tm>, xdvik buscará utilizando el archivo Fontmap proporcionado con Ghostscript, si es necesario. Además, la distribución de xdvik viene con una utilidad llamada t1mapper para hacer que estas fuentes estén disponibles para xdvi; consulte la página del manual de t1mapper(1) para obtener detalles de uso. Sin embargo, es probable que este programa se elimine en el futuro, ya que probablemente ya no sea necesario.

ESPECIALES (EN GENERAL)

A cualquiera de los especiales utilizados por xdvi se le puede anteponer los caracteres ``xdvi:''. Hacerlo no cambia el comportamiento del especial bajo xdvi, pero indica a otros controladores dvi (como, por ejemplo, dvips) que ignoren el especial.

ESPECIALES DE FUENTE

Algunas implementaciones de TeX o paquetes de macros proporcionan la funcionalidad para incluir automáticamente los llamados `especiales de fuente' en un archivo DVI. Estos contienen el número de línea, posiblemente un número de columna y el nombre del archivo de la fuente .tex. Esto permite saltar desde un archivo .dvi al lugar correspondiente en la fuente .tex y viceversa (también llamado `búsqueda inversa' - saltar desde el archivo DVI al archivo TeX también se conoce como `búsqueda inversa', y saltar desde el archivo TeX al archivo DVI como `búsqueda directa').

Para ser utilizables con xdvi, los especiales de fuente en el archivo dvi deben tener uno de los siguientes formatos:

    src:línea[ ]archivo
    src:línea:columna[ ]archivo
    src:línea
    src:línea:columna
    src::columna
Si se omite archivo o línea, se utilizan los valores más recientes. El primer especial de fuente en cada página debe estar en una de las dos primeras formas, ya que los valores predeterminados no se heredan entre páginas.

Necesitará una implementación de TeX que proporcione un interruptor adecuado (por ejemplo, -src) o un paquete de macros (como srcltx.sty o srctex.sty, disponibles en CTAN:macros/latex/contrib/supported/srcltx/) para insertar dichos especiales de fuente en el archivo DVI.

Para la búsqueda inversa, la combinación Ctrl-Ratón 1 hará que xdvi abra un editor (el valor de la opción de línea de comandos -editor) con el archivo y el número de línea de la fuente .tex. Consulte la descripción de la opción -editor para obtener más información y ejemplos de configuración.

Para la búsqueda directa, xdvi tiene una opción -sourceposition que hace que xdvi salte a la página en el archivo DVI correspondiente a la línea dada (o la línea más cercana que tenga un especial de fuente) del archivo especificado y resalte la región encontrada. Consulte la descripción de la opción -sourceposition para obtener más detalles.

Puede encontrar más información sobre la configuración de varios editores para su uso con especiales de fuente en:

http://xdvi.sourceforge.net/inverse-search.html

ESPECIALES DE TAMAÑO DE PÁGINA

xdvi acepta especiales para establecer el tamaño del papel del documento. Estos especiales deben tener la forma

    papersize=[*]ancho,alto

donde ancho y alto dan el ancho y la altura del papel, respectivamente. Cada uno de ellos debe aparecer en forma de un número decimal seguido de cualquiera de las abreviaturas de dos letras para unidades aceptadas por TeX (pt, pc, in, bp, cm, mm, dd, cc o sp). Si un asterisco (*) aparece justo antes del ancho, las mediciones se refieren a las dimensiones del documento (por ejemplo, pt en lugar de truept). Esto permite que un paquete de macros varíe el tamaño de la página según los elementos del documento; por ejemplo:

\special{xdvi: papersize=*\number\wd\mybox sp,
         \number\ht\mybox sp}

Excepto por el asterisco, este formato es compatible con dvips.

El último especial papersize en una página determina el tamaño de esa página. Si no hay ningún especial de este tipo en una página dada, se utiliza el papersize más reciente, o, si no hay especiales papersize en ninguna página anterior, se utiliza el valor del recurso paper (o la opción -paper en la línea de comandos). Por lo tanto, el tamaño del papel puede variar para diferentes páginas del archivo dvi.

Si el recurso paper (o la opción de línea de comandos -paper) comienza con un signo más (`+'), se ignorarán todos los especiales papersize en el archivo dvi.

LIMITATIONS

xdvi accepts many but not all types of PostScript specials accepted by dvips. For example, it accepts most specials generated by epsf and psfig. It does not, however, support bop-hook or eop-hook, nor does it allow PostScript commands to affect the rendering of things that are not PostScript (for example, the ``NEAT'' and rotated ``A'' examples in the dvips manual). These restrictions are due to the design of xdvi; in all likelihood they will always remain.

LaTeX2e rotation specials are currently not supported.

MetaPost files containing included text are not supported.

Xdvi's color handling doesn't support the \colorbox and \fcolorbox macros; this is not likely to change in the near future. This also means that e.g. colored tables (as created by the colortbl package) may render incorrectly: Text in colors different from the default foreground color may not be displayed. When the page is redrawn (e.g. after using the magnifier), the background color of the cells may overdraw the text.
