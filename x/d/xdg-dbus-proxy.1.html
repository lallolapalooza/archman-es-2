NOMBRE

xdg-dbus-proxy - Proxy de D-Bus

SINOPSIS

xdg-dbus-proxy [OPCIÓN...] [DIRECCIÓN RUTA [OPCIÓN...]...]

DESCRIPCIÓN

xdg-dbus-proxy es un proxy de filtrado para conexiones D-Bus. Sus argumentos son uno o más pares DIRECCIÓN-RUTA que especifican los buses a proxificar, con opciones que especifican qué filtrado aplicar.

Operación básica

El proxy escucha en el socket de dominio Unix en RUTA, y para cada cliente que se conecta al socket, abre una nueva conexión a la DIRECCIÓN D-Bus especificada (típicamente el bus de sesión) y reenvía los datos entre ambos. Durante la fase de autenticación, todos los datos se reenvían tal como se reciben, y adicionalmente para el primer byte cero, también enviamos las credenciales del proxy al bus.

Una vez que la conexión está autenticada, hay dos modos: filtrado y sin filtrar. En el modo sin filtrar, todos los mensajes se envían tal como se reciben. En el modo de filtrado, se aplica una política para determinar qué mensajes se permiten y cuáles se descartan.

El filtrado solo se aplica a las señales salientes y llamadas a métodos, y a las señales de difusión entrantes. Todas las respuestas (errores o retornos de método) se permiten una vez por una llamada a método pendiente, y nunca de otra manera.

Si un cliente recibe un mensaje de otro par en el bus, el nombre único del remitente se hace visible, por lo que el cliente puede rastrear la vida de los llamadores a través de señales NameOwnerChanged. Si un cliente llama a un método o recibe una señal de difusión de un nombre (incluso si se filtra a un subconjunto de rutas o interfaces), la política básica de ese nombre se considera (al menos) TALK, a partir de entonces.

Política

La política para el filtrado consiste en un mapeo de nombres conocidos a una política que es SEE, TALK u OWN. La política inicial por defecto es que al usuario solo se le permite TALK al bus en sí (org.freedesktop.DBus, o sin destino especificado), y TALK a su propio ID único. Todos los demás clientes son invisibles.

Aquí hay una descripción de los niveles de política (cada nivel implica los anteriores):

SEE

El nombre/ID es visible en la respuesta ListNames

El nombre/ID es visible en la respuesta ListActivatableNames

Puedes llamar a GetNameOwner sobre el nombre

Puedes llamar a NameHasOwner sobre el nombre

Ves señales NameOwnerChanged sobre el nombre

Ves señales NameOwnerChanged sobre el ID cuando el cliente se desconecta

Puedes llamar a los métodos GetXXX sobre el nombre/ID para obtener, por ejemplo, el PID del par

Recibes AccessDenied en lugar de NameHasNoOwner al enviar mensajes al nombre/ID

TALK

Puedes enviar cualquier llamada a método y señal al nombre/ID

Recibirás señales de difusión del nombre/ID (si tienes una regla de coincidencia para ellas)

Puedes llamar a StartServiceByName sobre el nombre

OWN

Se te permite llamar a RequestName/ReleaseName/ListQueuedOwners sobre el nombre

La política se especifica con las opciones --see, --talk y --own. Los nombres conocidos en estas opciones pueden tener un sufijo '.*'. Un nombre de "org.foo.*" coincide con "org.foo", "org.foo.bar" y "org.foo.bar.gazonk", pero no con "org.foobar".

Las políticas se especifican para nombres conocidos, pero también afectan al propietario de ese nombre, de modo que la política para un ID único es la unión de las políticas para todos los nombres que posee. Por razones técnicas, la política para un nombre único es "pegajosa", en el sentido de que se conserva la política más alta concedida por un nombre una vez poseído, incluso cuando el cliente libera ese nombre. Esto es imposible de evitar de forma libre de carreras en un proxy. Pero rara vez es un problema en la práctica, ya que pocos clientes liberan nombres y permanecen en el bus.

Además de la política básica SEE/TALK/OWN, es posible especificar reglas más complicadas sobre qué llamadas a métodos se pueden realizar y qué señales de difusión se pueden recibir de nombres conocidos. Una regla puede restringir las llamadas/señales permitidas a una ruta de objeto específica o a un subárbol de rutas de objeto, y puede restringir la interfaz permitida hasta un método individual o nombre de señal.

Las reglas se especifican con las opciones --call y --broadcast. La REGLA en estas opciones determina qué interfaces, métodos y rutas de objeto están permitidos. Debe tener la forma [METODO][@RUTA], donde METODO puede ser '*' o una interfaz D-Bus, posiblemente con un sufijo '.*', o un nombre de método completamente calificado, y RUTA es una ruta de objeto D-Bus, posiblemente con un sufijo '/*'.

OPCIONES

Cuando las opciones se usan varias veces, la última opción prevalece, a menos que se especifique lo contrario.

Opciones generales:

--help

Imprimir ayuda y salir

--version

Imprimir versión

--fd=FD

Escribir en FD cuando los proxies estén listos y detenerse cuando se cierre.

--args=FD

Analizar argumentos separados por nulos del descriptor de archivo dado. Esta opción se puede usar varias veces para analizar opciones de múltiples fuentes.

Opciones del proxy:

Estas opciones solo se pueden usar después de una DIRECCIÓN y se aplican al proxy para esa dirección.

--filter

Habilitar filtrado

--log

Activar registro

--sloppy-names

Hacer visibles todos los nombres únicos.

--see=NOMBRE

Establecer la política SEE para el nombre dado.

--talk= NOMBRE

Establecer la política TALK para el nombre dado.

--own= NOMBRE

Establecer la política OWN para el nombre dado.

--call=NOMBRE=REGLA

Establecer una regla para las llamadas al nombre dado.

--broadcast=NOMBRE=REGLA

Establecer una regla para las señales de difusión del nombre dado.

EJEMPLOS

$ xdg-dbus-proxy --fd=26 unix:path=/run/usr/1000/bus /run/usr/1000/.dbus-proxy/session-bus-proxy --filter --own=org.gnome.ghex.* --talk=ca.desrt.dconf --call=org.freedesktop.portal.*=* --broadcast=org.freedesktop.portal.*=@/org/freedesktop/portal/*
