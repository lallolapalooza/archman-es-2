NOMBRE

xdpdump - una herramienta simple similar a tcpdump para capturar paquetes en la capa XDP

SINOPSIS

xdpdump es una herramienta simple de captura de paquetes XDP que intenta comportarse de manera similar a tcpdump, sin embargo, no tiene capacidades de filtrado o decodificación de paquetes.

Esto se puede utilizar para depurar programas XDP que ya están cargados en una interfaz. Los paquetes se pueden volcar/inspeccionar antes de la entrada al programa XDP, o después de la salida de un programa XDP. Además, en la salida también se captura la acción XDP. Esto significa que incluso los paquetes que se descartan en la capa XDP se pueden capturar a través de esta herramienta.

xdpdump funciona adjuntando un programa de rastreo bpf a la función de entrada y/o salida de XDP que almacena el paquete crudo en un búfer de rastreo perf. Si no hay ningún programa XDP cargado, no se puede utilizar este enfoque y la herramienta utilizará una captura en vivo de libpcap para ser compatible con versiones anteriores.

Ejecutar xdpdump

La sintaxis para ejecutar xdpdump es:

Uso: xdpdump [opciones]
Herramienta XDPDump para volcar tráfico de red
Opciones:
     --rx-capture <modo>    Punto de captura para la dirección rx (valores válidos: entry,exit)
 -D, --list-interfaces      Imprime la lista de interfaces disponibles
 -i, --interface <ifname>   Nombre de la interfaz para capturar
     --perf-wakeup <eventos>  Despertar xdpdump cada <eventos> paquetes
 -p, --program-names <prog>  Programa específico al que adjuntarse
 -s, --snapshot-length <snaplen>  Bytes mínimos de paquete a capturar
     --use-pcap             Usar formato pcap antiguo para rastreos XDP
 -w, --write <archivo>       Escribir paquetes crudos al archivo pcap
 -x, --hex                  Imprimir el paquete completo en hexadecimal
 -v, --verbose              Habilitar registro detallado (-vv: más detallado)
     --version              Mostrar información de versión
 -h, --help                 Mostrar esta ayuda

Las opciones explicadas

La herramienta xdpdump intenta imitar las opciones básicas de tcpdump, pero por si acaso, a continuación se explican cada una de las opciones disponibles:

--rx-capture <modo>

Especifica dónde se captura el paquete de entrada. Ya sea en la entrada del programa XDP y/o en la salida del programa XDP. Las opciones válidas son entry, exit, o ambas entry,exit. El paquete en la salida puede ser modificado por el programa XDP. Si está interesado en ver el paquete original y el modificado, use la opción entry,exit. Con esto, cada paquete se captura dos veces. El valor predeterminado para esto es entry.

-D, --list-interfaces

Muestra una lista de las interfaces disponibles y cualquier programa XDP cargado

--load-xdp-mode

Especifica qué modo de cargador usar con la opción --load-xdp-program. Los valores válidos son 'native', que es el modo XDP nativo en el controlador por defecto, 'skb', que provoca el uso del llamado modo skb (también conocido como XDP genérico), 'hw' que provoca que el programa se descargue al hardware, o 'unspecified' que deja que el kernel elija un modo (lo que hará eligiendo el modo nativo si el controlador lo soporta, o el modo genérico de lo contrario). Tenga en cuenta que el uso de 'unspecified' puede dificultar la predicción del modo en el que terminará cargándose un programa. Por esta razón, el valor predeterminado es 'native'.

--load-xdp-program

Si no hay ningún programa XDP cargado en la interfaz, por defecto, xdpdump volverá al modo de captura en vivo de libpcap para capturar los paquetes. Alternativamente, con esta opción, puede solicitar a xdpdump que cargue un programa XDP para capturar los paquetes directamente.

-i, --interface <ifname>

Escucha en la interfaz ifname. Tenga en cuenta que si no hay ningún programa XDP cargado en la interfaz, utilizará el modo de captura en vivo de libpcap para capturar los paquetes.

--perf-wakeup <eventos>

Permite que el Kernel despierte a xdpdump una vez por cada <eventos> que se publican en el búfer de rastreo perf. Cuanto mayor sea el número, menor será el impacto en el programa XDP real. El valor predeterminado es 0, que calcula automáticamente el valor basándose en las CPUs/búferes disponibles. Use -v para ver el valor real utilizado.

-p, --program-names [<prog>|all]

Esta opción le permite capturar paquetes para un programa específico, un conjunto de programas o todos los programas XDP cargados en la interfaz. Puede especificar los nombres reales de los programas o los IDs de programa separados por comas. En el caso de que varios programas estén adjuntos con el mismo nombre, debe usar el ID del programa. Use la opción -D para ver los programas cargados y sus IDs.

Además, la API de Linux no proporciona el nombre completo de la función de entrada eBPF adjunta si tiene más de 15 caracteres. xdpdump intentará adivinar el nombre correcto de la función a partir de la información de depuración BTF disponible. Sin embargo, si existen varias funciones con el mismo prefijo, no puede elegir la correcta. Volcará las funciones disponibles, y usted puede elegir la correcta y proporcionarla con esta opción. Si tiene programas con nombres largos duplicados, también deberá especificar el ID del programa con el nombre completo. Esto se puede hacer añadiendo el id al nombre con el sufijo @<id>.

-P, --promiscuous-mode

Esta opción pone la interfaz en modo promiscuo.

-s, --snapshot-length <snaplen>

Captura snaplen bytes de un paquete en lugar de los 262144 bytes por defecto.

--use-pcap

Usa el formato pcap antiguo para los rastreos XDP. Por defecto, usará el formato PcapNG para poder almacenar varios metadatos.

-w, --write <archivo>

Escribe los paquetes crudos en un archivo pcap en lugar de imprimirlos en formato hexadecimal. Se usa la salida estándar si archivo es -.

-x, --hex

Al volcar paquetes en la consola, también imprime el contenido completo del paquete en hexadecimal.

-v, --verbose

Habilita el registro de depuración. Especifica dos veces para una verbosidad aún mayor.

--version

Muestra la información de la versión de xpdump y sale.

-h, --help

Muestra un resumen de las opciones disponibles

Ejemplos

Lo siguiente cargará el programa xdp-filter en eth0, pero no realizará ningún filtrado real:

# xdp-filter load --mode skb eth0
#
# xdpdump -D
Interfaz        Prio  Nombre del programa   Modo     ID   Etiqueta              Cadena acciones
--------------------------------------------------------------------------------------
lo                     <¡No hay programa XDP cargado!>
eth0                   xdp_dispatcher    skb      10651 d51e469e988d81da
 =>              10     xdpfilt_alw_all           10669 0b394f43ab24501c  XDP_PASS

Ahora podemos probar xdpdump:

NAME

xdpdump — capture and display XDP packets

SYNOPSIS

xdpdump -i interface [-c count] [-d] [-D] [-f] [-F filter] [-l logfile] [-n] [-q] [-s snaplen] [-t timestamp_format] [-v] [-w output_file] [-x]

The options explained

xdpdump is a tool to capture packets processed by XDP (eXpress Data Path) programs and display them in a human-readable format. It uses the BPF subsytem (specifically, tracepoints or kprobes) to hook into the XDP path and capture packets. The captured packets can be displayed directly, saved to a file, or piped to other tools like tcpdump or tshark.

-i interface
Specifies the network interface to capture packets from. This is a required option.
-c count
Stop capturing packets after receiving count packets.
-d
Dump XDP programs loaded on the interface.
-D
Dump all XDP programs loaded on all interfaces.
-f
Follow packet forwarding. This option is useful when capturing packets that are being forwarded between interfaces.
-F filter
Apply a packet filter. The filter syntax is the same as used by tcpdump.
-l logfile
Write captured packets to the specified logfile. If the -w option is also specified, the packets will be written to both files.
-n
Do not resolve hostname, port numbers, or usernames.
-q
Quiet mode. Suppress the printing of captured packets to standard output. This is useful when only writing to a file or piping to another tool.
-s snaplen
Set the snapshot length (the maximum number of bytes to capture per packet). The default is 262144 bytes.
-t timestamp_format
Set the timestamp format. Possible values are:
  • r: Relative timestamps (default).
  • a: Absolute timestamps.
-v
Verbose mode. Print more detailed information about the captured packets.
-w output_file
Write captured packets to the specified output_file in pcap format. If - is specified as the filename, the output will be written to standard output.
-x
Dump captured packets in hexadecimal format.
