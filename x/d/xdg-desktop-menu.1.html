NOMBRE

xdg-desktop-menu - herramienta de línea de comandos para (des)instalar elementos del menú de escritorio

SINÓPSIS

xdg-desktop-menu install [--noupdate] [--novendor] [--mode modo] archivo-directorio(s) archivo-escritorio(s)

xdg-desktop-menu uninstall [--noupdate] [--mode modo] archivo-directorio(s) archivo-escritorio(s)

xdg-desktop-menu forceupdate [--mode modo]

xdg-desktop-menu {--help | --manual | --version}

DESCRIPCIÓN

El programa xdg-desktop-menu se puede utilizar para instalar nuevas entradas de menú en el menú de aplicaciones del escritorio.

El menú de aplicaciones funciona de acuerdo con la Especificación de Menú de Escritorio XDG en http://www.freedesktop.org/wiki/Specifications/menu-spec

COMANDOS

install

Instala una o más aplicaciones en un submenú del sistema de menú del escritorio.

archivo-escritorio: Un archivo de escritorio representa una única entrada de menú en el menú. Los archivos de escritorio se definen por la Especificación de Archivo de Entrada de Escritorio de freedesktop.org. Los aspectos más importantes de los archivos *.desktop se resumen a continuación.

Las entradas del menú se pueden agregar al sistema de menú de dos maneras diferentes. Pueden agregarse a un submenú predefinido en el sistema de menú basándose en una o más palabras clave de categoría, o pueden agregarse a un nuevo submenú.

Para agregar una entrada de menú a un submenú predefinido, el archivo de escritorio que representa la entrada de menú debe tener una entrada Categories= que liste una o más palabras clave. El elemento del menú se incluirá en un submenú apropiado basándose en las palabras clave incluidas.

Para agregar elementos de menú a un nuevo submenú, los archivos de escritorio deben ir precedidos por un archivo de directorio que describa el submenú. Si se especifican varios archivos de escritorio, todas las entradas se agregarán al mismo menú. Si las entradas se instalan en un menú que se ha creado con una llamada anterior a xdg-desktop-menu, las entradas se instalarán además de las ya existentes.

archivo-directorio: El archivo *.directory indicado por archivo-directorio representa un submenú. El archivo de directorio proporciona el nombre y el icono de un submenú. El nombre del archivo de directorio se utiliza para identificar el submenú.

Si se proporcionan varios archivos de directorio, cada archivo representará un submenú dentro del menú que lo precede, creando una jerarquía de menús anidada (sub-sub-menús). Los elementos del menú se agregarán al último submenú.

Los archivos de directorio siguen la sintaxis definida por la Especificación de Entrada de Escritorio de freedesktop.org.

uninstall

Elimina aplicaciones o submenús del sistema de menú del escritorio previamente instalados con xdg-desktop-menu install.

Un submenú y su archivo de directorio asociado solo se eliminan cuando el submenú ya no contiene ningún elemento de menú.

forceupdate

Fuerza una actualización del sistema de menú.

Este comando solo es útil si la última llamada a xdg-desktop-menu incluyó la opción --noupdate.

OPCIONES

--noupdate

Posponer la actualización del sistema de menú. Si se realizan varios cambios en el sistema de menú en secuencia, esta bandera se puede usar para indicar que seguirán cambios adicionales y que no es necesario actualizar el sistema de menú de inmediato.

--novendor

Normalmente, xdg-desktop-menu verifica que los archivos *.directory y *.desktop a instalar tengan un prefijo de proveedor. Esta opción se puede usar para deshabilitar esa verificación.

Un prefijo de proveedor consiste en caracteres alfabéticos ([a-zA-Z]) y se termina con un guion ("-"). Se anima a las empresas y organizaciones a utilizar una palabra o frase, preferiblemente el nombre de la organización, para la cual poseen una marca registrada como prefijo de proveedor. El propósito del prefijo de proveedor es evitar conflictos de nombres.

--mode modo

modo puede ser user o system. En modo de usuario, el archivo se instala/desinstala solo para el usuario actual. En modo de sistema, el archivo se instala/desinstala para todos los usuarios del sistema. Normalmente, solo root puede instalar en modo de sistema.

El valor predeterminado es usar el modo de sistema cuando lo llama root y usar el modo de usuario cuando lo llama un usuario no root.

--help

Muestra el resumen del comando.

--manual

Muestra esta página del manual.

--version

Muestra la información de la versión de xdg-utils.

ARCHIVOS DE ESCRITORIO

Un elemento de aplicación en el menú de aplicaciones se representa mediante un archivo *.desktop. Un archivo *.desktop consta de una cabecera [Desktop Entry] seguida de varias líneas Clave=Valor.

Un archivo *.desktop puede proporcionar un nombre y una descripción para una aplicación en varios idiomas diferentes. Esto se hace agregando un código de idioma como se usa en LC_MESSAGES entre corchetes detrás de la Clave. De esta manera, se pueden especificar diferentes valores para la misma Clave dependiendo del idioma seleccionado actualmente.

Las siguientes claves se utilizan a menudo:

Type=Application

Este es un campo obligatorio que indica que el archivo *.desktop describe un lanzador de aplicaciones.

Name=Nombre de la Aplicación

El nombre de la aplicación. Por ejemplo, Mozilla

GenericName=Nombre Genérico

Una descripción genérica de la aplicación. Por ejemplo, Navegador Web

Comment=Comentario

Campo opcional para especificar una información sobre la aplicación. Por ejemplo, Visita sitios web en Internet

Icon=Archivo de Icono

El icono a utilizar para la aplicación. Puede ser una ruta absoluta a un archivo de imagen o un nombre de icono. Si se proporciona un nombre de icono, se realiza una búsqueda de imagen por nombre en el tema de iconos actual del usuario. El comando xdg-icon-resource se puede utilizar para instalar archivos de imagen en temas de iconos. La ventaja de usar un nombre de icono en lugar de una ruta absoluta es que con un nombre de icono, el icono de la aplicación se puede proporcionar en varios tamaños diferentes, así como en varios estilos temáticos.

Exec=Línea de Comandos

La línea de comandos para iniciar la aplicación. Si la aplicación puede abrir archivos, se debe especificar el marcador %f. Cuando se arrastra un archivo al lanzador de aplicaciones, %f se reemplaza con la ruta del archivo del archivo arrastrado. Si se pueden especificar varios archivos en la línea de comandos, se debe usar el marcador %F en lugar de %f. Si la aplicación es capaz de abrir URLs además de archivos locales, se pueden usar %u o %U en lugar de %f o %F.

Categories=Categorías

Una lista de categorías separadas por punto y coma. Una categoría es una palabra clave que describe y clasifica la aplicación. Por defecto, las aplicaciones se organizan en el menú de aplicaciones basándose en la categoría. Cuando los elementos del menú se asignan explícitamente a un nuevo submenú, no es necesario enumerar ninguna categoría.

Al usar categorías, se recomienda incluir una de las siguientes categorías: AudioVideo, Development, Education, Game, Graphics, Network, Office, Settings, System, Utility.

Consulte el Apéndice A de la Especificación de Menú de Escritorio XDG para obtener información sobre categorías adicionales: http://standards.freedesktop.org/menu-spec/menu-spec-1.0.html#category-registry

MimeType=Tipos MIME

Una lista de tipos MIME separados por punto y coma. Este campo se utiliza para indicar qué tipos de archivo puede abrir la aplicación.

Para obtener una descripción completa del formato de archivo *.desktop, visite http://www.freedesktop.org/wiki/Specifications/desktop-entry-spec

NAME

xdg-desktop-menu - add and remove application menu entries

SYNOPSIS

xdg-desktop-menu [options] command

DESCRIPTION

The xdg-desktop-menu utility can be used to install and uninstall menu entries for applications. The menu entries are defined by desktop files according to the Freedesktop.org Desktop Entry Specification.

COMMANDS

install
Installs one or more desktop files or directory files. The files are copied into the user's menu directory (see XDG Base Directory Specification) or to the system-wide menu directory, depending on the installation mode.
uninstall
Uninstalls one or more desktop files or directory files. The files are removed from the user's menu directory or the system-wide menu directory.
forceupdate
Forces an update of the desktop menu. This command is normally not needed as updates are triggered automatically when files are installed or uninstalled.

OPTIONS

--mode=mode
Overrides the installation mode. Valid values are user and system. If not specified, the mode is determined by the installation location of the menu files. If the menu files are installed in the user's menu directory, the mode is user. If they are installed in the system-wide menu directory, the mode is system. If neither of these are found, the mode defaults to user.
--noupdate
Suppresses the automatic update of the desktop menu after installing or uninstalling files. This can be useful if multiple operations are performed and a single manual update is desired afterwards using forceupdate.
-v, --verbose
Enable verbose output.
-h, --help
Show help message and exit.
-V, --version
Show version information and exit.

DESKTOP FILES

Desktop files are INI-style files with a [Desktop Entry] header followed by several Key=Value lines.

The following keys are relevant for applications:

Type=Application

This is a mandatory field that indicates that the .desktop file describes an application.

Name=Application Name

The name of the application. For example Mozilla Firefox. This key can be followed by a language code in square brackets to specify the name in different languages. For example: Name[nl]=Mozilla Vuursprinkhaaan.

Comment=Comment

An optional field to specify a tooltip for the application. This key can also be followed by a language code.

Exec=Command

The command to execute to start the application. It is recommended to specify the command with its absolute path or at least ensure that it can be found in the system's PATH.

Icon=Icon File

The icon to use for the application. This can be an absolute path to an image file or an icon-name. See the description for the Icon key in DIRECTORY FILES.

Categories=Category List

A list of categories the application belongs to, separated by semicolons. For a full list of predefined categories please refer to the Freedesktop.org Menu Specification. For example: Categories=Network;WebDevelopment;.

DIRECTORY FILES

Directory files are used to define submenus. They are also INI-style files with a [Desktop Entry] header followed by several Key=Value lines.

A *.directory file can provide a title (name) for the submenu in several different languages. This is done by adding a language code as used by LC_MESSAGES in square brackets behind the Key. This way one can specify different values for the same Key depending on the currently selected language.

The following keys are relevant for submenus:

Type=Directory

This is a mandatory field that indicates that the *.directory file describes a submenu.

Name=Menu Name

The title of submenu. For example Mozilla

Comment=Comment

Optional field to specify a tooltip for the submenu.

Icon=Icon File

The icon to use for the submenu. This can either be an absolute path to an image file or an icon-name. If an icon-name is provided an image lookup by name is done in the user's current icon theme. The xdg-icon-resource command can be used to install image files into icon themes. The advantage of using an icon-name instead of an absolute path is that with an icon-name the submenu icon can be provided in several different sizes as well as in several differently themed styles.

ENVIRONMENT VARIABLES

xdg-desktop-menu honours the following environment variables:

XDG_UTILS_DEBUG_LEVEL

Setting this environment variable to a non-zero numerical value makes xdg-desktop-menu do more verbose reporting on stderr. Setting a higher value increases the verbosity.

XDG_UTILS_INSTALL_MODE

This environment variable can be used by the user or administrator to override the installation mode. Valid values are user and system.

EXIT CODES

An exit code of 0 indicates success while a non-zero exit code indicates failure. The following failure codes can be returned:

1

Error in command line syntax.

2

One of the files passed on the command line did not exist.

3

A required tool could not be found.

4

The action failed.

5

No permission to read one of the files passed on the command line.

SEE ALSO

xdg-desktop-icon(1), xdg-icon-resource(1), xdg-mime(1), Desktop entry specification[1], Desktop menu specification[2]

EXAMPLES

The company ShinyThings Inc. has developed an application named "WebMirror" and would like to add it to the application menu. The company will use "shinythings" as its vendor id. In order to add the application to the menu there needs to be a .desktop file with a suitable Categories entry:

shinythings-webmirror.desktop:
  [Desktop Entry]
  Encoding=UTF-8
  Type=Application
  Exec=webmirror
  Icon=webmirror
  Name=WebMirror
  Name[nl]=WebSpiegel
  Categories=Network;WebDevelopment;

Now the xdg-desktop-menu tool can be used to add the shinythings-webmirror.desktop file to the desktop application menu:

xdg-desktop-menu install ./shinythings-webmirror.desktop

Note that for the purpose of this example the menu items are available in two languages, English and Dutch. The language code for Dutch is nl.

In the next example the company ShinyThings Inc. will add its own submenu to the desktop application menu consisting of a "WebMirror" menu item and a "WebMirror Admin Tool" menu item.

First the company needs to create two .desktop files that describe the two menu items. Since the items are to be added to a new submenu it is not necessary to include a Categories= line:

shinythings-webmirror.desktop:
  [Desktop Entry]
  Encoding=UTF-8
  Type=Application
  Exec=webmirror
  Icon=shinythings-webmirror
  Name=WebMirror
  Name[nl]=WebSpiegel
shinythings-webmirror-admin.desktop:
  [Desktop Entry]
  Encoding=UTF-8
  Type=Application
  Exec=webmirror-admintool
  Icon=shinythings-webmirror-admintool
  Name=WebMirror Admin Tool
  Name[nl]=WebSpiegel Administratie Tool

In addition a .directory file needs to be created to provide a title and icon for the sub-menu itself:

shinythings-webmirror.directory:
  [Desktop Entry]
  Encoding=UTF-8
  Icon=shinythings-webmirror-menu
  Name=WebMirror
  Name[nl]=WebSpiegel

These file can now be installed with:

xdg-desktop-menu install ./shinythings-webmirror.directory \
      ./shinythings-webmirror.desktop ./shinythings-webmirror-admin.desktop

The menu entries could also be installed one by one:

xdg-desktop-menu install --noupdate ./shinythings-webmirror.directory \
      ./shinythings-webmirror.desktop
xdg-desktop-menu install --noupdate ./shinythings-webmirror.directory \
      ./shinythings-webmirror-admin.desktop
xdg-desktop-menu forceupdate

Although the result is the same it is slightly more efficient to install all files at the same time.

The *.desktop and *.directory files reference icons with the names webmirror, webmirror-admin and webmirror-menu which should also be installed. In this example the icons are installed in two different sizes, once with a size of 22x22 pixels and once with a size of 64x64 pixels:

xdg-icon-resource install --size 22 ./wmicon-22.png shinythings-webmirror
xdg-icon-resource install --size 22 ./wmicon-menu-22.png shinythings-webmirror-menu
xdg-icon-resource install --size 22 ./wmicon-admin-22.png shinythings-webmirror-admin
xdg-icon-resource install --size 64 ./wmicon-64.png shinythings-webmirror
xdg-icon-resource install --size 64 ./wmicon-menu-64.png shinythings-webmirror-menu
xdg-icon-resource install --size 64 ./wmicon-admin-64.png shinythings-webmirror-admin
