xdp-bench(8) Una herramienta simple de benchmarking XDP xdp-bench(8)

NOMBRE

XDP-bench - una herramienta simple de benchmarking XDP

SINOPSIS

XDP-bench es una utilidad de benchmarking para ejercitar los diferentes modos de operación de XDP. Está pensada como un programa simple que demuestra los diversos modos de operación; estos incluyen descartar paquetes, reenvío hairpin (usando el código de retorno XDP_TX) y redirección utilizando las diversas facilidades de redirección de paquetes en el kernel.

Los modos drop y TX admiten varias opciones para controlar si los datos del paquete se tocan (leen o escriben) antes de descartarlos o transmitirlos. Los modos de redirección admiten el uso de la ayuda simple bpf_redirect basada en ifindex, la ayuda bpf_redirect_map usando un cpumap como destino, bpf_redirect_map usando un devmap como destino, y el modo de broadcast del devmap que permite redirigir a múltiples dispositivos.

Hay más información sobre el significado de la salida tanto en el modo de salida predeterminado (conciso) como en el extendido, en la sección Descripción del formato de salida a continuación.

Ejecutando xdp-bench

La sintaxis para ejecutar xdp-bench es:

Uso: xdp-bench COMANDO [opciones]
COMANDO puede ser uno de:
       drop           - Descarta todos los paquetes en una interfaz
       pass           - Pasa todos los paquetes a la pila de red
       tx             - Transmite paquetes de vuelta a una interfaz (reenvío hairpin)
       redirect       - Redirección XDP usando la función de ayuda bpf_redirect()
       redirect-cpu   - Redirección XDP por CPU usando BPF_MAP_TYPE_CPUMAP
       redirect-map   - Redirección XDP usando BPF_MAP_TYPE_DEVMAP
       redirect-multi - Redirección múltiple XDP usando BPF_MAP_TYPE_DEVMAP y el flag BPF_F_BROADCAST

Cada comando y sus opciones se explican a continuación. O use xdp-bench COMANDO --help para ver las opciones de cada comando.

El comando DROP

En este modo, xdp-bench instala un programa XDP en una interfaz que simplemente descarta todos los paquetes. Hay opciones para controlar qué hacer con el paquete antes de descartarlo (tocar los datos del paquete o no), así como qué estadísticas recopilar. Este es un benchmark básico para el rendimiento base (mejor caso) de XDP en una interfaz.

La sintaxis para el comando drop es:

xdp-bench drop [opciones] <nombre_interfaz>

Donde <nombre_interfaz> es el nombre de la interfaz en la que se debe instalar el programa XDP.

Las opciones admitidas son:

-p, --packet-operation <ACCION>

Especifica qué operación se debe realizar en el paquete antes de descartarlo. Las siguientes acciones están disponibles:

no-touch		- Descarta el paquete sin tocar los datos del paquete
read-data		- Lee un campo en la cabecera del paquete antes de descartar
parse-ip		- Analiza el campo de la cabecera IP antes de descartar
swap-macs		- Intercambia las direcciones MAC de origen y destino antes de descartar

Si se toca o no el paquete antes de descartarlo puede tener un impacto significativo en el rendimiento, ya que esto requiere traer los datos del paquete a la caché de la CPU (y vaciarla de vuelta si se escribe).

El valor predeterminado para esta opción es no-touch.

-l, --load-mode <MODO>

Especifica qué mecanismo debe usar xdp-bench para cargar (y almacenar) los datos del paquete. Los siguientes modos están disponibles:

dpa		- Usa el acceso directo a paquetes (Direct Packet Access) tradicional desde el programa XDP
load-bytes	- Usa las funciones de ayuda xdp_load_bytes() y xdp_store_bytes()

Esto se puede usar para comparar el rendimiento de los diversos modos de acceso a paquetes admitidos por el kernel.

El valor predeterminado para esta opción es dpa.

-r, --rxq-stats

Si se establece, el programa XDP también recopilará estadísticas sobre la cola de recepción (receive queue) en la que se recibió cada paquete. Esto se muestra en el modo de salida extendido junto con datos por CPU (que, dependiendo de la configuración del hardware, pueden ser equivalentes o no).

-i, --interval <SEGUNDOS>

Establece el intervalo de sondeo para recopilar todas las estadísticas y mostrarlas en la salida. La unidad del intervalo es en segundos.

-e, --extended

Inicia xdp-bench en modo de salida "extendido". Si no se establece, xdp-bench comenzará en modo "conciso". El modo de salida se puede cambiar presionando C-c mientras el programa se está ejecutando. Ver también la sección Descripción del formato de salida a continuación.

-m, --mode

Selecciona el modo del programa XDP (nativo o skb). Tenga en cuenta que el modo XDP nativo es el predeterminado, y cargar el programa de redirección en modo skb no es eficiente ni recomendable. Sin embargo, esta opción es útil si el controlador de la interfaz carece de soporte XDP nativo, o simplemente para probar la herramienta.

-v, --verbose

Habilita el registro detallado. Suminístrelo dos veces para habilitar el registro detallado de las bibliotecas subyacentes libxdp y libbpf.

--version

Muestra la versión de la aplicación y sale.

-h, --help

Muestra un resumen de las opciones disponibles

Formato de salida

Xdp-bench muestra estadísticas de rendimiento en tiempo real. El formato de salida se puede cambiar de conciso a extendido (y viceversa) presionando C-c.

Salida concisa

La salida concisa muestra la tasa de paquetes por segundo (PPS) y la tasa de bits por segundo (bps). También muestra el porcentaje de uso de CPU.

Time (s)  IFACE         PPS     BITS/s  %CPU
 0.100    eth0       14.88 M    11.90 Gb  0.50
 0.200    eth0       14.88 M    11.90 Gb  0.50
 ...

Salida extendida

La salida extendida muestra información más detallada, incluyendo estadísticas por CPU y por cola de recepción (si se habilita la opción -r).

Time (s)  IFACE      CPU RXQ     PPS     BITS/s  %CPU   Drops  XDP Drops  XDP Drps OK
 0.100    eth0         0   -    14.88 M   11.90 Gb  0.50      0          0           0
 0.100    eth0         1   -    14.88 M   11.90 Gb  0.50      0          0           0
 ...
 1.000    eth0         -   0    14.88 M   11.90 Gb  0.50      0          0           0
 1.000    eth0         -   1    14.88 M   11.90 Gb  0.50      0          0           0

En la salida extendida:

  • CPU: El número de CPU que procesó el paquete. Si no se recopilan estadísticas por CPU, se muestra un guion (-).

  • RXQ: El índice de la cola de recepción. Si no se recopilan estadísticas por cola de recepción, se muestra un guion (-).

  • PPS: Paquetes por segundo.

  • BITS/s: Bits por segundo.

  • %CPU: Porcentaje de uso de CPU.

  • Drops: Paquetes descartados por el controlador de red.

  • XDP Drops: Paquetes descartados por el programa XDP (código de retorno XDP_DROP).

  • XDP Drps OK: Paquetes que fueron manejados por el programa XDP y redirigidos correctamente (código de retorno XDP_TX o XDP_REDIRECT). Esto es útil para medir la sobrecarga de XDP.

El comando REDIRECT-MAP

En este modo, xdp-bench configura la redirección de paquetes entre dos interfaces proporcionadas en la línea de comandos utilizando el ayudante BPF bpf_redirect_map() activado en la recepción de paquetes en la interfaz de entrada, utilizando un devmap como su objetivo.

La sintaxis para el comando redirect-map es:

xdp-bench redirect-map [opciones] <ifname_in> <ifname_out>

Donde <ifname_in> es el nombre de la interfaz de entrada desde donde se redirigirán los paquetes a la interfaz de salida <ifname_out>.

Las opciones admitidas son:

-X, --load-egress

Carga un programa en la entrada del devmap utilizada para la redirección, de modo que se invoque después de que el paquete se redirige al dispositivo de destino, antes de que se transmita fuera de la interfaz de salida. El programa remoto actualizará los datos del paquete para que su dirección MAC de origen coincida con la de la interfaz de destino.

-i, --interval <SEGUNDOS>

Establece el intervalo de sondeo para recopilar todas las estadísticas y mostrarlas en la salida. La unidad del intervalo está en segundos.

-s, --stats

Habilita estadísticas para redireccionamiento exitoso. Esta opción conlleva una sobrecarga de rastreo por paquete para registrar todas las redirecciones exitosas.

-e, --extended

Inicia xdp-bench en modo de salida "extendido". Si no se establece, xdp-bench se iniciará en modo "conciso". El modo de salida se puede cambiar presionando C-$ mientras el programa se está ejecutando. Consulte también la sección Descripción del Formato de Salida a continuación.

-m, --mode

Selecciona el modo del programa XDP (nativo o skb). Tenga en cuenta que el modo XDP nativo es el predeterminado, y cargar el programa de redireccionamiento en modo skb no es eficiente ni recomendable. Sin embargo, esta opción es útil si el controlador de la interfaz carece de soporte XDP nativo, o al simplemente probar la herramienta.

-v, --verbose

--version

Muestra la versión de la aplicación y sale.

El comando REDIRECT-MULTI

En este modo, xdp-bench configura la redirección de paquetes de uno a muchos entre las interfaces proporcionadas en la línea de comandos, utilizando el ayudante BPF bpf_redirect_map activado en la recepción de paquetes en la interfaz de entrada, utilizando un devmap como su objetivo. El paquete se transmite a todas las interfaces de salida especificadas en la línea de comandos, utilizando la función de difusión de paquetes de devmap.

La sintaxis para el comando redirect-multi es:

xdp-bench redirect-multi [opciones] <ifname_in> <ifname_out1> ... <ifname_outN>

Donde <ifname_in> es el nombre de la interfaz de entrada desde donde se redirigirán los paquetes a una o más interfaces de salida.

Las opciones admitidas son:

-X, --load-egress

Descripción del Formato de Salida

Por defecto, las estadísticas de éxito de redireccionamiento están deshabilitadas; use --stats para habilitarlas. El modo de salida conciso es el predeterminado; el modo de salida extendido se puede activar utilizando la opción de línea de comandos --extended.

SIGQUIT (Ctrl + \) se puede usar para cambiar el modo dinámicamente en tiempo de ejecución.

El modo conciso muestra como máximo los siguientes campos:

rx/s		Número de paquetes recibidos por segundo
redir/s	Número de paquetes redirigidos exitosamente por segundo
err,drop/s	Recuento agregado de errores por segundo (incluidos paquetes descartados cuando no se usa el comando drop)
xmit/s	Número de paquetes transmitidos en el dispositivo de salida por segundo

El modo de salida extendido muestra como máximo los siguientes campos:

CAMPO		  DESCRIPCIÓN
receive	       Muestra el número de paquetes recibidos y los errores encontrados
                        Cada vez que ocurre un error o un paquete es descartado, los detalles de los errores por CPU
                        y las estadísticas de descarte se expandirán en línea en el modo conciso.

                                        drop/s		- Paquetes descartados por segundo

                       Los errores encontrados se expanden bajo el campo redirect_err

                                        redir/s		- Paquetes redirigidos exitosamente por segundo

                        El errno se expande bajo este campo con el recuento por CPU
                       Los errores reconocidos son:
