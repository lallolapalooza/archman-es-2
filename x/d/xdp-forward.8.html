NOMBRE

xdp-forward - el plano de reenvío XDP

SINOPSIS

xdp-forward es un plano de reenvío XDP, que acelerará el reenvío de paquetes usando XDP. Para usarlo, simplemente cárguelo en el conjunto de interfaces para acelerar el reenvío entre ellas. El componente de espacio de usuario de xdp-forward configurará y cargará programas XDP en esas interfaces, y reenviará paquetes entre ellas usando XDP_REDIRECT, utilizando la tabla de enrutamiento del kernel o la tabla de flujos netfilter para determinar el destino de cada paquete.

Cualquier paquete que xdp-forward no sepa cómo reenviar se pasará a la pila de red y será manejado por el kernel como de costumbre. Dependiendo del modo en que se cargue xdp-forward, esto lleva a diferentes comportamientos de reenvío. Consulte la sección sobre Modos de operación a continuación.

Ejecutando xdp-forward

La sintaxis para ejecutar xdp-forward es:

xdp-forward COMANDO [opciones]
Donde COMANDO puede ser uno de:
       load        - Cargar el plano de reenvío XDP
       unload      - Descargar el plano de reenvío XDP
       help        - mostrar la lista de comandos disponibles

Cada comando y sus opciones se explican a continuación. O use xdp-forward COMANDO --help para ver las opciones de cada comando.

El comando LOAD

El comando load carga el plano de reenvío XDP en una lista de interfaces.

La sintaxis del comando load es:

xdp-forward load [opciones] <ifname...>

Donde <ifname...> es el nombre del conjunto de interfaces entre las cuales reenviar paquetes. Se cargará un programa XDP en cada interfaz, configurado para reenviar paquetes a todas las demás interfaces del conjunto (utilizando la tabla de enrutamiento del kernel para determinar la interfaz de destino de cada paquete).

Las opciones compatibles son:

-f, --fwd-mode <modo>

Especifica en qué modo de reenvío debe operar xdp-forward. Dependiendo del modo seleccionado, xdp-forward realizará el reenvío de diferentes maneras, lo que puede llevar a comportamientos diferentes, incluyendo qué subconjunto de la configuración del kernel (como las reglas de firewall) se respeta durante el reenvío. Consulte la sección MODOS DE REENVÍO a continuación para una descripción completa de cada modo.

-F, --fib-mode <modo>

Especifica cómo xdp-forward realiza la búsqueda en la tabla de enrutamiento del kernel. Consulte la sección MODOS FIB a continuación para una descripción completa de cada modo.

-m, --mode <modo>

Especifica en qué modo se cargará el programa XDP. Los valores válidos son 'native', que es el modo XDP nativo del controlador por defecto, 'skb', que causa el uso del llamado modo skb (también conocido como XDP genérico), 'hw' que causa que el programa se descargue al hardware, o 'unspecified' que deja que el kernel elija un modo (lo hará eligiendo el modo nativo si el controlador lo soporta, o el modo genérico en caso contrario). Tenga en cuenta que usar 'unspecified' puede dificultar predecir en qué modo terminará cargándose un programa. Por esta razón, el valor por defecto es 'native'. Tenga en cuenta que el hardware con soporte para el modo 'hw' es raro: las tarjetas Solarflare (que usan el controlador 'sfc') son los únicos dispositivos con soporte para esto en el kernel principal de Linux.

-v, --verbose

Habilitar registro de depuración. Especifique dos veces para una mayor verborrea.

-h, --help

Mostrar un resumen de las opciones disponibles

El comando UNLOAD

El comando unload se utiliza para descargar programas de una interfaz.

La sintaxis del comando unload es:

xdp-forward unload [opciones] <ifname...>

Donde <ifname...> es la lista de interfaces de las cuales descargar el plano de reenvío XDP. Tenga en cuenta que, si bien xdp-forward examinará los programas XDP cargados en cada interfaz y se asegurará de descargar solo su propio programa, no verificará que la lista de interfaces proporcionadas sea la misma que la proporcionada durante la carga. Como tal, es posible realizar una descarga parcial proporcionando una lista diferente de interfaces, lo que puede generar un comportamiento inesperado.

Las opciones compatibles son:

-v, --verbose

Habilitar registro de depuración. Especifique dos veces para una mayor verborrea.

-h, --help

Mostrar un resumen de las opciones disponibles

MODOS DE REENVÍO

La utilidad xdp-forward soporta los siguientes modos de reenvío (seleccionados por el parámetro --fwd-mode de xdp-forward load.

fib (por defecto)

En el modo de reenvío fib, xdp-forward realizará una búsqueda en la tabla de enrutamiento del kernel (o FIB) para cada paquete, y reenviará paquetes entre las interfaces configuradas basándose en el resultado de la búsqueda. Cualquier paquete en el que la búsqueda falle se pasará a la pila. Esto incluye paquetes que requieren descubrimiento de vecinos para el siguiente salto, lo que significa que los paquetes pasarán periódicamente por la pila del kernel para el descubrimiento del siguiente salto (inicialmente, y cuando la entrada del siguiente salto expire).

Tenga en cuenta que no se realizan comprobaciones distintas de la búsqueda FIB; en particular, esto omite completamente el subsistema netfilter, por lo que las reglas de firewall no se comprobarán antes del reenvío.

flowtable

El modo de operación flowtable descarga la lógica de la tabla de flujos netfilter del espacio de usuario en la capa XDP si la tabla de flujos de hardware no está disponible. Actualmente, xdp-forward puede descargar solo entradas de tabla de flujos netfilter TCP o UDP a XDP. Se supone que el usuario configura la tabla de flujos por separado.

MODOS FIB

La utilidad xdp-forward soporta los siguientes modos fib (seleccionados por el parámetro --fib-mode de xdp-forward load.

full (por defecto)

En el modo de operación full, xdp-forward realizará una búsqueda completa en la tabla de enrutamiento del kernel (o FIB) para cada paquete, y reenviará paquetes entre las interfaces configuradas basándose en el resultado de la búsqueda. En particular, aplicará cualquier regla de enrutamiento de políticas configurada por el usuario.

direct

El modo direct funciona como full, excepto que pasa el flag BPF_FIB_LOOKUP_DIRECT a la rutina de búsqueda FIB. Esto significa que se omitirán las reglas de enrutamiento de políticas configuradas durante la búsqueda, lo que puede mejorar el rendimiento (pero obviamente no obedecerá la política de esas reglas).

Ejemplos

Para habilitar la descarga de tabla de flujos para tráfico tcp y udp entre las NICs n0 y n1, emita los siguientes comandos:

#nft -f /dev/stdin <<EOF
table inet filter {
    flowtable ft {
        hook ingress priority filter
        devices = { n0, n1 }
    }
    chain forward {
        type filter hook forward priority filter
        meta l4proto { tcp, udp } flow add @ft
    }
}
EOF
#xdp-forward load -f flowtable n0 n1
