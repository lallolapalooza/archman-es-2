xdp-trafficgen(8) Un generador de tráfico basado en XDP xdp-trafficgen(8)

NOMBRE

XDP-trafficgen - un generador de tráfico basado en XDP

SINOPSIS

XDP-trafficgen es un generador de paquetes que utiliza el subsistema XDP del kernel para generar paquetes y transmitirlos a través de una interfaz de red. Los paquetes se generan dinámicamente y se transmiten en el kernel, lo que permite un alto rendimiento (millones de paquetes por segundo por núcleo).

XDP-trafficgen admite la generación de tráfico UDP con puertos de destino fijos o dinámicos, y también tiene soporte básico para generar tráfico TCP ficticio en un solo flujo.

Ejecutando xdp-traffigen

La sintaxis para ejecutar xdp-trafficgen es:

Uso: xdp-trafficgen COMANDO [opciones]
COMANDO puede ser uno de:
       udp         - ejecutar en modo UDP
       tcp         - ejecutar en modo TCP
       probe       - probar soporte del kernel

Cada comando y sus opciones se explican a continuación. O use xdp-trafficgen COMANDO --help para ver las opciones de cada comando.

El comando UDP

El comando UDP genera tráfico UDP a una IP de destino dada y a un puerto de destino fijo, o a un rango de números de puerto. Solo se admite tráfico IPv6, y los paquetes generados tendrán su límite de saltos IP establecido en 1, por lo que no se pueden enrutar.

La sintaxis para el comando udp es:

xdp-trafficgen udp [opciones] <ifname>

Donde <ifname> es el nombre de la interfaz de destino en la que se transmitirán los paquetes. Tenga en cuenta que el controlador de red de esta interfaz de red debe admitir ser el objetivo de las redirecciones XDP (debe implementar la operación de controlador ndo_xdp_xmit).

Las opciones admitidas son:

-m, --dst-mac <dirección mac>

Establece la dirección MAC de destino de los paquetes generados. El valor predeterminado es generar paquetes con una dirección MAC de destino todo ceros.

-M, --src-mac <dirección mac>

Establece la dirección MAC de origen de los paquetes generados. El valor predeterminado es utilizar la dirección MAC de la interfaz en la que se transmiten los paquetes.

-a, --dst-addr <dirección>

Dirección IP de destino de los paquetes generados. El valor predeterminado es la dirección de enlace local fe80::2.

-A, --src-addr <dirección>

Dirección IP de origen de los paquetes generados. El valor predeterminado es la dirección de enlace local fe80::1.

-p, --dst-port <puerto>

Puerto UDP de destino de los paquetes generados, o el primer puerto en el rango si se ejecuta con --dyn-ports activado. Por defecto es 1.

-P, --src-port <puerto>

Puerto UDP de origen de los paquetes generados. Por defecto es 1.

-d, --dyn-ports <número de puertos>

Habilita el modo de puerto dinámico donde el puerto de destino se varía en un rango de <número de puertos> a partir de --dst-port.

-n, --num-packets <número de paquetes>

Número de paquetes a enviar antes de salir. Si no se especifica, xdp-trafficgen seguirá enviando paquetes hasta que se interrumpa.

-s, --pkt-size <bytes>

Tamaño de cada paquete UDP enviado, incluido el encabezado Ethernet. El tamaño mínimo, que es también el predeterminado, es de 64 bytes.

-t, --threads <hilos>

Número de hilos simultáneos desde los que transmitir. Cada hilo se fijará a un núcleo de CPU separado si es posible. Por defecto es 1.

-I, --interval <s>

Estadísticas de transmisión de salida con este intervalo (en segundos).

-v, --verbose

Habilita el registro detallado (-vv: más detallado).

--version

Muestra la información de la versión y sale.

-h, --help

Muestra un resumen de las opciones disponibles

El comando TCP

El comando TCP genera tráfico TCP ficticio en un solo flujo TCP. Esto depende de instalar primero un programa XDP de entrada en la interfaz utilizada para transmitir. Luego, se establece una conexión de socket TCP regular desde el espacio de usuario, y una vez completado el handshake, el programa XDP se hará cargo y comenzará a generar tráfico en esa tupla de flujo. El programa XDP de entrada interceptará los paquetes ACK del receptor y realizará un seguimiento de la ventana de recepción.

El generador de tráfico no tiene control de congestión, y solo un seguimiento de retransmisión muy básico: en esencia, cualquier ACK duplicado del receptor hará que el remitente restablezca su número de secuencia de envío al último valor ACKed y comience de nuevo desde allí. Lo mismo ocurre si no se hace ningún progreso en la ventana en dos segundos. Esto significa que el generador de tráfico puede generar una gran cantidad de tráfico ficticio, pero si hay pérdida de paquetes, muchas de estas pueden ser retransmisiones.

La sintaxis para el comando tcp es:

xdp-trafficgen tcp [opciones] -i <ifname> <hostname>

Donde <ifname> es el nombre de la interfaz de destino en la que se transmitirán los paquetes y <hostname> es el nombre de host o la dirección IP del par al que conectarse (solo se admite IPv6). Tenga en cuenta que el controlador de red de esta interfaz de red debe admitir ser el objetivo de las redirecciones XDP (debe implementar la operación de controlador ndo_xdp_xmit).

Las opciones admitidas son:

-p, --dst-port <puerto>

Conectarse al puerto de destino <puerto>. Por defecto 10000.

-m, --mode <modo>

Cargar el programa XDP de entrada en el modo <modo>; el valor predeterminado es native (valores válidos: native,skb,hw)

-n, --num-packets <paquetes>

Número de paquetes a enviar antes de salir. Si no se especifica, xdp-trafficgen seguirá enviando paquetes hasta que se interrumpa.

-I, --interval <s>

Estadísticas de transmisión de salida con este intervalo (en segundos).

-v, --verbose

Habilita el registro detallado (-vv: más detallado).

--version

Muestra la información de la versión y sale.

-h, --help

Muestra un resumen de las opciones disponibles

El comando PROBE

El comando PROBE sondea el kernel para descubrir si admite las características necesarias para ejecutar xdp-trafficgen. Esto se puede usar para descubrir si el kernel en ejecución es compatible con xdp-trafficgen, así como para descubrir si una interfaz en particular admite el envío de paquetes generados por xdp-trafficgen.

La sintaxis para el comando probe es:

xdp-trafficgen probe [opciones]

xdp-trafficgen(8)

NAME

xdp-trafficgen - A tool to generate traffic to test XDP programs

SYNOPSIS

xdp-trafficgen [-i | --ifname <ifname>] [-v | --verbose] [--version] [-h | --help]

The UDP command

Generates UDP traffic.

xdp-trafficgen udp --help
xdp-trafficgen udp --version
xdp-trafficgen udp <interface> <number of packets> <destination IP> <destination port> [source IP] [source port]

The TCP command

Generates TCP traffic.

xdp-trafficgen tcp --help
xdp-trafficgen tcp --version
xdp-trafficgen tcp <interface> <number of packets> <destination IP> <destination port> [source IP] [source port]

The PROBE command

xdp-trafficgen probes the kernel to verify XDP support. After probing, xdp-trafficgen will print the results of the probing of the kernel, and (if an interface name is supplied), whether the interface supports sending packets generated by xdp-trafficgen. The exit code will be 0 if all probes succeed, and 1 otherwise.

Note that the probing relies on the kernel XDP feature reporting, which was added after the XDP support itself. This means that with some older kernel versions, the probing may fail even though xdp-trafficgen would in fact be able to transmit packets.

The supported options are:

-i, --ifname <ifname>

Probe the supplied interface name, in addition to doing the general kernel probing.

-v, --verbose

Enable verbose logging (-vv: more verbose).

--version

Display version information and exit.

-h, --help

Display a summary of the available options
