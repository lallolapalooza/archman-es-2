NOMBRE

xcb_allow_events - liberar eventos en cola

SINOPSIS

#include <xcb/xproto.h>

Función de solicitud

xcb_void_cookie_t xcb_allow_events(xcb_connection_t *conn, uint8_t mode, xcb_timestamp_t time);

ARGUMENTOS DE LA SOLICITUD

conn
La conexión XCB a X11.
mode
Uno de los siguientes valores:
XCB_ALLOW_ASYNC_POINTER
Para AsyncPointer, si el puntero está congelado por el cliente, el procesamiento de eventos del puntero continúa normalmente. Si el puntero está congelado dos veces por el cliente en nombre de dos "grabs" separados, AsyncPointer se descongelará para ambos. AsyncPointer no tiene efecto si el puntero no está congelado por el cliente, pero el puntero no necesita estar "grabbed" por el cliente.

XCB_ALLOW_SYNC_POINTER
Para SyncPointer, si el puntero está congelado y activamente "grabbed" por el cliente, el procesamiento de eventos del puntero continúa normalmente hasta el siguiente evento ButtonPress o ButtonRelease que se reporte al cliente, momento en el cual el puntero parece congelarse nuevamente. Sin embargo, si el evento reportado provoca que el "grab" del puntero se libere, entonces el puntero no se congela. SyncPointer no tiene efecto si el puntero no está congelado por el cliente o si el puntero no está "grabbed" por el cliente.
XCB_ALLOW_REPLAY_POINTER
Para ReplayPointer, si el puntero está activamente "grabbed" por el cliente y está congelado como resultado de que se le ha enviado un evento al cliente (ya sea por la activación de un GrabButton o por un AllowEvents previo con modo SyncPointer pero no por un GrabPointer), entonces el "grab" del puntero se libera y ese evento se reprocesa completamente, ignorando esta vez cualquier "grab" pasivo en o por encima (hacia la raíz) de la ventana de "grab" del "grab" recién liberado. La solicitud no tiene efecto si el puntero no está "grabbed" por el cliente o si el puntero no está congelado como resultado de un evento.
XCB_ALLOW_ASYNC_KEYBOARD
Para AsyncKeyboard, si el teclado está congelado por el cliente, el procesamiento de eventos del teclado continúa normalmente. Si el teclado está congelado dos veces por el cliente en nombre de dos "grabs" separados, AsyncKeyboard se descongelará para ambos. AsyncKeyboard no tiene efecto si el teclado no está congelado por el cliente, pero el teclado no necesita estar "grabbed" por el cliente.
XCB_ALLOW_SYNC_KEYBOARD
Para SyncKeyboard, si el teclado está congelado y activamente "grabbed" por el cliente, el procesamiento de eventos del teclado continúa normalmente hasta el siguiente evento KeyPress o KeyRelease que se reporte al cliente, momento en el cual el teclado parece congelarse nuevamente. Sin embargo, si el evento reportado provoca que el "grab" del teclado se libere, entonces el teclado no se congela. SyncKeyboard no tiene efecto si el teclado no está congelado por el cliente o si el teclado no está "grabbed" por el cliente.
XCB_ALLOW_REPLAY_KEYBOARD
Para ReplayKeyboard, si el teclado está activamente "grabbed" por el cliente y está congelado como resultado de que se le ha enviado un evento al cliente (ya sea por la activación de un GrabKey o por un AllowEvents previo con modo SyncKeyboard pero no por un GrabKeyboard), entonces el "grab" del teclado se libera y ese evento se reprocesa completamente, ignorando esta vez cualquier "grab" pasivo en o por encima (hacia la raíz) de la ventana de "grab" del "grab" recién liberado. La solicitud no tiene efecto si el teclado no está "grabbed" por el cliente o si el teclado no está congelado como resultado de un evento.
XCB_ALLOW_ASYNC_BOTH
Para AsyncBoth, si el puntero y el teclado están congelados por el cliente, el procesamiento de eventos para ambos dispositivos continúa normalmente. Si un dispositivo está congelado dos veces por el cliente en nombre de dos "grabs" separados, AsyncBoth se descongelará para ambos. AsyncBoth no tiene efecto a menos que tanto el puntero como el teclado estén congelados por el cliente.
XCB_ALLOW_SYNC_BOTH
Para SyncBoth, si tanto el puntero como el teclado están congelados por el cliente, el procesamiento de eventos (para ambos dispositivos) continúa normalmente hasta el siguiente evento ButtonPress, ButtonRelease, KeyPress o KeyRelease que se reporte al cliente para un dispositivo "grabbed" (evento de botón para el puntero, evento de tecla para el teclado), momento en el cual los dispositivos parecen congelarse nuevamente. Sin embargo, si el evento reportado provoca que el "grab" se libere, entonces los dispositivos no se congelan (pero si el otro dispositivo todavía está "grabbed", entonces un evento posterior para él aún provocará que ambos dispositivos se congelen). SyncBoth no tiene efecto a menos que tanto el puntero como el teclado estén congelados por el cliente. Si el puntero o el teclado están congelados dos veces por el cliente en nombre de dos "grabs" separados, SyncBoth se descongelará para ambos (pero una congelación posterior para SyncBoth solo congelará cada dispositivo una vez).
time
Timestamp para evitar condiciones de carrera al ejecutar X sobre la red.

El valor especial XCB_CURRENT_TIME será reemplazado con la hora actual del servidor.

DESCRIPCIÓN

Libera los eventos en cola si el cliente ha causado que un dispositivo (puntero/teclado) se congele debido a que lo ha "grabbed" activamente. Esta solicitud no tiene efecto si time es anterior a la hora del último "grab" del "grab" activo más reciente para este cliente o si time es posterior a la hora actual del servidor X.

VALOR DE RETORNO

Devuelve una xcb_void_cookie_t. Los errores (si los hay) deben manejarse en el bucle de eventos.

Si desea manejar los errores directamente con xcb_request_check en su lugar, use xcb_allow_events_checked. Consulte xcb-requests(3) para obtener detalles.

ERRORES

xcb_value_error_t
Especificaste un mode inválido.
