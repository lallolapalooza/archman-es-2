xcb_create_window - Crea una ventana

#include <xcb/xproto.h>

value_mask
Uno de los siguientes valores:
XCB_CW_BACK_PIXMAP
Anula el pixmap de fondo predeterminado. El pixmap de fondo y la ventana deben tener la misma raíz y la misma profundidad. Se puede usar cualquier tamaño de pixmap, aunque algunos tamaños pueden ser más rápidos que otros.

Si se especifica XCB_BACK_PIXMAP_NONE, la ventana no tiene un fondo definido. El servidor puede rellenar el contenido con el contenido anterior de la pantalla o con contenido de su propia elección.

Si se especifica XCB_BACK_PIXMAP_PARENT_RELATIVE, se utiliza el fondo del padre, pero la ventana debe tener la misma profundidad que el padre (o se producirá un error de coincidencia). El fondo del padre se rastrea y se utiliza la versión actual cada vez que se requiere el fondo de la ventana.

XCB_CW_BACK_PIXEL
Anula BackPixmap. Se utiliza un pixmap de tamaño indefinido relleno con el píxel de fondo especificado para el fondo. No se realiza ninguna verificación de rango, el píxel de fondo se trunca al número apropiado de bits.
XCB_CW_BORDER_PIXMAP
Anula el pixmap de borde predeterminado. El pixmap de borde y la ventana deben tener la misma raíz y la misma profundidad. Se puede usar cualquier tamaño de pixmap, aunque algunos tamaños pueden ser más rápidos que otros.

El valor especial XCB_COPY_FROM_PARENT significa que el pixmap de borde del padre se copia (los cambios posteriores en el atributo de borde del padre no afectan al hijo), pero la ventana debe tener la misma profundidad que el padre.

XCB_CW_BORDER_PIXEL
Anula BorderPixmap. Se utiliza un pixmap de tamaño indefinido relleno con el píxel de borde especificado para el borde. No se realiza ninguna verificación de rango en el valor del píxel de borde, se trunca al número apropiado de bits.
XCB_CW_BIT_GRAVITY
Define qué región de la ventana debe conservarse si la ventana se redimensiona.
XCB_CW_WIN_GRAVITY
Define cómo se reposicionará la ventana si el padre se redimensiona (ver ConfigureWindow).
XCB_CW_BACKING_STORE
Un backing-store de WhenMapped aconseja al servidor que mantener el contenido de las regiones oscurecidas cuando la ventana está mapeada sería beneficioso. Un backing-store de Always aconseja al servidor que mantener el contenido incluso cuando la ventana no está mapeada sería beneficioso. En este caso, el servidor puede generar un evento de exposición cuando se crea la ventana. El valor NotUseful aconseja al servidor que mantener el contenido es innecesario, aunque un servidor aún puede elegir mantener el contenido mientras la ventana está mapeada. Tenga en cuenta que si el servidor mantiene el contenido, el servidor debe mantener el contenido completo, no solo la región dentro de los límites del padre, incluso si la ventana es más grande que su padre. Mientras el servidor mantiene el contenido, normalmente no se generarán eventos de exposición, pero el servidor puede dejar de mantener el contenido en cualquier momento.
XCB_CW_BACKING_PLANES
Los backing-planes indican (con bits establecidos en 1) qué planos de bits de la ventana contienen datos dinámicos que deben conservarse en los backing-stores y durante los save-unders.
XCB_CW_BACKING_PIXEL
El backing-pixel especifica qué valor usar en los planos no cubiertos por los backing-planes. El servidor es libre de guardar solo los planos de bits especificados en el backing-store o save-under y regenerar los planos restantes con el valor de píxel especificado. Cualquier bit más allá de la profundidad especificada de la ventana en estos valores simplemente se ignora.
XCB_CW_OVERRIDE_REDIRECT
El override-redirect especifica si las solicitudes de mapeo y configuración en esta ventana deben anular un SubstructureRedirect en el padre, típicamente para informar a un administrador de ventanas que no manipule la ventana.
XCB_CW_SAVE_UNDER
Si es 1, se aconseja al servidor que, cuando esta ventana esté mapeada, conservar el contenido de las ventanas que oscurece sería beneficioso.
XCB_CW_EVENT_MASK
La máscara de eventos define en qué eventos está interesado el cliente para esta ventana (o para algunos tipos de eventos, los inferiores de la ventana).
XCB_CW_DONT_PROPAGATE
La máscara do-not-propagate define qué eventos no deben propagarse a las ventanas ancestrales cuando ningún cliente tiene el tipo de evento seleccionado en esta ventana.
XCB_CW_COLORMAP
El colormap especifica el colormap que mejor refleja los colores verdaderos de la ventana. Los servidores capaces de soportar múltiples colormaps de hardware pueden usar esta información, y los administradores de ventanas pueden usarla para solicitudes InstallColormap.
