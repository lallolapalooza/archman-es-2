NOMBRE

xcb_allow_events - liberar eventos en cola

SINOPSIS

#include <xcb/xproto.h>

Función de solicitud

xcb_void_cookie_t xcb_allow_events(xcb_connection_t *conn, uint8_t mode, xcb_timestamp_t time);

ARGUMENTOS DE SOLICITUD

conn
La conexión XCB a X11.
mode
Uno de los siguientes valores:
XCB_ALLOW_ASYNC_POINTER
Para AsyncPointer, si el puntero está congelado por el cliente, el procesamiento de eventos del puntero continúa normalmente. Si el puntero está congelado dos veces por el cliente en nombre de dos capturas separadas, AsyncPointer las libera para ambas. AsyncPointer no tiene efecto si el puntero no está congelado por el cliente, pero el puntero no necesita ser capturado por el cliente.

XCB_ALLOW_SYNC_POINTER
Para SyncPointer, si el puntero está congelado y capturado activamente por el cliente, el procesamiento de eventos del puntero continúa normalmente hasta que el siguiente evento ButtonPress o ButtonRelease se reporta al cliente, momento en el cual el puntero vuelve a parecer congelado. Sin embargo, si el evento reportado provoca la liberación de la captura del puntero, entonces el puntero no se congela. SyncPointer no tiene efecto si el puntero no está congelado por el cliente o si el puntero no está capturado por el cliente.
XCB_ALLOW_REPLAY_POINTER
Para ReplayPointer, si el puntero está capturado activamente por el cliente y está congelado como resultado de que un evento ha sido enviado al cliente (ya sea por la activación de un GrabButton o por un AllowEvents previo con el modo SyncPointer pero no por un GrabPointer), entonces la captura del puntero se libera y ese evento se reprocesa completamente, ignorando esta vez cualquier captura pasiva en o por encima (hacia la raíz) de la ventana de captura recién liberada. La solicitud no tiene efecto si el puntero no está capturado por el cliente o si el puntero no está congelado como resultado de un evento.
XCB_ALLOW_ASYNC_KEYBOARD
Para AsyncKeyboard, si el teclado está congelado por el cliente, el procesamiento de eventos del teclado continúa normalmente. Si el teclado está congelado dos veces por el cliente en nombre de dos capturas separadas, AsyncKeyboard las libera para ambas. AsyncKeyboard no tiene efecto si el teclado no está congelado por el cliente, pero el teclado no necesita ser capturado por el cliente.
XCB_ALLOW_SYNC_KEYBOARD
Para SyncKeyboard, si el teclado está congelado y capturado activamente por el cliente, el procesamiento de eventos del teclado continúa normalmente hasta que el siguiente evento KeyPress o KeyRelease se reporta al cliente, momento en el cual el teclado vuelve a parecer congelado. Sin embargo, si el evento reportado provoca la liberación de la captura del teclado, entonces el teclado no se congela. SyncKeyboard no tiene efecto si el teclado no está congelado por el cliente o si el teclado no está capturado por el cliente.
XCB_ALLOW_REPLAY_KEYBOARD
Para ReplayKeyboard, si el teclado está capturado activamente por el cliente y está congelado como resultado de que un evento ha sido enviado al cliente (ya sea por la activación de un GrabKey o por un AllowEvents previo con el modo SyncKeyboard pero no por un GrabKeyboard), entonces la captura del teclado se libera y ese evento se reprocesa completamente, ignorando esta vez cualquier captura pasiva en o por encima (hacia la raíz) de la ventana de captura recién liberada. La solicitud no tiene efecto si el teclado no está capturado por el cliente o si el teclado no está congelado como resultado de un evento.
XCB_ALLOW_ASYNC_BOTH
Para AsyncBoth, si el puntero y el teclado están congelados por el cliente, el procesamiento de eventos para ambos dispositivos continúa normalmente. Si un dispositivo está congelado dos veces por el cliente en nombre de dos capturas separadas, AsyncBoth las libera para ambas. AsyncBoth no tiene efecto a menos que tanto el puntero como el teclado estén congelados por el cliente.
XCB_ALLOW_SYNC_BOTH
Para SyncBoth, si tanto el puntero como el teclado están congelados por el cliente, el procesamiento de eventos (para ambos dispositivos) continúa normalmente hasta que el siguiente evento ButtonPress, ButtonRelease, KeyPress o KeyRelease se reporta al cliente para un dispositivo capturado (evento de botón para el puntero, evento de tecla para el teclado), momento en el cual los dispositivos vuelven a parecer congelados. Sin embargo, si el evento reportado provoca la liberación de la captura, entonces los dispositivos no se congelan (pero si el otro dispositivo todavía está capturado, un evento posterior para él todavía provocará que ambos dispositivos se congelen). SyncBoth no tiene efecto a menos que tanto el puntero como el teclado estén congelados por el cliente. Si el puntero o el teclado está congelado dos veces por el cliente en nombre de dos capturas separadas, SyncBoth las libera para ambas (pero una congelación posterior para SyncBoth solo congelará cada dispositivo una vez).
time
Marca de tiempo para evitar condiciones de carrera al ejecutar X sobre la red.

El valor especial XCB_CURRENT_TIME será reemplazado por la hora actual del servidor X.

DESCRIPCIÓN

Libera eventos en cola si el cliente ha provocado que un dispositivo (puntero/teclado) se congele debido a su captura activa. Esta solicitud no tiene efecto si time es anterior a la hora de la última captura de la captura activa más reciente para este cliente o si time es posterior a la hora actual del servidor X.

VALOR DE RETORNO

Devuelve una xcb_void_cookie_t. Los errores (si los hay) deben manejarse en el bucle de eventos.

Si desea manejar los errores directamente con xcb_request_check en su lugar, use xcb_allow_events_checked. Consulte xcb-requests(3) para obtener detalles.

ERRORES

xcb_value_error_t
Especificaste un mode inválido.

VER TAMBIÉN

NOMBRE

xcb_allow_events - Permite la entrada de eventos para un cliente.

SINOPSIS

#include <xcb/xcb.h>

xcb_void_cookie_t xcb_allow_events (xcb_connection_t *connection ,uint8_t mode );

DESCRIPCIÓN

La solicitud xcb_allow_events se utiliza para controlar cuándo el servidor debe comenzar a enviar eventos a un cliente. Esto es útil para evitar que un cliente consuma todos los eventos de entrada que llegan al servidor.

Hay tres modos en los que se puede invocar esta solicitud:

  • XCB_ALLOW_REPLAY: Vuelve a enviar los eventos que se han puesto en cola y que el servidor ha estado reteniendo. El servidor también permitirá que los eventos futuros sean enviados normalmente.
  • XCB_ALLOW_TOGGLE_GRAB: El servidor dejará de retener los eventos y permitirá que se envíen normalmente. Cualquier evento de entrada que ocurra mientras el servidor retenía eventos será descartado.
  • XCB_ALLOW_SYNC_KEYBOARD: Esto es similar a XCB_ALLOW_TOGGLE_GRAB, pero también se envía un evento de teclado al cliente.

El parámetro mode especifica el modo en el que se deben permitir los eventos.

SOLICITUD

xcb_allow_events envía una solicitud que se puede probar para ver si hay errores.

xcb_allow_events(xcb_connection_t *connection, uint8_t mode)

  • connection: La conexión XCB a un servidor X.
  • mode: El modo en el que se deben permitir los eventos. Puede ser uno de:
    • XCB_ALLOW_REPLAY
    • XCB_ALLOW_TOGGLE_GRAB
    • XCB_ALLOW_SYNC_KEYBOARD

VALOR DE RETORNO

Devuelve una cookie de tipo xcb_void_cookie_t. La cookie se puede utilizar para consultar el estado de la solicitud y comprobar si se han producido errores.

Si el valor de retorno de la consulta de errores es XCB_REQUEST_ERROR, entonces un error ha ocurrido y debe ser manejado. Las estructuras de errores devueltas por la consulta de errores deben ser liberadas por el llamador.

ERRORES

xcb_allow_events puede generar los siguientes errores:

  • xcb_request_error_t: Si la solicitud falla.

xcb_grab_key(3), xcb_grab_keyboard(3), xcb_grab_pointer(3)
