Paquete: libxcb

Licencias: X11

xcb-requests(3) Ejemplos de XCB xcb-requests(3)

NOMBRE

xcb-requests - sobre las páginas del manual de solicitudes

DESCRIPCIÓN

Cada solicitud en X11, como MapWindow, corresponde a un número de funciones y estructuras de datos en XCB. Para MapWindow, XCB proporciona la función xcb_map_window, que rellena la estructura de datos xcb_map_window_request_t y la escribe en la conexión X11. Dado que la solicitud MapWindow no tiene respuesta, este es el caso más sencillo.

RESPUESTAS

Muchas solicitudes tienen respuestas. Para cada respuesta, XCB proporciona al menos una estructura de datos correspondiente y una función para devolver un puntero a una estructura de datos rellenada. Tomemos la solicitud InternAtom como ejemplo: XCB proporciona la estructura de datos xcb_intern_atom_reply_t y la función xcb_intern_atom_reply. Para respuestas más complejas (por ejemplo, listas, como en xcb_list_fonts), se proporcionan funciones accesoras.

COOKIES

XCB devuelve una cookie para cada solicitud que envías. Esta es una estructura de datos específica de XCB que contiene el número de secuencia con el que se envió la solicitud al servidor X11. Para obtener cualquier respuesta, debes proporcionar esa cookie (para que XCB sepa cuál de las respuestas en espera quieres). Aquí tienes un ejemplo para ilustrar el uso de las cookies:

void my_example(xcb_connection *conn) {
    xcb_intern_atom_cookie_t cookie;
    xcb_intern_atom_reply_t *reply;
    cookie = xcb_intern_atom(conn, 0, strlen("_NET_WM_NAME"), "_NET_WM_NAME");
    /* ... haz otro trabajo aquí si es posible ... */
    if ((reply = xcb_intern_atom_reply(conn, cookie, NULL))) {
        printf("El átomo _NET_WM_NAME tiene el ID %u\n", reply->atom);
    }
    free(reply);
}

VERIFICADO VS. NO VERIFICADO

Los sufijos checked (verificado) y unchecked (no verificado) para las funciones determinan qué tipo de manejo de errores se utiliza para esta solicitud específica.

Para solicitudes que no tienen respuesta (por ejemplo, xcb_map_window), los errores se entregarán al bucle de eventos (recibirás un evento X11 de tipo 0 al llamar a xcb_poll_for_event). Si deseas verificar explícitamente los errores de forma bloqueante, llama a la versión _checked de la función (por ejemplo, xcb_map_window_checked) y utiliza xcb_request_check.

Para solicitudes que tienen respuesta (por ejemplo, xcb_intern_atom), los errores se verificarán al llamar a la función de respuesta. Para obtener los errores en el bucle de eventos en su lugar, utiliza la versión _unchecked de la función (por ejemplo, xcb_intern_atom_unchecked).

Aquí tienes un ejemplo que ilustra las cuatro formas diferentes de manejar los errores:

/*
 * Solicitud sin respuesta, manejando errores en el bucle de eventos (por defecto)
 *
 */
void my_example(xcb_connection *conn, xcb_window_t window) {
    /* Esta es una solicitud sin respuesta. Los errores se entregarán al bucle de
     * eventos. Recibir un error en xcb_map_window probablemente sea un error en
     * nuestro programa, por lo que no necesitamos verificarlo de forma bloqueante. */
    xcb_map_window(conn, window);
    /* ... por supuesto, tu bucle de eventos no estaría en la misma función ... */
    while ((event = xcb_wait_for_event(conn)) != NULL) {
        if (event->response_type == 0) {
            fprintf("Recibido error X11 %d\n", error->error_code);
            free(event);
            continue;
        }
        /* ... maneja un evento normal ... */
    }
}
/*
 * Solicitud sin respuesta, manejando errores directamente
 *
 */
void my_example(xcb_connection *conn, xcb_window_t deco, xcb_window_t window) {
    /* Un gestor de ventanas que reparenta quiere saber si una nueva ventana fue
     * reparentada con éxito. Si no (porque la ventana ya se destruyó, por ejemplo),
     * no tiene sentido mapear una decoración de ventana vacía en absoluto, así que
     * necesitamos saber esto ahora mismo. */
    xcb_void_cookie_t cookie = xcb_reparent_window_checked(conn, window,
                                                           deco, 0, 0);
    xcb_generic_error_t *error;
    if ((error = xcb_request_check(conn, cookie))) {
        fprintf(stderr, "No se pudo reparentar la ventana\n");
        free(error);
        return;
    }
    /* ... haz cosas de gestor de ventanas aquí ... */
}
/*
 * Solicitud con respuesta, manejando errores directamente (por defecto)
 *
 */
void my_example(xcb_connection *conn, xcb_window_t window) {
    xcb_intern_atom_cookie_t cookie;
    xcb_intern_atom_reply_t *reply;
    xcb_generic_error_t *error;
    cookie = xcb_intern_atom(c, 0, strlen("_NET_WM_NAME"), "_NET_WM_NAME");
    /* ... haz otro trabajo aquí si es posible ... */
    if ((reply = xcb_intern_atom_reply(c, cookie, &error))) {
        printf("El átomo _NET_WM_NAME tiene el ID %u\n", reply->atom);
        free(reply);
    } else {
        fprintf(stderr, "Error X11 %d\n", error->error_code);
        free(error);
    }
}
/*
 * Solicitud con respuesta, manejando errores en el bucle de eventos
 *
 */
void my_example(xcb_connection *conn, xcb_window_t window) {
    xcb_intern_atom_cookie_t cookie;
    xcb_intern_atom_reply_t *reply;
    cookie = xcb_intern_atom_unchecked(c, 0, strlen("_NET_WM_NAME"),
                                       "_NET_WM_NAME");
    /* ... haz otro trabajo aquí si es posible ... */
    if ((reply = xcb_intern_atom_reply(c, cookie, NULL))) {
        printf("El átomo _NET_WM_NAME tiene el ID %u\n", reply->atom);
        free(reply);
    }
    /* ... por supuesto, tu bucle de eventos no estaría en la misma función ... */
    while ((event = xcb_wait_for_event(conn)) != NULL) {
        if (event->response_type == 0) {
            fprintf("Recibido error X11 %d\n", error->error_code);
            free(event);
            continue;
        }
        /* ... maneja un evento normal ... */
    }
}
