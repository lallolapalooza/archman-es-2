NOMBRE

xca - Gestión de certificados y claves X

Una GUI para manejar certificados X509, claves RSA/DSA/EC, Solicitudes PKCS#10 y CRLs en Software y en Tarjetas Inteligentes.

SINOPSIS

xca [OPCIONES]

DESCRIPCIÓN

Esta aplicación está pensada como una CA, almacén de certificados y claves. Utiliza una base de datos SQL para almacenar los elementos. Por defecto es SQLite3, pero MySQL y PostgreSQL también han sido probados y son compatibles. Los tipos conocidos son solicitudes de firma de certificados (PKCS#10), Certificados (X509v3), claves RSA, DSA y EC, y listas de revocación de certificados. Se soporta la firma de solicitudes y la creación de certificados autofirmados. Ambos pueden usar plantillas para mayor simplicidad. Las estructuras PKI se pueden importar y exportar en varios formatos como PKCS#12, PEM, DER, PKCS#8, PKCS#7.
XCA permite a los usuarios gestionar tarjetas inteligentes a través de la interfaz PKCS#11.

OPCIONES

--crlgen=<identificador-ca> *
Generar CRL para <ca>. Usar la opción 'name' para establecer el nombre interno de la nueva CRL.
--database=<base-de-datos>
Nombre del archivo (*.xdb) de la base de datos SQLite o un descriptor de base de datos remota: [usuario@host/TIPO:dbname#prefijo].
--exit
Salir después de importar elementos.
--help
Imprimir esta ayuda y salir.
--hierarchy=<directorio> *
Guardar la jerarquía de índice OpenSSL en <dir>.
--index=<archivo> *
Guardar el índice OpenSSL en <archivo>.
--import *
Importar todos los elementos proporcionados a la base de datos.
--import-names *
Una lista de nombres separados por punto y coma aplicada a los elementos importados en el orden en que se encuentran en el archivo PEM y en la línea de comandos.
--issuers *
Imprimir todos los certificados de emisor conocidos que tienen una clave privada asociada y la restricción básica de CA establecida a 'true'.
--keygen=<tipo> *
Generar una nueva clave e importarla a la base de datos. Usar la opción 'name' para establecer el nombre interno de la nueva clave. El parámetro <tipo> tiene el formato: '[RSA|DSA|EC]:[<tamaño>|<curva>]'.
--list-curves
Imprime todas las Curvas Elípticas conocidas.
--list-items *
Listar todos los elementos en la base de datos.
--name=<nombre-interno> *
Proporciona el nombre de los nuevos elementos generados. Se generará un nombre automático si se omite.
--no-native-dialogs
Deshabilita los diálogos nativos del sistema operativo para mensajes y operaciones de archivos y utiliza diálogos específicos de Qt en su lugar.
--no-gui
No iniciar la GUI. Alternativamente, establecer la variable de entorno XCA_NO_GUI=1 o llamar a xca como enlace simbólico 'xca-console'.
--password=<contraseña>
Contraseña de la base de datos para desbloquear la base de datos. Ver abajo para las opciones de formato de contraseña.
--pem
Imprimir la representación PEM de los archivos proporcionados. Imprime solo la parte pública de las claves privadas.
--pem-file
Especificar un nombre de archivo para los datos PEM. Implica '--pem'.
--print
Imprimir una sinopsis de los archivos proporcionados.
--select=<lista-de-ids> *
Selecciona todos los elementos de la lista de IDs separada por comas para ser mostrados con 'print', 'text' o 'pem'.
--sqlpass=<contraseña>
Contraseña para acceder al servidor SQL remoto. Ver abajo para las opciones de formato de contraseña.
--text
Imprimir el contenido de los archivos proporcionados como lo hace OpenSSL.
--verbose
Imprimir registro de depuración en stderr. Igual que establecer XCA_DEBUG=all. Ver XCA_DEBUG
--version
Imprimir información de versión y salir.
Las opciones marcadas con un asterisco necesitan una base de datos. Ya sea desde la línea de comandos o como base de datos predeterminada.

ARGUMENTOS DE CONTRASEÑA

Las opciones de contraseña aceptan la misma sintaxis que openssl:

env:var
Obtener la contraseña de la variable de entorno var. Dado que el entorno de otros procesos es visible en ciertas plataformas (por ejemplo, ps bajo ciertos sistemas operativos Unix) esta opción debe usarse con precaución.
fd:número
Leer la contraseña desde el descriptor de archivo número. Esto se puede usar para enviar los datos a través de una tubería, por ejemplo.
file:ruta
La primera línea de la ruta es la contraseña. Si se proporciona el mismo argumento de ruta a los argumentos password y sqlpassword, se utilizará la primera línea para ambas contraseñas. la ruta no necesita referirse a un archivo regular: podría referirse, por ejemplo, a un dispositivo o una tubería con nombre.
pass:contraseña
La contraseña real es contraseña. Dado que la contraseña es visible para las utilidades (como 'ps' en Unix), esta forma solo debe usarse donde la seguridad no sea importante.
stdin
Leer la contraseña desde la entrada estándar.

VARIABLES DE ENTORNO

Algunas variables de entorno más o menos útiles son evaluadas por xca

XCA_NO_GUI=1
No iniciar la interfaz gráfica de usuario forzosamente. Igual que el argumento --no-gui. Si ambos no se proporcionaron, XCA intenta ser inteligente y mira los otros argumentos para juzgar si iniciar la GUI o no.
XCA_DEBUG=<patrón>
La variable de entorno XCA_DEBUG controla la depuración dinámica. El formato es una lista de patrones separados por comas. Cada patrón es: all|[-]<función>|[-]<nombre-archivo>:<primera-línea>[-<última-línea>] Un guion inicial omite la coincidencia. La primera-línea y última-línea pueden estar vacías y se reemplazarán por la primera y última línea del archivo. Si se omite -<última-línea>, solo se coincide con el número de línea exacto de última-línea.
Ejemplo: XCA_DEBUG=all,-timerEvent Registra todo pero omite los molestos mensajes de timerEvent.
Ejemplo: XCA_DEBUG=pki_base.cpp:100-,-pki_base.cpp:340 Registra mensajes de pki_base desde la línea 100 hasta la última línea, excepto la línea 340.
XCA_ABORT_ON_WARNING=1
Opción de desarrollador para fallar en el depurador en caso de un mensaje de registro a nivel de advertencia. Documentado por completitud. No útil para no desarrolladores.
XCA_PORTABLE=1
Forzar el modo portátil de Windows. Documentado por completitud. No útil para no desarrolladores.
XCA_ARGUMENTS=<man|rst|completion>
