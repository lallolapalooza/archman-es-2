value_mask
Uno de los siguientes valores:
XCB_CW_BACK_PIXMAP
Anula el pixmap de fondo predeterminado. El pixmap de fondo y la ventana deben tener la misma raíz y la misma profundidad. Se puede usar un pixmap de cualquier tamaño, aunque algunos tamaños pueden ser más rápidos que otros.

Si se especifica XCB_BACK_PIXMAP_NONE, la ventana no tiene fondo definido. El servidor puede rellenar los contenidos con el contenido anterior de la pantalla o con contenido de su elección.

Si se especifica XCB_BACK_PIXMAP_PARENT_RELATIVE, se utiliza el fondo del padre, pero la ventana debe tener la misma profundidad que el padre (o se produce un error de coincidencia). El fondo del padre se rastrea y se utiliza la versión actual cada vez que se requiere el fondo de la ventana.

XCB_CW_BACK_PIXEL
Anula BackPixmap. Se utiliza un pixmap de tamaño indefinido rellenado con el píxel de fondo especificado para el fondo. No se realiza comprobación de rangos, el píxel de fondo se trunca al número apropiado de bits.
XCB_CW_BORDER_PIXMAP
Anula el pixmap de borde predeterminado. El pixmap de borde y la ventana deben tener la misma raíz y la misma profundidad. Se puede usar un pixmap de cualquier tamaño, aunque algunos tamaños pueden ser más rápidos que otros.

El valor especial XCB_COPY_FROM_PARENT significa que se copia el pixmap de borde del padre (los cambios posteriores en el atributo de borde del padre no afectan al hijo), pero la ventana debe tener la misma profundidad que el padre.

XCB_CW_BORDER_PIXEL
Anula BorderPixmap. Se utiliza un pixmap de tamaño indefinido rellenado con el píxel de borde especificado para el borde. No se realiza comprobación de rangos en el valor del píxel de borde, se trunca al número apropiado de bits.
XCB_CW_BIT_GRAVITY
Define qué región de la ventana se conservará si la ventana se redimensiona.
XCB_CW_WIN_GRAVITY
Define cómo se reposicionará la ventana si el padre se redimensiona (ver ConfigureWindow).
XCB_CW_BACKING_STORE
Un backing-store de WhenMapped aconseja al servidor que mantener los contenidos de las regiones oscurecidas cuando la ventana está mapeada sería beneficioso. Un backing-store de Always aconseja al servidor que mantener los contenidos incluso cuando la ventana no está mapeada sería beneficioso. En este caso, el servidor puede generar un evento de exposición cuando se crea la ventana. Un valor de NotUseful aconseja al servidor que mantener los contenidos es innecesario, aunque un servidor aún puede optar por mantener los contenidos mientras la ventana está mapeada. Tenga en cuenta que si el servidor mantiene los contenidos, entonces el servidor debe mantener contenidos completos, no solo la región dentro de los límites del padre, incluso si la ventana es más grande que su padre. Mientras el servidor mantiene los contenidos, normalmente no se generarán eventos de exposición, pero el servidor puede dejar de mantener los contenidos en cualquier momento.
XCB_CW_BACKING_PLANES
El backing-planes indica (con bits establecidos a 1) qué planos de bits de la ventana contienen datos dinámicos que deben conservarse en backing-stores y durante save-unders.
XCB_CW_BACKING_PIXEL
El backing-pixel especifica qué valor usar en los planos no cubiertos por backing-planes. El servidor es libre de guardar solo los planos de bits especificados en el backing-store o save-under y regenerar los planos restantes con el valor de píxel especificado. Cualquier bit más allá de la profundidad especificada de la ventana en estos valores simplemente se ignora.
XCB_CW_OVERRIDE_REDIRECT
El override-redirect especifica si las solicitudes de map y configure en esta ventana deben anular un SubstructureRedirect en el padre, típicamente para informar a un gestor de ventanas que no manipule la ventana.
XCB_CW_SAVE_UNDER
Si es 1, se aconseja al servidor que, cuando esta ventana se mapee, guardar los contenidos de las ventanas que oscurece sería beneficioso.
XCB_CW_EVENT_MASK
El event-mask define para qué eventos está interesado el cliente en esta ventana (o para algunos tipos de eventos, los inferiores de la ventana).
XCB_CW_DONT_PROPAGATE
El do-not-propagate-mask define para qué eventos no se propagarán a las ventanas ancestro cuando ningún cliente tenga seleccionado el tipo de evento en esta ventana.
XCB_CW_COLORMAP
El colormap especifica el mapa de colores que mejor refleja los colores verdaderos de la ventana. Los servidores capaces de soportar múltiples mapas de hardware pueden usar esta información, y los gestores de ventanas pueden utilizarla para solicitudes de InstallColormap. El value_list es un puntero a una estructura de datos que contiene los valores de las propiedades especificadas en value_mask, en el orden correcto. La estructura de datos exacta utilizada depende de los valores indicados en value_mask.

DESCRIPCIÓN

La solicitud xcb_create_window crea una ventana nueva.

La ventana nueva se convierte en un hijo de la ventana parent. La ventana nueva tiene el ID wid. Se posiciona en las coordenadas (x, y) relativas a la ventana parent.

El tamaño inicial de la ventana es width x height. El ancho del borde es border_width.

La profundidad especifica la profundidad de bits de la ventana nueva. XCB_COPY_FROM_PARENT hereda la profundidad del padre.

La clase especifica cómo debe comportarse la ventana en términos de entrada de eventos y cómo debe ser gestionada por el servidor. XCB_WINDOW_CLASS_INPUT_OUTPUT es la clase más común para las ventanas visibles. XCB_WINDOW_CLASS_INPUT_ONLY se utiliza para ventanas que no son visibles (por ejemplo, para gestores de ventanas). XCB_WINDOW_CLASS_COPY_FROM_PARENT hereda la clase del padre.

El visual especifica el tipo de visual de la ventana nueva. XCB_COPY_FROM_PARENT hereda el visual del padre.

El value_mask y el value_list se utilizan para configurar varias propiedades de la ventana nueva, como su fondo, borde, máscara de eventos, etc.

EVENTO DEVUELTO

XCB_CREATE_WINDOW

VALOR DE RETORNO

Devuelve una cookie para la solicitud xcb_create_window. La solicitud puede fallar con un error xcb_match_error_t si los parámetros no son válidos (por ejemplo, si la profundidad o el visual no coinciden con los del padre cuando se utiliza XCB_COPY_FROM_PARENT).

ERRORES

xcb_match_error_t Si los parámetros de profundidad, visual, border_width o colormap no son válidos o no coinciden con los del padre cuando se utiliza XCB_COPY_FROM_PARENT.

xcb_value_error_t Si se especifica un valor inválido en value_list.

xcb_window_error_t Si el padre no es una ventana válida.

DESCRIPCIÓN

Crea una ventana hijo sin mapear del padre especificado parent. Se generará un evento CreateNotify. La nueva ventana se coloca en la parte superior del orden de apilamiento con respecto a los hermanos.

El sistema de coordenadas tiene el eje X horizontal y el eje Y vertical con el origen [0, 0] en la esquina superior izquierda. Las coordenadas son integrales, en términos de píxeles, y coinciden con los centros de los píxeles. Cada ventana y pixmap tiene su propio sistema de coordenadas. Para una ventana, el origen está dentro del borde en la esquina interior superior izquierda.

La ventana creada aún no se muestra (mapeada), llama a xcb_map_window para mostrarla.

La ventana creada usará inicialmente el mismo cursor que su padre.

ARGUMENTOS DE LA SOLICITUD

El argumento opcional ... representa una lista de pares valor-campo. Los campos posibles para value_mask son:

XCB_CW_BACK_PIXMAP
Si se especifica un back-pixmap, este se usará para el fondo de la ventana. Si se especifica None, el fondo de la ventana será transparente.
XCB_CW_BACK_PIXEL
Si se especifica un back-pixel, este se usará para el fondo de la ventana. Si None se especifica, el fondo de la ventana será transparente.
XCB_CW_BORDER_PIXMAP
Si se especifica un border-pixmap, este se usará para el borde de la ventana. Si se especifica None, el borde de la ventana será transparente.
XCB_CW_BORDER_PIXEL
Si se especifica un border-pixel, este se usará para el borde de la ventana.
XCB_CW_BIT_GRAVITY
Establece la gravedad de bits de la ventana. Ver X(5) para más detalles.
XCB_CW_WINDOW_GRAVITY
Establece la gravedad de la ventana. Ver X(5) para más detalles.
XCB_CW_backing_store
Establece el comportamiento de almacenamiento auxiliar de la ventana. Ver X(5) para más detalles.
XCB_CW_LOAD_MEVEBOTICS
Establece el comportamiento de carga de la ventana. Ver X(5) para más detalles.
XCB_CW_SAVE_UNDER
Establece el comportamiento de guardado de la ventana. Ver X(5) para más detalles.
XCB_CW_EVENT_MASK
Establece la máscara de eventos para la ventana. Ver X(5) para más detalles.
XCB_CW_DONT_PROPAGATE
Establece la máscara de no propagación de eventos para la ventana. Ver X(5) para más detalles.
XCB_CW_COLORMAP
Si se especifica un mapa de colores, el mapa de colores del padre se copia (los cambios posteriores en el atributo del mapa de colores del padre no afectan al hijo). Sin embargo, la ventana debe tener el mismo tipo visual que el padre (o se produce un error de coincidencia), y el padre no debe tener un mapa de colores de None (o se produce un error de coincidencia). Para una explicación de None, ver la solicitud FreeColormap. El mapa de colores se copia compartiendo el objeto del mapa de colores entre el hijo y el padre, no haciendo una copia completa del contenido del mapa de colores.
XCB_CW_CURSOR
Si se especifica un cursor, se utilizará siempre que el puntero esté en la ventana. Si se especifica None, se usará el cursor del padre cuando el puntero esté en la ventana, y cualquier cambio en el cursor del padre provocará un cambio inmediato en el cursor mostrado.
