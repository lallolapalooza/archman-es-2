NOMBRE

xl2tpd.conf - Archivo de configuración de L2TPD

DESCRIPCIÓN

El archivo xl2tpd.conf contiene información de configuración para xl2tpd, la implementación gratuita del protocolo l2tp.

El archivo de configuración está compuesto por secciones y parámetros. Cada sección tiene un nombre dado que se utilizará al usar la FIFO de configuración (normalmente /var/run/xl2tpd/l2tp-control). Ver xl2tpd.8 para más detalles.

El nombre específico dado default especificará los parámetros aplicables a todas las secciones siguientes.

SECCIÓN GLOBAL

archivo de autenticación
Especifica dónde encontrar el archivo de autenticación utilizado para autenticar túneles l2tp. El valor predeterminado es /etc/xl2tpd/l2tp-secrets.
ipsec saref
Utiliza el seguimiento de asociación de seguridad IPsec. Cuando esto está activado, los paquetes recibidos por xl2tpd deben tener dos campos adicionales (refme y refhim) que permiten el seguimiento de múltiples clientes que utilizan la misma dirección IP NAT interna, y permiten el seguimiento de múltiples clientes detrás del mismo enrutador NAT. Esto necesita ser compatible con el kernel. Actualmente, esto solo funciona con Openswan KLIPS en modo "mast". (ver http://www.openswan.org/)

Establezca esto en sí y el sistema proporcionará valores SAref adecuados en las llamadas recvmsg().

Los valores pueden ser 'sí' o 'no'. El valor predeterminado es 'no'.

saref refinfo
Al utilizar el seguimiento de la asociación de seguridad IPsec, se utiliza un nuevo setsockopt. Dado que esto no es (todavía?) una opción oficial del kernel de Linux, hemos sido desplazados. Openswan hasta 2.6.35 para kernels de Linux hasta 2.6.35 utilizó un número saref de 22. Linux 3.6.36+ utiliza 22 para IP_NODEFRAG. Hemos movido nuestro IP_IPSEC_REFINFO a 30. Si no se establece, el valor predeterminado es usar 30. Para kernels antiguos con parches SAref, use 22.
listen-addr
La dirección IP de la interfaz en la que escucha el demonio. Por defecto, escucha en INADDR_ANY (0.0.0.0), lo que significa que escucha en todas las interfaces.
puerto
Especifica qué puerto UDP debe usar xl2tpd. El valor predeterminado es 1701.
control de acceso
Si se establece en 'sí', el proceso xl2tpd solo aceptará conexiones de direcciones de pares especificadas en las siguientes secciones. El valor predeterminado es 'no'.
debug avp
Establezca esto en 'sí' para habilitar la salida de syslog de información de depuración AVP de L2TP.
debug network
Establezca esto en 'sí' para habilitar la salida de syslog de información de depuración de red.
debug packet
Establezca esto en 'sí' para habilitar la impresión de información de depuración de paquetes L2TP. Nota: La salida va a STDOUT, así que úselo solo en conjunto con la opción de línea de comandos -D.
debug state
Establezca esto en 'sí' para habilitar la salida de syslog de información de depuración FSM.
debug tunnel
Establezca esto en 'sí' para habilitar la salida de syslog de información de depuración de túnel.
max intentos
Especifica cuántos reintentos antes de que se cierre un túnel. Si no hay túnel, deje de retransmitir. El valor predeterminado es 5.

SECCIÓN LNS

exclusivo
Si se establece en 'sí', solo se permitirá la construcción de un túnel de control entre 2 pares.
(no) rango ip
Especifica el rango de direcciones IP que el LNS asignará a los túneles PPP LAC que se conectan. Se pueden definir múltiples rangos. Usar la declaración 'no' prohíbe el uso de ese rango en particular. Los rangos se definen usando el formato IP - IP (ejemplo: 1.1.1.1 - 1.1.1.10). Tenga en cuenta que se debe proporcionar al menos una opción ip range, o debe establecer assign ip en no.
asignar ip
Establezca esto en 'no' si xl2tpd no debe asignar direcciones IP del pool definido con la opción ip range. Esto puede ser útil si tiene algún otro medio para asignar direcciones IP, por ejemplo, un pppd que admite RADIUS AAA.
(no) lac
Especifica las direcciones IP de los LAC que tienen permitido conectarse a xl2tpd actuando como LNS. El formato es el mismo que la opción ip range.
bit oculto
Si se establece en 'sí', xl2tpd utilizará la característica de ocultación de AVP de L2TP. Para obtener más información sobre AVP ocultos y AVP en general, consulte rfc2661 (¿añadir URL?)
ip local
Utiliza la siguiente IP como la propia dirección IP de xl2tpd.
rango ip local
Especifica el rango de direcciones que el LNS asignará como la dirección local a los túneles PPP LAC que se conectan. Esta opción es mutuamente exclusiva con la opción local ip y es útil en casos donde es deseable tener una dirección IP única para cada túnel. Especifique el valor del rango exactamente como la opción ip range. Tenga en cuenta que la opción assign ip no tiene ningún efecto en esta opción.
bit longitud
Si se establece en 'sí', se utilizará el bit de longitud presente en la carga útil del paquete l2tp.
(refuse | require) chap
Requerirá o rechazará la autenticación del par remoto a través de CHAP para la autenticación ppp.
(refuse | require) pap
Requerirá o rechazará la autenticación del par remoto a través de PAP para la autenticación ppp.
(refuse | require) authentication
Requerirá o rechazará la autenticación del par remoto.
autenticación unix
Si se establece en 'sí', se utilizará /etc/passwd para la autenticación ppp del par remoto.
nombre de host
Reportará esto como el nombre de host de xl2tpd en la negociación.
debug ppp
Esto habilitará la depuración para pppd.
pasar par
Pasa la dirección IP del par a pppd como ipparam. Habilitado por defecto.
pppoptfile
Especifica la ruta a un archivo que contiene parámetros de configuración de pppd a utilizar.
llamada rws
Esta opción está obsoleta y ya no funciona. Solía usarse para definir el tamaño de la ventana de control de flujo para llamadas o sesiones L2TP individuales. El estándar L2TP (RFC2661) ya no define el control de flujo ni los tamaños de ventana en llamadas o sesiones.
tunel rws
Esto define el tamaño de la ventana del canal de control. El tamaño de la ventana se define como el número de paquetes pendientes sin acuse de recibo, no como un número de bytes.
bits flujo
Si se establece en 'sí', se incluirán números de secuencia en la comunicación. La característica de uso de números de secuencia en sesiones está actualmente rota y no funciona.
desafío
Si se establece en 'sí', utiliza la autenticación de desafío para autenticar el par.
rx bps
Si se establece, el máximo de ancho de banda de recepción se establecerá en este valor.
tx bps
Si se establece, el máximo de ancho de banda de transmisión se establecerá en este valor.

SECCIÓN LAC

Las siguientes son banderas de configuración específicas de LAC. La mayoría de las descritas en la sección LNS pueden usarse en un contexto LAC, donde tiene sentido común (esencialmente, ajuste de protocolos l2tp

g flags and authentication / ppp related ones).

lns
Establece el nombre DNS o la dirección IP del LNS al que conectarse.
autodial
Si se establece en 'yes', xl2tpd marcará automáticamente al LAC durante el inicio.
redial
Si se establece en 'yes', xl2tpd intentará volver a marcar si la llamada se desconecta. Tenga en cuenta que, si está habilitado, xl2tpd mantendrá las contraseñas en memoria: un posible riesgo de seguridad.
redial timeout
Espera X segundos antes de volver a marcar. La opción redial debe establecerse en sí para usar esta opción. El valor predeterminado es 30 segundos.
max redials
Se rendirá en los intentos de volver a marcar después de X intentos.

ARCHIVOS

Archivo de control, utilizado por defecto.
