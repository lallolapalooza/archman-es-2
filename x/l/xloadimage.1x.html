XLOADIMAGE(1x) XLOADIMAGE(1x)

NOMBRE

xloadimage, xsetbg, xview - cargar imágenes en una ventana X11 o en la ventana raíz

SINOPSIS

xloadimage [opciones_globales] {[opciones_imagen] imagen ...}
xloadimage [opciones_globales] [opciones_imagen] stdin < imagen

DESCRIPCIÓN

Xloadimage muestra imágenes en una ventana X11, las carga en la ventana raíz o las escribe en un archivo. Se reconocen muchos tipos de imágenes; usa la opción -supported para listarlas.

Si se proporciona el nombre de archivo stdin, xloadimage leerá la imagen desde la entrada estándar si esta capacidad es compatible con el cargador para ese tipo de imagen (la mayoría de los tipos admiten la lectura desde stdin).

Si la pantalla de destino no puede soportar el número de colores de la imagen, la imagen se difuminará (destino monocromático) o se reducirá su tabla de colores (destino en color) según corresponda. Esto también se puede hacer forzosamente con las opciones -halftone, -dither y -colors.

Se puede especificar una variedad de manipulaciones de imágenes, incluyendo corrección gamma, brillo, recorte, difuminado, reducción de profundidad, rotación y zoom. La mayoría de estas manipulaciones tienen implementaciones sencillas; se priorizó la velocidad sobre la precisión.

Si estás viendo una imagen grande en una ventana, la ventana inicial tendrá como máximo el 90% del tamaño de la pantalla, a menos que el gestor de ventanas no maneje correctamente las solicitudes de tamaño de ventana o si has utilizado la opción -fullscreen. Puedes mover la imagen dentro de la ventana arrastrando con el primer botón del ratón. El cursor indicará en qué direcciones puedes arrastrar, si las hay. Puedes salir de la ventana escribiendo 'q' o '^C' cuando el foco del teclado esté en la ventana.

Si se especifican más de un archivo de imagen en la línea de comandos, cada imagen se mostrará en orden (excepto si se están utilizando -merge o -goto).

Se puede hacer una amplia variedad de manipulaciones comunes de imágenes combinando las opciones disponibles. Consulta la sección titulada CONSEJOS PARA BUENAS VISUALIZACIONES DE IMÁGENES para algunas ideas.

La opción -dump hace que una imagen se escriba en un archivo en lugar de mostrarse después de procesarla. Esto te permite leer una imagen, realizar una serie de operaciones de procesamiento sobre ella y guardar la imagen resultante. Esto también permite la traducción de cualquiera de los tipos de imagen reconocidos a cualquiera de los formatos que admiten volcado.

Xsetbg es equivalente a xloadimage -onroot -quiet y xview es equivalente a xloadimage -view -verbose.

CLASE DE RECURSOS

Xloadimage utiliza el nombre de clase de recurso Xloadimage para los gestores de ventanas que necesitan que este recurso esté configurado. Este nombre cambió en las versiones 2.00 y 2.01; algunas versiones anteriores utilizaban el nombre XLoadImage (que era difícil de predecir) o xloadimage (que entraba en conflicto con las convenciones de nomenclatura de clases).

OPCIONES GLOBALES

Las siguientes opciones afectan la operación global de xloadimage. Se pueden especificar en cualquier lugar de la línea de comandos. Adicionalmente, la opción -global puede usarse para forzar que una opción de imagen se aplique a todas las imágenes.

-borde color
Esto establece la porción de fondo de la ventana que no está cubierta por ninguna imagen a color.
-configuración
Muestra la ruta de las imágenes, los sufijos de las imágenes y los filtros soportados que se utilizarán al buscar y leer imágenes. Estos se cargan desde ~/.xloadimagerc y opcionalmente desde un archivo del sistema (normalmente /usr/lib/xloadimagerc). Esto reemplaza la opción -path.
-predeterminado
Utiliza el tramado raíz predeterminado como imagen. Esta opción fuerza -onroot. Si -predeterminado se usa solo, es lo mismo que xsetroot sin argumentos. Si se usa junto con -tile, esta opción se puede usar para colocar imágenes en el tramado raíz predeterminado (ver EJEMPLOS abajo).
-depuración
Habla con el servidor X en modo síncrono. Esto es útil para depurar. Si se ve un error X en este modo, se volcará un core.
-pantalla nombre_pantalla
Nombre de pantalla X11 a la que enviar la(s) imagen(es).
-volcar tipo_imagen[,opción[=valor]] archivo_volcado
En lugar de mostrar la imagen cargada y procesada, voltéala a un archivo de imagen del tipo especificado. Para obtener una lista de los tipos de imagen que se pueden volcar, usa la opción -supported. Algunos tipos de imagen tienen opciones que afectan el formato del archivo que se crea. Ver OPCIONES DE VOLCADO abajo. Una imagen se puede volcar en cualquier formato de volcado soportado independientemente del tipo de imagen original, por lo que la traducción de tipos de archivo de imagen es posible usando esta opción.
-ajustar
Forzar que la imagen use la visualización y tabla de colores predeterminadas. Esto es útil si no quieres efectos tecnicolor cuando el foco de la tabla de colores está dentro de la ventana de la imagen, pero puede reducir la calidad de la imagen mostrada. Esto está activado por defecto si se especifica -onroot o -windowid.
-bifurcar
Bifurca xloadimage. Esto hace que xloadimage se disocie del shell. Esta opción activa automáticamente -quiet.
-pantalla_completa
Utiliza toda la pantalla para mostrar imágenes. Si se combina con -onroot, la imagen se escalará para llenar toda la ventana raíz.
-geometría AxA[{+-X}{+-}Y]
Esto establece el tamaño de la ventana en la que se cargan las imágenes a un valor diferente al tamaño de la imagen. Al ver una imagen en una ventana, esto puede usarse para reducir el tamaño de la ventana de destino. Al cargar una imagen en la ventana raíz, esta opción controla el tamaño del pixmap que se cargará en la raíz. Si el tamaño es menor que el de la pantalla, la imagen se replicará.
-ir_a imagen_nombre
Forza que la siguiente imagen a mostrar sea la imagen llamada imagen_nombre. Esto es útil para generar presentaciones de diapositivas en bucle. Si hay más de una imagen con el mismo nombre que el objetivo en la lista de argumentos, se usa la primera en la lista de argumentos.
-ayuda [opción ...]
Proporciona información sobre una opción o lista de opciones. Si no se proporciona ninguna opción, se invoca una sencilla instalación de ayuda interactiva.
-identificar
Identifica las imágenes proporcionadas en lugar de mostrarlas.
-instalar
Instala forzosamente la tabla de colores de la imagen cuando la ventana tiene el foco. Esto viola los estándares ICCCM y solo existe para permitir la operación con gestores de ventanas ingenuos. Usa esta opción solo si tu gestor de ventanas no instala las tablas de colores correctamente.
-listar
Lista las imágenes que se encuentran en la ruta de las imágenes.
-en_raiz
Carga la(s) imagen(es) en la ventana raíz en lugar de verla(s) en una ventana. Esta opción establece automáticamente la opción -ajustar. Esto es lo opuesto a -ver. XSetbg tiene esta opción establecida por defecto.
-ruta
Muestra información diversa sobre la configuración del programa. Esta opción es obsoleta y ha sido reemplazada por -configuración.
-pixmap
Forzar el uso de un pixmap como respaldo. Esto se proporciona para servidores donde el respaldo está roto (como algunas versiones del servidor AIXWindows). Puede mejorar el rendimiento de desplazamiento en servidores que proporcionan respaldo.
-privado
Forzar el uso de una tabla de colores privada. Normalmente los colores se asignan compartidos a menos que no haya suficientes colores disponibles.
-silencioso
Forza que xloadimage y xview sean silenciosos. Este es el valor predeterminado para xsetbg, pero a los otros les gusta silbar.
-soportados
Lista los tipos de imagen soportados.

RUTAS Y EXTENSIONES

El archivo ~/.xloadimagerc (y opcionalmente un archivo global del sistema) define una serie de opciones de configuración que afectan a xloadimage.

Este archivo se divide en tres secciones: la sección path, la sección extension y la sección filter. Las secciones se identifican escribiendo el nombre de la sección seguido de un signo igual, por ejemplo, "path =".

La sentencia path se utiliza para proporcionar un conjunto de rutas de búsqueda que se utilizarán al buscar una imagen con un nombre especificado. Separa cada ruta en la lista con espacios en blanco (por ejemplo, uno o más espacios, tabulaciones o saltos de línea). La ruta se busca en el orden en que se especifica. Por ejemplo:

  path = ~/images /usr/local/images ~fred

primero buscará la imagen especificada, luego buscará el nombre en ~/images (la tilde se expande al valor de $HOME), luego en /usr/local/images, luego en el directorio personal del usuario fred. Esto permite un uso fácil de repositorios de imágenes.

La sentencia extension se utiliza para proporcionar un conjunto de extensiones predeterminadas que se utilizarán al buscar una imagen con un nombre especificado. Separa cada extensión en la lista con espacios en blanco. Las extensiones se buscan en el orden en que se especifican. Por ejemplo:

  extension = .gif .jpg

Si tienes un archivo llamado myimage.gif, podrías especificar el nombre myimage y xloadimage agregaría la extensión .gif automáticamente.

La sentencia filter se utiliza para describir programas de filtro, como "uncompress", que se aplicarán automáticamente a los archivos de imagen. Especificas un programa de filtro y cualquier número de extensiones reconocidas después de la palabra clave filter. Por ejemplo:

  filter = uncompress .Z

especifica que el programa uncompress se usará como filtro cada vez que un archivo de imagen tenga una extensión .Z. Por defecto, se proporcionan filtros para archivos comprimidos (.Z) y archivos GNU zip (.gz). Consulta la sección FILTROS para obtener más información sobre cómo definir tus propios filtros.

Cualquier texto en una línea después de una marca de almohadilla (#) se ignora; si deseas usar una marca de almohadilla en una ruta, extensión o filtro, puedes escaparla usando una barra invertida (\).

Si deseas incluir espacios en blanco en el nombre de un programa de filtro, ruta o extensión, puedes encerrar todo el texto entre comillas dobles. Por ejemplo:

  filter = "gzip -cd" .gz

Usa caracteres de barra invertida (\) para permitir la inclusión de comillas dobles o saltos de línea.

El siguiente es un ejemplo de archivo ~/.xloadimagerc:

  # rutas para buscar imágenes
  path = /usr/local/images        # repositorio de imágenes del sistema
        ~/images                 # imágenes personales
        /usr/include/X11/bitmaps # mapas de bits estándar de X
  # extensiones predeterminadas para imágenes
  extension = .csun .msun .sun .face .xbm .bm
  # invoca GNU zip si se encuentra una extensión .z o .zip
  filter = "gzip -cd" .z .zip

TIPOS DE IMAGEN

Xloadimage actualmente soporta muchos tipos de imagen comunes y algunos poco comunes, y puede crear imágenes en varios formatos. Para obtener una lista completa, utiliza la opción -supported.

VOLCANDO IMAGENES

Se incluyen varios volcado de imágenes que se pueden usar para crear una nueva imagen después de cargarla y procesarla. NIFF (Native Image File Format) es el más simple y crea imágenes que xloadimage puede leer más rápido; es esencialmente una copia del formato de imagen interno.

Algunos volcado de imágenes permiten opciones que afectan la salida de la imagen. Estas opciones se agregan al tipo de imagen después de una coma y se separan por comas. Si se desea un valor, se puede especificar después de un signo igual. Por ejemplo, para crear un archivo de imagen JPEG monocromático con un factor de calidad de 80, usarías la siguiente línea de comando:

  xloadimage image_name -dump jpeg,quality=80,grayscale new_image.jpg

Los nombres de las opciones se pueden abreviar, pero si la abreviatura es demasiado corta para ser única, la opción que se utilizará es indeterminada.

FILTROS

Xloadimage soporta filtrado automático reconociendo extensiones de archivo. Por defecto, se reconocen los archivos "compress" y "gzip" y sus nombres se pasan a los comandos apropiados para descomprimirlos.

La distribución de xloadimage incluye un decodificador especial "inteligente" de uudecode, llamado uufilter, que se puede usar para decodificar automáticamente archivos uu para su procesamiento. Uufilter ignora líneas extralimitadas en el archivo, por lo que es particularmente útil si el archivo uuencode fue creado concatenando correos electrónicos o publicaciones de noticias que tenían encabezados o indicadores de salto de línea incluidos.

Para utilizar uufilter, puedes agregar lo siguiente a tu archivo .xloadimagerc:

  filter = "uufilter -s" .uu .uue
El filtro se invocará automáticamente en cualquier archivo con una extensión .uu o .uue.

Para obtener una lista de los filtros reconocidos automáticamente por xloadimage, usa la opción -configuration.

OPCIONES DE IMAGEN SOPORTADAS

El volcado de imágenes JPEG soporta las siguientes opciones:

aritmetica
Usa codificación aritmética.
escala_de_grises
Forza la creación de una imagen monocromática (escala de grises) a partir de una imagen en color.
noentrelazado
Crea un archivo no entrelazado.
optimizar
Habilita la optimización del parámetro de entropía.
calidad
Ajusta la calidad de la imagen a crear. El factor de calidad predeterminado es 75; valores más bajos crean imágenes de menor calidad.
reinicio intervalo
Establece el intervalo de reinicio en filas MCU, o MCUs si 'b' sigue al valor del intervalo.
suavizado factor_de_suavizado
Establece el factor de suavizado. El valor debe estar entre 0 y 100, inclusive.

Si no estás familiarizado con el significado de estas opciones, puedes preguntar al Independent JPEG Group (IJG) por correo electrónico a jpeg@cs.columbia.edu.

El volcado de imágenes PBM soporta las siguientes opciones:

normal
Vuelca un archivo PBM/PPM normal (ascii).
crudo
Vuelca un archivo PBM/PPM en formato RawBits. Este es el valor predeterminado y da como resultado archivos de imagen significativamente más pequeños que al usar normal.

No hay forma de volcar un archivo en formato PGM o un archivo en formato PBM "compacto" (lo siento).

El volcado de imágenes TIFF soporta las siguientes opciones:

compresion
Técnica de compresión de datos de imagen. Puede ser una de: none (sin compresión), rle (compresión CCITT RLE), g3fax (compresión CCITT Group 3 FAX), g4fax (compresión CCITT Group 4 FAX), lzw (compresión Limpel-Ziv-Welsh, la predeterminada), jpeg (compresión JPEG), next (compresión por longitud de ejecución NeXT), rlew (compresión CCITT RLEW), mac (compresión Macintosh PackBits), packbits (igual que mac), thunderscan (compresión ThunderScan).

Xloadimage guardará usando las fotometrías MINISBLACK, MINISWHITE, COLORMAP o RGB según corresponda a su formato de imagen interno. No hay forma de especificar una fotometría particular ni ningún otro campo TIFF.

BUGS

Ampliar imágenes tramadas, especialmente hacia abajo, es HORRIBLE.

Las imágenes pueden venir en una variedad de relaciones de aspecto. Xloadimage no puede detectar qué relación de aspecto tiene la imagen particular que se está cargando, ni la relación de aspecto de la pantalla de destino, por lo que las imágenes con una relación de aspecto diferente de la pantalla de destino aparecerán distorsionadas. BUGS

The GIF format allows more than one image to be stored in a single GIF file, but xloadimage will only display the first.

Only GIF87a format is supported.

One of the pseudonyms for xloadimage, xview, is the same name as Sun uses for their SunView-under-X package. This will be confusing if you're one of those poor souls who has to use Sun's XView.

Some window managers do not correctly handle window size requests. In particular, many versions of the twm window manager use the MaxSize hint instead of the PSize hint, causing images which are larger than the screen to display in a window larger than the screen, something which is normally avoided. Some versions of twm also ignore the MaxSize argument's real function, to limit the maximum size of the window, and allow the window to be resized larger than the image. If this happens, xloadimage merely places the image in the upper-left corner of the window and uses the zero-value'ed pixel for any space which is not covered by the image. This behavior is less-than-graceful but so are window managers which are cruel enough to ignore such details.
