XSUBPP(1perl) Guía de Referencia para Programadores de Perl XSUBPP(1perl)

NOMBRE

xsubpp - compilador para convertir código XS de Perl a código C

SINOPSIS

xsubpp [-v] [-except] [-s patrón] [-prototipos] [-noversioncheck] [-nolinenumbers] [-nooptimize] [-typemap mapa_tipos] [-output nombre_archivo]... archivo.xs

DESCRIPCIÓN

Este compilador normalmente lo ejecutan los makefiles creados por ExtUtils::MakeMaker o por Module::Build u otras herramientas de construcción de módulos de Perl.

xsubpp compilará código XS a código C incrustando las construcciones necesarias para permitir que las funciones C manipulen valores de Perl y crea el pegamento necesario para permitir que Perl acceda a esas funciones. El compilador utiliza mapas de tipos (typemaps) para determinar cómo mapear parámetros y variables de funciones C a valores de Perl.

El compilador buscará archivos de mapa de tipos llamados typemap. Utilizará la siguiente ruta de búsqueda para encontrar mapas de tipos predeterminados, con el mapa de tipos más a la derecha teniendo precedencia.

../../../typemap:../../typemap:../typemap:typemap

También utilizará un mapa de tipos predeterminado instalado como "ExtUtils::typemap".

OPCIONES

Tenga en cuenta que la opción "XSOPT" de MakeMaker puede ser utilizada para añadir estas opciones a cualquier makefile generado por MakeMaker.

-hiertype
Conserva '::' en los nombres de tipos para que los tipos jerárquicos de C++ puedan ser mapeados.
-except
Añade stubs de manejo de excepciones al código C.
-typemap mapa_tipos
Indica que un mapa de tipos proporcionado por el usuario debe tener precedencia sobre los mapas de tipos predeterminados. Esta opción puede ser utilizada múltiples veces, con el último mapa de tipos teniendo la mayor precedencia.
-output nombre_archivo
Especifica el nombre del archivo de salida a generar. Si no se especifica ningún archivo, la salida se escribirá en la salida estándar.
-v
Imprime el número de versión de xsubpp en la salida estándar y luego sale.
-prototypes
Por defecto, xsubpp no generará automáticamente código de prototipo para todos los xsubs. Esta bandera habilitará los prototipos.
-noversioncheck
Deshabilita la prueba en tiempo de ejecución que determina si el archivo objeto (derivado del archivo ".xs") y los archivos ".pm" tienen el mismo número de versión.
-nolinenumbers
Evita la inclusión de directivas '#line' en la salida.
-nooptimize
Deshabilita ciertas optimizaciones. La única optimización que se ve afectada actualmente es el uso de targets por el código C de salida (ver perlguts). Esto puede ralentizar significativamente el código generado, pero así es como operaba xsubpp de la versión 5.005 y anteriores.
-noinout
Deshabilita el reconocimiento de las declaraciones "IN", "OUT_LIST" y "INOUT_LIST".
-noargtypes
Deshabilita el reconocimiento de descripciones de firmas de función similares a ANSI.
-C++
Actualmente no hace nada. Esta bandera ha sido un no-op durante muchas versiones de perl, al menos desde perl5.003_07. Se permite aquí por compatibilidad hacia atrás.
-s=... o -strip=...
Esta opción es oscura y no recomendada.

Si se especifica, la cadena dada se eliminará del principio del nombre de la función C en las funciones XS generadas (si comienza con ese prefijo). Esto solo se aplica a los XSUBs sin bloques "CODE" o "PPCODE". Por ejemplo, el XS:

void foo_bar(int i);

cuando se invoca "xsubpp" con "-s foo_" instalará una función "foo_bar" en Perl, pero realmente llamará a bar(i) en C. La mayoría de las veces, esto es lo contrario de lo que deseas y los modos de fallo son algo oscuros, así que por favor evita esta opción siempre que sea posible.

AMBIENTE

No se utilizan variables de entorno.

AUTOR

Originalmente por Larry Wall. Convertido al módulo "ExtUtils::ParseXS" por Ken Williams.
