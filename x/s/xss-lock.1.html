NOMBRE

xss-lock - usar un bloqueador externo como salvapantallas de X

SINOPSIS

xss-lock [-n cmd_notificador] [-s ID_sesión] [--ignore-sleep] [-l] [-v|-q] [--] bloqueador [arg] ...
xss-lock --help|--version

DESCRIPCIÓN

xss-lock conecta tu bloqueador favorito a la extensión de salvapantallas de MIT para X y también al gestor de inicio de sesión de systemd.

xss-lock debe ejecutarse en tu sesión X, ya sea iniciándolo en tu .xsessionrc o por otros medios específicos de la sesión (por ejemplo, configuración del gestor de ventanas). Ten en cuenta que xss-lock se ejecuta en primer plano (es decir, no se bifurca) y, por lo tanto, es posible que necesites ejecutarlo en segundo plano (por ejemplo, ejecutándolo con &).

El bloqueador se ejecuta en respuesta a eventos de estas dos fuentes:

  • Señales X cuando se fuerza la activación del salvapantallas o después de un período de inactividad del usuario (como se establece con xset s TIEMPO_ESPERA). En este último caso, el comando notificador, si se especifica, se ejecuta primero.
  • El gestor de inicio de sesión también puede solicitar que la sesión se bloquee; como resultado de loginctl lock-sessions, por ejemplo. Además, xss-lock utiliza la lógica de inhibición para bloquear la pantalla antes de que el sistema entre en suspensión.

xss-lock espera a que el bloqueador termine, o lo mata cuando se fuerza la desactivación del salvapantallas o el desbloqueo de la sesión, por lo que el comando no debería bifurcarse.

Además, xss-lock gestiona la sugerencia de inactividad en la sesión de inicio de sesión. El estado de inactividad de la sesión está directamente vinculado a la actividad del usuario según lo reportado por X (excepto cuando se ejecuta el notificador antes de bloquear la pantalla). Cuando todas las sesiones están inactivas, el gestor de inicio de sesión puede tomar medidas (como suspender el sistema) después de un retraso preconfigurado.

OPCIONES

-n cmd, --notifier=cmd
Ejecuta cmd cuando se activa el salvapantallas debido a la inactividad del usuario. Se admite el entrecomillado al estilo de shell. El notificador se mata con la señal SIGHUP cuando X señala actividad del usuario o con la señal SIGTERM cuando se inicia el bloqueador. El bloqueador se inicia después del primer ciclo del salvapantallas, como se establece con xset s TIEMPO_DE_ESPERA CICLO. Si el tiempo del ciclo del salvapantallas es 0, el notificador no se ejecuta y el bloqueador se inicia inmediatamente después del tiempo de espera.

Esto se puede usar para ejecutar una cuenta regresiva o (en portátiles) atenuar la pantalla antes de bloquearla. Para un ejemplo, consulta el script /usr/share/doc/xss-lock/dim-screen.sh.

Para un ejemplo sobre cómo usar las dos señales diferentes recibidas por el comando notificador, consulta el script /usr/share/doc/xss-lock/dim-screen2.sh.

-l, --transfer-sleep-lock
Permite que el proceso bloqueador herede el descriptor de archivo que representa el bloqueo de retardo obtenido del gestor de inicio de sesión. El índice correspondiente estará disponible en la variable de entorno $XSS_SLEEP_LOCK_FD; esto solo se establecerá si la razón para bloquear es que el sistema se está preparando para dormir. El bloqueador debe cerrar este descriptor de archivo para indicar que está listo.

Ejemplos de scripts que envuelven bloqueadores existentes están disponibles como /usr/share/doc/xss-lock/transfer-sleep-lock-*.sh.

-s ID, --session=ID
Usa la sesión con ID en lugar de la sesión actual.

Ejemplo: /usr/share/doc/xss-lock/xss-lock.service.

--ignore-sleep
No bloquear al suspender/hibernar.
-q, --quiet
Mostrar solo errores fatales.
-v, --verbose
Mostrar más mensajes.
-h, --help
Mostrar mensaje de ayuda y salir.
--version
Mostrar número de versión y salir.

SEÑALES

SIGHUP
Al recibir esta señal, xss-lock restablece el salvapantallas, pero solo si la pantalla no está bloqueada actualmente (a diferencia de xset s reset).

Esto se puede usar en la configuración de MPlayer como solución alternativa a la falla de MPlayer al reiniciar el temporizador del salvapantallas cuando la reproducción se pausa:

heartbeat-cmd="killall -HUP xss-lock"
stop-xscreensaver=false

NOTA:

Esto es ineficaz con mplayer2 (y mpv), porque su corazón sigue latiendo mientras la reproducción está en pausa.
SIGINT/SIGTERM
Al recibir esta señal, xss-lock sale después de matar cualquier notificador o bloqueador en ejecución.

NOTAS

•
Algunas aplicaciones dependen del script xdg-screensaver de xdg-utils, que utiliza xset s off y xset s default para suspender y reanudar el salvapantallas, respectivamente. Este último restablece el tiempo de espera y el ciclo a los valores predeterminados del servidor (xset s on utiliza un valor predeterminado codificado en lugar de eso), por lo que esto solo funciona si estás satisfecho con (o puedes controlar) la configuración del servidor.

Para corregir la acción de reanudación en este script (o una copia en ~/bin que preceda al original en $PATH), reemplaza on por tu tiempo de espera y ciclo preferidos, o evita los valores de tiempo codificados en el script ejecutando un bucle de suspensión como lo hace para otros salvapantallas, usando /usr/share/doc/xss-lock/xdg-screensaver.patch.

EJEMPLOS

•
Uso con xscreensaver a través de .xsessionrc (por lo tanto, en segundo plano):
xscreensaver &
xss-lock -- xscreensaver-command --lock &
•
Ejecutar xlock después de diez minutos de inactividad:
xset s 600
xss-lock xlock +resetsaver

Sin +resetsaver, xlock fuerza un reinicio del salvapantallas al inicio, diciendo así a xss-lock que mate inmediatamente a xlock de nuevo.

•
Atenuar la pantalla después de tres minutos de inactividad, bloquear la pantalla dos minutos después usando i3lock:
xset s 180 120
xss-lock -n dim-screen.sh -- i3lock -n

NOTA:

Se proporciona un script para usar el modo de bifurcación de i3lock con la opción --transfer-sleep-lock (ver arriba).
