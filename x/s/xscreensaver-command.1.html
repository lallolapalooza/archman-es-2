Paquete: xscreensaver

Licencias: BSD

XScreenSaver(1) General Commands Manual XScreenSaver(1)

NOMBRE

xscreensaver-command - controla un proceso xscreensaver en ejecución

SINOPSIS

xscreensaver-command [--display host:display.screen] [--help | --quiet | --verbose | --activate | --deactivate | --cycle | --next | --prev | --select n | --lock | --suspend | --exit | --restart | --time | --watch | --version]

DESCRIPCIÓN

El programa xscreensaver-command controla un demonio xscreensaver(1) en ejecución.

OPCIONES

xscreensaver-command acepta las siguientes opciones de línea de comandos:

--help
Imprime un breve resumen de las opciones de la línea de comandos.
--quiet
Solo imprime salida si ocurre un error.
--verbose
Opuesto a --quiet. Por defecto.
--activate
Indica a xscreensaver que se active inmediatamente (es decir, que ponga la pantalla en negro, como si el usuario hubiera estado inactivo el tiempo suficiente). El salvapantallas se desactivará tan pronto como haya alguna actividad del usuario, como de costumbre.
--deactivate
Esto indica a xscreensaver que simule actividad del usuario. Esto significa que si el salvapantallas está activo (la pantalla está en negro), este comando hará que la pantalla se ilumine como si hubiera habido actividad del teclado o del ratón. Si la pantalla está bloqueada, primero aparecerá el diálogo de contraseña, como de costumbre. Si la pantalla no está en negro, esta actividad simulada del usuario reiniciará la cuenta atrás (por lo tanto, emitir el comando --deactivate periódicamente es *una* forma de evitar que la pantalla se ponga en negro).
--cycle
Si el salvapantallas está activo (la pantalla está en negro), detiene la demostración gráfica actual y ejecuta una nueva (elegida al azar).
--next
Esto es como --activate o --cycle, dependiendo de cuál sea más apropiado, excepto que el hack gráfico que se ejecutará es el siguiente en la lista, en lugar de uno elegido al azar. En otras palabras, ejecutar repetidamente --next hará que el proceso xscreensaver invoque cada demostración gráfica secuencialmente. (Aunque usar la opción --settings es probablemente una forma más fácil de lograr eso).
--prev
Esto es como --next, pero cicla en la dirección opuesta.
--select número
Como --activate, pero ejecuta el N-ésimo elemento en la lista de hacks. Sabiendo qué hay en la lista programs, y en qué orden, puedes usar esto para activar el salvapantallas con una demostración gráfica particular. (El primer elemento de la lista se numera 1, no 0).
--lock
Indica al proceso xscreensaver en ejecución que bloquee la pantalla inmediatamente. Esto es como --activate, pero también fuerza el bloqueo, incluso si el bloqueo no es el predeterminado (es decir, incluso si el recurso lock de xscreensaver es falso, y aunque el recurso lockTimeout no sea cero).

Tenga en cuenta que el bloqueo no funciona a menos que el proceso xscreensaver se esté ejecutando como usted. Consulte xscreensaver(1) para obtener detalles.

--suspend
Como --activate, pero ignora lockTimeout y apaga la pantalla inmediatamente sin atenuación. Esto está diseñado para ejecutarse justo después de cerrar la tapa de su portátil, y justo antes de que la CPU se detenga, para bloquear las cosas rápidamente.
--exit
Hace que el proceso xscreensaver salga elegantemente. Esto no hace nada si la pantalla está actualmente bloqueada. **Advertencia:** nunca use kill -9 con xscreensaver. Eso puede dejar las cosas en un estado inconsistente, y es posible que deba cerrar la sesión para reparar el daño.
--restart
Hace que el proceso salvapantallas salga y luego se reinicie con los mismos argumentos de línea de comandos que la última vez. Realmente no debería necesitar hacer esto, ya que xscreensaver detecta cuándo cambia el archivo .xscreensaver y lo vuelve a leer según sea necesario.
--time
Imprime la hora en que el salvapantallas se activó o desactivó por última vez (aproximadamente, cuánto tiempo ha estado inactivo o activo el usuario: pero no exactamente, ya que solo le dice cuándo la pantalla se puso en negro o se iluminó).
--watch
Imprime una línea cada vez que el salvapantallas cambia de estado: cuando la pantalla se pone en negro, se bloquea, se ilumina o cuando se cambia el hack en ejecución. Esta opción nunca regresa; está destinada a ser utilizada por scripts de shell que desean reaccionar al salvapantallas de alguna manera. Un ejemplo de su salida sería: 
BLANK Vie Nov  5 01:57:22 1999
RUN 34
RUN 79
RUN 16
LOCK Vie Nov  5 01:57:22 1999
RUN 76
RUN 12
UNBLANK Vie Nov  5 02:05:59 1999
Lo anterior muestra que el salvapantallas se activó, ejecutó tres hacks diferentes, luego se bloqueó (quizás porque expiró el tiempo de espera de bloqueo) y luego se iluminó (porque el usuario se activó e ingresó la contraseña correcta). Los números de hack son su índice en la lista `programs' (comenzando con 1, no 0, como para el comando --select).

Por ejemplo, supongamos que desea ejecutar un programa que baja el volumen de su máquina cuando la pantalla se pone en negro y lo sube cuando la pantalla se ilumina. Podría hacerlo ejecutando un programa de Perl como el siguiente en segundo plano. El siguiente programa rastrea la salida del comando --watch y reacciona en consecuencia:

#!/usr/bin/perl
my $blanked = 0;
open (my $in, "xscreensaver-command -watch |") || die;
while (<$in>) {
  if (m/^(BLANK|LOCK)/) {
    if (!$blanked) {
      system ("sound-off");
      $blanked = 1;
    }
  } elsif (m/^UNBLANK/) {
    system ("sound-on");
    $blanked = 0;
  }
}
Tenga en cuenta que LOCK puede venir precedido o no por BLANK (dependiendo de si el tiempo de espera de bloqueo no es cero), por lo que el programa anterior realiza un seguimiento de ambos.
--version
Imprime la versión de xscreensaver que se está ejecutando actualmente en la pantalla: es decir, el número de versión real del proceso de fondo de xscreensaver en ejecución, en lugar del número de versión de xscreensaver-command. (Para ver el número de versión de xscreensaver-command en sí, use la opción --help).

DETENER GRÁFICOS

Si xscreensaver se está ejecutando, pero desea que deje de ejecutar hacks de pantalla (por ejemplo, si está conectado de forma remota y desea que la consola permanezca bloqueada pero simplemente negra, sin procesos gráficos en ejecución) puede lograrlo simplemente apagando el monitor de forma remota. En un minuto o dos, xscreensaver notará que el monitor está apagado y dejará de ejecutar hacks de pantalla. Puede apagar el monitor de esta manera:

xset dpms force off

Consulte el manual de xset(1) para más información.

También puede usar xscreensaver-settings(1) para configurar el monitor para que se apague después de unas horas, lo que significa que xscreensaver ejecutará gráficos hasta que haya estado inactivo durante el tiempo especificado; y después de eso, el monitor se apagará y no se ejecutarán más hacks de pantalla.

DIAGNÓSTICOS

Si ocurre un error al comunicarse con el demonio xscreensaver, o si el demonio informa un error, se imprimirá un mensaje de diagnóstico en stderr y xscreensaver-command saldrá con un valor distinto de cero. Si el comando se acepta, se imprimirá una indicación de esto en stdout y el valor de salida será cero.

ENTORNO

DISPLAY
para obtener el host y el número de pantalla del salvapantallas que se va a manipular.

PATH

PATH
para encontrar el ejecutable para reiniciar (para el comando --restart). Tenga en cuenta que esta variable se consulta en el entorno del proceso xscreensaver, no en el proceso xscreensaver-command.
