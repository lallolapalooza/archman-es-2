XScreenSaver(1) Manual de comandos generales XScreenSaver(1)

NOMBRE

xscreensaver - framework extensible de salvapantallas y bloqueo de pantalla

SINOPSIS

xscreensaver [--display host:display.screen] [--verbose] [--version] [--no-splash] [--log nombre_archivo]

DESCRIPCIÓN

XScreenSaver espera hasta que el usuario está inactivo y luego ejecuta demostraciones gráficas elegidas al azar. También puede bloquear tu pantalla y proporciona configuración y control de la gestión de energía de la pantalla.

XScreenSaver también está disponible en macOS, iOS y Android.

PRIMEROS PASOS

XScreenSaver es un demonio que se ejecuta en segundo plano. Lo configuras con el programa xscreensaver-settings(1).

xscreensaver &
xscreensaver-settings

CÓMO FUNCIONA

Cuando es hora de activar el salvapantallas, se crea una ventana negra a pantalla completa que cubre cada monitor. Se lanza un subproceso para cada uno ejecutando una demostración gráfica, apuntando a la ventana correspondiente. Debido a esto, cualquier programa que pueda dibujar en una ventana proporcionada puede usarse como salvapantallas. Las diversas demostraciones gráficas son, de hecho, solo programas independientes que hacen eso.

Cuando el usuario vuelve a estar activo, las ventanas del salvapantallas se desmapean y los subprocesos en ejecución se matan.

Los modos de visualización se ejecutan con una prioridad de proceso baja y pasan la mayor parte del tiempo durmiendo/inactivos por defecto, por lo que no deberían consumir recursos significativos del sistema.

OPCIONES DE LÍNEA DE COMANDOS

--display host:display.screen
La pantalla X a utilizar. Para pantallas con múltiples pantallas, XScreenSaver gestionará todas las pantallas de la pantalla simultáneamente.
--verbose
Imprime diagnósticos en stderr.
--version
Imprime el número de versión y sale.
--log nombre_archivo
Añade toda la salida de diagnóstico al archivo dado. Esto también implica --verbose. Utiliza esto al informar de errores.
--no-splash
No muestres la pantalla de bienvenida al inicio.

GESTIÓN DE ENERGÍA

El programa xscreensaver-settings(1) es donde configuras si y cuándo tu monitor debe apagarse. Guarda la configuración en tu archivo ~/.xscreensaver. No uses xset(1) para cambiar manualmente la configuración de gestión de energía, eso no funcionará.

Cuando el monitor se apaga, las demostraciones gráficas dejan de ejecutarse (aunque puede tardar uno o dos minutos en que XScreenSaver lo note).

TAPAS DE PORTÁTILES

Si tu sistema usa systemd(1) o elogind(8), entonces cerrar la tapa de tu portátil bloqueará la pantalla inmediatamente.

Si no, entonces la pantalla podría no bloquearse hasta unos segundos después de volver a abrir la tapa. Lo cual es menos que ideal. Así que si no tienes systemd(1), podrías acostumbrarte a bloquear manualmente tu pantalla antes de cerrar la tapa (xscreensaver-command --lock).

REPRODUCCIÓN DE VÍDEOS

Igualmente, si tienes systemd(1) o elogind(8), entonces todos los reproductores de vídeo y navegadores web populares evitarán que XScreenSaver apague la pantalla mientras se reproduce vídeo.

Ambas características requieren que xscreensaver-systemd(6) pueda conectarse a D-Bus.

INSTALACIÓN

Cada entorno de escritorio tiene su propio sistema para lanzar demonios de larga ejecución como XScreenSaver, y dado que muchos vienen incluidos con sus propios frameworks de bloqueo de pantalla (defectuosos, inseguros, inferiores), también es necesario deshabilitar esos otros frameworks antes de que XScreenSaver pueda funcionar.

INSTALAR XSCREENSAVER EN GNOME O UNITY

Durante muchos años, GNOME incluyó XScreenSaver tal cual, ¡y todo funcionaba! ¡Ya no!

1: Desinstala completamente los otros paquetes de salvapantallas:
	sudo apt remove gnome-screensaver
	sudo apt remove mate-screensaver
	sudo apt remove cinnamon-screensaver
	sudo apt remove light-locker
o
	sudo rpm -e gnome-screensaver
	sudo rpm -e mate-screensaver
	sudo rpm -e cinnamon-screensaver
	sudo rpm -e light-locker
Ten cuidado de que no intente desinstalar todo GNOME.
2: Desactiva el oscurecimiento de pantalla integrado de GNOME.
Establece todos los siguientes ajustes en "Nunca" u "Apagado", ya que todos estos son controlados ahora por xscreensaver-settings(1):

"Ajustes / Privacidad / Bloqueo de pantalla / Retraso al oscurecer la pantalla"
"Ajustes / Privacidad / Bloqueo de pantalla / Bloqueo de pantalla automático"
"Ajustes / Energía / Oscurecer pantalla"
"Ajustes / Energía / Suspensión automática"

3: Lanza XScreenSaver al iniciar sesión.
Lanza "Ajustes" (Tweaks), selecciona "Aplicaciones de inicio", haz clic en el signo más y selecciona "XScreenSaver" (no "Ajustes de XScreenSaver") de la lista (muy larga).

O, consulta la sección "LANZAR XSCREENSAVER DESDE SYSTEMD" a continuación. Eso también funciona.

4: Haz que el icono "Bloquear" de GNOME use XScreenSaver.
Esto solía funcionar, pero ya no con GNOME 3.38. Si lo averiguas, ¡dímelo! Esto todavía funciona para Cinnamon 4.8 y MATE 1.24: 
sudo ln -sf /usr/bin/xscreensaver-command \
       /usr/bin/gnome-screensaver-command
sudo ln -sf /usr/bin/xscreensaver-command \
    /usr/bin/cinnamon-screensaver-command
sudo ln -sf /usr/bin/xscreensaver-command \
        /usr/bin/mate-screensaver-command
sudo ln -sf /usr/bin/xscreensaver-command \
       /usr/bin/xfce4-screensaver-command
sudo ln -sf /usr/bin/xscreensaver-command \
            /usr/bin/light-locker-command
Este cambio se perderá cuando actualices.

EL ACCESO AL SERVIDOR X ES EL FIN DEL JUEGO

El modelo de seguridad de X11 es todo o nada. Si un programa puede conectarse a tu servidor X, ya sea localmente o a través de la red, puede registrar todas tus pulsaciones de teclas, simular pulsaciones de teclas, lanzar programas arbitrarios y cambiar la configuración de otros programas. Asume que cualquier cosa que pueda conectarse a tu servidor X puede ejecutar código arbitrario como el usuario conectado. Ver Xsecurity(1) y xauth(1).

CONTRASEÑAS PAM

Si tu sistema utiliza PAM (Módulos de Autenticación Conectables), entonces PAM debe estar configurado para XScreenSaver. Si no lo está, *podrías* encontrarte en una situación en la que no puedas desbloquear. Probablemente el archivo que necesitas sea /etc/pam.d/xscreensaver.

NO INICIES SESIÓN COMO ROOT

Nunca inicies sesión como root. Inicia sesión como un usuario normal y utiliza sudo(1) según sea necesario. Si inicias sesión como root, XScreenSaver no bloqueará tu pantalla ni ejecutará modos de visualización, por numerosas razones buenas y apropiadas.

CONFIGURACIÓN MULTIUSUARIO O PARA TODO EL SITIO

Para un solo usuario, la forma correcta de configurar XScreenSaver es simplemente ejecutar el programa xscreensaver-settings(1) y cambiar la configuración a través de la GUI. Los cambios se escriben en el archivo ~/.xscreensaver.

Si deseas establecer los valores predeterminados para todo el sistema, realiza tus ediciones en /etc/X11/app-defaults/XScreenSaver en su lugar. Los dos archivos tienen una sintaxis similar (pero no idéntica).

También puedes realizar cambios a través de la Base de Datos de Recursos X y xrdb(1), pero eso puede ser muy confuso y no se recomienda realmente.

Las opciones en ~/.xscreensaver anulan cualquier configuración en la base de datos de recursos o en el archivo de app-defaults.

Si cambias una configuración en el archivo .xscreensaver mientras XScreenSaver ya se está ejecutando, lo notará y recargará el archivo según sea necesario. Pero si cambias una configuración en la Base de Datos de Recursos X, deberás reiniciar XScreenSaver para que esos cambios surtan efecto:

xrdb < ~/.Xdefaults
xscreensaver-command --restart

RECURSOS X

Estos son los recursos X utilizados por el programa XScreenSaver. Probablemente no necesitarás cambiarlos manualmente: para eso está el programa xscreensaver-settings(1).

timeout (clase Time)
El salvapantallas se activará (desactivará la pantalla) después de que el teclado y el ratón hayan estado inactivos durante esta cantidad de minutos. Por defecto, 10 minutos.
cycle (clase Time)
Después de que el salvapantallas se haya estado ejecutando durante esta cantidad de minutos, el subproceso de hack gráfico que se está ejecutando actualmente se cerrará (con SIGTERM) y se iniciará uno nuevo. Si esto es 0, entonces el hack gráfico nunca se cambiará: solo se ejecutará una demostración hasta que el salvapantallas sea desactivado por la actividad del usuario. Por defecto, 10 minutos.

Si hay varias pantallas, los salvapantallas se escalonan ligeramente para que, si bien todos cambian cada cycle minutos, no todos cambian al mismo tiempo.

lock (clase Boolean)
Habilita el bloqueo: antes de que el salvapantallas se desactive, requerirá que escribas la contraseña del usuario conectado.
lockTimeout (clase Time)
Si el bloqueo está habilitado, esto controla la duración del "período de gracia" entre la activación del salvapantallas y el bloqueo de la pantalla. Por ejemplo, si esto es 5 y timeout es 10, entonces después de 10 minutos, la pantalla se desvanecerá. Si hubo actividad del usuario a los 12 minutos, no se requerirá contraseña para volver a activar la pantalla. Pero, si hubo actividad del usuario a los 15 minutos o más tarde (es decir, lockTimeout minutos después de la activación), entonces se requerirá una contraseña. El valor predeterminado es 0, lo que significa que si el bloqueo está habilitado, se requerirá una contraseña tan pronto como la pantalla se desactive.
passwdTimeout (clase Time)
Si la pantalla está bloqueada, este es el número de segundos que el cuadro de diálogo de contraseña permanecerá en la pantalla antes de rendirse (por defecto, 30 segundos). Se añaden unos pocos segundos cada vez que escribes un carácter.
dpmsEnabled (clase Boolean)
Si la gestión de energía está habilitada.
dpmsStandby (clase Time)
Si la gestión de energía está habilitada, cuánto tiempo hasta que el monitor se ponga completamente negro.
dpmsSuspend (clase Time)
Si la gestión de energía está habilitada, cuánto tiempo hasta que el monitor entre en modo de ahorro de energía.
dpmsOff (clase Time)
Si la gestión de energía está habilitada, cuánto tiempo hasta que el monitor se apague por completo. Ten en cuenta que estos ajustes no tendrán ningún efecto a menos que tanto el servidor X como el hardware de visualización admitan la gestión de energía; no todos lo hacen. Ver la sección Gestión de Energía, a continuación, para más información.
dpmsQuickOff (clase Boolean)
Si mode es blank y esto es verdadero, entonces la pantalla se apagará inmediatamente al desactivarse, independientemente de otros ajustes de gestión de energía.
verbose (clase Boolean)
Si imprimir diagnósticos. Por defecto, falso.
splash (clase Boolean)
Si mostrar una pantalla de bienvenida al inicio. Por defecto, verdadero.
splashDuration (clase Time)
Cuánto tiempo debe permanecer visible la pantalla de bienvenida; por defecto, 5 segundos.
helpURL (clase URL)
La pantalla de bienvenida tiene un botón de Ayuda. Cuando lo presionas, mostrará la página web indicada aquí en tu navegador web.
loadURL (clase LoadURL)
Este es el comando de shell utilizado para cargar una URL en tu navegador web.
demoCommand (clase DemoCommand)
Este es el comando de shell que se ejecuta cuando se presiona el botón Demo en la ventana de bienvenida. Por defecto, es xscreensaver-settings(1).
newLoginCommand (clase NewLoginCommand)
Si está configurado, este es el comando de shell que se ejecuta cuando se presiona el botón "Nuevo Inicio de Sesión" en el cuadro de diálogo de desbloqueo, para crear una nueva sesión de escritorio sin cerrar la sesión del usuario que ha bloqueado la pantalla. Típicamente, será alguna variante de gdmflexiserver(1), kdmctl(1), lxdm(1) o dm-tool(1).
nice (clase Nice)
Los subprocesos lanzados por XScreenSaver serán "nicados" a este nivel, de modo que tengan una prioridad menor que otros procesos en el sistema y no aumenten la carga innecesariamente. El valor predeterminado es 10. (Números más altos significan menor prioridad; ver nice(1) para detalles.)
fade (clase Boolean)
Si esto es verdadero, entonces cuando el salvapantallas se activa, el escritorio se desvanecerá a negro en lugar de desaparecer simplemente. Por defecto: verdadero.
unfade (clase Boolean)
Si esto es verdadero, entonces cuando el salvapantallas se desactiva, el escritorio se desvanecerá de vuelta en lugar de aparecer inmediatamente. Esto solo se hace si fade también es verdadero. Por defecto: verdadero.
fadeSeconds (clase Time)
Si fade es verdadero, esta es la duración del desvanecimiento en segundos. Por defecto, 3 segundos.
ignoreUninstalledPrograms (clase Boolean)
Puede haber programas en la lista que no estén instalados en el sistema, pero que estén marcados como "habilitados". Si esta preferencia es verdadera, entonces tales programas simplemente serán ignorados. Si es falso, se imprimirá una advertencia si se intenta ejecutar el programa inexistente. Además, el programa xscreensaver-settings(1) suprimirá los programas inexistentes de la lista si esto es verdadero. Por defecto: falso.
authWarningSlack (clase Integer)
Después de desbloquear la pantalla con éxito, puede aparecer un cuadro de diálogo informándote de intentos de inicio de sesión fallidos anteriores. Si todos esos intentos de inicio de sesión ocurrieron dentro de este período de tiempo, se ignoran. La suposición es que las contraseñas incorrectas ingresadas a los pocos segundos de una correcta son un error del usuario, en lugar de una acción hostil. Por defecto, 20 segundos.

OPTIONS

Los siguientes recursos pueden ser establecidos en el archivo .Xresources o en el archivo .xscreensaver, o ser establecidos en la línea de comandos.

mode
Modo de selección de programas. Puede ser uno de los siguientes:
random
Elige un modo de visualización aleatorio de entre los que están habilitados y son aplicables. Este es el valor predeterminado.
random-same
Similar a random, pero si hay múltiples pantallas, cada pantalla ejecutará el mismo modo de visualización aleatorio, en lugar de que cada pantalla ejecute uno diferente.
one
Al atenuar la pantalla, utiliza siempre un modo de visualización particular (el indicado por la configuración selected).
blank
Al atenuar la pantalla, simplemente se pone negra: no ejecuta ningún efecto gráfico.
off
Nunca atenúa la pantalla, y nunca permite que el monitor se apague.
selected (clase Integer)
Cuando mode está configurado como one, este es el modo seleccionado, indicado por su índice en la lista de programs. ¡Estarías loco si los contaras y establecieras este número manualmente: deja que xscreensaver-settings(1) lo haga por ti!
programs (clase Programs)
Los efectos gráficos que XScreenSaver ejecuta cuando el usuario está inactivo. El valor de este recurso es una cadena de múltiples líneas, un comando por línea en sintaxis sh. Cada línea debe contener exactamente un comando: sin puntos y comas, sin ampersands.

Cuando el salvapantallas se inicia, uno de estos se selecciona (según la configuración de mode) y se ejecuta. Después de que expira el período de cycle, se termina, y se selecciona y ejecuta otro.

Si una línea comienza con un guion (-) entonces ese programa en particular está deshabilitado: no será seleccionado aleatoriamente (aunque aún puedes seleccionarlo explícitamente usando el programa xscreensaver-settings(1)).

Si todos los programas están deshabilitados, entonces la pantalla simplemente se pondrá negra, como cuando mode está configurado como blank.

Para deshabilitar un programa, debes marcarlo como deshabilitado con un guion en lugar de eliminarlo de la lista. Esto se debe a que la configuración global del sistema (app-defaults) y la del usuario (.xscreensaver) se fusionan, y si un usuario simplemente elimina una entrada de su lista de programas, pero esa entrada todavía existe en la lista global del sistema, entonces volverá a aparecer. Sin embargo, si el usuario lo deshabilita, su configuración tiene prioridad.

El directorio predeterminado de efectos de XScreenSaver (típicamente /usr/libexec/xscreensaver/) se antepone a $PATH antes de buscar estos programas.

Para usar un programa como salvapantallas, debe ser capaz de dibujar en la ventana que se le proporciona en la variable de entorno $XSCREENSAVER_WINDOW. Si crea y mapea su propia ventana en su lugar, no funcionará. Debe dibujar en la ventana proporcionada.

Visuales:

Dado que XScreenSaver se creó cuando los dinosaurios deambulaban por la tierra, todavía contiene soporte para algunas cosas que probablemente nunca has visto, como monitores monocromáticos de 1 bit, monitores en escala de grises y monitores capaces de mostrar solo imágenes con mapeo de color de 8 bits.

Si hay algunos programas que deseas ejecutar solo cuando se usa una pantalla en color, y otros que deseas ejecutar solo cuando se usa una pantalla monocromática, puedes especificarlo así:

mono:   mono-program  -root        \n\
color:  color-program -root        \n\
Más generalmente, puedes especificar el tipo de visual que se debe usar para la ventana en la que el programa dibujará. Por ejemplo, si un programa funciona mejor si tiene un mapa de color, pero otro funciona mejor si tiene un visual de 24 bits, ambos pueden ser acomodados: 
PseudoColor: cmap-program  -root   \n\
TrueColor:   24bit-program -root   \n\
Además de los nombres de visual simbólicos descritos anteriormente (en la discusión del recurso visualID), se admite otro nombre de visual en la lista de programs:
default-n
Esto es como default, pero también solicita el uso del mapa de color predeterminado, en lugar de un mapa de color privado.

Si especificas un visual particular para un programa, y ese visual no existe en la pantalla, entonces ese programa no será elegido para ejecutarse. Esto significa que en pantallas con múltiples pantallas de diferentes profundidades, puedes organizar que se ejecuten efectos apropiados en cada una. Por ejemplo, si una pantalla es en color y la otra es monocromática, los efectos que se ven bien en mono se pueden ejecutar en una, y los efectos que solo se ven bien en color aparecerán en la otra.

visualID (clase VisualID)
Esto es un artefacto histórico que quedó de cuando las pantallas de 8 bits todavía eran comunes. Probablemente deberías ignorar esto.

Especifica qué visual de X usar por defecto. (Nota cuidadosamente que este recurso se llama visualID, no simplemente visual; si configuras el recurso visual en su lugar, las cosas funcionarán mal de maneras oscuras por razones oscuras.)

Los valores válidos para el recurso VisualID son:

default
Usa el visual predeterminado de la pantalla (el visual de la ventana raíz). Este es el valor predeterminado.
best
Usa el visual que soporte más colores. Ten en cuenta, sin embargo, que el visual con más colores podría ser un visual TrueColor, que no soporta animación de mapas de color. Algunos programas tienen un comportamiento más interesante cuando se ejecutan en visuales PseudoColor que en TrueColor.
mono
Usa un visual monocromático, si lo hay.
gray
Usa un visual en escala de grises o staticgray, si lo hay y tiene más de un plano (es decir, no es monocromático).
color
Usa el mejor de los visuales en color, si los hay.
GL
Usa el visual que sea mejor para programas OpenGL. (Los programas OpenGL tienen requisitos algo diferentes a los de otros programas X.)
class
donde class es uno de StaticGray, StaticColor, TrueColor, GrayScale, PseudoColor, o DirectColor. Selecciona el visual más profundo de la clase dada.
N
donde number (decimal o hexadecimal) se interpreta como un número de ID de visual, como lo informa el programa xdpyinfo(1); de esta manera puedes tener un control más fino sobre exactamente qué visual se usará, por ejemplo, para seleccionar uno menos profundo de lo que se habría elegido de otra manera.

Ten en cuenta que esta opción especifica solo el visual *predeterminado* que se usará: el visual utilizado puede ser anulado programa por programa. Ver la descripción del recurso programs, arriba.

installColormap (clase Boolean)
Esto es un artefacto histórico que quedó de cuando las pantallas de 8 bits todavía eran comunes. En pantallas PseudoColor (de 8 bits), instala un mapa de color privado mientras el salvapantallas está activo, para que los efectos gráficos puedan obtener tantos colores como sea posible. Este es el valor predeterminado. (Esto solo se aplica cuando se está utilizando el visual predeterminado de la pantalla, ya que los visuales no predeterminados obtienen sus propios mapas de color automáticamente). Esto también puede ser anulado por efecto individual: ver la discusión del nombre default-n en la sección sobre el recurso programs.

Esto no hace nada si tienes una pantalla TrueColor (de 16 bits o más profunda). (Lo cual, en este siglo, tienes.)

pointerHysteresis (clase Integer)
Si el ratón se mueve menos de esta cantidad de píxeles por segundo, ignóralo (no lo consideres como "actividad"). Esto es para que la pantalla no se reactive (o no logre atenuarse) solo porque golpeaste el escritorio. Predeterminado: 10 píxeles.

Un solo píxel de movimiento aún provocará que el monitor se encienda nuevamente, pero no que se desatenúe. Esto se debe a que el servidor X11 en sí mismo, desafortunadamente, maneja la detección de actividad relacionada con la gestión de energía en lugar de XScreenSaver.
