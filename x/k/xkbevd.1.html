XKBEVD(1) Manual de comandos generales XKBEVD(1)

NOMBRE

xkbevd - demonio de eventos XKB

SINOPSIS

xkbevd [ opciones ]

DESCRIPCIÓN

Este comando es muy rudimentario y, por lo tanto, solo está parcialmente implementado; lo presentamos aquí como un prototipo para desarrolladores, no como una herramienta de propósito general para usuarios finales. Algo como esto podría ser un reemplazo adecuado para xev; No me comprometo, pero es una idea interesante.

El demonio de eventos xkbevd escucha eventos XKB especificados y ejecuta los comandos solicitados si ocurren. El archivo de configuración consiste en una lista de pares de especificación de evento/acción y/o definiciones de variables.

Una especificación de evento consiste en un nombre corto de evento XKB seguido de una cadena o identificador que sirve como calificador entre paréntesis; los paréntesis vacíos indican que no hay calificación y sirven para especificar el comando predeterminado que se aplica a los eventos que no coinciden con ninguna de las otras especificaciones. La interpretación del calificador depende del tipo de evento: los eventos Bell coinciden usando el nombre de la campana, los eventos message coinciden con el contenido de la cadena del mensaje y las teclas lentas aceptan cualquiera de press, release, accept o reject. Actualmente no se reconocen otros eventos.

Una acción consiste en una palabra clave opcional seguida de un argumento de cadena opcional. Actualmente, xkbev reconoce las acciones: none, ignore, echo, printEvent, sound y shell. Si la acción no se especifica, la cadena se toma como el nombre de un archivo de sonido que se reproducirá, a menos que comience con un signo de exclamación, en cuyo caso se toma como un comando de shell.

Las definiciones de variables en la cadena de argumento se expanden con campos del evento en cuestión antes de que la cadena de argumento se pase al procesador de acciones. La sintaxis general de una variable es $c o $(str), donde c es un solo carácter y str es una cadena de longitud arbitraria. Todos los parámetros tienen nombres de un solo carácter y nombres largos.

La lista de parámetros reconocidos varía de un evento a otro y es demasiado larga para enumerarla aquí en este momento. De todos modos, esta es una versión para desarrolladores, por lo que se espera que consulte el código fuente (evargs.c es de particular interés).

Las acciones ignore, echo, printEvent, sound y shell hacen lo que esperarías que hicieran los comandos llamados ignore, echo, printEvent, sound y shell, excepto que el comando de sonido solo se ha implementado y probado en máquinas SGI. Actualmente lanza un programa externo, por lo que debería ser bastante fácil de adaptar, especialmente si te gustan las señales de audio que llegan aproximadamente medio segundo después de esperarlas.

Las únicas variables actualmente reconocidas son soundDirectory y soundCmd. Estoy seguro de que puedes imaginar lo que hacen.

OPCIONES

-help
Imprime un mensaje de uso que está mucho más actualizado que cualquier cosa en esta página del manual.
-cfg archivo
Especifica el archivo de configuración a leer. Si no se especifica ningún archivo de configuración, xkbevd busca en ~/.xkb/xkbevd.cf y $(LIBDIR)/xkb/xkbevd.cf en ese orden.
-sc cmd
Especifica el comando utilizado para reproducir sonidos.
-sd directorio
Especifica un directorio de nivel superior para archivos de sonido.
-display display
Especifica la pantalla a utilizar. Si no está presente, xkbevd utiliza $DISPLAY.
-bg
Le dice a xkbevd que se bifurque (y se ejecute en segundo plano).
-synch
Fuerza la sincronización de todas las solicitudes X. Lento.
-v
Imprime más información, incluidos mensajes de depuración. Múltiples especificaciones de -v provocan más salida, hasta cierto punto.
-version
Imprime la versión del programa y sale.
