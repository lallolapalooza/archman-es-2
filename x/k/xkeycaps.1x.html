XKeyCaps(1) Manual de comandos generales XKeyCaps(1)

NOMBRE

xkeycaps - muestra y edita gráficamente el mapeo del teclado X

SINOPSIS

xkeycaps [-opción-toolkit ...] [-opción ...]

DESCRIPCIÓN

El programa xkeycaps muestra un teclado. Mover el ratón sobre una tecla describe los keysyms y modificadores que esa tecla genera. Hacer clic izquierdo en una tecla simula un evento KeyPress. Hacer clic derecho en una tecla muestra un menú de operaciones, que incluye un comando para cambiar los keysyms que la tecla genera. Este programa es, en parte, una interfaz gráfica para xmodmap(1).

OPCIONES

xkeycaps acepta todas las opciones estándar del toolkit, y además acepta las siguientes opciones:

-keyboard nombre-teclado o -kbd nombre-teclado
Especifica el tipo de teclado a mostrar. Hay muchos teclados de ordenador diferentes en el mundo, y xkeycaps necesita saber cuál estás utilizando para funcionar correctamente. La capitalización no importa al especificar un nombre de teclado.

Si estás ejecutando en la consola de un Sun o HP, entonces xkeycaps interrogará el hardware del teclado conectado directamente para determinar qué teclado estás usando. Pero si estás ejecutando remotamente, o en otro tipo de máquina, entonces debes especificar un teclado de alguna manera.

-help
Enumera los valores reconocidos para la opción -keyboard.
-gutterwidth número o -gw número
Especifica el número de píxeles de espacio a dejar entre cada tecla.
-font nombre-fuente
Especifica la fuente a usar para mostrar las teclas.

Los siguientes argumentos de línea de comandos estándar del X Toolkit se usan comúnmente con xkeycaps:

-display host:dpy
Esta opción especifica el servidor X al que contactar.
-geometry geometría
Esta opción especifica el tamaño y posición preferidos de la ventana.
-bg color
Esta opción especifica el color a usar para el fondo de la ventana. El valor predeterminado es gris claro.
-fg color
Esta opción especifica el color a usar para el primer plano de la ventana. El valor predeterminado es negro.
-bw número
Esta opción especifica el ancho en píxeles del borde que rodea la ventana.
-xrm cadena-recurso
Esta opción especifica una cadena de recurso a ser utilizada. Esto es especialmente útil para establecer recursos que no tienen opciones de línea de comandos separadas.

MOSTRAR

La parte inferior de la ventana es un dibujo de un teclado. En la esquina superior izquierda de cada tecla se imprime la cadena que aparece realmente en la superficie de la tecla. En la esquina inferior derecha de la tecla está el keycode (en hexadecimal) que esta tecla genera.

En la parte superior de la pantalla hay varias líneas de texto que describen la tecla bajo el ratón (o la tecla más recientemente presionada.) Estas líneas son:

KeyCode:
Muestra el texto impreso en la tecla física, y el keycode generado por esa tecla en hexadecimal, decimal y octal.
KeySym:
Muestra el conjunto de KeySyms que esta tecla genera actualmente.
ASCII:
Muestra el equivalente ASCII de esta tecla, teniendo en cuenta las teclas modificadoras que están actualmente presionadas.
Modificadores:
Muestra los bits modificadores que esta tecla genera. Si una tecla genera modificadores, es una tecla combinada como Shift o Control.
AutoRepeat:
Si el servidor X afirma que esta tecla se repite automáticamente. Digo ``afirma'' porque el servidor X OpenWindows es el único que he encontrado para el cual esta información es precisa. La bandera de repetición automática por tecla parece ser casi universalmente ignorada.

COMANDOS

Hay varios botones en la esquina superior izquierda de la ventana. Son:

Quit
Sale del programa.
Select Keyboard
Abre un cuadro de diálogo desde el cual puedes cambiar qué teclado se muestra. La columna izquierda enumera los tipos de teclados conocidos, y la columna derecha enumera los diseños (mapas) conocidos de esos teclados.
Type At Window
Después de seleccionar esto, se te pide que hagas clic en alguna otra ventana. Después de hacer esto, hacer clic en las teclas en la pantalla del teclado simulará eventos de tecla en la ventana que seleccionaste. Seleccionar la ventana raíz o la ventana de xkeycaps desactiva esto.

Si estás usando un gestor de ventanas (por ejemplo, twm(1)) en el que puedes bloquear el foco del teclado en una ventana y aún así hacer clic en otras ventanas sin que el foco cambie, entonces puedes lograr lo mismo simplemente enfocando en otra ventana y haciendo clic en las teclas en la ventana de xkeycaps.

Restore Default Map
Este comando restaura el teclado a su estado predeterminado. Si ejecutas este comando mientras muestras un teclado que no es el tipo de teclado que realmente estás usando, tu mapa de teclas estará en un estado incomprensible. No hay forma de que xkeycaps sepa qué teclado estás usando excepto por tu palabra, así que no mientas.
Write Output
Este comando escribe un archivo de entrada de xmodmap que representa el estado actual del teclado (incluyendo todos tus cambios) a un archivo en tu directorio de inicio. Ten en cuenta que este comando NO escribe el mapa de teclas predeterminado para este tipo de teclado a menos que hayas hecho clic en Restore Default Map antes.

El archivo se llamará .xmodmap-nombre-host, donde nombre-host es el nombre de la máquina en la que estás ejecutando. Te advertirá si el archivo ya existe.

Te pedirá con un cuadro de diálogo: puedes escribir un archivo de xmodmap que represente el estado de cada tecla, o puedes escribir un archivo más pequeño que describa solo los cambios.

La idea es que en el script de inicio apropiado, agregarías una línea como

xmodmap  /.xmodmap-`uname -n`
en el archivo init apropiado, para que esas modificaciones del teclado se realicen cada vez que inicies sesión. (Si no estás seguro de dónde debe ir este comando, pregunta a tu administrador del sistema, ya que tiende a variar de un sitio a otro).

Hacer clic izquierdo en una tecla simula un evento KeyPress. Soltar el botón simula un evento KeyRelease. Si haces clic izquierdo en una tecla y mueves el ratón mientras el botón está presionado, se simularán eventos KeyPress y KeyRelease en cada tecla sobre la que muevas el ratón. Piensa en el ratón como tu dedo: si arrastras el ratón sobre varias teclas, estas se presionarán y soltarán en orden.

Hacer clic izquierdo en una tecla que está asociada con bits modificadores (como Shift o Control) hace que esa tecla se "bloquee" presionada. Hacer clic izquierdo de nuevo libera la tecla. De esta manera, puedes generar combinaciones de teclas con el ratón: para generar Control-C, haz clic izquierdo en la tecla Control, y luego haz clic en la tecla C. Haz clic de nuevo en Control para desactivar el modificador de control.

Presionar una tecla en el teclado real simula un par de eventos KeyPress/KeyRelease de la misma manera que lo hace hacer clic en una tecla.

Y si mantienes presionada la tecla real Control y haces clic en la tecla C en la ventana, se generará un evento Control-C. Hacer clic derecho en una tecla abre un menú de comandos para la tecla dada. Estos son:

Intercambiar Teclas
Después de seleccionar esta opción de menú, se te pedirá que hagas clic en otra tecla. Esa tecla y la tecla sobre la que abriste el menú se intercambiarán. Esto cambia el mapeo del teclado inmediatamente.
Duplicar Tecla
Después de seleccionar esta opción de menú, se te pedirá que hagas clic en otra tecla. Esa tecla se convertirá en una copia de la tecla sobre la que abriste el menú. Es decir, las dos teclas generarán el mismo conjunto de claves y modificadores. Esto cambia el mapeo del teclado inmediatamente.
Desactivar Tecla
La tecla sobre la que abriste el menú no generará ninguna clave ni modificador. Esto cambia el mapeo del teclado inmediatamente.
Restaurar Tecla a Predeterminado
La tecla sobre la que abriste el menú se restaurará a su estado predeterminado; no se alterará ninguna otra tecla. Esto realmente cambia el mapeo del teclado actual.
Editar Claves de Tecla
Esto abre la ventana "Editar Tecla", que te permite cambiar arbitrariamente qué claves y modificadores genera esta tecla.

En el lado izquierdo de la ventana se encuentra la lista de las claves que esta tecla genera actualmente. (Una tecla puede generar hasta ocho claves; la interpretación de estas claves se describe en el documento del protocolo X y se resume más adelante en la sección CLAVEST Y CÓDIGOS DE TECLA de esta página man).

La segunda columna es una lista de opciones múltiples de los ocho bits de modificador que esta tecla puede generar. Por ejemplo, si quieres que una tecla se comporte como una tecla de ``control'', deberías seleccionar el modificador Control.

La tercera y cuarta columna (las listas de desplazamiento) son para cambiar la clave asociada con la tecla. Cuando seleccionas una posición de clave de la primera columna, el conjunto de caracteres y la clave se mostrarán en las listas de desplazamiento. Hacer clic en una clave en la columna "KeySym" instalará esa clave en la ranura resaltada en la primera columna.

Para seleccionar una clave de un conjunto de caracteres diferente, haz clic en el nombre del conjunto de caracteres en la segunda columna. (Los conjuntos de caracteres Latin1 y Keyboard son los más comúnmente utilizados).

En la parte inferior de la ventana hay tres botones: Deshacer, Abortar y Ok. Hacer clic en Deshacer revierte la ventana Editar Tecla al estado actual de la tecla en cuestión. Abortar cierra la ventana Editar Tecla sin realizar ningún cambio. Ok cierra la ventana Editar Tecla e instala tus cambios (el mapeo del teclado actual se modifica).

CLAVEST Y CÓDIGOS DE TECLA

Para editar eficazmente tu mapeo de teclado, hay algunos términos con los que debes familiarizarte:

CÓDIGO DE TECLA (KeyCode)
Este es un código de escaneo crudo que se lee del teclado; cada tecla física en el teclado tiene un número diferente asociado; este mapeo no se puede cambiar (pero está bien).

En general, cada teclado tiene su propio conjunto de códigos de tecla, por lo que probablemente necesitarás tener un mapa de teclas diferente para cada sistema que utilices.

CLAVE (KeySym)
Este es un símbolo que puede ser generado por una sola pulsación de una tecla en el teclado: por ejemplo, todas las letras, números y signos de puntuación son claves, y también lo son cosas más abstractas como "shift" y "control".

Cada código de tecla (es decir, tecla en el teclado) está asociado con ciertas claves. Las claves son las que dan semántica a las teclas (y hacen que la tecla A genere una A), no los códigos de tecla.

Por lo general, las teclas se asocian con una o dos claves, que corresponden a los símbolos generados cuando se presiona la tecla, y cuando se presiona mientras se mantiene presionada la tecla shift. Hay un caso especial, y es que si la tecla contiene solo una clave, y es una letra, entonces la tecla Shift hace lo obvio que se hace con las letras.

CAPACIDAD DE TECLA (KeyCap)
No confundir con las claves, esto se refiere al texto que está impreso en las teclas físicas: es inmutable (a menos que repintes tu teclado...)
ACORDE (Chord)
Este término se refiere a un conjunto de dos o más teclas presionadas simultáneamente (por analogía con los teclados de piano). Todas menos una de las teclas serán generalmente Teclas Modificadoras. A veces se usa Constelación para referirse a lo mismo.
TECLA MODIFICADORA (Modifier Key)
Esta es una tecla como shift o control, que se utiliza para alterar la interpretación de otras teclas que se mantienen presionadas al mismo tiempo. Generalmente, presionar una tecla modificadora sin presionar también una tecla no modificadora no hace nada.

Una tecla es una tecla modificadora si tiene una Clave Modificadora en ella. (Más específicamente, si el Código de Tecla de esa tecla está asociado con una Clave Modificadora).

CLAVE MODIFICADORA (Modifier KeySym)
Una clave es una clave modificadora si tiene un Bit Modificador asociado. Pero las reglas son un poco más complicadas que eso. Es más fácil de describir con un ejemplo:

Para que una tecla se comporte como se espera que se comporte una tecla de shift, el código de tecla debe tener el bit modificador Shift activado; y la tecla debe generar una de las claves Shift_L y Shift_R. Si alguna de estas condiciones no se cumple, la tecla no se comportará como una tecla de shift.

Análogamente, una tecla de control debe tener el modificador Control activado y usar una de las claves Control_L o Control_R.

Esto implica que si quisieras intercambiar tus teclas de shift y control, no sería suficiente con intercambiar sus bits modificadores: también debes intercambiar sus claves. Si solo intercambias los bits modificadores, podría parecer que funciona al principio, pero otras cosas funcionarían mal.

Teclas como Meta (y Super, Hyper, etc.) son un poco más complicadas (ver más abajo).

BIT MODIFICADOR (Modifier Bit)
Los bits modificadores son atributos que ciertas claves pueden tener. Algunos bits modificadores tienen semántica predefinida: Shift, Lock y Control. Los bits modificadores restantes (Mod1 a Mod5) tienen semántica definida por las teclas con las que están asociados.

Es decir, el modificador Control significa Control si está asociado a Control_L o Control_R, y es ilegal en otros lugares.

Pero Mod1 significa Meta si está asociado a Meta_L o Meta_R; pero significaría Alt si estuviera asociado a Alt_L o Alt_R; o Hyper con Hyper_L o Hyper_R; y así sucesivamente. (Sin embargo, no podría asociarse a Control_L, ya que el modificador Control ya ha sido asignado a esas claves).

Si piensas que todo esto es innecesariamente complicado... tienes razón.

DOCUMENTO DEL PROTOCOLO X SOBRE MAPAS DE TECLAS

La siguiente es una explicación técnica más precisa de cómo funciona el mapeo de teclas. Esta descripción proviene del documento del Protocolo X y se reimprime aquí para su conveniencia:

Una lista de claves está asociada con cada código de tecla. Si esa lista (ignorando las entradas NoSymbol finales) es una sola clave "K", entonces la lista se trata como si fuera la lista "K NoSymbol K NoSymbol". Si la lista (ignorando las entradas NoSymbol finales) es un par de claves "K1 K2", entonces la lista se trata como si fuera la lista "K1 K2 K1 K2". Si la lista (ignorando las entradas NoSymbol finales) es un triple de claves "K1 K2 K3", entonces la lista se trata como si fuera la lista "K1 K2 K3 NoSymbol".

Los primeros cuatro elementos de la lista se dividen en dos grupos de claves. El Grupo 1 contiene la primera y segunda clave, el Grupo 2 contiene la tercera y cuarta clave. Dentro de cada grupo, si el segundo elemento del grupo es NoSymbol, entonces el grupo debe tratarse como si el segundo elemento fuera el mismo que el primer elemento, excepto cuando el primer elemento es una clave alfabética "K" para la cual están definidas tanto la forma minúscula como la mayúscula. En ese caso, el grupo debe tratarse como si el primer elemento fuera la forma minúscula de "K" y el segundo elemento fuera la forma mayúscula de "K".

Las reglas estándar para obtener una clave de un evento KeyPress utilizan solo las claves del Grupo 1 y Grupo 2; aquí no se da ninguna interpretación de otras claves de la lista. (Es decir, las últimas cuatro claves no se utilizan).

Qué grupo usar está determinado por el estado del modificador. El cambio entre grupos se controla mediante la clave llamada Mode_switch.

Al asociar esa clave con algún código de tecla y asociar ese código de tecla con cualquiera de los modificadores Mod1 a Mod5. Este modificador se llama "modificador de grupo". Para cualquier código de tecla, se utiliza el Grupo 1 cuando el modificador de grupo está desactivado y el Grupo 2 se utiliza cuando el modificador de grupo está activado.

Dentro de un grupo, la clave a utilizar también está determinada por el estado del modificador. La primera clave se utiliza cuando los modificadores Shift y Lock están desactivados. La segunda clave se utiliza cuando el modificador Shift está activado, o cuando el modificador Lock está activado y la segunda clave es alfabética mayúscula, o cuando el modificador Lock está activado y se interpreta como ShiftLock. De lo contrario, cuando el modificador Lock está activado y se interpreta como CapsLock, el estado del modificador Shift se aplica primero para seleccionar una clave, pero si esa clave es alfabética minúscula, entonces se usa la clave mayúscula correspondiente en su lugar.

ICCCM SOBRE EL MAPEO DE MODIFICADORES

La siguiente es una explicación técnica más precisa de cómo se interpretan las teclas modificadoras. Esta descripción proviene del Manual de Convenciones de Comunicación Inter-Cliente y se reimprime h

MODIFIER_MAPS

Aquí hay un resumen del modelo de teclado de X para su conveniencia:

X11 admite 8 bits modificadores, de los cuales 3 están preasignados a Shift, Lock y Control. Cada bit modificador está controlado por el estado de un conjunto de teclas, y estos conjuntos se especifican en una tabla a la que se accede mediante GetModifierMapping() y SetModifierMapping().

Un cliente que necesite usar uno de los modificadores preasignados debe asumir que la tabla de modificadores se ha configurado correctamente para controlar estos modificadores. El modificador Lock debe interpretarse como Caps Lock o Shift Lock, según si las keycodes en su conjunto de control incluyen XK_Caps_Lock o XK_Shift_Lock.

Los clientes deben determinar el significado de un bit modificador a partir de los keysyms que se utilizan para controlarlo.

Un cliente que necesite usar un modificador adicional, por ejemplo Meta, debe:

Escanear los mapas de modificadores existentes. Si encuentra un modificador que contiene una keycode cuyo conjunto de keysyms incluye XK_Meta_L o XK_Meta_R, debe usar ese bit modificador.

Si no existe ningún modificador existente controlado por XK_Meta_L o XK_Meta_R, debe seleccionar un bit modificador no utilizado (uno con un conjunto de control vacío) y:

Si existe una keycode con XL_Meta_L en su conjunto de keysyms, agregue esa keycode al conjunto para el modificador elegido, y luego

si existe una keycode con XL_Meta_R en su conjunto de keysyms, agregue esa keycode al conjunto para el modificador elegido, y luego

si el conjunto de control aún está vacío, interactúe con el usuario para seleccionar una o más teclas que serán Meta.

Si no hay bits modificadores no utilizados, solicite al usuario que tome medidas correctivas.

Lo anterior significa que el modificador Mod1 no significa necesariamente Meta, aunque algunas aplicaciones (como twm y emacs 18) lo asumen. Cualquiera de los cinco bits modificadores no asignados podría significar Meta; lo que importa es que un bit modificador es generado por una keycode que está vinculada al keysym Meta_L o Meta_R.

Por lo tanto, si desea crear una tecla "meta", la forma correcta es hacer que la keycode en cuestión genere tanto un keysym Meta como un bit modificador previamente no asignado.

EL KEYSYM MODE_SWITCH

En caso de que lo anterior no tuviera sentido, lo que hace el keysym Mode_switch es, básicamente, actuar como un tipo adicional de tecla de shift. Si tiene cuatro keysyms asociados a la tecla A, esos cuatro keysyms se accederán mediante las combinaciones: A; Shift-A, Mode_Switch-A; y Mode_Switch-Shift-A, respectivamente.

Como cualquier Tecla Modificadora, para que Mode_switch funcione, debe tener un bit modificador asociado. Por lo tanto, seleccione uno de los bits Mod1 a Mod5 (el que no esté en uso) y asócielo a la tecla Mode_switch.

EL KEYSYM MULTI_KEY

No confundir con Mode_switch, Multi_key permite la entrada de secuencias de caracteres múltiples que representan un solo carácter (keysym.) Un nombre más tradicional para este keysym podría haber sido Compose.

El keysym Multi_key *no* es un keysym modificador. Es decir, para que funcione correctamente, no debe tener ningún bit modificador asociado. Esto se debe a que no es una tecla de "combinación": no la mantiene presionada junto con otras teclas. Más bien, presiona Multi_key, luego la suelta, luego presiona y suelta otra tecla, y las dos juntas producen un nuevo carácter.

Por ejemplo, una vinculación tradicional sería para Multi_key, seguida de comilla simple, seguida de A para producir el keysym Aacute.

No todos los proveedores admiten el uso del keysym Multi_key; en particular, Digital, Sun y HP lo admiten, pero el X Consortium no. (La razón de esto, me han dicho, es que las secuencias "Compose" se consideran obsoletas; la versión oficial es que deberías usar Métodos de Entrada para hacer esto).

Si Multi_key funciona o no es una propiedad de la biblioteca Xt (no del servidor X), por lo que es posible que en un mismo sistema, Multi_key funcione con algunas aplicaciones y con otras no (dependiendo de cómo se compilaron y enlazaron esas aplicaciones).

Si usa Lucid Emacs o XEmacs, puede aprovechar las secuencias de Multi_key incluso si su versión de Xt no lo admite, cargando la biblioteca x-compose, que simula el comportamiento tradicional de Xt. Para más información, lea el comentario en la parte superior del archivo "/usr/local/lib/xemacs-*/lisp/x11/x-compose.el".

KEYSYMS MUERTOS

Las teclas muertas funcionan de manera similar a Multi_key, pero son comandos de dos pulsaciones en lugar de tres. Por ejemplo, presionar la tecla Dead_tilde, soltarla, y luego presionar la tecla A generaría el keysym único Atilde. (Se les llama teclas "muertas" porque no insertan caracteres por sí mismas, sino que modifican el carácter siguiente que se escribe. Pero HP le gusta llamarlas "mudo" en lugar de "muerto", sin duda para no asustar a los niños).

Nuevamente, no todas las versiones de la biblioteca Xt admiten esto (pero XEmacs puede simularlo).

Tenga en cuenta también que diferentes proveedores tienen nombres diferentes para los keysyms muertos. Por ejemplo: dependiendo de su proveedor, versión del servidor X y fase de la luna, podría encontrar que el nombre de "dead-tilde" es Dead_Tilde, Dtilde, SunFA_Tilde, SunXK_FA_Tilde, DXK_tilde, DXK_tilde_accent, hpmute_asciitilde, hpXK_mute_asciitilde, o incluso XK_mute_asciitilde. ¡Es un desastre! Tendrá que probar y ver qué funciona, si es que algo lo hace.

COSAS QUE NO PUEDES HACER

La gente a menudo pregunta si xkeycaps o xmodmap se pueden usar para hacer que una tecla genere una secuencia de caracteres. Desafortunadamente, no: no puede hacer este tipo de cosas manipulando los mapas de teclas del servidor. El modelo de teclado de X simplemente no funciona así.

La forma de hacer tales cosas es establecer recursos de traducción en widgets particulares. Tiene que hacerse aplicación por aplicación. Por ejemplo, así es como convencería a xterm(1) para que inserte la cadena next cuando presione F17:

xterm*VT100.Translations: #override \
    <Key>F17: string("next")
Otras aplicaciones pueden tener mecanismos diferentes para lograr lo mismo, y algunas aplicaciones podrían no admitirlo en absoluto. Consulte las páginas man relevantes para obtener detalles específicos.

Del mismo modo, no puede convencer a una tecla para que genere otra tecla con modificadores (por ejemplo, no puede hacer que F1 se comporte como Ctrl-A excepto usando traducciones, como se mencionó anteriormente).

Tampoco es posible hacer que una tecla del teclado se comporte como un botón del ratón.

PROVEEDORES PERDEDORES

Tanto HP como S.u.S.E. distribuyen sus sistemas con configuraciones de teclado rotas por defecto. Realmente deberían saberlo mejor, pero no lo hacen.

Como se explicó anteriormente, es un comportamiento indefinido que un bit modificador se comparta entre dos teclas con semánticas disimilares.

Por defecto, HP usa Mod1 tanto para Meta como para Mode_switch. Esto significa que es imposible que un programa distinga entre, por ejemplo, Meta-X y Mode_switch-X.

Entonces, para reparar este desastre, necesita asignar un bit modificador diferente a la tecla Mode_switch (mod2, por ejemplo). O, simplemente podría eliminarla por completo del mapa de teclas.

S.u.S.E. Linux está incluso más jodido que HP: mientras que el mapa de teclas predeterminado de HP contiene solo un error, ¡el mapa predeterminado de S.u.S.E. contiene tres errores completamente diferentes!

Primero, su mapa de teclas predeterminado tiene el modificador Control asociado tanto a la tecla Control como a Multi_key. Esto es completamente loco, porque no solo Multi_key no es una tecla de control, ¡sino que ni siquiera es una tecla de combinación! No debe tener ningún bit modificador asociado en absoluto.

Segundo, asocian Mod1 a Meta_L y también a Alt_R. Algunas personas piensan que "meta" y "alt" son sinónimos, pero el hecho es que el X Window System no está de acuerdo. Son teclas distintas. Es posible tener teclas "meta" y "alt" en el teclado al mismo tiempo, y hacer que los programas las interpreten de manera distinta. Pero por supuesto, solo si no comparten falsamente el mismo bit modificador, haciendo que la interpretación de ese bit sea ambigua.

Tercero, asocian Mod5 tanto a Scroll_Lock como a Hyper_R, lo cual es incorrecto por razones que ahora deberían ser obvias.

La forma más fácil de arreglar su configuración de S.u.S.E. es: eliminar control de Multi_key; cambiar la tecla Alt izquierda para que genere Alt_L en lugar de Meta_L; y eliminar el keysym Hyper_R del teclado.

Si tiene alguna influencia con estos proveedores, lo animo a que los anime a ponerse las pilas.

X RECURSOS

XKeyCaps entiende todos los nombres y clases de recursos principales, así como:

*Keyboard.keyboard (clase Keyboard)
Qué teclado mostrar; esto es lo mismo que la opción de línea de comandos -keyboard. Si no se especifica, se adivina el teclado predeterminado, basado en la cadena de identificación del proveedor del servidor.
*Keyboard.Keyboard.selectCursor (clase Cursor)
El cursor a usar al seleccionar una tecla o ventana con el ratón. El predeterminado es el cursor de cruz.
*Keyboard.Key.highlight (clase Background)
El color a usar para resaltar una tecla cuando se presiona. Si es el mismo que el color de fondo de la tecla, se resalta con un patrón de puntos en su lugar.
*Keyboard.Key.keycapColor (clase Foreground)
El color para pintar la cadena de la tecla.
*Keyboard.Key.keycodeColor (clase Foreground)
El color para pintar el número de la keycode.
*Keyboard.Key.borderColor (clase Color)
El color del borde alrededor de cada tecla.
*Keyboard.Key.keycapFont (clase Font)
La fuente a usar para dibujar la cadena de la tecla.
*Keyboard.Key.keycodeFont (clase Font)
La fuente a usar para dibujar el número de la keycode.
*Keyboard.Key.borderWidth (clase Int)
El grosor del borde alrededor de cada tecla.
*Keyboard.Key.gutterWidth (clase Int
)
Cuántos píxeles dejar entre esta tecla y sus vecinas a la derecha e inferior.

La clase de cada widget de tecla es ``Key'', como se ve arriba. El nombre de cada tecla es la(s) cadena(s) impresa(s) en su cara. Así que si quisieras (por ejemplo) que las teclas Shift tuvieran bordes más anchos, podrías especificarlo con

xkeycaps*Keyboard.Shift.borderWidth: 2

ACCIONES

Es posible reasignar las acciones que ocurren cuando se presiona o suelta una tecla o un botón del ratón. Estas acciones están disponibles en el widget Keyboard:

ResaltarTecla(condición, arg)
Esto pone la tecla en cuestión en el estado resaltado.

Si no se pasa ningún argumento a esta acción, la tecla se determina por el evento que invocó esta acción. Si esta acción es invocada por un evento KeyPress o KeyRelease, el widget de tecla es la tecla correspondiente a la tecla que representa el evento. Si es un evento ButtonPress, ButtonRelease o PointerMotion, entonces el widget de tecla es el que está debajo del ratón.

El argumento puede ser una de las palabras ratón, resaltado o mostrado, significando la tecla bajo el ratón, la tecla resaltada más recientemente, o la tecla descrita actualmente en el área ``Info'' en la parte superior de la ventana, respectivamente.

La condición puede ser una de las palabras simod, sinosemod, siseigue, sinoseigue, siresaltado o sinoresaltado. Si se especificó simod y la tecla en cuestión (determinada por el argumento o por el evento invocador) no es una tecla modificadora, entonces esta acción no se ejecuta. La condición sinosemod es lo opuesto. Las condiciones siseigue y sinoseigue te permiten realizar algunas acciones solo si (o a menos que) la tecla está siendo ``seguida'' con el ratón (ver abajo.) Las acciones siresaltado y sinoresaltado te permiten hacer algunas cosas solo si (o a menos que) la tecla en cuestión esté actualmente en el estado resaltado.

DeshacerResaltadoTecla(condición, arg)
Esto pone la tecla en cuestión en el estado no resaltado. Los argumentos son como arriba.
AlternarTecla(condición, arg)
Esto hace que la tecla esté resaltada si no está resaltada, o no resaltada si está resaltada. Los argumentos son como arriba.
SimularPresionTecla(condición, arg)
Esta acción genera un evento KeyPress correspondiente a la tecla en la ventana de enfoque. Los argumentos son como arriba.
SimularLiberacionTecla(condición, arg)
Esta acción genera un evento KeyRelease correspondiente a la tecla en la ventana de enfoque. Los argumentos son como arriba.
SeguirTecla(condición, arg)
Esto hace que la tecla en cuestión comience a ser ``seguida'', lo que significa que mover el ratón fuera de ella simulará una acción de liberación de botón, y luego simulará una acción de presión de botón en la tecla sobre la que se ha movido el ratón. Esta acción solo puede ser invocada desde un evento ButtonPress o ButtonRelease.
DejarSeguirTecla(condición, arg)
Esto hace que la tecla en cuestión ya no sea ``seguida''.
DescribirTecla(condición, arg)
Esta acción hace que la tecla y sus enlaces se muestren en la sección ``Info'' en la parte superior de la ventana, si no se describe allí ya.

Las acciones predeterminadas para el widget Keyboard son:

<Motion>:   DescribirTecla(raton,sinoseigue)      \n\
\
<KeyDown>:  ResaltarTecla()                         \
            DescribirTecla(sinosemod)              \
            DescribirTecla(mostrado)               \
            SimularPresionTecla()                   \n\
\
<KeyUp>:    DeshacerResaltadoTecla()                       \
            DescribirTecla(mostrado)                 \
            SimularLiberacionTecla()                   \n\
\
<Btn1Down>: ResaltarTecla(sinosemod)                \
            AlternarTecla(simod)                       \
            SeguirTecla(sinosemod)                    \
            SimularPresionTecla(siresaltado)        \
            SimularLiberacionTecla(sinoresaltado)  \n\
\
<Btn1Up>:   DejarSeguirTecla(resaltado)                \
            SimularLiberacionTecla(resaltado,sinosemod) \
            DeshacerResaltadoTecla(resaltado,sinosemod)  \n\
\
<Btn3Down>: XawPositionSimpleMenu(menuTeclado)         \
            MenuPopup(menuTeclado)                     \n
Si no quieres que una tecla sea descrita cada vez que el ratón pasa sobre ella, puedes eliminar la acción <Motion>. En ese caso, probablemente deberías añadir DescribirTecla() a las acciones <Btn1Down> y <KeyDown>.

Si quieres que la tecla bajo el ratón sea descrita incluso mientras el ratón se mueve con un botón presionado, entonces elimina el parámetro sinoseigue de la acción DescribirTecla enlazada a <Motion>.

Si no quieres que las teclas modificadoras alternen, cambia las acciones de Button1 a

xkeycaps*Keyboard.acciones:  #sobreescribir               \
        <Btn1Down>: ResaltarTecla()                  \
                    SeguirTecla(sinosemod)             \
                    SimularPresionTecla()              \n\
        <Btn1Up>:   DejarSeguirTecla(resaltado)         \
                    SimularLiberacionTecla(resaltado) \
                    DeshacerResaltadoTecla(resaltado)     \n
Recuerda que estas acciones existen en el widget Keyboard, no en los widgets Key. Si añades acciones a los widgets Key, las cosas funcionarán mal.

ERRORES

Debido a que este programa tiene colores predeterminados que no son "negro" y "blanco", la opción de línea de comandos -rv no funciona. Pero la invocación

% xkeycaps -fg white -bg black -bd white

hará lo que deseas en una pantalla monocromática.

Se cree que el mapa predeterminado de NeXT es incorrecto; alguien con acceso a un NeXT necesitará depurarlo.

No hay una forma portable de estar seguro de qué teclado se está utilizando; esto significa que a menudo no se activará el correcto por defecto, y si el usuario realiza cambios en el mapa de teclas mientras se muestra un teclado que no es el correcto, pueden ocurrir cosas muy malas.

Si presionas más de una docena de teclas a la vez, muchos servidores X se confunden y no transmiten suficientes eventos KeyRelease; el resultado de esto es que las teclas de xkeycaps se quedarán ``atascadas'' hasta que se vuelvan a presionar. (No te pongas así.)

La bandera AutoRepeat aparentemente es inútil en todos los servidores X excepto en el de OpenWindows (nunca he visto otro servidor que la ignore.)

No puedes seleccionar del conjunto de keysyms Vendor (aquellos keysyms que están definidos en el archivo XKeysymDB) a menos que estés ejecutando X11r5 o una versión más reciente.

Los teclados no-US de NCD no utilizan el mecanismo estándar R4/R5 para adjuntar más de dos keysyms a una tecla; en lugar de simplemente tener tres o cuatro keysyms adjuntos al keycode en cuestión, la tecla Compose cambia el keycode real de la tecla (activa su bit alto). El programa xkeycaps no entiende realmente esto. Alguien del soporte de NCD me dijo que en futuras versiones harán las cosas de la manera R4/R5 en lugar de la manera en que lo hacen ahora, por lo que hackear xkeycaps para entender el comportamiento actual probablemente no vale la pena el esfuerzo.

El comando Escribir en Ventana no parece funcionar en la versión WreckStation de XTerm. Supongo que es necesaria alguna variación del comando normal de XTerm Permitir SendEvents.

Si no puedes seleccionar nada del menú emergente del botón derecho, podría ser porque tienes NumLock o CapsLock activado. No estoy seguro de cómo arreglar esto, parece ser algo tonto de Xt.

Si el menú emergente siempre está desactivado o no corresponde a la tecla en la que hiciste clic, podría ser porque estás ejecutando xswarm, una versión antigua de xautolock, o algún otro programa que interfiere de manera antisocial con la propagación de eventos. (No te pongas así.)

Debido a la forma no lineal en que este programa utiliza XLookupString, no hay una forma sensata de procesar la composición y mostrarte los resultados de secuencias de teclas ``muertas'' o Multi_key.

Necesita conocer más tipos de teclado (y sin duda siempre lo hará...)

Las teclas en forma de L no se dibujan con precisión. Deberíamos usar la extensión Shape para eso.

Además de mostrar la versión ASCII del carácter dado, debería mostrar el carácter correspondiente en el conjunto de caracteres (Latin2, Kana, Griego, etc.) Esto requeriría tener fuentes para todos esos conjuntos de caracteres, sin embargo, y hasta donde yo sé, no todos vienen de serie.

Al ejecutarse en un Sun y comunicarse con un servidor OpenWindows, deberíamos analizar el archivo apropiado de $OPENWINHOME/etc/keytables/ para determinar el mapa de teclas predeterminado. Sin duda, existen formas específicas del sistema de hacer esto en otros entornos también.

BUGS

The xmodmap program still sucks. Since its ADD and REMOVE directives take keysyms as arguments instead of keycodes, there are things that you can do with XKeyCaps that you can't represent in an xmodmap script (at least, not without great pain.)

The xmodmap program has no commands for changing the autorepeat status of keys, so that information is not written in the output. Perhaps we could write out an appropriate xset command instead. (For example, to turn on autorepeat on PgUp (which happens to have key code 103) on Solaris, you would do: "xset r 103".)

Some versions of OpenWound use a nonstandard mechanism for specifying which keys have toggle (lock-like) behavior (whereas most other X servers base this behavior on the keysym: if Caps_Lock or Shift_Lock is generated, the key locks, otherwise it does not.) XKeyCaps doesn't know how to change the lock status on these servers. This is because I don't know how, either. If you know what system calls are necessary to hack this behavior, tell me.

The XKB interface of X11R6 looks to provide most of the information which xkeycaps needs to know, but I haven't had time to investigate this yet.
