NOMBRE

xbstream - Documentación de Percona xbstream

Para soportar compresión y streaming simultáneos, se introdujo un nuevo formato de streaming personalizado llamado xbstream a Percona XtraBackup además del formato TAR. Esto fue necesario para superar algunas limitaciones de los formatos de archivo tradicionales como tar, cpio y otros que no permitían el streaming de archivos generados dinámicamente, por ejemplo, archivos comprimidos dinámicamente. Otras ventajas de xbstream sobre los formatos de streaming/archivo tradicionales incluyen la capacidad de transmitir múltiples archivos concurrentemente (por lo que es posible usar streaming en el formato xbstream junto con la opción --parallel) y un almacenamiento de datos más compacto.

Esta utilidad tiene una interfaz similar a tar:

  • con la opción -x extrae archivos del stream leído de su entrada estándar al directorio actual a menos que se especifique lo contrario con la opción -c. El soporte para extracción paralela con la opción --parallel se implementó en Percona XtraBackup 2.4.7.
  • con la opción -c transmite los archivos especificados en la línea de comandos a su salida estándar.
  • con la opción --decrypt=ALGO especificada, xbstream descifrará automáticamente los archivos cifrados al extraer el stream de entrada. Los valores admitidos para esta opción son: AES128, AES192 y AES256. Se deben especificar las opciones --encrypt-key o --encrypt-key-file para proporcionar la clave de cifrado, pero no ambas. Esta opción se implementó en Percona XtraBackup 2.4.7.
  • con la opción --encrypt-threads puede especificar el número de hilos para el cifrado de datos en paralelo. El valor predeterminado es 1. Esta opción se implementó en Percona XtraBackup 2.4.7.
  • la opción --encrypt-key se utiliza para especificar la clave de cifrado que se utilizará. No se puede usar con la opción --encrypt-key-file porque son mutuamente excluyentes. Esta opción se implementó en Percona XtraBackup 2.4.7.
  • la opción --encrypt-key-file se utiliza para especificar el archivo que contiene la clave de cifrado. No se puede usar con la opción --encrypt-key. porque son mutuamente excluyentes. Esta opción se implementó en Percona XtraBackup 2.4.7.

La utilidad también intenta minimizar su impacto en la caché de páginas del sistema operativo utilizando las llamadas posix_fadvise() apropiadas cuando están disponibles.

Cuando la compresión está habilitada con xtrabackup, todos los datos se comprimen, incluido el archivo de registro de transacciones y los archivos de metadatos, utilizando el algoritmo de compresión especificado. El único algoritmo actualmente soportado es quicklz.

Los archivos resultantes tienen el formato de archivo qpress, es decir, cada archivo *.qp producido por xtrabackup es esencialmente un archivo qpress de un solo archivo y puede ser extraído y descomprimido por el archiver de archivos qpress. Esto significa que no es necesario descomprimir la copia de seguridad completa para restaurar una sola tabla como con tar.gz.

Para descomprimir archivos individuales, ejecute xbstream con la opción --decompress. Puede controlar el número de hilos utilizados para la descompresión pasando la opción --decompress-threads.

Además, los archivos pueden descomprimirse utilizando la herramienta qpress que se puede descargar desde aquí. Qpress soporta descompresión multihilo.
