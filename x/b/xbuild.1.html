NOMBRE

xbuild - Herramienta de Mono para construir archivos de proyecto MSBuild

SINOPSIS

xbuild [opción] [archivo-proyecto]

DESCRIPCIÓN

xbuild puede ser utilizado para construir archivos de proyecto MSBuild. Entornos de Desarrollo Integrado como MonoDevelop y "Microsoft Visual Studio .NET" utilizan el formato de archivo de proyecto msbuild.

xbuild toma la ruta del archivo de proyecto o solución a construir, como argumento principal. Si no se especifica ningún archivo, intenta construir cualquier archivo de solución o proyecto en el directorio actual que tenga una extensión de archivo *proj.

OPCIONES

/target:T1[,TN]
Lista de objetivos a construir
/property:Nombre=Valor
Establecer o anular propiedades del proyecto
/logger:<logger>
Registrador personalizado para registrar eventos de construcción
/toolsversion:versión , /tv:versión
Especifica la versión del conjunto de herramientas a utilizar.

Ej: /tv:4.0
Esto causaría que se utilice la versión 4.0 de Microsoft.Common.targets (entre otros). Esto anula
el valor especificado en un archivo de proyecto.

Valores válidos: 2.0, 3.0, 3.5 y 4.0

/verbosity:<nivel>
Nivel de detalle del registrador: quiet, minimal, normal, detailed, diagnostic
/validate
Valida el archivo de proyecto contra el esquema
/validate:<schema>
Valida el archivo de proyecto contra el esquema especificado
/consoleloggerparameters:<params> , /clp:<params>
Parámetros para el registrador de consola: PerfomanceSummary, Summary, NoSummary, NoItemAndPropertyList, Verbosity
/filelogger[n] , /fl[n]
Registra la salida en un archivo, llamado 'msbuild.log' por defecto. Si se especifica el número opcional 'n', entonces registra en 'msbuild[n].log'. Los parámetros para este registrador, incluido el nombre del archivo de registro, se pueden especificar a través de una opción /flp[n] correspondiente. El nivel de detalle por defecto para los registradores de archivos es 'detailed'. 'n' puede estar entre 1-9.
/fileloggerparameters[n]:<params> , /flp[n]:<params>
Parámetros para un registrador de archivos. Esto implica un /fl[n] correspondiente. 'n' puede estar entre 1-9, y se utiliza para añadir hasta 10 registradores de archivos. Los parámetros pueden ser, además de los disponibles para el registrador de consola:
LogFile=<archivo>
Archivo al que se escribirá el registro de construcción.
Append
Si se utiliza esto, el archivo de registro se anexa; de lo contrario, se creará uno nuevo.
Encoding=<codificación>
Codificación a utilizar para el archivo de registro, p. ej., UTF-8, ASCII.
Ej: xbuild foo.csproj /flp:Verbosity=normal "/flp1:LogFile=build.log;Append;Encoding=ASCII"
/nologo
No mostrar el banner inicial de xbuild
/help
Mostrar el uso de xbuild
/version
Mostrar la versión de xbuild

VARIABLES DE ENTORNO

XBUILD_EMIT_SOLUTION
Si esta variable está establecida, se emitirá el archivo de proyecto generado a partir de un archivo de solución.
XBUILD_LOG_REFERENCE_RESOLVER
Las referencias se resuelven intentando una lista de rutas de búsqueda de ensamblados ($(AssemblySearchPaths)). Si xbuild no puede resolver una referencia, registra detalles de por qué fallaron las diversas rutas de búsqueda. Si esta variable está establecida, registra lo mismo incluso para las referencias que se resolvieron correctamente. Estos registros aparecen si el nivel de detalle se establece en 'detailed' o superior.
MSBuildExtensionsPath
Las extensiones de MSBuild generalmente se instalan en $(MSBuildExtensionsPath), que xbuild resuelve a $prefix/lib/mono/xbuild . Cuando se usa en Import, como:


<Import Project="$(MSBuildExtensionsPath)\TestTargets.targets"/>

xbuild intenta varios valores para la propiedad msbuild $(MSBuildExtensionsPath), en orden:


1. Rutas especificadas en la variable de entorno $MSBuildExtensionsPath.
2. /Library/Frameworks/Mono.framework/External/xbuild en Mac OSX.
3. $XDG_CONFIG_HOME/xbuild/tasks (o Environment.SpecialFolder.ApplicationData)
4. $prefix/lib/mono/xbuild (ubicación predeterminada)

En cualquier otro lugar de los archivos de proyecto, $(MSBuildExtensionsPath) siempre se resolverá a la ubicación predeterminada. Esta es una característica exclusiva de xbuild. Esto también se aplica a las propiedades $(MSBuildExtensionsPath32) y $(MSBuildExtensionsPath64), y las variables de entorno tienen los nombres correspondientes - MSBuildExtensionsPath32/64 .

XBUILD_FRAMEWORK_FOLDERS_PATH
Con ToolsVersion 4.0, los proyectos pueden apuntar a frameworks arbitrarios referenciados por TargetFrameworkMoniker, que tiene el formato:


Identifier,Version=<versión>[,Profile=<perfil>]

Ej: ".NETFramework,Version=v4.0"

Las 3 partes del moniker se dan por las propiedades de msbuild:


$(TargetFrameworkIdentifier), $(TargetFrameworkVersion) y $(TargetFrameworkProfile)

Este moniker se mapea a un archivo de descripción del framework en disco:


<framework_root>/Identifier/Version/[Profile]/RedistList/FrameworkList.xml

Este archivo se utiliza para determinar la ruta donde encontrar los ensamblados del framework para este framework en particular.

La raíz del framework aquí es configurable y se resuelve en el siguiente orden:

  1. Rutas especificadas en la variable de entorno $XBUILD_FRAMEWORK_FOLDERS_PATH
  2. /Library/Frameworks/Mono.framework/External/xbuild-frameworks en Mac OSX.
  3. Propiedad de MSBuild $(TargetFrameworkRoot)
  4. $prefix/lib/mono/xbuild-frameworks (ubicación predeterminada)

XBuild intenta las rutas dadas arriba, en orden, hasta que encuentra un FrameworkList.xml para el moniker. Ejecutar con el nivel de detalle 'detailed' o superior mostrará las diversas rutas que intenta.

El propio FrameworkList.xml solo tiene un elemento raíz como:


<FileList Name=".NET Framework 3.5" TargetFrameworkDirectory="..\..\..\..\3.5" IncludeFramework="v3.0">
</FileList>

Aquí, el atributo TargetFrameworkDirectory especifica el directorio donde se pueden encontrar los ensamblados para este framework en particular. Si no se establece, se toma el padre de la carpeta que contiene el archivo xml como el directorio del framework.

El atributo IncludeFramework especifica la versión de un framework (bajo el *mismo* $(TargetFrameworkIdentifier)) que debe incluirse en la lista final de directorios de framework de destino.

XBUILD_COLORS
Si esta variable está establecida, contiene una cadena de la forma "tipo=primerplano,tipo=.." que especifica qué color usar para mostrar errores/advertencias, etc. en algunas terminales. El tipo aquí puede ser: 
errors, warnings, messages o events
events: Estos son mensajes de inicio y fin de eventos de proyecto/objetivo/tarea.

Los colores posibles para primer plano son: black, red, brightred, green, brightgreen, yellow, brightyellow, blue, brightblue, magenta, brightmagenta, cyan, brightcyan, grey, white y brightwhite.

Por ejemplo, podrías establecer esta variable desde tu shell:

export XBUILD_COLORS
XBUILD_COLORS=errors=brightred,warnings=blue

Puedes deshabilitar el esquema de colores integrado estableciendo esta variable a "disable".

NOTAS

En Mac OSX, para localizar archivos pkg-config (.pc), xbuild adicionalmente busca en "/Library/Frameworks/Mono.framework/Extern
