xjc(1) Herramientas de Servicios Web Java xjc(1)

NOMBRE

xjc - Compila un archivo de esquema XML en clases Java totalmente anotadas.

SINOPSIS

xjc [ opciones ] esquema archivo/URL/directorio/jar ... [-b infobindings ] ...
opciones
Las opciones de línea de comandos. Ver Opciones.
esquema archivo/URL/directorio/jar ...
La ubicación del archivo de esquema XML. Si se especifica directorio, entonces se compilan todos los archivos de esquema en él. Si se especifica jar, entonces se compila el archivo de bindings /META-INF/sun-jaxb.episode.
-b infobindings

La ubicación de los archivos de bindings.

DESCRIPCIÓN

Inicia el compilador de bindings con el script de shell xjc apropiado en el directorio bin para tu plataforma. También hay una tarea de Ant para ejecutar el compilador de bindings. Ver Uso de XJC con Ant en http://jaxb.java.net/nonav/2.1.3/docs/xjcTask.html

OPCIONES

•
Ver también Opciones no estándar
•
Ver también Opciones obsoletas y eliminadas
-nv

Por defecto, el compilador de bindings XJC realiza una validación estricta del esquema fuente antes de procesarlo. Usa esta opción para deshabilitar la validación estricta del esquema. Esto no significa que el compilador de bindings no realizará ninguna validación, sino que realizará una validación menos estricta.
-extension

Por defecto, el compilador de bindings XJC aplica estrictamente las reglas descritas en el capítulo de Compatibilidad de la Especificación JAXB. El Apéndice E.2 define un conjunto de características de W3C XML Schema que no son completamente soportadas por JAXB v1.0. En algunos casos, se te puede permitir usarlas en modo -extension habilitado por este interruptor. En modo estricto (predeterminado), también estás limitado a usar solo las personalizaciones de bindings definidas en la especificación. Al usar el interruptor -extension, se te permitirá usar las extensiones del proveedor JAXB.
-b archivo

Especifica uno o más archivos de bindings externos para procesar. Cada archivo de bindings debe tener su propio interruptor -b. La sintaxis de los archivos de bindings externos es flexible. Puedes tener un solo archivo de bindings que contenga personalizaciones para múltiples esquemas o puedes dividir la personalización en múltiples archivos de bindings: xjc schema1.xsd schema2.xsd schema3.xsd -b bindings123.xjbxjc schema1.xsd schema2.xsd schema3.xsd -b bindings1.xjb -b bindings2.xjb -b bindings3.xjb. Además, el orden de los archivos de esquema y de bindings en la línea de comandos no importa.
-d directorio

Por defecto, el compilador de bindings XJC genera las clases de contenido Java en el directorio actual. Usa esta opción para especificar un directorio de salida alternativo. El directorio de salida ya debe existir. El compilador de bindings XJC no lo crea por ti.
-p paquete

Cuando especificas un paquete de destino con esta opción de línea de comandos, anula cualquier personalización de bindings para el nombre del paquete y el algoritmo predeterminado de nombre de paquete definido en la especificación.
-httpproxy proxy

Especifica el proxy HTTP o HTTPS en el formato [usuario[:contraseña]@]hostproxy[:puertoproxy]. Las antiguas opciones -host y -port todavía son soportadas por la RI por compatibilidad hacia atrás, pero fueron obsoletas. La contraseña especificada con esta opción es un argumento visible para otros usuarios que usan el comando top. Para mayor seguridad, usa la opción -httpproxyfile.
-httpproxyfile archivo

Especifica el proxy HTTP o HTTPS con un archivo. El mismo formato que la opción -httpproxy, pero la contraseña especificada en el archivo no es visible para otros usuarios.
-classpath arg

Especifica dónde encontrar los archivos de clases de aplicación cliente usados por la personalización jxb:javaType y xjc:superClass.
-catalog archivo

Especifica archivos de catálogo para resolver referencias de entidades externas. Soporta los formatos TR9401, XCatalog y OASIS XML Catalog. Ver Resolutores de Entidades y URIs XML en http://xerces.apache.org/xml-commons/components/resolver/resolver-article.html
-readOnly

Por defecto, el compilador de bindings XJC no protege contra escritura los archivos fuente Java que genera. Usa esta opción para forzar al compilador de bindings XJC a marcar las fuentes Java generadas como de solo lectura.
-npa

Suprime la generación de anotaciones a nivel de paquete en **/package-info.java. Usar este interruptor hace que el código generado internalice esas anotaciones en las otras clases generadas.
-no-header

Suprime la generación de un comentario de encabezado de archivo que incluye alguna nota y marca de tiempo. Usar esto hace que el código generado sea más compatible con el comando diff.
-target 2.0

Evita generar código que dependa de cualquier característica de JAXB 2.1. Esto permitirá que el código generado se ejecute con un entorno de ejecución JAXB 2.0 (como Java SE 6).
-xmlschema

Trata los esquemas de entrada como W3C XML Schema (predeterminado). Si no especificas este interruptor, entonces tus esquemas de entrada se tratan como si fueran W3C XML Schemas.
-relaxing

Trata los esquemas de entrada como RELAX NG (experimental y no soportado). El soporte para esquemas RELAX NG se proporciona como una extensión del proveedor JAXB.
-relaxing-compact

Trata los esquemas de entrada como sintaxis compacta RELAX NG (experimental y no soportada). El soporte para esquemas RELAX NG se proporciona como una extensión del proveedor JAXB.
-dtd

Trata los esquemas de entrada como XML DTD (experimental y no soportado). El soporte para esquemas RELAX NG se proporciona como una extensión del proveedor JAXB.
-wsdl

Trata la entrada como WSDL y compila los esquemas dentro de él (experimental y no soportado).
-quiet

Suprime la salida del compilador, como información de progreso y advertencias.
-verbose

Sé extra verboso, por ejemplo, imprimiendo mensajes informativos o mostrando trazas de pila ante algunos errores.
-help

Muestra un breve resumen de los interruptores del compilador.
-version

Muestra la información de la versión del compilador.
esquema archivo/URL/directorio
Especifica uno o más archivos de esquema para compilar. Si especificas un directorio, entonces el comando xjc lo escanea en busca de todos los archivos de esquema y los compila.

OPCIONES NO ESTÁNDAR

-XLocator

Hace que el código generado exponga información de SAX Locator sobre el XML fuente en las instancias de bean Java después de la desmarshalización.
-Xsync-methods

Hace que todas las firmas de métodos generadas incluyan la palabra clave synchronized.

OPCIONES&#x00A0;DE&#x00A0;CÓDIGO&#x00A0;GENERADO

-mark-generated

Marca el código generado con la anotación @javax.annotation.Generated.
-episode file

Genera el archivo de episodio especificado para compilación separada.

OPCIONES&#x00A0;OBSOLETAS&#x00A0;Y&#x00A0;ELIMINADAS

-host & -port

Estas opciones son reemplazadas por la opción -httpproxy. Por compatibilidad retroactiva, estas opciones son soportadas, pero no serán documentadas y podrían ser eliminadas en futuras versiones.
-use-runtime

Debido a que la especificación JAXB 2.0 ha definido un entorno de ejecución portable, ya no es necesario que JAXB RI genere paquetes **/impl/runtime. Por lo tanto, este interruptor es obsoleto y ha sido eliminado.
-source

El interruptor de compatibilidad -source se introdujo en la primera versión de acceso temprano de JAXB 2.0. Este interruptor se elimina de futuras versiones de JAXB 2.0. Si necesita generar código 1.0.x, entonces use una instalación de la base de código 1.0.x.

RESTRICCIONES&#x00A0;DEL&#x00A0;COMPILADOR

En general, es más seguro compilar todos los esquemas relacionados como una sola unidad con las mismas opciones del compilador de enlace. Tenga en cuenta la siguiente lista de restricciones al ejecutar el comando xjc. La mayoría de estos problemas solo se aplican cuando compila múltiples esquemas con múltiples invocaciones del comando xjc.

Para compilar múltiples esquemas al mismo tiempo, tenga en cuenta las siguientes reglas de precedencia para el nombre del paquete Java de destino:

1.
La opción -p tiene la mayor precedencia.
2.
Personalización de jaxb:package.
3.
Si se declara targetNamespace, aplique el algoritmo de targetNamespace al nombre del paquete Java definido en la especificación.
4.
Si no se declara targetNamespace, use un paquete codificado de forma rígida llamado generated.

No puede tener más de un jaxb:schemaBindings por espacio de nombres, por lo que es imposible compilar dos esquemas en el mismo espacio de nombres de destino en diferentes paquetes Java.

Todos los esquemas que se compilan en el mismo paquete Java deben ser enviados al compilador de enlace XJC al mismo tiempo. No se pueden compilar de forma independiente y funcionar como se espera.

Los grupos de sustitución de elementos que se distribuyen en múltiples archivos de esquema deben compilarse al mismo tiempo.
