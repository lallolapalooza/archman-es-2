NOMBRE

xtables-monitor — mostrar cambios en el conjunto de reglas y eventos de trazabilidad

SINOPSIS

xtables-monitor [-t] [-e] [-4||-6]

DESCRIPCIÓN

xtables-monitor se utiliza para monitorizar cambios en el conjunto de reglas o para mostrar eventos de evaluación de reglas para paquetes etiquetados usando el objetivo TRACE. xtables-monitor se ejecutará hasta que el usuario aborte la ejecución, típicamente usando CTRL-C.

OPCIONES

-e, --event

Vigilar las actualizaciones del conjunto de reglas.
Las actualizaciones incluyen la creación de nuevas tablas, cadenas y reglas, y el nombre del programa que causó la actualización de la regla.
-t, --trace
Vigilar eventos de trazabilidad generados por paquetes que han sido etiquetados usando el objetivo TRACE.
-4
Restringir la salida a IPv4.
-6
Restringir la salida a IPv6.

EJEMPLO DE SALIDA

xtables-monitor --trace


1 TRACE: 2 fc475095 raw:PREROUTING:rule:0x3:CONTINUE -4 -t raw -A PREROUTING -p icmp -j TRACE
2 PACKET: 0 fc475095 IN=lo LL=0x304 0000000000000000000000000800 SRC=127.0.0.1 DST=127.0.0.1 LEN=84 TOS=0x0 TTL=64 ID=38349DF
3 TRACE: 2 fc475095 raw:PREROUTING:return:
4 TRACE: 2 fc475095 raw:PREROUTING:policy:ACCEPT
5 TRACE: 2 fc475095 filter:INPUT:return:
6 TRACE: 2 fc475095 filter:INPUT:policy:DROP
7 TRACE: 2 0df9d3d8 raw:PREROUTING:rule:0x3:CONTINUE -4 -t raw -A PREROUTING -p icmp -j TRACE

La primera línea muestra un paquete entrando en la evaluación del conjunto de reglas. Se muestra el número de protocolo (en este caso, AF_INET), luego un número de identificador de paquete que permite correlacionar los mensajes que provienen de la evaluación del conjunto de reglas de este paquete. Después de esto, se muestra la regla que coincidió con el paquete. Esta es la regla TRACE que activa los eventos de trazabilidad para este paquete.

La segunda línea muestra información sobre el paquete. Se muestra la interfaz de entrada y las cabeceras del paquete, como las direcciones de origen y destino.

La tercera línea muestra que el paquete completó la traversa de la cadena PREROUTING de la tabla raw, y está regresando, seguido por el uso de la política de la cadena para tomar la decisión de aceptar/rechazar (el ejemplo muestra que se aplica la aceptación). La quinta línea muestra que el paquete sale de la cadena INPUT del filtro, es decir, ninguna regla en la cadena INPUT de la tabla de filtros coincidió con el paquete. Luego fue RECHAZADO por la política de la tabla INPUT, como se muestra en la línea seis. La última línea muestra la llegada de otro paquete: el ID del paquete es diferente.

Al usar el objetivo TRACE, generalmente es una buena idea seleccionar solo los paquetes relevantes, por ejemplo, mediante

iptables -t raw -A PREROUTING -p icmp -j TRACE
xtables-monitor --event

1 EVENT: nft: NEW table: table filter ip flags 0 use 4 handle 444
2 EVENT: # nft: ip filter INPUT use 2 type filter hook input prio 0 policy drop packets 0 bytes 0
3 EVENT: # nft: ip filter FORWARD use 0 type filter hook forward prio 0 policy accept packets 0 bytes 0
4 EVENT: # nft: ip filter OUTPUT use 0 type filter hook output prio 0 policy accept packets 0 bytes 0
5 EVENT: -4 -t filter -N TCP
6 EVENT: -4 -t filter -A TCP -s 192.168.0.0/16 -p tcp -m tcp --dport 22 -j ACCEPT
7 EVENT: -4 -t filter -A TCP -p tcp -m multiport --dports 80,443 -j ACCEPT
8 EVENT: -4 -t filter -A INPUT -p tcp -j TCP
9 EVENT: -4 -t filter -A INPUT -m conntrack --ctstate RELATED,ESTABLISHED -j ACCEPT
10 NEWGEN: GENID=13904 PID=25167 NAME=iptables-nftables-restore

Este ejemplo muestra la monitorización de eventos. La línea uno muestra la creación de una tabla (en este caso, filter), seguida de tres cadenas base INPUT, FORWARD y OUTPUT. Las herramientas de iptables-nftables crean tablas y cadenas base automáticamente cuando es necesario, por lo que esto es esperado cuando una tabla aún no se ha inicializado o cuando se vuelve a crear desde cero mediante iptables-nftables-restore. La línea cinco muestra la adición de una nueva cadena definida por el usuario (TCP), seguida de la adición de algunas reglas. La última línea muestra que una nueva generación de reglas se ha activado, es decir, los cambios en el conjunto de reglas están ahora activos. Esto también enumera el ID del proceso y el nombre del programa.

LIMITACIONES

xtables-monitor solo funciona con reglas añadidas usando iptables-nftables, las reglas añadidas usando iptables-legacy no pueden ser monitorizadas.

ERRORES

Deben reportarse enviando un correo electrónico a netfilter-devel@vger.kernel.org o presentando un informe en https://bugzilla.netfilter.org/.
