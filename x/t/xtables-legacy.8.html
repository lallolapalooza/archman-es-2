NOMBRE

xtables-legacy — iptables usando la API antigua del kernel basada en getsockopt/setsockopt

DESCRIPCIÓN

xtables-legacy son las versiones originales de iptables que usan la interfaz antigua del kernel basada en getsockopt/setsockopt. Esta interfaz del kernel tiene algunas limitaciones, por lo que iptables también se puede usar con la API más nueva basada en nf_tables. Consulte xtables-nft(8) para obtener información sobre las variantes de iptables xtables-nft.

USO

El binario xtables-legacy-multi puede enlazarse a los nombres tradicionales:

/sbin/iptables -> /sbin/iptables-legacy-multi
/sbin/ip6tables -> /sbin/ip6tables-legacy-multi
/sbin/iptables-save -> /sbin/ip6tables-legacy-multi
/sbin/iptables-restore -> /sbin/ip6tables-legacy-multi

La cadena de versión de iptables indicará si se utiliza la API legado (get/setsockopt) o la nueva API nf_tables:

iptables -V
iptables v1.7 (legacy)

LIMITACIONES

Al insertar una regla usando iptables -A o iptables -I, iptables primero necesita recuperar el conjunto de reglas activas actual, cambiarlo para incluir la nueva regla y luego confirmar el resultado. Esto significa que si dos instancias de iptables se ejecutan simultáneamente, una de las actualizaciones podría perderse. Esto se puede solucionar parcialmente con la opción --wait.

Tampoco hay un método para monitorizar los cambios en el conjunto de reglas, excepto llamando periódicamente a iptables-legacy-save y verificando si hay diferencias en la salida. xtables-monitor(8) necesitará las versiones de xtables-nft(8) para funcionar, no puede mostrar cambios realizados utilizando las herramientas de iptables-legacy.

VER TAMBIÉN

xtables-nft(8), xtables-translate(8)
