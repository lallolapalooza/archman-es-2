XTABLES-NFT(8) Manual del Administrador del Sistema XTABLES-NFT(8)

NOMBRE

xtables-nft — iptables usando la API del kernel nftables

DESCRIPCIÓN

xtables-nft son versiones de iptables que utilizan la API de nftables. Este es un conjunto de herramientas para ayudar al administrador del sistema a migrar las reglas de iptables(8), ip6tables(8), arptables(8) y ebtables(8) a nftables(8).

El conjunto xtables-nft se compone de varios comandos:

•
iptables-nft
•
iptables-nft-save
•
iptables-nft-restore
•
ip6tables-nft
•
ip6tables-nft-save
•
ip6tables-nft-restore
•
arptables-nft
•
ebtables-nft

Estas herramientas utilizan las extensiones del framework libxtables y se enganchan al subsistema del kernel nf_tables usando el módulo nft_compat.

USO

Las herramientas xtables-nft permiten gestionar el backend de nf_tables utilizando la sintaxis nativa de iptables(8), ip6tables(8), arptables(8) y ebtables(8).

Deberías usar las herramientas xtables-nft exactamente de la misma manera que usarías las herramientas originales correspondientes.

Añadir una regla resultará en que dicha regla se añada al subsistema del kernel nf_tables. Listar el conjunto de reglas también usará el backend de nf_tables.

Cuando se diseñaron estas herramientas, la idea principal era reemplazar cada binario heredado con un enlace simbólico al programa xtables-nft, por ejemplo:

/sbin/iptables -> /usr/sbin/iptables-nft-multi
/sbin/ip6tables -> /usr/sbin/ip6tables-nft-multi
/sbin/arptables -> /usr/sbin/arptables-nft-multi
/sbin/ebtables -> /usr/sbin/ebtables-nft-multi

La cadena de versión de iptables indicará si se utiliza la API heredada (get/setsockopt) o la nueva API nf_tables:

iptables -V
iptables v1.7 (nf_tables)

DIFERENCIAS CON IPTABLES LEGADO

Dado que las herramientas xtables-nft utilizan la API del kernel nf_tables, las adiciones y eliminaciones de reglas son siempre atómicas. A diferencia de iptables-legacy, iptables-nft -A .. NO necesitará recuperar el conjunto de reglas actual del kernel, cambiarlo y recargar el conjunto de reglas alterado. En su lugar, iptables-nft indicará al kernel que añada una regla. Por esta razón, la opción --wait de iptables-legacy es inoperante en iptables-nft.

El uso de las herramientas xtables-nft permite monitorizar los cambios en el conjunto de reglas utilizando el comando xtables-monitor(8).

Al usar -j TRACE para depurar el recorrido de paquetes hasta el conjunto de reglas, ten en cuenta que necesitarás usar xtables-monitor(8) en modo --trace para obtener eventos de rastreo de monitorización.

EJEMPLOS

Un ejemplo básico es la creación del conjunto de reglas esqueleto en nf_tables a partir de las herramientas xtables-nft, en una máquina nueva:

root@machine:~# iptables-nft -L
[...]
root@machine:~# ip6tables-nft -L
[...]
root@machine:~# arptables-nft -L
[...]
root@machine:~# ebtables-nft -L
[...]
root@machine:~# nft list ruleset
table ip filter {
	chain INPUT {
		type filter hook input priority 0; policy accept;
	}
	chain FORWARD {
		type filter hook forward priority 0; policy accept;
	}
	chain OUTPUT {
		type filter hook output priority 0; policy accept;
	}
}
table ip6 filter {
	chain INPUT {
		type filter hook input priority 0; policy accept;
	}
	chain FORWARD {
		type filter hook forward priority 0; policy accept;
	}
	chain OUTPUT {
		type filter hook output priority 0; policy accept;
	}
}
table bridge filter {
	chain INPUT {
		type filter hook input priority -200; policy accept;
	}
	chain FORWARD {
		type filter hook forward priority -200; policy accept;
	}
	chain OUTPUT {
		type filter hook output priority -200; policy accept;
	}
}
table arp filter {
	chain INPUT {
		type filter hook input priority 0; policy accept;
	}
	chain FORWARD {
		type filter hook forward priority 0; policy accept;
	}
	chain OUTPUT {
		type filter hook output priority 0; policy accept;
	}
}

(ten en cuenta que en máquinas nuevas, listar el conjunto de reglas por primera vez da como resultado la creación de todas las tablas y cadenas).

Para migrar tu conjunto de reglas de filtro completo, en el caso de iptables(8), usarías:

root@machine:~# iptables-legacy-save > myruleset # lee desde x_tables
root@machine:~# iptables-nft-restore myruleset   # escribe en nf_tables
o 
root@machine:~# iptables-legacy-save | iptables-translate-restore | less

para ver cómo se verían las reglas en la sintaxis de nft de nft(8).

LIMITACIONES

Debes usar kernel de Linux >= 4.17.

El target CLUSTERIP no es compatible.

Para obtener información actualizada sobre esto, por favor, dirígete a http://wiki.nftables.org/.
