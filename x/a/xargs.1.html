XARGS(1) Manual de Comandos Generales XARGS(1)

NOMBRE

xargs - construir y ejecutar líneas de comando desde la entrada estándar

SINOPSIS

xargs [opciones] [comando [argumentos-iniciales]]

DESCRIPCIÓN

Esta página del manual documenta la versión de GNU de xargs. xargs lee elementos de la entrada estándar, delimitados por espacios en blanco (que pueden protegerse con comillas dobles o simples o una barra invertida) o saltos de línea, y ejecuta el comando (por defecto es echo) una o más veces con cualquier argumentos-iniciales seguido de los elementos leídos de la entrada estándar. Las líneas en blanco en la entrada estándar se ignoran.

La línea de comandos para comando se construye hasta que alcanza un límite definido por el sistema (a menos que se usen las opciones -n y -L). El comando especificado se invocará tantas veces como sea necesario para agotar la lista de elementos de entrada. Generalmente, habrá muchas menos invocaciones de comando que elementos en la entrada. Esto normalmente tendrá beneficios de rendimiento significativos. Algunos comandos pueden ejecutarse útilmente en paralelo; consulte la opción -P.

Debido a que los nombres de archivo de Unix pueden contener espacios en blanco y saltos de línea, este comportamiento predeterminado a menudo es problemático; los nombres de archivo que contienen espacios en blanco y/o saltos de línea son procesados incorrectamente por xargs. En estas situaciones es mejor usar la opción -0, que evita tales problemas. Al usar esta opción, deberá asegurarse de que el programa que produce la entrada para xargs también utiliza un carácter nulo como separador. Si ese programa es el GNU find, por ejemplo, la opción -print0 lo hace por usted.

Si alguna invocación del comando sale con un estado de 255, xargs se detendrá inmediatamente sin leer ninguna entrada adicional. Se emite un mensaje de error en stderr cuando esto ocurre.

OPCIONES

-0, --null
Los elementos de entrada están terminados por un carácter nulo en lugar de espacios en blanco, y las comillas y la barra invertida no son especiales (cada carácter se toma literalmente). Deshabilita la cadena de fin de archivo, que se trata como cualquier otro argumento. Útil cuando los elementos de entrada pueden contener espacios en blanco, comillas o barras invertidas. La opción GNU find -print0 produce una entrada adecuada para este modo.
-a archivo, --arg-file=archivo
Lee elementos del archivo en lugar de la entrada estándar. Si usa esta opción, stdin permanece sin cambios cuando se ejecutan los comandos. De lo contrario, stdin se redirige desde /dev/null.
--delimitador=delim, -d delim
Los elementos de entrada están terminados por el carácter especificado. El delimitador especificado puede ser un solo carácter, una secuencia de escape de carácter estilo C como \n, o un código de escape octal o hexadecimal. Los códigos de escape octales y hexadecimales se entienden como para el comando printf. No se admiten caracteres multibyte. Al procesar la entrada, las comillas y la barra invertida no son especiales; cada carácter de la entrada se toma literalmente. La opción -d deshabilita cualquier cadena de fin de archivo, que se trata como cualquier otro argumento. Puede usar esta opción cuando la entrada consiste simplemente en elementos separados por saltos de línea, aunque casi siempre es mejor diseñar su programa para usar --null donde sea posible.
-E cadena-fin-de-archivo
Establece la cadena de fin de archivo a cadena-fin-de-archivo. Si la cadena de fin de archivo aparece como una línea de entrada, el resto de la entrada se ignora. Si ni -E ni -e se utilizan, no se usa ninguna cadena de fin de archivo.
-e[cadena-fin-de-archivo], --eof[=cadena-fin-de-archivo]
Esta opción es un sinónimo de la opción -E. Use -E en su lugar, ya que cumple con POSIX mientras que esta opción no. Si se omite cadena-fin-de-archivo, no hay cadena de fin de archivo. Si ni -E ni -e se utilizan, no se usa ninguna cadena de fin de archivo.
-I cadena-reemplazo
Reemplaza las ocurrencias de cadena-reemplazo en los argumentos iniciales con nombres leídos de la entrada estándar. Además, los espacios en blanco sin comillas no terminan los elementos de entrada; en su lugar, el separador es el carácter de salto de línea. Implica -x y -L 1.
-i[cadena-reemplazo], --replace[=cadena-reemplazo]
Esta opción es un sinónimo de -Icadena-reemplazo si se especifica cadena-reemplazo. Si falta el argumento cadena-reemplazo, el efecto es el mismo que -I{}. La opción -i está obsoleta; use -I en su lugar.
-L max-lineas
Usa como máximo max-lineas líneas de entrada no vacías por línea de comando. Los espacios en blanco finales hacen que una línea de entrada se continúe lógicamente en la siguiente línea de entrada. Implica -x.
-l[max-lineas], --max-lines[=max-lineas]
Sinónimo de la opción -L. A diferencia de -L, el argumento max-lineas es opcional. Si max-lineas no se especifica, el valor predeterminado es uno. La opción -l está obsoleta ya que el estándar POSIX especifica -L en su lugar.
-n max-args, --max-args=max-args
Usa como máximo max-args argumentos por línea de comando. Se usarán menos de max-args argumentos si se excede el tamaño (ver la opción -s), a menos que se dé la opción -x, en cuyo caso xargs saldrá.
-P max-procs, --max-procs=max-procs
Ejecuta hasta max-procs procesos a la vez; el valor predeterminado es 1. Si max-procs es 0, xargs ejecutará tantos procesos como sea posible a la vez. Use la opción -n o la opción -L con -P; de lo contrario, es probable que solo se haga una ejecución. Mientras xargs se está ejecutando, puede enviar una señal SIGUSR1 a su proceso para aumentar el número de comandos a ejecutar simultáneamente, o una señal SIGUSR2 para disminuirlo. No puede aumentarlo por encima de un límite definido por la implementación (que se muestra con --show-limits). No puede disminuirlo por debajo de 1. xargs nunca termina sus comandos; cuando se le pide que disminuya, simplemente espera a que más de un comando existente termine antes de iniciar otro. xargs siempre espera a que todos los procesos hijos terminen antes de salir (pero ver BUGS).

Si no usa la opción -P, xargs no manejará las señales SIGUSR1 y SIGUSR2, lo que significa que terminarán el programa (a menos que estuvieran bloqueadas en el proceso padre antes de que se iniciara xargs).

Tenga en cuenta que depende de los procesos llamados que gestionen correctamente el acceso paralelo a los recursos compartidos. Por ejemplo, si más de uno intenta imprimir en la salida estándar, la salida se producirá en un orden indeterminado (y muy probablemente mezclado) a menos que los procesos colaboren de alguna manera para evitarlo. Usar algún tipo de esquema de bloqueo es una forma de evitar tales problemas. En general, usar un esquema de bloqueo ayudará a garantizar una salida correcta pero reducirá el rendimiento. Si no desea tolerar la diferencia de rendimiento, simplemente organice que cada proceso produzca un archivo de salida separado (o utilice recursos separados de otra manera).

-o, --open-tty
Reabre stdin como /dev/tty en el proceso hijo antes de ejecutar el comando. Esto es útil si desea que xargs ejecute una aplicación interactiva.
-p, --interactive
Pregunta al usuario si desea ejecutar cada línea de comando y lee una línea del terminal. Ejecuta la línea de comando solo si la respuesta comienza con `s' o `S'. Implica -t.
--process-slot-var=nombre
Establece la variable de entorno nombre a un valor único en cada proceso hijo en ejecución. Los valores se reutilizan una vez que los procesos hijos terminan. Esto puede usarse en un esquema de bloqueo rudimentario para que los procesos hijos se comporten de forma secuencial.

xargs(1)

NAME

xargs - build and execute command lines from standard input

SYNOPSIS

xargs [OPTION]... [COMMAND [ARG]...]

If COMMAND is omitted, the default is echo.

The COMMAND is run one or more times. Each invocation of the COMMAND uses some trailing arguments taken from the standard input.

DESCRIPTION

xargs reads items from the standard input, delimited by blanks (which can be quoted) or newlines, and executes the COMMAND one or more times with any initial-arguments followed by items read from standard input. If the COMMAND is not specified, use the default value echo. Most invocations of xargs build commands by appending arguments read from standard input to a fixed set of initial arguments.

Special characters in arguments read from standard input are quoted and then converted by the shell. Quote characters in the input are handled in a way that is compatible with the shell. Double quotes (") group words and prevent expansion, and quotes (') group words but do not prevent expansion. Special characters are: '(', ')', ';', '|', '&', '\', '`', '~', '$', '#', '^', '=', '{', '}', '\n', and whitespace.

The maximum length of the command line used is system-dependent but is typically obtained from sysconf(3) with the name _SC_ARG_MAX. If the command line is too long, xargs will run the command more than once. It is possible for xargs to run the command more than once even if the command line is not too long. For example, if you use the -n option.

When the standard input is empty, xargs terminates without running the command.

The options are recognized unless the -- option is specified.

-n max-args, --max-args=max-args
Use at most max-args arguments per command line.
-L max-lines, --max-lines=max-roots
Use at most max-lines non-blank input lines per command line. Blank lines in the input are skipped (i.e. not used to construct a command line).
-l, -i [replacement-string]
This is an alias for --replace.
-I replacement-string
This option replaces any existing --max-lines and --max-args options. Provide replacement-string from the standard input for each invocation of the command. This option is more limiting than the similar option in some other versions of xargs. Only the specified replacement-string is allowed to be used. Any command line arguments before -I are appended after the expanded command line argument.
--replace [replacement-string]
This option replaces any existing --max-lines and --max-args options. Provide replacement-string from the standard input for each invocation of the command. By default, replacement-string is `{}'. Any command line argument which contains the string replacement-string is replaced by the contents of the standard input. If the replacement-string is not specified, the default value is `{}`. The command line is constructed by taking the initial arguments, replacing the first occurrence of the replacement-string with the contents of the standard input. If the standard input does not contain any non-blank characters, the command is not executed.
-a file, --arg-file=file
Read items from the file instead of standard input.
-d delim, --delimiter=delim
Items are terminated by the delim character instead of by blanks and newlines. If delim is a two-character string, then the first character is the delimiter and the second is an initial character to be included in the arguments.
-D file, --diag-file=file
Same as --verbose, but use file instead of standard error.
-I replacement-string
Same as --replace.
-i [replacement-string]
Synonym for --replace.
-0, --null
Input items are terminated by a null character instead of by whitespace, and any quoted items or file names ending in a space are treated specially. This option is safe for file names containing whitespace or newlines. It is also the only option that can be used with the --max-args and --max-lines options, because those options require the input to be delimited.
-P max-procs, --max-procs=max-procs
Run up to max-procs processes at a time; the default is 1. If max-procs is 0, then xargs will run as many processes as possible at a time. Use with caution. This option is not compatible with the -n and -L options.
-r, --no-run-if-empty
If the standard input does not contain any nonblanks, do not run the command. Normally, the command is run once even if there is no input. This option is a GNU extension.
-s max-chars, --max-chars=max-chars
Use at most max-chars characters per command line, including the command and initial-arguments and the terminating nulls at the ends of the argument strings. The largest allowed value is system-dependent, and is calculated as the argument length limit for exec, less the size of your environment, less 2048 bytes of headroom. If this value is more than 128 KiB, 128 KiB is used as the default value; otherwise, the default value is the maximum. 1 KiB is 1024 bytes. xargs automatically adapts to tighter constraints.
--show-limits
Display the limits on the command-line length which are imposed by the operating system, xargs' choice of buffer size and the -s option. Pipe the input from /dev/null (and perhaps specify --no-run-if-empty) if you don't want xargs to do anything.
-t, --verbose
Print the command line on the standard error output before executing it.
-x, --exit
Exit if the size (see the -s option) is exceeded.
--
Delimit the option list. Later arguments, if any, are treated as operands even if they begin with -. For example, xargs -- --help runs the command --help (found in PATH) instead of printing the usage text, and xargs -- --mycommand runs the command --mycommand instead of rejecting this as unrecognized option.
--help
Print a summary of the options to xargs and exit.
--version
Print the version number of xargs and exit.

The options --max-lines (-L, -l), --replace (-I, -i) and --max-args (-n) are mutually exclusive. If some of them are specified at the same time, then xargs will generally use the option specified last on the command line, i.e., it will reset the value of the offending option (given before) to its default value. Additionally, xargs will issue a warning diagnostic on stderr. The exception to this rule is that the special max-args value 1 ('-n1') is ignored after the --replace option and its aliases -I and -i, because it would not actually conflict.

EXAMPLES

find /tmp -name core -type f -print | xargs /bin/rm -f

Find files named core in or below the directory /tmp and delete them. Note that this will work incorrectly if there are any filenames containing newlines or spaces.

find /tmp -name core -type f -print0 | xargs -0 /bin/rm -f

Find files named core in or below the directory /tmp and delete them, processing filenames in such a way that file or directory names containing spaces or newlines are correctly handled.

find /tmp -depth -name core -type f -delete

Find files named core in or below the directory /tmp and delete them, but more efficiently than in the previous example (because we avoid the need to use fork(2) and exec(2) to launch rm and we don't need the extra xargs process).

cut -d: -f1 < /etc/passwd | sort | xargs echo
Generates a compact listing of all the users on the system.

EXIT STATUS

xargs exits with the following status:

0
if it succeeds
123
if any invocation of the command exited with status 1–125
124
if the command exited with status 255
125
if the command is killed by a signal
126
if the command cannot be run
127
if the command is not found
1
if some other error occurred.

Exit codes greater than 128 are used by the shell to indicate that a program died due to a fatal signal.

STANDARDS CONFORMANCE

As of GNU xargs version 4.2.9, the default behaviour of xargs is not to have a logical end-of-file marker. POSIX (IEEE Std 1003.1, 2004 Edition) allows this.

The -l and -i options appear in the 1997 version of the POSIX standard, but do not appear in the 2004 version of the standard. Therefore you should use -L and -I instead, respectively.

The -o option is an extension to the POSIX standard for better compatibility with BSD.

The POSIX standard allows implementations to have a limit on the size of arguments to the exec functions. This limit could be as low as 4096 bytes including the size of the environment. For scripts to be portable, they must not rely on a larger value. However, I know of no implementation whose actual limit is that small. The --show-limits option can be used to discover the actual limits in force on the current system.

In versions of xargs up to and including version 4.9.0, SIGUSR1 and SIGUSR2 would not cause xargs to terminate even if the -P option was not used.

HISTORY

The xargs program was invented by Herb Gellis at Bell Labs. See the Texinfo manual for findutils, Finding Files, for more information.

BUGS

It is not possible for xargs to be used securely, since there will always be a time gap between the production of the list of input files and their use in the commands that xargs issues. If other users have access to the system, they can manipulate the filesystem during this time window to force the action of the commands xargs runs to apply to files that you didn't intend. For a more detailed discussion of this and related problems, please refer to the ``Security Considerations'' chapter in the findutils Texinfo documentation. The -execdir option of find can often be used as a more secure alternative.

When you use the -I option, each line read from the input is buffered internally. This means that there is an upper limit on the length of input line that xargs will accept when used with the -I option. To work around this limitation, you can use the -s option to increase the amount of buffer space that xargs uses, and you can also use an extra invocation of xargs to ensure that very long lines do not occur. For example:

somecommand | xargs -s 50000 echo | xargs -I '{}' -s 100000 rm '{}'

Here, the first invocation of xargs has no input line length limit because it doesn't use the -i option. The second invocation of xargs does have such a limit, but we have ensured that it never encounters a line which is longer than it can handle. This is not an ideal solution. Instead, the -i option should not impose a line length limit, which is why this discussion appears in the BUGS section. The problem doesn't occur with the output of find(1) because it emits just one filename per line.

In versions of xargs up to and including version 4.9.0, xargs -P would exit while some of its children were still running, if one of them exited with status 255.
