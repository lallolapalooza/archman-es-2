XAUTH(1) Manual de comandos generales XAUTH(1)

NOMBRE

xauth - utilidad del archivo de autorización X

SINOPSIS

xauth [ -f archivo_autorizacion ] [ -vqibn ] [ comando argumento ... ]

DESCRIPCIÓN

El programa xauth se utiliza para editar y mostrar la información de autorización utilizada para conectarse al servidor X. Este programa se usa normalmente para extraer registros de autorización de una máquina y fusionarlos en otra (como ocurre al usar inicios de sesión remotos o al otorgar acceso a otros usuarios). Los comandos (descritos a continuación) pueden introducirse interactivamente, en la línea de comandos de xauth o en scripts. Tenga en cuenta que este programa **no** contacta al servidor X excepto cuando se utiliza el comando generate. Normalmente, xauth no se utiliza para crear la entrada del archivo de autorización en primer lugar; el programa que inicia el servidor X (a menudo xdm o startx) lo hace.

OPCIONES

Las siguientes opciones pueden usarse con xauth. Pueden darse individualmente (por ejemplo, -q -i) o combinarse (por ejemplo, -qi).

-f archivo_autorizacion
Esta opción especifica el nombre del archivo de autorización a utilizar. Por defecto, xauth utilizará el archivo especificado por la variable de entorno XAUTHORITY o .Xauthority en el directorio personal del usuario.
-q
Esta opción indica que xauth debe operar en silencio y no imprimir mensajes de estado no solicitados. Este es el comportamiento predeterminado si se proporciona un comando de xauth en la línea de comandos o si la salida estándar no está dirigida a una terminal.
-v
Esta opción indica que xauth debe operar de forma verbosa e imprimir mensajes de estado que indiquen los resultados de varias operaciones (por ejemplo, cuántos registros se han leído o escrito). Este es el comportamiento predeterminado si xauth está leyendo comandos de su entrada estándar y su salida estándar está dirigida a una terminal.
-i
Esta opción indica que xauth debe ignorar cualquier bloqueo del archivo de autorización. Normalmente, xauth se negará a leer o editar cualquier archivo de autorización que haya sido bloqueado por otros programas (normalmente xdm u otro xauth).
-b
Esta opción indica que xauth debe intentar romper cualquier bloqueo del archivo de autorización antes de continuar. Use esta opción solo para limpiar bloqueos obsoletos.
-n
Esta opción indica que xauth no debe intentar resolver ningún nombre de host, sino que simplemente debe imprimir siempre la dirección del host tal como está almacenada en el archivo de autorización.
-V
Esta opción muestra el número de versión del ejecutable de xauth.

COMANDOS

Los siguientes comandos pueden usarse para manipular archivos de autorización:

add nombre_pantalla protocolo_nombre clave_hexadecimal
Se añade una entrada de autorización para la pantalla indicada usando el protocolo y los datos de clave proporcionados al archivo de autorización. Los datos se especifican como una cadena de longitud par de dígitos hexadecimales, cada par representa un octeto. El primer dígito de cada par representa los 4 bits más significativos del octeto, y el segundo dígito del par representa los 4 bits menos significativos. Por ejemplo, una clave_hexadecimal de 32 caracteres representaría un valor de 128 bits. Un nombre de protocolo que consiste solo en un punto se trata como una abreviatura de MIT-MAGIC-COOKIE-1.
generate nombre_pantalla protocolo_nombre [trusted|untrusted]
[timeout segundos] [group id_grupo] [data datos_hex]

Este comando es similar a add. La principal diferencia es que en lugar de requerir que el usuario proporcione los datos de la clave, se conecta al servidor especificado en nombre_pantalla y utiliza la extensión SECURITY para obtener los datos de la clave que se almacenarán en el archivo de autorización. Si no se puede contactar con el servidor o si no admite la extensión SECURITY, el comando falla. De lo contrario, se añade una entrada de autorización para la pantalla indicada utilizando el protocolo dado al archivo de autorización. Un nombre de protocolo que consiste solo en un punto se trata como una abreviatura de MIT-MAGIC-COOKIE-1.

Si se utiliza la opción trusted, los clientes que se conecten utilizando esta autorización tendrán control total de la pantalla, como de costumbre. Si se utiliza untrusted, los clientes que se conecten utilizando esta autorización se considerarán no confiables y se les impedirá robar o manipular datos pertenecientes a clientes de confianza. Consulte la especificación de la extensión SECURITY para obtener detalles completos sobre las restricciones impuestas a los clientes no confiables. El valor predeterminado es untrusted.

La opción timeout especifica cuánto tiempo en segundos será válida esta autorización. Si la autorización permanece sin usar (ningún cliente conectado con ella) durante más tiempo que este período, el servidor purgará la autorización y los intentos futuros de conexión con ella fallarán. Tenga en cuenta que la purga realizada por el servidor no elimina la entrada de autorización del archivo de autorización. El tiempo de espera predeterminado es de 60 segundos.

La opción group especifica el grupo de aplicaciones al que deberían pertenecer los clientes que se conecten con esta autorización. Consulte la especificación de la extensión de grupo de aplicaciones para obtener más detalles. El valor predeterminado es no pertenecer a un grupo de aplicaciones.

La opción data especifica los datos que el servidor debe utilizar para generar la autorización. Tenga en cuenta que esto **no** son los mismos datos que se escriben en el archivo de autorización. La interpretación de estos datos depende del protocolo de autorización. Los datos_hex están en el mismo formato que la clave_hexadecimal descrita en el comando add.

[n]extract archivo nombre_pantalla...
Las entradas de autorización para cada una de las pantallas especificadas se escriben en el archivo indicado. Si se utiliza el comando nextract, las entradas se escriben en un formato numérico adecuado para transmisión no binaria (como el correo electrónico seguro). Las entradas extraídas se pueden leer de nuevo utilizando los comandos merge y nmerge. Si el nombre de archivo consiste solo en un guion, las entradas se escribirán en la salida estándar.
[n]list [nombre_pantalla...]
Las entradas de autorización para cada una de las pantallas especificadas (o todas si no se nombran pantallas) se imprimen en la salida estándar. Si se utiliza el comando nlist, las entradas se mostrarán en el formato numérico utilizado por el comando nextract; de lo contrario, se mostrarán en formato de texto. Los datos de clave siempre se muestran en el formato hexadecimal dado en la descripción del comando add.
[n]merge [archivo...]
Las entradas de autorización se leen de los archivos especificados y se fusionan en la base de datos de autorización, reemplazando cualquier entrada existente que coincida. Si se utiliza el comando nmerge, se utiliza el formato numérico dado en la descripción del comando extract. Si un nombre de archivo consiste solo en un guion, se leerá la entrada estándar si no se ha leído antes.
remove nombre_pantalla...
Se eliminan del archivo de autorización las entradas de autorización que coinciden con las pantallas especificadas.
source archivo
El archivo especificado se trata como un script que contiene comandos de xauth para ejecutar. Las líneas en blanco y las líneas que comienzan con un signo de almohadilla (#) se ignoran. Se puede usar un guion para indicar la entrada estándar, si aún no se ha leído.
info
Se imprime en la salida estándar información que describe el archivo de autorización, si se han realizado cambios o no, y de dónde se están leyendo los comandos de xauth.
exit
Si se han realizado modificaciones, el archivo de autorización se escribe (si está permitido) y el programa sale. Un fin de archivo se trata como un comando exit implícito.
quit
Igual que exit.

COMANDOS

add display {cookie|hex:}string
Adds an entry to the authority file for the specified display. Authorization is based on a 128-bit number, which may be specified as a base-16 number (e.g., 0x...) or a base-64 number. If the authorization type is not specified, xauth defaults to MIT-R5-cookie.
generate display {cookie|hex:}string
Adds a new authorization entry to the authority file for the specified display. The string is used to generate the authorization. If the authorization type is not specified, xauth defaults to MIT-MAGIC-COOKIE-1.
info
Lists information about the current authority file.
load filename
Reads authorization entries from the specified file and adds them to the authority file.
remove display
Removes the entry for the specified display from the authority file.
[n]extract filename display
Writes the authorization entry for the specified display to the specified file. If n is given, no number sign (#) is printed before the number of bytes. If a hyphen is given in place of the filename, the output is written to standard output.
[n]merge filename
Reads authorization entries from the specified file and merges them into the authority file. If n is given, no number sign (#) is printed before the number of bytes. If a hyphen is given in place of the filename, the input is read from standard input.
[n]list [display]
Lists the contents of the authority file. If a display is specified, only the entry for that display is listed. If n is given, no number sign (#) is printed before the number of bytes.
quit
Exits the program, ignoring any modifications. This may also be accomplished by pressing the interrupt character.
version
This command shows the version number of the xauth executable.
help [string]
A description of all commands that begin with the given string (or all commands if no string is given) is printed on the standard output.
?
A short list of the valid commands is printed on the standard output.

NOMBRES DE PANTALLA

Los nombres de pantalla para los comandos add, [n]extract, [n]list, [n]merge y remove utilizan el mismo formato que la variable de entorno DISPLAY y el argumento común de línea de comandos -display. La información específica de la pantalla (como el número de pantalla) es innecesaria y se ignorará. Las conexiones en la misma máquina (como sockets de host local, memoria compartida y el nombre de host de protocolo de Internet localhost) se denominan hostname/unix:displaynumber para que las entradas locales de diferentes máquinas puedan almacenarse en un único archivo de autoridad.

EJEMPLO

El uso más común de xauth es extraer la entrada para la pantalla actual, copiarla a otra máquina y fusionarla en el archivo de autoridad del usuario en la máquina remota:

        %  xauth extract - $DISPLAY | ssh otherhost xauth merge -

El siguiente comando contacta al servidor :0 para crear una autorización utilizando el protocolo MIT-MAGIC-COOKIE-1. Los clientes que se conecten con esta autorización no serán de confianza.

%  xauth generate :0 .

ENTORNO

Este programa xauth utiliza las siguientes variables de entorno:

XAUTHORITY
para obtener el nombre del archivo de autoridad a utilizar si no se usa la opción -f.
HOME
para obtener el directorio de inicio del usuario si XAUTHORITY no está definido.

ARCHIVOS

$HOME/.Xauthority
archivo de autoridad predeterminado si XAUTHORITY no está definido.

VEASE TAMBIÉN

X(7), Xsecurity(7), xhost(1), Xserver(1), xdm(1), startx(1), Xau(3).

ERRORES

Los usuarios que tengan redes inseguras deben tener cuidado de utilizar mecanismos de transferencia de archivos cifrados para copiar entradas de autorización entre máquinas. De manera similar, el protocolo MIT-MAGIC-COOKIE-1 no es muy útil en entornos inseguros. Los sitios interesados en seguridad adicional pueden necesitar utilizar mecanismos de autorización cifrados como Kerberos.

Actualmente, los espacios no están permitidos en el nombre del protocolo. Se podría añadir el uso de comillas para los verdaderamente perversos.
