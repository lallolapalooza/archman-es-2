XA(1) Manual de comandos generales XA(1)

NOMBRE

xa - Ensamblador cruzado 6502/R65C02/65816

SINOPSIS

xa [OPCIÓN]... ARCHIVO

DESCRIPCIÓN

xa es un ensamblador cruzado multipaso para los procesadores de 8 bits de la serie 6502 (como el 6502, 65C02, 6504, 6507, 6510, 7501, 8500, 8501 y 8502), el R65C02 de Rockwell y el procesador de 16 bits 65816. Para una descripción de la sintaxis, consulte SINTAXIS DEL ENSAMBLADOR más adelante en esta página del manual.

OPCIONES

-E
No detenerse después de 20 errores, sino mostrar todos los errores.
-v
Salida detallada.
-C
Sin códigos de operación CMOS (el valor predeterminado es permitir los códigos de operación R65C02).
-W
Sin códigos de operación 65816 (predeterminado).
-w
Permitir códigos de operación 65816.
-B
Mostrar líneas con apertura/cierre de bloque (ver PSEUDO-OPS).
-c
Producir archivos objeto o65 en lugar de archivos ejecutables (no se realiza enlazado); los archivos pueden contener referencias indefinidas.
-o nombrearchivo
Establecer el nombre del archivo de salida. El valor predeterminado es a.o65; usar el nombre de archivo especial - para enviar la salida a la salida estándar.
-P nombrearchivo
Establecer el nombre del archivo de listado. El valor predeterminado es ninguno; usar el nombre de archivo especial - para imprimir el listado en la salida estándar.
-F formato
Establecer el formato del listado; el valor predeterminado es plain. El único otro formato actualmente compatible es html.
-e nombrearchivo
Establecer el nombre del archivo de registro de errores; el valor predeterminado es ninguno.
-l nombrearchivo
Establecer el nombre del archivo de lista de etiquetas; el valor predeterminado es ninguno. Esta es la tabla de símbolos y puede ser usada por desensambladores como dxa(1) para reconstruir el código fuente.
-r
Añadir una lista de referencias cruzadas a la lista de etiquetas (requiere -l).
-Xcompatset
Habilita configuraciones de compatibilidad para ser más (¡no completamente!) compatible con otros ensambladores y bases de código 6502. Actualmente se admiten los conjuntos de compatibilidad MASM, CA65 y C, con XA23 disponible como una opción obsoleta para bases de código que dependen de la compatibilidad con la versión anterior de xa. Se pueden especificar y combinar varios conjuntos de compatibilidad, por ejemplo, -XMASM -XXA23.
-XMASM permite que los dos puntos aparezcan en comentarios para compatibilidad con MASM. Esto no afecta la interpretación de los dos puntos en otros lugares y puede convertirse en el valor predeterminado en una versión futura.
-XCA65 añade características sintácticas más compatibles con ca65(1). Permite := para definir etiquetas (en lugar de simples =), y añade soporte para etiquetas sin nombre y etiquetas locales "baratas" usando el carácter @, pero deshabilita su otro significado para el modo de 24 bits (ver SINTAXIS DEL ENSAMBLADOR).
-XC habilita el uso de codificaciones de números estilo C 0xHEX y 0OCTAL.
-XXA23 restaura la compatibilidad parcial con xa 2.3.x. En particular, usa ^ para generar caracteres de control, deshabilita caracteres escapados con \, permite comentarios anidados multilínea y deshabilita todas las macros predefinidas del preprocesador de xa. Aunque algunas partes de esta opción siguen siendo sintaxis admitida, la opción en sí es intrínsecamente obsoleta y puede ser eliminada en la próxima versión 2.x o 3.x.
-a
Soporta etiquetas sin nombre estilo ca65(1) usando dos puntos, pero no el resto de las otras características compatibles de ca65(1). Esto permite su uso con el modo 65816, por ejemplo. Implica -XMASM.
-M
Esta opción está obsoleta y será eliminada en una versión futura; use -XMASM en su lugar. Permite que los dos puntos aparezcan en comentarios para compatibilidad con MASM. Esto no afecta la interpretación de los dos puntos en otros lugares, y puede convertirse en el valor predeterminado en una versión futura.
-k
Permite que el acento circunflejo (^) enmascare un carácter con $1f/31. Esto se puede usar como un atajo para caracteres de control, como ^m^j convirtiéndose en retorno de carro seguido de salto de línea.
-R
Iniciar el ensamblador en modo de reubicación, es decir, usar segmentos.
-U
No permitir etiquetas indefinidas en modo de reubicación.
-Llabel
Define label como una etiqueta absoluta (pero indefinida) incluso al enlazar.
-b? direccion
Establecer la base del segmento para el segmento ? en la dirección direccion. ? debe ser t, d, b o z para segmentos de texto, datos, bss o cero, respectivamente.
-A direccion
Hacer que el segmento de texto comience en una dirección tal que, cuando el archivo comience en la dirección direccion, la reubicación no sea necesaria. Anula -bt; los otros segmentos aún deben ser manejados con -b.
-G
Suprimir la lista de globales exportadas.
-DDEF=TEXTO
Definir una macro del preprocesador en la línea de comandos (ver PREPROCESADOR).
-I dir
Añadir el directorio dir a la ruta de inclusión (antes de XAINPUT; ver ENTORNO).
-O juego de caracteres
Definir el juego de caracteres de salida para cadenas de caracteres. Actualmente se admiten ASCII (predeterminado), PETSCII (ASCII de Commodore), PETSCREEN (códigos de pantalla de Commodore) y HIGH (establecer el bit alto en todos los caracteres).
-p?
Establecer el carácter alternativo del preprocesador en ?. Esto es útil cuando se desea usar cpp(1) y el preprocesador incorporado al mismo tiempo (ver PREPROCESADOR). Los caracteres pueden necesitar ser citados para su shell (ejemplo: -p'~').
--help
Mostrar resumen de opciones (-? es un sinónimo).
--version
Mostrar la versión del programa.

SINTAXIS DEL ENSAMBLADOR

Una introducción a la programación en lenguaje ensamblador 6502 y a la mnemotecnia está más allá del alcance de esta página del manual. Lo invitamos a investigar cualquiera de los excelentes libros sobre el tema; un título útil es "Machine Language For Beginners" de Richard Mansfield (COMPUTE!), que cubre los sistemas de 8 bits de Atari, Commodore y Apple, y está ampliamente disponible en el mercado de segunda mano.

xa admite tanto las instrucciones estándar NMOS 6502 como las instrucciones CMOS de Rockwell utilizadas en el 65C02 (R65C02). Con la opción -w, xa también aceptará instrucciones para el 65816. Las instrucciones indocumentadas del NMOS 6502 no se admiten intencionadamente y deben ingresarse manualmente usando la pseudo-op .byte (ver PSEUDO-OPS). Debido a conflictos entre los conjuntos de instrucciones del R65C02 y 65816 e instrucciones indocumentadas en el NMOS 6502, se desaconseja su uso.

En general, xa acepta el formato de ensamblador 6502 más o menos estándar popularizado por MASM y TurboAssembler. Los valores y las direcciones se pueden expresar como literales o como expresiones; es decir,

123
valor decimal
$234
valor hexadecimal (0x234 aceptado con -XC)
&123
octal (0123 aceptado con -XC)
%010110
binario
*
valor actual del contador de programa

El valor ASCII de cualquier carácter entre comillas se inserta directamente en el texto del programa (ejemplo: "A" inserta el byte "A" en el flujo de salida); ver también la sección PSEU

DO-OPS

Esto se ve afectado por el conjunto de caracteres actualmente seleccionado, si lo hay.

Las etiquetas definen ubicaciones dentro del texto del programa, al igual que en otros ensambladores de múltiples pasos. Una etiqueta se define por cualquier cosa que no sea un código de operación; por ejemplo, una línea como

etiqueta1 lda #0

define etiqueta1 como la ubicación actual del contador de programa (por lo tanto, la dirección del código de operación LDA). Una etiqueta se puede definir explícitamente asignándole el valor de una expresión, como

etiqueta2 = $d000

que define etiqueta2 como la dirección $d000, es decir, el inicio del bloque de registros VIC-II en computadoras Commodore 64. El contador de programa * se considera un tipo especial de etiqueta y se le puede asignar con sentencias como

* = $c000

que establece el contador de programa en la ubicación decimal 49152. Si se especifica -XCA65, también puede usar := además de =.

Con la excepción del contador de programa, a las etiquetas no se les puede asignar múltiples veces. Para declarar explícitamente la redefinición de una etiqueta, coloque un - (guion) antes de ella, por ejemplo,

-etiqueta2 = $d020

que establece etiqueta2 en el registro de color del borde de Commodore 64. El alcance de una etiqueta se ve afectado por el bloque en el que reside (ver PSEUDO-OPS para instrucciones de bloque). Una etiqueta también puede especificarse explícitamente con la opción de línea de comandos -L.

Redefinir una etiqueta no cambia el código ensamblado previamente que utilizó el valor anterior. Por lo tanto, dado que el contador de programa es un tipo especial de etiqueta, cambiar el contador de programa a un valor inferior no reordena el código ensamblado previamente y cambiarlo a un valor superior no genera relleno para colocar el código subsiguiente en la nueva ubicación. Este es un comportamiento intencional para facilitar la generación de código relocable e independiente de la posición, pero puede diferir de otros ensambladores que utilizan este comportamiento para enlazar. Sin embargo, es posible utilizar pseudo-ops para simular el comportamiento de otros ensambladores y usar xa como enlazador; ver PSEUDO-OPS y LINKING.

Si se especifica -XCA65 o -a, las etiquetas "sin nombre" pueden especificarse con : (es decir, sin etiqueta, solo dos puntos); las ramas pueden entonces referenciar estas etiquetas sin nombre con dos puntos y signos más para ramificación hacia adelante o signos menos para ramificación hacia atrás. Por ejemplo (de la documentación de ca65(1)),


: lda (ptr1),y ; #1
cmp (ptr2),y
bne :+ ; -> #2
tax
beq :+++ ; -> #4
iny
bne :- ; -> #1
inc ptr1+1
inc ptr2+1
bne :- ; -> #1


: bcs :+ ; #2 -> #3
ldx #$FF
rts


: ldx #$01 ; #3
: rts ; #4

Además, en el modo -XCA65, se pueden usar etiquetas locales "baratas", marcadas con el prefijo @. Estas etiquetas temporales solo existen entre dos etiquetas regulares y automáticamente salen de alcance con la siguiente etiqueta regular. Esto permite, con el cuidado razonable, reutilizar nombres de etiquetas comunes como "loop".

Para aquellas instrucciones donde el acumulador es el argumento implícito (como asl y lsr; inc y dec en R65C02; etc.), el modismo de especificar explícitamente el acumulador con a es innecesario ya que se seleccionará la forma correcta si no hay un argumento explícito. De hecho, por consistencia con el manejo de etiquetas, si hay una etiqueta llamada a, esto generará código que referencia esa etiqueta como una ubicación de memoria y no al acumulador. De lo contrario, el ensamblador se quejará.

Las etiquetas y los códigos de operación pueden tomar expresiones como sus argumentos para permitir valores calculados, y pueden referenciar otras etiquetas y/o el contador de programa. Una expresión como lab1+1 (que opera sobre el valor actual de la etiqueta lab1 y lo incrementa en uno) puede usar los siguientes operandos, dados de mayor a menor prioridad:

*
multiplicación (prioridad 10)
/
división entera (prioridad 10)
+
suma (prioridad 9)
-
resta (9)
<<
desplazamiento a la izquierda (8)
>>
desplazamiento a la derecha (8)
>= =>
mayor o igual que (7)
>
mayor que (7)
<= =<
menor o igual que (7)
<
menor que (7)
=
igual a (6); también se acepta ==
<> ><
no igual a (6); también se acepta !=
&
AND bit a bit (5)
^
XOR bit a bit (4)
|
OR bit a bit (3)
&&
AND lógico (2)
||
OR lógico (1)

Los paréntesis son válidos. Al redefinir una etiqueta, combinar operadores aritméticos o bit a bit con el operador = (igual) como += y así sucesivamente son válidos, por ejemplo,

-redefinetiqueta += (etiqueta12/4)

Normalmente, xa intenta determinar el valor del operando y (cuando se refiere a una ubicación de memoria) utiliza el banco de memoria, direcciones de 16 bits o (para 65816) de 24 bits según corresponda y cuando es compatible con el código de operación particular. Esto genera código más pequeño y rápido, y es casi siempre preferible.

Sin embargo, puede usar estos operadores de prefijo para forzar una representación particular del operando. Aquellos que generan un resultado de ocho bits también se pueden usar en modos de direccionamiento de 8 bits, como inmediato y banco de memoria.

<
byte bajo de la expresión, por ejemplo, lda #<vector
>
byte alto de la expresión
!
en situaciones donde la expresión podría entenderse como un valor absoluto o de banco de memoria, no intente optimizar a un argumento de banco de memoria para aquellos códigos de operación que lo admiten (es decir, manténgalo como palabra de 16 bits)
@
representar como cantidad de 24 bits para 65816, incluso si es menor de 24 bits (debe especificar la opción de línea de comandos -w, no debe especificar -XCA65)
`
forzar mayor optimización, incluso si la longitud de la instrucción no se puede determinar de manera confiable (ver NOTAS'Y'ERRORES)

Las expresiones pueden aparecer como argumentos de códigos de operación o dentro del preprocesador (ver PREPROCESADOR para la sintaxis). Por ejemplo,

lda etiqueta2+1

toma el valor en etiqueta2+1 (usando el valor de nuestra etiqueta anterior, esto sería $d021), y se ensamblará como $ad $21 $d0 en disco. De manera similar,

lda #<etiqueta2

tomará los 8 bits más bajos de etiqueta2 (es decir, $20), y los asignará al acumulador (ensamblando la instrucción como $a9 $20 en disco).

Los comentarios se especifican con un punto y coma (;), como

;esto es un comentario

También se pueden especificar en estilo de lenguaje C, usando /* */ y // que se entienden a nivel de PREPROCESADOR (q.v.).

Normalmente, los dos puntos (:) separan sentencias, como

etiqueta4 lda #0:sta $d020

o

etiqueta2: lda #2

(notar el uso de dos puntos para especificar una etiqueta, similar a algunos otros ensambladores, que xa también entiende con o sin los dos puntos). Esto también se aplica a los comentarios de punto y coma, de modo que

; un comentario:lda #0

se entiende como un comentario seguido de un código de operación. Para evitar esto, use el modo de compatibilidad -XMASM para permitir dos puntos dentro de los comentarios; esto puede convertirse en el predeterminado en una versión futura. La separación de sentencias con dos puntos no se aplica a los comentarios /* */ y //, que se manejan a nivel del preprocesador (q.v.).

PSEUDO-OPS

Pseudo-ops son códigos de operación falsos utilizados por el ensamblador para denotar comandos meta o incrustados. Como la mayoría de los ensambladores, xa tiene un conjunto rico.

.byt valor1,valor2,valor3,...
Especifica una cadena de bytes para colocarlos directamente en el objeto ensamblado. Los argumentos pueden ser expresiones. Se puede especificar cualquier número de bytes.
.asc "texto1" ,"texto2",...
Especifica una cadena de caracteres que se insertará en el objeto ensamblado. Las cadenas se entienden según el conjunto de caracteres especificado actualmente; por ejemplo, si se especifica ASCII, se representarán como ASCII, y si se especifica PETSCII, se traducirán al equivalente de Commodore ASCII. Otros ASCII no estándar como ATASCII para computadoras Atari deben usar los caracteres equivalentes ASCII; los caracteres gráficos y de control deben especificarse explícitamente usando .byt para el carácter preciso que desea. Tenga en cuenta que al especificar el argumento de un código de operación, .asc no es necesario; el carácter entre comillas se puede insertar simplemente (por ejemplo, lda #"A"), y también se ve afectado por el conjunto de caracteres actual. Se pueden especificar cualquier número de cadenas de caracteres.

.byt y .asc son sinónimos, por lo que puede mezclar cosas como .byt $43, 22, "una cadena de caracteres" y obtener el resultado esperado. La cadena está sujeta al conjunto de caracteres actual, pero los bytes restantes se insertan sin modificación.

.aasc "texto1" ,"texto2",...
Especifica una cadena de caracteres que se representa siempre en ASCII verdadero independientemente del conjunto de caracteres actual. Al igual que .asc, es sinónimo de .byt.
.word valor1,valor2,valor3...
Especifica una cadena de palabras de 16 bits para colocarlas en el objeto ensamblado en formato little-endian de 6502 (es decir, byte bajo/byte alto). Los argumentos pueden ser expresiones. Se puede especificar cualquier número de palabras.
.dsb longitud,byte_relleno
Especifica un bloque de datos; se insertará un total de longitud repeticiones de byte_relleno en el objeto ensamblado. Por ejemplo, .dsb 5,$10 insertará cinco bytes, cada uno siendo 16 decimal, en el objeto. Los argumentos pueden ser expresiones. Si solo se proporciona un argumento, entonces el argumento se trata como un número de bytes nulos para insertar. Ver LINKING para ver cómo usar este pseudo-op para enlazar múltiples objetos.
.bin offset,longitud,"nombre_archivo"
Incrusta un archivo binario sin mayor interpretació
ion especificada por filename desde el desplazamiento offset (relativo al principio del archivo) para length bytes. Esto te permite insertar datos como un archivo objeto ensamblado previamente o una imagen u otra estructura de datos binaria, incrustada directamente en el objeto de este archivo. Si length es cero, entonces se usa la longitud de filename, menos el desplazamiento. Los argumentos pueden ser expresiones. Consulta LINKING para ver cómo usar esta pseudo-instrucción para enlazar múltiples objetos.
.(
Abre un nuevo bloque para el alcance. Dentro de un bloque, todas las etiquetas definidas son locales a ese bloque y a cualquier sub-bloque, y salen de alcance tan pronto como el bloque contenedor se cierra (es decir, alcance léxico). Todas las etiquetas definidas fuera del bloque siguen siendo visibles dentro de él. Para declarar explícitamente una etiqueta global dentro de un bloque, precede la etiqueta con + o precedesla con & para declararla solo dentro del nivel anterior (o globalmente si solo estás a un nivel de profundidad). Se permiten dieciséis niveles de alcance.
.block se acepta como sinónimo de .(, así como .proc (pero no puedes especificar un nombre de alcance explícito como en ca65; solo se admiten bloques anónimos).
.)
Cierra un bloque. .bend o .endproc se aceptan como sinónimos.
.as .al .xs .xl
Solo relevantes en modo 65816 (con la opción -w especificada). Estas pseudo-instrucciones establecen qué tamaño de acumulador y registro X/Y se debe usar para instrucciones futuras; .as y .xs establecen operandos de 8 bits para el acumulador y los registros de índice, respectivamente, y .al y .xl establecen operandos de 16 bits. Estas pseudo-instrucciones a propósito no emiten automáticamente instrucciones sep y rep para establecer el ancho especificado en la CPU; establece los bits del procesador como necesites, o considera construir una macro. .al y .xl generan errores si -w no se especifica.
.assert expresión,"mensaje"
Evalúa expresión y si es falsa (es decir, se evalúa a cero), imprime mensaje como un error fatal, terminando el ensamblaje inmediatamente. Por ejemplo, un bloque de código ensamblado que crea ROM de alto nivel podría tener
.assert *<$fffa, "vectores de salto"
para asegurar que el código ensamblado no se filtre en los vectores de alto nivel del 6502. Si el código anterior es demasiado largo, la aserción será falsa y la condición se detectará de manera controlada. Cualquier operación puede usarse como parte de la expresión, incluidas comparaciones lógicas como =, ==, <, <=, >, >=, != y <>.
.include nombre_archivo
Incluye otro archivo en lugar de la pseudo-instrucción, como si el preprocesador lo hubiera hecho con una directiva #include (ver PREPROCESSOR), pero en la fase del ensamblador después de que el preprocesamiento ya haya ocurrido.

La siguiente pseudo-instrucción se aplica al modo de listado.

.listbytes numero
En la salida del listado, establece el número máximo de bytes hexadecimales a imprimir en el listado para pseudo-instrucciones como .byt, por defecto 8. El argumento especial unlimited establece un límite superior. Si el modo de listado está deshabilitado, esta pseudo-instrucción no tiene efecto observable.

Las siguientes pseudo-instrucciones se aplican principalmente a objetos .o65 reubicables. Una discusión completa del formato reubicable está fuera del alcance de esta página de manual; consulta http://www.6502.org/users/andre/o65/ para la especificación más actualizada.

.text .data .bss .zero
Estas pseudo-instrucciones cambian entre los diferentes segmentos, .text siendo la sección de código real, .data siendo el segmento de datos, .bss siendo espacio de etiquetas no inicializado para asignación y .zero siendo espacio de página cero no inicializado para asignación. En .bss y .zero, solo se evalúan las etiquetas. Estas pseudo-instrucciones son válidas en modos reubicable y absoluto.
.code
Para compatibilidad con ca65, actualmente se mapea a .text.
.zeropage
Para compatibilidad con ca65, actualmente se mapea a .zero.
.align valor
Alinea el segmento actual a un límite de byte (2, 4 o 256) según lo especificado por valor (y lo coloca en la cabecera cuando el modo de reubicación está habilitado). Otros valores generan un error.
.fopt tipo, valor1, valor2, valor3, ...
Actúa como .byt/.asc excepto que los valores se incrustan en el archivo objeto como opciones de archivo. El argumento tipo se usa para especificar la opción de archivo que se está referenciando. Una tabla de estas opciones se encuentra en la descripción del formato de archivo o65 reubicable. El resto de las opciones se interpretan como valores a insertar. Se puede especificar cualquier número de valores, y también pueden ser cadenas.
.import etiqueta1, etiqueta2, etiqueta3, ...
Define las etiquetas dadas como etiquetas globales que se importan y resuelven durante la etapa de enlace, como el parámetro de línea de comandos -L.
.importzp etiqueta1, etiqueta2, etiqueta3, ...
Análogo a .import, excepto que solo importa etiquetas de página cero (es decir, valores de byte).

PREPROCESADOR

xa implementa un preprocesador muy similar al del preprocesador del lenguaje C cpp(1) y muchas rarezas se aplican a ambos. Por ejemplo, al igual que en C, el uso de /* */ para delimitadores de comentarios también se admite en xa, y también lo son los comentarios que utilizan la doble barra //. El preprocesador también admite líneas de continuación, es decir, líneas que terminan con una barra invertida (\); la siguiente línea se anexa a ella como si no hubiera un salto de línea divisorio. Esto también se maneja en el nivel del preprocesador.

Por razones de memoria y complejidad, no se admite toda la amplitud de la sintaxis de cpp(1). En particular, las definiciones de macros no pueden definirse hacia adelante (es decir, una definición de macro solo puede hacer referencia a una definición de macro previamente definida), excepto para las funciones macro, donde se admite la evaluación recursiva; por ejemplo, para #define WW AA, AA debe haber sido definido previamente. Ciertas otras directivas no se admiten, ni la mayoría de las macros predefinidas estándar, y existen otras limitaciones en la evaluación y la longitud de la línea. Dado que los mantenedores de xa reconocen que algunos archivos requerirán un pre-procesamiento más complicado del que puede suministrar el preprocesador incorporado, el preprocesador aceptará salida de línea/nombre de archivo/banderas al estilo de cpp(1). Cuando se ven estas líneas en el archivo de entrada, xa las tratará como lo haría cc, excepto que las banderas se ignoran. xa no acepta archivos en la entrada estándar por razones de análisis, por lo que debe volcar la salida de su cpp(1) a un archivo temporal intermedio, como

cc -E test.s > test.xa
xa test.xa

No se necesitan argumentos especiales para xa; la presencia de la salida de cpp(1) se detecta automáticamente.

Tenga en cuenta que pasar su archivo a través de cpp(1) puede interferir con las propias directivas del preprocesador de xa. En este caso, para enmascarar las directivas de cpp(1), use la opción -p para especificar un carácter alternativo en lugar de #, como la tilde (por ejemplo, -p'~'). Con esta opción y argumento especificados, entonces en lugar de #include, por ejemplo, también puede usar ~include, además de #include (que también será aceptado por el preprocesador de xa, asumiendo que alguno sobreviva a cpp(1)). Se puede usar cualquier carácter, aunque opciones francamente patológicas pueden generar fallos divertidos y frustrantes durante el análisis. También puede usar esta opción para diferir las directivas del preprocesador que cpp(1) puede interpretar demasiado pronto hasta que el archivo llegue realmente a xa para su procesamiento.

Las siguientes macros predefinidas son compatibles, excepto si se especifica -XXA23:

XA_MAJOR
La versión principal actual de xa.
XA_MINOR
La versión menor actual de xa.

Las siguientes directivas del preprocesador son compatibles:

#include "nombre_archivo"
Inserta el contenido del archivo nombre_archivo en esta posición. Si el archivo no se encuentra, se busca utilizando las rutas especificadas por la opción de línea de comandos -I o la variable de entorno XAINPUT (véase). Al insertarse, el archivo también se analizará en busca de directivas del preprocesador.
#echo comentario
Inserta el comentario en el archivo de registro de errores, especificado con la opción de línea de comandos -e.
#print expresión
Calcula el valor de la expresión y lo imprime en el archivo de registro de errores.
#error mensaje
Muestra el mensaje como un error y termina el ensamblaje.
#define DEFINICION texto
Equivale la macro DEFINICION con el texto de tal manera que dondequiera que aparezca DEFINICION en el código fuente del ensamblaje, se sustituye texto en su lugar (igual que lo haría cpp(1)). Además, #define puede especificar funciones macro como cpp(1) de tal manera que una directiva como #define mult(a,b) ((a)*(b)) generaría el resultado esperado dondequiera que aparezca una expresión de la forma mult(a,b) en el código fuente. Esto también se puede especificar en la línea de comandos con la opción -D. Los argumentos de una función macro pueden ser evaluados recursivamente, a diferencia de otras definiciones #define; el preprocesador intentará reevaluar cualquier argumento que haga referencia a otra definición del preprocesador hasta diez veces antes de quejarse.

Las siguientes directivas son condicionales. Si la condición no se satisface, el código fuente entre la directiva y su #endif terminador se elimina y no se ensambla. Se admiten hasta quince niveles de anidamiento.

Verdadero solo si la macro DEFINICION está definida.
#ifndef DEFINICION
Lo opuesto; verdadero solo si la macro DEFINICION no ha sido definida previamente.

Verdadero si la expresión se evalúa a un valor distinto de cero. La expresión puede hacer referencia a otras macros.
#iflused etiqueta

ENLAZADO

xa está orientado a generar binarios secuenciales. El código se emite estrictamente en orden, incluso si el contador de programa se establece en una ubicación inferior a la del código ensamblado previamente, y el relleno no se emite automáticamente si el contador de programa se establece en una ubicación superior. Cambiar la ubicación del programa solo cambia las nuevas etiquetas para el código que se emite posteriormente; el código emitido previamente permanece sin cambios. Afortunadamente, para muchos archivos objeto, estas convenciones no tienen ningún efecto en su generación.

Sin embargo, algunas aplicaciones pueden requerir la generación de un archivo objeto construido a partir de varios componentes previamente generados y/o submódulos que pueden necesitar estar presentes en ubicaciones de memoria específicas. Con una pequeña cantidad de especificación adicional, también es posible usar xa para este propósito.

La primera forma de hacerlo utiliza el formato o65 para crear objetos reubicables que, a su vez, pueden ser enlazados por ldo65(1) (q.v.).

La segunda forma implica código ensamblado o la inserción de archivos objeto o datos previamente construidos con .bin, usando pseudo-operaciones .dsb con argumentos de expresión calculada para insertar cualquier relleno necesario entre ellos, en el orden secuencial en que deben residir en la memoria. Considere este ejemplo:


.word $1000
* = $1000


; este es tu código en $1000
part1 rts
; esta etiqueta marca el final del código
endofpart1


; ¡NO PONGAS UN NUEVO .word AQUÍ!
* = $2000
.dsb (*-endofpart1), 0
; sí, configúralo de nuevo
* = $2000


; este es tu código en $2000
part2 rts

Este ejemplo, escrito para microcomputadoras Commodore usando una dirección de inicio de 16 bits, tiene dos "módulos" en él: un bloque de código en $1000 (4096), indicado por el código entre las etiquetas part1 y endofpart1, y un segundo bloque en $2000 (8192) que comienza en la etiqueta part2.

El relleno se calcula mediante la pseudo-operación .dsb entre los dos módulos. Tenga en cuenta que el contador de programa se establece en la nueva dirección y luego una expresión calculada inserta el número correcto de bytes de relleno desde el final del código ensamblado en la parte 1 hasta la nueva dirección del contador de programa. Dado que esto aumenta el contador de programa, el contador de programa se restablece de nuevo y el ensamblaje continúa.

Cuando se cargue el objeto que genera este archivo fuente, habrá una instrucción rts en la dirección 4096 y otra en la dirección 8192, con bytes nulos entre ellas.

Si alguna de estas áreas necesita contener un archivo preconstruido, en lugar de código ensamblado, simplemente use una pseudo-operación .bin para cargar las porciones necesarias del archivo en la salida. El cálculo de direcciones y el número de bytes de relleno necesarios se realiza de la misma manera.

Aunque este ejemplo utilizó el contador de programa en sí mismo para calcular la diferencia entre direcciones, puede usar cualquier etiqueta para este propósito, teniendo en cuenta que solo el contador de programa determina dónde se resuelven las direcciones relativas dentro del código ensamblado.

NOTAS'N'ERRORES

Las instrucciones R65C02 ina (a menudo representada como inc a) y dea (dec a) deben ser representadas como instrucciones inc y dec desnudas, respectivamente.

Las instrucciones 65816 mvn y mvp usan dos parámetros de ocho bits, las únicas instrucciones en todo el conjunto de instrucciones que lo hacen. Las versiones anteriores de xa tomaban un solo valor absoluto de 16 bits. A partir de la versión 2.4.0, esta sintaxis antigua ya no se acepta.

Las etiquetas definidas posteriormente, es decir, etiquetas que se definen después de que se procesa la instrucción actual, no pueden ser optimizadas en instrucciones de página cero, incluso si la etiqueta termina siendo definida como una ubicación de página cero, porque el ensamblador no conoce el valor de la etiqueta de antemano durante la primera pasada cuando se calcula la longitud de una instrucción. En la segunda pasada, se emitirá una advertencia cuando una instrucción que podría haberse optimizado no se pueda hacer debido a esta limitación. (Obviamente, esto no se aplica a las instrucciones de salto o bifurcación porque de todos modos no son optimizables, y aquellas instrucciones que solo pueden tomar un parámetro de 8 bits siempre se convertirán a una cantidad de 8 bits.) Si la etiqueta no se puede definir de otra manera antes de la instrucción, el prefijo de comilla simple ` puede usarse para forzar una mayor optimización sin importar dónde se defina la etiqueta, siempre que la instrucción lo admita. Sin embargo, forzar la cuestión indiscriminadamente puede ser peligroso y no se recomienda; para desalentar esto, el ensamblador se quejará de su uso en situaciones de modo de direccionamiento donde no existe ambigüedad, como indexado indirecto, saltos, etc.
