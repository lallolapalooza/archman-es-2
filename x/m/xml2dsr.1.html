NOMBRE

xml2dsr - Convierte un documento XML a un archivo DICOM SR

SINOPSIS

xml2dsr [opciones] archivo-xml-entrada archivo-dsr-salida

DESCRIPCIÓN

La utilidad xml2dsr convierte el contenido de un documento XML (Extensible Markup Language) al formato DICOM Structured Reporting (SR) (formato de archivo o conjunto de datos en bruto). El Esquema XML dsr2xml.xsd todavía no sigue ningún formato estándar. Sin embargo, la aplicación xml2dsr podría mejorarse en este aspecto en el futuro (p. ej., al admitir HL7/CDA - Clinical Document Architecture).

Se puede crear un archivo XML apropiado usando la herramienta dsr2xml (se recomienda la opción +Xn para añadir la declaración del espacio de nombres XML al elemento raíz).

PARÁMETROS

archivo-xml-entrada   Nombre del archivo XML de entrada a convertir ("-" para stdin)
archivo-dsr-salida  Nombre del archivo DICOM SR de salida ("-" para stdout)

OPCIONES

Opciones generales

  -h   --help
         imprimir este texto de ayuda y salir
       --version
         imprimir información de versión y salir
       --arguments
         imprimir argumentos expandidos de la línea de comandos
  -q   --quiet
         modo silencioso, no imprimir advertencias ni errores
  -v   --verbose
         modo detallado, imprimir detalles del procesamiento
  -d   --debug
         modo de depuración, imprimir información de depuración
  -ll  --log-level  [l]evel: cadena de texto
         (fatal, error, warn, info, debug, trace)
         usar nivel l para el registrador
  -lc  --log-config  [f]ilename: cadena
         usar archivo de configuración f para el registrador

Opciones de entrada

codificación:
  +Ee  --template-envelope
         el elemento de plantilla encierra los elementos de contenido

Opciones de procesamiento

validación:
  +Vs  --validate-schema
         validar el documento XML contra el Esquema
         (no con --template-envelope)
  # requiere que libxml se compile con soporte para XML Schema
  +Vn  --check-namespace
         comprobar el espacio de nombres XML en la raíz del documento
identificadores únicos:
  +Ug  --generate-new-uids
         generar nuevos UID de Estudio/Serie/Instancia SOP
  -Uo  --dont-overwrite-uids
         no sobrescribir UIDs existentes (por defecto)
  +Uo  --overwrite-uids
         sobrescribir UIDs existentes

Opciones de salida

formato de archivo de salida:
  +F   --write-file
         escribir formato de archivo (por defecto)
  -F   --write-dataset
         escribir conjunto de datos sin metainformación del archivo
sintaxis de transferencia de salida:
  +t=  --write-xfer-same
         escribir con TS igual que la entrada (por defecto)
  +te  --write-xfer-little
         escribir con TS explícito VR little endian
  +tb  --write-xfer-big
         escribir con TS explícito VR big endian
  +ti  --write-xfer-implicit
         escribir con TS implícito VR little endian
  +td  --write-xfer-deflated
         escribir con TS explícito VR little endian deflactado
representaciones de valor post-1993:
  +u   --enable-new-vr
         habilitar soporte para nuevos VR (UN/UT) (por defecto)
  -u   --disable-new-vr
         deshabilitar soporte para nuevos VR, convertir a OB
codificación de longitud de grupo:
  +g=  --group-length-recalc
         recalcular longitudes de grupo si están presentes (por defecto)
  +g   --group-length-create
         escribir siempre con elementos de longitud de grupo
  -g   --group-length-remove
         escribir siempre sin elementos de longitud de grupo
codificación de longitud en secuencias y elementos:
  +e   --length-explicit
         escribir con longitudes explícitas (por defecto)
  -e   --length-undefined
         escribir con longitudes indefinidas
relleno final del conjunto de datos (no con --write-dataset):
  -p=  --padding-retain
         no cambiar el relleno (por defecto si no es --write-dataset)
  -p   --padding-off
         sin relleno (implícito si es --write-dataset)
  +p   --padding-create  [f]ile-pad [i]tem-pad: entero
         alinear archivo en múltiplos de f bytes
         y elementos en múltiplos de i bytes
nivel de compresión deflate (solo con --write-xfer-deflated):
  +cl  --compression-level  [l]evel: entero (por defecto: 6)
         0=sin comprimir, 1=más rápido, 9=mejor compresión

Compresión

Si libxml se compila con soporte para zlib, el archivo de entrada (archivo-xml-entrada) también puede comprimirse con ZIP, lo que generalmente resulta en archivos mucho más pequeños. Consulte la salida de la opción --version para verificar si el soporte para zlib está disponible.

Limitaciones

El Esquema XML dsr2xml.xsd no admite todas las variaciones del formato de salida de dsr2xml. Sin embargo, el formato de salida predeterminado (más la opción --use-xml-namespace) debería funcionar.

Las diferentes versiones de libxml parecen tener límites distintos para la longitud máxima del valor de un elemento XML. Por lo tanto, se debe evitar usar valores de elementos muy largos. Un límite típico para la versión 2.7.3 de libxml (y superiores) es de 10 MB para el valor de un solo elemento.

Por defecto, solo los errores y advertencias se escriben en el flujo de error estándar. Usando la opción --verbose también se informan mensajes informativos como detalles del procesamiento. En eventos de error muy graves, la aplicación generalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo "oflog".

Se proporciona un archivo de configuración de ejemplo en <etcdir>/logger.cfg.

COMANDO LÍNEA

Todas las herramientas de línea de comandos utilizan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos al final indican que se permiten varios valores (1-n), una combinación de ambos significa 0 a n valores.

Las opciones de línea de comandos se distinguen de los parámetros por un signo '+' o '-', respectivamente. Por lo general, el orden y la posición de las opciones de línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se utiliza la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix comunes.

Además, se pueden especificar uno o más archivos de comandos usando un signo '@' como prefijo del nombre del archivo (por ejemplo, @command.txt). Dicho argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre comillas dobles) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comandos no puede contener otro archivo de comandos. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (se proporciona un ejemplo en el archivo <datadir>/dumppat.txt).

AMBIENTE

La utilidad xml2dsr intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH. Por defecto, es decir, si la variable de entorno DCMDICTPATH no está configurada, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté integrado en la aplicación (predeterminado para Windows).

Se debe preferir el comportamiento predeterminado y utilizar la variable de entorno DCMDICTPATH solo cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix, en el sentido de que dos puntos (":") separan las entradas. En los sistemas Windows, se utiliza un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH. Es un error si no se puede cargar ningún diccionario de datos.
