XMLSEC1(1) Comandos de usuario XMLSEC1(1)

NOMBRE

xmlsec1 - firmar, verificar, cifrar y descifrar documentos XML

SINOPSIS

xmlsec <comando> [<opciones>] [<archivos>]

DESCRIPCIÓN

xmlsec es una herramienta de línea de comandos para firmar, verificar, cifrar y descifrar documentos XML. Los valores permitidos para <comando> son:

--ayuda
mostrar esta información de ayuda y salir
--ayuda-todo
mostrar información de ayuda para todos los comandos/opciones y salir
--ayuda-<cmd>
mostrar información de ayuda para el comando <cmd> y salir
--version
imprimir información de versión y salir
--llaves
manipulación de archivos XML de llaves
--firmar
firmar datos y generar documento XML
--verificar
verificar documento firmado
--firmar-tmpl
crear y firmar una plantilla de firma generada dinámicamente
--cifrar
cifrar datos y generar documento XML
--descifrar
descifrar datos de un documento XML

OPCIONES

--ignorar-manifiestos

no procesar elementos <dsig:Manifest>

--almacenar-referencias

almacenar e imprimir el resultado del procesamiento del elemento <dsig:Reference/> justo antes de calcular el resumen (digest)

--almacenar-firmas

almacenar e imprimir el resultado del procesamiento de <dsig:Signature> justo antes de calcular la firma

--uris-referencia-habilitados <lista>

lista separada por comas de los siguientes valores: "empty", "same-doc", "local", "remote" para restringir los valores posibles del atributo URI para el elemento <dsig:Reference>

--habilitar-hack-visa3d

habilita un hack específico del protocolo Visa3D para el procesamiento de atributos URI cuando intentamos no usar el motor XPath/XPointer; esto es un hack y no sé qué más podría romperse en tu aplicación cuando lo uses (también revisa la opción "--id-attr" porque podrías necesitarla)

--hmac-min-salida-len <bits>

establece la longitud mínima de salida de HMAC a <bits>

--datos-binarios <archivo>

archivo <archivo> binario para cifrar

--datos-xml <archivo>

archivo <archivo> XML para cifrar

--cipher-reference-uris-habilitados <lista>

lista separada por comas de los siguientes valores: "empty", "same-doc", "local", "remote" para restringir los valores posibles del atributo URI para el elemento <enc:CipherReference>

--clave-sesion <klass-llave>-<tamano-llave>

genera una nueva llave de sesión <klass-llave> de <tamano-llave> bits (por ejemplo, "--sesion des-192" genera una nueva llave DES de 192 bits para cifrado DES3)

--salida <nombrearchivo>

escribe el documento resultante en el archivo <nombrearchivo>; <nombrearchivo> puede ser una plantilla e incluir '{inputfile}' que se reemplazará con el nombre del archivo de entrada

--imprimir-debug

imprime información de depuración en stdout

--imprimir-xml-debug

imprime información de depuración en stdout en formato xml

--archivo-dtd <archivo>

carga el archivo especificado como DTD

--id-nodo <id>

establece el punto de inicio de la operación al nodo con el <id> dado

--nombre-nodo [<uri-namespace>:]<nombre>

establece el punto de inicio de la operación al primer nodo con el <nombre> y URI de <namespace> dados

--xpath-nodo <expresion>

establece el punto de inicio de la operación al primer nodo seleccionado por la expresión XPath especificada

--attr-id[:<nombre-attr>] [<uri-namespace-nodo>:]<nombre-nodo>

añade atributos <nombre-attr> (valor predeterminado "id") de todos los nodos con <nombre-nodo> y namespace <uri-namespace-nodo> a la lista de atributos ID conocidos; esto es un hack y si puedes usar DTD o esquema para declarar atributos ID en su lugar (ver opción "--archivo-dtd")

--add-attr-id <nombre-attr-id>

añade el atributo <nombre-attr-id> a todos los nodos del documento; esto es un hack y si puedes usar DTD o esquema para declarar atributos ID en su lugar (ver opción "--archivo-dtd")

--key-data-habilitado <lista>

lista separada por comas de los tipos de datos de llave a habilitar. Ejemplo:
rsa,dato-llave,x509
-> pobla <RSAKeyValue> y mantiene <X509Data>
cuando los marcadores <KeyValue/> y <X509Data/>
están presentes en la plantilla.
Usa "--listar-datos-llave" para ver la lista completa de clases de datos de llave registradas. Por defecto, todos los datos de llave registrados están habilitados.

--retrieval-method-uris-habilitados <lista>

lista separada por comas de los siguientes valores: "empty", "same-doc", "local", "remote" para restringir los valores posibles del atributo URI para el elemento <dsig:RetrievalMethod>.

--key-info-reference-uris-habilitados <lista>

lista separada por comas de los siguientes valores: "empty", "same-doc", "local", "remote" para restringir los valores posibles del atributo URI para el elemento <dsig11:KeyInfoReference>.

--generar-llave[:<nombre>] <klass-llave>-<tamano-llave>

genera una nueva llave <klass-llave> de <tamano-llave> bits, establece el nombre de la llave a <nombre> y añade el resultado al gestor de llaves (por ejemplo, "--generar:mikey rsa-1024" genera una nueva llave RSA de 1024 bits y establece su nombre a "mikey")

--archivo-llaves <archivo>

carga llaves desde un archivo XML

--privkey-pem[:<nombre>] <archivo>[,<archivo-ca>[,<archivo-ca>[...]]]

carga llave privada desde archivo PEM y certificados que verifican esta llave

--privkey-der[:<nombre>] <archivo>[,<archivo-ca>[,<archivo-ca>[...]]]

carga llave privada desde archivo DER y certificados que verifican esta llave

--pkcs8-pem[:<nombre>] <archivo>[,<archivo-ca>[,<archivo-ca>[...]]]

carga llave privada desde archivo PEM PKCS8 y certificados PEM que verifican esta llave

--pkcs8-der[:<nombre>] <archivo>[,<archivo-ca>[,<archivo-ca>[...]]]

carga llave privada desde archivo DER PKCS8 y certificados DER que verifican esta llave

--privkey-openssl-store[:<nombre>] <uri>

carga llave privada y certificados a través de la interfaz ossl_store de OpenSSL (por ejemplo, desde HSM)
