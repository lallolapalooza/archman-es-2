NOMBRE

xmlwf - Determina si un documento XML está bien formado

SINOPSIS


xmlwf
[OPCIONES] [ARCHIVO ...]

xmlwf
-h | --help

xmlwf
-v | --version

DESCRIPCIÓN

xmlwf utiliza la biblioteca Expat para determinar si un documento XML está bien formado. No valida.

Si no especifica ningún archivo en la línea de comandos, y tiene una versión reciente de xmlwf, el archivo de entrada se leerá de la entrada estándar.

DOCUMENTOS BIEN FORMADOS

Un documento bien formado debe cumplir las siguientes reglas:

•
El archivo comienza con una declaración XML. Por ejemplo, <?xml version="1.0" standalone="yes"?>. NOTA: xmlwf actualmente no verifica la declaración XML.
•
Cada etiqueta de inicio está vacía (<tag/>) o tiene una etiqueta de cierre correspondiente.
•
Hay exactamente un elemento raíz. Este elemento debe contener todos los demás elementos del documento. Solo comentarios, espacios en blanco y instrucciones de procesamiento pueden venir después del cierre del elemento raíz.
•
Todos los elementos se anidan correctamente.
•
Todos los valores de atributo están entre comillas (simples o dobles).

Si el documento tiene una DTD, y cumple estrictamente con esa DTD, entonces el documento también se considera válido. xmlwf es un analizador no validador: no verifica la DTD. Sin embargo, admite entidades externas (ver la opción -x).

OPCIONES

Cuando una opción incluye un argumento, puede especificar el argumento por separado ("-d salida") o concatenado con la opción ("-dsalida"). xmlwf admite ambas.

-a factor
Establece el factor de amplificación máximo tolerado para la protección contra ataques de mil risas (predeterminado: 100.0). El factor de amplificación se calcula como .. 
            amplificación := (directa + indirecta) / directa

.. mientras se analiza, donde <directa> es el número de bytes leídos del documento principal en el análisis y <indirecta> es el número de bytes añadidos al expandir entidades y leer archivos DTD externos, combinados.

NOTA: Si alguna vez necesita aumentar este valor para datos que no son de ataque, por favor, envíe un informe de error.

-b bytes
Establece el número de bytes de salida (incluida la amplificación) necesarios para activar la protección contra ataques de mil risas (predeterminado: 8 MiB). Esto puede considerarse un "umbral de activación".

NOTA: Si alguna vez necesita aumentar este valor para datos que no son de ataque, por favor, envíe un informe de error.

-c
Si el archivo de entrada está bien formado y xmlwf no encuentra ningún error, el archivo de entrada se copia sin cambios al directorio de salida. Esto implica que no hay espacios de nombres (desactiva -n) y requiere -d para especificar un directorio de salida.
-d directorio-salida
Especifica un directorio para contener representaciones transformadas de los archivos de entrada. Por defecto, -d genera una representación canónica (descrita a continuación). Puede seleccionar diferentes formatos de salida usando -c, -m y -N.

Los nombres de archivo de salida serán exactamente los mismos que los nombres de archivo de entrada o "STDIN" si la entrada proviene de la entrada estándar. Por lo tanto, debe tener cuidado de que el archivo de salida no vaya al mismo directorio que el archivo de entrada. De lo contrario, xmlwf eliminará el archivo de entrada antes de generar el archivo de salida (igual que ejecutar cat < archivo > archivo en la mayoría de las shells).

Dos documentos XML estructuralmente equivalentes tienen una representación XML canónica idéntica byte a byte. Tenga en cuenta que el espacio en blanco ignorado se considera significativo y se trata de manera equivalente a los datos. Puede encontrar más información sobre XML canónico en http://www.jclark.com/xml/canonxml.html .

-e codificación
Especifica la codificación de caracteres del documento, anulando cualquier declaración de codificación del documento. xmlwf admite cuatro codificaciones integradas: US-ASCII, UTF-8, UTF-16 e ISO-8859-1. Vea también la opción -w.
-g bytes
Establece el tamaño del búfer a solicitar por par de llamadas a XML_GetBuffer y read (predeterminado: 8 KiB).
-h, --help
Imprime información breve de uso en el comando xmlwf y luego sale. Similar a esta página de manual pero más concisa.
-k
Al procesar múltiples archivos, xmlwf por defecto se detiene después del primer archivo con un error. Esto le dice a xmlwf que informe el error pero que continúe procesando. Esto puede ser útil, por ejemplo, al probar un filtro que convierte muchos archivos a XML y desea averiguar rápidamente qué conversiones fallaron.
-m
Genera un tipo de archivo XML extraño que describe completamente el archivo de entrada, incluyendo las posiciones de los caracteres. Requiere -d para especificar un archivo de salida.
-n
Activa el procesamiento de espacios de nombres. (describir espacios de nombres) -c desactiva los espacios de nombres.
-N
Agrega declaraciones de doctype y notación a la salida XML canónica. Esto coincide con la salida de ejemplo utilizada por los casos de prueba XML formales. Requiere -d para especificar un archivo de salida.
-p
Indica a xmlwf que procese DTD externas y entidades de parámetros.

Normalmente xmlwf nunca analiza entidades de parámetros. -p le indica que siempre las analice. -p implica -x.

-q
Desactiva el aplazamiento de reprocesamiento y permite un tiempo de análisis cuadrático en tokens grandes (predeterminado: aplazamiento de reprocesamiento activado).
-r
Normalmente xmlwf mapea en memoria el archivo XML antes de analizarlo; esto puede resultar en un análisis más rápido en muchas plataformas. -r desactiva el mapeo en memoria y utiliza llamadas normales de E/S de archivo en su lugar. Por supuesto, el mapeo en memoria se desactiva automáticamente al leer desde la entrada estándar.

El uso del mapeo en memoria puede hacer que algunas plataformas informen un uso de memoria sustancialmente mayor para xmlwf, pero esto parece ser una cuestión de que el sistema operativo informa la memoria de manera extraña; no hay una fuga en xmlwf.

-s
Imprime un error si el documento no es independiente. Un documento es independiente si no tiene un subconjunto externo ni referencias a entidades de parámetros.
-t
Activa los tiempos. Esto le dice a Expat que analice el archivo completo, pero que no realice ningún procesamiento. Esto da una idea bastante precisa de la velocidad bruta de Expat en sí mismo sin sobrecarga del cliente. -t desactiva la mayoría de las opciones de salida (-d, -m, -c, ...).
-v, --version
Imprime la versión de la biblioteca Expat que se está utilizando, incluida alguna información sobre la configuración en tiempo de compilación de la biblioteca, y luego sale.
-w
Activa la compatibilidad con páginas de códigos de Windows. Normalmente, xmlwf generará un error si encuentra una codificación que no puede manejar por sí mismo. Con -w, xmlwf intentará usar una página de códigos de Windows. Vea también -e.
-x
Activa el análisis de entidades externas.

Los analizadores no validadores no están obligados a resolver entidades externas, o siquiera a expandir entidades. Expat siempre expande entidades internas (?), pero el análisis de entidades externas debe activarse explícitamente.

SALIDA

\n

xmlwf no produce ninguna salida para archivos que no tienen problemas. Si\ncualquier archivo de entrada no está bien formado, o si la salida para cualquier archivo\nde entrada no se puede abrir, xmlwf imprime una sola línea describiendo el problema\na la salida estándar.

\n

Si la opción -k no se proporciona, xmlwf se detiene al\nencontrar un error de buena formación o de archivo de salida. Si se proporciona -k,\nxmlwf continúa procesando los archivos de entrada restantes, describiendo los\nproblemas encontrados con cualquiera de ellos.

\n
\n
\n

ESTADO DE SALIDA

\n

Para las opciones -v|--version o -h|--help,\n xmlwf siempre sale con el código de estado 0. Para otros casos, los siguientes\ncódigos de estado de salida se devuelven:

\n
\n
0
\n
Los archivos de entrada están bien formados y la salida (si se solicitó) se escribió\n correctamente.
\n
1
\n
Ocurrió un error interno.
\n
2
\n
Uno o más archivos de entrada no estaban bien formados o no se pudieron analizar.
\n
3
\n
Si se utiliza la opción -d, ocurrió un error al abrir un archivo de salida.
\n
4
\n
Hubo un error en los argumentos de la línea de comandos en cómo se invocó\n xmlwf.
