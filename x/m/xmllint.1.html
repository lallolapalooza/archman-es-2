XMLLINT(1) Manual de xmllint XMLLINT(1)

NOMBRE

xmllint - herramienta XML de línea de comandos

SINOPSIS

xmllint [--version | --debug | --quiet | --shell | --xpath "expresión_XPath" | --copy | --recover | --huge | --nocompact | --nodefdtd | --nodict | --noenc | --noent | --nofixup-base-uris | --noout | --nonet | --path "RUTA(S)" | --load-trace | --valid | --postvalid | --dtdvalid URL | --dtdvalidfpi FPI | --timing | --output ARCHIVO | --repeat | --insert | --strict-namespace | --compress | --html | --xmlout | --push | --memory | --max-ampl ENTERO | --maxmem NBYTES | --nowarning | --noblanks | --nocdata | --format | --pretty ENTERO | --encode CODIFICACIÓN | --dropdtd | --nsclean | --catalogs | --nocatalogs | --auto | --xinclude | --noxincludenode | --loaddtd | --dtdattr | --stream | --walker | --pattern VALOR_PATRÓN | --relaxng SCHEMA | --schema SCHEMA | --schematron SCHEMA | --c14n | --c14n11 | --exc-c14n | --pedantic | --sax | --sax1 | --oldxml10] {ARCHIVO(S)_XML... | -}

DESCRIPCIÓN

El programa xmllint analiza uno o más archivos XML, especificados en la línea de comandos como ARCHIVO_XML (o la entrada estándar si el nombre de archivo proporcionado es - ). Imprime varios tipos de salida, dependiendo de las opciones seleccionadas. Es útil para detectar errores tanto en el código XML como en el propio analizador XML.

xmllint forma parte de la biblioteca libxml2.

OPCIONES DE VALIDACIÓN

Opciones que habilitan la validación.

--dtdvalid URL

Usa la DTD especificada por una URL para la validación.

--dtdvalidfpi FPI

Usa la DTD especificada por un Identificador Público Formal FPI para la validación, ten en cuenta que esto requerirá un catálogo que exporte ese Identificador Público Formal para funcionar.

--relaxng SCHEMA

Usa el archivo RelaxNG llamado SCHEMA para la validación.

--schema SCHEMA

Usa un archivo XML Schema W3C llamado SCHEMA para la validación.

--schematron SCHEMA

Usa un archivo Schematron llamado SCHEMA para la validación.

--valid

Determina si el documento es una instancia válida de la Definición de Tipo de Documento (DTD) incluida. Una DTD para validar también puede especificarse en la línea de comandos usando la opción --dtdvalid. Por defecto, xmllint también verifica si el documento está bien formado.

--strict-namespace

Devuelve un error si el documento está bien formado, pero tiene errores de espacio de nombres. Esto fuerza la corrección de los espacios de nombres.

OPCIONES DEL ANALIZADOR

Las siguientes opciones configuran las opciones del analizador respectivo.

--dtdattr

Obtiene DTD externas y popula el árbol con atributos heredados. Implica --loaddtd.

--huge

Ignora algunos límites codificados en el analizador.

--loaddtd

Obtiene una DTD externa y entidades de parámetros externas.

--max-ampl ENTERO

Establece el factor máximo de amplificación que protege contra la expansión exponencial de entidades ("risas de miles de millones"). El valor por defecto es 5. Los documentos que hacen un uso intensivo de la expansión de entidades pueden requerir un valor más alto.

--noblanks

Elimina los espacios en blanco "ignorables". Esta opción no es fiable y no debe usarse.

--nocatalogs

No usa ningún catálogo.

--nocdata

Sustituye las secciones CDATA por nodos de texto equivalentes.

--nodefdtd

No establece la doctype HTML por defecto (opción del analizador HTML_PARSE_NODEFDTD).

--noenc

Ignora la declaración de codificación (opción del analizador XML_PARSE_IGNORE_ENC).

--noent

Sustituye los valores de las entidades por referencias a entidades. Por defecto, xmllint deja las referencias a entidades en su lugar. Esto habilita la carga de DTDs y entidades externas.

--nofixup-base-uris

No arregla las URIs xml:base al procesar XIncludes (opción del analizador XML_PARSE_NOBASEFIX).

--nonet

No usa Internet para obtener DTDs o entidades. No tiene efecto con libxml2 2.15 o posterior.

--nowarning

No emite advertencias del analizador y/o validador.

--nsclean

Elimina las declaraciones de espacio de nombres redundantes.

--oldxml10

Usa reglas de análisis obsoletas anteriores a XML 1.0, 5ª edición.

--pedantic

Habilita advertencias adicionales.

--recover

Devuelve las porciones analizables de un documento no válido. El comportamiento exacto no está especificado. Se desaconseja el uso de esta opción.

--xinclude

Realiza el procesamiento XInclude.

OPCIONES MISCELÁNEAS

Opciones que no encajan en otra categoría.

--catalogs

Usa los catálogos SGML de SGML_CATALOG_FILES. Los catálogos XML se cargan por defecto.

--dropdtd

Elimina la DTD después del análisis.

--html

Usa el analizador HTML.

--path "RUTA(S)"

Usa la lista (separada por espacios o dos puntos) de rutas del sistema de archivos especificada por RUTAS para cargar DTDs o entidades. Encierra las listas separadas por espacios entre comillas.

--quiet

No imprime mensajes informativos a stderr.

--sax

Imprime callbacks SAX para depuración. Puede usarse para validación de DTD y Schema en streaming cuando se usa con --noout.

--shell

Ejecuta un shell de navegación. Detalles sobre los comandos disponibles en modo shell a continuación (ver la sección llamada “COMANDOS DEL SHELL”).

--stream

Usa la API de streaming - útil cuando se usa en combinación con las opciones --relaxng o --valid para la validación de archivos que son demasiado grandes para ser mantenidos en memoria.

--version

Muestra la versión de libxml2 utilizada.

OPCIONES DE SALIDA

Opciones que controlan la salida. Excepto --noout, estas no tienen efecto en el modo SAX o stream.

--compress

Activa la compresión gzip(1) de la salida.

--c14n, --c14n11, --exc-c14n

Usa la Canonicalización XML W3C (C14N) para serializar el resultado del análisis a stdout. Mantiene los comentarios en el resultado.

--encode CODIFICACIÓN

Salida en la codificación dada. Ten en cuenta que esto funciona para documentos completos, no para fragmentos o resultados de consultas XPath.

--format

Reforma y reindenta la salida. La variable de entorno XMLLINT_INDENT controla la indentación. El valor por defecto es dos espacios (" ").

Especialmente en ausencia de una DTD, esta característica nunca ha funcionado de manera fiable y está fundamentalmente rota.

--noout

Suprime la salida. Por defecto, xmllint produce el árbol de resultados.

--output <

OPCIONES DE SALIDA

--file ARCHIVO

Define una ruta de archivo donde xmllint guardará el resultado del análisis. Normalmente los programas construyen un árbol y lo guardan en stdout, con esta opción la instancia XML resultante se guardará en un archivo.

--pretty ENTERO

El valor 0 significa sin formato, 1 significa XML_SAVE_FORMAT (igual que --format), 2 significa XML_SAVE_WSNONSIG.

--xmlout

Se usa junto con --html. Normalmente, cuando se analiza HTML, el documento se guarda con el serializador HTML. Pero con esta opción, el documento resultante se guarda con el serializador XML. Esto se usa principalmente para generar XHTML a partir de entrada HTML.

OPCIONES DE DEPURACIÓN

Las siguientes opciones se pueden usar para depurar la biblioteca libxml2. El comportamiento de estas opciones puede cambiar sin previo aviso.

--auto

Genera un documento pequeño para fines de prueba.

--copy

Prueba la implementación interna de copia.

--debug

Analiza un archivo y muestra un árbol anotado de la versión en memoria del documento.

--insert

Prueba para inserciones válidas. OBSOLETO: Esta función se eliminará.

--load-trace

Muestra todos los documentos cargados durante el procesamiento en stderr.

--maxmem NNBYTES

Prueba el soporte de memoria del analizador. NNBYTES es el número máximo de bytes que la biblioteca puede asignar. Esto también se puede usar para asegurar que el procesamiento por lotes de archivos XML no agote la memoria virtual del servidor que los ejecuta.

--memory

Analiza desde memoria.

--nocompact

No generar nodos de texto compactos (opción del analizador XML_PARSE_COMPACT). Solo para depuración.

--nodict

No usar diccionarios (opción del analizador XML_PARSE_NODICT). Solo para depuración.

--noxincludenode

Realiza el procesamiento XInclude pero no genera nodos de inicio y fin de XInclude.

--pattern VALORPATRON

Se utiliza para ejercitar el motor de reconocimiento de patrones, que se puede usar con la interfaz lector del analizador. Permite seleccionar algunos nodos en el documento basándose en una expresión XPath (subconjunto). Se utiliza para depuración.

--postvalid

Valida después de que el análisis haya completado.

--push

Utiliza el modo push del analizador.

--repeat

Repite 100 veces, para medir tiempos o perfilar.

--sax1

Utiliza la interfaz SAX1 obsoleta (solo para depuración).

--timing

Muestra información sobre el tiempo que tarda xmllint en realizar los diversos pasos.

--walker

Prueba el módulo walker, que es una interfaz lector pero para un árbol de documentos; en lugar de usar la API lector en un documento no analizado, trabaja sobre un árbol existente en memoria. Se utiliza para depuración.

--xpath "expresión_XPath"

Ejecuta una expresión XPath dada como argumento e imprime el resultado. En caso de un conjunto de nodos como resultado, cada nodo del conjunto se serializa completamente en la salida. En caso de un conjunto de nodos vacío, se mostrará el resultado "XPath set is empty" y se devolverá el código de salida 11.

COMANDOS DEL SHELL

xmllint ofrece un modo de shell interactivo invocado con el comando --shell. Los comandos disponibles en modo shell incluyen (en orden alfabético):

base

Muestra la base XML del nodo.

bye

Sale del shell.

cat NODO

Muestra el nodo dado o el nodo actual.

cd RUTA

Cambia el nodo actual a la ruta dada (si es única) o a la raíz si no se proporciona argumento.

dir RUTA

Muestra información sobre el nodo (espacio de nombres, atributos, contenido).

du RUTA

Muestra la estructura del subárbol bajo la ruta dada o el nodo actual.

exit

Sale del shell.

help

Muestra esta ayuda.

load NOMBREARCHIVO

Carga un nuevo documento con el nombre de archivo dado.

ls RUTA

Lista el contenido de la ruta dada o el directorio actual.

pwd

Muestra la ruta al nodo actual.

quit

Sale del shell.

save NOMBREARCHIVO

Guarda el documento actual en el nombre de archivo dado o en el nombre original.

validate

Comprueba si hay errores en el documento.

write NOMBREARCHIVO

Escribe el nodo actual en el nombre de archivo dado.

ENTORNO

SGML_CATALOG_FILES

El comportamiento del catálogo SGML se puede cambiar redirigiendo las consultas al propio conjunto de catálogos del usuario. Esto se puede hacer estableciendo la variable de entorno SGML_CATALOG_FILES a una lista de catálogos. Una lista vacía debería desactivar la carga del catálogo predeterminado.

XML_CATALOG_FILES

El comportamiento del catálogo XML se puede cambiar redirigiendo las consultas al propio conjunto de catálogos del usuario. Esto se puede hacer estableciendo la variable de entorno XML_CATALOG_FILES a una lista de catálogos separada por espacios. Utilice la codificación por porcentaje para escapar espacios u otros caracteres. Una variable vacía debería desactivar la carga del catálogo predeterminado.

XML_DEBUG_CATALOG

Establecer la variable de entorno XML_DEBUG_CATALOG a un valor distinto de cero utilizando el comando export muestra información de depuración relacionada con las operaciones del catálogo.

XMLLINT_INDENT

Establecer la variable de entorno XMLLINT_INDENT controla la indentación. El valor predeterminado son dos espacios " ".

DIAGNÓSTICOS

Los códigos de retorno de xmllint proporcionan información que se puede utilizar al llamarlo desde scripts.

0

Sin error

1

No clasificado

2

Error en DTD

3

Error de validación

4

El documento no está bien formado o no se pudo leer

5

Error en la compilación del esquema

6

Error al escribir la salida

7

Error en el patrón (generado cuando se utiliza la opción --pattern)

9

Error de falta de memoria

10

Error de evaluación XPath

11

El resultado XPath está vacío
