NOMBRE

xmlto - aplicar una hoja de estilos XSL a un documento XML

SINOPSIS

xmlto [-o dir_salida] [-x xsl_personalizado] [-m fragmento_xsl] [-v] [-p opts_posprocesador] [--extensions] [--searchpath ruta] [--skip-validation] [--stringparam nombre_param=valor_param] [--noclean] [--noautosize] [--noextensions] [--profile] [--with-fop] [--with-dblatex] {formato} {archivo}

xmlto {[--help] | [--version]}

DESCRIPCIÓN

El propósito de xmlto es convertir un archivo XML al formato deseado utilizando los medios necesarios. Esto puede implicar dos pasos:

1.La aplicación de una hoja de estilos apropiada usando un procesador XSL-T.
2.Procesamiento adicional con otras herramientas. Este paso puede no ser necesario.

Para decidir qué hoja de estilos usar y qué se necesita hacer para posprocesar la salida, xmlto utiliza scripts de formato, que son scripts de shell simples que xmlto llama durante la conversión.

El script de formato apropiado se selecciona basándose en el tipo de archivo XML y el formato de salida deseado. xmlto viene con algunos scripts de formato para convertir archivos XML DocBook a una variedad de formatos. Puede especificar su propio script de formato utilizando un nombre de archivo absoluto para formato en la línea de comandos.

En primer lugar, si no se le ha dicho explícitamente a xmlto qué hoja de estilos usar (con la opción -x), se llamará al script de formato con $1 establecido a stylesheet. La variable de entorno XSLT_PROCESSOR contiene el nombre base del ejecutable que se utilizará para realizar la transformación XSL-T (por ejemplo, xsltproc). El script de formato debe escribir el nombre de la hoja de estilos a usar en la salida estándar y salir con éxito, o salir con un código de retorno distinto de cero si no hay una hoja de estilos apropiada para usar (por ejemplo, si la única hoja de estilos disponible se sabe que no funciona con el procesador XSL-T que se utilizará). Si no se escribe nada en la salida estándar pero el script sale con éxito, no se realizará ninguna transformación XSL-T.

En segundo lugar, después de que se ejecute un procesador XSL-T usando la hoja de estilos, se llamará nuevamente al script de formato, esta vez con $1 establecido a post-process. El script de formato debe realizar cualquier paso necesario para traducir la salida procesada por XSL-T al formato de salida deseado, incluida la copia de la salida al directorio de salida deseado. Para el posprocesamiento, el script de formato se ejecuta en un directorio temporal que contiene solo la salida procesada (cuyo nombre está almacenado en XSLT_PROCESSED y cuyo nombre base es el del archivo XML original con cualquier extensión de nombre de archivo reemplazada por .proc). INPUT_FILE se establece en el nombre del archivo XML original, OUTPUT_DIR se establece en el nombre del directorio en el que debe terminar la salida (y solo la salida), y SEARCHPATH se establece en una lista separada por dos puntos de directorios de respaldo en los que buscar la entrada (para imágenes, por ejemplo). Si este paso no tiene éxito, el script de formato debe salir con un código de retorno distinto de cero.

OPCIONES

-v

Ser verboso (-vv para muy verboso).

-x hoja_estilos

Usar hoja_estilos en lugar de pedir al script de formato que elija una.

-m fragmento

Usar el fragmento XSL proporcionado para modificar la hoja de estilos.

-o directorio

Colocar la salida en el directorio especificado en lugar del directorio de trabajo actual.

-p opts_posprocesador

Pasar opts_posprocesador a las etapas de procesamiento después de la aplicación de la hoja de estilos (por ejemplo, lynx o links al pasar de HTML a texto, o xmltex al pasar de TeX a DVI). Si se especifica -p una segunda vez, las opciones especificadas se pasarán al posprocesamiento de segunda etapa; actualmente esto solo es aplicable al pasar por xmltex y dvips a PostScript.

--extensions

Activar las extensiones de hoja de estilos para la cadena de herramientas en uso (use.extensions está activado). Las variables activadas son las utilizadas por las hojas de estilos DocBook XSL de Norman Walsh.

--searchpath ruta

Añadir la lista de directorios separada por dos puntos en ruta como directorios de respaldo para incluir la entrada.

--skip-validation

Omitir el paso de validación que normalmente se realiza.

--stringparam nombre_param=valor_param

Pasar un parámetro con nombre nombre_param con valor valor_param a la hoja de estilos desde la línea de comandos.

--noclean

Los archivos temporales no se eliminan (sus nombres se muestran y se conservan en el directorio tmp). Esto podría ayudar a analizar problemas.

--noautosize

Por defecto, algunas variables XSL se sobrescriben por autodetectar (uso de page.width y page.height para libpaper, selección basada en la configuración regional (LC_PAPER) para paper.type). Con esta opción, xmlto no usa esta autodetección y el usuario puede modificar los valores por defecto él mismo (ya sea mediante la modificación de param.xsl por defecto o mediante un fragmento XSL definido por el usuario).

--noextensions

Por defecto, xmlto habilita los parámetros XSL passivetex.extensions para el backend passivetex y fop.extensions y fop1.extensions para el backend fop. Esto generalmente produce mejores resultados. Si por alguna razón no desea usar estos parámetros, simplemente desactívelos usando esta opción.

--profile

Preprocesar el documento XML con la hoja de estilos de perfilado.

--with-fop

Usar fop para el formateo. Es una opción experimental, espera fop en una ubicación específica (detectada en el momento de la configuración), puede ser modificada manualmente en el script xmlto modificando FOP_PATH

--with-dblatex

Usar dblatex para el formateo. Es una opción experimental, espera dblatex en una ubicación específica (detectada en el momento de la configuración), puede ser modificada manualmente en el script xmlto modificando DBLATEX_PATH

--help

Mostrar un breve mensaje de uso. Describirá las opciones de xmlto y los formatos de salida disponibles.

--version

Mostrar el número de versión de xmlto.

AMBIENTE

XSLT_PROCESSOR

Nombre base del ejecutable que se utilizará para realizar la transformación XSL-T (predeterminado: xsltproc(1)).

TMPDIR

Directorio donde crear las hojas de estilos temporales (predeterminado: /tmp).

DIAGNÓSTICO

0

Todo salió bien. Este es el código de salida esperado.

1

Se llamó a xmlto con argumentos insuficientes.

2

mktemp falló al crear un archivo/directorio. Asegúrese de que /tmp o TMPDIR sean escribibles.

3

xmlto no pudo encontrar algún binario en la ubicación configurada. Asegúrese de que todos los paquetes necesarios estén instalados y que las rutas en el script xmlto estén configuradas correctamente.

10+(Código de error de validación distinto de cero)

xmlto intentó validar un documento xml, pero la validación falló. Para un mejor diagnóstico, se proporciona la salida de validación y el código de salida de xmllint. Considere arreglar su documento o usar --skip-validation.

EJEMPLOS

Para convertir un documento DocBook XML a PDF, use:

xmlto pdf mi_doc.xml

Para convertir un documento DocBook XML a HTML y almacenar los archivos HTML resultantes en un directorio separado, use:

xmlto -o dir_html html mi_doc.xml

Para convertir un documento DocBook XML a un único archivo HTML, use:

xmlto html-nochunks mi_doc.xml

EXAMPLES

To modify the output using an XSL fragment use:

xmlto -m ulink.xsl pdf mydoc.xml

To specify which stylesheet to use (overriding the one that the format script would choose) use:

xmlto -x mystylesheet.xsl pdf mydoc.xml
