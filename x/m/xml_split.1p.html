NOMBRE

xml_split - corta un archivo XML grande en fragmentos más pequeños

DESCRIPCIÓN

"xml_split" toma un archivo XML (presumiblemente grande) y lo divide en varios archivos más pequeños. La memoria utilizada es la memoria necesaria para el fragmento más grande (es decir, la memoria se reutiliza para cada nuevo fragmento).

Puede dividir en un nivel dado en el árbol (por defecto, divide los hijos de la raíz) o según una condición (utilizando el subconjunto de XPath comprendido por XML::Twig, por lo tanto "section" o "/doc/section").

Cada archivo generado se reemplaza por una instrucción de procesamiento que permitirá a "xml_merge" reconstruir el documento original. El formato de la instrucción de procesamiento es "<?merge subdocs=[01] :<nombre_archivo> ?>"

Los nombres de archivo son <archivo>-<num>.xml, con <archivo>-00.xml conteniendo el documento principal.

OPCIONES

-l <nivel>
nivel para cortar: 1 genera un archivo para cada hijo de la raíz, 2 para cada nieto

por defecto es 1

-c <condición>
genera un archivo para cada elemento que cumple la condición

xml_split -c <section> pondrá cada elemento "section" en su propio archivo (las secciones anidadas también se manejan)

Tenga en cuenta que en este momento esta opción es mucho más lenta que usar "-l"

-s <tamaño>
genera archivos de (aproximadamente) <tamaño>. El contenido de cada archivo está encerrado en un nuevo elemento ("xml_split::root"), para que sea XML bien formado. El tamaño se puede dar en bytes, Kb, Mb o Gb.
-g <num>
agrupa <num> elementos en un solo archivo. El contenido de cada archivo está encerrado en un nuevo elemento ("xml_split::root"), para que sea XML bien formado.
-b <nombre>
nombre base para la salida, los archivos se nombrarán <base>-<num><.ext>

<num> es un número de secuencia, ver más abajo "--nb_digits" <ext> es una extensión, ver más abajo "--extension"

por defecto es el nombre del archivo original (si está disponible) o "out" (si la entrada proviene de la entrada estándar)

-n <num>
número de dígitos en el número de secuencia para cada archivo

si se necesitan más dígitos que <num>, entonces se usan: si se usa "--nb_digits 2" y se generan 112 archivos, se nombrarán "<archivo>-01.xml" a "<archivo>-112.xml"

por defecto es 2

-e <ext>
extensión a usar para los archivos generados

por defecto es la extensión del archivo original o ".xml"

-i
usa elementos XInclude en lugar de Instrucciones de Procesamiento para marcar dónde se deben incluir los subarchivos
-v
salida detallada

tenga en cuenta que esta opción puede ralentizar considerablemente el procesamiento (en un orden de magnitud) cuando se generan muchos documentos pequeños

-V
muestra la versión y sale
-h
ayuda corta
-m
manual (requiere pod2text en la ruta)

EJEMPLOS

xml_split foo.xml             # dividir en el nivel 1
xml_split -l 2 foo.xml        # dividir en el nivel 2
xml_split -c section foo.xml  # se genera un archivo para cada elemento section
                              # las secciones anidadas se dividen correctamente

VER TAMBIÉN

XML::Twig, xml_merge

PENDIENTE

optimizar el código
¡cualquier idea es bienvenida! Ya he implementado la mayor parte de lo que pensaba que mejoraría el rendimiento.
proporcionar métodos distintos de PIs para mantener la información de fusión
XInclude es un buen candidato (soporte alfa añadido en 0.04).

usar entidades, lo que parecería la forma natural de hacerlo, no funciona, ya que hace imposible que tanto el documento principal como los subdocumentos estén bien formados si los subdocumentos incluyen sub-subdocumentos (no se pueden tener declaraciones de entidades en una entidad)
