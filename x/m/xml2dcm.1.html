NOMBRE

xml2dcm - Convierte documento XML a archivo o conjunto de datos DICOM

SINOPSIS

xml2dcm [opciones] xmlfile-in dcmfile-out

DESCRIPCIÓN

La utilidad xml2dcm convierte el contenido de un documento XML (Extensible Markup Language) a un archivo DICOM o conjunto de datos. Se espera que el documento XML valide contra la DTD (Document Type Definition) que se describe en el archivo dcm2xml.dtd. Se puede crear un archivo XML apropiado utilizando la herramienta dcm2xml (se recomienda la opción +Wb para incluir datos binarios).

PARÁMETROS

xmlfile-in   Nombre del archivo de entrada XML a convertir ("-" para stdin)
dcmfile-out  Nombre del archivo de salida DICOM ("-" para stdout)

OPCIONES

opciones generales

  -h   --help
         imprime este texto de ayuda y sale
       --version
         imprime información de la versión y sale
       --arguments
         imprime los argumentos de la línea de comandos expandidos
  -q   --quiet
         modo silencioso, no imprime advertencias ni errores
  -v   --verbose
         modo detallado, imprime detalles del procesamiento
  -d   --debug
         modo de depuración, imprime información de depuración
  -ll  --log-level  [l]evel: string constante
         (fatal, error, warn, info, debug, trace)
         usa el nivel l para el registrador
  -lc  --log-config  [f]ilename: string
         usa el archivo de configuración f para el registrador

opciones de entrada

formato de archivo de entrada:
  +f   --read-meta-info
         lee información meta si está presente (predeterminado)
  -f   --ignore-meta-info
         ignora la información meta del archivo

opciones de procesamiento

validación:
  +Vd  --validate-document
         valida el documento XML contra DTD
  +Vn  --check-namespace
         comprueba el espacio de nombres XML en la raíz del documento
identificadores únicos:
  +Ug  --generate-new-uids
         genera nuevos UIDs de Estudio/Serie/Instancia SOP
  -Uo  --dont-overwrite-uids
         no sobrescribe UIDs existentes (predeterminado)
  +Uo  --overwrite-uids
         sobrescribe UIDs existentes

opciones de salida

formato de archivo de salida:
  +F   --write-file
         escribe formato de archivo (predeterminado)
  -F   --write-dataset
         escribe conjunto de datos sin información meta del archivo
  +Fu  --update-meta-info
         actualiza información meta específica del archivo
sintaxis de transferencia de salida:
  +t=  --write-xfer-same
         escribe con la misma TS que la entrada (predeterminado)
  +te  --write-xfer-little
         escribe con TS explícita VR little endian
  +tb  --write-xfer-big
         escribe con TS explícita VR big endian
  +ti  --write-xfer-implicit
         escribe con TS implícita VR little endian
  +td  --write-xfer-deflated
         escribe con TS explícita VR little endian deflactada
manejo de errores:
  -E   --stop-on-error
         no escribe si el documento no es válido (predeterminado)
  +E   --ignore-errors
         intenta escribir incluso si el documento no es válido
representaciones de valores posteriores a 1993:
  +u   --enable-new-vr
         habilita soporte para nuevos VR (UN/UT) (predeterminado)
  -u   --disable-new-vr
         deshabilita soporte para nuevos VR, convierte a OB
codificación de longitud de grupo:
  +g=  --group-length-recalc
         recalcula longitudes de grupo si están presentes (predeterminado)
  +g   --group-length-create
         escribe siempre con elementos de longitud de grupo
  -g   --group-length-remove
         escribe siempre sin elementos de longitud de grupo
codificación de longitud en secuencias y elementos:
  +e   --length-explicit
         escribe con longitudes explícitas (predeterminado)
  -e   --length-undefined
         escribe con longitudes indefinidas
relleno de cola del conjunto de datos (no con --write-dataset):
  -p=  --padding-retain
         no cambia el relleno (predeterminado si no es --write-dataset)
  -p   --padding-off
         sin relleno (implícito si es --write-dataset)
  +p   --padding-create  [f]ile-pad [i]tem-pad: entero
         alinea el archivo en múltiplos de f bytes y los elementos en
         múltiplos de i bytes
nivel de compresión deflate (solo con --write-xfer-deflated):
  +cl  --compression-level  [l]evel: entero (predeterminado: 6)
         0=sin comprimir, 1=más rápido, 9=mejor compresión

NOTAS

La estructura básica de la entrada XML esperada se parece a lo siguiente:

<?xml version="1.0" encoding="ISO-8859-1"?>
<!DOCTYPE file-format SYSTEM "dcm2xml.dtd">
<file-format xmlns="http://dicom.offis.de/dcmtk">
  <meta-header xfer="1.2.840.10008.1.2.1" name="Little Endian Explicit">
    <element tag="0002,0000" vr="UL" vm="1" len="4"
             name="MetaElementGroupLength">
      166
    </element>
    ...
    <element tag="0002,0013" vr="SH" vm="1" len="16"
             name="ImplementationVersionName">
      OFFIS_DCMTK_353
    </element>
  </meta-header>
  <data-set xfer="1.2.840.10008.1.2" name="Little Endian Implicit">
    <element tag="0008,0005" vr="CS" vm="1" len="10"
             name="SpecificCharacterSet">
      ISO_IR 100
    </element>
    ...
    <sequence tag="0028,3010" vr="SQ" card="2" name="VOILUTSequence">
      <item card="3">
        <element tag="0028,3002" vr="xs" vm="3" len="6"
                 name="LUTDescriptor">
          256\0\8
        </element>
        ...
      </item>
      ...
    </sequence>
    ...
    <element tag="7fe0,0010" vr="OW" vm="1" len="262144"
             name="PixelData" loaded="no" binary="hidden">
    </element>
  </data-set>
</file-format>

Las etiquetas "file-format" y "meta-header" pueden estar ausentes para conjuntos de datos DICOM.

Codificación de caracteres

La codificación de caracteres DICOM se determina automáticamente a partir del elemento con la etiqueta "0008,0005" (Specific Character Set), si está presente. Los siguientes conjuntos de caracteres son compatibles actualmente (requiere que libxml incluya soporte para iconv, consulte la salida de --version):

ASCII         (ISO_IR 6)    (UTF-8)
UTF-8         "ISO_IR 192"  (UTF-8)
ISO Latin 1   "ISO_IR 100"  (ISO-8859-1)
ISO Latin 2   "ISO_IR 101"  (ISO-8859-2)
ISO Latin 3   "ISO_IR 109"  (ISO-8859-3)
ISO Latin 4   "ISO_IR 110"  (ISO-8859-4)
ISO Latin 5   "ISO_IR 148"  (ISO-8859-9)
ISO Latin 9   "ISO_IR 203"  (ISO-8859-15)
Cyrillic      "ISO_IR 144"  (ISO-8859-5)
Arabic        "ISO_IR 127"  (ISO-8859-6)
Greek         "ISO_IR 126"  (ISO-8859-7)
Hebrew        "ISO_IR 138"  (ISO-8859-8)

No se admiten múltiples conjuntos de caracteres (solo se utiliza el primer valor de "Specific Character Set" para la codificación de caracteres en caso de multiplicidad de valores).

Consulte la documentación de dcm2xml para obtener más detalles sobre la estructura XML.

Datos binarios

Los datos binarios (*) se pueden codificar como una secuencia de números hexadecimales separados por una barra invertida "\" o en formato Base64 (binary="base64"). Además, los datos binarios también se pueden leer desde un archivo (binary="file"). En este caso, el nombre del archivo debe especificarse como valor del elemento, por ejemplo:

@verbatim <element tag="7fe0,0010" vr="OW" ... binary="file">subdir/pixeldata.raw</element> \endverbatim

Tenga en cuenta que el contenido del archivo se leerá tal cual. Se espera que los datos OW estén ordenados en little endian y se intercambiarán si es necesario. No se realizarán comprobaciones para garantizar que la cantidad de datos sea razonable en relación con otros atributos como Rows o Columns.

(*) Tenga en cuenta que actualmente solo se admiten datos OB y OW, es decir, los valores de elemento con un VR de OD, OF, OL y OV no se consideran "datos binarios" y se tratan como cualquier otro VR.

@subsection xml2dcm_compression Compresión

Si libxml está compilado con soporte zlib, el archivo de entrada (\e xmlfile-in) también se puede comprimir con ZIP, lo que generalmente resulta en archivos mucho más pequeños. Consulte la salida de la opción \e --version para comprobar si el soporte zlib está disponible.

NOTES

Diferentes versiones de libxml pueden tener límites distintos para la longitud máxima de un valor de elemento XML. Por lo tanto, se debe evitar el uso de valores de elementos muy largos (por ejemplo, para datos de píxeles).

Tenga en cuenta que \b xml2dcm actualmente no admite completamente los archivos DICOMDIR. Específicamente, el valor de los diversos elementos de datos de desplazamiento no se actualiza automáticamente con esta herramienta.

@section xml2dcm_logging LOGGING

El nivel de salida de registro de las diversas herramientas de línea de comandos y bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo los errores y advertencias se escriben en el flujo de error estándar. Usando la opción \e --verbose, también se reportan mensajes informativos como detalles del procesamiento. La opción \e --debug se puede usar para obtener más detalles sobre la actividad interna, por ejemplo, con fines de depuración. Otros niveles de registro se pueden seleccionar usando la opción \e --log-level. En el modo \e --quiet, solo se reportan errores fatales. En tales eventos de error muy graves, la aplicación generalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo "oflog".

En caso de que la salida de registro deba escribirse en un archivo (opcionalmente con rotación de archivos de registro), en syslog (Unix) o en el registro de eventos (Windows), se puede usar la opción \e --log-config. Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes según el módulo o la aplicación donde se generan. Se proporciona un archivo de configuración de ejemplo en <em>\<etcdir\>/logger.cfg</em>.

@section xml2dcm_command_line COMANDO LINEA

Todas las herramientas de línea de comandos utilizan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos seguidos indican que se permiten múltiples valores (1-n), una combinación de ambos significa 0 a n valores.

Las opciones de línea de comandos se distinguen de los parámetros por un signo '+' o '-' respectivamente. Por lo general, el orden y la posición de las opciones de línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se utiliza la última aparición. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix comunes.

Además, se puede especificar uno o más archivos de comando usando un signo '@' como prefijo del nombre del archivo (por ejemplo, <em>\@command.txt</em>). Dicho argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (los espacios en blanco múltiples se tratan como un solo separador a menos que aparezcan entre dos comillas) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comando no puede contener otro archivo de comando. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comando largas y confusas (se proporciona un ejemplo en el archivo <em>\<datadir\>/dumppat.txt</em>).

@section xml2dcm_environment ENTORNO

La utilidad \b xml2dcm intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno \e DCMDICTPATH. Por defecto, es decir, si la variable de entorno \e DCMDICTPATH no está configurada, se cargará el archivo <em>\<datadir\>/dicom.dic</em>, a menos que el diccionario esté integrado en la aplicación (por defecto para Windows).

Se debe preferir el comportamiento por defecto y la variable de entorno \e DCMDICTPATH solo debe usarse cuando se requieren diccionarios de datos alternativos. La variable de entorno \e DCMDICTPATH tiene el mismo formato que la variable \e PATH del shell de Unix, en el sentido de que un signo de dos puntos (":") separa las entradas. En sistemas Windows, se utiliza un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH. Es un error si no se puede cargar ningún diccionario de datos.
