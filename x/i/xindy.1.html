NOMBRE

xindy - crea un índice ordenado y etiquetado a partir de un índice crudo

SINOPSIS

xindy [-V?h] [-qv] [-d magic] [-o outfile.ind] [-t log] \
      [-L lang] [-C codepage] [-M module] [-I input] \
      [--interactive] [--mem-file=xindy.mem] \
      [idx0 idx1 ...]

Opciones largas al estilo GNU para opciones cortas:

-V / --version
-? / -h / --help
-q / --quiet
-v / --verbose
-d / --debug          (múltiples veces)
-o / --out-file
-t / --log-file
-L / --language
-C / --codepage
-M / --module         (múltiples veces)
-I / --input-markup   (soportados: latex, xelatex, omega, xindy)

DESCRIPCIÓN

xindy es el comando independiente del formateador de xindy, el sistema de indexación flexible. Toma un índice crudo como entrada y produce un índice fusionado, ordenado y etiquetado. La fusión, el ordenamiento y el etiquetado se controlan mediante archivos de estilo de xindy.

Los archivos con el índice crudo se pasan como argumentos. Si no se pasan argumentos, el índice crudo se leerá de la entrada estándar.

xindy se describe completamente en su manual que encontrará en su sitio web, http://www.xindy.org/. Una buena descripción introductoria aparece en el capítulo de indexación del LaTeX Companion (2ª ed.)

Si desea producir un índice para documentos LaTeX, el comando texindy(1) probablemente sea de mayor interés para usted. Es un script de `wrapper` para xindy que activa por defecto muchas convenciones de LaTeX.

OPCIONES

"--version" / -V
muestra los números de versión de todos los componentes relevantes y sale.
"--help" / -h / -?
muestra el mensaje de uso con la explicación de las opciones.
"--quiet" / -q
No muestra mensajes de progreso. Solo muestra mensajes de error.
"--verbose" / -v
Muestra mensajes de progreso detallados.
"--debug" magic / -d magic
Muestra mensajes de depuración, esta opción puede especificarse varias veces. magic determina qué se muestra: 
magic          observación
------------------------------------------------------------
script         mensajes internos de progreso de los scripts del driver
keep_tmpfiles  no descartar archivos temporales
markup         traza de salida del marcado, como se explica en el manual de xindy
level=n        nivel de registro, n es 0 (predeterminado), 1, 2 o 3
"--out-file" outfile.ind / -o outfile.ind
Salida del índice al archivo outfile.ind. Si no se pasa esta opción, el nombre del archivo de salida es el nombre base del primer argumento y la extensión de archivo ind. Si el índice crudo se lee de la entrada estándar, esta opción es obligatoria.
"--log-file" log.ilg / -t log.ilg
Salida de mensajes de registro al archivo log.ilg. Estos mensajes de registro son independientes de los mensajes de progreso que puede controlar con "--debug" o "--verbose".
"--language" lang / -L lang
El índice se ordena según las reglas del idioma lang. Estas reglas están codificadas en un módulo de xindy creado por make-rules.

Si no se especifica ninguna codificación de entrada a través de "--codepage" o si no se exige por el marcado de entrada, se buscará un módulo de xindy para ese idioma con una codificación latin, cp, iso, ascii o utf8, en ese orden.

Los módulos de idioma se encuentran en el subdirectorio lang o en contrib/lang del directorio base de módulos.

"--codepage" enc / -C enc
La entrada cruda está en la codificación de entrada enc. Esta información se utiliza para seleccionar el módulo de ordenamiento de xindy correcto y la codificación de salida de los encabezados de grupo de letras.

Cuando se utiliza el marcado de entrada "xelatex" o "omega", siempre se utiliza "utf8" como página de código, por lo que esta opción se ignora.

Si la entrada cruda está en LICR, se debe usar texindy(1) en lugar de xindy(1). Activará un mapeo de la codificación de inputenc para el marcado de entrada "latex" a la página de código de entrada cruda elegida.

"--module" module / -M module
Carga el módulo de xindy module.xdy. Esta opción puede especificarse varias veces. Los módulos se buscan en la ruta de búsqueda de xindy que se puede cambiar con la variable de entorno "XINDY_SEARCHPATH".
"--input-markup" input / -I input
Especifica el marcado de entrada del índice crudo. Los valores soportados para input son "latex", "xelatex", "omega" y "xindy".

"latex" y "xelatex" es el marcado de entrada que emite por defecto el kernel de LaTeX, o el paquete de macros "index" de David Jones. Se soporta la notación ^^ para caracteres de un solo byte. No se realiza la reasignación de caracteres codificados en LICR; use texindy(1) para eso. Use el marcado de entrada "latex" si usa LaTeX estándar o pdfLaTeX y el marcado de entrada "xelatex" si usa XeLaTeX o LuaLaTeX.

"omega" el marcado de entrada es como el marcado de entrada "latex", pero con la notación ^^ de Omega como codificación para caracteres no ASCII.

"xindy" el marcado de entrada se especifica en el manual de xindy.

"--interactive"
Inicia xindy en modo interactivo. Estará en un bucle de lectura-evaluación de xindy donde se leen y evalúan expresiones de lenguaje xindy de forma interactiva.
"--mem-file" xindy.mem
Esta opción solo es utilizable para desarrolladores o en situaciones muy raras. El kernel compilado de xindy se almacena en un archivo llamado archivo de memoria, denominado canónicamente xindy.mem, y ubicado en el directorio de bibliotecas de xindy. Esta opción permite usar un kernel de xindy diferente.

ENTORNO

"XINDY_SEARCHPATH"
Una lista de directorios donde se buscan los módulos de xindy. No se realiza búsqueda en subárboles (como en TeX conforme a TDS).

Si esta variable de entorno no está establecida, se utiliza el valor predeterminado: ".:"dir_módulos":"dir_módulos"/base". dir_módulos se determina en tiempo de ejecución, en relación con la ubicación del comando xindy: puede ser ../modules, que es el caso para instalaciones opt. O puede ser ../lib/xindy/modules, que es el caso para instalaciones usr.

"XINDY_LIBDIR"
Directorio de la biblioteca donde se encuentra xindy.mem.

El directorio de módulos también puede ser un subdirectorio.

COMPATIBILIDAD CON MAKEINDEX

xindy no pretende ser completamente compatible con MakeIndex, ya que eso impediría algunas de sus mejoras. Dicho esto, nos esforzamos por ofrecer la mayor compatibilidad posible. Las incompatibilidades más importantes son:

  • Para entradas de índice en bruto en sintaxis LaTeX, "\index{aaa|bbb}" se interpreta de manera diferente. Para MakeIndex, "bbb" es un marcador que se muestra como una etiqueta LaTeX para el número de página. Para xindy, este es un atributo de ubicación, un identificador abstracto que posteriormente se asociará con el marcador que debe mostrarse para ese atributo.

    Para un uso directo, cuando "bbb" es "textbf" o similar, proporcionamos definiciones de atributos de ubicación que imitan el comportamiento de MakeIndex.

    Para un uso más complejo, cuando "bbb" no es un identificador, no existen definiciones de compatibilidad y es posible que tampoco se hayan creado con la versión actual de xindy. En particular, esto significa que, por defecto, el paquete LaTeX "hyperref" creará archivos de índice en bruto que no pueden ser procesados con xindy. Esto no es un error, es el desafortunado resultado de una incompatibilidad intencionada. Actualmente no es posible obtener tanto los enlaces de índice de hyperref como usar xindy.

    Se informa de una situación similar con la clase LaTeX "memoir".

    Los programadores que conozcan Common Lisp y Lex y deseen trabajar en una solución, por favor, pónganse en contacto con el autor.

  • Si tienes un rango de índice y un atributo de ubicación, por ejemplo, "\index{key\(attr}" inicia el rango, se necesita (1) especificar ese atributo también en la entrada de cierre del rango (es decir, como "\index{key\)attr}") y (2) declarar el atributo de índice en un archivo de estilo de xindy.

    MakeIndex mostrará el marcador "\attr{page1--page2}" para tal construcción. Esto no es posible de lograr en xindy, la salida será "\attrMarkup{page1}--\attrMarkup{page2}". (Esto se considera un error, pero no de alta prioridad.)

    La diferencia entre las etiquetas de número de página de MakeIndex y los atributos de ubicación de xindy ya se explicó en el punto anterior.

  • Las definiciones de compatibilidad de MakeIndex solo admiten la sintaxis de índice en bruto predeterminada y la definición de marcadores. No es posible configurar el análisis de índices en bruto ni utilizar un archivo de estilo de MakeIndex para describir los marcadores de salida.

PROBLEMAS CONOCIDOS

La opción -q también evita la salida de mensajes de error. Los mensajes de error deberían mostrarse en stderr y los mensajes de progreso en stdout.

Debería haber una forma de mostrar el índice final en stdout. Esto implicaría -q, por supuesto.

El análisis de índices en bruto de LaTeX debería ser configurable.

La página de código "utf8" debería ser compatible con todos los idiomas y utilizarse como página de código interna para la re-codificación de inputenc de LaTeX.
