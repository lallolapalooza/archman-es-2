XINIT(1) Manual de comandos generales XINIT(1)

NOMBRE

xinit - inicializador del sistema de ventanas X

SINOPSIS

xinit [ [ cliente ] opciones ... ] [ -- [ servidor ] [ display ] opciones ... ]

DESCRIPCIÓN

El programa xinit se utiliza para iniciar el servidor del sistema de ventanas X y un primer programa cliente en sistemas que no utilizan un gestor de pantalla como xdm(1) o en entornos que utilizan múltiples sistemas de ventanas. Cuando este primer cliente termina, xinit matará al servidor X y luego terminará.

Si no se proporciona ningún programa cliente específico en la línea de comandos, xinit buscará un archivo en el directorio de inicio del usuario llamado .xinitrc para ejecutarlo como un script de shell para iniciar los programas cliente. Si no existe dicho archivo, xinit utilizará lo siguiente como predeterminado:

xterm -geometry +1+1 -n login -display :0

Si no se proporciona ningún programa servidor específico en la línea de comandos, xinit buscará un archivo en el directorio de inicio del usuario llamado .xserverrc para ejecutarlo como un script de shell para iniciar el servidor. Si no existe dicho archivo, xinit utilizará lo siguiente como predeterminado:

X :0

Tenga en cuenta que esto asume que hay un programa llamado X en la ruta de búsqueda actual. Por lo tanto, el administrador del sitio debería crear un enlace al tipo de servidor apropiado en la máquina, o crear un script de shell que ejecute xinit con el servidor apropiado.

Nota: al utilizar un script .xserverrc, asegúrese de hacer ``exec'' al servidor X real. No hacerlo puede hacer que el servidor X tarde en iniciarse y terminar. Por ejemplo:

exec Xdisplaytype

Un punto importante es que los programas que son ejecutados por .xinitrc deben ser ejecutados en segundo plano si no terminan inmediatamente, para que no impidan que otros programas se inicien. Sin embargo, el último programa de larga duración iniciado (generalmente un gestor de ventanas o un emulador de terminal) debe dejarse en primer plano para que el script no termine (lo que indica que el usuario ha terminado y que xinit debe terminar).

Se puede especificar un cliente y/o servidor alternativo en la línea de comandos. El programa cliente deseado y sus argumentos deben darse como los primeros argumentos de la línea de comandos a xinit. Para especificar una línea de comandos de servidor particular, agregue un doble guion (--) a la línea de comandos de xinit (después de cualquier cliente y argumentos) seguido por el comando del servidor deseado.

Tanto el nombre del programa cliente como el nombre del programa servidor deben comenzar con una barra (/) o un punto (.). De lo contrario, se tratan como argumentos que se agregarán a sus respectivas líneas de inicio. Esto hace posible agregar argumentos (por ejemplo, colores de primer plano y fondo) sin tener que reescribir toda la línea de comandos.

Si no se proporciona un nombre de servidor explícito y el primer argumento después del doble guion (--) es dos puntos seguidos de un dígito, xinit usará ese número como el número de pantalla en lugar de cero. Todos los argumentos restantes se agregan a la línea de comandos del servidor.

EJEMPLOS

A continuación se presentan varios ejemplos de cómo se utilizan los argumentos de la línea de comandos en xinit.

xinit
Esto iniciará un servidor llamado X y ejecutará el .xinitrc del usuario, si existe, o de lo contrario iniciará un xterm.
xinit -- /usr/bin/Xvnc :1
Así es como se podría iniciar un tipo específico de servidor en una pantalla alternativa.
xinit -geometry =80x65+10+10 -fn 8x13 -j -fg white -bg navy
Esto iniciará un servidor llamado X, y agregará los argumentos dados al comando xterm predeterminado. Ignorará .xinitrc.
xinit -e widgets -- ./Xorg -l -c
Esto usará el comando ./Xorg -l -c para iniciar el servidor y agregará los argumentos -e widgets al comando xterm predeterminado.
xinit /usr/bin/ssh -X fasthost cpupig -- :1 -a 2 -t 5
Esto iniciará un servidor llamado X en la pantalla 1 con los argumentos -a 2 -t 5. Luego iniciará un shell remoto en la máquina fasthost en el que ejecutará el comando cpupig, indicándole que muestre de vuelta en la estación de trabajo local.

A continuación se muestra un ejemplo de .xinitrc que inicia un reloj, varios terminales y deja el gestor de ventanas en ejecución como la ''última'' aplicación. Suponiendo que el gestor de ventanas se ha configurado correctamente, el usuario elige el elemento del menú ``Exit'' para apagar X.


xrdb -load $HOME/.Xresources
xsetroot -solid gray &
xclock -g 50x50-0+0 -bw 0 &
xload -g 50x50-50+0 -bw 0 &
xterm -g 80x24+0+0 &
xterm -g 80x24+0-0 &
twm

Los sitios que deseen crear un entorno de inicio común simplemente podrían crear un .xinitrc predeterminado que haga referencia a un archivo de inicio a nivel de sitio:


#!/bin/sh
. /etc/X11/xinit/site.xinitrc

Otro enfoque es escribir un script que inicie xinit con un script de shell específico. Estos scripts suelen llamarse x11, xstart o startx y son una forma conveniente de proporcionar una interfaz simple para usuarios novatos:


#!/bin/sh
xinit /etc/X11/xinit/site.xinitrc -- /usr/bin/X -br

VARIABLES DE ENTORNO

DISPLAY
Esta variable se establece en el nombre de la pantalla a la que deben conectarse los clientes.
XINITRC
Esta variable especifica un archivo de inicio que contiene comandos de shell para iniciar las ventanas iniciales. Por defecto, se utilizará .xinitrc en el directorio de inicio.

ARCHIVOS

.xinitrc
script de cliente predeterminado
xterm
cliente a ejecutar si .xinitrc no existe
.xserverrc
script de servidor predeterminado
X
servidor a ejecutar si .xserverrc no existe
