xinput(1) General Commands Manual xinput(1)

NOMBRE

xinput - utilidad para configurar y probar dispositivos de entrada X

SINOPSIS

xinput [COMANDO] [OPCIONES] [DISPOSITIVO]

DESCRIPCIÓN

xinput es una utilidad para listar los dispositivos de entrada disponibles, consultar información sobre un dispositivo y cambiar la configuración de los dispositivos de entrada.

COMANDOS

--version
Prueba si la extensión de entrada X está disponible y devuelve el número de versión del programa y la versión soportada por el servidor. Esta opción no requiere un nombre de dispositivo.
list [--short || --long || --name-only || --id-only] [dispositivo]
Si no se proporciona ningún argumento, lista todos los dispositivos de entrada. Si se proporciona un argumento, muestra todas las características del dispositivo. Si se proporciona --long, la salida incluye información detallada sobre las capacidades de cada dispositivo. De lo contrario, o si se proporciona --short, solo se listan los nombres de los dispositivos y alguna información mínima. Si se proporciona --name-only, la salida se limita a los nombres de los dispositivos. Se lista un nombre de dispositivo por línea. Ten en cuenta que el orden en que se listan los dispositivos no está definido. Si se proporciona --id-only, la salida se limita a los IDs de los dispositivos. Se lista un ID de dispositivo por línea. Ten en cuenta que el orden en que se listan los dispositivos no está definido.
get-feedbacks dispositivo
Muestra las retroalimentaciones del dispositivo.
set-pointer dispositivo
Cambia el dispositivo a puntero principal. Esta opción no hace nada en los servidores X 1.5 y posteriores.
set-mode dispositivo ABSOLUTE|RELATIVE
Cambia el modo del dispositivo.
set-ptr-feedback dispositivo umbral num den
Cambia los parámetros de aceleración (o retroalimentación) del puntero del dispositivo. La página del manual de xset(1) tiene más detalles. Para el Servidor X.Org 1.7 y superior, hay propiedades de dispositivo adicionales relacionadas con la aceleración del puntero. Estas no reemplazan, sino que complementan la configuración de retroalimentación del puntero.
set-integer-feedback dispositivo índice valor
Cambia el valor de una retroalimentación entera del dispositivo.
set-button-map dispositivo map_botón_1 [map_botón_2 [...]]
Cambia el mapeo de botones del dispositivo. Los botones se especifican en orden físico (comenzando con el botón 1) y se mapean al botón lógico proporcionado. 0 deshabilita un botón. El mapeo de botones predeterminado para un dispositivo es 1 2 3 4 5 6, etc.
query-state dispositivo
Consulta el estado del dispositivo.
list-props dispositivo [dispositivo [...]]
Lista las propiedades que se pueden establecer para los dispositivos dados.
set-int-prop dispositivo propiedad formato valor
Establece una propiedad entera para el dispositivo. Los valores apropiados para formato son 8, 16 o 32, dependiendo de la propiedad. Obsoleto, usa set-prop en su lugar.
set-float-prop dispositivo propiedad valor
Establece una propiedad de punto flotante para el dispositivo. Obsoleto, usa set-prop en su lugar.
set-prop [--type=átomo|flotante|entero] [--formato=8|16|32] dispositivo propiedad valor [...]
Establece la propiedad al(los) valor(es) dados. Si no se especifica, el formato y el tipo de la propiedad se dejan como están. Los argumentos se interpretan según el tipo de propiedad. Ver la Sección CAMBIO DE PROPIEDADES.
watch-props dispositivo
Imprime en la salida estándar cuando ocurren cambios en las propiedades.
delete-prop dispositivo propiedad
Elimina la propiedad del dispositivo.
test [-proximity] dispositivo
Registra todos los eventos extendidos del dispositivo y entra en un bucle infinito mostrando los eventos recibidos. Si se proporciona -proximity, se registran ProximityIn y ProximityOut.
test-xi2 [--root] [dispositivo]
Se registra para varios eventos XI2 y los muestra. Si se proporciona un dispositivo, solo se muestran los eventos en este dispositivo. Si se proporciona --root, los eventos se seleccionan solo en la ventana raíz. De lo contrario, se crea una nueva ventana de cliente (similar a xev).
create-master prefijo [sendCore] [enable]
Crea un nuevo par de dispositivos maestros en un servidor habilitado para XI2 con el prefijo dado. El servidor creará un puntero maestro llamado "prefijo pointer" y un teclado maestro llamado "prefijo keyboard". Si sendCore es 1, este par de dispositivos maestros se configura para enviar eventos principales (por defecto). Si enable es 1, este par de dispositivos maestros se habilitará inmediatamente (por defecto).
remove-master maestro [Floating|AttachToMaster] [returnPointer] [returnKeyboard]
Elimina el maestro y su dispositivo maestro emparejado. Los dispositivos esclavos adjuntos se configuran como flotantes si se especifica Floating o se omite el argumento. Si el segundo argumento es AttachToMaster, returnPointer especifica el puntero maestro al que se adjuntarán todos los punteros esclavos y returnKeyboard especifica el teclado maestro al que se adjuntarán todos los teclados esclavos.
reattach esclavo maestro
Reasigna el esclavo al maestro.
float esclavo
Elimina el esclavo de su dispositivo maestro actual.
set-cp ventana maestro
Establece el ClientPointer para el cliente propietario de ventana a maestro. maestro debe especificar un puntero maestro.
map-to-output dispositivo crtc
Restringe los movimientos del dispositivo absoluto al crtc de RandR. El nombre de salida debe coincidir con una salida conectada actualmente (ver xrandr(1)). Si se detecta el controlador binario de NVIDIA o no está disponible RandR 1.2 o posterior, se puede especificar una salida de Xinerama como "HEAD-N", donde N es el número de pantalla de Xinerama. Esta opción no tiene efecto en dispositivos relativos. Si crtc se establece en "all", se aplica el comportamiento predeterminado.
enable dispositivo
Habilita el dispositivo. Esta llamada es equivalente a xinput --set-prop dispositivo "Device Enabled" 1
disable dispositivo
Deshabilita el dispositivo. Esta llamada es equivalente a xinput --set-prop dispositivo "Device Enabled" 0

dispositivo puede ser el nombre del dispositivo como una cadena o el XID del dispositivo.

esclavo puede ser el nombre del dispositivo como una cadena o el XID de un dispositivo esclavo.

maestro puede ser el nombre del dispositivo como una cadena o el XID de un dispositivo maestro.

propiedad puede ser la propiedad como una cadena o el valor Atom.

CAMBIO DE PROPIEDADES

Cuando xinput debe modificar el valor de una propiedad existente del controlador, es suficiente proporcionar el nombre del dispositivo y el nombre de la propiedad como cadena, seguido de el(los) nuevo(s) valor(es) de la propiedad. Por ejemplo:

xinput set-prop "mi dispositivo" "mi prop" 1 2 3

xinput(1) — Arch manual pages

NAME

xinput — utility to configure and test X input devices

SYNOPSIS

xinput [-v] [-q] [-f] [-t] [--] [device]

xinput list [options]

xinput list-props device

xinput list-button-actions device

xinput set-int-prop device property value...

xinput set-float-prop device property value...

xinput set-button-map device button1 button2 ...

xinput set-keymap device keycode keysym ...

xinput enable device

xinput disable device

xinput set-prop device property value...

xinput watch-props device

xinput test device

xinput create-prop device property type [initial_value ...]

xinput change-prop device property value...

xinput remove-prop device property

DESCRIPTION

xinput

is a utility to help configure and test X Input devices. It is used to select input devices, and to set and unset various properties of these devices.

The first form of the command is the default if no other options are given. It lists the currently configured devices. If a device is specified, only that device is shown.

The available commands are described in the following sections.

COMMANDS

list: Lists all available input devices and their attributes. If options are given, only devices matching the options are listed. list-props requires a device name or id. It lists the properties of the specified device and whether they are enabled.

list-button-actions: Lists the actions associated with the buttons of the specified device.

set-int-prop, set-float-prop, set-prop: Sets the specified property on the device. The property type is determined by the command. set-prop tries to guess the type.

set-button-map: Sets the button map for the specified device.

set-keymap: Sets the keymap for the specified device.

enable, disable: Enables or disables the specified device.

watch-props: Lists devices and watches for changes to their properties.

test: Tests the specified device by printing all events that are generated by it.

create-prop: Creates a new property on the specified device.

change-prop: Changes an existing property on the specified device.

remove-prop: Removes a property from the specified device.

CHANGING PROPERTIES

The exact list of properties depends on the device and the driver. Some common properties include:

Device Accel Profile: Controls the acceleration profile for pointing devices.

Device Accel Constant Deceleration: Controls the deceleration for pointing devices.

Device Accel Adaptive Deceleration: Controls the adaptive deceleration for pointing devices.

Device Accel Velocity Scaling: Controls the velocity scaling for pointing devices.

Device Product ID: The product ID of the device.

Device Vendor ID: The vendor ID of the device.

Coordinate Transformation Matrix: A transformation matrix that is applied to the device coordinates.

libinput Scrolling Pixel Distance: The distance in pixels that triggers a scroll event.

libinput Scrolling Button Lock: Whether to lock the scroll button.

libinput Natural Scrolling Enabled: Whether to enable natural scrolling.

libinput Left Handed Enabled: Whether to enable left-handed mode.

libinput Disable While Typing Enabled: Whether to disable the touchpad while typing.

libinput Send Events Modes Available: The available send events modes.

libinput Send Events Mode Enabled, particularly { 0: "disabled", 1: "enabled", 2: "disabled-on-external-mouse" }: Controls whether events are sent by the device.

libinput Scroll Methods Available: The available scrolling methods.

libinput Scroll Method Enabled, particularly { 0: "none", 1: "two-finger", 2: "edge-scrolling", 3: "no-button" }: Controls the enabled scrolling method.

libinput Click Methods Available: The available click methods.

libinput Click Method Enabled, particularly { 0: "none", 1: "click-drag", 2: "click-tap" }: Controls the enabled click method.

libinput Drag Enabled: Whether to enable drag and drop.

libinput Drag Lock Enabled: Whether to enable drag lock.

libinput Tapping Enabled: Whether to enable tapping.

libinput Tap Button Mapping Enabled: Controls the button mapping for tapping.

libinput Buttons is Key: Whether buttons are mapped to keys.

libinput Middle Emulation Enabled: Whether middle button emulation is enabled.

Device Enabled: Whether the device is enabled.

XWAYLAND

When running under Xwayland, which acts as a compatibility layer for X clients on a Wayland compositor, the devices listed by xinput are not physical devices. They are X Input Extension devices created by Xwayland that map to the Wayland protocol devices. These Xwayland devices (e.g., "xwayland-pointer", "xwayland-keyboard") are only visible to other X clients connected to the same Xwayland process. Changing properties on these Xwayland devices only affects those X clients and may not have the desired effect on Wayland-native applications or even on Xwayland itself.

Using xinput on Xwayland devices is generally not recommended and may indicate a misunderstanding of how input is handled in a Wayland environment. For Wayland-native device configuration, use the methods provided by your Wayland compositor or associated tools.
