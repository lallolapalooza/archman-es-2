NOMBRE

xpdfrc - archivo de configuración para herramientas Xpdf (versión 4.05)

DESCRIPCIÓN

Todas las herramientas Xpdf leen un único archivo de configuración.

En Linux/Unix/MacOS: si tienes un archivo .xpdfrc en tu directorio de inicio, será leído. De lo contrario, se leerá un archivo de configuración a nivel de sistema desde /etc/xpdfrc, si existe. (Esta es su ubicación predeterminada; dependiendo de las opciones de compilación, puede colocarse en otro lugar).

En Windows: el archivo debe llamarse xpdfrc (sin punto inicial, sin extensión) y debe colocarse en el mismo directorio que el ejecutable (pdftotext.exe, xpdf.exe, etc.).

El archivo xpdfrc consta de una serie de opciones de configuración, una por línea. Las líneas en blanco y las líneas que comienzan con '#' (comentarios) se ignoran.

Los argumentos pueden ir entre comillas simples o dobles, por ejemplo, para nombres de archivo que contienen espacios ("aaa bbb", 'aaa bbb'). Estas comillas no proporcionan ningún escape, por lo que no hay forma de incluir una comilla doble en un argumento entre comillas dobles o una comilla simple en un argumento entre comillas simples.

Los argumentos también pueden ir entre comillas de arroba: @"aaa bbb". Las cadenas entre comillas de arroba permiten el uso de la variable DATADIR, que se establece en el subdirectorio 'data' del directorio de instalación de xpdf. El signo de porcentaje (%) es un carácter de escape: un signo de porcentaje seguido de cualquier otro carácter se reemplaza con ese carácter.

@"abc %"def%" ghi" --> abc "def" ghi    
@"${DATADIR}/foo"  --> ...directorio-instalacion.../data/foo
@"%${DATADIR}/foo" --> ${DATADIR}/foo

Las siguientes secciones enumeran todas las opciones de configuración, clasificadas en grupos funcionales. Hay una sección de ejemplos al final.

INCLUIR ARCHIVOS

include archivo-config
Incluye el archivo de configuración especificado. El efecto de esto es equivalente a insertar el contenido de archivo-config directamente en el archivo de configuración padre en lugar del comando include. Los archivos de configuración pueden anidarse a cualquier profundidad.

CONFIGURACIÓN GENERAL DE FUENTES

fontFile nombre-fuente-PDF archivo-fuente
Mapea una fuente PDF, nombre-fuente-PDF, a un archivo de fuente para visualización o salida PostScript. El archivo de fuente, archivo-fuente, puede ser de cualquier tipo permitido en un archivo PDF. Este comando se puede usar para fuentes de 8 o 16 bits (CID).
fontDir dir
Especifica un directorio de búsqueda para archivos de fuentes. Puede haber múltiples comandos fontDir; todos los directorios especificados se buscarán en orden. Los archivos de fuente pueden ser Type 1 (.pfa o .pfb) o TrueType (.ttf o .ttc); se ignorarán otros archivos en el directorio. El nombre del archivo de fuente (sin incluir la extensión) debe coincidir exactamente con el nombre de la fuente PDF. Esta búsqueda se realiza si el nombre de la fuente no coincide con ninguna de las fuentes declaradas con el comando fontFile. No hay directorios fontDir predeterminados.
fontFileCC registro-orden archivo-fuente
Mapea la colección de caracteres de registro-orden a una fuente para visualización o salida PostScript. Este mapeo se utiliza si el nombre de la fuente no coincide con ninguna de las fuentes declaradas con los comandos fontFile, fontDir, psResidentFont16 o psResidentFontCC.

CONFIGURACIÓN DE FUENTES POSTSCRIPT

psFontPassthrough sí | no
Si se establece en "sí", pasa los nombres de fuentes de 8 bits a la salida PostScript sin sustitución. Se espera que las fuentes que no están incrustadas en el archivo PDF estén disponibles en la impresora. Esto tiene un valor predeterminado de "no".
psResidentFont nombre-fuente-PDF nombre-fuente-PS
Cuando la fuente de 8 bits nombre-fuente-PDF se utiliza (sin incrustar) en un archivo PDF, se traducirá a la fuente PostScript nombre-fuente-PS, que se supone que reside en la impresora. Típicamente, nombre-fuente-PDF y nombre-fuente-PS son lo mismo. Por defecto, solo se supone que las fuentes Base-14 residen en la impresora.
psResidentFont16 nombre-fuente-PDF modo-escritura nombre-fuente-PS codificación
Cuando la fuente de 16 bits (CID) nombre-fuente-PDF con modo de escritura modo-escritura se utiliza (sin incrustar) en un archivo PDF, se traducirá a la fuente PostScript nombre-fuente-PS, que se supone que reside en la impresora. El modo de escritura debe ser 'H' para horizontal o 'V' para vertical. Se supone que la fuente residente utiliza la codificación especificada (que debe haber sido definida con el comando unicodeMap).
psResidentFontCC registro-orden modo-escritura nombre-fuente-PS codificación
Cuando se utiliza una fuente de 16 bits (CID) que usa la colección de caracteres registro-orden y el modo de escritura modo-escritura (sin incrustar) en un archivo PDF, se sustituye por la fuente PostScript nombre-fuente-PS. Se supone que la fuente sustituida reside en la impresora. El modo de escritura debe ser 'H' para horizontal o 'V' para vertical. Se supone que la fuente residente utiliza la codificación especificada (que debe haber sido definida con el comando unicodeMap).
psEmbedType1Fonts sí | no
Si se establece en "no", evita la incrustación de fuentes Type 1 en PostScript generado. Esto tiene un valor predeterminado de "sí".
psEmbedTrueTypeFonts sí | no
Si se establece en "no", evita la incrustación de fuentes TrueType en PostScript generado. Esto tiene un valor predeterminado de "sí".
psEmbedCIDTrueTypeFonts sí | no
Si se establece en "no", evita la incrustación de fuentes CID TrueType en PostScript generado. Para PostScript Nivel 3, esto genera una fuente CID, para niveles inferiores genera una fuente compuesta no CID. Esto tiene un valor predeterminado de "sí".
psEmbedCIDPostScriptFonts sí | no
Si se establece en "no", evita la incrustación de fuentes CID PostScript en PostScript generado. Para PostScript Nivel 3, esto genera una fuente CID, para niveles inferiores genera una fuente compuesta no CID. Esto tiene un valor predeterminado de "sí".

CONTROL POSTSCRIPT

psPaperSize ancho(pts) alto(pts)
Establece el tamaño del papel para la salida PostScript. Los parámetros ancho y alto dan el tamaño del papel en puntos PostScript (1 punto = 1/72 de pulgada).
psPaperSize carta | legal | A4 | A3 | coincidir
Establece el tamaño del papel para la salida PostScript a un tamaño estándar. El tamaño de papel predeterminado se establece cuando se compilan xpdf y pdftops, típicamente a "letter" (carta) o "A4". Esto también se puede establecer a "match" (coincidir), lo que establecerá el tamaño del papel para que coincida con el tamaño especificado en el archivo PDF.
psImageableArea xiz piy xud yud
Establece el área imprimible para la salida PostScript. Los cuatro enteros son las coordenadas de las esquinas inferior izquierda y superior derecha de la región imprimible, especificadas en puntos (con el origen siendo la esquina inferior izquierda del papel). Esto tiene un valor predeterminado de todo el tamaño del papel; la opción psPaperSize restablecerá las coordenadas del área imprimible.
psCrop sí | no
Si se establece en "sí", la salida PostScript se recorta según el CropBox especificado en el archivo PDF; de lo contrario, no se realiza ningún recorte. Esto tiene un valor predeterminado de "sí".

POSTSCRIPT OPTIONS

psPageSize yes | no
If set to "yes", the page size from the PDF file will be used for the PostScript page size. Otherwise, the PostScript imageable area is used as the page size. By default, this is "no", and the MediaBox is used as the page size.
psExpandSmaller yes | no
If set to "yes", PDF pages smaller than the PostScript imageable area are expanded to fill the imageable area. Otherwise, no scaling is done on smaller pages. This defaults to "no".
psShrinkLarger yes | no
If set to yes, PDF pages larger than the PostScript imageable area are shrunk to fit the imageable area. Otherwise, no scaling is done on larger pages. This defaults to "yes".
psCenter yes | no
If set to yes, PDF pages smaller than the PostScript imageable area (after any scaling) are centered in the imageable area. Otherwise, they are aligned at the lower-left corner of the imageable area. This defaults to "yes".
psDuplex yes | no
If set to "yes", the generated PostScript will set the "Duplex" pagedevice entry. This tells duplex-capable printers to enable duplexing. This defaults to "no".
psLevel level1 | level1sep | level2 | level2gray | level2sep | level3 | level3gray | level3Sep
Sets the PostScript level to generate. This defaults to "level2".
psPreload yes | no
If set to "yes", PDF forms are converted to PS procedures, and image data is preloaded. This uses more memory in the PostScript interpreter, but generates significantly smaller PS files in situations where, e.g., the same image is drawn on every page of a long document. This defaults to "no".
psOPI yes | no
If set to "yes", generates PostScript OPI comments for all images and forms which have OPI information. This option is only available if the Xpdf tools were compiled with OPI support. This defaults to "no".
psASCIIHex yes | no
If set to "yes", the ASCIIHexEncode filter will be used instead of ASCII85Encode for binary data. This defaults to "no".
psLZW yes | no
If set to "yes", the LZWEncode filter will be used for lossless compression in PostScript output; if set to "no", the RunLengthEncode filter will be used instead. LZW generates better compression (smaller PS files), but may not be supported by some printers. This defaults to "yes".
psUncompressPreloadedImages yes | no
If set to "yes", all preloaded images in PS files will uncompressed. If set to "no", the original compressed images will be used when possible. The "yes" setting is useful to work around certain buggy PostScript interpreters. This defaults to "no".
psMinLineWidth float
Set the minimum line width, in points, for PostScript output. The default value is 0 (no minimum).
psRasterResolution float
Set the resolution (in dpi) for rasterized pages in PostScript output. (Pdftops will rasterize pages which use transparency.) This defaults to 300.
psRasterMono yes | no
If set to "yes", rasterized pages in PS files will be monochrome (8-bit gray) instead of color. This defaults to "no".
psRasterSliceSize pixels
When rasterizing pages, pdftops splits the page into horizontal "slices", to limit memory usage. This option sets the maximum slice size, in pixels. This defaults to 20000000 (20 million).
psAlwaysRasterize yes | no
If set to "yes", all PostScript output will be rasterized. This defaults to "no".
psNeverRasterize yes | no
Pdftops rasterizes an pages that use transparency (because PostScript doesn't support transparency). If psNeverRasterize is set to "yes", rasterization is disabled: pages will never be rasterized, even if they contain transparency. This will likely result in incorrect output for PDF files that use transparency, and a warning message to that effect will be printed. This defaults to "no".
fontDir dir
See the description above, in the DISPLAY FONTS section.

CONTROL DE TEXTO Y MAPPING DE CARACTERES

textEncoding nombre-codificacion
Establece la codificación a usar para la salida de texto. (Esto puede ser anulado con el modificador "-enc" en la línea de comandos.) El nombre-codificacion debe definirse con el comando unicodeMap (ver arriba). Por defecto es "Latin1".
textEOL unix | dos | mac
Establece la convención de fin de línea a usar para la salida de texto. Las opciones son: 
    unix = LF
    dos  = CR+LF
    mac  = CR
(Esto puede ser anulado con el modificador "-eol" en la línea de comandos.) El valor por defecto se basa en el sistema operativo en el que se compilaron xpdf y pdftotext.
textPageBreaks yes | no
Si se establece en "yes", la extracción de texto insertará saltos de página (caracteres de avance de formulario) entre páginas. Por defecto es "yes".
textKeepTinyChars yes | no
Si se establece en "yes", la extracción de texto conservará todos los caracteres. Si se establece en "no", la extracción de texto descartará caracteres diminutos (menores de 3 puntos) después de los primeros 50000 por página, evitando tiempos de ejecución extremadamente lentos para archivos PDF que usan fuentes especiales para sombreado o tramado. Por defecto es "yes".
nameToUnicode archivo-mapa
Especifica un archivo con el mapeo de nombres de caracteres a Unicode. Esto se utiliza para manejar fuentes PDF que tienen codificaciones válidas pero sin entrada ToUnicode. Cada línea de un archivo nameToUnicode tiene este aspecto:

cadena-hexadecimal nombre

La cadena-hexadecimal es el índice del carácter Unicode (UCS-2), y nombre es el nombre del carácter correspondiente. Se pueden usar múltiples archivos nameToUnicode; si un nombre de carácter se proporciona más de una vez, se utiliza el código del último archivo especificado. Hay una tabla nameToUnicode predeterminada incorporada con todos los nombres de caracteres estándar de Adobe.

cidToUnicode registro-ordenación archivo-mapa
Especifica el archivo con el mapeo de colección de caracteres a Unicode. Cada línea de un archivo cidToUnicode representa un carácter:

cadena-hexadecimal

La cadena-hexadecimal es el índice Unicode (UCS-2) para ese carácter. La primera línea mapea CID 0, la segunda línea CID 1, etc. El tamaño del archivo está determinado por el tamaño de la colección de caracteres. Solo se permite un archivo por colección de caracteres; se utiliza el último archivo especificado. No hay mapeos cidToUnicode incorporados.

unicodeToUnicode subcadena-nombre-fuente archivo-mapa
Esto se utiliza para solucionar fuentes PDF que tienen información Unicode incorrecta. Especifica un archivo que mapea los índices Unicode (incorrectos) dados a los índices correctos. El mapeo se utilizará para cualquier fuente cuyo nombre contenga subcadena-nombre-fuente. Cada línea de un archivo unicodeToUnicode representa un carácter Unicode:

in-hex out-hex1 out-hex2 ...

El campo in-hex es un índice Unicode de entrada (incorrecto), y los campos restantes son uno o más índices Unicode de salida (correctos). Cada ocurrencia de in-hex se convertirá a la secuencia de salida especificada.

unicodeRemapping archivo-remapeo
Remapea caracteres Unicode al hacer la extracción de texto. Esto especifica un archivo que mapea un índice Unicode particular a cero o más índices Unicode de reemplazo. Cada línea del archivo de remapeo representa un carácter Unicode:

in-hex out-hex1 out-hex2 ...

Cualquier carácter Unicode no listado permanecerá sin cambios. Esta función se utiliza típicamente para remapear elementos como espacios de no separación, guiones blandos, ligaduras, etc.

unicodeMap nombre-codificacion archivo-mapa
Especifica el archivo con el mapeo de Unicode a nombre-codificacion. Estas codificaciones se utilizan para la salida de texto (ver más abajo). Cada línea de un archivo unicodeMap representa un rango de uno o más caracteres Unicode que se mapea linealmente a un rango en la codificación de salida: 
     in-start-hex in-end-hex out-start-hex
Las entradas para caracteres individuales se pueden abreviar a: 
     in-hex out-hex
Los campos in-start-hex e in-end-hex (o el campo único in-hex) especifican el rango Unicode. El campo out-start-hex (o el campo out-hex) especifica el inicio del rango de codificación de salida. La longitud de la cadena out-start-hex (o out-hex) determina la longitud de los caracteres de salida (por ejemplo, UTF-8 usa diferentes números de bytes para representar caracteres en diferentes rangos). Las entradas deben proporcionarse en orden Unicode creciente. Solo se permite un archivo por codificación; se utiliza el último archivo especificado. Las codificaciones Latin1, ASCII7, Symbol, ZapfDingbats, UTF-8 y UCS-2 están predefinidas.
cMapDir registro-ordenación directorio
Especifica un directorio de búsqueda, directorio, para CMaps para el Xpdf tools.
ordering-del-registro colección de caracteres. Puede haber varios directorios para una colección en particular. No hay directorios CMap predeterminados.
toUnicodeDir dir
Especifica un directorio de búsqueda, dir, para CMaps ToUnicode. Puede haber varios directorios ToUnicode. No hay directorios ToUnicode predeterminados.
mapNumericCharNames sí | no
Si se establece en "sí", las herramientas Xpdf intentarán mapear varios nombres de caracteres numéricos a veces utilizados en subconjuntos de fuentes. En algunos casos, esto conduce a texto utilizable y, en otros casos, a galimatías; no hay forma de que Xpdf lo sepa. Esto está configurado por defecto en "sí".
mapUnknownCharNames sí | no
Si se establece en "sí", y mapNumericCharNames se establece en "no", las herramientas Xpdf aplicarán un mapeo simple de transmisión directa (índice Unicode = código de carácter) para todos los nombres de glifos no reconocidos. (Para fuentes CID, establecer mapNumericCharNames en "no" es innecesario). En algunos casos, esto conduce a texto utilizable y, en otros casos, a galimatías; no hay forma de que Xpdf lo sepa. Esto está configurado por defecto en "no".
mapExtTrueTypeFontsViaUnicode sí | no
Al rasterizar texto usando una fuente TrueType externa, hay dos opciones para manejar códigos de caracteres. Si mapExtTrueTypeFontsViaUnicode se establece en "sí", Xpdf utilizará la información de codificación/ToUnicode de la fuente para mapear códigos de caracteres a Unicode y luego utilizará el cmap Unicode de la fuente para mapear Unicode a GID. Si mapExtTrueTypeFontsViaUnicode se establece en "no", Xpdf asumirá que los códigos de caracteres son GID (es decir, utiliza un mapeo de identidad). Esto está configurado por defecto en "sí".
useTrueTypeUnicodeMapping sí | no
Si se establece en "sí", las herramientas Xpdf utilizarán la información de codificación Unicode en las fuentes TrueType (solo de 16 bits), si está disponible, para anular los mapas ToUnicode de PDF. De lo contrario, los mapas ToUnicode siempre se utilizan cuando están presentes. Esto está configurado por defecto en "no".
ignoreWrongSizeToUnicode sí | no
Si se establece en "sí", Xpdf ignorará cualquier CMap ToUnicode que no coincida con el tipo de fuente (8 bits vs 16 bits). La especificación PDF requiere que los CMaps ToUnicode coincidan, y Adobe parece ignorar los CMaps que no coinciden. Esto está configurado por defecto en "no" (por compatibilidad con versiones anteriores).
dropFont nombre-fuente
Descarta todo el texto dibujado en la fuente especificada. Para descartar texto dibujado en fuentes sin nombre, usa: 
    dropFont ""
Puede haber cualquier número de comandos dropFont.
separateRotatedText sí | no
Si se establece en "no", pdftotext intentará colocar el texto rotado en la ubicación "correcta" en la salida. Si se establece en "sí", cuando se utiliza el modo de orden de lectura, pdftotext adjuntará el texto rotado al final, después del texto no rotado. Esto está configurado por defecto en "no".

CONFIGURACIÓN DEL RASTERIZADOR

enableFreeType sí | no
Habilita o deshabilita el uso de FreeType (un rasterizador de fuentes TrueType / Type 1). Esto solo es relevante si las herramientas Xpdf se compilaron con soporte FreeType. ("enableFreeType" reemplaza la antigua opción "freetypeControl"). Esta opción está configurada por defecto en "sí".
disableFreeTypeHinting sí | no
Si esto se establece en "sí", el ajuste de indicaciones de FreeType se desactivará. Esta opción está configurada por defecto en "no".
antialias sí | no
Habilita o deshabilita el suavizado de fuentes en el rasterizador PDF. Esta opción afecta a todos los rasterizadores de fuentes. ("antialias" reemplaza el control de suavizado proporcionado por las antiguas opciones "t1libControl" y "freetypeControl"). Esto está configurado por defecto en "sí".
vectorAntialias sí | no
Habilita o deshabilita el suavizado de gráficos vectoriales en el rasterizador PDF. Esto está configurado por defecto en "sí".
imageMaskAntialias sí | no
Habilita o deshabilita el suavizado de máscaras de imagen (al reducir o aumentar la escala) en el rasterizador PDF. Esto está configurado por defecto en "sí".
antialiasPrinting sí | no
Si esto es "sí", los mapas de bits enviados a la impresora se suavizarán (según la configuración de "antialias" y "vectorAntialias"). Si esto es "no", los mapas de bits impresos no se suavizarán. Esto está configurado por defecto en "no".
strokeAdjust sí | no | cad
Establece el modo de ajuste de trazo. Si se establece en "no", no se realizará ningún ajuste de trazo. Si se establece en "sí", se realizará un ajuste de trazo normal: las líneas horizontales y verticales se moverán hasta medio píxel para que se vean más limpias cuando el suavizado vectorial esté habilitado. Si se establece en "cad", se utilizará un algoritmo de ajuste de trazo ligeramente diferente para garantizar que las líneas del mismo ancho original siempre tengan el mismo ancho ajustado (a costa de permitir huecos y superposiciones entre líneas adyacentes). Esto está configurado por defecto en "sí".
forceAccurateTiling sí | no
Si esto se establece en "sí", TilingType se fuerza a 2 (sin distorsión) para todos los patrones de mosaico, independientemente de la configuración en el diccionario de patrones. Esto está configurado por defecto en "no".
screenType disperso | agrupado | agrupado_estocástico
Establece el tipo de pantalla de semitonos, que se utilizará al generar un mapa de bits monocromático (1 bit). Las tres opciones son dithering de puntos dispersos, dithering de puntos agrupados (con un punto redondo y un ángulo de pantalla de 45 grados) y dithering de puntos agrupados estocástico. Por defecto, "agrupado_estocástico" se utiliza para resoluciones de 300 dpi y superiores, y "disperso" se utiliza para resoluciones inferiores a 300 dpi.
screenSize entero
Establece el tamaño de la matriz de umbral de pantalla de semitonos (cuadrada). Por defecto, es 4 para dithering de puntos dispersos, 10 para dithering de puntos agrupados y 100 para dithering de puntos agrupados estocástico.
screenDotRadius entero
Establece el radio del punto de la pantalla de semitonos. Esto solo se utiliza cuando screenType se establece en stochasticClustered, y está configurado por defecto en 2. En el modo de puntos agrupados, el radio del punto es la mitad del tamaño de la pantalla. El dithering de puntos dispersos no tiene radio de punto.
screenGamma flotante
Establece el parámetro de corrección gamma de la pantalla de semitonos. Los valores de gamma mayores que 1 hacen la salida más brillante; los valores de gamma menores que 1 la hacen más oscura. El valor predeterminado es 1.
screenBlackThreshold flotante
Al realizar semitonos, todos los valores por debajo de este umbral se fuerzan a negro sólido. Este parámetro es un valor de punto flotante entre 0 (negro) y 1 (blanco). El valor predeterminado es 0.
screenWhiteThreshold flotante
Al realizar semitonos, todos los valores por encima de este umbral se fuerzan a blanco sólido. Este parámetro es un valor de punto flotante entre 0 (negro) y 1 (blanco). El valor predeterminado es 1.
minLineWidth flotante
Establece el ancho mínimo de línea, en píxeles del dispositivo. Esto afecta solo al rasterizador, no al convertidor PostScript (excepto cuando utiliza rasterización para manejar la transparencia). El valor predeterminado es 0 (sin mínimo).
enablePathSimplification sí | no
Si se establece en "sí", simplifica las rutas eliminando puntos donde no hará una diferencia significativa en la forma. El valor predeterminado es "no".
overprintPreview sí | no
Si se establece en "sí", genera una salida de vista previa de sobreimpresión, respetando la configuración OP/op/OPM en el archivo PDF. Ignorado para salida que no sea CMYK. El valor predeterminado es "no".

CONFIGURACIÓN DEL VISOR

Estas configuraciones solo se aplican al visor PDF GUI de Xpdf.

initialZoom porcentaje | página | ancho
Establece el factor de zoom inicial. Un número especifica un porcentaje de zoom, donde 100 significa 72 ppp. También puede especificar 'página', para ajustar la página al tamaño de la ventana, o 'ancho', para ajustar el ancho de la página al ancho de la ventana.
defaultFitZoom porcentaje
Si xpdf se inicia con zoom de ajuste de página o ajuste de ancho y sin geometría de ventana, calculará un tamaño de ventana deseado basado en el tamaño de página del PDF y este valor de defaultFitZoom. Es decir, el tamaño de la ventana se elegirá de modo que exactamente una página quepa en la ventana con este factor de zoom (que debe ser un porcentaje). El valor predeterminado se basa en la resolución de la pantalla.
zoomScaleFactor ratio | real
Los porcentajes de zoom se escalarán por este factor. Por defecto, el zoom del 100% corresponde a 72 ppp. Establecer zoomScaleFactor en 1.5 hará que el zoom del 100% sea 1.5 veces más grande, es decir, 108 ppp. Si esto se establece en 'real', el factor de escala de zoom se calculará en función de la resolución de la pantalla. El valor predeterminado es 1.0.
zoomValues zoom1 zoom2 zoom3 ...
Establece la lista de valores de zoom (porcentajes) que se muestran en el cuadro combinado de zoom. La lista predeterminada es: 25 50 75 100 110 125 150 175 200 300 400 600 800.
initialDisplayMode single | continuous | sideBySideSingle | sideBySideContinuous | horizontalContinuous
Establece el modo de visualización inicial. La configuración predeterminada es "continuous".
initialToolbarState yes | no
Si se establece en "yes", xpdf se abre con la barra de herramientas visible. Si se establece en "no", xpdf se abre con la barra de herramientas oculta. El valor predeterminado es "yes".
initialSidebarState yes | no
Si se establece en "yes", xpdf se abre con la barra lateral (pestañas, esquema, etc.) visible. Si se establece en "no", xpdf se abre con la barra lateral contraída. El valor predeterminado es "yes".
initialSidebarWidth width
Establece el ancho inicial de la barra lateral, en píxeles. Esto solo es relevante si initialSidebarState es "yes". El valor predeterminado es cero, lo que indica a xpdf que utilice un tamaño predeterminado interno.
initialSelectMode block | linear
Establece el modo de selección inicial. La configuración predeterminada es "linear".
paperColor color
Establece el color del "papel", es decir, el fondo de la visualización de la página. El color puede ser #RRGGBB (hexadecimal) o un color con nombre. Esta opción no funcionará bien con archivos PDF que hagan cosas como rellenar blanco detrás del texto.
matteColor color
Establece el color del mate, es decir, el color utilizado para el fondo fuera del área real de la página. El color puede ser #RRGGBB (hexadecimal) o un color con nombre.
fullScreenMatteColor color
Establece el color del mate para el modo de pantalla completa. El color puede ser #RRGGBB (hexadecimal) o un color con nombre.
selectionColor color
Establece el color de selección. El color puede ser #RRGGBB (hexadecimal) o un color con nombre.
reverseVideoInvertImages yes | no
Si se establece en "no", el modo de video inverso de xpdf invierte el texto y los gráficos vectoriales, pero no las imágenes. Si se establece en "yes", xpdf también invierte las imágenes. El valor predeterminado es "no".
popupMenuCmd title command ...
Añade un comando al menú contextual. Title es el texto que se mostrará en el menú. Command es un comando de Xpdf (consulte la sección COMMANDS de la página man de xpdf(1) para obtener detalles). Múltiples comandos están separados por espacios.
maxTileWidth pixels
Establece el ancho máximo de las teselas que utilizará xpdf al rasterizar páginas. El valor predeterminado es 1500.
maxTileHeight pixels
Establece la altura máxima de las teselas que utilizará xpdf al rasterizar páginas. El valor predeterminado es 1500.
tileCacheSize tiles
Establece el número máximo de teselas que almacenará en caché xpdf al rasterizar páginas. El valor predeterminado es 10.
workerThreads numThreads
Establece el número de hilos de trabajo que utilizará xpdf al rasterizar páginas. El valor predeterminado es 1.
allowLinksToChangeZoom yes | no
Los enlaces PDF, incluidos los elementos del esquema, pueden incluir un nuevo nivel de zoom. Si esta configuración es "yes", Xpdf cambia el zoom cuando se hace clic en los enlaces; si es "no", Xpdf se mueve al destino pero no cambia el zoom. El valor predeterminado es "yes".
launchCommand command
Establece el comando que se ejecuta cuando se hace clic en un enlace de tipo "launch". La intención es que el comando sea un programa/script que determine el tipo de archivo y ejecute el visor apropiado. La línea de comandos consistirá en el archivo a lanzar, seguido de cualquier parámetro especificado con el enlace. No utilice "%s" en "command". Por defecto, esto no está configurado y Xpdf intentará simplemente ejecutar el archivo (después de preguntar al usuario).
movieCommand command
Establece el comando que se ejecuta cuando se hace clic en una anotación de película. La cadena "%s" se reemplazará con el nombre del archivo de película. Esto no tiene un valor predeterminado.
defaultPrinter printer
Establece la impresora predeterminada utilizada en el cuadro de diálogo de impresión del visor.
bind modifiers-key context command ...
Añade una vinculación de tecla o botón del ratón. Modifiers puede ser cero o más de: 
    shift-
    ctrl-
    alt-
Key puede ser un carácter ASCII normal, o cualquiera de: 
    space
    tab
    return
    enter
    backspace
    esc
    insert
    delete
    home
    end
    pgup
    pgdn
    left / right / up / down                (teclas de flecha)
    f1 .. f35                               (teclas de función)
    mousePress1 .. mousePress7              (botones del ratón)
    mouseRelease1 .. mouseRelease7          (botones del ratón)
    mouseClick1 .. mouseClick7              (botones del ratón)
    mouseDoubleClick1 .. mouseDoubleClick7  (botones del ratón)
    mouseTripleClick1 .. mouseTripleClick7  (botones del ratón)
Context es "any" o una combinación separada por comas de: 
    fullScreen / window       (modo de pantalla completa activado/desactivado)
    continuous / singlePage   (modo continuo activado/desactivado)
    overLink / offLink        (ratón sobre un enlace o no)
    scrLockOn / scrLockOff    (bloqueo de desplazamiento activado/desactivado)
La cadena de contexto solo puede incluir uno de cada par en la lista anterior.

Command es un comando de Xpdf (consulte la sección COMMANDS de la página man de xpdf(1) para obtener detalles). Múltiples comandos están separados por espacios.

El comando bind reemplaza cualquier vinculación existente, pero solo si se definió para los modificadores, la tecla y el contexto exactos. Todos los tokens (modificadores, tecla, contexto, comandos) distinguen entre mayúsculas y minúsculas.

Ejemplos de vinculaciones de teclas:

    # enlaza ctrl-a en cualquier contexto con el comando nextPage
    bind ctrl-a any nextPage
    # enlaza B mayúscula, cuando está en modo continuo
    # con el bloqueo de desplazamiento activado, con el comando reload
    # seguido del comando prevPage
    bind B continuous,scrLockOn reload prevPage
Consulte la página man de xpdf(1) para ver más ejemplos.
unbind modifiers-key context
Elimina una vinculación de teclas establecida con el comando bind. Esto es muy útil para eliminar las vinculaciones de teclas predeterminadas antes de establecer otras nuevas (por ejemplo, si la vinculación de teclas predeterminada se da para el contexto "any", y desea crear nuevas vinculaciones de teclas para múltiples contextos).
tabStateFile path
Establece el archivo utilizado por los comandos loadTabState y saveTabState (consulte la página man de xpdf(1) para obtener más información). La ruta predeterminada es ~/.xpdf.tabstate.
sessionFile path
Establece el archivo utilizado por los comandos saveSession y loadSession (consulte la página man de xpdf(1) para obtener más información). La ruta predeterminada es ~/.xpdf.session. Cuando xpdf guarda automáticamente la sesión a través de un administrador de sesiones, añade ".managed" a la ruta.
saveSessionOnQuit yes | no
Si se establece en "yes", xpdf guardará automáticamente la sesión actual (equivalente al comando saveSession) al salir (a través del menú o una vinculación de teclas). El valor predeterminado es "yes".

CONFIGURACIÓN MISCELÁNEA

drawAnnotations yes | no
Si se establece en "no", las anotaciones no se dibujarán ni imprimirán. El valor predeterminado es "yes".
drawFormFields yes | no
Si se establece en "no", los campos del formulario no se dibujarán ni imprimirán. El valor predeterminado es "yes".
enableXFA yes | no
Si hay un formulario XFA presente y esta opción se establece en "yes", Xpdf analizará el formulario XFA y utilizará cierta información XFA para anular la información de AcroForm. Si se establece en "no", el formulario XFA no se leerá. El valor predeterminado es "yes".
savePageNumbers yes | no
Si se establece en "yes", xpdf guardará los números de página actuales de todos los archivos abiertos en ~/.xpdf.pages cuando se cierren los archivos (o al salir de xpdf). La próxima vez que se abra el archivo, se restaurará el número de página visto por última vez. El valor predeterminado es "yes".
printCommands yes | no
Si se establece en "yes", los comandos de dibujo se imprimirán a medida que se ejecutan (útil para depurar). El valor predeterminado es "no".
printStatusInfo
Si se establece en "yes", imprime un mensaje de estado (en stdout) antes de que se procese cada página. El valor predeterminado es "no".
errQuiet yes | no
Si se establece en "yes", esto suprime todos los mensajes de error y advertencia de todas las herramientas de Xpdf. El valor predeterminado es "no".

# del paquete de soporte tailandés

fontFile Helvetica-BoldOblique /usr/local/share/ghostscript/fonts/n019024l.pfb
fontFile Courier               /usr/local/share/ghostscript/fonts/n022003l.pfb
fontFile Courier-Oblique       /usr/local/share/ghostscript/fonts/n022023l.pfb
fontFile Courier-Bold          /usr/local/share/ghostscript/fonts/n022004l.pfb
