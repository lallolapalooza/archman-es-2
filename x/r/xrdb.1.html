XRDB(1) Manual de Comandos Generales XRDB(1)

NOMBRE

xrdb - utilidad de base de datos de recursos del servidor X

SINOPSIS

xrdb [-opción ...] [archivo]

DESCRIPCIÓN

Xrdb se utiliza para obtener o establecer el contenido de la propiedad RESOURCE_MANAGER en la ventana raíz de la pantalla 0, o la propiedad SCREEN_RESOURCES en la ventana raíz de cualquiera o todas las pantallas, o todo combinado. Normalmente ejecutaría este programa desde su archivo de inicio de X.

La mayoría de los clientes X utilizan las propiedades RESOURCE_MANAGER y SCREEN_RESOURCES para obtener las preferencias del usuario sobre color, fuentes, etc. para las aplicaciones. Tener esta información en el servidor (donde está disponible para todos los clientes) en lugar de en disco, resuelve el problema en versiones anteriores de X que requerían que mantuviera archivos de defaults en cada máquina que pudiera usar. También permite el cambio dinámico de los valores predeterminados sin editar archivos.

La propiedad RESOURCE_MANAGER se utiliza para recursos que se aplican a todas las pantallas de la pantalla. La propiedad SCREEN_RESOURCES en cada pantalla especifica recursos adicionales (o que los anulan) que se utilizarán para esa pantalla. (Cuando solo hay una pantalla, normalmente no se utiliza SCREEN_RESOURCES, todos los recursos se colocan en la propiedad RESOURCE_MANAGER.)

El archivo especificado por archivo (o el contenido de la entrada estándar si se da - o ningún nombre de archivo) se pasa opcionalmente a través del preprocesador C con los siguientes símbolos definidos, basados en las capacidades del servidor que se esté utilizando:

SERVERHOST=hostname
la parte del nombre de host de la pantalla a la que está conectado.
SRVR_nombre
la cadena del nombre de host de SERVERHOST convertida en un identificador legal. Por ejemplo, "my-dpy.lcs.mit.edu" se convierte en SRVR_my_dpy_lcs_mit_edu.
HOST=hostname
lo mismo que SERVERHOST.
DISPLAY_NUM=num
el número de la pantalla en el host del servidor.
CLIENTHOST=hostname
el nombre del host en el que se está ejecutando xrdb.
CLNT_nombre
la cadena del nombre de host de CLIENTHOST convertida en un identificador legal. Por ejemplo, "expo.lcs.mit.edu" se convierte en CLNT_expo_lcs_mit_edu.
RELEASE=num
el número de versión del proveedor para el servidor. La interpretación de este número variará según el PROVEEDOR.
REVISION=num
la versión menor del protocolo X soportada por este servidor (actualmente 0).
VERSION=num
la versión principal del protocolo X soportada por este servidor (debería ser siempre 11).
VENDOR="proveedor"
una cadena literal que especifica el proveedor del servidor.
VNDR_nombre
la cadena del nombre del PROVEEDOR convertida en un identificador legal. Por ejemplo, "MIT X Consortium" se convierte en VNDR_MIT_X_Consortium.
EXT_nombre
Se define un símbolo para cada extensión de protocolo soportada por el servidor. Cada nombre de cadena de extensión se convierte en un identificador legal. Por ejemplo, "X3D-PEX" se convierte en EXT_X3D_PEX.
NUM_SCREENS=num
el número total de pantallas.
SCREEN_NUM=num
el número de la pantalla actual (desde cero).
BITS_PER_RGB=num
el número de bits significativos en una especificación de color RGB. Este es el logaritmo en base 2 del número de tonos distintos de cada primario que el hardware puede generar. Tenga en cuenta que normalmente no está relacionado con PLANES.
CLASS=clase_visual
uno de StaticGray, GrayScale, StaticColor, PseudoColor, TrueColor, DirectColor. Esta es la clase visual de la ventana raíz.
CLASS_clase_visual=id_visual
la clase visual de la ventana raíz en un formato sobre el que puede hacer #ifdef. El valor es el ID numérico del visual.
COLOR
definido solo si CLASS es uno de StaticColor, PseudoColor, TrueColor o DirectColor.
CLASS_clase_visual_profundidad=num
Se define un símbolo para cada visual soportado para la pantalla. El símbolo incluye la clase del visual y su profundidad; el valor es el ID numérico del visual. (Si más de un visual tiene la misma clase y profundidad, se utiliza el ID numérico del primero reportado por el servidor).
HEIGHT=num
la altura de la ventana raíz en píxeles.
WIDTH=num
el ancho de la ventana raíz en píxeles.
PLANES=num
el número de planos de bits (la profundidad) de la ventana raíz.
X_RESOLUTION=num
la resolución x de la pantalla en píxeles por metro.
Y_RESOLUTION=num
la resolución y de la pantalla en píxeles por metro.

Los identificadores SRVR_nombre, CLNT_nombre, VNDR_nombre y EXT_nombre se forman cambiando todos los caracteres que no sean letras y dígitos por guiones bajos (_).

Las líneas que comienzan con un signo de exclamación (!) se ignoran y pueden usarse como comentarios.

Tenga en cuenta que, dado que xrdb puede leer de la entrada estándar, se puede usar para cambiar el contenido de las propiedades directamente desde una terminal o desde un script de shell.

OPCIONES

El programa xrdb acepta las siguientes opciones:

-help
Esta opción (o cualquier opción no soportada) hará que se imprima una breve descripción de las opciones y parámetros permitidos.
-version
Esta opción hará que se imprima la versión de xrdb y el programa saldrá sin realizar ninguna otra operación.
-display pantalla
Esta opción especifica el servidor X a utilizar; véase X(7). También especifica la pantalla a utilizar para la opción -screen, y especifica la pantalla de la cual se derivan los símbolos del preprocesador para la opción -global.
-all
Esta opción indica que la operación se realizará en la propiedad de recursos independiente de la pantalla (RESOURCE_MANAGER), así como en la propiedad específica de la pantalla (SCREEN_RESOURCES) en cada pantalla de la pantalla. Por ejemplo, cuando se usa junto con -query, se muestra el contenido de todas las propiedades. Para -load, -override y -merge, el archivo de entrada se procesa una vez por cada pantalla. Los recursos que ocurren comúnmente en la salida de cada pantalla se recopilan y se aplican como recursos independientes de la pantalla. Los recursos restantes se aplican para cada propiedad individual por pantalla. Este es el modo de operación predeterminado.
-global
Esta opción indica que la operación solo se realizará en la propiedad independiente de la pantalla RESOURCE_MANAGER.
-screen
Esta opción indica que la operación solo se realizará en la propiedad SCREEN_RESOURCES de la pantalla predeterminada de la pantalla.
-screens
Esta opción indica que la operación se realizará en la propiedad SCREEN_RESOURCES de cada pantalla de la pantalla. Para -load, -override y -merge, el archivo de entrada

se procesa para cada pantalla.
-n
Esta opción indica que los cambios en las propiedades especificadas (cuando se usa con -load, -override o -merge) o en el archivo de recursos (cuando se usa con -edit) se mostrarán en la salida estándar, pero no se realizarán.
-quiet
Esta opción indica que no se deben mostrar advertencias sobre entradas duplicadas.
-cpp nombre_archivo
Esta opción especifica la ruta del programa preprocesador de C que se utilizará. Aunque xrdb fue diseñado para usar CPP, se puede usar cualquier programa que actúe como filtro y acepte las opciones -D, -I y -U.
-nocpp
Esta opción indica que xrdb no debe procesar el archivo de entrada a través de un preprocesador antes de cargarlo en las propiedades.
-undef
Esta opción se pasa al preprocesador de C si se utiliza. Evita que predefina cualquier macro específica del sistema.
-E
Esta opción indica que cualquier comando cpp ejecutado y su salida deben mostrarse en la salida estándar. Si también se especificó -nocpp, el archivo de entrada se mostrará tal como se leyó. Los cambios especificados también se realizarán a menos que también se especifique la opción -n.
-symbols
Esta opción indica que los símbolos definidos para el preprocesador se imprimirán en la salida estándar.
-query
Esta opción indica que el contenido actual de las propiedades especificadas se imprimirá en la salida estándar. Tenga en cuenta que, dado que los comandos del preprocesador en el archivo de recursos de entrada son parte del archivo de entrada, no de la propiedad, no aparecerán en la salida de esta opción. La opción -edit se puede usar para fusionar el contenido de las propiedades de nuevo en el archivo de recursos de entrada sin dañar los comandos del preprocesador.
-get nombre
Esta opción indica que el contenido actual de la propiedad que coincide con nombre se imprimirá en la salida estándar.
-load
Esta opción indica que la entrada se cargará como el nuevo valor de las propiedades especificadas, reemplazando lo que hubiera allí (es decir, se elimina el contenido antiguo). Esta es la acción predeterminada.
-override
Esta opción indica que la entrada se agregará al contenido actual de las propiedades especificadas, en lugar de reemplazarlo. Las nuevas entradas anulan las entradas anteriores.
-merge
Esta opción indica que la entrada se fusionará y ordenará lexicográficamente con el contenido actual de las propiedades especificadas, en lugar de reemplazarlo.
-remove
Esta opción indica que las propiedades especificadas deben eliminarse del servidor.
-retain
Esta opción indica que se debe instruir al servidor para que no se reinicie si xrdb es el primer cliente. Esto nunca debería ser necesario en condiciones normales, ya que xdm y xinit siempre actúan como el primer cliente.
-edit nombre_archivo
Esta opción indica que el contenido de las propiedades especificadas se editará en el archivo dado, reemplazando cualquier valor que ya esté listado allí. Esto le permite volver a colocar los cambios que ha realizado en sus valores predeterminados en su archivo de recursos, conservando cualquier comentario o línea de preprocesador.
-backup cadena
Esta opción especifica un sufijo que se agregará al nombre del archivo utilizado con -edit para generar un archivo de copia de seguridad.
-Dnombre[=valor]
Esta opción se pasa al preprocesador y se utiliza para definir símbolos para usarlos con condicionales como #ifdef.
-Unombre
Esta opción se pasa al preprocesador y se utiliza para eliminar cualquier definición de este símbolo.
-Idirectorio
Esta opción se pasa al preprocesador y se utiliza para especificar un directorio donde buscar archivos a los que se hace referencia con #include.

ARCHIVOS

Xrdb no carga ningún archivo por sí solo, pero muchos entornos de escritorio utilizan xrdb para cargar archivos ~/.Xresources al inicio de sesión para inicializar la base de datos de recursos, como un reemplazo generalizado para los archivos ~/.Xdefaults.

VER TAMBIÉN

ENTORNO
