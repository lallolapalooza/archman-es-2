NOMBRE

xrootdfs - demonio de sistema de archivos FUSE de xrootd

SINOPSIS

xrootdfs [opciones] parámetros

DESCRIPCIÓN

El demonio xrootdfs proporciona una vista de sistema de archivos de un clúster xrootd usando FUSE. El resumen de uso se puede mostrar escribiendo "xrootdfs -h". La documentación breve se puede encontrar en un archivo README en el directorio src/XrdFfs del código fuente.

EJEMPLOS

Suponiendo que el redireccionador es rdr:puerto

ejecutar desde la línea de comandos con salida de depuración

xrootdfs -d -o rdr=root://rdr:puerto//datos,uid=demonio /mnt

usar en /etc/fstab

xrootdfs /mnt fuse rdr=root://rdr:puerto//datos,uid=demonio 1 2

usar con autofs

1. agregar una línea a /etc/auto.master
/- /etc/auto.fuse

2. crear /etc/auto.fuse con la siguiente línea
/mnt -fstype=fuse,uid=2,rdr=root://rdr\:puerto//datos :xrootdfs.sh

3. crear el script /usr/bin/xrootdfs.sh (asegúrate de que el bit +x esté establecido)
#!/bin/sh
exec /usr/bin/xrootdfs $@ >/dev/null 2>&1

NOTAS

La documentación para todos los componentes asociados con xrootdfs se puede encontrar en https://xrootd.org/docs.html

xrootdfs permite a los usuarios y administradores consultar y cambiar los parámetros internos sobre la marcha a través de los atributos extendidos del sistema de archivos

getfattr -n nombre_atributo /punto_montaje
setfattr -n nombre_atributo [ -v valor ] /punto_montaje

nombre_atributo:

xroot.url: consultar la URL REAL de xrootd del archivo (esta es una antigua)
xrootdfs.fs.nworkers: consultar o cambiar el número de hilos que trabajan en paralelo en operaciones como stat(), unlink()/rmdir(), readdir(), statvfs(), etc.
xrootdfs.fs.dataserverlist: consultar o actualizar la lista de todos los servidores de datos conocidos por esta instancia de xrootdfs (o "kill -USR1 pid" para actualizar)

SEGURIDAD

Por defecto, XrootdFS no envía la identidad de usuario individual a los servidores de almacenamiento Xrootd. Por lo tanto, el almacenamiento Xrootd piensa que todas las operaciones de una instancia de XrootdFS provienen del usuario que ejecuta la instancia de XrootdFS. Cuando el módulo de seguridad "sss" de Xrootd (Seguridad Compartida Simple) está habilitado tanto en XrootdFS como en el sistema de almacenamiento Xrootd, XrootdFS enviará información de identidad de usuario individual a los servidores de almacenamiento Xrootd. Esta información se puede usar junto con la ACL de Xrootd para controlar el acceso a archivos/directorios.

Para usar el módulo de seguridad "sss", tanto los servidores de datos Xrootd como XrootdFS deben configurarse para usar "sss" de una manera particular, por ejemplo, ambos lados deben usar un archivo de clave que contenga la misma clave generada por el programa xrdsssadmin de la siguiente manera:

xrdsssadmin -k nombre_mi_clave -u cualquiera -g grupousuario añadir archivo_clave

(cambiar solo "nombre_mi_clave" y "archivo_clave"). Por favor, consulte la variable de entorno "XrdSecsssKT" en la "Referencia de Configuración de Autenticación y Control de Acceso" de Xrootd para obtener más información sobre la ubicación del archivo de clave y sus bits de permiso de Unix. Ese mismo documento también describe el archivo de base de datos de ACL de Xrootd.

Para habilitar "sss" con XrootdFS, use la opción sss=/archivo_clave con XrootdFS.

El siguiente ejemplo muestra cómo usar tanto los módulos de seguridad de Unix como los de sss con los servidores de datos Xrootd.


xrootd.seclib /usr/lib64/libXrdSec.so
sec.protocol /usr/lib64 sss -s /archivo_clave
sec.protocol /usr/lib64 unix
acc.authdb /tu_archivo_db_autenticación_ACL_xrootd
acc.authrefresh 300
ofs.authorize

DIAGNÓSTICOS

Los errores generan un mensaje de error y un estado de salida distinto de cero. El programa nunca sale en caso de éxito. Use el comando umount para terminar el programa.

La información de registro adicional se puede encontrar en syslog (/var/log/messages)
