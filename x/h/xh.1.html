XH(1) Comandos de Usuario XH(1)

NOMBRE

xh - Herramienta amigable y rápida para enviar peticiones HTTP

SINOPSIS

xh [OPCIONES] [METODO] URL [--] [ITEM_PETICION ...]

DESCRIPCIÓN

xh es un cliente HTTP con una interfaz de línea de comandos amigable. Se esfuerza por tener una salida legible y opciones fáciles de usar.

xh es mayormente compatible con HTTPie: ver http(1).

La opción --curl se puede usar para imprimir una traducción de curl(1) del comando en lugar de enviar una petición.

ARGUMENTOS POSICIONALES

[METODO]
El método HTTP a usar para la petición.

Por defecto es GET, o POST si la petición contiene un cuerpo.

URL
La URL a solicitar.

El esquema de la URL por defecto es "http://", o "https://" si el programa se invoca como "xhs".

Un dos puntos inicial funciona como atajo para localhost. ":8000" es equivalente a "localhost:8000", y ":/ruta" es equivalente a "localhost/ruta".

[ITEM_PETICION ...]
Pares clave-valor opcionales a incluir en la petición.

El separador se usa para determinar el tipo:

clave==valor
Añadir una cadena de consulta a la URL.
clave=valor
Añadir una propiedad JSON (--json) o un campo de formulario (--form) al cuerpo de la petición.
clave:=valor
Añadir un campo con un valor JSON literal al cuerpo de la petición.

Ejemplo: "numeros:=[1,2,3] habilitado:=verdadero"

clave@archivo
Subir un archivo (requiere --form o --multipart).

Para establecer el nombre del archivo y el tipo MIME, se pueden usar respectivamente ";type=" y ";filename=".

Ejemplo: "pfp@ra.jpg;type=image/jpeg;filename=perfil.jpg"

@archivo
Usar un archivo como cuerpo de la petición.
encabezado:valor
Añadir un encabezado, ej: "user-agent:foobar"
encabezado:
Anular un encabezado, ej: "connection:"
encabezado:;
Añadir un encabezado con un valor vacío.
Un prefijo "@" se puede usar para leer un valor de un archivo. Por ejemplo: "x-api-key:@api-key.txt".

Se puede usar una barra invertida para escapar caracteres especiales, ej: "weird\:key=value".

Para construir un objeto JSON complejo, la clave del ITEM_PETICION puede establecerse como una ruta JSON en lugar de un nombre de campo. Para más información sobre esta sintaxis, consulta https://httpie.io/docs/cli/nested-json.

OPCIONES

Cada --OPCION puede ser restablecida con un argumento --no-OPCION.

-j, --json
(por defecto) Serializar los elementos de datos de la línea de comandos como un objeto JSON.

Anula tanto --form como --multipart.

-f, --form
Serializar los elementos de datos de la línea de comandos como campos de formulario.

Anula tanto --json como --multipart.

--multipart
Similar a --form, pero fuerza una petición multipart/form-data incluso sin archivos.

Anula tanto --json como --form.

--raw=BRUTO
Pasar datos de petición brutos sin procesamiento adicional.
--pretty=ESTILO
Controla el procesamiento de la salida. Los valores posibles son:


all (por defecto) Habilita tanto el coloreado como el formateo
colors Aplica resaltado de sintaxis a la salida
format Formatea json e ordena encabezados
none Deshabilita tanto el coloreado como el formateo

Por defecto es "format" si la variable de entorno NO_COLOR está configurada y "none" si stdout no es una tty.

--format-options=OPCIONES_FORMATO
Establece opciones de formato de salida. Las opciones soportadas son:


json.indent:<NUM>
json.format:<true|false>
headers.sort:<true|false>

Ejemplo: --format-options=json.indent:2,headers.sort:false.

-s, --style=TEMA
Estilo de coloreado de salida.

[valores posibles: auto, solarized, monokai, fruity]

--response-charset=CODIFICACION
Anula la codificación de la respuesta para su visualización en terminal.

Ejemplo: --response-charset=latin1.

--response-mime=TIPO_MIME
Anula el tipo MIME de la respuesta para colorear y formatear en la terminal.

Ejemplo: --response-mime=application/json.

-p, --print=FORMATO
Cadena que especifica qué debe contener la salida


'H' encabezados de petición
'B' cuerpo de petición
'h' encabezados de respuesta
'b' cuerpo de respuesta
'm' metadatos de respuesta

Ejemplo: --print=Hb.

-h, --headers
Imprime solo los encabezados de respuesta. Atajo para --print=h.
-b, --body
Imprime solo el cuerpo de respuesta. Atajo para --print=b.
-m, --meta
Imprime solo los metadatos de respuesta. Atajo para --print=m.
-v, --verbose
Imprime toda la petición así como la respuesta.

Adicionalmente, esto habilita --all para imprimir peticiones/respuestas intermedias al seguir redirecciones.

Usar verbose dos veces, es decir -vv, imprimirá también los metadatos de respuesta.

Equivalente a --print=HhBb --all.

--debug
Imprime el stack de errores completo y mensajes de log de depuración.

El logging se puede configurar con más detalle usando la variable de entorno `$RUST_LOG`. Configura `RUST_LOG=trace` para mostrar aún más mensajes. Ver https://docs.rs/env_logger/0.11.3/env_logger/#enabling-logging.

--all
Muestra cualquier petición/respuesta intermedia al seguir redirecciones con --follow.
-P, --history-print=FORMATO
Lo mismo que --print pero se aplica solo a peticiones/respuestas intermedias.
-q, --quiet
No imprimir a stdout ni stderr.

Usar quiet dos veces, es decir -qq, suprimirá también las advertencias.

-S, --stream
Transmitir siempre el cuerpo de la respuesta.
-x, --compress
Contenido comprimido (codificado) con el algoritmo Deflate.

El encabezado Content-Encoding se establece a deflate.

La compresión se omite si parece que la relación de compresión es negativa. La compresión se puede forzar repitiendo esta opción.

Nota: La compresión no se puede usar si el encabezado de petición Content-Encoding está presente.

-o, --output=ARCHIVO
Guardar la salida en ARCHIVO en lugar de stdout.
-d, --download
Descargar el cuerpo a un archivo en lugar de imprimirlo.

El encabezado Accept-Encodin

OPCIONES

-c, --continue
Reanuda una descarga interrumpida. Requiere --download y --output.
--session=ARCHIVO
Crea, o reutiliza y actualiza una sesión.

Dentro de una sesión, las cabeceras personalizadas, las credenciales de autenticación, así como cualquier cookie enviada por el servidor persisten entre solicitudes.

--session-read-only=ARCHIVO
Crea o lee una sesión sin actualizarla a partir del intercambio de solicitud/respuesta.
-A, --auth-type=TIPO_AUTENTICACION
Especifica el mecanismo de autenticación.

[valores posibles: basic, bearer, digest]

-a, --auth=USUARIO[:CONTRASEÑA] | TOKEN
Autentícate como USUARIO con CONTRASEÑA (-A basic|digest) o con TOKEN (-A bearer).

Se te pedirá la CONTRASEÑA si falta. Usa dos puntos al final (es decir, "USUARIO:") para autenticarte solo con nombre de usuario.

Se espera un TOKEN si --auth-type=bearer.

--ignore-netrc
No uses credenciales de .netrc.
--offline
Construye solicitudes HTTP sin enviarlas a ningún sitio.
--check-status
(por defecto) Sale con un código de estado de error si el servidor responde con un error.

El código de salida será 4 para 4xx (Error del Cliente), 5 para 5xx (Error del Servidor), o 3 para 3xx (Redirección) si --follow no está configurado.

Si stdout está redirigido, se escribirá una advertencia en stderr.

-F, --follow
Sigue las redirecciones.
--max-redirects=NUM
Número de redirecciones a seguir. Solo se respeta si se usa --follow.
--timeout=SEG
Tiempo de espera de conexión de la solicitud.

El valor por defecto es "0", es decir, no hay límite de tiempo de espera.

--proxy=PROTOCOLO:URL
Usa un proxy para un protocolo. Por ejemplo: --proxy https:http://proxy.host:8080.

PROTOCOLO puede ser "http", "https" o "all".

Si tu proxy requiere credenciales, ponlas en la URL, así: --proxy http:socks5://usuario:contraseña@proxy.host:8000.

Puedes especificar proxies para múltiples protocolos repitiendo esta opción.

Las variables de entorno "http_proxy" y "https_proxy" también pueden ser usadas, pero son completamente ignoradas si se pasa --proxy.

--verify=VERIFICAR
Si es "no", omite la verificación SSL. Si es una ruta de archivo, úsala como un paquete de CA.

Especificar un paquete de CA deshabilitará los certificados raíz integrados del sistema.

"false" en lugar de "no" también funciona. El valor por defecto es "yes" ("true").

--cert=ARCHIVO
Usa un certificado de lado del cliente para SSL.
--cert-key=ARCHIVO
Un archivo de clave privada para usar con --cert.

Solo es necesario si la clave privada no está contenida en el archivo cert.

--ssl=VERSION
Fuerza una versión TLS particular.

"auto" da el comportamiento por defecto de negociar una versión con el servidor.

[valores posibles: auto, tls1, tls1.1, tls1.2, tls1.3]

--native-tls
Usa la biblioteca TLS del sistema en lugar de rustls (si está habilitada en tiempo de compilación).
--https
Realiza solicitudes HTTPS si no se especifica en la URL.
--http-version=VERSION
Versión HTTP a usar.

[valores posibles: 1.0, 1.1, 2, 2-prior-knowledge, 3-prior-knowledge]

--resolve=HOST:DIRECCION
Anula la resolución DNS para un dominio específico a una IP personalizada.

Puedes anular múltiples dominios repitiendo esta opción.

Ejemplo: --resolve=example.com:127.0.0.1.

--interface=NOMBRE
Enlaza a una interfaz de red o dirección IP local.

Ejemplo: --interface=eth0 --interface=192.168.0.2.

-4, --ipv4
Resuelve el nombre de host solo a direcciones ipv4.
-6, --ipv6
Resuelve el nombre de host solo a direcciones ipv6.
--unix-socket=ARCHIVO
Conéctate usando un socket de dominio Unix.

Ejemplo: xh :/index.html --unix-socket=/var/run/temp.sock.

-I, --ignore-stdin
No intentes leer de stdin.

Esto deshabilita el comportamiento por defecto de leer el cuerpo de la solicitud desde stdin cuando se detecta una entrada redirigida.

Se recomienda pasar esta bandera cuando se usa xh para fines de scripting. Para más información, consulta https://httpie.io/docs/cli/best-practices.

--curl
Imprime una traducción a un comando curl.

Para traducir en la otra dirección, prueba https://curl2httpie.online/.

--curl-long
Usa las versiones largas de las banderas de curl.
--generate=TIPO
Genera completado de shell o páginas man. Los valores posibles son:


complete-bash
complete-elvish
complete-fish
complete-nushell
complete-powershell
complete-zsh
man

Ejemplo: xh --generate=complete-bash > xh.bash.

--help
Imprime la ayuda.
-V, --version
Imprime la versión.

ESTADO DE SALIDA

0
Ejecución exitosa del programa.
1
Error de uso, sintaxis o red.
2
Tiempo de espera de solicitud agotado.
3
Redirección HTTP 3xx inesperada.
4
Error del cliente HTTP 4xx.
5
Error del servidor HTTP 5xx.
6
Demasiadas redirecciones.

AMBIENTE

XH_CONFIG_DIR
Especifica dónde buscar config.json y datos de sesión con nombre. El valor por defecto es ~/.config/xh para Linux/macOS y %APPDATA%\xh para Windows.
XH_HTTPIE_COMPAT_MODE
Habilita el Modo de Compatibilidad con HTTPie. La única diferencia actual es que --check-status no está habilitado por defecto. Una alternativa a establecer esta variable de entorno es renombrar el binario a http o https.
REQUESTS_CA_BUNDLE, CURL_CA_BUNDLE
Establece una ruta de paquete de CA personalizada.
http_proxy=[protocolo://]<host>[:puerto]
Establece el servidor proxy a usar para HTTP.
HTTPS_PROXY=[protocolo://]<host>[:puerto]
Establece el servidor proxy a usar para HTTPS.
NO_PROXY
Lista de hosts separados por comas para los cuales se ignoran las otras variables de entorno de proxy. "*" coincide con todos los nombres de host.
NETRC
Ubicación del archivo .netrc.
NO_COLOR
Deshabilita el coloreado de la salida. Ver https://no-color.org
RUST_LOG
Configura mensajes de depuración de bajo nivel. Ver https://docs.rs/env_logger/0.11.3/env_logger/#enabling-logging

ARCHIVOS

~/.config/xh/config.json
Archivo de configuración de xh. La única opción configurable es "default_options", que es una lista de argumentos de shell por defecto que se pasan a xh. Ejemplo:
{ "default_options": ["--native-tls", "--style=solarized"] }
~/.netrc, ~/_netrc
Archivo de información de auto-login.
~/.config/xh/sessions
Directorio de datos de sesiones agrupado por dominio y número de puerto.

EJEMPLOS

xh httpbin.org/json
Envía una solicitud GET.
xh httpbin.org/post name=ahmed age:=24
Envía una solicitud POST con el cuerpo {"name": "ahmed", "age": 24}.
xh get httpbin.org/json id==5 sort==true
Envía una solicitud GET a http://httpbin.org/json?id=5&sort=true.
xh get httpbin.org/json x-api-key:12345
Envía una solicitud GET e incluye una cabecera llamada X-Api-Key con el valor 12345.
echo "[1, 2, 3]" | xh post httpbin.org/post
Enviar una solicitud POST con el cuerpo leído desde stdin.
xh put httpbin.org/put id:=49 age:=25 | less
Enviar una solicitud PUT y canalizar el resultado a less.
xh -d httpbin.org/json -o res.json
Descargar y guardar en res.json.
xh httpbin.org/get user-agent:foobar
Realizar una solicitud con un agente de usuario personalizado.
xhs example.com
Realizar una solicitud HTTPS a https://example.com.
