x25(7) Manual de Información Miscelánea x25(7)

NOMBRE

x25 - Interfaz del protocolo X.25 / ISO/IEC 8208 de ITU-T

SINOPSIS

#include <sys/socket.h>
#include <linux/x25.h>
socket_x25 = socket(AF_X25, SOCK_SEQPACKET, 0);

DESCRIPCIÓN

Los sockets X25 proporcionan una interfaz al protocolo de capa de paquetes X.25. Esto permite a las aplicaciones comunicarse a través de una red de datos X.25 pública según lo estandarizado por la recomendación X.25 de la Unión Internacional de Telecomunicaciones (modo DTE-DCE de X.25). Los sockets X25 también se pueden usar para la comunicación sin una red X.25 intermedia (modo DTE-DTE de X.25) según se describe en ISO/IEC 8208.

Los límites de los mensajes se conservan: una llamada a read(2) desde un socket recuperará el mismo bloque de datos que se generó con la llamada correspondiente a write(2) al socket par. Cuando sea necesario, el kernel se encarga de segmentar y reensamblar mensajes largos mediante el bit M de X.25. No hay un límite superior codificado para el tamaño del mensaje. Sin embargo, el reensamblaje de un mensaje largo puede fallar si hay una falta temporal de recursos del sistema o cuando entran en juego otras restricciones (como los límites de memoria o tamaño de búfer del socket). Si eso ocurre, la conexión X.25 se reiniciará.

Direcciones de socket

La familia de direcciones de socket AF_X25 utiliza struct sockaddr_x25 para representar direcciones de red según se define en la recomendación X.121 de ITU-T.


struct sockaddr_x25 {
    sa_family_t sx25_family;    /* debe ser AF_X25 */
    x25_address sx25_addr;      /* Dirección X.121 */
};

sx25_addr contiene una matriz de caracteres x25_addr[] que debe interpretarse como una cadena terminada en nulo. sx25_addr.x25_addr[] consta de hasta 15 caracteres ASCII (sin contar el byte nulo terminador) que forman la dirección X.121. Solo se permiten los caracteres de dígito decimales '0' a '9'.

Opciones de socket

Las siguientes opciones de socket específicas de X.25 se pueden establecer utilizando setsockopt(2) y leer con getsockopt(2) con el argumento level establecido en SOL_X25.

X25_QBITINCL
Controla si el bit Q (Qualified Data Bit) de X.25 es accesible por el usuario. Espera un argumento entero. Si se establece en 0 (por defecto), el bit Q nunca se establece para los paquetes salientes y se ignora el bit Q de los paquetes entrantes. Si se establece en 1, se antepone un primer byte adicional a cada mensaje leído o escrito en el socket. Para los datos leídos del socket, un primer byte con valor 0 indica que los bits Q de los paquetes de datos entrantes correspondientes no estaban establecidos. Un primer byte con valor 1 indica que el bit Q de los paquetes de datos entrantes correspondientes estaba establecido. Si el primer byte de los datos escritos en el socket es 1, se establecerá el bit Q de los paquetes de datos salientes correspondientes. Si el primer byte es 0, no se establecerá el bit Q.

VERSIONES

La familia de protocolos AF_X25 es una nueva característica de Linux 2.2.

ERRORES

Muchos, ya que la implementación de X.25 PLP está en CONFIG_EXPERIMENTAL.

Esta página del manual está incompleta.

Todavía no hay un archivo de cabecera dedicado para el programador de aplicaciones; debe incluir el archivo de cabecera del kernel <linux/x25.h>. CONFIG_EXPERIMENTAL también podría implicar que las versiones futuras de la interfaz no son compatibles binariamente.

Los eventos de reinicio N de X.25 aún no se propagan al proceso de usuario. Por lo tanto, si ocurrió un reinicio, los datos podrían perderse sin previo aviso.
