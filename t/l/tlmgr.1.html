NOMBRE

tlmgr - el gestor nativo de TeX Live

SINOPSIS

tlmgr [opción...] acción [opción...] [operando...]

DESCRIPCIÓN

tlmgr gestiona una instalación existente de TeX Live, tanto los paquetes como las opciones de configuración. Para obtener información sobre cómo descargar e instalar TeX Live inicialmente, consulta https://tug.org/texlive/acquire.html.

La versión más actualizada de esta documentación (actualizada diariamente desde las fuentes de desarrollo) está disponible en https://tug.org/texlive/tlmgr.html, junto con procedimientos para actualizar el propio "tlmgr" e información sobre versiones de prueba.

TeX Live se organiza en unos pocos esquemas de nivel superior, cada uno de los cuales se especifica como un conjunto diferente de colecciones y paquetes, donde una colección es un conjunto de paquetes, y un paquete es lo que contiene los archivos reales. Los esquemas típicamente contienen una mezcla de colecciones y paquetes, pero cada paquete se incluye en exactamente una colección, ni más ni menos. Una instalación de TeX Live puede personalizarse y gestionarse a cualquier nivel.

Consulta https://tug.org/texlive/doc para toda la documentación de TeX Live disponible.

EJEMPLOS

Después de instalar TeX Live con éxito, aquí tienes algunas operaciones comunes con "tlmgr":

"tlmgr option repository ctan"
"tlmgr option repository https://mirror.ctan.org/systems/texlive/tlnet"
Indica a "tlmgr" que utilice un espejo de CTAN cercano para futuras actualizaciones; útil si instalaste TeX Live desde la imagen del DVD y quieres tener actualizaciones continuas. Los dos comandos son equivalentes; "ctan" es solo un alias para la url dada.

Advertencia: "mirror.ctan.org" se resuelve en muchos hosts diferentes, y no están perfectamente sincronizados; recomendamos actualizar solo diariamente (como máximo), y no con más frecuencia. Puedes elegir un espejo específico si hay problemas; la lista de todos los espejos de CTAN con el estado de cada uno está en https://ctan.org/mirrors/mirmon.

"tlmgr update --list"
Informa qué se actualizaría sin actualizar nada realmente.
"tlmgr update --all"
Haz que tu instalación local de TeX corresponda a lo que hay en el repositorio de paquetes (típicamente útil al actualizar desde CTAN).
"tlmgr info" qué
Muestra información detallada sobre un paquete qué, como el estado de instalación y la descripción, o busca qué en todos los paquetes.
"tlmgr bug" qué
Muestra información disponible para reportar errores para qué, un nombre de paquete o archivo.

Para todas las capacidades y detalles de "tlmgr", por favor lee la siguiente voluminosa información.

OPCIONES

Las siguientes opciones para "tlmgr" son opciones globales, no específicas de ninguna acción. Todas las opciones, ya sean globales o específicas de la acción, pueden especificarse en cualquier lugar de la línea de comandos, y en cualquier orden. El primer argumento que no sea una opción será la acción principal. En todos los casos, "--"opción y "-"opción son equivalentes, y un "=" es opcional entre un nombre de opción y su valor.

--repository url|ruta
Especifica el repositorio de paquetes desde el cual se deben instalar o actualizar los paquetes, ya sea un directorio local o una ubicación de red, como se indica a continuación. Esto anula el repositorio de paquetes predeterminado que se encuentra en la Base de Datos de Paquetes de TeX Live de la instalación (también conocida como TLPDB, que se encuentra completamente en el archivo "tlpkg/texlive.tlpdb").

Esta opción "--repository" cambia la ubicación solo para la ejecución actual; para realizar un cambio permanente, usa "option repository" (ver la acción "option").

Como ejemplo, puedes elegir un espejo de CTAN específico con algo como esto:

-repository http://ctan.example.org/its/ctan/dir/systems/texlive/tlnet

Por supuesto, se deben especificar un nombre de host real y su directorio principal de CTAN específico. La lista de espejos de CTAN está disponible en https://ctan.org/mirrors/mirmon.

Aquí hay un ejemplo de uso de un directorio local:

-repository /local/TL/repository

Por compatibilidad y conveniencia, se aceptan "--location" y "--repo" como alias para esta opción.

Las ubicaciones se pueden especificar como cualquiera de las siguientes:

"/algún/directorio/local"
"file:/algún/directorio/local"
Formas equivalentes de especificar un directorio local.
"ctan"
"https://mirror.ctan.org/systems/texlive/tlnet"
Elige un espejo de CTAN automáticamente, intentando encontrar uno que sea tanto cercano como actualizado. El espejo elegido se utiliza para toda la descarga. El simple "ctan" es meramente un alias para la url completa. (Ver https://ctan.org para más información sobre CTAN y sus espejos.)
"http://servidor/ruta/a/tlnet"
HTTP estándar. Si se usa el método LWP (predeterminado), se soportan conexiones persistentes. TL también puede usar "curl" o "wget" para realizar las descargas, o un programa arbitrario especificado por el usuario, como se describe en la documentación de "tlmgr" (https://tug.org/texlive/doc/tlmgr.html#ENVIRONMENT-VARIABLES).
"https://servidor/ruta/a/tlnet"
De nuevo, si se usa el método LWP (predeterminado), esto soporta conexiones persistentes. Desafortunadamente, algunas versiones de "wget" y "curl" no soportan https, e incluso cuando "wget" soporta https, los certificados pueden ser rechazados incluso cuando el certificado es válido, debido a la falta de raíces de certificados locales. La solución más simple para este problema es usar http o ftp.
"ftp://servidor/ruta/a/tlnet"
Si se usa el método LWP (predeterminado), se soportan conexiones persistentes.
"usuario@máquina:/ruta/a/tlnet"
"scp://usuario@máquina/ruta/a/tlnet"
"ssh://usuario@máquina/ruta/a/tlnet"
Estas formas son equivalentes; todas usan "scp" para transferir archivos. Se recomienda usar "ssh-agent". (Info: https://en.wikipedia.org/wiki/OpenSSH, https://en.wikipedia.org/wiki/Ssh-agent.)

Si el repositorio está en la red, se ignoran los caracteres "/" finales y/o los componentes finales "/tlpkg" y/o "/archive".

OPTIONS

--gui
Starts the native TeX Live Package Manager GUI. If no arguments are given, the GUI will be started at the main screen. See "GUI FOR TLMGR".
However, the native GUI requires Perl/TK, which is no longer included in TeX Live Perl for Windows. You may find "tlshell" or "tlcockpit" easier to work with.
--gui-lang llcode
By default, the GUI tries to deduce your language from the environment (on Windows via the registry, on Unix via "LC_MESSAGES"). If that fails you can select a different language by giving this option with a language code (based on ISO 639-1). Currently supported (but not necessarily completely translated) are: English (en, default), Czech (cs), German (de), French (fr), Italian (it), Japanese (ja), Dutch (nl), Polish (pl), Brazilian Portuguese (pt_BR), Russian (ru), Slovak (sk), Slovenian (sl), Serbian (sr), Ukrainian (uk), Vietnamese (vi), simplified Chinese (zh_CN), and traditional Chinese (zh_TW).
tlshell shares its message catalog with tlmgr.
--command-logfile file
"tlmgr" logs the output of all programs invoked (mktexlr, mtxrun, fmtutil, updmap) to a separate log file, by default "TEXMFSYSVAR/web2c/tlmgr-commands.log". This option allows you to specify a different file for the log.
--debug-translation
In GUI mode, this switch tells "tlmgr" to report any untranslated (or missing) messages to standard error. This can help translators to see what remains to be done.
--machine-readable
Instead of the normal output intended for human consumption, write (to standard output) a fixed format more suitable for machine parsing. See the "MACHINE-READABLE OUTPUT" section below.
--no-execute-actions
Suppress the execution of the execute actions as defined in the tlpsrc files. Unless you are going to do the postprocessing yourself (as, for example, "install-tl" does), this shouldn't be specified. Otherwise, format files and the filename database will become stale, among other problems.
--package-logfile file
"tlmgr" logs all package actions (install, remove, update, failed updates, failed restores) to a separate log file, by default "TEXMFSYSVAR/web2c/tlmgr.log". This option allows you to specify a different file for the log.
--pause
This option makes "tlmgr" wait for user input before exiting. Useful on Windows to avoid disappearing command windows.
--persistent-downloads
--no-persistent-downloads
For network-based installations, this option (on by default) makes "tlmgr" try to set up a persistent connection (using the "LWP" Perl module). The idea is to open and reuse only one connection per session between your computer and the server, instead of initiating a new download for each package.
If this is not possible, "tlmgr" will fall back to using "wget". To disable these persistent connections, use "--no-persistent-downloads".
--pin-file
Change the pinning file location from "TEXMFLOCAL/tlpkg/pinning.txt" (see "Pinning" below). Documented only for completeness, as this is only useful in debugging.
--usermode
Activates user mode for this run of "tlmgr"; see "USER MODE" below.
--usertree dir
Uses dir for the tree in user mode; see "USER MODE" below.
--verify-repo=[none|main|all]
Defines the level of verification done: If "none" is specified, no verification whatsoever is done. If "main" is given and a working GnuPG ("gpg") binary is available, all repositories are checked, but only the main repository is required to be signed. If "all" is given, then all repositories need to be signed. See "CRYPTOGRAPHIC VERIFICATION" below for details.

The standard options for TeX Live programs are also accepted: "--help/-h/-?", "--version", "-q" (no informational messages), "-v" (debugging messages, can be repeated). For the details about these, see the "TeXLive::TLUtils" documentation.

The "--version" option shows version information about the TeX Live release and about the "tlmgr" script itself. If "-v" is also given, revision number for the loaded TeX Live Perl modules are shown, too.

ACTIONS

help

Display this help information and exit (same as "--help", and on the web at https://tug.org/texlive/doc/tlmgr.html). Sometimes the "perldoc" and/or "PAGER" programs on the system have problems, resulting in control characters being literally output. This can't always be detected, but you can set the "NOPERLDOC" environment variable and "perldoc" will not be used.

version

Gives version information (same as "--version").

If "-v" has been given the revisions of the used modules are reported, too.

backup

backup [option...] --all
backup [option...] pkg...
If the "--clean" option is not specified, this action makes a backup of the given packages, or all packages given "--all". These backups are saved to the value of the "--backupdir" option, if that is an existing and writable directory. If "--backupdir" is not given, the "backupdir" option setting in the TLPDB is used, if present. If both are missing, no backups are made. (The installer sets "backupdir" to ".../tlpkg/backups", under the TL root installation directory, so it is usually defined; see the "option" description for more information.)
If the "--clean" option is specified, backups are pruned (removed) instead of saved. The optional integer value N may be specified to set the number of backups that will be retained when cleaning. If "N" is not given, the value of the "autobackup" option is used. If both are missing, an error is issued. For more details of backup pruning, see the "option" action.
Options:
--backupdir directory
Overrides the "backupdir" option setting in the TLPDB. The directory argument is required and must specify an existing, writable directory where backups are to be placed.
--all
If "--clean" is not specified, make a backup of all packages in the TeX Live installation; this will take quite a lot of space and time. If "--clean" is specified, all packages are pruned.
--clean[=N]
Instead of making backups, prune the backup directory of old backups, as explained above. The optional integer argument N overrides the "autobackup" option set in the TLPDB. You must use "--all" or a list of packages together with this option, as desired.
--dry-run
Nothing is actually backed up or removed; instead, the actions to be performed are written to the terminal.

bug [search-string]

Searches for search-string (prompted for, if not given) as a package name and in package descriptions, as complete words, and in filenames, as any substring, and outputs bug-reporting and other information for the package selected from the results.

The search is equivalent to "tlmgr search --word --file" search-string. Thus, search-string is interpreted as a (Perl) regular expression.

check [opción...] [depends|executes|files|runfiles|texmfdbs|all]

Ejecuta una (o todas) las comprobaciones de consistencia de la instalación. Si no se encuentran problemas, no habrá ninguna salida. (Para ver qué se está haciendo, ejecuta "tlmgr -v check".)

depends
Enumera los paquetes que aparecen como dependencias en una colección instalada, pero que no están instalados, y aquellos paquetes que no están contenidos en ninguna colección.

Si llamas a "tlmgr check collections", esta prueba se llevará a cabo en su lugar, ya que las versiones anteriores de "tlmgr" la llamaban de esa manera.

executes
Comprueba que los archivos a los que se refieren las directivas "execute" en la Base de Datos de TeX Live estén presentes.
files
Comprueba que todos los archivos listados en la TLPDB local ("texlive.tlpdb") estén realmente presentes, y enumera los que faltan.
runfiles
Enumera los nombres de archivo que aparecen más de una vez en las secciones runfiles, excepto los duplicados conocidos.
texmfdbs
Comprobaciones relacionadas con los archivos "ls-R". Si has definido nuevos árboles o has cambiado las variables "TEXMF" o "TEXMFDBS", no está de más ejecutar esto. Comprueba que:
- todos los elementos en "TEXMFDBS" tengan el prefijo "!!".
- todos los elementos en "TEXMFBDS" tengan un archivo "ls-R" (si existen en absoluto).
- todos los elementos en "TEXMF" con "!!" estén listados en "TEXMFDBS".
- todos los elementos en "TEXMF" con un archivo "ls-R" estén listados en "TEXMFDBS".

Opciones:

--use-svn
Utiliza la salida de "svn status" en lugar de listar los archivos; para comprobar el repositorio de desarrollo de TL. (Esto se ejecuta semanalmente).

conf

conf [texmf|tlmgr|updmap [--conffile archivo] [--delete] [clave [valor]]]
conf auxtrees [--conffile archivo] [show|add|remove] [valor]
Con solo "conf", muestra información general de configuración para TeX Live, incluyendo archivos de configuración activos, configuración de rutas y más. Esto es como ejecutar "texconfig conf", pero funciona en todas las plataformas soportadas.

Con uno de "conf texmf", "conf tlmgr", o "conf updmap", muestra todos los pares clave/valor (es decir, todas las configuraciones) guardados en "ROOT/texmf.cnf", el archivo de configuración específico del usuario para "tlmgr" (ver más abajo), o el primer archivo "updmap.cfg" encontrado (mediante "kpsewhich"), respectivamente.

Si se proporciona la clave adicionalmente, muestra solo el valor de esa clave en el archivo respectivo. Si también se proporciona la opción --delete, el valor en el archivo de configuración dado se elimina por completo (no solo se comenta).

Si se proporciona el valor adicionalmente, la clave se establece en valor en el archivo respectivo. ¡No se realiza ninguna verificación de errores!

El valor "PATH" mostrado por "conf" es el utilizado por "tlmgr". El directorio en el que se encuentra el ejecutable "tlmgr" se antepone automáticamente al valor PATH heredado del entorno.

Aquí hay un ejemplo práctico para cambiar valores de configuración. Si la ejecución de (algunos o todos) los comandos del sistema mediante "\write18" se dejó habilitada durante la instalación, puedes deshabilitarla después:

tlmgr conf texmf shell_escape 0

El subcomando "auxtrees" permite agregar y eliminar árboles texmf adicionales arbitrarios, completamente bajo control del usuario. "auxtrees show" muestra la lista de árboles adicionales, "auxtrees add" árbol agrega un árbol a la lista, y "auxtrees remove" árbol elimina un árbol de la lista (si está presente). Los árboles no deben contener un archivo "ls-R" (o los archivos no se encontrarán si el "ls-R" se vuelve obsoleto). Esto funciona manipulando la variable Kpathsea "TEXMFAUXTREES", en (por defecto) "ROOT/texmf.cnf". Ejemplo:

tlmgr conf auxtrees add /quick/test/tree
tlmgr conf auxtrees remove /quick/test/tree

En todos los casos, el archivo de configuración se puede especificar explícitamente a través de la opción "--conffile" archivo, por ejemplo, si no desea cambiar la configuración a nivel del sistema.

Advertencia: La facilidad general para cambiar los valores de configuración está aquí, pero se desaconseja encarecidamente modificar configuraciones de esta manera. De nuevo, no se realiza ninguna verificación de errores ni en las claves ni en los valores, por lo que es posible cualquier tipo de fallo.

dump-tlpdb [opción...] [--json]

Descarga la TLPDB local o remota completa a la salida estándar, tal cual. La salida es análoga a la salida "--machine-readable"; ver la sección "SALIDA LEGIBLE POR MÁQUINA".

Opciones:

--local
Descarga la TLPDB local.
--remote
Descarga la TLPDB remota.
--json
En lugar de descargar el contenido real, la base de datos se descarga como JSON. Para el formato de la salida JSON, consulta "tlpkg/doc/json-formats.txt", definición de formato "TLPDB".

Se debe proporcionar exactamente una de las opciones "--local" o "--remote".

En cualquier caso, la primera línea de la salida especifica la ubicación del repositorio, en este formato:

"url-ubicacion" "\t" ubicacion

donde "url-ubicacion" es el nombre literal del campo, seguido de una tabulación, y ubicacion es el archivo o URL del repositorio.

Los finales de línea pueden ser LF o CRLF dependiendo de la plataforma actual.

generate

generate [opción...] language
generate [opción...] language.dat
generate [opción...] language.def
generate [opción...] language.dat.lua

La acción "generate" sobrescribe cualquier cambio manual realizado en los archivos respectivos: los recrea desde cero basándose en la información de los paquetes instalados, más adaptaciones locales. El instalador de TeX Live y "tlmgr" llaman rutinariamente a "generate" para todos estos archivos.

Para gestionar tus propias fuentes, por favor lee la información de "updmap --help" y/o https://tug.org/fonts/fontinstall.html.

Para gestionar tus propios formatos, por favor lee la información de "fmtutil --help".

En más detalle: "generate" rehace cualquiera de los archivos de configuración "language.dat", "language.def" y "language.dat.lua" a partir de la información presente en la TLPDB local, más los archivos mantenidos localmente.

Los archivos mantenidos localmente son "language-local.dat", "language-local.def", o "language-local.dat.lua", buscados en "TEXMFLOCAL" en los directorios respectivos. Si hay adiciones locales presentes, el archivo final se crea comenzando con el archivo principal, omitiendo cualquier entrada que el archivo local especifique que se deshabilite, y finalmente agregando el archivo local.

(Nota histórica: Los archivos anteriormente soportados "updmap-local.cfg" y "fmtutil-local.cnf" ya no se leen, ya que "updmap" y "fmtutil" ahora leen y soportan múltiples archivos de configuración. Por lo tanto, las adiciones locales pueden y deben colocarse en un archivo "updmap.cfg" o "fmtutil.cnf" en "TEXMFLOCAL". Las acciones "generate updmap" y "generate fmtutil" ya no existen.)

Si hay actualizaciones para el propio "tlmgr" (u otras partes de la infraestructura básica), "tlmgr" se detendrá y no realizará la instalación a menos que se proporcione esta opción. No se recomienda.

Reinstala un paquete (incluyendo dependencias para colecciones) incluso si parece estar ya instalado (es decir, está presente en la TLPDB). Esto es útil para recuperarse de la eliminación accidental de archivos en la jerarquía.

option

La primera forma, "show", muestra la configuración global de TeX Live actualmente guardada en la TLPDB con una breve descripción y la "key" utilizada para cambiarla entre paréntesis.

La segunda forma, "showall", es similar, pero también muestra opciones que se pueden definir pero que actualmente no tienen ningún valor ("help" es un sinónimo).

Ambas formas "show..." toman una opción "--json", que vuelca la información de la opción en formato JSON. En este caso, ambas formas vuelcan los mismos datos. Para el formato de la salida JSON, consulta "tlpkg/doc/json-formats.txt", definición de formato "TLOPTION".

En la tercera forma, con key, si no se proporciona value, se muestra la configuración para key. Si value está presente, key se establece en value.

Los valores posibles para key son (ejecuta "tlmgr option showall" para la lista definitiva):

repository (repositorio de paquetes por defecto),
formats    (generar formatos al instalar o actualizar),
postcode   (ejecutar blobs de código postinstalación)
docfiles   (instalar archivos de documentación),
srcfiles   (instalar archivos fuente),
backupdir  (directorio por defecto para copias de seguridad),
autobackup (número de copias de seguridad a conservar).
sys_bin    (directorio al que se enlazan los ejecutables mediante la acción path)
sys_man    (directorio al que se enlazan las páginas man mediante la acción path)
sys_info   (directorio al que se enlazan los archivos Info mediante la acción path)
desktop_integration (solo Windows: crear accesos directos en el menú Inicio)
fileassocs (solo Windows: cambiar asociaciones de archivos)
multiuser  (solo Windows: instalar para todos los usuarios)

Un uso común de "option" es cambiar permanentemente la instalación para obtener futuras actualizaciones de Internet, después de haber instalado originalmente desde DVD. Para hacer esto, puedes ejecutar

tlmgr option repository https://mirror.ctan.org/systems/texlive/tlnet

La documentación de "install-tl" tiene más información sobre los posibles valores para "repository". (Para compatibilidad con versiones anteriores, "location" se puede usar como sinónimo de "repository".)

Si "formats" está establecido (este es el valor por defecto), entonces los formatos se regeneran cuando el motor o los archivos de formato han cambiado. Deshabilita esto solo cuando sepas cómo y quieras regenerar los formatos tú mismo cuando sea necesario (lo cual es frecuente, en la práctica).

La opción "postcode" controla la ejecución de código de acción postinstalación por paquete. Está establecida por defecto, y de nuevo, deshabilitarla no es probable que interese excepto a los desarrolladores que estén depurando.

Las opciones "docfiles" y "srcfiles" controlan la instalación de sus respectivos grupos de archivos (documentación, fuentes; la agrupación es aproximada) por paquete. Por defecto, ambos están habilitados (1). Uno o ambos pueden ser deshabilitados (establecidos a 0) si el espacio en disco es limitado o para instalaciones mínimas de prueba, etc. Cuando están deshabilitados, los respectivos archivos no se descargan en absoluto.

Las opciones "autobackup" y "backupdir" determinan los valores por defecto para las acciones "update", "backup" y "restore". Estas tres acciones necesitan un directorio en el que leer o escribir las copias de seguridad. Si "--backupdir" no se especifica en la línea de comandos, se usa el valor de la opción "backupdir" (si está establecido). El instalador de TL establece "backupdir" a ".../tlpkg/backups", bajo el directorio de instalación raíz de TL.

La opción "autobackup" (des)activa la generación automática de copias de seguridad. Su valor es un entero. Si el valor de "autobackup" es -1, no se eliminan copias de seguridad. Si "autobackup" es 0 o más, especifica el número de copias de seguridad a conservar. Por lo tanto, las copias de seguridad se deshabilitan si el valor es 0. En el modo "--clean" de la acción "backup", esta opción también especifica el número a conservar. El valor por defecto es 1, de modo que se realizan copias de seguridad, pero solo se conserva una copia.

Para configurar "autobackup" a -1 en la línea de comandos, usa:

tlmgr option -- autobackup -1

El "--" evita que el -1 se trate como una opción. (El "--" detiene el análisis de opciones en el punto en que aparece; esta es una característica general en la mayoría de los programas Unix.)

Las opciones "sys_bin", "sys_man" y "sys_info" se utilizan en sistemas Unix para controlar la generación de enlaces para ejecutables, archivos Info y páginas man. Consulta la acción "path" para más detalles.

Las últimas tres opciones afectan el comportamiento en instalaciones de Windows. Si "desktop_integration" está establecido, entonces algunos paquetes instalarán elementos en una subcarpeta del menú Inicio para "tlmgr gui", documentación, etc. Si "fileassocs" está establecido, se crearán asociaciones de archivos de Windows (ver también la acción "postaction"). Finalmente, si "multiuser" está establecido, entonces los cambios en el registro y en los menús se realizarán para todos los usuarios del sistema en lugar de solo para el usuario actual. Las tres opciones están activadas por defecto.

update [opción...] [pkg...]

Actualiza los paquetes dados como argumentos a la última versión disponible en la fuente de instalación. Se debe especificar "--all" o al menos un nombre de pkg. Opciones:

--all
Actualiza todos los paquetes instalados excepto "tlmgr". Si hay actualizaciones para "tlmgr", esto genera un error, a menos que también se proporcione la opción "--force" o "--self". (Ver abajo).

Además de actualizar los paquetes instalados, durante la actualización de una colección, la instalación local se (por defecto) sincroniza con el estado de la colección en el servidor, tanto para adiciones como para eliminaciones.

Esto significa que si un paquete ha sido eliminado en el servidor (y por lo tanto también ha sido eliminado de la colección respectiva), "tlmgr" eliminará el paquete en la instalación local. Esto se llama "auto-remove" y se anuncia como tal al usar la opción "--list". Esta eliminación automática se puede suprimir usando la opción "--no-auto-remove" (no recomendado, ver descripción de la opción).

Análogamente, si un paquete ha sido agregado a una colección en el servidor que también está instalada localmente, se agregará a la instalación local. Esto se llama "auto-install" y se anuncia como tal al usar la opción "--list". Esta instalación automática se puede suprimir usando la opción "--no-auto-install" (tampoco recomendado).

Una excepción a las comprobaciones de dependencias de la colección (incluida la instalación automática de paquetes mencionada justo ahora) son aquellas que han sido "forzosamente eliminadas" por usted, es decir, que usted llamó a "tlmgr remove --force" sobre ellas. (Ver la documentación de la acción "remove"). Para reinstalar cualquiera de estos paquetes forzosamente eliminados, use "--reinstall-forcibly-removed".

Para reiterar: las eliminaciones y adiciones automáticas están completamente determinadas por la comparación de colecciones. Por lo tanto, si usted instala manualmente un paquete individual "foo" que posteriormente se elimina del servidor, "tlmgr" no lo notará y no lo eliminará localmente. (Tiene que ser así, sin trabajos importantes de rearquitectura, ya que la tlpdb no registra el repositorio de donde provienen los paquetes).

Si desea excluir algunos paquetes de la ejecución de actualización actual (por ejemplo, debido a un enlace lento), vea la opción "--exclude" abajo.

--self
Actualiza "tlmgr" (es decir, los paquetes de infraestructura) si hay actualizaciones para él. En Windows esto incluye actualizaciones al intérprete Perl privado distribuido dentro de TeX Live.

Si se proporciona esta opción junto con "--all" o una lista de paquetes, entonces "tlmgr" se actualizará primero y, si esta actualización tiene éxito, la nueva versión se reiniciará para completar el resto de las actualizaciones.

En resumen:

tlmgr update --self        # actualizar solo la infraestructura
tlmgr update --self --all  # actualizar la infraestructura y todos los paquetes
tlmgr update --force --all # actualizar todos los paquetes pero *no* la infraestructura
                           # ... ¡este último bajo su propio riesgo, no recomendado!
--dry-run
En realidad no se instala nada; en su lugar, las acciones a realizar se escriben en la terminal. Este es un informe más detallado que "--list".
--list [pkg]
Enumera de forma concisa los paquetes que se actualizarían, se instalarían o se eliminarían, sin cambiar nada realmente. Si también se proporciona "--all", se enumeran todas las actualizaciones disponibles. Si se proporciona "--self", pero no "--all", solo se enumeran las actualizaciones de los paquetes críticos (tlmgr, infraestructura de texlive, perl en Windows, etc.). Si no se proporciona ni "--all" ni "--self", y además no se proporciona ningún pkg, entonces se asume "--all" (por lo tanto, "tlmgr update --list" es lo mismo que "tlmgr update --list --all"). Si no se proporciona ni "--all" ni "--self", pero se proporcionan nombres de paquetes específicos, se comprueban las actualizaciones de esos paquetes.
--exclude pkg
Excluye pkg del proceso de actualización. Si esta opción se proporciona más de una vez, sus argumentos se acumulan.

Un argumento pkg excluye tanto el paquete pkg en sí como todos sus paquetes relacionados específicos de la plataforma pkg.ARCH. Por ejemplo,

tlmgr update --all --exclude a2ping

no actualizará "a2ping", "a2ping.i386-linux", ni ningún otro paquete "a2ping."ARCH.

Si esta opción especifica un paquete que de otra manera sería candidato para instalación automática, eliminación automática o reinstalación de un paquete forzosamente eliminado, "tlmgr" saldrá con un mensaje de error. Las exclusiones no son compatibles en estas circunstancias.

Esta opción también se puede configurar de forma permanente en el archivo de configuración de tlmgr con la clave "update-exclude".

--no-auto-remove [pkg...]
Por defecto, "tlmgr" intenta eliminar paquetes en una colección existente que han desaparecido en el servidor, como se describe anteriormente bajo "--all". Esta opción evita tales eliminaciones, ya sea para todos los paquetes (con "--all"), o solo para los nombres de pkg dados. Esto puede llevar a una instalación de TeX inconsistente, ya que los autores con frecuencia renombran o reemplazan los paquetes. Por lo tanto, no se recomienda.
--no-auto-install [pkg...]
En circunstancias normales, "tlmgr" instalará paquetes que son nuevos en el servidor, como se describe anteriormente bajo "--all". Esta opción evita cualquier instalación automática, ya sea para todos los paquetes (con "--all"), o los nombres de pkg dados.

Además, después de que termine la ejecución de "tlmgr" usando esto, los paquetes que se habrían instalado automáticamente *se considerarán* como *forzosamente eliminados*. Así, si "foobar" es el único paquete nuevo en el servidor, entonces

tlmgr update --all --no-auto-install

es equivalente a

tlmgr update --all
tlmgr remove --force foobar

De nuevo, dado que los paquetes a veces se renombran o reemplazan, el uso de esta opción no se recomienda.

--reinstall-forcibly-removed
En circunstancias normales, "tlmgr" no instalará paquetes que han sido forzosamente eliminados por el usuario; es decir, eliminados con "remove --force", o cuya instalación fue prohibida por "--no-auto-install" durante una actualización anterior.

Esta opción hace que "tlmgr" ignore las eliminaciones forzosas y reinstale todos esos paquetes. Esto se puede usar para sincronizar completamente una instalación con la idea que tiene el servidor de lo que está disponible:

tlmgr update --reinstall-forcibly-removed --all
--backup
--backupdir directorio
Estas dos opciones controlan la creación de copias de seguridad de los paquetes *antes* de actualizar; es decir, haciendo copias de seguridad de los paquetes tal como están instalados actualmente. Si no se proporciona ninguna de las opciones, no se realizará ninguna copia de seguridad. Si se proporciona "--backupdir" y especifica un directorio escribible, se realizará una copia de seguridad en esa ubicación. Si solo se proporciona "--backup", se realizará una copia de seguridad en el directorio previamente establecido mediante la acción "option" (ver abajo). Si se proporcionan ambas, se realizará una copia de seguridad en el directorio especificado.

También puede establecer opciones mediante la acción "option" para hacer automáticamente copias de seguridad de todos los paquetes y/o conservar solo un cierto número de copias de seguridad.

"tlmgr" siempre realiza una copia de seguridad temporal al actualizar paquetes, en caso de fallo de descarga u otro fallo durante una actualización. En contraste, el propósito de esta opción "--backup" es guardar una copia de seguridad persistente en caso de que el contenido real de la actualización cause problemas, por ejemplo, introduzca una incompatibilidad de TeX.

La acción "restore" explica cómo restaurar desde una copia de seguridad.

--no-depends
Si solicita la actualización de un paquete normalmente, todos los paquetes dependientes también serán comprobados para actualizaciones y actualizados si es necesario. Este interruptor suprime este comportamiento.
--no-depends-at-all
Ver arriba en install (y cuidado).
--force
Fuerza la actualización de paquetes normales, sin actualizar "tlmgr" (a menos que también se proporcione la opción "--self"). No recomendado.

Además, "update --list" se realiza de todos modos independientemente de esta opción.

/dl>

Si el paquete en el servidor es más antiguo que el paquete ya instalado (por ejemplo, si el espejo seleccionado está desactualizado), "tlmgr" no realiza la degradación. Además, los paquetes para plataformas desinstaladas no se instalan.

"tlmgr" guarda una copia del archivo principal "texlive.tlpdb" utilizado para una actualización con un sufijo que representa la URL del repositorio, como en "tlpkg/texlive.tlpdb.main."cadena-hash-larga. Por lo tanto, incluso cuando se utilizan muchos espejos, solo se conserva una copia de seguridad principal de "tlpdb". Para repositorios que no son principales, que generalmente no tienen muchos espejos, no se realiza ninguna poda de copias de seguridad.

Esta acción no agrega ni elimina automáticamente nuevos enlaces simbólicos en los directorios del sistema; debe ejecutar "tlmgr" "path" usted mismo si está utilizando esta función y desea que se agreguen nuevos enlaces simbólicos.

ARCHIVO DE CONFIGURACIÓN PARA TLMGR

"tlmgr" lee dos archivos de configuración: uno es a nivel de sistema, en "TEXMFSYSCONFIG/tlmgr/config", y el otro es específico del usuario, en "TEXMFCONFIG/tlmgr/config". El específico del usuario es el predeterminado para la acción "conf tlmgr". (Ejecute "kpsewhich -var-value=TEXMFSYSCONFIG" o "... TEXMFCONFIG ..." para ver los nombres reales de los directorios).

Algunos valores predeterminados correspondientes a las opciones de la línea de comandos se pueden establecer en estos archivos de configuración. Además, el archivo a nivel de sistema puede contener una directiva para restringir las acciones permitidas.

En estos archivos de configuración, las líneas vacías y las líneas que comienzan con # se ignoran. Todas las demás líneas deben tener el siguiente formato:

clave = valor

donde los espacios son opcionales pero el "=" es obligatorio.

Las claves permitidas son:

"auto-remove =" 0 o 1 (predeterminado 1), igual que la opción de la línea de comandos.
"gui-expertmode =" 0 o 1 (predeterminado 1). Esto cambia entre la interfaz gráfica completa y una interfaz gráfica simplificada con solo la configuración más común.
"gui-lang =" llcode, con un valor de código de idioma como con la opción de la línea de comandos.
"no-checksums =" 0 o 1 (predeterminado 0, ver abajo).
"persistent-downloads =" 0 o 1 (predeterminado 1), igual que la opción de la línea de comandos.
"require-verification =" 0 o 1 (predeterminado 0), igual que la opción de la línea de comandos.
"tkfontscale =" número de punto flotante (predeterminado 1.0); factor de escala para fuentes en las interfaces basadas en Tk.
"update-exclude =" lista de paquetes separada por comas (sin espacios permitidos). Igual que la opción de la línea de comandos "--exclude" para la acción "update".
"verify-downloads =" 0 o 1 (predeterminado 1), igual que la opción de la línea de comandos.

El archivo de configuración a nivel de sistema puede contener una clave adicional:

"allowed-actions =" acción1[,acción2,...] El valor es una lista separada por comas (sin espacios) de acciones de "tlmgr" que se permiten ejecutar cuando se invoca "tlmgr" en modo de sistema (es decir, sin "--usermode"). Esto permite a los distribuidores incluir "tlmgr" en sus paquetes, pero permitir solo un conjunto restringido de acciones que no interfieran con su gestor de paquetes de distribución. Para instalaciones nativas de TeX Live, no tiene sentido establecer esto.

Finalmente, la clave "no-checksums" necesita más explicación. Por defecto, las sumas de verificación de paquetes calculadas y almacenadas en el servidor (en el TLPDB) se comparan con las sumas de verificación calculadas localmente después de la descarga. "no-checksums" deshabilita este proceso. El algoritmo de suma de verificación es SHA-512. Su sistema debe tener uno de (buscado en este orden) el módulo Perl "Digest::SHA", el programa "openssl" (https://openssl.org), el programa "sha512sum" (de GNU Coreutils, https://www.gnu.org/software/coreutils), o finalmente el programa "shasum" (solo para admitir Macs antiguos). Si ninguno de estos está disponible, se emite una advertencia y "tlmgr" procede sin verificar las sumas de verificación. "no-checksums" evita la advertencia. (Por cierto, otras implementaciones de SHA, como los módulos puros de Perl y Lua, son demasiado lentas para ser utilizables en nuestro contexto).

VERIFICACIÓN CRIPTOGRÁFICA

"tlmgr" e "install-tl" realizan verificación criptográfica si es posible. Si se realiza la verificación y tiene éxito, los programas informan "(verified)" después de cargar el TLPDB; de lo contrario, informan "(not verified)". Pero en cualquier caso, por defecto la instalación y/o las actualizaciones proceden normalmente.

Si un programa llamado "gpg" está disponible (es decir, se encuentra en "PATH"), por defecto se verificarán las firmas criptográficas: requerimos que el repositorio principal esté firmado, pero no repositorios adicionales. Si "gpg" no está disponible, por defecto no se verifican las firmas y no se realiza ninguna verificación, pero "tlmgr" aún procede normalmente.

El comportamiento de la verificación se puede controlar mediante la línea de comandos y la opción del archivo de configuración "verify-repo", que toma uno de los siguientes valores: "none", "main" o "all". Con "none", no se intenta ninguna verificación. Con "main" (el valor predeterminado) la verificación solo se requiere para el repositorio principal, y solo si "gpg" está disponible; aunque se intente para todos, las firmas faltantes de repositorios subsidiarios no resultarán en un error. Finalmente, en el caso de "all", "gpg" debe estar disponible y todos los repositorios deben estar firmados.

En todos los casos, si se verifica una firma y falla la verificación, se genera un error.

La verificación criptográfica requiere que la verificación de sumas de verificación (descrita justo arriba) tenga éxito, y un programa GnuPG funcional ("gpg") (ver más abajo para el método de búsqueda). Luego, a menos que la verificación criptográfica se haya deshabilitado, se descarga un archivo de firma ("texlive.tlpdb.*.asc") del archivo de sumas de verificación y se verifica la firma. La firma es creada por la clave GPG de distribución de TeX Live 0x0D5E5D9106BAB6BC, que a su vez está firmada por la clave de Karl Berry 0x0716748A30D155AD y la clave de Norbert Preining 0x6CACA448860CDC13. Todas estas claves se pueden obtener de los servidores de claves estándar.

Se pueden agregar claves de confianza adicionales usando la acción "key".

Configuración de la invocación de GnuPG

El ejecutable utilizado para GnuPG se busca de la siguiente manera: Si la variable de entorno "TL_GNUPG" está establecida, se prueba y se utiliza; de lo contrario, se comprueba "gpg"; finalmente, se comprueba "gpg2".

Se puede realizar una adaptación adicional de la invocación de "gpg" utilizando las dos variables de entorno "TL_GNUPGHOME", que se pasa a "gpg" como valor para "--homedir", y "TL_GNUPGARGS", que reemplaza las opciones predeterminadas "--no-secmem-warning --no-permission-warning".

MODO DE USUARIO

"tlmgr" proporciona una forma restringida, llamada "modo de usuario", para administrar árboles texmf arbitrarios de la misma manera que la instalación principal. Por ejemplo, esto permite a las personas sin permisos de escritura en la ubicación de instalación actualizar/instalar paquetes en su propio árbol.

"tlmgr" se cambia al modo de usuario con la opción de línea de comandos "--usermode". No se cambia automáticamente, ni existe ninguna configuración de archivo para ello. Por lo tanto, esta opción debe proporcionarse explícitamente cada vez que se desee activar el modo de usuario.

Algunas acciones de "tlmgr" no necesitan permisos de escritura y, por lo tanto, funcionan igual en modo de usuario y en modo normal. Actualmente, estos son: "check", "help", "list", "print-platform", "print-platform-info", "search", "show", "version".

Seleccionar paquetes que coincidan con un patrón específico. Por defecto, esto busca en descripciones y nombres de archivo. También puede seleccionar un subconjunto para la búsqueda.

Seleccionar paquetes para aquellos seleccionados, aquellos no seleccionados, o todos. Aquí, «seleccionado» significa que la casilla de verificación al principio de la línea de un paquete está marcada.

Área de lista de paquetes

La segunda área de la pantalla principal lista todos los paquetes instalados. Si se carga un repositorio, aquellos que están disponibles pero no instalados también se listan.

Hacer doble clic en una línea de paquete abre una ventana informativa con más detalles: la descripción larga, archivos incluidos, etc.

Cada línea de la lista de paquetes consta de los siguientes elementos:

Una casilla de verificación
Se utiliza para seleccionar paquetes particulares; algunos de los botones de acción (ver más abajo) funcionan solo en los paquetes seleccionados.
Nombre del paquete
El nombre (identificador) del paquete según se indica en la base de datos.
Revisión local (y versión)
Si el paquete está instalado, se mostrará el número de revisión de TeX Live para el paquete instalado. Si hay una versión de catálogo en la base de datos para este paquete, se mostrará entre paréntesis. Revisión remota (y versión)
Si se ha cargado un repositorio, se muestra la revisión del paquete en el repositorio (si está presente). Al igual que con la columna local, si se proporciona una versión de catálogo, se mostrará. Y también al igual que con la columna local, la versión del catálogo puede estar desactualizada.
Descripción corta
La descripción corta del paquete.

Botones de acción de la pantalla principal

Debajo de la lista de paquetes hay varios botones:

Actualizar todos los instalados
Esto llama a "tlmgr update --all", es decir, intenta actualizar todos los paquetes disponibles. Debajo de este botón hay un interruptor para permitir la reinstalación de paquetes previamente eliminados como parte de esta acción.

Los otros cuatro botones solo funcionan en los paquetes seleccionados, es decir, aquellos en los que la casilla de verificación al principio de la línea del paquete está marcada.

Actualizar
Actualizar solo los paquetes seleccionados.
Instalar
Instalar los paquetes seleccionados; actúa como "tlmgr install", es decir, también instala dependencias. Por lo tanto, instalar una colección instala todos sus paquetes constituyentes.
Eliminar
Elimina los paquetes seleccionados; actúa como "tlmgr remove", es decir, también eliminará las dependencias de las colecciones (pero no las dependencias de los paquetes normales).
Copia de seguridad
Realiza una copia de seguridad de los paquetes seleccionados; actúa como "tlmgr backup". Esta acción requiere que la opción "backupdir" esté configurada (ver "Opciones -" General>).

SALIDA LEGIBLE POR MÁQUINA

Con la opción "--machine-readable", "tlmgr" escribe en stdout en el formato fijo orientado a líneas descrito aquí, y los mensajes informativos habituales para el consumo humano se escriben en stderr (normalmente se escriben en stdout). La idea es que un programa pueda obtener toda la información que necesita leyendo stdout.

Actualmente, esta opción solo se aplica a las acciones de actualización, instalación y «opción».

Salida legible por máquina para «actualizar» e «instalar»

El formato de salida es el siguiente:

fieldname "\t" value
...
"end-of-header"
pkgname status localrev serverrev size runtime esttot
...
"end-of-updates"
otra salida de acciones post-instalación, no en formato legible por máquina

La sección de encabezado tiene actualmente dos campos: "location-url" (la fuente del repositorio de la que se obtienen las actualizaciones) y "total-bytes" (el número total de bytes a descargar).

Los campos localrev y serverrev para cada paquete son los números de revisión en la instalación local y en el repositorio del servidor, respectivamente. El campo size es el número de bytes a descargar, es decir, el tamaño del archivo tar comprimido para una instalación de red, no el tamaño desempaquetado. Los campos runtime y esttot solo están presentes para paquetes actualizados e instalados automáticamente, y contienen el tiempo transcurrido desde el inicio de la instalación/actualizaciones y el tiempo total estimado.

Los finales de línea pueden ser LF o CRLF dependiendo de la plataforma actual.

"location-url" ubicación
La ubicación puede ser una url (incluida "file:///foo/bar/..."), o un nombre de directorio ("/foo/bar"). Es el repositorio de paquetes del cual se obtuvieron los datos del nuevo paquete.
"total-bytes" cuenta
La cuenta es simplemente un número decimal, la suma de los tamaños de todos los paquetes que necesitan ser actualizados o instalados (que se listan posteriormente).

Luego viene una línea con solo la cadena literal "end-of-header".

Cada línea siguiente hasta una línea con la cadena literal "end-of-updates" informa sobre un paquete. Los campos en cada línea están separados por una tabulación. Aquí están los campos.

nombrepkg
El identificador del paquete TeX Live, con un posible sufijo de plataforma para ejecutables. Por ejemplo, "pdftex" y "pdftex.i386-linux" se dan como dos paquetes separados, uno en cada línea.
estado
Uno de los siguientes: "ok" (sin cambios), "install" (nuevo paquete), "upgrade" (actualización), "remove" (paquete eliminado), "none" (no se necesita acción), "error" (error durante la acción), o "kept" (paquete instalado pero no actualizado porque la configuración lo impide).
revisión local
El número de revisión del paquete instalado localmente. Si el paquete no está instalado, este campo estará vacío.
revisión del servidor
El número de revisión del paquete en el repositorio del servidor. Si el paquete no está disponible en el servidor, este campo estará vacío.
tamaño
El tamaño en bytes del archivo de paquete que se va a descargar (si procede). Para las instalaciones, esto es el tamaño del archivo tar.gz. Para las actualizaciones, es la diferencia de tamaño entre el nuevo y el viejo paquete. Para los paquetes que no se descargan, este campo está vacío.
tiempo de ejecución
El tiempo (en segundos) que ha transcurrido desde el inicio de la operación actual (actualización o instalación) hasta este punto. Este campo solo está presente para paquetes que requieren una acción, y se ignora para las entradas de «ok», «none» y «kept».
tiempo total estimado
El tiempo total estimado (en segundos) para completar toda la operación (actualización o instalación). Este campo solo está presente para los paquetes que requieren una acción, y se ignora para las entradas de «ok», «none» y «kept».

Después de la línea "end-of-updates", puede haber una salida adicional de las acciones post-instalación (como la ejecución de scripts de configuración).

Salida legible por máquina para «opción»

La acción "tlmgr option", cuando se ejecuta con la opción "--machine-readable", genera una salida de una sola línea si tiene éxito, y un mensaje de error en stderr en caso contrario.

El formato de la salida exitosa es:

option value

Por ejemplo, una ejecución de "tlmgr --machine-readable option path" podría producir:

option path /usr/local/texlive/2009/texmf-dist/scripts:/usr/local/texlive/2009/texmf-local/scripts

Y una ejecución de "tlmgr --machine-readable option repository" podría producir:

option repository http://mirror.ctan.org/systems/texlive/tlnet

tlmgr(1) — Arch Linux manual pages

DESCRIPTION

The "tlmgr" is a TeX Live Package Manager.

It is used to install, update, and remove TeX Live packages. It can also be used to query the status of packages, to manage different TeX Live repositories, and to perform other package management tasks.

COMMAND LINE OPTIONS

Options can be given in any order.

-h, --help
Show a help message and exit.
-v, --version
Show version information and exit.
--quiet
Suppress informational output. Only show warnings and errors.
--verbose
Show verbose output. This is useful for debugging.
--show-path
Show the paths used by TeX Live, and exit.
-c, --conffile FILE
Use configuration file FILE. Default is "~/texmf/texlive/tlmgr/texlive.conf".
-d, --debug LEVEL
Set debug level to LEVEL. Higher levels mean more output.
-e, --showerror
Show detailed error messages. This is useful for debugging.
--use-engine ENGINE
Use ENGINE for compiling TeX files. Default is "pdflatex".
--tex-defines OPTS
Pass OPTS to the TeX compiler. Default is empty.
--latex-defines OPTS
Pass OPTS to the LaTeX compiler. Default is empty.
--bibtex-defines OPTS
Pass OPTS to the BibTeX compiler. Default is empty.
--makeindex-defines OPTS
Pass OPTS to the MakeIndex program. Default is empty.
--git-defines OPTS
Pass OPTS to the git command. Default is empty.

ACTIONS

The following actions can be performed:

install PACKAGE
Install the specified package. If the package is already installed, it will be updated if a newer version is available.
update PACKAGE
Update the specified package. If the package is not installed, it will be installed.
remove PACKAGE
Remove the specified package. If other packages depend on this package, they will also be removed unless the --force option is given.
search KEYWORD
Search for packages matching the given keyword. The search is performed on package names and descriptions.
list
List all installed packages.
show PACKAGE
Show information about the specified package.
configure PACKAGE
Configure the specified package. This is usually done automatically when the package is installed or updated.
reconfigure PACKAGE
Reconfigure the specified package. This is useful if the configuration has been corrupted.
zip
Create a zip archive of the installed packages. This is useful for backup purposes.
unzip FILE
Unzip a previously created zip archive. This will install or update the packages contained in the archive.
backup
Create a backup of the installed packages. This is equivalent to zip.
restore FILE
Restore the installed packages from a backup archive. This is equivalent to unzip.
options
Show the current options of "tlmgr".
option NAME VALUE
Set the option NAME to VALUE.
conf
Show the configuration of "tlmgr".

CONFIGURATION FILE FOR TLMGR

The configuration file for "tlmgr" is usually located at "~/texmf/texlive/tlmgr/texlive.conf". It can be used to set various options, such as the preferred download method, the proxy server, and the installation directory.

The format of the configuration file is:

NAME=VALUE

For example:

TEXLIVE_DOWNLOADER=curl
HTTPS_PROXY=http://proxy.example.com:8080
TEXLIVE_INSTALL_PREFIX=/usr/local/texlive/2023

The available options are:

"TEXLIVE_DOWNLOADER"
Specifies the download program to use. Possible values are "lwp", "curl", "wget".
"TEXLIVE_COMPRESSOR"
Specifies the compression program to use. Possible values are "lz4", "gzip", "xz".
"HTTPS_PROXY"
Specifies the proxy server to use for HTTPS connections.
"HTTP_PROXY"
Specifies the proxy server to use for HTTP connections.
"TEXLIVE_INSTALL_PREFIX"
Specifies the installation directory for TeX Live.
"TEXLIVE_TLDonateLink"
URL for donations. Default is "https://tug.org/texlive/donate.html".
"TEXLIVE_AUTHFILE"
Path to the authentication file for proxy authentication.
"TEXLIVE_AUTHFILE_PASSWORD"
Password for proxy authentication.
"TEXLIVE_NO_VERIFY_HTTPS"
Set to 1 to disable HTTPS certificate verification. Use with caution.
"TEXLIVE_PREFER_OWN"
Set to 1 to prefer TeX Live's own binaries over system binaries. See below.

CRYPTOGRAPHIC VERIFICATION

When downloading packages, "tlmgr" verifies the cryptographic signatures of the downloaded files to ensure their integrity and authenticity. This is done using the public keys that are distributed with TeX Live.

The public keys are stored in the file "texmf-dist/texlive/webhooks/keys.txt". This file is updated automatically when you update TeX Live.

If you encounter problems with cryptographic verification, make sure that you have the latest version of TeX Live installed.

USER MODE

By default, "tlmgr" operates in system-wide mode, requiring root privileges to install or modify packages. However, it can also be used in user mode, allowing ordinary users to install and manage packages in their home directories without needing root privileges.

To enable user mode, you need to set the environment variable "TEXLIVE_USERMODE" to 1. For example:

export TEXLIVE_USERMODE=1
tlmgr install somepackage

In user mode, packages are installed in a directory specified by the "TEXLIVE_INSTALL_PREFIX" environment variable or "~/texmf" by default. If "TEXLIVE_INSTALL_PREFIX" is not set, "tlmgr" will attempt to create a "texmf" directory in your home directory.

MULTIPLE REPOSITORIES

"tlmgr" supports multiple repositories, allowing you to install packages from different sources. This is useful if you need to install packages that are not available in the default repository, or if you want to use a specific mirror.

You can manage repositories using the following commands:

repository list
List all configured repositories.
repository add NAME URL
Add a new repository with the given name and URL.
repository remove NAME
Remove the repository with the given name.
repository set-priority NAME PRIORITY
Set the priority of the repository with the given name.

When installing or updating packages, "tlmgr" will search for the package in the repositories in order of priority. If the package is found in multiple repositories, the one with the highest priority will be used.

GUI FOR TLMGR

A graphical user interface (GUI) for "tlmgr" is available. It can be launched by running the command "texlive-gui" (or similar, depending on your distribution).

The GUI provides a more user-friendly way to manage TeX Live packages, allowing you to search, install, update, and remove packages with a few clicks.

Note that the GUI may not be available on all systems, and its functionality may vary.

MACHINE-READABLE OUTPUT

Some "tlmgr" commands produce machine-readable output. This output is intended for use by other programs and scripts.

The output format is generally:

key: value

Or, for lists:

key1: value1
key2: value2
...

For example, the command tlmgr show --data <package> produces output like this:

name: tex
version: 2023
revision: 67008

The tlmgr --quiet --machine-readable command can be used to produce output suitable for scripting.

status
The status of the package update. One character, as follows:
"d"
The package was removed on the server.
"f"
The package was removed in the local installation, even though a collection depended on it. (E.g., the user ran "tlmgr remove --force".)
"u"
Normal update is needed.
"r"
Reversed non-update: the locally-installed version is newer than the version on the server.
"a"
Automatically-determined need for installation, the package is new on the server and is (most probably) part of an installed collection.
"i"
Package will be installed and isn't present in the local installation (action install).
"I"
Package is already present but will be reinstalled (action install).
localrev
The revision number of the installed package, or "-" if it is not present locally.
serverrev
The revision number of the package on the server, or "-" if it is not present on the server.
size
The size in bytes of the package on the server. The sum of all the package sizes is given in the "total-bytes" header field mentioned above.
runtime
The run time since start of installations or updates.
esttot
The estimated total time.

The output format is as follows:

key "\t" value

If a value is not saved in the database the string "(not set)" is shown.

If you are developing a program that uses this output, and find that changes would be helpful, do not hesitate to write the mailing list.

ENVIRONMENT VARIABLES

"tlmgr" uses many of the standard TeX environment variables, as reported by, e.g., "tlmgr conf" ("conf").

In addition, for ease in scripting and debugging, "tlmgr" looks for the following environment variables. These are not of interest for normal user installations.

"TEXLIVE_COMPRESSOR"
This variable allows selecting a different compressor program for backups and intermediate rollback containers. The order of selection is:
1.
If the environment variable "TEXLIVE_COMPRESSOR" is defined, use it; abort if it doesn't work. Possible values: "lz4", "gzip", "xz". The necessary options are added internally.
2.
If lz4 is available (either from the system or TL) and working, use that.
3.
If gzip is available (from the system) and working, use that.
4.
If xz is available (either from the system or TL) and working, use that.

lz4 and gzip are faster in creating tlmgr's local backups, hence they are preferred. The unconditional use of xz for the tlnet containers is unaffected, to minimize download sizes.

"TEXLIVE_DOWNLOADER"
"TL_DOWNLOAD_PROGRAM"
"TL_DOWNLOAD_ARGS"
These options allow selecting different download programs then the ones automatically selected by the installer. The order of selection is:
1.
If the environment variable "TEXLIVE_DOWNLOADER" is defined, use it; abort if the specified program doesn't work. Possible values: "lwp", "curl", "wget". The necessary options are added internally.
2.
If the environment variable "TL_DOWNLOAD_PROGRAM" is defined (can be any value), use it together with "TL_DOWNLOAD_ARGS"; abort if it doesn't work.
3.
If LWP is available and working, use that (by far the most efficient method, as it supports persistent downloads).
4.
If curl is available (from the system) and working, use that.
5.
If wget is available (either from the system or TL) and working, use that.

TL provides "wget" binaries for platforms where necessary, so some download method should always be available.

"TEXLIVE_PREFER_OWN"
By default, compression and download programs provided by the system, i.e., found along "PATH" are preferred over those shipped with TeX Live.

This can create problems with systems that are too old, and so can be overridden by setting the environment variable "TEXLIVE_PREFER_OWN" to 1. In this case, executables shipped with TL will be preferred.

Extra compression/download programs not provided by TL, such as gzip, lwp, and curl, are still checked for on the system and used if available, per the above. "TEXLIVE_PREFER_OWN" only applies when the program being checked for is shipped with TL, namely the lz4 and xz compressors and wget downloader.

Exception: on Windows, the "tar.exe" shipped with TL is always used, regardless of any setting.
