tls_read(3)

Paquete: libretls

Licencias: ISC, BSD, MIT

TLS_READ(3) Manual de funciones de biblioteca TLS_READ(3)

NOMBRE

tls_read, tls_write, tls_handshake, tls_error, tls_close, tls_reset — usar una conexión TLS

SINOPSIS

#include <tls.h>

ssize_t
tls_read(struct tls *ctx, void *buf, size_t buflen);

ssize_t
tls_write(struct tls *ctx, const void *buf, size_t buflen);

int
tls_handshake(struct tls *ctx);

const char *
tls_error(struct tls *ctx);

int
tls_close(struct tls *ctx);

void
tls_reset(struct tls *ctx);

DESCRIPCIÓN

tls_read() lee buflen bytes de datos desde el socket hacia buf. Devuelve la cantidad de datos leídos.

tls_write() escribe buflen bytes de datos desde buf al socket. Devuelve la cantidad de datos escritos.

tls_handshake() realiza explícitamente el handshake TLS. Solo es necesario llamar a esta función si necesita garantizar que el handshake se ha completado, ya que tanto tls_read() como tls_write() realizan automáticamente el handshake TLS cuando es necesario.

La función tls_error() puede usarse para recuperar una cadena que contenga más información sobre el error más reciente relacionado con un contexto.

tls_close() cierra una conexión después de su uso. Solo se cerrará la capa TLS y el llamador es responsable de cerrar los descriptores de archivo, a menos que la conexión se haya establecido utilizando tls_connect(3) o tls_connect_servername(3). Después de cerrar la conexión, ctx puede pasarse a tls_free(3).

VALORES DE RETORNO

tls_read() y tls_write() devuelven un tamaño en caso de éxito o -1 en caso de error.

tls_handshake() y tls_close() devuelven 0 en caso de éxito o -1 en caso de error.

Las funciones tls_read(), tls_write(), tls_handshake() y tls_close() también tienen dos valores de retorno especiales:

TLS_WANT_POLLIN
El descriptor de archivo de lectura subyacente debe estar legible para continuar.
TLS_WANT_POLLOUT
El descriptor de archivo de escritura subyacente debe ser escribible para continuar.

En el caso de descriptores de archivo bloqueantes, la misma llamada a la función debe repetirse inmediatamente. En el caso de descriptores de archivo no bloqueantes, la misma llamada a la función debe repetirse cuando se cumpla la condición requerida.

Los llamadores de estas funciones no pueden confiar en el valor de la variable global errno. Para evitar el manejo incorrecto de las condiciones de error, tls_read(), tls_write(), tls_handshake() y tls_close() limpian explícitamente errno.

tls_error() devuelve NULL si no ocurrió ningún error con ctx durante o desde la última llamada a tls_handshake(), tls_read(), tls_write(), tls_close() o tls_reset() que involucrara a ctx, o si falló la asignación de memoria al intentar ensamblar la cadena que describe el error más reciente relacionado con ctx.

EJEMPLOS

El siguiente ejemplo demuestra cómo manejar escrituras TLS en un descriptor de archivo bloqueante:

...
while (len > 0) {
	ssize_t ret;

	ret = tls_write(ctx, buf, len);
	if (ret == TLS_WANT_POLLIN || ret == TLS_WANT_POLLOUT)
		continue;
	if (ret == -1)
		errx(1, "tls_write: %s", tls_error(ctx));
	buf += ret;
	len -= ret;
}
...

El siguiente ejemplo demuestra cómo manejar escrituras TLS en un descriptor de archivo no bloqueante utilizando poll(2):

...
pfd[0].fd = fd;
pfd[0].events = POLLIN|POLLOUT;
while (len > 0) {
	nready = poll(pfd, 1, 0);
	if (nready == -1)
		err(1, "poll");
	if ((pfd[0].revents & (POLLERR|POLLNVAL)))
		errx(1, "bad fd %d", pfd[0].fd);
	if ((pfd[0].revents & (pfd[0].events|POLLHUP))) {
		ssize_t ret;

		ret = tls_write(ctx, buf, len);
		if (ret == TLS_WANT_POLLIN)
			pfd[0].events = POLLIN;
		else if (ret == TLS_WANT_POLLOUT)
			pfd[0].events = POLLOUT;
		else if (ret == -1)
			errx(1, "tls_write: %s", tls_error(ctx));
		else {
			buf += ret;
			len -= ret;
		}
	}
}
...

VER TAMBIÉN

tls_accept_socket(3), tls_configure(3), tls_conn_version(3), tls_connect(3), tls_init(3), tls_ocsp_process_response(3)

HISTORIA

tls_read(), tls_write(), tls_error(), tls_close() y tls_reset() aparecieron en OpenBSD 5.6 y obtuvieron sus nombres finales en OpenBSD 5.7.

tls_handshake() apareció en OpenBSD 5.9.

ADVERTENCIAS

La función tls_error() devuelve un puntero interno. No debe ser liberado por la aplicación, o se producirá un error de doble liberación. El puntero se invalidará cuando ocurra el siguiente error con ctx. En consecuencia, si la aplicación necesita el mensaje en un momento posterior, debe copiar la cadena antes de llamar a la siguiente función de libtls que involucre a ctx, o es probable que se produzca un fallo de segmentación o un acceso de lectura a datos no deseados.
