tls_init(3)

Paquete: libretls

Licencias: ISC, BSD, MIT

TLS_INIT(3) Manual de funciones de biblioteca TLS_INIT(3)

NOMBRE

tls_init, tls_config_new, tls_config_free, tls_config_error — inicializar la API del cliente y servidor TLS

SINOPSIS

#include <tls.h>

int
tls_init(void);

struct tls_config *
tls_config_new(void);

void
tls_config_free(struct tls_config *config);

const char *
tls_config_error(struct tls_config *config);

DESCRIPCIÓN

Las funciones de la familia tls establecen un canal de comunicación seguro utilizando el protocolo de socket TLS. Se admiten tanto clientes como servidores.

La función tls_init() inicializa las estructuras de datos globales. Ya no es necesario llamar a esta función directamente, ya que se invoca internamente cuando es necesario. Se puede llamar más de una vez y de forma concurrente.

Antes de crear una conexión, se debe crear una configuración. La función tls_config_new() asigna, inicializa y devuelve un nuevo objeto de configuración predeterminado que se puede utilizar para futuras conexiones. Existen varias funciones para cambiar las opciones de configuración; véase tls_config_set_protocols(3), tls_load_file(3), tls_config_ocsp_require_stapling(3) y tls_config_verify(3).

La función tls_config_error() se puede utilizar para recuperar una cadena de texto que contiene más información sobre el error más reciente relacionado con una configuración.

Un objeto de conexión TLS se crea mediante tls_client(3) o tls_server(3) y se configura con tls_configure(3).

Una conexión de cliente se inicia después de la configuración llamando a tls_connect(3). Un servidor puede aceptar una nueva conexión de cliente llamando a tls_accept_socket(3) en una conexión de socket ya establecida.

Se proporcionan dos funciones para entrada y salida, tls_read(3) y tls_write(3). Ambas realizan automáticamente el tls_handshake(3) cuando es necesario.

Las propiedades de las conexiones TLS establecidas se pueden inspeccionar con las funciones descritas en tls_conn_version(3) y tls_ocsp_process_response(3).

Después de su uso, una conexión TLS debe cerrarse con tls_close(3) y luego liberarse llamando a tls_free(3).

Cuando no se van a configurar más contextos, el objeto de configuración debe liberarse llamando a tls_config_free(). Es seguro llamar a tls_config_free() tan pronto como se haya realizado la última llamada a tls_configure(). Si config es NULL, no ocurre nada.

VALORES DE RETORNO

tls_init() devuelve 0 en caso de éxito o -1 en caso de error.

tls_config_new() devuelve NULL en caso de error o de falta de memoria.

tls_config_error() devuelve NULL si no se produjo ningún error con config o si la asignación de memoria falló al intentar compilar la cadena que describe el error más reciente relacionado con config.

VER TAMBIÉN

tls_accept_socket(3), tls_client(3), tls_config_ocsp_require_stapling(3), tls_config_set_protocols(3), tls_config_verify(3), tls_conn_version(3), tls_connect(3), tls_load_file(3), tls_ocsp_process_response(3), tls_read(3)

HISTORIA

La API tls apareció por primera vez en OpenBSD 5.6 como respuesta a los desafíos innecesarios que otras APIs presentaban para poder usarlas de forma segura.

Todas las funciones se renombraron de ressl_*() a tls_*() para OpenBSD 5.7.

tls_config_error() apareció en OpenBSD 6.0.

ADVERTENCIAS

La función tls_config_error() devuelve un puntero interno. No debe ser liberado por la aplicación, o se producirá un error de doble liberación. El puntero se invalidará cuando ocurra el próximo error con config. En consecuencia, si la aplicación puede necesitar el mensaje más tarde, debe copiar la cadena antes de llamar a la siguiente función de libtls que involucre a config, o el resultado probable será un error de segmentación o un acceso de lectura a datos no deseados.
