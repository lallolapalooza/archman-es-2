TAIL(1P) Manual de Programador de POSIX TAIL(1P)

PRÓLOGO

Esta página del manual es parte del Manual de Programador de POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

tail — copia la última parte de un archivo

SINOPSIS

tail [-f] [-c número|-n número] [archivo]

DESCRIPCIÓN

La utilidad tail copiará su archivo de entrada a la salida estándar comenzando desde un lugar designado.

La copia comenzará en el punto del archivo indicado por las opciones -c número o -n número. El argumento de opción número se contará en unidades de líneas o bytes, según las opciones -n y -c. Ambos recuentos, de líneas y bytes, comienzan desde 1.

Las colas relativas al final del archivo pueden guardarse en un búfer interno y, por lo tanto, su longitud puede ser limitada. Dicho búfer, si existe, no será menor a {LINE_MAX}*10 bytes.

OPCIONES

La utilidad tail cumplirá con el volumen de Definiciones Base de POSIX.1‐2017, *Sección 12.2*, *Guías de Sintaxis de Utilidades*, excepto que '+' puede ser reconocido como un delimitador de opciones además de '-'.

Se soportarán las siguientes opciones:

-c número
La aplicación garantizará que el argumento de opción número sea un entero decimal, que incluya opcionalmente un signo. El signo afectará la ubicación en el archivo, medida en bytes, desde donde se iniciará la copia:
Signo La copia comienza + Relativo al principio del archivo. - Relativo al final del archivo. ninguno Relativo al final del archivo.

La aplicación garantizará que si el signo del argumento de opción número es '+', el argumento de opción número sea un entero decimal distinto de cero.

El origen para el recuento será 1; es decir, -c +1 representa el primer byte del archivo, -c -1 el último.

-f
Si el archivo de entrada es un archivo regular o si el operando archivo especifica una FIFO, no terminar después de que se haya copiado la última línea del archivo de entrada, sino leer y copiar bytes adicionales del archivo de entrada cuando estén disponibles. Si no se especifica un operando archivo y la entrada estándar es una tubería o FIFO, la opción -f se ignorará. Si el archivo de entrada no es una FIFO, una tubería o un archivo regular, no está especificado si la opción -f se ignorará o no.
-n número
Esta opción será equivalente a -c número, excepto que la ubicación de inicio en el archivo se medirá en líneas en lugar de bytes. El origen para el recuento será 1; es decir, -n +1 representa la primera línea del archivo, -n -1 la última.

Si no se especifica ni -c ni -n, se asumirá -n 10.

OPERANDOS

Se soportará el siguiente operando:

archivo
Un nombre de ruta de un archivo de entrada. Si no se especifica un operando archivo, se utilizará la entrada estándar.

STDIN

La entrada estándar se utilizará si no se especifica un operando archivo, y se utilizará si el operando archivo es '-' y la implementación trata el '-' como entrada estándar. De lo contrario, la entrada estándar no se utilizará. Consulte la sección ARCHIVOS DE ENTRADA.

ARCHIVOS DE ENTRADA

Si se especifica la opción -c, el archivo de entrada puede contener datos arbitrarios; de lo contrario, el archivo de entrada debe ser un archivo de texto.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de tail:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, *Sección 8.2*, *Variables de Internacionalización* para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de locale).
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la locale para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a multibyte en argumentos y archivos de entrada).
LC_MESSAGES

Determina la locale que debe utilizarse para afectar el formato y contenido de los mensajes de diagnóstico escritos en la salida estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Predeterminado.

STDOUT

La porción designada del archivo de entrada se escribirá en la salida estándar.

STDERR

La salida estándar se utilizará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
Finalización exitosa.
>0
Ocurrió un error.

CONSECUENCIAS DE LOS ERRORES

Predeterminado.

Las siguientes secciones son informativas.

USO PARA APLICACIONES

La opción -c debe usarse con precaución cuando la entrada es un archivo de texto que contiene caracteres multibyte; puede producir una salida que no comience en un límite de caracteres.

Aunque el archivo de entrada para tail puede ser de cualquier tipo, los resultados pueden no ser los esperados en algunos archivos de dispositivos de caracteres especiales o en tipos de archivo no descritos por el volumen de Interfaces del Sistema de POSIX.1‐2017. Dado que este volumen de POSIX.1‐2017 no especifica el tamaño de bloque utilizado al realizar la entrada, tail no necesita leer todos los datos de dispositivos que solo realizan transferencias de bloques.

Al usar tail para procesar nombres de ruta, y la opción -c no se especifica, se recomienda que LC_ALL, o al menos LC_CTYPE y LC_COLLATE, se establezcan en POSIX o C en el entorno, ya que los nombres de ruta pueden contener secuencias de bytes que no forman caracteres válidos en algunas locales, en cuyo caso el comportamiento de la utilidad sería irrelevante.

NAME

tail — write the last part of a file

SYNOPSIS

tail[-F | -f [+flag]] [-c number | -n number] [file]
tail[-F | -f [+flag]] [-c number | -n number] [-file]
tail[-F | -f [+flag]] [-c number | -n number] [-file]
tail[-F | -f [+flag]] [-c number | -n number] [    ]

DESCRIPTION

The tail utility shall write the last 10 lines, by default, to standard output, of the given input file or, by default, from standard input if no file is specified. The number of lines or bytes to write is determined by the options.

The -f option shall not be processed if it is impossible to determine that the file has been extended. For example, if the input file is a pipe and the process is reading from the pipe, -f shall be ignored. If -f is used with a FIFO, it shall not be ignored.

When -f is specified, the utility shall not terminate until the file is closed by the process that opened it or until the process is terminated. If the file specified is not a FIFO or regular file, or if it is a regular file that is not readable, the behavior is unspecified.

If more than one file is specified, the contents of each file shall be preceded by a header indicating the name of the file, consisting of ==> file <==.

The -F option shall behave the same as the -f option, except that it also handles cases where the file is renamed or removed and recreated. It checks the file specified by name periodically. If it determines that the file has been removed, it will continue to monitor until the file is recreated. If it determines that the file has been replaced by a new file of the same name, it shall start to process the new file from the beginning.

OPTIONS

The tail utility shall conform to the Base Definitions volume of POSIX.1‐2017, Section 12.2, Utility Syntax Guidelines.

The following options shall be supported:

-c number
Start writing at the numberth byte from the end of the file. The default behavior is to write the last 10 bytes.
-f
Output appended data as the file grows. This option shall follow the last byte of the file. The utility shall not terminate until the file is closed by the process that opened it or until the process is terminated. The utility shall check the file periodically to see if new data has been appended. The default behavior is to write the last 10 lines.
-F
This option shall be equivalent to -f, but it also handles cases where the file is renamed or removed and recreated. It checks the file specified by name periodically. If it determines that the file has been removed, it will continue to monitor until the file is recreated. If it determines that the file has been replaced by a new file of the same name, it shall start to process the new file from the beginning.
-n number
Start writing at the numberth line from the end of the file. The default behavior is to write the last 10 lines.

The default behavior is equivalent to specifying -n 10.

If both -c and -n are specified, the behavior is unspecified.

The tail utility supports the "number" operand syntax from the Utility Syntax Guidelines for the -c and -n options.

OPERANDS

The following operands shall be supported:

file
A pathname of a file to be processed. If no file operands are specified, the standard input shall be used.

STDIN

If no file operand is specified, the standard input shall be used. The standard input shall be a regular file or a FIFO. The behavior is unspecified if the standard input is a pipe and the -f option is specified.

INPUT FILES

The input files shall be regular files or FIFOs. If a file is not a regular file or FIFO, or if it is a regular file that is not readable, the behavior is unspecified.

ENVIRONMENT VARIABLES

The following environment variables shall be supported:

LANG
Provide default values for the internationalization parameters that would otherwise be set by the corresponding environment variables from any of the categories for locale, messages, and numeric.
LC_ALL
Determine the locale category for any of the following settings that are not explicitly set by the corresponding LC_* environment variable (including unset variables).
LC_CTYPE
Determine the locale for the interpretation of sequences of bytes of UTF-8 characters or byte values. This variable determines the behavior of the -c and -n options.
LC_MESSAGES
Determine the locale that should be used for writing diagnostic and advisory messages that should be affected by locale. The default is the POSIX locale.
NLSPATH
Determine the locations of message catalogs for the processing of LC_MESSAGES.

ASYNCHRONOUS EVENTS

Default signal-handling shall apply. The -f option is intended to be used in conjunction with the SIGWINCH signal in some implementations. However, this is not specified by POSIX.

STDOUT

The last 10 lines or bytes of the file(s) are written to standard output. If more than one file is specified, the output for each file is preceded by a header consisting of:

==> file <==

STDERR

Diagnostic messages shall be written to standard error.

OUTPUT FILES

None.

EXTENDED DESCRIPTION

None.

EXIT STATUS

The following exit values shall be returned:

0
Successful completion.
>0
An error occurred.

CONSEQUENCES OF ERRORS

Upon any error, the utility shall not produce any output. The exit status shall be greater than 0.

APPLICATION USAGE

The -f option is useful for monitoring log files. When used with a file that is being appended to, -f will display new lines as they are added. The -F option provides similar functionality but also allows monitoring files that may be rotated (deleted and recreated).

The behavior of tail with respect to multi-byte characters is dependent on the setting of the LC_CTYPE environment variable. In the POSIX locale, each byte is a valid single-byte character, and therefore this problem is avoided.

EXAMPLES

The -f option can be used to monitor the growth of a file that is being written by some other process. For example, the command:

tail -f fred

prints the last ten lines of the file fred, followed by any lines that are appended to fred between the time tail is initiated and killed. As another example, the command:

tail -f -c 15 fred

prints the last 15 bytes of the file fred, followed by any bytes that are appended to fred between the time tail is initiated and killed.

RATIONALE

This version of tail was created to allow conformance to the Utility Syntax Guidelines. The historical -b option was omitted because of the general non-portability of block-sized units of text. The -c option historically meant ``characters'', but this volume of POSIX.1‐2017 indicates that it means ``bytes''. This was selected to allow reasonable implementations when multi-byte characters are possible; it was not named -b to avoid confusion with the historical -b.

The origin of counting both lines and bytes is 1, matching all widespread historical implementations. Hence tail -n +0 is not conforming usage because it attempts to output line zero; but note that tail -n 0 does conform, and outputs nothing.

Earlier versions of this standard allowed the following forms in the SYNOPSIS:

tail -[number][b|c|l][f] [file]
tail +[number][b|c|l][f] [file]

These forms are no longer specified by POSIX.1‐2008, but may be present in some implementations.

The restriction on the internal buffer is a compromise between the historical System V implementation of 4096 bytes and the BSD 32768 bytes.

The -f option has been implemented as a loop that sleeps for 1 second and copies any bytes that are available. This is sufficient, but if more efficient methods of determining when new data are available are developed, implementations are encouraged to use them.

Historical documentation indicates that tail ignores the -f option if the input file is a pipe (pipe and FIFO on systems that support FIFOs). On BSD-based systems, this has been true; on System V-based systems, this was true when input was taken from standard input, but it did not ignore the -f flag if a FIFO was named as the file operand. Since the -f option is not useful on pipes and all historical implementations ignore -f if no file operand is specified and standard input is a pipe, this volume of POSIX.1‐2017 requires this behavior. However, since the -f option is useful on a FIFO, this volume of POSIX.1‐2017 also requires that if a FIFO is named, the -f option shall not be ignored. Earlier versions of this standard did not state any requirement for the case where no file operand is specified and standard input is a FIFO. The standard has been updated to reflect current practice which is to treat this case the same as a pipe on standard input. Although historical behavior does not ignore the -f option for other file types, this is unspecified so that implementations are allowed to ignore the -f option if it is known that the file cannot be extended.
