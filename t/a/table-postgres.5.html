TABLE_POSTGRESQL(5) Manual de formatos de archivo TABLE_POSTGRESQL(5)

NOMBRE

table_postgresql — descripción del formato para tablas PostgreSQL de smtpd

DESCRIPCIÓN

Esta página del manual documenta el formato de archivo de las tablas PostgreSQL utilizadas por el demonio de correo smtpd(8).

El formato descrito aquí se aplica a las tablas definidas en smtpd.conf(5).

TABLA POSTGRESQL

Una tabla postgresql permite almacenar nombres de usuario, contraseñas, alias y dominios en un formato que puede compartirse entre varias máquinas que soportan postgres(1).

La tabla es utilizada por smtpd(8) al autenticar un usuario, cuando se requiere información del usuario como id de usuario y/o directorio principal para una entrega, cuando puede requerirse una búsqueda de dominio, y/o al buscar un alias.

Una tabla PostgreSQL consiste en una o más bases de datos postgresql(1) con una o más tablas.

Si la tabla se utiliza para la autenticación, la contraseña debe estar cifrada utilizando la función crypt(3). Dichas contraseñas pueden generarse utilizando la utilidad encrypt(1) o el comando encrypt de smtpctl(8).

ARCHIVO DE CONFIGURACIÓN DE TABLA POSTGRESQL

Las siguientes opciones de configuración están disponibles:

conninfo host='host' user='usuario' password='contraseña' dbname='nombrebasedatos'
Información de conexión necesaria para conectarse a la base de datos PostgreSQL. Por ejemplo: 
conninfo host='db.example.com' user='maildba' password='...' dbname='opensmtpdb'
query_alias sentencia SQL
Se utiliza para proporcionar una consulta para buscar alias. El signo de interrogación se reemplaza con los datos apropiados. Para alias, es el lado izquierdo de la dirección SMTP. Espera que se devuelva una VARCHAR con el nombre de usuario al que se resuelve el alias.
query_credentials sentencia SQL
Se utiliza para proporcionar una consulta para buscar credenciales de usuario. El signo de interrogación se reemplaza con los datos apropiados. Para credenciales, es el lado izquierdo de la dirección SMTP. La consulta espera que se devuelvan dos VARCHAR, una con un nombre de usuario y otra con una contraseña en formato crypt(3).
query_domain sentencia SQL
Se utiliza para proporcionar una consulta para buscar un dominio. El signo de interrogación se reemplaza con los datos apropiados. Para el dominio, sería el lado derecho de la dirección SMTP. Espera que se devuelva una VARCHAR con un nombre de dominio coincidente.
query_mailaddrmap sentencia SQL
Se utiliza para proporcionar una consulta para buscar remitentes. El signo de interrogación se reemplaza con los datos apropiados. Espera que se devuelva una VARCHAR con la dirección desde la que el remitente tiene permitido enviar correos.

Una sentencia SQL genérica sería algo como:

query_ SELECT value FROM table WHERE key=$1;

EJEMPLOS

EJEMPLO GENÉRICO

Ejemplo basado en el FAQ de OpenSMTPD: Construyendo un Servidor de Correo. La parte de filtrado se excluye en este ejemplo.

La configuración a continuación es para un servidor de correo de tamaño medio que maneja múltiples dominios con múltiples usuarios virtuales y se basa en varias suposiciones. Una de ellas es que se utiliza un único usuario del sistema llamado vmail para todos los usuarios virtuales. Este usuario necesita ser creado:

# useradd -g =uid -c "Virtual Mail" -d /var/vmail -s /sbin/nologin vmail
# mkdir /var/vmail
# chown vmail:vmail /var/vmail

Esquema de PostgreSQL:

CREATE TABLE domains (
  id SERIAL,
  domain VARCHAR(255) NOT NULL DEFAULT ''
);
CREATE TABLE virtuals (
    id SERIAL,
    email VARCHAR(255) NOT NULL DEFAULT '',
    destination VARCHAR(255) NOT NULL DEFAULT ''
);
CREATE TABLE credentials (
    id SERIAL,
    email VARCHAR(255) NOT NULL DEFAULT '',
    password VARCHAR(255) NOT NULL DEFAULT ''
);

Eso se puede poblar de la siguiente manera:

INSERT INTO domains VALUES (1, "example.com");
INSERT INTO domains VALUES (2, "example.net");
INSERT INTO domains VALUES (3, "example.org");

INSERT INTO virtuals VALUES (1, "abuse@example.com", "bob@example.com");
INSERT INTO virtuals VALUES (2, "postmaster@example.com", "bob@example.com");
INSERT INTO virtuals VALUES (3, "webmaster@example.com", "bob@example.com");
INSERT INTO virtuals VALUES (4, "bob@example.com", "vmail");
INSERT INTO virtuals VALUES (5, "abuse@example.net", "alice@example.net");
INSERT INTO virtuals VALUES (6, "postmaster@example.net", "alice@example.net");
INSERT INTO virtuals VALUES (7, "webmaster@example.net", "alice@example.net");
INSERT INTO virtuals VALUES (8, "alice@example.net", "vmail");

INSERT INTO credentials VALUES (1, "bob@example.com", "$2b$08$ANGFKBL.BnDLL0bUl7I6aumTCLRJSQluSQLuueWRG.xceworWrUIu");
INSERT INTO credentials VALUES (2, "alice@example.net", "$2b$08$AkHdB37kaj2NEoTcISHSYOCEBA5vyW1RcD8H1HG.XX0P/G1KIYwii");

/etc/mail/postgresql.conf

conninfo host='db.example.com' user='maildba' password='OpenSMTPDRules!' dbname='opensmtpdb'
query_alias SELECT destination FROM virtuals WHERE email=$1;
query_credentials SELECT email, password FROM credentials WHERE email=$1;
query_domain SELECT domain FROM domains WHERE domain=$1;

/etc/mail/smtpd.conf

table domains postgres:/etc/mail/postgres.conf
table virtuals postgres:/etc/mail/postgres.conf
table credentials postgres:/etc/mail/postgres.conf
listen on egress port 25 tls pki mail.example.com
listen on egress port 587 tls-require pki mail.example.com auth <credentials>
accept from any for domain <domains> virtual <virtuals> deliver to mbox

MUDÁNDOSE DESDE POSTFIX (& POSTFIXADMIN)

/etc/mail/postgres.conf

conninfo host='db.example.com' user='postfix' password='...' dbname='postfix'
query_alias SELECT destination FROM alias WHERE email=$1;
query_credentials SELECT username, password FROM mailbox WHERE username=$1;
query_domain SELECT domain FROM domain WHERE domain=$1;

El resto de la configuración permanece igual.
