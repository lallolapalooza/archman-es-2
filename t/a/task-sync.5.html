NOMBRE

task-sync - Una discusión y tutorial sobre las diversas capacidades de sincronización de datos de task(1).

INTRODUCCIÓN

Taskwarrior puede sincronizar tus tareas a un servidor. Esto tiene algunos beneficios:
- Hace que tus tareas sean accesibles desde múltiples sistemas, llamados "réplicas".
- Proporciona una copia de seguridad de tus tareas.
- Ahorra espacio en disco.

Por ejemplo, podrías querer una réplica de tus tareas en tu portátil y en tu teléfono.

NOTA: Un efecto secundario de la sincronización es que una vez que los cambios se han sincronizado, no se pueden deshacer. Esto significa que cada vez que se ejecuta la sincronización, ya no es posible deshacer operaciones anteriores.

GESTIÓN DE LA SINCRONIZACIÓN

Añadir una réplica

Para añadir una nueva réplica, configura una nueva réplica vacía idénticamente a la réplica existente y ejecuta `task sync`.

Cuándo sincronizar

Para sincronizar a un servidor, una solución común es ejecutar

    $ task sync

periódicamente, por ejemplo, a través de cron(8).

CONFIGURACIÓN

Taskwarrior proporciona varias opciones para sincronizar tus tareas:


- A un servidor diseñado específicamente para manejar datos de Taskwarrior.
+ A un proveedor de almacenamiento en la nube. Actualmente se admiten tanto AWS como GCP.
- A un archivo local en disco.

Para la mayoría de estas opciones, necesitarás un secreto de cifrado que se utiliza para cifrar y descifrar tus tareas. Este puede ser cualquier cadena secreta y debe coincidir para todas las réplicas que comparten tareas.

    $ task config sync.encryption_secret <secreto_cifrado>

Herramientas como pwgen(1) pueden generar valores de secretos adecuados.

Servidor de Sincronización

Para sincronizar tus tareas a un servidor de sincronización, necesitarás la siguiente información del administrador del servidor:


- La URL del servidor (como "https://tw.example.com/path")
- Un ID de cliente ("client_id") que identifica tus tareas

Configura Taskwarrior con estos detalles:

    $ task config sync.server.url               <url>
    $ task config sync.server.client_id         <client_id>

Ten en cuenta que la URL debe incluir el esquema, como 'http://' o 'https://'.


$ task config sync.server.origin <origin>

Es un sinónimo obsoleto de "sync.server.url".

Google Cloud Platform

Para sincronizar tus tareas a GCP, usa la Consola de GCP para crear un nuevo proyecto y, dentro de ese proyecto, un nuevo bucket de Cloud Storage. La configuración por defecto del bucket es adecuada.

Autentícate en el proyecto con:

    $ gcloud config set project $NOMBRE_DEL_PROYECTO
    $ gcloud auth application-default login

Luego, configura Taskwarrior con:

    $ task config sync.gcp.bucket               <nombre-del-bucket>

Sin embargo, puedes aportar tus propias credenciales de cuenta de servicio si tu `application-default` ya está siendo utilizado por alguna otra aplicación.

Para empezar, navega a la sección "IAM y Administración" en el Menú de Navegación, luego selecciona "Roles".

En la barra de menú superior dentro de la sección "Roles", haz clic en "CREAR ROL". Proporciona un nombre y una descripción apropiados para el nuevo rol.

Añade permisos a tu nuevo rol usando el filtro "Servicio:storage" (no el cuadro de entrada "Filtrar permisos por rol"). Selecciona los siguientes permisos:


- storage.buckets.create
- storage.buckets.get
- storage.buckets.update
- storage.objects.create
- storage.objects.delete
- storage.objects.get
- storage.objects.list
- storage.objects.update

Crea tu nuevo rol.

En la barra lateral izquierda, navega a "Cuentas de servicio".

En la barra de menú superior dentro de la sección "Cuentas de servicio", haz clic en "CREAR CUENTA DE SERVICIO". Proporciona un nombre y una descripción apropiados para la nueva cuenta de servicio. Selecciona el rol que acabas de crear y completa el proceso de creación de la cuenta de servicio.

Ahora, en el panel de la Cuenta de Servicio, haz clic en la nueva cuenta de servicio y selecciona "claves" en la barra de menú superior. Haz clic en "AÑADIR CLAVE" para crear y descargar una nueva clave (una clave JSON).

Luego, configura Taskwarrior con:

    $ task config sync.gcp.bucket               <nombre-del-bucket>
    $ task config sync.gcp.credential_path      <ruta-absoluta-a-las-credenciales-descargadas>

Amazon Web Services

Para sincronizar tus tareas a AWS, selecciona una región cercana a ti y usa la consola de AWS para crear un nuevo bucket S3. La configuración por defecto del bucket es adecuada. En particular, asegúrate de que no haya políticas de ciclo de vida habilitadas, ya que pueden eliminar o transicionar objetos automáticamente, lo que podría afectar la disponibilidad de los datos.

También necesitarás un usuario IAM de AWS con la siguiente política, donde NOMBRE_DEL_BUCKET es el nombre del bucket. El mismo usuario puede configurarse para varios clientes de Taskwarrior.

    {
        "Version": "2012-10-17",
        "Statement": [
            {
                "Sid": "TaskChampion",
                "Effect": "Allow",
                "Action": [
                    "s3:PutObject",
                    "s3:GetObject",
                    "s3:ListBucket",
                    "s3:DeleteObject"
                ],
                "Resource": [
                    "arn:aws:s3:::NOMBRE_DEL_BUCKET",
                    "arn:aws:s3:::NOMBRE_DEL_BUCKET/*"
                ]
            }
        ]
    }

Para crear un usuario así, crea una nueva política en la consola IAM, selecciona la opción JSON en el editor de políticas y pega la política. Haz clic en "Siguiente" y dale un nombre a la política, como "TaskwarriorSync". A continuación, crea un nuevo usuario, con un nombre de tu elección, selecciona "Adjuntar políticas directamente" y luego elige la política recién creada.

Necesitarás claves de acceso configuradas para el nuevo usuario. Encuentra al usuario en la lista de usuarios, abre la pestaña "Credenciales de seguridad" y luego haz clic en "Crear clave de acceso" y sigue los pasos.

En este punto, puedes elegir cómo proporcionar esas credenciales a Taskwarrior. Lo más sencillo es incluirlas en la configuración de Taskwarrior:

    $ task config sync.aws.region              <region>
    $ task config sync.aws.bucket              <nombre-del-bucket>
    $ task config sync.aws.access_key_id       <id-de-clave-de-acceso>
    $ task config sync.aws.secret_access_key   <clave-de-acceso-secreta>

Alternativamente, puedes configurar un perfil de AWS CLI, usando un nombre de perfil de tu elección, como "taskwarrior-creds":

    $ aws configure --profile taskwarrior-creds

Introduce el ID de clave de acceso y la clave de acceso secreta. La región y el formato por defecto no son importantes. Luego, configura Taskwarrior con:

    $ task config sync.aws.region              <region>
    $ task config sync.aws.bucket              <nombre-del-bucket>
    $ task config sync.aws.profile             taskwarrior-creds

Para usar las fuentes de credenciales predeterminadas de AWS, como variables de entorno, el perfil predeterminado o un perfil de instancia, configura

    $ task config sync.aws.region              <region>
    $ task config sync.aws.bucket              <nombre-del-bucket>
    $ task config sync.aws.default_credentials true

NAME

task-sync.5

sync taskwarrior data

INTRODUCTION

Taskwarrior includes a synchronization engine that allows the task database to be shared between multiple clients. Synchronization is accomplished by sending data to a central server. This page describes the synchronization engine, and the server implementation called taskchampion-sync-server.

This engine is designed to be simple, and to avoid common pitfalls. It is implemented as a Perl module, and is therefore very easy to extend.

MANAGING SYNCHRONIZATION

This is accomplished using the task sync command. For details, see the task(1) man page.

CONFIGURATION

Configuration is done in the ~/.taskrc file.

sync.server.location
The URL of the sync server. This is required to perform synchronization.
sync.server.username
The user name for the sync server. The default is "default".
sync.server.password
The password for the sync server. This is required.
sync.identity
The identity of the client. This should be a UUID, and is generated automatically by taskd. A new identity can be generated using the task sync.identity.new command.
sync.method
The method used to synchronize. Options are "default" (HTTP protocol), and "debug" (prints synchronization information to stdout). The default is "default".
sync.nonblocking
When set to "on", synchronization will occur in the background. The default is "off".
sync.verify.ssl
When set to "on", SSL certificates will be verified. The default is "on".
sync.uuid.file
The location of the file containing the sync UUID. This is generated automatically by taskd, and defaults to ~/.task/sync/uuid.
sync.key.file
The location of the file containing the encryption key. This is generated automatically by taskd, and defaults to ~/.task/sync/key.
data.location
The location of the task data directory. This directory will be synchronized. The default is ~/.task/. (See also: task(1))

RUNNING TASKCHAMPION-SYNC-SERVER

The TaskChampion sync server is an HTTP server supporting multiple users. Users are identified by a client ID, and users with different client IDs are entirely independent. Task data is encrypted by Taskwarrior, and the sync server never sees un-encrypted data.

The server is developed in https://github.com/GothenburgBitFactory/taskchampion-sync-server.

Adding a New User

To add a new user to the server, invent a new client ID with a tool like `uuidgen` or an online UUID generator. There is no need to configure the server for this new client ID: the sync server will automatically create a new user whenever presented with a new client ID. Supply the ID, along with the URL, to the user for inclusion in their Taskwarrior config. The user should invent their own "encryption_secret".

AVOIDING DUPLICATE RECURRING TASKS

If you run multiple clients that sync to the same server, you will need to run this command on your primary client (the one you use most often):

    $ task config recurrence on

And on the other clients, run:

    $ task config recurrence off

This protects you against the effects of a sync/duplication bug.

ALTERNATIVE: FILE SHARING SERVICES

There are many file sharing services, such as DropBox, Amazon S3, Google Drive, SkyDrive and more. This technique involves storing your .task directory in a shared directory under the control of the file hosting services.

Syncing happens quickly, although it is possible to run into conflict situations when there is no network connectivity, and the tasks are modified in two separate locations. This is because the file hosting service knows only about files, and it has no idea how to merge tasks. Avoid this problem by never modifying the same task on two machines, without an intervening sync.

Setup simply involves creating the directory and modifying your data.location configuration variable like this:

    $ task config data.location /path/to/shared/directory

Strengths:
- Good client support
- Easy setup
- Transparent use

Weaknesses:
- Tasks are not properly merged
