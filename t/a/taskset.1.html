TASKSET(1) Comandos de usuario TASKSET(1)

NOMBRE

taskset - establece o recupera la afinidad de CPU de un proceso

SINOPSIS

taskset [opciones] máscara comando [argumento...]

taskset [opciones] -p [máscara] pid

DESCRIPCIÓN

El comando taskset se utiliza para establecer o recuperar la afinidad de CPU de un proceso en ejecución dado su pid, o para lanzar un nuevo comando con una afinidad de CPU dada. La afinidad de CPU es una propiedad del planificador que "une" un proceso a un conjunto dado de CPUs en el sistema. El planificador de Linux respetará la afinidad de CPU dada y el proceso no se ejecutará en ninguna otra CPU. Tenga en cuenta que el planificador de Linux también admite la afinidad de CPU natural: el planificador intenta mantener los procesos en la misma CPU tanto como sea práctico por razones de rendimiento. Por lo tanto, forzar una afinidad de CPU específica solo es útil en ciertas aplicaciones. La afinidad de algunos procesos como los hilos por CPU del kernel no se puede establecer.

La afinidad de CPU se representa como una máscara de bits, con el bit de orden más bajo correspondiente a la primera CPU lógica y el bit de orden más alto correspondiente a la última CPU lógica. Es posible que no todas las CPUs existan en un sistema dado, pero una máscara puede especificar más CPUs de las que están presentes. Una máscara recuperada reflejará solo los bits que corresponden a las CPUs físicas del sistema. Si se proporciona una máscara inválida (es decir, una que no corresponde a ninguna CPU válida en el sistema actual), se devolverá un error. Las máscaras se pueden especificar en hexadecimal (con o sin un prefijo "0x"), o como una lista de CPUs con la opción --cpu-list. Por ejemplo,

0x00000001

es el procesador n.º 0,

0x00000003

son los procesadores n.º 0 y n.º 1,

FFFFFFFF

son los procesadores n.º 0 a 31,

0x32

son los procesadores n.º 1, n.º 4 y n.º 5,

--cpu-list 0-2,6

son los procesadores n.º 0, n.º 1, n.º 2 y n.º 6.

--cpu-list 0-10:2

son los procesadores n.º 0, 2, 4, 6, 8 y 10. El sufijo ":N" especifica el paso en el rango, por ejemplo, 0-10:3 se interpreta como la lista 0,3,6,9.

Cuando taskset se devuelve, se garantiza que el programa dado ha sido planificado en una CPU legal.

OPCIONES

-a, --all-tasks

Establece o recupera la afinidad de CPU de todas las tareas (hilos) para un PID dado.

-c, --cpu-list

Interpreta máscara como una lista numérica de procesadores en lugar de una máscara de bits. Los números están separados por comas y pueden incluir rangos. Por ejemplo: 0,5,8-11.

-p, --pid

Opera en un PID existente y no lanza una nueva tarea.

-h, --help

Muestra el texto de ayuda y sale.

-V, --version

Muestra la versión y sale.

USO

El comportamiento predeterminado es ejecutar un nuevo comando con una máscara de afinidad dada:

taskset máscara comando [argumentos]

También puede recuperar la afinidad de CPU de una tarea existente:

taskset -p pid

O establecerla:

taskset -p máscara pid

Cuando se especifica una lista de CPUs para un proceso existente, las opciones -p y -c deben agruparse:

taskset -pc lista-cpu pid

La forma --cpu-list solo es aplicable para lanzar nuevos comandos:

taskset --cpu-list lista-cpu comando

PERMISOS

Un usuario puede cambiar la afinidad de CPU de un proceso que le pertenece. Un usuario debe poseer CAP_SYS_NICE para cambiar la afinidad de CPU de un proceso que pertenece a otro usuario. Un usuario puede recuperar la máscara de afinidad de cualquier proceso.

ESTADO DE SALIDA

taskset devuelve 0 en su modo de obtención de afinidad siempre que el PID proporcionado exista.

taskset devuelve 0 en su modo de establecimiento de afinidad siempre que la llamada al sistema subyacente sched_setaffinity(2) lo haga. El éxito del comando no garantiza que el hilo especificado haya migrado realmente a la(s) CPU(s) indicada(s), sino solo que el hilo no migrará a una CPU fuera de la nueva máscara de afinidad. Por ejemplo, la afinidad del hilo del kernel kswapd se puede establecer, pero el hilo puede no migrar inmediatamente y no se garantiza que lo haga alguna vez:

$ ps ax -o comm,psr,pid | grep kswapd
kswapd0 4 82
$ sudo taskset -p 1 82
la máscara de afinidad actual del pid 82 es: 1
la nueva máscara de afinidad del pid 82 es: 1
$ echo $?
0
$ ps ax -o comm,psr,pid | grep kswapd
kswapd0 4 82
$ taskset -p 82
la máscara de afinidad actual del pid 82 es: 1

En contraste, cuando el usuario especifica una afinidad ilegal, taskset imprimirá un error y devolverá 1:

$ ps ax -o comm,psr,pid | grep ksoftirqd/0
ksoftirqd/0 0 14
$ sudo taskset -p 1 14
la máscara de afinidad actual del pid 14 es: 1
taskset: no se pudo establecer la afinidad del pid 14: Argumento inválido
$ echo $?
1
