talloc(3)

Paquete: talloc

Licencias: GPL-3.0-or-later

TALLOC(3) Herramientas de administración del sistema TALLOC(3)

NOMBRE

talloc - sistema de pools de memoria jerárquicos con recuento de referencias y destructores

SINOPSIS

#include <talloc.h>

DESCRIPCIÓN

Si estás acostumbrado a talloc de Samba3, por favor lee esto con atención, ya que talloc ha cambiado mucho.

El nuevo talloc es un sistema de pools de memoria jerárquico con recuento de referencias y destructores. Es un nombre bastante largo, pero no es tan malo una vez que te acostumbras.

Quizás el mayor cambio respecto a Samba3 es que no hay distinción entre un "contexto talloc" y un "puntero talloc". Cualquier puntero devuelto por talloc() es en sí mismo un contexto talloc válido. Esto significa que puedes hacer esto:

    struct foo *X = talloc(mem_ctx, struct foo);
    X->name = talloc_strdup(X, "foo");

y el puntero X->name sería un "hijo" del contexto talloc X, que a su vez es hijo de mem_ctx. Así, si haces talloc_free(mem_ctx) entonces todo se destruye, mientras que si haces talloc_free(X), solo se destruyen X y X->name, y si haces talloc_free(X->name), solo se destruye el elemento name de X.

Si piensas en esto, lo que efectivamente te da es un árbol n-ario, donde puedes liberar cualquier parte del árbol con talloc_free().

Si esto te confunde, te sugiero que ejecutes el programa testsuite para ver talloc en acción. También podrías querer añadir tus propias pruebas a testsuite.c para aclarar cómo se maneja alguna situación particular.

API TALLOC

La siguiente es una guía completa de la API de talloc. Léela entera al menos dos veces.

(tipo *)talloc(const void *ctx, tipo);

La macro talloc() es el núcleo de la biblioteca talloc. Toma un ctx de memoria y un tipo, y devuelve un puntero a un nuevo área de memoria del tipo dado.

El puntero devuelto es en sí mismo un contexto talloc, por lo que puedes usarlo como argumento ctx para más llamadas a talloc() si lo deseas.

El puntero devuelto es un "hijo" del contexto suministrado. Esto significa que si llamas a talloc_free() sobre ctx, el nuevo hijo desaparece también. Alternativamente, puedes liberar solo el hijo.

El argumento ctx a talloc() puede ser NULL, en cuyo caso se crea un nuevo contexto de nivel superior.

void *talloc_size(const void *ctx, size_t size);

La función talloc_size() debe usarse cuando no tienes un tipo conveniente para pasar a talloc(). A diferencia de talloc(), no es segura en cuanto a tipos (ya que devuelve un void *), por lo que la verificación de tipos corre por tu cuenta.

(typeof(ptr)) talloc_ptrtype(const void *ctx, ptr);

La macro talloc_ptrtype() debe usarse cuando tienes un puntero y quieres asignar memoria a la que apunte este puntero. Al compilar con gcc >= 3 es segura en cuanto a tipos. Nota: esto es un envoltorio de talloc_size() y talloc_get_name() devolverá la ubicación actual en el archivo fuente, y no el tipo.

int talloc_free(void *ptr);

La función talloc_free() libera una porción de memoria talloc, y todos sus hijos. Puedes llamar a talloc_free() sobre cualquier puntero devuelto por talloc().

El valor de retorno de talloc_free() indica éxito o fallo, devolviendo 0 para éxito y -1 para fallo. La única condición de fallo posible es si ptr tenía un destructor adjunto y el destructor devolvió -1. Ver “talloc_set_destructor()” para detalles sobre destructores.

Si este puntero tiene un padre adicional cuando se llama a talloc_free(), la memoria no se libera realmente, sino que se destruye el padre establecido más recientemente. Ver “talloc_reference()” para detalles sobre el establecimiento de padres adicionales.

Para un mayor control sobre qué padre se elimina, ver “talloc_unlink()”.

talloc_free() opera recursivamente sobre sus hijos.

Desde la versión 2.0 de talloc, como caso especial, se rechaza talloc_free() en punteros que tienen más de un padre, ya que talloc no tendría forma de saber qué padre debe eliminarse. Para liberar un puntero que tiene más de un padre, usa talloc_unlink().

Para ayudarte a encontrar problemas en tu código causados por este comportamiento, si intentas liberar un puntero con más de un padre, se llamará a la función de registro de talloc para producir una salida como esta:

    ERROR: talloc_free con referencias en some_dir/source/foo.c:123
	referencia en some_dir/source/other.c:325
	referencia en some_dir/source/third.c:121

Por favor, consulta la documentación de talloc_set_log_fn() y talloc_set_log_stderr() para más información sobre las funciones de registro de talloc.

void *talloc_reference(const void *ctx, const void *ptr);

La función talloc_reference() hace que ctx sea un padre adicional de ptr.

El valor de retorno de talloc_reference() es siempre el puntero original ptr, a menos que talloc se haya quedado sin memoria al crear la referencia, en cuyo caso devolverá NULL (cada referencia adicional consume alrededor de 48 bytes de memoria en plataformas Intel x86).

Si ptr es NULL, la función no hace nada y simplemente devuelve NULL.

Después de crear una referencia, puedes liberarla de una de las siguientes maneras:

• Puedes llamar a talloc_free() sobre cualquier padre del puntero original. Esto reducirá el número de padres de este puntero en 1, y hará que este puntero se libere si se queda sin padres.
• Puedes llamar a talloc_free() sobre el puntero mismo si tiene como máximo un padre. Este comportamiento ha cambiado desde la versión 2.0. Más información en la descripción de "talloc_free".

Para un mayor control sobre qué padre eliminar, ver “talloc_unlink()”.

int talloc_unlink(const void *ctx, void *ptr);

La función talloc_unlink() elimina un padre específico de ptr. El ctx pasado debe ser un contexto utilizado en talloc_reference() con este puntero, o debe ser un padre directo de ptr.

Ten en cuenta que si el padre ya ha sido eliminado usando talloc_free(), esta función fallará y devolverá -1. Igualmente, si ptr es NULL, la función no realizará ninguna modificación y devolverá -1.

Normalmente puedes usar talloc_free() en lugar de talloc_unlink(), pero a veces es útil tener control adicional sobre qué padre se elimina.

void talloc_set_destructor(const void *ptr, int (*destructor)(void *));

La función talloc_set_destructor() establece el destructor para el puntero ptr. Un destructor es una función que se llama cuando la memoria utilizada por un puntero está a punto de ser liberada. El destructor recibe ptr como argumento y debe devolver 0 para éxito y -1 para fallo.

El destructor puede hacer lo que quiera, incluida la liberación de otras porciones de memoria. Un uso común de los destructores es limpiar recursos del sistema operativo (como descriptores de archivos abiertos) contenidos en la estructura sobre la que se coloca el destructor.

Solo puedes colocar un destructor en un puntero. Si necesitas más de un destructor, puedes crear un hijo de longitud cero del puntero y colocar un destructor adicional en él.

Para eliminar un destructor, llama a talloc_set_destructor() con NULL para el destructor.

Si tu destructor intenta llamar a talloc_free() sobre el puntero para el que es el destructor, talloc_free() devolverá -1 y la liberación se ignorará. Esto sería

(TYPE *) talloc_parent_ptr(ptr);

The talloc_parent_ptr() function returns the pointer to the parent of the given talloc pointer. This function is intended for internal use by talloc itself, and should not be called from application code.

If the pointer has more than one parent (see talloc_reference(3)), then the parent returned is arbitrary.

The result is undefined if called with a NULL pointer.

(void (*talloc_destructor)(void *)) talloc_destructor(ptr);

The talloc_destructor() function returns the destructor that is associated with the talloc pointer ptr. A destructor is a function that is called when the pointer is freed using talloc_free().

This is primarily useful for debugging and should not be called from application code.

It is a pointless operation anyway, as the destructor is only called when the memory is just about to go away.

(int) talloc_increase_ref_count(const void *ptr);

The talloc_increase_ref_count(ptr) function is exactly equivalent to:

talloc_reference(NULL, ptr);

You can use either syntax, depending on which you think is clearer in your code.

It returns 0 on success and -1 on failure.

(size_t) talloc_reference_count(const void *ptr);

Return the number of references to the pointer.

(void) talloc_set_name(const void *ptr, const char *fmt, ...);

Each talloc pointer has a "name". The name is used principally for debugging purposes, although it is also possible to set and get the name on a pointer in as a way of "marking" pointers in your code.

The main use for names on pointer is for "talloc reports". See “talloc_report_depth_cb()”, “talloc_report_depth_file()”, “talloc_report()” “talloc_report()” and “talloc_report_full()” for details. Also see “talloc_enable_leak_report()” and “talloc_enable_leak_report_full()”.

The talloc_set_name() function allocates memory as a child of the pointer. It is logically equivalent to:

talloc_set_name_const(ptr, talloc_asprintf(ptr, fmt, ...));

Note that multiple calls to talloc_set_name() will allocate more memory without releasing the name. All of the memory is released when the ptr is freed using talloc_free().

(void) talloc_set_name_const(const void *ptr, const char *name);

The function talloc_set_name_const() is just like talloc_set_name(), but it takes a string constant, and is much faster. It is extensively used by the "auto naming" macros, such as talloc_p().

This function does not allocate any memory. It just copies the supplied pointer into the internal representation of the talloc ptr. This means you must not pass a name pointer to memory that will disappear before ptr is freed with talloc_free().

(void *) talloc_named(const void *ctx, size_t size, const char *fmt, ...);

The talloc_named() function creates a named talloc pointer. It is equivalent to:

ptr = talloc_size(ctx, size);
talloc_set_name(ptr, fmt, ....);

(void *) talloc_named_const(const void *ctx, size_t size, const char *name);

This is equivalent to:

ptr = talloc_size(ctx, size);
talloc_set_name_const(ptr, name);

(const char *) talloc_get_name(const void *ptr);

This returns the current name for the given talloc pointer, ptr. See “talloc_set_name()” for details.

(void *) talloc_init(const char *fmt, ...);

This function creates a zero length named talloc context as a top level context. It is equivalent to:

talloc_named(NULL, 0, fmt, ...);

(void *) talloc_new(void *ctx);

This is a utility macro that creates a new memory context hanging off an existing context, automatically naming it "talloc_new: __location__" where __location__ is the source line it is called from. It is particularly useful for creating a new temporary working context.

(TYPE *) talloc_realloc(const void *ctx, void *ptr, TYPE, count);

The talloc_realloc() macro changes the size of a talloc pointer. It has the following equivalences:

talloc_realloc(ctx, NULL, type, 1) ==> talloc(ctx, type);
talloc_realloc(ctx, ptr, type, 0)  ==> talloc_free(ptr);

The ctx argument is only used if ptr is not NULL, otherwise it is ignored.

talloc_realloc() returns the new pointer, or NULL on failure. The call will fail either due to a lack of memory, or because the pointer has more than one parent (see “talloc_reference()”).

(void *) talloc_realloc_size(const void *ctx, void *ptr, size_t size);

the talloc_realloc_size() function is useful when the type is not known so the type-safe talloc_realloc() cannot be used.

(TYPE *) talloc_steal(const void *new_ctx, const TYPE *ptr);

The talloc_steal() function changes the parent context of a talloc pointer. It is typically used when the context that the pointer is currently a child of is going to be freed and you wish to keep the memory for a longer time.

The talloc_steal() function returns the pointer that you pass it. It does not have any failure modes.

It is possible to produce loops in the parent/child relationship if you are not careful with talloc_steal(). No guarantees are provided as to your sanity or the safety of your data if you do this.

Note that if you try and call talloc_steal() on a pointer that has more than one parent then the result is ambiguous. Talloc will choose to remove the parent that is currently indicated by talloc_parent() and replace it with the chosen parent. You will also get a message like this via the talloc logging functions:

  WARNING: talloc_steal with references at some_dir/source/foo.c:123
	reference at some_dir/source/other.c:325
	reference at some_dir/source/third.c:121

To unambiguously change the parent of a pointer please see the function “talloc_reparent()”. See the talloc_set_log_fn() documentation for more information on talloc logging.

(TYPE *) talloc_reparent(const void *old_parent, const void *new_parent, const TYPE *ptr);

The talloc_reparent() function changes the parent context of a talloc pointer. It is typically used when the context that the pointer is currently a child of is going to be freed and you wish to keep the memory for a longer time.

The talloc_reparent() function returns the pointer that you pass it. It does not have any failure modes.

The difference between talloc_reparent() and talloc_steal() is that talloc_reparent() can specify which parent you wish to change. This is useful when a pointer has multiple parents via references.

(TYPE *) talloc_move(const void *new_ctx, TYPE **ptr);

The talloc_move() function is a wrapper around talloc_steal() which zeros the source pointer after the move. This avoids a potential source of bugs where a programmer leaves a pointer in two structures, and uses the pointer from the old structure after it has been moved to a new one.

(size_t) talloc_total_size(const void *ptr);

The talloc_total_size() function returns the total size in bytes used by this pointer and all child pointers. Mostly useful for debugging.

Passing NULL is allowed, but it will only give a meaningful result if talloc_enable_leak_report() or talloc_enable_leak_report_full() has been called.

(size_t) talloc_total_blocks(const void *ptr);

The talloc_total_blocks() function returns the total memory block count used by this pointer and all child pointers. Mostly useful for debugging.

Passing NULL is allowed, but it will only give a meaningful result if talloc_enable_leak_report() or talloc_enable_leak_report_full() has been called.

(void) talloc_report(const void *ptr, FILE *f);

id talloc_report(const void *ptr, FILE *f);

La función talloc_report() imprime un informe resumido de toda la memoria utilizada por ptr. Se imprime una línea de informe para cada hijo inmediato de ptr, mostrando la memoria total y el número de bloques utilizados por ese hijo.

Puedes pasar NULL para el puntero, en cuyo caso se imprime un informe para el contexto de memoria de nivel superior, pero solo si se ha llamado a talloc_enable_leak_report() o talloc_enable_leak_report_full().

void talloc_report_full(const void *ptr, FILE *f);

Esto proporciona un informe más detallado que talloc_report(). Imprimirá recursivamente todo el árbol de memoria referenciado por el puntero. Las referencias en el árbol se muestran dando el nombre del puntero al que se hace referencia.

Puedes pasar NULL para el puntero, en cuyo caso se imprime un informe para el contexto de memoria de nivel superior, pero solo si se ha llamado a talloc_enable_leak_report() o talloc_enable_leak_report_full().

void talloc_report_depth_cb(const void *ptr, int depth, int max_depth, void (*callback)(const void *ptr, int depth, int max_depth, int is_ref, void *priv), void *priv);

Esto proporciona informes más flexibles que talloc_report(). Llamará recursivamente a la función de devolución de llamada para todo el árbol de memoria referenciado por el puntero. Las referencias en el árbol se pasan con is_ref = 1 y el puntero al que se hace referencia.

Puedes pasar NULL para el puntero, en cuyo caso se imprime un informe para el contexto de memoria de nivel superior, pero solo si se ha llamado a talloc_enable_leak_report() o talloc_enable_leak_report_full().

La recursión se detiene cuando depth >= max_depth. max_depth = -1 significa que solo se detiene en los nodos hoja.

void talloc_report_depth_file(const void *ptr, int depth, int max_depth, FILE *f);

Esto proporciona informes más flexibles que talloc_report(). Te permitirá especificar la profundidad y la profundidad máxima.

void talloc_enable_leak_report(void);

Esto permite la llamada a talloc_report(NULL, stderr) cuando el programa termina. En Samba4, esto se habilita mediante la opción de línea de comandos --leak-report.

Para que sea útil, esta función debe llamarse antes que cualquier otra función de talloc, ya que establece un "contexto nulo" que actúa como la parte superior del árbol. Si no llamas a esta función primero, pasar NULL a talloc_report() o talloc_report_full() no te dará la impresión completa del árbol.

(type *)talloc_zero(const void *ctx, type);

La macro talloc_zero() es equivalente a:

ptr = talloc(ctx, type);
if (ptr) memset(ptr, 0, sizeof(type));

void *talloc_zero_size(const void *ctx, size_t size)

La función talloc_zero_size() es útil cuando no se tiene un tipo conocido.

void *talloc_memdup(const void *ctx, const void *p, size_t size);

La función talloc_memdup() es equivalente a:

ptr = talloc_size(ctx, size);
if (ptr) memcpy(ptr, p, size);

char *talloc_strdup(const void *ctx, const char *p);

La función talloc_strdup() es equivalente a:

ptr = talloc_size(ctx, strlen(p)+1);
if (ptr) memcpy(ptr, p, strlen(p)+1);

Esta función establece el nombre del nuevo puntero a la cadena proporcionada. Esto es equivalente a:

talloc_set_name_const(ptr, ptr)

char *talloc_strndup(const void *t, const char *p, size_t n);

La función talloc_strndup() es el equivalente de talloc de la función de la biblioteca C strndup(3).

Esta función establece el nombre del nuevo puntero a la cadena proporcionada. Esto es equivalente a:

talloc_set_name_const(ptr, ptr)

char *talloc_vasprintf(const void *t, const char *fmt, va_list ap);

La función talloc_vasprintf() es el equivalente de talloc de la función de la biblioteca C vasprintf(3).

Esta función establece el nombre del nuevo puntero a la nueva cadena. Esto es equivalente a:

talloc_set_name_const(ptr, ptr)

char *talloc_asprintf(const void *t, const char *fmt, ...);

La función talloc_asprintf() es el equivalente de talloc de la función de la biblioteca C asprintf(3).

Esta función establece el nombre del nuevo puntero a la cadena proporcionada. Esto es equivalente a:

talloc_set_name_const(ptr, ptr)

char *talloc_asprintf_append(char *s, const char *fmt, ...);

La función talloc_asprintf_append() agrega la cadena formateada dada a la cadena dada.

Esta función establece el nombre del nuevo puntero a la nueva cadena. Esto es equivalente a:

(type *)talloc_array(const void *ctx, type, unsigned int count);

La macro talloc_array() es equivalente a:

excepto que proporciona protección contra desbordamiento de enteros para la multiplicación, devolviendo NULL si la multiplicación se desborda.

void *talloc_array_size(const void *ctx, size_t size, unsigned int count);

La función talloc_array_size() es útil cuando el tipo no se conoce. Opera de la misma manera que talloc_array(), pero toma un tamaño en lugar de un tipo.

(typeof(ptr)) talloc_array_ptrtype(const void *ctx, ptr, unsigned int count);

Ten en cuenta que esto es un envoltorio de talloc_array_size() y talloc_get_name() devolverá la ubicación actual en el archivo fuente y no el tipo.

talloc(3) — Arch Linux

NAME

talloc - library for memory management

SYNOPSIS

#include <talloc.h>

void   *talloc_realloc_fn(const void *ctx, void *ptr, size_t size);
void   *talloc_autofree_context(void);
void   *talloc_check_name(const void *ptr, const char *name);
(type   *)talloc_get_type(const void *ptr, type);
talloc_set_type(const   void *ptr, type);
talloc_set_log_fn(void   (*log_fn)(const char *message));
talloc_set_log_stderr(void);

DESCRIPTION

talloc is a hierarchical memory allocation framework. It allows you to allocate memory, and then free all of that memory by calling free() on the top level context.

The main benefit of talloc is that it allows you to avoid memory leaks in complex applications. By using talloc you can ensure that all memory is freed when an object is freed, even if that object has child objects.

talloc also provides a range of helper functions to make it easier to manage your memory.

TALLOC API

void *talloc_realloc_fn(const void *ctx, void *ptr, size_t size)

This is a non-macro version of talloc_realloc(), which is useful as libraries sometimes want a realloc function pointer. A realloc(3) implementation encapsulates the functionality of malloc(3), free(3) and realloc(3) in one call, which is why it is useful to be able to pass around a single function pointer.

void *talloc_autofree_context(void);

This is a handy utility function that returns a talloc context which will be automatically freed on program exit. This can be used to reduce the noise in memory leak reports.

void *talloc_check_name(const void *ptr, const char *name);

This function checks if a pointer has the specified name. If it does then the pointer is returned. It it doesn't then NULL is returned.

(type *)talloc_get_type(const void *ptr, type);

This macro allows you to do type checking on talloc pointers. It is particularly useful for void* private pointers. It is equivalent to this:

(type *)talloc_check_name(ptr, #type)

talloc_set_type(const void *ptr, type);

This macro allows you to force the name of a pointer to be a particular type. This can be used in conjunction with talloc_get_type() to do type checking on void* pointers.

It is equivalent to this:

talloc_set_name_const(ptr, #type)

talloc_set_log_fn(void (*log_fn)(const char *message));

This function sets a logging function that talloc will use for warnings and errors. By default talloc will not print any warnings or errors.

talloc_set_log_stderr(void);

This sets the talloc log function to write log messages to stderr

PERFORMANCE

All the additional features of talloc(3) over malloc(3) do come at a price. We have a performance test in Samba that measures talloc() versus malloc() performance, and it seems that talloc() is about 50% slower than malloc() (AMD Ryzen 9 3900X). For Samba, the great reduction in code complexity that we get by using talloc makes this worthwhile, especially as the total overhead of talloc/malloc in Samba is already quite small.
