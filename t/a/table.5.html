TABLE(5) Manual de Formatos de Archivo TABLE(5)

NOMBRE

table — descripción de formato para tablas de smtpd

DESCRIPCIÓN

Esta página del manual documenta el formato de archivo para las diversas tablas utilizadas en el demonio de correo smtpd(8).

El formato descrito aquí se aplica a las tablas tal como se definen en smtpd.conf(5).

TIPOS DE TABLA

Hay dos tipos de tablas: listas y mapeos. Una lista consiste en una serie de valores, mientras que un mapeo consiste en una serie de claves y sus valores asociados. Lo siguiente ilustra cómo declararlas como tablas estáticas:

table mi_lista { valor1, valor2, valor3 }
table mi_mapeo { clave1 = valor1, clave2 = valor2, clave3 = valor3 }

Al usar una tabla de ‘file’, una lista se escribirá con cada valor en una línea separada.

valor1
valor2
valor3

Un mapeo se escribirá con cada clave y valor en una línea, con espacios en blanco y una coma opcional separando ambas columnas:

clave1:	valor1
clave2	valor2
clave3	valor3

Las líneas en blanco, los espacios al principio y al final, y las tabulaciones se ignoran. Las líneas cuyo primer carácter que no sea un espacio sea un signo de almohadilla (‘#’) son comentarios y se ignoran. Para forzar el análisis de una tabla de archivo como una lista en lugar de un mapeo, use este comentario especial:

# @list

Una tabla de archivo se puede convertir a una base de datos Berkeley utilizando la utilidad makemap(8) sin cambios de sintaxis.

Las tablas que utilizan un backend de ‘file’ o de base de datos Berkeley se referenciarán de la siguiente manera:

table nombre file:/ruta/al/archivo
table nombre db:/ruta/al/archivo.db

Alias de tablas

Las tablas de alias son mapeos que asocian un destinatario a uno o más destinos. Se pueden usar en dos contextos: alias de dominio principal y mapeo de dominio virtual.

action nombre método alias <tabla>
action nombre método virtual <tabla>

En un contexto de dominio principal, la clave es la parte del usuario de la dirección del destinatario, mientras que el valor son uno o más destinatarios tal como se describe en aliases(5):

usuario1	otro_usuario
usuario2	otro_usuario1,otro_usuario2
usuario3	otro_usuario@ejemplo.com

En un contexto de dominio virtual, la clave es la parte del usuario, una dirección de correo electrónico completa o una captura general (catch-all), siguiendo las reglas de selección descritas en smtpd.conf(5), y el valor son uno o más destinatarios tal como se describe en aliases(5):

usuario1			otro_usuario
usuario2@ejemplo.org	otro_usuario1,otro_usuario2
@ejemplo.org		otro_usuario@ejemplo.com
@			catchall@ejemplo.com

La siguiente directiva comparte el mismo formato de tabla, pero con un significado diferente. Aquí, se permite al usuario enviar correo desde las direcciones listadas:

listen on interfaz auth [...] senders <tabla>

Tablas de dominio

Las tablas de dominio son listas simples de dominios o hosts.

match for domain <tabla> action nombre
match helo <tabla> [...] action nombre

En ese contexto, la lista de dominios se comparará con el dominio del destinatario o con el nombre HELO anunciado por el host de envío, respectivamente. Para los backends ‘static’, ‘file’ y dbopen(3), se puede usar un comodín por lo que la tabla de dominio puede contener:

ejemplo.org
*.ejemplo.org

Tablas de credenciales

Las tablas de credenciales son mapeos de credenciales. Se pueden usar en dos contextos:

listen on interfaz tls [...] auth <tabla>
action nombre relay host relay-url auth <tabla>

En un contexto de escucha, las credenciales son un mapeo de nombre de usuario y contraseñas cifradas:

usuario1	$2b$10$hIJ4QfMcp.90nJwKqGbKM.MybArjHOTpEtoTV.DgLYAiThuoYmTSe
usuario2	$2b$10$bwSmUOBGcZGamIfRuXGTvuTo3VLbPG9k5yeKNMBtULBhksV5KdGsK

Las contraseñas deben cifrarse utilizando el subcomando encrypt de smtpctl(8).

En un contexto de retransmisión (relay), las credenciales son un mapeo de etiquetas y pares de nombre de usuario:contraseña:

etiqueta1	usuario:contraseña

La etiqueta debe ser única y se utiliza como selector para las credenciales adecuadas cuando múltiples credenciales son válidas para un solo destino. La contraseña no está cifrada, ya que debe proporcionarse al host remoto.

Tablas Netaddr

Las tablas Netaddr son listas de direcciones de red IPv4 e IPv6. Solo se pueden usar en el siguiente contexto:

match from src <tabla> action nombre

Cuando se utiliza como "fuente de origen", la dirección de un cliente se compara con la lista de direcciones en la tabla hasta que se encuentra una coincidencia.

Una tabla netaddr puede contener direcciones exactas o máscaras de red, y se ve así:

192.168.1.1
[::1]
192.168.1.0/24

Las direcciones IPv6 deben estar encerradas entre corchetes.

Tablas Userinfo

Las tablas Userinfo se utilizan en el contexto de reglas para especificar una base de usuarios alternativa, mapeando usuarios virtuales a usuarios del sistema local por UID, GID y directorio de inicio.

action nombre método userbase <tabla>

Una tabla userinfo se ve así:

joe	1000:100:/home/virtual/joe
jack	1000:100:/home/virtual/jack

En este ejemplo, tanto joe como jack son usuarios virtuales mapeados al usuario del sistema local con UID 1000 y GID 100, pero con directorios de inicio diferentes. Estos directorios pueden contener un archivo forward(5). Esto se puede usar en conjunción con una tabla de alias que mapea una dirección de correo electrónico o la parte del dominio al nombre de usuario virtual deseado. Por ejemplo:

joe@ejemplo.org     joe
jack@ejemplo.com    jack

Tablas Source

Las tablas Source son listas de direcciones IPv4 e IPv6. Solo se pueden usar en el siguiente contexto:

action nombre relay src <tabla>

Las consultas sucesivas a la tabla source devolverán los elementos uno por uno.

Una tabla source se ve así:

192.168.1.2
192.168.1.3
[::1]
[::2]

Las direcciones IPv6 deben estar encerradas entre corchetes.

Tablas Mailaddr

Las tablas Mailaddr son mapeos de direcciones de correo electrónico o dominios a direcciones de correo electrónico.

action name method mailaddr <table>
action name method addr <table>

Se utilizan en la acción mailaddr para mapear o validar direcciones de correo electrónico. La clave es la dirección de correo electrónico o el dominio de destino, y el valor es la dirección de correo electrónico deseada o una lista de ellas.

user@example.com	realuser@example.net
user@another.com	realuser1@example.net,realuser2@example.net
@example.org		catchall@example.net

En este ejemplo, los correos enviados a user@example.com se reescriben a realuser@example.net. Los correos enviados a user@another.com se reescriben a una lista de destinatarios. Los correos enviados a cualquier dirección en example.org se reescriben a catchall@example.net.

NAME

table — table definition

DESCRIPTION

The table keyword in smtpd.conf(5) allows the administrator to define lists of strings which can be referenced by other configuration keywords.

There are several types of tables, each suited for a different purpose.

TABLE TYPES

Mailaddr tables

Mailaddr tables are lists of email addresses. They can be used in the following contexts:

match mail-from <table> action name
match rcpt-to <table> action name

A mailaddr entry is used to match an email address against a username, a domain or a full email address. A "*" wildcard may be used in part of the domain name.

A mailaddr table looks as follow:

user
@domain
user@domain
user@*.domain

Addrname tables

Addrname tables are used to map IP addresses to hostnames. They can be used in both listen context and relay context:

listen on interface hostnames <table>
action name relay helo-src <table>

In listen context, the table is used to look up the server name to advertise depending on the local address of the socket on which a connection is accepted. In relay context, the table is used to determine the hostname for the HELO sequence of the SMTP protocol, depending on the local address used for the outgoing connection.

The format is a mapping from inet4 or inet6 addresses to hostnames:

[::1]		localhost
127.0.0.1	localhost
88.190.23.165	www.opensmtpd.org

IPv6 addresses must be enclosed in square brackets.
