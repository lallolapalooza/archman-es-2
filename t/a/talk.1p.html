TALK(1P) Manual del programador POSIX TALK(1P)

PROLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

talk — hablar con otro usuario

SINOPSIS

talk direccion [terminal]

DESCRIPCIÓN

La utilidad talk es un programa de comunicación bidireccional orientado a pantalla.

Cuando se invoca por primera vez, talk enviará un mensaje similar a:

Mensaje de <cadena no especificada>
talk: conexión solicitada por tu_direccion
talk: responde con: talk tu_direccion

En este punto, el destinatario del mensaje puede responder escribiendo:

talk tu_direccion

Una vez establecida la comunicación, las dos partes pueden escribir simultáneamente, con su salida mostrada en regiones separadas de la pantalla. Los caracteres se procesarán de la siguiente manera:

*
Escribir el carácter <alerta> alertará la terminal del destinatario.
*
Escribir <control>‐L provocará que las regiones de la pantalla del remitente se actualicen.
*
Escribir los caracteres de borrado y eliminación afectará la pantalla del remitente de la manera descrita por la interfaz termios en el volumen de Definiciones Base de POSIX.1‐2017, Capítulo 11, Interfaz General de Terminal.
*
Escribir los caracteres de interrupción o fin de archivo terminará la utilidad talk local. Una vez que la sesión de talk se ha terminado en un lado, el otro lado de la sesión de talk será notificado de que la sesión de talk ha sido terminada y solo podrá salir.
*
Escribir caracteres de las clasificaciones LC_CTYPE print o space provocará que esos caracteres se envíen a la terminal del destinatario.
*
Cuando y solo cuando el modo local stty iexten esté habilitado, la existencia y el procesamiento de caracteres de control especiales adicionales o funciones multibyte o de un solo byte serán definidos por la implementación.
*
Escribir otros caracteres no imprimibles provocará que secuencias de caracteres imprimibles, definidas por la implementación, se envíen a la terminal del destinatario.

El permiso para ser destinatario de un mensaje de talk puede ser denegado o concedido mediante el uso de la utilidad mesg. Sin embargo, el privilegio de un usuario puede restringir aún más el dominio de accesibilidad de las terminales de otros usuarios. La utilidad talk fallará cuando el usuario no tenga los privilegios apropiados para realizar la acción solicitada.

Ciertas terminales de modo bloqueado no tienen todas las capacidades necesarias para soportar el intercambio simultáneo de mensajes requerido para talk. Cuando este tipo de intercambio no puede ser soportado en tales terminales, la implementación puede soportar un intercambio con niveles reducidos de interacción simultánea o puede informar un error que describa la deficiencia relacionada con la terminal.

OPCIONES

Ninguna.

OPERANDOS

Se soportarán los siguientes operandos:

direccion
El destinatario de la sesión de talk. Una forma de direccion es el <nombre de usuario>, como lo devuelve la utilidad who. Otros formatos de dirección y cómo se manejan no están especificados.
terminal
Si el destinatario ha iniciado sesión más de una vez, el operando terminal puede usarse para indicar el nombre de terminal apropiado. Si no se especifica terminal, el mensaje de talk se mostrará en una o más terminales accesibles que esté usando el destinatario. El formato de terminal será el mismo que el devuelto por la utilidad who.

ENTRADA ESTÁNDAR

Los caracteres leídos de la entrada estándar se copiarán a la terminal del destinatario de una manera no especificada. Si la entrada estándar no es una terminal, talk escribirá un mensaje de diagnóstico y saldrá con un estado distinto de cero.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de talk:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de internacionalización para la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de configuración regional.)
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la configuración regional para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a multibyte en argumentos y archivos de entrada). Si la configuración regional del destinatario no utiliza una LC_CTYPE equivalente a la del remitente, los resultados no están definidos.
LC_MESSAGES

Determina la configuración regional que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida de error estándar y los mensajes informativos escritos en la salida estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.
TERM
Determina el nombre del tipo de terminal del invocador. Si esta variable no está establecida o está vacía, se utilizará un tipo de terminal predeterminado no especificado.

EVENTOS ASÍNCRONOS

Cuando la utilidad talk recibe una señal SIGINT, la utilidad terminará y saldrá con un estado cero. Tomará la acción estándar para todas las demás señales.

SALIDA ESTÁNDAR

Si la salida estándar es una terminal, los caracteres copiados de la entrada estándar del destinatario pueden escribirse en la salida estándar. La salida estándar también puede usarse para mensajes de diagnóstico. Si la salida estándar no es una terminal, talk saldrá con un estado distinto de cero.

SALIDA DE ERROR ESTÁNDAR

Ninguna.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
Finalización exitosa.
â>0
Ocurrió un error o talk fue invocado en una terminal incapaz de soportarlo.

NAME

talk — talk to another user

SYNOPSIS

talk ttyname
talk user
talk user@host

DESCRIPTION

The talk utility provides an interactive, visual communication facility between two users on the same or different hosts. When a user initiates a talk session, the receiving user is notified (unless they have disabled notifications using mesg). The receiving user can then respond, initiating the talk session.

When the session is established, the screen is divided into two (or more) sections. The talk utility notifies the sender of the recipient's terminal type and the recipient of the sender's terminal type. The talk utility then copies lines of text typed by each user to the other user's screen. Typically, the sender's input is displayed in the lower part of the screen and the recipient's input is displayed in the upper part.

The talk utility handles control characters that may be sent by the other user. If the receiving user has enabled write permission (using mesg), the sending user's terminal is used to display the text. Otherwise, a message is sent to the user indicating that write permission is denied.

OPTIONS

None.

OPERANDS

The following operands are supported:

ttyname
The login name or terminal name of the user to whom to talk. If ttyname is specified without a host, the default is the local host. The format of ttyname is implementation-defined, but should be the same format used by who.
user
The login name of the user to whom to talk. If user is specified without a host, the default is the local host.
user@host
The login name of the user to whom to talk on the specified host. The format of host is implementation-defined.

STDIN

Not used.

INPUT FILES

None.

ENVIRONMENT VARIABLES

The following environment variables affect the execution of talk:

COLUMNS
Determines the number of columns used for displaying text.
LINES
Determines the number of rows used for displaying text.
TERMIN
Determines the type of terminal being used.

ASYNCHRONOUS EVENTS

None.

STDOUT

The standard output is used to display the lines of text typed by the other user.

STDERR

The standard error is used for diagnostic messages.

OUTPUT FILES

None.

None.

None.

RATIONALE

The write utility was included in this volume of POSIX.1‐2017 since it can be implemented on all terminal types. The talk utility, which cannot be implemented on certain terminals, was considered to be a ``better'' communications interface. Both of these programs are in widespread use on historical implementations. Therefore, both utilities have been specified.

All references to networking abilities (talking to a user on another system) were removed as being outside the scope of this volume of POSIX.1‐2017.

Historical BSD and System V versions of talk terminate both of the conversations when either user breaks out of the session. This can lead to adverse consequences if a user unwittingly continues to enter text that is interpreted by the shell when the other terminates the session. Therefore, the version of talk specified by this volume of POSIX.1‐2017 requires both users to terminate their end of the session explicitly.

Only messages sent to the terminal of the invoking user can be internationalized in any way:

*
The original ``Message from <unspecified string> ...'' message sent to the terminal of the recipient cannot be internationalized because the environment of the recipient is as yet inaccessible to the talk utility. The environment of the invoking party is irrelevant.
*
Subsequent communication between the two parties cannot be internationalized because the two parties may specify different languages in their environment (and non-portable characters cannot be mapped from one language to another).
*
Neither party can be required to communicate in a language other than C and/or the one specified by their environment because unavailable terminal hardware support (for example, fonts) may be required.

The text in the STDOUT section reflects the usage of the verb ``display'' in this section; some talk implementations actually use standard output to write to the terminal, but this volume of POSIX.1‐2017 does not require that to be the case.

The format of the terminal name is unspecified, but the descriptions of ps, talk, who, and write require that they all use or accept the same format.

The handling of non-printable characters is partially implementation-defined because the details of mapping them to printable sequences is not needed by the user. Historical implementations, for security reasons, disallow the transmission of non-printable characters that may send commands to the other terminal.
