TAPESTAT(1) Manual de usuario de Linux TAPESTAT(1)

NOMBRE

tapestat - Informar estadísticas de cinta.

SINOPSIS

tapestat [ -k | -m ] [ -t ] [ -U ] [ -V ] [ -y ] [ -z ] [ --human ] [ -o JSON ] [ intervalo [ contador ] ]

DESCRIPCIÓN

El comando tapestat se utiliza para monitorizar la actividad de las unidades de cinta conectadas a un sistema.

El primer informe generado por el comando tapestat proporciona estadísticas relativas al tiempo transcurrido desde el arranque del sistema, a menos que se utilice la opción -y, en cuyo caso se omite este primer informe. Cada informe subsiguiente cubre el tiempo transcurrido desde el informe anterior.

El parámetro intervalo especifica la cantidad de tiempo en segundos entre cada informe. El parámetro contador se puede especificar junto con el parámetro intervalo. Si se especifica el parámetro contador, su valor determina el número de informes generados a intervalos de intervalo segundos. Si se especifica el parámetro intervalo sin el parámetro contador, el comando tapestat genera informes de forma continua.

INFORME

El informe tapestat proporciona estadísticas para cada unidad de cinta conectada al sistema. Se muestran los siguientes datos:

r/s
El número de lecturas emitidas expresado como el número por segundo promedio durante el intervalo.
w/s
El número de escrituras emitidas expresado como el número por segundo promedio durante el intervalo.
kB_read/s | MB_read/s
La cantidad de datos leídos expresada en kibibytes (por defecto o si se utiliza la opción -k) o mebibytes (si se utiliza la opción -m) por segundo promedio durante el intervalo.
kB_wrtn/s | MB_wrtn/s
La cantidad de datos escritos expresada en kibibytes (por defecto o si se utiliza la opción -k) o mebibytes (si se utiliza la opción -m) por segundo promedio durante el intervalo.
%Rd
Porcentaje de espera de lectura: El porcentaje de tiempo durante el intervalo dedicado a esperar a que se completen las solicitudes de lectura. El tiempo se mide desde que la solicitud se envía a la capa intermedia de SCSI hasta que indica que se ha completado.
%Wr
Porcentaje de espera de escritura: El porcentaje de tiempo durante el intervalo dedicado a esperar a que se completen las solicitudes de escritura. El tiempo se mide desde que la solicitud se envía a la capa intermedia de SCSI hasta que indica que se ha completado.
%Oa
Porcentaje de espera general: El porcentaje de tiempo durante el intervalo dedicado a esperar a que se complete cualquier solicitud de E/S (lectura, escritura y otras).
Rs/s
El número de E/S, expresado como el número por segundo promedio durante el intervalo, en el que se encontró un valor residual distinto de cero.
Ot/s
El número de E/S, expresado como el número por segundo promedio durante el intervalo, que se incluyeron como "otras". Otras E/S incluyen las llamadas ioctl realizadas al controlador de cinta y las operaciones implícitas realizadas por el controlador de cinta, como el rebobinado al cerrar (para dispositivos de cinta que implementan el rebobinado al cerrar). No incluye ninguna E/S realizada utilizando métodos fuera del controlador de cinta (por ejemplo, a través de ioctls sg).

OPCIONES

--human
Muestra los tamaños en formato legible por humanos (por ejemplo, 1.0k, 1.2M, etc.). Las unidades mostradas con esta opción anulan cualquier otra unidad predeterminada (por ejemplo, kibibytes, sectores...) asociada a las métricas.
-k
Muestra la cantidad de datos escritos o leídos en kibibytes por segundo en lugar de mebibytes. Esta opción es mutuamente excluyente con -m.
-m
Muestra la cantidad de datos escritos o leídos en mebibytes por segundo en lugar de kibibytes. Esta opción es mutuamente excluyente con -k.
-o JSON
Muestra las estadísticas en formato JSON (JavaScript Object Notation). El orden de los campos de salida JSON no está definido y se pueden agregar nuevos campos en el futuro.
-t
Muestra marcas de tiempo. El formato de la marca de tiempo puede depender del valor de la variable de entorno S_TIME_FORMAT (ver más abajo) y de si se ha utilizado la opción -U.
-U
Muestra la marca de tiempo (UTC - Hora Universal Coordinada) en segundos desde la época.
-V
Imprime la versión y sale.
-y
Omite la estadística inicial que muestra los valores desde el arranque.
-z
Indica a tapestat que omita la salida para cualquier cinta en la que no haya habido actividad durante el período de muestreo.

CONSIDERACIONES

Es posible que un valor porcentual (lectura, escritura u otro) sea mayor que el 100 por ciento (el comando tapestat nunca mostrará un valor porcentual superior a 999). Si el rebobinado de una cinta tarda 40 segundos y el tiempo de intervalo es de 5 segundos, el valor %Oa será 0 en los intervalos antes de que el rebobinado se complete, y luego mostrará aproximadamente 800 por ciento cuando el rebobinado se complete.

Se observarán valores similares para %Rd y %Wr si una unidad de cinta deja de leer o escribir y luego se reinicia (es decir, deja de transmitir). En tal caso, puede ver que r/s o w/s caen a cero y el valor de %Rd/%Wr podría ser superior al 100 cuando la lectura o escritura continúa (dependiendo de cuánto tiempo tarde en reiniciarse la escritura o la lectura). Esto solo es un problema si ocurre con mucha frecuencia, ya que puede causar desgaste de la cinta e impactar en los tiempos de copia de seguridad.

Para unidades de cinta rápidas, es posible que vea tiempos de espera porcentuales bajos. Esto no indica un problema con la unidad de cinta. Para una unidad de cinta más lenta (por ejemplo, una unidad DDS de generación anterior), la velocidad de la cinta (y de la unidad de cinta) es mucho menor que la E/S del sistema de archivos, los tiempos de espera porcentuales probablemente serán más altos. Para unidades de cinta más rápidas (por ejemplo, LTO), los tiempos de espera porcentuales probablemente serán más bajos, ya que el programa que escribe o lee de la cinta realizará mucha más E/S del sistema de archivos debido al mayor rendimiento.

Aunque las estadísticas de cinta se implementan en el kernel utilizando variables atómicas, no se pueden leer de forma atómica como grupo. Todos los valores de estadísticas se leen de diferentes archivos bajo /sys. Debido a esto, puede haber finalizaciones de E/S mientras se leen los diferentes archivos para la misma unidad de cinta. Esto puede resultar en un conjunto de estadísticas para un dispositivo que contenga algunos valores antes de que se complete una E/S y algunos después.

Este comando utiliza el redondeo hacia abajo como método de redondeo al calcular estadísticas por segundo. Si, por ejemplo, está utilizando dd para copiar una cinta a otra y está ejecutando tapestat con un intervalo de 5 segundos, y durante el intervalo hubo 3210 escrituras y 3209 lecturas, entonces w/s mostraría 642 y r/s 641 (641.8 redondeado hacia abajo a 641). En tal caso, si se tratara de un archivo tar copiado (con un tamaño de bloque de 10k), también vería una diferencia entre kB_read/s y kB_wrtn/s de 2 (una E/S de 10k de tamaño dividida por el período de intervalo de 5 segundos). Si en cambio hubo 3210 escrituras y 3211 lecturas, tanto w/s como r/s mostrarían 642, pero aún así vería una diferencia entre los valores de kB_read/s y kB_wrtn/s de 2 kB/s.

Este comando utiliza un intervalo en segundos. Sin embargo, internamente el intervalo se rastrea por dispositivo y puede tener un efecto en las estadísticas por segundo reportadas. El tiempo en que se captura cada conjunto de estadísticas se mantiene con esas estadísticas. La diferencia entre el tiempo actual y el anterior se convierte a milisegundos para su uso en cálculos. Podemos ver cómo esto puede afectar las estadísticas reportadas si usamos un ejemplo de un archivo tar copiándose entre dos unidades de cinta usando dd. Si ambos dispositivos reportaron 28900 kibibytes transferidos y la unidad de cinta que lee tuvo un intervalo de 5001 milisegundos y la unidad de cinta que escribe 5000 milisegundos, eso calcularía 5778 kB_read/s y 5780 kB_wrtn/s.

CONSIDERATIONS

Les statistiques de bande sont collectées à partir du système de fichiers /sys. Il se peut que ces données ne soient pas complètement synchronisées avec les opérations d'E/S d'une bande lorsqu'un périphérique de bande est en cours d'utilisation. Certaines informations, telles que la latence de l'E/S, peuvent ne pas être disponibles.

La latence des E/S est calculée à partir de la différence entre l'heure d'achèvement d'une E/S et l'heure à laquelle la demande d'E/S a été soumise. La latence peut ne pas être complètement précise en raison de la façon dont le noyau Linux gère les événements d'achèvement des E/S, de l'arrondi à la valeur inférieure et des petites différences dans la période d'intervalle des statistiques calculées. Ces différences devraient être minimales, mais peuvent être non nulles.

ENVIRONMENT

La commande tapestat prend en compte les variables d'environnement suivantes :

S_COLORS
Par défaut, les statistiques sont affichées en couleur lorsque la sortie est connectée à un terminal. Utilisez cette variable pour modifier les paramètres. Les valeurs possibles pour cette variable sont never, always ou auto (cette dernière équivaut aux paramètres par défaut).
Veuillez noter que la couleur (rouge, jaune ou une autre couleur) utilisée pour afficher une valeur n'indique pas un problème simplement en raison de la couleur. Elle indique uniquement différentes plages de valeurs.
S_COLORS_SGR
Spécifiez les couleurs et autres attributs utilisés pour afficher les statistiques sur le terminal. Sa valeur est une liste de capacités séparées par des deux-points, par défaut I=32;22:N=34;1:W=35;1:X=31;1:Z=34;22. Les capacités prises en charge sont :
I=
Sous-chaîne SGR (Select Graphic Rendition) pour les noms de bande.
N=
Sous-chaîne SGR pour les valeurs de statistiques non nulles.
W= (o M=)
Sous-chaîne SGR pour les valeurs de pourcentage comprises entre 75 % et 90 % (ou dans la plage de 10 % à 25 % selon la signification de la métrique).
X= (o H=)
Sous-chaîne SGR pour les valeurs de pourcentage supérieures ou égales à 90 % (ou inférieures ou égales à 10 % selon la signification de la métrique).
Z=
Sous-chaîne SGR pour les valeurs nulles.
S_TIME_FORMAT
Si cette variable existe et que sa valeur est ISO, la locale actuelle sera ignorée lors de l'impression de la date dans l'en-tête du rapport. La commande tapestat utilisera à la place le format ISO 8601 (AAAA-MM-JJ). L'horodatage affiché avec l'option -t sera également conforme au format ISO 8601.

BUGS

Le système de fichiers /sys doit être monté pour que tapestat fonctionne. Il ne fonctionnera pas sur des noyaux qui ne prennent pas en charge sysfs.

Cette commande nécessite le noyau version 4.2 ou ultérieure (ou le support des statistiques de bande rétrofité pour une version de noyau antérieure).

Bien que tapestat affiche des unités correspondant aux kilooctets (kB), mégaoctets (MB)..., il utilise en réalité des kibioctets (kiB), mébioctets (MiB)... Un kibioctet est égal à 1024 octets, et un mébioctet est égal à 1024 kibioctets.

FILES

/sys/class/scsi_tape/st<num>/stats/*

Fichiers de statistiques pour les périphériques de bande.

/proc/uptime contient la durée de fonctionnement du système.
