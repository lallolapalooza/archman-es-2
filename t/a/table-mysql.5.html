TABLE_MYSQL(5) Manual de formatos de archivo TABLE_MYSQL(5)

NOMBRE

table_mysql — descripción del formato para tablas MySQL o MariaDB de smtpd

DESCRIPCIÓN

Esta página del manual documenta el formato de archivo de las tablas MySQL o MariaDB utilizadas por el demonio de correo smtpd(8).

El formato descrito aquí se aplica a las tablas definidas en smtpd.conf(5).

TABLA MYSQL

Una tabla mysql permite almacenar nombres de usuario, contraseñas, alias y dominios en un formato que se puede compartir entre varias máquinas que soportan mysql(1).

La tabla es utilizada por smtpd(8) al autenticar a un usuario, cuando se requiere información de usuario como el ID de usuario y/o el directorio principal para una entrega, cuando puede ser necesaria una búsqueda de dominio, y/o al buscar un alias.

Una tabla MySQL consiste en una o más bases de datos mysql(1) con una o más tablas.

Si la tabla se utiliza para la autenticación, la contraseña debe estar cifrada utilizando la función crypt(3). Dichas contraseñas se pueden generar utilizando la utilidad encrypt(1) o el comando smtpctl(8) encrypt.

ARCHIVO DE CONFIGURACIÓN DE TABLAS MYSQL

Las siguientes opciones de configuración están disponibles:

host nombre_host
Este es el host que ejecuta MySQL o MariaDB. Por ejemplo: 
host db.example.com
username nombre_usuario
El nombre de usuario requerido para comunicarse con la base de datos MySQL o MariaDB. Por ejemplo: 
username maildba
password contraseña
La contraseña requerida para comunicarse con la base de datos MySQL o MariaDB. Por ejemplo: 
password OpenSMTPDRules!
database base_datos
El nombre de la base de datos MySQL o MariaDB. Por ejemplo: 
databse opensmtpdb
query_alias sentencia_SQL
Se utiliza para proporcionar una consulta para buscar alias. El signo de interrogación se reemplaza con los datos apropiados. Para alias, es el lado izquierdo de la dirección SMTP. Espera que se devuelva un VARCHAR con el nombre de usuario al que se resuelve el alias.
query_credentials sentencia_SQL
Se utiliza para proporcionar una consulta para buscar las credenciales del usuario. El signo de interrogación se reemplaza con los datos apropiados. Para credenciales, es el lado izquierdo de la dirección SMTP. La consulta espera que se devuelvan dos VARCHAR, uno con un nombre de usuario y otro con una contraseña en formato crypt(3).
query_domain sentencia_SQL
Se utiliza para proporcionar una consulta para buscar un dominio. El signo de interrogación se reemplaza con los datos apropiados. Para el dominio, sería el lado derecho de la dirección SMTP. Espera que se devuelva un VARCHAR con un nombre de dominio coincidente.
query_mailaddrmap sentencia_SQL
Se utiliza para proporcionar una consulta para buscar remitentes. El signo de interrogación se reemplaza con los datos apropiados. Espera que se devuelva un VARCHAR con la dirección desde la cual el remitente tiene permiso para enviar correos.

Una sentencia SQL genérica sería algo como:

query_ SELECT value FROM table WHERE key=?;

EJEMPLOS

EJEMPLO GENÉRICO

Ejemplo basado en las FAQ de OpenSMTPD: Creación de un Servidor de Correo. La parte de filtrado se excluye en este ejemplo.

La configuración a continuación es para un servidor de correo de tamaño mediano que maneja múltiples dominios con múltiples usuarios virtuales y se basa en varias suposiciones. Una de ellas es que se utiliza un solo usuario del sistema llamado vmail para todos los usuarios virtuales. Este usuario necesita ser creado:

# useradd -g =uid -c "Virtual Mail" -d /var/vmail -s /sbin/nologin vmail
# mkdir /var/vmail
# chown vmail:vmail /var/vmail

Esquema de MySQL

CREATE TABLE domains (
  id INT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  domain VARCHAR(255) NOT NULL DEFAULT ''
);
CREATE TABLE virtuals (
    id INT AUTO_INCREMENT PRIMARY KEY,
    email VARCHAR(255) NOT NULL DEFAULT '',
    destination VARCHAR(255) NOT NULL DEFAULT ''
);
CREATE TABLE credentials (
    id INT AUTO_INCREMENT PRIMARY KEY,
    email VARCHAR(255) NOT NULL DEFAULT '',
    password VARCHAR(255) NOT NULL DEFAULT ''
);
INSERT INTO domains VALUES (1, "example.com");
INSERT INTO domains VALUES (2, "example.net");
INSERT INTO domains VALUES (3, "example.org");

INSERT INTO virtuals VALUES (1, "abuse@example.com", "bob@example.com");
INSERT INTO virtuals VALUES (2, "postmaster@example.com", "bob@example.com");
INSERT INTO virtuals VALUES (3, "webmaster@example.com", "bob@example.com");
INSERT INTO virtuals VALUES (4, "bob@example.com", "vmail");
INSERT INTO virtuals VALUES (5, "abuse@example.net", "alice@example.net");
INSERT INTO virtuals VALUES (6, "postmaster@example.net", "alice@example.net");
INSERT INTO virtuals VALUES (7, "webmaster@example.net", "alice@example.net");
INSERT INTO virtuals VALUES (8, "alice@example.net", "vmail");

INSERT INTO credentials VALUES (1, "bob@example.com", "$2b$08$ANGFKBL.BnDLL0bUl7I6aumTCLRJSQluSQLuueWRG.xceworWrUIu");
INSERT INTO credentials VALUES (2, "alice@example.net", "$2b$08$AkHdB37kaj2NEoTcISHSYOCEBA5vyW1RcD8H1HG.XX0P/G1KIYwii");

/etc/mail/mysql.conf

host db.example.com
username maildba
password OpenSMTPDRules!
database opensmtpdb
query_alias SELECT destination FROM virtuals WHERE email=?;
query_credentials SELECT email, password FROM credentials WHERE email=?;
query_domain SELECT domain FROM domains WHERE domain=?;

/etc/mail/smtpd.conf

table domains mysql:/etc/mail/mysql.conf
table virtuals mysql:/etc/mail/mysql.conf
table credentials mysql:/etc/mail/mysql.conf
listen on egress port 25 tls pki mail.example.com
listen on egress port 587 tls-require pki mail.example.com auth <credentials>
accept from any for domain <domains> virtual <virtuals> deliver to mbox

NAME


table-mysql


- MySQL table file format






DESCRIPTION


The table-mysql program is a table lookup
    backend for OpenSMTPD, allowing it to use MySQL databases as a source for
    various lookup tables like virtual domains, aliases, users, etc.


A MySQL table is configured in smtpd.conf(5)
    using the following format:


table mysql:<mysql_config_file> <table_type>



Where <mysql_config_file> is a file
    containing the database connection parameters, and <table_type>
    specifies the type of table being configured.






MYSQL TABLE


The table-mysql program supports the following
    table types:




address


Used for mapping email addresses to other email addresses. The table should
        contain a column for the recipient address and a column for the replacement
        address.


domain


Used for mapping domains to other domains. The table should contain a column
        for the domain name and a column for the replacement domain name.


file


Used for mapping filenames to other filenames. The table should contain a
        column for the filename and a column for the replacement filename.


group


Used for mapping user accounts to groups. The table should contain a column
        for the username and a column for the group name.


mac


Used for mapping MAC addresses to other MAC addresses. The table should
        contain a column for the MAC address and a column for the replacement
        MAC address.


netgroup


Used for mapping netgroups to other netgroups. The table should contain a
        column for the netgroup name and a column for the replacement netgroup
        name.


password


Used for mapping usernames to passwords. The table should contain a column
        for the username and a column for the password.


user


Used for mapping usernames to other usernames. The table should contain a
        column for the username and a column for the replacement username.








MYSQL TABLE CONFIG FILE


The MySQL configuration file is a plain text file containing
    connection parameters for the MySQL database. Each parameter should be on a
    separate line, in the format key value.


The following keys are supported:




host


The hostname or IP address of the MySQL server.


port


The port number of the MySQL server. Defaults to 3306.


user


The username to use when connecting to the MySQL server.


password


The password to use when connecting to the MySQL server.


database


The name of the MySQL database to use.


table


The name of the table to query within the database.


key_column


The name of the column containing the key to search for.


value_column


The name of the column containing the value to return.


query


A custom SQL query to execute. If specified, the key_column
        and value_column directives are ignored. The query
        should contain a placeholder %s for the key being
        looked up.








EXAMPLES


The following example configures a virtual domain table using a
    MySQL database:


table vdom mysql:/etc/smtpd/mysql_vdom.conf domain



And the corresponding /etc/smtpd/mysql_vdom.conf
    file:


host      127.0.0.1
user      smtpd
password  secret
database  mail
table     virtual_domains
key_column  domain
value_column  domain



This configuration will query the virtual_domains
    table for entries where the domain column matches the
    incoming domain, and return the value from the domain
    column.


The following example configures an alias table using a custom
    query:


table aliases mysql:/etc/smtpd/mysql_aliases.conf address



And the corresponding /etc/smtpd/mysql_aliases.conf
    file:


host      127.0.0.1
user      smtpd
password  secret
database  mail
query     SELECT target FROM aliases WHERE source = '%s'







FILES


/etc/smtpd/mysql_*.conf: MySQL configuration
    files.
