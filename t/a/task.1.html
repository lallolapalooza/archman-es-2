NOMBRE

task - Un gestor de tareas pendientes por línea de comandos.

SINOPSIS

task <filtro> <comando> [ <modificadores> | <argumentos> ]
task --version

DESCRIPCIÓN

Taskwarrior es un gestor de listas de tareas pendientes por línea de comandos. Mantiene una lista de tareas que deseas realizar, permitiéndote añadirlas/eliminarlas y manipularlas de otras formas. Taskwarrior tiene un rico conjunto de subcomandos que te permiten hacer diversas cosas con él.

En esencia, Taskwarrior es un programa de procesamiento de listas. Añades texto y parámetros adicionales relacionados, y redisplay las informaciones de una manera agradable. Se convierte en un programa de lista de tareas pendientes cuando añades fechas de vencimiento y recurrencia. Se convierte en un programa de lista de tareas pendientes organizado cuando añades prioridades, etiquetas (descriptores de una palabra), grupos de proyectos, etc.

FILTRO

El <filtro> consiste en cero o más criterios de búsqueda que seleccionan tareas. Por ejemplo, para listar todas las tareas pendientes que pertenecen al proyecto 'Casa':

  task project:Home list

Puedes especificar múltiples términos de filtro, cada uno de los cuales restringe aún más el resultado:

  task project:Home +weekend garden list

Este ejemplo aplica tres filtros: el proyecto 'Home', la etiqueta 'weekend', y la descripción o anotaciones deben contener la secuencia de caracteres 'garden'. En este ejemplo, 'garden' se traduce internamente a:

  description.contains:garden

como un atajo conveniente. El 'contains' aquí es un modificador de atributo, que se utiliza para ejercer un mayor control sobre el filtro que la mera ausencia o presencia. Consulta la sección 'MODIFICADORES DE ATRIBUTOS' más abajo para obtener una lista completa de modificadores.

Ten en cuenta que un filtro puede tener cero términos, lo que significa que todas las tareas se aplican al comando. Esto puede ser peligroso, y este caso especial se confirma y no puede anularse. Por ejemplo, este comando:

  task modify +work
  Este comando no tiene filtro y modificará todas las tareas. ¿Estás seguro? (sí/no)

añadirá la etiqueta 'work' a todas las tareas, pero solo después de la confirmación.

Más ejemplos de filtros:

  task                                      <comando> <modificadores>
  task 28                                   <comando> <modificadores>
  task +weekend                             <comando> <modificadores>
  task +bills due.by:eom                    <comando> <modificadores>
  task project:Home due.before:today        <comando> <modificadores>
  task ebeeab00-ccf8-464b-8b58-f7f2d606edfb <comando> <modificadores>

Por defecto, los elementos del filtro se combinan con un operador 'y' implícito, pero también se pueden usar 'o' y 'xor', siempre que se incluyan paréntesis:

  task '( /[Cc]at|[Dd]og/ or /[0-9]+/ )'      <comando> <modificadores>

Los paréntesis aíslan el término lógico de cualquier filtro de comando predeterminado o filtro de informe implícito que se combinaría con un 'y' implícito.

Un filtro puede dirigirse a tareas específicas utilizando números de ID o UUID. Para especificar varias tareas, utiliza una de estas formas (lista separada por espacios de números de ID, números UUID o rangos de ID):

  task 1 2 3                                    delete
  task 1-3                                      info
  task 1 2-5 19                                 modify pri:H
  task 4-7 ebeeab00-ccf8-464b-8b58-f7f2d606edfb info

Ten en cuenta que puede ser necesario escapar correctamente los caracteres especiales, así como las comillas, para evitar sus significados especiales en la shell. Consulta también la sección 'ESPECIFICACIÓN DE DESCRIPCIONES' para obtener más información.

MODIFICACIONES

Los <modificadores> consisten en cero o más cambios a aplicar a las tareas seleccionadas, como:

  task <filtro> <comando> project:Home
  task <filtro> <comando> +weekend +garden due:tomorrow
  task <filtro> <comando> Texto de descripción/anotación
  task <filtro> <comando> /de/a/     <- reemplazar primera coincidencia
  task <filtro> <comando> /de/a/g    <- reemplazar todas las coincidencias

SUBCOMANDOS

Taskwarrior soporta diferentes tipos de comandos. Hay comandos de lectura, comandos de escritura, comandos misceláneos y comandos auxiliares de script. Los comandos de lectura no permiten la modificación de tareas. Los comandos de escritura pueden alterar casi cualquier aspecto de una tarea. Los comandos auxiliares de script se proporcionan para ayudarte a escribir scripts adicionales, por ejemplo, autocompletado de shell (solo se genera una salida mínima, como con verbose=nothing). Aquellos comandos que se ven explícitamente afectados por el *contexto* se denotan como tales.

SUBCOMANDOS DE LECTURA

Los informes son subcomandos de lectura. Actualmente hay varios informes predefinidos en Taskwarrior. La salida y el comportamiento de ordenación de estos informes se pueden configurar en el archivo de configuración. Consulta también la página del manual taskrc(5). También hay otros subcomandos de lectura que no son informes.

Este es el único argumento de línea de comandos convencional que soporta Taskwarrior, y está destinado a scripts adicionales para verificar el número de versión de una instalación de Taskwarrior sin invocar los mecanismos que crean archivos predeterminados.

task calendar [due|<mes> <año>|<año>] [y]

task colors [<muestra> | legend]

task <filtro> ids
Aplica el filtro y extrae solo los IDs de las tareas, presentándolos como una lista separada por espacios. Esto es útil como entrada para un comando de tarea, para lograr esto: 
  task $(task project:Home ids) modify priority:H

Este ejemplo primero obtiene los IDs para el filtro project:Home, luego establece la prioridad en H para cada una de esas tareas. Esto también se puede lograr directamente:

  task project:Home modify priority:H

Este comando es principalmente de utilidad para scripts externos.

task <filtro> uuids
Aplica el filtro en todas las tareas (incluso las eliminadas y completadas) y luego extrae solo los UUIDs de las tareas, presentándolos como una lista separada por espacios. Esto es útil como entrada para un comando de tarea, para lograr esto: 
  task $(task project:Home status:completed uuids) modify status:pending

Este ejemplo primero obtiene los UUIDs para los filtros project:Home y status:completed, y luego vuelve a poner en pendiente cada una de esas tareas.

Este comando es principalmente de utilidad para scripts externos.

SUBCOMANDOS DE ESCRITURA

task add <mods>
Agrega una nueva tarea pendiente a la lista de tareas. Se ve afectada por el contexto establecido actualmente.
task <filtro> annotate <mods>
Agrega una anotación a una tarea existente.
task <filtro> append <mods>
Agrega texto de descripción al final de una tarea existente.
task <filtro> delete <mods>
Elimina la tarea especificada de la lista de tareas. Se ve afectada por el contexto.
task <filtro> denotate <mods>
Elimina una anotación de la tarea especificada. Si la descripción proporcionada coincide exactamente con una anotación, se elimina la anotación correspondiente. Si la descripción proporcionada coincide parcialmente con anotaciones, se elimina la primera anotación que coincida parcialmente. Se ve afectada por el contexto.
task <filtro> done <mods>
Marca la tarea especificada como completada. Se ve afectada por el contexto.
task <filtro> duplicate <mods>
Duplica la tarea especificada y permite modificaciones. Se ve afectada por el contexto.
task <filtro> edit
Inicia un editor de texto para permitirle modificar todos los aspectos de una tarea directamente. En general, este no es el método recomendado para modificar tareas, pero se proporciona para circunstancias excepcionales. Úselo con cuidado. Se ve afectado por el contexto.
task import [<archivo> ...]
Importa tareas en formato JSON. Se puede utilizar para agregar nuevas tareas o actualizar las existentes. Las tareas se identifican por su UUID.

Si no se especifica ningún archivo o '-', importa tareas desde STDIN.

Se recomienda configurar rc.recurrence.confirmation a un nivel apropiado si la importación se va a utilizar en flujos de trabajo automatizados. Ver taskrc(5).

Para importar otros formatos de archivo, la versión estándar de Taskwarrior viene con algunos scripts de ejemplo, como:

  import-todo.sh.pl
  import-yaml.pl
task import-v2
Importa tareas del formato de Taskwarrior v2.x. Esto se utiliza al actualizar de la versión 2.x a la versión 3.x.
task log <mods>
Agrega una nueva tarea que ya está completada a la lista de tareas. Se ve afectada por el contexto actualmente establecido.
task <filtro> modify <mods>
Modifica la tarea existente con la información proporcionada.
task <filtro> prepend <mods>
Agrega texto de descripción al principio de una tarea existente. Se ve afectada por el contexto.
task <filtro> purge
Elimina permanentemente las tareas especificadas de los archivos de datos. Solo las tareas que ya están eliminadas pueden ser purgadas. Este comando tiene un efecto solo local y los cambios introducidos por él no se sincronizan. Se ve afectado por el contexto.

Advertencia: causa una pérdida de datos permanente y no revertible.

task <filtro> start <mods>
Marca las tareas especificadas como iniciadas. Se ve afectada por el contexto.
task <filtro> stop <mods>
Elimina la hora de inicio de la tarea especificada. Se ve afectada por el contexto.

SUBCOMANDOS MISCELÁNEOS

Los subcomandos misceláneos o no aceptan argumentos de línea de comandos, o aceptan argumentos no estándar.

task calc <expresion>
Evalúa una expresión algebraica. Puede usarse para probar cómo Taskwarrior interpreta y evalúa la expresión dada en la línea de comandos.

Ejemplos:

    task calc 1 + 1
    2
    task calc now + 8d
    2015-03-26T18:06:57
    task calc eom
    2015-03-31T23:59:59
task config [<nombre> [<;value> | '']]
Añade, modifica y elimina configuraciones directamente en el archivo de configuración de Taskwarrior. Este comando modifica la configuración 'nombre' con un nuevo valor de 'valor', o añade una nueva entrada que es equivalente a 'nombre=valor': 
    task config nombre valor

Este comando establece un valor en blanco. Esto tiene el efecto de suprimir cualquier valor predeterminado:

    task config nombre ''

Finalmente, este comando elimina cualquier entrada 'nombre=...' del archivo .taskrc:

    task config nombre
task context <nombre>
Establece el contexto activo actualmente. Ver la sección CONTEXTO.

Ejemplo:

    task context trabajo
task context delete <nombre>
Elimina el contexto con el nombre <nombre>. Si el contexto que se elimina está actualmente establecido como activo, se deshará.

Ejemplo:

    task context delete trabajo
task context define <nombre> <filtro>
Define un nuevo contexto con el nombre <nombre> y la definición <filtro>. Este comando no afecta al contexto establecido actualmente, solo añade una nueva definición de contexto.

Ejemplos:

    task context define trabajo project:Trabajo
    task context define casa project:Casa or +casa
    task context define superurgente due:today and +urgente
task context list
Muestra una lista de los contextos disponibles junto con sus definiciones.
task context none
Borra el contexto activo actualmente, si hay alguno establecido.
task context show
Muestra el contexto activo actualmente, junto con su definición.
task diagnostics
Muestra información de diagnóstico, del tipo necesario al informar de un problema. Cuando informes de un error, es probable que la plataforma, la versión y el entorno sean importantes. Ejecutar este comando genera un resumen de información similar que debería acompañar a un informe de error.

Incluye información del compilador, bibliotecas y software. No incluye ninguna información personal, aparte de la ubicación de tus datos de tareas.

Este comando también realiza un escaneo de diagnóstico de tus datos buscando problemas comunes, como UUIDs duplicados.

task execute <comando externo>
Ejecuta el comando especificado. No es útil por sí solo, pero cuando se usa en conjunción con alias y extensiones puede proporcionar una integración sin fisuras.
task logo
Muestra el logo de Taskwarrior.
task news
Guía al usuario a través de las notas de lanzamiento importantes cada vez que se instala una nueva versión de Taskwarrior. Proporciona comentarios personalizados, advertencias de desuso y consejos de uso, cuando corresponda.
task reports
Lista todos los informes compatibles. Esto incluye los informes integrados y cualquier informe personalizado que hayas definido.
task show [all | <substring>]
Muestra todas las configuraciones actuales. Si se especifica una subcadena, solo se mostrarán las configuraciones que contengan esa subcadena.
task <filtro> stats
Muestra estadísticas de las tareas definidas por el filtro. Está afectado por el contexto.
task <filtro> summary
Muestra un informe del estado agregado de las tareas por proyecto. Está afectado por el contexto.
task sync
El comando sync sincroniza los datos con el Taskserver, si está configurado.

Nota: Si usas múltiples clientes de sincronización, asegúrate de que esta configuración (que es la predeterminada) esté en tu cliente principal:

  recurrence=on

y en todos los demás clientes (esta no es la predeterminada):

  recurrence=off

Esto es una solución para evitar un error de recurrencia que duplica tareas recurrentes.

task <filtro> tags
Muestra una lista de todas las etiquetas utilizadas. Cualquier etiqueta especial utilizada se resalta. Ten en cuenta que las etiquetas virtuales no se listan - realmente no existen, y son solo una notación conveniente para otros metadatos de tareas. Es un error intentar añadir o eliminar una etiqueta virtual. Está afectado por el contexto.
task timesheet [<semanas>]
Muestra un informe semanal de tareas completadas y comenzadas.
task undo
Revierte la acción más reciente. Obedece la configuración de confirmación.
task version
Muestra el número de versión de Taskwarrior.

  tw.program
  tw.args
  tw.width
  tw.height

ATRIBUTOS Y METADATOS

ID
Las tareas se pueden especificar de forma única mediante IDs, que son los índices del "conjunto de trabajo" de tareas (principalmente tareas pendientes y recurrentes). El ID de una tarea puede cambiar, pero solo cuando se ejecuta un informe que muestra IDs. Al modificar tareas, es seguro confiar en el último ID mostrado. Ejecuta siempre un informe para comprobar que tienes el ID correcto para una tarea. Los IDs se pueden dar a task como una secuencia, por ejemplo: 
task 1,4-10,19 delete
+etiqueta|-etiqueta
Las etiquetas son palabras arbitrarias asociadas a una tarea. Usa + para añadir una etiqueta y - para eliminar una etiqueta de una tarea. Una tarea puede tener cualquier cantidad de etiquetas.

TAGS ESPECIALES

Los tags especiales se utilizan para filtrar las tareas. Los tags especiales son:

+nocolor
Deshabilita el procesamiento de reglas de color para esta tarea.
+nonag
La finalización de esta tarea suprime todos los mensajes de recordatorio.
+nocal
Esta tarea no aparecerá en el calendario.
+next
Eleva la tarea para que aparezca en el informe 'next' (siguiente).

También existen tags virtuales, que representan metadatos de tareas en forma de tag. Estos tags no existen, pero se pueden usar para filtrar tareas. Los tags virtuales admitidos son:

    ACTIVE       Coincide si la tarea está iniciada
    ANNOTATED    Coincide si la tarea tiene anotaciones
    BLOCKED      Coincide si la tarea está bloqueada
    BLOCKING     Coincide si la tarea está bloqueando
    CHILD        Coincide si la tarea tiene un padre (obsoleto en 2.6.0)
    COMPLETED    Coincide si la tarea tiene estado completado
    DELETED      Coincide si la tarea tiene estado eliminado
    DUE          Coincide si la tarea vence en los próximos 7 días (Ver rc.due)
    INSTANCE     Coincide si la tarea es una instancia recurrente
    LATEST       Coincide si la tarea es la tarea añadida más reciente
    MONTH        Coincide si la tarea vence este mes
    ORPHAN       Coincide si la tarea tiene algún valor UDA huérfano
    OVERDUE      Coincide si la tarea está vencida
    PARENT       Coincide si la tarea es un padre (obsoleto en 2.6.0)
    PENDING      Coincide si la tarea tiene estado pendiente
    PRIORITY     Coincide si la tarea tiene prioridad
    PROJECT      Coincide si la tarea tiene un proyecto
    QUARTER      Coincide si la tarea vence este trimestre
    READY        Coincide si la tarea es accionable
    SCHEDULED    Coincide si la tarea está programada
    TAGGED       Coincide si la tarea tiene tags
    TEMPLATE     Coincide si la tarea es una plantilla de recurrencia
    TODAY        Coincide si la tarea vence hoy
    TOMORROW     Coincide si la tarea vence mañana
    UDA          Coincide si la tarea tiene algún valor UDA
    UNBLOCKED    Coincide si la tarea no está bloqueada
    UNTIL        Coincide si la tarea expira
    WAITING      Coincide si la tarea está esperando
    WEEK         Coincide si la tarea vence esta semana
    YEAR         Coincide si la tarea vence este año
    YESTERDAY    Coincide si la tarea venció ayer

Puedes usar +BLOCKED para filtrar tareas bloqueadas, o -BLOCKED para tareas no bloqueadas. De manera similar, -BLOCKED es equivalente a +UNBLOCKED. Es un error intentar añadir o eliminar un tag virtual.

ATRIBUTOS DE TAREAS

Se admiten los siguientes atributos:

project:<nombre-proyecto>
Especifica el proyecto al que está relacionada una tarea.
status:pending|deleted|completed|waiting|recurring
Especifica el estado de la tarea.
priority:H|M|L o priority:
Especifica alta, media, baja y ninguna prioridad para una tarea.
due:<fecha-vencimiento>
Especifica la fecha de vencimiento de una tarea.
recur:<frecuencia>
Especifica la frecuencia de recurrencia de una tarea.
scheduled:<fecha-lista>
Especifica la fecha después de la cual una tarea puede ser completada.
until:<fecha-expiración>
Especifica la fecha de expiración de una tarea, después de la cual será eliminada.
limit:<número-de-filas>
Especifica el número deseado de tareas que un informe debe mostrar, si se proporciona un entero positivo. El valor 'page' también puede ser utilizado y limitará la salida del informe a tantas líneas de texto como quepan en la pantalla. El valor predeterminado es 25 líneas.
wait:<fecha-espera>
Cuando a una tarea se le asigna una fecha de espera, se oculta de la mayoría de los informes incorporados, que excluyen +WAITING. Cuando la fecha está en el pasado, la tarea no se considera +WAITING y vuelve a ser visible. Tenga en cuenta que, por compatibilidad, dichas tareas se muestran como con estado "waiting", pero esto cambiará en una futura versión.
depends:<id1,id2 ...>
Declara que esta tarea depende de id1 e id2. Esto significa que las tareas id1 e id2 deben completarse antes que esta tarea. En consecuencia, esta tarea aparecerá en el informe 'blocked'. Acepta una lista separada por comas de números de ID, números UUID y rangos de ID. Al prefijar cualquier elemento de esta lista con '-', las tareas especificadas se eliminan de la lista de dependencias.
entry:<fecha-creación>
Para propósitos de informes, especifica la fecha en que se creó una tarea.
modified:<fecha-modificación>
Especifica la fecha de modificación más reciente.

MODIFICADORES DE ATRIBUTOS

Los modificadores de atributos mejoran los filtros. Los modificadores admitidos son:

before (sinónimos: under, below)
after (sinónimos: over, above)
by
none
any
is (sinónimo: equals)
isnt (sinónimo: not)
has (sinónimo: contains)
hasnt
startswith (sinónimo: left)
endswith (sinónimo: right)
word
noword

Se pueden aplicar a todos los atributos regulares (ver arriba) y a los siguientes atributos calculados:

urgency (o corto urg)

Por ejemplo:

    task due.before:eom priority.not:L list

El modificador before se usa para comparar valores, preservando la semántica, por lo que project.before:B lista todos los proyectos que empiezan por 'A'. La prioridad 'L' está antes que 'M', y due:2011-01-01 está antes que due:2011-01-02. Los sinónimos 'under' y 'below' se incluyen para permitir filtros que se lean de forma más natural.

El modificador after es el inverso del modificador before.

El modificador by es el mismo que 'before', excepto que también incluye el momento en cuestión. Por ejemplo:

    task add test due:eoy

será encontrado usando el filtro inclusivo 'by':

    task due.by:eoy

pero no cuando se usa el filtro no inclusivo 'before':

    task due.before:eoy

esto se aplica igualmente a otras fechas nombradas como 'eom', 'eod', etc.; el modificador compara usando '<=' en lugar de '<' como lo hace 'before'.

El modificador none requiere que el atributo no tenga valor. Por ejemplo:

    task priority:      list
    task priority.none: list

son equivalentes y listan las tareas que no tienen prioridad.

El modificador any requiere que el atributo tenga un valor, pero cualquier valor servirá.

El modificador is requiere una coincidencia exacta con el valor.

El modificador isnt es el inverso del modificador is.

El modificador has se usa para buscar una subcadena, tal como:

    task description.has:foo list
    task foo                 list

Son equivalentes y devolverán cualquier tarea que tenga 'foo' en la descripción o anotaciones.

El modificador hasnt es el inverso del modificador has.

El modificador startswith coincide con el principio de un atributo, de modo que:

    task project.startswith:H list
    task project:H            list

Son equivalentes y coincidirán con cualquier proyecto que comience con 'H'. Coincidir con todos los proyectos que no comiencen con 'H' se hace con:

    task project.not:H         list

El modificador endswith coincide con el final de un atributo.

El modificador word requiere que el atributo contenga la palabra completa especificada, de modo que esto:

    task description.word:foo list

Coincidirá con la descripción 'foo bar baz' pero no con 'dog food'.

El modificador noword es el inverso del modificador word.

EXPRESIONES Y OPERADORES

Puedes usar los siguientes operadores en las expresiones de filtro:

  and  or  xor  !               Operadores lógicos
  <  <=  =  ==  !=  !==  >=  >  Operadores relacionales
  (  )                          Precedencia

Por ejemplo:

  task due.before:eom priority.not:L list
  task '( due < eom or priority != L )' list
  task '! ( project:Home or project:Garden )' list

El operador = prueba la igualdad aproximada. Las fechas comparan igual si están en el mismo día (la hora y los minutos se ignoran). Las cadenas comparan igual si el operando izquierdo empieza con el operando derecho. El operador == prueba la igualdad exacta. Los operadores != y !== son la negación de = y == respectivamente. El operador de negación es !.

Ten en cuenta que los paréntesis son necesarios cuando se usa un operador lógico que no sea el operador 'and'. La razón es que algunos informes contienen filtros que deben combinarse con la línea de comandos. Considera este ejemplo:

  task project:Home or project:Garden list

Aunque esto parece correcto, no lo es. El informe 'list' contiene un filtro de:

  task show report.list.filter
  Config Variable    Value
  -----------------  --------------
  report.list.filter status:pending

Lo que significa que el ejemplo es realmente:

  task status:pending project:Home or project:Garden list

El operador 'and' implícito lo convierte en:

  task status:pending and project:Home or project:Garden list

Este es un error de precedencia: el 'and' y el 'or' necesitan ser agrupados usando paréntesis, así:

  task status:pending and ( project:Home or project:Garden ) list

Por lo tanto, el ejemplo original debe introducirse como:

  task '( project:Home or project:Garden )' list

Esto incluye comillas para escapar los paréntesis, para que el shell no los interprete y los oculte de Taskwarrior.

Existe redundancia entre operadores, modificadores de atributos y otras azúcares sintácticas. Por ejemplo, los siguientes son todos equivalentes:

  task foo                      list
  task /foo/                    list
  task description.contains:foo list
  task description.has:foo      list
  task 'description ~ foo'      list

Períodos de recurrencia. Taskwarrior admite varias formas de especificar la frecuencia de las tareas recurrentes. Tenga en cuenta que las frecuencias se pueden abreviar.

Todos los días o un número de días.

Lunes, martes, miércoles, jueves, viernes y omitiendo los días de fin de semana.

Cada año o un número de años.
bianual, biyearly, 2yr
Cada dos años.

CONTEXTO

El contexto es una consulta definida por el usuario, que se aplica automáticamente a todos los comandos que filtran la lista de tareas y a los comandos que crean nuevas tareas (add, log). Por ejemplo, cualquier comando de informe se verá afectado por el contexto activo actual. Aquí hay una lista de los comandos afectados:

    add
    burndown
    count
    delete
    denotate
    done
    duplicate
    edit
    history
    log
    prepend
    projects
    purge
    start
    stats
    stop
    summary
    tags

Todos los demás comandos NO se ven afectados por el contexto.

    $ task list
    ID Age Project  Description        Urg
    1  2d  Sport    Run 5 miles        1.42
    2  1d  Home     Clean the dishes   1.14
    $ task context home
    Context 'home' set. Use 'task context none' to remove.
    $ task list
    ID Age Project  Description        Urg
    2  1d  Home     Clean the dishes   1.14
    Context 'home' set. Use 'task context none' to remove.

La lista de tareas se filtró automáticamente para project:Home.

    $ task add Vaccuum the carpet
    Created task 3.
    Context 'home' set. Use 'task context none' to remove.
    $ task list
    ID Age Project  Description         Urg
    2  1d  Home     Clean the dishes    1.14
    3  5s  Home     Vaccuum the carpet  1.14
    Context 'home' set. Use 'task context none' to remove.

Tenga en cuenta que la nueva tarea agregada "Vaccuum the carpet" tiene automáticamente el campo "project:Home".

Como se ve en el ejemplo anterior, el contexto se aplica especificando su nombre al comando "context". Para cambiar el contexto aplicado actualmente, simplemente pase el nombre del nuevo contexto al comando 'context'.

Para anular cualquier contexto, use el subcomando 'none'.

    $ task context none
    Context unset.
    $ task list
    ID Age Project  Description         Urg
    1  2d  Sport    Run 5 miles         1.42
    2  1d  Home     Clean the dishes    1.14
    3  7s  Home     Vaccuum the carpet  1.14

El contexto se puede definir usando el subcomando 'define', especificando tanto el nombre del nuevo contexto como su filtro asignado.

    $ task context define home project:Home
    Are you sure you want to add 'context.home.read' with a value of 'project:Home'? (yes/no) yes
    Are you sure you want to add 'context.home.write' with a value of 'project:Home'? (yes/no) yes
    Context 'home' successfully defined.

Tenga en cuenta que se le solicitó por separado que estableciera el contexto de 'lectura' y 'escritura'. Esto le permite especificar contextos que solo funcionan para comandos de informes o solo para comandos que crean tareas.

Para eliminar la definición, use el subcomando 'delete'.

    $ task context delete home
    Are you sure you want to remove 'context.home.read'? (yes/no) yes
    Are you sure you want to remove 'context.home.write'? (yes/no) yes
    Context 'home' deleted.

Para verificar cuál es el contexto actualmente activo, use el subcomando 'show'.

    $ task context show
    Context 'home' with
    * read filter: '+home'
    * write filter: '+home'
    is currently applied.

Los contextos pueden almacenar filtros arbitrariamente complejos.

    $ task context define family project:Family or +paul or +nancy
    Are you sure you want to add 'context.family.read' with a value of 'project:Family or +paul or +nancy'? (yes/no) yes
    Are you sure you want to add 'context.family.write' with a value of 'project:Family or +paul or +nancy'? (yes/no) no
    Context 'family' successfully defined.

Los contextos son permanentes, y el nombre del contexto actualmente establecido se almacena en la variable de configuración "context". La definición del contexto se almacena en la variable de configuración "context.<name>.read" (para comandos de informes) y la variable de configuración "context.<name>.write" (para adiciones de tareas, es decir, task add/log).

Tenga en cuenta que en el ejemplo anterior, el usuario decidió no definir el filtro complejo como contexto escribible. La razón de esta decisión es que el filtro complejo en el ejemplo no se traduce directamente en una modificación. De hecho, si se utiliza dicho contexto como contexto escribible, ocurre lo siguiente:

    $ task add Call Paul
    Created task 4.
    Context 'family' set. Use 'task context none' to remove.
    $ task 4 list
    ID Age  Project Tags       Description      Urg
     4 9min Family  nancy paul or or Call Paul    0

No hay una correspondencia clara entre el filtro complejo utilizado y las modificaciones (¿solo se debe establecer el proyecto? ¿solo las etiquetas? ¿ambas?). Además, observe los operadores 'or' presentes en la descripción. Taskwarrior no intenta adivinar la intención del usuario, y en su lugar, se espera que el usuario establezca la variable "context.<name>.write" para hacer explícita su intención, por ejemplo:

    $ task config context.family.write project:Family
    Are you sure you want to change the value of 'context.family.write' from 'project:Family or +paul or +nancy' to 'project:Family'? (yes/no) yes
    Config file /home/tbabej/.config/task/taskrc modified.
    $ task context
    Name   Type  Definition                        Active
    family read  project:Family or +paul or +nancy yes
           write project:Family                    yes
    home   read  +home                             no
           write +home                             no

Observe cómo los contextos de lectura y escritura difieren para el contexto "family", mientras que para el contexto "home" permanecen iguales.

Además, cada parámetro de configuración puede ser anulado para el contexto actual, especificando context.<name>.rc.<parameter>. Por ejemplo, si el comando por defecto para el contexto familiar debe ser la visualización del informe familiar:

    $ task config context.family.rc.default.command family_report

ABREVIATURA DE COMANDOS

Todos los comandos de Taskwarrior pueden abreviarse siempre que se utilice un prefijo único, por ejemplo:

  $ task li

es una abreviatura no ambigua para

  $ task list

pero

  $ task l

podría ser list, ls o long.

Tenga en cuenta que puede restringir el tamaño mínimo de abreviatura utilizando la configuración:

  abbreviation.minimum=3

ESPECIFICACIÓN DE DESCRIPCIONES

Algunas descripciones de tareas deben escaparse debido al shell y al significado especial de algunos caracteres para el shell. Esto se puede hacer agregando comillas a la descripción o escapando el carácter especial:

  $ task add "quoted ' quote"
  $ task add escaped \' quote

El argumento -- (un doble guion) le dice a Taskwarrior que trate todos los demás argumentos como descripción:

  $ task add -- project:Home needs scheduling

En otras situaciones, el shell ve espacios y divide los argumentos. Por ejemplo, este comando:

  $ t

MODIFICAR CON DESCRIPCIONES

A veces es necesario pasar comillas a Taskwarrior intactas, para que pueda usar:

  $ task 123 modify "/de esto/a eso/"

Se descompone en varios argumentos, lo que se corrige con comillas:

  $ task 123 modify "/de esto/a eso/"

A veces es necesario forzar que el shell pase las comillas a Taskwarrior intactas, por lo que puede usar:

  $ task add project:'Proyecto de Tres Palabras' description

Taskwarrior soporta Unicode usando solo la codificación UTF8.

ARCHIVO DE CONFIGURACIÓN Y OPCIONES DE ANULACIÓN

Taskwarrior almacena su configuración en un archivo en el directorio de inicio del usuario: ~/.taskrc. El archivo de configuración predeterminado puede ser anulado con:

task rc:<ruta-al-archivo-alternativo> ...
Especifica un archivo de configuración alternativo con la máxima prioridad.
TASKRC=<ruta-al-archivo-alternativo> task ..
La variable de entorno especifica un archivo de configuración alternativo a usar.
XDG_CONFIG_HOME=<ruta-al-directorio-de-configuración-alternativo> task ..
La variable de entorno especifica un archivo de configuración alternativo a usar.
task rc.<nombre>:<valor> ...
task rc.<nombre>=<valor> ... Especifica anulaciones individuales del archivo de configuración.
TASKDATA=/tmp/.task task ...
La variable de entorno anula el valor predeterminado y la configuración 'data.location' del directorio de datos de tareas.
