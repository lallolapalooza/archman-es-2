TARSNAP(1) General Commands Manual TARSNAP(1)

NAME

tarsnap — manipular copias de seguridad cifradas remotas

SYNOPSIS

tarsnap {-c} --keyfile archivo-clave --cachedir directorio-caché -f nombre-archivo [opciones] [archivos | directorios]

tarsnap {-d} --keyfile archivo-clave --cachedir directorio-caché -f nombre-archivo [opciones]

tarsnap {-t | -x} --keyfile archivo-clave -f nombre-archivo [opciones] [patrones]

tarsnap {-r} --keyfile archivo-clave -f nombre-archivo

tarsnap {--list-archives} --keyfile archivo-clave

tarsnap {--print-stats} --keyfile archivo-clave --cachedir directorio-caché [-f nombre-archivo]

tarsnap {--recover} --keyfile archivo-clave --cachedir directorio-caché

tarsnap {--fsck} --keyfile archivo-clave --cachedir directorio-caché

tarsnap {--fsck-prune} --keyfile archivo-clave --cachedir directorio-caché

tarsnap {--initialize-cachedir} --keyfile archivo-clave --cachedir directorio-caché

tarsnap {--nuke} --keyfile archivo-clave

tarsnap --verify-config

tarsnap --version

DESCRIPTION

tarsnap crea, lee, elimina y gestiona copias de seguridad en línea.

La primera opción para tarsnap es un indicador de modo de la siguiente lista:

-c
Crea un archivo que contiene los elementos y el nombre especificados.
-d
Elimina el archivo especificado.
-t
Lista el contenido del archivo en la salida estándar.
-x
Extrae a disco desde el archivo.
-r
Lee el archivo especificado, lo convierte en un flujo de tar y lo escribe en la salida estándar.
--list-archives
Imprime los nombres de los archivos almacenados. Si se especifica el indicador -v una o más veces, también se imprime la hora de creación de cada archivo; si se especifica el indicador -v dos o más veces, también se imprime la línea de comandos con la que se invocó tarsnap para crear cada archivo.
--print-stats
Imprime estadísticas globales sobre los archivos almacenados y, opcionalmente, información sobre archivos individuales. Consulte "IMPRESIÓN DE ESTADÍSTICAS DE ARCHIVOS" a continuación para obtener información sobre el formato de salida.
--recover
Recupera un archivo parcial desde un punto de control si existe dicho archivo. Esto también se realiza automáticamente la próxima vez que se cree o elimine un archivo.
--fsck
Realiza algunas comprobaciones de integridad en los archivos almacenados y reconstruye el directorio caché directorio-caché. En el improbable caso de que haya archivos corruptos, tarsnap saldrá y solicitará que se ejecute con la opción --fsck-prune.
--fsck-prune
Se ejecuta como --fsck, pero si se detectan archivos corruptos, se podan los datos rotos.
--initialize-cachedir
Crea e inicializa el directorio caché. Esta opción está pensada para la interfaz gráfica y no es necesaria para el uso desde la línea de comandos.
--nuke
Elimina todos los archivos almacenados. Para protegerse contra la pérdida accidental de datos, tarsnap le pedirá que escriba el texto "No Tomorrow" al usar el comando --nuke.
--verify-config
Comprueba si los archivos de configuración tienen errores sintácticos.
--version
Imprime el número de versión de tarsnap y sale.

En modo -c, cada archivo o directorio especificado se añade al archivo en el orden especificado en la línea de comandos. Por defecto, también se archivan los contenidos de cada directorio.

En modo -t o -x, se lee y analiza toda la línea de comandos antes de abrir el archivo. Las rutas o los patrones en la línea de comandos indican qué elementos del archivo se deben procesar. Los patrones son patrones de búsqueda de estilo shell, como se documenta en tcsh(1). Tenga en cuenta que siguen las reglas POSIX para la coincidencia de patrones, por ejemplo, '[]' son caracteres especiales que pueden escaparse con una barra invertida.

No se pueden realizar dos operaciones de creación o eliminación concurrentes con la misma clave. La extracción o listado de archivos puede realizarse en paralelo con cualquier otra operación.

OPTIONS

@archivo-archivo
(solo modo c) Se lee el archivo de archivo especificado y sus entradas se añadirán al archivo actual. Si archivo-archivo es "-", el archivo se leerá de la entrada estándar. Como ejemplo,
tarsnap -c --keyfile archivo-clave --cachedir directorio-caché -f mi_copia_seguridad @backup.tar
lee el archivo de copia de seguridad backup.tar del disco y lo almacena usando tarsnap

@@nombre-archivo
(solo modo c) Se lee el archivo tarsnap especificado y las entradas en él se añadirán al archivo actual.
--aggressive-networking
(solo modo c) Utiliza múltiples conexiones TCP para enviar datos al servidor tarsnap. Si la tasa de subida está limitada por la congestión en lugar de por cuellos de botella individuales, esto puede permitir a tarsnap utilizar una fracción significativamente mayor del ancho de banda disponible, a costa de ralentizar cualquier otro tráfico de red.
--archive-names nombre-archivo
Lee una lista de nombres de archivo de nombre-archivo.
-C directorio
(solo modos c y x) En modo c, esto cambia el directorio antes de añadir los siguientes archivos. En modo x, cambia de directorio después de abrir el archivo pero antes de extraer las entradas del archivo.
--cachedir directorio-cache
(solo modos c, d, print-stats y fsck) Guarda información sobre los archivos almacenados por tarsnap en el directorio directorio-cache. El contenido de este directorio no será copiado de seguridad por tarsnap, por lo que no debe utilizarse para ningún otro propósito. Si el directorio directorio-cache se pierde, puede ser reconstruido ejecutando tarsnap --fsck.
--check-links
(solo modo c) Emite una advertencia a menos que se archiven todos los enlaces a cada archivo.
--checkpoint-bytes bytesporpunto
(solo modo c) Crea un punto de control después de cada bytesporpunto bytes de datos subidos. El valor bytesporpunto debe ser de al menos 1000000, y se recomienda un valor más alto, ya que la creación de un punto de control en un archivo puede llevar unos segundos y varios cientos de kB de ancho de banda.
--chroot
(solo modo x) chroot() al directorio actual después de procesar cualquier opción -C y antes de extraer cualquier archivo.
--configfile nombre-archivo
Añade nombre-archivo a la lista de archivos de configuración que se leerán; las opciones establecidas a través de ellos tienen prioridad sobre los archivos de configuración predeterminados. Esta opción se puede especificar varias veces, en cuyo caso se leerán todos los archivos; donde las configuraciones entren en conflicto, el archivo de configuración anterior tendrá prioridad.
--creationtime X
(solo modo c) Especifica manualmente una hora de creación (una marca de tiempo Unix) para el archivo. Es poco probable que esto sea útil cuando tarsnap se invoca directamente desde la línea de comandos.
--csv-file nombre-archivo
(usar con --print-stats) Escribe las estadísticas en formato CSV en un archivo.
--disk-pause X
(solo modo c) Pausa durante X ms entre el almacenamiento de entradas del archivo y después de cada 64 kB de datos de archivo. Esto ralentizará tarsnap y, por lo tanto, reducirá su impacto en otras aplicaciones. Para archivar archivos que se almacenan en un disco ATA y no están en la caché del disco del sistema operativo, un valor de --disk-pause 10 aproximadamente duplicará el tiempo necesario.
--dry-run
(solo modo c) No crea realmente un archivo; solo simula hacerlo. La lista de rutas añadidas a un archivo (si se usa la opción -v), los mensajes de progreso (si se usa la opción --progress-bytes) y las estadísticas finales impresas (si se usa la opción --print-stats) serán casi idénticas (típicamente dentro de unos pocos kB o una fracción de un porcentaje) a si tarsnap se ejecuta sin la opción --dry-run.

Tenga en cuenta que la opción --maxbw no funciona en combinación con --dry-run, ya que no se utiliza ancho de banda real, y que como tarsnap no se pone en contacto con el servidor tarsnap al realizar una ejecución de prueba, no detectará un intento de crear un archivo con el mismo nombre que uno que ya existe. Si se está copiando un archivo existente a través de @@nombre-archivo, se utilizará algo de ancho de banda de red mientras tarsnap lee metadatos sobre nombre-archivo del servidor tarsnap.

Además, --dry-run no comprobará si el directorio de caché está desincronizado.

--dry-run-metadata
(solo modo c) No crea realmente un archivo; solo simula hacerlo. Esto es similar a --dry-run, excepto que no lee ningún archivo; solo procesa metadatos del sistema de archivos.

Esto es significativamente más rápido que una --dry-run normal, pero sigue siendo adecuado para comprobar qué entradas del sistema de archivos se archivarán (con -v), o para obtener el tamaño total del archivo sin comprimir (a través de --totals o --progress-bytes).

Esta opción no se puede utilizar con --print-stats.

--dump-config
Imprime la línea de comandos y todas las líneas no vacías leídas de los archivos de configuración.
--exclude patrón
(solo modos c, x y t) No procesa archivos o directorios que coincidan con el patrón especificado. Tenga en cuenta que las exclusiones tienen prioridad sobre los patrones o nombres de archivo especificados en la línea de comandos.
-f nombre-archivo
(solo modos c, d, x, t, r, list-archives y print-stats) Opera en el archivo nombre-archivo. En modo c, si la creación del archivo se interrumpe por ^Q, la señal SIGQUIT, o al alcanzar el límite de ancho de banda especificado a través de una opción --maxbw, el archivo se almacenará con ".part" añadido a su nombre. En modo print-stats, si nombre-archivo es *, se imprimirán estadísticas para cada archivo. En los modos print-stats y d, se puede especificar -f nombre-archivo varias veces, en cuyo caso la operación (impresión de estadísticas o eliminación) se realizará para cada uno de los archivos especificados.

Tenga en cuenta que cada archivo creado debe tener un nombre diferente; en consecuencia, a muchos usuarios les resulta útil incluir marcas de tiempo en los nombres de archivo al crear repetidamente archivos a partir de los mismos archivos/directorios (por ejemplo, copias de seguridad diarias).

Como caso especial, si se usa con --list-archives --hashes entonces -f indica una tapehash en lugar de un nombre-archivo, e imprimirá metadatos sobre los archivos especificados. Esta combinación de opciones está destinada a la GUI y no es necesaria para el uso de la línea de comandos. (-f no se puede usar con --list-archives si tampoco incluye --hashes.)

--null-input
(usar con -I, -T, o -X) Los nombres de archivo, nombres de archivo y patrones están separados por caracteres nulos, no por saltos de línea. Esto se usa a menudo para leer nombres de archivo generados por la opción -print0 de find(1).
--null-output
(solo modos x, t, list-archives y print-stats) Los nombres de archivo, los nombres de archivo y las líneas de salida están separados por caracteres nulos, no por saltos de línea.

Si hay varios campos en una línea, estarán separados por dos caracteres nulos. Si se imprime una línea de comandos dentro de uno de esos campos, cada argumento estará separado por tres caracteres nulos.

--numeric-owner
(solo modo x) Ignora los nombres simbólicos de usuario y grupo al restaurar archivos en disco, solo se obedecerán los valores numéricos uid y gid.
-O
(solo modos x y t) En modo de extracción (-x), los archivos se escribirán en la salida estándar en lugar de extraerse en disco. En modo de listado (-t), el listado de archivos se escribirá en stderr en lugar del stdout habitual.
-o
(solo modo x) Usa el usuario y grupo del usuario que ejecuta el programa en lugar de los especificados en el archivo. Ten en cuenta que esto no tiene significado a menos que se especifique -p y el programa lo ejecute el usuario root. En este caso, los permisos y marcas de archivo del archivo se restaurarán, pero las ACLs o la información del propietario en el archivo se descartarán.
--one-file-system
(solo modo c) No cruzar puntos de montaje.
-P
(solo modos c, x y t) Conservar nombres de ruta. Por defecto, los nombres de ruta absolutos (aquellos que comienzan con un carácter /) se les quita la barra inicial tanto al crear archivos como al extraer de ellos. Además, tarsnap se negará a extraer entradas de archivo cuyos nombres de ruta contengan .. o cuyo directorio de destino se modifique por un enlace simbólico. Esta opción suprime estos comportamientos.
-p
(solo modo x) Conservar permisos de archivo. Intenta restaurar los permisos completos, incluyendo propietario, modos de archivo, marcas de archivo y ACLs, si están disponibles, para cada elemento extraído del archivo. Por defecto, los archivos recién creados son propiedad del usuario que ejecuta tarsnap, el modo de archivo se restaura para los archivos regulares recién creados, y todos los demás tipos de entradas reciben permisos predeterminados. Si tarsnap lo ejecuta root, el valor predeterminado es restaurar el propietario a menos que también se especifique la opción -o.

--print-stats
(solo modos c y d) Imprime estadísticas del archivo que se está creando (modo c) o eliminando (modo d). Consulta "IMPRESIÓN DE ESTADÍSTICAS DEL ARCHIVO" a continuación para obtener información sobre el formato de salida.
--progress-bytes X
Muestra un mensaje de progreso (como si se generara desde SIGUSR1 o SIGINFO) después de procesar cada X bytes. Ocurre como máximo una vez por archivo.
-q (--fast-read)
(solo modos x y t) Extrae o lista solo la primera entrada de archivo que coincide con cada patrón u operando de nombre de archivo. Sale tan pronto como cada patrón o nombre de archivo especificado ha sido emparejado. Por defecto, el archivo siempre se lee hasta el final, ya que puede haber múltiples entradas con el mismo nombre y, por convención, las entradas posteriores sobrescriben a las anteriores. Esta opción se proporciona como una optimización de rendimiento.
--quiet
Evita imprimir algunas advertencias. Actualmente, las advertencias que se silencian con esta opción son "Eliminando '/' inicial...", "No se añade el directorio de caché al archivo", "... el archivo puede haber crecido mientras se archivaba" y "Omitiendo entrada en sistema de archivos de tipo... ", pero es probable que otras advertencias sean silenciadas por esta opción en futuras versiones de tarsnap.
--resume-extract
(solo modo x) No extrae archivos cuyo tamaño y mtime coinciden con los archivos existentes en el disco. Se usa principalmente para reanudar una extracción de archivo que fue interrumpida. La comparación de mtime ignora la precisión de subsegundo de la marca de tiempo, ya que esto no es compatible con todos los sistemas de archivos. Esto difiere de -k en que --resume-extract sobrescribirá un archivo si el tamaño o la hora de modificación no coinciden, como puede suceder si tarsnap se interrumpe a mitad de la extracción de un archivo.
--retry-forever
Esta opción hace que tarsnap intente reconectar al servidor tarsnap para siempre, en lugar de rendirse después de 5-10 minutos. Esto puede ser útil para personas con redes excesivamente inestables, o en dispositivos móviles que pierden regularmente sus conexiones a Internet durante períodos prolongados. Esto no está habilitado por defecto, ya que los fallos continuos generalmente indican un problema que debe ser investigado por el usuario.
-S
(solo modo x) Extrae archivos como archivos dispersos. Para cada bloque en disco, primero comprueba si contiene algún byte que no sea NULL y salta sobre él de lo contrario. Esto funciona de manera similar a la opción conv=sparse de dd.
-s patrón
Modifica los nombres de archivo o de miembros del archivo según patrón. El patrón tiene el formato /antiguo/nuevo/[gps]. antiguo es una expresión regular básica. Si no se aplica, el patrón se omite. nuevo es la cadena de reemplazo de la parte coincidente. ~ se sustituye con la coincidencia, \1 a \9 con el contenido del grupo capturado correspondiente. La g opcional al final especifica que la coincidencia debe continuar después de la parte coincidente y detenerse en el primer patrón no coincidente. La s opcional al final especifica que el patrón se aplica al valor de los enlaces simbólicos. La p opcional al final especifica que después de una sustitución exitosa, el nombre de ruta original y el nuevo nombre de ruta deben imprimirse en la salida de error estándar.
--snaptime nombre_archivo
(solo modo c) Esta opción DEBE especificarse al crear una copia de seguridad desde una instantánea del sistema de archivos, y nombre_archivo debe tener una hora de modificación anterior a la creación de la instantánea del sistema de archivos. (Esto es necesario para evitar condiciones de carrera entre la modificación del archivo y la creación de la instantánea que podrían dar como resultado que tarsnap no reconozca que un archivo ha sido modificado.)
--store-atime
(solo modo c) Habilita el almacenamiento de las horas de acceso a los archivos. El comportamiento predeterminado de tarsnap es no almacenar las horas de acceso a los archivos, ya que esto puede causar una cantidad significativa de ancho de banda y almacenamiento desperdiciado cuando el mismo conjunto de archivos se archiva varias veces (por ejemplo, si se crean archivos de copia de seguridad diarios) debido a que tarsnap accede a los archivos y, por lo tanto, provoca que sus horas de acceso cambien.
--strip-components cuenta
(solo modo x) Elimina el número especificado de elementos de ruta iniciales. Los nombres de ruta con menos elementos se omitirán silenciosamente. Ten en cuenta que el nombre de ruta se edita después de verificar los patrones de inclusión/exclusión pero antes de las comprobaciones de seguridad.

EJEMPLOS

Crear un archivo comprimido del directorio /usr/home y otro directorio:

tarsnap --keyfile /usr/tarsnap.key --cachedir /usr/tarsnap-cache -c -f backup-2008-04-24 /usr/home /other/stuff/to/backup

Crear otro archivo, un día después; esto es mucho más rápido ya que tarsnap evitará almacenar datos que ya se almacenaron previamente:

tarsnap --keyfile /usr/tarsnap.key --cachedir /usr/tarsnap-cache -c -f backup-2008-04-25 /usr/home /other/stuff/to/backup

Listar los archivos:

tarsnap --keyfile /usr/tarsnap.key --list-archives

Eliminar el primer archivo, dejando intacto el segundo archivo:

tarsnap --keyfile /usr/tarsnap.key --cachedir /usr/tarsnap-cache -d -f backup-2008-04-24

Listar los archivos en el archivo restante:

tarsnap --keyfile /usr/tarsnap.key -tv -f backup-2008-04-25

Restaurar los directorios de inicio de dos usuarios desde el archivo:

tarsnap --keyfile /usr/tarsnap.key -x -f backup-2008-04-25 usr/home/auser usr/home/anotheruser

En /etc/crontab para crear una copia de seguridad de todo el sistema a las 10:32 cada día:

32 10 * * * root tarsnap --keyfile /usr/tarsnap.key --cachedir /usr/tarsnap-cache -c -f backup-`date +\%Y\%m\%d` /

Tenga en cuenta que las opciones --keyfile y --cachedir se pueden especificar a través del archivo de configuración tarsnap.conf(5), en cuyo caso se pueden omitir de la línea de comandos.

SEGURIDAD

Ciertas cuestiones de seguridad son comunes a muchos programas de archivado, incluido tarsnap. En particular, los archivos cuidadosamente elaborados pueden solicitar que tarsnap extraiga archivos a ubicaciones fuera del directorio de destino. Esto potencialmente podría usarse para hacer que los usuarios desprevenidos sobrescriban archivos que no pretendían sobrescribir. Si el archivo está siendo extraído por el superusuario, cualquier archivo del sistema puede potencialmente ser sobrescrito. Hay tres formas en que esto puede suceder. Aunque tarsnap tiene mecanismos para protegerse contra cada una de ellas, los usuarios experimentados deben ser conscientes de las implicaciones:

  • Las entradas de archivo pueden tener nombres de ruta absolutos. Por defecto, tarsnap elimina el carácter / inicial de los nombres de archivo antes de restaurarlos para protegerse contra este problema.
  • Las entradas de archivo pueden tener nombres de ruta que incluyan componentes ... Por defecto, tarsnap no extraerá archivos que contengan componentes .. en su nombre de ruta.
  • Las entradas de archivo pueden explotar enlaces simbólicos para restaurar archivos en otros directorios. Un archivo puede restaurar un enlace simbólico a otro directorio, y luego usar ese enlace para restaurar un archivo en ese directorio. Para protegerse contra esto, tarsnap verifica cada ruta extraída en busca de enlaces simbólicos. Si el último elemento de la ruta es un enlace simbólico, se eliminará y se reemplazará con la entrada del archivo. Si se especifica -U, cualquier enlace simbólico intermedio también se eliminará incondicionalmente. Si no se especifica ni -U ni -P, tarsnap se negará a extraer la entrada.

Aunque tarsnap firma criptográficamente los archivos de tal manera que se cree que es impracticable que un atacante falsifique un archivo sin poseer el archivo-clave, es posible que desee examinar el contenido del archivo(s) con

tarsnap -t --keyfile archivo-clave -f nombre-archivo
antes de la extracción. Tenga en cuenta que la opción -P para tarsnap deshabilita las comprobaciones de seguridad anteriores y le permite extraer un archivo preservando cualquier nombre de ruta absoluto, componente .. o enlace simbólico a otros directorios.

HISTORIA

Un comando tar apareció en la Séptima Edición de Unix, lanzada en enero de 1979. Ha habido numerosas implementaciones, muchas de las cuales extendieron el formato de archivo. La implementación de dominio público pdtar de John Gilmore (alrededor de noviembre de 1987) fue bastante influyente y formó la base de GNU tar. GNU tar se incluyó como el tar del sistema estándar en FreeBSD a partir de FreeBSD 1.0, pero fue reemplazado por la utilidad bsdtar de Tim Kientzle y la biblioteca libarchive(3) en FreeBSD 5.3.

tarsnap se basa en bsdtar y libarchive(3).

ERRORES

Este programa sigue ISO/IEC 9945-1:1996 (“POSIX.1”) para la definición de la opción -l para tar(5). Tenga en cuenta que GNU tar antes de la versión 1.15 trataba -l como un sinónimo de la opción --one-file-system.

Para archivar un archivo llamado @foo, @@foo, o -foo, debe especificarlo como ./@foo, ./@@foo, o ./-foo, respectivamente.

En modo de creación, siempre se elimina un ./ inicial. Se elimina un / inicial a menos que se especifique la opción -P.

La información de enlaces duros puede perderse si un archivo que se incluye a través de la opción @archivo-archivo está en un formato que no sea "tar". (Esto es una consecuencia de las formas incompatibles en que los diferentes formatos de archivo almacenan la información de enlaces duros).

Existen opciones largas alternativas para muchas de las opciones cortas que deliberadamente no están documentadas.

El límite especificado por una opción --maxbw no se aplica estrictamente; en particular, debido a la necesidad de terminar limpiamente un archivo, la cantidad de ancho de banda utilizado puede exceder ligeramente el límite.

Si tarsnap se ejecuta con entrada estándar, salida estándar y error estándar redirigidos y dentro de un chroot donde los dispositivos de terminal no están expuestos, ^Q no se mapeará a SIGQUIT y, en consecuencia, no activará la truncación del archivo actual.
