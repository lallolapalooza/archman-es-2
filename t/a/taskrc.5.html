NOMBRE

taskrc - Detalles de configuración para el comando task(1)

SINOPSIS

$HOME/.taskrc
task rc:<ruta-directorio>/.taskrc ...
TASKRC=<ruta-directorio>/.taskrc task ...
XDG_CONFIG_HOME=<ruta-directorio>/task/taskrc task ...

DESCRIPCIÓN

Taskwarrior obtiene sus datos de configuración de un archivo llamado .taskrc. Este archivo se encuentra normalmente en el directorio personal del usuario:

    $HOME/.taskrc

La ubicación predeterminada puede ser anulada usando el atributo rc: al ejecutar task:

    $ task rc:<ruta-directorio>/.taskrc ...

o usando la variable de entorno TASKRC:

    $ TASKRC=/tmp/.taskrc task ...

Adicionalmente, si no existe ~/.taskrc, taskwarrior verificará si la variable de entorno XDG_CONFIG_HOME está definida:

    $ XDG_CONFIG_HOME=~/.config task ...

Las opciones individuales pueden ser anuladas usando el atributo rc.<nombre>: al ejecutar task:

    $ task rc.<nombre>:<valor> ...

o

    $ task rc.<nombre>=<valor> ...

Si Taskwarrior se ejecuta sin un archivo de configuración existente, preguntará si debe crear un archivo .taskrc predeterminado de ejemplo en el directorio personal del usuario.

El archivo .taskrc sigue una sintaxis muy simple que define pares nombre/valor:

    <nombre> = <valor>

Puede haber espacios en blanco alrededor de <nombre>, '=' y <valor>, y se ignoran. Los espacios en blanco dentro del <valor> se conservan. No se permiten espacios en blanco en listas separadas por comas. La entrada debe estar en una sola línea, sin continuaciones. Los valores admiten UTF8 así como codificación JSON, como \uNNNN.

Tenga en cuenta que Taskwarrior es flexible en cuanto a los valores utilizados para representar elementos booleanos. Puede usar "1" para habilitar, cualquier otra cosa se interpreta como deshabilitada. Los valores "on", "yes", "y" y "true" también son compatibles.

    include <archivo>

Puede haber espacios en blanco alrededor de 'include' y <archivo>. El archivo puede ser una ruta absoluta o relativa, y el carácter especial '~' se expande para significar $HOME. Si se especifica una ruta relativa, se evaluará en relación con los siguientes directorios (en orden de precedencia): 1. el directorio de trabajo actual 2. el directorio que contiene el archivo taskrc 3. los directorios establecidos por el gestor de paquetes (que normalmente contienen temas predefinidos)

Tenga en cuenta que las variables de entorno también se expanden en rutas (y en cualquier otra variable de taskrc).

    # <comentario>

Un comentario consiste en el carácter '#', y se extiende desde el '#' hasta el final de la línea. No hay forma de comentar un bloque de varias líneas. Puede haber líneas en blanco.

Casi todos los valores tienen un valor predeterminado, y un archivo .taskrc vacío es uno que utiliza todos los valores predeterminados. El contenido del archivo .taskrc, por lo tanto, representa anulaciones de los valores predeterminados. Para eliminar completamente un valor predeterminado, debe haber una entrada como esta:

    <nombre> =

Esta entrada anula el valor predeterminado con un valor en blanco.

EDICIÓN

Puede editar su archivo .taskrc manualmente si lo desea, o puede usar el comando 'config'. Para establecer permanentemente un valor en su archivo .taskrc, use este comando:

    $ task config nag "Tienes tareas más urgentes."

Para eliminar una entrada, use este comando:

    $ task config nag

Taskwarrior usará entonces el valor predeterminado. Para establecer explícitamente un valor en blanco, y por lo tanto evitar usar el valor predeterminado, use este comando:

    $ task config nag ""

Taskwarrior también mostrará todas sus configuraciones con este comando:

    $ task show

y además, realizará una verificación de todos los valores en el archivo, advirtiéndole de cualquier cosa que encuentre incorrecta.

INCLUSIÓN DE ARCHIVOS DE CONFIGURACIÓN

El .taskrc puede incluir otros archivos que contengan configuraciones usando la instrucción include:

    include <ruta/al/archivo/de/configuración/a/incluir>

Mediante el uso de archivos de inclusión, puede dividir su archivo de configuración principal en varios que contengan solo los datos de configuración relevantes, como colores, etc.

Hay dos excelentes usos de las inclusiones en su .taskrc, que se muestran aquí:

    include holidays.en-US.rc
    include dark-16.theme

Esto incluye dos archivos estándar que se distribuyen con Taskwarrior, que definen un conjunto de días festivos en EE. UU. y configuran un tema de 16 colores para usar, para colorear los informes y el calendario.

VARIABLES DE ENTORNO

Estas variables de entorno anulan los valores predeterminados, pero no los argumentos de la línea de comandos.

TASKDATA=~/.task
Esto anula la ruta predeterminada para los datos de Taskwarrior.
TASKRC=~/.taskrc
Esto anula el archivo RC predeterminado.

Esta variable de entorno se verificará si ~/.taskrc no existe

XDG_CONFIG_HOME=~/.config
Si está definida, taskwarrior buscará un archivo $XDG_CONFIG_HOME/task/taskrc.

VARIABLES DE CONFIGURACIÓN

Los nombres de variables válidos y sus valores predeterminados son:

ARCHIVOS

data.location=$HOME/.task
Esta es una ruta al directorio que contiene todos los datos de Taskwarrior. Por defecto, está configurado como ~/.task, por ejemplo: /home/paul/.task

Tenga en cuenta que puede usar el meta-carácter de shell ~, que se expandirá correctamente.

Tenga en cuenta que la variable de entorno TASKDATA anula esta configuración.

hooks.location=$HOME/.task/hooks
Esta es una ruta al directorio de scripts de hook. Por defecto es ~/.task/hooks.
gc=1
Se puede utilizar para suspender temporalmente la reconstrucción, de modo que los ID de las tareas no cambien. La reconstrucción requiere acceso de lectura/escritura a la base de datos, por lo que deshabilitar `gc` puede resultar en un mejor rendimiento.

Tenga en cuenta que esto debe usarse en forma de anulación de la línea de comandos (task rc.gc=0 ...), y no usarse permanentemente en el archivo .taskrc, ya que esto afecta significativamente el rendimiento a largo plazo.

purge.on-sync=0
Si está configurado, las tareas antiguas se purgarán automáticamente después de cada sincronización. Las tareas se identifican como "antiguas" cuando tienen el estado "Eliminado" y no se han modificado durante 180 días.
hooks=1
Este interruptor de control maestro habilita el procesamiento de scripts de hook. El valor predeterminado es '1', pero ciertas extensiones y entornos pueden necesitar deshabilitar los hooks.
exit.on.missing.db=0
Cuando se establece en '1', hace que el programa salga si falta la base de datos (~/.task o rc.data.location o anulación de TASKDATA). El valor predeterminado es '0'.

TERMINAL

detection=1
Determina si se utiliza ioctl para establecer el tamaño de la ventana que está utilizando, para el ajuste de texto.
limit:25
Especifica el número deseado de tareas que un informe debe mostrar, si se proporciona un número entero positivo. El valor 'page' también se puede utilizar, y limitará la salida del informe a tantas líneas de texto como quepan en la pantalla. El valor predeterminado es '25'.
>
defaultwidth=80
El ancho de salida utilizado cuando el soporte de autodetección no está disponible. El valor predeterminado es 80. Si se establece en 0, se interpreta como ancho infinito, por lo tanto, sin ajuste de línea; esto es útil cuando se redirige la salida del informe a un archivo para su posterior manejo.
defaultheight=24
La altura de salida utilizada cuando el soporte de autodetección no está disponible. El valor predeterminado es 24. Si se establece en 0, se interpreta como altura infinita. Esto es útil al redirigir gráficos a un archivo para su posterior manejo.
avoidlastcolumn=0
Hace que el ancho de la terminal menos uno se utilice como ancho completo. Esto evita colocar códigos de color en la última columna, lo que puede causar problemas para los usuarios de Cygwin. El valor predeterminado es '0'.
hyphenate=1
Guioniza las líneas cuando ocurren saltos de línea en medio de una palabra. El valor predeterminado es '1'.
editor=vi
Especifica qué editor de texto desea utilizar cuando se utiliza el comando task edit <ID>. Taskwarrior primero buscará esta variable de configuración. Si la encuentra, la utiliza. De lo contrario, buscará las variables de entorno $VISUAL o $EDITOR, antes de recurrir a usar "vi".
reserved.lines=1
Este es el número de líneas reservadas en la parte inferior de la pantalla para el prompt de la shell. Esto solo se referencia cuando se utiliza 'limit:page'.

MISCELÁNEO

verbose=1|0|nothing|list...
Cuando se establece en "1" (el valor predeterminado), se agregan comentarios explicativos útiles a toda la salida de Taskwarrior. Establecer esto en "0" significa que vería la salida normal.

El valor especial "nothing" se puede usar para eliminar toda la salida opcional, lo que resulta en que solo se muestren los datos formateados, sin nada más. Esta salida es la más fácil de analizar y utilizar por scripts de shell.

Alternativamente, puede especificar una lista separada por comas de tokens de verbosidad que controlan ocasiones específicas en las que se genera la salida. Esta lista puede contener:

    blank      Inserta líneas en blanco adicionales en la salida, para mayor claridad
    header     Mensajes que aparecen antes de la salida del informe (esto incluye las sustituciones de .taskrc/.task y el mensaje "[task next]")
    footnote   Mensajes que aparecen después de la salida del informe (principalmente mensajes de estado y descripciones de cambios)
    label      Etiquetas de columna en informes tabulares
    new-id     Proporciona comentarios sobre cualquier tarea nueva con ID (y UUID para tareas nuevas con ID 0, como tareas completadas nuevas).
    new-uuid   Proporciona comentarios sobre cualquier tarea nueva con UUID. Anula new-id. Útil para la automatización.
    news       Recuerda leer los aspectos más destacados de las nuevas versiones hasta que el usuario ejecute "task news".
    affected   Informa 'N tareas afectadas' y similares
    edit       Utiliza la plantilla detallada para el comando 'edit'
    special    Comentarios al aplicar etiquetas especiales
    project    Comentarios sobre cambios de estado de proyecto
    sync       Comentarios sobre sincronización
    filter     Muestra el filtro utilizado en el comando
    context    Muestra el contexto actual. Se muestra en el pie de página.
    override   Notificación cuando se anulan las opciones de configuración
    recur      Notificación cuando se crea una nueva instancia de tarea recurrente
    default    Notificaciones sobre la elección de Taskwarrior para realizar una acción predeterminada.

Los tokens "affected", "new-id", "new-uuid", "project", "override" y "recur" implican "footnote".

El token "default" implica "header".

Tenga en cuenta que la configuración "1" es equivalente a todos los tokens especificados, y la configuración "nothing" es equivalente a ninguno de los tokens especificados.

Aquí están los equivalentes de acceso directo:

    verbose=on
    verbose=blank,header,footnote,label,new-id,news,affected,edit,special,project,sync,filter,override,recur
    verbose=0
    verbose=blank,label,new-id,edit
    verbose=nothing
    verbose=

Esos comentarios adicionales se envían al error estándar para header, footnote y project. Los demás se envían a la salida estándar.

confirmation=1
Puede ser "1" o "0", y determina si Taskwarrior solicitará confirmación antes de eliminar una tarea o ejecutar el comando undo. El valor predeterminado es "1". Considere dejarlo habilitado, por seguridad.
allow.empty.filter=1
Un filtro vacío combinado con un comando de escritura es potencialmente una forma de modificar todas las tareas por error, y cuando esto se detecta, se requiere confirmación. Establecer esto en '0' significa que es un error usar un comando de escritura sin filtro.
indent.annotation=2
Controla el número de espacios para indentar las anotaciones cuando se muestran debajo del campo de descripción. El valor predeterminado es "2".
indent.report=0
Controla la indentación de toda la salida del informe. El valor predeterminado es "0".
row.padding=0
Controla el relleno izquierdo y derecho alrededor de cada fila de la salida del informe. El valor predeterminado es "0".
column.padding=0
Controla el relleno entre las columnas de la salida del informe. El valor predeterminado es "1".
bulk=3
Es un número, cuyo valor predeterminado es 3. Cuando este número o más de tareas se modifican en un solo comando, se requerirá confirmación, independientemente del valor de la variable confirmation. El valor especial bulk=0 se trata como infinito.

Esto es útil para prevenir cambios no intencionados a gran escala.

nag=You have more urgent tasks.
Puede ser una cadena de texto o estar en blanco. Se utiliza como un indicador cuando una tarea se inicia o completa, cuando hay otras tareas con mayor urgencia. El valor predeterminado es: 'You have more urgent tasks'. Es un recordatorio suave de que estás contradiciendo tu propia configuración de urgencia.
list.all.projects=0
Puede ser "1" o "0", y determina si el comando 'projects' lista todos los nombres de proyectos que has utilizado, o solo los utilizados en tareas activas. El valor predeterminado es "0".
summary.all.projects=0
Si se establece en "1", muestra todos los proyectos en el informe de resumen, incluso si no hay tareas pendientes. El valor predeterminado es "0".
complete.all.tags=1
Puede ser "1" o "0", y determina si los scripts de autocompletado de tabulación consideran todos los nombres de etiquetas que has utilizado, o solo los utilizados en tareas activas. El valor predeterminado es "0".
list.all.tags=1
Puede ser "1" o "0", y determina si el comando 'tags' lista todos los nombres de etiquetas que has utilizado, o solo los utilizados en tareas activas. El valor predeterminado es "0".
print.empty.columns=1
Puede ser "1" o "0", y determina si se imprimen las columnas sin datos para ninguna tarea. El valor predeterminado es "0".
search.case.sensitive=1
Puede ser "1" o "0", y determina si la búsqueda por palabras clave y las sustituciones en la descripción y las anotaciones se realizan de forma sensible a mayúsculas y minúsculas. El valor predeterminado es "1" en la mayoría de las plataformas. El valor predeterminado es "0" en Cygwin debido a problemas con bibliotecas de regex más antiguas con sensibilidad a mayúsculas y minúsculas.
regex=1
Controla si el soporte de expresiones regulares está habilitado. El valor predeterminado es "1".
xterm.title=1
Establece el título de la ventana de xterm cuando se ejecutan informes. El valor predeterminado es "0".
expressions=infix|postfix
Establece una preferencia por expresiones infijas (1 + 2) o postfijas (1 2 +). El valor predeterminado es infijo.
json.array=1
Determina si el comando export envuelve la salida JSON en '[...]' y agrega ',' después de cada objeto de tarea exportado para crear un JSON bien formado. array. Con json.array=0, export escribe objetos JSON sin procesar en STDOUT, uno por línea. El valor predeterminado es "1".
_forcecolor=1
Taskwarrior desactiva automáticamente el color cuando la salida no se envía directamente a un TTY. Por ejemplo, este comando:
$ task list > file

no usará ningún color. Para anular esto, use:

$ task rc._forcecolor=yes list > file

El valor predeterminado es "0".

active.indicator=*
El carácter o cadena que se muestra en la columna start.active. El valor predeterminado es *.
tag.indicator=+
El carácter o cadena que se muestra en la columna tag.indicator. El valor predeterminado es +.
dependency.indicator=D
El carácter o cadena que se muestra en la columna depends.indicator. El valor predeterminado es D.
uda.<name>.indicator=U<
uda.indicator=U
El carácter o cadena a mostrar en la columna del indicador <uda>. Por defecto es U.
recurrence=1
Controla si la recurrencia está habilitada y si las tareas recurrentes continúan generando nuevas instancias de tarea. Por defecto es "1".

Si estás sincronizando varios clientes, se recomienda que establezcas 'recurrence=1' en tu cliente principal y 'recurrence=0' en TODOS los demás clientes. Esta es una solución para un error de duplicación.

recurrence.confirmation=prompt
Controla si los cambios en las tareas recurrentes se propagan a otras tareas hijo con o sin confirmación. Un valor de 'yes' significa propagar cambios sin confirmación. Un valor de 'no' significa no propagar cambios y no pedir confirmación. Un valor de 'prompt' te pide confirmación cada vez. Por defecto es 'prompt'.
recurrence.indicator=R
El carácter o cadena a mostrar en la columna del indicador de recurrencia. Por defecto es R.
recurrence.limit=1
El número de tareas recurrentes futuras a mostrar. Por defecto es 1. Por ejemplo, si se añade una tarea recurrente semanal con fecha de vencimiento mañana, y recurrence.limit se establece en 2, entonces un informe listará 2 tareas recurrentes pendientes, una para mañana y otra para dentro de una semana.
abbreviation.minimum=2
Longitud mínima de cualquier comando/valor abreviado. Esto significa que "ve", "ver", "vers", "versi", "versio" equivaldrán a "version", pero "v" no lo hará. Por defecto es 2.
debug=0
Taskwarrior tiene un modo de depuración que muestra información diagnóstica. Normalmente, esto no es algo que nadie quiera, pero al informar de un error, la información de depuración puede ser útil. También puede ayudar a explicar cómo se está analizando la línea de comandos, pero la información se muestra de forma amigable para el desarrollador, no para el usuario.

Activar la depuración establece automáticamente debug.hooks=1 y debug.parser=1 si aún no tienen valores asignados. Por defecto es "0".

debug.hooks=0
Controla el nivel de diagnóstico del sistema de hooks. El nivel 0 significa sin diagnósticos. El nivel 1 muestra las llamadas a los hooks. El nivel 2 muestra también el estado de salida y las E/S.
debug.parser=0
Controla el nivel de diagnóstico del analizador sintáctico (parser). El nivel 0 no muestra diagnósticos. El nivel 1 muestra el árbol sintáctico final. El nivel 2 muestra el árbol sintáctico de todas las fases del análisis. El nivel 3 muestra detalles de la evaluación de expresiones.
obfuscate=0
Cuando se establece en '1', reemplaza todo el texto del informe con 'xxx'. Esto es útil para compartir la salida de informes en informes de errores. El valor por defecto es '0'.
alias.rm=delete
Taskwarrior soporta alias de comandos. Este alias proporciona un nombre alternativo (rm) para el comando delete. Puedes usar alias para proporcionar nombres alternativos para cualquiera de los comandos. Varios comandos que puedas usar son en realidad alias; el informe 'history', por ejemplo, o 'export'.
burndown.cumulative=1
Puede ser "1" o "0", y controla el comportamiento del comando burndown. Cuando se establece en 1, suma todas las tareas completadas, de lo contrario, solo se grafican en el intervalo donde la tarea se completó. Por defecto es 1.

FECHAS

dateformat=Y-M-D
dateformat.report=
dateformat.holiday=YMD
dateformat.edit=Y-M-D H:N:S
dateformat.info=Y-M-D H:N:S
dateformat.annotation=
report.X.dateformat=Y-M-D
Esta es una cadena de caracteres que define cómo Taskwarrior formatea los valores de fecha. El orden de precedencia para la variable de configuración es report.X.dateformat, luego dateformat.report, luego dateformat para formatear las fechas de vencimiento en los informes. Si tanto report.X.dateformat como dateformat.report no están establecidos, entonces dateformat se aplicará a la fecha. Las fechas introducidas, así como todas las demás fechas mostradas en los informes, se formatean según dateformat.

El valor por defecto es el estándar ISO-8601: Y-M-D. La cadena puede contener los siguientes caracteres:

    m  mes en dígito mínimo,    por ejemplo 1 o 12
    d  día en dígito mínimo,      por ejemplo 1 o 30
    y  año en dos dígitos,         por ejemplo 09 o 12
    D  día en dos dígitos,          por ejemplo 01 o 30
    M  mes en dos dígitos,         por ejemplo 01 o 12
    Y  año en cuatro dígitos,       por ejemplo 2009 o 2015
    a  nombre corto del día de la semana,  por ejemplo Lun o Mié
    A  nombre largo del día de la semana,   por ejemplo Lunes o Miércoles
    b  nombre corto del mes,    por ejemplo Ene o Ago
    B  nombre largo del mes,     por ejemplo Enero o Agosto
    v  semana en dígito mínimo,     por ejemplo 3 o 37
    V  semana en dos dígitos,         por ejemplo 03 o 37
    h  hora en dígito mínimo,     por ejemplo 3 o 21
    n  minutos en dígito mínimo,  por ejemplo 5 o 42
    s  segundos en dígito mínimo,  por ejemplo 7 o 47
    H  hora en dos dígitos,         por ejemplo 03 o 21
    N  minutos en dos dígitos,      por ejemplo 05 o 42
    S  segundos en dos dígitos,      por ejemplo 07 o 47
    J  día juliano en tres dígitos, por ejemplo 023 o 365
    j  día juliano,             por ejemplo 23 o 365
    w  Día de la semana,               por ejemplo 0 para Lunes, 5 para Viernes
Los caracteres 'v', 'V', 'a' y 'A' solo pueden usarse para formatear fechas impresas (no para analizarlas).
La cadena también puede contener otros caracteres para actuar como separadores o formato. Ejemplos de otros valores de dateformat:
    d/m/Y  usaría para entrada y salida 24/7/2009
    yMD    usaría para entrada y salida 090724
    M-D-Y  usaría para entrada y salida 07-24-2009
Ejemplos de otros valores de dateformat.report:
    a D b Y (V)   emitiría "vie 24 jul 2009 (30)"
    A, B D, Y     emitiría "Viernes, Julio 24, 2009"
    wV a Y-M-D    emitiría "s30 vie 2009-07-24"
    yMD.HN        emitiría "110124.2342"
    m/d/Y H:N     emitiría "1/24/2011 10:42"
    a D b Y H:N:S emitiría "lun 24 ene 2011 11:19:42"
Los campos no definidos se establecen a sus valores mínimos válidos (1 para mes y día y 0 para hora, minutos y segundos) cuando hay al menos otro campo de fecha global que está establecido. De lo contrario, se establecen a los valores correspondientes de "ahora". Por ejemplo:
    8/1/2013  con m/d/Y   implica 1 de agosto de 2013 a medianoche (inferido)
    8/1 20:40 con m/d H:N implica 1 de agosto de 2013 (inferido) a las 20:40
date.iso=1
Habilita el soporte de fechas ISO-8601. El valor por defecto es "1".

Los días festivos se introducen directamente en el archivo .taskrc o a través de un archivo de inclusión especificado en .taskrc. Para días festivos de un solo día, se requiere el nombre y la fecha:

    holiday.eastersunday.name=Pascua
    holiday.eastersunday.date=easter

The reports can be customized by using the following configuration variables. The output columns, their labels and the sort order can be set using the corresponding variables for each report. Each report name is used as a "command" name. For example

task overdue
report.X.description
The description for report X when running the "task help" command.
report.X.columns
This is a comma-separated list of columns and formatting specifiers. See the command 'task columns' for a full list of options and examples.
report.X.context
A boolean value representing whether the given report should respect (apply) the currently active context. See CONTEXT section for details about context. Defaults to 1.
report.X.labels
The labels for each column that will be used when generating report X. The labels are a comma separated list.
report.X.sort
The sort order of the tasks in the generated report X. The sort order is specified by using the column ids post-fixed by a "+" for ascending sort order or a "-" for descending sort order. The sort IDs are separated by commas. For example: 
    report.list.sort=due+,priority-,start.active-,project+

Additionally, after the "+" or "-", there can be a solidus "/" which indicates that there are breaks after the column values change. For example:

    report.minimal.sort=project+/,description+

This sort order now specifies that there is a listing break between each project. A listing break is simply a blank line, which provides a visual grouping.

A special sort value of "none" indicates that no sorting is required, and tasks will be presented in the order (if any) in which they are selected.

A special sort value of "random" indicates that the tasks will be sorted in a random order. Each time a report with 'sort:random' is run, a new random order will be generated.

report.X.filter
This adds a filter to the report X so that only tasks matching the filter criteria are displayed in the generated report.

There is a special case for 'report.timesheet.filter', which may be specified even though the 'timesheet' report is not very customizable.

report.X.dateformat
This adds a dateformat to the report X that will be used by the "due date" column. If it is not set then dateformat.report and dateformat will be used in this order. See the DATES section for details on the sequence placeholders.
