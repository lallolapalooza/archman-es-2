NOMBRE

tang - Servidor de enlace criptográfico basado en red

VISIÓN GENERAL

Tang es un servicio para enlazar claves criptográficas a la presencia en red. Ofrece una alternativa segura, sin estado y anónima a los servicios de custodia de claves.

El proyecto Tang surgió como una herramienta para ayudar a la automatización del descifrado. Los mecanismos existentes utilizan predominantemente sistemas de custodia de claves donde un cliente cifra algunos datos con una clave simétrica y almacena la clave simétrica en un servidor remoto para su posterior recuperación. El objetivo deseado de esta configuración es que el cliente pueda descifrar automáticamente los datos cuando pueda contactar al servidor de custodia y obtener la clave.

Sin embargo, los servidores de custodia tienen muchos requisitos adicionales, que incluyen autenticación (para que los clientes no puedan obtener claves que no deberían tener) y cifrado de transporte (para que los atacantes que escuchan en la red no puedan espiar las claves en tránsito).

Tang evita esta complejidad. En lugar de almacenar una clave simétrica de forma remota, el cliente realiza un intercambio de claves asimétrico con el servidor Tang. Dado que el servidor Tang no almacena ni transporta claves simétricas, no se requiere autenticación ni cifrado. Por lo tanto, Tang no tiene estado y no requiere configuración. Además, los clientes pueden ser completamente anónimos.

Tang no proporciona un cliente. Pero sí exporta una API REST simple y transfiere solo objetos JSON Object Signing and Encryption (JOSE) que cumplen con los estándares, lo que le permite crear sus propios clientes utilizando componentes listos para usar. Para un marco de cifrado automatizado listo para usar con soporte para Tang, consulte el proyecto Clevis. Para conocer los detalles técnicos completos del protocolo Tang, consulte la página principal del proyecto Tang.

COMIENZO

Poner en marcha un servidor Tang es sencillo:

$ sudo systemctl enable tangd.socket --now

Eso es todo. El servidor ya está en funcionamiento con un conjunto fresco de claves criptográficas y se iniciará automáticamente en el próximo reinicio.

CONFIGURACIÓN

Tang pretende ser un servicio de red mínimo y, por lo tanto, no tiene ninguna configuración. Para ajustar la configuración de red, puede anular el archivo de unidad tangd.socket utilizando los mecanismos estándar de systemd. Consulte systemd.unit(5) y systemd.socket(5) para más información.

AUTÓNOMO O A TRAVÉS DE SYSTEMD

El servidor Tang se puede ejecutar mediante la activación de socket de systemd o de forma autónoma cuando se pasa el parámetro -l. El puerto predeterminado utilizado es 9090 y se puede cambiar con la opción -p.

tang -l -p 9090

PUNTO FINAL

Al servidor Tang se le puede proporcionar un punto final. Este punto final actuará como prefijo para la URL a la que accederá el cliente. Este punto final se puede especificar con la opción -e.

tang -l -p 9090 -e this/is/an/endpoint

Cuando se especifica el punto final, este se antepondrá a la URL normal adv/rec. Si no se proporciona ningún punto final, y asumiendo que se utiliza el puerto 9090, el servidor Tang escuchará en las siguientes URLs:

http://localhost:9090/adv (GET)
http://localhost:9090/rec (POST)

Si se proporciona un punto final, y asumiendo que el punto final es /this/is/an/endpoint/, y asumiendo también que se utiliza el puerto 9090, el servidor Tang escuchará en las siguientes URLs:

http://localhost:9090/this/is/an/endpoint/adv (GET)
http://localhost:9090/this/is/an/endpoint/rec (POST)

ROTACIÓN DE CLAVES

Para preservar la seguridad del sistema a largo plazo, debe rotar sus claves periódicamente. El intervalo preciso al que debe rotar depende de su aplicación, el tamaño de las claves y la política institucional. Para algunas recomendaciones comunes, consulte: https://www.keylength.com.

Hay un script de conveniencia para manejar esto. Consulte tangd-rotate-keys(1) para más información. Esto también se puede realizar manualmente como se describe a continuación.

Para rotar las claves, primero necesitamos generar nuevas claves en el directorio de la base de datos de claves. Típicamente es /var/db/tang. Por ejemplo, puede crear nuevas claves de firma y de intercambio con los siguientes comandos:

# DB=/var/db/tang
# jose jwk gen -i '{"alg":"ES512"}' -o $DB/new_sig.jwk
# jose jwk gen -i '{"alg":"ECMR"}' -o $DB/new_exc.jwk

A continuación, renombra las claves antiguas para que tengan un punto . al principio para ocultarlas de la publicidad:

# mv $DB/old_sig.jwk $DB/.old_sig.jwk
# mv $DB/old_exc.jwk $DB/.old_exc.jwk

Tang recogerá inmediatamente todos los cambios. No se requiere reiniciar.

En este punto, las nuevas vinculaciones de clientes recogerán las nuevas claves y los clientes antiguos podrán seguir utilizando las claves antiguas. Una vez que esté seguro de que todos los clientes antiguos han sido migrados para usar las nuevas claves, puede eliminar las claves antiguas. Tenga en cuenta que eliminar las claves antiguas mientras los clientes todavía las están utilizando puede provocar la pérdida de datos. Ha sido advertido.

ALTO RENDIMIENTO

El protocolo Tang es extremadamente rápido. Sin embargo, en la configuración predeterminada utilizamos la activación de socket de systemd para iniciar un proceso por conexión. Esto impone una sobrecarga de rendimiento. Para la mayoría de las implementaciones, esto sigue siendo probablemente lo suficientemente rápido, dado que Tang es extremadamente ligero. Pero para implementaciones más grandes, se puede lograr un mayor rendimiento.

Nuestra recomendación para lograr un mayor rendimiento es proxy el tráfico a Tang a través de sus servicios web existentes utilizando un pool de conexiones. Dado que hay un proceso por conexión, mantener un número de conexiones abiertas en esta configuración permitirá un paralelismo efectivo ya que no hay bloqueos internos en Tang.

Para Apache, esto es posible utilizando la directiva ProxyPass del módulo mod_proxy.

ALTA DISPONIBILIDAD

Tang proporciona dos métodos para construir una implementación de alta disponibilidad.

1. Redundancia del cliente (recomendado)
2. Compartir claves con round-robin DNS

Si bien puede ser tentador compartir claves entre servidores Tang, este método debe evitarse. Compartir claves aumenta el riesgo de compromiso de claves y requiere una infraestructura de automatización adicional.

En su lugar, los clientes deben estar codificados con la capacidad de vincularse a múltiples servidores Tang. En esta configuración, cada servidor Tang tendrá sus propias claves y los clientes podrán descifrar contactando a un subconjunto de estos servidores.

Clevis ya admite este flujo de trabajo a través de su plugin sss.

Sin embargo, si aún siente que compartir claves es la estrategia de implementación correcta, Tang no le impedirá hacerlo. Simplemente transfiera (¡de forma segura!) todo el contenido del directorio de la base de datos a todos sus servidores. ¡Asegúrese de no olvidar las claves no anunciadas! Luego, configure el round-robin DNS para que los clientes se balanceen entre sus servidores.

COMANDOS

El servidor Tang no proporciona comandos públicos.

NAME

tang - servidor de claves para el servicio de cifrado de datos de Red Hat

OVERVIEW

tang es un servidor de claves para el servicio de cifrado de datos de Red Hat (RDS). Tang proporciona un punto final seguro para la obtención de claves de descifrado, lo que permite a los servidores descifrar su propio almacenamiento.

Tang está diseñado para ser ligero y fácil de desplegar. Puede ejecutarse de forma independiente o como un servicio systemd.

GETTING STARTED

Para empezar con Tang, instale el paquete tang:

sudo pacman -S tang

Una vez instalado, puede iniciar el servicio Tang:

sudo systemctl start tangd.service
sudo systemctl enable tangd.service

Por defecto, Tang escucha en el puerto 8080. Puede configurar esto en el archivo de configuración de Tang, que se encuentra en /etc/tang/tangd.conf.

CONFIGURATION

El archivo de configuración de Tang se encuentra en /etc/tang/tangd.conf. Este archivo contiene varias opciones que se pueden utilizar para configurar el comportamiento de Tang, incluyendo:

  • port: El puerto en el que Tang escuchará las conexiones.
  • key_dir: El directorio donde Tang almacenará sus claves.
  • log_level: El nivel de registro para Tang.

Para más información sobre las opciones de configuración, consulte la página man de tangd.conf.

STANDALONE OR VIA SYSTEMD

Tang se puede ejecutar de forma independiente o como un servicio systemd. Para ejecutar Tang de forma independiente, utilice el siguiente comando:

sudo tangd -f /etc/tang/tangd.conf

Para ejecutar Tang como un servicio systemd, utilice los siguientes comandos:

sudo systemctl start tangd.service
sudo systemctl enable tangd.service

ENDPOINT

El punto final de Tang es la URL donde Tang está escuchando. Por defecto, el punto final es http://localhost:8080. Puede cambiar esto modificando la opción port en el archivo de configuración de Tang.

KEY ROTATION

Tang admite la rotación de claves. Para rotar las claves de Tang, utilice el siguiente comando:

sudo tang-rotate-keys

Esto generará un nuevo conjunto de claves y reiniciará el servicio Tang.

HIGH PERFORMANCE

Tang está diseñado para ser de alto rendimiento. Puede manejar un gran volumen de solicitudes con una latencia mínima. Para optimizar el rendimiento de Tang, puede ajustar los siguientes parámetros:

  • num_workers: El número de hilos trabajadores que utilizará Tang.
  • max_connections: El número máximo de conexiones que Tang aceptará.

Puede ajustar estos parámetros en el archivo de configuración de Tang.

HIGH AVAILABILITY

Tang se puede desplegar en una configuración de alta disponibilidad para garantizar la disponibilidad continua. Para ello, puede ejecutar varias instancias de Tang y utilizar un balanceador de carga para distribuir el tráfico entre ellas.

COMMANDS

Tang proporciona los siguientes comandos:

  • tangd: El demonio de Tang.
  • tang-rotate-keys: Rota las claves de Tang.
