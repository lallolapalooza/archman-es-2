NOMBRE

targets.conf - Archivo de configuración de destino SCSI de Linux

DESCRIPCIÓN

tgt-admin utiliza /etc/tgt/targets.conf para inicializar la configuración de tgtd, por defecto. Su diseño utiliza una estructura similar a HTML, con una jerarquía de etiquetas anidadas para definir destinos y LUNs.

SINTAXIS DEL ARCHIVO DE CONFIGURACIÓN

Las directivas globales configuran opciones que son globales para la configuración de tgtd, así como definen destinos exportados, a través de secciones de destino.

Las secciones de destino contienen directivas específicas para un dispositivo de destino. Definen las LUNs exportadas de cada destino a través de directivas "backing-store" y "direct-store", así como otras opciones específicas del destino.

Las directivas de LUN ("backing-store" y "direct-store") pueden contener opciones específicas para una única unidad lógica exportada.

DIRECTIVAS GLOBALES

Con la excepción de las directivas de destino, cada una de estas debería aparecer como máximo una vez.

<target <IQN>>

Define el inicio de una definición de destino. IQN es un Nombre Cualificado ISCSI como "iqn.2001-04.com.example:storage1".

Dentro de este bloque deben ir las directivas a nivel de destino, como se documenta a continuación.

La definición de destino finaliza con "

default-driver <lld>

En lugar de especificar un tipo de controlador para cada destino, default-driver define un controlador de bajo nivel por defecto para todos los destinos exportados. Puede ser anulado a nivel de destino. Los valores válidos de lld son "iscsi" o "iser". Dado que iscsi se asume si esta directiva no está presente, generalmente solo se necesita si iser es el predeterminado deseado.

include <path>

Incluye la configuración de otro archivo de configuración. Se permiten comodines, por lo que se permite un ejemplo como "include /etc/tgt/xen/*.conf".

ignore-errors yes

Los errores de tgtadm serán ignorados. Por defecto es no.

control-port <port>

Define una clave de socket local diferente para la comunicación con tgtd. Por defecto es 0. Esto solo es útil generalmente si se utilizan múltiples instancias de tgtd.

iSNSServerIP <addr>

Define la dirección del servidor iSNS en formato de dirección IPv4 de cuatro cuartetos. Requerido cuando se utiliza iSNS, de lo contrario se ignora.

iSNSAccessControl <value>

Establece el control de acceso iSNS. Los valores válidos son "On" u "Off". Requerido cuando se utiliza iSNS, de lo contrario se ignora.

iSNSServerPort <port>

Establece un puerto de servidor iSNS diferente. El valor predeterminado es 3205. Opcional cuando se utiliza iSNS, de lo contrario se ignora.

iSNS On

Habilita iSNS. El único valor válido es "On". El valor predeterminado es off.

incomingdiscoveryuser <user> <userpassword>

Define la configuración de autenticación de descubrimiento entrante de iscsi. Si no se proporciona ningún valor, no se realiza ninguna autenticación.

outgoingdiscoveryuser <user> <userpassword>

Define la configuración de autenticación de descubrimiento saliente de iscsi. Si no se proporciona ningún valor, no se realiza ninguna autenticación.

DIRECTIVAS A NIVEL DE DESTINO

Cada destino puede exportar múltiples dispositivos de bloque, o unidades lógicas (LUNs). A efectos de numeración de LUNs, las directivas backing-store se procesan antes que las directivas direct-store.

backing-store <path>

Define una unidad lógica (LUN) exportada por el destino. Puede especificar un archivo regular o un dispositivo de bloque.

direct-store <path>

Define una unidad lógica mapeada directamente (LUN) con las mismas propiedades que el dispositivo físico (como VENDOR_ID, SERIAL_NUM, etc.).

driver <lld>

Define el controlador de bajo nivel a utilizar para este destino, "iscsi" o "iser" (sin comillas). Esto anula la directiva global "default-driver".

initiator-address <addr>

Permite conexiones solo desde la dirección IP especificada. Por defecto es ALL si no se especifica ninguna directiva initiator-address.

initiator-name <addr>

Permite conexiones solo desde el nombre de iniciador especificado.

incominguser <user> <userpassword>

Define la configuración de autenticación entrante de iscsi. Si no se especifica ningún "incominguser", no se utiliza. Esta directiva puede usarse varias veces por destino.

outgoinguser <user> <userpassword>

Define la configuración de autenticación saliente de iscsi. Si no se especifica ningún "outgoinguser", no se utiliza. Esta directiva puede usarse varias veces por destino.

controller_tid <val>

Define el tid del controlador. Por defecto es el siguiente entero disponible.

DIRECTIVAS A NIVEL DE LUN

Todas estas pueden listarse a nivel de destino (y aplicarse a todas las LUNs) o dentro de la definición de una LUN individual, si se define utilizando el formato de definición de contenedor de varias líneas, en lugar del formato de definición de una sola línea:

<backing-store /dev/sdb1>
  # Las directivas LUN van aquí
</backing-store>
<direct-store /dev/sdb1>
  # Las directivas LUN van aquí
</direct-store>

Se recomienda utilizar definiciones de LUN de una sola línea o de contenedor dentro de un destino. Mezclar estilos puede causar errores en el analizador.

write-cache <val>

"on" u "off", por defecto on.

scsi_id <val>

scsi_sn <val>

vendor_id <val>

product_id <val>

product_rev <val>

sense_format <val>

removable <val>

path <val>

mode_page <val>

readonly <val>

device-type <val>

bs-type <val>

allow-in-use <val>

block-size <val>

Especifica el tamaño del bloque para esta LUN.

lbppbe <val>

Especifica el exponente de bloques lógicos por bloque físico. Por defecto, TGTD establecerá lbppbe para que coincida automáticamente con el sistema de archivos subyacente. Utilice este parámetro para anular esa configuración.

Esta es una opción interna que no debe establecerse directamente.

la_lba <val>

Especifica la dirección de bloque lógico alineada más baja. Esta es una opción interna que no debe establecerse directamente.

optimal_xfer_gran <val>

Especifica la granularidad de transferencia óptima, que se reflejará en el VPD de Límites de Bloque. Esta es una opción interna que no debe establecerse directamente.

optimal_xfer_len <val>

Especifica la longitud de transferencia óptima, que se reflejará en el VPD de Límites de Bloque. Esta es una opción interna que no debe establecerse directamente.

params <vals>

Pasa parámetros adicionales a tgtadm.

Tenga en cuenta que '${tid}' y '${lun}' pueden usarse literalmente para referirse al tid y lun que se están configurando. Consulte targets.conf.vtl.L700 para ver un ejemplo.

EJEMPLO DE ARCHIVO DE CONFIGURACIÓN

Archivo de configuración de ejemplo:
<target iqn.2007-04.com.example:san.monitoring>
  backing-store /dev/san/monitoring
  # si no se especifica "incominguser", no se utiliza
  incominguser backup secretpass12
  # por defecto es ALL si no se especifica "initiator-address"
  initiator-address 192.168.1.2
</target>
<target iqn.2007-02.com.example:san.xen1>
  backing-store /dev/san/xen1-disk1 # LUN1
  direct-store /dev/san/xen1-disk2  # LUN2
  initiator-address 192.168.1.2     # IP permitida
  initiator-address 192.168.5.6     # IP permitida
  incominguser user1 secretpass12
  incominguser user2 secretpass23
  outgoinguser userA secretpas
