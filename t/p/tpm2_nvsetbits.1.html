tpm2_nvsetbits(1) Manual general de comandos tpm2_nvsetbits(1)

NOMBRE

tpm2_nvsetbits(1) - OR lógico de bits en un espacio No Volátil (NV).

SINOPSIS

tpm2_nvsetbits [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_nvsetbits(1) - OR lógico de bits en un espacio No Volátil (NV). El índice NV debe ser de tipo "bits", especificado a través del campo "nt" al crear el espacio NV con tpm2_nvdefine(1). El índice puede ser especificado como un manejador crudo o un valor de desplazamiento del rango de manejadores NV "TPM2_HR_NV_INDEX".

OPCIONES

•
-C, --hierarchy=OBJETO:

Especifica la jerarquía utilizada para autorizar. Las opciones soportadas son:

•
o para TPM_RH_OWNER
•
p para TPM_RH_PLATFORM
•
<num> donde se puede usar un manejador de jerarquía o un índice NV.

Cuando -C no se pasa explícitamente, el manejador del índice se usará para autorizar contra el índice. El valor de autorización del índice se establece mediante la opción -p de tpm2_nvdefine(1).

•
-P, --auth=AUTH:

Especifica el valor de autorización para la jerarquía.

•
-i, --bits=BITS:

Especifica el valor de bits como un número para aplicar OR lógico al valor actual del índice NV.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash, a menos que también se requiera rphash.

•
--rphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros de respuesta. Esto se denomina comúnmente rpHash.

•
-S, --session=ARCHIVO:

La sesión creada con tpm2_startauthsession. Esto se puede usar para especificar una sesión auxiliar para auditoría y/o cifrado/descifrado de parámetros.

•
-n, --name=ARCHIVO:

El nombre del índice NV que debe proporcionarse al calcular solo el cpHash sin enviar realmente el comando al TPM.

•
ARGUMENTO el argumento de la línea de comandos especifica el índice NV o el número de desplazamiento.

Referencias

Formato del objeto de contexto

El tipo de un objeto de contexto, ya sea un manejador o un nombre de archivo, se determina de acuerdo con la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, entonces se carga el archivo como un objeto transitorio de TPM restaurado.
•
Si el argumento coincide con un *prefijo* de uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un manejador, por ejemplo, 0x81010013 y se usará directamente._OBJETO_.

Formato de autorización

La autorización para usar un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autorizaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación usando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña en formato de cadena, especificada por el prefijo "str:" o su ausencia (cadena cruda sin prefijo) no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena hexadecimal

Una contraseña en formato de cadena hexadecimal, especificada por el prefijo "hex:", se convierte de formato hexadecimal a formato de arreglo de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables con la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo "file:", debe ser la ruta de un archivo que contenga la contraseña a leer por la herramienta o un "-" para usar stdin. Almacenar contraseñas en archivos evita fugas de información; las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de características comunes del historial del shell.

Ejemplos

# para usar stdin y que se solicite
file:-
# para usar un archivo de una ruta
file:ruta/a/archivo/de/contraseña
# para enviar una contraseña vía stdin:
echo foobar | tpm2_tool -p file:-
# para usar una cadena aquí de bash vía stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave *session*. Luego indique una ruta a un archivo de sesión que fue creado con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autorización para ser enviado con el manejador de sesión (por ejemplo, contraseña de política), agregue un + y una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones PCR

Puede satisfacer una política de PCR usando el prefijo "pcr:" y el minilenguaje de PCR. El minilenguaje de PCR es el siguiente: <especificador-pcr>=<archivo-pcr-crudo>

El especificador de PCR se documenta en la sección "Especificadores de banco de PCR".

El archivo-pcr-crudo es un argumento opcional que contiene la salida del contenido crudo del PCR tal como lo devuelve tpm2_pcrread(1).

NOMBRE

tpm2_nvsetbits - Establece bits en un índice de NV (Non-Volatile) del TPM.

SINOPSIS

tpm2_nvsetbits [opciones] [-C objeto_contexto] [-P contraseña_autorización] [-o ruta_archivo_salida] -i valor_bits_a_establecer indice

DESCRIPCIÓN

Establece bits en un índice de memoria no volátil (NV) del TPM. El índice debe haber sido definido previamente con los atributos adecuados para permitir esta operación. La operación de establecimiento de bits es una operación AND bit a bit entre el valor actual y el valor proporcionado. Para establecer bits, se requiere la autorización adecuada, que puede ser la autorización de propietario o la autorización de política específica, según los atributos del índice NV.

La operación bit a bit es la siguiente:

NV_Index_Value = NV_Index_Value | Value_To_Set

OPCIONES

-C objeto_contexto

El objeto de contexto que contiene la autorización y el objeto de sesión de política. El formato es: auth:palabra_contraseña o session:ruta_archivo_sesion.

Si el valor es o, se utiliza la autorización del propietario del TPM. Si el valor es e, se utiliza la autorización del evocador.

Si el objeto de contexto es un índice de NV, se utiliza la autorización de ese índice de NV.

También se pueden utilizar los identificadores de objetos del TPM.

Por ejemplo:

-C o            # Use owner authorization
-C e            # Use evocator authorization
-C 0x12345678   # Use the object handle 0x12345678
-C session:my_session.bin # Use a policy session
-C auth:my_password # Use a password for authorization

El formato predeterminado es o (propietario).

Consulte también tpm2_load(1) y tpm2_policycommand(1).

-P contraseña_autorización
La contraseña para el contexto de autorización. Puede ser la contraseña del propietario, la contraseña del evocador, o la contraseña de una política.
-o ruta_archivo_salida
Escribe el valor leído del índice NV en el archivo especificado. Si no se especifica, el valor leído se imprime en stdout en formato hexadecimal (con prefijo 0x).
-i valor_bits_a_establecer
El valor de los bits que se establecerán. Este valor se somete a una operación OR bit a bit con el valor actual del índice NV.

Formato del Objeto de Contexto

El formato del objeto de contexto es el siguiente:

pcr:sha256:0,1,2,3

especificando AUTH.

Formato de Autorización

Puede especificar la autorización de diferentes maneras:

-P mi_contraseña
-C o -P mi_contraseña_propietario
-C e -P mi_contraseña_evocador
-C session:my_policy.bin -P mi_contraseña_sesion

Configuración TCTI

El TCTI o “Interfaz de Transmisión” es el mecanismo de comunicación con el TPM. Los TCTIs se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTIs conocidos actualmente son:

• tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre tcti son sinónimos.
• mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
• device - Utilizado al hablar directamente con el archivo del dispositivo TPM.
• none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo admiten darán error al intentar usarlas sin una conexión TCTI. No admite NINGUNA opción y DEBE ser presentado como el texto exacto de “none”.

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre_tcti>:<config_opciones_tcti>

Especificar una cadena vacía para <nombre_tcti> o <config_opciones_tcti> da como resultado que se utilice el valor predeterminado para esa parte respectivamente.

Predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTIs tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor “default-tcti” indicará cuál de los TCTIs mencionados es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor bruto de tcti-name se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entiende la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utilizan para configurar los diversos módulos TCTI conocidos disponibles:

• device: Para el TCTI device, se puede especificar el archivo del dispositivo de caracteres TPM para su uso por el TCTI device. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

• mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

• abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter “,”. Cada cadena de clave y valor están separadas por un carácter “=”.
• El TCTI abrmd soporta dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia dbus (una cadena) limitada a `session' y `system'.

Especifica el nombre tcti tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifica el tcti predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

O 0xbadc0de en un índice de 0’s

tpm2_nvdefine -C o -a "nt=bits|ownerread|policywrite|ownerwrite|writedefine" 1
tpm2_nvsetbits -C o -i 0xbadc0de 1
tpm2_nvread -C o 1 | xxd -p | sed s/'^0*'/0x/
0xbadc0de

Devoluciones

Las herramientas pueden devolver cualquiera de los siguientes códigos:

• 0 - Éxito.
• 1 - Error general no específico.
• 2 - Error en el manejo de opciones.
• 3 - Error de autenticación.
• 4 - Error relacionado con TCTI.
• 5 - Esquema no soportado. Aplicable a tpm2_testparams.
