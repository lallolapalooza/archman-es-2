tpm2_policyor(1) Manual de Comandos Generales tpm2_policyor(1)

NOMBRE

tpm2_policyor(1) - Pone en OR lógico dos políticas.

SINOPSIS

tpm2_policyor [OPCIONES]

DESCRIPCIÓN

tpm2_policyor(1) - Genera un evento policy_or con el TPM. Espera que una sesión ya esté establecida a través de tpm2_startauthsession(1). Si la sesión de entrada es una sesión de prueba esta herramienta genera un resumen de política que compone dos o más resúmenes de política de entrada de tal manera que el resumen de política resultante requiere que al menos uno de los eventos de política sea verdadero. Si la sesión de entrada es una sesión de política real tpm2_policyor(1) autentica el objeto con éxito si al menos uno de los eventos de política son verdaderos.

OPCIONES

•
-L, --policy=ARCHIVO:

Archivo donde guardar el resumen de política compuesto.

•
-S, --session=ARCHIVO:

El archivo de sesión de política generado a través de la opción -S de tpm2_startauthsession(1).

•
ARGUMENTO El argumento de línea de comandos especifica la lista de archivos para los resúmenes de política que deben ser compuestos, resultando en políticas individuales que se añaden al resumen de política final que puede autenticar el objeto. La lista comienza con el alg de hash del resumen de política. Ejemplo sha256:policy1,policy2
•
-l, --policy-list=LISTA_DE_ARCHIVOS_DE_POLÍTICA:

Esta opción está OBSOLETA pero se mantiene por compatibilidad hacia atrás. Usa el método de argumento en su lugar. NOTA: Cuando se especifica -l y un argumento es lo mismo que especificarlo todo a la vez. Por ejemplo: tpm2_policyor -l sha256:file1 sha256:file2 es lo mismo que tpm2_policyor sha256:file1,file2.

Configuración TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTIs se pueden cambiar para comunicarse con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTIs conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente usado para comunicarse con el simulador de software del TPM.
•
device - Usado al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones "off-tpm" y por lo tanto soportan no usar un TCTI. Las herramientas que no lo soportan fallarán cuando se intenten usar sin una conexión TCTI. No soporta NINGUNA opción y DEBE presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno están en el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o <config-opciones-tcti> resulta en el uso del valor predeterminado para esa porción respectivamente.

Valores predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTIs tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO ENCONTRADO. Puede consultar qué TCTI se elegirá como predeterminado usando la opción -v para mostrar la información de versión. El par clave-valor "default-tcti" indicará cuál de los TCTIs mencionados es el predeterminado.

TCTIs personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica puede ser cargado. Las herramientas utilizan internamente dlopen(3), y el valor crudo tcti-name se utiliza para la búsqueda. Por lo tanto, esta podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entendido por la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres del TPM para uso del TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares clave-valor simples separados por un carácter `,'. Cada clave y valor se separan por un carácter `=´.
•
El TCTI abrmd soporta dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia dbus (una cadena) limitada a `session' y `system'.

DESCRIPTION

The tpm2_policyor command is used to create an authorization policy that is satisfied if any of the provided sub-policies are satisfied. This command is part of the tpm2-tools suite, which provides a set of tools for managing and interacting with a Trusted Platform Module (TPM).

The command takes an authorization session, an output policy file, and a list of input policy files. It then computes the OR combination of the input policies and stores the result in the output policy file. The policy session is used to keep track of the policy being built.

The structure of the command is as follows:

tpm2_startauthsession -S session.ctx
tpm2_policyor -S session.ctx -L policy.or policy1 policy2 ...
tpm2_flushcontext session.ctx

Where policy1, policy2, etc. are policy files previously created using other tpm2_policy commands (e.g., tpm2_policypcr(1), tpm2_policypassword(1)).

OPTIONS

A list of all the options supported by the command.

--help

--version
‑c SESSION

The policy session context, created using tpm2_startauthsession(1).

‑L POLICY

The policy file to write the resulting OR policy to.

‑p PROFILES

A comma-separated list of policy files to be OR-ed together.

These options are common to all tpm2 commands.

TCTI Configuration

This command uses the TPM Transmission Control Interface (TCTI) to communicate with the TPM. The TCTI can be configured using various methods, including:

--tcti=device:%s%s

Specify the device TCTI and a configuration string:

--tcti=device:ttyS0

Specify the socket TCTI and a configuration string:

--tcti=socket:host=127.0.0.1,port=2321

Specify the library TCTI and a configuration string:

--tcti=library:libfile.so

Specify the mtssoc TCTI and a configuration string:

--tcti=mtssoc:host=192.168.1.100,port=12345

Specify the tabrmd TCTI and a configuration string:

--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Create an authorization policy for a sealing object that compounds a pcr policy and a policypassword in an OR fashion and show satisfying either policies could unseal the secret.

Create policypcr as first truth value for compounding the policies

tpm2_startauthsession -S session.ctx
tpm2_policypcr -S session.ctx -L policy.pcr -l sha256:0,1,2,3
tpm2_flushcontext session.ctx

Create policypassword as second truth value for compounding the policies

tpm2_startauthsession -S session.ctx
tpm2_policypassword -S session.ctx -L policy.pass
tpm2_flushcontext session.ctx

Compound the two policies in an OR fashion with tpm2_policyor command

tpm2_startauthsession -S session.ctx
tpm2_policyor -S session.ctx -L policy.or sha256:policy.pass,policy.pcr
tpm2_flushcontext session.ctx

Create a sealing object and attach the auth policy from tpm2_policyor command

tpm2_createprimary -c prim.ctx -Q
echo "secret" | tpm2_create -C prim.ctx -c key.ctx -u key.pub -r key.priv \
-L policy.or -i-

Satisfy auth policy using password and unseal the secret

tpm2_startauthsession -S session.ctx --policy-session
tpm2_policypassword -S session.ctx
tpm2_policyor -S session.ctx sha256:policy.pass,policy.pcr
tpm2_unseal -c key.ctx -p session:session.ctx
tpm2_flushcontext session.ctx

Satisfy auth policy using pcr and unseal the secret

tpm2_startauthsession -S session.ctx --policy-session
tpm2_policypcr -S session.ctx -l sha256:0,1,2,3
tpm2_policyor -S session.ctx sha256:policy.pass,policy.pcr
tpm2_unseal -c key.ctx -p session:session.ctx
tpm2_flushcontext session.ctx

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
