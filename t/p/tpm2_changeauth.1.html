tpm2_changeauth(1) Manual de Comandos Generales tpm2_changeauth(1)

NOMBRE

tpm2_changeauth - Cambia los valores de autorización para objetos TPM.

SINOPSIS

tpm2_changeauth [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_changeauth - Configura los valores de autorización para las distintas jerarquías, índices NV, objetos transitorios y persistentes.

Nota: Para objetos no permanentes (objetos transitorios y objetos persistentes), las copias de la información privada (archivos o identificadores persistentes) creadas antes de cambiar la autorización no se invalidan.

OPCIONES

Las contraseñas deben seguir las "normas de formato de autorización de contraseñas", véase la sección "Formato de Autorización".

•
-c, --object-context=OBJETO:

El objeto de contexto de clave a utilizar para la operación.

•
-p, --object-auth=AUTH:

El valor de autorización anterior para el objeto TPM especificado con -c.

•
-C, --parent-context=OBJETO:

El objeto padre. Esto es necesario si el objeto para la operación es un objeto transitorio o persistente.

•
-r, --private=ARCHIVO: El archivo de salida que contiene la nueva porción sensible del objeto cuya autorización se estaba cambiando. # Detalles de Protección

Los objetos que pueden moverse fuera del TPM necesitan ser protegidos (confidencialidad e integridad). Por ejemplo, los objetos transitorios requieren que los datos protegidos por TPM (clave o material de sellado) se almacenen fuera del TPM. Esto se ve en herramientas como tpm2_create(1), donde la opción -r genera esta información protegida. Este blob contiene las porciones sensibles del objeto. Las porciones sensibles del objeto están protegidas por el objeto padre, utilizando los detalles de cifrado simétrico del padre para cifrar los datos sensibles y generar un HMAC sobre ellos.

Se pueden encontrar detalles exhaustivos en la sección 23 de:

•
https://trustedcomputinggroup.org/wp-content/uploads/TPM-Rev-2.0-Part-1-Architecture-01.38.pdf

Notablemente la Figura 20 es relevante, aunque se refiera específicamente a blobs de duplicación, el proceso es idéntico.

Si la salida proviene de tpm2_duplicate(1), la salida será ligeramente diferente, tal como se describe completamente en la sección 23.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará el comando, simplemente devolverá un cpHash, a menos que también se requiera rphash.

•
--rphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros de respuesta. Esto se denomina comúnmente rpHash.

•
-S, --session=ARCHIVO:

La sesión creada usando tpm2_startauthsession. Esto se puede usar para especificar una sesión auxiliar para auditoría y/o cifrado/descifrado de los parámetros.

•
ARGUMENTO el argumento de línea de comandos especifica la AUTH que se establecerá para el objeto especificado con -c.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un identificador o un nombre de archivo, se determina según la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, se carga el archivo como un objeto TPM transitorio restaurado.
•
Si el argumento coincide con un *prefijo* de uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de aprobación
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un identificador, por ejemplo, 0x81010013 y se usará directamente._OBJETO_.

Formato de Autorización

La autorización para usar un objeto en TPM2.0 puede venir de 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autorizaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas usando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña en formato de cadena, especificada por el prefijo "str:" o su ausencia (cadena sin prefijo), no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña en formato de cadena hexadecimal, especificada por el prefijo "hex:", se convierte de formato hexadecimal a formato de arreglo de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables para la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo "file:", debe ser la ruta de un archivo que contenga la contraseña a ser leída por la herramienta o un "-" para usar stdin. Almacenar contraseñas en archivos previene fugas de información, las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las características comunes del historial de shell.

Ejemplos

# para usar stdin y que se solicite la contraseña
file:-
# para usar un archivo de una ruta
file:ruta/a/archivo/contraseña
# para hacer eco de una contraseña vía stdin:
echo foobar | tpm2_tool -p file:-
# para usar un here-string de bash vía stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego, indique una ruta a un archivo de sesión que fue creado con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autorización para ser enviado con el identificador de sesión (por ejemplo, contraseña de política), entonces agregue un + y una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización HEX 0x11223344.

session:session.ctx+hex:11223344

ESPECIFICADORES_PCR

El PCR specifier es un argumento opcional. Cuando se usa, permite especificar las políticas de PCR. La sintaxis es la siguiente:

La política se define utilizando el prefijo “pcr:” y el minilenguaje PCR. El minilenguaje PCR es el siguiente:

<espec-pcr>=<archivo-pcr-crudo>

La especificación PCR está documentada en la sección “Especificadores de banco PCR”.

El archivo-pcr-crudo es un argumento opcional que contiene la salida de los contenidos PCR crudos tal como los devuelve tpm2_pcrread(1).

Ejemplos

Para satisfacer una política de PCR de sha256 en los bancos 0, 1, 2 y 3, usa el siguiente especificador:

pcr:sha256:0,1,2,3

especificando AUTH.

Configuración_TCTI

El TCTI o “Interfaz de Transmisión” es el mecanismo de comunicación con el TPM. Los TCTIs se pueden cambiar para comunicarse con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTIs conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombres de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Utilizado al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones off-tpm y por lo tanto soportan no usar un TCTI. Las herramientas que no lo soportan darán error cuando se intente usar sin una conexión TCTI. No soporta NINGUNA opción y DEBE presentarse como el texto exacto de “none”.

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <config-opciones-tcti> resulta en el uso del valor predeterminado para esa porción respectivamente.

Valores_Predeterminados_TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTIs tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO ENCONTRADO. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para imprimir la información de la versión. El par clave-valor “default-tcti” indicará cuál de los TCTIs mencionados es el predeterminado.

TCTIs_Personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica puede ser cargado. Las herramientas utilizan internamente dlopen(3), y el valor crudo nombre-tcti se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca tal como lo entiende la semántica de dlopen(3).

OPCIONES_TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres TPM para su uso por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples clave-valor separados por un carácter `,`. Cada cadena de clave y valor está separada por un carácter `=`.
•
El TCTI abrmd soporta dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia de dbus (una cadena) limitada a `session' y `system'.

Especifica el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifica el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

Establecer_autorizaciones_de_propietario,_respaldo_y_bloqueo_a_newpass

tpm2_changeauth -c owner newpass
tpm2_changeauth -c endorsement newpass
tpm2_changeauth -c lockout newpass

Cambiar_autorizaciones_de_propietario,_respaldo_y_bloqueo

tpm2_changeauth -c o -p newpass newerpass
tpm2_changeauth -c e -p newpass newerpass
tpm2_changeauth -c l -p newpass newerpass

Establecer_la_autorización_de_propietario_a_contraseña_vacía

tpm2_changeauth -c o -p oldpass

Modificar_autorización_para_un_objeto_transitorio_cargable

tpm2_createprimary -Q -C o -c prim.ctx
tpm2_create -Q -g sha256 -G aes -u key.pub -r key.priv -C prim.ctx
tpm2_load -C prim.ctx -u key.pub -r key.priv -n key.name -c key.ctx
tpm2_changeauth -c key.ctx -C prim.ctx -r key.priv newkeyauth

Modificar_autorización_para_un_Índice_NV

Requiere Soporte de Sesión Extendida.

tpm2_startauthsession -S session.ctx
tpm2_policycommandcode -S session.ctx -L policy.nvchange TPM2_CC_NV_ChangeAuth
tpm2_flushcontext session.ctx
NVIndex=0x1500015
tpm2_nvdefine   $NVIndex -C o -s 32 -a "authread|authwrite" -L policy.nvchange
tpm2_startauthsession \--policy-session -S session.ctx
tpm2_policycommandcode -S session.ctx -L policy.nvchange TPM2_CC_NV_ChangeAuth
tpm2_changeauth -p session:session.ctx -c $NVIndex newindexauth
