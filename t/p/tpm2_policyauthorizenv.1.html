tpm2_policyauthorizenv(1) Manual de Comandos Generales tpm2_policyauthorizenv(1)

NOMBRE

tpm2_policyauthorizenv(1) - Permite políticas mutables haciendo referencia a una política de un índice NV.

SINOPSIS

tpm2_policyauthorizenv [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_policyauthorizenv(1) - Este comando permite que las políticas cambien haciendo referencia a la política de autorización escrita en un índice NV. El índice NV que contiene la política de autorización debe permanecer legible incluso para sesiones de prueba. El índice puede especificarse como un manejador bruto o un valor de desplazamiento del rango de manejadores nv “TPM2_HR_NV_INDEX”.

OPCIONES

•
-C, --hierarchy=OBJETO:

Especifica la jerarquía utilizada para autorizar. Las opciones admitidas son:

•
o para TPM_RH_OWNER
•
p para TPM_RH_PLATFORM
•
<num> donde se puede usar un manejador de jerarquía o un índice nv.

Cuando -C no se pasa explícitamente, el manejador del índice se utilizará para autorizar contra el índice. El valor de autorización del índice se establece a través de la opción -p de tpm2_nvdefine(1).

•
-P, --auth=AUTH:

Especifica el valor de autorización para la jerarquía.

•
-L, --policy=ARCHIVO:

Archivo donde guardar el resumen de la política.

•
-S, --session=ARCHIVO:

Archivo de sesión de política generado a través de la opción -S de tpm2_startauthsession(1).

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se conoce comúnmente como cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará el comando, simplemente devolverá un cpHash.

Configuración TCTI

El TCTI o “Interfaz de Transmisión” es el mecanismo de comunicación con el TPM. Los TCTIs se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre tiene prioridad sobre la variable de entorno.

Los TCTIs conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombres de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Utilizado al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera de TPM y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo soportan darán un error cuando se intenten usar sin una conexión TCTI. No soporta *NINGUNA* opción y *DEBE* presentarse como el texto exacto de “none”.

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<configuración-opción-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <configuración-opción-tcti> da como resultado que se utilice el valor predeterminado para esa parte respectivamente.

Predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán tabrmd, device y mssim TCTIs **EN ESE ORDEN** y **USARÁN EL PRIMERO QUE ENCUENTREN**. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor “default-tcti” indicará cuál de los TCTIs mencionados es el predeterminado.

TCTIs Personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica puede cargarse. Las herramientas utilizan internamente dlopen(3), y el valor bruto tcti-name se utiliza para la búsqueda. Por lo tanto, podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entiendan las semánticas de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI device, se puede especificar el archivo del dispositivo de caracteres del TPM para su uso por el TCTI device. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se pueden especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter `,`. Cada clave y valor se separan por un carácter `=.
•
TCTI abrmd soporta dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de instancia de dbus (una cadena) limitada a `session' y `system'.

Especificar el nombre tcti de tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especificar el tcti predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

Crear una contraseña de política y escribir el resumen de la política en un índice NV. Construir una política policyauthorizenv que haga referencia al índice NV en una sesión de *trial*. El resumen de política resultante se utiliza luego en la creación de objetos.

En una sesión de autorización de política, primero satisface la política escrita en el índice NV. Luego ejecuta policyauthorizenv, que satisface la autorización para el objeto.

Definir el índice NV de prueba para almacenar la política de autorización

nv_test_index=0x01500001
tpm2_nvdefine -C o -p nvpass $nv_test_index -a "authread|authwrite" -s 34

Definir la política de autorización

tpm2_startauthsession -S session.ctx
tpm2_policypassword -S session.ctx -L policy.pass
tpm2_flushcontext session.ctx

Escribir la política de autorización en el índice NV

echo "000b" | xxd -p -r | cat - policy.pass | \
tpm2_nvwrite -C $nv_test_index -P nvpass $nv_test_index -i-

Definir policyauthorizenv

tpm2_startauthsession -S session.ctx
tpm2_policyauthorizenv -S session.ctx -C $nv_test_index -P nvpass \
-L policyauthorizenv.1500001 $nv_test_index
tpm2_flushcontext session.ctx

Crear y cargar un objeto de sellado con auth policy = policyauthorizenv

tpm2_createprimary -C o -c prim.ctx
echo "secretdata" | \
tpm2_create -C prim.ctx -u key.pub -r key.priv \
-a "fixedtpm|fixedparent|adminwithpolicy" -L policyauthorizenv.1500001 -i-
tpm2_load -C prim.ctx -u key.pub -r key.priv -c key.ctx

Satisfacer la política de autorización almacenada en el índice NV y por lo tanto policyauthorizenv

tpm2_startauthsession -S session.ctx --policy-session
tpm2_policypassword -S session.ctx
tpm2_policyauthorizenv -S session.ctx -C $nv_test_index -P nvpass $nv_test_index
tpm2_unseal -c key.ctx -p session:session.ctx
tpm2_flushcontext session.ctx

Devoluciones

Las herramientas pueden devolver cualquiera de los siguientes códigos:

•
0 - Éxito.
•
1 - Error general no específico.
•
2 - Error de manejo de opciones.
•
3 - Error de autenticación.
•
4 - Error relacionado con TCTI.
•
5 - Esquema no soportado. Aplicable a tpm2_testparams.

Limitaciones

Espera que una sesión ya se haya establecido a través de tpm2_startauthsession(1) y requiere uno de los siguientes:

•
acceso directo al dispositivo
•
soporte de sesión extendida con tpm2-abrmd.

Sin él, la mayoría de los administradores de recursos no guardarán el estado de la sesión entre invocaciones de comandos.
