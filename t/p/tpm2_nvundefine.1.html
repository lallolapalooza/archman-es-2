tpm2_nvundefine(1) Manual de Comandos Generales tpm2_nvundefine(1)

NOMBRE

tpm2_nvundefine(1) - Elimina un índice No Volátil (NV).

SINOPSIS

tpm2_nvundefine [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_nvundefine(1) - Elimina un índice No Volátil (NV) que previamente fue definido con tpm2_nvdefine(1). El índice se especifica como un argumento. Puede especificarse como un identificador crudo o un valor de desplazamiento del rango de identificadores nv “TPM2_HR_NV_INDEX”.

La herramienta también es capaz de eliminar índices NV con el atributo TPMA_NV_POLICY_DELETE, y la herramienta utiliza este atributo para la jerarquía predeterminada para seleccionar cuándo -C falta. El valor predeterminado para -C es la jerarquía “propietario” cuando TPMA_NV_POLICY_DELETE está despejado y “plataforma” cuando TPMA_NV_POLICY_DELETE está establecido.

OPCIONES

•
-C, --hierarchy=OBJETO:

Especifica la jerarquía utilizada para autorizar. Las opciones admitidas son:

•
o para TPM_RH_OWNER
•
p para TPM_RH_PLATFORM
•
<num> donde se puede especificar un identificador de jerarquía.
•
-P, --auth=AUTENTICACIÓN:

Especifica el valor de autenticación para la jerarquía.

•
-S, --session=SESIÓN_DE_POLÍTICA:

Especifica una sesión de política a usar cuando el índice NV tiene el atributo TPMA_NV_POLICY_DELETE establecido. Esto también se puede usar para especificar una sesión auxiliar para auditoría y/o cifrado/descifrado de los parámetros. Nota:

1.
Si se invoca TPM2_CC_NV_UndefineSpaceSpecial, solo se puede especificar una sesión auxiliar adicional. El orden en que se especifican las sesiones también importa. La primera especificación de -S se interpreta como la sesión para satisfacer el rol de ADMIN requerido para TPM2_CC_NV_UndefineSpaceSpecial.
2.
Si se invoca TPM2_CC_NV_Undefine, solo se pueden especificar dos sesiones auxiliares adicionales.
•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash, simplemente devolverá un cpHash a menos que también se requiera rphash.

•
--rphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros de respuesta. Esto se denomina comúnmente rpHash.

•
--with-policydelete=NINGUNO

Esto debe especificarse al calcular el cpHash con --tcti=none. Este es un requisito porque no hay forma de saber si el atributo TPMA_NV_POLICYDELETE se ha establecido solo a partir del nombre del índice NV.

•
-n, --name=ARCHIVO:

El nombre del índice NV que debe proporcionarse al calcular solo el cpHash sin enviar realmente el comando al TPM.

•
ARGUMENTO El argumento de la línea de comandos especifica el índice NV o el número de desplazamiento.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un identificador o un nombre de archivo, se determina según la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, se carga el archivo como un objeto transitorio TPM restaurado.
•
Si el argumento coincide con un *prefijo* de uno de:
•
propietario: la jerarquía del propietario
•
plataforma: la jerarquía de la plataforma
•
aval: la jerarquía de aval
•
bloqueo: el objeto persistente de control de bloqueo
•
Si el argumento se puede cargar como un número, se tratará como un identificador, por ejemplo, 0x81010013 y se usará directamente._OBJETO_.

Formato de Autenticación

La autenticación para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: “Las autenticaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican”.

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación utilizando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña de cadena, especificada por el prefijo “str:” o su ausencia (cadena cruda sin prefijo) no se interpreta y se utiliza directamente para la autenticación.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña de cadena hexadecimal, especificada por el prefijo “hex:” se convierte de un formato hexadecimal a un formato de array de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables para la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo “file:” debe ser la ruta de un archivo que contenga la contraseña a leer por la herramienta o un “-” para usar stdin. Almacenar contraseñas en archivos evita fugas de información, las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las características comunes del historial del shell.

Ejemplos

# para usar stdin y que se solicite
file:-
# para usar un archivo desde una ruta
file:ruta/a/archivo/de/contraseña
# para enviar una contraseña vía stdin:
echo foobar | tpm2_tool -p file:-
# para usar una cadena aquí de bash vía stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación para ser enviado con el identificador de sesión (por ejemplo, contraseña de política), agregue un + y una cadena como se describe en la sección de Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación *HEX* 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones PCR

Puede satisfacer una política PCR utilizando el prefijo "pcr:" y el minilenguaje PCR. El minilenguaje PCR es el siguiente: <pcr-spec>=<raw-pcr-file>

La especificación PCR se documenta en la sección "Especificadores del banco PCR".

El archivo-pcr-crudo es un argumento opcional que contiene la salida de los contenidos crudos de PCR tal como la devuelve tpm2_pcrread(1).

Especificadores del banco PCR

Ejemplos

Para satisfacer una política PCR de sha256 en los bancos 0, 1, 2 y 3, utilice un especificador de:

pcr:sha256:0,1,2,3

especificando AUTH.

Configuración del TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombres de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software TPM.
•
device - Se utiliza al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, soportan no usar un TCTI. Las herramientas que no lo soportan darán un error cuando se intenten usar sin una conexión TCTI. No soporta NINGUNA opción y DEBE presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o el <config-opciones-tcti> resulta en el uso del valor predeterminado para esa porción respectivamente.

Valores predeterminados del TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim EN ESE ORDEN y UTILIZARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para imprimir la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor crudo nombre-tcti se utiliza para la búsqueda. Por lo tanto, esta podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entienda la semántica de dlopen(3).

OPCIONES DEL TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres TPM para su uso por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se pueden especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter ','. Cada cadena de clave y valor están separadas por un carácter '='.
•
El TCTI abrmd soporta dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia de dbus (una cadena) limitada a 'session' y 'system'.

Especifica el nombre TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifica el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

Define un índice NV ordinario y elimínalo

tpm2_nvdefine 1
tpm2_nvundefine 1

Define un índice NV ordinario con el atributo TPMA_NV_POLICY_DELETE y elimínalo

tpm2_startauthsession -S s.ctx
tpm2_policyauthvalue -S s.ctx
tpm2_policycommandcode -S s.ctx -L policy.dat TPM2_CC_NV_UndefineSpaceSpecial
tpm2_nvdefine -C p -s 32 \
  -a "ppread|ppwrite|authread|authwrite|platformcreate|policydelete|write_stclear|read_stclear" \
  -L policy.dat 1
tpm2_flushcontext s.ctx
tpm2_startauthsession --policy-session -S s.ctx
tpm2_policyauthvalue -S s.ctx
tpm2_policycommandcode -S s.ctx TPM2_CC_NV_UndefineSpaceSpecial
tpm2_nvundefine -S s.ctx 1

Devoluciones

Las herramientas pueden devolver cualquiera de los siguientes códigos:

•
0 - Éxito.
•
1 - Error general no específico.
•
2 - Error en el manejo de opciones.
•
3 - Error de autenticación.
•
4 - Error relacionado con TCTI.
•
5 - Esquema no soportado. Aplicable a tpm2_testparams.
