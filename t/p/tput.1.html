tput(1) Comandos de usuario tput(1)

NOMBRE

tput - inicializa un terminal, ejercita sus capacidades o consulta la base de datos de terminfo

SINOPSIS

tput [-T tipo-terminal] {codigo-capacidad [parametro ...]} ...

tput [-T tipo-terminal] [-x] clear

tput [-T tipo-terminal] init

tput [-T tipo-terminal] reset

tput [-T tipo-terminal] longname

tput -S

tput -V

DESCRIPCIÓN

tput utiliza la biblioteca y base de datos de terminfo para poner a disposición de la shell capacidades e información específicas del terminal, para inicializar o restaurar el terminal, o para informar sobre una descripción del tipo de terminal actual (o especificado). Las capacidades del terminal se acceden mediante codigo-capacidad.

terminfo(5) discute las capacidades del terminal en detalle y presenta una lista completa de codigos-capacidad.

Al recuperar los valores de las capacidades, el resultado depende del tipo de capacidad.

Booleano
tput establece su estado de salida a 0 si el terminal posee codigo-capacidad, y 1 si no.
numérico
tput escribe el valor decimal de codigo-capacidad en el flujo de salida estándar si está definido (-1 si no lo está) seguido de una línea nueva.
cadena
tput escribe el valor de codigo-capacidad en el flujo de salida estándar si está definido, sin una línea nueva al final.

Antes de utilizar un valor devuelto en la salida estándar, la aplicación debe comprobar el estado de salida de tput para asegurarse de que es 0; véase la sección “ESTADO DE SALIDA” más abajo.

Operandos

Generalmente, un operando es un codigo-capacidad, un código de capacidad de la base de datos del terminal, o un parámetro del mismo. Otros tres son reconocidos especialmente por tput: init, reset y longname. Aunque se parecen a los códigos de capacidad, en realidad reciben un manejo especial; los denominamos “pseudo-capacidades”.

codigo-capacidad
indica una capacidad de la base de datos del terminal.
Si codigo-capacidad es de tipo cadena y toma parámetros, tput interpreta los argumentos que siguen a codigo-capacidad como los parámetros, hasta la cantidad (fija) que la capacidad requiere.
La mayoría de los parámetros son numéricos. Solo unas pocas capacidades de terminal requieren parámetros de cadena; tput utiliza una tabla para decidir cuáles pasar como cadenas. Normalmente tput utiliza tparm(3X) para realizar la sustitución. Si no se proporcionan parámetros para la capacidad, tput escribe la cadena sin realizar la sustitución.
init
inicializa el terminal. Si la base de datos del terminal está presente y existe una entrada para el tipo de terminal del usuario, ocurren los siguientes eventos.
(1)
tput recupera la configuración del modo del terminal. Prueba sucesivamente los descriptores de archivo correspondientes a
  • el flujo de error estándar,
  • el flujo de salida estándar,
  • el flujo de entrada estándar y
  • /dev/tty
para obtener la configuración del terminal. Habiéndola recuperado, tput recuerda qué descriptor utilizar para futuras actualizaciones.
(2)
Si las dimensiones del terminal no se pueden obtener del sistema operativo, pero el entorno o la entrada de la base de datos del tipo de terminal las describen, tput actualiza la noción del sistema operativo sobre ellas.
(3)
tput actualiza los modos del terminal.
  • Cualquier retraso especificado en la entrada (por ejemplo, al enviar una línea nueva) se establece en el controlador del terminal.
  • La expansión de tabulaciones se activa o desactiva según la especificación en la entrada, y
  • si las tabulaciones no se expanden, se establecen las tabulaciones estándar (cada 8 espacios).
(4)
Si las capacidades de inicialización, detalladas en la subsección “Pestañas e Inicialización” de terminfo(5), están presentes, tput las escribe en el flujo de salida estándar.
(5)
tput vacía el flujo de salida estándar.
Si una entrada carece de la información necesaria para una actividad anterior, esa actividad se omite silenciosamente.
reset
reinicializa el terminal. Una restauración difiere de una inicialización en dos aspectos.
(1)
tput establece los modos del terminal en un estado “sano”,
  • activando los modos "cooked" y de eco,
  • desactivando los modos cbreak y raw,
  • activando la traducción de línea nueva, y
  • estableciendo los caracteres especiales no definidos a sus valores predeterminados.
(2)
Si se definen capacidades de restauración para el tipo de terminal, tput las escribe en el flujo de salida. De lo contrario, tput utiliza las capacidades de inicialización definidas. Las capacidades de restauración se detallan en la subsección “Pestañas e Inicialización” de terminfo(5).
longname
Una entrada de terminfo comienza con uno o más nombres por los cuales una aplicación puede referirse a la entrada, antes de la lista de capacidades del terminal. Los nombres están separados por caracteres “|”. X/Open Curses denomina al último nombre el “nombre largo”, e indica que puede incluir espacios.
tic advierte si el último nombre no incluye espacios, para acomodar entradas antiguas de terminfo que trataban el nombre largo como una característica opcional. El nombre largo a menudo se denomina campo de descripción.
Si la base de datos del terminal está presente y existe una entrada para el tipo de terminal del usuario, tput informa su descripción en el flujo de salida estándar, sin una línea nueva al final. Véase terminfo(5).

Nota: Redirigir la salida de “tput init” o “tput reset” a un archivo capturará solo parte de sus acciones. Los cambios en los modos del terminal no se ven afectados por la redirección de descriptores de archivo, ya que los modos del terminal se modifican a través de ioctl(2).

Alias

Si tput se invoca a través de un enlace con alguno de los nombres clear, init o reset, opera como si se ejecutara con el operando (pseudo-)capacidad correspondiente. Por ejemplo, ejecutar un enlace llamado reset que apunta a tput tiene el mismo efecto que “tput reset”.

Esta característica fue introducida por ncurses 5.2 en 2000. Rara vez se utiliza:

clear
es un programa separado, que es tanto más pequeño como más frecuentemente ejecutado.
init
tiene el mismo nombre que otro programa de uso generalizado.
reset
es proporcionado por la utilidad tset(1) (también a través de un enlace llamado reset).

Tamaño del terminal

Además de las pseudo-capacidades (como init), tput trata los codigos-capacidad lines y cols especialmente: puede llamar a setupterm(3X) para obtener el tamaño del terminal.

  • Primero, tput intenta obtener estas capacidades de la base de datos del terminal. Esto generalmente falla para los emuladores de terminal, que carecen de un tamaño de ventana fijo y, por lo tanto, omiten las capacidades.

    OPCIONES

    -S
    recupera más de una capacidad por invocación de tput. Las capacidades deben pasarse a tput desde el flujo de entrada estándar en lugar de desde la línea de comandos (ver sección "EJEMPLOS" abajo). Solo se permite un código-cap por línea. La opción -S cambia el significado de los estados de salida 0 y 1 (ver sección "ESTADO DE SALIDA" abajo).
    Algunas capacidades utilizan parámetros de cadena en lugar de numéricos. tput emplea una tabla interna y la presencia de parámetros en su entrada para decidir cómo interpretarlos y si usar tparm(3X).
    -T tipo
    indica el tipo de terminal. Normalmente, esta opción es innecesaria, ya que se toma un valor predeterminado de la variable de entorno TERM. Si se especifica, las variables de entorno LINES y COLUMNS también se ignoran.
    -V
    informa la versión de ncurses asociada con tput y sale con un estado exitoso.
    -x
    evita que "tput clear" intente borrar el búfer de desplazamiento hacia atrás.

    ESTADO DE SALIDA

    Normalmente, se deben interpretar los estados de salida de tput de la siguiente manera.

    Estado Significado Cuando -S No Está Especificado
    0 Capacidad booleana o de cadena presente
    1 Capacidad booleana o numérica ausente
    2 error de uso o no se especificó tipo de terminal
    3 tipo de terminal no reconocido
    4 código de capacidad no reconocido
    >4 error del sistema (4 + errno)

    Cuando se utiliza la opción -S, algunos estados cambian de significado.

    Estado Significado Cuando -S Está Especificado
    0 todos los operandos interpretados
    1 no utilizado
    4 algunos operandos no interpretados

    AMBIENTE

    tput lee una variable de entorno.

    TERM
    denota el tipo de terminal. Cada tipo de terminal es distinto, aunque muchos son similares. La opción -T anula su valor.

    ARCHIVOS

    /usr/share/tabset
    base de datos de inicialización de tabulaciones
    /usr/share/terminfo
    base de datos de descripciones de terminales compilada

    PORTABILIDAD

    Con el tiempo, el tput de ncurses ha diferido del de System V en dos aspectos importantes, uno ahora mayormente histórico.

    •
    "tput código-cap" escribe en la salida estándar, la cual no tiene por qué ser un dispositivo terminal. Sin embargo, los operandos que manipulan los modos del terminal podrían no utilizar la salida estándar.
    Los operandos init y reset del tput de System V utilizan lógica de 4.1cBSD tset, manipulando los modos del terminal. Comprueba los mismos descriptores de archivo (y /dev/tty) para su asociación con un dispositivo terminal que ncurses ahora lo hace, y si ninguno los tiene, finalmente asume una terminal de 1200 baudios. Al actualizar los modos del terminal, ignora los errores.
    Hasta ncurses 6.1 (ver sección "HISTORIA" abajo), tput no modificaba los modos del terminal. Ahora emplea un esquema similar al de System V, utilizando funciones compartidas con tset (y en última instancia basado en 4.4BSD tset). Si no puede abrir una terminal (por ejemplo, cuando es ejecutado por cron(1)), tput sale con un estado de error.
    •
    El tput de System V asume que el tipo de un operando código-cap es numérico si todos los caracteres de su valor son números decimales; si no lo son, trata código-cap como una cadena de capacidad.
    La mayoría de las implementaciones que proporcionan soporte para operandos código-cap utilizan la función tparm(3X) para expandir sus parámetros. Esa función espera una mezcla de parámetros numéricos y de cadena, lo que requiere que tput sepa qué tipo usar.
    El tput de ncurses utiliza una tabla para determinar los tipos de parámetros para los operandos código-cap estándar y una función interna para analizar operandos código-cap no estándar.
    Aunque más fiable que la utilidad de System V, este análisis introduce un problema de portabilidad. Un desarrollador de OpenBSD adaptó la función interna de la biblioteca de ncurses para portar el tput basado en termcap de NetBSD a terminfo, y lo modificó para interpretar múltiples códigos-cap (y parámetros) en la línea de comandos. Las aplicaciones portables no deben confiar en esta característica; ncurses la ofrece para dar soporte a aplicaciones escritas específicamente para OpenBSD.

    Esta implementación, a diferencia de otras, acepta códigos termcap y terminfo si el soporte para termcap está compilado. En ese caso, sin embargo, los códigos predefinidos de termcap y terminfo tienen dos ambigüedades; ncurses asume el código terminfo.

    • El código-cap dl significa delete_line para termcap pero parm_delete_line para terminfo. termcap usa el código DL para parm_delete_line. terminfo usa el código dl1 para delete_line.
    • El código-cap ed significa exit_delete_mode para termcap pero clr_eos para terminfo. termcap usa el código cd para clr_eos. terminfo usa el código rmdc para exit_delete_mode.

    El operando longname, la opción -S y las características de sustitución de parámetros utilizadas en el ejemplo cup a continuación, no eran compatibles en AT&T/USL curses antes de SVr4 (1989). Más tarde, 4.3BSD-Reno (1990) añadió soporte para longname, y en 1994, NetBSD añadió soporte para las características de sustitución de parámetros.

    IEEE Std 1003.1/The Open Group Base Specifications Issue 7 (POSIX.1-2008) documenta solo los operandos clear, init y reset. Algunas observaciones de interés surgen de esa selección.

    • ncurses soporta clear como cualquier otro código-cap estándar. Los otros (init y longname) no corresponden a capacidades de terminal.
    • El tput en sistemas basados en SVr4 como Solaris, IRIX64 y HP-UX, así como otros como AIX y Tru64, también soportan operandos código-cap estándar.
    • Algunas plataformas como FreeBSD reconocen códigos termcap en lugar de códigos de capacidad terminfo en sus respectivos comandos tput. Desde 2010, el tput de NetBSD usa códigos terminfo. Antes de eso, (al igual que FreeBSD) reconocía códigos termcap.
    A partir de 2021, FreeBSD usa el tput de ncurses, configurado tanto para terminfo (probado primero) como para termcap (como plan B).

    Debido a que (aparentemente) todos los sistemas Unix certificados soportan el conjunto completo de códigos de capacidad, la razón para documentar solo unos pocos puede no ser aparente.

    • X/Open Curses Issue 7 documenta tput de manera diferente, con código-cap y las otras características utilizadas en esta implementación.
    • Es decir, existen dos estándares para tput: POSIX (un subconjunto) y X/Open Curses (la implementación completa). POSIX documenta un subconjunto para evitar la complicación de incluir X/Open Curses y la base de datos de capacidades de terminal.
    • Si bien es ciertamente posible escribir un programa tput sin usar curses, ningún sistema con una implementación de curses proporciona una utilidad tput que no soporte también los códigos-cap estándar.

    X/Open Curses Issue 7 (2009) es la primera versión en documentar utilidades. Sin embargo, esa parte de X/Open Curses no sigue la práctica existente (es decir, el comportamiento de curses de System V).

    • Asigna el estado de salida 4 a "operando inválido", que puede tener el mismo significado que "capacidad desconocida". Por ejemplo, el código fuente de xcurses de Solaris utiliza el término "inválido" en este caso.
    • Asigna el estado de salida 255 a una variable numérica que no está especificada en la base de datos de terminfo. Probablemente sea un error de documentación, confundiendo el "-1" escrito en la salida estándar para indicar una capacidad numérica ausente o cancelada con un estado de salida (sin signo).

    Las diversas implementaciones de System V (AIX, HP-UX, Solaris) utilizan los mismos estados de salida que ncurses.

    NetBSD curses documenta estados de salida que no corresponden ni a ncurses ni a X/Open Curses.

    System V desarrolló un comando tput diferente.

    HISTORIA

    La primera versión de tput fue incluida en el paquete de inicialización de terminales para AT&T Documenter's Workbench (1978). Esta versión usaba la base de datos termcap y aceptaba operandos nombrados para las capacidades de la terminal. Al igual que tset, utilizaba tparm para resolver las capacidades parametrizadas.

    • La versión original de XENIX tput (1980) era diferente. La página de manual de XENIX tput no mencionaba el uso de tparm(3X) para las capacidades parametrizadas. En lugar de eso, usaba un método específico de XENIX para obtener el parámetro contra cada capacidad predefinida y devolver el valor correspondiente. Esta versión de tput no utilizaba tparm(3X) para las capacidades parametrizadas.
    • SVr3 (1987) reemplazó eso con un programa más extenso cuyo soporte para operandos init y reset (más de la mitad del programa) incorporaba la característica reset de BSD tset escrita por Eric Allman.
    • SVr4 (1989) añadió la inicialización del color utilizando las capacidades orig_colors (oc) y orig_pair (op) en su lógica de init.

    Keith Bostic refactorizó BSD tput para su distribución en 4.3BSD-Tahoe (1988), luego lo reemplazó al año siguiente con una nueva implementación basada en System V tput. La versión de Bostic también aceptaba algunos parámetros nombrados para capacidades (pseudo-)de terminfo: clear, init, longname y reset. Sin embargo, dado que solo tenía termcap disponible, aceptaba códigos de termcap para otras capacidades. Además, el BSD tput de Bostic no modificaba los modos de la terminal como lo había hecho el BSD tset anterior.

    Al mismo tiempo, Bostic añadió un script de shell llamado "clear" que utilizaba tput para limpiar la pantalla. Ambos aparecieron en 4.4BSD, convirtiéndose en la implementación "moderna" de BSD de tput.

    El origen de ncurses tput se encuentra fuera de System V y BSD, en el paquete mytinfo de Ross Ridge, publicado en comp.sources.unix en diciembre de 1992. El programa de Ridge hacía un uso más sofisticado de las capacidades de la terminal que el programa de BSD. Eric Raymond utilizó ese programa tput (y otras partes de mytinfo) en ncurses en junio de 1995. Incorporando las partes relacionadas con las capacidades de la terminal casi sin cambios, Raymond introdujo mejoras en la forma en que se manejaban los parámetros de la línea de comandos.

    Antes de ncurses 6.1 (2018), sus utilidades tset y tput diferían.

    • tset era más eficaz, restableciendo los modos de la terminal y los caracteres especiales.
    • Por otro lado, el repertorio de capacidades de terminal de tset para restablecer la terminal era más limitado; solo tenía equivalentes de reset_1string (rs1), reset_2string (rs2) y reset_file (rf), y no las características de actualización de tabuladores y márgenes de tput.

    El programa reset es tradicionalmente un alias de tset debido a su capacidad para restablecer los modos de la terminal y los caracteres especiales.

    A partir de ncurses 6.1, las características de "reset" de los dos programas son (en su mayoría) las mismas. Quedan dos pequeñas diferencias.

    • El programa tset espera un segundo al restablecer, en caso de que la terminal sea un dispositivo de hardware.
    • Los dos programas escriben las cadenas de inicialización de la terminal en flujos diferentes; es decir, la salida estándar de error para tset y la salida estándar para tput.

    EJEMPLOS

    tput init
    Inicializa la terminal de acuerdo con el tipo de terminal en la variable de entorno TERM. Si el sistema no inicializa la terminal de manera confiable al iniciar sesión, este comando se puede incluir en $HOME/.profile después de exportar la variable de entorno TERM.
    tput -T5620 reset
    Restablece una terminal AT&T 5620, anulando el tipo de terminal en la variable de entorno TERM.
    tput cnorm
    Establece la visibilidad normal del cursor.
    tput home
    Mueve el cursor a la fila 0, columna 0: la esquina superior izquierda de la pantalla, generalmente conocida como la posición del cursor "home".
    tput clear
    Limpia la pantalla: escribe el valor de la capacidad clear_screen en el flujo de salida estándar.
    tput cols
    Informa el número de columnas utilizadas por el tipo de terminal actual.
    tput -Tadm3a cols
    Informa el número de columnas utilizadas por una terminal ADM-3A.
    strong=`tput smso` normal=`tput rmso`
    Establece variables de shell con valores de capacidad: strong y normal, para iniciar y finalizar, respectivamente, el modo de resalte para la terminal. Uno podría usar estas para presentar un prompt.
    printf "${strong}Nombre de usuario:${normal} "
    tput hc
    Indica mediante el estado de salida si la terminal es un dispositivo de copia dura.
    tput cup 23 4
    Mueve el cursor a la fila 23, columna 4.
    tput cup
    Informa el valor de la capacidad cursor_address (cup) (utilizada para el movimiento del cursor), sin sustitución de parámetros.
    tput longname
    Informa la descripción de la base de datos terminfo del tipo de terminal especificado en la variable de entorno TERM.
    tput -S
    Procesa múltiples capacidades. La opción -S se puede usar rentablemente con un "here document" de shell.
    $ tput -S <<!
> clear
> cup 10 10
> bold
> !
    Lo anterior limpia la pantalla, mueve el cursor a la posición (10, 10) y activa el modo negrita (extra brillante).
    tput clear cup 10 10 bold
    Realiza las mismas acciones que el ejemplo anterior de "tput -S".
