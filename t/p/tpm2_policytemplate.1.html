NOMBRE

tpm2_policytemplate(1) - Vincula una política con el resumen de datos de plantilla pública de un objeto.

SINOPSIS

tpm2_policytemplate [OPCIONES]

DESCRIPCIÓN

tpm2_policytemplate(1) - Vincula una política con el resumen de datos de plantilla pública de un objeto. Esta es una aserción diferida donde el hash de los datos de plantilla públicos de un objeto se compara con el especificado en la política.

OPCIONES

•
-L, --policy=ARCHIVO:

Archivo donde guardar el resumen de política compuesto.

•
-S, --session=ARCHIVO:

Archivo de sesión de política generado a través de la opción -S de tpm2_startauthsession(1).

•
--template-hash=ARCHIVO:

Archivo que contiene el hash de la plantilla pública del objeto.

Configuración TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Utilizado al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y por lo tanto soportan no usar un TCTI. Las herramientas que no lo soportan darán error al intentar usarse sin una conexión TCTI. No soporta NINGUNA opción y DEBE presentarse como el texto exacto de “none”.

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<configuración-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <configuración-opciones-tcti> da como resultado el uso del valor predeterminado para esa parte respectivamente.

Predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado usando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO ENCONTRADO. Puede consultar qué TCTI se elegirá como predeterminado usando la opción -v para mostrar la información de versión. El par clave-valor “default-tcti” indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs Personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica puede ser cargado. Las herramientas internamente usan dlopen(3), y el valor crudo tcti-name se usa para la búsqueda. Por lo tanto, podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca como lo entiende la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres TPM para usarlo en el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares clave-valor simples separados por un carácter `,'. Cada clave y valor se separan por un carácter `='.
•
El TCTI abrmd soporta dos claves:
1.
`bus_name': El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type': El tipo de la instancia dbus (una cadena) limitada a `session' y `system'.

Especificar el nombre TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especificar el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

NAME

tpm2_policytemplate - policy command for TPM2_PolicyTemplate

SYNOPSIS

tpm2_policytemplate [OPTIONS] --template-hash HASH

tpm2_policytemplate [OPTIONS] -L POLICY_FILE --template-hash HASH

DESCRIPTION

tpm2_policytemplate command applies a policy that requires the TPM to have performed a specific template operation. This policy is typically applied when creating primary keys. The template operation is defined by a hash value that represents the template that the TPM should have used.

The tool supports two ways of specifying the template hash:

•
Directly via the --template-hash option.
•
Via a policy file using the -L option, where the file contains the template hash.

This command is intended to be used in conjunction with commands that can create primary objects, such as tpm2_createprimary.

OPTIONS

The tpm2_policytemplate command supports the following OPTIONS:

--template-hash HASH

The policy digest that will be applied. This can be a file path containing the hash, or a hex string.

-L, --policy POLICY_FILE

Path to a file that stores the policy digest.

-S, --session SESSION_CONTEXT

The session context value to load the policy for.

COMMON OPTIONS

See tpm2_options(7) for options that are common to most tpm2_tools.

TCTI Configuration

See tpm2_options(7) for common TCTI configuration.

TCTI OPTIONS

See tpm2_options(7) for common TCTI options.

EXAMPLES

The following example demonstrates how to use policy template to restrict the primary object type created under a hierarchy.

# Assume template.data contains the raw data of the template
# that is required for the primary object.
cat template.data | openssl dgst -sha256 -binary -out template.hash
tpm2_startauthsession -S session.ctx -g sha256
tpm2_policytemplate -S session.ctx -L policy.template \
--template-hash template.hash
tpm2_flushcontext session.ctx
tpm2_setprimarypolicy -C o -g sha256 -L policy.template
tpm2_startauthsession -S session.ctx -g sha256 --policy-session
tpm2_policytemplate -S session.ctx --template-hash template.hash
tpm2_createprimary -C o -c prim2.ctx -P session:session.ctx
tpm2_flushcontext session.ctx

Restrict the primary object type created under a hierarchy

This example shows how to restrict the primary object type created under the owner hierarchy (hierarchy 4) to only allow RSA keys.

  1. Generate a template hash for an RSA primary key. 
    tpm2_createpolicy -P owner -r policy.rsa.bin -u policy.rsa.obj -a policy.rsa.auth
  2. Set the primary policy for the owner hierarchy to use the generated RSA template policy. 
    tpm2_setprimarypolicy -C o -L policy.rsa.bin
  3. Now, attempt to create a primary key using the owner hierarchy. If the primary key policy is set correctly, this command will succeed. 
    tpm2_createprimary -C o -c prim.rsa.ctx -g 3FFF --policy-file policy.rsa.auth
    The --policy-file option indicates that the primary key should be created with the specified policy. The -g 3FFF option specifies the algorithm for the primary key, which is RSA in this case.
  4. If you try to create a primary key with a different algorithm, for example, ECC, it will fail. 
    tpm2_createprimary -C o -c prim.ecc.ctx -g 23

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
