tpm2_setprimarypolicy(1) Manual de Comandos Generales tpm2_setprimarypolicy(1)

NOMBRE

tpm2_setprimarypolicy(1) - Establece la política de autorización para la jerarquía de bloqueo (lockoutPolicy), la jerarquía de plataforma (platformPolicy), la jerarquía de almacenamiento (ownerPolicy) y la jerarquía de aprobación (endorsementPolicy).

SINOPSIS

tpm2_setprimarypolicy [OPCIONES]

DESCRIPCIÓN

tpm2_setprimarypolicy(1) - Establece la política de autorización para la jerarquía de bloqueo (lockoutPolicy), la jerarquía de plataforma (platformPolicy), la jerarquía de almacenamiento (ownerPolicy) y la jerarquía de aprobación (endorsementPolicy).

OPCIONES

Estas opciones controlan la creación de la sesión de autorización de política:

•
-C, --hierarchy=OBJETO:

Especifica la jerarquía cuya política de autorización se va a configurar. Se puede especificar como o|p|e|l

•
-P, --auth=AUTH:

Especifica el valor de autorización para la jerarquía.

•
-L, --policy=ARCHIVO:

La ruta del archivo de los datos de la política de autorización.

•
-g, --hash-algorithm=ALGORITMO:

El algoritmo de hash utilizado en el cálculo del digest de la política.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un manejador o un nombre de archivo, se determina de acuerdo con la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto TPM transitorio restaurado.
•
Si el argumento coincide con un *prefijo* de uno de:
•
owner: la jerarquía de propietario
•
platform: la jerarquía de plataforma
•
endorsement: la jerarquía de aprobación
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento se puede cargar como un número, se tratará como un manejador, por ejemplo, 0x81010013, y se usará directamente.*OBJETO*.

Formato de Autorización

La autorización para usar un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autorizaciones se establecen por defecto a la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación usando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña en formato de cadena, especificada por el prefijo "str:" o su ausencia (cadena sin prefijo) no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena hexadecimal

Una contraseña en formato de cadena hexadecimal, especificada por el prefijo "hex:", se convierte de un formato hexadecimal a un formato de array de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no compatibles con la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo "file:" debería ser la ruta de un archivo que contenga la contraseña que será leída por la herramienta o un "-" para usar stdin. Almacenar contraseñas en archivos evita fugas de información; las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las funciones comunes del historial del shell.

Ejemplos

# para usar stdin y que se solicite
file:-
# para usar un archivo desde una ruta
file:ruta/a/archivo/contrasena
# para enviar una contraseña a través de stdin:
echo foobar | tpm2_tool -p file:-
# para usar una cadena de aquí de bash a través de stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego, indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación para ser enviado con el manejador de sesión (p. ej., contraseña de política), agregue un + y una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones PCR

Puede satisfacer una política PCR utilizando el prefijo "pcr:" y el minilenguaje PCR. El minilenguaje PCR es el siguiente: <especificador-pcr>=<archivo-pcr-crudo>

El especificador PCR se documenta en la sección "Especificadores de banco PCR".

El archivo-pcr-crudo es un argumento *opcional* que contiene la salida del contenido crudo del PCR tal como lo devuelve tpm2_pcrread(1).

Especificadores de banco PCR

Ejemplos

Para satisfacer una política PCR de sha256 en los bancos 0, 1, 2 y 3 use un especificador de:

pcr:sha256:0,1,2,3

especificando AUTH.

Especificadores de Algoritmo

Las opciones que toman algoritmos admiten "nombres amigables".

Hay dos clases principales de cadenas de especificación de algoritmos: simples y complejas. El TPM solo aceptará ciertos algoritmos, según el uso y las condiciones.

Especificadores simples

Estas son cadenas sin datos de especificación adicionales. Al crear objetos, las porciones no especificadas de un objeto se asumen por defecto. Puede encontrar la lista de "Especificadores Simples" conocidos a continuación.

SYNOPSIS

tpm2_algcompress [-h|--help] [-v|--version] [-Q|--quiet] [-T tcti-name] [-S hexstring] [-f filename] [--hex] [-c context-file] [-C parent-context] [-G algalg,...] [-u public-file] [-r private-file]

DESCRIPTION

This tool is used to take a TPM created object (or objects) and compress the algorithms used in the objects. The TPM can be quite restrictive about the size of the public data blob that it will accept. This tool is useful for reducing the size of these blobs.

This tool is intended to be used in conjunction with the tpm2_create(8) command, or any command that creates TPM objects.

The compressed blob, can be used in place of the original blob, and will be decompressed by the tool that consumed the blob.

The -G option specifies the algorithms to use to create the TPM object, this is not the same as the algorithms that are used to create the TPM object.

Complex Specifiers

Objects, when specified for creation by the TPM, have numerous algorithms to populate in the public data. Things like type, scheme and asymmetric details, key size, etc. Below is the general format for specifying this data: <type>:<scheme>:<symmetric-details>

Type Specifiers

This portion of the complex algorithm specifier is required. The remaining scheme and symmetric details will default based on the type specified and the type of the object being created.

•
aes - Default AES: aes128
•
aes128<mode> - 128 bit AES with optional mode (ctr|ofb|cbc|cfb|ecb). If mode is not specified, defaults to null.
•
aes192<mode> - Same as aes128<mode>, except for a 192 bit key size.
•
aes256<mode> - Same as aes128<mode>, except for a 256 bit key size.
•
sm4 - Default SM4: sm4128
•
sm4128 or sm4_128 <mode> - 128 bit SM4 with optional mode (ctr|ofb|cbc|cfb|ecb). If mode is not specified, defaults to null.
•
ecc - Elliptical Curve, defaults to ecc256.
•
ecc192 or ecc_nist_p192 - 192 bit ECC NIST curve
•
ecc224 or ecc_nist_p224 - 224 bit ECC NIST curve
•
ecc256 or ecc_nist_p256 - 256 bit ECC NIST curve
•
ecc384 or ecc_nist_p384 - 384 bit ECC NIST curve
•
ecc521 or ecc_nist_p521 - 521 bit ECC NIST curve
•
ecc_sm2 or ecc_sm2_p256 - 256 bit SM2 curve
•
rsa - Default RSA: rsa2048
•
rsa1024 - RSA with 1024 bit keysize.
•
rsa2048 - RSA with 2048 bit keysize.
•
rsa3072 - RSA with 3072 bit keysize.
•
rsa4096 - RSA with 4096 bit keysize.

Scheme Specifiers

Next, is an optional field, it can be skipped.

Schemes are usually Signing Schemes or Asymmetric Encryption Schemes. Most signing schemes take a hash algorithm directly following the signing scheme. If the hash algorithm is missing, it defaults to sha256. Some take no arguments, and some take multiple arguments.

Hash Optional Scheme Specifiers

These scheme specifiers are followed by a dash and a valid hash algorithm, For example: oaep-sha256.

Multiple Option Scheme Specifiers

This scheme specifier is followed by a count (max size UINT16) then followed by a dash(-) and a valid hash algorithm. * ecdaa For example, ecdaa4-sha256. If no count is specified, it defaults to 4.

No Option Scheme Specifiers

This scheme specifier takes NO arguments. * rsaes

Symmetric Details Specifiers

This field is optional, and defaults based on the type of object being created and it’s attributes. Generally, any valid Symmetric specifier from the Type Specifiers list should work. If not specified, an asymmetric objects symmetric details defaults to aes128cfb.

Examples

Create an rsa2048 key with an rsaes asymmetric encryption scheme

tpm2_create -C parent.ctx -G rsa2048:rsaes -u key.pub -r key.priv

Create an ecc256 key with an ecdaa signing scheme with a count of 4 and sha384 hash

tpm2_create -C parent.ctx -G ecc256:ecdaa4-sha384 -u key.pub -r key.priv

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>[:<tcti-arg>]

Example:

tpm2_algcompress -T device:drv=/dev/tpm0

The following section details how to configure the different TCTIs.

-name>:<tcti-option-config>

Especificar una cadena vacía para el <tcti-name> o <tcti-option-config> resulta en el uso del valor predeterminado para esa parte, respectivamente.

Valores Predeterminados de TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTIs tabrmd, device y mssim **EN ESE ORDEN** y **USARÁN EL PRIMERO** **ENCONTRADO**. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para imprimir la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTIs mencionados anteriormente es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor bruto de tcti-name se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entiendan las semánticas de dlopen(3).

OPCIONES DE TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo de dispositivo de caracteres TPM que utilizará el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares clave-valor simples separados por un carácter ','. Cada clave y valor de cadena están separados por un carácter '='.
•
El TCTI abrmd admite dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia dbus (una cadena) limitado a `session' y `system'.

Especifique el nombre tcti de tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifique el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.
