tpm2_geteccparameters(1)

tpm2_geteccparameters(1) Manual de comandos generales tpm2_geteccparameters(1)

NOMBRE

tpm2_geteccparameters(1) - Recupera los parámetros de una curva ECC identificada por su curveID asignada por TCG.

SINOPSIS

tpm2_geteccparameters [OPCIONES]

DESCRIPCIÓN

tpm2_geteccparameters(1) - Recupera los parámetros de una curva ECC identificada por su curveID asignada por TCG.

OPCIONES

•
ARGUMENTO=ALGORITMO:

Especifica la curva ECC. Ejemplo: ecc521.

•
-o, --output=ARCHIVO

Especifica la ruta del archivo para guardar los parámetros ECC.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se conoce comúnmente como cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará el comando, simplemente devolverá un cpHash.

Especificadores complejos

Los objetos, cuando se especifican para su creación por el TPM, tienen numerosos algoritmos que se poblarán en los datos públicos. Cosas como el tipo, el esquema y los detalles asimétricos, el tamaño de la clave, etc. A continuación, se muestra el formato general para especificar estos datos: <tipo>:<esquema>:<detalles-simétricos>

Especificadores de tipo

Esta parte del especificador de algoritmo complejo es obligatoria. El esquema restante y los detalles simétricos se establecerán de forma predeterminada según el tipo especificado y el tipo del objeto que se está creando.

•
aes - AES predeterminado: aes128
•
aes128<modo> - AES de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, el valor predeterminado es null.
•
aes192<modo> - Igual que aes128<modo>, excepto por un tamaño de clave de 192 bits.
•
aes256<modo> - Igual que aes128<modo>, excepto por un tamaño de clave de 256 bits.
•
sm4 - SM4 predeterminado: sm4128
•
sm4128 o sm4_128 <modo> - SM4 de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, el valor predeterminado es null.
•
ecc - Curva Elíptica, el valor predeterminado es ecc256.
•
ecc192 o ecc_nist_p192 - Curva NIST ECC de 192 bits
•
ecc224 o ecc_nist_p224 - Curva NIST ECC de 224 bits
•
ecc256 o ecc_nist_p256 - Curva NIST ECC de 256 bits
•
ecc384 o ecc_nist_p384 - Curva NIST ECC de 384 bits
•
ecc521 o ecc_nist_p521 - Curva NIST ECC de 521 bits
•
ecc_sm2 o ecc_sm2_p256 - Curva SM2 de 256 bits
•
rsa - RSA predeterminado: rsa2048
•
rsa1024 - RSA con tamaño de clave de 1024 bits.
•
rsa2048 - RSA con tamaño de clave de 2048 bits.
•
rsa3072 - RSA con tamaño de clave de 3072 bits.
•
rsa4096 - RSA con tamaño de clave de 4096 bits.

Especificadores de esquema

A continuación, hay un campo opcional, se puede omitir.

Los esquemas suelen ser Esquemas de Firma o Esquemas de Cifrado Asimétrico. La mayoría de los esquemas de firma toman un algoritmo hash directamente después del esquema de firma. Si falta el algoritmo hash, el valor predeterminado es sha256. Algunos no toman argumentos y otros toman varios argumentos.

NAME

tpm2_create - create a primary or object key

SYNOPSIS

tpm2_create [-h|--help=[man|no-man]] [-v|--version] [-V|--verbose] [-Q|--quiet] [-Z|--enable-errata] [-R|--autoflush] [-T|--tcti=tcti-name:tcti-options] [-c context] [-C parent-context] [-p parent-password] [-g digest-algorithm] [-f policy-file] [-i input-file] [-I input-file-xor-key] [-P primary-password] [-r private-blob] [-u public-blob] [-U attestation-blob] [-y attestation-key-password] [-Y attestation-key-password-hex] [-a object-attributes] [-E sensitive-data] [-f policy-file] [-L policy-digest-file] [-r private-blob] [-u public-blob] [-U attestation-blob] [-y attestation-key-password] [-Y attestation-key-password-hex] [-a object-attributes] [-E sensitive-data] [-p password] [-X external-auth-file] [-d creation-data-file] [-k creation-key-file] [-S creation-hash-alg] [-H creation-hash-file] [-K creation-policy-file] [-l ticket-file] [-r private-blob] [-u public-blob] [-U attestation-blob] [-y attestation-key-password] [-Y attestation-key-password-hex] [-a object-attributes] [-E sensitive-data] [-p password] [-X external-auth-file] [-d creation-data-file] [-k creation-key-file] [-S creation-hash-alg] [-H creation-hash-file] [-K creation-policy-file] [-l ticket-file] [-P password] [-i input-file] [-I input-file-xor-key] [-g digest-algorithm] [-f policy-file] [-L policy-digest-file] [-G key-type]

DESCRIPTION

The tpm2_create command is used to create primary keys or object keys. Primary keys are created under the Platform Hierarchy (PH), Storage Hierarchy (SH), or Endorsement Hierarchy (EH). Object keys are created under a specified parent key.

The object attributes -a flag determine the capabilities of the created object. The default attributes are 0x00000000. The attributes are:

fixedTPM: (0x00000001) The object is a fixed TPM.
stClear: (0x00000002) The object is cleared on an STClear command.
sensitiveDataOrigin: (0x00000004) The sensitive data is generated by the TPM.
userWithAuth: (0x00000008) The object is keyed by the user password.
userOrSoTpmOn: (0x00000010) The object is keyed by the user password OR the owner password.
authByParent: (0x00000020) The object is keyed by the parent password.
noDA: (0x00000040) The object is not a durable authorization object.
restricted: (0x00000100) The object is restricted. This means that the object can only be used to load keys that have the same cryptographic algorithm.
decrypt: (0x00000200) The object can be used for decryption.
sign: (0x00000400) The object can be used for signing.
adminWithPolicy: (0x00000800) The object is keyed by a policy.
n S P K: (0x00001000) The object can be used for disk encryption.
reserved1: (0x00002000)
reserved2: (0x00004000)
reserved3: (0x00008000)
resetAuth: (0x00010000) The object password can be reset by the owner.
phEnable: (0x00040000) Enable Platform Hierarchy.
shEnable: (0x00080000) Enable Storage Hierarchy.
ehEnable: (0x00100000) Enable Endorsement Hierarchy.
tpm EK: (0x00200000) The object is a TPM EK.
maxNSPK: (0x00400000) The object is a max NSPK.
noMigration: (0x00800000) The object is not allowed to migrate.
readPubek: (0x01000000) The object can read the public EK.

The tpm2_create command can generate the following types of keys:

rsa: RSA key.
ecc: ECC key.
hmac: HMAC key.
null: No key is generated.

The key type specifiers are generally of the form KEY-TYPE:KEY-BITS:SCHEME. For example:

rsa2048:rsaes
Create a 2048 bit RSA key with the RSAES encryption scheme.
ecc256:ecdsa
Create a 256 bit ECC key with the ECDSA signature scheme.

The schemes are:

rsaes: RSA Encryption Scheme.
rsassa: RSA Signature Scheme.
hmac: HMAC.
null: No scheme.
ecdsa: ECDSA signature scheme.
ecdh: ECDH key agreement scheme.
e c d a a: ECDAA signature scheme.

Keys are identified by a cryptographic digest. By default, the digest is calculated using SHA-1. The -g flag can be used to specify the digest algorithm.

The available digest algorithms are:

sha1
sha256
sha384
sha512

The -u flag specifies the path to a file that will contain the public key. The -r flag specifies the path to a file that will contain the private key. The -U flag specifies the path to a file that will contain the attestation public key.

The -c flag specifies the context file which contains the handle for the parent object. The -p flag specifies the password for the parent object.

The -P flag specifies the password for the primary object. The -i flag specifies the path to a file containing the sensitive data to be loaded into the object. If the data is XORed, the key is specified using the -I flag.

The -E flag specifies the path to a file containing the sensitive data to be loaded into the object. This sensitive data is then encrypted using the parent object's password.

The -d flag specifies the path to a file that will contain the creation data. The -k flag specifies the path to a file that will contain the creation key. The -H flag specifies the path to a file that will contain the creation hash. The -K flag specifies the path to a file that will contain the creation policy.

The -l flag specifies the path to a file that will contain the ticket.

Algorithm Specifiers

The -G flag allows you to specify the algorithm type and parameters. The format is:

<KEY-TYPE>[:<BITS>[:<SCHEME>[:<DIGEST>]]]

Where:

KEY-TYPE
Can be one of: rsa, ecc, hmac, or null.
BITS
For rsa and ecc keys, this specifies the bit size. Common values are 1024, 2048, 3072, 4096 for RSA, and 256, 384, 521 for ECC.
SCHEME
Specifies the cryptographic scheme to use with the key. The default scheme depends on the key type.
  • For RSA, the default is rsaes (encryption). Other options include rsassa (signing).
  • For ECC, the default is ecdsa (signing). Other options include ecdh (key agreement) and ecdaa (ECDAA signing).
  • For HMAC, the scheme is always hmac.
  • For null key type, no scheme is applicable.
DIGEST
For signing schemes (rsassa, ecdsa, ecdaa), this specifies the digest algorithm to be used. The default depends on the key size and scheme. For example, sha256, sha384, sha512. If not specified, an asymmetric objects symmetric details defaults to aes128cfb.

Examples

Create an rsa2048 key with an rsaes asymmetric encryption scheme

tpm2_create -C parent.ctx -G rsa2048:rsaes -u key.pub -r key.priv

Create an ecc256 key with an ecdaa signing scheme with a count of 4 and sha384 hash

/tpm2_create -C parent.ctx -G ecc256:ecdaa4-sha384 -u key.pub -r key.priv cryptographic algorithms ALGORITHM.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.
