tpm2_create(1) Manual de Comandos Generales tpm2_create(1)

NOMBRE

tpm2_create(1) - Crear un objeto hijo.

SINOPSIS

tpm2_create [OPCIONES]

DESCRIPCIÓN

tpm2_create(1) - Crear un objeto hijo. El objeto puede ser una clave o un objeto de sellado. Un objeto de sellado permite sellar datos del usuario al TPM, con un tamaño máximo de 128 bytes. Adicionalmente, cargará el objeto creado si se especifica la opción -c.

OPCIONES

Estas opciones para crear la entidad del TPM:

•
-C, --parent-context=OBJETO:

El padre del objeto a crear.

•
-P, --parent-auth=AUTH:

El valor de autorización del objeto padre especificado con -C.

•
-p, --key-auth=AUTH:

El valor de autorización para el objeto creado.

•
-g, --hash-algorithm=ALGORITMO:

El algoritmo de hash para generar el nombre del objeto. Es opcional y por defecto es sha256 cuando no se especifica.

•
-G, --key-algorithm=ALGORITMO:

El algoritmo de clave asociado a este objeto. Por defecto es "rsa" si no se especifica.

•
-a, --attributes=ATTRIBUTES:

Los atributos del objeto, opcional. El valor por defecto para los objetos creados es:

TPMA_OBJECT_SIGN_ENCRYPT|TPMA_OBJECT_DECRYPT|TPMA_OBJECT_FIXEDTPM| TPMA_OBJECT_FIXEDPARENT|TPMA_OBJECT_SENSITIVEDATAORIGIN| TPMA_OBJECT_USERWITHAUTH

Cuando se especifica -i para sellado, se eliminan TPMA_OBJECT_SIGN_ENCRYPT y TPMA_OBJECT_DECRYPT del conjunto de atributos por defecto. El algoritmo se configura de tal manera que el objeto solo sea útil para sellado y desellado. Es decir, no se puede usar un objeto para sellado y operaciones criptográficas.

Cuando se especifica -L para añadir información de autorización basada en políticas Y no se especifica una contraseña de cadena, el atributo TPMA_OBJECT_USERWITHAUTH se borra a menos que se haga una elección explícita estableciendo el atributo con la opción -a. Esto evita la creación de objetos con un modelo de autorización inadvertido donde el usuario pretendía imponer una política pero inadvertidamente creó un objeto con autorización vacía que puede ser utilizado en lugar de la autorización de política.

•
-i, --sealing-input=ARCHIVO o STDIN:

El archivo de datos a sellar, opcional. Si el archivo es -, leer desde stdin. Al sellar datos, solo se permite el algoritmo TPM_ALG_KEYEDHASH con un esquema NULL. Por lo tanto, no se puede especificar -G.

•
-L, --policy=ARCHIVO o CADENA_HEX:

El archivo de política de entrada o una cadena hexadecimal, opcional.

•
-u, --public=ARCHIVO:

El archivo de salida que contiene la parte pública del objeto creado, opcional.

•
-r, --private=ARCHIVO:

El archivo de salida que contiene la porción sensible del objeto, opcional. # Detalles de Protección

Los objetos que pueden salir del TPM deben ser protegidos (confidencialidad e integridad). Por ejemplo, los objetos transitorios requieren que los datos protegidos por el TPM (clave o material de sellado) se almacenen fuera del TPM. Esto se observa en herramientas como tpm2_create(1), donde la opción -r produce estos datos protegidos. Este blob contiene las porciones sensibles del objeto. Las porciones sensibles del objeto están protegidas por el objeto padre, utilizando los detalles de cifrado simétrico del padre para cifrar los datos sensibles y generar un HMAC de ellos.

Los detalles completos se pueden encontrar en la sección 23 de:

•
https://trustedcomputinggroup.org/wp-content/uploads/TPM-Rev-2.0-Part-1-Architecture-01.38.pdf

En particular, la Figura 20 es relevante, aunque se refiere específicamente a blobs de duplicación, el proceso es idéntico.

Si la salida proviene de tpm2_duplicate(1), la salida será ligeramente diferente, como se describe completamente en la sección 23.

•
-c, --key-context=ARCHIVO:

El archivo de salida que contiene el contexto de la clave, opcional. El contexto de la clave es análogo al archivo de contexto producido por tpm2_load(1), sin embargo, se genera a través de un comando tpm2_createloaded(1). Esta opción se puede usar para evitar las secuencias de comandos normales de tpm2_create(1) y tpm2_load(1) y hacerlo todo en un solo comando, atómicamente.

•
--creation-data=ARCHIVO:

Una salida de archivo opcional que guarda los datos de creación para certificación.

•
--template-data=ARCHIVO:

Una salida de archivo opcional que guarda los datos de la plantilla de clave (TPM2B_PUBLIC) para ser utilizada en tpm2_policytemplate.

•
-t, --creation-ticket=ARCHIVO:

Una salida de archivo opcional que guarda el ticket de creación para certificación.

•
-d, --creation-hash=ARCHIVO:

Una salida de archivo opcional que guarda el hash de creación para certificación.

•
-q, --outside-info=CADENA_HEX_O_ARCHIVO:

Una cadena hexadecimal opcional o una ruta para añadir datos únicos a los datos de creación. Tenga en cuenta que no contribuye a la creación de objetos estadísticamente únicos.

•
-l, --pcr-list=PCR:

La lista de bancos PCR y los IDs de PCR seleccionados para cada banco que se incluirán en los datos de creación para certificación.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash.

•
--rphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros de respuesta. Esto se denomina comúnmente rpHash.

•
-S, --session=ARCHIVO:

La sesión creada usando tpm2_startauthsession. Se pueden especificar múltiples de estas. Por ejemplo, puede tener una sesión para auditoría y otra para cifrado/descifrado de parámetros.

•
-f, --format:

Selección de formato para el archivo de salida de la clave pública. `tss` (por defecto) generará un blob binario según la Especificación TPM 2.0. `pem` generará una clave pública codificada en PEM compatible con OpenSSL. `der` generará una clave pública codificada en DER compatible con OpenSSL. `tpmt` generará un blob binario de la estructura TPMT_PUBLIC a la que se hace referencia en las especificaciones de TPM 2.0.

Formato de la clave pública.

•
-o, --output=ARCHIVO:

La ruta del archivo de salida, que registra la porción pública del objeto.

Referencias

Formato del Objeto de Contexto

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

Formato de Objeto

El tipo de un objeto de contexto, ya sea un manejador o un nombre de archivo, se determina según la siguiente lógica, **en orden**:

•
Si el argumento es una ruta de archivo, el archivo se carga como un objeto transitorio de TPM restaurado.
•
Si el argumento es una coincidencia de *prefijo* en uno de:
•
propietario: la jerarquía del propietario
•
plataforma: la jerarquía de la plataforma
•
respaldo: la jerarquía de respaldo
•
bloqueo: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un manejador, por ejemplo, 0x81010013, y se usará directamente._OBJECT_.

Formato de Autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones.

NOTA: Las autorizaciones se establecen por defecto en la CONTRASEÑA VACÍA cuando no se especifican.

Contraseñas

Las contraseñas se interpretan en las siguientes formas utilizando identificadores de prefijo.

Nota: Por defecto, se asume que las contraseñas están en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña en formato de cadena, especificada por el prefijo "str:" o su ausencia (cadena sin prefijo), no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña en formato de cadena hexadecimal, especificada por el prefijo "hex:", se convierte de una forma hexadecimal a una forma de matriz de bytes, lo que permite contraseñas con caracteres no imprimibles y/o no amigables para la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo "file:", debe ser la ruta de un archivo que contenga la contraseña a leer por la herramienta o un "-" para usar la entrada estándar. Almacenar contraseñas en archivos evita la fuga de información; las contraseñas pasadas como opciones pueden ser leídas desde la lista de procesos o características comunes de historial de shell.

Ejemplos

# para usar stdin y que se solicite
file:-
# para usar un archivo desde una ruta
file:ruta/a/archivo/contraseña
# para enviar una contraseña vía stdin:
echo foobar | tpm2_tool -p file:-
# para usar una cadena bash (here-string) vía stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al utilizar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego, indique la ruta a un archivo de sesión que fue creado con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación que se envíe con el manejador de la sesión (por ejemplo, contraseña de política), agregue un "+" y una cadena como se describe en la sección de Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones de PCR

Puede satisfacer una política de PCR utilizando el prefijo "pcr:" y el minilenguaje de PCR. El minilenguaje de PCR es el siguiente: <especificador-pcr>=<archivo-pcr-crudo>

El especificador de PCR está documentado en la sección "Especificadores de banco de PCR".

El archivo-pcr-crudo es un argumento opcional que contiene la salida de los contenidos crudos de PCR tal como los devuelve tpm2_pcrread(1).

Especificadores de banco de PCR

Ejemplos

Para satisfacer una política de PCR de sha256 en los bancos 0, 1, 2 y 3, use un especificador de:

pcr:sha256:0,1,2,3

especificando AUTH.

Especificadores Complejos

Los objetos, cuando se especifican para la creación por la TPM, tienen numerosos algoritmos que deben ser poblados en los datos públicos. Cosas como el tipo, esquema y detalles asimétricos, tamaño de clave, etc. A continuación se muestra el formato general para especificar estos datos: <tipo>:<esquema>:<detalles-simétricos>

Especificadores de Tipo

Esta porción del especificador de algoritmo complejo es obligatoria. El esquema restante y los detalles simétricos se establecerán por defecto según el tipo especificado y el tipo del objeto que se está creando.

•
aes - AES por defecto: aes128
•
aes128<modo> - AES de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, se establecerá por defecto a null.
•
aes192<modo> - Igual que aes128<modo>, excepto para un tamaño de clave de 192 bits.
•
aes256<modo> - Igual que aes128<modo>, excepto para un tamaño de clave de 256 bits.
•
sm4 - SM4 por defecto: sm4128
•
sm4128 o sm4_128 <modo> - SM4 de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, se establecerá por defecto a null.
•
ecc - Curva Elíptica, por defecto es ecc256.
•
ecc192 o ecc_nist_p192 - Curva NIST ECC de 192 bits
•
ecc224 o ecc_nist_p224 - Curva NIST ECC de 224 bits
•
ecc256 o ecc_nist_p256 - Curva NIST ECC de 256 bits
•
ecc384 o ecc_nist_p384 - Curva NIST ECC de 384 bits
•
ecc521 o ecc_nist_p521 - Curva NIST ECC de 521 bits
•
ecc_sm2 o ecc_sm2_p256 - Curva SM2 de 256 bits
•
rsa - RSA por defecto: rsa2048
•
rsa1024 - RSA con tamaño de clave de 1024 bits.
•
rsa2048 - RSA con tamaño de clave de 2048 bits.
•
rsa3072 - RSA con tamaño de clave de 3072 bits.
•
rsa4096 - RSA con tamaño de clave de 4096 bits.

Ejemplos

Atributos del Objeto

Los atributos del objeto se utilizan para controlar varias propiedades de los objetos creados. Cuando se especifican como una opción, se puede utilizar la máscara de bits sin procesar o "nombres amigables". Los valores se pueden encontrar en la Tabla 31 Parte 2 de la especificación TPM2.0, que se puede encontrar aquí:

https://trustedcomputinggroup.org/wp-content/uploads/TPM-Rev-2.0-Part-2-Structures-01.38.pdf

Los nombres amigables se calculan tomando el campo de nombre de la tabla 31 y eliminando el prefijo TPMA_OBJECT_ y convirtiendo el resultado a minúsculas. Por lo tanto, TPMA_OBJECT_FIXEDTPM se convierte en *fixedtpm*. Los nombres amigables se pueden unir usando el operador OR bit a bit *"|""*.

Por ejemplo, para establecer los campos TPMA_OBJECT_FIXEDTPM, TPMA_OBJECT_NODA y TPMA_OBJECT_SIGN_ENCRYPT, el argumento sería:

fixedtpm|noda|sign especificando los atributos del objeto *ATTRIBUTES*.

Configuración del TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para comunicarse con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre tiene prioridad sobre la variable de entorno.

Los TCTI actualmente conocidos son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Utilizado al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo admiten generarán un error cuando se intenten usar sin una conexión TCTI. No admite *NINGUNA* opción y *DEBE* presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o <config-opciones-tcti> resulta en que se utilice el valor por defecto para esa porción respectivamente.

Valores Predeterminados del TCTI

Cuando no se especifica un TCTI, se busca el TCTI por defecto utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTIs *tabrmd*, *device* y *mssim* EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá por defecto utilizando la opción -v para mostrar la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor *tcti-name* sin procesar se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entiendan las semánticas de dlopen(3).

OPCIONES DEL TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo de dispositivo de caracteres del TPM para uso del TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares clave-valor simples separados por un carácter ','. Cada cadena de clave y valor están separadas por un carácter '='.
•
El TCTI abrmd admite dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia de dbus (una cadena) limitada a `session' y `system'.

Especifique el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifique el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmdson sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

Configuración

Para crear un objeto, primero debemos crear una clave primaria como su padre.

tpm2_createprimary -c primary.ctx

Crear un Objeto

Esto creará un objeto utilizando todos los valores predeterminados y almacenará las partes privadas y públicas selladas del TPM en las rutas especificadas a través de -u y -r respectivamente. La herramienta utiliza una clave RSA por defecto.

tpm2_create -C primary.ctx -u obj.pub -r obj.priv

Sellar Datos al TPM

Además de los objetos de clave, el TPM permite sellar pequeñas cantidades de datos especificados por el usuario al TPM.

echo "mis datos sellados" > seal.dat
tpm2_create -C primary.ctx -i seal.dat -u obj.pub -r obj.priv

Crear un Objeto de Clave EC y cargarlo al TPM

Normalmente, al crear un objeto, solo se devuelven las partes pública y privada del objeto, y el llamador necesita usar tpm2_load(1) para cargar esas partes pública y privada al TPM antes de poder utilizar el objeto. Sin embargo, esto también se puede lograr dentro de este comando, cuando es compatible con el TPM. Puede verificar que su TPM soporta esta característica comprobando que los comandos tpm2_getcap(1) devuelven TPM2_CC_CreateLoaded en el conjunto de comandos. Si su TPM no soporta TPM2_CC_CreateLoaded, se devolverá un error de código de comando no soportado. Si no es compatible, uno debe usar tpm2_load(1). Consulte esa página man para obtener detalles sobre su uso.

tpm2_create -C primary.ctx -G ecc -u obj.pub -r obj.priv -c ecc.ctx

Crear un Objeto y obtener la clave pública como archivo PEM

Esto creará un objeto utilizando todos los valores predeterminados, pero también generará la clave pública como un archivo PEM compatible con herramientas como OpenSSL y cualquier otra que soporte archivos PEM.

tpm2_create -C primary.ctx -u obj.pub -r obj.priv -f pem -o obj.pem

Crear una clave de firma RSA restringida

Para una clave de firma restringida, se debe especificar el esquema y null para el algoritmo simétrico.

tpm2_create -C primary.ctx -Grsa2048:rsapss:null  \
    -a "fixedtpm|fixedparen|sensitivedataorigin|userwithauth|restricted|sign" \
    -r obj.priv -u obj.pub

Devoluciones

Las herramientas pueden devolver cualquiera de los siguientes códigos:

•
0 - Éxito.
•
1 - Error general no específico.
•
2 - Error en el manejo de opciones.
•
3 - Error de autenticación.
•
4 - Error relacionado con TCTI.
•
5 - Esquema no soportado. Aplicable a tpm2_testparams.
