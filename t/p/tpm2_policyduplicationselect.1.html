NOMBRE

tpm2_policyduplicationselect(1) - Restringe la duplicación a un padre nuevo específico.

SINOPSIS

tpm2_policyduplicationselect [OPCIONES]

DESCRIPCIÓN

tpm2_policyduplicationselect(1) - Restringe la duplicación a un padre nuevo específico.

OPCIONES

•
-S, --session=ARCHIVO:

El archivo de sesión de política generado a través de la opción -S de tpm2_startauthsession(1).

•
-n, --object-name=ARCHIVO:

Archivo de nombre de entrada del objeto a duplicar.

•
-N, --parent-name=ARCHIVO:

Archivo de nombre de entrada del nuevo padre.

•
-L, --policy=ARCHIVO:

Archivo para guardar el digest de la política.

•
--include-object:

Si existe, el nombre del objeto se incluirá en el valor del digest de la política.

Configuración TCTI

El TCTI o “Interfaz de Transmisión” es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente usado para comunicarse con el simulador de software del TPM.
•
device - Usado cuando se habla directamente con el archivo de dispositivo del TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo admiten generarán un error cuando se intenten usar sin una conexión TCTI. No admite *NINGUNA* opción y *DEBE* presentarse como el texto exacto de “none”.

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<configuración-opción-tcti>

Especificar una cadena vacía para <nombre-tcti> o <configuración-opción-tcti> resulta en que se utilice el valor predeterminado para esa porción respectivamente.

Valores predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado usando la opción -v para mostrar la información de versión. El par clave-valor “default-tcti” indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica puede ser cargado. Las herramientas utilizan internamente dlopen(3), y el valor crudo tcti-name se usa para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca tal como lo entiende la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utilizan para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres del TPM para su uso por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares clave-valor simples separados por un carácter `,`. Cada clave y cadena de valor están separadas por un carácter `=`.
•
El TCTI abrmd admite dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia de dbus (una cadena) limitada a `session' y `system'.

Especificar el nombre TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especificar el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

NAME

tpm2_policyduplicationselect — select policy for duplication

SYNOPSIS

tpm2_policyduplicationselect [OPTIONS] [ARGUMENT]...

DESCRIPTION

The tpm2_policyduplicationselect command is used to set up a policy session that selects the duplication role for a policy. This is typically used in conjunction with the tpm2_duplicate command to ensure that an object can be duplicated to a specific parent.

OPTIONS

-S, --session=SESSION
Policy session file descriptor. This session will be used to store the policyduplicationselect commands.
-N, --parent-name=NAME
The name of the parent of the policy. This is typically the name of the key used to create the object that needs to be duplicated.
-n, --object-name=NAME
The name of the object to be duplicated. This is the object that will be duplicated to the new parent.
-L, --policy=FILE
The file to write the policy digest to. This file will be used by the tool that requires the policy.
-Q, --quiet
Suppress printing policy digest and just output the policy digest.
--cphash=FILE
Compute and output a CP hash of the command to FILE. The CP hash is a hash of the command parameters and the TPM’s state.

COMMON OPTIONS

See tpm2_options(1) for common options that can be used with this command.

TCTI Configuration

See tpm2_tcti(7) for common TCTI configurations.

TCTI OPTIONS

-z, --tcti=name:device
Specify the TCTI device to use. This option is usually set via environment variables.

EXAMPLES

The following example demonstrates how to set up a policy session for duplicating an object to a new restricted parent.

Setup a duplication role policy to restricted new parent

Create source parent and destination(or new) parent

tpm2_createprimary -C n -g sha256 -G rsa -c dst_n.ctx -Q
tpm2_createprimary -C o -g sha256 -G rsa -c src_o.ctx -Q

Create the restricted parent policy

tpm2_readpublic -c dst_n.ctx -n dst_n.name -Q
tpm2_startauthsession -S session.ctx
tpm2_policyduplicationselect -S session.ctx  -N dst_n.name \
-L policydupselect.dat -Q
tpm2_flushcontext session.ctx
rm session.ctx

Create the object to be duplicated using the policy

tpm2_create -C src_o.ctx -g sha256 -G rsa -r dupkey.priv -u dupkey.pub \
-L policydupselect.dat  -a "sensitivedataorigin|sign|decrypt" -c dupkey.ctx -Q
tpm2_readpublic -c dupkey.ctx -n dupkey.name -Q

Satisfy the policy and duplicate the object

tpm2_startauthsession -S session.ctx --policy-session
tpm2_policyduplicationselect -S session.ctx  -N dst_n.name -n dupkey.name -Q
tpm2_duplicate -C dst_n.ctx -c dupkey.ctx -G null -p session:session.ctx \
-r new_dupkey.priv -s dupseed.dat
tpm2_flushcontext  session.ctx
rm session.ctx

NOTES

•
This command usually cooperates with tpm2_duplicate(1), so referring to the man page of tpm2_duplicate(1) is recommended.
•
This command will set the policy session’s command code to TPM_CC_Duplicate which enables duplication role of the policy.

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
