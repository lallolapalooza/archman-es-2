tpm2_createpolicy(1) Manual de Comandos Generales tpm2_createpolicy(1)

NOMBRE

tpm2_createpolicy(1) - Crea políticas de autorización de aserción simples basadas en valores de múltiples índices de PCR en múltiples bancos habilitados.

SINOPSIS

tpm2_createpolicy [OPCIONES]

DESCRIPCIÓN

tpm2_createpolicy(1) - Crea políticas de autorización de aserción simples basadas en valores de múltiples índices de PCR en múltiples bancos habilitados. Luego se puede usar con la creación de objetos y/o herramientas que utilicen el objeto.

OPCIONES

Estas opciones controlan la creación de la sesión de autorización de políticas:

•
-L, --policy=ARCHIVO:

El archivo donde guardar el resumen de la política.

•
--policy-pcr:

Identifica el tipo de política PCR para la creación de políticas.

•
-g, --policy-algorithm=ALGORITMO:

El algoritmo de hash utilizado en el cálculo del resumen de la política.

•
-l, --pcr-list=PCR:

La lista de bancos PCR y los IDs de los PCR seleccionados para cada banco.

•
-f, --pcr=ARCHIVO:

Ruta o nombre opcional del archivo que contiene los valores esperados de PCR para el índice especificado. Por defecto, se leen los PCR actuales según la lista establecida.

•
--policy-session:

Inicia una sesión de política de tipo TPM_SE_POLICY. Por defecto es TPM_SE_TRIAL si esta opción no se especifica.

Especificadores Complejos

Los objetos, cuando se especifican para la creación por el TPM, tienen numerosos algoritmos para poblar en los datos públicos. Cosas como el tipo, el esquema y los detalles asimétricos, el tamaño de la clave, etc. A continuación se presenta el formato general para especificar estos datos: <tipo>:<esquema>:<detalles-simétricos>

Especificadores de Tipo

Esta parte del especificador de algoritmo complejo es obligatoria. El esquema y los detalles simétricos restantes se establecerán por defecto según el tipo especificado y el tipo del objeto que se está creando.

•
aes - AES predeterminada: aes128
•
aes128<modo> - AES de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, se usa el valor predeterminado null.
•
aes192<modo> - Igual que aes128<modo>, excepto por un tamaño de clave de 192 bits.
•
aes256<modo> - Igual que aes128<modo>, excepto por un tamaño de clave de 256 bits.
•
sm4 - SM4 predeterminado: sm4128
•
sm4128 o sm4_128 <modo> - SM4 de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, se usa el valor predeterminado null.
•
ecc - Curva elíptica, por defecto es ecc256.
•
ecc192 o ecc_nist_p192 - Curva NIST ECC de 192 bits
•
ecc224 o ecc_nist_p224 - Curva NIST ECC de 224 bits
•
ecc256 o ecc_nist_p256 - Curva NIST ECC de 256 bits
•
ecc384 o ecc_nist_p384 - Curva NIST ECC de 384 bits
•
ecc521 o ecc_nist_p521 - Curva NIST ECC de 521 bits
•
ecc_sm2 o ecc_sm2_p256 - Curva SM2 de 256 bits
•
rsa - RSA predeterminado: rsa2048
•
rsa1024 - RSA con tamaño de clave de 1024 bits.
•
rsa2048 - RSA con tamaño de clave de 2048 bits.
•
rsa3072 - RSA con tamaño de clave de 3072 bits.
•
rsa4096 - RSA con tamaño de clave de 4096 bits.

Especificadores de Esquema

A continuación, hay un campo opcional, se puede omitir.

Los esquemas suelen ser Esquemas de Firma o Esquemas de Cifrado Asimétrico. La mayoría de los esquemas de firma toman un algoritmo de hash directamente después del esquema de firma. Si falta el algoritmo de hash, se utiliza sha256 por defecto. Algunos no toman argumentos y otros toman varios argumentos.

DESCRIPTION

The tpm2_create command is used to create a primary key or an object key. The primary key is used to create other keys and objects. The object key is used to seal/unseal data and sign data.

The primary key is created using the TPM2_CreatePrimary command. The object key is created using the TPM2_Create command. Primary keys are created with a set of attributes that define the key type, and the object key is created with a set of attributes that define the key type, and the parent key used to create the object key.

OPTIONS

These options control the type of key to be created, and the attributes of the key. See the Section Key Generation Specifiers for more information on how to specify these options.

-C ‘context’
The context of the parent key. This can be a permanent storage key, a primary key, or a temporary object. The parent key context is loaded using the -C option from a file created using the -c option. For example, to create a key under the primary seed, use:
tpm2_createprimary -o primary.ctx
tpm2_create -C primary.ctx -u key.pub -r key.priv
-G ‘scheme’
The asymmetric scheme for the key. This is a string that specifies the key algorithm, the hashing algorithm, and potentially other parameters. See the Key Generation Specifiers section below for more details.
-u ‘public’
The file path to store the public key in. This file will be created if it does not exist.
-r ‘private’
The file path to store the private key in. This file will be created if it does not exist.
-p ‘password’
The password to use for encrypting the private key. If not specified, the private key will not be encrypted. The password can be read from stdin or specified directly on the command line.
-a ‘authenc’
The authorization policy for the key. This is a string that specifies the policy type, and the associated parameters. See the Policy Authorizations section for more details.

KEY GENERATION SPECIFIERS

The -G option takes a string that specifies the key algorithm and any associated hashing or signing algorithms. The string is composed of one or more specifiers separated by colons (:

Asymmetric Key Specifiers

These specifiers define the algorithm and size of the asymmetric key.

•
rsa: Specifies an RSA key. The size of the key can be specified after the algorithm, e.g., rsa2048 or rsa3072.
•
ecc: Specifies an ECC key. The size of the key can be specified after the algorithm, e.g., ecc256 or ecc384.

Asymmetric Signature and Encryption Schemes

These specifiers define the signature or encryption scheme to be used with the asymmetric key.

•
rsaes: Specifies the RSAES-OAEP encryption scheme. This specifier takes no arguments.
•
rsassa: Specifies the RSASSA-PSS signature scheme. This specifier takes a hash algorithm as an argument. For example, rsassa-sha256.
•
ecdsa: Specifies the ECDSA signature scheme. This specifier takes a hash algorithm as an argument. For example, ecdsa-sha256.
•
ecdaa: Specifies the ECDAA signature scheme. This specifier takes a count and a hash algorithm as arguments. For example, ecdaa-sha256. If no count is specified, it defaults to 4.

Signing Scheme Specifiers

This scheme specifier is followed by a count (max size UINT16) then followed by a dash(-) and a valid hash algorithm. * ecdaa For example, ecdaa4-sha256. If no count is specified, it defaults to 4.

No Option Scheme Specifiers

This scheme specifier takes NO arguments. * rsaes

Symmetric Details Specifiers

This field is optional, and defaults based on the type of object being created and it’s attributes. Generally, any valid Symmetric specifier from the Type Specifiers list should work. If not specified, an asymmetric objects symmetric details defaults to aes128cfb.

Examples

Create an rsa2048 key with an rsaes asymmetric encryption scheme

tpm2_create -C parent.ctx -G rsa2048:rsaes -u key.pub -r key.priv

Create an ecc256 key with an ecdaa signing scheme with a count of 4 and sha384 hash

/tpm2_create -C parent.ctx -G ecc256:ecdaa4-sha384 -u key.pub -r key.priv cryptographic algorithms ALGORITHM.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.
