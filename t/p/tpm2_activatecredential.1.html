tpm2_activatecredential(1) Manual de Comandos Generales tpm2_activatecredential(1)

NOMBRE

tpm2_activatecredential(1) - Habilita el acceso al calificador de credenciales para recuperar el secreto de la credencial.

SINOPSIS

tpm2_activatecredential [OPCIONES]

DESCRIPCIÓN

tpm2_activatecredential(1) - Habilita la asociación de una credencial con un objeto de tal manera que garantiza que el TPM ha validado los parámetros del objeto acreditado. En un esquema de atestación, esto garantiza al registrador que la clave de atestación pertenece al TPM con una clave padre calificada en el TPM.

OPCIONES

•
-c, --credentialedkey-context=OBJETO:

Objeto asociado con el certificado creado por la CA.

•
-C, --credentialkey-context=OBJETO:

El objeto cargado utilizado para descifrar la semilla aleatoria.

•
-p, --credentialedkey-auth=AUTH:

El valor de autenticación del objeto acreditado especificado con -c.

•
-P, --credentialkey-auth=AUTH:

El valor de autenticación del objeto de credencial especificado con -C.

•
-i, --credential-blob=ARCHIVO:

La ruta del archivo de entrada que contiene el blob de credencial y el secreto creados con la herramienta tpm2_makecredential(1).

•
-o, --certinfo-data=ARCHIVO:

La ruta del archivo de salida para guardar la información del secreto de credencial descifrado.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash, a menos que también se requiera rphash.

•
--rphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros de respuesta. Esto se denomina comúnmente rpHash.

•
-S, --session=ARCHIVO:

La sesión creada usando tpm2_startauthsession. Esto se puede usar para especificar una sesión auxiliar para auditoría y/o cifrado/descifrado de los parámetros.

Referencias

Formato Objeto Contexto

El tipo de un objeto de contexto, ya sea un manejador o un nombre de archivo, se determina de acuerdo con la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio del TPM restaurado.
•
Si el argumento coincide con un prefijo de uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de plataforma
•
endorsement: la jerarquía de endorsement
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento se puede cargar como un número, se tratará como un manejador, por ejemplo, 0x81010013 y se usará directamente.

Formato de Autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autorizaciones se establecen por defecto en la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación, utilizando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña de cadena, especificada por el prefijo "str:" o su ausencia (cadena sin prefijo), no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena hexadecimal

Una contraseña de cadena hexadecimal, especificada por el prefijo "hex:", se convierte de una forma hexadecimal a una forma de matriz de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables para la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo "file:", debe ser la ruta de un archivo que contenga la contraseña a leer por la herramienta o un "-" para usar la entrada estándar. Almacenar contraseñas en archivos previene la fuga de información; las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las funciones comunes del historial del shell.

Ejemplos

# para usar la entrada estándar y ser solicitado
file:-
# para usar un archivo de una ruta
file:ruta/a/archivo/contraseña
# para hacer eco de una contraseña a través de la entrada estándar:
echo foobar | tpm2_tool -p file:-
# para usar una cadena bash "here-string" a través de la entrada estándar:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego, indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación para ser enviado con el manejador de sesión (por ejemplo, contraseña de política), agregue un + y una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones PCR

Puede satisfacer una política PCR utilizando el prefijo "pcr:" y el minilenguaje PCR. El minilenguaje PCR es el siguiente: <especificador-pcr>=<archivo-pcr-raw>

El especificador PCR se documenta en la sección "Especificadores de bancos de PCR".

El archivo-pcr-raw es un argumento opcional que contiene la salida del contenido bruto del PCR tal como lo devuelve tpm2_pcrread(1).

Especificadores de bancos de PCR

Ejemplos

Para satisfacer una política PCR de sha256 en los bancos 0, 1, 2 y 3, use un especificador de:

pcr:sha256:0,1,2,3
