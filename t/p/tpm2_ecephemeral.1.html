NOMBRE

tpm2_ecephemeral(1) - Crea una clave efímera para usarla en un protocolo de intercambio de claves en dos fases.

SINOPSIS

tpm2_ecephemeral [OPCIONES]

DESCRIPCIÓN

tpm2_ecephemeral(1) - Crea una clave efímera para usarla en un protocolo de intercambio de claves en dos fases.

OPCIONES

•
ARGUMENTO=ALGORITMO:

Especifica la curva ECC. Ejemplo: ecc521.

•
-u, --public=ARCHIVO

Especifica la ruta del archivo donde guardar el punto público efímero Q ≔ [r]G.

•
-t, --counter=ARCHIVO

Especifica la ruta del archivo donde guardar los 16 bits menos significativos del contador de confirmación.

•
--cphash=ARCHIVO

Ruta del archivo donde registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash.

Especificadores complejos

Los objetos, cuando se especifican para su creación por el TPM, tienen numerosos algoritmos para poblar en los datos públicos. Cosas como tipo, esquema y detalles asimétricos, tamaño de clave, etc. El formato general para especificar estos datos es: <tipo>:<esquema>:<detalles-simétricos>

Especificadores de tipo

Esta parte del especificador de algoritmo complejo es obligatoria. El esquema restante y los detalles simétricos se establecerán por defecto según el tipo especificado y el tipo del objeto que se está creando.

•
aes - AES por defecto: aes128
•
aes128<modo> - AES de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, se utiliza el valor por defecto null.
•
aes192<modo> - Igual que aes128<modo>, excepto por un tamaño de clave de 192 bits.
•
aes256<modo> - Igual que aes128<modo>, excepto por un tamaño de clave de 256 bits.
•
sm4 - SM4 por defecto: sm4128
•
sm4128 o sm4_128 <modo> - SM4 de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, se utiliza el valor por defecto null.
•
ecc - Curva Elíptica, por defecto es ecc256.
•
ecc192 o ecc_nist_p192 - Curva NIST ECC de 192 bits
•
ecc224 o ecc_nist_p224 - Curva NIST ECC de 224 bits
•
ecc256 o ecc_nist_p256 - Curva NIST ECC de 256 bits
•
ecc384 o ecc_nist_p384 - Curva NIST ECC de 384 bits
•
ecc521 o ecc_nist_p521 - Curva NIST ECC de 521 bits
•
ecc_sm2 o ecc_sm2_p256 - Curva SM2 de 256 bits
•
rsa - RSA por defecto: rsa2048
•
rsa1024 - RSA con tamaño de clave de 1024 bits.
•
rsa2048 - RSA con tamaño de clave de 2048 bits.
•
rsa3072 - RSA con tamaño de clave de 3072 bits.
•
rsa4096 - RSA con tamaño de clave de 4096 bits.

Especificadores de esquema

A continuación, hay un campo opcional, que se puede omitir.

Los esquemas suelen ser Esquemas de firma o Esquemas de cifrado asimétrico. La mayoría de los esquemas de firma toman un algoritmo de hash directamente después del esquema de firma. Si falta el algoritmo de hash, se utiliza el valor por defecto sha256. Algunos no toman argumentos y otros toman varios argumentos.

NAME

tpm2_create

create a primary or storage key.

SYNOPSIS

tpm2_create [-C parent context] [-G algorithm specifiers] [-u public file] [-r private file] [-p password] [-f policy file] [-l policy file] [-i input file] [-I input file digest] [-o output file] [-O output file digest] [-P parent password] [-W private password] [-X private password] [-S seed]

DESCRIPTION

tpm2_create is used to create a new primary or storage key within the TPM. This key can either be a primary key, which is used to create other keys, or a storage key, which is used to store data.

The key is created under a parent key or policy. If a parent context is specified using the -C option, the new key will be created under that parent. Otherwise, the key will be created as a primary key under the TPM's primary seed.

The algorithm for the key is specified using the -G option, which takes a comma-separated list of algorithm specifiers. These specifiers define the type of key, its attributes, and any associated cryptographic schemes.

The public and private portions of the created key are saved to files specified by the -u and -r options, respectively.

Optional arguments allow for specifying passwords for the parent key and the new key, as well as for defining policies that will be applied to the key.

OPTIONS

tpm2_create accepts the following options:

•
-C parent context: The context handle of the parent key or policy under which to create the new key. This can be a saved context file or a handle obtained from a previous command. If not specified, a primary key will be created.
•
-G algorithm specifiers: A comma-separated list of algorithm specifiers that define the key's properties. See the Algorithm Specifiers section for details.
•
-u public file: The file to which the public portion of the created key will be written.
•
-r private file: The file to which the private portion of the created key will be written.
•
-p password: The password to be used for the created key. If not specified, the key will be created without a password.
•
-f policy file: The file containing the policy digest to be associated with the key. This is used for policy-based authorization.
•
-l policy file: Similar to -f, this option specifies a policy file. The exact difference between -f and -l may depend on the specific TPM version and implementation.
•
-i input file: The file containing the data to be used as input for creating the key. This is typically used when creating keys based on specific data, such as in a policy scenario.
•
-I input file digest: Similar to -i, this option specifies an input file whose digest will be used in the key creation process.
•
-o output file: The file to which the output data related to the key creation will be written. This might include the created key handle or other relevant information.
•
-O output file digest: Similar to -o, this option specifies an output file for a digest related to the key creation process.
•
-P parent password: The password for the parent key specified with -C. Required if the parent key is password-protected.
•
-W private password: The password for the private portion of the created key. This is used to protect the generated private key file.
•
-X private password: An alternative password for the private portion of the created key. This might be used in conjunction with -W or as a separate mechanism for password protection.
•
-S seed: A seed value to be used in the key generation process. This can be used to influence the randomness of the generated key.

Algorithm Specifiers

The -G option accepts algorithm specifiers that define the type of key to be created and its associated cryptographic properties. These specifiers typically follow the format KEYTYPE:ATTRIBUTES, where KEYTYPE indicates the primary key type (e.g., rsa, ecc, sm2) and ATTRIBUTES specify additional properties like key size, signing/encryption schemes, and hash algorithms.

The following are some common algorithm specifiers:

  • rsa<SIZE>: Creates an RSA key of the specified size (e.g., rsa2048, rsa3072, rsa4096).
  • ecc<CURVE>: Creates an Elliptic Curve Cryptography (ECC) key using the specified curve (e.g., ecc256 for NIST P-256, ecc384 for NIST P-384).
  • sm2<SIZE>: Creates an SM2 key of the specified size (e.g., sm2256).

Attributes can be appended to the key type, separated by colons. These attributes specify the intended use and cryptographic schemes for the key. Common attributes include:

  • sign or encrypt: Specifies whether the key is intended for signing or encryption operations.
  • rsapss, rsaes, ecdsa, ecdaa, sm2sign: Specifies the asymmetric signing or encryption scheme to be used with the key.
  • <HASH>: Specifies the hash algorithm to be used in conjunction with a signing or encryption scheme (e.g., sha1, sha256, sha384, sha512).
  • fixedparent, fixedtpm, sensitivedata, userwithauth, adminwithpolicy, noDa, restricted, decrypt, sign, nvindex, confidential, exportable: These are various attribute flags that control the key's properties and behavior, such as its persistence, authorization requirements, and exportability.

The symmetric detail is optional, and defaults based on the type of object being created and its attributes. Generally, any valid Symmetric specifier from the Type Specifiers list should work. If not specified, an asymmetric objects symmetric details defaults to aes128cfb.

Examples

Create an rsa2048 key with an rsaes asymmetric encryption scheme

tpm2_create -C parent.ctx -G rsa2048:rsaes -u key.pub -r key.priv

Create an ecc256 key with an ecdaa signing scheme with a count of 4 and sha384 hash

tpm2_create -C parent.ctx -G ecc256:ecdaa4-sha384 -u key.pub -r key.priv cryptographic algorithms ALGORITHM.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

Tpm2 Commands Manual

NOMBRE

tpm2_ecephemeral - Creas un objeto clave de tipo primario de SE (Sesión de Equilibrio)

SINOPSIS

tpm2_ecephemeral [OPCIONES] [ARGUMENTOS]

DESCRIPCIÓN

tpm2_ecephemeral crea un objeto clave de tipo primario de SE (Sesión de Equilibrio) que se utilizará para la protección y gestión de datos. Este comando está diseñado para generar claves efímeras que son útiles en escenarios donde la persistencia de la clave no es necesaria o deseable.

OPCIONES

-p, --parent-key=OBJECT
Un objeto de clave primaria o un objeto de política que se utilizará como padre de la nueva clave. Si no se proporciona, se utilizará la clave primaria deorsement (TPM2_RH_ENDORSEMENT) por defecto.
-i, --input=FILE
Un archivo que contiene los datos de entrada (por ejemplo, una plantilla de política o datos de configuración).
-o, --output=FILE
Un archivo donde se guardará el objeto clave de SE creado.
-c, --context=FILE
Un archivo que contiene el contexto del TPM (por ejemplo, el estado de la sesión).
-e, --ecc-params=ecc_params
Parámetros específicos para curvas elípticas (ECC). Por ejemplo, nist_p256, nist_p384.
-r, --rsa-params=rsa_params
Parámetros específicos para RSA. Por ejemplo, 2048, 3072, 4096.
--pin=PIN
El PIN para acceder a la clave primaria si está protegida por contraseña.
--auth-session=SESSION
La sesión de autenticación a utilizar.
--policy-file=FILE
Especifica un archivo de política para aplicar.
-h, --help
Muestra un mensaje de ayuda y sale.
-v, --version
Muestra la información de la versión y sale.

ARGUMENTOS

Ninguno.

RETORNOS

Devuelve 0 si la operación se completa correctamente, de lo contrario devuelve un valor distinto de cero.

ERRORES

Informar de errores en <https://github.com/tpm2-software/tpm2-tools/issues>

AYUDA

La ayuda completa para este comando se puede encontrar en la sección de descripción, sin embargo, se puede encontrar más ayuda y documentación en línea en: <https://tpm2-software.github.io/tpm2-tools/>
