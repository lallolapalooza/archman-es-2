tpm2_clearcontrol(1) Manual de Comandos Generales tpm2_clearcontrol(1)

NOMBRE

tpm2_clearcontrol(1) - Establecer/Borrar el atributo TPMA_PERMANENT.disableClear para bloquear/desbloquear efectivamente el manejador de autorización de bloqueo para emitir la limpieza del TPM.

SINOPSIS

tpm2_clearcontrol [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_clearcontrol(1) - Permite al usuario con conocimiento de la autorización de bloqueo y/o la autorización de la jerarquía de plataforma establecer disableClear, lo que impide la capacidad de la autorización de bloqueo para ejecutar tpm2_clear. Solo el usuario con conocimiento de autorización de la jerarquía de plataforma puede borrar disableClear. Por defecto, intenta borrar el bit disableClear.

Nota: El manejador de autorización de la jerarquía de plataforma siempre se puede utilizar para borrar el TPM con el comando tpm2_clear.

OPCIONES

•
-C, --hierarchy=OBJETO:

Especifica en qué manejador de autorización, ya sea la jerarquía de plataforma o de bloqueo, debe operar la herramienta. Por defecto, opera en el manejador de la jerarquía de plataforma. Especifique el manejador como p|l|platform|lockout.

NOTA: OPERar en la jerarquía de plataforma requiere autenticación de plataforma.

•
-P, --auth=AUT:

El valor de autorización de la jerarquía especificada con -C. Esta herramienta solo respeta las opciones de Contraseña y HMAC.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash.

•
ARGUMENTO ** Especifica un entero 0|1 o una cadena c|s para borrar o establecer el atributo disableClear.

Referencias

Formato de Objeto de Contexto

El tipo de un objeto de contexto, ya sea un manejador o un nombre de archivo, se determina según la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio de TPM restaurado.
•
Si el argumento es una coincidencia de *prefijo* con uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un manejador, por ejemplo, 0x81010013 y se utilizará directamente._OBJETO_.

Formateo de Autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autorizaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación utilizando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña de cadena, especificada por el prefijo "str:" o su ausencia (cadena cruda sin prefijo) no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña de cadena hexadecimal, especificada por el prefijo "hex:", se convierte de una forma hexadecimal a una forma de matriz de bytes, lo que permite contraseñas con caracteres no imprimibles y/o no amigables para la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo "file:", debería ser la ruta de un archivo que contenga la contraseña a leer por la herramienta o un "-" para usar stdin. Almacenar contraseñas en archivos evita la fuga de información, las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las características comunes del historial del shell.

Ejemplos

# para usar stdin y que se le solicite
file:-
# para usar un archivo desde una ruta
file:ruta/al/archivo/de/contraseña
# para enviar una contraseña a través de stdin:
echo foobar | tpm2_tool -p file:-
# para usar un here-string de bash a través de stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, anteponga al argumento de la opción la palabra clave *session*. Luego, indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación para ser enviado con el manejador de sesión (por ejemplo, política de contraseña), entonces agregue un + y una cadena como se describe en la sección de *Contraseñas*.

Ejemplos

Para usar un archivo de contexto de sesión llamado *session.ctx*.

session:session.ctx

Para usar un archivo de contexto de sesión llamado *session.ctx* Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado *session.ctx* Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones PCR

Puede satisfacer una política PCR usando el prefijo "pcr:" y el minilenguaje PCR. El minilenguaje PCR es el siguiente: <especificador-pcr>=<archivo-pcr-crudo>

El especificador de PCR se documenta en la sección "Especificadores de bancos PCR".

El archivo-pcr-crudo es un argumento *opcional* que contiene la salida del contenido crudo del PCR tal como lo devuelve tpm2_pcrread(1).

Especificadores de bancos PCR

Ejemplos

Para satisfacer una política PCR de sha256 en los bancos 0, 1, 2 y 3, use un especificador de:

pcr:sha256:0,1,2,3

especificando *AUTORIZACIÓN*.

Configuración de TCTI

El TCTI o “Interfaz de transmisión” es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El administrador de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software TPM.
•
device - Se utiliza al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo admiten generarán un error cuando se intente usar sin una conexión TCTI. No admite NINGUNA opción y DEBE presentarse como el texto exacto de “none”.

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para <nombre-tcti> o <config-opciones-tcti> resulta en que se utilice el valor predeterminado para esa parte respectivamente.

Valores predeterminados de TCTI

Cuando no se especifica un TCTI, el TCTI predeterminado se busca utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor “default-tcti” indicará cuál de los TCTI mencionados anteriormente es el predeterminado.

TCTIs personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor crudo tcti-name se utiliza para la búsqueda. Por lo tanto, esta podría ser una ruta a la biblioteca compartida o un nombre de biblioteca según lo entendido por la semántica de dlopen(3).

OPCIONES DE TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres TPM para que lo use el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se pueden especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter ',';. Cada clave y valor se separan por un carácter '='.
•
TCTI abrmd admite dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia dbus (una cadena) limitado a `session' y `system'.

Especifique el nombre tcti tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifique el tcti predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

Establecer disableClear para bloquear el acceso de autorización de bloqueo al borrado del TPM

tpm2_clearcontrol -C l s

Borrar disableClear para desbloquear la autorización de bloqueo para el borrado del TPM

tpm2_clearcontrol -C p c

Devoluciones

Las herramientas pueden devolver cualquiera de los siguientes códigos:

•
0 - Éxito.
•
1 - Error general no específico.
•
2 - Error en el manejo de opciones.
•
3 - Error de autenticación.
•
4 - Error relacionado con TCTI.
•
5 - Esquema no soportado. Aplicable a tpm2_testparams.
