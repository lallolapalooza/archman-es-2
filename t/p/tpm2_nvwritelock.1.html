NOMBRE

tpm2_nvwritelock(1) - Bloquea el índice No Volátil (NV) para escrituras posteriores.

SINOPSIS

tpm2_nvwritelock [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_nvwritelock(1) - Bloquea el índice No Volátil (NV) para escrituras posteriores. El bloqueo del índice NV se desbloquea cuando el TPM se reinicia y el índice NV vuelve a ser escribible. El índice se puede especificar como un manejador bruto o un valor de desplazamiento del rango de manejadores nv “TPM2_HR_NV_INDEX”.

OPCIONES

•
-C, --hierarchy=OBJETO:

Especifica la jerarquía utilizada para autorizar. Las opciones admitidas son:

•
o para TPM_RH_OWNER
•
p para TPM_RH_PLATFORM
•
<num> donde se puede usar un manejador de jerarquía o índice nv.

Cuando no se pasa explícitamente -C, se utilizará el manejador del índice para autorizar contra el índice. El valor de autorización del índice se establece mediante la opción -p de tpm2_nvdefine(1).

•
-P, --auth=AUTH:

Especifica el valor de autorización para la jerarquía.

•
--global:

Bloquea todos los índices NV con el atributo TPMA_NV_GLOBALLOCK. Esta opción no requiere un índice NV o un desplazamiento como argumento.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash a menos que también se requiera rphash.

•
--rphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros de respuesta. Esto se denomina comúnmente rpHash.

•
-S, --session=ARCHIVO:

La sesión creada usando tpm2_startauthsession. Esto se puede usar para especificar una sesión auxiliar para auditoría y/o cifrado/descifrado de parámetros.

•
-n, --name=ARCHIVO:

El nombre del índice NV que debe proporcionarse al calcular solo el cpHash sin enviar realmente el comando al TPM.

•
ARGUMENTO El argumento de línea de comandos especifica el índice NV o el número de desplazamiento.

Referencias

Formato del objeto de contexto

El tipo de un objeto de contexto, ya sea un manejador o un nombre de archivo, se determina según la siguiente lógica en orden:

•
Si el argumento es una ruta de archivo, se carga el archivo como un objeto transitorio del TPM restaurado.
•
Si el argumento es una coincidencia de prefijo con uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de aprobación
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento se puede cargar como un número, se tratará como un manejador, por ejemplo, 0x81010013 y se utilizará directamente._OBJETO_.

Formateo de autorización

La autorización para usar un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: “Las autorizaciones se establecen por defecto en la CONTRASEÑA VACÍA cuando no se especifican”.

Contraseñas

Las contraseñas se interpretan en las siguientes formas usando prefijos identificadores.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña de cadena, especificada por el prefijo “str:” o su ausencia (cadena bruta sin prefijo) no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña de cadena hexadecimal, especificada por el prefijo “hex:”, se convierte de un formato hexadecimal a un formato de array de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables con la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo “file:”, debe ser la ruta de un archivo que contenga la contraseña a ser leída por la herramienta o un “-” para usar stdin. Almacenar contraseñas en archivos previene fugas de información, las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las funciones comunes del historial del shell.

Ejemplos

# para usar stdin y ser solicitado
file:-
# para usar un archivo de una ruta
file:ruta/a/archivo/contraseña
# para enviar una contraseña vía stdin:
echo foobar | tpm2_tool -p file:-
# para usar una cadena de bash vía stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego, indique una ruta a un archivo de sesión que fue creado con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autorización para ser enviado con el manejador de sesión (por ejemplo, contraseña de política), agregue un + y una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones de PCR

Puedes satisfacer una política de PCR usando el prefijo “pcr:” y el minilenguaje de PCR. El minilenguaje de PCR es el siguiente: <especificador-pcr>=<archivo-pcr-bruto>

El especificador de PCR se documenta en la sección “Especificadores de banco de PCR”.

El archivo-pcr-bruto es un argumento opcional que contiene la salida del contenido bruto del PCR tal como lo devuelve tpm2_pcrread(1).

NAME

tpm2_nvwritelock - Lock all or specific NV index to prevent writes

SYNOPSIS

tpm2_nvwritelock
    [-C context-option]
    [-p hierarchy-option]
    [index_num]
    [-Q]
    [-t TCTI-options]
    [-v]
    [-T TCTI]

DESCRIPTION

The tpm2_nvwritelock command is used to lock all NV indices or a specific NV index, from further writes. This is useful for protecting data that should not be changed after it has been written. The access policy for the NV index must permit the owner to perform this operation. The owner must also have the necessary capabilities to change the access policy for the NV index in order to unlock the index. The owner must have the capabilities to write to the index in order to lock the index.

The owner of the NV index is determined by the hierarchy that the NV index is associated with. The default hierarchy is the owner hierarchy.

OPTIONS

Those TPm2_tools options that are common to many commands are described in tpm2_tools(1).

•
-C context-option

Specifies the context of the TPM device. The context can be a TPM2_HANDLE or a file name. This option is required.

•
-p hierarchy-option

Specifies the hierarchy that the NV index is associated with. The default hierarchy is the owner hierarchy (0x150000).

•
index_num

Specifies the NV index number to lock. If not specified, all NV indices associated with the specified hierarchy will be locked.

•
-Q, --quiet

Suppresses normal output. Only errors will be printed.

•
-t, TCTI-options

This option is deprecated. Use -T instead.

•
-T TCTI

Specifies the TPM communication interface (TCTI) to use. This option overrides the TPM2TOOLS_TCTI environment variable.

See tpm2_tools(1) for more details.

Context Object Format

The context option is a string that can be specified in one of the following formats:

•
filename: Reads the context from the specified file.
•
handle: Specifies the handle of the context object. The handle can be specified in hexadecimal or decimal format.
•
type:value: Specifies the type and value of the context object. Valid types are:
•
eph: Ephemeral context.
•
hid: Handle ID context.
•
pcr: PCR context.
•
pmr: PMR context.
•
fs: File system context.

Authorization Formatting

•
pcr:sha256:0,1,2,3

specifying AUTH.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Lock an index

tpm2_nvdefine -C o -s 32 \
  -a "ownerread|policywrite|ownerwrite|writedefine" 1
echo "foobar" > nv.writelock
tpm2_nvwrite -C o -i nv.writelock 1
tpm2_nvwritelock -C o 1
# fails with "NV access locked"
tpm2_nvwrite -C o -i nv.writelock 1

Global Lock

tpm2_nvdefine -C o -s 32 \
  -a "ownerread|policywrite|ownerwrite|globallock" 1
tpm2_nvwritelock -C o --global
# this command fails with "NV access locked".
echo foo | tpm2_nvwrite -C o -i- 1

NAME

writelock - Prevent concurrent writes to a file

SYNOPSIS

writelock [OPTIONS] FILE...

DESCRIPTION

writelock creates a lock file for each specified FILE to prevent concurrent writes. If a lock file already exists, writelock will wait until it is removed. This utility is useful for ensuring that only one process at a time can modify a file.

OPTIONS

-h, --help

Display help message and exit.

-v, --version

Display version information and exit.

-f, --force

Force creation of the lock file even if the target file does not exist.

-t, --timeout SECONDS

Wait for the specified number of seconds for the lock file to be released. If the timeout is reached, writelock will exit with an error.

FILES

/path/to/your/file.lock

The lock file created by writelock. The default lock file name is derived from the target file name by appending .lock.
