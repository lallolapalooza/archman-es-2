tpm2_changepps(1) Manual de Comandos Generales tpm2_changepps(1)

NOMBRE

tpm2_changepps(1) - Reemplaza la semilla primaria de plataforma activa con una nueva generada fuera del RNG de TPM2.

SINOPSIS

tpm2_changepps [OPCIONES]

DESCRIPCION

tpm2_changepps(1) - Reemplaza la semilla primaria de plataforma activa con una nueva generada fuera del RNG de TPM2. Los objetos Transitorios y Persistentes bajo la jerarquía de plataforma se pierden, pero los objetos NV se conservan.

OPCIONES

•
-p, --auth especifica la AUTH para la jerarquía de plataforma.
•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash, a menos que también se requiera rphash.

•
--rphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros de respuesta. Esto se denomina comúnmente rpHash.

•
-S, --session=ARCHIVO:

La sesión creada usando tpm2_startauthsession. Esto se puede usar para especificar una sesión auxiliar para auditoría y/o cifrado/descifrado de los parámetros.

Referencias

Formato de Autorización

La autorización para usar un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autorizaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación usando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña en cadena, especificada por el prefijo "str:" o su ausencia (cadena sin prefijo), no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena hexadecimal

Una contraseña en cadena hexadecimal, especificada por el prefijo "hex:", se convierte de una forma hexadecimal a una forma de matriz de bytes, lo que permite contraseñas con caracteres no imprimibles y/o no aptos para terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo "file:", debería ser la ruta de un archivo que contenga la contraseña a leer por la herramienta o un "-" para usar stdin. Almacenar contraseñas en archivos evita fugas de información, las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las características comunes del historial del shell.

Ejemplos

# para usar stdin y que se solicite
file:-
# para usar un archivo desde una ruta
file:ruta/a/archivo/de/contraseña
# para enviar una contraseña vía stdin:
echo foobar | tpm2_tool -p file:-
# para usar un here-string de bash vía stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, anteponga al argumento de la opción la palabra clave session. Luego, indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autorización para ser enviado con el identificador de sesión (por ejemplo, contraseña de política), agregue un "+" y una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones PCR

Puede satisfacer una política de PCR usando el prefijo "pcr:" y el minilenguaje de PCR. El minilenguaje de PCR es el siguiente: <especificador-pcr>=<archivo-pcr-crudo>

El especificador de PCR se documenta en la sección "Especificadores de bancos de PCR".

El archivo-pcr-crudo es un argumento opcional que contiene la salida de los contenidos crudos de PCR tal como los devuelve tpm2_pcrread(1).

Especificadores de bancos de PCR

Ejemplos

Para satisfacer una política de PCR de sha256 en los bancos 0, 1, 2 y 3 use un especificador de:

pcr:sha256:0,1,2,3

especificando AUTH.

Configuración TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre tiene prioridad sobre la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente usado para comunicarse con el simulador de software de TPM.
•
device - Usado cuando se habla directamente con un archivo de dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y por lo tanto soportan no usar un TCTI. Las herramientas que no lo soportan darán error cuando se intenten usar sin una conexión TCTI. No soporta NINGUNA opción y DEBE SER presentado como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opcion-tcti>

Especificar una cadena vacía para el <nombre-tcti> o el <config-opcion-tcti> resulta en el uso del valor predeterminado para esa porción respectivamente.

Valores predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado usando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado usando la opción -v para imprimir la información de la versión. El par clave-valor "default-tcti" indicará cuál

tpm2_changepps(1) — tpm2-tools

NAME

tpm2_changepps - Change the platform primary seed (PPS) where the platform auth is NULL.

SYNOPSIS

tpm2_changepps [OPTIONS]

DESCRIPTION

The tpm2_changepps command allows the user to change the Platform Primary Seed (PPS). The PPS is used to generate the Platform Primary Key (PPK) which is the primary key for the TPM. The PPK is used to establish a secure channel between the platform and the TPM. The changepps command allows the user to generate a new PPS and use it to create a new PPK.

This command requires that the platform auth is NULL. This is because the platform auth is used to authorize the creation of the new platform primary seed. If the platform auth is not NULL, this command will fail.

If the platform auth is NULL, the command will proceed to generate a new PPS and use it to create a new PPK. The new PPS will be stored in the TPM and will be used to generate the PPK on subsequent boots.

OPTIONS

The following options are available:

-c, --clear
Clear the existing platform primary seed and create a new one. This option is required.
-p, --platform-auth=authValue
The platform authorization value. If not specified, the default value is NULL.
-t, --tcti=name:conf
Specifies the Tagged Command Transmission Interface (TCTI). The default TCTI is determined by the value of the TPM2TOOLS_TCTI environment variable. If the environment variable is not set, the default TCTI is used. If no TCTI is specified, the default TCTI is used.

Authorization Formatting

The authorization value is a string. If the string is empty, then the authorization value is NULL. If the string is not empty, then the authorization value is the string itself. The authorization value can also be specified in hexadecimal format by prefixing the string with '0x'. For example, 0x12345678.

TCTI Configuration

The TCTI is configured using a string that specifies the TCTI name and any associated configuration options. The format of the configuration string is dependent on the TCTI being used.

The following TCTIs are supported:

device
The device TCTI uses the TPM character device file. The default device file is /dev/tpm0. The configuration string can specify the device file using the following format: device:/dev/tpm0.
mssim
The mssim TCTI is used to connect to a TPM simulator. The default host is 127.0.0.1 and the default port is 2321. The configuration string can specify the host and port using the following format: mssim:host=hostname,port=port.
abrmd
The abrmd TCTI uses the tpm2-abrmd daemon to communicate with the TPM. The configuration string can specify the bus name and bus type using the following format: abrmd:bus_name=busname,bus_type=bustype.

The following table lists the default TCTI configuration:

TCTI                  DEFAULT VALUE
----                  -------------
device                /dev/tpm0
mssim                 host=127.0.0.1,port=2321
abrmd                 bus_name=com.intel.tss.tpm_daemon,bus_type=session

The default TCTI is the one that implements the dynamic TCTI interface. Which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Change the platform primary seed where the platform auth is NULL.

tpm2_changepps

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
