TPUT(1P) Manual del Programador POSIX TPUT(1P)

PROLOGO

Esta página del manual es parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

tput — cambia las características del terminal

SINOPSIS

tput [-T tipo] operando...

DESCRIPCION

La utilidad tput mostrará información dependiente del terminal. La forma en que se recupera esta información no se especifica. La información mostrada borrará la pantalla del terminal, inicializará el terminal del usuario o restablecerá el terminal del usuario, dependiendo del operando dado. Las consecuencias exactas de mostrar esta información no se especifican.

OPCIONES

La utilidad tput cumplirá con el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Guías de Sintaxis de Utilidades.

Se soportará la siguiente opción:

-T tipo
Indica el tipo de terminal. Si esta opción no se proporciona y la variable TERM no está establecida o está vacía, se utilizará un tipo de terminal predeterminado no especificado. La configuración de tipo tendrá prioridad sobre el valor en TERM.

OPERANDOS

Las siguientes cadenas serán soportadas como operandos por la implementación en la localizacin POSIX:

clear
Muestra la secuencia de borrado de pantalla.
init
Muestra la secuencia que inicializa el terminal del usuario de una manera definida por la implementación.
reset
Muestra la secuencia que restablece el terminal del usuario de una manera definida por la implementación.

Si un terminal no soporta alguna de las operaciones descritas por estos operandos, esto no se considerará una condición de error.

ENTRADA ESTÁNDAR

No utilizada.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de tput:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para conocer la prioridad de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización.)
LC_ALL
Si está establecida en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en comparación con caracteres multibyte en los argumentos).
LC_MESSAGES

Determina la localización que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en el error estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.
TERM
Determina el tipo de terminal. Si esta variable no está establecida o está vacía, y si la opción -T no se especifica, se utilizará un tipo de terminal predeterminado no especificado.

EVENTOS ASINCRONOS

Predeterminado.

SALIDA ESTÁNDAR

Si la salida estándar es un dispositivo de terminal, puede utilizarse para escribir la secuencia apropiada para borrar la pantalla o restablecer o inicializar el terminal. Si la salida estándar no es un dispositivo de terminal, se producen resultados indefinidos.

SALIDA DE ERROR ESTÁNDAR

El error estándar se utilizará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCION EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
La cadena solicitada se escribió correctamente.
 1
No especificado.
 2
Error de uso.
 3
No hay información disponible sobre el tipo de terminal especificado.
 4
El operando especificado no es válido.
>4
Ocurrió un error.

CONSECUENCIAS DE LOS ERRORES

Si uno de los operandos no está disponible para el terminal, tput continúa procesando los operandos restantes.

Las siguientes secciones son informativas.

USO DE APLICACIÓN

La diferencia entre restablecer e inicializar un terminal se deja sin especificar, ya que varían mucho según los tipos de hardware. En general, el restablecimiento es una acción más grave.

Algunos terminales utilizan caracteres de control para realizar las funciones indicadas, y en dichos terminales podría tener sentido utilizar tput para almacenar las cadenas de inicialización en un archivo o variable de entorno para su uso posterior. Sin embargo, dado que otros terminales pueden depender de llamadas al sistema para realizar este trabajo, la salida estándar no se puede utilizar de manera portátil, como las siguientes construcciones no portátiles:

ClearVar=`tput clear`
tput reset | mailx -s "Despierta" ddg

EJEMPLOS

1.
Inicializa el terminal según el tipo de terminal en la variable de entorno TERM. Este comando se puede incluir en un archivo .profile.
tput init
2.
Restablece un terminal 450.
tput -T 450 reset

RACIONALE

La lista de operandos se redujo a un mínimo por las siguientes razones:

*
Las únicas características elegidas fueron aquellas que probablemente usarían los usuarios humanos al interactuar con un terminal.
*
No se consideró deseable especificar el conjunto completo de terminfo, pero los desarrolladores del estándar no querían seleccionar entre operandos.
*
Este volumen de POSIX.1‐2017 no intenta proporcionar a las aplicaciones capacidades sofisticadas de manejo de terminales, ya que eso queda fuera de su alcance asignado y se cruza con las responsabilidades de otros organismos de normalización.

La diferencia entre restablecer e inicializar un terminal se deja sin especificar, ya que varía mucho según los tipos de hardware. En general, el restablecimiento es una acción más grave.

El estado de salida 1 se reserva históricamente para averiguar si un operando booleano no está establecido. Aunque los operandos se redujeron al mínimo, el estado de salida 1 todavía debería reservarse para los operandos booleanos, para aquellos sitios que deseen admitirlos.
