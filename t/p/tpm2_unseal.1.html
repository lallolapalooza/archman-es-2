tpm2_unseal(1) Manual General de Comandos tpm2_unseal(1)

NOMBRE

tpm2_unseal(1) - Devuelve un blob de datos en un objeto TPM cargado. El blob de datos se devuelve en claro.

SINOPSIS

tpm2_unseal [OPCIONES]

DESCRIPCIÓN

tpm2_unseal(1) - Devuelve un blob de datos en un objeto TPM cargado. El blob de datos se devuelve en claro. Los datos se sellan en el momento de la creación del objeto utilizando la herramienta tpm2_create. Dicho objeto destinado a sellar datos debe ser del tipo TPM_ALG_KEYEDHASH.

OPCIONES

•
-c, --object-context=OBJETO:

Contexto del objeto para el objeto cargado.

•
-p, --auth=AUTENTICACIÓN:

Valor de autenticación opcional a utilizar para la clave especificada por -c.

•
-o, --output=ARCHIVO:

Nombre del archivo de salida que contiene los datos desellados. Por defecto es STDOUT si no se especifica.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash, simplemente devolverá un cpHash, a menos que también se requiera rphash.

•
--rphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros de respuesta. Esto se denomina comúnmente rpHash.

•
-S, --session=ARCHIVO:

La sesión creada con tpm2_startauthsession. Se pueden especificar varios de estos. Por ejemplo, puede tener una sesión para auditoría y otra para cifrado/descifrado de los parámetros.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un manejador o un nombre de archivo, se determina según la siguiente lógica, en orden:

•
Si el argumento es una ruta de archivo, el archivo se carga como un objeto transitorio de TPM restaurado.
•
Si el argumento coincide con un prefijo de uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento se puede cargar como un número, se tratará como un manejador, por ejemplo, 0x81010013 y se utilizará directamente._OBJECT_.

Formato de Autenticación

La autenticación para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autenticaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación utilizando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña de cadena, especificada por el prefijo "str:" o su ausencia (cadena cruda sin prefijo) no se interpreta y se utiliza directamente para la autenticación.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña de cadena hexadecimal, especificada por el prefijo "hex:" se convierte de forma hexadecimal a forma de array de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables para la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo "file:" debe ser la ruta de un archivo que contenga la contraseña a leer por la herramienta o un "-" para usar stdin. Almacenar contraseñas en archivos evita fugas de información, las contraseñas pasadas como opciones pueden leerse de la lista de procesos o de funciones comunes del historial del shell.

Ejemplos

# para usar stdin y ser solicitado
file:-
# para usar un archivo desde una ruta
file:ruta/al/archivo/de/contraseña
# para hacer eco de una contraseña a través de stdin:
echo foobar | tpm2_tool -p file:-
# para usar una cadena de bash (here-string) a través de stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego, indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación para ser enviado con el manejador de sesión (por ejemplo, contraseña de política), agregue un + y una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones PCR

Puede satisfacer una política de PCR utilizando el prefijo "pcr:" y el minilenguaje PCR. El minilenguaje PCR es el siguiente: <especificador-pcr>=<archivo-pcr-crudo>

El especificador de PCR se documenta en la sección "Especificadores de banco PCR".

El archivo-pcr-crudo es un argumento opcional que contiene la salida del contenido crudo de PCR tal como lo devuelve tpm2_pcrread(1).

Especificadores de banco PCR

Ejemplos

Para satisfacer una política de PCR de sha256 en los bancos 0, 1, 2 y 3, use un especificador de:

pcr:sha256:0,1,2,3

especificando AUTENTICACIÓN.

Configuración de TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPM a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El administrador de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Se utiliza típicamente para comunicarse con el simulador de software del TPM.
•
device - Se utiliza al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializa una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo admiten generarán un error cuando se intenten usar sin una conexión TCTI. No admite *NINGUNA* opción y *DEBE* presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<configuración-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <configuración-opciones-tcti> da como resultado el uso del valor predeterminado para esa parte respectivamente.

Valores predeterminados de TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim **EN ESE ORDEN** y **UTILIZARÁN EL PRIMERO QUE ENCUENTREN**. Puede consultar qué TCTI se elegirá como predeterminado usando la opción -v para mostrar la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor crudo del nombre-tcti se utiliza para la búsqueda. Por lo tanto, esta podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entiendan las semánticas de dlopen(3).

Opciones de TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo de dispositivo de caracteres del TPM que utilizará el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se pueden especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter `,`. Cada cadena de clave y valor están separadas por un carácter `=`.
•
El TCTI abrmd admite dos claves:
1.
`bus_name`: El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type`: El tipo de la instancia de dbus (una cadena) limitada a `session` y `system`.

Especificar el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especificar el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos de los diversos módulos TCTI conocidos.

EJEMPLOS

tpm2_createprimary -c primary.ctx -Q
tpm2_pcrread -Q -o pcr.bin sha256:0,1,2,3
tpm2_createpolicy -Q --policy-pcr -l sha256:0,1,2,3 -f pcr.bin -L pcr.policy
echo 'secret' | tpm2_create -C primary.ctx -L pcr.policy -i-\
-u seal.pub -r seal.priv -c seal.ctx -Q
tpm2_unseal -c seal.ctx -p pcr:sha256:0,1,2,3

•

•
1 - Error general no específico.
•
2 - Error de manejo de opciones.
•
3 - Error de autenticación.
•
4 - Error relacionado con TCTI.
•
5 - Esquema no soportado. Aplicable a tpm2_testparams.
