tpm2_clear(1)

tpm2_clear(1) General Commands Manual tpm2_clear(1)

NOMBRE

tpm2_clear(1) - Borra los valores de autorización de la jerarquía de bloqueo, de la jerarquía de certificación y de la jerarquía del propietario, y otros datos del TPM.

SINOPSIS

tpm2_clear [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_clear(1) - Envía un comando de borrado al TPM para borrar los 3 valores de autorización de la jerarquía. Como argumento toma el valor de autorización para la jerarquía de plataforma o de bloqueo. Los detalles de los cambios realizados en el TPM se pueden encontrar en la Parte 3, "Comandos", de la especificación de la Biblioteca TPM ubicada en la siguiente URL: - https://trustedcomputinggroup.org/resource/tpm-library-specification

Por favor, busque la versión que corresponde a la versión de la especificación de soporte de su TPM y al comando TPM2_Clear. La versión de la especificación admitida por el TPM se puede encontrar emitiendo un tpm2_getcap properties-fixed en la propiedad TPM_PT_REVISION.

NOTA: Se pierden todos los objetos creados bajo las jerarquías respectivas.

OPCIONES

•
-c, --auth-hierarchy=OBJETO:

Especifica la jerarquía sobre la que deben operar las herramientas. Por defecto, opera sobre la jerarquía de bloqueo.

NOTA: Operar sobre la jerarquía de plataforma requiere autenticación de plataforma.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash.

•
ARGUMENTO el argumento de la línea de comandos especifica la AUTENTICACIÓN que se establecerá para el objeto especificado con -c.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un identificador o un nombre de archivo, se determina según la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, se carga el archivo como un objeto transitorio del TPM restaurado.
•
Si el argumento coincide con un *prefijo* de uno de los siguientes:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de plataforma
•
endorsement: la jerarquía de certificación
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un identificador, por ejemplo, 0x81010013 y se utilizará directamente. *OBJETO*.

Formato de Autorización

La autorización para usar un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autorizaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas utilizando prefijos identificadores.

Nota: Por defecto, se asume que las contraseñas están en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña en formato de cadena, especificada con el prefijo "str:" o su ausencia (cadena en bruto sin prefijo), no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña en formato de cadena hexadecimal, especificada con el prefijo "hex:", se convierte de formato hexadecimal a formato de matriz de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no compatibles con la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada con el prefijo "file:", debe ser la ruta de un archivo que contenga la contraseña a leer por la herramienta, o un "-" para usar stdin. Almacenar contraseñas en archivos evita fugas de información; las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las características comunes del historial del shell.

Ejemplos

# para usar stdin y que se solicite
file:-
# para usar un archivo de una ruta
file:ruta/al/archivo/de/contraseña
# para enviar una contraseña a través de stdin:
echo foobar | tpm2_tool -p file:-
# para usar una cadena aquí de bash a través de stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al utilizar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego, indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación para ser enviado con el identificador de la sesión (por ejemplo, contraseña de política), agregue un '+' y una cadena como se describe en la sección de Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones de PCR

Puede satisfacer una política de PCR utilizando el prefijo "pcr:" y el minilenguaje de PCR. El minilenguaje de PCR es el siguiente: <especificación-pcr>=<archivo-pcr-crudo>

La especificación de PCR se documenta en la sección "Especificadores de bancos de PCR".

El archivo-pcr-crudo es un argumento *opcional* que contiene la salida de los contenidos crudos de PCR tal como los devuelve tpm2_pcrread(1).

Especificadores de bancos de PCR

Ejemplos

Para satisfacer una política de PCR de sha256 en los bancos 0, 1, 2 y 3, use un especificador de:

pcr:sha256:0,1,2,3

especificando AUTENTICACIÓN.

OPCIONES COMUNES

Esta colección de opciones son comunes a muchos programas y proporcionan información que muchos usuarios pueden esperar.

-h, --help=[man|no-man]: Muestra el manual de la herramienta. Por defecto, intenta invocar el paginador de manuales para la herramienta; sin embargo, en caso de fallo, mostrará un resumen corto de la herramienta. DESCRIPTION

The tpm2_clear command is used to clear authorization values from TPM objects. It can be used to clear the owner authorization, the endorsement authorization, and the lockout authorization. The command can also be used to clear the authorization values on the platform hierarchy.

The command takes an optional authorization value as an argument. If no authorization value is provided, the command will attempt to clear the authorization values without any authorization. This may fail if the TPM is currently owned and the owner authorization is required.

The command can be used to clear the authorization values on the platform hierarchy by specifying the -c or --clear-platform option. This option requires the platform authorization value to be provided.

The command can also be used to clear the authorization values for the owner, endorsement and lockout authorizations by specifying the -o, -e, and -l options respectively. These options may be specified in conjunction with the -c option.

OPTIONS

The following options are available:

•
-c, --clear-platform: Clear the authorization values on the platform hierarchy. This option requires the platform authorization value to be provided.
•
-o, --clear-owner: Clear the owner authorization value.
•
-e, --clear-endorsement: Clear the endorsement authorization value.
•
-l, --clear-lockout: Clear the lockout authorization value.
•
-P, --platform-auth AUTH: The authorization value for the platform hierarchy. This is a passphrase that is expected to be a string.
•
-f, --force: Force the clearing of authorization values, even if the TPM is not in a clear state. This option can be used to clear the TPM even if it is not in a clear state. This is a potentially destructive operation and should be used with caution.
•
-t, --tcti TCTI: The TPM communication interface (TCTI) to use. This option can be used to specify the TCTI to use for communication with the TPM. For example, -t device:/dev/tpm0 or -t mssim:host=localhost,port=2321. The default TCTI is determined by the TPM2TOOLS_TCTI environment variable or by trying to load the default TCTI.
•
-Q, --quiet: Suppress normal output. Only print errors.
•
-v, --version: Print version information and exit.
•
--help: Print help information and exit.

Context Object Format

The context object is a filename or a path to a file containing the context information of a TPM object. The context object is used to specify the TPM object for which the command should be executed. The context object can be created using the tpm2_create, tpm2_load, or tpm2_readpublic commands.

The context object can be specified in the following formats:

•
A filename or a path to a file containing the context information of a TPM object.
•
A path to a directory containing context information files. In this case, the command will attempt to find the appropriate context information file in the directory.

Authorization Formatting

The authorization value can be specified in the following formats:

•
A string representing the authorization value.
•
An empty string, which will result in the authorization value being cleared.

COMMON OPTIONS

The following options are common to all tools in the tpm2-tools suite. They are described in the tpm2_options(7) man page.

The TPM2 tools all support a set of common options that allow users to specify the TCTI (TPM Communication and Test Interface) for communication with the TPM. The TCTI is the mechanism by which the tools communicate with the TPM. The following options are available:

The order of precedence for TCTI selection is:

  1. Command line option -T or --tcti.
  2. Environment variable TPM2TOOLS_TCTI.
  3. Default TCTI selection.

The default TCTI is determined by searching for available TCTI modules in the order: tabrmd, device, and mssim. The first one found is used. This behavior can be observed by running a tool with the -v option, which will print the selected default TCTI.

The TCTI configuration string follows the format:

<tcti-name>:<tcti-option-config>

If either the <tcti-name> or <tcti-option-config> is empty, the default value for that portion will be used.

The following TCTI modules are supported:

•
tabrmd: The resource manager provided by tpm2-abrmd. Note that tabrmd and abrmd are synonymous when used as a TCTI name.
•
mssim: Used for communicating with the TPM software simulator.
•
device: Used for direct communication with a TPM device file. The default device file is /dev/tpm0.
•
none: Disables TCTI initialization. This is useful for tools that support off-TPM operations. Tools that require a TCTI connection will error if this is used.

The following TCTI options are supported:

•
device: 
  -T device:/dev/tpm0
•
mssim: 
  -T mssim:host=localhost,port=2321
•
tabrmd: The configuration string is a series of key-value pairs separated by commas. Supported keys are:
•
bus_name: The name of the tabrmd service on the bus (e.g., com.example.FooBar).
•
bus_type: The type of the D-Bus instance. Limited to session or system.
Example: 
  -T tabrmd:bus_name=com.example.FooBar,bus_type=session
If only bus_type is specified, the default bus_name for tabrmd will be used: 
  -T tabrmd:bus_type=session

The following common options are available:

•
-v, --version: Display version information for this tool, supported tctis and exit.
•
-V, --verbose: Increase the information that the tool prints to the console during its execution. When using this option the file and line number are printed.
•
-Q, --quiet: Silence normal tool output to stdout.
•
-Z, --enable-errata: Enable the application of errata fixups. Useful if an errata fixup needs to be applied to commands sent to the TPM. Defining the environment TPM2TOOLS_ENABLE_ERRATA is equivalent.
•
-R, --autoflush: Enable autoflush for transient objects created by the command. If a parent object is loaded from a context file also the transient parent object will be flushed. Autoflush can also be activated if the environment variable TPM2TOOLS_AUTOFLUSH is is set to yes or true. information many users may expect.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

tpm2_clear -c p
