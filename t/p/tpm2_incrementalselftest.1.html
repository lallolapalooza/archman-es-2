NOMBRE

tpm2_incrementalselftest(1) - Solicitar la prueba de una lista de algoritmos especificada

SINOPSIS

tpm2_incrementalselftest [OPCIONES] LISTA_ESPEC_ALG

DESCRIPCIÓN

tpm2_incrementalselftest(1) Solicita al TPM que realice pruebas en el algoritmo especificado e imprima una lista de algoritmos programados para ser probados O que aún quedan por probar pero no programados.

El principal interés de este comando es reducir los retrasos que pueden ocurrir en las operaciones criptográficas, ya que el TPM debe probar el algoritmo antes de usarlo.

LISTA_ESPEC_ALG

Una lista separada por espacios de los conjuntos de algoritmos a probar. Los algoritmos deben seguir los "estándares de formato", ver la sección "Especificadores de Algoritmos". Además, consulte la sección "Algoritmos Hash Soportados" para obtener una lista de algoritmos hash soportados.

Si LISTA_ESPEC_ALG se deja vacía, tpm2_incrementalselftest(1) devolverá la lista de algoritmos que quedan por probar. Tenga en cuenta que en este caso, estos algoritmos NO están programados para ser probados.

Si LISTA_ESPEC_ALG no está vacía, tpm2_incrementalselftest(1) devolverá la lista de algoritmos que quedan por probar. Esta lista contiene algoritmos programados para pruebas Y algoritmos que quedan por probar y que aún no están programados. Esto puede ocurrir, por ejemplo, si aún no se han probado todos los modos AES.

Salida

La lista de algoritmos a probar (lo que implica que están programados) o que quedan por probar (no programados) también se imprime en formato YAML.

Si no se imprime ninguno de los algoritmos especificados, significa que ya han sido probados y que estos algoritmos no se volverán a probar.

OPCIONES

Esta herramienta no acepta opciones específicas de la herramienta.

Especificadores complejos

Los objetos, cuando se especifican para su creación por el TPM, tienen numerosos algoritmos para poblar los datos públicos. Cosas como el tipo, el esquema y los detalles asimétricos, el tamaño de la clave, etc. A continuación se muestra el formato general para especificar estos datos: <tipo>:<esquema>:<detalles-simétricos>

Especificadores de tipo

Esta parte del especificador de algoritmo complejo es obligatoria. El esquema restante y los detalles simétricos se establecerán por defecto según el tipo especificado y el tipo del objeto que se está creando.

•
aes - AES por defecto: aes128
•
aes128<modo> - AES de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, el valor por defecto es null.
•
aes192<modo> - Igual que aes128<modo>, excepto por un tamaño de clave de 192 bits.
•
aes256<modo> - Igual que aes128<modo>, excepto por un tamaño de clave de 256 bits.
•
sm4 - SM4 por defecto: sm4128
•
sm4128 o sm4_128 <modo> - SM4 de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, el valor por defecto es null.
•
ecc - Curva Elíptica, por defecto es ecc256.
•
ecc192 o ecc_nist_p192 - Curva NIST ECC de 192 bits
•
ecc224 o ecc_nist_p224 - Curva NIST ECC de 224 bits
•
ecc256 o ecc_nist_p256 - Curva NIST ECC de 256 bits
•
ecc384 o ecc_nist_p384 - Curva NIST ECC de 384 bits
•
ecc521 o ecc_nist_p521 - Curva NIST ECC de 521 bits
•
ecc_sm2 o ecc_sm2_p256 - Curva SM2 de 256 bits
•
rsa - RSA por defecto: rsa2048
•
rsa1024 - RSA con tamaño de clave de 1024 bits.
•
rsa2048 - RSA con tamaño de clave de 2048 bits.
•
rsa3072 - RSA con tamaño de clave de 3072 bits.
•
rsa4096 - RSA con tamaño de clave de 4096 bits.

Especificadores de esquema

A continuación, hay un campo opcional que se puede omitir.

Los esquemas suelen ser Esquemas de Firma o Esquemas de Cifrado Asimétrico. La mayoría de los esquemas de firma toman un algoritmo hash directamente después del esquema de firma. Si falta el algoritmo hash, el valor por defecto es sha256. Algunos no toman argumentos y otros toman múltiples argumentos.

Especificadores de Esquema con Múltiples Opciones

A este especificador de esquema le sigue un recuento (tamaño máximo UINT16) seguido de un guion (-) y un algoritmo hash válido. * ecdaa Por ejemplo, ecdaa4-sha256. Si no se especifica ningún recuento, el valor por defecto es 4.

Este especificador de esquema NO toma argumentos. * rsaes

Especificadores de Detalles Simétricos

Este campo es opcional y su valor por defecto se basa en el *tipo* de objeto que se está creando y sus atributos. En general, cualquier especificador *Symmetric* válido de la lista de especificadores de *Type* debería funcionar. Si no se especifica, los detalles simétricos de los objetos asimétricos por defecto son *aes128cfb*.

Ejemplos

Crear una clave rsa2048 con un esquema de cifrado asimétrico rsaes

tpm2_create -C parent.ctx -G rsa2048:rsaes -u key.pub -r key.priv

Crear una clave ecc256 con un esquema de firma ecdaa con un recuento de 4 y hash sha384

/tpm2_create -C parent.ctx -G ecc256:ecdaa4-sha384 -u key.pub -r key.priv algoritmos criptográficos *ALGORITHM*.

Configuración de TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: *TPM2TOOLS_TCTI*.

Nota: La opción de línea de comandos siempre tiene prioridad sobre la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Utilizado para comunicarse directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo admiten generarán un error cuando se intente usarlas sin una conexión TCTI. No admite *NINGUNA* opción y *DEBE* presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<tcti-name>:<tcti-option-config>

Especificar una cadena vacía para <tcti-name> o <tcti-option-config> resulta en el uso del valor por defecto para esa parte respectivamente.

Valores por defecto de TCTI

Cuando no se especifica un TCTI, se busca el TCTI por defecto utilizando la semántica de dlopen(3). Las herramientas buscarán *tabrmd*, *device* y *mssim* TCTIs **EN ESE ORDEN** y **UTILIZARÁN EL PRIMERO QUE ENCUENTREN**. Puede consultar qué TCTI se elegirá por defecto usando la opción **-v** para mostrar la información de versión. El par clave-valor "default-tcti" indicará cuál de los TCTIs mencionados es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas internamente utilizan dlopen(3), y el valor crudo *tcti-name* se utiliza para la búsqueda. Por lo tanto, esta podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca como lo entiende la semántica de dlopen(3).

OPCIONES DE TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de carácter TPM a utilizar por el TCTI de dispositivo. El valor predeterminado es * /dev/tpm0*.

Ejemplo: -T device:/dev/tpm0 o export *TPM2TOOLS_TCTI*=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export *TPM2TOOLS_TCTI*=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de cadena de configuración es una serie de pares clave-valor simples separados por un carácter ','. Cada clave y valor de cadena están separados por un carácter '='.
•
El TCTI abrmd soporta dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia de dbus (una cadena) limitada a `session' y `system'.

Especifique el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifique el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

Solicitar la prueba del algoritmo RSA

tpm2_incrementalselftest rsa

Solicitar la prueba de múltiples algoritmos

tpm2_incrementalselftest rsa ecc xor aes cbc

NOTAS

El conjunto de algoritmos especificado puede implicar la prueba de la combinación o del conjunto completo, dependiendo de la implementación del fabricante del TPM.

por ejemplo: Un TPM podría solo probar AES con modo CTR si se especifica "aes ctr". Otro podría también probar la lista completa de modos AES Y probar el modo CTR.

Si un algoritmo ya ha sido probado, este comando no permitirá volver a ejecutar la prueba. Solo la ejecución de tpm2_selftest(1) en modo de prueba completa habilitada forzará la repetición de la prueba.

1 - Error general no específico.

tpm2_incrementalselftest(1) — tpm2-tools

NAME

tpm2_incrementalselftest

ejecuta una autoevaluación incremental del TPM

SYNOPSIS

tpm2_incrementalselftest

  • [TCTI OPTIONS]
  • [OPTIONS]

DESCRIPTION

tpm2_incrementalselftest ejecuta una autoevaluación incremental en el TPM. El TPM realiza autoevaluaciones para verificar la integridad de su funcionamiento. La autoevaluación incremental solo se ejecuta si la autoevaluación completa previa fue un éxito. Si la autoevaluación completa falla, esta función no debe ser invocada.

Si la autoevaluación incremental se ejecuta correctamente, la bandera de autoevaluación en el TPM se establecerá en un valor incremental. La autoevaluación incremental se puede realizar repetidamente para probar la funcionalidad del TPM sin afectar el estado operativo del TPM. Por ejemplo, se puede usar para probar la memoria del TPM, las funciones criptográficas o los registros internos.

ALG_SPEC_LIST

Una lista de especificaciones de algoritmos que separan por comas. Consulte la sección de especificadores de algoritmos a continuación para ver la sintaxis.

Output

Actualmente no se produce ninguna salida.

OPTIONS

-l ALG_SPEC_LIST
especifica los algoritmos para los que se debe ejecutar la autoevaluación incremental. Si no se especifican, se ejecutarán todas las autoevaluaciones incrementales disponibles.
-h
ayuda para tpm2_incrementalselftest

Algorithm Specifiers

Un especificador de algoritmo es un nombre de algoritmo de TPM (por ejemplo, rsa, ecc, sha1, sha256, etc.). Pueden ir prefijados con un signo más (+) para incluir explícitamente un algoritmo. Si un algoritmo está precedido por un signo menos (-), será excluido.

Ejemplo:

+rsa,+sha256: especifica que solo se deben probar rsa y sha256.

-sha1,+sha256: especifica que se deben probar todos los algoritmos excepto sha1, pero incluyendo sha256.

COMMON OPTIONS

Para obtener una lista de las opciones comunes, consulte la página del manual de tpm2_tool_options(7).

TCTI Configuration

Para obtener una lista de las opciones de configuración de TCTI, consulte la página del manual de tpm2_tcti(7).

TCTI OPTIONS

Consulte la página del manual de tpm2_tool_options(7) para obtener una descripción de las opciones de TCTI.

EXAMPLES

Ejecuta la autoevaluación incremental para todos los algoritmos:

$ tpm2_incrementalselftest

Ejecuta la autoevaluación incremental solo para rsa y sha256:

$ tpm2_incrementalselftest -l +rsa,+sha256

NOTES

La autoevaluación incremental puede tardar un tiempo considerable en completarse.

Esta función solo debe invocarse si la autoevaluación completa previa fue un éxito.

Returns

0 si la autoevaluación incremental se ejecutó correctamente, de lo contrario, distinto de cero.
