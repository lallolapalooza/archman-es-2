tpm2_nvcertify(1) Manual de Comandos Generales tpm2_nvcertify(1)

NOMBRE

tpm2_nvcertify(1) - Proporciona atestación del contenido de un índice NV.

SINOPSIS

tpm2_nvcertify [OPCIONES] [ARGUMENTOS]

DESCRIPCIÓN

tpm2_nvcertify(1) - Proporciona atestación del contenido de un índice NV. NOTA: Como parte de la salida de atestación, se revelan los contenidos del índice NV.

OPCIONES

Estas opciones controlan la certificación:

•
-C, --signingkey-context=OBJETO:

El objeto clave que firma la estructura de atestación.

•
-P, --signingkey-auth=AUTENTICACIÓN:

El valor de autorización proporcionado para el objeto especificado con -C.

•
-c, --nvauthobj-context=OBJETO:

El objeto que es el manejador de autorización para el objeto NV. Es el manejador del índice NV mismo o el manejador de la jerarquía de plataforma/propietario. Si no se especifica, se usa por defecto el manejador del índice NV.

•
-p, --nvauthobj-auth=AUTENTICACIÓN:

El valor de autorización proporcionado para el objeto especificado con -c.

•
-g, --hash-algorithm=ALGORITMO:

El algoritmo de hash a usar en la generación de la firma.

•
-s, --scheme=ALGORITMO:

El esquema de firma utilizado para firmar los datos de atestación.

•
-f, --format=FORMATO:

Selección de formato para el archivo de salida de la firma.

•
-o, --signature=ARCHIVO:

Nombre del archivo de salida para los datos de la firma.

•
-q, --qualification=ARCHIVO_O_CADENA_HEX:

Opcional, los datos del calificador de política que el firmante puede elegir incluir en la firma. Puede ser una cadena hexadecimal o una ruta.

•
--size=NUMERO_NATURAL:

Especifica el tamaño de los datos a leer en bytes, comenzando desde 0 si no se especifica el desplazamiento. Si no se especifica, se usará el tamaño de los datos según lo informado por la porción pública del índice.

•
--offset=NUMERO_NATURAL:

El desplazamiento dentro del índice NV desde donde comenzar a leer.

•
--attestation=ARCHIVO:

Los datos de atestación del tipo TPM2_CREATION_INFO firmados con la clave de firma.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash a menos que también se requiera rphash.

•
--rphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros de respuesta. Esto se denomina comúnmente rpHash.

•
-S, --session=ARCHIVO:

La sesión creada usando tpm2_startauthsession. Esto puede usarse para especificar una sesión auxiliar para auditoría y/o cifrado/descifrado de los parámetros.

•
-n, --name=ARCHIVO:

El nombre del índice NV que debe proporcionarse cuando solo se calcula el cpHash sin enviar realmente el comando al TPM.

•
--signer-name=ARCHIVO:

El nombre de la clave de firma que debe proporcionarse cuando solo se calcula el cpHash sin enviar realmente el comando al TPM.

•
ARGUMENTO el argumento de línea de comandos especifica el índice NV o el número de desplazamiento.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un manejador o un nombre de archivo, se determina según la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio del TPM restaurado.
•
Si el argumento coincide con un *prefijo* de uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un manejador, por ejemplo, 0x81010013, y se usará directamente.

Formato de Autenticación

La autenticación para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: Las autenticaciones tienen por defecto la CONTRASEÑA VACÍA cuando no se especifican.

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación utilizando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena de texto

Una contraseña de cadena de texto, especificada con el prefijo “str:” o su ausencia (cadena bruta sin prefijo) no se interpreta y se utiliza directamente para la autenticación.

Ejemplos

foobar
str:foobar

Cadena hexadecimal

Una contraseña de cadena hexadecimal, especificada con el prefijo “hex:”, se convierte de forma hexadecimal a una forma de arreglo de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o difíciles de usar en la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada con el prefijo “file:”, debe ser la ruta de un archivo que contenga la contraseña a leer por la herramienta o un “-” para usar stdin. Almacenar contraseñas en archivos evita fugas de información, las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de funciones comunes del historial del shell.

Ejemplos

# para usar stdin y que se solicite
file:-
# para usar un archivo de una ruta
file:ruta/al/archivo/contraseña
# para enviar una contraseña vía stdin:
echo foobar | tpm2_tool -p file:-
# para usar una cadena aquí de bash vía stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave *session*. Luego indique una ruta a un archivo de sesión que fue creado con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere

ses un valor de autenticación para ser enviado con el manejador de sesión (por ejemplo, contraseña de política), luego adjunta un + y una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones PCR

Puede satisfacer una política de PCR usando el prefijo “pcr:” y el minilenguaje de PCR. El minilenguaje de PCR es el siguiente: <pcr-spec>=<archivo-pcr-crudo>

La especificación de PCR está documentada en la sección “Especificadores de banco PCR”.

El archivo-pcr-crudo es un argumento opcional que contiene la salida de los contenidos crudos de PCR tal como los devuelve tpm2_pcrread(1).

Especificadores de banco PCR

Ejemplos

Para satisfacer una política de PCR de sha256 en los bancos 0, 1, 2 y 3, use un especificador de:

pcr:sha256:0,1,2,3

especificando AUTH.

Especificadores Complejos

Los objetos, cuando se especifican para su creación por el TPM, tienen numerosos algoritmos que poblar en los datos públicos. Cosas como el tipo, el esquema y los detalles asimétricos, el tamaño de la clave, etc. A continuación se muestra el formato general para especificar estos datos: <tipo>:<esquema>:<detalles-simétricos>

Especificadores de Tipo

Esta porción del especificador de algoritmo complejo es requerida. El resto del esquema y los detalles simétricos se establecerán por defecto en función del tipo especificado y el tipo del objeto que se está creando.

•
aes - AES por defecto: aes128
•
aes128<modo> - AES de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, el valor por defecto es null.
•
aes192<modo> - Igual que aes128<modo>, excepto por un tamaño de clave de 192 bits.
•
aes256<modo> - Igual que aes128<modo>, excepto por un tamaño de clave de 256 bits.
•
sm4 - SM4 por defecto: sm4128
•
sm4128 o sm4_128 <modo> - SM4 de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, el valor por defecto es null.
•
ecc - Curva Elíptica, por defecto es ecc256.
•
ecc192 o ecc_nist_p192 - Curva NIST ECC de 192 bits
•
ecc224 o ecc_nist_p224 - Curva NIST ECC de 224 bits
•
ecc256 o ecc_nist_p256 - Curva NIST ECC de 256 bits
•
ecc384 o ecc_nist_p384 - Curva NIST ECC de 384 bits
•
ecc521 o ecc_nist_p521 - Curva NIST ECC de 521 bits
•
ecc_sm2 o ecc_sm2_p256 - Curva SM2 de 256 bits
•
rsa - RSA por defecto: rsa2048
•
rsa1024 - RSA con tamaño de clave de 1024 bits.
•
rsa2048 - RSA con tamaño de clave de 2048 bits.
•
rsa3072 - RSA con tamaño de clave de 3072 bits.
•
rsa4096 - RSA con tamaño de clave de 4096 bits.

Especificadores de Esquema

A continuación, hay un campo opcional, se puede omitir.

Los esquemas son generalmente Esquemas de Firma o Esquemas de Cifrado Asimétrico. La mayoría de los esquemas de firma toman un algoritmo de hash directamente después del esquema de firma. Si el algoritmo de hash falta, el valor por defecto es sha256. Algunos no toman argumentos y otros toman múltiples argumentos.

Este especificador de esquema va seguido de un recuento (tamaño máximo UINT16) y luego seguido de un guion (-) y un algoritmo de hash válido. * ecdaa Por ejemplo, ecdaa4-sha256. Si no se especifica ningún recuento, el valor por defecto es 4.

Especificadores de Esquema sin Opciones

Este especificador de esquema NO toma argumentos. * rsaes

Especificadores de Detalles Simétricos

Este campo es opcional y se establece por defecto según el tipo de objeto que se está creando y sus atributos. En general, cualquier especificador Simétrico válido de la lista de Especificadores de Tipo debería funcionar. Si no se especifica, los detalles simétricos de los objetos asimétricos tienen por defecto aes128cfb.

Ejemplos

Crear una clave rsa2048 con un esquema de cifrado asimétrico rsaes

tpm2_create -C parent.ctx -G rsa2048:rsaes -u key.pub -r key.priv

Crear una clave ecc256 con un esquema de firma ecdaa con un recuento de 4 y hash sha384

/tpm2_create -C parent.ctx -G ecc256:ecdaa4-sha384 -u key.pub -r key.priv algoritmos criptográficos ALGORITHM.

Selección de formato para el archivo de salida de la firma. tss (el valor por defecto) generará un blob binario según la especificación TPM 2.0 y cualquier posible relleno del compilador. La opción plain generará los datos de firma sin procesar tal como los define el algoritmo criptográfico utilizado. formato de firma FORMAT.

CONFIGURACIÓN DEL TCTI

El TCTI o "Transmission Interface" es el mecanismo de comunicación con el TPM. Los TCTIs se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre tiene prioridad sobre la variable de entorno.

Los TCTIs conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Se utiliza al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializa una conexión con el TPM. Algunas herramientas permiten opciones off-tpm y por lo tanto soportan no usar un TCTI. Las herramientas que no lo soportan generarán un error al intentar ser utilizadas sin una conexión TCTI. No soporta *NINGUNA* opción y *DEBE* presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o el <config-opciones-tcti> resulta en que se utilice el valor por defecto para esa porción respectivamente.

VALORES POR DEFECTO DEL TCTI

Cuando no se especifica un TCTI, se busca el TCTI por defecto utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTIs tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI será elegido como el valor por defecto utilizando la opción -v para mostrar la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTIs mencionados es el valor por defecto.

TCTIs PERSONALIZADOS

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor crudo nombre-tcti se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca tal como lo entiende la semántica de dlopen(3).

OPCIONES DEL TCTI

Esta colección de opciones se utiliza para configurar los varios módulos TCTI conocidos disponibles:

•
device: Para el TCTI device, se puede especificar el archivo del dispositivo de caracteres TPM para su uso por el TCTI device. El valor por defecto es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores por defecto son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter `,`. Cada cadena de clave y valor se separa por un carácter `=`.
•
TCTI abrmd soporta dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia dbus (una cadena) limitada a `session' y `system'.

Especifica el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifica el TCTI por defecto (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los varios módulos TCTI conocidos.

EJEMPLOS

tpm2_nvdefine -s 32 -a "authread|authwrite" 1
dd if=/dev/urandom bs=1 count=32 status=none| \
tpm2_nvwrite 1 -i-
tpm2_createprimary -C o -c primary.ctx -Q
tpm2_create -G rsa -u rsa.pub -r rsa.priv -C primary.ctx -c signing_key.ctx -Q
tpm2_readpublic -c signing_key.ctx -f pem -o sslpub.pem -Q
tpm2_nvcertify -C signing_key.ctx -g sha256 -f plain -s rsassa \
-o signature.bin --attestation attestation.bin --size 32 1

•

•
2 - Error en el manejo de opciones.
•
3 - Error de autenticación.
•
4 - Error relacionado con TCTI.
•
5 - Esquema no soportado. Aplicable a tpm2_testparams.
