NOMBRE

tpool - Parte de la extensión de hilos Tcl que implementa grupos de hilos trabajadores.

SINOPSIS

package require Tcl 8.4

package require Thread ?2.8?

tpool::create ?opciones?

tpool::names

tpool::post ?-detached? ?-nowait? tpool script

tpool::wait tpool joblist ?varname?

tpool::cancel tpool joblist ?varname?

tpool::get tpool job

tpool::preserve tpool

tpool::release tpool

tpool::suspend tpool

tpool::resume tpool

DESCRIPCIÓN

Este paquete crea y gestiona grupos de hilos trabajadores. Permite enviar trabajos a los hilos trabajadores y esperar su finalización. La implementación del grupo de hilos es consciente del bucle de eventos de Tcl. Esto significa que cada vez que un llamador se ve obligado a esperar por un evento (la finalización de un trabajo o la disponibilidad de un hilo trabajador o su inicialización), la implementación entrará en el bucle de eventos y permitirá el servicio de otros eventos de archivo o temporizador pendientes (o cualquier otro evento soportado).

COMANDOS

tpool::create ?opciones?
Este comando crea un nuevo grupo de hilos. Acepta varias opciones como pares clave-valor. Las opciones se utilizan para ajustar algunos parámetros del grupo de hilos. El comando devuelve el ID del grupo de hilos recién creado.

Las siguientes opciones son compatibles:

-minworkers número
Número mínimo de hilos trabajadores necesarios para esta instancia del grupo de hilos. Durante la creación del grupo de hilos, la implementación creará tantos hilos trabajadores por adelantado y mantendrá al menos ese número vivos durante la vida útil de la instancia del grupo de hilos. El valor por defecto de este parámetro es 0 (cero), lo que significa que un grupo de hilos nuevo no tendrá hilos trabajadores inicialmente. Todos los hilos trabajadores se iniciarán bajo demanda por los llamadores que ejecuten el comando tpool::post y envíen trabajos a la cola de trabajos.
-maxworkers número
Número máximo de hilos trabajadores permitidos para esta instancia del grupo de hilos. Si hay un nuevo trabajo pendiente y no hay hilos trabajadores disponibles, la implementación intentará crear un nuevo hilo trabajador. Si el número de hilos trabajadores disponibles es menor que el número dado, se iniciará un nuevo hilo trabajador. El llamador entrará automáticamente en el bucle de eventos y esperará hasta que el hilo trabajador se inicialice. Si, sin embargo, el número de hilos trabajadores disponibles es igual al número dado, el llamador entrará en el bucle de eventos y esperará a que el primer hilo trabajador quede inactivo, listo para ejecutar el trabajo. El valor por defecto de este parámetro es 4 (cuatro), lo que significa que la instancia del grupo de hilos permitirá un máximo de 4 hilos trabajadores ejecutando trabajos o inactivos esperando que se envíen nuevos trabajos a la cola de trabajos.
-idletime segundos
Tiempo en segundos que un hilo trabajador inactivo espera a que se envíe un trabajo a la cola de trabajos. Si no llega ningún trabajo durante este intervalo y el tiempo expira, el hilo trabajador comprobará el número de hilos trabajadores disponibles y, si es mayor que el número establecido por la opción minthreads, saldrá. Si se ha definido un exitscript, el hilo trabajador que sale ejecutará primero el script y luego saldrá. Los errores del script de salida, si los hay, se ignoran.

El hilo trabajador inactivo no está prestando servicio al bucle de eventos. Si, sin embargo, pone el hilo trabajador en el bucle de eventos, evaluando vwait u otros comandos Tcl relacionados, el hilo trabajador no estará en estado inactivo, por lo tanto, el temporizador de inactividad no se tendrá en cuenta. El valor por defecto para esta opción no está especificado.

-initcmd script
Establece un script Tcl utilizado para inicializar un nuevo hilo trabajador. Esto se usa normalmente para cargar paquetes y comandos en el trabajador, establecer variables por defecto, crear espacios de nombres, etc. Si el script pasado genera un error de Tcl, el trabajador no se creará y el comando iniciador (ya sea tpool::create o tpool::post) generará un error. El valor por defecto para esta opción no está especificado, por lo tanto, el intérprete Tcl del hilo trabajador contendrá solo el conjunto inicial de comandos Tcl.
-exitcmd script
Establece un script Tcl que se ejecuta cuando un hilo trabajador inactivo sale. Esto se usa normalmente para limpiar el estado del hilo trabajador, liberar recursos reservados, limpiar memoria y demás. El valor por defecto para esta opción no está especificado, por lo tanto, no se ejecutará ningún script Tcl al salir del hilo trabajador.
tpool::names
Este comando devuelve una lista de IDs de grupos de hilos creados con el comando tpool::create. Si no se encontraron grupos de hilos, el comando devolverá una lista vacía.
tpool::post ?-detached? ?-nowait? tpool script
Este comando envía un script al grupo de hilos de destino tpool para su ejecución. El script se ejecutará en el primer hilo trabajador inactivo disponible. Si no hay hilos trabajadores inactivos disponibles, el comando creará uno nuevo, entrará en el bucle de eventos y atenderá eventos hasta que el hilo recién creado se inicialice. Si el número actual de hilos trabajadores es igual al número máximo de hilos trabajadores, según se define durante la creación del grupo de hilos, el comando entrará en el bucle de eventos y atenderá eventos mientras espera que uno de los hilos trabajadores quede inactivo. Si se proporciona el argumento opcional ?-nowait?, el comando no esperará a un hilo inactivo. Simplemente colocará el trabajo en la cola de trabajos del grupo y devolverá inmediatamente.

El comando devuelve el ID del trabajo enviado. Este ID se utiliza para los comandos posteriores tpool::wait, tpool::get y tpool::cancel para esperar y recuperar el resultado del script enviado, o para cancelar el trabajo enviado respectivamente. Si se especifica el argumento opcional ?-detached?, el comando enviará un trabajo desacoplado. Un trabajo desacoplado no puede cancelarse ni esperarse y no se identifica por el ID del trabajo.

Si el grupo de hilos tpool no se encuentra en la lista de grupos de hilos activos, el comando generará un error. El error también se activará si el hilo trabajador recién creado no se inicializa correctamente.

tpool::wait tpool joblist ?varname?
Este comando espera a que uno o varios trabajos, cuyos IDs se proporcionan en la joblist, sean procesados por el(los) hilo(s) trabajador(es). Si ninguno de los trabajos especificados está listo, el comando entrará en el bucle de eventos, atenderá eventos y esperará a que el primer trabajo esté listo.

El comando devuelve la lista de IDs de trabajos completados. Si se proporciona la variable opcional ?varname?, se establecerá con la lista de trabajos en joblist que aún están pendientes. Si el grupo de hilos tpool no se encuentra en la lista de grupos de hilos activos, el comando generará un error.

tpool::cancel tpool joblist ?varname?
Este comando cancela los trabajos previamente enviados dados por la joblist al grupo tpool. La cancelación de trabajos solo tiene éxito para trabajos que aún esperan ser procesados. Si el trabajo ya está siendo ejecutado por uno de los hilos trabajadores, el trabajo no se cancelará. El comando devuelve la lista de IDs de trabajos cancelados. Si se proporciona la variable opcional ?varname?, se establecerá con la lista de trabajos en joblist que no fueron cancelados. Si el grupo de hilos tpool no se encuentra en la lista de grupos de hilos activos, el comando generará un error.

Este comando recupera el resultado del job enviado previamente. Solo se pueden recuperar los resultados de los trabajos esperados con el comando tpool::wait. NOMBRE

tpool - gestión de un grupo de hilos de trabajo

SINOPSIS

package require Tcl 8.5
package require thread
package require tpool ?version?
tpool subcommand ?arg ...?

DESCRIPCION

El comando tpool proporciona una interfaz para la gestión de grupos de hilos de trabajo (threadpools) con el fin de ejecutar tareas en segundo plano. Los grupos de hilos de trabajo son útiles para gestionar la sobrecarga de la creación de hilos en aplicaciones que necesitan realizar muchas tareas pequeñas y de corta duración.

Un grupo de hilos de trabajo consiste en un conjunto de hilos de trabajo que están listos para realizar tareas. Cuando se solicita una tarea, se asigna a un hilo de trabajo disponible. Si no hay hilos disponibles, la tarea se pone en cola hasta que un hilo esté libre. Esto evita la creación continua de nuevos hilos, lo que puede ser costoso en términos de rendimiento y uso de recursos.

COMANDOS

tpool::create ?-option value...?
Crea un nuevo grupo de hilos de trabajo. Los opciones soportadas son:
-minworkers num
El número mínimo de hilos de trabajo que se mantendrán activos en el grupo. Por defecto es 1.
-maxworkers num
El número máximo de hilos de trabajo que se permitirán en el grupo. Por defecto es 10.
-idle time
El tiempo en segundos que un hilo de trabajo puede permanecer inactivo antes de ser destruido. Por defecto es 60 segundos.
El comando devuelve el nombre del grupo de hilos de trabajo creado, que es un valor que se puede pasar a otros comandos de tpool. Si se producen errores, se lanzará una excepción Tcl.
tpool::destroy tpool
Destruye el grupo de hilos de trabajo especificado por tpool. Todos los hilos de trabajo en el grupo se terminan y se liberan los recursos asociados. Si el grupo de hilos de trabajo especificado no se encuentra, se lanzará un error Tcl.
tpool::post tpool script ?arg ...?
Publica un nuevo trabajo en el grupo de hilos de trabajo tpool. El script es el comando Tcl que se ejecutará en un hilo de trabajo. Los arg ... son los argumentos que se pasarán al script. El comando devuelve un identificador de trabajo que se puede utilizar para rastrear el estado del trabajo.
tpool::send tpool script ?arg ...?
Envía un nuevo trabajo al grupo de hilos de trabajo tpool. El comportamiento es similar a tpool::post, pero tpool::send espera a que el trabajo se complete antes de devolver el control. Esto se logra mediante el uso de un evento Tcl para señalar la finalización del trabajo.
tpool::cancel tpool jobid
Cancela un trabajo específico identificado por jobid. Si el trabajo ya se ha iniciado, no se puede garantizar la cancelación. Si el trabajo no se encuentra o ya se ha completado, se lanzará un error Tcl.
tpool::stat tpool
Devuelve estadísticas sobre el grupo de hilos de trabajo especificado tpool. Las estadísticas incluyen el número de hilos de trabajo activos, el número de trabajos en cola y el número total de trabajos completados. Si el grupo de hilos de trabajo especificado no se encuentra, se lanzará un error Tcl.
tpool::workers tpool
Devuelve una lista de los identificadores de los hilos de trabajo activos en el grupo tpool.
tpool::jobs tpool
Devuelve una lista de los identificadores de los trabajos pendientes de ejecución en el grupo tpool.
tpool::results tpool ?jobid?
Devuelve los resultados de los trabajos completados. Si se proporciona jobid, devuelve el resultado de ese trabajo específico. Si no se proporciona jobid, devuelve una lista de los resultados de todos los trabajos completados. Si el trabajo especificado no se encuentra o no se ha completado, se lanzará un error Tcl.
tpool::preserve tpool
Cada llamada a este comando incrementa en uno (1) el contador de referencias del grupo de hilos de trabajo tpool. El comando devuelve el valor del contador de referencias después del incremento. Al incrementar el contador de referencias, el llamante indica que desea utilizar el recurso durante un período de tiempo más largo.
tpool::release tpool
Cada llamada a este comando decrementa en uno (1) el contador de referencias del grupo de hilos de trabajo tpool. El comando devuelve el valor del contador de referencias después del decremento. Cuando el contador de referencias llega a cero (0), el grupo de hilos de trabajo tpool se marca para su terminación. No se debe hacer referencia al grupo de hilos de trabajo después de que el comando tpool::release devuelva cero. El manejador tpool sale del ámbito y no debe utilizarse más. Cualquier referencia posterior al mismo manejador de grupo de hilos de trabajo provocará un error de Tcl.
tpool::suspend tpool
Suspende el procesamiento de trabajo en esta cola. Todos los trabajadores del grupo se pausan, pero se puede añadir trabajo adicional al grupo. Tenga en cuenta que la adición de trabajo adicional no aumentará el número de trabajadores dinámicamente, ya que el procesamiento del grupo está suspendido. El número de trabajadores se mantiene en el recuento que se encontró antes de suspender la actividad de los trabajadores. Si necesita asegurar un cierto número de hilos de trabajo, utilice la opción minworkers del comando tpool::create.
tpool::resume tpool
Reanuda el procesamiento de trabajo en esta cola. Todos los trabajadores pausados (suspendidos) son libres de obtener trabajo del grupo. Tenga en cuenta que reanudar la operación del grupo simplemente permitirá que los trabajadores ya creados continúen. No creará hilos de trabajo adicionales para manejar el trabajo publicado en la cola de trabajo del grupo.

DISCUSION

El grupo de hilos de trabajo es uno de los paradigmas de hilos más comunes cuando se trata de aplicaciones de servidor que manejan un gran número de tareas relativamente pequeñas. Un modelo muy simplista para construir una aplicación de servidor sería crear un nuevo hilo cada vez que llega una solicitud y atender la solicitud en el nuevo hilo. Una de las desventajas de este enfoque es que la sobrecarga de la creación de un nuevo hilo para cada solicitud es significativa; un servidor que creara un nuevo hilo para cada solicitud pasaría más tiempo y consumiría más recursos del sistema en la creación y destrucción de hilos que en el procesamiento de solicitudes reales de usuarios. Además de la sobrecarga de la creación y destrucción de hilos, los hilos activos consumen recursos del sistema. La creación de demasiados hilos puede hacer que el sistema se quede sin memoria o que se produzca un "trashing" (intercambio excesivo entre memoria y disco) debido al consumo excesivo de memoria.

Un grupo de hilos de trabajo ofrece una solución tanto al problema de la sobrecarga del ciclo de vida del hilo como al problema del "trashing" de recursos. Al reutilizar hilos para múltiples tareas, la sobrecarga de la creación de hilos se distribuye entre muchas tareas. Como beneficio adicional, debido a que el hilo ya existe cuando llega una solicitud, se elimina el retraso introducido por la creación de hilos. Por lo tanto, la solicitud puede ser atendida inmediatamente. Además, al ajustar adecuadamente el número de hilos en el grupo de hilos de trabajo, también se puede eliminar el "trashing" de recursos al forzar a cualquier solicitud a esperar hasta que un hilo esté disponible para procesarla.
