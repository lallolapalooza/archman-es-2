tpm2_pcrextend(1) Manual de Comandos Generales tpm2_pcrextend(1)

NOMBRE

tpm2_pcrextend(1) - Extiende un PCR.

SINOPSIS

tpm2_pcrextend [OPCIONES] ESPECIFICACION_DIGEST_PCR

DESCRIPCIÓN

tpm2_pcrextend(1) - Extiende los PCRs con los valores indicados por ESPECIFICACION_DIGEST_PCR.

Una ESPECIFICACION_DIGEST_PCR se define de la siguiente manera:

•
Un identificador numérico de PCR.
•
Dos puntos seguidos de la especificación del hash del algoritmo.

La especificación del hash del algoritmo es la siguiente: * El nombre amigable del algoritmo o el número numérico bruto. * Un signo igual. * El valor hash en hexadecimal.

Ejemplo de especificación de digest

4:sha1=f1d2d2f924e986ac86fdf7b36c94bcdf32beec15

Nota: Se permiten múltiples especificaciones de PCR y hash. Múltiples hashes hacen que el PCR se extienda con ambos hashes. Múltiples valores de PCR iguales hacen que el PCR se extienda varias veces. La extensión se realiza en orden de izquierda a derecha, según lo especificado. Se admiten como máximo 5 extensiones de hash por entrada de PCR. Esto es para mantener el analizador simple.

OPCIONES

Esta herramienta no acepta opciones específicas de la herramienta.

•
-h, --help=[man|no-man]: Muestra el manual de la herramienta. Por defecto, intenta invocar el visor de manuales para la herramienta, sin embargo, en caso de fallo mostrará un breve resumen de la herramienta. Este es el mismo comportamiento si se especifica el argumento de opción "man", sin embargo, si se solicita explícitamente "man", la herramienta proporcionará errores de man en stderr. Si se especifica la opción "no-man", o si falla el visor de manuales, las opciones cortas se mostrarán en stdout.

Para utilizar correctamente la función de manuales se requiere que los manuales estén instalados o en MANPATH. Consulte man(1) para más detalles.

•
-v, --version: Muestra la información de versión de esta herramienta, tctis compatibles y sale.
•
-V, --verbose: Aumenta la información que la herramienta imprime en la consola durante su ejecución. Al usar esta opción, se imprime el archivo y el número de línea.
•
-Q, --quiet: Silencia la salida normal de la herramienta a stdout.
•
-Z, --enable-errata: Habilita la aplicación de correcciones de erratas. Útil si se necesita aplicar una corrección de errata a los comandos enviados al TPM. Definir la variable de entorno TPM2TOOLS_ENABLE_ERRATA es equivalente.

-R, --autoflush: Habilita el autoflush para objetos transitorios creados por el comando. Si un objeto padre se carga desde un archivo de contexto, el objeto padre transitorio también se vaciará. Configuración de TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre tiene precedencia sobre la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Utilizado al comunicarse directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo soportan darán un error cuando se intenten usar sin una conexión TCTI. No soporta NINGUNA opción y DEBE presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para <nombre-tcti> o <config-opciones-tcti> resulta en el uso del valor predeterminado para esa parte respectivamente.

Valores predeterminados de TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI de tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor bruto de tcti-name se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entendido por la semántica de dlopen(3).

OPCIONES DE TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres TPM a utilizar por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter ','. Cada cadena de clave y valor están separadas por un carácter '='.
•
El TCTI abrmd soporta dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia dbus (una cadena) limitada a 'session' y 'system'.

Especificar el nombre TCTI de tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especificar el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos.

Especificadores de bancos de PCR

EJEMPLOS

Extender el banco SHA1 del PCR 4 con un hash

tpm2_pcrextend 4:sha1=f1d2d2f924e986ac86fdf7b36c94bcdf32beec15

Extender el PCR 4 con m

tpm2_pcrextend 4:sha1=f1d2d2f924e986ac86fdf7b36c94bcdf32beec15 \
          sha256=f7bc83f430538424b13298e6aa6fb143ef4d5de16d85578731ad83e3fb0f45a4

Extender el PCR 4 con dos hashes

tpm2_pcrextend 4:sha1=f1d2d2f924e986ac86fdf7b36c94bcdf32beec15 \
          sha256=f7bc83f430538424b13298e6aa6fb143ef4d5de16d85578731ad83e3fb0f45a4

Extender el PCR 4 con dos hashes y luego el PCR 5 con un hash

tpm2_pcrextend 4:sha1=f1d2d2f924e986ac86fdf7b36c94bcdf32beec15 \
          sha256=f7bc83f430538424b13298e6aa6fb143ef4d5de16d85578731ad83e3fb0f45a4 \
          5:sha1=f1d2d2f924e986ac86fdf7b36c94bcdf32beec15
