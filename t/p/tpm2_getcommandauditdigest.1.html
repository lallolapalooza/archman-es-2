NOMBRE

tpm2_getcommandauditdigest(1) - Recupera los datos de atestación de auditoría de comandos del TPM.

SINOPSIS

tpm2_getcommandauditdigest [OPCIONES]

DESCRIPCIÓN

tpm2_getcommandauditdigest(1) - Recupera los datos de atestación de auditoría de comandos del TPM. Los datos de atestación incluyen el resumen de auditoría de los comandos en el conjunto configurado mediante el comando tpm2_setcommandauditstatus. Los datos de atestación también incluyen el resumen de la lista de comandos configurados para auditoría. El algoritmo del resumen de auditoría se configura en tpm2_setcommandauditstatus.

OPCIONES

•
-P, --hierarchy-auth=AUTH:

Especifica el valor de autorización para la jerarquía de respaldo (endorsement).

•
-c, --key-context=OBJETO:

Objeto de contexto para la clave de firma que firma los datos de atestación.

•
-p, --auth=AUTH:

Especifica el valor de autorización para la clave indicada por la opción -c.

•
-q, --qualification=CADENA_HEX_O_RUTA:

Datos proporcionados como una cadena hexadecimal o un archivo binario para calificar la cita (quote), opcional. Esto se utiliza típicamente para añadir un nonce contra ataques de repetición.

•
-s, --signature=ARCHIVO:

Archivo de salida de la firma, registra la firma en el formato especificado mediante la opción -f.

•
-m, --message=ARCHIVO:

Archivo de salida del mensaje, registra el mensaje de cita que compone los datos que son firmados por el TPM. Estos son los datos de atestación del resumen de auditoría de comandos.

•
-f, --format=FORMATO:

Selección del formato para el archivo de salida de la firma.

•
-g, --hash-algorithm:

Algoritmo de hash para la firma. Por defecto es sha256.

•
--scheme=ALGORITMO:

El esquema de firma utilizado para firmar el mensaje. Opcional. Los esquemas de firma deben seguir los "estándares de formato", ver sección "Especificadores de Algoritmos". También, ver sección "Esquemas de Firma Soportados" para una lista de esquemas de firma soportados. Si se especifica, el esquema de firma debe coincidir con el tipo de clave. Si se deja sin especificar, se utilizará un esquema de firma predeterminado para el tipo de clave.

Referencias

Formato de Objeto de Contexto

El tipo de un objeto de contexto, ya sea un manejador (handle) o un nombre de archivo, se determina de acuerdo con la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio del TPM restaurado.
•
Si el argumento coincide como prefijo con uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un manejador (handle), por ejemplo, 0x81010013 y se usará directamente. *OBJETO*.

Formato de Autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autorizaciones tienen como valor predeterminado la CONTRASEÑA VACÍA cuando no se especifican."

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación utilizando identificadores de prefijo.

Nota: Por defecto, se asume que las contraseñas están en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña en formato de cadena, especificada con el prefijo "str:" o su ausencia (cadena en bruto sin prefijo) no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña en formato de cadena hexadecimal, especificada con el prefijo "hex:", se convierte de forma hexadecimal a formato de arreglo de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o incompatibles con la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada con el prefijo "file:", debe ser la ruta de un archivo que contenga la contraseña que será leída por la herramienta o un "-" para usar la entrada estándar (stdin). Almacenar contraseñas en archivos evita fugas de información; las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de funciones comunes del historial del shell.

Ejemplos

# para usar stdin y ser solicitado
file:-
# para usar un archivo de una ruta
file:ruta/al/archivo/de/contraseña
# para enviar una contraseña vía stdin:
echo foobar | tpm2_tool -p file:-
# para usar una cadena de bash vía stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego indique la ruta a un archivo de sesión que fue creado con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autorización para ser enviado con el manejador de sesión (ej. política de contraseña), entonces añada un + y una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones de PCR

Puede satisfacer una política de PCR utilizando el prefijo "pcr:" y el minilenguaje de PCR. El minilenguaje de PCR es el siguiente: <espec-pcr>=<archivo-pcr-crudo>

La especificación de PCR se documenta en la sección "Especificadores de banco de PCR".

El archivo-pcr-crudo es un argumento opcional que contiene la salida de los contenidos crudos del PCR tal como los devuelve tpm2_pcrread(1).

Especificadores de banco de PCR

Ejemplos

Para satisfacer una política de PCR de sha256

NAME

tpm2_getcommandauditdigest - get the digest of commands executed by the TPM.

SYNOPSIS

tpm2_getcommandauditdigest [OPTIONS]

DESCRIPTION

The tpm2_getcommandauditdigest command is used to get the digest of commands executed by the TPM. This command is part of the tpm2-tools suite, which provides a set of tools for managing and interacting with the Trusted Platform Module (TPM).

OPTIONS

In addition to the common options, the following options are supported:

-c, --context=FILE
The context file for the primary key used to authorize the command. This file is generated by a previous invocation of a tpm2_tools command.
-P, --auth=AUTH
The authorization policy for the primary key. This can be a password or the hex string of a policy digest.
-p, --parent-auth=AUTH
The authorization policy for the parent key.
-m, --output=FILE
The file to write the digest to. The default is stdout.
-s, --signature=FILE
The file to write the signature to. The default is to not write a signature.

Context Object Format

The context object format is determined by the tool that created the context file. For tools that produce context objects, the format is typically a JSON formatted file containing the handle, name, and possibly other metadata associated with the object.

The following context object formats are supported:

tpm2:
The default context object format. This is a JSON object containing the following fields:
handle
The handle of the object.
name
The Name of the object.
type
The type of the object.
authValue
The authorization value of the object.
policy
The policy associated with the object.
fsapi:
The fsapi context object format is used by the fsapi-tpm2-tools. This format is a simple binary blob containing the TPM2B_CONTEXT structure.
json:
The json context object format is a JSON object containing the following fields:
object
The handle of the object.
name
The Name of the object.
type
The type of the object.
authValue
The authorization value of the object.
policy
The policy associated with the object.

To specify the context object format, use the --context-format option.

--context-format=FORMAT
Specify the context object format. Supported formats are tpm2, fsapi, and json. The default is tpm2.

Example of context object format

To specify the context object format as fsapi:

--context-format=fsapi

Authorization Formatting

The authorization formatting options are used to specify how authorization values are provided to the tools. The tools support both password-based authorization and policy-based authorization.

The following authorization formatting options are supported:

-P, --auth=AUTH
The authorization value for the object. This can be a password, a hex string, or a policy digest. The format of AUTH depends on the type of authorization.

Password Authorization

If the object is protected by a password, the password can be provided directly as the AUTH value. For example:

--auth=mypassword

If the password contains special characters or spaces, it should be quoted.

Hex Authorization

The authorization value can also be provided as a hex string. This is useful for authorization values that cannot be represented as plain text.

--auth=0x1234567890abcdef

Policy Authorization

If the object is protected by a policy, the policy digest can be provided as the AUTH value. The policy digest should be a hex string prefixed with '0x'.

--auth=0xdeadbeef0123456789abcdef

The specific policy digest to use is determined by the policy created with `tpm2_createpolicy`.

Applying Policy To PCRs

The tpm2_pcrread tool can be used to read the values of PCRs (Platform Configuration Registers). To apply a policy to specific PCRs, use the --pcr-input option with a comma-separated list of PCRs and their hashes.

For example, to apply a policy to PCRs 0, 1, 2 and 3 using SHA-256 hashes:

pcr:sha256:0,1,2,3

This specifies that the policy should be based on the SHA-256 hashes of PCRs 0, 1, 2, and 3. The tool will then compute the policy digest based on these PCR values.

This option is used in conjunction with the --policy-pcr option when creating a policy.

The -P option can also be used to specify the authorization policy when used in conjunction with PCRs. For example:

pcr:sha256:0,1,2,3

specifying AUTH.

Signature Format Specifiers

Format selection for the signature output file. tss (the default) will output a binary blob according to the TPM 2.0 specification and any potential compiler padding. The option plain will output the plain signature data as defined by the used cryptographic algorithm. signature FORMAT.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

tpm2_getcommandauditdigest -P ekpass -c key.ctx -p keypass -m att.data -s att.sig
