tpm2_policyrestart(1) Manual de comandos generales tpm2_policyrestart(1)

NOMBRE

tpm2_policyrestart(1) - Reinicia una sesión existente con el TPM.

SINOPSIS

tpm2_policyrestart [OPCIONES]

DESCRIPCIÓN

tpm2_policyrestart(1) - Reinicia una sesión con el TPM a su estado inicial. Esto es útil cuando el TPM devuelve un código de error TPM_RC_PCR_CHANGED (0x00000128) al usar una sesión de política PCR.

Esto se devolverá si un estado de PCR que afecta a la política se altera durante la sesión. Uno podría reiniciar la sesión e intentarlo de nuevo, sin embargo, el estado de PCR aún tendría que satisfacer la política.

OPCIONES

•
-S, --session=ARCHIVO:

Opcional, un archivo de sesión de la opción -S de tpm2_startauthsession(1). Esta sesión se utiliza en lugar de iniciar una sesión y usar las opciones de política PCR.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará el comando, simplemente devolverá un cpHash.

Configuración de TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Utilizado al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo soportan generarán un error cuando se intenten usar sin una conexión TCTI. No admite *NINGUNA* opción y *DEBE* presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o el <config-opciones-tcti> resulta en el uso del valor predeterminado para esa porción respectivamente.

Valores predeterminados de TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim **EN ESE ORDEN** y **USARÁN EL PRIMERO QUE ENCUENTREN**. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados anteriormente es el predeterminado.

TCTIs Personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica puede cargarse. Las herramientas utilizan internamente dlopen(3), y el valor bruto tcti-name se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entienda la semántica de dlopen(3).

OPCIONES DE TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres TPM para su uso por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter `,'. Cada clave y cadena de valor están separadas por un carácter `=’.
•
El TCTI abrmd admite dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia de dbus (una cadena) limitada a `session' y `system'.

Especifica el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifica el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

Inicia una sesión de política y la reinicia, desempaquetando algunos datos.

En este ejemplo se utiliza tpm2_policysecret(1) para un objeto de política y la sesión de política se mantiene en un archivo.

tpm2_policypassword -S session.bin -P my_password

NAME

tpm2_policyrestart — restart a policy session.

SYNOPSIS

tpm2_policyrestart [-S session | -Q] [-f] [-r] [-l] [-m policy_digest] [-t policy_ticket] [-o policy_out_digest] [-h]

DESCRIPTION

tpm2_policyrestart clears the policy state of an already established policy session.

The intent of tpm2_policyrestart is to clear the policy state of an already established policy session to the initial state, thereby allowing the policy to be re-evaluated.

This command is useful when a PCR event occurs during the evaluation of a policy session. If the event causes the PCR value to change, the policy session will fail to evaluate. tpm2_policyrestart allows the session to be reset to its initial state, enabling the policy to be re-evaluated with the new PCR values.

Note that tpm2_policyrestart does not allow access to objects that are normally restricted by the policy. If an object is tied to a policy, and the policy session is restarted, access to that object will still be denied until the policy is met again.

OPTIONS

-S session
Policy session hex-string or path to the session file. This option is mutually exclusive with -Q.
-Q
Use the default policy session. This option is mutually exclusive with -S.
-f
Clear the policy digest to the initial state. This is the default behavior.
-r
Clear the policy digest and replace it with the policyOR digest. This allows objects bound by policies to be accessed if any of the branches of the policy OR are met.
-l
Clear the policy digest and replace it with the policyAND digest. This requires all branches of the policy AND to be met.
-m policy_digest
Replace the policy digest with the provided digest. This can be useful for custom policy management.
-t policy_ticket
Replace the policy digest with the one derived from the provided ticket. This is used in conjunction with tpm2_policyticket(1).
-o policy_out_digest
Outputs the policy digest after the restart operation. This can be useful for debugging or for use in subsequent policy commands.
-h
Help message.

COMMON OPTIONS

These options are common to all tpm2 commands.

-f file
The TCTI module to use. The primary TCTI is the device(the TPM) and then the TCTI used for communication with the TPM.
-t tcti
The TCTI string to use.
-c context
The TPM context file to use. A TPM context is used to store state information about the TPM, allowing for more complex operations.

TCTI Configuration

The TPM communication is handled by the TCTI (Tabernacle Communication Interface) module. The default TCTI is `mssim` which is the Microsoft simulator. Other TCTI options include:

device
Connect to the TPM device via /dev/tpm0.
socket
Connect to a remote TPM simulator via a socket.
libtsp
Connect to a TPM via the libtsp library.

The TCTI configuration can be specified via the TPM2_TCTI_CONFIG environment variable or the -t command-line option.

TCTI OPTIONS

The following options are used to configure the TCTI:

-t tcti
The TCTI module to use. This can be one of the following:
device: Connect to the TPM device. This option can be specified as device:filename=/dev/tpm0.
socket: Connect to a remote TPM simulator. This option can be specified as socket:host=127.0.0.1,port=2321.
libtsp: Connect to a TPM via the libtsp library. This option can be specified as libtsp:host=127.0.0.1,port=2321.

EXAMPLES

This example demonstrates how to use tpm2_policyrestart to reset a policy session after a PCR event has occurred.

# create a policy and bind it to an object
tpm2_startauthsession -S session.dat
tpm2_policypcr -S session.dat -l "sha1:0,1,2,3" -L policy.dat
tpm2_createprimary -c primary.ctx
tpm2_create -Cprimary.ctx -u key.pub -r key.priv -L policy.dat -i- <<< "secret"
tpm2_load -C primary.ctx -c key.ctx -u key.pub -r key.priv
tpm2_flushcontext session.dat
# satisfy the policy and use the object
tpm2_startauthsession --policy -S session.dat
tpm2_policypcr -S session.dat -l "sha1:0,1,2,3"
# PCR event occurs here causing unseal to fail
tpm2_pcrevent 0 <<< "event data"
tpm2_unseal -psession:session.dat -c key.ct
ERROR: Esys_Unseal(0x128) - tpm:error(2.0): PCR have changed since checked
# Clear the policy digest to initial state, note access to object no longer allowed by
# policy so policyor would be useful here.
tpm2_policyrestart -S session.dat

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

tpm2_policyrestart expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
