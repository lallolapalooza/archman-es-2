tpm2_policynvwritten(1) Manual de Comandos Generales tpm2_policynvwritten(1)

NOMBRE

tpm2_policynvwritten(1) - Restringe la autorización del objeto TPM al estado escrito de un índice NV.

SINOPSIS

tpm2_policynvwritten [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_policynvwritten(1) - Restringe la autorización del objeto TPM al estado escrito de un índice NV. Útil al crear índices NV de escritura única.

Como [ARGUMENTO] toma el estado escrito esperado del índice NV. Puede especificarse como s|c|0|1.

OPCIONES

•
-S, --session=ARCHIVO:

Un archivo de sesión de la opción -S de tpm2_startauthsession(1).

•
-L, --policy=ARCHIVO:

Archivo para guardar el digest de la política.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash.

Configuración TCTI

El TCTI o "Transmission Interface" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre tiene prioridad sobre la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Utilizado cuando se habla directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo soportan darán error cuando se intenten usar sin una conexión TCTI. No soporta *NINGUNA* opción y *DEBE* presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para <nombre-tcti> o <config-opciones-tcti> da como resultado el uso del valor predeterminado para esa parte respectivamente.

Valores Predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI de tabrmd, device y mssim **EN ESE ORDEN** y **USARÁN EL PRIMERO** **QUE ENCUENTREN**. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs Personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica puede cargarse. Las herramientas internamente usan dlopen(3), y el valor crudo de nombre-tcti se usa para la búsqueda. Por lo tanto, podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entiendan las semánticas de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de carácter TPM para su uso por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter `,`. Cada clave y valor se separan por un carácter `=`.
•
TCTI abrmd soporta dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia dbus (una cadena) limitado a `session' y `system'.

Especifique el nombre TCTI abrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifique el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

**NOTA**: abrmd y tabrmd son sinónimos. los varios módulos TCTI conocidos.

tpm2_policynvwritten(1)

NAME

tpm2_policynvwritten - Set a policy for the NV index that requires the NV index to be written.

SYNOPSIS

tpm2_policynvwritten [OPTIONS] [POLICY_FILE]

DESCRIPTION

This command is used to define a policy that requires that an NV Index has been written. This policy is used to limit the commands that can be executed. For example, one may want to limit the write operation on a specific NV index to only be allowed if the index has been previously written. This policy is evaluated when it is passed to a command that accepts policy sessions.

The policy set by this command is: that the NV index has been written. This is checked by the TPM via the TPM2_PolicyNVWritten command. This command can be used to create a policy that can be used in conjunction with other policy commands or used as a standalone policy to dictate conditions on NV index operations.

The policy command code for the NV write operation will also need to be set.

OPTIONS

The following options are available:

-L, --policy policy file

Save the policy digest into the file specified by policy file. The policy digest is calculated as specified in the TPM 2.0 specification document.

-c, --create

This option is used to create a policy for the NV index that requires the NV index to be written. This option requires that the session used is a policy session.

-S, --session session file

The policy session file created by tpm2_startauthsession(1). If not specified, the session file will be read from the default location, or it will be created if it does not exist.

COMMON OPTIONS

See tpm2_options(7) for common options that can be used with this command.

TCTI Configuration

See tpm2_tcti(7) for common TCTI configurations.

TCTI OPTIONS

See tpm2_tcti(7) for common TCTI options.

EXAMPLES

To define a policy for the NV index that requires the NV index to be written, we first need to define the policy. The policy is defined by setting the command code for NV Write and then setting the policy for NV written. This policy will only be met if the NV index has been written. The policy file, nvwrite.policy, will contain the policy digest.

First, define the policy for the NV index write operation:

tpm2_startauthsession -S session.dat
tpm2_policycommandcode -S session.dat TPM2_CC_NV_Write
tpm2_policynvwritten -S session.dat -L nvwrite.policy
tpm2_flushcontext session.dat

Next, define the NV index with the policy that was just created. The policywrite attribute is set so that the policy defined by nvwrite.policy must be satisfied before any write operation can be performed on the NV index. The policydigest is specified by the -L option. The policydigest is tied to the NV index and will be evaluated when the NV index is written.

tpm2_nvdefine -s 1 -a "authread|policywrite" -p nvrdpass -L nvwrite.policy

Finally, to write to the NV index, the policy must be satisfied. This is done by first starting a session, setting the command code for NV Write, and then executing the NV Write command. The policy session is used to satisfy the policy. The policy is satisfied if the NV index has been written.

tpm2_startauthsession -S session.dat --policy-session
tpm2_policycommandcode -S session.dat TPM2_CC_NV_Write
tpm2_policynvwritten -S session.dat
echo 0xAA | xxd -r -p | tpm2_nvwrite 0x01000000 -i- -P session:session.dat
tpm2_flushcontext session.dat

The above example demonstrates how to satisfy the policy by writing to the NV index. The first time the policy is evaluated, the NV index has not yet been written. Therefore, the policy will fail. The NV index can only be written if the policy is satisfied. After the NV index has been written, the policy can be satisfied.

Note that the -c option is used with tpm2_policynvwritten to indicate that this is a policy for the NV index to be written. The policy file will contain the policy digest that will be used to verify that the NV index has been written. The policy will be associated with the NV index and will be evaluated when the NV index is written.

The following example shows how to define a policy that requires the NV index to be written. The policy is created using the -c option, which specifies that the policy should be created for the NV index write operation. The policy digest is saved to the file nvwrite.policy.

tpm2_startauthsession -S session.dat
tpm2_policycommandcode -S session.dat TPM2_CC_NV_Write
tpm2_policynvwritten -S session.dat -c -L nvwrite.policy
tpm2_flushcontext session.dat

Then, define the NV index with the policy:

tpm2_nvdefine -s 1 -a "authread|policywrite" -p nvrdpass -L nvwrite.policy

Now, to write to the NV index, you must satisfy the policy. This means that the NV index must have been written previously. The following command will attempt to write to the NV index. If the NV index has not been written, the command will fail. If the NV index has been written, the command will succeed.

tpm2_startauthsession -S session.dat --policy-session
tpm2_policycommandcode -S session.dat TPM2_CC_NV_Write
tpm2_policynvwritten -S session.dat
echo 0xAA | xxd -r -p | tpm2_nvwrite 0x01000000 -i- -P session:session.dat
tpm2_flushcontext session.dat

In this example, the first time the NV index is written, the policy will not be satisfied, and the command will fail. However, subsequent writes will succeed because the policy will be satisfied. This is because the policy requires that the NV index has been written, and once it has been written, the policy is satisfied. D; was never set.

Define the NV index write policy

tpm2_startauthsession -S session.dat
tpm2_policycommandcode -S session.dat TPM2_CC_NV_Write
tpm2_policynvwritten -S session.dat -L nvwrite.policy
tpm2_flushcontext session.dat

Define the NV index with the policy

 tpm2_nvdefine -s 1 -a "authread|policywrite" -p nvrdpass -L nvwrite.policy

Write the NV index by satisfying the policy

tpm2_startauthsession -S session.dat --policy-session
tpm2_policycommandcode -S session.dat TPM2_CC_NV_Write
tpm2_policynvwritten -S session.dat
echo 0xAA | xxd -r -p | tpm2_nvwrite 0x01000000 -i- -P session:session.dat
tpm2_flushcontext session.dat

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
