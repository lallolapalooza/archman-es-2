tpm2_createek(1) Manual de Comandos Generales tpm2_createek(1)

NOMBRE

tpm2_createek(1) - Genera una clave de respaldo (EK) compatible con el perfil TCG.

SINOPSIS

tpm2_createek [OPCIONES]

DESCRIPCIÓN

tpm2_createek(1) - Genera una clave de respaldo (EK) compatible con el perfil TCG, que es el objeto primario de la jerarquía de respaldo.

Si se genera un objeto transitorio, la herramienta genera un archivo de contexto especificado con -c.

Consultar: http://www.trustedcomputinggroup.org/files/static_page_files/7CAA5687-1A4B-B294-D04080D058E86C5F

OPCIONES

•
-P, --eh-auth=AUTH:

El valor de autorización para la jerarquía de respaldo.

•
-w, --owner-auth=AUTH

El valor de autorización para la jerarquía del propietario.

•
-c, --ek-context=OBJECT o FILE:

Una ruta de archivo o un valor de identificador persistente para guardar la clave de respaldo.

Si se pasa un valor de -, la herramienta encontrará un identificador persistente libre para usar e imprimirá el identificador seleccionado automáticamente.

Si se guarda el archivo de contexto a través de esta opción y la clave pública a través de la opción -u, la EK se puede restaurar mediante una llamada a tpm2_loadexternal(1).

•
-G, --key-algorithm=ALGORITHM:

El algoritmo de la clave de respaldo. Admite:

•
ecc - Una clave NIST_P256 por defecto. Se pueden seleccionar curvas alternativas usando especificadores de algoritmo (por ejemplo, ecc384 o ecc_nist_p384).
•
rsa - Una clave RSA2048.
•
keyedhash - clave hmac.
•
-u, --public=FILE:

La entrada opcional para un archivo donde guardar la porción pública de la clave de respaldo.

•
-t, --template:

La plantilla de clave de respaldo definida por el fabricante y el nonce opcionales de los índices NV fijos para poblar el área pública TPM2B_PUBLIC. Consulte la especificación del perfil de credenciales EK de TCG para obtener más información: https://trustedcomputinggroup.org/wp-content/uploads/ TCG_IWG_Credential_Profile_EK_V2.1_R13.pdf

•
-f, --format:

Selección de formato para el archivo de salida de la clave pública. `tss' (el valor predeterminado) generará un blob binario según la Especificación TPM 2.0. `pem' generará una clave pública codificada en PEM compatible con OpenSSL. `der' generará una clave pública codificada en DER compatible con OpenSSL. `tpmt' generará un blob binario de la estructura TPMT_PUBLIC referenciada en las especificaciones TPM 2.0.

Formato de la clave pública.

Referencias

Formato de Objeto de Contexto

El tipo de un objeto de contexto, ya sea un identificador o un nombre de archivo, se determina según la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio TPM restaurado.
•
Si el argumento es una coincidencia de *prefijo* en uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento se puede cargar como un número, se tratará como un identificador, por ejemplo, 0x81010013 y se utilizará directamente.*_OBJECT_.

Formato de Autorización

La autorización para el uso de un objeto en TPM2.0 puede provenir de 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: Las autorizaciones se establecen como la CONTRASEÑA VACÍA por defecto cuando no se especifican.

Contraseñas

Las contraseñas se interpretan en las siguientes formas utilizando prefijos identificadores.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña en formato de cadena, especificada por el prefijo "str:" o su ausencia (cadena sin prefijo), no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena hexadecimal

Una contraseña en formato de cadena hexadecimal, especificada por el prefijo "hex:", se convierte de forma hexadecimal a un array de bytes, lo que permite contraseñas con caracteres no imprimibles y/o no amigables con la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo "file:", debe ser la ruta de un archivo que contenga la contraseña que será leída por la herramienta o un "-" para usar stdin. Almacenar contraseñas en archivos evita la fuga de información; las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las funciones comunes del historial de la shell.

Ejemplos

# para usar stdin y que se solicite la contraseña
file:-
# para usar un archivo de una ruta
file:ruta/al/archivo/contraseña
# para enviar una contraseña vía stdin:
echo foobar | tpm2_tool -p file:-
# para usar una here-string de bash vía stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave *session*. Luego indique una ruta a un archivo de sesión que fue creado con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autorización para ser enviado con el identificador de sesión (por ejemplo, contraseña de política), agregue un '+' y una cadena como se describe en la sección de Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización HEX 0x11223344.

session:session.ctx+hex:11223344

La especificación PCR se documenta en la sección "Especificadores de banco PCR".

Especificadores Complejos

Los objetos, cuando se especifican para su creación por el TPM, tienen numerosos algoritmos para poblar en los datos públicos. Cosas como el tipo, esquema y detalles asimétricos, tamaño de clave, etc. A continuación se muestra el formato general para especificar estos datos: <tipo>:<esquema>:<detalles-simétricos>

Especificadores de Tipo

Esta parte del especificador de algoritmo complejo es obligatoria. El resto de detalles de esquema y simétricos se establecerán por defecto según el tipo especificado y el tipo del objeto que se está creando.

•
aes - AES por defecto: aes128
•
aes128<modo> - AES de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, por defecto es null.
•
aes192<modo> - Igual que aes128<modo>, excepto por un tamaño de clave de 192 bits.
•
aes256<modo> - Igual que aes128<modo>, excepto por un tamaño de clave de 256 bits.
•
sm4 - SM4 por defecto: sm4128
•
sm4128 o sm4_128 <modo> - SM4 de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, por defecto es null.
•
ecc - Curva Elíptica, por defecto es ecc256.
•
ecc192 o ecc_nist_p192 - Curva NIST ECC de 192 bits
•
ecc224 o ecc_nist_p224 - Curva NIST ECC de 224 bits
•
ecc256 o ecc_nist_p256 - Curva NIST ECC de 256 bits
•
ecc384 o ecc_nist_p384 - Curva NIST ECC de 384 bits
•
ecc521 o ecc_nist_p521 - Curva NIST ECC de 521 bits
•
ecc_sm2 o ecc_sm2_p256 - Curva SM2 de 256 bits
•
rsa - RSA por defecto: rsa2048
•
rsa1024 - RSA con tamaño de clave de 1024 bits.
•
rsa2048 - RSA con tamaño de clave de 2048 bits.
•
rsa3072 - RSA con tamaño de clave de 3072 bits.
•
rsa4096 - RSA con tamaño de clave de 4096 bits.

Especificadores de Esquema

A continuación, hay un campo opcional, se puede omitir.

Los esquemas suelen ser **Esquemas de Firma** o **Cifrado Asimétrico** **Esquemas**. La mayoría de los esquemas de firma toman un algoritmo de hash directamente después del esquema de firma. Si falta el algoritmo de hash, por defecto es sha256. Algunos no toman argumentos y otros toman múltiples argumentos.

Este especificador de esquema va seguido de un recuento (tamaño máximo UINT16) seguido de un guión (-) y un algoritmo de hash válido. * ecdaa Por ejemplo, ecdaa4-sha256. Si no se especifica ningún recuento, por defecto es 4.

Especificadores de Esquema sin Opción

Este especificador de esquema NO toma argumentos. * rsaes

Especificadores de Detalles Simétricos

Este campo es opcional y se establece por defecto según el tipo del objeto que se está creando y sus atributos. Generalmente, cualquier especificador **simétrico** válido de la lista **Tipo** **Especificadores** debería funcionar. Si no se especifica, los detalles simétricos de un objeto asimétrico por defecto son aes128cfb.

Ejemplos

Crear una clave rsa2048 con un esquema de cifrado asimétrico rsaes

tpm2_create -C parent.ctx -G rsa2048:rsaes -u key.pub -r key.priv

Crear una clave ecc256 con un esquema de firma ecdaa con un recuento de 4 y hash sha384

/tpm2_create -C parent.ctx -G ecc256:ecdaa4-sha384 -u key.pub -r key.priv algoritmos criptográficos ALGORITMO.

Configuración TCTI

El TCTI o “Interfaz de Transmisión” es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para comunicarse con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Normalmente se utiliza para comunicarse con el simulador de software de TPM.
•
device - Se utiliza al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializa una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo admiten generarán un error cuando se intente usarlas sin una conexión TCTI. No admite NINGUNA opción y DEBE presentarse como el texto exacto de “none”.

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<configuración-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <configuración-opciones-tcti> resulta en que se use el valor predeterminado para esa parte respectivamente.

Valores Predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim **EN ESE ORDEN** y **USARÁN EL PRIMERO QUE ENCUENTREN**. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor “default-tcti” indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor crudo nombre-tcti se utiliza para la búsqueda. Por lo tanto, esta podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entienden las semánticas de dlopen(3).

Opciones TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres del TPM para que lo utilice el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter `,´. Cada clave y valor de cadena están separados por un carácter `=´.
•
El TCTI abrmd admite dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia de dbus (una cadena) limitada a `session' y `system'.

Especifique el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifique el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

Crear una Clave de Respaldo RSA y hacerla persistente

tpm2_createek -P abc123 -w abc123 -c 0x81010001 -G rsa -u ek.pub

Crear una Clave de Respaldo ECC NIST_P384 y hacerla persistente

tpm2_createek -G ecc384 -c 0x81010002

Crear una Clave de Respaldo transitoria, eliminarla y recargarla.

Normalmente, al usar el TPM, las interacciones se realizan a través de un gestor de recursos, como tpm2-abrmd(8). Sin embargo, al interactuar directamente con el TPM, este escenario es posible. El siguiente ejemplo asume acceso directo al TPM no gestionado por un gestor de recursos. Específicamente usaremos /dev/tpm0.

tpm2_createek -c ek.ctx -G rsa -u ek.pub -Tdevice:/dev/tpm0 
# Comprobar que está cargada en memoria transitoria
tpm2_getcap handles-transient -Tdevice:/dev/tpm0 
- 0x80000000
# Eliminar el manejador
tpm2_flushcontext 0x80000000 -Tdevice:/dev/tpm0
# Observar que se ha eliminado
tpm2_getcap handles-transient -Tdevice:/dev/tpm0
<null output>
# Recargarla a través de loadexternal
tpm2_loadexternal -C o -u ek.pub -c ek.ctx -Tdevice:/dev/tpm0
# Comprobar que se ha vuelto a cargar en memoria transitoria
tpm2_getcap handles-transient -Tdevice:/dev/tpm0
- 0x80000000
