tpm2_startauthsession(1) Manual de Comandos Generales tpm2_startauthsession(1)

NOMBRE

tpm2_startauthsession(1) - Iniciar una sesión con el TPM.

SINOPSIS

tpm2_startauthsession [OPCIONES]

DESCRIPCIÓN

tpm2_startauthsession(1) - Inicia una sesión con el TPM. Por defecto, inicia una sesión de *prueba* a menos que se especifique la opción -a. Guarda los datos de la sesión de política en un archivo. Este archivo puede ser utilizado posteriormente por herramientas que puedan usar un archivo de política para autorización o eventos de política.

Esto no funcionará con gestores de recursos (RM) fuera de tpm2-abrmd, ya que la mayoría de los RM eliminarán los identificadores de sesión cuando un cliente se desconecta del canal IPC. Sin embargo, al usar un RM sin la función de "session gapping", se puede usar el comando TCTI para mantener la conexión abierta.

El primer paso es crear un oyente de socket que utilice tpm2_send:

mknod "$HOME/backpipe" p
while [ 1 ]; do tpm2_send 0<"$HOME/backpipe" | nc -lU "$HOME/sock" 1>"$HOME/backpipe"; done;

El siguiente paso es usar el comando TCTI y netcat (nc) para enviar datos al socket.

tpm2_startauthsession --tcti="cmd:nc -q 0 -U $HOME/sock" <opciones>

Al finalizar, asegúrese de matar al oyente. Para los comandos ejecutados con el tcti de comando contra el oyente, necesitará administrar los identificadores transitorios. La forma más sencilla es añadir un `flush` después de cada comando: tpm2_flushcontext --tcti="cmd:nc -q 0 -U $HOME/sock" -t

Nota: Este ejemplo utiliza sockets UNIX, ya que el socket se controla con los controles de acceso de Linux. No se recomienda usar un puerto ya que está expuesto a cualquier usuario del sistema (localhost) o está enlazado a una tarjeta de red y expuesto a la red.

Esto funcionará con acceso directo al TPM, pero ten en cuenta que internamente llama a `ContextSave` y `ContextLoad` en el identificador de sesión, por lo tanto, la sesión **no** se puede guardar/cargar de nuevo.

OPCIONES

•
--policy-session:

Inicia una sesión de política de tipo TPM_SE_POLICY. Por defecto, sin esta opción, es TPM_SE_TRIAL.

NOTA: Una sesión de *prueba* se usa al construir una política y una sesión de *política* se usa al autenticarse con una política.

•
--audit-session:

Inicia una sesión HMAC para ser usada como sesión de auditoría. Por defecto, sin esta opción, es TPM2_SE_TRIAL.

•
--hmac-session:

Inicia una sesión HMAC de tipo TPM_SE_HMAC. Por defecto, sin esta opción, es TPM2_SE_TRIAL.

•
-g, --hash-algorithm=ALGORITMO:

El algoritmo de hash utilizado en el cálculo del resumen de política.

•
-G, --key-algorithm=ALGORITMO:

El algoritmo simétrico utilizado en el cifrado/descifrado de parámetros.

•
-c, --key-context=OBJETO:

Establece los objetos `tpmkey` y `bind` como iguales. El cifrado de parámetros de sesión está activado. El descifrado de parámetros de sesión está activado. La clave simétrica de cifrado/descifrado de parámetros se establece en AES-CFB.

•
-S, --session=ARCHIVO:

El nombre del archivo de sesión de política, requerido.

•
--bind-context=ARCHIVO:

Establece el objeto `bind`. El cifrado de parámetros de sesión está desactivado. Use tpm2_sessionconfig para activarlo. El descifrado de parámetros de sesión está desactivado. Use tpm2_sessionconfig para activarlo. La clave simétrica de cifrado/descifrado de parámetros se establece en AES-CFB.

•
--bind-auth=AUTH:

Establece el valor de autorización para el objeto `bind`.

•
--tpmkey-context=ARCHIVO:

Establece el objeto `tpmkey`. El cifrado de parámetros de sesión está desactivado. Use tpm2_sessionconfig para activarlo. El descifrado de parámetros de sesión está desactivado. Use tpm2_sessionconfig para activarlo. La clave simétrica de cifrado/descifrado de parámetros se establece en AES-CFB.

•
-n, --name=ARCHIVO

Un archivo de nombre como salida de una herramienta como tpm2_readpublic(1) con la opción -n. El archivo de nombre se puede usar para verificar un identificador persistente de entrada para las opciones --tpmkey-context, -c, y --key-context. La verificación de que el objeto referenciado por un identificador persistente, por ejemplo 0x81000000, es la clave esperada previene que los atacantes realicen un ataque man-in-the-middle sobre el tráfico de la sesión.

Referencias

Formato del objeto de contexto

El tipo de un objeto de contexto, ya sea un identificador o un nombre de archivo, se determina según la siguiente lógica, *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio del TPM restaurado.
•
Si el argumento coincide con un *prefijo* de uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un identificador, por ejemplo, 0x81010013, y se usará directamente._OBJETO_.

Formato de autorización

La autorización para usar un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autorizaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas usando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña en formato de cadena, especificada con el prefijo "str:" o su ausencia (cadena en bruto sin prefijo) no se interpreta y se usa directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena hexadecimal

Una contraseña en formato de cadena hexadecimal, especificada con el prefijo "hex:", se convierte de un formato hexadecimal a un formato de arreglo de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o problemáticos para la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo "file:", debe ser la ruta a un archivo que contenga la contraseña a leer por la herramienta o un "-" para usar la entrada estándar. Almacenar contraseñas en archivos evita fugas de información; las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o del historial común del shell.

Nombre

tpm2_tool - TPM2 Tool Interface

SINÓPSIS

tpm2_tool [OPCIONES] [ARGUMENTOS]

DESCRIPCIÓN

This document describes the command line arguments and options supported by the TPM2 Access Broker & Resource Manager (tabrmd) and other TPM2 tools.

Contraseñas

In order to use password protected objects, the tool must be provided with the password. There are several ways to do this.

The most common way is via a file. A file may contain a single password, or it may contain multiple passwords, one per line. The tool will attempt to use the passwords in the file in order, until one succeeds.

Alternatively, a password can be provided via stdin. This is useful when the password is created dynamically, e.g. via a script.

All password options support the following formats:

•
file:[path] - Load password from a file. If the path is not specified, then use stdin.
•
stdin: - Use stdin.
•
hex:[hex string] - A hex string of the password.
•
pass:[password string] - The password string.

Ejemplos

Use a password from a file:

tpm2_tool -p file:./password.txt

Use a password from stdin:

echo foobar | tpm2_tool -p file:-

Use a password from stdin using the stdin: prefix:

echo foobar | tpm2_tool -p stdin:

Use a password defined in the environment variable PASSWORD:

export PASSWORD=foobar
tpm2_tool -p env:PASSWORD

Use a hex encoded password:

tpm2_tool -p hex:666f6f626172

Use a plain password:

tpm2_tool -p pass:foobar

Use a password from a file, using file: with no path, implies stdin:

echo foobar | tpm2_tool -p file:

Use a password from a file, using a bash here-string.

tpm2_tool -p file:- <<< "foobar"

Gestión de Contraseñas

By default, passwords specified on the command line using the -p or --password options are cleared from the command line history. This can be controlled by the TPM2TOOLS_CLEAR_PASSWORD_HISTORY environment variable.

If the environment variable TPM2TOOLS_CLEAR_PASSWORD_HISTORY is set to "no" or "false", then passwords will not be cleared.

If the environment variable TPM2TOOLS_CLEAR_PASSWORD_HISTORY is set to "yes" or "true", or if the variable is not set, then passwords will be cleared.

Sesiones de política y gestión de contraseñas

When using a policy session to authorize the use of an object, prefix the option argument with the session keyword. Then indicate a path to a session file that was created with tpm2_startauthsession(1). Optionally, if the session requires an auth value to be sent with the session handle (eg policy password), then append a + and a string as described in the Passwords section.

Ejemplos

To use a session context file called session.ctx.

session:session.ctx

To use a session context file called session.ctx AND send the authvalue mypassword.

session:session.ctx+mypassword

To use a session context file called session.ctx AND send the HEX authvalue 0x11223344.

session:session.ctx+hex:11223344

To use a session context file called session.ctx AND send the password via stdin.

echo foobar | tpm2_tool --session session.ctx+file:-

Autorizaciones de PCR

You can satisfy a PCR policy using the “pcr:” prefix and the PCR minilanguage. The PCR minilanguage is as follows: <pcr-spec>=<raw-pcr-file>

The PCR spec is documented in in the section “PCR bank specifiers”.

The raw-pcr-file is an optional argument that contains the output of the raw PCR contents as returned by tpm2_pcrread(1).

PCR bank specifiers

Ejemplos

To satisfy a PCR policy of sha256 on banks 0, 1, 2 and 3 use a specifier of:

pcr:sha256:0,1,2,3

specifying AUTH.

OPCIONES COMUNES

This collection of options are common to many programs and provide information that many users may expect.

•
-h, --help=[man|no-man]: Display the tools manpage. By default, it attempts to invoke the manpager for the tool, however, on failure will output a short tool summary. This is the same behavior if the “man” option argument is specified, however if explicit “man” is requested, the tool will provide errors from man on stderr. If the “no-man” option if specified, or the manpager fails, the short options will be output to stdout.

To successfully use the manpages feature requires the manpages to be installed or on MANPATH, See man(1) for more details.

•
-v, --version: Display version information for this tool, supported tctis and exit.
•
-V, --verbose: Increase the information that the tool prints to the console during its execution. When using this option the file and line number are printed.
•
-Q, --quiet: Silence normal tool output to stdout.
•
-Z, --enable-errata: Enable the application of errata fixups. Useful if an errata fixup needs to be applied to commands sent to the TPM. Defining the environment TPM2TOOLS_ENABLE_ERRATA is equivalent.
•
-R, --autoflush: Enable autoflush for transient objects created by the command. If a parent object is loaded from a context file also the transient parent object will be flushed. Autoflush can also be activated if the environment variable TPM2TOOLS_AUTOFLUSH is is set to yes or true. information many users may expect.

Configuración TCTI

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

Valores Predeterminados TCTI

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

TCTIs Personalizados

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

OPCIONES TCTI

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules. # EXAMPLES

Start a trial session and save the session data to a file

tpm2_startauthsession -S mysession.ctx

Start a policy session and save the session data to a file

tpm2_startauthsession --policy-session -S mysession.ctx

Start an encrypted and bound policy session and save the session data to a file

tpm2_createprimary -c primary.ctx
tpm2_startauthsession --policy-session -c primary.ctx -S mysession.ctx

Retornos

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.
