NOMBRE

tpm2_clockrateadjust(1) - Establece el período de la frecuencia del reloj en el TPM.

SINOPSIS

tpm2_clockrateadjust [OPCIONES] AJUSTADOR

DESCRIPCIÓN

tpm2_clockrateadjust(1) - Ajusta la velocidad a la que se actualizan el reloj y el tiempo en el TPM para que coincida mejor con el tiempo real. Sin argumento, se invoca el comando pero no se altera la frecuencia del reloj. Con un argumento, la herramienta ajustará el período del reloj y del tiempo. El comando puede aumentar o disminuir el período del reloj a través de 3 granularidades distintas: gruesa, media y fina. Para especificar esto, el argumento puede ser una cadena de 1 a 3 caracteres de *todos* `s` o `f`.

Argumentos de Ajustador Válidos

•
s - ralentiza el período del reloj un incremento fino.
•
ss - ralentiza el período del reloj un incremento medio.
•
sss - ralentiza el período del reloj un incremento grueso.
•
f - acelera el período del reloj un incremento fino.
•
ff - acelera el período del reloj un incremento medio.
•
fff - acelera el período del reloj un incremento grueso.

OPCIONES

•
-c, --hierarchy=OBJECT:

La jerarquía a utilizar para la autorización, ya sea plataforma o propietario. Por defecto, se utiliza la jerarquía del propietario si no se especifica.

•
-p, --auth=AUTH:

Especifica el valor de autorización para la jerarquía especificada por la opción -c.

•
--cphash=FILE

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un manejador o un nombre de archivo, se determina según la siguiente lógica, *en orden*:

•
Si el argumento es una ruta de archivo, se carga el archivo como un objeto transitorio del TPM restaurado.
•
Si el argumento es una coincidencia de *prefijo* con uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un manejador, por ejemplo, 0x81010013 y se usará directamente._OBJECT_.

Formato de Autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autorizaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación usando identificadores de prefijo.

Nota: Por defecto, se asume que las contraseñas están en forma de cadena cuando no tienen prefijo.

Cadena

Una contraseña en cadena, especificada por el prefijo "str:" o su ausencia (cadena sin prefijo) no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña en cadena hexadecimal, especificada por el prefijo "hex:", se convierte de una forma hexadecimal a una forma de array de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables para la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo "file:", debe ser la ruta de un archivo que contenga la contraseña a leer por la herramienta o un "-" para usar stdin. Almacenar contraseñas en archivos previene la fuga de información, las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las características comunes del historial del shell.

Ejemplos

# para usar stdin y que se le solicite
file:-
# para usar un archivo de una ruta
file:ruta/al/archivo/contraseña
# para enviar una contraseña vía stdin:
echo foobar | tpm2_tool -p file:-
# para usar una cadena aquí de bash vía stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al utilizar una sesión de política para autorizar el uso de un objeto, anteponga al argumento de la opción la palabra clave session. Luego, indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación que se envíe con el manejador de sesión (por ejemplo, contraseña de política), añada un + y una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones PCR

Puede satisfacer una política PCR utilizando el prefijo "pcr:" y el minilenguaje PCR. El minilenguaje PCR es el siguiente: <especificador-pcr>=<archivo-pcr-crudo>

El especificador PCR se documenta en la sección "Especificadores de bancos PCR".

El archivo-pcr-crudo es un argumento opcional que contiene la salida del contenido crudo del PCR tal como lo devuelve tpm2_pcrread(1).

Especificadores de bancos PCR

Ejemplos

Para satisfacer una política PCR de sha256 en los bancos 0, 1, 2 y 3, utilice un especificador de:

pcr:sha256:0,1,2,3

especificando AUTH.

Configuración del TCTI

El TCTI o “Interfaz de Transmisión” es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente se usa para comunicarse con el simulador de software del TPM.
•
device - Se usa cuando se habla directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo admiten darán un error cuando se intenten usar sin una conexión TCTI. No admite *NINGUNA* opción y *DEBE* presentarse como el texto exacto de “none”.

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o el <config-opciones-tcti> resulta en que se use el valor predeterminado para esa parte respectivamente.

Valores Predeterminados del TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim **EN ESE ORDEN** y **USARÁN EL PRIMERO QUE ENCUENTREN**. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor “default-tcti” indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor bruto de tcti-name se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entiendan los semántica de dlopen(3).

OPCIONES DEL TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres del TPM a ser utilizado por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter `,`. Cada clave y valor de cadena están separados por un carácter `=´.
•
El TCTI abrmd admite dos claves:
1.
`bus_name`: El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type`: El tipo de la instancia de dbus (una cadena) limitada a `session` y `system`.

Especificar el nombre del tcti tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especificar el tcti predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

Ajustar el reloj

Reducir la velocidad del reloj en un incremento medio usando la contraseña del propietario.

tpm2_clockrateadjust -p ownerpw ss

Aumentar la velocidad del reloj en un incremento grueso usando la contraseña de plataforma.

tpm2_clockrateadjust -c p -p platformpw fff

Retornos

Las herramientas pueden devolver cualquiera de los siguientes códigos:

•
0 - Éxito.
•
1 - Error general no específico.
•
2 - Error en el manejo de opciones.
•
3 - Error de autenticación.
•
4 - Error relacionado con TCTI.
•
5 - Esquema no soportado. Aplicable a tpm2_testparams.
