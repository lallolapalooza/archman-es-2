tpm2_nvreadpublic(1) Manual de Comandos Generales tpm2_nvreadpublic(1)

NOMBRE

tpm2_nvreadpublic(1) - Muestra todos los índices de Memoria No Volátil (NV) definidos.

SINOPSIS

tpm2_nvreadpublic [OPCIONES]

DESCRIPCIÓN

tpm2_nvreadpublic(1) - Muestra todos los índices de Memoria No Volátil (NV) definidos en la salida estándar en formato YAML.

Muestra metadatos de todos los índices NV definidos. Los metadatos incluyen:

•
El tamaño de la región definida.
•
El algoritmo hash utilizado para calcular el nombre del índice.
•
La política de autorización.
•
Los atributos NV definidos en la sección "Atributos NV".

Ejemplo de Salida

0x1500015:
  hash algorithm:
    friendly: sha256
    value: 0xB
  attributes:
    friendly: ownerwrite|ownerread
    value: 0x2000200
  size: 32
  authorization policy:
0x1500017:
  hash algorithm:
    friendly: sha256
    value: 0xB
  attributes:
    friendly: ownerwrite|ownerread
    value: 0x2000200
  size: 32
  authorization policy:

OPCIONES

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará el comando, simplemente devolverá un cpHash a menos que también se requiera rphash.

•
--rphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros de respuesta. Esto se denomina comúnmente rpHash.

•
-S, --session=SESIÓN_POLÍTICA:

Especifica una sesión auxiliar para auditoría y/o cifrado/descifrado de los parámetros.

•
-n, --name=ARCHIVO:

El nombre del índice NV que debe proporcionarse cuando solo se calcula el cpHash sin enviar realmente el comando al TPM.

OPCIONES COMUNES

Esta colección de opciones son comunes a muchos programas y proporcionan información que muchos usuarios pueden esperar.

•
-h, --help=[man|no-man]: Muestra el manual de la herramienta. Por defecto, intenta invocar el visor de manuales para la herramienta, sin embargo, en caso de fallo, mostrará un resumen corto de la herramienta. Este es el mismo comportamiento si se especifica el argumento de opción "man", sin embargo, si se solicita explícitamente "man", la herramienta proporcionará errores de man en stderr. Si se especifica la opción "no-man", o si el visor de manuales falla, las opciones cortas se mostrarán en stdout.

Para utilizar correctamente la función de manuales, se requiere que los manuales estén instalados o en MANPATH. Consulte man(1) para más detalles.

•
-v, --version: Muestra información de la versión de esta herramienta, los tctis soportados y sale.
•
-V, --verbose: Aumenta la información que la herramienta imprime en la consola durante su ejecución. Cuando se utiliza esta opción, se imprime el nombre del archivo y el número de línea.
•
-Q, --quiet: Silencia la salida normal de la herramienta a stdout.
•
-Z, --enable-errata: Habilita la aplicación de correcciones de erratas. Útil si se necesita aplicar una corrección de erratas a los comandos enviados al TPM. Definir la variable de entorno TPM2TOOLS_ENABLE_ERRATA es equivalente.
•
-R, --autoflush: Habilita el autoflush para objetos transitorios creados por el comando. Si un objeto padre se carga desde un archivo de contexto, también se liberará el objeto padre transitorio. El autoflush también se puede activar si la variable de entorno TPM2TOOLS_AUTOFLUSH está configurada como "yes" o "true".

Configuración de TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI pueden cambiarse para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Nota que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Utilizado al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y por lo tanto soportan no usar un TCTI. Las herramientas que no lo soportan generarán un error cuando se intenten usar sin una conexión TCTI. No soporta *NINGUNA* opción y *DEBE* presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre_tcti>:<config_opciones_tcti>

Especificar una cadena vacía para <nombre_tcti> o <config_opciones_tcti> resulta en el uso del valor predeterminado para esa porción respectivamente.

Predeterminados del TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán tabrmd, device y mssim TCTIs *EN ESE ORDEN* y *USARÁN EL PRIMERO* *ENCONTRADO*. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTIs mencionados es el predeterminado.

TCTIs Personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica puede cargarse. Las herramientas internamente utilizan dlopen(3), y el valor crudo nombre_tcti se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca tal como lo entiende la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres TPM para su uso por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se pueden especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter ','. Cada clave y valor están separados por un carácter '='.
•
El TCTI abrmd soporta dos claves:
1.
`bus_name': El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type': El tipo de la instancia de dbus

DESCRIPTION

Reads the public information associated with an NV Index. This includes information such as the size, permissions, and locality of the NV index.

OPTIONS

The tpm2_nvreadpublic command supports the following options:

-c, --session session_id
The session_id is the string representation of the session index. E.g. '0x3'. It can also be represented as a string, e.g. 'MySession'. This option is used to associate the command with a specific session index or a named session. The session type can be specified by appending ':type'. The type can be one of the following:
'session'
This is the default session type. It is a standard session which is created via tpm2_startauthsession(1). It is used for authorization of commands.
'system'
This is a system session. It is used for the TPM's system-level functions. This session is created using tpm2_startauthsession(1) with the --system-session option.
--policy-session policy_session_id
The policy_session_id is the string representation of the policy session index. E.g. '0x3'. It can also be represented as a string, e.g. 'MyPolicySession'. This option is used to associate the command with a specific policy session index or a named policy session. The session type can be specified by appending ':type'. The type can be one of the following:
session
This is the default session type. It is a standard session which is created via tpm2_startauthsession(1). It is used for authorization of commands.
system
This is a system session. It is used for the TPM's system-level functions. This session is created using tpm2_startauthsession(1) with the --system-session option.
--auth-session auth_session_id
The auth_session_id is the string representation of the auth session index. E.g. '0x3'. It can also be represented as a string, e.g. 'MyAuthSession'. This option is used to associate the command with a specific auth session index or a named auth session. The session type can be specified by appending ':type'. The type can be one of the following:

This is the default session type. It is a standard session which is created via tpm2_startauthsession(1). It is used for authorization of commands.

The transportsimulator configuration interface (TCTI) specifies how the tool communicates with the TPM. The default TCTI is abrmd. Example: --tcti=mssim

TCTI Configuration

The TCTI configuration is a string that specifies how the tool communicates with the TPM. The default TCTI is abrmd. Other TCTIs can be specified using the --tcti option.

The TCTI configuration string can be in one of the following formats:

tabrmd
Use the tabrmd TCTI. This TCTI is used to communicate with a TPM emulator or simulator.
abrmd
Use the abrmd TCTI. This TCTI is used to communicate with the system's TPM device.

The TCTI configuration string can also include a configuration string that specifies additional options for the TCTI. The configuration string is specified after the TCTI name, separated by a colon.

bus_name=com.example.FooBar
Specify the D-Bus bus name for the tabrmd TCTI.
bus_type=session
Specify the D-Bus bus type for the abrmd TCTI.
bus_type=system
Specify the D-Bus bus type for the abrmd TCTI.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous.

NV Attributes

NV Attributes are used to control various properties of the NV defined space. When specified as an option, either the raw bitfield mask or “nice-names” may be used. The values can be found in Table 204 Part 2 of the TPM2.0 specification, which can be found here:

https://trustedcomputinggroup.org/wp-content/uploads/TPM-Rev-2.0-Part-2-Structures-01.38.pdf

Nice names are calculated by taking the name field of table 204 and removing the prefix TPMA_NV_ and lowercasing the result. Thus, TPMA_NV_PPWRITE becomes ppwrite. Nice names can be joined using the bitwise or “|” symbol.

Note that the TPM_NT field is 4 bits wide, and thus can be set via nt= format. For instance, to set The fields TPMA_NV_OWNERREAD, TPMA_NV_OWNERWRITE, TPMA_NV_POLICYWRITE, and TPMA_NV_NT = 0x2, the argument would be:

ownerread|ownerwrite|policywrite|nt=0x2

Additionally, the NT field, which denotes the type of the NV index, can also be specified via friendly names: * ordinary - Ordinary contains data that is opaque to the TPM that can only be modified using TPM2_NV_Write. * extend - Extend is used similarly to a PCR and can only be modified with TPM2_NV_Extend. Its size is determined by the length of the hash algorithm used. * counter - Counter contains an 8-octet value that is to be used as a counter and can only be modified with TPM2_NV_Increment * bits - Bit Field contains an 8-octet value to be used as a bit field and can only be modified with TPM2_NV_SetBits. * pinfail - PIN Fail contains an 8-octet pinCount that increments on a PIN authorization failure and a pinLimit. * pinpass - PIN Pass contains an 8-octet pinCount that increments on a PIN authorization success and a pinLimit.

For instance, to set The fields TPMA_NV_OWNERREAD, TPMA_NV_OWNERWRITE, TPMA_NV_POLICYWRITE, and TPMA_NV_NT = bits, the argument would be:

ownerread|ownerwrite|policywrite|nt=bits
