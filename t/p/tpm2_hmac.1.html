NAME

tpm2_hmac(1) - Realiza una operación HMAC con el TPM.

SYNOPSIS

tpm2_hmac [OPCIONES] [ARGUMENTO]

DESCRIPTION

tpm2_hmac(1) - Realiza una operación HMAC y devuelve los resultados. Si no se especifica el archivo de argumento, los datos se leen de stdin.

El algoritmo de hash por defecto es el esquema de la clave o sha256 si la clave tiene un esquema NULL.

La salida por defecto es *STDOUT* y en formato binario a menos que se especifique lo contrario mediante las opciones -o y –hex respectivamente.

OPTIONS

•
-c, --key-context=OBJETO:

El objeto de contexto de la clave de firma simétrica que proporciona la clave HMAC. Puede ser un archivo o un número de handle. Consulte la sección "Formato del Objeto de Contexto".

•
-p, --auth=AUTH:

Valor de autorización opcional para usar la clave especificada por -c.

•
-g, --hash-algorithm=ALGORITMO:

El algoritmo de hash a utilizar. Los algoritmos deben seguir los "estándares de formato", consulte la sección "Especificadores de Algoritmos". Además, consulte la sección "Algoritmos de Hash Soportados" para obtener una lista de los algoritmos de hash soportados.

•
--hex

Convierte el HMAC de salida a formato hexadecimal sin un prefijo "0x".

•
-o, --output=ARCHIVO:

Archivo opcional de registro del resultado HMAC. Por defecto es *STDOUT*.

•
-t, --ticket=ARCHIVO:

Archivo opcional de registro del resultado del ticket.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará el comando, simplemente devolverá un cpHash.

•
ARGUMENTO el argumento de línea de comandos especifica la ruta del archivo para los datos a los que se aplicará HMAC. Por defecto es *STDIN* si no se especifica.

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un handle o un nombre de archivo, se determina según la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio del TPM restaurado.
•
Si el argumento es una coincidencia de *prefijo* en uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento se puede cargar como un número, se tratará como un handle, por ejemplo, 0x81010013 y se usará directamente. *OBJETO*.

Formato de Autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autorizaciones por defecto son la **CONTRASEÑA VACÍA** cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación utilizando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en forma de cadena de texto cuando no tienen prefijo.

Cadena de texto

Una contraseña en formato de cadena de texto, especificada con el prefijo "str:" o su ausencia (cadena de texto sin prefijo), no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena hexadecimal

Una contraseña en formato de cadena hexadecimal, especificada con el prefijo "hex:", se convierte de formato hexadecimal a un array de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables con la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en un archivo, especificada con el prefijo "file:", debe ser la ruta de un archivo que contenga la contraseña que la herramienta leerá o un "-" para usar stdin. Almacenar contraseñas en archivos evita la fuga de información, ya que las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las funciones comunes del historial del shell.

Ejemplos

# para usar stdin y que se solicite
file:-
# para usar un archivo de una ruta
file:ruta/a/archivo/contraseña
# para eco de una contraseña vía stdin:
echo foobar | tpm2_tool -p file:-
# para usar un here-string de bash vía stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al utilizar una sesión de política para autorizar el uso de un objeto, anteponga la palabra *session* al argumento de la opción. Luego, indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autorización que se envíe con el handle de la sesión (por ejemplo, contraseña de política), añada un + y una cadena de texto como se describe en la sección **Contraseñas**.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx **Y** enviar el valor de autorización mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx **Y** enviar el valor de autorización *HEXADECIMAL* 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones PCR

Puede satisfacer una política PCR usando el prefijo "pcr:" y el mini-lenguaje PCR. El mini-lenguaje PCR es el siguiente: <especificador-pcr>=<archivo-pcr-raw>

El especificador PCR se documenta en la sección "Especificadores de banco PCR".

El archivo-pcr-raw es un argumento **opcional** que contiene la salida del contenido raw del PCR tal como lo devuelve tpm2_pcrread(1).

Especificadores de banco PCR

Ejemplos

Para satisfacer una política PCR de sha256 en los bancos 0, 1, 2 y 3 use un especificador de:

pcr:sha256:0,1,2,3

especificando *AUTH*.

Configuración TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre tiene precedencia sobre la variable de entorno.

Los TCTI conocidos actualmente son:

tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
device - Utilizado cuando se habla directamente con el archivo del dispositivo TPM.
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo soportan generarán un error cuando se intenten utilizar sin una conexión TCTI. No soporta *NINGUNA* opción y *DEBE* presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<configuración-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <configuración-opciones-tcti> da como resultado que se use el valor predeterminado para esa porción respectivamente.

Valores Predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI *tabrmd*, *device* y *mssim* EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para imprimir la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs Personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica puede ser cargado. Las herramientas internamente usan dlopen(3), y el valor crudo *tcti-name* se utiliza para la búsqueda. Por lo tanto, esta podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entiendan las semánticas de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres del TPM para su uso por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares clave-valor simples separados por un carácter ','. Cada cadena de clave y valor están separadas por un carácter '='.
TCTI abrmd soporta dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia de dbus (una cadena) limitado a 'session' y 'system'.

Especifica el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifica el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

tpm2_hmac(1) — Arch Linux manual pages

NOMBRE

tpm2_hmac - realizar una operación HMAC usando una clave HMAC.

SINOPSIS

tpm2_hmac [OPTIONS] -c AUTH_HANDLE [DATA]

DESCRIPCIÓN

El comando tpm2_hmac realiza una operación HMAC (Hash-based Message Authentication Code) sobre los datos de entrada (opcional) utilizando la clave HMAC especificada por el parámetro de contexto del objeto de autenticación. La clave HMAC especificada por el parámetro de contexto debe ser una clave HMAC RSA o una clave HMAC con un esquema de firma definido.

La herramienta maneja un contexto de objeto de autenticación especificado por la opción -c. Este contexto debe contener una clave HMAC que se utilizará para calcular el HMAC. La operación HMAC requiere que la clave contenga un esquema de firma que sea compatible con el algoritmo hash especificado, o el algoritmo hash por defecto del dispositivo TPM, si no se especifica ninguno. Si se utiliza una clave RSA, el algoritmo hash utilizado se determinará por el esquema de firma de la clave.

La entrada de datos para el cálculo del HMAC se lee de la entrada estándar si no se proporciona ningún operando de datos. La salida del HMAC se imprime en la salida estándar en formato hexadecimal.

La operación HMAC está definida por el estándar TPM. Se utiliza para verificar la integridad de los datos y la autenticidad de los mensajes. La operación HMAC toma una clave secreta y un mensaje como entrada y produce un valor HMAC como salida. Este valor HMAC se puede utilizar posteriormente para verificar que el mensaje no ha sido alterado y que proviene de una fuente autorizada.

OPCIONES

-c AUTH_HANDLE
Especifica el contexto de un objeto de autenticación que contiene la clave HMAC. Este objeto debe ser una clave HMAC. El formato del manejador de contexto es 'primary.ctx' o 'hmac.key'.
--hex
Imprime la salida HMAC en formato hexadecimal.
-f DATOS
Lee los datos de entrada del archivo especificado en lugar de la entrada estándar.
-S SCHEME
Especifica el esquema de firma para el cálculo del HMAC. Los esquemas admitidos son:

* hmac: Utiliza el algoritmo HMAC especificado por el esquema de la clave.

-L
Lista los esquemas de firma disponibles.
-V VERSION
Especifica la versión del protocolo TPM. Los valores válidos son 1.2 o 2.0.

Formato del objeto de contexto

El objeto de contexto es un archivo que contiene el Handle de un objeto TPM y puede incluir información de autorización. Para claves HMAC, el objeto de contexto contendrá el Handle de la clave HMAC y puede incluir la política y el contraseña asociados con la clave.

Los objetos de contexto se crean típicamente usando comandos como tpm2_createprimary o tpm2_create.

Opciones comunes

Las siguientes opciones son comunes a la mayoría de las herramientas tpm2-tools:

-h, --help
Muestra el mensaje de ayuda y sale.
-v, --verbose
Habilita la salida detallada.
-t, --tcti TCTI
Especifica el TCTI (Tabernacle Client Transport Interface) a utilizar para comunicarse con el dispositivo TPM. El valor predeterminado es el primer TCTI disponible.

Configuración TCTI

El TCTI especifica cómo la herramienta tpm2-tools se comunica con el dispositivo TPM. Los TCTI comunes incluyen:

mssim
Utiliza un simulador TPM basado en software.
device
Utiliza un dispositivo TPM físico (por ejemplo, /dev/tpm0).
socket
Se conecta a un simulador TPM a través de un socket TCP.

Se puede especificar un TCTI utilizando la opción -t, por ejemplo:

tpm2_hmac -t device -c hmac.key data.in

Opciones TCTI

Las siguientes opciones se pueden utilizar para configurar el TCTI:

-T TCTI
Especifica el TCTI a utilizar. Por ejemplo, -T device o -T socket:host=localhost,port=2321.
--tcti-list
Lista los TCTI disponibles.

EJEMPLOS

Configuración

# crear un objeto primario
tpm2_createprimary -c primary.ctx
# crear una clave hmac
tpm2_create -C primary.ctx -G hmac -c hmac.key

Realizar un HMAC con algoritmo hash predeterminado

Realiza un hmac utilizando el esquema por defecto de la clave (algoritmo hash) y muestra la salida en la salida estándar en formato hexadecimal.

tpm2_hmac -c hmac.key --hex data.in
e6eda48a53a9ddbb92f788f6d98e0372d63a408afb11aca43f522a2475a32805

Devoluciones

Las herramientas pueden devolver cualquiera de los siguientes códigos:

•
0 - Éxito.
•
1 - Error general no específico.
•
2 - Error en el manejo de opciones.
•
3 - Error de autenticación.
•
4 - Error relacionado con TCTI.
•
5 - Esquema no soportado. Aplicable a tpm2_testparams.
