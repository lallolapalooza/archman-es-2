tpm2_selftest(1) Manual general de comandos tpm2_selftest(1)

NOMBRE

tpm2_selftest(1) - Ejecuta las rutinas internas de autocomprobación del TPM

SINOPSIS

tpm2_selftest [OPCIONES]

DESCRIPCIÓN

tpm2_selftest(1) - Causa que el TPM ejecute la autocomprobación de sus capacidades.

La autocomprobación se puede ejecutar en dos modos:

•
Prueba simple: el TPM probará las funciones que requieren prueba.
•
Prueba completa: el TPM probará todas las funciones independientemente de lo que ya se haya probado.

Una vez que el TPM reciba esta solicitud, devolverá TPM_RC_TESTING para cualquier comando que requiera una prueba. Si una prueba falla, el TPM devolverá TPM_RC_FAILURE para cualquier comando que no sea TPM2_GetTestResult() y TPM2_GetCapability() durante este tiempo. El TPM permanecerá en modo de error hasta la próxima inicialización del TPM.

OPCIONES

•
-f, --fulltest: Ejecuta la autocomprobación en modo completo.

Referencias

OPCIONES COMUNES

Esta colección de opciones son comunes a muchos programas y proporcionan información que muchos usuarios pueden esperar.

•
-h, --help=[man|no-man]: Muestra el manual de la herramienta. Por defecto, intenta invocar al paginador de manuales para la herramienta, sin embargo, en caso de fallo, mostrará un resumen corto de la herramienta. Este es el mismo comportamiento si se especifica el argumento de opción "man", sin embargo, si se solicita explícitamente "man", la herramienta proporcionará errores de man en stderr. Si se especifica la opción "no-man", o si el paginador de manuales falla, las opciones cortas se mostrarán en stdout.

Para usar correctamente la función de manuales se requiere que los manuales estén instalados o en MANPATH. Consulte man(1) para más detalles.

•
-v, --version: Muestra la información de la versión de esta herramienta, los tcti soportados y sale.
•
-V, --verbose: Aumenta la información que la herramienta imprime en la consola durante su ejecución. Al usar esta opción, se imprime el número de archivo y línea.
•
-Q, --quiet: Silencia la salida normal de la herramienta a stdout.
•
-Z, --enable-errata: Habilita la aplicación de correcciones de erratas. Útil si se necesita aplicar una corrección de erratas a los comandos enviados al TPM. Definir la variable de entorno TPM2TOOLS_ENABLE_ERRATA es equivalente.

Configuración TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Utilizado al comunicarse directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo soportan mostrarán un error cuando se intenten usar sin una conexión TCTI. No soporta *NINGUNA* opción y *DEBE* ser presentado como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <config-opciones-tcti> resulta en el uso del valor predeterminado para esa porción respectivamente.

Valores Predeterminados del TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs Personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica se puede cargar. Las herramientas utilizan internamente dlopen(3), y el valor crudo nombre-tcti se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entienda la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres TPM para que lo utilice el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares clave-valor simples separados por una coma ','. Cada cadena de clave y valor están separadas por un signo igual '='.
•
TCTI abrmd soporta dos claves:
1.
`bus_name': El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type': El tipo de la instancia dbus (una cadena) limitada a `session' y `system'.

Especifica el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifica el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

NAME

m2_selftest

runs self-tests on the TPM

SYNOPSIS

m2_selftest

[OPTIONS]

DESCRIPTION

m2_selftest runs self-tests on the TPM. The TPM has built-in self-tests that can be run to verify its integrity. This command executes these tests and reports the results.

OPTIONS

The following options are available:

•
-f, --force
Force the execution of self-tests even if they have been run recently or if the TPM indicates they have already passed.

COMMON OPTIONS

These options are common to most of the tpm2-tools commands:

•
-h, --help
Print help information.
•
-v, --version
Print version information.
•
-l, --log-level <level>
Set the logging level. Valid levels are: DEBUG, INFO, WARN, ERROR.
•
-t, --tcti <tcti>
Set the TCTI (Tabernacle Communication Transport Interface) to use. This specifies how to communicate with the TPM. Examples include mssim, device, socket.

TCTI Configuration

The TCTI can be configured using environment variables or command-line options. See tpm2_tool.conf(5) for more information.

TCTI OPTIONS

Specific TCTI options can be passed using the -t option. The format depends on the TCTI chosen. For example:

•
--tcti "device:/dev/tpm0"
Use the device TCTI with the TPM device at /dev/tpm0.
•
--tcti "socket:host=localhost,port=2321"
Use the socket TCTI to connect to a TPM simulator running on localhost at port 2321.

EXAMPLES

To run the TPM self-tests:

m2_selftest

To force the execution of TPM self-tests:

m2_selftest -f

To run self-tests using a specific TCTI:

m2_selftest -t "device:/dev/tpmrm0"

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.
