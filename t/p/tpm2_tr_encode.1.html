tpm2_tr_encode(1) Manual General de Comandos tpm2_tr_encode(1)

NOMBRE

tpm2_tr_encode(1) - Codifica un identificador persistente y TPM2B_NAME como un ESYS_TR serializado como salida.

SINOPSIS

tpm2_tr_encode [OPCIONES]

DESCRIPCIÓN

tpm2_tr_encode(1) - Codifica un identificador persistente de TPM2 junto con un TPM2B_PUBLIC poblado como un ESYS_TR serializado. Esto es útil para mover una clave pública e identificador de un entorno donde un TPM no está disponible a otro entorno con un TPM y hacerlo utilizable a través de la API ESAPI o tpm2-tools(1).

OPCIONES

•
-c, --object-context=OBJETO:

Identificador persistente.

•
-f, --format:

Selección de formato para el archivo de salida de la clave pública. `tss' (el predeterminado) generará un blob binario según la especificación TPM 2.0. `pem' generará una clave pública codificada en PEM compatible con OpenSSL. `der' generará una clave pública codificada en DER compatible con OpenSSL. `tpmt' generará un blob binario de la estructura TPMT_PUBLIC referenciada por las especificaciones de TPM 2.0.

Formato de la clave pública.

•
-o, --output=ARCHIVO:

La ruta del archivo de salida, que registra el ESYS_TR serializado.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un identificador o un nombre de archivo, se determina según la siguiente lógica en orden:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio de TPM restaurado.
•
Si el argumento es una coincidencia de prefijo con uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de aprobación
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un identificador, por ejemplo, 0x81010013 y se usará directamente._OBJETO_.

Configuración del TCTI

El TCTI o 'Interfaz de Transmisión' es el mecanismo de comunicación con el TPM. Los TCTI pueden cambiarse para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Normalmente se utiliza para comunicarse con el simulador de software de TPM.
•
device - Se utiliza al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo soportan generarán un error cuando se intenten usar sin una conexión TCTI. No soporta *NINGUNA* opción y *DEBE* presentarse como el texto exacto de 'none'.

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<configuración-opción-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <configuración-opción-tcti> resulta en el uso del valor predeterminado para esa parte respectivamente.

Valores Predeterminados del TCTI

Cuando no se especifica un TCTI, el TCTI predeterminado se busca utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim **EN ESE ORDEN** y **USARÁN EL PRIMERO** **ENCONTRADO**. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor 'default-tcti' indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs Personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica puede cargarse. Las herramientas utilizan internamente dlopen(3), y el valor bruto nombre-tcti se utiliza para la búsqueda. Por lo tanto, podría ser la ruta a la biblioteca compartida, o un nombre de biblioteca según lo entienda la semántica de dlopen(3).

OPCIONES DEL TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo de dispositivo de caracteres del TPM para uso del TCTI de dispositivo. El predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares clave-valor simples separados por un carácter ','. Cada clave

Configuración TCTI

En este momento, hay dos módulos TCTI (Transport Cipher Text Interface) conocidos:

•
abrmd: Este es el módulo TCTI predeterminado. El servicio abrmd debe ser invocado en el bus D-Bus. Este TCTI tiene las siguientes opciones configurables:
•
La opción bus_type: puede ser establecida a session o system. Predeterminado a session.
•
tabrmd: Este módulo TCTI es para el servicio tabrmd. El servicio tabrmd debe ser invocado en el bus D-Bus. Este TCTI tiene las siguientes opciones configurables:
•
La opción bus_name: el nombre del servicio tabrmd en el bus (una cadena).
•
La opción bus_type: el tipo de la instancia dbus (una cadena) limitado a session y system.

El nombre del TCTI y su string de configuración se separan por un carácter ':'. El nombre del TCTI y el valor de la cadena de configuración se separan por un carácter ':'.

•
TCTI abrmd soporta dos claves:
1.
bus_name : El nombre del servicio tabrmd en el bus (una cadena).
2.
bus_type : El tipo de la instancia dbus (una cadena) limitado a session y system.

Especifique el nombre tcti tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifique el tcti predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los varios módulos TCTI conocidos.

EJEMPLOS

Serializar un público y un handle como un ESYS_TR

tpm2_createprimary -c primary.ctx
tpm2_evictcontrol -c primary.ctx -o primary.tr 0x81000002
tpm2_readpublic -c primary.tr -o primary.pub
tpm2_tr_encode -c 0x81000002 -u primary.pub -o primary2.tr
