tpm2_nvincrement(1) Manual de Comandos Generales tpm2_nvincrement(1)

NOMBRE

tpm2_nvincrement(1) - Incrementa el contador en un índice No Volátil (NV).

SINOPSIS

tpm2_nvincrement [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_nvincrement(1) - Incrementa el valor de un índice No Volátil (NV) configurado como contador. El índice puede especificarse como un handle bruto o un valor de desplazamiento del rango de handles nv “TPM2_HR_NV_INDEX”.

OPCIONES

•
-C, --hierarchy=OBJETO:

Especifica la jerarquía utilizada para autorizar. Las opciones soportadas son:

•
o para TPM_RH_OWNER
•
p para TPM_RH_PLATFORM
•
<num> donde se puede usar un handle de jerarquía o un índice nv.

Cuando -C no se pasa explícitamente, el handle del índice se usará para autorizar contra el índice. El valor de autorización del índice se establece mediante la opción -p de tpm2_nvdefine(1).

•
-P, --auth=AUTH:

Especifica el valor de autorización para la jerarquía.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash a menos que también se requiera rphash.

•
--rphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros de respuesta. Esto se denomina comúnmente rpHash.

•
-S, --session=ARCHIVO:

La sesión creada usando tpm2_startauthsession. Esto se puede usar para especificar una sesión auxiliar para auditoría y/o cifrado/descifrado de los parámetros.

•
-n, --name=ARCHIVO:

El nombre del índice NV que debe proporcionarse cuando solo se calcula el cpHash sin enviar realmente el comando al TPM.

•
ARGUMENTO el argumento de la línea de comandos especifica el índice NV o el número de desplazamiento.

Referencias

Formato del objeto de contexto

El tipo de un objeto de contexto, ya sea un handle o un nombre de archivo, se determina de acuerdo con la siguiente lógica en orden:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio de TPM restaurado.
•
Si el argumento es una coincidencia de prefijo en uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un handle, por ejemplo, 0x81010013 y se usará directamente._OBJETO_.

Formato de autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: “Las autorizaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican”.

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación usando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña de cadena, especificada por el prefijo “str:” o su ausencia (cadena sin prefijo) no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena hexadecimal

Una contraseña de cadena hexadecimal, especificada por el prefijo “hex:” se convierte de forma hexadecimal a forma de array de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables para la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada con el prefijo “file:” debe ser la ruta de un archivo que contenga la contraseña a leer por la herramienta o un “-” para usar stdin. Almacenar contraseñas en archivos evita la fuga de información, las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de funciones comunes de historial de shell.

Ejemplos

# para usar stdin y que se le solicite
file:-
# para usar un archivo desde una ruta
file:ruta/a/archivo/contraseña
# para enviar una contraseña vía stdin:
echo foobar | tpm2_tool -p file:-
# para usar una cadena here de bash vía stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego, indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autorización para ser enviado con el handle de la sesión (por ejemplo, contraseña de política), agregue un + y una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones PCR

Puede satisfacer una política PCR usando el prefijo “pcr:” y el minilenguaje PCR. El minilenguaje PCR es el siguiente: <espec-pcr>=<archivo-pcr-bruto>

La especificación PCR se documenta en la sección “Especificadores de banco PCR”.

El archivo-pcr-bruto es un argumento opcional que contiene la salida del contenido bruto del PCR devuelto por tpm2_pcrread(1).

Especificadores de banco PCR

Ejemplos

Para satisfacer una política PCR de sha256 en los bancos 0, 1, 2 y 3 use un especificador de:

pcr:sha256:0,1,2,3

especificando AUTH.

Configuración TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTIs se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTIs conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Se utiliza al hablar directamente con un archivo de dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y, por lo tanto, soportan no usar un TCTI. Las herramientas que no lo soportan mostrarán un error cuando se intente usarlas sin una conexión TCTI. No soporta *NINGUNA* opción y *DEBE* presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o <config-opciones-tcti> da como resultado el uso del valor predeterminado para esa parte respectivamente.

Predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTIs tabrmd, device y mssim EN ESE ORDEN y **USARÁN EL PRIMERO QUE ENCUENTREN**. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para imprimir la información de versión. El par clave-valor "default-tcti" indicará cuál de los TCTIs mencionados es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor bruto de tcti-name se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca tal como lo entiende la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo de dispositivo de caracteres TPM para su uso por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de cadena de configuración es una serie de pares clave-valor simples separados por un carácter ','. Cada cadena de clave y valor se separan por un carácter '='.
•
El TCTI abrmd soporta dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia de dbus (una cadena) limitada a `session' y `system'.

Especifica el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifica el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

Para incrementar el contador en el índice 0x150016

tpm2_nvdefine -C o -s 8 -a "ownerread|authread|authwrite|nt=1" 0x1500016 -p index
tpm2_nvincrement -C 0x1500016  0x1500016 -P "index"
tpm2_nvread 0x1500016 -P index | xxd -p

•
1 - Error general no específico.
•
2 - Error en el manejo de opciones.
•
3 - Error de autenticación.
•
4 - Error relacionado con TCTI.
•
5 - Esquema no soportado. Aplicable a tpm2_testparams.
