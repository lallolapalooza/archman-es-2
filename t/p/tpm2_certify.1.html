tpm2_certify(1) Manual de Comandos Generales tpm2_certify(1)

NOMBRE

tpm2_certify(1) - Demuestra que un objeto está cargado en el TPM.

SINOPSIS

tpm2_certify [OPCIONES]

DESCRIPCIÓN

tpm2_certify(1) - Demuestra que un objeto con un NOMBRE específico está cargado en el TPM. Al certificar que el objeto está cargado, el TPM garantiza que un área pública con un NOMBRE dado es autoconsistente y está asociada con un área sensible válida.

Si una parte confiable tiene un área pública que tiene el mismo NOMBRE que un NOMBRE certificado con este comando, entonces los valores de esa área pública son correctos. Un objeto que solo tiene su área pública cargada no puede ser certificado.

OPCIONES

Estas opciones controlan la certificación:

•
-c, --certifiedkey-context=OBJETO:

El objeto a certificar.

•
-C, --signingkey-context=OBJETO:

La clave utilizada para firmar la estructura de atestación.

•
-P, --certifiedkey-auth=AUTENTICACION:

El valor de autorización proporcionado para el objeto especificado con -c.

•
-g, --hash-algorithm=ALGORITMO:

El algoritmo hash a utilizar en la generación de la firma.

•
--scheme=ALGORITMO:

El esquema de firma utilizado para firmar el mensaje. Opcional. Los esquemas de firma deben seguir los “estándares de formato”, ver la sección “Especificadores de Algoritmo”. Además, ver la sección “Esquemas de Firma Soportados” para una lista de esquemas de firma soportados. Si se especifica, el esquema de firma debe coincidir con el tipo de clave. Si se deja sin especificar, se utilizará un esquema de firma predeterminado para el tipo de clave.

•
-p, --signingkey-auth=AUTENTICACION:

El valor de autorización para la clave de firma especificada con -C.

•
-o, --attestation=ARCHIVO:

Nombre del archivo de salida para los datos de atestación.

•
-s, --signature=ARCHIVO:

Nombre del archivo de salida para los datos de la firma.

•
-f, --format=FORMATO:

Selección del formato para el archivo de salida de la firma.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash, a menos que también se requiera rphash.

•
--rphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros de respuesta. Esto se denomina comúnmente rpHash.

•
-S, --session=ARCHIVO:

La sesión creada usando tpm2_startauthsession. Esto se puede utilizar para especificar una sesión auxiliar para auditoría y/o cifrado/descifrado de los parámetros.

Referencias

Formato del objeto de contexto

El tipo de un objeto de contexto, ya sea un manejador o un nombre de archivo, se determina de acuerdo con la siguiente lógica, en orden:

•
Si el argumento es una ruta de archivo, entonces se carga el archivo como un objeto transitorio del TPM restaurado.
•
Si el argumento es una coincidencia de prefijo con uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento se puede cargar como un número, se tratará como un manejador, por ejemplo, 0x81010013 y se usará directamente._OBJETO_.

Formato de autenticación

La autenticación para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: “Las autorizaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican”.

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación, utilizando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en forma de cadena cuando no tienen prefijo.

Cadena

Una contraseña en cadena, especificada por el prefijo “str:” o su ausencia (cadena en bruto sin prefijo) no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena-hexadecimal

Una contraseña en cadena hexadecimal, especificada por el prefijo “hex:”, se convierte de una forma hexadecimal a una forma de matriz de bytes, lo que permite contraseñas con caracteres no imprimibles y/o que no son amigables con la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo “file:”, debe ser la ruta de un archivo que contenga la contraseña que será leída por la herramienta o un “-” para usar la entrada estándar. Almacenar contraseñas en archivos evita la fuga de información, las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las funciones comunes del historial del shell.

Ejemplos

# para usar entrada estándar y ser solicitado
file:-
# para usar un archivo desde una ruta
file:ruta/al/archivo/de/contraseñas
# para enviar una contraseña vía entrada estándar:
echo foobar | tpm2_tool -p file:-
# para usar una cadena de aquí de bash vía entrada estándar:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego, indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación que se enviará con el manejador de la sesión (por ejemplo, contraseña de política), agregue un + y una cadena como se describe en la sección de Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autenticaciones de PCR

Usted

que puede satisfacer una política de PCR usando el prefijo "pcr:" y el minilenguaje PCR. El minilenguaje PCR es el siguiente: <especificación-pcr>=<archivo-pcr-crudo>

La especificación PCR está documentada en la sección "Especificadores de bancos PCR".

El archivo-pcr-crudo es un argumento **opcional** que contiene la salida de los contenidos PCR crudos tal como los devuelve tpm2_pcrread(1).

Especificadores de bancos PCR

Ejemplos

Para satisfacer una política de PCR de sha256 en los bancos 0, 1, 2 y 3, utilice un especificador de:

pcr:sha256:0,1,2,3

especificando *AUTH*.

Especificadores complejos

Los objetos, cuando se especifican para su creación por el TPM, tienen numerosos algoritmos para poblar en los datos públicos. Cosas como el tipo, el esquema y los detalles asimétricos, el tamaño de la clave, etc. A continuación se muestra el formato general para especificar estos datos: <tipo>:<esquema>:<detalles-simétricos>

Especificadores de Tipo

Esta parte del especificador de algoritmo complejo es obligatoria. El esquema y los detalles simétricos restantes se establecerán por defecto según el tipo especificado y el tipo del objeto que se está creando.

•
aes - AES por defecto: aes128
•
aes128<modo> - AES de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, el valor por defecto es null.
•
aes192<modo> - Igual que aes128<modo>, excepto por un tamaño de clave de 192 bits.
•
aes256<modo> - Igual que aes128<modo>, excepto por un tamaño de clave de 256 bits.
•
sm4 - SM4 por defecto: sm4128
•
sm4128 o sm4_128 <modo> - SM4 de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, el valor por defecto es null.
•
ecc - Curva Elíptica, por defecto ecc256.
•
ecc192 o ecc_nist_p192 - Curva NIST ECC de 192 bits
•
ecc224 o ecc_nist_p224 - Curva NIST ECC de 224 bits
•
ecc256 o ecc_nist_p256 - Curva NIST ECC de 256 bits
•
ecc384 o ecc_nist_p384 - Curva NIST ECC de 384 bits
•
ecc521 o ecc_nist_p521 - Curva NIST ECC de 521 bits
•
ecc_sm2 o ecc_sm2_p256 - Curva SM2 de 256 bits
•
rsa - RSA por defecto: rsa2048
•
rsa1024 - RSA con tamaño de clave de 1024 bits.
•
rsa2048 - RSA con tamaño de clave de 2048 bits.
•
rsa3072 - RSA con tamaño de clave de 3072 bits.
•
rsa4096 - RSA con tamaño de clave de 4096 bits.

Especificadores de Esquema

A continuación, hay un campo opcional, se puede omitir.

Los esquemas suelen ser **Esquemas de Firma** o **Esquemas de Cifrado Asimétrico**. La mayoría de los esquemas de firma toman un algoritmo hash directamente después del esquema de firma. Si falta el algoritmo hash, el valor por defecto es *sha256*. Algunos no toman argumentos y otros toman múltiples argumentos.

Este especificador de esquema va seguido de un número (tamaño máximo UINT16) y luego seguido de un guion (-) y un algoritmo hash válido. * ecdaa Por ejemplo, ecdaa4-sha256. Si no se especifica ningún número, el valor por defecto es 4.

Especificadores de Esquema sin Opciones

Este especificador de esquema NO toma argumentos. * rsaes

Especificadores de Detalles Simétricos

Este campo es opcional y se establece por defecto según el *tipo* de objeto que se está creando y sus atributos. En general, cualquier especificador **Simétrico** válido de la lista de **Especificadores de Tipo** debería funcionar. Si no se especifica, los detalles simétricos de los objetos asimétricos por defecto son *aes128cfb*.

Ejemplos

Crear una clave rsa2048 con un esquema de cifrado asimétrico rsaes

tpm2_create -C parent.ctx -G rsa2048:rsaes -u key.pub -r key.priv

Crear una clave ecc256 con un esquema de firma ecdaa con un recuento de 4 y hash sha384

/tpm2_create -C parent.ctx -G ecc256:ecdaa4-sha384 -u key.pub -r key.priv algoritmos criptográficos *ALGORITMO*.

COMMON OPTIONS

The tpm2 tools provide several common options that are supported by all commands. These options are used to modify the behavior of the commands, such as changing the logging level or enabling debug output.

•
-h, --help: Print the help message for the command.
•
-v, --version: Print the version information for the command.
•
-c, --create: Create a new object. This option is used to specify the type of object to create, such as a primary key or a signing key.
•
-f, --force: Force the creation of a new object, even if an object with the same name already exists.
•
-p, --parent: Specify the parent object for the new object. This option is used to specify the context object for the new object, such as the primary key or a signing key.
•
-t, --take-ownership: Take ownership of the TPM. This option is used to specify the owner password for the TPM.
•
-l, --log-level: Set the logging level. This option is used to specify the logging level for the command, such as quiet, verbose, or debug.
•
-d, --debug: Enable debug output. This option is used to enable debug output for the command.
•
-q, --quiet: Silence normal tool output to stdout.
•
-Z, --enable-errata: Enable the application of errata fixups. Useful if an errata fixup needs to be applied to commands sent to the TPM. Defining the environment TPM2TOOLS_ENABLE_ERRATA is equivalent.
•
-R, --autoflush: Enable autoflush for transient objects created by the command. If a parent object is loaded from a context file also the transient parent object will be flushed. Autoflush can also be activated if the environment variable TPM2TOOLS_AUTOFLUSH is is set to yes or true. information many users may expect.

Configuración del TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Se utiliza al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo admiten fallarán cuando se intenten usar sin una conexión TCTI. No admite *NINGUNA* opción y *DEBE* presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<tcti-name>:<tcti-option-config>

Especificar una cadena vacía para el <tcti-name> o el <tcti-option-config> da como resultado que se utilice el valor predeterminado para esa parte respectivamente.

Valores predeterminados del TCTI

Cuando no se especifica un TCTI, el TCTI predeterminado se busca utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para imprimir la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas internamente utilizan dlopen(3), y el valor bruto tcti-name se utiliza para la búsqueda. Por lo tanto, podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entendido por la semántica de dlopen(3).

OPCIONES DEL TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres TPM para su uso por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter `,'. Cada cadena de clave y valor están separadas por un carácter `=.
•
El TCTI abrmd admite dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia dbus (una cadena) limitada a `session' y `system'.

Especifique el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifique el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

Cree una clave primaria y certifíquela con una clave de firma.

tpm2_createprimary -Q -C e -g sha256 -G rsa -c primary.ctx
tpm2_create -Q -g sha256 -G rsa -u certify.pub -r certify.priv -C primary.ctx
tpm2_load -Q -C primary.ctx -u certify.pub -r certify.priv -n certify.name \
-c certify.ctx
tpm2_certify -Q -c primary.ctx -C certify.ctx -g sha256 -o attest.out -s sig.out

0 - Éxito.
•
1 - Error general no específico.

2 - Error en el manejo de opciones.
•
3 - Error de autenticación.
•
4 - Error relacionado con TCTI.
•
5 - Esquema no soportado. Aplicable a tpm2_testparams.

device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres TPM para su uso por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter `,'. Cada cadena de clave y valor están separadas por un carácter `=.
•
El TCTI abrmd admite dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia dbus (una cadena) limitada a `session' y `system'.

Especifique el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifique el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

Cree una clave primaria y certifíquela con una clave de firma.

tpm2_createprimary -Q -C e -g sha256 -G rsa -c primary.ctx
tpm2_create -Q -g sha256 -G rsa -u certify.pub -r certify.priv -C primary.ctx
tpm2_load -Q -C primary.ctx -u certify.pub -r certify.priv -n certify.name \
-c certify.ctx
tpm2_certify -Q -c primary.ctx -C certify.ctx -g sha256 -o attest.out -s sig.out

0 - Éxito.

2 - Error en el manejo de opciones.
•
3 - Error de autenticación.
•
4 - Error relacionado con TCTI.

5 - Esquema no soportado. Aplicable a tpm2_testparams.
