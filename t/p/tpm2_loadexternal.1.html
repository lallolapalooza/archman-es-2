tpm2_loadexternal(1) Manual de Comandos Generales tpm2_loadexternal(1)

NOMBRE

tpm2_loadexternal(1) - Carga un objeto externo en el TPM.

SINOPSIS

tpm2_loadexternal [OPCIONES]

DESCRIPCIÓN

tpm2_loadexternal(1) - Este comando carga un objeto externo en el TPM, omitiendo las protecciones del TPM. Es decir, el material de la clave no está protegido por la semilla del objeto padre. También se puede utilizar para cargar Claves Privadas TSS2 en formato pem. El comando permite cargar solo la porción pública de un objeto o ambas porciones, pública y privada, de un objeto. Para Claves Privadas TSS2, solo se carga la porción pública de la clave.

La herramienta genera el nombre del objeto cargado en un formato de diccionario YAML con la clave nombre, donde el valor para esa clave es el nombre del objeto en formato hexadecimal, por ejemplo:

nombre: 000bac25cb8743111c8e1f52f2ee7279d05d3902a18dd1af694db5d1afa7adf1c8b3

También guarda un archivo de contexto para interacciones futuras con el objeto.

OPCIONES

•
-C, --hierarchy=OBJETO:

Jerarquía a usar para el ticket, opcional. Por defecto es n, null. Las opciones soportadas son:

•
o para la jerarquía del propietario.
•
p para la jerarquía de la plataforma.
•
e para la jerarquía de la certificación.
•
n para la jerarquía nula.
•
-G, --key-algorithm=ALGORITMO:

El algoritmo utilizado por la clave a importar. Soporta:

•
aes - Clave AES 128, 192 o 256.
•
rsa - Clave RSA 1024 o 2048.
•
ecc - Clave pública y privada ECC NIST P192, P224, P256, P384 o P521.
•
-u, --public=ARCHIVO:

La porción pública del objeto, puede ser uno de los siguientes formatos de archivo:

•
TSS - El formato TSS/TPM. Por ejemplo, de la opción -u del comando tpm2_create(1).
•
RSA - Formatos OSSL PEM. Por ejemplo public.pem del comando openssl rsa -in private.pem -out public.pem -pubout
•
ECC - Formatos OSSL PEM. Por ejemplo public.pem del comando openssl ec -in private.ecc.pem -out public.ecc.pem -pubout
•
-r, --private=ARCHIVO:

La porción sensible del objeto, opcional. Si se desea usar la porción privada de una clave, esta debe especificarse. Al igual que la opción -u, este comando acepta archivos en el siguiente formato:

•
RSA - Formatos OSSL PEM. Por ejemplo private.pem del comando openssl genrsa -out private.pem 2048 Dado que una clave pública RSA se puede derivar del archivo PEM privado, no es necesario especificar -u para la porción pública.
•
Formatos PEM de Clave Privada TSS2.

Nota: La porción privada no respeta los formatos TSS, ya que es imposible obtener una salida TPM2B_SENSITIVE de un comando anterior. Siempre están protegidas por el TPM como blobs TPM2B_PRIVATE.

•
-p, --auth=AUTENTICACIÓN:

El valor de autorización para la clave, opcional.

•
-L, --policy=ARCHIVO o CADENA_HEX:

El archivo de política de entrada o la cadena hexadecimal, opcional. Un archivo o cadena hexadecimal que contiene el hash de una política derivada de tpm2_createpolicy u otra fuente generadora de digestos de política.

•
-g, --hash-algorithm=ALGORITMO:

El algoritmo de hash para generar el nombre del objeto. Es opcional y por defecto es sha256 cuando no se especifica. Sin embargo, load external soporta tener un algoritmo de nombre nulo. En este caso, no se realizan comprobaciones criptográficas entre las porciones pública y privada.

•
-a, --attributes=ATRIBUTOS:

Los atributos del objeto, opcional. El valor por defecto para los objetos creados es: TPMA_OBJECT_SIGN_ENCRYPT|TPMA_OBJECT_DECRYPT. Opcionalmente, si se especifica -p o si no se especifica ni -p ni -L, entonces TPMA_OBJECT_USERWITHAUTH se añade al conjunto de atributos por defecto.

Nota: Si se especifican atributos, el TPM rechazará ciertos atributos como TPMA_OBJECT_FIXEDTPM, ya que esas garantías no se pueden hacer.

•
-c, --key-context=ARCHIVO

El nombre del archivo donde guardar el contexto del objeto, obligatorio.

•
-n, --name=ARCHIVO:

Un archivo opcional para guardar el nombre del objeto, que está en formato de hash binario. El tamaño del hash se basa en el algoritmo de nombre o en la opción -g.

•
--passin=OSSL_PEM_FILE_PASSWORD

Una contraseña opcional para un archivo de entrada proporcionado por Open SSL (OSSL). Refleja la opción -passin de OSSL y se sabe que soporta los formatos de contraseña pass, file, env, fd y plain de openssl. (ver man(1) openssl) para más información.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un identificador o un nombre de archivo, se determina según la siguiente lógica en orden:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio del TPM restaurado.
•
Si el argumento es una coincidencia de prefijo con uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de certificación
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un identificador, por ejemplo, 0x81010013 y se utilizará directamente._OBJECT_.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Atributos de Objeto

Los atributos de objeto se utilizan para controlar varias propiedades de los objetos creados. Cuando se especifican como una opción, se puede utilizar la máscara de campo de bits sin procesar o los "nombres amigables". Los valores se pueden encontrar en la Tabla 31, Parte 2 de la especificación TPM2.0, que se puede encontrar aquí:

https://trustedcomputinggroup.org/wp-content/uploads/TPM-Rev-2.0-Part-2-Structures-01.38.pdf

Los nombres amigables se calculan tomando el campo de nombre de la tabla 31 y eliminando el prefijo TPMA_OBJECT_ y convirtiendo el resultado a minúsculas. Por lo tanto, TPMA_OBJECT_FIXEDTPM se convierte en fixedtpm. Los nombres amigables se pueden unir utilizando el símbolo de OR bit a bit “|”.

Por ejemplo, para establecer los campos TPMA_OBJECT_FIXEDTPM, TPMA_OBJECT_NODA y TPMA_OBJECT_SIGN_ENCRYPT, el argumento sería:

fixedtpm|noda|sign especificando los atributos de objeto ATRIBUTOS.

Configuración TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTIs se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTIs conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software TPM.
•
device - Utilizado al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y, por lo tanto, soportan no usar un TCTI. Las herramientas que no lo soportan generarán un error cuando se intenten usar sin una conexión TCTI. No soporta NINGUNA opción y DEBE ser presentado como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<tcti-name>:<tcti-option-config>

Especificar una cadena vacía para el <tcti-name> o el <tcti-option-config> da como resultado que se use el valor predeterminado para esa parte respectivamente.

Valores Predeterminados del TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTIs tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO ENCONTRADO. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para imprimir la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTIs mencionados anteriormente es el predeterminado.

TCTIs Personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica puede ser cargado. Las herramientas utilizan internamente dlopen(3), y el valor crudo tcti-name se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entiende la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI device, se puede especificar el archivo de dispositivo de carácter TPM a utilizar por el TCTI device. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter `,'. Cada clave y valor de cadena están separados por un carácter `=.
•
El TCTI abrmd soporta dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia de dbus (una cadena) limitada a `session' y `system'.

Especifica el nombre del tcti tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifica el tcti predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

NOTAS

•
Si la jerarquía es null o el algoritmo de hash de nombres es null, los tickets producidos utilizando el objeto serán NULL.
•
Si se especifica la porción privada de un objeto, la jerarquía debe ser null o el TPM rechazará cargarlo.

EJEMPLOS

Cargar una clave pública generada por TPM en la jerarquía owner

tpm2_createprimary -c primary.ctx
tpm2_create -C primary.ctx -u pub.dat -r priv.dat
tpm2_loadexternal -C o -u pub.dat -c pub.ctx
name: 000b9be4d7c6193a57e1bfc86a42a6b03856a91d2f9e77c6cbdb796a783d52d4b3b9

Cargar una clave pública RSA en la jerarquía owner

openssl genrsa -out private.pem 2048
openssl rsa -in private.pem -out public.pem -outform PEM -pubout
tpm2_loadexternal -C o -Grsa -u public.pem -c key.ctx
name: 000b7b91d304d16995d42792b57d0fb25df7abe5fdd8afe9950730e00dc5b934ddbc

Cargar un par de claves RSA en la jerarquía null

openssl genrsa -out private.pem 2048
tpm2_loadexternal -C n -Grsa -r private.pem -c key.ctx
name: 000b635ea220b6c62ec1d02343859dd203c8ac5dad82ebc5b124e407d2502f88691f

Cargar una clave AES en la jerarquía null

dd if=/dev/urandom of=sym.key bs=1 count=16
tpm2_loadexternal -C n -Gaes -r sym.key -c key.ctx
name: 000bfc4d8dd7e4f921bcc9dca4b04f49564243cd9def129a3740002bfd4b9e966d34

Cargar clave privada TSS2 en la jerarquía null

tpm2_loadexternal -r tss_privkey.pem -c tss_privkey.ctx
name: 000bc5a216702aca9ba226af1214c50dc4dc33ce6269677aa581ea6d9eec7f27000d

Retornos

Las herramientas pueden devolver alguno de los siguientes códigos:

•
0 - Éxito.
•
1 - Error general no específico.
•
2 - Error en el manejo de opciones.
•
3 - Error de autenticación.
•
4 - Error relacionado con TCTI.
•
5 - Esquema no soportado. Aplicable a tpm2_testparams.
