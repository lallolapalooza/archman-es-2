tpm2_hierarchycontrol(1) Manual de Comandos Generales tpm2_hierarchycontrol(1)

NOMBRE

tpm2_hierarchycontrol(1) - Habilita y deshabilita el uso de una jerarquía y su almacenamiento NV asociado.

SINOPSIS

tpm2_hierarchycontrol [OPCIONES] VARIABLE OPERACION

DESCRIPCIÓN

tpm2_hierarchycontrol(1) - Permite al usuario cambiar phEnable, phEnableNV, shEnable y ehEnable cuando se proporciona la autorización adecuada. La autorización debe ser una de las siguientes: autorización de la jerarquía del propietario, autorización de la jerarquía de respaldo y autorización de la jerarquía de plataforma. Como argumento, la herramienta toma la VARIABLE como bit TPMA_STARTUP_CLEAR y la _OPERACION_ como cadena clear|set para limpiar o establecer el bit de VARIABLE .

Nota: Si falta la opción de contraseña, se asume NULL.

OPCIONES

•
-C, --hierarchy=OBJETO:

Especifica el manejador utilizado para autorizar. Por defecto, es la jerarquía de “plataforma”. Opciones admitidas:

•
o para TPM_RH_OWNER
•
p para TPM_RH_PLATFORM
•
<número> donde se puede usar un número bruto.
•
-P, --hierarchy-auth=AUTH:

Especifica el valor de autorización para la jerarquía.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará el comando, simplemente devolverá un cpHash.

Referencias

Formato de Objeto de Contexto

El tipo de un objeto de contexto, ya sea un manejador o un nombre de archivo, se determina de acuerdo con la siguiente lógica, en orden:

•
Si el argumento es una ruta de archivo, el archivo se carga como un objeto transitorio TPM restaurado.
•
Si el argumento coincide con un prefijo de uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un manejador, por ejemplo, 0x81010013 y se usará directamente._OBJETO_.

Formato de Autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: “Las autorizaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican”.

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación utilizando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en forma de cadena cuando no tienen prefijo.

Cadena

Una contraseña en formato de cadena, especificada por el prefijo “str:” o su ausencia (cadena sin prefijo), no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña en formato de cadena hexadecimal, especificada por el prefijo “hex:”, se convierte de forma hexadecimal a un array de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables para la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo “file:”, debe ser la ruta de un archivo que contenga la contraseña que será leída por la herramienta o un “-” para usar la entrada estándar. Almacenar contraseñas en archivos evita la fuga de información; las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las funciones comunes del historial del shell.

Ejemplos

# para usar stdin y que se le pida
file:-
# para usar un archivo de una ruta
file:ruta/a/archivo/contraseña
# para enviar una contraseña a través de stdin:
echo foobar | tpm2_tool -p file:-
# para usar un here-string de bash a través de stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego, indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación que se envíe con el manejador de sesión (por ejemplo, política de contraseña), agregue un + y una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones PCR

Puede satisfacer una política de PCR usando el prefijo “pcr:” y el minilenguaje PCR. El minilenguaje PCR es el siguiente: <especificación-pcr>=<archivo-pcr-bruto>

La especificación PCR se documenta en la sección “Especificadores de bancos PCR”.

El archivo-pcr-bruto es un argumento opcional que contiene la salida de los contenidos brutos de la PCR tal como se obtienen de tpm2_pcrread(1).

Especificadores de bancos PCR

Ejemplos

Para satisfacer una política de PCR sha256 en los bancos 0, 1, 2 y 3 use un especificador de:

pcr:sha256:0,1,2,3

especificando AUTH.
