tpm2_policycphash(1) Manual de Comandos Generales tpm2_policycphash(1)

NOMBRE

tpm2_policycphash(1) - Vincula una política con los parámetros del comando.

SINOPSIS

tpm2_policycphash [OPCIONES]

DESCRIPCIÓN

tpm2_policycphash(1) - Vincula una política con los parámetros del comando. Esta es una aserción diferida donde el hash de los parámetros del comando en un comando TPM se verifica contra el especificado en la política.

OPCIONES

•
-L, --policy=ARCHIVO:

Archivo donde se guardará el resumen de la política compuesta.

•
-S, --session=ARCHIVO:

El archivo de sesión de política generado a través de la opción -S de tpm2_startauthsession(1).

•
--cphash-input=ARCHIVO:

El archivo que contiene el hash de los parámetros del comando.

•
--cphash=ARCHIVO:

OBSOLETO, usar --cphash-input en su lugar.

Configuración TCTI

El TCTI o "Transmission Interface" es el mecanismo de comunicación con el TPM. Los TCTIs se pueden cambiar para comunicarse con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTIs conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente usado para comunicarse con el simulador de software del TPM.
•
device - Usado al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo soportan generarán un error cuando se intente usar sin una conexión TCTI. No soporta NINGUNA opción y *DEBE* presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opción-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <config-opción-tcti> resulta en el uso del valor predeterminado para esa porción, respectivamente.

Valores Predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTIs tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado usando la opción -v para mostrar la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTIs mencionados es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor bruto nombre-tcti se utiliza para la búsqueda. Por lo tanto, podría ser la ruta a la biblioteca compartida, o un nombre de biblioteca como lo entiende la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo de dispositivo de caracteres del TPM para su uso por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares clave-valor simples separados por un carácter `,`. Cada clave y valor se separan por un carácter `=`.
•
El TCTI abrmd soporta dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de instancia de dbus (una cadena) limitada a `session' y `system'.

Especifica el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifica el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

Define un objeto de índice NV con política autorizada

Aquí se utiliza una política de hash de comando (CPHash) para garantizar que la operación NV Index que se autoriza sea una operación de escritura en el índice NV. Esto requerirá que el archivo nv_index_write_policy.data contenga el hash de los parámetros del comando para la operación de escritura.

tpm2_nvwrite --policy -L nv_index_write_policy.data -Q
        -C o -p 0x1000001 -r 0x1000002 -f firmware.bin

El comando anterior generará el archivo nv_index_write_policy.data que contendrá el hash de los parámetros del comando y el resto de la política de autorización especificada. Una vez que se haya creado este archivo, se puede utilizar para autorizar futuras operaciones. Un ejemplo de cómo se podría hacer esto es:

tpm2_nvwrite --policy -L nv_index_write_policy.data -Q
        -C o -p 0x1000001 -r 0x1000002 -f firmware.bin

Es decir, el comando especificado en el primer ejemplo para generar la política se puede utilizar para ejecutar la operación de escritura una vez que se haya generado el archivo de política.

Para obtener más detalles, consulte el ejemplo en tpm2_nvwrite(1).

EJEMPLOS

Definir objeto de índice NV con política autorizada

openssl genrsa -out signing_key_private.pem 2048
openssl rsa -in signing_key_private.pem -out signing_key_public.pem -pubout
tpm2_loadexternal -G rsa -C o -u signing_key_public.pem -c signing_key.ctx \
-n signing_key.name
tpm2_startauthsession -S session.ctx -g sha256
tpm2_policyauthorize -S session.ctx -L authorized.policy -n signing_key.name
tpm2_flushcontext session.ctx
tpm2_nvdefine 1 -a "policywrite|authwrite|ownerread|nt=bits" -L authorized.policy

Crear policycphash

tpm2_nvsetbits 1 -i 1 --cphash cp.hash
tpm2_startauthsession -S session.ctx -g sha256
tpm2_policycphash -S session.ctx -L policy.cphash --cphash cp.hash
tpm2_flushcontext session.ctx

Firmar y verificar policycphash

openssl dgst -sha256 -sign signing_key_private.pem \
-out policycphash.signature policy.cphash
tpm2_verifysignature -c signing_key.ctx -g sha256 -m policy.cphash \
-s policycphash.signature -t verification.tkt -f rsassa

Satisfacer policycphash y ejecutar nvsetbits

tpm2_startauthsession -S session.ctx --policy-session -g sha256
tpm2_policycphash -S session.ctx --cphash cp.hash
tpm2_policyauthorize -S session.ctx -i policy.cphash -n signing_key.name \
-t verification.tkt
tpm2_nvsetbits 1 -i 1 -P "session:session.ctx"
tpm2_flushcontext session.ctx

Devoluciones

Las herramientas pueden devolver cualquiera de los siguientes códigos:

•
0 - Éxito.
•
1 - Error general no específico.
•
2 - Error de manejo de opciones.
•
3 - Error de autenticación.
•
4 - Error relacionado con TCTI.
•
5 - Esquema no soportado. Aplicable a tpm2_testparams.

Limitaciones

Espera que se establezca una sesión a través de tpm2_startauthsession(1) y requiere una de las siguientes opciones:

•
acceso directo al dispositivo
•
soporte de sesión extendida con tpm2-abrmd.

Sin esto, la mayoría de los administradores de recursos no guardarán el estado de la sesión entre invocaciones de comandos.
