tpm2_setclock(1) Manual de Comandos Generales tpm2_setclock(1)

NOMBRE

tpm2_setclock(1) - Establece la hora en el TPM.

SINOPSIS

tpm2_setclock [OPCIONES] HORA

DESCRIPCIÓN

tpm2_setclock(1) - Establece el reloj del TPM a una hora en el futuro. El único argumento es la hora del reloj como un número para establecer.

OPCIONES

•
-c, --hierarchy=OBJETO:

La jerarquía a usar para autorización, ya sea de plataforma o de propietario. Por defecto, usa la jerarquía del propietario si no se especifica.

•
-p, --auth=AUTENTICACION:

Especifica el valor de autorización para la jerarquía especificada por la opción -c.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se conoce comúnmente como cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash.

Referencias

Formato del objeto de contexto

El tipo de un objeto de contexto, ya sea un manejador o un nombre de archivo, se determina de acuerdo con la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio del TPM restaurado.
•
Si el argumento es una coincidencia de *prefijo* en uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un manejador, por ejemplo, 0x81010013 y se usará directamente._OBJETO_.

Formato de la autenticación

La autenticación para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: Las autenticaciones tienen por defecto la CONTRASEÑA **VACÍA** cuando no se especifican.

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación, utilizando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña en formato de cadena, especificada con el prefijo "str:" o su ausencia (cadena en bruto sin prefijo) no se interpreta y se utiliza directamente para la autenticación.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña en formato de cadena hexadecimal, especificada con el prefijo "hex:", se convierte de formato hexadecimal a formato de array de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no compatibles con la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada con el prefijo "file:", debe ser la ruta de un archivo que contenga la contraseña a leer por la herramienta o un "-" para usar la entrada estándar (stdin). Almacenar contraseñas en archivos evita la fuga de información; las contraseñas pasadas como opciones pueden ser leídas desde la lista de procesos o características comunes del historial del shell.

Ejemplos

# para usar la entrada estándar y que se solicite
file:-
# para usar un archivo desde una ruta
file:ruta/al/archivo/de/contraseña
# para enviar una contraseña a través de la entrada estándar:
echo foobar | tpm2_tool -p file:-
# para usar una cadena de aquí de bash a través de la entrada estándar:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave *session*. Luego, indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación para ser enviado con el manejador de sesión (por ejemplo, contraseña de política), agregue un + seguido de una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones de PCR

Puedes satisfacer una política de PCR usando el prefijo "pcr:" y el minilenguaje de PCR. El minilenguaje de PCR es el siguiente: <especificación-pcr>=<archivo-pcr-crudo>

La especificación de PCR se documenta en la sección "Especificadores de bancos de PCR".

El archivo-pcr-crudo es un argumento **opcional** que contiene la salida del contenido crudo de PCR tal como lo devuelve tpm2_pcrread(1).

Especificadores de bancos de PCR

Ejemplos

Para satisfacer una política de PCR de sha256 en los bancos 0, 1, 2 y 3, usa un especificador de:

pcr:sha256:0,1,2,3

especificando *AUTENTICACIÓN*.

NAME

tpm2_setclock - set the TPM's time and date.

SYNOPSIS

tpm2_setclock [-h|--help] [-V|--version] [-d|--dont-care] [-m|--mctimer] [-o|--reset-due-time] [-e|--startup-clear] [-T|--tcti tcti-name:tcti-option-config] [-c|--cancel hierarchy] [-p|--owner-password owner-password] [-f|--force] [--tcti-device tcti-device] [-l|--log-level log-level] [-q|--quiet] [-Q|--really-quiet] [--hex] [-u|--update update-policy] hierarchy time

DESCRIPTION

tpm2_setclock sets the TPM's time and date. The time is specified in seconds since the TPM's epoch. The epoch is defined by the TPM specification as 1 January 1970 00:00:00 UTC.

The owner password is required to set the clock.

This command supports setting the clock in a TPM which has the Clock capability.

By default the command will attempt to use the TPM2_SetClock command to set the TPM's time. This requires the TPM to have the Clock capability set.

However, tpm2_setclock also supports the following capabilities:

Startup Clear
This capability is set using the -e flag. This requires the TPM to support the Startup Clear capability. It indicates that the TPM should clear all volatile state and reset the clock on the next TPM power on or reset.
Reset Due Time
This capability is set using the -o flag. This requires the TPM to support the Reset Due Time capability. This resets the TPM's time to 0. This is useful for disabling TPM timeouts.
Don't Care
This capability is set using the -d flag. This requires the TPM to support the Don't Care capability. This means the TPM ignores the value passed into the TPM2_SetClock command. This is useful for testing.
MC Timer
This capability is set using the -m flag. This requires the TPM to support the MC Timer capability. This means the TPM will set the time to the value specified in the command. However, the TPM does not change the value of the TPM's time counter. This is useful for testing.

The TPM Hierarchy is specified using the -c flag. This is optional. If not specified, the command will attempt to use the owner hierarchy by default. If the owner hierarchy is not available, the command will error.

The command requires the owner password to be specified using the -p flag.

The command requires the time to be specified using the last argument.

Context Object Format

The context object, which is used to specify the hierarchy, can be specified in one of two formats:

1.
A string containing the hierarchy to use. The valid hierarchies are o, s, e, n.
2.
A file path to a context file. The context file must contain the hierarchy information in the form of a JSON object.

Authorization Formatting

The authorization value can be specified in one of two formats:

1.
A string containing the authorization value.
2.
A file path to a file containing the authorization value.

Note: If the authorization value is specified as a file, the file will be flushed after its use.

The autoflush capability can be enabled by passing the autoflush=true option to the -c command line option. This flushes the context object after it is used.

If a parent object is loaded from a context file, the transient parent object will also be flushed. Autoflush can also be activated if the environment variable TPM2TOOLS_AUTOFLUSH is set to yes or true.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.
