tpm2_policycountertimer(1) Manual de Comandos Generales tpm2_policycountertimer(1)

NOMBRE

tpm2_policycountertimer(1) - Habilita la autorización de políticas evaluando la operación de comparación en los parámetros del TPM tiempo, reloj, contador de reinicios, contador de reinicios y el indicador de reloj seguro del TPM.

SINOPSIS

tpm2_policycountertimer [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_policycountertimer(1) - Habilita la autorización de políticas evaluando la operación de comparación en los parámetros del TPM tiempo, reloj, contador de reinicios, contador de reinicios y el indicador de reloj seguro del TPM. Si es tiempo/reloj, se introduce como un valor en milisegundos. El parámetro y el valor se proporcionan como un argumento de línea de comandos como se indica a continuación:

tpm2_policycountertimer -S session.ctx safe
tpm2_policycountertimer -S session.ctx clock=<N ms>
tpm2_policycountertimer -S session.ctx time=<N ms>
tpm2_policycountertimer -S session.ctx resets=<N>
tpm2_policycountertimer -S session.ctx restarts=<N>

Por defecto, las comparaciones prueban la igualdad y también por defecto prueban el tiempo.

OPCIONES

•
-L, --policy=ARCHIVO:

Archivo donde guardar el resumen de la política.

•
-S, --session=ARCHIVO:

El archivo de sesión de política generado a través de la opción -S de tpm2_startauthsession o guardado de una ejecución anterior de la herramienta.

•
–eq

si el valor del tiempo actual en el TPM = valor del tiempo de entrada especificado.

•
–neq

si el valor del tiempo actual en el TPM != valor del tiempo de entrada especificado.

•
–sgt

si el valor con signo del tiempo actual en el TPM > valor con signo del tiempo de entrada especificado.

•
–ugt

si el valor sin signo del tiempo actual en el TPM > valor sin signo del tiempo de entrada especificado.

•
–slt

si el valor con signo del tiempo actual en el TPM < valor con signo del tiempo de entrada especificado.

•
–ult

si el valor sin signo del tiempo actual en el TPM < valor sin signo del tiempo de entrada especificado.

•
–sge

si el valor con signo del tiempo actual en el TPM >= valor con signo del tiempo de entrada especificado.

•
–uge

si el valor sin signo del tiempo actual en el TPM >= valor sin signo del tiempo de entrada especificado.

•
–sle

si el valor con signo del tiempo actual en el TPM <= valor sin signo del tiempo de entrada especificado.

•
–ule

si el valor sin signo del tiempo actual en el TPM <= valor sin signo del tiempo de entrada especificado.

•
–bs

si todos los bits establecidos en el valor del tiempo actual en el TPM están establecidos en el valor del tiempo de entrada especificado.

•
–bc

si todos los bits establecidos en el valor del tiempo actual en el TPM están borrados en el valor del tiempo de entrada especificado.

•
--cphash=ARCHIVO

Ruta del archivo donde registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará el comando, simplemente devolverá un cpHash.

Configuración TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombres de tcti son sinónimos.
•
mssim - Normalmente se utiliza para comunicarse con el simulador de software del TPM.
•
device - Se utiliza al hablar directamente con un archivo de dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, soportan no usar un TCTI. Las herramientas que no lo soportan generarán un error cuando se intente usarlas sin una conexión TCTI. No soporta NINGUNA opción y DEBE PRESENTARSE como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opción-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <config-opción-tcti> resulta en que se utilice el valor predeterminado para esa porción respectivamente.

Predeterminados TCTI

Cuando no se especifica un TCTI, el TCTI predeterminado se busca utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim **EN ESE ORDEN** y **USARÁN EL PRIMERO** **QUE ENCUENTREN**. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados es el predeterminado.

tpm2_policycountertimer(1) — tpm2-tools documentation

NAME

tpm2_policycountertimer - Create a policy that relies on the TPM’s counter or timer.

SYNOPSIS

tpm2_policycountertimer [-h | --help] [-v | --version] [-c CONTEXT | --context=CONTEXT] [-L POLICY | --policy=POLICY] [-l LEFT_DIGEST | --left=LEFT_DIGEST] [-r RIGHT_DIGEST | --right=RIGHT_DIGEST] [-t TIMEOUT | --timeout=TIMEOUT] [-T TCTI | --tcti=TCTI] [-f FLAGS | --policy-flags=FLAGS] [-q | --quiet] [-Q | --show-hash]

DESCRIPTION

The tpm2_policycountertimer command is used to set up a policy session for the TPM that can be evaluated against the TPM’s counter or timer. The command takes a policy session context and an output policy file. The policy session context may be specified with the -c option, or it may be specified implicitly with the -S option if the session is created using tpm2_startauthsession.

The policy is created and stored in a file specified with the -L option. The policy is calculated based on the provided parameters. The policy digest is then used to set up authorization values for TPM commands that accept a policy digest.

The TPM maintains two independent counters and two timers that can be used for policy evaluations. These are: the permanent counter, the startup counter, the permanent timer, and the startup timer.

The -l and -r options specify the policy digests that are compared against the TPM’s policy digests. By default, the policy digest is calculated based on the session digest and the selected policy values.

The -t option allows for specifying policy values to be set for the TPM’s counter or timer. The values are specified in milliseconds.

The -f option allows specifying policy flags. The policy flags are:

•
counterSeat: The policy session will be associated with the TPM’s permanent counter.
•
timerSeat: The policy session will be associated with the TPM’s permanent timer.
•
exclusiveSession: This flag is used to indicate that the policy session is to be used exclusively for policy evaluation. This means that the session may not be used for other operations like signing.

If neither -l nor -r is specified, the policy digest will be calculated and stored in the output policy file. If they are specified, the command will compare the calculated policy digest with the provided digests.

The command supports specifying a custom TCTI using the -T option. This allows the user to select a specific TPM communication mechanism.

OPTIONS

The following options are available:

•
-h, --help:

Prints the help message and exits.
•
-v, --version:

Prints the version message and exits.
•
-c CONTEXT, --context=CONTEXT:

The policy session context, obtained from tpm2_startauthsession.
•
-L POLICY, --policy=POLICY:

The output file path for the policy digest.
•
-l LEFT_DIGEST, --left=LEFT_DIGEST:

The left-hand side digest for policy comparison.
•
-r RIGHT_DIGEST, --right=RIGHT_DIGEST:

The right-hand side digest for policy comparison.
•
-t TIMEOUT, --timeout=TIMEOUT:

The timeout value in milliseconds. This can be used to specify a time limit for the policy evaluation.
•
-T TCTI, --tcti=TCTI:

The Tagged Command Transmission Interface (TCTI) to use. For example: “device”, “mssim”, or “tabrmd”.
•
-f FLAGS, --policy-flags=FLAGS:

Policy flags. Supported flags are counterSeat, timerSeat, and exclusiveSession. Multiple flags can be specified separated by a comma.
•
-q, --quiet:

Suppresses output except for errors.
•
-Q, --show-hash:

Prints the calculated policy hash.

COMMON OPTIONS

See tpm2_options(7) for options common to all commands.

TCTI Configuration

The TCTI configuration is used to specify how the tool should communicate with the TPM. The TCTI can be specified using the -T option or by setting the TPM2TOOLS_TCTI environment variable.

TCTI Modules

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Create a sealing object with an authorization policy that evaluates only for first minute of TPM restart.

Create the policy and the sealing object

tpm2_startauthsession -S session.ctx
tpm2_policycountertimer -S session.ctx -L policy.countertimer --ult 60000
tpm2_flushcontext session.ctx
tpm2_createprimary -C o -c prim.ctx -Q
echo "SUPERSECRET" | \
tpm2_create -Q -u key.pub -r key.priv -i- -C prim.ctx \
-L policy.countertimer -a "fixedtpm|fixedparent" -c key.ctx

Unsealing should work in the first minute after TPM restart

tpm2_startauthsession -S session.ctx --policy-session
tpm2_policycountertimer -S session.ctx --ult 60000
tpm2_unseal -c key.ctx -p session:session.ctx
tpm2_flushcontext session.ctx

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
