tpm2_readpublic(1) Manual de Comandos Generales tpm2_readpublic(1)

NOMBRE

tpm2_readpublic(1) - Lee el área pública de un objeto cargado.

SINOPSIS

tpm2_readpublic [OPCIONES]

DESCRIPCIÓN

tpm2_readpublic(1) - Lee el área pública de un objeto cargado.

OPCIONES

•
-c, --object-context=OBJETO:

Objeto de contexto para el objeto a leer.

•
-n, --name=ARCHIVO:

Un archivo opcional para guardar la estructura de nombre del objeto.

•
-f, --format:

Selección de formato para el archivo de salida de la clave pública. `tss' (el predeterminado) generará un blob binario según la especificación TPM 2.0. `pem' generará una clave pública codificada en PEM compatible con OpenSSL. `der' generará una clave pública codificada en DER compatible con OpenSSL. `tpmt' generará un blob binario de la estructura TPMT_PUBLIC referenciada por las especificaciones de TPM 2.0.

Formato de la clave pública.

•
-o, --output=ARCHIVO:

La ruta del archivo de salida, que registra la porción pública del objeto.

•
-t, --serialized-handle=MANGO:

Si el objeto a leer es un objeto persistente especificado por un mango bruto, guarda opcionalmente el mango serializado para usarlo más tarde. Esta rutina NO verifica el nombre del objeto que se está leyendo. Los llamantes deben asegurarse de que el contenido del nombre coincida con el nombre esperado del objeto.

•
-q, --qualified-name=ARCHIVO:

Guarda el nombre cualificado del objeto en ARCHIVO. El nombre cualificado del objeto es el hash del algoritmo de nombre del nombre cualificado de los padres y el nombre de los objetos. Por lo tanto, el nombre cualificado del objeto sirve como prueba de los padres del objeto.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un mango o un nombre de archivo, se determina según la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio de TPM restaurado.
•
Si el argumento es una coincidencia de *prefijo* con uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de validación
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un mango, por ejemplo, 0x81010013 y se usará directamente. *OBJETO*.

Configuración TCTI

El TCTI o "Transmission Interface" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Normalmente se utiliza para comunicarse con el simulador de software TPM.
•
device - Se utiliza al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializa una conexión con el TPM. Algunas herramientas permiten opciones fuera de tpm y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo soportan generarán un error cuando se intenten usar sin una conexión TCTI. No admite *NINGUNA* opción y *DEBE* presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<configuración-opción-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <configuración-opción-tcti> da como resultado que se utilice el valor predeterminado para esa parte respectivamente.

Predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim **EN ESE ORDEN** y **USARÁN EL PRIMERO QUE ENCUENTREN**. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor crudo del nombre-tcti se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca como lo entiende la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=

NAME

tpm2_readpublic — read the public structure of a TPM object

SYNOPSIS

tpm2_readpublic [-h handle] [-c context_file] [-o output_file] [-f format] [-t ticket_file] [--tcti=<name>[:<conf>]] [-e hierarchy] [-p password]

DESCRIPTION

The tpm2_readpublic command reads the public structure of a TPM object. This command can take a handle to a loaded object (e.g., from tpm2_load(1) or tpm2_createprimary(1)) or a context file that contains the handle to the object.

The public structure is output to stdout by default, or to a file specified by the -o option.

The public structure can be specified in one of two formats:

•
bytes: The raw bytes of the public structure.
•
pem: The public structure encoded in PEM format. This is useful for interfacing with other tools, such as OpenSSL.

If the object associated with the handle has associated signing keys or endorsement keys, the associated tickets will be read and written out to the file specified by the -t option.

OPTIONS

-h handle
The handle of the object to read the public structure from. This can be a numeric handle (e.g., 0x81000001) or a name (e.g., primary:host).
-c context_file
The context file that contains the handle and potentially the password for the object.
-o output_file
The file to write the public structure to. If not specified, the public structure will be written to stdout.
-f format
The format of the output. Can be bytes or pem. Defaults to bytes.
-t ticket_file
The file to write the associated tickets to. If not specified, the tickets will not be written out.
--tcti=<name>[:<conf>]
Specifies the Tagged Command Transmission Interface (TCTI) to use. This option can be used to specify the TCTI name and its configuration string. Examples include:
•
device: Use the TPM device. The device node path can be specified. Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=”device:/dev/tpm0”
•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

-e hierarchy
The hierarchy to use for the primary object. This can be one of: nv, owner, platform, or storage. This is only applicable when creating a primary object.
-p password
The password for the hierarchy. This is only needed if the hierarchy is sealed.

Context Object Format

The context object file format is a JSON file that contains the following fields:

name
The name of the object. This is a string that represents the object's name.
hierarchy
The hierarchy the object belongs to. This can be one of: nv, owner, platform, or storage.
policy_session
If the object is a policy session, this field will be present and contain the session information.
auth_session
If the object is an auth session, this field will be present and contain the session information.
handle
The handle of the object. This is a hexadecimal string.
password
The password for the object. This is only present if the object is password protected.

Create a primary object and read the public structure in an openssl compliant format

tpm2_createprimary -c primary.ctx
tpm2_readpublic -c primary.ctx -o output.dat -f pem

Serialize an existing persistent object handle to disk for later use

This work-flow is primarily intended for existing persistent TPM objects. This work-flow does not verify that the name of the serialized object matches the expected, and thus the serialized handle could be pointing to an attacker controlled object if no verification is done. If you are creating an object from scratch, save the serialized handle when making the object persistent.

We assume that an object has already been persisted, for example via:

# We assume that an object has already been persisted, for example
tpm2_createprimary -c primary.ctx
# context files have all the information for the TPM to verify the object
tpm2_evictcontrol -c primary.ctx
persistent-handle: 0x81000001
action: persisted

Next use the persistent handle to get a serialized handle:

# The persistent handle output could be at an attacker controlled object,
# best practice is to use the option "-o: for tpm2_evictcontrol to get a
# serialized handle instead.
tpm2_readpublic -c 0x81000001 -o output.dat -f pem -t primary.handle
# use this verified handle in an encrypted session with the tpm
tpm2_startauthsession --policy-session -S session.ctx -c primary.handle

For new objects, its best to use all serialized handles.

Returns

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
