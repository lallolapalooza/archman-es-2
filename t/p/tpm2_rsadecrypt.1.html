tpm2_rsadecrypt(1) Manual de Comandos Generales tpm2_rsadecrypt(1)

NOMBRE

tpm2_rsadecrypt(1) - Realiza una operación de descifrado RSA utilizando el TPM.

SINOPSIS

tpm2_rsadecrypt [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_rsadecrypt(1) - Realiza el descifrado RSA en el contenido del archivo utilizando el esquema de relleno indicado según la RFC 3447 de IETF (PKCS#1). El argumento de línea de comandos por defecto es stdin si no se especifica.

La clave referenciada por el contexto de clave debe ser:

1.
Una clave RSA
2.
Tener el atributo decrypt ESTABLECIDO en sus atributos.

OPCIONES

•
-c, --key-context=OBJETO:

Objeto de contexto que apunta a la porción pública de la clave RSA a utilizar para el descifrado. Puede ser un archivo o un número de identificador. Ver la sección "Formato del Objeto de Contexto".

•
-p, --auth=AUTORIZACION:

Valor de autorización opcional para utilizar la clave especificada con -c.

•
-o, --output=ARCHIVO:

Ruta opcional del archivo de salida para registrar los datos descifrados. Por defecto, los datos binarios descifrados se imprimen en STDOUT.

•
-s, --scheme=FORMATO:

Opcional, establece el esquema de relleno (por defecto es rsaes).

•
null - TPM_ALG_NULL utiliza el esquema de la clave si está establecido.
•
rsaes - TPM_ALG_RSAES que es RSAES_PKCSV1.5.
•
oaep - TPM_ALG_OAEP que es RSAES_OAEP.
•
-l, --label=ARCHIVO O CADENA:

Opcional, establece los datos de la etiqueta. El TPM requiere que el último byte de la etiqueta sea cero, esto se maneja internamente en la herramienta. No pueden existir otros bytes incrustados o el TPM truncará su etiqueta.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará el comando, simplemente devolverá un cpHash.

•
ARGUMENTO El argumento de línea de comandos especifica el archivo que contiene los datos a descifrar.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un identificador o un nombre de archivo, se determina según la siguiente lógica, en orden:

•
Si el argumento es una ruta de archivo, entonces se carga el archivo como un objeto transitorio TPM restaurado.
•
Si el argumento es una coincidencia de prefijo en uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de aprobación
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un identificador, por ejemplo, 0x81010013 y se utilizará directamente. OBJETO.

Formato de Autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autorizaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación utilizando identificadores de prefijo.

Nota: Por defecto, se asume que las contraseñas están en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña en cadena, especificada con el prefijo "str:" o su ausencia (cadena sin prefijo), no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena hexadecimal

Una contraseña en cadena hexadecimal, especificada con el prefijo "hex:", se convierte de un formato hexadecimal a un formato de arreglo de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o poco amigables para la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada con el prefijo "file:", debe ser la ruta de un archivo que contenga la contraseña a leer por la herramienta o un "-" para usar stdin. Almacenar contraseñas en archivos previene fugas de información, las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las características comunes del historial del shell.

Ejemplos

# para usar stdin y ser solicitado
file:-
# para usar un archivo desde una ruta
file:ruta/a/archivo/de/contraseña
# para enviar una contraseña vía stdin:
echo foobar | tpm2_tool -p file:-
# para usar un here-string de bash vía stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al utilizar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego, indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación para ser enviado con el identificador de la sesión (por ejemplo, contraseña de política), añada un + y una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones de PCR

Puede satisfacer una política de PCR utilizando el prefijo "pcr:" y el minilenguaje de PCR. El minilenguaje de PCR se describe a continuación: <especificación-pcr>=<archivo-pcr-crudo>

La especificación de PCR es opcional y contiene la salida de los contenidos brutos del PCR tal como los devuelve tpm2_pcrread(1).

Especificadores del banco de PCR

Ejemplos

Para satisfacer una política de PCR de sha256 en los bancos 0, 1, 2 y 3 utilice un especificador de:

pcr:sha256:0,1,2,3

especificando AUTORIZACIÓN.

Configuración TCTI

El TCTI o "Transmission Interface" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre tiene prioridad sobre la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Se utiliza al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializa una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, soportan no usar un TCTI. Las herramientas que no lo soportan generarán un error cuando se intenten usar sin una conexión TCTI. No soporta NINGUNA opción y DEBE presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<configuración-opción-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <configuración-opción-tcti> da como resultado que se use el valor predeterminado para esa parte respectivamente.

Valores Predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor crudo nombre-tcti se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entiende la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres TPM para su uso por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se pueden especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter ','. Cada cadena de clave y valor se separa por un carácter '='.
•
El TCTI abrmd soporta dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia dbus (una cadena) limitada a `session' y `system'.

Especificar el nombre tcti tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especificar el tcti predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

Crear y cargar una clave RSA

tpm2_createprimary -c primary.ctx
tpm2_create -C primary.ctx -Grsa2048 -u key.pub -r key.priv
tpm2_load -C primary.ctx -u key.pub -r key.priv -c key.ctx

Cifrar usando RSA

echo "my message" > msg.dat
tpm2_rsaencrypt -c key.ctx -o msg.enc msg.dat

Descifrar usando RSA

tpm2_rsadecrypt -c key.ctx -o msg.ptext msg.enc
cat msg.ptext
my message

Retornos

Las herramientas pueden devolver cualquiera de los siguientes códigos:

•
0 - Éxito.
•
1 - Error general no específico.
•
2 - Error en el manejo de opciones.
•
3 - Error de autenticación.
•
4 - Error relacionado con TCTI.
•
5 - Esquema no soportado. Aplicable a tpm2_testparams.
