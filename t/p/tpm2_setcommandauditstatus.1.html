tpm2_setcommandauditstatus(1) Manual de Comandos Generales tpm2_setcommandauditstatus(1)

NOMBRE

tpm2_setcommandauditstatus(1) - Añadir o eliminar comandos TPM2 de la lista de comandos auditados.

SINOPSIS

tpm2_setcommandauditstatus [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_setcommandauditstatus(1) - Añadir o eliminar comandos TPM2 de la lista de comandos auditados.

Como argumento toma el comando como un valor entero o una cadena amigable. El mapeo de cadena amigable a CÓDIGO DE COMANDO se puede encontrar en la sección MAPEO DE CÓDIGOS DE COMANDO.

OPCIONES

•
-C, --hierarchy=OBJETO:

Especificar la jerarquía del propietario o de la plataforma. Por defecto es TPM_RH_OWNER, cuando no se ha especificado ningún valor. Las opciones soportadas son:

•
o para TPM_RH_OWNER
•
p para TPM_RH_PLATFORM
•
-P, --hierarchy-auth=AUTH: Especifica el valor de autorización para la jerarquía. Los valores de autorización deben seguir las "normas de formato de autorización", véase la sección "Formato de Autorización".
•
-c, --clear-list: Especifica que el comando TPM especificado debe ser eliminado de la lista de auditoría. Cuando no se especifica, el comportamiento por defecto es añadir el comando TPM a la lista de auditoría.
•
-g, --hash-algorithm=ALGORITMO:

Configura el algoritmo de hash para el resumen de auditoría. Cuando no se especifica, el algoritmo por defecto del resumen de auditoría se establece en SHA256.

•
ARGUMENTO el argumento de la línea de comandos especifica el código de comando TPM2.

Configuración TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre tiene prioridad sobre la variable de entorno.

Los TCTI actualmente conocidos son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Utilizado al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y por lo tanto soportan no usar un TCTI. Las herramientas que no lo soportan darán error cuando se intenten usar sin una conexión TCTI. No soporta *NINGUNA* opción y *DEBE* ser presentado como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o el <config-opciones-tcti> resulta en que se use el valor por defecto para esa parte respectivamente.

Valores predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI por defecto utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim **EN ESE ORDEN** y **USARÁN EL PRIMERO QUE ENCUENTREN**. Puede consultar qué TCTI se elegirá como valor predeterminado utilizando la opción -v para mostrar la información de versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs Personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica puede ser cargado. Las herramientas utilizan internamente dlopen(3), y el valor crudo tcti-name se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entienda la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres TPM a utilizar por el TCTI de dispositivo. El valor por defecto es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores por defecto son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares clave-valor simples separados por un carácter `,'. Cada clave y valor se separan por un carácter `= `.
•
El TCTI abrmd soporta dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia de dbus (una cadena) limitada a `session' y `system'.

Especificar el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.

NAME

tpm2_setcommandauditstatus

set the command audit status, command code audit status and command hash algorithm.

SYNOPSIS

tpm2_setcommandauditstatus [-u|--audit-command-code] [-a|--audit-command-hash] [-S session] [-c] [command...]

DESCRIPTION

The tpm2_setcommandauditstatus command is used to set the command audit status, command code audit status and command hash algorithm. If no commands are specified, the command audit status of all commands are set. All commands that have not been explicitly specified will have their command audit status set to FALSE.

The command audit status dictates whether the TPM should log commands executed via the TPM. The command code audit status dictates whether the command code of the command is part of the digest logged by the TPM. The command hash algorithm dictates which hash algorithm is used to digest the logged command code. The hash algorithm is a part of the audit digest.

The command audit status controls whether the TPM logs commands executed using the TPM. When the command audit status is enabled, the TPM logs the command code and command attributes for each command that is executed. This log can be later retrieved using the tpm2_getcommandauditdigest(1) command.

The command code audit status flag determines if the command code itself is part of the hash digest computed by the TPM. If set, the command code is included in the audit digest.

The command hash algorithm is used to compute the audit digest. The TPM supports multiple hash algorithms, and the one specified here will be used for generating the audit digest. If not specified, the TPM defaults to a specific hash algorithm (e.g. SHA-256).

OPTIONS

The options below determine what command audit status is set.

-u, --audit-command-code
If set, the command code audit status is enabled. If not set, the command code audit status is disabled.
-a, --audit-command-hash
This option can be used multiple times to specify which hash algorithms are to be used for auditing. The list of supported hash algorithms can be obtained using the tpm2_getcap command.
Example:
tpm2_setcommandauditstatus -a sha256 -a sha160 TPM2_CC_GetRandom

The following options are general purpose and used by most TPM commands.

COMMON OPTIONS

-S, --session=session
The session is a policy session file that is generated by tpm2_startauthsession(1).
-c, --clear
When this option is specified, the command audit status is cleared. This means that the TPM will stop auditing commands. All command audit status flags are set to FALSE. This option is mutually exclusive with other options.

The following options are used to select the TCTI device.

TCTI Configuration

The following options are used to specify the TCTI Module.

TCTI OPTIONS

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

hash algorithm options collection of options to specify hash algorithm.

EXAMPLES

Add TPM2_CC_Unseal to the list of audited commands.

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
