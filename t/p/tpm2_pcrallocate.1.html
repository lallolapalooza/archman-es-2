tpm2_pcrallocate(1) Manual de comandos generales tpm2_pcrallocate(1)

NOMBRE

tpm2_pcrallocate(1) - Configura PCRs y algoritmos de banco.

SINOPSIS

tpm2_pcrallocate [OPCIONES] [*ARGUMENTO]

DESCRIPCIÓN

tpm2_pcrallocate(1) - Permite al usuario especificar una asignación de PCR para el TPM. Una asignación es la habilitación o deshabilitación de PCRs y sus bancos. Un PCR puede tener múltiples bancos, donde cada banco está asociado con un algoritmo de hash específico. La asignación se especifica en el argumento.

Si no se proporciona ninguna asignación, se asignan los bancos SHA1 y SHA256 con los PCRs 0 a 23.

La asignación es una lista de bancos y PCRs seleccionados. Los valores deben seguir los estándares de especificadores de bancos de PCR, ver la sección "Especificadores de bancos de PCR".

Las nuevas asignaciones serán efectivas después del próximo reinicio.

Nota: Este comando requiere autorización de plataforma.

OPCIONES

•
-P, --auth=AUTH:

Valor de autorización opcional. Los valores de autorización deben seguir los "estándares de formato de autorización", ver la sección "Formato de autorización".

•
ARGUMENTO el argumento de línea de comandos especifica la asignación de PCR.
•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash.

Referencias

Formato de Objeto Contexto

El tipo de un objeto de contexto, ya sea un manejador o un nombre de archivo, se determina según la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, el archivo se carga como un objeto transitorio del TPM restaurado.
•
Si el argumento es una coincidencia de *prefijo* en uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento se puede cargar como un número, se tratará como un manejador, por ejemplo, 0x81010013 y se usará directamente._OBJETO_.

Formato de Autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autorizaciones se establecen por defecto en la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación usando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña en formato de cadena, especificada con el prefijo "str:" o su ausencia (cadena sin prefijo), no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena hexadecimal

Una contraseña en formato de cadena hexadecimal, especificada con el prefijo "hex:", se convierte de forma hexadecimal a un array de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables para la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada con el prefijo "file:" debe ser la ruta de un archivo que contenga la contraseña que será leída por la herramienta o un "-" para usar stdin. Almacenar contraseñas en archivos evita la fuga de información; las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las características comunes del historial del shell.

Ejemplos

# para usar stdin y que se solicite
file:-
# para usar un archivo desde una ruta
file:ruta/a/archivo/contraseña
# para enviar una contraseña vía stdin:
echo foobar | tpm2_tool -p file:-
# para usar una cadena aquí de bash vía stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al utilizar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave *session*. Luego indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autorización que se enviará con el manejador de la sesión (por ejemplo, contraseña de política), agregue un + y una cadena como se describe en la sección de Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización *HEX* 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones de PCR

Puede satisfacer una política de PCR usando el prefijo "pcr:" y el minilenguaje de PCR. El minilenguaje de PCR es el siguiente: <especificador-pcr>=<archivo-pcr-crudo>

El especificador de PCR se documenta en la sección "Especificadores de bancos de PCR".

El archivo-pcr-crudo es un argumento opcional que contiene la salida del contenido crudo del PCR tal como lo devuelve tpm2_pcrread(1).

Especificadores de bancos de PCR

Ejemplos

Para satisfacer una política de PCR de sha256 en los bancos 0, 1, 2 y 3, use un especificador de:

pcr:sha256:0,1,2,3

especificando *AUTH*.

Especificadores de Algoritmo

Las opciones que toman algoritmos admiten "nombres amigables".

Hay dos clases principales de cadenas de especificación de algoritmos, simples y complejas. Solo ciertos algoritmos serán aceptados por el TPM, según el uso y las condiciones.

NAME

tpm2_pcrallocate — allocate PCR banks

SYNOPSIS

tpm2_pcrallocate [-T tcti-name] [-P auth] [-c context-file] [-g digest-algorithm] [-o output-file] [-f format] [-Q] [-S session-file] [-U update-auth] [-v] [-z] [-Z] [-R]

DESCRIPTION

tpm2_pcrallocate is used to allocate PCR banks. The allocation of PCR banks can be done in two ways: dynamically or statically.

Dynamically, the allocation can be done with default values, or it can be customized by specifying the PCR banks to be allocated, and optionally the size of the PCR bank (which is the size of the digest algorithm).

Statically, the allocation can be done by either deleting all the dynamically allocated PCR banks, or by disabling the allocation of PCR banks altogether.

A list of the available PCR banks can be obtained by using the command:

tpm2_pcrallocate -l.

OPTIONS

•
-l, --list: List of PCR banks that are currently allocated.
•
-P, --platform-auth auth: The platform authorization policy. This will be a hexadecimal string.
•
-c, --context-file context-file: Loads context data from a file. Can be used to load the primary key, policy, or other data from a file.
•
-g, --digest-algorithm digest-algorithm: The digest algorithm to use. The default is sha256. The list of supported algorithms are: sha1, sha256, sha384, sha512, sm3_256.
•
-o, --output-file output-file: The file to write the context data to. The file will be written in the canonical format.
•
-f, --format format: The format of the output file. The default is raw. Supported formats: raw, yaml.
•
-Q, --quiet: Suppress progress messages and print only errors.
•
-S, --session-file session-file: The session file to use. This is used to load sessions that are already open.
•
-U, --update-auth update-auth: Updates the authorization policy for the specified object. Can be used for the primary key, policy, or other data.
•
-v, --verbose: Enable verbose output, printing useful information from the tool.
•
-z, --take-ownership: Takes ownership of the TPM. This will set the desired owner authorization policy.
•
-Z, --enable-errata: Enable the application of errata fixups. Useful if an errata fixup needs to be applied to commands sent to the TPM. Defining the environment TPM2TOOLS_ENABLE_ERRATA is equivalent.
•
-R, --autoflush: Enable autoflush for transient objects created by the command. If a parent object is loaded from a context file also the transient parent object will be flushed. Autoflush can also be activated if the environment variable TPM2TOOLS_AUTOFLUSH is is set to yes or true. information many users may expect.

Context Object Format

The format for context objects is a comma separated list of key-value pairs. The key is the object type, and the value is the filename containing the object.

primary:primary.ctx,policy:policy.ctx

Authorization Formatting

The authorization value can be provided in different formats:

•
hex:0x1234567890abcdef: a hexadecimal string.
•
file:auth.txt: the authorization value is read from a file.
•
env:TPM2_OWNER_AUTH: the authorization value is read from an environment variable.

If no authorization is provided, the tool will try to read the authorization value from the environment variable TPM2_OWNER_AUTH.

Algorithm Specifiers

When specifying algorithm names, they can be provided in the following formats:

•
sha1: SHA-1 hash algorithm.
•
sha256: SHA-256 hash algorithm.
•
sha384: SHA-384 hash algorithm.
•
sha512: SHA-512 hash algorithm.
•
sm3_256: SM3 hash algorithm.

Object Attributes

The object attributes are a set of flags that define the properties of the object. The attributes are specified as a hexadecimal number.

For a list of available attributes, please refer to the TPM 2.0 specification.

PCR Bank Specifiers

PCR banks can be specified in the following format:

<digest-algorithm>:<pcr-list>

Where:

•
<digest-algorithm> is one of the supported digest algorithms (e.g., sha1, sha256).
•
<pcr-list> is a comma separated list of PCR indices, or the keyword 'all' to specify all PCRs, or 'none' to specify no PCRs.

Example:

sha256:0,1,2,3+sha1:4,5,6

This specifies that PCRs 0-3 should be allocated for SHA-256, and PCRs 4-6 should be allocated for SHA-1.

If a digest algorithm is specified without a PCR list, it defaults to allocating all PCRs for that algorithm.

If a digest algorithm is specified with none, it means that no PCRs should be allocated for that algorithm.

COMMON OPTIONS

•
-Z, --enable-errata: Enable the application of errata fixups. Useful if an errata fixup needs to be applied to commands sent to the TPM. Defining the environment TPM2TOOLS_ENABLE_ERRATA is equivalent.
•
-R, --autoflush: Enable autoflush for transient objects created by the command. If a parent object is loaded from a context file also the transient parent object will be flushed. Autoflush can also be activated if the environment variable TPM2TOOLS_AUTOFLUSH is is set to yes or true. information many users may expect.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

To allocate the two default banks (SHA1 and SHA256)

tpm2_pcrallocate

To make a custom allocation with a platform authorization

tpm2_pcrallocate -P abc sha1:7,8,9,10,16,17,18,19+sha256:all

To completly switch from SHA1 bank to SHA256 with a platform authorization

tpm2_pcrallocate -P abc sha1:none+sha256:all

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.
