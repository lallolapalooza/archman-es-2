tpm2_changeeps(1) Manual de comandos generales tpm2_changeeps(1)

NOMBRE

tpm2_changeeps(1) - Reemplaza la semilla primaria de aprobación activa con una nueva generada a partir de la RNG del TPM2.

SINOPSIS

tpm2_changeeps [OPCIONES]

DESCRIPCIÓN

tpm2_changeeps(1) - Reemplaza la semilla primaria de aprobación activa con una nueva generada a partir de la RNG del TPM2. Los objetos Transitorios y Permanentes bajo la jerarquía de aprobación se pierden. Este comando requiere autenticación de plataforma.

OPCIONES

•
-p, --auth=AUTH

Especifica la autenticación AUTH para la jerarquía de plataforma.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará el comando, simplemente devolverá un cpHash, a menos que también se requiera rphash.

•
--rphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros de respuesta. Esto se denomina comúnmente rpHash.

•
-S, --session=ARCHIVO:

La sesión creada usando tpm2_startauthsession. Esto se puede usar para especificar una sesión auxiliar para auditoría y/o cifrado/descifrado de parámetros.

Referencias

Formato de Autenticación

La autenticación para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autenticaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación utilizando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña en formato de cadena, especificada por el prefijo "str:" o su ausencia (cadena sin procesar sin prefijo) no se interpreta y se utiliza directamente para la autenticación.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña en formato de cadena hexadecimal, especificada por el prefijo "hex:", se convierte de una forma hexadecimal a una forma de matriz de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables para la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo "file:", debería ser la ruta de un archivo que contenga la contraseña a leer por la herramienta o un "-" para usar stdin. Almacenar contraseñas en archivos evita la fuga de información, las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las funciones comunes del historial de shell.

Ejemplos

# para usar stdin y ser solicitado
file:-
# para usar un archivo desde una ruta
file:ruta/a/archivo/de/contraseña
# para enviar una contraseña a través de stdin:
echo foobar | tpm2_tool -p file:-
# para usar una cadena aquí de bash a través de stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego, indique una ruta a un archivo de sesión que fue creado con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación para ser enviado con el identificador de sesión (por ejemplo, contraseña de política), agregue un + y una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autenticaciones de PCR

Puedes satisfacer una política de PCR usando el prefijo "pcr:" y el minilenguaje de PCR. El minilenguaje de PCR es el siguiente: <especificador-pcr>=<archivo-pcr-crudo>

El especificador de PCR se documenta en la sección "especificadores de banco de PCR".

El archivo-pcr-crudo es un argumento opcional que contiene la salida de los contenidos crudos de PCR tal como los devuelve tpm2_pcrread(1).

Especificadores de banco de PCR

Ejemplos

Para satisfacer una política de PCR de sha256 en los bancos 0, 1, 2 y 3 usa un especificador de:

pcr:sha256:0,1,2,3

especificando AUTH.

Configuración TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre tiene prioridad sobre la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente usado para comunicarse con el simulador de software del TPM.
•
device - Usado cuando se habla directamente con un archivo de dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo soportan darán error cuando se intenten usar sin una conexión TCTI. No soporta NINGUNA opción y DEBE SER presentado como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen la forma:

<nombre-tcti>:<configuración-opción-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <configuración-opción-tcti> resulta en el uso del valor predeterminado para esa parte respectivamente.

Valores Predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado usando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO ENCONTRADO. Puedes consultar qué TCTI se elegirá como predeterminado usando la opción -v para

NAME

tpm2_changeeps change the endorsement primary seed

SYNOPSIS

tpm2_changeeps [OPTIONS]

DESCRIPTION

The TPM has a primary seed value known as the Endorsement Primary Seed (EPS). The TPM specification requires that the EPS be changeable only once during the lifetime of the TPM. This command is used to change the EPS.

The command will prompt the user for the new EPS value. The value must be a 16-byte value. The user is prompted twice to prevent typos.

The tpm2_changeeps command is used to change the Endorsement Primary Seed (EPS) on the TPM. The EPS is a critical security parameter that is used to generate the primary keys for the TPM. Changing the EPS is a one-time operation that can only be performed once during the lifetime of the TPM.

The command requires the platform authorization to be NULL. This means that no platform authorization value is needed to execute the command.

The command will prompt the user to enter the new EPS value twice. The EPS value must be exactly 16 bytes in length. If the entered values do not match or are not 16 bytes long, the command will fail.

After successfully changing the EPS, the TPM will be reset. This means that all session state and other TPM context will be lost.

To avoid issues with the platform authorization value, the command will use a NULL authorization value. This means that no password or other authorization value is required to use this command.

The following is a list of the command line options available:

Authorization Formatting

The authorization value for the platform hierarchy is specified using the -P option. The format for the authorization value is a string.

--auth=P[type]:[value]

Where type is one of the following:

pm:
Platform hierarchy password.
pr:
Platform hierarchy policy digest.

The value is the actual authorization value.

For example, to specify a platform password of MyPassword, use:

--auth=Ppm:MyPassword

If the authorization value is not specified, it defaults to NULL.

TCTI Configuration

The TPM communication interface (TCTI) can be configured using the -T option or the TPM2TOOLS_TCTI environment variable. The TCTI specifies how the tpm2-tools will communicate with the TPM device.

The following TCTIs are available:

device:
Direct communication with the TPM device file (e.g., /dev/tpm0).
mssim:
Communication with the TPM simulator.
abrmd:
Communication with the tpm2-abrmd daemon.

The default TCTI is device.

You can specify the TCTI as follows:

--tcti=device:/dev/tpm0
--tcti=mssim:host=localhost,port=2321
--tcti=abrmd:bus_name=com.example.Tpm2Daemon

The TPM2TOOLS_TCTI environment variable can also be used to set the default TCTI.

If multiple TCTIs are specified, the last one specified will be used. The -T option takes precedence over the TPM2TOOLS_TCTI environment variable.

The tpm2_changeeps command will print the version information. The default-tcti key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,` character. Each key and value string are separated by a `=` character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Change the endorsement primary seed where the platform auth is NULL.

tpm2_changeeps

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
