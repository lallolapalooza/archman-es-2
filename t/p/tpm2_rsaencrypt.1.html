tpm2_rsaencrypt(1) Manual de Comandos Generales tpm2_rsaencrypt(1)

NOMBRE

tpm2_rsaencrypt(1) - Realiza una operación de cifrado RSA utilizando el TPM.

SINOPSIS

tpm2_rsaencrypt [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_rsaencrypt(1) - Realiza el cifrado RSA en los contenidos del archivo de datos utilizando el esquema de relleno indicado según IETF RFC 3447 (PKCS#1). La entrada por defecto es STDIN si no se especifica.

La clave referenciada por el contexto de clave se requiere que sea:

1.
Una clave RSA
2.
Tenga el atributo encrypt ACTIVADO en sus atributos.

OPCIONES

•
-c, --key-context=OBJETO:

Objeto de contexto que apunta a la porción pública de la clave RSA a utilizar para el cifrado.

•
-o, --output=ARCHIVO:

Ruta opcional del archivo de salida para registrar los datos cifrados. Por defecto, se imprimen los datos cifrados binarios en la salida estándar.

•
-s, --scheme=FORMATO:

Opcional, establece el esquema de relleno (por defecto es rsaes).

•
null - TPM_ALG_NULL usa el esquema de la clave si está establecido.
•
rsaes - TPM_ALG_RSAES que es RSAES_PKCSV1.5.
•
oaep - TPM_ALG_OAEP que es RSAES_OAEP.
•
-l, --label=ARCHIVO o CADENA:

Opcional, establece los datos de la etiqueta. Puede ser una cadena o una ruta de archivo. El TPM requiere que el último byte de la etiqueta sea cero, esto se maneja internamente en la herramienta. No puede haber otros bytes 0 incrustados o el TPM truncará su etiqueta.

•
ARGUMENTO el argumento de la línea de comandos especifica la ruta del archivo con los datos a cifrar.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un manejador o un nombre de archivo, se determina de acuerdo con la siguiente lógica en orden:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto TPM transitorio restaurado.
•
Si el argumento es una coincidencia de prefijo con uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un manejador, por ejemplo, 0x81010013 y se utilizará directamente._OBJETO_.

Formato de Autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: Las autorizaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican.

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación utilizando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña en formato de cadena, especificada con el prefijo "str:" o su ausencia (cadena cruda sin prefijo) no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena hexadecimal

Una contraseña en formato de cadena hexadecimal, especificada con el prefijo "hex:", se convierte de un formato hexadecimal a un formato de array de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables para la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada con el prefijo "file:", debería ser la ruta de un archivo que contenga la contraseña a leer por la herramienta o un "-" para usar la entrada estándar. Almacenar contraseñas en archivos evita fugas de información, las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las características comunes del historial del shell.

Ejemplos

# para usar stdin y que se le solicite
file:-
# para usar un archivo de una ruta
file:ruta/al/archivo/de/contraseña
# para hacer eco de una contraseña vía stdin:
echo foobar | tpm2_tool -p file:-
# para usar un here-string de bash vía stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego indique una ruta a un archivo de sesión que fue creado con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación para ser enviado con el manejador de sesión (por ejemplo, contraseña de política), entonces agregue un + y una cadena como se describe en la sección de Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones PCR

Puede satisfacer una política de PCR usando el prefijo "pcr:" y el minilenguaje PCR. El minilenguaje PCR es el siguiente: <especificador-pcr>=<archivo-pcr-crudo>

El especificador de PCR se documenta en la sección "Especificadores de banco PCR".

El archivo-pcr-crudo es un argumento opcional que contiene la salida del contenido crudo del PCR devuelto por tpm2_pcrread(1).

Especificadores de banco PCR

Ejemplos

Para satisfacer una política de PCR de sha256 en los bancos 0, 1, 2 y 3 use un especificador de:

pcr:sha256:0,1,2,3

especificando AUTH.

tpm2_rsaencrypt(1) — tpm2-tools documentation

NAME

tpm2_rsaencrypt, tpm2_rsadecrypt - encrypt and decrypt data with an RSA key

SYNOPSIS

tpm2_rsaencrypt [OPTIONS] [-c CONTEXT] [-u PUBLICKEY] [-o OUTPUT] [INPUT]

tpm2_rsadecrypt [OPTIONS] [-c CONTEXT] [-r PRIVATEKEY] [-o OUTPUT] [INPUT]

DESCRIPTION

The tpm2_rsaencrypt command will encrypt the INPUT data using the specified RSA key in CONTEXT or PUBLICKEY. The output will be written to OUTPUT.

The tpm2_rsadecrypt command will decrypt the INPUT data using the specified RSA key in CONTEXT or PRIVATEKEY. The output will be written to OUTPUT.

The RSA key may be loaded from a file using the -c option. The key may also be specified using the -u option for encryption or the -r option for decryption. For commands that load keys from files, the key is loaded into a persistent context.

The INPUT and OUTPUT arguments are optional. If INPUT is not specified, then it defaults to stdin. If OUTPUT is not specified, then it defaults to stdout.

The key size and padding scheme are determined by the key loaded into the context. The supported key sizes are 1024, 2048, 3072, and 4096 bits. The supported padding schemes are Null, OAEP, and PKCS#1.1.5.

The size of the input data must be less than or equal to the key size minus the size of the padding scheme. For example, for a 2048-bit key with OAEP padding, the maximum input size is 2048 / 8 - 42 = 214 bytes.

For a full list of padding schemes and their sizes, see tpm2_print.

OPTIONS

The options are divided into the following groups:

Context Object Format

-c, --context OBJECT
Load a context object from OBJECT. The context object may be a primary context, a key context, or a policy context. The context object is loaded into the TPM. The context may be a file path to a context blob generated by tpm2_create or tpm2_load. The context may also be a file path to a primary context blob generated by tpm2_createprimary.

Authorization Formatting

-P, --auth AUTH
The authorization value for the object. The format of AUTH depends on the type of authorization the object is using. For example, for HMAC authorization, the format is `hmac:value'. For password authorization, the format is `password:value'.
--auth-file AUTH_FILE
The authorization value for the object loaded from AUTH_FILE.

COMMON OPTIONS

These options are common to all tools in the tpm2-tools suite.

•
-h, --help: Display help information.

Note that errors are printed to stderr. When the tool exits with a non-zero exit code, the short options will be output to stdout.

•
-v, --version: Display version information for this tool, supported tctis and exit.
•
-V, --verbose: Increase the information that the tool prints to the console during its execution. When using this option the file and line number are printed.
•
-Q, --quiet: Silence normal tool output to stdout.
•
-Z, --enable-errata: Enable the application of errata fixups. Useful if an errata fixup needs to be applied to commands sent to the TPM. Defining the environment TPM2TOOLS_ENABLE_ERRATA is equivalent.
•
-R, --autoflush: Enable autoflush for transient objects created by the command. If a parent object is loaded from a context file also the transient parent object will be flushed. Autoflush can also be activated if the environment variable TPM2TOOLS_AUTOFLUSH is is set to yes or true. information many users may expect.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Create an RSA key and load it

tpm2_createprimary -c primary.ctx
tpm2_create -C primary.ctx -Grsa2048 -u key.pub -r key.priv
tpm2_load -C primary.ctx -u key.pub -r key.priv -c key.ctx

Encrypt using RSA

echo "my message" > msg.dat
tpm2_rsaencrypt -c key.ctx -o msg.enc msg.dat

Decrypt using RSA

tpm2_rsadecrypt -c key.ctx -o msg.ptext msg.enc
cat msg.ptext
my message
