tpm2_policylocality(1) Manual de Comandos Generales tpm2_policylocality(1)

NOMBRE

tpm2_policylocality(1) - Restringe la autorización de objetos TPM a localidades específicas.

SINOPSIS

tpm2_policylocality [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_policylocality(1) - Restringe la autorización de objetos TPM a una localidad TPM específica. Útil cuando se desea permitir solo una localidad específica con el objeto TPM. Una localidad indica la fuente del comando, por ejemplo, podría ser de la capa de aplicación o de la capa del controlador, cada una tendría su propio entero de localidad. Las localidades son pistas para el TPM y son aplicadas por el software que se comunica con el TPM. Por lo tanto, no son entradas de confianza por sí mismas y se implementan de maneras específicas de la plataforma.

Como argumento, toma la LOCALIDAD como un entero o un nombre amigable.

Las localidades tienen un tamaño fijo de un byte y tienen dos representaciones, localidad y localidad extendida.

Las localidades 0 a 4 son la representación de localidad normal y se representan como índices de bits establecidos. Por lo tanto, la localidad 0 se indica mediante 1<<0 y la localidad 4 se indica mediante 1<<4. En lugar de usar números brutos, estas localidades también se pueden especificar con los nombres amigables de: - zero: localidad 0 o 1<<0 - one: localidad 1 o 1<<1 - two: localidad 2 o 1<<2 - three: localidad 3 o 1<<3 - four: localidad 4 o 1<<4

Cualquier cosa en el rango de 32 a 255 son localidades extendidas.

OPCIONES

•
-S, --session=ARCHIVO:

Un archivo de sesión de la opción -S de tpm2_startauthsession(1).

•
-L, --policy=ARCHIVO:

Archivo donde guardar el digest de la política.

•
ARGUMENTO el argumento de la línea de comandos especifica el número de localidad.
•
--cphash=ARCHIVO

Ruta del archivo donde registrar el hash de los parámetros del comando. Esto se conoce comúnmente como cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash.

Configuración TCTI

El TCTI, o 'Interfaz de Transmisión', es el mecanismo de comunicación con el TPM. Los TCTIs se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre tiene prioridad sobre la variable de entorno.

Los TCTIs conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombres de tcti son sinónimos.
•
mssim - Típicamente usado para comunicarse con el simulador de software TPM.
•
device - Usado al hablar directamente con el archivo de dispositivo TPM.
•
none - No inicializa una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y por lo tanto soportan no usar un TCTI. Las herramientas que no lo soportan generarán un error cuando se intenten usar sin una conexión TCTI. No soporta NINGUNA opción y DEBE SER presentado como el texto exacto de 'none'.

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opcion-tcti>

Especificar una cadena vacía para el <nombre-tcti> o <config-opcion-tcti> resulta en el uso del valor predeterminado para esa porción respectivamente.

Valores Predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado usando la semántica de dlopen(3). Las herramientas buscarán los TCTIs tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor 'default-tcti' indicará cuál de los TCTIs mencionados anteriormente es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor bruto nombre-tcti se usa para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entendido por la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres TPM para usarlo con el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter ','. Cada clave

TCTI Configuration

The TCTI (TPM Command Transmission Interface) is a module that allows the tpm2-tools to communicate with the TPM device. It abstracts the underlying communication mechanism. There are several types of TCTI modules available:

•
mssim: This TCTI is for connecting to a TPM simulator. It requires a host and port configuration. Example:

--tcti='mssim:host=127.0.0.1,port=1234'

•
socket: This TCTI is for connecting to a remote TPM via a TCP socket. It also requires host and port configuration. Example:

--tcti='socket:host=remote.example.com,port=8080'

•
mssap: This TCTI is for connecting to a TPM on a remote host using the libtssap library. It requires a host and port. Example:

--tcti='mssap:host=remote.example.com,port=2321'

•
device: This TCTI is used to access the TPM device directly, typically via a character device like /dev/tpm0. Example:

--tcti=device

or with a specific device path:

--tcti='device:/dev/tpmrm0'

•
ldev: Similar to the device TCTI, this one is used for direct device access, often in environments where the resource manager is not present or not used. Example:

--tcti=ldev

•
libtpms: This TCTI connects to the libtpms emulator. It requires a socket path. Example:

--tcti='libtpms:unix=/path/to/libtpms.sock'

•
tcti-local: This is a special meta-TCTI that can be used to select another TCTI based on configuration. It is often used internally by other tools. Example:

--tcti='tcti-local:tcti=device'

•
abrmd: This TCTI connects to the system's TPM Resource Manager daemon (tpm2-abrmd). It can be configured with bus_name and bus_type. Example:

--tcti=abrmd:bus_type=session

•
tabrmd: This TCTI is synonymous with the abrmd TCTI. It also connects to the tpm2-abrmd daemon. Example:

--tcti=tabrmd:bus_name=com.example.tpm

The configuration for TCTIs is provided as a string after the TCTI name, separated by a colon (:). For TCTIs that accept multiple parameters, these parameters are provided as key-value pairs, separated by commas (,), where the key and value string are separated by an = character.

•
abrmd supports two keys:
1.
bus_name : The name of the tabrmd service on the bus (a string).
2.
bus_type : The type of the dbus instance (a string) limited to session and system.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Start a policy session and extend it with a specific locality number (like 3). Attempts to perform other operations would fail.

Create an policy restricted by locality 3

tpm2_startauthsession -S session.dat
tpm2_policylocality -S session.dat -L policy.dat three
tpm2_flushcontext session.dat

Create the object with auth policy

tpm2_createprimary -C o -c prim.ctx
tpm2_create -C prim.ctx -u sealkey.pub -r sealkey.priv -L policy.dat \
-i- <<< "SEALED-SECRET"

Try unseal operation

tpm2_load -C prim.ctx -u sealkey.pub -r sealkey.priv -n sealkey.name \
-c sealkey.ctx
tpm2_startauthsession \--policy-session -S session.dat
tpm2_policylocality -S session.dat -L policy.dat three
# Change to locality 3, Note: this operation varies on different platforms
tpm2_unseal -p session:session.dat -c sealkey.ctx
tpm2_flushcontext session.dat

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
