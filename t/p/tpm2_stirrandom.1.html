tpm2_stirrandom(1) Manual de Comandos Generales tpm2_stirrandom(1)

NOMBRE

tpm2_stirrandom(1) - Añadir "información adicional" al estado del RNG del TPM.

SINOPSIS

tpm2_stirrandom [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_stirrandom(1) - Inyectar "información adicional" como bytes en el pool de capacidad protegida de entropía del TPM.

La "información adicional" puede ser extraída de un archivo especificado como argumento o ser leída desde la *entrada estándar (STDIN)* si no se especifica un argumento.

Se pueden inyectar hasta 128 bytes a la vez a través de la entrada estándar a tpm2_stirrandom(1).

Si el archivo de entrada es mayor de 128 bytes, tpm2_stirrandom(1) fallará.

Añadir datos a través de tpm2_stirrandom(1) activará una reinicialización de la Capacidad Protegida del DRBG del TPM. Se utiliza al realizar cualquier acción sensible en una ubicación protegida, como cargar una clave persistente o actuar sobre una Capacidad Protegida, como actualizar el firmware del TPM.

Configuración TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI pueden cambiarse para comunicarse con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre tiene precedencia sobre la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente usado para comunicarse con el simulador de software del TPM.
•
device - Usado al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y por lo tanto soportan no usar un TCTI. Las herramientas que no lo soportan darán error cuando se intente usar sin una conexión TCTI. No soporta *NINGUNA* opción y *DEBE* ser presentado como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía tanto para el <nombre-tcti> como para el <config-opciones-tcti> resulta en que se use el valor predeterminado para esa porción respectivamente.

Predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado usando la semántica de dlopen(3). Las herramientas buscarán los TCTI *tabrmd*, *device* y *mssim* **EN ESE ORDEN** y usarán el **PRIMERO QUE ENCUENTREN**. Puede consultar qué TCTI se elegirá como predeterminado usando la opción -v para mostrar la información de versión. La pareja clave-valor "default-tcti" indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs Personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica puede ser cargado. Las herramientas usan internamente dlopen(3), y el valor crudo nombre-tcti se usa para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entiende la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo carácter TPM para su uso por el TCTI de dispositivo. El predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter ','. Cada clave y valor de cadena están separados por un carácter '='.
•
El TCTI abrmd soporta dos claves:
1.
`bus_name': El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type': El tipo de la instancia de dbus (una cadena) limitada a `session' y `system'.

Especificar el nombre TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especificar el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.)

tpm2_stirrandom(1)

NAME

tpm2_stirrandom - injects random data into the TPM's random number generator

SYNOPSIS

tpm2_stirrandom -f file | -q -s num_bytes | -a -i -z [ -c session ] [ -u -p ] [ -t -T ] [ -P password ] [ -r path ] [ -e path ] [ -o path ] [ -X ] [ -S state_file ]

DESCRIPTION

The tpm2_stirrandom command is used to fill the TPM's random number generator with entropy. The random number generator is used by the TPM to generate cryptographic keys and other random data.

The tool can inject random data from multiple sources:

  • From a file using the -f option.
  • From standard input using the < operator or by specifying /dev/stdin with the -f option.
  • By generating a specified number of random bytes using the -q option and optionally using -s to specify the number of bytes to generate.

The TPM command for this is TPM2_StirRandom.

The tpm2_stirrandom command can also be used to seed the random number generator with additional data from a file, which can then be used to generate random numbers.

StirRandom with additional data

The tpm2_stirrandom command supports the TPM2_StirRandom command which accepts optional randomly generated data (additional information). This data is provided as part of the input.

The size of the data to be supplied is limited by the TPM specification, which states that the size of the additional data should be less than or equal to the random_buffer_size, defined in the TPM specification.

OPTIONS

-f file
Specifies the input file containing the random data. If the file is /dev/stdin or -, then standard input is used.
-q
Generate random bytes. This option can be used with -s to specify the number of bytes to generate.
-s num_bytes
Specifies the number of random bytes to generate when -q is used.
-a
Inject additional data into the TPM's random number generator. This data is obtained from the input file specified with -f or standard input.
-i
Similar to -a, this option injects additional data. It reads up to the size of the random buffer supported by the TPM.
-z
Use this flag to indicate that the input data should be considered as entropy. This is often used when providing a large amount of random data from an external source.
-c session
Optional session information. This could be a policy session or a saved session.
-u
Use the TPM's built-in random number generator to provide additional entropy. This is useful if you don't have an external source of entropy.
-p
Similar to -u, this option uses the TPM's internal random number generator to supplement the provided entropy.
-t TCTI
The Transport Connection Interface (TCTI) to use. This specifies how the tool communicates with the TPM.
-T TCTI
Same as -t.
-P password
The password for the TPM owner authorization.
-r path
Path to a file to store the generated random data. This option is used when generating random data using -q.
-e path
Path to a file to store the raw random data read from the TPM. This is typically used with -i or -a.
-o path
Path to a file to store the enhanced random data (including any additional information provided).
-X
Enable verbose output for debugging.
-S state_file
Path to a file to save or load the TPM state. This is useful for resuming operations or for specific state management.

COMMON OPTIONS

These options are common to most of the tpm2-* tools.

--help
Print the help message and exit.
--version
Print the version of the tool and exit.
--tcti-list
List available TCTIs.

TCTI Configuration

The TCTI is used to specify how the tpm2_stirrandom tool communicates with the TPM. The default TCTI is the `device` TCTI, which uses the `/dev/tpm0` or `/dev/tpmrm0` device. Other TCTIs can be specified using the -t or -T options. For example, to use the `mssim` simulator TCTI, you would use --tcti mssim.

TCTI OPTIONS

--tcti-option option
Specify TCTI specific options.

EXAMPLES

Inject 64 bytes from stdin using a file

dd if=/dev/urandom bs=1 count=64 > myrandom.bin
tpm2_stirrandom < ./myrandom.bin

Inject bytes from a file and reading up to 128 bytes

dd if=/dev/urandom of=./myrandom.bin bs=1 count=42
tpm2_stirrandom ./myrandom.bin

NOTES

Please be aware that even if the “additional information” added by tpm2_stirrandom(1) can be entropy gathered from other DRBG sources, the TPM has no way of determining if the value has any entropy or not. As a consequence, it will just be considered as “additional input”.

The “additional input” is as defined in https://nvlpubs.nist.gov/nistpubs/Legacy/SP/nistspecialpublication800-90.pdf NIST SP800-90A

Returns

•
0 - Success.
•

•

•
3 - Authentication error.
•
4 - TCTI related error.
