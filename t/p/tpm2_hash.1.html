tpm2_hash(1) Manual de Comandos Generales tpm2_hash(1)

NOMBRE

tpm2_hash(1) - Realiza una operación de hash con el TPM.

SINOPSIS

tpm2_hash [OPCIONES] [ARGUMENTO o STDIN]

DESCRIPCIÓN

tpm2_hash(1) - Realiza una operación de hash en un archivo y devuelve los resultados. Si no se especifica un argumento, los datos se leen de stdin. Si los resultados del hash se utilizarán en una operación de firma que utilice una clave de firma restringida, el ticket devuelto por este comando puede indicar que el hash es seguro para firmar.

La salida es por defecto en stdout y en formato binario, a menos que se especifique lo contrario mediante las opciones -o y –hex respectivamente.

OPCIONES

•
-C, --hierarchy=OBJETO:

Jerarquía a utilizar para el ticket. Por defecto es o, TPM_RH_OWNER, cuando no se ha especificado ningún valor. Las opciones admitidas son:

•
o para TPM_RH_OWNER
•
p para TPM_RH_PLATFORM
•
e para TPM_RH_ENDORSEMENT
•
n para TPM_RH_NULL
•
-g, --hash-algorithm=ALGORITMO:

El algoritmo de hash para la operación de digest.

•
--hex

Convierte el hmac de salida a formato hexadecimal sin el prefijo “0x”.

•
-o, --output=ARCHIVO o STDOUT:

Archivo opcional para guardar el resultado del hash. Por defecto es stdout en formato hexadecimal.

•
-t, --ticket=ARCHIVO_TICKET

Archivo opcional de registro del resultado del ticket. Por defecto es stdout en formato hexadecimal.

•
ARGUMENTO o STDIN el argumento de línea de comandos especifica el ARCHIVO a hashear.

Referencias

Formato Objeto Contexto

El tipo de un objeto de contexto, ya sea un identificador o un nombre de archivo, se determina según la siguiente lógica en orden:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio TPM restaurado.
•
Si el argumento es una coincidencia de prefijo en uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de validación
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento se puede cargar como un número, se tratará como un identificador, por ejemplo, 0x81010013 y se utilizará directamente._OBJETO_.

Formato Autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: “Las autorizaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican”.

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación utilizando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña de cadena, especificada con el prefijo “str:” o su ausencia (cadena sin prefijo) no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña de cadena hexadecimal, especificada con el prefijo “hex:” se convierte de un formato hexadecimal a un formato de array de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables para la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada con el prefijo “file:” debe ser la ruta de un archivo que contenga la contraseña a leer por la herramienta o un “-” para usar stdin. Almacenar contraseñas en archivos evita la fuga de información, las contraseñas pasadas como opciones pueden ser leídas desde la lista de procesos o las funciones comunes del historial del shell.

Ejemplos

# para usar stdin y ser solicitado
file:-
# para usar un archivo desde una ruta
file:ruta/a/archivo/de/contraseña
# para enviar un eco de una contraseña a través de stdin:
echo foobar | tpm2_tool -p file:-
# para usar una cadena aquí de bash a través de stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al utilizar una sesión de política para autorizar el uso de un objeto, anteponga a la argumento de la opción la palabra clave session. Luego, indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación para ser enviado con el identificador de sesión (por ejemplo, contraseña de política), agregue un + y una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEXADECIMAL 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones PCR

Puedes satisfacer una política PCR utilizando el prefijo “pcr:” y el minilenguaje PCR. El minilenguaje PCR es el siguiente: <especificador-pcr>=<archivo-pcr-crudo>

El especificador PCR se documenta en la sección “Especificadores de banco PCR”.

El archivo-pcr-crudo es un argumento opcional que contiene la salida de los contenidos crudos del PCR tal como los devuelve tpm2_pcrread(1).

Especificadores de banco PCR

Ejemplos

Para satisfacer una política PCR de sha256 en los bancos 0, 1, 2 y 3, usa un especificador de:

pcr:sha256:0,1,2,3

Configuración TCTI

El TCTI o “Interfaz de Transmisión” es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Se utiliza al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo soportan fallarán cuando se intenten usar sin una conexión TCTI. No admite NINGUNA opción y DEBE presentarse como el texto exacto de “none”.

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para <nombre-tcti> o <config-opciones-tcti> resulta en que se use el valor predeterminado para esa porción respectivamente.

Valores Predeterminados del TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor “default-tcti” indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs Personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica puede ser cargado. Las herramientas internamente utilizan dlopen(3), y el valor bruto de tcti-name se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entiendan las semánticas de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres del TPM para su uso por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se pueden especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares clave-valor simples separados por un carácter `,”. Cada clave y cadena de valor están separadas por un carácter `=”.
•
El TCTI abrmd soporta dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia dbus (una cadena) limitada a `session' y `system'.

Especifique el nombre tcti tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifique el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

Hash de un archivo con el algoritmo de hash sha1 y guarda el hash y el ticket en un archivo

tpm2_hash -C e -g sha1 -o hash.bin -t ticket.bin data.txt

•
0 - Éxito.
•
1 - Error general no específico.
•
2 - Error de manejo de opciones.
•
3 - Error de autenticación.
•
4 - Error relacionado con TCTI.
•
5 - Esquema no soportado. Aplicable a tpm2_testparams.
