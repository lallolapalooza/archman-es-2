tpm2_pcrevent(1) Manual de Comandos Generales tpm2_pcrevent(1)

NOMBRE

tpm2_pcrevent(1) - Calcula el hash de un archivo y opcionalmente extiende un pcr.

SINOPSIS

tpm2_pcrevent [OPCIONES] ARCHIVO INDICE_PCR

DESCRIPCIÓN

tpm2_pcrevent(1) - Calcula el hash de ARCHIVO si se especifica o de la entrada estándar. Utiliza todos los algoritmos de hash que el TPM soporta.

Opcionalmente, si se especifica un índice de PCR, extiende ese PCR para todos los algoritmos soportados con el digest del hash. Los argumentos ARCHIVO y _INDICE_PCR_ no necesitan venir en ningún orden particular.

En cualquier caso, produce en la salida estándar el algoritmo de hash utilizado y el valor del digest, uno por línea:

alg:digest

Donde alg es el algoritmo utilizado (como sha1) y digest es el digest resultante del cálculo del hash de alg sobre los datos.

Ver secciones 23.1 y secciones 17 de la https://trustedcomputinggroup.org/wp-content/uploads/TPM-Rev-2.0-Part-3-Commands-01.38.pdf Especificación del TPM2.0

OPCIONES

Estas opciones controlan la extensión del pcr:

•
-P, --auth=AUTH:

Especifica el valor de autorización para el PCR.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando esta opción se selecciona, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash.

Configuración TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTIs se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTIs conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Utilizado al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y por lo tanto soportan no usar un TCTI. Las herramientas que no lo soportan darán error al intentar usarlas sin una conexión TCTI. No soporta NINGUNA opción y DEBE SER presentado como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno están en el formato:

<nombre_tcti>:<config_opciones_tcti>

Especificar una cadena vacía para el <nombre_tcti> o <config_opciones_tcti> resulta en que se use el valor por defecto para esa parte, respectivamente.

Valores por defecto del TCTI

Cuando no se especifica un TCTI, se busca el TCTI por defecto usando la semántica de dlopen(3). Las herramientas buscarán tabrmd, device y mssim TCTIs EN ESE ORDEN y USARÁN EL PRIMERO ENCONTRADO. Puede consultar qué TCTI se elegirá por defecto usando la opción -v para mostrar la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTIs mencionados es el predeterminado.

TCTIs personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica puede ser cargado. Las herramientas utilizan internamente dlopen(3), y el valor crudo tcti-name se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entendido por la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo de dispositivo de carácter TPM a utilizar por el TCTI de dispositivo. El valor por defecto es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores por defecto son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter ','. Cada clave y cadena de valor están separados por un carácter '='.
•
El TCTI abrmd soporta dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia de dbus (una cadena) limitada a `session' y `system'.

Especificar el nombre del tcti tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especificar el tcti abrmd (por defecto) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos.

EJEMPLOS

Calculate the SHA1 digest of the file named foo.bar and print it to stdout:

tpm2_pcrevent foo.bar sha1

Calculate the digests for all supported algorithms of the file named foo.bar and print them to stdout:

tpm2_pcrevent foo.bar

Calculate the SHA1 digest of the file named foo.bar, extend PCR 10 with the digest, and print the results to stdout:

tpm2_pcrevent foo.bar 10

Calculate the digests for all supported algorithms of the file named foo.bar, extend PCR 10 with the digests, and print the results to stdout:

tpm2_pcrevent foo.bar 10

Use the abrmd TCTI to extend PCR 10 with the SHA1 digest of foo.bar:

tpm2_pcrevent -T tabrmd foo.bar 10

Use the device TCTI to extend PCR 10 with the SHA1 digest of foo.bar:

tpm2_pcrevent -T device:/dev/tpmrm0 foo.bar 10

Calculate the hash digest of stdin and extend PCR 10 with the SHA1 digest:

cat foo.bar | tpm2_pcrevent - 10

Calculate the hash digest of stdin and extend PCR 10 with the digests of all supported algorithms:

cat foo.bar | tpm2_pcrevent - 10

Formato de autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: “Las autorizaciones tienen por defecto la CONTRASEÑA VACÍA cuando no se especifican”.

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación utilizando identificadores de prefijo.

Nota: Por defecto, se asume que las contraseñas están en forma de cadena cuando no tienen prefijo.

Cadena

Una contraseña en formato de cadena, especificada por el prefijo “str:” o su ausencia (cadena sin prefijo), no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña en formato de cadena hexadecimal, especificada por el prefijo “hex:”, se convierte de forma hexadecimal a forma de array de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables para la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo “file:”, debe ser la ruta de un archivo que contenga la contraseña a ser leída por la herramienta o un “-” para usar stdin. Almacenar contraseñas en archivos previene la fuga de información, las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de características comunes del historial del shell.

Ejemplos

# para usar stdin y que se solicite
file:-
# para usar un archivo desde una ruta
file:ruta/a/archivo/de/contraseña
# para enviar una contraseña vía stdin:
echo foobar | tpm2_tool -p file:-
# para usar una cadena here de bash vía stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego indique una ruta a un archivo de sesión que fue creado con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación para ser enviado con el manejador de sesión (por ejemplo, contraseña de política), entonces agregue un + y una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones de PCR

Puede satisfacer una política de PCR usando el prefijo “pcr:” y el minilenguaje de PCR. El minilenguaje de PCR es el siguiente: <especificador-pcr>=<archivo-pcr-crudo>

El especificador de PCR está documentado en la sección “Especificadores de bancos de PCR”.

El archivo-pcr-crudo es un argumento opcional que contiene la salida de los contenidos crudos de la PCR tal como los devuelve tpm2_pcrread(1).

Especificadores de bancos de PCR

Ejemplos

Para satisfacer una política de PCR de sha256 en los bancos 0, 1, 2 y 3, use un especificador de:

pcr:sha256:0,1,2,3

EJEMPLOS

Generar hash de un archivo

echo "foo" > data
tpm2_pcrevent data

Generar hash de un archivo y extender la PCR 8

echo "foo" > data
tpm2_pcrevent 8 data

Retornos

Las herramientas pueden devolver cualquiera de los siguientes códigos:

•
0 - Éxito.
•
1 - Error general no específico.
•
2 - Error en el manejo de opciones.
•
3 - Error de autenticación.
•
4 - Error relacionado con TCTI.
•
5 - Esquema no soportado. Aplicable a tpm2_testparams.
