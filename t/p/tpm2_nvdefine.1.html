tpm2_nvdefine(1) Manual de Comandos Generales tpm2_nvdefine(1)

NOMBRE

tpm2_nvdefine(1) - Define un índice No Volátil (NV) del TPM.

SINOPSIS

tpm2_nvdefine [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_nvdefine(1) - Define un índice NV con un valor de autenticación dado. El índice se especifica como un argumento. Puede ser especificado como un handle bruto o un valor de desplazamiento del rango de handles nv “TPM2_HR_NV_INDEX”. Si no se especifica un índice, la herramienta utiliza el primer índice libre. La herramienta imprime el índice nv definido en caso de éxito.

OPCIONES

•
-C, --hierarchy=OBJETO:

Especifica el handle utilizado para autorizar. Por defecto es o, TPM_RH_OWNER, cuando no se ha especificado ningún valor. Las opciones soportadas son:

•
o para TPM_RH_OWNER
•
p para TPM_RH_PLATFORM
•
<num> donde se puede usar un handle de jerarquía o un índice nv.
•
-s, --size=NUMERO_NATURAL:

Especifica el tamaño del área de datos en bytes. Por defecto es MAX_NV_INDEX_SIZE, que suele ser 2048.

•
-g, --hash-algorithm=ALGORITMO:

El algoritmo de hash utilizado para calcular el nombre del Índice y utilizado para la política de autorización. Si el índice es un índice de extensión, se utiliza el algoritmo de hash para la extensión.

•
-a, --attributes=ATRIBUTOS

Especifica los valores de los atributos para la región nv utilizada al crear la entidad. Se pueden usar tanto la máscara de bits bruta como los “nombres agradables”. Consulte la sección “Atributos NV” para más detalles. Si no se especifica, los atributos toman valores por defecto basados en la jerarquía en la que se define el índice.

Para la jerarquía del propietario, los valores por defecto son:

•
TPMA_NV_OWNERWRITE
•
TPMA_NV_OWNERREAD

Para la jerarquía de plataforma, los valores por defecto son:

•
TPMA_NV_PPWRITE
•
TPMA_NV_PPREAD

Si se especifica un archivo de política, los atributos por defecto elegidos de la jerarquía se combinan con un OR bit a bit con:

•
TPMA_NV_POLICYWRITE
•
TPMA_NV_POLICYREAD

Si NO se especifica un archivo de política, los atributos por defecto elegidos de la jerarquía se combinan con un OR bit a bit con:

•
TPMA_NV_AUTHWRITE
•
TPMA_NV_AUTHREAD
•
-P, --hierarchy-auth=AUTH:

Especifica el valor de autorización para la jerarquía. Los valores de autorización deben seguir los “estándares de formato de autorización”, consulte la sección “Formato de Autorización”.

•
-p, --index-auth=AUTH:

Especifica la contraseña del Índice NV al crearlo. Los valores de autorización HMAC y Contraseña deben seguir los “estándares de formato de autorización”, consulte la sección “Formato de Autorización”.

•
-L, --policy=ARCHIVO:

Especifica el archivo de hash de política para autorizaciones basadas en políticas.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash, a menos que también se requiera rphash.

•
--rphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros de respuesta. Esto se denomina comúnmente rpHash.

•
-S, --session=ARCHIVO:

La sesión creada usando tpm2_startauthsession. Se pueden especificar múltiples de estos. Por ejemplo, puede tener una sesión para auditoría y otra para cifrado/descifrado de parámetros.

•
ARGUMENTO el argumento de línea de comandos especifica el índice NV o el número de desplazamiento.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un handle o un nombre de archivo, se determina según la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio del TPM restaurado.
•
Si el argumento coincide *por prefijo* con uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un handle, por ejemplo, 0x81010013, y se utilizará directamente.*OBJETO*.

Formato de Autorización

La autorización para usar un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: “Las autorizaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican”.

Contraseñas

Las contraseñas se interpretan en las siguientes formas usando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en forma de cadena cuando no tienen prefijo.

Cadena

Una contraseña en forma de cadena, especificada por el prefijo “str:” o su ausencia (cadena bruta sin prefijo) no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena hexadecimal

Una contraseña en forma de cadena hexadecimal, especificada por el prefijo “hex:” se convierte de forma hexadecimal a un arreglo de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o difíciles de manejar en la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo “file:” debe ser la ruta de un archivo que contenga la contraseña a leer por la herramienta o un “-” para usar stdin. Almacenar contraseñas en archivos evita la fuga de información, las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de funciones comunes del historial del shell.

Ejemplos

# para usar stdin y que se solicite
file:-
# para usar un archivo desde una ruta
file:ruta/a/archivo/de/contraseña
# para enviar una contraseña vía stdin:
echo foobar | tpm2_tool -p file:-
# para usar una cadena de bash vía stdin:
tpm2_tool -p file:- <<< foobar

Usages

This section describes the usages for the tpm2_nvdefine tool.

tpm2_nvdefine

tpm2_nvdefine -C context-file -L policy-file -p password -r owner-password -u auth-value -a attributes -s size -f flag -t type -i index

Description

tpm2_nvdefine is used to define Name-Value (NV) pairs in the TPM.

NV Indexes are used to store arbitrary data in the TPM. The data stored in an NV Index is persistent and can be read by authorized callers. The data can also be written by authorized callers.

The NV Index is defined by the following parameters:

  • -i index: The index of the NV Index to define. This can be a number or a string representing the index.
  • -s size: The size of the data to be stored in the NV Index.
  • -a attributes: The attributes of the NV Index. These attributes control the access permissions to the NV Index. The attributes can be specified as a bitmask or as a human-readable string.
  • -p password: The password for the NV Index. This is used to authorize access to the NV Index.
  • -r owner-password: The owner password for the TPM. This is required to define NV Indexes.
  • -f flag: A flag that indicates the type of NV Index.
  • -t type: The type of data to be stored in the NV Index.

The NV Index can be accessed using the following context options:

  • -C context-file: The context file of the NV Index. This is used to load the NV Index into memory.
  • -L policy-file: The policy file of the NV Index. This is used to specify the policy that must be met to access the NV Index.
  • -u auth-value: The authorization value for the NV Index. This is used to authorize access to the NV Index.

Session Context

To use a session context, preface the option argument with the session keyword. Then indicate a path to a session file that was created with tpm2_startauthsession(1). Optionally, if the session requires an auth value to be sent with the session handle (eg password policy), then append a + and a string as described in the Passwords section.

Examples

To use a session context file called session.ctx.

session:session.ctx

To use a session context file called session.ctx AND send the authvalue mypassword.

session:session.ctx+mypassword

To use a session context file called session.ctx AND send the HEX authvalue 0x11223344.

session:session.ctx+hex:11223344

PCR Authorizations

You can satisfy a PCR policy using the pcr: prefix and the PCR minilanguage. The PCR minilanguage is as follows: <pcr-spec>=<raw-pcr-file>

The PCR spec is documented in in the section "PCR bank specifiers".

The raw-pcr-file is an optional argument that contains the output of the raw PCR contents as returned by tpm2_pcrread(1).

PCR bank specifiers

Examples

To satisfy a PCR policy of sha256 on banks 0, 1, 2 and 3 use a specifier of:

pcr:sha256:0,1,2,3

specifying AUTH.

Object Attributes

Object Attributes are used to control various properties of created objects. When specified as an option, either the raw bitfield mask or "nice-names" may be used. The values can be found in Table 31 Part 2 of the TPM2.0 specification, which can be found here:

https://trustedcomputinggroup.org/wp-content/uploads/TPM-Rev-2.0-Part-2-Structures-01.38.pdf

Nice names are calculated by taking the name field of table 31 and removing the prefix TPMA_OBJECT_ and lowercasing the result. Thus, TPMA_OBJECT_FIXEDTPM becomes fixedtpm. Nice names can be joined using the bitwise or "|" symbol.

For instance, to set The fields TPMA_OBJECT_FIXEDTPM, TPMA_OBJECT_NODA, and TPMA_OBJECT_SIGN_ENCRYPT, the argument would be:

fixedtpm|noda|sign specifying the nv attributes ATTRIBUTES.

TCTI Configuration

The TCTI or "Transmission Interface" is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of "none".

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The "default-tcti" key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI="device:/dev/tpm0"

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI="mssim:host=localhost,port=2321"

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,` character. Each key and value string are separated by a `=` character.
•
TCTI abrmd supports two keys:
1.
bus_name : The name of the tabrmd service on the bus (a string).
2.
bus_type : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

NAME

tpm2_nvdefine

define a persistent value in TPM NV memory

SYNOPSIS

tpm2_nvdefine [OPTIONS] [–data data] [–input file]

DESCRIPTION

tpm2_nvdefine is used to define a persistent value in TPM NV memory. NV memory is a persistent memory in the TPM that can be used to store arbitrary data. The data is preserved across TPM resets and power cycles. NV memory is organized into slots, each identified by an index. NV indices are 16-bit values. The lowest 16 indices are reserved for the TPM. The range of indices from 0x010000 to 0x01FFFF are available for the user. A user defined NV index can be defined with specific properties, such as size, permissions, and locality. The tpm2_nvdefine utility allows a user to define an NV index with custom parameters.

A specific NV index can be defined with read/write/pcr access permissions and can be set to be permanent or temporary. The value is associated with an authorization policy that must be met to access the value. The default authorization policy is that no authorization is required.

The defined value can be optionally initialized with data provided either via the standard input or a file.

OPTIONS

The options can be split into two groups:

"options" "nv define"nv define options

The following options are specific to the tpm2_nvdefine command:

"option" "index"-i, --index index

The NV index to define. This is a hexadecimal value.

"option" "size"-s, --size size

The size of the NV index in bytes. This is a decimal value.

"option" "value" "authorization"-a, --authValue value

The authorization value for the NV index. This is a hexadecimal string.

"option" "policy"--policy policy_file

The path to a file containing the authorization policy for the NV index. The policy is a sequence of TPM2 commands that must be executed in order to satisfy the policy.

"option" "read" "public"--read-public

Allow reading the public part of the NV index. This is required if the NV index is to be used for anything other than simple data storage.

"option" "write" "public"--write-public

Allow writing to the NV index. This is required if the NV index is to be written to.

"option" "read" "private"--read-private

Allow reading the private part of the NV index. This is required if the NV index is to be read.

"option" "write" "private"--write-private

Allow writing to the private part of the NV index. This is required if the NV index is to be written to.

"option" "pcr" "value"--pcr-value pcr_value

The PCR value to associate with the NV index. This is a decimal value. This option is only valid if the NV index is to be used for storing PCR values.

"option" "pcr" "read"--pcr-read

Allow reading the PCR value associated with the NV index. This is required if the NV index is to be read.

"option" "pcr" "write"--pcr-write

Allow writing the PCR value associated with the NV index. This is required if the NV index is to be written to.

"option" "permanent"--permanent

Make the NV index permanent. This means that the NV index will be preserved across TPM resets and power cycles.

"option" "temporary"--temporary

Make the NV index temporary. This means that the NV index will be lost upon TPM reset.

"option" "data"--data data

Initialize the NV index with the provided data. This is a hexadecimal string.

"option" "input"--input file

Initialize the NV index with the data from the provided file. This is a path to a file.

"options" "common"common options

See common options (tpm2_tools(1)).

Context Object Format

tpm2_nvdefine supports the following context object formats:

"context" "object" "format" "hex"hex

The context object is represented as a hexadecimal string.

"context" "object" "format" "file"file

The context object is represented as a file path.

Authorization Formatting

tpm2_nvdefine supports the following authorization formats:

"authorization" "formatting" "hex"hex

The authorization value is represented as a hexadecimal string.

"authorization" "formatting" "policy"policy

The authorization value is represented as a policy file.

Object Attributes

tpm2_nvdefine supports the following object attributes:

"object" "attributes" "read" "public"TPMA_NV_READ_PUBLIC

Allow reading the public part of the NV index.

"object" "attributes" "write" "public"TPMA_NV_WRITE_PUBLIC

Allow writing to the public part of the NV index.

"object" "attributes" "read" "private"TPMA_NV_READ_PRIVATE

Allow reading the private part of the NV index.

"object" "attributes" "write" "private"TPMA_NV_WRITE_PRIVATE

Allow writing to the private part of the NV index.

"object" "attributes" "pcr" "value"TPMA_NV_PCR_VALUE

The NV index will store PCR values.

"object" "attributes" "pcr" "read"TPMA_NV_PCR_READ

Allow reading the PCR value associated with the NV index.

"object" "attributes" "pcr" "write"TPMA_NV_PCR_WRITE

Allow writing the PCR value associated with the NV index.

"object" "attributes" "sticky" "write"TPMA_NV_STICKY_WRITE

The NV index can only be written to once per power cycle.

"object" "attributes" "gcc"TPMA_NV_GCC

The NV index is protected by a general challenge-response mechanism.

"object" "attributes" "permanent"TPMA_NV_PERMANENT

The NV index is permanent and will be preserved across TPM resets and power cycles.

"object" "attributes" "shutdown" "persistent"TPMA_NV_SHUTDOWN_PERSISTENT

The NV index will be preserved across TPM shutdowns.

"object" "attributes" "clearable"TPMA_NV_CLEARABLE

The NV index can be cleared by the TPM owner.

"object" "attributes" "ordered"TPMA_NV_ORDERED

The NV index is ordered, meaning that data is written to it in a specific order.

"object" "attributes" "writelocked"TPMA_NV_WRITELOCKED

The NV index is write-locked, meaning that data can only be written to it once.

COMMON OPTIONS

tpm2_nvdefine supports the following common options:

"common" "option" "allow" "fips"--allow-fips

Allow the use of FIPS-compliant TPMs.

"common" "option" "cancel"-c, --cancel context_handle

Cancel a previously started operation. The context handle is a hexadecimal value.

"common" "option" "force"-f, --force

Force the operation to complete, even if it fails.

"common" "option" "key"-k, --key key_handle

The key handle to use for signing the command. This is a hexadecimal value.

"common" "option" "password"-p, --password password

The password to use for authenticating the command. This is a string value.

"common" "option" "policy"-P, --policy policy_file

The path to a file containing the policy to use for authenticating the command.

"common" "option" "quiet"-Q, --quiet

Suppress output to stdout.

"common" "option" "remove" "policy"--remove-policy

Remove the policy associated with the NV index.

"common" "option" "reset" "policy"--reset-policy

Reset the policy associated with the NV index.

"common" "option" "take" "ownership"--take-ownership

Take ownership of the TPM. This is required if the NV index is to be defined with a policy that requires ownership.

"common" "option" "tcti"-T, --tcti tcti_string

The Tagged Command Transmission Interface (TCTI) string to use for connecting to the TPM. This is a string value.

"common" "option" "verbose"-V, --verbose

Increase the verbosity of the output.

"common" "option" "version"-v, --version

Print version information and exit.

TCTI Configuration

tpm2_nvdefine supports the following TCTI configurations:

"TCTI" "configuration" "device"device

Use the device TCTI to connect to the TPM. The device path is specified as an argument to the TCTI string.

"TCTI" "configuration" "mssim"mssim

Use the mssim TCTI to connect to the TPM simulator.

"TCTI" "configuration" "socket"socket

Use the socket TCTI to connect to the TPM simulator.

TCTI OPTIONS

The following options can be used to configure the TCTI:

"TCTI" "option" "device" "path"--device-path path

The path to the TPM device.

"TCTI" "option" "socket" "host"--socket-host host

The host to connect to the TPM simulator.

"TCTI" "option" "socket" "port"--socket-port port

The port to connect to the TPM simulator.

EXAMPLES

Define an NV index with index 0x1000, size 16 bytes, and no authorization:

$ tpm2_nvdefine -i 0x1000 -s 16

Define an NV index with index 0x1001, size 32 bytes, and a password authorization value:

$ tpm2_nvdefine -i 0x1001 -s 32 -a 00112233445566778899aabbccddeeff

Define an NV index with index 0x1002, size 64 bytes, permanent, and initialized with data from a file:

$ tpm2_nvdefine -i 0x1002 -s 64 --permanent --input mydata.bin

Define an NV index with index 0x1003, size 8 bytes, and a policy file for authorization:

$ tpm2_nvdefine -i 0x1003 -s 8 --policy mypolicy.txt

Returns

Returns 0 on success, 1 on failure.

No known bugs.
