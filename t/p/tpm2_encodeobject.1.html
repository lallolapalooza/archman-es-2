tpm2_encodeobject(1)

tpm2_encodeobject(1) Manual de Comandos Generales tpm2_encodeobject(1)

NOMBRE

tpm2_encodeobject(1) - Codifica un objeto en formato PEM combinado.

SINOPSIS

tpm2_encodeobject [OPCIONES]

DESCRIPCIÓN

tpm2_encodeobject(1) - Codifica tanto las porciones privada como pública de un objeto en formato PEM combinado utilizado por tpm2-tss-engine.

La herramienta lee las porciones privada y pública de un objeto y lo codifica en un formato PEM combinado utilizado por tpm2-tss-engine y otras aplicaciones.

NOTA: Se deben especificar tanto las porciones privada como pública de la clave tpm.

OPCIONES

•
-C, --parent-context=OBJETO:

El objeto padre.

•
-P, --auth=AUTH:

El valor de autorización del objeto padre especificado por -C.

•
-u, --public=ARCHIVO:

Un archivo que contiene la porción pública del objeto.

•
-r, --private=ARCHIVO:

Un archivo que contiene la porción sensible del objeto.

•
-p, --key-auth:

Indica si se necesita un valor de autorización para el objeto especificado por -r y -u.

•
-o, --output=ARCHIVO:

La ruta del archivo de salida, que registra la porción pública del objeto.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un manejador o un nombre de archivo, se determina de acuerdo con la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio TPM restaurado.
•
Si el argumento es una coincidencia de *prefijo* en uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un manejador, por ejemplo, 0x81010013 y se utilizará directamente.

Formato de Autorización

La autorización para usar un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autorizaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación utilizando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña de cadena, especificada por el prefijo "str:" o su ausencia (cadena sin prefijo), no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña en formato de cadena hexadecimal, especificada por el prefijo "hex:", se convierte de formato hexadecimal a formato de arreglo de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables para la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo "file:", debe ser la ruta de un archivo que contenga la contraseña a leer por la herramienta o un "-" para usar la entrada estándar. Almacenar contraseñas en archivos evita fugas de información, las contraseñas pasadas como opciones pueden ser leídas desde la lista de procesos o las características comunes del historial del shell.

Ejemplos

# para usar la entrada estándar y solicitarla
file:-
# para usar un archivo desde una ruta
file:ruta/al/archivo/de/contraseña
# para enviar una contraseña vía entrada estándar:
echo foobar | tpm2_tool -p file:-
# para usar una cadena de aquí de bash vía entrada estándar:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, anteponga al argumento de la opción la palabra clave session. Luego, indique la ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación para ser enviado con el manejador de sesión (por ejemplo, contraseña de política), agregue un "+" y una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones PCR

Puede satisfacer una política de PCR usando el prefijo "pcr:" y el minilenguaje PCR. El minilenguaje PCR es el siguiente: <especificador-pcr>=<archivo-pcr-crudo>

El especificador de PCR se documenta en la sección "Especificadores de banco de PCR".

El archivo-pcr-crudo es un argumento opcional que contiene la salida de los contenidos crudos de PCR tal como los devuelve tpm2_pcrread(1).

Especificadores de banco de PCR

Ejemplos

Para satisfacer una política de PCR de sha256 en los bancos 0, 1, 2 y 3, use un especificador de:

pcr:sha256:0,1,2,3

especificando AUTH.
