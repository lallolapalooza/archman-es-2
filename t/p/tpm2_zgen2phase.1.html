tpm2_zgen2phase(1) Manual de comandos generales tpm2_zgen2phase(1)

NOMBRE

tpm2_zgen2phase(1) - Comando para permitir que el TPM combine datos de la otra parte con la clave efímera generada en la primera fase de los protocolos de intercambio de claves en dos fases.

SINOPSIS

tpm2_zgen2phase [OPCIONES]

DESCRIPCIÓN

tpm2_zgen2phase(1) - Comando para permitir que el TPM combine datos de la otra parte con la clave efímera generada en la primera fase de los protocolos de intercambio de claves en dos fases.

OPCIONES

•
-c, --key-context=ARCHIVO:

Objeto de contexto que apunta a la clave ECC. Ya sea un archivo o un número de identificador. Véase la sección "Formato del Objeto de Contexto".

•
-p, --key-auth=AUTH:

El valor de autorización para el objeto de clave ECC.

•
-s, --scheme=ALGORITMO:

El esquema de intercambio de claves. Opcional. Las opciones válidas son ecdh o sm2.

•
-t, --counter=NUMEROPRIMO:

El contador de confirmación para determinar el índice de clave a utilizar.

•
--static-public=ARCHIVO:

La clave pública estática de entrada de la otra parte.

•
--ephemeral-public=ARCHIVO:

La clave pública efímera de entrada de la otra parte.

•
--output-Z1=ARCHIVO

Especificar la ruta del archivo para guardar el punto secreto ecdh calculado Z1.

•
--output-Z2=ARCHIVO

Especificar la ruta del archivo para guardar el punto secreto ecdh calculado Z2.

ESPECIFICADORES DE ALGORITMOS

Las opciones que toman algoritmos admiten "nombres amigables".

Existen dos clases principales de cadenas de especificación de algoritmos: simples y complejas. Solo ciertos algoritmos serán aceptados por el TPM, según el uso y las condiciones.

Especificadores complejos

Los objetos, cuando se especifican para su creación por el TPM, tienen numerosos algoritmos para poblar en los datos públicos. Cosas como tipo, esquema y detalles asimétricos, tamaño de clave, etc. A continuación, se muestra el formato general para especificar estos datos: <tipo>:<esquema>:<detalles-simétricos>

Especificadores de tipo

Esta parte del especificador de algoritmo complejo es obligatoria. El esquema restante y los detalles simétricos se establecerán por defecto según el tipo especificado y el tipo del objeto que se está creando.

•
aes - AES por defecto: aes128
•
aes128<modo> - AES de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, se usa por defecto null.
•
aes192<modo> - Igual que aes128<modo>, excepto por un tamaño de clave de 192 bits.
•
aes256<modo> - Igual que aes128<modo>, excepto por un tamaño de clave de 256 bits.
•
sm4 - SM4 por defecto: sm4128
•
sm4128 o sm4_128 <modo> - SM4 de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, se usa por defecto null.
•
ecc - Curva Elíptica, por defecto ecc256.
•
ecc192 o ecc_nist_p192 - Curva NIST ECC de 192 bits
•
ecc224 o ecc_nist_p224 - Curva NIST ECC de 224 bits
•
ecc256 o ecc_nist_p256 - Curva NIST ECC de 256 bits
•
ecc384 o ecc_nist_p384 - Curva NIST ECC de 384 bits
•
ecc521 o ecc_nist_p521 - Curva NIST ECC de 521 bits
•
ecc_sm2 o ecc_sm2_p256 - Curva SM2 de 256 bits
•
rsa - RSA por defecto: rsa2048
•
rsa1024 - RSA con tamaño de clave de 1024 bits.
•
rsa2048 - RSA con tamaño de clave de 2048 bits.
•
rsa3072 - RSA con tamaño de clave de 3072 bits.
•
rsa4096 - RSA con tamaño de clave de 4096 bits.

Especificadores de esquema

A continuación, hay un campo opcional, se puede omitir.

Los esquemas suelen ser Esquemas de Firma o Esquemas de Cifrado Asimétrico. La mayoría de los esquemas de firma toman un algoritmo hash directamente después del esquema de firma. Si falta el algoritmo hash, se usa por defecto sha256. Algunos no toman argumentos y otros toman múltiples argumentos.

Especificadores de esquema con hash opcional

Estos especificadores de esquema van seguidos de un guión y un algoritmo hash válido. Por ejemplo: oaep-sha256.

tpm2_create 1

tpm2_create - create a primary or storage key

tpm2_create [-h|--help=[man|no-man]] [-v|--version] [-T|--tcti=name[:conf]] [-I|--tcti-conf=str] [-c|--auth=handle] [-p|--policy=file] [-P|--policy-session=file] [-S|--session=file] [-H|--hierarchy=handle] [-C|--parent-context=file] [-u|--public=file] [-r|--private=file] [-i|--input=file] [-g|--hash-algorithm=alg] [-U|--ticket-symmetric=alg] [-X|--attestation=alg] [-E|--endorsement=alg] [-Q|--quiet] [-Z|--enable-errata] [-R|--autoflush] [keydef]

Description

The tpm2_create utility is used to create a primary or storage key. This utility is highly configurable and supports the creation of keys of various types, including RSA and ECC. The key can be created with a specified parent key, or as a primary key under a primary hierarchy (e.g., Owner, Endorsement, Storage, or Null).

The program takes the following arguments:

Key Definition

The key definition is a string that describes the key to be created. It is composed of zero or more of the following:

•
Key size (e.g., rsa2048, ecc256)
•
Algorithm (e.g., rsaes, rsassa, ecdaa, ecdh, ecdn)
•
Key options (e.g., fixed, stclear, sensitive, user, admin)
•
Scheme specifiers (e.g., hmac, mgf1)
•
Symmetric details (e.g., aes128cfb)
