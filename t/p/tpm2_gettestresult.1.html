tpm2_gettestresult(1) Manual de comandos generales tpm2_gettestresult(1)

NOMBRE

tpm2_gettestresult(1) - Obtener el resultado de las pruebas realizadas por el TPM

SINOPSIS

tpm2_gettestresult [OPCIONES]

DESCRIPCIÓN

tpm2_gettestresult(1) devolverá el resultado de las pruebas realizadas por el TPM.

El código de error indicará si la prueba se ejecutó correctamente o falló.

Si hay algoritmos pendientes programados para ser probados, tpm2_gettestresult devolverá "TESTING". De lo contrario, se devolverá "FAILED" o "SUCCESS" dependiendo del resultado de la prueba.

La información dependiente del fabricante también se imprimirá en formato hexadecimal crudo.

OPCIONES

Esta herramienta no acepta opciones específicas de la herramienta.

OPCIONES COMUNES

Esta colección de opciones son comunes a muchos programas y proporcionan información que muchos usuarios pueden esperar.

•
-h, --help=[man|no-man]: Muestra el manual de la herramienta. Por defecto, intenta invocar el visor de manuales para la herramienta; sin embargo, en caso de fallo, mostrará un resumen corto de la herramienta. Este es el mismo comportamiento si se especifica el argumento de opción "man", sin embargo, si se solicita explícitamente "man", la herramienta proporcionará errores de man en stderr. Si se especifica la opción "no-man", o si el visor de manuales falla, las opciones cortas se mostrarán en stdout.

Para utilizar correctamente la función de manuales, estos deben estar instalados o en MANPATH. Consulte man(1) para más detalles.

•
-v, --version: Muestra información de la versión de esta herramienta, tctis compatibles y sale.
•
-V, --verbose: Aumenta la información que la herramienta imprime en la consola durante su ejecución. Al usar esta opción, se imprimen el nombre del archivo y el número de línea.
•
-Q, --quiet: Silencia la salida normal de la herramienta a stdout.
•
-Z, --enable-errata: Habilita la aplicación de correcciones de erratas. Útil si se necesita aplicar una corrección de errata a los comandos enviados al TPM. Definir la variable de entorno TPM2TOOLS_ENABLE_ERRATA es equivalente.

El autoflush también se puede activar si la variable de entorno TPM2TOOLS_AUTOFLUSH está establecida en "yes" o "true".

Configuración de TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI pueden cambiarse para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre tiene prioridad sobre la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Se utiliza al comunicarse directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo admiten generarán un error cuando se intenten usar sin una conexión TCTI. No admite NINGUNA opción y DEBE presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<configuración-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <configuración-opciones-tcti> resulta en que se use el valor predeterminado para esa porción respectivamente.

Predeterminados de TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim **EN ESE ORDEN** y **USARÁN EL PRIMERO QUE ENCUENTREN**. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs Personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica puede ser cargado. Las herramientas utilizan internamente dlopen(3), y el valor crudo nombre-tcti se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entendido por la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres TPM para su uso por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares clave-valor simples separados por un carácter ','. Cada clave y valor de cadena están separados por un carácter '='.
•
El TCTI abrmd admite dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia dbus (una cadena) limitada a `session' y `system'.

Especificar el nombre TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especificar el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos.

tpm2_gettestresult(1) — tpm2-tools

NAME

tpm2_gettestresult - Get the test result and update the TPM in order to run tests. It also supports the setting of the TPM to a defined state. The TPM is put into a state that is defined and can be reset if the test result is not defined.

SYNOPSIS

tpm2_gettestresult [OPTIONS]

DESCRIPTION

The tpm2_gettestresult tool is used to get the test result from the TPM. It also allows for the TPM to be reset to a defined state, which is useful before running tests. The command will query the TPM for its test result. If the test result is not defined, the TPM will be reset to a defined state. This ensures that tests are run in a predictable environment.

OPTIONS

None

COMMON OPTIONS

A list of common options available to all tpm2-tools can be found in the tpm2_tool(1) manpage.

TCTI Configuration

The TPM Communication Interface (TCTI) can be configured using a TCTI file. The default TCTI used by this tool is the tabrmd TCTI.

A TCTI file can be specified using the -T or --tcti-list option.

TCTI OPTIONS

-Q, --quiet
Suppress most of the verbose output. Only errors will be printed.
-V, --verbose
Enable verbose output. This will print events and parameters.
-d, --debug
Enable debug output. This will print raw messages and responses.
-v, --version
Display version information and exit.
-h, --help
Display this help message and exit.

EXAMPLES

To get the test result and reset the TPM to a defined state:

 $ tpm2_gettestresult

NOTES

This command requires root privileges to access the TPM device.

Returns

0
Success.
1
General error.
2
Not yet implemented.
3
TSS related error (e.g. TPM connection error).
4
TCTI related error.
5
Non supported scheme. Applicable to tpm2_testparams.
