tpm2(1) Manual de Comandos Generales tpm2(1)

NOMBRE

tpm2(1) - Un único ejecutable pequeño que combina las diversas herramientas de tpm2, similar a un BusyBox que proporciona un entorno bastante completo para cualquier sistema pequeño o embebido.

SINOPSIS

tpm2 [OPCIONES] [ARGUMENTOS]

DESCRIPCIÓN

tpm2(1) - Para facilitar la instalación de tpm2-tools en initrd o sistemas embebidos donde la optimización del tamaño y los recursos limitados son importantes, es conveniente tener un único ejecutable que pueda despachar las diversas funcionalidades de TPM2 especificadas por el argumento, que es uno de los nombres de herramientas disponibles.

Las opciones y argumentos que siguen son opciones comunes o las específicas del nombre de la herramienta.

Es importante tener en cuenta que las herramientas individuales con el prefijo tpm2_ todavía se pueden invocar, sin embargo, ahora están enlazadas simbólicamente a este ejecutable tpm2. Y así, a diferencia de BusyBox, la funcionalidad completa de las herramientas individuales está disponible en el ejecutable. Por ejemplo: tpm2_getrandom 8 se puede especificar alternativamente como tpm2 getrandom 8.

OPCIONES COMUNES

Esta colección de opciones son comunes a muchos programas y proporcionan información que muchos usuarios pueden esperar.

•
-h, --help=[man|no-man]: Muestra la página del manual de la herramienta. Por defecto, intenta invocar el visor de páginas del manual para la herramienta, sin embargo, en caso de fallo, mostrará un resumen corto de la herramienta. Este es el mismo comportamiento si se especifica el argumento de opción 'man', sin embargo, si se solicita explícitamente 'man', la herramienta proporcionará errores de man en stderr. Si se especifica la opción 'no-man', o si el visor de páginas del manual falla, las opciones cortas se mostrarán en stdout.

Para utilizar con éxito la función de páginas del manual se requiere que las páginas del manual estén instaladas o en MANPATH. Consulte man(1) para más detalles.

•
-v, --version: Muestra la información de versión de esta herramienta, tctis compatibles y sale.
•
-V, --verbose: Aumenta la información que la herramienta imprime en la consola durante su ejecución. Al usar esta opción se imprime el archivo y el número de línea.
•
-Q, --quiet: Silencia la salida normal de la herramienta a stdout.
•
-Z, --enable-errata: Habilita la aplicación de correcciones de erratas. Útil si se necesita aplicar una corrección de errata a los comandos enviados al TPM. Definir la variable de entorno TPM2TOOLS_ENABLE_ERRATA es equivalente.
•
-R, --autoflush: Habilita el autoflush para objetos transitorios creados por el comando. Si un objeto padre se carga desde un archivo de contexto, también se eliminará el objeto padre transitorio. El autoflush también se puede activar si la variable de entorno TPM2TOOLS_AUTOFLUSH está configurada a 'yes' o 'true'.

Configuración del TCTI

El TCTI o 'Transmission Interface' es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Utilizado al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y por lo tanto soportan no usar un TCTI. Las herramientas que no lo soportan generarán un error al intentar ser utilizadas sin una conexión TCTI. No soporta *NINGUNA* opción y *DEBE* presentarse como el texto exacto de 'none'.

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o el <config-opciones-tcti> resulta en que se utilice el valor predeterminado para esa parte respectivamente.

tpm2(1) — Arch manual pages

NAME

tpm2 - TPM2 Access Tool

SYNOPSIS

tpm2 [-h | --help] [-v | --version] [-S phandle | --session=phandle] [-T tcti-name | --tcti-name=tcti-name] [-c | --clear] [-e policy-file | --policy=policy-file] [-f input-file | --input-file=input-file] [-p password | --password=password] [-R | -- R] [-r output-file | --output-file=output-file] [-l log-file | --log-file=log-file] [-L policy-file | --policy-file=policy-file] [-P password | --password-file=password-file] [-k key-file | --key-file=key-file] [--hex] [--tcti-list] [command] [command-options]

DESCRIPTION

The tpm2 utility is a command line tool that provides an interface to the TPM2 Software Stack (TSS). It allows users to interact with the TPM device by sending TPM commands and receiving TPM responses.

The tpm2 utility can be used for a variety of tasks, including:

  • Querying TPM information
  • Managing TPM objects (keys, policies, etc.)
  • Performing cryptographic operations
  • Starting up and shutting down the TPM
  • And more...

ARGUMENTS

The following arguments are supported:

-h | --help
Print the help message and exit.
-v | --version
Print version information and exit.
-S phandle | --session=phandle
Specifies the session handle to use for the TPM command.
-T tcti-name | --tcti-name=tcti-name
Specifies the Transport Chosen Trust Environment (TCTI) to use. This determines how the tool communicates with the TPM. See TCTI Configuration section for more details.
-c | --clear
Indicates that a TPM2_Startup(TPM2_SU_CLEAR) command should be sent.
-e policy-file | --policy=policy-file
Specifies a file containing a policy digest to be used for authorization.
-f input-file | --input-file=input-file
Specifies a file from which to read input data.
-p password | --password=password
Specifies the password to use for authorization.
-R | -- R
Indicates that the command should be performed on the primary seed.
-r output-file | --output-file=output-file
Specifies a file to which to write output data.
-l log-file | --log-file=log-file
Specifies a file to which to write TPM event logs.
-L policy-file | --policy-file=policy-file
Specifies a file containing a policy digest. This is used for policy authorization.
-P password-file | --password-file=password-file
Specifies a file containing the password for authorization.
-k key-file | --key-file=key-file
Specifies a file containing a key blob.
--hex
Prints output in hexadecimal format.
--tcti-list
Lists the available TCTIs.

COMMON OPTIONS

The following options are common to most tpm2 tools:

-T tcti-name
This option specifies how the tool should connect to the TPM. The default TCTI is determined by the tool, but can be overridden using this option. The TCTI name can be a string that specifies the type of TCTI and any associated parameters. See the TCTI Configuration section for details.
-S session-handle
Specify the session handle to use for the TPM command. This is useful for commands that require an active session.
-c
This flag is used to send a TPM2_Startup(TPM2_SU_CLEAR) command. This effectively resets the TPM to its default state.
-P password-file
Provides a password for authorization from a file. This is often used when accessing protected TPM functions.
-p password
Provides a password directly on the command line for authorization.
-r output-file
Specifies a file to write the output of the command to. This is useful for saving data like keys or other TPM objects.
-f input-file
Specifies a file to read input data from. This can be used for providing data to commands that require it, such as creating keys.
-l log-file
Writes TPM event logs to the specified file. This can be helpful for debugging and auditing.

TCTI Configuration

The TPM Communication Transport Executive Interface (TCTI) is responsible for establishing communication with the TPM device. The tpm2-tools suite supports multiple TCTIs, and they are searched for in the following order: tabrmd, device, and mssim. The first one found is used. You can check which TCTI will be chosen by default using the -v option, which will print version information including the “default-tcti” key-value pair.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,'` character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Get 8 rand bytes from the TPM

tpm2 getrandom 8 | xxd -p

Send a TPM Startup Command with flags TPM2_SU_CLEAR

tpm2 startup -c

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.
