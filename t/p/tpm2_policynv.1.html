tpm2_policynv(1) Manual de Comandos Generales tpm2_policynv(1)

NOMBRE

tpm2_policynv(1) - Evalúa la autorización de política comparando un valor especificado con el contenido del índice NV especificado.

SINOPSIS

tpm2_policynv [OPCIONES] [ARGUMENTO] [ARGUMENTO]

DESCRIPCIÓN

tpm2_policynv(1) - Este comando evalúa la autorización de política comparando el contenido escrito en un índice NV con el especificado en las opciones de la herramienta. La herramienta toma dos argumentos: (1) El índice NV especificado como identificador raw o un valor de desplazamiento del rango de identificadores NV “TPM2_HR_NV_INDEX” y (2) Operador de comparación para comparación de magnitud u operaciones de prueba de bits. En la especificación, el índice NV que contiene los datos se llama operandoA y los datos que el usuario especifica para comparar se llama operandoB. El operador de comparación se puede especificar de la siguiente manera: * “eq” si operandoA = operandoB * “neq” si operandoA != operandoB * “sgt” si operandoA con signo > operandoB con signo * “ugt” si operandoA sin signo > operandoB sin signo * “slt” si operandoA con signo < operandoB con signo * “ult” si operandoA sin signo < operandoB sin signo * “sge” si operandoA con signo >= operandoB con signo * “uge” si operandoA sin signo >= operandoB sin signo * “sle” si operandoA con signo <= operandoB con signo * “ule” si operandoA sin signo <= operandoB sin signo * “bs” si todos los bits establecidos en operandoA están establecidos en operandoB * “bc” si todos los bits establecidos en operandoA están borrados en operandoB

OPCIONES

•
-C, --hierarchy=OBJETO:

Especifica la jerarquía utilizada para autorizar. Las opciones soportadas son:

•
o para TPM_RH_OWNER
•
p para TPM_RH_PLATFORM
•
<num> donde se puede usar un identificador de jerarquía o un índice nv.

Cuando -C no se pasa explícitamente, el identificador del índice se usará para autorizar contra el índice. El valor de autorización del índice se establece mediante la opción -p de tpm2_nvdefine(1).

•
-P, --auth=AUTH:

Especifica el valor de autorización para la jerarquía.

•
-L, --policy=ARCHIVO:

Archivo para guardar el resumen de la política.

•
-S, --session=ARCHIVO:

El archivo de sesión de política generado mediante la opción -S de tpm2_startauthsession o guardado de una ejecución anterior de la herramienta.

•
--offset=NUMERO_NATURAL:

El desplazamiento dentro del índice NV para comenzar a comparar. El tamaño de los datos que comienzan en el desplazamiento y terminan en el tamaño del índice NV no debe exceder el tamaño del operando especificado en las opciones.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash.

•
-i, --input=ARCHIVO:

Especifica el archivo de entrada con datos para comparar con el contenido del índice NV. En la especificación estándar, esto se denomina operando o más específicamente operandoB. Se puede especificar como entrada de archivo o stdin si el valor de la opción es un “-”.

Configuración TCTI

El TCTI, o “Interfaz de Transmisión”, es el mecanismo de comunicación con el TPM. Los TCTIs se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre tiene precedencia sobre la variable de entorno.

Los TCTIs conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Utilizado al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y, por lo tanto, soportan no usar un TCTI. Las herramientas que no lo soportan generarán un error al intentar usarlas sin una conexión TCTI. No soporta *NINGUNA* opción y *DEBE* ser presentado como el texto exacto de “none”.

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opcion-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <config-opcion-tcti> resulta en que se use el valor predeterminado para esa parte respectivamente.

Valores Predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán tabrmd, device y mssim TCTIs EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor “default-tcti” indicará cuál de los TCTIs mencionados anteriormente es el predeterminado.

tpm2_policynv(1) — tpm2-tools documentation

NAME

tpm2_policynv

SYNOPSIS

tpm2_policynv [-h | --help] [-V | --version] [-T TCTI] [-C auth] [-S session] [-L policy] [-P nvpass] [-i nvindex] [-d | --decrypt] [-r | --raw-output] {eq | neq | sge | sgt | sle | slt} [input_data]

DESCRIPTION

The tpm2_policynv command is used to define a policy that can be used for authorizing TPM actions. This policy requires the TPM to perform a comparison operation of the data read from a specified NV index against the data specified in the command options.

The command supports various comparison operators:

•
eq: Checks if the NV index data is equal to the input data.
•
neq: Checks if the NV index data is not equal to the input data.
•
sge: Checks if the NV index data is greater than or equal to the input data.
•
sgt: Checks if the NV index data is greater than the input data.
•
sle: Checks if the NV index data is less than or equal to the input data.
•
slt: Checks if the NV index data is less than the input data.

The NV index is specified using the -i option, and its authorization policy is specified using the -P option. The comparison value is provided as input_data or via standard input if - is used. The resulting policy digest is saved to the file specified by the -L option.

The command also supports session management and TCTI configuration, allowing flexibility in how the TPM is accessed.

OPTIONS

A summary of options is included below.

•
-h, --help:
Prints the help messages.
•
-V, --version:
Prints the version string of the tool.
•
-T TCTI, --tcti=TCTI:
Specifies the Tabernacle Configuration and Transport Interface (TCTI) module to use. For more details, see TCTI OPTIONS.
•
-C auth, --context=auth:
The authorization value for the NV index. This can be a password, a policy digest, or a handle.
•
-S session, --session=session:
The session context file generated by tpm2_startauthsession(1). This is required for policy sessions.
•
-L policy, --policy=policy:
The file where the resulting policy digest will be stored.
•
-P nvpass, --nv-pass=nvpass:
The authorization value for the NV index. This can be a password, a policy digest, or a handle.
•
-i nvindex, --nv-index=nvindex:
The index of the NV index to perform the comparison against. This can be a numeric value or a name (e.g., 0x01500001).
•
-d, --decrypt:
Decrypts the NV index data before comparison. This requires the NV index to be created with the policy-write attribute.
•
-r, --raw-output:
Outputs the raw policy digest instead of the hexadecimal representation.

COMMON OPTIONS

The following options are common to most tpm2-* tools:

•
-T TCTI, --tcti=TCTI:
Specifies the Tabernacle Configuration and Transport Interface (TCTI) module to use. For more details, see TCTI OPTIONS.

TCTI Configuration

The TCTI can be specified via the -T option or the TPM2TOOLS_TCTI environment variable. The TCTI value is of the form: name[:option[,option]]... The TCTI name is a string identifying the TCTI module. The options are key-value pairs, where the key and value are separated by ‘=’ and pairs are separated by ‘,’. If an option value contains spaces or commas, it should be enclosed in quotes.

The following TCTIs are recognized:

•
device:
Uses a direct device TCTI. The following options are supported:
•
path: Specifies the path to the TPM device file. Defaults to /dev/tpm0.
Example: -T device:/dev/tpmrm0
•
mssim:
Uses the mssim simulator TCTI. The following options are supported:
•
host: The hostname or IP address of the simulator. Defaults to 127.0.0.1.
•
port: The port number of the simulator. Defaults to 2321.
Example: -T mssim:host=localhost,port=2321
•
abrmd:
Uses the tpm2-abrmd TCTI. The following options are supported:
•
bus_name: The name of the abrmd service on the D-Bus. Defaults to `com.intel.tss.Tpm2Abrmd`.
•
bus_type: The type of the D-Bus instance. Can be `session` or `system`. Defaults to `session`.
Example: -T abrmd:bus_type=system,bus_name=com.example.Tpm2Abrmd

If no TCTI is specified, the command will attempt to use the default TCTI, which is typically device.

The TCTI name can also be a path to a shared library that implements the TCTI interface. In this case, the library is loaded using dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Test if NV index content value is equal to an input number. To do this we first create an NV index of size 1 byte and write a value. Eg. 0xAA. Next we attempt to create a policy that becomes valid if the equality comparison operation of the NV index content against the one specified in the tool options.

Define the test NV Index and write the value 0xAA to it

nv_test_index=0x01500001
tpm2_nvdefine -C o -p nvpass $nv_test_index -a "authread|authwrite" -s 1
echo "aa" | xxd -r -p | tpm2_nvwrite -P nvpass -i- $nv_test_index

Attempt defining policynv with wrong comparison value specified in options.

tpm2_startauthsession -S session.ctx --policy-session
### This should fail
echo 0xBB | tpm2_policynv -S session.ctx -L policy.nv -i- 0x1500001 eq -P nvpass
tpm2_flushcontext session.ctx

Attempt defining policynv with right comparison value specified in options.

tpm2_startauthsession -S session.ctx --policy-session
### This should pass
echo 0xAA | tpm2_policynv -S session.ctx -L policy.nv -i- 0x1500001 eq -P nvpass
tpm2_flushcontext session.ctx

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
