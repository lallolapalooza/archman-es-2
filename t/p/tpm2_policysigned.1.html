tpm2_policysigned(1) Manual de Comandos Generales tpm2_policysigned(1)

NOMBRE

tpm2_policysigned(1) - Habilita la autorización de políticas verificando la firma de parámetros opcionales de TPM2. La firma es generada por una autoridad firmante.

SINOPSIS

tpm2_policysigned [OPCIONES]

DESCRIPCIÓN

tpm2_policysigned(1) - Habilita la autorización de políticas verificando la firma de parámetros opcionales de TPM2. La firma es generada por una autoridad firmante. Los parámetros opcionales de TPM2 que se verifican son cpHashA, nonceTPM, policyRef y expiration.

OPCIONES

•
-L, --policy=ARCHIVO:

Archivo para guardar el resumen de la política compuesta.

•
-S, --session=ARCHIVO:

El archivo de sesión de política generado a través de la opción -S de tpm2_startauthsession(1).

•
-c, --key-context=OBJETO:

Objeto de contexto para la clave utilizada en la operación. Puede ser un archivo o un identificador. Consulte la sección "Formato del Objeto de Contexto".

•
-g, --hash-algorithm=ALGORITMO:

El algoritmo de hash utilizado para resumir el mensaje.

•
-s, --signature=ARCHIVO:

El archivo de entrada de la firma a validar.

•
-f, --format=FORMATO:

Establece el archivo de firma de entrada a un formato especificado. El valor predeterminado es el formato de datos TPMT_SIGNATURE de tpm2.0, sin embargo, se pueden seleccionar diferentes esquemas si los datos provienen de una fuente externa como OpenSSL. La herramienta actualmente soporta rsassa y ecdsa.

•
-t, --expiration=NÚMERO_NATURAL:

Establece el tiempo de expiración de la política en segundos. En ausencia de nonceTPM, el tiempo de expiración es el valor de tiempo de espera de la política. Si la expiración es un valor negativo, adicionalmente se devuelve un ticket de autorización. Si el valor de expiración es 0, la política no tiene límite de tiempo en la autorización.

•
--cphash-input=ARCHIVO:

El hash de parámetros del comando (cpHash), que exige que el comando TPM a autorizar, así como su identificador y valores de parámetros, sean verificados.

•
--ticket=ARCHIVO:

El archivo para registrar la estructura del ticket de autorización.

•
--timeout=ARCHIVO:

La ruta del archivo para registrar la estructura de tiempo de espera devuelta.

•
-q, --qualification=CADENA_HEX_O_ARCHIVO:

Opcional, los datos de cualificación de política que la autoridad firmante puede elegir incluir en la firma. Puede ser una cadena hexadecimal o una ruta.

•
-x, --nonce-tpm:

Habilita la comparación del nonceTPM de la sesión actual para asegurar que la validez de la autorización de la política se limita a la sesión actual.

Configuración TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre tiene prioridad sobre la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Se utiliza al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializa una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, soportan no usar un TCTI. Las herramientas que no lo soportan generarán un error cuando se intenten usar sin una conexión TCTI. No soporta *NINGUNA* opción y *DEBE* presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<configuración-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <configuración-opciones-tcti> resulta en el uso del valor predeterminado para esa parte respectivamente.

Valores Predeterminados del TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim **EN ESE ORDEN** y **UTILIZARÁN EL PRIMERO QUE ENCUENTREN**. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs Personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica puede ser cargado. Las herramientas internamente utilizan dlopen(3), y el valor crudo nombre-tcti se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca tal como lo entiende la semántica de dlopen(3).

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo de dispositivo de caracteres TPM a utilizar por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares clave-valor simples separados por un carácter ','. Cada clave y valor de cadena están separados por un carácter '='.
•
El TCTI abrmd admite dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia dbus (una cadena) limitada a `session' y `system'.

Especifique el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifique el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

Autoriza una operación TPM sobre un objeto cuya autorización está ligada a una autoridad de firma específica.

Crear la autoridad de firma

openssl genrsa -out private.pem 2048
openssl rsa -in private.pem -outform PEM -pubout -out public.pem

Generar firma con nonceTPM, cpHashA, policyRef y expiración establecida a 0

echo "00 00 00 00" | xxd -r -p | \
openssl dgst -sha256 -sign private.pem -out signature.dat

Cargar la clave de verificación y crear la política policysigned

tpm2_loadexternal -C o -G rsa -u public.pem -c signing_key.ctx
tpm2_startauthsession -S session.ctx
tpm2_policysigned -S session.ctx -g sha256 -s signature.dat -f rsassa \
-c signing_key.ctx -L policy.signed
tpm2_flushcontext session.ctx

Crear un objeto de sellado para usar el policysigned

echo "plaintext" > secret.data
tpm2_createprimary -C o -c prim.ctx
tpm2_create -u key.pub -r sealing_key.priv -c sealing_key.ctx -C prim.ctx \
-i secret.data -L policy.signed

Satisfacer la política y desellar secreto

tpm2_startauthsession -S session.ctx --policy-session
tpm2_policysigned -S session.ctx -g sha256 -s signature.dat -f rsassa \
-c signing_key.ctx -L policy.signed
tpm2_unseal -p session:session.ctx -c sealing_key.ctx
tpm2_flushcontext session.ctx

Retornos

Las herramientas pueden devolver cualquiera de los siguientes códigos:

•
0 - Éxito.
•
1 - Error general no específico.
•
2 - Error de manejo de opciones.
•
3 - Error de autenticación.
•
4 - Error relacionado con TCTI.
•
5 - Esquema no soportado. Aplicable a tpm2_testparams.

Limitaciones

Espera que una sesión ya se haya establecido a través de tpm2_startauthsession(1) y requiere una de las siguientes opciones:

•
acceso directo al dispositivo
•
soporte de sesión extendida con tpm2-abrmd.

Sin esto, la mayoría de los administradores de recursos no guardarán el estado de la sesión entre invocaciones de comandos.
