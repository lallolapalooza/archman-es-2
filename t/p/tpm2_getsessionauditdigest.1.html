tpm2_getsessionauditdigest(1) Manual de Comandos Generales tpm2_getsessionauditdigest(1)

NOMBRE

tpm2_getsessionauditdigest(1) - Recupera los datos de atestación de auditoría de comandos del TPM.

SINOPSIS

tpm2_getsessionauditdigest [OPCIONES]

DESCRIPCIÓN

tpm2_getsessionauditdigest(1) - Recupera los datos de atestación del resumen de auditoría de sesión del TPM. Los datos de atestación incluyen el resumen de auditoría de sesión y una firma sobre el resumen de auditoría de sesión. La sesión en sí se inicia con el comando tpm2_startauthsession.

OPCIONES

•
-P, --hierarchy-auth=AUTH:

Especifica el valor de autorización para la jerarquía de respaldo (endorsement).

•
-c, --key-context=OBJECT:

Objeto de contexto para la clave de firma que firma los datos de atestación.

•
-p, --auth=AUTH:

Especifica el valor de autorización para la clave especificada por la opción -c.

•
-q, --qualification=HEX_STRING_OR_PATH:

Datos proporcionados como cadena hexadecimal o archivo binario para calificar la cita, opcional. Esto se usa típicamente para agregar una nonce contra ataques de repetición.

•
-s, --signature=FILE:

Archivo de salida de la firma, registra la firma en el formato especificado a través de la opción -f.

•
-m, --message=FILE:

Archivo de salida del mensaje, registra el mensaje de cita que constituye los datos firmados por el TPM. Estos son los datos de atestación del resumen de auditoría de comandos.

•
-f, --format=FORMAT:

Selección de formato para el archivo de salida de la firma.

•
-g, --hash-algorithm:

Algoritmo hash para la firma. Por defecto es sha256.

•
--scheme=ALGORITHM:

El esquema de firma utilizado para firmar el mensaje. Opcional. Los esquemas de firma deben seguir los "estándares de formato", véase la sección "Especificadores de Algoritmos". Además, véase la sección "Esquemas de Firma Soportados" para una lista de esquemas de firma soportados. Si se especifica, el esquema de firma debe coincidir con el tipo de clave. Si se deja sin especificar, se utilizará un esquema de firma por defecto para el tipo de clave.

•
-S, --session=FILE:

La ruta de la sesión que habilita y registra los resúmenes de auditoría.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un manejador o un nombre de archivo, se determina de acuerdo con la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio TPM restaurado.
•
Si el argumento es una coincidencia de *prefijo* en uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un manejador, por ejemplo, 0x81010013 y se usará directamente._OBJECT_.

Formateo de Autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autorizaciones tienen por defecto la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación utilizando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña en cadena, especificada por el prefijo "str:" o su ausencia (cadena sin procesar sin prefijo) no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña en cadena hexadecimal, especificada por el prefijo "hex:" se convierte de una forma hexadecimal a una forma de matriz de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no aptos para terminales.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo "file:" debería ser la ruta de un archivo que contenga la contraseña a leer por la herramienta o un "-" para usar la entrada estándar. Almacenar contraseñas en archivos evita fugas de información; las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de funciones comunes del historial de la shell.

Ejemplos

# para usar la entrada estándar y ser solicitado
file:-
# para usar un archivo de una ruta
file:ruta/al/archivo/contraseña
# para hacer eco de una contraseña a través de la entrada estándar:
echo foobar | tpm2_tool -p file:-
# para usar una cadena de shell bash a través de la entrada estándar:
tpm2_tool -p file:- <<< foobar

Sesiones

Al utilizar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego, indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación para ser enviado con el manejador de sesión (por ejemplo, política de contraseña), añada un "+" y una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones de PCR

Puede satisfacer una política de PCR usando el prefijo "pcr:" y el minilenguaje PCR. El minilenguaje PCR es el siguiente: <espec-pcr>=<archivo-pcr-crudo>

La especificación de PCR se documenta en la sección "Especificadores de bancos de PCR".

El archivo-pcr-crudo es un argumento **opcional** que contiene la salida del contenido crudo de PCR tal como lo devuelve tpm2_pcrread(1).

Especificadores de bancos de PCR

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

Ejemplos

Para satisfacer una política de PCR de sha256 en los bancos 0, 1, 2 y 3, use un especificador de:

pcr:sha256:0,1,2,3

especificando AUTH.

Especificadores de Formato de Firma

Selección de formato para el archivo de salida de la firma. tss (el valor predeterminado) generará un blob binario de acuerdo con la especificación TPM 2.0 y cualquier posible relleno del compilador. La opción plain generará los datos de firma simples según lo definido por el algoritmo criptográfico utilizado. firma FORMAT.

Configuración TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPM a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software TPM.
•
device - Utilizado cuando se habla directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo admiten generarán un error cuando se intenten usar sin una conexión TCTI. No admite NINGUNA opción y DEBE presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o el <config-opciones-tcti> resulta en el uso del valor predeterminado para esa parte respectivamente.

Valores Predeterminados de TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando las semánticas de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para imprimir la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados anteriormente es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor crudo nombre-tcti se utiliza para la búsqueda. Por lo tanto, podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entiendan las semánticas de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres TPM para su uso por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter `,`. Cada cadena de clave y valor están separadas por un carácter `=`.
•
El TCTI abrmd admite dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia dbus (una cadena) limitada a `session' y `system'.

Especifique el nombre TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifique el TCTI abrmd (predeterminado) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

tpm2_createprimary -Q -C e -c prim.ctx
tpm2_create -Q -C prim.ctx -c signing_key.ctx -u signing_key.pub \
-r signing_key.priv
tpm2_startauthsession -S session.ctx --audit-session
tpm2_getrandom 8 -S session.ctx
tpm2_getsessionauditdigest -c signing_key.ctx -m att.data -s att.sig \
-S session.ctx

•
0 - Éxito.
•
1 - Error general no específico.
•
2 - Error en el manejo de opciones.
•
3 - Error de autenticación.
•
4 - Error relacionado con TCTI.
•
5 - Esquema no admitido. Aplicable a tpm2_testparams.
