NOMBRE

tpm2_policynamehash(1) - Vincula una política con los nombres de objetos específicos.

SINOPSIS

tpm2_policynamehash [OPCIONES]

DESCRIPCIÓN

tpm2_policynamehash(1) - Vincula una política con los nombres de objetos específicos. Esta es una aserción diferida donde el hash de los nombres de todos los identificadores de objeto en un comando TPM se verifica contra el especificado en la política.

OPCIONES

•
-L, --policy=ARCHIVO:

Archivo donde se guardará el resumen de la política compuesta.

•
-S, --session=ARCHIVO:

El archivo de sesión de política generado a través de la opción -S de tpm2_startauthsession(1).

•
-n, --name=ARCHIVO:

El archivo que contiene el hash del nombre de los objetos referenciados.

Configuración TCTI

El TCTI o 'Interfaz de Transmisión' es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPM a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Normalmente se usa para comunicarse con el simulador de software TPM.
•
device - Se usa al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y, por lo tanto, soportan no usar un TCTI. Las herramientas que no lo soportan generarán un error cuando se intenten usar sin una conexión TCTI. No soporta *NINGUNA* opción y *DEBE* presentarse como el texto exacto de 'none'.

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<configuración-opciones-tcti>

Especificar una cadena vacía para <nombre-tcti> o <configuración-opciones-tcti> resulta en que se utilice el valor predeterminado para esa parte respectivamente.

Predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI de tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor 'default-tcti' indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs Personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica puede ser cargado. Las herramientas internamente utilizan dlopen(3), y el valor crudo del nombre-tcti se usa para la búsqueda. Por lo tanto, podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca tal como lo entiende la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres TPM a utilizar por el TCTI de dispositivo. El predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por una coma ','. Cada clave y valor de cadena están separados por un signo '='.
•
El TCTI abrmd soporta dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia de dbus (una cadena) limitada a `session' y `system'.

Especificar el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especificar el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

NAME

tpm2_policynamehash - To get a hash of the name of a TPM object and then hash that to verify that the object name has a given value.

SYNOPSIS

tpm2_policynamehash [OPTIONS] [-L policy file] [-S session file] [-n name of object] [-t ticket file]

DESCRIPTION

tpm2_policynamehash is used to perform a policy action. This tool is used to demonstrate the TPM2_CC_PolicyNameHash command.

This command is used to check if the name of an object matches a given name, or if a hash of the name of an object matches a given hash.

The command is used in conjunction with tpm2_policyauthorize to sign a hash of the name of an object. The signed hash can then be used to authorize operations.

This tool may be used to enforce policies that restrict operations to specific objects or types of objects. For example, a policy could be created to allow an operation only if the object being operated on is a specific key that has been signed by a particular signing key.

OPTIONS

The following options are available:

-L
policy file
-S
session file
-n
name of object
-t
ticket file

COMMON OPTIONS

These options are common to many tpm2_tool commands:

-C context
The TPM context of the object to load.
-c context file
The file containing the TPM context. Default: policy.ctx
-P password
The password for the object.
-p password
The password for the object.
-T
TCTI context
-I
TCTI context
-Q
Quiet output.
-V
Verbose output.
-l
List available command invocations.
-u
Usage information.

TCTI Configuration

The TPM Trustd Command Interface (TCTI) is the interface between the tpm2-tools and the TPM device. The TCTI can be specified using the -T or -I options, or through environment variables. The default TCTI is the libtss2-tcti-mssim.so.0.

TCTI OPTIONS

-T device TCTI string
Specifies the TCTI string to use for connecting to the TPM.
-I device TCTI string
Specifies the TCTI string to use for connecting to the TPM. This is an alias for -T.

For example, to use the system default TCTI:

    $ tpm2_policynamehash -T device

To use the simulator TCTI:

    $ tpm2_policynamehash -T mssim

EXAMPLES

The following examples demonstrate how to use tpm2_policynamehash to create and sign a policy that restricts the duplication of a key.

Generate a duplicable object

openssl genrsa -out signing_key_private.pem 2048
openssl rsa -pubout -in signing_key_private.pem -out signing_key_public.pem
tpm2_loadexternal -G rsa -C o -u signing_key_public.pem -c signing_key.ctx \
-n signing_key.name
tpm2_startauthsession -S session.ctx -g sha256
tpm2_policyauthorize -S session.ctx -L authorized.policy -n signing_key.name
tpm2_policycommandcode -S session.ctx -L policy.dat TPM2_CC_Duplicate
tpm2_flushcontext session.ctx
tpm2_createprimary -C o -g sha256 -G rsa -c primary.ctx -Q
## The duplicable key
tpm2_create -Q -C primary.ctx -g sha256 -G rsa -r key.prv -u key.pub \
-L policy.dat -a "sensitivedataorigin|sign|decrypt"
tpm2_load -Q -C primary.ctx -r key.prv -u key.pub -c key.ctx

Create the new parent

tpm2_create -Q -C primary.ctx -g sha256 -G rsa -r new_parent.prv \
-u new_parent.pub \
-a "decrypt|fixedparent|fixedtpm|restricted|sensitivedataorigin"
tpm2_loadexternal -Q -C o -u new_parent.pub -c new_parent.ctx

Modify the duplicable key policy to namehash policy to restrict parent and key

tpm2_readpublic -Q -c new_parent.ctx -n new_parent.name
tpm2_readpublic -Q -c key.ctx -n key.name
cat key.name new_parent.name | openssl dgst -sha256 -binary > name.hash
tpm2_startauthsession -S session.ctx -g sha256
tpm2_policynamehash -L policy.namehash -S session.ctx -n name.hash
tpm2_flushcontext session.ctx
openssl dgst -sha256 -sign signing_key_private.pem \
-out policynamehash.signature policy.namehash
tpm2_startauthsession -S session.ctx -g sha256
tpm2_policyauthorize -S session.ctx -L authorized.policy -i policy.namehash \
-n signing_key.name
tpm2_policycommandcode -S session.ctx -L policy.dat TPM2_CC_Duplicate
tpm2_flushcontext session.ctx

Satisfy the policy and attempt key duplication

tpm2_verifysignature -c signing_key.ctx -g sha256 -m policy.namehash \
-s policynamehash.signature -t verification.tkt -f rsassa
tpm2_startauthsession -S session.ctx --policy-session -g sha256
tpm2_policynamehash -S session.ctx -n name.hash
tpm2_policyauthorize -S session.ctx -i policy.namehash -n signing_key.name \
-t verification.tkt
tpm2_policycommandcode -S session.ctx TPM2_CC_Duplicate
tpm2_duplicate -C new_parent.ctx -c key.ctx -G null -p "session:session.ctx" \
-r dupprv.bin -s dupseed.dat
tpm2_flushcontext session.ctx

•

•

•
3 - Authentication error.
•
4 - TCTI related error.
•

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
