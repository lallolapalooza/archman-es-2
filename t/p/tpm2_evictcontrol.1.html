tpm2_evictcontrol(1) Manual de Comandos Generales tpm2_evictcontrol(1)

NOMBRE

tpm2_evictcontrol(1) - Hace que un objeto transitorio sea persistente o expulsa un objeto persistente.

SINOPSIS

tpm2_evictcontrol [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_evictcontrol(1) - Permite que un objeto transitorio se convierta en persistente o que un objeto persistente sea expulsado. El argumento HANDLE controla el índice al que se asignará el handle. Si el objeto especificado a través de -c es transitorio y se especifica un HANDLE permanente, el objeto se hará persistente en HANDLE. Si HANDLE es un -, entonces el objeto se hará persistente en la primera ubicación de handle permanente disponible. Si el objeto especificado a través de -c es un handle permanente, entonces el objeto será expulsado de su ubicación de handle permanente.

OPCIONES

•
-C, --hierarchy=OBJECT:

La jerarquía de autorización utilizada para autorizar los comandos. Por defecto es la jerarquía de “propietario”. Opciones soportadas son:

•
o para TPM_RH_OWNER
•
p para TPM_RH_PLATFORM
•
<num> donde se puede usar un número bruto.
•
-c, --object-context=OBJECT:

Un especificador de objeto de contexto de un objeto transitorio o persistente. Si OBJECT es un objeto transitorio, se hará persistente, ya sea en el handle especificado por el argumento o en la primera ubicación de handle persistente vacante disponible. Si el OBJECT es para un objeto persistente, entonces el objeto será expulsado de la memoria no volátil.

•
-P, --auth=AUTH:

El valor de autorización para la jerarquía especificada con -C.

•
-o, --output=FILE:

Opcionalmente, genera un objeto serializado que representa el handle persistente. Si no se manipula, estos archivos son más seguros de usar que los handles persistentes brutos. Se debe verificar un handle persistente bruto para asegurarse de que el objeto al que apunta es el esperado.

•
--cphash=FILE

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash.

•
ARGUMENT el argumento de la línea de comandos especifica el handle persistente al que se guardará el objeto transitorio.

Salida

La herramienta genera un diccionario compatible con YAML con los campos: persistent-handle: action: evicted|persisted

Donde persistent-handle es el handle sobre el que se realizó la acción. Donde action puede ser evicted (expulsado) o persisted (persistente). Si un objeto es evicted, entonces el objeto ya no reside en la dirección persistent-handle dentro del TPM. Si un objeto es persisted, entonces el objeto reside en la dirección persistent-handle dentro del TPM.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un handle o un nombre de archivo, se determina según la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio del TPM restaurado.
•
Si el argumento es una coincidencia de *prefijo* en uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un handle, por ejemplo, 0x81010013 y se usará directamente.*OBJECT*.

Formato de Autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: “Las autorizaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican”.

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación, utilizando prefijos.

Nota: Por defecto, se asume que las contraseñas están en forma de cadena cuando no tienen prefijo.

Cadena

Una contraseña en forma de cadena, especificada por el prefijo “str:” o su ausencia (cadena sin prefijo) no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña en forma de cadena hexadecimal, especificada por el prefijo “hex:”, se convierte de una forma hexadecimal a una forma de array de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables con la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo “file:”, debe ser la ruta de un archivo que contenga la contraseña a ser leída por la herramienta o un “-” para usar la entrada estándar. Almacenar contraseñas en archivos previene fugas de información, las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las funciones comunes del historial del shell.

Ejemplos

# para usar entrada estándar y ser solicitado
file:-
# para usar un archivo desde una ruta
file:ruta/al/archivo/de/contraseña
# para enviar una contraseña a través de entrada estándar:
echo foobar | tpm2_tool -p file:-
# para usar una "here-string" de bash a través de entrada estándar:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego indique una ruta a un archivo de sesión que fue creado con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación para ser enviado con el handle de la sesión (por ejemplo, contraseña de política), entonces añada un + y una cadena como se describe en la sección de Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones de PCR

Puede satisfacer una política de PCR usando el prefijo “pcr:” y el minilenguaje de PCR. El minilenguaje de PCR es el siguiente: <pcr-spec>=<archivo-pcr-bruto>

T

El argumento raw-pcr-file es un argumento opcional que contiene la salida de los contenidos brutos del PCR tal como los devuelve tpm2_pcrread(1).

Configuración del TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPM a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre tiene prioridad sobre la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente se usa para comunicarse con el simulador de software del TPM.
•
device - Se usa al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo soportan generarán un error al intentar usarse sin una conexión TCTI. No soporta NINGUNA opción y DEBE SER presentado como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<tcti-name>:<tcti-option-config>

Especificar una cadena vacía para el <tcti-name> o el <tcti-option-config> resulta en el uso del valor predeterminado para esa parte respectivamente.

Valores predeterminados del TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando las semánticas de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados anteriormente es el predeterminado.

TCTIs personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica se puede cargar. Las herramientas utilizan internamente dlopen(3), y el valor tcti-name bruto se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca tal como lo entiende la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo carácter del TPM para su uso por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter `,`. Cada clave y cadena de valor están separadas por un carácter `=.
•
El TCTI abrmd soporta dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia de dbus (una cadena) limitada a `session' y `system'.

Especifique el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifique el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

Para hacer un manejador transitorio persistente en la dirección 0x81010002

tpm2_changeauth -c o ownerauth
tpm2_createprimary -c primary.ctx -P ownerauth
tpm2_evictcontrol -C o -c primary.ctx 0x81010002 -P ownerauth

Para eliminar un manejador persistente

tpm2_evictcontrol -C o -c 0x81010002 -P ownerauth

Para hacer un manejador transitorio persistente y mostrar un manejador persistente serializado.

tpm2_evictcontrol -C o -c primary.ctx -o primary.handle -P ownerauth

TPM2 Commands

Nombre

tpm2_evictcontrol - Controla la evicción de objetos persistentes.

Descripción

tpm2_evictcontrol es un comando en la suite tpm2-tools que permite controlar objetos persistentes en el TPM. Los objetos persistentes son aquellos que sobreviven a un reinicio del TPM. Este comando permite evicted (eliminar) objetos persistentes especificados por su handle.

Opciones

-c, --parent-context <context_file>

El contexto del padre para la sesión. Esto permite que el comando acceda a objetos persistentes o claves que se gestionan en una sesión de TPM activa.

-ha, --parent-auth <hex_auth>

La contraseña del padre en formato hexadecimal. Necesaria si la política de autorización del objeto padre requiere una contraseña.

-po, --parent-policy <hex_policy>

La política de autorización del padre en formato hexadecimal. Útil si el objeto padre está protegido por una política.

-ho, --handle-object <handle>

El handle del objeto persistente a evicted. Este es el handle que se le dio al objeto cuando se creó inicialmente (por ejemplo, un handle que comienza con 0x8000000X).

-pwd, --policy-password <hex_policy>

La contraseña de política para el objeto a evicted en formato hexadecimal. Si el objeto está protegido por una política, se requiere esta contraseña para poder evicted.

-pwc, --policy-password-context <context_file>

El contexto de política para el objeto a evicted. Esto se utiliza cuando la política se define usando un archivo de contexto.

-pu, --policy-uživatelske <uživatelske_hex>

La entrada de política de usuario en formato hexadecimal. Si el objeto está protegido por una política de usuario, se requiere esta entrada.

-P, --password <password>

La contraseña en texto plano para el objeto a evicted. En lugar de pasar la contraseña en formato hexadecimal, se puede pasar en texto plano.

-hal, --auth-handle <handle>

El handle del objeto de autorización. Se utiliza si el objeto a evicted requiere un objeto de autorización específico (como una clave de firma) para su evicted.

-tcti, --tcti <tcti_name>

Especifica el TCTI (Transport Connection and Teaming Interface) a utilizar. Los valores comunes son:

  • device: Utiliza el dispositivo TPM estándar (ej. /dev/tpm0).
  • mssim: Utiliza un simulador TPM en modo multi-sesión.
  • socket: Utiliza una conexión socket a un TPM simulado o remoto.

También se pueden especificar parámetros adicionales para el TCTI usando la sintaxis <tcti_name>:param1=val1:param2=val2.

-eq, --ensure-capability <capability>

Asegura que el TPM tenga la capacidad especificada. Esto puede ser útil para garantizar que ciertas funcionalidades del TPM estén disponibles antes de ejecutar el comando.

-D, --debug

Habilita la salida de depuración detallada.

-H, --help

Muestra un mensaje de ayuda y sale.

-v, --version

Muestra la información de la versión y sale.

Opciones Comunes

Los comandos de tpm2-tools soportan una serie de opciones comunes que no se enumeran aquí explícitamente pero que se documentan en tpm2_options(7).

Configuración TCTI

El TCTI (Transport Connection and Teaming Interface) es la capa que permite a las herramientas de tpm2-tools interactuar con el hardware del TPM. El TCTI por defecto suele ser device, que intenta conectarse al dispositivo TPM del sistema (generalmente /dev/tpm0).

Los TCTI alternativos, como socket o mssim, se utilizan para interactuar con simuladores de TPM o instancias de TPM remotas. La configuración de estos TCTI puede requerir parámetros adicionales, especificados como pares clave-valor separados por dos puntos (:) después del nombre del TCTI.

Por ejemplo:

  • -tcti socket:host=127.0.0.1:port=8000: Conecta a un simulador de TPM en el host 127.0.0.1 en el puerto 8000.
  • -tcti device:/dev/tpmrm0: Especifica un dispositivo TPM alternativo.

Opciones TCTI

Algunos TCTI pueden tener opciones específicas. Estas se pasan usando la sintaxis <tcti_name>:param1=val1:param2=val2.

Para el TCTI device, se puede especificar el path al dispositivo TPM.

Para el TCTI socket, se pueden especificar el host y el port de la instancia remota del TPM.

Ejemplos

  1. Eviccionar un objeto persistente con su handle

    Este comando evicciona un objeto persistente con el handle 0x80000001. Se asume que el objeto no requiere autenticación especial para su evicted.

    tpm2_evictcontrol -ho 0x80000001

  2. Eviccionar un objeto persistente protegido por una política

    Si el objeto persistente con handle 0x80000002 está protegido por una política de autorización y se conoce la contraseña de la política en formato hexadecimal (01020304), se puede usar:

    tpm2_evictcontrol -ho 0x80000002 -pwc 01020304

  3. Eviccionar un objeto persistente usando el TCTI socket

    Este comando evicciona el objeto con handle 0x80000003 conectándose a un simulador de TPM en localhost, puerto 8000.

    tpm2_evictcontrol -tcti socket:host=127.0.0.1:port=8000 -ho 0x80000003

  4. Eviccionar un objeto persistente usando una contraseña en texto plano

    Si el objeto persistente con handle 0x80000004 requiere la contraseña "mi_secreta_contraseña" para su evicted:

    tpm2_evictcontrol -ho 0x80000004 -P mi_secreta_contraseña

Devoluciones

Devuelve 0 si la operación fue exitosa. En caso de error, devuelve un valor distinto de cero indicando el código de error.

Errores

Los errores son reportados normalmente a través de la salida estándar de errores. Se puede utilizar la opción -D para obtener información de depuración adicional.

Para reportar errores o solicitar nuevas características, por favor visite el repositorio de tpm2-tools en GitHub.

Ayuda

Para obtener ayuda sobre el uso de tpm2_evictcontrol, puede ejecutar el comando con la opción -h o --help:

tpm2_evictcontrol -h
