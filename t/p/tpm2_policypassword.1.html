tpm2_policypassword(1) Manual general de comandos tpm2_policypassword(1)

NOMBRE

tpm2_policypassword(1) - Habilita la vinculación de una política al valor de autorización del objeto TPM autorizado.

SINOPSIS

tpm2_policypassword [OPCIONES]

DESCRIPCIÓN

tpm2_policypassword(1) - Habilita una política que requiere que se proporcione la contraseña de autenticación del objeto. Esto es equivalente a autenticarse utilizando la contraseña del objeto en texto plano, solo que esto la impone como una política. Proporciona un mecanismo para permitir la autenticación por contraseña cuando un objeto solo permite la autorización basada en políticas, es decir, el atributo del objeto “userwithauth” es 0.

OPCIONES

•
-L, --policy=ARCHIVO:

Archivo para guardar el resumen de la política compuesta.

•
-S, --session=ARCHIVO:

El archivo de sesión de política generado a través de la opción -S de tpm2_startauthsession(1).

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash.

Configuración TCTI

El TCTI o “Interfaz de Transmisión” es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para comunicarse con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software de TPM.
•
device - Utilizado cuando se habla directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo admiten darán un error cuando se intenten usar sin una conexión TCTI. No admite NINGUNA opción y DEBE presentarse como el texto exacto de “none”.

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <config-opciones-tcti> da como resultado el uso del valor predeterminado para esa porción respectivamente.

Valores Predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando semántica de dlopen(3). Las herramientas buscarán los TCTIs tabrmd, device y mssim EN ESE ORDEN y UTILIZARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado usando la opción -v para mostrar la información de la versión. El par clave-valor “default-tcti” indicará cuál de los TCTIs mencionados anteriormente es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor tcti-name en bruto se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entienda la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de carácter TPM para su uso por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se pueden especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares clave-valor simples separados por un carácter `,'. Cada clave y valor de cadena están separados por un carácter `=’.
•
El TCTI abrmd admite dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de instancia de dbus (una cadena) limitada a `session' y `system'.

Especifique el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifique el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

Queremos que el objeto TPM sea autenticado por su contraseña.

Nombre

tpm2_policypassword - crear una política de contraseña para la autenticación TPM

SINOPSIS

tpm2_policypassword [-h] [-v] -L policy -p password [-S session | -s session_handle ]

DESCRIPCIÓN

La herramienta tpm2_policypassword escribe una estructura de política de contraseña en el archivo especificado por -L. Cuando se utiliza como parte de una sesión de política de TPM, requerirá que la contraseña proporcionada coincida con la contraseña esperada por el objeto TPM.

Para utilizar esta política, se requiere una sesión de política. Esto se puede crear usando tpm2_startauthsession con el flag --policy-session o con tpm2_startauthsession seguido por la invocación de tpm2_policypassword. La sesión se vinculará al hash de la política. La política será ejecutada cuando se utilice la sesión para autenticar un objeto.

Tenga en cuenta que la política de contraseña se puede aplicar de dos maneras:

  1. Direct authentication with password: En este caso, la contraseña proporcionada a tpm2_policypassword se utilizará para autenticar el objeto.
  2. Policy session authentication with password: La contraseña se almacena en la sesión de política. Cuando se usa la sesión para autenticar un objeto, se requerirá la contraseña.

La política se puede evadir autenticándose con el valor de texto plano de los objetos TPM. Si bien podríamos autenticarnos con una sesión de contraseña efímera, en este ejemplo nos autenticaremos con la contraseña de texto plano en una sesión de política en su lugar usando la herramienta tpm2_policypassword(1).

Crear la política de contraseña

tpm2_startauthsession -S session.dat
tpm2_policypassword -S session.dat -L policy.dat
tpm2_flushcontext session.dat

Crear el objeto con una contraseña y la política de contraseña

tpm2_createprimary -C o -c prim.ctx
tpm2_create -g sha256 -G aes -u key.pub -r key.priv -C prim.ctx -L policy.dat \
  -p testpswd

Autenticarse con entrada de contraseña de texto plano

tpm2_load -C prim.ctx -u key.pub -r key.priv -n key.name -c key.ctx
echo "plaintext" > plain.txt
tpm2_encryptdecrypt -c key.ctx -o encrypt.out plain.txt -p testpswd plain.txt

Autenticarse con contraseña y la política

tpm2_startauthsession \--policy-session -S session.dat
tpm2_policypassword -S session.dat -L policy.dat
tpm2_encryptdecrypt -c key.ctx -o encrypt.out \
  -p session:session.dat+testpswd plain.txt
tpm2_flushcontext session.dat

Devoluciones

Las herramientas pueden devolver alguno de los siguientes códigos:

•
0 - Éxito.
•
1 - Error general no específico.
•
2 - Error en el manejo de opciones.
•
3 - Error de autenticación.
•
4 - Error relacionado con TCTI.
•
5 - Esquema no soportado. Aplicable a tpm2_testparams.

Limitaciones

Espera que una sesión se establezca previamente a través de tpm2_startauthsession(1) y requiere uno de los siguientes:

•
acceso directo al dispositivo
•
soporte de sesión extendido con tpm2-abrmd.

Sin él, la mayoría de los administradores de recursos no guardarán el estado de la sesión entre invocaciones de comandos.
