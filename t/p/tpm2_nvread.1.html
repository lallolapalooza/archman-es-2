NOMBRE

tpm2_nvread(1) - Lee los datos almacenados en un índice No Volátil (NV).

SINOPSIS

tpm2_nvread [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_nvread(1) - Lee los datos almacenados en un índice No Volátil (NV). El índice puede especificarse como un handle bruto o un valor de desplazamiento al rango de handles NV “TPM2_HR_NV_INDEX”.

OPCIONES

•
-C, --hierarchy=OBJETO:

Especifica la jerarquía utilizada para autorizar. Las opciones soportadas son:

•
o para TPM_RH_OWNER
•
p para TPM_RH_PLATFORM
•
<num> donde se puede usar un handle de jerarquía o índice NV.

Cuando -C no se pasa explícitamente, el handle del índice se utilizará para autorizar contra el índice. El valor de autorización del índice se establece mediante la opción -p de tpm2_nvdefine(1).

•
-o, --output=ARCHIVO:

Archivo donde escribir los datos

•
-P, --auth=AUTH:

Especifica el valor de autorización para la jerarquía.

•
-s, --size=NUMERO_NATURAL:

Especifica el tamaño de los datos a leer en bytes, comenzando desde 0 si no se especifica el desplazamiento. Si no se especifica, se utilizará el tamaño de los datos según lo informado por la parte pública del índice.

•
--offset=NUMERO_NATURAL:

El desplazamiento dentro del índice NV desde donde comenzar a leer.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará el comando, simplemente devolverá un cpHash, a menos que también se requiera rphash.

•
--rphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros de la respuesta. Esto se denomina comúnmente rpHash.

•
-n, --name=ARCHIVO:

El nombre del índice NV que debe proporcionarse al calcular solo el cpHash sin ejecutar realmente el comando en el TPM.

•
-S, --session=ARCHIVO:

La sesión creada usando tpm2_startauthsession. Esto puede usarse para especificar una sesión auxiliar para auditoría y/o cifrado/descifrado de parámetros.

•
--print-yaml:

Imprime el contenido del índice NV en un formato legible por humanos, útil para mostrar el contenido de los índices de contador, bits y extensión, y de pines. Cuando se proporciona este argumento, el tamaño y el desplazamiento se ignoran.

•
ARGUMENTO el argumento de la línea de comandos especifica el índice NV o el número de desplazamiento.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un handle o un nombre de archivo, se determina de acuerdo con la siguiente lógica, en orden:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio de TPM restaurado.
•
Si el argumento coincide con un prefijo en uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento se puede cargar como un número, se tratará como un handle, por ejemplo, 0x81010013 y se usará directamente.

Formato de Autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: “Las autorizaciones se establecen por defecto en la CONTRASEÑA VACÍA cuando no se especifican”.

Contraseñas

Las contraseñas se interpretan en las siguientes formas utilizando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña en formato de cadena, especificada por el prefijo “str:” o su ausencia (cadena en bruto sin prefijo) no se interpreta y se usa directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña en formato de cadena hexadecimal, especificada por el prefijo “hex:”, se convierte de forma hexadecimal a un array de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables para la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo “file:”, debe ser la ruta de un archivo que contenga la contraseña a ser leída por la herramienta o un “-” para usar la entrada estándar. Almacenar contraseñas en archivos evita la fuga de información, las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las funciones comunes de historial del shell.

Ejemplos

# para usar la entrada estándar y ser solicitado
file:-
# para usar un archivo desde una ruta
file:ruta/al/archivo/de/contraseña
# para enviar una contraseña vía entrada estándar:
echo foobar | tpm2_tool -p file:-
# para usar un "here-string" de bash vía entrada estándar:
tpm2_tool -p file:- <<< foobar

Sesiones

Cuando se utiliza una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego, indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autorización para ser enviado con el handle de la sesión (por ejemplo, contraseña de política), agregue un + y una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización HEX 0x11223344.

session:session.ctx+hex:11223344

Nombre

tpm2_clear - Clear TPM2 objects and state.

SINÓPSIS

tpm2_clear [OPTIONS] [ARGUMENT]

DESCRIPCIÓN

The tpm2_clear command clears the TPM2 objects and state. The TPM can be reset to its factory default state. It is important to note that some TPMs may implement the clear command in varying ways. The TPM specification mandates that a clear operation should result in the following: Disable charging of the platform cert and end-orsement cert. Nullify the platform cert and end-orsement cert. Disable charging of all platform auth values. Nullify all platform auth values. Clear all loaded sessions and primary keys. Clear all primary keys.

It is also important to note that there are several ways to clear a TPM, with different implications:

clear
This is the primary command that is used to clear the TPM. It requires that the caller have the Platform Hierarchy Auth value. For systems that have the Platform Hierarchy disabled, this command will fail.
disable_owner
This command is used to disable the Platform Hierarchy. It requires that the caller have the Platform Hierarchy Auth value. This command should only be used if the Platform Hierarchy is not needed. It is recommended that this command not be used if the Platform Hierarchy is needed for any reason.
clear_control
This command allows for the clearing of certain TPM state. It is more granular than the clear command, and allows for the clearing of specific aspects of the TPM's state. This command requires that the caller have the Platform Hierarchy Auth value.
change_ep_auth
This command allows for the changing of the Endorsement Hierarchy Auth value. It requires that the caller have the Endorsement Hierarchy Auth value. This command should only be used if the Endorsement Hierarchy Auth value needs to be changed. It is recommended that this command not be used if the Endorsement Hierarchy Auth value is not needed.

PCR bank specifiers

The PCR spec is documented in in the section “PCR bank specifiers”.

The raw-pcr-file is an optional argument that contains the output of the raw PCR contents as returned by tpm2_pcrread(1).

PCR bank specifiers

Examples

To satisfy a PCR policy of sha256 on banks 0, 1, 2 and 3 use a specifier of:

Configuración de TCTI

El TCTI o “Transmission Interface” es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombres de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Utilizado cuando se habla directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y, por lo tanto, soportan no usar un TCTI. Las herramientas que no lo soportan generarán un error cuando se intente usar sin una conexión TCTI. No soporta NINGUNA opción y DEBE PRESENTARSE como el texto exacto de “none”.

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <config-opciones-tcti> resulta en el uso del valor predeterminado para esa parte respectivamente.

Valores Predeterminados de TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para imprimir la información de la versión. El par clave-valor “default-tcti” indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor nombre-tcti bruto se utiliza para la búsqueda. Por lo tanto, esta podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entiendan las semánticas de dlopen(3).

OPCIONES DE TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo de dispositivo de caracteres del TPM a utilizar por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter `,`. Cada cadena de clave y valor están separadas por un carácter `=‘.
•
TCTI abrmd soporta dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia dbus (una cadena) limitada a `session` y `system`.

Especifique el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifique el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.d)
