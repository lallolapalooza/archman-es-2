tpm2_nvwrite(1) Manual de comandos generales tpm2_nvwrite(1)

NOMBRE

tpm2_nvwrite(1) - Escribe datos en un índice No Volátil (NV).

SINOPSIS

tpm2_nvwrite [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_nvwrite(1) - Escribe datos especificados a través de ARCHIVO en un índice No Volátil (NV). Si no se especifica ARCHIVO, se utiliza la entrada estándar por defecto. El índice se especifica como un argumento y puede ser un identificador bruto o un valor de desplazamiento del rango de identificadores de NV “TPM2_HR_NV_INDEX”.

OPCIONES

•
ARGUMENTO=NÚMERO

Especifica el índice NV al que escribir como un desplazamiento del rango de índices NV inicial o un valor de índice absoluto. Ejemplo: tpm2_nvwrite 1 es igual que tpm2_nvwrite 0x01000001

•
-i, --input=ARCHIVO:

Esta es una entrada obligatoria para especificar el archivo de entrada con los datos a escribir en NV. La entrada también se puede especificar desde la entrada estándar con la opción -i-.

•
-C, --hierarchy=OBJETO:

Especifica la jerarquía utilizada para autorizar. Las opciones soportadas son:

•
o para TPM_RH_OWNER
•
p para TPM_RH_PLATFORM
•
<núm> donde se puede utilizar un identificador de jerarquía o de índice nv.

Cuando no se pasa explícitamente -C, el identificador del índice se utilizará para autorizar contra el índice. El valor de autorización del índice se establece a través de la opción -p de tpm2_nvdefine(1).

•
-P, --auth=AUTH:

Especifica el valor de autorización para la jerarquía.

•
--offset=NÚMERO_NATURAL:

El desplazamiento dentro del índice NV desde donde comenzar a escribir.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash a menos que también se requiera rphash.

•
--rphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros de respuesta. Esto se denomina comúnmente rpHash.

•
-S, --session=ARCHIVO:

La sesión creada usando tpm2_startauthsession. Esto se puede utilizar para especificar una sesión auxiliar para auditoría y/o cifrado/descifrado de los parámetros.

•
-n, --name=ARCHIVO:

El nombre del índice NV que debe proporcionarse al calcular solo el cpHash sin enviar realmente el comando al TPM.

Referencias

Formato de Objeto de Contexto

El tipo de un objeto de contexto, ya sea un identificador o un nombre de archivo, se determina de acuerdo con la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio de TPM restaurado.
•
Si el argumento es una coincidencia de *prefijo* en uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento se puede cargar como un número, se tratará como un identificador, por ejemplo, 0x81010013 y se utilizará directamente._OBJETO_.

Formato de Autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autorizaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación utilizando prefijos identificadores.

Nota: Por defecto, las contraseñas se asumen en forma de cadena cuando no tienen prefijo.

Cadena

Una contraseña de cadena, especificada con el prefijo "str:" o su ausencia (cadena sin prefijo), no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena hexadecimal

Una contraseña de cadena hexadecimal, especificada con el prefijo "hex:", se convierte de forma hexadecimal a forma de array de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables con la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada con el prefijo "file:", debe ser la ruta de un archivo que contenga la contraseña a leer por la herramienta o un "-" para usar la entrada estándar. Almacenar contraseñas en archivos evita fugas de información, las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las características comunes del historial del shell.

Ejemplos

# para usar la entrada estándar y ser preguntado
file:-
# para usar un archivo desde una ruta
file:ruta/al/archivo/de/contraseña
# para mostrar una contraseña a través de la entrada estándar:
echo foobar | tpm2_tool -p file:-
# para usar una cadena de bash a través de la entrada estándar:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave *session*. Luego indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación para ser enviado con el identificador de sesión (por ejemplo, política de contraseña), agregue un + y una cadena como se describe en la sección de **Contraseñas**.

Ejemplos

Para usar un archivo de contexto de sesión llamado *session.ctx*.

session:session.ctx

Para usar un archivo de contexto de sesión llamado *session.ctx* Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado *session.ctx* Y enviar el valor de autenticación *HEX* 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones PCR

Puede satisfacer una política de PCR utilizando el prefijo "pcr:" y el minilenguaje de PCR. El minilenguaje de PCR es el siguiente: <espec-pcr>=<archivo-pcr-crudo>

La especificación de PCR está documentada en la sección "especificadores de banco de PCR".

El archivo-pcr-crudo es un argumento **opcional** que contiene la salida de los contenidos brutos de PCR tal como se devuelve

d by tpm2_pcrread(1).

Especificadores de banco de PCR

Ejemplos

Para satisfacer una política de PCR de sha256 en los bancos 0, 1, 2 y 3, use un especificador de:

pcr:sha256:0,1,2,3

especificando AUTH.

Configuración TCTI

El TCTI o “Interfaz de Transmisión” es el mecanismo de comunicación con el TPM. Los TCTIs se pueden cambiar para comunicarse con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre tiene prioridad sobre la variable de entorno.

Los TCTIs conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Se utiliza para hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializa una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo admiten generarán un error cuando se intenten usar sin una conexión TCTI. No admite NINGUNA opción y DEBE presentarse como el texto exacto de “none”.

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opcion-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <config-opcion-tcti> da como resultado que se use el valor predeterminado para esa parte respectivamente.

Valores predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTIs tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor “default-tcti” indicará cuál de los TCTIs mencionados anteriormente es el predeterminado.

TCTIs personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor crudo nombre-tcti se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca como lo entiende la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres del TPM para que lo use el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter `,'. Cada clave y valor de cadena están separados por un carácter `=’.
•
El TCTI abrmd admite dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia dbus (una cadena) limitada a `session' y `system'.

Especifique el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifique el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

Escribir el archivo nv.data en el índice 0x01000001

tpm2_nvdefine -Q   1 -C o -s 32 -a "ownerread|policywrite|ownerwrite"
echo "please123abc" > nv.test_w
tpm2_nvwrite -Q   1 -C o -i nv.test_w

Devoluciones

Las herramientas pueden devolver cualquiera de los siguientes códigos:

•
0 - Éxito.
•
1 - Error general no específico.
•
2 - Error de manejo de opciones.
•
3 - Error de autenticación.
•
4 - Error relacionado con TCTI.
•
5 - Esquema no soportado. Aplicable a tpm2_testparams.
