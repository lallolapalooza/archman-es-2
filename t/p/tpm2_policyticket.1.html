tpm2_policyticket(1) Manual de Comandos Generales tpm2_policyticket(1)

NOMBRE

tpm2_policyticket(1) - Permite la autorización de políticas verificando un ticket que representa una autorización validada que tenía un tiempo de expiración asociado.

SINOPSIS

tpm2_policyticket [OPCIONES]

DESCRIPCIÓN

tpm2_policyticket(1) - Permite la autorización de políticas verificando un ticket que representa una autorización validada que tenía un tiempo de expiración asociado.

OPCIONES

•
-L, --policy=ARCHIVO:

Archivo donde guardar el resumen de la política combinada.

•
-S, --session=ARCHIVO:

El archivo de sesión de política generado a través de la opción -S de tpm2_startauthsession(1).

•
-n, --name=ARCHIVO:

Nombre del objeto que validó la autorización.

•
--ticket=ARCHIVO:

El archivo de ticket donde registrar la estructura del ticket de autorización.

•
--timeout=ARCHIVO:

La ruta del archivo donde registrar la estructura de tiempo de espera devuelta.

•
-q, --qualification=ARCHIVO_O_CADENA_HEX:

Opcional, los datos de calificación de la política que el firmante puede elegir incluir en la firma. Puede ser una cadena hexadecimal o una ruta.

Referencias

Configuración TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre reemplaza la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para la comunicación con el simulador de software del TPM.
•
device - Utilizado al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y por lo tanto soportan no usar un TCTI. Las herramientas que no lo soportan darán un error cuando se intenten usar sin una conexión TCTI. No soporta *NINGUNA* opción y *DEBE SER* presentado como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<configuración-opciones-tcti>

Especificar una cadena vacía para <nombre-tcti> o <configuración-opciones-tcti> resulta en el uso de los valores predeterminados para esa parte respectivamente.

Valores Predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado usando la semántica de dlopen(3). Las herramientas buscarán tabrmd, device y mssim TCTIs **EN ESE ORDEN** y **USARÁN EL PRIMERO QUE ENCUENTREN**. Puede consultar qué TCTI se elegirá como predeterminado usando la opción -v para mostrar la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados anteriormente es el predeterminado.

TCTIs Personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica puede ser cargado. Las herramientas usan internamente dlopen(3), y el valor crudo de tcti-name se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca tal como lo entiende la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres del TPM para usarlo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter `,'. Cada clave y valor se separan por un carácter `=`.
•
TCTI abrmd soporta dos claves:
1.
`bus_name': El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type': El tipo de la instancia de dbus (una cadena) limitada a `session' y `system'.

Especifica el nombre tcti de tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifica el tcti predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti=abrmd:bus_type=session

tpm2_policyticket(1)

NAME

tpm2_policyticket — Command to create a ticket with policy that authorizes an object.

SYNOPSIS

tpm2_policyticket [-h] [-v] [-c] [-p] [-S session_context] [-L policy_context] [-n name_of_signing_key] [-g ticket_digest_alg] [-f ticket_signing_alg] [-s signature] [-x ticket] [--ticket ticket] [--timeout timeout_tag] [-t ticket_timeout]

DESCRIPTION

This command is used to create a ticket that authorizes an object to be used. It is typically used as a credential by a remote party to authenticate themselves to the TPM. A ticket is signed by a key that is authorized by a policy. The policy is typically created by tpm2_policysigned(1).

The ticket is created by the TPM when the policy session is being authorized. The ticket is then used by the remote party to authorize the TPM operation. The ticket can be created and signed by the TPM itself.

The policy ticket is a credential that is signed by a signing key. The signing key is itself bound to a policy. The policy can require certain conditions to be met, such as the signing key being used to sign a specific digest. This allows for fine-grained control over access to objects.

The ticket is signed by the signing key. The signing key is itself bound to a policy. The policy can require certain conditions to be met, such as the signing key being used to sign a specific digest. This allows for fine-grained control over access to objects.

TCTI Configuration

The TCTI is a configuration string that specifies how the tpm2 tools communicate with the TPM. The default TCTI is used when none is specified.

The default TCTI can be overridden by the environment variable TPM2_TCTI.

The following TCTI configurations are supported:

  * "device[:/dev/tpm0]"
  * "mssim[:host=][:port=]"
  * "tabrmd[:host=][:port=][:firmware_capability=]"
  * "libspack[:/path/to/pkcs11/library.so]"
  * "openssl[:host=][:port=]"
  * "tcp[:host=][:port=]"
  * "cmd[:cmd=[:watchdog=]]"
  * "ftdi[:/dev/bus/usb//]"
  * "tcti-cmd"
  * "tcti-device"
  * "tcti-ftdi"
  * "tcti-grulib"
  * "tcti-mock"
  * "tcti-openssl"
  * "tcti-sim"
  * "tcti-tabrmd"
  * "tcti-tcp"

EXAMPLES

Authorize a TPM operation on an object whose authorization is bound to specific signing authority.

Create the signing authority and load the verification key

openssl genrsa -out private.pem 2048
openssl rsa -in private.pem -outform PEM -pubout -out public.pem
tpm2_loadexternal -C o -G rsa -u public.pem -c signing_key.ctx \
-n signing_key.name

Generate signature with the expiry time

EXPIRYTIME="FFFFFE0C"
echo $EXPIRYTIME | xxd -r -p | \
openssl dgst -sha256 -sign private.pem -out signature.dat

Create the policy

tpm2_startauthsession -S session.ctx
tpm2_policysigned -S session.ctx -g sha256 -s signature.dat -f rsassa \
-c signing_key.ctx -L policy.signed
tpm2_flushcontext session.ctx

Create a sealing object

tpm2_createprimary -C o -c prim.ctx -Q
echo "plaintext" > secret.dat
tpm2_create -u sealing_key.pub -r sealing_key.priv -c sealing_key.ctx \
-C prim.ctx -i secret.dat -L policy.signed -Q

Create ticket-able policy

tpm2_startauthsession -S session.ctx --nonce-tpm=nonce.test --policy-session
{ cat nonce.test & echo $EXPIRYTIME | xxd -r -p; } | \
openssl dgst -sha256 -sign private.pem -out signature.dat
tpm2_policysigned -S session.ctx -g sha256 -s signature.dat -f rsassa \
-c signing_key.ctx -x nonce.test --ticket tic.ket --timeout time.out \
-t 0xFFFFFE0C
tpm2_flushcontext session.ctx

##Test with policyticket instead of policysigned

tpm2_startauthsession -S session.ctx --policy-session
tpm2_policyticket -S session.ctx -n signing_key.name --ticket tic.ket \
--timeout time.out
tpm2_unseal -p session:session.ctx -c sealing_key.ctx

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
