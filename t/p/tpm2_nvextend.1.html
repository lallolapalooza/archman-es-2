tpm2_nvextend(1) Manual de Comandos Generales tpm2_nvextend(1)

NOMBRE

tpm2_nvextend(1) - Extiende un índice No Volátil (NV) como si fuera un PCR.

SINOPSIS

tpm2_nvextend [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_nvextend(1) - Extiende un índice No Volátil (NV) como si fuera un PCR. El índice NV debe ser de tipo "extend", el cual se especifica a través del campo "nt" al crear el espacio NV con tpm2_nvdefine(1). El índice puede ser especificado como un handle bruto o un valor de desplazamiento del rango de handles NV "TPM2_HR_NV_INDEX" como argumento.

OPCIONES

•
-C, --hierarchy=OBJETO:

Especifica la jerarquía utilizada para autorizar. Las opciones soportadas son:

•
o para TPM_RH_OWNER
•
p para TPM_RH_PLATFORM
•
<num> donde se puede usar un handle de jerarquía o un índice NV.

Cuando -C no se pasa explícitamente, el handle del índice se utilizará para autorizar contra el índice. El valor de autorización del índice se establece a través de la opción -p de tpm2_nvdefine(1).

•
-P, --auth=AUTH:

Especifica el valor de autorización para la jerarquía.

•
-i, --input=ARCHIVO:

Especifica el archivo de entrada con los datos para extender al índice NV.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Comúnmente se denomina cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará el comando, simplemente devolverá un cpHash, a menos que también se requiera rphash.

•
--rphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros de respuesta. Comúnmente se denomina rpHash.

•
-S, --session=ARCHIVO:

La sesión creada con tpm2_startauthsession. Se pueden especificar múltiples de estas. Por ejemplo, puedes tener una sesión para auditoría y otra para cifrado/descifrado de parámetros.

•
-n, --name=ARCHIVO:

El nombre del índice NV que debe proporcionarse al calcular solo el cpHash sin despachar realmente el comando al TPM.

•
ARGUMENTO el argumento de línea de comandos especifica el índice NV o el número de desplazamiento.

Referencias

Formato Objeto Contexto

El tipo de un objeto de contexto, ya sea un handle o un nombre de archivo, se determina según la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio de TPM restaurado.
•
Si el argumento es una coincidencia de *prefijo* en uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento se puede cargar como un número, se tratará como un handle, por ejemplo, 0x81010013 y se usará directamente.*OBJETO*.

Formato Autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autorizaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación utilizando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña de cadena, especificada por el prefijo "str:" o su ausencia (cadena cruda sin prefijo) no se interpreta y se usa directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña de cadena hexadecimal, especificada por el prefijo "hex:", se convierte de formato hexadecimal a formato de array de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables para la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo "file:", debe ser la ruta de un archivo que contenga la contraseña a ser leída por la herramienta o un "-" para usar stdin. Almacenar contraseñas en archivos evita fugas de información, las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las características comunes del historial del shell.

Ejemplos

# para usar stdin y que se le pida
file:-
# para usar un archivo de una ruta
file:ruta/al/archivo/de/contraseña
# para enviar una contraseña vía stdin:
echo foobar | tpm2_tool -p file:-
# para usar un here-string de bash vía stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego, indique una ruta a un archivo de sesión que fue creado con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autorización para ser enviado con el handle de la sesión (p. ej., contraseña de política), agregue un + y una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones PCR

Puedes satisfacer una política PCR usando el prefijo "pcr:" y el minilenguaje PCR. El minilenguaje PCR es el siguiente: <especificación-pcr>=<archivo-pcr-crudo>

La especificación PCR se documenta en la sección "Especificadores de banco PCR".

El archivo-pcr-crudo es un argumento opcional que contiene la salida del contenido crudo del PCR tal como lo devuelve tpm2_pcrread(1).

NAME

tpm2_nvextend - Add data to a TPM NV Index.

SYNOPSIS

tpm2_nvextend [-C context] [-p policy] [-f policyfile] [-i inputfile] [-S size] [-r retries] [-T tcti] [-Q] [-u] [-h]

DESCRIPTION

The tpm2_nvextend command extends a TPM NV Index with data provided in -i or stdin. The NV Index is specified by the -C option. The NV Index must have been previously defined using tpm2_nvdefine and must have the NT_EXTEND policy flag set. This command will take the data from the input file, hash it and then XOR the existing data in the NV Index with the provided data, and then take the result and hash it, to store the final digest in the NV Index. This command is useful for extending PCRs with data.

OPTIONS

The command supports the following options:

-C context
The context object for the NV Index. The context object is a handle that points to the NV Index. The context object can be specified in one of three forms:
A numeric handle (e.g., 0x1000c) prefixed with 0x.
A policy digest (e.g., 4c4bc10091501e334912579625c237d8e4a192765c81499d041a85863b262a3b).
A context file path (e.g., ~/.tpm2/nv_index.context).
-p policy
The policy digest to use for authorization. This will be a hex encoded digest.
-f policyfile
Path to a file containing the policy digest to use for authorization.
-i inputfile
Path to the input file containing the data to extend the NV Index with. If this option is not provided, the data will be read from stdin.
-S size
The size of the data to be written. This is used to ensure that the size of the data read from the input file matches the size specified. If this option is not provided, the size of the data will be determined by the size of the input file.
-r retries
The number of retries to attempt when extending the NV Index. This is useful when the NV Index is locked or has other temporary issues. Default is 0.
-T tcti
The TCTI (Tabernacle Connection and Transport Interface) used to connect to the TPM. This option is specified in the format "name:options". See TCTI Configuration for more information.
-Q
Quiet mode. Suppresses normal output to stdout.
-u
Update policy. This option is used to update the policy digest associated with the NV Index. This is useful when the policy associated with the NV Index needs to be updated.
-h
Print a help message and exit.

Context Object Format

The context object format is used to specify the NV Index to be used. The context object can be specified in one of three forms:

0x1000c

4c4bc10091501e334912579625c237d8e4a192765c81499d041a85863b262a3b

~/.tpm2/nv_index.context

Authorization Formatting

The authorization format is used to specify the policy digest to be used for authorization. The authorization format can be specified in one of two forms:

4c4bc10091501e334912579625c237d8e4a192765c81499d041a85863b262a3b

/path/to/policy/digest.txt

specifying AUTH.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.
