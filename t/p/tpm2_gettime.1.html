tpm2_gettime(1) Manual de Comandos Generales tpm2_gettime(1)

NOMBRE

tpm2_gettime(1) - Obtiene la hora y el reloj actuales del TPM de forma firmada.

SINOPSIS

tpm2_gettime [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_gettime(1) - Proporciona una copia firmada de la hora y el reloj actuales del TPM. Devuelve tanto una firma como los datos en el formato de atestación estándar del TPM, una estructura TPMS_ATTEST.

Genera en la salida estándar, en formato YAML, la estructura TPMS_TIME_INFO del TPM. La estructura contiene la configuración actual de Tiempo, Reloj, contador de reinicios (resetCount) y contador de reinicio (restartCount). La estructura se presenta como YAML definida como:

tiempo: 13673142     # Valor de 64 bits del tiempo transcurrido desde la última _TPM_Init o TPM2_Startup
                   # en ms.
info_reloj:
  reloj: 13673142  # Valor de 64 bits del tiempo que el TPM ha estado encendido en ms.
  contador_reinicio: 0   # Valor de 32 bits del número de reinicios del TPM desde la última
                   # TPM2_Clear.
  contador_reinicio_arranque: 0 # Valor de 32 bits del número de veces que TPM2_Shutdown o
                   # _TPM_Hash_Start han ocurrido desde el último reinicio del TPM o
                   # TPM2_Clear.
  seguro: sí        # Valor booleano sí|no que indica si el TPM ha reportado previamente algún valor de Reloj mayor
                   # que el valor actual de Reloj.

OPCIONES

•
-c, --contexto-clave=OBJETO:

Objeto de contexto que apunta a la clave utilizada para firmar. Puede ser un archivo o un número de identificador. Consulte la sección "Formato del Objeto de Contexto".

•
-p, --auth_AUTENTICACIÓN_:

Valor de autenticación opcional para usar la clave especificada por -c. Los valores de autenticación deben seguir los "estándares de formato de autenticación", consulte la sección "Formato de Autenticación".

•
-P, --auth-endorse_AUTENTICACIÓN_:

Valor de autenticación opcional para la jerarquía de respaldo (endorsement). Los valores de autenticación deben seguir los "estándares de formato de autenticación", consulte la sección "Formato de Autenticación".

•
-g, --algoritmo-hash=ALGORITMO:

El algoritmo de hash utilizado para digerir el mensaje. Los algoritmos deben seguir los "estándares de formato", consulte la sección "Especificadores de Algoritmo". Consulte también la sección "Algoritmos de Hash Soportados" para obtener una lista de algoritmos de hash soportados.

•
-s, --esquema=ALGORITMO:

El esquema de firma utilizado para firmar el mensaje. Opcional. Los esquemas de firma deben seguir los "estándares de formato", consulte la sección "Especificadores de Algoritmo". Consulte también la sección "Esquemas de Firma Soportados" para obtener una lista de esquemas de firma soportados. Si se especifica, el esquema de firma debe coincidir con el tipo de clave. Si se deja sin especificar, se utilizará un esquema de firma predeterminado para el tipo de clave.

•
-q, --calificacion=ARCHIVO_O_CADENA_HEX:

Opcional, los datos de calificación de política que el firmante puede optar por incluir en la firma. Puede ser una cadena hexadecimal o una ruta.

•
-o, --firma=ARCHIVO:

El archivo de firma, registra la estructura de la firma.

•
-f, --formato=FORMATO:

Selección de formato para el archivo de salida de la firma. Consulte la sección "Especificadores de Formato de Firma".

•
--atestacion=ARCHIVO:

Los datos de atestación del tipo TPMS_ATTEST firmados con la clave de firma.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se conoce comúnmente como cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash.

•
ARGUMENTO el argumento de la línea de comandos especifica los datos del archivo a firmar.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un identificador (handle) o un nombre de archivo, se determina según la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio del TPM restaurado.
•
Si el argumento coincide con un *prefijo* de uno de:
•
owner: la jerarquía del propietario (owner)
•
platform: la jerarquía de la plataforma (platform)
•
endorsement: la jerarquía de respaldo (endorsement)
•
lockout: el objeto persistente de control de bloqueo (lockout)
•
Si el argumento puede cargarse como un número, se tratará como un identificador (handle), por ejemplo, 0x81010013, y se usará directamente.

Formato de Autenticación

La autenticación para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autenticaciones tienen por defecto la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas utilizando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña en formato de cadena, especificada con el prefijo "str:" o su ausencia (cadena sin prefijo), no se interpreta y se utiliza directamente para la autenticación.

Ejemplos

foobar
str:foobar

Cadena-hexadecimal

Una contraseña en formato de cadena hexadecimal, especificada con el prefijo "hex:", se convierte de formato hexadecimal a formato de matriz de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no compatibles con la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada con el prefijo "file:", debe ser la ruta de un archivo que contenga la contraseña que será leída por la herramienta, o un "-" para usar la entrada estándar. Almacenar contraseñas en archivos evita la fuga de información; las contraseñas pasadas como opciones pueden ser leídas desde la lista de procesos o las características comunes del historial del shell.

Ejemplos

# para usar la entrada estándar y ser solicitado
file:-
# para usar un archivo desde una ruta
file:ruta/al/archivo/de/contraseña
# para enviar una contraseña vía entrada estándar:
echo foobar | tpm2_tool -p file:-
# para usar una cadena aquí de bash vía entrada estándar:
tpm2_tool -p file:- <<< foobar

Luego, indique una ruta a un archivo de sesión que fue creado con tpm2_startauthsession(1). Contextos de Sesión

Los contextos de sesión son utilizados por las herramientas de TPM2 para persistir información de autenticación entre invocaciones. Son generados por los comandos tpm2_startauthsession(1) y tpm2_policysession(1).

Si se invoca un comando que requiere autenticación de sesión, puede especificar el archivo de contexto de sesión usando el prefijo session:.

En el caso de que un comando lo requiera, también puede añadir un + y una cadena de texto como se describe en la sección de Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones PCR

Puede satisfacer una política de PCR usando el prefijo “pcr:” y el minilenguaje de PCR. El minilenguaje de PCR es el siguiente: <pcr-spec>=<raw-pcr-file>

La especificación de PCR se documenta en la sección “Especificadores de bancos de PCR”.

El raw-pcr-file es un argumento opcional que contiene la salida de los contenidos crudos de PCR tal como son devueltos por tpm2_pcrread(1).

Especificadores de bancos de PCR

Ejemplos

Para satisfacer una política de PCR de sha256 en los bancos 0, 1, 2 y 3 use un especificador de:

pcr:sha256:0,1,2,3

especificando AUTH.

Especificadores Complejos

Los objetos, cuando se especifican para su creación por el TPM, tienen numerosos algoritmos para poblar en los datos públicos. Cosas como tipo, esquema y detalles asimétricos, tamaño de clave, etc. A continuación se muestra el formato general para especificar estos datos: <type>:<scheme>:<symmetric-details>

Especificadores de Tipo

Esta parte del especificador de algoritmo complejo es obligatoria. El esquema y los detalles simétricos restantes se establecerán por defecto según el tipo especificado y el tipo del objeto que se está creando.

•
aes - AES por defecto: aes128
•
aes128<mode> - AES de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, por defecto es null.
•
aes192<mode> - Igual que aes128<mode>, excepto para un tamaño de clave de 192 bits.
•
aes256<mode> - Igual que aes128<mode>, excepto para un tamaño de clave de 256 bits.
•
sm4 - SM4 por defecto: sm4128
•
sm4128 o sm4_128 <mode> - SM4 de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, por defecto es null.
•
ecc - Curva Elíptica, por defecto es ecc256.
•
ecc192 o ecc_nist_p192 - Curva NIST ECC de 192 bits
•
ecc224 o ecc_nist_p224 - Curva NIST ECC de 224 bits
•
ecc256 o ecc_nist_p256 - Curva NIST ECC de 256 bits
•
ecc384 o ecc_nist_p384 - Curva NIST ECC de 384 bits
•
ecc521 o ecc_nist_p521 - Curva NIST ECC de 521 bits
•
ecc_sm2 o ecc_sm2_p256 - Curva SM2 de 256 bits
•
rsa - RSA por defecto: rsa2048
•
rsa1024 - RSA con tamaño de clave de 1024 bits.
•
rsa2048 - RSA con tamaño de clave de 2048 bits.
•
rsa3072 - RSA con tamaño de clave de 3072 bits.
•
rsa4096 - RSA con tamaño de clave de 4096 bits.

Especificadores de Esquema

A continuación, hay un campo opcional, puede omitirse.

Los esquemas son generalmente Esquemas de Firma o Esquemas de Cifrado Asimétrico. La mayoría de los esquemas de firma toman un algoritmo de hash directamente después del esquema de firma. Si el algoritmo de hash falta, por defecto es sha256. Algunos no toman argumentos y algunos toman múltiples argumentos.

Este especificador de esquema va seguido de un número (tamaño máximo UINT16) y luego seguido de un guion (-) y un algoritmo de hash válido. * ecdaa Por ejemplo, ecdaa4-sha256. Si no se especifica ningún número, por defecto es 4.

Especificadores de Esquema sin Opciones

Este especificador de esquema NO toma argumentos. * rsaes

Especificadores de Detalles Simétricos

Este campo es opcional y se establece por defecto según el tipo de objeto que se está creando y sus atributos. En general, cualquier especificador Symmetric válido de la lista de Especificadores de Tipo debería funcionar. Si no se especifica, los detalles simétricos de los objetos asimétricos son por defecto aes128cfb.

Ejemplos

Crear una clave rsa2048 con un esquema de cifrado asimétrico rsaes

Crear una clave ecc256 con un esquema de firma ecdaa con un recuento de 4 y hash sha384

/tpm2_create -C parent.ctx -G ecc256:ecdaa4-sha384 -u key.pub -r key.priv algoritmos criptográficos ALGORITHM.

Configuración TCTI

La TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Las TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar la TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Las TCTI conocidas actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente se utiliza para comunicarse con el simulador de software del TPM.
•
device - Se utiliza al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializa una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, admiten no usar una TCTI. Las herramientas que no lo admiten generarán un error al intentar usarlas sin una conexión TCTI. No admite *NINGUNA* opción y *DEBE* presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<tcti-name>:<tcti-option-config>

Especificar una cadena vacía para el <tcti-name> o el <tcti-option-config> resulta en que se use el valor predeterminado para esa parte respectivamente.

Valores predeterminados de TCTI

Cuando no se especifica una TCTI, se busca la TCTI predeterminada utilizando la semántica de dlopen(3). Las herramientas buscarán las TCTI tabrmd, device y mssim EN ESE ORDEN y USARÁN LA PRIMERA QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminada utilizando la opción -v para mostrar la información de la versión. El par clave-valor "default-tcti" indicará cuál de las TCTI mencionadas anteriormente es la predeterminada.

TCTIs personalizadas

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor bruto de tcti-name se utiliza para la búsqueda. Por lo tanto, esta podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entendido por la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para la TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres del TPM a utilizar por la TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para la TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para la TCTI abrmd, el formato de la cadena de configuración es una serie de pares clave-valor simples separados por un carácter `,'. Cada cadena de clave y valor están separadas por un carácter `= `.
•
La TCTI abrmd admite dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia dbus (una cadena) limitada a `session' y `system'.

Especifique el nombre de la TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifique la TCTI predeterminada (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos. # Especificadores de formato

Selección de formato para el archivo de salida de la firma. tss (el predeterminado) generará un blob binario según la especificación TPM 2.0 y cualquier relleno potencial del compilador. La opción plain generará los datos de firma sin formato según el algoritmo criptográfico utilizado.

Crear una clave y obtener el tiempo del TPM certificado
