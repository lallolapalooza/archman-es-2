tpm2_policycommandcode(1) Manual de Comandos Generales tpm2_policycommandcode(1)

NOMBRE

tpm2_policycommandcode(1) - Restringe la autorización de objetos TPM a comandos específicos de TPM.

SINOPSIS

tpm2_policycommandcode [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_policycommandcode(1) - Restringe la autorización de objetos TPM a comandos específicos de TPM. Útil cuando solo se desea permitir que comandos específicos interactúen con el objeto TPM.

Como argumento, toma el comando como un valor entero o una cadena de texto amigable. El mapeo de cadenas de texto amigables a CÓDIGOS DE COMANDO se puede encontrar en la sección MAPEO DE CÓDIGOS DE COMANDO.

OPCIONES

•
-S, --session=ARCHIVO:

Un archivo de sesión de la opción -S de tpm2_startauthsession(1).

•
-L, --policy=ARCHIVO:

Archivo donde guardar el resumen de la política.

•
ARGUMENTO el argumento de la línea de comandos especifica el código de comando TPM2.
•
--cphash=ARCHIVO

Ruta del archivo donde registrar el hash de los parámetros del comando. Esto se conoce comúnmente como cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash.

Configuración TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTIs se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTIs conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software TPM.
•
device - Utilizado al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, soportan no usar un TCTI. Las herramientas que no lo soportan darán error cuando se intenten usar sin una conexión TCTI. No soporta NINGUNA opción y DEBE presentarse como el texto exacto de 'none'.

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o <config-opciones-tcti> resulta en el uso del valor predeterminado para esa porción respectivamente.

Valores Predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTIs tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado usando la opción -v para mostrar la información de la versión. El par clave-valor 'default-tcti' indicará cuál de los TCTIs mencionados anteriormente es el predeterminado.

TCTIs Personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica puede ser cargado. Las herramientas internamente usan dlopen(3), y el valor crudo 'tcti-name' se usa para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entendido por la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo de dispositivo carácter TPM a utilizar por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter ','. Cada clave y valor se separan por un carácter '='.
•
El TCTI abrmd soporta dos claves:
1.
'bus_name': el nombre del servicio tabrmd en el bus (una cadena).
2.
'bus_type': el tipo de la instancia de dbus (una cadena) limitada a 'session' y 'system'.

Especificar el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especificar el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. Los diversos módulos TCTI conocidos.

NAME


tpm2_policycommandcode — Set a policy PCR that is met when the given command code is used for the next command.






SYNOPSIS


tpm2_policycommandcode [generic options] [-S session] [-L policy] commandcode






DESCRIPTION


The tpm2_policycommandcode command is used to set a policy that is met when the next command executed will have the given command code.


This command is used in conjunction with tpm2_startauthsession to establish a policy session. The policy session is then extended with the policy defined by tpm2_policycommandcode.


The policy is met when the next command executed within the same policy session has the specified command code.


The command code can be specified either as a hexadecimal value (e.g. 0x100) or as a symbolic name (e.g. TPM2_CC_PolicyAuthValue).






OPTIONS


The tpm2_policycommandcode command accepts the following options:



  
[-S session]

  
The path to the policy session file created by tpm2_startauthsession.

  
[-L policy]

  
The path to the policy file where the policy digest will be written.

  
commandcode

  
The command code for which the policy will be set. This can be a hexadecimal value (e.g. 0x100) or a symbolic name (e.g. TPM2_CC_PolicyAuthValue).








COMMON OPTIONS


These options are common to many of the TPM tools.



  
[-h]

  
Help information.

  
[-V level]

  
Verbosity level.

  
[-Q]

  
Quiet processing.

  
[-t tcti]

  
The TPM Technology Component Interface (TCTI) to use.








TCTI Configuration


This tool supports the following TCTI configurations:



  
[--tcti-device]

  
TCTI Device options.

  
[--tcti-mssim]

  
TCTI Mssim options.

  
[--tcti-cmd]

  
TCTI Cmd options.

  
[--tcti-tabrmd]

  
TCTI Tabrmd options.








TCTI OPTIONS


The following options are specific to the TCTI configuration:



  
[-connect host:port]

  
Connect to a TPM simulator at host:port.

  
[-d device path]

  
Open TPM device at device path.

  
[-i interface]

  
Select the TCTI interface to use. Defaults to the first one found.

EXAMPLES


Start a policy session and extend it with a specific
    command like unseal. Attempts to perform other operations would fail.




Create   an unseal-only policy



  

  

    
tpm2_startauthsession -S session.dat
tpm2_policycommandcode -S session.dat -L policy.dat TPM2_CC_Unseal
tpm2_flushcontext session.dat


  








Create   the object with unseal-only auth policy



  

  

    
tpm2_createprimary -C o -c prim.ctx
tpm2_create -C prim.ctx -u sealkey.pub -r sealkey.priv -L policy.dat \
  -i- <<< "SEALED-SECRET"


  








Try   unseal operation



  

  

    
tpm2_load -C prim.ctx -u sealkey.pub -r sealkey.priv -n sealkey.name \
  -c sealkey.ctx
tpm2_startauthsession --policy-session -S session.dat
tpm2_policycommandcode -S session.dat -L policy.dat TPM2_CC_Unseal
tpm2_unseal -p session:session.dat -c sealkey.ctx
SEALED-SECRET
tpm2_flushcontext session.dat


  








Try   any other operation



  

  

    
echo "Encrypt Me" > plain.txt
tpm2_encryptdecrypt plain.txt -o enc.txt -c sealkey.ctx plain.txt
ERROR: Esys_EncryptDecrypt2(0x12F) - tpm:error(2.0): authValue or authPolicy is
not available for selected entity


  










Returns


Tools can return any of the following codes:



  
•

  
0 - Success.

  
•

  
1 - General non-specific error.

  
•

  
2 - Options handling error.

  
•

  
3 - Authentication error.

  
•

  
4 - TCTI related error.

  
•

  
5 - Non supported scheme. Applicable to tpm2_testparams.








Limitations


It expects a session to be already established via
    tpm2_startauthsession(1) and requires one of the following:



  
•

  
direct device access

  
•

  
extended session support with tpm2-abrmd.




Without it, most resource managers will not save session
    state between command invocations.
