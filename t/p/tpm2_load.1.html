tpm2_load(1) Manual de Comandos Generales tpm2_load(1)

NOMBRE

tpm2_load(1) - Cargar un objeto en el TPM.

SINOPSIS

tpm2_load [OPCIONES]

DESCRIPCIÓN

tpm2_load(1) - Carga tanto las partes privada como pública de un objeto en el TPM o carga el objeto en formato PEM de Clave-Privada-TSS2. Esto se puede hacer especificando la sección privada así como la pública o a través de un archivo pem usando la opción -r.

La herramienta muestra el nombre del objeto cargado en un diccionario YAML con la clave name, donde el valor para esa clave es el nombre del objeto en formato hexadecimal, por ejemplo:

name: 000bac25cb8743111c8e1f52f2ee7279d05d3902a18dd1af694db5d1afa7adf1c8b3

También guarda un archivo de contexto para futuras interacciones con el objeto.

NOTA: Deben especificarse tanto la parte privada como la pública de la clave TPM. La excepción a esto es si se va a cargar un objeto PEM con formato Clave-Privada-TSS2, que no necesita la parte pública especificada.

OPCIONES

•
-C, --parent-context=OBJETO:

El objeto padre.

•
-P, --auth=AUTENTICACIÓN:

El valor de autenticación del objeto padre especificado por -C.

•
-u, --public=ARCHIVO:

Un archivo que contiene la parte pública del objeto.

•
-r, --private=ARCHIVO:

Un archivo que contiene la parte sensible del objeto.

•
-n, --name=ARCHIVO:

Un archivo opcional para guardar la estructura del nombre del objeto.

•
-c, --key-context=ARCHIVO:

El nombre del archivo del contexto del objeto guardado, requerido.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará el comando, simplemente devolverá un cpHash.

Referencias

Formato Objeto Contexto

El tipo de un objeto de contexto, ya sea un identificador o un nombre de archivo, se determina de acuerdo con la siguiente lógica, *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio del TPM restaurado.
•
Si el argumento es una coincidencia de *prefijo* en uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de aprobación
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento se puede cargar como un número, se tratará como un identificador, por ejemplo, 0x81010013 y se usará directamente. _OBJETO_.

Formato Autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: 'Las autorizaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican'.

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación usando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña en formato de cadena, especificada con el prefijo "str:" o su ausencia (cadena sin prefijo) no se interpreta y se usa directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena-hexadecimal

Una contraseña en formato de cadena hexadecimal, especificada con el prefijo "hex:", se convierte de forma hexadecimal a un array de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no aptos para terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada con el prefijo "file:", debe ser la ruta de un archivo que contenga la contraseña que será leída por la herramienta o un "-" para usar la entrada estándar (stdin). Almacenar contraseñas en archivos evita la fuga de información, las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las funciones comunes del historial del shell.

Ejemplos

# para usar la entrada estándar y que se solicite
file:-
# para usar un archivo desde una ruta
file:ruta/a/archivo/contraseña
# para enviar una contraseña via stdin:
echo foobar | tpm2_tool -p file:-
# para usar un "here-string" de bash via stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego, indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación que se envíe con el identificador de sesión (por ejemplo, contraseña de política), agregue un "+" y una cadena como se describe en la sección de Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones PCR

Puede satisfacer una política de PCR usando el prefijo "pcr:" y el minilenguaje PCR. El minilenguaje PCR es el siguiente: <especificación-pcr>=<archivo-pcr-crudo>

La especificación-pcr se documenta en la sección "Especificadores de banco PCR".

El archivo-pcr-crudo es un argumento **opcional** que contiene la salida de los contenidos crudos del PCR tal como los devuelve tpm2_pcrread(1).

Especificadores de banco PCR

Ejemplos

Para satisfacer una política de PCR de sha256 en los bancos 0, 1, 2 y 3 use un especificador de:

pcr:sha256:0,1,2,3

especificando AUTENTICACIÓN.

Configuración del TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre tiene prioridad sobre la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Se utiliza al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializa una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo soportan generarán un error al intentar usarse sin una conexión TCTI. No admite NINGUNA opción y DEBE presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<tcti-name>:<tcti-option-config>

Especificar una cadena vacía para <tcti-name> o <tcti-option-config> resulta en que se use el valor predeterminado para esa parte respectivamente.

Valores Predeterminados del TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para imprimir la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas internamente utilizan dlopen(3), y el valor bruto de tcti-name se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entienda la semántica de dlopen(3).

OPCIONES DEL TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres del TPM para ser utilizado por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter ','. Cada clave y valor se separan por un carácter '='.
•
El TCTI abrmd admite dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia de dbus (una cadena) limitado a 'session' y 'system'.

Especifique el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifique el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

Configuración

Para cargar un objeto, primero debe crear un objeto bajo un objeto principal. Por lo tanto, el primer paso es crear el objeto principal.

tpm2_createprimary -c primary.ctx

El paso 2 es crear un objeto bajo el objeto principal.

tpm2_create -C primary.ctx -u key.pub -r key.priv

Esto crea las porciones privada y pública del objeto TPM. Con estas porciones de objeto, ahora es posible cargar ese objeto en el TPM para su uso posterior.

Cargar un Objeto en el TPM

El paso final es cargar las porciones pública y privada del objeto en el TPM.

tpm2_load  -C primary.ctx -u key.pub -r key.priv -c key.ctx
name: 000bac25cb8743111c8e1f52f2ee7279d05d3902a18dd1af694db5d1afa7adf1c8b3

Devoluciones

Las herramientas pueden devolver cualquiera de los siguientes códigos:

•
0 - Éxito.
•
1 - Error general no específico.
•
2 - Error en el manejo de opciones.
•
3 - Error de autenticación.
•
4 - Error relacionado con TCTI.
•
5 - Esquema no soportado. Aplicable a tpm2_testparams.
