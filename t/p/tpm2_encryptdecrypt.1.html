NOMBRE

tpm2_encryptdecrypt(1) - Realiza el cifrado o descifrado simétrico.

SINOPSIS

tpm2_encryptdecrypt [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_encryptdecrypt(1) - Realiza el cifrado o descifrado simétrico con una clave simétrica especificada sobre el contenido de ARCHIVO. Si no se especifica ARCHIVO, se utiliza la entrada estándar por defecto.

OPCIONES

•
-c, --key-context=OBJETO:

El objeto de clave de cifrado.

•
-p, --auth=AUTENTICACION:

El valor de autenticación para el objeto de clave de cifrado.

•
-d, --decrypt:

Realiza una operación de descifrado. Por defecto es cifrado cuando esta opción no se especifica.

•
-e, --pad:

Habilita el relleno pkcs7 para los modos de cifrado AES aplicables cfb/cbc/ecb. Solo aplicable al cifrado y a los datos de entrada con el último bloque más corto que la longitud del bloque de cifrado.

•
-o, --output=ARCHIVO o STDOUT:

La ruta del archivo de salida para los datos cifrados o descifrados. Si no se especifica, se utiliza stdout por defecto.

•
-G, --mode=ALGORITMO:

El algoritmo de clave asociado a este objeto. Por defecto son las propiedades del objeto o CFB si no está definido.

•
-t, --iv=ARCHIVO:

Vector de inicialización opcional a usar. Por defecto son 0's. La sintaxis permite especificar una fuente de archivo de entrada y una fuente de archivo de salida. La ruta del archivo de entrada es la primera, seguida opcionalmente por dos puntos “:” y la ruta del IV de salida. Este IV de salida puede guardarse para llamadas posteriores al encadenar.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash.

•
ARGUMENTO el argumento de la línea de comandos especifica la ruta del archivo de entrada ARCHIVO de los datos a cifrar o descifrar.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un manejador o un nombre de archivo, se determina de acuerdo con la siguiente lógica en orden:

•
Si el argumento es una ruta de archivo, se carga el archivo como un objeto transitorio de TPM restaurado.
•
Si el argumento es una coincidencia de prefijo con uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento se puede cargar como un número, se tratará como un manejador, por ejemplo, 0x81010013 y se utilizará directamente._OBJETO_.

Formato de Autenticación

La autenticación para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: “Las autenticaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican”.

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación utilizando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña de cadena, especificada por el prefijo “str:” o su ausencia (cadena sin prefijo) no se interpreta y se utiliza directamente para la autenticación.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña en cadena hexadecimal, especificada por el prefijo “hex:”, se convierte de un formato hexadecimal a un formato de arreglo de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables para la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo “file:”, debe ser la ruta de un archivo que contenga la contraseña que será leída por la herramienta o un “-” para usar la entrada estándar. Almacenar contraseñas en archivos previene fugas de información, las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las funciones comunes del historial del shell.

Ejemplos

# para usar entrada estándar y que se solicite
file:-
# para usar un archivo desde una ruta
file:ruta/al/archivo/contraseña
# para hacer eco de una contraseña a través de la entrada estándar:
echo foobar | tpm2_tool -p file:-
# para usar un "here-string" de bash a través de la entrada estándar:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autenticar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego, indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación para ser enviado con el manejador de sesión (por ejemplo, contraseña de política), agregue un + y una cadena como se describe en la sección Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones PCR

Puede satisfacer una política de PCR usando el prefijo “pcr:” y el minilenguaje PCR. El minilenguaje PCR es el siguiente: <especificador-pcr>=<archivo-pcr-crudo>

El especificador de PCR se documenta en la sección “Especificadores de banco de PCR”.

El archivo-pcr-crudo es un argumento opcional que contiene la salida del contenido crudo de PCR devuelto por tpm2_pcrread(1).

Especificadores de banco de PCR

Ejemplos

Para satisfacer una política de PCR de sha256 en los bancos 0, 1, 2 y 3 use un especificador de:

pcr:sha256:0,1,2,3

especificando AUTENTICACIÓN.

Especificadores complejos

Los objetos, cuando se especifican para su creación por el TPM, tienen numerosos algoritmos para poblar los datos públicos. Cosas como el tipo, el esquema y los detalles asimétricos, el tamaño de la clave, etc. A continuación, se muestra el formato general para especificar estos datos: <tipo>:<esquema>:<detalles-simétricos>

Especificadores de Tipo

Esta porción del especificador de algoritmo complejo es obligatoria. El esquema y los detalles simétricos restantes se establecerán por defecto según el tipo especificado y el tipo del objeto que se está creando.

•
aes - AES por defecto: aes128
•
aes128<modo> - AES de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, el valor por defecto es null.
•
aes192<modo> - Igual que aes128<modo>, excepto por un tamaño de clave de 192 bits.
•
aes256<modo> - Igual que aes128<modo>, excepto por un tamaño de clave de 256 bits.
•
sm4 - SM4 por defecto: sm4128
•
sm4128 o sm4_128 <modo> - SM4 de 128 bits con modo opcional (ctr|ofb|cbc|cfb|ecb). Si no se especifica el modo, el valor por defecto es null.
•
ecc - Curva Elíptica, por defecto es ecc256.
•
ecc192 o ecc_nist_p192 - Curva NIST ECC de 192 bits
•
ecc224 o ecc_nist_p224 - Curva NIST ECC de 224 bits
•
ecc256 o ecc_nist_p256 - Curva NIST ECC de 256 bits
•
ecc384 o ecc_nist_p384 - Curva NIST ECC de 384 bits
•
ecc521 o ecc_nist_p521 - Curva NIST ECC de 521 bits
•
ecc_sm2 o ecc_sm2_p256 - Curva SM2 de 256 bits
•
rsa - RSA por defecto: rsa2048
•
rsa1024 - RSA con tamaño de clave de 1024 bits.
•
rsa2048 - RSA con tamaño de clave de 2048 bits.
•
rsa3072 - RSA con tamaño de clave de 3072 bits.
•
rsa4096 - RSA con tamaño de clave de 4096 bits.

Especificadores de Esquema

A continuación, hay un campo opcional, se puede omitir.

Los esquemas suelen ser **Esquemas de Firma** o **Esquemas de Cifrado Asimétrico**. La mayoría de los esquemas de firma toman un algoritmo hash directamente después del esquema de firma. Si falta el algoritmo hash, se establece por defecto en sha256. Algunos no toman argumentos y otros toman múltiples argumentos.

Este especificador de esquema va seguido de un recuento (tamaño máximo UINT16) luego seguido de un guión (-) y un algoritmo hash válido. * ecdaa Por ejemplo, ecdaa4-sha256. Si no se especifica el recuento, el valor por defecto es 4.

Especificadores de Esquema sin Opciones

Este especificador de esquema NO toma argumentos. * rsaes

Especificadores de Detalles Simétricos

Este campo es opcional y se establece por defecto según el *tipo* de objeto que se está creando y sus atributos. En general, cualquier especificador **Simétrico** válido de la lista de **Especificadores de Tipo** debería funcionar. Si no se especifica, los detalles simétricos de un objeto asimétrico se establecen por defecto en aes128cfb.

Ejemplos

Crear una clave ecc256 con un esquema de firma ecdaa con un recuento de 4 y hash sha384

/tpm2_create -C parent.ctx -G ecc256:ecdaa4-sha384 -u key.pub -r key.priv algoritmos criptográficos ALGORITMO.

Configuración del TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

TCTI Configuration

The Trusted Computing Base (TCB) Interface Transport (TCTI) specifies how to connect to the TPM. The TCTI can be specified either via the -T command line option or the $TPM2TOOLS_TCTI environment variable. The TCTI value is a string that is colon-separated list of key-value pairs. If there is only one TCTI specified, it may not be a colon-separated list.

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software TPM.
•
device - Se utiliza al hablar directamente con un archivo de dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo admiten fallarán al intentar usarlas sin una conexión TCTI. No admite *NINGUNA* opción y *DEBE* presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <config-opciones-tcti> da como resultado el uso del valor predeterminado para esa parte, respectivamente.

Valores predeterminados de TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando las semánticas de dlopen(3). Las herramientas buscarán los TCTI de tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO ENCONTRADO. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para imprimir la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados anteriormente es el predeterminado.

TCTIs personalizados

Se puede cargar cualquier TCTI que implemente la interfaz dinámica de TCTI. Las herramientas utilizan internamente dlopen(3), y el valor crudo de tcti-name se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida o un nombre de biblioteca según lo entienden las semánticas de dlopen(3).

OPCIONES DE TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres TPM para que lo use el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares clave-valor simples separados por un carácter ','. Cada clave y valor de cadena están separados por un carácter '='.
•
El TCTI abrmd admite dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de instancia dbus (una cadena) limitado a `session' y `system'.

Especifique el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifique el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EJEMPLOS

Crear una clave AES

tpm2_createprimary -c primary.ctx
tpm2_create -C primary.ctx -Gaes128 -u key.pub -r key.priv
tpm2_load -C primary.ctx -u key.pub -r key.priv -c key.ctx

Cifrar y descifrar algunos datos

echo "my secret" > secret.dat
tpm2_encryptdecrypt -c key.ctx -o secret.enc secret.dat
tpm2_encryptdecrypt -d -c key.ctx -o secret.dec secret.enc
cat secret.dec
my secret

•

•
4 - Error relacionado con TCTI.

5 - Esquema no soportado. Aplicable a tpm2_testparams.
