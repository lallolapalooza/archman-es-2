tpm2_flushcontext(1) Manual de Comandos Generales tpm2_flushcontext(1)

NOMBRE

tpm2_flushcontext(1) - Elimina un identificador especificado, o todos los contextos asociados con un objeto transitorio, una sesión cargada o una sesión guardada del TPM.

SINOPSIS

tpm2_flushcontext [OPCIONES] [ARGUMENTO]

DESCRIPCIÓN

tpm2_flushcontext(1) - Elimina un identificador especificado, o todos los contextos asociados con un objeto transitorio, una sesión cargada o una sesión guardada del TPM. El objeto a eliminar se especifica como el primer argumento de la herramienta y tiene una de las siguientes formas:

• El identificador del objeto a eliminar del TPM. Debe ser un número de identificador válido.

• Elimina una sesión a través de un archivo de sesión. Un archivo de sesión se genera a partir de la opción -S de tpm2_startauthsession(1).

OPCIONES

•
-t, --transient-object:

Elimina todos los objetos transitorios.

•
-l, --loaded-session:

Elimina todas las sesiones cargadas.

•
-s, --saved-session:

Elimina todas las sesiones guardadas.

•
ARGUMENTO el argumento de línea de comandos especifica el *OBJETO* a eliminar de la memoria residente del TPM.
•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecuta el comando, simplemente devuelve un cpHash.

OPCIONES COMUNES

Esta colección de opciones son comunes a muchos programas y proporcionan información que muchos usuarios pueden esperar.

Configuración de TCTI

El TCTI, o "Interfaz de Transmisión", es el mecanismo de comunicación con el TPM. Los TCTIs se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre tiene prioridad sobre la variable de entorno.

Los TCTIs conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Nota de que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Utilizado al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializa una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y, por lo tanto, soportan no usar un TCTI. Las herramientas que no lo soportan generarán un error al intentar usarlas sin una conexión TCTI. No soporta *NINGUNA* opción y *DEBE* presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<configuración-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <configuración-opciones-tcti> resulta en el uso del valor predeterminado para esa porción respectivamente.

Valores predeterminados de TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán *tabrmd*, *device* y *mssim* TCTIs **EN ESE ORDEN** y **USARÁN EL PRIMERO QUE ENCUENTREN**. Puede consultar qué TCTI se elegirá como predeterminado usando la opción -v para mostrar la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTIs mencionados anteriormente es el predeterminado.

TCTIs personalizados

Cualquier TCTI que implemente la interfaz TCTI dinámica puede ser cargado. Las herramientas utilizan internamente dlopen(3), y el valor crudo *tcti-name* se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entendido por la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utilizan para configurar los varios módulos TCTI conocidos disponibles:

•
device: Para el TCTI device, se puede especificar el archivo de dispositivo de caracteres TPM para su uso por el TCTI device. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se pueden especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter ','. Cada clave y valor se separan por un carácter '='.
•
El TCTI abrmd soporta dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia de dbus (una cadena) limitada a `session' y `system'.

Especificar el nombre del TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especificar el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos

NAME

tpm2_flushcontext

flush TPM context.

SYNOPSIS

tpm2_flushcontext [OPTIONS] [CONTEXT... ]

DESCRIPTION

The tpm2_flushcontext command is used to flush TPM context. This can include transient objects, sessions, and other TPM objects.

When a process exits, any transient objects it created are automatically flushed. This command is typically only needed when you are managing TPM state directly or if you are concerned about actively freeing up TPM resources before the process exits.

In normal usage with a resource manager like tpm2-abrmd(8), transient objects are flushed when the process that created them exits. This command should not be necessary.

The command can flush:

•
Transient objects (handles starting with 0x80000000)
•
Sessions (handle starting with 0x40000000)
•
Persistent context (handles starting with 0x80000000)

OPTIONS

The options are broken down into several groups:

  • Common Options
  • TCTI Configuration
  • TCTI Options

The command accepts a list of context handles to flush. If no contexts are specified, it defaults to flushing all transient objects.

COMMON OPTIONS

These are options that are common to many tpm2-* tools.

-h

Print the help message and exit.

--help

Print the help message and exit.

-v

Enable verbosity, to print additional debug messages.

--version

Print version string and exit.

TCTI Configuration

These options control the TCTI (Tabernacle Context Transport Interface) that the tool uses to communicate with the TPM.

TCTI OPTIONS

These options are used to specify the TCTI device and configuration.

-T <TCTI>

Specify the TCTI device to use. This can be a device path, or a TCTI name like:

  • mssim: Use the simulator provided by tpm2-abrmd.
  • device: Use the character device `/dev/tpm0`.
  • ftdi: Use an FTDI device.
  • libsp: Use the SP TCTI.
  • cmd: Use the cmd TCTI.

Refer to `tpm2_tcti-list(7)` for more options.

--tcti-conf <TCTI_CONF>

Specify TCTI configuration string. This is useful for TCTIs that require additional parameters, such as specifying a particular FTDI device or a different character device for the 'device' TCTI.

For example:

tpm2_flushcontext -T device --tcti-conf "device=/dev/tpmrm0"

In addition to the explicit context handle(s) passed on the command line, the following options can be used to specify what type of context to flush:

--context

Flush the specified context handle. This option can be specified multiple times.

--all

Flush all context types (transient, persistent, etc.). This is a potentially destructive operation, use with caution.

--transient-object

Flush all transient objects. This is the default behavior if no context handles or other flush options are specified.

--session

Flush all active sessions.

--persistent-context

Flush all persistent contexts.

By default, if no context handles or options are provided, tpm2_flushcontext will flush all transient objects. This is the most common use case. If you want to flush all contexts, use the --all option.

The context handle can be specified as an integer or hexadecimal value. For example, 0x80000000 or 2147483648.

When using a resource manager like tpm2-abrmd(8), you generally do not need to worry about flushing context manually. The resource manager handles this automatically when a client process exits.

This command is most useful when interacting directly with the TPM, for example, using the simulator or when managing persistent contexts manually.

The command can take multiple context handles as arguments. Each handle will be flushed individually. If an error occurs during flushing any of the contexts, the command will exit with an error code, and the remaining contexts may or may not have been flushed depending on the specific error. However, the command will attempt to flush all specified contexts.

EXAMPLES

Flushing a Transient Object

Typically, when using the TPM, the interactions occur through a resource manager, like tpm2-abrmd(8). When the process exits, transient object handles are flushed. Thus, flushing transient objects through the command line is not required. However, when interacting with the TPM directly, this scenario is possible. The below example assumes direct TPM access not brokered by a resource manager. Specifically we will use the simulator.

tpm2_createprimary -Tmssim -c primary.ctx
tpm2_getcap -T mssim handles-transient
- 0x80000000
tpm2_flushcontext -T mssim 0x80000000

Flush All the Transient Objects

tpm2_flushcontext \--transient-object

Flush a Session

tpm2_startauthsession -S session.dat
tpm2_flushcontext session.dat

Returns

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.
