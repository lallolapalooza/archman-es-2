tpm2_import(1) Manual de comandos generales tpm2_import(1)

NOMBRE

tpm2_import(1) - Importa una clave externa al tpm como un objeto de clave gestionado por el TPM.

SINOPSIS

tpm2_import [OPCIONES]

DESCRIPCIÓN

tpm2_import(1) - Importa una clave generada externamente como un objeto de clave gestionado por el TPM. Requiere que el objeto clave padre sea una clave RSA. También puede importar un objeto de clave gestionado por el TPM creado por la herramienta tpm2_duplicate.

OPCIONES

Estas opciones controlan el proceso de importación de claves:

•
-G, --key-algorithm=ALGORITMO:

El algoritmo utilizado por la clave que se va a importar. Admite:

•
aes - Clave AES 128, 192 o 256.
•
rsa - Clave RSA 1024, 2048, 3072 o 4096.
•
ecc - Clave pública y privada ECC NIST P192, P224, P256, P384 o P521.
•
hmac - Clave HMAC.
•
-g, --hash-algorithm=ALGORITMO:

El algoritmo de hash para generar el nombre del objeto. Es opcional y, si no se especifica, se usa sha256 por defecto. Los algoritmos deben seguir los "estándares de formato", consulte la sección "Especificadores de algoritmos". También, consulte la sección "Algoritmos de Hash Soportados" para ver una lista de los algoritmos de hash admitidos.

•
-i, --input=ARCHIVO:

Especifica el nombre del archivo de la clave que se va a importar. Para claves AES, este archivo contiene los bytes brutos de la clave. Para claves asimétricas en formato PEM o DER. Un archivo típico se genera con openssl genrsa.

•
-C, --parent-context=OBJETO:

El objeto clave padre.

•
-U, --parent-public=ARCHIVO:

Opcional. Especifica la entrada del archivo de datos públicos de la clave padre. Esto se puede leer con la herramienta tpm2_readpublic(1). Si no se especifica, la herramienta invoca a tpm2_readpublic en el objeto padre.

•
-k, --encryption-key=ARCHIVO:

Opcional. Especifica el archivo que contiene la clave del algoritmo simétrico que se utilizó para el envoltorio interno. Si se especifica el archivo, la herramienta asume que el algoritmo es AES 128 en modo CFB, de lo contrario, ninguno.

•
-r, --private=ARCHIVO:

Especifica la ruta del archivo necesaria para guardar la parte privada cifrada del objeto importado como clave.

Al importar un objeto duplicado, esta opción especifica el archivo que contiene la parte privada del objeto a importar. # Detalles de Protección

Los objetos que pueden moverse fuera del TPM necesitan ser protegidos (confidencialidad e integridad). Por ejemplo, los objetos transitorios requieren que los datos protegidos por el TPM (clave o material de sellado) se almacenen fuera del TPM. Esto se ve en herramientas como tpm2_create(1), donde la opción -r genera estos datos protegidos. Este blob contiene las partes sensibles del objeto. Las partes sensibles del objeto están protegidas por el objeto padre, utilizando los detalles de cifrado simétrico del padre para cifrar los datos sensibles y realizar un HMAC.

Los detalles profundos se pueden encontrar en las secciones 23 de:

•
https://trustedcomputinggroup.org/wp-content/uploads/TPM-Rev-2.0-Part-1-Architecture-01.38.pdf

Notablemente, la Figura 20 es relevante, aunque se refiera específicamente a blobs de duplicación, el proceso es idéntico.

Si la salida proviene de tpm2_duplicate(1), la salida será ligeramente diferente, como se describe completamente en la sección 23.

•
-u, --public=ARCHIVO:

Especifica la ruta del archivo necesaria para guardar la parte pública del objeto importado como clave

Al importar un objeto duplicado, esta opción especifica el archivo que contiene la parte pública del objeto a importar.

•
-a, --attributes=ATRIBUTOS:

Los atributos del objeto, opcional.

•
-P, --parent-auth=AUTENTICACIÓN:

El valor de autorización para usar la clave padre especificada con -C.

•
-p, --key-auth=AUTENTICACIÓN:

El valor de autorización para la clave importada, opcional.

•
-L, --policy=POLÍTICA o CADENA_HEX:

El archivo de política o la cadena hexadecimal de política utilizada para la autorización al objeto.

•
-s, --seed=ARCHIVO:

Especifica el archivo que contiene la semilla cifrada del objeto duplicado.

Para realizar una "importación sin cifrar", se debe proporcionar un archivo de semilla con el contenido 0x0000 (por ejemplo, printf "0000" | xxd -r -p >seed.file).

•
--passin=CONTRASEÑA_ARCHIVO_PEM_OSSL

Una contraseña opcional para un archivo de entrada proporcionado por Open SSL (OSSL). Refleja la opción -passin de OSSL y se sabe que admite los formatos pass, file, env, fd y contraseña simple de openssl. (ver man(1) openssl para más información).

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará el comando, simplemente devolverá un cpHash.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un identificador o un nombre de archivo, se determina según la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio del TPM restaurado.
•
Si el argumento es una coincidencia de *prefijo* con uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento se puede cargar como un número, se tratará como un identificador, por ejemplo, 0x81010013 y se usará directamente. *OBJETO*.

Formato de Autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autorizaciones se establecen por defecto en la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación utilizando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña en formato de cadena, especificada con el prefijo "str:" o su ausencia (cadena sin prefijo) no se interpreta y se utiliza directamente para la autorización.

Cadena hexadecimal


Una contraseña en formato hexadecimal, especificada con el prefijo “hex:”,
    se convierte de formato hexadecimal a un arreglo de bytes, permitiendo así
    contraseñas con caracteres no imprimibles y/o difíciles de manejar en la
    terminal.






Ejemplo



  

  

    
hex:1122334455667788


  








Archivo


Una contraseña basada en archivo, especificada con el prefijo “file:”,
    debe ser la ruta de un archivo que contenga la contraseña a ser leída por la
    herramienta, o un “-” para usar stdin. Almacenar contraseñas en
    archivos previene fugas de información, ya que las contraseñas pasadas como
    opciones pueden ser leídas de la lista de procesos o de los historiales
    comunes del shell.






Ejemplos



  

  

    
# para usar stdin y ser preguntado
file:-
# para usar un archivo desde una ruta
file:ruta/a/archivo/de/contraseña
# para enviar una contraseña vía stdin:
echo foobar | tpm2_tool -p file:-
# para usar un here-string de bash vía stdin:
tpm2_tool -p file:- <<< foobar


  








Sesiones


Al usar una sesión de política para autorizar el uso de un objeto,
    prefije el argumento de la opción con la palabra clave session. Luego,
    indique una ruta a un archivo de sesión que fue creado con tpm2_startauthsession(1).
    Opcionalmente, si la sesión requiere un valor de autenticación para ser enviado
    con el manejador de sesión (p. ej., contraseña de política), agregue un + y
    una cadena como se describe en la sección de Contraseñas.






Ejemplos


Para usar un archivo de contexto de sesión llamado session.ctx.



  

  

    
session:session.ctx


  




Para usar un archivo de contexto de sesión llamado session.ctx
    Y enviar el valor de autenticación mypassword.



  

  

    
session:session.ctx+mypassword


  




Para usar un archivo de contexto de sesión llamado session.ctx
    Y enviar el valor de autenticación HEX 0x11223344.



  

  

    
session:session.ctx+hex:11223344


  








Autorizaciones de PCR


Puedes satisfacer una política de PCR usando el prefijo “pcr:”
    y el minilenguaje de PCR. El minilenguaje de PCR es el siguiente:
    <especificador-pcr>=<archivo-pcr-crudo>


El especificador de PCR se documenta en la sección “Especificadores
    de banco PCR”.


El archivo-pcr-crudo es un argumento
    opcional que contiene la salida del contenido crudo de la PCR tal como
    lo devuelve tpm2_pcrread(1).


Especificadores de banco PCR






Ejemplos


Para satisfacer una política de PCR de sha256 en los bancos 0, 1, 2
    y 3, usa un especificador de:



  

  

    
pcr:sha256:0,1,2,3


  




especificando AUTH.

Especificadores complejos


Los objetos, cuando se especifican para su creación por el TPM, tienen
    numerosos algoritmos para poblar en los datos públicos. Cosas como tipo,
    esquema y detalles asimétricos, tamaño de clave, etc. A continuación se
    muestra el formato general para especificar estos datos:
    <tipo>:<esquema>:<detalles-simétricos>






Especificadores de Tipo


Esta porción del especificador de algoritmo complejo es obligatoria.
    El esquema restante y los detalles simétricos se establecerán por defecto según
    el tipo especificado y el tipo del objeto que se está creando.



  
•

  
aes - AES por defecto: aes128

  
•

  
aes128<modo> - AES de 128 bits con modo opcional
      (ctr|ofb|cbc|cfb|ecb). Si no se especifica
      el modo, se establece por defecto en null.

  
•

  
aes192<modo> - Igual que
      aes128<modo>, excepto por un tamaño de clave de
      192 bits.

  
•

  
aes256<modo> - Igual que
      aes128<modo>, excepto por un tamaño de clave de
      256 bits.

  
•

  
sm4 - SM4 por defecto: sm4128

  
•

  
sm4128 o sm4_128 <modo> - SM4 de 128 bits con
      modo opcional (ctr|ofb|cbc|cfb|ecb). Si no
      se especifica el modo, se establece por defecto en null.

  
•

  
ecc - Curva Elíptica, por defecto es ecc256.

  
•

  
ecc192 o ecc_nist_p192 - Curva NIST ECC de 192 bits

  
•

  
ecc224 o ecc_nist_p224 - Curva NIST ECC de 224 bits

  
•

  
ecc256 o ecc_nist_p256 - Curva NIST ECC de 256 bits

  
•

  
ecc384 o ecc_nist_p384 - Curva NIST ECC de 384 bits

  
•

  
ecc521 o ecc_nist_p521 - Curva NIST ECC de 521 bits

  
•

  
ecc_sm2 o ecc_sm2_p256 - Curva SM2 de 256 bits

  
•

  
rsa - RSA por defecto: rsa2048

  
•

  
rsa1024 - RSA con tamaño de clave de 1024 bits.

  
•

  
rsa2048 - RSA con tamaño de clave de 2048 bits.

  
•

  
rsa3072 - RSA con tamaño de clave de 3072 bits.

  
•

  
rsa4096 - RSA con tamaño de clave de 4096 bits.

Este campo es opcional y se establece por defecto según el
    tipo de objeto que se está creando y sus atributos. En general,
    cualquier especificador Simétrico válido de la lista de
    especificadores de Tipo debería funcionar. Si
not specified, an asymmetric objects symmetric details
    defaults to aes128cfb.

    ecc256:ecdaa4-sha384 -u key.pub -r key.priv cryptographic algorithms
    ALGORITHM.








Atributos del Objeto


Los atributos del objeto se utilizan para controlar varias propiedades de los
    objetos creados. Cuando se especifican como una opción, se puede usar la máscara de
    bits sin procesar o los "nombres agradables". Los valores se pueden encontrar en la
    Tabla 31, Parte 2 de la especificación TPM2.0, que se puede encontrar aquí:


https://trustedcomputinggroup.org/wp-content/uploads/TPM-Rev-2.0-Part-2-Structures-01.38.pdf


Los nombres agradables se calculan tomando el campo de nombre de la tabla 31
    y eliminando el prefijo TPMA_OBJECT_ y poniendo en minúsculas el resultado. Por lo
    tanto, TPMA_OBJECT_FIXEDTPM se convierte en fixedtpm. Los nombres agradables se
    pueden unir usando el símbolo de OR a nivel de bits “|”.


Por ejemplo, para establecer los campos TPMA_OBJECT_FIXEDTPM,
    TPMA_OBJECT_NODA y TPMA_OBJECT_SIGN_ENCRYPT, el argumento sería:


fixedtpm|noda|sign especificando los atributos del objeto
    ATTRIBUTES.

Configuración del TCTI


El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el
    TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de
    diferentes medios.


Para controlar el TCTI, las herramientas respetan:



  
1.

  
La opción de línea de comandos -T o --tcti

  
2.

  
La variable de entorno: TPM2TOOLS_TCTI.




Nota: La opción de línea de comandos siempre anula la variable de
    entorno.


Los TCTI conocidos actualmente son:



  
•

  
tabrmd - El gestor de recursos, llamado
      tabrmd.
      Tenga en cuenta que tabrmd y abrmd como nombres de tcti son sinónimos.

  
•

  
mssim - Típicamente utilizado para comunicarse con el simulador de software
      TPM.

  
•

  
device - Utilizado al hablar directamente con el archivo del dispositivo
      TPM.

  
•

  
none - No inicializar una conexión con el TPM. Algunas herramientas permiten
      opciones fuera del tpm y, por lo tanto, admiten no usar un TCTI. Las
      herramientas que no lo admiten generarán un error cuando se intenten usar
      sin una conexión TCTI. No admite NINGUNA opción y DEBE ser
      presentado como el texto exacto de "none".




Los argumentos para la opción de línea de comandos o la variable de
    entorno tienen el formato:


<tcti-name>:<tcti-option-config>


Especificar una cadena vacía para el <tcti-name>
    o el <tcti-option-config> resulta en el uso del valor por
    defecto para esa parte respectivamente.




Valores Predeterminados del TCTI


Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando
    la semántica de dlopen(3). Las herramientas buscarán
    los TCTI tabrmd, device y mssim **EN ESE ORDEN** y
    **USARÁN EL PRIMERO QUE ENCUENTREN**. Puede consultar qué TCTI se elegirá como
    predeterminado utilizando la opción -v para mostrar la información de la
    versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados
    anteriormente es el predeterminado.






TCTIs Personalizados


Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica.
    Las herramientas utilizan internamente dlopen(3), y el valor
    crudo tcti-name se utiliza para la búsqueda. Por lo tanto, esto podría ser
    una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entiende la
    semántica de dlopen(3).








OPCIONES DEL TCTI


Esta colección de opciones se utiliza para configurar los diversos módulos
    TCTI conocidos disponibles:



  
•

  
device: Para el TCTI de dispositivo, se puede especificar el archivo
      del dispositivo de caracteres TPM para su uso por el TCTI de dispositivo. El
      valor predeterminado es /dev/tpm0.






Ejemplo: -T device:/dev/tpm0 o export
    TPM2TOOLS_TCTI=“device:/dev/tpm0”





  
•

  
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio
      o la dirección IP y el número de puerto utilizados por el simulador. Los
      valores predeterminados son 127.0.0.1 y 2321.






Ejemplo: -T mssim:host=localhost,port=2321 o export
    TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”





  
•

  
abrmd: Para el TCTI abrmd, el formato de cadena de configuración es
      una serie de pares simples de clave-valor separados por un carácter `,'. Cada
      clave y valor se separan por un carácter `=’.







  
•

  
El TCTI abrmd admite dos claves:







  
1.

  
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).

  
2.

  
`bus_type' : El tipo de la instancia dbus (una cadena) limitada a
      `session' y `system'.






Especifica el nombre del TCTI tabrmd y una cadena de configuración de
    bus_name=com.example.FooBar:



  

  

    
\--tcti=tabrmd:bus_name=com.example.FooBar


  




Especifica el TCTI predeterminado (abrmd) y una cadena de
    configuración de bus_type=session:



  

  

    
\--tcti:bus_type=session


  




NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI
    conocidos.








EJEMPLOS




Para   importar una clave, se necesita tener una clave padre



  

  

    
tpm2_createprimary -Grsa2048:aes128cfb -C o -c parent.ctx


  




Crea tu clave e impórtala. Si ya tienes una clave, simplemente úsala y
    omite su creación.






Importar   una clave AES 128



  

  

    
dd if=/dev/urandom of=sym.key bs=1 count=16
tpm2_import -C parent.ctx -G aes -i sym.key -u key.pub -r key.priv


  








Importar   una clave RSA



  

  

    
openssl genrsa -out private.pem 2048
tpm2_import -C parent.ctx -G rsa -i private.pem -u key.pub -r key.priv


  








Importar   una clave ECC



  

  

    
openssl ecparam -name prime256v1 -genkey -noout -out private.ecc.pem
tpm2_import -C parent.ctx -G ecc -i private.ecc.pem -u key.pub -r key.priv
