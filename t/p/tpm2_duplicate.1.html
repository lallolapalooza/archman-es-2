tpm2_duplicate(1)

tpm2_duplicate(1) Manual de Comandos Generales tpm2_duplicate(1)

NOMBRE

tpm2_duplicate(1) - Duplica un objeto cargado para que pueda ser utilizado en una jerarquía diferente.

SINOPSIS

tpm2_duplicate [OPCIONES]

DESCRIPCIÓN

tpm2_duplicate(1) - Esta herramienta duplica un objeto cargado para que pueda ser utilizado en una jerarquía diferente. La nueva clave padre del duplicado puede estar en el mismo u otro TPM o TPM_RH_NULL.

OPCIONES

Estas opciones controlan el proceso de importación de claves:

•
-G, --wrapper-algorithm=ALGORITMO:

El algoritmo simétrico que se utilizará para el envoltorio interior si no se usa -U. Admite:

•
aes - AES 128 en modo CFB.
•
null - ninguno El algoritmo de clave asociado con el padre público si se usa -U.
•
-G, --key-algorithm=ALGORITMO:

El algoritmo de clave asociado con el padre público si se usa -U.

•
-i, --encryptionkey-in=ARCHIVO:

Especifica el nombre del archivo de la clave simétrica (datos de 128 bits) que se utilizará para el envoltorio interior. Válido solo cuando el algoritmo simétrico especificado no es nulo.

•
-o, --encryptionkey-out=ARCHIVO:

Especifica la ruta del archivo para almacenar la clave simétrica (datos de 128 bits) que se utilizó para el envoltorio interior. Válido solo cuando el algoritmo simétrico especificado no es nulo y no se especifica --input-key-file. El TPM genera la clave en este caso.

•
-C, --parent-context=OBJETO:

El objeto de clave padre.

•
-U, --parent-public=ARCHIVO:

Especifica la ruta del archivo de la clave pública del objeto padre en el TPM de destino. Debe ser un archivo con formato TPM2B_PUBLIC. Esta clave pública se utiliza para el cifrado de una clave PEM o DER que se exportará para un TPM remoto.

•
-k, --private-key=ARCHIVO:

Especifica la ruta del archivo de la clave privada externa que se cifrará para el TPM remoto. Debe ser una clave privada en formato PEM.

•
-r, --private=ARCHIVO:

Especifica la ruta del archivo para guardar la porción privada del objeto duplicado. # Detalles de Protección

Los objetos que pueden moverse fuera del TPM deben ser protegidos (confidencialidad e integridad). Por ejemplo, los objetos transitorios requieren que los datos protegidos por el TPM (clave o material de sellado) se almacenen fuera del TPM. Esto se ve en herramientas como tpm2_create(1), donde la opción -r genera estos datos protegidos. Este blob contiene las porciones sensibles del objeto. Las porciones sensibles del objeto están protegidas por el objeto padre, utilizando los detalles de cifrado simétrico del padre para cifrar los datos sensibles y HMACarlos.

Los detalles completos se pueden encontrar en las secciones 23 de:

•
https://trustedcomputinggroup.org/wp-content/uploads/TPM-Rev-2.0-Part-1-Architecture-01.38.pdf

En particular, la Figura 20 es relevante, aunque se refiera específicamente a blobs de duplicación, el proceso es idéntico.

Si la salida es de tpm2_duplicate(1), la salida será ligeramente diferente, como se describe completamente en la sección 23.

•
-u, --public=ARCHIVO:

Especifica la ruta del archivo para guardar la porción pública del objeto duplicado, si se está duplicando una clave externa.

•
-s, --encrypted-seed=ARCHIVO:

El archivo donde guardar la semilla cifrada del objeto duplicado.

•
-p, --auth=AUTORIZACIÓN:

El valor de autorización para la clave, opcional.

•
-L, --policy=ARCHIVO:

El archivo de política de entrada, opcional.

•
-c, --key-context=OBJETO:

El objeto que se va a duplicar.

•
-a, --attributes=ATRIBUTOS:

Los atributos del objeto, opcional. El valor predeterminado para los objetos creados es:

TPMA_OBJECT_SIGN_ENCRYPT|TPMA_OBJECT_DECRYPT|TPMA_OBJECT_USERWITHAUTH

Nota: Si se especifica una política sin un valor de autorización, se desactiva TPMA_OBJECT_USERWITHAUTH.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se conoce comúnmente como cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash.

Referencias

Formato del objeto de contexto

El tipo de un objeto de contexto, ya sea un manejador o un nombre de archivo, se determina de acuerdo con la siguiente lógica, *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio del TPM restaurado.
•
Si el argumento es una coincidencia de *prefijo* con uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un manejador, por ejemplo, 0x81010013 y se usará directamente._OBJETO_.

Formato de autorización

La autorización para usar un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autorizaciones tienen como valor predeterminado la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas utilizando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña de cadena, especificada por el prefijo "str:" o su ausencia (cadena cruda sin prefijo) no se interpreta y se usa directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña en formato de cadena hexadecimal, especificada por el prefijo "hex:", se convierte de formato hexadecimal a formato de array de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables con la terminal.

Ejemplo

hex:1122334455667788

CONFIGURACIÓN DEL TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPM a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Se utiliza al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del tpm y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo soportan generarán un error cuando se intente usarlas sin una conexión TCTI. No soporta *NINGUNA* opción y *DEBE* presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<configuración-opción-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <configuración-opción-tcti> da como resultado el uso del valor predeterminado para esa parte respectivamente.

VALORES PREDETERMINADOS DEL TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI *tabrmd*, *device* y *mssim* *EN ESE ORDEN* y *USARÁN EL PRIMERO* *ENCONTRADO*. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados anteriormente es el predeterminado.

TCTIS PERSONALIZADOS

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor bruto del *nombre-tcti* se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca según lo entienda la semántica de dlopen(3).

OPCIONES DEL TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de carácter del TPM para su uso por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter `,`. Cada clave y valor de cadena están separados por un carácter `=`.
•
El TCTI abrmd admite dos claves:
1.
`bus_name`: El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type`: El tipo de instancia dbus (una cadena) limitado a `session` y `system`.

Especifica el nombre del tcti tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especifica el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.

EXAMPLES

The tpm2_duplicate tool supports duplicating keys/objects to a remote TPM. This process requires several steps and involves sending intermediate files between the two TPMs.

The following examples demonstrate this process. We will use TPM-A as the source TPM and TPM-B as the destination TPM.

Example-1: Duplicate key to remote TPM

On TPM-A, create an object to be duplicated.

tpm2_createkey -c primary.ctx -u parent.pub -r parent.prv
tpm2_load -C primary.ctx -u parent.pub -r parent.prv -c parent.ctx
tpm2_create -C parent.ctx -u key.pub -r key.prv -c key.ctx

Now, start the duplication process. The parent context used for duplication must be the same as the parent context used to load the key.

tpm2_duplicate -C parent.ctx -c key.ctx -G null -p session:session.dat \
-r dup.dpriv -s dup.seed

Copy the following files to TPM-B:

  • dup.pub
  • dup.dpriv
  • dup.seed
  • (optionally data.encrypted just to test decryption)

On TPM-B, start an auth,policy session.

tpm2_startauthsession --policy-session -S session.dat
tpm2_policycommandcode -S session.dat -L dpolicy.dat TPM2_CC_Duplicate

Load the context we used to transfer.

tpm2_flushcontext --transient-object
tpm2_load -C primary.ctx -u new_parent.pub -r new_parent.prv -c new_parent.ctx

Import the duplicated context against the parent we used.

tpm2_import -C new_parent.ctx -u dup.pub -i dup.dpriv \
-r dup.prv -s dup.seed -L dpolicy.dat

Load the duplicated key context.

tpm2_flushcontext --transient-object
tpm2_load -C new_parent.ctx -u dup.pub -r dup.prv -c dup.ctx

Test the imported key matches.

•
Sign
echo "meet me at.." >file.txt
tpm2_sign -c dup.ctx -g sha256 -o sig.rss -p foo file.txt
dd if=sig.rss of=sign.raw bs=1 skip=6 count=256

Compare the signature file hash:

$ sha256sum sign.raw
a1b4e3fbaa29e6e46d95cff498150b6b8e7d9fd21182622e8f5a3ddde257879e
•
Decryption
tpm2_flushcontext --transient-object
tpm2_rsadecrypt -p foo -c dup.ctx -o data.ptext data.encrypted
# cat data.ptext 
meet me at..

Example-3: Exporting an OpenSSL RSA key for a remote TPM

To securely send an OpenSSL generated RSA key to a remote TPM such that only that remote TPM will be able to load it, and without exposing the private key to the host operating system on the remote machine:

•
On the destination TPM-B, create a primary context and read its public key, then send primary.pub to the source machine:
tpm2_createprimary -c primary.ctx
tpm2_readpublic -c primary.ctx -o primary.pub
•
On the source machine create the RSA private key and wrap it for the destination TPM’s public key. Similar to tpm2_makecredential, this step should not require a TPM.
openssl genrsa -out rsa.pem
tpm2_duplicate -U primary.pub -G rsa -k rsa.pem -u rsa.pub -r rsa.dpriv -s rsa.seed
•
Send the rsa.pub, rsa.dpriv and rsa.seed to the destination TPM-B and import the files, which will decrypt them using the primary.ctx to produce rsa.priv, which can then be loaded and used as a TPM key:
tpm2_import -C primary.ctx -G rsa -i rsa.dpriv -s rsa.seed -u rsa.pub -r rsa.priv
tpm2_load -C primary.ctx -c rsa.ctx -u rsa.pub -r rsa.priv
