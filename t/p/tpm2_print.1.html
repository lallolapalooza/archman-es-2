tpm2_print(1) Manual de Comandos Generales tpm2_print(1)

NOMBRE

tpm2_print(1) - Imprime estructuras de datos TPM

SINOPSIS

tpm2_print [OPCIONES] [ARGUMENTO o ENTRADA ESTÁNDAR]

DESCRIPCIÓN

tpm2_print(1) - Decodifica una estructura de datos TPM e imprime los elementos contenidos en stdout como YAML. Se puede especificar una ruta de archivo que contenga un objeto TPM o una clave privada TSS2 en formato PEM como argumento de ruta. Lee desde la entrada estándar si no se especifica.

OPCIONES

•
-t, --type:

Requerido. Tipo de estructura de datos. La opción admite los siguientes argumentos:

•
TPMS_ATTEST
•
TPMS_CONTEXT
•
TPM2B_PUBLIC
•
TPMT_PUBLIC
•
TSSPRIVKEY_OBJ
•
ESYS_TR
•
ARGUMENTO el argumento de la línea de comandos especifica la ruta de los datos TPM.
•
-f, --format:

Selección de formato para el archivo de salida de la clave pública. `tss' (el predeterminado) generará un blob binario según la Especificación de TPM 2.0. `pem' generará una clave pública codificada en PEM compatible con OpenSSL. `der' generará una clave pública codificada en DER compatible con OpenSSL. `tpmt' generará un blob binario de la estructura TPMT_PUBLIC referenciada por las especificaciones de TPM 2.0.

Formato de clave pública. Esto solo funciona si la opción --type/-t está establecida en TPM2B_PUBLIC o TPMT_PUBLIC.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un manejador o un nombre de archivo, se determina según la siguiente lógica, *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio TPM restaurado.
•
Si el argumento es una coincidencia de *prefijo* con uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento se puede cargar como un número, se tratará como un manejador, por ejemplo, 0x81010013 y se usará directamente.

Formato de Autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autorizaciones son por defecto la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas utilizando identificadores de prefijo.

Nota: Por defecto, se asume que las contraseñas están en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña de cadena, especificada con el prefijo "str:" o su ausencia (cadena sin prefijo), no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena hexadecimal

Una contraseña de cadena hexadecimal, especificada con el prefijo "hex:", se convierte de una forma hexadecimal a una forma de array de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables con la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada con el prefijo "file:", debe ser la ruta de un archivo que contenga la contraseña a leer por la herramienta o un "-" para usar la entrada estándar. Almacenar contraseñas en archivos evita la fuga de información; las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las características comunes del historial de la shell.

Ejemplos

# para usar entrada estándar y que se le pida
file:-
# para usar un archivo desde una ruta
file:ruta/a/archivo/de/contraseña
# para hacer eco de una contraseña a través de la entrada estándar:
echo foobar | tpm2_tool -p file:-
# para usar un "here-string" de bash a través de la entrada estándar:
tpm2_tool -p file:- <<< foobar

Sesiones

Al utilizar una sesión de política para autorizar el uso de un objeto, prefije el argumento de la opción con la palabra clave session. Luego, indique una ruta a un archivo de sesión que se creó con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autenticación para ser enviado con el manejador de sesión (por ejemplo, contraseña de política), agregue un + y una cadena como se describe en la sección de Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autenticación HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones de PCR

Puedes satisfacer una política de PCR utilizando el prefijo "pcr:" y el minilenguaje PCR. El minilenguaje PCR es el siguiente: <especificador-pcr>=<archivo-pcr-crudo>

El especificador de PCR se documenta en la sección "Especificadores de banco PCR".

El archivo-pcr-crudo es un argumento **opcional** que contiene la salida de los contenidos crudos del PCR tal como los devuelve tpm2_pcrread(1).

Especificadores de banco PCR

Ejemplos

Para satisfacer una política de PCR de sha256 en los bancos 0, 1, 2 y 3 utiliza un especificador de:

pcr:sha256:0,1,2,3

especificando AUTH.

Configuración de TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con los TPM a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Utilizado al hablar directamente con un archivo de dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo admiten generarán un error cuando se intenten usar sin una conexión TCTI. No admite *NINGUNA* opción y *DEBE* presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para <nombre-tcti> o <config-opciones-tcti> resulta en que se utilice el valor predeterminado para esa parte respectivamente.

Valores Predeterminados de TCTI

Cuando no se especifica un TCTI, el TCTI predeterminado se busca utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim **EN ESE ORDEN** y **USARÁN EL PRIMERO QUE ENCUENTREN**. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para imprimir la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados anteriormente es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor bruto de nombre-tcti se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca tal como lo entiende la semántica de dlopen(3).

OPCIONES DE TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres TPM a utilizar por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se pueden especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter `,'. Cada clave y valor de cadena están separados por un carácter `= '.
•
abrmd TCTI admite dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia de dbus (una cadena) limitada a `session' y `system'.

Especificar el nombre TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especificar el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. Los diversos módulos TCTI conocidos.

Configuración de TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con los TPM a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Utilizado al hablar directamente con un archivo de dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo admiten generarán un error cuando se intenten usar sin una conexión TCTI. No admite *NINGUNA* opción y *DEBE* presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para <nombre-tcti> o <config-opciones-tcti> resulta en que se utilice el valor predeterminado para esa parte respectivamente.

Valores Predeterminados de TCTI

Cuando no se especifica un TCTI, el TCTI predeterminado se busca utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim **EN ESE ORDEN** y **USARÁN EL PRIMERO QUE ENCUENTREN**. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para imprimir la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados anteriormente es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor bruto de nombre-tcti se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca tal como lo entiende la semántica de dlopen(3).

Configuración de TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con los TPM a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Utilizado al hablar directamente con un archivo de dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo admiten generarán un error cuando se intenten usar sin una conexión TCTI. No admite *NINGUNA* opción y *DEBE* presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para <nombre-tcti> o <config-opciones-tcti> resulta en que se utilice el valor predeterminado para esa parte respectivamente.

Valores Predeterminados de TCTI

Cuando no se especifica un TCTI, el TCTI predeterminado se busca utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim **EN ESE ORDEN** y **USARÁN EL PRIMERO QUE ENCUENTREN**. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para imprimir la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados anteriormente es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor bruto de nombre-tcti se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca tal como lo entiende la semántica de dlopen(3).

OPCIONES DE TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres TPM a utilizar por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se pueden especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter `,'. Cada clave y valor de cadena están separados por un carácter `= '.
•
TCTI abrmd admite dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia de dbus (una cadena) limitada a `session' y `system'.

Especificar el nombre TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especificar el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. Los diversos módulos TCTI conocidos.

Cuando no se especifica un TCTI, el TCTI predeterminado se busca utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTI tabrmd, device y mssim **EN ESE ORDEN** y **USARÁN EL PRIMERO QUE ENCUENTREN**. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para imprimir la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados anteriormente es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor bruto de nombre-tcti se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca tal como lo entiende la semántica de dlopen(3).

OPCIONES DE TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres TPM a utilizar por el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se pueden especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter `,'. Cada clave y valor de cadena están separados por un carácter `= '.
•
TCTI abrmd admite dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia de dbus (una cadena) limitada a `session' y `system'.

Especificar el nombre TCTI tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especificar el TCTI predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. Los diversos módulos TCTI conocidos.

NOMBRE

tpm2_print - Imprimir datos del TPM

SINOPSIS

tpm2_print [-h | --help] [-V | --version] [-h | --help] [-e | --encoding ENCODING] [-f | --format FORMAT] [-o | --output ARCHIVO] [-S | --session SESSION] [-t | --type TIPO] [-c | --ctx ARCHIVO] [-l | --tloword TLOWORD] [--tcti TCTI] ARCHIVO ...

DESCRIPCIÓN

tpm2_print es una utilidad para imprimir los datos del TPM en un formato legible. Las estructuras de datos del TPM se pueden serializar a un archivo en un formato binario. Esta herramienta deserializará los datos y los imprimirá en la salida estándar o en un archivo especificado.

Las siguientes estructuras de datos conocidas y sus formatos de archivo son compatibles:

TPM2B_PUBLIC: estructuras públicas de objetos TPM. Se pueden encontrar en archivos que contienen claves públicas de objetos TPM. Estas estructuras se pueden exportar de las claves TPM en un formato PEM si el TPM está configurado para ello.
TPMT_PUBLIC: la estructura pública de un objeto TPM. Esta estructura es la parte principal de la estructura TPM2B_PUBLIC, pero se puede utilizar para imprimir la estructura pública de forma más directa. Esta se puede exportar en un formato PEM si el TPM está configurado para ello.
TPMS_ATTEST: estructuras de datos de atestación de TPM. Estas estructuras se utilizan para la cita, la verificación, la recuperación y la señal de datos del TPM. Estas estructuras son más frecuentemente el resultado del comando tpm2_quote, tpm2_verifysig, y tpm2_commit.
TPM2B_PRIVATE: estructuras privadas de objetos TPM. Estas estructuras se pueden encontrar en archivos que contienen claves privadas de objetos TPM. Las claves privadas de objetos TPM se pueden exportar en un formato PEM si el TPM está configurado para ello.
TPM2B_SENSITIVE: estructuras sensibles de objetos TPM. Estas estructuras son similares a TPM2B_PRIVATE, pero contienen información sensible adicional que puede no ser exportable en un formato PEM. Esta estructura solo puede ser utilizada con la herramienta tpm2_print y no se puede convertir a un formato PEM.
TSSPRIVKEY_OBJ: estructura de objeto de clave privada TSS. Esta estructura es un contenedor de clave privada, que también puede contener información pública y metadatos del objeto TPM. Este tipo de objeto se puede exportar a un formato PEM.
ESYS_TR: la estructura del manejador de objeto TPM del sistema de enrutamiento de la API de “TSS_esys”. Esta estructura se utiliza para representar un objeto TPM que ha sido cargado en el TPM. Se puede serializar a un archivo utilizando herramientas como tpm2_evictcontrol y tpm2_readpublic. Esta estructura se puede imprimir para mostrar su nombre.

•

EJEMPLOS

Imprimir una cita del TPM

Configurar una clave para generar una cita

tpm2_createprimary -C e -c primary.ctx
tpm2_create -C primary.ctx -u key.pub -r key.priv
tpm2_load -C primary.ctx -u key.pub -r key.priv -c key.ctx
tpm2_quote -c key.ctx -l 0x0004:16,17,18+0x000b:16,17,18 -g sha256 -m msg.dat

Imprimir una cita

tpm2_print -t TPMS_ATTEST msg.dat

Imprimir un archivo público

tpm2_print -t TPM2B_PUBLIC key.pub

Imprimir un archivo público tpmt

tpm2_readpublic -c key.ctx -f tpmt -o key.tpmt
tpm2_print -t TPMT_PUBLIC key.tpmt

Imprimir un archivo TPM2B_PUBLIC y convertirlo al formato PEM

tpm2 print -t TPM2B_PUBLIC -f pem key.pub

Imprimir la porción pública de un archivo TSSPRIVKEY PEM y convertirlo al formato PEM

tpm2 print -t TSSPRIVKEY_OBJ tssprivkey.pem
tpm2 print -t TSSPRIVKEY_OBJ tssprivkey.pem -f pem > publickey.pem

Imprimir el nombre de un manejador ESYS_TR serializado.

Los manejadores ESYS_TR serializados se devuelven de herramientas como las opciones -o de tpm2_evictcontrol y -t de tpm2_readpublic.

tpm2_createprimary -c primary.ctx
tpm2_evictcontrol -c primary.ctx -o primary.tr
tpm2 print -t ESYS_TR primary.tr
