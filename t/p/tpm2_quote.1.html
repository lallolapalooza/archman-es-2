tpm2_quote(1) Manual General de Comandos tpm2_quote(1)

NOMBRE

tpm2_quote(1) - Proporciona una cita y firma del TPM.

SINOPSIS

tpm2_quote [OPCIONES]

DESCRIPCIÓN

tpm2_quote(1) - Proporciona una cita y firma para una lista dada de PCRs en el algoritmo/bancos dados.

OPCIONES

•
-c, --key-context=OBJETO:

Objeto de contexto para la clave de firma de la cita.

•
-p, --auth=AUTORIZACIÓN:

Especifica el valor de autorización para el AK especificado por la opción -C.

•
-l, --pcr-list=PCR:

La lista de bancos de PCR y los IDs de PCR seleccionados para cada banco. También ver la sección de NOTAS más abajo.

•
-m, --message=ARCHIVO:

Archivo de salida del mensaje, registra el mensaje de cita que conforma los datos firmados por el TPM.

•
-s, --signature=ARCHIVO:

Archivo de salida de la firma, registra la firma en el formato especificado a través de la opción -f.

•
-f, --format=FORMATO:

Selección de formato para el archivo de salida de la firma.

•
-o, --pcr=ARCHIVO.

Archivo de salida de PCR, opcional, registra la lista de valores de PCR como se define en -l.

•
-F, --pcrs_format=FORMATO:

Selección de formato para el blob binario en el archivo de salida de PCR. `values' generará un blob binario de los valores de PCR. `serialized' generará un blob binario de los valores de PCR en forma de estructura de datos serializada en formato little-endian. Opcional. Por defecto es `serialized'.

•
-q, --qualification=CADENA_HEX_O_RUTA:

Datos proporcionados como una cadena hexadecimal o archivo binario para cualificar la cita, opcional. Esto se usa típicamente para agregar un nonce contra ataques de repetición.

•
-g, --hash-algorithm:

Algoritmo de hash para la firma. Por defecto es sha256.

•
--scheme=ALGORITMO:

El esquema de firma utilizado para firmar el mensaje. Opcional. Los esquemas de firma deben seguir los "estándares de formato", ver la sección "Especificadores de Algoritmos". También, ver la sección "Esquemas de Firma Soportados" para una lista de esquemas de firma soportados. Si se especifica, el esquema de firma debe coincidir con el tipo de clave. Si se deja sin especificar, se utilizará un esquema de firma por defecto para el tipo de clave.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará realmente el comando, simplemente devolverá un cpHash.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un manejador o un nombre de archivo, se determina según la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, entonces el archivo se carga como un objeto transitorio del TPM restaurado.
•
Si el argumento coincide *al principio* con uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de respaldo
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento puede cargarse como un número, se tratará como un manejador, por ejemplo, 0x81010013 y se usará directamente._OBJETO_.

Formato de Autorización

La autorización para el uso de un objeto en TPM2.0 puede venir en 3 formas diferentes: 1. Contraseña 2. HMAC 3. Sesiones

NOTA: "Las autorizaciones por defecto son la CONTRASEÑA VACÍA cuando no se especifican".

Contraseñas

Las contraseñas se interpretan en las siguientes formas a continuación utilizando identificadores de prefijo.

Nota: Por defecto, las contraseñas se asumen en formato de cadena cuando no tienen prefijo.

Cadena

Una contraseña de cadena, especificada por el prefijo "str:" o su ausencia (cadena cruda sin prefijo) no se interpreta y se utiliza directamente para la autorización.

Ejemplos

foobar
str:foobar

Cadena Hexadecimal

Una contraseña en cadena hexadecimal, especificada por el prefijo "hex:" se convierte de forma hexadecimal a forma de array de bytes, permitiendo así contraseñas con caracteres no imprimibles y/o no amigables con la terminal.

Ejemplo

hex:1122334455667788

Archivo

Una contraseña basada en archivo, especificada por el prefijo "file:" debe ser la ruta de un archivo que contenga la contraseña a leer por la herramienta o un "-" para usar stdin. Almacenar contraseñas en archivos evita fugas de información, las contraseñas pasadas como opciones pueden ser leídas de la lista de procesos o de las características comunes del historial del shell.

Ejemplos

# para usar stdin y que se solicite
file:-
# para usar un archivo desde una ruta
file:ruta/al/archivo/contraseña
# para hacer echo de una contraseña vía stdin:
echo foobar | tpm2_tool -p file:-
# para usar una cadena de bash vía stdin:
tpm2_tool -p file:- <<< foobar

Sesiones

Al usar una sesión de política para autorizar el uso de un objeto, antepón el argumento de la opción con la palabra clave session. Luego indica una ruta a un archivo de sesión que fue creado con tpm2_startauthsession(1). Opcionalmente, si la sesión requiere un valor de autorización para ser enviado con el manejador de sesión (por ejemplo, contraseña de política), entonces añade un + y una cadena como se describe en la sección de Contraseñas.

Ejemplos

Para usar un archivo de contexto de sesión llamado session.ctx.

session:session.ctx

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización mypassword.

session:session.ctx+mypassword

Para usar un archivo de contexto de sesión llamado session.ctx Y enviar el valor de autorización HEX 0x11223344.

session:session.ctx+hex:11223344

Autorizaciones de PCR

Puedes satisfacer una política de PCR usando el prefijo "pcr:" y el minilenguaje de PCR. El minilenguaje de PCR es el siguiente: <especificación-pcr>=<archivo-pcr-crudo><

NAME

tpm2_pcrread - read PCR registers

SYNOPSIS

tpm2_pcrread [-h|--help[=man|no-man]] [-v|--version] [-Q|--quiet] [-T TCTI|--tcti=TCTI] [-c auth|--auth=auth] [-f format|--format=format] [-o output|--output=output] [-S session|--session=session] [-I input|--input=input] [-p policy|--policy=policy] [-P policy-auth|--policy-auth=policy-auth] [-r raw-pcr-file|--raw-pcr-file=raw-pcr-file] [PCR_SPEC...]

DESCRIPTION

The tpm2_pcrread command is used to read the contents of the TPM’s Platform Configuration Registers (PCRs).

The PCR spec is documented in in the section “PCR bank specifiers”.

The raw-pcr-file is an optional argument that contains the output of the raw PCR contents as returned by tpm2_pcrread(1).

PCR bank specifiers

Examples

To satisfy a PCR policy of sha256 on banks 0, 1, 2 and 3 use a specifier of:

pcr:sha256:0,1,2,3

specifying AUTH.

Signature Format Specifiers

Format selection for the signature output file. tss (the default) will output a binary blob according to the TPM 2.0 specification and any potential compiler padding. The option plain will output the plain signature data as defined by the used cryptographic algorithm. signature FORMAT.

PCR Bank Specifiers

PCR Bank Selection lists follow the below specification:

<BANK>:<PCR>[,<PCR>] or <BANK>:all

multiple banks may be separated by `+'.

For example:

sha1:3,4+sha256:all

will select PCRs 3 and 4 from the SHA1 bank and PCRs 0 to 23 from the SHA256 bank.

Certain commands support specifying forward sealing values as well:

sha1:0,1=da39a3ee5e6b4b0d3255bfef95601890afd80709,2

This will select the current values for PCRs 0 and 2, but use the specified value for PCR 1. Digest lengths must match the bank size. An optional 0x prefix will be stripped off.

Note

PCR Selections allow for up to 5 hash to pcr selection mappings. This is a limitation in design in the single call to the tpm to get the pcr values.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

NAME

tpm2_quote — quote data or a hash of data

SYNOPSIS

tpm2_quote [–h hex] [–p pem] [–r raw] [–P password] [–S session] [–c context] [–l locality] [–e ehashpolicy] [–g hashalg] [–G asymalg] [–o output] [–T tcti] [–Q] [–V level] [command options]

DESCRIPTION

The tpm2_quote command is used to quote data or a hash of data. This command supports quoting data or a hash of data using either an asymmetric key or the TPM’s endorsement key.

The TPM must be configured with the appropriate keys for signing and for sealing policies.

The data to be quoted can be provided via standard input, or via a file specified using the –o option. If the data is provided via standard input, and the –o option is also used, the data will be read from standard input, and the output will be written to the file.

The –l option is used to specify the locality for the quote. The locality is a bitmask that indicates the location of the quote. The default locality is 0x00.

The –e option is used to specify an eHash policy. The eHash policy is a hash of the policy that will be used to authorize the quote.

The –g option is used to specify the hash algorithm to be used for the quote. The default hash algorithm is sha256.

The –G option is used to specify the asymmetric algorithm to be used for the quote. The default asymmetric algorithm is rsa.

The –o option is used to specify the output file for the quote. If this option is not specified, the quote will be written to standard output.

The –T option is used to specify the TCTI to be used for the connection to the TPM. The default TCTI is "device:/dev/tpm0".

The –Q option is used to suppress all output except for the quote.

The –V option is used to specify the verbosity level for the command. The default verbosity level is 0.

Context Object Format

The context object format is a JSON object that contains the following fields:

  • context: The context object in JSON format.
  • locality: The locality of the quote.
  • policy: The policy to be used for the quote.

Authorization Formatting

The authorization formatting is used to specify the authorization policy for the quote. The authorization policy is a JSON object that contains the following fields:

  • password: The password for the authorization policy.
  • session: The session for the authorization policy.

Signature Format Specifiers

The signature format specifiers are used to specify the format of the signature. The following specifiers are supported:

  • hex: The signature will be printed as a hexadecimal string.
  • pem: The signature will be printed as a PEM-encoded string.
  • raw: The signature will be printed as a raw byte string.

PCR Bank Specifiers

The PCR bank specifiers are used to specify the PCR bank to be used for the quote. The following specifiers are supported:

  • sha1: Use the SHA1 PCR bank.
  • sha256: Use the SHA256 PCR bank.
  • sha384: Use the SHA384 PCR bank.
  • sha512: Use the SHA512 PCR bank.

COMMON OPTIONS

These options are common to all tpm2-* tools.

–T tcti

The TPM Transmission Control Interface (TCTI) used to connect to the TPM. The default TCTI is "device:/dev/tpm0".

Valid TCTIs include:

  • device: Connect to a TPM device using the specified device path.
  • socket: Connect to a TPM device using a network socket.
  • mssim: Connect to a TPM device using the MS Sim interface.
  • file: Connect to a TPM device using a file.
–Q

Quiet mode. Suppress all output except for the TPM2B_DATA or TPM2B_DIGEST response.

–V level

Set the verbosity level. The default level is 0. Higher levels provide more detailed output.

TCTI Configuration

The TCTI configuration is used to specify the TCTI to be used for the connection to the TPM. The TCTI configuration is a string that can take one of the following forms:

  • device: Connect to a TPM device using the specified device path. Example: device:/dev/tpm0
  • socket: Connect to a TPM device using a network socket. Example: socket:host=127.0.0.1,port=2321
  • mssim: Connect to a TPM device using the MS Sim interface. Example: mssim
  • file: Connect to a TPM device using a file. Example: file:path=/tmp/tpm.bin

TCTI OPTIONS

The following options can be used to configure the TCTI:

–T tcti

Specify the TCTI to use. The default is "device:/dev/tpm0".

EXAMPLES

Quote data from a file using the TPM's endorsement key: 

$ tpm2_quote -p some_password -o my_data.txt

Quote data from standard input using an asymmetric key: 

$ echo "my data" | tpm2_quote -p some_password -G rsa -o /dev/stdout

Quote a hash of data using a specific PCR bank: 

$ tpm2_quote -p some_password -l 0x110011 -r my_hash.bin -g sha256

NOTES

This command requires the TPM to be initialized and configured with the necessary keys for signing and sealing policies.

The –p option is used to specify the password for the authorization policy. If the policy is not protected by a password, this option can be omitted.

The –S option is used to specify the session for the authorization policy. If the policy is not protected by a session, this option can be omitted.

The –c option is used to specify the context object for the quote. If this option is not specified, the context object will be read from standard input.

The –l option is used to specify the locality for the quote. The locality is a bitmask that indicates the location of the quote. The default locality is 0x00.

The –e option is used to specify an eHash policy. The eHash policy is a hash of the policy that will be used to authorize the quote.

The –g option is used to specify the hash algorithm to be used for the quote. The default hash algorithm is sha256.

The –G option is used to specify the asymmetric algorithm to be used for the quote. The default asymmetric algorithm is rsa.

The –o option is used to specify the output file for the quote. If this option is not specified, the quote will be written to standard output.

The –T option is used to specify the TCTI to be used for the connection to the TPM. The default TCTI is "device:/dev/tpm0".

The –Q option is used to suppress all output except for the quote.

The –V option is used to specify the verbosity level for the command. The default verbosity level is 0.

Returns

Returns 0 on success, or a non-zero value on failure.

BUGS

None reported.
