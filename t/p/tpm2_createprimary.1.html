tpm2_createprimary(1) Manual de Comandos Generales tpm2_createprimary(1)

NOMBRE

tpm2_createprimary(1) - Crea una clave primaria.

SINOPSIS

tpm2_createprimary [OPCIONES]

DESCRIPCIÓN

tpm2_createprimary(1) - Este comando se utiliza para crear un objeto primario bajo una de las jerarquías: Propietario, Plataforma, Aval, NULL. El comando creará y cargará un Objeto Primario. Las porciones sensible y pública no se devuelven. Se guarda un archivo de contexto para el manejador del objeto creado como un archivo para interacciones futuras con el primario creado.

OPCIONES

•
-C, --hierarchy=OBJETO:

La jerarquía bajo la cual se crea el objeto. Esto también dictará qué secreto de autorización (si lo hay) debe proporcionarse. Por defecto es TPM_RH_OWNER, cuando no se especifica ningún valor. Las opciones admitidas son:

•
o para TPM_RH_OWNER
•
p para TPM_RH_PLATFORM
•
e para TPM_RH_ENDORSEMENT
•
n para TPM_RH_NULL
•
<num> donde se puede utilizar un número bruto.
•
-P, --hierarchy-auth=AUTH:

El valor de autorización para la jerarquía especificada con -C.

•
-p, --key-auth=AUTH:

El valor de autorización para el objeto primario creado.

•
-g, --hash-algorithm=ALGORITMO:

El algoritmo de hash a utilizar para generar el nombre del objeto. Por defecto es sha256 si no se especifica.

•
-G, --key-algorithm=ALGORITMO:

El tipo de algoritmo para la clave primaria generada. Por defecto es rsa2048:null:aes128cfb.

•
-c, --key-context=ARCHIVO:

La ruta del archivo para guardar el contexto del objeto primario generado.

•
-L, --policy=ARCHIVO o CADENA_HEX:

Un archivo opcional de entrada o una cadena hexadecimal que contiene el resumen de política para la autorización basada en política del objeto.

•
-a, --attributes=ATRIBUTOS:

Los atributos del objeto, opcional. Por defecto es: TPMA_OBJECT_RESTRICTED|TPMA_OBJECT_DECRYPT|TPMA_OBJECT_FIXEDTPM| TPMA_OBJECT_FIXEDPARENT|TPMA_OBJECT_SENSITIVEDATAORIGIN| TPMA_OBJECT_USERWITHAUTH

•
-u, --unique-data=ARCHIVO O STDIN:

Un archivo opcional de entrada que contiene el campo único de TPMT_PUBLIC en formato little-endian. El creador de la clave primaria puede colocar información que haga que el esquema de generación de clave primaria interno del TPM genere valores estadísticamente únicos. La especificación TPM v2.0 llama a este campo único y lo sobrecarga para que contenga un valor cuando la aplicación proporciona esta estructura como entrada y otro valor cuando la aplicación recibe esta estructura como salida (como la porción pública de la clave rsa).

Si los datos se especifican como un archivo, el usuario es responsable de garantizar que este búfer esté formateado según la unión TPMU_PUBLIC_ID.

Los datos únicos también se pueden recuperar de un búfer stdin especificando “-” como valor de la opción –unique-data y la herramienta analizará el tipo de clave y asociará los datos de entrada con el búfer de datos únicos asociado al tipo de clave.

NOTA:

1.
El número máximo de bytes permitidos depende del tipo de clave y de la implementación del TPM. Por ejemplo, mientras que TSS permite un valor de hasta 512 para MAX_RSA_KEY_BYTES, la implementación ibmSwTPM admite un valor de hasta 256 bytes.
2.
Los datos de entrada únicos especificados en stdin para ECC se dividen para especificar los búferes de la coordenada X y la coordenada Y.
•
--creation-data=ARCHIVO:

Un archivo de salida opcional que guarda los datos de creación para la certificación.

•
--template-data=ARCHIVO:

Un archivo de salida opcional que guarda los datos de plantilla de clave (TPM2B_PUBLIC) para ser utilizados en tpm2_policytemplate.

•
-t, --creation-ticket=ARCHIVO:

Un archivo de salida opcional que guarda el ticket de creación para la certificación.

•
-d, --creation-hash=ARCHIVO:

Un archivo de salida opcional que guarda el hash de creación para la certificación.

•
-q, --outside-info=ARCHIVO_O_HEX:

Un archivo o cadena hexadecimal opcional para agregar datos únicos a los datos de creación. Tenga en cuenta que no contribuye a crear un objeto estadísticamente único.

•
-l, --pcr-list=PCR:

La lista de bancos de PCR y los IDs de PCR seleccionados para cada banco que se incluirán en los datos de creación para la certificación.

•
--cphash=ARCHIVO

Ruta del archivo para registrar el hash de los parámetros del comando. Esto se denomina comúnmente cpHash. NOTA: Cuando se selecciona esta opción, la herramienta no ejecutará el comando, simplemente devolverá un cpHash.

•
-f, --format:

Selección del formato para el archivo de salida de la clave pública. `tss' (el valor por defecto) generará un blob binario de acuerdo con la especificación TPM 2.0. `pem' generará una clave pública codificada en formato PEM compatible con OpenSSL. `der' generará una clave pública codificada en formato DER compatible con OpenSSL. `tpmt' generará un blob binario de la struct TPMT_PUBLIC referenciada en las especificaciones TPM 2.0.

Formato de la clave pública.

•
-o, --output=ARCHIVO:

La ruta del archivo de salida, que registra la porción pública del objeto.

Referencias

Formato del Objeto de Contexto

El tipo de un objeto de contexto, ya sea un manejador o un nombre de archivo, se determina según la siguiente lógica *en orden*:

•
Si el argumento es una ruta de archivo, se carga el archivo como un objeto transitorio TPM restaurado.
•
Si el argumento es una coincidencia de *prefijo* en uno de:
•
owner: la jerarquía del propietario
•
platform: la jerarquía de la plataforma
•
endorsement: la jerarquía de aval
•
lockout: el objeto persistente de control de bloqueo
•
Si el argumento se puede cargar como un número, se tratará como un manejador, por ejemplo, 0x81010013 y se utilizará directamente._OBJECT_.

Passwords

There are 3 types of passwords that can be specified.

String

A string password, specified by prefix “str:” or it’s absence (raw string without prefix) is not interpreted, and is directly used for authorization.

Examples

foobar
str:foobar

Hex-string

A hex-string password, specified by prefix “hex:” is converted from a hexidecimal form into a byte array form, thus allowing passwords with non-printable and/or terminal un-friendly characters.

Example

hex:1122334455667788

File

A file based password, specified be prefix “file:” should be the path of a file containing the password to be read by the tool or a “-” to use stdin. Storing passwords in files prevents information leakage, passwords passed as options can be read from the process list or common shell history features.

Examples

# to use stdin and be prompted
file:-
# to use a file from a path
file:path/to/password/file
# to echo a password via stdin:
echo foobar | tpm2_tool -p file:-
# to use a bash here-string via stdin:
tpm2_tool -p file:- <<< foobar

Sessions

When using a policy session to authorize the use of an object, prefix the option argument with the session keyword. Then indicate a path to a session file that was created with tpm2_startauthsession(1). Optionally, if the session requires an auth value to be sent with the session handle (eg policy password), then append a + and a string as described in the Passwords section.

Examples

To use a session context file called session.ctx.

session:session.ctx

To use a session context file called session.ctx AND send the authvalue mypassword.

session:session.ctx+mypassword

To use a session context file called session.ctx AND send the HEX authvalue 0x11223344.

session:session.ctx+hex:11223344

PCR Authorizations

You can satisfy a PCR policy using the “pcr:” prefix and the PCR minilanguage. The PCR minilanguage is as follows: <pcr-spec>=<raw-pcr-file>

The PCR spec is documented in in the section “PCR bank specifiers”.

The raw-pcr-file is an optional argument that contains the output of the raw PCR contents as returned by tpm2_pcrread(1).

PCR bank specifiers

Examples

To satisfy a PCR policy of sha256 on banks 0, 1, 2 and 3 use a specifier of:

pcr:sha256:0,1,2,3

specifying AUTH.

Complex Specifiers

Objects, when specified for creation by the TPM, have numerous algorithms to populate in the public data. Things like type, scheme and asymmetric details, key size, etc. Below is the general format for specifying this data: <type>:<scheme>:<symmetric-details>

Type Specifiers

This portion of the complex algorithm specifier is required. The remaining scheme and symmetric details will default based on the type specified and the type of the object being created.

•
aes - Default AES: aes128
•
aes128<mode> - 128 bit AES with optional mode (ctr|ofb|cbc|cfb|ecb). If mode is not specified, defaults to null.
•
aes192<mode> - Same as aes128<mode>, except for a 192 bit key size.
•
aes256<mode> - Same as aes128<mode>, except for a 256 bit key size.
•
sm4 - Default SM4: sm4128
•
sm4128 or sm4_128 <mode> - 128 bit SM4 with optional mode (ctr|ofb|cbc|cfb|ecb). If mode is not specified, defaults to null.
•
ecc - Elliptical Curve, defaults to ecc256.
•
ecc192 or ecc_nist_p192 - 192 bit ECC NIST curve
•
ecc224 or ecc_nist_p224 - 224 bit ECC NIST curve
•
ecc256 or ecc_nist_p256 - 256 bit ECC NIST curve
•
ecc384 or ecc_nist_p384 - 384 bit ECC NIST curve
•
ecc521 or ecc_nist_p521 - 521 bit ECC NIST curve
•
ecc_sm2 or ecc_sm2_p256 - 256 bit SM2 curve
•
rsa - Default RSA: rsa2048
•
rsa1024 - RSA with 1024 bit keysize.
•
rsa2048 - RSA with 2048 bit keysize.
•
rsa3072 - RSA with 3072 bit keysize.
•
rsa4096 - RSA with 4096 bit keysize.

Ejemplos

Crear una clave rsa2048 con un esquema de cifrado asimétrico rsaes

Crear una clave ecc256 con un esquema de firma ecdaa con un recuento de 4 y hash sha384

/tpm2_create -C parent.ctx -G ecc256:ecdaa4-sha384 -u key.pub -r key.priv algoritmos criptográficos *ALGORITHM*.

Atributos del Objeto

Los atributos del objeto se utilizan para controlar varias propiedades de los objetos creados. Cuando se especifican como una opción, se puede usar la máscara de campo de bits sin procesar o los "nombres amigables". Los valores se pueden encontrar en la Tabla 31, Parte 2 de la especificación TPM2.0, que se puede encontrar aquí:

https://trustedcomputinggroup.org/wp-content/uploads/TPM-Rev-2.0-Part-2-Structures-01.38.pdf

Los nombres amigables se calculan tomando el campo de nombre de la tabla 31 y eliminando el prefijo TPMA_OBJECT_ y convirtiendo el resultado a minúsculas. Por lo tanto, TPMA_OBJECT_FIXEDTPM se convierte en fixedtpm. Los nombres amigables se pueden unir usando el operador OR a nivel de bits “|”.

Por ejemplo, para establecer los campos TPMA_OBJECT_FIXEDTPM, TPMA_OBJECT_NODA y TPMA_OBJECT_SIGN_ENCRYPT, el argumento sería:

fixedtpm|noda|sign especificando los atributos del objeto *ATTRIBUTES*.

Configuración TCTI

El TCTI o "Interfaz de Transmisión" es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Utilizado cuando se habla directamente con el archivo del dispositivo TPM.
•
none - No inicializar una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo admiten generarán un error cuando se intente usar sin una conexión TCTI. No admite *NINGUNA* opción y *DEBE* presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<tcti-name>:<tcti-option-config>

Especificar una cadena vacía para <tcti-name> o <tcti-option-config> da como resultado el uso del valor predeterminado para esa parte respectivamente.

Valores Predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán tabrmd, device y mssim TCTIs EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado utilizando la opción -v para mostrar la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTI mencionados anteriormente es el predeterminado.

TCTIs Personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor bruto de tcti-name se utiliza para la búsqueda. Por lo tanto, esto podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca tal como lo entiende la semántica de dlopen(3).

OPCIONES TCTI

Esta colección de opciones se utiliza para configurar los diversos módulos TCTI conocidos disponibles:

•
device: Para el TCTI de dispositivo, se puede especificar el archivo del dispositivo de caracteres TPM para que lo utilice el TCTI de dispositivo. El valor predeterminado es /dev/tpm0.

Ejemplo: -T device:/dev/tpm0 o export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Para el TCTI mssim, se puede especificar el nombre de dominio o la dirección IP y el número de puerto utilizados por el simulador. Los valores predeterminados son 127.0.0.1 y 2321.

Ejemplo: -T mssim:host=localhost,port=2321 o export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Para el TCTI abrmd, el formato de la cadena de configuración es una serie de pares simples de clave-valor separados por un carácter ','. Cada clave y cadena de valor están separadas por un carácter '='.
•
El TCTI abrmd admite dos claves:
1.
`bus_name' : El nombre del servicio tabrmd en el bus (una cadena).
2.
`bus_type' : El tipo de la instancia de dbus (una cadena) limitada a 'session' y 'system'.

Especificar el nombre del tcti tabrmd y una cadena de configuración de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Especificar el tcti predeterminado (abrmd) y una cadena de configuración de bus_type=session:

\--tcti:bus_type=session

NOTA: abrmd y tabrmd son sinónimos. los diversos módulos TCTI conocidos.
