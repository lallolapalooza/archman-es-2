tpm2_makecredential(1) Manual de Comandos Generales tpm2_makecredential(1)

NOMBRE

tpm2_makecredential(1) - Genera los datos cifrados elegidos por el usuario y la clave de cifrado de datos secretos envuelta para el proceso de credencialización sensible a la privacidad de un objeto TPM.

SINOPSIS

tpm2_makecredential [OPCIONES]

DESCRIPCIÓN

tpm2_makecredential(1) - El TPM soporta un protocolo de preservación de la privacidad para la distribución de credenciales para claves en un TPM. El proceso garantiza que el objeto TPM credencializado (AIK) se carga en el mismo TPM que un objeto de clave pública bien conocido (EK) sin conocimiento de las propiedades públicas específicas del objeto TPM credencializado (AIK). La privacidad se garantiza debido al hecho de que solo se comparte el nombre del objeto TPM credencializado (AIK) y no la clave pública del objeto TPM credencializado en sí.

Make-credential es el primer paso en este proceso donde, después de recibir la clave pública del objeto de clave pública (EK) del TPM y el nombre del objeto TPM credencializado (AIK), se genera un dato cifrado elegido por el usuario y la clave de cifrado de datos secretos se genera y se envuelve utilizando procesos criptográficos específicos para la activación de credenciales que garantizan que el objeto TPM credencializado (AIK) se carga en el TPM con el objeto de clave pública bien conocido (EK).

tpm2_makecredential se puede usar para generar los datos cifrados elegidos por el usuario y la clave de cifrado de datos secretos envuelta sin un TPM utilizando la opción TCTI none.

OPCIONES

•
-e, --encryption-key=ARCHIVO:

OBSOLETO, use -u o --public en su lugar.

•
-u, --public=ARCHIVO:

Una clave pública de TPM que se utilizó para envolver la semilla. NOTA: Esta opción es la misma que -e y se agrega para que sea similar a otras herramientas que especifican la clave pública. La opción antigua se conserva por compatibilidad con versiones anteriores.

•
-G, --key-algorithm=ALGORITMO:

El algoritmo de clave asociado con la clave pública del TPM. Especifique RSA o ECC. Cuando se usa esta opción, se espera que la clave pública de entrada esté en formato PEM y se utiliza la plantilla TCG EK predeterminada para las propiedades de la clave.

•
-s, --secret=ARCHIVO o STDIN:

El secreto que será protegido por la clave derivada de la semilla aleatoria. Se puede especificar como un archivo o pasar desde stdin.

•
-n, --name=ARCHIVO:

El nombre de la clave para la cual se creará el certificado.

•
-o, --credential-blob=ARCHIVO:

La ruta del archivo de salida, que registra los datos cifrados elegidos por el usuario y la clave de cifrado de datos secretos envuelta.

Configuración TCTI

El TCTI, o "Interfaz de Transmisión", es el mecanismo de comunicación con el TPM. Los TCTI se pueden cambiar para la comunicación con TPMs a través de diferentes medios.

Para controlar el TCTI, las herramientas respetan:

1.
La opción de línea de comandos -T o --tcti
2.
La variable de entorno: TPM2TOOLS_TCTI.

Nota: La opción de línea de comandos siempre anula la variable de entorno.

Los TCTI conocidos actualmente son:

•
tabrmd - El gestor de recursos, llamado tabrmd. Tenga en cuenta que tabrmd y abrmd como nombre de tcti son sinónimos.
•
mssim - Típicamente utilizado para comunicarse con el simulador de software del TPM.
•
device - Se utiliza al hablar directamente con el archivo del dispositivo TPM.
•
none - No inicializa una conexión con el TPM. Algunas herramientas permiten opciones fuera del TPM y, por lo tanto, admiten no usar un TCTI. Las herramientas que no lo soportan darán error cuando se intenten usar sin una conexión TCTI. No soporta NINGUNA opción y DEBE presentarse como el texto exacto de "none".

Los argumentos para la opción de línea de comandos o la variable de entorno tienen el formato:

<nombre-tcti>:<config-opciones-tcti>

Especificar una cadena vacía para el <nombre-tcti> o la <config-opciones-tcti> resulta en que se utilice el valor predeterminado para esa porción respectivamente.

Valores predeterminados TCTI

Cuando no se especifica un TCTI, se busca el TCTI predeterminado utilizando la semántica de dlopen(3). Las herramientas buscarán los TCTIs tabrmd, device y mssim EN ESE ORDEN y USARÁN EL PRIMERO QUE ENCUENTREN. Puede consultar qué TCTI se elegirá como predeterminado usando la opción -v para mostrar la información de la versión. El par clave-valor "default-tcti" indicará cuál de los TCTIs mencionados anteriormente es el predeterminado.

TCTIs personalizados

Se puede cargar cualquier TCTI que implemente la interfaz TCTI dinámica. Las herramientas utilizan internamente dlopen(3), y el valor bruto nombre-tcti se utiliza para la búsqueda. Por lo tanto, podría ser una ruta a la biblioteca compartida, o un nombre de biblioteca tal como lo entiende la semántica de dlopen(3).

tpm2_makecredential(1) — tpm2-tools — Arch Linux

NAME

tpm2_makecredential - Create credential data structure for loading into the TPM.

SYNOPSIS

tpm2_makecredential [OPTIONS] [-u keyed-digest | -n name] [-o output-file]

DESCRIPTION

The tpm2_makecredential utility is used to create a credential blob. The credential blob is a data structure that is used to prove ownership of a key. The credential blob is created by taking a public key, a password (or other secret), and a nonce, and then encrypting them together using a TPM-generated key.

The credential blob can then be loaded into the TPM using the tpm2_loadcredential command. Once loaded, the TPM can use the credential blob to verify that a user has ownership of the key.

The credential blob is created by invoking the Tss2_Sys_MakeCredential call.

OPTIONS

The following are options available:

-c, --context context-handle
Specifies the context handle of the primary key or object that the credential will be associated with. This option is required.
The context handle can be specified as a hexadecimal value (e.g. 0x81010009) or as a name associated with the object (e.g. TPM2_RH_OWNER).
-u, --ticket <in-file>
Specifies the input file containing the public key or ticket. This option is mutually exclusive with -n.
-n, --name <in-file>
Specifies the input file containing the Name of the object. This option is mutually exclusive with -u.
-p, --password <password>
Specifies the password to be used for the credential. If this option is not specified, the password will be prompted for.
-s, --size <size>
Specifies the size of the credential. This should be used when the credential is not a public key.
-o, --output <output-file>
Specifies the output file where the credential blob will be written.
-G, --key-alg <alg>
Specifies the key algorithm to be used for the credential. This option is only used when the credential is a public key. Supported algorithms are rsa and ecc.
-f, --format <format>
Specifies the format of the public key. Supported formats are:
pem: PEM format
der: DER format
This option is only used when the credential is a public key.

COMMON OPTIONS

See tpm2_tool(1) for common options.

TCTI Configuration

The TPM Communication Transport Interface (TCTI) is used to communicate with the TPM. The following TCTI modules are supported:

mssim: For the mssim TCTI, the configuration string format is `host=,port='. The default host is 127.0.0.1 and the default port is 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous.

TCTI OPTIONS

The TCTI configuration string can contain the following options:

-T, --tcti tcti-name[:tcti-options]
Specifies the TCTI to use. The default TCTI is mssim.

The TCTI configuration string can contain the following options:

host=hostname
The hostname or IP address of the TPM simulator. The default is 127.0.0.1.
port=port-number
The port number of the TPM simulator. The default is 2321.
bus_name=name
The name of the abrmd service on the bus.
bus_type=type
The type of the dbus instance (session or system).

EXAMPLES

tpm2 createek -Q -c 0x81010009 -G rsa -u ek.pub
tpm2 createak -C 0x81010009 -c ak.ctx -G rsa -g sha256 -s rsassa -u ak.pub \
-n ak.name -p akpass> ak.out
file_size=`ls -l ak.name | awk {'print $5'}`
loaded_key_name=`cat ak.name | xxd -p -c $file_size`
tpm2 readpublic -c 0x81010009 -o ek.pem -f pem -Q
echo "12345678" | tpm2 makecredential -Q -u ek.pem -s - -n $loaded_key_name \
-o mkcred.out -G rsa
