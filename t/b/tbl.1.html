Nombre

tbl - preparar tablas para documentos de groff

Sinopsis

tbl [-C] [archivo ...]
tbl --ayuda
tbl -v
tbl --version

Descripción

La implementación GNU de tbl forma parte del sistema de formateo de documentos groff(1). tbl es un preprocesador de troff(1) que traduce descripciones de tablas incrustadas en archivos de entrada de roff(7) al lenguaje entendido por troff. Copia el contenido de cada archivo al flujo de salida estándar, excepto que las líneas entre .TS y .TE se interpretan como descripciones de tabla. Si bien la sintaxis de entrada de GNU tbl es altamente compatible con AT&T tbl, la salida que produce GNU tbl no puede ser procesada por AT&T troff; se debe usar GNU troff (o un troff que implemente cualquier extensión GNU empleada). Normalmente, el usuario no ejecuta tbl directamente, sino que lo invoca especificando la opción -t a groff(1). Si no se dan operandos de archivo en la línea de comandos, o si archivo es “-”, tbl lee el flujo de entrada estándar.

Resumen

tbl espera encontrar descripciones de tablas entre líneas de entrada que comienzan con .TS (inicio de tabla) y .TE (fin de tabla). Cada una de estas regiones de tabla encierra una o más descripciones de tabla. Dentro de una región de tabla, las descripciones de tabla más allá de la primera deben ir precedidas por una línea de entrada que comience con .T&. Este mecanismo no inicia una nueva región de tabla; todas las descripciones de tabla se tratan como parte de su encierro .TS/.TE, incluso si están enmarcadas o tienen encabezados de columna que se repiten en páginas subsiguientes (ver más abajo).

(Los usuarios experimentados de roff deben observar que tbl no es un intérprete del lenguaje roff: se debe usar el carácter de control predeterminado, y no se permiten espacios ni tabulaciones entre el carácter de control y el nombre de la macro. Estos tokens de entrada de tbl permanecen tal cual en la salida, donde se convierten en llamadas a macros ordinarias. Los paquetes de macros a menudo definen macros TS, T& y TE para manejar problemas de ubicación de tablas en la página. tbl produce código groff para definir estas macros como vacías si sus definiciones no existen cuando el formateador encuentra una región de tabla.)

Cada región de tabla puede comenzar con opciones de región, y debe contener una o más definiciones de tabla; cada definición de tabla contiene una especificación de formato seguida de una o más líneas de entrada (filas) de entradas. Estas entradas comprenden los datos de la tabla.

Opciones de región

La línea inmediatamente posterior al token .TS puede especificar opciones de región, palabras clave que influyen en la interpretación o renderización de la región en su conjunto o de todas las entradas de tabla dentro de ella indiscriminadamente. Deben estar separadas por comas, espacios o tabulaciones. Aquellas que requieren un argumento entre paréntesis permiten espacios y tabulaciones entre el nombre de la opción y el paréntesis de apertura. Las opciones se acumulan y no pueden desestablecerse dentro de una región una vez declaradas; si se repite una opción que toma un parámetro, la última ocurrencia controla. Si están presentes, el conjunto de opciones de región debe terminar con un punto y coma (;).

Cualquiera de las opciones de región allbox, box, doublebox, frame y doubleframe hace que una tabla sea “encuadrada” para el propósito de discusiones posteriores.

allbox
Encierra cada entrada de tabla en un recuadro; implica box.
box
Encierra toda la región de tabla en un recuadro. Como extensión de GNU, también se reconoce el nombre de opción alternativo frame.
center
Centra la región de tabla con respecto a la sangría y longitud de línea actuales; el valor predeterminado es alinearlo a la izquierda. Como extensión de GNU, también se reconoce el nombre de opción alternativo centre.
decimalpoint(c)
Reconoce el carácter c como separador decimal en columnas que utilizan el clasificador N (numérico) (ver subsección “Clasificadores de columna” a continuación). Esta es una extensión de GNU.
delim(xy)
Reconoce los caracteres x y y como delimitadores de inicio y fin, respectivamente, para la entrada de eqn(1), e ignora la entrada entre ellos. x y y no necesitan ser distintos.
doublebox
Encierra toda la región de tabla en un doble recuadro; implica box. Como extensión de GNU, también se reconoce el nombre de opción alternativo doubleframe.
expand
Expande la tabla horizontalmente para llenar el espacio disponible (longitud de línea menos sangría) aumentando la separación de columnas. Ordinariamente, una tabla se hace solo tan ancha como sea necesario para acomodar los anchos de sus entradas y sus separaciones de columnas (ya sean especificadas o predeterminadas). Cuando expand se aplica a una tabla que excede el espacio horizontal disponible, la separación de columnas se reduce tanto como sea necesario (incluso a cero). tbl produce entrada groff que emite un diagnóstico si ocurre tal compresión. El modificador de columna x (ver más abajo) anula esta opción.
linesize(n)
Dibuja líneas o reglas (por ejemplo, de box) con un grosor de n puntos. El valor predeterminado es el tamaño de tipo actual cuando comienza la región. Esta opción se ignora en dispositivos terminales.
nokeep
No usar derivaciones de roff para gestionar saltos de página. Normalmente, tbl las emplea para evitar romper una página dentro de una fila de tabla. Este uso a veces puede interactuar mal con el uso propio de derivaciones por parte de los paquetes de macros (cuando se usan notas al pie, por ejemplo). Esta es una extensión de GNU.
nospaces
Ignorar espacios iniciales y finales en las entradas de tabla. Esta es una extensión de GNU.
nowarn
Suprimir mensajes de diagnóstico producidos en tiempo de formateo de documentos cuando las longitudes de línea o página son inadecuadas para contener una fila de tabla. Esta es una extensión de GNU.
tab(c)
Usar el carácter c en lugar de una tabulación para separar las entradas en una fila de datos de tabla.

Especificación de formato de tabla

La especificación de formato de tabla es obligatoria: determina el número de columnas en la tabla y dirige cómo se deben componer las entradas dentro de ella. La especificación de formato es una serie de descriptores de columna. Cada descriptor codifica un clasificador seguido de cero o más modificadores. Los clasificadores son letras (reconocidas sin distinguir mayúsculas de minúsculas) o símbolos de puntuación; los modificadores consisten en letras o números, o comienzan con ellos. Los espacios, tabulaciones, saltos de línea y comas separan los descriptores. Los saltos de línea y las comas son especiales; aplican los descriptores siguientes a una fila posterior de la tabla. (Esto permite que los encabezados de columna se centren o se pongan en negrita mientras que las entradas de tabla para los datos no lo estén, por ejemplo). Denominamos a este grupo resultante de descriptores de columna una definición de fila. Dentro de una definición de fila, la separación entre los descriptores de columna (por espacios o tabulaciones) es a menudo opcional; solo algunos modificadores, descritos a continuación, hacen que la separación sea necesaria.

Cada descriptor de columna comienza con un clasificador obligatorio, un carácter que selecciona entre varios arreglos. Algunos determinan el posicionamiento de las entradas de tabla dentro de una celda rectangular: centrado, alineado a la izquierda, numérico (alineado a un separador decimal configurable), y así sucesivamente. Except for “|”, any classifier can be followed by one or more modifiers; some of these accept an argument, which in GNU tbl can be parenthesized. Modifiers select fonts, set the type size, and perform other tasks described below.

The format specification can occupy multiple input lines, but must conclude with a dot “.” followed by a newline. Each row definition is applied in turn to one row of the table. The last row definition is applied to rows of table data in excess of the row definitions.

For clarity in this document's examples, we shall write classifiers in uppercase and modifiers in lowercase. Thus, “CbCb,LR.” defines two rows of two columns. The first row's entries are centered and boldfaced; the second and any further rows' first and second columns are left- and right-aligned, respectively.

The row definition with the most column descriptors determines the number of columns in the table; any row definition with fewer is implicitly extended on the right-hand side with L classifiers as many times as necessary to make the table rectangular.

Clasificadores de columna

The L, R, and C classifiers are the easiest to understand and use.

A, a
Center longest entry in this column, left-align remaining entries in the column with respect to the centered entry, then indent all entries by one en. Such “alphabetic” entries (hence the name of the classifier) can be used in the same column as L-classified entries, as in “LL,AR.”. The A entries are often termed “sub-columns” due to their indentation.
C, c
Center entry within the column.
L, l
Left-align entry within the column.
N, n
Numerically align entry in the column. tbl aligns columns of numbers vertically at the units place. If multiple decimal separators are adjacent to a digit, it uses the rightmost one for vertical alignment. If there is no decimal separator, the rightmost digit is used for vertical alignment; otherwise, tbl centers the entry within the column. The roff dummy character \& in an entry marks the glyph preceding it (if any) as the units place; if multiple instances occur in the data, the leftmost is used for alignment.
If N-classified entries share a column with L or R entries, tbl centers the widest N entry with respect to the widest L or R entry, preserving the alignment of N entries with respect to each other.
The appearance of eqn equations within N-classified columns can be troublesome due to the foregoing textual scan for a decimal separator. Use the delim region option to make tbl ignore the data within eqn delimiters for that purpose.
R, r
Right-align entry within the column.
S, s
Span previous entry on the left into this column.
^
Span entry in the same column from the previous row into this row.
_, -
Replace table entry with a horizontal rule. An empty table entry is expected to correspond to this classifier; if data are found there, tbl issues a diagnostic message.
=
Replace table entry with a double horizontal rule. An empty table entry is expected to correspond to this classifier; if data are found there, tbl issues a diagnostic message.
|
Place a vertical rule (line) on the corresponding row of the table (if two of these are adjacent, a double vertical rule). This classifier does not contribute to the column count and no table entries correspond to it. A | to the left of the first column descriptor or to the right of the last one produces a vertical rule at the edge of the table; these are redundant (and ignored) in boxed tables.

To change the table format within a tbl region, use the .T& token at the start of a line. It is followed by a format specification and table data, but not region options. The quantity of columns in a new table format thus introduced cannot increase relative to the previous table format; in that case, you must end the table region and start another. If that will not serve because the region uses box options or the columns align in an undesirable manner, you must design the initial table format specification to include the maximum quantity of columns required, and use the S horizontal spanning classifier where necessary to achieve the desired columnar alignment.

Attempting to horizontally span in the first column or vertically span on the first row is an error. Non-rectangular span areas are also not supported.

Modificadores de columna

Any number of modifiers can follow a column classifier. Arguments to modifiers, where accepted, are case-sensitive. If the same modifier is applied to a column specifier more than once, or if conflicting modifiers are applied, only the last occurrence has effect. The modifier x is mutually exclusive with e and w, but e is not mutually exclusive with w; if these are used in combination, x unsets both e and w, while either e or w overrides x.

b, B
Typeset entry in boldface, abbreviating f(B).
d, D
Align a vertically spanned table entry to the bottom (“down”), instead of the center, of its range. This is a GNU extension.
e, E
Equalize the widths of columns with this modifier. The column with the largest width controls. This modifier sets the default line length used in a text block.
f, F
Select the typeface for the table entry. This modifier must be followed by a font or style name (one or two characters not starting with a digit), font mounting position (a single digit), or a name or mounting position of any length in parentheses. The last form is a GNU extension. (The parameter corresponds to that accepted by the troff ft request.) A one-character argument not in parentheses must be separated by one or more spaces or tabs from what follows.
i, I
Typeset entry in an oblique or italic face, abbreviating f(I).
m, M
Call a groff macro before typesetting a text block (see subsection “Text blocks” below). This is a GNU extension. This modifier must be followed by a macro name of one or two characters or a name of any length in parentheses. A one-character macro name not in parentheses must be separated by one or more spaces or tabs from what follows. The named macro must be defined before the table region containing this column modifier is encountered. The macro should contain only simple groff requests to change text formatting, like adjustment or hyphenation. The macro is called after the column modifiers b, f, i, p, and v take effect; it can thus override other column modifiers.
p, P
Set the type size for the table entry. This modifier must be followed by an integer n with an optional leading sign. If unsigned, the type size is set to n scaled points. Otherwise, the type size is incremented or decremented per the sign by n scaled points. The use of a signed multi-digit number is a GNU extension. (The parameter corresponds to that accepted by the troff ps request.) If a type size modifier is followed by a column separation modifier (see below), they must be separated by at least one space or tab.
t, T
Align a vertically spanned table entry to the top, instead of the center, of its range.
u, U
Move the column up one half-line, “staggering” the rows. This is a GNU extension.
v, V
Set the vertical spacing to be used in a text block. This modifier must be followed by an integer n with an optional leading sign. If unsigned, the vertical spacing is set to n points. Otherwise, the vertical spacing is incremented or decremented per the sign by n points. The use of a signed multi-digit number is a GNU extension. (This parameter corresponds to that accepted by the troff vs request.) If a vertical spacing modifier is followed by a column separation modifier (see below), they must be separated by at least one space or tab.
w, W
Set the column's minimum width. This modifier must be followed by a number, which is either a unitless integer, or a roff horizontal measurement in parentheses. Parentheses are required if the width is to be followed immediately by an explicit column separation (alternatively, follow the width with one or more spaces or tabs). If no unit is specified, ens are assumed. This modifier sets the default line length used in a text block.
x, X
Expand the column. After computing the column widths, distribute any remaining line length evenly over all columns bearing this modifier. Applying the x modifier to more than one column is a GNU extension. This modifier sets the default line length used in a text block.

Nombre

tbl - formato de tabla

Sinopsis

tbl [opciones...] [-]

Descripción

El programa tbl se usa para dar formato a tablas en documentos groff(1). Preprocesa un documento, formateando las tablas definidas por los tokens .TS (inicio de tabla) y .TE (fin de tabla).

Los tokens de inicio y fin de tabla pueden ir seguidos de texto que describe el formato de la tabla. El texto dentro de los tokens .TS y .TE es interpretado por tbl, y el texto fuera de estos tokens es pasado sin cambios al procesador posterior (como groff(1)).

El formato de la tabla especifica la alineación de las columnas, el espaciado y las reglas (líneas horizontales y verticales). Los datos de la tabla se colocan entre la descripción del formato y el token .TE.

tbl puede manejar tablas de varias páginas, con encabezados repetidos y bordes. Admite diferentes clasificadores de columna para controlar la alineación y el espaciado del texto dentro de cada celda.

El procesador tbl puede interpretar secuencias de escape especiales para formatear el texto dentro de las celdas de la tabla, como el uso de negrita, cursiva y el tabulador.

Los modificadores de columna como l, c, r, s y n controlan la alineación del texto en la celda. l alinea a la izquierda, c al centro, r a la derecha, s estira el texto para llenar el ancho de la columna, y n alinea numéricamente (por el punto decimal).

Los modificadores de línea como all, lin, rcol, bot y ar controlan la colocación de las líneas horizontales. all dibuja líneas alrededor de todas las celdas, lin dibuja una línea horizontal en la parte superior, rcol dibuja una línea horizontal encima de la fila actual, bot dibuja una línea horizontal en la parte inferior y ar dibuja una línea horizontal encima de la fila actual y alrededor de todas las celdas.

El separador de columnas puede ser especificado con tab=.... El carácter por defecto es el tabulador. Las líneas verticales se pueden especificar con | en la descripción del formato.

Los modificadores de ancho de columna, como W, pueden ser utilizados para especificar el ancho exacto de una columna. El modificador _ se puede utilizar para indicar una columna vacía o una línea horizontal. Los modificadores ^ y ~ se utilizan para la alineación vertical.

Las secuencias de escape como \f[I] para cursiva o \f[B] para negrita se pueden usar dentro de las celdas de la tabla. El caracter de tabulador \t se utiliza para separar campos dentro de una celda si el delimitador de columna es un tabulador.

Los números de página y los marcadores de línea se manejan automáticamente. tbl también soporta la definición de macros para simplificar la entrada de tablas complejas. La aritmética básica puede ser realizada dentro de las tablas usando secuencias de escape específicas después de la aplicable aritmética.

Opciones

--help muestra un mensaje de uso, mientras que -v y --version muestran información de la versión; todo sale después.

-C
Habilita el modo de compatibilidad AT&T: reconoce .TS y .TE incluso cuando van seguidos de un carácter distinto de espacio o nueva línea. Además, interpreta la secuencia de escape de líder no interpretada \a.

Limitaciones

Las tablas de varias páginas, si están enmarcadas y/o si desea que sus encabezados de columna se repitan después de los saltos de página, requieren soporte en el momento en que se formatea el documento. Una convención para dicho soporte ha surgido en paquetes de macros como ms, mm y me. Para usarlo, siga el token .TS con un espacio y luego "H"; esto será interpretado por el formateador como una llamada a macro TS con un argumento H. Luego, dentro de los datos de la tabla, llame a la macro TH; esto informa al paquete de macros dónde terminan los encabezados. Si su tabla no tiene tales filas de encabezado, o no desea su repetición, llame a TH inmediatamente después de la especificación del formato de la tabla. Si una tabla de varias páginas está enmarcada o tiene encabezados de columna repetidos, no la encierre con macros de mantener/liberar, ni la desvíe de ninguna otra manera. Además, la solicitud bp no causará un salto de página en una tabla "TS H". Defina una macro para envolver bp: invóquela normalmente si no hay una desviación actual. De lo contrario, pase la llamada a macro a la desviación circundante usando la secuencia de escape de línea transparente \!; esto "hará burbujear" el salto de página al dispositivo de salida. Vea la sección "Ejemplos" a continuación para una demostración.

Las reglas horizontales dobles no son compatibles con grotty(1); se utilizan reglas simples en su lugar. grotty también ignora los movimientos de media línea, por lo que el modificador de columna u no tiene ningún efecto. En dispositivos de terminal ("modo nroff"), las reglas horizontales y los bordes de caja ocupan una vee completa de espacio; esta cantidad se duplica para las tablas doublebox. Las tablas que utilizan estas características requieren así más espacio vertical en modo nroff que en modo troff: escriba las solicitudes ne en consecuencia. Las reglas verticales entre columnas se dibujan en el espacio entre columnas en modo nroff; el uso de reglas verticales dobles y/o la reducción de la separación de columnas por debajo del valor predeterminado puede hacerlas feas o sobreescribirlas con datos de tabla.

Un bloque de texto dentro de una tabla debe poder caber en una sola página.

Usar \a para poner líderes en las entradas de tabla no funciona en GNU tbl, excepto en modo de compatibilidad. Este es un comportamiento correcto: \a es un líder *no interpretado*. Aún puede usar el carácter de líder de roff (Control+A) o definir una cadena para usar \a como fue diseñado: para ser interpretado solo en modo de copia.

.ds a \a
.TS
box center tab(;);
Lw(2i)0 L.
Population\*a;6,327,119
.TE
Población? 6.327.119

Un | inicial y/o final en una especificación de formato, como "|LCR|.", produce un espacio de en entre las reglas verticales y el contenido de las columnas adyacentes. Si no se desea dicho espacio (de modo que la regla toque el contenido), puede introducir columnas "simuladas" con separación cero y entradas de tabla vacías antes y/o después.

.TS
center tab(#);
R0|L C R0|L.
_
#levulosa#glucosa#dextrosa#
_
.TE

Estas columnas simuladas tienen ancho cero y por lo tanto son invisibles; desafortunadamente, generalmente no funcionan como se espera en dispositivos de terminal.

Algunas características de tbl no se pueden ilustrar en el entorno limitado de una página man portátil.

Podemos definir una macro fuera de una región de tbl que podemos llamar desde dentro de ella para causar un salto de página dentro de una tabla enmarcada de varias páginas. Puede elegir un nombre diferente; asegúrese de cambiar ambas ocurrencias de "BP".

.de BP
.  ie '\\n(.z'' .bp \\$1
.  el \!.BP \\$1
