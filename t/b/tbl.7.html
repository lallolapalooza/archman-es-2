TBL(7) Manual de Información Miscelánea TBL(7)

NOMBRE

tbl — referencia del lenguaje tbl para mandoc

DESCRIPCIÓN

El lenguaje tbl formatea tablas. Se utiliza dentro de las páginas mdoc(7) y man(7). Este manual describe el subconjunto del lenguaje tbl aceptado por la utilidad mandoc(1).

Cada tabla se inicia con una macro roff(7) TS, consiste en como máximo una línea de Opciones, una o más líneas de Diseño, una o más líneas de Datos, y termina con una macro TE. Toda la entrada debe ser ASCII de 7 bits.

Opciones

Si la primera línea de entrada de una tabla termina con un punto y coma, contiene opciones no sensibles a mayúsculas y minúsculas separadas por espacios, tabuladores o comas. De lo contrario, se interpreta como la primera línea de Diseño.

Las siguientes opciones están disponibles. Algunas de ellas requieren argumentos entre paréntesis:

allbox
Dibuja una caja de línea simple alrededor de cada celda de la tabla.
box
Dibuja una caja de línea simple alrededor de la tabla. Para compatibilidad con GNU, esto también puede ser invocado con frame.
center
Centra la tabla en lugar de ajustarla a la izquierda. Para compatibilidad con GNU, esto también puede ser invocado con centre.
decimalpoint
Usa el argumento de un solo carácter como punto decimal con la clave de diseño n. Esta es una extensión de GNU.
delim
Usa los dos caracteres del argumento como delimitadores de eqn(7). Actualmente no soportado.
doublebox
Dibuja una caja de doble línea alrededor de la tabla. Para compatibilidad con GNU, esto también puede ser invocado con doubleframe.
expand
Aumenta el ancho de la tabla a la longitud de línea actual. Actualmente ignorado.
linesize
Dibuja líneas con el tamaño de punto dado por el argumento de entero sin signo. Actualmente ignorado.
nokeep
Permite saltos de página dentro de la tabla. Esta es una extensión de GNU y actualmente ignorada.
nospaces
Ignora los espacios iniciales y finales en las celdas de datos. Esta es una extensión de GNU.
nowarn
Suprime advertencias sobre tablas que exceden la longitud de línea actual. Esta es una extensión de GNU y actualmente ignorada.
tab
Usa el argumento de un solo carácter como delimitador entre celdas de datos. Por defecto, se usa el carácter de tabulación horizontal.

Diseño

El diseño de la tabla sigue una línea de Opciones o una macro roff(7) TS o T&. Cada línea de diseño especifica cómo se formatea una línea de Datos. La última línea de diseño termina con un punto. También se aplica a todas las líneas de datos restantes. Se pueden unir varias líneas de diseño con comas en una sola línea física de entrada.

Cada línea de diseño consiste en una o más especificaciones de celda de diseño, separadas opcionalmente por espacios en blanco. Los siguientes caracteres clave, no sensibles a mayúsculas y minúsculas, inician una nueva especificación de celda:

c
Centra la cadena en esta celda.
r
Justifica la cadena a la derecha en esta celda.
l
Justifica la cadena a la izquierda en esta celda.
n
Justifica un número alrededor de su último punto decimal. Si no se encuentra un punto decimal en el número, se asume que está al final del número.
s
Cruce horizontal de columnas desde la última celda de diseño que no sea s. Es un error si un cruce de columna sigue a una celda _ o =, o viene primero en una línea de diseño. La celda combinada en su conjunto consume solo una celda de la línea de datos correspondiente.
a
Justifica una cadena a la izquierda y rellena con un espacio.
^
Cruce vertical de filas desde la última celda de diseño que no sea ^. Es un error invocar un cruce vertical en la primera línea de diseño. A diferencia de un cruce horizontal, un cruce vertical consume una celda de datos y descarta el contenido.
_
Dibuja una línea horizontal simple en esta celda. Esto consume una celda de datos y descarta el contenido. También puede ser invocado con -.
=
Dibuja una línea horizontal doble en esta celda. Esto consume una celda de datos y descarta el contenido.

Cada clave de celda puede ir seguida de cero o más de los siguientes modificadores, no sensibles a mayúsculas y minúsculas:

b
Usa una fuente en negrita para el contenido de esta celda.
d
Mueve el contenido hacia abajo a la última fila de este cruce vertical. Actualmente ignorado.
e
Hace que esta columna sea más ancha para que coincida con el ancho máximo de cualquier otra columna que también tenga el modificador e.
f
Los siguientes uno o dos caracteres seleccionan la fuente a usar para esta celda. Los nombres de fuente de un carácter deben ir seguidos de un espacio o un punto. Consulte el manual de roff(7) para conocer los nombres de fuente admitidos.
i
Usa una fuente cursiva para el contenido de esta celda.
m
Especifica una macro de inicio de celda. Esta es una extensión de GNU y actualmente no soportada.
p
Establece el tamaño de punto al siguiente argumento sin signo, o lo cambia en el siguiente argumento con signo. Actualmente ignorado.
v
Establece el espaciado de línea vertical al siguiente argumento sin signo, o lo cambia en el siguiente argumento con signo. Actualmente ignorado.
t
No centra verticalmente el contenido en este cruce vertical, déjalo en la fila superior. Actualmente ignorado.
u
Mueve el contenido de la celda hacia arriba en medio de una fila de tabla. Actualmente ignorado.
w
Especifica un ancho mínimo de columna.
x
Después de determinar el ancho de todas las demás columnas, distribuye el resto de la longitud de línea entre todas las columnas que tengan el modificador x.
z
No uses esta celda para determinar el ancho de esta columna.
|
Dibuja una línea vertical simple a la derecha de esta celda.
||
Dibuja una línea vertical doble a la derecha de esta celda.

tbl(7) — Arch Linux manual pages

NAME

tbl — manual text formatter table

DESCRIPTION

The tbl utility is a preprocessor for troff(1) that allows text to be formatted as tables. It is typically used within the context of mdoc(7) and man(7) manual pages.

A tbl environment is delimited by the tbl(1) format delimiters .TS and .TE.

The first line after .TS is the Layout line. It defines the overall table formatting, including column separation, alignment, and line drawing. The remaining lines describe the table's data.

Layout

The Layout line is a whitespace-separated list of format specifiers. Each specifier corresponds to a column and describes its formatting, alignment, and the type of vertical line separating it from the next column. The specifiers are:

l
Left-justified text.
r
Right-justified text.
c
Centered text.
C
Centered text, using the center macro.
s
Spanned column. This column spans across subsequent columns.
a
Left-justified text, using the left macro.
d
Top-justified text.
j
Full justification (ragged right and left).
n
Normal text, used for numerical data, aligned at the decimal point.
^
Spanned row. This row spans across subsequent rows.
_
Draw a horizontal line across the current cell.
=
Draw a double horizontal line across the current cell.
|
Draw a vertical line between the current column and the next column.
:
Draw a dotted vertical line between the current column and the next column.

Numeric arguments can be appended to the line-drawing specifiers. For example, _3 or =2 draws a line of thickness 3 or 2 units, respectively. A vertical line specifier may be followed by a decimal digit, specifying a minimum spacing in units of n between this column and the next column to the right. The default is 3. If there is a vertical line, it is drawn inside the spacing.

Data

The data section follows the last Layout line. Each data line consists of one or more data cells, delimited by tab characters.

If a data cell contains only the two bytes ‘^’, the cell above spans to this row, as if the layout specification of this cell were ^.

If a data cell contains only the single character ‘_’ or ‘=’, a single or double horizontal line is drawn across the cell, joining its neighbours. If a data cell contains only the two character sequence ‘\_’ or ‘\=’, a single or double horizontal line is drawn inside the cell, not joining its neighbours. If a data line contains nothing but the single character ‘_’ or ‘=’, a horizontal line across the whole table is inserted without consuming a layout row.

In place of any data cell, a text block can be used. It starts with T{ at the end of a physical input line. Input line breaks inside the text block neither end the text block nor its data cell. It only ends if T} occurs at the beginning of a physical input line and is followed by an end-of-cell indicator. If the T} is followed by the end of the physical input line, the text block, the data cell, and the data line ends at this point. If the T} is followed by the tab character, only the text block and the data cell end, but the data line continues with the data cell following the tab character. If T} is followed by any other character, it does not end the text block, which instead continues to the following physical input line.

COMPATIBILITY

The mandoc(1) implementation of tbl doesn't support mdoc(7) and man(7) macros and eqn(7) equations inside tables.

HISTORY

The tbl utility, a preprocessor for troff, was originally written by M. E. Lesk at Bell Labs in 1975. The GNU reimplementation of tbl, part of the groff package, was released in 1990 by James Clark. A standalone tbl implementation was written by Kristaps Dzonsons in 2010. This formed the basis of the implementation that first appeared in OpenBSD 4.9 as a part of the mandoc(1) utility.

BUGS

In -T utf8 output mode, heavy lines are drawn instead of double lines. This cannot be improved because the Unicode standard only provides an incomplete set of box drawing characters with double lines, whereas it provides a full set of box drawing characters with heavy lines. It is unlikely this can be improved in the future because the box drawing characters are already marked in Unicode as characters intended only for backward compatibility with legacy systems, and their use is not encouraged. So it seems unlikely that the missing ones might get added in the future.
