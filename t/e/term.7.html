NOMBRE

term - convenciones para nombrar tipos de terminal

DESCRIPCIÓN

La variable de entorno TERM normalmente debe contener el nombre del tipo de terminal, consola o dispositivo de visualización que esté utilizando. Esta información es crítica para todos los programas orientados a pantalla, incluyendo su editor y gestor de correo.

Un valor predeterminado de TERM será establecido por línea por /etc/inittab (por ejemplo, Unix similares a System-V) o /etc/ttys (Unix BSD). Esto será casi siempre suficiente para las consolas de estaciones de trabajo y microcomputadoras.

Si usa una línea de acceso telefónico, el tipo de dispositivo conectado a ella puede variar. Los sistemas Unix más antiguos preconfiguran un tipo de terminal muy simple como “dumb” o “dialup” en las líneas de acceso telefónico. Los más nuevos pueden preconfigurar “vt100”, reflejando la prevalencia de terminales compatibles con DEC VT100 y emuladores de computadoras personales.

Los telnets modernos pasan su variable de entorno TERM desde el lado local al remoto. Pueden surgir problemas si la entrada terminfo o termcap remota para su tipo no es compatible con la suya, pero esta situación es rara y casi siempre se puede evitar exportando explícitamente “vt100” (suponiendo que realmente está utilizando una consola, terminal o emulador de terminales que sea un superconjunto de VT100).

En cualquier caso, usted es libre de anular la configuración del sistema TERM a su gusto en su perfil de shell. La utilidad tset(1) puede ser de ayuda; puede darle un conjunto de reglas para deducir o solicitar un tipo de terminal basándose en el dispositivo tty y la velocidad en baudios.

Establecer su propio valor de TERM también puede ser útil si ha creado una entrada personalizada que incorpora opciones (como campana visual o video inverso) que desea anular el tipo predeterminado del sistema para su línea.

Las descripciones de tipos de terminal se almacenan como archivos de datos de capacidades debajo de /usr/share/terminfo. Para ver una lista de todos los nombres de terminales reconocidos por el sistema, ejecute:


toe | more

desde su shell. Estos archivos de capacidades están en un formato binario optimizado para la velocidad de recuperación (a diferencia del antiguo formato de texto termcap que reemplazan); para examinar una entrada, debe usar el comando infocmp(1M). Invoquelo de la siguiente manera:


infocmp nombre_entrada

donde nombre_entrada es el nombre del tipo que desea examinar (y el nombre de su archivo de capacidades en el subdirectorio de /usr/share/terminfo nombrado por su primera letra). Este comando vuelca un archivo de capacidades en el formato de texto descrito por terminfo(5).

La primera línea de una descripción de terminfo(5) da los nombres por los cuales terminfo conoce un terminal, separados por caracteres “|” (barra vertical) con el último campo de nombre terminado por una coma. El primer campo de nombre es el nombre primario del tipo, y es el que se debe usar al establecer TERM. El último campo de nombre (si es distinto del primero) es en realidad una descripción del tipo de terminal (puede contener espacios; los otros deben ser palabras únicas). Los campos de nombre entre el primero y el último (si están presentes) son alias para el terminal, generalmente nombres históricos conservados por compatibilidad.

Existen algunas convenciones sobre cómo elegir nombres primarios de terminal que ayudan a mantenerlos informativos y únicos. Aquí hay una guía paso a paso para nombrar terminales que también explica cómo analizarlos:

Primero, elija un nombre raíz. La raíz consistirá en una letra minúscula seguida de hasta siete letras minúsculas o dígitos. Debe evitar el uso de caracteres de puntuación en los nombres raíz, ya que se utilizan e interpretan como nombres de archivo y los meta-caracteres del shell (como !, $, *, ?, etc.) incrustados en ellos pueden causar un comportamiento extraño y poco útil. La barra inclinada (/), o cualquier otro carácter que pueda ser interpretado por el sistema de archivos de alguien (\\, $, [, ]), es especialmente peligrosa (terminfo es independiente de la plataforma, y elegir nombres con caracteres especiales podría dificultar la vida a los usuarios de un futuro puerto). El carácter de punto (.) es relativamente seguro siempre que haya como máximo uno por nombre raíz; algunos nombres históricos de terminfo lo utilizan.

El nombre raíz para un tipo de consola de terminal o estación de trabajo casi siempre debe comenzar con un prefijo de proveedor (como hp para Hewlett-Packard, wy para Wyse, o att para terminales AT&T), o un nombre común de la línea de terminales (vt para la serie VT de terminales de DEC, o sun para consolas de estaciones de trabajo Sun Microsystems, o regent para la serie ADDS Regent. Puede listar el árbol de terminfo para ver qué prefijos ya están en uso común. El prefijo del nombre raíz debe ir seguido, cuando sea apropiado, por un número de modelo; por lo tanto, vt100, hp2621, wy50.

El nombre raíz para un tipo de consola de PC-Unix debe ser el nombre del sistema operativo, es decir, linux, bsdos, freebsd, netbsd. ¡No debe ser console ni ningún otro genérico que pueda causar confusión en un entorno multiplataforma! Si sigue un número de modelo, este debe indicar el nivel de versión del sistema operativo o el nivel de versión del controlador de consola.

El nombre raíz para un emulador de terminal (suponiendo que no encaje en uno de los tipos estándar ANSI o vt100) debe ser el nombre del programa o una abreviatura fácilmente reconocible del mismo (es decir, versaterm, ctrm).

Después del nombre raíz, puede agregar cualquier número razonable de sufijos de características separados por guiones.

2p
Tiene dos páginas de memoria. Igualmente 4p, 8p, etc.
mc
Cookie mágica. Algunos terminales (notablemente Wyses antiguos) solo pueden soportar un atributo sin pérdida de cookie mágica. Su entrada base se combina generalmente con otra que tiene este sufijo y usa cookies mágicas para soportar múltiples atributos.
-am
Habilita margen automático (desbordamiento del margen derecho).
-m
Modo mono - suprime el soporte de color.
-na
Sin teclas de flecha - termcap ignora las teclas de flecha que realmente están en el terminal, para que el usuario pueda usar las teclas de flecha localmente.
-nam
Sin margen automático - suprime la capacidad am.
-nl
Sin etiquetas - suprime las etiquetas suaves.
-nsl
Sin línea de estado - suprime la línea de estado.
-pp
Tiene un puerto de impresora que se utiliza.
-rv
Terminal en modo de video inverso (negro sobre blanco).
-s
Habilita la línea de estado.
-vb
Usa campana visible (parpadeo) en lugar de pitido.
-w
Ancho; el terminal está en modo de 132 columnas.

Convencionalmente, si el tipo de su terminal es una variante destinada a especificar una altura de línea, ese sufijo debe ir primero. Por lo tanto, para un hipotético terminal FuBarCo modelo 2317 en modo de 30 líneas con video inverso, la mejor forma sería fubar-30-rv (en lugar de, por ejemplo, “fubar-rv-30”).

Los tipos de terminal que se escriben no como entradas independientes, sino como componentes para ser insertados en otras entradas a través de capacidades use, se distinguen por el uso de signos más incrustados en lugar de guiones.

Los comandos que utilizan un tipo de terminal para controlar la visualización a menudo aceptan una opción -T que acepta un argumento de nombre de terminal. Dichos programas deben recurrir a la variable de entorno TERM cuando no se especifica ninguna opción -T.

ARCHIVOS

/usr/share/terminfo
base de datos de descripciones de terminales compilada
/etc/inittab
inicialización de línea tty (Unix tipo AT&T)
/etc/ttys
inicialización de línea tty (Unix tipo BSD)

PORTABILIDAD

Para una máxima compatibilidad con los Unix System V más antiguos, los nombres y alias deben ser únicos dentro de los primeros 14 caracteres.

VER TAMBIÉN

NAME

term - terminal characteristics

DESCRIPTION

The term macro package is used by programs that need to know the characteristics of the terminal being used. The term package defines the TERMINFO database, which contains descriptions of terminals. Each description specifies the capabilities of a particular terminal, such as the number of rows and columns, the character set, and the control sequences for various functions (e.g., clearing the screen, moving the cursor, changing colors).

The TERMINFO database is located in the directory /usr/share/terminfo. Each terminal description is stored in a file named after the terminal type, which is typically determined by the TERM environment variable. For example, if the TERM variable is set to xterm, the program will look for the xterm terminal description in the TERMINFO database.

Programs that use the TERMINFO database typically use the terminfo library, which provides functions for accessing terminal capabilities. These functions allow programs to query the TERMINFO database for specific capabilities and to use them to control the terminal.

FILES

/usr/share/terminfo
Directory containing the TERMINFO database.

PORTABILITY

The TERMINFO database is intended to be portable across different systems. However, some terminal descriptions may be specific to certain systems or hardware.
