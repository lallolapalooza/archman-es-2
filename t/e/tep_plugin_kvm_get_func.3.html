NOMBRE

tep_plugin_kvm_get_func, tep_plugin_kvm_put_func - Añadir nombre de función para el puntero de instrucción del plugin kvm

SINOPSIS

#include <event-parse.h>
const char *tep_plugin_kvm_get_func(struct tep_event *event,
                                    struct tep_record *record,
                                    unsigned long long *paddr);
void tep_plugin_kvm_put_func(const char *func);

DESCRIPCIÓN

Las funciones tep_plugin_kvm_get_func() y tep_plugin_kvm_put_func() no deben ser llamadas por una aplicación, sino definidas por ella.

Ciertos eventos (como kvm_exit y kvm_entry) tienen el puntero de instrucción de dónde, dentro del huésped, el contexto cambió de huésped a anfitrión. Como el anfitrión solo conoce el puntero de instrucción y no tiene información sobre a qué función del huésped pertenece ese puntero de instrucción, solo puede imprimir la dirección.

Pero la aplicación puede tener más información sobre el huésped y saber dónde estaba el huésped cuando ocurrió la salida, e incluso conocer el nombre de la función de esa dirección.

El plugin KVM para libtraceevent se llama en estos eventos y luego llama a tep_plugin_kvm_get_func() para ver si esa función puede resolver la dirección del puntero de instrucción a un nombre de función real. Si la respuesta no es NULL, imprimirá la función en la salida de ese evento.

Estas funciones están definidas actualmente como funciones débiles dentro del plugin, para no requerir que se definan en otro lugar. Para que una aplicación anule la función débil, deberá definir la función en un archivo que se compile con -rdynamic. Esto indicará al enlazador dinámico que examine ese archivo objeto y utilice los nombres de las funciones para resolver funciones débiles en otros objetos compartidos (en este caso, el objeto compartido del plugin KVM).

Si la aplicación define tep_plugin_kvm_get_func(), debe usar el prototipo anterior. El event contendrá el evento KVM que tiene el campo del puntero de instrucción. El record será la instancia de ese evento. La función de la aplicación no necesita usar estos parámetros, pero pueden ser útiles para encontrar el nombre de la función para la dirección. El paddr es un puntero a un valor de 64 bits (donde solo se pueden usar 32 bits en máquinas de 32 bits). Este valor es el puntero de instrucción a buscar. Si la aplicación conoce la dirección de inicio de la función también, puede establecer paddr a esa dirección, y el plugin KVM también añadirá un "+offset" al nombre de la función, donde el offset es el valor original en paddr menos el valor en paddr cuando se llama. Finalmente, la aplicación debe devolver el nombre de la función como una cadena terminada en nulo si se encuentra alguna.

Si la cadena devuelta por tep_plugin_kvm_get_func() fue asignada, el plugin KVM llamará a tep_plugin_kvm_put_func() cuando termine con ella, pasando el valor devuelto por tep_plugin_kvm_get_func() como func. Esto permite a la aplicación liberarla si es necesario.

VALOR DE RETORNO

La función tep_plugin_kvm_get_func() no debe ser llamada por la aplicación, sino definida por ella. Debe devolver una cadena terminada en nulo que represente la función para el puntero de instrucción dado pasado a ella por referencia en paddr. Luego puede actualizar opcionalmente paddr a un valor que contenga el inicio de la función. La cadena devuelta puede ser liberada por la función tep_plugin_kvm_put_func() que la aplicación debe definir para limpiar la cadena.

El siguiente ejemplo necesita ser compilado con el flag -rdynamic para que el enlazador dinámico pueda resolver las funciones tep_plugin_kvm_get_func() y tep_plugin_kvm_put_func().

Cuando se ejecuta contra un archivo trace.dat producido por trace-cmd(1) grabando los eventos kvm_exit y kvm_entry en un huésped, y luego el archivo /proc/kallsyms del huésped se pasa como segundo parámetro, la salida producida se verá algo así:

CPU 0/KVM-20407 83156.177626 [000] kvm_exit     reason APIC_ACCESS rip 0xffffffffb0056ee2 exit native_apic_mem_write+0x2 info 10b0 0
CPU 0/KVM-20407 83156.177632 [000] kvm_entry     vcpu 0 rip 0xffffffffb0056ee8 enter native_apic_mem_write+0x8

Pero sin esas devoluciones de llamada, se vería así:

CPU 0/KVM-20407 83156.177626 [000] kvm_exit     reason APIC_ACCESS rip 0xffffffffb0056ee2 info 10b0 0
CPU 0/KVM-20407 83156.177632 [000] kvm_entry     vcpu 0 rip 0xffffffffb0056ee8

EJEMPLO

#include <stdio.h>
#include <stdlib.h>
#include <event-parse.h>
#include <trace-cmd.h>
#include <sys/stat.h>
static struct tep_handle *tep;
const char *tep_plugin_kvm_get_func(struct tep_event *event, struct tep_record *record,
                                    unsigned long long *paddr)
{
        const char *func;
        char *event_func;
        char *ename;
        func = tep_find_function(tep, *paddr);
        if (!func)
                return NULL;
        if (strcmp(event->name, "kvm_exit") == 0)
                ename = "exit";
        else
                ename = "enter";
        /*
         * Normalmente, devolver func directamente es suficiente y entonces
         * tep_plugin_kvm_put_func() no sería necesario. Pero este ejemplo
         * muestra cómo manejar la asignación de la cadena devuelta.
         */
        event_func = malloc(strlen(ename) + strlen(func) + 2);
        if (!event_func)
                return NULL;
        sprintf(event_func, "%s %s", ename, func);
        *paddr = tep_find_function_address(tep, *paddr);
        return event_func;
}
void tep_plugin_kvm_put_func(const char *func)
{
        char *f = (char *)func;
        free(f);
}
static int show_event(struct tracecmd_input *handle, struct tep_event *event,
                      struct tep_record *record, int cpu, void *data)
{
        static struct trace_seq seq;
        tep = data;
        if (!seq.buffer)
                trace_seq_init(&seq);
        trace_seq_reset(&seq);
        tep_print_event(tracecmd_get_tep(handle), &seq, record,
                        "%s-%d\t%6.1000d [%03d] %s\t%s\n",
                        TEP_PRINT_COMM, TEP_PRINT_PID,
                        TEP_PRINT_TIME, TEP_PRINT_CPU,
                        TEP_PRINT_NAME, TEP_PRINT_INFO);
        trace_seq_terminate(&seq);
        trace_seq_do_printf(&seq);
        return 0;
}
int main(int argc, char **argv)
{
        struct tracecmd_input *handle;
        struct tep_handle *guest_tep;
        struct stat st;
        FILE *fp;
        char *buf;
        if (argc < 3) {
                printf("usage: trace.dat guest_kallsyms_file\n");
                exit(-1);
        }
        handle = tracecmd_open(argv[1], 0);
        if (!handle) {
                perror(argv[1]);
                exit(-1);
        }
        /* Solo para el análisis de kallsyms */
        guest_tep = tep_alloc();
        if (!guest_tep)
                exit(-1);
        if (stat(argv[2], &st) < 0) {
                perror(argv[2]);
                exit(-1);
        }
        buf = malloc(st.st_size + 1);
        if (!buf)
                exit(-1);
        fp = fopen(argv[2], "r");
        if (!fp) {
                perror(argv[2]);
                exit(-1);
        }
        if (fread(buf, st.st_size, 1, fp) < 0) {
                perror(argv[2]);
                exit(-1);
        }
        buf[st.st_size] = '\0';
        if (tep_parse_kallsyms(guest_tep, buf) < 0) {
                printf("Failed to parse %s\n", argv[2]);
                exit(-1);
        }
        free(buf);
        tracecmd_follow_event(handle, "kvm", "kvm_exit", show_event, guest_tep);
        tracecmd_follow_event(handle, "kvm", "kvm_entry", show_event, guest_tep);
        tracecmd_iterate_events(handle, NULL, 0, NULL, NULL);
        tep_free(guest_tep);
        tracecmd_close(handle);
}

NAME

tep_plugin_kvm_get_func - get a plugin's function pointer

SYNOPSIS

#include <trace-event-parse.h>

void *tep_plugin_kvm_get_func(struct tep_event_plugin *plugin, const char *func_name);

DESCRIPTION

This function returns the function pointer for a given plugin function name.

The plugin is a pointer to the loaded plugin.

The func_name is the name of the function to retrieve.

RETURN VALUE

On success, returns the function pointer. On failure, returns NULL.

EXAMPLE

This is a simple example of how to use the function:

struct tep_event_plugin *plugin;
void *func;

plugin = tep_find_event_plugin("my_plugin");
if (!plugin) {
    /* Handle error */
}

func = tep_plugin_kvm_get_func(plugin, "my_function");
if (!func) {
    /* Handle error */
}

/* Use the function pointer */
/* For example, if my_function is a void (*)(int) function: */
/* ((void (*)(int))func)(123); */
