TEAMD.CONF(5) Configuración del demonio de equipo TEAMD.CONF(5)

NOMBRE

teamd.conf — Archivo de configuración del demonio libteam

DESCRIPCIÓN

teamd utiliza un formato de configuración JSON.

OPCIONES

dispositivo (cadena)
Nombre deseado del nuevo dispositivo de equipo.
nivel_debug (entero)
Nivel de mensajes de depuración. Cuanto mayor sea, más mensajes de depuración se imprimirán. Es lo mismo que añadir opciones de línea de comandos "-g".

Por defecto: 0 (desactivado)

direccion_hw (cadena)
Dirección de hardware deseada del nuevo dispositivo de equipo. Se acepta el formato habitual de dirección MAC.
nombre_ejecutor (cadena)
Nombre del dispositivo de equipo. Los siguientes ejecutores están disponibles:

broadcast — Ejecutor simple que dirige el dispositivo de equipo para transmitir paquetes a través de todos los puertos.

roundrobin — Ejecutor simple que dirige el dispositivo de equipo para transmitir paquetes en un orden cíclico.

random — Ejecutor simple que dirige el dispositivo de equipo para transmitir paquetes en un puerto seleccionado aleatoriamente.

activebackup — Supervisa los cambios de enlace y selecciona el puerto activo a utilizar para las transferencias de datos.

loadbalance — Para realizar balanceo de carga pasivo, el ejecutor solo configura una función hash BPF que determinará el puerto para la transmisión de paquetes. Para realizar balanceo de carga activo, el ejecutor mueve hashes entre los puertos disponibles intentando alcanzar un equilibrio perfecto.

lacp — Implementa el protocolo LACP 802.3ad. Puede usar las mismas posibilidades de selección de puertos de transmisión que el ejecutor loadbalance.

Por defecto: roundrobin

contador_notificar_pares (entero)
Número de ráfagas de paquetes NAs no solicitados y ARP gratuitos enviados después de que un puerto se habilita o deshabilita.

Por defecto: 0 (desactivado)

Por defecto para el ejecutor activebackup: 1

intervalo_notificar_pares (entero)
El valor es un número positivo en milisegundos. Especifica un intervalo entre ráfagas de paquetes de notificación a pares.

Por defecto: 0

contador_reunion_multicast (entero)
Número de ráfagas de solicitudes de reunión de grupo multicast enviadas después de que un puerto se habilita o deshabilita.

Por defecto: 0 (desactivado)

Por defecto para el ejecutor activebackup: 1

intervalo_reunion_multicast (entero)
El valor es un número positivo en milisegundos. Especifica un intervalo entre ráfagas de solicitudes de reunión de grupo multicast.

Por defecto: 0

nombre_vigilancia_enlace | puertos.NOMBRE_PUERTO.nombre_vigilancia_enlace (cadena)
Nombre del vigilante de enlace a utilizar. Los siguientes vigilantes de enlace están disponibles:

ethtool — Utiliza Libteam lib para obtener cambios de estado de ethtool del puerto.

arp_ping — Se envían solicitudes ARP a través de un puerto. Si se recibe una respuesta ARP, se considera que el enlace está activo.

nsna_ping — Similar al anterior, excepto que utiliza el mecanismo de Neighbor Solicitation / Neighbor Advertisement de IPv6. Esta es una alternativa a arp_ping y resulta útil en entornos puramente IPv6.

puertos (objeto)
Lista de puertos, dispositivos de red, a utilizar en un dispositivo de equipo.

Ver ejemplos para más información.

puertos.NOMBRE_PUERTO.id_cola (entero)
ID de la cola a la que se debe mapear este puerto.

Por defecto: Ninguno

OPCIONES ESPECIFICAS DEL EJECUTOR ACTIVE-BACKUP

politica_direccion_hw_ejecutor (cadena)
Esto define la política de cómo se deben establecer las direcciones de hardware del dispositivo de equipo y los dispositivos de puerto durante la vida útil del equipo. Los siguientes están disponibles:

same_all — Todos los puertos tendrán siempre la misma dirección de hardware que el dispositivo de equipo asociado.

by_active — El dispositivo de equipo adopta la dirección de hardware del puerto activo actualmente. Esto es útil cuando el dispositivo de puerto no puede cambiar su dirección de hardware.

only_active — Solo el puerto activo adopta la dirección de hardware del dispositivo de equipo. Los demás tienen las suyas propias.

Por defecto: same_all

prioridad_puerto (entero)
Prioridad del puerto. Un número mayor significa mayor prioridad.

Por defecto: 0

puerto_fijo (booleano)
Indicador que indica si el puerto es fijo. Si está establecido, significa que el puerto no se deselecciona si un puerto con mayor prioridad o mejores parámetros está disponible.

Por defecto: false

OPCIONES ESPECIFICAS DEL EJECUTOR LOAD BALANCE

hash_tx_ejecutor (array)
Lista de tipos de fragmentos (cadenas) que deben utilizarse para el cálculo del hash Tx de paquetes. Los siguientes están disponibles:

eth — Utiliza direcciones MAC de origen y destino.

vlan — Utiliza el ID de VLAN.

ipv4 — Utiliza direcciones IPv4 de origen y destino.

ipv6 — Utiliza direcciones IPv6 de origen y destino.

ip — Utiliza direcciones IPv4 e IPv6 de origen y destino.

l3 — Utiliza direcciones IPv4 e IPv6 de origen y destino.

tcp — Utiliza puertos TCP de origen y destino.

udp — Utiliza puertos UDP de origen y destino.

sctp — Utiliza puertos SCTP de origen y destino.

l4 — Utiliza puertos TCP, UDP y SCTP de origen y destino.

Por defecto: ["eth", "ipv4", "ipv6"]

nombre_balanceador_tx_ejecutor (cadena)
Nombre del balanceador Tx activo. El balanceo Tx activo está desactivado por defecto. El único valor disponible es basic.

Por defecto: Ninguno

intervalo_balanceo_balanceador_tx_ejecutor (entero)
En décimas de segundo. Intervalo periódico entre reequilibrios.

Por defecto: 50

OPCIONES ESPECIFICAS DEL EJECUTOR LACP

activo_ejecutor (booleano)
Si activo es true, se enviarán tramas LACPDU periódicamente a través de los enlaces configurados. Si no, actúa como "habla cuando se te hable".

Por defecto: true

tasa_rapida_ejecutor
>runner.fast_rate (bool)
La opción especifica la velocidad a la que se le pide a nuestro socio de enlace que transmita paquetes LACPDU. Si esto es true, los paquetes se enviarán una vez por segundo. De lo contrario, se enviarán cada 30 segundos.

Por defecto: false

runner.tx_hash (array)
Igual que para el runner de balanceo de carga.
runner.tx_balancer.name (string)
Igual que para el runner de balanceo de carga.
runner.tx_balancer.balancing_interval (int)
Igual que para el runner de balanceo de carga.
runner.sys_prio (int)
Prioridad del sistema, el valor puede ser 0 – 65535.

Por defecto: 65535

runner.min_ports (int)
Especifica el número mínimo de puertos que deben estar activos antes de afirmar la portadora en la interfaz maestra, el valor puede ser 1 – 1024.

Por defecto: 1

runner.agg_select_policy (string)
Esto selecciona la política de cómo se seleccionarán los agregadores. Las siguientes están disponibles:

lacp_prio – Se seleccionará el agregador con la mayor prioridad según el estándar LACP. La prioridad del agregador se ve afectada por la opción por puerto lacp_prio.

lacp_prio_stable – Igual que el anterior, excepto que no se reemplazará el agregador seleccionado si todavía es utilizable.

bandwidth – Selecciona el agregador con el mayor ancho de banda total.

count – Selecciona el agregador con el mayor número de puertos.

port_config – Se seleccionará el agregador con la mayor prioridad según las opciones por puerto prio y sticky. Esto significa que se seleccionará el agregador que contenga el puerto con la mayor prioridad, a menos que al menos uno de los puertos en el agregador actualmente seleccionado sea fijo (sticky).

Por defecto: lacp_prio

ports.PORTIFNAME.lacp_prio (int)
Prioridad del puerto según el estándar LACP. El número más bajo significa mayor prioridad.

Por defecto: 255

ports.PORTIFNAME.lacp_key (int)
Clave del puerto según el estándar LACP. Solo es posible agregar puertos con la misma clave.

Por defecto: 0

OPCIONES ESPECÍFICAS DE ETHTOOL PARA LINK WATCH

link_watch.delay_up | ports.PORTIFNAME.link_watch.delay_up (int)
El valor es un número positivo en milisegundos. Es el retraso entre que el enlace se activa y se notifica al runner al respecto.

Por defecto: 0

link_watch.delay_down | ports.PORTIFNAME.link_watch.delay_down (int)
El valor es un número positivo en milisegundos. Es el retraso entre que el enlace se desactiva y se notifica al runner al respecto.

Por defecto: 0

OPCIONES ESPECÍFICAS DE ARP PING PARA LINK WATCH

link_watch.interval | ports.PORTIFNAME.link_watch.interval (int)
El valor es un número positivo en milisegundos. Es el intervalo entre el envío de solicitudes ARP.

Por defecto: 1000

link_watch.init_wait | ports.PORTIFNAME.link_watch.init_wait (int)
El valor es un número positivo en milisegundos. Es el retraso entre la inicialización del monitor de enlace y el envío de la primera solicitud ARP.

Por defecto: 0

link_watch.missed_max | ports.PORTIFNAME.link_watch.missed_max (int)
Número máximo de respuestas ARP perdidas. Si este número se excede, el enlace se informa como caído.

Por defecto: 3

link_watch.source_host | ports.PORTIFNAME.link_watch.source_host (hostname)
Nombre de host a convertir en dirección IP que se rellenará en la solicitud ARP como dirección de origen.

Por defecto: 0.0.0.0

link_watch.target_host | ports.PORTIFNAME.link_watch.target_host (hostname)
Nombre de host a convertir en dirección IP que se rellenará en la solicitud ARP como dirección de destino.
link_watch.validate_active | ports.PORTIFNAME.link_watch.validate_active (bool)
Valida los paquetes ARP recibidos en puertos activos. Si no está configurado, todos los paquetes ARP entrantes se considerarán una respuesta válida.

Por defecto: false

link_watch.validate_inactive | ports.PORTIFNAME.link_watch.validate_inactive (bool)
Valida los paquetes ARP recibidos en puertos inactivos. Si no está configurado, todos los paquetes ARP entrantes se considerarán una respuesta válida.

Por defecto: false

link_watch.vlanid | ports.PORTIFNAME.link_watch.vlanid (int)
Por defecto, las solicitudes ARP se envían sin etiquetas VLAN. Esta opción hace que las solicitudes ARP salientes se envíen con el número de ID de VLAN especificado.

Por defecto: None

link_watch.send_always | ports.PORTIFNAME.link_watch.send_always (bool)
Por defecto, las solicitudes ARP se envían solo en puertos activos. Esta opción permite enviar incluso en puertos inactivos.

Por defecto: false

OPCIONES ESPECÍFICAS DE NS/NA PING PARA LINK WATCH

link_watch.interval | ports.PORTIFNAME.link_watch.interval (int)
El valor es un número positivo en milisegundos. Es el intervalo entre el envío de paquetes NS.

Por defecto: 1000

link_watch.init_wait | ports.PORTIFNAME.link_watch.init_wait (int)
El valor es un número positivo en milisegundos. Es el retraso entre la inicialización del monitor de enlace y el envío del primer paquete NS.
link_watch.missed_max | ports.PORTIFNAME.link_watch.missed_max (int)
Número máximo de paquetes de respuesta NA perdidos. Si este número se excede, el enlace se informa como caído.

Por defecto: 3

link_watch.target_host | ports.PORTIFNAME.link_watch.target_host (hostname)
Nombre de host a convertir en dirección IPv6 que se rellenará en el paquete NS como dirección de destino.
link_watch_policy (string)
Nombre de la política de evaluación del monitor de enlace. Las opciones disponibles son las siguientes:

any – El enlace está activo si cualquiera de los monitores de enlace informa que el enlace está activo.

all – El enlace está activo si todos los monitores de enlace informan que el enlace está activo.

Por defecto: any

EJEMPLOS

{
  "device": "team0",
  "runner": {"name": "roundrobin"},
  "ports": {"eth1": {}, "eth2": {}}
}

Configuración muy básica.

{
  "device": "team0",
  "runner": {"name": "activebackup"},
  "link_watch": {"name": "ethtool"},
  "ports": {
    "eth1": {
      "prio": -10,
      "sticky": true
    },
    "eth2": {
      "prio": 100
    }
  }
}

Esta configuración utiliza el runner active-backup con el monitor de enlace ethtool. El puerto eth2 tiene mayor prioridad, pero el flag sticky asegura que si eth1 se activa, permanece activo mientras el enlace esté activo.

{
  "device": "team0",
  "runner": {"name": "activebackup"},
  "link_watch": {
    "name": "ethtool",
    "delay_up": 2500,
    "delay_down": 1000
  },
  "ports": {
    "eth1": {
      "prio": -10,
      "sticky": true
    },
    "eth2": {
      "prio": 100
    }
  }
}

Similar a la anterior. La única diferencia es que los cambios de enlace no se propagan inmediatamente al runner, sino que se aplican retrasos.
