termkey_new(3)

Paquete: libtermkey

Licencias: MIT

TERMKEY_NEW(3) Manual de funciones de la biblioteca TERMKEY_NEW(3)

NOMBRE

termkey_new, termkey_destroy - crear o destruir una nueva instancia de termkey

SINOPSIS

#include <termkey.h>

TERMKEY_CHECK_VERSION;
TermKey *termkey_new(int fd, int flags);
TermKey *termkey_new_abstract(const char *term, int flags);
void termkey_destroy(TermKey *tk);

Enlazar con -ltermkey.

DESCRIPCIÓN

termkey_new() crea una nueva instancia de termkey(7) conectada al manejador de archivo abierto por fd usando las flags. La estructura termkey(7) debe ser considerada opaca; sus contenidos no están pensados para ser usados fuera de la biblioteca.

termkey_new_abstract() crea una nueva instancia de termkey() sin un manejador de archivo asociado. Como esto se hace generalmente para manejar otras fuentes de entrada de bytes del terminal, también toma una cadena que indica el tipo de terminal a usar.

termkey_destroy() destruye la instancia dada y libera cualquier recurso controlado por ella. No cerrará el manejador de archivo subyacente dado como argumento fd a termkey_new().

El constructor intenta detectar si la localización actual es consciente de UTF-8 o no, y establece la bandera TERMKEY_FLAG_UTF8 o TERMKEY_FLAG_RAW. Una de estas dos banderas siempre estará en efecto. Las banderas actuales en efecto se pueden obtener con termkey_get_flags(3).

Si se proporciona un manejador de archivo, el controlador de terminfo puede enviar una cadena para inicializar o establecer el estado del terminal antes de que termkey_new() retorne. Esto no se hará si no se proporciona un manejador de archivo, o si el manejador de archivo es una tubería (S_ISFIFO()). En este caso, será responsabilidad del llamador asegurarse de que el terminal esté en el modo correcto. Una vez inicializado, el terminal puede ser detenido con termkey_stop(3), y reiniciado con termkey_start(3).

Este comportamiento se modifica por la bandera TERMKEY_FLAG_NOSTART. Si se pasa en el argumento flags, la instancia no se iniciará aún por el constructor; el llamador debe invocar termkey_start() en algún momento futuro antes de que la instancia sea utilizable.

MACRO DE VERIFICACIÓN DE VERSIÓN

Antes de llamar a cualquier función en la biblioteca termkey, una aplicación debe usar la macro TERMKEY_CHECK_VERSION para verificar que la versión cargada de la biblioteca sea compatible con la versión con la que fue compilada. Esto debe hacerse temprano, idealmente justo después de entrar en su función main().

VALOR DE RETORNO

Si tiene éxito, termkey_new() devuelve un puntero a la nueva instancia. En caso de fallo, se devuelve NULL con errno establecido para indicar el fallo. termkey_destroy() no devuelve ningún valor.

ERRORES

ENOENT
Ningún controlador pudo reconocer el tipo de terminal dado.
ENOMEM
Una llamada a malloc(3) falló al asignar memoria.

Adicionalmente, termkey_new() puede fallar si fstat(2) o write(2) fallan en el manejador de archivo dado.

VER TAMBIÉN
