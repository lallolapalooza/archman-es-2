DESCRIPCIÓN

Esta página resume las variables proporcionadas por la interfaz de bajo nivel de terminfo de la biblioteca curses. Una descripción más completa se da en la página del manual curs_terminfo(3X).

Dependiendo de la configuración, estas pueden ser variables reales, o macros (ver curs_threads(3X)) que proporcionan acceso de solo lectura al estado de curses. En cualquier caso, las aplicaciones deben tratarlas como de solo lectura para evitar confundir a la biblioteca.

Mapeo del conjunto de caracteres alternativos

Después de inicializar las interfaces de curses o terminfo, la matriz acs_map contiene información utilizada para traducir celdas con el atributo de video A_ALTCHARSET en caracteres de dibujo de líneas.

La codificación de la información en esta matriz ha cambiado periódicamente. Los desarrolladores de aplicaciones solo necesitan saber que se utiliza para las constantes “ACS_” en <curses.h>.

Los datos comparables para la biblioteca de caracteres anchos son una variable privada.

Datos del terminal actual

Después de inicializar las interfaces de curses o terminfo, cur_term contiene datos que describen el terminal actual. Esta variable también se establece como un efecto secundario de set_term(3X) y delscreen(3X).

Es posible guardar un valor de cur_term para su uso posterior como parámetro para set_term, para cambiar entre pantallas. Alternativamente, se puede guardar el valor de retorno de newterm o setupterm(3X) para reutilizarlo en set_term.

Tablas de búsqueda de terminfo

Los programas tic(1) y infocmp(1) utilizan tablas de búsqueda para los nombres largos y cortos de las capacidades de terminfo, así como los nombres correspondientes para las capacidades de termcap. Estos están disponibles para otras aplicaciones, aunque las tablas hash utilizadas por las funciones de terminfo y termcap no lo están.

Los nombres largos de las capacidades de terminfo utilizan una “f” (ef) en sus nombres: boolfnames, numfnames y strfnames.

Estos son los nombres cortos para las capacidades de terminfo: boolnames, numnames y strnames.

Estos son los nombres correspondientes utilizados para las descripciones de termcap: boolcodes, numcodes y strcodes.

Tipo de terminal

Una descripción de terminal comienza con uno o más nombres de terminal separados por “|” (barras verticales). Al inicializar las interfaces de curses o terminfo, setupterm(3X) copia los nombres de terminal a la matriz ttytype.

Nombres de terminfo

Además de las variables, <term.h> también define un símbolo para cada nombre largo de capacidad de terminfo. Estos están en términos del símbolo CUR, que está definido

#define CUR ((TERMTYPE *)(cur_term))->

Estos símbolos proporcionan un método más rápido para acceder a las capacidades de terminfo que usar tigetstr(3X), etc.

La definición real de CUR depende de la implementación, pero cada biblioteca de terminfo proporciona estos nombres largos definidos para apuntar a la descripción del terminal actual cargada en memoria.

NOTAS

La interfaz de bajo nivel de terminfo se inicializa usando setupterm(3X). La interfaz de nivel superior curses utiliza internamente la interfaz de bajo nivel de terminfo.

PORTABILIDAD

X/Open Curses no describe ninguna de estas excepto por cur_term. (La inclusión de cur_term parece ser un descuido, ya que X/Open omite otra información comparable de bajo nivel).

Otras implementaciones pueden tener variables comparables. Algunas implementaciones proporcionan las variables en sus bibliotecas, pero las omiten de los archivos de encabezado.

Todas las implementaciones que proporcionan interfaces de terminfo añaden definiciones como se describe en la sección Nombres de terminfo. La mayoría, pero no todas, basan la definición en la variable cur_term.
