TEST(1P) Manual de Programador POSIX TEST(1P)

PROLOG

Esta página del manual forma parte del Manual de Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

test — evalúa una expresión

SINOPSIS

test [expresión]
[ [expresión] ]

DESCRIPCIÓN

La utilidad test evaluará la expresión e indicará el resultado de la evaluación mediante su estado de salida. Un estado de salida de cero indica que la expresión se evaluó como verdadera y un estado de salida de 1 indica que la expresión se evaluó como falsa.

En la segunda forma de la utilidad, donde el nombre de utilidad utilizado es [ en lugar de test, la aplicación deberá asegurarse de que el corchete de cierre sea un argumento separado. Las utilidades test y [ pueden implementarse como una única utilidad enlazada que examina el nombre base del argumento de línea de comandos cero para determinar si debe comportarse como la variante test o [. Las aplicaciones que utilicen la familia de funciones exec() para ejecutar estas utilidades deberán asegurarse de que el argumento pasado en arg0 o argv[0] sea '[' al ejecutar la utilidad [ y tenga un nombre base de "test" al ejecutar la utilidad test.

OPCIONES

La utilidad test no reconocerá el argumento "--" de la manera especificada por la Directriz 10 en el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de sintaxis de utilidad.

No se admitirán opciones.

TÉRMINOS

La aplicación deberá asegurarse de que todos los operadores y elementos de los primarios se presenten como argumentos separados a la utilidad test.

Los siguientes primarios se pueden usar para construir la expresión:

-b ruta
Verdadero si ruta se resuelve en una entrada de directorio existente para un archivo especial de bloque. Falso si ruta no se puede resolver, o si ruta se resuelve en una entrada de directorio existente para un archivo que no es un archivo especial de bloque.
-c ruta
Verdadero si ruta se resuelve en una entrada de directorio existente para un archivo especial de carácter. Falso si ruta no se puede resolver, o si ruta se resuelve en una entrada de directorio existente para un archivo que no es un archivo especial de carácter.
-d ruta
Verdadero si ruta se resuelve en una entrada de directorio existente para un directorio. Falso si ruta no se puede resolver, o si ruta se resuelve en una entrada de directorio existente para un archivo que no es un directorio.
-e ruta
Verdadero si ruta se resuelve en una entrada de directorio existente. Falso si ruta no se puede resolver.
-f ruta
Verdadero si ruta se resuelve en una entrada de directorio existente para un archivo regular. Falso si ruta no se puede resolver, o si ruta se resuelve en una entrada de directorio existente para un archivo que no es un archivo regular.
-g ruta
Verdadero si ruta se resuelve en una entrada de directorio existente para un archivo que tiene configurado su bit set-group-ID. Falso si ruta no se puede resolver, o si ruta se resuelve en una entrada de directorio existente para un archivo que no tiene configurado su bit set-group-ID.
-h ruta
Verdadero si ruta se resuelve en una entrada de directorio existente para un enlace simbólico. Falso si ruta no se puede resolver, o si ruta se resuelve en una entrada de directorio existente para un archivo que no es un enlace simbólico. Si el último componente de ruta es un enlace simbólico, ese enlace simbólico no se seguirá.
-L ruta
Verdadero si ruta se resuelve en una entrada de directorio existente para un enlace simbólico. Falso si ruta no se puede resolver, o si ruta se resuelve en una entrada de directorio existente para un archivo que no es un enlace simbólico. Si el último componente de ruta es un enlace simbólico, ese enlace simbólico no se seguirá.
-n cadena
Verdadero si la longitud de cadena es distinta de cero; de lo contrario, falso.
-p ruta
Verdadero si ruta se resuelve en una entrada de directorio existente para una FIFO. Falso si ruta no se puede resolver, o si ruta se resuelve en una entrada de directorio existente para un archivo que no es una FIFO.
-r ruta
Verdadero si ruta se resuelve en una entrada de directorio existente para un archivo para el cual se concederá permiso de lectura, tal como se define en la Sección 1.1.1.4, Lectura, Escritura y Creación de Archivos. Falso si ruta no se puede resolver, o si ruta se resuelve en una entrada de directorio existente para un archivo para el cual no se concederá permiso de lectura.
-S ruta
Verdadero si ruta se resuelve en una entrada de directorio existente para un socket. Falso si ruta no se puede resolver, o si ruta se resuelve en una entrada de directorio existente para un archivo que no es un socket.
-s ruta
Verdadero si ruta se resuelve en una entrada de directorio existente para un archivo que tiene un tamaño mayor que cero. Falso si ruta no se puede resolver, o si ruta se resuelve en una entrada de directorio existente para un archivo que no tiene un tamaño mayor que cero.
-t descriptor_archivo

Verdadero si el descriptor de archivo número descriptor_archivo está abierto y está asociado con una terminal. Falso si el descriptor de archivo descriptor_archivo no es un número de descriptor de archivo válido, o si el descriptor de archivo número descriptor_archivo no está abierto, o si está abierto pero no está asociado con una terminal.

Verdadero si ruta se resuelve en una entrada de directorio existente para un archivo que tiene configurado su bit set-user-ID. Falso si ruta no se puede resolver, o si ruta se resuelve en una entrada de directorio existente para un archivo que no tiene configurado su bit set-user-ID.
-w ruta
Verdadero si ruta se resuelve en una entrada de directorio existente para un archivo para el cual se concederá permiso de escritura, tal como se define en la Sección 1.1.1.4, Lectura, Escritura y Creación de Archivos. Falso si ruta no se puede resolver, o si ruta se resuelve en una entrada de directorio existente para un archivo para el cual no se concederá permiso de ejecución (o búsqueda).

cadena
Verdadero si la cadena cadena no es la cadena nula; de lo contrario, falso.
s1 = s2
Verdadero si las cadenas s1 y s2 son idénticas; de lo contrario, falso.
s1 != s2
Verdadero si las cadenas s1 y s2 no son idénticas; de lo contrario, falso.
n1 -eq n2
Verdadero si el entero n1 es igual al entero n2; de lo contrario, falso.
n1 -ge n2
Verdadero si el entero n1 es mayor o igual que el entero n2; de lo contrario, falso.

Verdadero si el entero n1 es mayor que el entero n2; de lo contrario, falso.

Verdadero si el entero n1 es menor o igual que el entero n2; de lo contrario, falso.
n1 -lt n2
Verdadero si el entero n1 es menor que el entero n2; de lo contrario, falso.
n1 -ne n2
Verdadero si el entero n1 no es igual al entero n2; de lo contrario, falso.

Se permite la negación usando el operador de prefijo !.

Se permiten los siguientes operadores de agrupación:

(expresión)
Los paréntesis agruparán la expresión. La aplicación deberá asegurarse de que los paréntesis se presenten como argumentos separados a la utilidad test. La evaluación de la expresión se realizará normalmente.

Los siguientes operadores se utilizan para combinar primarios:

exp1 -a exp2
Verdadero si tanto exp1 como exp2 se evalúan como verdaderos; de lo contrario, falso.
exp1 -o exp2
Verdadero si tanto exp1 como exp2 se evalúan como verdaderos; de lo contrario, falso.

En la construcción de una expresión, el resultado de la evaluación de un operador de prefijo será verdadero o falso. El resultado de la evaluación de un operador binario será verdadero o falso. Los operandos derechos de los operadores de prefijo y los operandos derechos de los operadores binarios no se evaluarán si el resultado de la evaluación se puede determinar sin ellos.

El siguiente orden de evaluación se aplica a los operadores !, -a, y -o:

  1. El operador ! tiene la mayor precedencia.

  2. El operador -a tiene la siguiente precedencia.

  3. El operador -o tiene la precedencia más baja.

Los operadores -a y -o son asociativos por la derecha.

La aplicación deberá asegurarse de que todos los operadores y elementos de las expresiones (incluidos los paréntesis) se presenten como argumentos separados a la utilidad test.

Se permiten las siguientes combinaciones de operadores y primarios:

Si se encuentra un argumento "(", entonces se buscará un argumento correspondiente ")". Si se encuentran, la expresión dentro de los paréntesis se evaluará primero.

Si se encuentran los argumentos "!", "(", -a, y -o, las aplicaciones deberán determinar la precedencia de la evaluación de la expresión utilizando las reglas definidas en la Sintaxis de la Utilidad y la descripción de los operadores.

Si no se especifican argumentos, test se evaluará como falso.

Si la expresión es nula, test se evaluará como falso.

Si la expresión es el argumento único "!", test se evaluará como verdadero.

ESTADO DE SALIDA

Se utilizará uno de los siguientes valores de salida:

0
La expresión evaluada como verdadera.
1
La expresión evaluada como falsa.
>1
Se produjo un error.

test — evaluate a conditional expression

test [expression]

[ expression ]

DESCRIPTION

The test utility shall evaluate the expression and, for each expression, it shall write an exit status to standard output that reflects the value of the expression. The expression is a sequence of predicates separated by one or more operators, and enclosed in what is described in the following grammar.

Operators and primaries are listed in decreasing order of precedence:

! expression
True if expression is false. False if expression is true.
( expression )
True if expression is true. False if expression is false. The parentheses can be used to alter the normal precedence and associativity.
expression1 -a expression2

True if both expression1 and expression2 are true; otherwise, false. The -a binary primary is left associative. It has a higher precedence than -o.
expression1 -o expression2

True if either expression1 or expression2 is true; otherwise, false. The -o binary primary is left associative.
string
True if the null-terminated string string is not null; otherwise, false.
s1 = s2
True if the strings s1 and s2 are identical; otherwise, false.
s1 != s2
True if the strings s1 and s2 are not identical; otherwise, false.
n1 -eq n2
True if the integers n1 and n2 are algebraically equal; otherwise, false.
n1 -ne n2
True if the integers n1 and n2 are not algebraically equal; otherwise, false.
n1 -gt n2
True if the integer n1 is algebraically greater than the integer n2; otherwise, false.
n1 -ge n2
True if the integer n1 is algebraically greater than or equal to the integer n2; otherwise, false.
n1 -lt n2
True if the integer n1 is algebraically less than the integer n2; otherwise, false.
n1 -le n2
True if the integer n1 is algebraically less than or equal to the integer n2; otherwise, false.
-b pathname
True if pathname exists and is a block special file.
-c pathname
True if pathname exists and is a character special file.
-d pathname
True if pathname exists and is a directory.
-e pathname
True if pathname exists.
-f pathname
True if pathname exists and is a regular file.
-h pathname
True if pathname exists and is a symbolic link.
-L pathname
True if pathname exists and is a symbolic link. (This is equivalent to -h).
-p pathname
True if pathname exists and is a named pipe (FIFO).
-r pathname
True if pathname exists and is readable.
-s pathname
True if pathname exists and has a size greater than zero.
-S pathname
True if pathname exists and is a socket.
-t fd
True if file descriptor fd is open and refers to a terminal.
-u pathname
True if pathname exists and the set-user-ID bit is set.
-w pathname
True if pathname exists and is writable.
-x pathname
True if pathname exists and is executable.
-z string
True if the null-terminated string string has a length of zero; otherwise, false.
-n string
True if the null-terminated string string has a length greater than zero; otherwise, false.
file1 -nt file2
True if file1 exists and is newer than file2. Otherwise, false.
file1 -ot file2
True if file1 exists and is older than file2. Otherwise, false.
file1 -ef file2
True if file1 and file2 refer to the same file. Otherwise, false.

With the exception of the -h pathname and -L pathname primaries, if a pathname argument is a symbolic link, test shall evaluate the expression by resolving the symbolic link and using the file referenced by the link.

These primaries can be combined with the following operators:

! expression
True if expression is false. False if expression is true.
( expression )
True if expression is true. False if expression is false. The parentheses can be used to alter the normal precedence and associativity.

The primaries with two elements of the form:

-primary_operator primary_operand

are known as unary primaries. The primaries with three elements in either of the two forms:

primary_operand -primary_operator primary_operand
primary_operand primary_operand primary_operand

are known as binary primaries. Additional implementation-defined operators and primary_operators may be provided by implementations. They shall be of the form -operator where the first character of operator is not a digit.

The algorithm for determining the precedence of the operators and the return value that shall be generated is based on the number of arguments presented to test. (However, when using the "[" form, the "]" final argument shall not be counted in this algorithm.)

In the following list, $1, $2, $3, and $4 represent the arguments presented to test:

0 arguments:
Exit false (1).
1 argument:
Exit true (0) if $1 is not null; otherwise, exit false.
2 arguments:
*
If $1 is !, exit true if $2 is null, false if $2 is not null.
*
If $1 is a unary primary, exit true if the unary test is true, false if the unary test is false.
*
Otherwise, produce unspecified results.
3 arguments:
*
If $2 is a binary primary, perform the binary test of $1 and $3.
*
If $1 is !, negate the two-argument test of $2 and $3.
*
If $1 is ( and $3 is ), perform the unary test of $2. On systems that do not support the XSI option, the results are unspecified if $1 is ( and $3 is ).
*
Otherwise, produce unspecified results.
4 arguments:
*
If $1 is !, negate the three-argument test of $2, $3, and $4.
*
If $1 is ( and $4 is ), perform the two-argument test of $2 and $3. On systems that do not support the XSI option, the results are unspecified if $1 is ( and $4 is ).
*
Otherwise, the results are unspecified.
>4 arguments:
The results are unspecified.

On XSI-conformant systems, combinations of primaries and operators shall be evaluated using the precedence and associativity rules described previously. In addition, the string comparison binary primaries = and != shall have a higher precedence than any unary primary.

APPLICATION USAGE

The XSI extensions specifying the -a and -o binary primaries and the ( and ) operators have been marked obsolescent. (Many expressions using them are ambiguously defined by the grammar depending on the specific expressions being evaluated.) Scripts using these expressions should be converted to the forms given below. Even though many implementations will continue to support these obsolescent forms, scripts should be extremely careful when dealing with user-supplied input that could be confused with these and other primaries and operators. Unless the application developer knows all the cases that produce input to the script, invocations like:

test "$1" -a "$2"

should be written as:

test "$1" && test "$2"

to avoid problems if a user supplied values such as $1 set to ! and $2 set to the null string. That is, in cases where maximal portability is of concern, replace:

test expr1 -a expr2

with:

test expr1 && test expr2

and replace:

test expr1 -o expr2

with:

test expr1 || test expr2

but note that, in test, -a has higher precedence than -o while && and || have equal precedence in the shell.

Parentheses or braces can be used in the shell command language to effect grouping.

Parentheses must be escaped when using sh; for example:

test \( expr1 -a expr2 \) -o expr3

This command is not always portable even on XSI-conformant systems depending on the expressions specified by expr1, expr2, and expr3. The following form can be used instead:

( test expr1 && test expr2 ) || test expr3

Or, if the shell supports the "[[ ... ]]" conditional construct:

[[ expr1 && expr2 ]] || [[ expr3 ]]

Note that the shell logical operators && and || are different from the test operators -a and -o.

The test utility is intended to be used by shell scripts to perform conditional evaluations. The Bourne shell built-in command `[` is described as being equivalent to test, with the exception that it requires a `]' argument.

The behavior is undefined if the expression contains the characters `[', `]', `(', `)', `!', `-', or any of the primaries defined in the DESCRIPTION section unless the argument is quoted or escaped.

The results are undefined when comparing strings that contain multi-byte characters unless the LC_CTYPE locale is set appropriately. Comparisons are performed lexicographically.

The arguments -operator and operand may be confused if the operand starts with a -. For example, the command:

test -- file

is safer than:

test - file

This problem can be avoided by using the [ form and ensuring that operands are quoted:

[ ! -f file ]

is safer than

[ -f file ]

as it avoids ambiguity when file is the name of an option.

EXAMPLES

1. Check if the file named myfile.txt exists:

test -e myfile.txt

2. Check if the file named myfile.txt does not exist:

test ! -e myfile.txt

3. Check if the file named myfile.txt is empty:

test -z $(cat myfile.txt)

4. Check if the variable $MYVAR is set and not null:

test -n "$MYVAR"

5. Check if two strings are equal:

test "$STR1" = "$STR2"

6. Check if two integers are equal:

test "$INT1" -eq "$INT2"

7. Check if a file exists and is executable:

test -e filename -a -x filename

This can be written more portably as:

test -e filename && test -x filename

8. Check if a file is older than another file:

test file1 -ot file2

FUTURE DIRECTIONS

The XSI extensions for -a and -o operators are obsolescent and may be removed in future issues.

OPERATORS


The primary operators are:



  
str1

  
True if the string str1 is not empty.

  
str1 = str2

  
True if the strings str1 and str2 are
      equal.

  
str1 != str2

  
True if the strings str1 and str2 are
      not equal.

  
-n str1

  
True if the length of the string str1 is non-zero.

  
-z str1

  
True if the length of the string str1 is zero.








FILE OPERATORS


The file operator primaries are:



  
-b file

  
True if file exists and is a block special file.

  
-c file

  
True if file exists and is a character special file.

  
-d file

  
True if file exists and is a directory.

  
-f file

  
True if file exists and is a regular file.

  
-g file

  
True if file exists and has the set-group-ID bit
      set.

  
-k file

  
True if file exists and has the sticky bit
      set.

  
-L file

  
True if file exists and is a symbolic link. (This
      test is true if the symbolic link itself is being tested; the test results
      are determined by the characteristics of the file pointed to by the
      symbolic link).

  
-p file

  
True if file exists and is a first-in,
      first-out (FIFO) special file.

  
-r file

  
True if file exists and is readable by the current
      user.

  
-s file

  
True if file exists and has a size greater than
      zero.

  
-u file

  
True if file exists and has the set-user-ID bit
      set.

  
-w file

  
True if file exists and is writable by the current
      user.

  
-x file

  
True if file exists and is executable by the current
      user.

  
-G file

  
True if file exists and its group ID matches the
      current process's group ID.

  
-P file

  
True if file exists and is a symbolic link. (This
      test is true if the symbolic link itself is being tested; the test results
      are determined by the characteristics of the file pointed to by the
      symbolic link).

  
-t fd

  
True if file descriptor fd is open and refers to a
      terminal.

  
-z file

  
True if file exists and has a size of zero.

  
-O file

  
True if file exists and its user ID matches the
      current process's user ID.

  
file1 -nt file2

  
True if file1 is a regular file and is newer
      than file2. Otherwise, false.

  
file1 -ot file2

  
True if file1 is a regular file and is older
      than file2. Otherwise, false.

  
file1 -ef file2

  
True if file1 and file2
      refer to the same file. Otherwise, false.








INTEGER COMPARISON


The integer comparison primaries are:



  
integer1 -eq integer2

  
True if integer1 is equal to integer2.

  
integer1 -ne integer2

  
True if integer1 is not equal to integer2.

  
integer1 -gt integer2

  
True if integer1 is greater than integer2.

  
integer1 -ge integer2

  
True if integer1 is greater than or equal to
      integer2.

  
integer1 -lt integer2

  
True if integer1 is less than integer2.

  
integer1 -le integer2

  
True if integer1 is less than or equal to
      integer2.








LOGICAL OPERATORS


The logical operators are:



  
! expr

  
True if expr is false.

  
-not expr

  
True if expr is false.

  
expr1 -a expr2

  
True if both expr1 and expr2
      are true.

  
expr1 -o expr2

  
True if either expr1 or expr2
      is true.

  
( expr )

  
True if expr is true. The parentheses must be escaped
      or quoted.

APPLICATION USAGE


It is recommended that strings be quoted when used with test
    to prevent the shell from splitting the string into multiple arguments or
    performing other expansions.


The [ is a shell reserved word, not a command.
    When used, it is parsed directly by the shell. The [
    command requires a closing ]. Each of the
    keywords and, if present, the [ and
    ] operands must be separate arguments to the
    command.


The test command does not require any special
    handling for operands like [ and
    ].


The test and [
    utilities are equivalent except for the handling of -
    as the first character of an operand. When test
    is invoked with the first operand being -, it
    is treated as an error. When [ is invoked
    with the first operand being -, it is treated as
    an error.






EXAMPLES


Check if a file exists:


if test -f /etc/hosts; then echo "hosts file exists"; fi


Check if a string is empty:


if test -z "$MY_VAR"; then echo "MY_VAR is empty"; fi


Compare two strings:


if test "$STR1" = "$STR2"; then echo "STR1 and STR2 are equal"; fi


Using the [ equivalent:


if [ -f /etc/hosts ]; then echo "hosts file exists"; fi


Compare integers:


COUNT=10
    if [ "$COUNT" -gt 5 ]; then echo "COUNT is greater than 5"; fi


Combine tests:


if [ -f file1 -a -r file1 ]; then echo "file1 exists and is readable"; fi


if [ -f file1 -o -f file2 ]; then echo "file1 or file2 exists"; fi


if [ ! -f file1 ]; then echo "file1 does not exist"; fi






RATIONALE


The test utility provides a way to evaluate
    expressions and return an exit status based on the result. This is commonly
    used in shell scripts for conditional execution.


The original test utility did not have
    many of the file operators or integer comparison operators that are now
    supported. These were added over time to provide more functionality.


The [ utility was introduced as a POSIX
    standard to provide a more readable and convenient way to use the test
    functionality within shell scripts. The [ is
    a keyword in many shells, meaning it is parsed by the shell itself rather
    than being executed as a separate command. This allows for more direct
    integration with shell control structures.


The use of = for string comparison is
    historical. Some versions of test also supported
    ==, but = is the standard
    POSIX version.


The behavior of -L and -P
    for symbolic links was clarified to indicate that they test the link
    itself, not the file it points to. The POSIX standard specifies that these
    tests should evaluate the characteristics of the symbolic link itself.
    However, in practice, many implementations evaluate the target of the link.
    The current POSIX standard clarifies this ambiguity by stating that the
    behavior is implementation-defined for -L, and
    -P is specified to be true if the file is a
    symbolic link.
