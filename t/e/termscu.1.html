NOMBRE

termscu - SCU de terminación DICOM

SINOPSIS

termscu [opciones] par [puerto]

DESCRIPCIÓN

La aplicación termscu implementa un Usuario de Clase de Servicio (SCU) para la Clase de SOP de Apagado privada de DCMTK. Intenta negociar esta Clase de SOP de Apagado privada con un Proveedor de Clase de Servicio (SCP) que (si esta característica está implementada) se apagará inmediatamente después de rechazar la asociación. La aplicación se puede utilizar para apagar algunas de las aplicaciones de servidor de DCMTK.

PARÁMETROS

par   nombre del host del par DICOM
puerto número de puerto tcp/ip del par

OPCIONES

opciones generales

  -h    --help
          imprime este texto de ayuda y sale
        --version
          imprime información de versión y sale
        --arguments
          imprime argumentos de línea de comandos expandidos
  -q    --quiet
          modo silencioso, no imprime advertencias ni errores
  -v    --verbose
          modo verboso, imprime detalles del procesamiento
  -d    --debug
          modo de depuración, imprime información de depuración
  -ll   --log-level  [n]ivel: cadena de caracteres
          (fatal, error, warn, info, debug, trace)
          usa el nivel n para el registrador
  -lc   --log-config  [a]rchivo: cadena de caracteres
          usa el archivo de configuración a para el registrador

opciones de red

versión del protocolo IP:
  -i4   --ipv4
          usa solo IPv4 (por defecto)
  -i6   --ipv6
          usa solo IPv6
  -i0   --ip-auto
          usa la búsqueda DNS para determinar el protocolo IP
títulos de entidades de aplicación:
  -aet  --aetitle  [t]ítulo: cadena de caracteres
          establece mi título AE de llamada (por defecto: ECHOSCU)
  -aec  --call  [t]ítulo: cadena de caracteres
          establece el título AE llamado del par (por defecto: ANY-SCP)
otras opciones de red:
  -pdu  --max-pdu  [n]úmero de bytes: entero (4096..131072)
          establece el PDU máximo de recepción a n bytes (por defecto: 16384)

NOTAS

Conformidad DICOM

La aplicación termscu soporta las siguientes Clases de SOP como SCU:

REGISTRO

El nivel de salida del registro de las diversas herramientas de línea de comandos y bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo los errores y las advertencias se escriben en el flujo de error estándar. Usando la opción --verbose también se reportan mensajes informativos como detalles del procesamiento. La opción --debug puede ser utilizada para obtener más detalles sobre la actividad interna, p. ej., con fines de depuración. Otros niveles de registro se pueden seleccionar usando la opción --log-level. En el modo --quiet solo se reportan errores fatales. En tales eventos de error muy graves, la aplicación generalmente terminará. Para más detalles sobre los diferentes niveles de registro, ver la documentación del módulo "oflog".

En caso de que la salida del registro deba ser escrita en un archivo (opcionalmente con rotación de archivos de registro), a syslog (Unix) o al registro de eventos (Windows), se puede usar la opción --log-config. Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o la aplicación donde se generan. Se proporciona un archivo de configuración de ejemplo en <etcdir>/logger.cfg.

LÍNEA DE COMANDOS

Todas las herramientas de línea de comandos utilizan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos al final indican que se permiten múltiples valores (1-n), una combinación de ambos significa 0 a n valores.

Las opciones de línea de comandos se distinguen de los parámetros por un signo '+' o '-' al principio, respectivamente. Usualmente, el orden y la posición de las opciones de línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se utiliza la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix comunes.

Además, se pueden especificar uno o más archivos de comandos usando un signo '@' como prefijo del nombre de archivo (p. ej., @command.txt). Dicho argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre comillas) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comandos no puede contener otro archivo de comandos. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (se proporciona un ejemplo en el archivo <datadir>/dumppat.txt).

ENTORNO

La utilidad termscu intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH. Por defecto, es decir, si la variable de entorno DCMDICTPATH no está establecida, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté integrado en la aplicación (por defecto para Windows).

Se debe preferir el comportamiento por defecto y usar la variable de entorno DCMDICTPATH solo cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix, en el sentido de que un dos puntos (":") separa las entradas. En sistemas Windows, un punto y coma (";") se usa como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH. Es un error si no se puede cargar ningún diccionario de datos.
