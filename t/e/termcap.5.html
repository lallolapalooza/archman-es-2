termcap(5) Manual de formatos de archivo termcap(5)

NOMBRE

termcap - base de datos de capacidades de terminal

DESCRIPCIÓN

La base de datos termcap es una instalación obsoleta para describir las capacidades de terminales y impresoras de celda de caracteres. Se conserva solo para compatibilidad con programas antiguos; los programas nuevos deben usar la base de datos terminfo(5) y las bibliotecas asociadas.

/etc/termcap es un archivo ASCII (la base de datos maestra) que enumera las capacidades de muchos tipos de terminales diferentes. Los programas pueden leer termcap para encontrar los códigos de escape particulares necesarios para controlar los atributos visuales del terminal en uso. (Otros aspectos del terminal son manejados por stty(1)). La base de datos termcap se indexa por la variable de entorno TERM.

Las entradas de termcap deben definirse en una sola línea lógica, usando '\' para suprimir el salto de línea. Los campos están separados por ':'. El primer campo de cada entrada comienza en el margen izquierdo y contiene una lista de nombres para el terminal, separados por '|'.

El primer subcampo puede (en entradas termcap de BSD de 4.3BSD y anteriores) contener un nombre corto que consta de dos caracteres. Este nombre corto puede consistir en letras mayúsculas o minúsculas. En las entradas termcap de 4.4BSD, este campo se omite.

El segundo subcampo (el primero, en el formato más nuevo de 4.4BSD) contiene el nombre utilizado por la variable de entorno TERM. Debe estar escrito en letras minúsculas. Las capacidades de hardware seleccionables deben marcarse añadiendo un guión y un sufijo a este nombre. Véase a continuación un ejemplo. Los sufijos habituales son w (más de 80 caracteres de ancho), am (márgenes automáticos), nam (sin márgenes automáticos) y rv (pantalla de video inversa).

Los campos subsiguientes contienen las capacidades del terminal; cualquier línea de capacidad continuada debe estar indentada una tabulación respecto al margen izquierdo.

Aunque no hay un orden definido, se sugiere escribir primero las capacidades booleanas, luego las numéricas y finalmente las de cadena, cada una ordenada alfabéticamente sin fijarse en mayúsculas o minúsculas. Las capacidades de funciones similares pueden escribirse en una sola línea.

Ejemplo para:

Línea de encabezado: vt|vt101|terminal DEC VT 101 en modo de 80 caracteres:\
Línea de encabezado: Vt|vt101-w|terminal DEC VT 101 en modo (ancho) de 132 caracteres:\
Booleano: :bs:\
Numérico: :co#80:\
Cadena: :sr=\E[H:\

NAME

termcap - terminal capability database

DESCRIPTION

The termcap file, also known as the terminal capability database, is a file that describes the capabilities of various terminals. The name termcap originally stood for terminal capabilities. The file is used by many Unix programs to determine how to handle terminal output, such as cursor movement, screen clearing, text formatting, and other terminal-specific operations. The database is usually located in /usr/share/termcap.

The termcap file format is a text file consisting of entries, where each entry describes a specific terminal type. Each entry starts with a line containing one or more terminal names (aliases) separated by vertical bars (|). These names are used to refer to the terminal type. The subsequent lines in the entry contain the terminal capabilities, which are represented as pairs of characters (termed capability codes) followed by a value or description. The capabilities are divided into three types:

  • Boolean capabilities: These indicate the presence or absence of a particular feature. They are represented by a two-character code.
  • Numeric capabilities: These specify a numerical value, such as the number of columns or rows on the screen. They are represented by a two-character code followed by a number.
  • String capabilities: These describe a sequence of characters used to perform a specific action, such as moving the cursor or clearing the screen. They are represented by a two-character code followed by a string value. String capabilities can also take parameters, which are indicated by special formatting within the string.

A terminal entry can inherit capabilities from other entries by including the name of the parent entry on the first line, preceded by an at symbol (@).

There are several ways of defining the control codes for string capabilities:

Every normal character represents itself, except '^', '\', and '%'.

A ^x means Control-x. Control-A equals 1 decimal.

\x means a special code. x can be one of the following characters:

E Escape (27)
n Linefeed (10)
r Carriage return (13)
t Tabulation (9)
b Backspace (8)
f Form feed (12)
0 Null character. A \xxx specifies the octal character xxx.
i
Increments parameters by one.
r
Single parameter capability
+
Add value of next character to this parameter and do binary output
2
Do ASCII output of this parameter with a field with of 2
d
Do ASCII output of this parameter with a field with of 3
%
Print a '%'

If you use binary output, then you should avoid the null character ('\0') because it terminates the string. You should reset tabulator expansion if a tabulator can be the binary output of a parameter.

Warning:
The above metacharacters for parameters may be wrong: they document Minix termcap which may not be compatible with Linux termcap.
