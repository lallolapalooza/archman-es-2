Advertencia

Esto es material avanzado y complicado. No lo necesitas a menos que sepas realmente lo que estás haciendo. La mayoría de las aplicaciones no lo necesitarán.

Históricamente, PhysicsFS proporcionaba acceso al sistema de archivos físico y a los archivos dentro de ese sistema de archivos. Sin embargo, a veces necesitas más potencia que esto. Quizás necesites proporcionar un archivo que esté completamente contenido en RAM, o necesites interconectar alguna otra API de E/S de archivos a PhysicsFS, o necesites traducir los bits (quizás tienes un archivo .zip estándar que está cifrado, y necesitas descifrarlo sobre la marcha para el archivador zip desprevenido).

Un PHYSFS_Io es la interfaz que los Archivers utilizan para obtener datos de archivo. Históricamente, esto se ha mapeado a E/S de archivos al sistema de archivos físico, pero desde PhysicsFS 2.1, las aplicaciones pueden proporcionar sus propias implementaciones de E/S en tiempo de ejecución.

Esta interfaz no es necesariamente un buen ajuste universal para las E/S. Hay algunos requisitos a tener en cuenta:

  • Solo realizan E/S bloqueante (al menos, por ahora).
  • Necesitan ser capaces de duplicarse. Si tienes un manejador de archivos de fopen(), necesitas poder crear un clon único de él (para que tengamos dos manejadores del mismo archivo que puedan buscar/leer/etc. sin interferir entre sí).
  • Necesitan conocer el tamaño de todo su conjunto de datos.
  • Necesitan ser capaces de buscar y rebobinar bajo demanda.

...en resumen, probablemente no escribirás una implementación HTTP.

Seguridad de hilos: No se garantiza que las implementaciones de PHYSFS_Io sean seguras para hilos por sí mismas. Bajo el capó, donde PhysicsFS las utiliza, la biblioteca proporciona sus propios bloqueos. Si planeas usarlas directamente desde hilos separados, deberías usar mutexes para protegerlas, o no usar el mismo PHYSFS_Io desde dos hilos al mismo tiempo.

void(* PHYSFS_Io::destroy) (struct PHYSFS_Io *io)

Limpiar y liberar la instancia de E/S. Liberar recursos asociados, incluido (opaque) si corresponde.

Esta función siempre debe tener éxito: como tal, devuelve void. El sistema puede llamar a tu método flush() antes que a este. Puedes informar un error allí si es necesario. Es posible que este método todavía se llame si flush() falla, en cuyo caso tendrás que abandonar los datos no vaciados y otras condiciones de fallo y limpiar.

Una vez que este método se llama para una instancia dada, el sistema asumirá que no es seguro volver a tocar esa instancia y descartará cualquier referencia a ella.

Parámetros

s La instancia de E/S a destruir.

struct PHYSFS_Io *(* PHYSFS_Io::duplicate) (struct PHYSFS_Io *io)

Duplicar esta instancia de E/S. Esto debe resultar en una copia completa de este PHYSFS_Io, que pueda vivir completamente independiente. La copia debe ser capaz de realizar todas sus operaciones sin alterar la original, incluido que cada objeto pueda ser destruido por separado (por lo tanto, por ejemplo: no pueden compartir un manejador de archivo; cada uno necesita el suyo).

Si no puedes duplicar un manejador, es legal devolver NULL, pero casi seguro necesitarás esta funcionalidad si quieres usar este PHYSFS_Io para respaldar un archivo.

Parámetros

io La instancia de E/S a duplicar.

Retorna

Un nuevo valor para el campo (opaque) de un stream, o NULL en caso de error.

int(* PHYSFS_Io::flush) (struct PHYSFS_Io *io)

Vaciar recursos a los medios, o donde sea. Esta es la oportunidad de informar errores para escrituras que habían declarado éxito anteriormente, pero que aún tenían la posibilidad de fallar. Este método puede ser NULL si no es necesario vaciar.

Esta función puede llamarse antes de destroy(), ya que puede informar errores y destroy() no puede. También puede llamarse en otros momentos.

Parámetros

io La instancia de E/S a vaciar.

Retorna

Cero en caso de error, distinto de cero en caso de éxito.

PHYSFS_sint64(* PHYSFS_Io::length) (struct PHYSFS_Io *io)

Determinar el tamaño del conjunto de datos de la instancia de E/S. Devolver el número de bytes disponibles en el archivo, o -1 si no se puede determinar. Un fallo será casi seguro fatal para el uso posterior de este stream, por lo que no puedes dejar esto sin implementar.

Parámetros

io La instancia de E/S a consultar.

Retorna

Tamaño total, en bytes, del conjunto de datos.

void* PHYSFS_Io::opaque

Datos de instancia para esta estructura. Cada instancia tiene un puntero asociado con el que se puede almacenar lo que se desee. Este puntero es por instancia del stream, por lo que presumiblemente cambiará al llamar a duplicate(). Esto se puede liberar durante el método destroy().

PHYSFS_sint64(* PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buf, PHYSFS_uint64 len)

Leer más datos. Leer (len) bytes de la interfaz, en la posición actual de E/S, y almacenarlos en (buffer). La posición actual de E/S debe avanzar el número de bytes leídos con éxito.

No tienes que implementar esto; establécelo en NULL si no está implementado. Esto solo se usará si el archivo se abre para lectura. Si se establece en NULL, se utilizará una implementación predeterminada que informa inmediatamente de un fallo.

Parámetros

io La instancia de E/S de la que leer.
buf El búfer donde almacenar los datos. Debe tener al menos (len) bytes de longitud y no puede ser NULL.
len El número de bytes a leer de la interfaz.

Retorna

número de bytes leídos del archivo, 0 en EOF, -1 si hay fallo completo.

NAME

PHYSFS_Io - I/O interface

SYNOPSIS

The PHYSFS_Io structure is an abstract interface that represents an opened file or other I/O stream.

typedef struct PHYSFS_Io {
    PHYSFS_uint32 version;
    void *opaqueData;
    PHYSFS_sint64 (* read)(struct PHYSFS_Io *io, void *buffer, PHYSFS_uint64 len);
    PHYSFS_sint64 (* write)(struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len);
    int (* seek)(struct PHYSFS_Io *io, PHYSFS_uint64 offset);
    PHYSFS_sint64 (* tell)(struct PHYSFS_Io *io);
    int (* close)(struct PHYSFS_Io *io);
    void *priv;
} PHYSFS_Io;

Detailed Description

The PHYSFS_Io structure is an abstract interface that represents an opened file or other I/O stream. It is used by the PhysFS library to read from and write to archives and other sources of data.

Each instance of PHYSFS_Io represents a single opened I/O stream. It contains function pointers that allow PhysFS to interact with the underlying I/O mechanism. These function pointers must be implemented by the user or provided by a PhysFS module.

Field Documentation

int (*PHYSFS_Io::close) (struct PHYSFS_Io *io)

Close the i/o stream. You may not leave this unimplemented, as it will be called when the file is closed. The returned value is ignored.

Parameters

io The i/o instance to close.

void *PHYSFS_Io::opaqueData

A pointer to user-defined data. This is not used by PhysFS itself, but can be used by the underlying implementation to store state.

void *PHYSFS_Io::priv

A pointer to private data. This is intended for internal use by PhysFS modules and should not be accessed directly by the user.

PHYSFS_sint64 (*PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buffer, PHYSFS_uint64 len)

Read data from the i/o stream. Read up to (len) bytes from the stream into the (buffer). The current i/o position should move ahead by the number of bytes successfully read.

You don't have to implement this; set it to NULL if not implemented. This will only be used if the file is opened for reading. If set to NULL, a default implementation that immediately reports failure will be used.

You are allowed to buffer; a read can succeed here and then later fail when flushing. Note that PHYSFS_setBuffer() may be operating a level above your i/o, so you should usually not implement your own buffering routines.

Parameters

io The i/o instance to read from.
buffer The buffer to read data into. It must be at least (len) bytes long and can't be NULL.
len The maximum number of bytes to read into (buffer).

Returns

number of bytes read from file, -1 if complete failure.

int (*PHYSFS_Io::seek) (struct PHYSFS_Io *io, PHYSFS_uint64 offset)

Change the current i/o position. The offset is a byte offset from the beginning of the stream. You must implement this; a failure to do so will be treated as an error.

Parameters

io The i/o instance to seek.
offset The new byte offset for the i/o position.

Returns

non-zero on success, zero on error.

PHYSFS_sint64 (*PHYSFS_Io::tell) (struct PHYSFS_Io *io)

Report current i/o position. Return bytes offset, or -1 if you aren't able to determine. A failure will almost certainly be fatal to further use of this stream, so you may not leave this unimplemented.

Parameters

io The i/o instance to query.

Returns

The current byte offset for the i/o position, -1 if unknown.

PHYSFS_uint32 PHYSFS_Io::version

Binary compatibility information. This must be set to zero at this time. Future versions of this struct will increment this field, so we know what a given implementation supports. We'll presumably keep supporting older versions as we offer new features, though.

PHYSFS_sint64 (*PHYSFS_Io::write) (struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len)

Write more data. Write (len) bytes from (buffer) to the interface at the current i/o position. The current i/o position should move ahead by the number of bytes successfully written.

You don't have to implement this; set it to NULL if not implemented. This will only be used if the file is opened for writing. If set to NULL, a default implementation that immediately reports failure will be used.

You are allowed to buffer; a write can succeed here and then later fail when flushing. Note that PHYSFS_setBuffer() may be operating a level above your i/o, so you should usually not implement your own buffering routines.

Parameters

io The i/o instance to write to.
buffer The buffer to read data from. It must be at least (len) bytes long and can't be NULL.
len The number of bytes to read from (buffer).

Returns

number of bytes written to file, -1 if complete failure.
