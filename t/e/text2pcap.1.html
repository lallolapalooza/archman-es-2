NOMBRE

text2pcap - Genera un archivo de captura a partir de un volcado hexadecimal ASCII de paquetes

SINOPSIS

text2pcap [ -a ] [ -b 2|8|16|64 ] [ -D ] [ -e <ethertype> ] [ -E <tipo de encapsulamiento> ] [ -F <formato de archivo> ] [ -i <proto> ] [ -l <numerotipo> ] [ -N <nombre-intf> ] [ -m <paquete-max> ] [ -o hex|oct|dec|none ] [ -q ] [ -r <regex> ] [ -s <puerto-origen>,<puerto-destino>,<etiqueta> ] [ -S <puerto-origen>,<puerto-destino>,<ppi> ] [ -t <formato-hora> ] [ -T <puerto-origen>,<puerto-destino> ] [ -u <puerto-origen>,<puerto-destino> ] [ -4 <ip-origen>,<ip-destino> ] [ -6 <ip-origen>,<ip-destino> ] [ --little-endian ] <archivo-entrada>|- <archivo-salida>|-

text2pcap -h|--help

text2pcap -v|--version

DESCRIPCIÓN

Text2pcap es un programa que lee un volcado hexadecimal ASCII y escribe los datos descritos en un archivo de captura. text2pcap puede leer volcados hexadecimales con múltiples paquetes y construir un archivo de captura de múltiples paquetes. Text2pcap también es capaz de generar cabeceras Ethernet, IP y UDP, TCP o SCTP ficticias, para construir volcados de paquetes completamente procesables solo a partir de volcados hexadecimales de datos a nivel de aplicación.

Text2pcap puede escribir el archivo en varios formatos de salida. La opción -F se puede usar para especificar el formato en el que se escribirá el archivo de captura; text2pcap -F proporciona una lista de los formatos de salida disponibles. Por defecto, escribe los paquetes en archivo-salida en formato de archivo pcapng. Text2pcap también soporta formatos de compresión, que se pueden especificar con las opciones --compress. Si esa opción no se proporciona, el método de compresión deseado, si lo hay, se deduce de la extensión de archivo-salida; por ejemplo, si tiene la extensión '.gz', el archivo de salida se comprime en un archivo gzip.

Text2pcap entiende muchos formatos diferentes de volcado hexadecimal. El formato nativo que Wireshark muestra en el panel Bytes del Paquete, copia al portapapeles, imprime y guarda, y que tshark produce con la opción --hexdump, es el generado por od -Ax -tx1 -v o hexdump -X -v. Es decir, cada línea debe comenzar con un desplazamiento que describe la posición en el paquete, cada byte se muestra individualmente, con espacios separando los bytes entre sí, y las líneas repetidas o todas NUL ('\0') no se omiten. Los dígitos hexadecimales pueden ser mayúsculas o minúsculas. Text2pcap puede manejar otros formatos de volcado hexadecimal, algunos de los cuales pueden detectarse automáticamente y otros requieren habilitar opciones para reconocerlos correctamente.

Los desplazamientos van seguidos de uno o más espacios o tabulaciones que los separan de los bytes. Opcionalmente, los desplazamientos pueden ir seguidos de dos puntos después de los dígitos. Los desplazamientos pueden tener entre 3 y 8 dígitos; por defecto se asume base hexadecimal (base), pero pueden estar en octal o decimal; consulte -o. Si los desplazamientos están en hexadecimal, pueden ir precedidos por 0x o 0X. Cada paquete debe comenzar con el desplazamiento cero, y un desplazamiento cero indica el inicio de un nuevo paquete. Los valores de desplazamiento deben ser correctos; un valor inesperado provoca la interrupción del paquete actual y la espera del inicio del siguiente paquete. También existe un modo de paquete único sin desplazamientos; consulte -o.

No hay límite en el ancho o número de bytes por línea, pero las líneas que solo contienen bytes hexadecimales sin un desplazamiento inicial se ignoran (en otras palabras, no se deben insertar saltos de línea en líneas largas que se envuelven). Los bytes deben ser hexadecimales; a diferencia de los desplazamientos (y el modo de expresión regular alternativo mencionado más adelante), otras bases como octal, decimal o binario no son compatibles. También se admiten grupos de bytes de dos a cuatro bytes. Por defecto, se asumen grupos de bytes en orden de bytes de red (big-endian); la opción --little-endian se puede usar para soportar el orden de bytes little-endian.

Los paquetes pueden ir precedidos por un indicador de dirección ('I' o 'O') y/o una marca de tiempo si se indica en la línea de comandos (consulte -D y -t). Si ambos están presentes, el indicador de dirección precede a la marca de tiempo. El formato de las marcas de tiempo se especifica como un parámetro obligatorio para -t. Si no se analiza ninguna marca de tiempo, en el caso del primer paquete se utiliza la hora actual del sistema, mientras que los paquetes subsiguientes se escriben con marcas de tiempo un microsegundo posteriores a la del paquete anterior.

Se ignora cualquier otro texto en los datos de entrada. Se ignora cualquier texto antes del desplazamiento, incluidos los caracteres de reenvío de correo electrónico '>'. Se ignora cualquier texto en una línea después de los bytes, por ejemplo, un volcado de caracteres ASCII (pero consulte -a para asegurarse de que los dígitos hexadecimales en el volcado de caracteres se ignoren si no hay un delimitador entre el volcado hexadecimal y la traducción de caracteres ASCII). Se ignorará cualquier línea donde el primer carácter que no sea espacio en blanco sea un '#' como comentario. No se admiten algunos utilitarios de volcado hexadecimal que usan una línea que contiene un solo '*' para indicar líneas omitidas, ya sea duplicando la línea anterior o que consisten enteramente en bytes NUL ('\0'). Cualquier línea de texto entre las líneas de secuencia de bytes se considera preámbulo; el inicio del preámbulo se escanea en busca del indicador de dirección y la marca de tiempo, como se mencionó anteriormente, y de lo contrario se ignora.

Cualquier línea que comience con #TEXT2PCAP es una directiva y se pueden insertar opciones después de este comando para ser procesadas por text2pcap. Actualmente no hay directivas implementadas; en el futuro, estas pueden usarse para dar un control más detallado sobre el volcado y la forma en que debe ser procesado, por ejemplo, marcas de tiempo, tipo de encapsulamiento, etc.

En general, a pesar de estas restricciones, text2pcap es bastante flexible para leer volcados hexadecimales y ha sido probado con una variedad de salidas modificadas (incluida ser reenviado a través de correo electrónico varias veces, con saltos de línea limitados, etc.)

Text2pcap también es capaz de escanear un archivo de entrada de texto usando una expresión regular personalizada compatible con Perl que coincide con un solo paquete. text2pcap busca en el archivo dado (que debe terminar con '\n') cadenas no superpuestas y no vacías que coincidan con la expresión regular. Los subgrupos de captura nombrados, que deben coincidir exactamente una vez por paquete, se utilizan para identificar los campos a importar. Los siguientes campos son compatibles en modo de expresión regular, uno obligatorio y tres opcionales:

"data"  Datos capturados reales a importar
"time"  Marca de tiempo del paquete
"dir"   Dirección del paquete
"seqno" ID arbitrario del paquete

El campo 'data' son los datos capturados, que deben estar en una codificación seleccionada: hexadecimal (la predeterminada), octal, binaria o base64 y que no contenga caracteres en el campo de datos fuera del conjunto de codificación además de los espacios en blanco. El campo 'time' se analiza según el formato en el parámetro -t. El primer carácter del campo 'dir' se compara con un conjunto de caracteres que corresponden a entrante y saliente, que por defecto son "iI<" para entrante y "oO>" para saliente para asignar una dirección. El campo 'seqno' se asume como un entero positivo base 10 utilizado para un ID arbitrario. La información de un campo opcional solo se escribirá si el campo está presente en la expresión regular y si el formato del archivo de captura lo admite. (Por ejemplo, el formato pcapng admite los tres campos, pero el formato pcap solo admite marcas de tiempo).

La expresión regular se compila con soporte multilinea, y se recomienda usar los anclajes '^' y '$' para obtener mejores resultados.

text2pcap también permite al usuario leer volcados de datos a nivel de aplicación e insertar cabeceras dummy L2, L3 y L4 antes de cada paquete. Esto permite que Wireshark o cualquier otro decodificador de paquetes completos maneje estos volcados. Si el tipo de encapsulación es Ethernet, el usuario puede elegir insertar cabeceras Ethernet, Ethernet e IP, o Ethernet, IP y cabeceras UDP/TCP/SCTP antes de cada paquete. Las cabeceras falsas también pueden usarse con las encapsulaciones Raw IP, Raw IPv4 o Raw IPv6, con la cabecera Ethernet omitida. Estas opciones de encapsulación se pueden usar tanto en modo volcado hexadecimal como en modo regex.

Cuando <infile> o <outfile> son '-', se usa la entrada estándar o la salida estándar, respectivamente.

OPCIONES

-a

Habilita la identificación de volcados de texto ASCII. Permite identificar el inicio del volcado de texto ASCII y no incluirlo en el paquete incluso si parece HEX. Este parámetro no tiene efecto en modo regex.

NOTA: No lo habilite si el archivo de entrada no contiene el volcado de texto ASCII, o si el volcado ASCII está separado del volcado hex por un delimitador no en blanco como |.

-b 2|8|16|64

Especifica la base (radio) de la codificación de los datos del paquete en modo regex. Las opciones soportadas son 2 (binario), 8 (octal), 16 (hexadecimal) y 64 (codificación base64), siendo hexadecimal el valor predeterminado. Este parámetro no tiene efecto en modo volcado hexadecimal.

-D

Indica que el texto antes de cada paquete de entrada puede comenzar con una I o una O indicando que el paquete es entrante o saliente. Si se usan tanto esta bandera como la bandera t, el indicador direccional se espera antes del código de tiempo. Este parámetro no tiene efecto en modo regex, donde la presencia del grupo de captura <dir> determina si se esperan indicadores de dirección.

La indicación direccional se almacena en las cabeceras del paquete si el formato de salida lo soporta (p.ej., pcapng), y también se usa al generar cabeceras dummy para intercambiar las direcciones y puertos de origen y destino según corresponda.

-e <ethertype>

Incluye una cabecera Ethernet dummy antes de cada paquete. Especifica el EtherType para la cabecera Ethernet en hexadecimal. Usa esta opción si tu volcado tiene cabecera y carga útil de Capa 3 (p.ej., cabecera IP), pero sin encapsulación de Capa 2. Ejemplo: -e 0x806 para especificar un paquete ARP.

Para paquetes IP, en lugar de generar una cabecera Ethernet falsa, también puedes usar -E rawip o -l 101 para indicar encapsulación IP cruda. Ten en cuenta que la encapsulación IP cruda no funciona para ningún paquete de Capa 3 que no sea IP (p.ej., ARP), mientras que la generación de una cabecera Ethernet dummy con -e funciona para cualquier tipo de paquete L3.

-E <tipo de encapsulación>

Establece el tipo de encapsulación del paquete del archivo de captura de salida. text2pcap -E proporciona una lista de los tipos disponibles; ten en cuenta que no todos los formatos de archivo soportan todos los tipos de encapsulación. El tipo predeterminado es ether (Ethernet).

NOTA: Esto establece el tipo de encapsulación del archivo de salida, pero no traduce las cabeceras del paquete ni agrega cabeceras adicionales. Se utiliza para especificar la encapsulación que coincide con los datos de entrada.

-F <formato de archivo>

Establece el formato de archivo del archivo de captura de salida. text2pcap puede escribir el archivo en varios formatos; text2pcap -F proporciona una lista de los formatos de salida disponibles. El valor predeterminado es el formato pcapng.

-h|--help

Imprime el número de versión y las opciones y sale.

-i <proto>

Incluye cabeceras IP dummy antes de cada paquete. Especifica el protocolo IP para el paquete en decimal. Usa esta opción si tu volcado es la carga útil de un paquete IP (es decir, tiene información L4 completa) pero no tiene una cabecera IP con cada paquete. Ten en cuenta que una cabecera Ethernet apropiada también se incluye automáticamente con cada paquete si el tipo de capa de enlace es Ethernet. Ejemplo: -i 46 para especificar un paquete RSVP (protocolo IP 46). Consulta https://www.iana.org/assignments/protocol-numbers/protocol-numbers.xhtml para la lista completa de números de protocolo de Internet asignados.

-l <typenum>

Establece el tipo de encapsulación del paquete del archivo de captura de salida, utilizando números de tipo de cabecera de capa de enlace pcap. El valor predeterminado es Ethernet (1). Consulta https://www.tcpdump.org/linktypes.html para la lista completa de encapsulaciones posibles. Ejemplo: -l 7 para paquetes ARCNet encapsulados al estilo BSD.

-m <paquete-máx>

Establece la longitud máxima del paquete, por defecto es 262144. Útil para probar diferentes límites de paquete cuando solo se dispone de una transmisión de datos a nivel de aplicación. Ejemplo:

od -Ax -tx1 -v stream | text2pcap -m1460 -T1234,1234 - stream.pcap

convertirá desde formato de transmisión cruda a una secuencia de paquetes TCP Ethernet.

-N <nombre-interfaz>

Especifica un nombre para la interfaz incluida al escribir un archivo en formato pcapng.

-o hex|oct|dec|none

Especifica la base para los desplazamientos (hexadecimal, octal, decimal o ninguno). Predeterminado es hexadecimal. Esto corresponde a la opción -A para od. Este parámetro no tiene efecto en modo regex.

NOTA: Con -o none, solo se creará un paquete, ignorando cualquier indicador de dirección o marca de tiempo después del primer byte junto con cualquier desplazamiento.

-P <disector>

Incluye una cabecera EXPORTED_PDU antes de cada paquete. Especifica, como una cadena, el disector que se llamará para el paquete (etiqueta DISSECTOR_NAME). Usa esta opción si tu volcado es la carga útil de un solo protocolo de capa superior (por lo que especificar un tipo de capa de enlace no funcionaría) y deseas crear un archivo de captura sin una pila de protocolos dummy completa. Establece automáticamente el tipo de capa de enlace a exportación PDU superior de Wireshark. Sin esta opción, si se selecciona el tipo de capa de enlace de exportación PDU superior (252), el disector será por defecto "data".

-q

No muestra el resumen de las opciones seleccionadas al principio, ni el recuento de paquetes procesados al final.

-r <regex>

Procesa el archivo en modo regex utilizando regex como se describe anteriormente.

NOTA: El modo regex utiliza E/S mapeada en memoria y no funciona en flujos que no soportan búsqueda, como terminales y tuberías.

-s <puerto-origen>,<puerto-destino>,<etiqueta>

Incluye cabeceras SCTP dummy antes de cada paquete. Especifica, en decimal, los puertos SCTP de origen y destino, y la etiqueta de verificación, para el paquete. Usa esta opción si tu volcado es la carga útil SCTP de un paquete pero no incluye ninguna cabecera SCTP, IP o Ethernet. Ten en cuenta que también se incluyen automáticamente cabeceras Ethernet e IP apropiadas con cada paquete. Se colocará una suma de verificación CRC32C en la cabecera SCTP.

-S <puerto-origen>,<puerto-destino>,<ppi>

Incluye cabeceras SCTP dummy antes de cada paquete. Especifica, en decimal, los puertos SCTP de origen y destino, y una etiqueta de verificación de 0, para el paquete, y antepone una cabecera de chunk de datos SCTP dummy con un identificador de protocolo de carga útil si ppi. Usa esta opción si tu volcado es la carga útil SCTP de un paquete pero no incluye ninguna cabecera SCTP, IP o Ethernet. Ten en cuenta que también se incluyen automáticamente cabeceras Ethernet e IP apropiadas con cada paquete. Se colocará una suma de verificación CRC32C en la cabecera SCTP.

-t <formato-tiempo>

Trata el texto antes del paquete como un código de fecha/hora; formato-tiempo es una cadena de formato soportada por strftime(3), complementada con el descriptor de campo '%f' para segundos fraccionarios hasta nanosegundos. Ejemplo: La hora "10:15:14.5476" tiene el código de formato "%H:%M:%S.%f". La cadena de formato especial ISO indica que la cadena debe ser analizada según la especificación ISO-8601. Este parámetro se utiliza en modo regex si y solo si está presente el grupo de captura <time>.

NOTA: Los campos de fecha/hora de la fecha/hora actual se utilizan como valor predeterminado para los campos no especificados.

-T <puerto-origen>,<puerto-destino>

Incluye cabeceras TCP dummy antes de cada paquete. Especifica los puertos TCP de origen y destino para el paquete en decimal. Usa esta opción si tu volcado es la carga útil TCP de un paquete pero no incluye ninguna cabecera TCP, IP o Ethernet. Ten en cuenta que también se incluyen automáticamente cabeceras Ethernet e IP apropiadas con cada paquete. Los números de secuencia comenzarán en 0.

-u <puerto-origen>,<puerto-destino>

Incluye cabeceras UDP dummy antes de cada paquete. Especifica los puertos UDP de origen y destino para el paquete en decimal. Usa esta opción si tu volcado es la carga útil UDP de un paquete pero no incluye ninguna cabecera UDP, IP o Ethernet. Ten en cuenta que también se incluyen automáticamente cabeceras Ethernet e IP apropiadas con cada paquete. Ejemplo: -u1000,69 para hacer que los paquetes parezcan paquetes TFTP/UDP.

-v|--version

Imprime la información completa de la versión y sale.

-4 <ip-origen>,<ip-destino>

Antepone una cabecera IP dummy con las direcciones IPv4 de origen y destino especificadas. Esta opción debe ir acompañada de una de las siguientes opciones: -i, -s, -S, -T, -u. Usa esta opción para aplicar direcciones IP "personalizadas". Ejemplo: -4 10.0.0.1,10.0.0.2 para usar 10.0.0.1 y 10.0.0.2 para todos los paquetes IP.

-6 <ip-origen>,<ip-destino>

Antepone una cabecera IP dummy con las direcciones IPv6 de origen y destino especificadas. Esta opción debe ir acompañada de una de las siguientes opciones: -i, -s, -S, -T, -u. Usa esta opción para aplicar direcciones IP "personalizadas". Ejemplo: -6 2001:db8::b3ff:fe1e:8329,2001:0db8:85a3::8a2e:0370:7334 para usar 2001:db8::b3ff:fe1e:8329 y 2001:0db8:85a3::8a2e:0370:7334 para todos los paquetes IP.

--compress <tipo>

Comprime el archivo de salida usando el formato de compresión de tipo. --compress sin argumento proporciona una lista de los compres

OPTIONS

--plugin <name>

A file that contains the dissector to use. If this option is given more than once, the dissectors are registered in the order they are given.

--list-plugins

A list of all available plugins, and the dissectors they contain.

--skip-columns <cols>

Skip columns when reading input. <cols> is a comma-separated list of column numbers (starting from 0).

--print

Print the contents of the input file to standard output.

--no-columns

Do not use columns when reading input.

--capture

Write the output to a pcap file.

--ascii

Write the output in ASCII format.

--hexdump

Write the output in hexdump format.

--hex

Write the output in hex format.

--raw

Write the output in raw format.

--packets

Print packet lengths to standard output.

--separator <sep>

Use <sep> as the separator instead of ",".

--endian <endian>

Write the output using the specified byte order. Supported values are "big" and "little".

--outfile <outfile>

Write the output to the specified file. If this option is not given, the output is written to standard output. The file type is determined by the extension of outfile. If the extension is unknown, the default is pcap.

--file-type <type>

Write the output using the specified file type. Supported types are "pcap", "pcapng", "ipfix", "text", "ascii", "hexdump", "hex", "raw". The type given takes precedence over the extension of outfile.

--little-endian

Treat multiple byte groups as in little-endian byte order, instead of the default, network (big-endian) byte order.

NOTE: This only applies to byte groups. If -a is used, the ASCII dump is still assumed to have the normal ordering.

DIAGNOSTIC OPTIONS

--log-level <level>

Set the active log level. Supported levels in lowest to highest order are "noisy", "debug", "info", "message", "warning", "critical", and "error". Messages at each level and higher will be printed, for example "warning" prints "warning", "critical", and "error" messages and "noisy" prints all messages. Levels are case insensitive.

--log-fatal <level>

Abort the program if any messages are logged at the specified level or higher. For example, "warning" aborts on any "warning", "critical", or "error" messages.

--log-domains <list>

Only print messages for the specified log domains, e.g. "GUI,Epan,sshdump". List of domains must be comma-separated. Can be negated with "!" as the first character (inverts the match).

--log-debug <list>

Force the specified domains to log at the "debug" level. List of domains must be comma-separated. Can be negated with "!" as the first character (inverts the match).

--log-noisy <list>

Force the specified domains to log at the "noisy" level. List of domains must be comma-separated. Can be negated with "!" as the first character (inverts the match).

--log-fatal-domains <list>

Abort the program if any messages are logged for the specified log domains. List of domains must be comma-separated.

--log-file <path>

Write log messages and stderr output to the specified file.
