NOMBRE

text, tk_textCopy, tk_textCut, tk_textPaste - Crear y manipular widgets de edición de hipertexto 'text'

SINOPSIS

text nombreRuta ?opciones?
tk_textCopy nombreRuta
tk_textCut nombreRuta
tk_textPaste nombreRuta

OPCIONES ESPECÍFICAS DEL WIDGET

Nombre de línea de comandos:	-autoseparators
Nombre de base de datos:	autoSeparators
Clase de base de datos:	AutoSeparators
Especifica un booleano que indica si los separadores se insertan automáticamente en la pila de deshacer. Sólo tiene sentido cuando la opción -undo es verdadera.
Nombre de línea de comandos: -blockcursor
Nombre de base de datos: blockCursor
Clase de base de datos: BlockCursor
Especifica un booleano que indica si el cursor de inserción parpadeante debe dibujarse como un bloque rectangular del tamaño de un carácter. Si es falso (por defecto) se utiliza una línea vertical delgada para el cursor de inserción.
Nombre de línea de comandos: -endline
Nombre de base de datos: endLine
Clase de base de datos: EndLine
Especifica un índice de línea entero que representa la línea del almacén textual subyacente que debe estar justo después de la última línea contenida en el widget. Esto permite que un widget de texto refleje sólo una porción de un texto más grande. En lugar de un entero, se puede proporcionar la cadena vacía a esta opción de configuración, lo que configurará el widget para que termine en la última línea del almacén textual.
Nombre de línea de comandos: -height
Nombre de base de datos: height
Clase de base de datos: Height
Especifica la altura deseada para la ventana, en unidades de caracteres de la fuente dada por la opción -font. Debe ser al menos uno.
Nombre de línea de comandos: -inactiveselectbackground
Nombre de base de datos: inactiveSelectBackground
Clase de base de datos: Foreground
Especifica el color a usar para la selección (la etiqueta sel) cuando la ventana no tiene el foco de entrada. Si está vacía, {}, entonces no se muestra selección cuando la ventana no tiene el foco.
Nombre de línea de comandos: -insertunfocussed
Nombre de base de datos: insertUnfocussed
Clase de base de datos: InsertUnfocussed
Especifica cómo mostrar el cursor de inserción cuando el widget no tiene el foco. Debe ser none (por defecto) que significa no mostrar el cursor, hollow que significa mostrar un cuadro hueco, o solid que significa mostrar un cuadro sólido. Tenga en cuenta que hollow y solid aparecerán muy similares cuando la opción -blockcursor es falsa.
Nombre de línea de comandos: -maxundo
Nombre de base de datos: maxUndo
Clase de base de datos: MaxUndo
Especifica el número máximo de acciones de deshacer compuestas en la pila de deshacer. Un valor cero o negativo implica una pila de deshacer ilimitada.
Nombre de línea de comandos: -spacing1
Nombre de base de datos: spacing1
Clase de base de datos: Spacing1
Solicita espacio adicional por encima de cada línea de texto en el widget, utilizando cualquiera de las formas estándar para distancias de pantalla. Si una línea se ajusta, esta opción sólo se aplica a la primera línea en la pantalla. Esta opción puede ser anulada con opciones -spacing1 en etiquetas.
Nombre de línea de comandos: -spacing2
Nombre de base de datos: spacing2
Clase de base de datos: Spacing2
Para las líneas que se ajustan (de modo que cubren más de una línea en la pantalla) esta opción especifica espacio adicional a proporcionar entre las líneas de pantalla que representan una sola línea de texto. El valor puede tener cualquiera de las formas estándar para distancias de pantalla. Esta opción puede ser anulada con opciones -spacing2 en etiquetas.
Nombre de línea de comandos: -spacing3
Nombre de base de datos: spacing3
Clase de base de datos: Spacing3
Solicita espacio adicional debajo de cada línea de texto en el widget, utilizando cualquiera de las formas estándar para distancias de pantalla. Si una línea se ajusta, esta opción sólo se aplica a la última línea en la pantalla. Esta opción puede ser anulada con opciones -spacing3 en etiquetas.
Nombre de línea de comandos: -startline
Nombre de base de datos: startLine
Clase de base de datos: StartLine
Especifica un índice de línea entero que representa la primera línea del almacén textual subyacente que debe ser contenida en el widget. Esto permite que un widget de texto refleje sólo una porción de un texto más grande. En lugar de un entero, se puede proporcionar la cadena vacía a esta opción de configuración, lo que configurará el widget para que comience en la primera línea del almacén textual.
Nombre de línea de comandos: -state
Nombre de base de datos: state
Clase de base de datos: State
Especifica uno de dos estados para el texto: normal o disabled. Si el texto está deshabilitado, no se pueden insertar ni eliminar caracteres y no se mostrará ningún cursor de inserción, incluso si el foco de entrada está en el widget.
Nombre de línea de comandos: -tabs
Nombre de base de datos: tabs
Clase de base de datos: Tabs
Especifica un conjunto de tabulaciones para la ventana. El valor de la opción consiste en una lista de distancias de pantalla que dan las posiciones de las tabulaciones, cada una de las cuales es una distancia relativa al borde izquierdo del widget (excluyendo bordes, relleno, etc.). Cada posición puede estar opcionalmente seguida en el siguiente elemento de la lista por una de las palabras clave left, right, center, o numeric, que especifica cómo justificar el texto en relación con la tabulación. Left es el valor por defecto; hace que el texto que sigue al carácter de tabulación se posicione con su borde izquierdo en la posición de tabulación. Right significa que el borde derecho del texto que sigue al carácter de tabulación se posiciona en la posición de tabulación, y center significa que el texto se centra en la posición de tabulación. Numeric significa que el punto decimal en el texto se posiciona en la posición de tabulación; si no hay punto decimal, entonces el dígito menos significativo del número se posiciona justo a la izquierda de la posición de tabulación; si no hay número en el texto, entonces el texto se justifica a la derecha en la posición de tabulación. Por ejemplo, “-tabs {2c left 4c 6c center}” crea tres tabulaciones en intervalos de dos centímetros; las dos primeras usan justificación izquierda y la tercera usa justificación centrada.

Si la lista de tabulaciones no tiene suficientes elementos para cubrir todas las tabulaciones en una línea de texto, entonces Tk extrapola nuevas tabulaciones utilizando el espaciado y la alineación de la última tabulación de la lista. Las distancias de tabulación deben ser estrictamente positivas, y siempre deben aumentar de una tabulación a la siguiente (si no, se produce un error). El valor de la opción -tabs puede ser anulado por opciones -tabs en etiquetas.

Si no se especifica ninguna opción -tabs, o si se especifica como una lista vacía, entonces Tk utiliza tabulaciones por defecto espaciadas cada ocho caracteres (tamaño promedio). Para lograr un espaciado estándar diferente, por ejemplo cada 4 caracteres, simplemente configure el widget con “-tabs "[expr {4 * [font measure $font 0]}] left" -tabstyle wordprocessor”.

MODIFICADORES DE ÍNDICE

- count ?submodifier? lines
Ajusta el índice hacia atrás en count líneas lógicas, manteniendo la misma posición de carácter dentro de la línea. Si hay menos de count líneas antes de la línea que contiene el índice actual, entonces establece el índice para que apunte a la misma posición de carácter en la primera línea del texto. Luego, si la línea no es lo suficientemente larga como para contener un carácter en la posición de carácter indicada, ajusta la posición de carácter para que apunte al último carácter de la línea (el salto de línea). Los espacios a ambos lados de count son opcionales. Si se proporciona el submodificador display, entonces cada línea de visualización se cuenta por separado. De lo contrario, si se proporciona any (o ningún modificador), entonces cada línea lógica (sin importar cuántas veces se ajuste visualmente) cuenta solo una vez. Si las líneas relevantes no se ajustan, entonces estos dos métodos de conteo son equivalentes.
?submodifier? linestart
Ajusta el índice para que apunte al primer índice de la línea. Si el submodificador display se proporciona, este es el primer índice en la línea de visualización, de lo contrario, en la línea lógica.
?submodifier? lineend
Ajusta el índice para que apunte al último índice de la línea (el salto de línea). Si el submodificador display se proporciona, este es el último índice en la línea de visualización, de lo contrario, en la línea lógica.
?submodifier? wordstart
Ajusta el índice para que apunte al primer carácter de la palabra que contiene el índice actual. Una palabra consiste en cualquier número de caracteres adyacentes que sean letras, dígitos o guiones bajos, o un solo carácter que no sea uno de estos. Si el submodificador display se proporciona, esto solo examina caracteres no elididos, de lo contrario, se examinan todos los caracteres (elididos o no).
?submodifier? wordend
Ajusta el índice para que apunte al carácter justo después del último carácter de la palabra que contiene el índice actual. Si el índice actual apunta al último carácter del texto, entonces no se modifica. Si el submodificador display se proporciona, esto solo examina caracteres no elididos, de lo contrario, se examinan todos los caracteres (elididos o no).

Si hay más de un modificador presente, se aplican en orden de izquierda a derecha. Por ejemplo, el índice “end - 1 chars” se refiere al penúltimo carácter del texto y “insert wordstart - 1 c” se refiere al carácter justo antes del primero en la palabra que contiene el cursor de inserción. Los modificadores se aplican uno por uno en este orden de izquierda a derecha, y después de cada paso, el índice resultante se limita a ser un índice válido en el widget de texto. Por lo tanto, por ejemplo, el índice “1.0 -1c +1c” se refiere al índice “2.0”.

Cuando los modificadores resultan en cambios de índice por líneas de visualización, caracteres de visualización o índices de visualización, y la *base* se refiere a un índice dentro de una etiqueta elidida, esa base se considera equivalente al primer índice no elidido siguiente.

ETIQUETAS

La primera forma de anotación en los widgets de texto es una etiqueta. Una etiqueta es una cadena textual que se asocia con algunos de los caracteres en un texto. Las etiquetas pueden contener caracteres arbitrarios, pero probablemente sea mejor evitar usar los caracteres “ ” (espacio), + o -: estos caracteres tienen un significado especial en los índices, por lo que las etiquetas que los contienen no se pueden usar como índices. Puede haber cualquier número de etiquetas asociadas con los caracteres en un texto. Cada etiqueta puede referirse a un solo carácter, a un rango de caracteres o a varios rangos de caracteres. Un carácter individual puede tener cualquier número de etiquetas asociadas.

Se define un orden de prioridad entre las etiquetas, y este orden se utiliza en la implementación de algunas de las funciones relacionadas con las etiquetas descritas a continuación. Cuando se define una etiqueta (al asociarla con caracteres o al establecer sus opciones de visualización o al vincular comandos a ella), se le da una prioridad mayor que a cualquier etiqueta existente. El orden de prioridad de las etiquetas se puede redefinir utilizando los comandos del widget “*pathName* tag raise” y “*pathName* tag lower”.

Las etiquetas cumplen tres propósitos en los widgets de texto. Primero, controlan la forma en que la información se muestra en la pantalla. Por defecto, los caracteres se muestran según lo determinado por las opciones -background, -font y -foreground del widget de texto. Sin embargo, las opciones de visualización se pueden asociar con etiquetas individuales utilizando el comando del widget “*pathName* tag configure”. Si un carácter ha sido etiquetado, entonces las opciones de visualización asociadas con la etiqueta anulan el estilo de visualización predeterminado. Actualmente se admiten las siguientes opciones para las etiquetas:

-background color
Color especifica el color de fondo a utilizar para los caracteres asociados con la etiqueta. Puede tener cualquiera de las formas aceptadas por Tk_GetColor.
-bgstipple bitmap
Bitmap especifica un mapa de bits que se utiliza como patrón de tramado para el fondo. Puede tener cualquiera de las formas aceptadas por Tk_GetBitmap. Si bitmap no se ha especificado, o si se especifica como una cadena vacía, entonces se utilizará un relleno sólido para el fondo.
-borderwidth pixels
Pixels especifica el ancho de un borde a dibujar alrededor de la etiqueta utilizando cualquiera de las formas aceptadas por Tk_GetPixels. Esta opción debe usarse junto con la opción -relief para proporcionar el borde deseado.
-elide boolean

TAGS

The first form of annotation is a tag. Tags are used to associate attributes with ranges of characters. Any number of tags can be associated with any particular character. Tags are named by strings, and the tags themselves are managed by the pathName tag widget command. Tags are added to ranges of characters using the pathName tag add command, and they can be removed using pathName tag remove. Ranges of characters can be tagged using the pathName tag set command.

Each tag can be associated with a set of display attributes. These attributes control how text that is associated with the tag is displayed. The set of supported display attributes are the same as the options for the text widget itself, except that the options have the form -option instead of option. For example, the foreground color for text with a given tag is specified using the -foreground option for the tag. These options are set using the pathName tag configure command.

The following tag options are supported:

-background color
Color specifies the background color to use for characters associated with the tag. It may have any of the forms accepted by Tk_GetColor. If color has not been specified, or if it is specified as an empty string, then the color used is specified by the -background widget option.
-bgstipple tile
Tile specifies a background stipple pattern to use for characters associated with the tag. It may have any of the forms accepted by Tk_GetBitmap. If tile has not been specified, or if it is specified as an empty string, then no background stipple is used.
-borderwidth borderWidth
Specifies the width of the border to draw around characters associated with the tag. borderWidth must be a non-negative integer. If this option is specified, a border is drawn. If it is not specified or is specified as an empty string, no border is drawn.
-defstrip boolean
This option is intended for use with the default configuration for tags and should not normally be used directly. It is used to indicate whether the default stipple should be used for the background.
-fgstipple tile
Tile specifies a foreground stipple pattern to use for characters associated with the tag. It may have any of the forms accepted by Tk_GetBitmap. If tile has not been specified, or if it is specified as an empty string, then no foreground stipple is used.
-font fontName
FontName specifies the font to use for characters associated with the tag. It may have any of the forms accepted by Tk_GetFont. If fontName has not been specified, or if it is specified as an empty string, then the font specified by the -font widget option is used.
-foreground color
Color specifies the foreground color to use for characters associated with the tag. It may have any of the forms accepted by Tk_GetColor. If color has not been specified, or if it is specified as an empty string, then the color specified by the -foreground widget option is used.
-justify justify
Justify specifies how to justify lines of text associated with this tag. It must be one of left, center, or right. This option only applies to a display line if it applies to the first non-elided character on that display line. If justify has not been specified, or if it is specified as an empty string, then the justification is determined by the -justify widget option.
-lmargin1 pixels
Pixels specifies how much the first line of a paragraph is indented from the left margin. This option only applies to a display line if it applies to the first non-elided character on that display line. If pixels has not been specified, or if it is specified as an empty string, then the indentation is determined by the -lmargin1 widget option.
-lmargin2 pixels
Pixels specifies how much subsequent lines of a paragraph are indented from the left margin. This option only applies to a display line if it applies to the first non-elided character on that display line. If pixels has not been specified, or if it is specified as an empty string, then the indentation is determined by the -lmargin2 widget option.
-offset pixels
Pixels specifies an offset in screen units to apply to the baseline of the text. Positive values raise the text, and negative values lower it. This option only applies to a display line if it applies to the first non-elided character on that display line. If pixels has not been specified, or if it is specified as an empty string, then the offset is determined by the -offset widget option.
-overstrike boolean
Boolean specifies whether or not to draw a horizontal line through the center of characters. It may have any of the forms accepted by Tcl_GetBoolean.
-relief relief
Specifies the relief for the border around characters associated with the tag. The value must be one of raised, sunken, flat, ridge, or groove. This option is ignored if the -borderwidth option is not specified or is zero.
-rmargin pixels
Pixels specifies how much the lines of text associated with this tag are indented from the right margin. This option only applies to a display line if it applies to the first non-elided character on that display line. If pixels has not been specified, or if it is specified as an empty string, then the indentation is determined by the -rmargin widget option.
-rmargincolor color
Color specifies the background color to use in regions that do not contain characters because they are indented by -rmargin. It may have any of the forms accepted by Tk_GetColor. If color has not been specified, or if it is specified as an empty string, then the color used is specified by the -background tag option (or, if this is also unspecified, by the -background widget option).
-selectbackground color
Color specifies the background color to use when displaying selected items. It may have any of the forms accepted by Tk_GetColor. If color has not been specified, or if it is specified as an empty string, then the color specified by the -background tag option is used.
-selectforeground color
Color specifies the foreground color to use when displaying selected items. It may have any of the forms accepted by Tk_GetColor. If color has not been specified, or if it is specified as an empty string, then the color specified by the -foreground tag option is used.
-spacing1 pixels
Pixels specifies how much additional space should be left above each text line, using any of the standard forms for screen distances. If a line wraps, this option only applies to the first line on the display.
-spacing2 pixels
For lines that wrap, this option specifies how much additional space to leave between the display lines for a single text line. Pixels may have any of the standard forms for screen distances.
-spacing3 pixels
Pixels specifies how much additional space should be left below each text line, using any of the standard forms for screen distances. If a line wraps, this option only applies to the last line on the display.
-tabs tabList
TabList specifies a set of tab stops in the same form as for the -tabs option for the text widget. This option only applies to a display line if it applies to the first non-elided character on that display line. If this option is specified as an empty string, it cancels the option, leaving it unspecified for the tag (the default). If the option is specified as a non-empty string that is an empty list, such as -tags { }, then it requests default 8-character tabs as described for the -tags widget option.
-tabstyle style
Style specifies either the tabular or wordprocessor style of tabbing to use for the text widget. This option only applies to a display line if it applies to the first non-elided character on that display line. If this option is specified as an empty string, it cancels the option, leaving it unspecified for the tag (the default).
-underline boolean
Boolean specifies whether or not to draw an underline underneath characters. It may have any of the forms accepted by Tcl_GetBoolean.
-underlinefg color
Color specifies the color to use when displaying the underline. It may have any of the forms accepted by Tk_GetColor. If color has not been specified, or if it is specified as an empty string, then the color specified by the -foreground tag option is used.
-wrap mode
Mode specifies how to handle lines that are wider than the text's window. This option only applies to a display line if it applies to the first non-elided character on that display line. It has the same legal values as the -wrap option for the text widget: none, char, or word. If this tag option is specified, it overrides the -wrap option for the text widget.

If a character has several tags associated with it, and if their display options conflict, then the options of the highest priority tag are used. If a particular display option has not been specified for a particular tag, or if it is specified as an empty string, then that option will never be used; the next-highest-priority tag's option will used instead. If no tag specifies a particular display option, then the default style for the widget will be used.

The second purpose for tags is event bindings. You can associate bindings with a tag in much the same way you can associate bindings with a widget class: whenever particular X events occur on characters with the given tag, a given Tcl command will be executed. Tag bindings can be used to give behaviors to ranges of characters; among other things, this allows hypertext-like features to be implemented. For details, see the description of the “pathName tag bind” widget command below. Tag bindings are shared between all peer widgets (including any bindings for the special sel tag).

The third use for tags is in managing the selection. See THE SELECTION below. With the exception of the special sel tag, all tags are shared between peer text widgets, and may be manipulated on an equal basis from any such widget. The sel tag exists separately and independently in each peer text widget (but any tag bindings to sel are shared).

MARKS

The second form of annotation in text widgets is a mark. Marks are used for remembering particular places in a text. They are something like tags, in that they have names and they refer to places in the file, but a mark is not associated with particular characters. Instead, a mark is associated with the gap between two characters. Only a single position may be associated with a mark at any given time. If the characters around a mark are deleted the mark will still remain; it will just have new neighbor characters. In contrast, if the characters containing a tag are deleted then the tag will no longer have an association with characters in the file. Marks may be manipulated with the “pathName mark” widget command, and their current locations may be determined by using the mark name as an index in widget commands.

Each mark also has a “gravity”, which is either left or right. The gravity for a mark specifies what happens to the mark when text is inserted at the point of the mark. If a mark has left gravity, then the mark is treated as if it were attached to the character on its left, so the mark will remain to the left of any text inserted at the mark position. If the mark has right gravity, new text inserted at the mark position will appear to the left of the mark (so that the mark remains rightmost). The gravity for a mark defaults to right.

The name space for marks is different from that for tags: the same name may be used for both a mark and a tag, but they will refer to different things.

Two marks have special significance. First, the mark insert is associated with the insertion cursor, as described under THE INSERTION CURSOR below. Second, the mark current is associated with the character closest to the mouse and is adjusted automatically to track the mouse position and any changes to the text in the widget (one exception: current is not updated in response to mouse motions if a mouse button is down; the update will be deferred until all mouse buttons have been released). Neither of these special marks may be deleted. With the exception of these two special marks, all marks are shared between peer text widgets, and may be manipulated on an equal basis from any peer.

EMBEDDED WINDOWS

The third form of annotation in text widgets is an embedded window. Each embedded window annotation causes a window to be displayed at a particular point in the text. There may be any number of embedded windows in a text widget, and any widget may be used as an embedded window (subject to the usual rules for geometry management, which require the text window to be the parent of the embedded window or a descendant of its parent).

The embedded window's position on the screen will be updated as the text is modified or scrolled, and it will be mapped and unmapped as it moves into and out of the visible area of the text widget. Each embedded window occupies one unit's worth of index space in the text widget, and it may be referred to either by the name of its embedded window or by its position in the widget's index space. If the range of text containing the embedded window is deleted then the window is destroyed. Similarly if the text widget as a whole is deleted, then the window is destroyed.

Eliding an embedded window immediately after scheduling it for creation via pathName window create index -create will prevent it from being effectively created. Uneliding an elided embedded window scheduled for creation via pathName window create index -create will automatically trigger the associated creation script. After destroying an elided embedded window, the latter won't get automatically recreated.

When an embedded window is added to a text widget with the pathName window create widget command, several configuration options may be associated with it. These options may be modified later with the pathName window configure widget command. The following options are currently supported:

-align where
If the window is not as tall as the line in which it is displayed, this option determines where the window is displayed in the line. Where must have one of the values top (align the top of the window with the top of the line), center (center the window within the range of the line), bottom (align the bottom of the window with the bottom of the line's area), or baseline (align the bottom of the window with the baseline of the line).
-create script
Specifies a Tcl script that may be evaluated to create the window for the text widget.

ANNOTATIONS

The text widget supports annotations. Annotations are used to associate arbitrary data with ranges of characters in the text widget. Annotations are managed using the tag command, and they have a variety of options that control their appearance and behavior. This section describes the options related to annotations, with a focus on embedded windows and images.

-create script
Specifies a script to be evaluated when the annotation is about to be displayed on the screen. If no -window option has been specified for the annotation, this script will be evaluated when the annotation is about to be displayed on the screen. Script must create a window for the annotation and return the name of that window as its result. Two substitutions will be performed in script before evaluation. %W will be substituted by the name of the parent text widget, and %% will be substituted by a single %. If the annotation's window should ever be deleted, script will be evaluated again the next time the annotation is displayed.
-padx pixels
Pixels specifies the amount of extra space to leave on each side of the embedded window. It may have any of the usual forms defined for a screen distance.
-pady pixels
Pixels specifies the amount of extra space to leave on the top and on the bottom of the embedded window. It may have any of the usual forms defined for a screen distance.
-stretch boolean
If the requested height of the embedded window is less than the height of the line in which it is displayed, this option can be used to specify whether the window should be stretched vertically to fill its line. If the -pady option has been specified as well, then the requested padding will be retained even if the window is stretched.
-window pathName
Specifies the name of a window to display in the annotation. Note that if a pathName has been set, then later configuring a window to the empty string will not delete the widget corresponding to the old pathName. Rather it will remove the association between the old pathName and the text widget. If multiple peer widgets are in use, it is usually simpler to use the -create option if embedded windows are desired in each peer.

EMBEDDED IMAGES

The final form of annotation in text widgets is an embedded image. Each embedded image annotation causes an image to be displayed at a particular point in the text. There may be any number of embedded images in a text widget, and a particular image may be embedded in multiple places in the same text widget.

The embedded image's position on the screen will be updated as the text is modified or scrolled. Each embedded image occupies one unit's worth of index space in the text widget, and it may be referred to either by its position in the widget's index space, or the name it is assigned when the image is inserted into the text widget with pathName image create. If the range of text containing the embedded image is deleted then that copy of the image is removed from the screen.

Eliding an embedded image immediately after scheduling it for creation via pathName image create index -create will prevent it from being effectively created. Uneliding an elided embedded image scheduled for creation via pathName image create index -create will automatically trigger the associated creation script. After destroying an elided embedded image, the latter won't get automatically recreated.

When an embedded image is added to a text widget with the pathName image create widget command, a name unique to this instance of the image is returned. This name may then be used to refer to this image instance. The name is taken to be the value of the -name option (described below). If the -name option is not provided, the -image name is used instead. If the imageName is already in use in the text widget, then #nn is added to the end of the imageName, where nn is an arbitrary integer. This insures the imageName is unique. Once this name is assigned to this instance of the image, it does not change, even though the -image or -name values can be changed with pathName image configure.

When an embedded image is added to a text widget with the pathName image create widget command, several configuration options may be associated with it. These options may be modified later with the pathName image configure widget command. The following options are currently supported:

-align where
If the image is not as tall as the line in which it is displayed, this option determines where the image is displayed in the line. Where must have one of the values top (align the top of the image with the top of the line), center (center the image within the range of the line), bottom (align the bottom of the image with the bottom of the line's area), or baseline (align the bottom of the image with the baseline of the line).
-image image
Specifies the name of the Tk image to display in the annotation. If image is not a valid Tk image, then an error is returned.
-name ImageName
Specifies the name by which this image instance may be referenced in the text widget. If ImageName is not supplied, then the name of the Tk image is used instead. If the imageName is already in use, #nn is appended to the end of the name as described above.
-padx pixels
Pixels specifies the amount of extra space to leave on each side of the embedded image. It may have any of the usual forms defined for a screen distance.
-pady pixels
Pixels specifies the amount of extra space to leave on the top and on the bottom of the embedded image. It may have any of the usual forms defined for a screen distance.

THE SELECTION

Selection support is implemented via tags. If the -exportselection option for the text widget is true then the sel tag will be associated with the selection:

[1]
Whenever characters are tagged with sel the text widget will claim ownership of the selection.
[2]
Attempts to retrieve the selection will be serviced by the text widget, returning all the characters with the sel tag.
[3]
If the selection is claimed away by another application or by another window within this application, then the sel tag will be removed from all characters in the text.
[4]
Whenever the sel tag range changes a virtual event <<Selection>> is generated. It might also be generated when selection is affected but not actually changed. Further, multiple selection changes could happen before events can be processed leading to multiple events with the same visible selection.

The sel tag is automatically defined when a text widget is created, and it may not be deleted with the “pathName tag delete” widget command. Furthermore, the -selectbackground, -selectborderwidth, and -selectforeground options for the text widget are tied to the -background, -borderwidth, and -foreground options for the sel tag: changes in either will automatically be reflected in the other. Also the -inactiveselectbackground option for the text widget is used instead of -selectbackground when the text widget does not have the focus. This allows programmatic control over the visualization of the sel tag for foreground and background windows, or to have sel not shown at all (when -inactiveselectbackground is empty) for background windows. Each peer text widget has its own sel tag which can be separately configured and set.

THE INSERTION CURSOR

The mark named insert has special significance in text widgets. It is defined automatically when a text widget is created and it may not be unset with the “pathName mark unset” widget command. The insert mark represents the position of the insertion cursor, and the insertion cursor will automatically be drawn at this point whenever the text widget has the input focus.

THE MODIFIED FLAG

The text widget can keep track of changes to the content of the widget by means of the modified flag. Inserting or deleting text will set this flag. The flag can be queried, set and cleared programmatically as well. Whenever the flag changes state a <<Modified>> virtual event is generated. See the pathName edit modified widget command for more details.

THE UNDO MECHANISM

The text widget has an unlimited undo and redo mechanism (when the -undo widget option is true) which records every insert and delete action on a stack.

Boundaries (called “separators”) are inserted between edit actions. The purpose of these separators is to group inserts, deletes and replaces into one compound edit action. When undoing a change everything between two separators will be undone. The undone changes are then moved to the redo stack, so that an undone edit can be redone again. The redo stack is cleared whenever new edit actions are recorded on the undo stack. The undo and redo stacks can be cleared to keep their depth under control.

Separators are inserted automatically when the -autoseparators widget option is true. You can insert separators programmatically as well. If a separator is already present at the top of the undo stack no other will be inserted. That means that two separators on the undo stack are always separated by at least one insert or delete action.

The <<UndoStack>> virtual event is generated every time the undo stack or the redo stack becomes empty or unempty.

WIDGETS IGUALES

El widget de texto tiene un almacén separado de todos sus datos relativos al contenido textual de cada línea, marcas, etiquetas, imágenes y ventanas, y la pila de deshacer.

Si bien este almacén de datos no se puede acceder directamente (es decir, sin un widget de texto como intermediario), se pueden crear múltiples widgets de texto, cada uno de los cuales presenta diferentes vistas sobre los mismos datos subyacentes. Dichos widgets de texto se conocen como widgets de texto iguales.

A medida que se agrega, elimina, edita y colorea texto en cualquiera de los widgets, y se ajustan imágenes, marcas y etiquetas, todos estos cambios se reflejarán en todos los iguales.

Todos los datos y el marcado se comparten, excepto por algunos pequeños detalles. Primero, la etiqueta sel puede establecerse y configurarse (en su estilo de visualización) de manera diferente para cada igual. Segundo, cada igual tiene sus propias posiciones de marca insert y current (pero todas las demás marcas se comparten). Tercero, las ventanas incrustadas, que son otros widgets arbitrarios, no se pueden compartir entre iguales. Esto significa que la opción -window de las ventanas incrustadas se establece de forma independiente para cada igual (es aconsejable utilizar las capacidades de script -create para permitir que cada igual cree sus propias ventanas incrustadas según sea necesario). Cuarto, todas las opciones de configuración de cada igual (por ejemplo, -font, etc.) se pueden establecer de forma independiente, con la excepción de -undo, -maxundo, -autoseparators (es decir, todos los problemas de estado de deshacer, rehacer y modificado se comparten).

Finalmente, cualquier igual individual no necesita contener todas las líneas del almacén de datos subyacente. Al crear un igual, se puede especificar un rango contiguo de líneas (por ejemplo, solo las líneas 52 a 125). Esto permite que un igual contenga solo una pequeña porción del texto general. El rango de líneas se expandirá y contraerá a medida que se inserte o elimine texto. El igual solo mostrará líneas completas de texto (no se puede compartir solo una parte de una línea). Si el contenido del igual se contrae a nada (es decir, todas las líneas completas en el widget igual se han eliminado de otro widget), entonces es imposible insertar nuevas líneas. El igual simplemente se convertirá en una carcasa vacía sobre la cual se puede configurar el fondo, pero que nunca mostrará ningún contenido (sin una reconfiguración manual de las líneas de inicio y fin). Tenga en cuenta que un igual que no contiene todos los datos del almacén subyacente todavía tiene índices numerados desde "1.0" hasta "end". Es simplemente que esos índices reflejan un subconjunto de los datos totales, y los datos fuera del rango contenido no son accesibles para el igual. Esto significa que el comando peerName index end puede devolver valores bastante diferentes en diferentes iguales. Del mismo modo, comandos como peerName tag ranges no devolverán rangos de índice fuera de lo que es significativo para el igual. Las opciones de configuración -startline y -endline se pueden usar para controlar cuánto de los datos subyacentes está contenido en cualquier widget de texto dado.

Tenga en cuenta que los iguales son realmente iguales. Eliminar el widget de texto "original" no provocará que se eliminen otros iguales ni que se vean afectados de ninguna otra manera.

Ver abajo para el comando del widget pathName peer que controla la creación de widgets iguales.

ACTUALIZACIÓN ASÍNCRONA DE LAS ALTURAS DE LÍNEA

Para mantener una experiencia de usuario receptiva, el widget de texto calcula las métricas de línea (alturas de línea en píxeles) de forma asíncrona. Debido a esto, algunos comandos del widget de texto pueden devolver resultados incorrectos si los cálculos asíncronos no han finalizado en el momento de la llamada. Esto se aplica a pathName count -ypixels y pathName yview.

Nuevamente, por razones de rendimiento, no sería apropiado dejar que estos comandos esperen siempre el final del cálculo de actualización cada vez que se llaman. En la mayoría de los casos de uso de estos comandos, un resultado más o menos inexacto no importa realmente en comparación con la velocidad de ejecución.

En caso de que se necesite un resultado preciso (y si el widget de texto es administrado por un gestor de geometría), se puede recurrir a pathName sync y pathName pendingsync para controlar la sincronización de la vista de los widgets de texto.

El evento virtual <<WidgetViewSync>> se dispara cuando las alturas de línea del widget de texto quedan obsoletas (debido a algún comando de edición o cambio de configuración), y nuevamente cuando los datos internos del widget de texto vuelven a estar sincronizados con la vista del widget. El campo de detalle (%d sustitución) es verdadero (cuando el widget está sincronizado) o falso (cuando no lo está).

pathName sync, pathName pendingsync y <<WidgetViewSync>> se aplican a cada widget de texto independientemente de sus iguales.

Ejemplos de uso:

## Ejemplo 1:
# completa inmediatamente las métricas de línea a cualquier costo (GUI no responde)
$w sync
$w yview moveto $fraction
## Ejemplo 2:
# espera síncronamente métricas de línea actualizadas (GUI responde)
# antes de ejecutar el comando programado, pero no bloquea el flujo de ejecución
$w sync -command [list $w yview moveto $fraction]
## Ejemplo 3:
# inicialización
set yud($w) 0
proc updateaction w {
set ::yud($w) 1
# cualquier otra acción de actualización aquí...
}
# tiempo de ejecución, espera síncronamente métricas de línea actualizadas (GUI responde)
$w sync -command [list updateaction $w]
vwait yud($w)
$w yview moveto $fraction
## Ejemplo 4:
# inicialización
set todo($w) {}
proc updateaction w {
foreach cmd $::todo($w) {uplevel #0 $cmd}
set todo($w) {}
}
# tiempo de ejecución
lappend todo($w) [list $w yview moveto $fraction]
$w sync -command [list updateaction $w]
## Ejemplo 5:
# inicialización
set todo($w) {}
bind $w <<WidgetViewSync>> {
if {%d} {
foreach cmd $todo(%W) {eval $cmd}
set todo(%W) {}
}
}
# tiempo de ejecución
if {![$w pendingsync]} {
$w yview moveto $fraction
} else {
lappend todo($w) [list $w yview moveto $fraction]
}

COMANDO DEL WIDGET

El comando text crea un nuevo comando Tcl cuyo nombre es el mismo que el nombre de ruta de la ventana del texto. Este comando se puede usar para invocar varias operaciones en el widget. Tiene la siguiente forma general:

pathName option ?arg arg ...?
PathName es el nombre del comando, que es el mismo que el nombre de ruta del widget de texto. Option y los args determinan el comportamiento exacto del comando. Los siguientes comandos son posibles para los widgets de texto:
pathName bbox index
Devuelve una lista de cuatro elementos que describen el área de pantalla del carácter dado por index. Los dos primeros elementos de la lista dan las coordenadas x e y de la esquina superior izquierda del área ocupada por el carácter, y los dos últimos elementos dan el ancho y la altura del área. Si el carácter solo es parcialmente visible en la pantalla, el valor de retorno reflejará solo la parte visible. Si el carácter no es visible en la pantalla, el valor de retorno es una lista vacía.
pathName cget option
Devuelve el valor actual de la opción de configuración dada por option. Option puede tener cualquiera de los valores aceptados por el comando text.
pathName compare index1 op index2
Compara los índices dados por index1 y index2 de acuerdo con el operador relacional dado por op, y devuelve 1 si la relación se cumple y 0 si no. Op debe ser uno de los operadores <, <=, ==, >=, >, o !=. Si op es ==, se devuelve 1 si los dos índices se refieren al mismo carácter, si op es <, se devuelve 1 si index1 se refiere a un carácter anterior en el texto que index2, y así sucesivamente.
pathName configure ?option? ?value option value ...?
Consulta o modifica las opciones de configuración del widget. Si no se especifica ningún option, devuelve una lista que describe todas las opciones disponibles para pathName (consulte Tk_ConfigureInfo para obtener información sobre el formato de esta lista). Si se especifica option sin ningún value, el comando devuelve una lista que describe la opción con nombre (esta lista será idéntica a la sublista correspondiente del valor devuelto si no se especifica ningún option). Si se especifican uno o más pares de option-value, el comando modifica las opciones del widget dadas para que tengan los valores dados; en este caso, el comando devuelve una cadena vacía. Option puede tener cualquiera de los valores aceptados por el comando text.
pathName count ?options? index1 index2
Cuenta el número de elementos relevantes entre los dos índices. Si index1 está después de index2, el resultado será un número negativo (y esto se aplica a cada una de las opciones posibles). Los elementos reales que se cuentan dependen de las opciones dadas. El resultado es una lista de enteros, uno para el resultado de cada opción de conteo dada. Las opciones de conteo válidas son -chars, -displaychars, -displayindices, -displaylines, -indices, -lines, -xpixels y -ypixels. El valor predeterminado, si no se especifica ninguna opción, es -indices. Hay una opción adicional posible -update que es un modificador. Si se da (y si el widget de texto es administrado por un gestor de geometría), entonces todas las opciones posteriores aseguran que se recalculará cualquier información posiblemente desactualizada. Esto actualmente solo tiene efecto para el conteo -ypixels (que, si no se da -update, usará el valor en caché actual del widget de texto para cada línea). Esta opción -update está obsoleta por pathName sync, pathName pendingsync y <<WidgetViewSync>>. Las opciones de conteo se interpretan de la siguiente manera:
-chars
cuenta todos los caracteres, estén o no elididos. No cuenta ventanas ni imágenes incrustadas.
-displaychars
cuenta todos los caracteres no elididos.
-displayindices
cuenta todos los caracteres, ventanas e imágenes no elididos.
-displaylines
cuenta todas las líneas di
splay (es decir, contar una por cada vez que una línea se ajusta) desde la línea del primer índice hasta, pero sin incluir, la línea de visualización del segundo índice. Por lo tanto, si ambos están en la misma línea de visualización, se devolverá cero. Por definición, las líneas de visualización son visibles y, por lo tanto, esto solo cuenta porciones de líneas visibles reales.
-indices
contar todos los caracteres y las ventanas o imágenes incrustadas (es decir, todo lo que cuenta en el espacio de índice del widget de texto), ya sea que estén omitidos o no.
-lines
contar todas las líneas lógicas (independientemente del ajuste) desde la línea del primer índice hasta, pero sin incluir, la línea del segundo índice. Por lo tanto, si ambos están en la misma línea, se devolverá cero. Las líneas lógicas se cuentan independientemente de si son visibles (no omitidas) o no.
-xpixels
contar el número de píxeles horizontales desde el primer píxel del primer índice hasta (pero sin incluir) el primer píxel del segundo índice. Para contar el ancho total deseado del widget de texto (asumiendo que el ajuste no está habilitado), primero encuentre la línea más larga y luego use “.text count -xpixels "${line}.0" "${line}.0 lineend"”.
-ypixels
contar el número de píxeles verticales desde el primer píxel del primer índice hasta (pero sin incluir) el primer píxel del segundo índice. Si ambos índices están en la misma línea de visualización, se devolverá cero. Para contar el número total de píxeles verticales en el widget de texto, use “.text count -ypixels 1.0 end”, y para asegurarse de que esté actualizado, use “.text count -update -ypixels 1.0 end”.

El comando devuelve un entero positivo o negativo que corresponde al número de elementos contados entre los dos índices. Se devuelve un entero por cada opción de conteo dada, por lo que se devuelve una lista si se proporcionó más de una opción. Por ejemplo, “.text count -xpixels -ypixels 1.3 4.5” es perfectamente válido y devolverá una lista de dos elementos.

pathName debug ?boolean?
Si se especifica boolean, debe tener uno de los valores verdaderos o falsos aceptados por Tcl_GetBoolean. Si el valor es verdadero, se activarán las comprobaciones internas de consistencia en el código B-tree asociado con los widgets de texto. Si boolean tiene un valor falso, se desactivarán las comprobaciones de depuración. En cualquier caso, el comando devuelve una cadena vacía. Si no se especifica boolean, el comando devuelve on u off para indicar si la depuración está activada o desactivada. Hay un único interruptor de depuración compartido por todos los widgets de texto: activar o desactivar la depuración en cualquier widget la activa o desactiva para todos los widgets. Para widgets con grandes cantidades de texto, las comprobaciones de consistencia pueden causar una desaceleración notable.

Cuando la depuración está activada, las rutinas de dibujo del widget de texto establecen las variables globales tk_textRedraw y tk_textRelayout a las listas de índices que se redibujan. Los valores de estas variables son probados por la suite de pruebas de Tk.

pathName delete index1 ?index2 ...?
Elimina un rango de caracteres del texto. Si se especifican tanto index1 como index2, elimina todos los caracteres que comienzan con el dado por index1 y terminan justo antes de index2 (es decir, el carácter en index2 no se elimina). Si index2 no especifica una posición posterior en el texto que index1, no se eliminan caracteres. Si no se especifica index2, se elimina el único carácter en index1. Los intentos de eliminar caracteres de una manera que deje el texto sin una nueva línea como último carácter serán ajustados por el widget de texto para evitar esto. En particular, la eliminación de líneas completas de texto hasta el final del texto también eliminará el carácter de nueva línea justo antes del bloque eliminado para que sea reemplazado por la nueva línea final del widget de texto. El comando devuelve una cadena vacía. Si se dan más índices, se eliminarán varios rangos de texto. Todos los índices se verifican primero para ver si son válidos antes de realizar cualquier eliminación. Se ordenan y el texto se elimina desde el último rango hasta el primer rango para que el texto eliminado no cause efectos secundarios de desplazamiento de índice no deseados. Si se dan varios rangos con el mismo índice de inicio, se utiliza el rango más largo. Si se dan rangos superpuestos, se fusionarán en segmentos que no causen la eliminación de texto fuera de los rangos dados debido al texto desplazado durante la eliminación.
pathName dlineinfo index
Devuelve una lista con cinco elementos que describen el área ocupada por la línea de visualización que contiene index. Los dos primeros elementos de la lista dan las coordenadas x e y de la esquina superior izquierda del área ocupada por la línea, el tercer y cuarto elemento dan el ancho y la altura del área, y el quinto elemento da la posición de la línea base para la línea, medida hacia abajo desde la parte superior del área. Toda esta información se mide en píxeles. Si el modo de ajuste actual es none y la línea se extiende más allá de los límites de la ventana, el área devuelta refleja toda el área de la línea, incluidas las porciones que están fuera de la ventana. Si la línea es más corta que el ancho total de la ventana, el área devuelta refleja solo la porción de la línea que está ocupada por caracteres y ventanas incrustadas. Si la línea de visualización que contiene index no es visible en la pantalla, el valor de retorno es una lista vacía.
pathName dump ?switches? index1 ?index2?
Devuelve el contenido del widget de texto desde index1 hasta, pero sin incluir, index2, incluido el texto e información sobre marcas, etiquetas y ventanas incrustadas. Si no se especifica index2, se asume por defecto un carácter después de index1. La información se devuelve en el siguiente formato:

key1 value1 index1 key2 value2 index2 ...

Los posibles valores de key son text, mark, tagon, tagoff, image y window. El valor correspondiente es el texto, el nombre de la marca, el nombre de la etiqueta, el nombre de la imagen o el nombre de la ventana. La información de index es el índice del inicio del texto, marca, transición de etiqueta, imagen o ventana. Se pueden especificar una o más de las siguientes opciones (o abreviaturas) para controlar el volcado:

-all
Devuelve información sobre todos los elementos: texto, marcas, etiquetas, imágenes y ventanas. Este es el valor predeterminado.
-command command
En lugar de devolver la información como resultado de la operación de volcado, invoca el command en cada elemento del widget de texto dentro del rango. El comando tiene tres argumentos añadidos antes de ser evaluado: la key, el value y el index.
-image
Incluye información sobre imágenes en los resultados del volcado.
-mark
Incluye información sobre marcas en los resultados del volcado.
-tag
Incluye información sobre transiciones de etiquetas en los resultados del volcado. La información de etiquetas se devuelve como elementos tagon y tagoff que indican el inicio y el final de cada rango de cada etiqueta, respectivamente.
-text
Incluye información sobre texto en los resultados del volcado. El valor es el texto hasta el siguiente elemento o el final del rango indicado por index2. Un elemento de texto no abarca nuevas líneas. Un bloque de texto de varias líneas que no contiene marcas ni transiciones de etiquetas se volcará todavía como un conjunto de segmentos de texto que cada uno termina con una nueva línea. La nueva línea es parte del valor.
-window
Incluye información sobre ventanas incrustadas en los resultados del volcado. El valor de una ventana es su ruta de Tcl, a menos que la ventana aún no se haya creado. (Debe tener un script de creación.) En este caso, se devuelve una cadena vacía, y debe consultar la ventana por su posición de índice para obtener más información.
pathName edit option ?arg arg ...?
Este comando controla el mecanismo de deshacer y el indicador de modificación. El comportamiento exacto del comando depende del argumento option que sigue al argumento edit. Actualmente se admiten las siguientes formas del comando:
pathName edit canredo
Devuelve un booleano verdadero si se puede rehacer, es decir, cuando la pila de rehacer no está vacía. De lo contrario, devuelve falso.
pathName edit canundo
Devuelve un booleano verdadero si se puede deshacer, es decir, cuando la pila de deshacer no está vacía. De lo contrario, devuelve falso.
pathName edit modified ?boolean?
Si no se especifica boolean, devuelve el indicador de modificación del widget. Los comandos de inserción, eliminación, edición de deshacer y edición de rehacer o el usuario pueden establecer o borrar el indicador de modificación. Si se especifica boolean, establece el indicador de modificación del widget a boolean.
pathName edit redo
Cuando la opción -undo es verdadera, vuelve a aplicar las últimas ediciones deshechas siempre que no se hayan realizado otras ediciones desde entonces. Genera un error cuando la pila de rehacer está vacía. No hace nada cuando la opción -undo es falsa.
pathName edit reset
Borra las pilas de deshacer y rehacer.
pathName edit separator
Inserta un separador (límite) en la pila de deshacer. No hace nada cuando la opción -undo es falsa.
pathName edit undo
Deshace la última acción de edición cuando la opción -undo es verdadera. Una acción de edición se define como todos los comandos de inserción y eliminación que un
regrabado en la pila de deshacer entre dos separadores. Genera un error cuando la pila de deshacer está vacía. No hace nada cuando la opción -undo es falsa.
nombreRuta get ?-displaychars? ?--? índice1 ?índice2 ...?
Devuelve un rango de caracteres del texto. El valor devuelto serán todos los caracteres del texto comenzando por el cuyo índice es índice1 y terminando justo antes del cuyo índice es índice2 (el carácter en índice2 no será devuelto). Si se omite índice2, se devuelve el único carácter en índice1. Si no hay caracteres en el rango especificado (por ejemplo, índice1 está después del final del archivo o índice2 es menor o igual que índice1), se devuelve una cadena vacía. Si el rango especificado contiene ventanas incrustadas, no se incluye información sobre ellas en la cadena devuelta. Si se dan múltiples pares de índices, se devolverán múltiples rangos de texto en una lista. Los rangos inválidos no se representarán con cadenas vacías en la lista. Los rangos se devuelven en el orden en que se pasaron a nombreRuta get. Si se proporciona la opción -displaychars, entonces, dentro de cada rango, solo se devolverán aquellos caracteres que no estén elididos. Esto puede tener el efecto de que algunos de los rangos devueltos sean cadenas vacías.
nombreRuta image opción ?arg arg ...?
Este comando se utiliza para manipular imágenes incrustadas. El comportamiento del comando depende del argumento opción que sigue al argumento image. Actualmente se admiten las siguientes formas del comando:
nombreRuta image cget índice opción
Devuelve el valor de una opción de configuración para una imagen incrustada. Índice identifica la imagen incrustada y opción especifica una opción de configuración particular, que debe ser una de las listadas en la sección IMÁGENES INCRUSTADAS.
nombreRuta image configure índice ?opción valor ...?
Consulta o modifica las opciones de configuración de una imagen incrustada. Si no se especifica ninguna opción, devuelve una lista que describe todas las opciones disponibles para la imagen incrustada en índice (consulte Tk_ConfigureInfo para obtener información sobre el formato de esta lista). Si se especifica opción sin valor, el comando devuelve una lista que describe la única opción nombrada (esta lista será idéntica a la sublista correspondiente del valor devuelto si no se especifica ninguna opción). Si se especifican una o más parejas opción-valor, el comando modifica la(s) opción(es) dada(s) para que tengan el(los) valor(es) dado(s); en este caso, el comando devuelve una cadena vacía. Consulte IMÁGENES INCRUSTADAS para obtener información sobre las opciones admitidas.
nombreRuta image create índice ?opción valor ...?
Este comando crea una nueva anotación de imagen, que aparecerá en el texto en la posición dada por índice. Se pueden especificar cualquier número de parejas opción-valor para configurar la anotación. Devuelve un identificador único que puede utilizarse como índice para referirse a esta imagen. Consulte IMÁGENES INCRUSTADAS para obtener información sobre las opciones admitidas y una descripción del identificador devuelto.
nombreRuta image names
Devuelve una lista cuyos elementos son los nombres de todas las instancias de imagen actualmente incrustadas en ventana.
nombreRuta index índice
Devuelve la posición correspondiente a índice en el formato línea.carácter, donde línea es el número de línea y carácter es el número de carácter. Índice puede tener cualquiera de los formatos descritos en ÍNDICES anteriormente.
nombreRuta insert índice chars ?tagList chars tagList ...?
Inserta todos los argumentos chars justo antes del carácter en índice. Si índice se refiere al final del texto (el carácter después de la última nueva línea), el nuevo texto se inserta justo antes de la última nueva línea en su lugar. Si hay un solo argumento chars y ningún tagList, el nuevo texto recibirá las etiquetas que estén presentes tanto en el carácter anterior como en el carácter posterior al punto de inserción; si una etiqueta está presente en solo uno de estos caracteres, no se aplicará al nuevo texto. Si se especifica tagList, consiste en una lista de nombres de etiquetas; los nuevos caracteres recibirán todas las etiquetas de esta lista y ninguna otra, independientemente de las etiquetas presentes alrededor del punto de inserción. Si hay varios pares de argumentos chars-tagList, producen el mismo efecto que si se hubiera emitido un comando de widget nombreRuta insert separado para cada par, en orden. El último argumento tagList puede omitirse.
nombreRuta mark opción ?arg arg ...?
Este comando se utiliza para manipular marcas. El comportamiento exacto del comando depende del argumento opción que sigue al argumento mark. Actualmente se admiten las siguientes formas del comando:
nombreRuta mark gravity nombreMarca ?dirección?
Si no se especifica dirección, devuelve left o right para indicar a cuál de sus caracteres adyacentes está adjunta nombreMarca. Si se especifica dirección, debe ser left o right; la gravedad de nombreMarca se establece en el valor dado.
nombreRuta mark names
Devuelve una lista cuyos elementos son los nombres de todas las marcas que están actualmente establecidas.
nombreRuta mark next índice
Devuelve el nombre de la siguiente marca en o después de índice. Si índice se especifica en forma numérica, la búsqueda de la siguiente marca comienza en ese índice. Si índice es el nombre de una marca, la búsqueda de la siguiente marca comienza inmediatamente después de esa marca. Esto aún puede devolver una marca en la misma posición si hay múltiples marcas en el mismo índice. Estas semánticas significan que la operación mark next puede usarse para recorrer todas las marcas en un widget de texto en el mismo orden que la información de marcas devuelta por la operación nombreRuta dump. Si una marca se ha establecido en el índice especial end, parece estar *después* de end con respecto a la operación nombreRuta mark next. Se devuelve una cadena vacía si no hay marcas después de índice.
nombreRuta mark previous índice
Devuelve el nombre de la marca en o antes de índice. Si índice se especifica en forma numérica, la búsqueda de la marca anterior comienza con el carácter justo antes de ese índice. Si índice es el nombre de una marca, la búsqueda de la siguiente marca comienza inmediatamente antes de esa marca. Esto aún puede devolver una marca en la misma posición si hay múltiples marcas en el mismo índice. Estas semánticas significan que la operación nombreRuta mark previous puede usarse para recorrer todas las marcas en un widget de texto en orden inverso al de la información de marcas devuelta por la operación nombreRuta dump. Se devuelve una cadena vacía si no hay marcas antes de índice.
nombreRuta mark set nombreMarca índice
Establece la marca llamada nombreMarca en una posición justo antes del carácter en índice. Si nombreMarca ya existe, se mueve de su antigua posición; si no existe, se crea una nueva marca. Este comando devuelve una cadena vacía.
nombreRuta mark unset nombreMarca ?nombreMarca nombreMarca ...?
Elimina la marca correspondiente a cada uno de los argumentos nombreMarca. Las marcas eliminadas no serán utilizables en índices y no serán devueltas por futuras llamadas a “nombreRuta mark names”. Este comando devuelve una cadena vacía.
nombreRuta peer opción args
Este comando se utiliza para crear y consultar pares de widgets. Tiene dos formas, dependiendo de opción:
nombreRuta peer create nuevoNombreRuta ?opciones?
Crea un widget par de texto con el nuevoNombreRuta dado, y cualquier opción de configuración estándar opcional (como para el comando text). Por defecto, el par tendrá la misma línea de inicio y fin que el widget padre, pero estas pueden ser anuladas con las opciones de configuración estándar.
nombreRuta peer names
Devuelve una lista de pares de este widget (esto no incluye el widget en sí). El orden dentro de esta lista no está definido.
nombreRuta pendingsync
Devuelve 1 si los cálculos de altura de línea no están actualizados, 0 en caso contrario.
nombreRuta replace índice1 índice2 chars ?tagList chars tagList ...?
Reemplaza el rango de caracteres entre índice1 y índice2 con los caracteres y etiquetas dados. Consulte la sección sobre nombreRuta insert para una explicación del manejo de los argumentos tagList..., y la sección sobre nombreRuta delete para una explicación del manejo de los índices. Si índice2 corresponde a un índice anterior en el texto que índice1, se generará un error.

La eliminación y la inserción se organizan de modo que no se produzca un desplazamiento innecesario de la ventana ni un movimiento del cursor de inserción. Además, las pilas de deshacer/rehacer se modifican correctamente, si las operaciones de deshacer están activas en el widget de texto. El comando devuelve una cadena vacía.

pathName scan option args
Este comando se utiliza para implementar el escaneo en textos. Tiene dos formas, dependiendo de option:
pathName scan mark x y
Registra x e y y la vista actual en la ventana de texto, para su uso en conjunción con comandos posteriores de pathName scan dragto. Normalmente, este comando se asocia con una pulsación de botón del ratón en el widget. Devuelve una cadena vacía.
pathName scan dragto x y
Este comando calcula la diferencia entre sus argumentos x e y y los argumentos x e y del último comando pathName scan mark para el widget. Luego, ajusta la vista en 10 veces la diferencia en las coordenadas. Este comando normalmente se asocia con eventos de movimiento del ratón en el widget, para producir el efecto de arrastrar el texto a alta velocidad a través de la ventana. El valor de retorno es una cadena vacía.
pathName search ?switches? pattern index ?stopIndex?
Busca el texto en pathName comenzando en index para un rango de caracteres que coincida con pattern. Si se encuentra una coincidencia, se devuelve el índice del primer carácter de la coincidencia como resultado; de lo contrario, se devuelve una cadena vacía. Se pueden especificar uno o más de los siguientes modificadores (o abreviaturas de los mismos) para controlar la búsqueda:
-forwards
La búsqueda procederá hacia adelante a través del texto, encontrando el primer rango coincidente que comience en o después de la posición dada por index. Este es el valor predeterminado.
-backwards
La búsqueda procederá hacia atrás a través del texto, encontrando el rango coincidente más cercano a index cuyo primer carácter esté antes de index (no se permite que esté en index). Tenga en cuenta que, por una variedad de razones, las búsquedas hacia atrás pueden ser sustancialmente más lentas que las búsquedas hacia adelante (particularmente cuando se usa -regexp), por lo que se recomienda que el código crítico para el rendimiento utilice búsquedas hacia adelante.
-exact
Utilice coincidencia exacta: los caracteres en el rango coincidente deben ser idénticos a los de pattern. Este es el valor predeterminado.
-regexp
Trate pattern como una expresión regular y coincídala con el texto utilizando las reglas para expresiones regulares (consulte el comando regexp y la página re_syntax para obtener detalles). La coincidencia predeterminada pasa automáticamente tanto las opciones -lineanchor como -linestop al motor regexp (a menos que se use -nolinestop), de modo que ^$ coincida con el principio y el fin de línea, y ., [^ las secuencias nunca coincidirán con el carácter de nueva línea \n.
-nolinestop
Esto permite que . y [^ las secuencias coincidan con el carácter de nueva línea \n, lo que de lo contrario no harán (consulte el comando regexp para obtener detalles). Esta opción solo es significativa si también se proporciona -regexp, y de lo contrario se producirá un error. Por ejemplo, para coincidir con todo el texto, use “pathName search -nolinestop -regexp ".*" 1.0”.
-nocase
Ignore las diferencias de mayúsculas y minúsculas entre el patrón y el texto.
-count varName
El argumento que sigue a -count da el nombre de una variable; si se encuentra una coincidencia, el número de posiciones de índice entre el principio y el final del rango coincidente se almacenará en la variable. Si no hay imágenes o ventanas incrustadas en el rango coincidente (y no hay caracteres omitidos si no se proporciona -elide), esto es equivalente al número de caracteres coincidentes. En cualquier caso, el rango matchIdx a matchIdx + $count chars devolverá todo el texto coincidente.
-all
Encuentra todas las coincidencias en el rango dado y devuelve una lista de los índices del primer carácter de cada coincidencia. Si se proporciona un modificador -count varName, entonces varName también se establece en una lista que contiene un elemento para cada coincidencia exitosa. Tenga en cuenta que, incluso para búsquedas exactas, los elementos de esta lista pueden ser diferentes, si hay imágenes, ventanas o texto oculto incrustados. Las búsquedas con -all se comportan de manera muy similar al comando Tcl regexp -all, en el sentido de que las coincidencias superpuestas normalmente no se devuelven. Por ejemplo, aplicar una búsqueda -all del patrón “\w+” a “hello there” solo coincidirá dos veces, una por cada palabra, y al hacer coincidir “Z[a-z]+Z” con “ZooZooZoo” solo coincidirá una vez.
-overlap
Al realizar búsquedas -all, el comportamiento normal es que no se devuelven las coincidencias que se superponen a una coincidencia ya encontrada. Este modificador cambia ese comportamiento para que se devuelvan todas las coincidencias que no están totalmente incluidas dentro de otra coincidencia. Por ejemplo, aplicar una búsqueda -overlap del patrón “\w+” a “hello there” solo coincidirá dos veces (es decir, no diferente a solo -all), pero al hacer coincidir “Z[a-z]+Z” con “ZooZooZoo” ahora coincidirá dos veces. Se producirá un error si este modificador se utiliza sin -all.
-strictlimits
Al realizar cualquier búsqueda, el comportamiento normal es que los límites de inicio y fin se verifican con respecto al inicio del texto coincidente. Con la bandera -strictlimits, todo el rango coincidente debe estar dentro de los límites de inicio y fin especificados para que la coincidencia sea válida.
-elide
Busca también texto omitido (oculto). Por defecto, solo se busca el texto visible.
--
Este modificador no tiene ningún efecto excepto terminar la lista de modificadores: el siguiente argumento se tratará como pattern incluso si comienza con -.

El rango coincidente puede estar dentro de una sola línea de texto, o abarcar múltiples líneas (si partes del patrón pueden coincidir con una nueva línea). Para la coincidencia de expresiones regulares, se pueden utilizar las diversas características de coincidencia de nuevas líneas como $ para coincidir con el final de una línea, ^ para coincidir con el principio de una línea y para controlar si se permite que . coincida con una nueva línea. Si se especifica stopIndex, la búsqueda se detiene en ese índice: para búsquedas hacia adelante, no se considerará ninguna coincidencia en o después de stopIndex; para búsquedas hacia atrás, no se considerará ninguna coincidencia anterior en el texto que stopIndex. Si se omite stopIndex, se buscará todo el texto: cuando se alcance el principio o el final del texto, la búsqueda continuará en el otro extremo hasta que se vuelva a alcanzar la ubicación de inicio; si se especifica stopIndex, no se producirá ninguna envoltura. Esto significa que, por ejemplo, si la búsqueda es -forwards pero stopIndex está más atrás en el texto que startIndex, nunca se encontrará nada. Los únicos eventos para los cuales se pueden especificar asociaciones son aquellos relacionados con el ratón y el teclado (como Enter, Leave, ButtonPress, Motion y KeyPress) o eventos virtuales. Las asociaciones de eventos de ratón y teclado para un widget de texto utilizan respectivamente las marcas current e insert descritas en MARCAS anteriormente. Un evento Enter se activa para una etiqueta cuando la etiqueta se vuelve presente por primera vez en el carácter actual, y un evento Leave se activa para una etiqueta cuando deja de estar presente en el carácter actual. Los eventos Enter y Leave pueden ocurrir ya sea porque la marca current se movió o porque el carácter en esa posición cambió. Tenga en cuenta que estos eventos son diferentes de los eventos Enter y Leave para ventanas. Los eventos del ratón se dirigen al carácter actual, mientras que los eventos del teclado se dirigen al carácter de inserción. Si se utiliza un evento virtual en una asociación, esa asociación solo se puede activar si el evento virtual está definido por un evento subyacente relacionado con el ratón o el teclado.

Es posible que el carácter actual tenga varias etiquetas, y que cada una de ellas tenga una asociación para una secuencia de eventos particular. Cuando esto ocurre, se invoca una asociación por cada etiqueta, en orden de prioridad más baja a más alta. Si hay varias asociaciones que coinciden para una sola etiqueta, se elige la asociación más específica (ver la entrada del manual del comando bind para más detalles). Los comandos continue y break dentro de los scripts de asociación se procesan de la misma manera que para las asociaciones creadas con el comando bind.

Si se crean asociaciones para el widget en su conjunto utilizando el comando bind, estas asociaciones complementarán las asociaciones de etiquetas. Las asociaciones de etiquetas se invocarán primero, seguidas de las asociaciones para la ventana en su conjunto.

Returns the bounding box of the character at index in the window's coordinate system. The value returned is a list of four integers, giving the x and y coordinates of the upper-left corner followed by the x and y coordinates of the lower-right corner. }

pathName xview ?args?
This command is used to query and change the horizontal position of the text in the widget's window. It can take any of the following forms:
pathName xview
Returns a list containing two elements. Each element is a real fraction between 0 and 1; together they describe the portion of the document's horizontal span that is visible in the window. For example, if the first element is .2 and the second element is .6, 20% of the text is off-screen to the left, the middle 40% is visible in the window, and 40% of the text is off-screen to the right. The fractions refer only to the lines that are actually visible in the window: if the lines in the window are all very short, so that they are entirely visible, the returned fractions will be 0 and 1, even if there are other lines in the text that are much wider than the window. These are the same values passed to scrollbars via the -xscrollcommand option.
pathName xview moveto fraction
Adjusts the view in the window so that fraction of the horizontal span of the text is off-screen to the left. Fraction is a fraction between 0 and 1.
pathName xview scroll number what
This command shifts the view in the window left or right according to number and what. What must be units, pages or pixels. If what is units or pages then number must be an integer, otherwise number may be specified in any of the forms acceptable to Tk_GetPixels, such as “2.0c” or “1i” (the result is rounded to the nearest integer value. If no units are given, pixels are assumed). If what is units, the view adjusts left or right by number average-width characters on the display; if it is pages then the view adjusts by number screenfuls; if it is pixels then the view adjusts by number pixels. If number is negative then characters farther to the left become visible; if it is positive then characters farther to the right become visible.
pathName yview ?args?
This command is used to query and change the vertical position of the text in the widget's window. It can take any of the following forms:
pathName yview
Returns a list containing two elements, both of which are real fractions between 0 and 1. The first element gives the position of the first visible pixel of the first character (or image, etc) in the top line in the window, relative to the text as a whole (0.5 means it is halfway through the text, for example). The second element gives the position of the first pixel just after the last visible one in the bottom line of the window, relative to the text as a whole. These are the same values passed to scrollbars via the -yscrollcommand option.
pathName yview moveto fraction
Adjusts the view in the window so that the pixel given by fraction appears at the top of the top line of the window. Fraction is a fraction between 0 and 1; 0 indicates the first pixel of the first character in the text, 0.33 indicates the pixel that is one-third the way through the text; and so on. Values close to 1 will indicate values close to the last pixel in the text (1 actually refers to one pixel beyond the last pixel), but in such cases the widget will never scroll beyond the last pixel, and so a value of 1 will effectively be rounded back to whatever fraction ensures the last pixel is at the bottom of the window, and some other pixel is at the top.

This command adjust the view in the window up or down according to number and what. What must be units, pages or pixels. If what is units or pages then number must be an integer, otherwise number may be specified in any of the forms acceptable to Tk_GetPixels, such as “2.0c” or “1i” (the result is rounded to the nearest integer value. If no units are given, pixels are assumed). If what is units, the view adjusts up or down by number lines on the display; if it is pages then the view adjusts by number screenfuls; if it is pixels then the view adjusts by number pixels. If number is negative then earlier positions in the text become visible; if it is positive then later positions in the text become visible.

[1]
If index is already visible somewhere in the window then the command does nothing.
[2]

[3]

[4]

The -pickplace option has been obsoleted by the pathName see widget command (pathName see handles both x- and y-motion to make a location visible, whereas the -pickplace mode only handles motion in y).

pathName yview number
This command makes the first character on the line after the one given by number visible at the top of the window. Number must be an integer. This command used to be used for scrolling, but now it is obsolete.

ASUNTOS PENDIENTES

ASUNTOS RELACIONADOS CON CARACTERES E INDICES

Antes de Tk 8.5, el widget usaba la cadena "chars" para referirse a posiciones de índice (que incluían caracteres, ventanas incrustadas e imágenes incrustadas). A partir de Tk 8.5, el widget de texto maneja por separado y correctamente "chars" e "indices". Sin embargo, para compatibilidad retroactiva, los modificadores de índice "+N chars" y "-N chars" continúan refiriéndose a índices. Se deben usar cualquiera de las formas completas "+N any chars" o "-N any chars", etc. para referirse a índices de caracteres reales. Esta confusión puede corregirse en una versión futura haciendo que el widget interprete correctamente "+N chars" como un sinónimo de "+N any chars".

ASUNTOS DE RENDIMIENTO

Los widgets de texto deberían ejecutarse de manera eficiente en una variedad de condiciones. El widget de texto utiliza aproximadamente 2-3 bytes de memoria principal por cada byte de texto, por lo que textos que contengan un megabyte o más deberían ser prácticos en la mayoría de las estaciones de trabajo. El texto se representa internamente con una estructura B-tree modificada que hace que las operaciones sean relativamente eficientes incluso con textos grandes. Las etiquetas se incluyen en la estructura B-tree de manera que permiten que las etiquetas abarquen rangos grandes o tengan muchos rangos pequeños y disjuntos sin pérdida de eficiencia. Las marcas también se implementan de manera que permiten un gran número de marcas. En la mayoría de los casos, está bien tener un gran número de etiquetas únicas, o una etiqueta que tenga muchos rangos distintos.

Un problema de rendimiento puede surgir si tiene cientos o miles de etiquetas diferentes que todas tienen las siguientes características: el primer y último rango de cada etiqueta están cerca del principio y del final del texto, respectivamente, o un único rango de etiqueta cubre la mayor parte del widget de texto. El costo de agregar y eliminar etiquetas como estas es proporcional al número de otras etiquetas con las mismas propiedades. En contraste, no hay problema con tener miles de etiquetas distintas si sus rangos generales están localizados y distribuidos uniformemente por todo el texto.

Las líneas de texto muy largas pueden ser costosas, especialmente si tienen muchas marcas y etiquetas dentro de ellas.

La línea de visualización con el cursor de inserción se redibuja cada vez que el cursor parpadea, lo que causa un flujo constante de tráfico gráfico. Establezca el atributo -insertofftime a 0 para evitar esto.

ERRORES CONOCIDOS

El subcomando pathName search -regexp intenta realizar coincidencias sofisticadas de expresiones regulares en múltiples líneas de manera eficiente (desde Tk 8.5), examinando cada línea individualmente y luego en pequeños grupos de líneas, ya sea buscando hacia adelante o hacia atrás. Bajo ciertas condiciones, el resultado de la búsqueda puede diferir del obtenido al aplicar la misma expresión regular a todo el texto del widget de una sola vez. Por ejemplo, al buscar con una expresión regular codiciosa, el widget continuará intentando agregar líneas adicionales a la coincidencia siempre que se cumpla una de las dos condiciones: o bien la biblioteca de expresiones regulares de Tcl devuelve un código que indica que es posible una coincidencia más larga (pero existen errores conocidos en Tcl que significan que este código no siempre se devuelve correctamente); o si cada línea adicional agregada resulta en al menos una coincidencia parcial con el patrón. Esto significa que en el caso en que la primera línea adicional agregada no resulte en ninguna coincidencia y el sistema de expresiones regulares de Tcl devuelva el código incorrecto y agregar una segunda línea adicional coincidiría, el widget de texto devolverá el resultado incorrecto. En la práctica, este es un problema raro, pero puede ocurrir, por ejemplo:

pack [text .t]
.t insert 1.0 "aaaa\nbbbb\ncccc\nbbbb\naaaa\n"
.t search -regexp -- {(a+|b+\nc+\nb+)+\na+} 1.0
no encontrará una coincidencia cuando existe una de 19 caracteres que comienza en la primera "b".

Siempre que una coincidencia posible esté completamente incluida en otra, el comando de búsqueda intentará asegurar que solo se devuelva la coincidencia más grande. Al realizar búsquedas de expresiones regulares hacia atrás, es posible que Tcl no siempre logre esto, en el caso en que una coincidencia esté precedida por una o más coincidencias cortas y no superpuestas, todas ellas precedidas por una coincidencia grande que en realidad las engloba a todas. El algoritmo de búsqueda utilizado por el widget no busca arbitrariamente lejos para una posible coincidencia que podría cubrir grandes porciones del widget. Por ejemplo:

pack [text .t]
.t insert 1.0 "aaaa\nbbbb\nbbbb\nbbbb\nbbbb\n"
.t search -regexp -backward -- {b+\n|a+\n(b+\n)+} end
coincide en "5.0" cuando una coincidencia codiciosa real coincidiría en "1.0". De manera similar, si agregamos -all a este caso, coincide en todas las de "5.0", "4.0", "3.0" y "1.0", cuando en realidad solo debería coincidir en "1.0" ya que esa coincidencia engloba a todas las demás.

    DESCRIPTION

    El comando text es una herramienta de línea de comandos utilizada para interactuar con el búfer de texto de GObject Introspection. Permite manipular el texto, obtener información sobre él y configurar varios aspectos de su visualización y comportamiento.

    SYNOPSIS

    text [OPTIONS] [FILE]

    OPTIONS

    Este comando no tiene opciones específicas. La interacción se realiza a través de comandos internos.

    EXAMPLES

    text mi_archivo.txt

    Esto abrirá el archivo mi_archivo.txt en el editor de texto interactivo.

    NOTES

    El comando text se basa en GObject Introspection y está diseñado para interactuar con widgets de texto. Su comportamiento y capacidades dependen de la implementación subyacente.

    TEXT PROPERTIES

    El texto en sí mismo tiene varias propiedades, como el contenido, la longitud, el tipo MIME, etc.

    THE TEXT BUFFER

    El búfer de texto almacena todo el contenido del texto. Proporciona métodos para insertar, eliminar y consultar texto.

    THE CURSOR

    El cursor representa la posición actual dentro del búfer de texto. Se mueve a medida que el usuario escribe o navega.

    THE MARK

    Una marca es un punto específico dentro del búfer de texto que puede ser rastreado. Se utiliza para resaltar texto, gestionar selecciones y para otras funcionalidades avanzadas.

    MARKS

    Puede haber múltiples marcas activas simultáneamente en el búfer de texto. Cada marca puede tener propiedades asociadas, como ser visible o no.

    EMBEDDED WINDOWS

    Los widgets de texto pueden contener ventanas incrustadas, lo que permite la integración de otros elementos de interfaz de usuario dentro del texto.

    EMBEDDED IMAGES

    De manera similar a las ventanas, también se pueden incrustar imágenes dentro del texto.

    THE SELECTION

    La selección se refiere a un rango de texto que ha sido marcado por el usuario, típicamente para copiar, cortar o pegar.

    THE INSERTION CURSOR

    El cursor de inserción indica dónde se insertará el próximo carácter escrito por el usuario.

    THE MODIFIED FLAG

    Un indicador que señala si el contenido del búfer de texto ha sido modificado desde la última vez que se guardó.

    THE UNDO MECHANISM

    El mecanismo de deshacer permite al usuario revertir los cambios realizados en el texto.

    PEER WIDGETS

    Los widgets "peer" son widgets relacionados que pueden interactuar o reflejar el estado del widget de texto.

    ASYNCHRONOUS UPDATE OF LINE HEIGHTS

    La altura de las líneas puede actualizarse de forma asíncrona para mejorar el rendimiento, especialmente en documentos largos.

    WIDGET COMMAND

    Comandos específicos que se pueden enviar al widget de texto para realizar acciones.

    Asociaciones entre eventos de entrada (teclado, ratón) y comandos del widget.
