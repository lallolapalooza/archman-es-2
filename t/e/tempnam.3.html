tempnam(3) Manual de funciones de biblioteca tempnam(3)

NOMBRE

tempnam - crear un nombre para un archivo temporal

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <stdio.h>
char *tempnam(const char *dir, const char *pfx);
Requisitos de macros de prueba de características para glibc (ver feature_test_macros(7)):

tempnam():

    Desde glibc 2.19:
        _DEFAULT_SOURCE
    glibc 2.19 y anteriores:
        _BSD_SOURCE || _SVID_SOURCE

DESCRIPCIÓN

Nunca use esta función. Utilice mkstemp(3) o tmpfile(3) en su lugar.

La función tempnam() devuelve un puntero a una cadena que es un nombre de archivo válido, y tal que un archivo con ese nombre no existía cuando tempnam() lo comprobó. La parte del sufijo del nombre de archivo generado comenzará con pfx en caso de que pfx sea una cadena no nula de hasta cinco bytes. La parte del prefijo del directorio del nombre de archivo generado debe ser "apropiada" (a menudo eso implica al menos que sea escribible).

Los intentos de encontrar un directorio apropiado pasan por los siguientes pasos:

(1)
En caso de que la variable de entorno TMPDIR exista y contenga el nombre de un directorio apropiado, se utiliza ese.
(2)
De lo contrario, si el argumento dir no es nulo y es apropiado, se utiliza.
(3)
De lo contrario, se utiliza P_tmpdir (tal como se define en <stdio.h>) cuando sea apropiado.
(4)
Finalmente, se puede utilizar un directorio definido por la implementación.

La cadena devuelta por tempnam() se asigna usando malloc(3) y, por lo tanto, debe liberarse con free(3).

VALOR DE RETORNO

En caso de éxito, la función tempnam() devuelve un puntero a un nombre de archivo temporal único. Devuelve NULL si no se puede generar un nombre único, con errno establecido para indicar el error.

ERRORES

ENOMEM
Fallo en la asignación de almacenamiento.

Interfaz Atributo Valor

ESTÁNDARES

POSIX.1-2008.

HISTORIA

SVr4, 4.3BSD, POSIX.1-2001. Obsoleto en POSIX.1-2008.

NOTAS

Aunque tempnam() genera nombres difíciles de adivinar, es posible que entre el momento en que tempnam() devuelve un nombre de archivo y el momento en que el programa lo abre, otro programa cree ese nombre de archivo usando open(2), o lo cree como un enlace simbólico. Esto puede conducir a agujeros de seguridad. Para evitar tales posibilidades, utilice el flag O_EXCL de open(2) para abrir el nombre de archivo. O mejor aún, use mkstemp(3) o tmpfile(3).

SUSv2 no menciona el uso de TMPDIR; glibc solo lo usará cuando el programa no sea set-user-ID. En SVr4, el directorio utilizado bajo (4) es /tmp (y esto es lo que hace glibc).

Debido a que asigna dinámicamente memoria utilizada para devolver el nombre de archivo, tempnam() es reentrante y, por lo tanto, seguro para hilos, a diferencia de tmpnam(3).

La función tempnam() genera una cadena diferente cada vez que se llama, hasta TMP_MAX (definido en <stdio.h>) veces. Si se llama más de TMP_MAX veces, el comportamiento se define por la implementación.

tempnam() utiliza como máximo los primeros cinco bytes de pfx.

La implementación de glibc de tempnam() falla con el error EEXIST si no se puede encontrar un nombre único.

ERRORES CONOCIDOS

El significado preciso de "apropiado" no está definido; no se especifica cómo se determina la accesibilidad de un directorio.

VER TAMBIÉN

mkstemp(3), mktemp(3), tmpfile(3), tmpnam(3)
