TEXDOCTK(1) Manual de Comandos Generales TEXDOCTK(1)

NOMBRE

texdoctk - GUI para un acceso más fácil a la documentación de paquetes y programas de TeX

SINOPSIS

texdoctk -[aq]

DESCRIPCIÓN

texdoctk es una GUI para un acceso más fácil a una gran parte de la vasta cantidad de documentación y tutoriales para paquetes y programas de TeX y sus diferentes derivados (principalmente LaTeX). Está optimizado e incluido en las distribuciones teTeX y fpTeX, y también está disponible con TeXLive.

La documentación se agrupa en 17 categorías; el 18º botón del panel principal está inactivo por defecto y destinado a usarse con adiciones locales (ver sección CONFIGURACIÓN más abajo).

En la ventana de configuración, verá una casilla de verificación en los menús del convertidor html->ps y text->ps para activar/desactivar la redirección de salida. Esto se debe a que algunos convertidores no escriben su salida en un archivo, sino en la salida estándar por defecto, por lo que se necesita una redirección, por ejemplo:

a2ps miarchivo.txt >miarchivo.ps

OPCIONES

-v
verbose: habilita algunos mensajes del visor que de otro modo se enviarían a stderr, así como algunas ventanas emergentes de advertencia. Esto también se puede configurar en un archivo de configuración.
-a
autoview: inicia automáticamente el visor si una lista contiene solo un elemento (esto ocurrirá con frecuencia en los resultados de búsqueda). Esto también se puede configurar en un archivo de configuración.

CONFIGURACIÓN

La configuración se controla mediante el archivo de configuración predeterminado del sistema ($TEXMFMAIN)/texdoctk/texdocrc.defaults, aunque la mayoría de sus entradas pueden ser anuladas por los propios archivos de configuración opcionales del usuario ~/.texdocrc y/o las opciones de línea de comandos.

El menú Configuración y los archivos de configuración

El menú Configuración se utiliza para cambiar la configuración personalizable de texdoctk durante la llamada al programa o como nuevos valores predeterminados. Este último caso es el propósito del botón Guardar, que genera o reescribe el archivo personal del usuario ~/.texdocrc. Los valores predeterminados del sistema no se pueden editar con el menú Configuración.

Rutas
Se informan las rutas de tipo TEXMF en el sistema, y el usuario puede especificar el nombre del subdirectorio de $HOMETEXMF, donde se almacena la documentación personal.
Comportamiento general del visor

Suprimir mensajes de error alterna el modo verboso (ver opción -v); el valor predeterminado es desactivado.

Iniciar visor automáticamente para listas de un solo elemento si una lista contiene solo un elemento (ver opción -a)

Usar visor de texto para formato de archivo desconocido es decir, tratar el archivo como texto plano. texdoctk debería reconocer los formatos de archivo habituales y también relacionar nombres como README con texto plano, pero algunas documentaciones pueden tener nombres inventados libremente. El valor predeterminado es activado; si se desactiva, intentar ver dichos archivos generará un error. El cambio no afecta la impresión: los formatos no reconocidos no se pueden imprimir.

Cambiar colores del visor utilizando tuplas RGB en el formato #rrggbb o los nombres estandarizados.

DVI/PostScript/PDF/HTML/Texto plano
Para archivos de texto, texdoctk proporciona su propio visor. Si este visor está deshabilitado, pero no se especifica ningún visor alternativo, texdoctk intenta leer el contenido de la variable de entorno $PAGER.

Si desea imprimir la documentación, necesitará convertidores para transformar archivos que no sean PS a PostScript. Aquí hay algunas sugerencias:

dvi->ps: dvips (es parte de teTeX) (http://www.radicaleye.com/dvips.html)

pdf->ps: pdf2ps (http://www.cs.wisc.edu/~ghost) o Acrobat Reader (http://www.adobe.com)

html->ps: html2ps (http://user.it.uu.se/~jan/html2ps.html)

texto plano->ps: a2ps (http://www-inf.enst.fr/~demaille/a2ps/)

Los menús del convertidor html->ps y text->ps para activar/desactivar la redirección de salida. Esto se debe a que algunos convertidores no escriben su salida en un archivo, sino en la salida estándar por defecto, por lo que se necesita una redirección, por ejemplo: a2ps miarchivo.txt >miarchivo.ps

El archivo de configuración a nivel de sistema es ($TEXMFMAIN)/texdoctk/texdocrc.defaults y solo debe ser escribible por el administrador de la instalación utilizando cualquier editor de texto. El archivo de configuración opcional del usuario es ~/.texdocrc y puede anular todas las configuraciones del sistema, excepto aquellas que afectan a la instalación en su conjunto. La forma preferida de cambiarlo es a través del menú Configuración.

Las bases de datos

texdoctk viene con un archivo de base de datos predeterminado ($TEXMFMAIN)/texdoctk/texdoctk.dat con un formato especial. Está dividido en 17 secciones que corresponden a los 17 botones que están activos por defecto. Cada sección comienza con una línea

@nombre_sección

donde nombre_sección es el texto tal como aparece en el botón. A este título le siguen las entradas descriptivas para cada documentación, que tienen este formato:

etiqueta_paquete;Descripción corta para la lista de selección (opcional: nombre_paquete);ruta en el directorio de documentación;palabras clave opcionales

(sin saltar línea!). Los comentarios (iniciados con #) y las líneas vacías son ignorados por el programa. El segundo campo es el texto que se muestra en las listas de selección de texdoctk, y normalmente querrá mencionar el nombre del paquete entre paréntesis junto con él; el primer campo es una etiqueta **única** para el paquete para uso interno del programa, que generalmente se elegirá idéntica al nombre del paquete, pero puede ser diferente si hay más de un archivo de documentación que viene con un paquete.

Es probable que el administrador instale paquetes adicionales en el árbol texmf local. La documentación correspondiente se puede hacer accesible mediante una base de datos adicional $TEXMFLOCAL/texdoctk/texdoctk-local.dat. Además, los usuarios individuales posiblemente instalen paquetes adicionales en un subdirectorio texmf de su $HOME, para lo cual pueden crear su propia base de datos individual como $TEXMFHOME/texdoctk/texdoctk-pers.dat. Después de crear dichos archivos, se debe ejecutar texhash.

Ambos tipos de bases de datos deben tener la misma estructura que la base de datos del sistema, aunque no es necesario (ni deben) incluir todas sus secciones si no hay entradas adicionales. Por ejemplo, si el paquete foo se agrega al árbol local de manera que su archivo de documentación sea ($TEXMFLOCAL)/doc/latex/foo/foo.dvi y se decide que encaja mejor en la categoría existente Gráficos, texdoctk-local.dat se vería así:

@Gráficos
foo;Crear campanas y silbatos (foo);latex/foo/foo.dvi;decoración

La entrada para foo se agregará a la lista de entradas de la categoría Gráficos. El 18º botón se puede activar de la misma manera, pero usando un nuevo nombre de categoría; las posibles entradas al principio de la base de datos que no se han asignado a una categoría se asignarán a la categoría predeterminada Varios, haciendo que el 18º botón esté activo con esa etiqueta. Tenga en cuenta que no puede haber más de 18 categorías; si hay más, solo aparecerá y se usará la última definida.

Si la documentación está incluida en el archivo .sty en lugar de un archivo de documentación adecuado, las palabras clave opcionales deben comenzar con -?- directamente después del punto y coma, donde ? es 0, 1, 2 o 3; estas son banderas que indican en qué parte del .sty se colocan las instrucciones y deberían ayudar a texdoctk a extraer la documentación del estilo y presentarla sin el código, lo que normalmente sería de poca utilidad.

0
sin lugar específico, disperso entre el código
1
al final, detrás de \endinput; algunos archivos .sty tienen documentación bien organizada detrás del final del código real, donde TeX no la ve durante la compilación
2
al principio, terminado por %%%%%%; en algunos otros casos, información de uso está al principio del .sty como un comentario terminado por un

ARCHIVOS

$TEXMFMAIN/texdoctk/texdocrc.defaults archivo de configuración global del sistema

~/.texdocrc (opcional) archivo de configuración personal; también puede ser creado con el menú de Configuración

$TEXMFMAIN/texdoctk/texdoctk.dat archivo de base de datos por defecto para archivos de documentación de la distribución

$TEXMFLOCAL/texdoctk/texdoctk-local.dat (opcional) archivo de base de datos local para archivos de documentación

$TEXMFHOME/texdoctk/texdoctk-pers.dat (opcional) archivo de base de datos personal de usuarios individuales para archivos de documentación

ERRORES

La colocación de widgets en los niveles superiores de los temas se vuelve fea cuando el nivel superior se estira o se encoge.

La fuente en las etiquetas de los marcos del menú de Configuración no se fuerza a la fuente predeterminada; esto se hará visible, por ejemplo, en pantallas de alta resolución, donde la fuente de la etiqueta no se escala hacia arriba.

La salida de errores de Netscape y Mozilla se escribirá en stderr incluso si se estableció el modo silencioso.
