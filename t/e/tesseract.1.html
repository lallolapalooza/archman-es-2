TESSERACT(1)   TESSERACT(1)

NOMBRE

tesseract - motor OCR de línea de comandos

SINOPSIS

tesseract ARCHIVO BASE_SALIDA [OPCIONES]... [ARCHIVO_CONFIG]...

DESCRIPCIÓN

tesseract(1) es un motor OCR de calidad comercial desarrollado originalmente en HP entre 1985 y 1995. En 1995, este motor estuvo entre los 3 mejores evaluados por UNLV. Fue liberado como código abierto por HP y UNLV en 2005, y ha sido desarrollado en Google hasta 2018.

ARGUMENTOS ENTRADA/SALIDA

ARCHIVO

El nombre del archivo de entrada. Puede ser un archivo de imagen o un archivo de texto.

Se admiten la mayoría de los formatos de archivo de imagen (cualquier cosa que Leptonica pueda leer).

Un archivo de texto enumera los nombres de todas las imágenes de entrada (un nombre de imagen por línea). Los resultados se combinarán en un solo archivo para cada formato de salida (txt, pdf, hocr, xml).

Si ARCHIVO es stdin o - entonces se utiliza la entrada estándar.

BASE_SALIDA

El nombre base del archivo de salida (al cual se añadirá la extensión apropiada). Por defecto, la salida será un archivo de texto con .txt añadido al nombre base, a menos que haya uno o más parámetros establecidos que especifiquen explícitamente la salida deseada.

Si BASE_SALIDA es stdout o - entonces se utiliza la salida estándar.

OPCIONES

-c VARIABLE_CONFIG=VALOR

Establece el valor del parámetro VARIABLE_CONFIG a VALOR. Se permiten múltiples argumentos -c.

--dpi N

Especifica la resolución N en DPI para la(s) imagen(es) de entrada. Un valor típico para N es 300. Sin esta opción, la resolución se lee de los metadatos incluidos en la imagen. Si una imagen no incluye esa información, Tesseract intenta adivinarla.

-l IDIOMA, -l ESCRITURA

El idioma o escritura a utilizar. Si no se especifica ninguno, se asume eng (inglés). Se pueden especificar varios idiomas, separados por signos más. Tesseract utiliza códigos de idioma ISO 639-2 de 3 caracteres (ver IDIOMAS Y ESCRITURAS).

--psm N

Configura Tesseract para que solo ejecute un subconjunto de análisis de diseño y asuma una cierta forma de imagen. Las opciones para N son: 
0 = Sólo detección de orientación y escritura (OSD).
1 = Segmentación automática de página con OSD.
2 = Segmentación automática de página, pero sin OSD, ni OCR. (no implementado)
3 = Segmentación automática de página completa, pero sin OSD. (Por defecto)
4 = Asumir una sola columna de texto de tamaños variables.
5 = Asumir un solo bloque uniforme de texto alineado verticalmente.
6 = Asumir un solo bloque uniforme de texto.
7 = Tratar la imagen como una sola línea de texto.
8 = Tratar la imagen como una sola palabra.
9 = Tratar la imagen como una sola palabra en un círculo.
10 = Tratar la imagen como un solo carácter.
11 = Texto disperso. Encontrar la mayor cantidad de texto posible sin un orden particular.
12 = Texto disperso con OSD.
13 = Línea bruta. Tratar la imagen como una sola línea de texto,
     omitendo trucos específicos de Tesseract.

--oem N

Especifica el modo del motor OCR. Las opciones para N son: 
0 = Sólo Tesseract original.
1 = Sólo redes neuronales LSTM.
2 = Tesseract + LSTM.
3 = Por defecto, basado en lo que esté disponible.

--tessdata-dir RUTA

Especifica la ubicación de la ruta de tessdata.

--user-patterns ARCHIVO

Especifica la ubicación del archivo de patrones de usuario.

--user-words ARCHIVO

Especifica la ubicación del archivo de palabras de usuario.

ARCHIVO_CONFIG

El nombre de una configuración a utilizar. El nombre puede ser un archivo en tessdata/configs o tessdata/tessconfigs, o una ruta de archivo absoluta o relativa. Una configuración es un archivo de texto plano que contiene una lista de parámetros y sus valores, uno por línea, con un espacio separando el parámetro del valor.

Los archivos de configuración interesantes incluyen:

•alto — Salida en formato ALTO (BASE_SALIDA.xml).
•hocr — Salida en formato hOCR (BASE_SALIDA.hocr).
•page — Salida en formato PAGE (BASE_SALIDA.page.xml). La salida puede personalizarse con las banderas: page_xml_polygon — Crear polígonos en lugar de cuadros delimitadores (por defecto: true) page_xml_level — Crear el archivo PAGE a nivel de 0=línea o 1=palabra (por defecto: 0)
•pdf — Salida PDF (BASE_SALIDA.pdf).
•tsv — Salida TSV (BASE_SALIDA.tsv).
•txt — Salida de texto plano (BASE_SALIDA.txt).
•get.images — Escribir imágenes de entrada procesadas a archivo (BASE_SALIDA.processedPAGENUMBER.tif).
•logfile — Redirigir mensajes de depuración a archivo (tesseract.log).
•lstm.train — Archivos de salida utilizados por el entrenamiento LSTM (BASE_SALIDA.lstmf).
•makebox — Escribir archivo box (BASE_SALIDA.box).
•quiet — Redirigir mensajes de depuración a /dev/null.

Es posible seleccionar varios archivos de configuración, por ejemplo tesseract imagen.png demo alto hocr pdf txt creará cuatro archivos de salida demo.alto, demo.hocr, demo.pdf y demo.txt con los resultados de OCR.

Nota bene: Las opciones -l IDIOMA, -l ESCRITURA y --psm N deben aparecer antes de cualquier ARCHIVO_CONFIG.

OPCIONES ÚNICAS

-h, --help

Mostrar mensaje de ayuda.

--help-extra

Mostrar ayuda adicional para usuarios avanzados.

--help-psm

Mostrar modos de segmentación de página.

--help-oem

Mostrar modos de motor OCR.

-v, --version

Devuelve la versión actual del ejecutable tesseract(1).

--list-langs

Lista los idiomas disponibles para el motor tesseract. Puede usarse con --tessdata-dir RUTA.

--print-parameters

Imprime los parámetros de tesseract.

IDIOMAS Y ESCRITURAS

Para reconocer algún texto con Tesseract, normalmente es necesario especificar el(los) idioma(s) o escritura(s) del texto (a menos que sea texto en inglés, que se admite por defecto) usando -l IDIOMA o -l ESCRITURA.

Seleccionar un idioma automáticamente también selecciona el conjunto de caracteres y el diccionario (lista de palabras) específicos de ese idioma.

Seleccionar una escritura típicamente selecciona todos los caracteres de esa escritura, que pueden ser de diferentes idiomas. El diccionario que se incluye también contiene una mezcla de diferentes idiomas. En la mayoría de los casos, una escritura también admite inglés. Por lo tanto, es posible reconocer un idioma para el que no se haya entrenado específicamente utilizando traineddata para la escritura en la que está escrito.

Se puede especificar más de un idioma o escritura usando +. Ejemplo: tesseract miimagen.png miimagen -l eng+deu+fra.

https://github.com/tesseract-ocr/tessdata_fast proporciona modelos rápidos de idiomas y escrituras que también forman parte de las distribuciones de Linux.

ARCHIVOS DE CONFIGURACIÓN Y AUMENTO CON DATOS DE USUARIO

Los archivos de configuración de Tesseract consisten en líneas con pares de parámetros y valores (separados por espacios). Los parámetros se documentan como indicadores en el código fuente, como el siguiente en tesseractclass.h:

STRING_VAR_H(tessedit_char_blacklist, "", "Lista negra de caracteres que no se deben reconocer");

Estos parámetros pueden habilitar o deshabilitar varias características del motor, y pueden hacer que cargue (o no cargue) varios datos. Por ejemplo, supongamos que desea hacer OCR en inglés, pero suprimir el diccionario normal y cargar una lista de palabras alternativa y una lista de patrones alternativa; estos dos archivos son los archivos de datos adicionales más utilizados.

Si su paquete de idioma está en /ruta/a/eng.traineddata y la configuración de hocr está en /ruta/a/configs/hocr, cree tres archivos nuevos:

/ruta/a/eng.user-words:

the
quick
brown
fox
jumped

/ruta/a/eng.user-patterns:

1-\d\d\d-GOOG-411
www.\n\\\*.com

/ruta/a/configs/bazaar:

load_system_dawg     F
load_freq_dawg       F
user_words_suffix    user-words
user_patterns_suffix user-patterns

Ahora, si pasa la palabra bazaar como CONFIGFILE a Tesseract, Tesseract no se molestará en cargar el diccionario del sistema ni el diccionario de palabras frecuentes y cargará y utilizará los archivos eng.user-words y eng.user-patterns que proporcionó. El primero es una lista simple de palabras, una por línea. El formato del segundo se documenta en dict/trie.h en read_pattern_list().

VARIABLES DE ENTORNO

TESSDATA_PREFIX

Si TESSDATA_PREFIX se establece en una ruta, esa ruta se utiliza para encontrar el directorio tessdata con los modelos de reconocimiento de idioma y escritura y los archivos de configuración. Usar --tessdata-dir PATH es la alternativa recomendada.

OMP_THREAD_LIMIT

Si el ejecutable de tesseract se compiló con soporte multihilo, normalmente utilizará cuatro núcleos de CPU para el proceso de OCR. Si bien esto puede ser más rápido para una sola imagen, ofrece un rendimiento malo si el equipo anfitrión proporciona menos de cuatro núcleos de CPU o si el OCR se realiza para muchas imágenes. Solo se utiliza un solo núcleo de CPU con OMP_THREAD_LIMIT=1.

HISTORIA

El motor se desarrolló en Hewlett Packard Laboratories Bristol y en Hewlett Packard Co, Greeley Colorado entre 1985 y 1994, con algunos cambios más realizados en 1996 para portarlo a Windows, y algo de C++ en 1998. Gran parte del código se escribió en C, y luego parte se escribió en C++. El código C++ hace un uso intensivo de un sistema de listas utilizando macros. Esto es anterior a STL, fue portable antes de STL y es más eficiente que las listas STL, pero tiene el gran inconveniente de que si se produce una violación de segmentación, es difícil de depurar.

La versión 2.00 trajo soporte Unicode (UTF-8), seis idiomas y la capacidad de entrenar Tesseract.

Tesseract se incluyó en la Cuarta Prueba Anual de Precisión de OCR de UNLV. Ver https://github.com/tesseract-ocr/docs/blob/main/AT-1995.pdf. Desde Tesseract 2.00, se incluyen scripts para permitir que cualquiera pueda reproducir algunas de estas pruebas. Ver https://tesseract-ocr.github.io/tessdoc/TestingTesseract.html para más detalles.

Tesseract 3.00 agregó varios idiomas nuevos, incluidos chino, japonés y coreano. También introdujo un nuevo sistema de gestión de datos de idioma basado en un solo archivo.

Tesseract 3.02 agregó soporte para texto bidireccional, la capacidad de reconocer múltiples idiomas en una sola imagen y un análisis de diseño mejorado.

Tesseract 4 agrega un nuevo motor de OCR basado en redes neuronales (LSTM) que se centra en el reconocimiento de líneas, pero también todavía admite el motor de OCR heredado de Tesseract 3 que funciona reconociendo patrones de caracteres. La compatibilidad con Tesseract 3 está habilitada con --oem 0. Esto también requiere archivos traineddata que admitan el motor heredado, por ejemplo, los del repositorio tessdata (https://github.com/tesseract-ocr/tessdata).

Para obtener más detalles, consulte las notas de la versión en la documentación de Tesseract (https://tesseract-ocr.github.io/tessdoc/ReleaseNotes.html).
