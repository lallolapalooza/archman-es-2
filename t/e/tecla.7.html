tecla(7) Manual de Información Miscelánea tecla(7)

NOMBRE

tecla, teclarc - La interfaz de usuario proporcionada por la biblioteca Tecla.

DESCRIPCIÓN

Esta página del manual describe las funciones de edición de línea de comandos que están disponibles para los usuarios de programas que leen la entrada del teclado a través de la biblioteca Tecla. Los usuarios del shell tcsh encontrarán los enlaces de teclas predeterminados muy familiares. Los usuarios del shell bash también lo encontrarán bastante familiar, pero con algunas diferencias menores, sobre todo en la forma en que se realizan las búsquedas hacia adelante y hacia atrás en la lista de comandos históricos. Hay dos modos de edición principales, uno con enlaces de teclas tipo emacs y otro con enlaces de teclas tipo vi. Por defecto, el modo emacs está habilitado, pero alternativamente se puede seleccionar el modo vi a través del archivo de configuración del usuario. Este archivo también se puede utilizar para cambiar los enlaces de teclas individuales según las preferencias del usuario. Por defecto, se proporciona la autocompletación de tabulación. Si la aplicación no ha reconfigurado esto para completar otros tipos de símbolos, entonces la autocompletación de tabulación completa nombres de archivo.

NOTACIÓN DE SECUENCIA DE TECLAS

En el resto de esta página del manual, y también en todos los archivos de configuración de Tecla, las secuencias de teclas se expresan de la siguiente manera:

^A  o  C-a
    Esto es un control-A, introducido presionando la tecla control al
    mismo tiempo que la tecla A.
\E    o   M-
    En secuencias de teclas, ambas notaciones se pueden introducir
    ya sea presionando la tecla escape, luego la siguiente tecla, o presionando
    la tecla Meta al mismo tiempo que la siguiente tecla. Por lo tanto,
    la secuencia de teclas M-p se puede escribir de dos maneras: presionando
    la tecla escape, seguida de presionar p, o presionando la
    tecla Meta al mismo tiempo que p.
up
    Esto se refiere a la tecla de flecha hacia arriba.
down
    Esto se refiere a la tecla de flecha hacia abajo.
left
    Esto se refiere a la tecla de flecha hacia la izquierda.
right
    Esto se refiere a la tecla de flecha hacia la derecha.
a
    Esto es solo una tecla A normal.

EL ARCHIVO DE CONFIGURACIÓN DE TECLA

Por defecto, Tecla busca un archivo llamado .teclarc en su directorio de inicio (es decir, ~/.teclarc). Si encuentra este archivo, lo lee, interpretando cada línea como la definición de un nuevo enlace de tecla o una opción de configuración de edición. Dado que los enlaces de teclas emacs se instalan por defecto, si desea utilizar el modo de edición vi, que no es el predeterminado, el elemento más importante a incluir en este archivo es la siguiente línea:

  edit-mode vi

Esto reconfigurará los enlaces de teclas predeterminados para el modo vi. El conjunto completo de argumentos que este comando acepta son:

  vi     -  Instalar enlaces de teclas como los del editor
            vi.
  emacs  -  Instalar enlaces de teclas como los del editor
            emacs. Este es el predeterminado.
  none   -  Utilizar solo las instalaciones nativas de edición de línea
            proporcionadas por el controlador de terminal.

Para evitar que suene la campana del terminal, por ejemplo, al escribir una secuencia de control no reconocida, coloque la siguiente línea en el archivo de configuración:

  nobeep

Un ejemplo de una línea de enlace de teclas en el archivo de configuración es la siguiente.

  bind M-[2~ insert-mode

En muchos teclados, la secuencia de teclas anterior se genera al presionar la tecla insert, por lo que con este enlace de teclas, se puede alternar entre los modos de inserción y sobrescritura del modo emacs presionando una tecla. También se podría hacer escribiendo la secuencia de caracteres anterior uno por uno. Como se explicó anteriormente, la parte M- de esta secuencia se puede escribir presionando la tecla de escape antes de la siguiente tecla, o presionando la tecla Meta al mismo tiempo que la siguiente tecla. Por lo tanto, si hubiera establecido el enlace de teclas anterior, y la tecla de inserción en su teclado no generara la secuencia de teclas anterior, aún podría escribirla de 2 maneras:

  1. Presione la tecla de escape momentáneamente, luego presione '[', luego '2', luego
     finalmente '~'.
  2. Presione la tecla meta al mismo tiempo que presiona la tecla '[',
     luego presione '2', luego '~'.

Si establece un enlace de teclas para una secuencia de teclas que ya está enlazada a una función, el nuevo enlace anula el anterior. Si en el nuevo enlace omite el nombre de la nueva función a la que enlazar la secuencia de teclas, el enlace original queda indefinido.

A partir de las versiones de libtecla posteriores a la 1.3.3, ahora es posible enlazar secuencias de teclas que comienzan con un carácter imprimible. Anteriormente, las secuencias de teclas debían comenzar con un carácter de control o meta.

Tenga en cuenta que las palabras clave especiales "up", "down", "left" y "right" se refieren a las teclas de flecha, y por lo tanto no se tratan como secuencias de teclas. Así, por ejemplo, para reasignar las teclas de flecha arriba y abajo para usar el mecanismo de búsqueda de historial en lugar del simple método de recuperación de historial, puede colocar lo siguiente en su archivo de configuración:

  bind up history-search-backwards
  bind down history-search-backwards

Para anular un enlace existente, puede hacerlo con el comando bind omitiendo especificar ninguna función de acción para reasignar la secuencia de teclas. Por ejemplo, al no especificar una función de acción, el siguiente comando anula la acción predeterminada de principio de línea de la secuencia de teclas ^A:

  bind ^A

Si crea un archivo de configuración ~/.teclarc, pero parece no tener ningún efecto en el programa, consulte la documentación del programa para ver si el autor eligió un nombre diferente para este archivo.

AUTCOMPLETADO DE NOMBRES DE ARCHIVO Y TILDE

Con los enlaces de teclas predeterminados, presionar la tecla TAB (también conocida como ^I) hace que Tecla intente completar el nombre de archivo incompleto que precede al cursor. Tecla busca hacia atrás desde el cursor, buscando el inicio del nombre de archivo, deteniéndose cuando encuentra un espacio o el inicio de la línea. Si más de un archivo tiene el prefijo especificado, entonces Tecla completa el nombre de archivo hasta el punto en que las coincidencias ambiguas comienzan a diferir, y luego enumera las coincidencias posibles.

Además de los nombres de archivo escritos literalmente, Tecla puede completar archivos que comienzan con expresiones ~/ y ~usuario/ y que contienen expresiones $variableentorno. En particular, si presiona TAB dentro de una expresión ~usuario incompleta, Tecla intentará completar el nombre de usuario, enumerando cualquier coincidencia ambigua.

El enlace de autocompletado se implementa utilizando la función cpl_word_completions(), que también está disponible por separado para los usuarios de esta biblioteca. Consulte la página del manual de cpl_complete_word(3) para obtener más detalles.

EXPANSIÓN DE NOMBRES DE ARCHIVO

Con los enlaces de teclas predeterminados, presionar ^X* hace que Tecla expanda el nombre de archivo que precede al cursor, reemplazando las expresiones ~/ y ~usuario/ con los directorios de inicio correspondientes, y reemplazando las expresiones $variableentorno con el valor de la variable de entorno especificada, y luego, si hay comodines, reemplazando el nombre de archivo expandido hasta el momento con una lista separada por espacios de los archivos que coinciden con los comodines.

El enlace de expansión se implementa utilizando la función ef_expand_file(). Consulte la página del manual de ef_expand_file(3) para obtener más detalles.

RECUERDO DE LÍNEAS ESCRITAS PREVIAMENTE

Cada vez que el usuario introduce una nueva línea, esta se añade a una lista de líneas de entrada históricas mantenidas dentro del objeto de recurso GetLine. Puede recorrer esta lista hacia arriba y hacia abajo usando las teclas de flecha arriba y abajo. Alternativamente, puede hacer lo mismo con las teclas ^P y ^N, y en el modo de comando vi, alternativamente puede usar las teclas k y j. Por lo tanto, presionar flecha arriba una vez, reemplaza la línea de entrada actual con la línea introducida previamente. Presionar flecha arriba nuevamente, la reemplaza con la línea que se introdujo antes de esa, etc. Habiendo retrocedido una o más líneas en la lista de historial, puede regresar a líneas más recientes presionando flecha abajo una o más veces. Si hace esto suficientes veces, regresará a la línea original que estaba introduciendo cuando presionó flecha arriba por primera vez.

Tenga en cuenta que en el modo vi, todas las funciones de recuperación de historial cambian la biblioteca al modo de comando.

  cd ~/tecla

ARCHIVOS DE HISTORIAL

Los autores de programas que utilizan la biblioteca Tecla tienen la opción de guardar las líneas de comandos históricas en un archivo antes de salir, y posteriormente leerlas de este archivo cuando el programa se inicie la próxima vez. No hay un nombre estándar para este archivo, ya que tiene sentido que cada aplicación utilice su propio archivo de historial, para que los comandos de diferentes aplicaciones no se mezclen.

JUEGOS DE CARACTERES INTERNACIONALES

Desde la versión 1.4.0 de libtecla, Tecla es compatible con 8 bits. Esto significa que todos los caracteres de 8 bits que son imprimibles en la configuración regional actual del usuario ahora se muestran tal cual y se incluyen en la línea de entrada devuelta. Suponiendo que el programa que llama contiene correctamente una llamada como la siguiente,

  setlocale(LC_CTYPE, "");

entonces la configuración regional actual se determina por la primera de las variables de entorno LC_CTYPE, LC_ALL y LANG, que se encuentre que contenga un nombre de configuración regional válido. Si ninguna de estas variables está definida, o si el programa no llama a setlocale, entonces se utiliza la configuración regional predeterminada C, que es ASCII de 7 bits de EE. UU. En la mayoría de las plataformas tipo Unix, puede obtener una lista de configuraciones regionales válidas escribiendo el comando:

  locale -a

en el prompt de la shell.

Teclas Meta y configuraciones regionales

Tenga en cuenta que en la mayoría de las configuraciones regionales que no sean la predeterminada C, los caracteres meta se vuelven imprimibles, y por lo tanto ya no se consideran que coinciden con las asignaciones de teclas de estilo M-c. Esto permite que los caracteres internacionales se introduzcan con la tecla Compose sin activar inesperadamente las asignaciones de teclas meta. Todavía puede invocar asignaciones meta, ya que hay dos maneras de hacerlo. Por ejemplo, la asignación M-c también se puede invocar presionando la tecla de escape momentáneamente, luego presionando la tecla c, y esto funcionará independientemente de la configuración regional. Además, muchos emuladores de terminales modernos, como los terminales gnome-terminal de gnome y konsole de KDE, ya generan pares de escape como este cuando se usa la tecla meta, en lugar de un carácter meta real, y otros emuladores generalmente tienen una forma de solicitar este comportamiento, por lo que puede continuar usando la tecla meta en la mayoría de los sistemas.

Por ejemplo, aunque los emuladores de terminal xterm generan caracteres meta de 8 bits reales por defecto cuando se usa la tecla meta, pueden configurarse para generar el par de escape equivalente estableciendo su recurso X EightBitInput en False. Puede hacer esto colocando una línea como la siguiente en su archivo ~/.Xdefaults,

  XTerm*EightBitInput: False
o iniciando un xterm con un argumento de línea de comandos -xrm '*EightBitInput: False'. En versiones recientes de xterm, puede activar y desactivar esta función con la opción "Meta Sends Escape" en el menú que se muestra al presionar el botón izquierdo del mouse y la tecla de control dentro de una ventana de xterm. En CDE, los dtterms pueden ser forzados de manera similar a generar pares de escape en lugar de caracteres meta, estableciendo el recurso Dtterm*KshMode en True.

Introducción de caracteres internacionales

Si no tiene un teclado que genere todos los caracteres internacionales que necesita, generalmente hay una tecla Compose que le permitirá introducir caracteres especiales, o una forma de crear una. Por ejemplo, bajo X windows en sistemas tipo Unix, si su teclado no tiene una tecla Compose, puede designar una tecla redundante para que sirva a este propósito con el comando xmodmap. Por ejemplo, en muchos teclados de PC hay una tecla de Microsoft-Windows, que de lo contrario es inútil bajo Linux. En mi portátil, el programa xev informa que al presionar esta tecla se genera el código de tecla 115, así que para convertir esta tecla en una tecla Compose, hago lo siguiente:

  xmodmap -e 'keycode 115 = Multi_key'

Luego puedo introducir una "i" con un umlaut encima escribiendo esta tecla, seguido de ", seguido de "i".

CONFIGURACIONES PREDETERMINADAS DE TECLAS EN MODO VI


Las siguientes configuraciones predeterminadas de teclas están

    significa que se proporcionan muy pocas funciones de edición en el modo de

    históricas.

    tanto en el modo de entrada como en el modo de comando. Las secuencias de

NAME


libtecla - line editor widget library






DESCRIPTION


libtecla is a library of C functions that provide an extensible
    interface to the shell's command line editing facilities. It supports both
    emacs and vi style command line editing, and includes built in filename,
    tilde, and history expansion.


libtecla provides a single function, gl_get_line(), that
    takes a prompt string and reads a line of text from the user, performing
    command line editing and history expansion as specified by the user's
    initialization file (~/.teclarc) or the environment variables TECARC, and
    SHELL.


The library is configurable by means of a text file, ~/.teclarc.
    This file contains a list of key bindings and their corresponding actions. It
    may also contain a list of directories to be searched for filenames when
    filename expansion is requested.


libtecla supports both interactive and non-interactive use. In
    interactive mode, the user is presented with a prompt, and can edit the line
    of text using emacs or vi style commands. The history of previously entered
    lines can be searched and recalled. In non-interactive mode, libtecla can be
    used to expand filenames, perform tilde expansion, and recall lines from
    history without prompting the user.






KEY
    SEQUENCE NOTATION


The following notation is used to describe key sequences:


    
  
  • ^A - Control-A
    • 
  
  • M-A - Meta-A (or Alt-A)
    • 
  
  • \r - Carriage Return
    • 
  
  • \n - Newline
    • 
  
  • \t - Tab
    • 
  
  • ? - Delete character
    • 







THE
    TECLA CONFIGURATION FILE


The file ~/.teclarc allows the user to customize the behaviour of
    libtecla. It consists of a series of key bindings, each consisting of a
    key sequence and an action to be performed when that key sequence is
    typed.


A key binding takes the form:


  key-sequence   action


The key sequence consists of one or more characters, possibly
    preceded by modifiers such as Control (indicated by '^') or Meta (indicated
    by 'M-'). The action is the name of a function to be called.


For example, the following binding makes the Control-A key insert
    the string "foo" at the current cursor position:


  ^A      insert-string "foo"


A list of the available actions is given below.


The configuration file may also contain a list of directories to be
    searched for filenames when filename expansion is requested. This is done
    using the following directive:


  path = /path/to/dir1:/path/to/dir2


Directories are separated by colons, and the current directory is
    always searched first.






FILENAME
    AND TILDE COMPLETION


libtecla supports filename and tilde completion. When the user types
    a filename or directory name, followed by the TAB key (Control-I), libtecla
    will attempt to complete the name. If there are multiple possible
    completions, a list of them will be displayed.


Tilde expansion is performed automatically when a '~' character is
    encountered at the beginning of a word. It is expanded to the user's home
    directory, or to the home directory of the specified user.






FILENAME
    EXPANSION


When the user types a shell globbing pattern (e.g., *.c), followed
    by Control-X followed by Control-F, libtecla will expand the pattern to a
    list of matching filenames. This list is then inserted into the command
    line.


The set of directories searched for filenames can be customized using
    the path directive in the ~/.teclarc file.






RECALLING
    PREVIOUSLY TYPED LINES


libtecla maintains a history of previously typed lines. The user can
    recall these lines using the up-arrow and down-arrow keys (or Control-P and
    Control-N for up and down, respectively).


The history can also be searched. Typing Control-R followed by a
    string will search the history backwards for lines containing that string.
    Typing Control-S will search forwards.






HISTORY
    FILES


By default, libtecla saves the command history to the file
    ~/.history. This file is read when libtecla is initialized, and written
    when the program exits.


The name of the history file can be changed using the following
    directive in the ~/.teclarc file:


  history = /path/to/history/file






INTERNATIONAL
    CHARACTER SETS


libtecla supports international character sets through the use of
    the setlocale() function. The behavior of libtecla can be customized for
    different character sets by setting the appropriate environment variables
    (e.g., LANG, LC_ALL).

ENTERING
    REPEAT COUNTS


Many of the key binding functions described previously take an
    optional count, typed in before the target key sequence. This is interpreted
    as a repeat count by most bindings. A notable exception is the goto-column
    binding, which interprets the count as a column number.


By default, you can specify this count argument by pressing the
    meta key while typing in the numeric count. This relies on the
    digit-argument action being bound to Meta-0, Meta-1 etc. Once any one
    of these bindings has been activated, you can optionally take your finger
    off the meta key to type in the rest of the number, since every numeric
    digit thereafter is treated as part of the number, unless it is preceded by
    the literal-next binding. As soon as a non-digit, or literal digit
    key is pressed, the repeat count is terminated and either causes the just
    typed character to be added to the line that many times, or causes the next
    key-binding function to be given that argument.


For example, in emacs mode, typing:


  M-12a


causes the letter 'a' to be added to the line 12 times,
  whereas


  M-4M-c


Capitalizes the next 4 words.


In vi command mode, the Meta modifier is automatically added to all
    characters typed in, so to enter a count in vi command-mode just involves
    typing in the number, just as it does in the vi editor itself. So for
    example, in vi command mode, typing:


  4w2x


moves the cursor four words to the right, then deletes two
    characters.


You can also bind digit-argument to other key sequences. If
    these end in a numeric digit, that digit gets appended to the current repeat
    count. If it doesn't end in a numeric digit, a new repeat count is started
    with a value of zero, and can be completed by typing in the number, after
    letting go of the key which triggered the digit-argument action.

NOMBRE


tecla - biblioteca para el manejo de secuencias de escape de terminal tipo VT100







SINOPSIS


#include <tecla.h>


int tecla_init();


int tecla_get_key(int *ascii, int *ext);


int tecla_get_string(char *buffer, int size);


int tecla_get_event(tecla_event_t *event);


void tecla_cleanup();







DESCRIPCIÓN


La biblioteca tecla proporciona una interfaz para manejar las secuencias de escape de terminal tipo VT100. Permite leer las pulsaciones de teclas, incluyendo las teclas especiales como las flechas, F1-F12, etc., y las secuencias de escape más complejas que generan caracteres de control o secuencias de varios bytes.


La función tecla_init() inicializa la biblioteca. Debe llamarse antes de cualquier otra función de tecla.


La función tecla_get_key() lee la siguiente pulsación de tecla de la entrada estándar. Si la pulsación de tecla es un carácter ASCII imprimible, el valor se almacena en *ascii y *ext se establece en 0. Si es una tecla especial, *ascii se establece en 0 y *ext contiene un valor que representa la tecla especial (por ejemplo, TECLA_UP para la flecha arriba).


La función tecla_get_string() lee una cadena de la entrada estándar hasta que se presiona la tecla Enter. La cadena leída se almacena en buffer, que tiene un tamaño de size bytes.


La función tecla_get_event() lee el siguiente evento de la entrada. Los eventos pueden ser pulsaciones de teclas, eventos de redimensionamiento de terminal, etc. El evento se almacena en la estructura tecla_event_t. La estructura tecla_event_t se define en el archivo de cabecera tecla.h.


La función tecla_cleanup() limpia la biblioteca y libera cualquier recurso asignado. Debe llamarse antes de que el programa termine.
