TEE(1P) Manual del Programador POSIX TEE(1P)

PROLOG

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

tee — duplica la entrada estándar

SINOPSIS

tee [-ai] [archivo...]

DESCRIPCIÓN

La utilidad tee copiará la entrada estándar a la salida estándar, creando una copia en cero o más archivos. La utilidad tee no almacenará la salida en búfer.

Si no se especifica la opción -a, los archivos de salida se escribirán (ver Sección 1.1.1.4, Lectura de Archivo, Escritura, y Creación.

OPCIONES

La utilidad tee cumplirá con las Definiciones Base del volumen de POSIX.1‐2017, Sección 12.2, Guías de Sintaxis de Utilidades.

Se soportarán las siguientes opciones:

-a
Añade la salida a los archivos.
-i
Ignora la señal SIGINT.

OPERANDOS

Se soportarán los siguientes operandos:

archivo
Un nombre de ruta de un archivo de salida. Si un operando archivo es '-', se referirá a un archivo llamado -; las implementaciones no lo tratarán como salida estándar. Se soportará el procesamiento de al menos 13 operandos archivo.

STDIN

La entrada estándar puede ser de cualquier tipo.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de tee:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no estén establecidas o estén vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece a un valor de cadena no vacío, anulará los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en los argumentos).
LC_MESSAGES

Determina la localización que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida de error estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Predeterminado, excepto que si se especificó la opción -i, SIGINT se ignorará.

STDOUT

La salida estándar será una copia de la entrada estándar.

STDERR

La salida de error estándar se utilizará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Si se especifican operandos archivo, la entrada estándar se copiará a cada archivo nombrado.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
La entrada estándar se copió correctamente a todos los archivos de salida.
>0
Ocurrió un error.

CONSECUENCIAS DE LOS ERRORES

Si falla la escritura en alguno de los operandos archivo abiertos correctamente, las escrituras en otros operandos archivo y en la salida estándar continuarán, pero el estado de salida será distinto de cero. De lo contrario, se aplican las acciones predeterminadas especificadas en la Sección 1.4, Predeterminados de Descripción de Utilidad.

Las siguientes secciones son informativas.

USO POR APLICACIÓN

La utilidad tee se usa generalmente en una tubería, para hacer una copia de la salida de alguna utilidad.

El operando archivo es técnicamente opcional, pero tee no es más útil que cat cuando no se especifica ninguno.

EJEMPLOS

Guardar una forma intermedia no ordenada de los datos en una tubería:

... | tee sin_ordenar | sort > ordenado

FUNDAMENTO

El requisito de no almacenar en búfer significa que a tee no se le permite utilizar escrituras totalmente en búfer o con búfer de línea estándar de ISO C. No significa que tee tenga que realizar lecturas de 1 byte seguidas de escrituras de 1 byte.

Cabe señalar que las primeras versiones de BSD ignoran cualquier opción inválida y aceptan un solo '-' como alternativa a -i. También imprimen un mensaje si no pueden abrir un archivo:

"tee: no se puede acceder a %s\n", <nombre_de_ruta>

Las implementaciones históricas ignoran los errores de escritura. Esto no está permitido explícitamente por este volumen de POSIX.1‐2017.

Algunas implementaciones históricas utilizan O_APPEND al proporcionar el modo de adición; otras utilizan la función lseek() para buscar el final del archivo después de abrir el archivo sin O_APPEND. Este volumen de POSIX.1‐2017 requiere una funcionalidad equivalente a usar O_APPEND; consulte la Sección 1.1.1.4, Lectura de Archivo, Escritura, y Creación.

tee.1p

tee - duplicate standard input to standard output and files

SYNOPSIS

tee [OPTION]... [FILE]...

DESCRIPTION

Copy standard input to each FILE, and also to standard output.

Example: 

ls -l | tee file.txt

This command is useful when you want to see the output of a command on your screen and also save it to a file for later use.

OPTIONS

-a, --append
append to the given FILEs, do not overwrite
--help
display this help and exit
--version
output version information and exit

The exit status is zero on success, non-zero on failure. Binary streams are delivered without translation or filtering.

APPLICATION USAGE

The tee command reads from standard input and writes to standard output and to one or more files simultaneously. It is often used in shell pipelines to capture intermediate output.

If no FILE is specified, tee reads from standard input and writes to standard output.

The -a or --append option causes tee to append to the given files rather than overwriting them.

EXAMPLES

To list the contents of the current directory and save the output to a file named dir_list.txt:

ls -l | tee dir_list.txt

To append the output of the date command to an existing log file named system.log:

date | tee -a system.log

To redirect standard error to a file and standard output to both the screen and another file:

your_command 2> error.log | tee output.log
