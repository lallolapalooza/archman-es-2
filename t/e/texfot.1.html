TEXFOT(1) Karl Berry TEXFOT(1)

NOMBRE

texfot - ejecuta TeX, filtrando la transcripción en línea para mensajes interesantes

SINOPSIS

texfot [opción]... texcmd [texarg...]

DESCRIPCIÓN

"texfot" invoca a texcmd con los argumentos texarg dados, filtrando la salida en línea para mensajes ``interesantes''. Su valor de salida es el de texcmd. Ejemplos:

# Ejemplo de invocación básica:
texfot pdflatex archivo.tex

# Normalmente la salida completa se copia a /tmp/fot.$UID antes
# de filtrarla, pero eso se puede omitir, o cambiar el nombre del archivo:
texfot --tee=/dev/null lualatex archivo.tex

# Ejemplo de invocación de motor más compleja:
texfot xelatex --recorder '\nonstopmode\input archivo'

Aquí hay un ejemplo de cómo se ve la salida (en su totalidad) en una ejecución sin errores:

/ruta/a/texfot: invocando: pdflatex hola.ltx
Esto es pdfTeX, Versión 3.141592653-2.6-1.40.24 (TeX Live 2022) (formato pre-cargado=pdflatex)
Salida escrita en hola.pdf (1 página, 94415 bytes).

Aparte de sus propias opciones, descritas a continuación, "texfot" simplemente ejecuta el comando dado con los argumentos dados (mismo enfoque de sintaxis de línea de comandos que "env", "nice", "timeout", etc.). Por lo tanto, "texfot" funciona con cualquier motor y cualquier opción de línea de comandos.

"texfot" no mira el archivo de registro ni ningún otro posible archivo de salida; solo mira la salida estándar y el error estándar del comando. La salida estándar se procesa primero, luego el error estándar. "texfot" escribe todas las líneas aceptadas en su salida estándar.

Los mensajes que se muestran están destinados a ser aquellos que probablemente requieran acción por parte del autor: mensajes de error, cajas desbordadas y subdesbordadas, citas indefinidas, caracteres faltantes en fuentes, etc.

FLUJO DE OPERACIÓN

Este es el orden en que se revisan las líneas de salida:

1.
Si la ``próxima línea'' necesita ser impresa (ver abajo), imprímela.
2.
De lo contrario, si la línea coincide con alguna lista de expresiones regulares suministrada por el usuario para aceptar (proporcionada con "--accept", ver abajo), en ese orden, imprímela.
3.
De lo contrario, si la línea coincide con la lista incorporada de expresiones regulares para ignorar, o con cualquier lista de expresiones regulares suministrada por el usuario para ignorar (proporcionada con "--ignore", ver abajo), en ese orden, ignórala.
4.
De lo contrario, si la línea coincide con la lista de expresiones regulares para las cuales se debe mostrar la siguiente línea (dos líneas en total), muestra esta línea y establece la bandera de ``próxima línea'' para la próxima vez que se ejecute el bucle. Ejemplos son los comunes mensajes de error "!" y "nombrearchivo:numerolinea:", que generalmente van seguidos de una línea con detalles específicos del error.
5.
De lo contrario, si la línea coincide con la lista de expresiones regulares para mostrar, muéstrala.
6.
De lo contrario, el valor predeterminado: si la línea provino de la salida estándar, ignórala; si la línea provino del error estándar, imprímela (en la salida estándar), con el prefijo "[stderr] ". Esta distinción se hace porque los motores TeX escriben relativamente pocos mensajes en el error estándar, y es probable que cualquiera de ellos deba ser considerado.

Una vez que una verificación particular coincide, el programa pasa a procesar la siguiente línea.

"texfot" coincide exclusivamente línea por línea; sin embargo, el propio TeX pliega las líneas de salida, típicamente en la columna 79. Esto significa que las coincidencias pueden fallar porque el texto que se está emparejando se dividió en dos líneas. Para solucionar esto, puedes desactivar efectivamente el plegado de TeX estableciendo el parámetro "max_print_line" a un número grande, ya sea en el entorno o en la línea de comandos:

# Cuando se pierden errores debido al plegado de líneas de TeX:
texfot pdftex --cnf-line max_print_line=999 archivo.tex

# De forma equivalente:
env max_print_line=999 texfot pdftex archivo.tex

No dudes en revisar el código fuente del script, que es esencialmente un bucle directo que coincide con las diferentes listas como se describió anteriormente. Puedes ver las expresiones regulares exactas que se emparejan en las diferentes categorías en el código fuente.

Por cierto, aunque nada en esta operación básica es específico de los motores TeX, todas las expresiones regulares incluidas en el programa son específicas de TeX. Por lo tanto, en la práctica, el programa no es útil excepto con motores TeX, aunque sería lo suficientemente fácil adaptarlo (si hubiera algo más tan verboso como TeX para que eso fuera útil).

OPCIONES

Las siguientes son las opciones para "texfot" en sí (no para el motor TeX que se invoca; consulta la documentación del motor o la salida de "--help" para eso).

La primera opción no definida termina el análisis de opciones de "texfot", y el resto de la línea de comandos se invoca como el comando TeX, sin análisis adicional. Por ejemplo, "texfot --debug tex --debug" emitirá información de depuración tanto de "texfot" como de "tex". Los motores TeX, a diferencia de muchos programas estándar, requieren que las opciones se especifiquen antes del nombre del archivo de entrada o del texto.

Las opciones pueden comenzar con - o --, y pueden abreviarse sin ambigüedades. Sin embargo, es mejor usar el nombre completo de la opción en los scripts para evitar posibles colisiones con nuevas opciones en el futuro.

"--accept" regexp
Aceptar líneas en la salida TeX que coincidan con regexp (Perl). Se puede repetir. Esta lista se revisa primero, por lo que todas las coincidencias se mostrarán, independientemente de otras opciones. Estas expresiones regulares no se anclan automáticamente (o se modifican de otra manera), simplemente se usan tal cual.
"--debug"
"--no-debug"
Emitir (o no) lo que está haciendo el programa en el error estándar; desactivado por defecto.
"--ignore" regexp
Ignorar líneas en la salida TeX que coincidan con regexp (Perl). Se puede repetir. Se agrega al conjunto predeterminado de expresiones regulares de ignorar en lugar de reemplazarlo. Al igual que las expresiones regulares de aceptación, estas no se anclan automáticamente (o se modifican de otra manera).
"--interactive"
"--no-interactive"
Por defecto, la entrada estándar al proceso TeX se cierra para que el modo interactivo de TeX (esperando entrada al ocurrir un error, el indicador "*", etc.) nunca se active. Dar "--interactive" permite que la interacción ocurra.
"--quiet"
"--no-quiet"
Por defecto, el comando TeX que se invoca se informa en la salida estándar; "--quiet" omite ese informe. Para obtener una ejecución completamente silenciosa, redirige la salida estándar: "texfot ... >/dev/null". (Los únicos mensajes al error estándar deberían ser errores de "texfot" en sí, por lo que no debería ser necesario redirigir ese, pero por supuesto eso también se podría hacer).
"--stderr"
"--no-stderr"
Por defecto, "texfot" informa todo lo escrito al error estándar por el comando TeX (en la salida estándar). "--no-stderr" omite ese informe. (Algunos programas, "dvisvgm" es uno, pueden ser bastante verbosos en el error estándar).
"--tee" archivo
Por defecto, la salida que se está filtrando se redirige ("tee"-ed), antes de filtrar, para que sea fácil comprobar la salida completa en caso de problemas.

El archivo predeterminado es "$TMPDIR/fot."uid; si "TMPDIR" no está definido, se usa "TMP" si está definido; si ninguno está definido, el directorio predeterminado es "/tmp". Por ejemplo: "/tmp/fot.1001". El sufijo uid es el id de usuario efectivo del proceso, añadido para evitar colisiones básicas entre diferentes usuarios en el mismo sistema.

texfot(1) - Arch Linux man pages

NAME

texfot

filter online output from TeX and friends

SYNOPSIS

texfot [ -b | -c | -p ] [ filename ... ]

DESCRIPTION

The TeX typesetting system and its friends (like LaTeX, ConTeXt, etc.) print a lot of messages to the terminal when they run. Many of these messages are useful for debugging or for monitoring the build process, but many are not. For example, the message "(/path/to/style.sty

included

..." is rarely useful, and the message "outputting file

foo.pdf" is informative but often redundant.

texfot filters the online output of TeX, printing only the messages that seem likely to be of interest to the user. It may be used as a filter, e.g.

texfot tex input.tex

or it may be used to process a log file that has been saved previously.

FLOW OF OPERATION

When texfot is invoked, it initializes itself to read from standard input, or from the specified files. It then reads the input line by line. If the line appears to be a message of interest, it is printed to standard output. Otherwise, it is discarded. After the entire input has been processed, texfot exits.

The definition of "message of interest" is hard-coded into the program. It includes things like warnings, errors, and notices of output files being created. It does not include messages about packages or files being included, nor messages about fonts being used.

OPTIONS

-b
Output messages that indicate that a build has been started. This is primarily useful for documenting the build process.
-c
Output messages that indicate that a build has been completed. This is primarily useful for documenting the build process.
-p
Output messages that indicate that a page has been processed. This is primarily useful for debugging page-building issues.
filename
If specified, texfot will read from these files instead of standard input. The files are processed in the order they are given.
--version
Output version information and exit successfully.
--help
Display this help and exit successfully.

RATIONALE

I wrote this because, in my work as a TUGboat editor (https://tug.org/TUGboat, article submissions always welcome!), I run and rerun many documents, many times each. It was easy to lose warnings I needed to see in the mass of unvarying and uninteresting output from TeX, such as style files being read and fonts being used. I wanted to see all and only those messages which needed some action by me.

I found some other programs of a similar nature, the LaTeX package "silence", and plenty of other (La)TeX wrappers, but it seemed none of them did what I wanted. Either they read the log file (I wanted to look at only the online output), or they output more, or less, than I wanted, or they required invoking TeX differently (I wanted to keep my build process exactly the same, most critically the TeX invocation, which can get complicated). Hence I wrote this little script.

Here are some keywords if you want to explore other options: texloganalyser, pydflatex, logfilter, latexmk, rubber, arara, and searching for "log" at https://ctan.org/search.

"texfot" is written in Perl, and runs on Unix. It may work on Windows if Perl and other software is installed, but I don't use Windows and don't support "texfot" there.

The name comes from the "trip.fot" and "trap.fot" files that are part of Knuth's trip and trap torture tests, which record the online output from the programs. I am not sure what "fot" stands for in trip and trap, but I can pretend that it stands for "filter online transcript" in the present case :).
