TERMKEY(7) Manual de Información Miscelánea TERMKEY(7)

NOMBRE

termkey - biblioteca de lectura de pulsaciones de teclas de terminal

DESCRIPCIÓN

termkey es una biblioteca que permite a los programas leer e interpretar pulsaciones de teclas y otros eventos de una terminal. Entiende los esquemas de codificación utilizados por las terminales para codificar las pulsaciones de teclas y UTF-8 , lo que le permite devolver eventos que representan eventos de teclas.

termkey opera de una manera pseudo orientada a objetos. Proporciona una función, termkey_new(3), que devuelve un puntero a una estructura recién asignada. Todas las demás funciones toman este puntero como su primer argumento. Un uso típico de esta biblioteca consistiría en una llamada a termkey_new() para construir una nueva instancia que represente el flujo stdin, luego usar la función termkey_waitkey(3) para esperar e interpretar eventos de pulsación de teclas. La función termkey_destroy(3) se puede utilizar para desasignar los recursos utilizados por la instancia si el programa ha terminado de usarla.

Lectura de Eventos

Cada instancia de una estructura termkey puede ser utilizada de una de tres maneras por el programa. Puede ser utilizada de forma síncrona, bloqueándose para esperar pulsaciones de teclas de un manejador de archivos. Puede ser utilizada de forma asíncrona, devolviendo pulsaciones de teclas si están disponibles, mientras coopera con un programa no bloqueante. O puede ser utilizada de forma abstracta, interpretando bytes de pulsaciones de teclas que le son alimentados directamente por el programa contenedor.

Para obtener el siguiente evento de tecla de forma síncrona, un programa puede llamar a termkey_waitkey(3). Esto devolverá un evento de su buffer interno, o se bloqueará hasta que una tecla esté disponible, devolviéndola cuando esté lista. Se comporta de manera similar a getc(3), fgetc(3) o similares, excepto que entiende y devuelve eventos completos de pulsación de teclas, en lugar de bytes individuales.

Para trabajar con un programa asíncrono, se utilizan otras dos funciones. termkey_advisereadable(3) informa a una instancia de termkey que puede haber más bytes de entrada disponibles en su manejador de archivos, por lo que debe llamar a read(2) para obtenerlos. El programa puede entonces llamar a termkey_getkey(3) para extraer eventos de pulsación de teclas del buffer interno, de una manera similar a termkey_waitkey().

Finalmente, los bytes de entrada pueden ser alimentados directamente en la instancia de termkey, llamando a termkey_push_bytes(3). Esto puede ser útil si los bytes ya han sido leídos de la terminal por la aplicación, o incluso en situaciones que no involucran directamente un manejador de archivos de terminal. Debido a estas situaciones, es posible construir una instancia de termkey no asociada con un manejador de archivos, pasando -1 como descriptor de archivo.

Una instancia de termkey contiene un buffer de bytes pendientes que han sido leídos pero aún no consumidos por termkey_getkey(3). termkey_get_buffer_remaining(3) devuelve el número de bytes de espacio de buffer actualmente libres en la instancia. termkey_set_buffer_size(3) y termkey_get_buffer_size(3) se pueden utilizar para controlar y devolver el tamaño total de este buffer.

Eventos de Teclas

Los eventos de teclas se almacenan en estructuras. Cada estructura contiene detalles de un evento de tecla. Esta estructura se define de la siguiente manera.


typedef struct {
    TermKeyType type;
    union {
        long       codepoint; /* TERMKEY_TYPE_UNICODE  */
        int        number;    /* TERMKEY_TYPE_FUNCTION */
        TermKeySym sym;       /* TERMKEY_TYPE_KEYSYM   */
    } code;
    int modifiers;
    char utf8[7];
} TermKeyKey;

El campo type indica el tipo de evento y determina cuál de los miembros de la unión code es válido. Será una de las siguientes constantes:

TERMKEY_TYPE_UNICODE
un punto de código Unicode. Este valor indica que code.codepoint es válido y contendrá el número del punto de código de la pulsación de tecla. En modo Unicode (si el bit TERMKEY_FLAG_UTF8 está establecido) será su número de carácter Unicode. En modo de bytes crudos, contendrá un solo byte de 8 bits.
TERMKEY_TYPE_FUNCTION
una tecla de función numerada. Este valor indica que code.number es válido y contiene el número de la tecla de función numerada.
TERMKEY_TYPE_KEYSYM
una tecla simbólica. Este valor indica que code.sym es válido y contiene el valor simbólico de la tecla.
TERMKEY_TYPE_MOUSE
la pulsación, liberación o movimiento de un botón del ratón. La estructura code debe considerarse opaca; termkey_interpret_mouse(3) puede ser utilizada para interpretarla.
TERMKEY_TYPE_POSITION
un informe de posición del cursor. La estructura code debe considerarse opaca; termkey_interpret_position(3) puede ser utilizada para interpretarla.
TERMKEY_TYPE_MODEREPORT
un informe de valor de modo ANSI o DEC. La estructura code debe considerarse opaca; termkey_interpret_modereport(3) puede ser utilizada para interpretarlo.
TERMKEY_TYPE_DCS
una secuencia DCS incluyendo su terminador. La estructura code debe considerarse opaca; termkey_interpret_string(3) puede ser utilizada para interpretarla.
TERMKEY_TYPE_OSC
una secuencia OSC incluyendo su terminador. La estructura code debe considerarse opaca; termkey_interpret_string(3) puede ser utilizada para interpretarla.
TERMKEY_TYPE_UNKNOWN_CSI
una secuencia CSI no reconocida. La estructura code debe ser considerada opaca; termkey_interpret_csi(3) puede ser utilizada para interpretarla.

La máscara de bits modifiers se compone de un OR a nivel de bits de las constantes TERMKEY_KEYMOD_SHIFT, TERMKEY_KEYMOD_CTRL y TERMKEY_KEYMOD_ALT.

El campo utf8 solo se establece en eventos cuyo type es TERMKEY_TYPE_UNICODE. No debe leerse para otros eventos.

Los eventos de teclas que representan teclas especiales (type es TERMKEY_TYPE_KEYSYM) tienen asociado un valor simbólico que identifica la tecla especial, en code.sym. termkey_get_keyname(3) puede ser utilizado para convertir este valor simbólico en una cadena, y termkey_lookup_keyname(3) puede ser utilizado para convertir nombres de cadena en valores simbólicos.

También se proporcionan un par de funciones para convertir entre eventos de teclas y cadenas. termkey_strfkey(3) convierte un evento de tecla en una cadena, y termkey_strpkey(3) analiza una cadena convirtiéndola en un evento de tecla.

Los eventos de teclas pueden compararse por igualdad u ordenación utilizando termkey_keycmp(3).

Banderas de Control

Los detalles del comportamiento de una instancia de termkey se controlan mediante dos máscaras de bits de banderas. termkey_set_flags(3) y termkey_get_flags(3) establecen o devuelven las banderas utilizadas para controlar el comportamiento general, y termkey_set_canonflags(3) y termkey_get_canonflags(3) establecen o devuelven las banderas que controlan el comportamiento de canonición del valor de la tecla realizado por termkey_canonicalise(3).

Se reconocen las siguientes banderas de control.

NAME

termkey - library for key presses

DESCRIPTION

The termkey library is a high-level API for reading key presses from a terminal, with support for mouse events, modifier keys, Unicode, and terminal size changes.

The library provides two main functions for waiting for and retrieving key presses: termkey_waitkey(3) and termkey_getkey(3). These functions return a `TermKeyKey` structure, which contains information about the key that was pressed. The `type` field of this structure indicates the type of key event that occurred.

The following `type` values are supported:

TERMKEY_TYPE_KEY
A normal key press.
TERMKEY_TYPE_SPECIAL
A special key, such as an arrow key or function key.
TERMKEY_TYPE_MOUSE
A mouse event.
TERMKEY_TYPE_RESIZE
A terminal resize event. This event is only generated if the terminal is resized while the application is running and the underlying terminal driver supports signalling the application on resize.
TERMKEY_TYPE_CHANGED
An event indicating that the terminal settings have changed. This can happen if the terminal is attached to a different device, or if the locale has changed.
TERMKEY_TYPE_ERROR
An error occurred while reading key presses. The `code` field will contain an error code.
TERMKEY_TYPE_UNKNOWN_CSI
An unknown CSI sequence was received. The sequence can be retrieved using termkey_interpret_csi(3).
TERMKEY_TYPE_DCS
A Device Control String (DCS) was received.
TERMKEY_TYPE_OSC
An Operating System Command (OSC) string was received.
TERMKEY_TYPE_POSITION
A cursor position report was received.
TERMKEY_TYPE_MODEREPORT
An ANSI or DEC mode report was received.

The `sym` field of the `TermKeyKey` structure contains a symbolic representation of the key press. The `modifiers` field contains a bitmask of modifier keys that were pressed. The `code` field contains the raw key code, which may be useful for distinguishing between different keys that have the same symbol.

The `TermKey` object can be configured with various flags that modify its behavior. These flags can be set using the termkey_set_flags(3) function.

TERMKEY_FLAG_NOINTERPRET
Do not attempt to interpret C0 codes into keysyms. Instead report them as plain Ctrl-letter events.
TERMKEY_FLAG_CONVERTKP
Convert xterm's alternative keypad symbols into the plain ASCII codes they would represent.
TERMKEY_FLAG_RAW
Ignore locale settings; do not attempt to recombine UTF-8 sequences. Instead report only raw values.
TERMKEY_FLAG_UTF8
Ignore locale settings; force UTF-8 recombining on. This flag overrides TERMKEY_FLAG_RAW.
TERMKEY_FLAG_NOTERMIOS
Even if the terminal file descriptor fd represents a TTY device, do not call the tcsetattr(3) termios function on it to set it to canonical input mode.
TERMKEY_FLAG_SPACESYMBOL
Report space as being a symbolic key rather than a Unicode codepoint. Setting or clearing this flag in fact sets or clears the TERMKEY_CANON_SPACESYMBOL canonicalisation flag.
TERMKEY_FLAG_CTRLC
Disable the SIGINT behaviour of Ctrl-C. If this flag is provided, then Ctrl-C will be available as a normal keypress, rather than sending the process group a SIGINT. This flag only takes effect without TERMKEY_FLAG_NOTERMIOS; with it, none of the signal keys are disabled anyway.
TERMKEY_FLAG_EINTR
Without this flag, IO operations are retried when interrupted by a signal (EINTR). With this flag the TERMKEY_RES_ERROR result is returned instead.
TERMKEY_FLAG_NOSTART
This flag is only meaningful to the constructor functions termkey_new(3) and termkey_new_abstract(3). If set, the constructor will not call termkey_start(3) as part of the construction process. The user must call that at some future time before the instance will be usable.

The following canonicalisation flags are recognised.

TERMKEY_CANON_SPACESYMBOL
If this flag is set then a Unicode space character is represented using the TERMKEY_SYM_SPACE symbol. If this flag is not set, it is represented by the U+0020 Unicode codepoint.
TERMKEY_CANON_DELBS
If this flag is set then an ASCII DEL character is represented by the TERMKEY_SYM_BACKSPACE symbol. If not, it is represented by TERMKEY_SYM_DEL. An ASCII BS character is always represented by TERMKEY_SYM_BACKSPACE, regardless of this flag.

Multi-byte Events

Special keys, mouse events, and UTF-8 encoded Unicode text, are all represented by more than one byte. If the start of a multi-byte sequence is seen by termkey_waitkey() it will wait a short time to see if the remainder of the sequence arrives. If the sequence remains unfinished after this timeout, it will be returned in its incomplete state. Partial escape sequences are returned as an Escape key (TERMKEY_SYM_ESCAPE) followed by the text contained in the sequence. Partial UTF-8 sequences are returned as the Unicode replacement character, U+FFFD.

The amount of time that the termkey instance will wait is set by termkey_set_waittime(3), and is returned by termkey_get_waittime(3). Initially it will be set to 50 miliseconds.

Mouse Events

The TERMKEY_TYPE_MOUSE event type indicates a mouse event. The code field of the event structure should be considered opaque, though modifiers will be valid. In order to obtain the details of the mouse event, call termkey_interpret_mouse(3) passing the event structure and pointers to integers to store the result in.

termkey recognises three mouse protocols: the original X10 protocol (CSI M followed by three bytes), SGR encoding (CSI < ... M, as requested by CSI ? 1006 h), and rxvt encoding (CSI ... M, as requested by CSI ? 1015 h). Which encoding is in use is inferred automatically by termkey, and does not need to be specified explicitly.

Position Events

The TERMKEY_TYPE_POSITION event type indicates a cursor position report. This is typically sent by a terminal in response to the Report Cursor Position command (CSI ? 6 n). The event bytes are opaque, but can be obtained by calling termkey_interpret_position(3) passing the event structure and pointers to integers to store the result in. Note that only a DEC CPR sequence (CSI ? R) is recognised, and not the non-DEC prefixed CSI R because the latter could be interpreted as the F3 function key instead.

Mode Reports

The TERMKEY_TYPE_MODEREPORT event type indicates an ANSI or DEC mode report. This is typically sent by a terminal in response to the Request Mode command (CSI $p or CSI ? $p). The event bytes are opaque, but can be obtained by calling termkey_interpret_modereport(3) passing the event structure and pointers to integers to store the result in.

Control Strings

The TERMKEY_TYPE_DCS and TERMKEY_TYPE_OSC event types indicate a DCS or OSC control string. These are typically sent by the terminal in response of similar kinds of strings being sent as queries by the application. The event bytes are opaque, but the body of the string itself can be obtained by calling termkey_interpret_string(3) immediately after this event is received. The underlying termkey instance itself can only store one pending string, so the application should be sure to call this function in a timely manner soon after the event is received; at the very least, before calling any other functions that will insert bytes into or remove key events from the instance.

Unrecognised CSIs

The TERMKEY_TYPE_UNKNOWN_CSI event type indicates a CSI sequence that the termkey does not recognise. It will have been extracted from the stream, but is available to the application to inspect by calling termkey_interpret_csi(3). It is important that if the application wishes to inspect this sequence it is done immediately, before any other IO operations on the termkey instance (specifically, before calling termkey_waitkey() or termkey_getkey() again), otherwise the buffer space consumed by the sequence will be overwritten. Other types of key event do not suffer this limitation as the TermKeyKey structure is sufficient to contain all the information required.
