term(5) Formatos de archivo term(5)

NOMBRE

term - descripción compilada de terminal terminfo

SINOPSIS

term

DESCRIPCIÓN

Ubicación de almacenamiento

Las descripciones de terminfo compiladas se colocan bajo el directorio /usr/share/terminfo. Se soportan dos configuraciones (al compilar las bibliotecas de ncurses):

árbol de directorios
Se utiliza un esquema de dos niveles para evitar una búsqueda lineal en un enorme directorio del sistema Unix: /usr/share/terminfo/c/nombre donde nombre es el nombre de la terminal, y c es el primer carácter de nombre. Por lo tanto, act4 se puede encontrar en el archivo /usr/share/terminfo/a/act4. Los sinónimos para la misma terminal se implementan mediante múltiples enlaces al mismo archivo compilado.
base de datos hasheada
Utilizando una base de datos Berkeley, se almacenan dos tipos de registros: los datos de terminfo en el mismo formato que se almacena en un árbol de directorios con el nombre primario de terminfo como clave, y registros que contienen solo alias que apuntan al nombre primario.
Si está compilado para escribir bases de datos hasheadas, ncurses todavía puede leer bases de datos de terminfo organizadas como un árbol de directorios, pero no puede escribir entradas en el árbol de directorios. Puede escribir (o reescribir) entradas en la base de datos hasheada.
ncurses distingue los dos casos en la variable de entorno TERMINFO y TERMINFO_DIRS asumiendo un árbol de directorios para las entradas que corresponden a un directorio existente, y una base de datos hasheada en caso contrario.

Formato de almacenamiento heredado

El formato ha sido elegido de tal manera que sea el mismo en todo hardware. Se asume un byte de 8 o más bits, pero no se hacen suposiciones sobre el orden de bytes o la extensión de signo.

El archivo compilado se crea con el programa tic, y es leído por la rutina setupterm(3X). El archivo se divide en seis partes:

a) cabecera,
b) nombres de terminal,
c) banderas booleanas,
d) números,
e) cadenas, y
f) tabla de cadenas.

La sección cabecera comienza el archivo. Esta sección contiene seis enteros cortos en el formato descrito a continuación. Estos enteros son

(1) el número mágico (octal 0432);
(2) el tamaño, en bytes, de la sección de nombres de terminal;
(3) el número de bytes en la sección de banderas booleanas;
(4) el número de enteros cortos en la sección de números;
(5) el número de desplazamientos (enteros cortos) en la sección de cadenas;
(6) el tamaño, en bytes, de la tabla de cadenas.

Las capacidades en las secciones de banderas booleanas, números y cadenas están en el mismo orden que el archivo <term.h>.

Los enteros cortos son firmados, en el rango de -32768 a 32767. Se almacenan como dos bytes de 8 bits. El primer byte contiene los 8 bits menos significativos del valor, y el segundo byte contiene los 8 bits más significativos. (Por lo tanto, el valor representado es 256*segundo+primero.) Este formato corresponde al hardware de la VAX y PDP-11 (es decir, máquinas little-endian). Las máquinas donde esto no corresponde al hardware deben leer los enteros como dos bytes y calcular el valor little-endian.

Los números en una descripción de terminal, ya sean entradas en la tabla de números o de cadenas, son enteros positivos. Las banderas booleanas se tratan como enteros positivos de un byte. En cada caso, esos enteros positivos representan una capacidad de terminal. El compilador de terminal tic utiliza enteros negativos para manejar los casos en que una capacidad no está disponible:

•
Si una capacidad está ausente en esta terminal, tic almacena un -1 en la tabla correspondiente.
El valor entero -1 se representa con dos bytes 0377, 0377.
Los valores booleanos ausentes se representan con el byte 0 (falso).
•
Si una capacidad ha sido cancelada de esta terminal, tic almacena un -2 en la tabla correspondiente.
El valor entero -2 se representa con dos bytes 0377, 0376.
El valor booleano -2 se representa con el byte 0376.
•
Otros valores negativos son ilegales.

La sección de nombres de terminal viene después de la cabecera. Contiene la primera línea de la descripción de terminfo, listando los diversos nombres para la terminal, separados por el carácter “|”. La sección de nombres de terminal se termina con un carácter NUL de ASCII.

La sección de banderas booleanas tiene un byte por cada bandera. Las capacidades booleanas son 1 o 0 (verdadero o falso) según si la terminal soporta la capacidad dada o no.

Entre la sección de banderas booleanas y la sección de números, se insertará un byte nulo, si es necesario, para asegurar que la sección de números comience en un byte par. Esto es una reliquia de la arquitectura con direcciones de palabras del PDP-11, originalmente diseñada para evitar trampas inducidas por el acceso a una palabra en un límite de byte impar. Todos los enteros cortos están alineados en un límite de palabra corta.

La sección de números es similar a la sección de banderas booleanas. Cada capacidad ocupa dos bytes y se almacena como un entero corto little-endian.

La sección de cadenas es también similar. Cada capacidad se almacena como un entero corto. El valor de la capacidad es un índice en la tabla de cadenas.

La tabla de cadenas es la última sección. Contiene todos los valores de las capacidades de cadena referenciadas en la sección de cadenas. Cada cadena está terminada por nulo. Los caracteres especiales en notación ^X o \c se almacenan en su forma interpretada, no en la representación de impresión. La información de relleno $<nn> y la información de parámetros %x se almacenan intactas en forma no interpretada.

Formato de almacenamiento extendido

La sección anterior describe el formato binario convencional de terminfo. Con algunas variaciones menores de los desplazamientos (ver PORTABILITY), el mismo formato binario se utiliza en todos los sistemas Unix modernos. Cada sistema utiliza un conjunto predefinido de capacidades booleanas, numéricas o de cadena.

Las bibliotecas y aplicaciones de ncurses soportan un formato binario de terminfo extendido, permitiendo a los usuarios definir capacidades que se cargan en tiempo de ejecución. Esta extensión es posible utilizando el hecho de que otras implementaciones dejan de leer los datos de terminfo cuando han alcanzado el final del tamaño dado en la cabecera. ncurses comprueba el tamaño y, si excede el de los datos predefinidos, continúa analizando según su propio esquema.

Primero, lee la cabecera extendida (5 enteros cortos):

(1)
recuento de capacidades booleanas extendidas
(2)
recuento de capacidades numéricas extendidas
(3)
recuento de capacidades de cadena extendidas
(4)
recuento de los elementos en la tabla de cadenas extendidas
(5)
tamaño de la tabla de cadenas extendidas en bytes

El recuento y el tamaño de la tabla de cadenas extendidas incluyen los nombres de las capacidades extendidas, así como los valores de las capacidades extendidas.

Usando los recuentos y tamaños, ncurses asigna arrays y lee los datos para las capacidades extendidas en el mismo orden que la información de la cabecera.

La tabla de cadenas extendidas contiene valores para las capacidades de cadena. Después del final de estos valores, contiene los nombres de cada una de las capacidades extendidas en orden, por ejemplo, booleanas, luego números y finalmente cadenas.

NAME

terminfo, termtype - terminal capability data base

SYNOPSIS

#include <curses.h>

#include <term.h>

bool* bool_table(struct termtos *)
char* num_table(struct termtos *)
char* str_table(struct termtos *)
int setupterm(const char *, int, int*)
int tigetflag(const char *)
int tigetnum(const char *)
char* tigetstr(const char *)
int tparm(char*, ...)

DESCRIPTION

The terminfo data base describes the capabilities of individual terminals. It is used by the curses library to perform operations on the terminal without the user needing to know the specifics of the terminal's command sequences.

The terminfo data base is organized as a directory tree containing compiled binary files, each representing a particular terminal description. These files are typically located in /usr/share/terminfo.

The terminfo file format includes:

  • A magic number, used to identify the file type.
  • A table of capabilities, including booleans, numbers, and strings.
  • A table of terminal names.

The setupterm routine initializes the terminfo data base for a given terminal. It reads the terminfo file and parses the capabilities, making them available through the TERMTYPE structure and associated functions.

The tigetflag, tigetnum, and tigetstr functions provide a portable way to access individual terminal capabilities. They take the name of a capability (e.g., "clear", "cols") and return its corresponding value.

The tparm function is used to parameterize string capabilities, allowing for dynamic generation of terminal control sequences.

Applications can extend the predefined capabilities by using the user_caps mechanism, allowing for more specialized terminal manipulation. See user_caps(5) for an overview of how ncurses uses this extended information.

Applications that manipulate terminal data can use the definitions described in term_variables(3X) which associate the long capability names with members of a TERMTYPE structure.

Extended Number Format

On occasion, 16-bit signed integers are not large enough. With ncurses 6.1, a new format was introduced by making a few changes to the legacy format:

  • a different magic number (octal 01036)
  • changing the type for the number array from signed 16-bit integers to signed 32-bit integers.

To maintain compatibility, the library presents the same data structures to direct users of the TERMTYPE structure as in previous formats. However, that cannot provide callers with the extended numbers. The library uses a similar but hidden data structure TERMTYPE2 to provide data for the terminfo functions.

FILES

/usr/share/terminfo
compiled terminal description database

PORTABILITY

setupterm

Note that it is possible for setupterm to expect a different set of capabilities than are actually present in the file. Either the database may have been updated since setupterm was recompiled (resulting in extra unrecognized entries in the file) or the program may have been recompiled more recently than the database was updated (resulting in missing entries). The routine setupterm must be prepared for both possibilities - this is why the numbers and sizes are included. Also, new capabilities must always be added at the end of the lists of Boolean, number, and string capabilities.

Binary Format

X/Open Curses does not specify a format for the terminfo database. System V curses used a directory-tree of binary files, one per terminal description.

Despite the consistent use of little-endian for numbers and the otherwise self-describing format, it is not wise to count on portability of binary terminfo entries between commercial Unix versions. The problem is that there are at least three versions of terminfo (under HP-UX, AIX, and OSF/1) which diverged from System V terminfo after SVr1, and have added extension capabilities to the string table that (in the binary format) collide with System V and X/Open Curses extensions. See terminfo(5) for detailed discussion of terminfo source compatibility issues.

This implementation is by default compatible with the binary terminfo format used by Solaris curses, except in a few less-used details where it was found that the latter did not match X/Open Curses. The format used by the other Unix versions can be matched by building ncurses with different configuration options.

Magic Codes

The magic number in a binary terminfo file is the first 16-bits (two bytes). Besides making it more reliable for the library to check that a file is terminfo, utilities such as file(1) also use that to tell what the file-format is. System V defined more than one magic number, with 0433, 0435 as screen-dumps (see scr_dump(5)). This implementation uses 01036 as a continuation of that sequence, but with a different high-order byte to avoid confusion.

The TERMTYPE Structure

Direct access to the TERMTYPE structure is provided for legacy applications. Portable applications should use the tigetflag and related functions described in curs_terminfo(3X) for reading terminal capabilities.

Mixed-case Terminal Names

A small number of terminal descriptions use uppercase characters in their names. If the underlying filesystem ignores the difference between uppercase and lowercase, ncurses represents the “first character” of the terminal name used as the intermediate level of a directory tree in (two-character) hexadecimal form.

Limits

ncurses stores compiled terminal descriptions in three related formats, described in the sections

  • LEGACY STORAGE FORMAT, and
  • EXTENDED STORAGE FORMAT, and
  • EXTENDED NUMBER FORMAT.

The legacy storage format and the extended number format differ by the types of numeric capability which they can store (i.e., 16-bit versus 32-bit integers). The extended storage format introduced by ncurses 5.0 adds data to either of these formats.

Some limitations apply:

  • total compiled entries cannot exceed 4096 bytes in the legacy format.
  • total compiled entries cannot exceed 32768 bytes in the extended format.
  • the name field cannot exceed 128 bytes.

Compiled entries are limited to 32768 bytes because offsets into the strings table use two-byte integers. The legacy format could have supported 32768-byte entries, but was limited to a virtual memory page's 4096 bytes.
