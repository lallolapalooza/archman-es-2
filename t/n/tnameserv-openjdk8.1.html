tnameserv(1) Herramientas de IDL y RMI-IIOP de Java tnameserv(1)

NOMBRE

tnameserv - Lenguaje de Definición de Interfaces (IDL).

SINOPSIS

tnameserve -ORBInitialPort [ puerto_servidor_nombres ]
-ORBInitialPort puerto_servidor_nombres

El puerto inicial donde el servicio de nombres escucha el protocolo de arranque utilizado para implementar los métodos resolve_initial_references y list_initial_references del ORB.

DESCRIPCIÓN

Java IDL incluye el Demonio del Broker de Objetos (ORBD). ORBD es un proceso demonio que contiene un Servicio de Arranque, un Servicio de Nombres Transitorio, un Servicio de Nombres Persistente y un Gestor de Servidores. Los tutoriales de Java IDL utilizan todos ORBD, pero puedes sustituir el comando tnameserv por el comando orbd en cualquiera de los ejemplos que utilizan un Servicio de Nombres Transitorio.

Ver orbd(1) o Servicio de Nombres en http://docs.oracle.com/javase/8/docs/technotes/guides/idl/jidlNaming.html

El Servicio de Nombres (COS) Común de Servicios de Objeto (COS) de CORBA proporciona un directorio con estructura de árbol para referencias de objetos, similar a un sistema de archivos que proporciona una estructura de directorio para archivos. El Servicio de Nombres Transitorio proporcionado con Java IDL, tnameserv, es una implementación simple de la especificación del Servicio de Nombres COS.

Las referencias de objetos se almacenan en el espacio de nombres por nombre y cada par referencia de objeto-nombre se llama enlace de nombre. Los enlaces de nombre se pueden organizar bajo contextos de nombres. Los contextos de nombres son enlaces de nombre y sirven la misma función organizativa que un subdirectorio de un sistema de archivos. Todos los enlaces se almacenan bajo el contexto de nombres inicial. El contexto de nombres inicial es el único enlace persistente en el espacio de nombres. El resto del espacio de nombres se pierde cuando el proceso del servicio de nombres de Java IDL se detiene y reinicia.

Para que una aplicación o applet utilice la nomenclatura COS, su ORB debe conocer el puerto de un host que ejecute un servicio de nombres o tener acceso a una cadena de contexto de nombres inicial para ese servicio de nombres. El servicio de nombres puede ser el servicio de nombres de Java IDL o cualquier otro servicio de nombres compatible con COS.

INICIAR EL SERVICIO DE NOMBRES

Debes iniciar el servicio de nombres de Java IDL antes de una aplicación o applet que utilice su servicio de nombres. La instalación del producto Java IDL crea un script (Oracle Solaris: tnameserv) o un archivo ejecutable (Windows: tnameserv.exe) que inicia el servicio de nombres de Java IDL. Inicia el servicio de nombres para que se ejecute en segundo plano.

Si no especificas lo contrario, el servicio de nombres de Java IDL escucha en el puerto 900 para el protocolo de arranque utilizado para implementar los métodos resolve_initial_references y list_initial_references del ORB, como sigue:

tnameserv -ORBInitialPort puerto_servidor_nombres&

Si no especificas el puerto del servidor de nombres, se utiliza el puerto 900 por defecto. Al ejecutar software Oracle Solaris, debes convertirte en el usuario root para iniciar un proceso en un puerto inferior a 1024. Por esta razón, se recomienda usar un número de puerto mayor o igual a 1024. Para especificar un puerto diferente, por ejemplo, 1050, y ejecutar el servicio de nombres en segundo plano, desde una shell de comandos de UNIX, introduce:

tnameserv -ORBInitialPort 1050&

Desde un símbolo del sistema de MS-DOS (Windows), introduce:

start tnameserv -ORBInitialPort 1050

Los clientes del servidor de nombres deben ser informados del nuevo número de puerto. Hazlo estableciendo la propiedad org.omg.CORBA.ORBInitialPort al nuevo número de puerto al crear el objeto ORB.

EJECUTAR EL SERVIDOR Y EL CLIENTE EN DIFERENTES HOSTS

En la mayoría de los tutoriales de Java IDL y RMI-IIOP, el servicio de nombres, el servidor y el cliente se ejecutan en la máquina de desarrollo. En el despliegue real, el cliente y el servidor probablemente se ejecutarán en máquinas host diferentes de las del Servicio de Nombres.

Para que el cliente y el servidor encuentren el Servicio de Nombres, deben ser informados del número de puerto y del host en el que se está ejecutando el servicio de nombres. Hazlo estableciendo las propiedades org.omg.CORBA.ORBInitialPort y org.omg.CORBA.ORBInitialHost en los archivos del cliente y del servidor al nombre de la máquina y número de puerto en el que se está ejecutando el Servicio de Nombres. Un ejemplo de esto se muestra en Getting Started Using RMI-IIOP en http://docs.oracle.com/javase/8/docs/technotes/guides/rmi-iiop/rmiiiopexample.html

También podrías usar las opciones de línea de comandos -ORBInitialPort puerto_servidor_nombres y -ORBInitialHost nombrehost_servidor_nombres para indicar al cliente y al servidor dónde encontrar el servicio de nombres. Para un ejemplo de cómo hacer esto usando la opción de línea de comandos, ver Java IDL: El Ejemplo Hola Mundo en Dos Máquinas en http://docs.oracle.com/javase/8/docs/technotes/guides/idl/tutorial/jidl2machines.html

Por ejemplo, supongamos que el Servicio de Nombres Transitorio, tnameserv, se está ejecutando en el puerto 1050 en el host nameserverhost. El cliente se está ejecutando en el host clienthost y el servidor se está ejecutando en el host serverhost.

Inicia tnameserv en el host nameserverhost:

tnameserv -ORBInitialPort 1050

Inicia el servidor en el serverhost:

java Server -ORBInitialPort 1050 -ORBInitialHost nameserverhost

Inicia el cliente en el clienthost:

java Client -ORBInitialPort 1050 -ORBInitialHost nameserverhost

DETENER EL SERVICIO DE NOMBRES

Para detener el servicio de nombres de Java IDL, utiliza el comando relevante del sistema operativo, como kill para un proceso Unix o Ctrl+C para un proceso de Windows. El servicio de nombres continúa esperando invocaciones hasta que se apaga explícitamente. Ten en cuenta que los nombres registrados con el servicio de nombres de Java IDL desaparecen cuando se termina el servicio.

OPCIONES

-Jopción

Pasa opción a la Máquina Virtual Java, donde opción es una de las opciones descritas en la página de referencia del lanzador de aplicaciones de Java. Por ejemplo, -J-Xms48m establece la memoria de inicio en 48 MB. Ver java(1).

tnameserv(8)

OpenJWeb-6R1 SUN MI 21 November 2013 OpenJWeb-6R1

NAME

tnameserv - Java(TM) 2 Platform, Standard Edition Naming Service

SYNOPSIS

tnameserv [-ORBInitialPort port]

DESCRIPTION

tnameserv is the CORBA Naming Service provided with the Java(TM) 2 Platform, Standard Edition.

The CORBA Naming Service allows CORBA objects to be registered and looked up by name. It provides a CORBA name space, which is a tree structure that can contain both CORBA objects and other naming contexts.

tnameserv is a Java application. It requires a Java Runtime Environment (JRE) to be installed.

The name server can be started using the command line:

tnameserv [-ORBInitialPort port]
-ORBInitialPort port
This option specifies the port number on which the naming service will listen for incoming requests. If not specified, the default port is 900.

The name server needs to be started before any CORBA clients or servers that intend to use it.

To stop the naming service, simply press Ctrl+C in the terminal where it is running.

OPTIONS

No options are supported.

EXAMPLES

To start the naming service on the default port (900):

tnameserv

To start the naming service on port 1050:

tnameserv -ORBInitialPort 1050

The following sample program shows how to bind a dummy object reference to a name in the naming service. This program can be used to populate the name space with objects.

import java.util.Properties;
import org.omg.CORBA.*;
import org.omg.CosNaming.*;
public class NameServerWriter {
    public static void main(String args[]) {
        try {

This code obtains the ORB instance and initializes it with the specified port number.

            Properties props = new Properties();
            props.put("org.omg.CORBA.ORBInitialPort", "1050");
            ORB orb = ORB.init(args, props);

This code obtains the initial naming context and assigns it to ctx. The second line copies ctx into a dummy object reference objref that is attached to various names and added into the name space.

            NamingContext ctx =
                NamingContextHelper.narrow(
                    orb.resolve_initial_references("NameService"));
             NamingContext objref = ctx;

This code creates a name plans of type text and binds it to the dummy object reference. plans is then added under the initial naming context using the rebind method. The rebind method enables you to run this program over and over again without getting the exceptions from using the bind method.

            NameComponent nc1 = new NameComponent("plans", "text");
            NameComponent[] name1 = {nc1};
            ctx.rebind(name1, objref);
            System.out.println("plans rebind successful!");

This code creates a naming context called Personal of type directory. The resulting object reference, ctx2, is bound to the name and added under the initial naming context.

            NameComponent nc2 = new NameComponent("Personal", "directory");
            NameComponent[] name2 = {nc2};
            NamingContext ctx2 = ctx.bind_new_context(name2);
            System.out.println("new naming context added..");

The remainder of the code binds the dummy object reference using the names schedule and calendar under the Personal naming context (ctx2).

            NameComponent nc3 = new NameComponent("schedule", "text");
            NameComponent[] name3 = {nc3};
            ctx2.rebind(name3, objref);
            System.out.println("schedule rebind successful!");
            NameComponent nc4 = new NameComponent("calender", "text");
            NameComponent[] name4 = {nc4};
            ctx2.rebind(name4, objref);
            System.out.println("calender rebind successful!");
        } catch (Exception e) {
            e.printStackTrace(System.err);
        }
    }
}

BROWSING THE NAME SPACE

The following sample program shoes how to browse the name space.

import java.util.Properties;
import org.omg.CORBA.*;
import org.omg.CosNaming.*;
public class NameClientList {
    public static void main(String args[]) {
        try {

In Start the Naming Service, the nameserver was started on port 1050. The following code ensures that the client program is aware of this port number.

            Properties props = new Properties();
            props.put("org.omg.CORBA.ORBInitialPort", "1050");
            ORB orb = ORB.init(args, props);

The following code obtains the initial naming context.

            NamingContext nc =
            NamingContextHelper.narrow(
                orb.resolve_initial_references("NameService"));

The list method lists the bindings in the naming context. In this case, up to 1000 bindings from the initial naming context will be returned in the BindingListHolder; any remaining bindings are returned in the BindingIteratorHolder.

            BindingListHolder bl = new BindingListHolder();
            BindingIteratorHolder blIt= new BindingIteratorHolder();
            nc.list(1000, bl, blIt);

This code gets the array of bindings out of the returned BindingListHolder. If there are no bindings, then the program ends.

            Binding bindings[] = bl.value;
            if (bindings.length == 0) return;

The remainder of the code loops through the bindings and prints outs the names.

            for (int i=0; i < bindings.length; i++) {
                // get the object reference for each binding
                org.omg.CORBA.Object obj = nc.resolve(bindings[i].binding_name);
                String objStr = orb.object_to_string(obj);
                int lastIx = bindings[i].binding_name.length-1;
                // check to see if this is a naming context
                if (bindings[i].binding_type == BindingType.ncontext) {
                    System.out.println("Context: " +
                        bindings[i].binding_name[lastIx].id);
                } else {
                    System.out.println("Object: " +
                        bindings[i].binding_name[lastIx].id);
                }
            }
        } catch (Exception e) {
            e.printStackTrace(System.err)
        }
    }
}
